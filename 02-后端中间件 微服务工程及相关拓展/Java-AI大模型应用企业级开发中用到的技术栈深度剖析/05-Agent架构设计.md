## 1. Agent 是什么

```
Agent（智能体）= 能自主规划 + 调用工具 + 反思的 LLM 应用

对比：
  普通应用：固定流程（Prompt → 回答）
  Agent：动态流程（LLM 决定下一步做什么）

⚠️ 面试必答：
"Agent = LLM 驱动的自主系统——
 规划（做什么）、工具（怎么做）、
 反思（对不对）三步循环；
 从'问答'升级为'办事'。"
```

---

## 2. Agent 核心组成

```
Agent 四大组件：
  ① 规划（Planning）：复杂目标拆解为步骤
  ② 记忆（Memory）：短期会话 + 长期知识
  ③ 工具（Tool Use）：执行能力（见 04 篇）
  ④ 反思（Reflection）：自我纠错与验证

⚠️ 面试必答：
"Agent 四件套——规划、记忆、工具、反思；
 工具是手、记忆是脑、规划是策略、反思是质检。"
```

### 2.1 规划（Planning）

```
规划方式：
  隐式规划：LLM 每步决策（ReAct）
  显式规划：先生成计划再执行（Plan-and-Execute）
  混合：计划 + 执行中重规划

⚠️ 面试必答：
"规划两种——ReAct 边想边做（灵活）、
 Plan-Execute 先计划后做（步骤明确场景）。"
```

## 3. 三种编排模式

### 3.1 模式总览（经验法则）

| 模式 | 适用 | 占比 |
|------|------|:---:|
| **ReAct** | 大多数业务场景 | 80% |
| Plan-and-Execute | 步骤明确的长任务 | 15% |
| Multi-Agent | 复杂协作（多角色） | 5% |

### 3.2 ReAct 模式（最经典）

```
ReAct（Reasoning + Acting）循环：
  Thought（思考）：分析当前情况
  Action（行动）：调用工具/查询
  Observation（观察）：工具结果
  → 循环直到得出答案

⚠️ 面试必答：
"ReAct = 思考-行动-观察循环——
 每步 Thought 透明可调试，
 80% 业务场景够用（最易落地）。"
```

### 3.3 Plan-and-Execute

```
Plan-and-Execute：
  ① 先生成完整计划（步骤列表）
  ② 逐步执行（每步可调工具）
  ③ 执行中重规划（计划失败时修正）

适用：任务步骤明确的长期执行
  （报告生成、批量处理）

⚠️ 面试必答：
"Plan-Execute = 先计划后执行——
 适合步骤明确场景；必须配合
 '执行中重规划'（计划会失效）。"
```

### 3.4 Multi-Agent

```
Multi-Agent：多个 Agent 各司其职协作
  例：研究 Agent + 写作 Agent + 审核 Agent

⚠️ 代价：管理成本高（消息协调/状态同步）
仅 5% 场景真正需要（复杂流水线）

⚠️ 面试必答：
"Multi-Agent 适合复杂流水线——
 但管理成本高（协调/同步/调试），
 能单 Agent 不双 Agent。"
```

## 4. 记忆体系

### 4.1 记忆三层

```
Agent 记忆三层：
  ① 短期记忆：当前会话（上下文窗口内）
  ② 长期记忆：跨会话（向量库存历史/偏好）
  ③ 工作记忆：任务进行中的中间状态

⚠️ 面试必答：
"记忆三层——短期（会话内）、
 长期（向量库）、工作（任务状态）；
 记忆是 Agent '越来越懂用户'的关键。"
```

### 4.2 记忆实现

```java
// 短期记忆：会话历史（Spring AI ChatMemory）
// 长期记忆：向量库存储用户偏好/历史结论
@Service
public class MemoryService {

    // 长期记忆：用户偏好存入向量库
    public void rememberPreference(String userId, String preference) {
        Document doc = new Document(preference);
        doc.getMetadata().put("userId", userId);
        doc.getMetadata().put("type", "preference");
        vectorStore.add(List.of(doc));
    }

    // 检索记忆：新对话时注入相关记忆
    public List<Document> recall(String userId, String question) {
        return vectorStore.similaritySearch(SearchRequest.builder()
                .query(question)
                .filterExpression("userId == '" + userId + "'")
                .topK(3)
                .build());
    }
}
```

> 🎯 **要点**：记忆实现 = 短期（会话历史）+ 长期（向量库 + 用户过滤）。**记忆注入是"个性化 Agent"的基础**。

## 5. 设计原则

### 5.1 六条铁律

```
Agent 设计六原则：
  ① 工具原子化（一个工具一件事）
  ② 上下文精选（窗口是有限资源）
  ③ 人工接管点（资金/权限/敏感必人工）
  ④ 可观测（每步思考/工具/耗时/成本记录）
  ⑤ 幂等设计（LLM 会重试）
  ⑥ 渐进复杂度（先 ReAct 后 Multi-Agent）

⚠️ 面试必答：
"Agent 设计六原则——工具原子、
 上下文精选、人工接管、可观测、
 幂等、渐进复杂度。"
```

### 5.2 上下文预算

```
Agent 上下文管理：
  窗口 = 输入（指令 + 历史 + 检索 + 工具结果）+ 输出
  预算分配：
    指令 10%、历史 20%、检索 40%、工具结果 20%、输出 10%

⚠️ 面试必答：
"上下文要'预算管理'——
 检索与历史是大头，超窗口
 用摘要压缩与精选。"
```

## 6. 人工接管与可观测

### 6.1 人工接管（产品能力）

```
人工接管场景：
  ① 资金操作（转账/退款/支付）
  ② 权限变更（提权/授权）
  ③ 敏感操作（删除数据/发公告）
  ④ 低置信度决策（模型不确定）

实现：
  工具返回"待确认" → 前端展示审批 → 用户确认后执行

⚠️ 面试必答：
"人工接管是产品能力不是故障兜底——
 高危操作设计'待审批'状态，
 把 AI 建议与人审批结合。"
```

### 6.2 Agent 可观测

```
Agent 可观测三要素：
  ① 思考过程（Thought 记录）
  ② 工具调用（调了哪个/参数/结果/耗时）
  ③ 成本指标（Token 消耗/模型费用）

工具：OpenTelemetry 链路 + 结构化日志 + LangSmith 类平台

⚠️ 面试必答：
"Agent 可观测 = 思考 + 工具 + 成本全记录——
 调试 Agent 与调试代码一样需要
 完整的执行轨迹。"
```

---

> 🎯 **核心要点**：Agent 体系 = **四组件**（规划/记忆/工具/反思）+ **三模式**（ReAct 80%/Plan 15%/Multi 5%）+ **记忆三层**（短期/长期/工作）+ **六原则**（原子/精选/接管/观测/幂等/渐进）+ **人工接管**（高危必审批）。"能单 Agent 不双、能 ReAct 不 Plan"是复杂度控制原则。
