## 1. 可靠性工程

### 1.1 异常分类与处理

```
LLM 调用的异常四类：
  ① 超时（模型慢/网络）
  ② 限流（429：触发速率限制）
  ③ 内容过滤（敏感/违规）
  ④ 解析失败（输出格式异常）

处理策略：
  重试（超时/限流，指数退避）
  熔断（连续失败快速失败）
  降级（模型 A → 模型 B）
  兜底（预设回答）

⚠️ 面试必答：
"LLM 异常四类——超时/限流/过滤/解析，
 策略 = 重试（退避）+ 熔断 + 降级 + 兜底。"
```

### 1.2 Resilience4j 集成

```java
// ⚠️ 重试 + 熔断（Resilience4j / Sentinel）
@Service
public class AiGatewayService {

    // ① 重试配置（指数退避）
    private final Retry retry = Retry.ofDefaults("ai-retry");

    // ② 熔断配置
    private final CircuitBreaker cb = CircuitBreaker.ofDefaults("ai-cb");

    public String callWithResilience(String prompt) {
        return Retry.decorateSupplier(retry, () ->
                CircuitBreaker.decorateSupplier(cb, () ->
                    chatModel.call(prompt)))       // ⚠️ 装饰器链
            .get();
    }
}

// ③ 降级（模型路由兜底）
public String callWithFallback(String prompt) {
    try {
        return flagshipClient.prompt().user(prompt).call().content();
    } catch (Exception e) {
        log.warn("旗舰模型失败，降级小模型", e);
        return cheapClient.prompt().user(prompt).call().content();
    }
}
```

> 🎯 **要点**：可靠性三件套——重试（退避）、熔断（快速失败）、降级（备用模型）。**LLM 是外部依赖，必须按外部依赖治理**。

## 2. 成本控制

### 2.1 成本构成与优化

```
LLM 成本构成：
  Token 费用（输入 + 输出）
  模型等级（旗舰 vs 小模型差 10 倍+）
  推理模型（token 消耗 3-10 倍）

优化五手段：
  ① 精简 Prompt（去掉冗余指令）
  ② 历史摘要压缩（长对话）
  ③ 模型路由（简单任务小模型）
  ④ RAG 精选（少而准的上下文）
  ⑤ 缓存（重复问题命中缓存）

⚠️ 面试必答：
"成本五手段——精简/压缩/路由/精选/缓存；
 推理模型成本高 3-10 倍，异步化 +
 流式展示思考过程。"
```

### 2.2 成本监控

```java
// 每次调用记录 token/成本
public class UsageTracker {
    // 从响应获取用量
    public void track(ChatResponse response, String model, String task) {
        TokenUsage usage = response.getMetadata().getUsage();
        metrics.counter("ai.tokens", "model", model, "task", task)
               .increment(usage.getTotalTokens());
        metrics.counter("ai.cost", "model", model)
               .increment(estimateCost(model, usage));
    }
}
```

## 3. 安全与合规

### 3.1 AI 安全风险矩阵

| 风险 | 场景 | 防御 |
|------|------|------|
| Prompt 注入 | 用户劫持指令 | 过滤 + 权限最小化 |
| 数据泄露 | 敏感数据进 Prompt | 脱敏 + 分类 |
| 越权工具调用 | 模型被诱导调危险工具 | 工具鉴权 + 人工接管 |
| 内容违规 | 生成违规内容 | 输入/输出过滤 |
| 供应链 | 依赖/模型漏洞 | SBOM + 扫描 |

### 3.2 合规落地

```
金融/政务合规场景：
  ① PII 脱敏：手机号/身份证进 Prompt 前脱敏
  ② 投资建议拦截：金融场景禁止 AI 直接给建议
  ③ 审计日志：每次调用记录（谁/什么/何时/成本）
  ④ 数据不出域：私有化部署（模型 + 向量库内网）

⚠️ 面试必答：
"AI 合规 = 脱敏 + 拦截 + 审计 + 私有化——
 PII 脱敏、高危内容拦截、全调用审计、
 敏感行业私有化部署。"
```

## 4. 可观测性

### 4.1 AI 专属指标

```
AI 可观测指标（在常规指标之上）：
  Token 消耗（输入/输出/总量）
  模型延迟（P95/P99）
  错误率（超时/限流/过滤分类）
  成本（按模型/业务维度）
  幻觉率/事实准确率（质量指标）
  用户反馈（点赞/点踩）

⚠️ 面试必答：
"AI 可观测 = 常规（延迟/错误）+ AI 专属
 （Token/成本/幻觉率/用户反馈）——
 模型质量与成本都要可度量。"
```

### 4.2 全链路追踪

```
AI 链路追踪：
  HTTP 请求 → Controller → ChatClient → 模型调用 → 工具调用
  每段埋点（OTel Span）：
    LLM Span：模型名/token/耗时
    Tool Span：工具名/参数/结果
  → 问题定位：哪段慢？哪个工具错？成本花在哪？

⚠️ 面试必答：
"AI 链路 = HTTP + LLM + Tool 三段追踪——
 模型调用与工具调用都要埋点，
 才能定位'慢在哪、错在哪、钱花在哪'。"
```

## 5. 模型治理

### 5.1 模型管理

```
模型治理四件事：
  ① 版本管理：模型升级可回滚（灰度）
  ② 配置隔离：Dev/Staging/Prod 独立模型参数
  ③ 效果评估：离线评测集 + 在线 A/B
  ④ 降级预案：主模型故障 → 备选模型

⚠️ 面试必答：
"模型治理 = 版本可回滚 + 环境隔离 +
 效果评测 + 降级预案——
 模型也是要'上线管理'的组件。"
```

### 5.2 评测体系

```
模型效果评测：
  离线：固定评测集（问答对）打分
  在线：A/B 对比（新旧模型分流）
  人工：抽样人工评审
  指标：准确率/相关性/幻觉率/延迟

⚠️ 面试必答：
"评测 = 离线评测集 + 在线 A/B + 人工抽样；
 模型升级必须有评测证据（不凭感觉换模型）。"
```

> 🎯 **核心要点**：生产工程化 = **可靠性**（重试/熔断/降级）+ **成本**（五手段 + 监控）+ **安全合规**（脱敏/拦截/审计/私有化）+ **可观测**（Token/成本/幻觉 + 三段链路）+ **模型治理**（版本/评测/降级）。"LLM 是外部依赖，按外部依赖治理"是生产化第一原则。
