## 1. 数据层全景

```
数据层四大件：
  ① MySQL：关系数据（主存储）
  ② Redis：缓存/会话/分布式（加速）
  ③ Elasticsearch：搜索/分析（扩展）
  ④ MQ：异步数据流（解耦）

关系：
  Redis 挡流量（缓存）→ MySQL 落库（主存）
  ES 查全文 → MySQL 存事实
  MQ 削峰 → 数据最终一致

⚠️ 面试必答：
"数据层分工——MySQL 事实、Redis 速度、
 ES 搜索、MQ 解耦；
 '缓存 + 主库 + 索引 + 异步'是企业数据架构。"
```

## 2. MySQL 核心考点

```
MySQL 面试三大主线：
  ① 索引：B+Tree、聚簇/二级、最左前缀、覆盖索引
  ② 事务：ACID、隔离级别、MVCC、锁
  ③ 优化：EXPLAIN、慢查询、索引失效

⚠️ 面试必答：
"MySQL 三线——索引（B+Tree + 回表 +
 最左前缀）、事务（MVCC + 隔离级别 +
 Next-Key）、优化（EXPLAIN + 慢查询）。"
```

## 3. Redis 核心应用

### 3.1 五大场景

```
Redis 五大场景：
  ① 缓存（读多写少热点）
  ② 分布式锁（setnx + 过期）
  ③ 分布式会话（Spring Session）
  ④ 计数器（incr：点赞/库存）
  ⑤ 排行榜（ZSet 有序集合）

⚠️ 面试必答：
"Redis 五场景——缓存/锁/会话/计数/排行；
 缓存三难（穿透/击穿/雪崩）必考。"
```

### 3.2 Redis 数据结构

| 结构 | 特点 | 场景 |
|------|------|------|
| String | 简单键值 | 缓存/计数/锁 |
| Hash | 字段级 | 对象存储 |
| List | 队列 | 消息/时间线 |
| Set | 去重 | 标签/好友 |
| ZSet | 有序去重 | 排行榜 |

```
⚠️ 持久化与高可用：
  RDB（快照）+ AOF（日志）
  主从 + 哨兵（自动切换）
  Cluster（分片扩容）

⚠️ 面试必答：
"Redis 三问——数据结构选型、
 缓存三难解决、高可用（哨兵/集群）。"
```

## 4. ORM 框架选型

### 4.1 MyBatis vs JPA

| 维度 | MyBatis | JPA |
|------|:---:|:---:|
| 核心 | SQL 可控 | 对象映射 |
| 复杂 SQL | ✅ 灵活 | ⚠️ 复杂 |
| 团队习惯 | 国内主流 | 国外主流 |
| 性能 | SQL 可控 | 需优化 |
| 自动 CRUD | Mapper XML | ✅ 接口推导 |

```
⚠️ 面试必答：
"国内互联网 MyBatis（SQL 可控）、
 国外 JPA（对象思维）——
 选型看团队与场景，无绝对优劣。"
```

### 4.2 关键实践

```
✅ MyBatis：#{} 预编译（防注入）
✅ JPA：方法名推导 + @Query
✅ 连接池：HikariCP（默认）
✅ 事务：@Transactional（失效五场景）
✅ 多数据源：@DS 注解

⚠️ 面试必答：
"数据访问实践五条——预编译防注入、
 连接池调优、事务声明式、
 多数据源读写分离、慢 SQL 治理。"
```

## 5. 缓存体系

### 5.1 缓存分层

```
缓存分层（由快到慢）：
  ① 本地缓存（Caffeine，进程内）
  ② Redis（分布式缓存）
  ③ 数据库（最终存储）

场景选择：
  单机热点：Caffeine（快）
  共享数据：Redis（一致性）
  热点 + 共享：二级缓存（Caffeine + Redis）

⚠️ 面试必答：
"缓存分层——本地（Caffeine）最快、
 Redis 共享、DB 兜底；
 二级缓存要处理一致性（先删 Redis +
 本地过期）。"
```

### 5.2 缓存一致性

```
缓存与数据库一致方案：
  ① Cache Aside：先更库再删缓存（推荐）
  ② 延迟双删：删 → 等 → 删（极端一致）
  ③ 消息异步删：MQ 通知删缓存
  ④ 最终一致：Binlog 订阅（Canal）

⚠️ 面试必答：
"一致性方案四选——Cache Aside 默认、
 延迟双删/异步删增强；
 强一致场景（金额）慎用缓存。"
```
