## 2. MQ 核心场景

### 2.1 四大价值

```
MQ 四大价值：
  ① 异步：耗时操作异步化（响应更快）
  ② 解耦：生产者消费者独立演进
  ③ 削峰：洪峰请求排队缓冲
  ④ 广播：一对多事件分发

⚠️ 面试必答：
"MQ 四价值——异步/解耦/削峰/广播；
 典型：下单发短信（异步）、
 秒杀削峰、订单事件分发。"
```

### 2.2 使用场景示例

```
下单流程（MQ 优化前后）：
  同步：下单 → 扣库存 → 发短信 → 记日志 → 返回（全做完才响应）
  异步：下单 → 返回成功 → MQ 异步发短信/日志

⚠️ 面试必答：
"'该异步的异步'是架构优化第一手段——
 核心链路同步、非核心（通知/日志）异步。"
```

## 3. RabbitMQ vs Kafka

| 维度 | RabbitMQ | Kafka |
|------|:---:|:---:|
| 定位 | 业务消息 | 大数据流 |
| 协议 | AMQP（功能全） | 自定义（高性能） |
| 吞吐 | 万级 | **百万级** |
| 可靠性 | 功能丰富（确认/事务） | 高（副本） |
| 顺序 | ✅ 单队列有序 | 分区内有序 |
| 延迟 | 低（毫秒） | 高（秒级批量） |
| 场景 | 业务解耦/任务队列 | 日志/埋点/数据管道 |

```
⚠️ 面试必答：
"RabbitMQ 业务消息（功能全、延迟低）、
 Kafka 大数据流（吞吐高、批量）；
 电商订单 RabbitMQ、日志埋点 Kafka。"
```

## 4. 消息可靠性

### 4.1 不丢失三阶段

```
消息不丢失三阶段：
  ① 生产端：Confirm 确认（发送成功回调）
  ② 服务端：持久化（RabbitMQ 落盘 + 镜像队列）
  ③ 消费端：手动 ACK（处理成功才确认）

⚠️ 面试必答：
"不丢失 = 生产确认 + 服务端持久化 +
 消费手动 ACK——三端配合；
 任一环节用默认（自动 ACK）都可能丢。"
```

### 4.2 重复消费与顺序

```
① 重复消费：MQ 至少一次语义 → 消费者幂等
   （唯一键去重/状态机）

② 消息顺序：
   RabbitMQ：单队列单消费者（简单但并发受限）
   Kafka：同一 key 进同一分区（业务顺序）

③ 消息积压：消费者扩容 + 临时队列

⚠️ 面试必答：
"可靠三问——不丢失（三端确认）、
 不重复（消费幂等）、不乱序（单队列/分区）；
 积压 = 扩容消费者。"
```

## 5. Elasticsearch 应用

### 5.1 ES 是什么

```
ES = 分布式搜索与分析引擎（Lucene 封装）
  全文检索（分词 + 倒排索引）
  聚合分析（日志/统计）
  近实时（秒级可见）

⚠️ 面试必答：
"ES 核心 = 倒排索引（词 → 文档）——
 全文搜索与聚合分析的标配；
 MySQL LIKE 无法胜任大数据量搜索。"
```

### 5.2 ES 核心概念

```
核心概念：
  Index（索引）≈ 数据库表
  Document（文档）≈ 行（JSON）
  Shard（分片）：水平扩展
  Replica（副本）：高可用

查询类型：
  全文：match（分词）
  精确：term（不分词）
  复合：bool（must/should）
  聚合：aggs（分组统计）

⚠️ 面试必答：
"ES 三概念——Index/Document/分片副本；
 查询四类——match 全文、term 精确、
 bool 复合、aggs 聚合。"
```

### 5.3 ES vs MySQL

| 维度 | MySQL | ES |
|------|:---:|:---:|
| 场景 | 事务存储 | 搜索分析 |
| 查询 | 结构化 SQL | 全文 + 聚合 |
| 一致性 | 强 | 近实时 |
| 组合 | 事实数据 | 搜索索引 |

```
⚠️ 面试必答：
"MySQL 存事实、ES 建索引——
 双写或 Canal 同步（MySQL → ES）；
 搜索场景标配组合。"
```
