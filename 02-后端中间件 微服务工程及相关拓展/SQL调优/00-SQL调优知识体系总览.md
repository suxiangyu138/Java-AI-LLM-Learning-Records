# 00 - SQL 调优知识体系总览

> 🐬 SQL 调优 = **先看懂执行计划，再动手优化，最后验证效果**——不是背「索引失效口诀」，是理解优化器怎么想。本系列定位**「调优实战方法论」**：执行原理 → EXPLAIN → 索引实战 → 慢查询治理 → JOIN/分页 → 锁事务，与 [[01-MySQL]] 体系（数据库全栈）互补：**MySQL 系列讲「数据库是什么」，本系列讲「查询怎么变快」**。

> 🎯 本系列共 **8 篇**：原理 → 工具 → 三大优化场景 → 治理流程 → 面试，覆盖「看懂 → 会用 → 会治 → 会讲」全链路。

## 5. 核心概念速查

| 概念 | 一句话解释 |
|------|-----------|
| **成本优化器** | 基于代价估算选执行计划（索引扫描 vs 全表扫描谁便宜） |
| **统计信息** | 优化器决策依据（ANALYZE TABLE 更新键分布） |
| **EXPLAIN** | 查看执行计划的命令（type/key/rows/Extra 四要素） |
| **type 金字塔** | system > const > eq_ref > ref > range > index > ALL |
| **最左前缀** | 联合索引 (a,b,c) 查询必须从 a 开始才生效 |
| **覆盖索引** | 索引包含查询所需全部列——无需回表 |
| **ICP 索引下推** | 索引层先过滤再回表（Extra: Using index condition） |
| **慢查询日志** | 记录超阈值 SQL（long_query_time）——调优入口 |
| **驱动表** | JOIN 外层表——小表驱动大表原则 |
| **Hash Join** | 8.0.18+ 等值 JOIN 新算法（大表 JOIN 性能飞跃） |
| **深分页** | OFFSET 大 → 扫描丢弃大量行——用游标/延迟关联 |
| **间隙锁** | RR 隔离级别防幻读的锁（性能开销 + 死锁源） |
| **死锁** | 互等锁——innodb 自动检测回滚一事务 |
| **执行基线** | 优化前后对比的量化指标（耗时/QPS/扫描行数） |
