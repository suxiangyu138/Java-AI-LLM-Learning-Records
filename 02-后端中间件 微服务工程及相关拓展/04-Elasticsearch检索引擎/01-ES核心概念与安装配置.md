## 1. Elasticsearch 是什么

### 1.1 概述

| 属性 | 说明 |
|------|------|
| 全称 | Elasticsearch（简称 ES） |
| 底层引擎 | Apache Lucene |
| 开发语言 | Java |
| 数据格式 | JSON（RESTful API） |
| 核心能力 | 分布式、近实时存储、检索、聚合分析 |
| 典型场景 | 全文搜索、日志分析（ELK）、商品搜索、RAG 语义检索 |
| 开源协议 | Elastic License 2.0 / SSPL（7.x 起双协议）|

### 1.2 企业架构位置

```text
用户请求 -> Nginx -> SpringBoot 应用 -> MySQL（写）
                         ↓
                    Elasticsearch（读/搜索）
                         ↑
              Logstash/Canal 同步数据
                         ↑
              Kafka -> Flink（实时 ETL 可选）
```

### 1.4 ES 核心优势

| 优势 | 说明 |
|------|------|
| 倒排索引 | 全文搜索性能碾压数据库 LIKE |
| 天然分布式 | 水平扩展，分片自动分配 |
| RESTful API | 基于 HTTP/JSON，任何语言可用 |
| 近实时搜索 | 默认 1 秒内可搜索到新数据 |
| 强大聚合 | Bucket + Metric 多级聚合分析 |
| 高可用 | 副本机制，节点故障自动恢复 |
| 生态丰富 | ELK + Beats + 大量插件 |

### 1.5 典型应用场景：电商搜索、日志分析（ELK）、APM、安全分析 SIEM、RAG 语义检索（8.x dense_vector）。

## 2. ES vs MySQL 核心概念对照

### 2.1 概念映射表

| Elasticsearch | MySQL 类比 | 说明 |
|---------------|-----------|------|
| **Cluster（集群）** | 数据库集群 | 多节点组成，对外统一服务 |
| **Node（节点）** | MySQL 实例 | 集群中的一个 ES 进程 |
| **Index（索引）** | Database / Table | 逻辑命名空间，文档集合 |
| **Document（文档）** | Row（行） | JSON 格式的单条数据 |
| **Field（字段）** | Column（列） | 文档中的键值对 |
| **Mapping（映射）** | Schema（表结构） | 定义字段类型、分词器 |
| **Shard（分片）** | 分库分表 | 索引拆分为分片分布式存储 |
| **Replica（副本）** | 主从复制 | 分片冗余备份，提升可用性 |
| **Inverted Index（倒排索引）** | B+Tree 索引 | 全文搜索的核心数据结构 |
| **DSL（查询语言）** | SQL | 基于 JSON 的查询语言 |

### 2.2 完整示例对照

```sql
-- MySQL: users 表
-- id  | name | age | desc
-- 1   | 张三 | 25  | 计算机专业学生
```

```json
// ES 对应 Document
{
  "_index": "user_index",
  "_id": "1",
  "_score": 1.0,
  "_source": {
    "id": 1,
    "name": "张三",
    "age": 25,
    "desc": "计算机专业学生"
  }
}
```

### 2.3 操作对照

| 操作 | MySQL | ES |
|------|-------|----|
| 查询 | `SELECT * FROM user WHERE name = '张三'` | `GET /user_index/_search { "query": { "match": { "name": "张三" } } }` |
| 新增 | `INSERT INTO user (name, age) VALUES ('张三', 25)` | `POST /user_index/_doc { "name": "张三", "age": 25 }` |
| 更新 | `UPDATE user SET age = 26 WHERE id = 1` | `POST /user_index/_update/1 { "doc": { "age": 26 } }` |
| 删除 | `DELETE FROM user WHERE id = 1` | `DELETE /user_index/_doc/1` |
| 全文搜索 | `SELECT * FROM user WHERE desc LIKE '%计算%'` | `GET /user_index/_search { "query": { "match": { "desc": "计算" } } }` |

> 💡 ES 不能替代 MySQL：不支持事务、不支持 JOIN、写入不是立即可见的（近实时）。

## 3. 集群架构原理

### 3.1 Cluster（集群）

多个 Node 通过 `cluster.name` 标识同一个集群，具备自动发现、自动分片分配、负载均衡。

```text
┌──────────────────────────────────────────────┐
│             Cluster: my-es-cluster             │
│                                                │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐ │
│  │ Node-1   │    │ Node-2   │    │ Node-3   │ │
│  │  Master  │    │  Data    │    │  Data    │ │
│  │  Data    │    │          │    │          │ │
│  └──────────┘    └──────────┘    └──────────┘ │
│         │              │              │        │
│         └──────────────┴──────────────┘        │
│                    9300 TCP                     │
└──────────────────────────────────────────────┘
                         │
               HTTP 9200 │ REST API
                         ▼
                   Client / Kibana
```

### 3.2 Node（节点）角色

ES 7.x+ 节点角色可组合配置：

| 角色 | 配置 | 职责 | 生产建议 |
|------|------|------|---------|
| **Master** | `node.roles: [master]` | 管理集群元数据、分配分片 | 3 个专属 Master 节点 |
| **Data** | `node.roles: [data]` | 存储数据，执行搜索/聚合 | 按数据量水平扩展 |
| **Ingest** | `node.roles: [ingest]` | 数据预处理 pipeline | 可选 |
| **Coordinating** | `node.roles: []` | 请求路由、结果聚合 | 大集群可配置专属 Coordinating |

```yaml

### 3.3 Shard（分片）与 Replica（副本）

```text
Index: user_index（3 主分片 + 1 副本，共 6 个分片）

    Node-1          Node-2          Node-3
  ┌─────────┐    ┌─────────┐    ┌─────────┐
  │ P0  R1  │    │ P1  R2  │    │ P2  R0  │
  └─────────┘    └─────────┘    └─────────┘

  P = Primary Shard（主分片，写入口）
  R = Replica Shard（副本分片，读 + 故障转移）
```

**核心公式：** `节点数 >= 主分片数 * (副本数 + 1)`

| 概念 | 说明 |
|------|------|
| **Primary Shard** | 主分片，写入入口，创建索引时指定，不可修改 |
| **Replica Shard** | 副本分片，主分片的完整副本，支持读请求 |
| **分片分配** | Master 根据节点负载自动分配分片 |
| **故障转移** | 主分片所在节点宕机，副本自动提升为主分片 |

> ⚠️ **主分片数量创建后不可修改**（路由算法依赖 `hash(_id) % number_of_primary_shards`），修改会导致数据错位。需修改时必须通过 Reindex 迁移到新索引。

### 3.4 数据写入流程

```text
1. 客户端发送写请求到任意节点（Coordinating Node）
2. 路由计算：shard = hash(document_id) % number_of_primary_shards
3. 请求转发到 Primary Shard 所在节点
4. Primary 写入成功后，并行复制到所有 Replica
5. 所有 Replica 确认后返回成功给客户端
```

### 3.5 近实时搜索原理

```text
写入 → Memory Buffer → Refresh(1s) → Segment(可搜索)
                             ↓
                     Translog(持久化) → Flush → 磁盘

Memory Buffer: 内存缓冲区，写入后暂存
    ↓ (默认 1 秒执行一次 Refresh)
Segment: 不可变的倒排索引文件，此时数据可搜索
    ↓ (Translog 已持久化到磁盘，防崩溃丢失)
Flush: Segment 从文件系统缓存刷到磁盘持久化
```

| 概念 | 默认值 | 说明 |
|------|:------:|------|
| **Refresh** | 1s | Memory Buffer 写入 Segment，数据变为可搜索 |
| **Flush** | 30min / 512MB | Segment 从缓存刷到磁盘 |
| **Translog** | 每次写入 fsync | 类似 MySQL binlog，崩溃后恢复 |
| **Segment Merge** | 后台自动 | 合并小 Segment，真正删除文档、释放空间 |

> 💡 调整 `refresh_interval` 可优化写入性能。批量导入时设为 `-1`（关闭），导入完成后再恢复。

## 4. Docker 部署

### 4.1 单节点（开发环境）

```bash
docker run -d \
  --name es \
  -p 9200:9200 \
  -p 9300:9300 \
  -e "discovery.type=single-node" \
  -e "ES_JAVA_OPTS=-Xms512m -Xmx512m" \
  -e "xpack.security.enabled=false" \
  elasticsearch:7.17.0
```

验证：

```bash
curl http://localhost:9200

# 返回示例
{
  "name" : "6a8e4f5b9c12",
  "cluster_name" : "elasticsearch",
  "cluster_uuid" : "xxxx",
  "version" : { "number" : "7.17.0" }
}
```

### 4.2 完整版：ES + Kibana + IK 分词器

```yaml
# docker-compose.yml
version: '3'
services:
  elasticsearch:
    image: elasticsearch:7.17.0
    container_name: es
    environment:
      - discovery.type=single-node
      - ES_JAVA_OPTS=-Xms512m -Xmx512m
      - xpack.security.enabled=false
    ports:
      - "9200:9200"
      - "9300:9300"
    volumes:
      - es_data:/usr/share/elasticsearch/data
  kibana:
    image: kibana:7.17.0
    container_name: kibana
    ports:
      - "5601:5601"
    environment:
      - ELASTICSEARCH_HOSTS=http://elasticsearch:9200
    depends_on:
      - elasticsearch

volumes:
  es_data:
```

启动并安装 IK 分词器：

```bash
docker-compose up -d

# 安装 IK 分词器
docker exec -it es bash -c "
  ./bin/elasticsearch-plugin install \
    https://github.com/medcl/elasticsearch-analysis-ik/releases/download/v7.17.0/elasticsearch-analysis-ik-7.17.0.zip
"
docker restart es

# 验证
curl http://localhost:9200
# Kibana: http://localhost:5601
```

### 5.1 前置要求

```bash
# ES 不能以 root 用户运行，必须先创建用户
useradd es
echo "password" | passwd --stdin es

# 配置系统限制
cat >> /etc/security/limits.conf << EOF
es soft nofile 65536
es hard nofile 65536
es soft nproc 4096
es hard nproc 4096
EOF

# 调整虚拟内存
echo "vm.max_map_count=262144" >> /etc/sysctl.conf
sysctl -p
```

### 5.2 安装步骤

```bash
# 1. 下载（根据版本修改下载链接）
wget https://artifacts.elastic.co/downloads/elasticsearch/elasticsearch-7.17.0-linux-x86_64.tar.gz

# 2. 解压
tar -zxvf elasticsearch-7.17.0-linux-x86_64.tar.gz -C /usr/local/
ln -s /usr/local/elasticsearch-7.17.0 /usr/local/elasticsearch

# 3. 更改目录所有者
chown -R es:es /usr/local/elasticsearch-7.17.0
chown -R es:es /usr/local/elasticsearch

# 4. 配置文件
mkdir -p /data/es/{data,logs}
chown -R es:es /data/es

su - es
```

### 5.3 配置 elasticsearch.yml

```yaml
# /usr/local/elasticsearch/config/elasticsearch.yml
cluster.name: my-es-cluster
node.name: node-1
path.data: /data/es/data
path.logs: /data/es/logs
network.host: 0.0.0.0
http.port: 9200
transport.port: 9300
discovery.seed_hosts: ["192.168.1.10", "192.168.1.11"]
cluster.initial_master_nodes: ["node-1", "node-2"]
bootstrap.memory_lock: true
http.cors.enabled: true
http.cors.allow-origin: "*"
```

### 5.4 启动与停止

```bash
# 切换到 es 用户
su - es

# 启动（后台）
cd /usr/local/elasticsearch
./bin/elasticsearch -d -p pid

# 查看日志
tail -f logs/my-es-cluster.log

# 验证
curl http://localhost:9200

# 停止
kill $(cat pid)

# 或者用 systemd（推荐）
```

### 5.5 Systemd 管理

```ini
[Unit]
Description=Elasticsearch
After=network.target

[Service]
Type=forking
User=es
Group=es
LimitNOFILE=65536
LimitNPROC=4096
ExecStart=/usr/local/elasticsearch/bin/elasticsearch -d -p /var/run/elasticsearch.pid
PIDFile=/var/run/elasticsearch.pid

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload && systemctl enable elasticsearch && systemctl start elasticsearch
```

## 7. 核心配置详解

### 7.1 elasticsearch.yml 完整配置

```yaml
# ===================== 集群配置 =====================
cluster.name: my-es-cluster
node.name: node-1
node.roles: [master, data, ingest]

# ===================== 路径配置 =====================
path.data: /data/es/data
path.logs: /data/es/logs

# ===================== 网络配置 =====================
network.host: 0.0.0.0
http.port: 9200
transport.port: 9300

# ===================== 集群发现 =====================
discovery.seed_hosts:
  - 192.168.1.10:9300
  - 192.168.1.11:9300
  - 192.168.1.12:9300
cluster.initial_master_nodes:
  - node-1
  - node-2
  - node-3

# ===================== 生产优化 =====================
bootstrap.memory_lock: true

# ===================== 跨域（Dev Tools 需要）=========
http.cors.enabled: true
http.cors.allow-origin: "*"

# ===================== 线程池 =======================
thread_pool.search.size: 30
thread_pool.write.queue_size: 1000
```

### 7.2 JVM 配置（jvm.options）

```text
# 规则：不超过物理内存 50%，最大 32GB
# 4GB → Xms1g Xmx1g | 8GB → Xms2g Xmx2g | 16GB → Xms4g Xmx4g | 64GB → Xms31g Xmx31g
-Xms4g
-Xmx4g

# GC：7.x 推荐 CMS，8.x 默认 G1GC
-XX:+UseConcMarkSweepGC
```

> ⚠️ 堆内存超过 32GB 时 JVM 切换为普通 OOPs，指针膨胀导致性能下降。

### 7.3 核心端口一览

| 端口 | 协议 | 用途 | 防火墙 |
|:----:|:----:|------|:------:|
| 9200 | HTTP | REST API（客户端、Kibana）| 对外开放 |
| 9300 | TCP | 节点间通信（Transport）| 集群内部 |
| 9600 | HTTP | 性能监控（可选）| 内部管理 |
| 5601 | HTTP | Kibana 管理界面 | 对外开放 |

```json
GET _cluster/health

// 响应
{
  "cluster_name": "my-es-cluster",
  "status": "green",        // green / yellow / red
  "timed_out": false,
  "number_of_nodes": 3,
  "number_of_data_nodes": 3,
  "active_primary_shards": 10,
  "active_shards": 20,
  "relocating_shards": 0,
  "initializing_shards": 0,
  "unassigned_shards": 0
}
```

| 状态 | 含义 | 紧急程度 |
|:----:|------|:--------:|
| `green` | 所有主分片和副本都正常 | 正常 |
| `yellow` | 所有主分片正常，部分副本未分配 | 观察（单节点集群正常）|
| `red` | 部分主分片未分配 | 紧急，数据不可用 |

## 9. 生产部署 Checklist

### 9.1 硬件与系统

| 检查项 | 要求 | 说明 |
|--------|------|------|
| JVM 堆内存 | <= 物理内存的 50%，最大 32GB | 避免指针膨胀 |
| 内存锁定 | `bootstrap.memory_lock: true` | 防止 ES 使用 Swap |
| 文件描述符 | >= 65536 | `/etc/security/limits.conf` |
| 虚拟内存 | `vm.max_map_count >= 262144` | `sysctl -w vm.max_map_count=262144` |
| 磁盘 | SSD，预留 20%+ 空间 | 磁盘满导致节点下线 |
| 禁用 Swap | `swapoff -a` | 性能稳定关键 |
| 网络 | 低延迟（<= 1ms）内网 | 节点间心跳与数据传输 |

### 9.2 架构设计

| 检查项 | 推荐 |
|--------|------|
| Master 节点 | 3 个，奇数，角色分离 |
| 分片大小 | 单分片 20-50GB |
| 副本数 | 至少 1，数据重要 >= 2 |
| 索引模板 | 统一管理 Mapping 和 Settings |
| 别名 | 应用层使用别名而非索引名 |

## 10. 面试核心要点

| 问题 | 答案 |
|------|------|
| **ES 为什么快？** | 倒排索引 + 内存 FST 词典 + 分片并行搜索 |
| **为什么主分片数不可修改？** | 路由公式 `hash(_id) % num_shards`，修改会导致数据错位 |
| **Refresh 和 Flush 区别？** | Refresh：数据变为可搜索；Flush：数据持久化到磁盘 |

| **Master 节点职责？** | 集群元数据管理、分片分配、节点增删 |
| **Green / Yellow / Red 含义？** | Green=全好；Yellow=副本缺失；Red=主分片缺失 |
| **ES 能替代 MySQL 吗？** | 不能。不支持事务/JOIN/一致性，定位是搜索引擎 |
| **单分片最佳大小？** | 20-50GB |
