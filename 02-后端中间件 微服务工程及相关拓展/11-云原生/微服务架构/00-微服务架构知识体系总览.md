# 00 - 微服务架构知识体系总览

## 4. 核心概念速查

| 概念 | 一句话解释 |
|------|-----------|
| **限界上下文** | DDD 的子域边界——按业务能力拆分服务的依据 |
| **服务粒度宁粗勿细** | 初期 5-8 个服务——拆分容易合并难 |
| **Nacos** | 注册中心 + 配置中心（AP/CP 可切换） |
| **Spring Cloud Gateway** | 响应式网关（吞吐量为 Zuul 的 1.5 倍） |
| **Sentinel** | 流量防护（流控/熔断/系统保护）——规则需持久化 Nacos |
| **Seata AT 模式** | 分布式事务（自动生成回滚 SQL——业务侵入最小） |
| **事务消息** | RocketMQ 最终一致性（本地事务 + 消息原子性） |
| **雪崩效应** | 一个服务故障 → 级联放大 → 全系统瘫痪 |
| **超时链路铁律** | A 超时 > B 超时 + B→C 耗时；网关 > 下游最大超时 |
| **双层网关** | K8s Ingress（TLS/域名）+ Spring Cloud Gateway（业务路由） |
| **服务网格** | Istio/ASM——sidecar 接管治理（无侵入迁移） |
| **AP vs CP** | 可用性优先 vs 一致性优先（微服务默认 AP） |

## 5. 一图看懂：微服务架构全景（2026）

```text
微服务架构拓扑（Spring Cloud Alibaba + K8s）
┌─────────────────────────────────────────────────────┐
│ 入口层：K8s Ingress（TLS/域名/全局限流）                │
├─────────────────────────────────────────────────────┤
│ 网关层：Spring Cloud Gateway（鉴权/限流/路由）          │
├─────────────────────────────────────────────────────┤
│ 服务层：业务微服务（order/user/payment...）             │
│   ├── Nacos（注册 + 配置）                            │
│   ├── OpenFeign（服务调用）+ Sentinel（熔断限流）       │
│   └── Seata（分布式事务）/ 消息队列（异步解耦）          │
├─────────────────────────────────────────────────────┤
│ 数据层：分布式数据库/缓存（各服务独立库）                 │
├─────────────────────────────────────────────────────┤
│ 可观测：Micrometer + Prometheus + Grafana + 链路追踪   │
└─────────────────────────────────────────────────────┘
```
