## 1. 磁盘日常管理

> **背景**：磁盘管理 = 使用率监控 + 大文件清理 + 轮转防满。
> **目的**：掌握日常管理手段。
> **适用范围**：所有 Linux 服务器。

```bash
# ① 使用率检查
df -h                     # 人类可读
df -i                     # inode 使用率（⚠️ 也重要！）

# ② 目录大小定位
du -sh *                  # 当前目录各子目录大小
du -sh /var/log/*         # 指定目录
du -h --max-depth=1 /     # 根目录一层

# ③ 清理常规项
# 旧内核（占用大）
dnf remove --oldinstallonly   # RHEL/CentOS
# 过期日志
find /var/log -name "*.gz" -mtime +30 -delete
# 无用备份/缓存
find /tmp -type f -mtime +7 -delete

# ④ 分区规划
# 数据盘/日志盘/备份盘独立（防相互干扰）
# 根分区预留足够（系统运行）
```

```text
磁盘管理要点
├── ① 阈值：使用率 <85% 安全、>90% 告警（见 01 篇）
├── ② inode 也监控：小文件多会耗尽 inode（df -i）
├── ③ 日志轮转：logrotate 防日志满（见 03 篇）
├── ④ 定期清理：旧内核/过期日志/无用备份
└── ⑤ 金句：磁盘管理 = 「监控 + 清理 + 轮转」日常三件
```

## 2. 定位大文件

```text
找大文件三步（磁盘快满时）
├── ① du 目录定位：
│   du -h --max-depth=1 / | sort -rh | head -10
│   # 一层层往下（找到占用大的目录）
├── ② find 大文件：
│   find / -type f -size +100M -exec ls -lh {} \;
│   # 直接找 >100M 的文件
├── ③ 分析后决策：
│   ├── 日志 → 轮转/清理
│   ├── 备份 → 归档/迁移
│   ├── 数据库 → 迁移/优化
│   └── 删除前确认（先备份！）
└── ④ 金句：先定位再清理（不盲目删）

命令速查
du -sh /var/lib/docker    # Docker 占用（常见大头）
docker system prune       # Docker 清理
du -sh ~/.cache           # 用户缓存
find /var/log -size +500M  # 超大日志
```

## 3. 磁盘满的排查

> ⚠️ **磁盘满但 df 未显示满**（经典故障）：被删除但仍被进程占用的文件：

```bash
# 症状：写文件报 No space left on device，但 df 显示有空间

# 排查：查找被删除但仍打开的文件
lsof | grep deleted
# java  12345  user  12u  REG  8,1  5.2G  123456 /var/log/app.log (deleted)

# 处理
# ① 确认是哪个进程占用
# ② 重启进程（释放文件）或 truncate 文件
truncate -s 0 /proc/12345/fd/12    # 截断（临时释放）

# 预防
# ① 日志轮转（copytruncate——见 03 篇）
# ② 定期检查 lsof | grep deleted
# ③ 金句：deleted 文件是「看不见的磁盘杀手」
```

```text
磁盘满的其他排查
├── ① inode 满：df -i 显示 100%
│   ├── 小文件太多（缓存/临时文件）
│   └── 清理小文件（find -type f | wc -l 定位）
├── ② 文件系统损坏：mount/fsck
├── ③ 配额限制：quota 检查
└── ④ 金句：磁盘满 = 空间满（df -h）+ inode 满（df -i）两个维度
```

## 4. IO 瓶颈三层排查

> 🎯 **IO 瓶颈三层证据链**（2026 标准方法论）：

```text
三层排查（设备 → 进程 → 文件）
├── 第一层：设备是否繁忙（iostat）
│   ├── iostat -xz 1
│   ├── %util：持续 100% = 设备饱和
│   └── await：>10ms = 响应慢
├── 第二层：哪个进程在读写（pidstat）
│   ├── pidstat -d 1
│   ├── 按读写量排序
│   └── 找到嫌疑进程
├── 第三层：进程在读写什么文件（lsof）
│   ├── lsof -p PID | grep -E 'REG|DIR'
│   └── 定位具体文件
└── 验证：fio 测存储能力基线（见第 5 节）
```

```bash
# 第一层：设备
iostat -xz 1
# avg-cpu:  %user %system %iowait
#           5.0    3.0    40.0     ← %iowait 高 = IO 等待
# Device  rrqm/s wrqm/s r/s w/s rkB/s wkB/s await %util
# sda       0     0   10  50   100  500   25   100  ← %util 100%

# 第二层：进程
pidstat -d 1
# PID   kB_rd/s  kB_wr/s  kB_ccwr/s
# 1234   1024.0   5120.0      0.0    ← 高写进程

# 第三层：文件
lsof -p 1234 | grep -E 'REG.*log'
# java 1234 user 12u REG 8,1 5.2G /var/log/app.log
```

## 5. fio 基线测试

> **背景**：调优前先测存储能力——知道「硬件上限」才知道「差距在哪」。
> **目的**：掌握 fio 基线测试（性能验证依据）。
> **适用范围**：存储调优/容量规划。

```bash
# 安装
yum install fio    # RHEL/CentOS
apt install fio    # Debian/Ubuntu

# 顺序读（大文件场景）
fio --name=seqread --rw=read --bs=1m --size=2g --numjobs=1 \
    --runtime=30 --group_reporting

# 随机读（数据库场景）
fio --name=randread --rw=randread --bs=4k --size=2g \
    --numjobs=4 --runtime=30 --group_reporting

# 随机写（日志/写入密集）
fio --name=randwrite --rw=randwrite --bs=4k --size=2g \
    --runtime=30 --group_reporting

# 输出关键指标
# IOPS（每秒 IO 次数）/ BW（带宽 MB/s）
# 对比：SSD 随机读 10万+ IOPS vs HDD 数百 IOPS
```

```text
fio 基线价值
├── ① 知道硬件上限（存储能力边界）
├── ② 调优前后对比（效果验证）
├── ③ 容量规划（新业务估算）
└── ④ 金句：基线 = 「性能的参照系」——没有基线无法判断
```

## 6. 备份策略 3-2-1

> 🎯 **3-2-1 备份铁律**：3 份副本、2 种介质、1 份异地：

```text
3-2-1 原则
├── ① 3 份副本：原件 + 2 份备份
├── ② 2 种介质：本地盘 + 异地/云/磁带
├── ③ 1 份异地：防灾（机房故障/勒索）
└── ④ 金句：备份 = 「数量 × 介质 × 异地」三要素

备份方案
├── rsync 增量备份（常规）
│   rsync -avz --delete /data backup@remote:/backup/
├── 数据库备份（mysqldump/pg_dump + 定时）
├── 快照（云服务器/文件系统）
└── 版本保留（按天/周/月）

⚠️ 关键：备份必须验证可恢复！
├── 定期恢复演练（季度）
├── 备份日志检查（每日）
└── 金句：不能恢复的备份 = 没有备份
```

## 7. 优化顺序

> 🎯 **IO 优化顺序（2026）：错峰 → 限速 → 拆分 → 应用 → 扩容**：

```text
IO 优化五步（从免费到花钱）
├── ① 错峰：备份/批处理移低峰期（免费）
├── ② 限速：ionice 优先级（免费）
│   ionice -c2 -n7 backup.sh    # 低优先级
├── ③ 拆分：数据/日志/备份分盘（低成本）
│   ├── 避免相互干扰
│   └── 目录规划（见 02 篇）
├── ④ 应用优化：
│   ├── 慢查询（数据库）
│   ├── 日志级别（减少写）
│   └── 批量读写（减少 IO 次数）
└── ⑤ 扩容：硬件升级（SSD/加盘——最后手段）
→ 金句：先软件优化再硬件投入——扩容是「最后手段」
```

## 8. 核心要点

> 🎯 **核心要点**：
> 1. 日常三件：监控（df -h + df -i）+ 清理（旧内核/日志/备份）+ 轮转
> 2. 大文件定位：du 目录定位 + find >100M（先定位再清理）
> 3. **deleted 文件陷阱**：磁盘满但 df 有空间——`lsof | grep deleted`
> 4. **IO 三层排查**：iostat（设备）→ pidstat（进程）→ lsof（文件）——证据链
> 5. fio 基线：存储能力参照系（调优对比/容量规划）
> 6. **3-2-1 备份**：3 份/2 介质/1 异地——**必须验证可恢复**
> 7. 优化顺序：错峰 → 限速 → 拆分 → 应用 → 扩容（从免费到花钱）
