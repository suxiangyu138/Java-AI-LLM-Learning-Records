## 1. 运维核心总则

> 🎯 **运维四铁律**（2026 共识）：

```text
运维核心总则
├── ① 高危操作提前报备
├── ② 先备份后操作
├── ③ 先测试后上线
├── ④ 严格区分测试/预发/线上环境
└── 金句：运维的「稳」来自「事前准备」——不是临场反应

操作纪律
├── ① 变更留痕：谁/何时/做了什么（台账）
├── ② 操作窗口：高峰期不做变更（业务低峰）
├── ③ 回滚预案：变更前想好「怎么回滚」
├── ④ 双人复核：高危操作双人确认
└── ⑤ 金句：一切变更可回滚——是运维的底线
```

## 2. 每日标准化巡检

> 🎯 **主动巡检代替被动处理**——每天固定巡检，问题早发现：

```text
每日巡检流程（15 分钟）
├── ① 系统资源：
│   ├── CPU/内存/磁盘/IO（见 01 篇）
│   └── 对比昨日（趋势）
├── ② 业务服务：
│   ├── systemctl status（Nginx/MySQL/Redis/Docker）
│   ├── 端口监听（ss -lnp）
│   └── 健康检查（curl /health）
├── ③ 定时任务：
│   ├── crontab -l（检查执行日志）
│   └── /var/log/cron（失败任务）
├── ④ 网络：
│   ├── 连通性（内网/外网）
│   ├── 延迟/丢包
│   └── 异常流量（iftop）
└── ⑤ 安全：
    ├── 登录日志（secure/auth.log——异常登录）
    ├── 磁盘告警（df）
    └── 更新状态（待打补丁）

巡检工具化
├── ① 巡检脚本：check.sh（一键跑全项）
├── ② 结果输出：/tmp/check-$(date).log
├── ③ 定时执行：cron 每天 9:00
└── ④ 金句：巡检 = 「每天 15 分钟，省下 3 小时救火」
```

## 3. 故障排查流程

### 3.1 五步流程（2026 标准）

```text
故障排查五步
├── ① 信息收集：
│   ├── 故障现象（什么不行/影响范围）
│   ├── 时间点（什么时候开始）
│   ├── 变更记录（最近改了什么！）
│   └── 监控数据（指标/日志）
├── ② 问题定位：
│   ├── 从简单到复杂
│   ├── 从外到内（网络 → 系统 → 应用）
│   ├── 从整体到局部
│   └── 二分法缩小范围
├── ③ 根因分析：
│   ├── 问「为什么」到底（5-Why）
│   ├── 区分表象与根因
│   └── 证据链（指标+日志+复现）
├── ④ 实施修复：
│   ├── 先止损（恢复服务）
│   ├── 再根治（修复根因）
│   └── 最小变更 + 可回滚
└── ⑤ 验证确认：
    ├── 功能验证（业务可用）
    ├── 监控观察（持续一段时间）
    └── 复盘沉淀（见第 6 节）
```

### 3.2 排查方向

```text
排查顺序（从外到内）
├── ① 网络层：ping/端口/防火墙
│   ├── 连通性 → 防火墙/安全组
│   └── 延迟 → 网络质量
├── ② 系统层：CPU/内存/磁盘/IO
│   ├── 资源耗尽 → 对应排查（见 01/02/04 篇）
│   └── 负载 → 进程热点
├── ③ 应用层：日志/进程/连接
│   ├── 应用日志（journalctl/应用日志）
│   ├── 进程状态（卡死/崩溃）
│   └── 连接数（线程/连接池）
└── ④ 金句：先看最近变更——80% 故障是变更引起的
```

## 4. 自动化运维

### 4.1 自动化工具链（2026）

```text
自动化工具分层
├── ① Shell 脚本 + cron：简单任务
│   ├── 巡检脚本/备份脚本/清理脚本
│   └── 定时执行（crontab）
├── ② Ansible：配置管理（推荐）
│   ├── Playbook（声明式配置）
│   ├── 幂等（重复执行结果一致）
│   ├── Vault（加密敏感数据）
│   └── 批量（多台机器统一）
├── ③ CI/CD：发布自动化
│   ├── Jenkins/GitLab CI
│   └── 构建 → 测试 → 部署
└── ④ 云自动化：云厂商工具（弹性伸缩/自动快照）

Ansible 示例
# playbook.yml
- hosts: web-servers
  tasks:
    - name: 安装 Nginx
      yum:
        name: nginx
        state: present
    - name: 配置
      template:
        src: nginx.conf.j2
        dest: /etc/nginx/nginx.conf
      notify: restart nginx
  handlers:
    - name: restart nginx
      systemd:
        name: nginx
        state: restarted
```

### 4.2 自动化原则

```text
自动化原则
├── ① 幂等：重复执行结果一致（Ansible 天然）
├── ② 可回滚：脚本/Playbook 可回退
├── ③ 有日志：自动化操作留痕
├── ④ 有告警：自动化失败要通知
└── ⑤ 金句：自动化 = 「把重复交给机器、把判断留给人」
```

## 5. 高可用方案

### 5.1 高可用三层

```text
高可用三层
├── ① 应用层：负载均衡
│   ├── Nginx/HAProxy（七层/四层）
│   ├── 多实例（Nginx 后端多个 Tomcat）
│   └── 健康检查（故障自动摘除）
├── ② 系统层：Keepalived VIP
│   ├── 主备切换（虚拟 IP 漂移）
│   ├── 主挂 → 备接管（秒级）
│   └── 适用：数据库/网关等有状态服务
├── ③ 容器层：Kubernetes
│   ├── Deployment（副本数）
│   ├── HPA（自动伸缩）
│   └── 探针（liveness/readiness）
└── ④ 金句：高可用 = 「多副本 + 自动切换 + 健康检查」
```

### 5.2 方案示例

```bash
# Keepalived VIP（主备切换）
# /etc/keepalived/keepalived.conf（主）
vrrp_instance VI_1 {
    state MASTER
    interface eth0
    virtual_router_id 51
    priority 100
    virtual_ipaddress {
        192.168.1.100          # 虚拟 IP
    }
}
# 备：state BACKUP + priority 90
# 主挂 → VIP 漂移到备（秒级接管）

# Nginx 负载均衡
upstream backend {
    server 192.168.1.11:8080 max_fails=3 fail_timeout=30s;
    server 192.168.1.12:8080 max_fails=3 fail_timeout=30s;
}
server {
    listen 80;
    location / {
        proxy_pass http://backend;
    }
}
```

## 6. 文档与复盘

### 6.1 运维文档

```text
运维文档三件套
├── ① 操作台账：
│   ├── 时间/内容/操作人/结果
│   └── 一切变更留痕
├── ② 服务器清单：
│   ├── 每台机器的角色/服务/端口/负责人
│   └── 交接的「命脉」
├── ③ 知识库：
│   ├── 故障案例（现象/根因/解法）
│   └── 常用命令/脚本库
└── ④ 金句：文档 = 「运维的传承」——人不在了知识还在
```

### 6.2 故障复盘（24 小时内）

```text
故障复盘五问
├── ① 发生了什么？（现象/影响/时间线）
├── ② 为什么发生？（根因——5-Why）
├── ③ 为什么没早发现？（监控盲区）
├── ④ 怎么防止再发生？（改进措施）
├── ⑤ 沉淀了什么？（知识库/脚本/规范）
└── ⑥ 金句：每次故障都是「免费的学习机会」——不复盘 = 白挂一次

复盘产出
├── ① 故障报告（存档）
├── ② 监控补盲（加指标/告警）
├── ③ 流程改进（规范/清单）
├── ④ 知识库更新（案例入库）
└── ⑤ 演练计划（验证改进）
```

## 7. 核心要点

> 🎯 **核心要点**：
> 1. 四铁律：报备/备份/测试/环境隔离——一切变更可回滚
> 2. 每日巡检 15 分钟：资源/服务/任务/网络/安全（主动代替被动）
> 3. 故障五步：收集 → 定位 → 根因 → 修复 → 验证（先看最近变更）
> 4. 自动化：Shell（简单）+ Ansible（配置管理幂等）+ CI/CD（发布）
> 5. 高可用三层：Nginx 负载均衡 + Keepalived VIP + K8s
> 6. 文档三件套：台账/清单/知识库；故障 24 小时内复盘
