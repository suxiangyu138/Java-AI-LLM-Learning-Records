## 1. 监控的四类指标

> **背景**：服务器健康 = CPU/内存/磁盘/网络四类基础指标正常。
> **目的**：掌握指标阈值（何时算问题）。
> **适用范围**：所有 Linux 服务器。

### 1.1 四类指标与阈值

| 指标 | 查看命令 | 安全阈值 | 告警红线 |
|------|---------|---------|---------|
| **CPU** | top/htop/uptime | 单核负载 <0.8 | 使用率持续 >85% |
| **内存** | free -h | 使用率 <80% | >90%（查泄漏） |
| **磁盘** | df -h | 使用率 <85% | >90% 立即清理 |
| **磁盘 IO** | iostat -x 1 | %util <80% | 持续 100%（IO 阻塞） |
| **网络** | iftop/ss | 正常流量 | 异常流量/丢包 |

```text
各指标要点
├── ① CPU：
│   ├── load average（负载）：单核 <0.8/多核 <80%
│   ├── us/sy 占比（用户/系统——sy 高查内核）
│   └── 使用率持续 >85% 需排查（热点进程）
├── ② 内存：
│   ├── free -h：used/buff/cache 区分
│   ├── 使用率 >90%：查泄漏（Java/Python 常驻进程）
│   └── Swap 使用：swap 高 = 内存不足信号
├── ③ 磁盘：
│   ├── df -h：分区使用率
│   ├── 根分区 <15% 可用 → 告警
│   └── 清理：日志/旧内核/备份
├── ④ IO：
│   ├── iostat -x 1：%util 持续 100% = IO 瓶颈
│   ├── await >10ms：响应慢
│   └── 定位：iostat → pidstat → lsof（见 04 篇）
└── ⑤ 网络：
    ├── iftop：实时流量（异常识别）
    ├── 连通性/延迟/丢包测试
    └── 错误率 >1% 告警
```

## 2. 监控工具体系

### 2.1 工具分层

```text
监控工具分层
├── ① 即时排查：top/free/df/iostat/ss
│   ├── 手动查看（应急/巡检）
│   └── 快速定位
├── ② 持续监控：Prometheus + Grafana
│   ├── 指标采集 + 存储 + 告警 + 可视化
│   └── 2026 主流开源方案
├── ③ 云监控：阿里云监控/腾讯云监控
│   └── 云厂商托管（免运维）
└── ④ 金句：即时用命令行、持续用 Prometheus、云上用云监控

Prometheus 架构
├── Node Exporter：采集节点指标（CPU/内存/磁盘/网络）
├── Prometheus Server：拉取 + 存储 + 规则告警
├── Grafana：可视化面板
└── Alertmanager：告警分发
```

### 2.2 即时排查命令

```bash
# CPU
top                     # 实时（按 CPU 排序）
htop                    # 增强版
uptime                  # 负载
mpstat -P ALL 1         # 每核使用率

# 内存
free -h                 # 内存概况
vmstat 1                # 内存/CPU/IO 综合

# 磁盘
df -h                   # 分区使用率
du -sh *                # 目录大小
iostat -x 1             # IO 详细

# 网络
ss -tlnp                # 端口监听
iftop                   # 实时流量
ping/traceroute         # 连通性
```

## 3. 告警设计

### 3.1 低噪音告警三原则（2026）

```text
低噪音告警（避免「狼来了」）
├── ① 阈值合理：
│   ├── CPU >85% 持续 10 分钟（不是瞬时）
│   ├── 磁盘可用 <15%
│   └── 内存可用 <10% 持续 10 分钟
├── ② 持续条件：连续 N 分钟才告警（防抖动）
├── ③ 收敛合并：同源问题合并（防轰炸）
└── ④ 金句：告警是「有人看才有效」——噪音 = 没人看

告警级别
├── P1（严重）：服务不可用 → 立即通知（值班）
├── P2（警告）：资源告急 → 白天处理
├── P3（提示）：趋势预警 → 记录跟踪
└── P4（信息）：正常变化 → 不通知

告警信息规范（必须包含）
├── ① 实例名（哪台机器）
├── ② 指标值（超了多少）
├── ③ 持续时间
└── ④ 排查入口（文档/命令）
```

### 3.2 三条基础告警（推荐起步）

```text
2026 推荐起步告警（低噪音）
├── ① CPU 使用率 >85% 持续 10 分钟
├── ② 根分区可用率 <15%
├── ③ 内存可用率 <10% 持续 10 分钟
└── 先这三条（稳定后加：IO/网络/错误率）
```

## 4. 监控频率与数据保留

```text
监控频率（2026 标准）
├── 关键指标：每分钟（CPU/内存/磁盘）
├── 重要指标：每 5 分钟（IO/网络）
├── 一般指标：每 15 分钟（文件系统等）
└── 金句：频率 = 重要度（关键的多看）

数据保留
├── 实时数据：7 天（Prometheus 内存/短存储）
├── 历史数据：30 天（周趋势/月对比）
├── 告警数据：90 天（审计/复盘）
└── 金句：保留 = 复盘与审计的底气
```

## 5. Prometheus 配置实战

### 5.1 基础配置

```yaml
# prometheus.yml
global:
  scrape_interval: 15s           # 采集频率
  evaluation_interval: 15s       # 规则评估

scrape_configs:
  - job_name: 'node'
    static_configs:
      - targets: ['localhost:9100']    # Node Exporter
        labels:
          env: prod
  - job_name: 'app'
    metrics_path: '/actuator/prometheus'   # Spring Boot 指标
    static_configs:
      - targets: ['app1:8080', 'app2:8080']
```

### 5.2 告警规则

```yaml
# rules/node.yml
groups:
  - name: node-alerts
    rules:
      - alert: HighCPU
        expr: 100 - (avg by(instance) (rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100) > 85
        for: 10m                    # 持续 10 分钟
        labels:
          severity: P1
        annotations:
          summary: "CPU 使用率过高"
          description: "{{ $labels.instance }} CPU >85% 持续 10 分钟"

      - alert: DiskNearlyFull
        expr: (1 - (node_filesystem_avail_bytes{mountpoint="/"} / node_filesystem_size_bytes{mountpoint="/"})) * 100 > 85
        for: 5m
        labels:
          severity: P1
```

## 7. 监控安全

> ⚠️ **监控系统自身需保护**（2026 常见暴露面）：

```text
监控安全要点
├── ① Grafana：强密码 + HTTPS
│   ├── 弱口令 → 面板被篡改/信息泄露
│   └── 2026 事故：Grafana 弱口令被扫
├── ② Prometheus：仅内网访问
│   ├── 不暴露公网（9090）
│   └── 防火墙限制
├── ③ Node Exporter：仅监控服务器拉取
├── ④ 云监控：API Key 权限最小化
└── ⑤ 金句：监控系统是「眼睛」——眼睛被挖更危险
```

## 8. 核心要点

> 🎯 **核心要点**：
> 1. 四类指标阈值：CPU >85%/内存 >90%/磁盘 >85%/IO 100%——告警红线
> 2. 工具分层：即时（top/free/df/iostat）+ 持续（Prometheus + Grafana）
> 3. **低噪音告警三原则**：阈值合理 + 持续条件 + 收敛合并（防狼来了）
> 4. 起步三条告警：CPU/磁盘可用/内存可用（稳定后扩展）
> 5. 频率：关键 1 分钟/重要 5 分钟/一般 15 分钟；保留 7/30/90 天
> 6. 监控安全：Grafana 强密码 HTTPS、Prometheus 内网——**眼睛不能被挖**
