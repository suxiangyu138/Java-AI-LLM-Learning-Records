## 1. 调优方法论

> 🎯 **调优铁律：先监控 → 再调优 → 后验证**——不盲目调参：

```text
调优五步
├── ① 建立基线：fio 测存储/iperf 测网络/压测工具
│   ├── 基线 = 「正常时的性能数字」
│   └── 没有基线无法判断「调优是否有效」
├── ② 定位瓶颈：监控找热点（CPU/内存/IO/网络哪块）
├── ③ 单参数调整：每次只调一个
│   ├── 多参数同调 → 无法归因
│   └── 调前记录当前值
├── ④ 对比验证：调优前后测试数据对比
└── ⑤ 回滚准备：异常立即回滚（记录原值）

⚠️ 原则
├── 不要调你不懂的参数（每个参数都要知道为什么）
├── 生产调整前：测试环境验证
├── 文档记录：改了哪个/为什么/效果
└── 金句：调优是「科学实验」不是「碰运气」
```

## 2. 内核参数优化

> **背景**：/etc/sysctl.conf 控制内核行为——网络/内存/文件系统调优入口。
> **目的**：掌握高频内核参数与安全范围。
> **适用范围**：高并发服务器。

```bash
# /etc/sysctl.conf 核心调优（按场景选择）
# ═══════════ 内存 ═══════════
vm.swappiness = 10              # Swap 使用倾向（0-100）
# 数据库/训练：1（几乎不用 Swap）；一般服务器：10-30
vm.dirty_ratio = 15             # 脏页比例（写缓存上限）
vm.dirty_background_ratio = 5   # 后台刷脏页阈值

# ═══════════ 网络 ═══════════
net.core.somaxconn = 65535      # 连接队列长度（高并发）
net.ipv4.tcp_max_syn_backlog = 65535   # SYN 队列
net.core.rmem_max = 16777216    # 接收缓冲 16MB
net.core.wmem_max = 16777216    # 发送缓冲 16MB
net.ipv4.tcp_congestion_control = bbr  # BBR 拥塞控制

# ═══════════ 文件系统 ═══════════
fs.file-max = 2097152           # 全局文件句柄
fs.nr_open = 2097152            # 单进程文件句柄上限

# 生效
sysctl -p                       # 加载配置
sysctl -w vm.swappiness=10      # 临时调整（重启失效）
```

```text
参数选择逻辑
├── ① swappiness：Swap 倾向（低 = 少用 Swap——性能）
├── ② somaxconn：连接队列（高并发必须）
├── ③ BBR：现代拥塞控制（高带宽低延迟）
├── ④ file-max：文件句柄（高并发连接/文件）
└── ⚠️ 注意：按场景选（不是全调——过度调优有害）
```

## 3. 资源限制

> **背景**：/etc/security/limits.conf 限制用户资源——防单进程耗尽系统。
> **目的**：配置合理的资源上限。
> **适用范围**：高并发服务用户。

```bash
# /etc/security/limits.conf
# 格式：用户/组 类型 项目 值

# 应用用户（高并发服务）
appuser soft nofile 65535        # 文件句柄软限制
appuser hard nofile 131072       # 文件句柄硬限制
appuser soft nproc 32768         # 进程数
appuser hard nproc 65536

# 所有用户默认
* soft nofile 65535
* hard nofile 65535
```

```bash
# 验证
ulimit -n                # 当前文件句柄限制
ulimit -u                # 进程数限制
su - appuser -c 'ulimit -n'    # 指定用户验证

# ⚠️ 常见坑
# ① 改 limits.conf 后需重新登录（session 级）
# ② systemd 服务用 LimitNOFILE（不是 limits.conf）：
# /etc/systemd/system/app.service
[Service]
LimitNOFILE=65535
LimitNPROC=32768
```

## 4. CPU 优化

```text
CPU 优化手段（2026）
├── ① tuned 动态调优：
│   ├── tuned-adm profile virtual-guest    # 虚拟化 Guest（常用）
│   ├── tuned-adm profile balanced         # 平衡
│   ├── tuned-adm profile powersave        # 省电
│   └── tuned-adm profile throughput-performance  # 高吞吐
├── ② CPU 调度器（governor）：
│   ├── performance：固定高频（性能）
│   └── ondemand：动态（省电）
│   echo performance > /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor
├── ③ NUMA 绑定：
│   ├── numactl --cpunodebind=0 --membind=0 app
│   └── 避免跨节点内存访问（延迟）
├── ④ 进程优先级：
│   ├── nice/renice：CPU 优先级
│   └── ionice -c2 -n7：IO 优先级（备份任务低优先）
└── ⑤ 金句：CPU 调优 = 场景配置集 + 绑定 + 优先级

CPU 排查命令
├── top（按 CPU 排序）→ 找热点进程
├── pidstat -p PID 1（进程 CPU 详情）
├── mpstat -P ALL 1（每核使用）
└── perf top（内核热点）
```

## 5. 磁盘 IO 优化

> 🎯 **IO 优化四步：错峰 → 限速 → 拆分 → 应用优化**（2026 顺序）：

```text
IO 优化顺序
├── ① 错峰：备份/批处理移到低峰期
├── ② 限速：ionice 设置 IO 优先级
│   ionice -c2 -n7 backup.sh    # 低优先（不抢业务）
├── ③ 拆分：数据库/上传/备份分盘
│   ├── 数据盘/日志盘/备份盘独立
│   └── 避免相互干扰
├── ④ 应用优化：慢查询/日志级别/批量读写
└── ⑤ 最后才扩容（硬件/升级 SSD）

IO 调度器
├── mq-deadline：机械硬盘（HDD）
├── none：NVMe SSD（现代推荐）
└── 查看/修改：
    cat /sys/block/sda/queue/scheduler
    echo none > /sys/block/sda/queue/scheduler

文件系统挂载
├── noatime：不更新访问时间（减少写操作）⚠️ 重要
├── XFS/ext4：现代推荐
└── /etc/fstab 配置：
    /dev/sdb1 /data xfs defaults,noatime 0 0

IO 排查命令
├── iostat -xz 1        # 设备级别（%util/await）
├── pidstat -d 1        # 进程级别（谁在读写）
├── lsof -p PID         # 文件路径
├── iotop               # 实时 IO 排序
└── fio                  # 存储基线测试（验证能力）
```

```text
网络优化要点（2026）

排查命令
├── ss -s（连接统计）
├── netstat -s（协议统计）
├── iftop（实时流量）
├── ping/mtr（延迟/路径）
```

## 7. OOM 防护

> **背景**：内存不足时内核 OOM Killer 杀进程——关键服务需防护。

```text
OOM 机制
├── ① OOM Killer：内存耗尽时选进程杀
├── ② 选择依据：oom_score（内存占用 + oom_adj）
└── ③ 风险：关键服务被误杀

防护手段
├── ① oom_adj 调整（关键服务免杀）：
│   echo -17 > /proc/PID/oom_adj
│   # -17 = 不可杀（OOM_SCORE_ADJ_MIN）
├── ② systemd 配置：
│   [Service]
│   OOMScoreAdjust=-1000     # 免杀（-1000 最小）
├── ③ 内存充足保障：
│   ├── 监控内存 >90% 告警（见 01 篇）
│   ├── 合理 JVM 堆（Java 服务）
│   └── Swap 兜底（swappiness 合理）
└── ④ 排查：
    dmesg | grep -i oom     # OOM 日志（谁被杀）
    journalctl -k | grep oom
```

## 8. 核心要点

> 🎯 **核心要点**：
> 1. 调优五步：基线 → 定位 → 单参数 → 对比 → 回滚——**不要调不懂的参数**
> 2. 内核参数：swappiness/somaxconn/BBR/file-max（按场景选）
> 3. 资源限制：nofile/nproc（systemd 用 LimitNOFILE）
> 4. CPU：tuned 配置集 + NUMA 绑定 + ionice 优先级
> 5. IO 优化顺序：错峰 → 限速 → 拆分 → 应用优化（最后扩容）
> 6. 文件系统：noatime 挂载（减少写）+ XFS/ext4
> 7. OOM 防护：关键服务 oom_adj=-17（免杀）+ 内存监控告警
