## 1. 核心日志路径

> **背景**：Linux 日志按功能分文件——知道「哪个文件查什么」是日志管理第一步。
> **目的**：掌握核心日志路径与用途。
> **适用范围**：CentOS/RHEL 与 Ubuntu 双系。

| 日志文件 | 内容 | 平台 |
|---------|------|:---:|
| **/var/log/messages** | 系统全局/内核 | CentOS/RHEL |
| **/var/log/syslog** | 系统全局 | Ubuntu |
| **/var/log/secure** | 安全事件（SSH 登录/爆破） | CentOS |
| **/var/log/auth.log** | 认证事件 | Ubuntu |
| **/var/log/cron** | 定时任务执行 | 通用 |
| **/var/log/boot.log** | 开机过程 | 通用 |
| **/var/log/dmesg** | 内核环形缓冲 | 通用 |
| **/var/log/nginx/** | Web 访问/错误 | Nginx |

```text
排障时的日志选择
├── ① SSH 登录问题 → /var/log/secure（auth.log）
├── ② 服务启动问题 → journalctl -u 服务
├── ③ 内核问题 → dmesg
├── ④ 定时任务问题 → /var/log/cron
├── ⑤ 系统资源异常 → messages/syslog（OOM 等）
└── ⑥ 金句：先知道「查哪个文件」——排障一半已过
```

## 2. journalctl 实战

> **背景**：systemd 统一管理日志——journalctl 是 2026 日志查询核心工具。

```bash
# ═══════════ 基本查询 ═══════════
journalctl                     # 全部日志（分页）
journalctl -n 50               # 最近 50 条
journalctl -f                  # 实时跟踪（tail -f）

# ═══════════ 按级别 ═══════════
journalctl -p err              # 错误及以上
journalctl -p err..emerg       # 范围（err 到 emerg）
journalctl -p warning -f       # 警告实时

# ═══════════ 按时间 ═══════════
journalctl --since "1 hour ago"      # 最近 1 小时
journalctl --since "2026-08-04 10:00" --until "11:00"  # 时间段
journalctl --since today             # 今天

# ═══════════ 按服务/单元 ═══════════
journalctl -u nginx.service          # 指定服务
journalctl -u sshd -p err            # 服务 + 级别
journalctl -u app.service -f         # 服务实时

# ═══════════ 其他 ═══════════
journalctl -k                  # 内核日志
journalctl _PID=1234           # 按进程
journalctl -o json-pretty      # JSON 输出（结构化）
```

```text
journalctl 排障流程
├── ① 服务有问题 → journalctl -u 服务 -f（实时看报错）
├── ② 只看错误 → -p err（过滤噪音）
├── ③ 时间定位 → --since "30 min ago"（回溯）
└── ④ 金句：journalctl = 「服务的实时黑匣子」
```

## 3. journal 持久化

> ⚠️ **journal 默认存内存（重启丢失）**——需配置持久化：

```bash
# 默认存储位置
ls /run/log/journal        # 内存（重启丢失）
ls /var/log/journal        # 持久化（需配置）

# 配置持久化
mkdir -p /var/log/journal
systemd-tmpfiles --create --prefix /var/log/journal
# 或 /etc/systemd/journald.conf:
# [Journal]
# Storage=persistent

# 生效
systemctl restart systemd-journald

# 清理（防磁盘被 journal 占满）
journalctl --vacuum-size=100M       # 总大小限 100M
journalctl --vacuum-time=30d        # 保留 30 天
journalctl --vacuum-files=10        # 最多 10 个文件

# ⚠️ 重要：journal 不清理会无限增长——定期 vacuum
```

## 4. logrotate 日志轮转

> **背景**：应用日志（Nginx/Java）无限增长 → 磁盘爆满。logrotate 定期切分。
> **目的**：掌握轮转配置（防日志填满磁盘）。
> **适用范围**：所有写文件的应用。

### 4.1 配置示例

```bash
# /etc/logrotate.d/myapp（应用日志轮转）
/var/log/myapp/*.log {
    daily                 # 每天轮转
    rotate 30             # 保留 30 份
    compress              # 压缩（.gz）
    delaycompress         # 延迟压缩（保留最近一份未压缩）
    missingok             # 文件缺失不报错
    notifempty            # 空文件不轮转
    copytruncate          # 复制+截断（应用无需重启）
    dateext               # 日期后缀
    size 100M             # 或超 100M 轮转
}
```

```text
轮转配置要点
├── ① 频率：daily/weekly/size（大小）
├── ② 保留：rotate N（份数）
├── ③ 压缩：compress（省空间）
├── ④ copytruncate：复制后截断（Java 应用必须！）
│   ├── 应用持有文件句柄
│   └── 不截断会写进已轮转文件
├── ⑤ 金句：轮转 = 「切分 + 保留 + 压缩」防磁盘满

验证
logrotate -d /etc/logrotate.d/myapp   # 调试模式（dry run）
logrotate -f /etc/logrotate.d/myapp   # 强制轮转
```

## 5. 日志集中化

> **背景**：多台服务器日志分散——排障要逐台查。集中化 = 一处在查。
> **目的**：掌握集中化方案。
> **适用范围**：多机环境。

### 5.1 rsyslog 集中（轻量）

```bash
# 服务器端（日志收集机）：/etc/rsyslog.conf
module(load="imudp")
input(type="imudp" port="514")      # 接收 UDP 514
# 或 TCP：imtcp

# 客户端（业务机）：/etc/rsyslog.d/50-forward.conf
*.* @log-server:514                 # UDP 转发（@）
# *.* @@log-server:514              # TCP 转发（@@，可靠）

# TLS 加密（生产要求）
# module(load="imtcp" TLSConfPort=6514)
# 启用证书加密传输

# 重启
systemctl restart rsyslog
```

### 5.2 ELK 集中（完整）

```text
ELK 集中化（见「日志Log」系列 07 篇）
├── ① Filebeat：客户端采集（轻量）
├── ② Logstash：解析/过滤
├── ③ Elasticsearch：存储索引
└── ④ Kibana：查询可视化

vs rsyslog
├── rsyslog：轻量（转发原始日志）——简单场景
├── ELK：完整（解析/检索/可视化）——生产标准
└── 选型：几台机器 rsyslog；正式环境 ELK/云日志
```

## 6. 时间同步

> ⚠️ **日志时间必须对齐**——多机日志对比的前提：

```bash
# chronyd（现代时间同步）
systemctl enable --now chronyd
timedatectl status            # 查看状态
chronyc sources -v            # 查看时间源

# 时间不准的后果
├── ① 多机日志无法对比（排障混乱）
├── ② 证书验证失败（HTTPS）
├── ③ 分布式系统一致性问题
├── ④ 定时任务错乱
└── ⑤ 金句：时间不同步 = 日志与审计全乱

# 配置（/etc/chrony.conf）
# 使用公司 NTP 服务器
server ntp.company.com iburst
```

## 7. 日志与监控的配合

> 🎯 **Syslog 与指标互补**——指标回答「是什么」、日志记录「为什么」：

```text
配合模式
├── ① 指标告警（发现问题）：CPU/内存/错误率
├── ② 日志定位（查明原因）：
│   ├── OOM 事件（dmesg）
│   ├── 磁盘满（ENOSPC）
│   ├── 服务异常退出（journalctl）
│   └── 安全事件（secure/auth.log）
└── ③ 金句：指标触发告警 → 日志深挖根因

排障标准流程（日志视角）
├── ① 指标异常 → 看日志（确认事件）
├── ② journalctl -p err（系统错误）
├── ③ 应用日志（业务错误）
├── ④ 时间对齐（多机关联）
└── ⑤ 集中化检索（ELK 搜 traceId）
```

## 8. 核心要点

> 🎯 **核心要点**：
> 1. 核心路径：messages/syslog（系统）+ secure/auth（安全）+ cron（任务）
> 2. journalctl 四查：-p（级别）/--since（时间）/-u（服务）/-f（实时）
> 3. **journal 需持久化配置**（默认内存重启丢失）+ 定期 vacuum 防满
> 4. logrotate 轮转：daily + rotate 30 + compress + **copytruncate（Java 应用必须）**
> 5. 集中化：rsyslog（轻量）/ELK（生产标准）——TLS 加密传输
> 6. **时间同步是前提**（chronyd）——时间不同步日志全乱
> 7. 配合：指标告警（是什么）+ 日志定位（为什么）
