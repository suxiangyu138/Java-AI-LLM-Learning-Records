## 1. 为什么需要心跳

```text
TCP Keep-Alive 的局限：
  → 默认 2 小时才探测一次（操作系统级）
  → 只检测 OS 层面的连接，不检测应用层"假死"
  → 无法自定义心跳逻辑

应用层心跳的必要性：
  → 及时检测对端崩溃/网络断连（秒级）
  → 清理无效连接资源（Channel/ByteBuf）
  → 负载均衡场景下的连接健康度
```

## 2. IdleStateHandler 空闲检测

> IdleStateHandler：一段时间内没有读写 → 触发 IdleStateEvent 事件。

```java
// 读空闲 60s / 写空闲 30s / 读写空闲 120s 分别触发
pipeline.addLast(new IdleStateHandler(60, 30, 120, TimeUnit.SECONDS));
```

| 参数 | 说明 |
|------|------|
| `readerIdleTime` | 读空闲时间（没收到数据） |
| `writerIdleTime` | 写空闲时间（没发送数据） |
| `allIdleTime` | 读写空闲时间（没有任何 IO） |

### 自定义空闲事件处理

```java
public class IdleEventHandler extends ChannelInboundHandlerAdapter {
    @Override
    public void userEventTriggered(ChannelHandlerContext ctx, Object evt) {
        if (evt instanceof IdleStateEvent) {
            IdleStateEvent event = (IdleStateEvent) evt;
            switch (event.state()) {
                case READER_IDLE:
                    System.out.println("读空闲 — 对端可能已断");
                    ctx.close();                    // 关闭连接
                    break;
                case WRITER_IDLE:
                    System.out.println("写空闲 — 发送心跳包");
                    ctx.writeAndFlush(new HeartbeatPacket());  // 发送心跳
                    break;
                case ALL_IDLE:
                    System.out.println("读写空闲");
                    break;
            }
        }
    }
}
```

## 3. 自定义心跳机制

### 3.1 心跳包定义

```java
public class HeartbeatPacket {
    public static final int PING = 1;    // 心跳请求
    public static final int PONG = 2;    // 心跳响应

    private int type;
    private long timestamp;

    public HeartbeatPacket(int type) {
        this.type = type;
        this.timestamp = System.currentTimeMillis();
    }
}
```

### 3.2 服务端：PING → PONG

```java
// 服务端收到 PING → 回复 PONG
public class HeartbeatServerHandler extends SimpleChannelInboundHandler<HeartbeatPacket> {
    @Override
    protected void channelRead0(ChannelHandlerContext ctx, HeartbeatPacket msg) {
        if (msg.getType() == HeartbeatPacket.PING) {
            ctx.writeAndFlush(new HeartbeatPacket(HeartbeatPacket.PONG));
        }
    }
}

// Pipeline 配置
pipeline
    .addLast(new IdleStateHandler(0, 0, 60))      // 60s 无读写
    .addLast(new IdleEventHandler())                // 触发心跳
    .addLast(new HeartbeatServerHandler());         // 处理心跳
```

### 3.3 客户端：收到 PONG 重置计数器

```java
public class HeartbeatClientHandler extends SimpleChannelInboundHandler<HeartbeatPacket> {
    @Override
    protected void channelRead0(ChannelHandlerContext ctx, HeartbeatPacket msg) {
        if (msg.getType() == HeartbeatPacket.PONG) {
            System.out.println("收到心跳响应，连接正常");
        }
    }
}
```

## 4. 断线重连机制

```java
public class ReconnectClient {

    private final EventLoopGroup group = new NioEventLoopGroup();

    public void connect(String host, int port) {
        Bootstrap bootstrap = new Bootstrap();
        bootstrap.group(group)
                 .channel(NioSocketChannel.class)
                 .handler(new ChannelInitializer<SocketChannel>() {
                     @Override
                     protected void initChannel(SocketChannel ch) {
                         ch.pipeline()
                           .addLast(new IdleStateHandler(0, 30, 0))
                           .addLast(new ClientReconnectHandler());  // 重连 Handler
                     }
                 });

        doConnect(bootstrap, host, port);
    }

    private void doConnect(Bootstrap bootstrap, String host, int port) {
        bootstrap.connect(host, port).addListener((ChannelFuture f) -> {
            if (f.isSuccess()) {
                System.out.println("连接成功");
            } else {
                System.out.println("连接失败，5s 后重试");
                f.channel().eventLoop().schedule(
                    () -> doConnect(bootstrap, host, port), 5, TimeUnit.SECONDS
                );
            }
        });
    }
}
```

### 指数退避重连

```java
public class ExponentialBackoff {
    private int attempt = 0;
    private static final int MAX_DELAY = 60;   // 最大 60 秒

    public long nextDelay() {
        long delay = (long) Math.min(Math.pow(2, attempt), MAX_DELAY);
        attempt++;
        return delay;
    }
}

// 重连时使用
long delay = backoff.nextDelay();  // 1s → 2s → 4s → 8s ... → 60s
f.channel().eventLoop().schedule(() -> doConnect(...), delay, TimeUnit.SECONDS);
```

## 5. 连接保活全链路

```text
完整的连接保活体系：

  客户端                                    服务端
  ┌──────────────┐                      ┌──────────────┐
  │ IdleStateHandler│                    │ IdleStateHandler│
  │ (写空闲 30s)    │                    │ (读空闲 60s)    │
  │   ↓            │                    │   ↓            │
  │ 发送 PING      │────── PING ──────→ │ 收到 PING      │
  │                │←───── PONG ───────│ 回复 PONG      │
  │ 收到 PONG      │                    │                │
  │ 连接正常        │                    │                │
  │                │                    │ 60s 未收到 PING │
  │                │                    │ → 判定对端死亡  │
  │                │                    │ → 关闭连接     │
  └──────────────┘                      └──────────────┘

  客户端检测到连接断开 → 触发重连（指数退避）
```

### 关键参数配置

```yaml
# 心跳相关配置
heartbeat:
  interval: 30          # 心跳间隔（秒）— 客户端写空闲
  timeout: 90           # 心跳超时（秒）— 服务端读空闲 (interval × 3)
  reconnect:
    initial: 1          # 初始重连延迟（秒）
    max: 60             # 最大重连延迟（秒）
    multiplier: 2       # 退避因子
```

> 🎯 **心跳黄金法则**：客户端写空闲 = 服务端读空闲 × 3。例：客户端 30s 发一次 PING，服务端 90s 收不到就断连。保证从容应对网络抖动。
