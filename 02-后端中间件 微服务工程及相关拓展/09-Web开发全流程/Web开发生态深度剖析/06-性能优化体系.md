## 1. 性能优化全景

```
Web 性能优化五层：
  ① 前端层：资源压缩、懒加载、CDN
  ② 网络层：HTTP/2、连接复用、Gzip
  ③ 应用层：缓存、异步、并行
  ④ 数据层：索引、SQL 优化、连接池
  ⑤ 架构层：集群、读写分离、分库分表

⚠️ 面试必答：
"性能优化五层——前端/网络/应用/数据/架构；
 先定位瓶颈再优化（监控数据驱动），
 不盲目调参。"
```

## 2. 缓存三件套

### 2.1 缓存层级

```
Web 缓存三层（访问速度递减）：
  ① 浏览器缓存（最快：本地）
  ② CDN 缓存（边缘节点）
  ③ 服务端缓存（Redis/本地缓存）

数据缓存场景：
  热点数据（排行榜/配置）
  读多写少（字典/分类）
  计算结果（统计/摘要）

⚠️ 面试必答：
"缓存三件套——浏览器、CDN、Redis；
 适用'读多写少 + 热点'数据，
 缓存是性能优化的第一手段。"
```

### 2.2 Redis 缓存模式

```
缓存三大模式：
  ① Cache Aside（旁路）：读缓存 → 未命中读库回填
  ② Read Through：缓存代理读库
  ③ Write Through/Behind：写缓存同步/异步写库

⚠️ Cache Aside 三问（面试必考）：
  为什么先删缓存后写库？（防脏读）
  为什么删缓存不是更新？（防并发写覆盖）
  双删/延迟双删？(极端一致性场景)

⚠️ 面试必答：
"Cache Aside 是标准——读：缓存 → 库 → 回填；
 写：先删缓存再写库（或延迟双删），
 避免并发下脏数据。"
```

### 2.3 缓存常见问题

| 问题 | 现象 | 解决 |
|------|------|------|
| 穿透 | 查不存在的数据打库 | 空值缓存 / 布隆过滤器 |
| 击穿 | 热点 key 过期瞬间 | 互斥锁 / 逻辑过期 |
| 雪崩 | 大量 key 同时过期 | 过期时间加随机 / 集群 |

> 🎯 **要点**：缓存三难——穿透（布隆）、击穿（互斥）、雪崩（随机过期）——面试必考组合题。

## 3. CDN 与静态资源

### 3.1 CDN 原理

```
CDN = 内容分发网络（静态资源边缘缓存）
  用户请求 → 就近边缘节点 → 命中返回 / 回源

场景：图片、JS/CSS、视频、下载文件

⚠️ 面试必答：
"CDN 把静态资源缓存到边缘节点——
 用户就近获取（减少延迟与源站压力）；
 动态 API 不适用（走应用服务器）。"
```

### 3.2 静态资源优化

```
静态资源优化五件套：
  ① Gzip/Brotli 压缩（文本类）
  ② 缓存头（Cache-Control: max-age + ETag）
  ③ hash 文件名（更新即换 URL，破缓存）
  ④ 合并/精简（减少请求数）
  ⑤ 懒加载（图片 loading="lazy"）

⚠️ 面试必答：
"静态资源优化 = 压缩 + 缓存 + hash 版本 +
 减少请求 + 懒加载；
 hash 文件名是前端缓存的黄金组合。"
```

## 4. 连接池与线程池

### 4.1 连接池（数据库）

```
连接池价值：创建连接贵（握手/认证）→ 复用

关键参数：
  maximum-pool-size：最大连接（核数 × 2 + 磁盘数）
  minimum-idle：常驻
  max-lifetime：< 数据库 wait_timeout
  connection-timeout：获取超时

⚠️ 面试必答：
"连接池参数——大小公式（核数 × 2 + 磁盘）、
 存活时间小于数据库超时、泄漏检测；
 连接池耗尽是数据库瓶颈第一信号。"
```

### 4.2 线程池（HTTP）

```
Tomcat/应用线程池：
  maxThreads：业务线程上限
  线程数 = 核数 × (1 + 等待/计算比)

⚠️ 线程池耗尽的表现：
  请求排队 → 超时 → 拒绝
  排查：线程 dump + 连接池监控

⚠️ 面试必答：
"线程池与连接池联动——
 线程池耗尽通常源于'慢查询占用连接'，
 优化 SQL 比加大线程数更根本。"
```

## 5. 数据库性能

### 5.1 SQL 优化流程

```
慢 SQL 排查流程：
  ① 慢查询日志定位（long_query_time）
  ② EXPLAIN 分析（type/key/rows/Extra）
  ③ 索引优化（缺索引/索引失效）
  ④ SQL 改写（避免 SELECT *、大分页）
  ⑤ 架构升级（缓存/读写分离/分库分表）

⚠️ 面试必答：
"SQL 优化五步——慢日志 → EXPLAIN →
 索引 → 改写 → 架构；
 '先看执行计划再动手'是原则。"
```

### 5.2 索引优化要点

```
✅ 高频查询列建索引（WHERE/ORDER BY/JOIN）
✅ 联合索引最左前缀
✅ 覆盖索引（查询列全在索引）
❌ 索引失效：函数包裹、隐式转换、前导模糊

⚠️ 面试必答：
"索引优化口诀——等值查询建普通、
 组合查询建联合（高区分度在前）、
 覆盖索引免回表。"
```

## 6. 压测与性能指标

### 6.1 性能指标

```
核心指标：
  吞吐量：QPS/TPS（每秒请求/事务）
  延迟：P50/P95/P99（分位延迟）
  资源：CPU/内存/IO/连接数
  错误率：5xx 占比

⚠️ 面试必答：
"性能四指标——QPS、P99 延迟、资源、
 错误率；P99 比平均值更有意义
 （长尾请求是用户体验杀手）。"
```

### 6.2 压测方法论

```
压测流程：
  ① 定目标（预期 QPS/P99）
  ② 工具（JMeter/wrk/ab）
  ③ 单接口 → 全链路
  ④ 逐步加压找拐点
  ⑤ 定位瓶颈（CPU/DB/连接）
  ⑥ 优化回归

⚠️ 面试必答：
"压测核心 = 找拐点（吞吐不再随并发增长）——
 瓶颈分层定位：CPU 计算型、
 锁等待型、DB 慢查询型。"
```
