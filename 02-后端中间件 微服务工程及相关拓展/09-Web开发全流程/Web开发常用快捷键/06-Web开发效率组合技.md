## 1. 组合技的设计思路

> **背景**：单快捷键是工具、组合流程是能力——真实排障是「多面板联动」。
> **目的**：把前五篇快捷键组装成可复用的排障 SOP。
> **适用范围**：前端日常开发与排障。
> **前提假设**：已掌握各面板基础快捷键（01-05 篇）。

```text
组合技的设计原则
├── ① 场景驱动：从「要解决的问题」出发选流程
├── ② 键盘优先：全程不碰鼠标（快捷键串联）
├── ③ 面板联动：Elements/Console/Sources/Network 协作
├── ④ 流程可复用：一次排障 = 一条 SOP
└── 金句：快捷键的价值在「组合」——单键省 2 秒，流程省 10 分钟
```

## 2. 场景一：样式 Bug 排查

```text
【场景】页面元素样式不对（间距/颜色/位置）

键盘流（全程键盘）：
① F12 打开 DevTools
② Ctrl+Shift+C 点击问题元素（检查模式）
③ Elements 面板：确认选中（DOM 结构）
④ 看 Styles 面板：
   ├── 样式被划掉？→ 高优先级覆盖（查来源）
   ├── 样式没生效？→ 选择器匹配问题
   └── 值不对？→ 数值微调
⑤ ↑↓ 微调数值（Shift 大步进/Alt 细步进）→ 实时预览
⑥ 期望值确认 → 复制样式（Ctrl+C）
⑦ 改源码（VS Code：Ctrl+Shift+P 打开文件 → Ctrl+V 粘贴）
⑧ Ctrl+R 刷新验证

常见坑：
├── 忘了「DevTools 修改是临时的」→ 改完必须复制到源码
├── hover 样式调不出来 → 右键 Force state
└── 元素动态生成找不到 → Ctrl+F 搜索选择器
```

## 3. 场景二：JS 逻辑 Bug

```text
【场景】点击按钮没反应/数据不对/报错

键盘流：
① Ctrl+Shift+J 打开 Console → 看报错
   ├── 有报错 → 点击报错位置 → Sources 定位
   └── 无报错 → 主动设断点
② Ctrl+P 打开可疑 JS 文件（:行号 直达）
③ F9 设置断点（关键行：事件处理/数据赋值）
④ 右键断点 → Edit → 条件断点（循环/特定值）
⑤ 页面操作触发 → 断点暂停
⑥ 先看 Call Stack（从哪来）→ Scope（变量值）
⑦ F10 单步跳过主流程 → 关键处 F11 深入
⑧ Watch 跟踪关键变量（右键 → Add to watch）
⑨ 找到根因 → 修改 → Ctrl+R 验证

高级技巧：
├── 异常断点：勾选 Break on exceptions（抛错即停）
├── 日志断点：只打印不停（线上零污染）
├── 忽略库代码：Blackbox（调用栈只显示业务代码）
└── 金句：先看 Call Stack——「我从哪来」比「我在哪」更重要
```

## 4. 场景三：接口联调 Bug

```text
【场景】页面数据不对/请求失败

键盘流：
① F12 → Network 面板
② Ctrl+R 刷新触发请求
③ / 输入 URL 关键字过滤 → 找到目标请求
④ 看状态码：
   ├── 4xx → 前端问题（参数/URL/Token）
   ├── 5xx → 后端问题
   └── 200 但数据不对 → 看 Response
⑤ Headers：请求头（Content-Type/Authorization）
⑥ Payload：请求体参数检查
⑦ Response：返回数据/错误信息
⑧ 需要复现 → 右键 → Copy as cURL（终端/后端复现）
⑨ 修复 → Ctrl+R 验证

进阶：
├── 请求重放：右键 Replay XHR（不刷新页面）
├── 模拟失败：Network conditions 离线模式
├── 缓存问题：Disable cache 勾选 + Ctrl+Shift+R
└── 跨域问题：看 Response Headers 的 Access-Control-*
```

## 5. 场景四：性能问题排查

```text
【场景】页面加载慢/交互卡顿

键盘流：
① 加载慢 → Network 面板看瀑布图（Timing）
   ├── 哪个请求慢 → 资源体积/接口耗时
   ├── 请求串行 → 并发优化
   └── 大图大文件 → 压缩/懒加载
② 交互卡顿 → Performance 面板
   ├── Ctrl+Shift+P → "Performance" → 录制
   ├── 操作页面 → 停止录制
   ├── 火焰图：找长任务（Long Tasks 红条）
   └── 定位：哪段 JS 耗时（点击火焰条 → 源码）
③ 渲染频繁 → React/Vue Profiler（05 篇）
   ├── 哪些组件重渲染
   ├── 为什么重渲染（Props 变化）
   └── 优化：memo/useMemo
④ 修复 → 重新录制对比

工具组合：
├── Lighthouse（Ctrl+Shift+P → Lighthouse）：整体评分
├── Coverage：未使用代码占比（打包优化依据）
└── 金句：性能排查 = Network（网络）+ Performance（执行）+ Profiler（渲染）三件套
```

## 6. 场景五：移动端适配

```text
【场景】移动端样式/交互问题

键盘流：
① Ctrl+Shift+M 进入设备模拟模式
② 设备选择：下拉选 iPhone/Android 型号
③ 问题 1：样式不对
   ├── 视口问题 → 检查 viewport meta
   ├── 断点媒体查询 → 调整窗口宽度（Ctrl+Shift+M 拖边缘）
   └── 响应式检查 → Elements 样式微调
④ 问题 2：触摸交互
   ├── 事件检查 → 是否用了 click（移动端 300ms 延迟）
   ├── 触摸事件 → Event Listener Breakpoints → touch
   └── 模拟触摸 → 设备模式下的触摸模拟
⑤ 真机验证 → 手机访问开发地址（局域网）

注意：
├── 设备模拟 ≠ 真机（浏览器内核差异）
├── 网络模拟：Network conditions 慢速 3G（移动网络）
└── 安全区域：刘海屏安全区检查（env(safe-area-inset)）
```

## 7. 场景六：线上问题排查

```text
【场景】线上页面报错/数据异常（无法本地复现）

键盘流（零污染原则）：
① 打开线上页面 → F12 → Console 看报错
② 日志断点：右键 → Add logpoint（不修改代码）
   ├── 线上关键路径打点
   ├── 观察变量值/执行轨迹
   └── 用完删除（零残留）
③ Overrides：本地覆盖线上资源
   ├── Sources → Overrides 目录设置
   ├── 修改线上 JS/CSS → 本地覆盖生效
   └── 直接调试线上（不影响线上用户）
④ 数据问题 → Network 看接口
   ├── 请求参数/响应对比（本地 vs 线上）
   ├── Copy as cURL 复现
   └── 环境差异定位（配置/数据）
⑤ 需要用户信息 → 埋点/日志平台（生产监控）

原则：
├── ① 线上绝不改源码调试（用日志断点/Overrides）
├── ② 复现优先：先找复现条件再修
├── ③ 记录完整：截图（Win+Shift+S）+ 控制台保存
└── ④ 修复后回归：线上验证 + 测试用例
```

## 9. 核心要点

> 🎯 **核心要点**：
> 1. 组合技六场景：样式/JS/接口/性能/移动端/线上——每个场景一条完整键盘流 SOP
> 2. 面板联动是核心：Elements（看）→ Console（查）→ Sources（断）→ Network（验）
> 3. 性能三件套：Network（网络）+ Performance（执行）+ Profiler（渲染）
> 4. 线上排查零污染：日志断点 + Overrides——**绝不改线上源码调试**
> 5. 复现优先：任何 Bug 先找复现条件，再谈修复
> 6. 速查总表：DevTools 18 键 + VS Code 10 键——打印贴显示器
