## 1. 安全威胁模型

> **背景**：公网服务器每秒都在被扫描——安全加固是生存基线不是可选。
> **目的**：理解攻击路径（防御的出发点）。
> **适用范围**：所有公网服务器。

```text
常见攻击路径
├── ① 端口扫描 → 找开放服务（Shodan 全球索引）
├── ② SSH 爆破 → 弱口令（22 端口）
├── ③ 服务漏洞 → 未打补丁（Web/中间件）
├── ④ Web 攻击 → SQL 注入/XSS（应用层）
├── ⑤ 勒索软件 → RDP/SMB 暴露（3389/445）
└── ⑥ 供应链 → 恶意依赖/镜像

防御逻辑（纵深防御）
├── 每一层拦截一部分攻击
├── 单层被破还有下层
└── 金句：不是「加一层锁」而是「每层都锁」
```

## 2. 四层防线总览

> 🎯 **2026 四层防线**：防火墙（入口）→ SSH 加固（远程）→ SELinux（系统）→ 审计更新（底线）：

```text
四层防线
┌─────────────────────────────────────────────┐
│ ④ 审计与更新：auditd + 自动安全更新           │
│    → 记录做了什么 + 补丁及时                  │
├─────────────────────────────────────────────┤
│ ③ SELinux/AppArmor：强制访问控制              │
│    → 即使进程被攻破也限制行为                 │
├─────────────────────────────────────────────┤
│ ② SSH 加固：密钥/禁 root/限源/fail2ban        │
│    → 远程入口防线（最高频攻击面）             │
├─────────────────────────────────────────────┤
│ ① 防火墙：默认拒绝、按需开放                  │
│    → 端口入口防线（第一道门）                 │
└─────────────────────────────────────────────┘
```

## 3. 第一层：防火墙

> **背景**：防火墙 = 端口入口的第一道门——默认拒绝、按需开放。
> **目的**：掌握防火墙配置（最小暴露）。
> **适用范围**：所有服务器（本机 + 云安全组双保险）。

```bash
# ═══════════ ufw（Ubuntu） ═══════════
ufw default deny incoming      # 默认拒绝入站
ufw default allow outgoing     # 默认允许出站
ufw allow 22/tcp               # 放行 SSH
ufw allow 80/tcp               # 放行 Web
ufw allow from 203.0.113.0/24 to any port 22   # SSH 限源
ufw enable

# ═══════════ firewalld（RHEL/CentOS） ═══════════
firewall-cmd --set-default-zone=drop        # 默认拒绝
firewall-cmd --add-service=ssh --permanent
firewall-cmd --add-port=80/tcp --permanent
firewall-cmd --permanent --add-rich-rule='rule family="ipv4" \
    source address="203.0.113.0/24" port port="22" protocol="tcp" accept'
firewall-cmd --reload

# ═══════════ 云安全组（云服务器） ═══════════
# 控制台：入方向只开放必要端口 + 限源
```

```text
防火墙要点
├── ① 默认拒绝：未显式放行的全拒
├── ② 按需开放：只开必要的（80/443/22）
├── ③ 限源：管理端口（22）只允许办公 IP
├── ④ 数据库/Redis 等：只对内网（见端口系列）
├── ⑤ 双保险：本机防火墙 + 云安全组
└── ⑥ 金句：防火墙 = 「默认关着、按需开窗」
```

## 4. 第二层：SSH 加固

> ⚠️ **SSH 是最高频攻击面**（每秒都在被爆破）——加固优先：

```bash
# /etc/ssh/sshd_config 加固（详见 SSH 系列）
# ═══════════ 认证 ═══════════
PasswordAuthentication no       # 禁用密码（核心！）
PubkeyAuthentication yes        # 密钥认证
PermitRootLogin prohibit-password  # root 仅密钥
MaxAuthTries 3                  # 尝试次数限制
LoginGraceTime 30               # 认证超时

# ═══════════ 用户/端口 ═══════════
AllowUsers deploy,ops           # 用户白名单
Port 2222                       # 改高位端口（降噪）

# ═══════════ 检查与生效 ═══════════
sshd -t                         # 语法检查（必做！）
systemctl restart sshd
```

```bash
# fail2ban（自动封禁爆破 IP）
apt install fail2ban
# /etc/fail2ban/jail.local
[sshd]
enabled = true
maxretry = 5
bantime = 3600

systemctl enable --now fail2ban
fail2ban-client status sshd     # 查看封禁
```

```text
SSH 加固要点
├── ① 禁用密码（密钥认证——不可爆破）
├── ② 禁 root 远程（或仅密钥）
├── ③ 限源（防火墙层：办公 IP）
├── ④ 限尝试（MaxAuthTries 3）
├── ⑤ fail2ban（爆破自动封禁）
├── ⑥ 安全顺序：先确认密钥可用再禁密码（防锁死）
└── ⑦ 金句：SSH 加固 = 「密钥 + 禁密码 + 限源 + fail2ban」
```

## 5. 第三层：SELinux/AppArmor

> **背景**：SELinux（强制访问控制）——即使进程被攻破也限制其行为。
> **目的**：理解 SELinux 的价值与使用（不是关掉它）。
> **适用范围**：RHEL/CentOS（SELinux）/Ubuntu（AppArmor）。

```text
SELinux 的价值
├── ① 强制访问控制（MAC）：
│   ├── 进程只能访问「被允许」的资源
│   └── 即使 Web 服务被攻破也不能读 SSH 密钥
├── ② 三模式：
│   ├── Enforcing：强制（生产推荐）
│   ├── Permissive：只记录（排查用）
│   └── Disabled：关闭（⚠️ 不推荐）
└── ③ 2026 现状：新系统默认 Enforcing

SELinux 使用
├── 查看：getenforce
├── 临时切换：setenforce 0（排查）/ 1（恢复）
├── 配置：/etc/selinux/config（SELINUX=enforcing）
└── 权限问题排查（不是先关！）：
    restorecon -Rv /var/www     # 恢复上下文
    setsebool -P httpd_can_network_connect 1   # 布尔开关
    audit2why -a                # 查看拒绝原因

⚠️ 常见错误
├── ❌ 服务权限问题 → 直接 setenforce 0（关安全）
├── ✅ 先 audit2why 查原因 → restorecon/setsebool
└── 金句：SELinux 不是麻烦——是「攻破后的第二道墙」
```

## 6. 第四层：审计与更新

### 6.1 审计（auditd）

```bash
# 审计关键操作（谁做了什么）
yum install audit
# /etc/audit/rules.d/audit.rules
-w /etc/ssh/sshd_config -p wa -k ssh_config    # 监控 SSH 配置
-w /etc/passwd -p wa -k passwd                 # 用户文件
-a always,exit -F arch=b64 -S execve -k exec   # 命令执行

systemctl enable --now auditd
ausearch -k ssh_config          # 查询审计记录
aureport --summary              # 审计摘要
```

### 6.2 自动安全更新

```bash
# Ubuntu（unattended-upgrades）
apt install unattended-upgrades
dpkg-reconfigure unattended-upgrades

# RHEL/CentOS（dnf-automatic）
yum install dnf-automatic
# /etc/dnf/automatic.conf
apply_updates = yes
systemctl enable --now dnf-automatic

# ⚠️ 更新策略
# ① 安全更新：自动（及时）
# ② 功能更新：手动（测试后）
# ③ 大版本：手动（计划窗口）
# ④ 更新前：快照/备份（回滚保障）
```

## 7. 其他安全规范

```text
其他安全规范（2026 清单）
├── ① 账号管理：
│   ├── 密码复杂度（字母+数字+符号）
│   ├── 定期修改
│   └── 最小权限（普通账号 + 按需 sudo）
├── ② 服务最小化：
│   ├── 关闭无用服务（systemctl list-unit-files）
│   ├── 关闭不必要端口
│   └── 删除默认账号/测试账号
├── ③ 恶意 IP 处理：
│   ├── 排查爆破/异常登录（secure/auth.log）
│   ├── fail2ban 拉黑
│   └── 定期清理
├── ④ 漏洞管理：
│   ├── 定期扫描（云厂商漏洞扫描）
│   ├── 高危漏洞优先修补
│   └── 更新前快照
└── ⑤ 金句：安全是「日常习惯」不是「一次加固」
```

## 8. 安全基线清单

```text
服务器安全总检查（上线前过一遍）
[ ] 防火墙：默认拒绝？只开必要端口？SSH 限源？
[ ] SSH：禁密码？密钥认证？禁 root 远程？
[ ] fail2ban：运行中？（fail2ban-client status）
[ ] SELinux：Enforcing？（getenforce）
[ ] 用户：无默认账号？最小权限？密码强度？
[ ] 服务：无用服务已关闭？
[ ] 高危端口：445/3389/6379 等不暴露公网？
[ ] 更新：自动安全更新启用？
[ ] 审计：auditd 启用？（关键文件监控）
[ ] 日志：secure/auth.log 定期查看？
[ ] 备份：3-2-1 策略 + 恢复演练？
[ ] 云安全组：入方向最小化？

加固顺序（优先级）
① 防火墙（默认拒绝）→ ② SSH 加固（禁密码）
③ 高危端口治理 → ④ SELinux → ⑤ fail2ban
⑥ 审计 → ⑦ 自动更新 → ⑧ 漏洞扫描
```

## 9. 核心要点

> 🎯 **核心要点**：
> 1. 威胁模型：扫描/爆破/漏洞/勒索/供应链——**默认不安全**
> 2. 四层防线：防火墙（入口）→ SSH（远程）→ SELinux（系统）→ 审计更新（底线）
> 3. 防火墙：默认拒绝 + 按需开放 + 限源（本机 + 云安全组）
> 4. SSH 加固：密钥 + 禁密码 + 禁 root + 限源 + fail2ban——**先确认密钥再禁密码**
> 5. SELinux：Enforcing 保持——权限问题用 audit2why 排查（不是关掉）
> 6. 审计更新：auditd 监控关键文件 + 自动安全更新
> 7. 安全基线清单 12 项——加固顺序：防火墙 → SSH → 高危端口 → SELinux
