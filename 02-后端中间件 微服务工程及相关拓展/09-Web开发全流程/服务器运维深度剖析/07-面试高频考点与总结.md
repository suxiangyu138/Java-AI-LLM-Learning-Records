## 1. 面试高频题与答题框架

### 1.1 监控类

**Q1：服务器监控哪些指标？阈值是多少？**

```text
① 四类：CPU/内存/磁盘/网络
② 阈值：
   CPU >85%（持续）/内存 >90%/磁盘 >85%/IO 持续 100%
③ 工具：top/free/df/iostat（即时）+ Prometheus（持续）
④ 低噪音告警：阈值合理 + 持续条件 + 收敛
⑤ 金句：监控 = 看得见——先监控再调优
```

**Q2：CPU 负载过高怎么排查？**

```text
① top 按 CPU 排序 → 找热点进程
② pidstat -p PID 1 → 进程 CPU 详情
③ mpstat -P ALL 1 → 每核使用（负载不均）
④ 区分 us/sy：sy 高查内核/wa 高查 IO
⑤ 应用层：线程 dump（Java 用 jstack）
⑥ 金句：先找进程再分析——CPU 高是结果不是原因
```

**Q3：内存使用率高怎么排查？**

```text
① free -h：used/buff/cache 区分（cache 可回收）
② 使用率 >90%：查常驻进程（Java/Python）
③ Java：jmap 堆分析（内存泄漏）
④ Swap 使用：swap 高 = 内存不足信号
⑤ OOM：dmesg | grep oom（谁被杀）
⑥ 金句：cache 不是问题、swap 才是信号
```

### 1.2 调优类

**Q4：Linux 内核参数怎么调优？**

```text
① 内存：vm.swappiness（Swap 倾向——DB 设 1）
② 网络：somaxconn（连接队列）/BBR（拥塞控制）
③ 文件：fs.file-max（文件句柄）
④ 原则：按场景选 + 单参数 + 基线对比 + 可回滚
⑤ 生效：sysctl -p
⑥ 金句：不要调不懂的参数——调优是科学实验
```

**Q5：文件句柄（nofile）怎么配置？**

```text
① 场景：高并发（每连接一个句柄）
② limits.conf：nofile 65535（用户级）
③ systemd：LimitNOFILE（服务级——注意！）
④ 验证：ulimit -n
⑤ 金句：高并发服务 nofile 是「连接数的天花板」
```

**Q6：磁盘 IO 瓶颈怎么排查？**

```text
① 三层证据链：
   iostat（设备繁忙？）→ pidstat（哪个进程？）→ lsof（什么文件？）
② 指标：%util 100% = 饱和、await >10ms = 慢
③ 优化顺序：错峰 → 限速（ionice）→ 拆分 → 应用 → 扩容
④ fio 基线：硬件能力参照
⑤ 金句：IO 排查 = 「设备 → 进程 → 文件」证据链
```

### 1.3 日志类

**Q7：日志怎么查？journalctl 有哪些用法？**

```text
① 核心路径：messages/syslog（系统）+ secure/auth（安全）
② journalctl：
   -p err（级别）/--since（时间）/-u 服务（单元）/-f（实时）
③ 持久化：Storage=persistent（默认内存重启丢）
④ 清理：--vacuum-size/time（防满）
⑤ 金句：journalctl = 服务的实时黑匣子
```

**Q8：logrotate 怎么配置？Java 应用注意什么？**

```text
① 配置：daily + rotate 30 + compress + size
② ⚠️ Java 应用必须 copytruncate（复制+截断）
   └── 应用持有文件句柄（rename 后写进旧文件）
③ 验证：logrotate -d（dry run）
④ 金句：轮转 = 切分 + 保留 + 压缩——防磁盘满
```

### 1.4 磁盘与备份类

**Q9：磁盘满但 df 显示有空间？**

```text
① 现象：No space left 但 df 有空间
② 根因：被删除但仍被进程占用的文件（deleted）
③ 排查：lsof | grep deleted
④ 处理：重启进程 / truncate 文件
⑤ 预防：日志轮转 copytruncate
⑥ 金句：deleted 文件 = 看不见的磁盘杀手
```

**Q10：备份策略是什么？**

```text
① 3-2-1：3 份副本、2 种介质、1 份异地
② 工具：rsync 增量/数据库 dump/云快照
③ ⚠️ 必须验证可恢复（定期演练）
④ 金句：不能恢复的备份 = 没有备份
```

### 1.5 安全类

**Q11：服务器安全加固怎么做？**

```text
① 四层防线：防火墙 → SSH → SELinux → 审计更新
② 防火墙：默认拒绝 + 按需开放 + 限源
③ SSH：密钥 + 禁密码 + 禁 root + fail2ban
④ SELinux：Enforcing（权限问题用 audit2why 排查）
⑤ 审计：auditd + 自动安全更新
⑥ 金句：纵深防御——每层拦截一部分
```

**Q12：SSH 被暴力破解怎么办？**

```text
① 立即：fail2ban 封禁（maxretry 5/bantime 3600）
② 根治：禁用密码登录（密钥认证）
③ 加固：改端口/限源（防火墙层）
④ 检查：secure/auth.log 排查异常登录
⑤ 金句：爆破的根治 = 密码认证关掉（不是只封 IP）
```

**Q13：SELinux 导致服务权限问题怎么办？**

```text
① 不要直接关：setenforce 0（关安全 = 裸奔）
② 排查：audit2why -a（查看拒绝原因）
③ 修复：restorecon（上下文）/setsebool（布尔开关）
④ 临时：Permissive（只记录——排查）
⑤ 金句：SELinux 是「攻破后的第二道墙」——别拆墙
```

### 1.6 规范类

**Q14：故障排查流程是什么？**

```text
① 五步：收集 → 定位 → 根因 → 修复 → 验证
② 先看最近变更（80% 故障是变更引起）
③ 从外到内：网络 → 系统 → 应用
④ 先止损（恢复服务）再根治（修复根因）
⑤ 复盘：24 小时内（监控补盲/流程改进）
⑥ 金句：先恢复服务、再找根因、最后防复发
```

**Q15：高可用怎么做？**

```text
① 应用层：Nginx 负载均衡（多实例 + 健康检查）
② 系统层：Keepalived VIP（主备漂移）
③ 容器层：K8s（副本 + HPA + 探针）
④ 数据层：数据库主从/集群
⑤ 金句：高可用 = 多副本 + 自动切换 + 健康检查
```

**Q16：每天巡检做什么？**

```text
① 系统资源：CPU/内存/磁盘/IO（对比昨日）
② 业务服务：systemctl/端口/健康检查
③ 定时任务：crontab 日志
④ 网络：连通性/延迟/异常流量
⑤ 安全：登录日志/补丁状态
⑥ 金句：巡检 15 分钟 = 省 3 小时救火
```

## 2. 速查表

```text
监控：CPU>85%/内存>90%/磁盘>85%/IO 100%——持续 + 收敛告警
调优：swappiness/somaxconn/BBR/file-max——单参数 + 基线对比
IO 排查：iostat（设备）→ pidstat（进程）→ lsof（文件）
日志：journalctl -p/-since/-u/-f；logrotate + copytruncate
磁盘：df -h/df -i；lsof | grep deleted（隐形杀手）
备份：3-2-1（3 份/2 介质/1 异地）+ 定期恢复演练
安全：防火墙（默认拒绝）→ SSH（禁密码）→ SELinux → 审计
故障：收集 → 定位 → 根因 → 修复 → 验证；先看变更
高可用：Nginx（负载均衡）+ Keepalived（VIP）+ K8s
```

## 3. 五大常见误区

| # | 误区 | 真相 |
|---|------|------|
| 1 | 「防火墙只开就行」 | 默认拒绝 + 按需开放 + 限源（最小暴露） |
| 2 | 「SELinux 麻烦就关掉」 | 攻破后的第二道墙——用 audit2why 排查 |
| 3 | 「备份了就行」 | 必须验证可恢复（定期演练）——不能恢复 = 没有 |
| 4 | 「日志轮转就够了」 | Java 应用必须 copytruncate（否则写进旧文件） |
| 5 | 「磁盘满看 df 就够」 | 还有 deleted 文件 + inode 满两个隐形维度 |

## 4. 一句话总结全系列

```text
01 监控：四类指标 + 阈值 + Prometheus + 低噪音告警
02 调优：基线 → 单参数 → 对比 → 回滚（不调不懂的）
03 日志：journalctl + logrotate（copytruncate）+ 集中化
04 磁盘：IO 三层排查 + 3-2-1 备份 + deleted 陷阱
05 安全：四层防线（防火墙/SSH/SELinux/审计）
06 规范：四铁律 + 巡检 + 故障五步 + 高可用三层
07 面试：16 题框架 + 速查 + 避坑
```

> 🎯 **系列总结**：服务器运维 = **监控（看得见）× 调优（跑得快）× 日志（查得清）× 磁盘（存得住）× 安全（守得住）× 规范（可持续）** 六维体系。2026 年核心框架：**可观测三支柱（指标/日志/追踪）+ 纵深防御四层 + 3-2-1 备份 + 主动巡检**——主动代替被动、自动化降低成本、文档化保障传承，系统才「稳定运行不宕机」。
