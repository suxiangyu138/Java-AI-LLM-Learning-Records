## 1. 测试金字塔

```text
          /\
         /E2E\           少量：核心业务流程
        /------\
       /集成测试 \        适量：服务间交互、数据库
      /----------\
     /  单元测试   \       大量：方法级别、快速反馈
    /--------------\

黄金比例：70% 单元 + 20% 集成 + 10% E2E

反模式：倒金字塔（冰淇淋模式）
  → 大量手工测试 + 少量自动化 → 每次上线心惊胆战

反模式：测试蛋糕（中间鼓）
  → 集成测试太多 → CI 跑得慢 → 开发效率降低
```

### 1.1 各层测试对比

| 维度 | 单元测试 | 集成测试 | E2E 测试 |
|------|:-----:|:-----:|:-----:|
| **速度** | 毫秒级 | 秒级 | 分钟级 |
| **范围** | 单个方法/类 | 多个组件交互 | 全系统 |
| **维护成本** | 低 | 中 | 高 |
| **运行频率** | 每次保存 | 每次提交 | 每次发布前 |
| **发现问题** | 逻辑错误 | 接口契约/数据 | 业务流程/UI |

## 2. 单元测试

### 2.1 测试结构 AAA

```java
@ExtendWith(MockitoExtension.class)
class UserServiceTest {

    @Mock
    private UserRepository userRepository;

    @InjectMocks
    private UserService userService;

    @Test
    @DisplayName("正常创建用户应返回用户DTO")
    void shouldCreateUserSuccessfully() {
        // Arrange（准备）
        CreateUserRequest request = new CreateUserRequest("Alice", "alice@test.com");
        User savedUser = new User(1L, "Alice", "alice@test.com");
        when(userRepository.save(any(User.class))).thenReturn(savedUser);

        // Act（执行）
        UserDTO result = userService.createUser(request);

        // Assert（验证）
        assertThat(result.getId()).isEqualTo(1L);
        assertThat(result.getName()).isEqualTo("Alice");
        verify(userRepository, times(1)).save(any(User.class));
    }

    @Test
    @DisplayName("用户名已存在应抛出异常")
    void shouldThrowExceptionWhenUsernameExists() {
        when(userRepository.existsByName("Alice")).thenReturn(true);
        CreateUserRequest request = new CreateUserRequest("Alice", "alice@test.com");

        assertThatThrownBy(() -> userService.createUser(request))
            .isInstanceOf(DuplicateUserException.class)
            .hasMessageContaining("用户名已存在");
    }
}
```

### 2.2 F.I.R.S.T 原则

| 原则 | 说明 |
|------|------|
| **Fast** | 测试必须快，否则没人愿意跑 |
| **Independent** | 测试之间不能有依赖顺序 |
| **Repeatable** | 任何环境、任何次数运行结果一致 |
| **Self-Validating** | 测试自己判断通过/失败（不要人工看日志） |
| **Timely** | 开发代码的同时写测试（TDD 是理想） |

### 2.3 什么值得测

```text
✅ 必须测：
  → 核心业务逻辑（计算、状态转换）
  → 边界条件（空值、最大值、负数）
  → 异常路径（非法输入、外部依赖异常）

❌ 不值得测：
  → POJO getter/setter（Lombok 生成的不测）
  → 一行调用另一个已测方法（委托）
  → Spring 配置加载（框架已测试）
  → 极端复杂的私有方法 → 重构为多个小方法再测
```

## 3. 集成测试

### 3.1 Spring Boot 测试

```java
@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)
@AutoConfigureMockMvc
class UserControllerIntegrationTest {

    @Autowired
    private MockMvc mockMvc;

    @Autowired
    private UserRepository userRepository;

    @BeforeEach
    void setUp() {
        userRepository.deleteAll();  // 每个测试前清数据
    }

    @Test
    @DisplayName("POST /users 创建用户 → 200 + JSON")
    void shouldCreateUser() throws Exception {
        String requestBody = """
            { "name": "Alice", "email": "alice@test.com" }
        """;

        mockMvc.perform(post("/api/v1/users")
                .contentType(MediaType.APPLICATION_JSON)
                .content(requestBody))
            .andExpect(status().isCreated())
            .andExpect(jsonPath("$.data.name").value("Alice"))
            .andExpect(jsonPath("$.data.email").value("alice@test.com"));
    }
}
```

### 3.2 Testcontainers（数据库真实测试）

```java
@Testcontainers
@SpringBootTest
class UserRepositoryTest {

    @Container
    static PostgreSQLContainer<?> postgres = new PostgreSQLContainer<>("postgres:16")
        .withDatabaseName("testdb")
        .withUsername("test")
        .withPassword("test");

    @DynamicPropertySource
    static void configureProperties(DynamicPropertyRegistry registry) {
        registry.add("spring.datasource.url", postgres::getJdbcUrl);
        registry.add("spring.datasource.username", postgres::getUsername);
        registry.add("spring.datasource.password", postgres::getPassword);
    }

    @Autowired
    private UserRepository userRepository;

    @Test
    void shouldSaveAndFindUser() {
        User user = new User("Alice", "alice@test.com");
        User saved = userRepository.save(user);

        Optional<User> found = userRepository.findById(saved.getId());
        assertThat(found).isPresent();
        assertThat(found.get().getName()).isEqualTo("Alice");
    }
}
```

## 4. E2E 与接口测试

### 4.1 接口自动化测试

```java
// REST Assured 接口测试
@SpringBootTest(webEnvironment = RANDOM_PORT)
class OrderApiTest {

    @LocalServerPort
    private int port;

    @Test
    void 正常下单流程() {
        // 1. 登录获取 Token
        String token = given()
            .port(port)
            .contentType(JSON)
            .body("{\"username\":\"test\",\"password\":\"123456\"}")
        .when()
            .post("/api/v1/auth/login")
        .then()
            .statusCode(200)
            .extract().path("data.token");

        // 2. 创建订单
        given()
            .port(port)
            .header("Authorization", "Bearer " + token)
            .contentType(JSON)
            .body("{\"productId\":1,\"quantity\":2}")
        .when()
            .post("/api/v1/orders")
        .then()
            .statusCode(201)
            .body("data.status", equalTo("PENDING"));
    }
}
```

### 4.2 测试数据管理

```text
测试数据原则：
  ✅ 每个测试自己准备数据（setUp / @BeforeEach）
  ✅ 每个测试自己清理数据（tearDown / @AfterEach）
  ✅ 不要依赖数据库中的预存数据
  ✅ 不要依赖测试执行顺序

数据隔离方案：
  → H2 内存数据库（单元测试）
  → Testcontainers 真实数据库（集成测试）
  → @Transactional + 自动回滚（Spring Boot 默认）
```

## 5. Bug 管理

### 5.1 Bug 等级

| 等级 | 说明 | 举例 | 处理时效 |
|:----:|------|------|:------:|
| **P0 致命** | 系统不可用 | 登录全部失败、支付无法使用 | 立刻修复 |
| **P1 严重** | 核心功能不可用 | 下单成功但不扣库存 | 4 小时内 |
| **P2 一般** | 非核心功能异常 | 头像上传失败 | 一个迭代内 |
| **P3 轻微** | 体验问题 | 文案错误、对齐像素偏差 | 排期修复 |

### 5.2 Bug 报告模板

```text
标题：[模块] 简要描述

环境：Staging / 版本号 v1.2.3
复现步骤：
  1. 登录普通用户账号
  2. 进入订单列表页
  3. 点击"取消订单"
  4. 观察结果

预期结果：订单状态变为"已取消"
实际结果：页面提示"操作失败"，但订单状态已变为"已取消"（成功但前端报错）
截图/日志：（附上）
频率：每次必现 / 偶现（约 30%）
```
