## 1. 环境准备

| 组件 | 版本要求 | 说明 |
|------|----------|------|
| JDK | 8+（3.x 推荐 11+） | 运行 Kafka 需要 JVM |
| OS | Linux / macOS / Windows | 生产环境建议 Linux |
| 内存 | 至少 2GB（生产 ≥ 8GB） | Broker 堆内存 + OS 页缓存 |
| 磁盘 | SSD 推荐 | 顺序写 + 页缓存，SSD 提升显著 |
| 网络 | 千兆网卡 | 副本同步依赖网络带宽 |

**下载 Kafka：**

```bash
# 下载最新稳定版
wget https://dlcdn.apache.org/kafka/3.9.0/kafka_2.13-3.9.0.tgz
tar -xzf kafka_2.13-3.9.0.tgz
cd kafka_2.13-3.9.0
```

## 2. 单机部署（KRaft 模式）

> 💡 KRaft（Kafka Raft）是 Kafka 3.3+ 的推荐模式，不再依赖外部 ZooKeeper，将所有元数据通过 Raft 共识协议存储在 Kafka 内部。

### 2.1 生成集群 ID

```bash
# 生成唯一的集群 ID
KAFKA_CLUSTER_ID="$(bin/kafka-storage.sh random-uuid)"
echo $KAFKA_CLUSTER_ID
# 示例输出: 7XJjH9d-RW2VZxVYFqMzLQ
```

### 2.2 格式化存储目录

```bash
# 使用生成的 ID 格式化存储目录
bin/kafka-storage.sh format \
  --cluster-id $KAFKA_CLUSTER_ID \
  --config config/kraft/server.properties
```

### 2.3 修改 KRaft 配置

`config/kraft/server.properties` 关键配置：

```properties
# Broker 基本配置
node.id=1                                  # 节点 ID（集群内唯一）
process.roles=broker,controller           # 角色：broker/controller/broker,controller
controller.quorum.voters=1@localhost:9093 # 投票者列表 id@host:port
listeners=PLAINTEXT://localhost:9092       # 监听地址
advertised.listeners=PLAINTEXT://localhost:9092  # 对外暴露地址
controller.listener.names=CONTROLLER

# 日志存储
log.dirs=/tmp/kraft-combined-logs         # 存储目录

# 元数据主题
num.partitions=1                          # 默认分区数
offsets.topic.replication.factor=1        # __consumer_offsets 副本数（单机设1）
```

### 2.4 启动与验证

```bash
# 启动 Kafka
bin/kafka-server-start.sh config/kraft/server.properties

# 后台启动
bin/kafka-server-start.sh -daemon config/kraft/server.properties

# 验证进程
jps | grep Kafka
```

## 3. 单机部署（ZooKeeper 模式）

> ⚠️ KRaft 已生产可用，新项目直接使用 KRaft。ZK 模式仅用于维护老集群。

```bash
# 1. 启动 ZooKeeper（Kafka 自带）
bin/zookeeper-server-start.sh config/zookeeper.properties

# 2. 启动 Kafka
bin/kafka-server-start.sh config/server.properties

# 3. 验证
bin/kafka-topics.sh --bootstrap-server localhost:9092 --list
```

`config/server.properties` 关键配置：

```properties
broker.id=0
listeners=PLAINTEXT://localhost:9092
log.dirs=/tmp/kafka-logs
zookeeper.connect=localhost:2181
num.partitions=3
```

## 4. Docker-Compose 部署

```yaml
# docker-compose.yml
version: '3.8'
services:
  kafka:
    image: apache/kafka:3.9.0
    container_name: kafka
    ports:
      - "9092:9092"
      - "9093:9093"
    environment:
      KAFKA_NODE_ID: 1
      KAFKA_PROCESS_ROLES: broker,controller
      KAFKA_LISTENERS: PLAINTEXT://0.0.0.0:9092,CONTROLLER://0.0.0.0:9093
      KAFKA_ADVERTISED_LISTENERS: PLAINTEXT://localhost:9092
      KAFKA_CONTROLLER_LISTENER_NAMES: CONTROLLER
      KAFKA_LISTENER_SECURITY_PROTOCOL_MAP: CONTROLLER:PLAINTEXT,PLAINTEXT:PLAINTEXT
      KAFKA_CONTROLLER_QUORUM_VOTERS: 1@localhost:9093
      KAFKA_OFFSETS_TOPIC_REPLICATION_FACTOR: 1
    volumes:
      - kafka-data:/var/lib/kafka/data

volumes:
  kafka-data:
```

```bash
# 启动
docker-compose up -d

# 进入容器使用 CLI
docker exec -it kafka bash
```

### 带 Web UI 的完整方案

```yaml
services:
  kafka:
    image: apache/kafka:3.9.0
    # ... 同上配置 ...

  kafka-ui:
    image: provectuslabs/kafka-ui:latest
    ports:
      - "8080:8080"
    environment:
      KAFKA_CLUSTERS_0_NAME: local
      KAFKA_CLUSTERS_0_BOOTSTRAP_SERVERS: kafka:9092
    depends_on:
      - kafka
```

> 💡 Kafka UI（provectuslabs/kafka-ui）是最流行的开源 Kafka Web 管理工具，访问 `http://localhost:8080`。

## 5. 集群部署

### 5.1 KRaft 三节点配置

**node1 (controller + broker)：**

```properties
node.id=1
process.roles=broker,controller
controller.quorum.voters=1@node1:9093,2@node2:9093,3@node3:9093
listeners=PLAINTEXT://node1:9092,CONTROLLER://node1:9093
advertised.listeners=PLAINTEXT://node1:9092
controller.listener.names=CONTROLLER
log.dirs=/data/kafka/logs
```

**node2 / node3 类似，修改 `node.id` 和主机名即可。**

```bash
# 每台机器上依次执行：
# 1. 格式化
bin/kafka-storage.sh format --cluster-id $KAFKA_CLUSTER_ID --config config/kraft/server.properties

# 2. 启动
bin/kafka-server-start.sh config/kraft/server.properties

# 3. 验证集群
bin/kafka-metadata-shell.sh --snapshot /data/kafka/logs/__cluster_metadata-0/00000000000000000000.log
```

### 5.2 集群验证

```bash
# 查看 Broker 列表
bin/kafka-broker-api-versions.sh --bootstrap-server node1:9092

# 查看集群元数据
bin/kafka-metadata.sh --snapshot /data/kafka/logs/...  --command "broker.list()"
```

## 6. 核心配置速查

### 6.1 Broker 关键配置

| 参数 | 默认值 | 建议值 | 说明 |
|------|--------|--------|------|
| `num.partitions` | 1 | 3~12 | 默认分区数 |
| `default.replication.factor` | 1 | 3 | 默认副本数 |
| `offsets.topic.replication.factor` | 1 | 3 | 位移主题副本数 |
| `log.retention.hours` | 168（7天） | 按需 | 消息保留时间 |
| `log.segment.bytes` | 1GB | 1GB | 日志分段大小 |
| `log.retention.bytes` | -1（不限制） | 按需 | 主题级别容量限制 |
| `auto.create.topics.enable` | true | **false**（生产） | 自动创建主题 |
| `delete.topic.enable` | true | true | 允许删除主题 |
| `message.max.bytes` | 1MB | 1~10MB | 单条消息最大字节 |

### 6.2 哪些配置必须改（生产环境）

```properties
# ⚠️ 必须显式设置
broker.id=每个节点唯一
listeners=PLAINTEXT://实际IP:9092
advertised.listeners=PLAINTEXT://对客户端可见的IP:9092  # ← 常配错！
log.dirs=/data/kafka                        # 不要用 /tmp

# ⚠️ 强烈建议
num.partitions=8
default.replication.factor=3
auto.create.topics.enable=false
offsets.topic.replication.factor=3
```

## 7. 命令行工具实战

### 7.1 主题管理

```bash
# 创建 Topic（分区 3，副本 3）
bin/kafka-topics.sh --bootstrap-server localhost:9092 \
  --create --topic my-topic \
  --partitions 3 --replication-factor 3

# 查看 Topic 列表
bin/kafka-topics.sh --bootstrap-server localhost:9092 --list

# 查看 Topic 详情
bin/kafka-topics.sh --bootstrap-server localhost:9092 \
  --describe --topic my-topic

# 增加分区（只能增不能减）
bin/kafka-topics.sh --bootstrap-server localhost:9092 \
  --alter --topic my-topic --partitions 6

# 删除 Topic
bin/kafka-topics.sh --bootstrap-server localhost:9092 \
  --delete --topic my-topic
```

### 7.2 生产与消费

```bash
# 生产者 — 控制台发送消息
bin/kafka-console-producer.sh --bootstrap-server localhost:9092 \
  --topic my-topic
# 输入消息，Ctrl+C 退出

# 带 Key 的生产
bin/kafka-console-producer.sh --bootstrap-server localhost:9092 \
  --topic my-topic \
  --property "parse.key=true" \
  --property "key.separator=:"

# 消费者 — 从最新开始消费
bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 \
  --topic my-topic

# 从最早开始消费
bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 \
  --topic my-topic --from-beginning

# 指定消费组
bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 \
  --topic my-topic --group my-group

# 显示 Key 和 Partition
bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 \
  --topic my-topic --group my-group \
  --property print.key=true \
  --property print.partition=true
```

### 7.3 消费组管理

```bash
# 查看消费组列表
bin/kafka-consumer-groups.sh --bootstrap-server localhost:9092 --list

# 查看消费组详情
bin/kafka-consumer-groups.sh --bootstrap-server localhost:9092 \
  --describe --group my-group

# 输出示例:
# GROUP    TOPIC     PARTITION  CURRENT-OFFSET  LOG-END-OFFSET  LAG
# my-group my-topic  0          105             200             95
# my-group my-topic  1          98              98              0

# 重置位移 — 到最早
bin/kafka-consumer-groups.sh --bootstrap-server localhost:9092 \
  --group my-group --topic my-topic --reset-offsets --to-earliest --execute

# 重置位移 — 按时间
bin/kafka-consumer-groups.sh --bootstrap-server localhost:9092 \
  --group my-group --topic my-topic \
  --reset-offsets --to-datetime 2026-07-01T00:00:00.000 --execute
```

## 8. 常见故障排查

### 8.1 连接不上 Broker

```bash
# 测试连通性
telnet localhost 9092

# 检查 advertised.listeners
# ❌ 错误：advertised.listeners=PLAINTEXT://localhost:9092
# ✅ 正确：advertised.listeners=PLAINTEXT://实际IP:9092
```

### 8.2 KRaft 集群无法启动

```bash
# 1. 检查 cluster-id 是否一致
bin/kafka-storage.sh info --config config/kraft/server.properties

# 2. 清除旧数据重新格式化
rm -rf /tmp/kraft-combined-logs
bin/kafka-storage.sh format --cluster-id $KAFKA_CLUSTER_ID --config config/kraft/server.properties
```

### 8.3 Topic 创建失败

```text
Error: replication factor: 3 larger than available brokers: 1
→ 原因：replication-factor 不能超过 Broker 数量
→ 解决：减少 replication-factor 或增加 Broker
```

### 8.4 磁盘满

```bash
# 检查磁盘
df -h

# 紧急：降低保留时间
bin/kafka-configs.sh --bootstrap-server localhost:9092 \
  --alter --entity-type topics --entity-name my-topic \
  --add-config retention.ms=3600000
```
