# 05 - 事务与锁机制

> 🎯 Oracle 的事务实现和 MySQL 有本质不同——没有 UNDO LOG 的"MVCC"，而是用 UNDO 表空间 + SCN 实现一致性读。Oracle 写不阻塞读（Writer Never Blocks Reader），这是它最引以为傲的特性

## 1. 事务模型

```text
Oracle 事务的核心原则：
  → 读不阻塞写，写不阻塞读
  → 一致性读基于 SCN (System Change Number)
  → 没有 MySQL 的"Read View"概念
  → UNDO 表空间保存修改前的数据
```

```sql
-- 事务控制
COMMIT;          -- 提交 + 释放锁 + 当前会话看到修改
ROLLBACK;        -- 回滚整个事务
SAVEPOINT sp1;   -- 保存点
ROLLBACK TO sp1; -- 部分回滚
```

### Oracle 默认 READ COMMITTED

```text
MySQL 默认 REPEATABLE READ → 一个事务内读到的数据不变
Oracle 默认 READ COMMITTED → 每次查询看到最新提交的数据

Oracle 的 REPEATABLE READ（很少用）：
  SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;
  → 看不到事务开始后的任何修改
```

## 2. 锁机制

| 锁类型 | 缩写 | 说明 | 阻塞 |
|-------|------|------|------|
| **行级共享** | RS | SELECT ... FOR UPDATE | 其他 RS/行排他 |
| **行级排他** | RX | INSERT/UPDATE/DELETE | 其他排他锁 |
| **表级共享** | S | LOCK TABLE IN SHARE MODE | 阻止写 |
| **表级排他** | X | LOCK TABLE IN EXCLUSIVE MODE | 阻止一切 |

```sql
-- 锁诊断
-- 查看当前锁
SELECT s.sid, s.serial#, s.username, l.type, l.lmode
FROM v$session s JOIN v$lock l ON s.sid = l.sid;

-- 查看阻塞链（谁锁了谁）
SELECT blocking_session, sid, serial#, wait_class, seconds_in_wait
FROM v$session WHERE blocking_session IS NOT NULL;

-- 杀掉阻塞会话
ALTER SYSTEM KILL SESSION 'sid,serial#' IMMEDIATE;
```

### 死锁检测

```text
Oracle 自动检测死锁（默认 3 秒一次）
  → 发现死锁 → 选择一个事务回滚 → 抛出 ORA-00060
  → 无需人工干预，被回滚的事务重新执行即可
```

## 3. Oracle vs MySQL 事务对比

| 特性 | Oracle | MySQL InnoDB |
|------|--------|-------------|
| 默认隔离级别 | **READ COMMITTED** | **REPEATABLE READ** |
| 一致性读 | SCN + UNDO | Read View + UNDO LOG |
| 写不阻塞读 | ✅ 核心特性 | ✅ 类似 |
| 回滚段 | UNDO 表空间 | UNDO LOG |
| 自动死锁检测 | ✅ | ✅ |
| `SELECT ... FOR UPDATE` | 行级锁 | 行级锁 |
| `NOWAIT` / `SKIP LOCKED` | ✅ | ✅ (8.0+) |

```sql
-- SELECT FOR UPDATE 高级用法
-- NOWAIT: 立即返回（不等）
SELECT * FROM orders WHERE id = 123 FOR UPDATE NOWAIT;

-- SKIP LOCKED: 跳过已锁定的行（队列模式！）
SELECT * FROM jobs WHERE status = 'PENDING'
FOR UPDATE SKIP LOCKED;
-- 多个消费者同时取任务，互不阻塞
```

## 核心要点回顾

- Oracle 的事务基石 = UNDO 表空间 + SCN（不是 UNDO LOG）
- Oracle 写不阻塞读（核心卖点）
- `FOR UPDATE NOWAIT` = 不等锁直接报错
- `FOR UPDATE SKIP LOCKED` = 队列模式取任务（最实用）
- 锁诊断三件套：`v$lock` + `v$session` + `blocking_session`
