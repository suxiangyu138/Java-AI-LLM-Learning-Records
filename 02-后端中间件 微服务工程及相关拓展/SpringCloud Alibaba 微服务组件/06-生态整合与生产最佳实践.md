## 1. RocketMQ + Spring Cloud Stream 事件驱动

### 1.1 架构定位

```text
微服务通信的两条路：

同步调用（HTTP/Feign/gRPC）:
  Order Service → Account Service（等回复）
  场景：查余额、验证库存

异步消息（RocketMQ）:
  Order Service → [RocketMQ] → Account Service（不等回复）
  场景：订单创建后 → 发短信、记积分、写日志
```

### 1.2 Spring Cloud Stream + RocketMQ 配置

```xml
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-stream-rocketmq</artifactId>
</dependency>
```

```yaml
spring:
  cloud:
    stream:
      # ===== Binder 配置 =====
      rocketmq:
        binder:
          name-server: rocketmq:9876
          group: order-service-group
          # 事务消息
          enable-msg-trace: true
          customized-trace-topic: RMQ_TRACE_TOPIC

      # ===== Binding 配置 =====
      bindings:
        # 生产者：订单创建后发送消息
        orderCreated-out-0:
          destination: order-created-topic
          content-type: application/json
          group: order-producer-group

        # 消费者：监听库存扣减结果
        inventoryDeducted-in-0:
          destination: inventory-deducted-topic
          content-type: application/json
          group: order-consumer-group

    # 函数式编程模型
    function:
      definition: orderCreated;inventoryDeducted
```

### 1.3 生产者/消费者代码

```java
// 生产者：使用 StreamBridge 发送消息
@Service
public class OrderEventPublisher {

    @Autowired
    private StreamBridge streamBridge;

    public void publishOrderCreated(Order order) {
        OrderCreatedEvent event = new OrderCreatedEvent(
            order.getId(), order.getUserId(), order.getAmount(),
            System.currentTimeMillis()
        );

        streamBridge.send("orderCreated-out-0",
            MessageBuilder.withPayload(event)
                .setHeader("orderId", order.getId())
                .setHeader("timestamp", event.getTimestamp())
                .build()
        );
    }
}

// 消费者：使用函数式编程模型
@Configuration
public class OrderEventConsumer {

    @Bean
    public Consumer<OrderCreatedEvent> orderCreated() {
        return event -> {
            log.info("收到订单创建事件: orderId={}", event.getOrderId());
            // 处理逻辑：发短信、记积分等
        };
    }

    @Bean
    public Consumer<InventoryDeductedEvent> inventoryDeducted() {
        return event -> {
            log.info("库存扣减完成: productId={}, success={}",
                event.getProductId(), event.isSuccess());
            // 更新订单状态
        };
    }
}
```

### 1.4 RocketMQ 事务消息 + Seata

```java
/**
 * 场景：订单创建 + 减库存 + 发消息 — 全在一个分布式事务中
 *
 * RocketMQ的事务消息≠Seata事务的替代
 * RocketMQ事务消息：确保本地事务和消息发送的原子性
 * Seata：确保多个服务间数据库操作的原子性
 *
 * 组合使用：
 *   Seata 保证 订单DB + 库存DB 的一致性
 *   RocketMQ事务消息 保证 "库存扣减成功" 与 "发送通知消息" 的原子性
 */
@Service
public class OrderService {

    @GlobalTransactional  // Seata 全局事务
    public void createOrder(OrderDTO dto) {
        // 1. 创建订单（本地服务 DB）
        orderMapper.insert(order);

        // 2. 调用库存服务（跨服务 DB）
        inventoryService.deduct(dto.getProductId(), dto.getQuantity());

        // 3. 都成功后 → 发送事务消息
        //    如果发消息失败 → Seata 回滚全部
        orderEventPublisher.publishOrderCreated(order);
    }
}
```

## 2. Dubbo + Nacos 微服务 RPC 方案

### 2.1 Dubbo vs Spring Cloud 调用方式

```text
┌──────────────┬─────────────────────┬─────────────────────┐
│    维度       │  Spring Cloud       │      Dubbo          │
│              │  (HTTP/Feign)       │                     │
├──────────────┼─────────────────────┼─────────────────────┤
│ 协议          │ HTTP/1.1           │ TCP (Dubbo 协议)     │
│ 序列化        │ JSON               │ Hessian/Protobuf     │
│ 注册中心      │ Nacos              │ Nacos / Zookeeper   │
│ 调用方式      │ 声明式（Feign）      │ 接口代理             │
│ 性能          │ ⭐⭐⭐              │ ⭐⭐⭐⭐⭐            │
│ 跨语言        │ ✅ 天然支持         │ ⚠️ 需额外工作        │
│ 适用场景      │ 通用微服务          │ 高性能内部 RPC       │
└──────────────┴─────────────────────┴─────────────────────┘
```

### 2.2 Dubbo + Nacos 集成

```xml
<dependency>
    <groupId>org.apache.dubbo</groupId>
    <artifactId>dubbo-spring-boot-starter</artifactId>
    <version>3.2.12</version>
</dependency>
<dependency>
    <groupId>org.apache.dubbo</groupId>
    <artifactId>dubbo-registry-nacos</artifactId>
</dependency>
```

```yaml
dubbo:
  application:
    name: user-service
  registry:
    address: nacos://nacos:8848       # 用 Nacos 做注册中心
    parameters:
      namespace: ${NACOS_NAMESPACE}
  protocol:
    name: dubbo
    port: 20880
  provider:
    timeout: 3000
    retries: 0                         # 通常不自动重试
    version: 1.0.0
```

```java
// 服务接口（公共模块）
public interface UserService {
    UserDTO getUserById(Long userId);
    List<UserDTO> listUsers(UserQuery query);
}

// 服务提供者
@DubboService(version = "1.0.0", group = "default")
public class UserServiceImpl implements UserService {
    @Override
    public UserDTO getUserById(Long userId) {
        // 实现逻辑
    }
}

// 服务消费者
@RestController
public class OrderController {

    @DubboReference(version = "1.0.0", check = false)
    private UserService userService;  // ← 就像调用本地方法

    @GetMapping("/order/{id}")
    public OrderDetailDTO getOrder(@PathVariable Long id) {
        Order order = orderService.getById(id);
        UserDTO user = userService.getUserById(order.getUserId());
        return OrderDetailDTO.of(order, user);
    }
}
```

### 2.3 何时用 Dubbo 而非 Feign

```text
选 Dubbo：
  ✅ 高并发内部 RPC（QPS > 1000）
  ✅ 需要长连接 + 多路复用
  ✅ Java 同构微服务集群
  ✅ 对延迟要求 < 5ms（相比 HTTP）

选 Feign/HTTP：
  ✅ 需要跨语言调用
  ✅ 需要浏览器/外部直接访问
  ✅ 团队更熟悉 HTTP/REST
  ✅ 网关代理和缓存更简单
```

## 3. Sidecar：非 Java 服务接入

### 3.1 问题场景

```text
你的 Python AI 服务需要：
  1. 注册到 Nacos（让其他服务发现它）
  2. 从 Nacos 读取配置
  3. 被 Sentinel 保护（限流）

但它不是 Java 项目，不能直接引入 Spring Cloud Alibaba SDK
→ Sidecar 解决异构语言接入问题
```

### 3.2 Spring Cloud Alibaba Sidecar

```xml
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-sidecar</artifactId>
</dependency>
```

```yaml
spring:
  application:
    name: python-ai-service

  cloud:
    nacos:
      discovery:
        server-addr: nacos:8848

    # Sidecar 配置
    sidecar:
      # 异构服务的 IP 和端口
      ip: 127.0.0.1
      port: 5000
      # 健康检查端点
      health-check-url: http://127.0.0.1:5000/health
```

```text
Sidecar 工作原理：

┌───────────────────────────────────────┐
│              K8s Pod / 主机             │
│                                       │
│  ┌─────────────────┐  localhost调用   │
│  │ Sidecar (Java)  │←──────────────→ │
│  │ 注册到 Nacos     │                 │
│  │ 心跳维持         │  ┌───────────┐  │
│  │ 健康检查         │  │ Python AI │  │
│  └────────┬────────┘  │ Service   │  │
│           │            │ :5000     │  │
│           │            └───────────┘  │
│  ┌────────▼────────┐                  │
│  │     Nacos       │                  │
│  │  python-ai-svc  │ ← 注册的服务名    │
│  │  192.168.1.10   │ ← Sidecar 的 IP  │
│  └─────────────────┘                  │
└───────────────────────────────────────┘

其他 Java 服务通过 Feign 调用 python-ai-service
→ 实际请求到了 Sidecar
→ Sidecar 转发给 localhost:5000 (Python 服务)
```

### 4.2 流量染色全链路传递

```java
// 网关层：根据 Header 或用户 ID 染色
@Component
public class GrayFilter implements GlobalFilter {
    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        ServerHttpRequest request = exchange.getRequest();
        String userId = request.getHeaders().getFirst("X-User-Id");

        if (isGrayUser(userId)) {
            // 染色：添加灰度标记到请求头
            request = request.mutate()
                .header("X-Gray", "true")
                .header("X-Gray-Version", "v2")
                .build();
        }

        return chain.filter(exchange.mutate().request(request).build());
    }
}

// 服务间调用：Feign 拦截器传递灰度标记
@Component
public class GrayFeignInterceptor implements RequestInterceptor {
    @Override
    public void apply(RequestTemplate template) {
        String gray = RequestContextHolder.currentRequestAttributes()
            .getAttribute("X-Gray", RequestAttributes.SCOPE_REQUEST);
        if (gray != null) {
            template.header("X-Gray", gray);
        }
    }
}
```

## 5. 版本升级指南

### 5.1 Spring Boot 2.7 → 3.2 迁移

```text
关键变更清单：

1. Java 版本：Java 8/11 → Java 17
2. javax → jakarta 命名空间
   javax.servlet → jakarta.servlet
   javax.persistence → jakarta.persistence

3. Spring Security 配置方式変化
   WebSecurityConfigurerAdapter 被移除 → 用 SecurityFilterChain Bean

4. Spring Cloud 版本号变革
   2021.0.x (Leyton) → 2023.0.x (Leyton)

5. Nacos Client 版本
   2.1.x → 2.3.x

6. Sentinel 版本
   1.8.5 → 1.8.6（基本兼容）
```

### 5.2 升级步骤

```text
Step 1: 升级 Java 到 17
   → 编译、单元测试通过

Step 2: 升级 Spring Boot 3.2
   → 处理 javax → jakarta
   → 更新 Security 配置
   → 处理废弃 API

Step 3: 升级 Spring Cloud 2023.0
   → 更新依赖版本
   → 适配新 API

Step 4: 升级 Spring Cloud Alibaba 2023.0.1
   → Nacos Client 2.3.x
   → Sentinel 1.8.6
   → Seata 1.8.x

Step 5: 灰度验证
   → 先在一个实例上升级
   → 观察 Nacos 注册、配置读取、Sentinel 规则是否正常
   → 逐步扩大范围
```

## 6. 全组件生产 Checklist

### 6.1 基础设施

```text
□ Nacos 集群 ≥ 3 节点（生产必须）
□ Nacos 使用 MySQL 存储（不用内嵌 Derby）
□ MySQL 做主从/集群（备份 Nacos 数据）
□ Sentinel Dashboard 可正常访问
□ Seata TC Server 集群部署（≥ 2 节点）
□ RocketMQ Name Server + Broker 集群
□ 所有控制台不暴露到公网（通过 VPN/堡垒机访问）
```

### 6.2 应用配置

```text
□ Nacos namespace 分环境（prod/dev/test）
□ Nacos 鉴权已开启
□ Sentinel 规则持久化到 Nacos
□ Seata 事务 group 配置正确
□ 所有服务配置了 @GlobalTransactional 超时时间
□ 敏感配置已加密
□ 日志中不输出敏感信息
```

### 6.3 监控告警

```text
□ Nacos 健康监控（节点存活、配置变更通知）
□ Sentinel 流控/熔断指标接入 Prometheus
□ Seata TC 全局事务成功率监控
□ RocketMQ 消息堆积告警
□ 微服务实例上下线通知
□ 配置变更通知（钉钉/企微/邮件）
```

### 6.4 测试验证

```text
□ Nacos 故障演练（单节点宕机 → 服务发现是否正常）
□ Sentinel 流控压测（验证阈值是否合理）
□ Seata 事务回滚测试（验证补偿逻辑正确）
□ RocketMQ 消息丢失测试（验证事务消息/重试机制）
□ 全链路压测（验证端到端性能）
```

## 7. 常见生产问题排查

### 7.1 Nacos 常见问题

```text
问题 1：服务注册成功但消费端发现不了
  → 检查 namespace 是否一致
  → 检查 group 是否匹配
  → 检查健康实例数 > 0

问题 2：Nacos 配置不刷新
  → 确认 @RefreshScope 注解是否存在
  → 检查配置 dataId 格式：${app}-${profile}.${ext}
  → Nacos 控制台查看监听者列表（监听者 IP != 预期 IP）

问题 3：Nacos 集群节点不同步
  → 检查 cluster.conf 配置
  → 检查 MySQL 是否所有节点都能访问
  → 检查网络策略（8848 + 7848 端口互通）
```

### 7.2 Sentinel 常见问题

```text
问题 1：Dashboard 看不到应用
  → 应用配置了 sentinel.transport.port 吗？
  → Dashboard 和应用网络是否互通？
  → 检查 sentinel-transport-simple-http 是否引入

问题 2：规则不生效
  → 检查规则的 resource 名称是否匹配（大小写敏感）
  → 检查 URL 清洗（/user/123 → /user/{id}）
  → 规则是否持久化到 Nacos？Nacos 中 dataId 是否匹配？

问题 3：集群流控不生效
  → Token Server 是否正常运行？
  → 检查 cluster-client-config 中的 flowId 是否和规则一致
  → 检查 fallbackToLocalWhenFail 是否开启
```

### 7.3 Seata 常见问题

```text
问题 1：AT 模式不生效
  → 业务表是否创建了 UNDO_LOG 表？
  → DataSource 是否被 Seata DataSourceProxy 代理？
  → SELECT FOR UPDATE 是否被使用（全局锁依赖）

问题 2：全局回滚失败
  → 检查 UNDO_LOG 中的 beforeImage/afterImage 是否完整
  → 检查是否发生了脏写（数据在 Phase1 和 Phase2 间被修改）
  → 检查 TC Server 是否可达

问题 3：全局锁等待超时
  → 检查是否有慢 SQL 持有锁
  → 调整锁超时时间（seata.at.lock-retry-times）
  → 考虑改用 TCC 模式避免全局锁
```
