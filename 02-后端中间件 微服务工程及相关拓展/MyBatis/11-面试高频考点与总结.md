## 1. 高频面试题

### Q1（⭐⭐⭐⭐⭐）: MyBatis 的工作流程？

> 加载配置 → SqlSessionFactory → SqlSession → Executor → MappedStatement → 执行 SQL → 结果映射
> Mapper 接口没有实现类，靠 JDK 动态代理（MapperProxy）拦截调用

### Q2: #{} 和 ${} 的区别？

> `#{}` = PreparedStatement ? 占位符（预编译，防注入）→ 99% 使用
> `${}` = 字符串拼接（可能注入）→ 仅 ORDER BY / 动态表名（需白名单校验）

### Q3: 一级缓存和二级缓存的区别？

| 维度 | 一级缓存 | 二级缓存 |
|------|:---:|:---:|
| 范围 | SqlSession 内 | Mapper (namespace) |
| 默认 | 开启 | 关闭（需手动开启） |
| 失效 | 更新/关闭 SqlSession | 更新/配置刷新间隔 |
| 序列化 | 不需要 | 实体必须 Serializable |

### Q4: N+1 问题是什么？怎么解决？

> 查 1 次主表 + N 次关联表
> 根因：`association` 用 `select` 属性（嵌套查询）
> 解决：用 JOIN + 嵌套结果映射（一条 SQL）

### Q5: MyBatis 插件原理？

> `@Intercepts` + `@Signature` → JDK 动态代理 → `Plugin.wrap()`
> 四大拦截点：Executor / StatementHandler / ParameterHandler / ResultSetHandler
> 责任链模式，多插件按配置顺序执行

### Q6: MyBatis-Plus 和 MyBatis 的区别？

> MyBatis-Plus 是增强工具：BaseMapper(自带CRUD) + 条件构造器 + 分页 + 逻辑删除 + 代码生成
> 不改变 MyBatis 原生功能，只是增强

## 核心要点回顾

- MyBatis 核心 = JDK 动态代理 + XML/注解映射 + 插件责任链
- #{} 防注入（99%），${} 仅 ORDER BY
- N+1 = 嵌套查询的坑，解决 = 嵌套结果（JOIN）
- 面试必问：工作流程、缓存区别、插件原理、N+1 问题
