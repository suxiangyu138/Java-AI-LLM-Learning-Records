## 1. 线程模型调优

### 1.1 Boss-Worker 线程配比

```java
EventLoopGroup bossGroup = new NioEventLoopGroup(1);       // Boss: 通常 1 即可
EventLoopGroup workerGroup = new NioEventLoopGroup(8);     // Worker: CPU 核数 × 2
```

```text
Boss 线程数：1 个 Boss 可以处理数万连接（仅负责 accept），设 1-2 足够
Worker 线程数：
  纯 IO 处理（无耗时业务）→ CPU 核数
  有轻量业务              → CPU 核数 × 2
  有耗时业务              → Worker 少 + 业务线程池大
```

### 1.2 业务线程池隔离

```java
// 为耗时 Handler 分配独立的 EventExecutorGroup
EventExecutorGroup bizGroup = new DefaultEventExecutorGroup(32);

pipeline
    .addLast(new LengthFieldBasedFrameDecoder(...))
    .addLast(new MessageDecoder())
    .addLast(bizGroup, new HeavyBizHandler());  // ⭐ 在 bizGroup 线程执行
```

### 1.3 Epoll vs NIO

```java
// Linux 生产环境 — 替换 NIO 为 Epoll（性能提升 30%+）
EventLoopGroup bossGroup = new EpollEventLoopGroup(1);
EventLoopGroup workerGroup = new EpollEventLoopGroup();

ServerBootstrap bootstrap = new ServerBootstrap();
bootstrap.channel(EpollServerSocketChannel.class);   // Epoll 模式
```

```xml
<dependency>
    <groupId>io.netty</groupId>
    <artifactId>netty-transport-native-epoll</artifactId>
    <classifier>linux-x86_64</classifier>
</dependency>
```

## 2. 内存与缓冲区调优

### 2.1 核心参数

```java
ServerBootstrap bootstrap = new ServerBootstrap();
bootstrap
    // ═══ 内存分配器 ═══
    .option(ChannelOption.ALLOCATOR, PooledByteBufAllocator.DEFAULT)
    .childOption(ChannelOption.ALLOCATOR, PooledByteBufAllocator.DEFAULT)

    // ═══ TCP 参数 ═══
    .option(ChannelOption.SO_BACKLOG, 1024)            // 全连接队列
    .childOption(ChannelOption.TCP_NODELAY, true)      // 禁用 Nagle
    .childOption(ChannelOption.SO_KEEPALIVE, true)     // TCP Keep-Alive
    .childOption(ChannelOption.SO_RCVBUF, 128 * 1024)  // 接收缓冲区 128KB
    .childOption(ChannelOption.SO_SNDBUF, 128 * 1024)  // 发送缓冲区 128KB

    // ═══ 水位线（防 OOM） ═══
    .childOption(ChannelOption.WRITE_BUFFER_WATER_MARK,
        new WriteBufferWaterMark(32 * 1024, 64 * 1024));  // 低水位 32KB / 高水位 64KB
```

| 参数 | 说明 | 推荐值 |
|------|------|:---:|
| `ALLOCATOR` | 池化内存分配器 | `PooledByteBufAllocator.DEFAULT` |
| `SO_BACKLOG` | 全连接队列 | 128-1024 |
| `TCP_NODELAY` | 禁用 Nagle | true |
| `SO_RCVBUF/SO_SNDBUF` | Socket 缓冲区 | 128KB-256KB |
| `WRITE_BUFFER_WATER_MARK` | 写缓冲区水位 | 低32KB/高64KB |

### 2.2 池化内存 JVM 参数

```bash
# 直接内存限制（避免 OOM）
-XX:MaxDirectMemorySize=512m

# 开启泄漏检测
-Dio.netty.leakDetectionLevel=PARANOID    # 开发/测试
-Dio.netty.leakDetectionLevel=SIMPLE      # 生产

# 池化配置
-Dio.netty.allocator.type=pooled          # 强制池化
```

### 2.3 水位线机制

```text
WriteBufferWaterMark 防止写缓冲区无限膨胀：

  High Watermark（高水位 64KB）：
    → Channel.isWritable() 返回 false
    → 应用层暂停写入，避免 OOM

  Low Watermark（低水位 32KB）：
    → 缓冲区降到低水位以下
    → Channel.isWritable() 恢复 true
    → 恢复写入

使用方法：
  if (ctx.channel().isWritable()) {
      ctx.writeAndFlush(msg);
  } else {
      // 等待 channelWritabilityChanged 事件后重试
  }
```

## 3. 常见设计模式

### 3.1 Singleton Handler（@Sharable）

```java
@Sharable   // 无状态 Handler，可被多个 Channel 共享
public class StatelessHandler extends ChannelInboundHandlerAdapter {
    @Override
    public void channelRead(ChannelHandlerContext ctx, Object msg) {
        // 无成员变量 → 线程安全 → 可共享
    }
}

// 所有 Channel 共用同一个实例
StatelessHandler sharedHandler = new StatelessHandler();
pipeline.addLast(sharedHandler);
```

### 3.2 Channel 连接池

```java
// 复用 Channel，避免频繁建连
public class ChannelPool {
    private final ConcurrentHashMap<String, Channel> channels = new ConcurrentHashMap<>();

    public Channel getChannel(String address) {
        return channels.computeIfAbsent(address, addr -> {
            // 创建新连接并缓存
            return bootstrap.connect(addr.split(":")[0],
                     Integer.parseInt(addr.split(":")[1]))
                    .syncUninterruptibly().channel();
        });
    }
}
```

### 3.3 Promise-Future 异步编排

```java
// 多个异步操作组合
ChannelFuture write1 = ctx.writeAndFlush(msg1);
ChannelFuture write2 = ctx.writeAndFlush(msg2);

// 等待全部完成
Promise<Void> allDone = ctx.executor().newPromise();
int[] count = {2};
write1.addListener(f -> { if (--count[0] == 0) allDone.setSuccess(null); });
write2.addListener(f -> { if (--count[0] == 0) allDone.setSuccess(null); });

allDone.addListener(f -> {
    if (f.isSuccess()) {
        System.out.println("两个消息都发送成功");
    }
});
```

## 4. 性能压测要点

```java
// 压测时关键监控指标
public class MetricsHandler extends ChannelInboundHandlerAdapter {

    private final AtomicLong receivedCount = new AtomicLong();
    private long lastCheckTime = System.currentTimeMillis();

    @Override
    public void channelRead(ChannelHandlerContext ctx, Object msg) {
        receivedCount.incrementAndGet();
        ReferenceCountUtil.release(msg);   // 仅计数，释放掉
    }

    // 每秒打印 TPS
    public void startReport() {
        ctx.executor().scheduleAtFixedRate(() -> {
            long now = System.currentTimeMillis();
            long elapsed = now - lastCheckTime;
            long count = receivedCount.getAndSet(0);
            long tps = count * 1000 / Math.max(elapsed, 1);
            System.out.printf("TPS: %d, 连接数: %d%n", tps, ...);
            lastCheckTime = now;
        }, 1, 1, TimeUnit.SECONDS);
    }
}
```

| 指标 | 说明 | 关注点 |
|------|------|--------|
| TPS | 每秒处理消息数 | Worker 线程数是否打满 |
| 连接数 | 当前活跃连接数 | 是否接近 `ulimit -n` |
| P99 延迟 | 消息端到端延迟 | Handler 链是否有瓶颈 |
| Direct 内存 | 堆外内存使用 | 是否接近 `MaxDirectMemorySize` |

## 5. 常见故障排查

| 现象 | 可能原因 | 排查 |
|------|----------|------|
| `OutOfDirectMemoryError` | Direct ByteBuf 未释放 | 开启泄漏检测、检查 Handler 是否 `release()` |
| 客户端频繁断连 | 空闲检测超时/心跳间隔不对 | 检查 IdleStateHandler 配置 |
| 服务端 CPU 100% | Worker 线程有死循环/空轮询 | `jstack <pid>` 查看线程栈 |
| OOM（堆内存） | Write Buffer 无限制 | 设置 `WRITE_BUFFER_WATER_MARK` |
| 响应延迟高 | Handler 链中有阻塞操作 | 检查是否有 DB/IO 在 EventLoop 线程执行 |

### 排查命令

```bash
# 1. 查看 Netty 内存泄漏
grep "LEAK" app.log

# 2. 查看直接内存使用
jcmd <pid> VM.native_memory summary

# 3. 查看线程栈（定位阻塞）
jstack <pid> | grep -A 20 "nioEventLoop"

# 4. 查看文件句柄数
ls /proc/<pid>/fd/ | wc -l

# 5. 查看 TCP 连接状态
ss -ant | awk '{print $1}' | sort | uniq -c
```

## 6. 生产 Checklist

| 分类 | 检查项 | 推荐配置 |
|------|--------|----------|
| **线程** | Boss = 1-2, Worker = CPU×2 | `NioEventLoopGroup(1)`, `NioEventLoopGroup(8)` |
| **内存** | 池化 + Direct | `PooledByteBufAllocator.DEFAULT` |
| **内存** | 限制直接内存 | `-XX:MaxDirectMemorySize=512m` |
| **内存** | 泄漏检测 | `SIMPLE`(生产) / `PARANOID`(开发) |
| **协议** | 粘包处理 | `LengthFieldBasedFrameDecoder` |
| **心跳** | 空闲检测 | `IdleStateHandler` + PING/PONG |
| **断连** | 重连机制 | 指数退避 |
| **缓冲** | 写水位线 | `WriteBufferWaterMark(32KB, 64KB)` |
| **TCP** | TCP_NODELAY | true |
| **性能** | Linux Epoll | `EpollEventLoopGroup` |

> 🎯 **Netty 调优公式**：Epoll + 池化 Direct + 业务线程隔离 + 水位线限制 + 泄漏检测。这 5 项到位，Netty 性能基本到顶。
