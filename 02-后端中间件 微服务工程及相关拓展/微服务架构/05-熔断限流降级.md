## 1. 雪崩效应

> **背景**：微服务相互依赖——一个服务故障可能级联放大，最终全系统瘫痪。
> **目的**：理解雪崩的传导机制（治理的出发点）。
> **适用范围**：所有微服务系统。

```text
雪崩传导链路
├── ① 起点：服务 C 故障（慢/挂）
├── ② 放大：B 调 C 超时 → B 的线程被占用（等待）
│   ├── B 的线程池耗尽（新请求无线程）
│   └── B 也开始超时/拒绝
├── ③ 蔓延：A 调 B 超时 → A 线程耗尽
├── ④ 结果：全链路雪崩（级联瘫痪）
└── ⑤ 金句：雪崩 = 「超时等待 → 线程耗尽 → 级联放大」

雪崩的四种形态
├── ① 流量突增（高峰打垮）
├── ② 缓存穿透（绕过缓存打库）
├── ③ 资源耗尽（线程/连接池）
├── ④ 单点故障（关键服务挂）
```

---

## 2. 三道防线

> 🎯 **2026 治理框架：限流（第一道）→ 熔断（第二道）→ 降级（第三道）**：

```text
三道防线
├── ① 限流（入口保护——防打垮）
│   ├── 位置：网关 + 服务入口
│   ├── 手段：QPS/线程数限制
│   └── 作用：拦截突刺流量
├── ② 熔断（依赖保护——防拖垮）
│   ├── 位置：服务调用（Feign 层）
│   ├── 手段：失败比例/慢调用触发断开
│   └── 作用：故障依赖快速失败（不等待）
├── ③ 降级（业务兜底——保可用）
│   ├── 位置：服务业务逻辑
│   ├── 手段：默认值/缓存/跳过
│   └── 作用：故障时给「可用但不完美」的响应
└── ④ 金句：限流防「进来太多」、熔断防「等太久」、降级保「还能用」
```

## 3. Sentinel 核心能力

> **背景**：Sentinel（阿里开源）是 2026 国内微服务流量防护标准——细粒度流控 + 熔断 + 系统保护。
> **目的**：掌握 Sentinel 的三大能力与配置。
> **适用范围**：Spring Cloud Alibaba 生态。

```text
Sentinel 三大能力
├── ① 流控：QPS/线程数/关联/链路
│   ├── 热点参数限流（商品 ID 维度）
│   ├── 匀速排队（削峰）
│   └── 冷启动（预热）
├── ② 熔断：三种策略
│   ├── 慢调用比例（RT 超阈值比例）
│   ├── 异常比例
│   └── 异常数
├── ③ 系统保护：自适应
│   ├── 系统负载（Load）
│   ├── CPU 使用率
│   └── 入口 QPS/线程数
└── ④ 集成：Gateway/Feign/Spring MVC 自动适配

依赖
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-sentinel</artifactId>
</dependency>
```

## 4. 流控规则

### 4.1 核心规则

```java
// 代码方式配置流控规则
@Configuration
public class SentinelConfig {
    @PostConstruct
    public void initRules() {
        // ① 接口 QPS 限流
        FlowRule flowRule = new FlowRule();
        flowRule.setResource("/api/orders");       // 资源（接口）
        flowRule.setGrade(RuleConstant.FLOW_GRADE_QPS);  // QPS 维度
        flowRule.setCount(100);                    // 每秒 100
        flowRule.setControlBehavior(RuleConstant.CONTROL_BEHAVIOR_DEFAULT);

        // ② 热点参数限流（商品 ID）
        ParamFlowRule paramRule = new ParamFlowRule();
        paramRule.setResource("query-stock");
        paramRule.setParamIdx(0);                  // 第一个参数
        paramRule.setCount(50);                    // 每秒 50

        FlowRuleManager.loadRules(List.of(flowRule));
        ParamFlowRuleManager.loadRules(List.of(paramRule));
    }
}
```

### 4.2 流控策略

```text
流控策略（按场景）
├── ① 快速失败：超阈值直接拒绝（默认）
├── ② Warm Up：冷启动（保护刚启动的服务）
│   └── 阈值从 1/3 逐步到满（预热 10s）
├── ③ 匀速排队：请求排队（削峰）
│   └── 超时时间内的请求排队处理
└── ④ 关联流控：资源 A 超限 → 限制资源 B
    └── 场景：写接口慢 → 限读接口（防资源争抢）
```

## 5. 熔断规则

```java
// 熔断规则（三种策略）
@Configuration
public class DegradeConfig {
    @PostConstruct
    public void initDegradeRules() {
        // ① 慢调用比例熔断
        DegradeRule slowRule = new DegradeRule();
        slowRule.setResource("GET:/api/orders/{id}");
        slowRule.setGrade(RuleConstant.DEGRADE_GRADE_RT);   // 慢调用
        slowRule.setCount(500);           // RT > 500ms 算慢
        slowRule.setTimeWindow(30);       // 熔断 30s
        slowRule.setSlowRatioThreshold(0.5);  // 慢调用比例 > 50%

        // ② 异常比例熔断
        DegradeRule exRule = new DegradeRule();
        exRule.setResource("POST:/api/payments");
        exRule.setGrade(RuleConstant.DEGRADE_GRADE_EXCEPTION_RATIO);
        exRule.setCount(0.3);             // 异常比例 > 30%
        exRule.setTimeWindow(30);

        // ③ 异常数熔断
        DegradeRule countRule = new DegradeRule();
        countRule.setResource("query-stock");
        countRule.setGrade(RuleConstant.DEGRADE_GRADE_EXCEPTION_COUNT);
        countRule.setCount(10);           // 1 分钟内异常 > 10

        DegradeRuleManager.loadRules(List.of(slowRule, exRule, countRule));
    }
}
```

```text
熔断机制
├── ① 半开恢复：熔断窗口后试探（放 1 个请求）
│   ├── 成功 → 关闭熔断（恢复）
│   └── 失败 → 继续熔断
├── ② 时间窗口：默认 30s（防频繁断开）
└── ③ 金句：熔断 = 「快速失败」——不让请求等待必挂的服务
```

## 6. 规则持久化

> ⚠️ **Sentinel 规则默认在内存——重启丢失**（生产必配持久化）：

```text
规则持久化到 Nacos（配置即代码）
├── ① 问题：内存规则 Pod 重启后丢失
├── ② 方案：datasource 推送 Nacos
│   ├── 控制台改规则 → Nacos
│   ├── 服务监听 Nacos → 热更新
│   └── 重启后从 Nacos 拉取
├── ③ 配置（NacosDataSource）：
│   ├── Nacos 配置：sentinel-flow.json（流控规则）
│   ├── sentinel-degrade.json（熔断规则）
│   └── 服务启动读取 + 监听变更
└── ④ 价值：
    ├── 规则不丢（重启恢复）
    ├── 热更新（改规则不重启）
    └── 规则即代码（评审/审计）
```

```yaml
# Sentinel 数据源配置（Nacos 持久化）
spring:
  cloud:
    sentinel:
      datasource:
        flow:
          nacos:
            server-addr: nacos:8848
            dataId: sentinel-flow
            groupId: SENTINEL_GROUP
            rule-type: flow
        degrade:
          nacos:
            server-addr: nacos:8848
            dataId: sentinel-degrade
            groupId: SENTINEL_GROUP
            rule-type: degrade
```

## 7. 降级设计

> 🎯 **降级必须按业务定制——不能一刀切**（2026 重要认知）：

```text
降级分级（按业务影响）
├── ① 查询类：返回保守默认值
│   ├── 库存查询失败 → 返回「库存不足」或缓存值
│   └── 数据带「不可靠」标记
├── ② 写操作：不能降级！
│   ├── 扣库存失败 → 降级 = 超卖！
│   └── 必须抛异常（让调用方处理）
├── ③ 非核心：直接降级
│   ├── 通知/积分 → 记录跳过
│   └── 或进 MQ 补偿
└── ④ 缓存兜底：优先读缓存（降级数据源）
    └── 缓存数据 + 异步刷新

降级实现（Feign fallback）
@FeignClient(name = "inventory-service",
    fallbackFactory = InventoryFallbackFactory.class)
public interface InventoryClient { ... }

@Component
public class InventoryFallbackFactory
        implements FallbackFactory<InventoryClient> {
    @Override
    public InventoryClient create(Throwable cause) {
        return new InventoryClient() {
            @Override
            public StockDTO queryStock(String skuId) {
                log.warn("库存服务降级: {}", cause.getMessage());
                return StockDTO.UNKNOWN;   // 查询降级：保守值
            }
        };
    }
}
```

## 8. 生产实践清单

```text
Sentinel 生产实践清单
[ ] 规则持久化 Nacos？（内存规则重启丢失！）
[ ] 流控：接口 QPS + 热点参数（商品/用户维度）
[ ] 熔断：慢调用 + 异常比例（timeWindow 30s）
[ ] 降级：按业务定制（读默认值/写抛异常）
[ ] 网关限流：令牌桶 + Redis（分布式）
[ ] 超时链路：网关 > 下游最大（见 02/04 篇）
[ ] 重试幂等：重试次数 ≤2 + 幂等键
[ ] 线程池隔离：核心依赖独立线程池（防耗尽传染）
[ ] 监控：熔断/限流事件告警
[ ] 演练：故障演练（人为熔断验证降级）

⚠️ 常见坑
├── ① 规则不持久化（重启丢失——最普遍）
├── ② 熔断窗口太小（频繁开合）
├── ③ 降级一刀切（写操作降级 = 数据错误）
├── ④ 无演练（降级逻辑线上才发现不对）
└── ⑤ 金句：治理 = 「规则 + 持久化 + 演练」三件套
```

## 9. 核心要点

> 🎯 **核心要点**：
> 1. 雪崩 = 超时等待 → 线程耗尽 → 级联放大——分布式头号杀手
> 2. 三道防线：限流（防打垮）+ 熔断（防拖垮）+ 降级（保可用）
> 3. Sentinel 三能力：流控（QPS/热点/冷启动）+ 熔断（慢调用/异常）+ 系统保护
> 4. **规则必须持久化 Nacos**（内存规则重启丢失——最普遍坑）
> 5. 降级定制：读操作给默认值、写操作必须抛异常（保数据正确）
> 6. 生产清单：持久化 + 超时链路 + 重试幂等 + 故障演练
