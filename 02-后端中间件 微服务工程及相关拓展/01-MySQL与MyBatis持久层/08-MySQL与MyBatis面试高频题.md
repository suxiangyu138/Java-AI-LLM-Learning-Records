## 1. 存储引擎与基础

### 1.1 InnoDB 和 MyISAM 区别

| 特性 | InnoDB | MyISAM |
|------|--------|--------|
| 事务 | 支持 | 不支持 |
| 锁粒度 | 行级锁 | 表级锁 |
| MVCC | 支持 | 不支持 |
| 外键 | 支持 | 不支持 |
| 崩溃恢复 | 支持（崩溃安全） | 易丢数据 |
| 全文索引 | 支持（MySQL 5.6+） | 支持 |
| 生产推荐 | **必选** | 基本淘汰 |

### 1.2 事务四大特性（ACID）

| 特性 | 说明 | 实现机制 |
|------|------|----------|
| **A** 原子性 | 事务要么全部执行，要么全部回滚 | undo log |
| **C** 一致性 | 事务前后数据完整性约束不变 | 应用层 + 数据库约束 |
| **I** 隔离性 | 多个事务互相隔离互不干扰 | MVCC + 锁 |
| **D** 持久性 | 事务提交后数据永久落地，崩溃不丢失 | redo log |

### 1.3 四大隔离级别

| 级别 | 脏读 | 不可重复读 | 幻读 | 默认 |
|------|------|-----------|------|------|
| READ UNCOMMITTED | 可能 | 可能 | 可能 | - |
| READ COMMITTED | 避免 | 可能 | 可能 | Oracle 默认 |
| **REPEATABLE READ** | 避免 | 避免 | 可能（InnoDB 间隙锁抑制） | **MySQL 默认** |
| SERIALIZABLE | 避免 | 避免 | 避免 | - |

### 1.4 脏读、不可重复读、幻读

| 问题 | 定义 | 解决 |
|------|------|------|
| **脏读** | 一个事务读到另一个事务**未提交**的数据 | 读已提交及以上 |
| **不可重复读** | 同一事务内，两次查同一数据，结果不同（其他事务修改提交） | 可重复读及以上 |
| **幻读** | 同一事务范围查询，前后行数不一致（其他事务插入/删除） | 串行化（或间隙锁） |

## 2. 索引（重中之重）

### 2.1 为什么索引用 B+ 树

| 特性 | 说明 |
|------|------|
| 多路平衡树 | 层高低，磁盘 IO 少（3~4 层即可存千万级数据） |
| 非叶子节点只存键 | 内存利用率高，可缓存更多索引 |
| 叶子节点双向链表 | **范围查询、排序、分页**性能极强 |
| B 树 vs B+ 树 | B 树叶子无链表，范围查询弱 |
| 哈希索引 | 不支持范围查询与排序，仅适用于等值查询 |

### 2.2 聚簇索引与二级索引

| 类型 | 说明 |
|------|------|
| **聚簇索引** | 主键索引，叶子节点存整行数据，一张表只有一个 |
| **二级索引** | 普通/联合/唯一索引，叶子节点只存主键值，查到后需回表 |

### 2.3 回表与覆盖索引

| 概念 | 说明 |
|------|------|
| **回表** | 通过二级索引拿到主键，再走聚簇索引查整行数据 |
| **覆盖索引** | 查询字段全部在索引中，无需回表，性能极高 |

```sql
-- 索引 (username, phone)
-- 覆盖索引：不回表
SELECT username, phone FROM t_user WHERE username = 'zhangsan';
-- 非覆盖索引：需回表
SELECT * FROM t_user WHERE username = 'zhangsan';
```

### 2.4 联合索引最左前缀原则

联合索引 `(a, b, c)`：

| 查询条件 | 是否走索引 |
|----------|-----------|
| `a` | 走 |
| `a, b` | 走 |
| `a, b, c` | 走 |
| `b` | **不走** |
| `c` | **不走** |
| `b, c` | **不走** |
| `a, c` | 走 a（跳 b 后 c 不走） |

> 范围条件（`>` `<` `LIKE%`）后面的索引列全部失效。

### 2.5 索引失效常见场景

| 场景 | 示例 | 解决 |
|------|------|------|
| LIKE 以 % 开头 | `LIKE '%keyword'` | 改 `LIKE 'keyword%'` |
| 隐式类型转换 | `WHERE phone = 13800000000` | 字符串加引号 |
| OR 两边未都建索引 | `WHERE a=1 OR b=2` | 两边都建索引或用 UNION |
| NOT IN / NOT EXISTS | `WHERE id NOT IN (1,2)` | 改 LEFT JOIN + IS NULL |
| 函数操作索引列 | `WHERE YEAR(created_at)=2024` | 改范围查询 |
| 联合索引跳列 | 查询 b 不查 a | 调整索引顺序 |

### 2.6 哪些字段不建索引

频繁更新、数据量小、重复度极高（性别、状态）、大文本字段。

## 3. MVCC 底层原理

### 3.1 什么是 MVCC

多版本并发控制（Multi-Version Concurrency Control），InnoDB 实现**无锁读**（读写不阻塞），大幅提升并发性能。

### 3.2 核心组成

| 组件 | 作用 |
|------|------|
| undo log | 保存数据的历史版本 |
| ReadView | 事务隔离的快照 |
| 隐藏列 | `DB_TRX_ID`（事务ID）、`ROLL_PTR`（回滚指针）组成版本链 |

### 3.3 RR 与 RC 的区别

| 隔离级别 | ReadView 生成时机 | 表现 |
|----------|------------------|------|
| RC | 每次查询都生成新的 ReadView | 会出现不可重复读 |
| **RR** | 事务首次查询时生成 ReadView，后续复用 | 保证可重复读 |

## 4. 三大日志

### 4.1 redo log（重做日志）

| 维度 | 说明 |
|------|------|
| 作用 | **崩溃恢复**，保证事务持久性 |
| 原理 | 先写日志再写磁盘（WAL），宕机重启后重做未落地的数据 |
| 配置 | `innodb_log_file_size`、`innodb_flush_log_at_trx_commit` |

### 4.2 undo log（回滚日志）

| 维度 | 说明 |
|------|------|
| 作用 | 事务回滚、MVCC 版本链 |
| 存储 | 数据修改前的旧版本 |

### 4.3 binlog（二进制日志）

| 维度 | 说明 |
|------|------|
| 作用 | **主从复制、数据归档、恢复** |
| 三种格式 | STATEMENT（记录 SQL）、ROW（记录行变更，主流）、MIXED |

## 5. 锁机制

### 5.1 锁分类

| 类型 | 说明 |
|------|------|
| 表锁 | 开销小、并发低，MyISAM 常用 |
| 行锁 | InnoDB，粒度细、并发高，只锁当前行 |
| 意向锁 | 表级辅助锁，快速判断表是否有行锁 |

### 5.2 InnoDB 行锁三种算法

| 算法 | 说明 |
|------|------|
| Record Lock（记录锁） | 锁单行 |
| Gap Lock（间隙锁） | 锁间隙，防止插入 |
| Next-Key Lock（临键锁） | 记录锁 + 间隙锁，RR 级别默认，解决幻读 |

### 5.3 死锁

| 维度 | 说明 |
|------|------|
| 必要条件 | 互斥、请求保持、不可剥夺、循环等待 |
| 解决方式 | 超时机制、死锁检测、统一加锁顺序、小事务 |

### 5.4 悲观锁与乐观锁

| 锁 | 说明 | 适用场景 |
|----|------|----------|
| 悲观锁 | 默认并发冲突多，`SELECT ... FOR UPDATE` 加锁 | 写多读少 |
| 乐观锁 | 版本号/时间戳，不加锁，更新时比对 | 读多写少 |

## 6. SQL 优化

### 6.1 EXPLAIN 关键字段

| 字段 | 说明 | 重点关注 |
|------|------|----------|
| **type** | 访问类型（从优到劣） | `const > eq_ref > ref > range > index > ALL` |
| key | 实际使用的索引 | NULL 表示没走索引 |
| rows | 预估扫描行数 | 越小越好 |
| Extra | 额外信息 | `Using filesort` 需优化；`Using index` 是好事 |

```sql
type 排序：system > const > eq_ref > ref > range > index > ALL
                                                  ↑ 至少达到 range
```

### 6.2 LIMIT 大分页优化

```sql
-- 慢（OFFSET 越大越慢）
SELECT * FROM t_order LIMIT 100000, 10;

-- 快（主键回溯）
SELECT * FROM t_order WHERE id > 100000 LIMIT 10;
```

### 6.3 COUNT 区别

| 写法 | 说明 |
|------|------|
| `COUNT(*)` | 统计行数，InnoDB 最优，忽略 NULL |
| `COUNT(1)` | 效果同 `COUNT(*)` |

### 6.4 禁止 SELECT *

- 多查无用字段，无法走覆盖索引
- 增加网络与 IO 开销

## 7. 主从复制与高可用

### 7.1 主从复制流程

```
1. 主库写入记录 → binlog
2. 从库 IO 线程 → 拉取 binlog → 写入 relay-log
3. 从库 SQL 线程 → 重放 relay-log → 同步数据
```

### 7.2 主从延迟原因

网络延迟、主库大事务、从库单线程回放（MySQL 5.6+ 支持多线程）、大批量写入。

### 7.3 分库分表

| 方式 | 说明 |
|------|------|
| 垂直拆分 | 按业务模块拆表 |
| 水平拆分 | 按 ID/时间分片拆大数据量表，解决单表千万级性能瓶颈 |

## 8. MyBatis 高频题

### 8.1 #{} 与 ${} 区别

| 维度 | `#{}` | `${}` |
|------|-------|-------|
| 底层 | PreparedStatement（预编译） | Statement（字符串拼接） |
| SQL 注入 | 无风险 | 有风险 |
| 用途 | 传字段值 | 传表名/列名/排序 |
| 优先 | 优先使用 | 谨慎使用 |

### 8.2 一级缓存与二级缓存

| 对比 | 一级缓存 | 二级缓存 |
|------|---------|---------|
| 默认 | 开启（不可关闭） | 关闭 |
| 范围 | SqlSession 级别 | Mapper Namespace 级别 |
| 跨会话 | 不共享 | 共享 |
| 序列化 | 不需要 | 实体需 Serializable |

### 8.3 MyBatis 插件原理

拦截四大核心对象：`Executor` → `StatementHandler` → `ParameterHandler` → `ResultSetHandler`

典型用途：PageHelper 分页（拦截 Executor，拼接 COUNT + LIMIT SQL）。

### 8.4 MyBatis 核心组件

| 组件 | 职责 |
|------|------|
| `SqlSessionFactoryBuilder` | 解析配置，构建工厂 |
| `SqlSessionFactory` | 创建 SqlSession，应用级别单例 |
| `SqlSession` | 数据库会话，CRUD API |
| `Executor` | SQL 执行器，缓存 + 事务 |
| `StatementHandler` | JDBC Statement 封装 |

## 9. 高频场景简答题

| 场景 | 解答要点 |
|------|----------|
| **大表加索引** | 使用 `ALGORITHM=INPLACE LOCK=NONE` 避免锁表 |
| **超卖解决** | 数据库悲观锁（FOR UPDATE）、乐观锁（版本号）、Redis 分布式锁、库存原子扣减 |
| **长事务危害** | 锁久不释放、undo log 膨胀、库性能下降、主从延迟 |
| **三高场景** | 读写分离（主从）、分库分表、Redis 缓存、MQ 削峰 |
| **SQL 执行慢** | 先 EXPLAIN 看 type → 检查索引 → 改写 SQL → 查锁等待 |
| **如何设计索引** | 高频查询字段 + 区分度高 + 联合索引最左匹配 + 覆盖索引优化 |

> 🎯 **面试关键**：MySQL 面试 70% 集中在"索引 + 事务 + 锁 + MVCC"这四个主题，建议结合源码和实际场景作答，避免死记硬背。
