## 1. 必背考点：十二问

### 1.1 什么是 IoC？BeanFactory 和 ApplicationContext 的区别？

**答题链**：IoC 定义（创建/装配/生命周期反转给容器）→ BeanFactory（最底层、惰性实例化、能力最小）→ ApplicationContext（叠加五能力：可列举/分层/国际化/事件/资源 + 单例预加载）→ 工程中始终用 ApplicationContext → Boot 内部是 AnnotationConfigServletWebServerApplicationContext。

### 1.2 依赖注入有哪几种方式？为什么推荐构造器注入？

**答题链**：三种方式表（构造器/setter/字段）→ 构造器优点（不可变 + 必填 + 可测 + 循环依赖立即暴露）→ 字段注入缺点（藏依赖、测试难、可变）→ 可选依赖用 setter 的例外。

### 1.3 @Autowired 多个候选怎么解决？

**答题链**：装配顺序（类型 → @Primary → @Priority → 名字 → 报错）→ 推荐组合（一个 @Primary 默认 + 注入点 @Qualifier 点名）→ 扩展：泛型注入、Map/List 集合注入（策略注册表）。

### 1.4 Bean 的生命周期？

**答题链**：九阶段（图纸 → 实例化 → 属性填充 → Aware → BPP before → 初始化三选 → BPP after（AOP 代理）→ 使用 → 销毁）→ 初始化三种写法与顺序（@PostConstruct → InitializingBean → initMethod）→ 销毁同理 → AOP 代理在 after 阶段创建的意义。

### 1.5 循环依赖怎么解决？什么情况解决不了？

**答题链**：成因（A↔B）→ 三级缓存提前暴露引用（源码见深度剖析系统）→ 可解决：字段/setter + singleton → 不可解决：构造器循环、prototype、代理冲突 → 工程态度：重构优先。

### 1.6 什么是 AOP？Spring AOP 的实现原理？

**答题链**：横切关注点与解耦 → 四概念（切点/通知/切面/织入）→ 五通知与 @Around → **实现 = 运行期动态代理**（JDK/CGLIB）→ Spring 7.0 CGLIB 一致默认 → 生效前提（调用必须走代理）。

### 1.7 JDK 动态代理 vs CGLIB？

**答题链**：接口 vs 子类 → 限制（final 类/方法不可代理）→ 历史选择逻辑（有接口 JDK 默认）→ **Spring 7.0 起 CGLIB 一致默认** → 性能与 AOT 考量。

### 1.8 @Transactional 为什么失效？有哪些场景？

**答题链**：总纲（**没走代理 + 异常没让事务看到**）→ 七场景（自调用/非 public/final/吞异常/受检异常/代理顺序/多数据源）→ 事务机制链（注解 → AOP → 事务管理器 → 数据源）。

### 1.9 事务传播行为 REQUIRED / REQUIRES_NEW / NESTED？

**答题链**：三兄弟语义（同生共死/各自独立/保存点）→ 典型场景（日志独立提交用 REQUIRES_NEW）→ 注意自调用失效。

### 1.10 Spring 事件机制？

**答题链**：观察者模式 → 三角色（事件/发布者/监听者）→ 默认同步 → @Async 异步（拆类防自调用）→ **@TransactionalEventListener 事务提交后才响应**（防"回滚了还发短信"）→ 异常自治原则。

### 1.11 @Value 和 @ConfigurationProperties 的区别？

**答题链**：单值 vs 成组 → 无类型安全 vs 类型安全绑定 + @Validated 启动校验 → 映射规则（kebab-case → camelCase）→ 使用标准（3+ 相关项建配置类）。

### 1.12 Spring 7.0 有哪些关键变化？

**答题链**（2025-11 GA）：Jakarta EE 11 与 javax.* 移除 → Java 17 基线/JDK 25 推荐 → JSpecify 空安全 → BeanRegistrar（AOT 友好编程式注册）→ **CGLIB 一致默认 + @Proxyable** → 原生 @Retryable/@ConcurrencyLimit → 移除 spring-jcl。对应 Boot 4.0：模块化 Starter、OpenTelemetry Starter、虚拟线程默认开启。

## 2. 高频陷阱题 10 连问

1. **对错**：`@Component` 类里的 `@Bean` 方法每次调用都新建实例。（✅ 对——只有 @Configuration 类被 CGLIB 代理保证单例）
2. **对错**：`@Transactional` 加在 private 方法上生效。（❌ 代理只拦 public）
3. **对错**：`@Transactional` 默认对受检异常回滚。（❌ 只回滚 RuntimeException/Error，需 rollbackFor=Exception.class）
4. **结果**：A 事务调 B（REQUIRES_NEW），B 回滚，A 会怎样？（A 不受影响继续；B 的回滚不传播）
5. **对错**：原型 Bean 的 @PreDestroy 会被容器调用。（❌ 容器不管理 prototype 的销毁）
6. **对错**：singleton 注入 prototype 字段，每次使用都是新实例。（❌ 注入只发生一次，需 ObjectProvider/@Lookup）
7. **结果**：构造器注入的循环依赖能解决吗？（❌ BeanCurrentlyInCreationException）
8. **对错**：Spring 事件默认是异步的。（❌ 默认同步，@Async 才异步）
9. **对错**：`@TransactionalEventListener` 默认在事务提交后触发。（✅ AFTER_COMMIT；无事务默认不触发）
10. **结果**：final 类能被 Spring AOP 代理吗？（❌ CGLIB 也无法代理 final 类）

## 3. 高频追问速答（一句话版本）

| 追问 | 速答 |
|------|------|
| 为什么 @Configuration 类必须被 CGLIB 代理？ | 保证 @Bean 方法单例语义——拦截后先查缓存 |
| Spring Boot 怎么找到 @SpringBootApplication？ | 主类被 @SpringBootApplication 的 @ComponentScan 扫描其所在包及子包 |
| 一个接口两个实现，不写任何注解怎么注入？ | 按参数名/字段名匹配 Bean 名（`@Autowired private PayChannel alipay`） |
| @Bean 方法参数从哪来？ | 自动按类型从容器装配（等价于构造器注入） |
| AOP 通知能拦截 static 方法吗？ | 不能——代理只覆盖实例方法 |
| @Async 方法的返回值？ | 返回 void 或 Future/CompletableFuture；直接返回对象会丢结果 |
| 事务方法里调用另一个事务方法（走代理）会怎样？ | REQUIRED：合并到同一事务 |
| 配置中心的配置能热更新吗？ | Nacos 等配置中心支持 refresh 机制（@RefreshScope），本地文件不行 |
| 测试里怎么禁用某个自动配置？ | `@SpringBootTest(properties = ...)` / `spring.autoconfigure.exclude` / @MockBean 覆盖 |
| 如何看到容器里所有 Bean？ | `ApplicationContext.getBeansOfType` / actuator `beans` 端点 / Debug 时看 DefaultListableBeanFactory |

> 💡 这十问覆盖面试官的"随口追问"——每题都是一句话的定性答案，展开细节对应本体系各模块。

## 4. 场景题：手写简化版 IoC 容器

**题目**：用反射实现一个支持 @Component + @Autowired 的迷你 IoC 容器（约 40 行）。

```java
// 注解（简化）
@interface Component { }
@interface Autowired { }

// 迷你容器
public class MiniIoc {
    private final Map<Class<?>, Object> beans = new HashMap<>();

    public void scan(String pkg) throws Exception {
        // ① 扫描包下带 @Component 的类（ClassPathScanningCandidateComponentProvider 简化版）
        for (Class<?> clazz : scanClasses(pkg)) {
            beans.put(clazz, clazz.getDeclaredConstructor().newInstance());  // ② 实例化
        }
        // ③ 属性注入（字段装配）
        for (Object bean : beans.values()) {
            for (Field f : bean.getClass().getDeclaredFields()) {
                if (f.isAnnotationPresent(Autowired.class)) {
                    f.setAccessible(true);
                    f.set(bean, beans.get(f.getType()));      // 按类型注入
                }
            }
        }
    }

    public <T> T get(Class<T> type) { return type.cast(beans.get(type)); }
}

// 验证
@Component class Dao { public String hi() { return "dao"; } }
@Component class Service {
    @Autowired Dao dao;
    public String serve() { return dao.hi(); }
}
new MiniIoc().scan("com.example");
```

**答题要点**：① 反射三件套（扫描/实例化/字段注入）② 说出与真实容器的差距：BeanDefinition、单例缓存、代理、生命周期回调、循环依赖处理——**能指出差距 = 真懂容器**。

## 5. 场景题：Spring 7.0 升级问答

**题目**：现有 Spring Boot 3.x 项目要升级到 Spring Boot 4 / Spring Framework 7，面试官问你会遇到哪些问题？

**答题框架**：

```text
① 基线确认：Java 17+（推荐 21/25）；Boot 3.5 → 4.0 迁移指南 + Spring Boot Migrator 工具
② 依赖变化：javax.* → jakarta.*（javax.annotation/javax.inject 被静默忽略，最隐蔽的坑）；
   spring-jcl 移除；Undertow 支持移除
③ 代理模型：CGLIB 一致默认 —— 检查依赖 JDK 代理行为/接口代理的代码
④ 可观测性：management.tracing.enabled → management.tracing.export.enabled；
   OpenTelemetry 专用 Starter（OTLP 导出）
⑤ 模块化 Starter：依赖坐标变化（如 MongoDB health 组件移动）；自动配置 public 成员移除 → 自研 Starter 用官方扩展点
⑥ 虚拟线程：Java 21+ 默认开启 —— 检查 ThreadLocal 使用（建议 ScopedValue）
⑦ 测试：JUnit 6、RestTestClient；TestContext 自动关闭上下文
```

## 6. 记忆口诀

```text
IoC 反转让容器，BeanFactory 是根基，ApplicationContext 五能力。
Bean 有三画：图纸（Definition）、成品（实例）、代理（AOP）——BPP 改实例 BFPP 改图纸。
注入三方式，构造器最优：不可变、必填、可测。
生命周期九步走：实例化 → 填充 → Aware → 前后处理器夹初始化，代理诞生在最后。
AOP 是代理：有接口 JDK、无接口 CGLIB、7.0 统一 CGLIB；自调用必失效。
事务四问：代理走了吗？异常看到了吗？传播选对了吗？管理器选对了吗？
事件三原则：默认同步、事务提交后响应（TransactionalEventListener）、监听器自治不连坐。
配置三件套：@Value 单值、ConfigurationProperties 成组、Profile 分环境。
```
