## 1. 选型方法论：配置怎么算

> **背景**：买服务器/开云主机，「2C4G 还是 8C16G」不能拍脑袋。
> **目的**：给出一套「先算后选」的方法。
> **适用范围**：从个人项目到生产系统（云上同理）。

```text
① 流量 → 并发 → 算力（自顶向下）
├── 日活 1 万：峰值 QPS ≈ 日活 × 0.1 ≈ 1000
├── 单请求耗时：典型 Java 接口 30-100ms
├── CPU 需求：QPS × 耗时 = 并行度
│   ├── 例：1000 QPS × 50ms = 50 并发处理
│   ├── 单核可并行处理 ~20 请求/秒（50ms 接口）
│   └── 需求 ≈ 50 核？→ 不对——缓存/异步让实际需求低 5-10 倍
├── 经验值（参考）
│   ├── 1000 QPS 业务：4C8G × 2 台（带缓存）
│   ├── 10000 QPS：8C16G × 4-8 台 + 缓存集群
│   └── 金句：先算 QPS，再算核数——别从「感觉」出发

② 内存怎么定
├── JVM 堆 = 实例数 × 堆大小（别让堆 > 物理内存 60%）
├── OS + 元空间 + 直接内存 ≈ 堆 × 0.5
├── 例：4G 内存 → 堆设 2G 左右（留 OS/GC 余量）
└── 数据库机：内存 = 数据量 × 0.3（buffer pool 热数据）

③ 磁盘与网络
├── 磁盘：容量（日志/数据增长）+ IOPS（数据库机重点）
├── 网络：带宽 = QPS × 平均响应体（1K 响应 × 1000QPS = 8Mbps）
│   └── 带宽通常被低估——检查大文件/图片场景
└── 金句：CPU 算并发，内存算容量，磁盘算 IO，网络算带宽
```

## 2. Linux 部署实战流程

> 🎯 **从「空服务器」到「服务上线」的七步**——2026 云主机标准流程：

```bash
# ① 登录（首选用密钥，别用密码）
ssh-keygen -t ed25519                # 生成密钥（本机）
ssh-copy-id root@<服务器IP>           # 上传公钥
ssh root@<服务器IP>                   # 密钥登录

# ② 系统初始化（新机必做）
sudo apt update && sudo apt upgrade -y        # Ubuntu 更新
sudo useradd -m deploy && sudo passwd deploy  # 非 root 账号（安全）
sudo timedatectl set-timezone Asia/Shanghai   # 时区

# ③ 基础软件（按需）
sudo apt install -y nginx git curl net-tools  # 常用
# Java 环境：SDKMAN（见 [[各种包管理器全方位剖析]] 08 篇）
curl -s "https://get.sdkman.io" | bash
sdk install java 21.0.5-temurin

# ④ 部署应用（容器为 2026 标准）
docker compose up -d                   # 应用 + 依赖（DB/Redis）
# 或 systemd 托管（非容器）
sudo systemctl enable myapp            # 开机自启

# ⑤ 反向代理接入
# nginx 配置：80/443 → 应用端口（8080）
# certbot 申请 HTTPS 证书（Let's Encrypt 免费）

# ⑥ 防火墙收口
sudo ufw allow 22/tcp && sudo ufw allow 80,443/tcp
sudo ufw enable

# ⑦ 监控接入（见第 4 节）
```

> ⚠️ **安全第一课**：新服务器上线前必做——改 SSH 端口或密钥登录、禁用 root 远程密码登录、防火墙收口、开自动更新。**默认配置直接上公网 = 24 小时内被入侵**。

## 3. 安全基线

> 🎯 **服务器的安全基线 = 「最小暴露面」**——攻击进不来，进来了也出不去：

```text
安全基线清单（服务器级）
├── ① 访问控制
│   ├── SSH：密钥登录 + 禁用密码 + 改端口（22→高位）+ fail2ban
│   ├── root 禁远程登录（sudo 提权）
│   └── 最小权限：应用账号 ≠ root
├── ② 网络
│   ├── 防火墙：只开需要的端口（ufw/firewalld/安全组）
│   ├── 管理口隔离：IPMI 不暴露公网
│   └── 入站/出站双向限制（防数据外带）
├── ③ 更新与漏洞
│   ├── 自动安全更新（unattended-upgrades）
│   ├── 定期漏洞扫描（trivy 扫容器镜像）
│   └── 关注高危 CVE（OpenSSH/内核）
├── ④ 数据
│   ├── 磁盘加密（LUKS 全盘加密）
│   ├── 数据库最小权限账号 + 网络隔离
│   └── 密钥管理（不用明文配置密码）
└── ⑤ 审计
    ├── 日志集中（auth.log 监控登录失败）
    └── 入侵检测（OSSEC/Wazuh——2026 免费方案）
```

## 4. 服务器监控第一课

> 🎯 **监控四指标起步**——CPU/内存/磁盘/网络，配合系统自带命令：

```bash
# 四件套速查
top                        # CPU/内存/负载（load 超核数 = 瓶颈）
free -h                    # 内存（available 为准，swap 用了要警惕）
df -h && iostat -x 1       # 磁盘容量 + I/O（util% 超 80% = 瓶颈）
ss -ant | head             # 网络连接（CLOSE_WAIT 堆积 = 应用 bug）

# 深入
ps aux --sort=-%cpu | head -10     # CPU 大户
dmesg | tail                       # 内核日志（OOM 杀进程在这看）
journalctl -u myapp -f             # 应用日志（systemd）
```

```text
监控告警建设（2026 标准）
├── 工具：Prometheus + Grafana（自建）/ 云监控（云上）
├── 指标：
│   ├── 基础：CPU/内存/磁盘/带宽使用率
│   ├── 业务：QPS/错误率/P99 延迟
│   └── 资源：连接数/线程数/GC 时间
├── 告警阈值（参考）：
│   ├── CPU > 85% 持续 10 分钟 → 告警
│   ├── 磁盘 > 85% → 告警（写满就完）
│   ├── 内存 swap 使用 > 0 → 告警（性能灾难）
│   └── 错误率 > 1% → 告警
└── 金句：监控不是「看面板」，是「异常能被发现」
```

## 5. 面试高频题

**Q1：服务器和普通电脑有什么区别？**

```text
答：原理相同（都是冯诺依曼机器），差异在工业标准：
① 可靠性——ECC 内存纠错、双电源、RAID 磁盘冗余；
② 性能——百核 CPU、TB 级内存、NVMe、10G+ 网卡；
③ 可管理——IPMI 带外管理（不依赖 OS 远程管理）；
④ 运行环境——机房恒温恒湿 7×24。
```

**Q2：为什么 Linux 是服务器主流操作系统？**

```text
答：开源免费（无授权费）、稳定可靠（内核级）、生态完整
（开发运维工具全家桶）、资源占用低（无桌面）、可裁剪、
且容器/云原生/K8s 全链路都建立在 Linux 之上。
```

**Q3：进程和线程的区别？**

```text
答：进程是资源容器（独立内存空间），线程是执行单位
（共享进程内存）。线程更轻（创建/切换开销小）。
Java 线程 = 原生线程；虚拟线程（JDK 21）是 JVM 管理的轻量线程。
```

**Q4：TCP 为什么三次握手？**

```text
答：双方确认「自己发的能到、对方发的能回」。
两次的话服务器无法确认客户端收到了自己的 SYN+ACK；
四次浪费。三次是建立双向可靠连接的最小次数。
```

**Q5：什么是 I/O 多路复用？epoll 为什么快？**

```text
答：一个线程同时监听 N 个连接，内核通知有事件的连接。
epoll 快在三改进：① 红黑树注册 fd（不用每次全量拷贝）；
② 就绪链表只返回有事件的 fd（不用 O(N) 全扫）；
③ 回调机制事件驱动（空闲连接零开销）。
```

**Q6：NIO、Netty、虚拟线程怎么选？**

```text
答：BIO 线程爆炸淘汰；NIO 是基础（Selector 封装 epoll）但 API
复杂；Netty 是工业级事件驱动框架（网关/框架层用）；
虚拟线程（JDK 21+）让阻塞式代码也能百万并发——业务服务
首选虚拟线程，框架层用 Netty。
```

**Q7：虚拟机和容器的区别？**

```text
答：VM 虚拟化硬件（每个 VM 有完整 Guest OS，内核级隔离，
启动分钟级，资源占用大）；容器共享宿主机内核（Namespace
隔离视图 + Cgroup 限资源，秒级启动，密度高）。
安全隔离要求高用 VM，应用标准化用容器——2026 是嵌套关系
（云底座 VM + 应用容器）。
```

**Q8：为什么 Redis 单线程还那么快？（跨体系经典）**

```text
答：① 内存操作本身快；② epoll I/O 多路复用（1 线程管
十万连接，空闲连接零开销）；③ 单线程避免了锁竞争和
上下文切换。瓶颈只在内存/网络，不在线程。
```

## 6. 核心要点

> 🎯 **核心要点**：
> 1. **选型先算**：QPS → 并发 → 核数；内存看堆，磁盘看 IO，带宽看响应体
> 2. **部署七步**：密钥登录 → 系统初始化 → 装环境 → 部署 → 反代 → 防火墙 → 监控
> 3. **安全基线**：密钥登录 + 防火墙收口 + 自动更新 + 最小权限——默认配置上公网必被入侵
> 4. **监控四件套**：CPU/内存/磁盘/网络——load 超核数、swap 出现、CLOSE_WAIT 堆积都是信号
> 5. **面试主线**：服务器 vs PC、Linux 地位、进程线程、三次握手、epoll、VM vs 容器、Redis 单线程
