## 1. 从物理机到云：抽象的三层

> **背景**：2010 前自建机房（物理机时代）→ 2010s 虚拟化（VM 时代）→ 2015+ 容器时代 → 2020s Serverless。
> **目的**：建立「抽象阶梯」——每一层都解决上一层的痛点。
> **适用范围**：云时代部署选型（ECS/容器/函数计算）。

```text
抽象阶梯（2026 全景）
├── ① 物理机（裸金属）
│   ├── 你直接拥有 CPU/内存/磁盘
│   ├── 痛点：资源浪费（一台机器跑不满）、扩缩容慢
│   └── 适用：极致性能/合规强隔离
├── ② 虚拟机（VM，2000s 起）
│   ├── 一台物理机切成 N 台「假机器」（各自完整 OS）
│   ├── 痛点解决：利用率↑（超卖）、开通快（分钟级）
│   └── 云服务器（ECS）的底层
├── ③ 容器（2015+）
│   ├── 一台 VM/物理机上跑 N 个隔离进程（共享内核）
│   ├── 痛点解决：更轻更快（秒级）、镜像可移植
│   └── Docker/K8s
└── ④ Serverless（2020s）
    ├── 连服务器都不用管——平台按函数调度
    ├── 痛点解决：弹性到极致（0→万→0）
    └── 函数计算（FaaS）

金句
├── 每层抽象 = 「你少管一层，代价是多一层心智」
├── 2026 现状：物理机（特殊场景）+ VM（主流底座）+ 容器（应用标准）三层并存
└── 云服务器 ≠ 神秘的东西——就是「租一台虚拟化的机器」
```

## 2. 虚拟机：硬件虚拟化

> 🎯 **VM 的核心：虚拟化「硬件」**——每个 VM 里有一个完整的、独立的操作系统：

```text
虚拟机原理
├── Hypervisor（虚拟化层）：资源分配器
│   ├── 类型 1（裸金属）：KVM（Linux 内置）/ VMware ESXi
│   │   └── 直接跑在硬件上（性能好，数据中心主流）
│   └── 类型 2（托管）：VirtualBox/VMware Workstation
│       └── 跑在 OS 上（桌面虚拟化）
├── 每个 VM 包含：虚拟 CPU/虚拟内存/虚拟磁盘/虚拟网卡
│   └── 完整的 Guest OS（内核独立！）
└── 特性：快照/迁移/克隆（虚拟机三大福利）

隔离与安全
├── 隔离级别：内核级隔离（最强）
│   └── VM 逃逸 = 攻破 Hypervisor（极难）
├── 资源配额：vCPU/内存严格分配（Cgroup + 调度）
└── 适用：多租户云（不同客户的机器互不感知）

性能开销
├── 虚拟化损耗：5-10%（现代硬件辅助虚拟化已很低）
├── 半虚拟化（virtio）：虚拟机 I/O 直接通道（损耗更低）
└── 金句：VM 是「重隔离 + 重开销」——隔离质量最高
```

## 3. 容器：进程级隔离

> 🎯 **容器 = 共享内核的隔离进程**——不虚拟化硬件，只「圈住」进程：

```text
容器两大内核机制（[[03]] 深化）
├── Namespace（隔离视图）：容器以为自己是唯一
│   ├── PID：只能看到自己的进程树
│   ├── Network：自己的 IP/端口
│   ├── Mount：自己的文件系统视图
│   └── UTS/User/IPC……
├── Cgroup（限制资源）：CPU/内存/磁盘/网络配额
└── OverlayFS：镜像分层（只读层 + 可写层）

容器生命周期
├── 镜像（Image）：模板（分层文件系统）
│   ├── docker build 构建 → 仓库存储 → pull 拉取
│   └── 分层缓存：改一层只重传一层（高效）
├── 容器（Container）：镜像的运行实例
│   └── 秒级启动（无内核启动过程）
└── 编排（K8s）：多台服务器的容器统一调度
    ├── Pod：最小调度单位（一组容器共享网络）
    ├── Deployment：副本管理/滚动发布
    ├── Service：服务发现 + 负载均衡
    └── 金句：Docker 管「单个容器」，K8s 管「一群容器」

容器安全边界（必须知道）
├── 共享内核 → 内核漏洞 = 容器逃逸风险
├── 特权容器（--privileged）：高危（别用）
├── 镜像供应链：用官方镜像 + 签名校验
└── 强隔离需求（多租户）→ 用 VM 不用容器
```

## 4. VM vs 容器：深度对比

| 维度 | 虚拟机 | 容器 |
|------|:---:|:---:|
| 隔离粒度 | 硬件级（完整内核） | 进程级（共享内核） |
| 隔离强度 | 强（内核独立） | 中（共享内核） |
| 启动时间 | 分钟级（引导内核） | 秒级（起进程） |
| 资源占用 | 大（整套 OS） | 小（KB-MB 级） |
| 密度 | 低（几十/台） | 高（几百/台） |
| 可移植性 | 低（绑定虚拟化平台） | 高（镜像标准） |
| 性能 | 有虚拟化损耗 | 近原生 |
| 安全 | 强隔离 | 共享内核风险 |
| 适用 | 多租户/异构 OS/强隔离 | 应用标准化/微服务/CI |

```text
2026 现实：两者是「嵌套关系」不是替代关系
├── 云厂商底座：VM（你的 ECS 是 VM）
├── 你的应用：容器（跑在 ECS 的 Docker/K8s）
└── 混合：容器内跑 VM？（Kata Containers——容器封装 VM 的隔离）
    └── gVisor/Kata：容器 + VM 隔离的合体方案（安全容器）
```

## 5. 公有云 IaaS 全景

> 🎯 **云服务器 = IaaS 的最小单元**——背后是完整的产品体系：

```text
云服务器（ECS/CVM）核心属性
├── 规格：vCPU/内存（2C4G/8C16G……）
├── 镜像：操作系统（Ubuntu/CentOS/Windows + 自定义镜像）
├── 磁盘：云盘（ESSD 高性能/SSD/高效云盘）+ 快照
├── 网络：VPC（专有网络）+ 弹性 IP + 安全组
├── 计费：包年包月/按量付费/竞价实例（省钱）
└── 运维：监控/告警/自动快照/密钥管理

VPC（专有网络）：云的隔离网络
├── 逻辑隔离：你的服务器组在一个私有网段（172.16.x.x）
├── 子网/路由表：网络规划（分层部署）
└── 与公网：NAT 网关/弹性 IP/负载均衡接入

安全组（云防火墙）
├── 规则：入站/出站白名单（端口级）
├── 例：只允许 22/80/443 入站
└── 金句：安全组 = 云上的「第一道防火墙」（必须配置）

高可用组合（云上标准架构）
├── 多可用区（AZ）：机房级容灾
├── 负载均衡（SLB）：流量分发 + 健康检查
├── 自动伸缩（AS）：按负载增减实例
└── 快照/备份：数据恢复
```

## 6. 裸金属与高性能场景

> 🎯 **裸金属（Bare Metal）= 没有虚拟化层的物理机**——云的形态，物理的隔离：

```text
裸金属适用场景
├── ① 高性能计算：数据库/缓存/计算密集
│   ├── 无虚拟化损耗（CPU 100% 可用）
│   ├── 资源独占（无邻居干扰——Noisy Neighbor 问题）
├── ② AI 训练：GPU 服务器（显存/带宽独占）
├── ③ 合规要求：金融/政务（物理隔离审计）
└── ④ 特殊硬件：FPGA/加密卡

虚拟化邻居问题（Noisy Neighbor）
├── 共享物理机的 VM 互相争抢 CPU/带宽
├── 表现：你的 ECS 突然变慢（邻居在跑大任务）
└── 对策：vCPU 配额/突发实例/上裸金属

裸金属 + 云化（云厂商方案）
├── 控制面云化：云控制台管理裸金属（弹性裸金属）
├── 存储网络云化：云盘/网络接云基础设施
└── 金句：裸金属 = 「物理机的性能 + 云的运维」
```

## 7. Serverless：连服务器都抽象掉

> 🎯 **Serverless = 「不关心服务器」**——平台按需运行你的函数/容器：

```text
Serverless 两种形态
├── FaaS（函数计算）：写函数即部署
│   ├── 阿里云 FC / AWS Lambda
│   ├── 触发：HTTP/事件/定时
│   ├── 计费：按调用次数 + 运行时长（不跑不收费）
│   └── 适合：定时任务/事件处理/轻量 API
├── 容器化 Serverless：容器按需调度
│   ├── K8s 自动扩缩（HPA 到 0）
│   └── 适合：有状态/长任务仍用容器

Serverless 的取舍
├── 优点：弹性极致（0→万→0）、免运维、按量付费
├── 缺点：冷启动延迟（函数首次调用慢）、有状态难、调试难
└── 2026 定位：**定时/事件型任务用 Serverless，核心业务服务用容器**
```

## 8. 云服务器选型

```text
云服务器选型五步（2026）
├── ① 场景定位
│   ├── Web 应用 → ECS/容器（2C4G 起步）
│   ├── 数据库 → 高内存型 + ESSD（别省磁盘）
│   ├── 高并发网关 → 网络增强型 + 多实例
│   ├── AI 推理 → GPU 实例（推理卡）
│   └── 训练 → GPU 集群（按卡付费）
├── ② 规格计算
│   ├── CPU：QPS × 单请求耗时 / 核数预算（如 2000QPS×50ms=100 核）
│   ├── 内存：JVM 堆 × 实例数 + OS（堆别超物理内存）
│   └── 磁盘：容量 + IOPS（ESSD 按 IOPS 计费）
├── ③ 架构决策
│   ├── 单机 → 负载均衡 + 多机（高可用）
│   ├── 多可用区（机房容灾）
│   └── 自建 vs 托管（DB 用云 RDS 还是自建 MySQL？）
├── ④ 成本策略
│   ├── 按量（弹性）+ 包年（稳定）混合
│   ├── 竞价实例（无状态任务省钱 80%）
│   └── 实例规格选「刚刚好」——虚高规格是最大浪费
└── ⑤ 安全基线
    ├── 安全组最小化（只开需要的端口）
    ├── 密钥登录（禁密码）
    ├── 系统盘快照策略
    └── 云监控告警（CPU/内存/流量）
```

## 9. 核心要点

> 🎯 **核心要点**：
> 1. **抽象四层**：物理机 → 虚拟机 → 容器 → Serverless——每层少管一层
> 2. **VM 虚拟化硬件**：完整 Guest OS + 内核级隔离（KVM 是主流）
> 3. **容器共享内核**：Namespace 隔离 + Cgroup 限额 + OverlayFS 分层镜像
> 4. **VM vs 容器**：不是替代是嵌套——云底座 VM、应用容器
> 5. **云 IaaS 全景**：ECS + VPC + 安全组 + SLB + 快照——安全组是云防火墙
> 6. **裸金属**：物理性能 + 云运维——AI 训练/合规场景
> 7. **Serverless**：定时/事件任务用，核心业务用容器
> 8. **选型五步**：场景 → 规格 → 架构 → 成本 → 安全基线
