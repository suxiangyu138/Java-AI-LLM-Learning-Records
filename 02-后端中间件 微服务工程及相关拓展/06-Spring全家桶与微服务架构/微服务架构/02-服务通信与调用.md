## 1. 服务通信方式

> **背景**：微服务间的通信是分布式系统的「神经」——同步/异步各司其职。
> **目的**：掌握通信方式选型。
> **适用范围**：所有微服务调用场景。

| 方式 | 技术 | 特点 | 场景 |
|------|------|------|------|
| **同步 HTTP** | OpenFeign/RestTemplate | 实时/易追踪 | 核心链路 |
| **同步 RPC** | Dubbo/gRPC | 高性能/强类型 | 内部高频调用 |
| **异步消息** | RocketMQ/Kafka | 解耦/削峰 | 非核心链路 |

```text
通信方式决策
├── ① 需要立即返回 → 同步（Feign/RPC）
├── ② 可以稍后处理 → 异步（MQ）
├── ③ 高性能内部调用 → RPC（Dubbo）
├── ④ 生态兼容 → HTTP（Feign——Spring 生态标准）
└── ⑤ 金句：2026 Java 微服务默认 = OpenFeign（HTTP）+ 消息队列（异步）
```

## 2. OpenFeign 声明式调用

### 2.1 基本用法

```java
// ① 定义 Feign 客户端（声明式——接口即调用）
@FeignClient(name = "order-service", path = "/api/orders")
public interface OrderClient {
    @GetMapping("/{orderId}")
    OrderDTO getOrder(@PathVariable String orderId);

    @PostMapping
    OrderDTO createOrder(@RequestBody CreateOrderCommand command);
}

// ② 使用（注入即可——像本地调用）
@Service
public class PaymentService {
    private final OrderClient orderClient;

    public void pay(String orderId) {
        OrderDTO order = orderClient.getOrder(orderId);   // 远程调用
        // 业务逻辑...
    }
}
```

### 2.2 配置要点

```yaml
# application.yml（Feign 配置）
feign:
  client:
    config:
      default:
        connectTimeout: 3000       # 连接超时（3s）
        readTimeout: 5000          # 读取超时（5s）
      order-service:               # 按服务定制
        connectTimeout: 1000
        readTimeout: 3000
```

```text
Feign 要点
├── ① 声明式：接口 + 注解（不写调用细节）
├── ② 负载均衡：集成 Spring Cloud LoadBalancer（Ribbon 已替代）
├── ③ 熔断集成：Sentinel/Resilience4j 可包装
├── ④ 超时配置：connectTimeout（连接）+ readTimeout（读取）
├── ⑤ ⚠️ 超时链路铁律（见下节）
└── ⑥ 2026：Feign + LoadBalancer + Sentinel 是标准组合
```

## 3. 超时链路铁律

> ⚠️ **超时是分布式第一坑**——超时设置不当导致：请求提前截断/级联超时/线程堆积：

```text
超时链路铁律（三层）
├── ① 网关 > 下游最大超时：
│   ├── 网关超时 < 服务超时 → 网关提前截断正常请求
│   └── 铁律：网关超时 > 所有下游服务超时的最大值
├── ② 链式调用 A→B→C：
│   ├── A 的超时 > B 超时 + B→C 耗时
│   └── 否则：A 先超时（B 还在处理——浪费）
├── ③ 每跳留余量：
│   ├── 调用方超时 = 被调方超时 + 传输余量
│   └── 例：C 超时 2s → B 调 C 设 3s → A 调 B 设 5s

超时的三个层
├── 连接超时（connect）：建立连接（网络问题）
├── 读取超时（read）：等待响应（服务慢/卡）
└── 全局超时（feign okhttp client）：总限制

⚠️ 超时相关的坑
├── ① 超时不设（默认无限等——线程堆积）
├── ② 超时链路倒挂（内层超时 > 外层——被截断）
├── ③ 超时后无降级（超时异常不处理——雪崩起点）
└── ④ 金句：超时 = 「防止线程无限等待」的保险丝
```

## 4. 重试与幂等

### 4.1 重试的决策

```text
什么时候重试
├── ✅ 可重试：网络抖动/连接超时/瞬时 5xx
├── ❌ 不可重试：业务错误（4xx）/请求已生效
└── ⚠️ 重试的前提 = 幂等（见下）

重试的配置
├── ① 次数：默认 1-2 次（多则放大压力）
├── ② 间隔：指数退避（0.5s → 1s → 2s）
├── ③ 抖动：随机偏移（防惊群）
└── ④ ⚠️ 重试 + 雪崩：下游已挂 → 重试放大压力（需熔断配合）

生产实践
├── 网络层重试：连接超时重试（安全）
├── 业务层重试：读操作可重试（幂等）；写操作需幂等键
└── 金句：重试必须配合「熔断 + 幂等」——否则是帮凶
```

### 4.2 幂等设计

```java
// 幂等：重复调用结果一致（防重试/重复提交）
// ① 幂等键（推荐）
public void refund(String orderId, String requestId) {
    String dedupKey = "refund:" + orderId + ":" + requestId;
    if (redis.setIfAbsent(dedupKey, "1", Duration.ofMinutes(30))) {
        doRefund(orderId);          // 首次执行
    } else {
        log.info("重复请求已拦截: {}", requestId);
    }
}

// ② 状态机幂等（订单状态流转）
public void cancelOrder(String orderId) {
    // 只有 PAYING 状态能取消——重复调用第二次直接返回
    int updated = orderDao.updateStatus(orderId, "PAYING", "CANCELLED");
    if (updated == 0) return;       // 状态不匹配 = 已处理
    // 取消成功逻辑...
}

// ③ 唯一索引（数据库级幂等）
// 表：refund_log(order_id, request_id, UNIQUE KEY(order_id, request_id))

// ⚠️ 无幂等的重试 = 灾难：
// 扣款接口重试 2 次 → 扣 3 次款！
```

## 5. 降级策略

> 🎯 **降级需按业务场景定制——不能一刀切**（2026 重要认知）：

```text
降级策略分类
├── ① 查询类：返回保守默认值
│   ├── 库存查询失败 → 返回「库存不足」或缓存值
│   └── 数据标「不可靠」标记
├── ② 写操作：不能降级！
│   ├── 扣库存失败 → 降级 = 超卖风险
│   └── 必须抛异常（让调用方处理）
├── ③ 非核心：直接降级
│   ├── 通知/积分失败 → 记录后跳过
│   └── 或进 MQ 异步补偿
└── ④ 金句：读可降级（给默认）、写不降级（保正确）

降级实现（Feign + Sentinel）
@FeignClient(name = "inventory-service", fallback = InventoryFallback.class)
public interface InventoryClient { ... }

@Component
public class InventoryFallback implements InventoryClient {
    @Override
    public StockDTO queryStock(String skuId) {
        return StockDTO.UNKNOWN;   // 查询降级：保守值
    }
}
```

## 6. 异步通信

```java
// ① 消息发送（RocketMQ）
@Autowired
private RocketMQTemplate rocketMQTemplate;

public void createOrder(Order order) {
    // 本地事务 + 消息（事务消息——见 06 篇）
    rocketMQTemplate.sendMessageInTransaction(
        "order-topic", MessageBuilder.withPayload(order).build(), order);
}

// ② 消息消费
@Component
public class OrderListener {
    @RocketMQMessageListener(topic = "order-topic", consumerGroup = "notify-group")
    public class NotifyConsumer implements RocketMQListener<Order> {
        @Override
        public void onMessage(Order order) {
            notifyUser(order);    // 异步通知（非核心）
        }
    }
}

// ③ 削峰场景
// 秒杀下单 → MQ 排队 → 订单服务按量消费
// 效果：流量高峰被消息队列「削平」

// ⚠️ 异步通信的注意
// ① 最终一致性（不是强一致）
// ② 消息可靠性（重试/死信）
// ③ 消费幂等（重复投递）
// ④ 乱序问题（顺序消息）
```

## 7. 通信最佳实践

```text
服务通信最佳实践（2026 清单）
├── ① 超时必设：connect/read 分层设置 + 链路铁律
├── ② 重试有度：1-2 次 + 退避 + 配合熔断
├── ③ 写操作幂等：幂等键/状态机/唯一索引
├── ④ 降级定制：读给默认、写抛异常
├── ⑤ 链路透传：traceId 跨服务传递（见日志系列 MDC）
├── ⑥ 日志完整：调用方/被调方都记（含耗时）
├── ⑦ 接口契约：DTO 独立定义（不共享实体）
├── ⑧ 连接池：Feign 连接池大小合理（防线程耗尽）
└── ⑨ 金句：通信质量 = 超时 + 幂等 + 降级 + 观测四件套
```

---

## 8. 核心要点

> 🎯 **核心要点**：
> 1. 通信方式：同步（Feign——核心链路）+ 异步（MQ——非核心）
> 2. OpenFeign 声明式：接口 + 注解 + LoadBalancer + Sentinel 集成
> 3. **超时链路铁律**：网关 > 下游最大超时；A > B + B→C；每跳留余量
> 4. 重试前提 = 幂等：幂等键/状态机/唯一索引三方案
> 5. 降级定制：读操作给默认值、写操作必须抛异常（不降级）
> 6. 异步通信：解耦/削峰/最终一致——消息可靠性 + 消费幂等
> 7. 通信四件套：超时 + 幂等 + 降级 + 观测
