## 1. Resource 抽象与 ResourceLoader

**Resource**：统一"资源"的抽象——classpath、文件系统、URL 三种来源用同一接口访问：

```java
// 三种资源前缀
Resource r1 = new ClassPathResource("config/app.json");     // classpath:
Resource r2 = new FileSystemResource("/etc/app.json");      // file:
Resource r3 = new UrlResource("https://example.com/x.json"); // url:
```

**ResourceLoader 按前缀自动解析**（@Value 直接注入）：

```java
@Service
public class TemplateService {
    @Value("classpath:templates/welcome.txt")     // 直接声明资源位置
    private Resource welcomeTemplate;

    @Value("file:${app.template.dir}/report.xlsx")
    private Resource reportTemplate;

    public String loadWelcome() throws IOException {
        try (InputStream in = welcomeTemplate.getInputStream()) {
            return new String(in.readAllBytes(), StandardCharsets.UTF_8);
        }
    }
}

// 编程式：注入 ResourceLoader，按前缀动态解析
@Service
public class AssetService {
    private final ResourceLoader loader;
    public AssetService(ResourceLoader loader) { this.loader = loader; }

    public Resource resolve(String location) {
        return loader.getResource(location);      // 支持 classpath:/file:/http: 统一解析
    }
}
```

**ResourcePatternResolver（通配）**：`classpath*:config/*.yml` 匹配所有 classpath 下的文件——Spring Boot 加载多个 `application-*.yml` 就是用它。

> 🎯 **核心要点**：**Resource 让"资源位置"成为配置**（`classpath:` / `file:` 前缀切换），代码不关心资源在哪——读模板、读 SQL 脚本、读证书时都用它。

## 2. MessageSource：国际化

**MessageSource**：消息（文案）的外置管理——多语言、占位符、区域感知：

```properties
# messages.properties（默认）
order.created=订单 {0} 已创建
order.not.found=订单不存在

# messages_zh_CN.properties / messages_en.properties ...（按 Locale 后缀）
```

```java
@Configuration
public class I18nConfig {
    @Bean
    public MessageSource messageSource() {
        ResourceBundleMessageSource source = new ResourceBundleMessageSource();
        source.setBasename("messages");              // messages*.properties
        source.setDefaultEncoding("UTF-8");
        return source;
    }
}

@Service
public class OrderService {
    private final MessageSource messages;

    public String buildMessage(String orderId, Locale locale) {
        return messages.getMessage(
                "order.created",                     // key
                new Object[]{orderId},               // 占位符 {0}
                locale);                             // 区域（从请求头/用户偏好取）
    }
}
```

**Spring Boot 简化**：默认扫描 `messages.properties`（`spring.messages.basename` 可改）；Web 场景通过 `Accept-Language` 请求头自动决定 Locale。

> 💡 工程要点：**业务提示语全部走 MessageSource**（key 而不是中文硬编码）——前端按 key 做多语言、后端统一文案维护，还能避免"文案散布在代码里"。

## 3. TestContext：容器测试框架

**TestContext 框架**：让测试可以**启动 Spring 容器**并自动注入 Bean——`@SpringBootTest` 是 Boot 的入口注解：

```java
@SpringBootTest                       // 启动完整应用上下文（自动配置生效）
class OrderServiceTest {

    @Autowired
    private OrderService orderService;            // 注入真实 Bean（含代理/事务）

    @Test
    void createOrder_shouldSave() {
        Order order = orderService.create(...);
        assertThat(order.getId()).isNotNull();
    }
}
```

**TestContext 的核心机制**：

| 机制 | 说明 |
|------|------|
| 缓存上下文 | 相同配置的测试**共享容器**（不重复启动）——同名配置切 Profile 会重建 |
| 事务回滚 | `@Transactional` 测试方法结束后**自动回滚**（不污染数据库） |
| 环境覆盖 | `@ActiveProfiles("test")` 切换测试配置 |
| 只测一层 | `@WebMvcTest`（只加载 Web 层）/ `@DataJpaTest`（只加载 JPA）——切片测试 |

```java
// 切片测试：只加载 MVC 层（不启动整个容器）——快
@WebMvcTest(OrderController.class)
class OrderControllerTest {
    @Autowired MockMvc mockMvc;
    @MockBean OrderService orderService;          // Web 层以外的依赖用 Mock

    @Test
    void getOrder_returnsOk() throws Exception {
        mockMvc.perform(get("/api/orders/1"))
                .andExpect(status().isOk());
    }
}
```

> 🎯 **核心要点**：测试分层——**单元测试（快、无容器）→ 切片测试（局部容器）→ 集成测试（全容器）**。`@SpringBootTest` 是集成测试，不该成为每个测试的默认选择。

## 4. 单元测试实践：分层策略与 Mock

**分层测试策略**（测试金字塔）：

| 层 | 测试类型 | 是否启动容器 | 工具 | 目标 |
|----|---------|:-----------:|------|------|
| Service/工具类 | 纯单元测试 | ❌ | JUnit + Mockito | 业务逻辑全覆盖，毫秒级 |
| Controller | 切片测试 | 局部 | @WebMvcTest + MockMvc | 参数/响应/异常映射 |
| DAO | 数据层测试 | 局部 | @DataJpaTest（H2/Testcontainers） | SQL/映射正确 |
| 端到端 | 集成测试 | ✅ | @SpringBootTest + Testcontainers | 关键链路 |

**Service 层单元测试**（构造器注入的收益体现）：

```java
class OrderServiceTest {
    private OrderDao dao;
    private OrderService service;

    @BeforeEach
    void setUp() {
        dao = mock(OrderDao.class);                       // Mockito mock
        service = new OrderService(dao);                  // ✅ 构造器注入让纯 Java 可测
    }

    @Test
    void getOrder_whenNotFound_shouldThrow() {
        when(dao.findById("1")).thenReturn(Optional.empty());
        assertThrows(OrderNotFoundException.class,
                () -> service.getOrder("1"));
    }

    @Test
    void getOrder_shouldReturnOrder() {
        Order o = new Order("1");
        when(dao.findById("1")).thenReturn(Optional.of(o));
        assertEquals("1", service.getOrder("1").getId());
        verify(dao).findById("1");                        // 验证交互
    }
}
```

> 🎯 **核心要点**：**构造器注入 + 接口依赖 = 可单元测试**——这是 03 模块"构造器注入首选"在测试层的直接回报。测试跑得快（无容器）、断言准（无 Spring 干扰）。

## 5. 测试隔离与启动加速

**测试隔离三原则**：

| 原则 | 做法 |
|------|------|
| 数据隔离 | 测试数据库（Testcontainers/H2）独立于开发库；测试方法事务回滚 |
| 配置隔离 | `@ActiveProfiles("test")` + `application-test.yml`（禁 MQ/外部调用） |
| 环境隔离 | 外部依赖 Mock（@MockBean / WireMock）——测试不依赖真实网络 |

**Testcontainers（现代标准）**：真实数据库容器，避免 H2 与 MySQL 行为差异：

```java
@Testcontainers
@DataJpaTest
class OrderRepositoryTest {
    @Container
    static MySQLContainer<?> mysql = new MySQLContainer<>("mysql:8.4")
            .withDatabaseName("test_db");

    @DynamicPropertySource
    static void props(DynamicPropertyRegistry registry) {
        registry.add("spring.datasource.url", mysql::getJdbcUrl);    // 动态注入
    }
}
```

**启动加速**：

| 手段 | 收益 |
|------|------|
| 切片测试优先 | 启动秒级 vs 全容器秒级+ |
| 上下文缓存 | 相同配置复用容器 |
| `@SpringBootTest(webEnvironment = NONE)` | 不启动 Web 服务器 |
| 懒加载 Bean（`spring.main.lazy-initialization=true`，测试 Profile 用） | 减少无用 Bean 初始化 |
| Spring 7.0 AOT 测试支持 | 原生/预编译加速 |

> 🎯 **核心要点**：测试质量的度量 = **速度（毫秒级单元测试为主）+ 隔离（数据/配置/网络全隔离）+ 覆盖（正常/边界/异常三路径）**——容器测试是保障，单元测试是主力。
