## 1. 必背考点：十二问

### 1.1 MP 和 MyBatis 的关系？

**答题链**：MP = MyBatis 的增强工具（"只做增强，不做改变"）→ 底层仍是 MyBatis（SqlSessionFactory/MappedStatement）→ 通用方法靠 SQL 注入器启动期生成 → 插件靠 MyBatis 拦截器改写 SQL → 单表 MP、复杂 SQL 原生（80/20）。

### 1.2 版本选型要点？

**答题链**（时效性）：最新 **3.5.17（2026-07）** → Boot 版本定 starter（2.x/3.x/4.x 三坐标，**Boot 4 用 `mybatis-plus-spring-boot4-starter`（3.5.13+）**）→ **3.5.9+ 分页需 `mybatis-plus-jsqlparser`**（JDK8 用 -4.9）→ 不引 mybatis/mybatis-spring。

### 1.3 主键策略？雪花 ID 的坑？

**答题链**：IdType 四策略（ASSIGN_ID 默认雪花/AUTO 自增/INPUT 业务/UUID）→ 雪花 = 时间戳+机器+序列（全局唯一/趋势递增）→ **19 位 Long 前端精度丢失 → String 序列化**。

### 1.4 逻辑删除原理与边界？

**答题链**：@TableLogic → DELETE 改写为 UPDATE（`SET deleted=1 WHERE id=? AND deleted=0`）→ 查询自动拼 `deleted=0` → 三条边界：**手写 SQL 不生效、唯一索引槽位不释放、与 Wrapper 条件 AND 连接**。

### 1.5 乐观锁的机制与坑？

**答题链**：@Version + OptimisticLockerInnerInterceptor → UPDATE 自动拼 `WHERE version=旧值` 并 `version=version+1` → **冲突不抛异常，返回 0 行——必须检查返回值**（与 JPA 抛异常不同）→ 重试需重新读取。

### 1.6 Wrapper 的 eq null 陷阱？

**答题链**：`.eq(col, null)` 拼 `WHERE col = null`（三值逻辑查不到）→ 条件重载 `.eq(cond, col, val)` false 时整段跳过 → **动态条件统一条件重载**（like/in 同理）。

### 1.7 updateById 与 UpdateWrapper 的区别？

**答题链**：updateById = 按主键更新 + **null 字段跳过**（NOT_NULL 策略）→ 置 null 用 `UpdateWrapper.set(col, null)` → 字段级 `updateStrategy=IGNORED` → 无 WHERE 更新 = 全表（防全表插件）。

### 1.8 分页插件配置？常见坑？

**答题链**：依赖（3.5.9+ jsqlparser）→ 注册（PaginationInnerInterceptor + **DbType 显式** + setMaxLimit）→ 页码从 1 起（0 查不到）→ 大表 COUNT 慢/深分页 OFFSET → Keyset/游标。

### 1.9 防全表更新插件？

**答题链**：BlockAttackInnerInterceptor 拦截无 WHERE 的 UPDATE/DELETE → 生产必装 → 边界：`WHERE 1=1` 拦不住（配合代码规范）→ 注册一行收益数据安全。

### 1.10 多租户插件？

**答题链**：TenantLineInnerInterceptor + TenantLineHandler（getTenantId/getTenantIdColumn/ignoreTable）→ 所有 SQL 自动拼 `tenant_id` → 业务零感知 → **手写 SQL 需手动补租户条件**（最高危边界）。

### 1.11 saveBatch 为什么快？

**答题链**：循环单条 = N 次 SQL + N 次提交；saveBatch = SqlSession 批量模式（ExecutorType.BATCH）复用 → 实测 ~5 倍提升 → 批次大小（默认 1000，考虑 max_allowed_packet）→ 无主键回填 → 百万级用 JDBC 批处理。

### 1.12 逻辑删除 × 唯一索引冲突？

**答题链**：逻辑删除不释放唯一索引槽位 → 新注册冲突 → 三解法：**释放唯一字段（推荐）**/应用层校验/条件唯一索引（MySQL 不支持）→ **复合索引 (phone, deleted) 不可行**（推迟冲突到注销时）。

## 2. 高频陷阱题 12 连问

1. **对错**：MP 需要单独引入 mybatis-spring-boot-starter。（❌ 冲突！MP starter 自带）
2. **结果**：3.5.9+ 不引 jsqlparser，分页会怎样？（静默失效——不报错但没有 LIMIT）
3. **对错**：逻辑删除后 `selectById` 还能查到已删数据。（❌ 自动过滤 deleted=0）
4. **结果**：`.eq(User::getStatus, null)` 生成的 SQL？（`WHERE status = null`——查不到任何数据）
5. **对错**：`updateById` 会把 null 字段更新为 null。（❌ 静默跳过——需 UpdateWrapper.set）
6. **结果**：分页页码传 0？（查不到数据——页码从 1 开始）
7. **对错**：MP 乐观锁冲突抛异常。（❌ 返回 0 行——必须检查返回值）
8. **结果**：逻辑删除记录还占唯一索引吗？（占——注册冲突是头号坑）
9. **对错**：手写 XML 的 SQL 会自动加逻辑删除条件。（❌ 需手动 `AND deleted=0`）
10. **结果**：`saveBatch` 会回填主键吗？（不回填——需要 id 的业务逐条 save）
11. **对错**：Boot 4 项目用 `mybatis-plus-spring-boot3-starter` 可以。（❌ 用 `-boot4-starter`（3.5.13+））
12. **结果**：实体字段不是表字段，不处理会怎样？（MP 生成 SQL 报"列不存在"——`@TableField(exist=false)`）

## 3. 高频追问速答

| 追问 | 速答 |
|------|------|
| MP 的通用 SQL 哪来的？ | SQL 注入器（AbstractSqlInjector）启动期为 BaseMapper 方法生成并注册 MappedStatement |
| 逻辑删除怎么恢复数据？ | 手动 UPDATE `deleted=0`（SQL 层操作）——MP 不提供 API（有意的：防误操作） |
| selectOne 查多条会怎样？ | 抛 TooManyResultsException——条件必须唯一 |
| 枚举字段怎么存数据库？ | 实现 IEnum/@EnumValue，MP 自动转数值；JSON 字段用 JacksonTypeHandler |
| 多数据源分页失效怎么办？ | 每个数据源注册独立 MybatisPlusInterceptor（@DS + @Bean） |
| 自定义 SQL 想复用 Wrapper 条件？ | `${ew.customSqlSegment}`（必须 `${}`，参数名 ew） |
| 更新接口一般怎么写？ | updateById（表单部分更新）+ UpdateWrapper（条件/置 null）+ 乐观锁检查返回值 |
| 大表查询优化？ | 索引匹配、只查必要列（select 方法）、Keyset/游标分页、归档分区 |
| MP 支持 Lambda 的条件是什么？ | 实体有 getter（Lombok @Data）——否则方法引用拿不到字段 |
| 生成器生成的代码能用吗？ | 起点而非终点——实体/Mapper 可留，Controller 常按业务裁剪 |
| MP 和 JPA 怎么选？ | 国内 Spring 生态标配 MP（单表增强 + 原生 SQL 兜底）；JPA 适合强领域建模——团队熟悉度与场景决定 |
| 逻辑删除恢复数据怎么做？ | 手动 SQL `UPDATE ... SET deleted=0`（无 API 是有意设计，防误操作） |
| selectPage 会执行几条 SQL？ | 两条：COUNT(*) + 主查询（LIMIT）——大表 COUNT 慢是分页性能点 |
| 自定义方法（XML）里能用 Wrapper 吗？ | 能——`${ew.customSqlSegment}` 拼接条件片段（必须 `${}`） |
| 为什么 MP 方法返回 int？ | 影响行数——乐观锁冲突/更新失败全靠它判断（必须检查） |
| 多租户怎么实现数据权限？ | TenantLineInnerInterceptor 自动拼租户条件 + 手写 SQL 手动补 |
| 更新接口幂等怎么做？ | 乐观锁（@Version + 检查返回值）或唯一业务键（幂等表） |

## 4. 场景题：企业级 CRUD 架构设计

**题目**：设计一个订单模块的持久层架构（MyBatis-Plus），要求规范统一、可扩展、防事故。

**答题框架**（按评分点展开）：

```text
① 依赖与版本（时效性）：
   - Spring Boot 3.x → mybatis-plus-spring-boot3-starter 3.5.17
   - 引入 mybatis-plus-jsqlparser（分页必需）
   - 不引 mybatis/mybatis-spring（防冲突）

② 实体规范：
   - BaseEntity 公共字段（id 雪花/创建更新时间/逻辑删除/乐观锁）
   - MetaObjectHandler 自动填充（时间 + 操作人）
   - 枚举处理（状态字段 IEnum）

③ 分层：
   - Controller → IService（继承）→ BaseMapper（继承）
   - 复杂查询 → Mapper 自定义 XML（80/20 原则）
   - 业务方法 → ServiceImpl 自定义（@Transactional）

④ 插件（防事故三件套）：
   - PaginationInnerInterceptor（DbType.MYSQL + maxLimit）
   - OptimisticLockerInnerInterceptor（并发安全）
   - BlockAttackInnerInterceptor（防全表更新）
   - （多租户场景）TenantLineInnerInterceptor

⑤ 关键决策：
   - 逻辑删除 + 唯一索引：释放唯一字段方案
   - 批量导入：saveBatch(500) 分批 + 事务
   - 大表：索引 + Keyset 分页

⑥ 加分点：
   - 谈"三个静默"（依赖/插件/手写 SQL 边界）
   - 谈 SQL 日志与 EXPLAIN 排查
   - 谈多数据源分页失效坑
```

## 5. 记忆口诀

```text
MP 是增强非替代，底层还是 MyBatis 家。
版本三选：Boot 定 starter、3.5.9 后引 jsqlparser、Latest 追 3.5.17。
实体三注解：TableName、TableId（雪花）、TableField（exist/fill）。
规范三件套：逻辑删除（DELETE 变 UPDATE）、乐观锁（version 校验）、自动填充（MetaObjectHandler）。
Wrapper 三戒：eq null 用条件重载、or 必须进括号、apply/last 只白名单。
插件三件套：分页（LIMIT）、乐观锁（version）、防全表（BlockAttack）。
三个静默坑：依赖缺失、插件未注册、手写 SQL 不覆盖。
边界两原则：单表 MP、复杂原生 SQL；80/20 恒记心。
批量一条龙：saveBatch 五倍速、循环调方法是大忌。
```

> 💡 背诵建议：口诀 9 句对应本体系 9 个模块——按"定位 → 映射 → CRUD → Wrapper → Service → 插件 → 扩展 → 生产 → 面试"顺序过一遍，体系自动浮现（结合总览的导图对照记忆效果更佳）。
