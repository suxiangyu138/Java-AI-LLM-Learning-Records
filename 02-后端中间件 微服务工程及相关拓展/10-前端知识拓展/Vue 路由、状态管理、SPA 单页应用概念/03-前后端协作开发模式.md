## 1. 协作流程

```text
标准前后端分离开发流程：

  [产品需求评审]
        │
  ┌─────┴─────┐
  │  接口设计   │  ← 前后端一起定义 API 契约（输入/输出/状态码）
  └─────┬─────┘
        │
  ┌─────┴─────┐
  │ 并行开发    │
  ├───────────┤
  │ 前端 Mock  │  后端实现 API
  │ 写页面 UI  │  写单元测试
  └─────┬─────┘
        │
  [联调对接]   ← 前后端连调，发现问题修复
        │
  [提测上线]
```

## 2. 接口文档先行

### OpenAPI 3.0（Swagger / Knife4j）

```yaml
# API 契约 — 前后端共同确认
openapi: 3.0.0
info:
  title: 用户服务 API
  version: 1.0.0
paths:
  /users/{id}:
    get:
      summary: 获取用户详情
      parameters:
        - name: id
          in: path
          required: true
          schema: { type: integer }
      responses:
        200:
          description: 成功
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/ResultUser'
components:
  schemas:
    ResultUser:
      type: object
      properties:
        code: { type: integer, example: 200 }
        data:
          type: object
          properties:
            id: { type: integer }
            name: { type: string }
            email: { type: string }
```

```java
// Spring Boot 自动生成 Swagger 文档
@Operation(summary = "获取用户详情")
@GetMapping("/users/{id}")
public Result<User> getUser(@PathVariable Long id) { ... }
```

### 前端根据 Swagger 生成 API 代码

```bash
# OpenAPI Generator — 自动生成前端 TypeScript 类型 + API 调用
npx openapi-generator-cli generate \
  -i http://localhost:8080/v3/api-docs \
  -g typescript-axios \
  -o ./src/api/generated
```

```text
生成的代码示例：
  src/api/generated/
  ├── api/user-api.ts      ← TypeScript API 方法（自动生成！）
  └── model/user.ts        ← TypeScript 类型定义（自动生成！）

好处：
  → 前后端接口定义严格一致
  → 后端改了接口 → 前端重新生成 → 编译报错（而非运行时发现）
```

## 3. Mock 数据方案

### 方案1：后端提前提供 Swagger → 前端 Mock Server

```bash
# 基于 Swagger/OpenAPI 生成 Mock Server
npx open-api-mocker -s http://localhost:8080/v3/api-docs -p 4010
# → 前端用 http://localhost:4010 开发，返回符合 Swagger 定义的 Mock 数据
```

### 方案2：前端独立 Mock

```javascript
// vite.config.ts — Vite 内置 Mock
export default defineConfig({
  server: {
    proxy: {
      '/api': {
        target: 'http://localhost:4010',   // Mock Server
        // target: 'http://localhost:8080',  // 联调时切到真实后端
        changeOrigin: true
      }
    }
  }
});
```

## 4. 部署与调试

### 开发环境

```text
Vite Proxy 方案（零跨域）：
  前端 localhost:3000
    ├── /api/** → Proxy → localhost:8080（Java 后端）
    └── 其他 → Vite Dev Server

不需要 Nginx，不需要 CORS 配置！
```

### 生产部署

```text
方式1：Nginx 分离部署（⭐ 推荐）
  前端 dist/ → Nginx 静态目录（/）
  后端 API → Nginx proxy_pass（/api → localhost:8080）

方式2：Docker Compose
  frontend: nginx + dist/
  backend:  java -jar app.jar
  nginx 统一路由
```

### 联调调试技巧

| 场景 | 后端操作 |
|------|----------|
| 前端说"接口不通" | 先用 curl 验证 → 排除前端问题 |
| 前端报"跨域错误" | 检查 CORS 配置 → 或直接用 Proxy 方式 |
| 前端"数据不对" | 后端 Postman/curl 返回什么？对比前端实际收到的 |
| 前端"需要加字段" | 接口文档先行修改 → 后端加 → 前端更新 |

```bash
# 后端自查 — curl 验证接口
curl -v http://localhost:8080/api/users/1
# 看响应 → 看 Header → 看 CORS 头 → 定位问题在上游还是下游

# 前端查 — Chrome DevTools Network 面板
# 看 Request Headers → 看 Response → 看状态码 → 看 Timing
```

> 🎯 **协作铁律**：接口文档（Swagger）先行开发、Vite Proxy 零跨域开发、OpenAPI Generator 自动生成类型前端代码。后端确保 curl 调得通，再找前端联调。
