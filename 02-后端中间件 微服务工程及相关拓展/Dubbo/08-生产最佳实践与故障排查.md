## 1. 线程模型调优

### 1.1 Dubbo 线程模型

```
Netty IO 线程池（默认 CPU 核数+1）
    ↓ 收到请求 → 派发
Dubbo 业务线程池（默认 200 固定线程）
    ↓
Provider 实现

⚠️ 关键：IO 线程不能阻塞，所有业务逻辑在业务线程池执行
```

### 1.2 线程池配置

```yaml
dubbo:
  protocol:
    threads: 200                  # 业务线程数
    threadpool: fixed             # fixed / cached / limited / eager
    iothreads: 4                  # IO 线程数
    queues: 0                     # 等待队列（0=同步队列，满即限流）
```

| 线程池类型 | 特点 | 适用 |
|-----------|------|------|
| **fixed** | 固定大小 + 队列 | ⭐ 默认，稳定流量 |
| **cached** | 动态伸缩 | 流量波动大 |
| **limited** | 固定大小 + 有界队列 | 防止 OOM |
| **eager** | 优先创建线程而非排队 | 低延迟场景 |

### 1.3 线程打满排查

```bash
# 现象：消费者超时、Provider CPU 正常但 RT 高
# 原因：业务线程池满了，请求在排队

# 解决：
# 1. 增大线程数（默认为 200）
dubbo.protocol.threads=500

# 2. 优化业务逻辑（减少耗时操作）

# 3. 异步化 （返回 CompletableFuture）
@DubboService
public class UserServiceImpl implements UserService {
    @Override
    public CompletableFuture<User> getUser(Long id) {
        return CompletableFuture.supplyAsync(() -> {
            // 业务逻辑
        }, asyncExecutor);
    }
}
```

## 2. 超时与重试策略

### 2.1 超时配置优先级

```text
方法级 > 接口级 > 全局 Consumer > 全局 Provider

方法级（最高优先级）
@DubboReference(timeout = 5000)

Provider 全局（默认）
dubbo.provider.timeout=3000
```

### 2.2 超时设置原则

```text
超时时间 > 业务 P99 延迟

示例：
  业务 P99 = 800ms → timeout = 2000ms (留 1-2 倍余量)

consumer 超时 < provider 超时
  消费者 1000ms 超时 < 提供者 3000ms 超时
  → 避免消费者已超时放弃，提供者还在处理（浪费资源）
```

### 2.3 重试策略

```yaml
dubbo:
  consumer:
    retries: 0    # ⚠️ 非幂等接口务必设为 0

# 幂等接口
@DubboReference(timeout = 2000, retries = 2, cluster = "failover")
private UserService userService;   # 查询类，幂等

# 非幂等接口
@DubboReference(timeout = 5000, retries = 0, cluster = "failfast")
private OrderService orderService;  # 创建订单，非幂等
```

## 3. 优雅上下线

```yaml
dubbo:
  provider:
    graceful-shutdown-timeout: 10000    # 优雅停机等待 10s
    warmup: 120000                       # 预热 2 分钟
    weight: 100                          # 初始权重
```

```text
优雅下线流程：
  1. 收到 kill 信号
  2. 从注册中心注销（不再接收新请求）
  3. 等待 graceful-shutdown-timeout 让正在处理的请求完成
  4. 关闭 Dubbo 连接
  5. 关闭 Spring 容器

K8s 建议：
  preStop hook 提前注销 → sleep 15s → 等待流量排干
```

## 4. 直连调试与本地开发

### 4.1 直连 Provider（跳过注册中心）

```java
// 方式1：注解指定 URL
@DubboReference(url = "dubbo://10.0.1.10:20880")
private UserService userService;
```

```yaml
# 方式2：关闭注册中心
dubbo:
  registry:
    address: N/A                    # 跳过注册中心
  consumer:
    check: false                    # 不检查 Provider 可用
```

```bash
# 方式3：telnet 直连调试
telnet localhost 20880
dubbo> invoke com.example.UserService.getUser(1L)
dubbo> ls                           # 列出所有服务
dubbo> ps 20880                     # 查看端口状态
```

### 4.2 本地开发 — 点对点直连

```java
// 本地 Consumer → 远程 Provider（不走注册中心）
@DubboReference(url = "dubbo://dev-server:20880")
private UserService userService;
```

## 5. 常见故障排查

### 5.1 故障速查表

| 现象 | 原因 | 排查 |
|------|------|------|
| `No provider available` | Provider 未注册/已下线 | Dubbo Admin 查看注册列表、`telnet` 检查端口 |
| `TimeoutException` | Provider 处理慢或线程打满 | 增大 timeout、检查业务线程池 |
| `Connection refused` | Provider 端口不可达 | `ss -tlnp \| grep 20880`、防火墙 |
| `Not found exported service` | 接口名不匹配/版本不对 | 检查 interface 全限定名和 version |
| 频繁重连 | 网络不稳定/心跳超时 | 检查网络延迟、心跳间隔 |
| 注册不上去 | ZK/Nacos 连不上 | `zkCli.sh ls /dubbo`、Dubbo Admin |

### 5.2 排查命令

```bash
# 1. 检查 Provider 端口监听
ss -tlnp | grep 20880

# 2. 检查注册中心是否注册成功（ZK）
./zkCli.sh ls /dubbo/com.example.UserService/providers

# 3. telnet 直接调用验证 Provider 可用
telnet 127.0.0.1 20880
dubbo> invoke com.example.UserService.getUser(1L)

# 4. 查看 Dubbo Admin 控制台
# http://localhost:8080 → 服务查询 → 查看 Provider/Consumer 状态
```

### 5.3 常见配置踩坑

| 问题 | 原因 | 修复 |
|------|------|------|
| Provider 不注册 | `@DubboService` 所在类没被 Spring 管理 | 加 `@Service` / `@Component` |
| Consumer 注入 null | `@DubboReference` 用在非 Spring Bean | 确保在 Spring 管理的类中 |
| 序列化失败 | POJO 没实现 `Serializable` | `implements Serializable` |
| Nacos 注册失败 | `namespace` 拼写错误 | 检查 namespace: prod（不是 ID） |
| Triple 调不通 | 端口冲突（50051） | 检查是否有 gRPC 服务占用 |

## 6. 生产 Checklist

| 分类 | 检查项 | 推荐配置 |
|------|--------|----------|
| **超时** | Consumer 超时 < Provider 超时 | C:2000ms / P:3000ms |
| **重试** | 非幂等接口 retries=0 | `retries=0, cluster=failfast` |
| **线程** | 业务线程池 ≤ 500 | `threads=200-500` |
| **连接** | 长连接，单 Consumer 单 Provider 1 连接 | 默认即可 |
| **序列化** | 不使用 Java Serializable | Hessian2 / Protobuf |
| **注册** | 应用级发现（3.x） | `register-mode=instance` |
| **优雅下线** | 等待 10s 排干流量 | `graceful-shutdown-timeout=10000` |
| **监控** | Dubbo Admin + Prometheus | metrics 暴露 |
| **日志** | accesslog 开启 | `dubbo.provider.accesslog=true` |

> 🎯 **生产铁律**：超时必设、非幂等不重试、优雅上下线必配、Java Serializable 禁用。
