## 1. 消息队列的演进

```text
阶段一：解耦（2000s）
  单体应用 → 异步解耦 → ActiveMQ / RabbitMQ
  关键词：JMS、AMQP、队列、主题

阶段二：削峰（2010s）
  海量请求 → 流量削峰 → Kafka / RocketMQ
  关键词：高吞吐、持久化、顺序消费

阶段三：流处理（2020s）
  实时数据 → 流式计算 → Kafka Streams / Flink
  关键词：流批一体、Exactly-Once、事件溯源
```

| 代际 | 代表产品 | 核心目标 | 典型吞吐 |
|------|----------|----------|----------|
| **传统 MQ** | RabbitMQ、ActiveMQ | 解耦 + 削峰 | 万级 TPS |
| **大数据 MQ** | Kafka | 高吞吐 + 持久化 | 百万级 TPS |
| **金融级 MQ** | RocketMQ | 事务消息 + 延迟 | 十万级 TPS |
| **云原生 MQ** | Pulsar | 存算分离 + 多租户 | 百万级 TPS |

## 2. Kafka 是什么

> Kafka 是一个**分布式的、基于发布/订阅模式的消息引擎系统**，同时也是一个**分布式流处理平台**。

**三个核心定位：**

```text
┌─────────────────────────────────────────────────────┐
│                    Apache Kafka                      │
├─────────────────┬─────────────────┬─────────────────┤
│   消息引擎系统    │   流处理平台     │   存储系统       │
│  (Pub/Sub)      │  (Streaming)    │  (Storage)      │
├─────────────────┼─────────────────┼─────────────────┤
│ • 发布/订阅      │ • Kafka Streams │ • 持久化到磁盘   │
│ • 消息队列       │ • KSQL / ksqlDB │ • 可回溯消费     │
│ • 连接器框架     │ • 窗口/聚合     │ • 日志压缩       │
│                 │ • 流表关联      │ • 分层存储       │
└─────────────────┴─────────────────┴─────────────────┘
```

**关键设计理念：**
- 一切皆日志（Log） — 不可变、有序、持久化的消息序列
- 磁盘不是瓶颈 — 顺序读写 + 零拷贝，磁盘顺序写速度快于随机内存
- 消费者拉动（Pull） — 消费者按自身速率拉取，避免推送过载

## 3. Kafka 核心特性

| 特性 | 说明 |
|------|------|
| **高吞吐** | 顺序写盘 + 零拷贝 + 批量处理 → 单机百万 TPS |
| **持久化** | 消息写入磁盘持久化，支持回溯消费（默认保留 7 天） |
| **水平扩展** | Partition 机制 → 增加 Broker 即可线性扩展 |
| **容错性** | 多副本机制（Replication） → 单 Broker 宕机不丢数据 |
| **顺序性** | 单 Partition 内严格有序，多 Partition 需 Key 保证 |
| **多订阅者** | 消费组支持多个独立消费者 → 发布/订阅模式 |
| **实时性** | 端到端延迟可低至 ms 级（配置得当） |
| **压缩** | 支持 Gzip/Snappy/LZ4/ZSTD 消息压缩 |

## 4. Kafka vs 传统 MQ

| 维度 | Kafka | RabbitMQ | ActiveMQ |
|------|-------|----------|----------|
| **架构定位** | 分布式日志 | AMQP 代理 | JMS 代理 |
| **吞吐量** | 百万 TPS | 万级 TPS | 万级 TPS |
| **消息持久化** | 全量持久化磁盘 | 可选持久化（内存为主） | 可选持久化 |
| **消息回溯** | ✅ 按 Offset 回放 | ❌ 消费即删除 | ❌ 消费即删除 |
| **消息优先级** | ❌ 不支持 | ✅ 支持 | ✅ 支持 |
| **延迟消息** | ❌ 需自行实现 | ✅ TTL + DLX | ✅ 支持 |
| **路由复杂度** | 简单（Topic→Partition） | 灵活（Exchange+Binding） | 中等 |
| **协议** | 自定义二进制协议 | AMQP 0-9-1 | OpenWire / AMQP |
| **事务消息** | ✅ 事务 / 幂等 | ❌ 发布确认 | ✅ XA |
| **运维复杂度** | 中等 | 低 | 低 |

> 💡 RabbitMQ 适合业务解耦（路由灵活、低延迟），Kafka 适合数据管道（高吞吐、可回溯）。

## 5. Kafka vs RocketMQ vs Pulsar

| 维度 | Kafka | RocketMQ | Pulsar |
|------|-------|----------|--------|
| **开发语言** | Java/Scala | Java | Java |
| **存储架构** | 存算一体（本地盘） | 存算一体（CommitLog） | 存算分离（BookKeeper） |
| **注册中心** | ZK / KRaft | NameServer | ZooKeeper |
| **事务消息** | ✅（幂等+事务） | ✅（半消息） | ❌ |
| **延迟消息** | ❌ 需自行实现 | ✅ 18 个级别 | ✅ 任意延迟 |
| **消息过滤** | ❌ 客户端过滤 | ✅ Tag/SQL92 | ❌ 客户端过滤 |
| **多租户** | ❌ 弱 | ❌ 弱 | ✅ 原生多租户 |
| **分层存储** | 3.6+ Tiered Storage | ❌ | ✅ 原生支持 |
| **国内生态** | 一般 | 阿里背书（金融级） | 一般 |
| **社区活跃度** | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐ |
| **适用场景** | 数据管道/流计算 | 业务解耦/交易 | 云原生/多租户 |

## 6. 典型应用场景

### 6.1 日志收集

```text
App Server 1 ──┐
App Server 2 ──┼──→ Kafka ──→ Logstash ──→ ES ──→ Kibana
App Server 3 ──┘
```

### 6.2 消息系统（削峰填谷）

```text
                    ┌── Consumer 1
Producer ──→ Kafka ─┼── Consumer 2
                    └── Consumer 3
```

### 6.3 流处理

```text
用户行为 ──→ Kafka ──→ Flink/Kafka Streams ──→ 实时推荐
```

### 6.4 CDC（数据变更捕获）

```text
MySQL binlog ──→ Debezium ──→ Kafka ──→ Hudi/Iceberg ──→ 数据湖
```

### 6.5 事件溯源（Event Sourcing）

```text
UserAction ──→ Kafka（不可变事件流）──→ 多消费组重放
```

## 7. 核心术语速查

| 术语 | 说明 | 类比 |
|------|------|------|
| **Broker** | Kafka 服务节点/进程 | 邮局 |
| **Topic** | 消息的逻辑分类/主题 | 收件人地址 |
| **Partition** | Topic 的物理分片，有序队列 | 地址下的多个信箱 |
| **Producer** | 消息生产者 | 寄信人 |
| **Consumer** | 消息消费者 | 收信人 |
| **Consumer Group** | 消费者组，组内分摊消费 | 多人轮值查信箱 |
| **Replica** | Partition 的副本 | 信件备份 |
| **Leader** | 每个 Partition 的主副本 | 主信箱 |
| **Follower** | 主副本的从副本 | 备用信箱 |
| **Offset** | 消息在 Partition 中的位置 | 信件编号 |
| **ISR** | In-Sync Replicas，与 Leader 同步的副本集合 | 同步过的备份 |
| **Controller** | 集群控制器，管理 Broker/Partition 分配 | 邮局管理员 |
