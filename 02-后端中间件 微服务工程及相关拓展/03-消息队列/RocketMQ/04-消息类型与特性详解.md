## 2. 普通消息

### 2.1 三种发送方式

```java
// 1. 同步发送 — 等待结果（可靠，吞吐低）
SendResult result = producer.send(msg);
System.out.println(result.getSendStatus());

// 2. 异步发送 — 回调通知（高吞吐，不阻塞）
producer.send(msg, new SendCallback() {
    @Override
    public void onSuccess(SendResult result) {
        System.out.println("成功: " + result.getMsgId());
    }
    @Override
    public void onException(Throwable e) {
        System.err.println("失败: " + e.getMessage());
    }
});

// 3. 单向发送 — 不关心结果（最高吞吐，不可靠）
producer.sendOneway(msg);  // 日志采集等场景
```

### 2.2 发送方式对比

| 方式 | 吞吐 | 可靠性 | 使用场景 |
|------|:---:|:---:|------|
| **同步** | 低 | 高 | 重要业务通知 |
| **异步** | 高 | 中 | 通用业务 |
| **单向** | 最高 | ✗ | 日志、指标采集 |

## 3. 顺序消息

### 3.1 两种顺序模式

```text
全局顺序（Global Order）：
  → Topic 只有一个 MessageQueue
  → 所有消息严格按发送顺序消费
  → 代价：吞吐量最低，无并发

分区顺序（Partition Order）：
  → 相同业务标识的消息发到同一个 MessageQueue
  → 同一个 Queue 内有序
  → 多个 Queue 之间并行 → 高吞吐
  → ⭐ 推荐，生产常用
```

### 3.2 分区顺序实现

```java
// 生产者 — 通过消息选择器保证同一订单的消息到同一 Queue
SendResult result = producer.send(msg, new MessageQueueSelector() {
    @Override
    public MessageQueue select(List<MessageQueue> mqs, Message msg, Object arg) {
        Long orderId = (Long) arg;                  // 订单 ID
        int index = (int) (orderId % mqs.size());   // Hash 到固定 Queue
        return mqs.get(index);
    }
}, orderId);

// 消费者 — 使用 MessageListenerOrderly 保证顺序消费
consumer.registerMessageListener(new MessageListenerOrderly() {
    @Override
    public ConsumeOrderlyStatus consumeMessage(List<MessageExt> msgs,
                                                ConsumeOrderlyContext context) {
        for (MessageExt msg : msgs) {
            processOrderMessage(msg);
        }
        return ConsumeOrderlyStatus.SUCCESS;
    }
});
```

### 3.3 顺序消息的代价

| 代价 | 说明 |
|------|------|
| **写** | 消息选择器 → 可能需要额外路由逻辑 |
| **读** | MessageListenerOrderly → 单线程消费一个 Queue |
| **FAIL** | 一条失败 → 后续消息全部阻塞（直到重试成功） |
| **HA** | 主从切换 → 可能短暂乱序 |

> ⚠️ 能用分区顺序就别用全局顺序，能用普通消息就别用顺序消息 — 顺序是有代价的。

## 4. 事务消息

### 4.1 分布式事务问题

```text
场景：下单 + 扣库存 — 两个操作需要原子性

传统方案：
  ① 写本地事务 → ② 发消息
  问题：② 失败？消息丢了，库存已扣

  ① 发消息 → ② 写本地事务
  问题：② 失败？消息发了，但没扣库存

RocketMQ 事务消息：两阶段提交 + 回查
```

### 4.2 事务消息流程

```text
事务消息的两阶段提交：

Producer                      Broker                    Local DB
   │                            │                         │
   │ ① 发送半消息(half msg)      │                         │
   │ ─────────────────────────→ │                         │
   │                            │ 半消息存在，消费者不可见    │
   │                            │                         │
   │ ② 执行本地事务              │                         │
   │ ─────────────────────────────────────────────────→ │
   │ ← 本地事务结果(成功/失败)    │                         │
   │                            │                         │
   │ ③ 提交/回滚                 │                         │
   │ ─────────────────────────→ │                         │
   │   COMMIT → 消费者可见        │                         │
   │   ROLLBACK → 删除半消息      │                         │
   │                            │                         │
   │ ⚠️ 如果③没收到（超时/宕机）：  │                         │
   │  ← ④ Broker 回查 ──────────│                         │
   │  ⑤ 返回事务状态              │                         │
   │ ─────────────────────────→ │                         │
```

### 4.3 代码实现

```java
// 事务消息生产者
TransactionMQProducer producer = new TransactionMQProducer("tx-group");
producer.setTransactionListener(new TransactionListener() {
    // 执行本地事务
    @Override
    public LocalTransactionState executeLocalTransaction(Message msg, Object arg) {
        try {
            // 执行本地事务：扣库存、写订单...
            doLocalTransaction(msg, arg);
            return LocalTransactionState.COMMIT_MESSAGE;
        } catch (Exception e) {
            return LocalTransactionState.ROLLBACK_MESSAGE;
        }
    }
    
    // Broker 回查（Broker 没收到提交/回滚时调用）
    @Override
    public LocalTransactionState checkLocalTransaction(MessageExt msg) {
        // 查询本地事务状态
        boolean success = checkLocalTransactionStatus(msg);
        return success ? LocalTransactionState.COMMIT_MESSAGE
                       : LocalTransactionState.ROLLBACK_MESSAGE;
    }
});

producer.start();
// 发送事务消息
Message msg = new Message("OrderTopic", "order", orderJSON.getBytes());
TransactionSendResult result = producer.sendMessageInTransaction(msg, orderId);
```

### 4.4 事务消息关键参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `transactionTimeout` | 6000ms | 事务超时时间 |
| `transactionCheckMax` | 15 | 最大回查次数 |
| `transactionCheckInterval` | 60000ms | 回查间隔 |

> 💡 事务消息是 RocketMQ 最核心的竞争力之一，Kafka 的实现相对复杂且有限。

## 5. 延迟消息

### 5.1 18 个延迟级别

```java
// 目前只支持固定级别的延迟（非任意时间）
// 配置在 Broker 的 messageDelayLevel
// 默认级别：
// 1s 5s 10s 30s 1m 2m 3m 4m 5m 6m 7m 8m 9m 10m 20m 30m 1h 2h

Message msg = new Message("Topic", "Tag", "body".getBytes());
// 设置延迟级别：3 → 10 秒后投递
msg.setDelayTimeLevel(3);
producer.send(msg);
```

| Level | 延迟时间 | 典型场景 |
|:-----:|------|------|
| 1 | 1s | 快速重试 |
| 3 | 10s | 短时回查 |
| 5 | 1m | 临时锁定释放 |
| 14 | 10m | 订单超时取消 |
| 16 | 30m | 长时间延迟通知 |

### 5.2 延迟消息实现原理

```text
延迟消息不是用定时器，而是通过特殊 Topic：

① 发送时：消息存入 SCHEDULE_TOPIC_XXXX
② 存储：ConsumeQueue 的 Tag Hash 存的是投递时间
③ 定时任务：扫描 SCHEDULE_TOPIC，判断是否到期
④ 到期：投递到原始 Topic
⑤ 消费者：正常消费

5.x 改进：支持任意时间的定时消息
  → 基于时间轮（TimeWheel）实现
  → 不再受 18 级限制
```

> ⚠️ 4.x 的 18 个级别可以通过修改 Broker 配置 `messageDelayLevel` 自定义。

## 6. 批量消息

```java
// 发送批量消息 — 必须同一 Topic
List<Message> messages = new ArrayList<>();
messages.add(new Message("Topic", "TagA", "msg1".getBytes()));
messages.add(new Message("Topic", "TagA", "msg2".getBytes()));
messages.add(new Message("Topic", "TagB", "msg3".getBytes()));  // 可以不同 Tag

SendResult result = producer.send(messages);

// ⚠️ 限制：
// ① 同 Topic
// ② 总大小 < 4MB（4.7 之前）
// ③ 不能是延迟/事务消息
```

### 批量拆分工具

```java
// 如果消息超过 4MB，需要手动拆分
ListSplitter splitter = new ListSplitter(messages, 1024 * 1024); // 1MB 一批
while (splitter.hasNext()) {
    List<Message> batch = splitter.next();
    producer.send(batch);
}
```

## 7. 消息过滤

### 7.1 Tag 过滤

```java
// 生产者 — 设置 Tag
Message msg = new Message("OrderTopic", "PAID", orderJSON.getBytes());
//                                 ------ Tag: 支付成功的订单
producer.send(msg);

// 消费者 — 订阅时指定 Tag
consumer.subscribe("OrderTopic", "PAID || CREATED");  // 同时订阅两种
// consumer.subscribe("OrderTopic", "*");             // 所有 Tag
// consumer.subscribe("OrderTopic", "PAID");           // 单个 Tag

// Tag 过滤在 Broker 端执行 → 减少网络传输 ✅
```

### 7.2 SQL92 属性过滤

```java
// 生产者 — 设置自定义属性
Message msg = new Message("Topic", "Tag", body);
msg.putUserProperty("region", "east");
msg.putUserProperty("amount", "1000");
msg.putUserProperty("vip", "true");
producer.send(msg);

// 消费者 — SQL92 表达式过滤（需 Broker 启用 enablePropertyFilter=true）
consumer.subscribe("Topic", MessageSelector.bySql(
    "(region = 'east' AND amount > 500) OR vip = 'true'"
));
```

### 7.3 过滤方式对比

| 方式 | 过滤位置 | 精度 | 性能 | 灵活度 |
|------|:---:|------|:---:|:---:|
| **Tag** | Broker | 粗 | 高 | 低 |
| **SQL92** | Broker | 细 | 中 | 高 |
| **客户端过滤** | Consumer | — | 低（多余传输） | — |

## 8. 消息重试与死信

### 8.1 重试机制

```java
// 消费者 — 消费失败返回 RECONSUME_LATER
consumer.registerMessageListener(new MessageListenerConcurrently() {
    @Override
    public ConsumeOrderlyStatus consumeMessage(List<MessageExt> msgs,
                                                ConsumeOrderlyContext context) {
        try {
            process(msgs);
            return ConsumeOrderlyStatus.SUCCESS;
        } catch (Exception e) {
            // 消费失败 → 自动进入重试队列
            return ConsumeOrderlyStatus.SUSPEND_CURRENT_QUEUE_A_MOMENT;
            // 或 context.setSuspendCurrentQueueTimeMillis(3000);
        }
    }
});
```

### 8.2 重试队列原理

```text
消费失败 → Broker 将消息投递到 RETRY Topic

重试 Topic: %RETRY%ConsumerGroupName

重试间隔（4.x 默认）：
  Level 1:  10s
  Level 2:  30s
  Level 3:  1m
  Level 4:  2m
  Level 5:  3m
  ...
  Level 16: 2h（最后一级）

⚠️ 16 次重试全部失败 → 进入死信队列
```

### 8.3 死信队列

```text
重试 16 次失败 → 消息进入 %DLQ%ConsumerGroupName

死信队列处理：
  ✅ 通过控制台查看死信消息
  ✅ 手动重发到原 Topic
  ✅ 或人工处理（写入数据库/告警）
  
死信队列不会自动删除，需要人工处理！

参数：
  → 最大重试次数通过 Consumer 的 MaxReconsumeTimes 设置
```

## 9. 消息类型速选指南

| 场景 | 推荐类型 | 关键配置 |
|------|----------|----------|
| 日志采集 | 普通消息（单向/异步） | sendOneway |
| 业务通知 | 普通消息（同步/异步） | 默认 |
| 订单状态流转 | 顺序消息（分区） | MessageQueueSelector |
| 下单+扣库存 | 事务消息 | TransactionMQProducer |
| 30 分钟未支付 | 延迟消息 | setDelayTimeLevel(14) |
| 批量导入 | 批量消息 | List<Message> |
| 多业务消费同一 Topic | Tag 过滤 | subscribe("Topic", "TagA") |
| 复杂条件消费 | SQL92 过滤 | MessageSelector.bySql(...) |
