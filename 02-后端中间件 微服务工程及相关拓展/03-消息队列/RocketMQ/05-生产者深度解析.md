## 1. 生产者核心组件

```text
DefaultMQProducer 内部结构：

┌───────────────────────────────────────────────────────┐
│                  DefaultMQProducer                     │
├───────────────────────────────────────────────────────┤
│  MQClientInstance（客户端实例，进程内单例）               │
│  ├── Netty Client → 与 Broker/NameServer 通信          │
│  ├── Topic Route Info → 本地缓存路由信息                │
│  ├── Heartbeat → 定时向 Broker 发送心跳                │
│  └── Rebalance → 消费者使用，生产者不需要                │
├───────────────────────────────────────────────────────┤
│  发送策略                                              │
│  ├── 同步发送 (sync)                                    │
│  ├── 异步发送 (async)                                   │
│  └── 单向发送 (oneway)                                  │
├───────────────────────────────────────────────────────┤
│  容错机制                                              │
│  ├── 发送重试 (retryTimesWhenSendFailed)               │
│  ├── Broker 故障延迟 (sendLatencyFaultEnable)          │
│  └── 自动切换 Queue                                    │
└───────────────────────────────────────────────────────┘
```

## 2. 生产者启动流程

```text
DefaultMQProducer.start() 过程：

① 创建 MQClientInstance（单例）
② 注册 Producer 到 ClientInstance
③ 启动 Netty 客户端
④ 启动定时任务：
     ├── 每 30s 从 NameServer 拉取路由
     ├── 每 30s 向所有 Broker 发送心跳
     └── 清理离线 Broker、过期消息
⑤ 发送启动完成信号
```

## 3. 消息发送流程详解

```text
producer.send(msg) 内部流程：

① 获取 Topic 路由信息
     ├── 本地缓存命中 → 直接使用
     └── 本地缓存未命中 → 向 NameServer 请求 → 缓存

② 选择 MessageQueue
     ├── 指定了 MessageQueueSelector → 按自定义逻辑选
     ├── 未指定 Key → 默认轮询
     └── 指定了 Key → Hash 到固定 Queue

③ 找到 Queue 所在的 Broker Master 地址

④ 组装 RemotingCommand → 通过 Netty Client 发送

⑤ 等待响应
     ├── 同步：阻塞等待（默认 3s 超时）
     ├── 异步：注册回调
     └── 单向：不等待

⑥ 失败处理
     ├── 重试（retryTimesWhenSendFailed=2，共 3 次）
     ├── 故障延迟（sendLatencyFaultEnable=true）
     └── 切换其他 Broker 的 Queue
```

## 4. 消息路由策略

### 4.1 默认轮询

```java
// 不指定 Key → 默认轮询（同步发送时是 round-robin）
for (int i = 0; i < 100; i++) {
    Message msg = new Message("Topic", "Tag", ("msg" + i).getBytes());
    producer.send(msg);  // 自动轮询到不同 Queue
}
```

### 4.2 Key Hash 路由

```java
// 相同 Key → 相同 Queue → 局部有序
String orderId = "ORDER-12345";
Message msg = new Message("Topic", "Tag", orderId, body);
producer.send(msg);  // Key=orderId，Hash 到固定 Queue
```

### 4.3 自定义路由

```java
SendResult result = producer.send(msg, new MessageQueueSelector() {
    @Override
    public MessageQueue select(List<MessageQueue> mqs, Message msg, Object arg) {
        // 自定义规则
        int id = (int) arg;
        return mqs.get(id % mqs.size());
    }
}, customId);
```

### 4.4 故障延迟机制

```java
// 开启故障延迟 — 避免重复向故障 Broker 发消息（默认关闭）
producer.setSendLatencyFaultEnable(true);

// 故障持续时长（毫秒）
producer.setNotAvailableDuration(30000L);  // Broker 不可用 30s
producer.setLatencyMax(500L);             // 超过 500ms 视为延迟

// 延迟级别和对应的不可用时间
// latencyMax=[50, 100, 550, 1000, 2000, 3000, 15000]
// notAvailableDuration=[0, 0, 30000, 60000, 120000, 180000, 600000]
```

## 5. 发送重试与容错

### 5.1 重试策略

```java
// 同步重试次数（默认 2 次，加上最初 1 次 = 共 3 次）
producer.setRetryTimesWhenSendFailed(2);

// 异步重试次数（默认 2 次）
producer.setRetryTimesWhenSendAsyncFailed(2);

// 重试逻辑：
// ① 重试时选择不同的 Broker 上的 Queue
// ② 总耗时 = (1 + retryTimes) × sendMsgTimeout
// ③ 全部失败 → 抛出 MQClientException
```

### 5.2 超时控制

```java
// 发送超时时间（毫秒，默认 3000 = 3 秒）
producer.setSendMsgTimeout(3000);

// 注意：总超时 ≈ sendMsgTimeout × (1 + retryTimes)
// retryTimes=2, sendMsgTimeout=3s → 总超时 ≈ 9s
```

### 5.3 异常处理最佳实践

```java
try {
    SendResult result = producer.send(msg);
    switch (result.getSendStatus()) {
        case SEND_OK:
            log.info("发送成功");
            break;
        case FLUSH_DISK_TIMEOUT:
            log.warn("刷盘超时，消息可能已写入");
            break;
        case FLUSH_SLAVE_TIMEOUT:
            log.warn("同步 Slave 超时，Master 可能已写入");
            break;
        case SLAVE_NOT_AVAILABLE:
            log.warn("Slave 不可用");
            break;
    }
} catch (MQClientException e) {
    if (e.getResponseCode() == 17) {
        // TOPIC_NOT_EXIST — Topic 不存在
        log.error("Topic 不存在");
    }
    // 写入本地重试表
    saveToRetryTable(msg);
} catch (RemotingException | MQBrokerException | InterruptedException e) {
    // 网络/服务端异常
    saveToRetryTable(msg);
}
```

## 6. 事务消息回查机制

### 6.1 回查触发条件

```text
Broker 在以下情况会回查 Producer：

① 半消息发送成功，但未收到 Commit/Rollback
② 半消息超时（transactionTimeout，默认 6s）
③ Producer 在回查前重启（Broker 重新发起回查）

回查参数：
  → transactionCheckMax = 15（最多回查 15 次）
  → transactionCheckInterval = 60s（回查间隔 60 秒）
```

### 6.2 checkLocalTransaction 实现要点

```java
public class OrderTransactionListener implements TransactionListener {
    
    @Override
    public LocalTransactionState executeLocalTransaction(Message msg, Object arg) {
        String orderId = msg.getKeys();
        try {
            // 执行本地事务
            orderService.createOrder(orderId, arg);
            return LocalTransactionState.COMMIT_MESSAGE;
        } catch (DuplicateKeyException e) {
            // 幂等处理：订单已存在
            return LocalTransactionState.COMMIT_MESSAGE;
        } catch (Exception e) {
            return LocalTransactionState.ROLLBACK_MESSAGE;
        }
    }
    
    @Override
    public LocalTransactionState checkLocalTransaction(MessageExt msg) {
        String orderId = msg.getKeys();
        // ⚠️ 回查必须能查到事务状态！
        // 推荐：通过 orderId 查数据库
        Order order = orderService.getByOrderId(orderId);
        if (order != null && order.getStatus() == OrderStatus.CREATED) {
            return LocalTransactionState.COMMIT_MESSAGE;
        } else if (order != null && order.getStatus() == OrderStatus.CANCELLED) {
            return LocalTransactionState.ROLLBACK_MESSAGE;
        } else {
            // 订单还在处理中 → 返回 UNKNOW，Broker 会继续回查
            return LocalTransactionState.UNKNOW;
        }
    }
}
```

### 6.3 事务消息注意事项

| 注意点 | 说明 |
|--------|------|
| **Producer Group** | 必须设置，用于标识事务回查的 Producer |
| **幂等** | `executeLocalTransaction` 必须幂等（可能重复调用） |
| **回查可达** | `checkLocalTransaction` 必须能找到事务状态 |
| **超时** | 本地事务执行不要太久，注意 `transactionTimeout` |
| **限制** | 事务消息不支持延迟和批量 |

## 7. 生产者关键配置

```java
// ===== 生产者完整配置参考 =====
DefaultMQProducer producer = new DefaultMQProducer("producer-group");

// ===== 基本 =====
producer.setNamesrvAddr("localhost:9876");        // NameServer 地址
producer.setProducerGroup("my-group");            // 生产组（事务消息必设）
producer.setInstanceName("instance-1");           // 实例名

// ===== 发送 =====
producer.setSendMsgTimeout(3000);                 // 发送超时 (ms)
producer.setRetryTimesWhenSendFailed(2);          // 同步重试次数
producer.setRetryTimesWhenSendAsyncFailed(2);     // 异步重试次数
producer.setCompressMsgBodyOverHowmuch(4096);     // 超过 4KB 压缩
producer.setRetryAnotherBrokerWhenNotStoreOK(true); // 失败切换 Broker

// ===== 容错 =====
producer.setSendLatencyFaultEnable(true);         // 开启故障延迟
producer.setNotAvailableDuration(30000L);         // 故障 Broker 不可用时间
producer.setLatencyMax(500L);

// ===== 消息体 =====
producer.setMaxMessageSize(4 * 1024 * 1024);      // 最大 4MB
```

## 8. Java 生产者实战

```java
public class ReliableProducer {
    
    private DefaultMQProducer producer;
    
    public void init() throws MQClientException {
        producer = new DefaultMQProducer("order-producer-group");
        producer.setNamesrvAddr("localhost:9876");
        producer.setSendMsgTimeout(5000);
        producer.setRetryTimesWhenSendFailed(3);
        producer.setCompressMsgBodyOverHowmuch(4096);
        producer.setRetryAnotherBrokerWhenNotStoreOK(true);
        producer.setSendLatencyFaultEnable(true);
        producer.start();
    }
    
    // 同步发送（重要业务）
    public SendResult sendSync(String topic, String tags, String keys, String body)
            throws Exception {
        Message msg = new Message(topic, tags, keys, body.getBytes(StandardCharsets.UTF_8));
        msg.putUserProperty("traceId", MDC.get("traceId"));
        try {
            SendResult result = producer.send(msg);
            log.info("发送成功: msgId={}, queue={}", result.getMsgId(), 
                     result.getMessageQueue());
            return result;
        } catch (MQClientException | RemotingException 
                | MQBrokerException | InterruptedException e) {
            log.error("发送失败: keys={}", keys, e);
            // 写入本地重试表
            saveToRetryQueue(msg);
            throw e;
        }
    }
    
    // 异步发送（通用场景）
    public void sendAsync(String topic, String tags, String body) {
        Message msg = new Message(topic, tags, body.getBytes(StandardCharsets.UTF_8));
        producer.send(msg, new SendCallback() {
            @Override
            public void onSuccess(SendResult result) {
                log.info("异步发送成功: msgId={}", result.getMsgId());
            }
            @Override
            public void onException(Throwable e) {
                log.error("异步发送失败", e);
                saveToRetryQueue(msg);
            }
        });
    }
    
    // 顺序发送
    public SendResult sendOrderly(String topic, long orderId, String body)
            throws Exception {
        Message msg = new Message(topic, "ORDER", "" + orderId,
                                  body.getBytes(StandardCharsets.UTF_8));
        return producer.send(msg, (mqs, m, arg) -> {
            long id = (long) arg;
            return mqs.get((int) (id % mqs.size()));
        }, orderId);
    }
    
    public void shutdown() {
        producer.shutdown();
    }
}
```

## 生产者速查

| 要点 | 说明 |
|------|------|
| **发送模式** | 同步（可靠）/ 异步（高吞吐）/ 单向（日志） |
| **消息路由** | Key Hash（保序）/ 轮询（均衡）/ 自定义 |
| **故障隔离** | sendLatencyFaultEnable=true → 避免连击故障 Broker |
| **重试策略** | 默认 2 次，切换 Queue/Broker |
| **事务消息** | 两阶段 + Broker 回查 → executeLocalTransaction + checkLocalTransaction |
| **压缩** | 超过 compressMsgBodyOverHowmuch 自动压缩 |
