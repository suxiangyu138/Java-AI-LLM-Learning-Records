## 1. 什么是企业级标准

```
企业级标准 = 从"能跑"到"能长期稳定运营"的工程体系

八个维度：
  ① 代码质量：规范、审查、静态检查
  ② 工程化：构建、依赖、版本
  ③ 测试：金字塔、覆盖率、契约
  ④ CI/CD：流水线、发布策略
  ⑤ 可观测性：日志、指标、链路
  ⑥ 安全：左移、密钥、漏洞
  ⑦ 性能稳定性：压测、容量、容灾
  ⑧ 文档协作：规范、流程、文化

⚠️ 面试必答：
"企业级 = 全生命周期工程能力——
 不只看功能跑通，更看质量、安全、
 可观测、可回滚、可度量的完整体系。"
```

## 2. 质量内建：从测试通过到全维度质量

### 2.1 质量定义扩展（2026）

```
现代质量观（超出"发布前测试通过"）：
  性能（延迟/吞吐）
  可用性（SLO）
  安全性（漏洞/合规）
  韧性（故障恢复）
  用户体验

⚠️ 面试必答：
"企业级质量是全维度——功能只是底线，
 性能、可用、安全、韧性都是发布标准。"
```

### 2.2 质量内建（Quality Built-in）

```
质量内建四实践：
  ① 代码审查（Code Review）——每变更必审
  ② TDD——先测试后实现
  ③ 持续重构——小步优化
  ④ 静态检查门禁——CI 强制

⚠️ 面试必答：
"'质量内建' = 质量不是测试阶段补的，
 而是开发全程构建的——
 审查/测试/检查进入每个环节。"
```

## 3. 12-Factor 原则

| # | 原则 | 说明 |
|:---:|------|------|
| 1 | 基准代码 | 一份代码库，多环境部署 |
| 2 | 依赖 | 显式声明依赖 |
| 3 | 配置 | **配置外置**（环境变量，不进代码） |
| 4 | 后端服务 | 数据库/消息队列视为可替换资源 |
| 5 | 构建/发布/运行 | 三阶段分离 |
| 6 | 无状态进程 | 进程不存状态（会话外置） |
| 7 | 端口绑定 | 自包含服务 |
| 8 | 并发 | 进程模型扩展 |
| 9 | 易处置 | 快速启动/优雅关闭 |
| 10 | 开发/生产一致 | 环境差异最小化 |
| 11 | 日志 | 日志是事件流（stdout） |
| 12 | 管理进程 | 一次性管理任务 |

```
⚠️ 面试必答：
"12-Factor 核心三条——配置外置（环境变量）、
 无状态进程（可水平扩展）、日志事件流
 （不落盘直接采集）。容器化时代依然适用。"
```

## 4. DORA 四指标

### 4.1 四个指标

| 指标 | 含义 | 精英级标准 |
|------|------|-----------|
| 部署频率 | 多久部署一次 | 每天多次 |
| 变更前置时间 | 提交到上线耗时 | < 1 小时 |
| 变更失败率 | 部署失败比例 | < 5% |
| 恢复时长（MTTR） | 故障恢复时间 | < 1 小时 |

```
⚠️ 面试必答：
"DORA 四指标度量交付效能——
 部署频率（快不快）、前置时间（顺不顺）、
 失败率（稳不稳）、恢复时长（扛不扛）。
 精英团队 = 高频 + 低失败 + 快恢复。"
```

### 4.2 指标之间的平衡

```
⚠️ 注意：
  部署频率与失败率矛盾（快 vs 稳）
  正确姿势：通过自动化让"又快又稳"
  （小批量 + 自动化测试 + 自动回滚）

⚠️ 面试必答：
"DORA 不是'越快越好'——四指标联动，
 快的前提是自动化兜底（测试/回滚）。"
```

## 5. SLO 与错误预算

### 5.1 三个 S 的概念

```
SLI（指标）：可度量的服务指标（如可用性 99.9%）
SLO（目标）：承诺的指标值（如 99.9%）
SLA（协议）：对外承诺（含惩罚）

⚠️ 面试必答：
"SLI 度量、SLO 承诺、SLA 协议——
 先定 SLI 再定 SLO；SLO 是团队内部
 目标，SLA 是对客户的合同。"
```

### 5.2 错误预算

```
错误预算 = 1 - SLO（允许出错的额度）
  99.9% SLO → 每月允许 43 分钟故障

用法：
  预算充足 → 正常发布
  预算烧完 → 冻结发布（只做稳定性）

⚠️ 面试必答：
"错误预算 = 允许失败的时间额度——
 预算烧完冻结新功能、只做稳定性修复。
 用数据决定'能不能发'而不是拍脑袋。"
```
