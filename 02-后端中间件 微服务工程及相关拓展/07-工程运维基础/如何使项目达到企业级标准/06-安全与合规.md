## 1. 安全体系总览

```
企业级安全四层：
  ① 代码层：漏洞扫描、输入校验、安全编码
  ② 构建层：依赖漏洞、镜像扫描、签名
  ③ 部署层：密钥管理、最小权限、网络隔离
  ④ 运行层：WAF、审计日志、监控告警

⚠️ 面试必答：
"安全四层——代码、构建、部署、运行，
 每层有检测与防护；
 安全左移 = 越早发现修复成本越低。"
```

## 2. OWASP Top 10 核心风险

### 2.1 最高频三大风险

| 风险 | 攻击方式 | 防御 |
|------|---------|------|
| 注入（SQL/命令） | 拼接输入执行 | 参数化查询 + 白名单校验 |
| 越权（BOLA/BFLA） | 直接访问他人资源 | 服务端权限校验（不信任前端） |
| XSS | 注入脚本窃取会话 | 输出转义 + CSP + Cookie httpOnly |

```java
// ⚠️ SQL 注入防御：参数化（MyBatis #{} 非 ${}）
// ❌ SELECT * FROM user WHERE id = ${id}      ← 注入！
// ✅ SELECT * FROM user WHERE id = #{id}      ← 参数化

// ⚠️ 越权防御：每次资源操作校验归属
public Order getOrder(Long orderId, Long userId) {
    Order order = orderRepo.findById(orderId);
    if (!order.getUserId().equals(userId)) {
        throw new ForbiddenException();   // ⚠️ 服务端校验
    }
    return order;
}
```

### 2.2 其他高频风险

```
① 失效认证：弱口令/会话固定 → 强密码策略 + 登录限制
② 敏感数据泄露：传输 TLS + 存储加密 + 日志脱敏
③ 安全配置错误：默认密码/调试端口 → 配置基线
④ 不安全组件：依赖漏洞 → 持续扫描
⑤ 日志伪造/信息泄露：错误信息不暴露内部细节
```

> 🎯 **要点**：OWASP 三大高频——注入（参数化）、越权（服务端校验）、XSS（转义 + httpOnly）。面试先答这仨再扩展。

## 3. 密钥与配置安全

### 3.1 密钥管理原则

```
密钥管理铁律：
  ❌ 代码/配置文件硬编码（最普遍的安全事故）
  ❌ 提交到 Git（历史记录永久存在）
  ✅ 环境变量 / 配置中心 / Vault / KMS
  ✅ 密钥轮换（定期更换）

⚠️ 面试必答：
"密钥管理铁律——不进代码、
 不进 Git、用 Vault/KMS 托管、
 定期轮换。gitleaks 扫描防遗漏。"
```

### 3.2 实践方案

| 方案 | 场景 |
|------|------|
| 环境变量 + Docker Secret | 简单部署 |
| Vault | 动态密钥 + 审计 |
| 云 KMS（AWS KMS/阿里 KMS） | 云环境 |
| 配置中心加密（Nacos/Apollo） | 微服务 |

```java
// 加密配置示例（Spring 配置中心加密）
// 配置中心存密文，应用解密使用
spring.datasource.password: ENC(xxxx加密串)
// 配合 jasypt 或配置中心解密插件
```

## 4. 认证与授权

### 4.1 认证方案演进

```
认证演进：
  ① Session（传统）：服务端存储 + Cookie
  ② JWT（无状态）：令牌自包含 + 签名
  ③ OAuth2/OIDC：第三方授权（企业标准）
  ④ SSO：统一登录（多系统）

⚠️ 面试必答：
"认证方案四代——Session、JWT、
 OAuth2/OIDC、SSO；
 企业标准是 OAuth2 + JWT 组合。"
```

### 4.2 JWT 安全要点

```
JWT 使用规范：
  ✅ 签名算法 RS256（非对称）
  ❌ HS256 + 弱密钥（可被爆破）
  ✅ 过期时间（短时效 + refresh token）
  ✅ HTTPS 传输（防中间人）
  ⚠️ 服务端仍需校验权限（JWT 只认证不授权）

⚠️ 面试必答：
"JWT 安全四要点——RS256 签名、
 短过期、HTTPS、服务端授权校验；
 JWT 解决认证，授权（越权）仍需 RBAC。"
```

### 4.3 授权模型

```
RBAC（基于角色）：
  用户 → 角色 → 权限
  ⚠️ 企业标准（Spring Security + 注解）

Spring Security 核心：
  SecurityFilterChain 过滤链
  @PreAuthorize("hasRole('ADMIN')") 方法级
  JWT 过滤器解析令牌 → 认证上下文

⚠️ 面试必答：
"授权用 RBAC——用户挂角色、角色挂权限；
 Spring Security 的过滤器链 +
 方法级 @PreAuthorize 是标准实现。"
```

## 5. 供应链安全

### 5.1 供应链攻击面

```
供应链风险（2026 高发）：
  ① 依赖漏洞（CVE 组件）
  ② 恶意包（typosquatting 拼写劫持）
  ③ 镜像漏洞（基础镜像带 CVE）
  ④ 构建工具被篡改（签名缺失）

⚠️ 面试必答：
"供应链安全 = 依赖 + 镜像 + 制品全链路——
 每个环节都可能被投毒。"
```

### 5.2 防御体系

| 环节 | 措施 |
|------|------|
| 依赖 | OWASP DC / Trivy 持续扫描 + 版本锁定 |
| 镜像 | 多阶段构建 + distroless + 扫描 |
| 制品 | cosign 签名 + syft SBOM |
| 仓库 | 私有源 + 代理（防被删包） |
| 人工 | 依赖升级评审（不看 CVE 就升级也危险） |

```
⚠️ 面试必答：
"供应链防御五件套——依赖扫描、
 镜像瘦身扫描、制品签名、SBOM、
 私有仓库代理。零 CVE 是 CI 门禁。"
```

## 6. 合规与安全清单

### 6.1 企业级安全清单

```
✅ 代码层：参数化查询、输入校验、无硬编码密钥
✅ 构建层：依赖扫描（Trivy）、安全静态分析（CodeQL）
✅ 部署层：最小权限（非 root）、端口最小暴露、网络隔离
✅ 运行层：WAF、审计日志、安全监控告警
✅ 数据层：传输 TLS、存储加密、日志脱敏
✅ 账号层：强密码、MFA、最小权限、离职回收
✅ 流程层：漏洞响应预案、安全评审（发布前）
```

### 6.2 合规要求

```
常见合规（视行业）：
  等保 2.0（国内通用）
  GDPR（欧盟数据）
  PCI-DSS（支付）
  SOX（上市企业）

合规通用要求：
  审计日志（谁在什么时候做了什么）
  数据加密（传输 + 存储）
  权限最小化 + 可追溯

⚠️ 面试必答：
"合规 = 审计 + 加密 + 权限三件套——
 审计日志可追溯、数据加密、最小权限；
 等保/GDPR 是常见行业要求。"
```

> 🎯 **核心要点**：安全体系 = **OWASP 三大风险**（注入/越权/XSS）+ **密钥管理**（Vault + 轮换 + 扫描）+ **认证授权**（OAuth2 + JWT + RBAC）+ **供应链**（依赖/镜像/制品全链路）+ **合规清单**（审计/加密/权限）。"安全左移 + 纵深防御"是企业安全的完整姿势。
