## 1. 知识全景图

```
软件工程知识体系（SWEBOK核心领域）
│
├── 📐 软件过程
│   ├── 瀑布模型 → 敏捷宣言 → DevOps
│   ├── CMMI成熟度模型
│   └── 过程改进（PDCA循环）
│       → 02-软件开发过程模型.md
│
├── 📋 需求工程
│   ├── 需求获取（访谈/问卷/原型）
│   ├── 需求分析（用例图/数据流图）
│   ├── 需求规格说明（SRS文档）
│   └── 需求验证与管理
│       → 03-需求工程.md
│
├── 🏗️ 软件设计
│   ├── 设计原则：SOLID、DRY、KISS、YAGNI
│   ├── 设计模式：创建型/结构型/行为型（GoF 23）
│   ├── 架构风格：分层/微服务/事件驱动/六边形
│   └── UML建模：类图/时序图/用例图
│       → 04-软件设计与架构原则.md
│
├── ✅ 质量保证
│   ├── SQA活动（审计/评审/测试）
│   ├── 验证 vs 确认（Verification vs Validation）
│   ├── 质量度量（缺陷密度/MTBF/客户满意度）
│   └── 软件可靠性工程
│       → 05-软件质量保证.md
│
├── 📦 配置管理
│   ├── 版本控制（Git工作流）
│   ├── 变更管理（CCB变更控制委员会）
│   ├── 分支策略（GitFlow/Trunk-Based）
│   └── 持续集成/持续交付
│       → 06-软件配置管理.md
│
└── 🔄 维护与演化
    ├── 维护类型（纠错/适应/完善/预防）
    ├── 重构技术
    ├── 技术债务管理
    └── 遗留系统现代化
        → 07-软件维护与演化.md
```

## 2. 与工程与项目能力目录的关系

| 维度 | `软件工程/`（本目录） | `工程与项目能力/`（兄弟目录） |
|------|---------------------|---------------------------|
| **定位** | 软件工程**理论与体系** | 工程**实践与技能** |
| **内容** | SDLC模型、需求工程、设计原则 | API设计、技术方案、敏捷实战、文档写作 |
| **粒度** | 宏观方法论 | 微观可操作技能 |
| **典型问题** | "为什么要做需求分析？" | "怎么写一份技术方案？" |
| **关系** | 理论指导 | 实践落地 |

> 💡 **学习建议**：先看本目录建立软件工程全局观 → 再看工程能力目录掌握实操技能 → 两者结合融会贯通。

## 4. 学习路线

### 🟢 入门（1天）

```
上午：软件工程概论（建立全局观） → 02-过程模型
下午：03-需求工程 → 04-设计与架构（重点：SOLID原则）
```

### 🔵 进阶（2天）

```
以上 + 05-质量保证 + 06-配置管理 + 07-维护与演化
配合实践：用学到的原则审查自己项目的代码质量
```
