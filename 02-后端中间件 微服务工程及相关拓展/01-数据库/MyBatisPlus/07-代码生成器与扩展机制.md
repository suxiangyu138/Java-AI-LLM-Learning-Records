## 1. FastAutoGenerator：三行生成全模块

**FastAutoGenerator**（3.5.x 推荐）——连数据库 → 生成实体/Mapper/Service/Controller 全套：

```xml
<!-- 依赖：代码生成器（仅开发期用，可放单独模块） -->
<dependency>
    <groupId>com.baomidou</groupId>
    <artifactId>mybatis-plus-generator</artifactId>
    <version>3.5.17</version>
</dependency>
<dependency>   <!-- 模板引擎（二选一） -->
    <groupId>org.apache.velocity</groupId>
    <artifactId>velocity-engine-core</artifactId>
    <version>2.3</version>
</dependency>
```

```java
// 核心三行：数据源 → 包配置 → 生成
public class Generator {
    public static void main(String[] args) {
        FastAutoGenerator.create(
                        "jdbc:mysql://localhost:3306/demo", "root", "root")   // ① 数据源
                .globalConfig(builder -> builder.author("苏巷雨")
                        .outputDir("D:/gen"))                                  // ② 输出
                .packageConfig(builder -> builder.parent("com.example")
                        .entity("entity").mapper("mapper").service("service")
                        .serviceImpl("service.impl").controller("controller"))
                .strategyConfig(builder -> builder
                        .addInclude("user", "order")                          // ③ 生成哪些表
                        .entityBuilder().enableLombok()                       // 实体：Lombok
                        .logicDeleteColumnName("deleted")                     // 逻辑删除字段
                        .versionColumnName("version")                         // 乐观锁字段
                        .controllerBuilder().enableRestStyle())               // Controller：@RestController
                .execute();                                                   // 执行！
    }
}
```

**生成的四层文件**：

```text
entity/User.java          —— @TableName + @TableId + Lombok（含逻辑删除/乐观锁标注）
mapper/UserMapper.java    —— extends BaseMapper<User>
service/UserService.java  —— extends IService<User>
service/impl/UserServiceImpl.java —— extends ServiceImpl<UserMapper, User>
controller/UserController.java   —— @RestController + 标准 REST 接口（get/list/page/save/update/delete）
```

> 🎯 **核心要点**：生成器把"建表 → 可运行 CRUD"压缩到分钟级——**表结构即代码蓝图**。生成的代码是"起点"而非"终点"：实体/Mapper 可保留，Controller 常要按业务裁剪。

## 2. 生成代码的企业级定制

**生成器的定制点**（生产规范落地）：

| 定制维度 | 配置 | 生产价值 |
|---------|------|---------|
| 逻辑删除/乐观锁 | `logicDeleteColumnName`/`versionColumnName` | 生成即带规范字段 |
| 自动填充字段 | `@TableField(fill=...)` 模板定制 | 时间字段自动填充 |
| 命名策略 | `columnNaming`/`entityNaming` | 团队命名统一 |
| 模板引擎 | Velocity/Freemarker | 可自定义模板（生成 DTO/VO 等） |
| 超类 | `superClass` | 实体继承公共基类（如 BaseEntity） |

```java
// 企业级定制的常用组合：
.strategyConfig(builder -> builder
        .addInclude("t_user", "t_order")
        .entityBuilder()
        .enableLombok()
        .superClass(BaseEntity.class)          // 公共字段（id/创建时间）继承
        .addSuperEntityColumns("id", "create_time", "update_time", "deleted", "version")
        .logicDeleteColumnName("deleted")
        .versionColumnName("version")
        .controllerBuilder().enableRestStyle().build());
```

**BaseEntity 模式**（公共字段收敛，团队标配）：

```java
@Data
public class BaseEntity {
    @TableId(type = IdType.ASSIGN_ID)
    private Long id;
    @TableField(fill = FieldFill.INSERT)
    private LocalDateTime createTime;
    @TableField(fill = FieldFill.INSERT_UPDATE)
    private LocalDateTime updateTime;
    @TableLogic
    private Integer deleted;
    @Version
    private Integer version;
}
// 业务实体 extends BaseEntity —— 五公共字段零重复声明
```

> 🎯 **核心要点**：生成器的真正价值 = "**把团队规范写进生成模板**"——规范字段（逻辑删除/乐观锁/时间）在生成时落地，新表接入零遗漏。

## 3. MetaObjectHandler 自动填充实战

**完整实战**（02 模块第 6 节的落地补充）——填充"创建/更新时间 + 操作人"：

```java
@Component
public class AuditFillHandler implements MetaObjectHandler {

    @Override
    public void insertFill(MetaObject metaObject) {
        this.strictInsertFill(metaObject, "createTime", LocalDateTime.class, LocalDateTime.now());
        this.strictInsertFill(metaObject, "updateTime", LocalDateTime.class, LocalDateTime.now());
        this.strictInsertFill(metaObject, "createBy", Long.class, SecurityUtils.getUserId());  // 当前用户
    }

    @Override
    public void updateFill(MetaObject metaObject) {
        this.strictUpdateFill(metaObject, "updateTime", LocalDateTime.class, LocalDateTime.now());
        this.strictUpdateFill(metaObject, "updateBy", Long.class, SecurityUtils.getUserId());
    }
}
```

**strict 系列 vs 普通填充**：

| 方式 | 行为 | 场景 |
|------|------|------|
| `strictInsertFill` | **仅字段为 null 时填充** | 推荐（不覆盖手动值） |
| `setFieldValByName` | 强制覆盖 | 特殊（字段已有值也要改） |

**注意**：自动填充在 **MyBatis 参数层面**生效——**手写 SQL（XML）不经过填充**（同逻辑删除边界）；需要的话 XML 里用数据库默认值或 `NOW()`。

> 🎯 **核心要点**：MetaObjectHandler 把"审计字段"（谁在什么时候建/改）变成框架级能力——**全库表的时间/操作人字段零手写且一致**。strict 系列（仅 null 填充）是推荐用法。

## 4. 自定义方法注入：SQL 注入器

**SQL 注入器（AbstractSqlInjector）**：给 BaseMapper 注入**你自己的通用方法**——团队级方法库：

```java
// ① 自定义方法类：继承 AbstractMethod，实现 SQL 生成
public class InsertOrUpdateIgnore extends AbstractMethod {
    @Override
    public MappedStatement injectMappedStatement(Class<?> mapperClass, Class<?> modelClass, TableInfo tableInfo) {
        String sql = "INSERT IGNORE INTO %s (%s) VALUES (%s)"
                .formatted(tableInfo.getTableName(),
                        sqlColumn(tableInfo, true),     // 列名（含逻辑删除）
                        sqlSet(tableInfo, true));       // 占位符
        SqlSource sqlSource = languageDriver.createSqlSource(configuration, sql, modelClass);
        return addInsertMappedStatement(mapperClass, "insertIgnore", sqlSource, modelClass, tableInfo);
    }
}

// ② 注入器：注册自定义方法
public class MySqlInjector extends DefaultSqlInjector {
    @Override
    public List<AbstractMethod> getMethodList(Class<?> mapperClass, TableInfo tableInfo) {
        List<AbstractMethod> methods = super.getMethodList(mapperClass, tableInfo);
        methods.add(new InsertOrUpdateIgnore());     // 追加团队通用方法
        return methods;
    }
}

// ③ 配置注入器
@Bean
public MySqlInjector mySqlInjector() { return new MySqlInjector(); }

// ④ 使用：任何 Mapper 继承 BaseMapper 即获得 insertIgnore 方法
@Mapper
public interface UserMapper extends BaseMapper<User> {
    int insertIgnore(User user);     // 方法名与 AbstractMethod 中一致
}
```

**适用场景**：`INSERT IGNORE`、`UPSERT`（ON DUPLICATE KEY）、批量插入公共方法等——**团队级 SQL 语义复用**（3.5.17 优化：SQL 注入改为函数拼接，性能提升）。

> 🎯 **核心要点**：SQL 注入器 = "**给 BaseMapper 家族添丁**"——团队把高频 SQL 语义（upsert/ignore）沉淀成方法，所有 Mapper 自动获得。进阶扩展点，生产团队值得建设。

## 5. 与 XML / 注解 SQL 的混合实践

**MP 不排斥手写 SQL**——正确姿势是"该自动的自动、该手写的精写"：

```java
// ① Mapper 接口自定义方法：注解 SQL（简单查询）
@Mapper
public interface OrderMapper extends BaseMapper<Order> {

    @Select("SELECT * FROM `order` WHERE user_id = #{userId} AND status = 1")
    List<Order> listPaidOrders(Long userId);

    // ② 注解 + Wrapper 融合（customSqlSegment，见 04 模块）
    @Select("SELECT * FROM `order` ${ew.customSqlSegment}")
    List<Order> selectByWrapper(@Param(Constants.WRAPPER) Wrapper<Order> wrapper);

    // ③ XML 文件（复杂多表联查）—— 对应 resources/mapper/OrderMapper.xml
    List<OrderDto> selectOrderDetail(@Param("orderId") Long orderId);
}
```

**混合实践的原则**（80/20 原则落地）：

| 场景 | 手段 |
|------|------|
| 单表 CRUD / 单表条件查询 | BaseMapper + Wrapper（80%） |
| 多表联查 / 复杂聚合 / 性能敏感 SQL | **XML 手写**（20%） |
| 简单自定义查询 | @Select 注解 |
| 需要复用 Wrapper 条件 | customSqlSegment |

**手写 SQL 的三个"自动能力丢失"提醒**：

1. **逻辑删除条件不自动拼**（XML 需手动 `AND deleted = 0`）；
2. **多租户条件不自动拼**（需手动 `AND tenant_id = ?`）；
3. **自动填充不生效**（用数据库默认值或 SQL 函数）。

> 🎯 **核心要点**：**MP 的边界 = 单表增强**——"80% 单表走 MP、20% 复杂查询精写 XML"是行业共识。手写 SQL 时把三个"自动丢失"补上（逻辑删除/租户/填充），就既享受效率又不掉进边界坑。
