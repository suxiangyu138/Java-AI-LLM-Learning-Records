## 1. 高频面试题

### Q1（⭐⭐⭐⭐⭐）: Oracle 和 MySQL 的核心差异？

| 维度 | Oracle | MySQL |
|------|--------|-------|
| 架构 | Instance + Database | 一体化 |
| 默认隔离级别 | READ COMMITTED | REPEATABLE READ |
| 自增 | SEQUENCE | AUTO_INCREMENT |
| 一致性读 | SCN + UNDO | Read View + UNDO LOG |
| 分页 | OFFSET FETCH / ROWNUM | LIMIT |
| 高可用 | RAC + Data Guard | MGR / MHA |
| 回收站 | ✅ FLASHBACK | ❌ |

### Q2: Oracle 的写不阻塞读怎么实现的？

> Oracle 用 UNDO 表空间保存修改前的数据。当读操作遇到正在被修改的数据块，直接从 UNDO 构造"修改前的版本"返回，不需要等待写锁释放。MySQL InnoDB 的 MVCC 原理类似但实现不同

### Q3: RAC 的脑裂怎么处理？

> 心跳网络中断 → 节点间无法通信 → 每个节点都以为自己是唯一的
> Oracle 通过投票磁盘 (Voting Disk) 解决：没有获得多数票的节点自动重启（STONITH）

### Q4: 怎么排查 Oracle 慢查询？

> 1. 查 ASH (`v$active_session_history`) → 找到热门等待事件
> 2. 生成 AWR 报告 → 看 Top SQL + Top Events
> 3. 对慢 SQL 看执行计划 (`EXPLAIN PLAN`)
> 4. 检查索引使用情况 + 统计信息新鲜度

### Q5: Oracle 的回收站是什么？

> `DROP TABLE` 不会物理删除，而是重命名放入回收站
> `FLASHBACK TABLE xxx TO BEFORE DROP` 恢复
> `PURGE RECYCLEBIN` 清空回收站

## 核心要点回顾

- Oracle = Instance + Database 分离架构（最核心差异）
- 一致性读 = UNDO + SCN（写不阻塞读的基石）
- RAC + Data Guard = Oracle 高可用核心（真正零数据丢失）
- AWR + ASH = 性能诊断双利器
- 面试关键是"差异思维"——能解释 Oracle 和 MySQL 为什么不同
