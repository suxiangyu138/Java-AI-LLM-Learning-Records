## 1. Untracked files 提示是怎么回事

- Git 初始化仓库后，工作区里原本就存在的文件一开始都是 **untracked**，意思是「Git 还没管它们」。 [stackoverflow](https://stackoverflow.com/questions/9663507/what-are-tracked-files-and-untracked-files-in-the-context-of-git)
- 只有执行了 `git add`（进入暂存区）或者 `git commit`（提交进历史）之后，这些文件才变成 tracked，后续修改才会被 Git 记录。 [blog.codecarrot](https://blog.codecarrot.net/what-is-difference-between-unstaged-and-untracked-file-in-git/)
- 你这次看到那一长串 Untracked files，只是 Git 在告诉你「这些文件从来没被提交过，你要不要让我开始管它们」。 [stackoverflow](https://stackoverflow.com/questions/9663507/what-are-tracked-files-and-untracked-files-in-the-context-of-git)

本次处理方式：

- 你决定把这个学习仓库的代码、笔记等全部纳入版本管理，然后在根目录直接用：`git add .` 把需要的文件全部交给 Git 跟踪。

## 2. LF will be replaced by CRLF 的 warning

- 这些 warning 都是类似：  
  `LF will be replaced by CRLF the next time Git touches it`。 [shazi](https://shazi.info/git-%E5%9C%A8-windows-%E9%80%B2%E8%A1%8C-add-%E5%87%BA%E7%8F%BE%E8%AD%A6%E5%91%8A%E3%80%8Cwarning-lf-will-be-replaced-by-crlf%E3%80%8D/)
- 含义：文件里当前是 LF 换行（类 Unix 风格），在 Windows 配置下 Git 可能会把工作区里的换行符转换为 CRLF，因此提前提示你。对代码本身没有本质破坏，只是换行符风格不同。 [stackoverflow](https://stackoverflow.com/questions/5834014/lf-will-be-replaced-by-crlf-in-git-what-is-that-and-is-it-important)
- 这类 warning 不会阻止提交，只是提醒，将来换行符可能自动转换。

本次处理方式：

- 你并没有被这些 warning 卡住，只是看到很多提示；我们选择「先不管它」，继续完成 add/commit。
- 后面如果需要，可以再通过 `core.autocrlf` / `core.safecrlf` 去精细控制，但对你当前个人学习仓库来说不关键。 [reddit](https://www.reddit.com/r/ObsidianMD/comments/1cl3686/solution_to_obsidian_git_warning_lf_will_be/)

## 3. 真正导致 git add 失败的错误

最后报错是：

```text
error: 'Java项目总结/简易 ATM 银行系统/' does not have a commit checked out
fatal: adding files failed
```

核心点：

- 这个目录里面之前单独执行过 `git init`，所以它自己就是一个小 Git 仓库（子仓库 / submodule）。 [blog.csdn](https://blog.csdn.net/jht2667796626/article/details/130505009)
- Git 发现子目录里有 `.git`，就当它是一个子仓库处理；但这个子仓库没有正常 checkout 的 commit，于是主仓库在 `git add .` 时失败。 [hrekov](https://hrekov.com/blog/git-main-does-not-have-commit-checked-out)
- 经验：一个项目目录里只应该有「一个」顶层 `.git`，子目录里不应该再有额外的 `.git`（除非你真的要用 submodule）。 [stackoverflow](https://stackoverflow.com/questions/56799562/git-submodule-add-error-does-not-have-a-commit-checked-out)

## 4. 你是怎么修复的（关键操作）

针对 `Java项目总结/简易 ATM 银行系统/`：

1. 找到这个子目录下面的隐藏 `.git` 目录（或者在子目录里 `git status`，确认它是一个单独仓库）。 [blog.csdn](https://blog.csdn.net/jht2667796626/article/details/130505009)
2. 删除这个子目录里的 `.git`（注意不是删除根目录的 `.git`），让它重新变成普通文件夹。可以命令行删，也可以资源管理器删。 [stackoverflow](https://stackoverflow.com/questions/56799562/git-submodule-add-error-does-not-have-a-commit-checked-out)
3. 回到总仓库根目录，重新执行 `git add .`，这时 Git 就会把 `简易 ATM 银行系统` 当成普通目录一起管理，不再当 submodule，错误消失。 [blog.csdn](https://blog.csdn.net/jht2667796626/article/details/130505009)

这一步的本质：**把「多余的子仓库」去掉，只保留最外层的一个仓库来统一管理所有学习项目。**

## 5. 这次操作带来的经验教训

- 一个学习总仓库（比如你现在的这个）里，所有项目/笔记都由「根目录」这个 Git 仓库统一管理，子目录不要再 `git init`。 [stackoverflow](https://stackoverflow.com/questions/56799562/git-submodule-add-error-does-not-have-a-commit-checked-out)
- 出现 `does not have a commit checked out` 这类错误，优先怀疑是否有子目录被单独 `git init`，检查并删除子目录里的 `.git`。这是以后遇到同类问题的通用解法。 [blog.csdn](https://blog.csdn.net/jht2667796626/article/details/130505009)
- 大量 `LF will be replaced by CRLF` 多半不是 bug，而是「换行符风格提醒」，除非出现 fatal 级别报错，否则可以先忽略。 [github](https://github.com/orgs/community/discussions/66838)
