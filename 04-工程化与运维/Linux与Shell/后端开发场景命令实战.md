# 后端开发场景命令实战（Java 后端版）

> **定位**：Java 后端开发真实场景 × 命令行解决方案
> **场景覆盖**：日志排查、端口冲突、服务器部署、性能诊断、数据库运维

## 场景一：线上日志紧急排查

### 问题：用户反馈订单创建失败

```bash
# 1. 实时看日志（先看清发生了什么）
tail -f /var/log/app/order-service.log

# 2. 过滤 ERROR + 前后 5 行上下文
tail -1000 /var/log/app/order-service.log | grep -B5 -A5 ERROR

# 3. 按时间范围截取日志
sed -n '/2024-06-15 14:30/,/2024-06-15 14:35/p' app.log | grep ERROR

# 4. 统计错误类型分布
grep ERROR app.log | awk -F': ' '{print $2}' | sort | uniq -c | sort -rn

# 输出示例：
#  45 NullPointerException at OrderService.createOrder
#  23 TimeoutException at PaymentGateway.pay
#   5 SQLException at OrderMapper.insert

# 5. 追踪一个请求的完整链路（假设 traceId 在日志中）
grep "traceId=abc123" app.log
```

### 日志切割与归档

```bash
# 按时间切割日志（配合 logback 滚动策略）
# 压缩 7 天前的日志
find /var/log/app/ -name "*.log" -mtime +7 -exec gzip {} \;

# 删除 30 天前的日志
find /var/log/app/ -name "*.gz" -mtime +30 -delete
```

## 场景二：端口冲突排查

### 问题：启动报错 "Address already in use: bind"

```bash
# 1. 看谁占了 8080
lsof -i :8080
# 输出：java  12345 root  150u  IPv6  ...  TCP *:8080

# 2. 杀掉
kill -9 12345

# 3. 或者找到所有占用 8080 的进程并杀掉
lsof -ti :8080 | xargs kill -9
```

```powershell
# Windows 版
netstat -ano | findstr :8080
# 输出：TCP  0.0.0.0:8080  0.0.0.0:0  LISTENING  12345
taskkill /PID 12345 /F
```

### 批量检查多个端口

```bash
for port in 8080 8081 9090 3306 6379; do
  if lsof -i :$port > /dev/null 2>&1; then
    echo "✅ $port: $(lsof -ti :$port)"
  else
    echo "❌ $port: 空闲"
  fi
done
```

## 场景三：服务器部署检查清单

### 部署前检查

```bash
# 1. 磁盘空间（确保 >20%）
df -h

# 2. 内存（确保 >1G 空闲）
free -h

# 3. CPU 负载
uptime
# 输出：14:30:00 up 30 days, 2:15, 3 users, load average: 0.50, 0.80, 0.60

# 4. 必要端口是否可用
for port in 8080 3306 6379; do
  nc -zv localhost $port
done

# 5. Java 版本
java -version

# 6. 环境变量
echo $JAVA_HOME
echo $SPRING_PROFILES_ACTIVE
```

### 部署后验证

```bash
# 1. 确认进程已启动
ps -ef | grep java | grep order-service

# 2. 确认端口已监听
ss -tunlp | grep 8080

# 3. 发一个健康检查请求
curl -s http://localhost:8080/actuator/health | python -m json.tool

# 4. 看启动日志最后 50 行
tail -50 /var/log/app/startup.log

# 5. 等 30 秒再确认
sleep 30 && curl -f http://localhost:8080/actuator/health || echo "启动失败!"
```

## 场景四：JVM 性能诊断

### 内存问题

```bash
# 1. 找到 Java 进程 PID
jps -l
# 输出：
# 12345 order-service.jar
# 12346 config-server.jar

# 2. 查看堆内存使用
jstat -gc 12345 1000 5
# S0C S1C S0U S1U  EC   EU   OC    OU    MC    MU
# S=Survivor, E=Eden, O=Old, M=Metaspace
# C=Capacity, U=Used

# 3. 堆转储（dump）
jmap -dump:format=b,file=heap_dump.hprof 12345

# 4. 查看 GC 情况
jstat -gcutil 12345 1000
# 关注 FGC（Full GC 次数）和 FGCT（Full GC 总时间）

# 5. 查看线程
jstack 12345 | grep -A10 "BLOCKED\|WAITING"
```

### 找内存最大的进程

```bash
ps aux --sort=-%mem | head -10
```

## 场景五：数据库相关

### MySQL 连接与查询

```bash
# 连接数据库
mysql -h localhost -u root -p mydb

# 执行一条 SQL（非交互）
mysql -u root -p mydb -e "SELECT COUNT(*) FROM orders WHERE status='PENDING';"

# 导出数据
mysqldump -u root -p mydb orders > orders_backup.sql

# 只导表结构
mysqldump -u root -p --no-data mydb > schema.sql

# 导入数据
mysql -u root -p mydb < orders_backup.sql
```

### Redis 连接与操作

```bash
# 连接
redis-cli -h localhost -p 6379

# 检查连通性
redis-cli ping  # 返回 PONG

# 查看 key 数量
redis-cli dbsize

# 查看内存
redis-cli info memory | grep used_memory_human

# 查看慢查询
redis-cli slowlog get 10

# 批量删除匹配的 key
redis-cli --scan --pattern "cache:user:*" | xargs redis-cli del
```

## 场景七：Git 应急操作

```bash
# 撤销最后一次 commit（保留改动）
git reset --soft HEAD~1

# 撤销最后一次 commit（丢弃改动）
git reset --hard HEAD~1

# 撤销某个文件的改动
git checkout -- src/file.java

# 临时保存当前改动
git stash
git stash pop

# 看某行代码是谁改的
git blame src/OrderService.java -L 100,120

# 找哪个提交引入了 bug
git bisect start
git bisect bad HEAD
git bisect good v1.0.0
# ... 二分法定位

# 合并冲突解决
git merge feature-branch
# 冲突后：
git diff --name-only --diff-filter=U  # 看哪些文件冲突
```

## 场景八：Docker 常用

```bash
# 查看运行中的容器
docker ps

# 查看所有容器（含已停止）
docker ps -a

# 查看容器日志
docker logs -f container_name --tail 100

# 进入容器
docker exec -it container_name bash

# 重启容器
docker restart container_name

# 清理资源
docker system prune -a         # ⚠️ 清理所有未使用资源
docker container prune          # 清理停止的容器
docker image prune              # 清理未使用的镜像

# Compose 操作
docker-compose up -d            # 启动
docker-compose down             # 停止并删除
docker-compose logs -f service  # 看某服务日志
docker-compose restart service  # 重启某服务
```

## 场景十一：日常效率脚本

### 一键启动开发环境

```bash
#!/bin/bash
# start-dev.sh
echo "启动 Redis..."
docker start redis-dev

echo "启动 MySQL..."
docker start mysql-dev

echo "等待服务就绪..."
sleep 5

echo "启动 SpringBoot..."
cd ~/project && mvn spring-boot:run
```

### 快速重启 SpringBoot 服务

```bash
#!/bin/bash
# restart-service.sh
SERVICE=$1
PID=$(ps -ef | grep "$SERVICE" | grep -v grep | awk '{print $2}')

if [ -n "$PID" ]; then
  echo "停止 $SERVICE (PID: $PID)"
  kill -15 $PID
  sleep 5
  # 还没死就强杀
  if ps -p $PID > /dev/null; then kill -9 $PID; fi
fi

echo "启动 $SERVICE..."
nohup java -jar "$SERVICE.jar" > /var/log/app/$SERVICE.log 2>&1 &
echo "完成"
```
