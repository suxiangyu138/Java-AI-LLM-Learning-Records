# 微服务核心知识点

## 一、微服务基础概念

### 1. 定义
将**单体应用**按**业务领域**拆分为多个**独立、轻量化、可独立部署**的小型服务，服务之间通过网络远程调用协作。

### 2. 单体 vs 微服务
- 单体：代码耦合高、扩容困难、上线风险大、技术栈单一
- 微服务：**低耦合、独立开发/部署/扩容、技术异构、容错隔离**

### 3. 核心特征
- 服务原子化、去中心化治理、独立数据库、轻量通信、持续交付

## 二、核心理论

### 1. 领域驱动设计 DDD
微服务拆分核心依据：
- 限界上下文：划分业务边界，决定服务范围
- 领域实体、聚合根、值对象
- 避免按技术层拆分，**按业务域拆分**

### 2. 架构演进
单体架构 → 垂直拆分 → 分布式SOA → **微服务架构**
- SOA：重ESB企业服务总线、中心化
- 微服务：去ESB、轻量化、去中心化

## 三、微服务核心组件栈（Spring Cloud 全家桶）
1. **服务注册与发现**
    - 作用：解决服务IP不固定、动态感知上下线
    - 组件：Nacos、Eureka、Consul
    - 核心：注册、续约、健康检查、下线剔除

2. **统一配置中心**
    - 作用：集中管理多环境配置、动态刷新、版本管控
    - 组件：Nacos、Apollo、SpringCloud Config

3. **远程调用**
    - 同步：OpenFeign（HTTP）、Dubbo（RPC）
    - 异步：消息队列
    - 核心：屏蔽网络调用细节，像调用本地方法一样调远程服务

4. **网关 Gateway**
    - 统一入口：路由转发、鉴权、限流、日志、跨域、灰度
    - 组件：Spring Cloud Gateway、Zuul
    - 位置：所有前端/外部请求统一经过网关

5. **熔断、降级、限流（服务容错）**
    - 熔断：依赖服务故障，快速断路，防止级联雪崩
    - 降级：非核心业务关停，保核心链路
    - 限流：控制QPS/并发，防流量击穿
    - 组件：Sentinel、Resilience4j

6. **分布式事务**
    微服务跨库跨服务必然出现数据一致性问题
    常见方案：2PC、TCC、本地消息表、可靠MQ、SAGA

7. **分布式锁**
    解决多服务共享资源并发竞争：Redis、Zookeeper实现

## 四、微服务通信模式
1. **同步调用**
    - HTTP/REST、RPC
    - 适用：实时查询、强交互场景
    - 缺点：耦合高、超时阻塞、级联故障

2. **异步调用**
    - 基于MQ：Kafka/RabbitMQ/RocketMQ
    - 优势：解耦、削峰、异步、消峰填谷
    - 适用：日志、通知、异步业务、最终一致场景

## 五、微服务关键问题与解决方案

### 1. 服务雪崩
- 成因：单个服务故障逐级传导，拖垮整条链路
- 解决：熔断、降级、隔离、超时控制、重试机制

### 2. 超时与重试
- 合理设置接口超时时间
- 幂等设计：防止重试导致重复业务

### 3. 幂等性
- 场景：接口重试、消息重复消费、网络重发
- 实现：唯一流水号、全局ID、状态机、唯一索引、分布式锁

### 4. 跨域问题
- 统一在网关层配置CORS，统一处理跨域

### 5. 链路追踪
- 作用：排查分布式调用链路异常、性能瓶颈
- 核心概念：Trace、Span、Context
- 组件：SkyWalking、Sleuth+Zipkin

### 6. 监控与告警
- 指标监控：CPU、内存、QPS、响应时间、异常率
- 组件：Prometheus + Grafana、Actuator

## 六、数据层设计
1. **数据隔离**
    - 原则：一服务一库/一服务多表，避免服务直连共享库
2. **读写分离**
    主库写入、从库查询，缓解数据库压力
3. **分库分表**
    应对大数据量、高并发存储瓶颈

## 七、微服务优缺点

### 优点
1. 业务解耦，单一服务职责清晰
2. 独立部署、迭代快、小版本风险低
3. 按需弹性扩容，资源利用率高
4. 支持多技术栈，团队独立开发

### 缺点
1. 架构复杂，运维、测试、排查成本大幅上升
2. 网络调用增多，延迟、超时、容错问题突出
3. 分布式事务、数据一致性难以保证
4. 依赖中间件：注册中心、网关、MQ、监控等

## 八、高频简答题速记
1. 微服务拆分原则：**按业务域、高内聚低耦合、单一职责、数据隔离**
2. 三大防护手段：**限流、降级、熔断**
3. 微服务核心三件套：**注册中心、配置中心、网关**
4. 同步用Feign/Dubbo，异步用MQ
5. 分布式问题：事务、幂等、雪崩、链路追踪
