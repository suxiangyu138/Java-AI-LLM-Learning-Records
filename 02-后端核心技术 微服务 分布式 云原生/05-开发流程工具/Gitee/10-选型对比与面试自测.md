## 1. 三平台选型对比总表

| 维度 | Gitee | GitHub | GitLab |
|------|-------|--------|--------|
| 定位 | 国内托管 + 合规信创 | 全球开源生态 | 企业一体化 DevOps |
| 国内网络 | 快 | 慢/不稳 | 一般 |
| 开源生态 | 国内为主 | 全球最大 | 中 |
| 免费 CI/CD | Gitee Go（200 分钟起） | Actions（2000 分钟/月私有） | 内置 Runner（有限） |
| 企业方案 | 私有化 + 信创 | Enterprise Cloud/Server | 自托管 CE/EE |
| 数据属地 | 中国 | 境外 | 自管 |
| AI | 模力方舟（本土化） | Copilot | Duo |
| 镜像能力 | Gitee ↔ GitHub 双向 | 无官方（第三方） | 仓库镜像支持 |
| 中文文档 | 原生 | 翻译 | 翻译 |

**结论**：没有"最好"，只有"匹配"——个人开源国际协作选 GitHub、国内团队选 Gitee（网络 + 合规）、一体化自托管选 GitLab、信创强制选 Gitee 私有化。多平台共存时用镜像同步衔接（03 篇）。

## 2. 选型决策树

```text
有信创/等保合规要求？ ── 是 → Gitee 企业版私有化部署
        │
        否 → 数据必须出境吗？ ── 否（可出境）→ 全球化协作 → GitHub
        │                              └ 国内为主 → Gitee
        └ 需要自托管完全掌控？ ── 是 → GitLab CE/EE 或 Gitee 私有化
```

三个判断维度按优先级：**合规（红线）→ 网络（体验）→ 生态（长期价值）**。个人项目没有合规压力，网络与生态是主要考量；企业项目先过合规红线再谈体验。

## 3. 国产替代场景：为什么与怎么做

国产替代（信创）驱动代码托管平台切换的核心原因：

- **政策要求**：党政/金融/国企关键系统要求国产化工具链，境外平台（GitHub/GitLab SaaS）不满足
- **数据安全**：源代码是核心资产，要求存储在中国境内、可审计、可留痕
- **供应链安全**：工具链全链路国产化，降低断供/制裁风险

迁移三步：**评估**（仓库清单、依赖关系、权限模型）→ **迁移**（导入/镜像，保留历史）→ **验证**（CI/CD 切换 Gitee Go、Webhook 重配、团队培训）。切换不是"换网址"，是**整个研发链路换底座**——CI、扫描、发布、通知都要跟着换。

## 4. 迁移实操清单

| 迁移项 | 操作 | 注意 |
|--------|------|------|
| 仓库历史 | 导入/镜像（2GB 限制） | 大仓库本地镜像迁移 |
| LFS 文件 | 单独传输 | 镜像不支持 LFS |
| 子模块 | 更新 .gitmodules 地址 | 内网地址变化 |
| CI/CD | 重写为 Gitee Go YAML | Actions 兼容，插件要换 |
| Webhook | 重配到 Gitee | 通知服务地址变更 |
| 保护分支 | 重建规则 | 门禁配置同步迁移 |
| 团队权限 | 重建成员/角色 | 无自动迁移 |
| 文档 | README/文档地址更新 | 引用旧地址的链接 |

**迁移纪律**：先在 Gitee 建镜像仓库验证流程（双跑期），稳定后再切换默认仓库——避免"搬家当天研发停摆"。

## 5. 落地避坑清单

| # | 坑 | 解法 |
|---|-----|------|
| 1 | 镜像双向同时提交丢代码 | 明确主从，从端不写 |
| 2 | Pages 提交即上线 | 免费版实名 + 审核，预留时间 |
| 3 | Actions 插件直接抄 | 插件不通用，找等价或改脚本 |
| 4 | 免费额度不够用 | 依赖缓存 + 条件触发 + 阶段跳过 |
| 5 | 密钥入库 | .gitignore 必配 + 已泄露即轮换 |
| 6 | 保护分支没配 | main 必须走 PR + 门禁 |
| 7 | API 批量操作被限流 | 控制频率，参考镜像 5 分钟间隔 |
| 8 | 导入后子模块失效 | 检查 .gitmodules 地址 |
| 9 | 文档链接还是旧地址 | 迁移后全局替换 |
| 10 | 忽略信创要求 | 政企场景先过合规红线再谈功能 |

## 6. 面试三范式

**价值式**：Gitee 解决什么问题？——国内网络 + 合规 + 信创三合一：GitHub 在国内不可靠且数据出境，Gitee 提供国内节点的托管与国产化 CI/CD，企业版私有化满足政企审计与信创要求。2026 年升级为"AI 驱动的工程效率基础设施"，模力方舟把 AI 生成/测试/检测融入研发流程。

**技术式**：核心机制？——镜像仓库（webhook 驱动、5 分钟间隔、LFS 不支持、双向丢码风险）、Gitee Go（与 Actions 兼容的 YAML、PR 门禁、制品不可变、多云发布）、保护分支 + 扫描 + 测试的质量门禁闭环、API v5 自动化。

**生产式**：你踩过什么坑？——镜像双向同步丢代码（必须主从）；Actions 插件不通用（迁移要重写）；密钥入库后删文件没用（必须轮换）；Pages 免费版实名审核延迟上线；免费额度用超（依赖缓存省 50%）。

**追问四连**：镜像同步的边界？Gitee Go 与 Actions 的差异？质量门禁怎么配？什么场景必须 Gitee 私有化？
