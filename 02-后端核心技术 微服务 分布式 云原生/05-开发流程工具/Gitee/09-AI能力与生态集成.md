## 1. 模力方舟：AI 战略全景

"模力方舟"是 Gitee 2025 年启动的 AI 战略，把 AI 能力融入开发各个环节：

```text
模力方舟 = MaaS 平台（Model-as-a-Service）+ 开发智能工具栈
├── AI 代码生成（写代码）
├── 测试路径推荐（测代码）
├── 漏洞检测（查代码）
└── Credits 配额制（企业版 500-1000/月）
```

核心认知：**Gitee 的 AI 不是"接入一个模型"，而是 MaaS 平台上构建的整体工具栈**——模型按需替换/升级，工具栈持续演进。这与 2026 年国产平台（火山方舟、百炼等）的 MaaS 思路一致：AI 能力平台化，应用层只管消费。

## 2. AI 代码生成：不是补全是理解

Gitee 的 AI 代码生成与普通补全工具的差异：

- **上下文语义理解**：不只按光标前文本续写，而是理解整个文件/项目的结构与语义
- **静态分析结合**：生成建议经过静态分析校验（语法、依赖、安全），减少"能跑但有问题"的生成
- **本土化训练**：基于海量开源项目数据训练专用模型，更懂中国开发者习惯（中文注释、常用框架写法、国内编码规范）

使用场景：函数级生成、单元测试生成、重复代码模式补全、注释文档生成。**边界**：AI 生成仍需人工审查——生成代码必须过 GiteeScan 与代码审查流程（07 篇的门禁同样适用）。实测中 AI 生成的代码两类问题最突出：**依赖幻觉**（引用不存在的库/API，编译期才能发现）与**安全盲区**（生成代码继承训练语料的旧漏洞模式）——这正是"生成后必须过扫描 + 编译 + 审查"三道关的原因，任何声称"生成即可用"的流程都是事故隐患。

## 3. 测试路径推荐与 AI 漏洞检测

- **测试路径推荐**：根据代码结构与改动，推荐测试路径/测试用例——覆盖"哪里改过、哪里可能受影响"的回归重点，与 GiteeTest 集成生成测试
- **AI 漏洞检测**：传统 SAST 按模式匹配，AI 检测结合上下文理解数据流与调用链，判断漏洞是否真实可达——减少误报、发现模式规则覆盖不了的逻辑漏洞

两者的定位都是**辅助人工**：AI 检测输出"建议人工确认"级别，测试推荐输出"建议执行的路径"，最终判断与执行还是人。**AI 质量能力的落地姿势 = 融入现有流水线**（Gitee Go 里作为一道扫描/测试阶段），而不是另起炉灶。

## 4. API v5：开放平台

Gitee 提供 RESTful API v5，是自动化的钥匙：

```text
API v5 覆盖：仓库/Issue/PR/成员/Webhook/镜像
鉴权：个人令牌（Authorization: Bearer token）
示例端点：
  GET  /api/v5/user                     用户信息
  POST /api/v5/user/repos               创建仓库
  GET  /api/v5/repos/{owner}/{repo}/issues   Issue 列表
  POST /api/v5/repos/{owner}/{repo}/hooks    Webhook
```

典型自动化场景：**镜像同步 webhook**（03 篇的 Payload URL 就是 API v5 端点）、**发布自动化**（CI 构建后调 API 创建 Release）、**数据导出**（Issue/PR 统计）、**团队治理**（批量创建仓库/权限设置）。限流注意：API 有速率限制，批量操作要控制频率（与镜像 5 分钟间隔同理）。

## 5. 本地工具链集成：Git 与 IDE

- **Git 客户端**：Gitee 完全兼容标准 Git 协议——任何 Git 客户端（VS Code、IntelliJ、SourceTree、TortoiseGit）都可以直接操作 Gitee 仓库，无需特殊插件
- **IDE 集成**：VS Code 的 Git 面板、IDEA 的 Git 集成天然支持；Gitee 的 IDE 插件（如 Gitee 扩展）提供 PR/Issue 的 IDE 内操作
- **命令行**：`git remote add origin git@gitee.com:user/repo.git` 之后一切照旧

**集成原则**：Gitee 是 Git 协议的托管实现，本地工具链零学习成本——这也是从 GitHub 迁移的心理成本极低的底层原因。

## 6. AI 生态与国产模型的关系

Gitee 的 AI 能力与国产大模型生态的关系：

- **MaaS 底座**：模力方舟的模型层可接入国产大模型（DeepSeek/Qwen/GLM 等），模型能力随生态升级
- **与 AI 开发工具体系互补**：Gitee 的 AI 聚焦"代码托管侧的开发智能"（生成/测试/检测），与 AI 编程助手（Copilot 类）和 AI 开发框架（LangChain 等）分工不同
- **企业版配额**：AI Credits 是使用门槛，政企购买企业版后可按需消费

关联体系：DeepSeek/Qwen 等模型 API 知识见"主流大模型API调用"目录；AI 工程化实践见 RAG/Agent 体系。**Gitee 的 AI 是"把模型能力变成研发流程的一部分"的落地形态**。

开发者最实际的用法：把 AI 能力当作研发流程的一档检查与辅助——生成代码过 GiteeScan、AI 检测输出人工确认、测试推荐进 GiteeTest 执行。**不要期待 AI 全自动**：模型输出有不确定性，代码托管场景（要进主干、要审计）必须以"人审 + 门禁"兜底。这个原则与 AI 时代所有生产系统的共识一致：AI 加速生成，人负责决策与质量。

对个人的落地方案：免费额度内先体验 AI 代码生成（写单元测试/重复代码最直观），在真实项目里跑一轮 GiteeScan + AI 检测对比误报率，再用 API v5 写一个自动化脚本（如 PR 标签自动打）——三条线分别对应 09 篇的 AI、07 篇的质量、04 篇的协作，串起来就是完整的"AI 辅助研发流程"实操。
