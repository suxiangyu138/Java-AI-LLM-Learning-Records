## 4. 与同级体系的定位分工

| 体系 | 定位 | 与 Gitee 的关系 |
|------|------|-----------------|
| Git 知识体系（13 篇） | Git 本身：对象模型/分支/命令 | Gitee 是 Git 协议的托管实现之一，底层一致 |
| GitHub 知识体系 | 全球最大托管平台 + 开源生态 | Gitee 的镜像同步对象、功能对标参照 |
| GitLab 知识体系 | 企业级一体化 DevOps 平台 | Gitee 企业版的主要国内竞品 |
| 本体系（Gitee） | 国内托管 + 信创合规 + 国产 CI/CD | 解决"国内网络 + 合规 + 国产化"场景 |

**一句话分工**：Git 是工具（学会用），GitHub 是生态（全球开源），GitLab 是企业一体化，Gitee 是**国内托管的合规选择**——代码托管在哪是次要的，Git 工作流是通用的；镜像同步让两平台共存。

## 7. 七大常见误区

1. **"Gitee 就是 GitHub 的中文版"**——定位不同：Gitee 强在合规/信创/国内网络，GitHub 强在开源生态与全球协作
2. **"代码放 Gitee 就安全"**——仍需 2FA + 保护分支 + 敏感信息检查（GiteeScan）
3. **"镜像同步是实时的"**——最小间隔 5 分钟、30 分钟超时、双向镜像有代码丢失风险
4. **"Gitee Go 语法要重新学"**——与 GitHub Actions 高度兼容，YAML 稍改即可迁移
5. **"Pages 随便发"**——免费版需实名认证，发布有内容审核
6. **"免费版功能全"**——镜像/Go/Pages 等高级能力企业版才完整
7. **"AI 能力就是代码补全"**——Gitee 的 AI 结合上下文语义 + 静态分析，覆盖测试推荐与漏洞检测
