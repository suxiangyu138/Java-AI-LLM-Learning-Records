## 1. 条款三要素框架

| 要素 | 含义 | 典型内容 |
|------|------|---------|
| Permissions（许可） | 授权做什么 | 商用、分发、修改、专利使用 |
| Conditions（条件） | 必须做什么 | 保留版权声明、注明修改、公开源码、声明专利 |
| Limitations（限制） | 不保障什么 | 免责声明（无担保）、商标不授权、责任限制 |

> 💡 用三要素拆解任何许可证（含非 OSI 条款）是通用技能：先找"可以做什么"，再看"必须做什么"，最后看"不保证什么"。

## 2. 宽松许可证：MIT / Apache-2.0 / BSD-3

### 2.1 MIT（最简）

| 要素 | 内容 |
|------|------|
| 许可 | 任意使用/复制/修改/合并/发布/分发/再许可/销售 |
| 条件 | 保留版权声明与许可文本（copies 或 substantial portions） |
| 限制 | 无担保（AS IS）、作者免责 |

一句话：**"随你怎么用，把版权声明带着就行。"**

### 2.2 Apache-2.0（宽松 + 专利）

| 要素 | 内容 |
|------|------|
| 许可 | 同 MIT + **显式专利授权**（第 3 条） |
| 条件 | 保留版权与 NOTICE 文件；**修改的文件需显著声明改动**（第 4b 条） |
| 限制 | 商标不授权（第 6 条）；专利报复条款（第 3 条） |
| 专利报复 | 使用者若起诉专利侵权，专利授权自动终止 |

一句话：**"MIT + 专利保护 + NOTICE 义务"**——企业开源首选。

### 2.3 BSD-3

| 要素 | 内容 |
|------|------|
| 许可 | 再分发与修改 |
| 条件 | 保留版权、条件、免责声明；**禁止用项目名背书衍生品**（第 3 条） |
| 限制 | 无担保 |

> 💡 BSD-2 只去掉了"禁止背书"条款；BSD-4 有争议的"广告条款"已被废弃（1999 年）——现在 BSD 默认指 3-Clause。

## 3. 弱著佐权：MPL-2.0 / LGPL

### 3.1 MPL-2.0（文件级）

| 要素 | 内容 |
|------|------|
| 许可 | 商用/分发/修改 |
| 条件 | **被修改的文件**（及其衍生文件）以 MPL 开源；未修改文件可用其他许可 |
| 限制 | 无担保；**不提供商标授权**（第 2.5 条） |
| 应用示例 | Firefox、LibreOffice |

一句话：**"改了哪个文件，哪个文件开源；其余随便。"**

### 3.2 LGPL（链接级）

| 要素 | 内容 |
|------|------|
| 许可 | 商用/分发/修改 |
| 条件 | 修改库本身需开源；**动态链接**的程序可闭源（库文件独立）；静态链接需提供重链接手段 |
| 限制 | 无担保 |
| 应用示例 | Linux 系统库（glibc 为 LGPL） |

> ⚠️ **面试高频坑**：LGPL 允许闭源 ≠ 免费改库——**改了库源码就必须开源库本身的修改**；闭源的只是"链接库的程序"。

## 4. 强著佐权：GPL-3.0 / AGPL-3.0

### 4.1 GPL-3.0（全项目传染）

| 要素 | 内容 |
|------|------|
| 许可 | 商用/分发/修改 |
| 条件 | **分发衍生作品必须整体以 GPL-3.0 开源**（第 5 条）；提供源码（对应源码条款，第 6 条）；保留版权声明 |
| 限制 | 无担保；专利报复条款（第 11 条，与 Apache 类似） |
| 传染边界 | "分发"（distribution）才触发；**内部使用不触发** |

| 边界场景 | 是否触发 GPL |
|----------|:---:|
| 内部使用（自用 SaaS） | ❌ |
| 闭源分发衍生品 | ✅ 违规 |
| 独立进程间通信（非衍生） | ❌（争议，通常不算） |
| 静态/动态链接 GPL 库 | ✅ 视为衍生 |

### 4.2 AGPL-3.0（网络著佐权）

| 要素 | 内容 |
|------|------|
| 与 GPL 差异 | 第 13 条：**通过网络提供服务的用户交互**视为"分发" |
| 触发场景 | SaaS 后端使用 AGPL 代码 → 必须开源提供服务**的完整衍生代码** |
| 适用 | 服务器端软件（防云服务商白嫖） |

> 🎯 **面试必答**："AGPL 与 GPL 的区别？"——GPL 只管"分发"（发软件包）；AGPL 把"通过网络提供服务"也算分发，堵住 SaaS 白嫖的洞。

## 5. 公有领域：Unlicense / CC0

| 条款 | 内容 |
|------|------|
| Unlicense | 放弃版权与相关权利；无条件允许使用 |
| CC0 | 同样放弃（含数据库权利声明） |

> ⚠️ 注意：Unlicense/CC0 的"放弃版权"在部分司法辖区（如 EU）有争议，法律上可能退化为宽松许可——非关键代码用 MIT 更稳妥。

## 6. 条款对比总表

| 许可证 | 商用 | 分发需开源 | 修改需声明 | 专利授权 | NOTICE/署名 | 传染级别 |
|--------|:---:|:---:|:---:|:---:|:---:|:---:|
| MIT | ✅ | ❌ | 仅版权声明 | ❌ | 版权声明 | 无 |
| Apache-2.0 | ✅ | ❌ | ✅ 显著声明 | ✅ 显式 | NOTICE | 无 |
| BSD-3 | ✅ | ❌ | 仅版权声明 | ❌ | 版权声明 | 无 |
| MPL-2.0 | ✅ | 修改文件级 | ✅ | 隐性 | 文件头 | 文件级 |
| LGPL | ✅ | 动态链接可闭源 | 改库需开源 | 3.0 ✅ | 库版权 | 链接级 |
| GPL-3.0 | ✅ | ✅ 全项目 | ✅ | ✅ | 版权+源码 | 全项目 |
| AGPL-3.0 | ✅ | ✅ 全项目+网络 | ✅ | ✅ | 版权+源码 | 全项目+网络 |
| Unlicense | ✅ | ❌ | ❌ | - | - | 无 |

## 7. 核心要点

> 🎯 **核心要点**：
> - 三要素拆解法（许可/条件/限制）可解任何许可证；
> - 宽松三兄弟差异：MIT 最简、Apache 加专利+NOTICE、BSD 加"禁背书"；
> - 弱著佐权：MPL 文件级、LGPL 链接级——库类项目的常见选择；
> - 强著佐权：GPL 分发触发、AGPL 网络触发（面试必考）；
> - 边界结论：**内部使用不传染，分发才传染**。
