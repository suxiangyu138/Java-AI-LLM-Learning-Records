## 1. 实战：Java 微服务 DevOps 三合一

```yaml
# .gitlab-ci.yml —— GitLab Flow + CI/CD + 安全门禁三合一
stages: [build, test, security, deploy]

workflow:
  rules:                                # MR-First 路由（04 篇）
    - if: '$CI_PIPELINE_SOURCE == "merge_request_event"'   # MR 跑测试+扫描
    - if: '$CI_COMMIT_BRANCH == "main"'                    # main 推送跑构建+部署
    - if: '$CI_PIPELINE_SOURCE == "schedule"'              # 定时跑回归

build:
  stage: build
  image: maven:3.9-eclipse-temurin-21
  script: mvn clean package -DskipTests
  artifacts: { paths: [target/*.jar], expire_in: 1 week }
  cache: { key: maven-$CI_COMMIT_REF_SLUG, paths: [.m2/repository] }

test:
  stage: test
  image: maven:3.9-eclipse-temurin-21
  needs: [build]                        # DAG（04 篇）
  script: mvn test
  artifacts:
    reports: { junit: target/surefire-reports/TEST-*.xml }   # 报告进 MR

sast:
  stage: security
  image: docker:27
  services: [docker:dind]
  script: docker run --rm $SECURE_ANALYZERS_PREFIX/semgrep:latest analyze .  # 或官方 SAST 模板
  rules:
    - if: '$CI_PIPELINE_SOURCE == "merge_request_event"'
    - when: never

deploy:
  stage: deploy
  image: alpine:3
  needs: [test]
  script:
    - echo "部署到 pre-production（GitLab Flow 环境分支，06 篇）"
  environment: pre-production
  rules:
    - if: '$CI_COMMIT_BRANCH == "main"'
```

**验收三问**：① 开 MR → MR 流水线自动跑（test + sast，报告内嵌 MR 页面）；② 合并到 main → 部署流水线触发（environment 标记 pre-production）；③ 代码故意加一个注入漏洞 → **SAST 扫描出 critical，MR 被安全门禁阻止合并**（07 篇门禁生效）；**验收四问（加试）**：④ 推 feature 分支 → 只有 MR 流水线跑（workflow rules 路由正确，部署不触发）——"路由正确性验证"。（真实项目建议 `deploy` 加 `needs: [test, sast]`——**部署等安全扫描完成，门禁在流水线内的顺序保障**。）

## 2. 生产纪律清单

- **分支纪律**：main 保护 + MR 必开 + Approval 规则（Code Owners 关键路径）；
- **MR 纪律**：Draft 未完成不合并；合并后删源分支；Issue 关联 Closes；
- **流水线纪律**：rules 不用 only/except；artifacts 配 expire_in；cache 绑锁文件；
- **密钥纪律**：Masked + Protected 双开；Secrets Manager/KMS 合规组织；
- **安全纪律**：SAST/依赖扫描每 MR 必跑；门禁只卡新引入漏洞；
- **制品纪律**：SHA 精确 tag；清理策略先保留规则后自动清理；
- **升级纪律**：先备份再升级；不跳大版本；测试环境先升；
- **备份纪律**：数据 + gitlab-secrets.json 两件套；异地存放；季度演练；
- **监控纪律**：磁盘 80% 告警；Sidekiq 队列三看；
- **版本纪律**：GitLab 19.2.x 锁版本，升级看 release notes；
- **AI 纪律**：Duo 生成的代码/流水线必须人 review（AI 审计事件留痕）。

## 3. 报错速查十条

| 报错/现象 | 原因 | 修复 |
|------|------|------|
| Pipeline 一直 pending | 没有匹配的 Runner（tags 不匹配/无 Runner） | 查 Runner 注册与 tags（05 篇） |
| Job 卡在 "Preparing" | Runner 拉镜像慢/网络 | 看 Runner 日志；镜像预热（05 篇） |
| 404 访问项目 | 权限不足/项目私有 | 组权限检查（02 篇） |
| git push 被拒 | 分支保护（main 直推被拒） | 开 MR 走评审（02/06 篇） |
| HTTPS push 认证失败 | 密码被禁，需 Token | Personal Access Token（02 篇） |
| CI 里 docker 命令不存在 | executor 没配 Docker | Docker executor/DinD（05 篇） |
| artifacts 找不到 | 前序 job 没配 paths/expire 过期 | artifacts paths 配置（03 篇） |
| 合并被阻止（Pipeline failed） | 测试失败/门禁拦截 | 看 MR 的流水线结果与扫描报告（06/07 篇） |
| 磁盘满 GitLab 只读 | 容量告警没配 | 清理制品/镜像 + 扩容（08/09 篇） |
| 升级后登录失效 | gitlab-secrets.json 丢失 | 恢复 secrets 文件（09 篇） |

**三层定位方法论**（GitLab 场景）：**先查 Runner（有没有匹配的/活不活）→ 再查流水线（rules 是否放行）→ 最后查脚本（命令是否可用）**——**环境类错误（Runner/版本）占一半**，先排查。

## 4. 面试三范式

**范式一：价值式**——"我落地了团队的 GitLab DevOps 平台：MR 流水线自动化（测试 + 安全扫描内嵌 MR），发布从手动 1 小时降到自动 10 分钟，安全门禁拦截了 3 次高危合并"——**用自动化收益与事故拦截讲价值**（10 篇实战）。

**范式二：技术式**——"GitLab 的 MR-First 三件套（merge request pipelines/merged results/workflow rules）让'测试与评审同处一屏'；needs DAG 把流水线墙钟时间降 40%；CI/CD Components 把 30 个服务的构建逻辑收敛到一个公共组件"——**展示流水线编排深度**（03/04 篇）。

**范式三：生产式**——"自托管运维的纪律：备份两件套（数据 + secrets）异地 + 季度演练；月度升级不跳版本；磁盘 80% 告警；Runner 与 GitLab 分机"——**展示运维意识**（09 篇）。

**追问四连防身**：①"GitLab CI 与 Jenkins 怎么选？"——**新项目 GitLab CI（代码即流水线、MR 闭环），存量 Jenkins 渐进迁移**（03 篇）；②"CI 里密钥怎么管理？"——**Masked + Protected 变量，合规组织 Secrets Manager/KMS**（07 篇）；③"流水线怎么提速？"——**needs DAG 并行、cache 绑锁文件、parallel 分片、Runner 扩容**（04/05 篇）；④"安全门禁怎么落地？"——**SAST/依赖扫描每 MR + Security Approval Policies 只卡新引入高危**（07 篇）；⑤"自托管挂了怎么办？"——**备份两件套 + 恢复演练 + 磁盘/队列监控——先备份再谈高可用**（09 篇）。

## 5. 简历呈现

**项目写法示例**："基于 GitLab 19.x 搭建团队 DevOps 平台：GitLab Flow 环境分支 + MR 强制评审（Approval + Code Owners）；CI/CD 流水线全自动化（build/test/security/deploy 四阶段，needs DAG 提速 40%，CI/CD Components 统一 30 服务构建逻辑）；SAST/依赖扫描内嵌 MR + 安全门禁拦截高危合并；制品走 Container Registry（SHA 精确 tag 可回滚）；自托管运维（备份两件套 + 月度升级 + 磁盘监控）——发布耗时 60 分钟 → 10 分钟，高危漏洞合并 0 起"——**要点：版本精确、流程完整、数字量化、安全与运维双维**。**一页纸速查**：五域/流水线四件套（stages/artifacts/rules/needs）/Runner 三类型/MR 八状态/门禁三纪律——**面试前过一遍**。
