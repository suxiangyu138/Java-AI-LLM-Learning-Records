## 4. 核心概念速查

| 概念 | 一句话定义 | 关键事实（2025-2026） |
|------|-----------|---------------------|
| 消息队列（MQ） | 生产-消费之间的异步缓冲通道 | 三大价值：解耦/异步/削峰 |
| Topic（主题） | 消息的逻辑分类 | 所有中间件的核心抽象 |
| 分区/队列 | 并行度的物理单位 | Kafka 分区、RocketMQ 队列 |
| 消费组 | 一组协同消费的消费者 | 分区在组内分配（不重复消费） |
| 投递语义 | 消息最多/至少/恰好一次 | 实际工程以至少一次 + 幂等为主 |
| ACK | 消费确认（成功/失败） | 失败重投 → 幂等成为必需品 |
| 顺序消息 | 消息按序消费 | 分区级顺序是现实折中 |
| 延迟消息 | 指定时间后才可消费 | RocketMQ 5.x 时间轮任意精度 |
| 死信队列（DLQ） | 消费失败消息的收容所 | 监控与人工处理的入口 |
| ISR | 同步副本集合 | acks=all 的可靠性基础 |
| KRaft | Kafka 的 Raft 元数据协议 | 4.0 起移除 ZooKeeper |
| 存算分离 | 计算与存储独立扩展 | RocketMQ 5.x / Pulsar 架构 |
| 事务消息 | 两阶段提交的消息 | Half message + 回查 |

> 🎯 **核心要点**：消息队列的全部理论围绕三个问题——**怎么保证不丢（可靠性）、怎么保证顺序（有序性）、怎么保证不重复消费（幂等）**。没有任何中间件同时完美解决三者：工程现实是"至少一次投递 + 消费端幂等 + 分区级顺序"。2025-2026 的生态主线是云原生化（KRaft 去 ZooKeeper、存算分离、Serverless）。
