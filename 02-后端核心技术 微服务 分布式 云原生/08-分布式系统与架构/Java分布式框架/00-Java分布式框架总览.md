## 3. 与主体系的分工

**与 Spring Cloud 全家桶的分工**：Spring Cloud Gateway/Feign/LoadBalancer/Config/Stream（`../../Spring组件汇总/Spring Cloud 微服务全家桶（分布式）/`）与 Spring Cloud Alibaba（Nacos/Sentinel/Seata）都各有专精体系——**本体系讲"Spring Cloud 之外的另一半"**：Dubbo、gRPC、ZooKeeper、Redisson、XXL-Job 等非 Spring 系框架，以及**跨体系的选型全景**（09 篇）——"**Spring Cloud 体系讲'全家桶怎么用'，本体系讲'分布式框架地图怎么选'**"。

**与分布式系统理论（`../分布式系统理论/01-分布式基础理论.md`）、分布式系统（`../分布式系统/01-分布式理论基石-CAP-BASE-一致性.md`）的分工**：理论体系讲 CAP/一致性协议（Paxos/Raft/ZAB）的**原理**，**本体系讲"原理的框架实现"**——ZK 是 ZAB 的工程实现、etcd 是 Raft 的工程实现、Redisson 是 Redis 锁的工程实现——"**理论看理论体系，框架看本体系，两册对照读**"。

**与雪花算法（`../雪花算法/00-雪花算法知识体系总览.md`）的分工**：分布式 ID 是七大件之外的第零件（各框架都依赖）——**ID 生成看雪花算法体系，本体系只在使用处引用**（任务调度幂等/防重表唯一键）。

**与消息队列（`../../03-消息队列/`）的分工**：消息队列是分布式系统的"异步总线"，**本体系聚焦"同步调用与协调"**（RPC/锁/事务/调度）——"**同步走 RPC，异步走 MQ，两套体系各管一半**"。

**2026-08 基线**：**Dubbo 3.2.20**（Triple 协议 = HTTP/2 + gRPC 完全兼容，支持四种流式/TLS/背压；主流组合 Dubbo3 + Spring Boot 3 + JDK 17/21，**Nacos 逐渐取代 ZooKeeper 作注册中心**，K8s + Proxyless Mesh 云原生方向）；**Redisson 4.6.1**（2026-06-18，双线 3.x/4.x 并存，锁家族 Lock/FairLock/MultiLock/RedLock/ReadWriteLock/Semaphore）；**ZooKeeper 仍是金融级强公平锁与协调的事实件**（Curator 封装）；**etcd（Raft）是 K8s 生态的强一致选择**（Java 客户端生态不成熟）；**任务调度三强**：XXL-Job（~23.4k stars，集中式 + DB 锁，务实默认）、Elastic-Job（Apache ShardingSphere 子项目，ZK 去中心化强分片）、PowerJob（无锁乐观锁 + 时间轮毫秒级精度 + DAG 编排，2020 后新一代）——"**Java 分布式框架的 2026：Dubbo 稳、Redisson 快、ZK 老而弥坚、XXL-Job 务实、云原生在路上**"。

## 6. 常见误区

**误区一：分布式框架 = Spring Cloud**——Spring Cloud 是生态之一，**Dubbo/gRPC/ZK/Redisson/XXL-Job 是另一大半**——"Spring Cloud 讲全家桶，本体系讲地图"（00 篇分工）。

**误区二：Redis 锁就是 setnx 两步**——**原生 Redis 锁不推荐生产**（无续期/无公平/主从切换丢锁）——**Redisson 的看门狗与可重入才是生产姿势**（04 篇）。

**误区三：ZooKeeper 过时了**——**ZK 在强公平锁/金融级协调仍是事实件**（Curator 封装成熟）；Nacos 是注册中心的主流化，ZK 不是淘汰是退场到专业场景（03 篇）。

**误区四：分布式事务都要上 Seata**——**大部分"伪分布式事务"用 Outbox/本地消息表更合适**——"**能异步解决的别上强一致，能本地消息解决的别上全局事务**"（05 篇）。

**误区五：任务调度就是 Quartz 集群**——**Quartz 集群是 DB 锁 + 无控制台**，XXL-Job/PowerJob 才是 2026 工程选择——"**Quartz 是单机时代的遗产，分布式调度看三强**"（07 篇）。

**误区六：一致性哈希是哈希取模**——**取模扩容全量迁移，一致性哈希只迁 1/n**——"**取模是静态寻址，一致性哈希是动态寻址**"（06 篇）。

**误区七：框架越多越分布式**——**每加一个框架加一个故障点**（如 ElasticJob 的 ZK 依赖）；**2026 的实践是"能少则少、能整合则整合"**（09 篇演进路径）。
