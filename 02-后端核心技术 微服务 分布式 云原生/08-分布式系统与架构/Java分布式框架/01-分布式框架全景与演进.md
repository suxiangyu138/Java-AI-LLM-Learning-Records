## 1. 七大件：分布式系统的问题清单

**分布式系统本质是"多台机器协作解决一个问题"，协作中冒出的每个问题都催生了一类框架**——先列问题清单，再对号入座：

**问题一：怎么调用**（服务在别的机器上）→ **RPC 框架**（Dubbo/gRPC，02 篇）；**问题二：怎么找到服务**（机器地址会变）→ **注册中心**（ZooKeeper/etcd/Nacos，03 篇）；**问题三：怎么互斥**（多机器抢同一资源）→ **分布式锁**（Redisson/ZK/etcd，04 篇）；**问题四：怎么保证一致性**（跨库写入）→ **分布式事务**（Seata/Outbox，05 篇）；**问题五：怎么寻址**（数据分到哪台机器）→ **一致性哈希**（06 篇）；**问题六：怎么定时执行**（任务要跑在多机上还不重复）→ **任务调度**（XXL-Job/PowerJob，07 篇）；**问题七：怎么限流降级**（流量洪峰打垮服务）→ **限流降级框架**（Sentinel/Resilience4j，08 篇）。**"七大件 + 分布式 ID（雪花算法体系）"是分布式系统的完整问题清单**——"**先知道问题是什么，才知道框架在解决什么**"。

## 2. 演进史：从 EJB 到云原生

**Java 分布式框架的演进是一部"从重到轻、从私有到标准"的历史**：

**第一代（2000s）**：**EJB**——重量级分布式组件（CORBA/RMI），配置地狱，被 Spring 替代；**第二代（2010s 上半）**：**Dubbo（2011 开源）**与 **Spring Cloud（2014）**双雄——**Dubbo 走 RPC 高性能路线（服务治理），Spring Cloud 走 HTTP REST 标准路线（生态全）**——"**Dubbo 快在协议，Spring Cloud 赢在标准**"；**第三代（2010s 下半）**：**Spring Cloud Alibaba**（Nacos/Sentinel/Seata）补齐中文生态、**gRPC（Google，HTTP/2 + protobuf）**成为跨语言标准；**第四代（2020s）**：**云原生**——K8s 提供服务发现/负载均衡基础设施，**Dubbo 3 的 Proxyless Mesh、Spring Cloud 的 K8s 原生集成**——"**云原生时代，'框架的功能'部分被 K8s 收编，框架退到'业务协议与治理'层**"。

**演进主线一句话**："**从 EJB 的'重'到 Dubbo 的'快'，从 Spring Cloud 的'全'到云原生的'省'——框架在变，问题清单没变**"。

## 3. 2026 现状与版本基线

**2026-08 关键版本**：**Dubbo 3.2.20**（3.x 主线稳定迭代，Triple 协议 + 云原生方向）；**Redisson 4.6.1**（2026-06-18，3.x/4.x 双线——**4.x 是新的 Java 17+/Spring Boot 4 兼容主线，老项目 3.x 继续维护**）；**ZooKeeper 3.9.x**（维护期，Curator 封装成熟）；**etcd 3.5.x**（K8s 配套）；**XXL-Job 2.4.x**（23.4k stars 社区活跃）；**Nacos 3.x**（2026 注册中心主流，专精体系交叉）。

**四个 2026 趋势**：其一，**注册中心迁移潮**——**Nacos 取代 ZooKeeper 成为 Java 服务注册主流**（更轻、CP/AP 可切、配置中心一体）——"**ZK 退到强一致协调场景**"；其二，**协议融合**——**Dubbo 3 的 Triple 与 gRPC 兼容**（HTTP/2 一统）——"**协议在收敛，多语言互调成本在下降**"（Rust 的 Rubbo 0.1.0 已可与 Java Dubbo 互调）；其三，**锁与协调的 Redis 化**——**Redisson 把锁/信号量/限流全塞进 Redis**（性能毫秒级）——"**Redis 从缓存变成'分布式原语平台'**"；其四，**云原生收编**——K8s 的 Service/DNS 承担了部分注册发现职能，**框架与 K8s 双轨并存**（09 篇演进路径）；其五，**可观测化**——链路追踪/指标埋点成为框架标配（Dubbo 的 Tracing 集成、Redisson 监控、XXL-Job 看板）——"**框架从'只管功能'到'功能 + 可观测一体'**"（日志监控指标体系交叉：`../../07-工程运维基础/运维/日志监控指标/`）。

## 4. 框架生态全景图

```text
问题           → Java 框架（2026 默认 → 备选）
RPC 调用      → Dubbo 3（Triple）→ gRPC/Spring Cloud OpenFeign
注册与发现    → Nacos → ZooKeeper/etcd/Consul
分布式锁      → Redisson → ZooKeeper(Curator)/etcd
分布式事务    → Seata → Outbox/本地消息表/事务消息
一致性哈希    → Redis Cluster slot / 自研代理
任务调度      → XXL-Job → ElasticJob/PowerJob
限流降级      → Sentinel → Resilience4j/Redis 令牌桶
分布式 ID     → 雪花算法（专精体系）
链路追踪      → Micrometer Tracing → SkyWalking/Zipkin（日志监控体系）
```

**读图方法**：**每行是一个问题的答案集**，**第一列是 2026 务实默认**——"**选型不是'哪个最好'，是'每个问题选一个默认，组合起来还要能协同'**"（09 篇整合）。

## 5. 三条技术栈

**2026 年 Java 分布式的主流组合有三套**：

**栈一：Dubbo 栈**——**Dubbo 3 + Nacos + Redisson + XXL-Job**——RPC 高性能、中文生态成熟、**内部服务间调用性能优先**——"**Dubbo 栈适合'服务多、调用密'的业务系统**"。

**栈二：Spring Cloud 栈**——**Spring Cloud + Nacos + Sentinel + Seata**（全家桶专精体系）——HTTP 标准、生态全面、**与 Spring 生态无缝**——"**Spring Cloud 栈适合'生态优先、团队 Java 标准'的系统**"（Feign 走 HTTP 与 Dubbo 二进制协议相比性能有差距，但生态与开发效率胜出——"**快与省事的经典取舍**"）。

**栈三：云原生栈**——**K8s（Service/Ingress）+ gRPC + etcd + Istio（可选）**——基础设施替框架干活、跨语言、**2026 新系统的方向**——"**云原生栈适合'新绿地 + 多语言 + K8s 已就位'的系统**"。

**三栈不是竞争是阶段**：**存量 Dubbo/Spring Cloud 迁移云原生是渐进过程**——"**先跑通 K8s 部署，再逐步收编服务发现，最后看要不要上 Mesh**"（09 篇演进路径）。

## 6. 边界：本体系与专精体系

**本体系是"地图与整合层"，专精体系是"单件深潜层"**——分工规则：**Nacos/Sentinel/Seata 见 Spring Cloud Alibaba 专精体系**（`../../Spring组件汇总/Spring Cloud 微服务全家桶（分布式）/Spring Cloud Alibaba（阿里实现，属于 Spring Cloud 生态实现）/`），**Gateway/Feign/LoadBalancer 见 Spring Cloud 专精体系**，**雪花 ID 见雪花算法体系**，**MQ 见消息队列体系**，**链路追踪见日志监控指标体系**（`../../07-工程运维基础/运维/日志监控指标/`）——**本体系只讲"专精体系之外的框架"（Dubbo/gRPC/ZK/Redisson/XXL-Job/一致性哈希）+ 全图选型**（09 篇）——"**专精体系教你'一件用透'，本体系教你'七件配齐'**"。
