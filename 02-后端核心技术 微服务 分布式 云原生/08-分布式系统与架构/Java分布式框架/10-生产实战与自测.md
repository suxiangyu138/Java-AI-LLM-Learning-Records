## 1. 实战：库存扣减三合一

```java
// 场景：下单扣库存 —— 分布式锁（防超卖）+ 幂等（防重复扣）+ 调度（对账兜底）
@Service
public class StockService {

    @Autowired private RedissonClient redisson;
    @Autowired private JdbcTemplate jdbc;

    // ① 幂等入口：防重表（05 篇）——重复请求号直接返回已处理
    public Result deduct(String requestId, Long skuId, int qty) {
        Integer dup = jdbc.queryForObject(
            "SELECT COUNT(*) FROM idem WHERE request_id = ?", Integer.class, requestId);
        if (dup > 0) return Result.already();

        // ② 分布式锁：Redisson 可重入 + 看门狗（04 篇）
        RLock lock = redisson.getLock("stock:" + skuId);
        lock.lock();                                        // 不传超时 → 看门狗续期
        try {
            // ③ 原子扣减（数据库原子操作优先于锁，06 篇）
            int affected = jdbc.update(
                "UPDATE stock SET stock = stock - ? WHERE sku_id = ? AND stock >= ?",
                qty, skuId, qty);
            if (affected == 0) return Result.outOfStock();
            // ④ 写防重表（与扣减同事务——或 Outbox 落消息，05 篇）
            jdbc.update("INSERT INTO idem(request_id, sku_id) VALUES(?, ?)", requestId, skuId);
            return Result.ok();
        } finally {
            lock.unlock();                                  // 必须释放
        }
    }

    // ④ 对账任务：XXL-Job 定时扫描防重表与订单表差异（07 篇）
    @XxlJob("stockReconcileJob")
    public void reconcile() {
        // 查"有订单无防重记录"的异常单 → 人工补偿队列
    }
}
```

**验收三问**：① 并发压测 100 线程扣同一 SKU，**库存不为负**（锁 + 原子 SQL 生效）；② 同一 requestId 重复提交 N 次，**只扣一次**（防重表生效）；③ 模拟"扣减成功但消息丢失"，**对账任务能找出差异**（调度兜底生效）。

## 2. 生产纪律清单

- **锁纪律**：finally 必释放；持锁代码最短；非幂等不开 failover 重试（02/04 篇）；
- **幂等纪律**：写接口默认幂等（唯一键/防重表/状态机三选一）；
- **事务纪律**：能异步的别强一致；Outbox 是默认，Seata 有理由才上；
- **调度纪律**：任务代码幂等；调度中心 ≥ 2 节点；失败必告警；
- **注册中心纪律**：≥ 3 节点；客户端本地缓存；发布先摘流量（03 篇）；
- **限流纪律**：限流值来自压测；熔断必须配降级；规则可热更；
- **版本纪律**：Dubbo 3.2.x/Redisson 4.x/XXL-Job 2.4.x 锁版本，升级看 CHANGELOG；
- **故障预案**：注册中心挂/锁服务挂/调度中心挂——各写一页预案 + 演练。

## 3. 报错速查十条

| 报错/现象 | 原因 | 修复 |
|------|------|------|
| RPC 超时（Dubbo timeout） | 慢接口/网络抖动/超时设置太小 | 方法级超时分级；非幂等关重试（02 篇） |
| 锁获取失败/锁提前释放 | TTL 太短/没看门狗/业务超时 | 不传超时用看门狗；持锁代码缩短（04 篇） |
| 库存扣成负数 | 原子 SQL 没写 stock >= qty 条件 | UPDATE ... AND stock >= ?（06 篇） |
| 重复扣款/重复下单 | 重试没幂等 | 防重表/唯一键（05 篇） |
| 注册中心连不上业务全挂 | 无本地缓存兜底 | 启动全量拉取 + 增量监听（03 篇） |
| ZK 会话过期节点全没 | 网络抖动/超时太短 | sessionTimeout 10-30s；Curator 处理（03 篇） |
| 任务重复执行 | 阻塞策略没配/任务不幂等 | 串行策略 + 任务幂等（07 篇） |
| 任务丢失不跑 | 调度中心单节点挂了 | 调度中心 ≥ 2 节点（07 篇） |
| 限流不生效（多实例） | 本地限流当分布式用 | 网关/Redis 统一计数（08 篇） |
| 熔断后全是失败 | 熔断无降级兜底 | 降级数据（缓存/默认值）（08 篇） |

## 4. 面试三范式

**范式一：价值式**——"我负责的库存系统并发 5000 QPS：Redisson 锁 + 原子 SQL 保证零超卖，防重表保证零重复扣款，XXL-Job 对账兜底月差异率为零"——**用并发量/零事故讲价值**（10 篇实战）。

**范式二：原理式**——"分布式锁的三硬性要求（互斥/防死锁/防误删），Redisson 的 Lua 原子 + 看门狗续期；ZK 锁的临时有序节点排队——公平性换性能；一致性哈希的虚拟节点治倾斜，Redis Cluster 的 16384 槽是槽化实现"——**展示原理深度**（04/06 篇）。

**范式三：架构式**——"选型三栈：我们 Dubbo + Nacos + Redisson + XXL-Job；每加一个框架我写'挂了怎么办'预案，注册中心挂有本地缓存、锁服务挂有对账兜底"——**展示架构思维与预案意识**（09 篇）。

**追问四连防身**：①"Redis 锁挂了怎么办？"——**锁服务不可用 = 降级为不互斥（允许短暂超卖）+ 对账兜底**——预案先行（09 篇）；②"为什么不直接用数据库行锁？"——**持锁期间不能做远程调用，长事务拖垮连接池**；原子 UPDATE 能解决的不用锁（04/06 篇）；③"Seata 与 Outbox 怎么选？"——**能异步别强一致：Outbox 降级为本地事务 + 重试，Seata 留给真强一致**（05 篇）；④"任务重复执行怎么办？"——**调度框架保证'会跑'不保证'只跑一次'；幂等是任务代码的责任**（07 篇）。

## 5. 简历呈现

**项目写法示例**："基于 Dubbo 3 + Nacos + Redisson 构建库存扣减服务（峰值 5000 QPS）：Redisson 可重入锁 + Lua 原子扣减保证零超卖；防重表 + 请求号幂等保证重复请求零重复扣款；XXL-Job 定时对账 + 差异补偿兜底（月差异率 0）；Sentinel 接口限流 + 熔断降级（压测定阈值、Nacos 热更规则）"——**要点：框架版本精确、并发量化、三层防线（锁/幂等/对账）清晰**。
