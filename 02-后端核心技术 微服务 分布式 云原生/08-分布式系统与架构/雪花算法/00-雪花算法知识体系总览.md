## 4. 核心概念速查

| 概念 | 一句话定义 | 关键事实（2025-2026） |
|------|-----------|---------------------|
| 雪花算法 | 64 位趋势递增分布式 ID | Twitter 2010；1+41+10+12 |
| 位结构 | 符号+时间戳+机器+序列 | 4096 ID/ms/生成器 |
| 时钟回拨 | 系统时钟后退（NTP 等） | 雪花的核心风险 |
| 趋势递增 | 时间有序（B-tree 友好） | 索引/分页优势 |
| 变体家族 | Discord/Instagram/Sonyflake 等 | 仅位分配不同 |
| 号段模式 | DB 批量分配 ID 段 | 美团 Leaf 双缓冲 |
| UUIDv7 | 128 位时间有序 ID（RFC 9562） | **2025-2026 新默认** |
| RFC 9562 | UUID 新标准（2024-05） | v6/v7/v8 标准化 |
| Java 26 | 原生 UUID.ofEpochMillis() | 官方支持 UUIDv7 |
| PG 18 | 原生 uuidv7() 函数 | 数据库侧生成 |
| JS 精度 | 64 位 ID 超 2⁵³ | 前端需字符串 |
| 未来时间借取 | 回拨时借未来时间戳 | 百度 UidGenerator |

> 🎯 **核心要点**：雪花算法 = "时间戳 + 机器号 + 序列号"拼出的 64 位趋势递增 ID——本地生成（零协调）、时间有序（索引友好）、性能极高。两大软肋：**时钟回拨**（可能重复/乱序）与 **64 位超 JS 安全整数**。2025-2026 的最大变化：**UUIDv7（RFC 9562）成为分布式表的新默认**（128 位、零协调、时间有序、原生支持），雪花退居"64 位预算"场景。选型的核心权衡：64 位紧凑 vs 128 位零协调。
