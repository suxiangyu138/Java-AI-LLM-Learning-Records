## 1. 与其他模块的集成地图

```text
                  spring-jdbc（数据访问模板层）
        ┌──────────┬──────────┬──────────┬──────────┐
        ↓          ↓          ↓          ↓          ↓
  spring-core  spring-beans  spring-tx  spring-orm   Spring Boot
  Resource     配置/注入     DataAccess   JPA/        starter-jdbc
  (SQL 脚本)    JdbcTemplate  Exception  Hibernate   自动装配
                Bean 装配     族定义      (JPA 3.2)   DataSource/模板
```

| 联动点 | 机制 | 说明 |
|--------|------|------|
| jdbc ↔ tx | `DataSourceTransactionManager` + `org.springframework.dao` 异常族 | 事务与异常契约都在 tx，jdbc 是实现者 |
| jdbc ↔ core | `Resource`/`EncodedResource` 加载 SQL 脚本、编码处理 | `ResourceDatabasePopulator` 执行 DDL |
| jdbc ↔ beans | `JdbcTemplate` 作为 Bean 注入、属性填充 | 模板本身是普通 Bean |
| jdbc ↔ orm | `DataSource` 共享 + `PersistenceExceptionTranslator` 统一翻译 | JPA/MyBatis 同一连接事务 |
| jdbc ↔ Boot | `DataSourceAutoConfiguration` / `JdbcTemplateAutoConfiguration` / `JdbcClientAutoConfiguration` | Boot 4 全自动装配（见第 2 节） |

> 🎯 **核心要点**：spring-jdbc 是"模板层"不是"框架层"——它不做连接池、不做 ORM、不做分布式事务，但**一切数据访问的接缝都在它这里**（DataSource 管理 + 连接事务绑定 + 异常翻译）。

## 2. Boot 数据访问的自动装配链

```text
spring-boot-starter-jdbc
  → DataSourceAutoConfiguration
      → 根据 classpath 选 HikariCP/Druid/Tomcat JDBC
      → 解析 spring.datasource.* → 创建 DataSource
  → DataSourceTransactionManagerAutoConfiguration
      → DataSourceTransactionManager Bean
  → JdbcTemplateAutoConfiguration
      → JdbcTemplate + NamedParameterJdbcTemplate（7.0 起废弃标记）
  → JdbcClientAutoConfiguration（Boot 4）
      → JdbcClient Bean ★
  → SQL 初始化：DataSourceInitializationConfiguration
      → schema.sql / data.sql（spring.sql.init.mode）
```

> 💡 一个依赖搞定全部：`spring-boot-starter-jdbc` = 数据源 + 连接池 + 事务管理器 + 三种模板 + SQL 脚本初始化；MyBatis/JPA 另加对应 starter 替换模板层。

## 3. 高频问题与排查速查

| 现象 | 根因 | 排查/解法 |
|------|------|----------|
| `CannotGetJdbcConnectionException` | 池耗尽/库不可达/密码错 | 先 ping 数据库；查 `HikariPool-1 - Connection is not available` 日志；看池参数与并发 |
| 连接池耗尽（request timed out） | 连接泄漏/事务未提交/池太小 | 找 `leakDetectionThreshold` 日志；检查 try-with-resources、流未关闭、事务包裹过宽 |
| 中文乱码 | 连接 URL 字符集/表字符集 | URL 加 `characterEncoding=utf8`；确认表 utf8mb4；列类型 VARCHAR/utf8mb4 |
| `queryForObject` 抛 EmptyResult | 无结果行 | 业务上"可能无"用 `optional()`/`list()` 形态 |
| 死锁/锁超时异常（1205/1213） | 并发事务交叉锁 | 索引优化 + `@Retryable(include = DeadlockLoserDataAccessException)`（[Spring-Core-07](../Spring‑Core/07-重试与弹性速查.md)） |
| 批量插入还是很慢 | MySQL 伪批量 | URL 加 `rewriteBatchedStatements=true`（[05-批量操作与存储过程速查](05-批量操作与存储过程速查.md)） |
| 事务没生效 | 自调用/类没进容器/方法非 public | `this.method()` 自调用 → 注入自身代理；检查 @Transactional 在 public 方法 |
| 事务内查不到刚插入的数据 | 隔离级别/缓存（JPA 一级缓存） | 同事务同连接应可见；JPA 混用注意 EntityManager 缓存 |
| 多数据源切换失效 | 事务已绑定第一个连接 | 事务内禁止切库；设计独立事务或分布式方案 |
| 升级 7.0 后 NamedParameterJdbcTemplate 告警 | 7.0 废弃 | 迁移 JdbcClient（[03-JdbcClient 速查](03-JdbcClient速查.md) 第 6 节） |
| 测试库数据被污染 | 测试事务未回滚 | `@Transactional` 测试默认回滚；确认测试类继承/配置 |
| SQL 脚本没执行 | `spring.sql.init.mode` 默认值 | 显式 `spring.sql.init.mode: always`（embed 时默认 always） |

> ⚠️ **排查三板斧**：① 连接类问题先看池日志与 SQL 监控；② 事务类问题先确认"代理与自调用"；③ 数据类问题（乱码/时区）先看 URL 参数与驱动版本。
