## 1. 异常翻译的价值

```text
裸 JDBC：SQLException（受检异常）——只能 catch(Exception) 笼统处理，
         无法区分"连接断了""主键冲突""锁超时"——业务代码无法精准应对。

Spring：SQLExceptionTranslator 把 SQLException 翻译为 DataAccessException（非受检）
        → 按数据库厂商错误码分类 → 业务代码可针对性处理：
          catch (DuplicateKeyException e) → 提示"重复"
          catch (CannotAcquireLockException e) → 重试
          catch (DeadlockLoserDataAccessException e) → 退避重试
```

> 🎯 **核心要点**：翻译让"数据库错误"变成**可编程应对的异常类型**——这是 JdbcTemplate 最大的隐性价值；ORM（JPA/MyBatis）也复用同一套翻译体系（MyBatis 在 Spring 集成中同样翻译）。

## 2. DataAccessException 家族

```text
DataAccessException（org.springframework.dao，spring-tx 模块）
├── NonTransientDataAccessException（重试无意义）
│   ├── DataIntegrityViolationException
│   │   └── DuplicateKeyException          ★ 主键/唯一键冲突
│   ├── DataRetrievalFailureException
│   │   ├── EmptyResultDataAccessException ★ queryForObject 空结果
│   │   └── IncorrectResultSizeDataAccessException ★ 多行结果
│   ├── InvalidDataAccessResourceUsageException
│   │   └── BadSqlGrammarException         ★ SQL 语法错误
│   └── CannotGetJdbcConnectionException   ★ 拿不到连接（池耗尽/库挂了）
├── TransientDataAccessException（重试可缓解）
│   ├── ConcurrencyFailureException
│   │   ├── CannotAcquireLockException     ★ 锁等待超时
│   │   ├── DeadlockLoserDataAccessException ★ 死锁牺牲者
│   │   └── OptimisticLockingFailureException ★ 乐观锁版本冲突
│   └── QueryTimeoutException              ★ 查询超时
└── (RecoverableDataAccessException 等边缘类型)
```

> 💡 归属提示：`org.springframework.dao` 在 **spring-tx** 模块（不是 jdbc）——jdbc 的翻译器产出 tx 定义的异常族，再次印证"tx 是数据访问的公共契约层"。

## 3. SQLExceptionTranslator：翻译机制

| 翻译器 | 机制 | 适用 |
|--------|------|------|
| `SQLErrorCodeSQLExceptionTranslator`（默认） | 按**数据库厂商错误码**映射 | ✅ 主流（内置 15+ 厂商错误码表） |
| `SQLStateSQLExceptionTranslator` | 按 SQLState（SQL 标准五类前缀） | 兜底/未知厂商 |
| `SQLExceptionSubclassTranslator` | 按 JDBC 4 异常子类（如 SQLIntegrityConstraintViolationException） | 驱动现代时优先 |
| 组合 | 翻译链：Subclass → ErrorCode → SQLState | 默认即此链 |

```text
翻译链（JdbcTemplate 默认）：
  SQLExceptionSubclassTranslator（子类直判）
    → SQLErrorCodeSQLExceptionTranslator（查错误码表）★
    → SQLStateSQLExceptionTranslator（SQLState 兜底）

错误码表：org.springframework.jdbc.support.sql-error-codes.xml
  （MySQL 1062 → DuplicateKeyException；MySQL 1213 → DeadlockLoser...）
```

> ⚠️ **厂商差异**：错误码是数据库私有的——同样"唯一键冲突"，MySQL 是 1062、PostgreSQL 是 23505、Oracle 是 00001——所以必须用 `DatabaseMetaData.getDatabaseProductName()` 选对厂商表；自定义错误码用 `setSqlErrorCodes` 追加。

## 4. 数据库错误码速查

| 场景 | MySQL | PostgreSQL | Oracle |
|------|-------|-----------|--------|
| 唯一键冲突 | 1062 | 23505 | 00001 |
| 外键违反 | 1452 | 23503 | 02291 |
| 语法错误 | 1064 | 42601 | 00900 |
| 锁等待超时 | 1205 | 55P03 | 00054 |
| 死锁牺牲者 | 1213 | 40P01 | 00060 |
| 连接拒绝 | - | - | 12541 |
| 表不存在 | 1146 | 42P01 | 00942 |

> 💡 面试加分：死锁与锁超时翻译为 **Transient 族**——配合重试（[Spring-Core-07](../Spring‑Core/07-重试与弹性速查.md) 的 @Retryable 只配 `include = DeadlockLoserDataAccessException`）是数据库并发斗争的标准姿势。

## 5. 翻译器的接入点

| 接入点 | 方式 |
|--------|------|
| JdbcTemplate | `tpl.setExceptionTranslator(custom)` |
| Boot 全局 | 无需配置（默认翻译链已生效） |
| 自定义错误码 | 继承翻译器 `setSqlErrorCodes(new SqlErrorCodes(){...})` |
| ORM | JPA/MyBatis-Spring 复用同一 `PersistenceExceptionTranslator`（ORM 异常 → DataAccessException） |

```java
// 自定义翻译器：追加业务错误码
SQLErrorCodeSQLExceptionTranslator translator = new SQLErrorCodeSQLExceptionTranslator();
translator.setSqlErrorCodes(new SqlErrorCodes() {{
    setProductName("MySQL");
    setBadSqlGrammarCodes(new String[]{"1064"});
    setDataIntegrityViolationCodes(new String[]{"1062", "1452"});
}});
jdbcTemplate.setExceptionTranslator(translator);
```

> 🎯 **核心要点**：翻译链是**分层兜底**设计（子类 → 错误码 → SQLState）——任何厂商任何错误都有归属；业务上"重试型异常"只认 Transient 族，"冲突型异常"认 DataIntegrityViolation 族，实现精准防御。
