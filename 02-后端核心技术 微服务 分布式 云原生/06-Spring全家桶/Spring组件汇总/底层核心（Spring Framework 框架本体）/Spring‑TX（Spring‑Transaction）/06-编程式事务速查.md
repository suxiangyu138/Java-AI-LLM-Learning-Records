## 1. 编程式 vs 声明式

| 维度 | @Transactional（声明式） | TransactionTemplate（编程式） |
|------|------------------------|------------------------------|
| 声明位置 | 方法级（AOP 织入） | 代码块内显式调用 |
| 粒度 | 整个方法 | **任意代码段**（可事务可非事务混合） |
| 自调用 | ❌ 失效 | ✅ 无代理依赖，直接可用 |
| 动态传播 | 编译期固定 | 运行时变量/循环内可控 |
| 事务内决策 | 被动（异常冒泡） | 主动（setRollbackOnly/返回值控制） |
| 可读性 | 高（一行注解） | 中（模板包裹） |
| 适用 | 90% 场景 | 自调用、循环、工具类、复杂流程 |

> 🎯 **核心要点**：声明式是"方法级事务"的语法糖；编程式是"任意代码块级事务"的底层能力——**自调用失效问题的最稳解法不是注入代理，而是 TransactionTemplate**（工具类/监听器场景尤甚）。

## 2. TransactionTemplate 基础用法

```java
@Component
public class AuditService {
    private final TransactionTemplate txTemplate;

    public AuditService(PlatformTransactionManager txManager) {
        this.txTemplate = new TransactionTemplate(txManager);   // 注入管理器构建
        // 可预置默认属性
        this.txTemplate.setPropagationBehavior(
                TransactionDefinition.PROPAGATION_REQUIRES_NEW);
        this.txTemplate.setTimeout(10);
    }

    // 有返回值
    public AuditLog saveAndReturn(AuditCmd cmd) {
        return txTemplate.execute(status -> {
            auditDao.insert(cmd);
            return auditDao.findById(cmd.id());        // 事务内查询返回
        });
    }

    // 无返回值
    public void saveOnly(AuditCmd cmd) {
        txTemplate.executeWithoutResult(status -> {
            auditDao.insert(cmd);                       // 异常自动回滚
        });
    }
}
```

| 方法 | 语义 |
|------|------|
| `execute(TransactionCallback<T>)` | 返回结果；回调抛异常 → 回滚并向外抛 |
| `executeWithoutResult(Consumer<TransactionStatus>)` | 无返回；lambda 抛异常 → 回滚 |
| 回调内 `status.setRollbackOnly()` | 主动标记回滚（不抛异常也回滚） |

> ⚠️ **模板是线程安全的**：`TransactionTemplate` 本身可共享（属性不可变后再暴露）；不要在回调里改模板属性——每线程用局部配置时新建模板。

## 3. TransactionOperations：接口化编程式事务

```java
// 面向接口编程：容器注入 TransactionOperations（默认实现即 TransactionTemplate）
@Service
public class BatchService {
    private final TransactionOperations txOps;      // 注入接口，测试时好替换

    public BatchService(TransactionOperations txOps) { this.txOps = txOps; }

    public void importAll(List<Row> rows) {
        for (Row row : rows) {
            txOps.executeWithoutResult(status -> importOne(row));  // 逐行事务
        }
    }
}
```

> 💡 `TransactionOperations` 是 6.x 引入的接口抽象（默认 Bean 由 Boot 提供）——好处是测试可 mock、实现可替换；Spring 官方推荐"编程式事务面向 TransactionOperations 编程"。

## 4. 事务回调与状态控制

```java
txTemplate.execute(status -> {
    // ① 主动回滚：不抛异常
    if (!validate(cmd)) {
        status.setRollbackOnly();
        return null;
    }
    // ② 事务内条件分支：REQUIRES_NEW 动态决定
    if (cmd.forceAudit()) {
        txTemplate.executeWithoutResult(s -> auditDao.insert(cmd));  // 内层新事务
    }
    // ③ 事务同步钩子：提交后发事件
    TransactionSynchronizationManager.registerSynchronization(
            new TransactionSynchronization() {
                @Override
                public void afterCommit() {
                    eventPublisher.publishEvent(new OrderCreated(cmd.id()));
                }
            });
    return doBusiness(cmd);
});
```

> 🎯 **核心要点**：编程式事务的"状态控制"是声明式做不到的——`setRollbackOnly` 精确回滚、`registerSynchronization` 的 afterCommit 钩子（"事务提交成功才发 MQ/事件"的经典实现，见 [Spring-Context-05](../Spring‑Context/05-事件驱动机制速查.md) 事务事件原理）。

## 5. TransactionalOperator：响应式事务

```java
// 响应式事务（R2DBC / Reactive Mongo 场景）
@Service
public class ReactiveOrderService {
    private final TransactionalOperator txOperator;   // Boot 自动装配

    public Mono<Void> create(OrderCmd cmd) {
        Mono<Void> work = orderRepository.insert(cmd)
                .then(accountRepository.debit(cmd.userId(), cmd.amount()));
        return txOperator.transactional(work);        // 订阅执行包进事务
    }
}
```

| 要点 | 说明 |
|------|------|
| 实现 | `TransactionalOperator`（reactive 包）+ `ReactiveTransactionManager` |
| 执行时机 | **订阅时**才开事务（不是构建时） |
| 错误处理 | Mono/Flux error → 自动回滚 |
| 混用禁止 | 阻塞式与响应式事务资源不能混在同一事务 |
| 管理器 | `R2dbcTransactionManager`（spring-r2dbc）/ `ReactiveMongoTransactionManager` |

> ⚠️ **响应式大坑**：响应式事务依赖**订阅线程传播上下文**——`block()` 混用或跨线程切换订阅器会丢事务；7.x 下响应式事务保持稳定语义（REQUIRED 等传播同样支持）。

## 6. 编程式事务适用场景

| 场景 | 为什么用编程式 |
|------|--------------|
| 同类自调用需要事务 | @Transactional 失效，模板直接可用 |
| 循环内逐条事务 | 方法级注解做不到"每条一事务" |
| 监听器/定时任务 | 方法常被内部调用，代理不可靠 |
| 动态传播决策 | 传播行为由运行时条件决定 |
| 测试工具/脚本 | 快速包裹任意代码段 |
| 大流程局部事务 | 只有中间一段需要事务 |

> 🎯 **核心要点**：编程式与声明式是**同一套管理器 + 同步机制**的两个入口——混用安全（模板内外同事务）；选型标准：**方法级固定语义 → 声明式；代码块级/动态/自调用 → 编程式**。
