## 1. Artifact 坐标与版本线

| 项 | 值 |
|----|----|
| GroupId | `org.springframework` |
| ArtifactId | `spring-tx` |
| 最新版本 | 7.0.x（2026-08 时点，随 Framework 7.0 主线） |
| 维护线 | 7.0.x / 7.1.x（最新）、6.2.x（Boot 3.x） |
| Java 基线 | 17+ |
| 配套 | spring-jdbc（DataSource 实现）、spring-orm（JPA 实现）、reactor（响应式） |

> 💡 独立使用场景：只想要"事务抽象 + 异常体系"而不引入 jdbc——spring-tx 是**最小事务依赖**（如纯 ORM 项目）。

## 2. 包结构地图

```text
org.springframework.transaction
├── PlatformTransactionManager / TransactionDefinition / TransactionStatus  # ★ 三件套接口
├── TransactionException 族（NoTransactionException、CannotCreateTransactionException...）
├── TransactionSystemException（包装未检查异常）
├── support
│   ├── AbstractPlatformTransactionManager（★ 模板实现：提交/回滚/保存点骨架）
│   ├── DefaultTransactionStatus / TransactionSynchronizationManager（★ 线程绑定资源）
│   ├── TransactionTemplate / TransactionOperations（编程式）
│   └── TransactionSynchronization（afterCommit 钩子）
├── annotation
│   ├── @Transactional / TransactionalPropagation / TransactionalIsolation
│   └── TransactionalAnnotationParser / SpringTransactionAnnotationParser
├── interceptor
│   ├── TransactionInterceptor（★ 声明式事务核心拦截器）
│   ├── TransactionAttributeSource / TransactionAttribute（回滚规则定义）
│   └── TransactionAspectSupport（事务环绕逻辑模板）★
├── jta
│   ├── JtaTransactionManager / JtaTransactionObject
│   └── TransactionFactory（JTA 适配）
├── config
│   └── AnnotationDrivenBeanDefinitionParser（<tx:annotation-driven> XML 解析）
├── event
│   └── TransactionalEventListener / TransactionalApplicationListener（事务事件）
└── reactive
    ├── ReactiveTransactionManager / GenericReactiveTransactionManager
    └── TransactionalOperator / ReactiveTransactionSynchronizationManager

org.springframework.dao（★ 数据访问异常族，本模块定义）
├── DataAccessException / DataIntegrityViolationException / DuplicateKeyException
├── TransientDataAccessException / ConcurrencyFailureException / DeadlockLoserDataAccessException
└── CannotAcquireLockException / EmptyResultDataAccessException ...
```

**高频面试点名类**：`PlatformTransactionManager`、`AbstractPlatformTransactionManager`、`TransactionSynchronizationManager`、`TransactionInterceptor`、`TransactionAspectSupport`。

## 3. 依赖边界

| 依赖 | 方向 | 说明 |
|------|------|------|
| `spring-core` / `spring-beans` | 依赖 | 工具、AOP 通知接入（advice）、Bean 属性 |
| `spring-aop` | 可选 | 声明式事务需 AOP 代理（@EnableTransactionManagement 时） |
| `spring-context` | 可选 | 事件、`TransactionalEventListener` |
| `spring-jdbc` / `spring-orm` | **被依赖** | 事务管理器**实现**所在——tx 只出合同 |
| `reactor` | 可选 | `TransactionalOperator`（响应式） |
| 反向依赖 | - | jdbc、orm、Boot 全依赖 tx（**公共事务契约**） |

> 🎯 **核心要点**：**spring-tx 不包含任何资源事务实现**——`DataSourceTransactionManager` 在 spring-jdbc，`JpaTransactionManager` 在 spring-orm；tx 是"接口 + 拦截器 + 异常族"，实现全部由资源模块提供（接口分离的教科书案例）。

## 4. 职责切割：tx vs jdbc vs orm

| 维度 | spring-tx | spring-jdbc | spring-orm |
|------|-----------|-------------|------------|
| 定位 | 事务合同 | JDBC 模板 | ORM 集成 |
| 提供 | 管理器接口/@Transactional/异常族 | DataSourceTransactionManager | Jpa/HibernateTransactionManager |
| 执行 | 不执行 SQL | 模板执行 | EntityManager 管理 |
| 资源绑定 | TransactionSynchronizationManager | DataSourceUtils | EntityManagerFactoryUtils |
| 代表 | 契约与拦截 | 连接与模板 | 实体与映射 |

> 💡 面试画图题："Spring 事务体系分几层？"——**契约层（tx）→ 实现层（jdbc/orm）→ 使用层（@Transactional/TransactionTemplate）**，三句话讲清。

## 5. 版本兼容速查

| Spring Framework | Spring Boot | 备注 |
|------------------|-------------|------|
| 7.0.x（2025-11 起） | Boot 4.0.x | 当前主线；CGLIB 代理默认；JPA 3.2/Hibernate 7 |
| 7.1.x（2026-05 起） | Boot 4.1.x | 最新维护线 |
| 6.2.x | Boot 3.4/3.5 | 存量主流；JDK 接口代理行为可配置 |

> ⚠️ **升级提示（6.x → 7.x）**：① `@Transactional` 语义不变，无需改造；② 依赖"JDK 接口代理"（`proxyTargetClass=false` + 接口事务方法）的代码，7.0 默认 CGLIB 下需 `@Proxyable(INTERFACES)` 或显式配置恢复；③ 引用 `org.springframework.orm.hibernate5` 的代码迁到 `orm.jpa.hibernate`（spring-orm）。
