## 1. 集成地图

```text
调用链：
  外部 Bean → Spring 代理（CGLIB 默认）→ 通知链 → 目标方法

同一代理上叠加的横切能力（执行顺序）：
  @Transactional（事务）→ @Cacheable（缓存）→ @PreAuthorize（安全）→ @Async（异步）→ 业务
  顺序由 @Order 与切面声明共同决定

地基关系：
  一切代理注解 → AbstractAutoProxyCreator → ProxyFactory → CGLIB
  （@Transactional/@Cacheable/@Async/@PreAuthorize/@Retryable 共用同一织入机制）
```

## 2. 与声明式能力的集成

| 能力 | 代理注解 | 与 AOP 的关系 | 联动文档 |
|------|---------|-------------|---------|
| 事务 | `@Transactional` | 事务管理器 + 事务切面（最经典 AOP 应用） | [Spring框架核心-06](../../../Spring框架核心/06-声明式事务管理.md) |
| 缓存 | `@Cacheable` 等 | 缓存切面（AnnotationCacheAspect） | Spring Data Redis 06 篇 |
| 异步 | `@Async` | 异步执行器切面（AnnotationAsyncExecutionInterceptor） | [Spring Task-04](../../../Spring Task/04-异步任务：@Async与线程池.md) |
| 安全 | `@PreAuthorize` | 方法安全切面（AuthorizationManagerBeforeMethodInterceptor） | [Spring Security-04](../../../Spring Security与Spring Security OAuth2/04-方法级安全：@EnableMethodSecurity与表达式.md) |
| 重试 | `@Retryable` | 重试切面（7.0 起 CGLIB 一致） | — |
| 事件 | `@EventListener` | 不依赖 AOP（观察者模式） | [Spring框架核心-07](../../../Spring框架核心/07-事件驱动机制.md) |

> 🎯 **要点**：AOP 是这些能力的"织入器"——它们的**失效原因 90% 相同**（自调用/代理未开），一份排障经验全通用。

## 3. 代理失效五大坑

| # | 坑 | 现象 | 解法 |
|:---:|-----|------|------|
| 1 | **同类自调用** | `this.method()` 绕过代理，注解静默失效 | 注入自身代理 / 拆类 / `AopContext.currentProxy()` |
| 2 | private / final 方法 | CGLIB 无法增强 | 方法改 public 非 final |
| 3 | 代理未开启 | `spring.aop.auto=false` 或未加 starter-aop | 检查配置与依赖 |
| 4 | 静态方法 | 代理不拦截静态方法 | 改为实例方法 |
| 5 | 新对象绕过容器 | `new Xxx()` 直接调用 | 一律从容器取 Bean |

```java
// 坑 1 的正确解法（三种）
@Service
public class OrderService {

    @Resource
    private OrderService self;                    // ① 注入自身代理

    public void create() {
        self.update();                            // 走代理 → @Transactional 生效
    }

    @Transactional
    public void update() { ... }
}

// ② 拆类：事务逻辑放独立 Bean
// ③ AopContext.currentProxy()（需 exposeProxy=true，最后手段）
```

> ⚠️ **坑 1 是生产头号事故**：代码看起来对、注解也写了、就是不生效——**"调自己"是最隐蔽的代理绕过**。排查第一问："这个方法是不是从外部 Bean 进来的？"

## 4. 高频问题速查

| 现象 | 根因 | 处理 |
|------|------|------|
| @Aspect 切面不执行 | 未加 spring-boot-starter-aop / 未注册 Bean | 加依赖；@Aspect 类标注 @Component |
| @Transactional 不生效 | 自调用 / 方法非 public | 见 3.1 坑 |
| 切点表达式没匹配上 | 包名/方法签名写错 | 用 `execution(* com.demo..*(..))` 调试到最小集 |
| 代理对象类型不对 | JDK 代理 vs CGLIB 混用（6.x） | 7.x 已统一 CGLIB；存量用 @Proxyable 显式控制 |
| 两个切面顺序不对 | 未定义 @Order | @Order 数字小的先执行 |
| @Around 里没调 proceed | 目标方法不执行 | 环绕通知必须 proceed() |
| 切面里拿不到注解参数 | 绑定方式错误 | `@Around("@annotation(xxx)")` + 同名参数绑定 |
| 异常被 @Around 吞掉 | catch 后不 rethrow | 事务/安全感知的异常必须继续抛出 |
| 代理对象序列化/类型判断异常 | CGLIB 子类 | 用接口类型/`AopUtils.isAopProxy` 判断 |

## 5. 排障流程

```text
① 确认代理存在：启动日志或断点 AbstractAutoProxyCreator
   （或 AopUtils.isAopProxy(bean) == true）
② 确认调用路径：是否从容器 Bean 外部进入（自调用检查）
③ 确认切点命中：切点表达式逐步放宽（execution → within → bean）定位
④ 确认通知顺序：多切面时检查 @Order 与同类通知顺序
⑤ 回归验证：@Aspect 切面加日志，观察织入前后行为
```

> 🎯 **速查结论**：AOP 集成地图一句话——**所有声明式能力共用一套代理织入机制**，失效原因高度同源（自调用、private/final、代理未开）。排障先答三问：代理存在吗？从外部调的吗？切点命中了吗？
