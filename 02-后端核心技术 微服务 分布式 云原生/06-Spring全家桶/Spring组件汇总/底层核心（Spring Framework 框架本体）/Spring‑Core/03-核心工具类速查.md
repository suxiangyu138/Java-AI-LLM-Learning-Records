## 1. 工具类总表

| 工具类 | 定位 | 替代品参考 |
|--------|------|-----------|
| `Assert` | 契约断言（缺省即抛 IllegalArgumentException） | - |
| `StringUtils` | 字符串判空/裁剪/驼峰 | Apache Commons Lang `StringUtils` |
| `ObjectUtils` | null 安全比较/toString/判空 | JDK `Objects` |
| `CollectionUtils` | 集合判空/合并/查找 | - |
| `ReflectionUtils` | 反射操作封装 | - |
| `ClassUtils` | 类加载/判断/短名 | - |
| `MethodInvoker` | 方法调用封装（含参数类型匹配） | - |
| `StopWatch` | 秒表计时 | - |
| `NamedThreadLocal` | 命名 ThreadLocal（易排查） | - |
| `ConcurrentReferenceHashMap` | 弱/软引用并发 Map | Caffeine 等 |
| `NumberUtils` / `SystemPropertyUtils` / `PropertiesLoaderUtils` | 数值/系统属性/属性加载 | - |

> 💡 使用原则：Spring 工具是"零依赖内建"，但**不代表最优**——判空优先 JDK `Objects`、并发 Map 优先 Caffeine；Spring 工具胜在"容器内天然一致"（如 `ReflectionUtils` 兼容 record/泛型）。

**选型决策表**（避免"拿到锤子什么都是钉子"）：

| 需求 | 首选 | 次选 | 理由 |
|------|------|------|------|
| 判空 | JDK `Objects.requireNonNull` / `isNull` | Spring `ObjectUtils` | JDK 无依赖、性能相同 |
| 字符串处理 | Apache Commons Lang | Spring `StringUtils` | Commons 方法更全（如 `join`/`abbreviate`） |
| 集合工具 | JDK Stream API | Spring `CollectionUtils` | Stream 表达力更强；Spring 版偏内部 |
| 反射操作 | Spring `ReflectionUtils` | Apache commons-lang `MethodUtils` | Spring 版异常处理统一、考虑泛型 |
| 计时 | Spring `StopWatch` | JMH（基准测试） | StopWatch 用于观测，JMH 用于严谨基准 |
| 并发 Map | Caffeine | `ConcurrentReferenceHashMap` | 功能与调优更完整 |

> 💡 **判空三兄弟**：`ObjectUtils.isEmpty`（null 或空容器/字符串）、`StringUtils.isEmpty`（仅 null 或空串）、`StringUtils.hasText`（非 null 且含非空白）——语义逐级严格，用错层级是静态扫描告警的高频项。

## 2. Assert：断言

| 方法 | 失败异常 |
|------|---------|
| `Assert.notNull(obj, msg)` | IllegalArgumentException |
| `Assert.hasText(str, msg)`（非 null 且含非空白） | IllegalArgumentException |
| `Assert.isTrue(cond, msg)` | IllegalArgumentException |
| `Assert.state(cond, msg)` | IllegalStateException |
| `Assert.isInstanceOf(Class, obj)` / `Assert.isAssignable(...)` | IllegalArgumentException |
| `Assert.notEmpty(Collection/Map/array, msg)` | IllegalArgumentException |

```java
public void create(Order order) {
    Assert.notNull(order, "order must not be null");
    Assert.hasText(order.getOrderNo(), "orderNo must have text");
    Assert.isTrue(order.getAmount().signum() > 0, "amount must be positive");
    // ...业务
}
```

> 💡 与 JDK `Objects.requireNonNull` 差异：Assert 提供消息 + 类型化异常；服务层参数校验**首选 Jakarta Validation（@Valid）+ 全局异常**，Assert 用于"程序内契约"（内部错误，非用户输入错误）。

**Assert 完整方法清单**（按语义分组速查）：

| 语义 | 方法 | 失败异常 |
|------|------|---------|
| 非 null | `notNull` / `notNull(Object, Supplier<String>)` | IllegalArgumentException |
| 文本 | `hasText` / `hasLength` / `doesNotContain` | IllegalArgumentException |
| 集合/数组 | `notEmpty` / `noNullElements` / `notEmpty(Map)` | IllegalArgumentException |
| 布尔 | `isTrue` / `state`（状态机场景） | IAE / IllegalStateException |
| 类型 | `isInstanceOf` / `isAssignable` | IAE |
| 元素匹配 | `isNull`（7.0 起）/ `notNullElements` | IAE |

```java
// 生产建议：断言消息用 Supplier 惰性拼接（仅在失败时构造，避免热路径无谓开销）
Assert.notNull(order, () -> "order missing, requestId=" + TraceContext.getId());
```

> ⚠️ **Assert 的两个边界**：① 不要用它做"用户输入校验"——抛出的 IAE 无业务错误码，全局异常处理器难统一；② 不要在循环内高频调用带字符串拼接的断言——失败路径才需要消息，用 Supplier 版本；③ Assert 校验失败即抛异常，**没有返回值**（区别于 Guava `Preconditions` 同样如此）。

**Assert 与 Jakarta Validation 分工示例**（同一方法两种校验共存）：

```java
public Order create(@Valid CreateOrderRequest req) {      // ① 用户输入：@Valid 校验
    // ② 内部契约：程序状态断言（不是用户能控制的）
    Assert.state(orderNoGenerator != null, "orderNoGenerator not initialized");
    Assert.isTrue(!duplicateCache.containsKey(req.orderNo()),
                  "duplicate order detected");            // 并发重复提交拦截
    // ③ 不可恢复错误：fail-fast 抛 IllegalStateException
    ...
}
```

| 校验类型 | 工具 | 异常语义 | 处理方 |
|---------|------|---------|--------|
| 用户输入 | Jakarta Validation（@Valid） | 400 级业务错误 | 全局异常处理器 → 错误码 |
| 程序契约 | Assert | 500 级内部错误 | 直接抛出，日志 + 告警 |
| 状态机约束 | Assert.state | IllegalStateException | 运维告警 |

> 💡 记忆点：**"用户传错"走 Validation，"代码写错/状态错"走 Assert**——两者的分界线就是"这个错误用户能避免吗"。

## 3. StringUtils 与 ObjectUtils

```java
// StringUtils 高频
StringUtils.hasText(name);                 // 非 null 非空白（比 !"".equals 严谨）
StringUtils.capitalize("order");           // "Order"
StringUtils.uncapitalize("Order");         // "order"
StringUtils.arrayToDelimitedString(arr, ",");  // a,b,c
StringUtils.replace(uri, "{id}", "123");   // 模板替换
StringUtils.split("a,b,c", ",");           // 不保留空串（注意与 split(",") 差异）

// ObjectUtils 高频
ObjectUtils.nullSafeEquals(a, b);          // 全 null 视为相等
ObjectUtils.nullSafeToString(obj);         // 不会 NPE
ObjectUtils.isEmpty(str / arr / map);      // null 或空
ObjectUtils.containsConstant(enumClass, name);  // 枚举常量模糊匹配
```

> ⚠️ 命名陷阱：Spring `StringUtils.split` 与 JDK `String.split` 行为不同（Spring 版不保留尾部空元素）；判空用 `hasText`/`hasLength`（含空白判定差异），别用 `!str.isEmpty()` 直接判断。

**StringUtils 更多高频方法**：

| 方法 | 行为 | 示例 |
|------|------|------|
| `trimWhitespace` / `trimAllWhitespace` | 去首尾空白 / 去全部空白 | `" a b "` → `"a b"` / `"ab"` |
| `hasLength` / `hasText` | 非 null 非空 / 非 null 且含非空白 | 判空分级 |
| `startsWithIgnoreCase` / `endsWithIgnoreCase` | 忽略大小写前缀/后缀 | 协议判断 |
| `countOccurrencesOf` | 子串出现次数 | 占位符计数 |
| `delete` / `replace` | 删除子串 / 全部替换 | 模板处理 |
| `collectionToDelimitedString` | 集合转分隔串 | `[a, b]` → `a,b` |
| `parseLocale` / `parseTimeZoneString` | 字符串转 Locale/时区 | 配置解析 |
| `applyRelativePath` | 相对路径拼接 | 资源路径处理 |

```java
// 生产高频组合：驼峰 ↔ 下划线（配置键转换）
String key = StringUtils.hasText(raw) 
        ? StringUtils.uncapitalize(raw.replace('-', '.'))
        : "default";
```

**ObjectUtils 易混点**：

| 方法 | 语义 | 陷阱 |
|------|------|------|
| `nullSafeEquals` | 两个 null 相等；数组按**元素**比较 | 与 `Objects.equals` 对数组的引用比较不同 |
| `nullSafeToString` | null 输出 `"null"` 字符串 | 数组输出 `{1, 2}` 形式（非 `[1, 2]`） |
| `isEmpty` | null / 空串 / 空数组 / 空集合 / 空 Map | 对 `Optional.empty` 不适用（用 `isEmpty(Optional)` 有重载） |
| `containsConstant` | 枚举名模糊匹配（忽略大小写） | 不匹配时返回 false，无异常 |

> 💡 **性能注意**：`nullSafeEquals` 内部含类型分支判断，比直接 `==`/`equals` 慢一个量级——仅在"可能为 null 且语义是空相等"时使用，热路径用显式判空。

**StringUtils 生产综合示例**（订单号生成器风格代码）：

```java
public String buildOrderNo(String prefix, long seq, String region) {
    String regionNorm = StringUtils.hasText(region) ? region.trim().toUpperCase() : "DF";
    return StringUtils.arrayToDelimitedString(
            new String[]{prefix, regionNorm, String.valueOf(seq)}, "-");
    // "SO" + "CN" + "1024" → "SO-CN-1024"
}
```

| 易错对比 | Spring 行为 | JDK 行为 |
|---------|------------|---------|
| `split("a,,b", ",")` | 保留中间空元素 `[a, "", b]` | 相同 |
| `split("a,b,", ",")` | `[a, b]`（**丢弃尾部空**） | `[a, b, ""]`（保留尾部空） |
| `replace(s, "{id}", "1")` | 替换全部匹配 | `String.replace` 同 |
| `capitalize` | 首字母大写（null 安全） | 无 JDK 对应 |

> ⚠️ **国际化注意**：`capitalize`/`toLowerCase` 默认 locale 敏感（土耳其语 I 问题）——国际产品文本处理需显式传 Locale（`toLowerCase(Locale.ROOT)`）；Spring 工具多数有 locale 参数版本。

**ObjectUtils 实战示例**（日志与判空场景）：

```java
// 日志脱敏场景：null 安全输出
log.info("order created: {}", ObjectUtils.nullSafeToString(order));  // 不会 NPE

// 响应包装：空集合统一转 null 或空列表
if (ObjectUtils.isEmpty(items)) {
    return Collections.emptyList();
}

// 枚举解析：容错解析（大小写不敏感）
if (ObjectUtils.containsConstant(PayStatus.class, statusStr)) {
    return PayStatus.valueOf(statusStr.toUpperCase());
}
```

> 💡 组合拳：`ObjectUtils.isEmpty` + `CollectionUtils.isEmpty` 语义一致（前者支持数组/Map/字符串），**接口层统一用前者**减少分支；内部集合算法用后者（类型更明确、IDE 提示更准）。

## 4. 反射三件套：ReflectionUtils / ClassUtils / MethodInvoker

```java
// ReflectionUtils：异常被包装为 UndeclaredThrowableException，可用 handleReflectionException 规整
Method m = ReflectionUtils.findMethod(OrderService.class, "create", Long.class);
ReflectionUtils.invokeMethod(m, service, 1L);

// 遍历类的全部方法（含父类）
ReflectionUtils.doWithMethods(OrderService.class,
        method -> System.out.println(method.getName()),
        method -> method.isAnnotationPresent(MyAnnotation.class));

// 字段操作
ReflectionUtils.makeAccessible(field);         // private 也可见
ReflectionUtils.setField(field, target, value);

// 构造器推断（Spring 内部大量使用）
Constructor<?> ctor = ReflectionUtils.accessibleConstructor(OrderService.class, Long.class);

// ClassUtils
ClassUtils.forName("com.example.OrderService", cl);
ClassUtils.isPresent("jakarta.persistence.Entity", cl);    // 依赖探测（自动配置用）
ClassUtils.getShortName(OrderService.class);               // "OrderService"
ClassUtils.getDefaultClassLoader();                        // 上下文类加载器
```

**MethodInvoker：带参数类型匹配的方法调用器**（框架注入器内部大量使用）：

```java
// 场景：按"名称 + 参数值"调用方法，自动匹配重载（不必自己处理类型转换）
MethodInvoker invoker = new MethodInvoker();
invoker.setTargetObject(handler);
invoker.setTargetMethod("onEvent");
invoker.setArguments(new Object[]{event, "order.created"});   // 字符串自动转目标参数类型
invoker.prepare();                 // 查找并校验方法（找不到抛 IllegalStateException）
invoker.invoke();                  // 执行；异常包装为 InvocationTargetException
```

| 能力 | 说明 |
|------|------|
| 重载匹配 | 按参数值类型匹配最合适的方法（含类型转换） |
| 参数转换 | 字符串 → 数值/枚举等（内部走 TypeConverter） |
| 静态方法 | `setTargetClass` + 静态调用 |
| 失败行为 | `prepare()` 阶段即校验，fail-fast |

> 🎯 **核心要点**：反射工具的意义不是"省几行代码"，而是**统一异常处理**（InvocationTargetException/IllegalAccessException → `UndeclaredThrowableException`）与 **Spring 内部一致语义**（泛型、record、Kotlin 数据类都考虑在内）——写框架级代码时用它，业务代码少用。

**反射三件套常见坑**：

| 坑 | 表现 | 解法 |
|----|------|------|
| 方法查找失败静默 | `findMethod` 返回 null，调用 NPE | 判空或 `getMethod`（抛 NoSuchMethodException） |
| 泛型桥接方法 | 找方法命中桥接方法（泛型擦除产物） | `ReflectionUtils.isBridgeMethod` 过滤 |
| 私有字段访问 | `setAccessible` 在 Java 17+ 强封装下受限 | 框架级用 `VarHandle`/`MethodHandles`；业务避免反射 |
| 静态方法调用 | `invokeMethod(m, null, args)` 实例传 null | 显式传 null 并注明 |
| Kotlin/record 支持 | 构造器推断需 `accessibleConstructor` | 优先用该 API 而非 `getDeclaredConstructor` |

```java
// 生产技巧：doWithMethods 实现"扫描某包下所有回调方法"
ReflectionUtils.doWithMethods(Handler.class, method -> {
    if (method.isAnnotationPresent(OnEvent.class)) {
        registry.register(method);      // 收集事件回调
    }
}, ReflectionUtils.USER_DECLARED_METHODS);   // 只处理用户声明的方法（过滤桥接/合成）
```

> ⚠️ **性能红线**：反射调用比直接调用慢 1-2 个数量级（JIT 优化后差距缩小，但开销仍存）——**启动期/低频路径**用反射没问题，**热路径**（每请求执行）应改用接口回调、`MethodHandle` 或代码生成（CGLIB/JDK Proxy 内部即用 MethodHandle 优化）。

**ClassUtils 更多方法**（依赖探测与类处理）：

| 方法 | 行为 | 典型场景 |
|------|------|---------|
| `isPresent(className, classLoader)` | 类是否在 classpath（不加载即判断可加载性） | 自动配置条件判断（Boot 大量使用） |
| `isAssignable(Class, Class)` | 兼容 `isAssignableFrom` 并处理接口/装箱 | 类型关系判断 |
| `getUserClass(Class)` | 代理类还原原始类 | 排查代理（见 5 节） |
| `getDefaultClassLoader` | 上下文类加载器优先的获取 | 框架加载资源/类 |
| `getShortName` / `getShortNameAsProperty` | 短类名 / 首字母小写短名 | 日志与命名 |
| `resolvePrimitiveIfNecessary` | 包装类型 → 基本类型 | 反射参数匹配 |
| `getMostSpecificMethod` | 接口方法 → 实现类实际方法 | 注解查找（避免接口注解丢失） |

```java
// 自动配置风格的条件判断：只有类存在才注册
if (ClassUtils.isPresent("org.apache.kafka.clients.KafkaClient", 
                          ClassUtils.getDefaultClassLoader())) {
    // 注册 Kafka 相关 Bean
}
```

## 5. StopWatch 与其他

```java
// StopWatch：多段计时
StopWatch sw = new StopWatch("pipeline");
sw.start("step1");  // ... 
sw.stop();
sw.start("step2");  // ...
sw.stop();
System.out.println(sw.prettyPrint());   // 每段耗时 + 占比表
```

| 工具 | 说明 |
|------|------|
| `StopWatch` | 多段秒表；生产环境慎用（`sw.isRunning()` 防忘停） |
| `NamedThreadLocal` | 命名 ThreadLocal，日志可读性翻倍 |
| `ConcurrentReferenceHashMap` | 弱引用缓存 Map（元数据缓存场景） |
| `SystemPropertyUtils` | 系统属性解析（含默认值/占位符） |
| `PropertiesLoaderUtils` | 加载 .properties（含 classpath 多源） |
| `FileCopyUtils` / `StreamUtils` | 流/文件复制（`copyToString` 等） |
| `AopUtils`/`ClassUtils.getUserClass` | 代理类还原原始类（**排查代理类型必备**） |

**NamedThreadLocal 与 ConcurrentReferenceHashMap 详解**：

```java
// NamedThreadLocal：命名 ThreadLocal（日志可读、支持引用清理）
private static final ThreadLocal<String> REQUEST_ID = new NamedThreadLocal<>("requestId");
// 对比匿名 ThreadLocal：堆栈里显示 "ThreadLocal" 无法区分，命名后显示 "requestId"

// ConcurrentReferenceHashMap：弱引用键的并发 Map（元数据缓存）
ConcurrentReferenceHashMap<Class<?>, Method[]> methodCache =
        new ConcurrentReferenceHashMap<>(16, 0.75f, 4, ReferenceType.WEAK);
// 键被 GC 回收后条目自动清理——避免类加载器泄漏（关键：缓存 Class 键必须弱引用）
```

| 组件 | 适用场景 | 禁忌 |
|------|---------|------|
| NamedThreadLocal | 请求链路标识、事务上下文 | 线程池复用必须清理（remove） |
| ConcurrentReferenceHashMap | 类元数据缓存（Class 键）、大对象缓存 | 不保证强一致语义（弱引用键可能随时消失） |
| 普通 ConcurrentHashMap | 强引用数据 | 缓存 Class 键会阻止类卸载（类加载器泄漏） |

> ⚠️ **类加载器泄漏是框架级常见病**：用 `ConcurrentHashMap<Class<?>, ?>` 缓存类元数据的框架代码，在热部署/插件场景会撑爆元空间——Spring 内部大量使用 `ConcurrentReferenceHashMap` 正是为此；**自定义框架缓存时优先弱引用键**。

> ⚠️ **排查技巧**：`AopUtils.isAopProxy(obj)` / `ClassUtils.getUserClass(obj.getClass())`——判断对象是否被代理、拿到被代理的真实类，是"为什么注解不生效"排查的第一步。

### 5.1 生产场景：StopWatch 与性能观测

```java
// 生产实践：慢路径观测 + 阈值告警（避免忘 stop 的坑）
StopWatch sw = new StopWatch("payment");
sw.start("http-call");
try {
    return callRemote();
} finally {
    sw.stop();                                   // finally 中停止，防异常漏停
    long ms = sw.getLastTaskTimeMillis();
    if (ms > 500) {
        log.warn("slow payment http-call: {}ms", ms);
    }
}
```

| StopWatch API | 用途 |
|---------------|------|
| `prettyPrint()` | 全量耗时统计表（开发期输出） |
| `getTotalTimeMillis()` | 总耗时 |
| `getLastTaskTimeMillis()` | 最近一段耗时 |
| `isRunning()` | 判断是否忘停（生产监控可轮询） |

> ⚠️ **生产纪律**：StopWatch 的 `start/stop` 必须成对，**finally 包裹**或 try-with-resources 风格封装；生产环境默认关闭细粒度分段（只留总耗时与慢路径日志），避免统计本身成为开销。

### 5.2 面试追问点

- **"Spring 为什么自己写工具类而不用 Guava"**：① 零依赖红线——core 编译期只能依赖 JDK；② 控制面窄——只需要框架自身用到的 20% 功能；③ 一致性——工具语义与框架内部假设绑定（如 `StringUtils.split` 的语义是框架定的）；
- **"ReflectionUtils 相比裸反射好在哪里"**：统一异常（包装为 `UndeclaredThrowableException` 并保留根因）、桥接方法过滤、record/Kotlin 感知、缓存友好——裸反射要自己处理四类异常；
- **"StopWatch 的坑"**：忘 stop 导致累计时间失真、非线程安全（单线程专用）、`start` 嵌套需成对——生产要封装或换 Micrometer Timer（`@Timed` 注解化更省心）；
- **"工具类何时该抽离成公共库"**：三个以上服务重复使用且语义稳定时——但注意工具库一旦发布就是契约，命名与边界（如"只做无状态纯函数"）要提前定好。

### 5.3 生产实践与常见坑汇总

| 坑 | 症状 | 解法 |
|----|------|------|
| 判空层级混淆 | `hasLength` 用于"含空白也算有值"的字段 | 按语义选 `hasText`（非空白） |
| 反射调用业务热路径 | 接口响应变慢、GC 压力大 | 改接口回调/缓存 MethodHandle |
| 断言消息昂贵拼接 | 每次调用都拼长字符串 | 用 `Supplier<String>` 重载 |
| ThreadLocal 忘记 remove | 线程池复用导致数据串线 | try-finally 清理；或 `NamedThreadLocal` + 拦截器统一清理 |
| 用错 split 语义 | 尾部空元素丢失或保留行为不符 | 确认 Spring 版（去尾部空）vs JDK 版（保留）差异 |

**工具类线程安全速查**（框架代码并发使用前必查）：

| 工具 | 线程安全 | 说明 |
|------|:---:|------|
| `StringUtils` / `ObjectUtils` | ✅ | 纯静态无状态 |
| `Assert` | ✅ | 纯静态无状态 |
| `ReflectionUtils` | ✅（方法线程安全） | 缓存类私有字段非公开 API |
| `StopWatch` | ❌ | 单线程专用；共享需加锁或每线程实例 |
| `NamedThreadLocal` | ✅ | 线程隔离是其本义 |
| `ConcurrentReferenceHashMap` | ✅ | 并发安全（弱引用语义见 5 节） |
| `ClassUtils` / `NumberUtils` | ✅ | 纯静态 |

**再补一个冷门但实用者**：`SystemPropertyUtils`（占位符解析，`resolvePlaceholders`）与 `PropertiesLoaderUtils`（多源加载）常在框架初始化路径出现——前者支持 `${key:default}` 语法，后者支持 `classpath*:` 多资源合并加载；业务代码偶尔需要"读一个非 Spring 管理的 properties 文件"时，直接 `PropertiesLoaderUtils.loadAllProperties("config/app.properties")` 一行解决（自动走类路径合并语义）。这两个工具是"脱离容器读配置"的快捷通道，值得记住。

> 🎯 **全篇收束**：工具类没有技术含量高深可言，但**选型与语义边界**决定代码质量——面试与评审中"为什么用这个工具"比"会用这个工具"更能体现水平；核心原则：判空归 JDK、字符串归 Commons、反射归 Spring、观测归 Micrometer；另外牢记 StopWatch 只在观测场景使用，生产性能分析交给 Micrometer 与 APM，两者定位不同不要混用。
