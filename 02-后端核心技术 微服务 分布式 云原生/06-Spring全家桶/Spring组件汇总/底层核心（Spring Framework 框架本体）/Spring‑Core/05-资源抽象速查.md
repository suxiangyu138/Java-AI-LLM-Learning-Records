## 1. Resource：资源统一抽象

`Resource`（`org.springframework.core.io`）把"类路径文件、磁盘文件、URL、字节数组、流"统一成同一接口：

```java
public interface Resource extends InputStreamSource {
    boolean exists();
    InputStream getInputStream() throws IOException;      // ★ 唯一必须可用的能力
    String getFilename();
    String getDescription();                               // 日志友好描述
    URL getURL() / URI getURI() / File getFile();          // 视实现可用
    default boolean isFile() / isReadable() / contentLength() ...
}
```

| 能力 | 说明 |
|------|------|
| 读流 | `getInputStream()` ——**唯一跨实现安全**的读取方式 |
| 元数据 | exists / isReadable / contentLength / lastModified |
| 定位 | getURL / getFile（**仅特定实现可用**，jar 内抛错） |
| 写 | `WritableResource.getOutputStream()`（FileSystemResource 等） |

> 🎯 **核心要点**：读资源**只用 `getInputStream()`**——`getFile()` 在 jar 打包后必然失败（类路径资源不存在"文件"）；描述/日志用 `getDescription()`。

## 2. 五种常用实现

| 实现 | 前缀 | 说明 |
|------|------|------|
| `ClassPathResource` | `classpath:` | 类路径资源（jar 内/IDE 类目录） |
| `FileSystemResource` | `file:` | 文件系统（实现 WritableResource 可写） |
| `UrlResource` | `http(s):` / `ftp:` | 任意 URL 资源 |
| `ByteArrayResource` | - | 内存字节数组 |
| `InputStreamResource` | - | 包装一次性输入流（**不可重复读**） |

```java
new ClassPathResource("templates/email.html");
new FileSystemResource("/data/app.conf");
new UrlResource("https://example.com/api.json");
```

> ⚠️ `InputStreamResource` 每次 `getInputStream()` 后流即耗尽——**避免复用**；读文件流首选 `FileCopyUtils.copyToString(res.getInputStream(), charset)` 一次性取完。

## 3. ResourceLoader 与资源解析

| 组件 | 接口方法 | 说明 |
|------|---------|------|
| `ResourceLoader` | `getResource(String location)` | 按位置解析（前缀决定类型，无前缀依实现而定） |
| `ResourcePatternResolver` | `getResources(String pattern)` | 模式解析（ant 通配） |
| `PathMatchingPatternResourceResolver` | - | 默认实现：classpath*: 扫描 + ant 匹配 |

```text
ResourceLoader 解析规则：
  "classpath:x.txt"     → ClassPathResource
  "file:/data/x.txt"    → FileSystemResource
  "https://..."         → UrlResource
  "x.txt"（无前缀）       → 依加载器：ClassPathXmlApplicationContext 下是类路径

ApplicationContext 本身实现 ResourcePatternResolver —— 注入它即可加载资源
```

```java
// 注入 ResourceLoader（ApplicationContext 即 ResourceLoader）
@Service
public class ResourceService {
    private final ResourcePatternResolver resolver;

    public ResourceService(ResourcePatternResolver resolver) {  // 可注入接口
        this.resolver = resolver;
    }

    public Resource single() {
        return resolver.getResource("classpath:config/app.properties");
    }
}
```

## 4. PatternResolver：模式加载与 classpath*

| 写法 | 语义 |
|------|------|
| `classpath:x.xml` | 类路径**单个**资源（第一个命中） |
| `classpath*:x.xml` | **所有**类路径上的 x.xml（多 jar 收集）★ |
| `classpath*:**/mapper/*.xml` | 全类路径递归 + ant 匹配 |
| `file:/data/**/*.conf` | 文件系统模式 |
| `?` / `*` / `**` / `{var}` | ant 通配：单字符 / 路径段内任意 / 跨目录 / 占位变量 |

```java
// 多 jar 配置收集（Spring 自身大量使用：spring.factories、imports 文件）
Resource[] rs = resolver.getResources("classpath*:META-INF/spring/imports/*.imports");
```

> 🎯 **核心要点**：`classpath:` 取第一个命中；`classpath*:` 扫描全部类路径——多模块/多 jar 场景（自动配置、SPI 文件、多模块 mybatis mapper）必须用 `classpath*:`，否则只加载第一个 jar 的。

## 5. Spring 内建使用场景

| 场景 | 使用方式 |
|------|---------|
| @Value 注入资源 | `@Value("classpath:templates/email.html") Resource tpl`（ResourceEditor 自动转换，context 模块） |
| XML 配置 | `<import resource="classpath*:config/spring-*.xml"/>` |
| Boot 配置文件 | `spring.config.location` / `spring.config.import`（Boot 内部全走 Resource 抽象） |
| MyBatis mapper | `classpath*:mapper/*.xml`（MyBatis 扫描器走 ResourcePatternResolver） |
| 自动配置候选 | `AutoConfigurationImportSelector` 读 `classpath*:META-INF/spring/...AutoConfiguration.imports` |
| 模板/静态资源 | ClassLoader 路径模板（Thymeleaf 等模板引擎内部） |

> 💡 **7.0 AOT 相关**：原生镜像下类路径资源需要显式 `RuntimeHints` 提示（`resourceHint`）——格式已从正则改 **glob**（`"/files/**/*.ext"`，`"/files/*.ext"` 不再匹配嵌套），见 [08-集成地图与常见问题](08-集成地图与常见问题.md)。
