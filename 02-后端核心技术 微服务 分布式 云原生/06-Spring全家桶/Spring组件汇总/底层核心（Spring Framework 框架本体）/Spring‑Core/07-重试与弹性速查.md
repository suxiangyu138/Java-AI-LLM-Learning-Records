## 1. 7.0 弹性体系总览

```text
Spring Framework 7.0 弹性能力（原独立项目 Spring Retry 并入并重设计）
├── spring-core  org.springframework.core.retry
│   ├── RetryTemplate（入口：同步执行 + 重试编排）
│   ├── RetryPolicy（何时重试：次数/异常分类）
│   ├── BackOffPolicy（重试间隔：固定/指数）
│   ├── RetryContext（本次执行上下文：尝试计数、异常记录）
│   └── RecoveryCallback（耗尽后的兜底）
└── spring-context  声明式注解
    ├── @EnableResilientMethods（开关：@Configuration 类上）
    ├── @Retryable（方法级重试，响应式自动适配）
    └── @ConcurrencyLimit（并发限流）
```

> 🎯 **核心要点**：7.0 把"重试"从第三方库升级为 Framework 一等能力——core 提供执行引擎，context 提供注解；响应式返回类型（Mono/Flux）自动用 Reactor 重试管道，命令式用 RetryTemplate。

## 2. RetryTemplate：编程式重试

```java
// ① Builder 快速构建（推荐）
RetryTemplate template = RetryTemplate.builder()
        .maxRetries(3)                                  // ★ 7.0 语义：最大重试次数（原 maxAttempts）
        .fixedBackoff(500)                              // 固定 500ms 间隔
        .exponentialBackoff(200, 2, 5_000)              // 或指数退避 200ms 起、×2、上限 5s
        .build();

// ② 执行：成功返回 / 失败重试 / 耗尽回调
String result = template.execute(
        ctx -> remoteCall(),                            // RetryCallback：可重试业务
        ctx -> fallbackValue(ctx.getLastThrowable()));  // RecoveryCallback：重试耗尽兜底
```

| 组件 | 职责 |
|------|------|
| `RetryCallback<T>` | 重试主体：`T doWithRetry(RetryContext ctx)` |
| `RecoveryCallback<T>` | 耗尽兜底：`recover(RetryContext)`（拿到最后异常） |
| `RetryContext` | `getRetryCount()` / `getLastThrowable()` / 属性传递 |
| `RetrySynchronizationManager` | 上下文在线程间传递（嵌套重试） |

> ⚠️ **失败判定默认**：任何 `Exception` 都重试——业务上"不可重试错误"（参数错误/4xx 类）要显式配置 `RetryPolicy` 排除（见第 3 节）。

## 3. RetryPolicy 与 BackOff 策略

| 策略 | 类 | 说明 |
|------|----|------|
| 次数 | `MaxAttemptsRetryPolicy`（builder 内建） | 最多尝试 N 次（含首次） |
| 异常分类 | `ExceptionClassifierRetryPolicy` | 按异常类型决定是否重试/是否退避 |
| 时间 | `TimeoutRetryPolicy` | 窗口期内重试 |
| 永不 | `NeverRetryPolicy` | 不重试（默认兜底） |
| 固定间隔 | `FixedBackOffPolicy` | 固定毫秒 |
| 指数退避 | `ExponentialBackOffPolicy` | 初始 × 倍数，可设上限与随机抖动 |
| 无退避 | `NoBackOffPolicy` | 立即重试 |

```java
// 异常分类：只对网络类异常重试，参数异常直接失败
RetryTemplate template = new RetryTemplate();
template.setRetryPolicy(new ExceptionClassifierRetryPolicy() {
    @Override
    protected boolean canRetry(RetryContext context) {
        Throwable t = context.getLastThrowable();
        return t instanceof IOException || t instanceof TimeoutException;
    }
});
template.setBackOffPolicy(new ExponentialBackOffPolicy());
```

> 💡 **最佳实践**：① 只重试"瞬时错误"（网络/限流/超时），不重试"确定错误"（参数/权限）；② 重试必须带退避（防打爆下游）；③ 调用方加**总超时**（重试总窗口），避免无限阻塞；④ 重试幂等——重试的副作用（已提交的订单）必须可幂等。

## 4. @Retryable 与 @ConcurrencyLimit（声明式）

```java
@Configuration
@EnableResilientMethods                       // ★ 总开关（context 7.0）
public class ResilientConfig { }

@Service
public class PaymentClient {
    @Retryable(maxRetries = 3,                 // ★ 7.0：maxAttempts → maxRetries
               backoff = @Backoff(delay = 200, multiplier = 2),
               include = {IOException.class},  // 只对指定异常重试
               exclude = {IllegalArgumentException.class})
    public PaymentResult charge(PaymentReq req) {
        return restTemplate.postForObject(...);   // 命令式：内部走 RetryTemplate
    }

    @Retryable(maxRetries = 2)
    public Mono<PaymentResult> chargeReactive(PaymentReq req) {
        return webClient.post().body(...).retrieve()...;   // 响应式：自动适配 Reactor retry
    }

    @ConcurrencyLimit(limit = 20)                // 并发限流：同方法同时执行 ≤ 20
    public void bulkSync() { ... }
}
```

| 注解属性 | 语义 |
|---------|------|
| `maxRetries`（7.0） | 最大重试次数（原 maxAttempts 已更名） |
| `backoff` / `@Backoff(delay, multiplier, maxDelay)` | 退避参数 |
| `include` / `exclude` | 异常白/黑名单 |
| `recover` | 兜底方法名（返回类型须兼容） |
| `label` / `listen` | 观测/日志（可扩展） |
| `@ConcurrencyLimit(limit)` | 并发上限（基于信号量式节流） |

> ⚠️ **注意**：① `@Retryable` 是代理注解——**同类自调用不生效**（见 [Spring-AOP-00](../Spring‑AOP/00-Spring AOP组件总览.md) 自调用坑）；② 7.0.0 曾有 `@ConcurrencyLimit` + `@Async`/`@Transactional` 组合异常（已修复）；③ 兜底 `recover` 方法默认按异常类型匹配。

## 5. 迁移与选型

| 场景 | 选型 |
|------|------|
| 新项目（Framework 7 / Boot 4） | ✅ 直接用内建 `core.retry` + `@Retryable` |
| 存量 spring-retry 独立项目 | 迁移：移除 `spring-retry` 依赖，`maxAttempts` → `maxRetries`，包名 `org.springframework.core.retry` |
| 简单单次重试 | 甚至不必引入——`RestClient` 等自带重试或循环 + sleep |
| 复杂重试编排 | 内建 RetryTemplate 足够；更重场景上 Spring Batch 的 Retry 或消息队列重投递 |
| 消息消费重试 | 优先 MQ 死信/延迟队列，而非方法重试（见消息队列系列） |

```xml
<!-- 迁移：移除独立 spring-retry -->
<!-- 旧：org.springframework.retry:spring-retry -->
<!-- 新：随 spring-core 7.0 内建，无需额外坐标 -->
```

> 🎯 **核心要点**：重试是"最后手段"——先做**超时 + 熔断 + 降级**（Sentinel/Resilience4j 见分布式系列），重试只对瞬时故障负责；内建重试的定位是"轻量、框架内一致"，复杂链路治理仍交给专业组件。
