## 1. 返回值处理：HandlerMethodReturnValueHandler

```text
控制器方法返回后：
  RequestMappingHandlerAdapter → HandlerMethodReturnValueHandler 链
    → 第一个 supportsReturnType 命中的处理器接管
    → 把返回值转成 ModelAndView 或写入响应（转换器）
```

| 返回值处理器 | 处理 |
|------------|------|
| `RequestResponseBodyMethodProcessor` | `@ResponseBody` 标注/`@RestController` 方法 → 转换器写响应 |
| `ResponseEntityReturnValueHandler` | `ResponseEntity` 返回值 → 状态码+头+体 |
| `ModelAndViewMethodReturnValueHandler` | ModelAndView/视图名 |
| `ModelAttributeMethodProcessor` | `@ModelAttribute` 返回值 → 模型 |
| `ResponseBodyEmitterReturnValueHandler` | SseEmitter/流式（异步） |

> 🎯 **核心要点**：返回值处理器与参数解析器是**对称的两条链**（一个管入、一个管出）——自定义响应类型可注册自己的 `HandlerMethodReturnValueHandler`（扩展点）。

### 返回值处理器链（默认顺序，节选）

| 顺序 | 处理器 | 处理 |
|:---:|--------|------|
| 1 | `ModelAndViewMethodReturnValueHandler` | ModelAndView / Model |
| 3 | `ViewMethodReturnValueHandler` | View 对象直接渲染 |
| 4 | `ResponseBodyEmitterReturnValueHandler` | SseEmitter / ResponseBodyEmitter（SSE） |
| 5 | `StreamingResponseBodyReturnValueHandler` | 流式下载 |
| 6 | `HttpEntityMethodProcessor` | ResponseEntity / HttpEntity（状态+头+体） |
| 7 | `HttpHeadersReturnValueHandler` | 仅响应头（无体） |
| 8 | `CallableMethodReturnValueHandler` | Callable（异步执行） |
| 9 | `DeferredResultMethodReturnValueHandler` | DeferredResult（异步） |
| 12 | `RequestResponseBodyMethodProcessor` | `@ResponseBody`（转换器写出）★ |
| 13 | `ViewNameMethodReturnValueHandler` | String 视图名（无 @ResponseBody） |
| 14 | `MapMethodProcessor` | Map → 模型属性 |
| 15 | `ModelAttributeMethodProcessor`（无注解） | 其他对象 → 模型属性 |

> 🎯 读链方法：**按顺序找第一个 `supportsReturnType` 为 true 的处理器**——`@ResponseBody` 方法命中 12 号（写响应），普通方法命中 13 号（视图名）或 15 号（模型属性）；这就是"同一个 String，一个出 JSON、一个出页面"的机制答案。

### 自定义返回值处理器（扩展示例）

```java
// 场景：统一包装响应（Result<T> 自动补 code/message）
@Component
public class ResultReturnValueHandler implements HandlerMethodReturnValueHandler {

    @Override
    public boolean supportsReturnType(MethodParameter returnType) {
        return returnType.getParameterType() == Result.class;   // 只处理 Result 类型
    }

    @Override
    public void handleReturnValue(Object returnValue, MethodParameter returnType,
                                  ModelAndViewContainer mavContainer,
                                  NativeWebRequest webRequest) throws Exception {
        mavContainer.setRequestHandled(true);                    // 声明已处理（不再走视图）
        // 写入响应：这里简单演示，实际应委托给转换器
        webRequest.getNativeResponse(HttpServletResponse.class)
                .getWriter().write(JsonMapper.builder().build().writeValueAsString(returnValue));
    }
}

// 注册
@Configuration
public class WebConfig implements WebMvcConfigurer {
    @Override
    public void addReturnValueHandlers(List<HandlerMethodReturnValueHandler> handlers) {
        handlers.add(new ResultReturnValueHandler());
    }
}
```

> ⚠️ 自定义处理器注意：**`mavContainer.setRequestHandled(true)` 是必须的**——否则返回值还会继续走视图渲染；一般场景优先用 @ResponseBody + 统一返回 DTO 而非自定义处理器（可维护性更好）。

### 响应形态选型表

| 响应形态 | 实现 | 场景 |
|---------|------|------|
| 纯 JSON | DTO 直接返回 | 默认（90% 接口） |
| JSON + 动态状态码 | ResponseEntity | 创建 201、条件 404/409 |
| 空体成功 | void / ResponseEntity.noContent() | 删除、幂等操作 |
| 文件下载 | StreamingResponseBody | 报表/导出/附件 |
| 实时推送 | SseEmitter | 通知/进度 |
| 多格式共存 | produces + 内容协商 | 开放平台 |

## 2. @ResponseBody 幕后

```java
@ResponseBody                                       // 或类上 @RestController
public Order get(@PathVariable Long id) { ... }
```

```text
RequestResponseBodyMethodProcessor.writeWithMessageConverters：
  1. 确定目标媒体类型：produces → Accept 协商 → 默认 JSON
  2. 泛型解析：ResolvableType（List<Order> 保留泛型）
  3. 遍历 HttpMessageConverter 链：canWrite(类型, 媒体类型) 命中
  4. 序列化写体（Jackson 等）→ 状态 200 + Content-Type
```

> ⚠️ **经典坑**：返回 `null` 时 JSON 为 `null` 文本（非 204）；想 204 用 `ResponseEntity.noContent()` 或 `void`；**BigDecimal/LocalDateTime 序列化**需注册 JavaTimeModule/自定义（Boot 4 默认已配）。

### JSON 序列化高频坑（生产排查表）

| 坑 | 现象 | 根因 | 解法 |
|----|------|------|------|
| 循环引用 | StackOverflowError | 双向关联实体序列化 | `@JsonIgnore` 一侧 / DTO 投影 |
| 懒加载序列化 | LazyInitializationException | 实体带未初始化代理（序列化在事务外） | 服务层组装 DTO / @JsonIgnore 懒字段 |
| 时间格式 | `"2026-08-07T10:00:00"` 非业务格式 | 默认 ISO-8601 | 自定义 LocalDateTimeSerializer / @JsonFormat |
| 时区偏差 | 时间差 8 小时 | Jackson 默认 UTC | `spring.jackson.time-zone=GMT+8`（Boot 属性） |
| 字段改名 | 前端拿不到驼峰字段 | 命名策略不匹配 | @JsonProperty 或 PropertyNamingStrategies |
| null 字段 | 响应多余 null 键 | 默认输出 null | @JsonInclude(NON_NULL) / 全局策略 |
| 金额精度 | 大数精度丢失 | Double 浮点误差 | BigDecimal + WRITE_BIGDECIMAL_AS_PLAIN |

> ⚠️ 排查顺序：**先看异常类型**——StackOverflow → 循环引用；LazyInitializationException → 事务边界；序列化格式怪 → 转换器配置——三个坑三种根因，别一上来就怀疑转换器。

### @ResponseBody 完整执行路径

```text
方法返回 Order 对象（@RestController）：
  ① RequestMappingHandlerAdapter 拿到返回值
  ② 返回值处理器链：RequestResponseBodyMethodProcessor.supportsReturnType = true
  ③ writeWithMessageConverters 流程：
     - 确定媒体类型：produces → Accept 协商 → 默认 application/json
     - 泛型解析：ResolvableType.forMethodReturnType（List<Order> 保留元素类型）
     - 遍历转换器：JacksonJsonHttpMessageConverter.canWrite(Order, JSON) ✅
     - JsonMapper 序列化 → 写入响应体 → 状态 200 + Content-Type
  ④ 若返回 null：转换器写出 "null" 文本（不是 204）
```

| 环节 | 关键点 |
|------|--------|
| 媒体类型确定 | produces 注解 > Accept(q 值) > 默认 JSON |
| 泛型保留 | ResolvableType 让 `List<Order>` 的 Order 泛型在反序列化时可用 |
| 状态码 | 默认 200；@ResponseStatus / ResponseEntity 可改 |
| null 语义 | 序列化为 "null" 文本；要 204 用 ResponseEntity.noContent() |

> 💡 面试深挖点：**ResolvableType 泛型解析**是"为什么 `ResponseEntity<List<Order>>` 反序列化不丢泛型"的答案——转换器拿到的不是原始 Class 而是带泛型参数的 Type。

### 序列化治理最佳实践

| 实践 | 说明 |
|------|------|
| 永远不直接返回实体 | Controller 返回值全部用 DTO/VO（解耦存储模型与契约） |
| 时间格式统一 | 全局 JsonMapper 配一个 LocalDateTime 格式 + 固定时区 |
| null 策略统一 | 全局 NON_NULL（列表空集保留，字段 null 剔除） |
| 金额用 BigDecimal | 序列化配 PLAIN 输出，前端按字符串处理 |
| 大小写/命名一致 | 后端 camelCase、前端同样 camelCase（免策略转换） |
| 敏感字段白名单 | DTO 显式声明字段，绝不让实体直接出网 |

## 3. 支持的返回类型速查

| 返回类型 | 行为 | 场景 |
|---------|------|------|
| `String` | 视图名（无 @ResponseBody）| 页面跳转 |
| `Object` / DTO | 转换器直出（@ResponseBody）| JSON API |
| `ResponseEntity<T>` | 状态码 + 头 + 体 | 自定义状态/响应头 |
| `void` | 200 空体（或写 HttpServletResponse）| 下载等 |
| `HttpHeaders` | 仅响应头 | 特殊 |
| `Callable` / `DeferredResult` | 异步请求处理 | 长任务解耦 |
| `SseEmitter` / `StreamingResponseBody` | 流式推送 | SSE/大文件 |
| `Mono`/`Flux`（webflux） | 响应式 | 响应式栈 |

### 异步返回的取舍与细节

| 维度 | Callable | DeferredResult | 同步方法 |
|------|----------|----------------|---------|
| 线程释放 | 立即释放（任务线程执行） | 立即释放 | 占住请求线程 |
| 结果设置 | 返回时即执行 | 任意时刻 complete() | 方法返回即完成 |
| 超时 | 默认容器超时 | 可配超时 → AsyncRequestTimeoutException（503） | 无（连接挂起） |
| 适用 | 简单异步 | 多任务聚合/事件驱动 | 常规业务 |

> 💡 虚拟线程时代结论：**同步方法 + 虚拟线程已覆盖绝大多数异步诉求**（请求线程便宜了）——Callable/DeferredResult 留给"必须释放容器线程"的存量场景或事件驱动架构；Boot 4 默认虚拟线程下先写同步，遇到吞吐瓶颈再考虑显式异步。实践顺序：**先压测发现瓶颈 → 再定位瓶颈位置 → 最后决定是否异步化**，不要为了"异步"而异步——异步化带来的线程安全与超时处理复杂度远高于同步代码。

```java
// 状态码控制的三种写法
@ResponseStatus(HttpStatus.CREATED)                  // ① 注解固定
public Order create(...) { ... }

public ResponseEntity<Order> get(...) {              // ② 动态状态
    return orderService.findById(id)
            .map(ResponseEntity::ok)
            .orElseGet(() -> ResponseEntity.notFound().build());
}

public void download(HttpServletResponse resp) {     // ③ 原生写流
    resp.setContentType("application/pdf");
    Files.copy(path, resp.getOutputStream());
}
```

> 💡 选型：简单 API → 直接返回 DTO；需要状态码/头控制 → ResponseEntity；文件/流 → void + HttpServletResponse（或 StreamingResponseBody）。

### 流式响应与文件下载（完整示例）

```java
// 大文件下载：流式写出，不占内存（每块 4KB 缓冲）
@GetMapping("/download/{id}")
public ResponseEntity<StreamingResponseBody> download(@PathVariable Long id) {
    StreamingResponseBody body = out -> Files.copy(Paths.get("/data/" + id + ".pdf"), out);
    return ResponseEntity.ok()
            .header(HttpHeaders.CONTENT_DISPOSITION,
                    "attachment; filename=report-" + id + ".pdf")
            .contentType(MediaType.APPLICATION_PDF)
            .body(body);
}

// SSE 推送：服务端持续下发事件（前端 EventSource 消费）
@GetMapping(value = "/events", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public SseEmitter events() {
    SseEmitter emitter = new SseEmitter(30_000L);      // 超时 30 秒
    executor.execute(() -> {
        try {
            emitter.send(SseEmitter.event().name("tick").data(Instant.now()));
            emitter.send(SseEmitter.event().name("tick").data(Instant.now()));
            emitter.complete();
        } catch (Exception ex) {
            emitter.completeWithError(ex);
        }
    });
    return emitter;
}
```

| 方式 | 适用 | 内存特征 |
|------|------|---------|
| void + HttpServletResponse | 简单下载 | 手动管理流 |
| StreamingResponseBody | 大文件/慢数据 | 异步线程写出，不占请求线程缓冲 |
| SseEmitter | 实时推送（通知/进度） | 长连接，注意超时与重连 |
| DeferredResult | 长任务异步化 | 释放请求线程，任务完成后补响应 |

> 💡 取舍：文件下载优先 `StreamingResponseBody`（不 OOM）；推送场景先确认是否必须 SSE——低频通知用轮询更简单，高频实时才上 SSE/WebSocket（[Spring-Web-07](../Spring‑Web/07-异步与流式速查.md) 有完整对比）。

### 状态码选择语义速查

| 状态码 | 语义 | 典型用法 |
|:---:|------|---------|
| 200 | 成功 | 查询/普通操作 |
| 201 | 创建成功 | POST 创建（Location 头指新资源） |
| 204 | 成功无体 | 删除/幂等空操作 |
| 400 | 客户端请求错误 | 参数缺失/格式错/校验失败 |
| 401 | 未认证 | 无 token/token 失效 |
| 403 | 无权限 | 已认证但越权 |
| 404 | 资源不存在 | 无路由/资源缺失 |
| 405 | 方法不允许 | 路径对方法不对 |
| 409 | 冲突 | 幂等冲突/并发修改 |
| 415/406 | 媒体类型协商失败 | Content-Type/Accept 不匹配 |
| 500 | 服务器内部错误 | 未处理异常（兜底） |
| 503 | 服务不可用 | 异步超时/熔断 |

> ⚠️ 语义红线：**别用 200 表示业务失败**（前端无法统一处理错误）；也别用 500 表示业务错误（监控会误报警）——业务失败用 4xx + 业务错误码（见 [05 篇第 4 节](05-异常处理速查.md) 错误码设计）。

## 4. 消息转换器（7.0 命名）

| 转换器（7.0） | 媒体类型 | 说明 |
|--------------|---------|------|
| `JacksonJsonHttpMessageConverter` | `application/json` | ★ 主转换器（取代 Jackson2 命名） |
| `JacksonXmlHttpMessageConverter` | `application/xml` | XML 序列化 |
| `JacksonCborHttpMessageConverter` | `application/cbor` | 7.0 默认装配 CBOR |
| `StringHttpMessageConverter` | `text/*` | 字符串 |
| `ByteArrayHttpMessageConverter` | `application/octet-stream` | 字节 |
| `KotlinSerializationJsonHttpMessageConverter` | `application/json` | Kotlin @Serializable（7.0 收紧） |
| `MarshallingHttpMessageConverter` / Gson / Jsonb | XML / JSON | 备选实现 |

```java
// 配置/替换（7.0 统一 API）
@Configuration
public class WebConfig implements WebMvcConfigurer {
    @Override
    public void configureMessageConverters(HttpMessageConverters converters) {
        converters.registerDefaults()
                .jsonMessageConverter(new JacksonJsonHttpMessageConverter(customMapper()));
    }

    private JsonMapper customMapper() {
        return JsonMapper.builder()
                .addModule(new JavaTimeModule())          // 时间序列化
                .disable(SerializationFeature.WRITE_DATES_AS_TIMESTAMPS)
                .build();
    }
}
```

> ⚠️ **升级注意**：引用 `MappingJackson2HttpMessageConverter`/`Jackson2ObjectMapperBuilder`（6.x 类名）的代码 7.0 下需改 `JacksonJsonHttpMessageConverter`/`JsonMapper`（[Spring-Web-03](../Spring‑Web/03-消息转换与内容协商速查.md) 转换器全家表）。

### 6.x → 7.x 转换器类名迁移对照

| 6.x（Boot 3） | 7.x（Boot 4） | 说明 |
|--------------|--------------|------|
| `MappingJackson2HttpMessageConverter` | `JacksonJsonHttpMessageConverter` | JSON 主转换器 |
| `Jackson2ObjectMapperBuilder` | `JsonMapper.builder()` | JsonMapper 工厂 |
| `MappingJackson2XmlHttpMessageConverter` | `JacksonXmlHttpMessageConverter` | XML |
| `MappingJackson2CborHttpMessageConverter` | `JacksonCborHttpMessageConverter` | CBOR（7.0 默认装配） |
| `ObjectMapper`（Jackson 2.x） | `JsonMapper`（Jackson 3.x） | 类型树变化 |

```java
// 自定义转换器示例：覆盖 JSON 转换器（7.0 统一 API）
@Configuration
public class WebConfig implements WebMvcConfigurer {
    @Override
    public void configureMessageConverters(HttpMessageConverters converters) {
        converters.registerDefaults()                       // 保留默认转换器
                .jsonMessageConverter(new JacksonJsonHttpMessageConverter(
                        JsonMapper.builder()
                                .addModule(new JavaTimeModule())
                                .disable(SerializationFeature.WRITE_DATES_AS_TIMESTAMPS)
                                .build()));
    }
}
```

> ⚠️ `registerDefaults()` 必须调用：7.0 下 `configureMessageConverters` 是"接管"语义——不注册默认转换器则 String/ByteArray 等基础能力也消失，导致 415/406 连锁故障。

### JsonMapper 常用配置速查（Jackson 3）

```java
JsonMapper.builder()
        .addModule(new JavaTimeModule())                          // 时间序列化
        .disable(SerializationFeature.WRITE_DATES_AS_TIMESTAMPS)  // ISO-8601 而非时间戳
        .disable(DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES) // 容忍未知字段
        .enable(SerializationFeature.INDENT_OUTPUT)               // 开发期美化（生产关）
        .serializationInclusion(JsonInclude.Include.NON_NULL)     // 全局剔除 null 字段
        .build();
```

| 配置项 | 说明 |
|--------|------|
| JavaTimeModule | LocalDateTime 等 java.time 类型支持（必加） |
| FAIL_ON_UNKNOWN_PROPERTIES=false | 客户端多传字段不报错（兼容演进） |
| WRITE_DATES_AS_TIMESTAMPS=false | 时间输出 ISO 字符串而非数字时间戳 |
| NON_NULL | 全局 null 剔除（列表保留） |
| WRITE_BIGDECIMAL_AS_PLAIN | 金额不输出科学计数法 |

> 💡 生产模板：**JavaTimeModule + 禁时间戳 + 容忍未知字段 + 固定时区**四件套是所有 JSON 接口的基线配置；改配置后必须回归 415/406 与序列化用例。调试技巧：用 `curl -i` 查看实际 Content-Type 与响应体，快速判断是协商问题还是序列化问题——协商失败无响应体，序列化失败有异常 JSON。

### 转换器链的工作方式

```text
写响应（@ResponseBody）：
  遍历 HttpMessageConverter 链 → canWrite(返回类型, 目标媒体类型)
  → 第一个命中者写出（JSON 转换器通常覆盖绝大部分类型）

读请求（@RequestBody）：
  遍历链 → canRead(目标类型, Content-Type)
  → 命中者反序列化

匹配失败：
  写方向 → HttpMediaTypeNotAcceptableException（406）
  读方向 → HttpMediaTypeNotSupportedException（415）
```

## 5. 内容协商与媒体类型

```text
响应媒体类型选择（默认策略）：
  1. produces 注解限定（优先）
  2. Accept 头 q 值排序
  3. 无 Accept → 默认 application/json（7.x 默认转换器首位）
  配置：spring.mvc.contentnegotiation.*（Boot）/
        WebMvcConfigurer.configureContentNegotiation
```

```java
// 同一端点多格式：根据 Accept 返回 JSON 或 XML
@GetMapping(value = "/orders/{id}", produces = {"application/json", "application/xml"})
public Order get(@PathVariable Long id) { ... }   // 客户端 Accept 决定格式

// 查询参数协商（少见）：?format=json
@Configuration
public class WebConfig implements WebMvcConfigurer {
    @Override
    public void configureContentNegotiation(ContentNegotiationConfigurer c) {
        c.parameterName("format");                    // ?format=json|xml
    }
}
```

> 🎯 **核心要点**：协商顺序 = **produces > Accept(q 值) > 默认**；`406` = 客户端 Accept 无转换器可写；`415` = 请求 Content-Type 无转换器可读（见 [Spring-Web-03](../Spring‑Web/03-消息转换与内容协商速查.md) 第 4 节）。

### 内容协商完整流程（写响应方向）

```text
writeWithMessageConverters 协商顺序：
  1. produces 注解声明（如 {"application/json","application/xml"}）→ 候选集合
  2. 客户端 Accept 头（q 值从高到低）过滤候选
  3. 遍历转换器链：canWrite(返回类型, 媒体类型) → 第一个命中者写出
  4. 无任何转换器可写 → HttpMediaTypeNotAcceptableException → 406

读请求（@RequestBody）对应：
  1. Content-Type 头决定目标媒体类型
  2. 遍历转换器链：canRead(目标类型, Content-Type) 命中
  3. 无转换器可读 → HttpMediaTypeNotSupportedException → 415
```

| 现象 | 归因 | 排查点 |
|------|------|--------|
| 406 Not Acceptable | Accept 声明了转换器没有的格式 | 转换器依赖缺失（XML 缺 jackson-dataformat-xml） |
| 415 Unsupported Media Type | Content-Type 无转换器可读 | 客户端头写错 / 缺解析依赖 |
| 协商到意外格式 | Accept 顺序或 q 值设计不当 | 明确 produces 限定候选集 |
| 返回类型不匹配 | canWrite 全 false | 自定义类型未注册序列化器 |

### 内容协商配置完整示例

```java
// 更细的协商配置（WebMvcConfigurer）
@Configuration
public class WebConfig implements WebMvcConfigurer {
    @Override
    public void configureContentNegotiation(ContentNegotiationConfigurer configurer) {
        configurer.defaultContentType(MediaType.APPLICATION_JSON)   // 无 Accept 时默认 JSON
                .mediaType("json", MediaType.APPLICATION_JSON)
                .mediaType("xml", MediaType.APPLICATION_XML);
        // 注意：7.0 已移除 favorParameter（?format=json 后缀/参数协商）
    }
}
```

```yaml
# Boot 属性方式（等价）
spring:
  mvc:
    contentnegotiation:
      default-media-type: application/json
```

> ⚠️ 7.0 变化：`favorPathExtension`（后缀协商）与参数协商相关旧配置已移除——不要再用 `.json` 后缀或 `?format=` 做格式切换，统一 Accept 头协商。

> ⚠️ 生产约定：**协商能力是给开放平台用的，内部服务别滥用**——内部接口固定 produces=application/json，客户端不传 Accept，行为完全确定；开放平台再开放 XML/多格式。同时建议所有对外接口在文档中明确"默认格式与可协商格式清单"，避免客户端猜测导致 406 频发。

### 面试官追问

| 追问 | 回答锚点 |
|------|---------|
| @ResponseBody 到底谁在工作？ | RequestResponseBodyMethodProcessor（返回值处理器 + 转换器） |
| 为什么 null 返回 "null"？ | 转换器对 null 也走序列化（WriteNull） |
| 怎么让所有接口不输出 null 字段？ | JsonMapper 全局 NON_NULL / 类级 @JsonInclude |
| 415 和 406 谁先发生？ | 读方向 415（请求体），写方向 406（响应） |
| 自定义返回类型怎么支持？ | 自定义 HandlerMethodReturnValueHandler 或注册转换器 |
| 大文件下载用什么？ | StreamingResponseBody（异步流式，不 OOM） |
| 返回 void 时状态码是什么？ | 默认 200 空体；可写 HttpServletResponse 自定义 |
| DTO 与实体混用的风险？ | 懒加载/字段泄漏（密码等敏感字段）——一律 DTO |
| 响应里有敏感字段怎么办？ | DTO 字段白名单 + 全局 @JsonIgnore 兜底敏感属性 |

> 🎯 本模块收官：返回值处理器链（管出）+ 转换器链（管格式）+ 协商（管选择）三层合起来就是"响应怎么变成 HTTP 响应"的完整答案；自测：能否讲清 @ResponseBody 从方法返回到字节流写出的完整路径？能否说清 415/406 的判定方向？能否背出 JsonMapper 生产四件套（JavaTimeModule、禁时间戳、容忍未知字段、固定时区）？
