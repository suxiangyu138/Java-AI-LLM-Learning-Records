## 1. Artifact 坐标与版本线

| 项 | 值 |
|----|----|
| GroupId | `org.springframework` |
| ArtifactId | `spring-webmvc` |
| 最新版本 | 7.0.x（2026-08 时点，随 Framework 7.0 主线） |
| 维护线 | 7.0.x / 7.1.x（最新）、6.2.x（Boot 3.x） |
| Java 基线 | 17+；Servlet 6.x（Jakarta EE 11） |
| 常用配套 | spring-web（必须）、Thymeleaf/Jackson（视图/JSON）、spring-boot-starter-web（Boot） |

> 💡 命名澄清：模块名 spring-webmvc，官方文档称 Spring MVC——与 spring-web（HTTP 基础设施）是两个模块；响应式栈对应 spring-webflux。

### 三种引入方式

```xml
<!-- 方式一：Boot 4（推荐，自动装配全套） -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>

<!-- 方式二：裸 Framework 7（需自己注册 DispatcherServlet） -->
<dependency>
    <groupId>org.springframework</groupId>
    <artifactId>spring-webmvc</artifactId>
    <version>7.0.x</version>
</dependency>
```

```gradle
// 方式三：Gradle（Boot 4）
dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-web'
}
```

| 方式 | 适用 | 额外要做的事 |
|------|------|------------|
| starter-web | 绝大多数 Boot 应用 | 无（WebMvcAutoConfiguration 全自动） |
| 裸 spring-webmvc | 手写容器/框架 | 注册 DispatcherServlet + 配置 WebMvcConfigurer |
| webflux starter | 响应式栈 | 与 MVC 互斥 |

> 💡 判断装配是否成功：启动日志出现 `RequestMappingHandlerMapping`（映射 N 个方法）即 MVC 就位；`spring-boot-starter-web` 自带内嵌 Tomcat，无需单独引入 Servlet 容器。

### 版本线同步规则

| 事实 | 说明 |
|------|------|
| 版本号一致 | spring-webmvc 与 spring-web/spring-core 等所有 Framework 模块**版本号永远相同**（统一发布） |
| Boot 管理 | Boot 4 的 BOM（spring-boot-dependencies）统一钉住 Framework 版本 |
| 混版本后果 | 跨版本混用（如 webmvc 6.2 + core 7.0）→ `NoSuchMethodError` / `NoClassDefFoundError` |
| 查看方式 | `mvn dependency:tree` 或 IDE Gradle 依赖报告 |

> ⚠️ 升级 Framework 时**全部模块一起升**——Spring 不保证模块间跨版本兼容；出现 `NoSuchMethodError` 先查是否混版本。

## 2. 包结构地图

```text
org.springframework.web.servlet
├── DispatcherServlet ★（中央调度器）
├── FrameworkServlet / HttpServletBean（基类：init 装配组件）
├── HandlerMapping（接口）/ HandlerExecutionChain（处理器+拦截器链）
├── HandlerAdapter（接口）/ HandlerInterceptor（接口）★
├── ModelAndView / ModelMap / View（接口）
├── ViewResolver（接口）/ ViewResolverComposite
├── handler ★ HandlerMapping 实现
│   ├── AbstractHandlerMapping（模板：拦截器装配、CORS 处理）
│   ├── RequestMappingHandlerMapping ★（注解路由）
│   ├── SimpleUrlHandlerMapping（URL 直配）
│   └── WelcomePageHandlerMapping / ResourceHandlerMapping
├── mvc ★ 注解 MVC 核心
│   ├── method：HandlerMethod / InvocableHandlerMethod（参数解析器聚合）
│   ├── method.annotation：
│   │   ├── RequestMappingHandlerAdapter ★（注解处理器适配器）
│   │   ├── RequestMappingHandlerMethodProcessor 族（参数/返回值解析器）★
│   │   ├── @ControllerAdvice / @InitBinder / @ModelAttribute 解析
│   │   └── SseEmitter / DeferredResult / ResponseBodyEmitter（异步）
│   └── WebMvcConfigurer ★（配置接口）/ WebMvcConfigurationSupport
├── resource：ResourceHttpRequestHandler（静态资源）
├── view：ViewResolver 实现（Thymeleaf 在第三方；InternalResourceViewResolver 等）
├── support：WebContentGenerator / DefaultHandlerExceptionResolver ★
├── async：WebAsyncManager 集成
└── function：WebMvc.fn（函数式端点，RouterFunction）
```

**高频面试点名类**：`DispatcherServlet`、`RequestMappingHandlerMapping`、`RequestMappingHandlerAdapter`、`HandlerMethodArgumentResolver`、`HandlerMethodReturnValueHandler`、`DefaultHandlerExceptionResolver`。

### 关键类职责速查（面试点名清单）

| 类 | 包 | 职责 |
|----|----|------|
| `DispatcherServlet` | servlet | 前端控制器：init 装配 + doDispatch 调度 |
| `HandlerExecutionChain` | servlet | 处理器 + 拦截器列表（路由结果） |
| `HandlerMethod` | mvc.method | 控制器方法的包装（含注解/参数/返回信息） |
| `InvocableHandlerMethod` | mvc.method | 执行 HandlerMethod：参数解析 + 反射调用 |
| `ModelAndViewContainer` | mvc.method | 模型与视图中间容器（参数/返回值处理间传值） |
| `ModelAndView` | servlet | 视图名 + 模型数据（渲染输入） |
| `AbstractHandlerMethodMapping` | handler | 注解路由的模板基类（注册/匹配算法） |
| `RequestMappingInfo` | mvc.method | 一个映射的完整条件（路径/方法/参数/头/版本） |
| `WebMvcConfigurer` | mvc | 配置回调接口（拦截器/转换器/校验器/跨域） |
| `DefaultHandlerExceptionResolver` | support | 框架标准异常 → 状态码（兜底） |
| `HttpEntityMethodProcessor` | mvc.method.annotation | `HttpEntity<T>` / `RequestEntity<T>` 读写 |
| `WebMvcConfigurationSupport` | mvc | 编程式配置基类（Boot 自动配置内部使用） |

> 🎯 阅读源码路线图：`DispatcherServlet → doDispatch → getHandler（HandlerMapping）→ getHandlerAdapter → handle（InvocableHandlerMethod）→ returnValueHandlers`——顺着这条线就能在 IDE 里走完一次请求。

### 包结构的分层逻辑

包名不是随便分的——它对应 MVC 的三个抽象层次：

| 层次 | 包 | 装什么 | 一句话职责 |
|------|-----|--------|-----------|
| 框架层 | `org.springframework.web.servlet` | 核心接口与调度器 | 定义 MVC 骨架：调度、路由、执行、视图、拦截的接口 |
| 路由层 | `...web.servlet.handler` | 各种 HandlerMapping | 解决"请求匹配谁"：注解路由/URL 直配/静态资源 |
| 注解层 | `...web.servlet.mvc.method` | 方法级处理器 | 解决"方法怎么执行"：参数解析、返回值处理 |
| 支持层 | `...web.servlet.support` | 工具与默认行为 | 默认异常解析、请求缓存等辅助设施 |
| 配置层 | `...web.servlet.mvc`（WebMvcConfigurer） | 配置回调 | 装配入口：拦截器/转换器/校验器/跨域 |

> 💡 阅读规律：**接口在顶层包，实现在子包**——想扩展哪个能力，先找顶层包的接口，再去对应子包看默认实现（例如路由接口在 servlet 包、注解实现 `RequestMappingHandlerMapping` 在 handler 包）。

### 包结构速记法

面试被问"spring-webmvc 包含哪些包"时按五层记忆：

| 记忆锚点 | 包 | 装什么 |
|---------|-----|--------|
| 宪法层 | `servlet` | 接口与骨架：调度器、映射、适配、视图、拦截 |
| 路由层 | `servlet.handler` | 各种 HandlerMapping 实现 |
| 执行层 | `servlet.mvc.method` | HandlerMethod 与参数/返回值处理 |
| 注解层 | `servlet.mvc.method.annotation` | @RequestBody/@RequestParam 等注解解析器 |
| 外围层 | `view` / `resource` / `async` / `function` | 视图、静态资源、异步、函数式端点 |

> 💡 顺口溜："**宪法在顶、路由在 handler、执行在 method、注解在 annotation、外围各分包**"——五层记完，包结构题稳拿分。

## 3. DispatcherServlet 装配的组件

| 组件 | 接口/类 | 职责 |
|------|---------|------|
| 路由 | `HandlerMapping` | 请求 → 处理器（含拦截器链） |
| 执行 | `HandlerAdapter` | 处理器调用 + 参数/返回值处理 |
| 异常 | `HandlerExceptionResolver` | 异常 → 错误响应 |
| 视图 | `ViewResolver` | 视图名 → View |
| 语言 | `LocaleResolver` | 请求 → Locale |
| 主题 | `ThemeResolver` | 主题（少用） |
| 文件 | `MultipartResolver` | 多部分解析（Boot 4 默认标准 Servlet 解析） |
| 闪存 | `FlashMapManager` | 重定向参数传递 |

> 🎯 **核心要点**：DispatcherServlet 是"**可装配的调度器**"——所有零件通过接口注入，Boot 4 自动装配全套（WebMvcAutoConfiguration）；面试答"DispatcherServlet 初始化做了什么"→ 装配这 8 类组件。

### initStrategies 源码级装配（7.x）

```java
// DispatcherServlet.initStrategies(ApplicationContext) —— 初始化 8 类组件
protected void initStrategies(ApplicationContext context) {
    initMultipartResolver(context);          // ① 文件上传解析（MultipartResolver）
    initLocaleResolver(context);             // ② 语言环境（LocaleResolver）
    initThemeResolver(context);              // ③ 主题（ThemeResolver，少用）
    initHandlerMappings(context);            // ④ 路由表（HandlerMapping 列表）
    initHandlerAdapters(context);            // ⑤ 执行器（HandlerAdapter 列表）
    initHandlerExceptionResolvers(context);  // ⑥ 异常解析（HandlerExceptionResolver）
    initViewResolvers(context);              // ⑦ 视图解析（ViewResolver 列表）
    initFlashMapManager(context);            // ⑧ 闪存（FlashMapManager，重定向传参）
}
```

| init 方法 | 缺省行为（找不到 Bean 时） | Boot 4 默认实现 |
|----------|--------------------------|----------------|
| initHandlerMappings | 报错/空路由表 | RequestMappingHandlerMapping 等 5 个 |
| initHandlerAdapters | 同上 | RequestMappingHandlerAdapter 等 3 个 |
| initHandlerExceptionResolvers | 同上 | ExceptionHandler / ResponseStatus / Default |
| initViewResolvers | 空（无视图能力） | Thymeleaf（引入 starter-thymeleaf 时） |
| initMultipartResolver | 无（上传功能关闭） | StandardServletMultipartResolver |

> ⚠️ 版本差异：Spring 6.0 时代的 `initRequestToViewNameTranslator`（视图名翻译器）在 6.1 已随 `RequestToViewNameTranslator` 一并移除——面试聊旧源码时注意版本口径。

### 组件替换的三种姿势

| 方式 | 写法 | 适用 |
|------|------|------|
| 注入自定义 Bean | 实现接口 + `@Component`（同名 Bean 覆盖） | 整体换实现 |
| 配置回调 | `WebMvcConfigurer` 的 add/configure 方法 | 增删改列表项 |
| 完全接管 | 继承 `WebMvcConfigurationSupport`（Boot 自动配置失效） | 定制全家桶（慎用） |

```java
// 方式一示例：替换全局异常解析器（同名 Bean 覆盖 Boot 默认）
@Component
public class CustomExceptionResolver implements HandlerExceptionResolver {
    @Override
    public ModelAndView resolveException(HttpServletRequest req,
                                         HttpServletResponse resp,
                                         Object handler, Exception ex) {
        resp.setStatus(502);                    // 网关语义
        return new ModelAndView("error-502");
    }
}

// 方式三警告：一旦出现 WebMvcConfigurationSupport 子类，
// Boot 的 WebMvcAutoConfiguration 整体失效——拦截器/转换器/静态资源全部回到默认空配置
```

> ⚠️ 事故高发点：很多人想"自定义 MVC 配置"时把类继承 `WebMvcConfigurationSupport`——结果静态资源 404、JSON 转换全失效；**优先实现 `WebMvcConfigurer` 接口**，它只覆盖你想覆盖的项。

### 八类组件的协作时序

```text
一次页面请求（含视图）的组件协作：
  MultipartResolver（① 仅上传请求时介入）
  → LocaleResolver（② 解析语言）
  → HandlerMapping（④ 路由 + 挂载拦截器）
  → HandlerAdapter（⑤ 执行：参数解析 → 方法 → 返回值处理）
  → HandlerExceptionResolver（⑥ 异常时介入）
  → ViewResolver（⑦ 解析视图）
  → FlashMapManager（⑧ 重定向后取闪存数据）
  ThemeResolver（③ 主题，几乎不用）
```

> 🎯 面试串联题："一次请求八类组件各干什么"——上传请求先过 MultipartResolver；路由失败走异常解析；页面请求最后经 ViewResolver；重定向场景 FlashMapManager 传递数据；**语言解析影响错误消息与页面文案**（配合国际化，见 [Spring-Context-06](../Spring‑Context/06-国际化与资源访问速查.md)）。

### 组件缺失时的表现

| 缺失组件 | 症状 | 排查方向 |
|---------|------|---------|
| HandlerMapping | 所有请求 404（无路由能力） | 启动日志无映射行 |
| HandlerAdapter | 找到处理器但无法执行（500） | `No adapter for handler` 报错 |
| HandlerExceptionResolver | 异常全部裸 500 错误页 | 异常解析链为空 |
| ViewResolver | 页面接口 500（视图名无法解析） | `Could not resolve view with name` |
| MultipartResolver | 上传请求无法解析（文件参数为空） | multipart 未启用 |
| LocaleResolver | 语言恒为默认，国际化不生效 | 请求 Locale 恒 null |

> 💡 生产直觉：**"全站性故障"先怀疑组件装配，局部故障先怀疑业务代码**——例如所有接口 404 是路由层问题，单个接口 404 才是映射写法问题。

## 4. 依赖边界

| 依赖 | 方向 | 说明 |
|------|------|------|
| `spring-web` | 依赖 | HTTP 模型/转换器/客户端（**必需**） |
| `spring-context` / `spring-beans` / `spring-core` | 依赖 | 容器与工具 |
| Servlet API | provided | 运行容器提供 |
| Jackson/Gson | 可选 | JSON 转换器 |
| Thymeleaf/JSP | 可选 | 视图渲染 |
| 反向依赖 | - | spring-boot-starter-web、Security（webmvc 集成）依赖它 |
| 与 webflux | 互斥使用 | 一个应用一个栈（可共存但罕见） |

> ⚠️ **栈选择**：`starter-web`（MVC）与 `starter-webflux` 同时引入时 Boot 会以 MVC 为准——**别混装**；需要响应式就换 webflux starter。

### 传递依赖树（starter-web 视角）

```text
spring-boot-starter-web
├── spring-boot-starter-tomcat（内嵌容器）
├── spring-webmvc
│   ├── spring-web（必需：HTTP 模型/转换器/Filter）
│   │   └── spring-core / spring-context / spring-beans
│   └── Servlet API（provided，容器提供）
└── spring-boot-starter-json（Jackson 3：JsonMapper 等）
```

| 功能需求 | 需要引入的模块 | 说明 |
|---------|--------------|------|
| JSON | starter-json（starter-web 自带） | Jackson 3 + JavaTimeModule 默认 |
| XML | jackson-dataformat-xml | JacksonXmlHttpMessageConverter 生效 |
| 模板页面 | spring-boot-starter-thymeleaf | ThymeleafViewResolver 自动装配 |
| 数据校验 | spring-boot-starter-validation | Hibernate Validator 实现 |
| 文件上传 | 无需额外依赖 | 标准 Servlet 解析（Boot 4 默认） |
| 响应式替代 | spring-boot-starter-webflux | 与 MVC 二选一 |

> 💡 判断"少依赖"问题：415/406 大概率是缺转换器依赖（如要 XML 没引 jackson-dataformat-xml）；模板 404 大概率是缺模板引擎 starter——**先查依赖再查代码**。

### 依赖方向解读

依赖边界要抓住两个"为什么"：

- **为什么 spring-web 是必需？** MVC 的所有 HTTP 模型（`HttpHeaders`、`HttpMessageConverter`、`HttpMethod`）与过滤器基础设施都定义在 spring-web 中，spring-webmvc 只做"Web 层编排"——两者分离让 WebFlux 能共享同一套 HTTP 抽象而不依赖 Servlet。
- **为什么 Servlet API 是 provided？** 运行时容器（Tomcat/Jetty/Undertow）提供 Servlet API，编译期需要、打包期排除——避免应用把 Servlet API 打进 jar 与容器冲突（`NoClassDefFoundError` 或版本冲突多源于此）。

> 💡 一句话记忆：**spring-web 是"HTTP 能力库"，spring-webmvc 是"HTTP 应用框架"**——一个管协议，一个管调度；面试被问"web 和 webmvc 模块区别"就答这句。

### 依赖冲突速查

| 冲突场景 | 表现 | 解法 |
|---------|------|------|
| 同时引 starter-web 与 starter-webflux | MVC 生效、响应式类混入 ClassPath | 移除其一，按栈二选一 |
| Jackson 2 与 Jackson 3 共存 | 转换器类型加载混乱、序列化行为不一致 | 统一由 Boot 4 BOM 管理版本 |
| 多个 Servlet API 版本 | 运行时 `NoSuchMethodError` | 依赖树排除旧版本 |
| 校验依赖缺失 | `@Valid` 静默不生效 | 补 spring-boot-starter-validation |

> ⚠️ 排查铁律：**先 `mvn dependency:tree` 看依赖树，再动代码**——MVC 侧 60% 的"玄学故障"（415/406/校验不生效/序列化异常）根因都在依赖层。

## 5. 版本兼容速查

| Spring Framework | Spring Boot | 备注 |
|------------------|-------------|------|
| 7.0.x（2025-11 起） | Boot 4.0.x | 当前主线；PathPattern 唯一默认、API 版本化、虚拟线程默认 |
| 7.1.x（2026-05 起） | Boot 4.1.x | 最新维护线；DataBinder disallowedFields 废弃 |
| 6.2.x | Boot 3.4/3.5 | 存量主流；ant_path_matcher 策略仍可切 |

> ⚠️ **升级提示（6.x → 7.x）**：① 请求映射通配规则收紧——`/**` 在模式中间需改 PathPattern 写法（或临时 `spring.mvc.pathmatch.matching-strategy=ant_path_matcher`）；② `HttpHeaders` 不再实现 MultiValueMap——以 `MultiValueMap` 类型引用的代码改 `HttpHeaders` 自身 API；③ 自定义转换器类名更新（[Spring-Web-01](../Spring‑Web/01-模块清单.md)）。

### 6.x → 7.x 升级检查清单

| # | 检查项 | 6.x 写法 | 7.x 写法 |
|---|--------|---------|---------|
| 1 | 通配模式 | `/api/**/detail` 可用 | PathPattern 下无效，改 `/api/{*path}` 拆分 |
| 2 | 尾部斜杠 | 可容忍 `/api/x/` | 已移除，按定义路径访问 |
| 3 | 转换器类名 | `MappingJackson2HttpMessageConverter` | `JacksonJsonHttpMessageConverter` |
| 4 | ObjectMapper | `Jackson2ObjectMapperBuilder` | `JsonMapper.builder()` |
| 5 | 头类型 | `MultiValueMap<String, String>` 引用 | `HttpHeaders` 自身 API |
| 6 | 路径后缀 | favorPathExtension 曾可配 | 已移除，禁止后缀协商 |
| 7 | 校验安全 | `disallowedFields` 黑名单 | 构造器绑定 / `allowedFields` 白名单（7.1） |
| 8 | 上传属性 | `spring.servlet.multipart.*` | 同左（属性未变） |

> ⚠️ 建议流程：升级后先跑一遍**全量路由清单**（`/actuator/mappings` 或启动日志对比），再跑接口回归——路由写法问题是 7.0 升级的第一高发区。

### 升级常见报错对照

| 报错/现象 | 根因 | 处理 |
|----------|------|------|
| 启动报"重复映射" | 7.0 通配规则变化后两个映射条件等价 | 检查 `/**` 写法与条件差异 |
| 接口全部 404 | ant 中间通配写法失效 | 改 PathPattern 写法（见 [03 篇第 6 节](03-控制器与请求映射速查.md)） |
| `ClassNotFoundException`（JacksonJson...） | 引用了 6.x 旧类名 | 改 7.0 新类名 |
| `NoSuchMethodError` | 模块混版本 | 统一 Framework 版本 |
| 静态资源 404 | 自定义配置误继承 WebMvcConfigurationSupport | 改实现 WebMvcConfigurer |

### 版本选择决策

| 你的处境 | 建议版本 | 理由 |
|---------|---------|------|
| 新项目（2026） | Framework 7.0/7.1 + Boot 4 | 当前主线，PathPattern/虚拟线程/API 版本化 |
| 存量 Boot 3 应用 | 6.2.x（可规划升 7） | 稳定维护中，生态兼容 |
| 刚需 CORS 预检过滤 | 7.1+ | PreFlightRequestFilter 在 7.1 引入 |
| 需要 disallowedFields 旧行为 | 6.2.x（7.1 起废弃） | 7.1 建议迁移到构造器绑定 |
| 强依赖 Servlet API 旧行为 | 6.2.x | 7.0 起 Jakarta EE 11 基线 |

> 💡 升级节奏建议：先升 Boot 小版本（3.4 → 3.5）把代码修干净，再一次性跨到 Boot 4（Framework 7）——跨大版本时重点回归**路由写法、转换器类名、HttpHeaders 类型**三处，其余注解 API 基本兼容；每个阶段留出完整回归窗口，别在发版前夜升级。多环境滚动：先在测试环境全量回归（接口清单对比 + 核心链路压测），确认无 404/415/406 类故障再上预发。
