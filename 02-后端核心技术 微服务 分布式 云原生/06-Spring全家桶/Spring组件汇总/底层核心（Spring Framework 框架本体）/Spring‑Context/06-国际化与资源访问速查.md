## 1. MessageSource 体系

| 组件 | 职责 |
|------|------|
| `MessageSource` | `getMessage(code, args, defaultMessage, locale)` |
| `ResourceBundleMessageSource` | ✅ 标准实现：基于 JDK ResourceBundle |
| `ReloadableResourceBundleMessageSource` | 支持热重载（开发期友好，cacheSeconds） |
| `StaticMessageSource` | 编程式注册消息（测试用） |
| `DelegatingMessageSource` | 默认空实现（未配置时返回 code 本身） |

```text
getMessage 解析流程：
  ① 按 code 查找 messages.properties（basename 默认 "messages"）
  ② 无默认 MessageSource → DelegatingMessageSource 返回 code 原样
  ③ {0} {1} 参数占位 → getMessage("order.created", new Object[]{id}, locale)
```

```java
@Service
public class I18nService {
    private final MessageSource ms;

    public String msg(String code, Object... args) {
        return ms.getMessage(code, args, LocaleContextHolder.getLocale());
    }
}
```

> 🎯 **核心要点**：MessageSource 是**纯进程内**消息解析——不含翻译服务、不含持久化；业务上"提示文案国际化"用它，"界面多语言资源"常交给前端。刷新时机：refresh 第 7 步 `initMessageSource`，Bean 名为 `messageSource`。

## 2. 资源文件与消息解析规则

```properties
# messages.properties（默认）
order.created=订单 {0} 已创建，金额 {1}
error.not.found=记录不存在

# messages_zh_CN.properties（中文）
order.created=订单 {0} 已创建，金额 {1}

# messages_en.properties（英文）
order.created=Order {0} created, amount {1}
```

| 特性 | 说明 |
|------|------|
| basename | 默认 `messages`，可 `setBasename("i18n/messages")` 分包 |
| 回退链 | `zh_CN` → `zh` → 默认 → code 原样 |
| 占位符 | `{0}` `{1}` 位置参数 |
| 编码 | **必须 UTF-8**（7.x 默认 UTF-8；旧版需 setDefaultEncoding） |
| 热重载 | `ReloadableResourceBundleMessageSource` + `cacheSeconds` |

```java
@Bean
public MessageSource messageSource() {
    ReloadableResourceBundleMessageSource ms = new ReloadableResourceBundleMessageSource();
    ms.setBasename("classpath:i18n/messages");
    ms.setDefaultEncoding("UTF-8");
    ms.setCacheSeconds(60);   // 开发期可设 1 秒
    return ms;
}
```

> ⚠️ 常见坑：属性文件保存为 GBK 时中文乱码——确认编辑器/CI 以 UTF-8 写入；`locale=zh_CN` 文件名格式是 `messages_zh_CN`（下划线）。

## 3. Locale 解析与切换

| 组件 | 用途 | 归属 |
|------|------|------|
| `LocaleContextHolder` | 线程绑定当前 Locale（`setLocale`/`getLocale`） | context |
| `RequestContext` / `RequestContextHolder` | Web 请求上下文（内含 Locale） | web 模块 |
| `LocaleResolver` | 请求 → Locale 解析策略 | web 模块 |
| `AcceptHeaderLocaleResolver`（默认） | 从 Accept-Language 头取 | web 模块 |
| `CookieLocaleResolver` | Cookie 记忆用户语言 | web 模块 |
| `SessionLocaleResolver` | 会话级语言 | web 模块 |

```java
// 请求级切换（Web 场景）：URL 参数 ?lang=en → 写入 SessionLocaleResolver 后刷新
@PostMapping("/locale")
public void changeLocale(@RequestParam String lang, HttpSession session) {
    session.setAttribute(SessionLocaleResolver.LOCALE_SESSION_ATTRIBUTE_NAME,
                         Locale.forLanguageTag(lang));
}
```

> 💡 归属边界：`LocaleContextHolder` 在 spring-context；`LocaleResolver` 族在 spring-web——纯 context 应用（无 Web）直接用 `LocaleContextHolder.setLocale()` 绑定。

## 4. Resource 抽象速查

`Resource` 是 Spring 对"可读取资源"的统一抽象（**接口定义在 spring-core 的 `org.springframework.core.io`**）：

```text
Resource（getInputStream / getFilename / exists / getURI ...）
├── ClassPathResource       classpath:xxx       类路径资源
├── FileSystemResource      file:/path/xxx      文件系统
├── UrlResource             http:// / https:// / ftp://  URL 资源
├── ByteArrayResource       -                    字节数组内存资源
├── InputStreamResource     -                    一次性输入流
└── WritableResource        FileSystemResource 实现（可写）

加载器：
  ResourceLoader.getResource("classpath:...")       按前缀解析（前缀缺省取决于实现）
  ResourcePatternResolver.getResources("classpath*:**/*.xml")  模式解析 ★
  PathMatchingPatternResourceResolver：ant 风格通配 ? * ** {var}
```

| 前缀 | 语义 |
|------|------|
| `classpath:` | 类路径单资源 |
| `classpath*:` | **全类路径扫描**（多 jar 内同名资源全收集） |
| `file:` | 文件系统 |
| `http(s):` / `url:` | 远程 URL |
| 无前缀 | 依加载器实现而定（Web 下为 ServletContext 路径） |

> 🎯 **核心要点**：`classpath*:` 与 `classpath:` 的差异是高频考点——前者扫描**所有**类路径（多 jar 同名资源全部返回），后者只取**第一个**；扫描配置类、自动配置文件（`spring.factories`、`META-INF/spring.components`）都用前者。

## 5. 模式加载与 @Value 注入资源

```java
// ① @Value 注入 Resource（最常用，Spring 自动用 ResourceEditor 转换）
@Service
public class TemplateService {
    @Value("classpath:templates/email.html")
    private Resource emailTemplate;

    public String read() throws IOException {
        return Files.readString(emailTemplate.getFile().toPath());   // 或 getInputStream()
    }
}

// ② 注入 ResourceLoader 按需加载
@Service
public class FileService {
    private final ResourcePatternResolver resolver = new PathMatchingPatternResourceResolver();

    public List<String> loadMappers() throws IOException {
        Resource[] rs = resolver.getResources("classpath*:mapper/*.xml");
        return Arrays.stream(rs).map(Resource::getDescription).toList();
    }
}

// ③ 读取文件内容的安全姿势：getInputStream + StreamUtils（不依赖 getFile 存在性）
String content = StreamUtils.copyToString(res.getInputStream(), StandardCharsets.UTF_8);
```

> ⚠️ **典型坑**：打包成 jar 后 `resource.getFile()` 抛 `FileNotFoundException`（类路径资源在 jar 内不是文件）——**统一用 `getInputStream()`** 读取；`getDescription()` 用于日志展示。
