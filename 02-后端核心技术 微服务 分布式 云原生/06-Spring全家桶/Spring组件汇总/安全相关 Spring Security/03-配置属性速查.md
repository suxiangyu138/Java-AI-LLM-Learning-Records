## 1. 基础属性

```yaml
spring:
  security:
    user:
      name: admin
      password: "{noop}123456"        # {noop} 明文标记（仅演示）
      roles: USER,ADMIN
    filter:
      order: -100                     # 安全过滤器链在容器过滤器中的注册顺序
```

| 属性 | 默认 | 说明 |
|------|:---:|------|
| `spring.security.user.name` | `user` | 默认用户名（无自定义 UserDetailsService 时） |
| `spring.security.user.password` | 启动日志随机 | 默认密码（生产必须覆盖） |
| `spring.security.user.roles` | 无 | 默认用户角色 |
| `spring.security.filter.order` | -100 | 过滤器链顺序（自定义 Filter 相对定位用） |

> ⚠️ **注意**：自定义 `UserDetailsService` 后默认用户自动失效；`{noop}` 明文前缀仅限演示/测试，生产必须真实编码。

## 2. 默认用户

```text
无自定义 UserDetailsService 时，Boot 自动配置：
  user / <随机密码>（打印在启动日志）

覆盖方式：
  ① spring.security.user.name/password 属性（简单场景）
  ② 自定义 UserDetailsService Bean（生产标准，见 02-核心类速查）
  ③ 内存 InMemoryUserDetailsManager（测试）
```

## 3. 过滤器链顺序

```yaml
spring:
  security:
    filter:
      order: -100
```

**顺序语义**（与其它 Servlet 组件）：

```text
负数 order < 0 的 Filter（Security 链 -100） → 先于应用自定义 Filter
Security 链内部顺序由框架固定（SecurityContextHolder → CSRF → 认证 → 授权）
```

> 💡 **自定义 Filter 的定位**：想在安全链**之后**取登录用户 → order 大于 -100；想在**之前**（如统一编码）→ order 更小。**安全相关逻辑优先用 Security 体系**（拦截器/过滤器），避免自造轮子绕过链。

## 4. OAuth2 客户端

```yaml
spring:
  security:
    oauth2:
      client:
        registration:                    # 客户端注册（可多个）
          github:                        # 注册名（任意）
            client-id: xxx
            client-secret: xxx
            scope: read:user,user:email
            authorization-grant-type: authorization_code   # 7.x 默认 + PKCE
            redirect-uri: "{baseUrl}/login/oauth2/code/{registrationId}"
          company:
            provider: company-issuer     # 引用下面的 provider
            client-id: app-001
            client-secret: secret
            client-authentication-method: client_secret_basic
            scope: openid,profile,email
        provider:
          company-issuer:
            issuer-uri: https://auth.example.com     # OIDC 自动发现
            # 或手动指定：
            # authorization-uri: ...
            # token-uri: ...
            # jwk-set-uri: ...
            # user-info-uri: ...
```

| 属性组 | 关键项 |
|--------|--------|
| `registration` | client-id/secret、scope、grant-type、redirect-uri |
| `provider` | issuer-uri（推荐）或手动端点 |

> ⚠️ **7.x 注意**：PKCE 默认强制（requireProofKey=true），无需配置；对接老授权服务器不支持 PKCE 时握手失败——需评估对方。

## 5. OAuth2 资源服务器

```yaml
spring:
  security:
    oauth2:
      resourceserver:
        jwt:
          issuer-uri: https://auth.example.com        # 方式一：自动发现 jwks
          # jwk-set-uri: https://auth.example.com/.well-known/jwks.json  # 方式二
          # audiences: my-api                         # 受众校验（7.x 推荐开启）
        opaque-token:
          introspection-uri: https://auth.example.com/oauth2/introspect
          client-id: order-service
          client-secret: secret
```

| 属性 | 说明 |
|------|------|
| `jwt.issuer-uri` | 从签发方自动发现公钥（推荐） |
| `jwt.jwk-set-uri` | 显式指定公钥端点 |
| `jwt.audiences` | 受众白名单（防令牌跨服务复用） |
| `opaque-token.*` | 不透明令牌 introspection 配置 |

> 💡 **7.x 默认**：JWT `typ` 头校验默认开启（混淆攻击防护）；`aud` 校验需显式配置 `audiences` 或自定义 JwtDecoder。

## 6. 安全相关杂项

```yaml
# 认证与会话
spring:
  mvc:
    login:
      default-success-url: /home        # 登录成功跳转（Boot 属性）

# 非 Security 但强相关的安全配置
server:
  servlet:
    session:
      cookie:
        http-only: true                 # 防 JS 读取 Cookie（XSS 缓解）
        secure: true                    # 仅 HTTPS 传输
        same-site: lax                  # SameSite 策略（CSRF 缓解）
```

| 配置 | 作用 |
|------|------|
| `cookie.http-only` | 阻断 XSS 窃取 Session Cookie |
| `cookie.secure` | Cookie 仅 HTTPS 发送 |
| `cookie.same-site` | 限制跨站携带（CSRF 第二道防线） |

> 🎯 **速查结论**：`spring.security.*` 只覆盖"自动配置能表达的部分"——**登录页、CSRF、授权规则、多因素等都在 Java 配置（HttpSecurity DSL）里写**。记住分界：属性管"基础设施"，DSL 管"安全策略"。
