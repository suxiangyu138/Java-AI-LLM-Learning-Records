## 1. 应用与服务器

| 属性 | 默认值 | 说明 |
|------|--------|------|
| `spring.application.name` | — | 应用名（服务发现/日志/指标标签） |
| `server.port` | 8080 | 端口（0 = 随机端口） |
| `server.servlet.context-path` | `/` | 上下文路径（MVC） |
| `spring.webflux.base-path` | — | WebFlux 基础路径 |
| `server.tomcat.*` / `server.netty.*` | — | 内嵌服务器细节（线程池/超时） |
| `spring.main.banner-mode` | console | 启动横幅 |
| `spring.main.web-application-type` | auto | none/servlet/reactive |

```yaml
spring:
  application:
    name: order-service
server:
  port: 8080
```

> 🎯 **高频三配**：`application.name`（一切可观测的标签）、`server.port`、`context-path`/`base-path`（统一前缀）。

## 2. 线程与虚拟线程

| 属性 | 默认值 | 说明 |
|------|--------|------|
| `spring.threads.virtual.enabled` | `false` | 全局虚拟线程开关（SF 7 原生支持） |
| `spring.task.execution.pool.core-size` | 8 | @Async 线程池核心数 |
| `spring.task.execution.pool.max-size` | 2147483647 | @Async 最大线程数 |
| `spring.task.execution.pool.queue-capacity` | 2147483647 | 队列容量 |
| `spring.task.execution.thread-name-prefix` | task- | 线程名前缀（排障） |
| `spring.task.scheduling.*` | — | @Scheduled 调度器配置 |

```yaml
spring:
  threads:
    virtual:
      enabled: true        # 高并发阻塞业务：MVC + 虚拟线程组合
  task:
    execution:
      thread-name-prefix: async-
```

> 💡 虚拟线程开启后注意：**池大小属性被忽略（虚拟线程无需池）**；ThreadLocal 传播与 pinning 陷阱见 Spring Task 深度体系（卡片 04 链接）。

## 3. 日志与监控

| 属性 | 默认值 | 说明 |
|------|--------|------|
| `logging.level.<包名>` | info | 按包设日志级别 |
| `logging.file.name` / `logging.file.path` | — | 文件输出 |
| `logging.pattern.*` | — | 输出格式（控制台/文件） |
| `management.endpoints.web.exposure.include` | health | Actuator 暴露端点 |
| `management.endpoint.health.show-details` | never | 健康详情（生产慎开） |
| `management.metrics.tags.*` | — | 指标全局标签 |
| `management.otlp.*` / `management.opentelemetry.*` | — | OTel 导出配置（4.1 增强） |
| `logging.logback.rollingpolicy.*` | — | 轮转策略（4.1 支持四类） |

```yaml
logging:
  level:
    com.example.mapper: debug
  file:
    name: /var/log/app.log
management:
  endpoints:
    web:
      exposure:
        include: health,info,metrics,loggers
```

> 🎯 生产标配：**health + metrics + loggers 暴露、文件日志、全局标签（应用名/环境）**——可观测三件套的配置侧。

## 4. 配置加载与 Profile

| 属性/机制 | 说明 |
|----------|------|
| `spring.profiles.active` | 激活环境（dev/prod） |
| `spring.config.import` | 引入外部配置文件（`optional:configserver:` 等） |
| `spring.config.additional-location` | 附加配置目录 |
| 配置优先级 | 命令行 > 环境变量 > application-{profile}.yml > application.yml > 默认 |
| `spring.profiles.group` | profile 分组（dev 组包含多个子 profile） |

```bash
# 命令行最高优先级（容器/CI 常用）
java -jar app.jar --server.port=8081 --spring.profiles.active=prod
```

> 🎯 配置心智模型：**默认值写 yml、环境差异写 profile、敏感信息走环境变量/密钥管理**——别把密钥提交进 application.yml。

## 5. 常用组合模板

```yaml
# 生产服务模板（Boot 4.x）
spring:
  application:
    name: order-service
  profiles:
    active: prod
  threads:
    virtual:
      enabled: true            # MVC + 虚拟线程（阻塞业务高并发）
  task:
    execution:
      thread-name-prefix: async-
server:
  port: 8080
logging:
  level:
    root: info
  file:
    name: /var/log/order-service.log
management:
  endpoints:
    web:
      exposure:
        include: health,info,metrics,loggers,prometheus
  metrics:
    tags:
      application: ${spring.application.name}
```

> 🎯 一句话：**应用名 + 虚拟线程 + 文件日志 + Actuator 四件套**——一个生产应用的最小可观测配置；更多属性（数据源/Redis/MQ 等）见各组件卡片 03 与深度体系 [02-SpringBoot配置体系](../../SpringBoot/02-SpringBoot配置体系.md)。
