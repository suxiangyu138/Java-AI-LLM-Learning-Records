## 1. 启动入口

| 类/注解 | 职责 |
|---------|------|
| `@SpringBootApplication` | 三合一：@Configuration + @EnableAutoConfiguration + @ComponentScan |
| `SpringApplication` | 启动器：`.run()`、`setBannerMode`、`setWebApplicationType` |
| `SpringApplicationBuilder` | 链式构建（多上下文/分层启动） |
| `ApplicationRunner` / `CommandLineRunner` | 启动后执行（@Order 控制顺序） |
| `ApplicationListener` / 事件 | 启动生命周期钩子（ApplicationReadyEvent 等） |
| `@Lazy` / `@Order` | 装配与执行顺序 |

```java
@SpringBootApplication
public class App {
    public static void main(String[] args) {
        SpringApplication app = new SpringApplication(App.class);
        app.setBannerMode(Banner.Mode.OFF);
        app.run(args);
    }
}

@Component
class DataSeeder implements ApplicationRunner {   // 启动后初始化
    @Override
    public void run(ApplicationArguments args) { /* ... */ }
}
```

> 🎯 **要点**：启动即"自动配置 + 组件扫描 + 属性绑定"三件事；Runner 是启动钩子的标准入口（区别于 @PostConstruct——后者在代理完整前执行）。

## 2. 自动配置与条件注解

| 注解 | 条件 | 典型用途 |
|------|------|---------|
| `@ConditionalOnClass` / `@ConditionalOnMissingClass` | classpath 有无类 | 按依赖启用配置 |
| `@ConditionalOnProperty` | 属性值匹配 | 开关控制（`matchIfMissing`） |
| `@ConditionalOnBean` / `@ConditionalOnMissingBean` | 容器有无 Bean | 用户可覆盖默认 Bean |
| `@ConditionalOnWebApplication` / `@ConditionalOnNotWebApplication` | 应用类型 | Web 专用配置 |
| `@AutoConfiguration` | 标记自动配置类（4.x 官方） | 自定义自动配置入口 |
| `@AutoConfigureAfter/Before` | 顺序控制 | 依赖别的自动配置 |
| `AutoConfiguration.imports` | 注册表文件 | 3.0+ 取代 spring.factories 注册 |

```java
// 自定义自动配置（库作者必备）
@AutoConfiguration
@ConditionalOnClass(MyService.class)
@ConditionalOnProperty(prefix = "my.lib", name = "enabled", matchIfMissing = true)
public class MyLibAutoConfiguration {
    @Bean
    @ConditionalOnMissingBean
    MyService myService() { return new MyService(); }
}
// 注册：META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports
```

> 💡 记忆法：**OnClass=依赖驱动、OnProperty=配置驱动、OnBean=覆盖驱动**——看懂这三个就懂了 Boot 自动配置的 80%。

## 3. 配置绑定

| 注解/API | 职责 |
|---------|------|
| `@ConfigurationProperties(prefix = "app")` | 属性绑定到类（类型安全） |
| `@ConfigurationPropertiesScan` | 扫描注册属性类（替代 @EnableConfigurationProperties 逐个列） |
| `@Value("${prop:default}")` | 单值注入 |
| `@Profile("prod")` | 环境分组 |
| `@Validated` + 约束注解 | 属性校验（启动期失败） |
| `Environment` / `PropertySource` | 编程式访问与自定义属性源 |
| `spring.config.import` | 引入外部配置文件 |
| `ConfigData` | 配置数据 SPI（自定义配置源） |

```java
@ConfigurationProperties(prefix = "app.upload")
public record UploadProperties(
        long maxFileSize,
        List<String> allowedTypes,
        @DefaultValue("oss") String storage) { }

// 绑定：app.upload.max-file-size=5242880
//       app.upload.allowed-types[0]=pdf
```

> 🎯 **要点**：**`@ConfigurationProperties`（类型安全绑定）优先于 `@Value` 散装注入**——聚合配置类 + record + 默认值注解是 4.x 推荐姿势。

## 4. 测试注解

| 注解 | 切面 |
|------|------|
| `@SpringBootTest` | 全容器集成测试 |
| `@WebMvcTest` | 仅 MVC 层（Mock MVC 组件） |
| `@DataJpaTest` | 仅 JPA 层（内存库 + 事务回滚） |
| `@WebFluxTest` | 仅 WebFlux 层 |
| `@RestClientTest` | WebClient/RestTemplate 测试 |
| `@MockBean` / `@MockitoBean`（4.x） | 容器内替换 Mock |
| `@TestConfiguration` | 测试专属配置 |
| `@AutoConfigureMockMvc` / `@AutoConfigureWebTestClient` | 自动化客户端 |

```java
@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)
class OrderControllerTest {
    @Autowired MockMvc mockMvc;

    @Test
    void getOrder() throws Exception {
        mockMvc.perform(get("/orders/1"))
                .andExpect(status().isOk());
    }
}
```

> 💡 切片测试哲学：**@SpringBootTest 是"全链路冒烟"，切片测试是"局部快速反馈"**——按层组合使用，别把所有测试都挂全容器。

## 5. Actuator 端点

| 端点 | 内容 | 用途 |
|------|------|------|
| `/actuator/health` | 健康状态（组件级） | 探针/负载均衡 |
| `/actuator/metrics` | 指标列表与查询 | 监控对接 |
| `/actuator/env` | 环境属性（可脱敏） | 配置排查 |
| `/actuator/info` | 自定义信息 | 版本/构建 |
| `/actuator/mappings` / `/beans` | 路由/Bean 清单 | 调试 |
| `/actuator/loggers` | 日志级别动态调整 | 线上排障 |
| `/actuator/prometheus` | Prometheus 格式 | 监控采集（需 -prometheus） |

```yaml
management:
  endpoints:
    web:
      exposure:
        include: health,info,metrics,loggers,prometheus
  endpoint:
    health:
      show-details: always   # 生产慎用（泄露内部状态）
```

> 🎯 生产三端点：**health（探针）+ metrics/prometheus（监控）+ loggers（动态调日志）**——开箱即用的生产可观测入口。

## 6. 4.x 变化对照

| 维度 | 3.x | 4.x |
|------|-----|-----|
| 基础 | SF 6.2 / Jakarta EE 10 | SF 7 / Jakarta EE 11 |
| 虚拟线程 | 需手动配置 | `spring.threads.virtual.enabled` 原生支持 |
| AOP | proxy-target-class 全局开关 | 全面 CGLIB + `@Proxyable` |
| 结构化并发 | — | JEP 453 支持 |
| gRPC | 手工装配 | 4.1 起 Spring gRPC 1.1 纳入 BOM |
| layertools | jar 模式可用 | 4.1 移除（用 tools） |
| Derby | 可用 | 4.1 弃用（迁 H2/HSQL） |
| 测试 Mock | @MockBean | @MockitoBean（@MockBean 迁移中） |

> ⚠️ 升级 4.1 必做：清 4.0 废弃 API（全部移除）、换 layertools、评估 Derby、`-DskipTests` → `maven.test.skip`——详细清单见 [官方升级说明](https://github.com/spring-projects/spring-boot/wiki)。
