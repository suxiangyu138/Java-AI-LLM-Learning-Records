## 1. 模块总览

```text
spring-boot                   ← 核心：启动器/内嵌服务器/配置处理
spring-boot-autoconfigure     ← 自动配置实现（imports 注册表）
spring-boot-starter           ← 基础 starter（自动配置 + 日志 + 核心）
spring-boot-starter-<能力>    ← 各能力 starter（web/data/security...）
spring-boot-actuator          ← 生产运维端点
spring-boot-test              ← 测试基建
spring-boot-tools             ← 构建工具（4.1 起 layertools 模式移除，用 tools）
spring-boot-dependencies      ← BOM：全家族版本锁定
spring-boot-plugin            ← Maven/Gradle 插件（打包/运行）
```

> 🎯 **要点**：开发者的日常坐标只有三类——**spring-boot-starter-parent（或 BOM）管版本、能力 starter 管依赖、插件管打包**；内部模块一般无需直接引入。

### 1.1 依赖传导链速览

```text
spring-boot-starter-parent（父 POM）
  └── spring-boot-dependencies（BOM：锁定全家版本）
        └── spring-boot-starter-web
              ├── spring-boot-starter（基础：logging + autoconfigure）
              │     └── spring-boot-autoconfigure
              ├── spring-webmvc / spring-web（SF 7）
              └── spring-boot-starter-tomcat（内嵌服务器）
```

> 💡 依赖缺失的第一直觉：**"没有 @SpringBootApplication 的处理" = 缺 spring-boot-autoconfigure（starter 已带）；"没有内嵌服务器" = 缺对应 server starter（web 默认 Tomcat、webflux 默认 Netty）**。

### 1.2 模块一句话全景

| 模块 | 一句话 |
|------|--------|
| spring-boot | 启动引擎：SpringApplication、内嵌服务器、配置处理、应用事件 |
| spring-boot-autoconfigure | 自动配置：AutoConfiguration.imports + @Conditional 体系 |
| spring-boot-starter | 基础集装：自动配置 + logback + 核心依赖 |
| spring-boot-actuator | 生产端点：health/metrics/env/mappings |
| spring-boot-test | 测试基建：@SpringBootTest 等切片注解 |
| spring-boot-tools | 打包工具（layertools 旧模式已移除） |
| spring-boot-dependencies | BOM：全家族版本管理 |
| spring-boot-maven-plugin / gradle-plugin | 运行与打包（可执行 jar/native） |

> 🎯 心智模型：**autoconfigure 是"大脑"（条件装配），starter 是"接口"（一键引入），BOM 是"尺子"（版本唯一），tools 是"手"（打包部署）**。

## 2. 核心模块

| Artifact | 职责 | 关键类 |
|---------|------|--------|
| `spring-boot` | 应用启动与生命周期 | `SpringApplication`、`ApplicationRunner`/`CommandLineRunner`、`Banner`、`SpringApplicationBuilder` |
| `spring-boot-autoconfigure` | 条件自动配置 | `@EnableAutoConfiguration`、`AutoConfigurationImportSelector`、`@ConditionalOnClass/OnProperty/OnBean` |
| `spring-boot-actuator` | 运维端点 | `HealthIndicator`、`@Endpoint`、`MetricsEndpoint` |
| `spring-boot-test` | 测试支持 | `@SpringBootTest`、`@WebMvcTest`、`@DataJpaTest` |
| `spring-boot-tools` | 构建工具 | repackage（可执行 jar）、native（GraalVM） |

> ⚠️ 4.x 结构变化：spring-boot 内部模块化重组（部分能力拆分为更细模块）；`layertools` jar 模式在 4.1 移除——镜像分层构建改用 `tools` 能力。

## 3. Starter 体系地图

| 类别 | Starter | 说明 |
|------|---------|------|
| 基础 | spring-boot-starter | 核心 + 日志（一切项目的底座） |
| Web | -web / -webflux | MVC+Tomcat / 响应式+Netty |
| 数据 | -data-jpa / -data-redis / -data-mongodb / -jdbc / -data-r2dbc | 数据访问全家桶 |
| 消息 | -amqp / -kafka / -integration / -websocket | 消息与集成 |
| 安全 | -security | Spring Security |
| 校验 | -validation | Hibernate Validator |
| 运维 | -actuator | 生产端点 |
| 测试 | -test | 测试全集（含 Testcontainers 支持） |
| 批处理 | -batch | Spring Batch |
| 云原生 | spring-cloud 系列 / Spring gRPC（4.1 起纳入默认管理） | 微服务生态 |

> 💡 4.1 新点：**Spring gRPC 1.1.0 直接进入默认依赖管理**——grpc starter 无需手工对齐版本。

## 4. 依赖什么场景引入什么

| 场景 | 需要的依赖 |
|------|-----------|
| REST API（MVC） | spring-boot-starter-web |
| 响应式 API | spring-boot-starter-webflux |
| JPA 持久化 | + spring-boot-starter-data-jpa + 驱动 |
| Redis | spring-boot-starter-data-redis |
| Kafka / RabbitMQ | spring-boot-starter-kafka / -amqp |
| 安全认证 | spring-boot-starter-security |
| 参数校验 | spring-boot-starter-validation |
| 批处理 | spring-boot-starter-batch |
| 生产监控 | spring-boot-starter-actuator |
| 单元/集成测试 | spring-boot-starter-test |
| gRPC（4.1+） | Spring gRPC starter（BOM 托管） |

```xml
<!-- REST + JPA + 运维的标准组合 -->
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>4.1.0</version>
</parent>
<dependencies>
    <dependency>...spring-boot-starter-web</dependency>
    <dependency>...spring-boot-starter-data-jpa</dependency>
    <dependency>...spring-boot-starter-actuator</dependency>
</dependencies>
```

### 4.1 依赖冲突与版本锁定

| 报错现象 | 根因 | 处理 |
|---------|------|------|
| 版本错乱（NoSuchMethodError 群发） | 未用 BOM/parent | 引入 spring-boot-starter-parent 或 dependencies BOM |
| 同时引 web 与 webflux | 双 Web 栈冲突 | 二选一 |
| gRPC 版本冲突 | 手工管理 Spring gRPC 版本 | 4.1 起交 BOM |
| `-DskipTests` 行为变化 | 4.1 不再跳过 AOT 测试处理 | 用 `maven.test.skip` |

> 🎯 经验法则：**一切依赖版本交给 spring-boot-dependencies BOM**；升级大版本先跑官方"升级检查器"，4.0→4.1 重点是清废弃 API。

## 5. BOM 与版本管理

| 机制 | 作用 |
|------|------|
| spring-boot-starter-parent | 父 POM：BOM + 插件配置 + 资源过滤（Maven 标准姿势） |
| spring-boot-dependencies | 独立 BOM（Gradle / 不使用 parent 时） |
| Spring Initializr | start.spring.io 生成骨架（版本自动对齐） |
| 升级检查器 | 官方工具：升级前的 API 变更清单 |

| Boot 版本线 | SF 配套 | Java | 说明 |
|------------|---------|------|------|
| 4.1.x | SF 7.0.x | 17+（支持至 26） | 当前主线 |
| 4.0.x | SF 7.0.x | 17+ | 年底到期，尽快迁 4.1 |
| 3.5.x | SF 6.2.x | 17+ | 3.x 收官 |

> 🎯 一句话选型：**parent（或 BOM）管版本 + 能力 starter 管依赖 + 插件管打包**；新项目直接 4.1.0；存量 3.5 项目规划迁移窗口（4.0→4.1 两步走，先清废弃 API）。
