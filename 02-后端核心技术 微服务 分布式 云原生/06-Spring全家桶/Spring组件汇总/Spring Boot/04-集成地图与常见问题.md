## 1. 集成地图

```text
                     ┌──────────────────────────────┐
                     │   spring-boot-starter-parent │
                     │   （BOM：全家族版本唯一）      │
                     └──────────────┬───────────────┘
                                    ▼
        ┌──────────────────────────────────────────┐
        │      SpringApplication（启动引擎）        │
        │  自动配置（imports 注册表 + @Conditional）│
        │  ┌─────────┬─────────┬─────────┬────────┐ │
        │  │ starter-web │ starter-webflux │ starter-data-* │  │
        │  │ starter-security │ starter-batch │ starter-actuator │
        │  └─────────┴─────────┴─────────┴────────┘ │
        │  外部化配置（yml → profile → 环境变量）    │
        └──────────────┬───────────────────────────┘
                       ▼
          可执行 jar / Native Image（GraalVM）
          部署：云主机 / K8s / Docker（tools 分层）
```

## 2. 与生态的集成

| 集成对象 | 方式 | 要点 |
|---------|------|------|
| Spring MVC / WebFlux | starter-web / starter-webflux | 二选一（双栈冲突） |
| Spring Data（JPA/Redis/Mongo…） | starter-data-* | 自动配置数据源/模板 |
| Spring Security | starter-security | 自动安全链 |
| Spring Batch | starter-batch | 6.0 默认无库运行 |
| Spring Cloud | 独立版本线（2025.x/2026.x） | 配置中心/注册中心/网关 |
| gRPC | Spring gRPC 1.1（4.1 纳入 BOM） | server/client 零装配 |
| Actuator + Micrometer + OTel | starter-actuator | 生产可观测（4.1 OTel 增强） |
| Testcontainers | starter-test | 容器化测试 |
| GraalVM Native | 插件 + AOT | 秒启原生镜像 |

> 🎯 集成铁律：**一切通过 starter 接入、版本交 BOM 管理**——手写依赖版本是冲突之源；Spring Cloud 有自己的版本线（与 Boot 4.1 对应），别混用。

## 3. 4.0 → 4.1 升级清单

| 项 | 变化 | 动作 |
|----|------|------|
| 废弃 API | 4.0 废弃的类/方法/属性**全部移除** | 先跑官方升级检查器清理 |
| layertools | jar 模式移除 | 镜像分层改用 `tools` |
| Apache Derby | 弃用（上游项目退役） | 评估迁 H2/HSQL |
| jOOQ 3.20 | 需 Java 21+ | 升级 JDK 或锁旧版 |
| `-DskipTests` | 不再跳过 AOT 测试处理 | 用 `maven.test.skip` |
| Spring gRPC 1.0 | 迁移指南 | 升级前阅读官方迁移文档 |
| 配置属性 | 4.0 废弃属性移除 | 升级检查器列出 |

> ⚠️ **升级顺序**：3.5 → 4.0（先清 3.x 废弃项）→ 4.1（再清 4.0 废弃项）——**不要跨大版本直接跳**；每次升级跑全量测试 + 升级检查器。

## 4. 高频问题速查

| 问题 | 根因 | 处理 |
|------|------|------|
| 启动报"Web application could not be started" | 端口占用 / 双 Web 栈 | 换端口；移除多余 starter |
| @ConfigurationProperties 不绑定 | 类未注册（缺 @ConfigurationPropertiesScan） | 加扫描或 @EnableConfigurationProperties |
| 条件注解配置没生效 | 属性名/条件不匹配 | 查 yml 前缀与 `matchIfMissing` |
| 版本冲突（NoSuchMethodError） | 未走 BOM / 手工版本 | parent/BOM 锁定 |
| `-DskipTests` 行为异常 | 4.1 变更 | maven.test.skip |
| Derby 启动失败 | 4.1 弃用 | 迁 H2/HSQL |
| 虚拟线程配置不生效 | 池属性被忽略 | 理解虚拟线程无需池（见卡片 03） |
| Actuator 端点 404 | 未暴露 | management.endpoints.web.exposure.include |
| @MockBean 报错 | 4.x 迁移中 | 用 @MockitoBean |
| 配置不生效（环境差异） | 优先级/缓存 | 查配置优先级链；检查 profile |

## 5. 排障流程

```text
① 启动层：启动失败看第一行异常（端口/双栈/版本冲突最外层）
② 装配层：Bean 没生效？→ /actuator/beans + conditions（自动配置报告）查条件匹配
③ 配置层：属性没生效？→ /actuator/env 查最终解析值；对比优先级链
④ 依赖层：版本问题？→ mvn dependency:tree 对 BOM
⑤ 运行层：线上异常？→ 指标/日志/动态日志级别（loggers 端点）
```

> 💡 排障三利器：**conditions（自动配置报告）、/actuator/env（配置解析实况）、dependency:tree（版本真相）**——三个"实况视图"能定位 90% 的 Boot 问题。

> 🎯 **核心要点**：集成地图一句话 = "starter 接入 + BOM 锁版本 + Actuator 看实况"；4.1 升级记住"废弃 API 全清 + layertools 移除 + Derby 弃用"三件事。深挖见 [Spring Boot 深度体系](../../SpringBoot/00-SpringBoot总览与核心概念.md)。
