## 1. 集成地图

```text
                     ┌──────────────────────────┐
   触发层            │ Spring Task / Quartz     │ 定时触发（调度与执行分离）
                    │ ShedLock（多实例防重入）  │
                    └────────────┬─────────────┘
                                 ▼
   执行层   Spring Batch 6.0     │  JobLauncher / JobOperator / CommandLineJobOperator
                    ┌────────────┴─────────────┐
                    │  Job → Step → Chunk      │
                    │  JobRepository（元数据）  │─── JDBC / MongoDB / Resourceless
                    └───┬────────┬────────┬───┘
      数据源层          │        │        │
     FlatFile/Kafka  ──┘        │        └──► 输出：DB / 文件 / Kafka / JMS
     JDBC/JPA/HTTP ─────────────┘
                    ┌──────────────────────────┐
   扩展层            │ Spring Integration 7.x   │ 远程分区 / 远程 Chunking / SEDA
                    │ （消息中间件：Kafka/AMQP/JMS/QueueChannel）│
                    └──────────────────────────┘
   观测层   Micrometer（spring.batch.* 指标）+ JFR 事件 + BATCH_* 表 SQL 巡检
```

## 2. 与生态的集成

| 集成对象 | 方式 | 要点 |
|---------|------|------|
| Spring Task | @Scheduled 调 JobLauncher | 防重入：运行中检查（JobExplorer 查 STARTED） |
| ShedLock / Quartz | 分布式锁 / 调度框架 | 多实例单点触发 |
| Spring Integration 7.x | spring-batch-integration | 远程分区/远程 Chunking/SEDA 通道 |
| Kafka / AMQP / JMS | 读写器 + 消息 starter | 消费位点持久化（saveState）、broker 事务 |
| Spring Data JPA / MongoDB | JPA/Hibernate 读写器；Mongo 仓库 | 6.0 移除 Mongo/Neo4j 读写器 |
| Micrometer / JFR | 指标 + 飞行记录 | 6.0 需显式 ObservationRegistry |
| Spring Boot 4 | 自动配置 + starter | 默认无库、GraalVM Native 支持 |
| 云原生（K8s） | 容器化 + 优雅停机 | SIGTERM 优雅停机（6.0 支持） |

> 🎯 集成铁律：**远程执行必须共享 JDBC/Mongo JobRepository**；**调度与执行分离**（Batch 不管什么时候跑）；**非事务写入（文件/Kafka）自带幂等**。

## 3. 高频问题速查

| 问题 | 根因 | 处理 |
|------|------|------|
| Job 启动时自动全跑了 | `spring.batch.job.enabled=true` + 多 Job Bean | 置 false + 显式触发 |
| 同参数重复启动报"实例已存在" | JOB_KEY 唯一约束；COMPLETED 默认不可重跑 | `.allowStartIfComplete(true)` 或换参数/Incrementer |
| 重启失败/参数不兼容 | v5→v6 参数序列化变化 | 迁移前把 v5 FAILED 实例 restart 或 abandon |
| `OptimisticLockingFailureException` | 并发操作同一执行记录 | 启动前查运行中状态；重试操作 |
| `ScopeNotActiveException` + @StepScope | 6.0.4 前本地 chunking 缺陷 | 升级 6.0.4+ |
| 指标不输出 | 缺 ObservationRegistry Bean | 显式提供（6.0 要求） |
| 重启后数据重复 | 写入无幂等键 | ItemKeyGenerator / 唯一键 SQL |
| 游标 reader 极慢 | 未设 fetchSize | `.fetchSize(500)`（Oracle/PG 必须） |
| 多线程 Step 丢数据 | reader 非线程安全 | Paging reader / Synchronized 包装 / 分区替代 |
| 序列 `BATCH_JOB_SEQ` 不存在 | 6.0 改名 | 执行 migration/6.0 迁移脚本 |

## 4. 排障流程

```text
① 依赖层：版本是否 Boot BOM 锁定（Batch 6.0 ↔ Boot 4）？
     └─ 残留 spring-retry / 缺 spring-batch-integration / 旧 import（core.repository.explore…）
② 配置层：job.enabled？initialize-schema？仓库是否 JDBC/Mongo？
     └─ Resourceless 无重启能力；never + 未建表 = 仓库操作报错
③ 执行层：查 BATCH_JOB_EXECUTION / BATCH_STEP_EXECUTION 状态与 EXIT_MESSAGE
     └─ STATUS=FAILED 看 EXIT_MESSAGE；STOPPED 看谁停了它；UNKNOWN 需人工介入
④ 容错层：skip 计数异常？超 skipLimit？重试风暴？
     └─ 查 READ_SKIP_COUNT/WRITE_SKIP_COUNT/PROCESS_SKIP_COUNT + SkipListener 审计表
⑤ 性能层：COMMIT_COUNT 推进慢？LAST_UPDATED 长时间不动？
     └─ fetchSize / commit-interval / 索引 / 连接占用
```

> 💡 排障三利器：**元数据表（状态与计数）、SkipListener 审计（跳了啥）、JFR/指标（卡在哪）**——比看业务日志快一个数量级。

> 🎯 **核心要点**：集成地图一句话 = "外部调度触发、Batch 执行、Integration 扩展、元数据驱动一切"；排障从元数据表下手，90% 的"重启不了/跑不动"问题都能在 BATCH_* 表里找到答案。深挖见 [Spring Batch 深度体系](../../../Spring Batch/00-Spring Batch知识体系总览.md)。
