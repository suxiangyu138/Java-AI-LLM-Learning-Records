## 1. spring.batch.* 属性表

| 属性 | 默认值 | 说明 |
|------|--------|------|
| `spring.batch.job.enabled` | `true` | 启动时是否自动运行容器中的 Job Bean |
| `spring.batch.job.name` | — | 指定要自动运行的 Job 名（逗号分隔） |
| `spring.batch.jdbc.initialize-schema` | `embedded` | `always` / `embedded` / `never`：元数据建表策略 |
| `spring.batch.jdbc.table-prefix` | `BATCH_` | 元数据表前缀 |
| `spring.batch.jdbc.isolation-level-for-create` | `ISOLATION_DEFAULT` | 创建元数据记录的事务隔离级别 |
| `spring.batch.jdbc.driver-class-name` | 自动 | JDBC 仓库驱动（一般无需配） |
| `spring.batch.jdbc.url` / `username` / `password` | 自动 | 指定批处理专用数据源（更常用的是 @EnableJdbcJobRepository dataSourceRef） |

```yaml
spring:
  batch:
    job:
      enabled: false            # 生产标配：关闭自动跑 Job，改为显式触发
    jdbc:
      initialize-schema: never  # 生产：表由 DBA/发布脚本建
      table-prefix: BATCH_
```

> 🎯 **生产三件套**：`job.enabled=false` + `jdbc.initialize-schema=never` + 显式触发（JobLauncher/JobOperator/调度平台）。

## 2. 作业启动策略配置

| 场景 | 配置 | 说明 |
|------|------|------|
| 单 Job 启动即跑（演示/简单任务） | `spring.batch.job.enabled=true` + `spring.batch.job.name=job1` | 只在无其他 Job 时安全 |
| 多 Job 显式触发（生产） | `spring.batch.job.enabled=false` | 代码注入 JobLauncher/JobOperator 触发 |
| 定时触发 | Spring Task `@Scheduled` + JobLauncher | 需防重入（运行中检查） |
| 多实例防重复 | ShedLock / 外部调度 + JOB_KEY 唯一约束 | 元数据层兜底 |

> ⚠️ 常见事故：`job.enabled=true` 且容器里有多个 Job Bean——**启动时全部自动执行**；加 Job 后忘了关开关是生产首坑。

## 3. 元数据初始化配置

| 取值 | 行为 | 适用 |
|------|------|------|
| `always` | 每次启动执行建表脚本（幂等 DDL） | 开发/测试（H2 等） |
| `embedded` | 仅嵌入式库（H2/HSQL）时初始化 | Boot 默认；开发环境 |
| `never` | 不初始化 | **生产**（脚本在 spring-batch-core 的 `org.springframework.batch.core` 包：schema-postgresql.sql / schema-mysql.sql / schema-oracle.sql…） |

```bash
# 生产建表（例：PostgreSQL，脚本来自依赖 jar 内）
psql -f schema-postgresql.sql your_db
```

> 💡 6.0 迁移注意：升级后需执行迁移脚本（`org.springframework.batch.core.migration/6.0`）完成序列改名 `BATCH_JOB_SEQ → BATCH_JOB_INSTANCE_SEQ`。

## 4. 仓库定制配置

| 需求 | 做法 |
|------|------|
| 批处理元数据独立库 | `@EnableJdbcJobRepository(dataSourceRef = "batchDataSource", transactionManagerRef = "batchTransactionManager")` |
| 表前缀隔离（多租户） | `@EnableJdbcJobRepository(tablePrefix = "T1_")` 或 `spring.batch.jdbc.table-prefix` |
| MongoDB 仓库 | `@EnableMongoJobRepository` + starter-data-mongodb |
| 无库快速验证 | 什么都不配（默认 Resourceless） |
| 深定制 | 继承 `JdbcDefaultBatchConfiguration` / `MongoDefaultBatchConfiguration` / `DefaultBatchConfiguration` |

```java
// 元数据与业务库分离（生产推荐架构）
@Configuration(proxyBeanMethods = false)
@EnableBatchProcessing(taskExecutorRef = "batchTaskExecutor")
@EnableJdbcJobRepository(dataSourceRef = "batchDataSource",
        transactionManagerRef = "batchTransactionManager")
class BatchInfraConfig {
    @Bean
    DataSource batchDataSource() { /* 批处理专用数据源 */ }
    // ... batchTransactionManager、batchTaskExecutor
}
```

> ⚠️ 6.0 注意：数据源相关配置从 `@EnableBatchProcessing` 拆到 `@EnableJdbcJobRepository`——5.x 的 `@EnableBatchProcessing(dataSourceRef=...)` 写法在 6.0 已不成立。

## 5. 与 6.0 默认行为的配合

| 6.0 默认行为 | 属性/配置影响 |
|-------------|--------------|
| 默认 Resourceless 仓库（无库运行） | 生产必须显式配 JDBC/Mongo 仓库，否则无重启/审计/监控 |
| 默认 ResourcelessTransactionManager | 配 JDBC 仓库后需显式提供 PlatformTransactionManager |
| 无 ObservationRegistry 时指标不采集 | 提供 ObservationRegistry Bean（Micrometer 全局注册表已弃用） |
| JobRegistry 自动注册 | 无需 JobRegistrySmartInitializingSingleton（已废弃） |

> 🎯 配置心智模型：**yaml 只管"启动开关 + 建表策略"，仓库与数据源归属走注解（@EnableJdbcJobRepository），事务/线程池/监控走 Bean 配置**——三者各司其职。
