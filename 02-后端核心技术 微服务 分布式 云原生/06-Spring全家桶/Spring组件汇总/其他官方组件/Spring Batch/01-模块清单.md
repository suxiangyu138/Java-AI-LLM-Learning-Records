## 1. 模块总览

```text
spring-batch-core            ← 领域模型/JobRepository/执行引擎（一切批处理的根）
spring-batch-infrastructure  ← 全部 ItemReader/ItemWriter 实现（文件/JDBC/JPA/Kafka…）
spring-batch-integration     ← 与 Spring Integration 7 的桥接（远程分区/Chunking/SEDA）
spring-batch-test            ← 测试工具（JobOperatorTestUtils、JobRepositoryTestUtils）
```

> 🎯 **要点**：`spring-boot-starter-batch` 只打包 core + infrastructure——**远程执行类能力需要额外引入 spring-batch-integration**，测试能力需要 `spring-boot-starter-batch-test`（独立 starter，不随主 starter 传递）。

### 1.1 依赖传导链速览

```text
spring-boot-starter-batch
  ├── spring-batch-core              ← 执行引擎 + 领域对象（必带）
  └── spring-batch-infrastructure    ← 读写器全家桶（必带）
spring-boot-starter-batch-test
  ├── spring-batch-test              ← 测试工具
  ├── spring-boot-starter-batch
  └── spring-boot-starter-test
spring-batch-integration（按需）
  └── spring-integration-core        ← 消息通道（7.x）
```

> 💡 依赖缺失的第一直觉：**报 `ClassNotFoundException: org.springframework.batch.item.file.FlatFileItemReader` = infrastructure 缺失（不太可能，starter 已带）；报 `MessageChannel` 相关 = 缺 spring-batch-integration**。

### 1.2 模块一句话全景

| 模块 | 一句话 |
|------|--------|
| spring-batch-core | 执行引擎：Job/Step/仓库/容错/流程控制 |
| spring-batch-infrastructure | 工具库：全部官方 reader/writer 实现 |
| spring-batch-integration | 桥接层：远程分区、远程 Chunking、异步通道 |
| spring-batch-test | 测试基建：Job 启动/元数据清理/上下文注解 |
| spring-batch-docs | 参考文档（不引入） |

> 🎯 心智模型：**core 是"发动机"，infrastructure 是"挂载的工具箱"，integration 是"接上外部世界的排气管"，test 是"试车台"**——日常业务只需发动机 + 工具箱。

## 2. 核心模块

| Artifact | 职责 | 关键类（包） |
|---------|------|-------------|
| `spring-batch-core` | 领域模型、JobRepository、执行引擎、容错 | `Job`/`JobExecution`（core.job）、`StepBuilder`（core.step）、`JobRepository`（core.repository）、`JobParameters`（core.job.parameters） |
| `spring-batch-infrastructure` | 读写器与处理器实现 | `FlatFileItemReader`、`JdbcBatchItemWriter`（item.file / item.database / item.function…） |

> ⚠️ **6.0 包改名提醒**：`core.explore` → `core.repository.explore`；DAO → `core.repository.dao.jdbc|mongo`；监听器 → `core.listener`——升级时旧 import 会直接编译失败，按新包重导。

### 2.1 infrastructure 内部结构

```text
org.springframework.batch.item
├── file        # 平面文件/JSON/XML 读写（FlatFileItemReader 等）
├── database    # JDBC 游标/分页、JdbcBatchItemWriter
├── jpa / hibernate / mongo / neo4j   # 各 ORM 读写器（6.0 移除 mongo/neo4j）
├── kafka / jms / amqp                # 消息读写器
├── support      # ListItemReader、ItemReaderAdapter 等基础件
├── function     # 5.2+ 函数适配器（SupplierItemReader/ConsumerItemWriter/…）
└── validate     # ValidatingItemProcessor、Validator 体系
```

> 💡 6.0 移除项：MongoItemReader/Writer、Neo4jItemReader/Writer（已废弃多时）——Mongo 场景用自定义 reader（基于 Spring Data Mongo 流式查询）。

### 2.2 core 内部结构

```text
org.springframework.batch.core
├── job          # Job/JobExecution/JobInstance、JobBuilder、JobLauncher
├── job.parameters   # 6.0 独立包：JobParameters/JobParameter（record）
├── step         # Step/StepExecution、StepBuilder、tasklet/partition
├── repository   # JobRepository/JobExplorer（6.0 上提）+ dao.jdbc|mongo
├── listener     # 四层监听器 + Skip/Retry 监听器
├── configuration  # @EnableBatchProcessing、DefaultBatchConfiguration 族
└── launcher     # JobLauncher、TaskExecutorJobOperator、CommandLineJobOperator
```

## 3. 辅助模块

| Artifact | 职责 | 引入时机 |
|---------|------|---------|
| `spring-batch-integration` | Spring Integration 桥接：MessageChannelPartitionHandler、RemoteChunkingManager/Worker、JobLaunchingGateway | 远程分区/远程 Chunking/SEDA 流水线 |
| `spring-batch-test` | JobOperatorTestUtils、JobRepositoryTestUtils、@SpringBatchTest | 任何 Job 测试（走 starter-batch-test） |
| `spring-batch-docs` | 官方文档产物 | 不引入 |

```xml
<!-- 远程执行场景：必加 integration 模块 -->
<dependency>
    <groupId>org.springframework.batch</groupId>
    <artifactId>spring-batch-integration</artifactId>
</dependency>
```

> 💡 远程执行三要素：spring-batch-integration + 消息中间件客户端（Kafka/AMQP/JMS）+ **共享的 JDBC/Mongo JobRepository**（Resourceless 不可用）。

## 4. 依赖什么场景引入什么

| 场景 | 需要的依赖 |
|------|-----------|
| 基础批处理（文件→库） | `spring-boot-starter-batch`（+ 数据库驱动/starter-jdbc） |
| 单元/集成测试 Job | + `spring-boot-starter-batch-test` |
| 远程分区 / 远程 Chunking | + `spring-batch-integration` + 消息中间件 starter（kafka/amqp/jms） |
| MongoDB 元数据仓库 | + `spring-boot-starter-data-mongodb`（5.2+ 支持） |
| 数据库（JDBC 仓库或业务库） | + `spring-boot-starter-jdbc` + 驱动（默认无库运行，不配也能跑） |
| 纯 Spring（非 Boot） | spring-batch-core + spring-batch-infrastructure + spring-tx + 数据源 |

### 4.1 依赖冲突与版本锁定

| 报错现象 | 根因 | 处理 |
|---------|------|------|
| `NoSuchMethodError`（batch 相关） | batch 版本与 Boot 不配套 | 交给 Boot BOM 锁定版本（当前 6.0.4） |
| `ClassNotFoundException: MessageChannel` | 缺 spring-batch-integration | 远程执行场景补依赖 |
| Spring Retry 类缺失/冲突 | 6.0 已不用 spring-retry（改用 SF7 内置） | 移除手工 spring-retry 依赖，验证代码走 SF7 RetryTemplate |
| `BATCH_JOB_SEQ` 序列不存在 | 6.0 改名 `BATCH_JOB_INSTANCE_SEQ` | 执行官方迁移脚本（spring-batch-core 的 migration/6.0） |

> 🎯 经验法则：**batch 相关依赖一律用 Boot BOM 管理**；6.0 迁移期最常见的三个依赖问题 = spring-retry 残留、缺 integration 模块、旧序列名。

### 4.2 版本线对照

| Boot 版本 | Batch 版本线 | 说明 |
|-----------|-------------|------|
| Boot 4.0.x | 6.0.x（当前 6.0.4） | 当前主线，SF 7 |
| Boot 3.5.x | 5.2.x（收官 5.2.6） | 存量系统，已停止开源维护 |
| Boot 3.x 早期 | 5.1.x | 仅商业维护 |

> ⚠️ **禁止混搭**：Batch 6.0 只能配 Boot 4 / SF 7；Batch 5.x 只能配 Boot 3 / SF 6.x——跨代混搭会触发 API 不兼容（编译期与运行期双炸）。

## 5. Starter 对照

| Starter | 包含 | 适用 |
|---------|------|------|
| `spring-boot-starter-batch` | batch-core + batch-infrastructure + batch 自动配置 | **标准入口（几乎人人都有）** |
| `spring-boot-starter-batch-test` | batch-test + starter-batch + starter-test | 测试专用 |
| `spring-boot-starter-integration` | Spring Integration 全套 | 与 spring-batch-integration 配合做远程执行 |

### 5.1 Boot 自动配置要点（Boot 4）

- 无需 `@EnableBatchProcessing`（Boot 4 自动配置默认开启；深度定制时扩展 `DefaultBatchConfiguration`/`JdbcDefaultBatchConfiguration`/`MongoDefaultBatchConfiguration`）；
- 默认 Resourceless 仓库 + ResourcelessTransactionManager（无库跑通）；
- `spring.batch.job.enabled=false` 关闭启动时自动跑 Job（生产标配，显式触发）。

> 🎯 一句话选型：**基础 = starter-batch；要测 = 加 batch-test；要远程 = 加 integration + 中间件**——永远用 Boot BOM 锁版本。
