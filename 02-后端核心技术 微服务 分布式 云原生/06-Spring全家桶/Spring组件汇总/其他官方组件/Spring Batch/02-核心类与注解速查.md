## 1. 领域对象与构建器

| 类/接口 | 职责 | 说明 |
|---------|------|------|
| `Job` / `JobInstance` / `JobExecution` | 作业定义 / 业务身份 / 一次运行 | 实例由 (JOB_NAME, JOB_KEY=参数哈希) 唯一确定 |
| `Step` / `StepExecution` | 执行单元 / 步骤运行记录 | StepExecution 携带全部计数器 |
| `JobParameters` / `JobParameter` | 启动参数（6.0 record + Set） | 决定实例身份；`JobParametersBuilder` 构建 |
| `ExecutionContext` | 键值状态存储 | 重启断点、Step 间传值 |
| `JobBuilder` / `StepBuilder` | 构建器（6.0 双参构造注入） | `new JobBuilder(name, jobRepository)` |
| `Tasklet` | 单块逻辑执行器 | 返回 RepeatStatus.CONTINUABLE/FINISHED |
| `JobParametersIncrementer` | 自动生成下一组参数 | RunIdIncrementer / SimpleJobParametersIncrementer |

```java
// 6.0 构建器标准形态：JobRepository 构造注入
Step step = new StepBuilder("import", jobRepository)
        .<Order, Order>chunk(500)
        .transactionManager(txManager)
        .reader(reader).processor(processor).writer(writer)
        .build();

Job job = new JobBuilder("orderImport", jobRepository)
        .start(step).next(step2).build();
```

> 🎯 **要点**：6.0 里 `JobBuilderFactory`/`StepBuilderFactory` 已移除；`.chunk(n, tx)` 双参形式废弃，改 `.chunk(n).transactionManager(tx)`。

### 1.1 注解速查

| 注解 | 用途 |
|------|------|
| `@EnableBatchProcessing` | 6.0 中不再必需（Boot 4 默认开启）；深度定制才用（可配 taskExecutorRef） |
| `@EnableJdbcJobRepository` | 6.0 新增：显式配 JDBC 仓库（dataSourceRef/transactionManagerRef/tablePrefix） |
| `@EnableMongoJobRepository` | 6.0 新增：Mongo 仓库 |
| `@StepScope` / `@JobScope` | 步骤/作业级作用域，支持 `#{jobParameters['x']}` / `#{stepExecution...}` 注入 |
| `@Bean`（Job/Step） | Job 与 Step 都是普通 Bean，6.0 自动注册进 JobRegistry |

## 2. ItemReader / ItemProcessor / ItemWriter

| 接口 | 契约 | 关键实现 |
|------|------|---------|
| `ItemReader<T>` | `read()` 返回 null = 数据耗尽 | FlatFileItemReader、JdbcCursorItemReader、JdbcPagingItemReader、JpaCursorItemReader、KafkaItemReader、CompositeItemReader、SupplierItemReader |
| `ItemProcessor<I,O>` | `process()` 返回 null = 过滤本条 | FunctionItemProcessor、PredicateFilteringItemProcessor、ValidatingItemProcessor、CompositeItemProcessor、ClassifierCompositeItemProcessor |
| `ItemWriter<T>` | `write(Chunk)` 一个 chunk 一次调用 | JdbcBatchItemWriter、JpaItemWriter、FlatFileItemWriter、JsonFileItemWriter、KafkaItemWriter、CompositeItemWriter、ClassifierCompositeItemWriter |

```java
// 高配组合：文件读 → 校验 → 函数转换 → JDBC 批写
FlatFileItemReader<Order> reader = new FlatFileItemReaderBuilder<Order>()
        .name("r").resource(resource).linesToSkip(1)
        .delimited().names("id", "customerId", "amount")
        .fieldSetMapper(orderMapper).build();

JdbcBatchItemWriter<Order> writer = new JdbcBatchItemWriterBuilder<Order>()
        .dataSource(ds)
        .sql("INSERT INTO t_order(id, customer_id, amount) VALUES (:id, :customerId, :amount)")
        .beanMapped().build();
```

> 💡 记忆法：**Reader 管"怎么取"，Processor 管"怎么变/滤"，Writer 管"怎么落"**；5.2+ 的 `function` 包（Supplier/Consumer/Predicate 适配器）让三者都能用 lambda 定义。

## 3. 容错：Skip / Retry / 重启

| 能力 | 关键 API | 说明 |
|------|---------|------|
| Skip | `.faultTolerant().skip(异常类).skipLimit(n)` / `SkipPolicy` / `SkipListener` | 三类计数：READ/PROCESS/WRITE_SKIP；写跳过代价最大（整块回滚+重放） |
| Retry | `.retry(异常类).retryLimit(n).backOffPolicy(...)` | **6.0 基于 SF7 内置 Retry**（不再是 spring-retry） |
| 重启 | `.startLimit(n)` / `.allowStartIfComplete(true)` / `.preventRestart()` | 同参数启动=续跑；已提交 chunk 不重放 |
| 幂等 | `ItemKeyGenerator` / 唯一键 SQL | 重放安全的前提 |
| 事务 | `transactionManager` + chunk(N) | 一个 chunk 一个事务 |

```java
.faultTolerant()
.skip(InvalidDataException.class).skipLimit(100)          // 坏数据：跳过
.retry(CannotAcquireLockException.class).retryLimit(3)    // 瞬时故障：重试
.backOffPolicy(new ExponentialBackOffPolicyBuilder()
        .initialInterval(1_000).multiplier(2.0).build())
```

> 🎯 选型口诀：**数据问题 skip、资源问题 retry、进程问题 restart**。

## 4. 并行与远程执行

| 能力 | 关键 API | 注意 |
|------|---------|------|
| 多线程 Step | `.taskExecutor(taskExecutor)` | reader 必须线程安全；**失去重启粒度** |
| 本地分区 | `Partitioner` + `TaskExecutorPartitionHandler` + `.partitioner(name, partitioner)` | 按分片保留重启记录 |
| 远程分区 | `MessageChannelPartitionHandler` + `StepExecutionRequestHandler` + `BeanFactoryStepLocator` | 只传分片范围；需共享 JobRepository |
| 远程 Chunking | `RemoteChunkingManagerStepBuilderFactory` / `RemoteChunkingWorkerBuilder`（6.0） | 数据过网；处理瓶颈场景 |
| 背压 | `BlockingQueueItemReader`/`Writer`（5.2+） | 6.0 生产者-消费者内核，throttleLimit 已移除 |

> 💡 扩展阶梯：单线程 → 多线程（失重启）→ 本地分区 → 远程分区/Chunking。

## 5. 启动与运维

| 类/接口 | 职责 |
|---------|------|
| `JobLauncher` | 同步启动入口（6.0 被 JobOperator 继承） |
| `TaskExecutorJobOperator`（旧 SimpleJobOperator） | start/stop/restart/recover/abandon |
| `CommandLineJobOperator`（6.0） | 命令行运维（替代 CommandLineJobRunner） |
| `JobExplorer` | 只读查询（6.0 被 JobRepository 继承） |
| `JobRepository` | 元数据读写（JDBC/Mongo/Resourceless 三实现） |
| `JobRegistry` / `JobLocator` | 按名查 Job（6.0 自动注册） |
| `JobExecutionListener` / `StepExecutionListener` / `ChunkListener` / `Item*Listener` | 四层监听器 |

```java
// 运维操作（REST/调度中触发）
jobOperator.startNextInstance("orderImport", params);  // 新实例
jobOperator.restart(executionId);                      // 续跑失败实例
jobOperator.stop(executionId);                         // 异步停止（当前 chunk 跑完才停）
jobOperator.recover(executionId);                      // 6.0：FAILED → ABANDONED
```

## 6. 6.0 变化对照

| 维度 | 5.x | 6.0 |
|------|-----|-----|
| 构建 | JobBuilderFactory / 单参构造 + repository() | 双参构造注入（工厂移除） |
| 仓库配置 | @EnableBatchProcessing(dataSourceRef=...) | @EnableJdbcJobRepository / @EnableMongoJobRepository |
| 参数模型 | Map<String, JobParameter> | Set<JobParameter>（record） |
| Retry | spring-retry | Spring Framework 7 内置 Retry |
| 并发 | throttleLimit | 有界队列生产者-消费者 |
| 运维 | SimpleJobOperator / CommandLineJobRunner | TaskExecutorJobOperator / CommandLineJobOperator |
| 改名 | JobRepositoryFactoryBean / JobLauncherTestUtils / ChunkHandler | JdbcJobRepositoryFactoryBean / JobOperatorTestUtils / ChunkRequestHandler |
| 仓库默认 | 需数据库 | Resourceless（默认无库） |

> ⚠️ 迁移必读：v5 FAILED 实例无法在 v6 续跑；`BATCH_JOB_SEQ` 改名；详细迁移清单见深度体系 [09-测试与生产实践](../../../Spring Batch/09-测试与生产实践.md) 第 6 节。
