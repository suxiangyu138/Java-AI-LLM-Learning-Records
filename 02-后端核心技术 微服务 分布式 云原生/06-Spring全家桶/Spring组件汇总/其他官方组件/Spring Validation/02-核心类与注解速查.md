## 1. 校验接口与错误容器

| 类/接口 | 职责 | 说明 |
|---------|------|------|
| `Validator`（org.springframework.validation） | Spring 自有校验接口 | `supports(Class)` + `validate(target, errors)` |
| `Errors` / `BindingResult` | 错误容器 | `rejectValue(field, code, msg)`、`getFieldErrors()` |
| `ValidationUtils` | 常用校验工具 | `rejectIfEmpty`、`rejectIfEmptyOrWhitespace` |
| `DataBinder` / `WebDataBinder` | 数据绑定 + 校验一体 | `setValidator()`、`validate()` |
| `SmartValidator` | Validator 扩展（分组支持） | `validate(target, errors, groups...)` |
| `LocalValidatorFactoryBean` | **Bean Validation → Spring 桥** | Boot 自动配置；同时暴露三接口（Spring Validator / JSR Validator / ValidatorFactory） |
| `SpringValidatorAdapter` | JSR Validator 适配为 Spring Validator | 框架内部桥接 |
| `MethodValidationPostProcessor` | 方法级校验 AOP 后置处理器 | 配合类级 @Validated 使用 |

```java
// 编程式校验（Spring 自有风格）
public class OrderValidator implements Validator {
    @Override
    public boolean supports(Class<?> clazz) { return Order.class.isAssignableFrom(clazz); }
    @Override
    public void validate(Object target, Errors errors) {
        Order order = (Order) target;
        ValidationUtils.rejectIfEmpty(errors, "customerId", "customerId.empty");
        if (order.getAmount() != null && order.getAmount().signum() < 0) {
            errors.rejectValue("amount", "amount.negative");
        }
    }
}
```

> 🎯 **要点**：两套 Validator 并存——Spring 自有（Validator/Errors，面向 DataBinder/表单）与 JSR-303（ConstraintValidator，面向注解）；**LocalValidatorFactoryBean 是两者的合流点**。

## 2. 约束注解速查

| 注解（jakarta.validation.constraints.*） | 约束 | 常用属性 |
|------|------|---------|
| `@NotNull` | 非 null | — |
| `@NotEmpty` | 非 null 且非空（集合/字符串） | — |
| `@NotBlank` | 非 null 且去空白后非空 | — |
| `@Size(min, max)` | 长度/大小范围 | min/max |
| `@Min` / `@Max` | 数值下/上限 | value |
| `@Positive` / `@PositiveOrZero` | 正数/非负 | — |
| `@Negative` / `@NegativeOrZero` | 负数/非正 | — |
| `@DecimalMin` / `@DecimalMax` | BigDecimal 边界 | value（字符串）、inclusive |
| `@Digits(integer, fraction)` | 整数/小数位上限 | integer/fraction |
| `@Pattern(regexp)` | 正则匹配 | regexp、flags |
| `@Email` | 邮箱格式 | — |
| `@Past` / `@PastOrPresent` / `@Future` / `@FutureOrPresent` | 时间前后 | — |
| `@Valid`（jakarta.validation） | 触发嵌套/递归校验 | — |
| `@AssertTrue` / `@AssertFalse` | 布尔断言 | — |

> 💡 字符串校验三兄弟：**@NotNull（非 null）、@NotEmpty（+非空串）、@NotBlank（+去空白）**——"允许空串"用 @NotNull，"不允许空串"用 @NotBlank。

## 3. 触发方式：@Valid 与 @Validated

| 维度 | @Valid（jakarta.validation.Valid） | @Validated（org.springframework.validation.annotation.Validated） |
|------|-------------------------------------|----------------------------------------------------------------|
| 来源 | Bean Validation 规范 | Spring 扩展 |
| 参数对象校验 | ✅（@RequestBody/@ModelAttribute） | ✅（超集） |
| 分组校验 | ❌ | ✅ |
| 方法级校验（类级标注） | ❌ | ✅（AOP 代理） |
| 嵌套校验（字段 @Valid） | ✅ | ✅（字段上的 @Valid 仍来自规范） |

```java
// 参数对象校验（最常见）
@PostMapping("/orders")
Order create(@Valid @RequestBody CreateOrderRequest req) { ... }

// 分组校验（场景化）
public interface CreateGroup {}
public interface UpdateGroup {}

@PutMapping("/orders/{id}")
Order update(@Validated(UpdateGroup.class) @RequestBody UpdateOrderRequest req) { ... }

// 方法级校验（类级 @Validated + 参数约束）
@Service
@Validated
class OrderService {
    Order find(@NotNull Long id, @Min(1) int page) { ... }   // 抛 ConstraintViolationException
}
```

> 🎯 **核心辨析**：@Valid 只触发"参数对象 + 嵌套"校验；@Validated 额外支持**分组**与**方法级校验**——"在哪用哪个"记住：**Controller 参数用 @Valid，分组/Service 方法用 @Validated**。

## 4. 异常体系

| 异常 | 触发场景 | 处置建议 |
|------|---------|---------|
| `MethodArgumentNotValidException` | @RequestBody/@ModelAttribute + @Valid 校验失败 | 取 `getBindingResult().getFieldErrors()` 返回 400 |
| `HandlerMethodValidationException`（6.1+） | Controller 方法参数上的约束注解直接触发 | 取 `getParameterValidationResults()`（按参数分组）→ 400 |
| `ConstraintViolationException`（jakarta.validation） | 方法级校验（@Validated 类级）失败 | 服务层统一捕获 → 业务异常包装 |
| `BindException` | 表单/DataBinder 绑定+校验失败 | @InitBinder 场景处理 |
| `MissingServletRequestParameterException` 等 | 参数缺失（非校验） | 400 系列 |

```java
// 6.1+ 方法约束校验的处理
@ExceptionHandler(HandlerMethodValidationException.class)
ResponseEntity<?> onMethodValidation(HandlerMethodValidationException ex) {
    List<String> errors = ex.getParameterValidationResults().stream()
            .map(r -> r.getMethodParameter().getParameterName() + ": " + r.getResolvableErrors())
            .toList();
    return ResponseEntity.badRequest().body(errors);
}
```

> ⚠️ 两个异常别混：**参数对象校验失败 → MethodArgumentNotValidException**；**方法参数上的约束注解失败 → HandlerMethodValidationException**——Controller 里两者可能同时存在，异常处理器都要接。

## 5. 分组校验与自定义约束

```java
// 分组接口
public interface CreateGroup {}
public interface UpdateGroup {}

// 约束带组
public record UserDto(
        @NotNull(groups = CreateGroup.class) Long id,     // 仅在 Create 组校验
        @NotBlank(groups = {CreateGroup.class, UpdateGroup.class}) String name) {}

// 组顺序（先 Create 后 Update，全过才成功）
@GroupSequence({CreateGroup.class, UpdateGroup.class})
public interface FullSequence {}
```

```java
// 自定义约束：注解 + 实现
@Documented
@Constraint(validatedBy = PhoneValidator.class)
@Target({FIELD, PARAMETER})
@Retention(RUNTIME)
public @interface @Phone {
    String message() default "invalid phone number";
    Class<?>[] groups() default {};
    Class<? extends Payload>[] payload() default {};
}

public class PhoneValidator implements ConstraintValidator<Phone, String> {
    @Override
    public boolean isValid(String value, ConstraintValidatorContext ctx) {
        return value != null && value.matches("^1[3-9]\\d{9}$");
    }
}
```

> 💡 自定义约束三件套：**@Constraint 元注解（绑定实现与消息）、message/groups/payload 三默认属性（规范要求）、ConstraintValidator 实现**——缺一不可。

## 6. SF 7 变化对照

| 维度 | SF 6.x | SF 7.0 |
|------|--------|--------|
| Bean Validation 基线 | 3.0 | **3.1** |
| Hibernate Validator | 8.x | 9.x |
| 命名空间 | javax.* 兼容期 | **jakarta.* 唯一**（javax 移除） |
| 方法约束校验 | 6.1 引入（MVC 内置） | 稳定（HandlerMethodValidationException） |
| 参数解析 | — | ParameterValidationResult 分组 API 完善 |

> ⚠️ 升级 SF 7/Boot 4 必做：全局替换 `javax.validation` → `jakarta.validation`、`javax.annotation` → `jakarta.annotation`；确认 Hibernate Validator 9.x（Boot BOM 锁定）；回归所有分组/方法级校验场景。
