## 1. 模块总览

```text
spring-context（内置）      ← Validator/Errors/DataBinder/LocalValidatorFactoryBean
spring-web（内置）          ← MVC 参数校验绑定（MethodArgumentNotValidException 等）
spring-aop（内置）          ← 方法级校验的代理支持（@Validated 类级 + MethodValidationPostProcessor）
jakarta.validation-api      ← Bean Validation 规范接口（@NotNull @Valid 等注解本体）
hibernate-validator         ← 规范实现（9.x，SF 7/Boot 4 配套线）
jakarta.el                  ← EL 表达式（消息插值 {min} 占位符需要）
```

> 🎯 **要点**：**不存在 `spring-validation` 独立模块**——Spring 侧能力全在既有框架模块里；真正需要显式引入的是"规范 + 实现 + EL"三件套，而 `spring-boot-starter-validation` 一键打包。

### 1.1 依赖传导链速览

```text
spring-boot-starter-validation
  ├── spring-context / spring-web / spring-aop（传递，框架自带校验 API）
  ├── jakarta.validation-api      ← 约束注解与接口（规范）
  ├── org.hibernate.validator:hibernate-validator  ← 实现（9.x）
  └── jakarta.el（tomcat-embed-el） ← 消息插值运行时
```

> 💡 依赖缺失的第一直觉：**约束注解无法 import = 缺 validation-api（starter 已带）；校验静默不执行 = 缺实现（hibernate-validator）；`{min}` 占位符不渲染 = 缺 EL**。

### 1.2 模块一句话全景

| 模块 | 一句话 |
|------|--------|
| spring-context | 校验抽象：Validator/Errors/DataBinder/LocalValidatorFactoryBean |
| spring-web | MVC/WebFlux 参数校验与异常（MethodArgumentNotValidException） |
| spring-aop | 方法级校验代理（@Validated + MethodValidationPostProcessor） |
| jakarta.validation-api | 规范：约束注解（@NotNull…）、Validator 接口 |
| hibernate-validator | 规范实现（Bean Validation 3.1） |
| jakarta.el | 消息插值（ValidationMessages 占位符） |

> 🎯 心智模型：**Spring 三件套是"插座"，validation-api 是"插头标准"，Hibernate Validator 是"电器"**——插座是框架自带的，插头与电器由 starter 带来。

## 2. 能力归属：三件套

| 模块 | 关键类 | 场景 |
|------|--------|------|
| spring-context | `Validator`、`ValidationUtils`、`Errors`、`DataBinder`、`LocalValidatorFactoryBean`、`MethodValidationPostProcessor` | 通用校验/数据绑定/方法级校验 |
| spring-web | `MethodArgumentNotValidException`、`HandlerMethodValidationException`（6.1+）、WebDataBinder、@InitBinder 校验 | Controller 参数校验 |
| spring-aop | 方法校验代理（@Validated 类级触发） | 任意 Service/Controller Bean 的方法约束 |

> ⚠️ **6.1+ 双轨并存**：Controller 方法约束校验有两种触发路径——(a) Spring MVC 内置方法校验（参数上直接 @NotNull，抛 HandlerMethodValidationException，**类上不要加 @Validated**）；(b) AOP 代理（类级 @Validated，走 MethodValidationPostProcessor）。两者可同时存在但行为不同，混用是常见困惑源。

## 3. Bean Validation 与实现层

| 依赖 | 版本线 | 说明 |
|------|--------|------|
| jakarta.validation-api | 3.1（SF 7 基线） | 约束注解与接口（jakarta.validation.*） |
| hibernate-validator | 9.x（Boot 4 配套） | 参考实现；8.x 配 Boot 3 |
| jakarta.el | 随 starter | 消息插值必需（`{min}`、`${}`） |
| javax.validation（旧） | — | **SF 7 已移除**，禁止使用 |

> ⚠️ **SF 7 移除项**：`javax.validation`、`javax.annotation`、`javax.inject` 在 Spring Framework 7 中全部不再支持——**存量项目升级 Boot 4 时校验相关 import 必须批量改 `jakarta.*`**。

### 3.1 版本线对照

| Boot 版本 | Hibernate Validator | Bean Validation | 说明 |
|-----------|--------------------|-----------------|------|
| Boot 4.0.x | 9.x | 3.1 | 当前主线（SF 7） |
| Boot 3.x | 8.x | 3.0 | 存量维护线 |

## 4. 依赖什么场景引入什么

| 场景 | 需要的依赖 |
|------|-----------|
| MVC/WebFlux 参数校验（@Valid） | `spring-boot-starter-validation`（Web 项目几乎必加） |
| 纯 Spring（非 Boot） | spring-context + jakarta.validation-api + hibernate-validator + jakarta.el |
| 方法级校验（@Validated 类级） | spring-aop + spring-context（starter 已含） |
| 自定义约束 | 无需新依赖（ConstraintValidator 在实现里） |
| 仅用 Spring 自有 Validator（不用 JSR-303） | 无需任何显式依赖（框架自带） |

```xml
<!-- 标准入口：一个 starter 全搞定 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-validation</artifactId>
</dependency>
```

### 4.1 依赖冲突与版本锁定

| 报错现象 | 根因 | 处理 |
|---------|------|------|
| `javax.validation` 相关类找不到 | SF 7 移除 javax 命名空间 | 全部改 `jakarta.validation.*` + 新版本依赖 |
| 校验注解无法 import | 缺 validation-api | 加 starter-validation |
| `NoClassDefFoundError: jakarta.el.*` | 缺 EL 实现 | starter 已带；手工引时补 jakarta.el |
| Hibernate Validator 版本冲突 | 与 Boot BOM 不配套 | 交 Boot BOM 锁定（9.x ↔ Boot 4） |

> 🎯 经验法则：**校验依赖永远走 Boot BOM + starter-validation**；手工引 validation-api/hibernate-validator 是版本冲突与命名空间错乱的头号来源。

## 5. Starter 对照

| Starter | 包含 | 适用 |
|---------|------|------|
| `spring-boot-starter-validation` | validation-api + hibernate-validator + jakarta.el | **标准入口（唯一需要的）** |
| `spring-boot-starter-web` | spring-web（校验 API 传递） | 不写约束注解时无需显式加 validation starter |

> 🎯 一句话选型：**要写 @NotBlank/@Size 就加 starter-validation；只用框架自带 Validator 接口就什么都不用加**——"校验注解能用"的最低成本入口永远是 starter-validation。
