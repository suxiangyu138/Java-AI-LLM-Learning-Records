## 1. 集成地图

```text
              HTTP 请求
                │
        ┌───────▼────────┐
        │  Spring MVC    │
        │  @RequestBody  │─── 反序列化 ──┐
        │  @ModelAttribute│              ▼
        └───────┬────────┘    LocalValidatorFactoryBean
                │              （jakarta.validation 3.1 + HV 9.x）
                ▼
        参数对象校验（@Valid/@Validated）
           │ 失败 → MethodArgumentNotValidException / HandlerMethodValidationException
           ▼
        Controller 方法 → Service（@Validated 类级 → 方法级校验 → ConstraintViolationException）
                │
        ┌───────┴────────┐
        │  WebFlux       │ 响应式同样走 @Valid（同步校验阶段）
        └────────────────┘
        ┌────────────────┐
        │  Spring Batch  │ ValidatingItemProcessor 复用同一套 Validator
        └────────────────┘
```

## 2. 与生态的集成

| 集成对象 | 方式 | 要点 |
|---------|------|------|
| Spring MVC | @Valid @RequestBody / @ModelAttribute | 异常接 MethodArgumentNotValidException |
| Spring MVC 方法约束 | 参数上直接 @Constraint | 6.1+ 内置，抛 HandlerMethodValidationException |
| WebFlux | @Valid（校验在装配阶段同步执行） | 响应式流中校验失败 → 400 响应 |
| Spring Batch | ValidatingItemProcessor + Validator | 批处理逐条校验 + Skip 容错（复用本套抽象） |
| DataBinder | @InitBinder 局部校验器 | 表单场景追加校验 |
| Spring AI / 工具调用 | 参数描述校验（范式相关） | 校验语义可复用（模式校验等） |
| 数据库层 | 仅兜底（唯一约束等） | **不要用 DB 约束代替参数校验**（性能与体验） |

> 🎯 集成铁律：**校验分层——DTO 参数层校验（快速失败）+ 业务规则层校验（自定义约束/服务内校验）+ DB 约束兜底**；一层管一层，别越权。

## 3. 高频问题速查

| 问题 | 根因 | 处理 |
|------|------|------|
| @NotBlank 不生效 | 缺 starter-validation（无实现） | 加依赖；Boot 4 自动装配校验器 |
| javax.validation 报错 | SF 7 移除 javax | 全部改 jakarta.validation.* |
| 校验抛 MethodArgumentNotValidException 但没处理 | 缺 @ControllerAdvice | 加全局异常处理器返回 400 |
| 消息显示 `{min}` 原样 | 缺 jakarta.el（插值失败） | starter 已带；检查 EL 依赖 |
| 嵌套对象没校验 | 字段缺 @Valid | DTO 内对象字段加 @Valid |
| 分组不生效 | 触发端没用 @Validated(groups) | @Valid 不支持分组；换 @Validated |
| 方法级校验不触发 | 类上缺 @Validated / 缺 MethodValidationPostProcessor | 类级 @Validated + 参数约束 |
| 自定义约束永远通过 | ConstraintValidator 没注册/实现类错误 | 检查 @Constraint(validatedBy=...) 与泛型 |
| 消息文件不生效 | ValidationMessages.properties 位置不对 | 放 classpath 根目录；编码 UTF-8 |
| 异常类型对不上（两轨混用） | Controller 同时有 @Validated 类级与方法约束 | 明确走 MVC 内置（去类级 @Validated）或 AOP 一轨 |

## 4. 排障流程

```text
① 依赖层：starter-validation 在吗？hibernate-validator 版本（Boot BOM）？
     └─ javax/jakarta 命名空间是否错乱（SF 7 只认 jakarta）
② 触发层：@Valid/@Validated 加对了吗？
     └─ 分组要 @Validated；嵌套要字段 @Valid；方法级要类级 @Validated
③ 执行层：异常接住了吗？
     └─ MethodArgumentNotValidException（参数对象）/ HandlerMethodValidationException（方法约束）
④ 消息层：占位符渲染了吗？消息文件在 classpath 根目录吗？
⑤ 边界层：自定义约束/交叉字段校验是否覆盖业务规则？
```

> 💡 排障三利器：**约束日志（@Validated 的 AOP 日志）、异常类型（判断走哪一轨）、消息插值（判断 EL）**——先确认"校验真的执行了"，再谈"为什么没通过"。

> 🎯 **核心要点**：集成地图一句话 = "校验是 Spring 的横切能力——MVC 管参数、Service 管方法、Batch 管逐条、DB 兜底"；排障先查依赖与触发方式（@Valid vs @Validated），再对异常类型。深挖见 [Spring Framework 官方 Validation 文档](https://docs.spring.io/spring-framework/reference/core/validation.html)。
