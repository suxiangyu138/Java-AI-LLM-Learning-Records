## 1. 依赖与自动配置

| 配置项 | 说明 |
|--------|------|
| `spring-boot-starter-validation` | 唯一需要的依赖（hibernate-validator 9.x + jakarta.el） |
| Boot 自动配置 | classpath 有实现时自动装配 `LocalValidatorFactoryBean`（Bean 名 `defaultValidator`） |
| `spring.mvc.validator`（旧） | 已废弃：MVC 用默认校验器即可 |
| 方法校验开关 | `@Validated` 类级 + MethodValidationPostProcessor（Boot 自动装配） |

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-validation</artifactId>
</dependency>
```

> 🎯 **要点**：Boot 4 下"加依赖即生效"——LocalValidatorFactoryBean 与 MVC 校验器自动装配，**零 yaml 配置起步**；绝大多数项目不需要改校验相关属性。

## 2. 消息资源配置

| 资源 | 位置/命名 | 说明 |
|------|----------|------|
| 全局消息 | `classpath:ValidationMessages.properties`（及 locale 变体） | 默认消息源（规范行为） |
| Spring 消息 | `messages.properties`（spring.messages 配置） | 与 Spring MessageSource 整合（Boot 支持） |
| 注解内消息 | `message = "..."` | 单条覆盖 |

```properties
# ValidationMessages.properties（类路径根目录）
notNull=customerId 不能为空
amount.negative=金额不能为负
typeMismatch.java.lang.Long=id 必须是数字
```

> 💡 消息查找优先级：**注解 message → ValidationMessages → 默认消息**；`{min}`/`{max}` 占位符由 EL 插值（缺 jakarta.el 时占位符不渲染——这是"校验报错但消息显示原始模板"的常见原因）。

## 3. 校验器定制

| 需求 | 做法 |
|------|------|
| 全局替换校验器 | 定义 `Validator` Bean 覆盖默认（或 WebMvcConfigurer.setValidator） |
| 多校验器并存 | 全局 + @InitBinder 局部校验器（控制器级） |
| 快速失败 | `hibernate.validator.fail_fast: true`（系统属性）或 `ValidatorFactory` 定制 |
| 方法校验自定义 | MethodValidationPostProcessor Bean 覆盖（validator 注入） |

```java
// 局部校验器（某 Controller 专用）
@InitBinder
void initBinder(WebDataBinder binder) {
    binder.addValidators(new OrderValidator());   // 表单校验追加
}
```

> ⚠️ 全局校验器覆盖要谨慎：Boot 自动装配的 LocalValidatorFactoryBean 承担 MVC + 方法校验两处职责——**自定义 Bean 后两处行为都可能变**，先确认替代实现能力等价。

## 4. 与 MVC 的配合

| 场景 | 配置/做法 |
|------|----------|
| 参数校验异常返回 | @ControllerAdvice + @ExceptionHandler（见卡片 02 异常体系） |
| 消息用 MessageSource | `spring.messages.basename` 指向业务消息文件 |
| JSON 反序列化后校验 | @Valid @RequestBody（自动） |
| 表单绑定校验 | @Valid @ModelAttribute + BindingResult 参数 |
| 忽略某个校验 | 分组空组 / 不触发即可 |

> 🎯 配置心智模型：**依赖决定"有没有"，消息资源决定"说什么"，异常处理器决定"回什么"**——三件事里只有依赖是必须的。

## 5. 常见配置组合

```yaml
spring:
  messages:
    basename: messages,ValidationMessages   # 业务消息源合并校验消息
  jackson:
    default-property-inclusion: non_null     # 错误响应不输出 null 字段
```

| 生产组合 | 说明 |
|---------|------|
| starter-validation + ControllerAdvice | 标准 Web 校验（90% 项目） |
| + ValidationMessages 国际化 | 多语言错误消息 |
| + @Validated 分组（Create/Update） | 同一 DTO 场景化校验 |
| + 自定义约束 | 业务规则（手机号/身份证/枚举） |

> 🎯 一句话：**配置层几乎是"空"的——校验的威力在注解与代码（分组/自定义约束），配置只碰消息资源与异常响应**。
