## 1. 集成地图

```text
              外部世界（30+ 适配器）
   Kafka / RabbitMQ / JMS / MQTT / HTTP / WebSocket / 文件 / FTP / 数据库 / 邮件 ...
                       │（ChannelAdapter / Gateway）
                       ▼
        ┌─────────────────────────────────────┐
        │      Spring Integration 消息流      │
        │  Message → Channel → EIP 组件链     │
        │  （转换/过滤/路由/拆分/聚合/处理）   │
        │  errorChannel（兜底）· MessageStore │
        │  LockRegistry（互斥）· Micrometer   │
        └───────┬──────────────┬─────────────┘
                │              │
        Spring Batch 6.0      WebFlux / RSocket
        （远程分区/Chunking）  （响应式通道）
                │
        共享 JobRepository（JDBC/Mongo）
```

## 2. 与生态的集成

| 集成对象 | 方式 | 要点 |
|---------|------|------|
| Spring Batch | spring-batch-integration | 远程分区（MessageChannelPartitionHandler）、远程 Chunking、SEDA 通道 |
| Kafka / AMQP / JMS | 各适配器模块 | 消息驱动 vs 轮询两种消费模型；事务/位点由中间件客户端管理 |
| Spring Cloud Stream | 共用 spring-messaging | 绑定器抽象之上，SI 可作消息流引擎 |
| WebFlux / RSocket | FluxMessageChannel、-webflux、-rsocket | 响应式端到端（非阻塞） |
| Micrometer | `spring.integration.management.observation-patterns` | 端点级观测（7.x） |
| Spring Security | spring-integration-security | 通道安全、认证上下文传播 |
| GraalVM Native | Boot 4 原生支持 | 消息流反射点需 runtime hints（官方支持） |
| 云事件 CloudEvents | 7.1.0 起 FromCloudEventTransformer | 云原生事件规范互通 |

> 🎯 集成铁律：**选适配器先定协议；消息流内不写死中间件 API（走通道抽象）；错误统一走 errorChannel**——这样换传输层不动业务代码。

## 3. 高频问题速查

| 问题 | 根因 | 处理 |
|------|------|------|
| 消息流不触发 | 端点没配 poller / 通道无人订阅 | 轮询源配 `@Poller` 或 DSL `.poller()`；检查通道订阅者 |
| 消息被"吞掉"无日志 | 端点无输出通道（nullChannel）或 errorChannel 静默 | `require-subscribers: true`；查 MessageHistory |
| 聚合永不释放 | ReleaseStrategy 条件不满足 / 相关键不匹配 | 检查 CorrelationStrategy（默认 correlationId）+ MessageGroupTimeout |
| 队列堆积不消费 | poller 未配或 maxMessagesPerPoll 太小 | 调 `poller.*`；确认消费者端点存在 |
| 多实例重复消费 | 无锁/无幂等 | LockRegistry（Jdbc/Redis）+ idempotent receiver |
| DirectChannel 意外多订阅者 | 通道被重复注入端点 | 单播通道订阅 >1 会报错（`max-unicast-subscribers`） |
| NoSuchMethodError | SI 与 Spring 版本不匹配 | Boot BOM 锁版本（SI 7 ↔ Boot 4） |
| 事务不回滚 | 消息流端点未绑定事务 | TransactionSynchronizationFactory + 事务性端点 |
| 文件端点写出越界 | 7.1 安全修复后的行为变更 | 升级后回归测试路径穿越场景 |
| gRPC 错误丢失 | 7.1 前的错误传播缺陷 | 升级 7.1.0 |

## 4. 排障流程

```text
① 触发层：消息源触发了吗？轮询源看 poller 日志/时间戳；消息驱动看中间件消费位点
② 通道层：消息到哪个通道了？WireTap / ChannelInterceptor 打点确认流向
③ 组件层：哪个端点处理失败？看端点的 ErrorMessage + MessageHistory（流转路径）
④ 错误层：errorChannel 收到什么？require-subscribers 是否暴露了错误
⑤ 数据层：聚合没释放？查 MessageGroupStore 分组状态；幂等判重误杀？查判重键
```

> 💡 排障三利器：**WireTap（旁路观察）、MessageHistory（流转路径）、errorChannel（错误汇聚）**——SI 排障先加这三个，再看业务日志。

> 🎯 **核心要点**：集成地图一句话 = "适配器接世界、通道串组件、errorChannel 兜底、MessageStore 保可靠"；排障从触发层开始逐层下探。与 Spring Batch 的远程执行联动细节见 [Spring Batch 深度体系-07](../../../Spring Batch/07-并行与分布式：多线程、分区与远程执行.md)。
