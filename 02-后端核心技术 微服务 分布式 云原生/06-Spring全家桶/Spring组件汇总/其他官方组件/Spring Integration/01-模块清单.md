## 1. 模块总览

```text
spring-integration-core       ← 消息模型/EIP 组件/DSL/端点（一切集成的根）
spring-integration-<适配器>    ← 30+ 外部系统适配器（file/jdbc/kafka/amqp/jms…）
spring-integration-test       ← 集成测试工具（MessageChannel 断言等）
spring-integration-security   ← 通道安全（@SecuredChannel 等）
```

> 🎯 **要点**：`spring-boot-starter-integration` 只打包 core——**每接一个外部系统就加一个对应适配器模块**；依赖选型是 SI 项目的日常大头。

### 1.1 依赖传导链速览

```text
spring-boot-starter-integration
  ├── spring-integration-core         ← 消息/EIP/DSL（必带）
  │     └── spring-messaging          ← 消息抽象（Message/Channel 接口）
  │     └── spring-aop / tx / context（基础设施）
  └── spring-boot-starter（传递）
spring-integration-kafka / -amqp / -jms ...（按需）
  └── 各消息中间件客户端
spring-integration-jdbc（按需）
  └── spring-jdbc
```

> 💡 依赖缺失的第一直觉：**报 `MessageChannel`/`Message` 类缺失 = 连 spring-messaging 都没有（基本不可能）；报 `KafkaTemplate` 相关 = 缺 spring-integration-kafka**——按"要接的系统"补齐即可。

### 1.2 模块一句话全景

| 模块 | 一句话 |
|------|--------|
| spring-integration-core | 消息模型、通道、EIP 组件、DSL、轮询、聚合、错误处理 |
| spring-messaging（外部） | Spring 消息抽象基座（Message/MessageChannel 接口） |
| spring-integration-file | 文件监听/读写（FileReadingMessageSource、FileWritingMessageHandler） |
| spring-integration-jdbc | 出/入站 JDBC 适配器 + JdbcMessageStore |
| spring-integration-{kafka,amqp,jms,mqtt} | 各消息中间件适配 |
| spring-integration-{http,rest,webflux,ws,rsocket,grpc} | Web/远程调用适配（7.1 新增 gRPC DSL） |
| spring-integration-{ftp,sftp,smb} | 文件传输协议适配 |
| spring-integration-{redis,mongodb,cassandra,jpa} | 存储/数据适配与 MessageStore 实现 |
| spring-integration-mail | IMAP/POP3/SMTP 适配 |
| spring-integration-test | 测试工具（MockIntegration 等） |
| spring-integration-security | 通道/端点安全 |

> 🎯 心智模型：**core 是"CPU"，spring-messaging 是"主板"，每个适配器模块是"外接卡"**——选外接卡 = 选集成目标。

## 2. 核心模块

| Artifact | 职责 | 关键类（包） |
|---------|------|-------------|
| `spring-integration-core` | 全部集成引擎 | `Message`/`MessageChannel`（org.springframework.messaging）、`IntegrationFlow`、`MessageHandler`、`Endpoint`、`PollerMetadata`（org.springframework.integration.*） |
| `spring-messaging` | 消息抽象（SI 复用） | `Message`、`MessageChannel`、`MessageHeaders`、`MessagingException` |
| `spring-integration-test` | 测试支持 | `MockIntegration`、`MessageChannelAssertions` |

> ⚠️ **包名注意**：`Message`/`MessageChannel`/`MessageHeaders` 在 `org.springframework.messaging`（spring-messaging 模块），SI 自己的类在 `org.springframework.integration`——报错堆栈按包名即可区分"抽象层问题"还是"集成层问题"。

### 2.1 core 内部结构（按功能）

```text
org.springframework.integration
├── channel        # 通道实现（Direct/Queue/PublishSubscribe/Executor/Flux）
├── endpoint       # 端点抽象（MessageProducer/MessageConsumer/PollingConsumer）
├── dsl            # IntegrationFlow / IntegrationFlowDefinition / 各 Spec
├── transformer / filter / router / splitter / aggregator
│                   # EIP 组件实现 + 注解处理器（MethodInvoking*）
├── support        # MessageBuilder、ErrorMessage 等基础件
├── selector       # MessageSelector（7.1 支持 header 值模式匹配）
├── store          # MessageStore / MessageGroupStore（simple/jdbc/redis/mongo 实现）
├── transaction    # TransactionSynchronizationFactory 等
├── util           # LockRegistry / JdbcLockRegistry / RedisLockRegistry
├── error          # 错误处理（ErrorMessagePoller 等）
└── config         # @EnableIntegration、注册器
```

## 3. 适配器模块地图

| 类别 | 模块 | 典型组件 |
|------|------|---------|
| 消息中间件 | -kafka / -amqp / -jms / -mqtt / -stream | KafkaMessageDrivenChannelAdapter、AmqpInboundGateway |
| 文件 | -file / -ftp / -sftp / -smb / -syslog | FileReadingMessageSource、SftpOutboundGateway |
| 数据 | -jdbc / -jpa / -redis / -mongodb / -cassandra | JdbcPollingChannelAdapter、RedisStore |
| Web | -http / -rest / -webflux / -ws / -rsocket / -grpc（7.1） | HttpRequestHandlingMessagingGateway、GrpcInboundGateway |
| 邮件 | -mail | MailReceivingMessageSource、MailSendingMessageHandler |
| 事件/脚本 | -event / -groovy / -scripting | ApplicationEventListeningMessageProducer |
| 物联网 | -ip / -xmpp / -zeromq / -influxdb / -mqtt | TcpInboundGateway、MqttPahoMessageDrivenChannelAdapter |

> 💡 选择逻辑：**先定"协议/中间件"，再查对应适配器模块**——Spring 官方文档有完整的适配器索引页。

## 4. 依赖什么场景引入什么

| 场景 | 需要的依赖 |
|------|-----------|
| 纯内存消息流（定时源+转换+日志） | `spring-boot-starter-integration` |
| 接 Kafka | + `spring-integration-kafka` |
| 接 RabbitMQ / JMS | + `spring-integration-amqp` / `spring-integration-jms` |
| 文件监听/输出 | + `spring-integration-file` |
| 轮询数据库表 | + `spring-integration-jdbc`（+驱动） |
| REST/HTTP 网关 | + `spring-integration-http`（或 -webflux 响应式） |
| 远程批处理（与 Spring Batch 联动） | + `spring-batch-integration` + 消息中间件适配器 |
| 集成测试 | + `spring-integration-test` |

```xml
<!-- 例：Kafka 消息驱动集成 -->
<dependency>
    <groupId>org.springframework.integration</groupId>
    <artifactId>spring-integration-kafka</artifactId>
</dependency>
```

### 4.1 版本线对照与冲突

| Boot 版本 | SI 版本线 | 说明 |
|-----------|----------|------|
| Boot 4.0.x | 7.1.x / 7.0.x | 当前主线（SF 7） |
| Boot 3.x | 6.4.x | 存量维护线 |
| Boot 2.x | 5.x | 已 EOL |

| 报错现象 | 根因 | 处理 |
|---------|------|------|
| `NoSuchMethodError`（messaging 类） | SI 与 Spring 大版本不匹配 | 用 Boot BOM 锁定 |
| `ClassNotFoundException: KafkaMessageDrivenChannelAdapter` | 缺 spring-integration-kafka | 按适配器补依赖 |
| `MessageChannel` 类冲突 | 手工引了不同版本的 spring-messaging | 删除手工依赖，交给 BOM |

> 🎯 经验法则：**SI 依赖永远走 Boot BOM；适配器模块与 core 必须同版本线**——跨线混搭是 NoSuchMethodError 的头号来源。

## 5. Starter 对照

| Starter | 包含 | 适用 |
|---------|------|------|
| `spring-boot-starter-integration` | core + 自动配置（@EnableIntegration 默认开启） | 标准入口 |
| `spring-boot-starter-amqp`（配合） | Spring AMQP 客户端 | -amqp 适配器场景 |
| （无独立 starter per 适配器） | — | 适配器模块手动加，版本由 BOM 管理 |

### 5.1 Boot 自动配置要点（Boot 4）

- `@EnableIntegration` 已自动生效（无需手写）——IntegrationFlow Bean 自动装配端点；
- `@MessagingGateway` 接口代理自动注册；
- 默认 `errorChannel` 自动创建（`spring.integration.error.*` 可配行为）。

> 🎯 一句话选型：**starter-integration + 目标系统适配器**——永远由 Boot BOM 锁版本；远程批处理再加 spring-batch-integration。
