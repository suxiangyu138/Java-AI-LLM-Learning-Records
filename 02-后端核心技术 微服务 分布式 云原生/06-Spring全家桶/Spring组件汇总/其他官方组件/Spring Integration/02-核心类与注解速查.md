## 1. 消息与通道

| 类/接口 | 职责 | 说明 |
|---------|------|------|
| `Message<T>` | 不可变消息（headers + payload） | `MessageBuilder.withPayload(x).setHeader(k,v).build()` |
| `MessageHeaders` | 消息头（时间戳、ID、相关键…） | 以 `MessageHeaders.ID` 唯一标识 |
| `MessageChannel` | 通道抽象 | 发消息 `channel.send(msg)` |
| `SubscribableChannel` | 订阅式通道（广播） | DirectChannel（默认同步直连）、PublishSubscribeChannel、ExecutorChannel |
| `PollableChannel` | 可轮询通道（队列） | QueueChannel（容量可配，满则阻塞/丢弃策略） |
| `FluxMessageChannel` | 响应式通道（Reactive Streams） | 与 WebFlux 配合 |
| `ChannelInterceptor` | 通道拦截器 | 发送前/后、消息修正、采样 |
| `MessageSelector` | 消息选择器 | **7.1 起支持 header 值匹配模式**（如 `headers[type]=order`） |
| `WireTap` | 旁路监听 | 日志/审计不打断主流程 |

```java
// 通道声明与使用
@Bean
MessageChannel orders() {
    return new DirectChannel();
}
// 发送
Message<Order> msg = MessageBuilder.withPayload(order)
        .setHeader("type", "NEW_ORDER").build();
orders().send(msg);
```

> 🎯 **要点**：DirectChannel 是同步直连（调用线程内执行）；PublishSubscribe 广播给所有订阅者；QueueChannel + Poller 才是"异步解耦"——**选错通道类型是消息流性能问题的头号来源**。

## 2. EIP 组件与注解

| 模式 | 注解 | DSL 方法 | 说明 |
|------|------|---------|------|
| 转换 | `@Transformer` | `.transform(...)` | 载荷/结构转换 |
| 过滤 | `@Filter` | `.filter(...)` | 返回 false 丢弃消息 |
| 路由 | `@Router` | `.route(...)` | 按规则选目标通道（header/表达式/自定义） |
| 拆分 | `@Splitter` | `.split(...)` | 一拆多 |
| 聚合 | `@Aggregator` | `.aggregate(...)` | 多合一批（按相关性+释放策略） |
| 处理 | `@ServiceActivator` | `.handle(...)` | 业务处理端点 |
| 桥接 | `@BridgeFrom/@BridgeTo` | `.bridge()` | 通道间透传 |
| 增强 | `@HeaderEnricher` | `.enrichHeaders(...)` | 补 header |
| 端点标注 | `@EndpointId` | — | 命名端点（7.x 推荐） |

```java
// 注解式组件（方法注入到消息流）
@Component
class OrderProcessor {
    @Transformer(inputChannel = "in", outputChannel = "out")
    public OrderEnriched enrich(Order order) { return new OrderEnriched(order); }
}
```

> 💡 组件方法规则：入参 = 载荷（或带 `@Payload`/`@Header` 注解的指定参数）；返回值 = 出站消息载荷；抛异常 → 进 errorChannel。

## 3. Java DSL

| API | 说明 |
|-----|------|
| `IntegrationFlow.from(...)` | 流起点：通道名 / MessageSource / Supplier / 网关 |
| `.transform / .filter / .route / .split / .aggregate / .handle` | 各 EIP 步骤 |
| `.channel(...)` | 显式切换通道（含 queue/publishSubscribe/executor 规格） |
| `.enrichHeaders(...)` / `.enrich(...)` | 头/载荷增强 |
| `.wireTap(...)` | 旁路 |
| `.bridge()` | 桥接 |
| `.publishSubscribeChannel(...)` | 广播子流 |
| `.gateway(...)` / `.log(...)` / `.nullChannel()` | 网关/日志/丢弃 |
| `IntegrationFlowAdapter` | 类化封装复杂流 |
| `.get()` | 产出 IntegrationFlow Bean |

```java
@Bean
IntegrationFlow orderFlow(OrderService orderService) {
    return IntegrationFlow.from("inbound")
            .filter(Order::isValid)
            .transform(Order::toEnriched)
            .route("type", m -> m.getPayload().getType().name())
            .split(OrderBatch::getItems)
            .handle(orderService::save)
            .get();
}
```

> 🎯 **要点**：DSL 是 SI 7.x 的首选风格——流程图即代码、IDE 可跳转、`f.context` 调试信息完备；注解式适合老项目/组件复用。

## 4. 网关、轮询与错误处理

| 类/注解 | 职责 |
|---------|------|
| `@MessagingGateway` | 接口代理：调方法 = 发消息/等应答（可配 requestChannel/replyChannel/errorChannel） |
| `GatewayProxyFactoryBean` | 编程式网关代理 |
| `@Poller` / `PollerMetadata` | 轮询配置：fixedDelay / fixedRate / cron / maxMessagesPerPoll |
| `@InboundChannelAdapter` | 定时/事件源 → 通道 |
| `ErrorMessage` / `errorChannel` | 全局错误通道（自动创建，默认日志） |
| `@ServiceActivator` + errorChannel | 错误处理网关（重试/降级/死信） |
| `MessageChannelReactiveUtils` | 响应式适配工具 |

```java
// 网关：接口即消息发送
@MessagingGateway(defaultRequestChannel = "orders")
interface OrderGateway {
    Order submit(OrderRequest request);
}

// 轮询源（每 5 秒读一次文件）
@Bean
IntegrationFlow fileFlow() {
    return IntegrationFlow.from(fileReadingMessageSource(),
                    spec -> spec.poller(p -> p.fixedDelay(5_000)))
            .handle(fileWritingMessageHandler())
            .get();
}
```

> 💡 错误处理最佳实践：业务端点包一层"错误网关"——捕获异常 → 重试/记录/发死信队列，而不是依赖默认日志静默吞掉。

## 5. 消息存储、聚合与锁

| 类/接口 | 职责 | 实现 |
|---------|------|------|
| `MessageStore` / `MessageGroupStore` | 消息/分组的持久化 | SimpleMessageStore（内存）、JdbcMessageStore、RedisMessageStore、MongoMessageStore |
| `MessageGroupQueue` / `MessageGroupDeque` | 基于存储的队列 | 跨实例可靠队列（与 QueueChannel 组合） |
| `CorrelationStrategy` / `ReleaseStrategy` | 聚合相关键 / 释放条件 | MessageGroupSizeReleasingStrategy 等 |
| `LockRegistry` | 跨实例互斥锁 | JdbcLockRegistry、RedisLockRegistry（**7.1 修复了竞态问题**） |
| `MessageHistory` | 消息流转路径记录 | 排障利器 |

```java
// 跨实例可靠队列：JdbcMessageStore + MessageGroupQueue
@Bean
MessageStore messageStore(DataSource ds) {
    return new JdbcMessageStore(ds);
}
@Bean
QueueChannel persistentQueue(MessageStore store) {
    return new QueueChannel(new MessageGroupQueue(store, "orders-group"));
}
```

> 🎯 生产三件套：**持久化 MessageStore（聚合/队列可靠）→ LockRegistry（分布式互斥）→ MessageHistory（流转排障）**。

## 6. 7.1 变化对照

| 维度 | 7.0.x | 7.1.0（2026-06） |
|------|-------|------------------|
| 云事件 | — | CloudEvents 支持（FromCloudEventTransformer / CloudEvents 类） |
| gRPC | 基础支持 | **gRPC DSL**（inbound/outbound gateway） |
| 选择器 | 自定义实现 | MessageSelector 支持 header 值模式匹配 |
| Web | @CrossOrigin 旧式 | 禁 allowCredentials + originPatterns（对齐 MVC） |
| 模式枚举 | 若干 | IntegrationPatternType 新增 `message_store` |
| 修复 | — | 文件写出目录防护、LockRegistry 竞态、gRPC 错误传播 |

> ⚠️ 升级 7.1 注意：@CrossOrigin 行为变化（allowCredentials 默认关闭）可能影响存量 Web 集成端点；文件输出端点的目录越界防护是行为变更点，需回归测试。
