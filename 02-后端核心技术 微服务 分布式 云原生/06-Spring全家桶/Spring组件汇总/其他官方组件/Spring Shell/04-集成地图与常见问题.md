## 1. 集成地图

```text
       终端用户 / CI / 脚本（-c / --script / 交互 REPL）
                        │
                        ▼
        ┌──────────────────────────────┐
        │    Spring Shell 4.0 应用     │
        │   CommandCatalog → @Command  │
        │   （命令方法内调用任意 Bean）  │
        └──────┬──────────┬───────────┘
               │          │
     Spring AI（Agent CLI） Spring Batch（JobOperator 运维触发）
     Spring Security（命令鉴权） Spring Data（查询/管理命令）
               │
     GraalVM Native Image（单文件 CLI，秒起）
```

## 2. 与生态的集成

| 集成对象 | 方式 | 要点 |
|---------|------|------|
| Spring AI / LLM | 命令方法内调 Agent/模型 | **AI CLI 工具**：`ask "..."` 命令 = 交互式 Agent 入口（2026 热门场景） |
| Spring Batch | 命令方法调 JobOperator | 运维终端：启动/停止/重启/查看 Job |
| Spring Security | 命令鉴权 / 认证信息注入 | 敏感命令做权限控制（多用户终端） |
| Spring Data / 服务层 | 直接注入 Bean | 命令 = 服务方法的薄壳 |
| 虚拟线程 / @Async | 命令内异步执行 | 长任务命令异步化 + 进度提示 |
| GraalVM Native | 原生命令自动注册（4.0.2+） | 秒启 CLI、单文件分发 |
| DevTools | 4.0.3 修复 AutoReload | 开发期命令热加载 |
| 监控/指标 | Micrometer 埋点 | 命令执行计数/耗时（可观测） |

> 🎯 集成铁律：**命令类只做"参数解析 + 调服务"的薄壳**，业务逻辑留在服务层——Shell 的复用价值在于"同一套服务，多一个终端入口"，而不是把逻辑写进命令方法。

## 3. 高频问题速查

| 问题 | 根因 | 处理 |
|------|------|------|
| 命令找不到 | @Command 类未注册 / 命令名拼写 | Boot 4 自动注册；检查类是否组件；`help` 查看实际命令名 |
| @ShellMethod 编译失败 | 3.x 注解，4.0 已移除 | 改 @Command / @Option |
| 自定义 Converter 不生效 | 3.x 注册方式残留 | 升级 4.0.3 + 用 Converter<T> 接口 |
| JDK 25 下 tab 补全失效 | JLine 过旧 | 升级 4.0.3（JLine 3.30.13） |
| CI 永远"成功" | 4.0.2 前非交互退出码恒为 0 | 升级 4.0.2+；命令失败配 ExitCodeExceptionProvider |
| 无 TTY 环境启动报错 | 交互模式在无终端环境初始化失败 | `spring.shell.interactive.enabled: false` |
| 子命令布尔标志不生效 | 4.0.2 前缺陷 | 升级 4.0.2+ |
| Profile 不生效 | 4.0.2 前命令注册未感知 profile | 升级 4.0.2+ |
| 原生镜像缺 stg 资源 | runtime hints 缺失 | 升级 4.0.3（已补 JLineRuntimeHints） |
| 历史不持久化 | 默认路径在容器内不可写 | 配 `spring.shell.history.file` + 挂载卷 |

## 4. 排障流程

```text
① 注册层：命令注册了吗？→ help / CommandCatalog 查询；@Command 类是否在扫描路径
② 解析层：参数解析对吗？→ 看报错是"未知选项"还是"转换失败"（Converter 日志）
③ 执行层：方法执行失败？→ 异常堆栈（本地开 stacktrace 命令查看）
④ 退出层：CI 退出码对吗？→ ExitCodeExceptionProvider 是否实现；4.0.2+ 真实退出码
⑤ 环境层：无 TTY？原生镜像？→ interactive.enabled=false；runtime hints 检查
```

> 💡 排障三利器：**help（注册事实）、stacktrace 命令（执行细节）、退出码（结果语义）**——CLI 排障先确认"命令到底注册没有"。

> 🎯 **核心要点**：集成地图一句话 = "Shell 是 Spring 能力的终端化入口——薄壳命令 + 服务层复用 + 退出码面向 CI"；4.0 迁移与 AI CLI 是两个最值得投入的方向。深挖见 [官方参考文档](https://docs.spring.io/spring-shell/reference/)。
