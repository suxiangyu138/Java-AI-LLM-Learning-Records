## 1. 核心模块

| Artifact | 说明 |
|----------|------|
| `spring-cloud-stream` | 核心：编程模型、绑定抽象、配置体系、Binder SPI |
| `spring-cloud-stream-test-binder` | 测试专用 Binder，不连接真实中间件 |
| `spring-cloud-stream-binder-test` | Binder 抽象测试套件（写自定义 Binder 时复用） |
| `spring-cloud-stream-parent` | 父 POM（构建管理） |
| `spring-cloud-stream-schema` | 基于 Avro 的 schema 注册（早期版本遗留，现代方案推荐 Confluent Schema Registry / Apache Avro 或 JSON Schema） |

核心模块依赖 `spring-cloud-function`（`spring-cloud-function-context` 等），函数式模型由 Spring Cloud Function 提供，Stream 在其上补充绑定层能力。

## 2. Binder 模块清单

| Binder Artifact | 对应中间件 | 状态 |
|-----------------|-----------|------|
| `spring-cloud-stream-binder-kafka` | Apache Kafka | 官方维护（主力） |
| `spring-cloud-stream-binder-kafka-reactive` | Apache Kafka（Reactor Kafka，响应式） | 官方维护（4.0 起） |
| `spring-cloud-stream-binder-kafka-streams` | Kafka Streams（流处理/状态化计算） | 官方维护 |
| `spring-cloud-stream-binder-rabbit` | RabbitMQ | 官方维护（主力） |
| `spring-cloud-stream-binder-kinesis` | AWS Kinesis | 官方维护（AWS 侧） |
| `spring-cloud-stream-binder-google-pubsub` | Google Cloud Pub/Sub | 官方维护（GCP 侧） |
| `spring-cloud-stream-binder-azure-eventhubs` | Azure Event Hubs | 官方维护（Azure 侧） |
| `spring-cloud-stream-binder-solace` | Solace PubSub+ | 官方维护（Solace 侧） |
| `spring-cloud-stream-binder-artemis` | ActiveMQ Artemis | 社区/官方维护 |
| `spring-cloud-stream-binder-pulsar` | Apache Pulsar | 社区方案（非官方主推，Pulsar 场景评估时留意） |

> 💡 **选型要点**：绝大多数项目在 `kafka` 与 `rabbit` 之间二选一；云厂商绑定器（Kinesis/GCP/Azure）用于云原生托管消息服务；响应式 Binder 仅在 WebFlux 全链路响应式场景使用（见 [06-Kafka Binder深入](06-Kafka Binder深入.md)）。

## 3. 版本矩阵

### 3.1 Stream ↔ 发布列车 ↔ Boot 对应关系

| Spring Cloud Stream | Spring Cloud 列车 | Spring Boot | 说明 |
|:---:|:---:|:---:|------|
| **5.0.x（5.0.2）** | 2025.1.x **Oakwood** | **4.0.x** | 当前主线：Boot 4 基线；5.0.1 起兼容 Boot 4.0.1+ |
| 4.3.x | 2025.0.x（Northfields） | 4.0.x 早期 / 3.5.x | 过渡列车 |
| 4.2.x（4.2.4） | 2024.0.x（Moorgate） | 3.4.x | Boot 3.x 长期线，存量项目主力 |
| 4.1.x | 2023.1.x（Leyton） | 3.2.x | Boot 3 早期 |
| 4.0.x | 2023.0.x（Kilburn） | 3.2.x | 注解模型彻底移除、响应式 Kafka Binder 引入 |
| 3.2.x | 2022.0.x（Jubilee） | 2.7.x / 3.0.x | 注解模型弃用期（函数式成为推荐） |
| 3.1.x | 2021.0.x（Jubilee） | 2.6.x | 函数式模型成熟 |

> ⚠️ **踩坑提示**：Stream 4.0 起只支持函数式模型，从 3.x 迁移不能靠改依赖版本完成，必须重写绑定声明（详见 [5. 历史版本演进](#5-历史版本演进) 与 [10-生产实践与选型避坑](10-生产实践与选型避坑.md)）。

### 3.2 Kafka 依赖链版本（5.0.x 基准）

| 依赖 | 版本参考 | 说明 |
|------|---------|------|
| Spring Cloud Function | 5.0.x（与 Stream 同列车） | 提供函数式模型运行时 |
| Spring for Apache Kafka | 4.0.x 时代版本 | Binder 底层容器，`spring-kafka` |
| kafka-clients | 3.9.x / 4.x | 由 spring-kafka 传递管理 |
| Reactor Kafka（仅响应式） | 1.4.x | `binder-kafka-reactive` 底层 |

### 3.3 Rabbit 依赖链版本（5.0.x 基准）

| 依赖 | 版本参考 | 说明 |
|------|---------|------|
| Spring AMQP | 4.0.x 时代版本 | Rabbit Binder 底层，`spring-rabbit` |
| RabbitMQ Java Client | 5.x | 由 spring-amqp 传递管理 |

> ⚠️ 以上依赖版本由 BOM 统一管理，**不要手工指定** spring-kafka / spring-rabbit 版本；引入 Binder 依赖即可，版本冲突时先查 BOM 归属。

## 4. 5.0.x 新特性与变更

### 4.1 5.0.0（2025.1.0-M2 起随 Oakwood 发布）

| 变更 | 说明 |
|------|------|
| 消费者优先级 | 新增 consumer priority 支持（issue #3147），Kafka 消费组内按优先级分配分区 |
| Kafka Streams Binder：KTable 物化控制 | 新增 `CacheEnabled`、`LoggingEnabled` 属性，控制 KTable 状态缓存与日志（#3136、#3094） |
| Kafka 事务管理器迁移 | `KafkaMessageChannelBinder` 改用 `ContainerProperties#setKafkaAwareTransactionManager`，替换已废弃的 `setTransactionManager`（#3130） |
| 修复：自定义 binder 依赖注入 | 非空属性下自定义 `KafkaMessageChannelBinder` 的依赖未注入（#3148） |
| 修复：容器设置传播 | 容器设置未传播到独立监听器（#3124） |
| 修复：Target Protocol 头 | 非 Kafka/Rabbit Binder 下 Target Protocol 头错误（#2222） |

### 4.2 5.0.x 维护版

| 版本 | 关键内容 |
|------|---------|
| 5.0.1 | 兼容 Spring Boot 4.0.1 及后续 4.0.x（2025.0.0 列车与这些 Boot 版本不兼容） |
| 5.0.2 | 修复 Kafka Binder 多绑定场景失效（#3173）；补充 `MessageRoutingCallback` 事件路由文档（#3198）；修正 `republishToDlq` 文档默认值（#3142） |

## 5. 历史版本演进

| 版本 | 里程碑 | 影响 |
|------|--------|------|
| 1.x（2016） | 注解模型 `@EnableBinding` + `@StreamListener` + `@InboundChannelAdapter` | 奠基，Channel/SubscribableChannel 模型 |
| 2.x | 消息通道模型成熟、`@StreamListener` 条件匹配、分区支持完善 | 国内教材主流时代 |
| 3.0（2020） | **函数式模型成为推荐**；Spring Cloud Function 2.x 集成 | 新项目开始用函数式 |
| 3.2 | 函数式功能补齐：`function.bindings`、函数组合、多输入输出 | Boot 2.7 长期线 |
| 4.0（2023） | **注解模型彻底移除**；响应式 Kafka Binder 引入；`zkNodes` 配置删除；错误目的地命名调整 | 必须函数式 |
| 4.2/4.3 | Boot 3.4+、Kafka 客户端升级、DLC 与重试行为文档修正 | Boot 3.x 长期线 |
| 5.0（2025.12+） | **Boot 4 基线**；消费者优先级；Kafka Streams KTable 控制；事务管理器 API 迁移 | 当前主线 |
