## 1. 属性体系总览

```text
spring.cloud.stream
 ├── default-binder                      全局默认 Binder
 ├── binders.<name>                      Binder 定义（type/environment）
 ├── poller.*                            轮询器（Supplier 轮询）
 ├── function.bindings.<fn>             函数绑定名 → 自定义绑定名映射
 ├── bindings.<binding>                  绑定配置（核心）
 │    ├── destination / group / content-type / binder
 │    ├── consumer.*                     消费侧属性
 │    └── producer.*                     生产侧属性
 ├── kafka.bindings.<binding>.*          Kafka Binder 专属（consumer/producer/binder 三级）
 ├── rabbit.bindings.<binding>.*         Rabbit Binder 专属
 └── source                               StreamBridge 显式源声明（; 分隔多源）
```

## 2. 公共绑定属性

| 属性 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `bindings.<b>.destination` | String | 绑定名 | 逻辑目的地名 |
| `bindings.<b>.group` | String | - | 消费组（不配=匿名消费者） |
| `bindings.<b>.content-type` | String | `application/json`（有类型信息时自动推断） | 消息内容类型，驱动转换器选择 |
| `bindings.<b>.binder` | String | default-binder | 指定该绑定使用的 Binder |
| `bindings.<b>.default-binder` | String | - | 旧属性名，功能同上（2.x 遗留） |

## 3. Producer 属性全表

| 属性 | 默认 | 说明 |
|------|------|------|
| `producer.partition-key-expression` | - | 分区键 SpEL（`payload.orderId` / `headers['k']`） |
| `producer.partition-key-extractor-name` | - | 自定义 `PartitionKeyExtractorStrategy` Bean 名 |
| `producer.partition-selector-name` | - | 自定义 `PartitionSelectorStrategy` Bean 名 |
| `producer.partition-count` | 3 | 分区数量（Kafka 自动建 topic 时决定分区数） |
| `producer.required-groups` | - | 需等待生产者确认的消费组列表（Kafka: 确认 group 存在并绑定后才发送；Rabbit: 确认队列绑定完成） |
| `producer.error-channel-enabled` | false | 生产异常是否发布到错误通道（`<binding>.errors`） |
| `producer.use-native-encoding` | false | 是否用 binder 原生序列化，绕过消息转换器 |
| `producer.direct-bind-destination` | - | 直接绑定目的地（跳过中转主题，Rabbit 相关） |

```yaml
spring:
  cloud:
    stream:
      bindings:
        order-out-0:
          destination: order-events
          producer:
            partition-key-expression: payload.orderId
            partition-count: 12
            required-groups: order-service   # 等组就绪再发，避免丢消息
```

> 💡 **required-groups 是"启动期不丢消息"的关键**：Kafka 下生产者会等到指定消费组的分区分配完成后才开始发送，防止"发得快、组还没就绪"造成的 offset 跳跃。

## 4. Consumer 属性全表

### 4.1 通用消费属性

| 属性 | 默认 | 说明 |
|------|------|------|
| `consumer.concurrency` | 1 | 并发消费者数（Kafka: listener 容器数；Rabbit: concurrentConsumers） |
| `consumer.max-attempts` | 3 | 最大尝试次数（含首次）；`1` 表示不重试（仅对 binder 级重试生效） |
| `consumer.back-off-initial-interval` | 1000ms | 重试首次退避 |
| `consumer.back-off-max-interval` | 10000ms | 重试最大退避 |
| `consumer.backoff-multiplier` | 2.0 | 退避乘数 |
| `consumer.batch-mode` | false | 批量模式（函数签名变 `List`） |
| `consumer.partitioned` | false | 输入绑定感知分区（Rabbit 下分区路由必需） |
| `consumer.instance-count` / `instance-index` | - | 分区手动分配场景声明实例数/索引 |
| `consumer.auto-rebalance-enabled` | true | 自动再均衡（false 时配合 instance-* 手动分配） |
| `consumer.error-channel-enabled` | false | 消费异常转发到错误通道 |
| `consumer.header-mode` | - | 头模式（raw/none/headers） |

### 4.2 错误处理相关（与 [08](08-消息可靠性与重试死信.md) 联动）

| 属性 | 默认 | 说明 |
|------|------|------|
| `consumer.default-retryable`（Kafka） | false | 未显式列出的异常是否可重试 |
| `consumer.retryable-exceptions`（Kafka） | - | 指定可重试异常类列表 |
| `consumer.common-error-handler-bean-name` | - | 共用错误处理器 Bean 名（4.x 仍支持） |

## 5. 内容类型与类型转换

### 5.1 转换链

```text
入站: byte[] → content-type 解析 → MessageConverter → 目标类型（函数泛型）
出站: 业务对象 → MessageConverter → 序列化 → byte[]
```

| content-type 值 | 转换行为 |
|-----------------|---------|
| `application/json` | Jackson 序列化/反序列化 |
| `application/x-java-object` | Java 原生序列化（不推荐跨语言） |
| `application/x-java-serialized-object` | 同上，显式旧格式 |
| `text/plain` | 字符串直通 |
| `application/octet-stream` | 原始字节直通 |

### 5.2 类型推断与显式声明

函数式模型按函数泛型自动推断转换目标类型：

```java
@Bean
public Consumer<OrderEvent> orderLogger() { ... }   // 自动按 OrderEvent 反序列化
```

显式覆盖：

```yaml
spring:
  cloud:
    stream:
      bindings:
        orderLogger-in-0:
          content-type: application/json
```

> ⚠️ **转换易错点**：
> 1. record/POJO 无默认构造器或缺少无参构造时 Jackson 反序列化失败；
> 2. 泛型擦除导致目标类型推断失败（`Consumer<Object>`），需显式 `content-type` + 自定义转换器；
> 3. `use-native-encoding` 与转换器冲突——启用后框架不参与编解码，类型必须与 binder 原生格式一致。

## 6. 消息转换器机制

| 转换器 | 职责 | 注册方式 |
|--------|------|---------|
| `MessageConverter` | 内容类型 ↔ 对象 | 框架内置 JSON/文本/字节；自定义实现注册为 Bean |
| `SmartMessageConverter` | 支持目标类型提示（从函数泛型获取） | 同上，推荐实现此接口 |
| Binder 原生序列化 | `use-native-encoding` 时由 binder 直接序列化 | 不需要额外配置 |

自定义转换器示例：

```java
@Bean
public SmartMessageConverter orderConverter() {
    return new MappingJackson2MessageConverter() {
        @Override
        protected boolean supports(Class<?> targetType, Object value, TypeDescriptor targetTypeDescriptor) {
            return OrderEvent.class.equals(targetType);
        }
    };
}
```

## 7. Binder 级公共属性

| 属性 | 默认 | 说明 |
|------|------|------|
| `spring.cloud.stream.binders.<name>.type` | - | Binder 类型（kafka/rabbit/kinesis/...） |
| `spring.cloud.stream.binders.<name>.inherit-environment` | true | 是否继承应用环境变量 |
| `spring.cloud.stream.binders.<name>.default-candidate` | true | 是否参与默认 Binder 选择 |
| `spring.cloud.stream.binders.<name>.environment` | - | Binder 专属环境（可覆盖全局配置） |
| `spring.cloud.stream.kafka.binder.brokers` | `localhost:9092` | Kafka 连接地址（kafka 前缀 binder 级） |
| `spring.cloud.stream.rabbit.binder.addresses` | `localhost:5672` | Rabbit 连接地址 |

## 8. 属性优先级

从高到低：

```text
命令行参数 > application-{profile}.yml > application.yml > Binder environment > 绑定默认值
```

- 绑定级（`bindings.<b>.*`）优先于 Binder 级（`kafka.binder.*`）；
- Binder environment 内可写任意 `spring.*` 属性，且仅对该 Binder 生效（多 Binder 隔离的常用手段）。

> ⚠️ **多 Binder 环境覆盖示例**：Kafka binder 的 `environment` 中写 `spring.cloud.stream.kafka.binder.brokers: cluster-a:9092` 即可让该 Binder 连集群 A，而全局配置连本地。

## 9. 核心要点

> 🎯 **核心要点**：
> - 绑定属性三件套：`destination`（连哪）、`group`（谁消费）、`binder`（用哪个中间件）；
> - producer 三高频：`partition-key-expression`（有序性）、`partition-count`（并行度）、`required-groups`（防启动期丢消息）；
> - consumer 三高频：`max-attempts`（重试）、`batch-mode`（吞吐）、`concurrency`（并发）；
> - 内容类型驱动转换，函数泛型自动推断目标类型；自定义转换器实现 `SmartMessageConverter`；
> - 属性优先级：命令行 > profile > 主配置 > Binder environment > 默认值。
