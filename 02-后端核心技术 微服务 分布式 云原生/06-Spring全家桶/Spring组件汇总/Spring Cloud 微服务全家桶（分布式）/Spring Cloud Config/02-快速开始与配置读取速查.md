```xml
</dependency>
```

## 2. 配置仓库组织（Git 后端）

### 2.1 文件命名规则（核心！）

```text
配置仓库根目录
├── application.yml                  # ★ 全局共享配置（所有应用）
├── application-dev.yml              # 全局 + dev 环境
├── order-service.yml                # ★ order-service 应用的配置
├── order-service-dev.yml            # order-service + dev 环境
├── order-service-prd.yml
├── payment-service.yml
└── ...
查找规则：{application}-{profile}.yml
  ├── application    = 应用名（spring.application.name）
  ├── profile        = 激活的环境（dev/test/prd...）
  └── label          = Git 分支/标签（默认 master/main）
```

> 🎯 面试必答：**"Config 怎么做到多环境隔离？"**——按 **`{application}-{profile}` 文件名**组织：每个应用有基础配置（order-service.yml）+ 环境覆盖（order-service-dev.yml / -prd.yml），Config Server 按客户端激活的 profile 决定返回哪些文件，客户端属性优先级 = 更具体的文件覆盖更通用的文件。

### 2.2 一份配置文件的两种写法

```yaml
# order-service.yml
server:
  port: 8081
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/order
    username: root
    password: '{cipher}AKJ...'     # ★ {cipher} 加密值（见 06 篇）
management:
  endpoints:
    web:
      exposure:
        include: refresh, health
```

```properties
# order-service.properties（等价写法，二选一）
server.port=8081
spring.datasource.url=jdbc:mysql://localhost:3306/order
```

> ⚠️ **注意**：properties 里的 {cipher} 值**不能加引号**（加了不解密）；yaml 里必须加引号（否则 YAML 解析问题）。

## 3. Config Server 配置

### 3.1 最小配置（application.yml）

```yaml
server:
  port: 8888
spring:
  application:
    name: config-server
  cloud:
    config:
      server:
        git:
          uri: https://github.com/you/config-repo    # ★ 仓库地址（默认 https://github.com/spring-cloud-samples/config-repo）
          # 私有仓库认证：
          username: ${GIT_USER}                       # 或 token 方式（https://user:token@host/repo）
          password: ${GIT_TOKEN}
          # 本地仓库默认克隆到：${user.home}/config-repo（可改）
          basedir: /data/config-repo-work
```

```java
@SpringBootApplication
@EnableConfigServer                    // ★ 唯一开关
public class ConfigServerApplication {
    public static void main(String[] args) {
        SpringApplication.run(ConfigServerApplication.class, args);
    }
}
```

### 3.2 常用 Server 配置项

| 配置 | 默认 | 说明 |
|------|------|------|
| spring.cloud.config.server.git.uri | 示例仓库 | 仓库地址 |
| spring.cloud.config.server.git.username/password | — | 私有仓库凭证 |
| spring.cloud.config.server.git.basedir | ~/config-repo | 本地工作目录 |
| spring.cloud.config.server.git.clone-on-start | false | 启动时立即 clone（true 可提前暴露错误） |
| spring.cloud.config.server.git.default-label | master | 默认分支（Git 2.28+ 仓库建议 main） |
| spring.cloud.config.server.git.timeout | 5s | clone/fetch 超时 |
| spring.cloud.config.server.git.force-pull | false | 本地冲突时强制 fetch（多 Server 部署建议 true） |
| spring.cloud.config.server.bootstrap | false | Server 自己拉自身配置（Config Server 的配置集中管理） |

> ⚠️ **多 Server 部署注意**：多个 Config Server 实例共享一个 Git 仓库时，**每个实例有自己的本地工作目录**——本地文件落后于远端时用 `force-pull: true` 或清 basedir 解决（[07 篇](07-安全认证与生产运维.md) 高可用）。

## 4. Config Client 配置

### 4.1 最小配置（application.yml）

```yaml
spring:
  application:
    name: order-service                  # ★ 决定拉哪个配置文件
  config:
    import: optional:configserver:http://localhost:8888   # ★ 拉取入口
  cloud:
    config:
      uri: http://localhost:8888         # 与 import 内联地址二选一（内联优先）
```

> 💡 **optional: 前缀含义**：`optional:configserver:` = **拉不到配置也能启动**（本地开发友好）；去掉 optional = 拉不到直接启动失败（生产建议，配合 fail-fast 语义）。

### 4.2 客户端常用配置项

| 配置 | 默认 | 说明 |
|------|------|------|
| spring.config.import | 无 | 导入入口（可内联 URL） |
| spring.cloud.config.uri | http://localhost:8888 | Server 地址（多地址逗号分隔） |
| spring.cloud.config.name | ${spring.application.name} | 拉取的应用名（覆盖） |
| spring.cloud.config.profile | ${spring.profiles.active} | 拉取的环境 |
| spring.cloud.config.label | 默认分支 | 拉取的 Git 分支 |
| spring.cloud.config.username/password | — | Server 认证凭证 |
| spring.cloud.config.token | — | Vault token |
| spring.cloud.config.request-connect-timeout | 6s | 连接超时 |
| spring.cloud.config.request-read-timeout | 60s | 读取超时 |
| spring.cloud.config.fail-fast | false | 启动拉取失败直接失败（bootstrap 模式） |
| spring.cloud.config.discovery.enabled | false | 通过注册中心发现 Server |
| spring.cloud.config.discovery.service-id | configserver | 注册中心里的 Server 服务名 |
| spring.cloud.config.retry.* | 6 次/1s×1.1 | 拉取失败重试（需 spring-retry） |

### 4.3 多 Server 地址容错

```yaml
spring:
  cloud:
    config:
      uri: http://config-1:8888,http://config-2:8888   # 逗号分隔，按序尝试
      multiple-uri-strategy: always                     # always=每个地址都试；connection-timeout-only=只试连接失败
```

## 5. 配置查找顺序与优先级

### 5.1 一次请求的查找顺序（Server 端）

```text
请求：GET /order-service/dev/master
Server 依次查找（找到即停）：
  ① order-service-dev.yml（应用+环境）
  ② order-service-dev.properties
  ③ order-service.yml（应用基础）
  ④ order-service.properties
  ⑤ application-dev.yml（全局+环境）
  ⑥ application.yml（全局基础）
  ⑦ application.properties
找不到 → 404
```

### 5.2 客户端属性源优先级（合并后）

```text
低 ────────────────────────────────────────────────────────────────► 高
application.yml（本地默认） < application-{profile}.yml < 远程配置（Config 拉的）
  └── 远程配置按文件顺序插入，越具体的（order-service-dev）越靠后（优先级越高）
  └── @ConfigurationProperties / @Value 读到的是合并后的最终值
```

> 🎯 面试必答：**"本地配置和远程配置谁优先？"**——**远程（Config）配置覆盖本地**：Config Data 加载时把远程 propertySources 追加到属性源链靠后位置，后加载的覆盖先加载的；所以"本地写死了远程覆盖不了"是错误认知（除非用了更高优先级的位置如命令行参数）。

### 5.3 覆盖远程配置的特例（Server 端 override）

```yaml
spring:
  cloud:
    config:
      server:
        override-none: false            # false=允许 Server 覆盖客户端本地属性
        override-system-properties: false  # 是否覆盖系统属性
```
> 用于"Server 强制统一下发"（如安全开关），默认关闭，生产一般不用。

## 6. HTTP 端点与返回格式

### 6.1 核心端点

| 端点 | 说明 |
|------|------|
| `GET /{application}/{profile}` | 常规拉取（label 默认 master） |
| `GET /{application}/{profile}/{label}` | 指定分支/标签 |
| `GET /{label}/{application}-{profile}.yml` | 直接返回 yaml 文本（服务端拼） |
| `GET /{application}-{profile}.properties` | 直接返回 properties 文本 |
| `GET /{application}-{profile}.json` | 直接返回 json |
| `GET /encrypt` / `POST /decrypt` | 加解密端点（[06 篇](06-加密解密与密钥管理速查.md)） |
| `POST /monitor` | Webhook 触发刷新（配合 Bus，[05 篇](05-动态刷新与Bus集成速查.md)） |

### 6.2 标准 JSON 返回结构

```json
// GET /order-service/dev
{
  "name": "order-service",
  "profiles": ["dev"],
  "label": "master",
  "version": "a1b2c3d",                  // Git commit 版本
  "state": null,
  "propertySources": [
    {
      "name": "https://github.com/you/config-repo/order-service-dev.yml",
      "source": { "server.port": 8082, "spring.datasource.url": "jdbc:mysql://dev-db:3306/order" }
    },
    {
      "name": "https://github.com/you/config-repo/order-service.yml",
      "source": { "server.port": 8081, "spring.datasource.username": "root" }
    },
    {
      "name": "https://github.com/you/config-repo/application-dev.yml",
      "source": { "log.level": "DEBUG" }
    }
  ]
}
```

> 💡 排查利器：**直接浏览器访问这个 JSON**——一眼看出 Server 有没有找到文件、合并顺序对不对、version 是不是最新 commit（[07 篇](07-安全认证与生产运维.md) 排障）。

## 7. 三步验证与排障

### 7.1 验证清单

| 步骤 | 做法 | 预期结果 |
|------|------|---------|
| ① Server 拉得到 | `curl http://localhost:8888/order-service/dev` | JSON 含 3 个 propertySources，version = 最新 commit |
| ② 客户端拉得到 | 起客户端看启动日志 | `Located property source: [BootstrapPropertySource... configserver:http://localhost:8888]` 或 Config Data 日志 |
| ③ 配置生效 | 客户端接口读配置值 | 返回远程值（如 server.port=8082 走了 dev 覆盖） |
| ④ 刷新生效 | 改 Git → `POST /actuator/refresh` | @RefreshScope Bean 新值（见 [05 篇](05-动态刷新与Bus集成速查.md)） |

### 7.2 排障起点

| 现象 | 大概率原因 | 处理 |
|------|-----------|------|
| /order-service/dev 404 | 文件名不匹配（application.name 拼错 / 文件不在仓库根） | 核对 `{app}-{profile}.yml` 命名 |
| 拉到的是旧配置 | Server 本地工作目录没 fetch 新 commit | 看 JSON 的 version 字段；force-pull / 清 basedir |
| 客户端没拉到（无日志） | spring.config.import 没写 / 写错 | 检查 Config Data 日志；optional: 前缀去掉看报错 |
| 属性值不对 | 优先级理解错（本地覆盖了远程？） | 看 /actuator/env 的 propertySources 顺序 |
| 私有仓库认证失败 | 凭证/token 没配或过期 | git.username/password 或 URL 内嵌 token |

> 💡 排障第一招永远是：**浏览器打开 `/{app}/{profile}` 看 JSON**——Server 端的问题全部暴露在响应里（404=文件问题，旧 version=工作目录问题，invalid.* 属性=解密问题）。
