## 1. 后端总览与选型地图

| 后端 | 存储模型 | 配置形式 | 适用场景 | 生产推荐 |
|------|---------|---------|---------|:---:|
| **Git** | Git 仓库 | 文件（yml/properties/json） | 通用主战场、版本化管理 | ✅ 默认 |
| 文件系统 | 本地目录 | 文件 | 开发调试、无 Git 环境 | ⚠️ 测试 |
| **Vault** | 秘钥引擎 | Key-Value | 密码/证书/Token 等敏感项 | ✅ 复合使用 |
| JDBC | 数据库表 | 行记录 | 已有 MySQL、要 SQL 管理 | ✅ 可选 |
| Redis | Hash | 键值 | 已有 Redis、高频读 | ✅ 可选 |
| MongoDB | Document | 文档 | 已有 Mongo | ⚠️ 少见 |
| AWS S3 | 对象存储 | 对象文件 | AWS 环境 | ✅ AWS 生态 |
| AWS Secrets Manager | 秘钥服务 | 秘钥 | AWS 敏感配置 | ✅ AWS 生态 |
| AWS Parameter Store | 参数存储 | 参数 | AWS 普通配置 | ✅ AWS 生态 |
| Google Secret Manager | 秘钥服务 | 秘钥 | GCP 环境 | ✅ GCP 生态 |
| CredHub | 秘钥服务 | 秘钥 | Cloud Foundry | ⚠️ CF 生态 |

> 🎯 选型心智：**普通配置 → Git（默认，版本化）；敏感配置 → Vault/AWS Secrets Manager（专业秘钥）；数据量级/已有基建 → JDBC/Redis；云环境 → 云厂商原生服务**；大部分团队 = Git + Vault 复合（[07 篇](07-安全认证与生产运维.md) 复合组合）。

## 2. Git 后端（默认主战场）

### 2.1 核心机制

```text
Git 后端 = JGit 实现的"懒克隆"模型：
  ├── 首次请求某配置 → clone 仓库到本地 basedir（~/.config-repo）
  ├── 后续请求 → fetch 远端（默认每次请求都 fetch，可配 fetch-interval 缓存）
  ├── 工作目录按 branch（label）切换 checkout
  └── 多分支：master/main + 自定义 label（灰度分支）
```

### 2.2 配置项速查

```yaml
spring:
  cloud:
    config:
      server:
        git:
          uri: https://github.com/you/config-repo
          username: ${GIT_USER}
          password: ${GIT_TOKEN}
          basedir: /data/config-repo       # 本地工作目录
          default-label: main              # 默认分支（新仓库用 main）
          clone-on-start: true             # 启动即 clone（快速暴露仓库配置错误）
          force-pull: true                 # 本地落后强制拉取（多 Server 必配）
          timeout: 10s                     # clone/fetch 超时
          fetch-interval: 0                # fetch 缓存间隔（0=每次请求都 fetch；>0=按秒缓存，性能好但延迟）
          # 子目录/通配符：
          search-paths: order,payment/**   # 只在仓库子目录找配置
          # 本地仓库（不走网络）：
          uri: file:///data/config-repo    # file:// 前缀指向本地 Git 仓库
          # 通配符 URI（多仓库）：
          uri: https://github.com/you/*     # * 匹配 {application}（org/repo* 形式）
```

### 2.3 多仓库通配符（按应用分仓库）

```yaml
spring:
  cloud:
    config:
      server:
        git:
          uri: https://github.com/{application}     # {application} = 应用名
          # 或
          uri: https://github.com/you/*             # 每个应用一个仓库：order-service 请求 → you/order-service
```

> ⚠️ 通配符仓库的坑：**通配符匹配的仓库没有"本地基于单一仓库的性能优化"**（每应用一个工作目录），且分支（label）必须在通配仓库里存在，否则请求失败。

### 2.4 Git 后端的坑（生产高频）

| 坑 | 现象 | 解决 |
|----|------|------|
| 工作目录落后 | 改了 Git 配置拉不到新值 | force-pull: true / 清 basedir / 看响应 version 字段 |
| 私有仓库凭证过期 | 401/无法 clone | 用专用 token（不要用个人密码） |
| 大仓库启动慢 | 首次请求阻塞几十秒 | clone-on-start: true + 启动探针 |
| 分支不存在 | 请求 /label 404 | 确认分支名；default-label 与仓库默认分支一致 |
| 并发 fetch 冲突 | 多 Server 或高并发 fetch 异常 | 单 Server 内存共享 + 多 Server 用 force-pull |

## 3. 文件系统后端（开发/测试）

```yaml
spring:
  cloud:
    config:
      server:
        native:
          search-locations: file:///data/config-repo   # 本地目录（不 clone，直接读文件）
# 启用方式：spring.profiles.active=native
```

| 维度 | 说明 |
|------|------|
| 用途 | 开发调试（没有 Git 服务器时）、CI 本地验证 |
| 与 Git 区别 | 直接读本地文件，无版本概念、无 fetch |
| 生产 | ❌ 不推荐（无版本化、无集中管理） |

> 💡 常用组合：**开发环境 `--spring.profiles.active=native` + 本地目录**，生产用 Git——同一套代码两套后端。

## 4. Vault 后端（秘钥管理）

### 4.1 定位与配置

```yaml
spring:
  cloud:
    config:
      server:
        vault:
          host: vault.example.com
          port: 8200
          scheme: https
          authentication: TOKEN          # TOKEN / KUBERNETES / APPID / APPROLE / AWS_EC2 ...
          token: ${VAULT_TOKEN}          # TOKEN 认证用
          kvVersion: 2                   # KV 引擎版本（Vault 1.9+ 默认 2）
          defaultKey: application        # 默认键
          profileSeparator: '/'          # profile 分隔符（默认 / → application/order-service）
```

### 4.2 读取语义

```text
客户端请求 /order-service/dev → Vault 路径查找：
  secret/order-service/dev
  secret/order-service
  secret/application/dev
  secret/application
KV v2 引擎 → 实际读 secret/data/...
```

> 🎯 什么时候用 Vault：**密码、证书、API Token 这类"秘钥"不适合放 Git（即使加密，审计/轮换也弱）**——Vault 原生支持版本化、租期（lease）、自动轮换、访问控制；典型组合 = **Git 管普通配置 + Vault 管秘钥**（复合后端，见第 7 节）。

### 4.3 与 {cipher} 加密的取舍

| 方案 | 存储位置 | 轮换 | 审计 | 复杂度 |
|------|---------|------|------|--------|
| Git + {cipher} | Git（密文） | 手动重加密 | Git 日志 | 低 |
| Vault | Vault 引擎 | 自动/租期 | Vault audit | 中 |
| 混合（复合） | 普通配置 Git，秘钥 Vault | 按需 | 两者 | 中 |

> 💡 实践建议：**小团队/轻量用 {cipher}（零新组件）；有安全合规要求（PCI/等保）用 Vault**。

## 5. 数据类后端：JDBC / Redis / MongoDB

### 5.1 JDBC（MySQL/PostgreSQL）

```sql
-- 表结构（固定，不能改列名）
CREATE TABLE properties (
    application VARCHAR(128) NOT NULL,
    profile     VARCHAR(128) NOT NULL,
    label       VARCHAR(128) NOT NULL,
    key         VARCHAR(512) NOT NULL,
    value       VARCHAR(2048),
    PRIMARY KEY (application, profile, label, key)
);
INSERT INTO properties VALUES ('order-service', 'dev', 'main', 'server.port', '8082');
```

```yaml
spring:
  cloud:
    config:
      server:
        jdbc:
          sql: SELECT key, value FROM properties WHERE application=? AND profile=? AND label=?
          order-by: key                # 排序（保证优先级可预测）
  datasource:
    url: jdbc:mysql://localhost:3306/config
    username: root
    password: root
```

| 维度 | 说明 |
|------|------|
| 优点 | 已有 MySQL 基建直接复用；配置可 SQL 管理/备份 |
| 缺点 | 无版本化（需自己维护变更表）；性能受 DB 约束 |
| 适用 | 已有 DB 基建且团队偏好 SQL 管理配置 |

### 5.2 Redis

```yaml
spring:
  cloud:
    config:
      server:
        redis:
          # 连接信息来自 spring.data.redis.*
```

```bash
# 数据模型：Hash
HSET order-service:dev:main server.port 8082
HSET order-service:dev:main spring.datasource.url jdbc:mysql://dev-db:3306/order
```

> 💡 Redis 后端的优势是**读性能**（高频拉取场景），适合"配置变化不频繁但读取量大"；配置管理工具链弱（无版本化、无审计），生产不多见。

### 5.3 MongoDB

```yaml
spring:
  cloud:
    config:
      server:
        mongodb:
          # 连接信息来自 spring.data.mongodb.*
```

```text
文档模型（collection: config）：
{ "application": "order-service", "profile": "dev", "label": "main", "key": "server.port", "value": "8082" }
```

> ⚠️ 与 Redis 类似：仅当团队已有 Mongo 基建才考虑；**普通团队选 Git 或 JDBC 即可，不要为配置中心引入新存储**。

## 6. 云原生后端：AWS / Google / CredHub

### 6.1 AWS 三件套

```yaml
spring:
  cloud:
    config:
      server:
        aws:
          region: us-east-1
          # 凭证走默认链（环境变量/IAM 角色...）
        aws-s3:                          # S3 对象存储（文件形式）
          region: us-east-1
          bucket: my-config-bucket
        aws-parameter-store:             # Parameter Store（普通参数）
          region: us-east-1
          prefix: /config
        aws-secrets-manager:             # Secrets Manager（敏感秘钥）
          region: us-east-1
          prefix: /config
```

| 后端 | 放什么 | 类似 |
|------|--------|------|
| S3 | 配置文件对象 | Git 文件 |
| Parameter Store | 普通参数（有版本、可分层路径） | Git + {cipher} |
| Secrets Manager | 秘钥（自动轮换、加密） | Vault |

> 🎯 AWS 团队心智：**普通配置 Parameter Store，敏感配置 Secrets Manager**——两者都有版本与审计，替代"Git+Vault"组合（全托管零运维）。

### 6.2 Google Secret Manager / CredHub

```yaml
spring:
  cloud:
    config:
      server:
        google-secret-manager:
          project-id: my-gcp-project
        credhub:
          url: https://credhub.example.com:8844
          # 认证：UAA 或 mTLS
```

> 💡 原则：**"云环境优先用云厂商的秘钥服务"**——避免自建 Vault 的运维成本；CredHub 仅 Cloud Foundry 部署用（国内市场几乎不用）。

## 7. 复合后端与自定义后端

### 7.1 复合后端（Composite，官方推荐组合方式）

```yaml
spring:
  cloud:
    config:
      server:
        composite:
          - type: git
            uri: https://github.com/you/config-repo
          - type: vault
            host: vault.example.com
            port: 8200
            scheme: https
            authentication: TOKEN
            token: ${VAULT_TOKEN}
```

```text
合并语义（默认 fail-fast=false）：
  ├── 顺序 = 配置数组顺序（先 git 后 vault → git 属性在前、vault 在后）
  ├── 默认只要有一个后端可用就继续（某后端挂了不影响其他）
  └── 客户端合并所有后端的 propertySources（后端的按数组顺序追加）
```

| 场景 | 组合 |
|------|------|
| 通用配置 + 秘钥分离 | **Git + Vault**（最常见） |
| 本地开发 + 生产 | native + git（按 profile 切换） |
| 多环境渐进迁移 | git + jdbc（存量配置迁移期） |

> ⚠️ 复合后端的坑：**同名属性多个后端都有时，顺序靠后的覆盖前面的**——秘钥类（Vault）放最后，避免被 Git 里的同名默认值覆盖。

### 7.2 自定义后端

```java
@Component
public class CustomEnvironmentRepository implements EnvironmentRepository {
    @Override
    public Environment findOne(String application, String profile, String label) {
        Environment env = new Environment(application, new String[]{profile}, label, null, null);
        // 自己造属性源（从任意来源读）
        env.add(new PropertySource("custom", Map.of("custom.key", "value")));
        return env;
    }
}
// 注册：配置 spring.cloud.config.server.environment.repository=com.example.CustomEnvironmentRepository
// 或直接 @Bean + 排除默认仓库
```

> 💡 自定义后端适用：**对接内部配置平台（自研配置中心/CMDB）、做配置迁移网关**——实现 `EnvironmentRepository` 接口即可，Server 其余能力（HTTP/加密/健康）全部复用。
