## 1. 模块组成

| 模块 | 类型 | 职责 | 引入方 |
|------|------|------|--------|
| **spring-cloud-config-server** | 核心库 | Config Server 本体：Git/后端读取、HTTP 暴露、加密解密、健康检查 | 服务端（配 @EnableConfigServer） |
| **spring-cloud-config-client** | 核心库 | Config Client 本体：Config Data 导入、拉取、refresh 端点 | 客户端（starter 内含） |
| **spring-cloud-starter-config** | starter | Server+Client 通吃：**服务端加依赖并 @EnableConfigServer；客户端加依赖即自动拉取** | 两侧都加（同一个坐标） |
| **spring-cloud-starter-bootstrap** | starter | 开启遗留 bootstrap 模式（Boot 2.4 前的加载方式） | 老项目迁移期 |
| spring-cloud-config-monitor | 辅助 | 监控仓库变更（Git 仓库 push 触发 Webhook） | 需 Webhook 自动刷新时 |
| spring-cloud-config-data | 内部 | Config Data 导入实现（spring.config.import 解析） | 传递依赖 |
| **spring-cloud-bus** | 配套 | 全网刷新广播（bus-refresh） | 需要全网刷新时单独引 bus starter |

> 💡 接入口诀：**服务端和客户端都加 `spring-cloud-starter-config`**——服务端补一个 `@EnableConfigServer` 注解，客户端什么都不用配（自动启用 Config Data 导入，前提是配置了 spring.config.import）。

## 2. 核心包结构

### 2.1 Server 端（spring-cloud-config-server）

```text
org.springframework.cloud.config.server
├── config.@EnableConfigServer        # 开关注解
├── environment                       # ★ 环境仓库抽象
│   ├── EnvironmentRepository        # 后端接口（Git/Jdbc/Redis/Vault... 各自实现）
│   ├── EnvironmentController        # ★ HTTP 端点：/{app}/{profile}/{label}
│   ├── git/                         # Git 后端（JGit：clone/fetch/工作目录）
│   ├── jdbc/ redis/ vault/ aws/     # 其他后端实现
│   └── CompositeEnvironmentRepository  # 复合后端（多后端按序合并）
├── encryption                        # ★ 加解密
│   ├── EncryptorEnvironmentRepository # 解密 {cipher} 值
│   ├── EnvironmentEncryptorController # /encrypt /decrypt 端点
│   └── TextEncryptorLocator          # 多密钥定位（每应用/每环境）
├── security                          # 认证（Basic Auth）
└── health                            # 健康检查
```

### 2.2 Client 端（spring-cloud-config-client / config-data）

```text
org.springframework.cloud.config.client
├── ConfigClientProperties           # spring.cloud.config.* 属性绑定
├── ConfigServerConfigDataLoader     # ★ Config Data 加载器（spring.config.import 触发）
├── ConfigServerConfigDataLocationResolver  # 解析 optional:configserver:
├── ConfigServicePropertySourceLocator      # 组装请求 URL、解析响应 propertySources
├── RetryProperties / RetryTemplateFactory  # 拉取失败重试
└── RefreshEndpoint                    # /actuator/refresh（配合 spring-cloud-commons）

org.springframework.cloud.config.data        # config-data 模块（import 解析底层）
```

> 🎯 关键认知：**客户端核心是 `ConfigServerConfigDataLoader`——它把 spring.config.import 解析成一次（或多次）对 Server 的 HTTP 请求**，返回的 propertySources 按顺序插入 Spring Environment 的属性源链——Config 的全部魔法就是"**启动时多请求一次 HTTP，把远程配置插进属性源链**"（[04 篇](04-客户端原理：配置加载与导入.md)）。

## 3. 依赖坐标与边界

### 3.1 官方坐标（Maven Central，5.0.4 实证）

```xml
<!-- 服务端 / 客户端通用 starter -->
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-config</artifactId>
</dependency>

<!-- 版本管理：Spring Cloud BOM（不写 version，由 BOM 锁） -->
<dependencyManagement>
    <dependency>
        <groupId>org.springframework.cloud</groupId>
        <artifactId>spring-cloud-dependencies</artifactId>
        <version>2025.1.2</version>       <!-- 与 Boot 4 对应的 Cloud 版本 -->
        <type>pom</type><scope>import</scope>
    </dependency>
</dependencyManagement>
```

### 3.2 依赖边界

| 边界 | 说明 |
|------|------|
| **Config 版本 ↔ Cloud release train** | 5.0.x↔2025.1.x（Boot 4）；4.3.x↔2025.0.x（Boot 3.5）——错配启动失败 |
| Server/Client 用同一坐标 | spring-cloud-starter-config 通吃，靠 @EnableConfigServer 区分 |
| 刷新需额外依赖 | /actuator/refresh 依赖 spring-boot-starter-actuator（端点暴露） |
| 全网刷新需 Bus | spring-cloud-starter-bus-amqp / bus-kafka（[05 篇](05-动态刷新与Bus集成速查.md)） |
| 加密需密钥配置 | encrypt.key / encrypt.keyStore.*（不配则 {cipher} 解密失败，[06 篇](06-加密解密与密钥管理速查.md)） |
| 无业务依赖 | 纯配置管理 |

> ⚠️ **最常见的坑**：Boot 3.5 项目手写 Config `5.0.x`（或 Boot 4 项目用 4.3.x）——启动直接失败（compatibility verifier）；**版本永远跟着 Spring Cloud BOM 走**。

## 4. 版本兼容矩阵（2026-08）

### 4.1 Config ↔ Spring Cloud ↔ Boot（权威组合）

| Spring Cloud | Config | Boot | JDK | 备注 |
|--------------|--------|------|-----|------|
| **2025.1.x（Oakwood）** | **5.0.x（5.0.4）** | **4.0.x/4.1.x** | 17+ | **当前主线**；Jackson 3、移除 deprecated |
| 2025.0.x（Northfields） | 4.3.x（4.3.4） | 3.5.x | 17 | OSS 已于 2026-06-30 EOL |
| 2024.0.x（Moorgate） | 4.2.x（4.2.4） | 3.4.x | 17 | EOL；**多 label（4.2.0 起）** |
| 2023.0.x（Leyton） | 4.1.x（4.1.7） | 3.2.x/3.3.x | 17 | EOL |
| 2022.0.x（Kilburn） | 4.0.x | 3.0.x/3.1.x | 8/11/17 | 老存量（Boot 3 首线，jakarta） |
| 2021.0.x（Jubilee） | 3.0.x | 2.6.x/2.7.x | 8/11 | 老存量（javax） |
| 2020.0.x（Ilford） | 2.2.x | 2.4.x/2.5.x | 8 | 老存量（javax） |
| Hoxton | 1.4.x | 2.2.x/2.3.x | 8 | 废弃（bootstrap 时代） |

> 💡 与 SCCB 的区别：**Config 没有跳过 4.x**（SCCB 3.3→5.0 跳版，Config 4.3→5.0 正常进位）——两个组件虽然同属 2025.1 列车且都升 5.0，但版本路径不同，别记混。

### 4.2 快速对齐口诀

| 场景 | 推荐组合 |
|------|---------|
| 新项目（Boot 4.0/4.1） | Spring Cloud 2025.1.x + Config 5.0.x + JDK 17 |
| 存量 Boot 3.5 | Config 4.3.x（**OSS 已 EOL，建议升级**） |
| 存量 Boot 3.4 | Config 4.2.x（EOL，建议升级） |
| 存量 Boot 2.7 | Config 3.0.x（**先升 Boot 全家桶**，别单点升） |

### 4.3 5.0 关键变化明细

| 变化 | 说明 | 影响 |
|------|------|------|
| Jackson 2 → 3 | JSON 处理库升级 | 自定义 ObjectMapper 的代码要核对 API |
| 移除全部 deprecated API | 大版本清理（issue #2908） | 升级前 grep `@Deprecated` 用法 |
| Boot 4 对齐 | Framework 7、jakarta | 整批升级 |
| 5.0.1 兼容修复 | 适配 Boot 4.0.1+（2025.1.1 发布） | 用 5.0.1+（5.0.4 最新） |
| 客户端属性稳定 | spring.config.import / spring.cloud.config.* | 迁移基本零改配置 |

## 5. 模块选型建议

| 场景 | 推荐 | 理由 |
|------|------|------|
| 微服务集中配置 | Config Server + Git 后端 | 默认方案，版本化管理 |
| 敏感配置 | + {cipher} 加密 | 密文入库，服务端解密（[06 篇](06-加密解密与密钥管理速查.md)） |
| 全网动态刷新 | + Bus（bus-amqp/bus-kafka） | 广播刷新事件（[05 篇](05-动态刷新与Bus集成速查.md)） |
| 密码/证书类配置 | Vault 后端（或复合 Git+Vault） | 专业秘钥管理（[03 篇](03-配置仓库后端全景.md)） |
| 已有 MySQL/Redis | JDBC/Redis 后端 | 复用基建（[03 篇](03-配置仓库后端全景.md)） |
| 老项目 bootstrap 模式 | spring-cloud-starter-bootstrap | 迁移期兼容（[04 篇](04-客户端原理：配置加载与导入.md)） |
| SCA 生态 | **Nacos 配置中心** | 内置长轮询推送，更省事（[08 篇](08-生产实践与选型避坑.md)） |
