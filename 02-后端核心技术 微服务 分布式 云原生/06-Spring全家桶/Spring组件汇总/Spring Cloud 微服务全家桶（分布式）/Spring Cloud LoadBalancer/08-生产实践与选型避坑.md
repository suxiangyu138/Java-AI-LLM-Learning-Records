## 1. 接入清单与配置基线

### 1.1 接入清单

| 调用类型 | 走 LB？ | 说明 |
|---------|:---:|------|
| Feign 服务调用 | ✅ 自动 | @FeignClient(name=) 隐式启用 |
| RestTemplate（@LoadBalanced） | ✅ | 显式标注 |
| WebClient（@LoadBalanced） | ✅ | 显式标注 |
| Gateway lb:// | ✅ 自动 | 网关内置 |
| @HttpExchange 客户端（5.0） | ✅ 自动 | HTTP Service Clients |
| 外部固定地址 API | ❌ | 无注册中心，直接 URL |
| 本地同进程调用 | ❌ | 不经过网络 |

### 1.2 生产配置基线

```yaml
spring:
  cloud:
    loadbalancer:
      cache:
        enabled: true          # ★ 缓存必开（默认）
        ttl: 35s               # 按业务调整（见 05 篇）
      configurations: health-check   # ★ 生产推荐：健康检查链
      health-check:
        interval: 10s
        path:
          default: /actuator/health
      eager-load:
        clients: payment-service,order-service   # 核心服务预加载
      retry:
        enabled: true          # 需要换实例重试时开（评估幂等）
```

## 2. 坑位表：10 大高频坑

| # | 坑 | 现象 | 解决 |
|---|-----|------|------|
| 1 | **@LoadBalanced 漏标** | RestTemplate 服务名调用报 UnknownHostException | 给 RestTemplate Bean 标注（[02 篇](02-快速开始与核心API速查.md)） |
| 2 | **缓存 TTL 导致打下线实例** | 下线实例仍收到请求（≤35s） | 接受（配重试/熔断）或 TTL 调小或 HealthCheck（[05 篇](05-缓存与健康检查.md)） |
| 3 | **关了缓存/TTL=0** | 注册中心压力暴增，注册中心抖动时调用全挂 | 缓存是可用性保险，保留合理 TTL |
| 4 | **configuration 类标了 @Configuration** | 自定义策略全局生效（污染所有服务） | 不标注解 + @LoadBalancerClient 绑定（[06 篇](06-重试与自定义扩展.md)） |
| 5 | **zone 没配** | zone-preference 策略不生效（全量候选） | Eureka 自动，Nacos 手动配 zone（[03 篇](03-负载均衡策略全解.md)） |
| 6 | **Ribbon 属性残留** | ribbon.* 静默失效（升级后） | 删除 ribbon 依赖与配置，迁移到 loadbalancer.*（[5 节](#5-ribbon-迁移路径)） |
| 7 | **写请求开 LB 重试** | 重复提交（换实例重试 = 重新执行） | 只读场景开重试；写场景靠幂等 |
| 8 | **HealthCheck 与 Caching 双包** | 双缓存 + 探测与列表不一致 | 二选一（官方明确）（[05 篇](05-缓存与健康检查.md)） |
| 9 | **原生镜像没配 eager-load** | 运行期找不到服务 LB 上下文 | eager-load.clients 显式列出（[06 篇](06-重试与自定义扩展.md)） |
| 10 | **api-version 载体不一致** | 版本匹配永远失败（客户端头 vs 服务端参数） | 载体统一 + 联调验证（[07 篇](07-API Versioning与HTTP Service Clients（5.0新特性）.md)） |

> 💡 排障口诀：**"实例在不在（注册中心）→ 缓存过没过（TTL）→ 策略滤没滤（supplier 链）"**——按序查，10 个坑解决 8 个。

## 3. 监控与调优

### 3.1 监控手段

| 手段 | 内容 |
|------|------|
| Micrometer Stats | `spring.cloud.loadbalancer.stats.micrometer.enabled: true` → `loadbalancer.requests.success/failed/discard` 指标 |
| LoadBalancerLifecycle | 自定义埋点（每次选择的实例/耗时/结果） |
| DEBUG 日志 | `logging.level.org.springframework.cloud.loadbalancer=DEBUG`（选择过程日志） |
| 注册中心监控 | 实例列表/健康状态（Nacos 控制台） |

### 3.2 调优决策表

| 症状 | 调整 |
|------|------|
| 故障感知慢 | TTL 调小 + HealthCheck 间隔调小 |
| 注册中心压力大 | TTL 调大 + 缓存容量调大 |
| 首调慢（冷启动） | eager-load 预加载核心服务 |
| 分发不均 | 权重策略（按容量）替代轮询 |
| 高并发瞬时失败 | LB 重试（只读）+ 熔断兜底 |
| 调用方打点缺失 | LoadBalancerLifecycle + Micrometer |

> 🎯 调优哲学：**LB 是"延迟 vs 成本"的旋钮系统**（缓存 TTL / 健康检查间隔 / 预加载）——按 SLA 选平衡点，压测验证后再固化配置。

## 4. vs Ribbon / vs Nacos：选型对比

### 4.1 vs Ribbon（历史替代）

| 维度 | LoadBalancer | Ribbon |
|------|-------------|--------|
| 维护 | ✅ 官方活跃 | 2018 停止 |
| 模型 | Supplier 链（组合） | Rule 继承（重） |
| 响应式 | ✅ | ❌ |
| 缓存 | ✅ 内置 Caffeine | ❌ |
| 健康检查 | ✅ 内置 | ⚠️ 弱 |
| 结论 | **官方唯一选择** | 必须迁移 |

### 4.2 vs Nacos 自带负载均衡（SCA 对照）

| 维度 | LoadBalancer | Nacos 自带 LB（SCA） |
|------|-------------|---------------------|
| 出身 | 官方 Cloud | 阿里 SCA |
| 权重 | metadata.weight（自定义） | ✅ **Nacos 控制台直接调权重** |
| 集群感知 | ❌（需自定义） | ✅ 同集群优先 |
| 服务分组 | ❌ | ✅（环境隔离） |
| 健康 | HTTP 探测（可配） | 心跳 + 控制台管理 |
| 灰度 | Hint/版本（代码级） | 权重/集群（控制台级） |
| 适用 | 官方 Cloud 生态 | SCA 生态 |

> 🎯 面试结论：**"LB 和 Nacos 自带负载均衡怎么选？"**——看生态：官方 Cloud 栈用 LoadBalancer（通用、可组合）；SCA 栈直接用 Nacos discovery 的权重/集群能力（**控制台调权重、集群优先是强项**）——**别双轨混用**（同一调用链只走一套选实例逻辑）。

## 5. Ribbon 迁移路径

### 5.1 迁移清单

```text
Ribbon → LoadBalancer 迁移（Boot 3+ 已强制，Boot 2.7 也建议）：
□ 1. 删除依赖：spring-cloud-starter-netflix-ribbon / ribbon-* 全部移除
□ 2. 删除配置：ribbon.* 属性（ribbon.eureka.enabled、ribbon.NFLoadBalancerRuleClassName...）
□ 3. 策略迁移对照：
     ribbon 轮询 → 默认（RoundRobin）
     ribbon 随机 → RandomLoadBalancer（自定义 Bean）
     ribbon 权重（ZoneAvoidance）→ Weighted + ZonePreference 组合
     ribbon 重试 → loadbalancer.retry.enabled
     ribbon 自定义 IRule → 自定义 ReactiveLoadBalancer
□ 4. 依赖检查：@RibbonClient / ILoadBalancer 引用全部替换
□ 5. 回归：轮询分布、故障感知、灰度规则
```

### 5.2 迁移注意

| 注意点 | 说明 |
|--------|------|
| 语义不完全等价 | Ribbon 的 ZoneAvoidanceRule ≈ Zone + Weighted 组合，非 1:1 |
| 属性名全换 | ribbon.* → spring.cloud.loadbalancer.*（无自动迁移工具） |
| 灰度规则重做 | Ribbon 自定义 rule → LoadBalancer 用 Hint/Weighted 内置方案 |

> 💡 迁移心法：**先跑默认（轮询）→ 再逐项迁移策略 → 最后验证灰度**——别一次全切（策略语义差异排查困难）。

## 6. 升级路径：4.3.x → 5.0.x

### 6.1 升级必要性

| 现状 | 判断 |
|------|------|
| 2025.0.x（Boot 3.5）+ LB 4.3.x | **建议升级**：Northfields OSS 已结束 |
| 2024.0.x（Boot 3.4）+ LB 4.2.x | **建议升级**：Moorgate EOL |
| 2023.0.x（Boot 3.2/3.3）+ LB 4.1.x | 计划升级 |
| Boot 2.7 + Ribbon | 先升 Boot 全家桶（大工程） |

### 6.2 升级 Checklist

```text
□ 1. 整批升级：Boot 3.5→4.x + Cloud 2025.0→2025.1
□ 2. 版本：LoadBalancer 随 commons 升 5.0.x（BOM 锁定，无单独坐标）
□ 3. 配置兼容：spring.cloud.loadbalancer.* 无破坏性变更（直接可用）
□ 4. 新特性可选：API Versioning（按需开启）、@HttpExchange 客户端集成
□ 5. 回归：轮询/权重/缓存/健康检查全链路
□ 6. 注意 JSpecify：自定义扩展类可能的编译期 null 警告
```

> 🎯 升级心法：**LB 5.0 是"能力加法"版本（API Versioning + 客户端集成）**——核心 API 与属性零破坏，升级 = 换 BOM 版本 + 回归；新特性按需启用即可。
