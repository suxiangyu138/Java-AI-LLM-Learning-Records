## 1. 模块组成与归属

| 模块 | 类型 | 职责 | 引入方 |
|------|------|------|--------|
| **spring-cloud-starter-loadbalancer** | starter | LoadBalancer 全部能力（含 Caching 与 Evictor 依赖） | 需要 LB 的服务（Feign/Gateway 内含） |
| **spring-cloud-commons** | 核心库 | **LoadBalancer 代码所在**（ReactiveLoadBalancer/Supplier/Client） | 传递依赖 |
| spring-cloud-loadbalancer（无独立包） | — | 没有独立模块——**代码在 commons 的 org.springframework.cloud.client.loadbalancer 包** | — |
| spring-cloud-starter-netflix-ribbon | 废弃 | Ribbon（4.x 已移除） | 迁移期（老项目） |
| 注册中心 starter | 配套 | 实例列表来源（nacos-discovery / eureka-client / consul） | 按选型 |
| spring-cloud-openfeign | 集成 | Feign + LB 自动集成 | Feign 项目 |
| spring-cloud-gateway | 集成 | 网关 lb:// 使用 LB | 网关项目 |

> 💡 接入口诀：**单独用加 `spring-cloud-starter-loadbalancer`**；Feign/Gateway 项目通常已传递引入——先检查依赖树，别重复加。

> ⚠️ **归属澄清**：LoadBalancer **没有独立的 GitHub 仓库与版本号**——它作为 spring-cloud-commons 的子模块发布，版本 = Commons 版本（5.0.2 等）；搜"spring-cloud-loadbalancer"独立版本号会查不到（[4 节](4-版本兼容矩阵2026-08) 矩阵以 Commons 版本为准）。

## 2. 核心包结构

```text
org.springframework.cloud.client.loadbalancer
├── ReactiveLoadBalancer              # ★ 核心接口：选择实例（策略抽象）
│   └── ReactorLoadBalancer<ServiceInstance>
│       ├── RoundRobinLoadBalancer    # 默认：轮询
│       └── RandomLoadBalancer        # 随机
├── ServiceInstanceListSupplier       # ★ 实例列表供应器（链式组合）
│   ├── DiscoveryClientServiceInstanceListSupplier     # 注册中心发现
│   ├── CachingServiceInstanceListSupplier             # Caffeine 缓存
│   ├── WeightedServiceInstanceListSupplier            # 权重
│   ├── ZonePreferenceServiceInstanceListSupplier      # 区域优先
│   ├── HealthCheckServiceInstanceListSupplier         # 健康探测
│   ├── HintBasedServiceInstanceListSupplier           # 提示（灰度）
│   ├── SubsetServiceInstanceListSupplier              # 子集
│   ├── SameInstancePreferenceServiceInstanceListSupplier   # 同实例偏好
│   ├── RequestBasedStickySessionServiceInstanceListSupplier # 粘性会话
│   ├── ReactiveApiVersionServiceInstanceListSupplier  # ★ API 版本（5.0）
│   └── BlockingApiVersionServiceInstanceListSupplier  # ★ API 版本（5.0）
├── LoadBalancerClientFactory         # 按服务名创建 LB 上下文
├── BlockingLoadBalancerClient        # 阻塞式客户端（RestTemplate/RestClient）
├── LoadBalancerRequestTransformer    # 请求变换（阻塞式）
├── LoadBalancerClientRequestTransformer # 请求变换（WebClient）
├── LoadBalancerLifecycle             # 生命周期回调（onStart/onComplete）
├── LoadBalancerProperties            # spring.cloud.loadbalancer.* 绑定
└── MicrometerStatsLoadBalancerLifecycle  # 指标统计

org.springframework.cloud.client.loadbalancer.reactive
├── ReactorLoadBalancerExchangeFilterFunction   # WebClient 集成
└── (响应式集成)
```

> 🎯 关键认知：**一切以 `ServiceInstanceListSupplier` 链为核心**——"拿列表 → 缓存 → 过滤 → 选择"每一步都是一个 supplier，用 builder 组合；策略差异化 = 组合不同的 supplier 链（[04 篇](04-核心原理：Supplier 链与响应式实现.md)）。

## 3. 依赖坐标与边界

### 3.1 官方坐标（Maven Central）

```xml
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-loadbalancer</artifactId>
</dependency>

<!-- 版本管理：Spring Cloud BOM（不写 version） -->
<dependencyManagement>
    <dependency>
        <groupId>org.springframework.cloud</groupId>
        <artifactId>spring-cloud-dependencies</artifactId>
        <version>2025.1.2</version>
        <type>pom</type><scope>import</scope>
    </dependency>
</dependencyManagement>
```

### 3.2 依赖边界

| 边界 | 说明 |
|------|------|
| **版本 = Commons 版本** | LoadBalancer 随 spring-cloud-commons 发布（5.0.2 ↔ 2025.1.x） |
| 注册中心必需 | 没注册中心时 LB 无实例可用（但可自定义 Supplier 提供静态列表） |
| Ribbon 冲突 | 4.x 起 Ribbon 移除；老项目迁移时删 ribbon 依赖（[08 篇](08-生产实践与选型避坑.md)） |
| Caffeine 可选 | 无 Caffeine 用内置 DefaultLoadBalancerCache（功能等同，性能略低） |
| 响应式可选 | WebClient 场景无需额外依赖（reactive 包在 commons 内） |

> ⚠️ **最常见的坑**：老项目升级后 Ribbon 属性（ribbon.*）静默失效 + LoadBalancer 用默认策略——升级必须检查 `ribbon.*` 配置迁移（[08 篇](08-生产实践与选型避坑.md) 迁移清单）。

## 4. 版本兼容矩阵（2026-08）

### 4.1 LoadBalancer（Commons）↔ Spring Cloud ↔ Boot（权威组合）

| Spring Cloud | Commons/LB | Boot | JDK | 备注 |
|--------------|-----------|------|-----|------|
| **2025.1.x（Oakwood）** | **5.0.x（5.0.2）** | **4.0.x/4.1.x** | 17+ | **当前主线**；API Versioning、HTTP Service Clients |
| 2025.0.x（Northfields） | 4.3.x（4.3.3） | 3.5.x | 17 | OSS 已于 2026-06-30 EOL |
| 2024.0.x（Moorgate） | 4.2.x（4.2.4） | 3.4.x | 17 | EOL |
| 2023.0.x（Leyton） | 4.1.x（4.1.6） | 3.2.x/3.3.x | 17 | EOL |
| 2022.0.x（Kilburn） | 4.0.x | 3.0.x/3.1.x | 8/11/17 | 老存量（Ribbon 移除） |
| 2021.0.x（Jubilee） | 3.1.x | 2.6.x/2.7.x | 8/11 | 老存量（Ribbon 共存） |
| 2020.0.x（Ilford） | 2.2.x | 2.4.x/2.5.x | 8 | 老存量 |
| Hoxton | 1.x（Netflix Ribbon 时代） | 2.2.x/2.3.x | 8 | 废弃 |

> 💡 **关键版本事实**：**Ribbon 在 Spring Cloud 2022.0（Kilburn）被彻底移除**——Boot 3.x 起 LoadBalancer 是唯一官方客户端 LB；老代码里 `ribbon.*` 属性、`IRule`、`@RibbonClient` 全部失效。

### 4.2 快速对齐口诀

| 场景 | 推荐组合 |
|------|---------|
| 新项目（Boot 4） | Spring Cloud 2025.1.x + LoadBalancer 5.0.x + JDK 17+ |
| 存量 Boot 3.5 | LoadBalancer 4.3.x（**OSS EOL，建议升级**） |
| 存量 Boot 2.7 + Ribbon | 升级 Boot 全家桶；Ribbon 配置迁移（[08 篇](08-生产实践与选型避坑.md)） |
| 网关项目 | Gateway starter 自带 LB，无需单独加 |

## 5. 5.0 新特性清单

| 新特性 | 说明 | 出处 |
|--------|------|------|
| **API Versioning 负载均衡** | `ReactiveApiVersionServiceInstanceListSupplier` / `BlockingApiVersionServiceInstanceListSupplier`：按实例 metadata 的 API 版本选择 | issue #1582 |
| **HTTP Service Clients 集成** | LoadBalancer 自动集成 Framework 7 声明式 HTTP 客户端（RestClient/WebClient @HttpExchange） | #1491/#1492 |
| JSpecify | 全公共 API null-safety 标注 | #1594 |
| callGetWithRequestOnDelegates | 4.1.0 引入，5.0 保留（默认 true）：supplier 带 Request 委托 | — |
| 属性稳定 | spring.cloud.loadbalancer.* 无破坏性变更 | — |

> 🎯 5.0 心智：**LoadBalancer 5.0 是"能力加法"版本**（API Versioning + 声明式客户端集成），核心 API 与属性零破坏——升级压力小，新特性收益直接（[07 篇](07-API Versioning与HTTP Service Clients（5.0新特性）.md)）。

## 6. 模块选型建议

| 场景 | 推荐 | 理由 |
|------|------|------|
| Feign/Gateway 项目 | 检查依赖树（通常已含） | 传递依赖，别重复加 |
| 独立 RestTemplate/WebClient | spring-cloud-starter-loadbalancer | 显式引入 |
| 需要权重/区域/灰度 | configurations 开关（无需额外依赖） | 内置策略（[03 篇](03-负载均衡策略全解.md)） |
| 需要健康探测 | health-check 配置 | 内置（[05 篇](05-缓存与健康检查.md)） |
| SCA 生态 | Nacos discovery + LB（或 Nacos 自带负载） | 权重/集群感知更强（[08 篇](08-生产实践与选型避坑.md)） |
