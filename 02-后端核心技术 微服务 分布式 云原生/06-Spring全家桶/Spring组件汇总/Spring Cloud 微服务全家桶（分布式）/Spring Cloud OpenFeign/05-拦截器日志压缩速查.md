## 1. RequestInterceptor：请求统一加工

### 1.1 用法

```java
// 方式一：配置类提供（按客户端生效）
@Configuration
public class FeignConfig {
    @Bean
    public RequestInterceptor traceIdInterceptor() {
        return template -> template.header("X-Trace-Id", MDC.get("traceId"));
    }
}

// 方式二：属性指定（按客户端）
spring:
  cloud:
    openfeign:
      client:
        config:
          payment-service:
            requestInterceptors:
              - com.example.TraceIdRequestInterceptor
            responseInterceptor: com.example.GlobalResponseInterceptor
```

### 1.2 典型拦截器场景

| 拦截器 | 做什么 |
|--------|--------|
| TraceId 透传 | 链路 ID 从 MDC → 请求头（下游日志关联） |
| Token 透传 | 认证 token 转发 |
| 用户上下文 | userId/tenantId 头 |
| 签名 | 请求签名（内部调用鉴权） |
| 客户端标识 | X-Caller-Service 头 |

```java
// 响应拦截器（5.x 支持）
@Component
public class GlobalResponseInterceptor implements ResponseInterceptor {
    @Override
    public Object intercept(Invocation invocation, Chain chain) throws Exception {
        return chain.next(invocation);   // 响应统一处理（记录/改写）
    }
}
```

> 🎯 面试必答：**"Feign 怎么透传 traceId？"**——**RequestInterceptor**：每个请求发前回调，从 MDC（日志上下文）取 traceId 放进请求头，下游同样从请求头取回 MDC——**一次注册，所有 Feign 调用自动带上**（[08 篇](08-生产实践与选型避坑.md) 也有）。

## 2. 日志：loggerLevel 四级

### 2.1 配置

```yaml
logging:
  level:
    com.example.PaymentClient: DEBUG        # ★ 接口日志类必须 DEBUG
spring:
  cloud:
    openfeign:
      client:
        config:
          payment-service:
            loggerLevel: full               # none | basic | headers | full
```

```java
// 或配置类
@Bean
Logger.Level feignLoggerLevel() { return Logger.Level.FULL; }
```

### 2.2 四级对比

| 级别 | 内容 | 用途 |
|------|------|------|
| NONE（默认） | 无 | 生产默认 |
| BASIC | 方法、URL、状态码、耗时 | 日常监控 |
| HEADERS | + 请求/响应头 | 头排查 |
| FULL | + 请求/响应体 | 调试（敏感数据注意！） |

> ⚠️ **两大坑**：① 只配 loggerLevel 不配 `logging.level.<接口>=DEBUG` → 日志不输出（两者缺一不可）；② FULL 级别**请求体/响应体会打日志**——生产别开，防敏感数据泄露。

## 3. 压缩：请求/响应

### 3.1 配置

```yaml
spring:
  cloud:
    openfeign:
      compression:
        request:
          enabled: true
          mime-types: text/xml,application/xml,application/json   # 压缩的 MIME 类型
          min-request-size: 2048                                   # 小于此大小不压缩
        response:
          enabled: true          # 响应压缩（需下游支持 gzip）
```

### 3.2 语义

```text
请求压缩：超过 min-request-size 且匹配 mime-types → 加压缩头并压缩请求体
响应压缩：加 Accept-Encoding: gzip 头 → 下游支持则返回压缩响应
适用：大 JSON 请求/响应（批量接口），带宽敏感场景
```

> 💡 取舍：压缩省带宽费 CPU（小请求别压，min-request-size 兜底）；内网高速场景通常不开（延迟优先）。

## 4. ErrorDecoder：异常响应解析

### 4.1 为什么需要

```text
默认行为：非 2xx 响应 → 抛 FeignException（原始状态码，无业务信息）
  └── 调用方拿到 FeignException 无法判断"404 业务不存在"还是"500 服务挂"

ErrorDecoder：把 HTTP 响应解码成业务异常
  └── 4xx → 业务异常（NotFound/ParamError）
  └── 5xx → 服务异常（可配熔断识别）
```

### 4.2 实现

```java
@Component
public class CustomErrorDecoder implements ErrorDecoder {
    @Override
    public Exception decode(String methodKey, Response response) {
        int status = response.status();
        if (status >= 400 && status < 500) {
            return new BusinessException("下游业务错误: " + status);
        }
        if (status == 404) {
            return new ResourceNotFoundException("资源不存在");
        }
        return new DownstreamException("下游服务异常: " + status);   // 5xx → 熔断统计
    }
}
// 注册：@Bean（自动装配）
```

### 4.3 与熔断的配合（重要）

```text
ErrorDecoder 抛什么异常 → 决定熔断怎么统计：
  ├── 抛"业务异常"（非熔断类）→ 不计入失败率（业务 404 正常）
  ├── 抛"服务异常"（IOException/5xx 类）→ 计入失败率 → 触发熔断
  └── 设计：4xx 抛业务异常、5xx 抛可重试/熔断异常
```

> 🎯 面试加分：**"怎么让 Feign 的 404 不触发熔断？"**——**ErrorDecoder**：把 404 解码成业务异常（如 ResourceNotFoundException）并配 `ignore-exceptions`（resilience4j）或使异常不入失败统计——**默认 FeignException 全算失败，业务 404 也会把熔断器打爆**（[08 篇](08-生产实践与选型避坑.md) 坑位表）。

## 5. 编码解码与 Spring Data 支持

### 5.1 默认编解码器

```text
自动装配的默认：
  ├── SpringEncoder（请求体序列化：Jackson）
  ├── ResponseEntityDecoder 包装 SpringDecoder（响应反序列化）
  ├── 支持：@RequestBody 对象、复杂泛型（List<Payment>）、文件（MultipartFile）
  └── 特性：Spring Data 支持（Jackson Databind + data-commons 在场时）
        → Page/Sort 自动转换（开箱即用）
        → 关闭：spring.cloud.openfeign.autoconfiguration.jackson.enabled=false
```

### 5.2 自定义编解码

```java
// 覆盖默认（配置类提供 Bean）
@Bean
public Encoder customEncoder() { return new GsonEncoder(); }      // 例：切 Gson
@Bean
public Decoder customDecoder() { return new GsonDecoder(); }
```

> 💡 默认 Jackson 足够 95% 场景；自定义仅用于特殊格式（XML/Proto/自定义协议）。

## 6. 可观测：Micrometer 集成

### 6.1 配置

```yaml
# 依赖：feign-micrometer（starter-openfeign 已含）+ ObservationRegistry（actuator）
spring:
  cloud:
    openfeign:
      micrometer:
        enabled: true          # ★ 开启 Feign 调用指标（默认 true）
```

### 6.2 观测能力

```text
Feign 自动接入 Micrometer Observation：
  ├── 指标：调用次数/耗时/失败率（feign 维度）
  ├── 追踪：与 Micrometer Tracing 集成（span 贯穿调用链）
  └── 排查：调用链路在 Zipkin/OTel 里可见
```

> 💡 生产观测组合：**Feign 指标（micrometer）+ 链路追踪（tracing）+ fallback 埋点（fallbackFactory）**——调用层三层可观测（[08 篇](08-生产实践与选型避坑.md) 监控）。
