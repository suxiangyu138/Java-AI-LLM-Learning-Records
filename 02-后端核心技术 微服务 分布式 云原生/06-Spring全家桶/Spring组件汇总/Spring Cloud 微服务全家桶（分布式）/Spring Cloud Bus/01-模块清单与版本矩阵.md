## 1. 模块组成

| 模块 | 类型 | 职责 | 引入方 |
|------|------|------|--------|
| **spring-cloud-bus** | 核心库 | 事件模型（RemoteApplicationEvent）、广播逻辑、端点定义 | 自动装配（starter 内含） |
| **spring-cloud-starter-bus-amqp** | starter | RabbitMQ binder + Bus 自动装配 | 用 RabbitMQ 的服务（推荐入门） |
| **spring-cloud-starter-bus-kafka** | starter | Kafka binder + Bus 自动装配 | 用 Kafka 的服务 |
| **spring-cloud-stream** | 底座 | 消息抽象（binder 概念，Bus 依赖它） | 传递依赖 |
| spring-cloud-config | 配套 | 配置源（Bus 刷新的数据来源） | 配置中心场景（可选） |

> 💡 接入口诀：**一个 starter 搞定**（bus-amqp 或 bus-kafka）；核心库与 Stream 是传递依赖，无需单独引。

## 2. 核心包结构

```text
org.springframework.cloud.bus
├── event                    # ★ 事件模型
│   ├── RemoteApplicationEvent        # 自定义事件基类（JSON 序列化）
│   ├── RefreshRemoteApplicationEvent # 配置刷新事件
│   ├── EnvironmentChangeRemoteApplicationEvent  # 环境属性更新事件
│   ├── AckRemoteApplicationEvent     # ack 确认事件（trace 用）
│   └── SentEvent / Destination 工具
├── endpoint                 # Actuator 端点
│   ├── RefreshBusEndpoint            # /actuator/bus-refresh
│   ├── EnvironmentBusEndpoint        # /actuator/bus-env
│   └── BusEndpoint 基类
├── BusAutoConfiguration     # 自动装配（Exchange/Queue 初始化）
├── BusBridge / BusConsumer  # Stream 桥接：发布/消费事件
└── trace                    # 事件跟踪（httptrace）
```

> 🎯 关键认知：**一切以 `RemoteApplicationEvent` 为载体的 JSON 消息**——发布方把它写进 Stream 的 input/output channel，消费方反序列化后按 destination 过滤执行——**Bus 的全部魔法就是"Spring 事件模型 + MQ 广播"两层拼接**（[03 篇](03-核心原理：事件与广播机制速查.md)）。

## 3. 依赖坐标与边界

### 3.1 官方坐标（Maven Central）

```xml
<!-- RabbitMQ 总线（Boot 3.x + Bus 4.x） -->
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-bus-amqp</artifactId>
</dependency>

<!-- Kafka 总线 -->
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-bus-kafka</artifactId>
</dependency>

<!-- 版本管理：Spring Cloud BOM（不写 version，由 BOM 锁） -->
<dependencyManagement>
    <dependency>
        <groupId>org.springframework.cloud</groupId>
        <artifactId>spring-cloud-dependencies</artifactId>
        <version>2024.0.x</version>     <!-- 与 Boot 3.x 对应的 Cloud 版本 -->
        <type>pom</type><scope>import</scope>
    </dependency>
</dependencyManagement>
```

### 3.2 依赖边界

| 边界 | 说明 |
|------|------|
| **Bus 大版本 ↔ Boot 大版本** | 4.x 只配 Boot 3.x（Jakarta）；3.x 只配 Boot 2.7（javax）——错配编译失败 |
| 版本由 Spring Cloud BOM 管理 | 不手写 version，用 cloud-dependencies BOM 对齐 |
| MQ 二选一 | bus-amqp 与 bus-kafka 互斥（同时引会双 binder 冲突） |
| 无业务依赖 | Bus 不引业务库（纯事件广播） |

> ⚠️ **最常见的坑**：Boot 2.7 项目手写 `spring-cloud-starter-bus-amqp 4.x`——启动直接 NoSuchMethodError/类不存在；**版本永远跟着 Spring Cloud BOM 走，别单独钉 Bus 版本**。

## 4. 版本兼容矩阵（2026-08）

### 4.1 Bus ↔ Spring Cloud ↔ Boot（权威组合）

| Spring Cloud | Bus | Boot | JDK | 备注 |
|--------------|-----|------|-----|------|
| **2025.x / 2024.x** | **4.x（4.1.x 主流）** | 3.5.x / 3.4.x | 17+ | 当前主线；Jakarta EE 9+ |
| 2023.x | 4.0.x | 3.2.x | 17 | Boot 3 首线 |
| 2022.x | 3.1.x | 2.7.x | 8/11/17 | Boot 2 末线（javax） |
| 2021.x | 3.0.x | 2.6.x | 8/11 | 老存量 |
| 2020.x | 2.2.x | 2.2-2.4 | 8 | 老存量 |
| Finchley-Greenwich | 1.x | 2.x 早期 | 8 | 废弃（/bus/refresh 端点） |

### 4.2 快速对齐口诀

| 场景 | 推荐组合 |
|------|---------|
| 新项目（Boot 3.5） | Spring Cloud 2025.x/2024.x + Bus 4.1.x + JDK 17 |
| 存量 Boot 3.2 | Spring Cloud 2023.x + Bus 4.0.x |
| 存量 Boot 2.7 | Spring Cloud 2022.x + Bus 3.1.x（**别升级 Boot 前升 Bus**） |
| Boot 2.6 老项目 | Spring Cloud 2021.x + Bus 3.0.x |

> ⚠️ **升级路径**：Boot 2.7 → 3.x 时 Bus 3.1 → 4.x 必须同步换——**涉及 javax → jakarta 包迁移**（spring.rabbitmq 属性不变，但代码里 javax.* import 要换）；建议整批升级而非 Bus 单点升级。

## 5. 消息代理选型（RabbitMQ vs Kafka）

| 维度 | RabbitMQ | Kafka |
|------|---------|-------|
| 场景 | 轻量消息、广播指令 | 高吞吐日志流、大数据管道 |
| Bus 接入 | `bus-amqp`（入门首选） | `bus-kafka` |
| 配置 | spring.rabbitmq.host/port | spring.cloud.stream.kafka.* |
| 可靠性 | Exchange/Queue 语义（手动 ack 可加固） | 分区 + offset（at-least-once 天然） |
| 运维成本 | 低（内存型） | 高（磁盘/分区/ZK 或 KRaft） |
| 若已有 MQ 基建 | 用已有的 | 用已有的 |

> 🎯 选型原则：**别为 Bus 单独引入新 MQ**——RabbitMQ 做配置刷新广播最合适（轻量 Topic 交换机）；已有 Kafka 就用 bus-kafka；**一条 MQ 走天下，Bus 只是它的一个 Topic**。

## 6. 模块选型建议

| 场景 | 推荐 | 理由 |
|------|------|------|
| Config + RabbitMQ 生态 | `spring-cloud-starter-bus-amqp` | 轻量、配置简单 |
| 已有 Kafka 基建 | `spring-cloud-starter-bus-kafka` | 复用集群 |
| 只需配置刷新 | Bus + Config（够了） | 别引多余模块 |
| 业务还要发消息 | MQ 直连（非 Bus） | Bus 只做广播指令（[05 篇](05-生产实践与选型避坑速查.md) 边界） |
| SCA 生态 | **不需要 Bus** | Nacos 内置推送（[05 篇](05-生产实践与选型避坑速查.md) 对比） |
