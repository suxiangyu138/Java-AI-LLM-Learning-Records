## 1. 模块组成

| 模块 | 类型 | 职责 | 引入方 |
|------|------|------|--------|
| **seata-server** | 独立发行包 | TC 协调器：全局/分支事务状态机、锁管理、会话存储、控制台 | 独立部署（1 台或集群） |
| **seata-all** | 客户端核心 | TM/RM 全量实现（协议、数据源代理、配置加载） | 参与事务的服务 |
| **seata-spring-boot-starter** | 客户端自动装配 | Boot 自动配置（数据源代理、GlobalTransactional 切面、XID 拦截器） | 参与事务的服务（Boot 3 用 2.x） |
| **spring-cloud-starter-alibaba-seata** | SCA 封装 | 在 seata-spring-boot-starter 之上提供 SCA 版本管理、WebFlux 支持 | SCA 微服务（推荐） |
| **seata-saga** | 客户端模块 | SAGA 状态机引擎 + 流程定义解析 | 使用 SAGA 模式的服务 |
| **seata-tm** | 客户端模块 | TM 实现（GlobalTransactional 切面） | 事务发起方（seata-all 已含） |
| **seata-rm-datasource** | 客户端模块 | AT/XA 数据源代理（DataSourceProxy/DataSourceProxyXA） | 使用 AT/XA 的服务 |
| **seata-console** | Server 附带 | 管理控制台（事务查询、2.6+ 集群信息、事务分组管理） | Server 集成 |

> 💡 接入选型一句话：**SCA 生态用 `spring-cloud-starter-alibaba-seata`（自动带对版本）；非 SCA（Dubbo/裸 Spring Boot）用 `io.seata:seata-spring-boot-starter`；原生不依赖 Boot 用 `seata-all`**。

## 2. 核心包结构

```text
io.seata
├── core                      # 协议与内核（client 与 server 共用）
│   ├── model                 # 全局事务/分支事务状态模型
│   ├── rpc                   # Netty 通信（client↔server RPC）
│   ├── context               # RootContext（XID 全局上下文）
│   └── exception             # 事务异常体系（GlobalTransactionException 等）
├── tm                        # 事务管理器（发起方侧）
│   ├── GlobalTransactionalInterceptor   # @GlobalTransactional AOP 拦截器
│   └── DefaultTransactionManager        # TM 实现（开/提交/回滚全局事务）
├── rm                        # 资源管理器（参与者侧）
│   ├── datasource            # AT 数据源代理：DataSourceProxy/ConnectionProxy
│   │   ├── undo              # undo_log 快照、反向 SQL 生成
│   │   ├── lock              # 全局锁获取/释放
│   │   └── sql               # SQL 解析（Druid parser）+ 前后镜像构建
│   ├── tcc                   # TCC 模式（@LocalTCC 解析、fence 表）
│   ├── saga                  # SAGA 状态机引擎
│   └── xa                    # XA 数据源代理（DataSourceProxyXA）
├── server                    # TC 协调器（seata-server 主体）
│   ├── session               # 会话存储（file/db/redis/raft 四种 store）
│   ├── lock                  # 锁管理器
│   └── console               # 控制台
└── spring / config           # Spring 集成 + 配置中心抽象（nacos/zk/etcd/file）
```

> 🎯 关键认知：**RM 侧最核心的类是 `DataSourceProxy`**——业务 SQL 全走它代理：解析 SQL → 查前后镜像 → 写 undo_log → 抢全局锁 → 提交本地事务。AT 模式"非侵入"的本质就是**数据源代理这一层**（[03 篇](03-核心原理：AT模式速查.md)）。

## 3. 依赖坐标与边界

### 3.1 官方坐标（Maven Central）

```xml
<!-- ① SCA 生态（推荐，版本由 SCA BOM 管理） -->
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-seata</artifactId>
</dependency>

<!-- ② 非 SCA（Dubbo/裸 Boot）：显式指定版本 -->
<dependency>
    <groupId>io.seata</groupId>
    <artifactId>seata-spring-boot-starter</artifactId>
    <version>2.6.0</version>
</dependency>

<!-- ③ 无 Spring 环境（纯 Java） -->
<dependency>
    <groupId>io.seata</groupId>
    <artifactId>seata-all</artifactId>
    <version>2.6.0</version>
</dependency>
```

### 3.2 依赖边界

| 边界 | 说明 |
|------|------|
| **Server 与 Client 版本必须一致** | 分支注册/二阶段协议是版本敏感的；2.5 client + 2.6 server 可能协议不兼容 |
| **Seata client 与 Boot 版本** | 2.x client 支持 Boot 2.x/3.x/4.x（2025.1.0.0 起 Boot 4）；1.x client 只支持 Boot 2.x |
| **AT 模式隐式依赖** | Druid/MySQL（仅 SQL 解析用，可换 parser）；每库必须建 undo_log 表 |
| **不传递业务依赖** | Seata 不引 OpenFeign/Nacos 业务库（XID 拦截器通过 SPI 适配各 RPC） |
| **TCC/SAGA 无表要求** | 无需 undo_log；TCC 可用 fence 表增强（[04 篇](04-TCC模式实战速查.md)） |

> ⚠️ **最常见的坑**：手写 `io.seata:seata-all` 与 SCA starter 同时引入，产生双数据源代理/双拦截器——**一个项目只允许一条 Seata 接入链**（要么 SCA starter，要么裸 seata starter）。

### 4.3 快速对齐口诀

| 场景 | 推荐组合 |
|------|---------|
| 新项目（Boot 4） | SCA 2025.1.0.0 + Seata 2.5.0（server 2.6.0）+ JDK 17+ |
| 新项目（Boot 3.5） | SCA 2025.0.0.0 + Seata 2.5.0（server 2.6.0）+ JDK 17+ |
| 存量 Boot 3.2 | SCA 2023.0.1.3 + Seata 2.1.0 + JDK 17 |
| 存量 Boot 2.6 | SCA 2021.0.5.0 + Seata 1.6.1 + JDK 8 |
| 非 SCA（Dubbo） | seata-spring-boot-starter 2.6.0 + 对应 Boot |

> ⚠️ **Server 独立升级原则**：client 跟着 SCA 版本走，**server 可以单独升到 2.6.0**（向后兼容 2.5 client 的常规链路）；但不要反着来（新 client + 老 server）。升级前查 [Seata 升级指南](https://seata.apache.org/zh-cn/docs/next/ops/upgrade/) 的 breaking change 清单（如 2.7 的 `tcc.contextJsonParserType` 弃用）。

## 5. 与 SCA 其他组件的依赖关系

| 组件 | 关系 | 说明 |
|------|------|------|
| Nacos | **强关联**（推荐） | Server 注册 + 配置中心；客户端事务分组通过 Nacos 拉 TC 列表（[08 篇](08-配置与注册中心集成速查.md)） |
| Sentinel | 无直接依赖 | 事务失败降级可结合 Sentinel 熔断（业务层搭配） |
| RocketMQ | 无直接依赖 | 事务消息与 Seata 是**二选一方案**（[06 篇](06-模式选型与对比.md)） |
| OpenFeign/LoadBalancer | 运行时协作 | Seata 通过 RPC 拦截器把 XID 注入请求头传递（[09 篇](09-集成地图与常见问题.md)） |
| Spring Boot | 必须 | starter 自动装配依赖 Boot 版本 |

## 6. 模块选型建议

| 场景 | 推荐接入方式 | 理由 |
|------|------------|------|
| SCA 微服务（Boot 3/4） | `spring-cloud-starter-alibaba-seata` | 版本由 SCA BOM 锁定，自动注入 XID 拦截器 |
| 非 SCA 但用 Boot | `io.seata:seata-spring-boot-starter` | 同自动装配能力，版本自管 |
| 纯 Java/非 Spring | `io.seata:seata-all` | 需手工初始化 TM/RM |
| 只想用 SAGA | `seata-all` + `seata-saga`（或 starter） | 状态机引擎独立模块 |
| 生产集群 | server 独立集群（db/raft 模式） | Server 永远单独部署，不嵌入业务 |
