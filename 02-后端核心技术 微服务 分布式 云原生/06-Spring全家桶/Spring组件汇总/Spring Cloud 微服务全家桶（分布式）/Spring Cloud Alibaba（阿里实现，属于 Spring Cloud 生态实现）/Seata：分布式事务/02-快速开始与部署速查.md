## 1. Server 部署总览

Seata Server 即 **TC 协调器**，独立进程（不嵌入业务），负责：全局/分支事务状态机推进、全局锁管理、会话持久化、控制台查询。

| 部署方式 | 场景 | 命令/入口 |
|---------|------|----------|
| 发行包直接部署 | 生产首选 | 解压 → 改 `conf/application.yml` → `bin/seata-server.sh`（Linux）/ `seata-server.bat`（Windows） |
| Docker | 开发/测试 | `docker run seataio/seata-server:2.6.0` |
| Docker-Compose | 联调环境 | compose 编排 server + nacos + mysql |
| Kubernetes/Helm | 云原生生产 | Helm chart 部署 Raft 集群 |

> ⚠️ **部署顺序铁律**：**先启动注册中心（Nacos）→ 再启动 Seata Server → 确认 Server 注册成功 → 最后启动业务服务**。顺序反了客户端会拿到空 TC 列表。

## 2. 存储模式选型（file/db/redis/raft）

Server 的会话（全局/分支事务 + 锁）存哪里？四种模式决定了集群能力与性能：

| 模式 | 集群 | 存储介质 | 性能 | 适用 | 说明 |
|------|:---:|---------|------|------|------|
| **file**（默认） | ❌ | 本地文件 | 高 | 单机开发/演示 | 多节点会报错（无文件同步） |
| **db** | ✅ | MySQL/Oracle/PG 等 | 中 | 已有 DB 基础设施的生产 | 需建 4 张表；MySQL 建议 `rewriteBatchedStatements=true` |
| **redis** | ✅ | Redis 单机/哨兵 | 高 | 高性能生产 | 免建表；pipeline 批量写 |
| **raft**（2.2+） | ✅ | Raft 日志文件 | 高 | 原生高可用生产 | 3+ 节点；**无需注册中心/DB**；扩缩容走 openapi |

### 2.1 db 模式建表（4 张）

```sql
-- 脚本官方路径：seata/script/server/db/mysql.sql
CREATE TABLE `global_table` (
  `xid` varchar(128) NOT NULL,               -- 全局事务 ID
  `transaction_id` bigint,                   -- 事务 ID
  `status` tinyint NOT NULL,                 -- 状态（Begin/Committing/…）
  `application_id` varchar(32),
  `transaction_service_group` varchar(32),
  `transaction_name` varchar(128),
  `timeout` int,                             -- 全局事务超时（ms）
  `begin_time` bigint,
  `application_data` varchar(2000),
  `gmt_create` datetime, `gmt_modified` datetime,
  PRIMARY KEY (`xid`), KEY `idx_gmt_modified_status` (`gmt_modified`,`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8;

CREATE TABLE `branch_table` (
  `branch_id` bigint NOT NULL,               -- 分支事务 ID
  `xid` varchar(128) NOT NULL,
  `transaction_id` bigint,
  `resource_group_id` varchar(32),
  `resource_id` varchar(256),                -- 库连接标识
  `branch_type` varchar(8),                  -- AT/TCC/SAGA/XA
  `status` tinyint,
  `client_id` varchar(64),
  `application_data` varchar(2000),
  `gmt_create` datetime, `gmt_modified` datetime,
  PRIMARY KEY (`branch_id`), KEY `idx_xid` (`xid`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8;

CREATE TABLE `lock_table` (
  `row_key` varchar(128) NOT NULL,           -- 资源:表:主键
  `xid` varchar(128),                        -- 持锁全局事务
  `transaction_id` bigint,
  `branch_id` bigint,
  `resource_id` varchar(256),
  `table_name` varchar(32),
  `pk` varchar(36),
  `status` tinyint DEFAULT 0,                -- 0 未锁 / 1 已锁
  `gmt_create` datetime, `gmt_modified` datetime,
  PRIMARY KEY (`row_key`), KEY `idx_status` (`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8;

CREATE TABLE `distributed_lock` (            -- 1.5.1+：集群互斥（仅一个 Server 执行提交/回滚）
  `lock_key` varchar(20) NOT NULL,
  `lock_value` varchar(20) NOT NULL,
  `expire` bigint DEFAULT 0,
  PRIMARY KEY (`lock_key`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8;
```

### 2.2 存储模式配置（server `conf/application.yml`）

```yaml
store:
  mode: db                  # file | db | redis | raft
  db:
    datasource: druid       # dbcp/druid/hikari
    db-type: mysql
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://127.0.0.1:3306/seata?rewriteBatchedStatements=true   # ★ 批量写提速 10 倍
    user: root
    password: root
    min-conn: 5
    max-conn: 100
    global-table: global_table
    branch-table: branch_table
    lock-table: lock_table
    distributed-lock-table: distributed_lock
    query-limit: 100
```

```yaml
# redis 模式（高性能免建表）
store:
  mode: redis
  redis:
    mode: single            # single | sentinel
    single:
      host: 127.0.0.1
      port: 6379
    password: ""            # 无则留空
    database: 0
    max-conn: 10
    min-conn: 1
    query-limit: 100
    type: pipeline          # lua | pipeline（默认 pipeline，批量性能优）
```

> 🎯 选型一句话：**开发用 file；有 DB 基建且要集群用 db；要高性能免建表用 redis；新生产环境直接 raft**（3 节点，去掉注册中心依赖）。

## 3. 启动参数与端口清单

### 3.1 启动参数

| 参数 | 默认 | 说明 |
|------|------|------|
| `-h / --host` | 本机 IP | 注册到注册中心的 IP（集群每节点配自身 IP） |
| `-p / --port` | 8091 | 通信端口（Netty） |
| `-m / --storeMode` | file | file/db/redis（raft 需在配置文件里配 `store.mode: raft`） |
| `-n / --serverNode` | 1 | Server 节点 ID（集群区分） |
| `-e / --seataEnv` | 空 | 运行环境标识 |

```bash
# 单机 file 模式
bin/seata-server.sh -h 192.168.0.1 -p 8091 -m file

# 生产 db 模式
bin/seata-server.sh -h 192.168.0.1 -p 8091 -m db
```

### 3.2 端口清单

| 端口 | 用途 |
|------|------|
| 8091 | Netty 通信端口（client 连这里） |
| 9091（默认 +1000） | Raft 通信端口（`-Dserver.raftPort=9092` 可改） |
| 7091 | 控制台/HTTP（2.x 起与 Netty 分离） |

> ⚠️ **集群注意**：多节点同机部署时 Netty 端口必须不同（如 7091~7094），**Raft 端口 = Netty 端口 + 1000** 自动偏移，避免冲突。

## 4. Docker 与 K8s 部署

### 4.1 Docker（开发/测试最快路径）

```bash
# file 模式单机（什么都不用配）
docker run -d --name seata-server -p 8091:8091 -p 7091:7091 seataio/seata-server:2.6.0

# 挂载配置（db/raft 模式改完配置再起）
docker run -d --name seata-server \
  -p 8091:8091 -p 7091:7091 \
  -v /data/seata/conf:/seata-server/conf \
  -e STORE_MODE=db \
  -e DB_HOST=mysql-host -e DB_PORT=3306 -e DB_DATABASE=seata \
  seataio/seata-server:2.6.0
```

### 4.2 K8s（Raft 集群，云原生）

```yaml
# 3 节点 StatefulSet + 固定存储卷（raftlog 必须持久化）
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: seata-server
spec:
  serviceName: seata-server
  replicas: 3
  template:
    spec:
      containers:
      - name: seata-server
        image: seataio/seata-server:2.6.0
        env:
        - name: SERVER_ADDR
          value: "seata-server-0:9091,seata-server-1:9091,seata-server-2:9091"
        volumeMounts:
        - name: raft-store
          mountPath: /root/sessionStore
  volumeClaimTemplates:
  - metadata: { name: raft-store }
    spec:
      accessModes: ["ReadWriteOnce"]
      resources: { requests: { storage: 10Gi } }
```

> ⚠️ **Raft 关键约束**：扩缩容**必须通过 Server openapi**（`/metadata/v1/changeCluster?raftClusterStr=new_cluster_list`），直接改配置重启不生效。

## 5. 客户端接入 5 步

### 5.1 五步清单

```text
① 引入依赖（spring-cloud-starter-alibaba-seata）
② 配置 seata（enabled + tx-service-group + 映射）
③ 每库建 undo_log 表（AT 模式必须）
④ 数据源代理确认（starter 自动，Hikari 也兼容）
⑤ 业务方法加 @GlobalTransactional
```

### 5.2 客户端配置（application.yml）

```yaml
seata:
  enabled: true                              # ★ 必须显式 true，否则切面不生效
  tx-service-group: my_test_tx_group         # ★ 事务分组名（三端一致）
  enable-auto-data-source-proxy: true        # 自动代理数据源（默认 true）
  service:
    vgroup-mapping.my_test_tx_group: default # 事务分组 → TC 集群名
    grouplist.default: "127.0.0.1:8091"      # file 注册方式下的 TC 地址
  registry:                                  # 用 Nacos 时改这里（见 08 篇）
    type: nacos
```

> ⚠️ **三端一致检查项**（90% 接不上的原因）：
> 1. `tx-service-group` 与 Server 侧 `vgroupMapping` 一致
> 2. 用 Nacos 时 namespace/group 与 Server 注册一致
> 3. `seata.enabled: true` 显式配置

### 5.3 undo_log 建表（AT 模式，每库必建）

```sql
CREATE TABLE `undo_log` (
  `id` bigint(20) NOT NULL AUTO_INCREMENT,
  `branch_id` bigint(20) NOT NULL,           -- 分支事务 ID
  `xid` varchar(100) NOT NULL,               -- 全局事务 ID
  `context` varchar(128) NOT NULL,
  `rollback_info` longblob NOT NULL,         -- 前/后镜像快照（回滚依据）
  `log_status` int(11) NOT NULL,             -- 0 正常 / 1 已回滚
  `log_created` datetime NOT NULL,
  `log_modified` datetime NOT NULL,
  `ext` varchar(100) DEFAULT NULL,
  PRIMARY KEY (`id`),
  UNIQUE KEY `ux_undo_log` (`xid`,`branch_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8;
```

> 💡 建表脚本官方路径：`seata/script/client/at/db/mysql.sql`（各数据库方言都有）。

### 5.4 数据源代理说明

| 情况 | 说明 |
|------|------|
| Boot 3.x/4.x + starter | **自动代理**（`seata.enable-auto-data-source-proxy: true`），无需手动写 `@EnableAutoDataSourceProxy` |
| 多数据源/动态数据源 | 需手动 `@EnableAutoDataSourceProxy` 或自定义 `DataSource` 装配（[09 篇](09-集成地图与常见问题.md)） |
| 与 ShardingSphere 同用 | 需特殊配置（代理顺序：Seata 代理在 ShardingSphere 外层） |

## 6. 级联回滚验证

```java
// 订单服务（发起方）
@GlobalTransactional(rollbackFor = Exception.class)
public void createOrder(OrderDTO dto) {
    orderMapper.insert(dto);                 // ① 本地提交（写 undo_log + 注册分支）
    stockService.deduct(dto.getSkuId(), 1);  // ② 跨服务调用（XID 传递）
    accountService.pay(dto.getUserId(), 100);// ③ 让这里抛异常
    throw new RuntimeException("模拟支付失败");
}
```

| 验证点 | 预期 | 检查方式 |
|--------|------|---------|
| Server 启动 | 日志 `Server started ...` | 8091 监听 |
| 客户端接入 | 分支注册日志 | Server 日志/控制台 global/branch 事务 |
| XID 传递 | 下游日志有 xid | 打印 `RootContext.getXID()` |
| **级联回滚** | **订单表 + 库存表 + 账户表全部还原** | 查库（重点：订单插入被回滚 = 全局事务生效） |
| undo_log 清理 | 提交后 undo_log 被异步删除；回滚后 log_status=1 | `SELECT * FROM undo_log` |

> 🎯 **及格标准一句话**：**"下游失败 → 上游已插入的数据消失"**——只要订单表数据没了，就是全局事务真正生效（如果订单还在，走 [09 篇](09-集成地图与常见问题.md) 排错表）。

## 7. 常见部署问题

| 现象 | 原因 | 处理 |
|------|------|------|
| Server 起不来：端口占用 | 8091 被占 | `-p` 换端口；同机多节点注意 Netty/Raft 端口偏移 |
| file 模式多节点报错 | file 不支持集群 | 换 db/redis/raft |
| 客户端连不上 TC | 事务分组映射错误/Server 未注册 | 先查注册中心 Server 实例；再查 `vgroupMapping` |
| 回滚报连接获取超时 | 连接池太小（回滚需新连接） | 调大 `spring.datasource.hikari.maximum-pool-size` |
| 控制台打不开 | 2.x 控制台在 7091 | 访问 `http://ip:7091`（不是 8091） |
| Raft 集群一直无主 | 节点数 < 3 / raftPort 冲突 | 至少 3 节点；同机改 `-Dserver.raftPort` |
