## 1. 配置体系总览

```text
两层配置：
    Server 侧：conf/application.yml（存储模式、注册中心、端口）
    Client 侧：application.yml（enabled、事务分组、注册/配置中心）
        └─ 生产推荐：把 client 配置外置到 Nacos 配置中心（改配置不重启）
```

| 层 | 文件 | 核心内容 |
|----|------|---------|
| Server | `conf/application.yml`（2.x 统一） | store（file/db/redis/raft）、registry、config、server |
| Client | 业务服务 `application.yml` | seata.enabled、tx-service-group、service、registry、config |
| 1.x 遗留 | `file.conf` + `registry.conf` | 2.x 已合并进 application.yml（迁移见 [07 篇](07-高可用与生产实践速查.md)） |

## 2. Server 配置（application.yml）

```yaml
server:
  port: 7091                      # 控制台/HTTP 端口
  servlet:
    context-path: /               # 控制台访问路径

seata:
  config:                         # 配置中心（Server 自身配置可外置）
    type: nacos
    nacos:
      server-addr: nacos-host:8848
      namespace: ""
      group: SEATA_GROUP
      username: nacos
      password: nacos
  registry:                       # 注册中心（客户端发现 TC 靠这个）
    type: nacos
    nacos:
      application: seata-server
      server-addr: nacos-host:8848
      group: SEATA_GROUP
      namespace: ""
      cluster: default            # ★ TC 集群名（客户端 vgroupMapping 指向它）
      username: nacos
      password: nacos
  store:
    mode: db                      # file/db/redis/raft（详见 02/07 篇）
  raft:                           # raft 模式专用
    group: default
    server-addr: 127.0.0.1:9091,127.0.0.2:9091,127.0.0.3:9091
```

> ⚠️ **namespace 一致性**：Server 注册的 namespace/group 必须与客户端配置的**完全一致**——这是"客户端拿到空实例列表"的头号原因（常见：Server 配了 namespace 而客户端没配）。

## 3. 客户端配置全表

```yaml
seata:
  enabled: true                        # ★ 是否启用（false = 全部降级为本地事务）
  application-id: order-service        # 应用名（默认取 spring.application.name）
  tx-service-group: my_test_tx_group   # ★ 事务分组名
  enable-auto-data-source-proxy: true  # 自动代理数据源（AT/XA 必需）
  data-source-proxy-mode: AT           # AT | XA（分支默认类型）
  use-jdk-proxy: false                 # CGLIB（默认）| JDK 代理
  registry:
    type: nacos                        # nacos/eureka/consul/zk/redis/etcd3/file
    nacos:
      application: seata-server
      server-addr: localhost:8848
      group: SEATA_GROUP
      namespace: ""
      cluster: default
  config:
    type: nacos                        # 配置中心（vgroupMapping 等从这里读）
    nacos:
      server-addr: localhost:8848
      group: SEATA_GROUP
      namespace: ""
  service:
    vgroup-mapping.my_test_tx_group: default   # 事务组 → TC 集群名
    grouplist.default: "127.0.0.1:8091"        # 仅 registry.type=file 时生效
  client:
    tm:
      degrade-check: false             # 开启后 TC 不可用降级本地事务
      default-global-transaction-timeout: 60000
    rm:
      lock:
        retry-interval: 10             # 全局锁重试间隔 ms
        retry-times: 30                # 重试次数
      report-success-enable: false
  tcc:
    fence:
      enable: true                     # TCC-FENCE 防悬挂（默认开）
      log-table-name: tcc_fence_log
```

| 配置项 | 默认 | 作用 |
|--------|------|------|
| `seata.enabled` | true | 总开关（false 全降级本地事务） |
| `tx-service-group` | 空 | **必须配置**：事务分组名（三端一致） |
| `vgroupMapping.<组>` | — | 事务组 → TC 集群名映射 |
| `grouplist.<集群>` | — | file 注册方式直连地址（不用注册中心时） |
| `registry.type` | file | 注册中心类型（生产必换 nacos 等） |
| `config.type` | file | 配置中心类型（生产必换 nacos） |
| `data-source-proxy-mode` | AT | 分支类型（XA 模式改 XA） |
| `tm.degrade-check` | false | TC 不可用时降级为本地事务（兜底开关） |
| `rm.lock.retry-times` | 30 | 全局锁冲突重试次数 |
| `tcc.fence.enable` | true | TCC-FENCE 防悬挂/空回滚 |

## 4. 注册中心集成（Nacos 为主）

### 4.1 客户端完整 Nacos 配置（生产推荐形态）

```yaml
seata:
  enabled: true
  tx-service-group: my_test_tx_group
  registry:
    type: nacos
    nacos:
      application: seata-server        # 与 Server 注册的 application 一致
      server-addr: ${NACOS_ADDR:localhost:8848}
      group: SEATA_GROUP
      namespace: ${NACOS_NS:}
      cluster: default                 # 与 Server 的 cluster 一致
      username: nacos
      password: nacos
  config:
    type: nacos
    nacos:
      server-addr: ${NACOS_ADDR:localhost:8848}
      group: SEATA_GROUP
      namespace: ${NACOS_NS:}
```

```text
Nacos 控制台应看到：
    seata-server（服务列表，含 1~N 个 TC 实例，metadata 含 cluster）
```

> 💡 **验证口诀**：控制台服务列表有 seata-server → 客户端日志出现 `successful loading vgroup configuration` 与 TC 连接 → 事务才可用。

## 5. 配置中心集成

把 client 的 vgroupMapping 等配置放 Nacos 配置中心（dataId 规则）：

| dataId | group | 内容 |
|--------|-------|------|
| `service.vgroupMapping.my_test_tx_group` | SEATA_GROUP | 值：default（组 → 集群名） |
| `client.tm.degradeCheck` | SEATA_GROUP | true/false |
| `store.mode` 等 Server 配置 | SEATA_GROUP | Server 外置配置（可选） |

> ⚠️ **配置中心 vs 注册中心的分工**：**配置中心**管"事务分组→集群名"这类**静态映射**；**注册中心**管"集群名→实例列表"这类**动态地址**——两者都要配，缺一不可（很多"连不上"是只配了注册中心）。

## 6. 事务分组解析链路

```text
一次全局事务的地址解析（完整链路）：
    ① 业务代码 @GlobalTransactional
    ② client 读 tx-service-group = my_test_tx_group
    ③ 配置中心查 service.vgroupMapping.my_test_tx_group → default
    ④ 注册中心按 cluster=default 拉 TC 实例（Nacos 服务列表过滤）
    ⑤ 选一台 TC 建 Netty 连接（8091）
    ⑥ 注册全局事务，拿到 XID → 后续分支都走这台 TC
```

| 断点 | 症状 | 检查 |
|------|------|------|
| ③ 映射缺失 | 日志 `no available service` 之前 vgroup 加载失败 | 配置中心有 mapping 配置吗 |
| ④ 实例为空 | `Failed to get available servers` | 控制台有 seata-server 吗；namespace/group/cluster 一致吗 |
| ⑤ 连接失败 | 连接超时 | 8091 通吗；防火墙；同机多节点端口冲突 |

## 7. 其他注册中心对照

| 注册中心 | 配置 type | 说明 |
|---------|----------|------|
| Nacos | `nacos` | **推荐**：注册 + 配置一体，SCA 标配 |
| Eureka | `eureka` | 老 Spring Cloud 存量 |
| Consul | `consul` | HashiCorp 系 |
| ZooKeeper | `zk` | 传统强一致 |
| Redis | `redis` | 注册信息存 Redis（轻量） |
| etcd3 | `etcd3` | k8s 生态 |
| file | `file` | 仅单机/测试（无健康检查，不推荐生产） |

> 🎯 生产建议：**一律 Nacos**（与 SCA 生态一致、配置中心同源）；file 模式只用于本地快速验证——无健康检查，TC 挂了客户端感知不到（[07 篇](07-高可用与生产实践速查.md) 高可用前提）。

## 8. 高频配置故障

| 现象 | 原因 | 处理 |
|------|------|------|
| `no available service` | vgroupMapping 缺失/集群名不匹配 | 核对 mapping 配置 + cluster 一致 |
| 服务列表有但连不上 | namespace/group 不一致 | 三端（Server/客户端/配置）namespace 对齐 |
| 事务不生效（无分支） | `seata.enabled` 未显式 true / 版本错配 | 显式 true；查 [01 篇](01-模块清单.md) 版本矩阵 |
| 用 file grouplist 但走集群 | registry.type 混用 | file 与注册中心二选一 |
| 配置改了不生效 | 未外置配置中心 / 缓存 | Nacos 配置中心 + 重启（vgroupMapping 不支持热刷新） |
| XA 模式连不上 | `data-source-proxy-mode` 未设 XA | 显式 `seata.data-source-proxy-mode: XA` |
