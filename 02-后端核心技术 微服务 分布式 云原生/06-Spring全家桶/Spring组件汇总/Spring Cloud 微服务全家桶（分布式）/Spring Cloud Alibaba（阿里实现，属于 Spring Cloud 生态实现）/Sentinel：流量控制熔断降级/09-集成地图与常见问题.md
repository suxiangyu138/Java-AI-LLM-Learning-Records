## 1. SCA 全家桶联动地图

```text
SCA 四件套协作（下单场景）：

    Gateway（Sentinel 网关限流：第一道闸门）
        │
        ▼
    订单服务（TM）──Sentinel 接口限流/熔断──► 库存服务（RM-AT）
        │                                          │
        ├── Nacos：注册 + 配置 + Sentinel 规则持久化
        ├── Seata TC：分布式事务协调（下单跨库一致）
        ├── Sentinel：接口防护 + Feign 调用熔断兜底
        └── RocketMQ：下单后异步消息（削峰解耦）
```

| 组件 | 在本体系中的角色 | 与 Sentinel 的关系 |
|------|----------------|-------------------|
| Nacos | 注册/配置中心 | **规则持久化数据源**（[06 篇](06-规则持久化与动态数据源速查.md)） |
| Seata | 分布式事务 | 事务接口同样可加 Sentinel 限流（并行治理，互不依赖） |
| Gateway | 网关 | Sentinel 网关适配器（第一道闸门） |
| RocketMQ | 消息解耦 | 消费端可加 Sentinel 消费限流（生态适配器） |
| OpenFeign | 服务调用 | feign.sentinel.enabled 熔断降级（[08 篇](08-与SpringCloudAlibaba集成速查.md)） |

> 🎯 联动要点：**Sentinel 管"流量与故障"，Seata 管"跨库一致"，Nacos 管"注册与配置"**——三者互不替代，组合成 SCA 的完整治理面。

## 2. 防护体系分层设计

```text
生产推荐的分层防护（从上到下）：
    L1 网关层：Gateway 限流（QPS/API 分组）── 挡住大部分突刺
    L2 接口层：FlowRule（QPS/线程）+ ParamFlowRule（热点）── 业务接口精细限流
    L3 调用层：Feign fallback + DegradeRule ── 下游故障快速失败
    L4 全局层：SystemRule（CPU/入口 QPS）── 系统濒危兜底
    L5 来源层：AuthorityRule 黑白名单 ── 来源控制
    ── 每层都配兜底：blockHandler / fallback / Feign fallback，层层有退路
```

| 设计原则 | 说明 |
|---------|------|
| 规则先行 | 上线前压测确定阈值（容量评估），别上线后临时拍 |
| 兜底齐全 | 每层防护都必须有降级兜底（无兜底 = 把 500 甩给用户） |
| 告警配套 | 熔断/限流触发要有监控告警（触发 = 事故信号，不是没事） |
| 规则入 Nacos | 全部规则持久化（[06 篇](06-规则持久化与动态数据源速查.md)），可审计可回滚 |

## 3. Hystrix → Sentinel 迁移清单

| 迁移项 | Hystrix | Sentinel | 动作 |
|--------|---------|----------|------|
| 依赖 | hystrix + feign-hystrix | `spring-cloud-starter-alibaba-sentinel` | 换依赖 |
| 熔断配置 | `hystrix.command.default` | DegradeRule（RT/比例/数） | 规则改控制台/Nacos |
| 降级 | `@HystrixCommand(fallbackMethod=...)` | `@SentinelResource(blockHandler/fallback)` | 注解替换 |
| Feign 兜底 | feign-hystrix 自动 | `feign.sentinel.enabled` + FallbackFactory | 开启 + 实现兜底 |
| 线程池隔离 | 线程池（默认 10） | 并发线程数限流（信号量级） | 概念替换（性能更好） |
| 规则管理 | 配置文件静态 | 控制台/Nacos 动态 | 规则外置 |
| 监控 | Hystrix Dashboard | Sentinel Dashboard | 控制台切换 |

> 💡 迁移收益：**动态规则（不用发版调阈值）+ 无线程池开销 + 限流能力（Hystrix 没有）+ 活跃维护**；迁移时先灰度一两个服务验证兜底链路再全量。

## 4. 高频坑排错表

| # | 现象 | 根因 | 处理 |
|---|------|------|------|
| 1 | 规则加了不生效 | 资源名不匹配 | 规则资源名 = 注解 value 完全一致 |
| 2 | 控制台看不到应用 | 心跳没通（8719/地址/eager） | 查启动日志 transport；确认 dashboard 地址 |
| 3 | blockHandler 不执行 | 兜底方法签名不符/标在接口/非 static | 按 [08 篇](08-与SpringCloudAlibaba集成速查.md) 三铁律检查 |
| 4 | Feign 兜底不生效 | `feign.sentinel.enabled` 没开 | 显式 true；降级 Bean 放 configuration |
| 5 | 重启规则丢光 | 没配数据源 | 加 sentinel-datasource-nacos（[06 篇](06-规则持久化与动态数据源速查.md)） |
| 6 | 链路模式失效 | `web-context-unify` 默认 true | 配 false |
| 7 | 授权规则全拒/全放 | 没实现 RequestOriginParser | 自定义来源解析（[05 篇](05-系统保护与授权规则速查.md)） |
| 8 | RT 熔断不准 | RT 统计上限 4900ms | `-Dcsp.sentinel.statistic.max.rt` 调大 |
| 9 | 异常数熔断反复 | timeWindow < 60s（分钟窗口） | timeWindow ≥ 60s 或换异常比例 |
| 10 | 集群规则不生效 | 规则没到 Token Server | 手动导入或 Dashboard 改造（[07 篇](07-集群流控速查.md)） |
| 11 | 误限流（正常用户被拒） | 阈值过低/热点误判 | 压测校准；查看监控曲线调阈值 |
| 12 | 限流返回 500 | 无兜底 | 所有资源配 blockHandler/fallback |
| 13 | 网关规则无效 | 用错规则体系 | Gateway 走 GatewayRuleManager（routeId 资源） |
| 14 | 注解切面不生效 | 切面未装配/方法内部自调用 | 加 aspectj 依赖；自调用不经过切面（走 AOP 代理外） |

## 5. 上线验证清单

| 阶段 | 检查项 | 通过标准 |
|------|--------|---------|
| 部署 | Dashboard 启动、客户端注册、规则入 Nacos | 控制台可见应用与规则 |
| 限流 | QPS=1 规则压测 | 超限被 Blocked + 兜底返回 |
| 熔断 | RT/异常策略注入故障 | 熔断触发 + timeWindow 后半开恢复 |
| 热点 | 参数级规则 | 同参数受限、异参数正常 |
| Feign | 下游停止模拟故障 | 调用走 fallback，不抛原始异常 |
| 系统保护 | 压测拉高 CPU | 全局拦截生效（注意别把测试环境搞挂） |
| 恢复 | 故障解除 | 熔断自动恢复、流量全量放行 |
| 持久化 | 重启客户端 | 规则从 Nacos 恢复，无需重新配置 |
| 告警 | 规则触发告警接入 | 熔断/限流事件可感知 |

> 🎯 上线总原则：**"先兜底，后规则"**——兜底（blockHandler/fallback）没有配齐之前，规则越多坑越多；兜底齐全后规则才是安全的。
