## 1. 部署总览

Sentinel 部署 = **Dashboard（控制台）+ 客户端（业务服务内嵌）** 两层，无独立 Server：

| 组件 | 形态 | 职责 | 数量 |
|------|------|------|------|
| Dashboard | 独立 JAR（Web 应用） | 规则管理 + 实时监控 + 集群流控管理 | 1（可集群部署，共用存储） |
| 客户端 | 业务服务内嵌 jar | 埋点统计 + 规则执行 + 心跳上报 | 每服务 1 份 |

```text
部署拓扑：
    Dashboard（8080）
      ▲ 心跳/规则/指标（HTTP）
      │
  业务服务A ──► 业务服务B（Feign，Sentinel 拦截熔断）
  业务服务C（Gateway 适配器限流）
  Nacos（规则持久化数据源，生产必配）
```

> ⚠️ **部署红线**：Dashboard 挂了**不影响**业务（客户端规则在本地内存执行，只是不能改规则/看监控）；但**规则持久化必须做**——否则 Dashboard 改的规则在客户端重启后消失（[06 篇](06-规则持久化与动态数据源速查.md)）。

## 2. Dashboard 部署（本机/Docker）

### 2.1 本机启动

```bash
# 下载 sentinel-dashboard-1.8.9.jar（GitHub releases）
java -Dserver.port=8080 \
     -Dcsp.sentinel.dashboard.server=localhost:8080 \
     -Dproject.name=sentinel-dashboard \
     -jar sentinel-dashboard-1.8.9.jar
```

| 启动参数 | 作用 |
|---------|------|
| `-Dserver.port` | 控制台端口（默认 8080） |
| `-Dcsp.sentinel.dashboard.server` | 控制台自身地址（客户端回调用） |
| `-Dproject.name` | 控制台在监控里的应用名 |
| `-Dauth.username / -Dauth.password` | 登录账号（默认 sentinel/sentinel） |
| `-Dsentinel.dashboard.auth.enabled=false` | 关闭鉴权（仅测试环境） |

> 💡 控制台访问 `http://localhost:8080`，默认账号 `sentinel` / `sentinel`。

### 2.2 Docker 部署（生产常用）

```bash
docker run -d --name sentinel-dashboard \
  -p 8080:8080 \
  -e JAVA_OPTS="-Dserver.port=8080 -Dcsp.sentinel.dashboard.server=localhost:8080 -Dproject.name=sentinel-dashboard -Dauth.username=admin -Dauth.password=YOUR_PASSWORD" \
  bladex/sentinel-dashboard:1.8.9
```

> ⚠️ **生产注意**：Dashboard 默认**无持久化**（规则在内存）——生产必须接 Nacos 双向同步（[06 篇](06-规则持久化与动态数据源速查.md) 的 Dashboard 改造方案），否则控制台重启规则全丢。

## 3. 客户端接入 4 步

### 3.1 四步清单

```text
① 引入 spring-cloud-starter-alibaba-sentinel（版本由 SCA BOM 管理）
② 配置 transport（dashboard 地址 + 8719 端口）+ eager: true
③ 业务代码加 @SentinelResource（或依赖 URL 自动埋点）
④ 控制台加规则 → 验证 Blocked
```

### 3.2 客户端配置（application.yml）

```yaml
spring:
  cloud:
    sentinel:
      transport:
        dashboard: localhost:8080     # ★ 控制台地址
        port: 8719                    # ★ 客户端上报端口（启动后占用）
      eager: true                     # ★ 启动即注册控制台（默认懒加载）
      web-context-unify: true         # 统一 Web 上下文（默认 true，链路模式注意）
      datasource:                     # 规则数据源（生产必配，见 06 篇）
        ds-flow:
          nacos:
            server-addr: localhost:8848
            dataId: ${spring.application.name}-flow-rules
            groupId: SENTINEL_GROUP
            rule-type: flow
```

```java
// 编程式埋点（非注解场景）
try (Entry entry = SphU.entry("order:create")) {
    return orderService.create(dto);          // 业务
} catch (BlockException e) {
    return fallback(dto, e);                  // 被拦截
}
```

### 3.3 注解式（推荐）

```java
@SentinelResource(value = "order:create",
        blockHandler = "createBlock",          // BlockException（限流/熔断/授权）→ 兜底
        fallback = "createFallback")           // 业务异常 → 兜底
public Order create(OrderDTO dto) { ... }

public Order createBlock(OrderDTO dto, BlockException e) { ... }   // 需加 BlockException 参数
public Order createFallback(OrderDTO dto, Throwable t) { ... }     // 需加 Throwable 参数
```

> ⚠️ **注解三坑**：① 只能标在实现类方法（不能标接口）；② fallback/blockHandler 需与原方法**同参数同返回**，且可加对应异常参数；③ 用 `fallbackClass`/`blockHandlerClass` 指定类时方法必须 **static**（[08 篇](08-与SpringCloudAlibaba集成速查.md) 全属性表）。

## 4. 控制台操作指南

| 功能 | 位置 | 说明 |
|------|------|------|
| 应用列表 | 首页/机器列表 | 心跳上线的客户端应用与实例 |
| 实时监控 | 监控页 | 秒级 QPS/RT/异常曲线（默认最多 5 秒粒度） |
| 流控规则 | 流量控制 | FlowRule：资源名 + QPS/线程数 + 模式/效果 |
| 熔断规则 | 熔断降级 | DegradeRule：RT/异常比例/异常数 |
| 热点规则 | 热点参数 | ParamFlowRule：参数索引 + 阈值 + 例外 |
| 系统规则 | 系统保护 | SystemRule：Load/CPU/RT/入口 QPS |
| 授权规则 | 授权管理 | AuthorityRule：黑/白名单 |
| 集群流控 | 集群流控 | Token Server/Client 管理 |

### 4.1 控制台加规则流程（以限流为例）

```text
控制台 → 选择应用 → 流量控制 → 新增流控规则
    资源名：order:create（与 @SentinelResource value 一致）
    阈值类型：QPS / 并发线程数
    单机阈值：10
    流控模式：直接
    流控效果：快速失败
→ 保存 → 客户端 1~2 秒内生效（推模式）→ 压测验证
```

> 🎯 **资源名对齐是规则生效的前提**：控制台写的资源名必须与注解 `value`（或 URL 路径）**完全一致**——不一致的规则静默无效（[09 篇](09-集成地图与常见问题.md) 高频坑 #1）。

## 5. 端口与参数清单

| 端口 | 用途 | 备注 |
|------|------|------|
| 8080 | Dashboard 控制台 | 可改 `-Dserver.port` |
| **8719** | 客户端心跳/规则/指标上报 | 客户端启动占用，被占自动 +1 偏移 |

| 客户端 JVM 参数 | 说明 |
|----------------|------|
| `-Dcsp.sentinel.dashboard.server` | 控制台地址（也可配 `spring.cloud.sentinel.transport.dashboard`） |
| `-Dcsp.sentinel.api.port` | 客户端 API 端口（默认 8719） |
| `-Dcsp.sentinel.statistic.max.rt` | RT 统计上限（默认 4900ms，熔断 RT 策略受它约束） |
| `-Dcsp.sentinel.flow.interval` | 流控统计窗口（默认 1s） |
| `-Dcsp.sentinel.log.dir` | 日志目录（默认 `~/logs/csp/`） |

> ⚠️ **8719 冲突**：多应用同机部署时 8719 可能被占——Sentinel 会**自动 +1 偏移**（8719→8720…），控制台按实际偏移连接；排查心跳问题先看启动日志的 `port already in use`。

## 6. 快速验证场景

| 场景 | 操作 | 预期 |
|------|------|------|
| 限流生效 | 规则 QPS=1 → 快速连点接口 | 第二次请求被 Blocked（`Blocked by Sentinel` 或 blockHandler 结果） |
| 熔断生效 | 熔断规则 RT>200ms → 接口 sleep 500ms | 连续 5 次后进入熔断，后续快速失败 |
| 热点限流 | 热点规则参数 idx=1 QPS=1 | 同一商品 ID 连续请求被限，不同 ID 正常 |
| 降级兜底 | 业务方法抛异常 → fallback | 返回 fallback 结果（不抛原始异常） |
| 控制台曲线 | 压测 10s | 监控页 QPS/RT 曲线可见 |

## 7. 常见部署问题

| 现象 | 原因 | 处理 |
|------|------|------|
| 控制台看不到应用 | 心跳没通：8719 被占/地址错/eager=false | 查启动日志 `Sentinel transport`；确认 dashboard 地址 |
| 规则不生效 | 资源名不匹配 | 控制台规则资源名 = 注解 value 完全一致 |
| 规则重启丢失 | 没配数据源 | 加 sentinel-datasource-nacos 推模式（[06 篇](06-规则持久化与动态数据源速查.md)） |
| Dashboard 登录失败 | 鉴权账号未配 | 默认 sentinel/sentinel；或 `-Dauth.username/-Dauth.password` |
| 应用频繁掉线 | 网络隔离 8719/心跳超时 | 控制台与客户端网络互通；检查防火墙 |
| 重启后规则变旧 | 推模式数据源配置错 | 查 dataId/groupId/rule-type 与 Nacos 配置一致 |
