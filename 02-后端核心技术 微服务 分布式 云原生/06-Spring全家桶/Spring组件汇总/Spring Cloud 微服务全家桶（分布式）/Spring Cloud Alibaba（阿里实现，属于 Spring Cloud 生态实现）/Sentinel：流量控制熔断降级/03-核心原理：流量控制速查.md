## 1. 资源与拦截链

```text
一次请求的旅程：
    SphU.entry("order:create")
        │
        └─► 责任链（Slot 依次执行）：
            NodeSelectorSlot（建节点/调用树）
            ClusterBuilderSlot（建 ClusterNode 统计）
            StatisticSlot（记录实时指标）
            ParamFlowSlot（热点参数检查）─── 拦截 → BlockException
            SystemSlot（系统保护检查）────── 拦截 → BlockException
            AuthoritySlot（授权黑白名单）─── 拦截 → BlockException
            FlowSlot（流控检查）────────── 拦截 → BlockException
            DegradeSlot（熔断检查）──────── 拦截 → BlockException
            ──► 通过 → 执行业务代码
```

| 概念 | 说明 |
|------|------|
| 资源（Resource） | 被保护对象：URL / 方法 / Feign 接口，有唯一资源名 |
| Entry | 一次资源访问的上下文（`SphU.entry()` 创建，`entry.exit()` 释放） |
| Node | 统计节点：DefaultNode（按调用来源）、ClusterNode（聚合） |
| Slot | 规则检查器（责任链顺序执行，任一拦截即抛 BlockException） |

> 🎯 面试必答：**"Sentinel 的规则怎么串起来？"**——**Slot 责任链**：一次 entry 按固定顺序过多个 Slot，FlowSlot/DegradeSlot/SystemSlot 各自检查对应规则，**任一拒绝抛 BlockException 阻止执行**——这就是 Sentinel 的 SPI 扩展点（自定义 Slot 可加规则）。

## 2. 统计基石：滑动窗口

限流要"知道当前秒有多少请求"，Sentinel 用**滑动窗口**做秒级统计：

```text
滑动窗口（默认 1s 窗口 / 2 个采样格）：
    ┌──────┬──────┬──────┬──────┬──────┬──────┐
    │ 0-500ms│500-1s│1-1.5s│1.5-2s│2-2.5s│2.5-3s│
    └──────┴──────┴──────┴──────┴──────┴──────┘
            当前窗口（滚动）：统计最近 1s 的 QPS/RT/异常

    LeapArray 环形数组：写只写当前格（CAS），读聚合窗口内所有格
```

| 特性 | 说明 |
|------|------|
| 精度 | 1s 窗口（可配），秒级实时统计 |
| 采样 | 默认 2 格（500ms/格），窗口滑动聚合 |
| 实现 | `LeapArray` 环形数组 + 时间戳定位格子，**无锁写 + CAS** |
| 统计量 | QPS、并发线程数、RT、成功/失败计数 |

> 🎯 面试必答：**"滑动窗口和固定窗口什么区别？"**——固定窗口（如 1s 计数清零）在**窗口边界会瞬间放 2 倍流量**（前一秒末尾 + 下一秒开头各打满）；滑动窗口按时间滚动聚合最近窗口，**边界流量被精确统计**——Sentinel 秒级滑动窗口基本无边界毛刺。

## 3. 限流维度：QPS 与并发线程数

| 维度 | FlowRule.grade | 原理 | 适用 |
|------|---------------|------|------|
| **QPS** | 1（默认） | 每秒请求数超阈值即拦截 | 接口整体限流（最常见） |
| **并发线程数** | 0 | 同时执行的线程数超阈值即拦截 | 慢接口保护（防线程堆积） |

```java
// 并发线程数限流的典型价值：慢调用防护
// 接口 RT=2s，并发线程阈值=10 → 同时最多 10 个请求在跑，
// 超出者快速失败——避免线程全部挂在慢接口上（雪崩前兆）
FlowRule rule = new FlowRule("slow:api");
rule.setGrade(RuleConstant.FLOW_GRADE_THREAD);   // 并发线程数
rule.setCount(10);
```

> 💡 选维度口诀：**流量型接口（下单/查询）用 QPS；慢接口/下游不稳用并发线程数**——线程维度天然保护"堆积"，QPS 维度保护"总量"。

## 4. 流控模式：直接/关联/链路

| 模式 | strategy | 含义 | 典型场景 |
|------|---------|------|---------|
| **直接** | 0 | 对资源自己限流 | 绝大多数接口 |
| **关联** | 1 | **关联资源**超阈值时，限流当前资源 | 支付高峰 → 限制查询接口 |
| **链路** | 2 | 只限制指定**调用链路**（按入口区分） | 同一方法被 A/B 两个入口调，只限 A |

```text
关联模式示例：
    资源 A：pay（支付）  资源 B：query（查询）
    B 的规则：strategy=关联，关联资源=pay
    → 支付流量超标时，查询被限流（保护支付优先，查询让路）

链路模式示例：
    资源 C：commonMethod（公共方法）
    入口 1：apiA → C；入口 2：apiB → C
    C 的规则：strategy=链路（入口 apiA），QPS=10
    → 只有 apiA 调 C 受限，apiB 调 C 不限
```

> ⚠️ **链路模式前置**：`spring.cloud.sentinel.web-context-unify: false`（关闭 Web 上下文合并），否则所有 Web 入口合并成同一个 context，链路区分失效（[09 篇](09-集成地图与常见问题.md) 坑位表）。

## 5. 流控效果：快速失败/预热/匀速排队

| 效果 | controlBehavior | 行为 | 场景 |
|------|----------------|------|------|
| **快速失败** | 0 | 超阈值立即拒绝（默认） | 一般接口 |
| **Warm Up 预热** | 2 | 阈值从 1/3 渐变到满值（冷启动） | 系统刚启动/缓存冷时防打爆 |
| **匀速排队** | 1 | 请求按固定速率排队通过（漏桶思想） | 秒杀/消息类平滑流量 |

### 5.1 Warm Up 预热

```text
启动冷启动：threshold=1000 QPS
    0s ──► 阈值 333（1/3）──渐变──► 60s 后满值 1000
    用途：JIT 预热、缓存冷启动、连接池建立期间保护
    参数：warmUpPeriodSec（预热秒数，默认 10）
```

### 5.2 匀速排队

```text
匀速排队（Rate Limiter 思想）：
    请求 100 个，阈值 10 QPS
    → 每秒放行 10 个，其余排队（超时 maxQueueingTimeMs 则拒绝）
    用途：把突刺流量拉平（类似 MQ 削峰的小规模版）
```

> 🎯 面试对比：**快速失败 = 令牌桶/计数（超即拒）；匀速排队 = 漏桶（排队匀速放）；预热 = 冷启动保护**——Sentinel 三种效果覆盖"拒/平/护"三种诉求。

## 6. 热点参数限流

按**参数值**（如商品 ID）做独立限流：热门商品被限，冷门商品不受影响。

```java
ParamFlowRule rule = new ParamFlowRule("product:detail");
rule.setParamIdx(0);                              // 第 0 个参数（商品 ID）
rule.setCount(100);                               // 该参数默认阈值
// 例外项：指定参数值单独配阈值
ParamFlowItem item = new ParamFlowItem("12345", 10);  // 爆款商品 ID=12345 只允许 10 QPS
rule.setParamFlowItemList(Collections.singletonList(item));
```

| 特性 | 说明 |
|------|------|
| 统计 | **LRU 缓存**按参数值独立计数（非全局计数） |
| 算法 | 参数级令牌桶（每参数值一个桶） |
| 维度 | 仅 QPS（不支持线程数） |
| 例外 | `paramFlowItemList`：指定参数值覆盖阈值 |
| 场景 | 秒杀爆款、热点商品详情、恶意刷单参数 |

> ⚠️ **热点限流限制**：只支持**基本类型 + String** 参数（对象参数取不到值）；不支持 `excludeParamIndexes` 之外的多参数组合例外。

## 7. 限流算法对照（面试弹药）

| 算法 | 思想 | 代表 | 特点 |
|------|------|------|------|
| 固定窗口 | 窗口内计数清零 | 简单计数 | 边界双倍流量 |
| 滑动窗口 | 滚动窗口精确统计 | **Sentinel 默认** | 精确、无边界毛刺 |
| 令牌桶 | 桶内令牌匀速补充，取令牌放行 | Guava RateLimiter | 允许突发 |
| 漏桶 | 请求入桶匀速流出 | Sentinel 匀速排队 | 平滑无突发 |
| 滑动日志 | 记录每次请求时间戳滑动剔除 | 精确但内存大 | 高精度 |

> 🎯 面试加分：**"Sentinel 用的什么算法？"**——统计层**滑动窗口**（LeapArray 秒级精确）；效果层**快速失败（直接计数判断）+ 预热（渐变阈值）+ 匀速排队（漏桶/令牌桶思想）**；热点参数是**参数级令牌桶**——三层各有所属，别只答"令牌桶"。
