## 1. 模块组成

| 模块 | 类型 | 职责 | 引入方 |
|------|------|------|--------|
| **sentinel-core** | 核心库 | 资源埋点、滑动窗口统计、规则引擎、拦截链 | 所有客户端 |
| **sentinel-dashboard** | 独立控制台 | 规则管理、实时监控、集群流控管理 | 独立部署（可 Docker） |
| **sentinel-transport-simple-http** | 传输层 | 客户端 ↔ 控制台心跳/规则/指标（HTTP 8719） | 客户端 |
| **sentinel-datasource-nacos** | 数据源 | 从 Nacos 拉取规则（推模式监听） | 生产客户端 |
| **sentinel-datasource-zookeeper / apollo / redis** | 数据源 | 对应配置中心规则源 | 按基建选 |
| **sentinel-annotation-aspectj** | 注解支持 | `@SentinelResource` AOP 切面 | 客户端 |
| **sentinel-web-servlet** | Web 适配器 | URL 自动埋点 + 统一入口拦截 | Web 服务 |
| **sentinel-spring-webmvc-adapter** | Spring MVC 适配 | Spring MVC 资源定义（1.8+） | Spring Web 服务 |
| **sentinel-cluster-client-default / server-default** | 集群流控 | Token Client / Token Server | 集群流控场景 |
| **sentinel-spring-cloud-gateway-adapter** | 网关适配 | Spring Cloud Gateway 限流 | 网关服务 |
| **sentinel-reactor-adapter / webflux-adapter** | 响应式适配 | WebFlux/Reactor 限流 | 响应式服务 |
| **sentinel-apache-dubbo-adapter / sofa-rpc-adapter** | RPC 适配 | Dubbo/Sofa RPC 埋点 | 对应 RPC 生态 |

> 💡 接入口诀：**SCA 生态 `spring-cloud-starter-alibaba-sentinel` 一个依赖全搞定**（core + transport + webmvc + aspectj 自动装配）；数据源（Nacos）和集群流控模块按需加。

## 2. 核心包结构

```text
com.alibaba.csp.sentinel
├── SphU / Entry              # 资源入口：SphU.entry("资源名") → 返回 Entry
├── entry                     # 资源条目、Context（调用上下文）、Node（统计节点）
├── node                      # 统计节点体系：DefaultNode / ClusterNode / 滑动窗口
├── slotchain                 # ★ 责任链：ProcessorSlot（流控/熔断/系统/授权等 Slot）
│   ├── NodeSelectorSlot      # 构建调用链节点
│   ├── FlowSlot              # 流量控制
│   ├── DegradeSlot           # 熔断降级
│   ├── SystemSlot            # 系统保护
│   ├── AuthoritySlot         # 授权（黑白名单）
│   └── ParamFlowSlot         # 热点参数限流
├── rule                      # 规则模型：FlowRule / DegradeRule / SystemRule / AuthorityRule / ParamFlowRule
├── datasource                # 数据源 SPI（Nacos/ZK/Apollo 实现）
├── annotation                # @SentinelResource 注解与切面
└── cluster                   # 集群流控（Token Server/Client）
```

> 🎯 关键认知：**Sentinel 的引擎是 Slot 责任链**——一次请求经过 NodeSelector→Flow→Degrade→System→Authority→ParamFlow 各 Slot 检查，任一 Slot 拦截即抛 `BlockException`；**理解拦截链顺序 = 理解规则优先级**（[03 篇](03-核心原理：流量控制速查.md)）。

## 3. 依赖坐标与边界

### 3.1 官方坐标（Maven Central）

```xml
<!-- ① SCA 生态（推荐，版本由 SCA BOM 管理） -->
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-sentinel</artifactId>
</dependency>

<!-- ② 原生使用（非 SCA）：显式指定版本 -->
<dependency>
    <groupId>com.alibaba.csp</groupId>
    <artifactId>sentinel-core</artifactId>
    <version>1.8.9</version>
</dependency>

<!-- ③ Nacos 规则持久化（生产必加） -->
<dependency>
    <groupId>com.alibaba.csp</groupId>
    <artifactId>sentinel-datasource-nacos</artifactId>
    <version>1.8.9</version>
</dependency>
```

### 3.2 依赖边界

| 边界 | 说明 |
|------|------|
| **客户端与 Dashboard 版本尽量一致** | 规则 API/传输协议版本敏感，跨大版本推送失败 |
| 1.8.x 支持 JDK 8/11/17 | 客户端与 Boot 2/3/4 均可（2025.1.0.0 起 Jackson 3 兼容） |
| **规则持久化 = 额外数据源依赖** | 不加数据源则规则存内存，重启即失（[06 篇](06-规则持久化与动态数据源速查.md)） |
| 与 Nacos 是"规则源"关系 | 非注册中心依赖（Sentinel 不需要 Nacos 做服务发现） |
| 不引入业务依赖 | 适配器通过 SPI/自动装配挂载，不强制特定 Web 框架 |

> ⚠️ **最常见的坑**：只加 `sentinel-core` 不加 transport——**控制台看不到应用**（没心跳）；只加规则不配数据源——**重启规则丢光**。生产接入 = starter + transport + datasource 三件套。

## 4. 版本兼容矩阵（2026-08）

### 4.1 Sentinel ↔ Spring Cloud Alibaba（2026 权威组合）

| Spring Cloud Alibaba | Sentinel | Spring Boot | Spring Cloud | JDK | 备注 |
|----------------------|----------|-------------|-------------|-----|------|
| **2025.1.0.0** | **1.8.9** | 4.0.x | 2025.1.x | 17+ | 最新；Sentinel 模块支持 Jackson 3 |
| **2025.0.0.0** | **1.8.9** | 3.5.x | 2025.0.x | 17+ | 当前稳定；Nacos 3.0.3/Seata 2.5.0/RocketMQ 5.3.1 |
| 2023.0.x | 1.8.6 | 3.2.x | 2023.x | 17+ | Boot 3 存量线 |
| 2022.0.0.0 | 1.8.6 | 3.0.x | 2022.x | 8+ | Boot 3 过渡线 |
| 2021.x | 1.8.1/1.8.0 | 2.6.x | 2021.x | 8+ | Boot 2 存量线 |

### 4.2 Sentinel 独立版本线

| Sentinel 版本 | 关键点 |
|--------------|--------|
| 1.8.9 | SCA 2025.x 内置稳定线；Jackson 3 支持 |
| 1.8.8 | JDK 17 完善 |
| 1.8.6 | SCA 2022/2023 线常用 |
| 1.8.1 | 控制台推荐基线（1.8.x 控制台功能稳定） |
| 1.7.x | 集群流控成熟、Gateway 适配 |
| 1.6.x | Gateway/WebFlux 适配起点 |

### 4.3 快速对齐口诀

| 场景 | 推荐组合 |
|------|---------|
| 新项目（Boot 4） | SCA 2025.1.0.0 + Sentinel 1.8.9 + JDK 17 |
| 新项目（Boot 3.5） | SCA 2025.0.0.0 + Sentinel 1.8.9 + JDK 17 |
| 存量 Boot 3.2 | SCA 2023.0.x + Sentinel 1.8.6 |
| 存量 Boot 2.6 | SCA 2021.x + Sentinel 1.8.x |
| 原生（非 SCA） | sentinel-core + 适配器 1.8.9 + 自管版本 |

> ⚠️ **Dashboard 版本选择**：控制台 jar 用 **1.8.1 及以上**即可管理 1.8.x 客户端；但若同时要集群流控管理功能，建议与控制台配套同版本。

## 5. 与 SCA 其他组件的依赖关系

| 组件 | 关系 | 说明 |
|------|------|------|
| Nacos | **规则数据源**（非注册依赖） | 规则持久化推模式（[06 篇](06-规则持久化与动态数据源速查.md)） |
| OpenFeign | **强协作** | `feign.sentinel.enabled: true` 开启 Feign 熔断降级（[08 篇](08-与SpringCloudAlibaba集成速查.md)） |
| Spring Cloud Gateway | 适配器 | sentinel-spring-cloud-gateway-adapter 网关限流 |
| Seata | 无直接依赖 | 事务接口也可加 Sentinel 防护（并行治理） |
| RocketMQ | 无直接依赖 | 消费端可用 Sentinel 做消费限流（`sentinel-mq-rocketmq-adapter` 生态） |

## 6. 模块选型建议

| 场景 | 推荐模块 | 理由 |
|------|---------|------|
| SCA Web 微服务 | `spring-cloud-starter-alibaba-sentinel` | 一个依赖全装配 |
| 需要规则持久化 | + `sentinel-datasource-nacos` | 推模式热更新（生产必须） |
| 网关限流 | + `sentinel-spring-cloud-gateway-adapter` | 网关层第一道闸门 |
| 响应式/WebFlux | + `sentinel-webflux-adapter` + `sentinel-reactor-adapter` | 反应式支持 |
| 集群精确限流 | + `sentinel-cluster-client-default`（Server 另部署） | [07 篇](07-集群流控速查.md) |
| 非 Spring 纯 Java | `sentinel-core` + 手工 `SphU.entry()` | 最小化接入 |
| Dubbo 生态 | + `sentinel-apache-dubbo-adapter` | RPC 埋点 |
