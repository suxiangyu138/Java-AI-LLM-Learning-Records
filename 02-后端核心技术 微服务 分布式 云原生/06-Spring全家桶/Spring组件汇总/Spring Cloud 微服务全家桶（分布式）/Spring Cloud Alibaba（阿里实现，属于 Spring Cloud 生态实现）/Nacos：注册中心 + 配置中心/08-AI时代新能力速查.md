## 1. 为什么注册中心要做 AI

**通俗**：微服务时代，Nacos 解决"服务实例在哪"；AI Agent 时代，新的问题是"**Agent 有哪些、能力（Skill/MCP 工具）在哪、Prompt 是什么**"——同样需要"注册 + 发现 + 变更通知"，Nacos 把这套成熟机制延伸到 AI 资源。

```text
微服务时代：服务实例（IP:port）注册 → 消费者发现 → 调用
AI Agent 时代：Agent/技能/工具（MCP Server）注册 → LLM/Agent 发现 → 按需调用

Nacos 3.x 的 AI Registry：同一套"注册-发现-订阅"心智，资源从"实例"变成"能力"
```

| 版本 | AI 能力里程碑 |
|------|--------------|
| 3.0（2024-10） | MCP Registry + Agent Registry 起步（"AI Registry" 概念） |
| 3.1 | AI Registry 扩展（资源模型完善） |
| **3.2.0（2026-03）** | **AI 三件套完成**：Skill Registry + Prompt Registry + MCP/Agent；Nacos Copilot 集成；MCP 工具 `_meta`/`outputSchema` 支持 |
| 3.2.1 | Prompt 生命周期管理 UI、**A2A AgentCard v1 协议**、Skill bizTag 过滤 |
| **3.3.0-BETA（2026-08）** | **协议无关的 Agent 注册/管理/发现**、**Agentic Resource Discovery（混合检索）**、分布式锁增强 |

> 🎯 定位一句话：**Nacos 从"微服务注册中心"升级为"AI Agent 时代的资源注册中心"**——服务、配置之外，再管 Agent/技能/Prompt/MCP 工具的注册与发现——**2026 面试可讲的 Nacos 新故事**（与 [MCP 协议与 Agent Skill](../../../../../../03-AI大模型应用开发/06-MCP协议与Agent Skill/) 深度联动）。

## 2. MCP Registry：LLM 工具注册与发现

### 2.1 是什么

**通俗**：LLM 要调用外部工具（查天气、下单、查库存）走 MCP 协议——MCP Server（工具提供方）注册到 Nacos，LLM/Agent 按需发现并调用。

```text
工具提供方（MCP Server：天气/订单/库存）──注册──► Nacos MCP Registry
                                                   │  （工具元数据：名称/参数/outputSchema）
LLM / Agent ◄──发现（按需检索）────────────────────┘
        │  挑选 3-5 个相关工具注入上下文（智能过滤降 token）
        ▼
调用工具（MCP 协议）
```

| MCP Registry 能力 | 说明 |
|-------------------|------|
| 工具注册 | MCP Server 注册工具元数据（名称、参数、`_meta`、`outputSchema`，3.2+） |
| 智能过滤 | 数百工具中推荐 3-5 个相关（**降 token 消耗**） |
| 变更通知 | 工具上下线/参数变更 → 订阅方实时感知 |
| 生态 | 配合 MCP SDK（3.2.1 用 MCP SDK 0.17.0） |

> 🎯 面试必答：**"MCP Registry 解决什么问题？"**——Agent 场景的工具发现：没有注册中心时，Agent 要么硬编码工具地址、要么把所有工具元数据全量塞进上下文（**token 爆炸**）；Nacos MCP Registry 提供**注册 + 按需检索 + 只推荐相关工具**——工具多了以后的"能力发现"问题（与 [MCP 协议](../../../../../../03-AI大模型应用开发/06-MCP协议与Agent Skill/) 配套）。

## 3. Agent / Skill / Prompt Registry

### 3.1 三类资源

| 资源 | 是什么 | 注册什么 | 3.x 支持 |
|------|--------|---------|---------|
| **Agent** | 智能体实例（可执行的 Agent 服务） | Agent 标识、能力描述、调用地址 | 3.0 起；**3.3 协议无关**（不限 MCP） |
| **Skill** | Agent 的技能/能力单元（可组合） | Skill 名称、描述、bizTag（业务标签，3.2.1） | 3.2.0 起 |
| **Prompt** | 提示词模板（可复用/可版本化） | Prompt 内容、版本、用途标签 | 3.2.0 起；3.2.1 完整生命周期 UI |

### 3.2 为什么 Prompt 也要注册中心

```text
Prompt 是 Agent 的"配置"——与微服务配置同理：
  版本管理（历史/回滚）│ 动态更新（改了不用发版）│ 按场景发现（检索）
Nacos 的配置中心能力天然适配 Prompt 资源管理
```

> 💡 认知：**Prompt Registry = 配置中心在 AI 场景的延伸**——把"Prompt 当配置管"（版本/灰度/回滚）是 Nacos 现有能力的自然复用（[04 篇](04-配置中心实战速查.md) 配置管理机制）。

## 4. Agentic Resource Discovery：混合检索

> **3.3.0-BETA 新能力**：资源检索从"关键词匹配"升级为"**关键词 + 向量混合检索**"（语义相似度）——Agent 按"意图"找能力，而非只按"名字"。

```text
Agent 需求："帮我查一下最近订单状态"（自然语言）
  → 关键词检索：order / status（可能漏）
  → 向量检索：语义相近的 Skill/工具（"订单查询"“物流跟踪”）
  → 混合检索（3.3）：两者融合排序（RRF）→ 返回最相关资源
```

| 能力 | 说明 |
|------|------|
| 混合检索 | 关键词 + 向量（语义）融合（与 [MongoDB 8.4 混合检索](../../../Spring Data 系列【数据访问层】/Spring Data MongoDB/08-向量检索与AI集成速查.md) 同思路） |
| 适用 | Skill/Prompt/MCP 资源的语义发现 |
| 前置 | 资源向量化（嵌入模型生成描述向量） |
| 意义 | **"按意图找能力"** ——Agent 能力发现的自然语言入口 |

> 🎯 面试加分句：**"Nacos 3.3 的 Agentic Resource Discovery 是什么？"**——Agent 资源（Skill/Prompt/MCP）的注册与检索升级为**关键词 + 向量混合检索**（语义匹配意图）——注册中心从"地址簿"变成"**能力目录**"（按语义找能力）——与向量数据库/语义检索同一趋势在注册中心的落地。

## 5. 分布式锁（3.3 实验性）

| 维度 | Nacos 3.3 锁 | Redis/Redisson 锁 |
|------|-------------|------------------|
| 能力 | 可重入/非可重入锁、看门狗续期、FIFO 等待、gRPC 通知 | 成熟（Redisson 看门狗/红锁） |
| 一致性 | **Raft 强一致**（CP） | AP（哨兵/集群下极端丢锁） |
| 状态 | **实验性（3.3.0-BETA）** | 生产成熟 |
| 适用 | 强一致锁场景（未来方向） | **当前生产首选** |

> ⚠️ **定位提醒**：3.3 分布式锁是实验性新能力——**生产锁仍用 Redisson**（[Redis 锁](../../../Spring Data 系列【数据访问层】/Spring Data Redis/06-分布式锁与Lua脚本速查.md)）；Nacos 锁的价值在"注册中心同一套集群顺带提供强一致锁"（少一套组件），成熟后按需评估——**别把实验特性当生产方案**。

## 6. 与 Spring AI / MCP 生态联动

### 6.1 联动图

```text
Spring AI 应用（Java Agent）
  ├── MCP 客户端（Spring AI MCP Client）
  │     └── 从 Nacos MCP Registry 发现工具（替代硬编码工具列表）
  ├── Agent 注册（发布自身能力到 Nacos）
  └── Prompt 管理（Nacos 配置中心存 Prompt，动态更新）

Nacos Copilot（3.2+）：AI 辅助管理（自然语言操作 Nacos——"把 order-service 的日志级别改成 DEBUG"）
```

### 6.2 落地骨架

```yaml
# Spring AI + MCP 客户端（2026 主流）
spring:
  ai:
    mcp:
      client:
        # 工具来源：Nacos MCP Registry 发现结果注入（配合 MCP SDK）
```

```java
// 概念骨架：Agent 注册自身到 Nacos
// （3.x AI Registry API/控制台：注册 Agent 标识、能力描述、调用端点）
nacosAgentRegistry.register(AgentInfo.builder()
        .name("order-agent")
        .description("订单查询与处理智能体")
        .endpoint("http://order-agent:8080")
        .skills(List.of("order-query", "order-cancel"))
        .build());
```

> 💡 生态联动认知：**Nacos AI 能力是"注册与发现"层**——嵌入生成（向量化）在 Spring AI/嵌入模型侧、工具调用协议是 MCP、Agent 编排是 LangChain4j/Spring AI——**Nacos 管"谁有这能力、在哪、怎么描述"**（配合 [Spring AI 系列](../../../../../../03-AI大模型应用开发/05-AI开发框架/)）。
