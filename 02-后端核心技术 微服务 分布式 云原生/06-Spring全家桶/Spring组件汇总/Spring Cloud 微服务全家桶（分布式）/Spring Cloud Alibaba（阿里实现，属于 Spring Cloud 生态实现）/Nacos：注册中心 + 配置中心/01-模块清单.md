## 1. Artifact 坐标与版本线

### 1.1 服务端与客户端

| 项 | 值 |
|----|----|
| 项目 | `alibaba/nacos`（GitHub） |
| 服务端当前线 | **3.2.3（稳定，2026-07）**；3.3.0-BETA（特性） |
| 客户端（Java） | `com.alibaba.nacos:nacos-client`（3.0.3 随 SCA 2025.0.x 内置） |
| 服务端运行 | Nacos Server 独立部署（JDK 17）；客户端 JDK 8+ |
| 双职责 | 注册中心 + 配置中心（同一进程同一端口组） |

### 1.2 Spring Cloud Alibaba 集成坐标

| Starter | 职责 | 说明 |
|---------|------|------|
| `spring-cloud-starter-alibaba-nacos-discovery` | 注册中心 | 服务注册/发现自动装配 |
| `spring-cloud-starter-alibaba-nacos-config` | 配置中心 | 配置拉取/刷新自动装配 |
| `spring-cloud-starter-alibaba-nacos` | 全家桶聚合 | 两 starter 聚合（按需二选一/都引） |

```xml
<!-- 注册 + 配置双职责（生产标配） -->
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-nacos-discovery</artifactId>
</dependency>
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-nacos-config</artifactId>
</dependency>
```

> ⚠️ **版本协调第一原则**：**nacos-client 与 Nacos 服务端不要跨大版本**——SCA 2025.0.0.0 内置 client 3.0.3，**必须配服务端 3.x**；配 2.x 服务端时配置中心不可用（[09 篇](09-集成地图与常见问题.md) 有降级方案）。

## 2. 版本兼容矩阵（client ↔ server）

### 2.1 2026 主流组合

| Spring Boot | Spring Cloud | Spring Cloud Alibaba | 内置 nacos-client | 必须配服务端 |
|-------------|-------------|---------------------|-----------------|-------------|
| **4.x / 3.5.x** | **2025.x** | **2025.0.x** | **3.0.3** | **Nacos 3.x（推荐 3.2.x）** |
| 3.4.x | 2024.0.x | 2023.0.4.x | 2.4.x | Nacos 2.4.x |
| 3.2.x | 2023.0.x | 2023.0.3.x | 2.3.x/2.4.x | Nacos 2.3.x/2.4.x |
| 2.7.x | 2021.0.x | 2021.0.6.x | 2.2.x | Nacos 2.2.x |

### 2.2 跨版本场景的处置

| 场景 | 处置 |
|------|------|
| SCA 2025.0.x + 服务端仍是 2.x | **配置中心不可用**（官方 Issue #4098）；临时方案：排除内置 nacos-client 3.0.3，改引 2.5.1（**仅过渡**，长期必须升服务端） |
| 服务端 3.x + 老客户端 2.x | 部分新能力不可用（AI Registry/CP 模式需 3.x 客户端）；建议同步升级 |
| 已知坑 | namespace 为空时读不到 public 配置（Issue #4094）；dataId 大小写/后缀一致性 |

> 🎯 面试必答：**"nacos-client 版本怎么定？"**——**跟 Spring Cloud Alibaba BOM 走，且与服务端保持同大版本**（client 3.x ↔ server 3.x，client 2.x ↔ server 2.x）——跨大版本最常见症状：注册能通但**配置拉不到/不刷新**（gRPC 协议兼容问题），排查先看版本矩阵。

## 3. 包结构地图

```text
Nacos Server（独立进程）
├── console（控制台 Web）          # 管理界面（3.x 默认鉴权）
├── naming（注册中心核心）          # Distro（AP）/ JRaft（CP）
├── config（配置中心核心）          # 配置存储 + 长轮询推送
├── plugin（SPI 插件体系，3.2+）    # 鉴权/限流/存储等插件化
├── ai（AI Registry，3.x）         # MCP/Agent/Skill/Prompt 注册
├── persistence（存储适配）         # MySQL/Derby（单机默认 Derby）
└── api（HTTP/gRPC 接口层）         # /v1 /v2 拆子模块（3.2，legacy-adapter 兼容）

nacos-client（Java 客户端，随 SCA 引入）
├── com.alibaba.nacos.client
│   ├── naming（NamingService：注册/发现/订阅）
│   ├── config（ConfigService：拉取/监听/刷新）
│   ├── env（配置加载）
│   └── utils（工具）
├── api（Nacos API 接口定义：NamingService/ConfigService）
└── common（公共：地址解析、容灾、日志）

Spring Cloud Alibaba 适配层（业务代码接触面）
├── com.alibaba.cloud.nacos
│   ├── discovery（NacosServiceDiscovery / NacosRegistration / NacosDiscoveryClient）
│   ├── config（NacosConfigDataLoader / NacosPropertySourceLocator）
│   ├── loadbalancer（NacosLoadBalancer 权重支持）
│   └── NacosConfigManager / NacosServiceManager（client 门面）
```

> 💡 记忆抓手：**业务代码只碰 SCA 适配层（discovery/config starter）**，它内部持 nacos-client（NamingService/ConfigService）；源码学习从 `NacosServiceManager`（client 统一门面）入手，双职责的注册/拉取都从这走。

### 3.1 运行时对象链

```text
注册：Spring Cloud 自动装配 → NacosAutoServiceRegistration
        → NacosServiceRegistry.register（心跳启动）
        → nacos-client NamingService → gRPC 长连接 → Nacos Server naming 模块

发现：OpenFeign/RestTemplate → LoadBalancer → NacosServiceDiscovery.getInstances
        → client 本地缓存（订阅后增量推送）

配置：启动 → NacosPropertySourceLocator 拉取 → 本地 PropertySource
        → 长轮询监听 → 变更推送 → @RefreshScope 刷新 Bean
```

## 4. 依赖边界与 SCA 集成

| 依赖 | 方向 | 说明 |
|------|------|------|
| nacos-client | 必须（starter 传递） | 服务端通信（gRPC + HTTP） |
| spring-cloud-commons | 必须 | DiscoveryClient 抽象（Nacos 是其一实现） |
| spring-cloud-loadbalancer | 注册发现联动 | 实例列表 → 负载均衡（2020 后 Ribbon 移除，必须引） |
| spring-cloud-openfeign | 调用联动 | @FeignClient 按服务名调用 |
| spring-boot-starter-bootstrap | 配置中心可选 | 用 bootstrap.yml 加载 Nacos 配置时需要 |
| spring-cloud-starter-bus | 可选 | 配置变更广播（非必须，Nacos 自带推送） |

> 💡 **依赖边界认知**：Nacos 只提供"地址与配置"，**调用链**（OpenFeign）、**负载均衡**（LoadBalancer）、**路由**（Gateway）是 Spring Cloud 家族其他成员——缺 LoadBalancer 依赖时服务名调用会报 `No instances available`（[09 篇](09-集成地图与常见问题.md) 高频坑）。

## 5. 职责切割：Nacos vs SCA vs 微服务

| 层 | 职责 | 典型 API | 本系列覆盖 |
|----|------|---------|-----------|
| **Nacos Server** | 注册数据存储、配置存储、推送、鉴权、AI Registry | 控制台 + API | 02-08 篇 |
| **nacos-client** | 注册/发现/配置拉取的客户端实现 | NamingService / ConfigService | 03/04 篇原理落点 |
| **SCA 适配** | Spring 自动装配、@RefreshScope、DiscoveryClient 抽象 | discovery/config starter | 03/04/09 篇 |
| **微服务业务** | 服务调用、负载均衡、路由 | OpenFeign / LoadBalancer / Gateway | 09 篇联动 |

### 5.1 典型误判案例

| 现象 | 错误归因 | 正确归因 |
|------|---------|---------|
| 服务调用失败 | "Nacos 没发现" | 注册了没？（控制台）；LoadBalancer 缺依赖？（[09 篇](09-集成地图与常见问题.md)） |
| 配置不刷新 | "Nacos bug" | 缺 @RefreshScope / 缺 config starter / 版本跨大版本（[04 篇](04-配置中心实战速查.md)） |
| 服务列表空 | "Nacos 挂了" | 9848 gRPC 端口没开（2.x 起） |
| 鉴权失败 | "账号错了" | 3.x 默认鉴权开 + 客户端也要配 username/password（[07 篇](07-安全与权限速查.md)） |

> 🎯 一句话：**Nacos 管"注册与配置"，调用成败是"负载均衡 + 超时 + 业务"的锅**——排障从控制台与服务端日志开始，别先怀疑客户端。
