## 1. 部署方式速查（单机/集群/Docker/K8s）

| 方式 | 命令/做法 | 适用 |
|------|----------|------|
| Docker 单机（开发） | `docker run -d --name nacos -p 8848:8848 -p 9848:9848 -e MODE=standalone nacos/nacos-server:v3.2.3` | 本地联调 |
| 二进制单机 | 下载解压 → `startup.sh -m standalone` | 开发/测试 |
| 二进制集群 | `startup.sh -m cluster`（配 cluster.conf） | **生产标配（3 节点）** |
| Docker 集群 | docker-compose 三节点 + Nginx 前置 | 生产（小规模） |
| K8s | Helm Chart（nacos 官方 chart）/ Operator | 云原生生产 |

```bash
# 开发单机（Docker，含鉴权开关）
docker run -d --name nacos -p 8848:8848 -p 9848:9848 \
  -e MODE=standalone \
  -e NACOS_AUTH_ENABLE=true \
  -e NACOS_AUTH_IDENTITY_KEY=serverIdentity \
  -e NACOS_AUTH_IDENTITY_VALUE=nacos123 \
  -e NACOS_AUTH_TOKEN=SecretKey012345678901234567890123456789012345678901234567890123456789 \
  nacos/nacos-server:v3.2.3
```

> ⚠️ **3.x 默认鉴权开启**：`NACOS_AUTH_TOKEN` 必须 ≥ 32 字节（官方示例长度）；开发偷懒可 `NACOS_AUTH_ENABLE=false`，**生产必须开**（[07 篇](07-安全与权限速查.md)）。

## 2. 端口清单与网络要求

| 端口 | 用途 | 必开？ | 说明 |
|------|------|:---:|------|
| **8848** | HTTP 主端口（控制台 + 客户端 HTTP API） | ✅ | 客户端/浏览器访问 |
| **9848** | **gRPC 客户端端口（8848+1000）** | ✅ | **2.x 起客户端主链路，漏开 = 服务列表空** |
| 9849 | gRPC 服务端间通信（8848+1001） | 集群内 | 集群节点互连 |
| 7848 | JRaft 选举/数据同步端口（3.x CP 模式） | 集群内 | CP 模式集群必需 |
| 8849 | 客户端 gRPC 服务（部分版本） | — | 视版本 |

> 🎯 面试必答：**"为什么服务列表为空但 8848 能通？"**——客户端 2.x+ 注册/订阅走 **gRPC（9848）**，只开 8848（HTTP）则"能连控制台但注册不上去/拉不到实例"——**排查网络先 telnet 9848**（[09 篇](09-集成地图与常见问题.md) 排错表）。

## 3. MySQL 持久化配置

**通俗**：默认单机用内嵌 Derby（数据存文件，集群不共享）；生产必须接 MySQL——注册数据与配置都持久化到库，节点重启/故障不丢。

```properties
# conf/application.properties（或环境变量）
spring.datasource.platform=mysql
db.num=1
db.url.0=jdbc:mysql://mysql-host:3306/nacos?characterEncoding=utf8&connectTimeout=1000&socketTimeout=3000&autoReconnect=true&useUnicode=true&useSSL=false&serverTimezone=Asia/Shanghai
db.user.0=nacos
db.password.0=你的密码
```

```bash
# 初始化表结构（首次部署必做）
mysql -u root -p < conf/mysql-schema.sql
```

| 要点 | 说明 |
|------|------|
| 版本支持 | MySQL 5.7+/8.x、PostgreSQL、Oracle、Derby（[00 篇](00-Nacos知识体系总览.md) 3.x 兼容矩阵） |
| 表结构 | 官方 `mysql-schema.sql`（config_info/naming_instance 等核心表） |
| **主从要求** | 集群部署必须 MySQL 主从（读写分离 + 高可用），单实例 MySQL = 单点 |
| 连接池 | Nacos 自带连接池参数（db.pool.*） |
| 数据备份 | 定时备份 MySQL（配置与注册数据都是资产） |

> ⚠️ **MySQL 挂了会怎样**：配置读写失败、注册数据丢失（AP 模式下实例心跳仍能撑一阵）——**生产 Nacos 集群 + MySQL 主从缺一不可**（[06 篇](06-高可用与生产实践速查.md)）。

## 4. 集群部署（3 节点生产标配）

### 4.1 部署骨架

```text
                客户端（服务/消费者）
                      │ 8848/9848
              ┌───────┴────────┐
              │  Nginx（负载/健康检查）│
              └───────┬────────┘
        ┌─────────────┼─────────────┐
   ┌────▼────┐   ┌────▼────┐   ┌────▼────┐
   │ Nacos-1 │   │ Nacos-2 │   │ Nacos-3 │
   └────┬────┘   └────┬────┘   └────┬────┘
        │       JRaft/Distro 数据同步（9849/7848）
        └───────┬───────┘
        ┌───────▼───────┐
        │ MySQL 主从（数据持久化）│
        └───────────────┘
```

### 4.2 步骤速查

```bash
# ① 三台机器各放 conf/cluster.conf（节点 IP:port 列表）
# cluster.conf:
#   192.168.1.10:8848
#   192.168.1.11:8848
#   192.168.1.12:8848

# ② 各节点配置 MySQL（第 3 节）+ 相同 nacos 账号
# ③ 各节点启动（集群模式）
./bin/startup.sh -m cluster

# ④ Nginx 前置（客户端统一入口 + 故障切换）
# upstream nacos { server 192.168.1.10:8848; server 192.168.1.11:8848; server 192.168.1.12:8848; }
```

| 要点 | 说明 |
|------|------|
| 节点数 | **3 节点起步**（JRaft 多数派 = 2/3；2 节点无意义） |
| 一致配置 | 三节点**同一 MySQL**（或主从）+ 同一鉴权配置 |
| 客户端地址 | `server-addr: nacos.example.com:8848`（Nginx）或逗号分隔多地址 |
| 权重 | Nginx 按节点权重/健康检查（3.x 控制台也有节点视角） |
| 升级 | 滚动升级（一次一台，[06 篇](06-高可用与生产实践速查.md) 迁移清单） |

> 🎯 面试必答：**"Nacos 集群为什么至少 3 节点？"**——① 注册默认 AP 模式（Distro）下节点越多容错越高（N-1 挂还能服务）；② **CP 模式（JRaft）需要多数派**：3 节点容忍 1 挂，2 节点挂 1 就废（且脑裂风险）——**3 是性价比拐点**（与 ZK/Raft 类集群同逻辑，[05 篇](05-核心原理：一致性协议速查.md)）。

## 5. 控制台与初始化

```text
访问：http://IP:8848/nacos
默认账号：nacos / nacos（3.x 默认鉴权开，首次登录强制建议改密）
```

| 初始化动作 | 说明 |
|-----------|------|
| 改默认密码 | **必做**（默认账号是公开的） |
| 创建命名空间 | 生产/测试/灰度各一个（ID 自动生成 UUID，**客户端配的是 ID**） |
| 创建配置 | 按 dataId 规范建配置（[04 篇](04-配置中心实战速查.md) dataId 规则） |
| 建账号 + RBAC | 按团队/角色建用户（[07 篇](07-安全与权限速查.md)） |
| 观察服务列表 | 服务注册后在此确认（健康实例数/权重） |

> ⚠️ **namespace 配 ID 不配名字**：控制台里看到的"命名空间名"是人读的，客户端 `namespace:` 配置项填的是**ID（UUID 字符串）**——复制错导致"配置拉不到/服务列表对不上"（[09 篇](09-集成地图与常见问题.md) 高频坑）。

## 6. 常见部署问题排错

| 症状 | 根因 | 排查动作 |
|------|------|---------|
| 控制台打不开 | 8848 没监听/防火墙 | `curl http://IP:8848/nacos`；`netstat -anp | grep 8848` |
| 服务列表空（8848 通） | **9848 gRPC 端口没开** | `telnet IP 9848`（[09 篇](09-集成地图与常见问题.md)） |
| 集群节点互相找不到 | cluster.conf 配置错/7848 未开 | 检查 cluster.conf；日志 `cluster node` |
| 数据不持久 | 没用 MySQL（默认 Derby） | 接 MySQL（第 3 节） |
| 鉴权 403/401 | 3.x 默认鉴权 + 客户端没配账号 | 客户端加 username/password（[07 篇](07-安全与权限速查.md)） |
| 控制台慢/卡 | 单机 + 大流量（单机 Derby 压力） | 升级集群 + MySQL |
| 启动失败（表不存在） | mysql-schema.sql 没初始化 | 执行初始化 SQL（第 3 节） |

> 🎯 排障顺序铁律：**端口（8848/9848）→ 鉴权（账号/Token）→ 持久化（MySQL）→ 集群（节点互连）**——从下往上，部署期问题 80% 在端口与鉴权两层。
