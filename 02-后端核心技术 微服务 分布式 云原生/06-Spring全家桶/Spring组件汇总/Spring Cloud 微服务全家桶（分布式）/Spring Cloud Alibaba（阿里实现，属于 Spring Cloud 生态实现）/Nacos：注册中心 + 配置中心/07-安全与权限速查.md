## 1. 安全风险全景

| 风险 | 场景 | 后果 |
|------|------|------|
| 未鉴权裸奔 | 3.0 前默认无鉴权 / 部署时关掉 | 任何人可读写配置、注销服务（**配置投毒/服务下线**） |
| 默认账号 | nacos/nacos 未改 | 弱口令直接登录 |
| 配置泄露 | 配置含密钥/连接串 | 数据库/Redis 凭据泄露 |
| 服务伪造 | 无鉴权时伪造注册 | 流量打到攻击者实例（数据窃取） |
| 管理接口暴露 | 控制台公网可达 | 全面接管 |

> 🎯 安全认知：**Nacos 是"基础设施中的皇冠"**——拿到 Nacos 控制台 = 拿到全系统的配置与拓扑（数据库地址、密钥、服务清单）——**安全基线是上生产的第一道门槛**。

## 2. 鉴权机制（3.x 默认开启）

### 2.1 服务端开启（3.x 默认，2.x 需手动）

```properties
# conf/application.properties（3.x 默认已开；2.x 手动开）
nacos.core.auth.enabled=true
nacos.core.auth.plugin.nacos.token.secret.key=<Base64 编码的 ≥32 字节密钥>
nacos.core.auth.server.identity.key=serverIdentity
nacos.core.auth.server.identity.value=<随机长字符串>
```

> ⚠️ **密钥要求**：`token.secret.key` 必须 **Base64 编码且解码后 ≥ 32 字节**（官方示例长度）——太短会启动失败/鉴权失效；**集群所有节点必须同一密钥**（否则节点互不认）。

### 2.2 客户端认证（配置中心"静默失败"的根源）

```yaml
spring:
  cloud:
    nacos:
      server-addr: localhost:8848
      username: nacos          # ★ 客户端也要配（3.x 必配）
      password: 你的密码
```

> ⚠️ **静默失败陷阱**：服务端开了鉴权、客户端没配账号——**注册可能成功（部分版本）但配置拉取/刷新静默失败**（无报错、无日志）——**升级 3.x 后配置不生效先查客户端认证配置**（[09 篇](09-集成地图与常见问题.md) 高频坑）。

## 3. RBAC 权限体系

```text
用户（User）──被授予──► 角色（Role）──绑定──► 权限（Resource + Action）
                                                │
                        资源粒度：命名空间/服务/配置（dataId + group）
                        动作：读 / 写 / 删除
```

| 控制台操作 | 说明 |
|-----------|------|
| 用户管理 | 建用户（业务账号，不共享默认账号） |
| 角色管理 | 建角色（admin/developer/viewer） |
| 权限管理 | 角色绑定"资源 + 动作"（如：prod 命名空间配置只读） |
| 命名空间授权 | 按命名空间授权（环境隔离 + 权限隔离） |

| 角色设计（推荐） | 权限 |
|-----------------|------|
| admin | 全部（集群管理） |
| developer | 开发环境全权限 + 生产环境只读 |
| operator | 生产配置读写（变更走审批） |
| viewer | 只读（审计/巡检） |

> 🎯 面试必答：**"Nacos 权限怎么设计？"**——三层：① **命名空间隔离**（环境/租户物理隔离数据）；② **RBAC 角色**（admin/developer/operator/viewer 按职责）；③ **资源级授权**（服务/配置粒度的读写）——**生产环境配置写入走 operator + 变更审计**（与代码发布同等管控）。

## 4. 命名空间隔离与最小权限

### 4.1 隔离模型（安全视角）

```text
命名空间 = 安全边界：
  prod 命名空间 ← 生产账号才有权限（operator）
  test 命名空间 ← 开发账号
  dev  命名空间 ← 开发账号
跨命名空间不可见（数据 + 权限双隔离）
```

| 隔离手段 | 防什么 |
|---------|--------|
| 命名空间 | 测试环境连生产配置/服务（事故源） |
| 分组 | 同环境内业务域误写 |
| RBAC | 越权读写（开发改生产配置） |
| 客户端认证 | 未授权应用接入 |

### 4.2 最小权限原则

| 原则 | 落地 |
|------|------|
| 账号按人/按团队 | 不用共享账号（审计可追溯） |
| 只授所需 | 消费者账号只读、操作账号仅对应环境 |
| 密钥最小化 | 配置里不放密钥（引加密插件/密钥管理） |
| 客户端最小权限 | 服务账号只访问自己的命名空间 |

## 5. TLS 与网络加固

| 手段 | 说明 |
|------|------|
| 控制台 HTTPS | Nginx 前置 TLS（控制台与 API 走 HTTPS） |
| 内网隔离 | Nacos 只在内网（不暴露公网）；跨网走 VPN/专线 |
| 防火墙 | 只放行 8848/9848 到可信客户端网段 |
| 节点间加密 | 3.x 支持 gRPC TLS（按部署环境启用） |
| 客户端 TLS | 客户端连接配置支持 HTTPS（`spring.cloud.nacos.server-addr: https://...`） |

```bash
# 网络加固示例（防火墙）
# 允许：客户端网段 → 8848/9848；集群节点间 8848/9848/7848/9849
# 禁止：公网 → 任何 Nacos 端口
```

> ⚠️ **Nacos 放公网 = 事故**（历史上多起 Nacos 未授权访问导致的配置泄露事件）——**内网部署是底线**，云上部署用安全组/VPC 隔离。

## 6. 安全基线清单

| # | 基线项 | 说明 |
|---|--------|------|
| ① | 改默认密码 | nacos/nacos 必须改（3.x 首次登录提醒） |
| ② | 鉴权开启 | 3.x 默认；2.x 手动开（[第 2 节](#2-鉴权机制3x-默认开启)） |
| ③ | 密钥强度达标 | token.secret.key ≥ 32 字节 + 集群一致 |
| ④ | 客户端配认证 | 所有服务配 username/password（防静默失败） |
| ⑤ | RBAC 落地 | 按角色授权 + 生产写权限收敛 |
| ⑥ | 命名空间隔离 | 环境隔离 + 权限隔离 |
| ⑦ | 内网部署 | 不暴露公网（HTTPS + 防火墙） |
| ⑧ | 密钥不进配置 | 敏感信息加密或外部密钥管理 |
| ⑨ | 升级补丁 | 跟踪安全修复版本（3.2.1 修了 LDAP 绕过；[00 篇](00-Nacos知识体系总览.md) 2.1） |
| ⑩ | 审计日志 | 配置变更/登录审计（谁、何时、改了什么） |

> 🎯 安全自检十问（上线前过一遍）：默认密码改了吗？鉴权开了吗？客户端都配认证了吗？RBAC 落地了吗？环境隔离了吗？内网部署了吗？密钥进配置了吗？补丁到最新了吗？审计有吗？——**十问全过才算"不裸奔"**。
