## 1. 与 SCA 全家桶的集成地图

| 组件 | 联动点 | 要点 |
|------|--------|------|
| **OpenFeign** | 服务调用 | @FeignClient 服务名 → Nacos 发现实例（[03 篇](03-注册中心实战速查.md) 5 节） |
| **LoadBalancer** | 负载均衡 | NacosLoadBalancer 权重支持（`loadbalancer.nacos.enabled=true`） |
| **Gateway** | 网关路由 | 网关按服务名路由下游（Nacos 发现）——"入口先注册到 Nacos" |
| **Seata**（SCA 兄弟） | 分布式事务 | Seata Server 注册到 Nacos；事务分组配置走 Nacos 配置中心（Seata 目录） |
| **Sentinel**（SCA 兄弟） | 流量治理 | 限流规则可持久化到 Nacos 配置中心（动态下发，Sentinel 目录） |
| Spring Cloud Config | 配置中心对照 | Nacos 内建配置中心替代 Config Server（少一套组件） |
| Spring Cloud Bus | 配置广播 | Nacos 自带长轮询推送，**无需 Bus** |
| Spring AI | AI 资源 | MCP/Agent Registry 联动（[08 篇](08-AI时代新能力速查.md)） |

> 🎯 集成总原则：**Nacos 是 SCA 的地基**——注册（所有服务）+ 配置（所有动态参数）+ 规则存储（Sentinel 规则/Seata 配置）——**全家桶组件都往 Nacos 注册/取配置**，一套集群管全家。

## 2. Eureka → Nacos 迁移清单

### 2.1 迁移动作

| # | 动作 | 说明 |
|---|------|------|
| ① | 依赖替换 | 移除 `spring-cloud-starter-netflix-eureka-client` → 加 `spring-cloud-starter-alibaba-nacos-discovery` |
| ② | 配置替换 | `eureka.client.service-url.*` → `spring.cloud.nacos.server-addr`（IP:port 不带 http://） |
| ③ | 注解清理 | 删 `@EnableEurekaClient`（Nacos 自动装配，`@EnableDiscoveryClient` 可留可去） |
| ④ | LoadBalancer | Spring Cloud 2020+ 已移除 Ribbon → 显式引 `spring-cloud-starter-loadbalancer` |
| ⑤ | 配置中心（可选） | 需要动态配置 → 加 `nacos-config` starter（[04 篇](04-配置中心实战速查.md)） |
| ⑥ | 双注册过渡（推荐） | 同时保留 Eureka + Nacos 依赖 → 双注册双订阅 → 稳定后删 Eureka |

```yaml
# 迁移前后对照
# 旧（Eureka）：
eureka:
  client:
    service-url:
      defaultZone: http://eureka:8761/eureka/
# 新（Nacos）：
spring:
  cloud:
    nacos:
      server-addr: localhost:8848
      username: nacos
      password: xxxxx
```

> ⚠️ 迁移注意：① 双注册过渡可能遇 `AutoServiceRegistration` Bean 冲突（需排除配置）；② Eureka 的 `eureka.instance.*`（实例名/租约）语义 → Nacos 的 `discovery.*` 对应项；③ **迁移期间两注册中心都通**（双订阅），切流窗口业务无感。

## 3. 2.x → 3.x 迁移速查

> 完整清单见 [06 篇](06-高可用与生产实践速查.md) 5 节；此处给速查：

| # | 事项 | 速查 |
|---|------|------|
| ① | 版本对齐 | **client 3.x ↔ server 3.x**（SCA 2025.0.x 内置 client 3.0.3） |
| ② | 鉴权 | 3.x 默认开：客户端配 username/password（**不配 = 配置静默失效**） |
| ③ | namespace | 默认 public；自定义 namespace 核对 ID |
| ④ | UDP PUSH | 3.2 移除（依赖的老客户端升级） |
| ⑤ | 节点模型 | 临时/持久节点区分简化 |
| ⑥ | 升级顺序 | 先新集群灰度 → 客户端同步 → 切流 → 下线旧集群 |

## 4. 高频坑排错表

| 症状 | 根因 | 解法 |
|------|------|------|
| 服务列表空（8848 通） | **9848 gRPC 端口没开** | telnet IP 9848；放行端口（[02 篇](02-快速开始与部署速查.md) 2 节） |
| 配置拉不到 | dataId 命名不对 / namespace ID 错 / 缺 file-extension | 控制台核对 dataId 规则（[04 篇](04-配置中心实战速查.md) 1 节） |
| 配置不刷新 | 缺 @RefreshScope / 缺 config starter | 排查清单（[04 篇](04-配置中心实战速查.md) 3.2） |
| 静默不刷新（无报错） | 服务端鉴权开 + 客户端没配账号 | 客户端加 username/password（[07 篇](07-安全与权限速查.md)） |
| `No instances available` | 缺 loadbalancer 依赖 | 引 `spring-cloud-starter-loadbalancer`（[03 篇](03-注册中心实战速查.md) 5 节） |
| 服务名调用 404/超时 | 实例健康但业务问题 | 控制台看健康状态 + 应用日志（Nacos 只给地址） |
| 跨版本配置失效 | client 3.x ↔ server 2.x | 版本对齐（[01 篇](01-模块清单.md) 矩阵） |
| 集群节点不互认 | cluster.conf 错 / 7848 未开 | 检查 cluster.conf + 端口（[02 篇](02-快速开始与部署速查.md) 4 节） |
| 403/401 | 鉴权配置（服务端/客户端） | 服务端密钥一致性 + 客户端账号（[07 篇](07-安全与权限速查.md)） |
| 注册成功但控制台无 | namespace 不一致 | 客户端 namespace ID 与控制台一致（[03 篇](03-注册中心实战速查.md) 3 节） |
| namespace 为空读不到 public 配置 | 已知坑（Issue #4094） | 显式配置 namespace 或升级版本 |
| 启动慢/卡 | 连接 Nacos 超时（server-addr 错） | 检查地址；本地联调可断连重试（客户端有容灾） |

## 5. 测试实践

### 5.1 测试策略

| 场景 | 姿势 | 说明 |
|------|------|------|
| 注册发现集成 | **Testcontainers Nacos 容器** | `GenericContainer("nacos/nacos-server:v3.2.3")` + 动态属性指向容器 |
| 配置刷新 | 测试内调用 Nacos API 改配置 → 断言 @RefreshScope 更新 | 用 Nacos Open API（`/nacos/v1/cs/configs`） |
| 单元测试 | Mock Nacos（不连服务端） | 注册/发现逻辑用 mock |
| 契约测试 | OpenFeign + WireMock | 调用链不依赖真实 Nacos |

```java
// Testcontainers Nacos（集成测试）
@Testcontainers
class NacosIntegrationTest {
    @Container
    static GenericContainer<?> nacos = new GenericContainer<>("nacos/nacos-server:v3.2.3")
            .withExposedPorts(8848, 9848)
            .withEnv("MODE", "standalone");

    @DynamicPropertySource
    static void props(DynamicPropertyRegistry registry) {
        registry.add("spring.cloud.nacos.server-addr",
                () -> nacos.getHost() + ":" + nacos.getMappedPort(8848));
    }
    // 测试：启动服务 → 断言注册（调 Nacos API 查实例）→ 改配置 → 断言刷新
}
```

> ⚠️ 测试三坑：① 容器必须暴露 **9848**（gRPC，只暴露 8848 注册不上）；② 测试改配置要清理（恢复原值，防污染其他用例）；③ 别连生产 Nacos 跑测试（注册污染 + 配置误改）。
