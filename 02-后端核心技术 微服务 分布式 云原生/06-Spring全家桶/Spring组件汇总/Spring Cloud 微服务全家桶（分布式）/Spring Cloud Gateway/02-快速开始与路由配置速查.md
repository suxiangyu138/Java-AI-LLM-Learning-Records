## 1. 环境准备与依赖

### 1.1 版本组合（2026-08 主线）

| 项 | 版本 |
|----|------|
| Spring Boot | **4.0.x/4.1.x** |
| Spring Cloud | **2025.1.x（Oakwood）** |
| Spring Cloud Gateway | **5.0.x**（BOM 锁定） |

### 1.2 依赖（WebFlux 栈，5.0 新坐标）

```xml
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-gateway-server-webflux</artifactId>
</dependency>

<!-- 需要注册中心路由（lb://）时，按你的注册中心加 -->
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-nacos-discovery</artifactId>
</dependency>
<!-- 或 Eureka：spring-cloud-starter-netflix-eureka-client -->

<!-- Actuator（路由管理端点） -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-actuator</artifactId>
</dependency>
```

> 💡 纯转发（固定 uri）不需要注册中心；**lb:// 服务名转发必须配注册中心**。

## 2. 路由四要素

```text
一条 Route = 四要素：
  id        路由唯一标识（管理/日志用）
  uri       转发目标（固定 http://host:port 或 lb://服务名）
  predicates 匹配条件（全部满足才命中，AND 语义）
  filters   命中后的处理链（改写/限流/熔断，可选）
```

| 要素 | 必填 | 示例 | 说明 |
|------|:---:|------|------|
| id | ✅ | `order-service` | 全局唯一，冲突启动报错 |
| uri | ✅ | `lb://order-service` | 转发目标 |
| predicates | ✅（至少一个） | `- Path=/orders/**` | 匹配条件 |
| filters | ❌ | `- StripPrefix=1` | 横切处理 |

> 🎯 心智模型：**路由 = "if (谓词全部满足) 转发到 uri，并执行过滤器链"**——所有网关能力（灰度/限流/熔断/认证）都是"谓词 + 过滤器"的组合。

## 3. yaml 路由定义

### 3.1 基本路由（5.0 前缀）

```yaml
spring:
  cloud:
    gateway:
      server:                # ★ 5.0 新增层级
        webflux:
          routes:
            - id: order-service
              uri: lb://order-service
              predicates:
                - Path=/orders/**
              filters:
                - StripPrefix=1
                - AddRequestHeader=X-Gateway-Env, prod
```

```text
请求：GET /orders/123
  → Path 谓词命中 → StripPrefix 去掉 /orders → AddRequestHeader 加头
  → 转发：lb://order-service/123
```

### 3.2 多路由与匹配语义

```yaml
spring:
  cloud:
    gateway:
      server:
        webflux:
          routes:
            - id: order-service
              uri: lb://order-service
              predicates:
                - Path=/orders/**
                - Method=GET,POST          # ★ 同路由内谓词 AND：路径且方法
            - id: payment-service
              uri: lb://payment-service
              predicates:
                - Path=/payments/**
              filters:
                - StripPrefix=1
            - id: fallback-route
              uri: https://www.example.com  # 固定 URI（不经过注册中心）
              predicates:
                - Path=/legacy/**
```

> ⚠️ **匹配语义**：多个路由之间是**第一个全命中者生效**（按定义顺序）——不是"最精确优先"；路由顺序即优先级（[10 篇](10-生产实践与选型避坑.md) 排序坑）。

### 3.3 谓词/过滤器语法：短式与展开式

```yaml
# 短式（逗号参数，常用）
predicates:
  - Path=/orders/**,/goods/**
  - Header=X-Request-Id, \d+

# 展开式（命名参数，参数多时可读性好）
predicates:
  - name: Path
    args:
      patterns: /orders/**,/goods/**
  - name: Header
    args:
      header: X-Request-Id
      regexp: \d+
```

> 💡 规则：**参数简单的用短式，参数多/含特殊字符用展开式**（如正则含逗号时必须展开式）。

## 4. Java Fluent DSL 路由

### 4.1 用法

```java
@Configuration
public class GatewayRoutes {
    @Bean
    public RouteLocator customRoutes(RouteLocatorBuilder builder) {
        return builder.routes()
                .route("order-service", r -> r
                        .path("/orders/**")
                        .filters(f -> f
                                .stripPrefix(1)
                                .addRequestHeader("X-Gateway-Env", "prod"))
                        .uri("lb://order-service"))
                .route("weighted", r -> r
                        .weight("group1", 8)        // 灰度分流 80%
                        .uri("https://weighthigh.org"))
                .build();
    }
}
```

### 4.2 yaml vs Java 怎么选

| 维度 | yaml | Java DSL |
|------|------|---------|
| 声明式/可视化 | ✅ | ❌ |
| 动态性 | 配 Config 可动态刷新 | 代码编译期固定 |
| 复杂逻辑 | ❌ | ✅（谓词/过滤器可编程） |
| 团队习惯 | 运维友好 | 开发者友好 |
| 适用 | **默认推荐** | 复杂自定义场景 |

> 💡 实践：**路由配置 90% 用 yaml**（可读可审计、可接 Config 动态刷新）；Java DSL 用于 yaml 表达不了的逻辑（动态构造谓词、条件分支）。

## 5. DiscoveryClient 路由

### 5.1 原理

```text
DiscoveryClient 路由定位器：从注册中心拉服务列表 → 为每个服务自动生成路由
  └── 服务 order-service 注册后，网关自动有路由：
      路径 /order-service/** → lb://order-service（服务名作为前缀）
```

### 5.2 配置

```yaml
spring:
  cloud:
    gateway:
      server:
        webflux:
          discovery:
            locator:
              enabled: true            # ★ 开启注册中心自动路由（默认 false）
              lower-case-service-id: true   # 服务名小写（Nacos 服务名大小写敏感时注意）
              # predicates: - Path=/${serviceId}/**    # 默认前缀模式
              # filters: - RewritePath=/${serviceId}/(?<segment>.*), /$\{segment}
```

```text
开启后访问：GET /order-service/orders/1 → 自动路由到 order-service
（默认含 RewritePath 过滤：把 /order-service/ 前缀去掉再转发）
```

### 5.3 显式路由 vs Discovery 路由

| 方式 | 控制力 | 配置量 | 适用 |
|------|--------|--------|------|
| 显式 yaml 路由 | 强（精细谓词/过滤器） | 每服务一段 | **生产推荐** |
| Discovery 自动路由 | 弱（统一前缀模式） | 零配置 | 开发环境、服务多不想维护 |

> ⚠️ Discovery 自动路由的坑：**所有服务暴露同一前缀模式**，无法按服务定制谓词/过滤器；生产建议"显式路由为主 + Discovery 为辅"。

## 6. lb:// 负载均衡转发

### 6.1 lb:// 前缀

```yaml
uri: lb://order-service     # ★ lb:// = 从注册中心解析服务名，负载均衡转发
# 对比：
uri: http://localhost:8081  # 固定地址（无注册中心参与）
uri: https://api.example.com # 外部服务
```

### 6.2 负载均衡策略（Spring Cloud LoadBalancer）

```yaml
spring:
  cloud:
    loadbalancer:
      configurations: [default]        # 默认轮询
      # 策略切换：
      # - random（随机）
      # - round-robin（轮询，默认）
      # - retry（重试版）
      # 自定义：spring.cloud.loadbalancer.<服务名>.ribbon.enabled=false + @LoadBalancerClient 配置
```

| 策略 | 说明 | 适用 |
|------|------|------|
| 轮询（默认） | 均匀分配 | 通用 |
| 随机 | 随机分配 | 压测/混合负载 |
| 重试 | 失败自动换实例重试 | 有瞬断场景 |
| 自定义（同机房优先等） | @LoadBalancerClient 实现 | 复杂路由策略 |

> 🎯 面试必答：**"lb:// 是什么？"**——**负载均衡协议前缀**：网关看到 lb:// 就把服务名交给 Spring Cloud LoadBalancer，由它向注册中心（Nacos/Eureka）查实例列表并按策略选择目标——**lb:// 是网关与注册中心+负载均衡集成的桥梁**。

## 7. 三步验证与排障

### 7.1 验证清单

| 步骤 | 做法 | 预期结果 |
|------|------|---------|
| ① 路由加载 | GET /actuator/gateway/routes | 路由列表（含 order-service 及谓词/过滤器定义） |
| ② 转发成功 | GET /orders/1（下游在跑） | 返回下游数据（日志可见转发） |
| ③ 匹配隔离 | GET /orders/1（下游停掉） | 500/超时（路由命中但下游不可达）→ 熔断/重试过滤器生效场景 |
| ④ 未匹配 | GET /unknown/** | 404（谓词没命中，网关不转发） |

### 7.2 排障起点

| 现象 | 大概率原因 | 处理 |
|------|-----------|------|
| 404 | 谓词没匹配上 / 路由没加载 | 查 /actuator/gateway/routes；核对 Path 模式 |
| 500 / Service Unavailable | 路由命中但下游不可达 / lb:// 服务名错 | 查注册中心服务名；curl 下游直连验证 |
| 转发 404 | 路径没剥干净（多级路径） | StripPrefix 数量不对（/orders/1 → StripPrefix=1 → /1） |
| 路由冲突 | 两条路由 id 相同 / 谓词重叠 | 启动日志有路由重复警告；调整顺序 |
| lb:// 解析失败 | 注册中心没连上 / 服务未注册 | 查 Nacos/Eureka 服务列表 |

> 💡 排障第一招：**`/actuator/gateway/routes` 看路由存不存在 → 404 归谓词、500 归下游**——这两类错误码把排查范围切开一半（[10 篇](10-生产实践与选型避坑.md) 也有）。
