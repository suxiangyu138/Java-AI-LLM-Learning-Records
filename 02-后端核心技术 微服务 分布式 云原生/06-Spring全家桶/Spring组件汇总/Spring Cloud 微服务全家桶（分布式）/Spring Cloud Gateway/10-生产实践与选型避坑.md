## 1. 网关接入清单

| 流量类型 | 过网关？ | 说明 |
|---------|:---:|------|
| 外部客户端（App/Web） | ✅ | 主战场 |
| 第三方开放 API | ✅ | 统一认证+限流+计费 |
| 内部服务间调用（Feign） | ❌ | 直连注册中心（网关绕行=性能损耗） |
| 定时任务/批处理 | ❌ | 内部触发，不需要网关 |
| WebSocket | ⚠️ | 网关支持但注意长连接资源（WebsocketRoutingFilter） |
| 静态资源 | ⚠️ | 大静态资源建议 CDN/Nginx 前置 |

> 🎯 边界原则：**"外部进，网关收；内部走，Feign 直"**——网关是门面不是总线，所有流量绕网关会变成单点瓶颈。

## 2. 坑位表：10 大高频坑

| # | 坑 | 现象 | 解决 |
|---|-----|------|------|
| 1 | **路由顺序错误** | 宽泛路由先定义，精确路由永远不命中 | 精确在前、兜底在后（[03 篇](03-路由谓词工厂速查.md)） |
| 2 | **StripPrefix 段数不对** | 转发 404 / 路径多前缀 | 数清谓词段：/orders/1 → StripPrefix=1 → /1 |
| 3 | **RewritePath 的 `$` 未转义** | 替换路径为 null | yaml 写 `$\{segment}`（[04 篇](04-过滤器工厂全景（上）.md)） |
| 4 | **Add 与 Set 混用** | 头被追加成两个值 | 覆盖用 SetRequestHeader，追加用 Add |
| 5 | **限流没配 key-resolver** | 所有请求共一把锁（互相误伤） | 按 IP/用户/接口配 KeyResolver（[07 篇](07-网关级限流与熔断.md)） |
| 6 | **多实例本地限流** | 3 实例 = 3 倍上限 | 用 Redis 共享桶 |
| 7 | **fallbackUri 配了外部 URL** | 兜底不生效 | 只能用 forward:/本地端点（[05 篇](05-过滤器工厂全景（下）与全局过滤器.md)） |
| 8 | **WebFlux 里写阻塞代码** | 压测吞吐骤降/线程耗尽 | 事件循环里禁阻塞；用 publishOn 或 WebMVC 栈（[06 篇](06-核心原理：WebFlux 处理链路.md)） |
| 9 | **重试写接口** | 下游重复提交 | 只重试 GET；写接口靠幂等或下游重试 |
| 10 | **5.0 用旧 starter/旧前缀** | 启动 deprecation 警告/属性不生效 | 换新 starter + 新前缀（[01 篇](01-模块清单与版本矩阵.md)） |

> 💡 排障口诀：**"404 归谓词，500 归下游，429 归限流，504 归超时"**——先按状态码切分范围，再进 [10.3 排查法](#3-全链路排查法) 分段定位。

## 3. 全链路排查法

### 3.1 四段排查

| 段 | 验证 | 手段 |
|----|------|------|
| ① 路由存在 | 路由加载了吗 | `/actuator/gateway/routes`（列表 + 谓词/过滤器 JSON） |
| ② 谓词命中 | 请求匹配了吗 | 未命中=404；命中但下游错=5xx |
| ③ 转发目标 | lb:// 解析对了吗 | 注册中心服务列表；`/actuator/gateway/routes/{id}` 看 uri |
| ④ 过滤链 | 哪个过滤器出错 | 网关日志（过滤器名在堆栈）；逐个移除过滤器二分定位 |

### 3.2 状态码速查

| 状态码 | 含义 | 排查方向 |
|--------|------|---------|
| 404 | 谓词未命中 / 路由不存在 | 路由表、Path 模式 |
| 429 | 限流拒绝 | 限流参数、key-resolver |
| 5xx | 转发后下游错误 | 下游服务、过滤器异常 |
| 504 | 网关/下游超时 | response-timeout、下游慢 |
| 401/403 | 认证/授权拦截 | 认证过滤器、TokenRelay |

### 3.3 调试技巧

```yaml
logging:
  level:
    org.springframework.cloud.gateway: DEBUG    # 过滤器链执行日志
```

> 💡 网关 DEBUG 日志会打出每个过滤器执行与路由匹配细节——**疑难问题先开 DEBUG，别猜**。

## 4. vs Nginx/Kong：选型对比

### 4.1 对比表

| 维度 | Spring Cloud Gateway | Nginx | Kong |
|------|---------------------|-------|------|
| 语言/生态 | Java/Spring | C/Lua | OpenResty（Lua） |
| 定位 | 应用层 API 网关 | 高性能反向代理/LB | API 网关（插件化） |
| 路由模型 | 谓词+过滤器（Spring 语义） | location 配置 | 插件链 |
| 动态路由 | ✅（Actuator/Redis 共享） | ❌ 改配置 reload | ✅（Admin API） |
| 注册中心集成 | ✅ 原生（lb://） | ❌ | 插件 |
| 限流 | ✅ Redis 令牌桶 | ⚠️ 模块级 | ✅ 插件 |
| 熔断降级 | ✅ CircuitBreaker 过滤器 | ❌ | ⚠️ 插件 |
| 认证 | ✅ 自定义/Spring Security | ⚠️ 脚本 | ✅ 插件 |
| 性能 | 高（Netty/虚拟线程） | **极高**（C 核心） | 高 |
| 运维 | Java 应用 | 轻量进程 | 需管理面（DB/控制台） |
| 适用 | **Java 微服务生态** | 静态/边缘/前置代理 | 异构服务 API 网关 |

### 4.2 架构分工（生产常见形态）

```text
互联网入口
  │
  ▼
Nginx（边缘层：静态资源、证书、四层/七层分发、DDoS 基础防护）
  │
  ▼
Spring Cloud Gateway（应用层：路由、认证、限流熔断、灰度）
  │
  ▼
微服务（注册中心路由 lb://）
```

> 🎯 面试必答：**"网关和 Nginx 什么关系？"**——**不是替代关系，是分层配合**：Nginx 擅长**边缘层**（极致性能、静态资源、基础安全），Spring Cloud Gateway 擅长**应用层**（Spring 语义路由、注册中心动态发现、限流熔断、认证）——生产常见 Nginx 前置 + Gateway 后置的组合；小规模纯 Java 生态只用 Gateway 也成立。

### 4.3 选型建议

| 场景 | 选 |
|------|-----|
| Java 微服务生态 + 需要熔断限流认证 | **Spring Cloud Gateway** |
| 边缘代理/静态/证书终结 | Nginx |
| 异构多技术栈统一入口 | Kong（插件生态） |
| 云原生（K8s） | Ingress/Envoy（与 K8s 原生） |
| 国内 SCA 生态 | 基于 Gateway + Nacos（或 SCA 网关整合） |

## 5. 升级路径：4.3.x → 5.0.x（双栈迁移）

### 5.1 升级必要性判断

| 现状 | 判断 |
|------|------|
| 2025.0.x（Boot 3.5）+ Gateway 4.3.x | **建议升级**：Northfields OSS 已结束（2026-06-30） |
| 2024.0.x（Boot 3.4）+ Gateway 4.2.x | **建议升级**：Moorgate EOL |
| 2023.0.x（Boot 3.2/3.3）+ Gateway 4.1.x | 计划升级 |
| Boot 2.7 + Gateway 3.1.x | 先规划 Boot 升 4（大工程） |

### 5.2 升级 Checklist（双栈迁移）

```text
□ 1. 选栈：WebFlux（保持原样）或 WebMVC（想换编程模型才选，见 09 篇）
□ 2. 换依赖：
     spring-cloud-starter-gateway → spring-cloud-starter-gateway-server-webflux（或 -webmvc）
□ 3. 换属性前缀（可加 spring-boot-properties-migrator 辅助）：
     spring.cloud.gateway.* → spring.cloud.gateway.server.webflux.*
□ 4. 核对过滤器差异（MVC 迁移时）：JsonToGrpc/LocalResponseCache 等 WebFlux 独有过滤器
□ 5. 核对自定义代码：
     - 自定义 GatewayFilter/GlobalFilter（WebFlux API）
     - 自定义谓词工厂
     - WebFlux 独有 API（Mono/Flux 签名）
□ 6. 回归验证：
     - 路由表 /actuator/gateway/routes
     - 谓词匹配（404 语义）
     - 限流（429 行为与 Redis 桶）
     - 熔断 fallback（CircuitBreaker + fallbackUri）
     - 转发链路（lb://、StripPrefix、RewritePath）
□ 7. 新特性体验：Framework Retry 过滤器、API Versioning 谓词（5.0 新增）
```

### 5.3 升级风险提示

| 风险 | 说明 |
|------|------|
| 版本错配启动失败 | 2025.1 compatibility verifier 直接拒启动 |
| 属性前缀不迁移 | 配置静默不生效（无报错，路由全空）——**升级后第一件事查 routes 端点** |
| 旧 starter 警告 | 功能可用但未来移除，别留 |
| WebMVC 迁移范围 | 过滤器差异 + 自定义代码重写（不是换依赖就完事） |
| JSpecify/API 变化 | 自定义扩展类可能编译期警告（泛型 null 语义） |

> 🎯 升级心法：**"先跑通最小路由，再迁移全部路由"**——新栈 + 一条测试路由验证 → 逐条迁移 → 压测回归；不要一次性改完再启动（路由问题好定位，配置问题全黑）。
