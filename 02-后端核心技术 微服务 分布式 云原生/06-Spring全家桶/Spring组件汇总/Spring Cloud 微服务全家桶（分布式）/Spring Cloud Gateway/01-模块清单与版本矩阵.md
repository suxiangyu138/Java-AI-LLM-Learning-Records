## 1. 5.0 双栈拆分：模块体系重构

### 1.1 为什么拆

```text
背景：Spring Boot 4 / Framework 7 时代，Java 21 虚拟线程成熟
  ├── WebFlux（非阻塞/Netty）：高性能但编程模型复杂（响应式学习曲线）
  ├── WebMVC（阻塞/Servlet）：编程简单，但传统每请求一线程扛不住高并发
  └── 虚拟线程：让"阻塞式代码"也能接近非阻塞的高并发性能
      → 官方把 Gateway 拆成两个 starter，开发者按技术栈选择
```

| 栈 | starter | 运行时 | 编程模型 | 适用 |
|----|---------|--------|---------|------|
| **WebFlux** | `spring-cloud-starter-gateway-server-webflux` | Reactor Netty | 响应式 | 原有 Gateway 用户（默认迁移路径） |
| **WebMVC** | `spring-cloud-starter-gateway-server-webmvc` | Servlet + 虚拟线程 | 传统阻塞式 | 团队不熟响应式、现有 MVC 基建 |

> 🎯 一句话：**Gateway 5.0 = "同一条路由模型，两套运行时"**——路由/谓词/过滤器概念一致，starter 与属性前缀分开。

### 1.2 拆分对应关系

```text
旧（4.x）                          新（5.0）
spring-cloud-gateway-server      →  spring-cloud-gateway-server-webflux
                                     spring-cloud-gateway-server-webmvc
spring-cloud-starter-gateway     →  spring-cloud-starter-gateway-server-webflux
（废弃，deprecation 警告）           spring-cloud-starter-gateway-server-webmvc
spring-cloud-gateway-proxy-exchange → spring-cloud-gateway-proxyexchange-webflux
                                     spring-cloud-gateway-proxyexchange-webmvc
```

> ⚠️ **旧 starter 还能用吗？**——能（5.0 起打 deprecation 警告），**未来版本移除**；新项目必须用新坐标，存量项目升级时顺手迁移（[10 篇](10-生产实践与选型避坑.md) 升级路径）。

## 2. 模块组成与新旧坐标对照

### 2.1 完整模块清单（5.0.2）

| 模块 | 类型 | 职责 | 引入方 |
|------|------|------|--------|
| **spring-cloud-starter-gateway-server-webflux** | starter | WebFlux 网关（原 starter 的继任者） | WebFlux 网关项目 |
| **spring-cloud-starter-gateway-server-webmvc** | starter | WebMVC 网关（5.0 新增） | WebMVC 网关项目 |
| spring-cloud-starter-gateway-proxyexchange-webflux | starter | Proxy Exchange 响应式嵌入式代理 | WebFlux 应用内代理 |
| spring-cloud-starter-gateway-proxyexchange-webmvc | starter | Proxy Exchange MVC 嵌入式代理 | MVC 应用内代理 |
| spring-cloud-gateway-server-webflux | 核心库 | 路由模型 + WebFlux 实现（谓词/过滤器工厂） | 传递依赖 |
| spring-cloud-gateway-server-webmvc | 核心库 | 路由模型 + MVC 实现 | 传递依赖 |
| spring-cloud-starter-gateway | 废弃 starter | 老坐标（WebFlux 语义） | 迁移期 |
| spring-cloud-gateway-server | 废弃模块 | 老模块名 | 迁移期 |

### 2.2 官方坐标（5.0.2）

```xml
<!-- WebFlux 栈（推荐默认） -->
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-gateway-server-webflux</artifactId>
</dependency>

<!-- WebMVC 栈（5.0 新增，虚拟线程） -->
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-gateway-server-webmvc</artifactId>
</dependency>

<!-- 版本管理：Spring Cloud BOM（不写 version） -->
<dependencyManagement>
    <dependency>
        <groupId>org.springframework.cloud</groupId>
        <artifactId>spring-cloud-dependencies</artifactId>
        <version>2025.1.2</version>
        <type>pom</type><scope>import</scope>
    </dependency>
</dependencyManagement>
```

> ⚠️ **别同时引两个 starter**：WebFlux 与 WebMVC 栈互斥（一个应用一种运行时）；误引会启动冲突（容器类型无法确定）。

## 3. 属性前缀迁移

### 3.1 新旧前缀对照

| 旧（4.x） | 新（5.0） | 适用 |
|-----------|----------|------|
| `spring.cloud.gateway.*` | `spring.cloud.gateway.server.webflux.*` | WebFlux 栈 |
| `spring.cloud.gateway.mvc.*` | `spring.cloud.gateway.server.webmvc.*` | WebMVC 栈 |
| `spring.cloud.gateway.proxy-exchange.*` | 拆分到两个栈前缀 | Proxy Exchange |

### 3.2 迁移示例

```yaml
# 4.x（旧前缀）
spring:
  cloud:
    gateway:
      routes:
        - id: order
          uri: lb://order-service

# 5.0（新前缀：只多一层 server.webflux）
spring:
  cloud:
    gateway:
      server:
        webflux:
          routes:
            - id: order
              uri: lb://order-service
```

### 3.3 平滑迁移工具

```xml
<!-- 加 properties-migrator：启动时打印旧前缀警告并自动迁移 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-properties-migrator</artifactId>
</dependency>
```

> 💡 迁移三步：**① 换 starter 坐标；② 加 migrator 看警告；③ 按警告改前缀后移除 migrator**——警告列表就是迁移清单。

## 4. 版本兼容矩阵（2026-08）

### 4.1 Gateway ↔ Spring Cloud ↔ Boot（权威组合）

| Spring Cloud | Gateway | Boot | JDK | 备注 |
|--------------|---------|------|-----|------|
| **2025.1.x（Oakwood）** | **5.0.x（5.0.2）** | **4.0.x/4.1.x** | 17+（21 虚拟线程） | **当前主线**；双栈拆分 |
| 2025.0.x（Northfields） | 4.3.x（4.3.5） | 3.5.x | 17 | OSS 已于 2026-06-30 EOL |
| 2024.0.x（Moorgate） | 4.2.x（4.2.7） | 3.4.x | 17 | EOL |
| 2023.0.x（Leyton） | 4.1.x（4.1.9） | 3.2.x/3.3.x | 17 | EOL |
| 2022.0.x（Kilburn） | 4.0.x | 3.0.x/3.1.x | 8/11/17 | 老存量（Boot 3 首线） |
| 2021.0.x（Jubilee） | 3.1.x | 2.6.x/2.7.x | 8/11 | 老存量（javax） |
| 2020.0.x（Ilford） | 3.0.x | 2.4.x/2.5.x | 8 | 老存量 |
| Hoxton | 2.x | 2.2.x/2.3.x | 8 | 废弃（WebFlux 首线） |

> 💡 Gateway 与 Config 一样**没有跳版**：4.3.x（Northfields）→ 5.0.x（Oakwood）正常进位。

### 4.2 快速对齐口诀

| 场景 | 推荐组合 |
|------|---------|
| 新项目（Boot 4） | Spring Cloud 2025.1.x + Gateway 5.0.x + **新 starter** |
| 存量 Boot 3.5 网关 | Gateway 4.3.x（**OSS EOL，尽快升级**） |
| 存量 4.x 网关升 5.0 | 换 starter + 改前缀（见第 3 节，别只改版本号） |
| 老 Boot 2.7 网关 | Gateway 3.1.x（先升 Boot 全家桶） |

## 5. 5.0 新特性清单

| 新特性 | 说明 | 出处 |
|--------|------|------|
| **WebFlux/WebMVC 双栈** | 模块/ starter 拆分，WebMVC + 虚拟线程 | issue #3858 |
| **Framework Retry 过滤器** | 基于 Spring Framework 7 retry 的新重试过滤器 | issue #3970 |
| **API Versioning 谓词** | Server WebFlux 新增版本路由谓词 | issue #3864 |
| JSpecify null-safety | 全公共 API 标注 | #3944/#3953 |
| Bucket4jRateLimiter | 桶式限流支持 | 发布说明 |
| gRPC JSON 处理 | 换 Google 库 | #3853 |
| Proxy Exchange 双栈 | proxyexchange-webflux / -webmvc 拆分 | 发布说明 |
| 旧 starter 废弃 | 打警告，未来移除 | 发布说明 |

> 🎯 5.0 心智：**版本号是 5.0，但真正的迁移量在"starter 坐标 + 属性前缀"**——代码级 API（谓词/过滤器工厂名）基本不变。

## 6. 模块选型建议

| 场景 | 推荐 | 理由 |
|------|------|------|
| 原有 WebFlux 网关 | `server-webflux`（直接迁移） | 原行为不变，只换坐标+前缀 |
| 新项目、团队不熟响应式 | `server-webmvc`（5.0 新） | 阻塞式编程 + 虚拟线程性能（[09 篇](09-WebMVC网关与ProxyExchange（5.0新特性）.md)） |
| 应用内轻量代理 | proxyexchange 双栈 starter | 不需要独立网关进程时（[09 篇](09-WebMVC网关与ProxyExchange（5.0新特性）.md)） |
| 需要限流熔断 | server-webflux/webmvc + 对应过滤器 | RequestRateLimiter/CircuitBreaker 内置（[07 篇](07-网关级限流与熔断.md)） |
| SCA 生态 | 基于 Gateway + Nacos 集成 | 注册中心换 Nacos 即可（Discovery 路由） |
