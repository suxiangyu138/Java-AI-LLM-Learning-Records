## 1. 过滤器模型：路由级横切

```text
GatewayFilter = 命中路由后的"处理单元"，按配置顺序组成链
  └── 作用范围：只作用于配置它的路由
  └── 对照 GlobalFilter：作用于所有路由（见 05 篇）

示例（一条路由的过滤器链）：
filters:
  - AddRequestHeader=X-Gateway, prod      # ① 加头
  - StripPrefix=1                         # ② 剥路径
  - AddRequestParameter=source, gw        # ③ 加参数
  - SetStatus=200                         # ④ 改状态码
按顺序执行（可配置 order 控制）
```

| 维度 | 说明 |
|------|------|
| 数量 | 一条路由可配多个过滤器 |
| 顺序 | 默认按配置顺序；可用 `order` 属性调整 |
| 失败 | 过滤器抛异常 → 500（除非有熔断/兜底） |
| 对照 | 谓词决定"进不进"，过滤器决定"怎么处理" |

> 🎯 心智模型：**过滤器 = 请求/响应在网关的"加工流水线"**——每一站改一个维度（头/路径/体/状态），改完转发。

## 2. 头部类：Add / Set / Remove / Map / Rewrite

### 2.1 AddRequestHeader / AddResponseHeader（追加）

```yaml
filters:
  - AddRequestHeader=X-Gateway-Env, prod       # 请求头（不存在才加？No：追加/覆盖）
  - AddRequestHeadersIfNotPresent=X-Trace-Id, gw-123   # ★ 只有不存在时才加
  - AddResponseHeader=X-Gateway-Version, 5.0.2  # 响应头
```

| 过滤器 | 语义 | 用途 |
|--------|------|------|
| AddRequestHeader | 追加请求头（同键追加，值可多段） | 网关标识、环境标记 |
| AddRequestHeadersIfNotPresent | 不存在才加 | 透传默认值（不覆盖客户端传入） |
| AddResponseHeader | 追加响应头 | 网关版本、Cache-Control |

> ⚠️ **Add 的"追加"语义**：同键已有值时 **Add 会追加第二个值**（不是覆盖）——要覆盖用 SetRequestHeader！

### 2.2 SetRequestHeader / SetResponseHeader（覆盖）

```yaml
filters:
  - SetRequestHeader=X-Env, prod        # 覆盖请求头（有则改、无则加）
  - SetResponseHeader=X-Frame-Options, DENY
```

### 2.3 RemoveRequestHeader / RemoveResponseHeader（删除）

```yaml
filters:
  - RemoveRequestHeader=X-Internal-Token     # ★ 剥离内部头（安全）
  - RemoveResponseHeader=Server
```

> 💡 安全实践：**下游不需要的内部头（内网凭证、调试头）在网关剥掉**——客户端→网关的敏感信息不进下游。

### 2.4 MapRequestHeader / RewriteRequestHeader

```yaml
filters:
  - MapRequestHeader=X-Original-Auth, X-Auth-Token   # 把 X-Original-Auth 的值复制到 X-Auth-Token
  - RewriteRequestHeader=X-Env, prod, prd            # 正则替换：prod → prd
```

## 3. 参数类：AddRequestParameter / RemoveRequestParameter / RewriteRequestParameter

```yaml
filters:
  - AddRequestParameter=source, gateway       # ★ 加查询参数（拼到 URL）
  - RemoveRequestParameter=secret             # 删参数
  - RewriteRequestParameter=page, \\d+, 10    # 正则替换参数值
```

```text
GET /orders/1 → 加 source=gateway → GET /orders/1?source=gateway
```

> 💡 典型用途：**链路标识透传**（网关加 trace 参数）、**平台来源标记**（source 参数区分 App/Web）、**敏感参数剥离**。

## 4. 路径类：StripPrefix / PrefixPath / RewritePath / SetPath / SetRequestHostHeader

### 4.1 StripPrefix（剥前缀，最常用）

```yaml
filters:
  - StripPrefix=1        # 剥掉最前面的 1 段路径
```

```text
GET /orders/1 → 剥 1 段 → GET /1        （转发到 order-service 的 /1）
GET /orders/detail/1 → StripPrefix=2 → GET /1
```

> ⚠️ **剥几段想清楚**：`/orders/**` 命中后，`StripPrefix=1` 把 `/orders` 剥掉——**转发路径 = 谓词路径后面的部分**；剥多了下游 404，剥少了重复前缀。

### 4.2 PrefixPath（加前缀）

```yaml
filters:
  - PrefixPath=/api
```

```text
GET /orders/1 → 加 /api → GET /api/orders/1
```

> 💡 典型用途：**下游要求统一前缀**（所有接口 /api 开头）时网关统一补。

### 4.3 RewritePath（正则重写，最强）

```yaml
filters:
  - RewritePath=/orders/(?<segment>.*), /api/orders/$\{segment}
```

```text
GET /orders/123 → 正则捕获 → /api/orders/123
```

| 特点 | 说明 |
|------|------|
| 正则捕获组 | `(?<name>...)` 命名捕获 |
| 替换引用 | `$\{name}`（注意 yaml 里 `$` 要转义写成 `$\{`） |
| 与 StripPrefix 区别 | StripPrefix 只剥固定段数；RewritePath 任意正则变换 |

> ⚠️ **yaml 转义坑**：RewritePath 的 `$\{segment}` 在 yaml 里 `$` 后必须 `{` 转义（`$\{`），否则 Spring 占位符解析出错——**写错的表现是替换后路径为 null**（[10 篇](10-生产实践与选型避坑.md) 坑位表）。

### 4.4 SetPath（整体替换）

```yaml
filters:
  - SetPath=/api/{segment}      # {segment} 引用 Path 谓词提取的变量
```

```text
GET /orders/123（Path=/orders/{segment}）→ SetPath=/api/{segment} → /api/123
```

### 4.5 SetRequestHostHeader

```yaml
filters:
  - SetRequestHostHeader=order.internal.com    # 覆盖转发时的 Host 头
```

> 💡 典型用途：**下游按 Host 头做虚拟主机路由**（Nginx 场景）时网关统一设置。

## 5. 响应类：SetStatus / RedirectTo / 响应头类

### 5.1 SetStatus（改状态码）

```yaml
filters:
  - SetStatus=201          # 强制返回 201
  - SetStatus=BAD_GATEWAY  # 或枚举名
```

> 💡 典型用途：**兜底路由统一返回码**（熔断/维护路由返回 503 而非 200）、**测试模拟**。

### 5.2 RedirectTo（重定向）

```yaml
filters:
  - RedirectTo=302, https://example.com/new-path
```

```text
命中该路由 → 302 重定向到指定地址
```

> 💡 典型用途：**旧域名/旧路径迁移**（301 永久跳转）、**登录跳转**（302）。

### 5.3 响应头汇总

```yaml
filters:
  - RewriteLocationResponseHeader=LOCATION, /legacy/, /new/   # 重写 Location 头（重定向场景）
  - DedupeResponseHeader=Access-Control-Allow-Origin, RETAIN_FIRST   # 去重响应头（CORS 场景，见 05 篇）
```

## 6. 内容类：ModifyRequestBody / ModifyResponseBody / RequestSize / RequestHeaderSize

### 6.1 ModifyRequestBody（改请求体）

```java
// 编程式（Java DSL 或 @Bean 自定义过滤器）
@Bean
public RouteLocator modifyBodyRoutes(RouteLocatorBuilder builder) {
    return builder.routes()
            .route("modify-body", r -> r
                    .path("/orders/**")
                    .filters(f -> f.modifyRequestBody(String.class, String.class,
                            (exchange, body) -> Mono.just(body.replace("old", "new"))))
                    .uri("lb://order-service"))
            .build();
}
```

| 要点 | 说明 |
|------|------|
| 泛型 | (入参类型, 出参类型, 转换函数) |
| 响应式 | 返回 Mono（非阻塞） |
| 场景 | 请求体加密/解密、脱敏、格式转换 |

### 6.2 ModifyResponseBody（改响应体）

```java
.route("modify-resp", r -> r
        .path("/orders/**")
        .filters(f -> f.modifyResponseBody(String.class, String.class,
                (exchange, body) -> Mono.just(body + "<!-- gw-modified -->")))
        .uri("lb://order-service"))
```

> 💡 典型用途：**响应体脱敏（手机号/身份证）、统一包装（{code,data} 格式）、HTML 注入**。

### 6.3 RequestSize（请求体积限制）

```yaml
filters:
  - name: RequestSize
    args:
      maxSize: 5MB          # 超限返回 413 Payload Too Large
```

> 💡 安全用途：**防大请求体 DoS**（上传接口单独放大、普通接口限制 1-5MB）。

### 6.4 RequestHeaderSize（请求头体积限制）

```yaml
filters:
  - name: RequestHeaderSize
    args:
      maxSize: 8KB
```

> 💡 安全用途：**防超大头 DoS**（Header 放大攻击）。

## 7. 重试类：Retry 过滤器

### 7.1 用法（5.0 起基于 Framework Retry）

```yaml
filters:
  - name: Retry
    args:
      retries: 3                        # 最多重试 3 次
      statuses: SERVICE_UNAVAILABLE,GATEWAY_TIMEOUT   # 按响应码重试
      methods: GET
      exceptions: java.io.IOException, java.util.concurrent.TimeoutException  # 按异常重试
      backoff:                          # 退避策略
        firstBackoff: 100ms
        maxBackoff: 1000ms
        factor: 2.0
        basedOnPreviousValue: true
```

### 7.2 重试策略要点

| 规则 | 说明 |
|------|------|
| 只重试幂等请求 | **GET 默认**；POST/PUT 重试有重复提交风险（除非下游幂等） |
| 按状态码 | 5xx（服务端错误）可重试；4xx 绝不重试 |
| 按异常 | 连接异常/超时可重试；业务异常不重试 |
| 退避 | 指数退避 + 随机抖动（防重试风暴） |
| 与熔断组合 | 重试在外、熔断在内（先重试后熔断，[05 篇](05-过滤器工厂全景（下）与全局过滤器.md)） |

> ⚠️ **重试放大效应**：网关 100 请求 × 3 重试 = 下游 300 请求——**重试必须配退避 + 只重试瞬时故障**；下游已挂时重试=雪上加霜（此时靠熔断过滤器，不是重试）。

## 8. 过滤器速查总表

| 过滤器 | 作用 | 面试价值 |
|--------|------|:---:|
| AddRequestHeader / AddRequestHeadersIfNotPresent | 加请求头 | ★★ |
| SetRequestHeader / SetResponseHeader | 覆盖头 | ★★ |
| RemoveRequestHeader / RemoveResponseHeader | 删头（安全） | ★★★ |
| MapRequestHeader | 头复制 | ★ |
| RewriteRequestHeader / RewriteLocationResponseHeader | 头正则改写 | ★ |
| AddRequestParameter / RemoveRequestParameter / RewriteRequestParameter | 查询参数增删改 | ★★ |
| **StripPrefix** | 剥路径前缀 | ★★★ |
| PrefixPath | 加路径前缀 | ★★ |
| **RewritePath** | 正则重写路径 | ★★★ |
| SetPath | 整体替换路径 | ★★ |
| SetRequestHostHeader | 覆盖 Host 头 | ★ |
| SetStatus | 改状态码 | ★★ |
| RedirectTo | 重定向 | ★★ |
| ModifyRequestBody / ModifyResponseBody | 体改写（Java） | ★★★ |
| RequestSize / RequestHeaderSize | 体积限制 | ★★ |
| **Retry** | 转发重试 | ★★★ |

> 🎯 面试组合拳：**"网关怎么保证安全？"**——**RemoveRequestHeader 剥内部头 + RequestSize/RequestHeaderSize 限体积 + SecureHeaders 安全头 + 限流熔断**（[05 篇](05-过滤器工厂全景（下）与全局过滤器.md)）+ TLS（[08 篇](08-高级特性速查.md)）——四层防护各管一段。
