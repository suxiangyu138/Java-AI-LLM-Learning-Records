## 1. 集成地图：与全家桶的衔接

### 1.1 与 Spring Boot / Framework 的关系

```text
Spring Boot 4.x（自动配置）
  ├─ spring.elasticsearch.* 属性 → 客户端与模板 Bean
  ├─ @EnableElasticsearchRepositories → Repository 扫描
  └─ 启动引导：索引初始化、审计、实体回调

Spring Framework 7.x（底层）
  ├─ DI：所有组件可注入（Operations/Client/Repository）
  ├─ AOP：@Retryable 等可作用于 ES 调用（重试幂等场景）
  └─ 生命周期：IndexOperations 的创建时机由 Bean 生命周期驱动
```

| 集成点 | 用法 | 说明 |
|--------|------|------|
| 配置属性 | `spring.elasticsearch.*` | 见 [02 篇](02-快速开始与连接配置速查.md) |
| 审计 | `@EnableElasticsearchAuditing` + `@CreatedDate` | 自动维护创建/修改时间 |
| 实体回调 | `BeforeConvertCallback` 等 | 写前转换钩子（如自动补 ID/向量） |
| 事件 | Spring 事件 + `@TransactionalEventListener` | 注意：ES 无事务，事务事件对 ES 写入**不适用** |
| 重试 | `@Retryable`（连接超时/瞬时错误） | 幂等场景可用，非幂等慎用 |
| 监控 | Micrometer + 客户端 metrics | 连接池、请求耗时打点 |

> ⚠️ **最常见错误认知**：给 ES 写入方法加 `@Transactional`——**ES 不支持事务**，注解不会生效（不报错但毫无意义），还会给人虚假的安全感。ES 数据一致性靠"幂等 ID + 覆盖写 + 版本号"，不是事务。

### 1.2 与 Spring Data 其他组件的混用模式

| 组合 | 典型架构 | 数据流 |
|------|---------|--------|
| JPA + ES（最常见） | MySQL 主数据 + ES 搜索 | 写 MySQL → 同步 ES（CDC/MQ/双写） |
| MyBatis + ES | 同 JPA 模式 | 同上 |
| ES + Redis | 搜索 + 缓存 | 热搜索结果缓存 Redis |
| WebFlux + 响应式 ES | 全响应式网关/搜索 | Mono/Flux 全链路 |

```java
// JPA + ES 双写的经典服务模式（注意：先主库后 ES，失败补偿）
@Service
public class ProductService {
    private final ProductJpaRepository jpa;      // 主数据（MySQL）
    private final ProductEsRepository es;        // 搜索（ES）

    @Transactional                                // 事务只作用于 MySQL
    public void create(Product p) {
        jpa.save(p);                              // ① 主库落盘
        es.save(p);                               // ② 同步 ES（失败要补偿/重试）
    }
}
```

> 🎯 **主从一致性三方案**：① 双写 + 重试（简单，有窗口期）；② 本地消息表/事务消息（可靠，代码多）；③ **CDC 订阅 binlog 同步 ES**（解耦，生产主流，方案细节见 `03-消息队列/` 目录的消费实践与 [消息队列理论与实战](../../../../03-消息队列/消息队列理论与实战/00-消息队列知识体系总览.md) 相关篇）。**架构上永远让 MySQL 当唯一事实源，ES 是可重建的索引副本**。

## 3. 中文搜索实战（IK 分词）

### 3.1 完整落地步骤

```bash
# ① ES 服务端安装 IK 插件（版本必须与 ES 一致）
bin/elasticsearch-plugin install https://get.infini.cloud/elasticsearch/analysis-ik/9.4.2

# ② 验证分词效果
curl -X POST 'localhost:9200/_analyze' -H 'Content-Type: application/json' \
  -d '{"analyzer": "ik_max_word", "text": "智能手机壳"}'
# 期望输出：智能 / 手机 / 手机壳 / 机壳...
```

```java
// ③ Java 侧声明分词器（03 篇 3.3 节）
@Document(indexName = "product")
public class Product {
    @Field(type = FieldType.Text,
           analyzer = "ik_max_word",        // 索引：最细粒度
           searchAnalyzer = "ik_smart")     // 搜索：较粗粒度（查得准）
    private String name;
}
```

| 坑 | 现象 | 解法 |
|----|------|------|
| 插件版本不匹配 | 启动报错/analyzer 找不到 | 插件版本 = ES 版本 |
| 未安装插件但声明 analyzer | `Analyzer [ik_max_word] not found` | 插件装 ES 服务端，不是 Java 依赖 |
| 只用 ik_max_word | 短查询召回差 | searchAnalyzer 用 ik_smart |
| 专有名词拆错 | "深度学习"拆成"深/度/学/习" | IK 自定义词典（`IKAnalyzer.cfg.xml`） |
| 拼音/错别字 | 搜"shouji"查不到"手机" | pinyin 插件 + copyTo 字段 |

> 💡 **中文搜索质量三件套**：IK 分词（默认）+ 自定义词典（业务名词）+ searchAnalyzer=ik_smart；进阶（同义词、拼音）见 [04-ELK-02 分词器](../../../../04-ELK/Elasticsearch/02-ES倒排索引与分词器.md)。

## 4. 15 个高频坑速查

### 4.1 连接与配置类

| # | 坑 | 现象/根因 | 解法 |
|---|----|----------|------|
| 1 | ES 9 默认安全未配 | `security_exception` / 连接被拒 | 配 username/password 或开发环境关 xpack（02 篇） |
| 2 | 版本错配 | `NoClassDefFoundError: co/elastic/clients/...` | SDE 6.x ↔ ELC 9.x ↔ ES 9（01 篇） |
| 3 | 超时默认太短 | 高并发下 `ConnectTimeoutException` | restclient.connect-timeout 调大（02 篇） |
| 4 | CA 证书没配 | `unable to verify the first certificate` | SSL bundle / 指纹（02 篇 5.2） |
| 5 | Legacy RestClient 迁移 | 5.x 代码 6.x 编译失败 | 回调改 `rest5_client.Rest5Clients`（01 篇） |

### 4.2 映射与写入类

| # | 坑 | 现象/根因 | 解法 |
|---|----|----------|------|
| 6 | 字段类型不可改 | `mapper_parsing_exception` | 别名重建索引（03 篇 5.1） |
| 7 | Text 字段排序/聚合 | `Fielddata is disabled on text fields` | .keyword 子字段（03 篇） |
| 8 | 数组对象拍平 | 组合条件交叉命中 | Nested（03 篇 3.2） |
| 9 | save 部分更新丢字段 | 覆盖写把其他字段清空 | update + doc/script（05/06 篇） |
| 10 | 并发写丢更新 | 同文档 read-modify-write | script + retryOnConflict（06 篇 7.1） |
| 11 | save 后查不到 | refresh 延迟（默认 1s） | 理解近实时语义；需要强可见用 refresh 控制 |
| 12 | 金额精度 | double 存钱误差 | scaled_float（03 篇） |

### 4.3 查询与性能类

| # | 坑 | 现象/根因 | 解法 |
|---|----|----------|------|
| 13 | 深分页报错 | `Result window is too large` | search_after / scroll（06 篇 5） |
| 14 | 高亮丢失 | 返回 List 而非 SearchHits | 返回类型改 SearchHits（04/05 篇） |
| 15 | 用户输入特殊字符 | query_string 语法异常 | 输入转义 / 用 match（04 篇） |

> 🎯 **三个"改都改不掉"的认知坑**：① mapping 类型改不了（重建索引）；② dims 改不了（重建索引）；③ 深分页上限绕不开（换方案）——这三条是 ES 的设计护栏，别浪费时间对抗，顺着设计走。

## 5. 排错三板斧与日志清单

### 5.1 排错三板斧（按顺序）

```text
① 连通性：curl http://localhost:9200  → 通不通？认证？版本？
② 传输日志：trace 看真实 DSL       → 请求发对没有？服务端响应什么？
③ 引擎侧验证：Kibana 重放 DSL      → 查询语义对不对？分词对不对？
```

| 现象 | 第几斧 | 命中后 |
|------|:---:|--------|
| 连不上/认证失败 | ① | 02 篇第 8 节报错速查 |
| 查询结果不对 | ②③ | 拿 DSL 去 Kibana Dev Tools 重放对比 |
| 性能慢 | ③ | `_profile` API 分阶段分析 |

### 5.2 生产日志配置建议

```yaml
logging:
  level:
    org.springframework.data.elasticsearch: info     # 生产默认
    # 排查期临时开：
    # org.springframework.data.elasticsearch.core: debug
    # co.elastic.clients.transport.rest5_client.low_level.Request: trace（排查完必须关）
```

| 关注指标 | 工具 |
|---------|------|
| 请求耗时/错误率 | Micrometer + Grafana（ES 客户端自带 metrics） |
| 连接池状态 | 客户端 metrics（active/queued connections） |
| 慢查询 | ES 服务端 slowlog（04-ELK-06 篇） |
| 集群健康 | `_cluster/health` / Kibana Monitoring |

## 6. 面试高频考点清单

| 考点 | 一句话答法 | 深挖方向 |
|------|-----------|---------|
| SDE 与原生客户端区别 | 抽象层（Repository/模板/映射）+ 全能力逃生舱 NativeQuery | 01 篇第 4 节 |
| 派生方法如何工作 | 方法名解析 → 查询对象 → ELC Query → HTTP | 04 篇第 1/2 节 |
| 三类查询选型 | 简单 Criteria、复杂 Native、String 不用 | 05 篇第 1 节 |
| 为什么 ES 不能当主库 | 无事务、近实时、更新是删+写 | 00 篇 1.2 |
| save vs update | save 覆盖、update 字段级/脚本原子 | 05/06 篇 |
| 深分页方案 | scroll 快照导出、search_after 实时翻页 | 06 篇第 5 节 |
| 聚合原理 | 桶分组 + 指标统计，一次请求 | 06 篇第 1 节 |
| ES 做向量库行不行 | 行，kNN+HNSW+混合检索，已有集群首选 | 07 篇第 1 节 |
| 混合检索 | BM25 语义盲区 + kNN 关键词盲区 → RRF 融合 | 07 篇第 4 节 |
| 换 Embedding 模型代价 | dims 锁死 → 重建索引 | 07 篇 2.1 |
| 中文搜索怎么做 | IK + max_word/smart + 词典 | 08 篇第 3 节 |
| 版本矩阵 | 6.x ↔ ES 9；5.x ↔ ES 8（已停维护） | 01 篇第 5 节 |

> 🎯 **面试开场白模板**：Spring Data Elasticsearch 是 Spring Data 家族对接 ES 的数据访问组件——Repository 方法名/注解生成查询，Operations 模板做动态查询，NativeQuery 透传全能力（聚合、kNN）；底层走 elasticsearch-java 9 客户端。深度追问（倒排索引、评分、集群）自然引到 04-ELK 体系闭环。
