### 1.1 引入方式速查

| 方式 | 写法 | 说明 |
|------|------|------|
| Boot starter（推荐） | `spring-boot-starter-data-elasticsearch` | 自动引入 SDE + ELC + Jackson + Boot 自动配置 |
| Maven 显式 | `org.springframework.data:spring-data-elasticsearch:6.1.x` | 非 Boot 项目或精确控制 |
| Gradle | `implementation 'org.springframework.data:spring-data-elasticsearch'` | 由 Boot BOM 管版本 |
| Boot 4 BOM | 不写版本号 | `spring-boot-dependencies` 统一管理 |

```xml
<!-- Boot 4 项目最小依赖 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-elasticsearch</artifactId>
</dependency>
<!-- 需要 @EnableElasticsearchRepositories 等价物：Boot 自动配置已开启 Repository 扫描 -->
```

> ⚠️ **版本协调三原则**：① 永远跟 Boot BOM 走，不手写 SDE 版本；② SDE 6.x 必须配 elasticsearch-java 9.x（starter 自动带，别混 8.x 客户端）；③ ES 服务端版本与客户端小版本无需逐字相同，但**大版本必须一致**（6.x 组件 ↔ ES 9 集群，5.x 组件 ↔ ES 8 集群）。

## 2. 包结构地图

```text
org.springframework.data.elasticsearch
├── annotations                              # ★ 映射与查询注解
│   ├── Document / Id / Field / Mapping / Setting / Indexed
│   ├── Query / SearchTemplateQuery / Aggregation
│   ├── FieldType（Text/Keyword/Date/Dense_Vector/Nested...）
│   └── KnnAlgorithmType / KnnSimilarity / Dynamic / WriteTypeHint
├── core.query                               # ★ 查询对象
│   ├── Criteria / CriteriaQuery             # 链式类型安全查询
│   ├── StringQuery / BaseQuery / Query 接口
│   └── HighlightQuery / Sort / SourceFilter / IndexBoost / RuntimeField
├── client.elc                               # ★ ELC（Elasticsearch Java Client）桥接
│   ├── ElasticsearchConfiguration / ReactiveElasticsearchConfiguration
│   ├── ElasticsearchClients / ClientConfiguration
│   ├── NativeQuery / NativeQueryBuilder    # 直传 ELC 原生 Query
│   ├── Aggregation / AggregationContainer  # 聚合封装
│   └── rest_client（Legacy，弃用）/ rest5_client（6.x 默认，含 Rest5Clients）
├── repository
│   ├── ElasticsearchRepository / ReactiveElasticsearchRepository
│   └── ElasticsearchRepositoryFactoryBean
├── core
│   ├── ElasticsearchOperations             # ★ 编程式模板总接口
│   ├── DocumentOperations / SearchOperations / IndexOperations  # 4.0 拆分
│   ├── ElasticsearchTemplate / ReactiveElasticsearchTemplate
│   └── IndexCoordinates（索引坐标，4.0 起显式传参）
├── document
│   ├── Document / SimpleElasticsearchDocument  # 文档模型
│   └── SearchHit / SearchHits / SearchPage    # 搜索结果封装
├── core.convert
│   ├── ElasticsearchEntityMapper           # ★ 实体映射器（4.0 起默认）
│   ├── MappingElasticsearchConverter

├── support
│   └── ElasticsearchExceptionTranslator / 实体回调 / 审计
└── reactive
    └── ReactiveElasticsearchOperations / ReactiveElasticsearchTemplate / ReactiveIndexOperations
```

**高频面试点名类**：`ElasticsearchOperations`、`DocumentOperations`/`SearchOperations`/`IndexOperations`、`ElasticsearchTemplate`、`NativeQuery`、`CriteriaQuery`、`ElasticsearchEntityMapper`、`ClientConfiguration`。

### 2.1 三操作域的职责分工（4.0 起的核心设计）

| 接口 | 职责 | 代表方法 |
|------|------|---------|
| `DocumentOperations` | 文档级读写（不涉及搜索） | `save`、`get`、`delete`、`bulkIndex`、`count` |
| `SearchOperations` | 搜索/聚合 | `search`、`searchForPage`、`aggregate`、`scroll`、`searchWithHits` |
| `IndexOperations` | 索引生命周期 | `create`、`putMapping`、`aliases`、`refresh`、`exists` |
| `ElasticsearchOperations` | 三域的统一门面（继承前两者 + `opsForIndex()`） | 一键获得三类操作 |

> 🎯 **面试锚点**："为什么 4.0 拆分 Operations？"——职责单一：写、查、建索引是三类生命周期完全不同的操作，拆开后 IndexOperations 可为响应式单独实现（`ReactiveIndexOperations`），也避免了老版接口"什么都有但什么都难扩展"的问题。查询总入口仍是一个 Bean（`ElasticsearchOperations`），业务代码无感。

### 2.2 三类查询对象的选择（面试高频）

| 查询对象 | 类型安全 | 能力边界 | 适用 |
|---------|:---:|---------|------|
| `CriteriaQuery` | ✅（Java 链式） | 常规匹配/范围/存在；无法表达聚合/kNN | 简单条件查询、动态拼接 |
| `StringQuery` | ❌（JSON 字符串） | 全部 DSL，但不检查语法 | 简单固定 JSON、快速原型 |
| `NativeQuery` | ✅（ELC builder） | **全部 DSL**：聚合、kNN、高亮、建议器、字段折叠 | 复杂查询、聚合、向量检索（主力） |

> 💡 选型口诀："**简单用 Criteria，复杂用 Native**"——StringQuery 只有"懒"这一个理由，生产代码尽量不写裸 JSON 字符串。

### 2.3 高频类职责速查表

| 类 | 包 | 职责 | 面试出镜率 |
|----|----|------|:---:|
| `ElasticsearchOperations` | core | 编程式查询统一门面 | ★★★★★ |
| `NativeQuery` | client.elc | 直传 ELC 原生查询（聚合/kNN） | ★★★★★ |
| `CriteriaQuery` | core.query | 链式条件查询 | ★★★★ |
| `ElasticsearchRepository` | repository | 声明式仓库接口 | ★★★★ |
| `ElasticsearchEntityMapper` | core.convert | 实体 ↔ ES 文档映射 | ★★★★ |
| `IndexOperations` | core | 索引生命周期管理 | ★★★ |
| `SearchHit`/`SearchHits`/`SearchPage` | document | 搜索命中封装（高亮/分数） | ★★★ |
| `ClientConfiguration` | client.elc | 连接配置（认证/SSL/超时） | ★★★ |
| `IndexCoordinates` | core | 显式索引坐标（4.0 起必传） | ★★★ |
| `ElasticsearchTemplate` | core | 老版模板（仍可用，内部委托 Operations） | ★★ |

> 🎯 **记法**：`Operations`（门面）→ `Template`（实现）→ `CriteriaQuery/NativeQuery`（入参）→ `SearchHits`（出参），一条链就是一次搜索的完整数据流。

## 3. 依赖边界

| 依赖 | 方向 | 说明 |
|------|------|------|
| `spring-data-commons` | 依赖 | Repository/Pageable/审计等 Spring Data 公共契约 |
| `spring-core` / `spring-beans` / `spring-context` | 依赖 | 容器、类型转换、事件 |
| `elasticsearch-java`（co.elastic.clients） | **被依赖（核心）** | 9.x，NativeQuery 的 Query/Aggregation 类型来源 |
| `elasticsearch-rest-client` | 可选（Legacy） | 仅旧 RestClient 路径需要；6.x 起不推荐 |
| Jackson | 依赖 | JSON 序列化（EntityMapper 底层） |
| `reactor-core` | 可选 | 响应式模板 |
| Boot starter | 依赖 | `spring-boot-starter-data-elasticsearch` 聚合以上 |

> 🎯 **核心要点**：**spring-data-elasticsearch 自己不实现 HTTP 传输**——真正的网络通信由 `elasticsearch-java`（自带 Rest5Client）完成；SDE 的价值全在"注解解析 + 查询翻译 + 结果映射"这一层，去掉它你用原生客户端也能连 ES，只是所有样板代码要自己写。

### 3.1 依赖边界常见疑问

**Q1：`elasticsearch-java` 和 `spring-data-elasticsearch` 什么关系？**
ELC 是 ES 官方 Java 客户端（TypeScript 风格 builder，覆盖全部 REST API）；SDE 构建在它之上，把 Repository/注解模型翻译成 ELC 调用。**NativeQuery 里的 Query/Aggregation 类型全部来自 ELC**——所以 SDE 的版本必须与 ELC 大版本同步（6.x ↔ ELC 9.x）。

**Q2：为什么还需要 `elasticsearch-rest-client`（Legacy）？**
6.x 默认 Rest5Client 不需要它；只有当你要用弃用的旧 RestClient（`ElasticsearchLegacyRestClientConfiguration`）或直接注入 `RestClient` 时，才需要显式加依赖并排除 `commons-logging`。新代码一律不用。

**Q3：与 spring-data-commons 的版本怎么对齐？**
发行列车统一管理：2026.0 列车中 commons 3.x ↔ SDE 6.1.x 同步发版。Boot BOM 会一起管住，混用不同列车版本会出 `NoSuchMethodError`。

**Q4：响应式要不要额外依赖？**
要。`ReactiveElasticsearchTemplate` 依赖 reactor-core——`spring-boot-starter-data-elasticsearch` 会传递引入；纯命令式项目可排除，但一般没必要。

> ⚠️ **依赖排查提醒**：启动报 `NoClassDefFoundError: co/elastic/clients/...` 或 `NoSuchMethodError`，90% 是 SDE 与 elasticsearch-java 版本错配（例如 SDE 5.x + ELC 9.x）——先 `mvn dependency:tree -Dincludes=co.elastic.clients,org.springframework.data` 看实际版本。

### 3.2 依赖树实战（Boot 4 + SDE 6.x）

```text
mvn dependency:tree -Dincludes=org.springframework.data,co.elastic.clients

org.springframework.boot:spring-boot-starter-data-elasticsearch
├─ org.springframework.data:spring-data-elasticsearch:6.1.x
│   ├─ org.springframework.data:spring-data-commons:3.x
│   ├─ co.elastic.clients:elasticsearch-java:9.4.x        ← 原生客户端（核心）
│   │   └─ org.elasticsearch.client:elasticsearch-rest-client:9.4.x（Rest5Client 内部依赖）
│   ├─ com.fasterxml.jackson.core:jackson-databind
│   └─ io.projectreactor:reactor-core（响应式）
└─ org.springframework.boot:spring-boot-autoconfigure（ES 自动配置）
```

**依赖问题的三种典型形态：**

| 形态 | 现象 | 处理 |
|------|------|------|
| 缺 starter | `NoSuchBeanDefinitionException: ElasticsearchOperations` | 加 starter 依赖 |
| 客户端版本错配 | 启动/首次查询抛 `NoClassDefFoundError` 或方法签名错误 | dependency:tree 定位，统一到 BOM 版本 |
| 多客户端共存 | 类路径同时有 ELC 8 和 9 | 排除旧版本（`mvn dependency:tree` 逐级排查） |

## 4. 职责切割：SDE vs elasticsearch-java vs ES 引擎

| 维度 | spring-data-elasticsearch | elasticsearch-java | ES 引擎（服务端） |
|------|--------------------------|--------------------|------------------|
| 定位 | 数据访问抽象 | 官方客户端 | 分布式搜索引擎 |
| 提供 | Repository/注解/模板/映射 | 全量 REST API builder | 倒排索引/分词/评分/聚合执行 |
| 查询表达 | 方法名/@Query/Criteria/Native | Query builder | JSON DSL 执行器 |
| 结果处理 | 自动映射 POJO、SearchHit 封装 | 返回 ELC 类型/JsonData | 原始 JSON 响应 |
| 状态管理 | 无状态（每次调用） | 连接池 | 分片、段、translog |
| 代表能力 | 声明式开发体验 | 类型安全的全 API 覆盖 | 搜索与分析能力本体 |

> 💡 面试画图题："一次 Spring Data ES 查询走了哪几层？"——**业务方法 → Repository/Template（SDE）→ ELC 客户端 → Rest5Client HTTP → ES 引擎 → 反序列化回 POJO**，五层链路，任何一层版本错配都会在某一环爆掉。

### 4.1 一次搜索请求的完整链路

```text
repository.findByNameContaining("手机")
  → ElasticsearchRepositoryImpl（SDE）
    → 方法名解析：findByNameContaining → match 查询（+ 分词器）
    → ElasticsearchOperations.search(CriteriaQuery, Product.class, IndexCoordinates)
      → ElasticsearchTemplate → ELC ElasticsearchClient.search()
        → Rest5Client → HTTP POST /product/_search
          → ES 引擎：倒排索引匹配 → 打分 → 返回 JSON
    ← SearchHits<Product>（自动映射 + 分数/高亮）
```

**各层"翻译"了什么：**

| 层 | 翻译动作 | 失败症状 |
|----|---------|---------|
| Repository 方法名 | 方法名 → 查询语义（and/or/containing...） | 方法名解析异常（拼写错） |
| SDE 模板 | 查询对象 → ELC Query | 类型不兼容/索引缺失 |
| ELC 客户端 | Query → HTTP JSON | 连接超时/认证失败 |
| ES 引擎 | JSON → 倒排匹配 | mapping 不匹配（字段类型冲突） |

> 🎯 **抽象记忆**：SDE 是"翻译官"，ELC 是"信使"，ES 引擎是"大脑"——翻译官译错（查询语义理解错）、信使迷路（网络/认证）、大脑答非所问（mapping/分词错），三种故障症状完全不同，排错先定位层。

### 4.2 职责切割的面试话术

**画图题标准答法（30 秒版）：**

| 层 | 代表 | 一句话 |
|----|------|--------|
| 抽象层 | Repository / ElasticsearchOperations | 把"查询意图"表达为 Java 对象 |
| 翻译层 | ElasticsearchEntityMapper / QueryConverters | 实体与查询 → ELC 类型 |
| 传输层 | ElasticsearchClient / Rest5Client | 类型安全地发 HTTP 请求 |
| 引擎层 | ES 集群 | 倒排索引执行与打分 |

**追问应对：**

1. "为什么 NativeQuery 的参数类型是 `co.elastic.clients...Query`？"——SDE 复用 ELC 的查询模型而非自造一套，避免 DSL 能力被二次阉割；这是 4.4 起的设计取向（"薄封装、全能力"）；
2. "Spring Data JPA 与它结构上差在哪？"——JPA 之上有 Hibernate 做 ORM 与事务，ES 无事务、无关系模型，SDE 的映射器只做"文档 ↔ POJO"，不做级联和脏检查；
3. "换 ES 版本要改什么？"——大版本换代换整个 SDE 线（5.x→6.x），小版本跟随列车点版本（6.0.x→6.1.x）；业务代码若只用标准 API（Repository/Operations），迁移成本集中在客户端配置与个别弃用 API。

> 🎯 **一句话收尾**：职责切割的本质是"把 ES 复杂 DSL 折叠成 Java 开发体验，同时保留全能力逃生舱（NativeQuery）"——常用路径舒服，极端路径不堵死。

## 5. 版本兼容速查

| 发行列车 | Spring Data ES | Elasticsearch | Framework | Boot 配套 | 状态 |
|----------|---------------|---------------|-----------|-----------|------|
| 2026.0 | 6.1.x | 9.4.2 | 7.0.x | 4.1.x | **当前** |
| 2025.1 | 6.0.x | 9.2.2 | 7.0.x | 4.0.x | Stable |
| 2025.0 | 5.5.x | 8.18.1 | 6.2.x | 3.5.x | 停止维护 |
| 2024.1 | 5.4.x | 8.15.5 | 6.1.x | 3.4.x | 停止维护 |
| 2024.0 | 5.3.x | 8.13.4 | 6.1.x | 3.3.x | 停止维护 |
| 2021.2 | 4.4.x | 7.17.3 | 5.3.x | 2.7.x | 停止维护 |

> ⚠️ **升级提示（5.5.x → 6.0.x 关键动作）**：① 迁移客户端配置回调：`ElasticsearchClients` → `rest5_client.Rest5Clients`；② 弃用包中的旧 RestClient 代码迁到 `client.elc.rest_client` 确认并逐步替换；③ `ScriptType` → `ScriptData`；④ `UpdateQuery.ifSeqNo/ifPrimaryTerm` 改 `Long`——**业务代码若只用 Repository/Operations 标准 API，升级工作量很小**，这是 6.x 线的设计承诺。

### 5.1 升级顺序建议

```text
① 先升 ES 集群 8 → 9（按 ES 官方升级手册，注意 9.x 移除 typed_keys 等兼容入口）
② 升 Spring Boot 4.x + SDE 6.x（BOM 统一）
③ 编译期修复：弃用包引用、ScriptType、UpdateQuery 字段类型
④ 回归测试：查询结果、高亮、聚合、kNN 向量检索全量验证
```

| 检查项 | 5.x 表现 | 6.x 表现 |
|--------|---------|---------|
| 默认传输客户端 | RestClient（elasticsearch-rest-client） | Rest5Client（ES Java client 9+ 内置） |
| 客户端配置类包 | `client.elc.ElasticsearchClients` | `client.elc.rest5_client.Rest5Clients` |
| 空值注解 | JetBrains @Nullable | JSpecify |
| ScriptType | 枚举（INLINE/STORED） | ScriptData record |
| UpdateQuery 版本字段 | Integer | Long |

> 💡 **兼容策略一句话**：SDE 6.x 对标准 API 几乎零迁移成本，工作量集中在"客户端配置回调迁移 + ES 9 集群升级"两项；建议先用 Docker 起 ES 9 做影子验证再动生产。
