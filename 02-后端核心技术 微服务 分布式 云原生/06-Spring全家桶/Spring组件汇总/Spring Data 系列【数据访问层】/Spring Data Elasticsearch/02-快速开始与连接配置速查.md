## 1. 三步起项目

**① 依赖**（Boot 4.x BOM 管版本）：

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-elasticsearch</artifactId>
</dependency>
```

**② 配置**（application.yml，最简开发配置）：

```yaml
spring:
  elasticsearch:
    uris: http://localhost:9200
```

**③ 验证**（注入两个 Bean 即可用）：

```java
@RestController
public class PingController {
    private final ElasticsearchOperations operations;   // 高级模板
    private final ElasticsearchClient client;           // 原生客户端（co.elastic.clients）

    public PingController(ElasticsearchOperations operations, ElasticsearchClient client) {
        this.operations = operations;
        this.client = client;
    }

    @GetMapping("/es/ping")
    public boolean ping() {
        try {
            return client.ping().value();               // 底层走 Rest5Client
        } catch (IOException e) {
            return false;
        }
    }
}
```

> 🎯 **最小心智模型**：Boot 自动配置只需 `uris` 一个属性就能装配全套——`ElasticsearchClient`、`ElasticsearchOperations`、`ElasticsearchRepository`、`ReactiveElasticsearchOperations`（类路径有 reactor 时）。其余全是"按需定制"。

### 1.1 自动配置帮你干了什么（Boot 视角）

```text
spring.elasticsearch.uris
  → ElasticsearchClientAutoConfiguration
      → ElasticsearchClient（ELC 9.x 顶层客户端，默认 Rest5Client 传输）
      → JsonpMapper（Jackson 序列化）
  → ElasticsearchDataAutoConfiguration
      → ElasticsearchEntityMapper / ElasticsearchConverter
  → ElasticsearchRepositoriesAutoConfiguration
      → 扫描 @EnableElasticsearchRepositories 等价注解下的 Repository 接口
  → ElasticsearchRestClientAutoConfiguration（Legacy 路径，6.x 弃用）
```

> 💡 启动日志里搜 `ElasticsearchClient` 和 `ElasticsearchRepositories` 两行"ConditionalOn..."，可确认自动配置是否全部生效——排查"Repository 为空 / 模板 Bean 缺失"的第一步。

### 1.2 常见自动配置"没生效"的三种原因

| 现象 | 原因 | 处理 |
|------|------|------|
| `NoSuchBeanDefinitionException: ElasticsearchOperations` | 依赖没引入 starter | 检查 pom |
| Repository 接口没被扫描 | 接口没在启动类同包/子包 | 调整包结构或用 `@EnableElasticsearchRepositories(basePackages=...)` |
| 启动超时/连不上 | uris 写错或 ES 未启动 | curl 验证 9200；ES 9 默认 https+安全，开发环境显式关或配认证 |

## 2. 客户端选型：Rest5Client vs Legacy RestClient

| 维度 | Rest5Client（默认，6.x） | RestClient（Legacy，弃用） |
|------|--------------------------|---------------------------|
| 来源 | ES Java client 9+ 内置传输 | `org.elasticsearch.client:elasticsearch-rest-client` |
| 状态 | **默认/推荐** | 6.0 起标记弃用 |
| 配置回调包 | `org.springframework.data.elasticsearch.client.elc.rest5_client.Rest5Clients` | `org.springframework.data.elasticsearch.client.elc.rest_client.RestClients` |
| 依赖 | 无需额外声明 | 需显式加依赖 + 排除 commons-logging |
| 注入类型 | `Rest5Client` | `RestClient` |
| 新代码选择 | ✅ 永远选它 | ❌ 只有存量迁移场景 |

```java
// Legacy 路径（仅存量代码需要）额外依赖：
<dependency>
    <groupId>org.elasticsearch.client</groupId>
    <artifactId>elasticsearch-rest-client</artifactId>
    <version>${elasticsearch-client.version}</version>
    <exclusions>
        <exclusion>
            <groupId>commons-logging</groupId>
            <artifactId>commons-logging</artifactId>
        </exclusion>
    </exclusions>
</dependency>
```

> ⚠️ **升级提醒**：从 5.x 迁移到 6.x 时，`ElasticsearchClients` 的静态方法（如 `ElasticsearchClients.ElasticsearchRestClientConfigurationCallback`）已不在，改从 `rest5_client.Rest5Clients` 取同名回调——搜索代码里 `ElasticsearchClients` 出现处即需修改。

## 3. Spring Boot 自动配置属性速查

```yaml
spring:
  elasticsearch:
    uris: https://es1:9200,https://es2:9200   # 集群地址列表（默认 http://localhost:9200）
    username: elastic                          # 基本认证用户名
    password: ${ES_PASSWORD}                   # 基本认证密码（敏感信息用环境变量）
    path-prefix: ela                           # 反向代理路径前缀（多个集群共享入口时）
    # ⚠️ 以下两个在 Boot 3.4+ 弃用，改用 restclient.*：
    # connection-timeout: 5s
    # socket-timeout: 3s
    restclient:
      connect-timeout: 5s                      # 连接超时（默认 1s）
      read-timeout: 30s                        # 读取超时（默认 30s）
      ssl:
        bundle: es-trust                       # 引用 SSL bundle（见第 5 节）
```

| 属性 | 默认值 | 说明 |
|------|--------|------|
| `spring.elasticsearch.uris` | `http://localhost:9200` | 逗号分隔的集群地址 |
| `spring.elasticsearch.username` / `password` | 空 | Basic Auth（ES 安全开启时必需） |
| `spring.elasticsearch.path-prefix` | 空 | URL 路径前缀 |
| `spring.elasticsearch.restclient.connect-timeout` | 1s | 连接超时（Boot 3.4+ 新属性） |
| `spring.elasticsearch.restclient.read-timeout` | 30s | 读超时（Boot 3.4+ 新属性） |
| `spring.elasticsearch.restclient.ssl.bundle` | 空 | SSL bundle 名称 |
| `spring.elasticsearch.connection-timeout` / `socket-timeout` | — | **弃用**（Boot 3.4+），勿用于新代码 |

> ⚠️ **无 api-key 属性**：Boot 不提供 `spring.elasticsearch.api-key` 配置项——API key 认证只能走编程式 `ClientConfiguration`（见第 5 节）。此外 `connection-timeout`/`socket-timeout` 在 Boot 3.4 起被 `restclient.connect-timeout`/`restclient.read-timeout` 取代，Boot 4 中旧属性已无效。

## 4. ClientConfiguration 编程式配置

Boot 属性覆盖不了的场景（API key、自定义 SSLContext、多集群、请求头），继承配置类自定义：

```java
@Configuration
public class MyElasticsearchConfig extends ElasticsearchConfiguration {
    @Override
    public ClientConfiguration clientConfiguration() {
        return ClientConfiguration.builder()
            .connectedTo("es1:9200", "es2:9200")         // 集群地址
            .usingSsl()                                   // 启用 TLS（默认 http）
            .withBasicAuth("elastic", "secret")           // Basic 认证
            .withConnectTimeout(Duration.ofSeconds(5))    // 连接超时
            .withSocketTimeout(Duration.ofSeconds(30))    // 读超时
            .withPathPrefix("ela")                        // 代理前缀
            .withProxy("localhost:8888")                  // 出网代理
            .withDefaultHeaders(headers)                  // 全请求默认头
            .withHeaders(() -> headersSupplier())         // 每请求动态头（如 JWT 续期；响应式中禁止阻塞）
            .build();
    }
}
```

| 方法 | 作用 | 典型场景 |
|------|------|---------|
| `connectedTo(String...)` | 集群地址列表 | 生产多节点 |
| `usingSsl()` | 开启 TLS（可传 SSLContext 或证书指纹） | 生产集群 |
| `withBasicAuth(user, pass)` | 用户名密码认证 | ES 安全开启时 |
| `withApiKey(key)` | API key 认证（Boot 属性无此项） | 服务间调用 |
| `withConnectTimeout` / `withSocketTimeout` | 超时控制 | 慢查询/网络抖动场景 |
| `withPathPrefix` | URL 前缀 | 反向代理多集群 |
| `withProxy` | HTTP 代理 | 受限网络 |
| `withDefaultHeaders` / `withHeaders` | 静态/动态请求头 | 审计、租户隔离、JWT |
| `withClientConfigurer(callback)` | 底层传输细调 | 连接池、keep-alive 等高级项 |

> 🎯 **优先级**：Boot 自动配置发现用户自定义的 `ClientConfiguration` Bean（或继承 `ElasticsearchConfiguration`）时会**尊重并覆盖**默认配置——"默认属性能用就够，特殊需求再覆盖"。

## 5. 认证与 TLS 速查

### 5.1 三种认证方式选型

| 方式 | 配置入口 | 适用 | 安全性 |
|------|---------|------|--------|
| Basic Auth | `spring.elasticsearch.username/password` 或 `withBasicAuth` | 单集群、人可管理的账号 | ⭐⭐⭐ |
| API Key | `ClientConfiguration.builder().withApiKey(...)` | 服务间调用、按服务轮换 | ⭐⭐⭐⭐ |
| TLS 证书校验 | `usingSsl()` + SSL bundle | 所有生产环境**必须** | ⭐⭐⭐⭐⭐ |

> 💡 ES 9 默认启用 xpack 安全——本地开发起容器时要么关安全（`xpack.security.enabled=false`），要么配认证；生产**必须 TLS + 认证双开**（[08 篇](08-集成地图与常见问题.md) 有完整排错清单）。

### 5.2 CA 证书信任（SSL bundle 方式）

```yaml
spring:
  ssl:
    bundle:
      pem:
        es-trust:                          # bundle 名称，可任意起
          truststore:
            certificate: "classpath:ca-cert.pem"   # ES CA 证书文件
  elasticsearch:
    uris: https://localhost:9200
    restclient:
      ssl:
        bundle: es-trust                   # 引用上面的 bundle
```

**开发环境两个快速替代**（二选一，生产别用）：

```java
// 方案 A：证书指纹（ES 8+ 启动日志会打印）
.usingSsl("sha256:3b4eab...")              // 跳过 CA 校验，用指纹锁定服务器

// 方案 B：信任所有证书（仅本地联调，生产严禁）
usingSsl(sslContextThatTrustsAll())        // 自建 SSLContext
```

> ⚠️ **认证失败三连排查**：① `security_exception` 用户不存在/密码错；② `unable to verify the first certificate` → CA 链没配；③ `http_certificate` 校验失败 → 指纹/SNI 不匹配。逐一对照错误信息开头即可定位。

## 6. 超时、代理与高级定制

### 6.1 底层传输回调（withClientConfigurer）

Boot 属性之外的高级定制都通过回调，在 `ClientConfiguration` 上按需叠加：

| 回调 | 配置对象 | 典型用途 |
|------|---------|---------|
| `Rest5Clients.ElasticsearchRest5ClientConfigurationCallback` | `RestClientBuilder` | 压缩、自定义调度器 |
| `Rest5Clients.ElasticsearchHttpClientConfigurationCallback` | `HttpAsyncClientBuilder` | Apache HttpClient 5 连接池参数 |
| `Rest5Clients.ElasticsearchConnectionConfigurationCallback` | `ConnectionConfig` | 连接级超时/缓冲区 |
| `Rest5Clients.ElasticsearchConnectionManagerCallback` | `PoolingAsyncClientConnectionManagerBuilder` | 连接池大小、空闲回收 |
| `Rest5Clients.ElasticsearchRequestConfigCallback` | `RequestConfig` | 请求级超时覆盖 |

```java
.withClientConfigurer(
    Rest5Clients.ElasticsearchRest5ClientConfigurationCallback.from(builder -> {
        builder.setCompressionEnabled(true);          // gzip 压缩传输
        return builder;
    }))
```

> 💡 响应式模板复用同一套 `ClientConfiguration`——回调同样生效；`withHeaders(() -> ...)` 的 Supplier 在响应式下**禁止阻塞**（每个请求回调执行于事件循环线程）。

### 6.2 连接池与并发规模速查

| 参数 | 默认参考 | 调优方向 |
|------|---------|---------|
| 每路由最大连接 | 视版本（HttpClient 默认 20~100） | 高并发查询服务调大 |
| 空闲连接回收 | 默认配置 | 长连接保活 + 定期回收防泄漏 |
| 每连接最大并发请求 | 受线程模型限制 | 命令式用线程池 + 连接池双维度 |
| 响应式 | 事件循环 + 少量连接 | 天然高吞吐，注意背压 |

> 🎯 **经验值**：命令式服务先按 `线程数 ≈ 连接数 × 单连接并发` 估算；出现 `ConnectionPoolTimeoutException` 先调连接池上限，再回头看慢查询——**池不够用往往是查询太慢的另一个名字**。

## 7. 响应式配置

```java
@Configuration
public class MyReactiveConfig extends ReactiveElasticsearchConfiguration {
    @Override
    public ClientConfiguration clientConfiguration() {
        return ClientConfiguration.builder()
            .connectedTo("localhost:9200")
            .withBasicAuth("elastic", "secret")
            .build();
    }
}

// 可注入的 Bean：
// ReactiveElasticsearchOperations / ReactiveElasticsearchTemplate
// ReactiveElasticsearchClient（响应式客户端）
// Rest5Client / JsonpMapper
```

| 响应式 Bean | 对应命令式 | 说明 |
|------------|-----------|------|
| `ReactiveElasticsearchOperations` | `ElasticsearchOperations` | 非阻塞模板（Mono/Flux） |
| `ReactiveElasticsearchClient` | `ElasticsearchClient` | 原生响应式客户端 |
| `ReactiveElasticsearchRepository` | `ElasticsearchRepository` | 响应式仓库接口 |

> ⚠️ **响应式 ≠ 更快**：响应式适合 IO 密集高并发（网关、搜索聚合服务），收益来自线程利用率；命令式简单直接，运维心智成本低——**没有响应式需求不要强行上**，Boot 默认两者都能用，按团队能力选。

## 8. 日志与排错速查

### 8.1 传输层日志（看真实请求/响应）

```yaml
logging:
  level:
    co.elastic.clients.transport.rest5_client.low_level.Request: trace   # 打印完整 HTTP 交互
    org.springframework.data.elasticsearch: debug                        # SDE 内部（查询翻译、映射）
```

| 日志包 | 级别 | 看到什么 | 何时用 |
|--------|------|---------|--------|
| `co.elastic.clients.transport.rest5_client.low_level.Request` | trace | 请求行 + 响应行（**不含 body**） | 排查连接/认证问题 |
| `org.springframework.data.elasticsearch.core` | debug | 查询对象、结果大小 | 排查查询翻译问题 |
| `org.elasticsearch.client.RestClient` | debug | 旧客户端节点选择 | 仅 Legacy 场景 |

> ⚠️ trace 日志在**生产必须关闭**（每请求两行以上日志，量级翻倍）；排查完立即恢复级别。

### 8.2 高频启动/连接报错速查

| 报错关键字 | 根因 | 处理 |
|-----------|------|------|
| `Connection refused` / `ConnectTimeoutException` | ES 没起 / uris 错 / 防火墙 | curl 9200 验证；检查 uris |
| `security_exception` / `authentication_exception` | 认证缺失或密码错 | 配 username/password 或 API key |
| `unable to verify the first certificate` | TLS 信任没配 | SSL bundle / 证书指纹 |
| `Could not parse the main document` | 索引 mapping 与实体冲突 | 检查 @Field 类型与已有 mapping |
| `IndexNotFoundException` | 索引未创建或名称错 | IndexOperations.create / 检查 @Document(indexName) |
| `NoClassDefFoundError: co/elastic/clients/...` | SDE 与 ELC 版本错配 | dependency:tree 核对版本线 |
| `too_many_requests`（429） | 写入速率超限 | 降速、批量化、调并发 |
