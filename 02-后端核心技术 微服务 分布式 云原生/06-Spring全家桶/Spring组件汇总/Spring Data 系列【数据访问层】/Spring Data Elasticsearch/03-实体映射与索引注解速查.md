## 1. 注解总览与最小示例

```java
@Document(indexName = "product")                    // 实体 ↔ 索引
@Setting(shards = 1, replicas = 1)                  // 索引设置
@Mapping(mappingPath = "mappings/product.json")     // 可选：精细 mapping JSON
public class Product {
    @Id
    private String id;                              // 文档 _id

    @Field(type = FieldType.Text, analyzer = "ik_max_word", searchAnalyzer = "ik_max_word")
    private String name;                            // 全文搜索字段

    @Field(type = FieldType.Keyword)
    private String category;                        // 精确匹配/聚合字段

    @Field(type = FieldType.Keyword, ignoreAbove = 256)
    private String brand;

    @Field(type = FieldType.Double)
    private double price;                           // 范围/排序/聚合

    @Field(type = FieldType.Date, format = DateFormat.date_optional_time)
    private LocalDateTime createdAt;                // 日期（LocalDateTime 自动支持）

    @Field(type = FieldType.Integer)
    private int stock;

    @Field(type = FieldType.Object, enabled = false) // 整个对象不做索引
    private AuditInfo audit;

    @Field(type = FieldType.Dense_Vector, dims = 1024)
    private float[] embedding;                      // 向量字段（RAG，见 07 篇）
}
```

> 🎯 **最小心法**：**Text 管"搜"，Keyword 管"精确/排序/聚合"**——同一字段常拆两个：`title`（Text，全文） + `title.keyword`（子字段，Keyword）。ES 默认对 Text 自动加 `.keyword` 子字段，但显式声明更可控。

### 1.1 索引创建流程（自动 vs 手动）

```text
应用启动 → Repository 引导 → 检查索引是否存在
  ├─ 不存在 → 用 @Setting + @Mapping/@Field 创建索引与映射（createIndex=true 时）
  └─ 存在 → 默认跳过；alwaysWriteMapping=true 时强制写映射（慎用）
```

| 配置 | 行为 |
|------|------|
| `@Document(createIndex = true)` | 启动时自动创建索引（默认） |
| `@Document(createIndex = false)` | 不自动创建——生产常用，索引由 DBA/CI 管理 |
| `@Document(alwaysWriteMapping = true)` | 索引已存在也强制写映射（**危险**：可能覆盖已有 mapping） |
| 手动 | `IndexOperations.create()` / `putMapping()` |

> ⚠️ **生产原则**：索引一旦有数据，mapping 的字段类型**不可改**（只能加字段）。生产环境推荐 `createIndex=false`，由独立的索引管理流程（脚本/CI）先建好索引——避免应用启动顺序竞争与误覆盖。

## 2. @Document 属性速查

| 属性 | 默认值 | 说明 |
|------|--------|------|
| `indexName` | 必填 | 索引名：仅小写，不能含 `\ / * ? " > < | 空格 , #`，不能以 `- _ +` 开头，不能是 `.`/`..`，≤255 字节 |
| `createIndex` | true | 启动时自动建索引 |
| `alwaysWriteMapping` | false | 索引存在也写映射 |
| `dynamic` | `INHERIT` | 动态字段策略：`TRUE`（自动加字段）/ `FALSE`（忽略未知字段）/ `STRICT`（未知字段抛错）/ `INHERIT` |
| `storeIdInSource` | true | id 是否写入 _source |
| `storeVersionInSource` | true | 版本号是否写入 _source |
| `versionType` | `EXTERNAL` | 版本管理策略（EXTERNAL 用外部版本号做乐观并发） |
| `writeTypeHint` | `DEFAULT` | 是否写类型提示（多态/接口类型需要） |
| `aliases` | 空 | 索引别名定义（配合别名读写分离） |

```java
@Document(
    indexName = "order",
    createIndex = false,                      // 生产：索引由 CI 管理
    dynamic = Dynamic.STRICT,                 // 严格模式：字段漂移直接报错
    versionType = Document.VersionType.EXTERNAL
)
public class Order {
    @Id private String id;
    @Version private Long version;            // 外部版本号（乐观锁）
    // ...
}
```

> 💡 `dynamic=STRICT` 是**线上质量利器**：实体加字段忘记同步 mapping 时，老文档照常读、新文档直接报错——把"静默字段漂移"变成"显式错误"，配合日志能第一时间发现 mapping 失配。

### 2.1 @Id 与版本控制

```java
// 字符串 ID（常用，业务生成或 UUID）
@Id private String id;

// 数值 ID（ES 支持自动生成，但不建议依赖自动生成——幂等写入需要可控 ID）
// 版本乐观锁：
@Version private Long version;
```

| 写法 | 语义 | 适用 |
|------|------|------|
| `@Id String` | 显式 ID，覆盖写入（同 ID 覆盖更新） | 业务主键如 orderId |
| 无 @Id | ES 自动生成 `_id` | 日志类、无需幂等的场景 |
| `@Version Long` | 外部版本控制（versionType=EXTERNAL 时） | 乐观并发写入 |

> ⚠️ **覆盖更新真相**：ES 的"更新"本质是**删除旧文档 + 写入新文档**（_id 相同）。依赖此语义做幂等写入时，务必显式提供业务 ID；无 ID 时每次 save 都是新文档。

## 3. @Field 属性速查与字段类型选型

### 3.1 属性全表（6.x）

| 属性 | 默认值 | 说明 |
|------|--------|------|
| `name` / `value` | 属性名 | 文档字段名（可重命名） |
| `type` | `Auto` | 字段类型（见 3.2 选型表） |
| `index` | true | 是否索引（false = 只存不搜） |
| `format` | `{date_optional_time, epoch_millis}` | 日期格式（Date 字段） |
| `pattern` | 空 | 自定义日期格式 |
| `store` | false | 独立存储（默认只存 _source） |
| `analyzer` / `searchAnalyzer` | 空 | 索引分词器 / 搜索分词器 |
| `normalizer` | 空 | 规范化器（Keyword 字段小写化等） |
| `copyTo` | 空 | 复制到目标字段（多字段合并搜索） |
| `fielddata` | false | Text 字段聚合开关（**慎用**，吃内存） |
| `ignoreAbove` | -1 | 超长字段忽略（Keyword 常用 256） |
| `coerce` | true | 自动类型强转 |
| `docValues` | true | 列式存储（排序/聚合依赖） |
| `ignoreMalformed` | false | 非法值忽略而不是报错 |
| `norms` | true | 评分规范（纯过滤字段可关省空间） |
| `indexOptions` | `none` | 索引选项（positions 等） |
| `indexPhrases` / `indexPrefixes` | false | 短语/前缀索引优化 |
| `nullValue` | 空 | 空值替代值 |
| `similarity` | 空 | 评分算法（BM25/boolean） |
| `positionIncrementGap` | -1 | 多值短语间距 |
| `termVector` | none | 词向量（高亮性能） |
| `storeNullValue` | false | null 也存储 |
| `storeEmptyValue` | true | 空值存储（5.1+） |
| `dynamic` | `INHERIT` | Object/Nested 字段的动态策略 |
| `excludeFromSource` | false | 从 _source 排除 |
| `enabled` | true | Object 字段整体禁用索引 |
| `dims` | -1 | **Dense_Vector 维度**（4.2+） |
| `elementType` | 空 | **Dense_Vector 元素类型**（5.4+，如 float/int8） |
| `knnSimilarity` | `DEFAULT` | **向量相似度**（l2_norm/cosine/dot_product，5.4+） |
| `knnIndexOptions` | 空 | **向量索引选项**（HNSW/FLAT 参数，5.4+） |
| `scalingFactor` | 1.0 | scaled_float 缩放因子 |
| `eagerGlobalOrdinals` | false | 全局序号预加载（大基数聚合） |
| `mappedTypeName` | 空 | 覆盖映射类型名（5.4+） |
| `positiveScoreImpact` | true | rank_feature 正相关 |

> 🎯 **记住三组高频组合**：① Text + analyzer + searchAnalyzer（全文）；② Keyword + ignoreAbove + normalizer（精确/聚合）；③ Dense_Vector + dims + knnSimilarity + knnIndexOptions（向量）。

### 3.2 字段类型选型表

| FieldType | ES 类型 | 场景 | 注意事项 |
|-----------|--------|------|---------|
| `Text` | text | 全文搜索（分词） | 不可排序/聚合（除非 fielddata） |
| `Keyword` | keyword | 精确匹配、排序、聚合 | ignoreAbove 防超长 |
| `Date` | date | 时间字段 | format/pattern 控制解析 |
| `Integer`/`Long`/`Double`/`Float` | 对应数值 | 范围、排序、聚合 | 选型看量级（int ≤ 2^31） |
| `Boolean` | boolean | 布尔过滤 | — |
| `Nested` | nested | 对象数组独立检索 | 数组内对象**必须** Nested（否则拍平） |
| `Object` | object | 单对象字段 | 数组内对象语义坑（拍平） |
| `Auto` | 推断 | 不确定时让 ES 推断 | 生产少用：推断结果不可控 |
| `Dense_Vector` | dense_vector | 向量检索（kNN） | dims 必须显式（4.2+） |
| `Sparse_Vector` | sparse_vector | 稀疏向量（BM25 替代） | 6.x 支持，见 07 篇 |
| `Rank_Feature` | rank_feature | 自定义相关性权重 | 业务打分，见 07 篇 |
| `Ip` | ip | IP 匹配/范围 | — |
| `Geo_Point`/`Geo_Shape` | geo_point/geo_shape | 地理位置 | Criteria 不支持 GeoJson 派生 |
| `Keyword` + normalizer | keyword+normalizer | 不区分大小写精确匹配 | — |

> ⚠️ **Nested 的隐藏代价**：Nested 把每个数组对象独立成"迷你文档"，查询正确但**聚合与性能有代价**（Lucene 内部 join）。能用 Object + 平铺解决的别用 Nested；需要"数组内对象按组合条件检索"时才必须 Nested（如订单明细项）。

### 3.3 分词器配置速查（中文场景重点）

```java
@Field(type = FieldType.Text,
       analyzer = "ik_max_word",            // 索引用最细粒度分词
       searchAnalyzer = "ik_smart")         // 搜索用较粗粒度（查得准）
private String name;
```

| 方案 | 插件 | 适用 | 注意 |
|------|------|------|------|
| 标准分词 | 内置 | 英文 | 中文按单字拆，效果差 |
| IK 分词 | ik 插件 | **中文通用（首选）** | ik_max_word（索引）/ ik_smart（搜索）组合 |
| ICU 分词 | analysis-icu | 多语言 | 官方插件，重 |
| 拼音 | pinyin 插件 | 拼音搜索 | 与 IK 配合 copyTo |
| 自研 | — | 专业领域 | 词典维护成本高 |

> 💡 IK 插件装在 **ES 服务端**（`bin/elasticsearch-plugin install analysis-ik`），组件侧只需声明 analyzer 名；集群重启后验证 `_analyze` 接口，别在 Java 侧找分词器——它不在那。

## 4. @Mapping / @Setting：精细控制

### 4.1 @Mapping 属性速查

| 属性 | 默认值 | 说明 |
|------|--------|------|
| `mappingPath` | 空 | classpath 下 mapping JSON 文件路径 |
| `enabled` | true | 是否启用映射（false = 不建索引的原始文档库） |
| `dateDetection` | `DEFAULT` | 日期自动检测开关 |
| `numericDetection` | `DEFAULT` | 数值自动检测开关 |
| `dynamicDateFormats` | 空 | 动态日期格式 |
| `runtimeFieldsPath` | 空 | runtime 字段定义 JSON（4.3+） |
| `aliases` | 空 | 字段别名定义（5.3+） |

```json
// mappings/product.json（mappingPath 引用）
{
  "properties": {
    "name": { "type": "text", "analyzer": "ik_max_word", "search_analyzer": "ik_smart" },
    "category": { "type": "keyword", "ignore_above": 256 },
    "specs": { "type": "nested", "properties": { "key": {"type": "keyword"}, "value": {"type": "keyword"} } }
  }
}
```

### 4.2 @Setting 属性速查

| 属性 | 默认值 | 说明 |
|------|--------|------|
| `settingPath` | 空 | 设置 JSON 文件路径（6.0 起支持 SpEL） |
| `shards` | 1 | 分片数（ES 7+ 默认 1，别随意调大） |
| `replicas` | 1 | 副本数 |
| `refreshInterval` | `"1s"` | 刷新间隔（写入可见延迟） |
| `indexStoreType` | `"fs"` | 存储类型 |
| `sortFields` / `sortOrders` / `sortModes` / `sortMissingValues` | 空 | **索引级排序**（4.2+，配合 search_after 分页） |
| `useServerConfiguration` | false | 使用服务端设置创建索引 |

```java
@Setting(shards = 3, replicas = 2, refreshInterval = "30s")  // 写多读少场景调大 refresh
```

> ⚠️ **refresh 与写入吞吐**：`refreshInterval` 越小写入可见越快，但段合并开销越大。日志类高吞吐场景调到 `"30s"` 甚至 `-1`（禁用刷新、手动 refresh）；搜索类实时性要求高的用 `"1s"`。**它决定了 ES"近实时"的语义**——save 后立刻 findById 查不到是正常现象，不是 bug。

### 4.3 @Indexed / @Aggregation / @SearchTemplateQuery 等辅助注解

| 注解 | 用途 |
|------|------|
| `@Indexed` | 属性级（标记某字段参与索引查询场景） |
| `@Aggregation` | 属性级：聚合字段声明（Repository 方法上用） |
| `@Query` / `@SearchTemplateQuery` | Repository 方法级查询（见 04 篇） |
| `@Highlight` / `@HighlightField` | 高亮字段声明（见 05 篇） |
| `@CreatedDate` / `@LastModifiedDate` | 审计字段（需 @EnableElasticsearchAuditing） |

## 5. 索引生命周期管理（IndexOperations）

```java
// 从 Operations 获取索引操作域
IndexOperations ops = operations.indexOps(Product.class);
// 或按名称操作不存在的实体映射：
IndexOperations ops2 = operations.indexOps(IndexCoordinates.of("product_v2"));

ops.create();                                   // 创建索引（按 @Setting/@Mapping）
ops.putMapping();                               // 写映射
ops.exists();                                   // 是否存在
ops.delete();                                   // 删除（慎！不可恢复）
ops.getSettings() / ops.getMapping();           // 读取当前配置
ops.refresh();                                  // 手动刷新（等写入可见）
ops.createAlias(Alias.of(a -> a.isWriteIndex(false)));  // 别名管理
ops.putAlias(Alias.of(a -> a.filter("{\"term\":{\"status\":\"active\"}}")));  // 过滤别名
```

### 5.1 别名读写分离（零停机重建索引的标准姿势）

```text
product_v1  ← 当前真实索引
product     ← 别名（应用只认别名）
流程：建 product_v2（新 mapping）→ 全量迁移数据 → 切别名 product → product_v1
```

| 场景 | 操作 |
|------|------|
| 上线新 mapping | 建 v2 → 迁移 → 原子切别名 |
| 过滤路由 | 别名加 filter（租户隔离等） |
| 写索引分离 | `isWriteIndex(false)` 的只读别名 |

> 🎯 **别名是 ES 生产运维的核心模式**——mapping 不能改字段类型，别名 + 重建索引才是正解；应用侧永远引用别名而不是索引名，切换对业务无感。

## 6. 映射原理：ElasticsearchEntityMapper

### 6.1 映射链路由来（4.0 起）

```text
POJO → ElasticsearchEntityMapper（核心转换器）
  ├── 解析 @Document/@Field 注解 → 生成 mapping JSON
  ├── 属性类型解析：集合/嵌套/日期/LocalDateTime → 对应映射
  └── 文档序列化/反序列化：Jackson 底层 + 类型系统
```

| 版本 | 映射器 | 说明 |
|------|--------|------|
| ≤3.2 | Jackson ObjectMapper | 自定义 Jackson 注解可生效 |
| 4.0+ | ElasticsearchEntityMapper | 注解驱动；**实体上的 Jackson 注解不再生效**——需要功能用 @Field |

> ⚠️ **迁移踩坑**：从 3.x 升级时，实体类上的 `@JsonProperty`/`@JsonFormat` 等自定义 Jackson 注解**全部失效**——字段重命名改用 `@Field(name=...)`，日期格式改用 `@Field(format=...)`。

### 6.2 自定义转换器（特殊类型）

```java
@Configuration
public class EsConfig extends ElasticsearchConfiguration {
    @Override
    public ClientConfiguration clientConfiguration() { return ClientConfiguration.builder().connectedTo("localhost:9200").build(); }

    @Bean
    @Override
    public ElasticsearchCustomConversions elasticsearchCustomConversions() {
        List<Converter<?, ?>> converters = List.of(
            new Converter<Instant, Long>() {                       // Instant → epoch millis
                public Long convert(Instant source) { return source.toEpochMilli(); }
            });
        return new ElasticsearchCustomConversions(converters);
    }
}
```

## 7. 常见映射坑速查

| 坑 | 现象 | 解法 |
|----|------|------|
| 字段类型冲突 | 写入报 `mapper_parsing_exception` | 删除重建索引（或别名重建）——mapping 类型不可改 |
| Text 字段排序/聚合报错 | `Fielddata is disabled on text fields` | 用 `.keyword` 子字段；确实需要再开 fielddata |
| 数组对象拍平 | 查询结果交叉匹配（a=1,b=2 各自存在却命中） | 改 `Nested` |
| 日期格式不匹配 | `ParseFailure` / 写入 null | 统一 `format`（ISO 8601 或 epoch_millis） |
| 中文搜索不准 | 搜"手机壳"返回无关结果 | 装 IK + analyzer/searchAnalyzer 分设 |
| save 后查不到 | 刷新延迟 | `refreshInterval` 调小 / 手动 refresh / 测试用 `withRefreshPolicy` |
| 数字精度丢失 | double 存钱差几分 | 金额用 `scaled_float`（scalingFactor=100）或字符串 |
| 实体加字段不生效 | 新字段查询为空 | 索引 mapping 更新（新增字段允许，类型不可改） |
| 多态/接口类型丢失 | 反序列化类型错 | `writeTypeHint` / 显式 mappedTypeName |
