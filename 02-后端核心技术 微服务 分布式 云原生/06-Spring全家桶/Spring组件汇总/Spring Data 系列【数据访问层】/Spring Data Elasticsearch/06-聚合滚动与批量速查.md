## 1. 聚合概览与选型

```java
NativeQuery query = NativeQuery.builder()
    .withQuery(q -> q.bool(b -> b.filter(f -> f.term(t -> t.field("status").value("PAID")))))
    .withAggregation("by_category", a -> a.terms(t -> t.field("category.keyword").size(10)))
    .withAggregation("avg_price", a -> a.avg(avg -> avg.field("price")))
    .withAggregation("date_hist", a -> a.dateHistogram(dh -> dh.field("createdAt").calendarInterval(CalendarInterval.Month)))
    .withPageable(PageRequest.of(0, 0))       // 只关心聚合：size=0 不取文档
    .build();

List<Aggregation> aggs = operations.aggregate(query, Order.class, IndexCoordinates.of("order"));

// 取桶聚合结果
Aggregate catAgg = aggs.stream()
    .filter(a -> a.getName().equals("by_category")).findFirst().orElseThrow()
    .getAggregate();
List<LongTermsBucket> buckets = catAgg.lterms().buckets().array();
for (LongTermsBucket b : buckets) {
    b.key();       // 桶键（category）
    b.docCount();  // 桶内文档数
}
```

> 🎯 **聚合心智模型**：聚合 = **桶（分组）+ 指标（统计）**。桶把文档分组，指标在组内计算——`terms` 按类别分组（桶），`avg` 算每组的平均价（指标）。**查询与聚合同一次请求完成**，返回 `SearchHits` 或 `List<Aggregation>` 二选一（`aggregate()` 只拿聚合）。

### 1.1 聚合使用要点

| 要点 | 说明 |
|------|------|
| 分页与聚合 | 聚合独立于 from/size；只要聚合可设 `PageRequest.of(0, 0)` |
| 字段类型 | 桶聚合要求 **Keyword/doc_values** 字段（Text 需 `.keyword` 子字段） |
| 嵌套 | Nested 字段聚合需 `nested` 聚合包裹 |
| 返回 | `operations.aggregate(query, clazz, index)` → `List<Aggregation>` |
| 调试 | 拿生成的 DSL 去 Kibana 聚合可视化直接看 |

> ⚠️ **常见报错**：`Fielddata is disabled on text fields`——Text 字段直接聚合报错。解法：聚合字段用 `.keyword` 子字段或映射为 Keyword。

## 2. 指标聚合速查

| 聚合 | lambda 写法 | 返回 |
|------|-------------|------|
| avg | `a.avg(x -> x.field("price"))` | 平均值 |
| sum | `a.sum(x -> x.field("price"))` | 总和 |
| min / max | `a.min(x -> x.field("price"))` | 最值 |
| stats | `a.stats(x -> x.field("price"))` | 五合一（count/min/max/avg/sum） |
| value_count | `a.valueCount(x -> x.field("price"))` | 非空值计数 |
| cardinality | `a.cardinality(x -> x.field("userId").precisionThreshold(40000))` | 去重计数（近似） |
| percentiles | `a.percentiles(x -> x.field("price").percents(50.0, 90.0, 99.0))` | 分位数（响应时间统计） |
| top_hits | `a.topHits(x -> x.size(5).sort(...))` | 组内取 top 文档 |

```java
// 响应时间 P99 统计（性能看板经典）
NativeQuery query = NativeQuery.builder()
    .withAggregation("p99", a -> a.percentiles(p -> p.field("latency").percents(99.0)))
    .withPageable(PageRequest.of(0, 0))
    .build();
List<Aggregation> aggs = operations.aggregate(query, Trace.class, IndexCoordinates.of("trace"));
// aggs → tdigestPercentiles() 取值
```

> 💡 **近似聚合要知道**：`cardinality`（HyperLogLog）和 `percentiles`（TDigest）都是**近似算法**——量大时结果有误差但可控（precisionThreshold/percents 可调）。对账、金额类统计用精确聚合（sum/stats），UV 类去重用 cardinality。

## 3. 桶聚合速查

| 聚合 | lambda 写法 | 场景 |
|------|-------------|------|
| terms | `a.terms(t -> t.field("category.keyword").size(10))` | 分组统计（最常用） |
| date_histogram | `a.dateHistogram(dh -> dh.field("createdAt").calendarInterval(CalendarInterval.Month))` | 时间分桶（趋势图） |
| histogram | `a.histogram(h -> h.field("price").interval(100.0))` | 数值分桶 |
| range | `a.range(r -> r.field("price").ranges(...))` | 自定义区间 |
| filter | `a.filter(f -> f.term(t -> t.field("status").value("PAID")))` | 条件分桶 |
| nested | `a.nested(n -> n.path("specs"))` | Nested 字段聚合（内嵌子聚合） |
| missing | `a.missing(m -> m.field("brand"))` | 空值分桶 |

### 3.1 桶内嵌套指标（经典组合：每个类别下的平均价）

```java
NativeQuery query = NativeQuery.builder()
    .withAggregation("by_category", a -> a.terms(t -> t.field("category.keyword").size(10)
        .aggregations("avg_price", agg -> agg.avg(x -> x.field("price")))))   // 桶内子聚合
    .withPageable(PageRequest.of(0, 0))
    .build();

// 取值：by_category → buckets → 每桶再取 avg_price 子聚合
```

> 🎯 **嵌套模式**：桶聚合支持任意深度子聚合——"分组 → 组内统计 → 组内再分组"形成聚合树；这是 BI 报表、品类分析的通用骨架。

## 4. 组合聚合与 Pipeline

### 4.1 多聚合并行

```java
NativeQuery query = NativeQuery.builder()
    .withQuery(q -> q.matchAll(m -> m))
    .withAggregation("sales_total", a -> a.sum(s -> s.field("amount")))
    .withAggregation("order_count", a -> a.valueCount(v -> v.field("_id")))
    .withAggregation("by_region", a -> a.terms(t -> t.field("region.keyword")))
    .withPageable(PageRequest.of(0, 0))
    .build();
```

### 4.2 Pipeline 聚合（基于其他聚合结果）

| Pipeline 聚合 | 用途 |
|--------------|------|
| `avg_bucket` / `sum_bucket` | 对桶聚合结果再求平均/求和 |
| `derivative` | 时间序列求导（增量） |
| `cumulative_sum` | 累计求和（GMV 累计曲线） |
| `bucket_script` | 桶间脚本计算 |

```java
// 月度 GMV + 环比增量（date_histogram + derivative）
.withAggregation("monthly_sales", a -> a.dateHistogram(dh -> dh.field("createdAt")
        .calendarInterval(CalendarInterval.Month)
        .aggregations("sum_amount", agg -> agg.sum(s -> s.field("amount")))))
.withAggregation("sales_delta", a -> a.derivative(d -> d
        .bucketsPath("monthly_sales>sum_amount")))          // pipeline 引用桶内聚合路径
```

> ⚠️ **Pipeline 路径语法**：`bucketsPath` 用 `>` 连接父子聚合名（如 `monthly_sales>sum_amount`）——路径写错返回空聚合，这是 pipeline 最常见的坑。

## 5. 深分页：scroll / search_after / PIT 选型

| 方案 | 原理 | 适合 | 局限 |
|------|------|------|------|
| from+size | 偏移量 | **前 10000 条** | 深分页性能暴跌，超上限直接报错 |
| scroll | 游标快照 | **全量导出**（一次性） | 快照过期、不实时；不适合翻页交互 |
| search_after | 上页末条排序值 | **实时深分页**（推荐） | 依赖稳定排序；无"跳页" |
| PIT + search_after | 时间点视图 + 游标 | **稳定深分页 + 数据在变** | 需维护 PIT 生命周期 |

### 5.1 search_after 标准姿势

```java
// 第一页：普通查询 + 稳定排序
NativeQuery first = NativeQuery.builder()
    .withQuery(q -> q.matchAll(m -> m))
    .withSort(s -> s.field(f -> f.field("createdAt").order(SortOrder.Asc)))   // 排序必须唯一稳定
    .withSort(s -> s.field(f -> f.field("_id").order(SortOrder.Asc)))         // 加 _id 兜底唯一
    .withPageable(PageRequest.of(0, 1000))
    .build();
SearchHits<Product> page1 = operations.search(first, Product.class, index);

// 后续页：取上页最后一条的排序值作为游标
List<Object> searchAfter = page1.getSearchHit(page1.getSearchHits().size() - 1).getSortValues();
NativeQuery next = NativeQuery.builder()
    .withQuery(q -> q.matchAll(m -> m))
    .withSort(s -> s.field(f -> f.field("createdAt").order(SortOrder.Asc)))
    .withSort(s -> s.field(f -> f.field("_id").order(SortOrder.Asc)))
    .withSearchAfter(searchAfter)                                // ★ 游标
    .withPageable(PageRequest.of(0, 1000))
    .build();
```

### 5.2 scroll 全量导出

```java
// ① 开启滚动（1 分钟快照）
SearchScrollHits<Product> scroll = operations.searchScrollStart(
        1000,                                                     // 每批大小
        new NativeQuery(QueryBuilders.matchAll().build()),        // 或 StringQuery
        Product.class, index);

String scrollId = scroll.getScrollId();
while (scroll.hasSearchHits()) {                                  // ② 逐批拉取
    for (SearchHit<Product> hit : scroll.getSearchHits()) {
        handle(hit.getContent());
    }
    scroll = operations.searchScrollContinue(scrollId, 1000, Product.class, index);  // 续滚
}
operations.searchScrollClear(scrollId);                           // ③ 释放快照（务必）
```

> ⚠️ **scroll 三件事**：① 快照语义——滚动期间的数据变更**不可见**；② 必须 `searchScrollClear` 释放（否则 ES 侧快照资源泄漏）；③ 不适合交互式翻页（用户翻到第 50 页时快照可能早过期）——交互翻页用 search_after。

### 5.3 深分页选型口诀

```text
翻前 10000 条        → from+size（默认）
导出全量 / 定时任务   → scroll
交互式深翻页         → search_after（排序必须稳定唯一）
数据边写边翻 + 稳定快照 → PIT + search_after
```

## 6. 批量写入（bulk）与性能调优

### 6.1 批量写入三种姿势

```java
// ① 简单批量（实体列表）
ops.save(List.of(p1, p2, p3, ...), IndexCoordinates.of("product"));

// ② 精细控制（IndexQuery：显式 ID、路由、版本）
List<IndexQuery> queries = products.stream()
    .map(p -> new IndexQuery.Builder().withId(p.getId()).withObject(p).build())
    .toList();
ops.bulkIndex(queries, IndexCoordinates.of("product"));

// ③ 原生 bulk（ELC，最灵活）
BulkRequest request = BulkRequest.of(b -> b
    .operations(List.of(BulkOperation.of(o -> o.index(i -> i.index("product").id("1").document(Map.of(...)))))));
BulkResponse response = client.bulk(request);
```

### 6.2 写入性能调优速查

| 手段 | 效果 | 注意 |
|------|------|------|
| 批量条数 500~1000/批 | 吞吐明显提升 | 过大会撑爆请求体/堆 |
| `refreshInterval` 调大（30s/禁用） | 减少段合并竞争 | 牺牲可见性 |
| 关闭 `_source`（日志场景） | 省存储 | 无法回查原文 |
| 关闭 `norms`/`docValues`（纯写场景） | 省空间省 IO | 影响排序/评分 |
| 并行写入 + 合理连接池 | 打满带宽 | 注意客户端线程模型 |
| 索引 `max_result_window` 不设大 | 防止误用深分页 | 设计上的护栏 |

> 🎯 **吞吐优化次序**：先批量 → 再 refresh → 后并行——三步做完通常已达磁盘/网络瓶颈；**别一上来就上 Kafka + Logstash 管道**，先确认单机直写压满没有。

### 6.3 幂等写入与重试

```java
// 外部版本控制（乐观并发，见 03 篇）
@Document(versionType = Document.VersionType.EXTERNAL)
public class Order {
    @Id private String id;
    @Version private Long version;
}

// 冲突重试（update 场景）
UpdateQuery update = UpdateQuery.builder(id)
    .withScript(...)
    .withRetryOnConflict(3)      // 版本冲突自动重试
    .build();
```

## 7. 多文档操作与脚本更新

### 7.1 脚本更新（服务端计算，减少数据传输）

```java
// 库存扣减（原子操作，无需读-改-写）
UpdateQuery update = UpdateQuery.builder(productId)
    .withScript("ctx._source.stock -= params.qty")
    .withScriptParams(Map.of("qty", 2))
    .withRetryOnConflict(3)
    .build();
operations.update(update, IndexCoordinates.of("product"));

// 字段级部分更新（doc 覆盖）
UpdateQuery docUpdate = UpdateQuery.builder(orderId)
    .withDoc(JsonData.of(Map.of("status", "SHIPPED")))
    .build();
```

| 更新方式 | 语义 | 并发安全 | 场景 |
|---------|------|:---:|------|
| save | 全量覆盖 | ❌ 丢更新 | 全字段写入 |
| update + doc | 字段级覆盖 | ⚠️ 需重试 | 状态流转 |
| update + script | 服务端计算 | ✅ 原子 | 计数器、库存扣减 |

> 🎯 **并发写核心原则**：ES 没有行锁——**同文档并发更新必须靠版本（乐观锁）+ 冲突重试**；高频计数/扣减用 `script` + `retryOnConflict` 是唯一正解，先读再写（read-modify-write）在高并发下必丢更新。

### 7.2 批量删除与按查询删除

```java
// 按 ID 批量删除
ops.delete(List.of("id1", "id2"), index);

// 按查询条件删除（delete_by_query 语义）
DeleteRequest request = DeleteRequest.of(d -> d
    .index("product")
    .query(q -> q.term(t -> t.field("status").value("OFF_SHELF"))));
client.delete(request);
```

> ⚠️ **按查询删除的注意**：`delete_by_query` 是**逐批快照删除**（有版本冲突和网络中断风险）——大范围删除前先在 Kibana 用相同 DSL 确认命中范围；删除后索引段会留空间，必要时 `_forcemerge`。
