## 1. 为什么 MongoDB 可以做向量库

**通俗**：MongoDB 8.x 原生支持向量索引与向量检索——**业务数据（订单/商品/用户）和它的向量（语义嵌入）存在同一个库里**，不用再单独搭一套向量数据库（Milvus/FAISS）+ 同步管道。

| 对比 | 传统方案（MySQL + Milvus） | MongoDB 一体化 |
|------|---------------------------|----------------|
| 数据同步 | 业务库 → 同步管道 → 向量库（双写/延迟/一致性） | **同库同文档**（业务字段 + 向量字段共存） |
| 查询结合 | 向量库查相似 → 回业务库取详情（两次查询） | **一次查询：向量相似 + 业务条件过滤** |
| 运维 | 两套存储两套监控 | 一套集群 |
| 代价 | — | 向量检索需 Search/Vector 索引（mongot 组件）；规模超大时专用向量库更优 |

> 🎯 定位一句话：**"实体中心"的轻量语义检索（商品相似推荐、文档召回、智能客服命中）用 MongoDB 一体化最顺手**；大规模独立 RAG 知识库（亿级向量 + 高并发检索）仍推荐 [Milvus](../../../../../03-AI大模型应用开发/08-向量数据库/Milvus/00-Milvus知识体系总览.md) 或 [Spring Data Elasticsearch 向量检索](../../Spring%20Data%20系列【数据访问层】/Spring%20Data%20Elasticsearch/07-向量检索与RAG集成速查.md)。

## 2. 向量索引：VectorIndex 与 SearchIndexOperations

### 2.1 前置：向量字段与索引

```java
@Document(collection = "product")
public class Product {
    @Id private String id;
    private String name;
    private String description;
    private float[] embedding;          // 向量字段（由嵌入模型生成，如 1536 维）
    private String category;            // 过滤字段（缩小检索范围）
}
```

```java
// ① 管理入口：SearchIndexOperations（MongoTemplate 提供）
SearchIndexOperations ops = mongoTemplate.searchIndexOps(Product.class);

// ② 创建向量索引（4.x VectorIndex API）
VectorIndex index = new VectorIndex("product_vector_idx")     // 索引名
        .addVector("embedding", vector -> vector
                .dimensions(1536)                             // 维度：与嵌入模型一致
                .similarity(VectorSimilarity.COSINE))         // COSINE / EUCLIDEAN / DOT_PRODUCT
        .addFilter("category");                              // 过滤字段（可选）
ops.createIndex(index);

// ③ 等待索引就绪（异步构建）
IndexStatus status;
do {
    status = ops.getIndexStatus(indexName);
    Thread.sleep(1000);
} while (status != IndexStatus.READY);                        // CREATING → READY
```

| 参数 | 说明 |
|------|------|
| dimensions | **必须与嵌入模型输出维度一致**（OpenAI text-embedding-3: 1536；BGE: 1024 等） |
| similarity | COSINE（语义相似常用）/ EUCLIDEAN / DOT_PRODUCT |
| 过滤字段 | 附加可过滤字段（category/tenant），检索时缩小范围 |

> ⚠️ **向量索引不是普通索引**：走 MongoDB Search/Vector 索引体系（mongot 组件）——**Atlas 或 Enterprise 版自带；社区版自建需要部署 mongot**（2026 起社区版可用性增强，但生产仍建议 Atlas/企业版）；建索引是**异步**的，创建后要轮询 READY 再查询（上面的 do-while）。

## 3. $vectorSearch 查询（模板 API）

### 3.1 VectorSearchOperation（4.x 官方 API）

```java
// 查询与商品 "手机壳" 语义最相近的 10 个商品
VectorSearchOperation search = VectorSearchOperation.search("product_vector_idx")  // 索引名
        .path("embedding")                      // 向量字段
        .vector(embeddingOf("手机壳"))           // 查询向量（由嵌入模型生成）
        .numCandidates(150)                     // 候选池（> limit，提高召回）
        .limit(10)
        .withSearchScore("score");              // 输出相似度分数字段

AggregationResults<ProductWithScore> results = mongoTemplate.aggregate(
        newAggregation(Product.class, search), ProductWithScore.class);
List<ProductWithScore> hits = results.getMappedResults();
```

| 参数 | 说明 |
|------|------|
| numCandidates | 候选数 = limit 的 10-20 倍（越大召回越好、越慢） |
| limit | 返回条数 |
| filter | `search.filter(Criteria...)` 预过滤（类别/租户/时间） |
| score | `withSearchScore` 把 `vectorSearchScore` 输出成字段 |

### 3.2 带过滤的语义检索

```java
VectorSearchOperation search = VectorSearchOperation.search("product_vector_idx")
        .path("embedding")
        .vector(embeddingOf("夏季连衣裙"))
        .numCandidates(200)
        .limit(20)
        .filter(Criteria.where("category").is("女装")     // 业务过滤与向量检索同查
                .and("price").lte(BigDecimal.valueOf(500)))
        .withSearchScore("score");

AggregationResults<Product> results = mongoTemplate.aggregate(
        newAggregation(Product.class, search), Product.class);
```

> 🎯 面试必答：**"$vectorSearch 怎么和业务条件结合？"**——答两层：① filter 参数（在向量索引上做预过滤，性能最好）；② 管道里先 `$match` 再 `$vectorSearch`（把过滤下沉到查询）；**加分句**：过滤字段必须注册进 VectorIndex 的 filter 列表，否则无法作为预过滤字段。

## 4. @VectorSearch 仓库方法

### 4.1 基本用法（4.0 起支持，4.1 成熟）

```java
public interface ProductRepository extends MongoRepository<Product, String> {

    // 语义相似：按嵌入向量最近邻
    @VectorSearch(indexName = "product_vector_idx", limit = "10", numCandidates = "100")
    SearchResults<Product> findByNameNear(Vector queryVector, Score score);

    // 带距离范围
    @VectorSearch(indexName = "product_vector_idx", limit = "10", numCandidates = "100")
    SearchResults<Product> findByDescriptionWithin(Vector queryVector, Range<Double> maxDistance);

    // 与业务字段组合：方法名派生过滤 + 向量搜索
    @VectorSearch(indexName = "product_vector_idx", limit = "5", numCandidates = "50")
    SearchResults<Product> findByCategoryAndDescriptionNear(String category, Vector queryVector, Score score);
}
```

| 关键词 | 语义 |
|--------|------|
| `Near` | 最近邻（kNN）检索 |
| `Within` | 距离阈值内（Range 上限过滤） |
| `searchTop` / `searchBy` | 组合派生方法的前缀 |

```java
// 使用
Vector queryVec = Vector.of(embeddingOf("手机壳"));
SearchResults<Product> results = productRepository.findByNameNear(queryVec, Score.of("score"));
for (SearchHit<Product> hit : results) {
    Product p = hit.getContent();
    double score = hit.getScore();      // 相似度
}
```

> 💡 执行原理：`@VectorSearch` 由 `VectorSearchAggregation` 执行（内部翻译成 `$vectorSearch` 聚合）——仓库方法与模板 API 同一条引擎路径；**方法名派生的业务条件 = filter 预过滤**。

## 5. 混合检索：全文 + 向量 + $rankFusion

### 5.1 为什么混合检索

```text
纯向量检索：语义相近但"关键词不中"（同义改写）→ 查得到
纯全文检索：精确关键词命中（型号、代码）→ 查得准
混合检索：两者结果用 RRF（Reciprocal Rank Fusion）融合排名 → 又准又全
```

### 5.2 MongoDB 8.3 的 $rankFusion

```java
// 8.3 起：$rankFusion 管道阶段（RRF 算法融合多个检索结果）
Aggregation agg = Aggregation.newAggregation(
        Aggregation.stage("{'$rankFusion': {'input': {" +
                "'pipelines': [" +
                "  {'$search': {'text': {'query': '手机壳', 'path': 'name'}}}," +          // 全文
                "  {'$vectorSearch': {'queryVector': ?, 'path': 'embedding', 'numCandidates': 100, 'limit': 20}}" +
                "], 'fusion': 'rrf'}}}")
);

// 业务上更常见：RRF 之外再叠加业务权重（price/销量）排序
```

| 版本 | 能力 |
|------|------|
| ≤ 8.2 | 手动 RRF：分别查全文 + 向量，应用侧合并排名 |
| **8.3** | `$rankFusion` 原生管道阶段（RRF 融合） |

> 🎯 面试必答：**"RRF 是什么？为什么用 RRF 而不是分数加权？"**——RRF（Reciprocal Rank Fusion）按"排名倒数"融合：`score = Σ 1/(k + rank_i)`（k≈60）——**不依赖不同检索器的分数可比性**（全文 BM25 分数和向量余弦相似度量纲完全不同，直接加权没意义），用排名融合鲁棒且免调参；分数加权需要跨检索器分数归一化（难调）。

## 6. 与 Spring AI / RAG 集成

### 6.1 完整链路

```text
文档/商品数据 ──► 嵌入模型（Spring AI / LangChain4j）
                      │  embedding(float[])
                      ▼
              MongoDB 文档（业务字段 + embedding 字段）
                      │  VectorIndex（第 2 节）
                      ▼
          检索（$vectorSearch / @VectorSearch / 混合检索）
                      │  top-k 相似文档
                      ▼
              拼进 Prompt ──► LLM 生成回答（RAG）
```

### 6.2 Spring AI 嵌入 + MongoDB 检索

```java
// ① 生成嵌入（Spring AI OpenAI/本地模型）
@Autowired EmbeddingModel embeddingModel;
Vector embedding = embeddingModel.embed("手机壳 硅胶 防摔");

// ② 写库（业务事务内：业务字段 + 向量一起落）
Product p = new Product();
p.setName("硅胶手机壳");
p.setEmbedding(embedding.toArray());
productRepository.save(p);

// ③ 检索（语义相似 + 业务过滤）
VectorSearchOperation search = VectorSearchOperation.search("product_vector_idx")
        .path("embedding").vector(embedding.toArray())
        .numCandidates(100).limit(10)
        .filter(Criteria.where("status").is("ON_SALE"));
List<Product> similar = mongoTemplate.aggregate(
        newAggregation(Product.class, search), Product.class).getMappedResults();

// ④ RAG：拼进 Prompt 交给 LLM
String context = similar.stream().map(Product::getDescription).collect(joining("\n"));
```

> 💡 **Spring AI 有现成方案**：`MongoDBVectorStore`（Spring AI 官方集成，`org.springframework.ai:spring-ai-mongodb-store`）——`VectorStore.add(List<Document>)` / `similaritySearch()` 直接可用，底层就是本页 API；自己拼管道适合需要精细控制（过滤/分数/混合检索）的场景（联动见 [RAG 知识体系总览](../../../../../03-AI大模型应用开发/04-RAG检索增强生成/00-RAG知识体系总览.md)）。

### 6.3 与 ES/Milvus 的 RAG 分工（2026 主流）

| 场景 | 首选 | 理由 |
|------|------|------|
| 业务数据 + 语义检索一体（订单/商品/用户） | **MongoDB 向量** | 同库同事务、过滤能力强 |
| 独立大规模知识库（亿级文档） | Milvus / ES | 检索性能与生态更专业 |
| 已有 ES 集群的搜索业务 | ES 向量 | 复用集群与全文能力（[ES 07 篇](../../Spring%20Data%20系列【数据访问层】/Spring%20Data%20Elasticsearch/07-向量检索与RAG集成速查.md)） |

## 7. 能力边界与选型

| 边界 | 说明 |
|------|------|
| 需要 mongot | 向量/全文索引由 Search/Vector 组件提供——Atlas 或企业版；社区版自建需部署 mongot |
| 索引异步 | 建索引后要等 READY；索引构建中查询报错 |
| 过滤字段有限 | 预过滤字段必须注册进 VectorIndex；复杂过滤（范围区间）支持有限制 |
| 无 HNSW 调参暴露 | 索引参数（M/HNSW 参数）由 MongoDB 管理，不像 Milvus 可精细调 |
| 混合检索 | 8.3 $rankFusion 原生支持；8.2 及以下需应用侧 RRF |
| 规模上限 | 千万级向量内推荐；亿级高频检索选专用向量库 |

> 🎯 选型口诀：**"业务向量一体化选 MongoDB，知识库大而专选 Milvus，已有 ES 选 ES"**——MongoDB 向量检索的价值在"少一套系统"，不是"性能碾压"；评审时把这点讲清楚，比堆参数更有说服力。
