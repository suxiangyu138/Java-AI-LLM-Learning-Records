## 1. Artifact 坐标与版本线

| 项 | 值 |
|----|----|
| GroupId | `org.springframework.data` |
| ArtifactId | `spring-data-mongodb` |
| 当前线 | 4.1.x（4.1.0，2026.0 发行列车，2026-08 时点） |
| 稳定线 | 4.0.x（2025.1 列车，Boot 4.0.x） |
| 存量线 | 3.5.x（2025.0 列车，Boot 3.5.x，**已停止维护**） |
| Java 基线 | 21+（随 Boot 4 / Spring Framework 7） |
| 底层驱动 | `mongodb-driver-sync` / `mongodb-driver-reactivestreams` 5.6.x（Boot BOM 管理） |
| 配套 | spring-data-commons、MongoDB 8.x（兼容 6.x~8.x） |

> 💡 版本记忆口诀："**3.x 配 Boot 3，4.x 配 Boot 4**"——2026 年起新项目直接 4.1；服务端大版本（MongoDB 8.x）与驱动**无需逐字一致**，但别用老驱动连新集群（8.x 的 `$vectorSearch` 等新能力老驱动不识别）。

### 1.1 引入方式速查

| 方式 | 写法 | 说明 |
|------|------|------|
| Boot starter（推荐） | `spring-boot-starter-data-mongodb` | 同步版：SDM + mongodb-driver-sync + 自动配置 |
| 响应式 starter | `spring-boot-starter-data-mongodb-reactive` | WebFlux 场景：ReactiveMongoTemplate + 响应式仓库 |
| Maven 显式 | `org.springframework.data:spring-data-mongodb:4.1.0` | 非 Boot 项目或精确控制 |
| Boot 4 BOM | 不写版本号 | `spring-boot-dependencies` 统一管理 |

```xml
<!-- Boot 4 同步版最小依赖 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-mongodb</artifactId>
</dependency>
```

> ⚠️ **版本协调三原则**：① 永远跟 Boot BOM 走，不手写 SDM/驱动版本；② 同步与响应式 starter **二选一**（混用 = 两个连接池 + 心智混乱）；③ 驱动大版本与 MongoDB 服务端对齐（8.x 集群用 5.x 驱动，别混 4.x 老驱动）。

### 1.2 版本坐标速记

| 记忆点 | 数值 |
|--------|------|
| GroupId | `org.springframework.data`（Spring Data 家族统一） |
| 当前主线 | 4.1.x（2026.0 列车，配 Boot 4.1） |

## 2. 包结构地图

```text
org.springframework.data.mongodb
├── repository                              # ★ Repository 体系
│   ├── MongoRepository / ReactiveMongoRepository
│   ├── query
│   │   ├── MongoQueryMethod / PartTreeMongoQuery    # 派生方法 → Query
│   │   ├── MongoQueryExecution / AbstractMongoQuery
│   │   └── VectorSearchAggregation / @VectorSearch  # 向量检索查询（4.x）
│   ├── support
│   │   ├── MongoRepositoryFactory / SimpleMongoRepository  # 默认实现（动态代理目标）
│   │   └── QueryMethodConversionService
│   ├── @Query / @Aggregation / @Modifying（注解定义）
│   └── config（@EnableMongoRepositories）
├── core                                   # ★ 模板与查询核心
│   ├── MongoTemplate / ReactiveMongoTemplate   # 编程式主入口
│   ├── query
│   │   ├── Query / Criteria / Update / Sort   # 链式查询对象
│   │   ├── VectorSearchOperation / VectorIndex # 向量检索（4.x）
│   │   └── TextCriteria / GeoCommand
│   ├── aggregation
│   │   ├── Aggregation / TypedAggregation      # 聚合管道
│   │   └── AggregationOperation 实现（group/match/$lookup/$unwind/$sort）
│   ├── BulkOperations / BulkWriteResult        # 批量操作
│   ├── WriteConcernResolver / ReadPreference   # 读写关注
│   ├── MongoTransactionManager                 # 多文档事务管理器
│   └── index
│       ├── IndexOperations / SearchIndexOperationsProvider  # 索引管理
│       └── VectorIndex（4.x 向量索引）
├── core.convert                                # 类型转换体系
│   ├── MappingMongoConverter                   # POJO ↔ BSON 转换器
│   ├── MongoCustomConversions（自定义读写转换器）
│   └── MongoTypeMapper / DbRefResolver
├── core.mapping                                 # 映射元数据
│   ├── MongoPersistentEntity / MongoPersistentProperty
│   └── MongoMappingContext（注解扫描 @Document）
├── gridfs                                     # 大文件存储
│   ├── GridFsTemplate / GridFsOperations
│   └── GridFSBucket（底层）
├── core.aggregation / core.geo                # 聚合与地理查询
├── domain                                     # 审计（Auditable）
└── config                                     # 编程式配置
    ├── MongoConfigurationSupport / AbstractMongoClientConfiguration
    └── MongoClientSettingsBuilderCustomizer
```

> 💡 记忆抓手：**`SimpleMongoRepository` 是所有 Repository 接口的默认实现**（等价于 JPA 的 SimpleJpaRepository）；编程式操作一律走 **`MongoTemplate`**（查询/更新/聚合/索引/批量/GridFS 全入口）——源码学习从这两个类入手。

### 2.1 运行时对象链

```text
业务代码 → ProductRepository（接口）
        → JDK 动态代理（MongoRepositoryFactory 生成）
        → SimpleMongoRepository（默认实现，含审计/乐观锁钩子）
        → MongoTemplate（查询翻译：派生方法/JSON → Query → BSON）
        → MongoClient（mongodb-driver-sync，连接池 + 协议）
        → MongoDB 8.3 集群（WiredTiger 存储引擎）
```

> 🎯 面试高频：**"Spring Data MongoDB 和原生驱动什么关系？"**——驱动（mongodb-driver）是"能连上 MongoDB 的 TCP/BSON 协议层"，Spring Data MongoDB 在驱动之上提供"对象映射 + 仓库抽象 + 模板便利层"；`MongoTemplate` 内部持有 `MongoClient`（4.x 起由 `MongoClientFactoryBean` 管理）。

## 3. 依赖边界

| 依赖 | 方向 | 说明 |
|------|------|------|
| spring-data-commons | 必须 | Repository/Pageable/Sort/审计等 Spring Data 底座 |
| mongodb-driver-sync | 必须（starter 自带） | 同步驱动（MongoClient 协议实现） |
| mongodb-driver-reactivestreams | 响应式场景 | ReactiveMongoRepository 依赖 |
| mongodb-driver-core | 必须（传递） | BSON 编解码核心 |
| spring-tx | 必须 | MongoTransactionManager（多文档事务） |
| spring-context | 必须 | 事件/审计支持 |
| spring-boot-starter-validation | 可选 | 实体 @Valid 校验（@NotNull/@Size 等） |
| Spring AI / LangChain4j | 可选 | 向量嵌入生成（[08 篇](08-向量检索与AI集成速查.md) 联动） |

### 3.1 依赖方向约定

```text
业务代码
   │  只依赖
   ▼
spring-data-mongodb ──► spring-data-commons ──► spring-core / spring-tx / spring-beans
   │
   ├──► mongodb-driver-sync（协议层，运行时）
   └──► spring-boot-starter-data-mongodb（Boot 视角：一键装配）
```

> 💡 **分层认知**：业务代码**不应该**直接依赖 `com.mongodb.client` 的 Document API（除非特殊场景）——正确姿势是依赖 `org.springframework.data.mongodb` + `org.bson`（类型转换时）；直接用原生驱动写业务 = 丢掉映射与仓库抽象的全部红利。

## 4. 职责切割：SDM vs 驱动 vs MongoDB 引擎

| 层 | 职责 | 典型代码/API | 本系列覆盖 |
|----|------|-------------|-----------|
| **Spring Data MongoDB** | 仓库抽象、对象映射、模板便利、聚合翻译、事务管理 | `MongoRepository`、`MongoTemplate`、`@Document`、`@Aggregation` | ✅ 本系列全部 |
| **mongodb-driver** | TCP 协议、BSON 编解码、连接池、Cursor | `MongoClient`、`Document`、`FindIterable` | 02 篇连接配置落点 |
| **MongoDB 引擎** | 存储（WiredTiger）、索引、复制集、分片、聚合执行 | 服务端能力（$vectorSearch/$lookup） | [MongoDB 深度体系](../../../../02-非关系型数据库/MongoDB/01-MongoDB核心概念与安装配置.md) |
| **Atlas/Enterprise 组件** | Search/Vector 索引（mongot） | 全文/向量检索内核 | 08 篇能力边界 |

### 4.1 典型误判案例

| 现象 | 错误归因 | 正确归因 |
|------|---------|---------|
| 查询慢 | "SDM 太慢" | 没走索引 / 模型设计差（[07 篇](07-索引与性能优化速查.md)） |
| 关联数据查不到 | "框架不支持关联" | 用了 @DBRef 但没解析 / 应该内嵌（[03 篇](03-实体映射与文档注解速查.md)） |
| 事务不回滚 | "事务没用" | 单节点无副本集 / 没配 MongoTransactionManager（[06 篇](06-批量操作与写关注速查.md)） |
| 向量检索报错 | "组件 bug" | 没建 Vector 索引 / mongot 未部署（[08 篇](08-向量检索与AI集成速查.md)） |

> 🎯 一句话：**SDM 只管"API 好不好用"，查询快慢由"索引 + 文档模型 + 集群配置"共同决定**——排障永远从 `explain()` 与慢查询日志开始。

## 5. 版本兼容速查

| 你的项目 | 该用什么 | 迁移成本 |
|---------|---------|---------|
| 新项目（2026） | Boot 4.1 + SDM 4.1 + MongoDB 8.x + Java 21 | — |
| Boot 4.0 存量 | SDM 4.0，升 4.1 无痛（同大版本） | 低 |
| Boot 3.5 存量 | SDM 3.5 + MongoDB 7/8，升 4.x 需 Java 21 + 全量回归 | **高**（[09 篇](09-集成地图与常见问题.md) 迁移清单） |
| Boot 3.3/3.4 存量 | SDM 3.3/3.4，尽快规划升级 | 高 |
| Boot 2.7 存量（2023 前） | SDM 3.2 线 + javax 时代 | 极高（两次大迁移） |

### 5.1 兼容性对照表

| 版本线 | 命名空间 | Spring Framework | MongoDB 服务端 | Java |
|--------|---------|-----------------|---------------|------|
| SDM 4.1.x | `jakarta.*` | 7.0.x | 6.x~8.3（推荐 8.x） | 21+ |
| SDM 4.0.x | `jakarta.*` | 7.0.x | 6.x~8.x | 21+ |
| SDM 3.5.x | `jakarta.*` | 6.2.x | 5.x~7.x | 17+ |
| SDM 3.4.x | `jakarta.*` | 6.1.x | 5.x~7.x | 17+ |
| SDM 3.3.x | `jakarta.*` | 6.1.x | 5.x~6.x | 17+ |
| SDM 2.x | `javax.*` | 5.3.x | 3.x~5.x | 8+ |

> ⚠️ 升级到 4.x 前跑全量测试：类型转换（Enum/日期默认行为）、空值处理（null 字段默认跳过）、聚合翻译的细微变化都会在升级中暴露（[09 篇](09-集成地图与常见问题.md) 有完整清单）。
