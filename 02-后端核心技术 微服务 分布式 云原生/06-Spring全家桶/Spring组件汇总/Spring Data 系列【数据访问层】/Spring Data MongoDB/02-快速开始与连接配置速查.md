## 1. 三步启动最小工程

### 1.1 依赖

```xml
<!-- 同步版：SDM + mongodb-driver-sync 一键装配 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-mongodb</artifactId>
</dependency>

<!-- 响应式版（WebFlux 场景二选一）：
     spring-boot-starter-data-mongodb-reactive  -->
```

| 场景 | 选哪个 |
|------|--------|
| Spring MVC / 常规业务 | `starter-data-mongodb`（同步） |
| WebFlux / 高并发 IO | `starter-data-mongodb-reactive`（响应式） |
| 两者混用 | ❌ 不推荐（双连接池、心智混乱） |

> 💡 依赖最小化原则：**不要**手动引入驱动/BSON 写版本——starter + Boot BOM 已锁定（[01 篇](01-模块清单.md) 版本协调三原则）。

### 1.2 配置文件（application.yml）

```yaml
spring:
  data:
    mongodb:
      uri: mongodb://localhost:27017/shop          # ★ 最简：一条连接串搞定
      auto-index-creation: true                     # 开发期自动按 @Indexed 建索引（生产建议 false + 迁移脚本）
  # 或分段配置（不推荐，uri 优先）：
  #   host: localhost
  #   port: 27017
  #   database: shop
```

| 属性 | 默认 | 说明 |
|------|------|------|
| `spring.data.mongodb.uri` | — | **首选**：标准连接串（可含认证/多节点/参数） |
| `spring.data.mongodb.host` / `port` | localhost / 27017 | 分段写法（存在 uri 时忽略） |
| `spring.data.mongodb.database` | — | 库名（uri 里已带则忽略） |
| `spring.data.mongodb.username` / `password` | — | 认证凭据（uri 里已带则忽略） |
| `spring.data.mongodb.authentication-database` | 同 database | 认证库（admin 等） |
| `spring.data.mongodb.auto-index-creation` | true | 自动建索引（生产建议关） |
| `spring.data.mongodb.gridfs.database` | 同主库 | GridFS 元数据库 |

### 1.3 实体扫描与仓库扫描

| 机制 | 默认行为 | 定制 |
|------|---------|------|
| 实体扫描 | 主启动类所在包及子包 | `@EntityScan` 不适用（MongoDB 用 `@Document` 扫描，Boot 自动按包扫） |
| Repository 扫描 | 主启动类所在包及子包 | `@EnableMongoRepositories(basePackages = "...")` |
| 事务管理器 | 单节点自动跳过；副本集自动配置 | `MongoTransactionManager`（[06 篇](06-批量操作与写关注速查.md)） |

```java
@SpringBootApplication
@EnableMongoRepositories(basePackages = "com.example.shop.repository")
public class ShopApplication { ... }
```

> 💡 多模块工程最常见的坑：**仓库散落在主包之外但忘了声明扫描包** → 启动报"找不到 Repository 实现"（[09 篇](09-集成地图与常见问题.md) 有排错表）。

### 1.4 最小实体 + 仓库跑通

```java
@Document(collection = "user_account")
public class UserAccount {
    @Id private String id;               // String ↔ ObjectId 自动转换
    private String username;
    private LocalDateTime createdAt;

    protected UserAccount() {}           // 框架反序列化需要无参构造
    public UserAccount(String username) { this.username = username; }
    // getter/setter
}

public interface UserAccountRepository extends MongoRepository<UserAccount, String> {
    Optional<UserAccount> findByUsername(String username);
}

// 使用
UserAccount ua = new UserAccount("zhangsan");
userAccountRepository.save(ua);                       // → insert into user_account
Optional<UserAccount> found = userAccountRepository.findByUsername("zhangsan");
```

> 🎯 跑通即及格：**save → findById → findByUsername 三者全通**，说明"映射 + 仓库生成 + 连接"整条链路 OK，可以进 [03 篇](03-实体映射与文档注解速查.md) 学映射细节了。

## 2. Boot 4 属性总表

### 2.1 连接串参数速查（uri query 段）

| 参数 | 默认 | 说明 |
|------|------|------|
| `replicaSet=名字` | — | 指定副本集（从 uri 推导也 OK） |
| `readPreference=primary/secondaryPreferred` | primary | 读偏好（读写分离用 secondaryPreferred） |
| `readConcernLevel=majority` | — | 读关注级别 |
| `writeConcern=w=1/majority` | — | 写关注（[06 篇](06-批量操作与写关注速查.md) 专节） |
| `retryWrites=true` / `retryReads=true` | true（驱动默认） | 网络抖动自动重试（**建议保持开启**） |
| `maxPoolSize=100` | 100 | 连接池上限 |
| `appName=xxx` | — | 集群监控里识别应用名 |
| `connectTimeoutMS` / `serverSelectionTimeoutMS` | 10000 / 30000 | 连接/选服务器超时 |

```yaml
spring:
  data:
    mongodb:
      uri: mongodb://localhost:27017,localhost:27018/shop?replicaSet=rs0&readPreference=secondaryPreferred&appName=shop-service
```

> ⚠️ 排障第一动作：**uri 报错先看 `serverSelectionTimeoutMS`（默认 30s）**——`Timed out after 30000 ms` 时先确认集群可达（mongosh 手动连），再查 uri 格式。

### 2.2 编程式定制（MongoClientSettingsBuilderCustomizer）

```java
@Configuration
public class MongoConfig {
    @Bean
    MongoClientSettingsBuilderCustomizer mongoCustomizer() {
        return builder -> builder
            .applyConnectionString(new ConnectionString("mongodb://localhost:27017/shop"))
            .applyToConnectionPoolSettings(pool -> pool.maxSize(50).minSize(5))
            .applyToServerSettings(srv -> srv.heartbeatFrequency(10, TimeUnit.SECONDS))
            .applicationName("shop-service");
    }
}
```

> 💡 什么时候需要编程式定制：连接池调参、超时调优、TLS 配置、多集群切换（第 5 节）——常规项目 uri 就够，别过度定制。

## 3. 连接定制：MongoClientSettings

| 定制项 | API | 场景 |
|--------|-----|------|
| 连接池 | `applyToConnectionPoolSettings` | maxSize/minSize/maxWaitTime |
| 超时 | `applyToSocketSettings`（connectTimeout/readTimeout） | 慢网络调优 |
| TLS | `applyToSslSettings`（enabled/context） | 加密传输（Atlas 默认 TLS） |
| 服务器选择 | `applyToServerSettings`（heartbeatFrequency） | 心跳频率 |
| 编解码器 | `codecRegistry`（如 UUID 编解码） | 自定义类型 |
| 凭据 | `credential(MongoCredential.createScramSha256Credential(...))` | 编程式认证 |

> ⚠️ Boot 自动配置的 MongoClient 已内置合理默认（连接池 100、retryWrites 等）；定制原则：**只改业务需要的项**，全盘重写易引入兼容问题。

## 4. 认证与安全

| 认证机制 | 连接串写法 | 说明 |
|---------|-----------|------|
| SCRAM-SHA-256 | `mongodb://user:pass@host:27017/db?authSource=admin` | **默认推荐**（8.x 默认机制） |
| SCRAM-SHA-1 | 同左 | 兼容老客户端 |
| X.509 证书 | `?authMechanism=MONGODB-X509` | 企业集群证书认证 |
| LDAP/AD | `?authMechanism=PLAIN` | 企业版 LDAP 集成 |
| Atlas | `mongodb+srv://user:pass@cluster.mongodb.net/db` | SRV 记录自动解析 + TLS 默认开 |

```yaml
spring:
  data:
    mongodb:
      uri: mongodb://shop_user:******@localhost:27017/shop?authSource=admin
```

> ⚠️ 安全红线：① 连接串里的密码**不要硬编码**进 yml——用环境变量/配置中心（`${MONGODB_PASSWORD}`）；② 生产必须 TLS（Atlas 默认；自建集群 `?tls=true`）；③ 用**最小权限账号**（只给业务库读写，不给 admin），别用 root 连接业务。

## 5. 多集群与动态选择

### 5.1 双集群（读写分离 / 分环境）

```java
@Configuration
public class MultiMongoConfig {
    // ① 两个 MongoClient（各自 uri）
    @Bean @Primary
    MongoClient primaryClient() {
        return MongoClients.create("mongodb://primary-host:27017/shop");
    }
    @Bean
    MongoClient secondaryClient() {
        return MongoClients.create("mongodb://secondary-host:27017/shop");
    }

    // ② 两个 MongoTemplate（注入不同 Client）
    @Bean @Primary
    MongoTemplate primaryTemplate(@Qualifier("primaryClient") MongoClient c) {
        return new MongoTemplate(c, "shop");
    }
    @Bean
    MongoTemplate secondaryTemplate(@Qualifier("secondaryClient") MongoClient c) {
        return new MongoTemplate(c, "shop");
    }
}
```

> 💡 更优雅的读写分离：**uri 配 `readPreference=secondaryPreferred`**——驱动自动把读请求发到从节点（副本集内），写仍走主节点，业务代码零改动（比双模板简单得多，前提是集群为副本集）。

### 5.2 动态多租户/多环境

| 场景 | 方案 |
|------|------|
| 按租户分库 | 每请求解析租户 → 动态切换 database（自定义 `MongoDatabaseFactory` 包装） |
| 灰度/双跑 | 两套 MongoTemplate 按开关切换 |
| 跨地域 | uri 配多节点 + readPreference |

> ⚠️ 多数据源三红线（同 JPA 系列）：① 事务别跨库（MongoDB 事务只在单副本集内，[06 篇](06-批量操作与写关注速查.md)）；② 动态切换注意连接池隔离；③ 租户场景优先"单副本集 + 多库"而非多集群（运维成本更低）。

## 6. 常见连接问题排错

| 症状 | 根因 | 排查动作 |
|------|------|---------|
| `Timed out after 30000 ms` | 集群不可达 / uri 错 / 防火墙 | `mongosh mongodb://host:27017` 手动连；检查安全组 |
| `Authentication failed` | 账号密码错 / authSource 错 | 用 mongosh 验证凭据；确认 authSource（admin 还是业务库） |
| `Connection refused` | 服务没起 / 端口错 | `docker ps` / `netstat` 确认 27017 监听 |
| `Invalid connection string` | uri 格式错误 | 检查 `mongodb://` 前缀、特殊字符转义（密码含 `@` 需 `%40`） |
| 连接被频繁断开 | 心跳超时 / 池配置与集群不匹配 | 检查 heartbeatFrequency、maxPoolSize 与集群负载 |
| 认证机制不匹配 | 服务端 SCRAM 版本与客户端默认不同 | 显式 `?authMechanism=SCRAM-SHA-256` |
| TLS 报错 | Atlas 默认 TLS，本地未配置 | uri 加 `?tls=true` 或用 srv 前缀（自动 TLS） |

> 🎯 排障顺序铁律：**集群层（mongosh 能连吗）→ 连接层（uri/认证对吗）→ 映射层（字段对得上吗）→ 查询层（explain 对吗）**——从下往上，90% 的"启动失败"在集群/连接层解决。
