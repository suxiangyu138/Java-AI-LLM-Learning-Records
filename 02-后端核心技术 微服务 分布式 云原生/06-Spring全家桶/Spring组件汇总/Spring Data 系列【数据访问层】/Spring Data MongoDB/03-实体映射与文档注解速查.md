## 1. 文档映射基础：@Document 与 @Id

### 1.1 @Document

| 属性 | 默认 | 说明 |
|------|------|------|
| `collection` | 类名首字母小写（Product → product） | 指定集合名 |
| `language` | — | 全文索引的语言覆盖 |
| `collation` | — | 排序规则（大小写/语言排序） |

```java
@Document(collection = "product")
public class Product {
    @Id private String id;
    // ...
}
```

> 💡 集合名显式指定的原因：类名重构（改名）时集合不跟着变，历史数据不受影响——**生产集合名一经使用不再改**。

### 1.2 @Id 的四种形态

| @Id 类型 | 落库形态 | 适用 |
|---------|---------|------|
| `String` | ObjectId（自动转换，12 字节可排序） | **默认推荐** |
| `ObjectId` | ObjectId | 需要原生类型操作 |
| `UUID` | BinData（需要注册 UUID 转换） | 分布式/外部系统对接 |
| 自定义对象 | 复合文档（可含业务键） | 复杂主键（类似 JPA 复合主键） |

```java
@Document
public class OrderEntity {
    @Id private String id;        // save 后自动回填 ObjectId 的字符串形态
}
```

> ⚠️ **业务键 ≠ @Id**：`@Id` 是文档主键（MongoDB 强制），业务唯一键（订单号、流水号）应另设字段 + 唯一索引（`@Indexed(unique = true)`）——用业务键当 @Id 会丢失 ObjectId 的自动生成与排序优势（[07 篇](07-索引与性能优化速查.md) 有对比）。

### 1.3 record 实体（4.x 支持完善）

```java
@Document(collection = "product")
public record Product(
        @Id String id,
        String name,
        @Field("price_cny") BigDecimal price,     // @Field 指定字段名
        @Indexed(unique = true) String sku) {}    // 字段级索引
```

> 💡 record 做文档实体：不可变、简洁（推荐新代码）；注意**必须有默认构造或参数名保留**（编译加 `-parameters` 或显式构造器），否则反序列化失败。

## 2. 字段映射速查

### 2.1 @Field

| 属性 | 默认 | 说明 |
|------|------|------|
| `name` | 属性名原样（**不做驼峰转换**） | 指定 BSON 字段名（JPA 会下划线，Mongo 不会！） |
| `targetType` | — | 强制写入目标类型（如 long → String） |
| `nullValue` | NullHandling.NATIVE | 空值处理：SKIP（不写字段）/ SET（写 null）/ NATIVE（保留） |

> ⚠️ **最大命名差异**：JPA 自动驼峰→下划线，**MongoDB 默认字段名 = Java 属性名**（`createdAt` 就存 `createdAt`，不是 `created_at`）——想用下划线风格必须 `@Field("created_at")` 逐字段指定；用 MongoDB 深度体系的 shell/聚合脚本对字段时，名称必须与这里对齐。

### 2.2 常用类型映射表

| Java 类型 | BSON 形态 | 说明 |
|-----------|----------|------|
| `String` | String | 常规 |
| `int/long/double` | 数值 | 注意 long 大值跨语言精度（JS 端会丢精度） |
| `BigDecimal` | Decimal128 | **金额用 Decimal128**（默认转换器自动支持） |
| `boolean` | Bool | 常规 |
| `LocalDate/LocalDateTime` | Date（UTC 毫秒） | **读回自动转本地时区**（存储始终 UTC，见 [09 篇](09-集成地图与常见问题.md) 时区坑） |
| `java.util.Date` | Date | 老 API，新代码用 java.time |
| 枚举 | String（默认） | 存名字（EnumType 不可配，想要数字存序数需自定义转换器） |
| `Map<String,Object>` | 内嵌文档 | 动态字段场景 |
| `List<T>` | 数组 | 常规 |
| `byte[]` | BinData | 小二进制（大文件走 GridFS，[09 篇](09-集成地图与常见问题.md)） |
| `ObjectId` | ObjectId | @Id 或显式字段 |
| `float[]` | 数组 | 向量字段（[08 篇](08-向量检索与AI集成速查.md) 配 VectorIndex） |

### 2.3 字段级索引注解

| 注解 | 说明 | 示例 |
|------|------|------|
| `@Indexed` | 单字段索引 | `@Indexed(unique = true)` 唯一索引（幂等方案常用，思路同 [名词系列-幂等与防抖](../../../../09-Web开发全流程/后端 分布式常用名词通俗解释/04-重复请求治理：幂等与防抖.md)） |
| `@CompoundIndex` | 复合索引 | `@CompoundIndex(def = "{'category':1, 'price':-1}")` |
| `@TextIndexed` | 全文索引字段 | `@TextIndexed` 参与文本搜索 |
| `@GeoSpatialIndexed` | 地理索引 | 附近的人/门店 |
| `@HashIndexed` | 哈希索引 | 分片键哈希 |
| `@WildcardIndexed` | 通配索引（8.x） | 动态字段全部可索引 |

```java
@Document(collection = "product")
@CompoundIndex(def = "{'category': 1, 'price': -1}", name = "idx_cat_price")
public class Product {
    @Id private String id;
    private String category;
    private BigDecimal price;
    @Indexed(unique = true) private String sku;
}
```

> 💡 索引生命周期：开发期 `auto-index-creation: true` 自动建；**生产关闭**，用迁移脚本（mongo-shell 脚本/部署流程）显式管理——与 JPA 的 ddl-auto 同理（[02 篇](02-快速开始与连接配置速查.md)）。索引细节与选型见 [07 篇](07-索引与性能优化速查.md)。

## 3. 内嵌文档与 @DBRef

### 3.1 内嵌文档（推荐主力）

```java
// 内嵌：地址作为文档的一部分（订单里有收货地址）
@Document(collection = "order")
public class OrderEntity {
    @Id private String id;
    private Address address;          // 内嵌文档（无独立集合）
    private List<OrderItem> items;    // 内嵌数组（子项不单独存）
    // getter/setter
}

public record Address(String province, String city, String detail) {}
```

| 内嵌优点 | 内嵌代价 |
|---------|---------|
| 一次查询拿到全部（无 join） | 数据冗余（用户改了地址，历史订单里的旧地址不会变——**这通常是想要的**） |
| 原子更新（整个文档一个事务单元） | 文档变大（16MB 上限） |
| 符合"按查询建模" | 无法独立查询/更新子文档（要 $ 位置运算符） |

> 🎯 **内嵌优先原则**：**"总是和父文档一起读、生命周期从属于父文档"的数据 → 内嵌**（订单明细、收货地址、评论列表）——MongoDB 文档模型的第一原则，[07 篇](07-索引与性能优化速查.md) 有完整决策表。

### 3.2 @DBRef（引用，慎用）

```java
@Document(collection = "order")
public class OrderEntity {
    @Id private String id;
    @DBRef private UserAccount user;       // 引用另一个集合的文档
}
```

| @DBRef 特性 | 说明 |
|------------|------|
| 存储 | 只存 `{"$ref": "user_account", "$id": "..."}` 引用标记 |
| 查询 | **默认不自动加载**（要 `@Query` 显式加载或手动转换）；反序列化时会解析（有性能开销） |
| 无级联 | 删除/更新被引用文档不影响引用方（无外键约束） |
| 事务 | 不参与引用方事务（跨文档事务不含它） |
| **适用** | 真正的"多对多共享数据"（用户↔角色）或必须独立存活的数据 |

> ⚠️ **@DBRef 是 MongoDB 里被误用最多的特性**：JPA 习惯了就下意识给所有关联加 @DBRef——结果查询 N+1、无约束、无级联，全踩一遍。**决策表**：和父文档同读同灭 → 内嵌；独立生命周期且"一起读"是常态 → 干脆冗余一份或分两次查；只有"共享引用 + 极少一起查"才用 @DBRef（[07 篇](07-索引与性能优化速查.md) 设计模式专节）。

## 4. 类型转换体系

### 4.1 转换链路

```text
Java 属性 ←→ 自定义转换器（MongoCustomConversions）
          ←→ 默认转换器（MappingMongoConverter 内置：String/ObjectId/Date/Decimal128...）
          ←→ BSON 文档（org.bson 类型）
```

### 4.2 自定义转换器（枚举转序数 / 自定义对象）

```java
// 枚举 → 存序数（跨语言数值对接）
@WritingConverter
public class StatusToIntConverter implements Converter<OrderStatus, Integer> {
    @Override public Integer convert(OrderStatus source) { return source.ordinal(); }
}

@ReadingConverter
public class IntToStatusConverter implements Converter<Integer, OrderStatus> {
    @Override public OrderStatus convert(Integer source) { return OrderStatus.values()[source]; }
}

@Configuration
public class MongoConvertersConfig {
    @Bean
    MongoCustomConversions customConversions() {
        return new MongoCustomConversions(List.of(
                new StatusToIntConverter(), new IntToStatusConverter()));
    }
}
```

> 💡 转换器注册后全局生效（所有映射走它）；注意 **@WritingConverter/@ReadingConverter 区分方向**，写错方向会陷入死循环或无效。

## 5. @Version 乐观锁与审计

### 5.1 @Version 乐观锁

```java
@Document(collection = "product")
public class Product {
    @Id private String id;
    private BigDecimal price;
    @Version private Long version;      // 版本字段（数字，首次 save 自动置 0/1）
}

// 并发更新：save 时执行 CAS
//   UPDATE 语义：{_id: id, version: 旧值} → {$set: {price: 新值, version: 旧值+1}}
//   影响 0 条 → OptimisticLockingFailureException（JPA 同款异常语义）
```

| 要点 | 说明 |
|------|------|
| 触发 | save / 更新（模板操作）时带版本条件 |
| 冲突异常 | `OptimisticLockingFailureException`（Spring 统一） |
| 适用 | 更新型文档的并发控制（金额、状态字段） |
| 批量 | 批量操作/原生驱动绕过版本校验（与 JPA 相同边界） |

> 🎯 与 JPA 系列对比：**@Version 语义完全一致**（CAS + 重试），会 [JPA 乐观锁](../../Spring%20Data%20系列【数据访问层】/Spring%20Data%20JPA/06-事务与并发控制速查.md) 的同学零迁移成本；注意 MongoDB 没有"行锁"概念（文档级原子），高冲突写场景靠文档原子更新 + 重试。

### 5.2 审计

```java
@Configuration
@EnableMongoAuditing
public class MongoAuditingConfig { }

@Document
public class Product {
    @CreatedDate private LocalDateTime createdAt;      // insert 自动填
    @LastModifiedDate private LocalDateTime updatedAt; // 更新自动改
    @CreatedBy private String createdBy;               // 操作者（AuditorAware）
    @LastModifiedBy private String updatedBy;
}
```

> 💡 与 JPA 审计同一套注解语义（`AuditorAware` 取当前用户），全家族统一——[JPA 08 篇](../../Spring%20Data%20系列【数据访问层】/Spring%20Data%20JPA/08-审计事件与多租户速查.md) 的用法直接搬。

## 6. 数据校验与空值处理

### 6.1 Bean Validation

```java
@Document(collection = "user_account")
public class UserAccount {
    @Id private String id;
    @NotBlank @Size(max = 32) private String username;   // jakarta.validation 注解
    @Email private String email;
    @NotNull private Integer age;
}
```

> 💡 与 JPA 相同：`spring-boot-starter-validation` + 控制器 `@Valid` 触发；**save 不自动校验**（校验在入口层，不在仓库层）——与 JPA 语义一致。

### 6.2 空值处理

| 配置 | 行为 |
|------|------|
| 默认 | null 字段**不写入文档**（文档里没有该字段，不是 null）——字段可选性天然 |
| `@Field(nullValue = NullHandling.SET)` | 显式写 null |
| 查询语义 | `findByField(null)` 匹配"字段不存在或为 null"——注意与 JPA 的 IS NULL 差异 |

> ⚠️ **"字段不存在" vs "字段为 null"是两回事**（MongoDB 无强 schema）：`exists: true` 查询才能区分——派生方法 `findByXxxExists(true)` 可用；这是迁移自 JPA 最容易踩的语义坑（[09 篇](09-集成地图与常见问题.md)）。

## 7. 映射设计红线

| # | 红线 | 理由 | 正确姿势 |
|---|------|------|---------|
| 1 | 下意识 @DBRef | N+1、无级联、无约束 | 内嵌优先（第 3 节决策表） |
| 2 | 用业务键当 @Id | 丢 ObjectId 优势 | 独立 @Id + 业务键唯一索引 |
| 3 | 金额用 double | 精度丢失 | BigDecimal → Decimal128 |
| 4 | 字段名依赖 Java 属性 | 与 shell/聚合脚本对不上 | 显式 @Field 命名约定（团队统一 camelCase 或 snake_case） |
| 5 | 大字段内嵌 | 16MB 文档上限 | GridFS（>16MB）/ 独立集合存引用 |
| 6 | 忘记 @Version | 并发覆盖丢数据 | 更新型文档加版本字段 |
| 7 | 无索引直接上线 | 全集合扫描 | 查询字段 @Indexed（[07 篇](07-索引与性能优化速查.md)） |
| 8 | 多级深层内嵌（>3 层） | 查询/更新复杂度爆炸 | 扁平化或拆集合 |
| 9 | 枚举存序数不注册转换器 | 加枚举值错位（与 JPA ORDINAL 同坑） | 默认存名字；要序数注册转换器 |
| 10 | 忽略 UTC 时区 | 日期差 8 小时（[09 篇](09-集成地图与常见问题.md)） | 存储 UTC，展示层转本地 |

> 🎯 映射自检清单（写新实体前过一遍）：集合名显式了吗？@Id 是 ObjectId 形态吗？关联是内嵌吗？金额用 BigDecimal 了吗？枚举处理对了吗？更新型字段有 @Version 吗？查询字段有索引吗？——七问全过再落代码。
