## 1. MongoTemplate：编程式查询的最终出口

**通俗**：Repository 是"写好的接口"，MongoTemplate 是"手里直接拿锤子"——所有查询（含 Repository 内部实现）最终都走它。

```java
@Service
@RequiredArgsConstructor
public class ProductService {
    private final MongoTemplate mongoTemplate;    // 直接注入

    public List<Product> search(String category, BigDecimal min, BigDecimal max, int limit) {
        Query query = new Query();
        if (category != null) {
            query.addCriteria(Criteria.where("category").is(category));
        }
        if (min != null && max != null) {
            query.addCriteria(Criteria.where("price").gte(min).lte(max));
        }
        query.with(Sort.by("price").descending()).limit(limit);
        return mongoTemplate.find(query, Product.class);
    }
}
```

| 能力域 | 模板 API | 说明 |
|--------|---------|------|
| 查询 | `find/findOne/findById/exists/count` | Query 对象翻译成 BSON |
| 更新 | `updateFirst/updateMulti/findAndModify/upsert` | Update 对象 |
| 聚合 | `aggregate(Aggregation, 类, 结果类)` | 管道执行 |
| 索引 | `indexOps(类)` | IndexOperations 管理 |
| 批量 | `bulkOps` | 批量写 |
| 文件 | `GridFsTemplate` | 大文件存储 |
| 会话/事务 | `withSession` / `executeInTransaction` | 多文档事务 |
| 地理 | `geoNear` / `findNear` | 地理查询 |

> 🎯 **什么时候用模板**：动态条件任意组合、Repository 派生方法表达不了、需要直接操作索引/批量/事务、写工具类/框架代码——**模板是"兜底出口"，Repository 是"声明式入口"**，两者可以混用（模板查的实体与 Repository 同一套映射）。

## 2. Criteria 条件构造速查

### 2.1 常用条件

```java
// 基础
Criteria.where("name").is("手机");                        // = 
Criteria.where("price").gte(100).lt(5000);                // 链式区间
Criteria.where("status").in("ON", "PAUSED");              // in
Criteria.where("status").nin("DELETED");                  // not in
Criteria.where("stock").gt(0);                            // >

// 字符串/正则
Criteria.where("name").regex("^华为", "i");               // 正则（i=忽略大小写）
Criteria.where("name").contains("手机");                  // 包含（转义自动处理）

// 空值与存在
Criteria.where("deletedAt").exists(false);                // 字段不存在
Criteria.where("deletedAt").isNull();                     // 为 null 或不存在

// 数组
Criteria.where("tags").size(3);                           // 数组长度
Criteria.where("items").elemMatch(Criteria.where("sku").is("A001").and("qty").gt(2));
Criteria.where("items.sku").is("A001");                   // 数组元素直接匹配

// 逻辑组合
new Criteria().andOperator(c1, c2);                       // AND
new Criteria().orOperator(c1, c2);                        // OR
Criteria.where("category").is("手机").orOperator(
        Criteria.where("price").lt(100), Criteria.where("price").gt(9000));
```

### 2.2 空值陷阱（与 SQL 的差异）

| 写法 | 语义 | SQL 对照 |
|------|------|---------|
| `is(null)` | 字段**不存在或为 null** | `IS NULL`（但 SQL 的 NULL 不匹配空字符串） |
| `exists(false)` | 字段**不存在** | 无对应（schema 强制的 SQL 没有"无此列"） |
| `ne(null)` | 字段**存在且非 null** | `IS NOT NULL` |

> ⚠️ 记忆点：**MongoDB 里"字段不存在"和"字段为 null"查询结果一样（都是 `is(null)` 命中）**，要区分必须 `exists`——这是从 SQL/JPA 迁移过来最高频的查询语义差异（[03 篇](03-实体映射与文档注解速查.md) 6.2 同步提醒）。

## 3. Query / Update 对象速查

### 3.1 Query 对象

```java
Query query = new Query();

// 条件
query.addCriteria(Criteria.where("status").is("ON"));
// 排序/分页
query.with(Sort.by(Sort.Order.desc("createdAt"), Sort.Order.asc("id")));
query.skip(20).limit(10);                     // 分页（深分页慎用 skip，[04 篇](04-Repository速查.md) 6 节）
// 投影
query.fields().include("name", "price").exclude("_id");   // include/exclude 二选一混用有坑
// 提示/注释
query.comment("find-products-by-category");   // 慢查询日志可追踪
// 游标
query.cursorBatchSize(100);                   // 大数据量分批读

List<Product> products = mongoTemplate.find(query, Product.class);
```

### 3.2 Update 对象

```java
Update update = new Update();

update.set("price", new BigDecimal("3999"));       // $set
update.inc("stock", -1);                           // $inc 原子自减（防超卖核心）
update.push("tags", "新品");                        // $push 数组追加
update.pull("tags", "下架");                        // $pull 数组移除
update.unset("deletedAt");                         // $unset 删字段
update.setOnInsert("createdAt", LocalDateTime.now());  // upsert 插入时才设置

// 应用
mongoTemplate.updateFirst(Query.query(Criteria.where("id").is("123")), update, Product.class);
mongoTemplate.updateMulti(Query.query(Criteria.where("category").is("手机")), update, Product.class);
mongoTemplate.upsert(Query.query(Criteria.where("sku").is("A001")), update, Product.class);
```

| 更新方法 | 语义 | 场景 |
|---------|------|------|
| `updateFirst` | 更新匹配的第一条 | 单条更新 |
| `updateMulti` | 更新所有匹配 | 批量改状态（库存全量上架） |
| `upsert` | 匹配则更新，不匹配则插入 | 幂等写入/累加器 |
| `findAndModify` | 更新并返回更新后的文档 | 需要旧值/新值的原子操作 |

> 🎯 **$inc vs 读-改-写**：并发场景（库存、计数、余额）永远用 `$inc` 原子操作，禁止"find → 改内存 → save"三步（并发必丢更新）；需要"不能扣成负数"的校验时用条件更新（`$inc` 前检查或 `findAndModify` + 条件）。

## 4. 聚合管道：TypedAggregation

### 4.1 编程式管道（动态拼接）

```java
import static org.springframework.data.mongodb.core.aggregation.Aggregation.*;

Aggregation agg = Aggregation.newAggregation(
        match(Criteria.where("createdAt").gte(start)),
        group("category").count().as("count")
                        .sum("totalAmount").as("amount"),
        project("count", "amount").and("category").previousOperation(),
        sort(Sort.by(Sort.Order.desc("amount"))),
        limit(10)
);
AggregationResults<CategoryStat> results =
        mongoTemplate.aggregate(agg, OrderEntity.class, CategoryStat.class);
List<CategoryStat> stats = results.getMappedResults();
```

| 阶段静态方法 | 对应管道 | 说明 |
|-------------|---------|------|
| `match(Criteria)` | $match | 过滤（放最前） |
| `group(...)` | $group | `group("字段").count().as("别名").sum(...).as(...)` |
| `project(...)` | $project | 投影与计算列 |
| `sort(...)` / `limit(n)` / `skip(n)` | 排序/限量/跳过 | 顺序敏感 |
| `unwind("$items")` | $unwind | 数组展开 |
| `lookup(from, localField, foreignField, as)` | $lookup | 有限 join |
| `replaceRoot` / `addFields` | 换根/加字段 | 重构文档形态 |
| `facet` / `bucket` | 分面/分桶 | 多维统计 |

> ⚠️ 管道性能铁律：**`$match` 永远放第一个阶段**（先缩数据量）；`$lookup` 的被连接集合必须有索引；`$group` 的字段要有对应索引（8.x 支持部分管道索引优化）。管道写法的完整语义见 [MongoDB 深度体系-03 索引与聚合](../../../../02-非关系型数据库/MongoDB/03-MongoDB索引与聚合操作.md)。

### 4.2 @Aggregation 与模板的选择

| 场景 | 用哪个 |
|------|--------|
| 固定管道（参数少） | Repository @Aggregation（[04 篇](04-Repository速查.md) 4 节） |
| 动态管道（阶段数量不定） | 模板 TypedAggregation |
| 结果要分页/排序组合 | 模板（灵活组装） |
| 团队规范集中管理 | Repository 注解 |

> 💡 结果投影接口（CategoryStat）自动映射：管道输出字段名与接口 getter 对齐（`count` ↔ `getCount()`）；管道里 `_id` 默认是分组键，要取回原字段名用 `.as()` 或 `previousOperation()`。

## 5. 投影与字段过滤

### 5.1 查询投影（少取字段）

```java
// 模板
Query query = new Query(Criteria.where("category").is("手机"));
query.fields().include("name", "price");          // 只取 name/price（_id 默认含）
query.fields().exclude("description", "attributes");  // 排除大字段
mongoTemplate.find(query, Product.class);

// Repository
@Query(value = "{'category': ?0}", fields = "{'name': 1, 'price': 1}")
List<Product> findProjected(String category);
```

| 注意 | 说明 |
|------|------|
| include 与 exclude 混用 | **不能混用**（除 _id 外）——要么全含要么全排 |
| 投影 + 实体映射 | 未取的字段为 null（实体字段可能为 null，注意 NPE） |
| 性能意义 | 少传输大字段（description/图片数据），配合覆盖索引 |

### 5.2 聚合投影

```java
project("name", "price")                        // 保留字段
project().andExclude("attributes")              // 排除
project().and("month").dateOperators().monthOfYear("createdAt")  // 日期计算列
```

> 💡 投影是"索引覆盖查询"的前提：只查索引内字段 → 索引扫描不读文档（[07 篇](07-索引与性能优化速查.md) 覆盖索引节）。

## 6. 文本与地理查询

### 6.1 文本搜索（需 Text Index）

```java
// 实体建文本索引（03 篇 @TextIndexed）
// 查询：
TextCriteria tc = TextCriteria.forDefaultLanguage()
        .matchingPhrase("华为手机")              // 短语匹配
        .caseSensitive(false);
Query query = TextQuery.queryText(tc).sortByScore();   // 按相关度排序
List<Product> products = mongoTemplate.find(query, Product.class);
```

> ⚠️ 文本搜索边界：MongoDB 文本索引是**分词式全文搜索**（英文友好，中文需自定义分词器/或走 ES）；中文语义搜索 2026 主流方案是向量检索（[08 篇](08-向量检索与AI集成速查.md)）或 [Spring Data Elasticsearch](../../Spring%20Data%20系列【数据访问层】/Spring%20Data%20Elasticsearch/00-Spring%20Data%20Elasticsearch组件总览.md)。

### 6.2 地理查询（需 Geo Index）

```java
// 附近的门店
GeoResults<Store> results = mongoTemplate.geoNear(
        NearQuery.near(new Point(lng, lat))
                .maxDistance(Distance.between(5, Metrics.KILOMETERS))
                .limit(20),
        Store.class);
// 圈内查询
Query query = new Query(Criteria.where("location")
        .withinSphere(new Circle(new Point(lng, lat), Distance.between(5, Metrics.KILOMETERS))));
```

> 💡 地理索引 `@GeoSpatialIndexed`（2dsphere）+ 地理查询是 MongoDB 强项（周边人/店/车场景），坐标用 GeoJSON `{"type": "Point", "coordinates": [lng, lat]}`（**注意顺序：经度在前**）。

## 7. 模板 vs Repository 选型

| 维度 | Repository | MongoTemplate |
|------|-----------|---------------|
| 学习成本 | 低（声明式） | 中（编程式） |
| 动态条件 | 派生方法难表达 | ✅ 天然支持 |
| 复杂管道 | @Aggregation 固定管道 | ✅ 动态拼接 |
| 索引/批量/事务 | 无直接 API | ✅ 全能力 |
| 类型安全 | 方法名解析 | 字符串属性（4.1 起类型安全路径） |
| 适用 | 常规 CRUD 与固定查询（**默认首选**） | 动态查询/聚合/管理类操作（**兜底出口**） |

> 🎯 工程惯例：**业务查询优先 Repository（可读可测可审计），模板收敛到"复杂查询服务"或"基础设施代码"**——两套混用时保持映射一致（同一实体、同一转换器），别在模板里写一套字段名、Repository 里写另一套。
