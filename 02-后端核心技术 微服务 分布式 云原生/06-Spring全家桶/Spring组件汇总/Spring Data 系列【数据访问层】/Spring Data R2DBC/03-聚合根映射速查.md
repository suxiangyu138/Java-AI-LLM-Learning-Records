## 1. 聚合根模型：放下三样东西

**通俗**：R2DBC 的数据模型是"聚合根"——**一个实体 = 一个表的一行**，实体里只有标量字段和嵌入值对象，**没有对象关联导航**。

| 从 JPA 带来的习惯 | R2DBC 的答案 | 替代方案 |
|------------------|-------------|---------|
| **懒加载**（`order.getItems()` 自动查） | ❌ 不存在（没有代理） | 手写 join SQL / 分次查询 |
| **一级缓存**（同事务同实体只查一次） | ❌ 不存在（无持久化上下文） | 应用层缓存（Caffeine/Redis） |
| **脏检查**（改属性自动 UPDATE） | ❌ 不存在 | **显式 save/update**（改完必须调更新） |
| 关联映射（@OneToMany/@ManyToOne） | ❌ 无关联注解 | 聚合根 + 手写 SQL（DatabaseClient） |
| 级联操作 | ❌ 无 | 显式事务里逐表操作 |

> 🎯 面试必答：**"R2DBC 为什么不用 JPA 的关联模型？"**——三层答案：① 关联导航依赖"代理 + 持久化上下文"（懒加载/缓存/脏检查的底座），而响应式模型里**连接不绑定线程、上下文无法跨异步边界维护**；② 聚合根模型把"对象图"换成"显式 SQL"，**查询意图完全透明**（没有 ORM 生成层的黑盒）；③ 取舍结果：**牺牲便利，换来非阻塞与 SQL 可控**——复杂关联场景配 DatabaseClient 手写 join 是官方推荐姿势。

## 2. 表与字段映射

### 2.1 @Table 与 @Column

```java
@Table("product")                    // 表名（默认：类名）
public class Product {
    @Id private Long id;
    @Column("product_name") private String name;   // 列名（默认：属性名）
    private BigDecimal price;
}
```

| 注解 | 默认行为 | 说明 |
|------|---------|------|
| `@Table` | 类名（Product → product） | 显式指定表名 |
| `@Id` | — | 主键（自增/序列/UUID） |
| `@Column` | 属性名（**不做驼峰转换**） | 列名覆盖 |
| `@Transient` | — | 不入库字段 |
| `@Version` | — | 乐观锁版本列（第 5 节） |
| `@CreatedDate` 等审计 | — | 审计字段（第 6 节） |

> ⚠️ **与 JPA 的关键差异**：R2DBC 默认列名 = Java 属性名原样（`createdAt` 就查 `createdAt` 列，不是 `created_at`）——与 MongoDB 系列一致、与 JPA 相反；4.0 起标识符默认**带引号**（大写/保留字行为更稳），迁移时注意表列大小写敏感性（[09 篇](09-集成地图与常见问题.md)）。

### 2.2 类型映射表

| Java 类型 | 数据库列 | 说明 |
|-----------|---------|------|
| `Long/Integer` | BIGINT/INT | 常规 |
| `String` | VARCHAR | 常规 |
| `BigDecimal` | DECIMAL | **金额必用** |
| `boolean` | BOOLEAN/TINYINT | 常规 |
| `LocalDate/LocalDateTime/Instant` | DATE/DATETIME/TIMESTAMP | **存储建议 TIMESTAMP + UTC 约定**（同 JPA 时区坑） |
| `byte[]` | BLOB | 小二进制 |
| 枚举 | VARCHAR（默认转名字） | 4.x 支持枚举映射（名或序数按配置） |
| UUID | CHAR(36)/BINARY(16) | 主键备选 |

> 💡 无独立"转换器注册中心"（区别于 MongoDB 的 MongoCustomConversions）：类型映射由 `R2dbcTypeMapper` + 驱动编解码共同决定；特殊类型（JSON 列、数组列）走 `@Query` SQL 直写 + 手动转换更直接（[05 篇](05-查询构造与DatabaseClient速查.md)）。

## 3. 主键与复合主键

### 3.1 主键生成策略

| 策略 | 做法 | 适用 |
|------|------|------|
| 自增（默认） | `@Id Long id`，save 后回填 | MySQL/SQL Server |
| 序列 | 数据库序列（PG/Oracle） | PostgreSQL |
| UUID | `@Id UUID id` 应用生成 | 分布式/无中心 |
| 业务键 | 手动赋值 | 已有业务主键 |

```java
// 自增主键：save 后自动回填（无需配置）
@Table("product")
public class Product {
    @Id private Long id;
    // ...
}

// UUID 主键：应用生成（与 JPA 相同姿势）
@Table("order_entity")
public class OrderEntity {
    @Id private UUID id = UUID.randomUUID();
}
```

### 3.2 复合主键（4.0 支持完善）

```java
// ① 主键类（必须实现 Serializable + equals/hashCode）
public class OrderItemKey implements Serializable {
    private Long orderId;
    private Long itemNo;
    // getter/setter + equals/hashCode
}

// ② 实体用 @IdClass（同 JPA 风格）
@Table("order_item")
@IdClass(OrderItemKey.class)
public class OrderItem {
    @Id private Long orderId;
    @Id private Long itemNo;
    private Integer qty;
}
```

> 💡 4.0 起复合主键（@IdClass）与嵌入实体支持完善——迁移老 JPA 项目的复合键表可以直接平移；单一自增主键仍是默认推荐（复合键查询/更新都更繁琐）。

## 4. @Embedded 嵌入值对象

```java
@Table("order_entity")
public class OrderEntity {
    @Id private Long id;
    @Embedded private Address address;     // 嵌入值对象（列平铺）
}

public class Address {
    private String province;              // 列：province
    private String city;                  // 列：city
    // getter/setter
}
```

| 要点 | 说明 |
|------|------|
| 落库 | 嵌入对象的字段**平铺成列**（order_entity.province/city） |
| 嵌套 | 可多层嵌入（@Embedded 内再 @Embedded） |
| 与 JPA 差异 | 无 `@AttributeOverrides`（JPA 的多实例列名覆盖）——同名嵌入对象实例多个需手动改名 |
| 查询 | 嵌入字段参与条件（`Criteria.where("address.city")`） |

> 💡 适用：地址、金额对、坐标等"值对象"——聚合根模型的组合方式；注意与 MongoDB 内嵌的差异：**R2DBC 的嵌入是"列平铺"，不是嵌套文档**。

## 5. @Version 乐观锁

```java
@Table("product")
public class Product {
    @Id private Long id;
    private BigDecimal price;
    @Version private Long version;        // 版本列（int/long）
}

// 更新语义（同 JPA）：
//   UPDATE product SET price=?, version=version+1 WHERE id=? AND version=旧值
//   影响 0 行 → OptimisticLockingFailureException
```

| 要点 | 说明 |
|------|------|
| 触发 | `save`（含 update 语义）/ `R2dbcEntityTemplate.update` 时带版本条件 |
| 冲突异常 | `OptimisticLockingFailureException`（Spring 统一，可重试） |
| 显式更新 | **无脏检查**——改完属性必须显式 save/update 才落库，版本校验在这时发生 |
| 批量 | 批量/原生 SQL 绕过版本（手动加 where version 条件） |

> 🎯 与 JPA 同语义（[JPA 06 篇](../../Spring%20Data%20系列【数据访问层】/Spring%20Data%20JPA/06-事务与并发控制速查.md) 乐观锁）：**面试答"R2DBC 并发控制"就说 @Version + CAS + 重试**，语义零迁移；注意响应式下重试用 `.retryWhen(...)`（[06 篇](06-响应式事务与并发控制速查.md)）。

## 6. 审计与类型转换

### 6.1 审计

```java
@Configuration
@EnableR2dbcAuditing
public class R2dbcAuditingConfig {
    @Bean
    ReactiveAuditorAware<String> auditorAware() {     // 响应式版 AuditorAware
        return () -> ReactiveSecurityContextHolder.getContext()
                .map(ctx -> ctx.getAuthentication().getName())
                .switchIfEmpty(Mono.just("system"));
    }
}

@Table("product")
public class Product {
    @Id private Long id;
    @CreatedDate private LocalDateTime createdAt;      // insert 自动填
    @LastModifiedDate private LocalDateTime updatedAt; // 更新自动改
    @CreatedBy private String createdBy;
    @LastModifiedBy private String updatedBy;
}
```

| 差异 | JPA | R2DBC |
|------|-----|-------|
| 启用注解 | `@EnableJpaAuditing` | `@EnableR2dbcAuditing` |
| AuditorAware | `AuditorAware`（同步） | `ReactiveAuditorAware`（返回 Mono，可从响应式 Security 上下文取） |
| 字段注解 | 相同 | `@CreatedDate`/`@LastModifiedDate`/`@CreatedBy`/`@LastModifiedBy` 通用 |

### 6.2 类型转换与自定义映射

```java
// 枚举映射（4.x）：默认存名字
@Table("user_account")
public class UserAccount {
    @Id private Long id;
    private UserStatus status;      // 存 VARCHAR（名字）
}

// 特殊类型走 SQL 直写 + RowMapper 手动映射（JSON 列等）
@Query("select id, name, json_data from product where id = :id")
Mono<Product> findWithJson(@Param("id") Long id);   // 配合自定义 RowMapper
```

> 💡 认知边界：R2DBC 的映射是"约定 + 驱动编解码"，**没有 JPA 的 AttributeConverter 注解体系**；复杂类型（JSON 列）的正解是 DatabaseClient SQL 直写 + 手动转换（[05 篇](05-查询构造与DatabaseClient速查.md) 5 节），而不是硬塞进实体。

## 7. 映射设计红线

| # | 红线 | 理由 | 正确姿势 |
|---|------|------|---------|
| 1 | 想用懒加载/关联导航 | R2DBC 无此能力 | 聚合根 + join SQL（第 1 节） |
| 2 | 改属性不调 save | 无脏检查，改动不落库 | 修改后显式 save/update |
| 3 | 金额用 double | 精度丢失 | BigDecimal |
| 4 | 依赖驼峰→下划线 | R2DBC 默认属性名原样 | @Column 显式命名约定 |
| 5 | 忽略 4.0 引号标识符 | 大写/保留字表行为变化 | 升级时审查表列大小写（[09 篇](09-集成地图与常见问题.md)） |
| 6 | 复合键不用 @IdClass | 4.0 支持完善，别手搓 | 用 @IdClass + Serializable 主键类 |
| 7 | 枚举存序数 | 加值错位 | 默认存名字；要序数走转换 |
| 8 | 复杂类型硬塞实体 | 映射器不支持 | DatabaseClient SQL 直写 + RowMapper |
| 9 | 忘记 @Version | 并发覆盖 | 更新型表加版本列 |
| 10 | 忽略 UTC 时区 | 日期差 8 小时 | TIMESTAMP + UTC 约定（同 JPA 系列） |

> 🎯 映射自检清单（写新实体前过一遍）：@Table 显式了吗？@Id 策略选了吗？有 @Embedded 该用的值对象吗？改字段记得显式更新吗？更新型表有 @Version 吗？——五问全过再落代码。
