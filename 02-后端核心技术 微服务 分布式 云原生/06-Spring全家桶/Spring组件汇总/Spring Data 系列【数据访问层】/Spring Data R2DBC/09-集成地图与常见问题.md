## 1. 与全家桶的集成地图

| 组件 | 联动点 | 要点 |
|------|--------|------|
| WebFlux | 全链路非阻塞 | Controller 返回 Mono/Flux（[08 篇](08-WebFlux响应式集成速查.md)） |
| Spring AI | 响应式 RAG | WebClient + 响应式向量库（[向量检索系列](../../../../../03-AI大模型应用开发/08-向量数据库/)） |
| Redis | 缓存热点 | **ReactiveRedisTemplate**（响应式版，[Spring Data Redis 系列](../../../Spring Data Redis/00-Spring Data Redis知识体系总览.md)） |
| 消息队列 | 异步解耦 | 响应式客户端（Pulsar/RocketMQ reactive；或 WebFlux + WebClient 桥接） |
| Flyway | 建表迁移 | **Flyway 走 JDBC（spring.datasource），业务走 R2DBC（spring.r2dbc）——行业标配双轨** |
| 监控 | Actuator | `r2dbc.pool` 指标 + 慢 SQL 日志（[07 篇](07-性能优化与批量速查.md) 6 节） |
| 测试 | r2dbc-h2 / Testcontainers | StepVerifier 断言（[08 篇](08-WebFlux响应式集成速查.md) 5 节） |
| 容错 | Resilience4j 响应式 | 超时/熔断/限流的响应式适配（[08 篇](08-WebFlux响应式集成速查.md) 4 节） |

> 🎯 集成总原则：**响应式项目里，所有组件都要"响应式版"**——同步组件（RestTemplate/RedisTemplate/Hikari）混入会破坏非阻塞（[08 篇](08-WebFlux响应式集成速查.md) 阻塞陷阱）；唯一例外是**迁移类工具**（Flyway 走 JDBC 可接受，它只发生在部署期）。

## 2. JPA 双轨：同库共存与渐进迁移

**通俗**：大项目不可能一夜全换——同库同时跑 JPA（老链路）和 R2DBC（新链路）是常见过渡态，但要管好"两套连接池 + 两套事务"。

```yaml
# 双轨配置：同一 MySQL 库，两套连接
spring:
  datasource:                    # JPA 用（老链路）
    url: jdbc:mysql://localhost:3306/shop
    username: root
    password: root
  r2dbc:                         # R2DBC 用（新链路）
    url: r2dbc:mysql://localhost:3306/shop
    username: root
    password: root
```

| 双轨风险 | 说明 | 解法 |
|---------|------|------|
| 两套事务管理器 | @Transactional 默认找哪个？ | 默认事务管理器保持一个（JPA）；R2DBC 链路显式 `@Transactional("r2dbcTransactionManager")` |
| 双缓存语义 | JPA 有一级缓存，R2DBC 没有 | 新链路按"无缓存"设计（[07 篇](07-性能优化与批量速查.md) 4 节） |
| 连接成本 | 两套连接池两套驱动 | 接受过渡成本；迁移完删 JDBC 侧 |
| 事务跨轨 | JPA 事务内调 R2DBC（或反之） | **禁止跨轨事务**（两个管理器不感知对方）；拆服务/最终一致 |

> 🎯 迁移策略建议：**按"聚合根/业务域"切分迁移**（一个域一次），不是按方法逐个换——域内全量 R2DBC（含事务/缓存），域间走服务调用或消息；过渡期双轨配置如上，迁移完成即删 JDBC 侧。

## 3. JPA → R2DBC 迁移对照表

| 维度 | JPA（源） | R2DBC（目标） | 迁移动作 |
|------|----------|---------------|---------|
| 返回类型 | `T` / `List<T>` / `Page<T>` | `Mono<T>` / `Flux<T>` / `Mono<Page<T>>` | **全链路改写**（方法签名 + 调用方 + Controller） |
| 实体注解 | `@Entity`/`@Table`/`@Column` | `@Table`/`@Id`/`@Column` | 删 @Entity 保留 @Table；关联注解**全删** |
| 关联映射 | @OneToMany/@ManyToOne | ❌ 无 | join 改 @Query/DatabaseClient SQL |
| save 语义 | persist/merge | 直写（无先查） | 行为更可预测，注意"改属性不保存" |
| 懒加载 | 有 | ❌ | 预加载/join SQL |
| 一级缓存 | 有 | ❌ | 应用层缓存（[07 篇](07-性能优化与批量速查.md) 4 节） |
| 脏检查 | 有 | ❌ | 显式 save/update |
| 派生查询 | 相同（关键词同源） | 相同 | 返回类型改 Mono/Flux |
| @Query | JPQL | **原生 SQL** | 全量改写（方言自己管） |
| 事务 | 线程绑定 | 管道绑定 | @Transactional 保留；去掉 block/吞异常（[06 篇](06-响应式事务与并发控制速查.md)） |
| 乐观锁 | @Version（同） | @Version（同） | 直接平移；重试改 retryWhen |
| 审计 | @EnableJpaAuditing | @EnableR2dbcAuditing | 启用注解换；AuditorAware 改响应式版 |
| 分页 | Pageable（同） | Pageable（同） | 返回 Mono<Page<T>> |

> ⚠️ **迁移心法**：这不仅是"换框架"，是**并发模型的切换**——方法论上：① 先选"值得迁移的域"（高并发 IO 密集）；② 域内全量改（签名/调用链/Controller 一起）；③ 测试用 StepVerifier 重写；④ 事务/缓存/容错全部换响应式版——**逐方法迁移会造出"阻塞陷阱"横飞的混合体**（[08 篇](08-WebFlux响应式集成速查.md) 3 节）。

## 4. 3.x → 4.1 迁移清单

> Boot 3.5（SDR 3.5）→ Boot 4.1（SDR 4.1）。**前置条件：Java 21**。

### 4.1 必改项

| # | 项目 | 3.x | 4.x | 说明 |
|---|------|-----|-----|------|
| ① | Java/框架基线 | Java 17 + Framework 6.2 | **Java 21 + Framework 7.0** | 非协商项 |
| ② | 驱动坐标 | dev.miku（MySQL 老坐标） | **io.asyncer:r2dbc-mysql** | dev.miku 已归档，升级顺手换 |
| ③ | 空值注解 | JetBrains | JSpecify | 静态检查适配 |
| ④ | 已移除 API | — | 3.x 废弃项清理 | 编译期错误逐条解 |

### 4.2 行为变化（重点回归）

| # | 项目 | 变化 | 回归要点 |
|---|------|------|---------|
| ⑤ | **标识符带引号** | 无引号 → 默认带引号 | 表/列大小写敏感行为变化；大写列名/保留字审查（`order`/`user`/`group`） |
| ⑥ | 复合主键/@Embedded | 支持增强 | 老项目可简化代码；重测复合键读写 |
| ⑦ | 派生查询生成 | SQL 生成细节调整 | show-sql 对比；正则/日期参数重点测 |
| ⑧ | 投影映射 | record 支持完善 | 重测 DTO 投影（列名对齐） |
| ⑨ | 事务/审计 | 行为细节 | 重测事务回滚与审计字段 |

### 4.3 升级收益验收

| 新能力 | 出处 | 验收方式 |
|--------|------|---------|
| 类型安全属性路径 | [05 篇](05-查询构造与DatabaseClient速查.md) 3 节 | 重构一处字符串 Criteria → PropertyPath 编译期校验 |
| 聚合根 upsert | [07 篇](07-性能优化与批量速查.md) 2 节 | 批量导入场景压测 |
| AOT Repository | [01 篇](01-模块清单.md) | 构建期元数据验证 |

> 🎯 迁移心法（同系列通用）：**先解编译期硬约束（①-④），再跑全量测试暴露行为变化（⑤-⑨）——其中⑤（引号标识符）是最容易"上线才炸"的一项，必须全量回归表列大小写**。

## 5. 高频坑排错表

| 症状 | 根因 | 解法 |
|------|------|------|
| `Unknown driver` | URL 前缀错（jdbc:/r2dbc: 混） | 确认 `r2dbc:mysql:` 前缀（[02 篇](02-快速开始与连接配置速查.md) 6 节） |
| 全服务卡死 | 事件循环线程被 block 占满 | 搜 `.block()`/同步 IO（[08 篇](08-WebFlux响应式集成速查.md) 3 节） |
| 数据没提交 | 事务管道未完整订阅 | 调用链检查（[06 篇](06-响应式事务与并发控制速查.md) 2 节） |
| 事务不回滚 | 异常被吞 / 自调用 | 失效清单对照（[06 篇](06-响应式事务与并发控制速查.md) 4 节） |
| 表/列找不到（升级后） | 4.0 引号标识符大小写敏感 | 审查表列大小写 + SQL 引号（本页 4.2 ⑤） |
| `order`/`user` 等表名报错 | 保留字未加引号 | MySQL 反引号：`` `order` ``（[04 篇](04-Repository速查.md) 3 节） |
| 枚举存不进 | 映射器不认识 | 默认存名字；特殊需求走 @Query + 转换 |
| 日期差 8 小时 | 时区/UTC 语义 | TIMESTAMP + UTC 约定（同 JPA 系列 [09 篇](../../Spring%20Data%20系列【数据访问层】/Spring%20Data%20JPA/09-集成地图与常见问题.md)） |
| 乐观锁重试无效 | 重试复用完成的流 | `Mono.defer` 包裹读-改-写（[06 篇](06-响应式事务与并发控制速查.md) 5 节） |
| 批量导入慢 | saveAll 逐条 | insertAll / 手拼多值 SQL（[07 篇](07-性能优化与批量速查.md) 2 节） |
| 测试断言超时 | StepVerifier 用法 | expectNext 系列 + thenAwait（[08 篇](08-WebFlux响应式集成速查.md) 5 节） |
| 内存增长 | flatMap 无并发限制 | `.concatMap` / 限制 concurrency（[07 篇](07-性能优化与批量速查.md) 5 节） |

## 6. 测试实践

### 6.1 测试栈

| 姿势 | 用途 | 要点 |
|------|------|------|
| `@SpringBootTest` + r2dbc-h2 | Repository/Service 单测 | 快；方言差异（MySQL 语法别在 H2 测） |
| Testcontainers（r2dbc-mysql） | 真库集成 | 关键 SQL/事务/引号行为必测 |
| `@WebFluxTest` | Controller 切片 | Mock Repository，测响应式链路 |
| StepVerifier | 断言标准 | 全部响应式断言（[08 篇](08-WebFlux响应式集成速查.md) 5 节） |

```java
// Controller 测试（WebTestClient）
@WebFluxTest(ProductController.class)
class ProductControllerTest {

    @Autowired WebTestClient webTestClient;

    @MockBean ProductService productService;

    @Test
    void get_shouldReturnProduct() {
        when(productService.getProduct(1L)).thenReturn(Mono.just(new Product("手机")));

        webTestClient.get().uri("/products/1")
                .exchange()
                .expectStatus().isOk()
                .expectBody(Product.class)
                .consumeWith(r -> assertThat(r.getResponseBody().getName()).isEqualTo("手机"));
    }
}
```

> ⚠️ 测试三坑：① 响应式测试**没有自动回滚事务**（与 JPA 不同）——用容器/清理策略；② 别在测试里大量 `.block()`（掩盖时序问题，StepVerifier 才是断言正道）；③ H2 测过的 SQL 必须在真库（Testcontainers）复测——**方言差异是 R2DBC 的手写 SQL 带来的额外成本**（[04 篇](04-Repository速查.md) 3 节）。
