## 1. Artifact 坐标与版本线

| 项 | 值 |
|----|----|
| GroupId | `org.springframework.data` |
| ArtifactId | `spring-data-r2dbc`（与 spring-data-jdbc 同属 Relational 项目） |
| 当前线 | 4.1.x（4.1.0，2026.0 发行列车，2026-08 时点） |
| 稳定线 | 4.0.x（2025.1 列车，Boot 4.0.x） |
| 存量线 | 3.5.x（2025.0 列车，Boot 3.5.x，**已停止维护**） |
| Java 基线 | 21+（随 Boot 4 / Spring Framework 7） |
| 规范 | `io.r2dbc:r2dbc-spi` 1.0.0.RELEASE（驱动间通用协议 + TCK） |
| 配套 | spring-data-commons、Reactor、WebFlux |

> 💡 版本记忆口诀："**4.x 配 Boot 4 + r2dbc-spi 1.0**"——规范 1.0 后协议稳定，驱动升级不影响 API；新项目直接 4.1。

### 1.1 引入方式速查

| 方式 | 写法 | 说明 |
|------|------|------|
| Boot starter（推荐） | `spring-boot-starter-data-r2dbc` | SDR + r2dbc-pool + 自动配置（不含驱动） |
| Maven 显式 | `org.springframework.data:spring-data-r2dbc:4.1.0` | 非 Boot 项目或精确控制 |
| Gradle | `implementation 'org.springframework.boot:spring-boot-starter-data-r2dbc'` | 由 Boot BOM 管版本 |

```xml
<!-- Boot 4 + MySQL 最小依赖 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-r2dbc</artifactId>
</dependency>
<dependency>
    <groupId>io.asyncer</groupId>
    <artifactId>r2dbc-mysql</artifactId>     <!-- 版本由 Boot BOM 管理 -->
</dependency>
```

> ⚠️ **版本协调三原则**：① 永远跟 Boot BOM 走，不手写 SDR/r2dbc-spi 版本；② **驱动坐标选对**——MySQL 用 `io.asyncer:r2dbc-mysql`（dev.miku 已归档），PostgreSQL 用 `io.r2dbc:r2dbc-postgresql`，H2 用 `io.r2dbc:r2dbc-h2`；③ 驱动版本与 Boot 对齐（r2dbc-mysql 1.4.2 配 Boot 4）。

### 2.1 连接池：r2dbc-pool

| 项 | 说明 |
|----|------|
| 坐标 | `io.r2dbc:r2dbc-pool`（starter 自动带） |
| 对应物 | HikariCP 的响应式版（`ConnectionPool` + `ConnectionPoolConfiguration`） |
| 关键参数 | `max-size`（默认 10）、`initial-size`、`max-idle-time`、`validation-query` |
| 与 Hikari 差异 | 获取连接返回 `Mono<Connection>`（非阻塞），无"等待超时抛异常"的阻塞语义 |

## 3. 包结构地图

```text
org.springframework.data.r2dbc
├── repository                                  # ★ Repository 体系
│   ├── R2dbcRepository / ReactiveCrudRepository / ReactiveSortingRepository
│   ├── query
│   │   ├── R2dbcQueryMethod / PartTreeR2dbcQuery   # 派生方法 → SQL
│   │   ├── R2dbcQueryExecution / AbstractR2dbcQuery
│   │   └── @Query / @Modifying / QueryByExample
│   ├── support
│   │   ├── R2dbcRepositoryFactory / SimpleR2dbcRepository  # 默认实现（动态代理目标）
│   │   └── R2dbcRepositoryFactoryBean
│   └── config（@EnableR2dbcRepositories）
├── core                                        # ★ 模板与查询核心
│   ├── R2dbcEntityTemplate                      # 实体级编程式模板
│   ├── DatabaseClient                            # SQL 直写入口（bind/execute/rowMapper）
│   ├── query
│   │   ├── Criteria / Update / SqlBuilder       # 类型安全条件构造（4.1 属性路径）
│   │   └── R2dbcEntityOperations / R2dbcEntityUpdate
│   ├── mapping
│   │   ├── R2dbcEntityWriter / R2dbcEntityReader # POJO ↔ 行
│   │   └── R2dbcTypeMapper / R2dbcConverter
│   ├── connection
│   │   ├── ConnectionFactory / ConnectionFactoryOptions
│   │   ├── R2dbcTransactionManager               # 响应式事务管理器
│   │   └── r2dbc-pool 集成（ConnectionPool）
│   └── NamedParameterExpander / BindMarkersFactory  # 参数绑定
├── core.aggregation / core.query                # 4.x 扩展
├── domain                                       # 审计（Auditable）
└── config                                       # 编程式配置
    ├── AbstractR2dbcConfiguration / R2dbcConfigUtils
    └── EnableR2dbcRepositories
```

> 💡 记忆抓手：**`SimpleR2dbcRepository` 是所有 Repository 的默认实现**（内部持 DatabaseClient + R2dbcEntityTemplate）；编程式操作的两个入口：**实体级用 R2dbcEntityTemplate、SQL 直写用 DatabaseClient**——源码学习从这两者入手。

### 3.1 运行时对象链

```text
业务代码（WebFlux Controller/Service）
    ↓ Mono/Flux
R2dbcRepository（接口）→ 动态代理（R2dbcRepositoryFactory）
    → SimpleR2dbcRepository（默认实现，内部转调 R2dbcEntityTemplate）
    → R2dbcEntityTemplate → DatabaseClient
    → R2dbcConnectionProvider（事务上下文）
    → ConnectionPool（r2dbc-pool）
    → 驱动（r2dbc-mysql / r2dbc-postgresql，Netty 非阻塞协议）
    → MySQL / PostgreSQL
```

> 🎯 面试高频：**"Spring Data R2DBC 和 JDBC 驱动什么关系？"**——JDBC 是阻塞规范（每次操作占一个线程等 IO），R2DBC 是非阻塞规范（r2dbc-spi 定义 Connection/Statement 的响应式契约）；Spring Data R2DBC 在其上提供"实体映射 + Repository + 模板"；**底层协议仍走数据库原生协议**（MySQL 协议/PostgreSQL 协议），性能提升来自"不占线程等 IO"。

## 4. 职责切割：SDR vs r2dbc-spi vs 驱动 vs JDBC

| 层 | 职责 | 典型代码/API | 本系列覆盖 |
|----|------|-------------|-----------|
| **Spring Data R2DBC** | 仓库抽象、聚合根映射、模板便利、事务管理 | `R2dbcRepository`、`R2dbcEntityTemplate`、`@Table` | ✅ 本系列全部 |
| **r2dbc-spi** | 规范接口（Connection/Statement/Result）、TCK | `io.r2dbc.spi.*` | 02 篇连接落点 |
| **驱动** | 协议实现（MySQL/PostgreSQL 协议）、Netty 传输 | `r2dbc-mysql`、`r2dbc-postgresql` | 01/02 篇选型 |
| **数据库** | 存储、索引、事务 ACID 物理实现 | — | [MySQL 系列](../../../../01-关系型数据库/MySQL/00-MySQL总览与技术术语.md) |
| **JDBC（对照）** | 阻塞规范（非本组件依赖，但团队往往双轨） | java.sql.* | [JDBC 深度体系](../../../../01-关系型数据库/JDBC/00-JDBC知识体系总览.md) |

### 4.1 典型误判案例

| 现象 | 错误归因 | 正确归因 |
|------|---------|---------|
| 并发没提升 | "R2DBC 没用" | 链路里有阻塞调用（[08 篇](08-WebFlux响应式集成速查.md) 阻塞陷阱） |
| 单查询比 JDBC 慢 | "框架性能差" | 协议开销差异（响应式价值在并发模型，非单查询） |
| 事务不回滚 | "响应式事务不行" | 线程/Publisher 边界传播没做对（[06 篇](06-响应式事务与并发控制速查.md)） |
| 关联数据取不到 | "框架不支持关联" | 聚合根模型，关联要手写 join SQL（[03 篇](03-聚合根映射速查.md)） |

> 🎯 一句话：**SDR 只管"响应式 API 好不好用"，并发收益来自"全链路非阻塞"，SQL 质量与事务正确性由"手写 SQL + 事务边界 + 数据库"共同决定**。

## 5. 版本兼容速查

| 你的项目 | 该用什么 | 迁移成本 |
|---------|---------|---------|
| 新项目（2026） | Boot 4.1 + SDR 4.1 + r2dbc-spi 1.0 + 对应驱动 | — |
| Boot 4.0 存量 | SDR 4.0，升 4.1 无痛（同大版本） | 低 |
| Boot 3.5 存量 | SDR 3.5，升 4.x 需 Java 21 + 引号标识符审查 | **高**（[09 篇](09-集成地图与常见问题.md) 迁移清单） |
| Boot 2.7 存量（SDR 1.5） | 规范 0.9 → 1.0 已变，API 差异大 | 极高（重写数据层） |
