## 1. 实体与主键映射

### 1.1 @Entity 硬性要求

| 要求 | 说明 | 反例 |
|------|------|------|
| 无参构造器 | JPA 规范要求（protected 也行） | 只写了带参构造 → 反射实例化失败 |
| 不可 final | 代理增强需要继承/接口 | final class → 代理失败 |
| 主键必须有 | 无主键的表无法用 JPA | 无 @Id → 启动报错 |
| 属性可访问 | getter/setter 或直接字段（统一一种风格） | 字段访问与属性访问混用 |

```java
@Entity
@Table(name = "product", indexes = {
        @Index(name = "idx_product_category", columnList = "category_id"),
        @Index(name = "idx_product_price", columnList = "price")
})
public class Product {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    // ...字段
}
```

### 1.2 主键生成策略对比（面试高频）

| 策略 | 原理 | 批量插入 | 适用 | 注意 |
|------|------|:---:|------|------|
| `IDENTITY` | 数据库自增（auto_increment） | ❌ 必须立即回填 id，批量失效 | MySQL/SQL Server（无序列） | 插入前拿不到 id；[07 篇](07-性能优化与批量操作速查.md) 批量方案 |
| `SEQUENCE` | 数据库序列（nextval） | ✅ 预取序列号可批量 | PostgreSQL/Oracle/H2 | 需 `@SequenceGenerator` 分配器 |
| `TABLE` | 模拟序列表 | ⚠️ 每表更新计数，锁竞争 | 跨库移植 | **不推荐**，性能差 |
| `UUID` | 应用生成 UUID 字符串 | ✅ | 分布式无中心 | 主键 36 字符、索引更大；趋势上 **UUIDv7 更优**（见 [雪花算法系列 UUIDv7](../../../../08-分布式系统与架构/雪花算法/04-分布式ID方案全景.md)） |
| `AUTO` | 由 Provider 挑（Hibernate 7 下映射到上者） | — | 开发期 | 生产显式指定，别依赖默认 |

```java
@Entity
public class OrderEntity {
    @Id
    @GeneratedValue(strategy = GenerationType.SEQUENCE, generator = "order_seq")
    @SequenceGenerator(name = "order_seq", sequenceName = "order_seq", allocationSize = 100)
    private Long id;
}
```

> 🎯 选型一句话：**MySQL 单库用 IDENTITY；PostgreSQL / 分库分表前用 SEQUENCE（allocationSize≥50 配合批处理）；分布式无中心用 UUIDv7**。面试必答点："IDENTITY 为什么无法批量插入？——因为 id 值只能 insert 时由库生成，JPA 必须逐条 flush 拿回 id"。

### 1.3 复合主键两种姿势

```java
// 姿势 A：@EmbeddedId（推荐，可放行为方法）
@Embeddable
public record OrderItemKey(Long orderId, Long itemNo) {}

@Entity
public class OrderItem {
    @EmbeddedId private OrderItemKey key;
}

// 姿势 B：@IdClass（表风格）
public class OrderItemKey implements Serializable { ... }   // 需实现 equals/hashCode/Serializable

@Entity
@IdClass(OrderItemKey.class)
public class OrderItem {
    @Id private Long orderId;
    @Id private Long itemNo;
}
```

> ⚠️ 复合主键类必须重写 `equals`/`hashCode`（基于所有键字段）；7.4 起复合主键支持数据库生成列（如 IDENTITY 组件），是 7.4 新特性。

## 2. 字段映射速查

### 2.1 @Column 常用属性

| 属性 | 默认 | 说明 |
|------|------|------|
| `name` | 驼峰→下划线 | 列名覆盖 |
| `nullable` | true | 是否可空（ddl-auto 建表用；validate 模式校验） |
| `length` | 255 | 字符串长度（DDL 用） |
| `precision` / `scale` | 0 | BigDecimal 精度（如 `precision=10, scale=2`） |
| `unique` | false | 单列唯一约束 |
| `insertable` / `updatable` | true | 只读列（DB 生成值）设 false |
| `columnDefinition` | — | 原生 DDL 片段（**慎用**，破坏跨库移植） |

### 2.2 特殊类型映射

| Java 类型 | 注解 | 落库 | 说明 |
|-----------|------|------|------|
| `BigDecimal` | —（可加 `@Column(precision,scale)`） | DECIMAL | 金额必用，**禁用 double/float 存金额** |
| `LocalDateTime` / `LocalDate` | —（JPA 3.2 直接支持） | DATETIME / DATE | **不要用** `java.util.Date`（老 API） |
| 枚举 | `@Enumerated(EnumType.STRING)` | VARCHAR / INT | STRING 可读、可加值；ORDINAL 加枚举值会错位 |
| 布尔 | —（Hibernate 自动） | BOOLEAN/TINYINT | MySQL 落 tinyint(1) |
| 大文本/字节 | `@Lob` | TEXT / LONGBLOB | 大字段别参与查询条件 |
| JSON 列 | Hibernate 6.6+ `@JdbcTypeCode(SqlTypes.JSON)` | JSON | MySQL/PostgreSQL 原生 JSON 列；Hibernate 7 走 `json_object()` 系列函数 |
| 向量字段 | `@JdbcTypeCode(SqlTypes.VECTOR)` | VECTOR | **4.0 新能力**：经 hibernate-vector 做 AI 语义检索（见 2.3） |
| 不可变字段 | `@Immutable` | — | 只读列，插入后不再更新 |

```java
@Entity
public class UserProfile {
    @Id private Long userId;

    @Enumerated(EnumType.STRING)
    private UserStatus status;                    // ACTIVE / LOCKED → 'ACTIVE'

    @JdbcTypeCode(SqlTypes.JSON)
    private Map<String, Object> attributes;       // Hibernate 7 JSON 列（MySQL 8+/PG 9.4+）

    @JdbcTypeCode(SqlTypes.VECTOR)
    private float[] embedding;                    // 4.0 向量字段（配合索引做 kNN，见 2.3）

    @Column(name = "created_at", insertable = false, updatable = false)
    private LocalDateTime createdAt;              // 库侧 default 值，只读回显
}
```

### 2.3 向量字段与 AI 检索（4.0 新能力）

> Spring Data 2025.1（4.0）起全家族支持 **Vector Search**，JPA 侧经 Hibernate 7 的向量类型对接数据库原生向量能力（PG pgvector / MySQL 9 向量 / SQL Server），Repository 可直接声明 `findNearestNeighbors` 类方法。

```java
// 依赖：hibernate-vector（与 ORM 同版本）+ 支持向量列的数据库

@Entity
public class DocChunk {
    @Id private Long id;
    private String content;

    @JdbcTypeCode(SqlTypes.VECTOR)
    private float[] embedding;                    // 嵌入向量（由 Spring AI/LLM 生成）

    public static final String VECTOR_INDEX =
        "CREATE INDEX doc_chunk_vec_idx ON doc_chunk USING hnsw (embedding vector_cosine_ops)";
}
```

> ⚠️ 定位提醒：JPA 向量检索适合**实体中心**的轻量语义搜索（如"按文档相似度查记录"）；生产级 RAG 知识库仍首选 [Spring Data Elasticsearch 向量检索](../../Spring Data 系列【数据访问层】/Spring Data Elasticsearch/07-向量检索与RAG集成速查.md) 或 [Milvus](../../../../../03-AI大模型应用开发/08-向量数据库/Milvus/00-Milvus知识体系总览.md)——向量索引、混合检索、租户隔离都更成熟。

### 2.4 时态与审计字段

```java
@Entity
public class OrderEntity {
    // 方案 A：应用侧维护（Spring Data 审计，见 08 篇）
    @CreatedDate private LocalDateTime createdAt;
    @LastModifiedDate private LocalDateTime updatedAt;

    // 方案 B：数据库侧维护（7.4 推荐 @CreationTimestamp/@UpdateTimestamp）
    @CreationTimestamp private LocalDateTime createdAt;    // Hibernate 生成，插入时自动填
    @UpdateTimestamp private LocalDateTime updatedAt;
}
```

> 💡 7.4 新特性 `@Temporal`（时态历史表）与 `@Audited`（审计表）把"每次变更留痕"内置进 ORM——历史版本、审计追踪不用再自己写触发器/双表，见 [08 篇](08-审计事件与多租户速查.md) 专节。

## 3. 关联映射四件套

### 3.1 总览

| 关联 | 注解 | 持有方 | 表结构 |
|------|------|--------|--------|
| 多对一 | `@ManyToOne` | 多的一方（存外键） | 多表加 `@JoinColumn` 外键 |
| 一对多 | `@OneToMany(mappedBy=...)` | 一的一方（不建表） | 由对方 `@JoinColumn` 决定 |
| 一对一 | `@OneToOne` | 主表持外键 | 主表外键唯一 |
| 多对多 | `@ManyToMany` | 任意一方（必须 @JoinTable） | 中间关联表 |

```java
// 多对一 + 一对多（最常见订单模型）
@Entity
public class OrderEntity {
    @Id private Long id;

    @OneToMany(mappedBy = "order", cascade = CascadeType.ALL, orphanRemoval = true)
    private List<OrderItem> items = new ArrayList<>();

    public void addItem(OrderItem item) {         // ★ 双端维护（见 3.3）
        items.add(item);
        item.setOrder(this);
    }
}

@Entity
public class OrderItem {
    @Id private Long id;

    @ManyToOne(fetch = FetchType.LAZY)            // ★ 多对一默认 EAGER，务必显式 LAZY
    @JoinColumn(name = "order_id")
    private OrderEntity order;
}
```

### 3.2 FetchType 选择铁律

| FetchType | 默认场景 | 选择 |
|-----------|---------|------|
| LAZY | 一对多、多对多 | ✅ 一律 LAZY，访问时按需加载（07 篇讲 N+1 治理） |
| EAGER | 多对一、一对一 | ⚠️ **显式改成 LAZY**——EAGER 会无条件 join，列表查询性能灾难 |

> 🎯 面试必答：**"为什么集合默认 LAZY？"**——集合加载成本不可控（行数未知），EAGER 会在任何查询（包括 count）上附加 join；而多对一单条成本固定，规范才默认 EAGER——但实践中多对一也改 LAZY，配合 fetch join 按需组装（[07 篇](07-性能优化与批量操作速查.md)）。

### 3.3 双端维护与 equals/hashCode

```java
@Entity
public class OrderEntity {
    // 正确姿势：双向关联必须双端维护
    public void addItem(OrderItem item) {
        this.items.add(item);
        item.setOrder(this);
    }
}
```

| 陷阱 | 症状 | 规则 |
|------|------|------|
| 只维护一端 | 只存了外键没同步集合（或反之），缓存与 DB 不一致 | 提供 addItem/removeItem 双端方法，禁止直接操作集合 |
| 关联字段参与 equals/hashCode | 未持久化实体 equals 全等、Set 去重错乱 | equals/hashCode **只用业务唯一键**（如自然键），绝不包含关联对象与集合 |
| toString 打印集合 | 懒加载未初始化时 toString 触发加载/异常 | toString 不打印关联集合 |
| 集合初始化为 null | NPE | `= new ArrayList<>()` 初始化为空集合 |

### 3.4 多对多

```java
@Entity
public class Student {
    @Id private Long id;

    @ManyToMany
    @JoinTable(name = "student_course",
            joinColumns = @JoinColumn(name = "student_id"),
            inverseJoinColumns = @JoinColumn(name = "course_id"))
    private Set<Course> courses = new HashSet<>();
}
```

> 💡 多对多**不带额外属性**（如选课时间）时才用 @JoinTable；**带属性**（成绩、选课时间）必须把关联表升为实体（StudentCourse 实体，用 [1.3 复合主键](#13-复合主键两种姿势)），否则永远加不了列——这是建模面试常考题。

### 3.5 一对一

```java
@Entity
public class UserAccount {
    @Id private Long id;

    @OneToOne(mappedBy = "account", cascade = CascadeType.ALL)
    private AccountDetail detail;               // 反向侧（无外键）
}

@Entity
public class AccountDetail {
    @Id private Long id;

    @OneToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "account_id", unique = true)   // 持有外键
    private UserAccount account;
}
```

## 4. 级联与孤儿删除

### 4.1 CascadeType 速查

| CascadeType | 触发的操作 | 典型用途 |
|-------------|-----------|---------|
| PERSIST | save 父 → save 子 | 聚合根创建 |
| MERGE | 更新父 → 更新子 | 聚合根更新 |
| REMOVE | 删父 → 删子 | 聚合根删除 |
| ALL | 以上全部 | 聚合根模式统一入口 |
| REFRESH / DETACH | 刷新/脱管传播 | 少见 |
| **PERSIST+REMOVE 组合** | 常用折中 | 避免 MERGE 误伤子表 |

> ⚠️ **级联不是越多越好**：CascadeType.ALL 配合错误的多对多/跨聚合关联，会造成**意外删除**（删 A 连带删了不该删的 B）。规则：**级联只沿"聚合根 → 内部子实体"方向**（订单→订单项），跨聚合（用户→订单）一律不级联、只做查询关联。

### 4.2 orphanRemoval

```java
@OneToMany(mappedBy = "order", cascade = CascadeType.ALL, orphanRemoval = true)
private List<OrderItem> items = new ArrayList<>();
```

| 概念 | 行为 | 与 cascade=REMOVE 区别 |
|------|------|----------------------|
| orphanRemoval | 从集合**移除**子对象 → 自动 DELETE 该子行 | REMOVE 是删父连带删子；orphan 是"子脱离父即删除" |
| 适用 | 值对象式集合（明细、标签） | 集合元素完全由父决定生命周期 |

> 🎯 面试必答：**"orphanRemoval 和 CascadeType.REMOVE 什么区别？"**——REMOVE 沿关联删除；orphanRemoval 是**集合层面**的"脱离即删"（同时隐含 REMOVE 语义），适合明细表（删掉某一行明细，子行必须清掉，否则外键悬空）。

## 5. 组合与继承映射

### 5.1 @Embeddable 值对象

```java
@Embeddable
public record Address(String province, String city, String detail) {}

@Entity
public class OrderEntity {
    @Embedded
    @AttributeOverrides({
            @AttributeOverride(name = "province", column = @Column(name = "ship_province")),
            @AttributeOverride(name = "city",     column = @Column(name = "ship_city"))
    })
    private Address shipAddress;               // 收货地址（列前缀 ship_）
}
```

| 要点 | 说明 |
|------|------|
| 复用 | 同一值对象（地址、金额对）多字段场景免重复建列 |
| 覆盖列名 | 同一实体用两个相同 embeddable 时 `@AttributeOverride` 必须改名 |
| 集合嵌入 | `@ElementCollection`（如 List\<String\> tags）→ 子表，用 `@CollectionTable` 指定表名 |
| record 支持 | 4.0 起 record 做 embeddable 完全支持（见第 6 节） |

### 5.2 @MappedSuperclass 共享列

```java
@MappedSuperclass
public abstract class BaseEntity {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    @CreationTimestamp private LocalDateTime createdAt;
    // getter/setter
}

@Entity
public class Product extends BaseEntity { ... }        // product 表包含 id/created_at
```

> 💡 场景：多张表共享 id 策略/审计列（不建父表）。注意：**@MappedSuperclass 不建表、不能查询、无多态**——和 @Inheritance 区分开。

### 5.3 @Inheritance 三种策略

| 策略 | 表结构 | 查询 | 适用 |
|------|--------|------|------|
| `SINGLE_TABLE` | 一张表 + discriminator 列（默认） | 快（无 join） | 差异字段少；**注意列会全部可空** |
| `JOINED` | 每类一表 + 主表共享列 | 多态查询 join 多表 | 差异大、规范三范式 |
| `TABLE_PER_CLASS` | 每类完整一表 | 多态查询 union 各表 | **JPA 支持差**，尽量避免 |

```java
@Entity
@Inheritance(strategy = InheritanceType.SINGLE_TABLE)
@DiscriminatorColumn(name = "pay_type")
public abstract class Payment {
    @Id private Long id;
    private BigDecimal amount;
}

@Entity
@DiscriminatorValue("WECHAT")
public class WechatPay extends Payment { private String openId; }

@Entity
@DiscriminatorValue("ALIPAY")
public class AlipayPay extends Payment { private String buyerId; }
```

> ⚠️ 继承映射是 JPA 里最常被误用的设计：**业务上"类型不同" ≠ 数据模型"继承不同"**——支付方式差异大（字段完全不同）时，接口 + 组合（各自独立表）往往优于继承；继承策略选错（SINGLE_TABLE 列爆炸 / JOINED 查询慢）后期很难改表。

## 6. record 实体与值对象（4.0 增强）

> 4.0 起 record 作为实体/嵌入对象/投影得到完整支持（Spring Data 2025.1 的明确改进项），代码更简洁、不可变更安全。

```java
// record 实体：无参构造需求由 Hibernate 内部反射处理（7.x 支持）
@Entity
@Table(name = "product")
public record Product(
        @Id @GeneratedValue(strategy = GenerationType.IDENTITY) Long id,
        String name,
        @Column(precision = 10, scale = 2) BigDecimal price) {}

// 构造函数注入（Spring Data 自动识别唯一构造器）
@Entity
public class Customer {
    private final Long id;
    private final String name;

    public Customer(Long id, String name) { this.id = id; this.name = name; }
    // 只有 getter，无 setter —— Hibernate 通过字段访问赋值
}
```

| 要点 | 说明 |
|------|------|
| 多构造器 | 用 `@PersistenceCreator` 标注持久化构造器（4.0 起替代 `@PersistenceConstructor`） |
| 不可变实体 | 只留 getter + 全参构造即可（Hibernate 字段反射赋值），线程安全红利 |
| 投影 | record 做接口投影替代品（[07 篇](07-性能优化与批量操作速查.md) 投影节） |
| 边界 | record 不适合大对象图（无继承、不可变，无法承载集合级联状态机）——聚合根还是用普通类 |

## 7. 映射设计红线

| # | 红线 | 理由 | 正确姿势 |
|---|------|------|---------|
| 1 | 金额用 double/float | 精度丢失 | BigDecimal + precision/scale |
| 2 | 日期用 java.util.Date | 可变、时区混乱 | LocalDate/LocalDateTime |
| 3 | 枚举用 ORDINAL | 加枚举值全表错位 | EnumType.STRING |
| 4 | 多对一不写 LAZY | 列表查询 join 爆炸 | 显式 `fetch = FetchType.LAZY` |
| 5 | 集合 equals/hashCode 带关联 | 状态错乱、死循环 | 只用业务唯一键 |
| 6 | 级联跨聚合 | 意外删除 | 级联只沿聚合根向内 |
| 7 | @Column(columnDefinition) 滥用 | 锁死数据库方言 | 标准注解 + 迁移工具管 DDL |
| 8 | 表名/列名用保留字 | SQL 报错 | 表名加反引号场景用 `@Table(name="\`order\`")` 或改名 |
| 9 | 大字段进查询条件/索引 | 性能灾难 | @Lob 字段只存读 |
| 10 | 双向关联不维护双端 | 缓存/DB 不一致 | addXxx/removeXxx 封装 |

> 🎯 映射设计自检清单（写新实体前过一遍）：主键策略选了没？金额/日期/枚举类型对没对？多对一 LAZY 了没？双向关联有没有双端方法？级联方向是不是"聚合内"？——十条全过再落代码。
