## 1. Artifact 坐标与版本线

| 项 | 值 |
|----|----|
| GroupId | `org.springframework.data` |
| ArtifactId | `spring-data-jpa` |
| 当前线 | 4.1.x（4.1.0，2026.0 发行列车，2026-08 时点） |
| 稳定线 | 4.0.x（2025.1 列车，Boot 4.0.x） |
| 存量线 | 3.5.x（2025.0 列车，Boot 3.5.x，**已停止维护**） |
| Java 基线 | 21+（随 Boot 4 / Spring Framework 7，硬性要求） |
| 规范基础 | Jakarta Persistence 3.2（Jakarta EE 11） |
| 配套 | spring-data-commons、Hibernate ORM 7.4.x、HikariCP |

> 💡 版本记忆口诀："**3.x 配 Boot 3 和 Hibernate 6，4.x 配 Boot 4 和 Hibernate 7**"——2026 年起新项目直接 4.1；存量 Boot 3.5 项目不升 Java 21 就只能停 3.5.x（已停止维护）。

### 1.1 引入方式速查

| 方式 | 写法 | 说明 |
|------|------|------|
| Boot starter（推荐） | `spring-boot-starter-data-jpa` | 自动引入 spring-data-jpa + Hibernate + Hikari + 自动配置 |
| Maven 显式 | `org.springframework.data:spring-data-jpa:4.1.0` | 非 Boot 项目或精确控制 |
| Gradle | `implementation 'org.springframework.boot:spring-boot-starter-data-jpa'` | 由 Boot BOM 管版本 |
| Boot 4 BOM | 不写版本号 | `spring-boot-dependencies` 统一管理 |

```xml
<!-- Boot 4 项目最小依赖 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-jpa</artifactId>
</dependency>
<!-- 驱动按库添加（runtime scope）：
     MySQL    → com.mysql:mysql-connector-j
     PostgreSQL → org.postgresql:postgresql
     H2（开发/测试）→ com.h2database:h2        -->
```

> ⚠️ **版本协调三原则**：① 永远跟 Boot BOM 走，不手写 spring-data-jpa / Hibernate 版本；② 4.x 组件必须配 Hibernate 7（3.x 时代的 Hibernate 6 API 有破坏性变化，见 [02 篇](02-快速开始与连接配置速查.md)）；③ 数据库驱动大版本与数据库服务端对齐（MySQL 8.x 用 8.x+ 驱动，别用 5.1 老驱动）。

## 2. 包结构地图

```text
org.springframework.data.jpa
├── repository                                   # ★ Repository 体系
│   ├── JpaRepository / JpaSpecificationExecutor
│   ├── CrudRepository / PagingAndSortingRepository（在 commons）
│   ├── query                                      # 查询执行
│   │   ├── JpaQueryMethod / QueryByExampleExecutor
│   │   ├── JpaQueryCreator / PartTreeJpaQuery     # 派生方法 → JPQL（4.0 重写）
│   │   ├── JpaQueryExecution / AbstractJpaQuery
│   │   └── QueryEnhancerSelector                  # 原生查询增强开关（4.0 起）
│   ├── support                                    # 仓库基础设施
│   │   ├── JpaRepositoryFactory / JpaRepositoryFactoryBean
│   │   ├── SimpleJpaRepository                   # 默认实现（运行时动态代理的目标）
│   │   └── EntityManagerBeanDefinitionRegistrar
│   ├── EntityGraph / EntityGraphAttribute（@EntityGraph 支持）
│   └── RepositoryMetadata / RepositoryMethod
├── domain                                         # 领域模型辅助
│   ├── Auditable / AbstractAuditable             # 审计基类
│   └── JpaAuditorAware                            # 审计人获取接口
├── support                                         # Boot 无关的支持类
│   ├── JpaMetamodelEntityInformation / SimpleJpaMetamodel
│   └── ConvertingEntityInformation
└── config                                         # 编程式配置
    ├── EnableJpaRepositories                       # 扫描/工厂定制注解
    ├── JpaRepositoryConfigExtension
    └── JpaConfiguration（基类）
```

```text
org.springframework.boot.autoconfigure.orm.jpa      # Boot 自动配置
├── JpaBaseConfiguration / HibernateJpaAutoConfiguration / JpaProperties
├── HibernateProperties                            # spring.jpa.hibernate.*
└── HibernateJpaConfiguration
```

> 💡 记忆抓手：**`SimpleJpaRepository` 是所有 Repository 接口的默认实现**——你继承 `JpaRepository` 写的方法，运行时由 `JpaRepositoryFactory` 生成代理，最终都走 `SimpleJpaRepository` + `EntityManager` 执行。源码学习从 `SimpleJpaRepository` 入手看 CRUD，从 `PartTreeJpaQuery` 入手看派生方法翻译（4.0 重写后的主战场）。

### 2.1 运行时对象链

```text
业务代码 → ProductRepository（接口）
        → JDK 动态代理（JpaRepositoryFactory 生成）
        → SimpleJpaRepository（默认实现，含 @Transactional 模板方法）
        → EntityManager（JPA 规范 API，注入 Hibernate Session 实现）
        → Hibernate Session / PersistenceContext（一级缓存、脏检查、SQL 生成）
        → JDBC（HikariCP 连接池）
        → MySQL/PostgreSQL/SQL Server
```

> 🎯 面试高频：**"Spring Data JPA 和 Hibernate 什么关系？"**——JPA 是规范（接口+注解），Hibernate 是规范的实现（Provider），Spring Data JPA 是"在规范之上的仓库抽象层"（Repository 接口+方法名派生+声明式配置），三者是"规范 → 实现 → 更上层的便利抽象"。

## 3. 依赖边界

| 依赖 | 方向 | 说明 |
|------|------|------|
| spring-data-commons | 必须 | Repository/Pageable/Sort/审计等 Spring Data 底座（与 JPA 同版本列车） |
| jakarta.persistence-api | 必须（provided） | JPA 规范接口（4.1 线为 3.2 版，随 Jakarta EE 11） |
| Hibernate ORM | 运行时 | 默认 Provider（hibernate-core；starter 自动带） |
| Hibernate Processor | 编译期（annotationProcessor） | JPA metamodel 静态元模型生成器（4.0 起改名） |
| spring-aop / spring-tx | 必须 | @Transactional 的代理与事务管理器 |
| HikariCP | 运行时 | 默认连接池（spring-boot-starter-jdbc 自动带） |
| Jackson | 可选 | 实体序列化（Spring MVC 场景由 starter-web 带） |
| Querydsl | 可选（4.0 起需显式） | 动态查询备选（见 [05 篇](05-复杂查询与Specification速查.md) 现状说明） |

### 3.1 依赖方向约定

```text
业务代码
   │  只依赖
   ▼
spring-data-jpa ──► spring-data-commons ──► spring-core / spring-tx / spring-beans
   │
   ├──► jakarta.persistence-api（规范接口，编译期）
   ├──► hibernate-core（Provider，运行时）
   └──► spring-boot-starter-data-jpa（Boot 视角：一键装配以上全部）
```

> 💡 **分层认知**：业务代码**不应该**直接依赖 `org.hibernate` 包（除非用 Hibernate 专有 API）；正确姿势是依赖 `jakarta.persistence` + `org.springframework.data`。Hibernate 只是"底下实现"，换 Provider（如 EclipseLink）业务代码可不动——这就是 JPA 规范的价值。

## 4. 职责切割：SDJ vs Hibernate vs JPA 规范 vs 数据库

| 层 | 职责 | 典型代码/API | 本系列覆盖 |
|----|------|-------------|-----------|
| **Spring Data JPA** | 仓库抽象、方法名派生、分页排序、声明式事务边界、审计/事件 | `JpaRepository`、`findByName`、`Pageable`、`@Transactional`、`@CreatedDate` | ✅ 本系列全部 |
| **JPA 规范** | 实体映射标准、EntityManager 语义、JPQL 标准语法 | `@Entity`、`@Id`、`EntityManager`、`TypedQuery` | 03/04 篇映射与查询落点 |
| **Hibernate** | SQL 生成、一级缓存、脏检查、锁/隔离实现、方言 | `Session`、`@JdbcTypeCode`、dialect | 02/06/07 篇底层行为 |
| **数据库** | 存储、索引、事务 ACID 物理实现、锁等待 | DDL、SQL 执行计划 | [MySQL 系列](../../../../01-关系型数据库/MySQL/00-MySQL总览与技术术语.md) |
| **连接池** | 连接复用与治理 | HikariCP 参数 | [数据库连接池系列](../../../../01-关系型数据库/数据库连接池/) |

### 4.1 典型误判案例

| 现象 | 错误归因 | 正确归因 |
|------|---------|---------|
| 查询慢 | "JPA 太慢" | SQL 没走索引 / N+1（[07 篇](07-性能优化与批量操作速查.md)） |
| 并发更新丢数据 | "JPA 并发差" | 没加 @Version 乐观锁（[06 篇](06-事务与并发控制速查.md)） |
| 启动报 dialect 错误 | "配置错了" | Hibernate 7 自动检测，显式配置了旧类名（[02 篇](02-快速开始与连接配置速查.md)） |
| 事务外懒加载报错 | "JPA bug" | 设计问题：LazyInitializationException（[09 篇](09-集成地图与常见问题.md)） |

> 🎯 一句话：**Spring Data JPA 只管"API 好不好用"，SQL 质量与并发正确性由"查询写法 + 映射设计 + 数据库"共同决定**——排障永远从 SQL 与执行计划开始（`show-sql: true` 或 [MySQL 慢日志/SQL调优系列](../../../../01-关系型数据库/SQL调优/)）。

## 5. 版本兼容速查

| 你的项目 | 该用什么 | 迁移成本 |
|---------|---------|---------|
| 新项目（2026） | Boot 4.1 + SDJ 4.1 + Hibernate 7.4 + Java 21 | — |
| Boot 4.0 存量 | SDJ 4.0 + Hibernate 7.2，升 4.1 无痛（同大版本） | 低 |
| Boot 3.5 存量 | SDJ 3.5 + Hibernate 6.6，升 4.x 需 Java 21 + 全量回归 | **高**（见 [09 篇迁移清单](09-集成地图与常见问题.md)） |
| Boot 3.3/3.4 存量 | SDJ 3.3/3.4，尽快规划升级 | 高 |
| Boot 2.7 存量（2023 前） | SDJ 2.7 + javax 命名空间 | **极高**（两次大迁移：jakarta + Framework 7） |

### 5.1 兼容性对照表（Jakarta EE 时代）

| 版本线 | 命名空间 | JPA 规范 | Hibernate | Spring Framework | Java |
|--------|---------|---------|-----------|-----------------|------|
| SDJ 4.1.x | `jakarta.*` | 3.2 | 7.4.x | 7.0.x | 21+ |
| SDJ 4.0.x | `jakarta.*` | 3.2 | 7.2.x | 7.0.x | 21+ |
| SDJ 3.5.x | `jakarta.*` | 3.1 | 6.6.x | 6.2.x | 17+ |
| SDJ 3.3.x | `jakarta.*` | 3.1 | 6.5.x | 6.1.x | 17+ |
| SDJ 2.7.x | `javax.*` | 2.2 | 5.6.x | 5.3.x | 8+ |

> ⚠️ 升级到 4.x 前先跑全量测试——派生查询从 Criteria 生成改 JPQL 生成（构建期验证）后，**SQL 文本会变化**（行为等价但字面不同），`show-sql` 断言类测试会挂；另外 `hibernate-processor` 坐标不更新会导致 metamodel 静默缺失（[09 篇](09-集成地图与常见问题.md) 有完整清单）。
