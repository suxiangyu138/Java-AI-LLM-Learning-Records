## 1. 三步启动最小工程

### 1.1 依赖

```xml
<!-- 仅需这一个 starter，Hibernate/Hikari/JPA 接口全部自动装配 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-jpa</artifactId>
</dependency>
<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
    <scope>runtime</scope>
</dependency>
```

| 想用 | 追加依赖 | 说明 |
|------|---------|------|
| H2 内存库（开发/测试） | `com.h2database:h2`（runtime） | 零配置启动，测试首选 |
| PostgreSQL | `org.postgresql:postgresql`（runtime） | 驱动名 `org.postgresql.Driver` 自动检测 |
| SQL Server | `com.microsoft.sqlserver:mssql-jdbc`（runtime） | JDBC 42.x 版 |
| 数据库迁移 | `org.flywaydb:flyway-core` / `org.liquibase:liquibase-core` | 生产建表必选（别用 ddl-auto） |

> 💡 依赖最小化原则：**不要**手动引入 `hibernate-core`/`spring-data-jpa` 写版本——starter + Boot BOM 已锁定兼容版本（[01 篇](01-模块清单.md) 版本协调三原则）。

### 1.2 配置文件（application.yml）

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/shop?useSSL=false&serverTimezone=Asia/Shanghai&characterEncoding=utf8
    username: root
    password: root
    hikari:
      maximum-pool-size: 20        # 核心调参点：≈ 并发事务峰值 × (1 + 慢查询占比)
      minimum-idle: 5
      connection-timeout: 30000
  jpa:
    hibernate:
      ddl-auto: update             # 开发期；生产必须 none（由 Flyway/Liquibase 管）
    show-sql: true                 # 开发期；生产关掉（有 SQL 注入日志风险）
    open-in-view: false            # ★ 生产必设 false（9 大坑之首，见 09 篇）
    properties:
      hibernate:
        format_sql: true           # show-sql 时格式化输出
        jdbc.batch_size: 50        # 批量插入优化（见 07 篇）
    database-platform:             # ★ 不要配置！Hibernate 7 自动检测方言
```

> ⚠️ **Hibernate 7 关键变化**：`database-platform`（`hibernate.dialect`）**必须移除**——7.0 起按 JDBC 元数据自动检测方言，显式配置旧类名（如 `org.hibernate.dialect.MySQL8Dialect`，该类在 7.x 已改名/删除）会直接启动失败。自定义方言场景改走 `HibernatePropertiesCustomizer`（见 3.4 节）。

### 1.3 实体扫描与仓库扫描

| 机制 | 默认行为 | 定制 |
|------|---------|------|
| 实体扫描 | 主启动类所在包及子包 | `@EntityScan("com.example.entity")` |
| Repository 扫描 | 主启动类所在包及子包 | `@EnableJpaRepositories(basePackages = "...")` 或 `@EnableJpaRepositories(repositoryFactoryBeanClass=...)` |
| 事务管理器 | `JpaTransactionManager`（Bean 名 `transactionManager`） | `@EnableTransactionManagement` 一般不需要（Boot 默认开） |

```java
@SpringBootApplication
@EntityScan(basePackages = "com.example.shop.domain")
@EnableJpaRepositories(basePackages = "com.example.shop.repository")
public class ShopApplication { ... }
```

> 💡 多模块工程最常见的坑：**实体/仓库散落在主包之外但忘了声明扫描包** → 启动"不认识实体"/"找不到 Repository 实现"（[09 篇](09-集成地图与常见问题.md) 有排错表）。

### 1.4 最小实体 + 仓库跑通

```java
@Entity
@Table(name = "user_account")
public class UserAccount {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String username;        // 无 @Column 时驼峰自动映射下划线列 username

    protected UserAccount() {}      // JPA 规范要求无参构造（protected 即可）
    public UserAccount(String username) { this.username = username; }
    // getter/setter
}

public interface UserAccountRepository extends JpaRepository<UserAccount, Long> {
    Optional<UserAccount> findByUsername(String username);
}

// 使用（务必在事务内或确认无懒加载，见 06/09 篇）
UserAccount ua = new UserAccount("zhangsan");
userAccountRepository.save(ua);
Optional<UserAccount> found = userAccountRepository.findByUsername("zhangsan");
```

> 🎯 跑通即及格：**save → findById → findByUsername 三者全通**，说明"实体映射 + Repository 生成 + 事务管理"整条链路 OK，可以进 [03 篇](03-实体映射与关联映射速查.md) 学映射细节了。

## 2. Boot 4 属性总表

### 2.1 spring.datasource.*

| 属性 | 默认 | 说明 |
|------|------|------|
| `spring.datasource.url` | — | JDBC 连接串（不同库格式不同） |
| `spring.datasource.username` / `password` | — | 账号密码 |
| `spring.datasource.driver-class-name` | 自动检测 | 一般不用写，url 前缀推断 |
| `spring.datasource.hikari.*` | 见下 | HikariCP 参数（Boot 4 默认连接池仍为 Hikari） |
| `spring.datasource.hikari.maximum-pool-size` | 10 | 最大连接数 |
| `spring.datasource.hikari.minimum-idle` | = maximum-pool-size | 最小空闲（生产建议 = max，避免抖动建连） |
| `spring.datasource.hikari.connection-timeout` | 30000 | 获取连接超时（ms） |
| `spring.datasource.hikari.max-lifetime` | 1800000 | 连接最大存活（应小于数据库 wait_timeout） |
| `spring.datasource.hikari.connection-test-query` | 自动 | 探活 SQL（MySQL 自动用 `/* ping */`） |

> ⚠️ 连接池调参口诀：**池大小 ≠ 越大越好**——`maximum-pool-size ≈ 峰值并发事务数`（每事务占 1 连接），配大反增等待与内存；长事务/慢查询才是连接打满的根因（去优化 SQL，不是加连接）。

### 2.2 spring.jpa.*

| 属性 | 默认 | 说明 |
|------|------|------|
| `spring.jpa.hibernate.ddl-auto` | `create-drop`（内嵌库）/ `none`（其他） | `create`/`update`/`validate`/`none`；生产用 none + 迁移工具 |
| `spring.jpa.show-sql` | false | 打印 SQL（配合 format_sql 更可读） |
| `spring.jpa.open-in-view` | true | ★ 生产设 false（长连接持有事务隐患，见 09 篇） |
| `spring.jpa.properties.*` | — | 透传 Hibernate 原生属性（`hibernate.*` 键） |
| `spring.jpa.hibernate.naming.physical-strategy` | `CamelCaseToUnderscoresNamingStrategy` | 物理命名：驼峰→下划线 |
| `spring.jpa.hibernate.naming.implicit-strategy` | `SpringImplicitNamingStrategy` | ⚠️ Boot 4 包路径变化：`org.springframework.boot.hibernate.SpringImplicitNamingStrategy`（3.x 在 `...boot.orm.jpa.hibernate...`） |
| `spring.jpa.hibernate.use-new-id-generator-mappings` | true | 新 ID 生成器 |
| `spring.jpa.generate-ddl` | false | 是否让 Boot 执行建表（一般不直接用，走 ddl-auto） |

> 💡 Boot 4 相对 Boot 3 的 JPA 属性变化：① 命名策略类包路径迁移（见上表）；② `spring.data.jpa.query.native.parser` **已移除**（原用于原生查询解析增强，改用 `QueryEnhancerSelector`）；其余 `spring.jpa.*` 属性名基本未动。

### 2.3 常用 hibernate.* 透传属性

```yaml
spring:
  jpa:
    properties:
      hibernate:
        jdbc.batch_size: 50                  # 批量 DML 块大小（07 篇）
        jdbc.batch_versioned_data: true      # 版本字段也参与批处理
        order_inserts: true                  # 按类型排序插入，提升批处理命中率
        order_updates: true
        format_sql: true
        default_batch_fetch_size: 100        # 集合加载 in 子查询（缓解 N+1，07 篇）
        query.in_clause_parameter_padding: true  # in 子句参数 2 的幂填充（利于缓存复用）
        session.events.log.LOG_QUERIES_SLOWER_THAN_MS: 200  # 慢查询日志
```

> ⚠️ `hibernate.enable_lazy_load_no_trans` **在 Hibernate 7 已移除**——别再搜到旧教程往配置里加；懒加载必须在事务内（正解是 [06 篇](06-事务与并发控制速查.md) 的事务边界 + [09 篇](09-集成地图与常见问题.md) 的 LazyInitializationException 解法）。

## 3. Hibernate 7 配置变化（升级必读）

| 变化 | 3.x（Hibernate 6） | 4.x（Hibernate 7） | 迁移动作 |
|------|-------------------|-------------------|---------|
| 方言配置 | 显式 `hibernate.dialect` 常见 | **自动检测**（JDBC 元数据） | 删除显式配置 |
| 懒加载逃逸开关 | `enable_lazy_load_no_trans` 可用 | **已移除** | 删除；修正事务边界 |
| 命名策略包 | `org.springframework.boot.orm.jpa.hibernate.SpringImplicitNamingStrategy` | `org.springframework.boot.hibernate.SpringImplicitNamingStrategy` | 改包路径 |
| 注解处理器 | `hibernate-jpamodelgen` | `hibernate-processor` | 改坐标（[04 篇](04-Repository速查.md) metamodel 节） |
| Session.get(锁定) | `session.get(clazz, id, LockMode.PESSIMISTIC_WRITE)` | **已废弃** | 用 `session.byId(clazz).with(LockOptions.PESSIMISTIC_WRITE).load(id)` |
| @JoinColumn nullable | 默认 true（多年行为） | 默认行为调整 | 升级后审查外键可空性（新增的 NOT NULL 约束可能让旧数据插入失败） |
| 持久化上下文关闭 | — | 增强 | 无操作项 |

### 3.1 自定义方言（7.x 改名速查）

| 数据库 | 6.x 类名 | 7.x 类名 |
|--------|---------|---------|
| MySQL 8 | `org.hibernate.dialect.MySQLDialect`（8.x 合并） | 同左（8.x 后无 5/8 区分） |
| PostgreSQL | `org.hibernate.dialect.PostgreSQLDialect` | 同左（7.x 按版本折叠） |
| SQL Server | `org.hibernate.dialect.SQLServerDialect` | 同左 |
| H2 | `org.hibernate.dialect.H2Dialect` | 同左 |

> 💡 结论：**常规项目不要写任何 dialect 类名**；只有企业版定制 SQL 函数/类型映射时才需要 `HibernatePropertiesCustomizer` 注入自定义 dialect，且必须用 7.x 命名（每个旧 `*8Dialect` 类都已删除，写错直接 NoClassDefFoundError）。

### 3.2 HibernatePropertiesCustomizer 示例

```java
@Configuration
public class HibernateConfig {
    @Bean
    HibernatePropertiesCustomizer hibernateCustomizer() {
        return props -> props.put(AvailableSettings.DIALECT, MyDialect.class.getName());
    }
}
```

## 4. 编程式配置

非 Boot 环境或需精细控制时，用 Spring Data 原生配置类：

```java
@Configuration
@EnableJpaRepositories(basePackages = "com.example.repo")   // 仓库工厂/事务定制入口
@EnableTransactionManagement
public class JpaConfig {
    @Bean
    DataSource dataSource() { /* HikariDataSource ... */ }

    @Bean
    LocalContainerEntityManagerFactoryBean entityManagerFactory(DataSource ds) {
        LocalContainerEntityManagerFactoryBean emf = new LocalContainerEntityManagerFactoryBean();
        emf.setDataSource(ds);
        emf.setPackagesToScan("com.example.domain");          // 实体扫描
        emf.setJpaVendorAdapter(new HibernateJpaVendorAdapter());  // ★ Boot 4 起 databasePlatform 属性已移除，
                                                                   //   方言交给 Hibernate 自动检测
        return emf;
    }

    @Bean
    PlatformTransactionManager transactionManager(EntityManagerFactory emf) {
        return new JpaTransactionManager(emf);
    }
}
```

> ⚠️ Boot 4 中 `HibernateJpaVendorAdapter.setDatabasePlatform()`（老 `databasePlatform` 属性）**已移除**，这是编程式配置最常见的迁移报错点（`NoSuchMethodError`）。

## 5. 多数据源实战

> 业务上**优先单一数据源**；确需多库（主从读写分离、多租户分库）时用下法。多租户的 Hibernate 原生方案见 [08 篇](08-审计事件与多租户速查.md)。

### 5.1 多数据源骨架（两个 EntityManagerFactory）

```java
@Configuration
public class MultiDataSourceConfig {
    // ① 两个 DataSource（各自的连接参数）
    @Bean @Primary @ConfigurationProperties("spring.datasource.primary")
    DataSource primaryDs() { return DataSourceBuilder.create().build(); }

    @Bean @ConfigurationProperties("spring.datasource.secondary")
    DataSource secondaryDs() { return DataSourceBuilder.create().build(); }

    // ② 两个 EntityManagerFactory（必须指定 packagesToScan + persistenceUnit）
    @Bean @Primary
    LocalContainerEntityManagerFactoryBean primaryEmf(@Qualifier("primaryDs") DataSource ds) {
        LocalContainerEntityManagerFactoryBean emf = new LocalContainerEntityManagerFactoryBean();
        emf.setDataSource(ds);
        emf.setPackagesToScan("com.example.domain.primary");
        emf.setPersistenceUnitName("primary");
        return emf;
    }

    @Bean
    LocalContainerEntityManagerFactoryBean secondaryEmf(@Qualifier("secondaryDs") DataSource ds) {
        LocalContainerEntityManagerFactoryBean emf = new LocalContainerEntityManagerFactoryBean();
        emf.setDataSource(ds);
        emf.setPackagesToScan("com.example.domain.secondary");
        emf.setPersistenceUnitName("secondary");
        return emf;
    }

    // ③ 两个 JpaTransactionManager（事务边界要指名用哪个！）
    @Bean @Primary
    JpaTransactionManager primaryTx(@Qualifier("primaryEmf") EntityManagerFactory emf) {
        return new JpaTransactionManager(emf);
    }

    @Bean
    JpaTransactionManager secondaryTx(@Qualifier("secondaryEmf") EntityManagerFactory emf) {
        return new JpaTransactionManager(emf);
    }
}

// ④ 仓库分两批扫描
@Configuration
@EnableJpaRepositories(basePackages = "com.example.repo.primary",
        entityManagerFactoryRef = "primaryEmf", transactionManagerRef = "primaryTx")
class PrimaryRepoConfig {}

@Configuration
@EnableJpaRepositories(basePackages = "com.example.repo.secondary",
        entityManagerFactoryRef = "secondaryEmf", transactionManagerRef = "secondaryTx")
class SecondaryRepoConfig {}
```

### 5.2 多数据源三大坑

| 坑 | 症状 | 解法 |
|----|------|------|
| 实体被两个 EMF 都扫到 | `Ambiguous mapping` 或重复建表 | 两库实体**分包隔离**（primary/secondary 子包） |
| 事务用错管理器 | 跨库操作只提交了一半 | `@Transactional("secondaryTx")` 显式指定；**一个事务管一个库** |
| 主从只读分离 | 写操作走了只读实例 | `@Transactional(readOnly=true)` 精确标注读方法；或按方法切换 |

> 💡 主从读写分离的现代做法：引入 `@RoutingDataSource`（AbstractRoutingDataSource）+ 事务只读语义路由；要真正读高可用还是上中间件（ShardingSphere）或云数据库，框架层方案治标不治本。

## 6. 常见连接问题排错

| 症状 | 根因 | 排查动作 |
|------|------|---------|
| `Communications link failure` / Connection refused | 数据库没起 / url 错 / 防火墙 | `telnet localhost 3306`；`mysql -uroot -p` 手动连 |
| `Access denied for user` | 账号密码/授权错 | 用客户端确认账号；`GRANT ALL ON shop.* TO 'root'@'%'` |
| `Public Key Retrieval is not allowed` | MySQL 8 认证插件（caching_sha2_password） | url 加 `allowPublicKeyRetrieval=true` |
| 启动报方言类找不到 | 显式配置了旧 dialect 类 | 删除 `database-platform`（Hibernate 7 自动检测） |
| `Unknown column 'xxx'` | 实体字段与表列不一致 | 对 `@Column(name=...)` 或改表；`ddl-auto: validate` 启动校验 |
| `Table 'shop.product' doesn't exist` | ddl-auto=none 且没建表 | 开发用 update/create-drop；生产上 Flyway 迁移脚本 |
| 连接被数据库踢（`Connection is not available`） | max-lifetime > 数据库 wait_timeout | `hikari.max-lifetime` 设 < 数据库超时（MySQL 默认 8h → 设 30min） |
| 启动巨慢 | 实体扫描范围过大 / 无连接可用重试 | 收窄 `@EntityScan`；检查池参数与数据库可达性 |

> 🎯 排障顺序铁律：**数据库层（能连上吗）→ 连接层（池配置对吗）→ 映射层（表和实体对得上吗）→ 查询层（SQL 对吗）**——从下往上，90% 的"JPA 启动失败"在数据库/连接层就解决了，别先怀疑框架。
