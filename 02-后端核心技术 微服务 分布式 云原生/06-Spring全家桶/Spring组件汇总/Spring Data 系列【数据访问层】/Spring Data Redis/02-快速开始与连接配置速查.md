## 1. 三步启动最小工程

### 1.1 依赖

```xml
<!-- 最小依赖：Lettuce 默认驱动，无需额外配置 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-redis</artifactId>
</dependency>

<!-- 需要连接池时追加（★ Lettuce 池化必需） -->
<dependency>
    <groupId>org.apache.commons</groupId>
    <artifactId>commons-pool2</artifactId>
</dependency>
```

| 场景 | 追加依赖 | 说明 |
|------|---------|------|
| Lettuce + 连接池（生产标配） | `commons-pool2` | 不加则 Lettuce 单共享连接不复用 |
| 换 Jedis | `redis.clients:jedis` + 排除 lettuce | 老项目存量习惯（[01 篇](01-模块清单.md) 2 节） |
| 响应式 | 无额外依赖 | Lettuce 原生支持（[08 篇](08-响应式与ReactiveRedisTemplate速查.md)） |

> 💡 依赖最小化原则：**不要**手动引入 lettuce/jedis 写版本——starter + Boot BOM 已锁定（[01 篇](01-模块清单.md) 版本协调三原则）。

### 1.2 配置文件（application.yml）

```yaml
spring:
  data:
    redis:
      host: localhost                 # 单节点：host/port
      port: 6379
      password:                       # 无认证留空
      database: 0                     # 逻辑库（默认 0；生产按业务分库/分前缀）
      timeout: 3s                     # 命令超时
      lettuce:
        pool:                         # ★ 池化（需 commons-pool2）
          max-active: 16              # 池上限（≈ 峰值并发 × (1+慢查询占比)）
          max-idle: 8
          min-idle: 2
          max-wait: 3s                # 获取连接等待上限
      # 连接串写法（二选一，优先）：
      # url: redis://user:pass@localhost:6379/0
```

### 1.3 模板 Bean（序列化配置是第一步）

```java
@Configuration
public class RedisConfig {
    @Bean
    RedisTemplate<String, Object> redisTemplate(RedisConnectionFactory factory) {
        RedisTemplate<String, Object> t = new RedisTemplate<>();
        t.setConnectionFactory(factory);
        // ★ key 必须 String 序列化（业务可读、跨端一致）
        t.setKeySerializer(new StringRedisSerializer());
        t.setHashKeySerializer(new StringRedisSerializer());
        // value 用 JSON（GenericJackson2JsonRedisSerializer 带类型信息）
        t.setValueSerializer(new GenericJackson2JsonRedisSerializer());
        t.setHashValueSerializer(new GenericJackson2JsonRedisSerializer());
        t.afterPropertiesSet();
        return t;
    }
}
```

> 🎯 跑通即及格：**SET 写 → GET 读 → redis-cli 核对**——key 清晰、value 是 JSON（或业务约定格式）= 序列化配置 OK；出现 `\xAC\xED\x00\x05` 前缀 = 默认 JDK 序列化，必须换（[03 篇](03-序列化器与实体映射速查.md) 乱码排查）。

## 2. Boot 4 属性总表

### 2.1 spring.data.redis.*（通用）

| 属性 | 默认 | 说明 |
|------|------|------|
| `spring.data.redis.host` / `port` | localhost / 6379 | 单节点地址 |
| `spring.data.redis.url` | — | 连接串（redis://user:pass@host:port/db），优先于 host/port |
| `spring.data.redis.password` | — | 认证密码（与 url 二选一） |
| `spring.data.redis.database` | 0 | 逻辑库编号 |
| `spring.data.redis.timeout` | 60s | 命令超时（**生产建议 2-3s**，防慢命令占连接） |
| `spring.data.redis.connect-timeout` | — | 连接超时（默认同 timeout） |
| `spring.data.redis.client-name` | — | 客户端名（集群监控里识别） |
| `spring.data.redis.username` | — | ACL 用户名（Redis 6+ ACL） |

### 2.2 驱动级属性

| 属性 | 说明 |
|------|------|
| `spring.data.redis.lettuce.pool.*` | max-active/max-idle/min-idle/max-wait/time-between-eviction |
| `spring.data.redis.lettuce.shutdown-timeout` | 关闭超时 |
| `spring.data.redis.jedis.pool.*` | Jedis 池参数（同结构） |
| `spring.data.redis.lettuce.pool.enabled` | 池开关（false = 共享连接不池化） |
| `spring.data.redis.sentinel.master` / `nodes` | 哨兵配置（第 4 节） |
| `spring.data.redis.cluster.nodes` | 集群节点列表（第 4 节） |

> ⚠️ **timeout 是命令超时不是连接超时**：默认 60s 意味着一条慢命令（如大 KEYS/大批量）可以占连接 60 秒——生产设 2-3s + 慢命令治理（[07 篇](07-管道事务与批量性能速查.md)）。

## 3. 连接池：Lettuce 池化与 Jedis 池

### 3.1 Lettuce 连接模型（先理解再配池）

```text
无池化（默认）：
  Lettuce 单条共享连接 ← 所有线程复用（Netty 非阻塞，线程安全）
  → 优点：零池开销；缺点：无并发上限，一条慢命令拖所有请求

池化（加 commons-pool2）：
  连接池（max-active=16）→ 每次命令借/还连接
  → 优点：并发隔离、可控；缺点：池化开销（借还）
```

| 场景 | 池化？ |
|------|:---:|
| 单机低并发（<100 QPS） | 可不池化（共享连接够用） |
| 生产多实例/高并发 | **推荐池化**（隔离 + 可控上限） |
| 响应式（ReactiveRedisTemplate） | 不池化（Lettuce 共享连接天然适配非阻塞） |

> 🎯 面试必答：**"Lettuce 要不要连接池？"**——Lettuce 是 Netty 非阻塞模型，**单连接可多线程共享**（线程安全），默认不池化也能跑；加池（commons-pool2）的意义是**控制并发上限与隔离**（防一条慢命令拖全部 + 防连接数不可控）；响应式场景**不要池化**（共享连接 + 非阻塞是绝配）——结论：**同步生产上池，响应式不上池**。

### 3.2 池参数速查

| 参数 | 默认 | 调参要点 |
|------|------|---------|
| `max-active` | 8 | ≈ 峰值并发 × (1 + 慢命令占比)；太大浪费、太小排队 |
| `max-idle` / `min-idle` | 8 / 0 | 预热（min-idle=2 启动即建） |
| `max-wait` | -1（无限等） | **生产必须设**（如 3s），防无限排队拖死调用方 |
| `time-between-eviction-runs` | — | 空闲回收周期 |

> ⚠️ 连接池误区：**池大小 ≠ 吞吐**——Redis 单线程处理命令（8.4 部分多线程），连接再多单条命令还是串行；池的意义在"隔离慢命令 + 控制客户端连接数"，吞吐靠"少而快的命令 + 管道"（[07 篇](07-管道事务与批量性能速查.md)）。

## 4. 哨兵与集群连接

### 4.1 哨兵（高可用）

```yaml
spring:
  data:
    redis:
      sentinel:
        master: mymaster              # 哨兵监控的主节点名
        nodes: host1:26379,host2:26379,host3:26379   # 哨兵节点（不是 Redis 节点！）
      password: xxx                   # 若哨兵/主节点开了认证
```

| 要点 | 说明 |
|------|------|
| 连接的是哨兵 | `nodes` 填**哨兵端口 26379**，不是 Redis 6379 |
| 故障转移 | 主节点宕机 → 哨兵选举新主 → 客户端自动切换（Lettuce 自动刷新拓扑） |
| 客户端配置 | 只配 master 名 + 哨兵列表，无需关心当前主节点是谁 |

### 4.2 集群（Cluster）

```yaml
spring:
  data:
    redis:
      cluster:
        nodes: host1:6379,host2:6379,host3:6379   # 任一节点即可（自动发现全拓扑）
      timeout: 3s
```

| 要点 | 说明 |
|------|------|
| 命令路由 | 自动计算 slot → 路由到对应节点（MOVED/ASK 重定向自动处理） |
| 多 key 命令 | **跨 slot 的 multi-key 命令不可用**（MGET 需同 slot → 用 hash tag `{user:1}`） |
| 拓扑刷新 | 集群变更（加节点/迁移 slot）后自动刷新（Lettuce 支持自适应刷新） |
| 原子槽迁移 | Redis 8.4 `CLUSTER MIGRATION` 后客户端仍需拓扑刷新（[00 篇](00-Spring Data Redis组件总览.md) 2.2） |

```java
// hash tag：强制多 key 落在同一 slot（跨 key 事务/管道的前提）
redisTemplate.opsForValue().set("{user:123}:profile", p);
redisTemplate.opsForValue().set("{user:123}:session", s);
// MGET/事务在集群下可用（同 slot）
```

> ⚠️ **集群三坑**：① 多 key 操作（事务/管道/MGET）必须同 slot（hash tag）；② 单节点命令 `KEYS *` 在集群下会全节点扫描（禁止，用 SCAN）；③ 哨兵与集群**二选一**（哨兵=单主多从高可用，集群=分片扩展），别混配。

## 5. TLS 与认证

```yaml
spring:
  data:
    redis:
      url: rediss://user:pass@redis.example.com:6379/0   # rediss:// = TLS（注意双 s）
      ssl: true                                          # 或显式开启
      # 自定义 SSL 上下文：编程式（第 5.1 节）
```

| 场景 | 配置 |
|------|------|
| 云 Redis（阿里云/腾讯云/AWS ElastiCache） | 必须 TLS + 密码（`rediss://`） |
| 自建 | 可选 TLS（`spring.data.redis.ssl: true`） |
| ACL 用户名 | Redis 6+ 支持 `username` 属性（不填默认 default 用户） |

```java
// 编程式 TLS（自定义证书/双向认证）
@Bean
RedisConnectionFactory redisConnectionFactory() {
    RedisStandaloneConfiguration cfg = RedisStandaloneConfiguration.withHostAndPort("host", 6379);
    cfg.setPassword("pass");
    SslOptions ssl = SslOptions.builder()
            .trustManager(trustStorePath, trustStorePassword)   // 服务端证书信任
            .build();
    LettuceClientConfiguration client = LettuceClientConfiguration.builder()
            .useSsl().sslOptions(ssl)
            .commandTimeout(Duration.ofSeconds(3))
            .build();
    return new LettuceConnectionFactory(cfg, client);
}
```

> ⚠️ 安全红线：① 密码别硬编码进 yml（环境变量/配置中心 `#{${REDIS_PASSWORD}}`）；② 生产必须 TLS（云服务商默认）；③ 用 ACL 最小权限账号（Redis 6+），别用默认超管。

## 6. 常见连接问题排错

| 症状 | 根因 | 排查动作 |
|------|------|---------|
| `Connection refused` | Redis 没起/端口错/防火墙 | redis-cli -h host -p 6379 ping |
| `NOAUTH Authentication required` | 开了认证但没配密码 | yml password / url 带密码 |
| `WRONGPASS invalid username-password pair` | 密码错/ACL 用户错 | redis-cli -a 验证；确认 username |
| key 乱码（`\xAC\xED`） | 默认 JDK 序列化 | 配置序列化器（[03 篇](03-序列化器与实体映射速查.md)） |
| 高并发连接数暴涨 | Lettuce 没池化 + 高并发 | 加 commons-pool2 + max-active（第 3 节） |
| `MOVED`/`ASK` 重定向报错 | 集群配置/路由问题 | 确认 cluster.nodes 配置；Lettuce 自动处理但拓扑未刷新时可能透出 |
| 命令超时（`command timed out`） | 慢命令/大 key/网络 | timeout 调 2-3s + 慢命令治理（[07 篇](07-管道事务与批量性能速查.md)） |
| `unknown command 'X'` | Redis 版本低于新命令要求 | 确认服务端版本（[04 篇](04-操作API与Redis-8-4新命令速查.md) 版本对照） |
| TLS 握手失败 | ssl 未开/证书不信任 | `rediss://` 或 ssl:true；自定义 trustManager |

> 🎯 排障顺序铁律（同系列通用）：**Redis 层（redis-cli 能通吗）→ 连接层（认证/TLS/池配置对吗）→ 序列化层（key 可读吗）→ 命令层（版本/慢命令吗）**——从下往上，90% 的问题在前两层。
