## 1. Artifact 坐标与版本线

| 项 | 值 |
|----|----|
| GroupId | `org.springframework.data` |
| ArtifactId | `spring-data-redis` |
| 当前线 | 4.1.x（4.1.0，2026.0 发行列车，2026-08 时点） |
| 稳定线 | 4.0.x（2025.1 列车，Boot 4.0.x） |
| 存量线 | 3.5.x（2025.0 列车，Boot 3.5.x，**已停止维护**） |
| Java 基线 | 21+（随 Boot 4 / Spring Framework 7） |
| 驱动 | Lettuce 7.5.1（默认）/ Jedis 7.4.1 |
| 配套 | spring-data-commons、commons-pool2（池化）、Redis 8.4 |

> 💡 版本记忆口诀："**4.x 配 Boot 4 + Redis 8.x**"——2026 年起新项目直接 4.1；服务端版本影响新命令可用性（[04 篇](04-操作API与Redis-8-4新命令速查.md) 版本对照）。

### 1.1 引入方式速查

| 方式 | 写法 | 说明 |
|------|------|------|
| Boot starter（推荐） | `spring-boot-starter-data-redis` | SDR + Lettuce + 自动配置 |
| 换 Jedis 驱动 | 加 `redis.clients:jedis` + 排除 lettuce | 显式声明驱动（第 2 节） |
| 连接池 | 加 `org.apache.commons:commons-pool2` | Lettuce 池化必需（不加大不池化） |
| Maven 显式 | `org.springframework.data:spring-data-redis:4.1.0` | 非 Boot 项目 |

```xml
<!-- Boot 4 最小依赖（Lettuce 默认） -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-redis</artifactId>
</dependency>
<!-- 需要连接池时追加（Lettuce 池化必需） -->
<dependency>
    <groupId>org.apache.commons</groupId>
    <artifactId>commons-pool2</artifactId>
</dependency>
```

> ⚠️ **版本协调三原则**：① 永远跟 Boot BOM 走，不手写 SDR/驱动版本；② **Lettuce 默认、Jedis 显式二选一**（混用两套驱动 = 两份连接管理）；③ 连接池：**Lettuce 池化需要 commons-pool2**（不加则连接不复用，高并发打爆 Redis 连接数）。

## 2. 驱动双轨：Lettuce vs Jedis

| 维度 | Lettuce（默认） | Jedis |
|------|----------------|-------|
| 底层模型 | **Netty 非阻塞**（共享连接） | 阻塞（每线程一条连接，池化） |
| 线程安全 | ✅ 单连接多线程共享 | ❌ 靠连接池（getResource/close） |
| 响应式 | ✅ **原生支持**（ReactiveRedisTemplate 的地基） | ❌（4.1 起部分） |
| 连接池 | 可选（commons-pool2） | 必需（JedisPool） |
| 默认选择 | **Boot 默认**（推荐新项目） | 老项目存量 |
| 4.1 状态 | 7.5.1 | 7.4.1（**UnifiedJedis 新 API**） |

> 🎯 面试必答：**"Lettuce 和 Jedis 区别？"**——Lettuce 基于 Netty **非阻塞**：单连接可被多线程共享（省连接、支持响应式）；Jedis 是**阻塞**模型：每条命令独占连接，靠池化并发——**Boot 默认 Lettuce**，响应式场景必须 Lettuce；老项目用 Jedis 的注意 4.1 的 UnifiedJedis 迁移（第 3 节）。

## 3. UnifiedJedis 迁移专节（4.1 头条）

> **Spring Data Redis 4.1 的重大变化**：Jedis 驱动从 legacy API 迁移到 **UnifiedJedis**（Jedis 7 现代客户端）——凡是自定义 Jedis 连接工厂/集群连接的代码都要动。

### 3.1 迁移对照

| 维度 | 4.0 及以前（legacy） | 4.1（UnifiedJedis） |
|------|--------------------|--------------------|
| 客户端类 | `Jedis` / `JedisPool` / `JedisCluster` | `JedisRedisClient` / `RedisClient` / `RedisClusterClient` |
| 连接工厂 | 手写 JedisConnectionFactory 扩展 | 由 `JedisClientConfiguration` 构建（builder 模式） |
| 集群 | `JedisClusterConnection` 老构造器 | `JedisClusterTopologyProvider(UnifiedJedis, Duration)` |
| 连接管理 | `getResource()`/`close()` 显式 | **命令执行后自动归还池**（无显式获取/关闭） |
| 配置 | 50+ 重载构造器 | builder 模式集中配置 |
| 线程安全 | 客户端不安全（池化兜底） | 客户端**线程安全可共享** |

```java
// 4.1 编程式构建 Jedis 连接工厂（新姿势）
@Bean
RedisConnectionFactory jedisConnectionFactory() {
    JedisClientConfiguration config = JedisClientConfiguration.builder()
            .clientName("shop-service")
            .build();
    return new JedisConnectionFactory(
            RedisStandaloneConfiguration.withHostAndPort("localhost", 6379), config);
}
```

### 3.2 迁移动作清单

| # | 动作 | 说明 |
|---|------|------|
| ① | 升级 Jedis 到 7.4.1 | BOM 管理，无需手写 |
| ② | 替换 `Jedis`/`JedisCluster` 直接调用 | 业务代码**不应直接使用**驱动类（应走 RedisTemplate）——只在自定义工厂/监控里出现 |
| ③ | 自定义连接工厂改 builder 构建 | `JedisClientConfiguration.builder()` |
| ④ | 集群拓扑构造器参数变化 | `JedisClusterTopologyProvider(UnifiedJedis, Duration)` |
| ⑤ | 依赖 commons-pool2 配置池 | UnifiedJedis 的池化是内建的（隐式），旧 pool 配置迁移 |
| ⑥ | 全量回归 | 哨兵/集群/管道/事务路径重点测（[10 篇](10-集成地图与常见问题.md) 迁移清单） |

> 🎯 面试必答：**"Spring Data Redis 4.1 的 UnifiedJedis 迁移是什么？"**——Jedis 7 推出的统一客户端 API（`UnifiedJedis`：命令创建 CommandObjects / 执行 CommandExecutor / 反序列化 BuilderFactory 三分离），Spring Data Redis 4.1 用它替代 legacy Jedis：客户端 `RedisClient`/`RedisClusterClient` 线程安全、builder 配置、命令执行后自动归还池——**迁移收益**：去掉显式 getResource/close、50+ 构造器收敛；**迁移风险**：自定义连接工厂/集群代码的 API 变化。

## 4. 包结构地图

```text
org.springframework.data.redis
├── core                                        # ★ 核心
│   ├── RedisTemplate / ReactiveRedisTemplate    # 同步/响应式模板
│   ├── RedisAccessor（模板基类：序列化器/连接工厂装配）
│   ├── DefaultStringRedisConnection / DefaultRedisScript
│   └── RedisMessageSendingTemplate（4.1 新）
├── connection                                 # ★ 连接层
│   ├── RedisConnectionFactory / RedisConnection / RedisClusterConnection
│   ├── lettuce
│   │   ├── LettuceConnectionFactory / LettuceConnection / LettuceClusterConnection
│   │   └── LettuceClientConfiguration（builder）
│   ├── jedis
│   │   ├── JedisConnectionFactory / JedisConnection / JedisClusterConnection
│   │   └── JedisClientConfiguration（builder，4.1 UnifiedJedis）
│   ├── DataAccessException（异常体系：RedisSystemException 等）
│   └── stream（StreamOperations 基础设施）
├── core.script                                # Lua 脚本
│   ├── DefaultRedisScript / RedisScript / ScriptExecutor
├── core.operations                            # ★ 六大 Operations
│   ├── ValueOperations / HashOperations / ListOperations
│   ├── SetOperations / ZSetOperations / StreamOperations
│   ├── GeoOperations / HyperLogLogOperations
│   └── BoundXxxOperations（绑定 key 的变体）
├── repository                                 # Repository 模式
│   ├── RedisRepository / RedisHashRepository
│   ├── mapping（@RedisHash / @Indexed / RedisPersistentEntity）
│   └── support（QueryByExample 等）
├── cache                                      # Spring Cache 适配
│   ├── RedisCacheManager / RedisCache / RedisCacheConfiguration
│   └── RedisCacheWriter（4.0 非阻塞 evict）
├── listener                                   # 消息监听
│   ├── RedisMessageListenerContainer / StreamMessageListenerContainer
│   ├── RedisMessageListenerAdapter / MessageConverter
│   └── @RedisListener / @EnableRedisListeners（2026 新）
├── search                                     # 搜索（RediSearch 适配）
│   └── RedisSearchRepository / query
├── observability                               # 可观测
│   ├── RedisTracingCommandInterceptor / RedisMetricsCommandInterceptor
│   └── Micrometer 集成
└── config                                     # 配置
    ├── EnableRedisRepositories / RedisConfiguration
    └── RedisBootstrapConfiguration
```

> 💡 记忆抓手：**`RedisTemplate` 是同步主入口、`ReactiveRedisTemplate` 是响应式主入口**——两者都基于连接工厂 + 序列化器；源码学习从 `RedisTemplate` 的 execute 回调模型入手（它不直接持有连接，每次 execute 从工厂取）。

### 4.1 运行时对象链

```text
业务代码
  → RedisTemplate.execute（回调模型：从工厂取连接 → 执行命令 → 归还）
  → RedisConnectionFactory（Lettuce：单共享连接 / Jedis：池）
  → Lettuce Connection（Netty 非阻塞 / Jedis Connection（阻塞））
  → Redis 8.4 集群（RESP 协议）
```

## 5. 职责切割：SDR vs 驱动 vs Redis 引擎

| 层 | 职责 | 典型代码/API | 本系列覆盖 |
|----|------|-------------|-----------|
| **Spring Data Redis** | 模板、序列化、缓存抽象、消息、Repository | `RedisTemplate`、`@Cacheable`、`@RedisListener` | ✅ 本系列全部 |
| **驱动**（Lettuce/Jedis） | 协议实现、连接管理 | `LettuceConnectionFactory`、`RedisClient` | 02 篇连接配置 |
| **Redis 引擎** | 数据结构、持久化、高可用、搜索 | 服务端命令（SET/HSET/XADD/FT.HYBRID） | [Redis 深度体系](../../../../02-非关系型数据库/Redis/01-Redis入门与安装配置.md) |

### 5.1 典型误判案例

| 现象 | 错误归因 | 正确归因 |
|------|---------|---------|
| key 乱码 | "Redis 坏了" | 序列化器配置错（[03 篇](03-序列化器与实体映射速查.md)） |
| 缓存全丢 | "框架丢数据" | 持久化策略（AOF/主从）配置（[Redis-04](../../../../02-非关系型数据库/Redis/04-Redis持久化与数据安全.md)） |
| 高并发连接爆 | "Redis 扛不住" | Lettuce 没开池化（缺 commons-pool2）（[02 篇](02-快速开始与连接配置速查.md)） |
| 事务不生效 | "Redis 事务没用" | Redis 事务无回滚 + 需 enableTransactionSupport（[07 篇](07-管道事务与批量性能速查.md)） |

## 6. 版本兼容速查

| 你的项目 | 该用什么 | 迁移成本 |
|---------|---------|---------|
| 新项目（2026） | Boot 4.1 + SDR 4.1 + Lettuce 7.5.1 + Redis 8.4 | — |
| Boot 4.0 存量 | SDR 4.0，升 4.1 需过 UnifiedJedis 检查（用 Jedis 时） | 中（仅 Jedis 用户） |
