## 1. 与全家桶的集成地图

| 组件 | 联动点 | 要点 |
|------|--------|------|
| Spring Cache | 缓存抽象 | @Cacheable + RedisCacheManager（[05 篇](05-缓存实战：Spring-Cache与一致性速查.md)） |
| WebFlux | 响应式缓存 | ReactiveRedisTemplate（[08 篇](08-响应式与ReactiveRedisTemplate速查.md)） |
| Spring MVC | 会话/验证码 | StringRedisTemplate 存 token/验证码（[03 篇](03-序列化器与实体映射速查.md)） |
| R2DBC | 响应式数据层 | 全链路 Cache-Aside（[08 篇](08-响应式与ReactiveRedisTemplate速查.md) 4 节） |
| JPA | 缓存 + 一致性 | 读多写少数据 Redis 缓存，Cache-Aside 先库后删（[05 篇](05-缓存实战：Spring-Cache与一致性速查.md) 4 节） |
| 消息队列 | 任务可靠性 | 轻量用 Stream、重量上 MQ（[09 篇](09-消息Pub-Sub与Stream速查.md) 6 节） |
| Spring AI | 语义缓存 | Redis 8.4 向量检索 + Embedding（[05 篇](05-缓存实战：Spring-Cache与一致性速查.md) 6 节） |
| 可观测 | 命令级指标 | Micrometer + Redis 连接工厂观测回调（[Redis-05](../../../../02-非关系型数据库/Redis/05-Redis高可用架构.md)） |
| Redisson | 分布式锁 | 生产锁首选（[06 篇](06-分布式锁与Lua脚本速查.md) 3.2） |

> 🎯 集成总原则：**Redis 是"加速与协作层"**——放得进缓存/原子/消息的都是它的菜；主数据、强一致、复杂查询留给 JPA/MongoDB/ES——**"这数据丢了能重建吗？"能 → Redis，不能 → 主存储**。

## 2. 家族五组件协同作战

| 场景 | JPA | MongoDB | ES | R2DBC | **Redis** |
|------|:---:|:---:|:---:|:---:|:---:|
| 主数据（订单/用户） | ✅ | 备选 | ❌ | 备选 | ❌ |
| 文档型/向量 | ❌ | ✅ | 备选 | ❌ | ❌ |
| 全文搜索 | ❌ | ⚠️ | ✅ | ❌ | ❌ |
| 高并发响应式 SQL | ❌ | ❌ | ❌ | ✅ | ❌ |
| **热点缓存/计数/锁/消息** | ❌ | ❌ | ❌ | ❌ | **✅** |

```text
经典协同（电商下单）：
  MySQL（JPA）主数据 ←→ Redis（缓存商品/计数/防重/锁）→ 秒杀削峰走 MQ
  ES 搜索 ←→ MongoDB 日志/画像 ←→ Redis 会话/排行榜
  响应式网关（R2DBC + ReactiveRedis）全链路非阻塞
```

> 💡 **Redis 在家族里的独特生态位**：唯一"无查询语言但有原子性"的组件——**它不跟谁竞争，它给所有人加速**；分布式锁/限流/防重/排行榜/语义缓存这些"跨组件协作能力"是 Redis 的专属领地。

## 3. 3.x → 4.1 迁移清单

> Boot 3.5（SDR 3.5）→ Boot 4.1（SDR 4.1 + Redis 8.x）。**前置条件：Java 21**。

### 3.1 必改项

| # | 项目 | 3.x | 4.x | 说明 |
|---|------|-----|-----|------|
| ① | Java/框架基线 | Java 17 + Framework 6.2 | **Java 21 + Framework 7.0** | 非协商项 |
| ② | **Jedis 驱动** | legacy Jedis API | **UnifiedJedis（7.4.1）** | 仅 Jedis 用户（[01 篇](01-模块清单.md) 3 节迁移清单） |
| ③ | Jackson | 2.x（com.fasterxml） | **3.x（tools.jackson）** | 序列化器依赖变化（[03 篇](03-序列化器与实体映射速查.md) 4 节） |
| ④ | 空值注解 | JetBrains | JSpecify | 静态检查适配 |
| ⑤ | 已移除 API | — | 3.x 废弃项清理 | 编译期错误逐条解 |

### 3.2 行为变化（重点回归）

| # | 项目 | 变化 | 回归要点 |
|---|------|------|---------|
| ⑥ | **管道与事务互斥** | 4.x 约束增强 | Lettuce 下管道内开事务的代码要改（[07 篇](07-管道事务与批量性能速查.md) 2 节） |
| ⑦ | Jackson 3 序列化 | @class 格式兼容性 | **存量数据全量读写回归**（[03 篇](03-序列化器与实体映射速查.md) 4 节） |
| ⑧ | resetCaches 语义 | 4.1 单次 FLUSHDB | 同 DB 多业务共用时评估影响（[05 篇](05-缓存实战：Spring-Cache与一致性速查.md) 2.2） |
| ⑨ | 连接/池默认值 | 参数调整 | 生产连接池配置显式化（[02 篇](02-快速开始与连接配置速查.md)） |
| ⑩ | Redis 8.x 命令 | 新命令可用 | 服务端版本确认（[04 篇](04-操作API与Redis-8-4新命令速查.md) 6.2） |

### 3.3 升级收益验收

| 新能力 | 出处 | 验收方式 |
|--------|------|---------|
| @RedisListener 注解监听 | [09 篇](09-消息Pub-Sub与Stream速查.md) 4 节 | 一处监听改注解式 |
| 8.4 条件 SET/DEL | [04 篇](04-操作API与Redis-8-4新命令速查.md) 5 节 | 防重/锁释放免 Lua 重构 |
| resetCaches 单次清空 | [05 篇](05-缓存实战：Spring-Cache与一致性速查.md) 2.2 | 发版缓存失效流程 |
| 类型安全属性路径 | 全家族 | 模板层重构（如适用） |

> 🎯 迁移心法（同系列通用）：**先解编译期硬约束（①-⑤）→ 跑全量测试暴露行为变化（⑥-⑩）→ 按业务验收新能力**——其中 ②③（UnifiedJedis + Jackson 3）是 Redis 系列特有的两大迁移重点，**存量数据兼容性回归不可省**。

## 4. 高频坑排错表

| 症状 | 根因 | 解法 |
|------|------|------|
| key 乱码（`\xAC\xED`） | JDK 默认序列化 | 配置序列化器（[03 篇](03-序列化器与实体映射速查.md) 7 节） |
| 反序列化失败（ClassCast/JSON parse） | 类型信息丢失/序列化器不一致 | @class 检查；双模板序列化器对齐（[03 篇](03-序列化器与实体映射速查.md)） |
| `Connection refused` | Redis 没起/端口/防火墙 | redis-cli ping（[02 篇](02-快速开始与连接配置速查.md) 6 节） |
| `NOAUTH` / `WRONGPASS` | 认证配置 | password/url/username（[02 篇](02-快速开始与连接配置速查.md) 5 节） |
| 高并发连接数暴涨 | Lettuce 没池化 | commons-pool2 + max-active（[02 篇](02-快速开始与连接配置速查.md) 3 节） |
| 命令超时 | 慢命令/大 key | timeout 2-3s + 慢命令治理（[07 篇](07-管道事务与批量性能速查.md) 6 节） |
| `unknown command` | Redis 版本低 | 确认服务端版本（[04 篇](04-操作API与Redis-8-4新命令速查.md) 6.2） |
| @Cacheable 不生效 | 未 @EnableCaching / 自调用 | 开启注解；拆 Bean（[05 篇](05-缓存实战：Spring-Cache与一致性速查.md) 1 节） |
| 缓存穿透打库 | 未缓存空值 | 空值缓存 + 布隆（[05 篇](05-缓存实战：Spring-Cache与一致性速查.md) 3 节） |
| 锁失效/误删 | 无 token / 两步释放 | SETNX+token+Lua 释放（[06 篇](06-分布式锁与Lua脚本速查.md) 3 节） |
| 事务不回滚 | Redis 事务无回滚误解 | 用 Lua 实现"全不做"语义（[07 篇](07-管道事务与批量性能速查.md) 4 节） |
| 消息丢了 | Pub/Sub 模型 | 换 Stream/MQ（[09 篇](09-消息Pub-Sub与Stream速查.md) 6 节） |
| 响应式卡死 | 事件循环被 block | 换 ReactiveRedisTemplate（[08 篇](08-响应式与ReactiveRedisTemplate速查.md) 5 节） |
| 升级后 Jedis 编译错 | UnifiedJedis API | 迁移清单（[01 篇](01-模块清单.md) 3 节） |

## 5. 测试实践

### 5.1 测试栈

| 姿势 | 用途 | 要点 |
|------|------|------|
| `@SpringBootTest` + 本地/容器 Redis | 模板/缓存/锁集成 | Testcontainers `GenericContainer("redis:8.4")` 或本地实例 |
| `@DataRedisTest`（4.x 切片） | Repository（@RedisHash）切片 | 只起 Redis 相关上下文 |
| Mock 连接工厂 | 单元测试（不连 Redis） | `MockRedisConnectionFactory`（spring-data-redis-test） |
| 断言 | 响应式用 StepVerifier（[08 篇](08-响应式与ReactiveRedisTemplate速查.md) 6 节）；同步用普通断言 | — |

```java
// Testcontainers：版本一致的 Redis 8.4
@Testcontainers
class RedisIntegrationTest {
    @Container
    static GenericContainer<?> redis = new GenericContainer<>("redis:8.4")
            .withExposedPorts(6379);

    @DynamicPropertySource
    static void props(DynamicPropertyRegistry registry) {
        registry.add("spring.data.redis.host", redis::getHost);
        registry.add("spring.data.redis.port", () -> redis.getMappedPort(6379));
    }
    // ... 测试（测试后 FLUSHDB 清理）
}
```

> ⚠️ 测试三坑：① **别连生产/共享 Redis**（数据污染、误清 FLUSHDB——尤其测试 resetCaches 场景）；② 8.x 新命令测试用 8.x 容器（老版本容器测新命令直接 unknown command）；③ 缓存/锁测试注意**过期时间**（TTL 测试用短 TTL + 等待，别用 Thread.sleep 长等——响应式用 StepVerifier 的 thenAwait）。
