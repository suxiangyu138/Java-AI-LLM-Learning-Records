## 1. Mono 与 Flux

| 类 | 语义 | 典型工厂方法 |
|----|------|-------------|
| `Mono<T>` | 0 或 1 个元素（类似 CompletableFuture + Optional） | `Mono.just`、`Mono.empty`、`Mono.error`、`Mono.defer`、`Mono.fromCallable` |
| `Flux<T>` | 0..N 个元素（类似异步 Stream） | `Flux.just`、`Flux.range`、`Flux.fromIterable`、`Flux.interval`、`Flux.generate` |

| 维度 | Mono | Flux |
|------|------|------|
| 元素数 | 0/1 | 0..N |
| 对应场景 | 单个查询/单个写操作 | 列表/流/事件序列 |
| 常见来源 | 响应式 DAO 单查、WebClient 单响应 | R2DBC 查询结果、SSE 流、Kafka 消息 |
| 转换 | `.flatMap()` | `.flatMap()` 展开嵌套流 |

```java
Mono<User> user = userRepo.findById(1L);                    // 0/1
Flux<Order> orders = orderRepo.findByUserId(1L);            // 0..N
Flux<User> users = user.flatMapMany(u -> orderRepo...);     // Mono → Flux
Mono<List<Order>> list = orders.collectList();              // Flux → Mono
```

> 🎯 **要点**：Mono/Flux 都是**惰性**的——只有 `subscribe()`（或 WebFlux 自动订阅）才执行；链上的操作符每次订阅都重放（冷流）。

## 2. 创建与变换操作符

| 分类 | 操作符 | 说明 |
|------|--------|------|
| 创建 | `just / range / fromIterable / fromCallable / fromSupplier / defer / interval / generate` | defer=延迟创建（每次订阅重新执行）；fromCallable=阻塞调用包装 |
| 变换 | `map / cast / index / timestamp` | 同步 1:1 变换 |
| 异步变换 | `flatMap / concatMap / flatMapSequential / switchMap` | **flatMap=并发展开（顺序不保）；concatMap=保序串行；switchMap=取最新** |
| 分组窗口 | `groupBy / window / buffer` | 分组/窗口化/批量缓冲 |

```java
// flatMap 并发 vs concatMap 保序（高频考点）
Flux.just("a", "b", "c")
    .flatMap(s -> asyncCall(s))       // 并发执行，完成顺序不定
    .concatMap(s -> asyncCall(s))     // 严格保序串行
    .switchMap(s -> asyncCall(s))     // 新元素到达即取消旧的（搜索框场景）
```

> 💡 记忆法：**flatMap 是"并发扩散"，concatMap 是"排队扩散"，switchMap 是"最新优先"**——并发上限用 `.flatMap(fn, concurrency)` 控制。

## 3. 组合与过滤操作符

| 分类 | 操作符 | 说明 |
|------|--------|------|
| 组合 | `zip / zipWith / merge / mergeSequential / concat / combineLatest` | zip=一一配对（等齐）；merge=并发混合（乱序）；concat=串行拼接 |
| 过滤 | `filter / take / skip / distinct / elementAt / next` | take(n)=取前 n 个；distinct=去重 |
| 转换容器 | `collectList / collectMap / toStream / blockFirst / blockLast` | 聚合；**block* 是反模式入口（见 04 卡片）** |
| 副作用 | `doOnNext / doOnSubscribe / doOnComplete / doOnError / doFinally / doOnCancel` | 观察不修改数据 |
| 条件 | `defaultIfEmpty / switchIfEmpty / any / all` | 空流兜底 |

```java
// 组合 + 兜底
Mono.zip(price1, price2, price3)
    .map(t -> t.getT1() + t.getT2() + t.getT3())
    .switchIfEmpty(Mono.just(0))        // 空 → 兜底值
    .doOnNext(total -> log.info("total={}", total));
```

## 4. 调度器与背压

| Scheduler | 线程模型 | 适用 |
|-----------|---------|------|
| `Schedulers.parallel()` | 固定 N=CPU 核的并行线程 | CPU 密集计算 |
| `Schedulers.boundedElastic()` | 有界弹性线程池（默认 10×核数上限） | **阻塞 IO 包装**（JDBC 调用等） |
| `Schedulers.single()` | 单线程 | 定时/串行需求 |
| `Schedulers.immediate()` | 当前线程 | 测试/无切换 |
| `Schedulers.fromExecutorService(...)` | 自定义 | 接入虚拟线程池等 |

```java
// 阻塞调用必须包装（boundedElastic），绝不能占 event loop
Mono.fromCallable(() -> jdbcDao.query(id))
    .subscribeOn(Schedulers.boundedElastic())   // 订阅时切线程
    .publishOn(Schedulers.parallel())           // 下游切换
```

| 背压 API | 行为 |
|---------|------|
| `limitRate(n)` | 每批请求 n 个（默认 256），减少请求往返 |
| `onBackpressureBuffer(maxSize, overflowStrategy)` | 缓冲（可配丢弃策略） |
| `onBackpressureDrop` / `onBackpressureLatest` | 丢弃最旧/保留最新 |
| `request(n)`（订阅端） | 手动控制需求 |

> ⚠️ 核心纪律：**订阅链默认跑在"发布/订阅现场线程"上**（WebFlux 中即 Netty event loop）——在链中做阻塞调用会卡死整个服务器；阻塞代码一律 `subscribeOn(boundedElastic)`。

## 5. 错误处理与重试

| 操作符 | 行为 |
|--------|------|
| `onErrorReturn` / `onErrorReturnItem` | 出错返回兜底值 |
| `onErrorResume` | 出错切换到备选发布者（可读异常后降级） |
| `onErrorMap` | 异常翻译（包装成业务异常） |
| `onErrorContinue` | 逐个元素容错继续（Flux 逐元素场景） |
| `retry(n)` | 固定次数重试（错误原样重放） |
| `retryWhen(Retry.backoff(n, Duration))` | 指数退避重试（规范 API，3.8 推荐） |
| `onErrorStop` | 错误后停止（配合 onErrorContinue） |

```java
Mono<User> safe = userRepo.findById(id)
        .onErrorResume(DataAccessException.class, e -> Mono.empty())   // 按类型降级
        .retryWhen(Retry.backoff(3, Duration.ofSeconds(1))
                .filter(e -> e instanceof TransientException));        // 只重试瞬时错误
```

> 🎯 记忆法：**Return=给值、Resume=换流、Map=换异常**；重试用 `retryWhen + Retry` 规范（退避 + 过滤器），别用裸 retry(n)。

## 6. 测试与调试 API

| API | 用途 |
|-----|------|
| `StepVerifier.create(flux)` | 标准断言：`expectNext` / `expectComplete` / `expectError` |
| `StepVerifier.withVirtualTime()` | 虚拟时间（测试 interval/超时，不真等） |
| `TestPublisher` | 手动控制发布者（背压/错误场景） |
| `Hooks.onOperatorDebug()` | 开启操作符组装栈（全局调试） |
| `reactor.core.publisher.Signal` | 信号类型（onNext/onError/onComplete） |
| `Flux.log()` | 操作符信号日志（每个元素打点） |

```java
@Test
void squaresEvenNumbers() {
    StepVerifier.create(
            Flux.range(1, 10).map(i -> i * i).filter(n -> n % 2 == 0))
            .expectNext(4, 16, 36, 64, 100)
            .verifyComplete();
}

// 虚拟时间：不等真实 5 秒
StepVerifier.withVirtualTime(() -> Flux.interval(Duration.ofSeconds(1)).take(3))
        .thenAwait(Duration.ofSeconds(3))
        .expectNext(0L, 1L, 2L)
        .verifyComplete();
```

> 💡 生产调试三板斧：**`Hooks.onOperatorDebug()`（组装栈）→ `Flux.log()`（信号明细）→ Micrometer 观测（指标）**——前两个本地排障，第三个线上监控。
