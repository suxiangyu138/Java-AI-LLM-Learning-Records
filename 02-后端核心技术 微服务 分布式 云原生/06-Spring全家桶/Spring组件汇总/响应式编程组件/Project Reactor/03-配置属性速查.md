## 1. spring.reactor.* 属性表

| 属性 | 默认值 | 说明 |
|------|--------|------|
| `spring.reactor.debug-agent.enabled` | `true` | 启动 Reactor 调试代理（组装栈追踪） |
| `spring.reactor.stacktrace-mode.enabled` | `true` | 操作符堆栈追踪模式（定位"哪条链抛的错"） |
| `spring.codec.max-in-memory-size` | `256KB` | WebFlux/WebClient 编解码缓冲上限（大数据流要调大） |
| `spring.codec.logging-request-details` | `false` | 请求细节日志（调试用，生产慎开） |
| `spring.threads.virtual.enabled` | `false` | 全局虚拟线程开关（影响 Reactor 调度器配合，见第 4 节） |

```yaml
spring:
  reactor:
    debug-agent:
      enabled: true        # 默认开；性能敏感可关（有开销）
    stacktrace-mode:
      enabled: true
  codec:
    max-in-memory-size: 4MB   # 上传/下载大对象必调
```

> 🎯 **高频三配**：`codec.max-in-memory-size`（大 payload 报 DataBufferLimitException 时）、`reactor.debug-agent.enabled`（生产降开销）、`stacktrace-mode`（定位操作符错误）。

## 2. 调试与可观测配置

| 场景 | 配置/做法 |
|------|----------|
| 定位"异常堆栈没有操作符链" | `spring.reactor.stacktrace-mode.enabled: true`（默认） |
| 生产降低调试开销 | `spring.reactor.debug-agent.enabled: false`（指标已够时） |
| 运行期编程式开启 | `Hooks.onOperatorDebug()`（代码级） |
| 指标观测 | Micrometer 自动（reactor 3.8 与 Micrometer 1.16 深度集成） |
| 追踪 | Micrometer Tracing（3.8.x 配套 1.6.x） |

> ⚠️ 取舍：调试代理与堆栈模式都有运行时开销——**开发开满、生产按需**；线上排障首选指标 + Tracing，而不是全量调试栈。

## 3. Codec 与内存配置

| 配置 | 默认 | 说明 |
|------|------|------|
| `spring.codec.max-in-memory-size` | 256KB | 超过即抛 `DataBufferLimitException`（最常见的响应式 500 之一） |
| `spring.codec.logging-request-details` | false | WebClient/服务器请求细节日志 |
| Netty 层 | — | `server.netty.max-initial-line-length` 等（服务器专用，见 WebFlux 卡片 03） |

> 💡 排查经验：**上传/下载 >256KB 报 DataBufferLimitException**——第一反应就是调 `spring.codec.max-in-memory-size`（4MB~16MB 视业务）；流式处理大文件优先考虑不落内存的 `DataBuffer` 流式 API。

## 4. 与虚拟线程的配合

| 场景 | 配置 | 说明 |
|------|------|------|
| MVC + 虚拟线程（SF 7 推荐组合） | `spring.threads.virtual.enabled: true` | 阻塞式代码低成本高并发，无需响应式 |
| WebFlux + 虚拟线程 | 默认 false（WebFlux 不需要） | 响应式链不占用线程，虚拟线程无增益 |
| 响应式内嵌阻塞调用 | 代码级 `subscribeOn(boundedElastic)` | 比全局开关更精准（见卡片 02） |
| 自定义调度器接虚拟线程 | `Schedulers.fromExecutor(Executors.newVirtualThreadPerTaskExecutor())` | 重度 IO 的响应式链路可尝试 |

> 🎯 **SF 7 时代选型定论**：**"高并发 + 阻塞式业务"选 MVC + 虚拟线程；"全栈响应式/流式"选 WebFlux**——Reactor 的调度器与虚拟线程是互补而非替代关系（详见 WebFlux 卡片 04 的对比表）。

## 5. 常见配置组合

```yaml
spring:
  reactor:
    debug-agent:
      enabled: false          # 生产：省开销
  codec:
    max-in-memory-size: 8MB   # 大 payload
  threads:
    virtual:
      enabled: true           # 若混合阻塞逻辑（配合 boundedElastic 使用）
```

| 生产组合 | 说明 |
|---------|------|
| stacktrace-mode 开 + debug-agent 关 | 保排障能力、降开销 |
| max-in-memory-size 与业务 payload 匹配 | 防 DataBufferLimitException 与内存溢出两头 |
| 指标 + Tracing（BOM 内置） | 响应式链路可观测 |

> 🎯 配置心智模型：**调试三件套（debug-agent/stacktrace-mode）开发期全开；内存上限按业务 payload 设；虚拟线程与响应式按"阻塞/非阻塞"选型**——Reactor 的配置很少，贵的都是写错的代码。
