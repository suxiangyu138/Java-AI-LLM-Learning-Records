## 1. 集成地图

```text
          业务层（Mono/Flux 操作符链）
                 │
   ┌─────────────┼──────────────────────┐
   │             │                      │
 WebFlux       R2DBC/RSocket          reactor-kafka
 （HTTP/SSE/   （响应式数据库）        （Kafka 消费/生产）
  WebSocket）
   │             │                      │
   └─────────────┼──────────────────────┘
                 ▼
        reactor-netty（传输层）
           │（默认 / 非阻塞 / 背压）
           ▼
        Netty event loop（调度现场）
           │ 阻塞调用？→ subscribeOn(boundedElastic)
           ▼
   Micrometer 观测 + Tracing + StepVerifier 测试
```

## 2. 与生态的集成

| 集成对象 | 方式 | 要点 |
|---------|------|------|
| Spring WebFlux | Controller 返回 Mono/Flux，框架自动订阅 | **不要在 Controller 里 subscribe/block** |
| R2DBC | 响应式 DAO 返回 Mono/Flux | 连接池由 reactor-pool 实现 |
| RSocket | 响应式通信协议（req-stream 模型） | 天然背压语义 |
| reactor-kafka | KafkaReceiver/KafkaSender | 响应式消费 + 位点管理 |
| Micrometer / Tracing | 3.8.x 深度集成 | 指标 + 分布式追踪开箱即用 |
| 虚拟线程 | Schedulers.fromExecutor(virtual) | IO 重链路可混合 |
| WebClient | 响应式 HTTP 客户端 | 非阻塞调用外部服务 |
| 事件流 | Flux.interval / 处理器 | 定时/事件驱动处理 |

> 🎯 集成铁律：**响应式链内禁止阻塞调用**（block()、Thread.sleep、同步 JDBC）——要么包 `subscribeOn(boundedElastic)`，要么换响应式驱动（R2DBC）；违反这条是响应式项目崩溃的头号原因。

## 3. 高频问题速查

| 问题 | 根因 | 处理 |
|------|------|------|
| 链不执行 | 没订阅（冷流惰性） | WebFlux 框架自动订阅；纯代码需 subscribe() |
| 卡死无响应 | 阻塞调用占住 event loop | 阻塞代码包 subscribeOn(boundedElastic) |
| `block()` 抛 IllegalStateException | 在 event loop（非阻塞线程）上 block | 检查控制器/过滤器；换成响应式组合 |
| `DataBufferLimitException` | 超过 codec 内存上限 | 调 `spring.codec.max-in-memory-size` |
| `OverflowException` / 背压错误 | 下游慢且无缓冲策略 | onBackpressureBuffer/Drop/Latest |
| 上下文丢失 | 跨线程未传递 Context | 用 `deferContextual` + 自动传播（Context 不随线程） |
| flatMap 顺序乱 | 并发展开不保序 | 需要保序用 concatMap / flatMapSequential |
| retry(n) 立刻重试风暴 | 无退避 | retryWhen + Retry.backoff |
| 堆栈没有操作符链 | 调试代理未开 | `Hooks.onOperatorDebug()` / stacktrace-mode |
| 测试真实等待超时 | 用 interval 等真实时间 | StepVerifier.withVirtualTime |
| 内存爆炸 | 无限缓冲 + 大流 | 背压策略 + limitRate + 窗口化 |

## 4. 排障流程

```text
① 执行层：链真的订阅了吗？（WebFlux 自动 / 手动 subscribe 缺失 = 静默不执行）
② 线程层：在哪个线程跑？（event loop 上做阻塞 = 卡死；日志看线程名 Reactor-http-*）
③ 背压层：下游跟上吗？（OverflowException / 队列堆积 → 缓冲策略与并发度）
④ 数据层：数据对了吗？（Flux.log() 看信号明细 / StepVerifier 复现断言）
⑤ 观测层：线上怎么查？（Micrometer 指标 + Tracing 链路，而非调试栈）
```

> 💡 排障三利器：**线程名（Reactor-http-* 即 event loop）、Flux.log()（信号明细）、StepVerifier（本地复现）**——响应式问题 80% 是"线程错了"或"没订阅"。

> 🎯 **核心要点**：集成地图一句话 = "Reactor 是响应式生态的地基——WebFlux/R2DBC/RSocket/Kafka 全建在 Mono/Flux 之上"；排障先查"执行没执行、在哪个线程、背压跟不跟"。深挖见 [官方参考文档](https://projectreactor.io/docs/core/release/reference/)。
