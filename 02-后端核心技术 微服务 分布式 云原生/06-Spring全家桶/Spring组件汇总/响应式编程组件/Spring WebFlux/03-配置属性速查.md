## 1. spring.webflux.* 属性表

| 属性 | 默认值 | 说明 |
|------|--------|------|
| `spring.webflux.base-path` | — | 全局基础路径前缀（如 `/api`） |
| `spring.webflux.static-path-pattern` | `/**` | 静态资源映射 |
| `spring.webflux.multipart.max-file-size` | `1MB` | 单文件上传上限 |
| `spring.webflux.multipart.max-request-size` | `10MB` | 整请求上限 |
| `spring.webflux.format.date` / `date-time` / `time` | — | 响应式 JSON 日期格式 |
| `spring.codec.max-in-memory-size` | `256KB` | 编解码缓冲上限（全局） |
| `spring.codec.logging-request-details` | `false` | 请求细节日志 |

```yaml
spring:
  webflux:
    base-path: /api
    multipart:
      max-file-size: 5MB
      max-request-size: 20MB
  codec:
    max-in-memory-size: 4MB
```

> 🎯 **高频三配**：`base-path`（统一前缀）、`codec.max-in-memory-size`（大 payload）、`multipart.*`（上传）。

## 2. Codec 与请求体配置

| 场景 | 配置 |
|------|------|
| 大 JSON 请求/响应 | `spring.codec.max-in-memory-size: 4MB`（默认 256KB，超限抛 DataBufferLimitException） |
| 请求体流式处理 | 不设上限 + `Mono<DataBuffer>` 流式读（避免整体入内存） |
| 调试请求细节 | `spring.codec.logging-request-details: true`（生产慎开） |
| WebClient 自定义 | 编程式 `.exchangeStrategies(...)`（codec 定制） |

> ⚠️ 内存守恒原则：**响应式不是"无限内存"**——`max-in-memory-size` 保护服务器；大文件/大流一律走流式（FilePart / DataBuffer），不要 collectList 到大集合。

## 3. Netty 服务器配置

| 属性 | 默认值 | 说明 |
|------|--------|------|
| `server.port` | 8080 | 端口 |
| `server.netty.connection-timeout` | — | 连接超时 |
| `server.netty.max-initial-line-length` | 4096 | HTTP 首行上限 |
| `server.netty.max-http-header-size` | 8KB | 请求头上限 |
| `server.netty.keep-alive-timeout` | — | 保活超时 |
| `server.netty.idle-timeout` | — | 空闲超时（长连接重要） |
| `server.http2.enabled` | false | HTTP/2 开关 |
| `spring.threads.virtual.enabled` | false | 虚拟线程（对 WebFlux 通常无增益） |

> 💡 Netty 属性以 `server.netty.*` 为前缀（不是 `spring.reactor.netty.*`）——写 yaml 前先确认前缀，两者都存在但作用不同（后者为编程式 HttpClient 配置）。

## 4. 多部分上传配置

| 属性 | 默认 | 说明 |
|------|------|------|
| `spring.webflux.multipart.max-file-size` | 1MB | 单文件 |
| `spring.webflux.multipart.max-request-size` | 10MB | 整请求 |
| `spring.webflux.multipart.max-in-memory-size` | 0 | 内存缓冲阈值（超限落盘） |
| `spring.webflux.multipart.resolve-lazily` | false | 延迟解析（需要时才读） |

> ⚠️ 注意：WebFlux 的多部分配置在 `spring.webflux.multipart.*`（**不是** servlet 的 `spring.servlet.multipart.*`——那是 MVC 的）。

## 5. 常见配置组合

```yaml
spring:
  webflux:
    base-path: /api
    multipart:
      max-file-size: 5MB
      max-request-size: 20MB
  codec:
    max-in-memory-size: 4MB
server:
  port: 8080
  netty:
    idle-timeout: 60s
  http2:
    enabled: true
```

| 生产组合 | 说明 |
|---------|------|
| base-path + 网关路由 | 微服务统一前缀 |
| max-in-memory-size 匹配业务 payload | 防 256KB 误伤 + 防内存溢出 |
| http2 + idle-timeout | 长连接性能与资源释放 |
| 流式 API（SSE/大文件） | 不调大内存，走流式处理 |

> 🎯 配置心智模型：**yaml 管"服务器与协议层"（端口/Netty/HTTP2）、"编解码层"（内存上限）、"业务层"（路径/上传）**——三层各司其职；响应式项目的性能问题 80% 在代码（线程/背压）而非配置。
