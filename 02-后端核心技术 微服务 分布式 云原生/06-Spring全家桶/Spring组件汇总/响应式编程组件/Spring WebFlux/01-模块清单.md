## 1. 模块总览

```text
spring-webflux         ← WebFlux 框架本体（SF 内置：注解/函数式/WebClient）
spring-web             ← 共享 HTTP 抽象（与 MVC 共用：HttpMessageConverter 等）
reactor-netty          ← Netty 传输（默认服务器 + WebClient 底层）
spring-webmvc          ← ⚠️ 与 WebFlux 二选一（同一应用别同时引 starter-web）
spring-boot-starter-webflux ← 一站式入口（内嵌 Netty）
```

> 🎯 **要点**：**WebFlux 与 WebMVC 是并列的 Web 栈**——同一应用只选其一（同时引两个 starter 会启动报错/行为混乱）；Spring Cloud Gateway 等框架内部就是 WebFlux 应用。

### 1.1 依赖传导链速览

```text
spring-boot-starter-webflux
  ├── spring-webflux        ← 框架本体（SF 7.0.x）
  ├── spring-web            ← HTTP 抽象（MVC 同款）
  ├── reactor-core          ← Mono/Flux
  ├── reactor-netty         ← Netty 服务器 + HttpClient（默认）
  └── spring-boot-starter（传递）
spring-boot-starter-data-r2dbc（按需）
  ├── spring-data-r2dbc
  └── r2dbc-* 驱动（r2dbc-postgresql 等）
```

> 💡 依赖缺失的第一直觉：**`WebClient`/`RouterFunction` 找不到 = 缺 spring-webflux（starter 已带）；WebFlux 启动无 Netty = 缺 reactor-netty；想要响应式数据库 = 加 data-r2dbc**。

### 1.2 模块一句话全景

| 模块 | 一句话 |
|------|--------|
| spring-webflux | 注解式 + 函数式响应式 Web、WebClient、WebFilter/WebSession |
| spring-web | 与 MVC 共享的 HTTP/编解码抽象 |
| reactor-netty | Netty 传输（HTTP/HTTP2/TCP/UDP 非阻塞） |
| spring-webmvc（对照） | 阻塞式 Web 栈（**二选一**） |
| spring-boot-starter-webflux | 自动配置：Netty 服务器、WebClient、codec 等 |

> 🎯 心智模型：**webflux 是"发动机"，web 是"底盘"（与 MVC 共用），reactor-netty 是"车轮"**——starter-webflux 一次打包。

## 2. 核心模块

| Artifact | 职责 | 关键类（包） |
|---------|------|-------------|
| `spring-webflux` | 响应式 Web 框架 | `RouterFunction`/`HandlerFunction`、`WebClient`、`WebFilter`、`WebSession`、`ServerWebExchange`（org.springframework.web.reactive / web.reactive.function） |
| `spring-web` | 共享抽象 | `HttpMessageConverter`、`MediaType`、`UriComponentsBuilder`（org.springframework.http） |
| `reactor-netty` | 传输层 | `HttpServer`/`HttpClient`（reactor.netty.http） |

> ⚠️ **包名对照**：WebFlux 的类在 `org.springframework.web.reactive`，MVC 在 `org.springframework.web.servlet`——报错堆栈先看包名即可判断用的是哪个栈。

### 2.1 spring-webflux 内部结构

```text
org.springframework.web.reactive
├── result                # 处理器结果处理（@RestController 返回值 → 响应）
├── function              # 函数式编程模型（RouterFunction/HandlerFunction/RequestPredicates）
├── method.annotation     # 注解式（RequestMappingHandlerMapping 响应式版）
├── client                # WebClient
├── server                # 服务器抽象（WebHttpHandlerBuilder、ExchangeStrategies）
├── context               # WebSession、WebFilter、WebExceptionHandler
├── socket                # WebSocket（WebSocketHandler、HandshakeInfo）
└── support               # 通用支持（响应式适配器）
org.springframework.web.reactive.function
├── client                # WebClient 实现
└── server                # RouterFunctions、ServerRequest/ServerResponse
```

## 3. 传输与数据访问

| 类别 | 依赖 | 说明 |
|------|------|------|
| 服务器 | reactor-netty（默认） | 也可配 Tomcat/Undertow/Jetty 的非阻塞模式（少见） |
| 数据访问 | spring-boot-starter-data-r2dbc | 响应式关系库（PostgreSQL/MySQL/H2 驱动） |
| 数据访问 | spring-boot-starter-data-mongodb-reactive | 响应式 MongoDB |
| 缓存/消息 | spring-boot-starter-data-redis-reactive、RSocket 等 | 全响应式链路组件 |

> 💡 全响应式链路原则：**WebFlux + R2DBC/响应式 Mongo + WebClient + 响应式 Redis**——任何一环换成阻塞式（JDBC、RestTemplate），收益就没了。

## 4. 依赖什么场景引入什么

| 场景 | 需要的依赖 |
|------|-----------|
| 响应式 Web 应用 | `spring-boot-starter-webflux`（**不要同时加 starter-web**） |
| 响应式数据库 | + `spring-boot-starter-data-r2dbc` + 驱动 |
| 响应式测试 | + `spring-boot-starter-test`（含 WebTestClient 支持） |
| 响应式网关 | Spring Cloud Gateway（内部即 WebFlux） |
| 客户端调用 | WebClient（starter 已带） |

```xml
<!-- 响应式 Web 标准组合 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-webflux</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-r2dbc</artifactId>
</dependency>
<dependency>
    <groupId>org.postgresql</groupId>
    <artifactId>r2dbc-postgresql</artifactId>
    <scope>runtime</scope>
</dependency>
```

### 4.1 冲突与版本

| 报错现象 | 根因 | 处理 |
|---------|------|------|
| 两个 Web 栈同时存在 | 同时引了 starter-web 与 starter-webflux | 二选一（Boot 启动也会警告） |
| `NoSuchMethodError`（webflux 类） | SF 版本与 Boot 不配套 | Boot BOM 锁定 |
| WebFlux 起不来 | 缺传输实现 | 加 reactor-netty（starter 已带） |

> 🎯 经验法则：**响应式项目从第一行依赖就"全响应式"**——starter-webflux 与 starter-web 严格二选一；数据库用 R2DBC 而非 JDBC，客户端用 WebClient 而非 RestTemplate。

## 5. Starter 对照

| Starter | 包含 | 适用 |
|---------|------|------|
| `spring-boot-starter-webflux` | webflux + web + reactor-netty + 自动配置 | **响应式 Web 唯一入口** |
| `spring-boot-starter-web` | webmvc（阻塞） | MVC + 虚拟线程场景（对照） |
| `spring-boot-starter-data-r2dbc` | 响应式数据访问 | 端到端非阻塞 |

> 🎯 一句话选型：**全响应式 → starter-webflux（绝不加 starter-web）+ data-r2dbc；常规业务 → starter-web + 虚拟线程**——2026 年的默认答案越来越偏向后者（见 00 卡片版本现状）。
