## 1. 响应式 Controller

| 类/注解 | 职责 | 说明 |
|---------|------|------|
| `@RestController` / `@GetMapping` 等 | 注解式风格（与 MVC 相同） | 区别只在返回值 |
| `Mono<T>` 返回值 | 单个响应 | `Mono<ResponseEntity<T>>` 控状态码 |
| `Flux<T>` 返回值 | 流式响应 | 需 `produces = text/event-stream` 或 `application/json`（自动分帧） |
| `ServerWebExchange` | 请求/响应访问 | 与 MVC 的 HttpServletRequest 对应 |
| `@RequestBody` + `Mono<T>` 参数 | 响应式请求体 | 支持 `@Valid`（WebExchangeBindException） |
| `@RequestPart` | 文件上传（响应式） | FilePart 流式 |

```java
@RestController
class OrderController {
    // 单个响应 + 状态码
    @GetMapping("/orders/{id}")
    Mono<ResponseEntity<Order>> find(@PathVariable Long id) {
        return repo.findById(id)
                .map(ResponseEntity::ok)
                .defaultIfEmpty(ResponseEntity.notFound().build());
    }

    // 流式响应（JSON 分帧 / SSE）
    @GetMapping(value = "/orders", produces = MediaType.APPLICATION_NDJSON_VALUE)
    Flux<Order> list() {
        return repo.findAll();
    }

    // 响应式请求体 + 校验
    @PostMapping("/orders")
    Mono<Order> create(@Valid @RequestBody Mono<CreateOrderRequest> req) {
        return req.flatMap(r -> repo.save(toOrder(r)));
    }
}
```

> 🎯 **要点**：WebFlux 与 MVC 的 Controller 代码几乎相同——**唯一的大差异是返回值类型（Mono/Flux vs 对象）与"不要 block"**。

## 2. 函数式路由 RouterFunction

| API | 说明 |
|-----|------|
| `RouterFunctions.route(...)` | 构建路由：`GET("/orders/{id}")` + 处理器引用 |
| `RequestPredicates.GET/POST/...` | 路由谓词（路径/内容类型/查询参数） |
| `ServerRequest` / `ServerResponse` | 请求/响应（响应式） |
| `HandlerFunction` | 处理器函数：`req -> Mono<ServerResponse>` |
| `RouterFunctions.toHttpHandler(...)` | 适配到服务器 |
| Kotlin `coRouter { }` | 协程风格 DSL（SF 7 增强） |

```java
@Configuration(proxyBeanMethods = false)
class OrderRoutes {
    @Bean
    RouterFunction<ServerResponse> orderRoutes(OrderHandler handler) {
        return RouterFunctions.route()
                .GET("/orders/{id}", handler::find)
                .GET("/orders/stream", accept(TEXT_EVENT_STREAM), handler::stream)
                .POST("/orders", handler::create)
                .build();
    }
}

// 处理器
class OrderHandler {
    Mono<ServerResponse> find(ServerRequest req) {
        return orderRepo.findById(Long.valueOf(req.pathVariable("id")))
                .flatMap(order -> ServerResponse.ok().bodyValue(order))
                .switchIfEmpty(ServerResponse.notFound().build());
    }
}
```

> 💡 选型建议：**简单 CRUD 用注解式；路由条件复杂/API 网关式用函数式**——两者可共存于一个应用。

## 3. WebClient

| API | 说明 |
|-----|------|
| `WebClient.create(baseUrl)` / `.builder()` | 构建（可配过滤器、codec、超时） |
| `.get()/.post()/.put()/.delete()` | 方法 |
| `.uri(...)` / `.body(...)` / `.retrieve()` / `.exchangeToMono()` | 请求与响应 |
| `.exchangeToMono` 进阶 | 手动处理状态码/头（比 retrieve 灵活） |
| `RetrySpec` / 超时 | `.retryWhen(...)` + `.timeout(...)` |

```java
// 非阻塞调用外部服务（响应式链内可用）
WebClient client = WebClient.create("http://user-service");

Mono<User> user = client.get()
        .uri("/users/{id}", id)
        .accept(APPLICATION_JSON)
        .retrieve()
        .bodyToMono(User.class)
        .timeout(Duration.ofSeconds(3))
        .retryWhen(Retry.backoff(2, Duration.ofMillis(500)));

// 并发扇出（网关典型场景）
Flux.merge(serviceA.call(), serviceB.call(), serviceC.call());
```

> ⚠️ **不要用 RestTemplate 混进响应式链**（阻塞）；WebClient 是唯一正解。SF 7 的 `ReactiveAdapterRegistry` 支持在响应式链中调用命令式服务（适配方式，仍有边界）。

## 4. SSE 与 WebSocket

| 场景 | 实现 |
|------|------|
| SSE 服务端推送 | 返回 `Flux<ServerSentEvent<T>>`（或 `produces=TEXT_EVENT_STREAM`） |
| WebSocket | 实现 `WebSocketHandler`：`handle(WebSocketSession)` 返回 `Mono<Void>` |
| WebSocket 客户端 | `ReactorNettyWebSocketClient` 等 |
| 心跳/重连 | `ServerSentEvent.builder().comment(...)` / 客户端重连逻辑 |

```java
// WebSocket handler（响应式，SF 7 仅保留响应式 handler）
class EchoHandler implements WebSocketHandler {
    @Override
    public Mono<Void> handle(WebSocketSession session) {
        return session.send(session.receive()
                .map(msg -> session.textMessage("echo: " + msg.getPayloadAsText())));
    }
}
```

> 💡 长连接场景是 WebFlux 的保留地：**SSE 的背压 + Netty 少量线程扛大量连接**——虚拟线程替代不了流式语义。

## 5. 横切与异常处理

| 能力 | API | 说明 |
|------|-----|------|
| 过滤器 | `WebFilter` | 认证/日志/限流（响应式链路，需返回 Mono<Void>） |
| 会话 | `WebSession` | 会话数据（响应式） |
| 异常 | `@ControllerAdvice` + `@ExceptionHandler` | 与 MVC 同款，返回值可为 Mono |
| 内置异常 | `ResponseStatusException` | 链内直接抛（404/400 等） |
| 校验异常 | `WebExchangeBindException` | @Valid 失败（对应 MVC 的 MethodArgumentNotValidException） |

```java
// 统一异常处理（响应式）
@RestControllerAdvice
class GlobalErrorHandler {
    @ExceptionHandler(WebExchangeBindException.class)
    Mono<ResponseEntity<Map<String, String>>> onBind(WebExchangeBindException ex) {
        Map<String, String> errors = ex.getFieldErrors().stream()
                .collect(toMap(FieldError::getField, FieldError::getDefaultMessage));
        return Mono.just(ResponseEntity.badRequest().body(errors));
    }
}
```

> 🎯 要点：**异常从响应式链内抛出 → 冒泡到 WebExceptionHandler（@ControllerAdvice）**——错误处理时机与 MVC 相同，只是链路是异步的。

## 6. 测试 API

| API | 用途 |
|-----|------|
| `WebTestClient` | 端到端测试（bindToServer / bindToRouterFunction / bindToController） |
| `@AutoConfigureWebTestClient` | Boot 测试自动装配 |
| `WebTestClient.exchange()/expectStatus()/expectBody()` | 断言链 |
| `StepVerifier`（reactor-test） | 直接测返回的 Mono/Flux |

```java
@SpringBootTest
@AutoConfigureWebTestClient
class OrderControllerTest {
    @Autowired WebTestClient client;

    @Test
    void findsOrder() {
        client.get().uri("/orders/1")
                .exchange()
                .expectStatus().isOk()
                .expectBody()
                .jsonPath("$.id").isEqualTo(1);
    }
}
```

> 💡 测试要点：**WebTestClient 是"响应式 MockMvc"**——测 Controller 用 bindToController、测路由用 bindToRouterFunction、集成用 bindToServer。
