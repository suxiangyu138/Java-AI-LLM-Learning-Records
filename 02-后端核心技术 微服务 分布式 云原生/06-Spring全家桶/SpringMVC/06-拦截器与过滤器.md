# 06 拦截器与过滤器

## 1. Filter vs HandlerInterceptor：本质区别

```text
请求路径：
  Servlet 容器 → Filter 链 → DispatcherServlet → HandlerMapping
                                                  → HandlerInterceptor.preHandle
                                                  → 处理器方法
                                                  → HandlerInterceptor.postHandle
                                                  → 消息转换写响应
                                                  → HandlerInterceptor.afterCompletion
```

| 维度 | Filter（过滤器） | HandlerInterceptor（拦截器） |
|------|:---:|:---:|
| 所属层 | Servlet 容器（Servlet API） | SpringMVC 框架 |
| 执行时机 | DispatcherServlet **之前** | DispatcherServlet 之后、处理器**前后** |
| 依赖 Spring | 无（但可注入 Bean） | 有（Spring 容器管理） |
| 能拿到 | request/response | request/response + **Handler 方法信息** |
| 典型用途 | 编码、压缩、安全（Security 过滤器）、日志 | 登录校验、权限、审计、横切响应 |
| 数量与顺序 | 按注册顺序（@Order） | 按注册顺序 |

> 🎯 **核心要点**：Filter 在"请求进入 MVC 之前"（最早、最底层），拦截器在"找到处理器之后"（能知道**要调哪个方法**）——需要方法信息的逻辑（鉴权要拿 @RequireAuth、审计要拿方法名）必须用拦截器。

## 2. HandlerInterceptor 的三个回调时机

```java
public interface HandlerInterceptor {

    // ① 处理器执行前（返回 false 则中断请求）
    default boolean preHandle(HttpServletRequest request, HttpServletResponse response,
                              Object handler) throws Exception { return true; }

    // ② 处理器执行后、视图渲染前（无 @ResponseBody 时才有意义）
    default void postHandle(HttpServletRequest request, HttpServletResponse response,
                            Object handler, ModelAndView modelAndView) throws Exception { }

    // ③ 请求处理完成（无论成败/异常都会执行）
    default void afterCompletion(HttpServletRequest request, HttpServletResponse response,
                                 Object handler, Exception ex) throws Exception { }
}
```

| 回调 | 时机 | 典型用途 |
|------|------|---------|
| `preHandle` | 方法调用前 | 登录/权限校验（false 中断）、计时开始 |
| `postHandle` | 方法返回后、写响应前 | 修改 ModelAndView（服务端渲染场景） |
| `afterCompletion` | 响应完成后 | 审计、清理资源、计时结束（**无论异常都执行**） |

> ⚠️ **注意**：异常时 `postHandle` 不执行，但 `afterCompletion` 一定执行（ex 参数携带异常）——**清理与审计放 afterCompletion**。

## 3. 拦截器注册与顺序

```java
@Configuration
public class WebConfig implements WebMvcConfigurer {

    @Resource
    private AuthInterceptor authInterceptor;
    @Resource
    private AuditInterceptor auditInterceptor;

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(auditInterceptor)        // ① 先注册
                .addPathPatterns("/api/**");             // 匹配路径
        registry.addInterceptor(authInterceptor)         // ② 后注册
                .addPathPatterns("/api/**")
                .excludePathPatterns("/api/auth/login",  // 排除：公开接口
                                     "/api/auth/register",
                                     "/api/public/**",
                                     "/error");
    }
}
```

| 方法 | 语义 |
|------|------|
| `addInterceptor` | 注册（**按注册顺序执行**：先注册先 preHandle） |
| `addPathPatterns` | 匹配路径（PathPattern 语法） |
| `excludePathPatterns` | 排除路径（白名单） |

```text
多个拦截器的执行顺序：
  preHandle：注册顺序（A → B）
  处理器方法
  postHandle：逆序（B → A）
  afterCompletion：逆序（B → A）
  （类似栈：先进后出）
```

> 💡 **记忆**：preHandle 正序进入、postHandle/afterCompletion 逆序退出——与过滤器的洋葱模型一致。

## 4. 实战：登录鉴权拦截器

```java
@Component
public class AuthInterceptor implements HandlerInterceptor {

    @Resource
    private TokenService tokenService;       // 注入业务 Bean

    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response,
                             Object handler) throws Exception {
        // 非处理器方法（静态资源等）直接放行
        if (!(handler instanceof HandlerMethod handlerMethod)) {
            return true;
        }

        // 提取令牌
        String token = request.getHeader("Authorization");
        if (token == null || !token.startsWith("Bearer ")) {
            return reject(response, 401, "未登录");
        }

        // 校验并解析用户
        LoginUser user = tokenService.parse(token);
        if (user == null) {
            return reject(response, 401, "令牌无效或过期");
        }

        // 注入当前用户（配合参数解析器取用）
        request.setAttribute("currentUser", user);
        return true;
    }

    private boolean reject(HttpServletResponse response, int status, String msg) throws IOException {
        response.setStatus(status);
        response.setContentType("application/json;charset=UTF-8");
        response.getWriter().write("{\"code\":" + status + ",\"message\":\"" + msg + "\"}");
        return false;      // 中断请求
    }
}
```

| 设计点 | 说明 |
|--------|------|
| 白名单外置 | excludePathPatterns 管公开接口（登录/注册/健康检查） |
| HandlerMethod 判断 | 只拦控制器方法 |
| 用户上下文传递 | request attribute（同一请求内有效） |
| 中断语义 | preHandle 返回 false + 直接写响应 |

> 💡 **进阶**：`@AuthenticationPrincipal` 参数注入是 Spring Security 生态的标准做法；纯 SpringMVC 项目可用"自定义注解 + HandlerMethodArgumentResolver"（01 篇扩展点）替代 request attribute。

## 5. 实战：响应头与审计拦截器

```java
// 审计拦截器：记录每个 API 的调用（afterCompletion 保证无论成败都记）
@Component
public class AuditInterceptor implements HandlerInterceptor {

    private final ThreadLocal<Long> startTime = new ThreadLocal<>();

    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response,
                             Object handler) {
        startTime.set(System.currentTimeMillis());
        return true;
    }

    @Override
    public void afterCompletion(HttpServletRequest request, HttpServletResponse response,
                                Object handler, Exception ex) {
        Long start = startTime.get();
        if (start == null) return;
        long cost = System.currentTimeMillis() - start;
        String user = String.valueOf(request.getAttribute("currentUser"));
        String handlerName = handler instanceof HandlerMethod hm
                ? hm.getMethod().getName() : handler.toString();

        log.info("audit: user={} method={} path={} status={} cost={}ms ex={}",
                user, request.getMethod(), request.getRequestURI(),
                response.getStatus(), cost, ex == null ? "-" : ex.getClass().getSimpleName());
        startTime.remove();      // 线程复用场景必须清理（虚拟线程时代尤其）
    }
}

// 响应头拦截器：统一加安全头 / 请求ID
@Component
public class ResponseHeaderInterceptor implements HandlerInterceptor {
    @Override
    public void postHandle(HttpServletRequest request, HttpServletResponse response,
                           Object handler, ModelAndView modelAndView) {
        response.setHeader("X-Content-Type-Options", "nosniff");
        response.setHeader("X-Request-Id", request.getAttribute("requestId").toString());
    }
}
```

> ⚠️ **ThreadLocal 清理红线**：拦截器用了 ThreadLocal（计时、上下文），**afterCompletion 必须 remove()**——线程复用/虚拟线程 carrier 复用时残留会串到下一个请求。

## 6. Filter 的注册与使用

```java
// 方式一：@Component 注册（Boot 自动收集）
@Component
@Order(1)                                     // 执行顺序（小在前）
public class RequestLogFilter implements Filter {

    @Override
    public void doFilter(ServletRequest request, ServletResponse response, FilterChain chain)
            throws IOException, ServletException {
        long start = System.currentTimeMillis();
        try {
            chain.doFilter(request, response);   // 放行到下一层（拦截器/控制器）
        } finally {
            log.info("filter: {} cost={}ms", ((HttpServletRequest) request).getRequestURI(),
                    System.currentTimeMillis() - start);
        }
    }
}

// 方式二：FilterRegistrationBean（精细控制 URL 与顺序）
@Bean
public FilterRegistrationBean<MyFilter> myFilter() {
    FilterRegistrationBean<MyFilter> reg = new FilterRegistrationBean<>(new MyFilter());
    reg.addUrlPatterns("/api/*");
    reg.setOrder(10);
    return reg;
}
```

| Filter 场景 | 说明 |
|------------|------|
| 请求编码/日志 | 最底层、最先 |
| 压缩/缓存 | Servlet 层处理 |
| Spring Security | 整条安全过滤器链就在这一层 |
| 网关语义 | 跨应用统一处理 |

> 💡 **顺序敏感**：Security 过滤器链在 Boot 中的 order 默认 `-100` 级别，**自定义 Filter 若需在安全链之后（如拿登录用户）注意顺序**——安全相关需求优先考虑 Security 体系的过滤器/拦截器。

## 7. 选型决策与常见坑

**选型决策：**

```text
需要"方法级信息"（注解/方法名）？ → HandlerInterceptor
需要在 MVC 之前做全局处理（编码/安全）？ → Filter
两者能互换的场景 → 优先拦截器（框架内、可注入、有方法信息）
```

| 常见坑 | 现象 | 处理 |
|--------|------|------|
| preHandle 返回 false 却继续执行 | 未正确返回 false | 返回 false + 已写响应 |
| 拦截器内抛异常 | 跳过 postHandle | afterCompletion 兜底清理 |
| 异步请求拦截器提前结束 | 异步场景 preHandle 返回后线程就释放 | 7.x 支持异步拦截器（AsyncHandlerInterceptor） |
| 静态资源被拦截 | 白名单漏配 | excludePathPatterns("/static/**", "/favicon.ico") |
| 拦截器拿不到 Handler 信息 | instanceof 判断 | 非 HandlerMethod 放行 |
| ThreadLocal 不清理 | 数据串请求 | afterCompletion remove() |

> 🎯 **核心要点**：Filter 管"进入 MVC 之前"（最外层、容器级），拦截器管"处理器前后"（有方法信息、框架内）。拦截器三回调：preHandle 拦截、postHandle 视图、afterCompletion 兜底清理——**登录鉴权 + 审计 + 统一响应头是三大经典用例**。ThreadLocal 清理与异步场景是两个最容易踩的坑。
