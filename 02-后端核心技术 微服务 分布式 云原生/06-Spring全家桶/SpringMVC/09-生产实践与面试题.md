## 1. REST API 设计规范

**黄金十二条：**

| # | 规范 | 依据模块 |
|:---:|------|:---:|
| 1 | 资源名词 + HTTP 方法语义（POST 创建、PUT 全量、PATCH 部分） | 02 |
| 2 | 类级前缀 + 组合注解（@GetMapping 等） | 02 |
| 3 | 显式 `produces=JSON`（内容协商行为确定） | 02/04 |
| 4 | 查询参数 ≥4 个封装 Query 对象 | 03 |
| 5 | 请求体必带 @Valid + DTO 分组校验 | 03 |
| 6 | 错误响应统一 ProblemDetail（RFC 7807）+ 业务码 | 05 |
| 7 | 全局异常五件套：校验/解析/业务/安全/未知 | 05 |
| 8 | 登录鉴权走拦截器 + 白名单管理 | 06 |
| 9 | 文件名清洗 + 上传三层限制 | 08 |
| 10 | 响应统一包装：Result<T>（code/msg/data）或直接资源 | 05/04 |
| 11 | 接口版本化（URL 或头） | 02 |
| 12 | 敏感字段 @JsonView 脱敏分层输出 | 04 |

**统一响应结构（二选一）：**

```json
// 方案 A：ProblemDetail 标准（异常统一，推荐）
{"type":"about:blank","title":"User Not Found","status":404,"detail":"...","code":40401}

// 方案 B：业务包装（成功统一）
{"code":0,"message":"ok","data":{...}}
{"code":40001,"message":"参数校验失败","errors":{...}}
```

> 🎯 **建议**：成功用 Result 包装（前端友好）、异常用 ProblemDetail——两者都保持"code 业务码 + message 人类可读 + data/errors 明细"的结构一致。

## 2. 性能调优要点

| 层面 | 手段 | 说明 |
|------|------|------|
| 线程模型 | Boot 4 虚拟线程默认开启 | I/O 密集吞吐 +39%（实测） |
| 序列化 | 精简字段（@JsonIgnore/视图）、null 过滤 | 大响应体是网络与 GC 双负担 |
| 参数绑定 | 避免巨型请求体、合理校验开销 | 校验放服务层一次完成 |
| 静态资源 | CDN + 强缓存（指纹资源 1 年） | 08 篇缓存策略 |
| 流式 | 大导出用 StreamingResponseBody | 防内存峰值 |
| 异步 | SSE 推送连接上限 + 背压 | 07 篇 |
| 监控 | 接口耗时/错误率/吞吐指标 | Actuator + Micrometer |

**慢接口排查链：**

```text
接口慢 → 网关/代理层耗时对比 → 应用内耗时（Filter 计时）
  → 定位：DB 慢查询 / 外部调用 / 序列化大对象 / GC
  → 工具：Arthas trace / 慢 SQL 日志 / 调用链
```

## 3. Boot 3→4 迁移清单

| 变化 | 影响 | 处理 |
|------|------|------|
| **Jackson 3**（tools.jackson） | 序列化器类名、ObjectMapper→JsonMapper | 更新 import 与 Bean 配置（04 篇） |
| **响应默认值变化** | 字段字母序、斜杠转义、日期 ISO-8601 | 接口回归 + JsonMapperBuilderCustomizer 定制 |
| 虚拟线程默认 | ThreadLocal 泄漏、pinning | 检查拦截器/Filter 的 ThreadLocal 清理 |
| ProblemDetail 行为 | 7.x 与安全体系联动变化 | 验证错误响应结构 |
| `PathPatternParser` 默认 | 尾斜杠/中间 `**` 差异 | 路径回归测试 |
| Spring Security 7 联动 | 401/403 语义、CSRF 默认 | 见 Security 体系迁移清单 |
| Undertow 移除 | 换容器 | 评估 Tomcat/Jetty |

**迁移五步法：**

```text
① 升级前：全量接口回归脚本（响应体快照对比）
② 升级依赖：Boot 4 + Jackson 3 类名/import 替换
③ 启动修复：配置类/转换器 Bean 调整
④ 接口回归：响应体逐字段对比（顺序/转义/日期/null）
⑤ 压测验证：虚拟线程下的并发与 ThreadLocal 检查
```

> ⚠️ **升级头号风险**：Jackson 3 的三个默认值变化（字段顺序、斜杠转义、日期格式）是**静默破坏**——没有回归脚本的迁移等于盲升级。

## 4. 故障排查手册

| 故障现象 | 排查链 |
|---------|--------|
| 接口 404 | ① 映射路径写错？② 尾斜杠？③ 拦截器放行？ |
| 405 Method Not Allowed | 方法语义与前端不一致（GET vs POST） |
| 406 Not Acceptable | produces 声明 vs Accept 头不匹配（02/04 篇） |
| 415 Unsupported Media Type | consumes 声明 vs Content-Type 不匹配 |
| 400 参数错误 | ① 类型转换失败 ② 校验失败（看 errors 明细） |
| 参数绑定不上（null） | ① 参数名不匹配 ② @ModelAttribute vs @RequestBody 用错 |
| JSON 字段丢失 | ① null 被过滤 ② @JsonView 视图不含该字段 ③ 拼写 |
| 字段顺序乱/斜杠转义 | Jackson 3 默认行为（04 篇配置） |
| 异常返回默认错误体 | 全局 handler 未覆盖该异常（05 篇） |
| 上传 413 | 三层限制哪层先拒绝（08 篇） |
| SSE 断连 | 心跳缺失 / 代理超时 / 连接上限（07 篇） |
| ThreadLocal 串数据 | 异步/虚拟线程未清理（06/07 篇） |

## 5. 面试高频 15 问

**核心链路：**

**Q1：DispatcherServlet 的处理流程？**
请求 → HandlerMapping 找处理器（+拦截器链）→ HandlerAdapter 参数绑定并调用 → 异常走 HandlerExceptionResolver → 返回值经消息转换器/视图解析写响应 → 拦截器 afterCompletion。（01 篇）

**Q2：@RestController 与 @Controller 区别？**
@RestController = @Controller + @ResponseBody——所有方法返回值走消息转换器输出 JSON；@Controller 返回值默认走视图渲染。（02 篇）

**Q3：@RequestBody 与 @RequestParam 区别？**
@RequestBody 从请求体反序列化对象（JSON）；@RequestParam 从查询参数/表单取单个值。（03 篇）

**Q4：@Valid 与 @Validated 区别？**
@Valid 是 JSR 标准注解、不支持分组；@Validated 是 Spring 扩展、支持分组校验（@Validated(CreateGroup.class)）。嵌套校验用 @Valid 字段级触发。（03 篇）

**Q5：Jackson 3 迁移影响什么？**
包名 com.fasterxml.jackson → tools.jackson；MappingJackson2HttpMessageConverter → JacksonJsonHttpMessageConverter；默认字段字母序、斜杠转义、日期 ISO-8601。（04 篇）

**Q6：消息转换器怎么工作？**
按"类型 + 媒体类型"匹配转换器链：canRead/canWrite 判断，read/write 转换。JSON 走 Jackson、XML 走 JacksonXml、字节走 ByteArray。（04 篇）

**异常：**

**Q7：全局异常处理怎么做？**
@RestControllerAdvice + @ExceptionHandler：校验失败（400+字段错误）、业务异常（业务码）、安全异常（401/403）、未知异常（500+日志+不泄露）。（05 篇）

**Q8：ProblemDetail 是什么？**
RFC 7807 标准错误体（type/title/status/detail/instance + 自定义属性）——比自定义 JSON 更规范，客户端开箱即用。（05 篇）

**Q9：Controller 内异常 vs 全局 Advice 谁生效？**
最近的优先：控制器内 @ExceptionHandler > @RestControllerAdvice；同级别异常类型更具体的优先。（05 篇）

**拦截与异步：**

**Q10：Filter 与 HandlerInterceptor 区别？**
Filter 在 Servlet 容器层（DispatcherServlet 前，无方法信息）；拦截器在 MVC 管道内（能拿到 HandlerMethod）。鉴权/审计用拦截器，编码/安全用 Filter。（06 篇）

**Q11：拦截器三个方法的执行时机？**
preHandle 方法前（false 中断）；postHandle 方法后响应前；afterCompletion 响应完成后（无论异常都执行，用于清理）。（06 篇）

**Q12：SSE 与 WebSocket 怎么选？**
服务端单向推送 → SSE（HTTP 天然穿透、自动重连）；双向交互 → WebSocket。多数通知场景 SSE 足够。（07 篇）

**Q13：Boot 4 虚拟线程对 MVC 的影响？**
Java 21+ 默认虚拟线程处理请求（吞吐 +39% 实测）——同步代码回归首选；新陷阱是 ThreadLocal 泄漏与 synchronized pinning（JDK 24 修复）。（07 篇）

**实践：**

**Q14：大文件上传怎么做？**
常规限 10-100MB 直传；更大走分片上传（init/chunk/complete）或 OSS 签名直传。应用层中转大文件是反模式。（08 篇）

**Q15：接口响应怎么统一？**
成功 Result 包装（code/msg/data）、异常 ProblemDetail + 业务码；逐字段校验错误；版本化（URL/头）；敏感字段 @JsonView 脱敏。（02/04/05 篇）

## 6. 版本特性速查（2026）

| 版本线 | 关键能力 | 本体系章节 |
|--------|---------|:---:|
| Spring Framework 6.x | PathPattern 默认、ProblemDetail、HTTP Interface | 01-05 |
| Spring Framework 7.0（2025-11） | Jackson 3 默认、SmartHttpMessageConverter + hints、转换器类名重命名、API 版本化 | 04 |
| Spring Boot 4.0（2025-11） | 虚拟线程默认（Java 21+）、Undertow 移除、JsonMapperBuilderCustomizer | 04/07 |
| Spring Boot 4.0.4+ | 虚拟线程上下文快照（ThreadLocal 传播） | 07 |

> 💡 **迁移提醒**：Boot 3→4 的三件套——Jackson 3（类名/默认值）、虚拟线程（ThreadLocal 审计）、Security 7（403 语义）——任何一件都是静默行为变化，回归脚本先行。

> 🎯 **核心要点**：SpringMVC 实践 = 请求链路（映射→绑定→转换→异常）理解 × 接口规范（资源化+统一响应+校验）× 异步能力（虚拟线程/SSE/流式）× 迁移纪律（Jackson 3 回归）。面试满分结构：**能画链路图、能答 Jackson 3 差异、能用 ProblemDetail + 分组校验 + SSE 讲完整接口方案**。
