## 1. 文件上传：MultipartFile 全流程

```html
<!-- 前端 -->
<form method="post" action="/api/files" enctype="multipart/form-data">
    <input type="file" name="file">
    <button>上传</button>
</form>
```

```java
@RestController
public class FileController {

    @PostMapping("/api/files")
    public FileInfo upload(@RequestParam("file") MultipartFile file) {
        // 基本信息
        String name = file.getOriginalFilename();
        long size = file.getSize();
        String contentType = file.getContentType();

        // 保存：流式写入（禁止 getBytes() 大文件场景）
        String objectKey = UUID.randomUUID() + "-" + sanitize(name);
        try (InputStream in = file.getInputStream()) {
            storageService.put(objectKey, in, size);     // 本地/OSS/MinIO
        } catch (IOException e) {
            throw new BizException(50001, INTERNAL_SERVER_ERROR, "文件保存失败");
        }
        return new FileInfo(objectKey, name, size);
    }
}
```

| API | 用途 |
|-----|------|
| `getOriginalFilename()` | 原始文件名（**含路径的坑**：IE 老版本传全路径） |
| `getSize()` | 大小 |
| `getContentType()` | MIME 类型 |
| `getInputStream()` | 流式读取（**首选**） |
| `getBytes()` | 一次性读入内存（小文件可用） |
| `transferTo(File)` | 直接落盘（注意临时目录） |

> ⚠️ **安全红线**：文件名必须清洗（`sanitize()` 去 `../`、空字节、非法字符），**绝不能直接用原始文件名拼路径**——路径穿越漏洞；contentType 不能信客户端，按扩展名/魔数重判。

## 2. 上传配置与限制

```yaml
spring:
  servlet:
    multipart:
      max-file-size: 10MB          # 单文件上限（默认 1MB）
      max-request-size: 100MB      # 单请求总上限（多文件）
      file-size-threshold: 2MB     # 超过阈值落临时文件（否则驻内存）
      location: ${java.io.tmpdir}  # 临时目录
```

| 配置 | 默认 | 说明 |
|------|:---:|------|
| max-file-size | 1MB | 单文件限制（超限 → 413） |
| max-request-size | 10MB | 请求体总限制 |
| file-size-threshold | 0 | 大小阈值：小文件内存、大文件临时盘 |

**超限处理（统一错误体，05 篇联动）：**

```java
@ExceptionHandler(MaxUploadSizeExceededException.class)
public ProblemDetail handleUploadSize(MaxUploadSizeExceededException e) {
    ProblemDetail detail = ProblemDetail.forStatusAndDetail(
            HttpStatus.PAYLOAD_TOO_LARGE, "文件大小超限");
    detail.setProperty("code", 41301);
    return detail;
}
```

> 🎯 **要点**：文件上限是**三层**的（网关/服务器/Spring），任何一层先拒绝都行——但错误响应要统一（网关 413 透传语义）。

## 3. 大文件与多文件上传

### 3.1 多文件

```java
@PostMapping("/api/files/batch")
public List<FileInfo> uploadBatch(@RequestParam("files") List<MultipartFile> files) {
    return files.stream().map(this::upload).toList();
}
```

### 3.2 大文件策略

| 方案 | 适用 | 说明 |
|------|------|------|
| 直接上传（限 10-100MB） | 常规 | max-request-size 配大 |
| 分片上传 | 数百 MB~GB | 前端分片 + 后端合并 |
| OSS/MinIO 直传 | 任意 | 签名 URL 直传对象存储，绕过应用 |

**分片上传接口设计（要点）：**

```text
POST /api/files/upload/init       → { uploadId, chunkSize }
POST /api/files/upload/chunk      → uploadId + 序号 + 分片（幂等：重复分片覆盖）
POST /api/files/upload/complete   → uploadId → 合并 → FileInfo
GET  /api/files/upload/status     → 已收分片列表（断点续传）
```

> 💡 **实践经验**：超过 100MB 就考虑分片或直传——应用层中转大文件既吃带宽又吃内存，多数大文件场景的对象存储直传是更优解。

## 4. 文件下载与断点续传

### 4.1 基础下载

```java
@GetMapping("/api/files/{objectKey}")
public ResponseEntity<Resource> download(@PathVariable String objectKey) {
    StorageObject obj = storageService.get(objectKey);
    return ResponseEntity.ok()
            .header(HttpHeaders.CONTENT_DISPOSITION,
                    "attachment; filename*=UTF-8''" + URLEncoder.encode(obj.getName(), UTF_8))
            .contentType(MediaType.APPLICATION_OCTET_STREAM)
            .contentLength(obj.getSize())
            .body(new InputStreamResource(obj.getInputStream()));
}
```

| 头 | 作用 |
|----|------|
| `Content-Disposition: attachment` | 触发下载而非浏览器打开 |
| `filename*=UTF-8''` | 中文文件名 RFC 5987 编码 |
| `Content-Length` | 长度（断点续传必需） |

### 4.2 断点续传（Range 支持）

```java
@GetMapping("/api/files/{objectKey}")
public ResponseEntity<Resource> downloadWithRange(@PathVariable String objectKey,
        @RequestHeader(value = "Range", required = false) String rangeHeader) throws IOException {

    StorageObject obj = storageService.get(objectKey);
    long fileSize = obj.getSize();

    if (rangeHeader == null) {
        // 普通下载（200 + 全量）
        return fullResponse(obj);
    }
    // 解析 Range: bytes=start-end
    Range range = parse(rangeHeader, fileSize);
    if (range.invalid()) {
        return ResponseEntity.status(HttpStatus.REQUESTED_RANGE_NOT_SATISFIABLE)
                .header(HttpHeaders.CONTENT_RANGE, "bytes */" + fileSize).build();   // 416
    }
    // 部分响应（206）
    return ResponseEntity.status(HttpStatus.PARTIAL_CONTENT)
            .header(HttpHeaders.CONTENT_RANGE,
                    "bytes " + range.start() + "-" + range.end() + "/" + fileSize)
            .contentLength(range.length())
            .body(new InputStreamResource(skipTo(obj.getInputStream(), range.start())));
}
```

| 状态码 | 语义 |
|:---:|------|
| 200 | 全量响应 |
| 206 | Partial Content（断点续传/多线程下载） |
| 416 | Range 不可满足（越界） |

> 💡 **实现捷径**：`ResourceRegion` + `HttpRange` 是 Spring 内置的 Range 支持（`org.springframework.core.io.support`）——但多数生产场景直接由对象存储/CDN 承担断点续传。

## 5. 静态资源映射与缓存

```java
@Configuration
public class WebConfig implements WebMvcConfigurer {

    @Override
    public void addResourceHandlers(ResourceHandlerRegistry registry) {
        registry.addResourceHandler("/static/**")
                .addResourceLocations("classpath:/static/")
                .setCacheControl(CacheControl.maxAge(7, TimeUnit.DAYS).cachePublic());  // 强缓存
    }
}
```

```yaml
spring:
  web:
    resources:
      cache:
        cachecontrol:
          max-age: 7d
      static-locations: classpath:/static/,file:/data/upload/   # 外部目录映射
```

| 资源场景 | 缓存策略 |
|---------|---------|
| 指纹静态资源（webpack 带 hash） | 强缓存（1 年） |
| 无指纹静态资源 | no-cache + ETag |
| 上传文件预览 | 短缓存 + 校验 |

> ⚠️ **注意**：开发调试常见"改了静态资源不生效"——浏览器强缓存；用 `?v=版本号` 或 nginx 层控缓存头。

## 6. 内容协商策略配置

```java
@Configuration
public class WebConfig implements WebMvcConfigurer {

    @Override
    public void configureContentNegotiation(ContentNegotiationConfigurer configurer) {
        configurer
                .defaultContentType(MediaType.APPLICATION_JSON)          // 默认 JSON
                .mediaType("json", MediaType.APPLICATION_JSON)           // ?format=json
                .mediaType("xml", MediaType.APPLICATION_XML)
                .parameterName("format")                                  // 开启参数协商
                .ignoreAcceptHeader(false);                               // 保留 Accept 协商
    }
}
```

| 协商方式 | 优先级 | 说明 |
|---------|:---:|------|
| URL 后缀（.json/.xml） | 高 | 已废弃趋势（PathPattern 下语义模糊） |
| 请求参数（?format=） | 中 | 需显式开启 |
| Accept 头 | 低 | 标准方式（配合 produces） |

> 🎯 **要点**：现代 REST API 只用 Accept 头协商（produces 声明 + JSON 默认）；URL 后缀与参数协商留给兼容旧客户端。**"只做 JSON"的团队配置默认 JSON 即可，协商逻辑透明化**。

> 🎯 **核心要点**：文件与资源四件事——上传（流式 + 文件名清洗 + 三层限制）、下载（Content-Disposition + Range 断点）、静态资源（缓存策略分层）、协商（Accept 标准 + JSON 默认）。安全红线：文件名永不直用、contentType 永不轻信。
