## 1. 参数来源与绑定注解全景

| 注解 | 来源 | 典型场景 |
|------|------|---------|
| `@PathVariable` | URL 路径变量 | `/api/users/{id}` |
| `@RequestParam` | 查询参数 / 表单字段 | `?page=1&size=20` |
| `@RequestHeader` | 请求头 | 版本号、令牌 |
| `@CookieValue` | Cookie | 会话标识 |
| `@RequestBody` | 请求体（JSON/XML） | POST 创建 |
| `@ModelAttribute` | 表单字段 → 对象 | 表单提交 |
| `@RequestPart` | multipart 部分 | 上传（08 篇） |
| `HttpServletRequest` 等 | Servlet API | 原生访问 |
| `@AuthenticationPrincipal` | 安全主体（Security 体系） | 当前用户 |

```java
@GetMapping("/api/users/{id}")
public User get(@PathVariable Long id,
                @RequestParam(defaultValue = "1") int page,
                @RequestHeader("X-API-Version") String version) { ... }
```

> 🎯 **要点**：每个注解对应一个 `MethodArgumentResolver`（01 篇链路第 3 步）。**解析失败统一 400**（TypeMismatchException → 400）。

## 2. 类型转换体系：Converter 与 Formatter

### 2.1 转换链

```text
字符串参数（"1001"）→ Converter（String→Long）→ 方法参数（Long 1001）

内置转换：String→数值/布尔/日期/枚举/集合...
```

### 2.2 自定义转换器

```java
// 场景：URL 传 "20260807" → LocalDate
@Component
public class StringToLocalDateConverter implements Converter<String, LocalDate> {

    @Override
    public LocalDate convert(String source) {
        return LocalDate.parse(source, DateTimeFormatter.ofPattern("yyyyMMdd"));
    }
}
```

```java
// 场景：请求参数 "ADMIN,USER" → List<String>（自动转换）
// ?roles=ADMIN,USER → @RequestParam List<String> roles
```

| 转换器类型 | 用途 |
|-----------|------|
| `Converter<S,T>` | 通用类型转换 |
| `Formatter<T>` | 字符串↔对象（含解析/打印双向） |
| 内置 | 基本类型、日期（ISO-8601）、枚举、集合 |

> ⚠️ **日期格式注意**：Jackson 3 默认日期序列化为 ISO-8601 字符串；请求参数日期转换按 `@DateTimeFormat` 指定模式，两者体系不同（04 篇展开）。

## 3. 对象绑定与 @ModelAttribute

```java
// 场景：GET 查询条件 → 对象
@GetMapping("/api/users")
public List<User> search(UserQuery query) { ... }    // ?name=张&status=1 → 自动装配

// 显式写法
@GetMapping("/api/users")
public List<User> search(@ModelAttribute UserQuery query) { ... }

public class UserQuery {
    private String name;      // ?name=张
    private Integer status;   // ?status=1
    private Integer page = 1;
    private Integer size = 20;
    // getters/setters
}
```

| 绑定行为 | 说明 |
|---------|------|
| 字段名匹配 | 请求参数名 = 属性名（支持驼峰） |
| 默认值 | 对象初始值（page=1）不被空参数覆盖 |
| 嵌套对象 | `address.city=x` → 嵌套属性 |
| 集合 | `ids=1&ids=2` → List<Integer> |

> 💡 **经验**：查询参数多（≥4 个）就封装成 Query 对象——可复用、可加校验、可默认值。POST 表单场景同属 @ModelAttribute，REST JSON 场景用 @RequestBody。

## 4. @RequestBody 的绑定语义

```java
@PostMapping("/api/users")
public User create(@RequestBody @Valid User user) { ... }   // JSON → User
```

**绑定流程（与消息转换器联动，04 篇）：**

```text
Content-Type: application/json 请求体
  → 选转换器（JacksonJsonHttpMessageConverter）
  → 反序列化为 User（@JsonCreator/@JsonProperty 参与）
  → 未匹配字段：默认忽略（FAIL_ON_UNKNOWN_PROPERTIES 可配）
  → null 字段：不进对象（或按配置报错）
```

| 场景 | 行为 |
|------|------|
| JSON 字段多余 | 默认忽略（生产建议关闭容忍或显式处理） |
| JSON 字段缺失 | 对象字段为 null |
| JSON 语法错误 | 400（HttpMessageNotReadableException） |
| Content-Type 不匹配 | 415 |

> ⚠️ **注意**：@RequestBody 绑定的是"对象整体"，**不做属性级默认值**（与 @ModelAttribute 不同）——缺失即 null。校验职责交给 @Valid（下节）。

## 5. @Valid / @Validated：校验与分组

### 5.1 基础校验

```java
public class UserCreateRequest {

    @NotBlank(message = "用户名不能为空")
    @Size(min = 2, max = 20, message = "用户名长度 2-20")
    private String username;

    @Email(message = "邮箱格式不正确")
    private String email;

    @Min(value = 1, message = "年龄最小 1")
    @Max(value = 150, message = "年龄最大 150")
    private Integer age;

    @Pattern(regexp = "^1[3-9]\\d{9}$", message = "手机号格式不正确")
    private String phone;
}
```

```java
// 方法参数校验（Java Bean Validation）
@PostMapping("/api/users")
public User create(@RequestBody @Valid UserCreateRequest req) { ... }

// 或类级校验（方法参数与返回值）
@Validated
@RestController
public class UserController { ... }
```

### 5.2 @Valid 与 @Validated 的区别（面试必考）

| 维度 | @Valid | @Validated |
|------|:---:|:---:|
| 来源 | JSR-303 标准 | Spring 扩展 |
| 分组校验 | ❌ 不支持 | ✅ `@Validated(Group.class)` |
| 嵌套校验 | ✅（@Valid 字段级触发） | 依赖 @Valid 嵌套 |
| 方法参数校验 | 部分 | ✅ 完整 |

**分组校验实战：**

```java
// 分组接口
public interface CreateGroup { }
public interface UpdateGroup { }

public class UserRequest {
    @Null(groups = CreateGroup.class, message = "创建时 ID 必须为空")
    @NotNull(groups = UpdateGroup.class, message = "更新时 ID 必填")
    private Long id;

    @NotBlank(groups = {CreateGroup.class, UpdateGroup.class}, message = "用户名不能为空")
    private String username;
}

// 使用
@PostMapping("/api/users")
public User create(@RequestBody @Validated(CreateGroup.class) UserRequest req) { ... }

@PutMapping("/api/users/{id}")
public User update(@PathVariable Long id,
                   @RequestBody @Validated(UpdateGroup.class) UserRequest req) { ... }
```

> 🎯 **要点**：同一种请求对象在创建/更新时校验规则不同——分组校验让一个 DTO 承载两套规则，避免"两个 DTO 大量重复"。

## 6. 自定义校验注解

```java
// 场景：枚举合法性校验
@Target({ElementType.FIELD, ElementType.PARAMETER})
@Retention(RetentionPolicy.RUNTIME)
@Constraint(validatedBy = EnumValueValidator.class)   // 绑定校验器
public @interface EnumValue {
    Class<? extends Enum<?>> enumClass();
    String message() default "枚举值不合法";
    Class<?>[] groups() default {};
    Class<? extends Payload>[] payload() default {};
}

// 校验器实现
public class EnumValueValidator implements ConstraintValidator<EnumValue, Object> {

    private Set<String> values;

    @Override
    public void initialize(EnumValue constraint) {
        values = Arrays.stream(constraint.enumClass().getEnumConstants())
                .map(Enum::name).collect(Collectors.toSet());
    }

    @Override
    public boolean isValid(Object value, ConstraintValidatorContext context) {
        return value == null || values.contains(value.toString());
    }
}
```

| 自定义校验要素 | 说明 |
|--------------|------|
| `@Constraint` | 声明校验器（必选） |
| `initialize()` | 读注解参数（枚举类等） |
| `isValid()` | 校验逻辑（null 视为合法，由 @NotNull 管） |
| message | 默认错误消息（支持 {参数} 插值） |

## 7. 校验失败响应设计

```java
// 默认失败：MethodArgumentNotValidException → 400 + 默认错误体
// 生产标准：统一格式（配合 05 篇异常体系）

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<Map<String, Object>> handleValidation(MethodArgumentNotValidException e) {
        Map<String, String> errors = e.getBindingResult().getFieldErrors().stream()
                .collect(Collectors.toMap(
                        FieldError::getField,
                        fe -> fe.getDefaultMessage() == null ? "invalid" : fe.getDefaultMessage(),
                        (a, b) -> a));
        return ResponseEntity.badRequest().body(Map.of(
                "code", 400,
                "message", "参数校验失败",
                "errors", errors));
    }
}
```

```json
{
  "code": 400,
  "message": "参数校验失败",
  "errors": {
    "username": "用户名长度 2-20",
    "phone": "手机号格式不正确"
  }
}
```

| 设计要点 | 说明 |
|---------|------|
| 逐字段错误 | errors 字典（field → message），前端可逐字段提示 |
| 统一 code | 业务码与 HTTP 状态码分离 |
| 覆盖所有校验异常 | MethodArgumentNotValidException + ConstraintViolationException + BindException |

> 🎯 **核心要点**：参数层 = 绑定（注解定位来源 + 转换器转类型 + 装配进对象）+ 校验（Bean Validation 声明规则 + 分组区分场景 + 自定义注解扩规则）。**校验必须进"统一错误响应"体系**——散落的 400 默认体是接口质量的减分项。REST JSON 用 @RequestBody + @Valid，表单/查询用 @ModelAttribute + @Validated。
