## 1. Starter 模块清单

### 1.1 模型接入 Starter

| Starter | 模型 | 说明 |
|---------|------|------|
| `spring-ai-starter-model-openai` | OpenAI | 仅剩 SDK 变体（Azure/HTTP 变体已收敛），OpenAI 兼容 API 也可用此接入（DeepSeek 等） |
| `spring-ai-starter-model-anthropic` | Anthropic Claude | 仅剩 SDK 变体，兼容 Minimax 等 |
| `spring-ai-starter-model-deepseek` | DeepSeek | 官方维护核心集成员 |
| `spring-ai-starter-model-ollama` | Ollama（本地开源模型） | 本地部署首选 |
| `spring-ai-starter-model-bedrock` | Amazon Bedrock | 云厂商 |
| `spring-ai-starter-model-google-genai` | Google GenAI SDK | Vertex 变体已收敛 |
| `spring-ai-starter-model-mistralai` | Mistral AI | 官方维护核心集成员 |
| `spring-ai-starter-model-oci-genai` | OCI Generative AI | 与厂商协作维护 |
| `spring-ai-starter-model-zhipuai` / 其他 | 智谱等 | 外部维护（社区） |

> 💡 **2.0 收敛策略**：核心项目只维护 7 个官方 provider（OpenAI/Anthropic/DeepSeek/Ollama/Bedrock/Google/Mistral），其余由厂商或社区维护——选型时优先官方集，减少兼容风险。

| Starter | 向量库 | 场景 |

| `spring-ai-starter-vector-store-pgvector` | PostgreSQL + pgvector | 复用关系库 |
| `spring-ai-starter-vector-store-redis` | Redis（含 Redis Stack） | 缓存+向量一体 |

| `spring-ai-starter-vector-store-chroma` | Chroma | 轻量/原型 |

### 1.3 MCP 与支撑 Starter

| Starter | 用途 |
|---------|------|
| `spring-ai-starter-mcp-client` | 作为 MCP **客户端**连接外部 MCP Server（stdio / Streamable HTTP） |
| `spring-ai-starter-mcp-server` | 把应用暴露为 MCP **Server**（`@McpTool` 自动注册） |
| `spring-ai-starter-tools` | 内置工具集（天气、搜索等，按需） |
| `spring-ai-starter-memory-redis` 等 | 记忆存储实现 |

### 1.4 模块命名注意（2.0 改名）

| 旧名 | 新名 |
|------|------|
| `spring-ai-advisors-vector-store` | `spring-ai-vector-store-advisor` |

> ⚠️ 依赖坐标以官方 BOM（`spring-ai-bom`）管理，**不要手写版本**；2.0 改名模块在旧坐标下会解析失败。

## 2. 版本矩阵与演进史

| 版本 | 发布时间 | 基线 | 关键变化 |
|------|---------|------|---------|
| 0.x（M 系列） | 2023-2024 | Boot 3.1/3.2 | 原型期：ChatClient 雏形、向量库抽象 |
| 1.0.0 GA | 2025-05 | Boot 3.4/3.5 | 首个 GA：20+ 模型、20+ 向量库、`@Tool`、MCP 初版 |
| 1.1.x | 2025 下半年 | Boot 3.5.x | 维护线（Boot 3 用户停靠点） |
| 2.0.0（8 里程碑 + 2 RC） | 2025-12 ~ 2026-06 | **Boot 4.0/4.1** | 架构重构（见第 3 节） |
| **2.0.0 GA** | **2026-06-12** | Boot 4.0/4.1 | 本文档基准 |

> ⚠️ **版本铁律**：Spring AI 2.0 **无法**在 Boot 3.x 上运行——想用 2.0 必须先把应用升到 Boot 4.0；Boot 3 项目只能停在 1.1.x。没有"只升 AI 不升 Boot"的路径。

## 3. 2.0 重大变更全景

### 3.1 基础设施升级

| 变更 | 影响 |
|------|------|
| Boot 4.0/4.1 + Framework 7.0 + Jakarta EE 11 | 系统依赖全线换代 |
| Jackson 2 → **Jackson 3** | 序列化行为变化；`JsonMapper` 可定制，新增 `JsonHelper` |
| JSpecify 空安全注解全库覆盖 | 编译期防 NPE；Kotlin 原生友好 |
| Java 17 最低（推荐 21） | 老项目需先升 JDK |

### 3.2 API 方向重构

| 变更 | 旧 | 新 |
|------|----|----|
| 主 API | ChatModel 直接调用 | **ChatClient 为主**，ChatModel 降为底层构建块 |
| 工具调用 | 各 ChatModel 内部私循环 | **ToolCallingAdvisor 统一循环**，ChatClient 自动注册 |
| 工具注册 | `toolNames()` / `SpringBeanToolCallbackResolver` | 显式 `ToolCallback` Bean + `.tools(...)` 传入（旧 API 已删除） |
| 模型默认值 | 各模型自带默认 option | **默认值下沉 provider**，未设置时用厂商默认 |
| Options | 可变对象 | **不可变构建器**，反射合并移除，与配置属性解耦 |
| 配置属性 | `.options` 段 | 属性键去掉 `.options` 段 |

### 3.3 工具与 Agent 变更

| 变更 | 说明 |
|------|------|
| `ToolCallingAdvisor` | 工具循环作为 Advisor 链一等公民，支持递归重入；`returnDirect` 直接返回工具结果 |
| `ToolCallAdvisor` 改名 | 旧名保留为废弃子类 |
| `ToolSearchToolCallingAdvisor` | 渐进式工具披露，支持数百个工具的按需发现（ToolIndex：向量库/Lucene/正则） |
| 内部工具执行移除 | `internalToolExecutionEnabled` 删除，`ToolExecutionEligibilityChecker` 不再是模型内部逻辑 |
| 记忆与工具循环分离 | 记忆 Advisor 默认在工具循环**之外**（2.0 排序调整） |

### 3.4 MCP 变更

| 变更 | 说明 |
|------|------|
| 原生集成 | `@McpTool` 注解编程模型，自动扫描注册 |
| 传输层内移 | 从 MCP Java SDK 移入 Spring AI 自身（WebMVC/WebFlux） |
| **Streamable HTTP 默认** | 取代已弃用的 SSE 传输；STDIO 保留给本地进程 |
| 双角色 | 一个应用可同时是 MCP Client 与 MCP Server |
| 命名防冲突 | `DefaultMcpToolNamePrefixGenerator`；`McpToolFilter` 限制外部工具 |

### 3.5 其他

| 变更 | 说明 |
|------|------|
| `StructuredOutputValidationAdvisor` | 输出 schema 校验 + 失败重试（默认 3 次），`EntityParamSpec` 支持调用点配置 |
| 记忆窗口裁剪 | `MessageWindowChatMemory` 裁剪点前移到最近 USER 消息，避免切分对话轮次 |
| 可观测性 | Advisor 链、工具循环全程 Micrometer Tracing 支持 |

## 4. 1.x → 2.0 迁移路径

```text
① 升 Boot 3.5 → 4.0.x（含 Framework 7 / Jakarta EE 11 / JDK 17+）
② 升 Jackson 2 → 3（检查自定义 ObjectMapper/JsonMapper 配置）
③ 工具调用改造：toolNames() → 显式 ToolCallback Bean + .tools()
④ Options 改用不可变构建器；配置属性键去掉 .options 段
⑤ 校验 @Tool 签名与 MCP 传输（SSE → Streamable HTTP）
⑥ 逐项对照官方 Upgrade Notes 跑回归
```

| 迁移风险 | 表现 | 处理 |
|----------|------|------|
| 工具静默失效 | 模型不再收到工具定义 | 步骤 ③ 是硬性破坏，无兼容层 |
| 序列化差异 | 输出结构与 1.x 不同 | 用 `JsonMapper`/`JsonHelper` 对齐 |
| MCP 连接失败 | SSE 端点不可用 | 换 Streamable HTTP 端点 |
| 属性不生效 | `.options` 键被忽略 | 属性键迁移 |

> 🎯 **核心要点**：2.0 的迁移本质是"**工具调用架构迁移**"——从模型内私循环到 Advisor 链统一循环。理解 ToolCallingAdvisor + 递归链，就理解了 2.0 的一半。

## 5. 核心要点

> 🎯 **核心要点**：
> - 7 个官方 provider + 20+ 向量库 + MCP Client/Server 双角色，覆盖完整 AI 应用栈；
> - 2.0 只能在 Boot 4 运行；Boot 3 项目停靠 1.1.x；
> - 破坏性核心：工具调用统一进 Advisor 链、`toolNames()` 删除、Jackson 3、Options 不可变；
> - 迁移按 6 步走，工具改造是唯一硬性阻断点。
