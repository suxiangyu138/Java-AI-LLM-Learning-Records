## 1. Provider 接入全景

| Provider | Starter | 配置要点 | 场景 |
|----------|---------|---------|------|
| OpenAI | `spring-ai-starter-model-openai` | `spring.ai.openai.api-key`、模型 ID | 通用首选（兼容 API 也可接） |
| Anthropic | `spring-ai-starter-model-anthropic` | `spring.ai.anthropic.api-key` | Claude 系列 |
| DeepSeek | `spring-ai-starter-model-deepseek` | `spring.ai.deepseek.api-key` | 国内主力（OpenAI 兼容） |
| Ollama | `spring-ai-starter-model-ollama` | `spring.ai.ollama.base-url`（默认 localhost:11434） | 本地私有化 |
| Bedrock | `spring-ai-starter-model-bedrock` | AWS 凭证 | 云原生 |
| Google GenAI | `spring-ai-starter-model-google-genai` | Gemini API key | Google 生态 |
| Mistral | `spring-ai-starter-model-mistralai` | API key | 欧洲模型 |

> 💡 **OpenAI 兼容接入 DeepSeek/本地网关**：DeepSeek 等提供 OpenAI 兼容端点，可仅引入 `model-openai` starter + 覆写 base-url 接入——但官方有专用 starter 时优先专用（模型 ID/参数映射更准）。

## 2. 配置体系：spring.ai.model 与 api-key

### 2.1 核心配置

```yaml
spring:
  ai:
    model:
      chat: openai            # 默认 ChatModel 选择器（2.0 配置解耦）
      embedding: openai       # 默认 EmbeddingModel 选择器
    openai:
      api-key: ${OPENAI_API_KEY}
      chat:
        options:
          model: gpt-4o       # 模型 ID
          temperature: 0.7
    ollama:
      base-url: http://localhost:11434
      chat:
        options:
          model: qwen3:8b
```

### 2.2 2.0 配置变化（Options 解耦）

| 变化 | 说明 |
|------|------|
| 配置键去 `.options` 段 | `spring.ai.openai.chat.options.model` 直接可用；属性与 Options 对象解耦 |
| 默认值下沉 provider | 2.0 移除模型侧默认值——未配置时由厂商 API 使用其默认 |
| 不可变 Options | 运行时改参数用构建器 `.mutate()`/新建，而非改对象 |

> ⚠️ **易错点**：2.0 不再有"框架给的默认 temperature 等"——不配置就完全跟随厂商默认。要稳定输出必须显式配置。

## 3. ChatOptions 与参数语义

| 参数 | 语义 | 注意 |
|------|------|------|
| `model` | 模型 ID | 厂商列表页为准，滚动更新 |
| `temperature` | 随机性（0~2，OpenAI 系） | 结构化输出/工具调用建议低值 |
| `maxTokens` | 输出上限 | 长输出必配 |
| `topP` | 核采样 | 与 temperature 通常不同时用 |
| `frequencyPenalty` / `presencePenalty` | 重复控制 | 仅部分厂商支持 |
| `stop` | 停止序列 | 生成式文本截断 |
| `stream` | 是否流式 | 走 `chatClient.stream()` 由框架管理 |

运行时覆写：

```java
ChatOptions options = ChatOptions.builder()
        .model("gpt-4o-mini")
        .temperature(0.2)
        .build();

String answer = chatClient.prompt()
        .options(options)
        .user("总结这段文字")
        .call()
        .content();
```

## 4. 结构化输出：entity() 与校验

### 4.1 基础用法

```java
public record OrderInfo(String orderId, String status, BigDecimal amount) {}

OrderInfo info = chatClient.prompt()
        .user("从文本中提取订单信息: " + text)
        .entity(OrderInfo.class);       // 直接映射 POJO
```

### 4.2 校验与重试（2.0 核心能力）

| 机制 | 说明 |
|------|------|
| `StructuredOutputValidationAdvisor` | 用目标类型生成的 JSON Schema 校验模型输出；失败带错误信息重试（默认最多 3 次），自动累计 token 用量 |
| `EntityParamSpec` | 调用点级配置：`chatClient.entity(EntityParamSpec)`，可指定 provider 原生结构化输出或 schema 校验 |
| 自定义 Schema | `outputType` 与 `outputJsonSchema` 二选一（互斥），可跳过 POJO 直接给 JSON Schema |

```java
// 调用点级结构化输出配置
EntityParamSpec spec = EntityParamSpec.builder()
        .outputType(OrderInfo.class)
        .build();

OrderInfo info = chatClient.entity(spec).prompt()
        .user("提取订单: " + text)
        .call()
        .entity(OrderInfo.class);
```

### 4.3 模式对比

| 模式 | 机制 | 适用 |
|------|------|------|
| JSON 模式（json_mode） | 强制输出合法 JSON | 简单结构 |
| Function Calling 模式 | 用工具 schema 约束字段 | 复杂嵌套结构（推荐） |
| JSON Schema 模式（strict） | 输出严格匹配 schema | 高可靠解析 |
| Provider 原生结构化输出 | 厂商端生成保证 | 厂商支持时最高效 |

> ⚠️ **校验是兜底不是替代**：模型即使 strict 模式也可能违规；生产环境保留 `StructuredOutputValidationAdvisor` 做最后防线，解析失败走降级流程（重试 → 拒答 → 告警）。

## 5. 多模型切换与降级

### 5.1 配置级切换

```yaml
spring:
  ai:
    model:
      chat: deepseek     # 一键切默认模型
    deepseek:
      api-key: ${DEEPSEEK_API_KEY}
```

### 5.2 代码级多模型（多 Bean）

```java
@Bean
public ChatClient deepSeekChatClient(ChatClient.Builder builder,
        @Qualifier("deepseekChatModel") ChatModel deepseekModel) {
    return builder.defaultModel(deepseekModel).build();
}

@Bean
public ChatClient openAiChatClient(ChatClient.Builder builder,
        @Qualifier("openAiChatModel") ChatModel openAiModel) {
    return builder.defaultModel(openAiModel).build();
}
```

| 场景 | 方案 |
|------|------|
| 不同业务用不同模型 | 多 ChatClient Bean + `defaultModel` |
| 主备降级 | 运行时 try-catch 切换备用 ChatClient（重试策略见 10） |
| 成本分层 | 简单任务 `gpt-4o-mini`/`deepseek-chat`，复杂任务大模型 |

> 🎯 **核心要点**：结构化输出是 AI 应用与业务系统对接的"类型安全层"——`entity()` + 校验 Advisor + provider 原生模式三件套；多模型切换靠"选择器配置 + 多 Bean"，业务代码不变。

## 6. 核心要点

> 🎯 **核心要点**：
> - 7 大官方 provider 一套 ChatClient API，换模型只改 starter + 配置；
> - 2.0 默认值下沉厂商，稳定输出必须显式配置 Options（不可变构建器）；
> - 结构化输出 = entity() 映射 + Schema 校验重试 + provider 原生模式；
> - 多模型 = 选择器配置切默认 + 多 ChatClient Bean 做降级。
