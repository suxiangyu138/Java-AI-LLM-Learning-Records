## 1. 环境准备

| 依赖 | 要求 | 说明 |
|------|------|------|
| JDK | 17+（推荐 21） | 2.0 强制 |
| Spring Boot | 4.0.x / 4.1.x | 2.0 只能在 Boot 4 运行 |
| 模型 API Key | 任一：OpenAI / DeepSeek / Anthropic | 本 Demo 用 DeepSeek（国内可达） |
| 可选 | Ollama 本地模型 | 无网络/无 key 环境的替代 |

```yaml
# 本地 Ollama 方案（零成本跑通）
spring:
  ai:
    model:
      chat: ollama
    ollama:
      base-url: http://localhost:11434
      chat:
        options:
          model: qwen3:8b
```

## 2. 工程骨架（Maven）

```xml
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>4.0.1</version>
    <relativePath/>
</parent>

<properties>
    <spring-ai.version>2.0.0</spring-ai.version>
</properties>

<dependencies>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>
    <dependency>
        <groupId>org.springframework.ai</groupId>
        <artifactId>spring-ai-starter-model-deepseek</artifactId>
    </dependency>
    <!-- 或本地模型 -->
    <dependency>
        <groupId>org.springframework.ai</groupId>
        <artifactId>spring-ai-starter-model-ollama</artifactId>
    </dependency>
</dependencies>

<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.springframework.ai</groupId>
            <artifactId>spring-ai-bom</artifactId>
            <version>${spring-ai.version}</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>
```

> ⚠️ **版本纪律**：Spring AI 版本一律由 `spring-ai-bom` 管理，不要单独写 starter 版本；2.0 发布版在 Maven Central（无需额外仓库），快照版需 repo.spring.io 快照仓。

## 3. Demo 一：ChatClient 对话

```java
@Configuration
public class ChatConfig {
    @Bean
    ChatClient chatClient(ChatClient.Builder builder) {
        return builder.build();
    }
}

@RestController
public class ChatController {

    private final ChatClient chatClient;

    public ChatController(ChatClient chatClient) {
        this.chatClient = chatClient;
    }

    @GetMapping("/chat")
    public String chat(@RequestParam String q) {
        return chatClient.prompt()
                .system("你是电商客服助手，回答简洁、用中文。")
                .user(q)
                .call()
                .content();
    }

    @GetMapping(value = "/chat/stream", produces = "text/event-stream")
    public Flux<String> chatStream(@RequestParam String q) {
        return chatClient.prompt()
                .user(q)
                .stream()
                .content();
    }
}
```

```yaml
spring:
  ai:
    deepseek:
      api-key: ${DEEPSEEK_API_KEY}
      chat:
        options:
          model: deepseek-chat
          temperature: 0.3
```

## 4. Demo 二：结构化输出

```java
public record OrderInfo(String orderId, String status, String receiver, BigDecimal amount) {}

@RestController
public class ExtractController {

    private final ChatClient chatClient;

    @PostMapping("/extract")
    public OrderInfo extract(@RequestBody String text) {
        return chatClient.prompt()
                .system("提取文本中的订单信息，缺失字段填空字符串。")
                .user(text)
                .entity(OrderInfo.class);       // 自动 JSON Schema + 校验重试
    }
}
```

验证：

```bash
curl -X POST http://localhost:8080/extract \
  -d '订单号 SO-20260808-001 已支付，收货人张三，金额 299.00 元'
# → {"orderId":"SO-20260808-001","status":"已支付","receiver":"张三","amount":299.00}
```

> 💡 输出为 record/POJO 时字段缺失、类型错乱会触发 `StructuredOutputValidationAdvisor` 自动重试——生产可观察重试次数与 token 开销。

## 5. Demo 三：工具调用

```java
@Component
public class WeatherTools {

    @Tool(description = "查询指定城市的当前天气")
    public String getWeather(@ToolParam(description = "城市名，如 北京") String city) {
        // 真实场景对接气象 API；此处返回模拟
        return city + ": 晴, 28℃";
    }
}

@RestController
public class ToolController {

    private final ChatClient chatClient;

    public ToolController(ChatClient.Builder builder, WeatherTools weatherTools) {
        this.chatClient = builder
                .defaultTools(weatherTools)     // 默认挂载工具
                .build();
    }

    @GetMapping("/weather")
    public String weather(@RequestParam String q) {
        return chatClient.prompt()
                .user(q)                        // "北京天气怎么样？"
                .call()
                .content();
    }
}
```

```yaml
spring:
  ai:
    chat:
      client:
        tool-call-advisor: true    # 2.0 自动注册 ToolCallingAdvisor（默认开启）
```

## 6. 运行与验证

| 验证项 | 方法 | 预期 |
|--------|------|------|
| 模型连通 | `GET /chat?q=你好` | 返回正常回答 |
| 流式 | `curl -N /chat/stream` | 逐 token 输出（SSE） |
| 结构化 | `POST /extract` | 严格 JSON，字段与 record 一致 |
| 工具调用 | `GET /weather?q=北京天气` | 回答包含"晴, 28℃"（证明工具被执行） |
| 工具循环日志 | 开启 `SimpleLoggerAdvisor` | 可见"模型请求工具 → 执行 → 回传"两轮 |

## 7. 常见启动失败排查

| 现象 | 原因 | 处理 |
|------|------|------|
| `No qualifying bean of type ChatModel` | 未引入任何 model starter，或 `spring.ai.model.chat` 指向未引入的 provider | 检查 starter 依赖与选择器配置 |
| 401 认证失败 | api-key 未配置/配错 | 检查环境变量注入 |
| 连接超时（Ollama） | 本地模型未启动/端口不对 | `ollama serve` + 检查 `base-url` |
| 工具不生效 | 2.0 需显式 `.tools(...)` 或 `defaultTools(...)` | 旧 `toolNames()` 写法已删除 |
| 输出无法反序列化 | record 字段与模型输出不匹配 | 检查描述清晰度 + 开启校验 Advisor 看重试日志 |
| Boot 3 项目引入 2.0 | 版本冲突/启动异常 | 先升 Boot 4.0（2.0 硬性要求） |
