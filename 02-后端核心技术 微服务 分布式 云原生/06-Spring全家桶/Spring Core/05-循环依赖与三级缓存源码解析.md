## 1. 循环依赖场景与解决前提

### 1.1 什么是循环依赖

```text
场景 A：
  A 依赖 B（字段注入）
  B 依赖 A（字段注入）
  → 容器能解决（三级缓存）

场景 B（解决不了）：
  A 构造器依赖 B，B 构造器依赖 A
  → 创建实例本身需要对方 → 死锁 → BeanCurrentlyInCreationException
```

### 1.2 解决的前提条件（面试必答）

| 条件 | 说明 |
|------|------|
| 单例 bean | 原型/Request 等作用域不缓存、不解决 |
| 非构造器注入 | 字段/Setter 注入才能提前暴露原始实例 |
| 非懒加载（默认） | 懒加载单例创建时也可解决（只要走 getBean 链路） |
| 非 @Async 前置 | 代理需要目标完整初始化，提前暴露有损（见第 6 节） |

> 🎯 面试开场白：**「Spring 能解决的是『单例 + 字段/Setter 注入』的循环依赖，构造器循环依赖与原型循环依赖无法解决」**——先把边界说清，再讲机制。

## 2. 三级缓存结构

### 2.1 源码字段（DefaultSingletonBeanRegistry）

```java
public class DefaultSingletonBeanRegistry {
    // 一级缓存：成品单例（完全初始化）
    private final Map<String, Object> singletonObjects = new ConcurrentHashMap<>(256);

    // 二级缓存：提前暴露的原始实例（未完成初始化）
    private final Map<String, Object> earlySingletonObjects = new ConcurrentHashMap<>(16);

    // 三级缓存：ObjectFactory（延迟决策工厂，只在首次访问时执行）
    private final Map<String, ObjectFactory<?>> singletonFactories = new HashMap<>(16);

    // 记录正在创建中的 bean（循环依赖检测）
    private final Set<String> singletonsCurrentlyInCreation = Collections.newSetFromMap(new ConcurrentHashMap<>(16));
}
```

### 2.2 三级缓存职责表

| 级 | 名称 | 存什么 | 什么时候用 |
|:---:|------|------|------|
| 一级 | singletonObjects | 完整单例（成品） | getBean 最终命中 |
| 二级 | earlySingletonObjects | 提前暴露的原始实例 | 循环依赖已发生、工厂已执行 |
| 三级 | singletonFactories | ObjectFactory（延迟工厂） | 循环依赖首次检测到、尚未执行 |

> 🎯 记忆锚点：**一级存成品、二级存半成品、三级存「怎么造半成品的工厂」**。三级是「延迟」，二级是「结果」。

## 3. 提前暴露机制：getEarlyBeanReference

### 3.1 何时暴露（addSingletonFactory）

```java
// AbstractAutowireCapableBeanFactory.doCreateBean
// 在 populateBean（属性填充）之前：
boolean earlySingletonExposure = (mbd.isSingleton() && this.allowCircularReferences
        && isSingletonCurrentlyInCreation(beanName));
if (earlySingletonExposure) {
    addSingletonFactory(beanName, () -> getEarlyBeanReference(beanName, mbd, bean));
    // 把「延迟决策工厂」放入三级缓存
}
```

```text
关键点：暴露的是 ObjectFactory（lambda），不是实例本身
  → 工厂何时执行？另一个 bean 依赖它且 getSingleton 发现三级缓存有货时
  → 工厂执行 = 调 getEarlyBeanReference
```

### 3.2 getEarlyBeanReference 源码

```java
protected Object getEarlyBeanReference(String beanName, RootBeanDefinition mbd, Object bean) {
    Object exposedObject = bean;
    // 遍历 SmartInstantiationAwareBeanPostProcessor：
    //   · AnnotationAwareAspectJAutoProxyCreator 是典型实现
    //   · 若匹配切点（@Transactional/@Aspect）→ 创建【提前代理】
    if (!mbd.isSynthetic() && hasInstantiationAwareBeanPostProcessors()) {
        for (SmartInstantiationAwareBeanPostProcessor bp : getBeanPostProcessorCache().smartInstantiationAware) {
            exposedObject = bp.getEarlyBeanReference(exposedObject, beanName);
        }
    }
    return exposedObject;   // 可能已变成代理
}
```

> 🎯 核心认知：**三级缓存 = 「要不要提前代理」的延迟决策**——循环依赖发生时才知道是否需要提前包装，避免所有 bean 无谓代理。

## 4. 完整解决流程推演

### 4.1 场景：A 依赖 B，B 依赖 A（字段注入）

```text
① 创建 A：getSingleton("a") 未命中 → createBean
   doCreateBean → addSingletonFactory("a", 工厂A)  ← A 进入三级缓存（原始实例）
   populateBean(A) 需要 B
② 创建 B：getSingleton("b") 未命中 → createBean
   doCreateBean → addSingletonFactory("b", 工厂B)
   populateBean(B) 需要 A
③ 获取 A：getSingleton("a", true) 允许早期引用
   → 一级无 → 二级无 → 三级有！
   → 执行工厂A → getEarlyBeanReference(A)（无切点则返回原始 A）
   → 结果放入二级缓存（earlySingletonObjects）
   → B 拿到 A 的早期引用，注入完成
④ B 完成初始化 → 一级缓存放入完整 B
⑤ 回到 A 的 populateBean：注入 B（完整 B）
⑥ A 完成初始化 → 初始化后处理器（无代理需求）→ 一级缓存放入 A
```

```text
最终结果：A、B 都在一级缓存；B 持有的 A 是「早期原始 A」
         若 A 需要代理 → 早期已生成代理 → B 拿到的也是代理（语义一致）
```

### 4.2 关键代码路径

```java
// getSingleton 的三级查找（DefaultSingletonBeanRegistry）
protected Object getSingleton(String beanName, boolean allowEarlyReference) {
    Object singletonObject = this.singletonObjects.get(beanName);        // 一级
    if (singletonObject == null && isSingletonCurrentlyInCreation(beanName)) {
        singletonObject = this.earlySingletonObjects.get(beanName);       // 二级
        if (singletonObject == null && allowEarlyReference) {
            synchronized (this.singletonObjects) {
                ObjectFactory<?> singletonFactory = this.singletonFactories.get(beanName); // 三级
                if (singletonFactory != null) {
                    singletonObject = singletonFactory.getObject();       // 执行工厂！
                    this.earlySingletonObjects.put(beanName, singletonObject);
                    this.singletonFactories.remove(beanName);
                }
            }
        }
    }
    return singletonObject;
}
```

> 💡 面试手绘：**三个 Map 的画法 + 箭头流转（一级查 → 二级查 → 三级执行 → 回填二级）**——画出来基本就过了。

## 5. 为什么三级缓存不能降级为二级

### 5.1 问题：二级缓存能解决循环依赖吗

```text
能解决「无代理」场景：提前把原始实例放二级即可
但有 AOP 代理需求时：
  方案一（提前代理所有 bean）：性能浪费——大多数 bean 无切点
  方案二（先放原始、后代理）：B 拿到的是【原始 A】，
    但 A 最终是【代理 A】→ B 注入的是不一致的原始对象 → 语义错误！
```

### 5.2 三级缓存的价值

```text
三级缓存 = 延迟决策「是否需要提前代理」
  · 无循环依赖：工厂永不执行，无代理开销
  · 有循环依赖 + 有切点：工厂执行时生成提前代理（getEarlyBeanReference）
  · 有循环依赖 + 无切点：工厂执行返回原始实例

结论：三级缓存把「要不要代理」的决策推迟到【真正需要早期引用时】，
      既保证循环依赖可用，又保证代理语义一致
```

> 🎯 面试必答：**「三级 vs 二级」的差别不在解决循环依赖（二级就够），而在 AOP 代理的一致性**——需要提前代理时三级工厂能生成代理，纯二级缓存做不到（要么过度代理要么语义不一致）。

## 6. @Async 循环依赖失效与解决方案

### 6.1 为什么 @Async 循环依赖报错

```text
@Async 代理（AsyncAnnotationBeanPostProcessor）是 BeanPostProcessor，
  走初始化后（afterInitialization）生成代理——没有提前代理能力
  （不实现 SmartInstantiationAwareBeanPostProcessor.getEarlyBeanReference）

→ 循环依赖时：
  B 拿到的是 A 的【原始实例】（三级工厂返回原始，因为无提前代理实现）
  但 A 初始化后会被替换为【@Async 代理】
  → initializeBean 最后检测：exposedObject != bean
    → 报错 BeanCurrentlyInCreationException / 校验失败
  （Spring 6.x+：直接抛异常「Bean currently in creation」类错误）
```

### 6.2 解决方案

| 方案 | 做法 | 评价 |
|------|------|------|
| 重构消除环 | 拆服务/事件解耦 | 最优 |
| 注入 ObjectProvider | 延迟获取，避开创建期依赖 | 简单可靠 |
| 加 @Lazy | 依赖侧懒加载代理 | 快速但延迟语义 |
| 注入自身（self 注入） | 解决「内部调用不走代理」 | 只解决 self 调用，不解决循环 |
| 提高循环依赖容忍 | `allowCircularReferences=false` 反而更糟 | 不建议 |

```java
// 推荐：ObjectProvider 延迟获取
@Service
public class A {
    @Autowired
    private ObjectProvider<B> bProvider;   // 需要时再 getIfAvailable()

    public void useB() {
        B b = bProvider.getIfAvailable();
        b.doSomething();
    }
}
```

> ⚠️ 面试提示：@Async + 循环依赖是「代理时机」问题的教科书案例——**普通 AOP（AnnotationAwareAspectJAutoProxyCreator）实现了提前代理，@Async 的后置处理器没有**，所以场景不同结果不同。

## 7. 高频追问汇总

| 问题 | 标准回答 |
|------|------|
| 循环依赖解决的前提？ | 单例 + 非构造器注入（字段/Setter） |
| 三级缓存各存什么？ | 成品 / 半成品 / ObjectFactory |
| 为什么三级不是二级？ | AOP 代理一致性 + 延迟决策避免过度代理 |
| 构造器循环依赖能解决吗？ | 不能——创建实例本身需要对方，无法提前暴露 |
| 原型 bean 循环依赖？ | 不能——原型不缓存 |
| @Async 为什么失效？ | 代理后置处理器无提前代理能力，暴露的是原始对象 |
| 解决 @Async 循环依赖？ | ObjectProvider / @Lazy / 重构消除环 |
| allowCircularReferences 关掉会怎样？ | 所有循环依赖直接报错（Boot 默认开启，可关） |

> 🎯 **核心要点**：循环依赖机制一句话 = **「单例创建时先把『原始实例工厂』放三级缓存，对方需要时执行工厂（可能提前代理）得到半成品，回填二级，最终双方都拿到一致对象」**。面试三问必背：三级缓存职责、二级降级不行（AOP 一致性）、@Async 失效（代理时机不同）。Spring 7.0 该机制保持稳定（2026 现状），是新特性介绍中的「核心机制不变」部分。
