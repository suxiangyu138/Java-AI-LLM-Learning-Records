## 1. 认证机制全景对比

| 机制 | 凭据形态 | 适用场景 | 7.0 状态 |
|------|---------|---------|:---:|
| 表单登录 | 用户名+密码（Session） | Web 应用、有状态场景 | ✅ 默认 |
| HTTP Basic | `Authorization: Basic base64(u:p)` | 简单 API/内部工具 | ✅ |
| Remember-Me | 持久化 Cookie 令牌 | 登录状态保持 | ✅ |
| JWT Bearer | `Authorization: Bearer <jwt>` | 无状态 API | ✅（08 篇） |
| OAuth2 登录 | 授权码换令牌 | 三方/企业 SSO | ✅（07 篇） |
| 证书 X.509 | 客户端证书 | 机器认证 | ✅ |
| Passkey/WebAuthn | FIDO2 设备凭据 | 无密码登录 | ✅ 7.0 一等公民 |

> 🎯 **要点**：认证机制 = 凭据形式 + 校验策略的组合。Spring Security 用 `AuthenticationProvider` 抽象校验策略，用 `AuthenticationManager` 调度多个 Provider——**加一种认证方式 = 加一个 Provider**。

## 2. 表单登录：UsernamePasswordAuthenticationFilter

### 2.1 处理流程

```text
POST /login (username, password)
  → UsernamePasswordAuthenticationFilter
  → UsernamePasswordAuthenticationToken（未认证）
  → AuthenticationManager.authenticate()
  → DaoAuthenticationProvider
      ├── UserDetailsService.loadUserByUsername()  查用户（DB/LDAP/内存）
      └── PasswordEncoder.matches()               校验密码
  → 成功：SecurityContext 写入已认证 Authentication
  → 失败：AuthenticationException → ExceptionTranslationFilter → 重定向登录页
```

### 2.2 配置与定制

```java
http
    .formLogin(form -> form
        .loginPage("/custom-login")               // 自定义登录页（返回 HTML）
        .loginProcessingUrl("/do-login")          // 表单提交地址
        .usernameParameter("account")             // 参数名定制
        .passwordParameter("pwd")
        .defaultSuccessUrl("/home", true)         // 登录成功跳转
        .failureUrl("/login?error=true"));        // 失败跳转
```

> ⚠️ **CSRF 联动**：Boot 4 默认开启 CSRF，登录表单**必须携带 CSRF 令牌**（Thymeleaf 模板 `th:action` + `csrf` 隐藏域自动注入）。前端手写 fetch 登录常因缺令牌 403——见 05 篇。

### 2.3 无状态 API 的表单认证（登录即 JSON）

```java
http
    .formLogin(form -> form
        .successHandler((req, res, auth) -> {        // 成功返回 JSON 而非跳转
            res.setContentType("application/json;charset=UTF-8");
            res.getWriter().write("{\"code\":0,\"msg\":\"ok\"}");
        })
        .failureHandler((req, res, exc) -> {          // 失败返回 JSON
            res.setStatus(401);
            res.getWriter().write("{\"code\":401,\"msg\":\"bad credentials\"}");
        }))
    .exceptionHandling(ex -> ex
        .authenticationEntryPoint((req, res, exc) -> { // 未认证访问 → 401 JSON 而非重定向
            res.setStatus(401);
            res.getWriter().write("{\"code\":401,\"msg\":\"unauthenticated\"}");
        }));
```

## 3. HTTP Basic 与客户端认证

```java
http.httpBasic(basic -> basic.realmName("demo"));   // 开启 Basic

// 请求侧：curl -u admin:123456  /  Authorization: Basic YWRtaW46MTIzNDU2
```

| 要点 | 说明 |
|------|------|
| 传输安全 | Base64 **不是加密**，必须配 HTTPS，否则密码明文裸奔 |
| 无状态 | 每次请求都带凭据，天然适合简单 API |
| 适用边界 | 内部工具、CI 回调、压测脚本；不适用面向用户的正式产品 |

## 4. PasswordEncoder：密码存储的演进

### 4.1 演进路线：为什么一代代换

| 编码器 | 算法 | 特征 | 状态 |
|--------|------|------|:---:|
| `PlaintextPasswordEncoder` | 明文 | 灾难 | ❌ 远古 |
| `Md5PasswordEncoder` | MD5 | 可彩虹表秒破 | ❌ 远古 |
| `SHA-256` | 单向散列 | 无盐、可并行破解 | ❌ |
| `BCryptPasswordEncoder` | Blowfish 变体 | 内置盐、自适应强度、**单次慢** | ✅ 广泛使用 |
| `SCryptPasswordEncoder` | scrypt | 抗 GPU/ASIC，**内存密集** | ✅ |
| `Pbkdf2PasswordEncoder` | PBKDF2 | 标准 HMAC 迭代 | ✅ |
| `Argon2PasswordEncoder` | Argon2id | **内存+CPU 双密集**，密码竞赛冠军 | ✅ **7.0 推荐默认** |

### 4.2 7.0 的 Password4j 支持

7.0 引入 Password4j 库支持（Argon2/BCrypt/SCrypt/PBKDF2/Balloon），官方推荐默认：

```java
// 7.0 推荐：Argon2（OOM 级防暴力破解）
PasswordEncoder encoder = Argon2PasswordEncoder.defaultsForSpring7();

// 经典选择：BCrypt（兼容性与性能均衡，绝大多数生产现状）
PasswordEncoder bcrypt = new BCryptPasswordEncoder(12);   // strength=12 成本因子

// 多算法并存：{id} 前缀自动路由（迁移期神器）
PasswordEncoder delegating = PasswordEncoderFactories.createDelegatingPasswordEncoder();
// 存值形如：{bcrypt}$2a$12$...  {argon2}$argon2id$...  {noop}123456
```

| 关键点 | 说明 |
|--------|------|
| `{id} 前缀` | DelegatingPasswordEncoder 按前缀路由校验算法，**支持存量数据渐进迁移** |
| BCrypt strength | 越高越慢越安全（10-14 合理区间），7.0 默认 10 |
| 验证时机 | 登录校验 = `matches(明文, 密文)`，**永不 reverse**（不可逆） |
| 迁移策略 | 旧 MD5 库升级：Delegating + 登录成功时用新算法重写密文 |

> 💡 **面试必答**：为什么 MD5 不行？——无盐 + 计算快，彩虹表与 GPU 并行秒破。BCrypt 为什么好？——内置随机盐（相同密码不同密文）+ 自适应成本因子（硬件升级可调参）。Argon2 为什么更好？——内存密集抗 GPU/ASIC，是 2015 密码哈希竞赛冠军，7.0 默认推荐。

### 4.3 密码存储最佳实践

- 新系统直接用 `Argon2PasswordEncoder.defaultsForSpring7()`；
- 存量 BCrypt 不必强迁，`DelegatingPasswordEncoder` 兼容并存；
- **永不自定义加密算法**（`new MyHash()`），安全编码的底线是"使用经过竞赛验证的标准算法"；
- 强度参数随硬件定期上调（BCrypt 12 → 14）。

## 5. 7.0 原生 MFA 多因素认证

MFA（多因素认证）是被请求了 12 年的特性，7.0 正式原生支持——**核心类是 `FactorGrantedAuthority`**（记录"哪个因素、何时验证"），开箱可配：

```java
// 1. 开启 MFA（Authentication.Builder 驱动）
@Bean
public AuthenticationManager authenticationManager(AuthenticationConfiguration config) throws Exception {
    AuthenticationManager am = config.getAuthenticationManager();
    return new MultiFactorAuthenticationManager.Builder(am)
            .withFactor(new TimeBasedOneTimePasswordFactor(TotpSecretRepository.defaults()))
            .build();
}
```

```java
// 2. 站点级强制 / 端点级 / 定时复验
@Bean
SecurityFilterChain chain(HttpSecurity http) throws Exception {
    http
        .formLogin(Customizer.withDefaults())
        .authorizeHttpRequests(auth -> auth
            .requestMatchers("/api/settings/**")
                .access(new AllRequiredFactorsAuthorizationManager())   // 端点级：要求全部因素
            .anyRequest().authenticated());
    return http.build();
}
```

| MFA 能力 | 说明 |
|---------|------|
| `FactorGrantedAuthority` | 记录认证使用了哪个因素、何时使用（可做"1 小时前验证过 TOTP，本操作免再验"） |
| `AllRequiredFactorsAuthorizationManager` | 要求全部因素都通过才授权 |
| `Authentication.Builder` | 链式构建多因素认证结果 |
| TOTP 因子 | 时间基一次性密码（Google Authenticator 同族） |
| 时间性复验规则 | 支持"敏感操作重新验证"策略 |

> 🎯 **面试点**：7.0 三大卖点之一就是原生 MFA。答"7.0 新特性"时列出：原生 MFA（FactorGrantedAuthority）、模块化配置（Customizer Bean）、授权服务器并入核心、PKCE 默认、Password4j——每一条都能展开讲，就是满分。

## 6. UserDetailsService 与自定义认证源

### 6.1 标准接入点

```java
@Service
public class JdbcUserService implements UserDetailsService {

    @Resource
    private UserMapper userMapper;

    @Override
    public UserDetails loadUserByUsername(String username) throws UsernameNotFoundException {
        UserEntity user = userMapper.findByUsername(username);
        if (user == null) throw new UsernameNotFoundException("用户不存在");
        return org.springframework.security.core.userdetails.User
                .withUsername(user.getUsername())
                .password(user.getPassword())          // 密文（BCrypt/Argon2）
                .roles(user.getRoles().split(","))     // 角色（自动加 ROLE_ 前缀）
                .disabled(!user.getEnabled())
                .build();
    }
}
```

### 6.2 认证流程中的扩展点

| 扩展点 | 用途 |
|--------|------|
| `UserDetailsService` | 查询用户（最常用） |
| `UserDetails` | 自定义用户模型（扩展字段） |
| `AuthenticationProvider` | 自定义校验逻辑（如验证码、短信） |
| `AuthenticationSuccessHandler` | 登录成功后的行为 |
| `AuthenticationFailureHandler` | 登录失败后的行为（如错误计数） |

> ⚠️ **注意**：只自定义 `UserDetailsService` 时，密码校验仍由 `DaoAuthenticationProvider` 完成（走 PasswordEncoder）；想要"验证码登录""短信登录"等全新认证方式，需要自定义 `AuthenticationProvider` 甚至 `AuthenticationFilter`。

## 7. 认证漏洞与防护清单

| 漏洞/风险 | 危害 | 防护 |
|----------|------|------|
| 明文密码传输 | 中间人窃取 | 必须 HTTPS |
| 弱密码哈希 | 数据库泄露即全库可破 | Argon2/BCrypt + 高成本因子 |
| 用户枚举 | 反馈"用户不存在"泄露注册信息 | 统一错误文案 |
| 暴力破解 | 无限尝试 | 登录限流/锁定（配合 Redis 计数，见 Spring Data Redis 体系 04 篇） |
| 会话固定 | 攻击者预置会话 ID 钓鱼 | 7.0 默认 `changeSessionId` 防固定 |
| 开放重定向 | 登录后跳转钓鱼站 | 白名单校验 `defaultSuccessUrl` 目标 |
| 明文存储默认值 | 演示配置上生产 | `{noop}` 仅限演示；生产删除默认用户 |

> 🎯 **核心要点**：认证机制的选择 = 凭据形态 + 场景匹配（Web 用表单、API 用 Basic/JWT、企业级用 OAuth2）；密码存储的红线是"标准算法 + 自适应强度 + 不可逆"（Argon2 是 7.0 默认答案）；MFA 是 7.0 的原生卖点，FactorGrantedAuthority 记录因素使用历史让"敏感操作复验"成为一行配置。
