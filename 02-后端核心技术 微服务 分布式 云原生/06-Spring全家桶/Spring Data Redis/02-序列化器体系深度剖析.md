## 1. 序列化器抽象与整体家族

Redis 只存字节（RESP 协议层面 key/value 都是 bulk string），Java 对象入库前必须转字节，取回时再还原——这就是 `RedisSerializer<T>` 的职责：

```java
public interface RedisSerializer<T> {
    byte[] serialize(T t) throws SerializationException;
    T deserialize(byte[] bytes) throws SerializationException;
}
```

**家族全景（Spring Data Redis 4.x）：**

```text
RedisSerializer<T>
├── StringRedisSerializer          UTF-8 字符串（key 首选）
├── GenericToStringSerializer<T>   通过 ConversionService 转 String 再 UTF-8
├── JdkSerializationRedisSerializer  JDK ObjectOutputStream（默认值，陷阱之源）
├── Jackson2JsonRedisSerializer<T>  Jackson 2 + 显式类型（deprecated 于 4.0）
│   └── JacksonJsonRedisSerializer<T>（4.0 新，Jackson 3）
├── GenericJackson2JsonRedisSerializer  Jackson 2 + 默认类型 @class（deprecated 于 4.0）
│   └── GenericJacksonJsonRedisSerializer（4.0 新，Jackson 3）
├── OxmSerializer                    XML 序列化
├── ProtobufSerializer               Protobuf 序列化
└── 自定义实现                      implements RedisSerializer<T>
```

**RedisTemplate 四个槽位，可分别指定：**

```java
template.setKeySerializer(ks);          // key 序列化
template.setValueSerializer(vs);        // value 序列化
template.setHashKeySerializer(hks);     // hash 域(field)序列化
template.setHashValueSerializer(hvs);   // hash 值序列化
```

> 💡 不设置时默认全用 `JdkSerializationRedisSerializer`（RedisTemplate 与 StringRedisTemplate 除外，后者全用 String）。**默认即陷阱**——几乎每个 Spring Data Redis 新手都会在第一个 demo 里看到 `\xac\xed\x00\x05t\x00...`。

## 2. JDK 序列化：默认值的三大陷阱

### 陷阱一：可读性灾难

```
redis-cli> GET user:1001
"\xac\xed\x00\x05t\x00\x0fuser:1001"      # key 是乱码
"\xac\xed\x00\x05sr\x00\x1dcom.demo.User..."  # value 是二进制垃圾
```

- 无法在 redis-cli / 可视化工具中阅读与调试；
- 无法与其它语言/工具（Python、Node、redis-cli 脚本）互操作；
- key 带 `\xac\xed` 头，`KEYS user:*` 通配匹配全部失效。

### 陷阱二：兼容性灾难

JDK 序列化要求目标类实现 `Serializable`，且 `serialVersionUID` 一致。**类字段一改（增删字段），旧数据直接反序列化失败**——线上最经典的"改了个字段，缓存全挂"事故。

### 陷阱三：性能与体积

| 对比项 | JDK 序列化 | JSON 序列化 |
|--------|:---:|:---:|
| 字节体积 | 约 2-4 倍膨胀（含类元数据） | 1 倍基准 |
| 序列化速度 | 慢（反射 + 对象图遍历） | 快 |
| 网络/RDB 成本 | 高 | 低 |

> 🎯 **结论**：生产环境务必替换默认序列化器。key 一律 `StringRedisSerializer`，value 用 JSON 或二进制协议（如 Protobuf/Kryo 需自建）。

## 3. String 序列化器

```java
StringRedisSerializer stringSerializer = StringRedisSerializer.UTF_8;  // 常量，直接复用
```

**特点：**
- 使用 `StandardCharsets.UTF_8` 编解码，字节就是可读字符串；
- 线程安全、无状态，可单例共享（4.x 提供 `UTF_8` 常量，旧版 `new StringRedisSerializer()` 亦可）；
- **天然适合 key**：业务 key 本来就是字符串（`user:1001`、`order:20260807:10086`）。

> ⚠️ **注意**：若 value 也用 String 序列化器，则只能存字符串（数值、JSON 串、布尔需自行转换）——这正是 StringRedisTemplate 的场景（见 04 篇）。

## 4. Jackson 序列化器：2 → 3 迁移与新命名

### 4.1 版本对应关系（2026 年现状）

Spring Boot 3.x / Spring Data Redis 3.x 内置 Jackson 2（`com.fasterxml.jackson.databind`）；**Spring Boot 4.x / Spring Data Redis 4.x 内置 Jackson 3（`tools.jackson.databind`）**，序列化器同步改名：

| Jackson 2 时代（3.x） | Jackson 3 时代（4.x，2026） | 状态 |
|----------------------|--------------------------|------|
| `Jackson2JsonRedisSerializer<T>` | `JacksonJsonRedisSerializer<T>` | 旧名 deprecated |
| `GenericJackson2JsonRedisSerializer` | `GenericJacksonJsonRedisSerializer` | 旧名 deprecated |
| `Jackson2ObjectReader` / `Jackson2ObjectWriter` | `JacksonObjectReader` / `JacksonObjectWriter` | 旧名 deprecated |

> ⚠️ **迁移注意**：Spring Boot 4 项目里写 `new GenericJackson2JsonRedisSerializer()` 仍可编译（deprecated 而非删除），但新的 Jackson 3 `ObjectMapper`（`tools.jackson.databind.JsonMapper`）**无法传入旧构造器**——升级时要么换新类，要么保留 Jackson 2 依赖。新代码一律用新命名。

### 4.2 两类 Jackson 序列化器：显式类型 vs 默认类型

**① `JacksonJsonRedisSerializer<T>`（显式类型）：**

```java
JacksonJsonRedisSerializer<User> serializer =
        new JacksonJsonRedisSerializer<>(User.class);   // 构造时指定类型
```

- 序列化不含类型信息，体积小、可读性好；
- 反序列化依赖构造时固定的 `User.class`；
- **只适合单一类型**——多态（存 `User` 又存 `Order` 到同一 value 槽）会直接失败。

**② `GenericJacksonJsonRedisSerializer`（默认类型 + `@class` 提示）：**

```java
GenericJacksonJsonRedisSerializer serializer = new GenericJacksonJsonRedisSerializer();
```

- 通过 Jackson 默认类型（default typing）在 JSON 中写入 `@class` 字段：

```json
{"@class": "com.demo.User", "id": 1001, "name": "张三"}
```

- 反序列化无需显式类型，多态安全；
- **代价**：体积增大、`@class` 是类路径明文（注意类名混淆/重命名导致的历史数据失效）、反序列化有反序列化安全约束（默认类型校验）。

### 4.3 自定义 ObjectMapper（Jackson 3 写法）

```java
import tools.jackson.databind.DeserializationFeature;
import tools.jackson.databind.JsonMapper;
import tools.jackson.databind.ObjectMapper;
import tools.jackson.databind.jsontype.BasicPolymorphicTypeValidator;
import tools.jackson.databind.jsontype.DefaultTypeResolverBuilder;
import tools.jackson.databind.jsontype.DefaultTyping;
import tools.jackson.databind.jsontype.impl.LaissezFaireSubTypeValidator;

ObjectMapper mapper = JsonMapper.builder()
        .activateDefaultTyping(BasicPolymorphicTypeValidator.builder()
                        .allowIfSubType(Object.class).build(),
                DefaultTyping.NON_FINAL, JsonTypeInfo.As.PROPERTY)
        .configure(DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES, false)
        .build();

GenericJacksonJsonRedisSerializer serializer = new GenericJacksonJsonRedisSerializer(mapper);
```

> 💡 **典型报错**：Jackson 3 迁移后最常见的 `SerializationException: ... missing type id property '@class'`——根因就是未激活 default typing。对照上述 builder 补齐即可。

### 4.4 Builder 家族（3.3.1+，4.x 延续）

```java
GenericJacksonJsonRedisSerializer serializer = GenericJacksonJsonRedisSerializer.builder()
        .defaultTyping(true)                  // 是否写 @class
        .typeHintPropertyName("@class")       // 类型提示字段名
        .objectMapper(mapper)                 // 自定义 mapper
        .registerNullValueSerializer(false)   // null 是否注册处理
        .build();
```

## 5. 自定义序列化器

内置不够时自己实现——典型场景：Protobuf、Kryo、MessagePack、压缩 JSON：

```java
public class GzipJsonRedisSerializer implements RedisSerializer<Object> {

    private final GenericJacksonJsonRedisSerializer json =
            new GenericJacksonJsonRedisSerializer();

    @Override
    public byte[] serialize(Object value) {
        byte[] plain = json.serialize(value);
        if (plain == null) return null;
        return gzip(plain);          // 压缩：大数据 value 可省 70%+ 空间
    }

    @Override
    public Object deserialize(byte[] bytes) {
        if (bytes == null) return null;
        return json.deserialize(ungzip(bytes));
    }
}
```

**实现要点：**
- `serialize(null)` 必须返回 null（框架据此跳过写入）；
- `deserialize(null/空数组)` 必须返回 null；
- 保持无状态（线程安全），避免把 ObjectMapper 每次 new；
- 序列化/反序列化必须对称——换了算法，Redis 里的旧数据全废（可先换 key 前缀做灰度）。

## 6. key/value 双序列化设计

**黄金法则：key 用 String，value 用 JSON（或按类型策略）。**

```java
RedisTemplate<String, Object> template = new RedisTemplate<>();
template.setConnectionFactory(factory);

// key 层：String
template.setKeySerializer(StringRedisSerializer.UTF_8);
template.setHashKeySerializer(StringRedisSerializer.UTF_8);

// value 层：JSON + @class（多态安全）
GenericJacksonJsonRedisSerializer json = new GenericJacksonJsonRedisSerializer();
template.setValueSerializer(json);
template.setHashValueSerializer(json);
```

**为什么 key 必须 String：**
- 可读性：`user:1001` 一目了然，`\xac\xed...` 无法运维；
- 模式匹配：`KEYS user:*`、SCAN 通配、延迟任务 ZSet 排序都依赖可读 key；
- 幂等性：同一个 key 若被不同序列化器写过，会形成**语义相同、字节不同**的双份数据。

**value 策略选型：**

| 数据类型 | 推荐序列化 | 理由 |
|---------|-----------|------|
| 字符串/数值 | String 或 JSON | 简单直接 |
| 单一 POJO | `JacksonJsonRedisSerializer<T>` | 体积小、类型明确 |
| 多种 POJO/多态 | `GenericJacksonJsonRedisSerializer` | @class 兜底多态 |
| 二进制/大文件 | 自定义（Protobuf/压缩） | 体积与性能最优 |
| 不要求可读 | Protobuf/Kryo | 极致性能 |

## 7. 序列化选型对照表

| 序列化器 | 可读性 | 体积 | 多态 | 性能 | 适用场景 | 4.x 状态 |
|---------|:---:|:---:|:---:|:---:|---------|:---:|
| JdkSerializationRedisSerializer | ❌ | ❌ | ✅ | ❌ | 仅默认兜底 | ✅（不推荐） |
| StringRedisSerializer | ✅ | ✅ | ❌ | ✅ | key、纯字符串 value | ✅ |
| JacksonJsonRedisSerializer | ✅ | ✅ | ❌ | ✅ | 单一类型 POJO | ✅（新命名） |
| GenericJacksonJsonRedisSerializer | ✅ | 中 | ✅ | 中 | 多态 value | ✅（新命名） |
| ProtobufSerializer | ❌ | ✅ | ✅ | ✅ | 高性能二进制 | ✅ |
| 自定义 | 由实现决定 | 由实现决定 | 由实现决定 | 由实现决定 | 压缩/加密/专用协议 | ✅ |

## 8. 踩坑手册与排查流程

| 现象 | 根因 | 处理 |
|------|------|------|
| key 变 `\xac\xed` 乱码 | key 用了默认 JDK 序列化 | key 一律 String 序列化器 |
| value 是乱码 | value 默认 JDK 序列化 | 换 JSON 序列化器，**旧数据需清掉或换前缀** |
| `ClassCastException`（反序列化后类型不对） | 泛型擦除 + 无类型信息 | 用 Generic 带 @class，或显式类型构造器 |
| Jackson 3 报 missing type id `@class` | 默认类型未激活 | `activateDefaultTyping(...)` 补齐 |
| 改了字段后缓存反序列化失败 | JDK 序列化兼容性差 / JSON 缺字段容错 | JSON + `FAIL_ON_UNKNOWN_PROPERTIES=false` |
| 历史数据与旧类绑定 | 类包名/类名变更 | 灰度换 key 前缀，双写迁移 |
| 多态数据存进显式类型序列化器 | 类型不匹配 | 换 Generic 系列 |

**排查流程四步：**

```text
1. redis-cli 看原始字节 → 判断是哪种序列化产物（\xac\xed=JDK，{...}=JSON，明文=String）
2. 检查 RedisTemplate 四个槽位的序列化器配置
3. 确认 key 与 value 是否混用了不同序列化器写同一 key
4. 反序列化报错时看异常里缺失的字段/类型 → 对应修 ObjectMapper 或换序列化器
```

> 🎯 **核心要点**：序列化决策 = 可读性 × 兼容性 × 体积 × 性能的权衡。生产基线：**key 用 String、value 用 Generic Jackson（多态兜底）、显式类型序列化器用于单一类型、JDK 序列化器只准出现在面试题里**。Spring Data Redis 4.x 记得用 Jackson 3 新命名，并配置好 default typing。
