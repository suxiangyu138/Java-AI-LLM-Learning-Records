## 1. 测试工具链：spring-boot-starter-batch-test

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-batch-test</artifactId>
    <scope>test</scope>
</dependency>
```

### 1.1 核心组件

| 组件 | 6.0 名称（旧名） | 作用 |
|------|-----------------|------|
| 启动执行工具 | `JobOperatorTestUtils`（旧 `JobLauncherTestUtils`） | 在测试中启动/重启 Job |
| 元数据清理 | `JobRepositoryTestUtils` | 清空 BATCH_* 表，保证测试隔离 |
| 上下文注解 | `@SpringBatchTest` | 自动注入测试工具 Bean，开启事务回滚语义 |
| 输出捕获 | `JobScopeTestExecutionListener` / `StepScopeTestExecutionListener` | 在测试中模拟 Step/Job scope 属性解析 |

### 1.2 端到端 Job 测试

```java
@SpringBatchTest
@SpringBootTest(properties = "spring.batch.job.enabled=false")
class OrderImportJobTests {

    @Autowired JobOperatorTestUtils jobOperatorTestUtils;
    @Autowired JobRepositoryTestUtils jobRepositoryTestUtils;

    @BeforeEach
    void cleanUp() {
        jobRepositoryTestUtils.removeJobExecutions();   // 清理元数据
    }

    @Test
    void importsCsvAndWritesDb() throws Exception {
        JobParameters params = new JobParametersBuilder()
                .addString("input.file", "classpath:testdata/orders.csv")
                .toJobParameters();

        JobExecution execution = jobOperatorTestUtils.launchJob(params);

        assertThat(execution.getStatus()).isEqualTo(BatchStatus.COMPLETED);
        assertThat(execution.getExitStatus().getExitCode()).isEqualTo("COMPLETED");
        assertThat(orderRepository.count()).isEqualTo(3);          // 业务断言
        assertThat(execution.getStepExecutions())
                .extracting(StepExecution::getReadCount).contains(3);
    }

    @Test
    void skipsBadRows() throws Exception {
        JobExecution execution = jobOperatorTestUtils.launchJob(badDataParams());
        assertThat(execution.getStatus()).isEqualTo(BatchStatus.COMPLETED);
        assertThat(totalSkips(execution)).isEqualTo(1);            // 容错断言
    }
}
```

> ⚠️ 注意：`@SpringBatchTest` 场景下 Job 测试会真实写库（建议 H2 内存库 + `spring.batch.jdbc.initialize-schema=always`）；要验证"重启续跑"行为，**必须**用真实（或内存）数据库而非 Resourceless 仓库。

## 2. 四层测试模式

| 层级 | 测什么 | 工具 | 目标 |
|------|--------|------|------|
| 单元 | FieldSetMapper、Processor、Validator、自定义 reader/writer | 直接 new + 断言 | 业务逻辑纯测，不启动容器 |
| 集成 | reader/writer 与真实数据源 | Spring Boot 测试 + 测试库 | 映射、SQL、序列化正确性 |
| 作业 | 完整 Job 端到端（含流程分支） | JobOperatorTestUtils + @SpringBatchTest | 状态机、容错、参数语义 |
| 回归 | 重启续跑、skip 上限、并发分区 | 针对性参数化测试 | 工程级保障 |

单元级示例（最常用）：

```java
@Test
void parsesDelimitedLine() {
    DefaultLineMapper<Order> mapper = new DefaultLineMapper<>();
    mapper.setLineTokenizer(new DelimitedLineTokenizer("id,customerId,amount"));
    mapper.setFieldSetMapper(new OrderFieldSetMapper());
    Order order = mapper.mapLine("1,1001,99.5", 1);
    assertThat(order.getAmount()).isEqualByComparingTo("99.5");
}
```

> 💡 测试批次：把"文件头、空行、坏行、多字节字符、文件末尾无换行"全部纳入 reader 测试用例——批处理生产故障一半出在边界输入。

## 3. 生产黄金实践

| # | 实践 | 理由 |
|---|------|------|
| 1 | Job 名 + 参数**可追溯**（input.file、业务日期进 JobParameters） | 实例身份、审计、对账的基础 |
| 2 | 幂等写入（唯一键 / ON DUPLICATE KEY / 先删后插） | 重启重放安全（模块 06） |
| 3 | Skip 必配审计监听器落表 | 数据质量报告 + 故障定位 |
| 4 | 元数据与业务库分离（batchDataSource） | 避免事务与状态相互污染（模块 02） |
| 5 | `spring.batch.job.enabled=false` + 显式触发 | 防止意外自动跑库里的 Job Bean |
| 6 | 临时文件策略：写临时文件 → 成功后原子 rename | 文件写入无事务，避免半成品被下游消费 |
| 7 | 资源清理：reader/writer close 的兜底（@StepScope + afterStep 钩子） | 连接/流泄漏是长跑 Job 的慢性病 |
| 8 | 运行中防重入（JobExplorer 查询 + 唯一约束） | 调度重复触发安全（模块 08） |
| 9 | 结构化日志 + executionId 入 MDC | 分布式排障链路 |
| 10 | 数据量变化告警（读条数 vs 业务预期范围） | 静默少数据比失败更危险 |

## 4. 性能调优清单

按投入产出排序：

1. **commit-interval 匹配写入方式**：JDBC batch 500~2000；文件 1000~5000；重 processor 100~500（实测为准）；
2. **JDBC fetchSize**：Oracle/PostgreSQL 游标 reader 必须设（默认 10 会极慢）；
3. **批量写**：MySQL `rewriteBatchedStatements=true`、JpaItemWriter `usePersist(true)`（模块 05）；
4. **分页 reader 排序键**：必须唯一稳定（主键优先），深翻页改游标分页；
5. **索引**：按模块 02 的查询模式建元数据索引；业务侧查询 SQL 走索引；
6. **并行**：先本地分区再远程（模块 07 阶梯），别过早上分布式；
7. **内存**：Paging reader 的 pageSize 与 chunk 匹配，避免两倍放大；观察 GC；
8. **IO**：文件读取缓冲区、压缩文件（gzip）按需。

性能基线参考（单 JVM、普通硬件）：JDBC 批量插入 5k~50k 行/s 量级；CSV 读 10万~50万 行/s 量级——偏离一个数量级先查 fetchSize/批处理/索引。

## 5. 常见故障排查手册

| 症状 | 根因 | 排查/修复 |
|------|------|----------|
| `OptimisticLockingFailureException` | 并发修改同一执行记录（重复启动/stop 竞态） | 启动前检查运行中状态；重试操作 |
| 重启报"参数不兼容/实例已存在" | JobParameters 序列化格式变化（v5→v6）；或同参数已 COMPLETED 未 allowStartIfComplete | 迁移前重启 v5 失败实例；检查 startLimit/allowStartIfComplete |
| `ScopeNotActiveException` + @StepScope | 6.0.4 之前 + 本地 chunking 组合的缺陷 | 升级 6.0.4+ |
| 提交后数据缺失 | writer `assertUpdates(false)` 静默 0 行 | 开启 assertUpdates 校验 |
| Step 卡死无进展 | 游标 reader 连接被占 / 长事务 | 检查 fetchSize 与事务超时；看元数据 LAST_UPDATED |
| 重启后重复写入 | 写入无幂等键 | 按模块 05/06 补幂等设计 |
| JSON 文件 append 后结构损坏 | 6.0.4 前 JsonFileItemWriter 缺陷 | 升级；或临时文件 + 合并 |
| 远程分区无 worker 执行 | worker 没注册 StepLocator / 通道不共享 | 检查 BeanFactoryStepLocator 与通道绑定 |
| 多线程 Step 丢数据 | reader 非线程安全共享 | 换 Paging reader / Synchronized 包装（模块 07） |
| 6.0 指标不输出 | 未提供 ObservationRegistry Bean | 显式配置（模块 08） |

## 6. 5.x → 6.0 迁移清单

按模块索引汇总（官方迁移指南 + 6.0.4 公告交叉核对）：

| 域 | 5.x | 6.0 | 模块 |
|----|-----|-----|------|
| 配置 | `@EnableBatchProcessing(dataSourceRef=...)` | 拆分为 `@EnableJdbcJobRepository(dataSourceRef=...)` | 02 |
| 默认行为 | 需数据库 | Resourceless 默认；无事务管理器回退 ResourcelessTransactionManager | 02 |
| Chunk API | `.chunk(n, txManager)` | `.chunk(n).transactionManager(txManager)` / ChunkOrientedStepBuilder | 03 |
| 工厂 | JobBuilderFactory / StepBuilderFactory（已移除） | `new JobBuilder(name, jobRepository)` 构造注入 | 03 |
| Retry | Spring Retry | Spring Framework 7 内置 Retry | 06 |
| 并发 | throttleLimit（已移除） | 生产者-消费者有界队列 | 07 |
| 运维 | SimpleJobOperator / CommandLineJobRunner | TaskExecutorJobOperator / CommandLineJobOperator | 08 |
| 改名 | JobRepositoryFactoryBean / JobExplorerFactoryBean / JobLauncherTestUtils / ChunkHandler | JdbcJobRepositoryFactoryBean / JdbcJobExplorerFactoryBean / JobOperatorTestUtils / ChunkRequestHandler | 02/09 |
| 包 | core.explore、分散 listener | core.repository.explore、core.listener、core.repository.dao.jdbc|mongo | 01 |
| 数据库 | BATCH_JOB_SEQ | BATCH_JOB_INSTANCE_SEQ（迁移脚本） | 02 |
| 数据 | v5 FAILED 实例 | **无法用 v6 重启**，先 restart 或 abandon | 01 |
| JSON | Jackson 2（Jackson2* 工件） | Jackson 3 | 04/05 |
| 观测 | Micrometer 全局注册表 | 显式 ObservationRegistry | 08 |
| 移除 | JSR-352、Mongo/Neo4j reader/writer、JobRegistryBeanPostProcessor、listener 支持类、XML namespace（废弃） | — | 全域 |

**迁移顺序建议**：先读 01（模型变化）→ 02（配置与库）→ 改代码编译（包/构造器）→ 修 chunk/容错配置 → 验证重启与指标 → 上生产前跑迁移脚本。

---

> 🎯 **核心要点**：测试层从单元到端到端四层覆盖，JobOperatorTestUtils + @SpringBatchTest 是标准武器；生产实践的十条黄金法则里"幂等 + 审计 + 元数据分离"是命门；故障排查要会看元数据表定位（LAST_UPDATED、skip 计数、乐观锁异常）；迁移 5→6 最痛的三件事：构造注入 API、包改名、v5 失败实例兼容。
