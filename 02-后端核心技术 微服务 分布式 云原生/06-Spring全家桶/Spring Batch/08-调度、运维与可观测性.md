## 1. 启动方式全景：JobLauncher / JobOperator / CLI

### 1.1 接口关系（6.0 继承重构）

```text
JobLauncher（同步启动入口）
   start(job, parameters) → JobExecution
        ▲
JobOperator（运维入口：start/stop/restart/recover/abandon）
   ▲                          ▲
TaskExecutorJobOperator     CommandLineJobOperator（6.0 新增，替代 CommandLineJobRunner）
```

6.0 起 **JobOperator extends JobLauncher**——一个接口同时具备"启动"与"运维"能力；`SimpleJobOperator` 改名为 **`TaskExecutorJobOperator`**（按默认 TaskExecutor 异步执行）。

### 1.2 Boot 4 自动启动与手动启动

| 方式 | 配置 | 适用 |
|------|------|------|
| Boot 自动启动 | `spring.batch.job.enabled=true`（默认）启动时运行所有 Job Bean；`spring.batch.job.name=job1,job2` 指定 | 单 Job 简单场景 |
| 手动启动（推荐生产） | `spring.batch.job.enabled=false` + 代码里注入 JobLauncher | Web 平台触发、参数化启动 |
| CLI 启动 | CommandLineJobOperator / 命令行参数 | 脚本化、k8s Job |

```java
// 手动启动（REST 接口触发，生产最常见形态）
@RestController
class BatchController {
    private final JobOperator jobOperator;

    @PostMapping("/batch/start")
    public JobExecution start(@RequestParam String jobName,
                              @RequestParam Map<String, String> params) {
        // 6.0：JobOperator 即 JobLauncher，可直接 start；或走 startNextInstance
        return jobOperator.startNextInstance(jobName, jobParameters);
    }
}
```

**JobOperator 核心操作**（6.0 语义）：

| 方法 | 行为 |
|------|------|
| `startNextInstance(jobName, params)` | 用 JobParametersIncrementer 生成参数启动新实例 |
| `restart(executionId)` | 用失败执行的参数重启（仅 FAILED/STOPPED 可重启） |
| `stop(executionId)` | 请求停止运行中的执行（**异步**：真正停下要等当前 chunk 完成） |
| `recover(executionId)`（6.0 新增） | 把 FAILED 执行标记为 ABANDONED，允许重新启动 |
| `abandon(executionId)` | 放弃（对 STOPPED/FAILED 的已存执行） |
| `getJobExecutions(jobName)` / `getParameters(executionId)` | 查询运维 |

> ⚠️ `stop` 的异步语义：它设置停止标志，**正在执行的 chunk 会跑完才停**（6.0 支持在安全边界停止）；"立刻终止"需求需配合进程级 SIGTERM（见 3.3）。

### 1.3 CommandLineJobOperator（6.0）

替代老旧的 `CommandLineJobRunner`，提供一致、可扩展的命令行交互（start/stop/restart），便于脚本与容器编排调用：

```text
java -jar app.jar --job=orderImport --params="input.file=/data/orders.csv"
```

## 2. 与调度系统集成

**职责分离原则**：Spring Batch 不管"什么时候跑"，只管"怎么跑"——调度交给外部。

| 调度方案 | 集成方式 | 适用 |
|---------|---------|------|
| Spring Task（@Scheduled） | 定时方法里调 JobLauncher.start（异步） | 单实例、简单定时（注意：**防止上次未跑完又触发**——加"运行中标志"） |
| Quartz | JobDetail 里调用 Batch Job | 复杂 cron/日历调度 |
| ShedLock + @Scheduled | 分布式锁保证多实例只触发一次 | 多实例部署（Spring Task 场景） |
| 外部调度（XXL-Job / 云 Cron / K8s CronJob） | 走 REST/CLI 触发 | 平台化、跨语言协作 |
| 消息触发（MQ 通知"文件已就绪"） | 监听器里调 JobLauncher | 事件驱动批处理 |

```java
// 多实例安全定时触发（ShedLock 模式）
@Scheduled(cron = "0 0 2 * * ?")
@SchedulerLock(name = "dailyOrderImport", lockAtMostFor = "2h")
public void runDailyImport() {
    if (!isJobRunning()) {          // JobExplorer 查询运行中状态
        jobLauncher.start(job, dailyParams());
    }
}
```

> 🎯 多实例部署必答点：**Job 幂等 + 单点触发**。即使调度重复触发，JobParameters 相同的实例由 JOB_KEY 唯一约束兜底；"运行中禁止重入"用 JobExplorer 查 RUNNING 状态的 JobExecution 判断。

## 3. 停止、恢复与优雅停机

### 3.1 停机链路全景

```text
人工/告警 → JobOperator.stop(executionId)   → 置停止标志，当前 chunk 完成后 STOPPED
进程信号 → SIGTERM（容器/发布）             → 6.0 优雅停机：保存重启状态后退出
异常崩溃 → 进程终止                          → 元数据停在最后提交点，重启续跑
```

### 3.2 StoppableStep（6.0）

6.0 引入 `StoppableStep` 接口：**任何 Step 类型**（不只是 Tasklet）都能响应外部停止信号，在安全边界（chunk 之间）停止并持久化状态——优雅停机的基础设施。

### 3.3 优雅停机（Graceful Shutdown）

- 6.0 支持 SIGTERM 下的优雅停机：完成当前 chunk、持久化状态、**以可重启状态退出**；
- 配合 `CommandLineJobOperator`/JobOperator 管理生命周期；
- 发布升级时的标准流程：先 `stop` 或 SIGTERM → 等 STOPPED → 新版本用同参数 restart 续跑。

### 3.4 恢复与放弃

| 操作 | 前条件 | 结果 |
|------|--------|------|
| restart(executionId) | FAILED / STOPPED | 新 JobExecution 从断点续跑 |
| recover(executionId) | FAILED | 标记 ABANDONED（该实例不可再重启），之后可用**新参数**或新实例启动 |
| abandon(executionId) | STOPPED / FAILED 已持久化 | 同上，人工放弃 |

> ⚠️ ABANDONED 的语义：让"这个失败实例永远结束"，防止 JOB_KEY 唯一约束挡住后续重试启动。

## 4. JobRegistry 与多 Job 管理

- **6.0 自动注册**：容器中的 Job Bean 自动进入 JobRegistry（不再需要 `JobRegistrySmartInitializingSingleton`，它已废弃）；
- JobRegistry 按名字查 Job → `BeanFactoryJobLocator` 可按名字查找并启动；
- `@EnableBatchProcessing(modular = true)` 已废弃（计划 6.2 移除）：多模块聚合改用 **Spring 上下文层级 + `GroupAwareJobs`**——子上下文注册 Job，父上下文统一启动。

## 5. 可观测性：Micrometer 指标与 JFR

### 5.1 Micrometer 指标（6.0 变化）

| 指标 | 类型 | 含义 |
|------|------|------|
| `spring.batch.job` | Timer | Job 执行耗时（标签：jobName、status） |
| `spring.batch.step` | Timer | Step 执行耗时（jobName、stepName、status） |
| `spring.batch.chunk.*` / `spring.batch.item.*` | Counter | chunk 与 item 级计数（read/write/skip…） |

> ⚠️ **6.0 破坏性变化**：不再使用 Micrometer 全局静态注册表——**必须显式提供 `ObservationRegistry` Bean** 才能采集指标（默认注册表无埋点）。配置示例：

```java
@Bean
ObservationRegistry observationRegistry() {
    // Boot 4 通常已自动装配 SimpleMeterRegistry + ObservationRegistry
    return ObservationRegistry.create();
}
```

### 5.2 Java Flight Recorder（JFR）事件（6.0 新增）

6.0 为 job/step 执行、item 读/写、事务边界新增 **JFR 事件**：

```text
jcmd <pid> JFR.start name=batch duration=10m filename=batch.jfr
# 事件类型（示例）：
#   BatchJobExecution  / BatchStepExecution  / BatchItemRead / BatchItemWrite / BatchTransaction
```

价值：生产故障时**零业务埋点**回放批处理执行轨迹（每次读写的时序、事务边界、耗时分布），与指标、日志形成三层观测。

### 5.3 日志规范

- Job 启动/结束打结构化日志（jobName、executionId、参数摘要、耗时）；
- Skip/Retry 必须打 WARN 级并带 executionId（模块 06）；
- 禁止业务代码用 System.out（Batch 日志走 slf4j，结合 JobLogger 过滤器可附加 executionId 到 MDC）。

## 6. 基于元数据的监控与告警设计

JobRepository 本身就是监控数据源——围绕 BATCH_* 表建告警查询：

```sql
-- 运行中超时告警（执行超过 30 分钟仍未结束）
SELECT je.JOB_EXECUTION_ID, ji.JOB_NAME, je.START_TIME
FROM BATCH_JOB_EXECUTION je
JOIN BATCH_JOB_INSTANCE ji ON ji.JOB_INSTANCE_ID = je.JOB_INSTANCE_ID
WHERE je.STATUS = 'STARTED'
  AND je.START_TIME < NOW() - INTERVAL 30 MINUTE;

-- 失败执行统计（按作业）
SELECT ji.JOB_NAME, COUNT(*) AS fail_count
FROM BATCH_JOB_EXECUTION je
JOIN BATCH_JOB_INSTANCE ji ON ji.JOB_INSTANCE_ID = je.JOB_INSTANCE_ID
WHERE je.STATUS = 'FAILED' AND je.END_TIME > NOW() - INTERVAL 24 HOUR
GROUP BY ji.JOB_NAME;

-- skip 异常阈值告警
SELECT STEP_EXECUTION_ID, READ_SKIP_COUNT + WRITE_SKIP_COUNT + PROCESS_SKIP_COUNT AS skips
FROM BATCH_STEP_EXECUTION
WHERE SKIPS > 1000 AND END_TIME > NOW() - INTERVAL 1 HOUR;
```

**生产运维四件套**：

1. 指标：Micrometer → Prometheus/Grafana（作业耗时 P95、skip 速率、运行中任务数）；
2. 事件：JFR 按需采集 + 定期抽样；
3. 告警：元数据 SQL 巡检（运行超时、失败率、skip 激增）+ 进程存活探针；
4. 对账：每天核对 BATCH_JOB_EXECUTION 的 COMPLETED 记录数与业务侧产出记录数。

---

> 🎯 **核心要点**：6.0 的运维入口收敛为 JobOperator（extends JobLauncher）与 CommandLineJobOperator；stop 是异步的、优雅停机走 SIGTERM + StoppableStep；可观测性三件套 = Micrometer（需显式 ObservationRegistry）+ JFR 事件 + 元数据 SQL；调度与执行分离，多实例靠"JOB_KEY 唯一 + 运行中检查"防重入。
