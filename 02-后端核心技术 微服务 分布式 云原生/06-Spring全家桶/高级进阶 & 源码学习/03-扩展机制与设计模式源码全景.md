## 1. 扩展机制的三大支柱

| 支柱 | 机制 | 回答的问题 |
|------|------|-----------|
| 后处理器（BPP/BFPP） | Bean 生命周期钩子 | "每个 Bean 创建时怎么插手" |
| @Import 体系 | 类级导入 | "怎么把别人的配置/Bean 装进容器" |
| SPI（ImportCandidates） | 文件级发现 | "jar 包里的自动配置怎么被发现" |

> 💡 三者关系：SPI 发现"有哪些自动配置类" → @Import 把配置类装进容器 → 后处理器在 Bean 创建过程中动手。**从 jar 到 Bean 的完整链路**。

## 2. @Import 体系源码

### 2.1 三类导入方式

```text
@Import(X.class)
 ├─ 普通配置类/组件类 → 直接注册 BeanDefinition
 ├─ ImportSelector → selectImports 返回类名数组（再走一次解析）
 │     ├─ 普通 ImportSelector（可返回任意类名）
 │     └─ DeferredImportSelector ★ 延迟导入（自动配置专用，最后执行）
 └─ ImportBeanDefinitionRegistrar → registerBeanDefinitions 编程注册
```

| 实现 | 用途 | 源码入口 |
|------|------|---------|
| `ConfigurationClassParser` | @Import 解析总入口 | `processImports` 方法 |
| `DeferredImportSelector` | **自动配置排序**（`@AutoConfiguration` 实现它） | `processDeferredImportSelectors` |
| `ImportBeanDefinitionRegistrar` | 动态注册（如 `@EnableConfigurationProperties`） | `processImports` 分支 |

> 🎯 **面试锚点**：为什么 `@EnableAutoConfiguration` 能加载所有 jar 的自动配置？答 = 它是 `DeferredImportSelector`，SPI 发现候选类 → **延迟到最后解析**，保证用户配置优先。

### 2.2 @EnableXxx 注解套路

```java
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
@Import(XxxRegistrar.class)   // 或 @Import(XxxSelector.class)
public @interface EnableXxx {}
```

| 经典案例 | Import 目标 | 机制 |
|----------|------------|------|
| `@EnableAsync` | `AsyncConfigurationSelector` | ImportSelector 按模式选配置 |
| `@EnableScheduling` | `SchedulingConfiguration` | 普通配置类 |
| `@EnableConfigurationProperties` | Registrar | 注册属性绑定 Bean |
| `@EnableTransactionManagement` | `TransactionManagementConfigurationSelector` | 按模式（proxy/aspectj）选配置 |

## 3. SPI 机制：Boot 4 的 ImportCandidates

### 3.1 文件约定（Boot 4）

```text
META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports
（每行一个自动配置类全限定名，替代旧 spring.factories 的 EnableAutoConfiguration 键）
```

| 机制 | 类 | 位置 |
|------|----|------|
| 自动配置发现 | `AutoConfigurationImportSelector`（DeferredImportSelector 实现） | spring-boot-autoconfigure |
| 文件加载 | `ImportCandidates.load` | spring-core（`META-INF/spring/*.imports` 通用） |
| 通用 SPI（非自动配置） | `ImportCandidates.load(clazz, location)` | 任意 `*.imports` 文件 |

```java
// 通用 SPI 用法（Boot 4 起官方推荐）
ImportCandidates.load(MyExtension.class).forEach(className -> {...});
```

> ⚠️ **版本差异**：Boot 3.x 的 `spring.factories` 中 `EnableAutoConfiguration` 键在 Boot 4 已移除，统一走 `.imports`；自定义自动配置必须改文件名与格式（详见「Spring生态深度剖析」07）。

## 4. 条件装配源码

### 4.1 条件求值流程

```text
ConditionEvaluator.shouldSkip
 → 解析 @Conditional 注解列表
 → 依次调用 Condition.matches(ConditionContext, AnnotatedTypeMetadata)
 → 任一不匹配 → skip 该配置类/Bean 方法
```

| 条件注解 | 实现类 | 判定依据 |
|----------|--------|---------|
| `@ConditionalOnClass` | `OnClassCondition` | ClassLoader 能否加载类 |
| `@ConditionalOnMissingBean` | `OnBeanCondition` | BeanFactory 当前 Bean 状态 |
| `@ConditionalOnProperty` | `OnPropertyCondition` | Environment 属性 |
| `@ConditionalOnWebApplication` | `OnWebApplicationCondition` | 容器类型 |
| `@ConditionalOnExpression` | 内建 | SpEL |

### 4.2 源码读法

| 关注点 | 位置 |
|--------|------|
| 条件执行时机 | `ConfigurationClassParser` 解析配置类时（`shouldSkip`） |
| 结果缓存 | `ConditionEvaluator` 内（每类只评估一次） |
| 顺序控制 | 自动配置类 `@AutoConfiguration(before=..., after=...)` |

> ⚠️ **易错点**：`@ConditionalOnMissingBean` 的"缺"是**求值时刻**的容器状态——所以自动配置中它常配合 `@ConditionalOnClass` 与顺序控制，避免误判。

## 5. 设计模式在 Spring 源码中的落点

| 模式 | 源码位置 | 一句话说明 |
|------|---------|-----------|
| 工厂方法 | `FactoryBean` / `AbstractFactoryBean` | Bean 生产入口 |
| 抽象工厂 | `BeanDefinitionReader` 族 | 解析器族 |
| 单例 | `DefaultSingletonBeanRegistry`（单例注册表） | 三级缓存之一 |
| 模板方法 | `AbstractApplicationContext.refresh` / `AbstractAutowireCapableBeanFactory` | 骨架 + 子类钩子 |
| 观察者 | `ApplicationEventMulticaster` / `ApplicationListener` | 事件驱动 |
| 策略 | `ResolvableType` 解析、`HandlerMapping` 族 | 算法互换 |
| 适配器 | `HandlerAdapter` / `MethodValidationAdapter` | 接口转接 |
| 装饰器 | `SingletonBeanRegistry` 包装、`BeanFactory` 包装链 | 功能叠加 |
| 代理 | `ProxyFactory`（JDK/CGLIB） | AOP 基础 |
| 责任链 | `HandlerInterceptor` / Security 过滤器链 / Advisors 链 | 链式处理 |
| 组合 | `CompositePropertySource` / `BeanDefinition` 继承 | 树状结构 |
| 建造者 | `BeanDefinitionBuilder` / `ChatClient.Builder` 类 | 复杂对象组装 |
| 门面 | `ApplicationContext`（对 BeanFactory 的多能力封装） | 统一入口 |
| 享元 | 单例缓存 + `DefaultSingletonBeanRegistry` | 对象复用 |

> 🎯 **核心要点**：Spring 源码是"设计模式教科书"——**模板方法（骨架）+ 策略（算法互换）+ 责任链（处理管线）**三个模式是理解 Spring 的主干，其余按图索骥。

## 6. 扩展点速查总表

| 扩展点 | 接口/注解 | 时机 | 典型用途 |
|--------|----------|------|---------|
| 容器级 | `BeanFactoryPostProcessor` | refresh ⑤ | 修改 BeanDefinition |
| 容器级 | `BeanDefinitionRegistryPostProcessor` | ⑤ 最先 | 注册新 BeanDefinition |
| 实例化前 | `InstantiationAwareBeanPostProcessor.postProcessBeforeInstantiation` | 创建前 | 返回代理跳过默认实例化 |
| 属性填充 | `postProcessProperties` | 填充属性时 | 自动装配 |
| 初始化前 | `BeanPostProcessor.postProcessBeforeInitialization` | 初始化前 | 包装/AOP |
| 初始化后 | `postProcessAfterInitialization` | 初始化后 | **AOP 代理主要挂点** |
| Aware | `BeanNameAware`/`ApplicationContextAware` 等 | 初始化前 | 注入框架信息 |
| 生命周期 | `InitializingBean`/`@PostConstruct`/`@PreDestroy` | 初始化/销毁 | 自定义启停 |
| 事件 | `ApplicationListener`/`@EventListener` | 发布时 | 解耦通知 |
| 配置 | `@Import` 三方式 | 解析时 | 导入配置 |
| 条件 | `@Conditional` | 解析时 | 按环境装配 |

## 7. 核心要点

> 🎯 **核心要点**：
> - 三大支柱：后处理器（创建期插手）、@Import（类级导入）、SPI（文件级发现）；
> - `@EnableAutoConfiguration` = DeferredImportSelector + `.imports` SPI + 条件求值三段式；
> - Boot 4 SPI 全部走 `.imports` 文件（`ImportCandidates.load`），`spring.factories` 的自动配置键已移除；
> - 设计模式主干：模板方法 + 策略 + 责任链；扩展点记忆单位 = 接口 + 时机。
