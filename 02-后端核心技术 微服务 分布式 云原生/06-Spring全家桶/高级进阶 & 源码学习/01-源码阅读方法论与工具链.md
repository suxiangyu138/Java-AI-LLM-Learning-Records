## 1. 阅读前的三个准备

### 1.1 版本锁定（铁律）

| 步骤 | 做法 |
|------|------|
| 锁定框架版本 | 看项目依赖或官方页脚（如 Framework 7.0.5 / Boot 4.0.2） |
| 对应源码 tag | GitHub tag 与版本一一对应（`v7.0.5`），**别读 main 分支** |
| 本地源码下载 | IDEA 自动下载 `-sources.jar`；或 clone tag |
| 核对模块 | Boot 4 起源码模块化拆分，确认类属于哪个模块 |

> ⚠️ 80% 的"源码看不懂"源于版本错位：`main` 分支可能是未发布行为；低版本教程引用的类在 7.x 可能已删除（如 Spring Security 6 的 `WebSecurityConfigurerAdapter`）。

### 1.2 目标驱动（先有问题再读）

| 错误姿势 | 正确姿势 |
|----------|---------|
| 从 `main()` 开始通读 | 从一个**具体问题**出发（"自动配置的 Bean 什么时候创建的？"） |
| 读完所有类注释 | 只读"从入口到结论"路径上的关键方法与类注释 |
| 纠结每个细节 | 先建立主干链路，细节用类图索引回头补 |

### 1.3 建立"源码地图"意识

读任何框架先画三张图（本体系 [02](02-Spring容器源码架构地图.md) 已给出 Spring 版）：

| 图 | 内容 | 工具 |
|----|------|------|
| 类图 | 核心接口/实现层级（谁继承谁） | IDEA Structure / Diagrams |
| 时序图 | 一次完整调用的方法链 | 断点栈 + SequenceDiagram 插件 |
| 入口索引 | 每个功能的入口类/方法表 | 本体系各文件的"源码入口速查表" |

## 2. 五步阅读法

```text
① 找入口：从"你触发过的 API"反查（Bean 注入 → getBean → ...）
② 画主干：方法调用链（断点栈）→ 只有主干后读分支
③ 卡扩展点：找到"留给你插手的接口"（PostProcessor/Advisor/...）
④ 验证假设：用日志/断点/Arthas 印证你推断的行为
⑤ 输出笔记：结论 + 类名 + 方法名 + 版本，写成可复讲的口诀
```

| 步骤 | 工具 | 产出 |
|------|------|------|
| ① 找入口 | 断点在调用处打 | 入口类/方法 |
| ② 画主干 | 调用栈（Debugger Stack） | 时序链路 |
| ③ 卡扩展点 | 全文搜索"接口实现/SPI 加载" | 扩展点清单 |
| ④ 验证假设 | 日志/Arthas watch | 行为证据 |
| ⑤ 输出笔记 | Markdown | 可复讲笔记（**费曼式：讲得出来才算懂**） |

## 3. IDEA 源码调试技巧

| 技巧 | 用法 | 场景 |
|------|------|------|
| 条件断点 | 断点右键 → Condition（如 `beanName.equals("orderService")`） | 只停目标 Bean |
| 方法断点/求值 | Break on method entry + `Evaluate Expression` | 观察参数 |
| 栈帧回退 | `Drop Frame` 回到上层方法重走 | 反复走同一链路 |
| 日志断点 | 断点勾选"Log message"，不停只打印 | 高频调用不打断流 |
| 强制入内 | `Step Into` 进入 JDK/框架内部（关掉过滤） | 看 `getSingleton` 等底层实现 |
| Live Templates | 收藏常用表达式（`context.getBeanNamesForType` 等） | 调试提速 |
| 类图 | `Diagrams → Show Diagram` | 接口层级速览 |

## 4. 运行时观测：Arthas / JFR / 日志

### 4.1 Arthas（线上/本地运行时反推源码）

| 命令 | 作用 | 源码学习用法 |
|------|------|--------------|
| `watch` | 观测方法入参/返回值/异常 | 印证"这个类到底被谁调、传了什么" |
| `trace` | 方法内部调用树 | 反推时序链路（无需断点） |
| `stack` | 当前调用栈 | 找入口类 |
| `jad` | 反编译目标类 | 读线上真实字节码 |
| `classloader` | 类加载器与类归属 | 排查类加载问题 |

```bash
# 例：观测所有 BeanPostProcessor 的 postProcessAfterInitialization 调用
watch org.springframework.beans.factory.config.BeanPostProcessor postProcessAfterInitialization '{params[0].getClass().getName()}' -n 20
```

### 4.2 JFR（Java Flight Recorder）

| 用途 | 说明 |
|------|------|
| 方法采样 | `jfr` 录制后看热点方法（源码阅读重点线索） |
| 事件流 | GC/锁/IO 事件与业务时序对齐 |
| 启动分析 | `-XX:StartFlightRecording` 看启动阶段方法热点 |

### 4.3 框架日志开关

```yaml
# Spring 家族日志：调成 DEBUG 看内部流转，配合源码逐行印证
logging:
  level:
    org.springframework.beans.factory: DEBUG
    org.springframework.boot.autoconfigure: DEBUG   # 自动配置报告
    org.springframework.security: DEBUG
```

> 💡 黄金组合：**源码断点走读（本地）+ Arthas watch（运行时）+ DEBUG 日志（印证）**——三条证据链对齐，结论才可靠。

## 5. 常见误区清单

| # | 误区 | 纠正 |
|---|------|------|
| 1 | 读 main 分支源码 | 按版本 tag 锁定 |
| 2 | 从构造函数开始通读 | 从问题 + 入口方法开始 |
| 3 | 只看类不看调用关系 | 类注释 + 调用链 + 类图三件套 |
| 4 | 不断点、纯肉眼看 | 断点/Arthas 验证，代码不会骗你，直觉会 |
| 5 | 记结论不记路径 | 结论 + 入口类 + 关键方法名一起记（面试要讲路径） |
| 6 | 低版本教程直接套 7.x | 先确认类是否存在、包名是否变化 |
| 7 | 一次读完整个框架 | 一次只读一条链路，下次再读另一条 |
| 8 | 源码 = 所有答案 | 源码是"实现"，设计意图看官方文档/注释/Issue |

## 6. 核心要点

> 🎯 **核心要点**：
> - 三准备：版本锁定、目标驱动、源码地图；
> - 五步法：找入口 → 画主干 → 卡扩展点 → 验证假设 → 输出笔记；
> - 三工具：IDEA 断点（条件断点/日志断点）、Arthas（watch/trace 反推）、框架 DEBUG 日志；
> - 记忆单位是"**入口类 + 关键方法 + 调用链**"，不是代码行。
