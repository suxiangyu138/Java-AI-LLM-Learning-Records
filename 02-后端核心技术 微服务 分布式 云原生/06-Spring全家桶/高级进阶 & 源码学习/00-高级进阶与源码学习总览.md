## 2. 定位：与现有 Spring 体系的分工

| 体系 | 定位 | 回答的问题 | 本体系补充什么 |
|------|------|-----------|----------------|
| Spring 生态 | 全景 | Spring 家族有哪些组件、怎么选 | 不重复 |
| Spring 全家桶原理纵深 | 原理 | 组件怎么用、原理是什么 | 不重复 |
| Spring 生态深度剖析 | 机制 | 核心引擎**内部怎么运转**（生命周期/启动/循环依赖/AOP/MVC/事件） | 本体系引用其结论，不再重讲机制 |
| **高级进阶 & 源码学习（本体系）** | **方法 + 地图 + 跨框架** | **怎么读源码、源码从哪读起、怎么读完整套家族** | 方法论 + 类图索引 + Security/Data/Cloud 源码入口 + 实战 + 面试 |

> 🎯 **核心要点**：本体系不做"第二份深度剖析"——深度剖析讲"机制"，本体系讲"**导航**"（源码地图、入口类、关键方法、断点路径）与"**方法**"（怎么自己读任何框架的源码）。两者配合：先看机制结论，再按地图进源码验证。

## 5. 源码学习核心概念速查

| 概念 | 一句话 | 对应源码类（7.x） |
|------|--------|-------------------|
| BeanFactory | 容器最底层接口 | `DefaultListableBeanFactory` |
| ApplicationContext | 高级容器（含资源/事件/国际化） | `AnnotationConfigApplicationContext` |
| BeanDefinition | Bean 的"图纸" | `GenericBeanDefinition` |
| refresh() | 容器启动总入口 | `AbstractApplicationContext#refresh` |
| BeanPostProcessor | Bean 实例化后扩展点 | `BeanPostProcessor`/`InstantiationAwareBeanPostProcessor` |
| ImportCandidates | Boot 4 自动配置 SPI | `ImportCandidates.load`（`META-INF/spring/...imports`） |
| 三级缓存 | 循环依赖解决方案 | `DefaultSingletonBeanRegistry` 三 Map |
| ProxyFactory | AOP 代理工厂 | `org.springframework.aop.framework.ProxyFactory` |
| SecurityFilterChain | 安全过滤器链 | `FilterChainProxy` + `SecurityFilterChain` |
| MapperProxy | MyBatis Mapper 动态代理 | `org.apache.ibatis.binding.MapperProxy` |
| 源码阅读铁律 | 版本锁死再读 | 页脚版本 = 源码 tag |

## 6. 版本窗口说明

| 项 | 基准版本 | 说明 |
|----|---------|------|
| Spring Framework | 7.0.x | Boot 4 基线（Jakarta EE 11） |
| Spring Boot | 4.0.x / 4.1.x | 自动配置 SPI 用 `.imports` 文件 |
| Spring Security | 7.0.x | Lambda DSL 强制、`Customizer<HttpSecurity>`、MFA/Passkey 内建 |
| Spring Cloud | 2025.1.x（Oakwood） | 源码入口类按 5.x 组件版本 |
| Nacos Client | 3.x | 注册/订阅客户端源码 |
| MyBatis | 3.5.x / mybatis-spring 3.x | MapperProxy 机制稳定 |
| 源码获取 | GitHub tag 与版本一一对应 | `spring-framework v7.0.x`、`spring-boot v4.0.x` |

> ⚠️ **时效性**：源码阅读必须与版本绑定——读 `main` 分支源码可能遇到未发布行为。本文以 7.0/Boot 4 为基准，低版本差异集中在类路径与配置属性，核心机制（refresh/三级缓存/代理链）跨版本稳定。
