## 1. 问题引入：接口怎么变成 Bean 的

```java
// 你只写了接口，没有实现类——调用却正常
@Mapper
public interface OrderMapper {
    Order selectById(Long id);
}
```

| 问题 | 答案线索 |
|------|---------|
| 接口能注入吗？ | 不能直接注入——被替换成了**动态代理** |
| 代理谁创建的？ | 框架在启动期扫描 `@Mapper`/`@Repository` 接口，注册"工厂 Bean" |
| 方法调用发生了什么？ | 代理拦截方法调用 → 解析 SQL → 执行 → 映射结果 |

> 🎯 **核心要点**：数据访问框架的核心技艺 = **接口 → 代理 → 执行**三段式。看懂 MyBatis 与 Spring Data 的代理生成，就掌握了所有"接口式编程"框架（Feign、Stream 函数绑定同理）。

## 2. MyBatis 源码链路

### 2.1 注册阶段（启动期）

```text
@MapperScan → MapperScannerRegistrar（ImportBeanDefinitionRegistrar）
 → ClassPathMapperScanner（扫描接口）
 → 每个接口注册 MapperFactoryBean（FactoryBean）
      └─ MapperFactoryBean.getObject()
           → SqlSessionTemplate.getMapper(mapperInterface)
           → MapperRegistry.getMapper
           → 返回 MapperProxy（JDK 动态代理，InvocationHandler）
```

| 环节 | 关键类 | 说明 |
|------|--------|------|
| 扫描入口 | `MapperScannerConfigurer`/`@MapperScan` | BeanDefinitionRegistryPostProcessor |
| 工厂 | `MapperFactoryBean`（`FactoryBean<T>`） | 延迟创建代理 |
| 注册表 | `MapperRegistry` | 接口 → MapperProxyFactory 映射 |
| 会话 | `SqlSessionTemplate` | 线程安全会话（内部 ThreadLocal 连接） |

### 2.2 调用阶段（运行期）

```text
mapper.selectById(1L)
 → MapperProxy.invoke（JDK 代理拦截）
 → PlainMethodInvoker / DefaultMethodInvoker 分发
 → MapperMethod.execute
      ├─ 判断 SQL 类型（SELECT/INSERT/UPDATE/DELETE）
      ├─ 解析参数 → SqlSource → BoundSql
      └─ SqlSession.selectOne → 执行器（Executor 链）
           ├─ 二级缓存（CachingExecutor）
           ├─ 一级缓存（本地缓存）
           └─ SimpleExecutor/ReuseExecutor/BatchExecutor
                → StatementHandler → 预编译 → 结果映射（ResultSetHandler）
```

| 面试锚点 | 源码事实 |
|----------|---------|
| 为什么 Mapper 是线程安全的 | 每个方法调用新建 `MapperMethod` 上下文 + `SqlSessionTemplate` 内部代理管理连接 |
| 一级缓存 | `BaseExecutor.localCache`（会话级，默认开启） |
| 二级缓存 | `CachingExecutor` 装饰器（命名空间级，需显式开启） |
| 与 Spring 事务整合 | `SqlSessionTemplate` 检测事务同步（`SpringManagedTransaction`）——有事务用事务连接 |

### 2.3 与 Spring 事务的整合点

```text
@Transactional
 └─ TransactionInterceptor → 事务管理器（DataSourceTransactionManager）
       └─ ConnectionHolder 绑定到 ThreadLocal（TransactionSynchronizationManager）
             └─ SqlSessionTemplate 获取连接时优先取事务连接（SpringManagedTransaction）
```

> 💡 这也是"事务内 MyBatis 连接与 JDBC 同源"的源码证据：`TransactionSynchronizationManager` 是 Spring 事务与数据访问的统一枢纽。

## 3. Spring Data JPA 源码链路

### 3.1 注册阶段

```text
@EnableJpaRepositories / @SpringBootApplication（默认扫描）
 → JpaRepositoriesRegistrar（ImportBeanDefinitionRegistrar）
 → RepositoryConfigurationExtensionSupport
 → 每个接口注册 RepositoryFactoryBean（FactoryBean）
      └─ getObject()
           → JpaRepositoryFactory.getRepository
           → 创建代理（Spring AOP 代理，含查询方法解析）
```

| 环节 | 关键类 | 说明 |
|------|--------|------|
| 注册 | `RepositoryFactoryBeanSupport` | FactoryBean 模式 |
| 工厂 | `JpaRepositoryFactory` | 目标代理创建 |
| 核心处理器 | `QueryExecutorMethodInterceptor`（MethodInterceptor） | **方法级查询派发** |
| 查询解析 | `PartTreeJpaQuery` | 方法名 → JPQL（`findByOrderIdAndStatus` 解析） |

### 3.2 调用阶段

```text
repository.findByOrderId("SO-1")
 → 代理拦截（QueryExecutorMethodInterceptor.invoke）
 → RepositoryQuery.execute
      ├─ 方法名派生查询（PartTreeJpaQuery → JPQL 生成）
      └─ @Query 显式查询（NamedQuery / 原生 SQL）
 → JpaQueryExecution（按返回类型选择执行器）
      ├─ 单对象 / 集合 / 计数 / 存在 / 流式
 → EntityManager（JPA）→ Hibernate → JDBC
```

| 面试锚点 | 源码事实 |
|----------|---------|
| 方法名派生 | `PartTree` 解析 `findBy`/`And`/`Or`/`OrderBy` 等 → 构造 JPQL |
| 返回类型分发 | `JpaQueryExecution` 策略族（单对象/集合/Count/Exists...） |
| 事务包裹 | `RepositoryFactorySupport` 默认给查询加只读事务（`@Transactional(readOnly=true)`） |
| 自定义实现类 | 接口 `XxxRepositoryCustom` + `SimpleJpaRepository` 合并（`getTargetRepository` 逻辑） |

## 4. 两条链路的对比

| 维度 | MyBatis（Mapper） | Spring Data JPA（Repository） |
|------|-------------------|------------------------------|
| 代理类型 | JDK 动态代理（`MapperProxy`） | Spring AOP 代理（含 JDK/CGLIB 选择） |
| SQL 来源 | XML/注解 SQL | 方法名派生 / `@Query` / 规范（Specification） |
| 调用分发 | `MapperMethod`（SQL 类型分支） | `QueryExecutorMethodInterceptor`（查询类型分支） |
| 缓存 | 一/二级缓存（MyBatis 自身） | JPA 一级缓存（EntityManager）+ 可选二级 |
| 事务整合 | SpringManagedTransaction | JpaTransactionManager |
| 注册机制 | `MapperFactoryBean` | `RepositoryFactoryBean` |
| 接口扫描 | `@MapperScan`/`@Mapper` | `@EnableJpaRepositories`/自动扫描 |

> 🎯 **核心要点**：两条链路同构——**扫描接口 → FactoryBean 注册 → 代理生成 → 方法调用拦截 → 执行策略分发**。这个模板可以套用到 OpenFeign（[07](07-Spring-Cloud源码导读.md)）、Spring Data Redis 模板等一切"接口即 DAO"框架。

## 5. 断点阅读路径

| 场景 | 断点位置 | 观察点 |
|------|---------|--------|
| Mapper 代理生成 | `MapperRegistry.getMapper` | 返回的代理类型 |
| Mapper 方法执行 | `MapperMethod.execute` | SQL 类型分支 |
| 一级缓存命中 | `BaseExecutor.query` | cacheKey 命中 |
| Repository 代理 | `RepositoryFactorySupport.getRepository` | 代理与 Advisor |
| 查询方法分发 | `QueryExecutorMethodInterceptor.invoke` | query 选择 |
| 事务连接绑定 | `TransactionSynchronizationManager.getResource` | 连接归属 |

## 6. 核心要点

> 🎯 **核心要点**：
> - 接口式编程 = 扫描 + FactoryBean + 动态代理 + 方法拦截四部曲；
> - MyBatis：`MapperProxy`（JDK 代理）→ `MapperMethod` 分发 → Executor 链（缓存/执行）；
> - Spring Data：`QueryExecutorMethodInterceptor` → `RepositoryQuery` → `JpaQueryExecution` 策略；
> - 两条链都通过 `TransactionSynchronizationManager` 与 Spring 事务打通；
> - 模板复用：所有"接口即组件"框架源码都可以按此四部曲读。
