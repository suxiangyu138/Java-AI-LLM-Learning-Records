## 1. 答题范式

| 步骤 | 要求 | 示例 |
|------|------|------|
| ① 结论先行 | 一句话说出机制 | "循环依赖靠三级缓存解决" |
| ② 入口类 | 说类名（证明读过） | `DefaultSingletonBeanRegistry.getSingleton` |
| ③ 关键方法 | 说方法名与流程 | `createBean → doCreateBean → getEarlyBeanReference` |
| ④ 边界 | 补充失效场景/条件 | "仅单例 + 非构造器注入" |
| ⑤ 版本 | 标注版本差异 | "7.x 与 6.x 行为一致；Boot 4 自动配置用 .imports" |

> 🎯 面试官要的不是"背源码"，是**"路径感"**——你能否带他从入口走到结论。范式 ②③ 是核心。

## 2. 容器与生命周期（1~8）

| # | 题目 | 答题要点（入口类/方法） |
|---|------|------------------------|
| 1 | Spring 容器启动流程？ | `AbstractApplicationContext.refresh` 十二步；重点 ⑤ BFPP ⑥ BPP ⑪ 预实例化 ⑫ 事件 |
| 2 | Bean 的完整生命周期？ | `AbstractAutowireCapableBeanFactory.doCreateBean`：实例化→属性填充→初始化回调→销毁；BPP 五个挂点 |
| 3 | 循环依赖怎么解决？为什么三级缓存？ | `DefaultSingletonBeanRegistry` 三 Map；三级存 `ObjectFactory` 的原因 = **AOP 代理延迟创建** |
| 4 | 构造器注入为什么不能解决循环依赖？ | 构造器阶段对象未创建，无"提前暴露"机会；`getEarlyBeanReference` 之前实例未完成 |
| 5 | 三级缓存为什么不是两级？ | 若二级存最终对象，代理创建时机错误（无 AOP 时多此一举）；`getEarlyBeanReference` 的延迟语义 |
| 6 | BeanFactory 和 ApplicationContext 区别？ | 后者 = 前者 + 资源/事件/国际化/环境；`ApplicationContext` 是门面 |
| 7 | @Autowired 的装配顺序？ | `AutowiredAnnotationBeanPostProcessor.postProcessProperties`：byType → 多个候选按名字 |
| 8 | 一个 Bean 什么时候被创建？ | 单例：`preInstantiateSingletons` 启动时预实例化；prototype：getBean 时；lazy-init：首次使用 |

## 3. AOP 与代理（9~14）

| # | 题目 | 答题要点 |
|---|------|---------|
| 9 | AOP 代理创建流程？ | `AbstractAutoProxyCreator.wrapIfNecessary`：找 Advisor → 匹配切点 → `ProxyFactory` 创建 |
| 10 | JDK 代理和 CGLIB 区别？ | 接口 vs 子类；`InvocationHandler` vs `MethodInterceptor`；FastClass 直调 |
| 11 | Spring 默认用哪种？ | Boot 4 默认 `proxy-target-class=true` → CGLIB |
| 12 | 为什么 @Transactional 自调用失效？ | `this` 非代理；调用发生在 `invokeSuper` 内部，绕过拦截器 |
| 13 | @Async 实现原理？ | `AsyncAnnotationBeanPostProcessor` + `AsyncExecutionInterceptor` + TaskExecutor（见 [04](04-并发与异步源码.md)） |
| 14 | 切面与通知的调用顺序？ | 责任链 + `@Order`；前通知先进后出，后通知后进先出（Around 包裹） |

## 4. 事务（15~17）

| # | 题目 | 答题要点 |
|---|------|---------|
| 15 | @Transactional 怎么生效？ | `TransactionInterceptor`（AOP 拦截）→ 事务管理器 → 连接绑定 `TransactionSynchronizationManager` |
| 16 | 事务传播行为实现？ | `AbstractPlatformTransactionManager` 模板方法；`doBegin`/`doSuspend`/`doCommit`；7 种传播在 `TransactionDefinition` |
| 17 | 事务为什么会失效？（收集清单） | 自调用/非 public/异常被吞/代理未创建/类未加载进容器/传播设置（REQUIRES_NEW 嵌套） |

## 5. Boot 启动与自动配置（18~22）

| # | 题目 | 答题要点 |
|---|------|---------|
| 18 | SpringApplication.run 做了什么？ | 环境准备 → `refresh` → 启动 Web 容器（`ServletWebServerApplicationContext.onRefresh`）→ 监听器事件 |
| 19 | 自动配置原理？ | `@EnableAutoConfiguration` = `DeferredImportSelector` + `.imports` SPI + `@Conditional` 过滤（见 [03](03-扩展机制与设计模式源码全景.md)） |
| 20 | 条件注解怎么实现？ | `ConditionEvaluator.shouldSkip` 解析 `@Conditional` → `Condition.matches` |
| 21 | Boot 4 自动配置 SPI 变化？ | `spring.factories` 的 EnableAutoConfiguration 键 → `AutoConfiguration.imports` 文件（`ImportCandidates.load`） |
| 22 | starter 原理？ | 自动配置类 + 依赖管理；`@AutoConfiguration(before/after)` 排序 |

## 6. Web 与 MVC（23~25）

| # | 题目 | 答题要点 |
|---|------|---------|
| 23 | 一次请求的处理链路？ | `DispatcherServlet.doDispatch` 八阶段：HandlerMapping → HandlerAdapter → 参数解析 → 调用 → 返回值处理（详见「深度剖析」05） |
| 24 | 参数解析与返回值处理原理？ | `HandlerMethodArgumentResolverComposite` / `HandlerMethodReturnValueHandlerComposite`（策略+组合） |
| 25 | 拦截器 vs 过滤器区别？ | 过滤器（Servlet 层，`DelegatingFilterProxy` 接入）vs 拦截器（MVC 层，`HandlerInterceptor` 责任链） |

## 7. 框架与生态（26~30）

| # | 题目 | 答题要点 |
|---|------|---------|
