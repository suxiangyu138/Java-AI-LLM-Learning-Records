## 2. 案例一：@EnableAutoConfiguration 加载链路

### 2.1 断点清单

| # | 断点位置（类.方法） | 观察点 |
|---|---------------------|--------|
| 1 | `SpringApplication.run` | 应用启动入口 |
| 2 | `AbstractApplicationContext.refresh` | 十二步总入口 |
| 3 | `ConfigurationClassParser.processImports` | @Import 解析 |
| 4 | `AutoConfigurationImportSelector.getAutoConfigurationEntry` | **自动配置候选加载** |
| 5 | `ImportCandidates.load` | `.imports` 文件读取 |
| 6 | `ConditionEvaluator.shouldSkip` | 条件求值 |

### 2.2 走读过程

```text
① SpringApplication.run（main 方法断点）→ 进入 refresh
② 断点 4：观察 getAutoConfigurationEntry 返回的候选类数量
   └─ 追问：这些类名哪来的？→ 单步进入
③ 断点 5：ImportCandidates.load 断住，看读取的文件路径
   └─ 观察点：META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports
④ 断点 6：shouldSkip 反复命中——观察每个候选类的条件评估
   └─ 观察点：哪些类被跳过（条件不满足）、哪些进入容器
⑤ 结论：候选发现（SPI）→ 排序（@AutoConfiguration 注解）→ 条件过滤（@Conditional）→ 注册
```

### 2.3 验证产出

| 观察结果 | 记录 |
|----------|------|
| 候选类总数 | 约数百（含 starter 传递依赖） |
| 被跳过原因 Top3 | 类不存在（OnClass）/Bean 已存在（OnMissingBean）/属性不满足（OnProperty） |
| 加载文件路径 | `classpath*:META-INF/spring/...imports` |

> 🎯 演练收获：一次走读把"自动配置三段式（发现/排序/过滤）"变成亲眼所见——面试讲这题时引用断点观察比背书有说服力。

## 3. 案例二：Security 过滤器链执行

### 3.1 断点清单

| # | 断点位置（类.方法） | 观察点 |
|---|---------------------|--------|
| 1 | `DelegatingFilterProxy.doFilter` | Servlet → Spring 桥 |
| 2 | `FilterChainProxy.doFilter` | 安全门面 |
| 3 | `SecurityFilterChainFilter.doFilter` | 链执行器 |
| 4 | `AuthorizationFilter`（或任一过滤器） | 链内过滤器 |
| 5 | `ProviderManager.authenticate` | 认证分发（表单登录时） |

### 3.2 走读过程

```text
① 启动应用，浏览器访问受保护接口
② 断点 1~3 依次命中：桥 → 门面 → 链执行
③ 断点 3 内观察：过滤器列表（约 15+ 个）与顺序
   └─ 追问：顺序谁定的？→ 看 HttpSecurity 构建的 FilterOrderRegistration
④ 访问 /login 提交表单：断点 5 命中
   └─ 观察：ProviderManager 的 providers 列表 → DaoAuthenticationProvider
⑤ 结论：认证（过滤器内）→ 上下文（SecurityContextHolder）→ 授权（AuthorizationFilter）
```

### 2.3 验证产出

| 观察结果 | 记录 |
|----------|------|
| 链内过滤器数量与顺序 | 记录首尾几个（CsrfFilter → ... → AuthorizationFilter） |
| 认证前后上下文 | `SecurityContextHolder.getContext()` 内容变化 |
| 匿名访问行为 | 未认证 → 进入 AnonymousAuthenticationFilter → 授权拒绝 |

## 4. 案例三（自选）：Bean 创建三阶段

### 4.1 断点清单（简化版）

| # | 断点位置 | 观察点 |
|---|---------|--------|
| 1 | `AbstractAutowireCapableBeanFactory.doCreateBean` | 实例化入口 |
| 2 | `populateBean`（属性填充） | 依赖注入 |
| 3 | `initializeBean`（初始化） | 初始化回调链 |
| 4 | `AbstractAutoProxyCreator.postProcessAfterInitialization` | AOP 代理时机 |

### 4.2 走读目标

```text
选一个带 @Transactional 的 Service，观察：
① 实例化 → ② 属性填充（依赖注入）→ ③ 初始化回调 → ④ 代理包装
关键观察：④ 之后 bean 的类名带 $$EnhancerBySpringCGLIB 后缀（CGLIB 代理）
```

> 💡 该案例与「Spring生态深度剖析」01 联动：断点观察 = 机制的现场验证。
