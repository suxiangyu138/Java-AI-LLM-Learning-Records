## 2. 定时任务故障排查手册

### 2.1 故障分类速查

| 故障现象 | 排查链 |
|---------|--------|
| 任务不按时跑 | ① 单线程调度器被占？② cron 时区？③ 调度线程卡死（jstack） |
| 任务执行多次 | ① 多实例未加锁？② 锁过期太早？③ 手动补跑与自动执行重叠 |
| 任务异常无感知 | ① errorHandler 未配？② 异常被吞（void 异步）？③ 日志被刷没 |
| 任务越跑越慢 | ① 积压叠加（fixedRate）② 数据量增长 ③ DB 慢查询 |
| 应用启动就执行 | ① 无 initialDelay 错峰 ② 启动风暴 |
| 停机丢任务 | ① 未配优雅关闭 ② await 超时太短 |
| 异步不生效 | ① @EnableAsync 未开 ② 同类自调用 ③ 私有方法 |
| 异步线程池打满 | ① 容量设计不足 ② 拒绝策略静默 ③ 下游变慢连锁 |

### 2.2 排查工具链

```bash
jstack <pid> | grep -A10 "task-sched-"      # 调度线程状态（定位阻塞）
jcmd <pid> Thread.dump_to_file              # 虚拟线程 dump（JDK 21+）
# 指标看板：task.execution.failure / task.overlap / queue.depth
# 日志检索：task=[任务名] instance=[pod名]（07 篇日志规范）
```

**标准排查五步：**

```text
① 看指标：失败率/重叠数/队列深度（先数据后猜测）
② 看线程：调度线程与业务线程是否卡死
③ 看日志：按任务名+实例聚合
④ 看配置：线程池参数/锁参数/时区
⑤ 复现与修复：灰度验证 + 记录复盘
```

## 3. 面试高频 15 问

**调度机制：**

**Q1：@Scheduled 的三种触发模式区别？**
fixedDelay=上次结束后等 N 毫秒（不叠加）；fixedRate=按开始时刻间隔（任务超长可能叠加/错过）；cron=日历表达式（秒级）。耗时不可控选 fixedDelay。（02 篇）

**Q2：为什么两个 @Scheduled 任务会互相阻塞？**
默认调度器单线程（ThreadPoolTaskScheduler poolSize=1，或 Boot 4 虚拟线程前的默认）——一个任务阻塞，其它任务排队。（01 篇）

**Q3：cron 表达式怎么写？日和周的互斥规则？**
六位：秒分时日月周（可加年）。日与周不能同时指定具体值，一方必须 `?`。（02 篇）

**Q4：@Scheduled 的 cron 改了为什么不生效？怎么动态化？**
注解 cron 是启动时解析进 Trigger 的快照，运行期不再重读。动态化 = SchedulingConfigurer + Trigger 每次执行前重算（nextExecutionTime 里 new CronTrigger）。（03 篇）

**Q5：@Scheduled 有自调用问题吗？**
没有——@Scheduled 由 BeanPostProcessor 直接注册方法，不走 AOP 代理。真正会失效的是任务内部调的 @Async/@Transactional 方法（代理跨类生效）。（02 篇）

**异步：**

**Q6：@Async 生效的三个条件？**
@EnableAsync 开启、从外部 Bean 代理调用（同类 this 调用失效）、方法非 private。（04 篇）

**Q7：异步方法抛异常怎么办？**
CompletableFuture 返回值 → 调用方 exceptionally 处理；void → AsyncUncaughtExceptionHandler 全局处理（生产必配，否则静默吞）。异步"失败"不可见是最大坑。（04 篇）

**Q8：线程池核心/最大/队列怎么设计？**
由平均并发（QPS×耗时）推导 core，峰值定 max，积压容忍度定 queue。拒绝策略推荐 CallerRuns（背压）而非静默丢弃。（05 篇）

**Q9：优雅关闭怎么配？**
`shutdown.await-termination=true` + `await-termination-period=30s`——停机等任务完成再销毁，超时强杀兜底。默认直接中断会丢在途任务。（05 篇）

**虚拟线程：**

**Q10：Boot 4 的调度有什么变化？**
Java 21+ 默认虚拟线程：SimpleAsyncTaskScheduler 每任务独立虚拟线程，pool-size 属性被忽略；ThreadLocal 由上下文快照传播（Boot 4.0.4+ 自动）。（06 篇）

**Q11：虚拟线程的 pinning 是什么？**
虚拟线程执行 synchronized 块/原生方法时阻塞会钉扎 carrier，优势退化。JDK 24（JEP 491）已修复；21/23 用 ReentrantLock 规避。（06 篇）

**Q12：虚拟线程下还要调线程池吗？**
大部分调优消失——改为限制**并发上限**（信号量/限流），因为外部资源（DB 连接池）仍是硬约束。（06 篇）

**可靠性：**

**Q13：定时任务失败会重试吗？**
Spring 默认不重试——异常只是记录，下次照常调度。重试要在任务内自实现（次数+指数退避+最终告警）。（07 篇）

**Q14：多实例部署任务执行几次？怎么防？**
每实例一个调度器 → 执行 N 次。ShedLock 分布式锁：@SchedulerLock 抢锁，持锁者执行；配合 lockAtMostFor（防死锁）+ lockAtLeastFor（防抖动双跑）+ 任务幂等。（08 篇）

**Q15：ShedLock 和 Quartz/XXL-Job 怎么选？**
ShedLock=给 @Scheduled 补锁（轻量、任务少）；Quartz=全功能调度框架（日历/misfire 策略）；XXL-Job=分布式任务平台（管理台/分片/告警，任务多）。规模与管理需求驱动选型。（08 篇）

## 4. 版本特性速查（2026）

| 版本线 | 关键能力 | 本体系章节 |
|--------|---------|:---:|
| Spring Framework 6.1 | PeriodicTrigger 增强、@Scheduled 优化 | 01-03 |
| Spring Boot 3.2+ | `spring.threads.virtual.enabled`（虚拟线程 opt-in） | 06 |
| Spring Boot 4.0（2025-11）/ Framework 7 | **虚拟线程默认开启**（Java 21+）、SimpleAsyncTaskScheduler、池参数忽略、上下文快照（4.0.4+） | 06 |
| JDK 24（JEP 491） | synchronized pinning 修复 | 06 |
| ShedLock 5.x | Redis/DB/ZK 多 provider、续期支持 | 08 |

> 💡 **迁移提醒**：Boot 3 → 4 时——若依赖 `spring.task.scheduling.pool.size` 的行为，需评估虚拟线程默认开启的影响（任务并发行为变化）；用 ThreadLocal 的业务确认 Boot 4.0.4+ 的上下文快照已覆盖；JDK 21 且有大量 synchronized 的场景考虑回退或升级 JDK 24。

> 🎯 **核心要点**：Spring Task 的实践 = 调度（多线程/虚拟线程防阻塞）+ 语义（fixedDelay 安全、cron 配 zone）+ 动态（Trigger 重算）+ 异步（代理三条件、异常可见）+ 容量（池或信号量）+ 可靠（幂等、锁、告警）。面试答"定时任务怎么做"的满分结构：**单实例用 @Scheduled + 多线程调度器，动态 cron 用 SchedulingConfigurer，多实例用 ShedLock，失败用指标告警 + 任务幂等**——每个选择都能讲出"为什么"。
