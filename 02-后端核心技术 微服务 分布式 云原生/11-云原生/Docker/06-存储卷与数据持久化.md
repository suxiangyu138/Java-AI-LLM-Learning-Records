## 1. 临时存储机制与持久化核心

> ⚠️ **核心前提**：Docker 容器默认"临时存储"——容器内部所有数据（软件配置、运行日志、生成文件）都存在容器自身的可写层中。**容器删除后该可写层被彻底清理，数据丢失无法恢复**。

持久化的核心作用 = 将长期数据挂载到宿主机或 Docker 管理的卷中，实现**数据与容器分离**。卷间状态共享 = 基于持久化的延伸，多容器挂载同一数据卷实现数据互通、状态同步（如多服务共用配置文件、静态资源）。

## 2. 绑定挂载（方式 1：最直观）

**核心逻辑**：宿主机上的具体文件夹 ↔ 容器内软件的指定数据存储路径双向同步（容器内新建/修改/删除 → 宿主机同步；反之亦然）。优势：数据存储位置清晰，容器删除后宿主机数据不受影响。

```bash
docker run -d -p 80:80 --name my-nginx \
  -v /host/nginx/data:/usr/share/nginx/html \
  nginx
```

**关键说明（避坑细节）**：

| 细节 | 说明 |
|------|------|
| 路径顺序 | `-v` 格式严格为**「宿主机路径:容器路径」**，不可颠倒 |
| 容器路径固定 | 右边是容器内软件的数据路径，由官方镜像固定，参考镜像官方文档 |
| 自动创建 | 无需提前手动创建宿主机文件夹，`docker run` 时自动检测并创建 |
| 覆盖行为 | 宿主机文件夹已有文件时，挂载后自动同步到容器并**覆盖容器内原有默认文件** |

## 3. Docker 管理卷（方式 2：更省心）

**核心逻辑**：Docker 系统自动创建、管理的虚拟卷，无需指定宿主机路径，存储位置由 Docker 统一管理。优势：不用记忆宿主机路径；劣势：无法直接在宿主机上找到对应文件夹（需命令查看）。

```bash
# 1. 创建一个 Docker 卷（可重复使用）
docker volume create nginx-volume

# 2. 启动容器，挂载该卷
docker run -d -p 80:80 --name my-nginx \
  -v nginx-volume:/usr/share/nginx/html \
  nginx

# 查看卷信息（默认路径）
docker volume inspect nginx-volume
docker volume ls                    # 查看所有已创建的卷
```

> 💡 **卷的复用性**：卷可重复使用，新容器或删除后的容器重新挂载同一卷即可恢复之前数据。

## 4. tmpfs 内存挂载（方式 3）

将数据存放在**容器内存**中，不写入磁盘——容器停止后数据消失：

```bash
docker run -d -p 8080:8080 \
  --tmpfs /tmp:rw,size=100m \
  my-java-app
```

| 特点 | 说明 |
|------|------|
| 存储位置 | 容器内存（RAM），不落磁盘 |
| 生命周期 | 与容器一致，停止即消失 |
| 适用场景 | 临时文件、敏感数据（不落盘更安全）、配合只读根文件系统（`--read-only --tmpfs /tmp`） |
| 性能 | 最快（纯内存读写） |

## 5. 卷间状态共享（多容器共用数据）

**核心逻辑**："多容器共用同一个数据卷"——多个容器同时挂载同一个绑定挂载文件夹或同一个 Docker 管理卷，实现数据实时同步。无需额外同步工具，且不影响容器隔离性。

**实操案例（两个 Nginx 容器共享数据）**：

```bash
# 1. 先创建一个共享卷（或用已有的卷）
docker volume create share-volume

# 2. 启动第一个 Nginx 容器，挂载共享卷
docker run -d -p 80:80 --name nginx1 \
  -v share-volume:/usr/share/nginx/html \
  nginx

# 3. 启动第二个 Nginx 容器，挂载同一个共享卷
docker run -d -p 8080:80 --name nginx2 \
  -v share-volume:/usr/share/nginx/html \
  nginx
```

**效果说明**：

- **实时同步**：向任一容器的 `/usr/share/nginx/html` 增删改文件，另一容器实时同步，两个 Nginx 展示相同静态页面；
- **数据一致性**：共用同一批数据避免冗余，修改静态页面只需一次、两容器同时生效；
- **扩展**：适用于所有软件（两个 MySQL 容器共享数据卷需注意数据库锁机制避免同时写入冲突；Python 容器与前端容器共享静态资源等），只需替换容器内挂载路径。

## 6. 三种挂载方式对比

| 维度 | 绑定挂载（Bind Mount） | Docker 管理卷（Volume） | tmpfs |
|------|----------------------|------------------------|-------|
| 存储位置 | 宿主机指定路径 | Docker 管理目录 | 容器内存 |
| 数据位置清晰 | ✅ 可直接查看修改 | ❌ 需命令查看 | - |
| 持久化 | ✅ 容器删除不影响 | ✅ 容器删除不影响 | ❌ 容器停止即消失 |
| 复用性 | 手动管理路径 | ✅ 卷可复用 | - |
| 适用 | 需要直接访问宿主机文件（配置、日志） | **推荐默认**：数据库数据、应用数据 | 临时/敏感数据 |
| 权限控制 | 支持 `:ro`/`:rw` | 支持 | - |

## 7. 注意事项与避坑

| # | 避坑点 | 说明 |
|---|--------|------|
| 1 | **路径别写反** | `-v` 格式「宿主机路径:容器路径」，顺序绝对不能颠倒。写反会导致容器内数据无法正常挂载，甚至覆盖宿主机文件夹内容造成数据丢失 |
| 2 | **权限问题** | 挂载后报 "Permission denied" 时，在 `-v` 参数末尾加权限标识：`:ro`（只读，适合共享配置文件）、`:rw`（读写，默认）<br>示例：`-v /host/nginx/data:/usr/share/nginx/html:ro` |
| 3 | **卷的删除** | Docker 管理卷不随容器删除自动删除，长期不用占用宿主机空间：`docker volume rm 卷名称`、`docker volume prune`（删除所有未使用卷，谨慎） |
| 4 | **容器路径适配** | 挂载方式完全一致，唯一要改的是**「容器内数据路径」**（MySQL 默认 `/var/lib/mysql`，Nginx 静态文件 `/usr/share/nginx/html`） |
| 5 | **绝对路径** | 绑定挂载的宿主机路径尽量用绝对路径（如 `/host/nginx/data`），避免相对路径导致挂载失败 |
| 6 | **卷命名** | Docker 管理卷名称不能含特殊字符（空格、符号），建议字母+数字组合 |

## 8. Java 应用持久化实战

### 8.1 配置文件持久化（配置与镜像分离）

```bash
mkdir -p /host/java/app/config

docker run -d -p 8080:8080 \
  -v /host/java/app/config:/app/config \
  --name my-java-app my-java-image
```

```dockerfile
# Spring Boot 通过启动参数指定配置文件路径
ENTRYPOINT ["java", "-Xms512m", "-Xmx1g", "-jar", "/app/app.jar", "--spring.config.location=/app/config/application.yml"]
```

> 💡 修改宿主机 `/host/java/app/config` 下配置，重启容器即生效，无需重新构建镜像。

### 8.2 日志持久化

```bash
docker run -d -p 8080:8080 \
  -v /host/java/app/logs:/app/logs \
  --name my-java-app my-java-image
```

> 💡 可结合日志轮转（Logback 的 rollingPolicy）避免日志文件过大；宿主机可通过 ELK 等日志分析工具直接读取挂载的日志文件。

### 8.3 数据库数据持久化（MySQL 示例）

```bash
docker run -d -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=123456 \
  -v mysql-data:/var/lib/mysql \
  -v /host/mysql/config:/etc/mysql/conf.d \
  --name mysql mysql:8.0
```

> ⚠️ Java 应用连接 Docker 中的 MySQL 时，数据库地址为**宿主机 IP（或容器 IP）**，端口为**映射的宿主机端口**（详见 [05](05-Docker网络配置与通信.md)）。

## 9. 核心要点

> 🎯 **核心要点**：
> - 容器可写层是临时的——**删除容器 = 删除数据**，持久化必须挂载；
> - 三方式：绑定挂载（路径清晰）、管理卷（省心可复用，**默认推荐**）、tmpfs（内存临时）；
> - 卷间共享 = 多容器挂同一卷，实时同步零成本；
> - Java 三场景：配置挂载（改配置不重建镜像）、日志挂载（ELK 可读）、数据库挂载（卷+配置目录）；
> - 两条铁律：路径顺序不可反、容器路径以官方镜像文档为准。
