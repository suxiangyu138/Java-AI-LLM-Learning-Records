## 1. 前期准备（必做）

| 准备项 | 说明 |
|--------|------|
| 确认 Docker 已安装并启动 | `docker --version` 查看版本；Linux 用 `systemctl start docker`，Windows/Mac 用 Docker Desktop |
| 获取对应软件的镜像 | 优先从官方仓库（Docker Hub）拉取；私有镜像需先配置私有仓库地址 |
| 了解软件的运行要求 | 提前确认软件所需端口、环境变量、数据存储路径（参考镜像官方文档） |

## 2. 镜像管理命令

```bash
docker pull nginx                      # 拉取镜像（默认 latest）
docker pull nginx:1.24                 # 指定版本
docker images                          # 列出所有镜像
docker image ls                        # 同上
docker rmi nginx:latest                # 删除镜像
docker image prune                     # 清理悬空镜像（dangling images）
docker tag src dst                     # 给镜像打标签
```

> 💡 私有镜像：先 `docker login 仓库地址` 再拉取；国内访问 Docker Hub 慢可配置镜像加速器（阿里云/网易）。

## 3. 容器生命周期命令

### 3.1 创建并启动容器（核心命令）

```bash
docker run [选项] 镜像名称:版本号 软件启动命令
```

Nginx 示例：

```bash
docker run -d -p 80:80 --name my-nginx nginx
```

**命令参数解析表（必懂）**：

| 参数 | 说明 |
|------|------|
| `-d` | 后台运行（守护进程模式），避免终端关闭后容器停止 |
| `-p 80:80` | 端口映射：宿主机 80 → 容器 80（格式`宿主机端口:容器端口`，顺序不可颠倒） |
| `--name my-nginx` | 给容器命名，方便管理（避免用容器 ID 操作） |
| `-e 变量名=变量值` | 环境变量（如 MySQL：`-e MYSQL_ROOT_PASSWORD=123456`） |
| `-v 宿主机路径:容器路径` | 数据卷挂载（详见 [06](06-存储卷与数据持久化.md)） |
| `--restart unless-stopped` | 重启策略（容器故障自动重启） |
| `-m 512m` / `--cpus 1.5` | 内存/CPU 限制（详见 [08](08-Docker安全与资源限制.md)） |

### 3.2 完整生命周期命令

```bash
docker ps                     # 运行中的容器
docker ps -a                  # 所有容器（含已停止）
docker ps -q                  # 只显示容器 ID

docker stop my-app            # 停止（发送 SIGTERM，优雅停止）
docker start my-app           # 启动已停止的容器
docker restart my-app         # 重启

docker rm my-app              # 删除容器（需先停止）
docker rm -f my-app           # 强制删除运行中的容器
```

> ⚠️ **优雅停机**：`docker stop` 先发 SIGTERM 给容器主进程，等待超时（默认 10s）后才 SIGKILL。Spring Boot 配置 `server.shutdown: graceful` 可执行优雅停机流程（详见 [03](03-Dockerfile与镜像构建.md)）。

## 4. 容器交互与调试命令

```bash
# === 日志 ===
docker logs my-app                 # 查看日志
docker logs -f my-app              # 实时跟踪日志（tail -f 效果）
docker logs --tail 100 my-app      # 只显示最后 100 行

# === 进入容器 ===
docker exec -it my-app /bin/bash   # 进入容器内部（交互式）
docker exec -it my-app /bin/sh     # Alpine 镜像用 sh
# 退出容器输入 exit
docker exec my-app ls /app         # 在容器内执行命令（非交互）

# === 文件复制 ===
docker cp /host/file my-app:/app   # 宿主机 → 容器
docker cp my-app:/app/log.log .    # 容器 → 宿主机

# === 查看详情 ===
docker inspect my-app              # 容器详细信息（JSON）
docker top my-app                  # 容器内进程
docker stats                       # 实时资源使用（内存/CPU）
```

## 5. 资源清理命令

```bash
docker system df                   # 查看 Docker 磁盘使用情况
docker system prune                # 清理所有未使用的资源
docker system prune -a --volumes   # 彻底清理（包含镜像和卷，⚠️ 慎用）
docker volume prune                # 清理未使用的数据卷（详见 06）
```

## 6. 关键注意事项与避坑

| # | 注意事项 | 说明 |
|---|----------|------|
| 1 | **端口冲突** | 提示"端口已被占用"时，更换宿主机端口（`-p 8080:80`）或停止占用端口的服务 |
| 2 | **数据持久化** | 容器默认临时存储，MySQL 数据库、Nginx 日志需长期保存必须 `-v` 挂载数据卷，否则容器删除后数据丢失 |
| 3 | **镜像版本选择** | 优先官方镜像和稳定版本，**避免 latest**，防止版本更新导致不兼容 |
| 4 | **权限问题** | 部分软件需要 root 权限可加 `--privileged=true`（⚠️ 谨慎使用，有安全风险，详见 08） |
| 5 | **容器隔离性** | 每个容器独立隔离环境，配置/依赖只作用于当前容器，不影响宿主机和其他容器 |

## 7. 常见问题排查表

| 问题 | 排查方向 |
|------|----------|
| 容器启动后立即退出 | 大概率是软件启动命令错误，或缺少环境变量；`docker logs` 查看报错，补充对应配置 |
| 外部无法访问容器内软件 | 检查宿主机防火墙是否开放映射端口；确认端口映射命令正确（`宿主机端口:容器端口`，顺序不可颠倒） |
| 镜像拉取失败 | 检查网络连接；无法访问 Docker Hub 时配置国内镜像源（阿里云、网易），再重新拉取 |
| 容器内应用连接不到外部服务 | 容器内 `localhost` 指向容器自身；宿主机服务用 `172.17.0.1`（Linux）或 `host.docker.internal`（Windows/Mac），详见 [05](05-Docker网络配置与通信.md) |

## 8. 核心要点

> 🎯 **核心要点**：
> - 运行软件三步：`docker pull`（拿镜像）→ `docker run`（起容器）→ `docker logs`（验状态）；
> - 参数三件套必配：`-d`（后台）、`-p`（端口映射）、`--name`（命名）；
> - 数据要持久化必须 `-v` 挂载；版本要固定避免 latest；
> - 排查顺序：`docker ps -a`（活着吗）→ `docker logs`（报什么错）→ `docker exec`（进去看）；
> - `docker stop` 是优雅停机（SIGTERM），配合 Spring Boot graceful shutdown 实现平滑下线。
