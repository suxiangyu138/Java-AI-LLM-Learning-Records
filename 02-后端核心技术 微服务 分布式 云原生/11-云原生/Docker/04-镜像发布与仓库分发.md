## 1. 分发核心认知与选型

**Java 后端关注的 4 大痛点**（选型依据）：

| 痛点 | 说明 |
|------|------|
| 安全性 | 镜像可能含数据库密码、接口密钥、核心业务代码 |
| 效率 | 微服务镜像数量多、体积大，拉取/推送需快速稳定 |
| 版本管理 | 版本追溯、回滚，多环境用指定版本 |
| 权限控制 | 限制推送/拉取权限，避免未授权操作、篡改镜像 |

**公有 vs 私有分发对比**：

| 维度 | 公有仓库（Docker Hub/阿里云公有版） | 私有仓库（Registry/Harbor/阿里云私有版） |
|------|-----------------------------------|------------------------------------------|
| 访问权限 | 公开镜像任意拉取，私有镜像账号授权 | 全权限可控（推送/拉取/管理细分） |
| 安全性 | 较低，不适合含敏感信息的企业镜像 | 较高，可隔离外部网络 |
| 分发效率 | 依赖公网带宽 | 内部网络，速度快 |
| 适用 Java 场景 | 个人开发、开源项目、公共基础镜像 | 企业级应用、微服务、多环境部署 |
| 维护成本 | 无 | 需维护私有仓库服务器 |

> 💡 **结合使用**：基础镜像（JDK、Tomcat）从公有仓库拉取，业务镜像（用户服务、订单服务）通过私有仓库分发——兼顾效率与安全。

## 2. tag / push / pull 命令（Docker Hub）

> 核心规则：公有仓库推送时标签必须遵循 **"仓库地址/账号名/仓库名:版本号"** 格式，否则推送失败。

```bash
# 1. 本地镜像打标签（关键步骤）
# 格式：docker tag 本地镜像名:版本号 docker.io/账号名/仓库名:版本号
docker tag springboot-demo:1.0.0 docker.io/your-username/springboot-demo:1.0.0

# 2. 登录 Docker Hub
docker login docker.io

# 3. 推送镜像
docker push docker.io/your-username/springboot-demo:1.0.0

# 4. 目标服务器拉取镜像（部署场景）
docker pull docker.io/your-username/springboot-demo:1.0.0

# 5. 拉取后启动容器（Java 应用部署）
docker run -d -p 8080:8080 docker.io/your-username/springboot-demo:1.0.0
```

> 💡 标签版本号需与 Java 应用版本一致（主版本.次版本.修订号），**避免使用 latest**。国内开发者优先选国内仓库（阿里云容器镜像服务），解决 Docker Hub 国内慢的问题（或配置镜像加速器）。

## 3. 公有分发注意事项

| # | 注意 | 说明 |
|---|------|------|
| 1 | 禁止推送含敏感信息的镜像 | 公有仓库任意用户可访问；敏感信息用环境变量注入而非打包进镜像 |
| 2 | 标签格式严格 | 遵循"仓库地址/账号名/仓库名:版本号"；版本号与应用版本一致 |
| 3 | 国内访问优化 | Docker Hub 慢可配镜像加速器（如阿里云加速器） |
| 4 | 权限控制 | 私有仓库严格控制授权账号 |

## 4. 私有分发方案选型

| 维度 | 自定义 Registry（Docker 官方） | Harbor | 阿里云私有仓库 |
|------|-------------------------------|--------|---------------|
| 核心特点 | 轻量、简洁，仅基础推送/拉取/权限 | 漏洞扫描、镜像签名、多环境隔离 | 无需部署，按需付费 |
| 资源占用 | 极低（几十 MB 内存） | 较高（多组件：数据库、扫描工具） | 无本地占用 |
| 维护成本 | 极低 | 较高 | 无 |
| Java 场景 | 中小型团队、单体、微服务初期 | 中大型团队、微服务大规模部署 | 阿里云生态团队 |

| 场景 | 推荐 |
|------|------|
| 个人/开源 | 公有分发 |
| 小型企业/单一应用 | Docker Registry（性价比最优） |
| 中大型企业/微服务 | Harbor 或阿里云私有版 |
| 国内团队 | 国内仓库 |

## 5. 自建 Registry 部署

前置：Linux（CentOS/Ubuntu）+ Docker **1.13 以上**；开放 **5000 端口**；规划存储路径（如 /data/registry）。

```bash
# 步骤1：拉取 Registry 官方镜像
docker pull registry:latest

# 步骤2：创建存储目录（数据持久化，权限 777 避免权限不足）
mkdir -p /data/registry
chmod 777 /data/registry

# 步骤3：启动 Registry 容器（端口映射+数据挂载+后台运行）
docker run -d \
  --name custom-registry \
  -p 5000:5000 \
  -v /data/registry:/var/lib/registry \
  --restart=always \
  registry:latest

# 步骤4：验证部署成功
curl http://localhost:5000/v2/_catalog
# 成功返回：{"repositories":[]}（表示暂无镜像）
```

> ⚠️ Registry 容器默认将镜像数据存容器内部，**删除容器数据即丢失**，必须数据卷挂载。

## 6. Registry 认证与安全（htpasswd/HTTPS/IP 限制）

### 6.1 htpasswd 认证（Java 团队必备）

默认无权限控制，任何人可推送/拉取，有安全风险：

```bash
# 步骤1：创建权限认证文件
mkdir -p /data/registry/auth

# 步骤2：安装 htpasswd 工具
yum install -y httpd-tools        # CentOS
# apt-get install -y apache2-utils   # Ubuntu

# 步骤3：生成用户和密码（示例：用户 java-dev，密码 123456）
htpasswd -Bc /data/registry/auth/htpasswd java-dev

# 步骤4：重启 Registry 容器，启用权限控制
docker stop custom-registry && docker rm custom-registry
docker run -d \
  --name custom-registry \
  -p 5000:5000 \
  -v /data/registry:/var/lib/registry \
  -v /data/registry/auth:/auth \
  -e REGISTRY_AUTH=htpasswd \
  -e REGISTRY_AUTH_HTPASSWD_REALM="Registry Realm" \
  -e REGISTRY_AUTH_HTPASSWD_PATH=/auth/htpasswd \
  --restart=always \
  registry:latest

# 步骤5：验证（未登录 401，登录后正常）
curl http://服务器IP:5000/v2/_catalog        # 401 权限不足
docker login 服务器IP:5000                    # 输入用户密码
curl http://服务器IP:5000/v2/_catalog        # 正常返回
```

### 6.2 HTTPS 加密（生产级必备）

默认 HTTP 明文传输（镜像、密码泄露风险）：

```bash
docker run -d \
  --name custom-registry \
  -p 443:5000 \                                  # HTTPS 默认端口 443
  -v /data/registry:/var/lib/registry \
  -v /data/registry/auth:/auth \
  -v /data/registry/certs:/certs \
  -e REGISTRY_AUTH=htpasswd \
  -e REGISTRY_AUTH_HTPASSWD_PATH=/auth/htpasswd \
  -e REGISTRY_HTTP_TLS_CERTIFICATE=/certs/your-cert.crt \
  -e REGISTRY_HTTP_TLS_KEY=/certs/your-cert.key \
  --restart=always \
  registry:latest
```

### 6.3 限制访问 IP（防火墙）

```bash
# 仅允许指定 IP 访问 5000 端口（CentOS）
firewall-cmd --permanent --add-rich-rule="rule family=\"ipv4\" source address=\"192.168.1.10\" port protocol=\"tcp\" port=\"5000\" accept"
firewall-cmd --reload
```

## 7. Registry 高级运维（GC/高可用）

### 7.1 镜像 GC 清理（Registry 不支持自动清理）

```bash
#!/bin/bash
# 清理 30 天前的镜像，保留最近 10 个版本
docker exec custom-registry registry garbage-collect /etc/docker/registry/config.yml --delete-untagged=true
# 清理无用镜像层
docker system prune -f
```

```bash
crontab -e    # 添加定时任务：0 2 * * * /root/clean-registry.sh（每天凌晨 2 点）
```

标签规范（便于脚本清理）：`Registry地址:端口/应用名:主版本.次版本.修订号-环境`，如 `服务器IP:5000/springboot-user:1.0.0-dev`、`服务器IP:5000/springboot-order:1.0.0-prod`。

### 7.2 高可用（NFS 共享存储）

思路：多台服务器部署 Registry，共享存储（NFS）实现镜像数据同步，避免单节点故障无法拉取。

```bash
# NFS 服务器创建共享目录（如 /nfs/registry）
# 每台 Registry 服务器挂载
mount -t nfs NFS服务器IP:/nfs/registry /data/registry
# 每台按基础部署启动容器并挂载 NFS 目录
```

## 8. Harbor 企业级私有仓库

### 8.1 部署（依赖 Docker + Compose）

```bash
# 1. 下载 Harbor 安装包
wget https://github.com/goharbor/harbor/releases/download/v2.8.0/harbor-offline-installer-v2.8.0.tgz
# 2. 解压
tar -zxvf harbor-offline-installer-v2.8.0.tgz
cd harbor
# 3. 配置：复制模板并修改核心配置
cp harbor.yml.tmpl harbor.yml
vi harbor.yml
#    修改：1. hostname 为服务器 IP 或域名
#          2. harbor_admin_password（管理员密码）
#          3. 关闭 HTTPS（测试环境；生产建议开启）
# 4. 安装并启动
./install.sh
docker-compose up -d
```

### 8.2 权限配置与镜像推送

- **权限配置**：创建项目（如 java-dev，选"私有"）→ 新建用户（dev-user、ops-user）→ 项目"成员"分配权限（开发：推送+拉取；运维：管理员）；
- **标签规范**：`私有仓库地址/项目名/应用名:版本号-环境`，如 `192.168.1.100/java-dev/springboot-user:1.0.0-dev`。

```bash
# 本地手动推送
docker login 192.168.1.100
# 若提示无法连接，需配置信任列表：
# /etc/docker/daemon.json 加入后重启 Docker：
```

```json
{ "insecure-registries": ["192.168.1.100"] }
```

```bash
docker tag springboot-user:1.0.0-dev 192.168.1.100/java-dev/springboot-user:1.0.0-dev
docker push 192.168.1.100/java-dev/springboot-user:1.0.0-dev
```

```bash
# 部署场景拉取
docker login 192.168.1.100 -u dev-user -p 123456
docker pull 192.168.1.100/java-dev/springboot-user:1.0.0-dev
docker run -d -p 8080:8080 192.168.1.100/java-dev/springboot-user:1.0.0-dev
```

### 8.3 Harbor 企业级高级配置

| 配置 | 说明 |
|------|------|
| 版本管理与回滚 | 配置**镜像保留策略**（保留最近 10 个版本，防磁盘不足）；出问题快速拉历史版本回滚 |
| 安全加固 | 镜像签名（构建时签名、拉取时校验）；漏洞扫描（定期扫描依赖/系统漏洞）；网络隔离（内部网络部署） |
| 多环境隔离 | java-dev（开发测试）/ java-test / java-prod（仅运维可推拉）三个项目隔离 |

## 10. 分发高频避坑清单

| # | 报错/现象 | 成因 | 解决方案 |
|---|----------|------|----------|
| 1 | `denied: requested access to the resource is denied` | 标签格式错误、未登录、无推送权限 | 检查标签格式；`docker login`；Harbor 添加项目成员并分配权限 |
| 2 | 私有仓库拉取慢或无法拉取 | 带宽不足、网络隔离、未配信任列表 | 内部网络/VPN；daemon.json 加信任列表 |
| 3 | Java 镜像含敏感信息泄露 | 密码/密钥打包进镜像、公有仓库公开推送 | 环境变量注入；敏感应用用私有分发 |
| 4 | 微服务多镜像版本混乱 | 标签不规范未区分环境/版本 | 统一标签规范（应用名+版本+环境） |
| 5 | CI/CD 报 `docker login failed` | Jenkins 未配仓库登录信息 | Jenkins 添加凭证；检查账号密码与访问权限 |
| 6 | `http: server gave HTTP response to HTTPS client` | Docker 默认要求 HTTPS，HTTP 的 Registry 未配信任 | daemon.json 加 `"insecure-registries": ["服务器IP:5000"]` |
| 7 | 登录报 `authentication required` | 密码错误、认证文件路径配置错误 | 确认密码；检查 htpasswd 路径与挂载 |
| 8 | Registry 重启后镜像数据丢失 | 未配数据卷挂载或路径错误 | 加 `-v /data/registry:/var/lib/registry` |
| 9 | Maven 插件推送失败 `repository does not exist` | 标签缺 Registry 地址、Registry 未运行 | 标签含"服务器IP:5000/镜像名:版本号"；curl 验证 |
| 10 | Registry 磁盘空间不足 | 迭代频繁未清理过期镜像 | GC 清理脚本 + 定时任务 |

## 11. 核心要点

> 🎯 **核心要点**：
> - 标签铁律：`仓库地址/账号名/仓库名:版本号`，版本=应用版本，禁止 latest；
> - 选型：小团队 Registry（几十 MB 内存）→ 中大型 Harbor（扫描/签名/隔离）；
> - 私有仓库三件安全：htpasswd 认证 + HTTPS（生产必须）+ IP 白名单；
> - 数据持久化：Registry 数据必须挂载卷，否则删容器即丢数据；
> - 生产免密：登录信息预配到服务器 Docker 配置；
> - 敏感信息永不打进镜像——环境变量注入是唯一正确姿势。
