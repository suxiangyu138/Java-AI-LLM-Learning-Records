## 1. networks 顶层键字段全解

```yaml
networks:
  backend:
    driver: bridge                 # 默认 bridge；overlay 需 Swarm
    driver_opts:                   # 驱动特定选项
      com.docker.network.bridge.name: br-backend
    ipam:                          # IP 地址管理
      driver: default
      config:
        - subnet: 172.20.0.0/16
          gateway: 172.20.0.1
          ip_range: 172.20.5.0/24
    attachable: true               # 独立容器可手动接入（overlay 用）
    internal: true                 # 禁止外部访问（生产隔离）
    external: false                # true = 使用已存在的网络
    name: my-app-backend           # 实际网络名（external 时必配）
```

| 字段 | 默认 | 说明 |
|------|------|------|
| `driver` | bridge | bridge（单机）/ overlay（Swarm）/ host / none |
| `driver_opts` | - | 驱动选项（如设置网桥名） |
| `ipam.config.subnet` | 自动 | 指定子网（多网络时避免冲突） |
| `ipam.config.gateway` | 自动 | 网关 IP |
| `attachable` | false | 允许 `docker run --network` 手动接入（overlay 场景） |
| `internal` | false | **内部网络**：容器间可通信，外部不可达（生产隔离关键） |
| `external` | false | true 时 Compose 不创建，使用已存在网络 |
| `name` | 键名 | 实际网络名；与 `external: true` 配合指定存量网络 |

## 2. 网络接入方式：容器侧配置

```yaml
services:
  app:
    networks:
      - backend                    # 加入单个网络（短语法）
    # 长语法：指定别名/IP
    networks:
      backend:
        aliases:                   # 网络别名（其他服务可用此名访问）
          - app-backend
        ipv4_address: 172.20.0.10  # 固定 IP（需 ipam 子网配合）
  db:
    networks:
      - backend
```

| 网络特性 | 说明 |
|----------|------|
| 默认 DNS 解析 | 同网络内服务可用**服务名**互相访问（Compose 自动维护） |
| `aliases` | 给服务增加网络别名（同服务多别名场景） |
| 多网络 | 一个服务可加入多个网络（网关服务连通前后端） |
| 服务发现 | 与容器名通信同理——`jdbc:mysql://db:3306` |

## 3. volumes 顶层键字段全解

```yaml
volumes:
  mysql-data:
    driver: local                    # 卷驱动（local/nfs/云驱动）
    driver_opts:                     # 驱动选项
      type: nfs
      o: addr=192.168.1.50,nolock,soft
      device: :/nfs/mysql
    external: false                  # true = 使用已存在卷
    name: prod-mysql-data            # 实际卷名
```

| 字段 | 默认 | 说明 |
|------|------|------|
| `driver` | local | 卷驱动（local/NFS/云厂商） |
| `driver_opts` | - | 驱动选项（NFS 挂载参数等） |
| `external` | false | true 时 Compose 不创建卷，使用已存在卷 |
| `name` | 键名 | 实际卷名（external 时必配） |

> 💡 **NFS 共享卷**（多机场景）：`driver_opts` 配 `type: nfs` + `o: addr=...` + `device: :/path`，实现多主机共享数据（配合 Swarm 部署）。

## 4. 三种挂载写法（Compose 版）

### 4.1 短语法（-v 风格）

```yaml
services:
  app:
    volumes:
      - mysql-data:/var/lib/mysql        # 命名卷
      - ./config:/app/config:ro          # 绑定挂载（只读）
      - /host/logs:/app/logs             # 绝对路径绑定
```

格式：`源:目标[:模式]`，模式支持 `ro`/`rw`/`z`/`Z`（SELinux）。

### 4.2 长语法（推荐，字段清晰）

```yaml
services:
  app:
    volumes:
      - type: volume                    # volume | bind | tmpfs | image
        source: mysql-data
        target: /var/lib/mysql
        read_only: false
        volume:
          nocopy: true                  # 不复制镜像内已有数据到空卷
      - type: bind
        source: ./config
        target: /app/config
        bind:
          create_host_path: true        # 宿主机路径不存在时创建
      - type: tmpfs
        target: /tmp
        tmpfs:
          size: 104857600               # 100MB（字节）
      - type: image                     # v2.40.3+：挂载镜像内容为卷
        source: nginx:alpine
        target: /usr/share/nginx/html
```

| type | 说明 | 场景 |
|------|------|------|
| `volume` | 命名卷（推荐默认） | 数据库数据 |
| `bind` | 绑定宿主机路径 | 配置/源码/日志 |
| `tmpfs` | 内存挂载（不落盘） | 临时/敏感数据 |
| `image` | 挂载镜像内容（新特性） | 静态资源注入 |

### 4.3 文件级挂载：configs 与 secrets

```yaml
services:
  app:
    configs:
      - source: app-config
        target: /app/config/application.yml
        uid: "1000"                     # 可选：文件属主
        mode: 0440                      # 可选：文件权限
    secrets:
      - db-password
configs:
  app-config:
    file: ./application.yml             # 从文件读取
    # 或 content: | 直接内联
secrets:
  db-password:
    file: ./secrets/db-password.txt
    # 或 environment: DB_PASSWORD       # 从环境变量读取
```

| 特性 | configs | secrets |
|------|:---:|:---:|
| 只读挂载 | ✅ | ✅ |
| 默认路径 | 按 target 指定 | `/run/secrets/<name>` |
| 内容来源 | file / content / external | file / environment / external |

> ⚠️ 敏感信息**不应写入 YAML**——用 `.env`、secret 文件或平台 secrets（详见 [04](04-多环境与配置管理.md)）。

## 5. 共享卷与数据同步模式

```yaml
services:
  nginx1:
    image: nginx
    volumes:
      - share-volume:/usr/share/nginx/html
  nginx2:
    image: nginx
    volumes:
      - share-volume:/usr/share/nginx/html
volumes:
  share-volume:
```

| 模式 | 适用 |
|------|------|
| 多容器挂同一命名卷 | 静态资源、配置、日志共享（实时同步） |
| 容器间数据传递 | 生产者写卷、消费者读卷 |
| 只读挂载共享 | `:ro` 防止误改（共享配置推荐） |

> ⚠️ 数据库共享卷注意锁机制：两个 MySQL 同时写同一卷有数据损坏风险——数据库用主从复制而非共享卷。

## 6. 外部资源：external 与已存在资源

```yaml
networks:
  shared-net:
    external: true
    name: my-company-shared-net    # 使用已存在的网络

volumes:
  legacy-data:
    external: true
    name: prod-legacy-data         # 使用已存在的卷

secrets:
  db-password:
    external: true                 # 使用 Swarm/平台 secrets
```

| 场景 | 说明 |
|------|------|
| 跨项目共享网络 | 多个 Compose 项目接入同一网络互相通信 |
| 存量数据卷 | 容器删除重建后数据不丢（`external: true` 防止误删） |
| 平台管理资源 | Swarm secrets / K8s 管理的资源标记 external |

> 💡 与 `external: false`（默认，Compose 管理生命周期）对比：external 资源 **Compose 不创建也不删除**——防止 `down` 时误删共享数据。

## 7. 生产网络隔离实践

```yaml
services:
  app:
    networks: [backend, frontend]    # 网关式：前后端网络桥接
  db:
    networks: [backend]              # 数据库只在 backend，外部不可达
  redis:
    networks: [backend]
networks:
  backend:
    driver: bridge
    internal: true                   # 数据库/缓存网络：禁止外部访问
  frontend:
    driver: bridge                   # 应用对外网络：仅暴露必要端口
```

| 实践 | 说明 |
|------|------|
| 内外网分离 | frontend（对外）+ backend（internal，DB/Redis 不可达外部） |
| 最小暴露 | 只有 app 映射端口到宿主机，DB/Redis 零映射 |
| IPAM 固定子网 | 多项目部署时避免子网冲突 |
| 加密 overlay | Swarm 场景 `driver: overlay` + `encrypted` 选项 |

## 8. 核心要点

> 🎯 **核心要点**：
> - networks 五字段：driver/ipam/attachable/internal/external——`internal: true` 是生产隔离的关键开关；
> - volumes 四 type：volume（默认推荐）/bind/tmpfs/image（新特性）；
> - 长语法挂载字段清晰（read_only/create_host_path/nocopy），生产推荐；
> - `external: true` = 资源不受 Compose 生命周期管理（防 down 误删共享数据）；
> - configs/secrets 只读文件挂载，敏感信息不进 YAML；
> - 内外网分离 + 最小端口暴露是 Compose 生产网络标配。
