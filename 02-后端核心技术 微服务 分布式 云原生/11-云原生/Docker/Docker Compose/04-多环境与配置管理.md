## 1. .env 文件与变量插值

### 1.1 变量插值语法

| 语法 | 行为 |
|------|------|
| `${VAR}` | 引用变量（未定义则警告并替换为空） |
| `${VAR:-default}` | 未定义或为空时用默认值 |
| `${VAR-default}` | 仅未定义时用默认值（空值保留） |
| `${VAR:?err}` | 未定义时报错退出（强制必填） |
| `${VAR:+alt}` | 已定义且非空时用 alt（替代值） |

```yaml
services:
  app:
    environment:
      SPRING_PROFILES_ACTIVE: ${SPRING_PROFILES_ACTIVE:-dev}   # 默认 dev
      DB_PASSWORD: ${DB_PASSWORD:?DB_PASSWORD 未设置}          # 必填校验
      DB_HOST: ${DB_HOST:-db}
```

```bash
# .env（与 compose.yaml 同目录，自动加载）
SPRING_PROFILES_ACTIVE=prod
DB_PASSWORD=root123
DB_HOST=mysql-prod
```

### 1.2 变量来源优先级（高 → 低）

```text
① Shell 环境变量（当前终端 export）
② --env-file 指定的文件
③ 项目根目录 .env 文件（默认自动加载）
④ Compose 文件内的默认值（${VAR:-default}）
```

> ⚠️ **注意**：`.env` 只用于**变量插值**（Compose 解析时替换），不会自动注入容器环境变量——容器内变量要显式 `environment` 引用或 `env_file`。`env_file` 与 `.env` 是两个概念！

```yaml
services:
  app:
    env_file:
      - ./app.env          # 注入容器内的变量文件
```

## 2. 多文件 -f 合并与环境分层

### 2.1 标准三层结构

```text
compose.yaml                # 基础：所有环境共用的服务定义
compose.dev.yaml            # 开发覆盖：源码挂载、调试端口、dev profile
compose.prod.yaml           # 生产覆盖：资源限制、健康检查、密码环境变量化
```

```bash
docker compose -f compose.yaml -f compose.dev.yaml up -d
docker compose -f compose.yaml -f compose.prod.yaml up -d
```

### 2.2 合并规则速记

```text
① 后面的文件覆盖前面的（字段级合并，非整块替换）
② 标量字段：后覆盖前
③ 序列字段（ports/environment 列表）：按索引合并
④ 映射字段（environment map / volumes）：键级合并
⑤ 验证：docker compose -f A -f B config
```

### 2.3 环境变量驱动多环境（无需多文件）

```yaml
# compose.yaml + .env（COMPOSE_PROFILES 控制）
services:
  app:
    image: my-app:${APP_VERSION:-1.0.0}
    environment:
      SPRING_PROFILES_ACTIVE: ${SPRING_PROFILES_ACTIVE:-dev}
    ports:
      - "${APP_PORT:-8080}:8080"
```

```bash
# 开发
SPRING_PROFILES_ACTIVE=dev docker compose up -d
# 生产
SPRING_PROFILES_ACTIVE=prod APP_VERSION=1.0.3 docker compose up -d
```

## 3. profiles：一份文件管多场景

```yaml
services:
  app:
    image: my-app:1.0
    # 核心服务：无 profile，总是启动

  grafana:
    image: grafana/grafana
    profiles: ["monitoring"]          # 监控：按需启动

  mailhog:
    image: mailhog/mailhog
    profiles: ["debug"]               # 调试邮件：按需启动

  test-db:
    image: postgres:16
    profiles: ["test"]                # 测试数据库：按需启动

  # 生产专属服务（反向代理）
  nginx:
    image: nginx:alpine
    profiles: ["prod"]
```

```bash
docker compose up -d                                      # 只有 app
docker compose --profile monitoring up -d                 # app + grafana
docker compose --profile debug --profile monitoring up -d # 组合
docker compose --profile test run test-db                 # 一次性
COMPOSE_PROFILES=prod docker compose up -d                # 环境变量方式
```

| 典型 profile | 服务 |
|--------------|------|
| `monitoring` | Prometheus、Grafana、cAdvisor |
| `debug` | Mailhog、Adminer、调试工具 |
| `test` | 测试数据库、mock 服务 |
| `prod` | Nginx 反代、生产专属组件 |

> 🎯 **profiles vs 多文件**：同一服务的"多场景开关"用 profiles（监控/调试）；"多环境的整体差异"用多文件（dev/prod 覆盖）。两者可组合使用。

## 4. configs：配置文件注入

```yaml
services:
  app:
    configs:
      - source: app-config
        target: /app/config/application.yml    # 覆盖到指定路径
        mode: 0440
      - source: nginx-conf
        target: /etc/nginx/nginx.conf

configs:
  app-config:
    file: ./config/application.yml     # 从文件
  nginx-conf:
    content: |                          # 内联内容（简单配置）
      events {}
      http { server { listen 80; } }
  external-config:
    external: true                      # 平台管理的外部配置
```

| 来源 | 写法 | 场景 |
|------|------|------|
| `file` | 从文件读取 | 复杂配置（application.yml） |
| `content` | 内联内容 | 简短配置 |
| `external` | 平台资源 | Swarm/K8s 管理的配置 |

> 💡 **热更新**：挂载为文件的 configs 修改后重启服务生效（`docker compose restart app`）；不重建镜像——这正是"配置与镜像分离"的 Compose 版实现。

## 5. secrets：敏感数据注入

```yaml
services:
  app:
    secrets:
      - db-password
      - source: redis-password
        target: /run/secrets/redis-pass    # 自定义路径

secrets:
  db-password:
    file: ./secrets/db-password.txt        # 从文件（不提交 Git）
  redis-password:
    environment: REDIS_PASSWORD            # 从环境变量
  vault-secret:
    external: true                         # Swarm/K8s 平台 secrets
```

```bash
# 容器内读取（默认路径）
cat /run/secrets/db-password

# Spring Boot 读取
# spring.datasource.password=${DB_PASSWORD_FILE:/run/secrets/db-password}
```

| 安全实践 | 说明 |
|----------|------|
| secrets 文件不入 Git | `.gitignore` 排除 `secrets/` 目录 |
| 不 echo 到日志 | 应用侧禁止打印敏感值 |
| 不嵌入 YAML | 用 file/environment/external 三种来源 |
| 权限收紧 | 默认 `0440`，按需调整 |

## 6. 日志配置

```yaml
services:
  app:
    logging:
      driver: json-file                 # 默认驱动
      options:
        max-size: "10m"                 # 单个日志文件上限
        max-file: "3"                   # 保留文件数（轮转）
        # driver: syslog / gelf / fluentd / loki 等按需选择

  # 生产建议：限制日志大小，防止磁盘写满
  db:
    logging:
      options:
        max-size: "20m"
        max-file: "5"
```

```bash
docker compose logs -f app              # 查看服务日志
docker compose logs --tail=100 app      # 只看末尾 100 行
docker compose logs -f --no-color app   # 无颜色输出（管道处理）
```

> ⚠️ 默认 json-file 驱动**无大小限制**——日志写满磁盘是生产事故高发点；`max-size` + `max-file` 是必配项。集中式日志（ELK/Loki）用对应 driver。

## 7. 完整多环境示例

```yaml
# compose.yaml（基础，提交 Git）
name: order-app
services:
  app:
    build: .
    image: order-app:${APP_VERSION:-dev}
    environment:
      SPRING_PROFILES_ACTIVE: ${SPRING_PROFILES_ACTIVE:-dev}
      DB_URL: jdbc:mysql://db:3306/orders?useSSL=false
      DB_PASSWORD: ${DB_PASSWORD:?DB_PASSWORD 必须设置}
    depends_on:
      db:
        condition: service_healthy
    ports:
      - "${APP_PORT:-8080}:8080"
    profiles: []
  db:
    image: mysql:8.0
    environment:
      MYSQL_ROOT_PASSWORD: ${DB_PASSWORD}
      MYSQL_DATABASE: orders
    volumes:
      - db-data:/var/lib/mysql
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
      interval: 10s
      timeout: 5s
      retries: 5
  prometheus:
    image: prom/prometheus
    profiles: ["monitoring"]
volumes:
  db-data:
```

```yaml
# compose.dev.yaml（开发覆盖）
services:
  app:
    volumes:
      - ./src:/app/src                  # 源码挂载（热重载）
      - ~/.m2:/root/.m2                 # 共享 Maven 仓库
    ports:
      - "5005:5005"                     # 远程调试
    environment:
      JAVA_TOOL_OPTIONS: "-agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=*:5005"
```

```yaml
# compose.prod.yaml（生产覆盖）
services:
  app:
    image: registry:5000/order-app:${APP_VERSION}
    restart: unless-stopped
    deploy:
      resources:
        limits: { cpus: '1', memory: 1G }
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8080/actuator/health"]
      interval: 15s
      timeout: 5s
      retries: 3
      start_period: 40s
    logging:
      options: { max-size: "10m", max-file: "3" }
  db:
    volumes:
      - /data/prod/mysql:/var/lib/mysql
```

```bash
# 启动命令
docker compose -f compose.yaml -f compose.dev.yaml up -d          # 开发
docker compose -f compose.yaml -f compose.prod.yaml up -d         # 生产
docker compose -f compose.yaml --profile monitoring up -d         # 带监控
docker compose config                                             # 验证合并结果
```

## 8. 核心要点

> 🎯 **核心要点**：
> - 变量插值四语法：`${VAR}` / `${VAR:-def}` / `${VAR:?必填}` / `${VAR:+alt}`；
> - `.env`（插值用）≠ `env_file`（注入容器用）——两个概念别混淆；
> - 多文件 `-f` 合并：标量覆盖、序列按索引、映射按 key；`config` 命令验证；
> - **profiles 管"场景开关"（监控/调试/测试库），多文件管"环境差异"（dev/prod）**——可组合；
> - configs（配置，热更新靠 restart）与 secrets（敏感，只读 /run/secrets）分工明确；
> - 日志 `max-size` + `max-file` 必配，防磁盘写满。
