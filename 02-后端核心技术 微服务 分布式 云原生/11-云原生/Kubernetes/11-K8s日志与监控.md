## 1. K8s可观测性三支柱

```text
可观测性 (Observability) = Logs + Metrics + Traces

┌─────────────────────────────────────────────────────────┐
│ Logs (日志)      │ Metrics (指标)      │ Traces (链路)    │
│─────────────────────────────────────────────────────────│
│ 记录什么发生了     │ 量化系统状态         │ 追踪请求经过的路径 │
│ EFK/Loki          │ Prometheus+Grafana  │ Jaeger/SkyWalking│
│ "为什么挂了？"     │ "趋势如何？"         │ "慢在哪里？"     │
└─────────────────────────────────────────────────────────┘
```

### 1.1 K8s日志的特殊性

```text
传统部署：日志写在文件中 → SSH上去看
K8s部署：Pod随时销毁重建 → 日志随Pod消失！

解决方案：
  ✅ 应用日志直接输出到 stdout/stderr（K8s自动收集）
  ✅ 集中式日志平台（Elasticsearch + Fluentd + Kibana）
  ✅ 日志中注入TraceId（关联Metrics和Traces）
```

## 2. 日志管理：EFK技术栈

### 2.1 EFK架构

```text
┌──────────┐    ┌──────────┐    ┌──────────────┐    ┌──────────┐
│   Pod    │───→│ Fluentd  │───→│Elasticsearch │───→│  Kibana  │
│ stdout   │    │ (Daemon  │    │  (存储+索引) │    │ (可视化) │
│ stderr   │    │  Set)    │    │              │    │          │
└──────────┘    └──────────┘    └──────────────┘    └──────────┘

Fluentd以DaemonSet部署（每个Node一个），自动收集该Node上所有Pod日志
```

### 2.2 SpringBoot日志输出到stdout

```yaml
# application.yml
logging:
  pattern:
    console: "%d{yyyy-MM-dd HH:mm:ss} [%thread] %-5level %logger{36} - [%X{traceId}] %msg%n"
    # ↑ 输出到控制台 = stdout，K8s自动收集
```

```xml
<!-- logback-spring.xml: JSON格式（更利于Elasticsearch索引） -->
<appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
    <encoder class="net.logstash.logback.encoder.LogstashEncoder"/>
</appender>
```

### 2.3 kubectl日志命令

```bash
# 查看实时日志
kubectl logs -f deployment/user-service

# 查看最近100行
kubectl logs --tail=100 deployment/user-service

# 查看前一个崩溃容器的日志（排查CrashLoopBackOff）
kubectl logs --previous deployment/user-service

# 查看特定Pod日志
kubectl logs user-service-7d4f8c9b-abcde

# 多容器Pod指定容器
kubectl logs user-service-7d4f8c9b-abcde -c sidecar
```

## 3. 监控：Prometheus + Grafana

### 3.1 Prometheus架构

```text
Prometheus Server → 定期Pull Metrics → 存储时序数据 → Grafana查询+可视化

数据来源：
  ✅ Node Exporter：Node的CPU/内存/磁盘/网络
  ✅ cAdvisor (内置在kubelet)：容器级CPU/内存
  ✅ kube-state-metrics：K8s资源对象状态(Deployment/Pod)
  ✅ SpringBoot Actuator + Micrometer：应用级指标
```

### 3.2 SpringBoot暴露Prometheus指标

```xml
<dependency>
    <groupId>io.micrometer</groupId>
    <artifactId>micrometer-registry-prometheus</artifactId>
</dependency>
```

```yaml
management:
  endpoints:
    web:
      exposure:
        include: health,prometheus
  metrics:
    tags:
      application: ${spring.application.name}
```

```bash
curl http://localhost:8080/actuator/prometheus
# http_server_requests_seconds_count{uri="/api/users",status="200"} 1523
# jvm_memory_used_bytes{area="heap"} 2.5E8
```

### 3.3 关键监控指标

| 层次 | 指标 | 告警条件 |
|------|------|------|
| **Node** | CPU/内存/磁盘使用率 | CPU>80%, 磁盘>85% |
| **Pod** | CPU/内存使用率、重启次数 | 重启>3次/hour, OOMKilled |
| **Deployment** | 可用副本数、期望副本数 | 可用<期望 |
| **JVM** | 堆内存使用率、GC耗时 | 堆>85%, GC>1s |
| **HTTP** | QPS、P99延迟、错误率 | P99>1s, 错误率>1% |

### 3.4 Grafana仪表盘

```text
推荐SpringBoot Grafana Dashboard模板：
  - JVM Micrometer (Dashboard ID: 4701)
  - Spring Boot Statistics (ID: 6756)
  - Kubernetes Deployment (ID: 8588)

导入方式：
  Grafana → Create → Import → 输入Dashboard ID → 选择Prometheus数据源
```

## 4. SpringBoot应用的可观测性

### 4.1 三大支柱与SpringBoot映射

| 支柱 | SpringBoot方案 | 生产配置 |
|------|---------------|----------|
| **Logging** | SLF4J + Logback → stdout | JSON格式 + traceId注入 |
| **Metrics** | Micrometer → Prometheus | `@Timed`注解方法耗时 |
| **Tracing** | Micrometer Tracing → Zipkin/SkyWalking | `spring.micrometer.tracing` |

### 4.2 Micrometer Tracing

```xml
<dependency>
    <groupId>io.micrometer</groupId>
    <artifactId>micrometer-tracing-bridge-brave</artifactId>
</dependency>
```

```yaml
spring:
  application:
    name: user-service
management:
  tracing:
    sampling:
      probability: 1.0          # 全量采样（生产建议0.1=10%）
  zipkin:
    tracing:
      endpoint: http://zipkin:9411/api/v2/spans
```

```java
// 自动注入TraceId到日志
// logback-spring.xml: [%X{traceId}] 
// 输出: 2024-01-15 10:30:00 [http-nio-8080-1] INFO - [a1b2c3d4e5f6] 用户登录成功
```

## 5. 告警与通知

### 5.1 Alertmanager规则示例

```yaml
# prometheus-rules.yaml
groups:
  - name: springboot
    rules:
      - alert: HighErrorRate
        expr: rate(http_server_requests_seconds_count{status=~"5.."}[5m]) > 0.1
        for: 5m
        labels:
          severity: critical
        annotations:
          summary: "{{ $labels.application }} 错误率过高"
          description: "5xx错误率 {{ $value }} /s，持续5分钟"
      
      - alert: PodRestarting
        expr: rate(kube_pod_container_status_restarts_total[15m]) > 0
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "Pod {{ $labels.pod }} 频繁重启"
```

### 5.2 告警通知渠道

```yaml
# alertmanager.yaml
receivers:
  - name: 'team-dev'
    slack_configs:
      - channel: '#alerts'
        text: '{{ .CommonAnnotations.summary }}'
    webhook_configs:
      - url: 'https://hooks.example.com/alert'
```

> 🎯 **K8s可观测性核心原则**：日志集中存储（Pod消失日志不丢）、指标趋势监控（Prometheus+Grafana）、告警及时通知（Alertmanager）。三根支柱缺一不可。
