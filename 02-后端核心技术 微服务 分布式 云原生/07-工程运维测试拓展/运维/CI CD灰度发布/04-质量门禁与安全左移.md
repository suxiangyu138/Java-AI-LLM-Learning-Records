## 1. 安全左移理念

```text
传统模式：安全问题上线后才发现（修复成本 ×10-100）
安全左移：检查前置到流水线早期

左移层次：
  提交时：编译 + 单测（分钟级）
  PR 时：静态扫描 + 覆盖率 + 依赖扫描
  发布时：镜像扫描 + 密钥检查 + 合规
  运行时：监控告警（兜底，见日志监控指标体系）
```

> 🎯 **核心理念**：**越早发现的问题修复成本越低**——编译错误 1 分钟修复，生产漏洞可能 1 天+。安全左移 = 把"上线前检查"变成"提交时检查"。

## 2. 测试门禁

| 门禁 | 工具 | 阻断条件 |
|------|------|---------|
| 单元测试 | JUnit + Surefire | 任一失败 |
| 覆盖率 | JaCoCo | 核心模块 < 80% |
| 集成测试 | Testcontainers/测试环境 | 任一失败 |
| 契约测试 | 接口定义（见 APIFox 体系） | 契约不匹配 |

```xml
<!-- JaCoCo 覆盖率门禁 -->
<plugin>
    <groupId>org.jacoco</groupId>
    <artifactId>jacoco-maven-plugin</artifactId>
    <executions>
        <execution>
            <id>check</id>
            <goals><goal>check</goal></goals>
            <configuration>
                <rules>
                    <rule>
                        <element>BUNDLE</element>
                        <limits>
                            <limit>
                                <counter>LINE</counter>
                                <value>COVEREDRATIO</value>
                                <minimum>0.80</minimum>   <!-- 80% 红线 -->
                            </limit>
                        </limits>
                    </rule>
                </rules>
            </configuration>
        </execution>
    </executions>
</plugin>
```

> ⚠️ **覆盖率红线设计**：80% 是常见基线，但**核心模块（支付/库存）单独加严**（90%+）；覆盖率是手段不是目的——关键路径测试比覆盖率数字更重要。

## 3. 代码质量扫描（SonarQube）

```bash
# 本地/CI 扫描
mvn sonar:sonar \
  -Dsonar.projectKey=order-service \
  -Dsonar.host.url=https://sonar.example.com \
  -Dsonar.token=$SONAR_TOKEN
```

| 检查维度 | 说明 |
|----------|------|
| 代码异味（Code Smell） | 可维护性问题 |
| Bug | 潜在缺陷 |
| 漏洞（Vulnerability） | 安全风险 |
| 重复代码 | 维护成本 |
| 复杂度 | 可测试性 |

```text
Quality Gate（质量门禁）典型规则：
  A 级：无阻断级问题（Blocker/Critical = 0）
  B 级：新代码覆盖率 ≥ 80%
  C 级：重复率 < 3%
```

> 💡 SonarQube 在 CI 中作为**发布门禁**：`mvn sonar:sonar` 后查询 Quality Gate 状态，不通过则阻断流水线。

## 4. 依赖漏洞扫描

| 工具 | 定位 | 使用 |
|------|------|------|
| OWASP Dependency-Check | Java 依赖漏洞 | `mvn org.owasp:dependency-check-maven:check` |
| Snyk | 商业/开源 | CLI + CI 集成 |
| Dependabot | GitHub 原生 | 自动依赖更新 PR（见 GitHub 体系） |
| Trivy | 全栈（含依赖） | `trivy fs .` |

```bash
# OWASP Dependency-Check（CI 门禁）
mvn org.owasp:dependency-check-maven:check \
  -DfailBuildOnCVSS=7      # CVSS ≥ 7 阻断构建
```

| 漏洞等级 | 处理 |
|----------|------|
| Critical（CVSS 9-10） | **阻断 + 立即升级** |
| High（7-8.9） | 阻断（可评估临时缓解） |
| Medium | 记录 + 限期修复 |
| Low | 记录 |

> ⚠️ **依赖漏洞是供应链攻击入口**（Log4Shell 教训）：**高危漏洞 0 容忍**是 2026 基线；银行等严苛场景集成扫描后拦截 95% 漏洞镜像。

## 5. 镜像安全扫描（Trivy）

```bash
# 本地扫描
trivy image harbor.example.com/prod/order-service:1.0.3

# CI 门禁（高危即失败）
trivy image --severity CRITICAL,HIGH --exit-code 1 \
  --ignore-unfixed harbor.example.com/prod/order-service:1.0.3

# 扫描文件系统（依赖层）
trivy fs .
```

| Trivy 扫描内容 | 说明 |
|----------------|------|
| OS 软件包漏洞 | 基础镜像层（Alpine/Debian 包） |
| 依赖漏洞 | JAR 中的库 |
| 密钥泄露 | 镜像内敏感信息 |
| 配置问题 | 不安全的 Dockerfile 配置 |

> 🎯 **扫描三层**：基础镜像（OS 包）+ 应用依赖（JAR）+ 配置（密钥/权限）——Harbor 集成 Trivy 后**推送即扫描**，扫描结果作为部署门禁。

## 6. 密钥与凭证管理

| 工具 | 场景 |
|------|------|
| CI Secrets | 流水线内凭证（GitHub Actions secrets / GitLab CI 变量 / Jenkins credentials） |
| Sealed Secrets | K8s 中加密存储 Secret（Git 可提交加密版） |
| External Secrets | 从 Vault/AWS 同步到 K8s |
| cert-manager | 证书自动签发续期 |

```text
密钥管理纪律：
  ① 代码仓库零密钥（扫描器检测）
  ② 环境分离（dev/prod 密钥隔离）
  ③ 轮换机制（定期/事故后）
  ④ 审计（谁用了哪个密钥）
```

```yaml
# Sealed Secrets 示例（Git 安全存储加密 Secret）
apiVersion: bitnami.com/v1alpha1
kind: SealedSecret
metadata:
  name: db-password
spec:
  encryptedData:
    password: AgBy3i4OJSWK+PiTySYZZA9rO43cGDEq...  # 加密后的值
```

> ⚠️ **密钥泄露事故链**：密钥进 Git → 扫描发现已太迟 → 轮换 + 清理历史（filter-repo，见 Git 体系）——**预防靠"代码零密钥 + 扫描检测"双保险**。

## 7. 门禁配置实践

```yaml
# 门禁在流水线中的落地（综合示例）
stages: [build, test, scan, package, deploy]

build:
  script: [mvn clean compile]                    # 门禁 1：编译
test:
  script: [mvn verify jacoco:report]             # 门禁 2：测试 + 覆盖率
  after_script:
    - mvn sonar:sonar                            # 门禁 3：质量扫描
scan:
  script:
    - mvn org.owasp:dependency-check-maven:check -DfailBuildOnCVSS=7   # 门禁 4：依赖
    - trivy image --severity CRITICAL,HIGH --exit-code 1 $IMAGE        # 门禁 5：镜像
package:
  script: [docker build, docker push]            # 通过全部门禁才打包
deploy:
  when: manual                                   # 发布按钮
```

```text
门禁分级总结：
  提交/PR：编译 + 单测 + 覆盖率 + 静态扫描（快，10 分钟内）
  发布：依赖扫描 + 镜像扫描 + 密钥检查（重，全量）
  生产：灰度指标 + 健康检查（运行时，见 05/06）
```

> 🎯 **门禁落地要点**：门禁必须是**"阻断"不是"提醒"**（exit-code 1 / failBuildOnCVSS）——提醒型门禁等于没有门禁。

## 8. 核心要点

> 🎯 **核心要点**：
> - 安全左移：提交时快检查（编译/单测/覆盖率）、发布时重检查（依赖/镜像/密钥）；
> - 门禁五件套：编译、测试+覆盖率（80% 红线）、SonarQube Quality Gate、依赖扫描（CVSS≥7 阻断）、Trivy 镜像扫描（高危阻断）；
> - 扫描三层：OS 包 + 应用依赖 + 配置密钥；
> - 密钥纪律：代码零密钥、环境隔离、轮换、审计；Sealed Secrets 可安全入 Git；
> - 门禁必须是阻断不是提醒；
> - 越早发现越便宜：左移的本质是成本优化。
