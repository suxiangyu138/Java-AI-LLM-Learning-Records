## 1. SFTP 文件管理

```text
连接服务器后，左侧自动打开文件管理器（SFTP）：
  本地（左侧树） ↔ 服务器（右侧树）
  终端与文件树实时同步（终端 cd 的目录 = 文件树定位）
```

| 能力 | 说明 |
|------|------|
| 双向拖拽 | 本地 ↔ 服务器直接拖拽上传/下载 |
| 右键菜单 | 上传/下载/编辑/权限/属性 |
| 文件编辑 | 内置编辑器（语法高亮）直接改服务器文件 |
| 搜索 | 服务器文件内容/文件名搜索 |
| 权限修改 | 批量修改文件权限（chmod 可视化） |

> 🎯 **核心体验**：**"像操作本地文件夹一样管理 Linux 服务器"**——不再需要记 `scp`/`rz`/`sz` 命令，拖拽即传输。

## 2. 大文件与批量传输

| 场景 | 能力 | 注意 |
|------|------|------|
| 大文件 | **断点续传**（中断后继续） | > 500MB 拖拽可能卡顿 → 用 rsync |
| 多文件 | 并行传输 | - |
| 前端静态资源 | **一键打包上传/解压下载** | 部署前端神器 |
| 批量权限 | 批量 chmod | 目录+文件分别设置 |

```text
打包上传流程（前端部署场景）：
  本地 dist/ 目录 → 右键"打包上传"
  → 服务器自动打包解压到目标目录
  省去：本地 tar → 上传 → 服务器解压三步
```

> ⚠️ **大文件纪律**：超过 500MB 建议用 `rsync`（增量/断点可靠）；数据库文件备份用 `mysqldump` 后在服务器内操作——SFTP 不是大数据的搬运工。

## 3. Java 部署场景文件操作

```text
Java 后端日常文件操作（FinalShell 可视化）：
  ① 上传 JAR 包 → 拖拽到服务器部署目录
  ② 修改配置 → 右键编辑 application.yml（语法高亮）
  ③ 查看日志 → 双击 tail（或终端 tail -f）
  ④ 修改权限 → 批量 chmod 可执行位
```

| 场景 | FinalShell 操作 |
|------|----------------|
| 部署新版本 | 上传 JAR → 重启服务（终端）→ 看日志 |
| 改配置 | 右键编辑 → 保存 → 重启 |
| 看日志 | 文件树定位日志 → 双击查看 |
| 传证书 | 拖拽上传 → chmod 600 |
| 备份 | 服务器内 cp/tar（本地右键下载） |

> 💡 **部署闭环**：拖拽上传 → 终端重启 → 监控面板看状态——FinalShell 的"终端+文件+监控"三合一让部署全程不切工具。

## 4. 实时监控面板

```text
连接后右侧自动显示实时监控（独家特色——无需在服务器安装监控脚本）：
```

| 监控项 | 展示 | 运维价值 |
|--------|------|---------|
| CPU | 使用率曲线 | 性能瓶颈第一信号 |
| 内存 | 已用/总量/交换分区 | OOM 前预警 |
| 网卡 | 上下行流量图 | 网络异常 |
| 磁盘 IO | 读写速率 | 慢查询/备份压力 |
| 分区占用 | 各分区使用率 | **磁盘满预警** |

```text
监控面板的典型用法：
  部署后看 CPU/内存是否异常（发布验证）
  偶发慢 → 看监控是否持续高占用
  磁盘告警前 → 分区占用提前发现
```

> 🎯 **监控面板 vs 专业监控**：FinalShell 监控是**"当前这台服务器实时状态"**（排查用）；长期趋势/告警用 Prometheus+Grafana（见日志监控指标体系）——两者互补。

## 5. 进程管理

| 能力 | 说明 |
|------|------|
| 进程列表 | 实时查看所有进程（CPU/内存排序） |
| 筛选 | 按 CPU/内存排序快速定位高占用 |
| 一键 kill | 可视化结束进程（比 `kill -9` 盲杀安全） |
| Java 进程定位 | 找到 `java -jar` 进程的 PID（供 jstack/jmap） |

```text
Java 排障联动：
  监控面板看到内存持续高位
  → 进程列表定位 java 进程 PID
  → 终端执行 jstack <pid> / jmap -dump 分析
  （详见网络问题排查体系的 Java 章节）
```

> ⚠️ kill 前确认：**先看进程是什么**（命令行/父进程），误杀生产进程 = 事故；FinalShell 的进程信息完整展示降低误杀风险。

## 6. 网络监控工具

| 工具 | 用途 |
|------|------|
| Ping | 多地址 ping 监控（延迟/丢包） |
| Trace 路由 | 路径与丢包定位（等价 traceroute） |
| 端口扫描 | 目标端口开放检查（等价 nc/telnet） |
| 双边加速 | 海外服务器连接优化（付费功能） |

> 💡 与[网络问题排查](../网络问题排查/00-网络问题排查总览.md)体系联动：FinalShell 提供**图形化的 ping/trace/端口检查**，五连工具集的可视化版。

## 7. 核心要点

> 🎯 **核心要点**：
> - 文件管理 = "像操作本地文件夹"：拖拽、断点续传、打包上传、内置编辑器；
> - 监控面板是独家特色：CPU/内存/网络/IO/进程——**无需服务器装监控脚本**；
> - Java 部署闭环：上传 → 重启 → 监控验证，全程一个工具；
> - 大文件用 rsync（>500MB 拖拽会卡）；kill 前先确认进程身份；
> - 监控面板是"实时排查"工具，长期趋势/告警交给 Prometheus 体系。
