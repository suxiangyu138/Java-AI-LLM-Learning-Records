## 1. 五步排查法

```text
① 现象确认：报错是什么？影响多大？什么时候开始？
② 监控定位：指标曲线找趋势（连接数/延迟/堆积量）
③ 日志取证：错误日志/慢日志/客户端日志
④ 根因分析：现象 → 证据 → 根因（一个根因解释所有现象）
⑤ 解决与验证：最小干预解决 → 观察指标恢复 → 防复发
```

| 步骤 | 核心动作 | 产出 |
|------|---------|------|
| ① 现象确认 | 收集报错/时间/影响面 | 故障描述 |
| ② 监控定位 | 看指标曲线（开始点/趋势） | 时间线 |
| ③ 日志取证 | 服务端/客户端日志交叉 | 证据链 |
| ④ 根因分析 | 一个根因解释所有现象 | 根因结论 |
| ⑤ 解决验证 | 最小干预 + 观察恢复 | 处理记录 |

> 🎯 **根因检验标准**：**"一个根因解释所有现象"**——如果解释不通，说明还没找到根因（可能只是表象）。

## 2. 监控先行

```text
中间件核心监控项（故障定位的"仪表盘"）：
  MySQL：连接数、慢查询数、锁等待、主从延迟、磁盘/IO
  Redis：内存使用、命中率、客户端连接、阻塞时间
  MQ：生产/消费速率、堆积量、消费失败率、死信数
```

| 故障 | 关键曲线 |
|------|---------|
| 连接数满 | 连接数曲线（爬升斜率/峰值） |
| 消息堆积 | 堆积量曲线（开始时间 = 故障开始） |
| 主从延迟 | 延迟曲线（持续增长 vs 偶发） |
| 内存问题 | 内存曲线（缓慢增长 vs 突增） |

> 💡 曲线的**拐点**就是故障的开始时间——与"变更时间"对比（发布/配置/数据量变化），一半故障当场破案。

## 3. 现象分级与优先级

| 级别 | 影响面 | 处理策略 |
|------|--------|---------|
| P1 | 全挂/核心链路中断 | 立即止血（回滚/重启/扩容），后查根因 |
| P2 | 部分功能异常 | 快速定位根因，最小干预 |
| P3 | 偶发/性能劣化 | 常规排查，可走变更流程 |

```text
处理原则：
  P1 先止血再查根因（重启/回滚优先，别在故障中分析）
  P2 快速定位（监控 + 日志 + 复现）
  P3 记录跟踪（影响面小，可从容排查）
```

> ⚠️ **P1 的铁律**：**先恢复服务再分析根因**——在故障高峰期"深入分析"是最常见的错误（延长故障时长）；恢复后复盘再查根因。

## 4. 变更回溯

```text
故障排查必问：故障前发生了什么变更？
  发布（代码/版本）
  配置（参数/开关）
  数据（量级/结构）
  环境（迁移/扩容/网络）
```

| 变更类型 | 典型故障 |
|----------|---------|
| 代码发布 | 慢 SQL 引入/连接泄漏 |
| 配置调整 | 参数不匹配（超时/内存） |
| 数据增长 | 大 key/慢查询/堆积 |
| 扩容/迁移 | 数据倾斜/连接风暴 |

> 💡 **变更回溯是最高效的排查入口**：故障开始时间 ≈ 变更时间——先怀疑变更，再查其他（"最后变更最可疑"原则）。

## 5. 最小复现与保留现场

```text
保留现场（故障分析的关键证据）：
  报错信息（完整堆栈）
  监控截图（曲线）
  日志片段（时间窗口）
  当前状态（连接数/进程状态）
```

| 场景 | 复现方式 |
|------|---------|
| 慢 SQL | 拿到 SQL + 执行计划（EXPLAIN） |
| 死锁 | `SHOW ENGINE INNODB STATUS`（死锁现场） |
| 连接问题 | 报错 + 连接数曲线 |
| 消息堆积 | 堆积量 + 消费日志 |

> ⚠️ 故障"恢复"后现场就没了——**先取证再恢复**（拿日志/状态/监控）；能复现的故障都好定位，不能复现的靠证据链。

## 6. 复盘与防复发

```text
复盘四段式：
  ① 现象（发生了什么）
  ② 根因（为什么发生）
  ③ 解决（怎么恢复的）
  ④ 防复发（如何不再发生）
```

| 防复发手段 | 示例 |
|-----------|------|
| 监控告警 | 连接数 > 80% 告警 |
| 参数优化 | 连接池/超时参数调整 |
| 代码修复 | 慢 SQL 优化/连接释放 |
| 预案沉淀 | 故障处理 SOP |
| 演练 | 定期故障演练（混沌工程） |

> 🎯 **故障的价值在复盘**：没有防复发的复盘 = 白疼一次——**每类故障沉淀为一条监控告警或一条 SOP**，是运维体系的成长路径。

## 7. 核心要点

> 🎯 **核心要点**：
> - 五步法：现象 → 监控 → 日志 → 根因 → 解决；
> - 根因检验："一个根因解释所有现象"；
> - 曲线拐点 = 故障开始时间 = 变更回溯的锚点；
> - 分级处理：P1 先止血后分析、P2 快速定位、P3 从容排查；
> - 先取证再恢复（现场是证据）；
> - 复盘四段式 + 防复发（监控/SOP/演练）；
> - 与各中间件章节联动：方法论在这里，具体命令在 02-08。
