## 1. 版本与 Java 要求（2026）

| 项目 | 说明 |
|------|------|
| 当前 LTS | **2.555.x**（2.555.3，2026-06-08） |
| Java 要求 | **Java 21 或 25**（2.555 起；Java 17 不再支持） |
| 上一个 LTS | 2.541.x（2026-04-15 EOL，需升级） |
| 发行模型 | 每周版（Weekly）+ LTS（每 12 周基线 + 3 个月度补丁） |
| 内存建议 | 小团队 2-4GB；中大规模 8GB+ |

> 🎯 版本选型：**生产一律 LTS**（每周版给尝鲜）；升级按 LTS 基线节奏（约每 3 个月一个基线）。Java 用 **21 LTS**（25 可选，等生态跟上）。

## 2. 安装方式对比

| 方式 | 优点 | 缺点 | 适用 |
|------|------|------|------|
| **Docker/Compose** | 隔离、可移植、升级快 | 数据卷管理需注意 | **推荐（新环境）** |
| War（Tomcat） | 传统可控 | 多一层容器管理 | 存量 Tomcat 环境 |
| 原生包（deb/rpm） | 系统服务管理 | 升级/迁移较麻烦 | 传统服务器 |
| K8s Helm | 云原生 + 高可用 | 复杂度高 | 大规模生产 |

> 🎯 2026 现实：**Docker 是标准姿势**（尤其配合 Agent 容器化）；大规模生产用 Helm 部署在 K8s（[06-Agent与分布式构建](06-Agent与分布式构建.md) 展开）。

## 3. 方式一：Docker 部署（推荐）

```yaml
# docker-compose.yml（生产基础版）
services:
  jenkins:
    image: jenkins/jenkins:lts-jdk21      # LTS + JDK 21 镜像
    container_name: jenkins
    user: root                            # 便于 Docker-in-Docker（谨慎，见 04 安全）
    ports:
      - "8080:8080"                       # Web UI
      - "50000:50000"                     # Agent 通信端口
    volumes:
      - jenkins_home:/var/jenkins_home    # 数据卷（唯一持久化点！）
      - /var/run/docker.sock:/var/run/docker.sock   # 调用宿主机 Docker（DIND 场景）
    environment:
      JAVA_OPTS: "-Xmx4g -Duser.timezone=Asia/Shanghai"
    restart: unless-stopped

volumes:
  jenkins_home:
```

```bash
# 快速启动（开发）
docker run -d -p 8080:8080 -p 50000:50000 \
  -v jenkins_home:/var/jenkins_home \
  jenkins/jenkins:lts-jdk21

# 查看初始管理员密码
docker exec jenkins cat /var/jenkins_home/secrets/initialAdminPassword
```

> ⚠️ 数据持久化铁律：**`/var/jenkins_home` 必须挂数据卷**——容器可以随便删，数据卷是全部身家（配置/Job/构建记录/凭证）。[08](08-生产运维与故障排查.md) 备份篇会讲数据卷的完整备份。

## 4. 方式二：War/包安装（传统）

```bash
# 下载 war（LTS）
wget https://get.jenkins.io/war-stable/latest/jenkins.war

# 方式 A：独立运行（内置 Jetty）
java -jar jenkins.war --httpPort=8080

# 方式 B：部署到已有 Tomcat（legacy，不推荐新用）
cp jenkins.war /opt/tomcat/webapps/

# 原生包（Debian/Ubuntu）
sudo wget -O /usr/share/keyrings/jenkins-keyring.asc \
  https://pkg.jenkins.io/debian-stable/jenkins.io-2023.key
echo "deb [signed-by=/usr/share/keyrings/jenkins-keyring.asc] \
  https://pkg.jenkins.io/debian-stable binary/" | sudo tee /etc/apt/sources.list.d/jenkins.list
sudo apt update && sudo apt install jenkins
```

> 💡 独立 war 运行（内置 Jetty）是传统标准；Tomcat 部署已属遗留姿势。关键目录：`JENKINS_HOME`（默认 `~/.jenkins` 或 `/var/lib/jenkins`）——所有配置都在这个目录里。

## 5. 初始化向导

```text
首次访问 http://localhost:8080 的初始化流程：
  ① 输入初始密码（日志/容器文件里）
  ② 选择插件安装方式：
     · 安装建议插件（recommended，新手）
     · 自定义选择（select plugins to install，生产按需）
  ③ 创建管理员账号（admin/强密码）
  ④ 实例配置（URL 等）

生产建议：自定义安装，只装需要的插件（插件越少攻击面越小）
```

```bash
# 推荐的最小插件集（后端 Java 项目起步）
Pipeline                       # 流水线（必装）
Credentials                    # 凭证（必装）
Git                             # Git 集成
JDK Tool / Maven Integration    # Java 构建工具
Docker Pipeline                 # Docker 构建
Blue Ocean                     # 可视化流水线（体验好）
SonarQube Scanner              # 质量门禁（可选）
```

> ⚠️ 插件管理哲学：**"够用就好"**——每个插件都是攻击面与升级负担（Jenkins CVE 史与插件生态强相关，见 [04-凭证与安全](04-凭证与安全.md)）。装插件前问"真的需要吗"。

## 6. 插件管理

```text
管理入口：Manage Jenkins → Plugins
  · Available：可安装（搜索/依赖自动解析）
  · Installed：已装（看版本/更新可用）
  · Updates：可更新（生产定期批量更新）

插件更新策略：
  · 安全更新：立即
  · 常规更新：随 LTS 升级节奏批量（避免插件与新 LTS 冲突）
  · 升级前：先在测试实例验证
```

```bash
# 离线环境装插件（内网隔离场景，见 00 定位）
# 1. 在可联网环境下载 .hpi/.jpi 插件包
# 2. 上传到 JENKINS_HOME/plugins/ 目录
# 3. 重启 Jenkins（或热加载）
```

| 插件管理要点 | 说明 |
|-------------|------|
| 依赖解析 | 装 A 会自动装其依赖插件（注意冲突） |
| 版本锁定 | 生产记录插件清单（版本 + 更新日期） |
| 冲突排查 | 插件冲突 = 功能异常/构建失败（[08](08-生产运维与故障排查.md) 故障篇） |
| 安全公告 | 关注 [Jenkins 安全公告](https://www.jenkins.io/security/)（CVE 密集） |

> 🎯 2026 安全现实：**Jenkins 的 CVE 历史大部分与插件相关**——"插件越少、更新越勤"是 Jenkins 运维的第一安全原则（[04 §7](04-凭证与安全.md) 有完整加固清单）。

## 7. 系统配置要点

```text
Manage Jenkins → System 的核心配置：
  · Jenkins URL：外部访问地址（Webhook/通知要用）
  · 时区：JAVA_OPTS 里设 -Duser.timezone=Asia/Shanghai
  · 并发与队列：执行器数量、队列深度
  · SCM：Git 全局配置（user.name/email）
  · 邮件通知：SMTP（构建结果通知）
  · 全局工具：JDK/Maven/Node 路径（见 05）
```

```bash
# 时区设置（Docker 环境变量方式）
environment:
  JAVA_OPTS: "-Duser.timezone=Asia/Shanghai"

# 构建历史保留策略（磁盘管理，见 08 故障篇）
# Manage Jenkins → Jobs → Discard Old Builds
# 保留策略：保留最近 30 天 或 最近 100 次构建
```

> 💡 上线前三件事：**URL 配对外地址、时区配对、构建历史设保留策略**——前两件影响协作与日志时间，最后一件决定磁盘寿命（[08](08-生产运维与故障排查.md) 磁盘满故障的预防）。
