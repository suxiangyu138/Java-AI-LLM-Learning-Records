## 1. 备份与恢复

```text
备份对象（JENKINS_HOME 里的核心）：
  · jobs/          —— 所有 Job 配置（含 Jenkinsfile 引用）
  · credentials/   —— 凭证库（最敏感！）
  · plugins/       —— 插件（可重装，但版本锁定有价值）
  · config.xml     —— 全局配置
  · secrets/       —— 加密密钥（⚠️ 与凭证配套，缺它无法解密！）
  · users/         —— 用户

关键认知：备份 = JENKINS_HOME 目录 + 加密密钥一起备份
```

```bash
# Docker 场景备份（停容器或一致性快照）
docker run --rm -v jenkins_home:/data -v /backup:/backup alpine \
  tar czf /backup/jenkins-backup-$(date +%F).tar.gz /data

# 恢复
docker run --rm -v jenkins_home:/data -v /backup:/backup alpine \
  tar xzf /backup/jenkins-backup-YYYY-MM-DD.tar.gz -C /data
```

| 备份要素 | 说明 |
|---------|------|
| 频率 | 每日（配置变更频繁可增量） |
| 保留 | 30 天滚动 |
| 加密 | 备份含凭证 → 加密存储 |
| **恢复演练** | 季度演练（备份的价值在恢复） |
| 测试实例 | 恢复演练用独立实例（不碰生产） |

> ⚠️ **secrets/ 目录是备份的"另一半"**：只备份 jobs 不备份 secrets → 恢复后凭证全部无法解密（报 `DecryptionException`）。备份必须整目录 + 加密密钥一起。

## 2. 升级与迁移

```text
升级路径（2026 现状）：
  2.541.x（EOL 2026-04-15）→ 2.555.x（当前 LTS）
  ⚠️ Java 要求变化：2.555 起需要 Java 21/25（Java 17 不再支持）

升级流程：
  ① 备份（含 secrets/）
  ② 测试实例升级验证（插件兼容！）
  ③ 生产升级（替换 war/镜像 tag）
  ④ 验证登录/构建/凭证
```

```bash
# Docker 升级（替换镜像 tag）
docker compose pull jenkins        # lts-jdk21 镜像更新
docker compose up -d jenkins

# war 方式
# 替换 jenkins.war + 重启（JENKINS_HOME 不变）
```

| 升级注意 | 说明 |
|---------|------|
| 插件兼容 | 先看 [插件兼容矩阵](https://www.jenkins.io/doc/developer/plugin-compat-tester/) |
| Java 升级 | 2.555 前先换 JDK 21 环境 |
| 大版本跨跳 | 分步升级（2.375 → 2.452 → 2.541 → 2.555） |
| 回滚 | 备份保留旧版镜像/包，异常立即回滚 |

> ⚠️ 升级铁律：**"升级前必备份，跨版本必分步"**——Jenkins 升级失败 90% 是插件冲突（[03 故障表](08-生产运维与故障排查.md) 有排查法）；测试实例先行是唯一防线。

## 3. 常见故障速查表

| 故障现象 | 根因 | 排查/解法 |
|---------|------|----------|
| 构建一直排队 | Executor 占满 | Nodes 看执行器使用；加 Agent/执行器 |
| 构建卡在 Checkout | Git 凭证失效/网络 | 凭证轮换；`git ls-remote` 测试 |
| **偶发构建失败（换 Agent 就好）** | Agent 环境漂移 | 环境一致化（Docker Agent）；清 workspace |
| Workspace 冲突 | 并发构建同一 Agent | 禁止并发（disableConcurrentBuilds）/加 Agent |
| 磁盘满 | 构建历史/workspace 堆积 | 保留策略 + 清理（§4） |
| 凭证解密失败 | 恢复时丢了 secrets/ | **secrets/ 必须一起备份**（§1） |
| 插件功能失效 | 插件冲突/未升级 | 测试实例排查；禁用冲突插件 |
| Script Console 报错 | Groovy 语法/权限 | 检查语法（声明式校验）；权限矩阵 |
| Agent 连不上 | 网络/密钥/Java 版本 | SSH 测试；Agent Java 21 |
| 构建结果 UNSTABLE | 测试失败/门禁不过 | 看测试报告/质量门禁详情 |
| Webhook 不触发 | URL 不可达/令牌不配 | curl 测 Webhook；双侧令牌核对 |
| 时区不对 | JAVA_OPTS 未设 | `-Duser.timezone=Asia/Shanghai` |

```bash
# 故障定位三板斧
# ① 构建失败 → 构建记录 → Console Output（第一现场）
# ② 环境问题 → Nodes → Agent → 手动跑一次（复现）
# ③ 系统问题 → Manage Jenkins → System Log（服务端日志）
```

> 🎯 排障方法论：**先 Console Output 看构建侧，再 System Log 看系统侧**——构建失败 80% 在 Console Output 里直接定位（凭证/网络/编译错）；System Log 是"为什么 Jenkins 本身不正常"的入口。

## 4. 磁盘与性能治理

```text
磁盘增长的四大来源：
  ① 构建历史（builds 目录）—— 最肥
  ② Workspace（检出的代码 + 构建产物）
  ③ 构建制品（archiveArtifacts）
  ④ 日志（System Log / 构建日志）

治理三板斧：
  ① 保留策略：logRotator(numToKeepStr: '50')（只留 50 次构建）
  ② 清理：post { always { cleanWs() } }（工作区用完即清）
  ③ 定期大扫除：Jenkins Script Console（管理员）
     或插件：Workspace Cleanup / Disk Usage
```

```groovy
// 保留策略（options 里配）
pipeline {
    options {
        buildDiscarder(logRotator(
            numToKeepStr: '50',          // 保留构建数
            daysToKeepStr: '30'          // 保留天数（双条件）
        ))
        // 制品也受限：archiveArtifacts 默认随构建保留
    }
}
```

| 治理手段 | 做法 |
|---------|------|
| 构建历史 | 保留策略（数量 + 天数） |
| Workspace | `cleanWs()` + 定期清理 |
| 制品 | 只归档必要产物；大制品进制品库（Nexus/Harbor） |
| 日志 | 定期清理（log 保留策略） |
| 监控 | 磁盘告警（>80% 告警，[日志监控指标体系](../日志监控指标/00-日志监控指标总览.md)） |

> 🎯 磁盘铁律：**"Jenkins 的磁盘是消耗品"**——不做保留策略的 Jenkins 半年必爆盘。新 Job 上线就配 `logRotator` + `cleanWs`，别等告警再补。

## 5. 12 大避坑清单

| # | 坑 | 现象 | 解法 |
|:---:|----|------|------|
| 1 | 凭证写死 Jenkinsfile | 泄露/难轮换 | withCredentials（[04](04-凭证与安全.md)） |
| 2 | 密码打进构建日志 | 明文日志 | withCredentials 自动屏蔽 |
| 3 | 默认 "Anyone can do anything" | 权限裸奔 | 矩阵授权（[04 §4](04-凭证与安全.md)） |
| 4 | Script Console 给普通用户 | RCE 风险 | 仅管理员 |
| 5 | 新 Job 用 Freestyle | 无法版本化 | Pipeline（[02 §3](02-核心概念.md)） |
| 6 | 忘记 timeout | 构建挂死 | options { timeout } |
| 7 | 不配保留策略 | 磁盘爆满 | logRotator（§4） |
| 8 | 并发构建共享 Agent | workspace 冲突 | disableConcurrentBuilds/加 Agent |
| 9 | 依赖不缓存 | 每次全量下载 | 挂载 m2 缓存（[05 §2](05-构建工具集成.md)） |
| 10 | 升级不备份 | 升级失败无法回滚 | 先备份再升级（§2） |
| 11 | 备份丢 secrets/ | 凭证全解密失败 | 整目录 + secrets（§1） |
| 12 | 插件装一堆 | 攻击面/冲突 | 最小化 + 更新（[01 §6](01-安装与初始化.md)） |

## 6. 高频面试题

### Q1：Jenkins 主从架构是什么？为什么要分离？
> Master 管调度/配置/UI（不干重活），Agent 执行构建（可多台/动态）。分离的价值：横向扩展（加 Agent = 构建能力翻倍）、环境隔离（不同 Agent 跑不同构建）、Master 稳定性（构建失败不影响调度）。

### Q2：Freestyle 和 Pipeline 的区别？为什么推荐 Pipeline？
> Freestyle 是 UI 配置（存数据库，无法版本化/复用/审计）；Pipeline 是代码（Jenkinsfile 进 Git，可审查、可复用（共享库）、可条件并行）。Pipeline 是 CI 配置"代码化"的落地。

### Q3：声明式 Pipeline 的核心结构？
> pipeline → agent（在哪执行）→ options（超时/保留）→ parameters（参数化）→ environment（环境变量）→ stages（stage 序列，核心）→ post（收尾：always/success/failure）。复杂逻辑用 script{} 转义 Groovy。

### Q4：Jenkins 凭证怎么管理？为什么不能用明文？
> Credentials 库集中存储（用户名密码/SSH 私钥/Secret text/文件/证书），流水线用 withCredentials 注入（自动屏蔽日志）。明文风险：泄露即发布链沦陷（Git/制品库/服务器/云凭证全在手里）。最小授权 + 定期轮换。

### Q5：共享库是什么？解决什么问题？
> 独立 Git 仓库存放公共流水线代码（vars 函数/src 类），全局配置后所有流水线 @Library 引用。解决"公共逻辑每仓库复制"——一处维护、全部生效。Jenkinsfile 只留编排，公共步骤进库。

### Q6：多分支流水线有什么用？
> 一个 Job 自动管理所有分支：分支自动发现建流水线、`when { branch }` 控制分支行为（main 部署、PR 验证）、tag 触发发布。解决"每分支手工建 Job"的运维量。

### Q7：Docker Agent 和 K8s 动态 Agent 的区别？
> Docker：每次构建起容器（镜像即环境），隔离 + 一致；K8s：按需创建 Pod（jnlp + 多工具容器），弹性伸缩（高峰扩、空闲归零）+ 多容器协作。演进：SSH 静态 → Docker 隔离 → K8s 弹性。

### Q8：Jenkins 怎么保证构建环境一致性？
> ① Docker Agent（镜像即环境声明）；② 依赖缓存挂载（m2）；③ 禁止环境漂移（动态 Agent 用完即焚）；④ 环境问题不修 Agent 改镜像。核心思想：环境代码化，杜绝"换台机器就失败"。

### Q9：Jenkins 怎么备份和恢复？坑在哪？
> 备份 JENKINS_HOME 整目录（jobs/credentials/plugins/config/secrets/users）；**secrets/ 加密密钥必须一起备份**（否则恢复后凭证解密失败）；频率每日 + 季度恢复演练。恢复演练是备份的一部分。

### Q10：2026 年 Jenkins 还值得学/用吗？
> 市场：组织采用率 28%（GitHub Actions 33% 领跑、GitLab CI 19%）。新项目默认 GitHub Actions/GitLab CI；Jenkins 的甜区是存量企业（已有大量流水线/插件）、内网隔离/数据主权、多 SCM、复杂 Groovy 逻辑。学它=理解 CI/CD 底层机制 + 存量工作刚需；当前 LTS 2.555.x 需 Java 21。
