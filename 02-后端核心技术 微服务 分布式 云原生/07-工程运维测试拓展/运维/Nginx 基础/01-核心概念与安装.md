## 1. Nginx 是什么

```text
Nginx（engine x）：高性能 HTTP 服务器 + 反向代理服务器 + 邮件代理服务器
  2004 年发布，俄罗斯 Igor Sysoev 开发
  高并发、低内存、模块化设计
```

| 角色 | 说明 |
|------|------|
| Web 服务器 | 静态资源高性能服务 |
| 反向代理 | 代理后端服务（隐藏拓扑） |

## 2. 高并发原理（面试必答）

```text
Nginx 能抗高并发的核心原因：
  ① 事件驱动 + 异步非阻塞：一个 worker 进程管理大量连接
  ② I/O 多路复用：Linux 用 epoll、BSD 用 kqueue
  ③ master/worker 架构：master 管理，worker 处理
  ④ 与传统"1 连接 1 线程"对比：
     传统模型：连接越多线程越多 → 内存爆炸
     Nginx：事件驱动 → 内存消耗在流量增长时保持稳定
```

| 对比 | Apache（进程/线程模型） | Nginx（事件驱动） |
|------|------------------------|-------------------|
| 并发模型 | 每连接一进程/线程 | 每 worker 管理海量连接 |
| 高并发 | 内存消耗线性增长 | 内存消耗稳定 |
| 模块 | 功能模块多 | 核心精简 + 模块化 |
| 动态加载模块 | 支持 | 编译期（社区版） |

> 🎯 **面试 30 秒模板**："Nginx 基于事件驱动与异步非阻塞 IO（epoll），一个 worker 进程通过 I/O 多路复用管理大量连接；master 管理 worker，worker 处理请求——相比 1 连接 1 线程的模型，高并发下内存消耗稳定。"

## 3. 进程模型

```text
master 进程（1 个）：
  读取配置、管理 worker、平滑重启（reload）

worker 进程（多个）：
  处理请求（事件驱动，无锁竞争共享）
  worker_processes auto = CPU 核数

cache manager/loader（缓存管理）
```

```text
请求处理流程：
客户端连接 → worker 进程（epoll 监听事件）
  → 事件循环处理（非阻塞）→ 响应
```

| 进程 | 职责 | 数量 |
|------|------|------|
| master | 配置/管理/信号 | 1 |
| worker | 处理请求 | CPU 核数（auto） |
| cache manager | 缓存淘汰 | 1 |
| cache loader | 缓存加载 | 1 |

> 💡 **worker_processes auto**：默认等于 CPU 核数——worker 太多（进程切换开销）或太少（并发不足）都不好。

## 4. 安装与版本选择

```bash
# Ubuntu/Debian
apt install nginx

# CentOS/RHEL
yum install nginx

# 编译安装（自定义模块）
./configure --prefix=/usr/local/nginx --with-http_ssl_module

# 验证
nginx -v          # nginx version: nginx/1.28.2
```

## 5. 配置文件结构

```text
nginx.conf 三层结构：
  http 块（全局 HTTP 配置）
    ├─ server 块（虚拟主机：域名/端口）
    │    ├─ location 块（URL 匹配）
    │    └─ location 块
    └─ upstream（后端组，负载均衡）
```

```nginx
# nginx.conf 骨架
user nginx;                    # 运行用户（安全：非 root）
worker_processes auto;         # worker 数 = CPU 核数
events {
    worker_connections 10240;  # 每 worker 最大连接数
    use epoll;                 # Linux I/O 多路复用
}
http {
    include mime.types;        # MIME 类型
    gzip on;                   # 压缩

    upstream backend {         # 后端组（负载均衡）
        server 127.0.0.1:8080;
    }

    server {                   # 虚拟主机
        listen 80;
        server_name example.com;

        location / {           # URL 匹配
            proxy_pass http://backend;
        }
    }
}
```

| 配置块 | 作用域 | 说明 |
|--------|--------|------|
| `http` | 全局 | HTTP 通用配置 |
| `server` | 虚拟主机 | 按域名/端口区分站点 |
| `location` | URL 匹配 | 按路径分发处理 |
| `upstream` | 后端组 | 负载均衡定义 |

## 6. 基本操作命令

```bash
nginx -t              # 测试配置语法（修改后必跑）
nginx -s reload       # 平滑重载（不断连接）
nginx -s stop         # 停止
nginx -s quit         # 优雅停止（处理完请求）
systemctl restart nginx   # 重启（CentOS/Ubuntu 服务方式）

# 查看状态
ps aux | grep nginx    # master + worker 进程
```

> ⚠️ **改配置的标准流程**：`vim 配置 → nginx -t 验证 → nginx -s reload`——**reload 是热加载（不中断连接）**，不要用 restart 替代（restart 会断开连接）。

## 7. 核心要点

> 🎯 **核心要点**：
> - 高并发原理四要素：事件驱动、epoll、master-worker、异步非阻塞（面试必答）；
> - 进程模型：master 管理 + worker 处理（worker_processes auto = CPU 核数）；
> - 配置三层：http → server → location（+ upstream 后端组）；
> - 改配置流程：`nginx -t` → `nginx -s reload`（热加载，勿随意 restart）；
> - 生产选稳定版 1.28.x；运行用户非 root（安全）；
> - 与 Apache 对比：事件驱动 vs 进程模型——高并发内存稳定。
