## 1. 性能调优清单

### 1.1 Nginx 配置

```nginx
# 核心调优（生产基线）
worker_processes auto;                 # = CPU 核数
worker_rlimit_nofile 65535;            # 文件描述符上限

events {
    worker_connections 10240;          # 每 worker 连接数（10240+）
    use epoll;                         # Linux I/O 多路复用
    multi_accept on;                   # 一次 accept 多个连接
}

http {
    keepalive_timeout 65;              # 客户端 keepalive
    sendfile on;                       # 零拷贝（静态文件）
    tcp_nopush on;                     # 数据包合并
    tcp_nodelay on;                    # 禁用 Nagle（小包即时）
    gzip on;                           # 压缩
    open_file_cache max=1000 inactive=20s;   # 文件句柄缓存
}
```

| 调优项 | 收益 |
|--------|------|
| `worker_processes auto` + `worker_connections` | 并发能力 |
| `sendfile on` | 零拷贝（静态资源吞吐） |
| `tcp_nodelay` | 小请求延迟 |
| `open_file_cache` | 减少磁盘 IO |
| `gzip` | 传输体积 |

### 1.2 操作系统

```bash
# 文件描述符限制
ulimit -n 65535

# 内核参数（/etc/sysctl.conf）
net.core.somaxconn = 32768            # accept 队列
net.ipv4.tcp_max_syn_backlog = 65536  # SYN 队列
net.ipv4.ip_local_port_range = 1024 65535  # 本地端口范围
```

> 🎯 **调优顺序**：先确认瓶颈（worker 数量/连接数/文件描述符/内核队列）——**每个参数对应一个资源上限**，逐个对齐。

## 2. 502/504/499 排障实战

### 2.1 502 Bad Gateway（连接失败）

```text
现象：Nginx 无法连接后端
日志：connect() failed (111: Connection refused) while connecting to upstream
```

| 原因 | 排查 |
|------|------|
| 后端未启动 | `ss -tlnp \| grep 8080` |
| 端口配置错 | proxy_pass 的端口 |
| 防火墙 | telnet 后端端口 |
| 后端崩溃 | 后端日志/监控 |

### 2.2 504 Gateway Timeout（后端超时）

```text
现象：Nginx 等不到后端响应
日志：upstream timed out
```

| 原因 | 排查 |
|------|------|
| proxy_read_timeout 太小 | 调大（按业务） |
| 后端处理慢 | `$upstream_response_time` 看后端耗时 |
| 后端线程池/连接池满 | 后端监控 |

### 2.3 499（客户端断开）

```text
现象：客户端等不及断开（Nginx 记录 499）
排查关键：$request_time（总耗时）vs $upstream_response_time（后端耗时）
```

```text
耗时对比法（面试加分）：
  rt 大 + urt 小 → 网络层问题（客户端→Nginx 链路慢）
  rt 大 + urt 大 → 后端处理慢（后端优化）
  都正常但 499 → 客户端侧主动超时（前端超时配置）
```

## 3. 高频避坑清单

| # | 坑 | 规避 |
|---|----|------|
| 1 | 改配置不 `nginx -t` | 语法错直接 reload 失败 |
| 2 | 用 restart 代替 reload | reload 热加载不断连接 |
| 3 | proxy_pass 路径配错 | 带 `/` 替换前缀、不带保留（见 03） |
| 4 | 忘记 proxy_set_header | 后端拿不到真实 IP/Host |
| 5 | 限流误伤内网 | 内网共享出口 IP——zone 按需/放行内网 |
| 6 | 日志只 mv 不 USR1 | 磁盘不释放（见 09） |
| 7 | 证书私钥权限 | chmod 600 |
| 8 | 超时一刀切 | 流式/WS 单独 location 长超时 |
| 9 | 缓存键过碎 | 命中率低（见 07） |
| 10 | worker 数拍脑袋 | auto（= CPU 核数） |

## 4. 面试 30 秒模板

```text
① 高并发原理：
"Nginx 基于事件驱动与异步非阻塞 IO（Linux epoll），
一个 worker 进程通过 I/O 多路复用管理海量连接；
master 管理 worker、worker 处理请求，
相比 1 连接 1 线程的模型，高并发下内存消耗稳定。"

② 正向 vs 反向：
"正向代理代理客户端（隐藏客户端），反向代理代理服务端（隐藏后端）。
Nginx 是反向代理：客户端只认识 Nginx，不知道真实后端。"

③ location 优先级：
"精确(=) > 前缀(^~) > 正则(~/~*) > 最长前缀 > 默认(/)。"

④ 负载均衡策略：
"轮询（默认）、加权轮询（weight）、最少连接（least_conn）、IP 哈希（ip_hash）。"

⑤ proxy_pass 路径：
"带 /（有 URI）替换 location 前缀；不带则路径原样保留。"
```

## 5. 面试题

| 题目 | 答题要点 |
|------|---------|
| Nginx 为什么能抗高并发？ | 事件驱动 + epoll + master-worker + 异步非阻塞（30 秒模板） |
| 正向代理和反向代理区别？ | 代理客户端 vs 代理服务端；Nginx 是反向代理 |
| location 匹配优先级？ | 精确 > ^~ > 正则 > 最长前缀 > 默认 |
| proxy_pass 带 / 与不带 / 的区别？ | 带 / 替换前缀、不带保留路径（高频） |
| proxy_set_header 必配哪些？ | Host/X-Real-IP/X-Forwarded-For/X-Forwarded-Proto |
| 负载均衡几种策略？ | 轮询/加权/最少连接/IP 哈希 |
| 怎么实现会话保持？ | ip_hash（或 sticky 模块） |
| 502/504 区别？ | 连接失败 vs 响应超时 |
| 怎么判断是网络问题还是后端问题？ | $request_time vs $upstream_response_time 对比 |
| limit_req 是什么算法？ | 漏桶：rate + burst + 超限 503/429 |
| 怎么防 SQL 注入/XSS？ | 关键字拦截（基础）+ WAF（生产）+ 安全头 |
| HTTPS 怎么优化性能？ | 会话复用 + TLS1.3 + HTTP/2 + OCSP 装订 |
| 日志切割怎么做？ | logrotate + kill -USR1 |
| Nginx 与 Gateway 的分工？ | Nginx 管流量（网络层）、Gateway 管路由（应用层） |

## 6. 核心要点

> 🎯 **核心要点**：
> - 调优三件套：worker 数（auto）+ 连接数（10240+）+ 文件描述符（65535）；
> - 排障三码：502（连接）/504（超时）/499（客户端断）——配日志三变量（rt/urt/ustatus）；
> - 耗时对比法是"网络 vs 后端"的裁决器；
> - 避坑 Top3：nginx -t 不跑、restart 代替 reload、proxy_pass 路径错；
> - 面试五模板：高并发/正反代理/location 优先级/负载均衡策略/proxy_pass 路径；
> - 与体系联动：安全看 [08](08-限流与安全防护.md)、排障看网络问题排查、监控看日志监控指标。
