## 1. 跳板机（Jump Host）

```text
场景：生产环境只能通过堡垒机/跳板机访问内网服务器
Xshell 的 Jump Host 代理：
  目标会话 → 连接 → 通过代理（跳板会话）→ 自动跳转
```

```text
配置方式：
  ① 先创建跳板机会话（能访问内网的那台）
  ② 目标服务器会话 → 属性 → 连接 → 代理 → 选择跳板机会话
  ③ 连接目标时自动经跳板机跳转
```

| 能力 | 说明 |
|------|------|
| 跳板代理 | 通过已有会话作为代理 |
| 多层跳转 | 跳板链（A → B → 目标） |
| 凭据独立 | 跳板机与目标服务器凭据分开保存 |
| 可视化 | 会话属性配置（无需手写 ProxyCommand） |

> 🎯 **跳板机是生产环境的标配**：**数据库/管理台不暴露公网，全部经跳板访问**——Xshell 的会话代理让跳转配置可视化。

## 2. 端口转发

```text
SSH 隧道（与 FinalShell 同源能力）：
  本地转发：本地端口 → 服务器 → 内网目标
  远程转发：服务器端口 → 本地
  动态转发：SOCKS 代理
  X11 转发：图形界面转发（Linux GUI 程序）
```

```text
配置方式：
  会话 → 属性 → 连接 → SSH → 隧道 → 添加
  本地端口 3307 → 目标 127.0.0.1:3306（内网 MySQL）
```

| 典型场景 | 配置 |
|----------|------|
| 本地连内网数据库 | 本地 3307 → 127.0.0.1:3306 |
| 本地访问内网管理台 | 本地 8080 → 127.0.0.1:8080 |
| 安全访问 | 不开放公网端口，按需隧道 |

> ⚠️ 隧道即暴露面：**用完删除规则**；生产数据库管理走隧道比安全组开端口更安全（临时、加密、有审计）。

## 3. 脚本录制与自动化

```text
场景：重复性操作（部署流程/巡检命令）自动化
Xshell 脚本能力：
  脚本录制（操作回放）
  Python 脚本（高级自动化）
  JavaScript 脚本
```

```text
脚本录制流程：
  工具 → 脚本 → 录制 → 执行操作（登录、执行命令）
  → 停止录制保存 → 后续一键回放
```

| 脚本类型 | 用途 |
|----------|------|
| 录制回放 | 简单重复操作（部署/巡检） |
| Python 脚本 | 复杂逻辑（条件/循环） |
| JavaScript | 终端交互自动化 |

```text
典型场景：
  一键部署：上传 → 备份 → 重启 → 健康检查
  巡检脚本：df/free/top 输出收集
  批量登录执行
```

> 💡 **脚本自动化 vs CI/CD**：Xshell 脚本适合"人在终端做的重复操作"（临时部署/巡检）；正式交付流水线用 CI/CD 体系（见 CI CD灰度发布）。

## 4. 快捷命令与触发器

### 4.1 快捷命令

```text
快捷命令（Quick Command）：
  常用命令保存为按钮/菜单 → 一键执行
  支持参数（发送所选文本）
```

| 快捷命令示例 | 命令 |
|--------------|------|
| 查磁盘 | `df -h` |
| 查内存 | `free -m` |
| Java 日志 | `tail -f /app/logs/app.log` |
| 重启服务 | `systemctl restart {服务}` |

### 4.2 触发器（Trigger）

```text
触发器 = 终端输出匹配 → 自动动作
  匹配特定文本 → 发送命令/运行脚本/高亮
```

| 触发器场景 | 配置 |
|------------|------|
| 登录后自动执行 | 匹配 `$` 提示符 → 发送巡检命令 |
| 日志关键字告警 | 匹配 `ERROR` → 高亮/声音 |
| 自动跳转目录 | 登录后 → cd 到工作目录 |

> 🎯 **触发器是"终端自动化"的轻量方案**：登录即执行、关键字即反应——不用写脚本也能自动化高频操作。

## 5. 撰写窗格与本地 Shell

| 功能 | 说明 |
|------|------|
| 撰写窗格（Compose Bar） | 输入一次命令 → 发送到多个会话（批量） |
| 本地 Shell | Windows 本地命令行（cmd/PowerShell）标签 |
| WSL 集成 | Windows 子系统 Linux 终端标签 |

```text
撰写窗格用法（批量命令）：
  视图 → 撰写窗格 → 勾选目标会话
  → 输入命令 → 发送
  典型：所有节点 systemctl restart app
```

> ⚠️ 批量命令纪律（同 FinalShell）：**先单台验证再批量**；只读命令批量安全，写操作谨慎。

## 6. 与 FinalShell 对比选型

| 维度 | Xshell + Xftp | FinalShell |
|------|---------------|-----------|
| 形态 | 双工具（成熟组合） | 单工具四合一 |
| 平台 | Windows | Win/Mac/Linux |
| 会话管理 | 老牌成熟（主密码加密） | 良好 |
| 实时监控 | ❌ | ✅ 内置 |
| 脚本自动化 | ✅ 录制/触发器/脚本 | 基础 |
| 跳板机 | ✅ Jump Host | ✅ 代理链 |
| 文件同步 | ✅ Xftp 文件夹同步/FXP | ✅ 打包上传 |
| 免费 | 个人/学校 | 免费版（广告） |
| 适合 | **Windows 老用户/企业** | 全平台/一体化 |

| 选择场景 | 推荐 |
|----------|------|
| Windows + 习惯双工具 | Xshell + Xftp |
| 需要脚本自动化 | Xshell（录制/触发器更强） |
| 需要实时监控 | FinalShell（内置监控） |
| 跨平台 | FinalShell |
| 企业采购 | 按平台与预算评估 |

> 🎯 **结论**：两个工具不是"谁更好"，是"流程匹配"——**Xshell 赢在成熟与自动化，FinalShell 赢在一体化与监控**；Windows 纯运维老用户选 Xshell 组合更顺手。

## 7. 生产避坑清单

| # | 坑 | 规避 |
|---|----|------|
| 1 | 非官方渠道下载 | NetSarang 官网 |
| 2 | 商业环境用个人免费授权 | 商业购买许可 |
| 3 | 密码登录生产 root | 公钥（ED25519）+ 禁密码 root |
| 4 | 主密码丢失 | 无法找回——务必记录 |
| 5 | 隧道长期挂 | 用完删规则 |
| 6 | 批量命令写操作 | 先单台验证 |
| 7 | 触发器误触发 | 匹配文本精确（避免宽松匹配） |
| 8 | 会话无保活 | 属性开启 Keep-Alive |
| 9 | 会话命名混乱 | `环境-角色` 分组规范 |
| 10 | 忽略日志记录 | 开启会话日志（审计） |

## 8. 核心要点

> 🎯 **核心要点**：
> - 跳板机：会话代理可视化（生产访问内网的标配姿势）；
> - 端口转发：本地/远程/动态 + X11，隧道即暴露面（用完删）；
> - 自动化三件套：脚本录制（简单）、Python 脚本（复杂）、触发器（登录即执行）；
> - 快捷命令 + 撰写窗格（批量）= 高频运维效率杠杆；
> - 选型：成熟自动化选 Xshell，一体化监控选 FinalShell；
> - 避坑 Top3：非官方下载、主密码丢失、批量写操作；
> - 定位：Windows 平台"终端+文件"的老牌组合，与 FinalShell 互补并存。
