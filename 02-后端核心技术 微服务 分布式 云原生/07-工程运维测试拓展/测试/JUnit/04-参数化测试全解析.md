## 1. 参数化模型与依赖

`@ParameterizedTest` 本质是 `@TestTemplate`：由 `ParameterizedTestExtension` 为每组参数生成一次调用。需要依赖 `junit-jupiter-params`（`junit-jupiter` 聚合器已包含）。

```java
@ParameterizedTest
@ValueSource(ints = {0, 1, 2, 3, 5, 8})
void fib_knownValues(int input) {
    assertEquals(fib(input), fibRecur(input));
}
```

> 💡 每个参数组合是**独立测试节点**：IDE 与报告中展开为 N 条记录，失败只标红对应行——这正是参数化优于 for 循环断言的根本原因（后者一条失败全组归零）。

## 2. 六类数据源

### 2.1 @ValueSource：单参数基础值

| 属性 | 类型 |
|------|------|
| `shorts/bytes/ints/longs` | 数值数组 |
| `floats/doubles` | 浮点数组 |
| `chars` | 字符数组 |
| `booleans` | 布尔数组 |
| `strings` | 字符串数组（含空串 `""`，不含 null） |
| `classes` | 类数组（5.8+） |

### 2.2 @NullSource / @EmptySource / @NullAndEmptySource

```java
@ParameterizedTest
@NullAndEmptySource                    // null + "" 全测
@ValueSource(strings = {"  ", "ab"})   // 与业务值组合
void trim_handlesEdgeCases(String input) {
    assertNotNull(Objects.requireNonNullElse(input, "").trim());
}
```

- `@NullSource`：注入一个 null；`@EmptySource`：注入 `""`（或空数组/空集合，取决于参数类型）；JUnit 6.1 起 `@EmptySource` 支持 `Iterable`/`Iterator` 参数。

### 2.3 @EnumSource：枚举遍历

```java
@ParameterizedTest
@EnumSource(value = Status.class, names = {"ACTIVE", "PENDING"}, mode = EnumSource.Mode.INCLUDE)
void status_valid(Status s) { }

@ParameterizedTest
@EnumSource(value = Status.class, names = "^(ACTIVE|PENDING)$", mode = EnumSource.Mode.MATCH_ALL)
void status_regex(Status s) { }
```

### 2.4 @MethodSource：工厂方法（最灵活）

```java
@ParameterizedTest
@MethodSource("provideOrders")
void order_validation(Order order, boolean valid) {
    assertEquals(valid, validator.isValid(order));
}

static Stream<Arguments> provideOrders() {           // 必须 static（PER_CLASS 下可非 static）
    return Stream.of(
        Arguments.of(Order.builder().amount(-1).build(), false),
        Arguments.of(Order.builder().amount(100).build(), true)
    );
}
```

- 返回类型须为 `Stream<Arguments>` / `Stream<T>`（单参时）/ `Collection` / `Iterator` / `Iterable` / `Arguments` 数组；
- 未指定名称时默认寻找**同名**工厂方法；跨类引用用 `包名.类名#方法名`；
- JUnit 6 新增 `Arguments.of(...)` 从 `Iterable` 构造的工厂方法。

### 2.5 @CsvSource / @CsvFileSource：表格数据

```java
@ParameterizedTest
@CsvSource({
    "apple, 3",
    "banana, 6",
    "'a, b', 2",        // 单引号包裹含逗号的值
    "'' , 0"            // 空串
})
void count_chars(String input, int expected) {
    assertEquals(expected, count(input));
}
```

```java
@ParameterizedTest
@CsvFileSource(resources = "/data/orders.csv", numLinesToSkip = 1)
void batch_orders(String id, int amount) { }
```

### 2.6 @ArgumentsSource：自定义 Provider

```java
@ParameterizedTest
@ArgumentsSource(RandomAmountProvider.class)
void amount_positive(int amount) { assertTrue(amount > 0); }

class RandomAmountProvider implements ArgumentsProvider {
    @Override
    public Stream<? extends Arguments> provideArguments(ExtensionContext context) {
        return IntStream.range(0, 10).mapToObj(i -> Arguments.of(i * 37 % 100 + 1));
    }
}
```

> 🎯 选型速记：值少用 `@ValueSource`；枚举用 `@EnumSource`；结构数据用 `@MethodSource`（命名工厂可复用）；表格/批数据用 `@CsvSource`/`@CsvFileSource`；需复用复杂逻辑用 `@ArgumentsSource` 实现类。

## 3. 类型转换机制

### 3.1 隐式转换

字符串自动转为方法参数类型，内置支持：基础类型及包装类、`BigDecimal/BigInteger`、`UUID`、`LocalDate/Time/DateTime`（ISO 8601）、`Duration/Period`、`File/Path`、`java.net.URI/URL`、`Charset/Currency/Locale/TimeZone`、枚举、`Class` 等（遵循 JavaBeans 属性命名如 `yyyy-MM-dd` 的日期格式）。

```java
@ParameterizedTest
@ValueSource(strings = {"2026-01-01", "2026-08-06"})
void date_valid(LocalDate d) { }
```

### 3.2 显式转换 @ConvertWith

```java
@ParameterizedTest
@ValueSource(strings = {"1,2,3", "4,5"})
void sum_list(@ConvertWith(StringToIntList.class) List<Integer> nums) {
    assertEquals(3 + 3, nums.stream().mapToInt(i -> i).sum());
}

class StringToIntList extends SimpleArgumentConverter {
    @Override
    protected Object convert(Object source, Class<?> targetType) {
        return Arrays.stream(((String) source).split(","))
            .map(Integer::parseInt).toList();
    }
}
```

### 3.3 无参/接口参数的限制

参数类型为接口或抽象类时，若隐式转换不可用则回退到 `@ConvertWith`；**多个 `@ConvertWith` 无法同时修饰多参数**——多参数复杂转换请用参数聚合。

## 4. 参数聚合

### 4.1 @ArgumentsAccessor：按索引取

```java
@ParameterizedTest
@CsvSource({"zhang, 30, Beijing", "li, 25, Shanghai"})
void user_import(ArgumentsAccessor args) {
    User u = new User(args.getString(0), args.getInteger(1), args.getString(2));
}
```

### 4.2 @AggregateWith：自定义聚合器

```java
@ParameterizedTest
@CsvSource({"zhang, 30, Beijing"})
void user_import(@AggregateWith(UserAggregator.class) User user) {
    assertEquals("zhang", user.name());
}

static class UserAggregator implements ArgumentsAggregator {
    @Override
    public Object aggregateArguments(ArgumentsAccessor accessor, ParameterContext context) {
        return new User(accessor.getString(0), accessor.getInteger(1), accessor.getString(2));
    }
}
```

> 💡 聚合器把「CSV 行 → 领域对象」的转换集中为一处，测试方法与数据格式解耦；JUnit 6 中**单 String/CharSequence 属性的 record/类**可直接由参数化测试构造，部分聚合场景可省略自定义聚合器。

## 5. 显示名称与自定义 Provider

### 5.1 命名占位符

```java
@ParameterizedTest(name = "[{index}] {0} → 期望 {1}")   // 索引 + 参数插值
@CsvSource({"apple,3", "banana,6"})
void count(String input, int expected) { }
```

JUnit 6 起默认显示格式统一为 `name = value`，字符串参数默认加引号（可用 `quoteTextArguments = false` 关闭）。

### 5.2 组合注解（@ParameterizedTest 元注解）

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
@ParameterizedTest
@ValueSource(ints = {0, 1, 2})
public @interface BoundValueTest { }
```

自定义组合注解可在多个测试类中复用同一组数据源配置。

## 6. JUnit 6 的变化与陷阱

| 变化 | 说明 |
|------|------|
| FastCSV 替换 univocity | CSV 解析更快、RFC 4180 合规；**闭合引号后出现多余字符 → 直接格式错误**（旧版宽容忽略） |
| `lineSeparator` 移除 | 行尾自动识别 `\r`/`\n`/`\r\n`，原属性配置删除即可 |
| 字符串参数默认加引号 | 显示名 `input = "apple"`；`quoteTextArguments=false` 还原 |
| `CharSequence` 转换 | 单 `String`/`CharSequence` 属性 record 可直接构造 |
| `@EmptySource` 支持 Iterable/Iterator | 6.1+ 空集合参数化 |
| `Arguments.computeIfAbsent` | 接口新增空安全方法 |

**常见陷阱清单**：

1. `@MethodSource` 方法找不到 → 检查是否为 static、方法名/签名是否精确匹配（`Stream<Arguments>` vs `List<String>`）；
2. CSV 中空格被保留 → `@CsvSource({" apple , 3 "})` 会传 `" apple "`；数据源内用 `useHeadersInDisplayName` 前先确认表头；
3. 单参数测试声明了多参数方法 → 编译过但运行报「参数数量不匹配」，IDE 参数预览可提前发现；
4. 隐式转换对 `null`：`@NullSource` 不参与转换直接注入 null，符合预期；
5. 参数化 + 并行执行：每组调用是独立节点，天然并行友好，但共享外部资源时仍需 `@ResourceLock`（见 05 模块）。

> 🎯 **核心要点**：参数化测试的黄金法则是「**一个维度一个数据源**」——矩阵式笛卡尔积用嵌套参数化（JUnit 6 已支持）或显式 Arguments 列表，避免 3+ 维组合爆炸；数据源优先内聚（CSV 文件便于产品/测试协作），复杂对象一律走聚合器，保持测试体只关心「断言」。
