## 1. Maven 集成（Surefire/Failsafe 3.x）

### 1.1 版本要求

**JUnit 6 要求 Surefire/Failsafe ≥ 3.0.0**（2.x 不兼容）。3.x 对 JUnit Platform 原生支持（默认发现引擎），无需额外 provider 依赖。

```xml
<properties>
    <junit.version>6.1.1</junit.version>
</properties>

<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.junit</groupId>
            <artifactId>junit-bom</artifactId>
            <version>${junit.version}</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>

<dependencies>
    <dependency>
        <groupId>org.junit.jupiter</groupId>
        <artifactId>junit-jupiter</artifactId>
        <scope>test</scope>
    </dependency>
    <dependency>
        <groupId>org.mockito</groupId>
        <artifactId>mockito-junit-jupiter</artifactId>
        <scope>test</scope>
    </dependency>
</dependencies>
```

### 1.2 Surefire（单元测试）

```xml
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-surefire-plugin</artifactId>
    <version>3.5.3</version>
    <configuration>
        <!-- 默认匹配 *Test.java / Test*.java / *Tests.java / *TestCase.java -->
        <includes>
            <include>**/*Test.java</include>
        </includes>
        <groups>fast</groups>                     <!-- 只跑 fast 组 -->
        <excludedGroups>slow,integration</excludedGroups>
        <forkCount>2</forkCount>                  <!-- JVM 分叉：隔离 + 并行 -->
        <reuseForks>true</reuseForks>
    </configuration>
</plugin>
```

### 1.3 Failsafe（集成测试）

集成测试命名 `*IT.java`，绑定 `integration-test`/`verify` 阶段，**失败不中断 install 前的构建，但在 verify 时汇总判定**：

```xml
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-failsafe-plugin</artifactId>
    <version>3.5.3</version>
    <executions>
        <execution>
            <goals>
                <goal>integration-test</goal>
                <goal>verify</goal>
            </goals>
        </execution>
    </executions>
</plugin>
```

```bash
mvn verify                          # 单测(未单元) + IT(集成) + 质量门禁全跑
mvn test -Dgroups=fast              # 仅 fast 组单测
mvn verify -Dit.test=OrderIT        # 只跑指定 IT
```

> 💡 **命名约定即策略**：`*Test` 进 `test` 阶段（快、无外部依赖），`*IT` 进 `verify` 阶段（慢、要容器/真实环境）——这条物理边界让「单测秒级、集成按需」成为团队默认。

## 2. Gradle 集成

```groovy
dependencies {
    testImplementation(platform("org.junit:junit-bom:6.1.1"))
    testImplementation("org.junit.jupiter:junit-jupiter")
    testImplementation("org.mockito:mockito-junit-jupiter")
    testRuntimeOnly("org.junit.platform:junit-platform-launcher")   // IDE/工具发现引擎
}

tasks.test {
    useJUnitPlatform {
        includeTags("fast")
        excludeTags("slow", "integration")
    }
    maxParallelForks = Runtime.runtime().availableProcessors()      // 按 JVM 分叉并行
    // 失败即停（JUnit 6 --fail-fast 的 Gradle 等价）
    // 见下：通过 systemProperty 传递或 build 时 failFast
}
```

Gradle 7.6+/8.x 对 JUnit Platform 支持成熟；`test` 任务的 `maxParallelForks` 是**进程级**并行（与 JUnit 内部并行互补，见 05 模块）。

## 3. ConsoleLauncher 独立执行

CI、脚本、docker 内执行测试的独立入口：

```bash
# 单包方式（含引擎与 Jupiter）
java -jar junit-platform-console-standalone-6.1.1.jar --scan-class-path target/classes:target/test-classes

# 筛选与输出
java -jar junit-platform-console-standalone.jar \
  --select-class com.example.OrderServiceTest \
  --include-tag fast \
  --fail-if-no-tests \
  --details tree

# JUnit 6：失败即停
java -jar junit-platform-console-standalone.jar --scan-class-path . --fail-fast
```

### 3.1 JUnit 6.1 单文件测试（org.junit.start，Java 25+）

```java
// HelloTests.java —— 单文件源码程序，免 Maven/Gradle
import module org.junit.start;

void main() {
    JUnit.run();
}

@Test
void stringLength() {
    Assertions.assertEquals(11, "Hello JUnit".length());
}
```

```bash
java --module-path lib --add-modules org.junit.start HelloTests.java
# 输出：JUnit Jupiter ✔ → HelloTests ✔ → stringLength() ✔
```

适用：算法题练习、教学示例、单文件脚本化验证——无需构建工具即可跑测试。

## 4. JUnit 6 平台新能力：JFR 与失败即停

### 4.1 JFR 集成（内置 launcher）

JUnit 6 起 JFR 事件内置于 `junit-platform-launcher`，无需额外依赖即可录制测试事件：

```bash
java -XX:StartFlightRecording=filename=test.jfr,duration=10m \
     -jar junit-platform-console-standalone-6.1.1.jar --scan-class-path .
```

事件类型：测试发现、类/方法开始与结束、失败断言等。用 `jfr` 工具或 IDE 分析：慢测试热点、GC 影响、锁竞争与测试并行效率。

### 4.2 CancellationToken 与 --fail-fast

JUnit 6 平台层支持运行时取消：`LauncherSession` 传入 `CancellationToken`，首个失败即中止剩余执行并汇总。收益：

- CI 快速失败：大仓库中把「失败后 20 分钟的无效执行」压缩到秒级；
- 消耗性资源（容器、付费 API）测试中及时止损。

编程式 Launcher 示例：

```java
LauncherDiscoveryRequest request = LauncherDiscoveryRequestBuilder.request()
    .selectors(selectClass(OrderServiceTest.class))
    .build();

try (LauncherSession session = LauncherFactory.openSession()) {
    session.getLauncher().execute(request,
        new SummaryGeneratingListener(),
        new CancellationToken() { });   // 默认 execute 即携带可取消令牌
}
```

## 5. CI 流水线实践

### 5.1 GitHub Actions 示例

```yaml
name: build
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with: { distribution: temurin, java-version: '21' }
      - uses: actions/cache@v4                    # Maven/Gradle 依赖缓存提速
        with: { path: ~/.m2, key: ${{ runner.os }}-m2 }
      - name: 单元测试 + 覆盖率
        run: mvn verify -B -Dgroups=fast
      - name: 上传测试报告
        uses: actions/upload-artifact@v4
        with: { name: surefire-reports, path: '**/target/surefire-reports/**' }
```

### 5.2 流水线策略

| 策略 | 说明 |
|------|------|
| 分层流水线 | fast 组 PR 门禁（分钟级）→ slow/IT 合并后跑（Testcontainers） |
| 失败即停 | JUnit 6 `--fail-fast` / CI 的 fail-fast，节省失败后时间 |
| 报告可见 | surefire-reports/HTML 报告上传，失败可追溯 |
| 测试重试策略 | 对**稳定代码**禁止重试掩盖问题；仅对已知 flaky 定点处理 |
| 矩阵 | JDK 17/21/25 矩阵验证多版本兼容 |

## 6. 覆盖率与质量门禁

```xml
<!-- JaCoCo：统计 + 门禁 -->
<plugin>
    <groupId>org.jacoco</groupId>
    <artifactId>jacoco-maven-plugin</artifactId>
    <version>0.8.13</version>
    <executions>
        <execution>
            <id>check</id>
            <goals><goal>check</goal></goals>
            <configuration>
                <rules>
                    <rule>
                        <element>BUNDLE</element>
                        <limits>
                            <limit><counter>LINE</counter><value>COVEREDRATIO</value><minimum>0.80</minimum></limit>
                        </limits>
                    </rule>
                </rules>
            </configuration>
        </execution>
    </executions>
</plugin>
```

> ⚠️ **覆盖率的正确姿势**：行覆盖率是**下限信号**而非目标——新代码要求 80%+，但关键分支（异常路径、幂等、并发）必须显式覆盖；用 JaCoCo 的 `excludes` 排除配置类/生成类，避免「凑覆盖率」；变异测试（Pitest）做局部强化验证时，配合 `@Disabled` 未覆盖路径审查。

> 🎯 **核心要点**：构建集成的本质是把「测试」变成「工程行为」——Surefire/Failsafe 的命名分界、Gradle 的 useJUnitPlatform、ConsoleLauncher 的零依赖执行，让测试在不同阶段以不同代价运行；JUnit 6 的 JFR 内置与失败即停是 2026 年 CI 提速的两个新杠杆，值得优先启用。
