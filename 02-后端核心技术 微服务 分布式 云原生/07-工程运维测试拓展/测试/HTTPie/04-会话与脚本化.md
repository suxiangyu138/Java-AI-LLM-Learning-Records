## 1. 会话（Sessions）机制

```text
会话 = 认证凭证 + Cookie + 自定义头的持久化存储
  ├─ 命名会话：~/.httpie/sessions/<HOST>/<NAME>.json
  ├─ 文件路径会话：--session=/tmp/sess.json（跨主机复用）
  └─ 只读会话：--session-read-only（复用但不更新）
```

```bash
# 命名会话（按主机隔离存储）
http --session=myapi POST api.example.com/login \
  username=admin password=secret
# 后续请求自动携带会话中的 Cookie/认证/头
http --session=myapi GET api.example.com/orders

# 文件路径会话（跨主机复用）
http --session=/tmp/sess.json POST api.example.com/login username=admin password=secret
http --session=/tmp/sess.json GET other.example.com/data

# 只读会话（不更新会话状态）
http --session-read-only=myapi GET api.example.com/orders
```

| 会话类型 | 存储位置 | 适用 |
|----------|---------|------|
| 命名会话 | `~/.httpie/sessions/<HOST>/<NAME>.json` | 单主机日常（推荐） |
| 文件路径会话 | 指定路径 | 跨主机/CI 临时会话 |
| 只读会话 | 复用不更新 | 幂等查询、脚本 |

> 💡 Windows 存储位置：`%APPDATA%\httpie\sessions\<HOST>\<NAME>.json`。

## 2. 认证一次，处处免认证

```bash
# 1. 登录并保存会话（密码提示输入，不落命令行）
http --session=myapi -a admin POST api.example.com/login \
  username=admin

# 2. 后续请求免认证（会话自动携带 Cookie/Token）
http --session=myapi GET api.example.com/orders
http --session=myapi POST api.example.com/orders \
  productId=1001 qty=2

# 3. 3.0+：提示输入的密码也会存入会话
# 之后同一会话无需再写 -a 参数
```

```text
会话持久化内容（3.x）：
  ✅ 自定义头（除 Content-*/If-* 外）
  ✅ 认证凭证（basic/digest/bearer）
  ✅ Cookie（手动设置 + 服务端 Set-Cookie）
  ✅ 提示输入的密码（3.0+）
  ✅ 重复头（3.2+ 同名字段持久化）
```

> 🎯 **核心价值**：会话把"登录 → 携带凭证 → 多次请求"从多步变一步——脚本和日常调试都不再重复写认证参数。

## 3. 会话安全实践

| # | 实践 | 说明 |
|---|------|------|
| 1 | 会话文件是明文 JSON | 含 Token/密码，**禁止提交 Git**（`.gitignore` 排除） |
| 2 | 每环境独立会话 | dev/test/prod 分开，避免用 dev token 打 prod |
| 3 | 密钥轮换 | 事故后轮换会话中存储的令牌 |
| 4 | 密码提示输入 | `-a user` 不写密码（不落 shell 历史） |
| 5 | 不在共享频道粘贴 Authorization | 明文 Token 泄露 |

> ⚠️ 会话文件（`~/.httpie/sessions/*.json`）是**明文存储**——本质是"本地便利"，不是安全存储。高敏感环境用环境变量注入 Token 而非会话持久化。

## 4. 离线构建与请求预览

```bash
# 1. 离线构建（不发请求，显示完整请求）
http --offline POST api.example.com/orders \
  productId=1001 qty:=2

# 2. 输出等价 curl 命令（分享/迁移）
http --offline POST api.example.com/orders productId=1001 | grep curl

# 3. 结合 -v 查看构造细节
http --offline -v POST api.example.com/orders \
  'Authorization: Bearer token' \
  productId:=1001
```

| 场景 | 用法 |
|------|------|
| 验证请求构造 | `--offline` 不发请求看全貌 |
| 分享请求给同事 | `--offline` 输出等价 curl 命令 |
| 迁移到 curl 脚本 | `--offline` 生成 curl 再改写 |

> 💡 `--offline` 是"调试前调试"：先确认请求构造正确再真正发送——避免把错误请求打到线上。

## 5. 脚本化与 CI 集成

```bash
#!/bin/bash
# api-smoke-test.sh — 冒烟测试脚本示例
set -e

BASE=https://api.example.com
TOKEN=$API_TOKEN                    # 环境变量注入（CI secrets）

# 1. 健康检查（--check-status 让 5xx 失败）
http --check-status -q $BASE/health

# 2. 认证并创建会话（CI 中不落盘用临时会话）
http --session=/tmp/ci-sess.json -A bearer -a $TOKEN \
  POST $BASE/orders productId=1001 qty:=2

# 3. 查询验证（复用会话）
RESP=$(http --session=/tmp/ci-sess.json --pretty=none \
  GET $BASE/orders/1001)
echo "$RESP" | jq -e '.status == "CREATED"' > /dev/null

echo "✅ API 冒烟测试通过"
```

| CI 集成要点 | 说明 |
|-------------|------|
| Token 注入 | 环境变量（GitHub Actions secrets / Jenkins credentials） |
| 会话临时化 | `/tmp/ci-sess.json` 用完即弃 |
| 门禁判断 | `--check-status` + `jq -e` 断言 |
| 日志友好 | `--pretty=none` 管道处理 |

```yaml
# GitHub Actions 示例
- name: API Smoke Test
  env:
    API_TOKEN: ${{ secrets.API_TOKEN }}
  run: |
    http --check-status -q https://api.example.com/health
    http -A bearer -a "$API_TOKEN" POST https://api.example.com/orders \
      productId=1001 qty:=2 --session=/tmp/ci-sess.json
```

> 💡 对比：HTTPie 适合"人写的冒烟/验收脚本"（可读）；大规模压测/复杂断言仍用 APIFox 套件 + JMeter（见同级 `APIFox/`、`Jmeter/` 体系）。

## 6. 多环境会话管理

```bash
# 按环境建会话（命名隔离）
http --session=dev-login POST https://dev-api.example.com/login username=admin
http --session=prod-login POST https://prod-api.example.com/login username=admin

# 使用对应环境会话
http --session=dev-login GET https://dev-api.example.com/orders
http --session=prod-login GET https://prod-api.example.com/orders

# 查看会话文件（确认存储内容）
ls ~/.httpie/sessions/api.example.com/
cat ~/.httpie/sessions/api.example.com/dev-login.json
```

| 实践 | 说明 |
|------|------|
| 环境隔离 | dev/test/prod 独立会话（防串环境） |
| 命名规范 | `<env>-<用途>`（dev-login/prod-read） |
| 定期清理 | 过期会话删除（`rm ~/.httpie/sessions/...`） |
| 密钥轮换 | 事故后删除对应会话文件重建 |

## 7. 核心要点

> 🎯 **核心要点**：
> - 会话三类型：命名（按主机）、文件路径（跨主机）、只读（复用不更新）；
> - 持久化内容：认证凭证 + Cookie + 自定义头（3.0 含提示密码、3.2 含重复头）；
> - **会话是明文 JSON**：不入 Git、每环境独立、事故即轮换；
> - `--offline`：不发请求看构造 + 输出等价 curl（分享/迁移）；
> - CI 公式：`--check-status` + 环境变量 Token + 临时会话 + jq 断言；
> - 定位：人写的冒烟/验收脚本利器；重测试交给 APIFox/JMeter。
