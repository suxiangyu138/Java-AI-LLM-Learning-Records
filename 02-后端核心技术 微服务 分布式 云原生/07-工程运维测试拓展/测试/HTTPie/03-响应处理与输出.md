## 1. 默认输出与格式化

```bash
# 默认输出：响应头 + 格式化正文（语法高亮）
http https://api.example.com/users

# 输出控制
http --pretty=all url          # 头+正文格式化（默认）
http --pretty=colors url       # 仅着色
http --pretty=format url       # 仅格式化（无颜色）
http --pretty=none url         # 原始输出（管道/重定向友好）
```

| 输出模式 | 行为 | 适用 |
|----------|------|------|
| 默认 | 头 + 高亮格式化正文 | 日常调试 |
| `--pretty=colors` | 仅颜色 | 管道处理 |
| `--pretty=format` | 仅格式化无颜色 | CI 日志 |
| `--pretty=none` | 原始输出 | 重定向到文件 |

> 💡 检测到非终端（管道/重定向）时自动降级为原始输出——脚本不会拿到 ANSI 颜色码。

## 2. 选择性输出（-p 组合）

```bash
# -p 选项组合：H=头、B=体、h=请求头、b=请求体
http -p H url                # 仅响应头
http -p B url                # 仅响应体
http -p hb url               # 请求头 + 请求体
http -p HB url               # 响应头 + 响应体（默认）
http -p hHBB url             # 请求+响应全量

# 常用快捷方式
http --headers url           # 等价 -p H
http --body url              # 等价 -p B
```

| 组合 | 显示内容 |
|------|---------|
| `-p h` | 请求头 |
| `-p b` | 请求体 |
| `-p H` | 响应头 |
| `-p B` | 响应体 |
| `-p hb` / `-p HB` / `-p hHBB` | 组合 |

## 3. 响应头与元信息

```bash
# 仅响应头（快速看状态/Content-Type/Set-Cookie）
http --headers https://api.example.com/users

# 完整元信息
http -v https://api.example.com/users
# 显示：请求行、请求头、请求体、响应行、响应头、响应体
```

```text
HTTP/1.1 200 OK                    ← 状态行
Content-Type: application/json     ← 响应头
Set-Cookie: session=abc123; ...
Date: ...
```

> 💡 调试三看：状态码（成功与否）→ Content-Type（解析方式）→ Set-Cookie/头（会话信息）——`--headers` 一眼看完。

## 4. 下载与文件输出

```bash
# 下载到文件
http https://example.com/file.zip -o ./file.zip
# 等价于 curl -o

# 输出到 stdout（管道）
http https://api.example.com/users --pretty=none | jq '.data[0].name'

# 上传 + 下载组合（API 二进制场景）
http POST api.example.com/convert -o ./result.pdf < ./input.docx
```

| 场景 | 命令 |
|------|------|
| 下载文件 | `http url -o ./out` |
| 管道 jq 处理 | `http --pretty=none url \| jq ...` |
| 响应直接重定向 | `http url > out.json` |

## 5. 流式输出与 SSE

```bash
# 流式输出（大响应/实时数据）
http --stream https://api.example.com/stream

# SSE 自动流式（3.x 特性：text/event-stream 自动启用）
http https://ai.example.com/chat/stream
# 无需 --stream：检测到 text/event-stream 自动流式显示
```

| 流式场景 | 行为 |
|----------|------|
| `--stream` | 强制流式（大 JSON/实时日志） |
| SSE 自动流式 | Content-Type: text/event-stream 时自动启用（3.x） |
| AI 接口调试 | 大模型流式输出（DeepSeek/通义 SSE）直接查看 |

> 💡 AI 场景：调试 LLM 流式接口（`text/event-stream`）时 HTTPie 自动流式——配合 `--pretty=none` 可管道处理事件流。

## 6. 退出码与脚本判断

| 退出码 | 含义 |
|--------|------|
| 0 | 成功（请求已发送并收到响应） |
| 1 | 一般错误（连接失败/DNS 失败等） |
| 2 | 请求被中断（Ctrl+C） |
| 3 | 其他错误（如无效选项） |

```bash
# 脚本用法：判断请求是否成功
if http -q https://api.example.com/health; then
    echo "服务正常"
else
    echo "服务异常"
fi
```

> ⚠️ **注意**：HTTPie 的退出码只表示"请求是否完成"，**不区分 HTTP 状态码**——404/500 也是退出码 0。判断业务状态看响应体/`--check-status`。

```bash
# --check-status：HTTP 状态码映射退出码（4xx=4, 5xx=5）
http --check-status https://api.example.com/users
echo $?    # 404 → 4；500 → 5；成功 → 0
```

> 💡 `--check-status` 让 HTTPie 像 curl `-f` 一样适合 CI 门禁：5xx 直接退出非 0。

## 7. verbose 调试全貌

```bash
# 完整请求+响应（调试首选）
http -v POST https://api.example.com/login \
  username=admin password=secret

# 精简版：只看请求
http -p hb POST url ...

# 离线查看将要发送的内容（不发请求）
http --offline POST https://api.example.com/login \
  username=admin password=secret
```

```text
# -v 输出全貌：
POST /login HTTP/1.1
Host: api.example.com
Content-Type: application/json

{"username": "admin", "password": "secret"}

HTTP/1.1 200 OK
Set-Cookie: session=abc...
Content-Type: application/json

{"token": "xxx"}
```

> 🎯 排查顺序：`http -v`（看请求是否正确）→ `--headers`（看响应头）→ `--offline`（不发请求看构造）。`--offline` 还输出等价 curl 命令（详见 [04](04-会话与脚本化.md)）。

## 8. 核心要点

> 🎯 **核心要点**：
> - 输出四模式：默认（格式化高亮）、colors、format、none（管道用）；
> - `-p` 组合：h/b（请求）H/B（响应），`--headers`/`--body` 快捷；
> - 下载 `-o`、管道 `--pretty=none \| jq`；
> - SSE 自动流式（3.x）——AI 接口调试利器；
> - 退出码只表示"请求完成"，业务判断用 `--check-status` 或响应断言；
> - 调试三连：`-v` 全貌 → `--headers` 头 → `--offline` 构造。
