## 1. items 运算符全表

| 运算符 | 含义 | 示例 | 说明 |
|--------|------|------|------|
| `=` | JSON 字符串字段 | `name=张三` | 自动序列化（JSON 模式） |
| `:=` | 原始 JSON 值 | `age:=30`、`tags:='["a","b"]'` | 数字/布尔/嵌套对象 |
| `:` | 请求头 | `X-Token:abc` | 头字段 |
| `==` | URL 查询参数 | `page==2` | Query 参数 |
| `@` | 从文件读取 | `key=@file.json`、`data:@file` | 文件内容作为值 |
| `==@` | 查询参数从文件（3.x） | `q==@query.txt` | 值来自文件 |
| `:@` | 头从文件（3.x） | `X-Sign:@sign.txt` | 头值来自文件 |
| `;` | 多值头 | `X-Tag:a;b` | 同名字段多个值（3.0 非唯一头） |

> 🎯 记忆法：`=` 系列处理 Body、`:` 系列处理头、`==` 处理 URL——**三个符号覆盖请求的全部组成**。

## 2. JSON 请求构造

```bash
# 1. 简单 JSON（自动序列化）
http POST api.example.com/users \
  name=张三 \
  email=zhangsan@example.com

# 2. 原始 JSON 值（数字/布尔/嵌套）
http POST api.example.com/users \
  name=张三 \
  age:=30 \
  active:=true \
  address:='{"city":"北京","street":"中关村"}'

# 3. JSON 数组
http POST api.example.com/batch \
  ids:='[1,2,3]'

# 4. 从文件读 JSON Body
http POST api.example.com/users < data.json
# 或
http POST api.example.com/users data=@data.json

# 5. 显式 JSON 模式（防止误判）
http -j POST api.example.com/users name=张三
```

```text
# 生成的请求（-v 查看）：
POST /users HTTP/1.1
Content-Type: application/json

{"name": "张三", "age": 30, "active": true}
```

> ⚠️ 易错点：`age=30` 是**字符串**"30"；要数字必须 `age:=30`。`=` 与 `:=` 的区别是 JSON 构造的核心。

## 3. 表单与文件上传

```bash
# 1. 普通表单（x-www-form-urlencoded）
http -f POST api.example.com/login \
  username=admin \
  password=secret

# 2. multipart 文件上传
http -m POST api.example.com/upload \
  file@./report.pdf \
  remark=季度报告

# 3. 二进制数据（不指定类型）
http POST api.example.com/upload < ./data.bin

# 4. 下载（响应到文件）
http https://example.com/file.zip -o ./file.zip
```

| 场景 | 模式 | 示例 |
|------|------|------|
| 登录表单 | `-f`（form） | `http -f POST ... username=admin` |
| 文件上传 | `-m`（multipart） | `http -m POST ... file@./a.pdf` |
| 原始 Body | 重定向 stdin | `http POST ... < body.json` |
| 下载 | `-o` | `http url -o ./out` |

> 💡 `-m` 与 `-f` 的区别：multipart 支持文件字段，form 仅键值——**上传文件用 `-m`**。

## 4. 请求头与查询参数

```bash
# 1. 自定义请求头
http GET api.example.com/orders \
  X-Auth-Token:abc123 \
  X-Trace-Id:20260808-001

# 2. 多值头（3.0 非唯一头支持）
http GET api.example.com/search \
  'X-Tag:a;b;c'

# 3. 查询参数（== 运算符）
http GET api.example.com/orders \
  page==2 \
  size==20 \
  status==PAID

# 4. 覆盖默认头
http GET api.example.com \
  'Accept:application/json' \
  'User-Agent:my-client/1.0'

# 5. 取消默认头（3.2.3）
http GET api.example.com 'User-Agent:' 'Accept-Encoding:'
```

> ⚠️ 3.2.3 新特性：**可取消 User-Agent / Accept-Encoding**——`头名:` 空值即移除，解决某些服务端对默认 UA 的校验问题。

## 5. 认证：basic / digest / bearer

```bash
# 1. Basic 认证
http -a user:pass api.example.com/private
http -a user api.example.com/private      # 只给用户名，提示输入密码

# 2. Digest 认证
http -A digest -a user:pass api.example.com/private

# 3. Bearer 认证（3.0 原生）
http -A bearer -a your-token api.example.com/api/orders
# 等价于 Authorization: Bearer your-token

# 4. 无认证参数时的 Authorization 头
http api.example.com/api 'Authorization: Bearer token'
```

| 认证类型 | 选项 | 说明 |
|----------|------|------|
| Basic | `-a user:pass`（默认） | 明文 base64 |
| Digest | `-A digest -a user:pass` | 摘要认证（MD5 挑战） |
| Bearer | `-A bearer -a token` | **3.0 原生支持** |
| 自定义头 | `'Authorization: ...'` | 任意格式手动控制 |

> 💡 **安全建议**：密码提示输入（`-a user` 不写密码）比命令行明文更安全——结合 `--session` 持久化（见 [04](04-会话与脚本化.md)），只需认证一次。

## 6. 自定义认证插件

```bash
# 插件管理（3.0+ httpie 命令）
httpie plugins install httpie-hmac-auth     # HMAC 签名认证
httpie plugins install httpie-edgegrid      # Akamai EdgeGrid
httpie plugins list

# 使用插件认证
http --auth-type=hmac-auth -a 'key:secret' api.example.com/orders
```

| 插件 | 场景 |
|------|------|
| httpie-hmac-auth | 自定义 HMAC 签名（时间戳+密钥签名） |
| httpie-edgegrid | Akamai API 认证 |
| 自研插件 | 按认证协议实现 AuthPlugin |

> 💡 Java 后端常见场景：网关签名认证（AppKey + 时间戳 + Sign）——用 hmac-auth 插件或前置脚本生成签名头。

## 7. 代理与 TLS

```bash
# 1. HTTP 代理
http --proxy=http://proxy.example.com:8080 https://api.example.com

# 2. 不同协议不同代理
http --proxy=http://http-proxy:8080 --proxy=https://https-proxy:8080 url

# 3. TLS 校验跳过（自签名证书调试）
http --verify=no https://self-signed.example.com

# 4. 指定 CA 证书
http --verify=/path/to/ca.pem https://api.example.com

# 5. 客户端证书
http --cert=./client.crt --cert-key=./client.key https://api.example.com
```

| TLS 场景 | 选项 |
|----------|------|
| 跳过校验（调试） | `--verify=no` |
| 自定义 CA | `--verify=/path/ca.pem` |
| 客户端证书 | `--cert` + `--cert-key` |
| 环境变量代理 | `HTTP_PROXY` / `HTTPS_PROXY` 自动读取 |

> ⚠️ 生产安全：`--verify=no` 仅限本地调试；生产脚本必须校验证书（默认行为）。

## 8. 完整请求构造示例

```bash
# 一个"完整"请求：认证 + 头 + 查询 + JSON Body
http -A bearer -a $TOKEN \
  POST https://api.example.com/orders \
  X-Trace-Id:20260808-001 \
  'X-Tag:order;urgent' \
  page==1 \
  orderId:='["SO-1001","SO-1002"]' \
  customerName=张三 \
  amount:=299.50 \
  items:='[{"sku":"A01","qty":2}]'
```

```text
生成的请求：
POST /orders?page=1 HTTP/1.1
Authorization: Bearer <token>
X-Trace-Id: 20260808-001
X-Tag: order;urgent
Content-Type: application/json

{"orderId":["SO-1001","SO-1002"],"customerName":"张三","amount":299.50,"items":[...]}
```

## 9. 核心要点

> 🎯 **核心要点**：
> - 运算符三族：`=`/`:=`/`@`（Body）、`:`/`:@`/`;`（头）、`==`/`==@`（URL）——一条命令覆盖请求全部；
> - `=` 字符串 vs `:=` 原始 JSON（数字/布尔/嵌套）——最易错的区分点；
> - 上传文件用 `-m`（multipart），登录表单用 `-f`；
> - 认证三件套：basic（默认）、digest（-A digest）、bearer（-A bearer，3.0 原生）；密码提示输入更安全；
> - 自定义认证走插件（`httpie plugins install`）；
> - TLS：调试 `--verify=no`，生产必须校验；
> - 3.2.3：可取消 User-Agent/Accept-Encoding。
