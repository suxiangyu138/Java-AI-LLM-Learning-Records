## 2. 测试金字塔模型

> 🎯 **测试金字塔**是测试策略的核心指导思想：越底层测试越多、越快、越稳定；越上层测试越少、越慢、越脆弱。

```
        ╱  End-to-End  ╲             手动测试/Selenium
       ╱   (极少)        ╲            数量: ~5%
      ╱──────────────────╲
     ╱    Integration      ╲          REST Assured / Testcontainers
    ╱    API测试 (少量)      ╲         WireMock
   ╱──────────────────────────╲       数量: ~15%
  ╱     Service/Integration    ╲      
 ╱     @SpringBootTest (适中)   ╲     数量: ~20%
╱────────────────────────────────╲
╲     Unit Tests / 单元测试       ╱    JUnit5 + Mockito
 ╲     (大量、快速、稳定)         ╱    数量: ~60%
  ╲────────────────────────────╱
```

| 层级 | 工具 | 特点 | 占比 | 执行速度 |
|------|------|------|------|----------|
| **单元测试** | JUnit5 + Mockito | 测试单个类/方法，Mock外部依赖 | ~60% | 毫秒级 |
| **Service集成测试** | @SpringBootTest + MockMvc | 测试Spring上下文，真实Bean交互 | ~20% | 秒级 |
| **API集成测试** | REST Assured + Testcontainers | 测试完整HTTP请求-响应链路 | ~15% | 秒-分钟级 |
| **E2E端到端测试** | Selenium/Playwright | 模拟真实用户操作 | ~5% | 分钟级 |

## 4. 分层学习路线

### 🟢 路线一：新手入门（2天）

```
Day 1上午: 05-测试金字塔（理论框架）
Day 1下午: JUnit5+Mockito + 01实战（动手写第一个单元测试）
Day 2上午: Postman（API调试）
Day 2下午: Testcontainers（集成测试环境）
```

**产出**：能独立编写SpringBoot项目的单元测试和基本集成测试

### 🔵 路线二：专业后端（5天）

```
在路线一基础上增加：
Day 3: REST Assured（API自动化测试）
Day 4: WireMock + JaCoCo（外部Mock + 覆盖率度量）
Day 5: JMeter（性能压测）+ 07-工具对比
```

**产出**：具备完整的Java后端测试体系能力，能搭建CI/CD质量门禁

### 🟣 路线三：测试架构师（持续）

```
在路线二基础上：
- 深入研究性能测试工具选型
- 搭建公司级测试基础设施
- 制定团队测试规范和质量标准
- 引入Mutation Testing（PIT）验证测试质量
- 推动TDD/BDD实践
```
