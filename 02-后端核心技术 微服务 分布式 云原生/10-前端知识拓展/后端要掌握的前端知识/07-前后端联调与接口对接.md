## 1. 前后端协作模式

### 1.1 两种主流模式

| 模式 | 架构 | 适用场景 |
|------|------|----------|
| **前后端分离 (SPA)** | 前端独立部署(nginx/CDN)，通过HTTP API通信 | ✅ 主流，大项目 |
| **服务端渲染 (SSR)** | 后端Thymeleaf/JSP渲染HTML | 传统、SEO强需求、小项目 |

```text
前后端分离架构：
┌──────────┐  HTTP/HTTPS  ┌──────────────┐
│  前端SPA  │────→JSON←────│  后端API      │
│ :3000    │              │  :8080       │
│ Vue/React│              │  Spring Boot │
└──────────┘              └──────────────┘
     ↑ 开发时跨域！需配置代理或CORS

生产部署架构：
┌──────────┐     ┌──────────┐     ┌──────────────┐
│  浏览器   │────→│  Nginx   │────→│  后端API      │
│          │     │  :80     │     │  :8080       │
│          │     │ (静态文件  │     │              │
│          │     │  + 反向代理)│     │              │
└──────────┘     └──────────┘     └──────────────┘
     同一域名，同源！ → 不跨域
```

## 2. 跨域问题全套解决方案

### 2.1 方案对比

| 方案 | 适用场景 | 配置位置 | 推荐度 |
|------|----------|----------|:---:|
| **后端CORS** | 开发+生产通用 | 后端@CrossOrigin | ⭐⭐⭐⭐⭐ |
| **前端代理** | 仅开发环境 | vite.config / vue.config | ⭐⭐⭐⭐ |
| **Nginx反向代理** | 生产环境 | nginx.conf | ⭐⭐⭐⭐⭐ |
| **JSONP** | 仅GET请求 | 前后端同时改 | ❌ 过时 |

### 2.2 后端CORS（一次配置永久生效）

```java
// Spring Boot 最简配置
@Configuration
public class CorsConfig implements WebMvcConfigurer {
    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/**")
            .allowedOriginPatterns("*")
            .allowedMethods("*")
            .allowedHeaders("*")
            .allowCredentials(true);
    }
}

// 仅开发环境开启（生产用Nginx代理）
@Profile("dev")
@Configuration
public class DevCorsConfig { ... }
```

### 2.3 前端Vite代理（开发环境推荐）

```javascript
// vite.config.js
export default {
  server: {
    port: 3000,
    proxy: {
      '/api': {
        target: 'http://localhost:8080', // 后端地址
        changeOrigin: true,
        // rewrite: (path) => path.replace(/^\/api/, '') // 可选：去掉/api前缀
      }
    }
  }
}
```

> 💡 前端请求`/api/users` → Vite自动转发到`http://localhost:8080/api/users` → 浏览器视角是同源（无跨域问题）

### 2.4 Nginx反向代理（生产环境）

```nginx
server {
    listen 80;
    server_name example.com;

    # 前端静态文件
    location / {
        root /var/www/dist;
        try_files $uri /index.html;
    }

    # 后端API代理
    location /api/ {
        proxy_pass http://backend:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

## 3. 前端代理配置

### 3.1 各框架代理配置

| 框架 | 配置文件 | 代理方式 |
|------|----------|----------|
| Vue (Vite) | `vite.config.js` | `server.proxy` |
| Vue (Webpack) | `vue.config.js` | `devServer.proxy` |
| React (CRA) | `package.json` | `"proxy": "http://localhost:8080"` |
| Next.js | `next.config.js` | `rewrites()` |

### 3.2 环境变量管理

```javascript
// .env.development
VITE_API_BASE_URL = '/api'          // 开发：走代理

// .env.production
VITE_API_BASE_URL = 'https://api.example.com'  // 生产：直接请求
```

```javascript
// 使用环境变量
const apiClient = axios.create({
    baseURL: import.meta.env.VITE_API_BASE_URL,
    timeout: 10000
});
```

## 4. 接口约定与Mock

### 4.1 接口文档先行

```text
推荐流程（避免联调阶段扯皮）：
1. 后端定义接口 → 写Swagger → 生成接口文档
2. 前端根据文档写Mock + 页面
3. 后端开发 + 自测
4. 前后端联调（只需对接口 + 处理边界case）
```

### 4.2 前端Mock方案

```javascript
// Mock.js 快速模拟数据
Mock.mock('/api/users', 'get', {
    'code': 200,
    'data|10': [{                    // 生成10条数据
        'id|+1': 1,                  // id从1递增
        'name': '@cname',            // 随机中文名
        'email': '@email',
        'createTime': '@datetime'
    }]
});
```

### 4.3 接口约定规范

```text
双方遵守的约定：
✅ URL: /api/版本/资源  →  /api/v1/users
✅ 请求体: Content-Type: application/json
✅ 响应体: { code, message, data }
✅ 分页: { page, size, total, list }
✅ 错误: 统一ErrorCode枚举，前后端共享
✅ 时间: ISO 8601格式 "2024-01-01T00:00:00Z"
```

## 5. 联调排错实战

### 5.1 万能排查流程

```
接口调不通时：
1. 前端F12 → Network → 确认请求是否发出？
   - 没发 → 前端代码问题（点击事件、请求拦截器）
   - 发了 → 看第2步

2. 看状态码：
   - 404 → URL路径不对（前端baseURL + 接口路径拼错了）
   - 400 → 参数问题（后端@RequestBody vs 前端发的JSON结构不一致）
   - 405 → HTTP方法不对（前端POST，接口是PUT）
   - 415 → Content-Type不对（前端发JSON但没设content-type头）
   - 500 → 后端报错，看后端日志

3. 看Response：
   - 空响应 → 检查后端是否有 @ResponseBody/@RestController
   - 数据格式不对 → 前端用的字段名和后端返回的不一致

4. 看Console：
   - CORS error → 跨域问题
   - Network Error → 后端没启动/端口/防火墙
```

### 5.2 后端快速自测

```bash
# 不用等前端，curl自己先测一遍
curl -X POST http://localhost:8080/api/users \
  -H "Content-Type: application/json" \
  -d '{"name":"test","email":"test@example.com"}'

# 如果curl返回正常 → 接口没问题 → 问题在前端
# 如果curl也报错 → 接口本身有问题 → 修后端
```

---

> 🎯 **联调第一定律**：后端提供接口后，自己先用curl测通了再给前端。减少80%的"接口调不通"返工时间。
