## 1. 实战：前后端登录体系

把全体系知识点压进一个项目：双 Token 登录 + 拦截器刷新 + 路由守卫 + 安全加固。交付「登录 → 受保护接口 → 过期静默恢复 → 登出」的完整闭环。

```javascript
// ─── tokenStore.js：存储与刷新（内存 + 单飞）───
let accessToken = null, refreshToken = null, refreshing = null;

export const getAccessToken = () => accessToken;
export function saveTokens(a, r) { accessToken = a; refreshToken = r; }
export function clearTokens() { accessToken = null; refreshToken = null; }

// ─── api.js：axios 实例 + 双拦截器 ───
import axios from 'axios';
import { getAccessToken, saveTokens, refreshToken, clearTokens } from './tokenStore';

const api = axios.create({ baseURL: '/api', timeout: 15000 });

api.interceptors.request.use((cfg) => {
  const t = getAccessToken();
  if (t) cfg.headers.Authorization = `Bearer ${t}`;
  return cfg;
});

api.interceptors.response.use(
  (resp) => resp,
  async (error) => {
    const { response, config } = error;
    if (response?.status === 401 && !config._retry && !config._isAuth) {
      if (!refreshing) {
        refreshing = api.post('/auth/refresh', { refreshToken }, { _isAuth: true })
          .then(({ data }) => saveTokens(data.accessToken, data.refreshToken))
          .catch(() => { clearTokens(); authEvents.emit('logout'); })
          .finally(() => { refreshing = null; });
      }
      try {
        await refreshing;
        config._retry = true;
        return api(config);
      } catch { return Promise.reject(error); }
    }
    return Promise.reject(error);
  });

// ─── auth.js：登录/登出 + 事件 ───
export const authEvents = { listeners: new Set(), emit(t) { this.listeners.forEach(f => f(t)); }, on(f) { this.listeners.add(f); } };

export async function login(username, password) {
  const { data } = await api.post('/auth/login', { username, password });
  saveTokens(data.accessToken, data.refreshToken);
  authEvents.emit('login');
}
export async function logout() {
  try { await api.post('/auth/logout'); } catch {}
  clearTokens(); authEvents.emit('logout');
}
```

**验收三问**：**闭环对吗**——登录后调受保护接口 200；手动把 access 改错 → 静默刷新成功 + 原请求重放 200（用户无感知）；刷新也失败 → 跳登录页。**并发对吗**——开两个 tab 同时发请求（access 已过期）→ 只发一次刷新，两请求都成功（无 401 连环）。**安全对吗**——devtools 里 `localStorage` 无 Token；`document.cookie` 读不到 HttpOnly；登出后旧 refresh 调刷新接口被拒。

## 2. 生产配置模板与纪律清单

**Token**：access 15 分钟（敏感 5）、refresh 7-14 天 + 轮换 + 重用检测 + 家族撤销。**存储**：内存 + 静默刷新（SPA）或 HttpOnly Cookie 全属性（Web）；不用 localStorage。**传输**：Bearer 头 + 拦截器 + 绝不放 URL + 日志脱敏。**安全**：算法白名单（RS256）、验证五要点、认证端点限流 + 恒定响应、审计全量。**密钥**：环境变量/密钥管理 + 定期轮换 + 多环境隔离（dev/prod 密钥不同）。**监控**：401 率、刷新成功率、重登频次、登录失败率四指标。**框架**：三层拦截 + 全局状态 + BroadcastChannel 多 tab。

**常见失败模式与排查顺序**：登录成功但后续 401——先查「存储」环节（tokenStore 是否真的存了、Cookie 方案查 Domain/Path 是否匹配），再查「携带」环节（拦截器是否注入、Bearer 格式是否 `Bearer ` + 空格）；刷新失败——先查 refresh 是否有效（是否被轮换/撤销/过期），再看是否并发重复刷新触发重用检测；**所有认证问题的第一排查工具是浏览器 devtools 的 Network 面板**——看请求头带没带 Authorization、Cookie 带没带、响应 401 是哪个端点——前端认证 80% 的 bug 一眼可见；后端侧配合看认证服务日志（限流命中、重用检测触发、验签失败原因）。**排查顺序铁律：先看请求长什么样，再怀疑代码逻辑**——请求头里没有凭证，代码写得再对也白搭。

## 3. 报错速查十条

| 现象 | 原因 | 处理 |
|------|------|------|
| 401 无限循环 | 拦截器无 `_retry`/`_isAuth` | 补标记，刷新失败跳登录 |
| 并发 401 连环失败 | 无单飞，重复刷新触发轮换 | refreshing 单例 |
| 登录成功但请求 401 | access 未正确存储/携带 | 查 tokenStore 与拦截器注入 |
| Cookie 带不上 | 跨域无 withCredentials | axios 配置 + CORS Allow-Credentials |
| CORS 报错 | 预检未放行 Authorization | 后端允许头与方法 |
| Token 能解码但请求失败 | 验签/iss/aud 不匹配 | 后端按五要点排查 |
| 刷新后仍是 401 | refresh 已轮换作废（多设备/重用） | 重登；查重用检测是否误报 |
| 登出后还能调接口 | 只清前端未撤 refresh | 后端撤销 + 前端双清 |
| `exp` 正常但被拒 | 时钟偏差 | 验证库时差窗口 + 服务器 NTP |
| 403 而非 401 | 认证过了授权不足 | 授权层排查（BOLA 方向） |

## 4. 面试三范式

**价值式**：「我实现的双 Token 登录体系——access 15 分钟 + refresh 轮换 + 重用检测，泄漏窗口从天级压到分钟级；401 拦截器静默刷新，刷新成功率 99.8%，用户零感知。」——先讲安全收益与体验数据，再讲手段。

**技术式**：「session 与 JWT 的本质是状态位置——会话状态在服务端（撤销快、需共享存储），JWT 状态在客户端（验签快、撤销难）；所以 Web 用会话、API 用 JWT；JWT 验证五要点——验签 + iss + aud + exp + jti，算法白名单防 alg:none 与算法混淆。」——原理讲到「为什么」，别停在「JWT 很流行」。

**生产式**：「安全是系统工程——localStorage 是反模式（XSS 一读即丢），HttpOnly + SameSite 是 Web 标准；refresh 必须轮换 + 有状态（存哈希）；认证端点限流 + 恒定响应防枚举；越权（BOLA）是 API 头号漏洞，授权独立设计。」——存储、轮换、运维、授权四点是区分度。

**追问四连**：为什么 Web 不用 JWT？（撤销难 + 无状态优势用不上）｜刷新并发怎么防？（单飞 + 服务端宽容窗口）｜token 被偷怎么办？（短 TTL 限损 + 重用检测发现 + DPoP 绑定）｜会话与 JWT 能混用吗？（按安全域分层，同一接口不双凭证）。

## 5. 简历呈现

项目经历写法：「基于双 Token 机制的前后端登录体系——JWT access（15 分钟）+ refresh 轮换与重用检测，拦截器 401 静默刷新重试，路由守卫 + 多 tab 同步；安全加固：算法白名单、Cookie 全属性、认证限流、审计日志；支持 OAuth 2.1 授权码 + PKCE 微信/Google 登录。」技能栏：「前端鉴权体系（JWT/双 Token/OAuth2/OIDC），前端安全（XSS/CSRF 防护）」。——机制 + 安全 + 协议三要素。
