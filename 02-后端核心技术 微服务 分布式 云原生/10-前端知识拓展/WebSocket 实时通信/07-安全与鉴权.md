## 1. WebSocket 安全的不同之处

**WebSocket 的安全面与 HTTP 有三处本质差异**：其一，**握手只有一次鉴权机会**——HTTP 每个请求都能带 token，WebSocket **连上之后请求头就没了**（帧格式里没有头字段，01 篇）——"**鉴权必须在握手时做完，事后无法补票**"；其二，**跨域检查发生在握手**——浏览器对 `new WebSocket('wss://evil.com')` 的跨域请求带 Origin 头，**服务端不校验 = 任何网页都能连你的服务**；其三，**连接是常驻的**——攻击者拿到一条连接 = 长期通道（HTTP 是一次性的）——**连接数限制与踢人下线是安全手段**。**"HTTP 的安全是'每个请求都验'，WebSocket 的安全是'入场验一次 + 场内常驻防护'"**。

## 2. 传输层：wss:// 是生产标配

**wss://（TLS 加密的 WebSocket）是生产唯一选择**，三个理由：**加密**（消息明文走公网 = 聊天内容/业务数据裸奔）、**浏览器强制**（**混合内容限制：https 页面里 ws:// 会被浏览器直接拦截**）、**代理兼容**（443 端口过防火墙，80 端口常被限）。**实现**：**与 HTTPS 同一套证书**（Nginx 终结 TLS 再反代 ws:// 后端，06 篇三要素 + ssl 配置）——"**HTTP 用 https，WS 就用 wss——证书复用，配置一行**"。**本地开发例外**：localhost 允许 ws://（浏览器豁免本地）。

## 3. Origin 校验：防 CSWSH

**CSWSH（Cross-Site WebSocket Hijacking，跨站点 WebSocket 劫持）**：**攻击者网页里偷偷 `new WebSocket('wss://victim.com/ws')`**——**如果服务端不校验 Origin，这个请求会带着用户的 Cookie/本地 token 建立连接**——攻击者拿到"你的身份"的实时通道（读你的消息、发消息冒充你）——"**CSRF 的 WebSocket 版，危害比 CSRF 更直接（长连接）**"。

**防护**：**服务端校验握手请求的 Origin 头**——只允许白名单域名：

```java
// Spring 原生
registry.addHandler(handler, "/ws")
        .setAllowedOrigins("https://app.example.com");   // 白名单，不是 "*"

// Spring Security 风格（Boot 4 的 @EnableWebSocketSecurity 时代）
// 校验 Origin + CSRF token 才放行握手（第 5 节）
```

**配套防线**：**鉴权别依赖 Cookie**（cookie 会被跨站请求自动携带，token 放自定义位置，第 4 节）——"**Origin 白名单 + 非 Cookie 鉴权**"双保险：**Origin 挡"别人家的网页"、token 挡"伪造的身份"**。

## 4. 握手鉴权：token 的三个位置

**WebSocket 没有请求头 API，token 的三个可放位置**：

| 位置 | 写法 | 优劣 |
|------|------|------|
| query 参数 | `wss://host/ws?token=xxx` | ⭐ 最常用；**但会进访问日志/代理日志，别放长期密钥** |
| 子协议 | `Sec-WebSocket-Protocol: bearer, token` | 可自定义；**浏览器子协议要服务端回显才放行** |
| STOMP CONNECT 头 | connectHeaders: Authorization | 03/02 篇姿势；**在 STOMP 层验，代理层看不到** |

**选型主线**：**简单场景 token 放 query**（接入方便、Spring 拦截器好取）；**网关/代理层鉴权场景用子协议或 STOMP 头**（不进访问日志）——**JWT 的短时效（15 分钟-2 小时）缓解了"token 进日志"的泄露风险**（Token 体系交叉：`../Token/00-Token总览.md` 双 Token 模式）；**token 刷新与重连联动**：长连接超过 token 时效时前端先刷新再重连——"**连接寿命与 token 寿命对齐**"（04 篇第 5 节）。**服务端三个校验点**：**握手拦截器**（HTTP 头/query 里验——验不过直接拒绝 101）、**STOMP CONNECT 帧**（ChannelInterceptor 验 STOMP 层 token）、**业务消息**（敏感操作再验权限）——"**入场验身份，场内验权限，两层都别省**"。

## 5. Spring Security 集成

**Boot 4 时代（2026）的 WebSocket 安全**：**@EnableWebSocketSecurity 取代旧的组件绑定模式**（00 篇基线）——**STOMP 消息的安全规则独立配置**：

```java
@Configuration
@EnableWebSocketSecurity      // Boot 4 新姿势（取代旧 WebSocketSecurity 绑定）
public class WsSecurityConfig {

    @Bean
    public AuthorizationManager<Message<?>> messageAuthorizationManager() {
        return MessageMatcherDelegatingAuthorizationManager.builder()
            .simpDestMatchers("/topic/admin/**").hasRole("ADMIN")   // 目标地址权限
            .simpTypeMatchers(SimpMessageType.CONNECT).authenticated()  // 连接必须登录
            .anyMessage().denyAll()
            .build();
    }
}
```

**三个要点**：其一，**CONNECT 必须先鉴权**（authenticated）——"**没登录连都别连**"；其二，**按目标地址授权**——`/topic/admin/**` 只有管理员能订阅（**订阅鉴权**——"能连上 ≠ 能订阅所有主题"）；其三，**迁移注意**：Boot 4 升级后**旧的 WebSocket 安全配置写法失效**，**迁移时先测安全规则**（03 篇 Boot 4 变化）。**用户身份注入**：握手鉴权通过后把用户放进 `SimpUserRegistry`——`convertAndSendToUser` 靠它解析目标（03 篇点对点原理）——"**鉴权成功的那一刻，用户身份进入连接上下文**"。

## 6. 消息层防护

**连接建立后的消息层防护**：**消息大小限制**（服务端设 maxMessageSize——默认 64KB，超限拒收——防"一条消息打爆内存"）；**频率限制**（每连接每秒 N 条——防刷屏/滥用，与 REST 限流同思路，可复用令牌桶）；**内容校验**（消息正文反序列化 + 字段校验——**别把 JSON 直接透传**，09 篇类型化）；**敏感操作二次鉴权**（删除/转账类消息再验权限——**"连接身份 ≠ 操作权限"**）；**踢人下线**（管理端/检测到异常 → 定位连接 → 关闭——连接注册表用途三，06 篇）。**一条总纲**：**"入场验一次只是入场券，场内每条消息按敏感度分级防护"**。

## 7. 生产安全清单

- [ ] 传输层 wss://（TLS），证书与 HTTPS 同源
- [ ] Origin 白名单（setAllowedOrigins 具体域名，非 "*"）
- [ ] 握手鉴权（query/子协议/STOMP 头三选一），**不依赖 Cookie**
- [ ] CONNECT 必须 authenticated，订阅按目标地址授权
- [ ] token 短时效（JWT 15min-2h），刷新与重连联动（04 篇）
- [ ] 消息大小限制 + 每连接频率限制
- [ ] 敏感操作消息级二次鉴权
- [ ] 连接数上限（单用户多连接/全局上限，08 篇）
- [ ] 访问日志脱敏（query 里的 token 不落日志）
- [ ] 异常检测（异地登录踢人/频率异常封禁）

## 8. 五个常见坑

- **坑一**：setAllowedOrigins("*") 上生产——**任何网页可连；白名单域名**（第 3 节）；
- **坑二**：token 放 query 且长时效——**访问日志泄露长期凭证；短时效 JWT**（第 4 节）；
- **坑三**：鉴权依赖 Cookie——**CSWSH 的帮凶；token 放自定义位置**（第 3 节）；
- **坑四**：只验连接不验订阅——**用户能订阅所有 /topic；按目标地址授权**（第 5 节）；
- **坑五**：Boot 3 的安全配置原样升 Boot 4——**@EnableWebSocketSecurity 取代旧模式；迁移先测安全规则**（第 5 节）。
