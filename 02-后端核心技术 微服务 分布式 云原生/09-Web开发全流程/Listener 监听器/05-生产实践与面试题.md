## 1. 应用场景总表

| 场景 | 监听器 | 说明 |
|------|--------|------|
| 启动初始化 | ServletContextListener | 缓存预热/配置加载 |
| 关闭清理 | ServletContextListener | 优雅停机 |
| 在线人数统计 | HttpSessionListener | 创建/销毁计数 |
| 在线用户管理 | HttpSessionListener + 属性监听 | 用户维度在线列表 |
| 登录/登出感知 | HttpSessionAttributeListener | 监听 user 属性 |
| 访问日志 | ServletRequestListener | 请求级记录 |
| 全局属性管理 | ServletContextAttributeListener | context 数据变化 |
| 会话迁移 | HttpSessionActivationListener | 分布式 Session |

> 🎯 **场景记忆**：**初始化/清理用 Context、在线统计用 Session、访问记录用 Request、登录感知用属性**——每个监听器服务一个场景。

## 2. 现代替代方案

| 传统 Listener 场景 | 现代替代 |
|-------------------|---------|
| 启动初始化 | **ApplicationRunner / ApplicationReadyEvent** |
| 优雅停机 | Spring 优雅停机（server.shutdown=graceful） |
| 登录/登出感知 | **Spring Security 事件/过滤器** |
| 会话管理 | Spring Session（见会话体系） |
| 访问日志 | Filter + 日志体系（见 Filter 体系） |
| 请求级处理 | Interceptor（可拿 HandlerMethod） |

```text
替代主线：
  能注入 Spring 的 → Spring 机制（Runner/事件/Bean）
  必须容器事件级 → Listener（注册为 Bean）
  传统 JavaWeb 项目 → 保留 Listener 用法
```

> 🎯 **认知总结**：**Listener 是"容器事件时代的产物"**——Boot 时代大部分场景被 Spring 机制替代，但"会话级监听"（在线统计）仍是 Listener 的主场。

## 3. 高频避坑清单

| # | 坑 | 规避 |
|---|----|------|
| 1 | @WebListener 无法注入 Bean | 注册为 Spring Bean（@Component） |
| 2 | 在线统计用 int 变量 | 多实例/并发问题——context 或 Redis |
| 3 | 全局数据非线程安全 | ConcurrentHashMap |
| 4 | 初始化任务太重 | 启动慢——异步/按需加载 |
| 5 | 初始化失败不处理 | 快速失败（启动即报错） |
| 6 | 忘记关闭资源 | contextDestroyed 释放 |
| 7 | 浏览器关闭以为会触发销毁 | 等超时——统计滞后是正常 |
| 8 | 混用两种注册方式 | 统一一种（@Component 或 @WebListener） |
| 9 | 监听器里做重业务 | 监听器保持轻量（回调是高频的） |
| 10 | Boot 项目还手动写初始化 Listener | 用 ApplicationRunner（可注入） |

## 4. 面试题

| 题目 | 答题要点 |
|------|---------|
| Listener 是什么？ | 监听容器事件（应用/会话/请求）的观察者；事件发生时自动回调 |
| 八大监听器分类？ | 3 对象 × 2 事件 = 6 + 2 会话绑定（生命周期/属性/绑定） |
| 最常用的是哪个？ | ServletContextListener（启动初始化） |
| 在线人数统计怎么做？ | HttpSessionListener：创建 +1、销毁 -1；存 context（多实例用 Redis） |
| 会话销毁什么时候触发？ | 超时/invalidate/服务器关闭；浏览器关闭不立即触发 |
| Listener 和 Filter 区别？ | Listener 监听事件（观察者）；Filter 拦截请求（责任链）——时机与职责不同 |
| Listener 和 Spring 事件区别？ | Servlet 容器事件 vs Spring 容器事件；Listener 传统、Spring 事件可注入 |
| Boot 中怎么注册？ | @Component（可注入）或 ServletListenerRegistrationBean |
| 启动初始化怎么做（Boot）？ | ApplicationRunner/ApplicationReadyEvent（替代 Listener） |
| 登录事件怎么实现（传统）？ | 监听 Session 属性 user 的增删 |
| 全局数据注意什么？ | 线程安全（ConcurrentHashMap）+ 全局共享只读数据 |
| 在线统计的误差？ | 浏览器关闭不触发销毁——统计滞后于实际 |

## 5. 核心要点

> 🎯 **核心要点**：
> - 八大分类框架：3 对象 × 2 事件 + 2 绑定——**最常用 ServletContextListener**；
> - 场景映射：Context=初始化/清理、Session=在线统计、Request=访问记录、属性=登录感知；
> - Boot 姿势：Listener 注册为 Bean（可注入）；启动初始化用 ApplicationRunner；
> - 避坑 Top3：@WebListener 不可注入、在线统计内存变量、浏览器关闭不触发销毁；
> - 面试主线：是什么 → 八大分类 → 在线统计实现 → Listener vs Filter → Boot 注册 → 现代替代；
> - 定位：**容器事件观察者**——传统项目主力、Boot 项目"会话级场景"补充。
