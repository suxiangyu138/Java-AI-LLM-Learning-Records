## 1. 十二名词一张地图

这些名词不是孤立的，它们围绕三件大事：**别让流量打死系统、别让故障拖垮系统、别让重复搞乱数据**。

```text
                   后端/分布式系统的三大战场
┌─────────────────────────────────────────────────────────────┐
│ ① 流量治理：来的人太多，怎么办？                              │
│    限流（拦一部分） → 削峰（排个队慢慢来） → 背压（让上游慢点发） │
├─────────────────────────────────────────────────────────────┤
│ ② 容错保护：下游/自己出故障，怎么办？                          │
│    超时 → 熔断（断开故障依赖） → 降级（保核心舍次要）            │
│    → 隔离（把故障关在笼子里） → 最终目标：不雪崩                 │
├─────────────────────────────────────────────────────────────┤
│ ③ 数据一致与扩展：请求重复/数据太多，怎么办？                    │
│    幂等（重复请求结果一样） → 防抖（重复触发只干一次）            │
│    → 缓存（热数据放快处） → 分片（数据拆开存）                   │
├─────────────────────────────────────────────────────────────┤
│ ④ 架构风格：让 ①②③ 更容易实现                                │
│    解耦（拆分强依赖） → 异步（不等慢任务） → MQ（三者工具箱）      │
└─────────────────────────────────────────────────────────────┘
```

> 💡 记忆抓手：**限流、熔断、降级、幂等是面试四大金刚**；**解耦、异步、削峰是 MQ 三大作用**；**缓存、分片是性能双引擎**——本系列 01-05 篇逐组拆解，06 篇一个电商案例全部串起来。

## 2. 一句话速查表

| 名词 | 一句话解释 | 类比 | 出处 |
|------|-----------|------|------|
| **解耦** | 把强绑定的两件事拆开，A 出事不影响 B | 插件式家电，坏一个换一个 | [01 篇](01-解耦与异步.md) |
| **异步** | 不用等这件事做完，先返回，后台慢慢做 | 点菜拿号走人，做好通知你 | [01 篇](01-解耦与异步.md) |
| **削峰** | 瞬时洪峰请求排队缓冲，摊平到一段时间处理 | 水坝蓄洪，错峰放水 | [02 篇](02-流量治理：限流、削峰与背压.md) |
| **限流** | 超过阈值的请求直接拒绝，保护系统 | 商场限流放号，人满就不进 | [02 篇](02-流量治理：限流、削峰与背压.md) |
| **背压** | 下游处理不过来，反推上游降速 | 传送带前堆满了，按暂停键 | [02 篇](02-流量治理：限流、削峰与背压.md) |
| **熔断** | 下游故障时主动断开调用，快速失败不傻等 | 保险丝，短路就断 | [03 篇](03-容错保护：熔断、降级与雪崩.md) |
| **降级** | 压力大时主动关掉非核心功能，保核心业务 | 大促只保下单支付，砍掉推荐 | [03 篇](03-容错保护：熔断、降级与雪崩.md) |
| **雪崩** | 一个服务挂了，连锁拖垮整条链路 | 多米诺骨牌 | [03 篇](03-容错保护：熔断、降级与雪崩.md) |
| **幂等** | 同一个请求执行多次，结果和执行一次完全一样 | 同一张票验多次，只算一次入场 | [04 篇](04-重复请求治理：幂等与防抖.md) |
| **防抖** | 短时间连续触发，只执行最后一次 | 打字停顿一下才搜索 | [04 篇](04-重复请求治理：幂等与防抖.md) |
| **分片** | 数据太多拆成多份存储，每份只扛一部分 | 一本厚书拆成多册 | [05 篇](05-数据扩展：缓存与分片.md) |
| **缓存** | 热数据放到更快的存储，少查慢库 | 常用工具放桌面，不每次去仓库翻 | [05 篇](05-数据扩展：缓存与分片.md) |
| **MQ 三作用** | 解耦 + 异步 + 削峰 | 中间快递站 | [01 篇](01-解耦与异步.md) |

## 3. 三大组团的底层逻辑

### 3.1 流量治理组（限流/削峰/背压）——"进来的流量"怎么管

```text
上游请求 ──► 限流：超阈值直接拒绝（丢）           ──► 削峰：超阈值排队等待（缓）
                                              ──► 背压：通知上游降速（反推）
```

| 手段 | 对请求的态度 | 用户感知 | 典型实现 |
|------|-------------|---------|---------|
| 限流 | 超阈值**拒绝**（丢弃/返回错误） | 被拒：稍后重试 | 令牌桶/滑动窗口，Sentinel |
| 削峰 | 超阈值**缓冲**（排队/暂存） | 有延迟：排队中 | MQ 积压 + 慢速消费 |
| 背压 | **告诉上游**降速 | 上游减速：自然平滑 | 反应式流、Kafka 消费慢反馈 |

> 🎯 三者关系一句话：**限流是"挡"，削峰是"存"，背压是"喊停"**——线上通常限流打头、削峰保底、背压兜底（生产者是自研系统时）。

### 3.2 容错保护组（超时/熔断/降级/隔离/雪崩）——"故障的传播"怎么断

```text
故障发生 ──► 超时兜底（不等死） ──► 熔断（断开故障源）
        ──► 降级（保核心）    ──► 隔离（关进笼子） ──► 不雪崩
```

| 手段 | 主动性 | 保护对象 | 一句话 |
|------|:---:|---------|--------|
| 超时 | 被动兜底 | 自己的线程/连接 | 不等一个注定失败的调用 |
| 熔断 | 被动（检测到故障后） | 自己的资源 | 下游坏了，我不再调它 |
| 降级 | **主动**（压力大时） | 核心业务 | 次要功能先让路 |
| 隔离 | 主动（设计期） | 故障范围 | 把故障关在独立的笼子里 |
| 雪崩 | — | — | 以上全部没做好的结果 |

### 3.3 一致性组（幂等/防抖）与性能组（缓存/分片）

| 名词 | 解决什么 | 谁负责 |
|------|---------|--------|
| 幂等 | 重复请求造成**重复扣款/重复下单** | **后端必须做**（支付、下单核心） |
| 防抖 | 前端疯狂触发造成**无效请求** | 前端为主，后端可兜底 |
| 缓存 | 读多写少的**慢查询** | 后端 |
| 分片 | 单表数据量超限的**容量瓶颈** | 后端/架构 |

> ⚠️ 常见误区：防抖能代替幂等吗？**不能**——防抖防的是"同一用户在短时间内多次触发"，防不住"网络重试、消息重投、恶意刷单"；支付扣款这种资金操作，后端幂等是底线（[04 篇](04-重复请求治理：幂等与防抖.md) 有对比表）。

## 4. 面试对比总表

| 对比组 | 核心区别 | 一句话记忆 |
|--------|---------|-----------|
| **熔断 vs 降级** | 熔断=下游故障**被动**断开；降级=自身压力大**主动**舍弃 | 熔断是"它坏了我不调了"，降级是"我撑不住我先砍" |
| **限流 vs 削峰** | 限流=超阈值**拒绝**；削峰=超阈值**排队延后** | 限流丢请求，削峰存请求 |
| **限流 vs 背压** | 限流=服务侧**挡**；背压=生产者侧**降速** | 一个管入口，一个管源头 |
| **幂等 vs 防抖** | 幂等=重复执行**结果一致**（后端兜底）；防抖=重复触发**只执行一次**（前端拦截） | 防抖防触发，幂等防结果 |
| **同步 vs 异步** | 同步=等结果再走（简单可靠）；异步=先返回后处理（快、解耦、难排查） | 异步省时间，难的是兜底与一致性 |
| **缓存 vs 分片** | 缓存=读快（解决慢查询）；分片=容量大（解决装不下） | 缓存治"慢"，分片治"大" |
| **水平扩展 vs 垂直扩展** | 加机器 vs 加配置 | 分片是水平扩展的地基 |
| **缓存穿透 vs 击穿 vs 雪崩** | 查不存在的 key / 一个热点 key 过期 / 大量 key 同时过期 | 不存在/单个/成片（[05 篇](05-数据扩展：缓存与分片.md) 专节） |
