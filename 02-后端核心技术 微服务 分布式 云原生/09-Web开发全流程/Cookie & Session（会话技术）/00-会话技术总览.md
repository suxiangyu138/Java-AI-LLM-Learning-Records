## 4. 会话技术演进主线

```text
单体时代：Session（内存）——简单，但无法水平扩展
   ↓
集群时代：分布式 Session（Redis 集中）——可扩展，有存储成本
   ↓
无状态时代：Token/JWT——无服务器状态，跨域友好，有安全成本
   ↓
2026：混合方案——敏感业务 Session+Redis，通用认证 JWT 双 Token
```

| 时代 | 方案 | 特点 |
|------|------|------|
| 单体 | Servlet Session（内存） | 简单，无法扩展 |
| 集群 | Session 复制/粘滞/Redis | 复制有风暴、粘滞有单点、Redis 最优 |
| 无状态 | JWT | 无状态、跨域，令牌泄露风险 |
| 现代 | 混合（Session+Redis 与 JWT 双 Token） | 按业务场景选择 |

> 🎯 **2026 主流判断**：**服务端会话（Session+Redis）仍是"登录态"的稳妥选择**（可控、可撤销）；JWT 用于"无状态接口认证/微服务间信任"；**"JWT 全面替代 Session"已不是共识**——混合是常态。

## 5. 核心概念速查

| 概念 | 一句话 |
|------|--------|
| HTTP 无状态 | 每次请求独立，服务器不记得上次 |
| Cookie | 浏览器存储的小数据（随请求自动携带） |
| HttpOnly | Cookie 禁止 JS 读取（防 XSS 窃取） |
| SameSite | Cookie 跨站发送策略（Lax 现代默认） |
| Session | 服务器端保存的会话数据 |
| SessionID | 会话标识（通常存 Cookie） |
| HttpSession | Java 的 Session 对象（Servlet API） |
| 会话固定攻击 | 攻击者预置 SessionID 诱导受害者使用 |
| 会话劫持 | 窃取 SessionID 冒充用户 |
| CSRF | 跨站请求伪造（借用户 Cookie 发请求） |
| Spring Session | 会话存储抽象（Redis 实现） |
| JWT | 无状态令牌（Header.Payload.Signature） |
| 双 Token | Access Token（短效）+ Refresh Token（长效） |
