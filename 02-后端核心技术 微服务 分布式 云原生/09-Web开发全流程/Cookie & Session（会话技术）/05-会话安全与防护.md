## 1. 会话四大威胁总览

| 威胁 | 原理 | 关键防护 |
|------|------|---------|
| **会话劫持** | 窃取 SessionID 冒充用户 | HTTPS + HttpOnly + 轮换 ID + 异常检测 |
| **会话固定** | 预置 SessionID 诱导受害者使用 | 登录成功轮换 ID |
| **XSS 窃取** | JS 读取 Cookie（无 HttpOnly） | HttpOnly + 输入输出过滤 |
| **CSRF** | 借用户 Cookie 发恶意请求 | SameSite + Token 校验 |

> 🎯 **一句话总览**：**劫持是"偷 ID"、固定是"送 ID"、XSS 是"读 Cookie"、CSRF 是"借 Cookie"**——四种攻击四种防护。

## 2. 威胁一：会话劫持

### 2.1 原理

```text
攻击者获取合法用户的 SessionID → 冒充用户访问

SessionID 泄露途径：
  ① 明文传输（HTTP）——网络窃听
  ② URL 中携带（jsessionid）——日志/分享泄露
  ③ XSS 窃取（无 HttpOnly）
  ④ 第三方脚本/日志
```

### 2.2 防护

| 防护 | 说明 |
|------|------|
| **HTTPS 全站** | 防明文窃听（第一防护） |
| **HttpOnly** | 防 JS 读取 |
| 不用 URL 重写 | 避免 ID 进 URL |
| 登录后轮换 ID | 防固定（见威胁二） |
| 异常检测 | 异地登录/IP 变化提示 |
| 双因素 | 高敏感操作 |

> ⚠️ **劫持防护的核心**：**让攻击者"拿不到"（HTTPS/HttpOnly）比"拿到用不了"（轮换/检测）更根本**——HTTPS + HttpOnly 是底线。

## 3. 威胁二：会话固定攻击

### 2.1 原理

```text
攻击流程：
① 攻击者先获取一个 SessionID（访问网站生成）
② 把这个 ID 发给受害者（诱导点击含 ID 的链接）
③ 受害者用该 ID 登录
④ 攻击者用同一 ID → 直接以受害者身份登录！

关键：登录前后 SessionID 不变 → 攻击成立
```

### 3.2 防护：登录成功后轮换 SessionID

```java
// 登录成功后轮换 SessionID（标准防护）
@PostMapping("/login")
public String login(@RequestParam String username, HttpServletRequest request) {
    // ① 校验密码
    // ② 轮换 SessionID（防固定攻击）
    request.changeSessionId();          // Servlet 3.1+
    // ③ 存入用户
    request.getSession().setAttribute("user", username);
    return "ok";
}
```

| 防护 | 说明 |
|------|------|
| **登录后轮换 ID** | `request.changeSessionId()`（核心） |
| 登出后失效 | `invalidate()` + 清 Cookie |
| 固定 ID 拒绝 | 不接受客户端指定的 ID（现代容器默认） |

> 🎯 **会话固定攻击的唯一核心防护**：**登录成功必须轮换 SessionID**——前后 ID 不同，攻击者手里的旧 ID 立即失效。

## 4. 威胁三：XSS 窃取 Cookie

### 4.1 原理

```text
XSS（跨站脚本）：攻击者在页面注入恶意 JS
  → document.cookie 读取 Cookie（无 HttpOnly 时）
  → 窃取 SessionID → 劫持会话
```

### 4.2 防护

| 防护 | 说明 |
|------|------|
| **HttpOnly（核心）** | JS 无法读取认证 Cookie |
| 输入过滤 | 防注入（框架默认转义） |
| 输出编码 | 防存储型 XSS |
| CSP | 内容安全策略兜底 |

```text
HttpOnly 的意义：
  document.cookie 读不到 HttpOnly Cookie → XSS 也偷不到 SessionID
  （XSS 仍可执行其他恶意操作，但会话安全保住了）
```

> 💡 **HttpOnly 是"防 XSS 窃取会话"的关键**：即使 XSS 存在，SessionID 也拿不到——**认证 Cookie 不设 HttpOnly = 裸奔**。

## 5. 威胁四：CSRF

### 5.1 原理

```text
CSRF（跨站请求伪造）：
  受害者已登录（Cookie 有效）
  访问恶意网站 → 恶意页面发起请求（带 Cookie 自动携带）
  服务器认为是"用户操作" → 执行转账/改密等

经典：<img src="https://bank.com/transfer?to=attacker&amount=1000">
```

### 5.2 防护（双层）

```text
第一层：SameSite=Lax（现代浏览器默认）
  跨站 POST 不携带 Cookie → 大部分 CSRF 自动失效

第二层：CSRF Token 校验
  服务器下发 Token（不在 Cookie）→ 请求必须带 → 攻击者拿不到
  Spring Security 默认开启 CSRF 防护
```

| 防护 | 说明 |
|------|------|
| **SameSite=Lax** | 浏览器层（跨站不携带） |
| **CSRF Token** | 应用层（请求必须带 Token） |
| 自定义头 | API 场景要求 X-Requested-With |
| 双重提交 | Cookie + 参数 Token 比对 |

> ⚠️ **现代 CSRF 防护的认知**：**SameSite=Lax 已挡住大部分 CSRF**（浏览器默认）；前后端分离（SameSite=None）时 **CSRF Token 是必须的应用层防护**——Spring Security 默认开启。

## 6. 会话安全防护清单

| # | 防护 | 威胁 | 实施 |
|---|------|------|------|
| 1 | HTTPS 全站 | 劫持（窃听） | 证书 + 跳转 |
| 2 | HttpOnly | XSS 窃取 | Cookie 属性 |
| 3 | Secure | 劫持 | Cookie 属性 |
| 4 | SameSite=Lax | CSRF | Cookie 属性（现代默认） |
| 5 | 登录轮换 ID | 固定攻击 | `request.changeSessionId()` |
| 6 | 登出失效+清 Cookie | 残留会话 | `invalidate()` + Max-Age=0 |
| 7 | CSRF Token | CSRF | Spring Security 默认 |
| 8 | 超时策略 | 长会话风险 | 30 分钟无活动 |
| 9 | 异常检测 | 劫持 | 异地/设备变化提示 |
| 10 | 输入输出过滤 | XSS | 框架默认 + 自查 |

## 7. 核心要点

> 🎯 **核心要点**：
> - 四威胁一句话：偷 ID（劫持）/送 ID（固定）/读 Cookie（XSS）/借 Cookie（CSRF）；
> - Cookie 三件套：**HttpOnly + Secure + SameSite=Lax**——三防各挡一类；
> - 固定攻击唯一核心防护：**登录轮换 SessionID**（changeSessionId）；
> - CSRF 双层：SameSite（浏览器）+ Token（应用，Spring Security 默认）；
> - 登出纪律：invalidate + 清 Cookie；
> - 安全不是单点：**清单 10 项层层设防**（纵深防御）。
