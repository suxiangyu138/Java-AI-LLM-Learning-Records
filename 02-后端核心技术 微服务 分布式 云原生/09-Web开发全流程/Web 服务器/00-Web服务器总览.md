## 4. Web 服务器定位

```text
一次请求的完整链路：
客户端 → CDN/边缘（Cloudflare 等）
       → Web 服务器（Nginx/Apache/Caddy：静态资源 + 反代）
       → 应用服务器（Tomcat/Jetty + 业务代码：动态内容）
                          ↑
        Web 服务器管"流量入口"，应用服务器管"业务计算"
```

| 服务器类别 | 代表 | 核心职责 |
|-----------|------|---------|
| Web 服务器 | Nginx / Apache / Caddy / IIS | 静态资源、反向代理、缓存、TLS 终止 |
| 应用服务器 | Tomcat / Jetty / Undertow / ASP.NET Core | 执行业务代码、生成动态内容 |
| 边缘/CDN | Cloudflare / 云 CDN | 全球分发、WAF、缓存 |
| 硬件负载均衡 | F5 / LVS | 四层流量分发（可被 Nginx/网关替代） |

> 🎯 **时代结论（2026）**：单体 Web 服务器时代结束——现代架构是"CDN + Web 服务器（反代）+ 应用服务器"三层分工；Web 服务器层正在被云原生网关（Ingress/API 网关）部分吸收，但"第一跳"仍是 Web 服务器。

## 6. 核心概念速查

| 概念 | 一句话 |
|------|--------|
| Web 服务器 | 处理 HTTP 请求的软件：静态资源 + 反代 + TLS |
| 应用服务器 | 执行业务逻辑的容器（Tomcat/ASP.NET Core） |
| 动静分离 | 静态资源由 Web 服务器直出，动态请求反代到应用 |
| 反向代理 | 隐藏后端、统一入口、负载分发 |
| MPM | Apache 进程模型：prefork / worker / event |
| 事件驱动 | Nginx/Caddy 的高并发模型（单线程 + 事件循环） |
| 虚拟主机 | 一台服务器托管多个域名/站点 |
| TLS 终止 | 证书解密放在入口层（Web 服务器/CDN） |
| 自动 HTTPS | Caddy 的 ACME 自动申请/续期证书 |
| ACME | Let's Encrypt 证书自动化协议 |
| HTTP/3 | QUIC 协议上的 HTTP（Caddy/Nginx 已支持） |
| CDN 边缘 | Cloudflare 等全球节点：缓存 + WAF + 加速 |
| ARR | IIS 的应用程序请求路由（反代扩展） |
