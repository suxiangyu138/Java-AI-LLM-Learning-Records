## 1. 选型决策树

```text
新项目选 Web 服务器，按优先级问自己：

① 运行平台？
   ├─ Windows + AD 域环境 → IIS（集成认证无可替代）
   └─ Linux / 跨平台 → 继续

② 站点规模与团队？
   ├─ 个人/中小站/内网 → Caddy（自动 HTTPS，零运维）
   └─ 企业/生产/大流量 → 继续

③ 架构复杂度？
   ├─ 简单反代 + 静态 → Nginx（标准答案，生态最全）
   ├─ 微服务网关场景 → 网关（Spring Cloud Gateway/Ingress）
   └─ 存量 Apache 生态（.htaccess/共享主机）→ 保留 Apache

④ 有无 CDN/边缘？
   ├─ 有 → Web 服务器只管反代（Nginx），静态上 CDN
   └─ 无 → Nginx 兼静态 + 反代（动静分离）
```

> 🎯 2026 年一句话结论：**默认 Nginx；个人/内网用 Caddy；Windows 域环境用 IIS；老生态不折腾 Apache**。选型依据的是"团队熟悉度 + 生态 + 运维成本"，纯性能差距已不是主因。

## 3. 性能对比

### 3.1 模型差异（理论）

| 服务器 | 模型 | 静态并发极限 | 动态能力 |
|--------|------|:---:|------|
| Apache prefork | 进程 | ~1k 连接 | 差 |
| Apache event | 事件+线程 | 数万连接 | 中 |
| Nginx | 事件驱动 | **十万级连接** | 反代为主 |
| Caddy | 事件驱动（Go） | 数万连接 | 反代为主 |
| IIS | 内核 http.sys | 高 | 与 .NET 集成强 |

### 3.2 现实结论

```text
2026 年的性能现实：
  · 静态资源：Nginx ≈ Caddy > Apache(event) > IIS（同量级差距，非数量级）
  · 瓶颈早已不在 Web 服务器，而在：网络/DB/业务代码/慢客户端
  · 静态资源最优解是 CDN（不是任何自建服务器）
```

> 🎯 面试观点：**"现代性能问题第一层在网络与 CDN，第二层在应用，Web 服务器层只要模型正确（事件驱动）就不会成为瓶颈"**——别为 5% 的差距选型，为生态与团队选型。

## 4. Apache → Nginx 迁移要点

| Apache 概念 | Nginx 对应 | 迁移注意 |
|------------|-----------|---------|
| `<VirtualHost>` | `server {}` | 一一对应 |
| `DocumentRoot` | `root` | 语法直译 |
| `.htaccess` | ❌ 无对应 | **需把规则搬进 server/location 块**（最大的迁移工作量） |
| mod_rewrite 规则 | `rewrite` / `try_files` | 语法转换（RewriteRule 与 rewrite 基本同构） |
| mod_proxy | `proxy_pass` | `ProxyPass /x/ http://b/` → `location /x/ { proxy_pass http://b/; }` |
| AllowOverride | 无 | 目录权限收敛到主配置 |
| 动态模块 | 编译模块/OpenResty | 部分模块无 Nginx 版（mod_security → naxsi/ModSecurity Nginx 版） |

```nginx
# 迁移示例：.htaccess 的伪静态规则 → Nginx
# Apache:  RewriteRule ^user/(\d+)$ /user.php?id=$1 [L]
# Nginx:
location / {
    rewrite ^/user/(\d+)$ /user.php?id=$1 last;
}
```

> 💡 迁移工具：`htaccess2nginx`（社区脚本）可半自动转换；但**正确姿势是重构路由**——现代应用早该把路由交给应用框架（Spring MVC/Rails），Web 服务器只做反代。

## 6. 10 大避坑清单

| # | 坑 | 现象 | 解法 |
|:---:|----|------|------|
| 1 | Apache 默认 prefork | 高并发内存爆 | 换 event MPM（02 §3） |
| 2 | 开着 .htaccess 解析 | 每请求磁盘查找 | AllowOverride None + 收敛主配置 |
| 3 | Nginx 迁移漏了 .htaccess 规则 | 伪静态 404 | 规则全部搬进 location 块（§4） |
| 4 | 反代超时小于应用超时 | 客户端超时应用还在跑 | 超时分层设计（05 §4） |
| 5 | Caddy 不升级 | 已知 CVE 裸奔 | 保持升级（v2.11.1 曾修 6 CVE） |
| 6 | On-demand TLS 无 ask | ACME 配额耗尽 | 必配 ask 校验（03 §2.4） |
| 7 | IIS 用高权限账户 | 被攻破即提权 | 最小权限应用池（04 §6） |
| 8 | 静态资源放应用服务器 | 线程被拖垮 | 静态上 Web 服务器/CDN（05 §2） |
| 9 | 只信单一份额报告 | 选型被误导 | 交叉口径（§2） |
| 10 | 想用一台服务器扛所有 | 架构失衡 | 动静分离 + 分层（05 §3） |

## 7. 高频面试题

### Q1：Nginx 为什么比 Apache 并发高？
> 模型差异：Apache 默认 prefork（1 连接 1 进程，内存几十 MB×并发）必然 C10K 崩溃；Nginx 事件驱动（1 进程 + epoll 事件循环处理万级连接），内存占用几乎与连接数无关。Apache 2.4 的 event MPM 已缩小差距，但 Nginx 的模型更彻底。

### Q2：Web 服务器和应用服务器的区别？
> Web 服务器是流量管道：静态资源直出、反向代理、TLS、缓存、限流，不执行业务；应用服务器是业务计算：Tomcat 跑 Servlet/Spring MVC 生成动态内容。现代架构动静分离：Nginx 管入口，Boot 管 API。

### Q3：什么是动静分离？为什么？
> 静态资源（JS/CSS/图片）由 Web 服务器/CDN 直出，动态请求反代到应用集群。原因：静态请求占比高且廉价（事件驱动零线程占用），动态请求昂贵（线程/CPU/DB）——分离后各自独立扩缩容，性能与成本都最优。

### Q4：Caddy 的自动 HTTPS 怎么实现的？
> 内置 ACME 客户端：配置出现公共域名即自动向 Let's Encrypt/ZeroSSL 申请证书（HTTP-01/TLS-ALPN-01/DNS-01 三种验证）、到期前 30 天自动续期、OCSP stapling、HTTP→HTTPS 重定向，全程零脚本。内网/localhost 用本地 CA 自签并自动装入信任库。通配符证书走 DNS-01。

### Q5：Apache 的 MPM 有哪几种？怎么选？
> prefork（1 进程 1 线程，兼容老模块，默认）、worker（多线程）、event（事件循环 + 线程池，处理 keep-alive 空闲连接）。高并发选 event；强依赖 mod_php 老栈才用 prefork。

### Q6：.htaccess 和 Nginx 配置的区别？
> .htaccess 是运行时解析的目录级配置（每请求向上查找解析，性能差），Nginx 没有 .htaccess——配置只能由管理员改（性能好、更安全）。迁移时把规则搬进 server/location 块。

### Q7：2026 年 Web 服务器市场格局？
> W3Techs（2026-08）：Nginx 31.5%、Cloudflare 边缘 29.0%、Apache 23.1%；头部站点 Cloudflare 过半。趋势：CDN 边缘崛起、Apache 下滑、Nginx 见顶、Caddy 约 3% 上升。注意口径差异（站点/机器/头扫描）。

### Q8：什么时候必须用 IIS？
> Windows + AD 域集成认证（Windows Authentication 免密登录内网系统）、SharePoint、老 ASP.NET 存量。新 .NET 项目标准姿势是 Kestrel 自托管 + Nginx/IIS 反代。

### Q9：Web 服务器层要配哪些东西？
> TLS 终止（证书集中管理）、gzip/brotli 压缩、静态缓存头、入口限流（漏桶）、超时三件套（连接/读/写）、X-Forwarded-* 头转发、访问日志（含耗时）。详情见 [05 §4 反代职责清单](05-Web服务器与应用服务器分工.md)。

### Q10：K8s 里还需要 Nginx 吗？
> 形态变了：Ingress Controller（Nginx/Envoy）吸收反代职责，静态资源上 CDN/对象存储，应用 Pod 自带内嵌容器。"Web 服务器"概念被吸收为基础设施，但分层思想不变。
