## 1. 异常到响应的完整链路

```text
Controller 抛异常
  │
  ▼
MVC 异常处理链（HandlerExceptionResolver，见 02 §7）
  ├─ @ControllerAdvice 命中？→ 统一响应格式（200/4xx/5xx）✅ 结束
  └─ 未命中（如 404 无映射、Filter 异常、容器级错误）
      │
      ▼
响应状态码（4xx/5xx）+ 异常冒泡到容器
  │
  ▼
容器错误分发（dispatcherType=ERROR，内部转发到 /error）
  │
  ▼
BasicErrorController（/error 的兜底控制器）
  ├─ ErrorAttributes 组装错误 JSON（status/message/path/...）
  └─ 或渲染错误页（HTML 客户端）
```

> 🎯 关键认知：**@ControllerAdvice 只能接住"进了 MVC 的异常"**——Filter 里抛的异常、404（无映射）、容器级错误（连接超限等）最终都走 /error 兜底。两条路不是替代关系，是**互补兜底**。

## 2. /error 兜底与 BasicErrorController

```java
// ErrorPageRegistrar 把错误页注册进容器（Boot 自动注册 /error）
public class ErrorPageRegistrar {
    // 容器把 4xx/5xx/异常 都内部转发到 /error
}

// BasicErrorController 两个处理方法：
@Controller
public class BasicErrorController extends AbstractErrorController {
    // ① HTML 客户端（浏览器）→ 渲染错误页
    @RequestMapping(produces = MediaType.TEXT_HTML_VALUE)
    public ModelAndView errorHtml(HttpServletRequest request) { ... }

    // ② 其他客户端（API 调用）→ 返回 JSON
    @RequestMapping
    public ResponseEntity<Map<String, Object>> error(HttpServletRequest request) { ... }
}
```

| 属性 | 说明 |
|------|------|
| 注册方式 | `ErrorPageRegistrar`（`DefaultErrorPageRegistrar` 自动注册 `/error`） |
| 分发类型 | ERROR（区别于 REQUEST）——Filter 可选择性放行 |
| 状态码 | 保留原始状态码（不会变成 200） |
| 请求属性 | `jakarta.servlet.error.status_code` 等（Servlet 规范，见 [Servlet 体系](../Servlet/05-配置方式演进与动态注册.md)） |

## 3. ErrorAttributes：错误信息的结构化提供者

```java
// 默认错误 JSON 结构（DefaultErrorAttributes）：
{
  "timestamp": "2026-08-08T09:30:00.123+00:00",
  "status": 500,
  "error": "Internal Server Error",       // 状态码短语
  "message": "系统繁忙",                  // 异常 message（server.error.include-message 控制）
  "path": "/api/users"                    // 请求路径
}

// 定制：覆盖 ErrorAttributes Bean（全局错误结构，前后端统一格式的根）
@Configuration
public class ErrorConfig {
    @Bean
    public ErrorAttributes errorAttributes() {
        return new DefaultErrorAttributes() {
            @Override
            public Map<String, Object> getErrorAttributes(WebRequest webRequest,
                    ErrorAttributeOptions options) {
                Map<String, Object> attrs = super.getErrorAttributes(webRequest, options);
                Map<String, Object> result = new LinkedHashMap<>();
                result.put("code", attrs.get("status"));       // 统一成 code
                result.put("msg", attrs.get("message"));
                result.put("data", null);
                result.put("traceId", MDC.get("traceId"));     // 运维可追踪
                return result;
            }
        };
    }
}
```

```yaml
# 错误信息暴露控制（生产安全：别把堆栈发给客户端）
server:
  error:
    include-message: never        # 生产建议 never；开发用 always
    include-stacktrace: never     # 生产必须 never（堆栈泄露 = 攻击信息）
    include-binding-errors: never
    include-exception: false
    path: /error                  # 兜底路径可改
```

> ⚠️ **生产铁律**：`include-stacktrace`/`include-message` 生产必须关闭——堆栈和内部 message 会泄露代码结构、SQL、文件路径，是攻击者的免费情报。排查走日志（traceId 关联），不靠错误响应。

## 4. @RestControllerAdvice 与 ErrorController 的分工

| 维度 | @RestControllerAdvice | ErrorAttributes / /error |
|------|:---:|:---:|
| 接住什么 | 进入 MVC 的 Controller/拦截器异常 | 未接住的异常、404、容器错误 |
| 响应格式 | 由你完全控制（Result 封装） | 由 ErrorAttributes 提供 |
| 状态码 | 注解/@ResponseStatus 控制 | 保留原始状态码 |
| 日志记录 | 你负责 | Boot 记录 |
| 适用 | **业务异常统一格式（90% 场景）** | 兜底 + 运维错误信息 |

```java
// 推荐组合：Advice 处理业务、ErrorAttributes 兜底
@RestControllerAdvice
public class GlobalExceptionHandler {
    // 业务异常 → 400 + code/message
    @ExceptionHandler(BizException.class)
    public Result<Void> handleBiz(BizException e) { ... }

    // 校验异常 → 400 + 字段错误
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<Void> handleValid(MethodArgumentNotValidException e) { ... }

    // 兜底：意料之外异常 → 500 + 隐藏细节（日志留痕）
    @ExceptionHandler(Exception.class)
    public Result<Void> handleOther(Exception e) {
        log.error("系统异常", e);          // ⚠️ 必须记录：排查唯一线索
        return Result.error(500, "系统繁忙");
    }
}
```

> 🎯 边界题（面试高频）：**@ExceptionHandler(Exception.class) 能不能接住 404？** 不能——404 是"没有 Handler"而非"Handler 抛异常"，不进异常处理链，只能由容器错误分发到 /error。同理 Filter 异常也接不住。

## 5. JSON vs HTML 内容协商

```text
请求 /error 的客户端类型决定响应：
  Accept: text/html（浏览器）→ 错误页（ModelAndView + 视图解析）
  Accept: application/json（API）→ JSON（ErrorAttributes 结构）
```

| 场景 | 响应 |
|------|------|
| 前端页面（浏览器直访） | HTML 错误页 |
| API 客户端（fetch/axios） | JSON 错误结构 |
| 无 Accept 头 | 默认 JSON（Boot 4 起协商规则统一） |

> 💡 前后端分离项目的隐藏坑：**错误页兜底是 HTML 还是 JSON 取决于 Accept 头**——有的客户端库不带 Accept 或带 `text/html,*/*;q=0.8`（如某些 WebView），会拿到 HTML 而不是 JSON。统一方案：全局异常用 @Advice 包住业务异常；兜底错误让 ErrorAttributes 输出统一 JSON（前端全量 API 场景）。

## 6. 错误页定制

| 方式 | 场景 | 做法 |
|------|------|------|
| 模板错误页 | 前后端一体 | `src/main/resources/templates/error/404.html`（按状态码自动匹配） |
| 静态错误页 | 无模板引擎 | `src/main/resources/static/error/404.html` |
| 全局错误页 | 所有错误 | `templates/error/error.html` |
| ErrorPageRegistrar | 编程式指定 | 自定义状态码 → 自定义路径 |

```java
// 编程式：把特定状态码/异常指向自定义路径
@Configuration
public class ErrorPageConfig {
    @Bean
    public ErrorPageRegistrar errorPageRegistrar() {
        return registry -> {
            registry.addErrorPages(new ErrorPage(HttpStatus.NOT_FOUND, "/error/404"));
            registry.addErrorPages(new ErrorPage(HttpStatus.FORBIDDEN, "/error/403"));
            registry.addErrorPages(new ErrorPage(SQLException.class, "/error/db"));
        };
    }
}
```

> ⚠️ 优先级：`templates/error/{status}.html` > `static/error/{status}.html` > 通用 `error.html` > 白标页（Whitelabel Error Page）。

## 7. 404 与其他边角细节

### 7.1 404 全家桶排查

| 404 现象 | 根因 |
|---------|------|
| 接口 404 | 路径写错 / 尾斜杠（Boot 4 不再等价，见 03 §8） |
| 接口 404 | Controller 未被扫描（启动类包外） |
| 静态资源 404 | 自定义 ResourceHandler 覆盖默认 / 目录配置错误 |
| 错误页 404 | 模板目录/命名错误（`templates/error/` 拼错） |
| 转发 404 | `forward:` 目标不存在 |
| 网关 404 | 路由未配置（见网关体系） |

### 7.2 405 / 406 / 415 速查

| 状态码 | 含义 | 常见根因 |
|:---:|------|---------|
| 405 | 方法不允许 | GET 请求 POST 接口；或未覆盖对应方法 |
| 406 | 不可接受 | 消息转换器缺失（JSON 转换器被 configureMessageConverters 覆盖弄丢） |
| 415 | 不支持媒体类型 | Content-Type 与 @RequestBody 期望不一致（text/plain 传 JSON） |
| 400 | 参数错误 | JSON 解析失败、类型转换失败、校验失败 |

### 7.3 与 Servlet 错误机制的关联

```text
Servlet 规范：web.xml <error-page>（见 Servlet 体系 §5）
Boot 等价：ErrorPageRegistrar 编程式注册
两者共享容器错误分发机制（dispatcherType=ERROR + error 请求属性）
```
