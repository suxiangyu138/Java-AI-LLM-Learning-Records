## 1. 内嵌 vs 外置容器

| 维度 | 内嵌（Boot 默认） | 外置（War + 独立 Tomcat） |
|------|------------------|--------------------------|
| 部署单元 | 单个可执行 jar | war 包 + 容器目录 |
| 启动 | `java -jar app.jar` | 容器脚本启动 |
| 环境一致性 | 容器版本随应用锁定 | 环境差异（容器版本不一致） |
| 运维 | 一条命令 | 需管理容器生命周期 |
| 热部署 | DevTools / 重启 | 容器级 reload |
| 适用 | 微服务、云原生（默认） | 传统单体、团队有容器运维规范 |

> 🎯 时代结论（2026-08）：**内嵌是绝对主流**——云原生/容器化（K8s 每个 Pod 一个进程）让外置容器失去存在价值；War 部署仅存于存量企业场景，见 [07-部署形态与HTTPS配置](07-部署形态与HTTPS配置.md)。

## 2. 容器工厂抽象：ServletWebServerFactory

```text
ServletWebServerFactory（接口）
  ├── TomcatServletWebServerFactory      ← 默认
  ├── JettyServletWebServerFactory
  └── UndertowServletWebServerFactory    ← Boot 4 已删除（不支持 Servlet 6.1）
         │
         └── getWebServer(initializers) → WebServer（生命周期：start/stop/port）
```

```java
// Boot 如何选择容器：条件装配
// 类路径有 tomcat-embed-core → 装配 TomcatServletWebServerFactory
// 有 jetty-server          → 装配 JettyServletWebServerFactory
// 有 undertow-core         → 装配 UndertowServletWebServerFactory（Boot 3 及以前）
```

| 抽象 | 职责 |
|------|------|
| `WebServerFactory` | 工厂标记接口 |
| `ServletWebServerFactory` | 创建 Servlet 栈 WebServer |
| `WebServer` | 容器生命周期（start/stop/getPort） |
| `WebServerFactoryCustomizer` | 定制工厂的钩子（Boot 推荐的定制入口） |
| `ServletContextInitializer` | 容器启动时回调（注册 Servlet/Filter/Listener） |

> 🎯 核心机制：Boot 把"启动应用"变成"**启动一个内嵌容器 + 容器启动时回调注册**"——容器对 Boot 来说只是可插拔的运行时，这也是 Boot 4 把服务器依赖独立成 starter 的原因。

## 3. 启动时序全链路

```text
main() → SpringApplication.run(App.class)
  │
  ├─ 1. 环境准备（配置加载）
  ├─ 2. 创建容器上下文（ServletWebServerApplicationContext）
  ├─ 3. Bean 定义加载 + 自动配置（ServletWebServerFactoryAutoConfiguration）
  │     └─ 装配 TomcatServletWebServerFactory
  ├─ 4. 【关键】refresh() → onRefresh()
  │     └─ createWebServer()
  │           ├─ factory.getWebServer(initializers)
  │           │     ├─ 创建 Tomcat 实例（Connector/Engine/Host/Context）
  │           │     └─ 把 ServletContextInitializer 列表交给 TomcatStarter
  │           └─ 启动 Tomcat（端口监听就绪）
  ├─ 5. 【关键】TomcatStarter.onStartup(ServletContext)
  │     └─ 遍历所有 ServletContextInitializer Bean 并调用
  │           ├─ DispatcherServletRegistrationBean（注册 DispatcherServlet，映射 "/"）
  │           ├─ CharacterEncodingFilterRegistrationBean（UTF-8 Filter）
  │           ├─ ErrorPageServletRegistrationBean（/error 错误页）
  │           └─ 用户自定义 ServletRegistrationBean
  ├─ 6. Spring 容器 refresh() 完成
  └─ 7. SpringApplication.run 返回 → 应用就绪（ApplicationRunner/CommandLineRunner 执行）
```

| 时序细节 | 说明 |
|---------|------|
| 容器先启动还是 Bean 先就绪？ | **容器启动早于 Spring 容器完成**：Tomcat 先监听端口，此时请求会进入但 DispatcherServlet 相关 Bean 可能未就绪——**并发首请求偶发 404/503 的根源之一** |
| ServletContextInitializer 何时收集 | refresh 过程中从 BeanFactory 收集，按注册顺序执行 |
| 请求何时真正可服务 | 全部 Bean 就绪后（Boot 4 起 `server.servlet.register-default-servlet` 等仍有默认） |

> 💡 面试关键理解：**内嵌容器的启动是 Spring 容器刷新流程的一部分**（onRefresh 钩子），不是两个独立系统——这解释了为什么"端口已开但接口 404"（Bean 未 ready 窗口）与"优雅停机要等容器"。

## 4. 容器切换：Tomcat / Jetty / Undertow

### 4.1 Boot 4 的 starter 重构（重要变更）

```xml
<!-- Boot 3.x 时代：一个 starter 带全部 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>   <!-- 含内嵌 Tomcat -->
</dependency>

<!-- Boot 4 时代：Web 与服务器解耦（旧名 spring-boot-starter-web 保留为废弃别名） -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-webmvc</artifactId>          <!-- MVC 本体 -->
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web-server-tomcat</artifactId>  <!-- 服务器：选一 -->
</dependency>
```

| Starter | 说明 |
|---------|------|
| `spring-boot-starter-webmvc` | Boot 4 新名（Servlet 栈 MVC） |
| `spring-boot-starter-web` | 旧名，废弃但可用 |
| `spring-boot-starter-web-server-tomcat` | Tomcat 11（默认） |
| `spring-boot-starter-web-server-jetty` | Jetty 12.1 |
| `spring-boot-starter-reactive-web-server-tomcat` | 响应式栈（WebFlux）变体 |

### 4.2 切换为 Jetty

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-webmvc</artifactId>
    <exclusions>
        <exclusion>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-web-server-tomcat</artifactId>
        </exclusion>
    </exclusions>
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web-server-jetty</artifactId>
</dependency>
```

> ⚠️ **Undertow 在 Boot 4 被彻底移除**（不支持 Servlet 6.1）——存量 Undertow 项目必须迁移 Tomcat/Jetty，`server.undertow.*` 配置失效，WebSocket/SSE 长连接场景需回归测试。这是 Boot 3 → 4 迁移的最大 Web 层坑之一。

## 5. server.* 配置全表

### 5.1 通用（`server.*`）

```yaml
server:
  port: 8080                    # 端口；0 = 随机端口（测试用）
  address: 0.0.0.0              # 绑定地址
  servlet:
    context-path: /app          # 应用上下文（对应 Servlet getContextPath）
    encoding:
      charset: UTF-8            # 请求/响应编码
      enabled: true
      force: true               # 强制覆盖（防容器默认 ISO-8859-1）
    session:
      timeout: 30m              # 会话超时
      cookie:
        http-only: true
        secure: true
        same-site: lax          # Boot 4：SameSite 显式配置
    register-default-servlet: false
    application-display-name: my-app
  shutdown: graceful            # 优雅停机
  forward-headers-strategy: framework   # 反代后正确取 X-Forwarded-*
  max-http-request-header-size: 8KB
```

### 5.2 Tomcat 专属（`server.tomcat.*`）

```yaml
server:
  tomcat:
    threads:
      max: 200                  # 业务线程池上限（默认 200）
      min-spare: 10             # 常驻线程
    accept-count: 100           # 排队队列长度
    max-connections: 8192       # 最大连接数
    connection-timeout: 20000ms # 连接超时
    keep-alive-timeout: 60s
    max-http-form-post-size: 2MB
    max-swallow-size: 2MB
    uri-encoding: UTF-8         # GET 参数解码
    relaxed-query-chars: "[,]"  # 允许的特殊字符
    accesslog:
      enabled: true
      pattern: "%h %l %u %t \"%r\" %s %b %D"   # %D 处理耗时
```

### 5.3 压缩与 HTTPS（详见 07）

```yaml
server:
  compression:
    enabled: true
    mime-types: application/json,text/html,text/css,application/javascript
    min-response-size: 1024     # 小于 1KB 不压
  http2:
    enabled: true               # 需 TLS（h2）或 h2c 显式开启
  ssl:
    enabled: true
    protocol: TLS
    key-store: classpath:keystore.p12
    key-store-type: PKCS12
    key-store-password: changeit
```

> 🎯 速记：`server.*` 通用 + `server.tomcat.*`/`server.jetty.*` 容器专属——切换容器时专属配置互不通用（Boot 4 后 Undertow 配置直接失效）。

## 6. 虚拟线程与连接器定制

### 6.1 虚拟线程（JDK 21+）

```yaml
# Boot 3.2+ 引入：启用虚拟线程执行请求
spring:
  threads:
    virtual:
      enabled: true
```

| 效果 | 说明 |
|------|------|
| 请求线程 | Tomcat 改用虚拟线程执行（替代 maxThreads=200 的平台线程池） |
| 并发能力 | 从几百提升到几十万（IO 密集场景） |
| 代价 | JDK 21+；共享状态竞争依旧要防（无状态铁律不变） |

> 💡 关联：[Servlet 体系](../Servlet/06-异步处理与非阻塞IO.md) 的"异步 vs 虚拟线程"决策——Boot 中同理：JDK 21+ 新项目开虚拟线程，传统项目用异步返回类型（见 02 §6）。

### 6.2 编程式定制容器

```java
// 方式一：WebServerFactoryCustomizer（Boot 推荐）
@Configuration
public class TomcatConfig {
    @Bean
    public WebServerFactoryCustomizer<TomcatServletWebServerFactory> tomcatCustomizer() {
        return factory -> {
            factory.setPort(9090);
            factory.addConnectorCustomizers(connector -> {
                connector.setProperty("relaxedPathChars", "[]");
            });
        };
    }
}

// 方式二：直接覆盖 Bean（完全接管）
@Bean
public ServletWebServerFactory servletWebServerFactory() {
    TomcatServletWebServerFactory factory = new TomcatServletWebServerFactory();
    factory.setPort(9090);
    factory.setContextPath("/app");
    return factory;
}
```

> ⚠️ 优先级：方式二覆盖自动配置 → 方式一 customize 自动配置的工厂。**优先用 Customizer**（可叠加多个、不影响其他自动配置）。

## 7. 启动慢排查

| 现象 | 可能原因 | 排查方向 |
|------|---------|---------|
| 启动 30s+ | 大量 @ComponentScan 全包扫描 | 收敛扫描范围、用类型安全注册 |
| 端口已开但首请求慢 | 懒加载 + 首请求初始化 | 预热（Runner/缓存预热） |
| 启动卡死 | 阻塞在外部资源（DB/Redis） | `spring.datasource.connection-fetch=lazy`（Boot 4.1）推迟连接 |
| 循环依赖 | Bean 循环引用 | 启动时即报错（Boot 2.6+ 默认禁止） |
| 启动耗时波动 | 容器类型检测/随机熵 | 固定依赖、禁用不必要的自动配置 |

> 🎯 定位工具：`spring-boot-starter-actuator` 的 `/actuator/startup`（ApplicationStartup）能按步骤拆解启动耗时——企业排障标准姿势，详见 [SpringBoot 运维体系](../../06-Spring全家桶/SpringBoot/07-SpringBoot生产运维与可观测.md)。
