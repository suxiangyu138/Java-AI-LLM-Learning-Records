## 1. 文件上传下载速查

### 1.1 配置（与 Servlet @MultipartConfig 一一对应）

```yaml
spring:
  servlet:
    multipart:
      max-file-size: 10MB        # 单文件上限（对应 maxFileSize）→ 超限抛 MaxUploadSizeExceededException
      max-request-size: 50MB     # 整个请求上限（对应 maxRequestSize）
      file-size-threshold: 1MB   # 内存阈值（对应 fileSizeThreshold）
      enabled: true
      location: /tmp             # 临时目录（可选）
```

### 1.2 接收与保存

```java
@PostMapping("/upload")
public String upload(@RequestParam("file") MultipartFile file) {
    String original = file.getOriginalFilename();     // ⚠️ 客户端原始名：不可信！
    long size = file.getSize();
    String safeName = UUID.randomUUID() + "_" + sanitize(original);  // 消毒+重命名
    file.transferTo(Path.of("/data/uploads", safeName));            // 落盘
    return safeName;
}

// 多文件 + 字段
@PostMapping("/uploads")
public String uploads(@RequestParam("files") MultipartFile[] files,
                      @RequestParam String title) { ... }
```

### 1.3 超限异常处理

```java
// 上传超限：默认返回 500，应转为友好 400
@ExceptionHandler(MaxUploadSizeExceededException.class)
public Result<Void> handleMaxSize(MaxUploadSizeExceededException e) {
    return Result.error(400, "文件过大，单文件不超过 10MB");
}
```

> 💡 机制同源：Boot 的 `MultipartFile` 就是 Servlet `Part` 的框架包装（[Servlet 上传体系](../Servlet/07-文件上传下载与PartAPI.md) 的 API 与安全清单全部适用）；下载/断点续传/大文件策略同样复用那套方案。

## 2. 常见 Web 故障排障

### 2.1 接口 404/405/406 排查表

| 现象 | 排查顺序 |
|------|---------|
| 全部 404 | 容器是否起来（/actuator/health）→ context-path 是否设置 → 启动类包扫描范围 |
| 单个 404 | 路径拼写 → 尾斜杠（Boot 4）→ Controller 注解（@GetMapping 拼错）→ 网关路由 |
| 405 | 方法不匹配（GET 打 POST 接口）→ 路由前缀冲突 |
| 406 | **消息转换器被 configureMessageConverters 覆盖弄丢**（03 §5 头号坑） |
| 415 | Content-Type 与 @RequestBody 不匹配（前端没设 application/json） |
| 500 且日志无 MVC 异常 | Filter 层异常（未进 MVC 异常链）→ 查 Filter 代码 |

### 2.2 慢请求三件套

| 工具 | 动作 |
|------|------|
| 访问日志 | 开 `server.tomcat.accesslog`（pattern 加 %D 耗时）→ 找 P99 以上请求 |
| Actuator | `/actuator/metrics/http.server.requests`（耗时分布） |
| 链路 | traceId（04 §2 的 Filter）+ 日志时间线 → 定位慢在哪一段 |

### 2.3 连接耗尽类故障

| 现象 | 根因 | 解法 |
|------|------|------|
| `Connection refused`/`Too many open files` | 线程/连接满 | 先看线程水位与连接数，再调参数（07 §6） |
| 请求排队 RT 飙升 | accept-count 打满 | 压测定位瓶颈（DB 连接池？下游慢？） |
| 线程一直涨 | 慢调用占住线程 | 慢 SQL/下游超时配置 → 异步化（02 §8） |
| 内存 OOM | 大上传/大响应/缓存 | multipart 阈值、分页、流式（07 §5） |

## 3. Web 安全配置速查

```yaml
server:
  servlet:
    session:
      cookie:
        http-only: true          # XSS 防脚本读
        secure: true             # 仅 HTTPS 携带
        same-site: lax           # CSRF 防护（Boot 4 显式配置）
        name: SID                # 改名：别暴露技术栈（JSESSIONID → SID）
  max-http-request-header-size: 8KB

# 响应安全头：Filter 统一加（见 04），或交给 Spring Security
# 核心四件套：X-Content-Type-Options / X-Frame-Options / Referrer-Policy / CSP
```

| 项 | 速查 |
|----|------|
| 会话固定 | 登录成功后 `request.changeSessionId()`（配合 HttpSessionIdListener，Servlet 6.1） |
| 错误信息泄露 | `server.error.include-stacktrace: never`（05 §3） |
| 上传 | 大小限制 + 文件名消毒 + 隔离目录（§1 + [Servlet 07](../Servlet/07-文件上传下载与PartAPI.md)） |
| CORS | 白名单来源，禁 `*` 配 allowCredentials（03 §3） |
| 反向代理 | `forward-headers-strategy` 只在可信代理后开（07 §3.3） |

## 4. Boot 3 → 4 迁移要点

| # | 变更 | 迁移动作 |
|:---:|------|---------|
| 1 | starter 更名 `spring-boot-starter-webmvc` | 依赖坐标替换（旧名废弃可用） |
| 2 | 服务器 starter 拆分 `-web-server-tomcat/-jetty` | 显式声明服务器依赖 |
| 3 | **Undertow 移除** | 迁移 Tomcat/Jetty，`server.undertow.*` 失效 |
| 4 | **尾斜杠不再等价** | `/foo/` 请求 404 → 客户端修正或 UrlHandlerFilter |
| 5 | **Jackson 3 默认** | 日期 ISO-8601/字段字母序/基本类型缺值报错；`tools.jackson` 包 |
| 6 | HttpMessageConverters 废弃 | 用 ServerHttpMessageConvertersCustomizer |
| 7 | @MockBean/@SpyBean 移除 | 测试改造（@MockitoBean / RestTestClient） |
| 8 | @SpringBootTest 不再自动配 MockMvc | 显式 @AutoConfigureMockMvc |
| 9 | Tomcat 11 / Servlet 6.1 | 第三方 Filter/Listener 兼容性验证 |
| 10 | Java 17 基线（21+ 推荐） | JDK 升级；虚拟线程可开启 |

> 🎯 迁移路径官方建议：先升 **Boot 3.5.x**（清理废弃 API）→ 再跳 4.0；`spring-boot-starter-classic` 可过渡。版本矩阵详见 [01-规范演进史](../Servlet/01-规范演进史与版本矩阵.md) 的容器部分。

## 5. 12 大避坑清单

| # | 坑 | 现象 | 解法 |
|:---:|----|------|------|
| 1 | configureMessageConverters 不调 super | JSON 全 406 | 用 extend/Customizer（03 §5） |
| 2 | 拦截器忘 exclude 登录接口 | 登录死循环 | 白名单必配（03 §2） |
| 3 | @WebFilter 想注入依赖 | 注入 null | 换 FilterRegistrationBean（04 §1） |
| 4 | ResponseWrapper 不 copyBodyToResponse | 客户端空响应 | 包装类回写（04 §6） |
| 5 | include-stacktrace 生产开启 | 堆栈泄露 | 设为 never（05 §3） |
| 6 | 用 @ExceptionHandler(Exception.class) 兜 404 | 接不住 | 404 走 /error；Advice 管业务异常（05 §4） |
| 7 | 尾斜杠依赖（升级 Boot 4） | 突然 404 | 客户端修正/UrlHandlerFilter（03 §8） |
| 8 | 上传不设 max-file-size | 大文件撑爆内存 | multipart 配置 + 异常处理（§1） |
| 9 | 启动类包外放 Controller | 接口 404 | 扫描范围正确（01 §7） |
| 10 | 接口前加 context-path 却网关没配 | 网关 404 | 网关路径与 context-path 对齐 |
| 11 | 虚拟线程 + 共享可变状态 | 数据错乱 | 无状态铁律不变（01 §6） |
| 12 | SPA history 刷新 404 | 前端路由失效 | Nginx try_files 或 ResourceResolver 兜底（06 §5） |

## 6. 高频面试题

### Q1：Spring Boot 是怎么启动内嵌 Tomcat 的？
> `SpringApplication.run` → 容器刷新 `onRefresh` → `createWebServer()`：`ServletWebServerFactory`（自动配置装配 TomcatServletWebServerFactory）创建 Tomcat 实例 → 容器启动监听端口 → 启动时 TomcatStarter（ServletContainerInitializer）回调所有 `ServletContextInitializer` Bean，注册 DispatcherServlet（映射 `/`）、编码 Filter、/error 错误页。**核心：内嵌容器的启动是 Spring 容器刷新流程的一部分**。

### Q2：DispatcherServlet 处理一次请求的流程？
> doDispatch：① multipart 包装 → ② HandlerMapping 找 Handler → ③ 找 HandlerAdapter → ④ 拦截器 preHandle（false 短路）→ ⑤ Controller 方法执行（参数解析器绑定参数）→ ⑥ 返回值解析（@ResponseBody 走消息转换器）→ ⑦ postHandle → ⑧ 视图渲染/响应 → ⑨ afterCompletion（finally 清理）。

### Q3：Filter、Interceptor、AOP 的区别与选型？
> Filter 容器层（拦一切含静态资源）；Interceptor MVC 层（能拿 HandlerMethod，范围可控）；AOP 切 Spring Bean 方法（事务/审计）。选型：traceId/编码用 Filter，鉴权用 Interceptor，切方法用 AOP。执行顺序：Filter → Interceptor preHandle → Controller → postHandle → afterCompletion → Filter 返回。

### Q4：@ControllerAdvice 能处理所有异常吗？
> 不能。它接住"进了 MVC 的异常"（Controller/参数绑定/转换器异常）。Filter 异常、404（无 Handler）、容器级错误最终走容器错误分发到 /error，由 BasicErrorController + ErrorAttributes 兜底。业务异常用 @Advice 统一格式，兜底交给 /error。

### Q5：/error 的 JSON 和 HTML 是怎么区分的？
> BasicErrorController 两个 @RequestMapping：一个 `produces=text/html`（浏览器 → 错误页），一个默认（API → JSON）。错误结构由 ErrorAttributes 提供（可定制统一 code/msg/traceId）。生产必须关 include-stacktrace/message。

### Q6：拦截器里怎么拿到 HandlerMethod？能拿参数值吗？
> preHandle 的 handler 参数强转 HandlerMethod 可拿方法/注解（方法级鉴权）；拿**参数值**需自定义 HandlerMethodArgumentResolver 或 HandlerMethodArgumentResolverComposite 手工解析（一般不这么做）。参数级拦截标准姿势是自定义参数解析器。

### Q7：WebMvcConfigurer 和 WebMvcAutoConfiguration 什么关系？
> Boot 的 WebMvcAutoConfiguration 检测到自定义 WebMvcConfigurer 后通过 WebMvcConfigurerComposite 组合：默认配置 + 自定义配置合并。**覆盖方法且不调 super 会破坏默认行为**（如 configureMessageConverters 整体替换）。

### Q8：Boot 4 相比 Boot 3 的 Web 层主要变化？
> ① starter 更名 webmvc + 服务器 starter 拆分；② Undertow 移除（Servlet 6.1 不支持）；③ 尾斜杠匹配移除；④ Jackson 3 默认（ISO-8601/字母序/基本类型缺值报错）；⑤ HttpMessageConverters 废弃 → Customizer Bean；⑥ @MockBean 移除 + RestTestClient；⑦ 内置 API 版本管理（spring.mvc.apiversion.*）；⑧ Tomcat 11（Servlet 6.1）、虚拟线程就绪。

### Q9：请求参数绑定是怎么完成的？自定义注解参数怎么注入？
> HandlerAdapter 内维护 HandlerMethodArgumentResolver 链，逐个调用 supportsParameter 判断，首个支持的解析器执行 resolveArgument。自定义 @LoginUser 注入 = 实现 HandlerMethodArgumentResolver + WebMvcConfigurer.addArgumentResolvers 追加。

### Q10：Boot 的静态资源在哪？为什么刷新 SPA 页面会 404？
> 默认 classpath:/static/ 等四个目录，未命中 Controller 时由 ResourceHttpRequestHandler 兜底。SPA history 路由刷新 `/user/123` → 后端无此路径 → 404，因为 Boot/Framework **没有内置 SPA fallback 配置**（2026-08 验证）——标准解法是 Nginx `try_files $uri /index.html`，或自定义 PathResourceResolver 返回 index.html。

### Q11：怎么给接口做多版本管理？
> Boot 4 内置 `spring.mvc.apiversion.*`（header/param/media-type 三种方式）；传统做法是自定义 HandlerMapping 或网关层路由。注意版本管理放网关（对外）+ 应用内按需（对内）。

### Q12：上传大文件为什么 OOM？怎么处理？
> MultipartFile 全量读内存（默认阈值 0 或很小）。解法：`spring.servlet.multipart.file-size-threshold` 调大让容器落临时盘；超大文件走流式 Part/对象存储直传（预签名 URL）。任何情况下服务端都要限制 max-file-size 并消毒文件名。
