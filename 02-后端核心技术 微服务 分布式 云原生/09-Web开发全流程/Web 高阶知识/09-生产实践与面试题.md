## 1. 接口设计进阶：幂等/限流/防重放

### 1.1 幂等落实三板斧

```text
POST 不幂等是协议语义，但业务必须幂等（否则重复下单/重复转账）：
① 幂等键（Idempotency-Key）：客户端生成唯一键，服务端按键去重
② 数据库唯一约束：业务唯一键（订单号）兜底
③ 乐观锁版本号：UPDATE ... WHERE version = ?
```

```java
// 幂等键实现（Redis 去重）
public OrderVO createOrder(OrderCreateDTO dto, String idempotencyKey) {
    // SETNX：键存在 → 重复请求直接返回已创建结果
    Boolean first = redis.setIfAbsent("idem:" + idempotencyKey, "1", Duration.ofHours(24));
    if (!first) {
        return orderService.getByIdempotencyKey(idempotencyKey);  // 幂等返回
    }
    return orderService.create(dto);   // 首次执行
}
```

### 1.2 限流与防刷

| 层 | 手段 | 粒度 |
|----|------|------|
| 入口层 | Nginx limit_req / 网关限流 | IP/路由 |
| 应用层 | Sentinel / 自定义过滤器 | 接口/用户 |
| 业务层 | 验证码 / 频控表 | 账号维度 |

> 💡 完整限流理论（漏桶/令牌桶/滑动窗口）见 [Sentinel 体系](../../06-Spring全家桶/Spring组件汇总/Spring%20Cloud%20微服务全家桶（分布式）/Spring%20Cloud%20Alibaba（阿里实现，属于%20Spring%20Cloud%20生态实现）/Sentinel：流量控制熔断降级/00-Sentinel知识体系总览.md) 与 [后端名词体系](../后端%20分布式常用名词通俗解释/00-后端分布式名词知识体系总览.md)。

### 1.3 防重放（签名 + 时间戳）

```text
开放平台防重放三件套：
  · 请求签名：参数 + 密钥 → HMAC 签名
  · 时间戳：|now - ts| > 5min 拒绝（防历史重放）
  · 随机数 nonce：同 nonce 只接受一次（防同秒重放）
```

```bash
# Web 调试三板斧
curl -i https://api.example.com/users          # 看响应头（缓存/TLS/安全头）
```

## 3. 12 大避坑清单

| # | 坑 | 现象 | 解法 |
|:---:|----|------|------|
| 1 | 误用 no-cache（以为是不缓存） | 数据仍被缓存 | 理解语义：no-cache=验证，no-store=不缓存（[02 §4](02-HTTP缓存体系.md)） |
| 2 | 无版本化 + 长缓存 | 更新永远看不到 | 版本化 URL（[02 §7](02-HTTP缓存体系.md)） |
| 3 | 依赖浏览器启发式缓存 | 页面被缓存成旧版 | 显式 Cache-Control |
| 4 | 证书链不全 | 浏览器/客户端证书错误 | 下发完整链（[03 §2](03-HTTPS与TLS深入.md)） |
| 5 | 只开 TLS 1.2 | 握手慢 | TLS 1.3 优先 + 会话恢复 |
| 6 | HSTS preload 过早 | HTTP 永远进不来 | 纯 HTTPS 稳定后再 preload（[03 §7](03-HTTPS与TLS深入.md)） |
| 7 | Allow-Origin 用 * | 带凭据跨域失败 | 白名单 + Credentials 配套（[05 §3](05-跨域与浏览器安全机制.md)） |
| 8 | 忘了 Expose-Headers | JS 读不到自定义头 | 显式暴露（[05 §2](05-跨域与浏览器安全机制.md)） |
| 9 | WebSocket 不配粘滞/广播 | 连接漂移消息丢失 | Redis 广播（[06 §5](06-实时通信WebSocket与SSE.md)） |
| 10 | SSE 被代理缓冲 | 推送不实时 | proxy_buffering off（[06 §5](06-实时通信WebSocket与SSE.md)） |
| 11 | CSP 直接强制上线 | 业务资源全被拦 | report-only 过渡（[05 §6](05-跨域与浏览器安全机制.md)） |
| 12 | 出网请求不设白名单 | SSRF 打内网 | 域名白名单 + 内网段拦截（[07 §5](07-Web安全攻防.md)） |

## 4. 高频面试题

### Q1：HTTP 为什么无状态？怎么解决？
> 协议设计使然：每个请求独立，服务器不保留上下文（支撑高并发与水平扩展）。状态通过 Cookie（携带标识）+ Session/Token（服务端/客户端存储）解决。演进：单体 Session → 分布式 Session 外置 → JWT 无状态（见 [会话体系](../Cookie%20%26%20Session（会话技术）/00-会话技术总览.md)）。

### Q2：强缓存和协商缓存区别？
> 强缓存（Cache-Control: max-age）：命中不发请求，0 网络流量；协商缓存（ETag/Last-Modified）：每次都发请求，304 免 body。ETag 优于 Last-Modified（秒级粒度、强校验）。生产：静态资源版本化 + 长强缓存，HTML no-cache 协商。

### Q3：HTTPS 握手过程（TLS 1.3）？
> ClientHello（带 ECDHE 参数）→ ServerHello + 证书 + Finished → 客户端验证证书链后回 Finished → 1-RTT 完成，开始加密通信。TLS 1.3 相比 1.2：预发密钥参数省一个来回、强制前向保密（ECDHE）、精简套件、PSK 会话恢复 0-RTT（仅幂等请求）。证书链：根证书 → 中间 CA → 站点证书。

### Q4：HTTP/2 和 HTTP/3 的核心区别？
> HTTP/2：二进制帧 + 单连接多路复用 + HPACK 压缩，解决应用层队头阻塞；但仍跑在 TCP 上，TCP 丢包重传导致传输层队头阻塞。HTTP/3 换 QUIC（UDP + 内置 TLS 1.3）：独立流隔离丢包、连接迁移、0-RTT。2026 现状：HTTP/2 流量 ~51-55% 是主力，HTTP/3 站点支持 ~40%、流量 ~21-34%。

### Q5：跨域是怎么发生的？CORS 预检怎么回事？
> 浏览器同源策略拦截跨源响应读取。非简单请求（自定义头/JSON/PUT 等）先发 OPTIONS 预检，服务器回 Access-Control-Allow-* 规则，通过后发真实请求。带凭据时 Allow-Origin 不能是 *。注意：请求其实发出去了，是响应被浏览器拦截。终极方案是反代同域。

### Q6：WebSocket 和 SSE 怎么选？
> 单向推送（通知/进度/LLM 流式）→ SSE：纯 HTTP、自动重连、代理兼容、简单；双向交互（聊天/游戏/协作）→ WebSocket：全双工但有状态（心跳/粘滞/广播）。80% 业务推送用 SSE 即可。

### Q7：XSS 和 CSRF 的区别？
> XSS：注入恶意脚本窃取会话/篡改页面（防：输出转义 + CSP + HttpOnly）；CSRF：利用已登录身份跨站代发请求（防：SameSite + Token）。XSS 是"偷钥匙"，CSRF 是"借手"——XSS 能绕过 CSRF 防线（拿到 Token），所以 XSS 防护更底层。

### Q8：OWASP Top 10 2025 有哪些变化？为什么？
> A01 访问控制仍第一（SSRF 并入）；A02 配置错误升至第二、A03 供应链升至第三（云原生配置面扩大 + 依赖生态风险）；注入从 #3 降至 #5（框架参数化缓解）；新增 A10 异常处理不当。总趋势：风险从代码漏洞转向架构与配置。

### Q9：SSRF 是什么？为什么 2026 特别危险？
> 服务端请求伪造：利用服务器"能访问内网"的特性，让服务器去请求内网/云元数据（169.254.169.254 可拿云凭证）。云时代内网价值极高，成为横向移动跳板。防护：出网域名白名单 + 内网 IP 段拦截 + 禁止重定向跟随 + 网络层隔离。

### Q10：Core Web Vitals 有哪些？后端怎么影响？
> LCP（最大内容渲染 ≤2.5s）、INP（交互响应 ≤200ms，替代 FID）、CLS（布局稳定 ≤0.1）。后端影响：TTFB 直接决定 LCP（接口渲染主内容时）、慢接口拖累 INP、返回结构不稳定引发 CLS。性能是前后端联动责任。

### Q11：页面加载慢怎么排查？
> 分阶段看瀑布图：DNS/TCP/TLS（网络层）→ TTFB（后端，看接口耗时与缓存）→ 资源传输（压缩/CDN）→ 解析渲染（JS/CSS 阻塞）。工具：DevTools Network + Lighthouse + 压测。方法论：先度量定位瓶颈层，最大的窟窿先补。

### Q12：怎么做接口防刷/防重放？
> 分层：入口限流（IP/路由，Nginx/网关）→ 应用限流（用户维度，Sentinel）→ 业务防重（幂等键 + 唯一约束）→ 开放平台签名（HMAC + 时间戳 + nonce）。每个层管不同威胁：限流管频率、幂等管重复、签名管伪造与重放。
