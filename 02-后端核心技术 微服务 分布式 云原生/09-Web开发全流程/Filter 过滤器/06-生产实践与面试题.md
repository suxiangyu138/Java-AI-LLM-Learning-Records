## 1. 生产最佳实践

| # | 实践 | 说明 |
|---|------|------|
| 1 | **继承 OncePerRequestFilter** | 转发场景只执行一次 + 可注入 |
| 2 | FilterRegistrationBean 注册 | 顺序可控（@WebFilter 顺序不可控） |
| 3 | 单一职责 | 一个 Filter 一件事（编码/鉴权/日志分开） |
| 4 | 顺序编排 | 编码最先、CORS 次之、鉴权居中、统计最外 |
| 5 | 静态资源放行 | 业务 Filter 内白名单放行静态路径 |
| 6 | 不写重逻辑 | Filter 保持轻量（耗时/IO 影响全链路） |
| 7 | 日志结构化 | Filter 日志进统一采集（见日志监控指标） |
| 8 | 异常处理 | doFilter 内异常要 catch 处理（否则 500 裸奔） |

```java
// 生产级 Filter 骨架（最佳实践组合）
@Component
public class ProductionFilter extends OncePerRequestFilter {

    @Override
    protected boolean shouldNotFilter(HttpServletRequest request) {
        // 静态资源/白名单跳过（避免无谓拦截）
        String uri = request.getRequestURI();
        return uri.startsWith("/static/") || uri.startsWith("/favicon.ico");
    }

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                    HttpServletResponse response,
                                    FilterChain filterChain)
            throws ServletException, IOException {
        try {
            // 前置逻辑（轻量）
            filterChain.doFilter(request, response);
        } catch (Exception e) {
            // 异常兜底（防 500 裸奔）
            log.error("Filter 异常: {}", request.getRequestURI(), e);
            throw e;
        } finally {
            // 后置逻辑（耗时统计等）
        }
    }
}
```

> 🎯 **生产 Filter 四要素**：OncePerRequestFilter（基类）+ shouldNotFilter（白名单）+ try/finally（异常兜底）+ 轻量逻辑。

## 2. 高频避坑清单

| # | 坑 | 规避 |
|---|----|------|
| 1 | @WebFilter 顺序不可控 | FilterRegistrationBean.setOrder |
| 2 | @WebFilter 无法注入 Bean | Filter 加 @Component 或注册为 Bean |
| 3 | 转发场景重复执行 | 继承 OncePerRequestFilter |
| 4 | 不调 chain.doFilter（忘了） | 请求黑洞——确认拦截逻辑有放行分支 |
| 5 | Filter 里写重逻辑 | 阻塞全链路——保持轻量 |
| 6 | 静态资源被业务 Filter 拦截 | shouldNotFilter/白名单 |
| 7 | 异常不处理 | 500 裸奔/日志缺失——try/finally |
| 8 | 多方式注册混用 | 顺序混乱——统一 FilterRegistrationBean |
| 9 | Filter 修改了响应后忘记传递 | 包装后必须 chain.doFilter(wrapper) |
| 10 | 限流/登录 Filter 放最后 | 顺序错误（应先于业务 Filter） |

## 3. 面试题

| 题目 | 答题要点 |
|------|---------|
| Filter 生命周期？ | init 一次、doFilter 每次、destroy 一次（容器管理） |
| Filter 怎么拦截请求？ | 不调 chain.doFilter = 拦截 |
| FilterChain 执行机制？ | 责任链：前置顺序、后置逆序（洋葱模型） |
| Filter 和 Interceptor 区别？ | 容器层 vs MVC 层；Filter 拦所有请求、Interceptor 拿 HandlerMethod |
| Filter、Interceptor、AOP 执行顺序？ | Filter → Interceptor.preHandle → Controller（AOP）→ postHandle → afterCompletion → Filter 后置 |
| 登录校验用 Filter 还是 Interceptor？ | 细粒度（读注解）用 Interceptor；全局白名单 Filter 也可 |
| Spring Boot 怎么注册 Filter？ | FilterRegistrationBean（推荐，顺序可控）；@WebFilter（顺序不可控） |
| OncePerRequestFilter 是什么？ | Spring 基类：一次请求只执行一次（转发场景）+ 可注入 |
| Filter 能拿到 HandlerMethod 吗？ | 不能（容器层）——Interceptor 才能 |
| 请求体只能读一次怎么解决？ | 请求包装（HttpServletRequestWrapper 缓存 Body） |
| Filter 里能注入 Spring Bean 吗？ | @Component 的 Filter 可以（或注册为 Bean） |
| 过滤器顺序怎么定？ | Order 越小越先；编码最先、鉴权居中、统计最外 |

## 4. 核心要点

> 🎯 **核心要点**：
> - 生产四要素：OncePerRequestFilter + shouldNotFilter 白名单 + try/finally + 轻量；
> - 避坑 Top3：@WebFilter 顺序不可控、忘了 chain.doFilter、转发重复执行；
> - 面试主线：生命周期 → 拦截原理 → 责任链 → 三机制对比 → Boot 注册 → OncePerRequestFilter；
> - 与体系联动：登录校验接会话技术、CORS 接 Nginx、监控接日志监控指标、Sentinel 做生产限流；
> - Filter 是"请求链路的统一关卡"——**单一职责 + 顺序明确 + 轻量执行**是用好的三原则。
