## 1. Servlet 的由来

Servlet 诞生于 1996-1997 年，是 Sun 公司为**替代 CGI 而生的 Java 方案**。

| 维度 | CGI（Common Gateway Interface） | Servlet |
|------|------|---------|
| 进程模型 | 每个请求 fork 一个**进程** | 每个请求分配一个**线程** |
| 资源开销 | 1000 并发 ≈ 1000 进程，开销巨大 | 线程池复用，几十线程扛千并发 |
| 跨平台 | 依赖操作系统 | JVM 一次编写处处运行 |
| 数据共享 | 进程间共享困难 | ServletContext 全局共享 |
| 内存 | 每请求独立内存 | 堆内存共享 |

> 🎯 Servlet 用"**单实例多线程**"模型彻底解决了 CGI 的进程风暴问题，这一模型沿用至今，也是理解 Servlet 线程安全问题的起点（详见 [02-生命周期与线程模型](02-生命周期与线程模型.md)）。

## 2. 演进时间线全表

```text
 1997       2001      2006      2009      2013      2017      2020      2022      2025
   │          │         │         │         │         │         │         │         │
 Servlet   Servlet  Servlet  Servlet   Servlet   Servlet   Servlet   Servlet   Servlet
  1.0→2.2    2.3      2.5      3.0       3.1       4.0       5.0       6.0       6.1
   (诞生)   (Filter)  (稳定)   (注解)    (NIO)     (HTTP/2)  (jakarta) (现代化)  (EE11)
                                                                    └── 6.2 里程碑开发中（2026-08）
```

| 版本 | 平台 / 年份 | 核心变化 |
|:---:|------------|---------|
| 1.0-2.2 | J2EE 1.2 / 1999 | 随 J2EE 平台发布，web.xml 声明式配置成型 |
| **2.3** | J2EE 1.3 / 2001 | **引入 Filter 过滤器**与 ServletContextListener |
| 2.4 | J2EE 1.4 / 2003 | web.xml 升级为 Schema 校验；加入请求级监听器 |
| 2.5 | Java EE 5 / 2006 | web.xml 2.5；与 JSP 2.1 统一 EL 表达式 |
| **3.0** | Java EE 6 / 2009 | **注解驱动**（@WebServlet）、SCI 编程式注册、**异步处理**、Part 上传、web-fragment |
| **3.1** | Java EE 7 / 2013 | **非阻塞 IO**（ReadListener/WriteListener）、HTTP 协议升级 |
| **4.0** | Java EE 8 / 2017 | **HTTP/2**、server push、缺省 Servlet 不再遮蔽 JSP |
| **5.0** | Jakarta EE 9 / 2020 | **javax → jakarta 命名空间**全面迁移 |
| **6.0** | Jakarta EE 10 / 2022 | Java 11 基线（实现普遍 17）、Cookie RFC 6265、请求唯一 ID、**移除单线程模型** |
| **6.1** | Jakarta EE 11 / 2025 | 重定向状态码控制、ByteBuffer IO、HttpSessionIdListener、SecurityManager 移除、**HTTP/2 push 废弃** |
| 6.2 | Jakarta EE 12（规划中） | 2026-08 时点已发布 M1/M2 里程碑，正式特性待定 |

> 💡 3.0 是 Servlet 历史上**最重要的分水岭**：从"XML 声明式"走向"注解 + 编程式"，现代 Spring Boot 的零配置启动正是建立在 3.0+ 的 SPI 机制上。

## 3. 关键版本深读

### 3.1 Servlet 6.0（Jakarta EE 10，2022-09 发布）—— 现代化与清理

- **Java 基线**：规范最低 Java SE 11（EE 10 平台同时支持 17），主流实现（Tomcat 10.1 要求 Java 11+、Jetty 12 直接 17+）
- **Cookie 全面现代化**：弃用 RFC 2109，全面遵循 **RFC 6265**；Cookie 类支持**通用属性**——`Cookie.setAttribute("SameSite", "Lax")` 由此可行（此前必须手动拼 `Set-Cookie` 字符串）
- **请求唯一标识**：新增 `ServletRequest.getRequestId()` 与 `getProtocolRequestId()`（协议层 ID，如 HTTP/2 的 stream ID），日志链路追踪不再依赖自造 UUID
- **模块化**：提供 `module-info.java`，Servlet API 可被 JPMS 直接引用
- **安全清理**：规范不再推荐容器输出 `X-Powered-By` 头；移除 `SingleThreadModel`、`HttpUtils`、`HttpSessionContext` 等废弃 API
- **其他**：URI 路径规范化/解码语义澄清；包装 Request/Response 用于 RequestDispatcher 的限制放宽

### 3.2 Servlet 6.1（Jakarta EE 11，2025 年发布）—— 小步快跑

定位为维护版（maintenance release），API 完全向后兼容 6.0，重点在**澄清灰色地带 + 补全常用能力**：

| 新增/变更 | 说明 |
|-----------|------|
| **重定向状态码控制** | 新增 3 个重载：`sendRedirect(location, sc)`、`sendRedirect(location, sc, clearBuffer)` 等，可自定义 301/303/307/308 而非永远 302 |
| **ByteBuffer IO** | `ServletInputStream.read(ByteBuffer)` / `ServletOutputStream.write(ByteBuffer)`，非阻塞 IO 不再被迫走 byte[] |
| **HttpSessionIdListener** | 新监听器接口，会话 ID 变更（如 `changeSessionId()` 防固定攻击）时通知应用 |
| **错误分发携带 query string** | 新增 `RequestDispatcher.ERROR_QUERY_STRING`（`jakarta.servlet.error.query_string`）属性 |
| **参数解析失败明确抛异常** | `getParameter` 系列在解析失败时抛 `IllegalStateException`（此前行为未定义） |
| **错误分发恒用 GET** | 错误页分发始终以 GET 进行，不再继承原始请求方法 |
| Charset 重载 | 编码相关方法新增 `java.nio.charset.Charset` 重载，编译期类型安全 |
| 新 HTTP 状态码常量 | 补齐新协议状态码 |
| **SecurityManager 移除** | 全面移除 SecurityManager 相关引用（Java 17 已弃用） |
| **HTTP/2 push 废弃** | server push 标记废弃（浏览器支持差、与客户端缓存冲突），Tomcat 11 直接移除 |

### 3.3 Servlet 6.2（Jakarta EE 12 候选，开发中）

截至 **2026-08**，`jakartaee/servlet` 仓库已标记 `6.2.0-M1`、`6.2.0-M2` 里程碑版本，目标随 Jakarta EE 12 发布。正式特性清单尚未定型，选型时**不押注未发布特性**。

> 🎯 **版本选型铁律**：面试和生产一律以 **6.1（Jakarta EE 11 / Tomcat 11）** 为准；存量项目常见 Servlet 4.0（javax，Tomcat 9）——迁移路径见下节。

## 4. javax → jakarta 命名空间迁移

### 4.1 为什么迁移

Oracle 2017 年将 Java EE 捐献给 Eclipse 基金会，改名 Jakarta EE。由于 Oracle 保留 `javax.*` 商标使用权，Jakarta EE 9 起所有 API 必须使用 **`jakarta.*`** 命名空间。

### 4.2 迁移范围与影响

| 项目 | 迁移前 | 迁移后 |
|------|--------|--------|
| 包名 | `javax.servlet.*` | `jakarta.servlet.*` |
| 依赖坐标 | `javax.servlet:javax.servlet-api` | `jakarta.servlet:jakarta.servlet-api` |
| 依赖版本 | 4.0.x | 5.0+ / 6.0 / 6.1 |
| web.xml 头 | `xmlns="http://xmlns.jcp.org/xml/ns/javaee" version="4.0"` | `xmlns="https://jakarta.ee/xml/ns/jakartaee" version="6.0"` |
| 容器要求 | Tomcat 9 及以下 | Tomcat 10.0+（9 无法运行 jakarta 应用） |

### 4.3 迁移三步走

1. **全局替换包名**：`javax.servlet` → `jakarta.servlet`（IDE 批量替换，不涉及逻辑）
2. **升级依赖**：`javax.servlet-api` 4.0.x → `jakarta.servlet-api` 6.x
3. **换容器**：Tomcat 9 → Tomcat 10.1+（或 11），改 web.xml 头与 `<web-app>` 根元素

```xml
<!-- 迁移后：Servlet 6.x 的 web.xml 头 -->
<web-app xmlns="https://jakarta.ee/xml/ns/jakartaee"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="https://jakarta.ee/xml/ns/jakartaee
                             https://jakarta.ee/xml/ns/jakartaee/web-app_6_0.xsd"
         version="6.0">
</web-app>
```

> ⚠️ 常见坑：`javax.*` 与 `jakarta.*` 混用（两个 jar 都依赖）导致 `NoClassDefFoundError: javax/servlet/...`；依赖里藏着的旧库（如老版 Dubbo、Shiro）也要一起排查——用 `mvn dependency:tree | grep servlet` 全量核对。

## 5. 容器生态版本矩阵

Servlet 是**规范（API）**，容器是**实现**。选容器 = 选 Servlet 版本。

| 容器 | Servlet 版本 | Java 要求 | 说明 |
|------|:---:|:---:|------|
| Tomcat 9.x | 4.0（javax） | 8+ | 存量项目主力，已进入维护期 |
| Tomcat 10.0.x | 5.0（jakarta） | 8+ | 过渡版本，不建议新用 |
| Tomcat 10.1.x | 6.0（jakarta） | 11+ | EE 10 基准，Boot 3.x 默认 |
| **Tomcat 11.x** | **6.1（jakarta）** | **17+** | EE 11 基准；11.0.6（2025-04-09）起稳定；支持**虚拟线程**（JDK 21+，VirtualThreadExecutor）、**TLS 证书热重载**、Panama OpenSSL；HTTP/2 push 已移除 |
| Tomcat 12.x | 开发中 | - | 2026 年处于夜间构建阶段 |
| Jetty 11 | 5.0（jakarta） | 11+ | |
| Jetty 12 | 6.0 / 6.1（jakarta） | 17+ | EE 10 / EE 11 双变体（`jetty-ee10` / `jetty-ee11`） |
| Undertow 2.x | 4.0（javax） | 8+ | WildFly 老版本 |
| Undertow 3.x | 6.0 / 6.1（jakarta） | 17+ | WildFly 32+ / 34+ 采用，Boot 内置 Web 服务器可选 |

> 🎯 实际选型：**Spring Boot 3.x 默认内嵌 Tomcat 10.1（Servlet 6.0）**；Spring Boot 4.x / 新项目可直接换 Tomcat 11（Servlet 6.1，Java 17+ 环境）。详见 [05-配置方式演进与动态注册](05-配置方式演进与动态注册.md) 的 Spring Boot 注册部分。

## 6. 与 JavaWeb 其他组件的关系

| 组件 | 规范位置 | 与 Servlet 的关系 |
|------|---------|------------------|
| Filter | Servlet 规范（2.3+） | 请求进入 Servlet 前的拦截关卡 |
| Listener | Servlet 规范（2.3+） | 观察 ServletContext/Session/Request 生命周期事件 |
| JSP | Pages 规范（独立） | JSP 文件被容器翻译为 **Java 类本质是 Servlet**（继承 HttpServlet） |
| WebSocket | WebSocket 规范（独立） | 复用容器连接管理，独立于 HTTP 请求-响应模型 |
| Spring MVC | 框架层 | `DispatcherServlet` 是一个**标准 Servlet**，借助 HandlerMapping 实现路由分发 |

> 🎯 一句话理解：**JavaWeb 三大组件（Servlet/Filter/Listener）都在 Servlet 规范里**；JSP 是 Servlet 的"模板语法糖"；Spring MVC 是 Servlet 的"框架化封装"——学透 Servlet，JavaWeb 全部打通。
