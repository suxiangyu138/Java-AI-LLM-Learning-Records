## 1. 一次请求的完整旅程

```text
浏览器
  │ HTTP 请求
  ▼
Connector（NIO，解析报文：请求行/头/body）
  │ 构造 Request/Response 对象（Facade 包装，防类型向下转换）
  ▼
Mapper（URL → Servlet 映射匹配，详见 §3）
  │
  ▼
FilterChain（[Filter 过滤器](../Filter%20过滤器/00-Filter过滤器总览.md) 链）
  │ chain.doFilter
  ▼
Servlet.service() → doGet/doPost
  │ 业务处理
  ▼
响应经 Response 对象 → Connector 写回浏览器
```

> 🎯 Tomcat 的 `Mapper` 是映射的核心组件：**一次请求只做一次映射**（查 `mappingData`），映射发生在 Filter 链之前，Filter 拿到的 `dispatcherType` 与映射结果已经确定。

## 2. URL 拆解与各段含义

```text
http://localhost:8080/app/user/list?page=1&size=20
├──scheme──┘ ├─host─┘ ├port┘├context├├servlet├─query─┘
                        ├──── getRequestURL() ────┤
              ├────────── getRequestURI() ────────┤
```

| 段 | 获取方式 | 示例 | 说明 |
|----|---------|------|------|
| Scheme | `getScheme()` | http/https | 反向代理后注意 X-Forwarded-Proto |
| Host | `getServerName()` | localhost | 反代后取 X-Forwarded-Host |
| Port | `getServerPort()` | 8080 | 80/443 时可能被规范化 |
| Context Path | `getContextPath()` | /app | 应用上下文，**始终以 / 开头** |
| Servlet Path | `getServletPath()` | /user/list | 与 Servlet 映射匹配的部分 |
| Path Info | `getPathInfo()` | 见 §3.2 | `/*` 匹配时的剩余部分 |
| Query String | `getQueryString()` | page=1&size=20 | 原始未解码字符串 |

> 💡 `getServletPath()` vs `getPathInfo()`：只有**路径前缀匹配（`/xxx/*`）**时才有 PathInfo（映射后的剩余部分）；精确匹配时 PathInfo 为 null。RESTful 框架（JAX-RS / Spring）正是靠解析 PathInfo 实现路径参数（`/user/{id}`）。

## 3. 四种映射规则与优先级

### 3.1 规则总表

| 类型 | 写法 | 示例 | 优先级 |
|------|------|------|:---:|
| **精确匹配** | `/a/b` | `/user/login` | 1（最高） |
| **路径前缀匹配** | `/a/*` | `/user/*` | 2（最长的前缀优先） |
| **扩展名匹配** | `*.ext` | `*.do` | 3 |
| **缺省匹配** | `/` | `/` | 4（最低） |

```java
@WebServlet("/user/login")     // 精确
@WebServlet("/user/*")         // 前缀
@WebServlet("*.do")            // 扩展名
@WebServlet("/")               // 缺省
```

### 3.2 匹配算法（规范 §12.1，Tomcat Mapper 实现）

对请求路径 `/user/list.do` 的判定顺序：

1. **精确匹配**：存在 `/user/list.do`？→ 命中
2. **最长前缀**：依次尝试 `/user/list.do`、`/user/list`、`/user`、`/`（逐级去末段）→ 命中 `/user/*` 则结束
3. **扩展名匹配**：取最后一段找 `*.do` → 命中
4. **缺省 Servlet**：`/` 兜底

```text
请求 /user/login
候选匹配：/user/login（精确，赢）> /user/*（前缀）> *.do（扩展）> /（缺省）
```

| 细节 | 规则 |
|------|------|
| 前缀 vs 扩展名 | **二者不能同时存在**于一个映射：`@WebServlet("/user/*.do")` 非法，部署报错 |
| 多个前缀竞争 | **最长前缀胜出**：`/user/*` 与 `/user/list/*` 同时存在，请求 `/user/list/x` 命中后者 |
| 前缀 + PathInfo | 命中 `/user/*` 时：`getServletPath()`=`/user`，`getPathInfo()`=`/list/x` |
| 扩展名 + ServletPath | 命中 `*.do` 时：`getServletPath()`=`/user/list.do`，`getPathInfo()`=null |
| 大小写 | 匹配**区分大小写**（Windows 文件系统除外）；Tomcat 有 `Mapper` 大小写宽容开关 |
| 尾斜杠 | `/user` 与 `/user/` 视为不同路径（精确匹配不相等） |

> ⚠️ 面试常问：`/` 与 `/*` 的区别——`/` 是**缺省 Servlet**（只接未被其他映射命中的请求）；`/*` 是**前缀匹配**（拦截一切，包括 JSP 与静态资源），映射到 `/*` 的 Servlet 等于"接管全世界"，非特殊需求别这么干。

### 3.3 映射冲突与部署校验

| 冲突 | 容器行为 |
|------|---------|
| 两个 Servlet 声明相同精确路径 | 部署时报错 |
| `/a/*` 与 `/a/*` 重复 | 部署时报错（同一 Context） |
| `/a/*` 与 `*.a` 混合 | 合法（不同规则族） |
| 与静态资源冲突 | 容器内定优先级，见下节 |

## 4. 缺省 Servlet 与静态资源

```text
请求 /static/logo.png：
  Filter 链（/*）→ Mapper：无业务 Servlet 命中 → 缺省 Servlet（DefaultServlet）
  → DefaultServlet 读 WEB-INF 外的静态文件 → 200 + Content-Type 按扩展名映射
```

| 版本行为 | 说明 |
|---------|------|
| Servlet 4.0 之前 | 映射 `/` 的缺省 Servlet 会接收 JSP 请求（JSP 优先权低于缺省） |
| **Servlet 4.0 起** | 规范修订：**JSP 请求绝不交给缺省 Servlet**，容器为 JSP 保留独立映射 |
| 5.0+ | 语义延续，Spring Boot 中 DispatcherServlet 映射 `/`，`/*.jsp` 仍走 JSP 引擎 |

> 💡 这就是 Spring Boot 中"**DispatcherServlet 映射 `/`，同时 JSP 还能用**"的规范依据——`/` 只是缺省，JSP 有自己的保留映射。静态资源由 Spring Boot 的 `ResourceHttpRequestHandler` 处理，本质是缺省 Servlet 的框架版。

## 5. 特殊映射：`/` 与空字符串

```java
@WebServlet("/")    // 缺省 Servlet：处理所有未命中请求
@WebServlet("")     // 映射到 Context Root（应用首页），仅精确匹配 "" 路径
```

| 映射 | 效果 | 典型场景 |
|------|------|---------|
| `/` | 缺省兜底 + 静态资源 | DispatcherServlet 的映射 |
| `/*` | 前缀通吃（危险） | 过滤器式 Servlet（几乎不用） |
| `""` | 仅应用根路径 | 首页 Servlet |

> ⚠️ 若把 DispatcherServlet 配成 `/*`，所有请求（含 JSP/静态资源）都进 Spring MVC，导致 404 风暴——经典配置错误。

## 6. 转发 vs 重定向深潜

### 6.1 核心区别

| 维度 | 转发 Forward | 重定向 Redirect |
|------|:---:|:---:|
| 请求次数 | **1 次**（服务器内部） | **2 次**（浏览器再发一次） |
| URL 变化 | 不变 | 变为目标地址 |
| Request 共享 | ✅ 同一个（Attribute 可传） | ❌ 新请求（数据丢失） |
| 范围 | 仅应用内 | 可跨域、可到静态页 |
| 执行位置 | 服务器端 `RequestDispatcher` | 浏览器端 3xx + Location |
| 状态码 | 200 | 302（6.1 可自定义） |
| 速度 | 快（无网络往返） | 慢（多一次 RTT） |

```java
// 转发：服务器内部接力
req.setAttribute("user", user);                       // 传对象
req.getRequestDispatcher("/user/detail").forward(req, resp);
// ⚠️ forward 后原 Servlet 的未提交响应体被清空；已 commit 的响应再 forward 抛 IllegalStateException

// 重定向：让浏览器重新请求
resp.sendRedirect("/app/user/detail");
// ⚠️ 路径必须以 / 开头才会带上 Context Path——写 "/user/detail" 会丢掉 /app！
```

### 6.2 路径解析规则（最容易错）

```java
// Forward 路径（getRequestDispatcher 参数）：
//   "/x"（以 / 开头）  → 相对于 Context Root：/app/x
//   "x"（不以 / 开头） → 相对于当前 Servlet 路径：/user/list 映射 → /user/list/x 同级

// Redirect 路径（sendRedirect 参数）：
//   "/x"    → 相对于**服务器根**（不含 Context Path！必须写全 /app/x）
//   "x"     → 相对于当前 URL 的最后一段
//   "https://..." → 完整 URL，直接跳
```

| 场景 | 推荐 |
|------|------|
| Servlet → JSP 渲染 | **Forward**（共享 Request，快） |
| 表单提交后（PRG 防重复提交） | **Redirect**（302/303） |
| 登录失败回登录页带错误信息 | **Forward**（传 Attribute） |
| 未登录跳登录页 | **Redirect**（地址栏更新） |
| 跨站跳转 | **Redirect** |
| Spring MVC 返回视图 | 内部 Forward 语义（视图渲染） |
| Spring MVC `redirect:` 前缀 | 内部 Redirect 语义 |

> 🎯 **PRG 模式（Post-Redirect-Get）**：POST 处理完 → `sendRedirect` → 浏览器 GET 结果页。刷新浏览器变成"重放 GET"而非"重放 POST"，杜绝重复下单/重复支付。这是 Web 开发防重最基础的一招。

## 7. 编码问题全解

### 7.1 编码链路

```text
GET 参数：URL 中的 query string
   → Tomcat 8+ 默认按 UTF-8 解码（URIEncoding="UTF-8"，旧版 ISO-8859-1 中文乱码根源）

POST 表单（application/x-www-form-urlencoded）：
   → 读取 body 时的解码字符集 = 当前 request 字符编码
   → 默认 ISO-8859-1！必须 setCharacterEncoding("UTF-8")

响应：
   → Content-Type 里的 charset（setCharacterEncoding 影响响应体编码）
```

### 7.2 三个铁律

```java
// 1. POST 编码：第一次 getParameter() 之前设置（惰性解析后缓存）
@WebServlet("/echo")
public class EchoServlet extends HttpServlet {
    protected void doPost(HttpServletRequest req, HttpServletResponse resp) {
        req.setCharacterEncoding("UTF-8");       // ← 必须在 getParameter 之前！
        String name = req.getParameter("name");
        resp.setContentType("text/html;charset=UTF-8");
        resp.getWriter().write(name);
    }
}

// 2. GET 编码：由容器 Connector 决定（Tomcat server.xml）
//    <Connector URIEncoding="UTF-8" />  （Tomcat 8.0+ 默认即 UTF-8，老版本要显式配）

// 3. 响应编码：setContentType("...charset=UTF-8") 或 setCharacterEncoding("UTF-8") 二选一
```

| 乱码场景 | 根因 | 解法 |
|---------|------|------|
| POST 中文乱码 | 未设置 request 编码 | `setCharacterEncoding("UTF-8")` 前置 |
| GET 中文乱码（老容器） | Connector 默认 ISO-8859-1 | `URIEncoding="UTF-8"` |
| 响应中文乱码 | 无 charset | `setContentType("text/html;charset=UTF-8")` |
| JSON 中文乱码 | 同上 | `application/json;charset=UTF-8` |
| **Filter 里统一解决** | 每 Servlet 写一遍易漏 | 编码 Filter（见 [Filter 常用场景](../Filter%20过滤器/03-常用Filter场景.md)） |

> ⚠️ **Spring Boot 时代为什么很少遇到 POST 乱码？** 因为 `CharacterEncodingFilter` 默认注册（`server.servlet.encoding` 配置），请求/响应编码默认 UTF-8——但**自定义 Servlet 且绕过了 Boot 的 Filter 配置**时，三个铁律依然适用。

## 8. multipart 请求的参数行为

| Content-Type | getParameter 可用？ | 表单字段读取 |
|--------------|:---:|------|
| `application/x-www-form-urlencoded` | ✅ | getParameter 直接读 |
| `multipart/form-data`（文件上传） | ✅（Servlet 3.0+） | 普通字段仍可用 getParameter；文件用 `Part`（见 [07-文件上传下载与PartAPI](07-文件上传下载与PartAPI.md)） |
| `application/json` | ❌（返回 null） | 必须读 InputStream 自行解析 |

```java
@MultipartConfig
@WebServlet("/upload")
public class UploadServlet extends HttpServlet {
    protected void doPost(HttpServletRequest req, HttpServletResponse resp) {
        // 普通字段照常
        String desc = req.getParameter("desc");
        // 文件字段走 Part API
        Part file = req.getPart("file");
        // 6.1 澄清：multipart 解析失败（格式损坏）→ getPart 抛 IllegalStateException
    }
}
```

> 🎯 面试题：**"JSON 请求为什么 getParameter 是 null？"**——因为 `getParameter` 只解析 `application/x-www-form-urlencoded` 与 multipart 的规范字段，JSON body 是应用层协议，必须 `getReader()`/`getInputStream()` 手动解析（Spring MVC 的 `@RequestBody` 就是这么干的）。
