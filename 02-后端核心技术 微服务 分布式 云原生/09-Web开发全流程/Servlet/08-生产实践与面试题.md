## 1. 安全清单：Servlet 层该做什么

### 1.1 响应安全头（每个响应都该有）

```java
// 在 Filter 里统一设置（见 Filter 体系）
resp.setHeader("X-Content-Type-Options", "nosniff");       // 防 MIME 嗅探
resp.setHeader("X-Frame-Options", "DENY");                 // 防点击劫持
resp.setHeader("Referrer-Policy", "strict-origin-when-cross-origin");
resp.setHeader("Content-Security-Policy", "default-src 'self'");  // 按需收紧
```

### 1.2 Cookie 与 Session 加固

```java
// Servlet 6.0 起可用通用属性 API（RFC 6265）
Cookie sessionCookie = new Cookie("JSESSIONID", id);
sessionCookie.setHttpOnly(true);          // 防脚本读取（XSS 保护）
sessionCookie.setSecure(true);            // 仅 HTTPS
sessionCookie.setAttribute("SameSite", "Lax");   // 6.0+ 官方 API，防 CSRF
sessionCookie.setAttribute("Partitioned", "");   // 可选：跨站追踪隔离
resp.addCookie(sessionCookie);

// 或全局配置：web.xml / SessionCookieConfig
sessionCookie.setPath(getServletContext().getContextPath());
```

> 💡 关于 JSESSIONID 的 `SameSite`：Servlet 6.0 的 Cookie 通用属性让 `Set-Cookie: JSESSIONID=...; SameSite=Lax` 成为规范能力——Boot 4 中 `server.servlet.session.cookie.same-site` 显式配置，详见 [Cookie & Session 体系](../Cookie%20%26%20Session（会话技术）/00-会话技术总览.md)。

### 1.3 其他安全要点

| 项 | 措施 |
|----|------|
| 错误页信息泄露 | 生产环境自定义错误页，不暴露堆栈/版本号 |
| TRACE 方法 | 容器禁用（Tomcat `allowTrace="false"`） |
| X-Powered-By | Servlet 6.0 起规范不再推荐输出，确认容器未开启 |
| 上传 | 见 [07 §7 上传安全](07-文件上传下载与PartAPI.md) |
| 会话固定攻击 | 登录成功后 `req.changeSessionId()`（可配 `HttpSessionIdListener` 记录，6.1） |
| 参数校验 | 永远在服务端校验，请求参数不可信 |
| 请求唯一 ID | 用 `getRequestId()`（6.0+）贯穿日志，替代自造 UUID |

> 🎯 **分层认知**：Servlet 层只做"传输安全"（头/Cookie/方法），业务安全（认证授权、注入防护）在上层框架与业务代码。别指望 Servlet 解决一切，也别裸奔传输层。

## 2. 性能调优

### 2.1 容器层（Tomcat server.xml）

| 参数 | 默认 | 调优建议 |
|------|:---:|---------|
| `maxThreads` | 200 | IO 密集按需调大（如 500）；CPU 密集保持接近核数×2 |
| `acceptCount` | 100 | 队列长度，太大 → 等待时间长；太小 → 直接拒绝 |
| `connectionTimeout` | 20000ms | 防慢速连接占用 |
| `maxConnections` | 8192 | 连接数上限 |
| `compression` | off | 开 `compression="on"`（文本收益明显） |
| `enableLookups` | false | 保持 false（反查 DNS 拖慢） |

### 2.2 应用层

| 优化点 | 做法 |
|--------|------|
| 无状态 Servlet | 可写成员变量清零（线程安全 + 可水平扩展） |
| 缓存头 | 静态资源加 `Cache-Control: max-age`；动态接口按需 |
| Gzip/压缩 | 容器级 compression 或 Filter 压缩 JSON |
| 连接池 | 数据库/HTTP 客户端连接池参数对齐 QPS |
| 异步 | 慢 IO 场景按 [06 §7 决策表](06-异步处理与非阻塞IO.md) 上异步或虚拟线程 |
| 大响应 | 分页/流式输出，避免大 JSON 一次性拼内存 |

> ⚠️ **先压测再调参**：JMeter 压出线程池水位与 RT 分布再动 `maxThreads`，盲目调大线程数在锁竞争场景反而更差。

## 3. Servlet 与 Spring MVC 的本质关系

```text
浏览器 ──> Tomcat ──> DispatcherServlet（一个标准 Servlet，映射 "/"）
                        │ 在 service() 里不按 HTTP 方法分发，而是：
                        │ 1. HandlerMapping：URL → 方法映射
                        │ 2. HandlerAdapter：执行 @Controller 方法
                        │ 3. HandlerExceptionResolver：异常 → 错误响应
                        │ 4. ViewResolver：逻辑视图名 → 渲染
                        ▼
                  业务代码（@Controller）
```

| 对比点 | Servlet | DispatcherServlet |
|--------|---------|-------------------|
| 定位 | 规范组件 | Servlet 的框架化实现 |
| 分发 | HTTP 方法 → doXxx | URL → HandlerMethod（方法级路由） |
| 参数绑定 | `getParameter` 手动转 | `@RequestParam`/`@RequestBody` 自动 |
| 拦截 | Filter（容器层） | Interceptor（MVC 层） |
| 注册 | @WebServlet | Spring 容器注册（见 [05 §7](05-配置方式演进与动态注册.md)） |

> 🎯 面试金句：**"Spring MVC 本质是一个扩展版 Servlet——它只是重写了分发逻辑，把'HTTP 方法分发'升级为'URL 到方法的映射'，从而让一个 Servlet 处理所有请求。"** 这就是为什么"学透 Servlet 才能真懂 Spring MVC"。

## 4. 10 大避坑清单

| # | 坑 | 现象 | 解法 |
|:---:|----|------|------|
| 1 | 覆盖 `init(ServletConfig)` 不调 super | `getServletConfig()` NPE | 只覆盖无参 `init()` |
| 2 | 覆盖 `service()` | 分发失效，全部进自定义逻辑 | 只覆盖 doXxx |
| 3 | 可写成员变量 | 并发数据错乱 | 无状态 + ThreadLocal（记得 remove） |
| 4 | `sendRedirect("/x")` 丢 Context Path | 404 | 写全 `/app/x` |
| 5 | `getParameter` 前未设编码 | POST 中文乱码 | `setCharacterEncoding("UTF-8")` 前置 |
| 6 | `/*` 映射 | JSP/静态资源 404 | 用 `/` 或精确路径 |
| 7 | Boot 里 @WebServlet 没扫到 | 静默不生效 | 加 `@ServletComponentScan` |
| 8 | 异步不 complete | 连接泄漏 | complete/dispatch 兜底 + 超时 |
| 9 | 直接写 `getSubmittedFileName()` | 路径穿越 | 消毒 + UUID 重命名 |
| 10 | 注册时机过期后 addServlet | IllegalStateException | 启动阶段完成注册 |
| 11 | 上传不设 maxFileSize | 内存/磁盘被打爆 | @MultipartConfig 限大小 |
| 12 | 信任 Content-Type 做校验 | 伪装文件绕过 | 魔数校验 + 白名单扩展名 |

## 5. 高频面试题

### Q1：Servlet 生命周期？
> 加载 → 实例化（无参构造，1 次）→ `init()`（1 次，可覆盖无参版做资源初始化）→ `service()`（N 次，按 HTTP 方法分发到 doXxx）→ `destroy()`（1 次）。注意：懒加载默认，`load-on-startup` 可提前；init/destroy 单线程，service 多线程并发。

### Q2：Servlet 线程安全吗？
> 默认不安全。单实例多线程模型：可写成员变量被所有请求共享，有竞态。黄金标准是**无状态 Servlet**；需要线程级数据用 ThreadLocal（必须 remove）；SingleThreadModel 已死（6.0 从 API 移除）。

### Q3：Forward 和 Redirect 的区别？
> Forward：服务器内部、1 次请求、URL 不变、共享 Request（可传 Attribute）、只能应用内。Redirect：浏览器再发请求、2 次、URL 变化、数据丢失、可跨域。表单提交后用 Redirect（PRG 防重复提交）；传数据渲染用 Forward。6.1 起 Redirect 可自定义状态码（301/303/307）。

### Q4：URL 映射规则与优先级？
> 精确匹配 > 最长路径前缀（`/user/*`）> 扩展名（`*.do`）> 缺省（`/`）。前缀与扩展名不能共存于一个映射。`/` 是缺省 Servlet（兜底+静态资源）；`/*` 是前缀通吃（危险）。

### Q5：`/` 和 `/*` 有什么区别？
> `/`：缺省 Servlet，只处理未被其他映射命中的请求（含静态资源，4.0 起不接 JSP）；`/*`：前缀匹配，拦截一切请求（含 JSP/静态），映射到 `/*` 基本等于接管所有流量。DispatcherServlet 用 `/`，配成 `/*` 是经典错误。

### Q6：Servlet 与 Spring MVC 的关系？
> DispatcherServlet 是一个标准 Servlet（映射 `/`），它重写了分发逻辑：不按 HTTP 方法分发，而是用 HandlerMapping 把 URL 映射到 Controller 方法。**Spring MVC 的一切能力都是在一个 Servlet 内部实现的**。

### Q7：如何动态注册 Servlet？（3.0 SPI）
> 三个途径：注解 @WebServlet（扫描）；ServletContainerInitializer（`META-INF/services` SPI + `@HandlesTypes` 筛选 + `onStartup` 回调）；web-fragment（jar 内迷你 web.xml）。Spring Boot 的 `ServletRegistrationBean` 是第三条的封装。注意注册窗口期（启动阶段）。

### Q8：Servlet 异步处理是什么？怎么用？
> `startAsync()` 把请求标记为异步，容器线程立即返回；业务在自建线程池执行，完成后 `complete()` 或 `dispatch()`。用于慢 IO（外部 API/长轮询/SSE）。必须 `asyncSupported=true`、设置超时、保证 complete 兜底。虚拟线程（JDK 21+/Tomcat 11）是它的简化替代。

### Q9：POST 请求 getParameter 为什么拿到 null？
> 三种情况：① body 是 JSON（只解析表单编码与 multipart 的字段，JSON 必须读流）；② multipart 中该字段是文件（Part API）；③ 参数名拼错。对应解法：读 `getReader()` 解析 / `getPart()` / 核对表单 name。

### Q10：中文乱码怎么排查？
> 看编码在哪丢的：POST 参数（request 编码需先设 UTF-8）、GET 参数（容器 URIEncoding）、响应（charset 需声明）、数据库连接（JDBC URL 编码参数）。统一编码 Filter + 全链路 UTF-8 是根治方案。

### Q11：Session 和 Cookie 在 Servlet 里怎么协同？
> 首次访问 `req.getSession()` → 容器生成 JSESSIONID → Set-Cookie 下发 → 后续请求带 Cookie → 容器据 ID 找到 Session（URL 重写是兜底）。Servlet 6.1 的 `HttpSessionIdListener` 可监听 ID 轮换（防固定攻击）。详见 [Cookie & Session 体系](../Cookie%20%26%20Session（会话技术）/00-会话技术总览.md)。

### Q12：Servlet 6.0/6.1 有什么新东西？（差异化加分）
> 6.0：Java 11 基线、Cookie RFC 6265 + 通用属性（SameSite）、请求唯一 ID（`getRequestId`）、移除 SingleThreadModel/HttpUtils、X-Powered-By 去推荐。6.1：重定向状态码控制（`sendRedirect(location, sc, clearBuffer)`）、ByteBuffer IO、`HttpSessionIdListener`、错误分发携带 query string、`getParameter` 解析失败抛 ISE、SecurityManager 移除、HTTP/2 push 废弃。
