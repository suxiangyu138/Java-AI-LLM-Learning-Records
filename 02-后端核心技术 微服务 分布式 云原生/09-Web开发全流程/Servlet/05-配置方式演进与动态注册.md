## 1. 四种配置方式总览

```text
配置方式演进（Servlet 3.0 为分水岭）：
 web.xml（2.x，声明式） ──> 注解（3.0，零 XML） ──> SCI（3.0，编程式/SPI）
                                                        └──> Spring Boot 封装（framework 层）
```

| 方式 | 引入版本 | 特点 | 当前定位 |
|------|:---:|------|---------|
| web.xml | 1.0 | 集中声明，元数据完整 | 全局配置（欢迎页/错误页/安全）仍用它 |
| 注解 @WebServlet | 3.0 | 就近声明，类与配置同文件 | 简单场景首选 |
| SCI 编程式 | 3.0 | 动态、可条件化、**第三方库注册入口** | 框架层唯一选择（Spring 靠它） |
| web-fragment | 3.0 | jar 内声明，插件化 | 组件库用，应用内少用 |

> 🎯 一句话：**应用自己的 Servlet 用注解；框架/组件给别人用的 Servlet 用 SCI**；web.xml 退居"全局元数据"；Spring Boot 把 SCI 机制封装成 `ServletRegistrationBean`。

## 2. web.xml 声明式配置

### 2.1 标准结构（Servlet 6.x）

```xml
<?xml version="1.0" encoding="UTF-8"?>
<web-app xmlns="https://jakarta.ee/xml/ns/jakartaee"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="https://jakarta.ee/xml/ns/jakartaee
                             https://jakarta.ee/xml/ns/jakartaee/web-app_6_0.xsd"
         version="6.0">

    <display-name>MyApp</display-name>

    <!-- 全局参数：ServletContext.getInitParameter() -->
    <context-param>
        <param-name>appName</param-name>
        <param-value>my-app</param-value>
    </context-param>

    <!-- Servlet 声明 -->
    <servlet>
        <servlet-name>UserServlet</servlet-name>
        <servlet-class>com.demo.UserServlet</servlet-class>
        <init-param>
            <param-name>encoding</param-name>
            <param-value>UTF-8</param-value>
        </init-param>
        <load-on-startup>1</load-on-startup>
    </servlet>
    <servlet-mapping>
        <servlet-name>UserServlet</servlet-name>
        <url-pattern>/user/*</url-pattern>
    </servlet-mapping>

    <!-- 错误页：状态码/异常 → 资源 -->
    <error-page>
        <error-code>404</error-code>
        <location>/error/404.html</location>
    </error-page>
    <error-page>
        <exception-type>java.lang.RuntimeException</exception-type>
        <location>/error/exception.jsp</location>
    </error-page>

    <!-- 会话超时（分钟） -->
    <session-config>
        <session-timeout>30</session-timeout>
    </session-config>

    <!-- 声明式安全（容器级认证授权） -->
    <security-constraint>
        <web-resource-collection>
            <web-resource-name>admin</web-resource-name>
            <url-pattern>/admin/*</url-pattern>
        </web-resource-collection>
        <auth-constraint><role-name>admin</role-name></auth-constraint>
    </security-constraint>
    <login-config>
        <auth-method>FORM</auth-method>
    </login-config>
</web-app>
```

> 💡 错误页机制值得记住：状态码 404/500 或指定异常触发时，容器**内部转发**到 `<location>`（`dispatcherType=ERROR`），请求属性 `jakarta.servlet.error.status_code` 等携带错误上下文；6.1 起还多了 `ERROR_QUERY_STRING`。

## 3. 注解配置与扫描机制

### 3.1 常用注解

```java
@WebServlet(
    name = "UserServlet",
    urlPatterns = {"/user", "/member"},   // 等价 value，二者不能同时写
    initParams = @WebInitParam(name = "encoding", value = "UTF-8"),
    loadOnStartup = 1,
    asyncSupported = true
)
public class UserServlet extends HttpServlet { }

@WebFilter(urlPatterns = "/*", filterName = "auth")
public class AuthFilter implements Filter { }

@WebListener
public class AppListener implements ServletContextListener { }

@WebInitParam(name = "pageSize", value = "20")   // 初始化参数注解
```

### 3.2 扫描机制与 metadata-complete

```text
容器启动时：
1. 扫描 Web 应用的 WEB-INF/classes 与 WEB-INF/lib 下所有 .class
2. 检查字节码注解（@WebServlet/@WebFilter/@WebListener/@WebInitParam）
3. 有注解的类 → 注册到 ServletContext
4. 扫描顺序：web.xml > web-fragment（按 jar 名排序）> 注解，后者的配置合并前者
```

| 开关 | 效果 |
|------|------|
| `<web-app metadata-complete="true">` | **跳过全量注解扫描**，启动更快；注解全部失效（必须走 web.xml） |
| `<absolute-ordering>` | 指定 web-fragment 的加载顺序 |
| `<ordering>` | web-fragment 内的相对排序 |

> ⚠️ 性能坑：大应用（几百 MB class）启动时注解扫描耗时明显；如果全部走 web.xml/编程式注册，设 `metadata-complete="true"` 可显著提速。

## 4. ServletContainerInitializer 编程式注册

### 4.1 机制：SPI + 回调

```text
容器启动 → 读取 META-INF/services/jakarta.servlet.ServletContainerInitializer
        → 实例化所有 SCI → 调用 onStartup(classes, ServletContext)
```

```java
// 1. 编写 SCI（放在第三方 jar 里）
@HandlesTypes({MyServlet.class})          // 筛选关注的类型（可空）
public class MyInitializer implements ServletContainerInitializer {

    @Override
    public void onStartup(Set<Class<?>> classes, ServletContext ctx) {
        // classes：应用里所有被 @HandlesTypes 选中的类（含子类/实现类）
        // 条件化注册：只有业务类存在才注册对应 Servlet
        if (classes != null && !classes.isEmpty()) {
            ServletRegistration.Dynamic reg = ctx.addServlet("my", MyServlet.class);
            reg.addMapping("/my/*");
            reg.setLoadOnStartup(1);
        }
    }
}
```

```text
// 2. 声明 SPI：META-INF/services/jakarta.servlet.ServletContainerInitializer
//    文件内容一行：
com.demo.MyInitializer
```

> 🎯 **为什么这是框架层的命根子？** Spring 的 `SpringServletContainerInitializer`（处理 `WebApplicationInitializer`）正是靠它注册 DispatcherServlet 与 ContextLoaderListener——**Spring MVC 不写一行 web.xml 的底层机制就是它**。Spring Boot 内嵌容器同样遵循该 SPI。

### 4.2 @HandlesTypes 与热插拔

| 场景 | 用法 |
|------|------|
| 容器里有某接口的实现类 → 注册对应 Servlet | `@HandlesTypes(ServiceInterface.class)` |
| 无条件注册 | 不写 @HandlesTypes |
| 与 web-fragment 搭配 | 插件 jar 自带 SCI + fragment，一 jar 即插即用 |

## 5. web-fragment.xml 与插件化

```xml
<!-- 第三方组件 jar 的 META-INF/web-fragment.xml -->
<web-fragment xmlns="https://jakarta.ee/xml/ns/jakartaee"
              version="6.0">
    <name>log-plugin</name>
    <servlet>
        <servlet-name>LogServlet</servlet-name>
        <servlet-class>com.log.LogServlet</servlet-class>
    </servlet>
    <servlet-mapping>
        <servlet-name>LogServlet</servlet-name>
        <url-pattern>/log/*</url-pattern>
    </servlet-mapping>
    <ordering>
        <after><name>security-plugin</name></after>
    </ordering>
</web-fragment>
```

> 💡 web-fragment = **jar 包自带的迷你 web.xml**：组件作者把 Servlet/Filter/Listener 声明写进 jar，应用引入依赖即自动生效。这是"自动配置"思想的规范源头——Spring Boot 的 AutoConfiguration 是它的框架级继承者。

## 6. 动态注册 API 详解

### 6.1 ServletContext 注册三件套

```java
ServletRegistration.Dynamic reg = ctx.addServlet("name", ServletClass.class);
// 或 ctx.addServlet("name", "com.demo.XServlet")（按类名，可延迟加载）
// 或 ctx.addJspFile("jspServlet", "/index.jsp")   // 将 JSP 注册为 Servlet（6.0+）

reg.addMapping("/a", "/b");        // 映射（可多个）
reg.setLoadOnStartup(1);
reg.setInitParameter("k", "v");
reg.setAsyncSupported(true);
reg.setMultipartConfig(new MultipartConfigElement("/tmp", 10*1024*1024, 50*1024*1024, 1024*1024));

FilterRegistration.Dynamic f = ctx.addFilter("auth", AuthFilter.class);
f.addMappingForUrlPatterns(EnumSet.of(DispatcherType.REQUEST), true, "/admin/*");

ctx.addListener(MyListener.class);
```

| API | 用途 |
|-----|------|
| `addServlet/addFilter/addListener` | 三种组件统一入口 |
| `Dynamic` 对象 | 返回的注册对象，链式配置 |
| `addMappingForUrlPatterns(types, isMatchAfter, patterns)` | 控制 Filter 顺序（isMatchAfter=false 排前面） |
| `setMultipartConfig` | 编程式 @MultipartConfig 等效 |
| `getServletRegistration("name")` | 获取已注册对象修改 |

### 6.2 注册时机限制

> ⚠️ **注册窗口期**：动态注册只能在容器**启动阶段**（Context 初始化完成前）调用——`ServletContextListener.contextInitialized()` 之后调用 `addServlet` 会抛 `IllegalStateException`。异步运行时注册是反模式。

## 7. Spring Boot 中的 Servlet 注册

### 7.1 三条路径

```java
// ═══ 路径一：ServletRegistrationBean（推荐，Boot 风格）═══
@Configuration
public class WebConfig {
    @Bean
    public ServletRegistrationBean<UserServlet> userServlet() {
        ServletRegistrationBean<UserServlet> bean =
            new ServletRegistrationBean<>(new UserServlet(), "/user/*");
        bean.setLoadOnStartup(1);
        bean.addInitParameter("encoding", "UTF-8");
        return bean;   // 可设置 order 控制注册顺序
    }
}

// ═══ 路径二：@WebServlet + @ServletComponentScan（注解扫描）═══
@ServletComponentScan(basePackages = "com.demo.servlet")
@SpringBootApplication
public class App { }   // 扫描 @WebServlet/@WebFilter/@WebListener

// ═══ 路径三：ServletContextInitializer（模仿 SCI）═══
@Bean
public ServletContextInitializer myInitializer() {
    return ctx -> {
        ServletRegistration.Dynamic reg = ctx.addServlet("x", XServlet.class);
        reg.addMapping("/x");
    };
}
```

### 7.2 启动时序：Boot 如何把 Servlet 塞进 Tomcat

```text
SpringApplication.run()
 → 创建内嵌 Tomcat（ServletWebServerFactory → TomcatServletWebServerFactory）
 → TomcatStarter（实现 ServletContainerInitializer）onStartup
    → 收集所有 ServletContextInitializer Bean（ServletRegistrationBean 等）
    → 逐个调用 onStartup(servletContext)：注册 Servlet/Filter/Listener
 → 初始化 DispatcherServlet（DispatcherServletRegistrationBean，映射 "/"）
 → server 启动，端口监听
```

| 组件 | 注册的东西 |
|------|-----------|
| `DispatcherServletRegistrationBean` | DispatcherServlet，映射 `/` |
| `CharacterEncodingFilterRegistrationBean` | UTF-8 编码 Filter（`server.servlet.encoding`） |
| `ErrorPageServletRegistrationBean` | `/error` 全局错误页 |
| 业务 `ServletRegistrationBean` | 用户自建 Servlet |
| 内嵌 Tomcat | Tomcat 10.1（Boot 3.x，Servlet 6.0）；可换 Tomcat 11（Servlet 6.1）或 Jetty/Undertow |

> 🎯 **本质认知**：Spring Boot 的 `@SpringBootApplication` 里没有任何魔法——Servlet 注册全走"`ServletContextInitializer` Bean 收集 → TomcatStarter 回调"这条标准 Servlet 3.0 路径。理解 SCI 机制就能解释 Boot 的启动时序。

## 8. 选型对比与避坑

| 场景 | 推荐方式 | 原因 |
|------|---------|------|
| 应用内简单 Servlet | @WebServlet | 就近声明，无 XML |
| 需要统一元数据（错误页/安全/欢迎页） | web.xml | 注解无对应能力 |
| 第三方框架注册组件 | SCI | 无法控制业务源码 |
| Boot 应用注册第三方 Servlet | ServletRegistrationBean | 可注入、可排序 |
| 追求启动速度 | metadata-complete + 编程式 | 跳过扫描 |
| Filter 顺序控制 | FilterRegistrationBean（Boot）/ `isMatchAfter` | 注解无法表达顺序 |

| 避坑 | 说明 |
|------|------|
| `urlPatterns` 与 `value` 同写 | 部署报错（二选一） |
| 注册时机过期 | contextInitialized 后动态 addServlet → IllegalStateException |
| `/*` 映射 | 吞掉所有请求含 JSP/静态资源 |
| Boot 里 @WebServlet 没加 @ServletComponentScan | 静默不生效（最常见坑） |
| metadata-complete=true 但用了注解 | 注解全部失效，看似"Servlet 不见了" |
| jar 里 `META-INF/web-fragment.xml` 冲突 | absolute-ordering 显式排序 |
