## 1. 聚合分类总览

### 1.1 分类结构

```text
ES Aggregation
├── Metric（指标聚合）      → 计算统计值
│   ├── avg / sum / min / max
│   ├── stats / extended_stats
│   ├── cardinality         → 去重计数（类似 COUNT DISTINCT）
│   └── value_count         → 计数
├── Bucket（桶聚合）         → 分组
│   ├── terms               → 按字段值分组
│   ├── range               → 按数值范围分组
│   ├── date_histogram      → 按时间分组
│   ├── histogram           → 按直方图分组
│   └── filter / filters    → 按条件分组
├── Pipeline（管道聚合）     → 对聚合结果再计算
│   ├── avg_bucket / max_bucket
│   └── cumulative_sum / derivative / moving_fn
└── Matrix（矩阵聚合）       → 多字段交叉分析（较少用）
```

### 1.2 聚合与 SQL 类比

| 聚合类型 | 类似 SQL | 说明 |
|---------|----------|------|
| `terms` | `GROUP BY field` | 按字段值分组 |
| `avg` / `sum` / `min` / `max` | `AVG()` / `SUM()` / `MIN()` / `MAX()` | 指标计算 |
| `stats` | `COUNT()` + 上述全部 | 一键五值统计 |
| `cardinality` | `COUNT(DISTINCT field)` | 近似去重计数 |
| `date_histogram` | `GROUP BY DATE_TRUNC()` | 按时间窗口分组 |
| `range` | `CASE WHEN ... THEN ... END` | 按自定义范围分组 |

> 💡 聚合计算依赖 Doc Values（列式存储），只读取聚合相关字段，不加载整行数据，这是 ES 聚合性能优异的核心原因。

## 2. Metric 指标聚合

### 2.1 基础统计

```json
GET /orders/_search
{
  "size": 0,
  "aggs": {
    "total_amount":  { "sum": { "field": "amount" } },
    "avg_amount":    { "avg": { "field": "amount" } },
    "max_amount":    { "max": { "field": "amount" } },
    "min_amount":    { "min": { "field": "amount" } },
    "order_count":   { "value_count": { "field": "order_id" } }
  }
}
```

返回：

```json
{
  "aggregations": {
    "total_amount": { "value": 5000000.0 },
    "avg_amount":   { "value": 250.5 },
    "max_amount":   { "value": 9999.0 },
    "min_amount":   { "value": 1.0 },
    "order_count":  { "value": 20000 }
  }
}
```

### 2.2 stats（一键统计）

```json
GET /orders/_search
{
  "size": 0,
  "aggs": {
    "amount_stats": { "stats": { "field": "amount" } }
  }
}
// 返回：count, min, max, avg, sum 五个值
```

### 2.3 extended_stats（扩展统计）

```json
GET /orders/_search
{
  "size": 0,
  "aggs": {
    "extended_stats": {
      "extended_stats": { "field": "amount" }
    }
  }
}
// 额外返回：sum_of_squares, variance, std_deviation, std_deviation_bounds
```

### 2.4 cardinality（去重计数）

```json
GET /orders/_search
{
  "size": 0,
  "aggs": {
    "unique_users": {
      "cardinality": {
        "field": "user_id",
        "precision_threshold": 40000
      }
    }
  }
}
```

| 特性 | 说明 |
|------|------|
| 算法 | HyperLogLog（HLL）近似算法 |
| 精确度 | 默认误差约 1-5% |
| precision_threshold | 默认 3000，最大 40000 |
| 内存消耗 | 极低（KB 级） |
| 适用场景 | 百万级以上的 COUNT DISTINCT |

### 2.5 Metric 聚合对照表

| 聚合 | 类似 SQL | 说明 |
|------|----------|------|
| `avg` | `AVG()` | 平均值 |
| `sum` | `SUM()` | 求和 |
| `min` / `max` | `MIN()` / `MAX()` | 最小值 / 最大值 |
| `stats` | 以上全部 | 一键五值 |
| `value_count` | `COUNT(field)` | 非空计数 |
| `cardinality` | `COUNT(DISTINCT)` | 近似去重计数 |
| `extended_stats` | — | 含方差、标准差 |

## 3. Bucket 桶聚合

### 3.1 terms 分组统计

```json
GET /orders/_search
{
  "size": 0,
  "aggs": {
    "by_category": {
      "terms": {
        "field": "category",
        "size": 10,
        "order": { "_count": "desc" },
        "shard_size": 100
      },
      "aggs": {
        "avg_amount": { "avg": { "field": "amount" } },
        "total_amount": { "sum": { "field": "amount" } }
      }
    }
  }
}
```

对应 SQL：`SELECT category, COUNT(*), AVG(amount), SUM(amount) FROM orders GROUP BY category`

**terms 关键参数**：

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `size` | 返回的桶数量 | 10 |
| `shard_size` | 每个分片返回的桶数（调大可提高精度） | size * 2 |
| `order` | 排序方式，支持 `_count`、`_key`、子聚合 | `_count: desc` |
| `min_doc_count` | 最小文档数，过滤低频桶 | 1 |
| `missing` | 处理空值时的替代值 | — |

### 3.2 range 范围分组

```json
GET /orders/_search
{
  "size": 0,
  "aggs": {
    "price_ranges": {
      "range": {
        "field": "amount",
        "ranges": [
          { "key": "0-100",   "from": 0,    "to": 100 },
          { "key": "100-500", "from": 100,  "to": 500 },
          { "key": "500-1000","from": 500,  "to": 1000 },
          { "key": "1000+",   "from": 1000 }
        ]
      }
    }
  }
}
```

### 3.3 date_histogram 时间直方图

```json
GET /orders/_search
{
  "size": 0,
  "aggs": {
    "sales_over_time": {
      "date_histogram": {
        "field": "create_time",
        "calendar_interval": "day",
        "format": "yyyy-MM-dd",
        "min_doc_count": 0,
        "extended_bounds": { "min": "2024-01-01", "max": "2024-01-31" }
      },
      "aggs": {
        "daily_total": { "sum": { "field": "amount" } }
      }
    }
  }
}
```

**间隔选项**：

| 参数 | 说明 | 示例 |
|------|------|------|
| `calendar_interval` | 日历感知间隔 | minute, hour, day, week, month, quarter, year |
| `fixed_interval` | 固定间隔 | 1s, 1m, 1h, 1d |
| `extended_bounds` | 强制覆盖日期范围 | — |
| `min_doc_count` | 最小文档数（设为 0 可显示空桶）| 1 |

### 3.4 histogram 数值直方图

```json
GET /orders/_search
{
  "size": 0,
  "aggs": {
    "price_histogram": {
      "histogram": {
        "field": "price",
        "interval": 500,
        "min_doc_count": 1
      }
    }
  }
}
```

### 3.5 filter / filters 条件分组

```json
GET /orders/_search
{
  "size": 0,
  "aggs": {
    "high_value_orders": {
      "filter": { "range": { "amount": { "gte": 1000 } } },
      "aggs": { "avg_amount": { "avg": { "field": "amount" } } }
    }
  }
}

// filters 同时多条件
GET /orders/_search
{
  "size": 0,
  "aggs": {
    "order_tiers": {
      "filters": {
        "filters": {
          "high": { "range": { "amount": { "gte": 1000 } } },
          "mid":  { "range": { "amount": { "gte": 500, "lt": 1000 } } },
          "low":  { "range": { "amount": { "lt": 500 } } }
        }
      }
    }
  }
}
```

### 3.6 Bucket 聚合汇总

| 聚合 | SQL 类比 | 适用场景 |
|------|----------|---------|
| `terms` | `GROUP BY col` | 分类统计、品牌聚合 |
| `range` | `CASE WHEN ... GROUP BY` | 价格区间、年龄分段 |
| `date_histogram` | `GROUP BY DATE_TRUNC()` | 日报、月报趋势 |
| `histogram` | 等宽直方图 | 数值分布分析 |
| `filter` | `WHERE` + 子查询 | 条件独立的子统计 |
| `filters` | 多个 `WHERE` 并排 | 多条件对比 |

## 4. 嵌套聚合

### 4.1 多级下钻

聚合可以嵌套任意层次：

```json
GET /orders/_search
{
  "size": 0,
  "aggs": {
    "by_category": {
      "terms": { "field": "category", "size": 10 },
      "aggs": {
        "by_brand": {
          "terms": { "field": "brand", "size": 5 },
          "aggs": {
            "by_status": {
              "terms": { "field": "status", "size": 3 },
              "aggs": {
                "stats": { "stats": { "field": "amount" } }
              }
            }
          }
        }
      }
    }
  }
}
```

数据模型：分类 → 品牌 → 订单状态 → 统计指标（四级下钻）。

### 4.2 实战：电商聚合筛选

商品搜索页的"聚合筛选"是 ES 聚合最经典的实战场景：

```json
GET /goods/_search
{
  "size": 20,
  "query": {
    "bool": {
      "must": [{ "match": { "title": "手机" } }],
      "filter": [{ "term": { "is_on_sale": true } }]
    }
  },
  "aggs": {
    "by_category": {
      "terms": { "field": "category", "size": 20 }
    },
    "by_brand": {
      "terms": { "field": "brand", "size": 50 }
    },
    "price_range": {
      "range": {
        "field": "price",
        "ranges": [
          { "from": 0,    "to": 1000 },
          { "from": 1000, "to": 3000 },
          { "from": 3000, "to": 5000 },
          { "from": 5000 }
        ]
      }
    }
  }
}
```

一次查询返回：搜索商品列表 + 分类分布 + 品牌分布 + 价格区间分布。

### 4.3 嵌套聚合性能考虑

| 因素 | 影响 | 建议 |
|------|------|------|
| 嵌套深度 | 每层增加内存和 CPU 消耗 | 控制在 3 层以内 |
| 桶数量 | 桶越多，协调节点归并压力越大 | terms 的 size 不要过大 |
| 父级桶数 | 子聚合在父级每个桶内都执行 | 父级 terms 的 size 调小 |

## 5. Pipeline 管道聚合

Pipeline 聚合对其他聚合的输出结果进行二次计算。

### 5.1 父级 Pipeline

```json
GET /orders/_search
{
  "size": 0,
  "aggs": {
    "sales_per_month": {
      "date_histogram": {
        "field": "create_time",
        "calendar_interval": "month"
      },
      "aggs": {
        "total": { "sum": { "field": "amount" } }
      }
    },
    "avg_monthly_sales": {
      "avg_bucket": {
        "buckets_path": "sales_per_month>total"
      }
    },
    "max_monthly_sales": {
      "max_bucket": {
        "buckets_path": "sales_per_month>total"
      }
    },
    "total_yearly_sales": {
      "sum_bucket": {
        "buckets_path": "sales_per_month>total"
      }
    }
  }
}
```

### 5.2 同级 Pipeline

```json
GET /orders/_search
{
  "size": 0,
  "aggs": {
    "daily_sales": {
      "date_histogram": { "field": "create_time", "fixed_interval": "1d" },
      "aggs": {
        "daily_revenue": { "sum": { "field": "amount" } },
        "cumulative_revenue": {
          "cumulative_sum": { "buckets_path": "daily_revenue" }
        },
        "revenue_change": {
          "derivative": { "buckets_path": "daily_revenue" }
        },
        "moving_avg": {
          "moving_fn": {
            "buckets_path": "daily_revenue",
            "window": 3,
            "script": "MovingFunctions.unweightedAvg(values)"
          }
        }
      }
    }
  }
}
```

### Pipeline 聚合汇总

| Pipeline 聚合 | 类型 | 说明 |
|---------------|------|------|
| `avg_bucket` | 父级 | 所有桶的平均值 |
| `max_bucket` / `min_bucket` | 父级 | 最大 / 最小桶 |
| `sum_bucket` | 父级 | 所有桶求和 |
| `stats_bucket` | 父级 | 桶的统计信息 |
| `cumulative_sum` | 同级 | 累计求和 |
| `derivative` | 同级 | 导数（变化率）|
| `moving_fn` | 同级 | 移动窗口计算 |
| `percentiles_bucket` | 父级 | 桶的百分位数 |

## 6. 聚合实战场景

### 6.1 电商后台数据看板

```json
GET /orders/_search
{
  "size": 0,
  "query": { "range": { "create_time": { "gte": "now-7d" } } },
  "aggs": {
    "daily_revenue": {
      "date_histogram": {
        "field": "create_time", "calendar_interval": "day"
      },
      "aggs": {
        "revenue": { "sum": { "field": "amount" } },
        "orders": { "value_count": { "field": "order_id" } },
        "unique_customers": { "cardinality": { "field": "user_id" } }
      }
    },
    "top_category": {
      "terms": { "field": "category", "size": 10 },
      "aggs": { "revenue": { "sum": { "field": "amount" } } }
    },
    "avg_order_value": { "avg": { "field": "amount" } }
  }
}
```

### 6.2 日志聚合统计

```json
GET /app-logs-*/_search
{
  "size": 0,
  "query": { "range": { "@timestamp": { "gte": "now-24h" } } },
  "aggs": {
    "error_count_by_service": {
      "terms": { "field": "service_name.keyword", "size": 20 },
      "aggs": {
        "error_only": {
          "filter": { "term": { "level.keyword": "ERROR" } },
          "aggs": { "error_count": { "value_count": { "field": "message.keyword" } } }
        }
      }
    },
    "requests_per_hour": {
      "date_histogram": { "field": "@timestamp", "fixed_interval": "1h" }
    }
  }
}
```

### 6.3 聚合场景汇总

| 业务场景 | 聚合类型 | 说明 |
|---------|---------|------|
| 数据看板 | multi_metric + date_histogram | 每日收入、订单数、独立客户 |
| 商品筛选栏 | terms + range | 品牌、分类、价格区间分布 |
| 销售报表 | date_histogram + pipeline | 月度销售趋势、环比变化 |
| 用户画像 | terms + cardinality | 用户行为标签分布 |
| 日志监控 | date_histogram + filter | 每小时错误数、按服务聚合 |
| 异常检测 | moving_fn + derivative | 指标突增/突降告警 |

## 7. 聚合性能优化

### 7.1 优化原则

| 优化手段 | 说明 |
|----------|------|
| `size: 0` | 不返回文档，只返回聚合结果，省带宽 |
| 限制 terms 的 size | 返回 Top N 即可，不需要全部桶 |
| keyword 字段聚合 | text 字段聚合会报错，需用 `.keyword` |
| `execution_hint: map` | 数据量小时提升速度 |
| 近似聚合 | cardinality 比精确去重快 100 倍以上 |
| Doc Values | 聚合依赖 Doc Values，默认开启 |
| 合理分片数 | 分片过多增加合并开销 |

### 7.2 shard_size 调优

```json
{
  "aggs": {
    "by_category": {
      "terms": {
        "field": "category",
        "size": 10,
        "shard_size": 100
      }
    }
  }
}
```

| size | shard_size | 精度 | 性能 |
|:----:|:----------:|:----:|:----:|
| 10 | 默认 (20) | 较低 | 快 |
| 10 | 100 | 较高 | 中 |
| 10 | 1000 | 最高 | 慢 |

### 7.3 性能陷阱

| 陷阱 | 后果 | 解决方案 |
|------|------|----------|
| text 字段聚合 | 报错 | 用 `.keyword` 子字段 |
| 超大规模 terms | OOM | 限制 size，开启 `execution_hint: map` |
| 时间粒度过细 | 桶数量爆炸 | 根据时间跨度选择合适的 interval |
| 嵌套过深 | GC 压力大 | 控制在 3 层以内 |
| cardinality 用于精确去重 | 不准确 | 用 scripted_metric 或外部计算 |

## 8. 面试核心要点

**Q: ES 聚合类比 SQL 的哪些能力？**

terms = GROUP BY，avg/sum/min/max = 聚合函数，date_histogram = 按时间分组统计，cardinality = COUNT DISTINCT，range = CASE WHEN GROUP BY。

**Q: size: 0 的作用？**

告诉 ES 不需要返回搜索命中的文档列表，只返回聚合结果，省带宽和省内存。

**Q: terms 聚合结果不精确怎么办？**

调大 `shard_size` 参数。terms 聚合默认每个分片返回 `size * 2` 条候选桶，`shard_size` 调大后每个分片返回更多候选，协调节点合并后的结果更精确。

**Q: 聚合为什么比 MySQL GROUP BY 快？**

ES 使用 Doc Values（列式存储），聚合时只读取相关列数据，不加载整行。且分布式场景下各分片并行计算后归并，天然支持水平扩展。

**Q: cardinality 为什么快？**

基于 HyperLogLog 近似算法，用极小的内存（KB 级）估算亿级数据的不同值数量，不需要真正去重。

> 🎯 **总结**：Metric 算指标，Bucket 做分组，Pipeline 再计算，嵌套下钻多维度分析。核心优势是列式存储 + 分布式并行计算。
