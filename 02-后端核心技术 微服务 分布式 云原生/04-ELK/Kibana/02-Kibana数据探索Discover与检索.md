## 1. Discover 界面总览

### 1.1 界面区域

```text
┌────────────────────────────────────────────────────┐
│ 搜索栏（KQL / ES|QL 切换）     时间范围选择器   刷新 │
├───────────────┬────────────────────────────────────┤
│ 字段列表       │  文档列表                          │
│ · 可用字段     │  · 时间柱状图（命中数分布）        │
│ · 已选字段     │  · 每条文档的关键字段表格          │
│ · 搜索字段     │  · 点击展开 JSON 详情              │
└───────────────┴────────────────────────────────────┘
```

| 区域 | 作用 |
|------|------|
| 搜索栏 | 输入 KQL/DSL/ES|QL，决定「查什么」 |
| 时间选择器 | 决定「查哪个时间段」 |
| 字段列表 | 选择展示哪些字段、排序 |
| 时间柱状图 | 命中数量随时间分布（快速定位峰值） |
| 文档列表 | 命中结果表格，可展开详情 |

### 1.2 选择数据视图（9.x）

| 概念 | 说明 |
|------|------|
| Data View（数据视图） | 指向一个或多个索引（如 `logstash-*`） |
| 通配符 | `logs-*`、`nginx-access-2026.08.*` |
| 创建入口 | 管理 → Data Views → 创建 |
| 时间字段 | 必须指定（如 `@timestamp`）才支持时间范围过滤 |

> ⚠️ 常见坑：数据视图的时间字段配置错误（选错字段或未配置）会导致 Discover 显示「No results」——先检查数据视图时间字段。

## 2. KQL：Kibana 查询语言

### 2.1 KQL 基础语法

| 语法 | 示例 | 含义 |
|------|------|------|
| 字段等于 | `status: "200"` | status 字段等于 200 |
| 逻辑与 | `status: 200 AND url: "/api"` | 两个条件都满足 |
| 逻辑或 | `status: 400 OR status: 500` | 任一满足 |
| 取反 | `NOT status: 200` | 不等于 |
| 括号分组 | `(status: 200 OR status: 404) AND path: "api"` | 优先级控制 |
| 存在性 | `response_time: *` | 字段存在 |
| 范围 | `response_time >= 500` | 数值范围 |
| 通配符 | `url: /api/*` | 前缀匹配 |
| 全文 | `"订单支付失败"` | 在全文搜索字段里搜 |

### 2.2 KQL 常见坑

| 坑 | 错误 | 正确 |
|------|------|------|
| 字段名带点 | `kubernetes.pod.name: xxx` 未加引号 | 带点字段用引号或直接写（KQL 支持点号字段） |
| 值含空格 | `message: hello world` | `message: "hello world"` |
| 大小写 | KQL 关键字必须大写 | `and` 写成 `AND` |
| 全文搜索字段 | 忘记指定字段 | 明确 `message: xxx` 而不是裸关键词 |
| 通配符性能 | `message: *error*` 全表扫描 | 用 n-gram/通配符字段或换 ES|QL |

### 2.3 KQL vs Lucene（旧版）

| 维度 | KQL（推荐） | Lucene（遗留） |
|------|------|------|
| 语法 | 更严格、自动补全 | 灵活但易错 |
| 字段引用 | `field: value` | 相同 |
| 通配符 | 值内支持 | 支持更多组合 |
| 推荐 | ✅ 9.x 默认 | 仅兼容老查询 |

## 3. Query DSL：精确控制

### 3.1 在 Discover 中使用 DSL

Kibana 搜索栏选择「Query DSL」模式（或 New Search → Query DSL），直接输入 ES 查询 JSON：

```json
{
  "query": {
    "bool": {
      "must": [
        { "match": { "message": "支付失败" } },
        { "range": { "response_time": { "gte": 500 } } }
      ],
      "filter": [
        { "term": { "level": "ERROR" } }
      ]
    }
  }
}
```

| DSL 组件 | 作用 | 对应 KQL |
|------|------|------|
| `match` | 分词匹配（全文） | `message: 支付失败` |
| `term` | 精确匹配（不分词） | `level: ERROR` |
| `range` | 数值/日期范围 | `response_time >= 500` |
| `bool.must` | AND 语义（参与评分） | `A AND B` |
| `bool.filter` | 过滤（不参与评分，可缓存） | 性能更好 |

> 💡 生产建议：**能走 `filter` 不走 `must`**——filter 子句结果可缓存，日志检索场景命中率与性能都更好。

### 3.2 DSL 模式的使用场景

| 场景 | 说明 |
|------|------|
| KQL 表达不了 | 嵌套查询、聚合条件 |
| 调试 ES 查询 | 先在 Discover 验证，再放进代码 |
| 精确控制相关性 | must/should 评分组合 |

## 4. ES|QL：新一代查询管道

### 4.1 ES|QL 是什么（9.x 重点）

ES|QL（8.14 GA，9.x 全面集成）是一种**管道式查询语言**——每一步输出到下一步，类似 SQL 的 SELECT 加管道处理，Kibana 9.x 中 Discover/Dashboard/告警全部支持。

```sql
FROM logstash-*
| WHERE level == "ERROR" AND @timestamp > now() - 1h
| STATS count = COUNT(*) BY service.name
| SORT count DESC
| LIMIT 10
```

### 4.2 ES|QL 核心语法

| 语句 | 作用 | 示例 |
|------|------|------|
| `FROM` | 指定数据源 | `FROM logs-*` |
| `WHERE` | 过滤 | `WHERE response_time > 500` |
| `STATS ... BY` | 聚合分组 | `STATS avg = AVG(t) BY host` |
| `SORT` | 排序 | `SORT @timestamp DESC` |
| `LIMIT` | 限制条数 | `LIMIT 100` |
| `EVAL` | 计算新字段 | `EVAL ratio = a / b` |
| `RENAME` | 重命名字段 | `RENAME foo AS bar` |
| `KEEP/DROP` | 保留/丢弃字段 | `KEEP @timestamp, message` |
| `ENRICH` | 关联外部数据 | `ENRICH service_catalog` |
| 时间序列 | `RATE`、`*_OVER_TIME`、`TBUCKET` | 监控指标分析 |

### 4.3 ES|QL vs KQL vs SQL（选型）

| 维度 | KQL | ES|QL | SQL（ES `_sql` 接口） |
|------|------|------|------|
| 定位 | 快速过滤 | 管道分析 | 经典 SQL 翻译层（SQL → DSL） |
| 聚合能力 | ❌ | ✅ 强 | ✅ 强（翻译为 DSL 执行） |
| 学习曲线 | 低 | 中 | 低（通用标准，团队都会） |
| 9.x 地位 | Discover 默认 | 全面集成（可视化为 9.1 GA） | 保留可用，**非主推**（Elastic 战略转向 ES|QL） |
| 典型场景 | 随手查日志 | 统计报表、异常分析 | BI/JDBC 工具对接、SQL 团队平滑迁移 |

> ⚠️ 修正认知（易错点）：**ES 不是「没有 SQL」**——官方 `_sql` REST 接口（`POST /_sql`）与 JDBC/ODBC 驱动自 6.3 起一直存在，9.x 未移除（社区 SQL 插件也持续跟进 9.x）。但它是「SQL → DSL」的翻译层而非关系型引擎，且 Elastic 自 8.14 推出 ES|QL 后战略重心已转移：**新工具与可视化能力都投入 ES|QL**，SQL 接口定位为兼容保留。面试答「ES SQL 不存在」是错的，正确说法是「存在但非主推，新项目走 ES|QL」。

> 🎯 面试要点：**KQL 用于「快速过滤」，ES|QL 用于「分析统计」**——9.x 里做「按服务统计错误数 Top10」这类需求，ES|QL 是官方推荐路径；SQL 接口保留给 BI/JDBC 存量对接。

### 4.4 ES|QL 在 9.x 的工程事实（2026，逐条核实）

| 事实 | 版本 | 核实情况 |
|------|------|------|
| ES|QL 可视化 GA（可直接出 Lens 图表） | 9.1 | ✅ 官方文档确认 |
| 图表配置持久化（改查询不丢配置，兼容时保留） | 9.1 文档已描述 | ✅ 官方文档确认功能存在；「9.2 GA」无直接出处，不标注 |
| 多字段 Breakdown（柱/折/面按多字段分组，图例 `›` 分隔） | 9.x | ✅ 官方文档确认功能存在；「9.4 GA」无直接出处，不标注 |
| PromQL 可在 ES|QL 编辑器中运行（`PROMQL` 命令，覆盖 Discover/Dashboard/告警，>80% 覆盖率） | 9.4 技术预览 | ✅ 官方确认 |

## 5. 时间范围与字段操作

### 5.1 时间范围选择

| 方式 | 说明 |
|------|------|
| 快捷区间 | Last 15 minutes / Last 24 hours / Today |
| 自定义 | 绝对时间（2026-08-07 10:00:00）或相对（now-2h） |
| 刷新频率 | Auto refresh：5s ~ 1h（日志看板常用 30s-1m） |
| 时间柱状图缩放 | 在柱状图上框选可放大时间段 |

> ⚠️ 时区坑：ES 存储 UTC，Kibana 默认按浏览器时区展示——同一文档在不同时区的同事看到的时间不同，排查日志时先确认显示时区。

### 5.2 字段操作

| 操作 | 路径 |
|------|------|
| 选择展示字段 | 字段列表点击 + 添加到表格 |
| 排序 | 点击表头（按 @timestamp 或任意字段） |
| 字段过滤 | 点击文档中字段值的 +/- 图标 |
| 查看字段统计 | 字段列表悬停显示 Top 值分布 |

## 8. 检索性能优化

| 场景 | 优化手段 |
|------|------|
| 查询慢 | 缩小时间范围；用 `filter` 替代 `must`；给常用过滤字段建 keyword 子字段 |
| 通配符慢 | 避免 `*error*` 形态；用 n-gram 分词器或 ES|QL 精确计算 |
| 字段过多 | 减少展示字段（只选需要的） |
| 数据量大 | 用 ES|QL 先聚合再展示，别拉全量文档 |
| 结果截断 | Discover 默认 500 条，分析用 ES|QL `STATS` 聚合 |

### 8.1 日志检索最佳实践

```text
① 按服务/环境先过滤（service.name + environment）
② 时间范围收窄（先 15 分钟再放宽）
③ 错误排查用 level: ERROR + 时间柱状图定位峰值
④ 峰值时刻用 ES|QL 按接口/实例聚合定位 TOP 来源
```

> 🎯 **核心要点**：Discover 检索三语言——**KQL（快速过滤，语法最简）、Query DSL（精确控制，生产代码同源）、ES|QL（管道分析，9.x 主力）**。排查日志的标准动作：选数据视图 → 收时间窗 → KQL 过滤 → 柱状图看峰值 → ES|QL 聚合定位。记住三个坑：数据视图时间字段、UTC 时区、通配符性能。
