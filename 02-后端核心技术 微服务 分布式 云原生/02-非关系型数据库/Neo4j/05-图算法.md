## 1. 图算法概览

### 1.1 四大类

| 类别 | 回答的问题 | 代表算法 |
|------|-----------|---------|
| 路径 | 怎么走最近/最优？ | 最短路径、A*、最小生成树 |
| 中心性 | 谁最重要？ | PageRank、度中心性、介数中心性 |
| 社区检测 | 哪些节点是一伙的？ | Louvain、标签传播、弱连通分量 |
| 相似度 | 谁和谁像？ | 余弦、Jaccard、节点相似度 |

```text
与查询的区别：
  查询：回答"具体关系"（谁认识谁）
  算法：回答"图结构特征"（谁最重要/哪些聚类）
  → 查询是 OLTP，算法是图分析（GDS 承载）
```

### 1.2 应用场景

| 场景 | 算法 |
|------|------|
| 好友推荐 | 共同邻居/相似度 |
| 风险团伙识别 | 社区检测 + 中心性 |
| 关键节点（供应链） | 介数中心性 |
| 影响力分析 | PageRank |
| 最短配送路径 | 最短路径 |
| 欺诈检测 | 可疑社区 + 路径 |

> 🎯 核心认知：**图算法把"图的结构"变成"可计算的业务洞察"**——中心性回答"谁关键"、社区回答"谁同伙"、路径回答"怎么到达"。Cypher 回答"是什么关系"，图算法回答"图在说什么"。

## 2. 路径算法

### 2.1 核心算法

| 算法 | 作用 | 复杂度 |
|------|------|:---:|
| 最短路径（BFS/狄克斯特拉） | 无权/加权最短路 | O(V+E) / O(E log V) |
| A* | 启发式最短路 | 更快（有启发） |
| 全部最短路径 | 所有最短路 | O(V·(V+E)) |
| 最小生成树 | 连通所有节点的最小代价 | O(E log V) |
| 最大流 | 网络容量 | 多项式 |

### 2.2 GDS 中的路径算法

```cypher
// 最短路径（GDS 库）
CALL gds.shortestPath.dijkstra.stream('myGraph', {
    sourceNode: 42,
    targetNode: 100,
    relationshipWeightProperty: 'distance'
})
YIELD index, sourceNode, targetNode, totalCost, path
RETURN index, totalCost, path;

// 结果：节点 42 → 100 的最短路径与总代价
// 场景：物流配送、网络路由、依赖链分析
```

### 2.3 路径算法的业务应用

```text
应用模式：
  ① 最短路径：物流/路由/社交"距离"
  ② 最小生成树：网络布线/供应链骨架
  ③ 最大流：网络容量/资源调度

与 Cypher shortestPath 的区别：
  Cypher：小规模（图内查询）
  GDS：大规模 + 加权/多算法（分析）
  → 按规模与需求选择
```

## 3. 中心性算法

### 3.1 算法家族

| 算法 | 衡量 | 适用 |
|------|------|------|
| 度中心性 | 连接数 | 简单影响力 |
| 介数中心性 | 经过该节点的最短路径数 | 关键桥梁/瓶颈 |
| 紧密度中心性 | 到所有节点的平均距离 | 信息传播效率 |
| PageRank | 随机游走稳态概率 | 权威节点（网页/用户） |
| 特征向量中心性 | 邻居重要性加权 | 社交影响力 |

### 3.2 PageRank（GDS）

```cypher
// PageRank（图上的影响力计算）
CALL gds.pageRank.stream('myGraph', {
    maxIterations: 20,
    dampingFactor: 0.85
})
YIELD nodeId, score
RETURN gds.util.asNode(nodeId).name AS name, score
ORDER BY score DESC LIMIT 10;
// 场景：KOL 识别、重要商品、关键账号
```

```text
PageRank 的核心思想：
  节点的重要性 = 指向它的重要节点的加权和
  随机游走解释：从任意节点出发随机跳转，
  长期访问概率高的节点 = 重要
  → 搜索引擎（Google 起源）与图分析的通用工具
```

### 3.3 中心性的业务价值

| 场景 | 算法 | 业务含义 |
|------|------|---------|
| 供应链 | 介数中心性 | 关键中转（断供影响） |
| 社交 | PageRank | 意见领袖 |
| 风控 | 度+介数 | 高危枢纽 |
| 网络 | 介数 | 单点故障 |
| 推荐 | 特征向量 | 影响力用户 |

```text
工程要点：
  中心性结果可持久化（属性存储）
  定期重算（图变化后）
  与其他特征组合（风控评分）
```

## 4. 社区检测

### 4.1 核心算法

| 算法 | 原理 | 特点 |
|------|------|------|
| 弱连通分量（WCC） | 连通子图 | 最基础（孤立群） |
| 标签传播（LPA） | 邻居多数标签传播 | 快、近似 |
| Louvain | 模块度最大化 | **最流行**（分层） |
| 强连通分量（SCC） | 有向互相可达 | 环检测 |

### 4.2 Louvain（GDS）

```cypher
// Louvain 社区检测
CALL gds.louvain.stream('myGraph')
YIELD nodeId, communityId
RETURN gds.util.asNode(nodeId).name AS name, communityId
ORDER BY communityId LIMIT 20;

// 结果：同一 communityId = 同一社区
// 场景：欺诈团伙、用户聚类、兴趣圈
```

```text
模块度（Modularity）：
  衡量"社区内连接密度 vs 随机期望"
  越高 = 社区结构越明显
  Louvain 贪心最大化模块度（分层聚合）

工程流程：
  ① 建图（投影）
  ② Louvain 计算
  ③ 结果分析（社区规模/密度）
  ④ 业务标注（团伙/群体）
```

### 4.3 社区检测的应用

| 场景 | 社区含义 |
|------|---------|
| 欺诈 | 可疑交易圈（异常社区） |
| 用户 | 兴趣群体（精准运营） |
| 供应链 | 依赖集群（风险传播范围） |
| 知识图谱 | 主题聚类（GraphRAG 的社区摘要基础！） |

```text
与 GraphRAG 的联系（06 模块）：
  GraphRAG 的社区摘要 = 社区检测的产物
  Louvain → 社区 → LLM 摘要 → 检索索引
  → 图算法直接服务 AI 应用
```

## 5. 相似度与链路预测

### 5.1 相似度算法

| 算法 | 衡量 | 适用 |
|------|------|------|
| 余弦相似度 | 向量夹角 | 属性/embedding |
| Jaccard | 集合重叠 | 共同邻居 |
| 重叠系数 | 重叠/最小集合 | 稀疏场景 |
| 节点相似度 | 邻居结构 | 图结构相似 |

```cypher
// Jaccard 相似度（共同好友比例）
MATCH (a:Person {name:'张三'})-[:FRIEND]->(fa)
WITH a, collect(fa) AS friendsA
MATCH (b:Person {name:'李四'})-[:FRIEND]->(fb)
WITH friendsA, collect(fb) AS friendsB
RETURN
  toFloat(size([x IN friendsA WHERE x IN friendsB])) /
  toFloat(size(friendsA + friendsB)) AS jaccard;
// 场景：好友推荐（共同好友多 = 可能认识）
```

### 5.2 链路预测

```text
链路预测：预测"可能存在的边"（还没发生的关系）
  依据：结构相似（共同邻居、路径长度）

工程应用：
  好友推荐（可能认识的人）
  商品推荐（协同过滤的图版）
  风险预测（异常连接）

推荐流程：
  ① 相似度/路径特征计算
  ② 候选生成（Top-N）
  ③ 业务过滤（排除已有关系）
  ④ 排序返回
```

## 6. GDS 库与工程实践

### 6.1 GDS（Graph Data Science）

```text
GDS：Neo4j 的图算法库（企业版/部分社区）
  特点：
    ① 图投影（内存图，独立于存储图）
    ② 60+ 算法（路径/中心性/社区/相似度）
    ③ 流式/写入/统计三种结果模式
    ④ Cypher 调用（过程/函数）

图投影：
  CALL gds.graph.project('myGraph', 'Person', 'FRIEND')
  → 把存储图投影为内存计算图
  → 算法在投影上运行（不影响存储）

版本：GDS 2.x（2025-2026 稳定）
```

### 6.2 工程实践模式

```text
图分析的工程流程：
  ① 数据建模（节点/关系——图存储）
  ② 图投影（算法输入）
  ③ 算法执行（中心性/社区等）
  ④ 结果回写（算法结果存为属性）
  ⑤ 业务集成（查询/推荐/风控）

性能注意：
  投影内存开销（大图需内存规划）
  算法复杂度（中心性 O(V·E) 级别）
  定期重算（增量/全量策略）

算法结果的持久化：
  写入模式（write 参数）→ 属性存储
  → 查询直接使用（无需重算）
```

### 6.3 图算法的选择框架

```text
需求 → 算法选择：
  "谁重要" → 中心性（PageRank/介数）
  "谁同伙" → 社区（Louvain/WCC）
  "怎么走" → 路径（最短路径/MST）
  "谁像谁" → 相似度（Jaccard/余弦）
  "谁可能连接" → 链路预测（结构特征）

规模与成本：
  小图（万级）→ Cypher 直接实现
  大图（百万+）→ GDS（内存投影/并行）
  超大规模 → 分布式图平台（TigerGraph 等）
```

> 🎯 **核心要点**：图算法四大类（路径/中心性/社区/相似度）把"图结构"变成"业务洞察"——Louvain 找团伙、PageRank 找权威、最短路径找路线、Jaccard 找相似。GDS 库（图投影 + 60+ 算法）是生产级图分析的载体；而社区检测正是 GraphRAG（06 模块）的社区摘要基础——图算法正在直接服务 AI 应用。
