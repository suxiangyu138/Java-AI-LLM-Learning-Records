## 4. 核心概念速查

| 概念 | 一句话定义 | 关键事实（2025-2026） |
|------|-----------|---------------------|
| 分布式缓存 | 多节点内存缓存（客户端分片） | 无内置集群，靠一致性哈希 |
| slab 分配器 | 按大小分桶的内存管理 | 每键开销仅 60-70 字节 |
| chunk | slab 内的固定大小内存单元 | 大小按 2 的幂增长 |
| LRU | 最近最少使用淘汰 | 支持分段 LRU（热/冷） |
| 1MB 限制 | 单值默认最大 1MB | 可配置（slab 调整） |
| 一致性哈希 | 客户端路由的哈希环 | 虚拟节点平衡分布 |
| 多线程 | 自始支持多线程 | 8 线程 ~150 万 ops/s |
| CAS | 比较并交换（防并发覆盖） | 乐观锁语义 |
| 过期时间 | 相对/绝对过期 | 惰性删除 + 定期清理 |
| 无持久化 | 纯内存缓存 | 重启即失（可重建） |
| 协议 | ASCII/二进制 | 约 15 个命令 |
| 版本 | 1.6.x（2025-2026 稳定） | BSD 许可（无限制） |

> 🎯 **核心要点**：Memcached 是"刻意简单"的缓存——只做一件事（内存 KV 缓存）并做到极致：多线程（吞吐高）、slab 分配器（内存省）、BSD 许可（无限制）。它的取舍与 Redis 形成鲜明对照：无持久化/无数据结构/无集群，换来的是极简与极致吞吐。2025-2026 的现实：**"Redis 管会话与实时特性、Memcached 管高吞吐页面/API 缓存"的双用架构**仍是生产主流。
