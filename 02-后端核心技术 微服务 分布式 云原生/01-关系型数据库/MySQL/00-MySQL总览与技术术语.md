## 1. MySQL 是什么

```
MySQL = 开源关系型数据库管理系统（RDBMS）
  以表存储数据，SQL 查询，事务安全（InnoDB）

定位：
  中小型业务首选数据库（互联网应用事实标准）
  与 Java 后端生态深度绑定（JDBC/MyBatis/Spring）

⚠️ 面试必答：
"MySQL 是开源关系型数据库，InnoDB 引擎
 提供事务与行级锁——互联网业务的默认选择。"
```

## 2. 版本现状与选型（2026-07 验证）

### 2.1 版本时间线

| 版本 | 状态 | 说明 |
|------|------|------|
| 8.0 | ⚠️ EOL（2026-04） | 8.0.46 为最后版本，不再有安全补丁 |
| 8.4 LTS | ✅ 维护中（支持至 2029） | 当前生产首选 LTS |
| 9.7.0 LTS | ✅ 新 LTS（2026-04-21 发布，支持至 2031） | 8.4 之后首个 LTS |
| 9.6.0 Innovation | 创新版 | 非 LTS，尝鲜用 |
| 26.7.0 Innovation | 创新版（2026-07） | ⚠️ 新日历命名（YY.M.P） |

### 2.2 9.7 LTS 核心新特性（社区版下放）

| 特性 | 说明 |
|------|------|
| Hypergraph 优化器 | DPhyp 算法重写成本优化，支持 Bushy 连接；实验性默认关闭，TPC-DS 约半数查询提升 25%+ |
| JSON Duality Views DML | 社区版首次支持二元视图增删改 |
| 组复制运维补齐 | 复制延迟指标、资源管理器、主节点选举优化 |
| OpenTelemetry 原生支持 | OTLP 导出日志/指标/追踪 |
| 向量检索增强 | VECTOR 类型 + SQL 向量相似检索（RAG 场景），较 8.4 快约 45% |

### 2.3 升级注意

```
⚠️ 不能 8.0 直接跳 9.7：必须先升 8.4 LTS 验证再升
⚠️ 9.7 优化器重构 → 升级前全量 SQL 回归
⚠️ 生产选型建议：新项目 8.4 LTS（稳）；追求新特性 9.7 LTS

⚠️ 面试必答：
"生产用 8.4 LTS（8.0 已 EOL）；
 9.7 的 Hypergraph 优化器是社区版最大变化，
 但默认关闭、需 SQL 回归。"
```

## 5. 核心术语表

| 术语 | 一句话定义 | 详见 |
|------|-----------|------|
| InnoDB | 默认存储引擎（事务 + 行锁 + MVCC） | 01 |
| WAL | 先写日志再写磁盘（redo log 保证持久性） | 01 |
| undo log | 记录旧值的回滚日志（原子性 + MVCC 版本链） | 01、03 |
| redo log | 记录修改的物理日志（崩溃恢复） | 01 |
| binlog | 逻辑日志（复制与恢复，8.0 默认 ROW 格式） | 08 |
| 事务 | 一组原子操作（ACID） | 03 |
| ACID | 原子性/一致性/隔离性/持久性 | 03 |
| 隔离级别 | 并发隔离的四档（MySQL 默认 RR） | 03 |
| MVCC | 多版本并发控制（快照读不加锁） | 03 |
| ReadView | 快照读的可见性判断视图 | 03 |
| 快照读 / 当前读 | 普通 SELECT / FOR UPDATE 等加锁读 | 03 |
| 行锁 / Gap Lock / Next-Key | 记录锁 / 间隙锁 / 组合锁（防幻读） | 03 |
| 死锁 | 循环等待锁（等待图检测 + 超时） | 03 |
| B+Tree | InnoDB 索引底层结构（矮树 + 叶子链表） | 04 |
| 聚簇索引 | 主键索引（叶子存整行） | 04 |
| 二级索引 | 非主键索引（叶子存主键值，需回表） | 04 |
| 覆盖索引 | 查询列全在索引中（免回表） | 04 |
| 最左前缀 | 联合索引必须从左列开始使用 | 04 |
| 索引下推 ICP | 存储引擎层先过滤（5.6+） | 04 |
| EXPLAIN | 执行计划分析工具 | 05 |
| 慢查询日志 | 记录超时 SQL（mysqldumpslow 分析） | 05 |
| 主从复制 | binlog → relay log → 回放（三线程） | 08 |
| 半同步复制 | 至少一个从库确认才提交 | 08 |
| 读写分离 | 写主读从（中间件/应用层） | 08 |
| 分库分表 | 垂直/水平拆分（ShardingSphere） | 08 |
| 三大范式 | 1NF 原子性/2NF 消除部分依赖/3NF 消除传递依赖 | 07 |

## 6. 学习路线推荐

### 路线 A：面试冲刺（2-3 天）

```
09 面试题（全局）→ 04 索引（B+Tree/回表/最左前缀）
→ 03 事务锁（MVCC/隔离级别/死锁）→ 05 优化（EXPLAIN）
```

### 路线 B：系统学习（1-2 周）

```
06 操作 → 02 SQL 进阶 → 04 索引 → 03 事务锁
→ 05 优化 → 01 引擎 → 07 设计 → 08 高可用 → 09 复盘
```

### 路线 C：架构方向（进阶）

```
08 高可用（主从/分片）→ 07 设计（范式/反范式）
→ 01 引擎（日志体系）→ 结合分布式事务体系
```
