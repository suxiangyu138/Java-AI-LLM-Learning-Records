## 1. 安全模型总览

```text
MinIO 安全四层：
  ① 身份：Access Key / Secret Key（谁）
  ② 授权：Policy（能做什么）——IAM 风格
  ③ 传输：TLS（路上安全）
  ④ 存储：SSE 加密（静态安全）

访问判定流程：
  请求 → 身份验证（AK/SK 签名）→ 策略匹配（Action/Resource）→ 放行/拒绝
```

| 层 | 机制 | 对应章节 |
|----|------|:---:|
| 身份 | AK/SK、服务账号、STS | §3 |
| 授权 | Policy / Bucket Policy | §2 |
| 传输 | TLS 证书 | §5 |
| 静态 | SSE-S3 / SSE-KMS | §6 |

> 🎯 核心认知：**MinIO 的安全模型是 AWS IAM 的兼容实现**——会 AWS S3 权限就会 MinIO 权限；反之亦然。权限是对象存储事故（数据泄露）的第一防线，值得投入。

## 2. 访问策略（Policy）语法

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:PutObject"],
      "Resource": ["arn:aws:s3:::avatars/*"]
    },
    {
      "Effect": "Deny",
      "Action": ["s3:DeleteObject"],
      "Resource": ["arn:aws:s3:::avatars/*"]
    }
  ]
}
```

| 要素 | 含义 | 示例 |
|------|------|------|
| Effect | 允许/拒绝 | Allow / Deny |
| Action | 操作 | s3:GetObject / s3:PutObject / s3:ListBucket / s3:DeleteObject |
| Resource | 资源 | `arn:aws:s3:::bucket/*`（对象）/ `arn:aws:s3:::bucket`（桶级） |
| 通配 | 批量匹配 | `s3:*` / `*/*` |

```bash
# 策略落地（mc）
mc admin policy create local readonly /path/readonly.json
mc admin user add local app-user secret123
mc admin policy attach local readonly --user app-user
```

| 高频 Action | 场景 |
|------------|------|
| `s3:GetObject` | 下载/读取 |
| `s3:PutObject` | 上传 |
| `s3:DeleteObject` | 删除 |
| `s3:ListBucket` | 列对象（列表页） |
| `s3:GetBucketPolicy` | 管理策略（管理员） |
| `s3:GetPresignedUrl` | 生成预签名（常用） |

> ⚠️ 权限设计三原则：**① 最小权限**（只给需要的 Action+Resource）；**② 显式 Deny 兜底**（敏感操作如 Delete）；**③ 桶隔离**（不同业务不同桶不同账号，别一桶通吃）。

## 3. 服务账号与最小权限

```text
凭证体系：
  根凭证（Root）     ：初始唯一，管理用（别给应用！）
  服务账号（Service） ：每个应用/服务一个，绑定策略
  临时凭证（STS）    ：短时（15min-12h），自动过期

生产标准：
  应用 A → 服务账号 A（只读写 avatars 桶）
  应用 B → 服务账号 B（只读 files 桶）
  根凭证 → 锁进保险箱（密码管理器），仅运维应急
```

```bash
# 创建最小权限服务账号
mc admin accesskey create local \
  --access-key app-avatars \
  --secret-key strong-secret \
  --policy '{"Version":"2012-10-17","Statement":[{"Effect":"Allow",
    "Action":["s3:PutObject","s3:GetObject","s3:DeleteObject"],
    "Resource":["arn:aws:s3:::avatars/*"]}]}'
```

> ⚠️ 密钥泄露应对：**泄露后立即轮换**——服务账号删除重建（应用改配置即可，无需动根凭证）；2026 的 `mc admin accesskey diagnose` 可快速排查 Access Denied 根因。密钥一律走环境变量/密钥管理，**别硬编码进代码仓库**。

## 4. 预签名 URL：不暴露密钥的访问

```text
预签名 URL = 用 Secret Key 对"URL + 过期时间"签名的临时链接：
  优点：
  · 客户端拿 URL 直接访问，不接触 AK/SK
  · 限时有效（分钟级/小时级），过期自动失效
  · 可限制方法（GET 下载 / PUT 直传）

经典场景（[06-后端架构配合](06-后端架构配合.md)）：
  · 下载：应用生成预签名 GET URL → 前端直接 <img src>/下载
  · 直传：前端拿预签名 PUT URL → 直接传 MinIO（不经应用服务器）
```

```python
# MinIO Python SDK 生成预签名（Java 见 05）
from minio import Minio

# 生产：secure=True（HTTPS 校验）；开发连本地自签时用信任库或一次性 secure=False
client = Minio("localhost:9000", access_key="app", secret_key="secret", secure=True)
url = client.presigned_get_object("avatars", "user-42.png", expires=3600)
print(url)   # https://localhost:9000/avatars/user-42.png?X-Amz-...
```

| 预签名类型 | 方法 | 场景 |
|-----------|------|------|
| presigned GET | GET | 限时下载/图片直读 |
| presigned PUT | PUT | 浏览器直传（绕应用） |
| presigned POST | POST 表单 | 表单直传（带策略限制） |

> 🎯 面试金句：**"预签名 URL 是'把权限外包给 URL'——密钥不出服务器，客户端凭限时 URL 直传直读"**。这是对象存储架构里"应用不碰文件字节流"的关键机制。

## 5. TLS 与传输安全

```bash
# 方式一：启动时指定证书目录（cert.pem + private.key）
./minio server /data --certs-dir /etc/minio/certs

# 方式二：环境变量（单证书场景）
export MINIO_CERT_FILE=/etc/minio/certs/public.crt
export MINIO_PRIVATE_KEY_FILE=/etc/minio/certs/private.key

# 验证
mc alias set secure https://minio.example.com:9000 admin pass
mc admin info secure
```

| 场景 | 证书策略 |
|------|---------|
| 生产公网 | 正式证书（Let's Encrypt 自动续期） |
| 内网生产 | 内网 CA 签发的证书（应用侧信任该 CA） |
| 开发 | 自签证书 → **客户端把 CA 加入信任库**（`http_client` 配置） |
| 反代后面 | 可在 Nginx 终结 TLS（MinIO 只走内网 HTTP） |

> ⚠️ 与 [爬虫阶段 HTTPS 章节](../../../03-AI大模型应用开发/01-Python语言/Python爬虫/阶段%201：前置基础（必备）/02-HTTP协议基础（爬虫视角）.md) 同理：**自签场景的正确姿势是信任该 CA，而不是关闭校验**——SDK 的 `secure=False`/`verify=False` 只用于一次性开发。

## 6. 服务端加密（SSE）

```text
SSE 三种模式：
  SSE-S3：MinIO 自己管密钥（简单，适合默认加密需求）
  SSE-KMS：外部 KMS 管密钥（合规/轮换/审计要求）
  SSE-C：客户端自带密钥（最灵活，密钥不落地）

效果：对象在磁盘上是密文，读取时自动解密（对应用透明）
```

| 模式 | 密钥管理 | 适用 |
|------|---------|------|
| SSE-S3 | MinIO 内置 | 默认加密（等保/合规基线） |
| SSE-KMS | 外部 KMS（如 Vault） | 审计/轮换/多集群统一 |
| SSE-C | 客户端每次传密钥 | 数据主权要求高的场景 |

```bash
# 桶级默认加密（最简单：全桶 SSE-S3）
mc encrypt set sse-s3 local/avatars
mc encrypt info local/avatars
```

> 💡 2026 新特性：`mc encrypt update` 支持**就地轮换加密密钥**（SSE-S3/SSE-KMS → SSE-KMS，无需重新上传对象）——历史对象的加密升级不再需要重传。

## 7. 安全基线清单

```text
生产上线安全自检（照着打勾）：
  □ 根凭证已改默认值且仅运维持有
  □ 每个应用独立服务账号 + 最小权限策略
  □ 敏感桶（备份/隐私）启用 SSE 加密
  □ 传输层 TLS（公网场景必配）
  □ 无公开可写的桶（匿名写 = 事故）
  □ 版本控制开启（防误删/覆盖）
  □ 预签名 URL 过期时间最小化（下载 1h、直传 15min）
  □ 密钥存环境变量/密钥管理（不进代码仓库）
  □ 访问日志开启（审计）
  □ 及时升级（2026 年 CVE-2026-34204 等均靠升级修复）
```

> ⚠️ 升级提示：MinIO 2026 年已修复多个安全 CVE（复制头注入 CVE-2026-34204、未签名 trailer 认证绕过等）——**对象存储是数据资产，保持升级是安全基线的一部分**（[07](07-生产实践与故障排查.md) 有升级实践）。
