## 4. MinIO 定位

### 4.1 对象存储 vs 文件系统 vs 数据库

| 维度 | 文件系统（NFS） | 对象存储（MinIO/S3） | 关系数据库 |
|------|:---:|:---:|:---:|
| 数据模型 | 目录树 + 文件 | **扁平桶 + 对象**（键值） | 表 + 行 |
| 访问方式 | 挂载/路径 | **HTTP API**（S3） | SQL |
| 扩展性 | 差（单机上限） | **无限水平扩展** | 中等（分库分表） |
| 元数据 | 目录结构 | 对象键 + 自定义元数据 | 字段 |
| 适用 | 传统服务器文件 | **海量非结构化文件** | 结构化数据 |
| 典型场景 | 共享目录 | 图片/视频/备份/AI 语料 | 业务数据 |

> 🎯 一句话：**MinIO 解决的是"海量文件放哪里"**——图片、视频、文档、模型文件、日志归档这些"非结构化数据"，既不该进数据库（拖垮性能），也不该堆在应用服务器磁盘（无法扩展），对象存储是标准答案。

### 4.2 S3 兼容的意义

```text
S3 API = 对象存储的"事实标准"（AWS 定义）
  · 100% 兼容 → 所有 S3 SDK（Java/Python/Go/JS）改个端点就能用
  · 开发/测试用 MinIO → 生产切云 S3 → 代码零改动
  · 混合云：本地 MinIO + 云 OSS 可互相迁移/同步
  · 生态：备份工具（restic/rclone）、大数据（Spark/Iceberg）原生支持 S3
```

> 🎯 2026 选型主线：**开发环境与私有云用 MinIO（成本/数据主权），生产 ToC 大流量用云 OSS（托管/带宽/CDN）**——详见 [08-选型对比与面试题](08-选型对比与面试题.md) 的决策树。

## 5. 核心概念速查

| 概念 | 一句话 |
|------|--------|
| 对象存储 | 以"桶 + 键"组织海量文件的存储（无目录树） |
| Bucket（桶） | 对象的命名空间（类似"顶层目录"） |
| Object（对象） | 一个文件 = 数据 + 元数据 + 唯一键 |
| Endpoint | 服务地址（`http://localhost:9000`） |
| Access Key / Secret Key | 访问凭证（S3 的"用户名密码"） |
| 纠删码（Erasure Coding） | 数据分片 + 校验块，磁盘损坏可重建（比副本省空间） |
| Bit Rot | 磁盘静默损坏（纠删码可检测修复） |
| 版本控制 | 对象多版本保留（防误删/覆盖） |
| 生命周期 | 按规则自动迁移/过期删除 |
| 预签名 URL | 限时有效的临时访问链接（不暴露密钥） |
| SSE | 服务端加密（SSE-S3/SSE-KMS） |
| 站点复制 | 集群间异步镜像（类 rsync，非强一致） |
| mc | MinIO 官方命令行客户端 |
| S3 兼容 | 与 AWS S3 API 完全兼容 |
