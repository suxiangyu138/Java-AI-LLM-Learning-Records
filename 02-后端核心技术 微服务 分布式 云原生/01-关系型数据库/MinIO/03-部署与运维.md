## 1. 部署形态选型

| 形态 | 规模 | 数据保护 | 适用 |
|------|:---:|:---:|------|
| **单机单盘** | 开发 | 无 | 本地测试/学习 |
| 单机多盘 | 小规模 | 纠删码（多盘） | 内网小应用（2GB 内存即可跑） |
| **分布式** | 生产 | 纠删码 + 节点冗余 | 标准生产（≥4 节点 × 4 盘） |
| Docker/Compose | 开发/CI | 按挂载盘 | 快速起环境 |
| K8s（Operator） | 大规模 | 纠删码 | 云原生集群 |

> 🎯 选型铁律：**生产必须分布式**（≥4 节点）——单机版没有节点级容错，只配开发/测试。最小生产参考：4 节点 × 4 盘 = 16 盘（8+8 纠删码，容错 8 盘）。

## 2. 单机部署（开发/小规模）

```bash
# 下载（单二进制，Linux）
wget https://dl.min.io/server/minio/release/linux-amd64/minio
chmod +x minio

# 单机单盘启动（开发用）
MINIO_ROOT_USER=admin MINIO_ROOT_PASSWORD=yourpassword \
  ./minio server /data --console-address ":9001"

# 单机多盘（小规模生产：多盘 = 纠删码！）
./minio server /data1 /data2 /data3 /data4 --console-address ":9001"

# 启动后输出：
#   API: http://localhost:9000      ← 应用接入端点
#   Console: http://localhost:9001  ← 管理界面
```

| 环境变量 | 说明 |
|---------|------|
| `MINIO_ROOT_USER` | 根凭证用户名（≥3 字符） |
| `MINIO_ROOT_PASSWORD` | 根凭证密码（**≥8 字符**，否则拒绝启动） |
| `--console-address` | 控制台端口（默认随机） |
| `--address` | API 端口（默认 9000） |

> ⚠️ 单机多盘要点：**单机多盘 = 同机纠删码**——防盘损，但机器挂了全没。生产别用"一台机器 16 盘"冒充分布式（[02 §5](02-架构原理纠删码与数据保护.md) 的节点冗余设计失效）。

## 3. 分布式部署（生产标准）

```bash
# 4 节点 × 4 盘（16 盘，8+8 纠删码）
# 每台节点执行同一命令（IP 列表相同即集群）
MINIO_ROOT_USER=admin MINIO_ROOT_PASSWORD=yourpassword \
  ./minio server \
  http://192.168.1.11/data{1...4} \
  http://192.168.1.12/data{1...4} \
  http://192.168.1.13/data{1...4} \
  http://192.168.1.14/data{1...4} \
  --console-address ":9001"
```

| 分布式要点 | 说明 |
|-----------|------|
| 命令一致性 | 所有节点用**完全相同**的启动命令（IP 列表） |
| 磁盘独立性 | 每盘独立路径（`data{1...4}` 展开为 4 盘） |
| 时钟同步 | 节点间 NTP 同步（复制/一致性依赖） |
| 网络 | 节点间低延迟（同机房/同 VPC） |
| 故障域 | 机架感知部署（别让单机架带走全部校验块） |
| 数据目录 | 建议**裸盘/独立分区**（官方不建议 RAID，纠删码自己管） |

> 🎯 部署验证：`mc admin info <alias>` 应显示 16 块盘全部 online；任一节点宕机 → 数据仍可读写（quorum 满足时）。

## 4. Docker 与 Compose

```yaml
# docker-compose.yml（开发/CI 标准姿势）
services:
  minio:
    image: minio/minio:latest
    command: server /data --console-address ":9001"
    environment:
      MINIO_ROOT_USER: minioadmin
      MINIO_ROOT_PASSWORD: minioadmin
    ports:
      - "9000:9000"     # API
      - "9001:9001"     # Console
    volumes:
      - minio-data:/data

  # 可选：创建初始桶（官方 mc 容器）
  minio-init:
    image: minio/mc
    depends_on: [minio]
    entrypoint: >
      /bin/sh -c "
      mc alias set local http://minio:9000 minioadmin minioadmin;
      mc mb local/avatars;
      mc mb local/files;
      "
volumes:
  minio-data:
```

```bash
# 快速起环境（开发）
docker run -d -p 9000:9000 -p 9001:9001 \
  -e MINIO_ROOT_USER=minioadmin -e MINIO_ROOT_PASSWORD=minioadmin \
  -v minio-data:/data \
  minio/minio server /data --console-address ":9001"
```

> 💡 K8s 场景用 **MinIO Operator**（官方云原生方案）：声明式部署分布式集群 + 自动创建 PVC/纠删集，细节见 [MinIO K8s 文档](https://min.io/docs/minio/kubernetes/upstream/index.html)。

## 5. mc 客户端命令速查

```bash
# 配置连接
mc alias set local http://localhost:9000 admin yourpassword

# 桶操作
mc mb local/avatars                    # 建桶
mc rb --force local/old-bucket         # 删桶（2026 起支持一键连内容删除）
mc ls local                            # 列桶

# 对象操作
mc cp file.png local/avatars/          # 上传
mc cp local/avatars/file.png ./        # 下载
mc ls local/avatars/                   # 列对象
mc cat local/avatars/file.png          # 直接看内容
mc rm local/avatars/file.png           # 删除
mc du local/avatars                    # 目录用量

# 版本与生命周期
mc version enable local/avatars        # 开启版本控制
mc ilm rule add local/logs --expire-days 7   # 生命周期过期规则

# 管理
mc admin info local                    # 集群健康（盘状态/容量）
mc admin heal local                    # 手动修复
mc admin prometheus generate local     # 生成 Prometheus 抓取配置
mc admin accesskey create local        # 创建服务账号
```

| 常用管理操作 | 场景 |
|-------------|------|
| `mc admin info` | 日常巡检第一命令（盘/容量/版本） |
| `mc admin heal` | 磁盘恢复后手动触发重建 |
| `mc admin prometheus generate` | 监控接入（见 §6） |
| `mc alias set` | 多环境切换（dev/staging/prod） |

> 🎯 日常铁律：**先 `mc admin info` 看健康，再谈业务**——盘 offline、纠删码降级、容量告警都在这一个命令里。

## 6. 监控与健康检查

```yaml
# Prometheus 指标（mc admin prometheus generate 输出抓取配置）
scrape_configs:
  - job_name: minio
    metrics_path: /minio/v2/metrics/cluster
    bearer_token: <generated_token>
    static_configs:
      - targets: ["minio:9000"]
```

| 核心指标 | 含义 | 告警建议 |
|---------|------|---------|
| `minio_cluster_capacity_usable_total_bytes` | 可用容量 | <20% 告警 |
| `minio_node_disk_used_bytes` | 各盘用量 | 不均衡告警 |
| `minio_node_drive_offline` | 离线盘数 | >0 告警 |
| `minio_cluster_health` | 集群健康 | <1 告警 |
| 读写延迟/吞吐 | 性能 | 基线偏离告警 |

```bash
# 应用层健康检查（K8s 探针/负载均衡用）
curl -s http://minio:9000/minio/health/live     # 存活
curl -s http://minio:9000/minio/health/ready    # 就绪（含磁盘检查）
curl -s http://minio:9000/minio/health/cluster  # 集群健康（分布式）
```

> 🎯 三探针组合：`live`（进程在）+ `ready`（可服务）+ `cluster`（quorum 满足）——K8s/负载均衡的探针直接用它（与 [Docker 三探针](../../11-云原生/Docker/10-Docker与Kubernetes衔接.md) 呼应）。

## 7. 备份与恢复

```text
三层数据保护（MinIO 官方建议）：
  ① 纠删码       → 硬件故障容错（集群内）
  ② 版本控制     → 逻辑误删防护（桶内）
  ③ 站点复制/备份 → 灾难恢复（跨站点）

备份工具生态（S3 兼容 = 通用工具直接可用）：
  · rclone：最通用（MinIO↔云 OSS↔本地）
  · restic：加密备份（增量 + 去重）
  · mc mirror：官方镜像同步
```

```bash
# 备份姿势一：站点复制（跨站异步镜像，灾备）
mc admin replicate add local remote --remote-bucket "*"

# 备份姿势二：mc mirror（手动/定时同步）
mc mirror local/bucket backup/bucket --overwrite

# 备份姿势三：rclone（加密 + 增量，推荐）
rclone sync local:bucket backup:backup --transfers 16 --checkers 32
```

> ⚠️ 备份恢复验证：**恢复演练是备份的一部分**——"有备份没验证恢复"等于没有备份。定期（如每季度）在测试环境做一次完整恢复演练（[07](07-生产实践与故障排查.md) 备份篇展开）。
