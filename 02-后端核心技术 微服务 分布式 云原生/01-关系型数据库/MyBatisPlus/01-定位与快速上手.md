## 1. MP 与 MyBatis 的关系

**定位**：MyBatis-Plus（简称 MP）是 **MyBatis 的增强工具**——"只做增强，不做改变"：

| 维度 | MyBatis | MyBatis-Plus |
|------|:-------:|:------------:|
| 本质 | ORM 框架（XML/注解 SQL 映射） | MyBatis 的增强插件（工具库） |
| 关系 | **地基** | 建立在 MyBatis 之上（增强其能力） |
| 单表 CRUD | 手写 SQL 或通用 Mapper 扩展 | **内置 BaseMapper 通用方法（零 SQL）** |
| 复杂查询 | 手写 XML/动态 SQL | 同样手写（MP 不替代） |
| 底层 | SqlSessionFactory 等原生机制 | 复用 MyBatis 全部机制 + 拦截器增强 |

```text
MP 的增强原理（核心认知）：
BaseMapper 接口 → MP 在启动时用 SQL 注入器（AbstractSqlInjector）为接口方法
自动生成对应的 SQL（insert/selectById/selectList...）→ 注册进 MyBatis 的 MappedStatement
→ 你的 Mapper 接口扩展 BaseMapper 就"凭空"获得全套 CRUD

插件体系 → 通过 MyBatis 拦截器（Interceptor）在 SQL 执行前后改写
（分页加 LIMIT、逻辑删除加 WHERE、乐观锁加 version 校验）
```

**两个"不是"**：MP **不是** MyBatis 的替代品（底层仍是 MyBatis）；MP **不是** JPA 风格的重型 ORM（不管理实体生命周期、不做隐式脏检查）。

> 🎯 **核心要点**：MP = "**MyBatis + 免写单表 SQL + SQL 拦截增强**"——单表操作它包办，复杂 SQL 它让路（原生 XML）。"只做增强，不做改变"意味着：**学过的 MyBatis 知识全部保留有效**。

## 2. 版本选型与依赖坐标

**版本现状（2026-08 检索核实）**：最新版 **3.5.17（2026-07-08 发布）**，3.5.x 全线活跃。

**starter 坐标随 Spring Boot 版本变化**（关键！）：

| Spring Boot 版本 | starter 坐标 | 说明 |
|:----------------:|------------|------|
| 2.x | `mybatis-plus-boot-starter` | 老项目 |
| 3.x | `mybatis-plus-spring-boot3-starter` | 主流 |
| **4.x**（自 MP 3.5.13） | `mybatis-plus-spring-boot4-starter` | **Boot 4 必须用这个** |

```xml
<!-- Spring Boot 3.x 标准引入 -->
<dependency>
    <groupId>com.baomidou</groupId>
    <artifactId>mybatis-plus-spring-boot3-starter</artifactId>
    <version>3.5.17</version>
</dependency>

<!-- 3.5.9+ 分页等插件拆为可选依赖：分页必须额外引入！否则分页静默失效 -->
<dependency>
    <groupId>com.baomidou</groupId>
    <artifactId>mybatis-plus-jsqlparser</artifactId>
    <version>3.5.17</version>
</dependency>
<!-- JDK 8 项目用：mybatis-plus-jsqlparser-4.9（兼容旧版 jsqlparser） -->
```

**三条依赖红线**：

| 红线 | 原因 |
|------|------|
| 不引入 `mybatis`/`mybatis-spring-boot-starter`/`mybatis-spring` | 与 MP 版本冲突（MP 自带） |
| 3.5.9+ 不引 jsqlparser 就配分页 | 分页静默失效（不报错！） |
| 升级大版本前看 release notes | 3.5.x 有依赖拆分/包名调整（3.5.17 修了 JDK 9+ 模块化包重名） |

> 🎯 **核心要点**：版本选型 = **Boot 版本定 starter、3.5.9+ 定 jsqlparser、其余追 3.5.x Latest**——三个决策点记住，依赖配置不再踩坑（分页静默失效是最隐蔽的坑）。

## 3. 快速开始：5 分钟第一个 CRUD

```yaml
# application.yml 最小配置
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/demo?useSSL=false&serverTimezone=Asia/Shanghai
    username: root
    password: root

mybatis-plus:
  configuration:
    log-impl: org.apache.ibatis.logging.stdout.StdOutImpl   # 开发期打印 SQL
  global-config:
    db-config:
      id-type: assign_id          # 全局主键策略：雪花 ID
      logic-delete-field: deleted # 全局逻辑删除字段（可选，或注解）
      logic-delete-value: 1
      logic-not-delete-value: 0
```

```java
// ① 实体类
@Data
@TableName("user")                 // 表映射（驼峰转下划线可自动）
public class User {
    @TableId(type = IdType.ASSIGN_ID)   // 雪花 ID（默认策略，可省略）
    private Long id;
    private String name;
    private Integer age;
    @TableField(exist = false)     // 非表字段
    private String remark;
}

// ② Mapper：零方法定义，继承即得全套 CRUD
@Mapper
public interface UserMapper extends BaseMapper<User> { }

// ③ 使用：一个方法调用 = 一条 SQL
UserMapper mapper = ...;
mapper.insert(new User("张三", 25));                          // INSERT
User u = mapper.selectById(1L);                              // SELECT ... WHERE id=?
List<User> list = mapper.selectList(
        new LambdaQueryWrapper<User>().ge(User::getAge, 18)); // SELECT ... WHERE age >= 18
mapper.deleteById(1L);                                       // DELETE
```

**启动要求**：主类 `@MapperScan("com.example.mapper")`（或每个 Mapper 加 `@Mapper`）。

> 🎯 **核心要点**：MP 上手的全部动作 = **实体注解（表映射）+ 继承 BaseMapper（通用方法）+ 配置（逻辑删除/主键）**——三个文件（实体/Mapper/配置）即可开始 CRUD，这就是"效率提升数倍"的来源。

## 5. 核心配置速查（application.yml 全注解）

```yaml
mybatis-plus:
  # ① Mapper XML 位置（自定义 SQL 文件）
  mapper-locations: classpath*:/mapper/**/*.xml
  # ② 类型别名（XML resultType 可写短类名）
  type-aliases-package: com.example.entity
  # ③ 枚举处理器包（自动扫描枚举类型）
  type-enums-package: com.example.entity.enums
  configuration:
    # ④ SQL 日志（开发期；生产用 logback 控制级别）
    log-impl: org.apache.ibatis.logging.stdout.StdOutImpl
    # ⑤ 驼峰映射（默认开启）
    map-underscore-to-camel-case: true
    # ⑥ 缓存（默认关闭，开启二级缓存用）
    cache-enabled: false
  global-config:
    banner: false                 # 关启动 Banner
    db-config:
      id-type: assign_id          # 全局主键策略：雪花 ID
      logic-delete-field: deleted # 全局逻辑删除字段（可免注解）
      logic-delete-value: 1
      logic-not-delete-value: 0
      # 更新策略（默认 NOT_NULL：null 不更新）
      update-strategy: not_null
```

**配置要点记忆**：`mapper-locations`（XML 位置）、`log-impl`（SQL 日志）、`logic-delete-*`（逻辑删除）、`id-type`（主键）——**四个配置组覆盖日常 90% 需求**。
