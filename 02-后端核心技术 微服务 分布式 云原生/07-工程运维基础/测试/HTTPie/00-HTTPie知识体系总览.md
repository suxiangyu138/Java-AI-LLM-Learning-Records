## 4. HTTPie vs curl 定位对比

| 维度 | HTTPie | curl |
|------|--------|------|
| 设计目标 | **人类可读**（面向开发者日常调试） | 通用传输工具（面向脚本与传输） |
| 语法 | `http GET url key=value`（声明式 items） | `curl -X GET -H ... -d ...`（选项堆叠） |
| JSON | 自动序列化/高亮 | 需手动 `-H 'Content-Type: application/json' -d '...'` |
| 输出 | 语法高亮、自动格式化 | 原始输出 |
| 会话 | ✅ 内置 sessions（认证/Cookie 持久化） | ❌ 需手写 Cookie 管理 |
| 认证 | basic/digest/bearer + 插件 | basic/bearer 手写头 |
| 脚本化 | 适合人写的脚本 | **传输级脚本之王**（万用） |
| 存在度 | 日常 API 调试首选 | 系统级/传输级事实标准 |

> 🎯 一句话：**调试用 HTTPie（快、可读、少敲），传输用 curl（通用、无处不在）**——两者互补不互斥。

## 6. 核心概念速查

| 概念 | 一句话 |
|------|--------|
| `http` 命令 | HTTPie 主命令（别名 `httpie`） |
| items | 请求项声明语法：`key=value`、`key:value`、`key==value` 等 |
| 运算符 `=` | JSON 字段（自动序列化） |
| 运算符 `:=` | 原始 JSON 值（`age:=30`、嵌套对象） |
| 运算符 `:` | 请求头（`X-Auth:token`） |
| 运算符 `==` | URL 查询参数 |
| `@` 后缀 | 从文件读取（`key=@file.json`、`data:@file`） |
| `--session` | 命名/路径会话（认证、Cookie、头持久化） |
| `--offline` | 离线构建请求（不发送，输出完整命令） |
| `-A bearer` | Bearer 认证（3.0.0 原生） |
| `--stream` | 流式输出（SSE 自动流式） |
| `--pretty` | 输出格式化（all/colors/format/none） |
