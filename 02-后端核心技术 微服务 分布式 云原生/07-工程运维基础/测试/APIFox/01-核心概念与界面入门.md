## 1. APIFox 是什么

APIFox 是国产 **API 全生命周期一体化工具**：接口调试、接口文档、Mock、自动化测试、环境管理、团队协作在**一个平台**完成。核心设计哲学：

> 🎯 **"定义一次，处处联动"**：接口定义好后——文档自动生成、Mock 自动推导、测试自动关联、代码自动生成。传统工具链（Postman + Swagger + Mock + 测试框架）的"多次重复定义"被消除。

## 2. 三大核心模型

### 2.1 项目（Project）

| 维度 | 说明 |
|------|------|
| 类比 | Postman Workspace / Swagger 一个文档集 |
| 内容 | 接口、数据模型、环境、Mock、测试套件 |
| 协作 | 团队成员共享、分支管理、权限控制 |
| 使用 | 一个服务/一个端（前端/后端）一个项目 |

### 2.2 接口定义（API Definition）

```text
接口 = 方法 + 路径 + 参数定义 + 响应定义
  GET /api/orders/{orderId}
    ├─ Query/Path/Header 参数（类型、必填、默认、枚举）
    ├─ Body 定义（JSON Schema 级，支持嵌套对象/数组）
    ├─ 响应定义（成功/错误响应、字段类型）
    └─ 关联数据模型（复用公共 Schema）
```

| 定义能力 | 说明 |
|----------|------|
| 参数级定义 | 类型/必填/默认值/枚举/描述（驱动 Mock 与文档） |
| JSON Schema | 嵌套结构、数组、对象引用 |
| 数据模型 | 公共 Schema 复用（用户模型/订单模型） |
| 响应示例 | 多状态码示例（驱动文档与断言） |

### 2.3 环境（Environment）

```text
环境 = 一组变量的集合（dev / test / prod）
  ├─ 基础 URL：https://dev-api.company.com
  ├─ 鉴权 Token
  ├─ 数据库/Redis 地址（文档引用）
  └─ 任意自定义变量

使用：${baseUrl} / ${token} 插值
切换：一键切换环境，全部接口自动生效
```

| 变量层级 | 优先级 | 说明 |
|----------|:---:|------|
| 局部变量 | 高 | 单接口内定义 |
| 环境变量 | 中 | 当前环境 |
| 全局变量 | 低 | 所有环境共享 |

## 3. 核心功能矩阵

| 功能 | 说明 | 对应传统工具 |
|------|------|-------------|
| 接口调试 | 发送请求、查看响应、断言校验 | Postman |
| 接口文档 | 定义即文档，自动生成在线文档 | Swagger/ShowDoc |
| Mock | 智能 Mock + 期望规则 + 自托管 | Mockoon/Rap2 |
| 自动化测试 | 测试套件 + 场景编排 + 定时任务 | Postman Runner + Newman |
| 代码生成 | 一键生成 Java/Go/Python/TS 请求代码 | OpenAPI Generator |
| 导入导出 | Postman/OpenAPI/Hoppscotch 双向 | 迁移工具 |
| 团队协作 | 项目共享、分支、评论、变更记录 | Postman Team |
| AI 能力 | 文档自愈、CLI+Skill、MCP 调试 | - |

> 💡 对 Java 后端：接口定义 → 一键生成 Java（Feign/OkHttp/RestTemplate 风格）请求代码；后端重构 → 文档自愈自动更新（见 [07](07-AI能力与MCP调试.md)）。

## 5. 与 Postman 的差异对照

| 维度 | APIFox | Postman | 迁移注意 |
|------|--------|---------|---------|
| 接口管理 | 接口定义驱动一切 | Collection 即一切 | 概念映射：Collection → 项目 |
| 文档 | 内置自动生成 | 需额外工具 | 迁移后文档自动可得 |
| 环境 | 环境 + 全局 + 局部 | Environment + Globals | 变量语法兼容 `${var}` |
| 脚本 | JS 前后置脚本 | Pre-request/Test Scripts | 脚本 API 有差异（pm.* vs 内置） |
| Mock | 智能 Mock + 期望 | Mock Server | Mock 规则需重配 |
| 自动化 | 内置套件/场景/定时 | Runner + Newman | `apifox run` ≈ `newman run` |
| 协作 | 项目分支 + 成员 | Workspace 订阅 | 免费版协作能力更强 |
| 语言 | 中文原生 | 英文 | - |

> ⚠️ **迁移提示**：脚本语法是主要差异点——Postman 的 `pm.*` API 与 APIFox 内置脚本 API 不完全兼容，复杂脚本需改写（详见 [06](06-团队协作与导入导出.md)）。

## 6. 快速上手五步

```text
① 创建项目（个人/团队）
② 定义第一个接口（GET /api/hello，含响应示例）
③ 创建环境（dev + baseUrl 变量）
④ 发送请求验证（环境变量插值生效）
⑤ 查看自动生成的文档与 Mock（零配置即可用）
```

| 步骤 | 产出 |
|------|------|
| ① 项目 | 组织单元 |
| ② 接口定义 | 调试可用 + 文档雏形 |
| ③ 环境 | 多环境切换 |
| ④ 调试 | 验证通过 |
| ⑤ 文档/Mock | **定义即得**——这就是 APIFox 的核心体验 |

## 7. 核心要点

> 🎯 **核心要点**：
> - 三大模型：项目（容器）、接口定义（单一事实源）、环境（变量切换）；
> - 设计哲学："定义一次，处处联动"——文档/Mock/测试/代码生成全部从接口定义派生；
> - 变量三级：局部 > 环境 > 全局，`${var}` 插值语法与 Postman 兼容；
> - 与 Postman 最大差异：内置文档 + 智能 Mock + 一体化测试，免去多工具拼装；
> - 迁移注意：脚本 API（pm.*）是主要改写点。
