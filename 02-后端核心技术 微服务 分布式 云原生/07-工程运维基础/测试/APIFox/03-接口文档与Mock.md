## 1. 定义即文档

**核心体验**：接口定义完成后，文档**自动生成**——不需要单独写 Swagger 注解、不需要维护独立文档站。

| 文档内容 | 来源 |
|----------|------|
| 接口列表/分组 | 项目结构 |
| 参数说明（类型/必填/枚举/描述） | 接口定义 |
| 请求/响应示例 | 定义中的示例数据 |
| 数据模型 | 公共 Schema 引用 |
| 变更记录 | 接口修改历史 |
| 调试入口 | 文档页内直接"发送请求" |

> 🎯 与 Swagger 的本质区别：APIFox 是**"定义驱动文档"**（先定义后文档，可 Mock/可测试）；Swagger 是**"代码驱动文档"**（先注解后生成）。对前后端协作，定义驱动让"接口即契约"更早成立。

## 2. 文档的发布与共享

| 发布方式 | 说明 |
|----------|------|
| 在线文档链接 | 一键生成分享链接（无需登录可看） |
| 团队内共享 | 项目成员直接查看 |
| 导出 | Markdown/OpenAPI/HTML |
| 权限控制 | 公开/内部/私密 |

```text
文档页典型结构：
├─ 项目概览（接口数量、状态统计）
├─ 接口列表（按目录/标签分组）
├─ 单个接口（参数表 + 示例 + 调试按钮）
└─ 数据模型（公共 Schema 引用）
```

> 💡 **协作价值**：前端拿文档链接即可开始联调（带 Mock 地址）；后端重构后文档自动更新（配合 AI 自愈，见 [07](07-AI能力与MCP调试.md)）。

## 3. 智能 Mock：零配置生成测试数据

### 3.1 原理

```text
基于 Mock.js 引擎 + 接口定义的 JSON Schema：
  字段类型（string/number/boolean/array/object）
  + 字段名语义（name/phone/email/age...）
  + 枚举/格式约束
  → 自动推导"像模像样"的测试数据
```

| 字段 | 生成示例 |
|------|---------|
| `name: string` | 真实中文姓名（张三、李四...） |
| `age: number` | 合理年龄范围（18-60） |
| `phone: string` | 有效手机号（1xx-xxxx-xxxx） |
| `email: string` | 合法邮箱 |
| `status: enum` | 从枚举值随机 |
| 嵌套对象/数组 | 结构完整推导 |

### 3.2 高级 Mock 能力（2026）

| 能力 | 说明 |
|------|------|
| 字段关联维护 | 省市区联动（选择了省份，城市列表自动匹配） |
| 团队共享 Mock 规则 | 团队级 Mock 规则复用 |
| AI 自愈联动 | 后端重构后旧字段 Mock 规则自动迁移到新字段 |
| 稳定性优化 | Mock 数据生成表现更稳定（2026-05） |

```javascript
// 自定义 Mock 规则（字段级）
"id": "@guid()",                    // Mock.js 语法
"createTime": "@datetime('yyyy-MM-dd HH:mm:ss')",
"amount": "@float(1, 1000, 2, 2)"  // 1~1000 元，两位小数
```

> ⚠️ Mock 数据"像模像样"≠ 业务真实：联调用 Mock，测试用真实数据——Mock 的使命是**让前端开发不阻塞**，不是替代测试。

## 4. 期望（Expectation）：Mock 规则引擎

期望 = 按条件匹配请求，返回指定响应：

```text
期望匹配逻辑：
请求到达 Mock 服务
  → 匹配条件（路径/方法/参数值/Header）
  → 命中期望 → 返回预设响应
  → 未命中 → 返回智能 Mock 默认响应
```

| 期望要素 | 说明 |
|----------|------|
| 匹配条件 | 入参值、Header、路径参数 |
| 响应内容 | 指定 JSON/状态码/延迟 |
| 延迟模拟 | 模拟慢接口（网络超时场景） |
| 状态码 | 200/400/500 等（错误场景模拟） |

```javascript
// 示例：orderId=999 时返回"订单不存在"
期望匹配：path = /api/orders/{orderId}，orderId = 999
响应：{"code": 404, "msg": "订单不存在", "data": null}
```

| 联调场景 | 期望用法 |
|----------|---------|
| 前端错误处理开发 | 期望返回 400/500 场景 |
| 慢接口/超时模拟 | 期望设置响应延迟 |
| 特殊数据场景 | 期望按参数返回定制数据 |
| 前后端并行 | 后端未实现，前端用期望驱动开发 |

## 5. 自托管 Mock Runner

**场景**：Mock 服务需在内网/离线（air-gapped）环境运行，满足合规要求。

```bash
# 自托管 Mock Runner（Docker 容器交付）
docker run -d \
  -p 3000:3000 \
  -e APIFOX_TOKEN=<项目令牌> \
  apifox/mock-runner:latest
```

| 特性 | 说明 |
|------|------|
| 部署方式 | Docker 容器，私有服务器 |
| 网络要求 | 内网/离线可用（物理隔离） |
| 安全 | 2026-05 支持容器内服务以**非 root 用户**运行 |
| 数据同步 | 从项目拉取接口定义与期望 |
| 合规 | 数据不出内网 |

> 💡 自托管适用：银行/政务等数据合规场景；普通团队直接用 APIFox 云端 Mock 即可。

## 6. Mock 与联调工作流

```text
后端先行定义接口 → 前端打开 Mock 开关 → 前端按 Mock 地址开发
        ↓
后端实现完成 → 切换真实环境（${baseUrl} 切换）
        ↓
联调验证 → 发现字段差异 → 后端改定义 → 前端重新拉取
```

| 阶段 | 前端使用 | 后端使用 |
|------|---------|---------|
| 定义期 | 看文档 + 智能 Mock | 写接口定义 |
| 开发期 | Mock 地址开发（零阻塞） | 实现接口 |
| 联调期 | 切真实环境 | 修复差异 |
| 测试期 | 配合自动化测试 | 看测试报告 |

> 🎯 **关键价值**：Mock 让前后端**彻底并行**——后端实现进度不再阻塞前端开发，接口定义成为唯一的契约。

## 7. 核心要点

> 🎯 **核心要点**：
> - 定义即文档：不需要 Swagger 注解，接口定义自动生成文档（可发布/导出/调试）；
> - 智能 Mock：Mock.js + JSON Schema 推导，字段名语义驱动"像模像样"的数据；
> - 期望引擎：按条件匹配返回定制响应（错误码/延迟/特殊数据）——前端错误处理开发的利器；
> - 自托管 Runner：Docker 部署，内网/离线合规场景专用；
> - 工作流：定义先行 → Mock 先行 → 前后端零阻塞并行；
> - Mock 是联调手段，不是测试替代品。
