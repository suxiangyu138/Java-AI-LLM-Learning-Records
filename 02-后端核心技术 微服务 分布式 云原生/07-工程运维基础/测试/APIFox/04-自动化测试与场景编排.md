## 1. 测试体系层级

```text
接口用例（单接口）→ 场景用例（多接口链路）→ 测试套件（用例集合）→ 定时任务/CI
    断言              数据流转              回归策略              持续执行
```

| 层级 | 粒度 | 回答的问题 |
|------|------|-----------|
| 接口用例 | 单接口 | 这个接口的入参/响应正确吗？ |
| 场景用例 | 业务链路 | 登录→下单→支付整条链路通吗？ |
| 测试套件 | 用例集合 | 本轮回归要跑哪些用例？ |
| 定时/CI | 持续执行 | 代码变更后自动验证了吗？ |

## 2. 单接口用例与断言

```text
接口用例 = 请求配置（参数/环境/鉴权）+ 前置脚本 + 断言 + 后置脚本
```

| 用例要素 | 说明 |
|----------|------|
| 请求配置 | 复用接口定义，可覆盖参数值 |
| 环境选择 | 指定运行环境（dev/test/prod） |
| 前置脚本 | 请求前执行（生成签名/时间戳） |
| 断言 | 响应校验（见第 3 节） |
| 后置脚本 | 提取变量/清理数据 |

```javascript
// 用例后置脚本：提取下单返回的 orderId 供后续用例使用
const json = response.json;
apifox.setEnvVariable("orderId", json.data.orderId);
```

## 3. 断言库全解

| 断言类型 | 说明 | 示例 |
|----------|------|------|
| 状态码 | 响应状态码校验 | `期望 200` |
| 响应时间 | 耗时上限 | `< 1000ms` |
| 字段断言 | 字段值/类型/存在性 | `data.orderId 存在` |
| 枚举校验 | 字段值在指定集合 | `status ∈ [SUCCESS, FAIL]` |
| JSON Schema | 响应结构校验 | 与接口定义 Schema 匹配 |
| 自定义脚本 | 复杂业务校验 | 见下 |

```javascript
// 自定义断言脚本示例
const json = response.json;

// 1. 业务码校验
apifox.assert(json.code === 200, "业务码应为 200");

// 2. 数据完整性
apifox.assert(json.data && json.data.length > 0, "数据列表不应为空");

// 3. 金额精度校验（Java 后端常见场景）
apifox.assert(Math.abs(json.data.amount - 99.90) < 0.001, "金额精度错误");

// 4. 字段间逻辑校验
apifox.assert(json.data.total === json.data.items.length * json.data.unitPrice, "总价计算错误");
```

> 🎯 断言是测试的"眼睛"：**状态码通过 ≠ 业务正确**——业务码、字段值、计算逻辑的断言才是 API 测试的核心价值。

## 4. 前后置脚本

### 4.1 前置脚本（请求前）

```javascript
// 场景：动态签名（时间戳 + 密钥 + MD5）
const ts = Date.now().toString();
const sign = md5(`orderId=${apifox.getVariable("orderId")}&ts=${ts}&key=${secretKey}`);
apifox.setEnvVariable("ts", ts);
apifox.setEnvVariable("sign", sign);
```

### 4.2 后置脚本（请求后）

```javascript
// 场景：登录后提取 token，供后续用例使用
const json = response.json;
apifox.setEnvVariable("token", json.data.accessToken);

// 场景：分页数据循环校验
if (json.data.list) {
    json.data.list.forEach(item => {
        apifox.assert(item.id != null, "列表项 id 不应为空");
    });
}
```

| 脚本能力 | 说明 |
|----------|------|
| 变量读写 | `apifox.getVariable` / `setEnvVariable` / `setGlobalVariable` |
| 内置函数 | md5/sha1/base64/uuid/randomInt 等 |
| 断言 | `apifox.assert(condition, message)` |
| 日志 | `console.log`（控制台查看） |
| 兼容层 | `pm.*` API 兼容（Postman 迁移） |

## 5. 场景用例：业务链路编排

```text
场景：用户下单全流程
 ① 登录（提取 token）
 ② 创建订单（提取 orderId）
 ③ 支付订单（使用 orderId + token）
 ④ 查询订单（断言状态 = PAID）
 ⑤ 取消订单（断言可取消）
```

| 场景能力 | 说明 |
|----------|------|
| 步骤顺序 | 按编排顺序执行（支持条件跳过） |
| 数据流转 | 上一步提取变量 → 下一步使用 |
| 依赖控制 | 前置步骤失败可中止后续 |
| 参数覆盖 | 每步可覆盖接口默认参数 |
| 断言位置 | 每步独立断言 + 场景级断言 |

```javascript
// 场景用例的变量流转示意
// 步骤 ① 后置：apifox.setEnvVariable("token", ...)
// 步骤 ② 后置：apifox.setEnvVariable("orderId", ...)
// 步骤 ③ 请求体：{"orderId": "${orderId}"}  ← 自动插值
```

> 💡 场景用例的价值：**接口单独都对，链路不一定通**——token 流转、状态依赖、数据关联只有链路测试能覆盖。

## 6. 测试套件（Test Suite）

**测试套件** = 单接口用例 + 场景用例的集合，两种运行模式（2026-01 发布）：

| 模式 | 说明 | 适用 |
|------|------|------|
| **静态模式** | 精确指定测试项、灵活调整顺序 | 稳定回归集（固定用例） |
| **动态模式** | 按规则自动筛选最新用例 | 持续集成（用例持续新增） |

```text
套件组成：
├─ 单接口用例（直接执行）
├─ 场景用例（链路执行）
└─ 运行配置（环境/并发/超时/失败中止策略）
```

| 套件能力 | 说明 |
|----------|------|
| 用例选择 | 静态勾选 / 动态规则筛选 |
| 运行环境 | 指定环境运行 |
| 并发控制 | 串行/并发执行 |
| 失败策略 | 失败即停 / 失败继续 |
| 定时绑定 | 关联定时任务（见第 8 节） |

## 7. 测试报告与定位

**测试报告重构**（2026-01）：结构化展示所有测试步骤，层次关系更清晰。

| 报告维度 | 内容 |
|----------|------|
| 总览 | 通过/失败/跳过、成功率、耗时 |
| 分层展示 | 套件 → 用例 → 步骤 层级钻取 |
| 失败详情 | 断言失败信息、请求/响应快照 |
| 耗时分析 | 慢接口定位 |
| 历史对比 | 与上次运行对比（回归趋势） |
| 导出 | 报告导出分享（CI 集成见 [05](05-CLI与CI-CD集成.md)） |

> 💡 失败定位三步：报告看失败用例 → 点开看失败断言 → 对照请求/响应快照——APIFox 的报告自带请求快照，无需复现即可定位大部分问题。

## 8. 定时任务与回归

```text
定时任务 = 测试套件 + 定时触发 + 报告通知
```

| 定时能力 | 说明 |
|----------|------|
| 触发频率 | 每小时/每天/每周（2026-06 新增"每 8 小时"） |
| 执行范围 | 指定套件/场景 |
| 结果通知 | 失败通知到企业微信/钉钉/邮件/Webhook |
| 报告留存 | 历史报告对比 |

> 💡 落地建议：**每日定时跑全量回归 + 变更时跑定向回归**——定时任务保证"没人在意的时候也在验证"。

## 9. 核心要点

> 🎯 **核心要点**：
> - 四层体系：接口用例（单接口）→ 场景用例（链路）→ 测试套件（回归集）→ 定时/CI（持续）；
> - 断言是眼睛：状态码通过 ≠ 业务正确——业务码/字段值/计算逻辑都要断言；
> - 前后置脚本串联数据流：提取 token/orderId → 下一步插值使用（场景用例的血液）；
> - 套件双模式：静态（固定回归集）/ 动态（规则筛选最新用例）；
> - 失败定位三步：报告 → 失败断言 → 请求快照；
> - 定时任务让回归"无人值守持续验证"。
