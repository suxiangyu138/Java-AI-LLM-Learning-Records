## 4. APIFox vs Postman 定位对比

| 维度 | APIFox | Postman |
|------|--------|---------|
| 定位 | **API 全生命周期一体化**（调试+文档+Mock+测试+协作） | 接口调试工具 + 生态 |
| 文档 | 内置自动生成（接口定义即文档） | 需 Postman API 或独立文档工具 |
| Mock | 内置 Mock.js 智能 Mock | 需 Mock Server 配置 |
| 自动化测试 | 内置测试套件/场景编排 | Runner + Newman（命令行） |
| 中文支持 | ✅ 原生中文 | ⚠️ 英文为主 |
| 团队协作 | 内置项目协作/分支 | 需 Workspace 付费 |
| AI 能力 | 文档自愈、CLI+Skill for Agent、MCP 调试 | Copilot（部分付费） |
| 国内访问 | ✅ 快 | ⚠️ 需代理 |
| 适用 | **国内团队、前后端协作、测试驱动开发** | 国际团队、既有生态 |

> 🎯 一句话：Postman 是"调试工具"，APIFox 是"API 工作台"——定义一次接口，文档/Mock/测试/协作全部自动联动。

## 6. 核心概念速查

| 概念 | 一句话 |
|------|--------|
| 项目（Project） | 组织接口/文档/测试的容器（类似 Postman Workspace） |
| 接口定义 | 一次定义，文档/Mock/测试/代码生成联动 |
| 环境（Environment） | 变量集合（dev/test/prod），一键切换 |
| 环境变量 | `${baseUrl}` 插值，支持全局/环境/局部三级 |
| Mock | 基于接口 Schema 自动生成"像模像样"的测试数据 |
| 期望（Expectation） | Mock 返回规则的匹配条件（入参匹配 → 指定响应） |
| 测试套件（Test Suite） | 单接口用例 + 场景用例的集合（静态/动态模式） |
| 场景用例 | 多接口串联编排（登录 → 下单 → 支付） |
| 断言 | 响应校验（状态码/字段/JSON Schema/自定义脚本） |
| 前后置脚本 | 请求前/后执行 JS 脚本（生成签名、提取变量） |
| `apifox run` | CLI 执行测试（CI 集成入口） |
| 文档自愈 | AI 感知代码变更自动更新接口文档 |
