## 1. 接口定义四要素

```text
接口 = 方法 + 路径 + 请求定义 + 响应定义
```

| 要素 | 内容 | 驱动能力 |
|------|------|---------|
| 方法/路径 | GET/POST/PUT/DELETE + `/api/orders/{orderId}` | 调试、文档 |
| 请求定义 | Query/Path/Header/Body 参数（类型/必填/枚举/描述） | Mock 推导、代码生成 |
| 响应定义 | 多状态码响应 + JSON Schema | 文档、断言、Mock |
| 元信息 | 标签、描述、负责人、变更记录 | 团队协作 |

```yaml
# 接口定义示意（结构层面）
GET /api/orders/{orderId}
  path: orderId (string, required, "订单号")
  query: includeItems (boolean, optional)
  header: X-Trace-Id (string, optional)
  responses:
    200: OrderDetail (数据模型引用)
    404: ErrorResponse
```

> 🎯 定义质量决定一切：参数类型/枚举/描述写得越完整，Mock 越逼真、文档越可用、测试断言越精准——**接口定义是 APIFox 所有能力的上游**。

## 2. 请求参数构造

| 参数类型 | 支持能力 | 调试要点 |
|----------|---------|---------|
| Path | 路径参数（`{orderId}`） | 调试时填实际值 |
| Query | 键值对，支持数组/嵌套 | 排序/分页参数 |
| Header | 自定义头 | 鉴权头、Trace 头 |
| Body | form-data / x-www-form-urlencoded / JSON / XML / 二进制 | JSON 自动校验格式 |
| Cookie | 携带 Cookie | 会话场景 |

```text
调试页发送流程：
① 选择环境（baseUrl 生效）
② 填写参数（Path/Query/Header/Body）
③ 点"发送"→ 响应区显示状态码/耗时/响应体
④ 一键复制为 cURL / 生成代码（Java/Go/Python/TS）
```

> 💡 **代码生成**：调试通过后一键生成 Java 请求代码（RestTemplate/OkHttp/Feign 风格）——前端拿 TS/Fetch 代码，后端拿 Java 代码，接口联调零手写。

## 3. 环境变量与动态值

### 3.1 变量插值

```text
${baseUrl}          → https://dev-api.company.com
${token}            → 登录后提取的 Token
${randomInt(1,100)} → 内置动态函数
```

| 内置动态函数 | 说明 | 示例 |
|--------------|------|------|
| `randomInt(min,max)` | 随机整数 | `${randomInt(1,100)}` |
| `randomString(n)` | 随机字符串 | `${randomString(8)}` |
| `timestamp()` | 当前时间戳 | `${timestamp()}` |
| `date()` | 格式化日期 | `${date('yyyy-MM-dd')}` |
| `uuid()` | UUID | `${uuid()}` |

### 3.2 变量提取（后置脚本）

```javascript
// 登录接口后置脚本：提取 token 存入环境变量
const json = pm.response.json();        // 兼容 pm.* 风格
apifox.setEnvironmentVariable("token", json.data.token);
```

```javascript
// 或内置风格
const json = response.json;
apifox.setEnvVariable("token", json.data.token);
```

### 3.3 变量作用域与优先级

```text
局部变量（接口内） > 环境变量（当前环境） > 全局变量（所有环境）
```

> ⚠️ 与 Postman 的差异：脚本 API 有 `pm.*` 兼容层与 APIFox 内置 API 两套写法——迁移时优先用兼容层，新脚本用内置 API。

## 4. 鉴权配置

| 鉴权类型 | 配置位置 | 说明 |
|----------|---------|------|
| No Auth | - | 公开接口 |
| Bearer Token | 接口/环境级 | `Authorization: Bearer ${token}` |
| Basic Auth | 接口级 | 用户名/密码 |
| API Key | Header/Query | 自定义 key 位置 |
| OAuth 2.0 | 环境级 | **2026-06 支持自动刷新令牌**（临近过期自动刷新，持久化保存） |
| 自定义鉴权脚本 | 前置脚本 | 动态签名（时间戳+密钥+MD5 等） |

```javascript
// 自定义签名前置脚本示例（Java 后端常见）
const ts = Date.now().toString();
const sign = md5(ts + secretKey);          // 业务自定义签名
apifox.setEnvVariable("ts", ts);
apifox.setEnvVariable("sign", sign);
```

> 💡 **OAuth 2.0 自动刷新**（2026-06）：Access Token 临近过期或已过期时自动完成刷新，减少因 token 失效导致的请求中断；刷新后的 token 可持久化保存——长链路自动化测试不再被 token 过期打断。

## 5. 发送与响应查看

| 响应查看能力 | 说明 |
|--------------|------|
| 状态码/耗时 | 每次请求的状态与耗时统计 |
| 响应体格式化 | JSON/XML 高亮、折叠、搜索 |
| 响应头 | 全部响应头（Set-Cookie 等） |
| 断言结果 | 内联显示断言通过/失败 |
| 控制台 | 脚本 console 输出 |
| 请求快照 | 对比"实际发送的请求"与"定义" |

> 💡 请求快照是排查利器：响应不对时先看"实际发送了什么"——参数/Header/鉴权是否按预期。

## 6. 网络信息查看（2026 新能力）

| 网络信息 | 说明 | 排查价值 |
|----------|------|---------|
| HTTP 版本 | 1.1 / 2 / 3 | 确认协议协商结果 |
| TLS 协议 | TLS 1.2 / 1.3 | 证书/加密配置排查 |
| 连接信息 | 本地地址、远端地址 | 代理/网络路径 |
| DNS 信息 | 解析结果 | 域名配置排查 |

> 💡 场景：接口偶发失败 → 查看 TLS 版本与连接复用情况；前后端协议不一致（HTTP/2 特性未生效）→ 看 HTTP 版本。

## 7. SSE 与流式接口调试

```text
SSE（Server-Sent Events）：服务端单向推送（AI 对话流式输出、实时通知）
```

| 调试能力 | 说明 |
|----------|------|
| 流式响应展示 | 实时显示 `data:` 事件流 |
| 事件类型区分 | event/data/id/retry 字段解析 |
| 断点续看 | 支持 `\r\n` 换行符（2026-05 兼容） |
| 超时控制 | 长连接调试不中断 |

> 💡 **AI 场景**：调试大模型流式接口（DeepSeek/通义 SSE 输出）时，APIFox 直接查看事件流比浏览器/终端更清晰——配合 [07](07-AI能力与MCP调试.md) 的 MCP 调试能力覆盖 Agent 工具链。

## 8. 前端/后端协作最佳实践

| 实践 | 说明 |
|------|------|
| 后端先行定义 | 后端定义接口 → 前端直接用 Mock 联调 |
| 环境分离 | dev/test/prod 三环境，`${baseUrl}` 切换 |
| 变更通知 | 接口修改自动通知团队成员 |
| 评论闭环 | 接口级评论（参数含义、返回结构疑问） |
| 版本记录 | 变更历史可回溯 |
| Mock 先行 | 前端开发不阻塞（后端未实现也能联调） |

## 9. 核心要点

> 🎯 **核心要点**：
> - 接口定义四要素（方法/路径/请求/响应）是所有能力的上游——定义质量决定一切；
> - 变量三级 + 动态函数（randomInt/uuid/timestamp）+ 后置提取 = 动态请求构造；
> - 鉴权四件套：Bearer/API Key/OAuth2（2026 支持自动刷新）/自定义签名脚本；
> - 排查三看：请求快照（发了什么）→ 网络信息（HTTP 版本/TLS）→ 控制台（脚本输出）；
> - SSE 流式调试覆盖 AI 接口场景；
> - 协作模式：定义先行 + Mock 先行，前后端零阻塞。
