## 2. 终端效率：Shell与命令行

### 2.1 常用命令组合

```bash
# 查找包含特定字符串的Java文件
grep -r "TODO" --include="*.java" src/

# 查找并删除target目录
find . -name "target" -type d -exec rm -rf {} +

# 查看端口占用
netstat -ano | grep 8080          # Windows
lsof -i :8080                     # Mac/Linux

# Git日志美化
git log --graph --oneline --decorate --all -20

# 查找大文件
find . -type f -size +100M

# JSON格式化
curl -s http://api/users/1 | python -m json.tool
# 或
curl -s http://api/users/1 | jq .

# 统计代码行数
find . -name "*.java" | xargs wc -l | tail -1

# Git统计个人贡献
git log --author="YourName" --oneline --since="2024-01-01" | wc -l
```

## 3. 自动化脚本

### 3.1 一键启动开发环境

```bash
#!/bin/bash
# dev-start.sh - 一键启动所有开发依赖

echo "Starting MySQL..."
docker start mysql-dev 2>/dev/null || \
  docker run -d --name mysql-dev -p 3306:3306 -e MYSQL_ROOT_PASSWORD=root mysql:8.0

echo "Starting Redis..."
docker start redis-dev 2>/dev/null || \
  docker run -d --name redis-dev -p 6379:6379 redis:7-alpine

echo "Starting Nacos..."
docker start nacos-dev 2>/dev/null || \
  docker run -d --name nacos-dev -p 8848:8848 -e MODE=standalone nacos/nacos-server:v2.2.3

echo "All services started! 🚀"
```

### 3.2 Git提效脚本

```bash
#!/bin/bash
# git-sync.sh - 同步所有远程分支并清理本地已删除的远程分支

git fetch --all --prune
git branch -vv | grep ': gone]' | awk '{print $1}' | xargs -r git branch -D
echo "Branches synced! ✅"
```

### 3.3 日志分析脚本

```bash
#!/bin/bash
# analyze-errors.sh - 统计今天的错误日志Top10

grep "$(date +%Y-%m-%d)" /var/log/app/error.log | \
  grep -oP 'Exception: \K.*' | sort | uniq -c | sort -rn | head -10
```

## 4. AI辅助编程

### 4.1 AI能帮你做什么

| 场景 | 示例Prompt |
|------|-----------|
| **生成代码** | "写一个SpringBoot @ControllerAdvice 统一异常处理" |
| **代码审查** | "Review这段代码，关注NPE风险和性能问题" |
| **SQL优化** | "分析这个SQL的执行计划，建议优化方案" |
| **单元测试** | "为这个Service方法生成JUnit5测试，覆盖正常和异常路径" |
| **正则表达式** | "写一个匹配中国大陆手机号的正则表达式" |
| **重构建议** | "这段代码有哪些可以改进的地方？用更加函数式的方式重写" |
| **API文档** | "给这个Controller生成Swagger注解" |
| **解释代码** | "解释这段代码的逻辑，特别是递归部分" |

### 4.2 AI使用原则

```
✅ AI加速器模式（推荐）：
  "先理解 → 让AI生成初稿 → 审查修改 → 测试验证"
  你始终是代码质量和正确性的最终负责人

❌ AI黑箱模式（危险）：
  "Ctrl+C → Ctrl+V → 能跑就上线"
  不理解代码逻辑、不审查潜在Bug、不测试就提交
```
