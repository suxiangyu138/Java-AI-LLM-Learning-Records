## 2. 模型 API 层：OpenAI 兼容协议是通用语言

### 2.1 为什么以 OpenAI 为纲

OpenAI 的 Chat Completions 接口已成为事实标准：DeepSeek、Qwen（百炼）、Ollama、vLLM 等全部提供 OpenAI 兼容端点。**掌握 OpenAI 协议 ≈ 掌握所有主流模型的调用方式**，换模型只改 `base_url` + `model` 两个参数。

### 2.2 OpenAI 精读章节清单

| 主题 | 章节 | 面试/实战触点 |
|------|------|---------------|
| Chat Completions | Messages API（system/user/assistant 角色、temperature/top_p/max_tokens） | 请求结构、token 计价 |
| Streaming | 流式输出（SSE、delta 增量） | 打字机效果实现 |
| Tool Calling | function calling（tools 定义、tool_choice、并行调用） | Agent 核心能力 |
| Structured Outputs | json_schema / json_mode | 结构化数据抽取 |
| Token 与限流 | Tokenizer、Rate limits（TPM/RPM）、计费页 | 成本估算、限流策略 |
| Embeddings | 嵌入模型与用法 | RAG 前置 |

> 🎯 **核心要点**：读 OpenAI 文档时关注**协议语义而非产品细节**——"messages 数组如何表达多轮对话""tools 定义与调用回传闭环""流式与工具调用的组合"这三点是全部 Agent 应用的地基。

## 3. DeepSeek / Qwen / Anthropic

### 3.1 DeepSeek（国内主力）

| 主题 | 要点 |
|------|------|
| 兼容性 | OpenAI 兼容（`https://api.deepseek.com` 或 `/v1`），现有 OpenAI 代码可直接切换 |
| 模型 ID | `deepseek-chat`（非思考）、`deepseek-reasoner`（思考模式）——注意 ID 指向的底层模型由官方滚动更新 |
| 能力 | 工具调用、结构化输出、较长上下文 |
| 精读 | 官方文档的"快速开始 → 模型列表 → 工具调用 → 推理模式"四节 |

> ⚠️ **模型 ID 陷阱**：`deepseek-chat` 指向的版本会随官方发布滚动（历史上从 V2 一路到 V3.x），接口代码不变但能力/价格变化——以官方文档模型页为准，不要写死对旧版本的假设。

### 3.2 Qwen（通义千问 / 百炼）

| 主题 | 要点 |
|------|------|
| 双入口 | 开源模型文档（qwen.readthedocs.io）+ 阿里云百炼（help.aliyun.com/zh/model-studio） |
| 模型矩阵 | `qwen-max` / `qwen-plus` / `qwen-turbo`（API），Qwen3 开源系列（本地部署） |
| 能力 | 工具调用、结构化输出、多模态；DashScope SDK 与 OpenAI 兼容端点并存 |
| 精读 | 百炼的"模型广场 → API 文档（chat/tool）→ 数据管理（RAG 场景）" |

### 3.3 Anthropic Claude（可选项）

| 主题 | 要点 |
|------|------|
| Messages API | 与 OpenAI 结构相近但角色/工具定义不同（tools 定义、`tool_use`/`tool_result` 回环） |
| MCP | 官方力推 Model Context Protocol，Agent 生态标准 |
| 精读 | Messages 概览 → Tool use → Streaming → MCP |

## 4. 应用框架层：LangChain / LangChain4j / Spring AI

### 4.1 LangChain（Python，v1）

| 主题 | 章节 | 要点 |
|------|------|------|
| v1 起点 | Introduction / Getting Started | **2025-10 发布 v1.0**，API 大改，旧教程全部过时 |
| 核心抽象 | Chat Models / Prompt / Output Parsers | 概念与 OpenAI 协议一一对应 |
| RAG | Retrieval（Retriever/Vector Store/Embedding）、Document Loaders | RAG 标准链路 |
| Agent | Tools / Agents（AgentExecutor → 新 Agent 接口） | 工具闭环 |
| 组合 | LCEL（LangChain Expression Language） | 管道式组装 |
| 集成 | Integrations（DeepSeek、Milvus 等第三方） | 按需查表 |

> ⚠️ **中文站已弃用**：LangChain 官方中文文档站（python.langchain.ac.cn）随 v1.0 发布已标记弃用不再维护，一律以 python.langchain.com 为准。

### 4.2 LangChain4j（Java 生态）

| 主题 | 要点 |
|------|------|
| 定位 | Java 版 LangChain：AiServices、ChatLanguageModel 抽象 |
| 精读 | Getting Started → AiServices（结构化输出/工具绑定）→ RAG（EmbeddingStore/Retriever）→ Tools |
| 场景 | 已有 Java 后端团队做 AI 功能时的首选集成层 |

### 4.3 Spring AI（Java 生态，详细见 [01](01-Java生态与JVM官方文档.md) 第 5 节）

| 主题 | 要点 |
|------|------|
| 定位 | Spring 官方 AI 框架：ChatClient、Advisors、Tool Calling、RAG/向量库、MCP、评估 |
| 版本 | 2.0.x ↔ Boot 4.x；1.1.x ↔ Boot 3.5.x |
| 场景 | Java 单体/微服务内嵌 AI 能力（比 LangChain4j 更贴近 Spring 全家桶） |

> 🎯 **框架三选一策略**：Python 为主 → LangChain v1；Java 后端为主 → Spring AI 或 LangChain4j（Spring AI 2.x 与 Boot 4 对齐优先）；纯工具链 → 不引框架直接调 OpenAI 兼容 API（最小依赖方案）。

## 5. 向量数据库：Milvus 与其他

### 5.1 Milvus（RAG 首选精读）

| 主题 | 章节 | 要点 |
|------|------|------|
| 数据模型 | Collections/Fields/Entities | 与关系表概念对照 |
| 索引 | 索引类型（HNSW/IVF/扁平）、索引参数 | 召回率 vs 内存 vs 延迟 |
| 检索 | 向量相似度检索、标量过滤、**混合检索（3.x 支持稀疏+稠密）** | RAG 精度关键 |
| 部署 | Standalone / Cluster、分片与副本 | 规模扩展 |
| 集成 | 与 LangChain/Spring AI/SDK 对接 | 工程落地 |

### 5.2 其他向量库（按需）

| 库 | 地址 | 场景 |
|----|------|------|
| Qdrant | https://qdrant.tech/documentation/ | 生产级独立服务（Rust 实现） |
| Chroma | https://docs.trychroma.com/ | 轻量/原型 |
| PGVector | https://github.com/pgvector/pgvector | 复用 PostgreSQL 存储 |
| FAISS | https://github.com/facebookresearch/faiss | 内存级高性能检索（Python） |
| Elasticsearch | 详见 [02](02-中间件官方文档.md) | 文本+向量一体 |

> 💡 选型文档阅读顺序：先读 Milvus 完整（概念最全），再按需求比对 Qdrant/PGVector 的官方对比章节，最后定方案。

## 8. 本方向避坑清单

| # | 坑 | 规避 |
|---|----|------|
| 1 | 教程/博客基于旧版 LangChain（0.x/1.0 前） | 一律以 python.langchain.com v1 文档为准 |
| 2 | 中文文档站滞后或弃用（LangChain、部分 Spring 文档） | 英文官方站点为主，中文站只做辅助理解 |
| 3 | 模型 ID 写死旧版本假设 | 以官方模型列表页为唯一事实源 |
| 4 | Spring AI 版本与 Boot 不对齐 | 2.x ↔ Boot 4.x；1.1.x ↔ Boot 3.5.x |
| 5 | 向量库选型只看评测不看官方文档 | 索引类型与检索语义（混合检索支持）以官方文档为准 |
| 6 | OpenAI 兼容 ≠ 完全兼容 | 部分能力（工具调用 strict 模式、结构化输出细节）各厂商实现有差异，读各厂商文档核实 |
| 7 | 只看框架不看 API | 框架文档建立在 API 概念上，API 层薄弱则框架学不透 |
