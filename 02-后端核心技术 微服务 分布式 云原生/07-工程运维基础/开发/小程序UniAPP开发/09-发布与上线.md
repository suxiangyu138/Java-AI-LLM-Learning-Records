## 1. 上线前置配置

上线前的三件配置（缺一不可）：**AppID**——微信公众平台注册小程序获取（个人/企业主体——**「测试号只能开发，正式上线要注册 AppID」**）——manifest.json 填写（03 篇）；**服务器域名**——小程序后台配置 **request 合法域名**（HTTPS——05 篇域名限制）——**「域名不配，线上请求全挂」**；**业务域名**（H5/网页跳转场景）。**配置的流程**：注册小程序 → 获取 AppID → manifest 填 AppID → 后台配域名（开发/上线双配置——**「开发环境可关校验，上线必须配齐」**）。

## 2. 版本形态

微信小程序的版本形态（发布流程的认知基础）：**开发版**（工具里预览——开发者自己调试）；**体验版**（上传后选为体验版——**体验成员可扫码测试**——上线前验证）；**审核版**（提交审核的版本——平台审核中）；**正式版**（审核通过发布——用户可见）——**「版本的流转：开发 → 体验 → 审核 → 正式」**——**「体验版是上线前的最后验证关卡」**（真机环境、域名配置、正式 AppID 全在体验版暴露问题）。

## 3. 微信小程序发布流程

发布全流程（从工具到线上）：**第一步，工具上传**——微信开发者工具「上传」（填版本号与备注——版本语义——[[../项目从开始开发到上线全流程/00-项目全流程知识体系总览|项目版本管理]]）；**第二步，后台管理**——mp.weixin.qq.com 登录 → 版本管理 → 看到上传的版本；**第三步，设为体验版**——体验成员扫码测试（**「上线前体验版完整测一遍」**——功能 + 域名 + 权限）；**第四步，提交审核**——填类目（**小程序类目决定可用能力**——支付等能力要对应类目）、提交审核；**第五步，审核通过后发布**——正式版上线（**可设灰度发布**——按比例放量——[[../横向通用能力/06-架构模式知识地图|发布策略]] 的小程序版）；**第六步，线上监控**——线上版本的问题反馈（客服消息/崩溃监控——[[../横向通用能力/09-治理与演进|可观测]] 的运营面）。

## 4. 审核要点

**审核是上线的最不可控环节**——要点：**类目匹配**——小程序类目与内容对应（电商类目要资质——「类目不对审核被拒」）；**内容合规**——隐私政策（收集用户信息必须声明——个保法）、内容规范（违禁词/违规内容）；**能力申请**——支付/位置等能力按类目申请（**「能力申请要提前——审核周期长」**）；**审核被拒的应对**——拒绝原因在后台查看 → 修改 → 重新提交（**「审核是迭代不是一次过」**——预留审核时间在排期里——[[../项目从开始开发到上线全流程/00-项目全流程知识体系总览|上线排期]]）。

## 5. App 云打包

uni-app 的 App 端发布（区别于小程序）：**云打包**——HBuilderX 的云打包服务（本地无需 Android/iOS 环境——上传代码云端打包——免费额度/付费加速）；**打包配置**——manifest 的 App 配置（应用图标、启动图、权限声明、Android 证书/签名）；**测试与上架**——真机安装测试 → 应用市场发布（Android 各市场 + iOS App Store——**iOS 上架要求 Apple 开发者账号（年费）与审核**）；**原生能力**——原生插件（复杂硬件交互——01 篇边界）——**「App 发布的复杂度高于小程序」（证书、市场、审核各自独立）**。

## 6. 多平台发布

多平台发布（uni-app 的价值兑现）：**各平台发布流程**——支付宝小程序（开放平台）、抖音小程序（开发者平台）、百度/快手等——**流程同构**（注册 → AppID → 域名 → 上传 → 审核 → 发布）但平台各异（各平台后台、审核规范不同——**「多平台 = 多份配置 + 多轮审核」**）；**H5 发布**——编译产物部署到服务器（Nginx——[[../运维/Nginx%20基础|Nginx 体系]]——域名 + HTTPS）；**鸿蒙发布**——DevEco Studio 打包上架华为应用市场（01 篇——uni-app x 支持）——**「跨端开发省的是代码，不省发布」**——每端都要过平台流程（发布排期要乘端数）。

## 7. 常见坑

**坑一：域名没配齐**。线上请求全挂——request 合法域名上线前配齐。

**坑二：AppID 用测试号**。上线不了——正式注册。

**坑三：跳过体验版直接审核**。线上问题——体验版完整验证。

**坑四：类目不对**。审核被拒——类目与内容匹配。

**坑五：隐私政策缺失**。收集信息无声明——审核被拒。

**坑六：App 证书缺失**。云打包失败——Android 证书签名配置。

**坑七：审核时间没排期**。上线延期——审核预留时间。

**上线后的运营与迭代**（发布不是终点）：**线上问题监控**——客服消息（用户反馈入口——小程序后台）、崩溃/异常监控（错误上报——[[../横向通用能力/09-治理与演进|可观测]] 的前端版）、版本回退（发布后出问题 → 后台回退到上一版本——**「回滚是上线流程的一部分」**——[[../运维/CI%20CD灰度发布|发布策略]] 的小程序版）；**版本迭代节奏**——小程序版本迭代快（周/双周发版常见——审核周期要算进节奏）；**灰度发布**——正式版支持按比例灰度（先 10% 观察再全量——「灰度是小程序发布的标准姿势」）；**数据验证**——发布后的业务数据对比（转化率/使用量——功能是否达成目标——[[../项目从开始开发到上线全流程/00-项目全流程知识体系总览|项目验证]]）——**「上线后闭环：监控 → 反馈 → 迭代」**。
