## 1. 项目结构全景

标准 uni-app（Vue3 + Vite）项目结构：

```text
my-app/
├── pages/               # 页面目录（每个页面一个文件夹）
│   └── index/index.vue  # 首页（页面 = 一个 .vue 文件）
├── static/              # 静态资源（图片等）
├── uni_modules/         # 插件市场组件（uView 等）
├── components/          # 自定义组件（可选）
├── App.vue              # 应用入口（全局样式/生命周期）
├── main.js              # 入口文件（createSSRApp）
├── pages.json           # ★ 路由与窗口配置
├── manifest.json        # ★ 应用配置
├── uni.scss             # 全局样式变量
└── vite.config.js       # Vite 配置（CLI 工程）
```

**结构认知**：**页面是「文件夹 + index.vue」的形态**（`pages/index/index.vue`——路径即路由）；**两个 json 是框架的「中枢」**（下两节）——**「先读 pages.json 再看代码」是阅读 uni-app 项目的正确顺序**（路由表先行——项目有哪些页面一目了然）。

## 2. pages.json：路由与窗口

pages.json 是「路由表 + 窗口配置」二合一：

```json
{
  "pages": [
    { "path": "pages/index/index", "style": { "navigationBarTitleText": "首页" } },
    { "path": "pages/login/login", "style": { "navigationBarTitleText": "登录" } }
  ],
  "globalStyle": {
    "navigationBarTextStyle": "white",
    "navigationBarTitleText": "我的应用",
    "navigationBarBackgroundColor": "#4CAF50",
    "backgroundColor": "#f5f5f5"
  },
  "tabBar": {
    "color": "#999", "selectedColor": "#4CAF50",
    "list": [
      { "pagePath": "pages/index/index", "text": "首页" },
      { "pagePath": "pages/mine/mine", "text": "我的" }
    ]
  }
}
```

**配置项语义**：**pages 数组**——页面注册（**第一个页面是启动页**——「想改启动页就改数组顺序」）；**globalStyle**——全局窗口样式（导航栏/背景色）；**tabBar**——底部标签栏（**tab 页面的路由必须是 tabBar 注册的路径**——跳转有差异，06 篇）；**页面级 style 覆盖全局**——**「配置的层级：全局 → 页面」**——路由注册、导航栏标题、tabBar 都在这里——**「pages.json 是项目的目录页」**。

## 3. manifest.json：应用配置

manifest.json 是「应用级配置」——各平台的标识与能力配置：**基础配置**——应用名称、AppID（uni-app 的 DCloud AppID）；**各平台配置**——微信小程序（appid——**微信小程序的 AppID 在这里填**——「manifest 里填微信 appid 才能真机/上传」）、App（iOS/Android 配置）、H5（路由模式/标题）；**权限配置**——各平台 API 权限（位置/相机等——平台申请与代码声明）。

**manifest 与 pages 的分工**：**pages.json 管「界面结构」、manifest.json 管「应用身份与平台能力」**——「改应用名 → manifest；改导航栏 → pages」——**「配置错了往哪找：界面向 pages、身份向 manifest」**。

## 4. App.vue 与 main.js

**App.vue**——应用入口组件：**应用级生命周期**（`onLaunch`——应用启动、`onShow`——应用进入前台、`onHide`——应用退后台——**登录态检查、全局初始化放 onLaunch**）；**全局样式**（`<style>` 非 scoped——全局生效）。**main.js**——Vue 应用创建（`createSSRApp`）+ 全局注册（Pinia 挂载——06 篇）：

```js
// main.js
import { createSSRApp } from 'vue'
import App from './App.vue'
import { createPinia } from 'pinia'

export function createApp() {
  const app = createSSRApp(App)
  app.use(createPinia())        // 状态管理挂载
  return { app }
}
```

**「App.vue 是入口、pages 是页面、main.js 是装配」**——应用级的事（全局样式/启动逻辑）在 App.vue，页面的活在 pages 里。

## 5. 页面生命周期

页面的生命周期（与 Vue 组件生命周期的差异点——小程序特有）：**页面级**——`onLoad`（页面加载——**接收路由参数**——`onLoad(options)` 的 options 是传参）、`onShow`（页面显示——**每次进入都触发**——「列表页刷新放 onShow」）、`onReady`（页面渲染完成）、`onHide`（页面隐藏）、`onUnload`（页面卸载）；**组件级**——Vue 标准生命周期（`onMounted` 等——[[../../10-前端知识拓展/Vue/00-Vue总览与核心概念|Vue 体系]]）。

**生命周期的工程要点**：**onLoad 拿参数**（路由传参——06 篇——「从列表页到详情页，详情页 onLoad 拿 id」）；**onShow 刷新数据**（页面从后台回来/切 tab 回来——onShow 触发——「数据可能变了，onShow 刷新」）；**onLoad vs onShow**（首次加载都触发，onShow 每次进入都触发——**「初始化放 onLoad、刷新放 onShow」**）。

## 6. 组件与 uni_modules

**内置组件**——view（div）、text（span）、image、button、input、scroll-view（滚动）、swiper（轮播）——**「用 view/text 不用 div/span」**（小程序无 HTML 标签）；**自定义组件**——`components/` 目录 + Vue 组件语法（props/emits——[[../../10-前端知识拓展/Vue/02-Vue组件化开发|Vue 组件化]]——`easycom` 机制：符合目录规范自动引入，免手动注册）；**uni_modules**——插件市场的组件安装目录（uView Plus 等 UI 库——07 篇）——**「组件生态：内置 + 自定义 + uni_modules 三来源」**。

**页面间通信的完整姿势**（03 篇生命周期 + 06 篇路由的补充）：**场景一：列表 → 详情传参**——url 参数（id——onLoad options 拿）；**场景二：详情修改 → 返回列表刷新**——onShow 重新拉数据（「返回必刷新的约定」——简单可靠）；**场景三：跨页面全局数据**——Pinia store（登录态、用户信息——06 篇）；**场景四：页面间事件**——`uni.$emit`/`uni.$on`（轻量事件——「详情页通知列表页更新」）；**场景五：跨页面大数据**——storage 暂存（表单草稿）——**「通信姿势的选择：小数据 url、全局数据 store、事件 uni.$emit、大数据 storage」**。

## 7. 常见坑

**坑一：页面没注册**。访问 404——pages.json 注册。

**坑二：启动页改错**。pages 数组第一个是启动页——想换启动页改顺序。

**坑三：tabBar 路径错**。tab 页跳转用 `uni.switchTab`（06 篇）——普通跳转 tab 页报错。

**坑四：用 div/span**。小程序无 HTML 标签——view/text。

**坑五：传参在 onMounted 拿**。路由参数在 onLoad 的 options——onMounted 没有。

**坑六：微信 appid 没填 manifest**。真机预览/上传失败——manifest 里填。

**坑七：全局样式写 scoped**。App.vue 的样式要全局生效——不写 scoped。

**uni.scss 与全局样式的分工**：**uni.scss**——编译期注入的 SCSS 变量（颜色/尺寸——所有页面可引用——**「样式变量集中地」**）；**App.vue 的 style**——全局样式类（通用类——按钮/卡片等公共样式）；**页面 scoped**——页面私有样式——**「三层的样式体系：变量（uni.scss）→ 全局类（App.vue）→ 页面私有（scoped）」**——样式不串层（页面样式不污染全局、全局类不写死页面细节）。

**页面的通用结构模板**（页面开发的标准骨架）：**`<template>`**——页面结构（view 容器 + 内容组件）；**`<script setup>`**——逻辑（组合式 API——04 篇）；**`<style scoped>`**——页面样式——**页面三段的组织纪律**：**数据/计算/方法按序**（script 内：state → computed → watch → 方法——「script 的可读性规范」）、**模板结构清晰**（区块注释「列表区/表单区」）、**样式变量引用**（颜色/尺寸用 uni.scss 变量——「页面骨架 = 结构 + 逻辑 + 样式三段，各自有规范」）。

**tabBar 的配置要点**——list 的 `pagePath` 必须是 pages 注册路径、图标 81×81px PNG（不配只显示文字）、`color`/`selectedColor` 选中色——**tab 页面的两个特性**——切换不销毁（onShow 每次触发——刷新时机）、跳转只能用 switchTab（04 篇导航纪律）——「tab 页是常驻页面，注意 onShow 刷新与页面栈管理」。

**页面的加载状态设计**（数据页面的高频细节）：**加载中**——首屏 loading（骨架屏/loading 组件——首屏不白屏）；**数据为空**——空态提示（「暂无数据」+ 操作引导——07 篇列表三态）；**加载失败**——错误提示 + 重试按钮（「失败可重试」是体验底线——05 篇错误处理）——**「页面三态（加载/空/错）是每个数据页面的标配」**——「只写有数据态 = 页面不完整」。
