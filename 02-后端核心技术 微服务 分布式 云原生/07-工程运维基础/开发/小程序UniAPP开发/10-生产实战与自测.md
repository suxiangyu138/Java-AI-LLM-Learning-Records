## 1. 实战：登录 + 列表 + 详情小程序

把全体系知识点压进一个项目：对接后端 API 的完整小程序（微信登录 → 列表页 → 详情页），交付「能跑通后端闭环」的工程。

**第一步，工程骨架（02/03 篇）**——HBuilderX 创建 Vue3 项目 → pages.json 注册三页（login/list/detail）→ 结构清晰。

**第二步，请求封装（05 篇）**——统一 request 封装（baseURL/Token 注入/状态码判定/401 处理）：

```js
// api/request.js —— 统一封装（05 篇完整版）
import { useUserStore } from '@/stores/user'

export function request(options) {
  return new Promise((resolve, reject) => {
    uni.request({
      url: import.meta.env.VITE_API_BASE + options.url,
      method: options.method || 'GET',
      data: options.data,
      header: { Authorization: `Bearer ${useUserStore().token}` },
      success: (res) => {
        if (res.statusCode === 401) { handleAuthExpired(); return reject(res) }
        if (res.statusCode >= 200 && res.statusCode < 300) resolve(res.data)
        else { uni.showToast({ title: res.data?.message || '请求失败', icon: 'none' }); reject(res) }
      },
      fail: () => { uni.showToast({ title: '网络异常', icon: 'none' }); reject() }
    })
  })
}
```

**第三步，登录（05/06 篇）**——login 页：`uni.login()` 拿 code → `request` 调 `/auth/login` → 存 Token 到 store + storage → `redirectTo` 列表页。

**第四步，列表页（07/08 篇）**——onShow 拉列表（分页 + 下拉刷新 + 上拉加载）→ 列表项组件 → 点击 `navigateTo` 详情带 id。

**第五步，详情页（03/06 篇）**——onLoad 拿 id → 请求详情 → 渲染。

**验收五问**：**登录通吗**——code 流程拿 Token、请求带 Bearer、401 刷新/跳登录；**列表对吗**——分页正确（到底停止）、下拉刷新、空态/加载态；**详情对吗**——参数传递正确（id 转 Number）；**结构好吗**——封装统一、组件复用、状态在 store；**上线齐吗**——域名配置、体验版验证、发布流程（09 篇）。

## 2. 生产配置模板与纪律清单

**技术栈**：uni-app 4.x + Vue3 Setup + Vite + Pinia + SCSS（01 篇基线）；**工程**：请求统一封装（四职责）、状态在 store（页面不碰 storage）、组件 easycom、页面 < 300 行；**安全**：code 换 openid 在后端、Token 短存、HTTPS、防越权靠后端；**性能**：setData 量小频低、列表分页 + 虚拟列表、图片懒加载 + 尺寸压缩、分包按模块；**多端**：业务代码平台无关、条件编译收拢独立文件、平台差异清单（支付/登录/分享）；**上线**：AppID/域名/类目三前置、体验版完整验证、审核预留时间、多平台排期；**后端配合**：OpenAPI 契约对接（[[../../../01-底层根基-Java核心底座/09-计算机工具与常识补全/Swagger/00-Swagger总览|Swagger 体系]]）、错误码字典、统一返回格式（[[../../10-前端知识拓展/RESTful%20接口设计、统一返回格式/00-RESTful接口设计知识体系总览|统一格式]]）。

## 3. 报错速查十条

| 报错/现象 | 原因 | 处理 |
|-----------|------|------|
| 运行不到微信工具 | 服务端口未开 | 设置→安全→开端口 |
| 请求失败「域名不合法」 | 域名未配置/非 HTTPS | 后台配 request 合法域名 |
| 404 页面 | 页面未注册路由 | pages.json |
| 登录失败 | code 流程/后端问题 | Network 看请求 + 后端日志 |
| 401 循环 | Token 失效未处理 | 401 统一刷新/跳登录 |
| 列表不滚动 | 页面滚动/scroll-view 问题 | 布局检查 |
| 图片不显示 | 宽高未设/路径错 | image 宽高 + 路径 |
| 主包超 2MB | 未分包/资源大 | 分包 + 体积治理 |
| 支付报错 | 平台参数/类目 | 平台参数 + 类目能力 |
| 审核被拒 | 类目/隐私/内容 | 后台看原因修改 |

## 4. 面试三范式

**价值式**：「我开发的小程序对接后端完整闭环——微信登录拿 Token（双 Token + 401 静默刷新）、列表分页 + 下拉刷新 + 虚拟列表（千条流畅）、分包按模块（主包 1.6MB）、体验版验证后发布上线。」——先讲闭环与性能数据，再讲手段。

**技术式**：「小程序是双线程模型——逻辑层与视图层靠 setData 通信，数据量/频率/路径三纪律防卡顿；uni-app 跨端是编译器差异——条件编译收拢平台差异（支付/登录/分享），业务代码平台无关；rpx 是 750 设计稿响应式单位。」——原理到「为什么」，别停在「我会写页面」。

**生产式**：「上线三前置（AppID/域名/类目）；体验版是上线前最后验证关卡；审核要预留时间（类目/隐私/能力申请）；App 云打包与多平台发布是独立流程——跨端省代码不省发布；后端配合按 OpenAPI 契约 + 错误码字典。」——上线流程、契约对接、多端排期三点是区分度。

**追问四连**：小程序卡顿怎么排查？（setData 量频 + 列表虚拟化 + 图片）｜Token 怎么管理？（code 换 openid 在后端、双 Token、401 刷新）｜多端差异怎么处理？（条件编译收拢独立文件）｜上线要注意什么？（域名/类目/体验版/审核）。
