## 1. 容器网络排查

```text
容器网络层级：
容器内 → Docker 网络（bridge/自定义）→ 宿主机 → 外部
```

| 排查场景 | 命令 |
|----------|------|
| 容器 IP | `docker inspect <container> \| grep IPAddress` |
| 容器网络列表 | `docker network ls` |
| 网络成员 | `docker network inspect <network>` |
| 容器内网络工具 | `docker exec <c> ping 目标` / `curl` |
| 端口映射确认 | `docker ps` 的 PORTS 列 / `ss -tlnp \| grep 端口` |

```bash
# 容器内排查（注意：精简镜像可能没有 ping/curl）
docker exec -it app bash
cat /etc/resolv.conf          # DNS 配置
ip addr                       # 容器 IP
ping db                       # 容器名通信（自定义网络内）
curl -v http://db:3306        # 服务连通

# 宿主机视角
ss -tlnp | grep 8080          # 映射端口监听确认
iptables -L -n | grep 8080    # 端口映射规则（Docker 用 iptables 实现）
```

> ⚠️ **经典坑**：容器内 `localhost` 是容器自身——访问宿主机服务用 `172.17.0.1`（Linux）或 `host.docker.internal`（Docker Desktop）；容器间通信必须同一自定义网络用容器名（详见 [Docker 体系](../../../11-云原生/Docker/05-Docker网络配置与通信.md)）。

## 2. Docker 常见网络问题

| 问题 | 现象 | 根因与解决 |
|------|------|-----------|
| 容器间不通 | Connection refused | 未入同一自定义网络；用容器名而非 IP |
| 外部访问不了 | 宿主机访问失败 | 端口映射未配/防火墙/应用绑 127.0.0.1 |
| 容器访问外网失败 | 超时 | 宿主机网络/DNS 配置（`--dns`） |
| 端口冲突 | already allocated | 换映射端口/停占用 |
| 重启后 IP 变了 | 配置的固定 IP 失效 | 用容器名通信（自定义网络 DNS） |

```bash
# 三连排查
docker network inspect my-net        # ① 同一网络？
docker exec app ping db              # ② 容器名解析与连通
docker exec app curl -v db:8080      # ③ 应用层
```

## 3. K8s 网络模型

```text
K8s 网络四层：
  ① Pod 间（同节点）：CNI 插件（Flannel/Calico/Cilium）
  ② Pod 间（跨节点）：overlay/underlay
  ③ Service：kube-proxy（iptables/IPVS）负载均衡到 Pod
  ④ Ingress：七层路由到 Service

DNS（CoreDNS）：Service 名 → ClusterIP
  service.namespace.svc.cluster.local（FQDN）
```

| 层 | 排查工具 |
|----|---------|
| Pod 网络 | `kubectl get pod -o wide`（IP/节点） |
| Service | `kubectl get svc` / `kubectl get endpoints` |
| 跨节点 | 节点间 CNI 连通性 |
| DNS | `kubectl exec pod -- nslookup svc` |
| Ingress | `kubectl get ingress` / Ingress Controller 日志 |

## 4. K8s 常见网络问题

### 4.1 Service 不通

```bash
# 排查链路
kubectl get svc my-service              # ① Service 存在？ClusterIP？
kubectl get endpoints my-service        # ② Endpoints 有 Pod 吗？（空 = selector 不匹配！）
kubectl get pods -l app=my-app -o wide  # ③ Pod 标签与 selector 一致？
kubectl exec other-pod -- curl my-service:8080   # ④ 集群内访问
kubectl get networkpolicy               # ⑤ NetworkPolicy 拦截？
```

| 现象 | 根因 |
|------|------|
| Endpoints 为空 | **selector 与 Pod 标签不匹配**（最高频） |
| 集群内不通 | NetworkPolicy / kube-proxy 异常 |
| 时通时不通 | 某 Pod 不健康（Endpoints 部分为空） |
| 跨命名空间不通 | 用了短名（需 FQDN） |

> 🎯 **K8s Service 排查第一问**：`kubectl get endpoints`——**Endpoints 为空 = selector 不匹配**，80% 的 Service 不通是这个原因。

### 4.2 DNS 问题

```bash
kubectl exec pod -- nslookup my-service.default.svc.cluster.local
# 失败 → CoreDNS 问题
kubectl get pods -n kube-system -l k8s-app=kube-dns
kubectl logs -n kube-system -l k8s-app=kube-dns --tail=100
kubectl get configmap -n kube-system coredns -o yaml   # 检查 Corefile
```

| DNS 现象 | 根因 |
|----------|------|
| 服务名解析失败 | CoreDNS 故障/未创建 |
| 短名失败、FQDN 成功 | search 域配置（resolv.conf） |
| 偶发解析失败 | CoreDNS 副本不足/性能 |

### 4.3 Ingress 问题

```bash
kubectl get ingress                    # Ingress 规则
kubectl describe ingress my-ingress    # 事件/后端
kubectl logs -n ingress-nginx deploy/ingress-nginx-controller   # Controller 日志
curl -H "Host: api.example.com" http://<LB-IP>/health           # 直连测试
```

| Ingress 现象 | 根因 |
|--------------|------|
| 404 | 路径/后端 service 配置错 |
| 502/504 | 后端 Service 无可用 Pod/处理慢 |
| 证书错误 | TLS secret 缺失/过期 |
| 域名不通 | DNS 指向 LB + Ingress host 匹配 |

## 5. 微服务调用链排查

```text
微服务调用链路：
A 服务 → 网关 → B 服务 → C 服务（含服务发现与负载均衡）
```

| 排查点 | 命令/工具 |
|--------|----------|
| 服务发现注册了吗 | Nacos/Gateway 服务列表（管理台） |
| 调用地址解析 | 日志中的服务名 vs 实际地址 |
| 每跳耗时 | 链路追踪（Tempo/Jaeger）或日志 traceId |
| 负载均衡到坏实例 | 逐实例健康检查 + 服务发现剔除 |

```bash
# 逐跳排查（A 调 B 失败）
# ① A 的日志：调 B 的异常（超时/reset/unknown host）
# ② B 是否注册/健康：Nacos 控制台 / B 的 /actuator/health
# ③ 直连 B 验证：从 A 的 Pod/容器 telnet B:port
# ④ B 的日志：请求是否到达（没到 = 网络/发现问题；到了 = B 处理问题）
```

> 🎯 **调用链定位口诀**：**请求到没到**（B 日志有无）区分"网络/发现问题"与"B 处理问题"——一半的微服务排查问题瞬间缩小范围。

## 6. 服务发现与负载均衡问题

| 场景 | 问题 | 解决 |
|------|------|------|
| Nacos 注册但调用失败 | 实例 IP 不对（容器 IP vs 宿主机 IP） | 注册地址配置（`spring.cloud.nacos.discovery.ip`） |
| 调用偶发失败 | LB 轮询到不健康实例 | 健康检查 + 剔除（Nacos 临时实例心跳） |
| 网关路由 503 | 服务未注册/权重 0 | 注册中心检查 |
| 蓝绿/灰度流量异常 | 标签路由未匹配 | 服务发现元数据标签检查 |

> 💡 容器化微服务经典坑：**Nacos 注册的是容器 IP，跨宿主机不可达**——需配置 `ip` 为宿主机 IP 或使用 K8s Service 名注册。

## 7. 容器网络排查工具集

| 场景 | 工具 |
|------|------|
| 容器内网络诊断 | `kubectl exec` + 容器镜像内置工具（curl/nslookup） |
| 临时网络调试容器 | `kubectl run debug --image=nicolaka/netshoot -it --rm -- bash` |
| K8s 网络插件状态 | `kubectl get pods -n kube-system -l k8s-app=flannel/calico` |
| 节点网络 | 节点上 `ping`/`ss`/`tcpdump` |
| 全链路 | 链路追踪（Tempo/Jaeger）+ 指标（Grafana） |

```bash
# netshoot：K8s 网络排障瑞士军刀
kubectl run netshoot --image=nicolaka/netshoot -it --rm -- bash
# 容器内可用：ping/traceroute/curl/tcpdump/ss/nslookup 全齐
```

## 8. 核心要点

> 🎯 **核心要点**：
> - Docker 三问：同一网络？容器名通信？端口映射对？
> - K8s Service 第一问：`kubectl get endpoints`（空 = selector 不匹配）；
> - K8s DNS：短名失败查 search 域、FQDN 失败查 CoreDNS；
> - Ingress：404 查规则、502 查后端、证书查 secret；
> - 微服务调用链口诀：**请求到没到**（B 日志）区分网络问题与处理问题；
> - 容器化注册坑：Nacos 注册容器 IP 跨宿主机不可达——配置注册地址；
> - netshoot 镜像 = 容器网络排障瑞士军刀。
