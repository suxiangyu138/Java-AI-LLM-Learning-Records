## 1. ping：网络连通性

```bash
ping -c 3 10.0.0.5          # 发 3 个包
ping -c 3 -i 0.2 10.0.0.5   # 间隔 0.2s（快速测试）
ping -c 3 -s 1400 10.0.0.5  # 大包（MTU 问题探测）
```

| 输出解读 | 结论 |
|----------|------|
| 全部 reply，延迟稳定 | 网络层通 |
| 超时/丢包 | 网络层问题（路由/防火墙 ICMP 拦截/物理） |
| 延迟波动大 | 网络质量差（带宽/抖动） |
| 大包失败小包通 | **MTU 问题**（隧道/overlay 场景常见） |

> ⚠️ **注意**：ping 通 ≠ 服务可用（ping 走 ICMP，服务走 TCP）；防火墙常拦截 ICMP 导致"ping 不通但服务正常"——**ping 不通不要急着下结论**。

## 2. telnet / nc：端口连通性

```bash
telnet 10.0.0.5 8080            # 端口测试（连上显示 Connected）
nc -zv -w 3 10.0.0.5 8080       # nc 版（-z 扫描 -v 详细 -w 超时）
nc -zv 10.0.0.5 80-90           # 端口范围
```

| 输出 | 结论 |
|------|------|
| Connected | 端口通（TCP 握手成功） |
| Connection refused | 端口未监听（应用没起）或防火墙 reject |
| Connection timed out | 防火墙 drop 或网络不通 |

> 🎯 **telnet 是"端口通不通"的标准答案**：refused 与 timeout 的区别直接区分"应用没起"与"防火墙拦截"。

## 3. ss / netstat：连接状态

```bash
ss -tlnp | grep 8080        # 监听端口（-t TCP -l 监听 -n 数字 -p 进程）
ss -tnp | grep 8080         # 已建立连接
ss -tn state syn-recv       # 半连接（SYN_RECV）
ss -tn state time-wait | wc -l    # TIME_WAIT 数量
ss -s                       # TCP 统计总览
ss -tnp | awk '{print $1}' | sort | uniq -c   # 状态分布

netstat -s | grep -iE 'reset|timewait'   # RST/TIME_WAIT 统计
```

| 状态 | 含义 | 关注点 |
|------|------|--------|
| LISTEN | 端口在监听 | 应用是否启动 |
| SYN_SENT | 客户端发出 SYN 未回 | 网络/防火墙/服务端队列满 |
| SYN_RECV | 服务端收到 SYN 未完成 | **半连接队列溢出** |
| ESTABLISHED | 已建立 | 连接数/增长趋势 |
| TIME_WAIT | 主动关闭等待 | 大量 = 连接频繁创建关闭 |
| CLOSE_WAIT | 对端关闭未关 | **应用未关闭连接（泄漏）** |

> ⚠️ **CLOSE_WAIT 堆积是 Java 应用经典问题**：对端关闭连接后应用未调用 close——连接池/HTTP 客户端泄漏信号，`ss -tn state close-wait | wc -l` 持续增长要查代码。

## 4. curl：应用层验证

```bash
curl -v http://api.example.com:8080/health    # 详细（DNS/TLS/HTTP 全链路）
curl -I https://api.example.com               # 只看响应头
curl -w '耗时: %{time_total}s 连接: %{time_connect}s\n' url   # 耗时分解
curl -k https://self-signed.example.com       # 跳过证书校验（仅测试）
curl -x http://proxy:8080 url                 # 走代理
```

```text
curl -v 输出解读（按顺序）：
  Trying 10.0.0.5:8080...        ← TCP 连接（卡这里 = 传输层问题）
  Connected to ...               ← TCP 建立成功
  TLS handshake completed        ← TLS 握手（卡这里 = 证书/协议问题）
  > GET /health HTTP/1.1         ← 请求已发出
  < HTTP/1.1 200 OK              ← 收到响应（应用层 OK）
```

| curl -w 变量 | 含义 |
|--------------|------|
| `time_namelookup` | DNS 解析耗时 |
| `time_connect` | TCP 连接耗时 |
| `time_appconnect` | TLS 握手耗时 |
| `time_starttransfer` | 首字节耗时 |
| `time_total` | 总耗时 |

> 🎯 **耗时分解定位慢在哪**：DNS 慢（time_namelookup 大）→ 网络慢（time_connect 大）→ 服务处理慢（time_starttransfer 大）。

## 5. traceroute：路径与丢包定位

```bash
traceroute -n 10.0.0.5          # -n 不做 DNS 反解（更快）
traceroute -n -T -p 8080 10.0.0.5   # TCP 方式（绕过 ICMP 拦截）
traceroute -n -q 5 10.0.0.5     # 每跳 5 个探测包（丢包判断）

# 更快更直观的替代：mtr
mtr -n 10.0.0.5                 # 持续探测，实时显示每跳丢包率
```

| 现象 | 结论 |
|------|------|
| 中间某跳 `* * *` | 该跳不响应 ICMP（可能是防火墙策略，不一定故障） |
| 某跳持续丢包 | 该节点质量问题 |
| 到达目标跳数异常多 | 路由绕路（可能造成延迟高） |
| 最后一跳通但应用不通 | 目标主机防火墙/应用问题 |

> 💡 `*` 不一定是故障：很多路由器不响应 ICMP——结合 mtr 持续观察与两端视角判断。

## 6. nslookup / dig：DNS 查询

```bash
nslookup api.example.com                    # 基础查询
nslookup api.example.com 8.8.8.8            # 指定 DNS 服务器

dig api.example.com                         # 详细查询
dig +short api.example.com                  # 简洁输出
dig api.example.com @8.8.8.8                # 指定服务器
dig api.example.com A                       # 指定记录类型
dig api.example.com ANY                     # 所有记录
```

```text
dig 输出关键字段：
  ANSWER SECTION: 解析结果（IP 列表）
  TTL: 缓存时间
  Query time: 解析耗时
  SERVER: 实际使用的 DNS 服务器
```

| 排查场景 | 命令 |
|----------|------|
| 域名解析到哪个 IP | `dig +short api.example.com` |
| 换 DNS 是否正常 | `dig api.example.com @8.8.8.8` 对比 |
| 解析耗时 | `dig` 的 Query time |
| 本地缓存问题 | `hosts` 文件检查 + `nscd/systemd-resolved` 状态 |

## 7. 工具选择速查表

| 想确认什么 | 工具 | 一步命令 |
|-----------|------|---------|
| 域名解析对吗 | nslookup | `nslookup api.example.com` |
| IP 通吗 | ping | `ping -c 3 ip` |
| 路径/丢包在哪 | traceroute/mtr | `mtr -n ip` |
| 端口通吗 | telnet/nc | `telnet ip port` |
| 端口监听了吗 | ss | `ss -tlnp \| grep port` |
| 连接状态如何 | ss | `ss -tn \| grep port` |
| HTTP 通吗/慢在哪 | curl | `curl -v -w '耗时分解' url` |
| 到底发生了什么 | tcpdump | `tcpdump -nn port 8080` |

## 8. 核心要点

> 🎯 **核心要点**：
> - 五工具五层：nslookup（DNS）→ ping（网络）→ traceroute（路径）→ telnet（端口）→ curl（HTTP）；
> - ping 不通别急着下结论（ICMP 可能被防火墙拦截）；
> - telnet 区分 refused（应用没起）与 timeout（防火墙/网络）；
> - ss 三状态关注：SYN_RECV（半连接溢出）、TIME_WAIT（连接频繁）、**CLOSE_WAIT（泄漏）**；
> - curl -w 耗时分解：DNS/连接/TLS/首字节——慢在哪一目了然；
> - mtr 是 traceroute 的现代替代（实时丢包率）。
