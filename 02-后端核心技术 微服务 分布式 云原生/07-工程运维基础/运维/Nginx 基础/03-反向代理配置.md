## 1. 正向代理 vs 反向代理

| 维度 | 正向代理 | 反向代理 |
|------|---------|---------|
| 代理对象 | **客户端**（隐藏客户端身份） | **服务端**（隐藏后端服务器） |
| 位置 | 客户端侧 | 服务端侧 |
| 客户端感知 | 配置代理 | 无感知（只认识 Nginx） |
| 典型 | VPN、翻墙代理 | Nginx 反代后端 |
| 作用 | 访问受限资源 | 统一入口/隐藏拓扑/TLS 终止 |

```text
反向代理的价值：
  ① 统一访问入口（一个域名/端口）
  ② 隐藏后端拓扑（后端不暴露公网）
  ③ 集中 TLS 终止（证书只配 Nginx）
  ④ 传递真实客户端 IP（X-Forwarded-For）
  ⑤ 负载均衡基础（见 04）
```

> 🎯 **一句话**：正向代理"替客户端去"，反向代理"替服务端收"——客户端只知道反向代理的存在，不知道真实后端。

## 2. 最小反向代理配置

```nginx
server {
    listen 80;
    server_name example.com;

    location /api/ {
        proxy_pass http://127.0.0.1:8080/;

        # 必配头（见第 4 节）
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 超时
        proxy_connect_timeout 5s;
        proxy_read_timeout 60s;
        proxy_send_timeout 60s;
    }
}
```

## 3. proxy_pass 路径规则（高频考点）

```text
核心规则：proxy_pass 的 URI 部分（/ 结尾与否）决定路径处理

① 带 URI（/ 结尾）：location 前缀被替换
   location /api/ { proxy_pass http://backend:8080/; }
   请求 /api/user/list → 转发 /user/list（前缀 /api/ 被替换为 /）

② 不带 URI：路径原样保留
   location /api/ { proxy_pass http://backend:8080; }
   请求 /api/user/list → 转发 /api/user/list（原样）

③ 正则 location：proxy_pass 不能带 URI（原样转发）
```

```text
记忆：proxy_pass 带 /（有 URI）→ 替换前缀；不带 → 原样保留
```

> ⚠️ **高频面试题**："`proxy_pass http://backend/;` 与 `proxy_pass http://backend;` 的区别？"——带 `/` 会替换 location 前缀（/api/ 消失），不带则保留。**配错 = 后端 404**。

## 4. proxy_set_header 必配项

| 头 | 作用 | 不配的后果 |
|----|------|-----------|
| `Host $host` | 保持原始域名 | 后端按域名路由时拿到错误 Host |
| `X-Real-IP $remote_addr` | 客户端真实 IP | 后端日志/限流/风控失效（看到 127.0.0.1） |
| `X-Forwarded-For $proxy_add_x_forwarded_for` | 代理链 IP 记录 | 无法追溯真实客户端 |
| `X-Forwarded-Proto $scheme` | 原始协议（http/https） | 后端生成错误的重定向 |

```nginx
# $proxy_add_x_forwarded_for vs 手写：
# $proxy_add_x_forwarded_for = 已有 XFF + 当前客户端 IP（自动追加上游）
# 手写 $remote_addr 会覆盖已有 XFF（多级代理丢失链）
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;   # ✅ 推荐
```

> 🎯 **四头必配**：Host / X-Real-IP / X-Forwarded-For / X-Forwarded-Proto——**不传真实 IP，后端的限流、审计、日志全部失真**。

## 5. 超时控制

| 超时 | 含义 | 建议 |
|------|------|------|
| `proxy_connect_timeout` | 连接后端超时 | 5s |
| `proxy_read_timeout` | 读取响应超时 | 60-200s（按业务） |
| `proxy_send_timeout` | 发送请求超时 | 60s |

```nginx
# 普通 API：60-200s
proxy_read_timeout 60s;

# SSE / WebSocket / AI 推理（长连接场景）
location /api/stream/ {
    proxy_pass http://backend:8080;
    proxy_read_timeout 86400s;      # 24 小时
    proxy_buffering off;            # 关闭缓冲（边收边发）
}
```

> ⚠️ **超时不要一刀切**：普通 API 与流式接口（SSE/AI）的超时需求差几个数量级——**流式接口单独 location 配置长超时**（详见 [05-HTTP层问题排查](../网络问题排查/05-HTTP层问题排查.md) 的超时链设计）。

## 6. Buffer 调优（含流式场景）

```nginx
# 方案 1：常规 API/大响应体 → 大 Buffer
proxy_buffer_size 1024k;
proxy_buffers 16 1024k;

# 方案 2：SSE/AI 流式 → 关闭缓冲，边收边发
location /api/stream/ {
    proxy_pass http://backend:8080;
    proxy_buffering off;                          # 关键：关闭缓冲
    proxy_http_version 1.1;
    chunked_transfer_encoding on;                 # 分块传输
    proxy_read_timeout 86400s;
}
```

| 场景 | 策略 |
|------|------|
| 常规 API/大响应 | 大 Buffer（1024k 级） |
| SSE/AI 流式 | **proxy_buffering off**（边收边发，实时性） |
| WebSocket | 关闭缓冲（长连接） |

> 💡 **proxy_buffering off 的语义**：Nginx 默认缓冲后端响应（收完再发给客户端）——流式接口必须关闭，否则客户端等不到增量数据（AI 打字机效果失效）。

## 7. WebSocket 代理

```nginx
location /ws/ {
    proxy_pass http://backend:8080;
    proxy_http_version 1.1;                       # WebSocket 需要 HTTP/1.1
    proxy_set_header Upgrade $http_upgrade;       # 升级协议
    proxy_set_header Connection "upgrade";        # 保持长连接
    proxy_read_timeout 86400s;                    # 长连接超时
    proxy_buffering off;
}
```

```text
WebSocket 代理三要素：
  ① proxy_http_version 1.1（WS 需要）
  ② Upgrade / Connection 头透传
  ③ 长超时（连接持续）
```

> ⚠️ WebSocket 是线上常见坑：**缺 Upgrade/Connection 头 → 握手失败**；连接正常但秒断 → 超时未调长。

## 8. 核心要点

> 🎯 **核心要点**：
> - 正向代理客户端、反向代理服务端（面试第一问）；
> - **proxy_pass 路径规则**：带 `/` 替换前缀、不带原样保留（高频考点）；
> - 四头必配：Host/X-Real-IP/X-Forwarded-For/X-Forwarded-Proto（真实 IP 传递）；
> - 超时按业务：普通 60s、流式/WS 86400s（单独 location）；
> - 流式三件套：proxy_buffering off + HTTP/1.1 + chunked；
> - WebSocket 三要素：HTTP/1.1 + Upgrade/Connection + 长超时。
