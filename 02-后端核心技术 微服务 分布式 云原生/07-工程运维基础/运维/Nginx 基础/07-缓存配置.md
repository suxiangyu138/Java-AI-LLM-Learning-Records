## 1. 两级缓存模型

```text
第一级：浏览器缓存（客户端侧）
  浏览器直接使用本地缓存（不发请求）
  控制：Cache-Control / Expires（Nginx 下发）

第二级：Nginx 代理缓存（服务端侧）
  Nginx 缓存后端响应（后端少算一次）
  控制：proxy_cache（Nginx 配置）

第三级：后端缓存（应用侧：Redis/本地）
  后端自身缓存（数据库少查一次）
```

> 🎯 **缓存层级价值**：**越靠近客户端，节省的链路越长**——浏览器缓存省全程；Nginx 缓存省后端计算；后端缓存省数据库查询。三层配合，逐层兜底。

## 2. 浏览器缓存配置

```nginx
# 静态资源长缓存
location ~* \.(js|css|png|jpg|jpeg|gif|svg|woff2?)$ {
    expires 30d;
    add_header Cache-Control "public, max-age=2592000";
}

# HTML 不缓存
location / {
    add_header Cache-Control "no-cache";
}
```

| 资源 | 策略 |
|------|------|
| JS/CSS（带 hash） | 长缓存（365d） |
| 图片/字体 | 长缓存（30-365d） |
| HTML | no-cache（内容会变） |
| API 动态 | 不缓存（或短缓存） |

> ⚠️ 浏览器缓存的前提：**文件名带 hash/版本**——更新 = 新文件名 = 新缓存；否则长缓存导致"用户看不到更新"。

## 3. proxy_cache：代理缓存

```nginx
# 缓存定义（http 块）
proxy_cache_path /data/nginx/cache levels=1:2
                 keys_zone=api_cache:10m
                 max_size=10g
                 inactive=60m;

server {
    location /api/cacheable/ {
        proxy_cache api_cache;                 # 使用缓存区
        proxy_cache_key $host$uri$is_args$args;  # 缓存键（URL+参数）
        proxy_cache_valid 200 302 60m;         # 成功响应缓存 60 分钟
        proxy_cache_valid 404 1m;              # 404 缓存 1 分钟
        proxy_cache_valid any 1m;              # 其他 1 分钟

        proxy_pass http://backend;
    }
}
```

| 配置 | 说明 |
|------|------|
| `proxy_cache_path` | 缓存目录 + 内存索引（keys_zone） |
| `proxy_cache_key` | 缓存键（URL/参数/自定义） |
| `proxy_cache_valid` | 按状态码设置缓存时长 |
| `inactive` | 未访问清理时间 |
| `max_size` | 磁盘上限 |

> 🎯 **proxy_cache 的价值**：**热点数据（商品详情/配置接口）后端只算一次，后续全部 Nginx 直接返回**——大幅降低后端压力。

## 4. 缓存键与缓存策略

### 4.1 缓存键设计

```nginx
# 基础：URL + 参数
proxy_cache_key $host$uri$is_args$args;

# 需要区分用户/设备的场景（谨慎——缓存碎片化）
proxy_cache_key $host$uri$is_args$args$http_user_agent;

# 忽略某些参数（防止缓存爆炸）
# 使用 proxy_cache_key 排除：如时间戳参数
```

> ⚠️ **缓存键与碎片化**：键越细（含用户/UA），缓存碎片越多命中越低——**能不加就不加**；高频变化的参数（时间戳）应从键中排除。

### 4.2 什么内容适合缓存

| 适合缓存 | 不适合缓存 |
|----------|-----------|
| 商品详情/配置（读多写少） | 用户私有数据（订单/余额） |
| 列表数据（短时缓存） | 实时数据（库存/价格） |
| 静态资源 | 动态个性化内容 |
| 搜索结果（短时） | 写操作响应 |

## 5. 缓存失效与更新

```text
缓存失效三方式：
  ① 过期（proxy_cache_valid 时长）
  ② 主动清除（proxy_cache_purge，需第三方模块）
  ③ 版本化（URL 带版本号，新版本新缓存）
```

```nginx
# 版本化更新（推荐：配合发布）
# 后端发布新版本时 URL 变化（/v2/ 或带版本参数）→ 自然新缓存
# 或使用 proxy_cache_bypass 强制回源

# 强制回源（管理员接口旁路缓存）
location /admin/ {
    proxy_cache_bypass $http_x_admin;    # 带该头时绕过缓存
    proxy_pass http://backend;
}
```

> 💡 **缓存更新的最佳实践**：**版本化 > 主动清除**——URL 带版本，发版即换缓存，无需清缓存操作；紧急场景用 `proxy_cache_bypass` 按请求旁路。

## 6. 缓存命中率监控

```nginx
# 添加命中状态头（排障利器）
add_header X-Cache-Status $upstream_cache_status;
# 输出：HIT（命中）/ MISS（未命中）/ EXPIRED（过期）/ BYPASS（绕过）
```

```bash
# 验证命中
curl -I http://example.com/api/cacheable/ | grep X-Cache
# X-Cache-Status: MISS   ← 第一次
# X-Cache-Status: HIT    ← 第二次（命中）

# 查看缓存占用
du -sh /data/nginx/cache
```

| 状态 | 含义 |
|------|------|
| HIT | 缓存命中（Nginx 直接返回） |
| MISS | 未命中（回源） |
| EXPIRED | 过期（重新回源） |
| BYPASS | 绕过（配置旁路） |
| UPDATING | 更新中（旧缓存+后台刷新） |

> 🎯 **命中率是缓存的核心指标**：`X-Cache-Status` 头 + 日志统计——命中率低 = 缓存键太碎/时长太短/内容不适合缓存。

## 7. 核心要点

> 🎯 **核心要点**：
> - 三层缓存：浏览器（省全程）→ Nginx（省后端）→ 应用（省数据库）；
> - 浏览器缓存：hash 文件名 + 长缓存，HTML no-cache；
> - proxy_cache 四要素：路径+keys_zone、缓存键、valid 时长、inactive/max_size；
> - 缓存键纪律：能不加就不加（防碎片化）；
> - 适合缓存：读多写少（商品/配置）；不适合：私有/实时数据；
> - 更新策略：版本化 > 主动清除；紧急用 proxy_cache_bypass；
> - 监控：X-Cache-Status 头看命中（HIT/MISS/EXPIRED）。
