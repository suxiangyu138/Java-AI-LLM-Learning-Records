## 4. Nginx 定位

```text
Nginx 在架构中的位置：
客户端 → [Nginx 接入层] → 后端服务（Java/Node/静态资源）
              ├─ 反向代理（隐藏后端）
              ├─ 负载均衡（分发流量）
              ├─ HTTPS 终止（证书集中管理）
              ├─ 静态资源（高性能服务）
              ├─ 缓存/限流/安全（接入层保护）
              └─ 日志（统一访问记录）
```

| 与同类对比 | 说明 |
|-----------|------|
| vs Apache | Nginx 事件驱动（高并发）、Apache 进程模型（模块多） |
| vs Spring Cloud Gateway | Nginx 网络层（静态/LB/HTTPS），网关应用层（路由/限流/鉴权）——常串联使用 |
| vs K8s Ingress | Nginx Ingress Controller 是 K8s 的七层入口实现 |

> 🎯 **Nginx 与 Gateway 的分工**：**Nginx 管"流量"（网络层），Gateway 管"路由"（应用层）**——Nginx 在前扛并发 + TLS 终止，Gateway 在后做业务路由。

## 6. 核心概念速查

| 概念 | 一句话 |
|------|--------|
| 事件驱动 | 一个 worker 管理大量连接（非 1 连接 1 线程） |
| epoll | Linux 的 I/O 多路复用（高并发核心） |
| master-worker | master 管理、worker 处理请求 |
| 配置文件 | `nginx.conf`（http/server/location 三层） |
| location | URL 匹配块（按优先级匹配） |
| proxy_pass | 反向代理转发目标 |
| upstream | 后端服务器组（负载均衡） |
| rewrite | URL 重写 |
| limit_req | 请求限流（漏桶） |
| proxy_cache | 反向代理缓存 |
| gzip | 响应压缩 |
| 正向代理 vs 反向代理 | 代理客户端 vs 代理服务端 |
