## 1. 日志体系

```text
Nginx 两类日志：
  access.log：访问日志（每次请求一行）
  error.log：错误日志（错误/警告/调试）

位置：/var/log/nginx/（默认）
```

| 日志 | 内容 | 用途 |
|------|------|------|
| access.log | 每次请求（IP/时间/URL/状态/耗时） | 流量分析、排障、审计 |
| error.log | 错误与警告 | 配置错误、限流触发、上游错误 |

## 2. access 日志格式设计

```nginx
# 自定义格式（http 块）
log_format main escape=json
    '$remote_addr - $remote_user [$time_local] "$request" '
    '$status $body_bytes_sent "$http_referer" '
    '"$http_user_agent" '
    'rt=$request_time uct=$upstream_connect_time '
    'urt=$upstream_response_time '
    'upstream=$upstream_addr ustatus=$upstream_status '
    'xff=$http_x_forwarded_for';

access_log /var/log/nginx/access.log main;
```

| 变量 | 含义 | 排障价值 |
|------|------|---------|
| `$request_time` | 总处理耗时 | 慢请求定位 |
| `$upstream_response_time` | 后端处理耗时 | **前后端耗时对比** |
| `$upstream_addr` | 后端地址 | 负载均衡定位 |
| `$upstream_status` | 后端状态码 | 502/504 排障 |
| `$http_x_forwarded_for` | 真实客户端 IP | 审计 |

> 🎯 **排障关键对比**：`$request_time` 大但 `$upstream_response_time` 小 → **问题在网络层**（网络慢）；两者都大 → **问题在后端**（见 [10](10-生产实践与面试题.md)）。

## 3. 错误日志

```nginx
# 错误日志级别
error_log /var/log/nginx/error.log warn;
# 级别：debug < info < notice < warn < error < crit < alert < emerg

# 调试定位（临时）
error_log /var/log/nginx/error_debug.log debug;   # 排查完改回
```

| 级别 | 记录内容 |
|------|---------|
| warn | 警告（限流触发/上游超时） |
| error | 错误（连接失败/配置错误） |
| crit/alert | 严重（资源耗尽） |
| debug | 全量调试（仅排查用） |

> ⚠️ **debug 日志纪律**：生产默认 warn（debug 会拖垮性能）；排查时临时开、定位后关。

## 4. 日志切割与保留

```bash
# 方案 1：logrotate（推荐，系统自带）
# /etc/logrotate.d/nginx
/var/log/nginx/*.log {
    daily                    # 每天切割
    rotate 30                # 保留 30 份
    compress                 # 压缩旧日志
    missingok
    notifempty
    sharedscripts
    postrotate
        [ -f /var/run/nginx.pid ] && kill -USR1 `cat /var/run/nginx.pid`
    endscript
}
```

```text
切割原理：kill -USR1 让 Nginx 重新打开日志文件
  （直接 mv 日志文件后，Nginx 仍写旧 inode——必须 USR1）
```

> ⚠️ **日志切割的坑**：只 `mv` 日志文件不 `kill -USR1` → Nginx 继续写被移走的文件（磁盘不释放）——**logrotate 的 postrotate 信号是标准姿势**。

## 5. 关键指标与采集

| 指标 | 来源 | 监控价值 |
|------|------|---------|
| QPS | access.log 统计 | 流量趋势 |
| 状态码分布（5xx 率） | access.log | **错误率告警** |
| p99 延迟 | `$request_time` | 性能劣化 |
| 上游错误（502/504） | `$upstream_status` | 后端健康 |
| 带宽 | body_bytes_sent 汇总 | 流量成本 |
| 限流触发 | error.log | 攻击/超限 |

```text
采集方式：
  ① Prometheus + nginx-exporter/vts-module（指标接口）
  ② 日志采集（Filebeat/Alloy → Loki/ES，见日志监控指标体系）
  ③ 简易：awk 统计（临时排查）
```

```bash
# 临时统计示例
awk '{print $9}' /var/log/nginx/access.log | sort | uniq -c | sort -rn  # 状态码分布
awk '{print $NF}' /var/log/nginx/access.log | awk '{s+=$1} END {print s/NR}'  # 平均耗时
```

> 🎯 **核心监控项**：5xx 率（错误告警）+ p99 延迟（性能）+ QPS（流量）——与 [日志监控指标](../日志监控指标/00-日志监控指标总览.md) 体系联动。

## 6. 排障日志分析

```text
502 Bad Gateway：Nginx 连不上后端
  看 error.log：connect() failed (111: Connection refused) while connecting to upstream
  排查：后端没起？端口错？防火墙？

504 Gateway Timeout：后端超时
  看 error.log：upstream timed out
  排查：proxy_read_timeout 太小？后端处理慢？

499：客户端断开
  看 access.log：request_time 大 → 客户端等不及
  排查：后端慢（配合 upstream_response_time）
```

```bash
# 组合排查
tail -f /var/log/nginx/error.log | grep "upstream"
grep " 502 " /var/log/nginx/access.log | tail -20
# 按上游状态过滤
awk '$NF ~ /502|504|503/' /var/log/nginx/access.log
```

| 现象 | 日志线索 | 方向 |
|------|---------|------|
| 502 | error.log connect refused | 后端未起/防火墙 |
| 504 | error.log upstream timed out | 超时配置/后端慢 |
| 499 | access.log rt 大 | 客户端断开（后端慢） |
| 429/503 | error.log limiting requests | 限流触发 |
| 循环代理 | error.log "rewrite or internal redirection cycle" | 配置死循环 |

## 7. 核心要点

> 🎯 **核心要点**：
> - 两日志：access（请求记录）+ error（错误记录）；
> - 排障三变量：`$request_time`（总耗时）/ `$upstream_response_time`（后端耗时）/ `$upstream_status`（后端状态）；
> - 耗时对比法：rt 大 urt 小 → 网络问题；都大 → 后端问题；
> - 日志切割：logrotate + `kill -USR1`（否则磁盘不释放）；
> - 监控三件套：5xx 率 + p99 延迟 + QPS；
> - 502（连接）/504（超时）/499（客户端断）各有日志线索；
> - 与日志监控指标体系联动：日志进 Loki/ES，指标进 Prometheus。
