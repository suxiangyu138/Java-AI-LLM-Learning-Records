## 1. 限流原理：漏桶算法

```text
漏桶算法（Nginx limit_req 实现）：
  请求进入"桶"（队列）
  按固定速率"漏出"（处理）
  桶满 → 拒绝（503）

作用：平滑突发流量（削峰）
```

| 算法 | 特点 | Nginx 实现 |
|------|------|-----------|
| 漏桶 | 固定速率，平滑突发 | `limit_req` |
| 令牌桶 | 允许突发（桶有容量） | limit_req 的 burst 参数近似 |

> 🎯 面试点：**limit_req 是漏桶实现**——`rate` 固定处理速率 + `burst` 允许短暂突发 + 超出拒绝（503）。

## 2. limit_req：请求限流

```nginx
# 限流区域定义（http 块）
limit_req_zone $binary_remote_addr zone=api_limit:10m rate=10r/s;

server {
    location /api/ {
        limit_req zone=api_limit burst=20 nodelay;   # 每 IP 10 req/s
        proxy_pass http://backend;
    }
}
```

| 参数 | 说明 |
|------|------|
| `rate=10r/s` | 处理速率（10 请求/秒） |
| `burst=20` | 突发容量（桶大小） |
| `nodelay` | 突发立即处理（不加延迟）；不写 = 排队延迟 |
| 返回码 | 超限默认 503（可自定义 429） |

```nginx
# 超限返回 429（更语义化）
limit_req_status 429;

# 按 URL 限流（不同接口不同阈值）
limit_req_zone $binary_remote_addr zone=login_limit:10m rate=1r/s;
location /api/login {
    limit_req zone=login_limit burst=5 nodelay;    # 登录接口更严
}
```

> 💡 **典型限流配置**：通用 API 10r/s + 敏感接口（登录/短信）1r/s——**接口分级限流**是接入层防护的标配。

## 3. limit_conn：连接限制

```nginx
# 连接数限制（http 块）
limit_conn_zone $binary_remote_addr zone=conn_limit:10m;

server {
    location /download/ {
        limit_conn conn_limit 10;      # 每 IP 最多 10 个并发连接
        limit_conn_status 429;
    }
}
```

| 场景 | 配置 |
|------|------|
| 下载/大文件 | 限制并发连接数（防带宽打满） |
| 长连接 | 限制每 IP 连接数 |
| 与 limit_req 组合 | 请求速率 + 连接数双重限制 |

> 💡 **limit_req vs limit_conn**：`limit_req` 限"请求速率"（每秒几个）、`limit_conn` 限"并发连接数"（同时几个）——**速率限突发、连接限资源**，组合使用。

## 4. IP 黑名单与访问控制

```nginx
# 黑名单（http 块）
deny 1.2.3.4;              # 拒绝单个 IP
deny 1.2.3.0/24;           # 拒绝网段
allow 192.168.1.0/24;      # 允许内网
allow all;                 # 放行其他（放在 deny 后）

# 按 User-Agent 拦截
if ($http_user_agent ~* "(curl|wget|python-requests)") {
    return 403;
}

# 管理员接口仅限内网
location /admin/ {
    allow 192.168.1.0/24;
    deny all;
    proxy_pass http://backend;
}
```

| 访问控制 | 场景 |
|----------|------|
| `allow/deny` | IP 白/黑名单 |
| UA 拦截 | 拦截扫描器/爬虫 |
| 内网限定 | 管理接口只允许内网 |
| `valid_referers` | 防盗链（见 02） |

## 5. 安全响应头

```nginx
# 安全头（http 块或 server）
add_header X-Frame-Options SAMEORIGIN always;        # 防点击劫持
add_header X-Content-Type-Options nosniff always;    # 防 MIME 嗅探
add_header X-XSS-Protection "1; mode=block" always;  # XSS 过滤
add_header Referrer-Policy strict-origin-when-cross-origin always;
add_header Content-Security-Policy "default-src 'self'" always;   # CSP（按需）
add_header Strict-Transport-Security "max-age=31536000" always;   # HSTS（HTTPS 站点）
```

| 安全头 | 防护 |
|--------|------|
| X-Frame-Options | 点击劫持（iframe 嵌入） |
| X-Content-Type-Options | MIME 嗅探攻击 |
| HSTS | 强制 HTTPS（防降级） |
| CSP | 内容安全策略（XSS 兜底） |

> 🎯 **安全头是"零成本防护"**：几行配置挡住一类攻击面——面试答"Nginx 安全加固"先背安全头清单。

## 6. 防攻击配置

```nginx
# 防 SQL 注入/常见攻击关键字（基础版）
if ($request_uri ~* "(union.*select|insert.*into|drop.*table)") {
    return 403;
}

# 限制请求体大小（防大包攻击/上传滥用）
client_max_body_size 10m;

# 限制请求行/头大小
large_client_header_buffers 4 16k;

# 隐藏版本号
server_tokens off;

# 超时防护（防慢速攻击）
client_body_timeout 10s;
client_header_timeout 10s;
```

| 防护 | 说明 |
|------|------|
| `client_max_body_size` | 请求体上限（默认 1m） |
| `server_tokens off` | 隐藏版本号 |
| 请求超时 | 防慢速连接攻击 |
| 关键字拦截 | 基础 WAF（生产建议专业 WAF） |

> ⚠️ **定位**：Nginx 关键字拦截是"基础防线"；**生产安全建议用专业 WAF**（ModSecurity/云 WAF）——Nginx 层做轻量防护，WAF 做深度防护。

## 7. 限流排障

```bash
# 查看限流触发（错误日志）
tail -f /var/log/nginx/error.log | grep "limiting requests"
# limiting requests, excess: 5.000 by zone "api_limit"

# 429/503 排查
# 1. 确认限流配置的 zone 与 rate
# 2. 看是否误伤（正常用户也被限）
# 3. 调整 burst 或按接口分级

# 日志中看限流命中
# 自定义日志格式加 $limit_rate / 状态码判断
```

| 现象 | 排查 |
|------|------|
| 用户偶发 429 | burst 过小 / rate 过低 |
| 误伤内网 | 限流 zone 按 IP——内网共享出口 IP |
| 全站被限 | zone 配置错误（rate 太低） |

## 8. 核心要点

> 🎯 **核心要点**：
> - limit_req 漏桶：rate（速率）+ burst（突发）+ nodelay（立即处理），超限 503/429；
> - limit_conn：并发连接限制（下载/长连接场景）；
> - 速率限突发、连接限资源——组合使用；
> - 访问控制：allow/deny IP、UA 拦截、内网限定、防盗链；
> - 安全头五件套：X-Frame-Options/X-Content-Type-Options/HSTS/CSP/Referrer-Policy；
> - 防攻击基础：client_max_body_size、server_tokens off、请求超时；
> - 定位：轻量防护在 Nginx，深度防护上 WAF。
