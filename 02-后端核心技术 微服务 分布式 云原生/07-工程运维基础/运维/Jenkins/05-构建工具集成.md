## 1. 全局工具配置

```text
Manage Jenkins → Tools（全局工具）：
  · JDK：多个版本（21 用于构建，25 可备）
  · Maven：3.9.x
  · Node.js：前端构建（如需要）
  · Gradle / Go 等按需

配置方式：自动安装（从官方下载）或本地路径
流水线里用 tools{} 声明：
```

```groovy
pipeline {
    agent any
    tools {
        jdk 'jdk21'              // 引用全局工具名
        maven 'maven-3.9'
    }
    stages {
        stage('Build') {
            steps {
                sh 'java -version && mvn -version'   // 工具已注入 PATH
                sh 'mvn -B clean package'
            }
        }
    }
}
```

> 🎯 工具管理原则：**全局定义、流水线引用**——版本升级只改全局工具配置，所有流水线生效；避免每个 Job 里手写路径（维护噩梦）。

## 2. Maven 构建最佳实践

```groovy
stage('Maven Build') {
    steps {
        // ① 依赖缓存：本地仓库挂载（构建提速关键）
        //    声明式环境：environment { MAVEN_OPTS = ... } 或容器挂载
        sh '''
            # ② 标准构建命令（-B 批处理 -DskipTests 先跳过）
            mvn -B clean package -DskipTests
            # ③ 依赖安全扫描（供应链左移，见 CI/CD 体系 04 篇）
            mvn -B org.owasp:dependency-check-maven:check
        '''
    }
}
```

| Maven 优化项 | 做法 | 收益 |
|-------------|------|------|
| **依赖缓存** | 本地仓库目录持久化（挂载卷） | 构建提速 50%+ |
| `-B` 批处理 | 不输出进度条 | 日志干净 |
| 并行模块 | `-T 1C`（CPU 核并行） | 多模块提速 |
| 增量构建 | `-o` 离线（依赖缓存命中时） | 减少网络 |
| 版本号管理 | `mvn versions:set -DnewVersion=$VERSION` | 发布版本化 |

> ⚠️ **依赖缓存是 CI 提速的第一杠杆**：每次构建从零下载依赖 = 每分钟浪费在网络上。`~/.m2/repository` 挂到持久卷（Docker Agent 场景尤其关键），缓存命中后单模块构建常 <1 分钟。

## 3. 质量门禁：SonarQube 集成

```groovy
pipeline {
    agent any
    environment {
        SONAR_HOST_URL = 'http://sonar:9000'
    }
    stages {
        stage('SonarQube Analysis') {
            steps {
                // ① 质量分析（withSonarQubeEnv 注入认证）
                withSonarQubeEnv('sonar') {
                    sh 'mvn -B verify sonar:sonar -Dsonar.projectKey=demo'
                }
            }
        }
        stage('Quality Gate') {
            steps {
                // ② 质量门禁等待（失败 → 构建 UNSTABLE/FAILURE）
                timeout(time: 5, unit: 'MINUTES') {
                    waitForQualityGate abortPipeline: true
                }
            }
        }
    }
}
```

```text
质量门禁（Quality Gate）机制：
  分析 → 结果上传 SonarQube → waitForQualityGate 轮询判定
  门禁规则（SonarQube 侧配置）：
    · 新增 Bug/漏洞 = 0
    · 新增代码覆盖率 < 80% 拒绝
    · 重复率 > 3% 拒绝
  结果：通过 → 继续；不通过 → 流水线失败（abortPipeline）

价值：代码质量红线自动化——坏代码进不了发布流水线
```

> 🎯 面试点：**"质量门禁是 CI 的'红绿灯'"**——SonarQube 分析 + waitForQualityGate 让"质量不合格"成为与"构建失败"同级的阻断条件。门禁规则在 SonarQube 配置（品质模型），Jenkins 只负责等待判定。

## 4. 制品管理：Nexus 与 Harbor

```text
两类制品：
  · 依赖/快照（jar/war）→ Nexus（Maven 私服）
  · 镜像（docker image）→ Harbor（镜像仓库）

流水线角色：
  Build → 推 Nexus（快照制品）
  Docker Build → 推 Harbor（发布镜像）
  Deploy → 从仓库拉取（不是从 workspace！）
```

```groovy
stage('Publish') {
    steps {
        // ① jar 推送 Nexus（Maven settings 配置仓库认证）
        sh 'mvn -B deploy -DskipTests'

        // ② 镜像构建 + 推送 Harbor（凭证注入，见 04）
        withCredentials([usernamePassword(credentialsId: 'harbor-cred',
                usernameVariable: 'H_USER', passwordVariable: 'H_PASS')]) {
            sh '''
                docker build -t harbor.local/demo:$VERSION .
                docker login harbor.local -u $H_USER -p $H_PASS
                docker push harbor.local/demo:$VERSION
            '''
        }
    }
}
```

| 制品类型 | 仓库 | 流水线动作 |
|---------|------|-----------|
| jar/war | Nexus | `mvn deploy` |
| docker 镜像 | Harbor | build + push |
| npm 包 | npm registry | npm publish |
| 安装包 | 制品归档（Artifacts） | archiveArtifacts |

> 💡 制品管理铁律：**"部署从仓库拉，不从 workspace 拿"**——workspace 是临时的，仓库是持久的；发布流程以"仓库里的制品"为准（可追溯、可回滚）。详见 [CI/CD 体系制品篇](../CI%20CD灰度发布/03-GitHub-Actions与制品管理.md)。

## 5. 测试报告与覆盖率

```groovy
stage('Test') {
    steps {
        sh 'mvn -B test'
    }
    post {
        success {
            // ① JUnit 报告（构建页展示测试趋势）
            junit 'target/surefire-reports/*.xml'
            // ② 覆盖率（JaCoCo 插件展示）
            jacoco()
            // ③ 制品归档
            archiveArtifacts artifacts: 'target/*.jar', fingerprint: true
        }
    }
}
```

| 报告类型 | 插件 | 展示 |
|---------|------|------|
| 单元测试 | junit | 构建页测试趋势图 |
| 覆盖率 | JaCoCo | 行/分支覆盖率 |
| 代码质量 | SonarQube | 质量面板（外链） |
| 性能 | JMeter 插件 | 压测报告 |

> 🎯 报告集成价值：**构建页一眼看趋势**——测试数/覆盖率随构建号变化的趋势图，是"质量在变好还是变坏"的仪表盘。`post { success }` 里集成报告，失败构建不产生噪音报告。

## 6. Java 项目标准流水线模板

```groovy
// ═══ Java 项目完整模板（可直接改造使用）═══
pipeline {
    agent { label 'java' }
    options {
        timeout(time: 30, unit: 'MINUTES')
        buildDiscarder(logRotator(numToKeepStr: '50'))
    }
    parameters {
        string(name: 'BRANCH', defaultValue: 'main', description: '构建分支')
        choice(name: 'ENV', choices: ['dev', 'staging', 'prod'])
    }
    environment {
        APP = 'demo-service'
        VERSION = "${params.BRANCH}-${BUILD_NUMBER}"
    }
    stages {
        stage('Checkout') {
            steps { checkout scm }
        }
        stage('单元测试') {
            steps { sh 'mvn -B test' }
            post { success { junit 'target/surefire-reports/*.xml' } }
        }
        stage('质量分析') {
            when { expression { params.ENV != 'dev' } }   // 非 dev 才扫描
            steps {
                withSonarQubeEnv('sonar') {
                    sh 'mvn -B sonar:sonar -Dsonar.projectKey=${APP}'
                }
                timeout(5) { waitForQualityGate abortPipeline: true }
            }
        }
        stage('构建与推送') {
            steps {
                sh 'mvn -B clean package -DskipTests'
                sh 'mvn -B deploy -DskipTests'
                withCredentials([usernamePassword(credentialsId: 'harbor-cred',
                        usernameVariable: 'H_USER', passwordVariable: 'H_PASS')]) {
                    sh '''
                        docker build -t harbor.local/${APP}:${VERSION} .
                        docker login harbor.local -u $H_USER -p $H_PASS
                        docker push harbor.local/${APP}:${VERSION}
                    '''
                }
            }
        }
    }
    post {
        always { cleanWs() }
        failure { mail to: 'dev@example.com', subject: "${APP} 构建失败 #${BUILD_NUMBER}" }
    }
}
```

> 🎯 模板设计模式：**Checkout → 测试 → 质量门禁 → 构建推送 → 通知收尾**——五段式是 Java 服务流水线的标准骨架；按项目裁剪（无前端就去掉 docker，纯库项目到 deploy 为止）。与 [CI/CD 流水线设计篇](../CI%20CD灰度发布/01-CI-CD概念与流水线设计.md) 的七阶段模型对齐。
