## 4. 排查总原则

```text
① 监控先行：先看指标曲线（什么时候开始、什么趋势）
② 现象分级：影响面（全挂/部分/偶发）决定排查优先级
③ 由外到内：连接层 → 服务层 → 数据层
④ 最小复现：能复现的故障好定位（保留现场）
⑤ 变更回溯：故障前改了什么（发布/配置/数据量）
⑥ 记录复盘：现象/根因/解决/防复发四段式归档
```

> ⚠️ 最高频的错误：**不看监控直接改配置**——先看曲线定位"什么时候开始、什么趋势"，比猜配置高效十倍。

## 5. 版本窗口说明

| 中间件 | 版本基准 | 说明 |
|--------|---------|------|
| MySQL | 8.4 LTS / 9.x | 8.0 行为差异注意（默认认证/JSON/优化器） |
| Redis | 8.x | 连接/内存/阻塞机制跨版本稳定 |
| Kafka | 4.x | KRaft-only（ZooKeeper 已移除） |
| RocketMQ | 5.x | Proxy/gRPC/Pop 消费模式 |
| RabbitMQ | 4.x | 仲裁队列/流队列 |

> ⚠️ 本文档是**故障排查手册**（行为模式跨版本稳定）；具体版本行为差异以各中间件官方文档为准。

## 6. 核心概念速查

| 概念 | 一句话 |
|------|--------|
| max_connections | MySQL 最大连接数（默认 151） |
| 慢查询 | 超过 long_query_time 的 SQL |
| 锁等待 | 行锁/表锁/间隙锁竞争 |
| 死锁 | 两个事务互相等锁 |
| 主从延迟 | 从库落后主库的时间 |
| binlog | 二进制日志（复制/恢复基础） |
| maxmemory | Redis 内存上限 |
| 内存淘汰 | Redis 内存满的驱逐策略 |
| 大 key | 单个 key 数据量过大（阻塞元凶） |
| 阻塞命令 | KEYS/SMEMBERS 等 O(N) 命令 |
| 消息堆积 | 生产速度 > 消费速度 |
| 死信 | 消费失败多次进入死信队列 |
| 重复消费 | 至少一次语义的副作用 |
| 顺序消息 | 同 key 消息按序消费 |
