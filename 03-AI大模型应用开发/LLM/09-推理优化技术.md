## 1. 推理 vs 训练的差异

| 维度 | 训练 | 推理 |
|------|------|------|
| 计算模式 | 并行（一次看全部） | **串行**（逐 token） |
| 瓶颈 | 算力 (TFLOPS) | **显存带宽** |
| 批处理 | 大 batch | 小 batch / 单条 |
| 精度 | BF16/FP16 | 可以 INT8/INT4 |
| 优化器状态 | 有（Adam 2x） | 无 |
| KV Cache | 不需要 | **必需** |
| 显存占用 | 模型 + 梯度 + 优化器 | 模型 + **KV Cache** |

> 🎯 推理瓶颈在显存带宽，不是算力——GPU 大部分时间在等数据从显存读到寄存器

## 2. KV Cache 原理

### 2.1 为什么需要 KV Cache

```text
生成 "我爱北京" 的过程：

Step 1: 输入 "我" → 计算所有层的 K, V → 输出 "爱"
        K₁, V₁（保存到 Cache）

Step 2: 输入 "爱"
        不需要重算 "我" 的 K, V！直接从 Cache 读 K₁, V₁
        只需计算 "爱" 的 K₂, V₂ → 输出 "北"

Step 3: 输入 "北"
        从 Cache 读 K₁, V₁, K₂, V₂
        只需计算 K₃, V₃ → 输出 "京"

→ KV Cache 让每步只算 1 个 token，而不是重算全部历史
  n 个 token 的序列：无 Cache = O(n²)，有 Cache = O(n)
```

### 2.2 KV Cache 显存计算

```text
Llama 3.1 8B 的 KV Cache 大小：

每层: 2 (K+V) × 8 (heads) × 128 (head_dim) × 2 bytes (FP16) = 4KB
32 层 × 4KB × context_len = 128KB × context_len

context_len = 4096:  128KB × 4096  = 512 MB
context_len = 32768: 128KB × 32768 = 4 GB  ← 比模型本身还大！
context_len = 131072: 128KB × 131072 = 16 GB
```

> ⚠️ 长上下文推理的显存瓶颈不是模型权重，是 KV Cache！

### 2.3 KV Cache 优化方法

| 方法 | 原理 | 效果 |
|------|------|:---:|
| **GQA/MQA** | 多个 Q 头共享 K/V 头 | 显著减少 KV Cache |
| **PagedAttention** | 分页管理（vLLM） | 显存利用率 40%→90% |
| **KV Cache 量化** | INT8/INT4 存储 K/V | 大小减半或 1/4 |
| **滑动窗口** | 只保留最近 N 个 token 的 KV | 固定内存占用 |

## 3. Flash Attention

```text
问题：标准 Attention 需要存储 N×N 的注意力矩阵
  → 1024 序列 = 1M 个值 × 2 bytes = 2MB（还好）
  → 32K 序列 = 1B 个值 × 2 bytes = 2GB ← 显存爆炸

Flash Attention 的核心创新：
  → 不存储完整的 N×N 注意力矩阵
  → 使用 Tiling（分块计算）+ Recomputation（需要时重算）
  → 结果：显存从 O(N²) 降到 O(N)，速度提升 2-4x

现代 LLM 全部标配 Flash Attention：
  GPT-4/Llama/Mistral/Qwen → Flash Attention 2/3
```

## 4. 量化推理

### 4.1 量化方案对比

| 方法 | 精度 | 加速比 | 显存节省 | 质量损失 |
|------|:---:|:---:|:---:|:---:|
| FP16 | 16-bit | 1x | 基准 | 0% |
| INT8 | 8-bit | 1.5-2x | 50% | <0.5% |
| GPTQ/AWQ | 4-bit | 2.5-3x | 75% | <2% |
| GGUF Q4_K_M | 4.5-bit | 2-3x | 72% | <5% |
| GGUF Q2_K | 2.6-bit | 3-4x | 84% | 5-15% |

### 4.2 量化方法对比

```text
GPTQ (Post-Training Quantization)
  → 一次性量化整个模型，需要校准数据
  → 适合 GPU 推理

AWQ (Activation-Aware Weight Quantization)
  → 保护重要通道（基于激活值分布）
  → 质量通常优于 GPTQ
  → vLLM 默认支持

GGUF (llama.cpp)
  → K-quant 混合精度量化
  → 支持 CPU + GPU offload
  → Ollama 的底层格式
```

## 5. Speculative Decoding

```text
核心思想：用小模型"猜"后面几个 token，大模型一次验证

传统：大模型 → Token1 → 大模型 → Token2 → 大模型 → Token3
        （每次生成都要走一遍大模型 → 慢）

Speculative：小模型 → Token1,Token2,Token3 → 大模型一次验证
        （小模型快，大模型并行验证 → 快 2-3x）

流程：
1. 小模型快速生成 5 个候选 token
2. 大模型一次前向验证这 5 个 token
3. 接受正确的，拒绝错误的 → 继续

→ 不改变输出质量（大模型最终把关），速度提升 2-3x
```

## 核心要点回顾

- 推理瓶颈 = 显存带宽（不是算力），KV Cache 是显存消耗大头
- KV Cache = 缓存已计算的 K,V，避免每步重算历史
- Flash Attention = O(N) 显存代替 O(N²)，所有现代 LLM 标配
- GQA = 共享 K/V 头，减少 KV Cache（Llama 3.1 的关键技术）
- 量化方案：GPU→AWQ/GPTQ，CPU→GGUF，API→FP8
- Speculative Decoding = 小模型猜+大模型验，加速 2-3x
