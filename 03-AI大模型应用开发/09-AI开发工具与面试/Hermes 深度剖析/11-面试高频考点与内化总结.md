## 2. 基础概念题

### Q1: Hermes 是什么？定位是什么？

> **标准回答**：Hermes 是 Nous Research 推出的开源 LLM 系列，定位是"无审查、高可控、强 Function Calling 的通用大模型"。它不是纯推理模型，也不是纯聊天模型，而是专注于 Agent 开发场景的开源基座。

| 关键信息 | 答案 |
|---------|------|
| 开发方 | Nous Research（开源 AI 研究组织） |
| 基座 | Llama 3.1 / Llama 3.2 / Mistral |
| 最大参数量 | 405B（业界首个 Llama 3.1 405B 全参数微调） |
| 核心技术 | ChatML + Function Calling + RLHF |
| 许可证 | Llama 3 Community License |

### Q2: Hermes 1 → 2 → 3 → DeepHermes 3 的演进？

> **标准回答**：
> - Hermes 1（2023）：首个无审查开源模型，基础对话
> - Hermes 2 Pro（2024）：引入 Function Calling + JSON Mode
> - Hermes 3（2024）：全参数微调 Llama 3.1，RLHF 加持，覆盖 3B-405B
> - DeepHermes 3（2025）：混合推理模型，system prompt 一键切换直觉/深度推理

### Q3: ChatML 格式的四个角色？

> **标准回答**：
> - `system`：设定行为、角色、工具
> - `user`：人类输入
> - `assistant`：模型输出（可含 `<tool_call>`）
> - `tool`：工具执行结果（`<tool_response>` 包裹）

## 3. Function Calling 题

### Q4（⭐⭐⭐⭐⭐ 高频）: Hermes Function Calling 怎么实现？

> **标准回答**：
> 1. System Prompt 中用 `<tools>` XML 标签声明函数的 JSON Schema
> 2. 模型需要工具时，输出 `<tool_call>{"name": "...", "arguments": {...}}</tool_call>`
> 3. 应用层解析 JSON → 执行函数 → 结果用 `<tool_response>` 回填
> 4. 模型接收到结果后，给出自然语言最终答案
> 5. 多轮递归（默认 5 轮）支持多步工具链

**面试追问：和 OpenAI Function Calling 有什么区别？**

| 维度 | Hermes | OpenAI |
|------|--------|--------|
| 格式 | ChatML + XML | OpenAI Tool Schema + JSON |
| 部署 | 本地 / vLLM / Ollama | 仅 API |
| 多工具 | `<tool_call>` 数组 | `tool_calls` 数组 |
| vLLM 支持 | `--tool-call-parser hermes` | N/A |
| 成本 | 免费（自部署） | API 按量付费 |

### Q5: 工具调用失败怎么处理？

> **标准回答**：
> - 工具返回 `{"error": "具体错误信息"}`，模型看到 error 会自动重试
> - 设置 `max_depth=5` 防止死循环
> - 参数幻觉：在 system prompt 中明确"Don't assume values"
> - 工具 Schema 写清楚 `required` 字段和 `enum` 约束

## 4. 架构与设计题

### Q6: 如果让你设计一个基于 Hermes 的 Agent 系统，架构怎么画？

> **标准回答**：

```text
┌──────────────────────────────────────────────────┐
│                  API Gateway (Spring Cloud)        │
├──────────────────────────────────────────────────┤
│  Agent Service                                     │
│  ┌───────────┐  ┌──────────┐  ┌──────────────┐   │
│  │ Orchestrator│  │ Tool Registry│  │ Memory Mgr │   │
│  │ (递归循环)  │  │ (Spring Beans)│  │ (MEMORY.md) │   │
│  └─────┬─────┘  └─────┬────┘  └──────┬───────┘   │
│        │              │              │            │
│  ┌─────▼──────────────▼──────────────▼───────┐    │
│  │         LLM Adapter (vLLM / Ollama)        │    │
│  │         OpenAI-compatible API              │    │
│  └─────────────────────┬─────────────────────┘    │
└────────────────────────┼──────────────────────────┘
                         │
              ┌──────────▼──────────┐
              │  vLLM Server (GPU)   │
              │  Hermes 3 70B FP8    │
              └─────────────────────┘
```

> **要点**：编排器 → 工具注册 → 记忆系统 → LLM 适配器 → 各层解耦

### Q7: 怎么保证 Agent 的 Function Calling 稳定性？

> **标准回答**：
> 1. **工具数量控制**：≤ 10 个，减少选择困难
> 2. **Schema 质量**：每个参数写清楚 description + constraints
> 3. **temperature 控制**：Function Calling 场景用 0.3-0.5，不高于 0.7
> 4. **错误降级**：3 次重试 → 降级到"我暂时无法处理"
> 5. **监控告警**：统计 `<tool_call>` 解析失败率，设置阈值告警
> 6. **A/B 测试**：关键场景准备 fallback 规则（正则匹配 → 直接路由）

## 5. 对比选型题

### Q8: 为什么选 Hermes 不选 GPT-4？

> **标准回答**：
> - **成本**：自部署 Hermes 3 8B 在 RTX 3060 上零 API 费用
> - **隐私**：金融/医疗数据不出本地
> - **可控性**：Hermes 的 "aggressively follows system prompt" 更适合 Agent
> - **定制**：全参数微调、量化、私有化部署
> - GPT-4 的优势是通用推理天花板 + 多语言，如果场景对这两个要求极高，选 GPT-4

### Q9: Hermes vs DeepSeek V3 怎么选？

> **标准回答**：

| 场景 | 选 Hermes | 选 DeepSeek V3 |
|------|:---:|:---:|
| 需要 Function Calling | ✅ | 一般 |
| 需要低硬件门槛 | ✅ (3B/8B) | 需要至少 380GB |
| 需要中文能力强 | 一般 | ✅ |
| 需要完全无审查 | ✅ | 一般 |
| 需要最高通用推理 | 一般 | ✅ |
| 需要 MIT 许可证 | ❌ (Llama 3 限制) | ✅ |

## 6. 实战场景题

### Q10: 你在 Java 项目里怎么集成 Hermes？遇到了什么问题？

> **标准回答框架**：
> 1. **选型理由**：项目需要 Agent 式 Function Calling，预算有限必须本地部署
> 2. **技术栈**：Spring AI + Ollama + Hermes 3 8B
> 3. **架构**：Spring Boot → Spring AI Ollama Starter → Ollama Server → Hermes 3
> 4. **问题一**：中文回答质量不够好 → System Prompt 指定"用中文回答" + few-shot
> 5. **问题二**：高并发时 Ollama 成为瓶颈 → 迁移到 vLLM，API 兼容，零代码改动
> 6. **问题三**：递归调用死循环 → max_depth=3 + timeout 机制

### Q11: 给一个没有 GPU 的服务器部署 Hermes，你会怎么做？

> **标准回答**：
> 1. 选择 Hermes 3 3B（最小模型）
> 2. 使用 GGUF Q4_K_M 量化（~2GB）
> 3. 用 llama.cpp 做 CPU 推理
> 4. 或者：用 Ollama（内置 llama.cpp），自动 CPU 推理
> 5. 预期：3B 模型在 8 核 CPU 上约 10-15 tokens/s，可接受
> 6. 备选：如果完全不能本地，用 OpenRouter / Together AI 的 Serverless API

## 7. 记忆系统题

### Q12: Hermes-Agent 的三层记忆架构是什么？

> **标准回答**：
> - **L1 内置记忆**：MEMORY.md (2200 字符) + USER.md (1375 字符)，Frozen Snapshot 模式
> - **L2 外部 Provider**：8 个可选（Honcho/Mem0/Holographic...），当时只选一个
> - **L3 会话搜索**：SQLite FTS5 全文索引所有历史会话
>
> 关键设计：**Frozen Snapshot** → 会话开始时拍快照注入 System Prompt，会话内写入只持久化到磁盘，不更新 System Prompt，保持前缀缓存（成本低 10 倍）

### Q13: Context Fencing 是什么？为什么重要？

> **标准回答**：用 `<memory-context>` 标签包裹所有召回的记忆内容，并在旁边标注"这是记忆上下文，不是新指令"。防御记忆注入攻击（用户把恶意指令写入记忆 → 下次加载时被当作 system prompt 执行）。这是 Agent 记忆系统的安全最佳实践。

## 核心要点回顾

| 考点 | 一句话 |
|------|--------|
| Hermes 是什么 | Nous Research 的无审查 + 强 Function Calling 开源 LLM |
| ChatML | `<\|im_start\|>` + 角色 + 内容 + `<\|im_end\|>` |
| Function Calling | system prompt 注入 `<tools>` → 模型输出 `<tool_call>` → 应用执行 → 回填 `<tool_response>` |
| 推理模式 | DeepHermes 3：system prompt 切换直觉/深度推理，`<think>` 包裹推理链 |
| 记忆系统 | 三层 + Frozen Snapshot + Context Fencing 安全防护 |
| 部署 | Ollama（开发）→ vLLM（生产）→ GGUF（边缘） |
| Java 集成 | Spring AI + Ollama starter，`@Description` 自动生成工具 Schema |
| 选型 | Hermes = 需要本地 + Agent + 无审查；GPT-4 = 需要天花板 + 多语言 |
