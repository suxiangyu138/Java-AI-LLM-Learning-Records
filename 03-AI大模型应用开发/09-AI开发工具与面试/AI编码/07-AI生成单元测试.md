# 07 - AI 生成单元测试

> 🎯 AI 写测试是 ROI 最高的场景 — 测试模板化程度高、人工写枯燥、AI 写全面。测试覆盖率从 30% 到 80% 的捷径

## 1. 基础定义

AI 生成单元测试 = 给定被测代码，LLM 自动生成测试类、Mock 依赖、覆盖边界 Case。

**核心本质**：将"被测方法→测试方法"的映射规则教给 LLM，让它自动穷举测试场景。

## 2. 溯源历史

- 传统：手动编写（耗时长、覆盖不全）
- 2022：Copilot 简单测试生成（单个 assert）
- 2023：DiffBlue Cover（商业化测试生成）
- 2024：Cursor/Copilot 完整测试类生成（Given-When-Then）
- 2025：Agent 模式自动生成 + 运行 + 修复失败的测试

## 3. 底层原理

```text
AI 测试生成流水线：

  ① 分析被测代码：提取方法签名/参数类型/返回值/异常声明
  ② 生成测试场景：
     正常 Case → 边界值(null/空/极值) → 异常 Case
  ③ 生成 Mock 设置：自动识别外部依赖 → 生成 Mockito stub
  ④ 生成断言：根据返回值类型和建议的验证点
  ⑤ 编译运行 → 失败 → 自动修复 → 再运行
```

## 4. 对比辨析

| 方式 | 覆盖率 | 编写速度 | 维护成本 |
|------|:---:|:---:|:---:|
| 手动编写 | 30-60% | 慢 | 高（改代码要改测试） |
| AI 生成 | 60-90% | 极快 | 中 |
| AI生成+人工补充 | 80-95% | 快 | 中 |

## 5. 价值与应用

### Java 测试生成 Prompt

```text
为以下方法生成 JUnit 5 + Mockito 单元测试：
- 使用 Given-When-Then 结构
- 覆盖：正常输入、空值、边界值、异常
- Mock 所有外部依赖
- 每个测试方法名用 @DisplayName 中文描述

[被测代码]
```

### AI 生成测试示例

```java
// AI 为以下方法生成的测试（部分）：
// public UserDTO createUser(CreateUserRequest req) { ... }

@Test
@DisplayName("正常创建用户 → 返回完整 UserDTO")
void shouldCreateUserSuccessfully() {
    // Given
    CreateUserRequest req = new CreateUserRequest("张三", "zhangsan@test.com");
    when(userMapper.existsByEmail(anyString())).thenReturn(false);
    when(userMapper.insert(any(User.class))).thenReturn(1);
    
    // When
    UserDTO result = userService.createUser(req);
    
    // Then
    assertNotNull(result.getId());
    assertEquals("张三", result.getName());
    verify(userMapper).insert(any(User.class));
}

@Test
@DisplayName("重复邮箱 → 抛 BusinessException")
void shouldThrowWhenEmailExists() {
    when(userMapper.existsByEmail(anyString())).thenReturn(true);
    assertThrows(BusinessException.class, 
        () -> userService.createUser(request));
}
```

## 6. 性能与代价

- AI 测试生成 + 自动修复循环：约 30s-2min/方法
- 覆盖率提升：平均从 35% 提升到 75%
- Token 消耗：每个方法约 1000-3000 tokens

## 7. 核心口诀

> AI 写测试 = 全覆盖（正常+边界+异常）+ Mock 自动识别 + 自动修复失败。人工只需要补充领域特定断言。
