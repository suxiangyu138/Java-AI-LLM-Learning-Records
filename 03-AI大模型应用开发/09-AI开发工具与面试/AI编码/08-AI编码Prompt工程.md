# 08 - AI 编码 Prompt 工程

> 🎯 同样的 AI 工具，好的 Prompt vs 差的 Prompt → 代码质量差 3-5 倍。Prompt 是你和 AI 之间的"编程语言"

## 1. 基础定义

AI 编码 Prompt 工程 = 通过结构化指令让 LLM 生成更准确、更完整、更安全的代码。

**核心本质**：用最小的 Token 消耗，获得最精确的代码输出。

## 2. 核心原则

```text
代码 Prompt 四要素：

  ① 角色设定：你是什么角色？→ 决定代码风格和专业度
     "你是资深 Java 架构师" vs "你是 Python 初学者" → 产出完全不同

  ② 技术栈约束：用什么技术？→ 限制输出范围
     "Spring Boot 3 + JDK 17 + MyBatis Plus"

  ③ 功能描述 + 边界：做什么？不做什么？
     "实现分页查询，不需要缓存，不需要权限校验"

  ④ 输出格式：代码怎么呈现？
     "只输出代码，不要解释" / "给出修改前后的 Diff"
```

## 3. 模板库

### 代码生成模板

```text
你是 [角色]，精通 [技术栈]。

请用 [语言/框架] 实现 [功能描述]。

要求：
- [约束1]（如：使用 Stream API）
- [约束2]（如：参数校验用 @Valid）
- [约束3]（如：异常统一用 BusinessException）

输出格式：[代码]  [需要解释]
```

### Bug 修复模板

```text
以下代码有 Bug：[描述现象]

环境：[JDK版本/框架版本/依赖]
代码：
[贴代码]
错误日志：
[贴日志]

请分析根因并给出修复代码（Diff 格式）。
```

### 架构设计模板

```text
你是 10 年经验的架构师。设计以下系统：
[需求描述]

请输出：
1. 架构图（ASCII）
2. 核心模块说明
3. 数据库设计（关键表）
4. 接口定义（关键 API）
5. 技术选型及理由
6. 潜在风险点
```

## 4. 常见误区

| 误区 | 改正 |
|------|------|
| "帮我写一个 XXX" | 缺少技术栈约束 → 可能用你不用的框架 |
| Prompt 太长（>2000字） | 核心信息在前，细节在后 |
| 不指定版本号 | "用最新版" → 模型训练数据可能滞后 |
| 一次要求太多 | 复杂需求分步提问 |
| 不贴错误日志 | Bug 修复不给日志 → AI 靠猜 |

## 5. 迭代技巧

```text
第一轮：生成初版代码
"用 Spring Boot 3 写用户注册接口，含参数校验"

第二轮：加约束
"密码要加密存储（BCrypt），返回 JWT Token"

第三轮：加异常处理
"加全局异常处理，重复注册抛 DuplicateUserException"

第四轮：加测试
"为这个接口生成单元测试和集成测试"

→ 4 轮迭代比一次性写 500 字 Prompt 效果更好
```

## 6. 核心口诀

> 角色+技术栈+约束+输出格式 = 高质量代码 Prompt。分步迭代优于一次性长篇。
