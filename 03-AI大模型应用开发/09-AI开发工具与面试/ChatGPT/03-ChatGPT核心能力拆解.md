## 2. 推理能力原理

GPT 的推理能力来自两个层面：

**① 训练数据的"模式匹配"**：数十亿行代码 + 数学论文 + 逻辑推理文本中学习了推理模式。HumanEval 从 GPT-3.5 的 67% 跳到 GPT-4 的 87%，核心原因是更大模型学到的推理模式更完整。

**② Chain-of-Thought 的"慢思考"**：`"让我们一步步思考"` → 自回归生成中，前面的推理步骤约束了后续 token 的生成空间。中间推理链缩小了答案的搜索范围 → 准确率大幅提升。这类似于人类从 System 1（直觉）切换到 System 2（分析）。

**为什么不是真正的推理？** GPT 本质是概率生成，没有符号逻辑引擎。对于多步推理中隐藏的逻辑漏洞，它可能"自信地给出错误推理链" → 需要人工审查。

## 3. 代码能力分析

**为什么 GPT 代码能力强？**
- 代码有严密的语法规则 → 比自然语言更容易学习概率分布
- GitHub 等平台提供了海量高质量代码训练数据
- 代码中的"函数调用"天然训练了长距离依赖

**代码生成限制**：
- 复杂业务逻辑（多系统联动）容易出错
- 生成的代码可能有安全漏洞（研究显示 AI 代码漏洞率比人工高 30%）
- 不了解公司内部框架和私有库 → 生成不可用的代码

## 4. 上下文窗口机制

GPT-4o 支持 128K tokens 上下文（约 300 页文档）。上下文窗口 = 模型的"短期记忆"——所有对话历史、系统指令、上传文件都在这个窗口内。

**关键限制**：128K 窗口 ≠ 完美利用 128K。研究显示长文本的中间位置信息容易被模型"忽略"（Lost in the Middle 现象）。使用建议：重要信息放在开头或结尾。

**Token 消耗**：长上下文 = 更高的 API 成本。128K 上下文一次对话可能消耗 $1-3 → 长文档分析需谨慎控制。

## 5. ChatGPT 适合和不适合做什么

```text
✅ 适合：
  → 代码生成/Debug/解释（GPT-4o 代码能力最强之一）
  → 长文写作/翻译/润色
  → 数据分析（上传 CSV，自动分析趋势）
  → 图片理解（OCR/图表/架构图分析）
  → 头脑风暴/方案探索/技术调研

❌ 不适合：
  → 需要 100% 准确的事实 → 有幻觉风险，用 RAG 兜底
  → 实时信息 → 需联网搜索（GPT-4o 支持但需手动开启）
  → 涉密数据 → 数据传给 OpenAI 服务器
  → 超大规模重复操作 → API 成本管理复杂
```
