## 1. GPT-4o 是什么

GPT-4o 是 OpenAI 2024 年 5 月发布的端到端多模态模型。"o" = "omni"（全能），单一模型统一处理文本、图片、音频的输入和输出。

**核心本质**：不再需要"语音→文本→LLM→文本→语音"的级联流水线，而是语音直接入、语音直接出。一个模型做所有模态的事。

## 2. 端到端架构原理

```text
传统方案（级联，延迟 2-5s）：
  语音 → Whisper(STT) → 文本 → GPT-4 → 文本 → TTS → 语音
  问题：丢失语气/情感/停顿信息、延迟高、多环节误差累积

GPT-4o 端到端架构（推测）：
  ┌────────────────────────────────────────┐
  │  文本 Token ──┐                        │
  │  图片 Patch   ──┤                        │
  │  音频 Chunk   ──┤                        │
  │               ↓                        │
  │      统一的 Transformer 主干            │
  │               ↓                        │
  │  输出 Token → 文本/图片/音频的解码       │
  └────────────────────────────────────────┘

核心创新：所有模态在统一的 Token 空间中表示和处理
→ 语音延迟 ~232ms（接近人类对话的 ~200ms）
→ 保留语气、情感、环境音等"副语言信息"
```

## 4. Java 开发实战场景

```text
① 架构图分析
   上传微服务架构图 → "分析这个架构的单点故障和性能瓶颈"
   输出：逐组件分析 + 改进建议 + 优化后架构图描述

② 错误日志截图分析
   上传控制台红色报错截图 → "这是什么错误，根因是什么，怎么修"
   输出：错误类型 + 根因分析 + 修复代码

③ 数据库 ER 图转 SQL
   上传 ER 图 → "生成所有表的建表 SQL（MySQL）"
   输出：完整 DDL + 索引建议

④ UI 设计稿转前端代码
   上传 UI 截图 → "生成对应的 Vue3 + Element Plus 代码"
   输出：完整前端组件代码

⑤ 接口文档截图转代码
   上传 Swagger/接口文档截图 → "生成 Java DTO + Controller"
   输出：完整 Java 类 + 参数校验注解
```

## 5. 性能与成本
