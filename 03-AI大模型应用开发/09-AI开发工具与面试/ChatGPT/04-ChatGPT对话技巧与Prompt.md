## 1. Prompt 的本质

GPT 是自回归概率模型——前面的 Prompt 决定了后面的生成分布。好的 Prompt = 把概率分布"聚焦"到期望的输出空间。

```text
模糊 Prompt："写点什么" → 输出随机、不可控
精准 Prompt："你是Java架构师，对比A和B，用表格输出，10个维度"
→ 输出精准、可用
```

---

## 2. 四要素核心公式

```text
高质量 Prompt = 角色 + 任务 + 约束 + 示例

示例：
  "你是资深 Java 架构师（角色）。
   对比 Spring Cloud Gateway 和 Kong 网关（任务）。
   用 Markdown 表格对比，至少 8 个维度（约束）。
   参考格式：| 维度 | SCG | Kong | 说明 |（示例）"
```

每个要素的作用：
- **角色**：决定回答的专业深度和视角。`"资深架构师"` vs `"初学者"` → 输出完全不同
- **任务**：明确做什么，用动词引导。`"对比"`、`"生成"`、`"解释"`、`"修复"`
- **约束**：控制格式、长度、范围。`"用表格"`、`"100 字以内"`、`"只输出代码"`
- **示例**：给模型"照葫芦画瓢"的参照。示例 > 描述

## 3. 高频模板库

```text
【代码生成】
角色：你是 10 年 Java 架构师
任务：用 Spring Boot 3 实现[功能]
约束：JDK17 / 参数校验 / 全局异常 / 单元测试
输出：完整代码，不要解释

【Bug 修复】
角色：你是资深 Java 调试专家
输入：[贴代码] + [贴完整报错]
任务：分析根因，给出修复后的完整方法
约束：保持原有逻辑不变

【技术决策】
角色：你是 CTO 级架构师
任务：在[场景]下对比[技术A]和[技术B]
输出：对比表(10 维度) + 决策建议 + 风险提示

【代码审查】
角色：你是 Java 代码审查专家，按阿里巴巴规范
任务：审查以下代码
重点：并发安全 / 事务边界 / SQL 注入 / NPE 风险
输出：🔴致命 / 🟡警告 / 🟢建议 分级输出
```

## 4. 对话管理技巧

```text
① 新话题 → 新对话
   清空上下文，避免前面话题干扰当前回答质量

② 长任务 → 分步对话
   每步验证后再下一步，一次性 2000 字 Prompt 不如 4 轮 500 字

③ 不满意 → 换表述
   "换一种方式解释" / "给出 3 个不同方案" / "再详细一点"

④ 固定风格 → Custom Instructions
   设置持久化 System Prompt（Settings → Customize ChatGPT）
   "请始终用中文回答，代码示例用 Java，遵循阿里巴巴规范"
```

## 5. 常见误区

| 误区 | 正确做法 |
|------|----------|
| "帮我写一个..." | 加技术栈约束 → "用 Spring Boot 3 + JDK 17 写一个..." |
| 一次要求太多 | 分步：先生成框架→ 再加细节→ 再加测试 |
| 不指定版本号 | "用 Spring Boot 3.2" 而非 "用最新版" |
| 不贴错误日志 | Bug 修复必须贴完整堆栈 + 复现步骤 |
| 不问"为什么" | 追问"为什么这样设计"→ 理解原理而非答案 |

> 🎯 Prompt 四要素 = 角色+任务+约束+示例。分步迭代优于一次性长篇，追问"为什么"优于只看答案。
