## 1. 数据流向与风险

```text
你的数据流向：
  浏览器/API → OpenAI 服务器（美国）→ 模型推理 → 返回结果

三个核心风险：
  ① 数据被用于模型训练 → 你的代码可能被"记住"并泄露给其他用户
  ② 敏感信息泄露 → API Key、数据库密码、客户 PII 上传后不可控
  ③ 合规违规 → GDPR/数据出境法要求数据不能出境

2023 年三星员工粘贴内部代码到 ChatGPT → 商业机密泄露事件
→ 三星随后禁用 ChatGPT，自建内部 AI
```

## 2. 隐私配置（必做）

```text
ChatGPT 网页版：Settings → Data controls →
  □ "Improve the model for everyone" → 关闭！
  □ "Chat history & training" → 关闭！

API 用户：
  ✅ 默认不用于训练（2023.03 后 OpenAI 承诺）
  ✅ 可在 API Platform 确认"Zero Data Retention"设置
  ⚠️ 免费版网页对话仍可能用于训练（除非手动关闭）

Enterprise 用户：
  ✅ 完全不出训练域（合同保证）
  ✅ 可自定义数据保留策略（30天/90天/永久删除）
```

## 3. 代码安全边界

```text
✅ 可以做的：
   → 通用算法/设计模式咨询
   → 开源框架使用问题
   → 生成测试数据（用假数据，不用真实用户数据）
   → 代码审查（脱敏后，替换真实变量名和值）

❌ 绝对不能做的：
   → 粘贴包含真实用户数据的代码（手机号/身份证/邮箱）
   → 粘贴公司内部 API Key / Token / 密钥
   → 粘贴未公开的商业逻辑 / 核心算法
   → 粘贴数据库连接字符串 / 服务器 IP
   → 粘贴客户合同 / 法律文件原文
```

## 4. 企业合规方案

| 方案 | 数据安全等级 | 成本 | 适用场景 |
|------|:---:|:---:|------|
| ChatGPT Enterprise | ⭐⭐⭐⭐ | $60+/人/月 | 有合规要求的中大型企业 |
| API + 数据不训练 | ⭐⭐⭐⭐ | 按量 | 自建应用的开发团队 |
| Azure OpenAI | ⭐⭐⭐⭐⭐ | 按量 | 需要数据驻留在指定区域 |
| 本地部署（Qwen/Llama） | ⭐⭐⭐⭐⭐ | 硬件+运维 | 涉密/军工/最高合规要求 |

## 5. 安全对比：云端 vs 自建

| 维度 | ChatGPT API | 本地部署 |
|------|:---:|:---:|
| 数据出境 | ⚠️ 是 | ✅ 否 |
| 模型控制 | ❌ 不可控 | ✅ 完全自主 |
| 运维成本 | 零 | 高（GPU+人力） |
| 模型质量 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ |

```text
推荐策略：
  ① 敏感业务 → 本地部署 Qwen/DeepSeek（数据不出公司）
  ② 非敏感开发 → ChatGPT API + 关闭训练（效率最高）
  ③ 混合 → 开发测试用 ChatGPT，生产用本地模型
```

> 🎯 敏感代码不上传、训练开关必关闭、涉密项目用本地。数据安全不是可选项，是上线前的必选项。
