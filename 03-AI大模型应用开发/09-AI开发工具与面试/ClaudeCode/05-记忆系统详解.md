# Claude Code 记忆系统详解

> **核心摘要**：Claude Code 如何"记住"用户偏好和项目信息？如何在跨会话复用知识？本文深度解析记忆系统架构、四种记忆类型、文件格式和最佳实践。

---

## 1. 记忆系统架构

```
Claude Code 记忆系统
├── CLAUDE.md（项目级指令）— 项目根目录，每次对话自动加载
├── .claude/memory/（持久化记忆文件）
│   ├── MEMORY.md        ← 记忆索引
│   ├── user_role.md     ← 用户角色
│   ├── feedback_test.md ← 用户反馈
│   └── project_xxx.md   ← 项目背景
├── settings.json（配置记忆）— 权限、钩子、偏好设置
└── 会话上下文（短期记忆）— 当前对话历史和操作轨迹
```

## 2. 四种记忆类型

| 类型 | 何时保存 | 示例 |
|------|---------|------|
| **user** | 了解用户角色、偏好、技术背景 | "他是 Java 后端，熟悉 Spring Boot" |
| **feedback** | 用户纠正或确认工作方式 | "不要在回复末尾加总结" |
| **project** | 项目背景、目标、约束、时间线 | "下周四前冻结代码合并" |
| **reference** | 外部系统资源指针 | "bug 追踪在 Linear 项目 INGEST" |

## 3. 记忆文件格式

```markdown
---
name: user-role-java-backend
description: 用户是 Java 后端工程师，SpringBoot 全栈方向
metadata:
  type: user
---

用户是 Java 后端开发，5 年经验，主攻 SpringBoot + 微服务。
正在同时学习 AI 大模型开发（Agent/RAG/MCP）。

[project-java-ai-learning](project-java-ai-learning.md) [feedback-no-trailing-summary](feedback-no-trailing-summary.md)
```

**关键字段**：
- `name`：唯一标识（kebab-case）
- `description`：用于判断何时读取该记忆
- `metadata.type`：user / feedback / project / reference
- 正文：记忆具体内容，Why + How to apply
- `[link](link.md)`：关联其他记忆

## 4. MEMORY.md —— 记忆索引

```markdown
- [用户角色：Java后端 AI全栈](user_role.md) — 5年Java经验
- [反馈：简洁回复](feedback_concise.md) — 不要写尾部总结
- [项目：学习笔记仓库](project_learning_repo.md)
- [参考：微服务文档](reference_microservice_docs.md) — Confluence地址
```

> **重点**：MEMORY.md 只是索引（每行 < 150 字符），正文在各 `*.md` 文件中。

## 5. 什么时候写入记忆

| 类型 | 触发条件 |
|------|---------|
| user | 了解用户角色、偏好、技术背景 |
| feedback | 用户纠正或确认不符合直觉的做法 |
| project | 了解项目目标、时间线、约束 |
| reference | 知道外部系统中资源的地址 |

## 6. 记忆与 CLAUDE.md 的区别

| 维度 | CLAUDE.md | Memory 系统 |
|------|-----------|-------------|
| 粒度 | 项目级通用指令 | 细粒度话题记忆 |
| 变化频率 | 低频 | 中高频 |
| 加载时机 | 每次对话全量加载 | 按需选择性加载 |
| 维护方式 | 手动编辑 | AI 自动写入 |
| 和 Git 关系 | 通常提交 | 通常不提交 |

## 7. 记忆最佳实践

| 应该写入 | 不要写入 |
|---------|---------|
| 用户纠正你行为时写入 feedback | 代码模式、目录结构 |
| 新外部工具地址写入 reference | Git 历史、提交信息 |
| 用户角色和背景写入 user | 当前对话临时状态 |
| 项目时间线和约束写入 project | 已写在 CLAUDE.md 中的内容 |

## 核心要点回顾

- 记忆 = 跨会话持久化知识
- 四种类型：user（角色）+ feedback（工作方式）+ project（项目上下文）+ reference（外部指针）
- MEMORY.md = 索引，memory/*.md = 正文
- 写入时机：用户纠正/确认/告知时立即写入
- 不写入：代码结构、Git 历史、临时状态
- 使用前验证记忆是否过时（文件是否存在、函数是否还在）
