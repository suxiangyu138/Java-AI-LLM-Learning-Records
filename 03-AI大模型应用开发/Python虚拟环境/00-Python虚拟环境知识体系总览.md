## 4. 核心概念速查

| 概念 | 一句话解释 |
|------|-----------|
| **虚拟环境** | 隔离的 Python 运行环境（独立解释器 + 独立 site-packages） |
| **PEP 405** | 虚拟环境的官方标准规范（venv 的实现基础） |
| **pyvenv.cfg** | 虚拟环境的配置文件（home 路径 + include-system-site-packages） |
| **venv** | Python 标准库内置虚拟环境工具（Python 3.3+） |
| **uv** | 2026 默认选型：Rust 单二进制，替代 pip/venv/pyenv/pipx/poetry 大部分功能 |
| **Poetry** | 成熟的锁文件 + 发布 PyPI 的库项目首选 |
| **conda** | 跨语言二进制包管理器（CUDA/GDAL 等原生依赖场景） |
| **锁文件（uv.lock）** | 精确到哈希的依赖锁定，提交版本控制保证可复现 |
| **pyproject.toml** | PEP 621 标准项目配置文件，现代工具的统一声明 |
| **uv run** | 免激活直接运行（无需 activate） |

## 5. 一图看懂：2026 工具选型

| 场景 | 工具 | 一句话理由 |
|------|------|-----------|
| **新项目（默认）** | **uv** | 快 10-100 倍 + 自带 Python 管理 |
| 受限环境/临时脚本 | venv | 标准库零安装 |
| 数据科学/AI（CUDA 等） | conda/mamba | 管理非 Python 原生依赖 |
| 现有 Poetry 项目（CI 正常） | 保持 Poetry | 健康项目不动 |
| 发布库到 PyPI | uv / Poetry | 成熟发布流程 |
| CI 流水线 | uv（`--frozen`） | 确定性构建 + 提速 30-90s |
| 全局 CLI 工具 | `uv tool install` | 替代 pipx |
| 教学入门 | venv → uv | 先原理后效率 |

---

> 💡 **一句话总结**：虚拟环境的本质只有三个文件（pyvenv.cfg + 解释器链接 + site-packages）——看懂原理，任何工具都只是语法糖。2026 年选型：**新项目用 uv，现有健康项目不动，需要原生依赖用 conda，受限环境用 venv**。
