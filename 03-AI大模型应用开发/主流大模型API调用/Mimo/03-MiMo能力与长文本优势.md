## 2. 长文本能力详解

### 2.1 大海捞针测试（长文本检索的黄金标准）

| 检索范围 | 准确率 |
|----------|:---:|
| 200K 以内 | 极高 |
| 200K-800K | 强（95%+） |
| 800K+ | 仍保持高准确率 |

### 2.2 1M 上下文的实际应用

```text
1M tokens ≈ 约 75 万英文单词 ≈ 2000+ 页文档

整库加载场景：
├── 大型代码仓库一次加载（无需 RAG 分块）
├── 数百页合同/法律文书全文分析
├── 年度财务报告完整阅读
├── 多轮长对话全量回顾
└── 企业知识库全文问答
```

### 2.3 长文本的成本优势

```text
同样处理 500K token 的长文档：

| 方案 | 成本（输入） |
|------|:---:|
| MiMo-V2.5 Pro（缓存命中） | ¥0.0125 |
| MiMo-V2.5 Pro（未命中） | ¥1.5 |
| GPT-5.6 Terra | ~$1.25（¥9） |
| Claude Opus 4.7 | $2.50（¥18） |

结论：长文档场景 MiMo 比国际旗舰便宜 10-100 倍
```

## 3. Agent 与工具调用

| 能力 | 详情 |
|------|------|
| Agent 指数 | 全球开源并列第一 |
| 工具调用 | OpenAI 兼容格式 |
| V2.5 改进 | **并行 tool calls 的 JSON 格式合规性** |
| 上下文 | 1M（长链路 Agent 不丢上下文） |

```python
# 工具调用示例（OpenAI 兼容）
tools = [{
    "type": "function",
    "function": {
        "name": "search_docs",
        "description": "搜索企业文档库",
        "parameters": {
            "type": "object",
            "properties": {"query": {"type": "string"}},
            "required": ["query"]
        }
    }
}]
# 1M 上下文 + 长链路 Agent = 长程任务不丢上下文
```


**短板说明：**
