## 1. AI 产品 PMF 验证框架

### 1.1 Sean Ellis 测试 × AI 特化版

```text
经典 PMF 问题："如果明天这个产品消失了，你会有什么感受？"

AI 特化版 PMF 信号：
├── 🟢 Strong PMF — ≥ 40% 用户说"非常失望"
├── 🟡 Early PMF — 25-40% 用户"非常失望"
├── 🟠 Pre-PMF   — < 25% 用户"非常失望"
└── 🔴 No PMF    — 用户不在乎 + 无有机增长
```

### 1.2 AI 产品的 PMF 双重验证

| 维度 | 传统 SaaS | AI 产品额外要求 |
|------|---------|---------------|
| **价值验证** | 用户愿意付费 | + AI 输出质量达到可用标准 |
| **体验验证** | 用户能完成任务 | + 用户信任 AI 的输出 |
| **成本验证** | 毛利 > 50% | + 算力成本随规模线性可控 |
| **增长验证** | 有有机增长 | + 数据飞轮在转动 |

> 🎯 **AI PMF 的独特挑战**：传统 SaaS PMF 看"用户愿不愿意付钱"，AI 产品还得看"用户敢不敢信任 AI 的输出"——前者验证价值，后者验证信任

## 2. 量化 PMF 的核心指标

### 2.1 AI 产品北极星指标体系

| 产品类型 | 北极星指标 | 为什么 |
|---------|-----------|--------|
| AI 客服 | 自动解决率 | 直接衡量 AI 替代人工的程度 |
| AI 写作 | 采纳率（生成内容被使用的比例） | 生成 ≠ 有价值，使用才是 |
| AI 搜索 | 任务完成率 | 找到信息 → 完成任务 |
| AI 编程 | 代码接受率 | 生成 → 采纳 → 提交 |
| AI 设计 | 生成→导出率 | 从"好玩"到"真用"的转化 |

### 2.2 PMF 信号检测

```python
class PMFDetector:
    """PMF 信号检测器"""

    PMF_SIGNALS = {
        "strong": {
            "retention_d7": 0.40,       # 7 日留存 > 40%
            "retention_d30": 0.25,      # 30 日留存 > 25%
            "organic_growth": 0.30,     # 自然增长占比 > 30%
            "nvp_score": 0.40,          # 消失失望 > 40%
            "ltv_cac": 3.0,             # LTV/CAC > 3
            "ai_adoption_rate": 0.50,   # AI 功能采纳率 > 50%
        },
        "early": {
            "retention_d7": 0.25,
            "organic_growth": 0.15,
            "nvp_score": 0.25,
            "ai_adoption_rate": 0.30,
        }
    }

    @classmethod
    def evaluate(cls, metrics: dict) -> str:
        """评估 PMF 阶段"""
        strong_score = sum(
            1 for k, v in cls.PMF_SIGNALS["strong"].items()
            if metrics.get(k, 0) >= v
        )
        early_score = sum(
            1 for k, v in cls.PMF_SIGNALS["early"].items()
            if metrics.get(k, 0) >= v
        )

        if strong_score >= 4:
            return "🟢 Strong PMF"
        elif early_score >= 3:
            return "🟡 Early PMF"
        elif early_score >= 1:
            return "🟠 Pre-PMF"
        else:
            return "🔴 No PMF"
```

## 3. 从 0 到 1 增长策略

### 3.1 AARRR 海盗指标 × AI

| 阶段 | 传统打法 | AI 特化打法 |
|------|---------|-----------|
| **Acquisition 获客** | 广告/SEO/内容营销 | **"Wow Demo"** — 5 秒展示 AI 能力 |
| **Activation 激活** | 注册 → 关键功能 | **"First Magic Moment"** — 第一次让用户惊叹 |
| **Retention 留存** | 推送/邮件/功能迭代 | **"数据飞轮"** — 越用越准，越准越用 |
| **Revenue 变现** | 订阅/广告 | **"能力分层"** — 免费体验 → 高级能力付费 |
| **Referral 推荐** | 邀请奖励 | **"可分享的 AI 结果"** — 生成的内容自带传播 |

### 3.2 AI 产品的 "First Magic Moment"

```text
普通产品 Aha Moment：
  "原来这个 App 能帮我记账！"

AI 产品 First Magic Moment：
  "天哪，它真的理解了我的需求！"

设计 First Magic Moment 的三个要素：
  1. 速度 — 必须 30 秒内到达（AI 等待每多 1 秒，流失 +10%）
  2. 精准 — 第一次结果就要对（用户不会给 AI 第二次机会）
  3. 超预期 — 用户没说出来的需求也被满足
```

### 3.3 增长飞轮设计

## 4. AI 产品留存与激活

### 4.1 留存曲线健康度

| 留存类型 | AI 产品基准 | 说明 |
|------|:---:|------|
| D1 留存 | > 50% | 第一天回来 |
| D7 留存 | > 30% | 第一周回来 |
| D30 留存 | > 20% | 月度活跃 |
| 使用频率 | > 3 次/周 | AI 产品需要高频才能建立信任 |

### 4.2 AI 特有的流失原因

| 流失原因 | 占比 | 对策 |
|------|:---:|------|
| **AI 输出质量不稳定** | 35% | 错误重试 + 人工兜底 |
| **等待时间太长** | 25% | 流式输出 + 预加载 |
| **不信任 AI** | 20% | 渐进式信任建立 |
| **不知道 AI 能做什么** | 15% | 主动推荐 + Use Case 引导 |
| **成本/价格** | 5% | Freemium 降低门槛 |

### 4.3 激活优化清单

```text
☐ D0：用户注册后 30 秒内体验 AI First Magic Moment
☐ D1：推送一个"你的 AI 助手为您准备了..."通知
☐ D3：展示"AI 已为您节省 X 小时"
☐ D7：推荐一个用户没用过但可能需要的 AI 能力
☐ D14：对比新老用户的 AI 使用数据 → 引导深度使用
```

## 5. PMF 失败诊断与 Pivot

### 5.1 失败信号速查

| 信号 | 阈值 | 可能原因 |
|------|:---:|------|
| D7 留存 < 15% | 🔴 严重 | 产品没解决真实问题 |
| NPS < 0 | 🔴 严重 | 用户不推荐你的产品 |
| AI 采纳率 < 20% | 🟠 警告 | AI 能力不够好或不够可见 |
| 自然增长 < 10% | 🟠 警告 | 没有口碑传播 |
| 付费转化 < 1% | 🟠 警告 | 价值感知不够 |

### 5.2 Pivot 决策框架

```text
发现 PMF 信号弱 → 诊断

├── 问题不对？（没人在乎这个需求）
│   └── Pivot: 换目标用户 or 换需求场景
│
├── 解决方案不对？（需求存在但方案不行）
│   └── Pivot: 改 AI 模型 or 改交互方式
│
├── 市场太小？（需求真实但用户基数不够）
│   └── Pivot: 向上游/下游/横向扩展
│
└── 时机未到？（需求存在但用户习惯未养成）
    └── 策略: 缩减 burn rate，等待时机
```

## 核心要点回顾

- AI PMF 双重验证：价值验证（愿不愿付费）+ 信任验证（敢不敢用）
- PMF 强信号：D7 留存 > 40%、自然增长 > 30%、消失失望 > 40%
- First Magic Moment = 30 秒内让用户惊叹 AI 的能力
- AI 流失三大原因：输出不稳定（35%）、太慢（25%）、不信任（20%）
- 增长飞轮核心：使用 → 数据 → 模型更好 → 更多使用
- PMF 失败 ≠ 产品失败，关键是快速诊断 + 果断 Pivot
