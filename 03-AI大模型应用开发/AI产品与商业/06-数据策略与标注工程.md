## 1. 数据飞轮：从 0 到 1 启动

### 1.1 飞轮公式

```
高质量数据 → 模型能力提升 → 用户体验改善 → 更多用户使用
     ↑                                                ↓
     └──────── 用户行为数据 ←── 使用过程产生 ←─────────┘
```

### 1.2 冷启动策略

| 阶段 | 数据量 | 目标 | 方法 |
|------|:---:|------|------|
| 冷启动 | 500-2000 条 | 跑通 MVP | 专家标注 + 模板生成 |
| 早期 | 2000-1万条 | 达到 80% 准确率 | 主动学习 + 众包 |
| 增长期 | 1万-10万条 | 达到 90%+ 准确率 | 用户反馈 + 半自动 |
| 成熟期 | 10万+ | 持续优化长尾 | 自动化 + 异常检测 |

> 💡 飞轮启动的第一批数据不需要"完美"，只需要"可用"——500 条高质量标注数据通常足够跑通一个领域 MVP

### 1.3 数据飞轮三大陷阱

| 陷阱 | 表现 | 对策 |
|------|------|------|
| **垃圾进-垃圾出** | 低质量标注导致模型越训越差 | 标注质量 > 标注数量 |
| **数据分布漂移** | 用户行为变化但训练数据未更新 | 持续监控数据分布 + 定期重训 |
| **飞轮断裂** | 用户反馈链路缺失，数据回不来 | 嵌入隐式反馈（点击/停留/采纳率） |

## 2. 主动学习标注策略

### 2.1 核心思想

```text
传统标注：随机抽样 → 全部标注 → 大量低价值样本浪费人力

主动学习：模型选最不确定的样本 → 只标注这些 → 标注效率提升 3-10x
```

### 2.2 不确定性采样策略

| 策略 | 原理 | 适用场景 |
|------|------|---------|
| **Least Confidence** | 选模型最"没把握"的样本 | 分类任务 |
| **Margin Sampling** | 选 Top-1 和 Top-2 概率差最小的 | 多分类 |
| **Entropy** | 选熵最大的样本 | 复杂场景 |
| **Query-by-Committee** | 多个模型投票最不一致的 | 确保多样性 |

### 2.3 实现框架

```python
import numpy as np

class ActiveLearner:
    """主动学习标注器"""

    def __init__(self, model, unlabeled_pool):
        self.model = model
        self.unlabeled_pool = unlabeled_pool
        self.labeled = []

    def uncertainty_sampling(self, strategy="entropy", n_samples=100):
        """选出模型最不确定的 n 个样本"""
        probs = self.model.predict_proba(self.unlabeled_pool)

        if strategy == "least_confidence":
            scores = 1 - np.max(probs, axis=1)        # 置信度最低
        elif strategy == "margin":
            sorted_probs = np.sort(probs, axis=1)
            scores = 1 - (sorted_probs[:, -1] - sorted_probs[:, -2])  # 边缘最小
        elif strategy == "entropy":
            scores = -np.sum(probs * np.log(probs + 1e-10), axis=1)  # 熵最大

        # 选得分最高的（最不确定的）
        query_idx = np.argsort(scores)[-n_samples:]
        return self.unlabeled_pool[query_idx]

    def add_labeled(self, samples, labels):
        """添加新标注样本 → 增量训练"""
        self.labeled.extend(zip(samples, labels))
        self.model.partial_fit(samples, labels)

    def estimate_remaining_budget(self, target_accuracy=0.90):
        """估算还需标注多少样本才能达到目标准确率"""
        current_acc = self.model.evaluate(self.labeled)
        improvement_rate = 0.02  # 每 100 条提升约 2%
        gap = target_accuracy - current_acc
        return int(gap / improvement_rate * 100) if gap > 0 else 0
```

## 3. 合成数据生成

### 3.1 四种生成方法

| 方法 | 原理 | 适用 | 质量 |
|------|------|------|:---:|
| **模板生成** | 预定义模板 + 变量填充 | 结构化任务 | ⭐⭐⭐ |
| **LLM 生成** | GPT-4/Claude 生成训练样本 | 通用 NLP | ⭐⭐⭐⭐ |
| **反向翻译** | 中→英→中 产生变体 | 文本增强 | ⭐⭐⭐ |
| **对抗生成** | GAN/扩散模型生成 | 图像/CV | ⭐⭐⭐⭐ |

### 3.2 LLM 合成数据流水线

```python
class SyntheticDataGenerator:
    """用 LLM 批量生成训练数据"""

    GENERATION_PROMPT = """
你是一个训练数据生成器。请生成 {num_samples} 条高质量的 {task_type} 训练样本。

任务描述：{task_description}

输出格式（JSON 数组）：
[
  {{"input": "用户输入", "output": "期望输出", "label": "标签"}},
  ...
]

要求：
- 覆盖 {num_categories} 种不同类型的场景
- 包含一些边界情况（edge cases）
- 输入多样化，避免重复模式
"""

    def __init__(self, llm_client):
        self.client = llm_client

    def generate(self, task_type, task_description,
                 num_samples=100, num_categories=5):
        prompt = self.GENERATION_PROMPT.format(
            num_samples=num_samples,
            task_type=task_type,
            task_description=task_description,
            num_categories=num_categories
        )
        response = self.client.chat(prompt)
        samples = json.loads(response)

        # 去重 + 质量过滤
        samples = self._deduplicate(samples)
        samples = self._quality_filter(samples)
        return samples

    def _deduplicate(self, samples):
        seen = set()
        unique = []
        for s in samples:
            key = s["input"][:50]
            if key not in seen:
                seen.add(key)
                unique.append(s)
        return unique

    def _quality_filter(self, samples):
        """过滤掉明显异常的低质量样本"""
        return [
            s for s in samples
            if len(s["input"]) > 5                      # 不能太短
            and len(s["output"]) > 0                    # 必须有输出
            and s["input"] != s["output"]               # 输入输出不能相同
        ]
```

> ⚠️ **合成数据风险**：LLM 生成的数据可能包含模型自身的偏见和错误。合成数据必须与真实数据混合使用（建议比例 3:7），且始终保留人工抽检

## 4. 数据版本管理与质量保障

### 4.1 版本管理策略

```yaml
# dataset-v2.3.yaml
version: 2.3
created: 2026-07-27
description: "客服意图分类数据集 v2.3 — 新增退款场景 200 条"
statistics:
  total_samples: 8500
  categories: 12
  avg_input_length: 45
  label_distribution:
    售后咨询: 25%
    订单查询: 20%
    投诉建议: 15%
    # ...
quality_metrics:
  inter_annotator_agreement: 0.92    # 标注一致性
  test_accuracy: 0.88                # 测试集准确率
  data_drift_score: 0.05             # 数据漂移度
```

### 4.2 质量保障检查清单

| 维度 | 检查项 | 通过标准 |
|------|--------|:---:|
| 完整性 | 所有样本都有标签/输出 | 100% |
| 一致性 | 相似输入得到相同标签 | IAA ≥ 0.85 |
| 多样性 | 覆盖所有预期场景 | 每类 ≥ 50 条 |
| 准确性 | 标注正确率 | ≥ 95% |
| 时效性 | 数据未过时 | 季度 review |
| 合规性 | 无 PII / 敏感信息 | 自动化扫描 |

## 5. 标注团队 SOP

### 5.1 标注流水线

```text
Step 1: 标注指南 → Step 2: 试标(20条) → Step 3: 一致性校准
       ↓                                        ↓
Step 4: 正式标注 → Step 5: 交叉验证(10%) → Step 6: 专家仲裁
                                         ↓
                                   Step 7: 入库 + 质量报告
```

### 5.2 标注指南模板

```markdown
## 任务：客服意图分类

### 类别定义
| 标签 | 定义 | 示例 |
|------|------|------|
| 售后咨询 | 退换货、维修 | "这个东西坏了能换吗" |
| 订单查询 | 物流、订单状态 | "我的快递到哪了" |
| 投诉建议 | 不满、建议 | "你们客服态度太差了" |

### 标注规则
1. 一句话可能属于多个意图 → 选最核心的一个
2. 不确定时 → 标注 `uncertain` + 备注原因
3. 遇到脏话/敏感 → 不标内容，标记 `flagged`

### 常见误区
- ❌ "帮我查一下" 不一定都是查询类，看上下文
- ❌ 不要根据"有没有礼貌用语"判断意图
```

## 核心要点回顾

- 数据飞轮冷启动只需 500-2000 条高质量标注数据
- 主动学习可以将标注效率提升 3-10 倍（只标模型最不确定的样本）
- 合成数据是冷启动利器，但必须与真实数据 3:7 混合 + 人工抽检
- 标注质量 > 标注数量——垃圾数据会让模型越训越差
- 数据版本管理 + 质量报告 = 模型可追溯、可复现
- 标注 SOP = 指南 + 试标 + 交叉验证 + 专家仲裁
