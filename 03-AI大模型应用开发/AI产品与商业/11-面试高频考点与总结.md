## 2. 产品思维题

### Q1（⭐⭐⭐⭐⭐ 高频）: AI 产品和传统产品最大的不同是什么？

> **标准回答**：
> 1. **输出不确定**：传统产品用户点击按钮 100% 知道结果，AI 产品可能给出不同质量的回答
> 2. **用户心智模型**：传统产品的交互模型是"我操作→它响应"，AI 产品是"我描述→它理解→它生成"
> 3. **信任是第一关**：传统产品关注可用性，AI 产品还得先解决"用户凭什么信你"
> 4. **数据飞轮**：传统产品靠功能迭代，AI 产品靠"使用→数据→模型更好→更多使用"的正循环
> 5. **成本结构**：传统 SaaS 边际成本接近 0，AI 产品每次推理都有算力成本

### Q2: 你怎么定义 AI 产品的成功指标？

> **标准回答**：
> 我通常用三层指标体系：
> - **技术层**：准确率、召回率、幻觉率、响应延迟（P50/P95）
> - **产品层**：AI 功能采纳率（用了的人/能看到的人）、AI 输出采纳率（用了的输出/生成的输出）、任务完成率
> - **商业层**：留存率（AI 产品留存通常比传统 SaaS 高 10-15%）、付费转化率、单位算力收入
>
> **举个例子**：对于 AI 客服——技术层看"自动解决率 85%+"，产品层看"用户转人工率 < 15%"，商业层看"客服从均工单量 +30%"

### Q3: 如果 AI 的输出质量不稳定，你作为 PM 怎么处理？

> **标准回答**：
> 1. **先定位问题**：是 Prompt 问题、模型能力问题、还是数据问题？（快速 A/B 测试隔离）
> 2. **降级策略**：对低置信度输出，不要强行展示，而是提示用户"AI 不确定，建议人工核实"
> 3. **渐进式信任**：高风险操作（发邮件、扣款）加人工确认，低风险操作（查天气）AI 直接回答
> 4. **反馈循环**：每个 AI 输出加"有用/没用"按钮，收集用户信号，持续优化
> 5. **预期管理**：产品内明确标注"AI 生成，可能有误"，让用户心理有准备

## 3. 商业分析题

### Q4: 怎么给一个 AI SaaS 产品定价？

> **标准回答**：
> 1. **成本底价**：算力成本 + 人力成本 + 边际成本 = 保本价
> 2. **价值定价**：为用户创造的价值 × 10-30% = 合理定价
> 3. **竞争参照**：市场上类似产品的价格区间
> 4. **定价模型选型**：
>    - 如果使用频率差异大 → 按量计费
>    - 如果使用频率稳定 → 订阅制
>    - C 端产品 → Freemium（转化率 2-5%）
>    - 企业产品 → 混合制（基础订阅 + 超额按量）
>
> **关键原则**：先定价值再定价格，不要按成本加成（AI 产品价值远超成本）

### Q5: 评估一个 AI 创业项目，你看什么？

> **标准回答**：
> 我按 **PMF 三问 + 护城河两问** 评估：
> - PMF 三问：
>   1. 解决的是"止痛药"还是"维生素"？（刚需 > 锦上添花）
>   2. 用户今天的替代方案是什么？AI 方案好多少？（10x 更好才值得切换）
>   3. 有付费意愿吗？（至少 10 个付费用户说了 yes）
> - 护城河两问：
>   1. 数据飞轮能转起来吗？（使用 → 数据 → 模型更好 → 更多使用）
>   2. 大厂做这个需要多久？（< 6 个月 = 没有护城河）

### Q6: 怎么计算 AI 项目的 ROI？

```text
ROI = (AI 带来的价值 - AI 的总成本) / AI 的总成本

AI 带来的价值：
  ├── 效率提升：节省的人力时间 × 人力成本
  ├── 收入增长：转化率提升 × 客单价
  ├── 体验改善：NPS 提升 → 留存率提升 → LTV 提升
  └── 机会成本：不做 AI 被竞品超越的损失

AI 的总成本：
  ├── 一次性：模型训练/微调、系统集成
  └── 持续：算力费用（月）、人力维护（月）、数据标注（按需）
```

## 4. 技术理解题

### Q7: RAG 是什么？什么时候用 RAG 而不是微调？

| 维度 | RAG | 微调 |
|------|-----|------|
| 知识更新 | 实时（改知识库即可） | 重新训练 |
| 成本 | 低（向量检索 + LLM 调用） | 高（GPU 训练） |
| 适用场景 | 知识库问答、实时信息 | 风格/格式/领域术语定制 |
| 幻觉控制 | 更好（有"参考答案"） | 一般 |
| 技术门槛 | 低 | 中高 |

> **一句话选择**：需要让模型"查资料"→ RAG；需要让模型"变成专家"→ 微调

### Q8: Function Calling 和 Agent 的区别？

> **标准回答**：
> - **Function Calling** = 模型调用一个工具然后返回结果（一问一答 + 一步操作）
> - **Agent** = 模型自主规划多步操作 → 调用多个工具 → 根据中间结果调整策略 → 直到完成任务
> - 类比：Function Calling 是"帮我查一下天气"，Agent 是"帮我规划一次北京三日游（查天气→查景点→查酒店→查交通→做行程表）"

### Q9: 你怎么评估一个 LLM 是否适合你的产品？

| 评估维度 | 方法 |
|---------|------|
| **任务准确率** | 准备 200 条真实场景测试集 → 人工评估准确率 |
| **响应速度** | P50/P95 延迟是否符合产品要求 |
| **成本** | 单次调用成本 × 预估日调用量 = 日成本 |
| **Function Calling** | 工具调用准确率 → 格式正确率 → 参数正确率 |
| **安全合规** | Prompt 注入防御、内容安全审查 |
| **部署灵活性** | 能否私有化部署？是否支持量化？ |

## 5. 案例设计题

### Q10: 设计一个智能客服系统

```
架构（5 分钟画出）：
┌────────────────────────────────────────────┐
│                   用户入口                    │
│        App / Web / 微信 / 电话               │
└────────────────────┬───────────────────────┘
                     │
          ┌──────────▼──────────┐
          │   意图识别（Router）  │  ← Fine-tuned 分类模型
          │  售前/售后/投诉/其他  │
          └──────────┬──────────┘
                     │
     ┌───────────────┼───────────────┐
     ▼               ▼               ▼
  售前知识库      售后流程         人工客服
  (RAG 问答)    (Function Calling)  (转接+工单)
     │               │               │
     └───────────────┴───────────────┘
                     │
          ┌──────────▼──────────┐
          │     智能路由 + 回答    │
          │  置信度高 → 直接回答  │
          │  置信度中 → 建议答案  │
          │  置信度低 → 转人工    │
          └─────────────────────┘

关键指标：自动解决率 85%+、转人工率 < 15%、用户满意度 > 4.2/5
```

### Q11: 如果你负责 ChatGPT 的增长，你会做什么？

> **回答框架**：
> 1. **激活优化**：新用户 30 秒内体验"First Magic Moment"——一个让用户惊叹的回答
> 2. **留存提升**：个性化推荐 Prompt（"你上次在写代码，要继续吗？"）
> 3. **病毒传播**：一键分享精彩的 AI 对话为图片/链接
> 4. **付费转化**：在免费用户"爽"的瞬间弹出付费引导（用完月度配额时）
> 5. **企业版**：团队协作 + 数据隔离 + 管理员控制台

## 6. 面试话术模板

### 开场自我介绍

```
"我是 XX，过去 X 年在 XX 公司做 AI 产品。我做的产品服务了 X 万用户，
AI 功能的采纳率达到 X%。我最大的收获是——AI 产品经理的核心不是懂
算法细节，而是能把技术能力翻译成用户价值和商业结果。

比如我做的 XX 项目，我们把一个 85% 准确率的模型做到 92%，技术上
提升 7%，但产品留存率提升了 20%——关键是找到了用户最在意的那个
场景，把准确率投到刀刃上。"
```

### 回答问题的思维框架

```text
STAR 法则 × AI 特化：
  Situation  → 业务背景 + 为什么需要 AI（不是别的方案）
  Task      → 产品目标 + 技术约束
  Action    → 我的决策 + 为什么这么选（Prompt vs 微调 vs RAG?）
  Result    → 量化的业务结果 + 学到了什么
```

### 反问面试官

```
1. "你们目前 AI 功能的使用率怎么样？用户最大的抱怨是什么？"
2. "团队目前是怎么决策'用模型A还是模型B'的？"
3. "你觉得你们产品最大的'反 AI'（不适合用 AI 解决）的场景是什么？"
4. "如果我要来，前 30 天你最希望我解决什么问题？"
```

## 核心要点回顾

- AI PM 面试最看重的不是"懂多少 AI"，而是"能翻译成多少商业价值"
- 产品思维题核心：不确定性管理 + 信任建立 + 数据飞轮
- 商业分析题核心：价值定价 > 成本定价，PMF > 规模化
- 技术理解题核心：知道 RAG/微调/Agent 的边界和选型依据
- 案例设计题核心：分层架构 + 降级策略 + 量化指标
- 反问环节是加分项：问产品现状而非公司文化
