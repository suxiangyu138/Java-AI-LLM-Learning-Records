## 1. 基础检索策略

### 1.1 Top-K 选择

```text
Top-K 太小（K=1-2）：
  ✅ 信息精准、噪音少
  ❌ 可能漏掉正确答案

Top-K 太大（K=20+）：
  ✅ 很少漏检
  ❌ 大量无关信息混入 → LLM 被误导
  ❌ Context 过长 → 成本增加

经验值：
  简单查询 → K=3-5
  复杂查询 → K=5-10
  多步推理 → K=10-15
```

### 1.2 相似度阈值过滤

```python
def retrieve_with_threshold(query_vec, index, top_k=10, min_score=0.7):
    """检索 + 阈值过滤"""
    scores, indices = index.search(query_vec, top_k)
    
    results = []
    for score, idx in zip(scores[0], indices[0]):
        if score < min_score:
            continue  # 低于阈值 → 丢弃（可能不相关）
        results.append({"idx": idx, "score": float(score)})
    
    return results

# 阈值选择：
#   0.8+ → 高精度（只返回高度相关）
#   0.6-0.8 → 平衡
#   <0.6 → 高召回（宁愿多返回）
```

## 2. 检索后处理

### 2.1 MMR 多样性重排

```python
from langchain_community.vectorstores import Chroma

retriever = vectorstore.as_retriever(
    search_type="mmr",  # Maximal Marginal Relevance
    search_kwargs={
        "k": 5,
        "fetch_k": 20,         # 先取 20 个
        "lambda_mult": 0.5     # 0=最大多样性, 1=最大相关性
    }
)
# MMR = 选相关但不重复的文档
```

### 2.2 相似度分数校准

```python
# 问题：不同查询的分数分布不同 → 无法设统一阈值
# 解决：用 Top-1 分数做归一化

def calibrate_scores(results):
    if not results:
        return results
    max_score = results[0]["score"]
    for r in results:
        r["calibrated_score"] = r["score"] / max_score
    return results
```

## 3. 查询改写

### 3.1 为什么需要改写

```text
用户输入的口语化问题 → 不利于向量检索

  用户："这个功能咋用啊，怎么搞都搞不出来"
  改写："XX 功能的使用方法和常见问题排查"

改写收益：检索命中率可提升 30-50%
```

### 3.2 改写策略

```python
# 策略 1：用 LLM 改写查询
def rewrite_query(user_query, llm):
    prompt = f"""将以下口语化的用户问题改写为适合文档检索的关键词搜索语句：
用户问题：{user_query}
搜索语句："""
    return llm(prompt)

# 策略 2：生成多角度查询（Multi-Query）
def multi_query_retrieval(user_query, llm, retriever):
    """生成 3 个不同角度的查询 → 分别检索 → 合并"""
    queries = generate_variants(user_query, llm)  # LLM 生成变体
    all_results = []
    for q in queries:
        results = retriever(q)
        all_results.extend(results)
    return deduplicate(all_results)

# 策略 3：HyDE（假设文档嵌入）
# 先用 LLM 生成一个"假设答案" → 用假设答案的 Embedding 去检索
def hyde_retrieval(user_query, llm, embed_fn, index):
    hypothetical_answer = llm(f"请简要回答：{user_query}")
    hyde_vec = embed_fn(hypothetical_answer)  # 假设答案的向量
    return index.search(hyde_vec)
```

## 4. 多路召回

```text
多路召回 = 多种检索方式并行 → 合并结果

  ① Dense 向量检索（语义匹配）
  ② BM25 关键词检索（精确匹配）
  ③ 元数据过滤检索（按来源/时间/类型过滤）

  合并 → 去重 → 融合排序 → Top-K
```

## 5. 检索问题诊断

| 现象 | 可能原因 | 排查方法 |
|------|----------|----------|
| **检索结果完全不相关** | Embedding 模型选错/向量未归一化 | 手动算几个相似度验证 |
| **相关但排位很低** | 切片质量差/向量被稀释 | 检查切片长度和内容 |
| **总是漏检** | Top-K 太小/相似度阈值太高 | 增大 K，降低阈值 |
| **结果全是同一文档** | 文档被切太碎/无多样性处理 | 加 MMR 或文档级去重 |
| **中文检索差** | 用了英文优化的 Embedding 模型 | 换成 BGE-M3 或 Qwen-Embedding |

---

## 核心要点回顾

- Top-K 默认 5，简单查询 3、复杂查询 10
- 相似度阈值 <0.6 → 结果可能不相关（建议 0.7+）
- 查询改写（LLM 改写 + Multi-Query + HyDE）可提升命中率 30-50%
- MMR 多样性重排避免返回重复内容
- 检索问题 → 先查 Embedding 模型匹配，再查切片策略
