## 3. 为什么必须学透 RAG 深化

1. **2025-2026 是 RAG 的范式剧变期**：从"切块+向量检索"的朴素形态，演进到 GraphRAG、Agentic RAG、Contextual Retrieval（Anthropic 2026）——**2025 年的 RAG 课程在 2026 年已过时**，本体系按最新状态撰写。
2. **质量瓶颈在"检索前后"而非检索本身**：查询改写、重排、上下文压缩带来的提升远超"换个 Embedding 模型"——**生产级 RAG 的优化空间 80% 在基础系统之外**。
3. **长上下文之争是 2026 最重要的架构决策**：1M+ token 模型是否让 RAG 过时？答案不是二选一而是**混合决策框架**——能讲清这个争论 = 架构师级认知。
4. **评估体系决定 RAG 能否持续迭代**：RAGAS 指标、黄金集、CI 门禁——"感觉还行"到"可度量"是工程化的分水岭。
5. **面试新题源**：GraphRAG 必要性之争、Agentic RAG 死循环、Lost in the Middle、Contextual Retrieval——2026 年面试的高频新题都在本体系。

## 4. 核心概念速查

### 4.1 RAG 五代演进

| 代 | 时期 | 代表 | 一句话 |
|:--:|:----:|------|--------|
| 1 | 2023 | Naive RAG | 切块 + 向量检索 + 拼上下文 |
| 2 | 2023-24 | Advanced RAG | 查询改写、重排、混合检索 |
| 3 | 2024 | Modular RAG | 模块化流水线（可插拔） |
| 4 | 2024-25 | Graph/Agentic | 图谱全局观 + Agent 自主检索 |
| 5 | **2026** | **Contextual Retrieval** | 块级上下文描述（Anthropic） |

### 4.2 核心概念一句话

| 概念 | 一句话 |
|------|--------|
| HyDE | 先让 LLM 生成假设答案，再用它检索（文档-查询语义对齐） |
| Step-back | 把具体问题改写为更泛化的问题再检索 |
| Multi-Query | 一个查询拆成多个角度并行检索再融合 |
| RRF | 多路检索的倒数排名融合 |
| Cross-Encoder | 查询-文档对一起编码打分（精度高、慢） |
| GraphRAG | 实体/关系图谱 + 社区摘要（全局问题强） |
| Lost in the Middle | 相关文档在上下文中间时被忽视（75%→50%） |
| Contextual Retrieval | 给每个块生成上下文描述（失败率降 49%） |
| RAGAS | 开源评估框架（四指标） |

## 6. 学习路线推荐

**路线一：架构进阶（2~3 天，对应模块 01-03）**
五代演进与三大范式 → 查询优化（重点 HyDE 与 Multi-Query）→ 重排与压缩（生产 Reranker 落地）。

**路线二：前沿范式（1 周，对应模块 04-07）**
GraphRAG（重点 Local/Global 与成本之争）→ Agentic RAG（重点自我反思与防死循环）→ 长上下文之争（重点决策框架）→ 多模态。

**路线三：工程深化（对应模块 08-10）**
评估体系（黄金集 + CI 门禁）→ 性能与成本 → 面试冲刺；对照基础系统的生产实战篇查漏补缺。

> 🎯 **核心要点**：RAG 深化的学习终点 = "**能按问题类型选范式（向量/图谱/Agentic/长上下文），能量化评估与成本，能防住前沿范式的坑**"——三件事是 2026 年 RAG 工程师的分水岭。
