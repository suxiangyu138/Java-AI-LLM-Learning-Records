## 1. 必背考点：十二问

### 1.1 RAG 五代演进？

**答题链**：Naive（2023 切块+向量）→ Advanced（2023-24 查询改写/重排/混合）→ Modular（2024 可插拔）→ Graph/Agentic（2024-25）→ **Contextual Retrieval（2026 Q2 Anthropic）**→ "Naive RAG 之死"讨论（2026-04 峰会）→ 2026 生产底线（混合+重排+改写+评估）。

### 1.2 Contextual Retrieval 是什么？

**答题链**：给每个文档块生成"上下文描述"再编码 → 解决"块脱离语境"→ 实测失败率 -49%（+BM25+重排 -67%）→ 本质是块质量工程（不动检索算法）。

### 1.3 查询改写有哪些流派？

**答题链**：三流派 = **HyDE（假设答案检索，解决表述不对齐）+ Step-back（泛化改写，解决层次不对齐）+ Decomposition（子查询拆分，解决粒度不对齐）**→ Multi-Query（多角度并行 + RRF 融合）→ 评估闭环（黄金集验证，防"改歪"）。

### 1.4 为什么 Cross-Encoder 重排更准？

**答题链**：Bi-Encoder 独立编码（向量相似度）vs Cross-Encoder **拼接联合编码**（注意力交互）→ 检索用 Bi（快）、重排用 Cross（准）→ 标准模式：混合召回 20 → 重排 → Top-5 → MRR +5-15、缓解 Lost in the Middle、token 成本下降。

### 1.5 GraphRAG 的架构？

**答题链**：LLM 实体/关系抽取 → 知识图谱 → **Leiden 社区检测 → 社区摘要**（两级索引）→ **Local Search（实体图，具体事实）/ Global Search（社区摘要 Map-Reduce，全局总结）**→ 收益：Exact +23%、Multi-hop +46%、跨文档 +47%。

### 1.6 什么场景值得用 GraphRAG？

**答题链**：选型判据 = 全局/关系问题占比 × 文档规模 − 构建成本（**100 万字 ≈ 数十美元**）× 更新频率 → **《Is GraphRAG Needed?》（ACL GEM 2026）结论：全局问题值得、局部问题混合检索+重排就够**→ LightRAG 轻量替代（砍社区摘要、换增量更新）。

### 1.7 Agentic RAG 是什么？风险？

**答题链**：检索从"强制流水线"变"Agent 工具"（按需调用/多跳/反思）→ 任务分解（Plan-then-Execute / 动态）→ 自我反思（**CRAG 评估纠错重查 / Self-RAG 按需检索+反思标记**）→ **死循环风险（烧 token）→ max_iterations + 循环检测 + 超时三道防线**。

### 1.8 长上下文模型为什么没有消灭 RAG？

**答题链**：两个实验事实——**Lost in the Middle（相关文档居中准确率 75%→50%）** + **Context Rot（长上下文推理衰减，声明窗口 > 可用窗口）**→ 成本（全量输入百倍于 RAG 输入）+ 新鲜度/权限/溯源约束 → **混合决策框架：单文档深读用长上下文、单点查询用 RAG、多文档综合用混合（检索 50K-200K 再推理）**。

### 1.9 RAGAS 四指标？

**答题链**：**Faithfulness（忠实度，幻觉哨兵）+ Answer Relevance（相关）+ Context Precision（精度）+ Context Recall（召回）**→ 对应三层评估（检索层/生成层/端到端）→ 分层定位问题（检索漏了 vs 没用好）→ 第五指标 Answer Correctness（有黄金答案时）。

### 1.10 评估体系怎么建？

**答题链**：黄金集（50-500 条，人工标注相关块，覆盖问题类型）→ 离线 CI 门禁（每次改动跑评估，降 2-3% 阻断）→ 在线抽样（5-10% 流量 + 漂移告警）→ 成本控制（检索指标零成本、日常小判官、蒸馏判官）。

### 1.11 RAG 成本怎么优化？

**答题链**：四板斧 = **语义缓存（相似问题秒回）+ 路由分流（简单问题小模型/免检索）+ 上下文精简（Top-5 + 压缩）+ 模型分级**→ 成本模型（输入/输出 token 记账）→ 先定质量底线与延迟预算，再在约束内砍成本。

### 1.12 多模态 RAG 怎么做？

**答题链**：企业文档模态混合（PDF/表格/图表）→ 两条路线：**文本抽取（解析转文本，便宜但丢图表）vs 视觉检索（ColPali 页面图像编码，保真）**→ ColPali = late-interaction（查询 token × 页面 patch 最大相似度）→ 生产组合：双通道 + 路由 + VLM 生成。

## 2. 高频陷阱题 12 连问

1. **对错**：长上下文模型（1M token）出现后 RAG 不再需要。（❌ Lost in the Middle + Context Rot + 成本/新鲜度/权限约束——混合才是正解）
2. **对错**：GraphRAG 适合所有场景。（❌ 局部问题用混合检索+重排更划算——成本账与必要性研究）
3. **结果**：Agentic RAG 不设 max_iterations 会怎样？（死循环烧 token——三道防线必配）
4. **对错**：HyDE 一定能提升检索。（❌ 假设答案跑偏会污染检索——必须评估验证）
5. **对错**：Cross-Encoder 用于召回阶段。（❌ 慢——召回用 Bi-Encoder，重排用 Cross-Encoder）
6. **结果**：检索指标升了但回答质量没升？（"检索-生成鸿沟"——端到端也要评估）
7. **对错**：Contextual Retrieval 是换检索算法。（❌ 是块质量工程——给块补语境）
8. **对错**：RAGAS 只需要测端到端准确率。（❌ 分三层评估才能定位问题层）
9. **结果**：语义缓存阈值设太低（如 0.7）？（误命中——给相似但不相同的问题错误答案）
10. **对错**：GraphRAG 的 Global Search 适合查"张三的职责"。（❌ 那是 Local Search——全局问题才用 Global）
11. **对错**：多模态 RAG = 文本 RAG + OCR。（❌ 视觉检索（ColPali）直接对图像编码，跳过文本层）
12. **结果**：重排后还需要阈值过滤吗？（需要——重排管排序，阈值管"不够相关的别喂"）

## 3. 高频追问速答

| 追问 | 速答 |
|------|------|
| 检索失败率是什么？目标？ | 检索结果不含所需信息的请求占比；2026 工程目标 <5% |
| Step-back 和 HyDE 能一起用吗？ | 能——但每层都有成本与跑偏风险，评估决定取舍 |
| 语义缓存存什么？ | 问题-答案对（语义索引 + 相似度阈值 0.9-0.95） |
| 提示缓存和语义缓存区别？ | 提示缓存 = API 层前缀 token 复用；语义缓存 = 应用层相似问题答案复用 |
| GraphRAG 更新知识怎么办？ | 增量索引是痛点（LightRAG 支持）；全量重建成本高 |
| 为什么 2026 强调"问题-策略映射"？ | 没有一种检索策略通吃——按问题类型选路径是架构方法论 |
| 多模态检索的评估难点？ | 图表相关性人工标注主观；VLM 读图错误难自动检测 |
| 蒸馏判官是什么？ | 用旗舰 LLM 标注数据蒸馏出的专用小评估模型（在线高频评分） |
| Agentic RAG 和传统 RAG 哪个好？ | 不是替代——简单查询传统更快更稳，复杂多跳 Agentic 更聪明（路由分流） |
| 上下文压缩和重排的区别？ | 重排管"哪些块进"（文档级）、压缩管"块里哪些内容进"（片段级） |

## 4. 场景题：生产级 RAG 深化设计

**题目**：现有 RAG 系统（切块 + 向量检索 + Top-5 拼上下文）效果不佳：① 全局问题答不了 ② 精确术语查不到 ③ 相关文档在中间时答错 ④ 成本偏高。请设计优化方案。

**答题框架**（按评分点展开）：

```text
① 问题诊断（先评估后优化）：
   - 建黄金集（50-200 条，覆盖四类问题）→ RAGAS 分层评估
   - 定位：② 术语问题 → 检索层（Context Recall 低）
   - 定位：③ 位置问题 → 生成层（Lost in the Middle）
   - 定位：① 全局问题 → 结构盲区（向量检索做不了）

② 分层优化：
   - 检索层：混合检索（BM25 + Dense + RRF）+ 查询改写（术语类走 BM25 强权重）
   - 索引层：Contextual Retrieval（块语境）+ 块质量优化
   - 排序层：Cross-Encoder 重排（召回 20 → Top-5，解决 Lost in the Middle）
   - 结构层：全局问题路由到 GraphRAG（评估全局问题占比决定是否上）

③ 成本控制：
   - 语义缓存（重复查询秒回）+ 路由分流（简单问题小模型/免检索）
   - 上下文精简（Top-5 + 压缩）→ 输入 token -40-60%

④ 评估闭环：
   - 每步优化用黄金集验证（检索失败率逐层下降 → 目标 <5%）
   - CI 门禁 + 在线抽样监控（防回归与漂移）

⑤ 加分点：
   - 谈"检索-生成鸿沟"（检索指标升 ≠ 回答质量升，端到端要测）
   - 谈长上下文方案（单文档场景可直输，混合决策框架）
   - 谈多模态（文档含图表时上视觉检索通道）
```
