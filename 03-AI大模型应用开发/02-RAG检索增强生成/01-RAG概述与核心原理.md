## 1. 什么是 RAG

```text
RAG = Retrieval-Augmented Generation

  用户问题 → 检索相关文档 → 将文档作为上下文 → LLM 生成回答

传统 LLM：
  Q: "公司最新的请假政策是什么？"
  A: "我不知道，我的知识截止于 2023 年..." ❌

RAG LLM：
  Q: "公司最新的请假政策是什么？"
  ① 检索：从公司内部文档中找到《2026 年考勤制度 v3.2》
  ② 拼接：将文档内容作为 prompt 的一部分
  ③ 生成："根据《2026 年考勤制度 v3.2》，年假..." ✅
```

---

## 2. 为什么需要 RAG

```text
RAG 解决 LLM 的三大核心问题：

  ① 知识时效性
    LLM 知识截止于训练日期 → RAG 接入最新文档

  ② 幻觉
    LLM 可能编造事实 → RAG 约束回答基于检索到的文档

  ③ 私有知识
    LLM 不知道企业内部知识 → RAG 接入私有文档库

相比微调：
  ✅ 无需训练 → 知识更新只需更新文档
  ✅ 可溯源 → 知道答案来自哪个文档
  ✅ 成本低 → 不需要 GPU 微调
```

## 3. RAG 核心链路

```text
RAG 全链路 = 离线索引 + 在线检索 + 生成

┌──────────────────────────────────────────────────────┐
│  离线索引（Indexing）                                  │
│                                                       │
│  文档 → 切片(Chunk) → Embedding → 向量数据库           │
│                                                       │
├──────────────────────────────────────────────────────┤
│  在线检索 + 生成（Retrieval + Generation）             │
│                                                       │
│  用户问题 → Embedding → 向量检索 → Top-K 文档          │
│  → 拼接 Prompt → LLM → 回答                           │
└──────────────────────────────────────────────────────┘

关键组件：
  ① 文档处理：加载 + 解析 + 切片
  ② Embedding 模型：文本→向量
  ③ 向量数据库：存储 + 检索
  ④ 检索策略：相似度计算 + Top-K + 过滤
  ⑤ LLM：基于检索结果生成回答
```

### 代码级理解

```python
# RAG 的最简实现（10 行核心逻辑）
def simple_rag(question, doc_chunks, embed_fn, llm):
    # ① 离线：文档向量化（可提前做）
    doc_vecs = embed_fn(doc_chunks)
    
    # ② 在线：问题向量化 + 检索
    q_vec = embed_fn(question)
    scores = cosine_similarity(q_vec, doc_vecs)
    top_chunks = doc_chunks[top_k_indices(scores)]
    
    # ③ 生成
    context = "\n".join(top_chunks)
    prompt = f"参考资料：\n{context}\n\n问题：{question}\n回答："
    return llm(prompt)
```

## 4. RAG vs 微调 vs 长上下文

| 维度 | RAG | 微调 | 长上下文 LLM |
|------|:---:|:---:|:---:|
| **知识注入** | 外挂文档 | 训练进模型参数 | 全放 Prompt 里 |
| **知识更新** | 即时（更新文档） | 需重训 | 即时（改 Prompt） |
| **成本** | 低 | 中（需 GPU） | 高（长 Prompt 贵） |
| **可溯源** | ✅ | ❌ | ✅ |
| **幻觉控制** | ⭐⭐⭐⭐ | ⭐⭐ | ⭐⭐⭐ |
| **适用数据量** | 海量（向量库） | 中等 | 小（受 Context Window 限制） |

```text
三者不是互斥关系，而是互补：
  最优方案 = 微调（领域风格）+ RAG（最新知识）+ 长上下文（单文档深度分析）
```

## 5. RAG 的适用场景

| 场景 | 说明 | 典型应用 |
|------|------|----------|
| **企业知识库** | 内部文档问答 | 员工手册/技术文档/规章制度查询 |
| **客服系统** | 基于产品文档的智能问答 | 自动回复/工单建议 |
| **个人知识管理** | 笔记/阅读材料的智能检索 | 第二大脑/AI 笔记助手 |
| **法律法规查询** | 基于法条的精准问答 | 法律顾问/合规审查 |
| **代码库问答** | 基于代码仓库的技术问答 | 代码搜索/Bug 定位 |

---

## 核心要点回顾

- RAG = 检索（从知识库找相关内容）+ 生成（基于内容回答）
- 核心链路：文档切片 → Embedding → 向量库 → 检索 → LLM 生成
- RAG 解决三大问题：知识时效性、幻觉、私有知识
- RAG vs 微调：RAG 即时更新、成本低、可溯源
- 最佳实践：微调（风格）+ RAG（知识）+ 长上下文（深度分析）
