## 1. 为什么需要向量数据库

```text
传统数据库：
  SELECT * FROM docs WHERE content LIKE '%Transformer%'
  → 只能精确/模糊匹配关键词 → 找不到语义相关的内容

向量数据库：
  查询 "Attention 机制" → 找向量最相似的文档
  → 能返回 "自注意力机制"、"Transformer 核心架构" → 语义匹配
```

---

## 2. 核心概念

| 概念 | 说明 |
|------|------|
| **向量 Embedding** | 文本/图片转成的浮点数数组（如 1024 维） |
| **ANN 近似最近邻** | Approximate Nearest Neighbor — 牺牲少量精度换速度 |
| **索引 Index** | 加速向量检索的数据结构（Flat/HNSW/IVF） |
| **Collection** | 向量 + 元数据的集合（类似数据库的 Table） |
| **相似度度量** | 余弦相似度 / 内积 / 欧氏距离 |

```text
ANN 的核心 trade-off：
  精度 Recall vs 速度 QPS vs 内存
  → 三选二，无法三者兼得
```

---

## 3. 核心性能指标

| 指标 | 说明 | 目标 |
|------|------|:---:|
| **QPS** | 每秒查询数 | >100 |
| **Recall@K** | 前 K 个结果中包含正确答案的比例 | >95% |
| **延迟 P99** | 99% 请求的响应时间 | <50ms |
| **内存** | 向量索引占用的内存 | — |
| **插入速度** | 每秒可插入的向量数 | >1000/s |

## 4. 向量数据库 vs 传统数据库

| 维度 | MySQL/PostgreSQL | Elasticsearch | 向量数据库 (Milvus) |
|------|:---:|:---:|:---:|
| **查询方式** | SQL 精确匹配 | 全文检索 | 向量相似度 |
| **语义理解** | ❌ | ❌ | ✅ |
| **扩展性** | 垂直 | 水平 | 水平 |
| **典型 QPS** | 10K+ | 1K+ | 100-10K |
| **数据规模** | TB 级 | TB 级 | 10 亿向量 |

---

## 核心要点回顾

- 向量数据库 = 存储 Embedding + 高效 ANN 检索
- 核心指标：QPS / Recall@K / 延迟 P99 / 内存
- ANN 的 trade-off：精度 vs 速度 vs 内存（三选二）
