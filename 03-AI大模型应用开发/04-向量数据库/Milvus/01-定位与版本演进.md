## 1. Milvus 的定位

**Milvus**：基于云原生架构的**开源向量数据库**（Apache 2.0），Zilliz 主导开发，LF AI & Data 基金会毕业项目——在开源向量数据库采用率中**全球第一**。

**与同类产品的定位差异**：

| 产品 | 定位 | 规模 | 特点 |
|------|------|:----:|------|
| **Milvus** | 分布式向量数据库 | **亿级+** | 云原生架构、混合检索、完整数据管理 |
| Qdrant | 向量数据库 | 千万级 | Rust 实现、API 友好 |
| Weaviate | 向量数据库 | 千万级 | GraphQL、模块化 |
| Chroma | 轻量向量库 | 万-百万级 | 极简、开发测试 |
| FAISS | 索引库（非数据库） | 亿级 | 仅索引，无数据管理 |
| pgvector | PostgreSQL 扩展 | 百万级 | 复用 PG 生态 |

**Milvus 的核心竞争力**：

1. **分布式原生**：存算分离架构（Proxy/DataNode/QueryNode 等组件），水平扩展；
2. **混合检索**：稠密向量 + 稀疏向量（BM25）+ 标量过滤一体（2.5+）；
3. **完整数据管理**：分区、TTL、快照、多租户、备份恢复——不只是"索引"；
4. **生态集成**：Spring AI、LangChain4j、LangChain、Dify 全部官方支持；
5. **云端一致性**：Zilliz Cloud 托管（与开源同代码）。

> 🎯 **核心要点**：Milvus 的定位 = "**生产级分布式向量数据库**"——对比的参照物是"数据库"而非"索引库"：它管理数据生命周期（写入/检索/删除/备份），而 FAISS 只是索引组件。**选型口诀：原型 Chroma、生产 Milvus、超大规模 Cloud**。

## 2. 版本时间线：2.4 → 2.5 → 2.6 → 3.0

**版本演进（时效性重点，2026-08 检索核实）**：

| 版本 | 时间 | 核心变化 | 工程影响 |
|------|:----:|---------|---------|
| 2.4 | 2024 | 分区键（Partition Key）、**upsert 原子操作**、流式 API | 多租户与实时更新落地 |
| **2.5** | 2025 | **集成 Tantivy 搜索引擎**：内置 **Sparse-BM25** 原生全文检索、`TEXT_MATCH` 关键词匹配、内置分词器（含中文）、**RRFRanker 混合检索** | 告别"外部全文检索组件"，混合检索开箱即用 |
| **2.6** | 2025 Q1 | **性能大升级**：内存占用降 72%（2G 可运行）、检索速度提升 4 倍（<50ms）、写入吞吐 2.5 倍、索引构建 3 倍、并发连接 5000+ | 小规模单机部署成为现实 |
| **3.0** | **2026-06 预览 → 2026-07-16 GA** | **Lake-Native 架构**（下节详述） | 向量库与数据湖打通 |

**关键认知**：

- **2.5 的 BM25 是分水岭**：此前全文检索要靠 Elasticsearch 等外部组件（两套系统 + 数据同步）；2.5 起 **Milvus 单库完成混合检索**——这是 RAG 工程架构的重大简化；
- **2.6 的"2G 内存可运行"**：让"生产级向量库"的下限大幅降低——中小项目单机 Docker 即可；
- **3.0 是"史上最大架构更新"**：不只是功能叠加，是数据架构的代际变化。

> 🎯 **核心要点**：版本记忆锚 = "**2.5 解决检索能力（BM25）、2.6 解决性能成本（内存/速度）、3.0 解决数据架构（湖仓原生）**"——三个阶段各自回答一个工程痛点。

## 3. 3.0 Lake-Native 架构总览

**Milvus 3.0（2026-07-16 GA，Apache 2.0）**——"**Lake-Native（湖仓原生）**"是核心关键词：**向量检索直接作用于数据湖上的开放格式数据，无需数据拷贝**。

**五大核心能力**：

| 能力 | 说明 | 价值 |
|------|------|------|
| **外部集合（External Collections）** | 直接对 Lance / Iceberg / Parquet / Vortex 等开放格式数据建 Collection——源数据不入 Milvus，Milvus 只建索引（向量/BM25/JSON/标量），支持增量同步 | **消灭数据拷贝**——数据湖一份数据，检索直接用 |
| **Loon（存储引擎 V3）** | 基于清单（manifest）的列式存储引擎，用 **Vortex**（Arrow 兼容列式格式）；点读 I/O 从 ~9.4MB 降到 ~0.07MB（**~135 倍**） | 对象存储上的低延迟点查 |
| **快照（Snapshots）** | 在线集合的**时间点只读视图**（MVCC 隔离）——评估/去重/回填等批处理可跑在生产写入之上 | 生产与批处理并行 |
| **Spark DataSource V2** | Spark / Databricks / EMR 以标准批处理读写 Milvus（含向量原生去重/聚类算子） | 数据管道打通 |
| **在线 Schema 演进** | 运行时 ALTER ADD/DROP COLUMN，无需重建索引/中断服务 | 字段演进零停机 |

**检索引擎扩展**（不止 Top-K）：

- 服务端 **ORDER BY**（多字段排序下推）、SQL 风格**聚合**（COUNT/SUM/AVG/GROUP BY）；
- **StructList**：原生多向量存储（每实体可变长度向量数组——chunks/patches/tokens），原生支持 **ColBERT/ColPali 的 late-interaction 检索**；
- **SINDI**：新的默认稀疏倒排索引（比旧稀疏索引小 ~3 倍，学习型稀疏向量上 QPS 高 ~10 倍）；
- 服务端 MinHash（DIDO）近似去重；更多 Faiss 兼容索引（SVS/Panorama/PQ/ScaNN）。

**Schema 与类型增强**：**TEXT 一等类型**（原文与向量共存、支持 BM25）、**BLOB**（二进制）、可空向量字段、全局主键去重、实体级 TTL（TIMESTAMPTZ）、自定义词典/同义词表（FileResource，中文检索增强）。

> 🎯 **核心要点**：3.0 的一句话 = "**向量检索不再需要把数据搬进向量库**"——外部集合直读数据湖 + Loon 低延迟存储 + 快照 + Spark 管道，让 Milvus 从"向量数据库"进化为"**AI 检索的数据基础设施**"。面试谈 3.0 时抓住"Lake-Native + 外部集合 + StructList 多向量"三个词即可。

## 4. 核心能力三维度

**Milvus 的能力地图**（理解"为什么是数据库"）：

| 维度 | 能力 | 说明 |
|------|------|------|
| **数据管理** | Schema/主键/分区/分片 | 结构化数据管理（类比关系型） |
| | upsert 原子操作 | 幂等写入（2.4+） |
| | 一致性级别 | Strong/Bounded/Session/Eventually |
| | 数据生命周期 | 删除/分区清理/3.0 TTL/快照 |
| | 多租户 | 分区键物理隔离 |
| **检索能力** | ANN 索引家族 | FLAT/IVF/HNSW/DiskANN/稀疏倒排 |
| | 标量过滤 | expr 表达式 + 标量索引 |
| | 混合检索 | 稠密 + 稀疏 + RRF（2.5+） |
| | 全文检索 | TEXT_MATCH + 内置分词（2.5+） |
| | 3.0 扩展 | 服务端聚合/ORDER BY/StructList |
| **部署形态** | Lite/单机/集群/云 | 开发到生产全覆盖 |
| | 存算分离 | 计算与存储独立扩展 |
| | 可观测性 | Prometheus 指标/健康检查 |

> 💡 对照"索引库"（FAISS）：数据管理维度是 Milvus 的差异化——**"库"管理数据生命周期，"索引"只管理内存结构**。

## 5. 开源协议与 Zilliz 云生态

| 维度 | 说明 |
|------|------|
| 开源协议 | **Apache 2.0**（宽松商业友好） |
| 社区治理 | LF AI & Data 基金会毕业项目 |
| 托管云 | **Zilliz Cloud**（托管 Milvus / Vector Lakebase，与开源同代码） |
| 部署形态 | K8s（Operator）/ Docker / 单机 / 嵌入式（Milvus Lite） |
| SDK | Python（pymilvus）/ Java（milvus-sdk-java）/ Go / Node.js（3.0 起 Python/Go/Node 已发布，Java 紧随） |

**选型决策**（自建 vs 云）：

```text
自建 Milvus：数据合规要求高、团队有运维能力、成本敏感（开源免费）
Zilliz Cloud：快速上线、无运维、弹性伸缩、企业级 SLA
Milvus Lite：本地开发与测试（无 Docker、内存 ~500MB、单用户）
```

> ⚠️ 版本注意：Milvus Lite 需要 `pymilvus >= 2.4.11` 且 `milvus-lite == 2.4.10`（版本绑定严格）；BM25 全文检索需 pymilvus 2.5+。

## 6. 常用工具与命令速查

**客户端与工具**：

| 工具 | 用途 | 说明 |
|------|------|------|
| pymilvus | Python 客户端（标准） | 数据管道首选 |
| milvus-sdk-java | Java 客户端 | Spring AI/LangChain4j 底层 |
| Milvus CLI | 命令行工具（2.4+） | 快速交互/诊断 |
| Attu | 图形化管理界面 | Collection/数据/检索可视化 |
| Milvus Backup | 备份恢复工具 | 2.x 备份方案（3.0 快照替代） |

**Python 快速验证链路**（5 行验证部署）：

```python
from pymilvus import connections, Collection

connections.connect(host="localhost", port="19530")   # 连接（Lite 用 uri 文件）
collection = Collection("document_kb")                # 打开集合
collection.load()                                     # 加载
result = collection.search(
    data=[query_vec], anns_field="embedding",
    param={"metric_type": "COSINE"}, limit=5)         # 检索验证
print(result[0][0].id, result[0][0].score)            # 最近邻
```

**排障命令链**：

```bash
curl http://localhost:9091/healthz      # 组件健康
curl http://localhost:9091/metrics      # 指标（Prometheus）
# 客户端：milvus_cli > show collections   # 查看集合
```

> 💡 工具链记忆：**pymilvus 干活、Attu 看数、CLI 诊断、metrics 监控**——四件套覆盖开发到运维。
