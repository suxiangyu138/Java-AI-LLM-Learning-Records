## 1. 静态 vs 动态：数据在哪层

```text
静态页面：
  服务器 → HTML（数据直接写在 HTML 里）
  爬虫：requests 拿 HTML → 解析（阶段 2 全套）

动态页面：
  服务器 → 空壳 HTML + JS 脚本
  浏览器 → 执行 JS → JS 请求接口 → 渲染数据
  爬虫 requests 拿到的只是"空壳"（数据不在里面！）

判断标志（阶段 1 §3 已学，此处实战化）：
  Ctrl+U 看源码：数据在源码里 → 静态
  源码里没有但页面上有 → 动态（JS 加载）
```

> 🎯 认知核心：**"动态页 = HTML 是'房子'，数据是'搬进去的家具'（JS 搬的）"**——requests 只能看到空房子；要么找到"搬家具的接口"（02 章），要么"开着浏览器看它搬"（03-05 章）。

## 2. SSR vs CSR：两种渲染哲学

| 维度 | SSR（服务端渲染） | CSR（客户端渲染） |
|------|:---:|:---:|
| 数据在哪 | **HTML 里**（服务器拼好） | JS 接口（客户端拉） |
| 首屏速度 | 快（HTML 即内容） | 慢（先壳后数据） |
| SEO | 好（爬虫能读） | 差（需预渲染） |
| 爬虫难度 | 静态爬虫即可 | **需接口/渲染** |
| 代表 | 传统站点/JSP/部分新站 | SPA（Vue/React） |

```text
SPA（单页应用）= CSR 的典型：
  index.html 是空壳（<div id="app"></div>）
  JS 启动 → 请求 /api/data → 渲染进 #app
  前端路由切换 → 只换数据不刷新页面

现代站点常见组合：
  首屏 SSR（SEO/首屏）+ 后续 CSR（体验）——混合
```

> 🎯 判断价值：**"先判断 SSR 还是 CSR，再决定爬法"**——SSR 页面 requests 直接拿（阶段 2 技能）；CSR 页面才需要本阶段的接口/渲染方案。F12 看源码 30 秒出结论。

## 3. JS 渲染的完整链路

```text
浏览器加载动态页的完整过程：
  ① 请求 HTML（空壳）→ 解析
  ② 发现 <script src="app.js"> → 下载 JS
  ③ 执行 JS（Vue/React 框架启动）
  ④ JS 发起接口请求（fetch /api/data）
  ⑤ 接口返回 JSON → JS 渲染进 DOM
  ⑥ 用户看到数据（此时 DOM 才有内容）

对爬虫的三个启示：
  ① requests 只走到第①步（拿到空壳）
  ② 接口在第④步出现（F12 Network 可捕获）
  ③ DOM 在第⑤步才有数据（渲染后解析要等这一步）
```

> 🎯 启示总结：**"动态页的爬法取决于'在第几步介入'"**——第④步介入（接口直取，最快）、第⑤-⑥步介入（渲染后解析，兜底）。02 章讲第④步，03-05 章讲第⑤-⑥步。

## 4. 判断数据来源：四步定位法

```text
四步定位法（任何页面 2 分钟内定位数据源）：
  ① Ctrl+U 看源码：数据在 HTML 里？
     → 在 → 静态爬虫（阶段 2）✅ 结束
     → 不在 → 继续
  ② F12 Network → 刷新 → 筛 Fetch/XHR：
     有数据接口？→ 继续 ③
     没有接口但页面有数据 → 数据由 JS 生成（少见）→ 渲染方案
  ③ 逐个看接口 Response：
     有目标数据？→ 接口直取（02 章）✅ 最优
     数据加密/需要签名？→ 接口拿不到 → 渲染方案
  ④ 总结：
     接口直取 or 渲染兜底（策略树见 §5）
```

```python
# 定位辅助（requests 版源码检查）
import requests

def check_static_or_dynamic(url):
    resp = requests.get(url, timeout=10)
    html = resp.text
    # 检查数据关键词是否在 HTML 里（用目标数据特征词）
    keyword = "新闻标题"          # 替换为页面上的实际数据特征
    if keyword in html:
        print("✅ 静态：数据在 HTML 里，直接解析")
    else:
        print("❌ 动态：数据由 JS 加载，找接口或渲染")
        print("提示：F12 Network 筛 Fetch/XHR 找数据接口")
```

> 🎯 定位产出 = **"数据源结论"**（静态/接口/渲染）——四步定位是动态页爬虫的"分诊"，结论决定整条技术路线。**先定位，再写代码**（别拿 requests 硬刚动态页然后怀疑人生）。

## 5. 动态页爬虫的策略树

```text
动态页爬虫决策树：
  数据在 HTML？
  ├─ 是 → 静态爬虫（阶段 2）
  └─ 否（动态）
      ├─ 有数据接口（未加密）？→ 接口直取（02 章）⭐⭐ 最优
      ├─ 接口加密/签名？→ 评估（阶段 7 逆向 or 渲染兜底）
      └─ 无接口 → 渲染方案：
          ├─ 小规模/简单 → Playwright（05 章）推荐
          └─ 兼容老环境 → Selenium（03/04 章）
      渲染也拿不到 → 评估放弃/换源（阶段 4 §7）

优先级铁律：接口直取 > Playwright > Selenium
```

| 数据源 | 方案 | 效率 | 稳定性 |
|--------|------|:---:|:---:|
| HTML | 静态爬虫 | 高 | 高 |
| **接口** | **直取** | **最高** | **最高** |
| 渲染 | Playwright | 低（资源重） | 中 |
| 渲染（老） | Selenium | 低 | 中低 |

> 🎯 本阶段核心态度：**"接口直取是'正路'，渲染是'兜底'"**——渲染方案一页要几百 MB 内存 + 数秒加载，接口直取毫秒级——能用接口绝不上浏览器。下一章就把"正路"讲透。
