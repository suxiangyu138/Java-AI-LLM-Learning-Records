## 1. 三条路线的完整对比

| 路线 | 数据来源 | 速度 | 稳定性 | 适用 |
|------|---------|:---:|:---:|------|
| **接口直取**（02 章） | 直接请求接口 | 最快 | 高 | 接口未加密 |
| **响应捕获**（05 §5） | 浏览器代请求，监听响应 | 中 | 高 | 接口带签名（浏览器能拿） |
| **渲染后解析**（03-05） | 渲染 DOM → 解析 HTML | 慢 | 中 | 无接口/数据在 DOM |

```text
完整决策树（动态页）：
  ① 接口能直取？→ 直取（02 章）✅ 最优
  ② 接口要签名？→ Playwright 响应捕获（05 §5）✅ 次优
  ③ 无接口？→ 渲染后解析（07 §2）✅ 兜底
  ④ 全不行？→ 评估放弃/换源（阶段 4 §7）
```

> 🎯 本阶段能力全景：**"直取（快）+ 捕获（巧）+ 渲染（稳）三路并进"**——按页面情况选路，而非一条路走到黑。这就是"动态页爬虫"的完整答案。

## 2. 路线一：渲染后解析（HTML）

```python
"""渲染后解析：Playwright 渲染 → bs4 解析（阶段 2 技能复用）"""
from playwright.sync_api import sync_playwright
from bs4 import BeautifulSoup


def crawl_rendered(url, item_selector, fields):
    """渲染页面 → 等数据 → 解析提取"""
    with sync_playwright() as p:
        browser = p.chromium.launch(headless=True)
        page = browser.new_page()
        page.goto(url, timeout=30000)
        page.wait_for_selector(item_selector, timeout=15000)   # 等数据
        html = page.content()                                   # 渲染后 HTML
        browser.close()

    # 阶段 2 的解析技能直接复用（渲染后 = 静态 HTML）
    soup = BeautifulSoup(html, "lxml")
    results = []
    for item in soup.select(item_selector):
        row = {}
        for key, selector in fields.items():
            el = item.select_one(selector)
            row[key] = el.get_text(strip=True) if el else ""
        results.append(row)
    return results

# 使用
data = crawl_rendered(
    "https://example.com/list",
    item_selector="ul.news-list li",
    fields={"title": "a.title", "date": "span.date", "url": "a.title"},
)
print(f"提取 {len(data)} 条")
```

| 渲染后解析要点 | 说明 |
|---------------|------|
| 等待先行 | `wait_for_selector`（数据出现才算渲染完） |
| HTML 即静态 | 渲染后 HTML 用 bs4 解析（技能 100% 复用） |
| 字段模板 | fields dict（选择器映射，好维护） |
| 性能 | 比接口直取慢 10-50 倍（只用于兜底） |

> 🎯 架构之美：**"渲染只是'把动态变静态'的转换器"**——渲染后 HTML 交给阶段 2 的解析技能处理，两阶段知识无缝衔接，无需新学解析。

## 3. 路线二：响应捕获（接口 JSON）

```python
"""响应捕获：让浏览器请求接口，监听拿 JSON（绕开签名）"""
from playwright.sync_api import sync_playwright
import json


def crawl_with_api_capture(url, api_keyword, wait_selector=None):
    """渲染页面 + 捕获匹配接口的 JSON"""
    captured = []

    with sync_playwright() as p:
        browser = p.chromium.launch(headless=True)
        page = browser.new_page()

        def on_response(response):
            if api_keyword in response.url:
                try:
                    captured.append(response.json())
                    print(f"捕获接口: {response.url[:80]}...")
                except Exception:
                    pass

        page.on("response", on_response)
        page.goto(url, timeout=30000)
        if wait_selector:
            page.wait_for_selector(wait_selector, timeout=15000)
        page.wait_for_timeout(1000)          # 等尾部接口（可选）
        browser.close()

    return captured

# 使用：直接拿接口 JSON（结构化，比解析 HTML 好）
apis = crawl_with_api_capture(
    "https://example.com/list",
    api_keyword="/api/articles",
    wait_selector="ul.news-list li",
)
for api in apis:
    for item in api.get("data", {}).get("list", []):
        print(item["title"], item["url"])
```

| 响应捕获要点 | 说明 |
|-------------|------|
| 匹配 | URL 关键词（api/接口路径特征） |
| 结构化 | JSON 直接可用（免解析） |
| 绕签名 | 浏览器代请求（签名自动带） |
| 多接口 | 分页/详情接口可一并捕获 |
| 局限 | 依赖接口存在（无接口则走渲染解析） |

> 🎯 路线二的价值：**"签名接口的'文明解法'"**——不逆向签名（阶段 7 的苦活），让浏览器自己带签名请求，监听响应拿数据。本阶段最优兜底，比逆向安全合规（不突破技术措施，只是"观察"）。

## 5. 动态页爬虫的稳定性设计

```text
稳定性设计（动态页爬虫的"防翻车"）：
  ① 等待超时兜底：wait_for_selector 超时 → 检查 page.screenshot
     （被验证码拦截/结构变化 → 截图一眼看出）
  ② 页面结构校验：解析结果为空 → 告警（不是静默通过）
  ③ 数据量校验：条数异常（0/暴增）→ 告警
  ④ 失败降级：浏览器失败 → 记录 + 标记"需要人工"
  ⑤ 资源管理：每页关闭 context（防内存泄漏）
  ⑥ 定期验证：每周跑一个"样本页"确认仍可爬
```

```python
# ═══ 稳定性三件套（模板内置）═══
def fetch_with_guard(page, url, selector):
    """带兜底的渲染抓取"""
    try:
        page.goto(url, timeout=30000)
        page.wait_for_selector(selector, timeout=15000)
    except Exception as e:
        # ① 截图取证（被拦/结构变一眼看出）
        page.screenshot(path=f"debug_{url.split('/')[-1]}.png")
        print(f"抓取异常: {url} — {e}（已截图）")
        return None
    # ② 数据量校验
    html = page.content()
    count = html.count(selector.split(" ")[-1])
    if count == 0:
        print(f"⚠️ 数据为空: {url}（可能被拦截或结构变化）")
    return html
```

> 🎯 稳定性哲学：**"动态页爬虫的敌人不是'写不出来'，是'跑一段时间后悄悄坏掉'"**——等待超时 + 截图取证 + 数据量校验 + 定期验证，四件套让"悄悄坏"变成"立刻发现"。这是本阶段毕业级的工程素养（阶段 6 会把这些做成框架能力）。
