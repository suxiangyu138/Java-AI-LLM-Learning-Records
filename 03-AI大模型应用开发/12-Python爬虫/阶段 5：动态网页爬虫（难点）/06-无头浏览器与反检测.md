## 1. 无头浏览器的价值

```text
无头（headless）= 浏览器无界面运行：
  价值：
  · 服务器上可运行（无显示器环境）
  · 资源更省（无渲染开销）
  · CI/容器化部署（Docker 里跑爬虫）

有头 vs 无头：
  有头：调试方便（肉眼看页面）、反检测更"真"
  无头：生产运行、资源省、可部署

2026 现状：headless=new（新无头模式）比老 headless 更接近有头
  · Chrome 的无头模式已重构（Chrome 112+ 的 --headless=new）
  · 指纹差异大幅缩小（但仍可检测，见 §3）
```

> 🎯 使用建议：**"开发调试用有头（看得到），生产用无头（省资源）"**——模板里 `headless=True/False` 参数切换（05 §7 已内置）。

## 2. 自动化特征：被识别的信号

```text
浏览器自动化的可检测特征（服务器怎么认出你）：
  ① navigator.webdriver = true（最经典！）
     · 自动化浏览器此属性为 true，正常浏览器为 false/undefined
  ② Chrome DevTools 特征（window.chrome 差异）
  ③ 插件列表异常（自动化插件/空列表）
  ④ 行为特征：鼠标无移动轨迹/点击过快
  ⑤ 环境矛盾：UA 说 Windows 但字体是 Linux

Selenium 的经典标志：
  navigator.webdriver = true（Selenium 默认暴露）
  → undetected-chromedriver 打补丁去掉

Playwright 的现状：
  默认也会暴露部分自动化特征（需 stealth 插件）
```

```python
# 检测自己的暴露程度（页面里执行 JS 查看）
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch(headless=True)
    page = browser.new_page()
    page.goto("about:blank")
    result = page.evaluate("navigator.webdriver")
    print("webdriver 标志:", result)          # True = 会被检测
    browser.close()
```

> 🎯 认知：**"自动化特征 = 浏览器留给自动化工具的'指纹'"**——`navigator.webdriver` 是最主要的信号；配合阶段 4 §6 的设备指纹知识，服务器能识别"这不是普通用户"。

## 3. headless 的指纹差异

```text
无头 vs 有头的指纹差异（2026 现状）：
  老 headless（--headless=old）：
  · UA 带 "HeadlessChrome" 字样（一眼假）
  · 大量环境差异（GPU/字体/渲染）

新 headless（--headless=new，Chrome 112+）：
  · UA 与有头一致（去掉 HeadlessChrome）
  · 大部分环境差异消除
  · 但仍有细微差异（navigator.webdriver 等）

可检测的残留差异（新 headless）：
  navigator.webdriver = true
  部分 API 行为差异（window.chrome 等）
  渲染/GPU 相关差异（少见）
```

> 🎯 2026 结论：**"新 headless 已'足够像'有头，但 webdriver 标志仍需处理"**——组合拳：`headless=new` + 清除 webdriver 标志 + stealth 插件（§4），大部分站点能过。

## 4. stealth 方案

```python
# ═══ 方案一：Playwright + 手动清除标志（最轻量）═══
from playwright.sync_api import sync_playwright

STEALTH_JS = """
// 清除 navigator.webdriver 标志
Object.defineProperty(navigator, 'webdriver', {get: () => undefined});
// 补全 window.chrome（部分检测依赖）
window.chrome = window.chrome || {runtime: {}};
// 补全插件列表（真实浏览器有插件）
Object.defineProperty(navigator, 'plugins', {get: () => [1, 2, 3, 4, 5]});
"""

with sync_playwright() as p:
    browser = p.chromium.launch(headless=True, args=["--disable-blink-features=AutomationControlled"])
    context = browser.new_context()
    context.add_init_script(STEALTH_JS)      # 页面加载前注入（关键！）
    page = context.new_page()
    page.goto("https://example.com")
    print("webdriver:", page.evaluate("navigator.webdriver"))   # undefined ✅
    browser.close()

# ═══ 方案二：stealth 库（playwright-stealth，社区方案）═══
# pip install playwright-stealth
# from playwright_stealth import stealth_async / stealth_sync
```

| stealth 手段 | 说明 |
|-------------|------|
| `add_init_script` | 页面加载前注入补丁（Playwright 推荐姿势） |
| `--disable-blink-features=AutomationControlled` | 去自动化特性标志 |
| playwright-stealth | 社区整合方案（多补丁） |
| 自定义补丁 | 按目标站点检测点定制 |

> ⚠️ stealth 的边界认知：**"stealth 补的是'已知检测点'，不是'隐身术'"**——站点升级检测（新特征）→ 补丁失效；商业级风控（阶段 4 §6 的指纹组合）依然能识别。stealth 用于"正常采集不被误伤"，不是"对抗强风控"。

## 5. 反检测的正确态度

```text
反检测的分层判断（与阶段 4 §6/§7 衔接）：
  ① 站点只是"顺带检测"（大多数中小站）
     → headless=new + webdriver 清除 → 足够
  ② 站点有明确 JS 检测
     → 加 stealth 补丁 → 多数能过
  ③ 商业级风控（指纹组合/行为分析）
     → stealth 不够 → 评估"该不该继续"（阶段 4 §7）
  ④ 极强风控
     → 换数据源/放弃（合规优先）

使用纪律：
  · 反检测用于"正常采集不被误伤"（正当）
  · 不用于"绕过付费/隐私保护"（违规）
  · 与礼貌节奏/合规边界并行（阶段 4 全套）

工程建议：
  · 默认无头 + 基础 stealth（统一模板）
  · 遇到检测再升级（分级配置，06 章 06 节）
  · 检测成本 > 数据价值 → 停
```

> 🎯 本章小结：**"无头是生产形态，stealth 是补丁不是隐身术"**——`headless=new` + webdriver 清除是标准组合；遇到强风控先想"该不该"（阶段 4 §7），再想"能不能"。技术与边界，永远是两条线。
