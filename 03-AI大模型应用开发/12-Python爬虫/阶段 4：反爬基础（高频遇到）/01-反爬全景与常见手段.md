## 1. 反爬全景：五个层次

```text
站点反爬的五层防线（从简单到复杂）：
  ① 请求头校验    → UA/Referer/Cookie 是否像浏览器（最基础）
  ② 频率与 IP    → 请求太快/同 IP 太多 → 429/封 IP
  ③ 行为风控     → 访问模式/时间分布/点击轨迹是否像人
  ④ JS 检测      → 用 JS 探测"是不是真浏览器"（指纹）
  ⑤ 加密与验证码 → 数据加密/参数签名/人机验证

本阶段覆盖：①②③（高频遇到）
阶段 5 涉及：④（动态渲染相关）
阶段 7 涉及：⑤（进阶）
```

> 🎯 关键认知：**"90% 的反爬拦截发生在①②层"**——大多数站点只做 UA 校验和频率限制。学会诊断"被哪层拦了"，90% 的问题用本阶段三件套解决。

## 2. 第一层：请求头校验

```text
站点检查的请求头（从 UA 到全套）：
  基础：User-Agent（是浏览器还是库？）
  进阶：Accept/Accept-Language/Referer/Origin 是否成套
  高级：头顺序/Cookie 一致性（指纹的一部分，阶段 6）

被第一层拦的表现：
  403 Forbidden
  返回一个"跳转验证页"或空内容
  返回内容与浏览器看到的不同（降级内容）
```

| 校验点 | 爬虫常见破绽 |
|--------|-------------|
| UA | `python-requests/2.34.0`（一眼假） |
| Accept 系列 | 缺 Accept-Language/Referer |
| Cookie | 无 Cookie 或对不上 |
| 完整性 | 只有 UA 没有其他头（单头暴露） |

> 🎯 诊断方法：**"浏览器能看，爬虫 403" → 第一层嫌疑最大**——把 F12 里复制的完整请求头（Copy as cURL）套到爬虫上测试（[02-UA 与 Headers 伪装](02-UA与Headers伪装.md)）。

## 3. 第二层：频率与 IP

```text
站点检查的频率/IP 信号：
  同一 IP 请求速率（次/秒）
  同一 IP 单位时间总量（次/小时/天）
  同一 UA/会话的访问模式（翻页速度是否像人）

被第二层拦的表现：
  429 Too Many Requests（明确限流）
  403 伴随"访问过于频繁"提示
  突然全部 403（IP 被临时/永久封禁）
  CAPTCHA 验证码突然出现
```

| 限流信号 | 含义 | 应对（03/04 章） |
|---------|------|------------------|
| 429 + Retry-After | 明确限流 | 等待 + 降频 |
| 403 频繁 | 可能封 IP | 代理换 IP |
| 验证码突现 | 风控升级 | 降频 + 检查行为 |

> 🎯 诊断要点：**"429 是温柔的提示，403 是粗暴的拒绝，验证码是最后的警告"**——看到这些先降频，别硬冲（硬冲 = 从临时封升级到永久封）。

## 4. 第三层：行为与风控

```text
行为风控的观察维度：
  请求节奏：固定间隔（机器特征）vs 随机间隔（人）
  时间分布：24 小时不间断（机器）vs 有昼夜规律（人）
  访问路径：顺序翻页（机器）vs 跳转浏览（人）
  会话行为：单会话海量请求（机器）

被第三层拦的表现：
  频率不高也 403（行为分低）
  需要过验证码（行为验证码：滑块/点选）
  数据被"污染"（返回假数据/延迟返回）
```

| 行为信号 | 机器特征 | 人特征 |
|---------|---------|--------|
| 间隔 | 固定 1s | 0.5-3s 随机 |
| 时间 | 24h 不停 | 白天为主 |
| 路径 | 顺序 page1→2→3 | 随机跳转 |
| 翻页速度 | 匀速 | 有快有慢 |

> 🎯 认知：**"行为风控是'概率判定'不是'规则拦截'"**——把请求做得"像人"（随机间隔/随机顺序）能显著降低风控分。这是 [03-频率控制](03-频率控制与限流应对.md) 的核心动机。

## 5. 第四层：JS 与加密（概念）

```text
JS 检测与加密（本阶段只认知，阶段 5/7 处理）：
  ① JS 渲染：数据在 JS 执行后才出现（动态页）→ 阶段 5
  ② JS 环境检测：window/navigator 属性探测（指纹）→ 阶段 6 概念
  ③ 参数加密：请求参数带签名（sign/token 由 JS 计算）→ 阶段 7
  ④ 数据加密：响应内容是密文，JS 解密 → 阶段 7

被第四层拦的表现：
  请求正常但拿不到数据（数据在 JS 里）
  参数里有无法伪造的签名
  Headless 检测（页面能识别自动化浏览器）
```

> 🎯 应对原则（本阶段）：**"遇到第四层，先问'有没有接口可直取'（阶段 5 第一课）"**——很多"加密页面"其实是"接口 + 渲染"，直取接口绕开渲染；真正强加密留到阶段 7，本阶段不硬碰。

## 6. 被拦了怎么诊断

```text
诊断五步（被拦时的标准流程）：
  ① 浏览器打开：能正常看吗？
     → 不能：站点本身问题（不是反爬）
  ② curl 带完整头：能拿到吗？
     → 能：请求头问题 → 套完整 Headers（02）
     → 不能：继续
  ③ 看状态码：403/429/200？
     → 429：限流 → 降频等待（03）
     → 403：身份/风控 → 检查 UA/Cookie/代理（02/04）
     → 200 但内容不对：可能降级内容/JS 渲染
  ④ 看响应内容：是验证码页？跳转页？空？
     → 验证码：行为风控 → 降频/换 IP
  ⑤ 看频率：是不是自己爬太快？
     → 是：先降频再谈其他（80% 的 403 是频率问题）
```

```python
# 诊断工具函数（被拦时先跑这个）
def diagnose(url: str):
    import requests
    # ① 裸请求（看基础 UA 是否被拦）
    r1 = requests.get(url, timeout=10)
    print(f"裸请求: {r1.status_code}, 长度 {len(r1.text)}")
    # ② 带浏览器头（看是否头的问题）
    headers = {"User-Agent": "Mozilla/5.0 ...Chrome/126.0.0.0",
               "Accept-Language": "zh-CN,zh;q=0.9"}
    r2 = requests.get(url, headers=headers, timeout=10)
    print(f"带浏览器头: {r2.status_code}, 长度 {len(r2.text)}")
    # 对比两次结果 → 判断是哪层拦的
```

> 🎯 诊断心法：**"一次只换一个变量"**——裸请求 → 带头 → 带 Cookie → 换 IP，每步对比状态码和内容长度，锁定被拦层。诊断清楚再开药，别乱试。

## 7. 反爬强度分级与应对

| 强度 | 表现 | 应对 | 本阶段 |
|:---:|------|------|:---:|
| 弱 | 无校验或仅 UA | 正常爬 | ✅ |
| 中 | UA/频率校验 | UA 池 + 随机延迟 | ✅ 02/03 |
| 中强 | IP 限流 | 代理池 | ✅ 04 |
| 强 | 登录 + 验证码 | 登录态 + 验证码处理 | ✅ 05（基础） |
| 很强 | 指纹/加密 | 动态渲染/逆向 | 阶段 5/7 |
| 极强 | 商业级风控 | **换数据源/放弃** | ⚠️ 07 |

> 🎯 本阶段毕业线：**"中强及以下反爬的站点，你能稳定采集"**——遇到"很强/极强"知道"这是阶段 5/7 的事"或"该停了"。对抗能力与合规边界同步成长，才是合格的爬虫工程师。
