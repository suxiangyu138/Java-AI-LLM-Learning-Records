## 1. 两大定位体系总览

| 体系 | 语法风格 | 优点 | 缺点 | 解析库支持 |
|------|---------|------|------|-----------|
| **CSS 选择器** | 简洁（`.title a`） | 好读、Chrome 一键生成 | 不能按文本匹配、不能向上找 | bs4 `select()` / lxml cssselect |
| **XPath** | 路径式（`//div[@class="title"]`） | **最强**：文本匹配/轴/条件 | 语法复杂、易写错 | lxml（原生最强） |

> 🎯 学习策略：**CSS 选择器做 80% 的常规定位（简单直白），XPath 攻坚 20% 的复杂场景（文本匹配/动态 class）**——两条腿走路，别只学一个。

## 2. CSS 选择器全解

### 2.1 基础选择器

| 选择器 | 语法 | 匹配 | 示例 |
|--------|------|------|------|
| 标签 | `div` | 所有 div | `p` 所有段落 |
| 类 | `.title` | class 含 title | `.news-title` |
| ID | `#header` | id="header" | `#main` |
| 通配 | `*` | 一切 | 几乎不用 |

### 2.2 组合与关系

| 选择器 | 语法 | 匹配 |
|--------|------|------|
| 后代 | `div a` | div 内部所有 a（任意层级） |
| 子代 | `div > a` | div 的直接子 a |
| 相邻 | `h2 + p` | h2 后面的第一个 p |
| 兄弟 | `h2 ~ p` | h2 之后的所有 p |
| 多选 | `h2, h3` | h2 或 h3 |

### 2.3 属性选择器（爬虫高频）

| 语法 | 匹配 |
|------|------|
| `a[href]` | 有 href 属性的 a |
| `a[href="x"]` | href 精确等于 x |
| `a[href*="news"]` | href **包含** news |
| `a[href^="https"]` | href **以** https 开头 |
| `a[href$=".pdf"]` | href **以** .pdf 结尾 |

### 2.4 伪类（结构化定位）

| 伪类 | 匹配 |
|------|------|
| `li:first-child` | 第一个 li |
| `li:last-child` | 最后一个 li |
| `li:nth-child(2)` | 第 2 个 li |
| `li:nth-child(odd)` | 奇数位 li |
| `a:hover` | 悬停（爬虫用不到） |

```python
# bs4 调用（阶段 2 详讲，先看语法怎么用）
from bs4 import BeautifulSoup
soup = BeautifulSoup(html, "lxml")

soup.select(".news-list li a.news-title")          # 后代+类组合
soup.select("a[href*='/news/']")                   # 属性包含
soup.select("ul > li:first-child")                 # 子代+伪类
```

> 💡 实战组合拳：**`容器选择器 + 子元素选择器`**——先选中整个列表容器，再逐项提取，比一条长选择器更稳（容器 class 不变、内部微调不影响）。

## 3. XPath 语法全解

### 3.1 路径表达式

```text
// 开头含义：从任意位置找（绝对路径从 / 开头：/html/body/div）

//div                     所有 div（任意层级）
/div                     根下 div（少用）
//div/div                 div 下的直接子 div
//div//span              div 下任意层级 span
./a                      当前节点的子 a（相对路径）
..                       父节点
```

### 3.2 谓词（条件过滤）——XPath 的灵魂

```text
//div[@class="title"]             class 精确等于 title
//div[contains(@class,"title")]   class 包含 title（动态 class 必备！）
//a[@href]                        有 href 的 a
//a[starts-with(@href,"https")]   href 以 https 开头
//li[1] / li[last()] / li[position()>2]   按位置
//p[text()="标题一"]               按文本精确匹配（CSS 做不到！）
//p[contains(text(),"关键词")]     按文本包含匹配（CSS 做不到！）
```

### 3.3 轴（Axis）：上下左右都能走

```text
//h2/following-sibling::p[1]     h2 之后第一个兄弟 p
//h2/preceding-sibling::span     h2 之前的所有兄弟 span
//div/parent::*                   div 的父节点
//div/ancestor::section           div 的所有祖先 section
//a/..                           a 的父节点（简写）
```

```python
# lxml 调用
from lxml import etree
tree = etree.HTML(html)

tree.xpath('//div[contains(@class,"item")]//a/@href')          # 提取所有链接
tree.xpath('//*[contains(text(),"价格")]/following-sibling::span/text()')  # 文本定位
```

> 🎯 XPath 三大独门绝技（CSS 做不了）：**① 按文本匹配**（`text()`）；**② 往上/旁走**（轴）；**③ 动态 class 模糊匹配**（`contains(@class,...)`）——遇到"class 是随机哈希"的页面，XPath 是唯一解。

## 4. CSS 选择器 vs XPath 对比

| 场景 | CSS 选择器 | XPath | 推荐 |
|------|-----------|-------|:---:|
| 常规 class/ID 定位 | `.title` / `#x` | `//*[@class="title"]` | **CSS** |
| 属性包含匹配 | `a[href*="x"]` | `//a[contains(@href,"x")]` | 平手 |
| **按文本匹配** | ❌ 做不到 | `//p[text()="x"]` | **XPath** |
| **父/兄弟节点** | ❌ 做不到（CSS 只能向下） | `..` / `following-sibling` | **XPath** |
| 动态 class（哈希类名） | 难 | `contains(@class,"x")` | **XPath** |
| 可读性 | ✅ 简洁 | 较长 | CSS |
| 性能（lxml） | 快 | 快 | 平手 |

> 🎯 决策规则：**CSS 够用就用 CSS，CSS 做不到（文本/父级/动态 class）就上 XPath**——两者在 lxml 里性能差距可忽略，选择标准是"能否表达需求"。

## 5. Chrome 帮你生成选择器

```text
F12 → Elements 面板 → 右键元素 → 三个实用功能：
  ① Copy selector    → 复制 CSS 选择器（直接给 bs4.select 用）
  ② Copy XPath       → 复制 XPath（直接给 lxml 用）
  ③ Copy full XPath  → 复制绝对路径（脆弱，慎用）

⚠️ 生成的 selectors 常见问题：
  · 可能依赖 :nth-child（位置）→ 改版易崩，检查后手动优化
  · 可能含哈希 class → 换成稳定锚点
  · 生成的是"这条元素"的路径，批量抓取要泛化
```

```text
生成 → 泛化的步骤：
  ① Copy selector 得到：div#app > div:nth-child(2) > a.title
  ② 泛化（去掉位置依赖）：div#app a.title
  ③ 验证：console 里 $$('div#app a.title') 看返回数量
```

> ⚠️ **生成选择器的"泛化"是必须步骤**：Chrome 复制的是"选中这一个元素"的选择器（常带 `:nth-child`），而爬虫要的是"匹配这一类元素"——拿到后手动去掉位置伪类，用 Console 验证命中数量（[07](07-浏览器开发者工具实战.md) 会完整演示）。

## 6. 定位实战：从页面到代码

```text
实战流程（拿到任意页面的标准动作）：
  ① F12 Elements 找到目标数据节点
  ② 观察结构：容器 class？数据在文本还是属性？
  ③ 用 Copy selector 拿到初稿
  ④ 泛化 + 验证（Console 里 $$('...') 数个数）
  ⑤ 转成 Python（bs4.select 或 lxml.xpath）
```

```python
# 完整示例：提取新闻列表（标题+链接+日期）
import requests
from bs4 import BeautifulSoup

resp = requests.get("https://example.com/news", headers={"User-Agent": "Mozilla/5.0"}, timeout=10)
soup = BeautifulSoup(resp.text, "lxml")

# 容器选择器（稳定锚点）
items = soup.select("ul.news-list li")          # 每个 li 一个条目
for item in items:
    title = item.select_one("a.news-title").text.strip()
    url = item.select_one("a.news-title")["href"]
    date = item.select_one("span.date").text
    print(title, url, date)

# XPath 等价写法（lxml）
tree = etree.HTML(resp.text)
rows = tree.xpath('//ul[contains(@class,"news-list")]/li')
for row in rows:
    title = row.xpath('.//a[contains(@class,"news-title")]/text()')[0]
    url = row.xpath('.//a[contains(@class,"news-title")]/@href')[0]
```

> 🎯 本阶段的定位能力在阶段 2 会变成正式解析流程（BeautifulSoup 全套 API）；现在先掌握"选择器怎么写、怎么验证"——这是所有解析的地基。
