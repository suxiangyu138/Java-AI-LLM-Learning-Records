## 1. 为什么要先谈法律

```text
爬虫的技术难度：低（几行代码）
爬虫的法律风险：高（2020s 起判例密集）

近年的典型判例方向（中国）：
  · 爬取并商业化他人数据 → 不正当竞争（大数据杀熟/搬运判例）
  · 突破反爬措施（绕过登录/验证码/加密）→ 可能构成"破坏计算机信息系统"
  · 爬取个人信息 → 个人信息保护法（PIPL）合规义务
  · 平台服务条款禁止爬取 → 民事违约/不正当竞争风险
```

> 🎯 第一课结论：**"技术能做" ≠ "法律允许"**。学爬虫正当用途：学习/研究/个人使用/公开数据聚合/训练语料（注意合规）；红线：绕过防护抓非公开数据、商业化搬运、个人隐私。本阶段的定位是"明边界"，具体判例与深度合规在阶段 4 反爬篇展开。

## 2. robots.txt：网站的自律声明

```text
robots.txt 是网站放在根目录的声明文件（协议，非强制法律）：
  https://example.com/robots.txt

示例（标准 robots.txt）：
  User-agent: *                 # 对所有爬虫
  Disallow: /admin/             # 禁止抓 /admin/ 目录
  Disallow: /api/               # 禁止抓接口
  Allow: /public/               # 允许 /public/
  Crawl-delay: 10               # 建议两次抓取间隔 10 秒
```

| 字段 | 含义 |
|------|------|
| `User-agent` | 规则适用的爬虫（`*` = 全部） |
| `Disallow` | 禁止的路径（空 = 全允许） |
| `Allow` | 允许的路径（在 Disallow 内开洞） |
| `Crawl-delay` | 建议的抓取间隔（秒） |
| `Sitemap` | 站点地图地址（合法数据的金矿！） |

```python
# 爬虫第一动作：读 robots.txt（阶段 2 会写成函数）
import requests

robots = requests.get("https://example.com/robots.txt", timeout=10).text
print(robots)      # 看允许什么、禁止什么、有没有 Sitemap
```

> 🎯 实践态度：**公开站点先看 robots.txt 与 Sitemap**——Sitemap 往往提供结构化 URL 清单（合法且高效）；Disallow 的区域尊重声明。注意 robots.txt 是"君子协定"，但违反它会在纠纷中成为不利证据。

## 3. 法律红线全景（中国）

| 法律/法规 | 管什么 | 爬虫相关红线 |
|----------|--------|-------------|
| **《数据安全法》**（2021） | 数据分级分类/国家安全 | 重要数据（政务/地理/人口等）出境与获取红线 |
| **《个人信息保护法》**（2021） | 个人信息处理 | 爬取个人信息须合法正当、最小必要；批量个人信息 = 高风险 |
| **《反不正当竞争法》** | 市场竞争秩序 | 爬取后搬运/竞价排名/商业利用 → 不正当竞争 |
| **《刑法》285/286 条** | 计算机系统安全 | 突破技术措施（绕过验证码/加密/登录）可能构成犯罪 |
| **《著作权法》** | 内容版权 | 抓取并转发的文字/图片/视频的版权责任 |
| 平台服务条款（合同） | 民事约定 | 明确禁止爬取的条款 → 违约/不正当竞争风险 |

```text
实操分级（爬虫合规难度阶梯）：
  ① 公开页面 + 低频率 + 个人学习          → 风险最低（仍看条款）
  ② 公开接口 + 尊重 robots + 合规使用     → 一般风险
  ③ 需登录/绕过防护才能获取               → 高风险（突破技术措施）
  ④ 个人信息批量采集                      → 高危（PIPL）
  ⑤ 抓取后商业变现/搬运                   → 高危（不正当竞争+版权）
```

> ⚠️ 特别提示：**"登录后才能看"的数据 ≠ 可以爬**——绕过登录态获取数据在多个判例中被认定突破技术措施。个人学习用公开数据练手；涉及商用/规模采集前必须做合规评估。

## 4. 技术合规的四个原则

```text
① 公开获取：只爬无需绕过技术措施的公开数据
② 尊重声明：遵守 robots.txt 与站点条款
③ 最小影响：低频率、低并发、控制负载（见 §5）
④ 正当使用：学习/研究/个人用途，不商业化搬运、不侵犯隐私
```

| 原则 | 落地动作 |
|------|---------|
| 公开获取 | 不绕过登录/验证码/加密（练技术可，生产别碰） |
| 尊重声明 | 代码里读 robots.txt + 检查服务条款 |
| 最小影响 | 频率 ≤ 站内正常用户行为（见 §5） |
| 正当使用 | 使用前问一句："数据给我用，权利方会同意吗？" |

## 5. 礼貌爬虫：频率与负载

```text
礼貌爬虫的"三不"：
  · 不把站点抓崩（并发与频率控制）
  · 不抢用户带宽（避开高峰期）
  · 不制造垃圾流量（UA 明确标识自己）

频率参考：
  小站：1 请求/秒 以内（甚至 10 秒 1 次）
  中型站：5-10 请求/秒（看站点体量）
  大平台 API：按官方限速（通常 100+ 请求/分）
  铁律：别超过"人工浏览"的速度太多
```

```python
# 礼貌爬虫最小实现（阶段 2 正式展开）
import time
import requests

UA = "MyStudyCrawler/1.0 (学习用途; contact: me@example.com)"

for url in urls:
    resp = requests.get(url, headers={"User-Agent": UA}, timeout=10)
    process(resp)
    time.sleep(2)          # 每请求间隔 2 秒（礼貌下限）
```

| 礼貌行为 | 做法 |
|---------|------|
| UA 标识 | 写明身份与用途（比伪装更受站点欢迎） |
| 限速 | time.sleep + 并发上限 |
| 重试礼貌 | 429/503 后指数退避等待 |
| 时间窗口 | 避开高峰（19-23 点） |
| 减少重复 | 去重/增量抓取（别反复抓同一页） |

> 🎯 反直觉事实：**老实标识 UA 的礼貌爬虫往往比伪装的活得久**——站点反爬主要打"恶意行为"（高频/无标识/异常模式），礼貌爬虫常常不被针对。伪装的目的是"不被误伤"，不是"对抗"。

## 6. 数据使用的边界

| 数据类别 | 使用边界 |
|---------|---------|
| 公开资讯（新闻/文档） | 引用/学习可；全文搬运商业用 → 版权风险 |
| 用户生成内容（UGC） | 版权归属用户/平台，商业化需授权 |
| 个人信息（手机号/邮箱等） | **PIPL 约束**：最小必要 + 告知同意（学习用脱敏数据） |
| 价格/行情类 | 不构成版权但可能构成不正当竞争（镜像搬运） |
| AI 训练语料 | 版权与合规是 2024+ 热点（合理使用争议中） |

> 💡 与本仓库定位的关系：本仓库的 AI 学习路径大量涉及"采集语料做 RAG/微调"——**训练数据合规**是 AI 应用的必修课；阶段 1 先立意识：采集合法来源（公开 API、官方数据集、自有数据、授权数据）。RAG 语料工程的合规做法见 [RAG 检索增强生成体系](../../../04-RAG检索增强生成/00-RAG知识体系总览.md) 相关章节。

## 7. 合规自检清单

```text
动手前 10 问（全部 ✅ 才算合规起步）：
  □ 数据是公开可访问的吗（无需绕过任何措施）？
  □ robots.txt 允许吗？
  □ 站点服务条款禁止爬取吗？
  □ 用途是学习/研究/个人吗（非商业搬运）？
  □ 涉及个人信息吗？（涉及则脱敏+最小化）
  □ 频率会打扰站点正常运行吗？
  □ UA 标识清楚吗？
  □ 有联系方式可被找到吗？
  □ 抓取范围最小化了吗（只要需要的字段/页面）？
  □ 数据使用符合权利方预期吗？
```

> 🎯 收尾结论：**合规不是束缚，是爬虫的"长久之计"**——尊重边界 + 礼貌抓取 = 可持续的数据管道；无视边界 = 封 IP、律师函、甚至刑事责任。本阶段的红线意识将贯穿所有后续阶段（尤其阶段 4 反爬对抗，对抗之前先问"该不该对抗"）。
