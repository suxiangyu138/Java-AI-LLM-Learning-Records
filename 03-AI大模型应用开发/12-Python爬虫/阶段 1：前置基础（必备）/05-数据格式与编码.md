## 1. 三种数据格式定位

| 格式 | 是什么 | 爬虫场景 |
|------|--------|---------|
| **JSON** | 键值对/数组（Python 字典亲戚） | **接口返回的主力**（F12 里 90% 的 XHR） |
| **XML** | 标签树（HTML 的表亲） | 遗留站点/RSS/部分 SOAP 接口 |
| HTML | 标签树（带样式语义） | 网页本身 |

> 🎯 现状结论：**2026 年新接口几乎全是 JSON**；XML 出现在 RSS 订阅、老系统、部分政务/企业接口——认识即可，解析方式与 HTML 同源（都是树）。

## 2. JSON：接口数据的主角

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "total": 2,
    "list": [
      {"id": 1001, "title": "标题一", "tags": ["AI", "爬虫"]},
      {"id": 1002, "title": "标题二", "tags": ["Python"]}
    ]
  }
}
```

```python
import json

# 字符串 → Python 对象
data = json.loads(resp.text)          # dict/list 嵌套
# requests 的快捷方式：
data = resp.json()                    # 等价 json.loads(resp.text)

# 取数据（dict 用 [] 或 .get，list 用索引）
code = data["code"]
items = data["data"]["list"]
for item in items:
    print(item["id"], item["title"], item.get("tags", []))

# Python 对象 → 字符串（构造请求体）
body = json.dumps({"page": 1, "size": 20}, ensure_ascii=False)
# ensure_ascii=False：中文不转义（默认会变成 \uXXXX，接口可能不接受）
```

| JSON 类型 | Python 对应 | 注意 |
|----------|------------|------|
| `{}` 对象 | dict | 键用引号 |
| `[]` 数组 | list | 索引从 0 开始 |
| `"str"` | str | 双引号（Python 单引号也能写，JSON 必须双引号） |
| `true/false` | True/False | **大小写不同** |
| `null` | None | **拼写不同** |
| `123/1.5` | int/float | - |

> ⚠️ JSON 四坑：① **`true/false/null` 小写 vs Python 大写/None**；② 取嵌套键用 `data["a"]["b"]` 前先确认存在（用 `.get()` 防 KeyError）；③ **`json.dumps` 默认 `ensure_ascii=True`**（中文变 `\uXXXX`，部分接口签名校验会失败）；④ 大 JSON 用 `json.loads` 即可，别手动正则（除非是超大文件流式解析）。

## 3. XML：遗留站点的数据

```xml
<?xml version="1.0" encoding="UTF-8"?>
<rss version="2.0">
  <channel>
    <title>新闻频道</title>
    <item>
      <title>第一条新闻</title>
      <link>https://example.com/news/1001.html</link>
      <pubDate>2026-08-08</pubDate>
    </item>
  </channel>
</rss>
```

```python
# lxml 解析 XML（与 HTML 同库）
from lxml import etree
tree = etree.fromstring(resp.content)          # XML 用 fromstring
items = tree.xpath('//item')
for item in items:
    title = item.xpath('title/text()')[0]
    link = item.xpath('link/text()')[0]
```

> 💡 实战提示：**RSS 是爬虫的"合法金矿"**——大量站点提供 RSS 订阅（XML 格式），结构规整、更新及时、通常无反爬。想练手先找 RSS（如新闻站、博客站）。

## 4. 字符编码：乱码的根源

```text
编码的本质：字节 ↔ 字符的翻译规则
  UTF-8：现代标准（中文 3 字节），网页主流（charset="utf-8"）
  GBK/GB2312：老中文站（中文 2 字节）
  ISO-8859-1：西欧（中文不可表示）

乱码 = 编码方式不匹配：
  网页按 GBK 编码 → 爬虫按 UTF-8 解码 → 乱码
```

| 编码 | 中文支持 | 场景 | 2026 现状 |
|------|:---:|------|----------|
| **UTF-8** | ✅ | 现代网页/接口标准 | **绝对主流**（Python 3.15 起默认！） |
| GBK/GB2312 | ✅ | 老中文站 | 存量站仍会遇到 |
| UTF-16 | 少见 | 特殊文件 | 很少 |
| ISO-8859-1 | ❌ | 欧洲遗留 | 遇到即乱码（需转换） |

```python
# 编码处理三板斧
# ① 优先看响应头/HTML 声明的编码
resp.encoding          # requests 推断的编码（可能错）
resp.encoding = resp.apparent_encoding   # 用内容探测（chardet）

# ② 显式解码（终极手段：拿字节自己解）
resp.content.decode("utf-8")             # 字节 → 字符串
resp.content.decode("gbk")               # 老站用 GBK 解
resp.content.decode("gbk", errors="ignore")  # 容错解码

# ③ 乱码后的抢救：转码
text.encode("latin1").decode("utf-8")    # 双重编码还原（少见但存在）
```

> 🎯 2026 好消息：**Python 3.15（2026-10 发布，PEP 686）默认编码改 UTF-8**——大量"默认编码不一致"的乱码会从源头消失；但老站 GBK 问题依旧，`apparent_encoding` + 显式 `decode("gbk")` 是爬虫必备急救。

## 5. 乱码排查四步法

| 步骤 | 动作 | 说明 |
|:---:|------|------|
| ① | 看 `resp.encoding` | requests 推断的编码是否合理 |
| ② | 看响应头/HTML 声明 | `Content-Type: charset=...` / `<meta charset>` |
| ③ | `resp.apparent_encoding` 探测 | 让 chardet 猜（成功率 90%+） |
| ④ | 人工指定 + 换编码重试 | `decode("gbk")` / `decode("utf-8")` 逐个试 |

```python
# 万能急救模板（乱码出现时的标准动作）
def fix_encoding(resp):
    if resp.encoding and resp.encoding.lower() in ("utf-8", "gbk", "gb2312"):
        return resp.text
    resp.encoding = resp.apparent_encoding      # 先让库猜
    for enc in ("utf-8", "gbk", "gb18030"):     # 再逐个试
        try:
            return resp.content.decode(enc)
        except UnicodeDecodeError:
            continue
    return resp.text
```

> ⚠️ **`resp.text` 是"推断解码"**：requests 按 `resp.encoding` 解，推断错就乱码——所以"网页没问题、requests 乱码"的根因几乎都是编码推断失败。**优先 `resp.content.decode(明确编码)`**，把控制权拿在自己手里。

## 6. HTML 实体与特殊字符

```html
<!-- 网页里看到的特殊字符可能是实体（HTML entity） -->
&amp;    = &
&lt;    = <
&gt;    = >
&quot;  = "
&#39;   = '
&nbsp;  = 空格（不换行空格）

<!-- 中文网页常见："&amp;nbsp;" 造成 strip() 无效 -->
```

```python
# bs4 自动解码实体（解析出的 text 已是正常字符）
from bs4 import BeautifulSoup
soup = BeautifulSoup("&lt;p&gt;内容&lt;/p&gt;", "lxml")
print(soup.text)          # <p>内容</p>（实体已还原）

# 纯文本场景手动还原（html 模块）
import html
print(html.unescape("&amp;quot;"))    # &quot;
```

> 💡 实战提示：**`&nbsp;`（不换行空格 \xa0）是爬虫经典坑**——提取的文本 `strip()` 不掉它（它不是普通空格）。处理：`text.replace("\xa0", " ").strip()`。bs4 解析场景实体已自动解码，主要提防 `\xa0`。
