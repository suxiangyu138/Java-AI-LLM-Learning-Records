## 1. F12 四板斧总览

| 面板 | 看什么 | 爬虫用途 |
|------|--------|---------|
| **Elements** | HTML 结构/样式 | 找数据节点、复制选择器 |
| **Network** | 所有网络请求 | **找数据接口（核心）** |
| **Console** | JS 运行/调试 | 验证选择器、试表达式 |
| **Application** | Cookie/存储/缓存 | 看登录态、手动复制 Cookie |

> 🎯 爬虫观察流程：**Elements 看结构 → Network 看请求 → Console 验证 → Application 取凭证**——四板斧打通，任何页面的数据链路都能看穿。

## 2. Elements：看结构

```text
Elements 面板使用要点：
  ① 选中元素：点击左上角箭头图标（或 Ctrl+Shift+C）→ 点页面元素
  ② 层级折叠：点三角展开/收起，快速看整体结构
  ③ 右键元素 → Copy → Copy selector / Copy XPath（见 04 §5）
  ④ 右键 → Copy → Copy outerHTML（复制该元素完整 HTML 做测试）

爬虫信息获取：
  · 数据在哪个标签/class 里
  · 数据在文本、属性（href/src/data-*）还是 JS 里
  · 复制选择器 → 去 Console 验证
```

> 💡 技巧：**搜索元素**——Ctrl+F 在 Elements 里直接搜文本/属性（如搜"标题一"找到数据所在节点），比肉眼翻快得多。

## 3. Network：看请求（爬虫主战场）

```text
Network 面板使用要点：
  ① 打开面板 → 刷新页面（F5）→ 观察全部请求
  ② 筛选类型：Fetch/XHR（接口）/ Doc（文档）/ Img / JS / CSS
  ③ 点开请求 → 三个 Tab 最关键：
       Headers    → 请求头/响应头（UA/Cookie/Content-Type）
       Payload    → 请求参数（query/form/JSON body）
       Response   → 返回内容（接口数据！）
  ④ 保留日志：勾选 Preserve log（跳转后请求不丢）
```

| 筛选 | 用途 |
|------|------|
| **Fetch/XHR** | 只看接口（找数据第一筛选） |
| Doc | 页面文档本身（html） |
| JS/CSS | 资源文件（一般不看） |
| 大小排序 | 找最大的响应（数据往往最大） |

> 🎯 **Fetch/XHR 筛选是找接口的第一动作**：页面刷新后，数据接口通常混在几十个请求里——只筛 XHR，剩下 3-5 个候选，逐个看 Response 就能锁定数据源。

## 4. Console：验证选择器与试代码

```javascript
// Console 里直接验证选择器（回车即执行）
$$('ul.news-list li a.news-title')        // 返回匹配的元素数组
$$('a[href*="/news/"]').length           // 数个数（验证是否批量命中）
document.querySelectorAll('#app a').length

// 快速看元素的文本
$$('.news-title')[0].textContent

// 模拟 fetch（验证接口可用性）
fetch('/api/news?page=1').then(r => r.json()).then(console.log)
```

| 场景 | Console 动作 |
|------|-------------|
| 验证选择器命中数量 | `$$('选择器').length` |
| 试 XPath | `$x('//div[@class="item"]')` |
| 看元素内容 | `$$('.title')[0].textContent` |
| 直接调接口 | `fetch(url)` |
| 看全局数据 | `window.__DATA__` / `Object.keys(window)` |

> 🎯 Console 是**爬虫的"实验室"**：选择器先在这里验证通过，再写进 Python——避免"代码写完才发现选择器写错"的返工。

## 5. Application：看存储

```text
Application 面板（按域查看）：
  Cookies → 各域的 Cookie（值/过期/HttpOnly）
  Local Storage / Session Storage → 站点本地存储（token 常在这）
  IndexedDB → 复杂客户端存储

爬虫用途：
  · 登录后看 Cookie（找 session/token 字段名）
  · 复制完整 Cookie 串 → 塞进代码（阶段 2 手动带 Cookie 方案）
  · 看 token 存在哪（localStorage 的 token 通常要 JS 拿）
```

```python
# 从 F12 复制的 Cookie 串直接可用（阶段 2 写法预览）
cookies = "session_id=abc123; csrf_token=xyz; _ga=GA1.2.xxx"
resp = requests.get(url, headers={"Cookie": cookies}, timeout=10)
```

> ⚠️ 手动复制 Cookie 的局限：**会过期**（会话型 Cookie 关闭浏览器/过期即失效）——适合快速验证，正式爬虫要模拟登录（阶段 2 Session 方案）。

## 6. 定位数据接口五步法

```text
① 打开目标页 → F12 Network → 勾 Preserve log
② 刷新页面（或触发加载更多/翻页）
③ 筛 Fetch/XHR → 找候选接口（看名字/路径/大小）
④ 点开看 Response → 确认是否含目标数据
⑤ 看 Headers/Payload → 记录完整请求参数（含 Cookie/签名）

验证：Console 里 fetch(接口) 能拿到数据 → 接口确认
```

| 观察点 | 记录什么 |
|--------|---------|
| URL | 完整地址（含 query） |
| 请求方法 | GET / POST |
| Payload | form 字段 / JSON body |
| Headers | UA / Cookie / Referer / 自定义头 |
| 响应格式 | JSON 结构（字段名） |
| 分页规律 | page/size/offset 参数变化 |

> 🎯 五步法产出 = **接口调用说明书**：有了它，阶段 2 的代码就是"把说明书翻译成 requests"（快 10 倍于渲染方案，见 [03 §6](03-网页三件套与DOM.md) 的黄金法则）。

## 7. 复制 curl 转 requests

```text
Network → 找到目标请求 → 右键 → Copy → Copy as cURL

复制出的 curl 包含完整请求信息：
  curl 'https://api.example.com/news?page=1' \
    -H 'User-Agent: Mozilla/5.0 ...' \
    -H 'Cookie: session_id=abc123' \
    -H 'Referer: https://example.com/list'

转换到 Python（两种方式）：
  ① 在线转换器（curlconverter.com，支持 Python requests）
  ② 手动翻译（理解头字段后照着写，推荐学这个）
```

```python
# curl → requests 手动翻译模板
import requests

resp = requests.get(
    "https://api.example.com/news",           # curl 的 URL
    params={"page": "1"},                     # curl 的 ?query
    headers={
        "User-Agent": "Mozilla/5.0 ...",      # -H 的请求头
        "Referer": "https://example.com/list",
        "Cookie": "session_id=abc123",        # 或放 cookies= 参数
    },
    timeout=10,
)
print(resp.json())
```

> ⚠️ curl 转代码的注意：① **Cookie 会过期**——复制后尽快用，正式方案走 Session；② **签名参数（sign/token）可能含时间戳**——接口若校验时间，静态复制的 curl 会失效；③ 别把 curl 里的敏感凭证提交到代码仓库（Cookie/token 要进配置或环境变量）。
