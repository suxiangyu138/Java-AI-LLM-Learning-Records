## 1. 正则的定位：什么时候该用

```text
正则适合：从"非结构文本"里提取片段
  ✅ 从 HTML/JS 源码里抠 URL、ID、数字、内嵌 JSON
  ✅ 从长文本里提取手机号/邮箱/日期
  ✅ 文本清洗（去空白/替换）

正则不适合：解析"有结构的树"
  ❌ 提取 HTML 里的列表项 → 用 BeautifulSoup（选择器更强）
  ❌ 解析 JSON → 用 json.loads
  口诀：有结构的用解析库，无结构的用正则
```

> 🎯 定位：**正则与解析库是互补的**——解析库管"树"，正则管"文本"。爬虫实战里最经典的组合：**用正则抠出 HTML 里的内嵌 JSON/URL，再用 json.loads/解析库处理**。

## 2. 元字符速查表

| 元字符 | 含义 | 示例 |
|--------|------|------|
| `.` | 任意字符（除换行） | `a.c` 匹配 abc/adc |
| `\d` | 数字 | `\d{4}` 四位数字 |
| `\w` | 字母数字下划线 | `\w+` 单词 |
| `\s` | 空白（空格/制表/换行） | `\s+` 空白串 |
| `\D \W \S` | 对应取反 | `\D` 非数字 |
| `[abc]` | 字符集 | `[0-9]` 数字 |
| `[^abc]` | 排除集 | `[^0-9]` 非数字 |
| `^` | 开头 | `^https` 以 https 开头 |
| `$` | 结尾 | `\.html$` 以 .html 结尾 |
| `\b` | 单词边界 | `\bcat\b` 独立单词 cat |

| 量词 | 含义 | 示例 |
|------|------|------|
| `*` | 0 次或多次 | `ab*` → a/ab/abb |
| `+` | 1 次或多次 | `ab+` → ab/abb |
| `?` | 0 次或 1 次 | `ab?` → a/ab |
| `{n}` | 恰好 n 次 | `\d{11}` 手机号 |
| `{n,}` | 至少 n 次 | `\d{4,}` |
| `{n,m}` | n 到 m 次 | `\d{1,3}` |

```text
常用组合（背下来）：
  \d+        数字串
  \w+        单词串
  [一-龥]+   中文字符串
  https?://[\w./-]+  URL（简单版）
```

## 3. 分组与捕获

```python
import re

text = "文章ID: 1001, 浏览量: 2345, 发布时间: 2026-08-08"

# 分组：用 () 圈出想提取的部分
m = re.search(r"文章ID: (\d+), 浏览量: (\d+)", text)
print(m.group(0))     # 整个匹配：文章ID: 1001, 浏览量: 2345
print(m.group(1))     # 第 1 组：1001
print(m.group(2))     # 第 2 组：2345

# 命名分组：可读性更好
m = re.search(r"发布时间: (?P<date>\d{4}-\d{2}-\d{2})", text)
print(m.group("date"))    # 2026-08-08

# 非捕获分组 (?:...)：只想分组不想捕获
re.search(r"(?:https?://)?\w+\.com", "example.com")
```

| 分组语法 | 作用 |
|---------|------|
| `(abc)` | 捕获组（group 1, 2...） |
| `(?P<name>abc)` | 命名捕获组 |
| `(?:abc)` | 非捕获组（只分组不捕获） |
| `(a|b)` | 分支（匹配 a 或 b） |

> ⚠️ **捕获组索引从 1 开始，group(0) 是整体**——新手常犯 `group(0)` 当第一组用。命名组（`?P<name>`）在字段多时是救命良药。

## 4. 贪婪 vs 懒惰

```python
import re

text = "<b>标题一</b> 和 <b>标题二</b>"

# 贪婪（默认）：尽可能多地匹配 → 一次吞掉两个标签！
re.findall(r"<b>.*</b>", text)
# ['<b>标题一</b> 和 <b>标题二</b>']  ← 一个结果，多吞了

# 懒惰（加 ?）：尽可能少地匹配 → 逐个标签
re.findall(r"<b>.*?</b>", text)
# ['<b>标题一</b>', '<b>标题二</b>']  ← 两个结果 ✅
```

| 写法 | 模式 | 行为 |
|------|------|------|
| `.*` | 贪婪 | 尽可能多（默认） |
| `.*?` | 懒惰 | 尽可能少 |
| `.+?` | 懒惰（至少 1 个） | 同上 |
| `.*?` 结束锚定 | 常配 `</标签>` | 提取到"第一个结束点" |

> ⚠️ **`.*` 贪婪是爬虫正则头号 bug**：HTML 里提取 `<a href="...">` 之间内容用 `.*?`；用 `.*` 会跨标签吞掉一切。**提取 HTML 片段一律懒惰匹配**。

## 5. Python re 模块实战

| 函数 | 用途 | 返回值 |
|------|------|--------|
| `re.search(pattern, text)` | 找第一个匹配 | Match 或 None |
| `re.findall(pattern, text)` | 找全部匹配 | **列表**（组 → 元组列表） |
| `re.finditer` | 迭代匹配 | 迭代器（大文本省内存） |
| `re.sub(pattern, repl, text)` | 替换 | 新字符串 |
| `re.split(pattern, text)` | 分割 | 列表 |
| `re.compile(pattern)` | 预编译（复用） | Pattern 对象 |

```python
import re

# findall 与分组：返回组内容的元组列表
html = '<a href="/news/1001.html">新闻一</a> <a href="/news/1002.html">新闻二</a>'
links = re.findall(r'href="([^"]+)"[^>]*>([^<]+)', html)
# [('/news/1001.html', '新闻一'), ('/news/1002.html', '新闻二')]

# sub 清洗：去掉 HTML 标签
clean = re.sub(r"<[^>]+>", "", html)      # 标签全删

# compile 预编译（循环里必须用！）
pattern = re.compile(r'id="article-(\d+)"')
for chunk in big_html_chunks:
    m = pattern.search(chunk)             # 预编译快一个数量级

# 常用标志
re.findall(r"^\d+", text, re.MULTILINE)        # 每行开头
re.findall(r"内容", text, re.IGNORECASE)        # 忽略大小写
re.findall(r"a.b", text, re.DOTALL)            # . 匹配换行
```

> 🎯 性能铁律：**循环内绝不用 `re.search("字面量", ...)` 每次现编译**——`re.compile` 预编译一次，循环里复用。大文本批量提取用 `finditer`（不一次性建全量列表）。

## 6. 爬虫高频正则模板

```python
import re

# ── 经典模板库（爬虫直接抄）──
URL = r'https?://[\w./\-?=&%#]+'                     # URL（含查询参数）
PHONE = r'1[3-9]\d{9}'                                # 大陆手机号
EMAIL = r'[\w.+-]+@[\w-]+\.[\w.]+'                    # 邮箱
DATE = r'\d{4}-\d{2}-\d{2}'                           # 日期 2026-08-08
CHINESE = r'[一-龥]+'                         # 中文串
HTML_TAG = r'<[^>]+>'                                 # HTML 标签（用于删除）
IMG_SRC = r'<img[^>]+src="([^"]+)"'                   # 图片地址
LINK = r'<a[^>]+href="([^"]+)"'                       # 链接地址
JSON_IN_SCRIPT = r'<script[^>]*type="application/json"[^>]*>(.*?)</script>'  # 内嵌 JSON

# 内嵌 JSON 提取（配合 json.loads 一步到位）
m = re.search(JSON_IN_SCRIPT, html, re.DOTALL)
if m:
    data = json.loads(m.group(1))     # 结构化数据直接可用！
```

> 💡 **内嵌 JSON 正则是最实用的模板**：SPA 站点的 `__NEXT_DATA__`/`__INITIAL_STATE__` 都能用这条抠出来——比解析 HTML 快得多（对应 [03 §6](03-网页三件套与DOM.md)）。

## 7. 正则 vs 解析库：怎么分工

| 场景 | 用谁 | 原因 |
|------|------|------|
| 提取 HTML 列表项/标题 | **BeautifulSoup/lxml** | 树结构定位，稳 |
| 从 JS 源码抠 URL/ID | **正则** | 无结构文本 |
| 抠内嵌 JSON | **正则 + json** | 先抠后解析 |
| 数据清洗（去标签/空白） | 正则 sub | 一次性替换 |
| 校验格式（手机号/邮箱） | 正则 | 精确匹配 |
| 大 HTML 全量提取 | lxml XPath | 性能与稳定 |

> 🎯 决策口诀：**有结构（HTML/JSON/XML）→ 解析库；无结构（JS/文本/日志）→ 正则**。硬用正则解析 HTML 是新手常见弯路（HTML 不规范时正则必崩）；硬用解析库抠 JS 里的数字也是事倍功半。
