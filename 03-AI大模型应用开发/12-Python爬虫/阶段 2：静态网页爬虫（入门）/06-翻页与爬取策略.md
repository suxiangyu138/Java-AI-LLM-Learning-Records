## 1. 分页的四种模式

| 模式 | URL 规律 | 示例 | 遍历方式 |
|------|---------|------|---------|
| **查询参数分页** | `?page=N` | `/list?page=1` | 循环 page 参数（最常见） |
| 路径分页 | `/page/N` | `/list/page/2` | 循环路径 |
| **偏移分页** | `?offset=N` | `/list?offset=20` | offset 累加 |
| 下一页链接 | `<a href="?page=3">下一页</a>` | 无规律 | 跟链接（最通用） |

```python
# ═══ 模式一：参数分页（最常见）═══
for page in range(1, 11):                     # 第 1-10 页
    resp = session.get(
        "https://example.com/api/news",
        params={"page": page, "size": 20},
        timeout=10,
    )
    items = parse_list(resp.text)
    if not items:
        break                                  # 空页 = 到底了
    save(items)

# ═══ 模式四：下一页链接（无规律站点的通用解）═══
url = "https://example.com/list"
while url:
    resp = session.get(url, timeout=10)
    items, next_url = parse_list_with_next(resp.text)   # 解析出"下一页"链接
    save(items)
    url = next_url                             # 没有下一页 → None → 结束
```

> 🎯 模式选型：**能参数化就参数化（简单可控）；只能跟链接就跟链接（通用）**——"下一页"链接解析是任何站点都适用的保底方案。

## 2. 翻页遍历实现

```python
# ═══ 完整翻页实现（参数分页 + 下一页混合兼容）═══
def crawl_paginated(session, base_url, start_page=1, max_pages=100):
    """翻页采集：参数分页 + 空页终止 + 上限保护"""
    all_items = []
    for page in range(start_page, start_page + max_pages):
        resp = session.get(base_url, params={"page": page}, timeout=10)
        resp.raise_for_status()

        items = parse_list(resp.text)
        if not items:
            print(f"第 {page} 页无数据，结束")
            break                              # ① 空页终止

        all_items.extend(items)
        print(f"第 {page} 页：{len(items)} 条，累计 {len(all_items)}")

        time.sleep(1)                          # ② 礼貌间隔（§4）
    return all_items

# 解析函数返回列表（清洗/去重在内部完成）
def parse_list(html_text):
    soup = BeautifulSoup(html_text, "lxml")
    container = soup.select_one("ul.news-list")
    if not container:
        return []
    return [extract_item(item) for item in container.select("li")]
```

| 翻页要素 | 实现 |
|---------|------|
| 循环 | for page / while next_url |
| 终止 | 空页 break / 上限保护（max_pages） |
| 礼貌 | 每页 sleep（§4） |
| 失败 | 单页失败重试（02 §3）或记录跳过 |
| 进度 | 打印每页进度（大采集必需） |

> ⚠️ **max_pages 上限保护是安全阀**：没有上限的翻页循环，一旦站点分页逻辑异常（如永远有下一页）会无限爬——生产代码必须设上限（如 100 页）或按"无新数据"终止。

## 3. 终止条件与防循环

```text
终止条件的四种判断：
  ① 空页：当前页无数据 → 结束（最常见）
  ② 重复：下一页 URL 已抓过 → 结束（防循环）
  ③ 上限：达到 max_pages → 结束（保护）
  ④ 异常：连续 N 次失败 → 结束（止损）

防循环三件套：
  seen_urls 集合（本会话）
  max_pages 上限（兜底）
  连续失败计数（异常止损）
```

```python
# ═══ 下一页跟链 + 防循环 ═══
def crawl_follow_next(session, start_url, max_pages=50):
    seen = set()                       # 已访问 URL（防循环）
    url = start_url
    fails = 0                          # 连续失败计数
    for _ in range(max_pages):
        if url in seen:                # ① 循环检测
            print("检测到循环，终止")
            break
        seen.add(url)

        try:
            resp = session.get(url, timeout=10)
            resp.raise_for_status()
            items, url = parse_with_next(resp.text)
            save(items)
            fails = 0
            if not url:                # ② 没有下一页
                break
        except requests.RequestException:
            fails += 1
            if fails >= 3:             # ③ 连续 3 次失败止损
                print("连续失败，终止")
                break
        time.sleep(1)
```

> 🎯 防循环认知：**"下一页链接循环"真实存在**（站点 bug 或恶意设计）——`seen` 集合检测 + `max_pages` 上限双保险，是翻页爬虫的标配防护。

## 4. 爬取节奏：礼貌与效率

```python
import time
import random

# ═══ 礼貌间隔（固定 vs 随机）═══
time.sleep(1)                        # 固定间隔：简单
time.sleep(random.uniform(0.5, 1.5)) # 随机间隔：更像人（推荐）

# ═══ 节奏设计 ═══
# 礼貌基线（阶段 1 §8）：
#   小站：1-2 秒/请求
#   中型站：0.5-1 秒/请求
#   大平台 API：按官方限速
# 参考：人工浏览速度（别比真人快太多）

# ═══ 429 处理（被限速的信号）═══
resp = session.get(url, timeout=10)
if resp.status_code == 429:
    retry_after = int(resp.headers.get("Retry-After", "60"))   # 服务器建议等待
    print(f"被限速，等待 {retry_after}s")
    time.sleep(retry_after)
```

| 节奏策略 | 说明 |
|---------|------|
| 固定间隔 | 简单可预期 |
| **随机间隔** | 防模式识别（更像人，阶段 4 深化） |
| 429 等待 | 尊重 Retry-After（服务器明示） |
| 高峰期避开 | 19-23 点少爬（阶段 1 §8） |
| 频率监控 | 统计每分钟请求数 |

> ⚠️ 节奏认知：**"爬太快不是效率，是自杀"**——高频请求触发限流/封禁后，重试成本远超"慢一点"的代价。礼貌节奏 + 稳定运行 > 快节奏 + 频繁被封。

## 5. 失败与断点

```python
# ═══ 失败处理策略 ═══
# ① 单页失败：重试（02 §3）→ 仍失败：记录跳过（不中断整批）
failed_pages = []                     # 失败清单

for page in range(1, 21):
    try:
        items = fetch_and_parse(page)
        save(items)
    except requests.RequestException as e:
        failed_pages.append(page)     # 记录
        print(f"第 {page} 页失败：{e}，稍后重试")

# ② 收尾补抓：失败页统一重试
for page in failed_pages:
    try:
        items = fetch_and_parse(page)
        save(items)
    except requests.RequestException:
        print(f"第 {page} 页最终失败，人工处理")

# ═══ 断点续抓（简单版：记录进度）═══
# 已抓页码写入文件，中断后从断点继续
progress_file = "progress.txt"
with open(progress_file) as f:
    done = {int(line.strip()) for line in f if line.strip()}

for page in range(1, 21):
    if page in done:
        continue                      # 已抓过，跳过
    # ... 抓取与保存 ...
    with open(progress_file, "a") as f:
        f.write(f"{page}\n")          # 完成即记录
```

| 失败处理 | 做法 |
|---------|------|
| 失败不中断 | 记录失败项，收尾统一补抓 |
| 断点续抓 | 进度落文件（简单）→ 落数据库（阶段 3） |
| 最终失败 | 人工处理清单（别无限重试） |

> 🎯 工程认知：**"爬虫要能'中断再续'"**——几百页的采集跑一半断了很正常；失败清单 + 进度文件让"断点续跑"成为可能（阶段 3 后进度进数据库，更可靠）。

## 6. 全站爬取策略设计

```text
全站爬取的标准策略（列表页 → 详情页两层）：
  ① 列表页：翻页采集 URL（只抓链接，不解析内容）
  ② 详情页：逐条抓取（列表 URL → 详情 HTML → 提取）
  ③ 去重：URL 集合（详情页不重复抓）
  ④ 节奏：列表页快（轻请求）、详情页慢（重请求）

示例流程：
  list_urls = crawl_pagination(列表页)      # 收集所有列表 URL
  seen = set()
  for url in list_urls:
      if url in seen: continue
      seen.add(url)
      detail_html = fetch(url)              # 抓详情
      data = extract_detail(detail_html)    # 提取
      save(data)                            # 存储（07）
      time.sleep(1)
```

| 策略要素 | 设计 |
|---------|------|
| 分层 | 列表页只收 URL、详情页才提取 |
| 去重 | 详情 URL 集合（防重复抓） |
| 节奏 | 详情页是主要成本（加重睡眠） |
| 失败 | 详情失败记录，收尾补抓 |
| 存储 | 07 章（CSV/JSON/SQLite） |

> 🎯 面试点：**"全站爬虫的标准架构 = 列表页（URL 收集）+ 详情页（内容提取）两层"**——这也是 Scrapy 框架（阶段 6）内置的 Spider 模式；先用手写代码理解它，用框架时就是"换个壳"。
