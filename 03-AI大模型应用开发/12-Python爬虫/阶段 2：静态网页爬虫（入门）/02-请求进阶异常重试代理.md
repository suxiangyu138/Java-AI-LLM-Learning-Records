## 1. 异常体系全景

```python
import requests

# requests 异常层级（从具体到通用）：
# requests.exceptions.RequestException（所有异常的基类）
#   ├── ConnectionError         连接失败（DNS/拒连/断网）
#   ├── Timeout                 超时（connect/read）
#   │     ├── ConnectTimeout    连接超时
#   │     └── ReadTimeout       读取超时
#   ├── HTTPError               HTTP 状态错误（4xx/5xx，需 raise_for_status 触发）
#   ├── ProxyError              代理错误
#   ├── SSLError                TLS 证书问题
#   └── TooManyRedirects        重定向过多

try:
    resp = requests.get("https://example.com", timeout=10)
    resp.raise_for_status()          # ⚠️ 4xx/5xx 抛 HTTPError（默认不抛！）
except requests.Timeout:
    print("超时：网络慢或服务器慢")
except requests.ConnectionError:
    print("连接失败：检查网络/域名")
except requests.HTTPError as e:
    print(f"HTTP 错误：{e.response.status_code}")
except requests.RequestException as e:
    print(f"其他请求异常：{e}")
```

| 异常 | 触发场景 | 处理 |
|------|---------|------|
| `Timeout` | 连接/读取超时 | 重试（临时故障）或跳过 |
| `ConnectionError` | 断网/DNS/拒连 | 重试或告警 |
| `HTTPError` | **需 raise_for_status() 才抛** | 按状态码处理（403/429 见阶段 1） |
| `SSLError` | 证书问题 | 检查证书（阶段 1 §7 正确姿势） |
| `RequestException` | 兜底 | 统一记录 |

> ⚠️ 两大认知：**① `raise_for_status()` 必须手动调**——requests 对 404/500 默认不抛异常（静默返回响应）；**② 异常 ≠ 状态码**——网络异常走 except，业务错误（403/404）走状态码判断，两者都要处理。

## 2. 超时设计：连接与读取

```python
# ═══ 超时两种写法 ═══
resp = requests.get(url, timeout=10)              # 总超时（连接+读取合计）
resp = requests.get(url, timeout=(3, 30), timeout=10)  # 连接 3s + 读取 30s（推荐）

# 为什么要分离：
#   connect timeout=3   ：快速失败（服务器不可达时 3 秒止损）
#   read timeout=30     ：慢响应容忍（大页面/慢接口给足时间）
```

| 超时设计 | 建议 |
|---------|------|
| 普通页面 | `timeout=(3, 15)` |
| 大文件下载 | `timeout=(3, 60)` 或流式 |
| 快速 API | `timeout=(2, 5)` |
| 永不设超时 | ❌ 禁止（请求挂死 = 爬虫线程卡死） |

> 🎯 面试/实战点：**"超时是爬虫的保命符"**——不设超时的爬虫，一个挂死的请求会堵住整个采集线程；`(connect, read)` 分离让"连不上快速失败、读得慢多等等"两全。

## 3. 自动重试：指数退避

```python
import time
import requests

# ═══ 手动重试 + 指数退避（最通用）═══
def fetch_with_retry(url, max_retries=3, **kwargs):
    for attempt in range(max_retries):
        try:
            resp = requests.get(url, timeout=(3, 15), **kwargs)
            resp.raise_for_status()
            return resp
        except requests.Timeout:
            if attempt == max_retries - 1:
                raise
            # 指数退避：1s → 2s → 4s（+ 随机抖动防雪崩）
            sleep_time = 2 ** attempt + random.uniform(0, 1)
            print(f"超时重试 {attempt+1}/{max_retries}，等待 {sleep_time:.1f}s")
            time.sleep(sleep_time)
        except requests.ConnectionError:
            # 连接类错误同样退避重试（网络抖动常见）
            time.sleep(2 ** attempt)
    # 到达此处说明 retries 用完
    raise requests.RequestException(f"请求失败（重试 {max_retries} 次）: {url}")

# ═══ 用 HTTPAdapter 配重试（requests 原生）═══
from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry

session = requests.Session()
retry = Retry(
    total=3,                          # 总重试次数
    connect=3,                        # 连接错误重试
    read=2,                           # 读取错误重试
    status=2,                         # 特定状态码重试
    status_forcelist=[500, 502, 503, 504],   # 服务器错误才重试
    backoff_factor=0.5,               # 退避系数：0.5, 1, 2, 4...
)
adapter = HTTPAdapter(max_retries=retry)
session.mount("http://", adapter)
session.mount("https://", adapter)
```

| 重试规则 | 说明 |
|---------|------|
| 可重试 | 超时、连接错误、5xx（服务器临时故障） |
| **不可重试** | 403/404/400（重试也白搭——身份/路径问题） |
| 退避 | 指数增长 + 随机抖动（防"集体重试风暴"） |
| 上限 | 3-5 次足够（重试是缓解，不是治疗） |
| 幂等 | 只有 GET 等幂等请求可安全重试 |

> ⚠️ 重试铁律：**"只重试临时故障（超时/5xx），不重试永久错误（4xx）"**——403 重试 10 次只会更早触发封禁。429 是特殊信号：重试前必须等待 `Retry-After`（阶段 4 展开）。

## 4. 代理：换出口 IP

```python
# ═══ 代理基本用法 ═══
proxies = {
    "http": "http://user:pass@proxy.example.com:8080",
    "https": "http://user:pass@proxy.example.com:8080",
}
resp = requests.get(url, proxies=proxies, timeout=10)

# ═══ 环境变量代理（全局生效）═══
# export HTTP_PROXY=http://proxy:8080
# export HTTPS_PROXY=http://proxy:8080

# ═══ 本地测试禁用代理 ═══
proxies = {"http": None, "https": None}
```

| 代理类型 | 场景 |
|---------|------|
| 正向代理 | 换出口 IP（反爬对抗，**阶段 4 重点**） |
| 隧道代理 | 单次请求独立 IP（高匿） |
| 内网代理 | 企业网络出口 |
| 本地直连 | 测试时禁用代理（`None`） |

> 💡 本阶段只需"会用"：代理是阶段 4（反爬基础）的核心武器——IP 被封后换出口。现在知道 `proxies={}` 参数即可，别过早投入。

## 5. HTTPS 校验与 verify

```python
# ═══ 正确姿势：信任指定 CA（自签证书环境）═══
resp = requests.get(url, verify="/path/to/ca.crt", timeout=10)
# 或全局设置：REQUESTS_CA_BUNDLE=/path/to/ca.crt 环境变量

# ═══ 请求带客户端证书（双向 TLS）═══
resp = requests.get(url, cert=("/path/client.crt", "/path/client.key"), timeout=10)
```

> ⚠️ 安全红线（与阶段 1 §7 一致）：**任何情况下都不要用 `verify=False` 跳过证书验证**——那等于告诉爬虫"不验证对方身份"，公网环境会暴露在中间人攻击下（流量可被窃听/篡改）。自签证书环境的正规解法是 `verify=CA 证书路径`（把 CA 加入信任库）；生产必须真证书 + 完整校验。

## 6. 健壮请求封装模板

```python
"""健壮请求模块（爬虫项目标配，直接抄）"""
import random
import time
import requests
from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry

HEADERS = {
    "User-Agent": ("Mozilla/5.0 (Windows NT 10.0; Win64; x64) "
                   "AppleWebKit/537.36 (KHTML, like Gecko) "
                   "Chrome/126.0.0.0 Safari/537.36"),
    "Accept-Language": "zh-CN,zh;q=0.9",
}

def build_session(retries: int = 3) -> requests.Session:
    """创建带重试与统一头的会话"""
    session = requests.Session()
    session.headers.update(HEADERS)
    retry = Retry(
        total=retries,
        connect=retries,
        read=retries,
        status=retries,
        status_forcelist=[500, 502, 503, 504],
        backoff_factor=0.5,
        allowed_methods=["GET", "POST"],
    )
    adapter = HTTPAdapter(max_retries=retry)
    session.mount("http://", adapter)
    session.mount("https://", adapter)
    return session

def fetch(session: requests.Session, url: str, **kwargs) -> requests.Response:
    """安全请求：超时兜底 + 状态码校验 + 礼貌间隔"""
    kwargs.setdefault("timeout", (3, 15))
    resp = session.get(url, **kwargs)
    resp.raise_for_status()               # 4xx/5xx 抛异常
    time.sleep(0.5)                       # 礼貌间隔（阶段 1 §8）
    return resp

# 使用
session = build_session()
resp = fetch(session, "https://example.com/news")
```

> 🎯 封装的价值：**"请求代码写一次，全项目复用"**——超时/重试/UA/礼貌间隔全在函数里，业务代码只关心"拿到 HTML"。这是爬虫工程化的第一小步（阶段 6 异步化时这套封装直接升级复用）。
