## 2. CSV 存储

```python
import csv

# ═══ 写入（标准姿势）═══
data = [
    {"title": "新闻一", "url": "https://example.com/n/1", "date": "2026-08-08"},
    {"title": "新闻二", "url": "https://example.com/n/2", "date": "2026-08-07"},
]

with open("news.csv", "w", newline="", encoding="utf-8-sig") as f:
    writer = csv.DictWriter(f, fieldnames=["title", "url", "date"])
    writer.writeheader()                  # 表头
    writer.writerows(data)                # 全部写入

# ═══ 追加写入（增量爬取）═══
with open("news.csv", "a", newline="", encoding="utf-8-sig") as f:
    writer = csv.DictWriter(f, fieldnames=["title", "url", "date"])
    writer.writerow(new_item)             # 单条追加

# ═══ 读取 ═══
with open("news.csv", encoding="utf-8-sig") as f:
    reader = csv.DictReader(f)
    for row in reader:
        print(row["title"], row["url"])
```

| CSV 要点 | 说明 |
|---------|------|
| **`encoding="utf-8-sig"`** | Excel 打开不乱码的关键（带 BOM） |
| `newline=""` | 防 Windows 下空行（官方要求） |
| `DictWriter` | 字典直接写（字段对齐表头） |
| 追加 | 增量采集用 `"a"` 模式 |
| 坑 | 字段含逗号/换行 → csv 自动加引号（别手拼） |

> ⚠️ **`utf-8-sig` 是 Excel 兼容密码**：普通 `utf-8` 写的 CSV 用 Excel 打开中文乱码——`utf-8-sig`（带 BOM）是爬虫 CSV 的标准编码。同理读取时也用 `utf-8-sig`。

## 3. JSON 存储

```python
import json

# ═══ 写入（结构化数据首选）═══
data = [
    {"title": "新闻一", "tags": ["AI", "爬虫"], "views": 1234},
    {"title": "新闻二", "tags": ["Python"], "views": 567},
]

with open("news.json", "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False, indent=2)
# ensure_ascii=False：中文不转义（可读）
# indent=2：格式化（人可读）

# ═══ 追加（JSON 不适合追加 → 先读后写）═══
with open("news.json", encoding="utf-8") as f:
    data = json.load(f)
data.append(new_item)
with open("news.json", "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False, indent=2)

# ═══ 读取 ═══
with open("news.json", encoding="utf-8") as f:
    data = json.load(f)
```

| JSON 要点 | 说明 |
|---------|------|
| `ensure_ascii=False` | **中文必须**（否则变 \uXXXX） |
| `indent=2` | 可读性（小数据）；大数据不缩进省空间 |
| 追加 | JSON 数组不适合追加（先读后写；大数据用 SQLite） |
| 嵌套结构 | dict/list 自由组合（比 CSV 强） |

> 🎯 CSV vs JSON 选型：**表格型数据（每行同字段）→ CSV（Excel 友好）；嵌套/异构数据 → JSON**。学习阶段先 CSV（看得见、Excel 能开），生产结构复杂再 JSON/数据库。

## 4. Excel 存储（可选）

```python
# 需要库：pip install openpyxl（2026 标准 Excel 库）

from openpyxl import Workbook

wb = Workbook()
ws = wb.active
ws.title = "新闻数据"

# 表头
ws.append(["标题", "链接", "日期"])
# 数据行
for item in data:
    ws.append([item["title"], item["url"], item["date"]])

wb.save("news.xlsx")
```

| 场景 | 说明 |
|------|------|
| 交付给业务 | Excel 是"非技术同事最爱"的格式 |
| 数据分析 | 直接进 Excel 透视 |
| 大数据 | ❌（Excel 上限 100 万行，用 CSV/SQLite） |

> 💡 Excel 是**交付格式**不是**存储格式**：爬虫中间过程用 CSV/JSON/SQLite，最终交付才转 Excel（`pandas.to_excel` 或 openpyxl）。

## 5. SQLite：轻量数据库

```python
import sqlite3

# ═══ 建表 + 写入（单文件数据库，无需安装服务）═══
conn = sqlite3.connect("news.db")          # 不存在则创建
cur = conn.cursor()

# 建表（字段类型明确 + 唯一约束去重）
cur.execute("""
    CREATE TABLE IF NOT EXISTS news (
        id      INTEGER PRIMARY KEY AUTOINCREMENT,
        title   TEXT NOT NULL,
        url     TEXT NOT NULL UNIQUE,      -- ⚠️ UNIQUE：数据库级去重！
        date    TEXT,
        views   INTEGER DEFAULT 0,
        created_at TEXT DEFAULT (datetime('now'))
    )
""")

# 插入（参数化防注入 + 幂等去重）
cur.execute(
    "INSERT OR IGNORE INTO news (title, url, date, views) VALUES (?, ?, ?, ?)",
    (item["title"], item["url"], item["date"], item.get("views", 0)),
)   # INSERT OR IGNORE：url 重复则跳过（去重！）

conn.commit()

# ═══ 查询 ═══
cur.execute("SELECT title, url, views FROM news WHERE views > 100 ORDER BY views DESC LIMIT 10")
for row in cur.fetchall():
    print(row)

conn.close()
```

| SQLite 要点 | 说明 |
|-----------|------|
| 零安装 | 单文件数据库（Python 内置 sqlite3） |
| `UNIQUE` 约束 | **数据库级去重**（比代码集合可靠） |
| `INSERT OR IGNORE` | 重复插入静默跳过（幂等） |
| 参数化 `?` | **防 SQL 注入**（爬虫数据也可能含恶意字符串！） |
| 事务 | commit() 提交（批量后统一提交更快） |

> ⚠️ **参数化是铁律**：`f"INSERT INTO news VALUES ('{title}')"` 这种字符串拼接——爬到的数据里若含 `'` 或恶意 SQL，直接注入或报错。**一律 `?` 占位符**（与 [Web 安全注入篇](../../../../02-后端核心技术%20微服务%20分布式%20云原生/09-Web开发全流程/Web%20高阶知识/07-Web安全攻防.md) 的 SQL 注入防护同源）。

## 6. 存储工程规范

```text
存储规范自查：
  □ CSV 用 utf-8-sig（Excel 兼容）
  □ JSON 用 ensure_ascii=False + 缩进
  □ 文件按日期/批次命名（news_20260808.csv）
  □ 追加写入防重复（数据库 UNIQUE / 代码集合）
  □ 所有 SQL 参数化（? 占位符）
  □ 存储与爬取分离（先收集后落盘，别边爬边纠结格式）
  □ 定期检查文件大小（异常增长 = 重复写入）

进阶预告（阶段 3）：
  MySQL/MongoDB 生产存储
  去重与增量策略（数据库级）
  数据清洗流水线（pandas）
```

> 🎯 本阶段存储定位：**"能落盘、能看、能用"即可**——别在存储上过度设计；阶段 3 会把这些文件级经验升级为数据库级方案（表结构/索引/事务/增量）。
