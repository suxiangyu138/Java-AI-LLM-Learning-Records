## 1. AI+爬虫的定位

**2026 年爬虫的最大变化：AI 重写了"解析与提取"环节**：

```text
AI 重写了爬虫的什么
├── 解析层：CSS 选择器/正则（手写）→ Jina Reader/LLM（自动理解）
├── 提取层：字段规则（手写）→ 自然语言描述（"提取标题和价格"）
├── 反爬层：拟人行为（手写）→ Scrapling 自动拟人（02 篇三件套）
└── 编排层：多步流程 → Data Agent（拆解/执行/验证）
    ——"AI 不替代'请求'（还是要 HTTP），替代的是'理解页面'（解析与提取）"
```

**定位心智**：**"AI+爬虫的核心价值：'把'写解析规则'变成'说提取需求'"**——**"旧时代：页面改版 = 改选择器；AI 时代：页面改版 = 模型重新理解（容错更强）——'AI 提取的容错性 = 爬虫抗改版的能力'"**（"传统解析是'精确匹配'（改版就挂），LLM 提取是'语义理解'（改版也能认）——**'抗改版是 AI 提取的第一价值'"**）；**AI 的边界**——"AI 提取也吃'请求质量'（反爬拦截了照样没内容）、LLM 有成本（Token 计费）、有幻觉（编字段）——**'AI 是解析器的升级，不是爬虫的全部——请求/调度/存储还是老手艺'"**（"AI 优化的环节：解析+提取（40% 的工作量）；不动：请求+调度（60%）——**'爬虫的骨架还是工程师的'"**）。

## 2. Jina Reader：一行提取

**Jina Reader（2026 年 LLM 网页提取的"零摩擦"首选）——URL 直接变 Markdown**：

```python
import requests

# 一行提取：URL 前加 r.jina.ai/ 前缀——返回干净 Markdown
url = "https://example.com/news/article1"
resp = requests.get(f"https://r.jina.ai/{url}", timeout=30)
print(resp.text[:500])          # 干净的 Markdown（标题/正文——HTML 噪音已剥离）

# 结构化输出：Accept: application/json
resp = requests.get(f"https://r.jina.ai/{url}",
                    headers={"Accept": "application/json"})
data = resp.json()              # {"title": ..., "content": ..., "url": ...}

# 免费额度：每日 200 次（高并发申请 API Key——Token 计费 $0.05/百万）
# 技术内核：ReaderLM-v2（1.5B 模型）——渲染页面 + 剥离样板 + 去重链接
```

**Jina 心智**：**"Jina Reader 的价值：'摩擦最低的抽取器'——不用写选择器、不用管反爬（它处理）、输出 LLM 直接能用的 Markdown"**——**"适用场景：原型开发（3 分钟出数据）、一次性提取、RAG 数据源（Markdown 直接喂 LLM）——'Jina = 爬虫的'自动驾驶——一脚油门到目的地'"**（数据分析阶段 5 方向 C 09 篇的落地工具）；**Jina 的边界**——"免费额度有限（200 次/天）、公众号/强反爬 403（打不过）、不支持全站爬取（单页提取）——**'Jina 是'页面提取器'，不是'爬虫系统'——它的定位是解析层的替代，不是调度层的替代'"**（"批量/全站还是自己的爬虫 + Jina 做解析——**'Jina 嵌进爬虫管道 = 最佳姿势'"**）。

## 3. 工具对比与分级路由

**2026 提取工具三巨头对比——按场景路由**：

| 维度 | Jina Reader | Firecrawl | Scrapling |
|------|------------|-----------|-----------|
| 定位 | 单页提取（Markdown/JSON） | 全站爬取 + 结构化提取 | 轻量爬虫库（含反爬） |
| 反爬 | 一般（公众号 403） | 强（云浏览器） | 强（StealthyFetcher 拟人） |
| 免费 | 200 次/天 | 部分免费 | 完全免费（开源） |
| 动态页面 | 支持（Headless） | 支持 | 支持（Dynamic 模式） |
| 最佳场景 | 原型/单页/LLM 数据 | 全站/结构化 Schema | 公众号/强反爬/免费 |

```python
# 分级路由策略（2026 最佳实践——按 URL 特征选工具）
def smart_extract(url):
    if "mp.weixin.qq.com" in url:              # 公众号 → Scrapling（唯一免费方案）
        return scrapling_extract(url)
    if jina_quota_left() > 0:                   # Jina 有额度 → Jina（质量最优）
        return jina_extract(url)
    return scrapling_extract(url)               # 兜底 → Scrapling（免费无限）
```

**路由心智**：**"分级路由的核心：'每个工具干它最擅长的'——Jina 质量优/Scrapling 反爬强/Firecrawl 全站强"**——**"路由的判断依据：URL 特征（公众号域名）+ 额度状态（Jina 200 次）+ 页面类型（动态/静态）——'路由规则 = 工具选型的工程化——把'选哪个工具'的思考写进代码'"**（"实测结论（2026）：静态页 Jina≈Scrapling、公众号 Scrapling 唯一能打、动态 SPA Scrapling(Dynamic) 领先——**'路由规则来自实测，不是想当然'"**）；**Scrapling 的崛起**——"开源免费 + StealthyFetcher（自动拟人绕 Cloudflare——02 篇三件套的封装）——**'2026 年免费爬虫的'性价比之王'——反爬 + 解析一体化'"**（"Scrapling = requests 的'2026 升级版'——防检测内置"）。

## 4. LLM 提取：从解析到理解

**LLM 提取 = 用自然语言描述"要什么字段"，模型从页面理解并提取**：

```python
# 场景：传统方式要写 CSS 选择器（.price, .title——改版就挂）
# LLM 方式：说需求——模型语义理解（改版也能认）

# 示例（配合 Jina 的 Markdown 输出——数据干净了，LLM 才好理解）
def llm_extract(markdown: str, fields: list[str]) -> dict:
    """用 LLM 从 Markdown 提取字段（简化示意——实际调用大模型 API）"""
    prompt = f"""从以下文章提取字段：{fields}
要求：JSON 输出；字段缺失时填 null；不要编造。
文章内容：
{markdown[:3000]}"""
    # resp = call_llm(prompt)   # 调用 LLM（03-AI 大模型 API 体系）
    return parse_json(resp)

# 用法：改版/新站不用写选择器——说一句"提取标题、作者、发布日期、正文"就完事
```

**LLM 提取心智**：**"LLM 提取的适用：'字段不固定/页面经常改/新站快速上线'——传统解析的适用：'字段固定/量大/成本敏感'"**——**"选型权衡：LLM 提取（抗改版 + 快上线 + Token 成本）vs 选择器（零成本 + 快 + 改版就挂）——'混合姿势：主字段选择器（快），易变字段 LLM（稳）——'稳定的用规则，易变的用 AI'"**；**LLM 提取的工程纪律**——"提示词要'不许编造 + 缺失填 null'（幻觉控制——数据分析阶段 5 方向 C 09 篇三查的提取版）、输出要 JSON 校验（解析失败重试）、成本要监控（Token 按量计——**'LLM 提取的成本 = 页数 × 每页 Token——先小样本估成本再全量'"**；**LLM 提取 vs 传统解析的对照**——"传统：确定但脆弱（改版挂）；LLM：灵活但有成本（幻觉/计费）——**'没有免费午餐——选型是'稳定性 vs 灵活性'的权衡'"**（"结构化强页面（列表/表格）用规则；非结构化页面（新闻/文章）用 LLM——**'规则管结构，LLM 管理解'"**）。

## 5. MCP 集成与 Agent 生态

**MCP（Model Context Protocol）——2026 年爬虫与 AI Agent 的接口标准**：

```text
MCP 集成（爬虫能力开放给 Agent）
├── 爬虫工具封装成 MCP Server：fetch_url / extract_data / search_web
├── Agent（Claude/ChatGPT 类）通过 MCP 调用——"Agent 说'查一下这个页面的价格'，
│    爬虫 MCP 工具去抓 + 提取，结果回给 Agent"
├── 现成生态：Jina Reader MCP（@mseep/mcp-web-reader——三引擎智能降级）、
│    Jina 官方 MCP Server（搜索 + 提取）
└── 意义：爬虫从"工程师的工具"变成"Agent 的能力"——数据获取的最后一环 AI 化
    ——"2026 年：爬虫能力的消费方从'人'扩展到了'Agent'"
```

**MCP 心智**：**"MCP 的价值：'把爬虫能力标准化成 Agent 可调用的接口'"**——**"Agent 时代的爬虫形态：Agent 提问 → MCP 工具抓取 → 提取 → Agent 分析——'爬虫从'数据管道'变成'Agent 的手'"**（`../../03-Agent开发/` 与 `../../06-MCP协议与Agent%20Skill/` 的衔接——"爬虫课程与 AI 课程的汇合点"）；**MCP 集成的工程细节**——"工具设计（fetch_url 参数：url/格式/等待选择器）、降级策略（Jina → 本地解析 → Playwright——智能降级——'能用的先试，被拦的自动换'）、权限与频率（Agent 调用也要限速——**'Agent 是更激进的调用方——频率纪律要内建'**）——"**MCP 化爬虫的验收：Agent 一句话能拿到数据——'数据获取的最后一环 AI 化'"**；**2026 全景定位**——"Jina Reader 已是 RAG/Agent 的基础设施（抓取 + 转 Markdown 喂 LLM）——**'爬虫工程师的新角色：AI 的数据管道工——把网页变成 LLM 能吃的格式'"**（"本阶段与数据分析方向 C 09 篇（Data Agent）的汇合——**'爬虫课程的终点，是 AI Agent 数据获取的起点'"**）。
