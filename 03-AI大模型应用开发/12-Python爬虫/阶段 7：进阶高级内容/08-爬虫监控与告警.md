## 1. 监控的定位

**爬虫系统与普通程序的区别：7×24 无人值守运行**——所以监控是标配不是选项：

```text
为什么爬虫必须监控
├── 无人值守：半夜 3 点跑——挂了你不知道 = 数据断了没人发现
├── 外部依赖多：目标站改版/反爬升级/IP 被封/网络波动——随时可能挂
├── 数据有承诺：周期爬虫的时效性承诺（每日更新）——挂一天 = 失信一天
└── 成本放大：分布式（05 篇）——挂一台 ≠ 挂一点，是挂一片
    ——"爬虫的故障不是'会不会发生'，是'什么时候发生'——监控决定你多早知道"
```

**监控心智**：**"监控的目标：'故障发现时间'最小化"**——**"发现时间的公式：故障 = 数据缺失 + 下游停摆 + 信任流失——发现越晚损失越大——'监控的价值 = 把'三天后发现'变成'三分钟后发现'"**（"不监控的爬虫 = 开着车不系安全带——平时没事，出事就是大事"）；**监控的分层**——"系统层（进程活没活/内存 CPU）+ 爬虫层（速率/队列/失败率）+ 数据层（质量指标——07 篇）——**'三层监控 = 从'机器活着'到'数据对了'的完整链路'"**（"只监控进程 = 机器活着但爬的数据全是垃圾——你要的是'数据对了'"）。

## 2. 监控什么：四大指标

**爬虫监控四大指标（爬虫层 + 数据层的核心）**：

```text
爬虫监控四大指标
├── ① 速率（RPS）：每秒请求/每分钟抓取——"0 了 = 挂了或队列空了"
├── ② 队列积压（05 篇 Redis）：待爬队列长度——"暴涨 = 解析/存储慢了"
├── ③ 失败率：请求失败/解析失败比例——"突增 = 反爬升级或目标站改版"
├── ④ 质量指标（07 篇）：完整率/去重率——"质量掉 = 数据采集出问题"
    ——"四个指标 = 爬虫的'心电图'——每个都能定位一类故障"
```

```python
# 监控数据上报（简单实现——记录到 Redis/日志，面板展示）
import redis, time

r = redis.Redis(host="redis-host", decode_responses=True)

def report_stats(ok=0, fail=0, parsed=0):
    """每分钟上报一次统计（Redis 计数器——跨进程共享）"""
    minute = time.strftime("%Y%m%d%H%M")
    r.hincrby(f"crawl:stats:{minute}", "requests", ok + fail)
    r.hincrby(f"crawl:stats:{minute}", "fails", fail)
    r.hincrby(f"crawl:stats:{minute}", "parsed", parsed)
    r.set("crawl:heartbeat", time.time())     # 心跳——监控进程检查这个 key
```

**指标心智**：**"四个指标的读法：'变化'比'绝对值'重要——速率 100→0 是故障，速率 100→80 是目标站变慢"**——**"指标之间的关联诊断："速率降 + 失败率升 = 被反爬了；速率降 + 队列积压升 = 解析/存储慢了；速率正常 + 完整率降 = 反爬假页（07 篇）"**——**"指标组合诊断 = 爬虫排障的方法论——单个指标只会报警，组合指标才给方向"**（"排障的套路：先看哪两个指标一起变——**'变化的方向组合就是病因'"**）；**心跳机制**——"爬虫定期写心跳（`set heartbeat time`）——监控进程检查心跳是否新鲜（超过 5 分钟没更新 = 挂了）——**'心跳 = 最便宜的活着检测——监控的心跳、爬虫的呼吸'"**。

## 3. 告警体系

**告警 = 监控发现异常时的"喊人"——分级 + 渠道 + 防打扰**：

```text
告警分级（按严重程度）
├── P0 致命：爬虫全挂/数据全断——立即告警（电话/短信/紧急群@）
├── P1 严重：速率降 50%+/失败率突增——告警（即时通知）
├── P2 一般：单个站点失败/质量轻微下降——汇总告警（日报）
└── P3 提示：容量趋势/慢查询——不告警（进面板看）
    ——"分级的价值：'P0 响铃，P3 静默'——告警疲劳（狼来了）是告警最大的敌人"
```

```python
# 告警脚本（阈值 + 防打扰——07 篇质量监控的告警版）
def check_and_alert():
    stats = load_minute_stats()
    fail_rate = stats["fails"] / max(stats["requests"], 1)

    if stats["requests"] == 0:                       # 速率归零 = 挂了
        send_alert("P0", "爬虫速率归零——进程可能已挂！")
    elif fail_rate > 0.3:                            # 失败率 > 30%
        send_alert("P1", f"失败率异常 {fail_rate:.0%}——疑似反爬或改版")
    # 防打扰：同类型告警 30 分钟内只发一次
    if not r.get(f"alert:suppress:{alert_type}"):
        r.setex(f"alert:suppress:{alert_type}", 1800, "1")   # 30 分钟抑制
        send_alert(...)
```

**告警心智**：**"告警三纪律：分级（P0 响铃 P3 静默）、阈值（有依据——压测报告 06 篇定基线）、防打扰（同告警 30 分钟一次——'告警疲劳 = 告警失效'）"**——**"告警阈值从哪来：压测报告（06 篇——安全线）+ 历史数据（正常波动范围）——'阈值不是拍脑袋，是基线 + 余量'"**（"阈值太紧天天报（狼来了）、太松出事没人知道（纸包火）——**'阈值的校准 = 告警体系的日常维护'"**）；**告警的通知渠道**——"企微/钉钉/飞书机器人（2026 国内标配）+ 电话（P0）——**'渠道按级别配：P0 电话（吵醒人），P1 消息（看一眼），P2 日报（汇总）'"**；**告警的处置闭环**——"告警 → 处置（修复）→ 复盘（为什么挂）→ 改进（监控补漏）——**'告警不是终点，是问题的开始——每个告警都要追到根因'"**（"告警记录 = 爬虫故障史——'每周复盘告警，就是爬虫健康度的周报'"）。

## 4. 故障自愈

**故障自愈 = 让爬虫"挂了能自己爬起来"——运维的最高追求**：

```text
自愈三件套
├── ① 看门狗（Watchdog）：监控进程发现爬虫心跳过期 → 自动重启
│    （systemd 的 Restart=always / 自研 watchdog 脚本）
├── ② 任务恢复：重启后从队列续爬（05 篇——队列是天然断点）
└── ③ 降级策略：某目标站挂了 → 自动跳过（换源/降频/延后）——不拖垮全局
    ——"自愈的目标：'常见故障无人值守'——人只处理'自愈不了的'"
```

```python
# 看门狗脚本（简化——systemd/任务计划替代方案）
import time, subprocess, redis

r = redis.Redis(host="redis-host", decode_responses=True)

while True:
    heartbeat = float(r.get("crawl:heartbeat") or 0)
    if time.time() - heartbeat > 300:              # 心跳 5 分钟没更新
        print("爬虫心跳过期——重启进程")
        subprocess.Popen(["python", "crawler.py"])  # 重新拉起
        time.sleep(60)                              # 重启后等 1 分钟再查
    time.sleep(30)
```

**自愈心智**：**"自愈的设计原则：'能自动处理的别麻烦人'——重启/续爬/降级三件事自动做"**——**"自愈的边界：'自愈 80% 的常见故障，20% 的疑难留给人'——自动重启 3 次还挂 = 停止自愈（防止无限重启循环）转人工——'自愈不是让故障消失，是把故障处理时间从小时级降到分钟级'"**（"无限重启循环 = 最隐蔽的自愈事故——'重启上限：3 次，超了报警等人'"）；**自愈的幂等**——"重启后的爬虫不能重复入库（去重体系——07 篇五道闸兜底）——**'自愈的前提是'重跑安全'——不幂等的系统不能随便重启'"**（"先做幂等（去重+断点），再谈自愈——顺序不能反"）；**自愈的演练**——"定期演练'kill 爬虫进程'——看它能不能自己爬起来——**'没演练过的自愈 = 纸面自愈——演练是自愈的验收'"**（"自愈演练 = 运维的消防演习——每月一次"）。

## 5. 监控面板与复盘

**监控面板 = 监控数据的可视化 + 定期复盘机制**：

```text
监控面板（Grafana 自建 / Redis+自绘 / 商用监控）
├── 实时视图：速率曲线/队列积压/失败率（当前状态一眼看）
├── 历史视图：24h/7d 趋势（对比——"今天比昨天快/慢"）
├── 质量视图：完整率/去重率趋势（07 篇指标）
└── 告警记录：历史告警列表（复盘素材）
    ——"面板是'看'，复盘是'想'——看是日常，想是每周"
```

**面板心智**：**"面板的设计：'打开 10 秒能判断爬虫健康吗'——四个指标画四个图，趋势一眼可见"**——**"面板不是装饰——是'决策仪表盘'（今天该不该干预）——'没面板的监控 = 有数据没眼睛'"**（数据分析阶段 5 方向 C 07 篇指标平台思想的爬虫版——"爬虫的指标也要'单一事实来源'——所有机器上报同一套指标"）；**复盘的机制**——"每周爬虫复盘：本周告警清单 → 根因分类（反爬/改版/网络/代码 bug）→ 改进项（监控补漏/代码修复/阈值校准）——**'复盘 = 把故障变成经验——每次故障都让系统更强'"**（"故障不可怕，重复故障才可怕——'复盘记录 = 爬虫团队的成长日记'"）；**监控的演进**——"随着爬虫规模扩大：指标越来越多（各站点单独监控）→ 告警规则越来越细（站点级/时间级）——**'监控体系跟着爬虫系统一起长大——先 4 个指标，再 40 个'"**（本课的 4 指标是起点不是终点）。
