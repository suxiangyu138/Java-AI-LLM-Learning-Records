## 1. 毕业项目：大型爬虫采集系统

**毕业项目 = 一个"生产级"的爬虫系统**（综合本阶段全部九课 + 阶段 1-6 技能）：

```text
毕业项目要求（"新闻采集系统"或自选题）
├── 目标：10 个以上数据源、每日增量、百万级数据量
├── 架构：Scrapy 框架 + Scrapy-Redis 分布式（阶段 6 + 05 篇）
├── 对抗：curl_cffi TLS 指纹 + 频率纪律 + 代理池（02 篇——按目标强度分层）
├── 质量：内容指纹去重 + 校验四件套 + 质量报告（07 篇）
├── 监控：心跳 + 四指标 + 告警 + 看门狗自愈（08 篇）
├── 存储：MySQL/MongoDB（阶段 3）+ 增量更新
└── AI 增强：Jina/Scrapling 分级路由提取 + LLM 提取一个环节（09 篇）
```

**毕业验收标准（模拟"上线评审"）**：

```markdown
# 毕业评审自检
- [ ] 合规评估：三个自问（该拿吗/合法吗/正当吗）书面过一遍（01 篇）
- [ ] 稳定性：连续 3 天无人值守运行（数据每日更新不中断）
- [ ] 数据质量：质量报告四指标达标（去重率/完整率/覆盖率/时效性）
- [ ] 监控在线：面板 4 图 + 告警能响 + kill 后能自愈（演练过）
- [ ] 分布式：多进程/多机不重复（去重体系验证——05/07 篇）
- [ ] 性能：压测报告（安全线）+ 运行速率记录（06 篇）
- [ ] AI 环节：分级路由 + LLM 提取跑通（含成本估算——09 篇）
- [ ] 文档：架构图 + 运行手册 + 质量报告（数据契约——01 篇）
```

**毕业项目心智**：**"毕业项目 = 你面试时'能讲 10 分钟'的采集系统"**——**"面试官不问'爬了多少'，问'怎么保证不重复、挂了怎么办、数据质量怎么验'"**——本项目的每个环节都要经得起追问（"3 天稳定运行"是硬指标——"验收的不是'能爬'，是'能一直爬、爬得准'"）；**选题建议**——"真实数据源优先（公开资讯/商品/公告——合规范围内）——**'真实目标才有真实的对抗与质量问题'"**；**规模的平衡**——"系统完整 > 规模宏大（方向 B 10 篇纪律延续）——**'爬虫课程的毕业设计，是'做专业'不是'做最大'"**。

## 3. 报错速查 10 条

| 报错/现象 | 原因 | 解法 |
|---------|------|------|
| 换 UA 还被拦 | TLS 指纹暴露（requests 原罪） | curl_cffi `impersonate="chrome"`（02 篇） |
| 验证码突然频繁 | 行为/IP 信号已被标记 | 修行为 + 换代理（03 篇——打码是治标） |
| mitmproxy 抓不到 HTTPS | 证书没装/App 有 Pinning | 装证书 + 信任设置；Pinning 用 frida（04 篇） |
| 抓包看到但接口调不通 | UA/Header 不像 App | 补 App UA + 设备 Header（04 篇复刻三要素） |
| Redis 队列暴涨 | 解析/存储慢了 | 查解析吞吐 + 存储批量（06 篇） |
| 布隆误判漏爬 | 容量/误判率设置 | `error_rate` 调小（容量要估准——05 篇） |
| 爬虫挂了没发现 | 没心跳/没监控 | 心跳 + 看门狗（08 篇） |
| 完整率突降 | 反爬假页/解析 bug | 查丢弃原因分布（07 篇——短内容阈值） |
| Jina 返回 403 | 免费额度/公众号 | 路由到 Scrapling（09 篇分级路由） |
| LLM 提取出幻觉字段 | 提示词没约束 | "缺失填 null + 不许编造"（09 篇） |

**报错心智**：**"进阶报错的规律：'问题在更底层'——被拦先查 TLS/行为（不是 UA）、挂了先查监控（不是代码）——**'报错往下挖一层，才是根因'"**——把新坑写进自己的速查表。

## 4. 5 个扩展任务

1. **对抗实战**：对一个真实反爬站做分层对抗（从 requests → curl_cffi → Playwright 拟人逐层升级，记录每层结果——02 篇）
2. **App 实战**：抓包一个无害 App 并复刻接口（合规评估先行——04 篇）
3. **分布式扩容**：把毕业项目扩成 3 节点分布式（队列/去重/监控全 Redis——05 篇）
4. **质量深化**：给毕业项目加内容指纹去重 + 增量更新（07 篇）
5. **AI 采集管线**：把毕业项目的解析层换成"分级路由 + LLM 提取"并对比成本与容错（09 篇）

## 5. 面试演练

**爬虫工程师面试（本阶段特有）**：

**Q1：讲讲你的爬虫系统架构？**——答：**"我的采集系统：Scrapy + Scrapy-Redis 分布式（Redis 队列 + 布隆去重——1000 万 URL 约 20MB）；对抗层按目标强度分层（普通站 curl_cffi TLS 指纹模拟，强反爬 Playwright 行为拟人 + 住宅代理）；质量层内容指纹去重 + 校验四件套（完整率 95%+）；运维层心跳 + 四指标监控 + 看门狗自愈（kill 后 5 分钟内自恢复，3 天无人值守稳定运行）；AI 层 Jina/Scrapling 分级路由提取——合规上先过三个自问（该拿吗/合法吗/正当吗）"**——结构：**架构分层 → 对抗策略 → 质量 → 运维 → AI → 合规**——"答出'分层 + 数字 + 合规'是高级爬虫工程师的回答"。

**Q2：目标站突然开始反爬（验证码/封 IP），你怎么排查？**——答：**"三步：① 看监控四指标（速率降 + 失败率升 = 被反爬了——先确认不是代码 bug）；② 定位信号（看返回是验证码还是 429——验证码 = 会话被标记（03 篇：先修行为再打码），429 = 频率/IP 问题（降速 + 换代理））；③ 分级应对（先降速到安全线观察——压测报告的基线（06 篇）——再按层升级（curl_cffi → 拟人 → 托管）——同时评估'值不值得'（01 篇止损线：三层都失败就换源/买数据）——全程记录对抗日志，同类站点下次直接跳到正确层"**——结构：**监控确认 → 信号定位 → 分级应对 → 止损评估**——"答出'先看监控再动手 + 止损线'是工程素养"。

**Q3：爬虫数据质量和稳定性怎么保证？**——答：**"质量四道闸：① 内容指纹去重（同内容不同 URL 不重复入库）；② 校验四件套（完整性/类型/值域/长度——丢弃留痕，原因分布是改进方向）；③ 数据库唯一键兜底；④ 定期全库清扫——交付附质量报告（去重率/完整率/覆盖率/时效性）。稳定性：心跳 + 四指标监控 + 分级告警（P0 电话） + 看门狗自愈（3 次上限转人工）+ 每周故障复盘（把故障变成经验）——先做幂等（去重+断点）再谈自愈"**——结构：**质量四道闸 → 报告 → 稳定性三件套 → 复盘**——"答出'先幂等再自愈'是踩过坑的证明"。
