## 1. 数据质量：爬虫的信用

**爬虫的交付标准 = 数据质量**（01 篇数据契约的落地）——质量四维：

```text
爬虫数据质量四维
├── 完整性：该抓的字段抓全了吗？（缺字段 = 下游分析缺原料）
├── 准确性：抓的值对吗？（截断/编码/错位——解析 bug 的重灾区）
├── 一致性：格式统一吗？（日期格式/单位/编码——阶段 3 清洗的源头）
└── 时效性：数据新鲜吗？（更新频率——周期爬虫的承诺）
    ——"爬虫是数据链路的起点——起点的质量决定下游的一切（01 篇）"
```

**质量心智**：**"质量问题的代价：下游分析师/模型用脏数据 → 结论错 → 追溯发现是采集端——'爬虫工程师的信用 = 数据质量的稳定性'"**（"一次脏数据事故，十次准时交付都补不回信任"）；**质量的责任分工**——"采集端管'抓得全不全、格式对不对'，清洗端管'缺失/异常'（数据分析阶段 2 清洗课）——**'能在地基解决的别推到楼上去——采集端的质量投入性价比最高'"**（"阶段 3 存储课的清洗是'亡羊补牢'，采集端校验是'未雨绸缪'"）；**质量的验收**（01 篇契约）——"交付时附质量报告（字段完整率/去重率/抽样核对）——**'带质量报告的交付 = 专业的交付'"**（本课第 5 节）。

## 2. 内容指纹去重

**内容指纹去重 = 比 URL 去重更强的去重——"同内容不同 URL"的克星**：

```text
为什么需要指纹去重
├── URL 去重的盲区：翻页参数（?page=2 与 ?page=2#list）、时间戳参数、
│   追踪参数（?utm_source=...）——同一内容 N 个 URL
├── 指纹思路：抓下来的内容算哈希——内容相同 = 指纹相同 = 去重
└── 指纹要素：标题 + 正文关键内容（不是整页——导航/广告会污染）
    ——"URL 是地址，指纹是内容——地址会变，内容认得出来"
```

```python
import hashlib

def content_fingerprint(title: str, body: str) -> str:
    """内容指纹：标题 + 正文前 N 字符 + 长度——抵抗页面噪声"""
    # 归一化（去空白/转小写——"同一文章不同排版"指纹一致）
    text = (title + body[:500]).strip().lower()
    return hashlib.md5(text.encode()).hexdigest()

# 去重判断（配合 Redis——05 篇去重体系）
fp = content_fingerprint(item["title"], item["content"])
if not r.sismember("data:seen_fp", fp):      # 指纹没见过
    r.sadd("data:seen_fp", fp)               # 记录指纹
    save_item(item)                          # 才入库
else:
    log_duplicate(item["url"])               # 重复——丢弃（或更新）
```

**指纹心智**：**"指纹设计三要素：稳定（同一内容指纹相同）、敏感（不同内容指纹不同）、鲁棒（抗页面噪声）"**——**"指纹的工程细节：正文取多少（500 字够）、归一化做什么（空白/大小写——'排版变化不改变指纹'）、用什么哈希（md5 足够——非安全场景）"**（"指纹设计的验证：同文不同 URL 指纹一致？不同文指纹不同？——**'指纹质量用样例验证——10 对测试用例过一遍'"**）；**指纹 vs URL 的配合**——"URL 去重挡'完全相同的 URL'（便宜），指纹去重挡'同内容不同 URL'（贵一点）——**'两层都要：URL 是前置粗筛，指纹是终审'"**（"只做 URL 去重 = 漏网之鱼（翻页参数）；只做指纹 = 每个 URL 都要下载才能算指纹（费流量）——**'先 URL 后指纹的顺序 = 流量与精度的平衡'"**）。

## 3. 多层去重体系

**完整去重体系 = 五道闸（从入口到出口）**：

```text
多层去重五道闸
├── ① 入队前：URL 指纹去重（调度器——05 篇——队列里没重复）
├── ② 下载后：内容指纹去重（本课 2 节——同内容不同 URL）
├── ③ 解析后：业务键去重（唯一键——标题/ID——数据库 UNIQUE——阶段 3）
├── ④ 入库时：数据库约束（PRIMARY KEY/UNIQUE——最后防线——重复插入报错/忽略）
└── ⑤ 定期：全库扫描去重（兜底清洗——历史脏数据的清理）
    ——"五道闸的分工：每道挡一种重复——单一闸门挡不住所有"
```

**体系心智**：**"去重体系的哲学：'每道闸挡一类'——URL 挡地址重复、指纹挡内容重复、唯一键挡业务重复、数据库兜底、定期清扫"**——**"最容易被忽视的是 ③ 业务键去重——'业务上'的重复（同一商品被两个栏目爬到——URL 不同、内容略异——只有业务键（商品 ID）认得出"**（"业务键 = 你领域里'什么是同一条数据'的定义——和数据分析阶段 3 09 篇契约同源"）；**去重的升级策略**——"重复数据的处理：丢弃（最简单）/更新（内容变了要刷新——**'新闻改了正文——指纹变了——更新入库'"**（"去重不是'丢'，是'判断新不新'——指纹变 = 内容更新 = 更新不是丢弃——**'去重系统 = 判重系统 + 更新策略'"**）；**去重的记录**——"去重日志（重复了多少/什么类型）——**'去重率是质量指标（本课 5 节）——去重日志是它的数据源'"**。

## 4. 数据校验

**数据校验 = 入库前的体检——"脏数据不进库"**：

```python
# 校验三件套（管道里执行——Scrapy Item Pipeline）
def validate_item(item):
    """校验 + 修复/丢弃——返回 (item, 状态)"""
    # ① 字段完整性：必填字段缺失 → 丢弃（或标记）
    required = ["title", "url", "date"]
    missing = [f for f in required if not item.get(f)]
    if missing:
        return None, f"missing:{missing}"        # 丢弃并记录原因

    # ② 类型校验：日期/数字格式
    try:
        item["date"] = parse_date(item["date"])   # "2026年8月10日" → datetime
    except ValueError:
        return None, "bad_date"

    # ③ 值域校验：异常值拦截（价格 0/负数/超离谱）
    if item.get("price") and float(item["price"]) < 0:
        return None, "bad_price"

    # ④ 长度校验：正文太短 = 可能是反爬假页面/加载失败
    if len(item.get("content", "")) < 100:
        return None, "short_content"
    return item, "ok"
```

**校验心智**：**"校验的定位：'不让坏数据进入下游'——校验成本远低于清洗/返工成本"**——**"校验四件套：完整性（必填字段）、类型（日期/数字）、值域（价格>0）、长度（内容阈值——'太短 = 反爬页/渲染失败——最常见的假数据来源'"**（"反爬假页面的识别：内容 50 字 + 全是验证码提示——**'内容长度阈值是反爬假页的第一探测器'"**）；**校验的动作：修 vs 丢**——"能修的修（类型转换——日期格式）、不能修的丢（缺必填字段）+ 记录原因——**'丢弃要留痕——丢弃原因统计 = 下一个优化方向'"**（"丢弃 30% 都是'内容太短' → 查是不是渲染失败/被反爬——**'校验日志是爬虫健康度的镜子'"**）；**校验与清洗的分工**（本课 1 节）——"采集端校验'格式与完整性'，清洗端处理'统计性脏数据'（缺失填补/异常处理——数据分析阶段 2 03 篇）——**'能在地基解决的别推到楼上'"**。

## 5. 质量指标与报告

**质量指标 = 数据质量的"体检报告"（01 篇数据契约的量化版）**：

```text
爬虫质量指标四件套
├── 去重率 = 去重数 / 抓取数（高 = 调度/指纹工作正常；异常高 = 队列重复严重）
├── 完整率 = 通过校验数 / 抓取数（低 = 反爬假页/解析 bug）
├── 覆盖率 = 抓到数 / 目标总数（抽样估——目标站总共有多少条）
└── 时效性 = 数据新鲜度（上次更新距现在多久——周期承诺）
    ——"四个指标 = 质量报告的四章——每次交付附上"
```

```python
# 质量报告生成（交付物）
def quality_report(stats):
    return f"""
# 爬虫质量报告（{stats['date']}）
- 抓取数：{stats['total']}（目标 {stats['target']}）
- 去重率：{stats['dup_rate']:.1%}（URL {stats['dup_url']} + 指纹 {stats['dup_fp']}）
- 完整率：{stats['valid_rate']:.1%}（丢弃原因：{stats['drop_reasons']}）
- 覆盖率：{stats['coverage']:.1%}（目标站总量估算）
- 时效性：最后更新 {stats['last_update']}（承诺每日更新 ✓）
"""
```

**指标心智**：**"质量报告的价值：'让下游放心用'——带指标的交付 = 专业爬虫团队的门面"**——**"指标的解读：完整率 85% 要配丢弃原因分布（30% 短内容 → 反爬假页——下一步修渲染）"**——**"指标不是终点，指标背后的原因才是"**（"质量报告 = 现状 + 原因 + 下一步——和数据分析的报告三段式同构（方向 A 04 篇）"）；**指标的监控化**——"质量指标进监控（08 篇——完整率跌破阈值告警）——**'质量指标不是'交付时看一眼'，是'每天监控着'"**（"质量监控 = 爬虫健康的第二只眼——速率监控看'跑没跑'，质量监控看'跑对没'"）。
