## 1. 去重的四个层级

| 层级 | 手段 | 防什么 | 阶段 |
|------|------|--------|:---:|
| ① 请求前 | URL 集合（内存） | 本会话重复请求 | 阶段 2 |
| ② 入库时 | **数据库唯一键** | 跨会话重复入库 | 本阶段 |
| ③ 内容层 | **内容指纹** | URL 不同内容相同 | 本阶段 |
| ④ 任务层 | 抓取状态机 | 重复抓取/遗漏 | 本阶段 |

```text
为什么需要内容指纹：
  同一文章可能出现在多个 URL（转载/参数不同）：
    /news/1001.html
    /news/1001.html?from=index
    /news/1001.html?from=home
  URL 去重挡不住 → 内容指纹（标题/正文 hash）去重
```

> 🎯 去重体系认知：**"URL 去重防'重复请求'，指纹去重防'重复内容'，状态机防'重复劳动'"**——三层各管一段，生产增量爬虫三层都要。

## 2. 内容指纹：URL 之外的去重

```python
import hashlib

def content_fingerprint(title: str, content: str = "") -> str:
    """内容指纹：标题+正文归一化后 MD5"""
    raw = f"{title}|{content}".strip().lower()     # 归一化（去空格/大小写）
    return hashlib.md5(raw.encode("utf-8")).hexdigest()

# ═══ 指纹去重入库（MySQL）═══
# 表加字段：fingerprint CHAR(32) UNIQUE
cur.execute(
    "INSERT IGNORE INTO news (title, url, content, fingerprint) VALUES (%s, %s, %s, %s)",
    (title, url, content, content_fingerprint(title, content)),
)
# 同一文章（不同 URL）→ 同指纹 → 被 IGNORE

# ═══ 指纹去重（MongoDB）═══
col.create_index("fingerprint", unique=True)
col.update_one(
    {"fingerprint": fp},
    {"$set": {"title": title, "url": url, "content": content}},
    upsert=True,
)
```

| 指纹设计 | 说明 |
|---------|------|
| 指纹内容 | 标题 + 正文（或标题 + 发布时间） |
| 归一化 | 去空白/大小写统一（否则同一文不同指纹） |
| 算法 | MD5/SHA1（32/40 字符，索引友好） |
| 入库 | UNIQUE 约束（MySQL）/ 唯一索引（Mongo） |

> ⚠️ 指纹归一化细节：**"内容一样但格式不同"**（全角/半角、换行位置）会产生不同指纹——清洗先行（阶段 2 §5 的 clean_text）再算指纹，否则指纹形同虚设。

## 3. 增量抓取三策略

| 策略 | 原理 | 适用 | 局限 |
|------|------|------|------|
| **时间增量** | 只抓"最新时间"之后的数据 | 有发布时间的列表 | 依赖时间字段 |
| **ID 增量** | 记录最大 ID，只抓更大的 | 自增 ID 的站点 | 依赖 ID 规律 |
| **状态增量** | 任务状态机（待抓→已抓） | 通用（推荐） | 需任务表 |

```python
# ═══ 策略一：时间增量（新闻站经典）═══
def fetch_incremental_by_time(session, base_url):
    # ① 读上次抓取时间（存文件或数据库）
    last_time = get_last_crawl_time()          # "2026-08-08 10:00:00"
    # ② 只抓发布时间 > last_time 的
    items = []
    for page in range(1, 20):
        resp = session.get(base_url, params={"page": page}, timeout=10)
        page_items = parse_list(resp.text)
        new_items = [it for it in page_items if it["date"] > last_time]
        items.extend(new_items)
        if len(page_items) != len(new_items):   # 出现旧数据 → 到底了
            break
    # ③ 更新上次抓取时间
    save_crawl_time(max(it["date"] for it in items) if items else last_time)
    return items

# ═══ 策略二：ID 增量 ═══
max_id = get_max_id()              # SELECT MAX(id) FROM news
for item in items:
    if item["id"] > max_id:
        save(item)                 # 只存新 ID

# ═══ 策略三：状态增量（最通用，见 §4）═══
```

> 🎯 时间增量细节：**"发现旧数据立即停"**——列表页按时间倒序时，一旦当前页出现 `date <= last_time` 说明后面全是旧的，直接 break（省一半请求，[阶段 2 §6](../阶段%202：静态网页爬虫（入门）/06-翻页与爬取策略.md) 的终止条件升级版）。

## 4. 抓取状态机

```python
# ═══ 任务状态机：待抓 → 抓取中 → 已抓/失败 ═══
# 状态定义：
#   0 = 待抓取（pending）
#   1 = 抓取中（processing，可选）
#   2 = 抓取成功（done）
#   3 = 抓取失败（failed，可重试）

# ① 发现新 URL → 建任务（INSERT IGNORE 天然去重）
cur.executemany(
    "INSERT IGNORE INTO crawl_tasks (url, status) VALUES (%s, 0)",
    [(url,) for url in new_urls],
)

# ② 取任务（待抓的）
cur.execute("SELECT url FROM crawl_tasks WHERE status = 0 LIMIT 100")
tasks = cur.fetchall()

# ③ 抓取 + 更新状态
for task in tasks:
    try:
        data = fetch_and_parse(task["url"])
        save_to_news(data)                        # 数据入库（独立去重）
        cur.execute("UPDATE crawl_tasks SET status = 2 WHERE url = %s", (task["url"],))
    except Exception:
        cur.execute("UPDATE crawl_tasks SET status = 3 WHERE url = %s", (task["url"],))
    conn.commit()

# ④ 失败重试（下一次运行自动捞回）
cur.execute("UPDATE crawl_tasks SET status = 0 WHERE status = 3 AND retry < 3")
```

| 状态机价值 | 说明 |
|-----------|------|
| 断点续抓 | 中断后重跑 → 状态 0 的继续抓 |
| 失败重试 | status=3 → 下次自动捞回 |
| 统计 | 按状态计数（已抓/失败率） |
| 分布式扩展 | 多进程/多机按状态抢任务（阶段 6） |

> 🎯 面试点：**"增量爬虫的核心是任务状态机，不是去重"**——`crawl_tasks` 表（url + status + retry + crawl_time）让"断点续抓、失败重试、并发分配"全部有据可依。这是从"脚本"到"数据管道"的标志性设计。
