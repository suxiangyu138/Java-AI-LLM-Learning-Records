## 4. 阶段定位与核心策略

```text
核心策略（本阶段第一原则）：
  手写 requests 循环 ≠ 爬虫工程！

  ① 前 5 阶段 = 技能零件（请求/解析/存储/反爬/渲染）
  ② 本阶段 = 把这些零件装进 Scrapy 引擎统一调度
  ③ 工程化三件套：并发引擎（省 10 倍时间）+ 管道化（每层可插拔）
     + 中间件（横切面统一治理反爬/代理/重试）

与主体系 04-Scrapy框架实战.md 的分工：
  主体系 = 速查版（一篇文章讲完全部概念）
  本阶段 = 课程执行版（每个组件一章深潜 + 生产级实战，
           并覆盖 2026 年 Scrapy 2.14+ 异步现代化与生态新变化）
```

> 🎯 认知起点：**框架解决的不是"能不能爬到"，而是"爬得快、爬得稳、可维护、可扩展"**——单页脚本写循环，十万页面必须靠框架的调度器、管道与中间件。学框架的正确姿势是**先懂数据流（01 章），再往每个组件里填代码**。

## 5. 核心概念速查

| 概念 | 一句话 |
|------|--------|
| Scrapy | Python 最主流的爬虫框架（2.16.0，2026-05-19 发布） |
| Engine | 引擎，调度所有组件协作的"总指挥" |
| Scheduler | 调度器，管理请求队列 + 去重（DownloaderAwarePriorityQueue 2.14 起默认） |
| Downloader | 下载器，发出 HTTP 请求拿响应 |
| Spider | 爬虫，定义起始请求 + 解析规则 + 提取 Item |
| Item Pipeline | 数据管道，逐层校验/清洗/入库 |
| Middleware | 中间件，横切面拦截请求/响应/Item |
| Selector | 选择器，CSS/XPath 提取数据（基于 parsel） |
| ItemAdapter | 统一 Item 访问接口（dict/Item/dataclass 通吃） |
| meta | 请求上下文参数，跨回调传递数据 |
| CrawlSpider | 自动跟随链接的爬虫（Rule 规则） |
| AutoThrottle | 自动限速，根据响应速度动态调并发 |
| scrapy-playwright | 官方生态动态页方案（0.0.48，浏览器渲染进请求流） |
| scrapy-redis | 分布式方案（0.7.x，已停维护但稳定，替换 Scheduler + 去重） |
| 断点续爬 | 任务持久化，重启后继续（Scheduler 持久化） |
| RFPDupeFilter | 默认去重器，基于请求指纹的 Redis Set（1000 万 URL ≈ 2GB+ 内存） |
| Scrapyd | 爬虫部署守护进程（1.6.0，低活跃维护，轻量单机） |
| StatsCollection | 统计收集器（请求数/错误数/Item 数，运维监控数据源） |
