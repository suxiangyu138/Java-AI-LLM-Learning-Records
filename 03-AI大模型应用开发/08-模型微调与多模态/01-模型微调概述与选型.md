# 01 - 模型微调概述与选型

> 🎯 微调让通用模型适配你的场景 — 但全量微调 70B 需 8×A100，LoRA 微调只需一张 4090。选对方案省 10 倍成本

## 微调 vs RAG vs Prompt 决策

```text
什么时候微调？
  ✅ 需要特定风格/语气（客服语气、法律文书风）
  ✅ 领域术语多且固定（医疗、法律）
  ✅ 需要提升特定任务准确率（分类、提取）
  ✅ 推理延迟敏感（微调后模型本地推理）
  ❌ 知识频繁更新 → RAG 更合适
  ❌ 任务经常变化 → Prompt 更合适
  ❌ 数据量很少(<100条) → Few-Shot Prompt 更合适
```

## 微调方法全景

| 方法 | 修改参数 | 显存(7B) | 显存(70B) | 效果 | 训练速度 |
|------|:---:|:---:|:---:|:---:|:---:|
| **全量微调** | 100% | ~60GB | ~600GB | ⭐⭐⭐⭐⭐ | 慢 |
| **LoRA** | 0.1~1% | ~16GB | ~48GB | ⭐⭐⭐⭐ | 快 |

| **Prompt Tuning** | <0.01% | ~15GB | ~45GB | ⭐⭐ | 快 |

## 选型决策树

```text
有多少数据？
  ├── <100条 → Prompt Engineering / Few-Shot
  ├── 100-1000条 → LoRA/QLoRA 微调
  ├── 1000-10000条 → LoRA 微调(加大 rank)
  └── >10000条 → 全量微调 或 LoRA(r=64+)

有多少显存？
  ├── <8GB → QLoRA(4-bit) + 7B 模型 / 用 API
  ├── 8-24GB → LoRA + 7B 模型 / QLoRA + 13B
  ├── 24-48GB → LoRA + 13B / QLoRA + 70B
  └── >48GB → 全量微调 7B / LoRA + 70B

追求什么？
  ├── 极致效果 → 全量微调（足够数据和显存时）
  ├── 快速实验 → LoRA（r=8, alpha=16）
  └── 消费级硬件 → QLoRA（4-bit + LoRA）
```

## 微调完整流程

```text
① 明确目标：分类/生成/对话？需要什么风格？
② 准备数据：Alpaca/ShareGPT格式，质量>数量
③ 选择基座模型：中文选 Qwen/GLM，英文选 LLaMA/Mistral
④ 选择微调方法：默认 LoRA (r=8)
⑤ 训练：epoch=1~3, lr=2e-4(LoRA) 或 2e-5(全量)
⑥ 评估：验证集 Loss + 人工评测
⑦ 部署：合并权重 / 导出 GGUF
```

## 常见误区

| 误区 | 真相 |
|------|------|
| "数据越多越好" | 质量>数量，1000条高质量 > 10万条噪声 |
| "epoch 越多越好" | 微调 1-3 epoch 足够，多了过拟合 |
| "LoRA 效果不如全量" | r=16 时效果接近全量，差距<3% |
| "微调后模型通用能力会下降" | LoRA 冻结基座，天然抗灾难性遗忘 |
