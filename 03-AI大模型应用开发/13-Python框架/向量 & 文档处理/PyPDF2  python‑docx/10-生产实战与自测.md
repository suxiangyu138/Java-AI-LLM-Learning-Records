## 1. 实战：PDF 批量提取 + Word 报告生成

把全体系知识点压进一个项目：批量提取 PDF → 清洗 → 统计 → 生成 Word 汇总报告。目标是交付一个「输入目录、输出报告」的完整脚本，可重跑、有日志、失败有清单。

```python
import os, re, json
from pypdf import PdfReader
from docx import Document
from docx.shared import Inches
from loguru import logger

SRC, OUT = "pdfs/", "output/"
failures = []

def clean(text: str) -> str:
    lines = [l for l in text.splitlines()
             if not re.match(r"^(第?\s*\d+\s*页?|Page\s+\d+)$", l.strip())]
    return re.sub(r"\n{3,}", "\n\n", "\n".join(lines))

def extract_one(path: str) -> dict | None:
    try:
        reader = PdfReader(path)
        text = "\n".join(clean(p.extract_text() or "") for p in reader.pages)
    except Exception as e:
        failures.append({"file": path, "stage": "extract", "error": repr(e)})
        return None
    if len(text) < 100:
        failures.append({"file": path, "stage": "quality", "error": "text too short"})
        return None
    return {"file": os.path.basename(path), "pages": len(reader.pages),
            "chars": len(text), "text": text}

def build_report(results: list[dict], chart_path: str | None):
    doc = Document()
    doc.add_heading("PDF 批量提取汇总报告", level=0)
    doc.add_paragraph(f"处理文件数：{len(results)}；总字符数：{sum(r['chars'] for r in results)}")
    table = doc.add_table(rows=len(results) + 1, cols=3)
    table.style = "Table Grid"
    for j, h in enumerate(["文件", "页数", "字符数"]):
        table.cell(0, j).text = h
    for i, r in enumerate(results, start=1):
        table.cell(i, 0).text = r["file"]
        table.cell(i, 1).text = str(r["pages"])
        table.cell(i, 2).text = str(r["chars"])
    if chart_path and os.path.exists(chart_path):
        doc.add_picture(chart_path, width=Inches(5))
    doc.save(OUT + "summary.docx")

def main():
    os.makedirs(OUT, exist_ok=True)
    results = []
    for name in sorted(os.listdir(SRC)):
        if not name.lower().endswith(".pdf"):
            continue
        r = extract_one(os.path.join(SRC, name))
        if r:
            results.append(r)
            logger.info("成功 {file}（{pages} 页，{chars} 字）", **r)
    json.dump(results, open(OUT + "extracted.json", "w"), ensure_ascii=False)
    json.dump(failures, open(OUT + "failures.json", "w"), ensure_ascii=False)
    build_report(results, chart_path=None)
    logger.info("完成：成功 {}，失败 {}，报告已生成", len(results), len(failures))

if __name__ == "__main__":
    main()
```

**验收三问**：**提取对吗**——抽查 3 个文件对照原文，`extracted.json` 无乱码无缺页；**失败清楚吗**——`failures.json` 按阶段归类，扫描件/加密/损坏可区分；**交付完整吗**——Word 报告 + JSON 数据 + 失败清单三件套齐，重跑幂等（删 output 重跑结果一致）。

**常见失败模式与排查顺序**：脚本报错——先看**路径问题**（工作目录与脚本目录不一致是头号原因，`os.path.abspath` 打出来确认）；再看**编码问题**（Windows 下文件名/内容 GBK，`open(..., encoding="utf-8")` 统一声明）；再看**版本问题**（PyPDF2 残留 import、pypdf 版本太老 API 不对）。提取结果异常——按 03 篇五问（扫描件→加密→字体→源头→轮廓）逐层排查，先判「是不是文件本身没文本层」再怀疑代码。**排查的第一原则是先环境后代码**：文档处理的报错一半以上是环境（编码、路径、版本）而非逻辑——日志打全路径与版本号，报错时先读日志头尾，别一上来改业务逻辑。

## 2. 生产配置模板与纪律清单

**版本**：`pypdf==6.15.0`、`python-docx==1.2.0` 锁死；升级看 CHANGELOG。**路径**：源/输出目录分离，输出先 `makedirs(exist_ok=True)`。**异常**：单文件 try/except 隔离 + 失败清单按阶段归类。**质量**：清洗纯函数 + 空提取阈值判扫描件 + 抽样人工复核。**日志**：loguru 进度/失败/耗时三指标，rotation + retention。**安全**：PDF 密码不硬编码；`PdfReader` 只读安全（不执行内容）；不做 `eval` 类动态执行。**合规**：文档处理的版权边界——仅处理有权限的文档，OCR 与提取不豁免版权。

## 3. 报错速查十条

| 报错 | 含义 | 处理 |
|------|------|------|
| `FileNotFoundError` | 路径不存在 | 查相对路径基准（脚本工作目录） |
| `PdfReadError` | PDF 损坏/非 PDF | 判文件头 `%PDF`，损坏源替换 |
| 提取返回空/None | 扫描件/加密/无文本层 | 03 篇五问排查 |
| `is_encrypted` 后访问 pages 报错 | 未解密访问 | `PdfReader(path, password=...)` |
| 中文乱码 | 字体编码/输入编码 | 换引擎或查源头（03 篇） |
| `KeyError` 字段名 | 表单字段名不匹配 | `get_fields()` 打印键名核对 |
| 中文字体不生效 | 只设西文字体 | `w:eastAsia` 一并设置 |
| `KeyError: "Heding 1"` | 样式名拼错 | 内置样式名照文档抄 |
| docx 打开报错 | 文件非 docx/损坏 | 查 ZIP 头 `PK`，用 Word 修复 |
| 内存暴涨 | 大文件全量 join | 生成器逐页处理 |

## 4. 面试三范式

**价值式**：「我搭的文档处理管道把 5000 份 PDF 合同提取入库——批量提取 + 清洗 + 失败分类，扫描件自动转 OCR，每天增量处理 200 份，检索命中率提升 30%。」——先讲规模与收益，再讲手段。

**技术式**：「PDF 是排版格式不是数据格式，extract_text 是字形还原，质量取决于来源；扫描件无文本层必须 OCR（300dpi + chi_sim）；python-docx 三层对象模型，run 是格式最小单位，样式是模板化写作核心。」——原理要讲到「为什么」，别停在「能用」。

**生产式**：「批量管道三纪律——纯函数单文件、产出检查续跑、失败隔离归类；版本锁死（PyPDF2 已死，pypdf 6.15.0）；RAG 衔接五步管道带溯源；多格式生产 ETL 交给 unstructured。」——版本意识、可重跑、分工边界三点是区分度。

**追问四连**：PyPDF2 为什么不用？（2024 停止维护、3.12+ 静默失败、未打补丁 CVE）｜提取乱码怎么排查？（五问：扫描件→加密→字体→源头→轮廓）｜RAG 里表格怎么处理？（pdfplumber 行列 / unstructured text_as_html）｜批量 5000 份怎么保证质量？（失败分类 + 质量评估 + 抽查复核）。
