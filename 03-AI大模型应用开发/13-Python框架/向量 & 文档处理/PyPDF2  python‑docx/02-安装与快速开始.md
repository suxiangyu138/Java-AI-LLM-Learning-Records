## 1. 安装与版本锁定

两个库都是纯 Python（pypdf 无系统依赖，python-docx 依赖 lxml），安装零编译、零系统库：

```bash
pip install "pypdf==6.15.0" "python-docx==1.2.0"
```

**版本纪律**：pypdf 快速迭代（2026 年已 6.15），锁版本避免行为漂移；python-docx 稳定（1.2.0 一年未动），锁版本保证可复现。**迁移纪律**：如果环境里残留 PyPDF2，先卸载——`pip uninstall PyPDF2`，否则两个包共存时 `import PyPDF2` 与 `import pypdf` 指向不同代码，排查混乱。

验证安装：

```bash
python -c "import pypdf; print(pypdf.__version__)"          # 6.15.0
python -c "import docx; print(docx.__version__)"            # 1.2.0
```

注意导入名：pypdf 导入 `pypdf`，python-docx 导入 **`docx`**（不是 `python_docx`）——第二个坑最常见。

**测试样本怎么来**：学习阶段需要 PDF 样例——三个来源：**自己生成**（Word/WPS 另存为 PDF——最可控，知道原文长什么样，提取对错一眼判定）；**python-docx 造**（`doc.add_paragraph("测试文本")` 存 docx 再转 PDF，或直接拿 docx 测 python-docx 读取）；**公开样例**（政府公告、论文预印本——注意用有权限处理的文档）。**别用扫描件当第一个测试对象**——提取必然为空，会把「环境坏了」和「文件没文本层」混为一谈。先文本型 PDF 跑通，再逐步加复杂版式（多栏、表格）、加密件、扫描件。

## 2. 第一个 PDF 读取

pypdf 读取的最小路径——三步：`PdfReader` 打开 → `len(reader.pages)` 数页 → `extract_text()` 提取：

```python
from pypdf import PdfReader

reader = PdfReader("report.pdf")            # 打开（懒加载，不一次性读入）
print(f"共 {len(reader.pages)} 页")          # 页数
page = reader.pages[0]                      # 第 1 页（0 索引）
text = page.extract_text()                  # 提取文本
print(text[:200])
```

三个要点：**`reader.pages` 是页对象集合**，支持索引与切片（`reader.pages[1:3]` 取 2-3 页）；**extract_text 是逐页方法**，整本提取要循环拼接；**元数据一并可读**——`reader.metadata` 给出标题、作者、创建时间（05 篇详解）。注意：提取结果可能包含多余空白与错误断行——这是 PDF 文本层的常态，08 篇讲清洗。

## 3. 第一个 PDF 写出

pypdf 的写出方向是「编辑」而非「创建」——它不能从零画文本，但能合并、拆分、旋转、加密现有页面：

```python
from pypdf import PdfReader, PdfWriter

writer = PdfWriter()
for path in ["a.pdf", "b.pdf"]:             # 合并：把两个 PDF 的页加进来
    reader = PdfReader(path)
    for page in reader.pages:
        writer.add_page(page)
writer.encrypt("password123")               # 顺手加密（字符串密码）
with open("merged.pdf", "wb") as f:
    writer.write(f)
```

`PdfWriter` 的用法统一是「add 页 → 配置 → write 到文件对象」。从零生成 PDF（画文字、画图形）不是 pypdf 的定位——那是 ReportLab 的领域（09 篇选型）。「PDF 不能从零创建」是本体系第一课：**pypdf 是 PDF 的编辑器，不是创作器**。

## 4. 第一个 Word 文档

python-docx 的最小路径——`Document()` 新建 → `add_heading`/`add_paragraph` → `save`：

```python
from docx import Document

doc = Document()                            # 新建空白文档
doc.add_heading("月度报告", level=0)         # 标题（level 0 = 文档大标题）
doc.add_heading("一、销售概况", level=1)      # 一级标题
p = doc.add_paragraph("本月销售额")
p.add_run("1234 万元").bold = True          # run：加粗文本片段
doc.add_paragraph("较上月增长 12%。")        # 普通段落
doc.save("report.docx")                     # 保存
```

**对象模型三层**：`Document`（文档）→ `Paragraph`（段落）→ `Run`（文本片段）。段落是排版单位，run 是格式单位——「一句话里部分加粗」就要拆成两个 run（06 篇详解）。`Document(path)` 打开已有文件继续编辑，也是同一套 API。

## 5. 双库闭环

把两库串起来的完整场景：读 PDF 提取内容 → 生成 Word 报告。这是文档处理最典型的工作流：

```python
from pypdf import PdfReader
from docx import Document

# 读：PDF 提取
reader = PdfReader("incoming.pdf")
content = "\n".join(p.extract_text() or "" for p in reader.pages)

# 写：Word 报告
doc = Document()
doc.add_heading("PDF 内容摘要", level=0)
doc.add_paragraph(f"来源：incoming.pdf（{len(reader.pages)} 页）")
for para in content.splitlines()[:10]:      # 前 10 行入报告
    doc.add_paragraph(para)
doc.save("summary.docx")
```

这个闭环就是「数据进来、结果出去」的最小形态——日常文档自动化、RAG 预处理的雏形都在里面。

**双库的学习顺序建议**：先学 pypdf（PDF 读取简单直接——reader → pages → extract_text 三步），再学 python-docx（对象模型略抽象——Document → Paragraph → Run 三层）。两个库不互相依赖，也可以按项目需求只学一边；但**「读 PDF + 写 docx」的组合能力**才是文档自动化最常用的完整形态（读进数据 → 处理 → 产出报告），建议两边都过一遍再决定深耕哪侧。

## 6. 常见坑

**坑一：import docx 失败但装了 python-docx**。导入名是 `docx`，不是 `python_docx`——装的是 python-docx，导入的是 docx。

**坑二：PyPDF2 残留**。环境里 PyPDF2 与 pypdf 共存，老代码 import 到死库——先 `pip uninstall PyPDF2`。

**坑三：extract_text 返回空**。三种可能：扫描件（无文本层）、加密 PDF（未解密）、字体编码特殊——03 篇逐一排查。

**坑四：writer.write 忘写文件对象**。`write("merged.pdf")` 传字符串报错——必须 `open(path, "wb")` 的文件对象。

**坑五：docx 保存覆盖原文件**。`Document("a.docx")` 编辑后 `save("a.docx")` 直接覆盖——要保留原稿先 `save` 到新路径。

**坑六：中文文档样式不对**。python-docx 新建文档默认模板无中文字体设置——中文段落设置字体见 06 篇，直接生成的文档在 Word 里可能显示默认字体。

**坑七：lxml 版本冲突**。python-docx 依赖 lxml，与别的库锁了不同版本——用 venv 隔离，别硬解。

**坑八：把 pypdf 当创建器**。想从零画 PDF 用 pypdf 寸步难行——创建型任务换 ReportLab（09 篇）。

**坑九：extract_text 报错直接怀疑库**。`PdfReadError`/`PdfStreamError` 大多是文件问题（损坏、非 PDF、加密）——先判文件头（`open(path, 'rb').read(5) == b'%PDF-'`）再怀疑代码。

**坑十：docx 与 PDF 混用 API**。`docx.Document("file.pdf")` 必然报错——docx 只吃 .docx，PDF 只吃 pypdf/pdfplumber；两库的「文档」是两个物种。

**坑十一：测试样本质量太差**。拿扫描件/损坏文件当第一个样例——提取失败分不清是环境还是文件——先文本型 PDF 跑通（「测试样本怎么来」一节）。

**坑十二：路径用相对路径裸写**。脚本在不同目录运行行为不同——`Path(__file__).parent` 锚定脚本目录，输入输出路径显式拼。

**坑十三：`writer.write` 与 `writer.close` 混用**。pypdf 2.x 起 write 后自动关闭 writer——重复 close 报错，正常流程一个 write 即可（老教程的 close 调用在新版会抛错）。

**坑十四：docx 保存中文文件名乱码**。Windows 控制台编码问题（脚本正常）——`doc.save("报告.docx")` 在 PowerShell 里正常，乱码先查终端编码（`chcp 65001`），代码层统一 UTF-8 即可。

**坑十五：循环里 save 同名**。生成多份文档只存了最后一份——文件名带序号或业务键（`f"{name}_report.docx"`）。

**坑十六：docx 默认模板无中文字体**。`Document()` 新建的默认样式西文优先——中文内容直接存出来在 Word 里字体可能不对（06 篇 eastAsia 双设置解决）。

**坑十七：读 PDF 时编码声明缺失**。`open("file.pdf", "rb")` 传二进制没问题，但文件名含中文时 Windows 上可能乱码——路径统一 `Path` 对象 + UTF-8 字符串。
