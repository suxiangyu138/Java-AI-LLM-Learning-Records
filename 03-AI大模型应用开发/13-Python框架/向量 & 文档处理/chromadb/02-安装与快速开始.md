## 1. 安装与验证

```bash
pip install chromadb==1.5.9   # 2026-08 基线，必须锁版本
```

依赖说明：Chroma 自带默认嵌入模型（all-MiniLM-L6-v2 的 ONNX 版），首次使用会自动下载模型文件；若用 OpenAI 嵌入需另装 `openai`；官方镜像 `chromadb/chroma` 用于服务器模式（09 篇）。

```python
import chromadb
print(chromadb.__version__)          # 1.5.9
client = chromadb.EphemeralClient()  # 验证能创建客户端即安装成功
```

**锁版本的理由**：1.5.x 约两周一个小版本，且 1.x 存在破坏性变更——"教程里写的 API 可能是 1.3 的，锁住版本才锁住行为"。

## 2. 三种客户端形态

| 客户端 | 数据去向 | 适用场景 | 关键约束 |
|--------|---------|---------|---------|
| `EphemeralClient()` | 纯内存 | 测试/Notebook | 进程退出数据全丢 |
| `PersistentClient(path)` | 本地 SQLite 落盘 | 单进程应用 | **数据目录独占锁，多进程会损坏索引** |
| `HttpClient(host, port)` | 远程服务器（官方镜像） | 多进程/Web 服务/生产 | 服务器需先部署，可配鉴权 |

**选型口诀**：**"写脚本用 Ephemeral，单进程应用用 Persistent，Web 服务/生产用 Http"**。最常踩的坑是"FastAPI 里每个 worker 各开一个 PersistentClient 指向同一路径"——SQLite 独占锁意味着**两个进程指向同路径轻则读脏数据、重则索引损坏**；多进程场景必须 `docker run chromadb/chroma` 起服务器，客户端全走 `HttpClient`（09 篇部署）。

**一个客户端 = 一个库**：客户端对象可以管理任意多个 Collection——"库管库，Collection 管集合"。服务器模式体验同样快：`docker run -d -p 8000:8000 -v /data/chroma:/data chromadb/chroma:1.5.9` 一行起服务，客户端换成 `chromadb.HttpClient(host="localhost", port=8000)` 即可——**"三种客户端切换只换一行创建代码，Collection 操作完全一致"**（09 篇部署细节）。

**查看与修改集合配置**：`client.list_collections()` 列出全部集合；`collection.name`、`collection.metadata` 查看集合配置（距离度量等）；查询候选队列 `hnsw:ef_search` 是少数**创建后可改**的参数——`collection.modify(metadata={"hnsw:ef_search": 100})`——"检索不准时第一个旋钮"（07 篇）。删除集合用 `client.delete_collection(name)`——**不可恢复，先备份再删**（05 篇）。

## 3. Collection：建集合五要素

```python
collection = client.get_or_create_collection(
    name="products",                 # ① 集合名，库内唯一
    metadata={"hnsw:space": "cosine"},  # ② 配置：距离度量（默认 l2，07 篇详讲）
    embedding_function=None,         # ③ 嵌入函数：None = 默认 ONNX miniLM（04 篇）
)
```

集合创建后可配置项：`hnsw:space`（距离度量）、`hnsw:construction_ef`（建索引候选数）、`hnsw:M`（节点连接数）、`hnsw:ef_search`（查询候选数，可后改）——**注意：space 与 M 创建后不可变**，改度量只能克隆集合（07 篇）。

**五要素一行入库**：

```python
collection.add(
    ids=["p1", "p2"],
    documents=["无线机械键盘", "有线静音鼠标"],   # 原文，嵌入函数自动向量化
    metadatas=[{"price": 299, "tag": "键盘"}, {"price": 89, "tag": "鼠标"}],
    # embeddings=...  # 传了 embeddings 就跳过嵌入函数（自定义向量）
)
```

`add` 的规则：**`ids` 必填且唯一**（重复会报错，改 `upsert`）；`documents` 与 `embeddings` 至少给一个——**给了 documents 用嵌入函数算，给了 embeddings 直接用**（05 篇全解）。

**查询就是一行**：

```python
results = collection.query(
    query_texts=["机械键盘推荐"],   # 查询文本，自动走同一嵌入函数
    n_results=2,                    # 返回条数
    where={"tag": "键盘"},           # 元数据过滤（可选）
)
print(results["ids"], results["documents"], results["distances"])
```

**对齐直觉**：`query` 返回的 `distances` 越小越相似（l2/cosine 距离语义，07 篇讲透）。

## 4. 第一个完整示例

```python
import chromadb

client = chromadb.PersistentClient(path="./chroma_db")
collection = client.get_or_create_collection(
    name="kb", metadata={"hnsw:space": "cosine"})

# 入库三条知识
collection.upsert(
    ids=["k1", "k2", "k3"],
    documents=["MySQL 的 InnoDB 使用 B+ 树索引",
               "Redis 是内存型键值数据库",
               "Kafka 是分布式消息队列"],
    metadatas=[{"topic": "数据库"}, {"topic": "缓存"}, {"topic": "消息"}],
)

# 检索：只取"数据库"主题下最相似的
res = collection.query(
    query_texts=["什么数据库用 B+ 树？"],
    n_results=2,
    where={"topic": "数据库"},
)
print(res["documents"])   # [['MySQL 的 InnoDB 使用 B+ 树索引']]
print(res["distances"])   # [[0.47]]  越小越相似
```

**这个例子的意义**：入库（upsert）与检索（query）全部走同一嵌入函数、同一距离度量——**"嵌入一致性是 Chroma 自动保证的，你不用管"**；`where` 过滤在向量检索前生效，缩小候选集。

## 5. 快速调试三步

**第一步：全量看数据**——`collection.get()` 不带参数返回全部记录（含文档与元数据），确认入库内容与期望一致：

```python
all_data = collection.get(include=["documents", "metadatas"])
print(len(all_data["ids"]))   # 3，确认条数
```

**第二步：看类型分布**——`collection.count()` 快速数数；`get(ids=[...])` 按 ID 抽查单条——"入库了没有、对不对，先 get 后 query"。

**第三步：专项验证**——怀疑过滤语法时，`get(where={"topic": "数据库"})` 单独验证过滤条件本身是否命中（不掺向量排序的干扰）——**"过滤问题先用 get 隔离验证，再回 query 看组合效果"**。

## 6. 常见坑

1. **重复 id 直接 `add` 报错**（unique constraint）——重复写入用 `upsert`（覆盖语义）。
2. **PersistentClient 多进程共用路径**——独占锁 + 索引损坏风险，Web 服务必须 HttpClient。
3. **默认度量是 l2 不是 cosine**——文本检索结果会"跑偏"，建集合时显式配 `hnsw:space: cosine`。
4. **metadata 值类型混用**——同字段"一会字符串一会数字"在 1.x 会写入报错（03 篇 schema 强制）。
5. **query 忘写 n_results**——默认返回 10 条；写超大值（如 10000）做"全量相似排序"不是好姿势，用 `get` + 过滤。
6. **模型文件首次下载慢/失败**——默认 ONNX 模型首次使用需下载，离线环境要预下载或换嵌入函数（04 篇）。
7. **`client.list_collections()` 名字拿错**——集合名大小写敏感、库内唯一，`get_or_create_collection` 是幂等姿势（存在即复用）。
8. **`delete_collection` 手一抖**——删除不可恢复且**不弹确认**；删除前先 `list_collections` 确认名字，生产环境删除操作走脚本留痕。
9. **重连后集合"不认识"了**——集合配置（嵌入函数/度量）存在集合元数据里，但**自定义嵌入函数未注册持久化**时，重连要重新传参（04 篇注册机制）；快速开始阶段用默认嵌入函数最省心。
