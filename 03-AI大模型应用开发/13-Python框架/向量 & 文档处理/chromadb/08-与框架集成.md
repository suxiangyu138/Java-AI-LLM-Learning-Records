## 1. 为什么框架都封装 Chroma

LangChain 与 LlamaIndex 都内置 Chroma 的官方集成件——原因是 **Chroma 是 Python RAG 生态默认的检索存储端**：嵌入式零部署、Collection 模型与框架的"向量存储"抽象天然对齐、嵌入函数机制与框架的 Embeddings 抽象可桥接。**框架封装的是"连接与编排"，Chroma 的本体（索引/过滤/距离）原样生效**——"框架没有替换 Chroma，只是替你写了连接代码"。

两条集成线：**LangChain 系**（`langchain-chroma` 包，RAG 链式编排生态）与 **LlamaIndex 系**（`llama-index-vector-stores-chroma` 包，索引/查询引擎生态）——**"两个框架一个库：选框架是选编排哲学，存储都是 Chroma"**。

## 2. LangChain 集成：LangChainChroma

```bash
pip install langchain-chroma>=0.1.2
```

```python
from langchain_chroma import Chroma
from langchain_community.embeddings import OllamaEmbeddings

vector_store = Chroma(
    collection_name="kb",
    embedding_function=OllamaEmbeddings(model="bge-m3"),   # LangChain 的嵌入对象
    persist_directory="./chroma_db",   # 本地持久化（或配置 client 指向服务器）
)
vector_store.add_documents(documents)   # 入库存分块后的 Document
```

**检索三件套**：

```python
docs = vector_store.similarity_search(query, k=5, filter={"source": "wiki"})
docs_scores = vector_store.similarity_search_with_score(query, k=5)  # 带距离
retriever = vector_store.as_retriever(
    search_type="similarity", search_kwargs={"k": 5, "filter": {"tag": "产品"}}
)
retriever.invoke(query)   # 直接喂给 RAG 链
```

**要点**：`filter` 参数透传给 Chroma 的 `where`（06 篇语法原样生效）；`as_retriever` 是 RAG 链的入口——`RetrievalQA`/`create_retrieval_chain` 都吃 retriever；**`search_type="mmr"`** 可选最大边际相关检索（结果多样化，去冗余）。**无凭证要求**——本地 Chroma 开箱即用。

**双入口与语义缓存**：写入有两个等价入口——`add_texts(texts, metadatas)`（文本列表）与 `add_documents(Document)`（Document 对象列表），**底层都落到 Chroma 的 upsert**；`persist_directory` 与 `client` 参数二选一（本地路径或 HttpClient）。进阶姿势是**语义缓存**：LangChain 的语义缓存（SemanticCache 类）可以用向量库做底座——"相同/相似问题直接命中缓存返回，省一次 LLM 调用"——**"Chroma 在 RAG 里不止当知识库，还能当缓存层"**（cache 与 RAG 的字段设计区别：缓存集合 key 用问题原文，命中后直接取答案）。

## 3. 嵌入函数桥接

**两种嵌入体系要桥接**：LangChain 的 `Embeddings`（embed_query/embed_documents 接口）与 Chroma 的 `EmbeddingFunction`（`__call__` 接口）——**框架集成件内部会做转换**，但裸 Chroma 集合与 LangChain 嵌入混用时需要显式包装：

```python
from chromadb.utils.embedding_functions import ChromaLangchainEmbeddingFunction
ef = ChromaLangchainEmbeddingFunction(lc_embeddings)   # LangChain 嵌入 → Chroma 嵌入函数
collection = client.get_or_create_collection(name="kb", embedding_function=ef)
```

**桥接的三个坑**：其一，**函数要绑定到集合**——绕开框架直接 `collection.query(query_texts=...)` 时，若嵌入函数没正确绑定会退回默认模型，维度报错或静默错配；其二，**已知工作区**——包装后的嵌入函数偶发 `query_texts` 异常，改用 `query_embeddings=[embeddings.embed_query(text)]` 绕行（官方 cookbook 记录）；其三，**统一入口**——"一个项目只走一条嵌入路径：要么全框架对象，要么全裸 Chroma 函数，混用是事故温床"。

## 4. LlamaIndex 集成：ChromaVectorStore

```bash
pip install llama-index-vector-stores-chroma
```

```python
import chromadb
from llama_index.core import StorageContext, VectorStoreIndex
from llama_index.vector_stores.chroma import ChromaVectorStore

chroma_client = chromadb.PersistentClient(path="./chroma_db")
collection = chroma_client.get_or_create_collection("kb", metadata={"hnsw:space": "cosine"})
vector_store = ChromaVectorStore(chroma_collection=collection)   # 包装集合

storage = StorageContext.from_defaults(vector_store=vector_store)
index = VectorStoreIndex.from_documents(documents, storage_context=storage)
# 或直接包装已有集合：VectorStoreIndex.from_vector_store(vector_store)
retriever = index.as_retriever(similarity_top_k=5)
query_engine = index.as_query_engine()   # 检索 + 生成一站式
```

**要点**：包装对象是**集合不是客户端**（`ChromaVectorStore(chroma_collection=...)`）；Ephemeral/Persistent/Http 三种客户端**零改动切换**（换客户端创建方式即可）；元数据过滤操作符（FilterOperator.GT 等）框架侧有映射支持；**LlamaIndex V0.10+ 用 `Settings` 统一嵌入模型**（`Settings.embed_model = ...`），与 Chroma 集合绑定的嵌入函数保持同模型同维度（04 篇纪律）。

**多模态扩展**：LlamaIndex 生态有 Chroma 多模态示例（ChromaMultiModalDemo）——**文本与图像向量（OpenCLIP 嵌入）进同一集合**，文本查询直接检索图片——"同一模型空间的向量才能同库可比"（04 篇纪律的多模态版）；框架层用 MultiModalVectorStoreIndex 编排，存储层仍是 ChromaVectorStore——**"多模态只是嵌入换了，存储模型不变"**。

## 5. 与 unstructured：RAG 管道两段

本体系在 00 篇划的分工，到这里落地成代码：

```python
from unstructured.partition.pdf import partition_pdf     # 第一段：文档解析
from unstructured.chunking.title import chunk_by_title  # + 分块

elements = partition_pdf("manual.pdf", strategy="hi_res")
chunks = chunk_by_title(elements, max_characters=800)

# 第二段：入库 Chroma（本体系）
collection.upsert(
    ids=[f"{i}" for i in range(len(chunks))],
    documents=[c.text for c in chunks],
    metadatas=[{"page": c.metadata.page_number, "type": c.category} for c in chunks],
)
```

**"unstructured 负责'喂什么'，Chroma 负责'怎么存怎么取'——两段管道各司其职，交接点是 Chunk 文本 + metadata"**（unstructured 07 篇分块参数与 06 篇清洗，决定入库文本质量；本体系 03 篇 metadata 设计，决定检索过滤能力）。

## 6. 裸库 vs 框架：选型决策

| 姿势 | 适用 | 成本 |
|------|------|------|
| 裸 Chroma | 学习/调试/自定义检索逻辑/轻量脚本 | 无依赖，全控制 |
| LangChainChroma | 已有 LangChain 链/Agent 生态 | 学习框架抽象 |
| ChromaVectorStore | LlamaIndex 查询引擎/文档管道 | 同上 |

**混合是生产标准答案**：**"框架管编排（链/Agent/引擎），裸库管质量（过滤语法/批量写入/监控）"**——生产项目常见组合：数据管道用裸 Chroma 批量入库（05 篇），问答链路用框架 retriever 编排；**"交接点就是 Collection 本身——框架读、裸库写，同一个集合两边都对得上"**。

## 7. 常见坑

1. **嵌入函数桥接缺失**——框架嵌入未包装/未绑定，退回默认模型维度错配（InvalidDimensionException）。
2. **query_texts 异常**——包装函数偶发问题，`query_embeddings` 绕行（官方工作区）。
3. **filter 语法写框架风格的**——LangChain 的 `filter` 就是 Chroma 的 `where`，照 06 篇写。
4. **框架版本与 chromadb 版本不匹配**——锁定 langchain-chroma / llama-index-vector-stores-chroma 的版本矩阵。
5. **两套嵌入模型混用**——框架 Settings 的模型 ≠ 集合绑定的模型，维度对不上。
6. **直接用框架默认集合配置**——框架创建的集合没配 `hnsw:space: cosine`，文本检索跑偏（07 篇）。
7. **集成层不做过滤验证**——框架层出了空结果先回裸库 get/query 隔离验证（02 篇三步法）。
