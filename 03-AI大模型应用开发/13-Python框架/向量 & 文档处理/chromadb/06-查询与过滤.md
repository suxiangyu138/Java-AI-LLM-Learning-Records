## 1. query：相似度检索基础

`query` 是 RAG 的主查询通道：**输入查询文本/向量 → 相似度排序 → 返回 top-k**：

```python
results = collection.query(
    query_texts=["什么是 B+ 树？"],   # 文本：自动走集合绑定嵌入函数
    # query_embeddings=[vec],       # 向量：跳过嵌入函数直接查
    n_results=5,                      # top-k（默认 10）
    where={"topic": "数据库"},        # 元数据预过滤
    where_document={"$contains": "索引"},  # 文档内容预过滤
    include=["documents", "metadatas", "distances"],  # 返回字段
)
# results 是列式字典：ids/documents/metadatas/distances
```

**三个关键认知**：其一，**`query_texts` 与 `query_embeddings` 二选一**——传文本自动嵌入，传向量直接用（与集合绑定模型不一致的后果自负，04 篇）；其二，**`where` 与 `where_document` 是"先过滤后排序"**——先按条件缩小候选集，再在候选里做相似度排序，不是"排序后过滤"——**"过滤是闸门，排序是决赛"**；其三，**`include` 控制返回字段**——不需要的字段别拉（远程模式省带宽）。

**1.x 新能力：query by ids**——`query(ids=["doc1:chunk0", ...])` 把相似度搜索限制在指定 ID 子集内——"先圈定一批候选，再在其中找最相似"，多轮检索/路由检索的实用姿势。

**批量查询**：`query_texts` 支持传**列表**一次查多个问题——返回按查询排列的嵌套结构（`results["documents"][i]` 是第 i 个问题的 top-k）——"离线评估、批量问答、知识库巡检"用它一次跑完；注意**批量查询与单查一样共享 n_results**，每个问题各自返回 top-k。"一条查询一个话题，批量查询是批处理姿势不是多路召回"。

## 2. where：元数据过滤全语法

`where` 作用于 **metadata 字段**，完整操作符：

| 操作符 | 语义 | 示例 |
|--------|------|------|
| `$eq` / `$ne` | 等于/不等于（字符串等值区分大小写） | `{"tag": {"$eq": "键盘"}}` |
| `$gt` / `$gte` / `$lt` / `$lte` | 数值比较 | `{"price": {"$gte": 100}}` |
| `$in` / `$nin` | 在/不在列表（列表内类型一致） | `{"tag": {"$in": ["键盘", "鼠标"]}}` |
| `$contains` / `$not_contains` | **数组字段**包含/不包含某元素（1.5.0+） | `{"tags": {"$contains": "机械"}}` |

**书写要点**：一是**简写**——`{"tag": "键盘"}` 等价于 `{"tag": {"$eq": "键盘"}}`，等值过滤不必写全；二是**每个字段只能一个操作符**——`{"price": {"$gt": 10, "$lt": 100}}` 不合法，要用 `$and`（见 4 节）；三是**数值比较只对数值字段**，字符串字段做大小比较无意义；四是 **`$contains` 的语境区分**——在 `where`（元数据）里它作用于**数组字段**，在 `where_document` 里它检查**文档文本子串**——"同一个符号、两个世界"。

**注意**：`where` 里 `$contains` 的"数组"指 **metadata 值是数组**（`{"tags": ["a", "b"]}`），1.5.0 起支持——**"标签类字段用数组存，一个 where 就能做交集式筛选"**。

## 3. where_document：文档内容过滤

`where_document` 作用于 **document 原文文本**：

```python
collection.query(
    query_texts=["故障排查"],
    where_document={"$and": [
        {"$contains": "MySQL"},
        {"$not_contains": "Redis"},
    ]},
)
```

四个操作符：`$contains`（包含子串）、`$not_contains`（不包含）、`$regex`（正则匹配）、`$not_regex`（正则不匹配）。**关键特性**：`$contains` 是**大小写敏感**的子串匹配（"MySQL" 匹配不到 "mysql"）——**"内容过滤是字面匹配不是语义匹配"**，正则场景用 `$regex` 补位。

**使用场景**：召回后过滤"标题含'勘误'的段落"、排除"包含机密标记的文本"、用 `$regex` 做格式模式筛选（如邮箱/编号）——**"语义检索负责'像不像'，内容过滤负责'是不是'"**。

## 4. 逻辑组合与混合过滤

**`$and` / `$or` 是组合器**，where 与 where_document 内部都能用，且**支持嵌套**：

```python
collection.query(
    query_texts=["数据库索引"],
    n_results=5,
    where={
        "$and": [
            {"topic": "数据库"},
            {"$or": [{"level": "入门"}, {"level": "进阶"}]},
        ]
    },
    where_document={"$contains": "B+ 树"},
)
```

**组合规则**：单条过滤是单 key 对象（一个字段或一个逻辑符）；**多条件必须显式 `$and`/`$or` 包裹**（Chroma 不支持隐式多条件）。**`where` 与 `where_document` 同时给出时是隐式 AND**——"元数据条件 AND 内容条件 AND 相似度排序"三段式。

**混合过滤的典型姿势**（生产 RAG 的标配）：

```python
collection.query(
    query_texts=[question],
    n_results=10,
    where={
        "$and": [
            {"source": {"$in": ["wiki", "docs"]}},   # 来源白名单
            {"is_deleted": {"$eq": 0}},              # 软删除过滤
        ]
    },
    where_document={"$not_contains": "内部机密"},     # 敏感内容排除
)
```

## 5. get vs query：两种查询的分工

| | get | query |
|------|------|------|
| 匹配方式 | 精确条件（id/where/where_document） | 相似度排序 + 条件预过滤 |
| 输出顺序 | 无定义顺序 | 按距离从小到大 |
| 典型用途 | 看数据/过滤验证/导出 | RAG 检索 |
| 分页 | limit/offset | n_results |

**选型口诀**：**"要'找出符合条件的所有'用 get，要'找出最相似的 k 个'用 query"**——调试过滤条件先用 get 隔离验证（02 篇三步法），生产检索走 query。**query 没有分页语义**（top-k 就是全部），大规模条件查询（如导出、清洗）用 get 分页。

**检索质量三查（空结果/差结果的归因顺序）**：其一，**过滤过严？**——先去掉 where/where_document 再查，能命中说明闸门太紧（用 get 单测过滤条件）；其二，**大小写/类型不匹配？**——`$contains` 大小写敏感、数值字段传了字符串（06/03 篇坑）；其三，**嵌入方向偏？**——过滤全去掉仍差，说明查询词与库内文本不在一个语义面（换查询词复测；仍差要回看嵌入模型选型，04 篇）——**"先闸门后语义，逐层剥离定位"**。

## 6. 常见坑

1. **$contains 混语境**——where 里它是数组包含，where_document 里它是子串匹配；写错位置过滤结果为空还难排查。
2. **$regex 忘转义**——正则里的特殊字符（`.`、`*`）按正则语义生效，字面匹配用 `$contains` 不用 `$regex`。
3. **大小写敏感**——"MySQL" 查不到 "mysql"，先确认数据实际大小写。
4. **隐式多条件**——`{"a": 1, "b": 2}` 不合法，必须 `$and` 包裹。
5. **n_results 设置过大**——top-k 语义下取 1 万条是"全量排序"，用 where 缩小候选 + 合理 k。
6. **只查不验证**——检索结果质量用"人工抽查 top-5 + 空结果归因"（过滤条件过严？嵌入方向偏？）三步排查。
7. **where 数值字段传字符串**——`{"price": "100"}` 匹配不到 `100`（类型严格，03 篇 schema）。

3. $and/$or 嵌套规则？为什么"隐式多条件不合法"？

5. 混合过滤的典型姿势？$regex 与 $contains 的选型？

> 🎯 **核心要点**：查询 = **query 相似度排序 + where 元数据闸门 + where_document 内容闸门 + $and/$or 组合**——"三个通道一次调用，过滤缩小候选，排序决定名次——检索质量的 20% 在查询写法，而查询写法的第一步是数据模型（03 篇）"。
