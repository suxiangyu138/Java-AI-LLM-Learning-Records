## 1. 索引家族全景：两个维度的组合

FAISS 的索引不是"一个列表"，而是**两个正交维度的组合**：

**维度一：检索方式**——精确（Flat，全量扫描，100% 召回）vs 近似（IVF 倒排 / HNSW 图 / LSH 哈希，牺牲少量召回换速度）。

**维度二：存储方式**——无压缩（原始向量原样存）vs 压缩（PQ 乘积量化，向量压缩存储，内存骤降）。

| 组合 | 索引类 | 特点 | 典型规模 |
|------|--------|------|---------|
| 精确 + 无压缩 | IndexFlatL2/IP | 100% 召回、内存大、小库最快 | <10 万 |
| 近似 + 无压缩 | IndexIVFFlat / IndexHNSWFlat | 快且准、内存仍大 | 10 万-1 亿 |
| 近似 + 压缩 | IndexIVFPQ / IndexHNSWPQ | 内存降一个量级、召回略降 | 千万-十亿 |
| 精确 + 压缩 | IndexLSH / IndexPQ（无 IVF） | 少用，权衡尴尬 | 特殊场景 |

**"索引 = 结构（怎么找）× 存储（怎么放）——两轴相乘就是 FAISS 的几十种组合"**；再叠加 IDMap（自定义 ID，08 篇）、降维（PCA，09 篇）等包装器，组合空间更大——**"不要背组合，记两轴"**。

## 2. 四象限心智：按场景落座

**象限一：小库（<10 万）→ IndexFlat**——"精确、零训练、毫秒级"——大多数原型与中小项目的最优解，**别为了'高级'上近似索引**（Flat 在小维数小库上比 IVF 更快，缓存友好）。

**象限二：中大规模 + 精度优先 → IndexHNSWFlat**——图结构，**检索速度与召回质量兼顾**（约 99% 召回），无需训练直接 add——"质量敏感的场景（RAG 问答）默认选它"（07 篇）。

**象限三：中大规模 + 速度优先 → IndexIVFFlat**——倒排分桶，检索只碰 nprobe 个桶——"召回 95-99%，调 nprobe 换速度"（05 篇）。

**象限四：亿级/内存受限 → IndexIVFPQ**——PQ 压缩把内存降一个量级——"十亿向量 32GB 内存跑起来，就是 PQ 的成名作"（06 篇）。

**一句话落座**：**"10 万以内 Flat，10 万以上质量优先 HNSW、速度优先 IVF、内存受限 PQ"**——这是 FAISS 选型的默认答案，其余都是特例。

## 3. 包装器与组合

**IndexIDMap / IndexIDMap2**——给索引包一层自定义 int64 ID（业务主键），`add_with_ids` 入库、`remove_ids` 删除——"裸索引的行号换成语义 ID，这是'当数据库用'的第一件外套"（08 篇）。

**MetricType**——同一索引类可选度量：IndexFlatL2（欧氏）与 IndexFlatIP（内积，归一化后 = 余弦）是**两个不同的索引类**；构造时 `faiss.IndexFlat(d, faiss.METRIC_INNER_PRODUCT)` 是另一写法——"选度量 = 选相似的定义，文本嵌入标准答案是归一化 + IP"（04 篇）。

**降维/白化**——PCA 降维、OPQ 旋转（PQ 前置优化）在构建时组装：`faiss.index_factory(d, "PCA64,IVF100,PQ8")`——**index_factory 字符串语法**用一行描述完整索引组合——"'Flat'、'IVF100,Flat'、'HNSW32' 就是工厂配方"，生产上常以此做配置化选型（09 篇）。

## 4. 选型决策树

1. **数据量多大？**——<10 万 → **Flat**（结束）；≥10 万 → 继续；
2. **内存够吗？**——原始向量 × 4 字节 × 条数，放不下 → **PQ 系**；放得下 → 继续；
3. **质量优先还是速度优先？**——质量 → **HNSWFlat**；速度/吞吐 → **IVFFlat**；
4. **亿级以上？**——**IVFPQ + 分片/降维**组合拳；
5. **要不要业务 ID / 删除 / 增量？**——**包 IndexIDMap/IDMap2**（08 篇）。

**决策的量化依据**：选完类型必须**用真实数据测**——召回率（top-k 里真正邻居占比）、延迟（p95）、内存（驻留内存实测）三个数字说话——"**选型表只是起点，你的数据与硬件才是裁判**"（09 篇压测方法）。

## 5. 训练集：近似索引的前提

IVF（聚类分桶）与 PQ（码本学习）在**建索引前需要 train 阶段**——用**代表性子集**训练数据结构：

```python
index = faiss.IndexIVFFlat(quantizer, d, nlist)
index.train(training_vectors)   # 训练集：全量抽样即可（几万条足够）
index.add(vectors)              # 之后才能 add
```

**训练三条纪律**：其一，**训练集与入库数据同分布**（同一嵌入模型、同一领域）；其二，**训练集是子集不是全量**（几万条足够聚类，全量训练白费算力）；其三，**train 是一次性的**——训练好就落盘复用，别每次重建（08 篇落盘）。**Flat 与 HNSW 不需要训练**（无聚类/码本），这也是它们"上手快"的原因——**"需要 train 的索引（IVF/PQ）才是真正的'重型'索引"**（05/06 篇详讲）。

## 6. 常见坑

1. **小库上近似索引反而更慢**——10 万以内 Flat 就是最优，别为了"高级"牺牲。
2. **忘了 train 就 add**——IVF/PQ 不报错但结果垃圾（最危险的静默失败）。
3. **训练集与数据不同分布**——聚类中心学偏，召回崩了还找不到原因。
4. **全量数据去 train**——浪费算力，抽样几万条足够。
5. **选型不做量化验证**——"感觉 HNSW 好"不如"实测召回 98.5% vs 96.3%"。
6. **index_factory 字符串拼错**——"IVF100,Flat" 少逗号就变另一个索引；工厂语法查官方对照表。
7. **度量选错**——文本检索用 L2 直接上（没归一化），相似语义全反（04 篇）。
