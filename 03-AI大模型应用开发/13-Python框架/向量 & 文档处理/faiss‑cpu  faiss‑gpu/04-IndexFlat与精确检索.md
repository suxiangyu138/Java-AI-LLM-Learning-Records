## 1. 精确检索：100% 召回的意义

IndexFlatL2 的"Flat"指**扁平存储**——所有向量原样存进连续内存，查询时**全量计算距离、精确排序**。它带来两个特性：

**其一，100% 召回**——不近似、不抽样，返回的就是数学上最相似的前 k 个——**"Flat 的结果是'标准答案'，其他索引的召回率都是相对它的百分比"**。这个属性让它成为**评估基准**：测近似索引的召回率 = 近似结果 ∩ 精确结果 / 精确结果。

**其二，零训练零参数**——不需要 train、没有 nprobe/efSearch，**建好就能 add、add 完就能查**——"FAISS 里唯一'无脑可用'的索引"。

**"Flat 不是入门玩具，是精度基准"**——评估任何索引方案前，先用 Flat 跑一遍拿到标准答案；生产上小库直接用 Flat 就是最优解（03 篇四象限）。

**标准答案的两种用法**：其一，**近似索引的召回率基准**（05/07 篇闭环的分子）；其二，**检索质量的基线回归**——数据更新/嵌入模型调整后跑一遍 Flat 对比新旧结果，"**质量回归测试用 Flat 当 golden 集**"——"**Flat 的'贵'（全量扫描）在评估场景里是'准'，值得**"。

## 2. L2 与 IP：两种距离语义

IndexFlat 有两个度量变体，**在构造时定死**：

| 索引类 | 距离定义 | 直觉 | 适配向量 |
|--------|---------|------|---------|
| IndexFlatL2 | 平方 L2（欧氏）距离 | 空间几何距离 | 图像特征、非归一化向量 |
| IndexFlatIP | 内积（点积） | 方向 + 模长 | 归一化向量（= 余弦） |

**两个关键认知**：其一，**L2 返回的是"平方距离"**——FAISS 直接返回 Σ(Ai−Bi)²，开根号才是欧氏距离（提速设计：开根号单调不改变排序，省掉计算）；其二，**IP 返回的是内积"分数"**——**越大越相似**（与 L2 相反！）——"同一个 search 返回，L2 看最小、IP 看最大——**度量决定排序方向，这是新手最容易搞反的点**"。

**选度量 = 选'相似'的定义**：图像/几何场景 L2，文本语义场景 IP + 归一化（下一节）——"先定相似语义，再选索引类"。

## 3. 余弦的正确姿势：归一化 + IP

**FAISS 没有 cosine 索引类**——因为余弦相似度可以通过**归一化 + 内积**等价实现：

cos(A,B) = A·B / (|A| × |B|)——如果 A、B 都是单位向量（|A|=|B|=1），**cos = 内积**。

```python
index = faiss.IndexFlatIP(d)                       # 内积索引
faiss.normalize_L2(vectors)                        # ① 入库前归一化（原地修改！）
index.add(vectors)
faiss.normalize_L2(query)                          # ② 查询前同样归一化
D, I = index.search(query, k)
# D 越大越相似（IP 语义），0-1 区间，1 = 完全一致
```

**两条纪律**：其一，**入库归一化一次、查询归一化一次——两次缺一不可**；其二，`faiss.normalize_L2` 是**原地修改**（返回 None），别把它当返回新数组的函数——"**归一化是 cosine 的前置手续，忘一次结果就废**"。**为什么用 IP 而不是 L2 实现 cosine**：归一化后 L2² = 2−2·cos（单调同序），理论上都能用，但 IP 语义直接、语义直观（越大越相似），且与 PQ/IVF 组合时是标准配方。

**等价手写实现**（理解语义用）：`norm = np.linalg.norm(x, axis=1, keepdims=True); x = x / norm`——`faiss.normalize_L2` 就是这行的 C++ 加速版——"**会手写就知道它在干什么，用内置就知道它更快**"；注意**零向量**（全 0）归一化会除零，前置过滤或加 epsilon 保护——"脏数据先清，再谈归一化"。

## 4. 批量检索：一次查 N 个

`search` 天然支持批量——**查询矩阵 (Q, d) 一次算完**，返回 (Q, k) 两矩阵：

```python
queries = np.random.rand(100, d).astype('float32')   # 100 个查询
D, I = flat.search(queries, k=10)   # D/I 形状 (100, 10)
for qi in range(3):                 # 逐条解读
    print(f"查询 {qi} 的 top-10 行号: {I[qi]}")
```

**批量检索是 FAISS 的性能钥匙**：底层 SIMD 与多线程按批量摊薄开销，**100 个查询一次调用远比 100 次单查快**——"能批量就批量，这是调优第一法则"（09 篇）。批量也用于**离线评估**：一批查询 + 精确答案，批量测召回率。

## 5. 小库性能优势

**Flat 在小库上的表现常被低估**：10 万条以内（甚至 100 万条、低维时），Flat 的**连续内存全量扫描**受益于 CPU 缓存与 SIMD 指令，实际延迟毫秒级——**"它'理论上 O(N)'，但常数极小；IVF 虽然'理论上 O(√N)'，但引入了间接寻址与调度开销"**。FAISS 官方观察：**维数 <64 时 Flat 甚至可能比 IVF 更快**（缓存完全装得下）。

**选型含义**：**"10 万条以内默认 Flat——简单、精确、够快；等数据量真正压出延迟，再考虑近似索引"**——别为不存在的性能问题付复杂度（03 篇四象限）。

## 6. 常见坑

1. **L2 结果当欧氏距离**——是平方距离；排序语义一样，但数值别拿去和阈值比较。
2. **IP 结果"越大越相似"搞反**——L2 看小、IP 看大，度量决定方向。
3. **归一化忘一次**——入库忘了 = 库内向量不单位；查询忘了 = 余弦失效；**两次都要**。
4. **`faiss.normalize_L2` 当函数用**——原地修改返回 None，`x = faiss.normalize_L2(x)` 会把 x 变 None。
5. **用 L2 跑文本嵌入**——模长差异污染相似度；文本语义场景归一化 + IP。
6. **单条循环查询**——100 次 search 单查 vs 1 次批量查，差一个数量级。
7. **拿 Flat 的 D 值跨索引比较**——IVF 返回同度量同语义，但 PQ 的距离是**近似距离**（06 篇），别混比。
