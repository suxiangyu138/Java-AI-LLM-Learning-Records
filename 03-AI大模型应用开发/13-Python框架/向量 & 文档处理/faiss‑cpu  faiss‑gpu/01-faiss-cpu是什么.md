## 1. 算法库：'找相似'的计算引擎

FAISS（Facebook AI Similarity Search）是 **Meta（Facebook）AI 研究团队开源的相似度检索算法库**，定位一句话：**"给向量做'找相似'的 C++ 计算引擎，Python 封装开箱即用"**。它解决的是检索领域的经典问题：给定一个查询向量，在一亿个候选向量里找出最相似的 top-k——**"暴力扫描太慢，FAISS 用索引结构把'找相似'从 O(N) 降到亚线性"**。

**它和数据库的本质区别**：Chroma/Milvus 是**数据库**（数据模型、过滤、持久化、服务一体），FAISS 是**算法库**——只提供一个 C++ 索引对象 + Python API，**持久化、元数据、过滤、去重、增量更新全要使用者自己搭**。这个"少"是双刃剑：**"代价是自己写外围，收益是内核级的速度与绝对的控制力"**。

**核心心智**：FAISS 的一切围绕 **Index（索引对象）**——`index.add(向量)` 建库，`index.search(查询, k)` 检索，返回 `(距离矩阵 D, 索引矩阵 I)`。**"建索引 = 选数据结构（怎么组织向量），检索 = 在这个结构上快速找邻居"**——这是 FAISS 的全部哲学。

## 2. 解决什么问题

**问题一：暴力扫描太慢**——10 万向量 × 512 维，每个查询全量算距离是毫秒级；**1 亿向量就是不可用的分钟级**。FAISS 的索引家族（倒排 IVF、图结构 HNSW、量化 PQ）把"全量扫描"变成"先粗筛再精算"——**"从 O(N) 全扫到 O(√N) 级探测，这就是索引的价值"**（03-07 篇逐个讲）。

**问题二：亿级向量内存装不下**——1 亿条 384 维 float32 向量 = 1 亿 × 384 × 4 字节 ≈ **143GB**，单机内存直接爆掉。FAISS 的**乘积量化（PQ）**把每条向量压缩到几百字节甚至几十字节——**"内存降一个量级，精度损失可控，这是 FAISS 独有的杀手锏"**（06 篇）。

**问题三：索引选型复杂**——"到底用哪种索引"是向量检索的第一道坎。FAISS 不替你做选择，但把**所有选项摊开**（精确/近似 × 无压缩/压缩 × 倒排/图/哈希……几十种组合），并且每个索引的参数（nprobe/efSearch/M）都可调——**"选型逻辑与调参手感，正是 FAISS 使用者的核心技能"**（03 篇决策表）。

## 3. 2026 现状与版本基线

**2026-08 基线：faiss-cpu 1.14.3（2026-06-13 发布）**；GitHub 仓库已发布 **v1.15.0**（PyPI 待同步）——**"锁版本，但知道下一个版本已经来了"**。faiss-cpu 是 PyPI 上的官方 CPU 轮子，**周下载约 350 万**、安全扫描 0 漏洞——向量检索内核的绝对主流。

**1.14 系列新特性**：Apple Silicon 上 **Metal GPU 后端默认启用**、新增 MetalIndexIVFFlat（Metal 的 IVF 扫描/合并内核）、musllinux 轮子恢复（Linux musl 环境可装）——"FAISS 在持续补平台覆盖，核心 API 十年稳定"。

**faiss-gpu 的现状（重要认知）**：PyPI 的 **faiss-gpu 包已停更**——卡在 1.7.x、仅支持 Python ≤3.10，官方明确"PyPI faiss-gpu 不受支持"；**2026 的 GPU 正确姿势**：conda 通道（`conda install faiss-gpu -c pytorch` 或 conda-forge）或社区轮子 faiss-gpu-cu11/cu12——**"pip 装 GPU 版是 2026 年第一大 FAISS 坑"**（09 篇详讲）。

**对学习者的含义**：索引 API（Index 家族 + add/search）**十余年稳定**，学一遍用十年；迭代集中在**平台覆盖与性能内核**（Metal/量化/新索引）——"**版本跟着锁，索引心智不变**"。

## 4. 与替代品对比

| 工具 | 形态 | 强项 | 短板 |
|------|------|------|------|
| FAISS | 算法库 | 性能/索引家族全/亿级向量/PQ 压缩 | 持久化过滤全要自己搭 |
| annoy | 算法库（Spotify） | 极简（单一 HNSW 式索引） | 功能少、召回弱于 FAISS |
| scikit-learn | ML 库 | 教学用、API 统一 | 性能差、无索引概念 |
| Chroma | 嵌入式数据库 | 零配置、过滤一体、原文存储 | 规模上限、可控性弱 |
| Milvus/Qdrant | 分布式数据库 | 亿级规模/过滤/多租户 | 部署运维重 |

**选型判断**：**"要快速交付 RAG 选 Chroma/Qdrant，要内核控制与极致性能选 FAISS；FAISS 是唯一'索引家族 + PQ 压缩 + GPU'全占的算法库"**；annoy 胜在极简（一个接口），scikit-learn 只是教学工具——**"工程检索的默认答案是 FAISS，除非你明确要数据库"**。注意：**Chroma/Milvus 的 HNSW 内核与 FAISS 是同族实现**——"选数据库 vs 选 FAISS 不是选'用什么算法'，是选'谁替你维护外围'"。

## 5. 生态位置与边界

**生态位置**：FAISS 是**向量检索的事实标准内核**——Milvus 的索引引擎（IVF/HNSW 同族）、大量 RAG 框架的 FAISS vector store 封装（LangChain/LlamaIndex）都以它为底；PyPI 周下载 350 万说明它不只是"一个库"——**是向量检索时代的地基**。**"Chroma 里跑着 HNSW、Milvus 里跑着 FAISS 同族——学 FAISS 等于学一切向量库的底牌"**。

**边界要划清楚**：其一，**它不是数据库**——无事务、无持久化保证、无过滤、无元数据（08 篇教你怎么自己补）；其二，**它不产生向量**——嵌入在外部完成，FAISS 只存只查；其三，**ID 与向量分离**——默认 ID 是 0..n-1 的数组下标，业务 ID 要 IndexIDMap 包装（08 篇）；其四，**无内置更新语义**——update 要 remove+add 手动完成（08 篇）；其五，**余弦要预处理**——没有 cosine 索引类，归一化 + IP 是标准姿势（04 篇）——**"FAISS 把'找相似'做到极致，把'其余一切'留给你——边界即自由，也是责任"**。
