## 1. 乘积量化：向量切段学码本

PQ（Product Quantization，乘积量化）解决的是**内存**问题——原始 float32 向量太大：384 维 = 1536 字节/条，1 亿条 = 143GB。PQ 的思路一句话：**"把向量切成 m 段，每段独立学一个码本，用码本编号代替数值"**：

**第一步（train）**：把每条 d 维向量切成 m 个子向量（每段 d/m 维），对**每一段**用 k-means 聚成 2^nbits 个类（码本）——m 个码本，每个码本 2^nbits 个"码字"。

**第二步（编码）**：入库时每条向量**逐段找到最近的码字**，每段只存"码字编号"（nbits 个 bit）——**"原向量没了，留下的是'每段最像哪个码字'的编号串"**。

**第三步（查询）**：查询向量同样切段，**距离计算变成'查表'**——预计算查询向量每段与码字距离表，查表求和即得近似距离——**"不存原向量、不算全维度距离——这就是内存与算力双降的来源"**。

## 2. IndexIVFPQ 构造与参数

生产上 PQ 从不单独用（精确 + 压缩的组合定位尴尬），**标配是 IndexIVFPQ**——倒排 + 量化组合拳：

```python
nlist = 1000          # 簇数（与 IVF 同语义）
m = 96                # 子量化器数：切成 96 段
nbits = 8             # 每段码本大小 2^8 = 256 个码字
index = faiss.IndexIVFPQ(faiss.IndexFlatL2(d), d, nlist, m, nbits)

index.train(training_vectors)   # 学码本 + 学簇中心
index.add(vectors)              # 编码入库
index.nprobe = 20
D, I = index.search(queries, k)
```

**参数语义**：`m` 决定压缩粒度——**m 越大每段越短、码本越精确、压缩率越高**（每段 nbits 位）；`nbits` 决定每段码本大小——8 是标准值（256 码字），更小更省、更粗糙。**经验配方**：`m` 取维度能被整除的值（384 维常用 96/64/48），nbits=8——"**m 和 nbits 是精度-内存的直接买卖**"。

## 3. 压缩比账本

| 配置 | 每条内存 | 1 亿条总量 |
|------|:---:|:---:|
| 原始 float32（384 维） | 1536 B | 143 GB |
| PQ m=96, nbits=8 | 96 B | 8.9 GB |
| PQ m=48, nbits=8 | 48 B | 4.5 GB |
| PQ m=96, nbits=4 | 48 B | 4.5 GB |

**账本要点**：其一，**PQ 压缩比 = d/m × nbits/8 的缩放**——384 维、m=96、nbits=8 时**每条 96 字节，降 16 倍**；其二，**10 亿条 384 维向量 ≈ 89GB**，PQ 后 ≈ 5-9GB——"**十亿向量进单机内存，这是 PQ 的成名作**"；其三，**码本本身有小内存**（m × 2^nbits × d/m 维浮点），相对向量总量可忽略——"**账单算的是数据内存，码本零头不算账**"。

**内存预算流程**：`条数 × (d/m × nbits/8) 字节 + 倒排结构开销` 估算 → 实测 `resource.getrusage` 校验——"**先算账本后开工，内存爆了再换 m**"（09 篇内存治理）。

## 4. 精度权衡：近似距离的代价

PQ 的召回损失来自**编码失真**：码本不是无限精细的，**"最像的码字" ≠ 原向量**——距离计算基于码字而非原向量，是**近似距离**。影响与对策：

**对策一：加大 nprobe**——IVF 部分召回损失用探测更多簇补偿（05 篇同一旋钮）；**对策二：调 m**——m 越大每段越短，码本对子空间拟合越好，召回回升但压缩率下降；**对策三：OPQ 旋转**——`IndexIVFPQ(..., use_precomputed_table=True)` 或 OPQ 预处理（先旋转坐标再切段，让各段信息均衡）——"OPQ+IVFPQ 是生产配方，召回能再拉 1-3 个点"。

**验证纪律与 Flat 同款**（05 篇闭环）：基准 Flat 答案 → 扫描 m/nprobe → **"目标是'内存降 10 倍、召回保持 95%+'"**——PQ 的成败标准是这一条，不是"尽量压"。

**何时值得上 PQ**：内存账本先算——**"1 亿条以下、内存放得下，就别上 PQ（召回损失没必要付）；放不下或成本敏感，PQ 是唯一答案"**——典型信号：单机内存 < 原始向量总量、云上内存规格的成本占比、十亿级数据的单机野心——"**PQ 是'内存换召回'的买卖，账本清楚才下单**"。

## 5. 与 IVF 的组合拳

IVFPQ 完整链路 = **倒排（粗筛）+ 量化（压缩）+ 查表（快算）**三合一：

1. **train 学两样东西**——簇中心（IVF 的格子）与 m 段码本（PQ 的字典）——"一次 train，两个结构"；
2. **add 两段处理**——先分配进簇（存簇内编号），再逐段编码（存码字编号）——"簇编号 + 码字串"两条信息定一条记录；
3. **search 三步**——探簇（nprobe 个）→ 查表（查询向量对码本算距离表）→ 归并排序——"粗筛 → 近似距离 → top-k"。

**记忆点**：**"IVF 管'找哪些桶'，PQ 管'桶里怎么存怎么算'"**——两个近似叠加，召回约 90-98%（视配置），换来的是**唯一能在单机内存跑十亿级向量的方案**——"**速度不够 HNSW 上，内存不够只有 PQ 上**"。

## 6. 常见坑

1. **PQ 裸用（不配 IVF）**——精确 + 压缩的组合召回定位尴尬，生产标配 IVFPQ。
2. **m 选维度不可整除的值**——报错；m 必须整除 d。
3. **nbits 拍脑袋**——8 是标准，4 更省但粗糙，先 8 后测。
4. **拿 PQ 的 D 值与 Flat 比**——PQ 距离是**近似距离**，跨索引比数值没意义。
5. **忘 train 静默失败**——IVF 系通病，train 纪律三连（05 篇）。
6. **只压不回测**——"压完内存看召回"，目标 95%+，不达标调 m/nprobe。
7. **码本内存没算进预算**——大 nbits × 高维时码本变大，预算留 10% 余量。
