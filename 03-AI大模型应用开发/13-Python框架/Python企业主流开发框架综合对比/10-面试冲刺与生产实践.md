## 1. 高频面试题 12 问

### Q1：Django、FastAPI、Flask 的区别？2026 年怎么选？

> 答：哲学不同——Django 电池内置（全栈/Admin/认证），FastAPI 类型驱动（契约三件套自动），Flask 极简核心（乐高扩展）。选型口诀：要后台选 Django，要接口/模型服务选 FastAPI，要快/教学选 Flask。市场数据：JetBrains 2024 使用率 FastAPI 38% 登顶、Django 35%、Flask 34%。（→ 01/05/09）

### Q2：FastAPI 为什么火？核心优势是什么？

> 答：类型驱动闭环——Pydantic v2 校验 + 自动 OpenAPI 文档 + IDE 类型提示三合一；ASGI 原生异步（流式/SSE/WebSocket）；AI 双风口（42% ML 工程师使用，OpenAI/HuggingFace 背书）。GitHub star 五年 +487%。（→ 03）

### Q3：ASGI 和 WSGI 的区别？

> 答：WSGI 同步协议（一请求一线程），ASGI 异步协议（事件循环并发 + WebSocket + 流式）。FastAPI/Starlette 走 ASGI，Django/Flask 传统走 WSGI。差距在并发承载量级（千级 vs 万级），单请求 CPU 速度两者相当（GIL 公共天花板）。（→ 06）

### Q4：FastAPI 和 Starlette 什么关系？

> 答：FastAPI 是 Starlette 之上的 API 体验层——Starlette 提供路由/中间件/异步/WebSocket，FastAPI 增加 Pydantic 集成、依赖注入、自动 OpenAPI。想要更裸的控制力直接用 Starlette。（→ 03）

### Q5：FastAPI 的依赖注入怎么实现的？和 Spring 比呢？

> 答：函数式 DI——依赖是普通函数，靠类型声明自动解析，`yield` 依赖实现请求级生命周期（进入-退出）。比 Spring 的注解式更轻，但能力等价（作用域/替换/嵌套解析）。（→ 03）

### Q6：Django 的 MTV 是什么？和 MVC 什么关系？

> 答：Model-Template-View，MVC 的 Django 变体——Model 管数据、Template 管展示、View 管逻辑（扮演 Controller）。Django 用"模板"而非"视图"做展示层，命名不同、职责相同。（→ 02）

### Q7：Django Admin 的价值？为什么说它无可替代？

> 答：模型注册即后台（搜索/过滤/编辑/权限集成），一行代码获得完整管理界面；全 Python 生态没有等价物（FastAPI/Flask 都要自建或低代码平台）。"带后台的项目选 Django"的底层原因。（→ 02/07）

### Q8：Django 6.0 有什么新特性？

> 答：内置后台任务框架（替代 Celery 的轻量方案）、原生 CSP 中间件、模板 partials（组件化）；6.1（2026-08）补模型字段抓取模式、数据库级删除；支持 Python 3.12-3.14。（→ 02）

### Q9：Flask 支持异步吗？和 FastAPI 的异步差在哪？

> 答：支持但有限——2.0 起可写 async 视图，但 WSGI 同步模型不变，WebSocket/流式靠扩展拼装；FastAPI 是 ASGI 原生异步，事件循环 + 流式 + WebSocket 一等公民。差距是"兼容层 vs 原生"。（→ 04/06）

### Q10：为什么 FastAPI 成为 AI 模型服务的事实标准？

> 答：模型服务四需求（异步并发 + 流式输出 + 类型校验 + 快速迭代）FastAPI 全中；vLLM/Ollama 官方示例、OpenAI/HuggingFace 内部使用都是 FastAPI 形态；42% ML 工程师使用、过半财富 500 强生产使用。（→ 03/08）

### Q11：Django 项目想 API 化，选 DRF 还是 Django Ninja？

> 答：DRF 是传统选择（模型联动 Serializer、生态老）；Django Ninja 是现代选择（Pydantic 驱动、自动 OpenAPI、异步支持），更接近 FastAPI 体验。2026 年新项目 API 化首选 Ninja，绿地 API 项目直接 FastAPI。（→ 07/08）

### Q12：FastAPI 项目怎么组织目录？生产部署怎么搭？

> 答：按模块分包（api/ 路由、core/ 配置、models/ 数据、schemas/ Pydantic、services/ 业务）；部署用 gunicorn + uvicorn worker（进程管理 + 事件循环）或容器内 uvicorn 多 worker，K8s 接管进程管理。异步代码纪律：阻塞调用丢线程池（asyncio.to_thread）。（→ 06）

## 2. 项目话术：AI 项目框架叙事模板

面试讲 AI 项目时用"三层框架分工"叙事：

```text
项目背景：XX 企业知识库问答（RAG + Agent），需对接内部权限系统。
我的方案：
  ① 框架分工——对话/检索/工具调用用 FastAPI（SSE 流式输出、
     Pydantic 契约、异步并发），知识库与运营后台用 Django（Admin
     管理文档与用户、6.0 内置后台任务做文档切分向量化）；
  ② 关键设计——Django 签发 JWT、FastAPI 校验同一密钥；流式对话
     走 SSE；向量索引异步刷新；
  ③ 结果量化——P99 首 token 延迟 XXms、知识库管理后台一周交付、
     单机并发 XX。
```

加分点：主动说出"为什么这么分"（流式需求定 FastAPI、后台需求定 Django），引用 42% 数据与 Django 6.0 新特性——证明你有"框架分工判断力"而非"会用一个框架"。

## 3. 生产落地清单 10 项

1. **服务器选型**：FastAPI → uvicorn（开发）/ gunicorn + uvicorn worker（生产）；Django/Flask → gunicorn WSGI
2. **进程与 worker 数**：`2 × CPU 核 + 1` 起步；异步框架 worker 数按事件循环负载调
3. **异步纪律**：FastAPI 里阻塞调用必须 `asyncio.to_thread` 或换线程池，否则事件循环卡死
4. **Pydantic 配置**：`model_config` 严格模式（禁止额外字段）在 API 边界开启
5. **依赖锁定**：uv 或 pip-tools 锁文件，Python 3.14 环境 + 框架版本基线（Django 6.1/FastAPI 0.139/Flask 3.1.3）
6. **安全基线**：CSP（Django 6.0 原生/FastAPI 中间件）、HTTPS、密码哈希（argon2/bcrypt）、`SECRET_KEY` 环境变量化
7. **可观测**：OpenTelemetry + 结构化日志，traceId 贯穿；FastAPI 中间件记录耗时与状态码
8. **测试**：pytest + TestClient（FastAPI）或 Django test client；覆盖率红线 80%；关键链路契约测试
9. **CI/CD**：ruff + mypy（严格模式）+ pytest 三门禁；镜像多阶段构建 + 非 root 运行
10. **性能预算**：压测（locust/wrk）留 3-5 倍峰值余量，P99 记录基线，每次发版对比

## 4. 常见坑与排查

- **坑一：async 视图里写阻塞调用**——`requests.get`/`time.sleep` 卡死事件循环，全服务假死；症状：一个慢请求拖垮所有请求；解法：`httpx.AsyncClient`/`asyncio.to_thread`
- **坑二：Django 迁移冲突**——多人并行改模型生成重复迁移；解法：`makemigrations --merge`，或约定"模型改动先拉主干再生成"
- **坑三：Flask 生产忘关调试模式**——`app.run(debug=True)` 的调试器是 RCE 入口；解法：环境变量控制，生产强制关闭
- **坑四：Pydantic 校验过严/过松**——严格模式挡掉合法请求（extra 字段），宽松模式放过脏数据；解法：边界严格、内部宽松
- **坑五：gunicorn 起不来 FastAPI**——忘了 `-k uvicorn.workers.UvicornWorker`；症状：同步 worker 跑异步代码全 500
- **坑六：Admin 裸奔**——Django Admin 未接认证/权限就上线；解法：默认 `is_staff` 校验 + HTTPS + 限 IP

附加题（深水区）：

11. FastAPI 里 `async def` 和普通 `def` 路由的区别？（答：`async def` 跑在事件循环，`def` 自动丢线程池执行——**CPU 阻塞型用 `def`（线程池防卡循环），IO 型用 `async def`**；混用是 FastAPI 的正确姿势而非错误 → 03/10）
12. 面试官问"Django 这么重为什么还要用"怎么答？（答：重是"功能密度"不是"性能负担"——Admin/认证/迁移/后台任务全是内置；后台密集型项目 Django 的总成本最低；重框架对"要后台的项目"是收益而非负担 → 02/05）

13. 一个"运营后台 + 实时推送"项目，框架怎么搭？（答：Django 管后台（Admin/认证/任务）+ FastAPI sidecar 管推送（WebSocket/SSE），反向代理分流，JWT 共享——这是 2026 年最标准的"全栈 + 实时"组合 → 08/09）
