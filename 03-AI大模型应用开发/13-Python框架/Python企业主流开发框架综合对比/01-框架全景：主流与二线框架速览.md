## 1. 三大主流：2026 市场格局

三大框架的格局数据（多来源交叉，2026 检索）：

| 维度 | Django | FastAPI | Flask |
|------|:---:|:---:|:---:|
| JetBrains 2024 使用率 | 35% | **38%** | 34% |
| Stack Overflow 2025（全 Web 框架） | — | **14.8%** | 14.4% |
| GitHub Stars（2020→2026） | 68K→87K（+10%） | 15K→96K（+487%） | 60K→71K（+13%） |
| PyPI 月下载 | ~9M | ~9M（追平） | 增长平缓 |

> ⚠️ **数据口径提醒**：使用率调查（JetBrains/SO）与下载量（PyPI）统计口径不同——调查反映"开发者自报使用"，下载量包含 CI 与教学环境；两组数据都指向"三强并存、FastAPI 领先"的同一结论即可，不必纠结绝对值。
| ML 工程师使用（2025） | 22% | **42%** | 28% |
| 生产案例 | 内容站/电商/后台 | OpenAI、HuggingFace、Uber | 教学/原型/内部工具 |

一句话格局：**FastAPI 是"增速王"**（API 与 AI 双风口），**Django 是"存量王"**（全栈与应用型系统稳固），**Flask 是"教学与极简王"**（心智模型无可替代）。三者 2026 年全部健康活跃，没有输家——选错才是唯一的输法。

## 2. 分类维度：全栈 / 微框架 / 异步 API

理解框架版图先掌握三个分类维度，每个框架都能定位到"三维坐标"：

| 维度 | 端点 | 说明 |
|------|------|------|
| 功能范围 | 全栈 ↔ 微框架 | Django 带 ORM/Admin/认证；Flask 只有路由+模板 |
| 并发模型 | 同步（WSGI）↔ 异步（ASGI） | Flask/Django 传统同步；FastAPI/Starlette 原生异步 |
| 定位 | 应用型 ↔ API 型 | Django 面向"完整应用"；FastAPI 面向"接口服务" |

坐标举例：Django =（全栈，同步为主，应用型）；FastAPI =（微框架偏中，原生异步，API 型）；Flask =（微框架，同步，应用/API 两可）。**没有框架能同时占据三个维度的两个端点**——这就是选型必须妥协的本质：功能与速度、同步与异步、应用与 API，三选二甚至三选一。

**妥协的具体形态**值得展开，因为它决定了"选完后的别扭感"从哪来：选 Django 的团队会发现"想要并发连接数"时（WebSocket 大流量）要绕 Channels 或引 sidecar——**Django 的妥协点在异步**；选 FastAPI 的团队会发现"想要现成后台"时只能自建或低代码——**FastAPI 的妥协点在功能广度**；选 Flask 的团队会发现"想要契约自动"时只能手写校验与文档——**Flask 的妥协点在类型系统**。**"选框架 = 选妥协点"这个视角比"哪个更好"更接近决策真相**：先想清楚"哪个妥协点你能接受"，框架就浮出水面了。

## 3. 二线梯队速览：六位选手一句话定位

二线框架不是"更差"，而是"更专"——每个都在某个维度做到了极致，只是综合能力不足以进入主流决策：

| 框架 | 一句话定位 | 2026 状态 | 何时考虑 |
|------|-----------|-----------|---------|
| Starlette | FastAPI 的异步基座本体 | 活跃，Gunicorn ASGI 套件 98% 通过 | 要 FastAPI 的速度、不要 Pydantic 校验 |
| Litestar | "功能更全的 FastAPI 替代" | 活跃，自带 ORM（Advanced Alchemy）、DTO 一等公民 | 嫌 FastAPI 插件太散、要开箱完整 |
| Quart | Flask API 的 ASGI 克隆 | 活跃但生态兼容不完全 | 存量 Flask 想渐进异步 |
| Sanic | 最早的异步框架 | 维护中，早期团队留存 | 几乎不需要新选 |
| Tornado | 久经考验的老将（FriendFeed→Meta） | 维护 + 安全修复（CVE-2025-47287 已修） | 存量 Tornado 团队；Gunicorn worker |
| aiohttp | 异步 HTTP 客户端/服务端库 | 活跃 | 客户端为主；自建轻量服务 |
| Pyramid | "框架中的框架"，可大可小 | 维护中，社区缩小 | 极端定制需求的存量项目 |

**选型保守主义的一个建议**：二线框架里"被 Gunicorn ASGI 兼容套件收录"是 2026 年衡量"异步框架健康度"的客观指标（Starlette/FastAPI/Litestar/Quart/Sanic/BlackSheep 全在册、438/444 通过）——**上兼容套件意味着服务器生态持续适配，是"会被长期维护"的信号**；未收录的框架（或收录后长期不修）在选型时应当提高警惕，这是用"基础设施信号"过滤"社区热度幻觉"的实用技巧。

> 💡 **判断准则**：二线框架的"最佳时机"通常是"你不确定该不该用它"的时候——答案几乎总是回主流。真正的例外只有两个：需要 Starlette 的裸异步控制力，或团队已是某二线框架的存量持有者。新项目在三大主流中选，2026 年依然成立。

**Litestar 值得多看一眼**——它是 2026 年最活跃的"挑战者"：与 FastAPI 同源（Starlette 血统）但自带更多一等公民能力（DTO、控制器、自带 ORM Advanced Alchemy），被 Gunicorn 26 的 ASGI 兼容套件重点适配（438/444 通过）。它的主张是"FastAPI 的插件太散，我们开箱完整"——对"想要 FastAPI 体验但讨厌组装"的团队有吸引力。但现实是：**生态与招聘市场仍以 FastAPI 为绝对主体**，Litestar 适合"尝鲜型团队"，不适合"要确定性"的企业选型——它的存在意义是证明"异步框架的差异化空间仍在"，而不是取代 FastAPI。

## 4. 市场数据解读：FastAPI 的崛起曲线

FastAPI 的增长不是运气，而是一条清晰的"需求红利"曲线：

1. **2018-2020 起步**：填补"类型驱动的异步 API"空白——当时 Django/Flask 都同步为主，异步框架（Sanic/aiohttp）又缺类型生态；FastAPI 用 Pydantic + Starlette 把"类型标注"变成"校验 + 文档 + IDE 提示"三合一，体验断代式领先
2. **2021-2023 爆发**：AI 浪潮带来大量"模型服务化"需求——FastAPI 的异步流式、OpenAPI 自动文档、与 numpy/PyTorch 的顺畅集成恰好命中；OpenAI、HuggingFace 的官方示例与内部使用形成背书
3. **2024-2026 登顶**：JetBrains 38% 登顶、SO 2025 调查单年涨 4.9pt（全后端框架最大涨幅）、ML 工程师 42% 使用、超过一半的财富 500 强在生产使用（2025 年中报道）——**"API + AI"双风口让 FastAPI 完成了从挑战者到主流的跃迁**

对学习者的含义：**FastAPI 不是"又一个框架"，而是"Python 后端的新默认起点"**——但它没有吞掉 Django（全栈/后台场景 Django 依然更优），也没有杀死 Flask（教学与极简心智模型无人替代）。三者的共存不是僵局，而是分工的稳态。

再补两组观察数据，用于面试中展示"数据敏感度"：**Stack Overflow 2025 年度调查**显示 FastAPI 在所有 Web 框架中的占比从 9.9% 跃升至 14.8%（全后端框架单年最大涨幅），Flask 14.4% 紧随——注意这份调查覆盖所有 Web 技术（Node.js 48.7% 领先），绝对数字不代表 Python 生态内部份额；**PyPI 月下载量**FastAPI 约 900 万次已追平 Django。两组数据拼起来读：FastAPI 的"增速"来自存量切换（Django/Flask 迁移者）与增量需求（AI 服务），而非"凭空多出的 Python 开发者"——**Python 生态总量在增长，FastAPI 吃掉了增长中的最大份额**，这才是 38% 使用率的真实注脚。

> 🎯 **核心要点**：版图一句话——FastAPI 赢 API 与 AI（增速王），Django 赢全栈与应用（存量王），Flask 赢教学与极简（心智王）；二线框架各自"专而不全"，新项目默认三大主流，二线只在存量或极致控制力场景出场。

## 5. 核心要点与思考题

> 🎯 **本章三句话总结**：
> 1. 2026 格局：JetBrains 38%（FastAPI）/ 35%（Django）/ 34%（Flask），ML 工程师 42% 用 FastAPI；
> 2. 分类三坐标（全栈↔微框架、同步↔异步、应用↔API）决定每个框架的妥协点；
> 3. 二线框架"专而不全"，新项目默认三大主流，存量与极简控制力才轮到二线。
