## 1. 一句话定位

**Retriever 负责"取回 top-k 节点"，QueryEngine 负责"取回 + LLM 合成回答"——生产上两段分开用（一段管质量，一段管表达）**：

```text
查询链路
├── Retriever：query → embedding → 向量库相似度 → top-k Node
├── Postprocessor：过滤（相似度阈值）/重排（06 篇）
├── Synthesizer：Node 拼进上下文 → LLM 生成（response_mode 控制怎么拼）
└── QueryEngine：上面三段的组装器（一句 as_query_engine 全包）
    ——"QueryEngine = Retriever + Postprocessor + LLM 合成的标准组合"
```

**定位心智**：**"先懂 Retriever 再懂 QueryEngine——QueryEngine 只是把标准件装进一个壳"**——"**默认提示词是'根据上下文回答，不要用先验知识'——RAG 的边界意识内置'"**。

## 2. Retriever：检索器

```python
# 检索器：只取节点，不调 LLM（调试/嵌入自定义逻辑用）
retriever = index.as_retriever(similarity_top_k=5)
nodes = retriever.retrieve("LlamaIndex 支持哪些索引类型？")
print(nodes[0].node.score)      # 相似度分数
print(nodes[0].node.metadata)   # 溯源元数据

# 异步姿势（FastAPI 场景）
nodes = await retriever.aretrieve("...")
```

**要点**：① `similarity_top_k` 是检索宽度的唯一旋钮——**"调试先调它：召回不足加大，噪声过多减小"**；② 结果带 `score` 与 `metadata`——**"分数是过滤依据，metadata 是溯源依据"**；③ 检索器可自由组合——多路检索融合见 06 篇；④ 检索是"召回"不是"答案"——**"检索结果只是素材，质量由合成阶段兜底"**。

## 3. QueryEngine：问答引擎

```python
# 查询引擎：检索 + 合成一步到位（最常用入口）
query_engine = index.as_query_engine(
    similarity_top_k=5,
    response_mode="compact",
)
response = query_engine.query("LlamaIndex 支持哪些索引类型？")
print(response)            # 回答文本
print(response.source_nodes)  # 引用节点（溯源）
```

**要点**：① 一句 `as_query_engine` 拿到完整问答能力；② `response.source_nodes` 就是引用依据——**"企业级回答必须带引用（来源文件/页码）"**；③ 提示词可查可改：`query_engine.get_prompts()` / `update_prompts()`——**"默认提示词够用，特殊需求再定制"**。

## 4. response_mode：合成策略

| 模式 | 行为 | 适合 | 记忆 |
|------|------|------|------|
| compact | 能塞进窗口的节点打包成一次调用 | 默认——多数场景 | 默认 |
| refine | 一个节点一次调用，逐块精炼 | 节点内容差异大 | 慢但细 |
| tree_summarize | 分层汇总 | 总结类问答 | 树状 |
| simple_summarize | 全拼接一次生成 | 小语料 | 最省 |

**选型心智**：**"默认 compact——窗口够大（如 1M 上下文）它几乎总够用"**——"**refine 每节点一次 LLM 调用（慢），除非节点间强关联需要逐块精炼，否则别换——'先默认，出问题再调'"**。

## 5. 过滤与后处理

```python
from llama_index.core.postprocessor import SimilarityPostprocessor
from llama_index.core.vector_stores import MetadataFilters, ExactMatchFilter

# 元数据过滤：先按条件筛再取 top-k（检索阶段）
filters = MetadataFilters(filters=[
    ExactMatchFilter(key="source", value="report.pdf"),
])

# 后处理：相似度阈值砍噪声（检索后过滤）
query_engine = index.as_query_engine(
    similarity_top_k=10,
    node_postprocessors=[
        SimilarityPostprocessor(similarity_cutoff=0.7),  # 低于 0.7 丢弃
    ],
)
```

**要点**：① 过滤分两阶段——**metadata filter 在向量库内筛（省计算），SimilarityPostprocessor 在召回后砍（防噪声）**；② 阈值要按 embedding 模型实测（不同模型分数分布差异大）——**"先打印 node.score 分布，再定 cutoff"**；③ 重排器也挂在 `node_postprocessors`（06 篇）。

## 6. 聊天引擎：多轮对话

```python
# 聊天引擎：query engine + 对话历史（05 篇记忆的入口）
chat_engine = index.as_chat_engine(chat_mode="condense_plus_context", verbose=True)
resp = chat_engine.chat("你好，我叫小明")
resp = chat_engine.chat("我叫什么？")   # 记得上下文
```

**要点**：① `condense_plus_context`：先压缩历史成新问题，再检索合成——多轮最常用；② 底层是 ChatMemoryBuffer（09 篇）——可换记忆/持久化；③ **查询引擎无状态、聊天引擎有状态**——"**API 服务里按会话粒度创建/复用聊天引擎**"；④ 其他 chat_mode：`best`（自动选最优）、`context`（每轮都带全部上下文检索——上下文敏感场景）——**"默认 condense_plus_context 就够，特殊需求再换"**；⑤ 聊天引擎与查询引擎可并存——**"一个知识库同时暴露'单轮问答 API'与'多轮聊天 API'——按产品场景选（10 篇实战两个都上）"**。

**多轮检索的坑**：多轮对话中用户常只给增量信息（"那第二个呢？"）——condense 模式会先让 LLM 补全指代再检索——**"这步失败（补全错了）检索就歪——排查多轮回答怪，先看 condense 后的实际查询语句"**（`verbose=True` 打印每一步）。

## 7. 流式输出与提示词定制

**流式输出（打字机效果——SSE 聊天标配）**：

```python
# 同步流式
response = query_engine.query("问题", streaming=True)
for token in response.response_gen:
    print(token, end="")

# 异步流式（FastAPI StreamingResponse 直接消费）
stream = await query_engine.aquery("问题", streaming=True)
async for token in stream.async_response_gen():
    yield f"data: {token}\n\n"
```

**要点**：流式只流"生成的 token"——检索阶段不可见；**"先检索后流式——检索耗时在流式前就发生了（响应首字延迟 = 检索 + 首 token）"**；② 流式响应对象的 `response_txt` 要流完才有完整文本——**"前端要么自己拼 token，要么等流完再取完整文本"**；③ 聊天引擎流式：`chat_engine.stream_chat(msg)` 逐 token 消费 `response_gen`。

**带引用的回答（企业级标配）**：

```python
def format_answer(response) -> str:
    """回答 + 引用：'……（来源：report.pdf 第 3 页）'"""
    lines = [str(response)]
    for i, node in enumerate(response.source_nodes, 1):
        meta = node.node.metadata
        src = meta.get("file_name", meta.get("source", "未知"))
        page = meta.get("page_label", "")
        lines.append(f"[{i}] {src} {page}")
    return "\n".join(lines)
```

**要点**：引用数据全在 `source_nodes` 的 metadata 里——**"溯源能力在加载阶段就决定了：加载时没存 file_name/page_label，回答阶段就无引用可加（03 篇 filename_as_metadata）"**；**引用是合规与信任的底线**——"AI 幻觉的缓解靠引用：回答必须能查到出处（02-后端 的可信 AI 实践同思路）"。

**提示词定制**：

```python
from llama_index.core.prompts import PromptTemplate
from llama_index.core import get_prompt_modules

# 查看当前提示词 → 定制后更新
print(query_engine.get_prompts())
query_engine.update_prompts({
    "text_qa_template": PromptTemplate(
        "你是一个严谨的客服。只根据上下文回答，不知道就说不知道。\n"
        "上下文：{context_str}\n问题：{query_str}"
    ),
})
```

**自定义检索器**（接入私有逻辑：缓存/规则过滤/多源聚合）：

```python
from llama_index.core.retrievers import BaseRetriever

class MyRetriever(BaseRetriever):
    def _retrieve(self, query_bundle):
        return [...]   # 返回 List[NodeWithScore]

    async def _aretrieve(self, query_bundle):
        return [...]
```

**心智**：**"检索器协议 = _retrieve(query) → List[NodeWithScore]——会这一个接口就能把任意'找数据'逻辑接进 LlamaIndex"**——"**接进后 QueryEngine/Router/Agent 全部可用——'检索器是检索层的标准插座'"**。

**NodeWithScore 的结构**（写后处理/自定义逻辑前先懂它）：

```text
NodeWithScore
├── node：Node（text/metadata/node_id）
├── score：相似度/重排分数（float）
└── 来源信息：embedding/BM25/图路径……
    ——"后处理器（过滤/重排）的输入输出都是 List[NodeWithScore]"
```

**心智**：理解"检索 → 后处理 → 合成"三段式的接口契约——**"QueryEngine 的可定制点全在这条链上：换 Retriever、换 Postprocessor、换 response_mode——'三段都是可插拔的'"**（自定义 postprocessor 只需实现 `postprocess_nodes(nodes, query_bundle)`）。
