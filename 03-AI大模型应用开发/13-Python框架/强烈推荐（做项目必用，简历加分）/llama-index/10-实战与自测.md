## 1. 实战项目一：企业知识库 RAG

**目标：100 份文档 → 带引用的混合检索问答 API（简历可写：'基于 LlamaIndex 构建知识库问答系统，混合检索 + 重排后准确率提升 X%'）**：

```python
# ① 加载 + 切分 + 索引（03/04 篇）
from llama_index.core import SimpleDirectoryReader, Settings
from llama_index.core.node_parser import SentenceSplitter

Settings.llm = OpenAI(model="gpt-5-mini")
Settings.embed_model = OpenAIEmbedding(model="text-embedding-3-small")
Settings.node_parser = SentenceSplitter(chunk_size=512, chunk_overlap=20)

index = VectorStoreIndex.from_documents(
    SimpleDirectoryReader("./data", filename_as_metadata=True).load_data())
index.storage_context.persist("./storage")

# ② 生产检索配方（06 篇：召回宽 + 重排精）
from llama_index.core.retrievers import QueryFusionRetriever, BM25Retriever
from llama_index.postprocessor.cohere_rerank import CohereRerank

vector_retriever = VectorIndexRetriever(index=index, similarity_top_k=20)
bm25_retriever = BM25Retriever.from_defaults(index.docstore, similarity_top_k=20)
fusion = QueryFusionRetriever([vector_retriever, bm25_retriever], mode="relative_score")

query_engine = RetrieverQueryEngine.from_args(
    fusion, node_postprocessors=[CohereRerank(top_n=5)], response_mode="compact")

# ③ 观测 + 评估 + FastAPI 暴露（09 篇 + Python 异步体系）
set_global_handler("otlp", ...)          # 追踪
hit_rate = await retriever_eval.aevaluate(...)   # 评估基线
# FastAPI: POST /chat → query_engine.aquery(user_msg) → 返回 answer + source_nodes
```

**验收三问**：能答带引用的答案？混合检索前后评估数字有提升？重启后 from_vector_store 零重嵌入？——**"三问全过 = 项目成立"**——（环境三件套：Python 3.12+ / venv 或 uv / 显存或 API key 就绪，与 Python 框架体系其他目录一致）。

**部署注意**（上生产的三件套）：① 环境隔离——`uv`/venv + 锁版本（`llama-index-core>=0.14,<0.15`，周更版本不锁会翻车）；② 依赖最小化——只装用到的集成包（多包架构的价值就是"装什么用什么"）；③ 配置外置——OpenAI key/向量库地址走环境变量，Settings 初始化放独立模块——**"能复现 = 能部署——README 写清安装命令 + 版本清单"**。

## 2. 实战项目二：文档调研 Agent

**目标：一个"调研 → 写报告"的文档 Agent（08 篇 AgentWorkflow）——简历可写：'基于事件驱动工作流构建多 Agent 调研系统，支持人机协同审批'**：

```text
调研 Agent 流程
├── Researcher：检索/读文档 → 产出事实摘要
├── Reviewer：核查摘要与引用的忠实度 → 通过/驳回
└── Writer：合成最终报告（output_cls 结构化输出）
    ——"handoff 转交 + ctx.store 共享 + 人机审批点：三件套全用上"
```

**讲项目 3 分钟模板**：① 背景（100 份文档、人工调研慢）；② 方案（LlamaIndex 检索 + AgentWorkflow 分工）；③ 亮点（混合检索重排、多 Agent handoff、人机审批、OTel 追踪）；④ 数字（评估 HitRate、P95 延迟、成本）——**"能讲清'为什么这么设计'才算会"**。

**项目二代码骨架**（照着填即可跑通）：

```python
from llama_index.core.agent.workflow import AgentWorkflow, FunctionAgent

researcher = FunctionAgent(
    name="Researcher",
    tools=[query_engine.as_tool(description="知识库问答——用于收集事实")],
    system_prompt="只输出带引用的事实列表",
    can_handoff_to=["Writer"],
)
writer = FunctionAgent(
    name="Writer",
    tools=[],
    system_prompt="把事实列表写成结构化报告",
    can_handoff_to=[],
)
agent_workflow = AgentWorkflow(
    agents=[researcher, writer], root_agent="Researcher",
)
resp = await agent_workflow.run(
    user_msg="调研 LlamaIndex 的检索优化手段并出报告",
    output_cls=Report,
)
```

**要点**：`query_engine.as_tool()` 是"检索器 → Agent 工具"的一行转换——**"05 篇的查询引擎直接变成 Agent 的'知识工具'——'检索 + Agent 的拼装点就在这里'"**。

## 3. 报错速查

| 报错 | 原因 | 解法 |
|------|------|------|
| 版本不符（0.10 教程报错） | API 已变 | 查官方文档最新写法（0.13 融合检索/0.14 Workflows） |
| HybridQueryEngine 不存在 | 0.13.0 移除 | QueryFusionRetriever + RetrieverQueryEngine（06 篇） |
| mode 缺失报错 | 0.13+ 必填 | PropertyGraphIndex.from_documents(mode="llm") |
| embedding 维度不匹配 | 建索引与查询用不同模型 | Settings.embed_model 全局唯一（02 篇） |
| token 超限 | context_window 没设 | Settings.context_window + token_limit（02/09 篇） |
| 加载器 ImportError | 集成包没装 | pip install llama-index-readers-xxx（03 篇） |
| 检索结果全为空 | top_k 太小/向量库没数据 | 查 vector_store 文档数 + 加大 top_k |
| 回答没引用上下文 | 元数据没传/提示词被覆盖 | 检查 metadata 继承 + get_prompts 验证 |
| 记忆串会话 | memory 全局共享 | 每会话独立 memory + session_id 持久化（09 篇） |

**排障方法论**：先看版本 → 再看报错第一行 + 最后一行 → 最小复现——**"70% 的坑是版本/依赖——锁版本区间是第一步"**。

## 4. 面试三范式

**范式一：框架价值式**——"LlamaIndex 解决什么？数据侧四环节（接入/切分/检索/关系）标准化——对比手写 RAG：切分调参、混合检索融合、溯源都要自己造"。

**范式二：版本对比式**——"0.13/0.14 的变化：HybridQueryEngine → QueryFusionRetriever、QueryPipeline → Workflows、PropertyGraphIndex 显式 mode——体现关注官方演进（每周 release notes）"。

**范式三：选型式**——"LlamaIndex vs LangChain：数据 vs 编排——纯 RAG 选 LlamaIndex（检索质量开箱即用），复杂 Agent 选 LangGraph，混合架构 LlamaIndex 当检索层——'先定需求再选框架'"。

**加分项（项目细节经得起追问）**：① 为什么 chunk_size=512？（文档段落粒度 + 评估验证——不是抄的）；② 混合检索为什么有效？（向量懂语义、BM25 懂字面——专有名词场景实测）；③ 图谱为什么不用？（答案都在单段内——成本收益算过账）；④ 成本怎么控的？（重排 top_n 限制 + 查询改写次数 + 观测响应成本）——**"每句话都有数字和理由 = 面试加分"**。

**检索（05-06）**：9. Retriever/QueryEngine 区别？（取节点 vs 取+合成）10. response_mode 默认？（compact）11. 生产检索配方？（召回 20 + 重排 top5）12. 混合检索 0.13+ 写法？（QueryFusionRetriever + mode 必填）13. 重排为什么有效？（强模型精排——交叉编码器）
