## 1. 实战项目：RAG 文档管道

**项目目标**：把"PDF + Word + 扫描件"混合文档库变成 milvus 里的可检索向量库——**全格式 → 策略匹配 → 清洗 → 分块 → 入库**五段式管道，验收标准：**检索结果的每个 chunk 带来源（文件名 + 页码）且内容干净**。

**步骤一：策略匹配器**（按文件类型与特征选策略——04 篇决策表的代码化）：

```python
from unstructured.partition.pdf import partition_pdf
from unstructured.partition.docx import partition_docx
from unstructured.partition.image import partition_image

def pick_partitioner(path: str, is_scan: bool = False):
    ext = path.rsplit(".", 1)[-1].lower()
    if ext in ("png", "jpg", "jpeg", "tiff"):
        return lambda: partition_image(filename=path, strategy="ocr_only")
    if ext == "pdf" and is_scan:
        return lambda: partition_pdf(filename=path, strategy="hi_res",
                                     languages=["chi_sim", "eng"])
    if ext == "pdf":
        return lambda: partition_pdf(filename=path, strategy="fast")
    if ext == "docx":
        return lambda: partition_docx(filename=path)
    raise ValueError(f"不支持的格式: {ext}")
```

**步骤二：清洗管线**（06 篇五步）：

```python
def clean_elements(elements):
    els = [el for el in elements
           if el.category not in ("Header", "Footer", "PageBreak", "PageNumber")]
    els = [el for el in els if len(el.text.strip()) >= 10]
    for el in els:
        el.text = " ".join(el.text.split())          # 空白归一
    seen, out = set(), []
    for el in els:
        key = (el.metadata.get("page_number"), el.text.strip())
        if key not in seen:
            seen.add(key); out.append(el)
    return out
```

**步骤三：分块 + 入库**（07 篇 + milvus‑python 体系打通）：

```python
from unstructured.chunking.title import chunk_by_title
from pymilvus import MilvusClient

def store_chunks(elements, source: str, client: MilvusClient):
    chunks = chunk_by_title(elements, max_characters=2000, overlap=200,
                            include_roles=["Title", "NarrativeText", "ListItem", "Table"])
    records = [{
        "id": f"{source}-{i}",
        "text": c.text,
        "source": source,
        "page": c.metadata.get("page_number", 0),
        "embedding": embed(c.text),
    } for i, c in enumerate(chunks)]
    res = client.insert("docs", data=records)
    assert res["insert_count"] == len(records)     # milvus 纪律：检查 insert_count
```

**步骤四：管道入口**（断点续跑 + 日志）：

```python
import json, os
from loguru import logger

def build_index(document_dir: str):
    done = set(json.load(open("done.json"))) if os.path.exists("done.json") else set()
    for root, _, files in os.walk(document_dir):
        for fn in files:
            if fn in done or not fn.rsplit(".", 1)[-1].lower() in SUPPORTED:
                continue
            path = os.path.join(root, fn)
            try:
                elements = pick_partitioner(path)()
                cleaned = clean_elements(elements)
                store_chunks(cleaned, path, milvus)
                done.add(fn); json.dump(sorted(done), open("done.json", "w"))
                logger.info("已入库 {} 共 {} 块", fn, len(cleaned))
            except Exception:
                logger.exception("解析失败 {}", fn)      # 失败留痕，管道继续
```

**验收三问**：**一**，混合文档全部入库且 `done.json` 记录完整（断点续跑可用）；**二**，抽查检索结果——"回答来源带文件名与页码"（溯源成立）；**三**，扫描件文档可检索（OCR 策略生效）。**加试一题**：把管道接入 LangChain（UnstructuredLoader + 自己的清洗）对比差异（08 篇）。

## 3. 报错速查

| 报错 | 原因 | 解法 |
|------|------|------|
| `ImportError: No module named 'pdfminer'` | 缺 [pdf] extras | `pip install "unstructured[pdf]"`（02 篇） |
| `AttributeError: module 'unstructured.partition.auto' has no attribute...` | 老 import 姿势 | 用格式专属分区器（00 篇误区六） |
| `ValueError: invalid strategy` | 策略名写错 | `auto/fast/hi_res/ocr_only`（04 篇） |
| `FileNotFoundError: tesseract` | OCR 引擎没装 | 装 tesseract + 配 PATH（04 篇） |
| `ImportError: No module named 'detectron2'` | hi_res 缺依赖 | `pip install "unstructured[local-inference]"`（04 篇） |
| 扫描件解析为空 | 策略没选 OCR | `strategy="hi_res"/"ocr_only"`（04 篇坑一） |
| 表格解析成碎文本 | fast 策略 | hi_res + infer_table_structure（05 篇坑三） |
| 中文 OCR 全丢 | 缺语言包/参数 | `languages=["chi_sim"]` + 装语言包（04 篇坑四） |
| 内存爆（200 页） | 一把梭解析 | 分页 + 批处理 + 限额（09 篇坑二） |
| `metadata` 点访问报错 | 0.15+ dict 风格 | `el.metadata["key"]`（03 篇坑一） |

## 4. 面试三范式

**范式一：价值式**——"RAG 数据预处理为什么用 unstructured"：PDF 是 RAG 最大坑（多列/表格/扫描件），unstructured 输出**带类型与元数据的 Elements**（标题/正文/表格 + 页码/坐标），"**无 metadata 的 RAG 是黑箱检索，有 metadata 的 RAG 可审计**"（03 篇）。

**范式二：技术式**——"解析策略怎么选"：**"默认 fast、复杂上 hi_res、扫描必 OCR"**——hi_res 用布局模型（YOLOX/Chipper/VLM）还原版面与表格，代价是 CPU 3-5 页/分、200 页 4-6GB 内存——**"策略是质量与速度的交易，先小样本验证再全量跑"**（04 篇）。

**范式三：生产式**——"文档管道怎么设计的"：回答链路——**策略匹配器（按格式/扫描件）→ 解析 → 清洗五步（过滤页眉页脚/去重/排序）→ chunk_by_title（表格 include_roles）→ milvus 入库（metadata 溯源）→ 断点续跑 + Docker 部署**——**能完整讲出这条链 = 有真实 RAG 落地经验**（10 篇实战）。

**追问应对**（面试官往下挖的四个点）：问"表格怎么处理"答"hi_res + infer_table_structure 出 text_as_html 结构化表示，chunk_by_title 显式 include_roles=['Table']，表格不碎成文本"（05/07）；问"扫描件怎么解析"答"策略走 hi_res（版面模型理解后再 OCR）或 ocr_only，中文加 languages=['chi_sim']"（04）；问"性能与资源"答"hi_res CPU 3-5 页/分、200 页 4-6GB，生产 Docker 隔离 + 分页批处理 + GPU 可选"（09）；问"和框架 loader 什么关系"答"UnstructuredLoader 是封装，底层同 partition——裸库控制力强，框架接生态"（08）——**每一问都有对应篇目的答案**。

**把文档管道写进简历**：项目描述加一条——"**基于 unstructured 搭建 RAG 文档管道：全格式解析（PDF/Word/扫描件）+ 策略匹配 + 清洗分块 + milvus 入库（metadata 溯源），支持中文 OCR 与断点续跑**"——这一条体现**真实文档处理能力 + RAG 工程化落地**，与 milvus‑python 的"检索存储层"简历条目构成**"预处理 + 检索"双段组合**（00 篇分工）。
