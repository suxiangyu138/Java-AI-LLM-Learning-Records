## 1. 策略是什么：质量与速度的交易

**strategy 参数决定"用什么技术解析"**——与向量索引的"速度与精度交易"同构（milvus 06 篇），unstructured 的解析也是交易：**解析质量（结构识别准确性）↔ 解析速度与资源消耗**。`partition_pdf(filename=..., strategy="fast")`——**"策略选错，解析白费"**是本文的核心警告：默认 auto 可能选到不匹配文档类型的策略，解析结果质量崩盘。

**为什么需要多策略**：文档世界差异巨大——**干净的数字 PDF**（文字可选中、排版简单）、**复杂版面**（多列、嵌套表格、图文混排）、**扫描件**（纯图片、无文字层）——**没有一种策略通吃**，四策略就是四个档位的技术组合。

## 2. 四策略原理

| 策略 | 技术 | 特点 | 适用 |
|------|------|------|------|
| `auto` | 自动探测 | 按文档特征选择 | 默认——不确定时 |
| `fast` | pdfminer + 启发式（字体/位置/正则） | 快（毫秒-秒级）、轻量 | **干净数字 PDF** |
| `hi_res` | 布局 ML 模型（YOLOX/Detectron2 等） | 准（版面/表格/多列）、慢 | 复杂版面/表格 |
| `ocr_only` | OCR（Tesseract 等） | 唯一能读扫描件 | **扫描件/纯图片 PDF** |

**auto 的局限**：自动探测不是万能——对"文字层存在但排版复杂"的 PDF 可能选 fast（快但结构差）——**"auto 是起点，关键文档显式指定策略"**。

**fast 的原理**：pdfminer 提取文字 + 启发式分类（按字体大小/位置判断标题正文）——**没有版面模型，多列会乱序、表格会碎裂**；但它快且依赖轻——**"干净的文档 fast 够用且最优"**。

**hi_res/ocr_only**：重依赖（`[local-inference]`/tesseract），慢但准/能读——**"精度换速度"的两档**。

## 3. 性能账单

**性能数据（官方与社区实测基准）**：

| 指标 | fast | hi_res（CPU） |
|------|------|--------------|
| 速度 | 毫秒-秒级/页 | **3-5 页/分钟** |
| 内存（200 页 PDF） | 低 | **4-6 GB** |
| 依赖 | 轻（pdfminer） | 重（布局模型 数百 MB+） |
| GPU | 不需要 | **可加速（快数倍）** |

**账单的工程含义**：**hi_res 不是"慢一点"，是"数量级不同 + 内存数量级不同"**——**批量解析 1 万页文档用 hi_res = 33 小时 CPU 单机**——生产架构必须考虑：**GPU 加速、并行、Docker 隔离、或托管 API**（09 篇）。**"先问文档类型，再定策略，最后算账单"**是生产选型的完整顺序。

## 4. 选型决策表

| 文档类型 | 策略 | 理由 |
|---------|------|------|
| 干净数字 PDF（文字可选中、单列） | `fast` | 快且够准 |
| 多列排版（论文/杂志） | `hi_res` | 坐标还原阅读顺序 |
| 含复杂表格 | `hi_res` | 表格边界提取 |
| 扫描件/纯图片 PDF | `ocr_only` 或 `hi_res` | 必须 OCR |
| 图片（PNG/JPG） | `partition_image` + ocr_only | 图片分区器 |
| 不确定 | `auto` 起步 → 抽样验证 | 看类型分布再定（02 篇） |

**决策心法**：**"默认 fast，复杂上 hi_res，扫描必 OCR"**——再加一条：**"先小样本验证，再全量跑"**（10 篇实战的管道节奏）——策略选型不是拍脑袋，是"抽 5 页看类型分布"后的决定。**混合策略也是选项**：批量管道里"按文档特征分流"（简单文档 fast 队列、扫描件 hi_res 队列并行处理——09 篇"按文档复杂度分队列"）——**"不是全库一个策略，是每类文档一个策略"**是生产管道的精细化姿势。

## 5. hi_res 详解：布局模型家族

hi_res 的底层是**版面分析模型**，几个选项（`model_name` 参数）：

| 模型 | 类型 | 特点 |
|------|------|------|
| YOLOX | 目标检测 | 快、版面框检测 |
| Detectron2 | 实例分割 | 经典布局模型 |
| Chipper | unstructured 专用模型 | 表格/版面综合最优（官方推荐） |
| VLM（GPT-4o 等） | 视觉语言模型 | 最强理解力、最贵最慢 |

**hi_res 的产出升级**：**表格边界精确**（Table 元素带 text_as_html 结构）、**多列按阅读顺序重组**（03 篇坐标）、**图文关系识别**（Image + FigureCaption 关联）——**"hi_res = 版面理解，不只是文字提取"**。**选型**：默认 Chipper（官方优化）；VLM 是"金钱换质量"的终极档（贵、慢、但复杂文档理解最强——2026 年托管 API 的推荐档位之一）。

## 6. OCR 详解：三件套

**OCR（光学字符识别）把图片里的文字变成可检索文本**——扫描件的唯一出路。unstructured 支持三个引擎：

| 引擎 | 特点 | 依赖 |
|------|------|------|
| Tesseract | 经典开源 OCR、**100+ 语言** | tesseract 系统包 + `pytesseract` |
| DocTR | 深度学习 OCR、准确率高 | `unstructured[local-inference]` |
| Google Vision | 云 OCR、最强 | 云凭证（托管 API 里可用） |

```python
# 扫描件标准姿势：ocr_only + 语言参数
elements = partition_pdf(filename="scan.pdf",
                         strategy="ocr_only",
                         languages=["chi_sim", "eng"])   # 中文简体 + 英文
```

**三个要点**：**中文 OCR**——`languages=["chi_sim"]`（Tesseract 的中文模型要单独装语言包）；**OCR 是准入门**——`[local-inference]` 装的是布局模型，**OCR 引擎要单独配**（tesseract 系统级安装，Windows 要配 PATH）；**OCR 结果无坐标语义**——它是"图片 → 文本"，版面结构靠 hi_res 层补——**"扫描件最佳实践是 hi_res（模型先理解版面再 OCR 内容）"**，ocr_only 是轻量备选。

## 7. 策略切换实践

```python
# 从 fast 切 hi_res 的完整动作（不止改参数！）
# 1. 装依赖
# pip install "unstructured[local-inference]"
# 2. 改参数
elements = partition_pdf(filename="complex.pdf",
                         strategy="hi_res",
                         model_name="chipperv2",        # 官方推荐模型
                         infer_table_structure=True)     # 表格结构提取
# 3. 验证：类型分布 + 表格完整性 + 坐标存在性
```

**切换检查单**：依赖（`[local-inference]`）→ 参数（strategy/model_name/infer_table_structure）→ **验证（类型分布有没有 Table/坐标齐不齐）**——**"切了策略不验证 = 白切"**（02 篇三步调试法）。

## 8. 常见坑

**坑一：扫描件用 fast**——解析结果全空或乱码；**扫描件必 OCR/hi_res**（第 2 节）。

**坑二：hi_res 没装依赖**——`unstructured_inference` 缺失报错；**切 hi_res 先装 `[local-inference]`**（第 7 节）。

**坑三：CPU 上批量 hi_res**——33 小时级账单；**先算性能账（第 3 节）再排架构**。

**坑四：中文 OCR 没语言包**——中文全丢；**`languages=["chi_sim"]` + 装语言包**（第 6 节）。

**坑五：auto 当万能**——复杂文档 auto 选了 fast 质量崩盘；**关键文档显式指定 + 抽样验证**（第 4 节）。
