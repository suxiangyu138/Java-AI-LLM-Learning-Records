## 1. 为什么需要清洗

**解析出来 ≠ 可以入库**——真实文档解析后的常见污染：

**页眉页脚与分页符**——每页重复的"公司名 + 页码"进向量库是**检索噪音**（相似度计算被重复文本污染）；**乱码与编码残留**——OCR 的误识别、特殊字符转义残留（`\uXXXX`、`&amp;`）；**重复内容**——文档更新产生的重复段落、合并文档的重复章节；**无意义文本**——邮件签名、网页导航、页脚链接。

**清洗的价值**：**向量检索的质量上限由"入库内容"决定**——脏数据进库 = 脏结果出库——**"清洗是 RAG 质量的隐形分水岭"**（与 pyyaml 07 篇"值合法 ≠ 可用"同理：解析成功 ≠ 内容干净）。

## 2. clean 函数家族

unstructured 提供 `cleaners` 模块的清洗函数（文本级）：

```python
from unstructured.cleaners.core import (
    clean_extra_whitespace,     # 合并多余空白/换行
    clean_non_ascii_chars,      # 去掉非 ASCII 字符
    clean_ligatures,            # 连字展开（ﬁ → fi）
    clean_bullets,              # 去列表符号（• 等）
    clean_dashes,               # 破折号统一
    clean_trailing_punctuation, # 去尾部标点
    clean_quotes,               # 引号统一
    replace_unicode_quotes,     # Unicode 引号 → ASCII
    clean_emojis,               # 去 emoji
    clean_headers_footers,      # 页眉页脚清洗（按文本匹配）
)

text = "  Hello   World  •  item\r\n"
print(clean_extra_whitespace(text))   # "Hello World • item"
```

**用法两种**：**手动调用**（清洗某个文本后重新赋值 `el.text = clean_extra_whitespace(el.text)`）或**分区时传入**（`partition_pdf(..., clean_extra_whitespace=True)`——分区器内置清洗开关）。**选型**：分区时开常用的（空白/连字），**业务定制清洗（页眉页脚/邮件签名）写在自己管线里**（第 3 节）。

## 3. 元素级清洗姿势

**元素级清洗 = 过滤 + 改写**（03 篇 Element 操作的进阶）：

```python
# 过滤：页眉页脚与分页符（入库前标配）
keep = [el for el in elements
        if el.category not in ("Header", "Footer", "PageBreak")]

# 过滤：正文可读性阈值（太短的元素是噪音）
keep = [el for el in keep if len(el.text) >= 10]

# 改写：文本级清洗（空白 + 连字）
for el in keep:
    el.text = clean_extra_whitespace(el.text)

# 定制：页眉页脚按内容匹配（公司名/版权行）
NOISE = ("© 2026 Acme Corp", "Confidential - Internal")
keep = [el for el in keep
        if not any(n in el.text for n in NOISE)]

# 定制：邮件签名/网页导航去噪
keep = [el for el in keep if not el.text.startswith("Sent from")]
```

**"过滤是判断题（留不留），改写是清洗题（变干净）"**——两类动作组合成完整清洗管线（第 6 节）；**注意**：`el.text` 可直接赋值改写（Element 是可变对象）——**"清洗管线 = 过滤列表 + 改写元素"两句话**。

## 4. 去重与哈希

**重复内容去重的两个层次**：

```python
# 层次一：元素级去重（内容完全相同的元素——合并文档常见）
seen = set()
deduped = []
for el in elements:
    key = el.text.strip()
    if key not in seen:
        seen.add(key)
        deduped.append(el)

# 层次二：基于 metadata 的 element_hash（unstructured 自带哈希）
from unstructured.documents.elements import Element
hashes = {el.metadata.get("element_hash") for el in elements}
# 哈希相同的元素 = 内容指纹相同（可在入库前比对历史指纹做增量）
```

**element_hash 的增量价值**：**文档更新时只重灌哈希变化的段落**——"指纹去重 = 增量更新的依据"（与爬虫体系的 MD5 内容指纹同思想，00 篇分工）；**注意**：**哈希是内容指纹不是文档指纹**——段落级去重，不是文件级。

## 5. 输出转换家族

解析结果可以转成多种格式（`convert_*` 与 staging 模块）：

```python
from unstructured.staging.base import (
    elements_to_json,         # Elements → JSON 字符串
    elements_from_json,       # JSON → Elements（round-trip）
    convert_to_dataframe,     # → pandas DataFrame
    convert_to_csv,           # → CSV
    convert_to_dict,          # → dict 列表
)
from unstructured.staging.markdown import elements_to_markdown  # → Markdown

# JSON：持久化 + 断点续处理的交接格式（推荐）
json_out = elements_to_json(elements)
# 恢复
elements_again = elements_from_json(json_out)

# DataFrame：pandas 生态（分析/抽样检查）
df = convert_to_dataframe(elements)
print(df[["type", "text", "page_number"]].head())
```

**选型**：**JSON 是推荐的中间格式**（元素与元数据全量保留、可 round-trip 恢复——**管道中断点续跑的依据**）；DataFrame 用于**抽样分析**（类型分布/文本质量检查——02 篇三步调试的进阶版）；Markdown 用于**人工审阅**（人读友好）。**注意**：`elements_to_json` 会丢弃部分 metadata（坐标等）——**需要全量保真时先存原始 Elements 或选 JSON 细节参数**（00 篇误区六的延伸）。

**转换与清洗的衔接**：**"先清洗后转换"**是标准顺序——清洗改的是 Elements 对象（内存态），转换是"把清洗结果落成格式"（持久态）——**顺序反了（先转再洗）等于清洗了又转一份没洗的**；**管道里的 JSON 交接点**：解析 → 清洗 → **JSON 落盘** → 分块（从 JSON 恢复）——**"JSON 是清洗后的快照，分块从快照继续"**（02 篇完整示例的延续，省去重解析的时间账单）。

## 6. 清洗管线设计

完整清洗管线的标准形状（**解析 → 过滤 → 改写 → 去重 → 转换**五步）：

```python
def clean_pipeline(elements):
    # 1. 类型过滤：不要页眉页脚/分页符
    els = [el for el in elements
           if el.category not in ("Header", "Footer", "PageBreak", "PageNumber")]
    # 2. 内容过滤：可读性阈值 + 噪音匹配
    els = [el for el in els if len(el.text.strip()) >= 10]
    # 3. 文本改写：空白/连字/统一引号
    for el in els:
        el.text = clean_extra_whitespace(el.text)
    # 4. 去重：内容指纹
    seen = set(); out = []
    for el in els:
        key = el.text.strip()
        if key not in seen:
            seen.add(key); out.append(el)
    # 5. 排序：页码 + 坐标还原阅读顺序
    out.sort(key=lambda el: (el.metadata.get("page_number", 0),
                             el.metadata.get("coordinates", {}).get("points", [(0, 0)])[0][1]))
    return out
```

**设计原则**：**顺序固定（先过滤再改写再去重再排序）**——改写后去重（脏文本去重会漏掉）；**每一步可开关**（调试时逐级开）；**清洗是纯函数**（输入 Elements 输出 Elements——可测试可复用）。**"清洗管线是 RAG 管道里的质检环"**——写进 10 篇实战的完整管道。

**清洗与去重的边界**（别把两件事混为一谈）：**清洗治"脏"**（空白/连字/噪音——文本质量），**去重治"重"**（重复内容——数据冗余）；**脏文本去重会漏掉重复**（"Hello   World"与"Hello World"哈希不同——**先清洗再去重**是第 6 节顺序的依据）；**去重后还要防"近似重复"**（同一内容不同版本——精确去重管不住，靠语义哈希/相似度聚类，属进阶，见 RAG 体系）。

## 7. 常见坑

**坑一：不洗页眉页脚**——每页重复文本污染相似度；**类型过滤必做**（第 3 节）。

**坑二：先排序后过滤**——过滤掉元素后排序语义乱；**先过滤再排序**（第 6 节顺序）。

**坑三：清洗太狠**——去 emoji/去标点把语义信息删了（"30%!"变"30"）；**清洗参数按内容类型权衡**（第 2 节选型）。

**坑四：去重只看文本不看页码**——不同页的相同文本（重复出现的章节标题）被误删；**去重键带页码**（第 4 节）。

**坑五：elements_to_json 丢 metadata**——round-trip 后坐标没了；**确认转换保真度**（第 5 节）。
