## 1. 安装与 extras 依赖体系

unstructured 的依赖按格式拆分（extras），**按需安装是纪律**（全量装 `[all-docs]` 约 2GB）：

```bash
pip install "unstructured==0.24.1"          # 核心：文本/html/markdown/邮件
pip install "unstructured[pdf]"             # + PDF（pdfminer/pikepdf/pypdf）
pip install "unstructured[docx]"            # + Word
pip install "unstructured[pptx]"            # + PowerPoint
pip install "unstructured[xlsx]"            # + Excel
pip install "unstructured[local-inference]" # + hi_res 策略（布局模型）
pip install "unstructured[all-docs]"        # 全格式（2GB，谨慎）
```

**三个要点**：其一，**锁版本**——0.22→0.24 三个月跨三个大版本（01 篇），`==0.24.1` 或 `>=0.24,<0.25`；其二，**缺 extras 的症状是 ImportError 而不是文档解析失败**——`partition_pdf` 报"pdfminer 找不到"就是忘了 `[pdf]`；其三，**hi_res 与 OCR 是重依赖**——`[local-inference]`（detectron2/布局模型）与 tesseract（OCR）体积大、安装有系统依赖（Windows 上 tesseract 要单独装）——**"原型 fast 起步，需要精度再上重依赖"**（04 篇策略与依赖对应）。

## 2. partition 家族：统一入口

**2026 年的 import 姿势**（0.10.0 起 `partition.auto` 已移除——00 篇误区六）：

```python
from unstructured.partition.pdf import partition_pdf        # PDF/扫描件
from unstructured.partition.docx import partition_docx      # Word
from unstructured.partition.pptx import partition_pptx      # PPT
from unstructured.partition.xlsx import partition_xlsx      # Excel
from unstructured.partition.html import partition_html      # HTML
from unstructured.partition.text import partition_text      # TXT/Markdown
from unstructured.partition.image import partition_image    # 图片（OCR）
from unstructured.partition.email import partition_email    # 邮件 EML/MSG
from unstructured.partition.md import partition_md          # Markdown 专属
```

**统一心智**：**"格式专属分区器，一个 API 风格"**——所有 partition 函数签名一致（`filename` 或 `file` + 各自专属参数），输出都是 Elements 列表——**"换格式只换函数名，下游代码零改动"**是这套设计的核心价值（01 篇问题三）。函数名即格式（pdf/docx/pptx/xlsx/html/text/image/email/md）——**记忆即用，不用查文档**。

## 3. 第一个 Elements 输出

```python
from unstructured.partition.pdf import partition_pdf

elements = partition_pdf(filename="report.pdf")

for el in elements[:5]:
    print(el.category)        # 元素类型：Title/NarrativeText/ListItem...
    print(el.text)            # 文本内容
    print(el.metadata)        # 元数据：页码/坐标/语言/来源
```

**输出结构三层**：**category**（类型——RAG 过滤/分块的依据）、**text**（内容）、**metadata**（溯源——`page_number`、`coordinates`、`languages`、`filename`、`filetype`、`last_modified`）。**一句话看懂输出**："第 3 页有一个 Title 元素，内容是《2026 年报》，坐标在页面左上"——**这就是"结构化文档"的精确含义**（03 篇详讲 Element 模型）。**全量输出习惯**：`for el in elements: print(el.category, "|", el.text[:50])`——一眼看出解析质量。

## 4. 输入姿势：文件/流/URL

partition 家族支持三种输入：

```python
# 姿势一：文件路径（最常用）
elements = partition_pdf(filename="docs/report.pdf")

# 姿势二：文件对象（已打开的流——内存/网络流场景）
with open("docs/report.pdf", "rb") as f:
    elements = partition_pdf(file=f)

# 姿势三：URL 抓取（partition_html 支持 url 参数）
elements = partition_html(url="https://example.com/docs/guide")

# 姿势四：原始字节（requests 下载后直接解析）
import requests
resp = requests.get("https://example.com/doc.pdf")
elements = partition_pdf(file=resp.content)   # 字节流直接进
```

**选型**：本地文件用 `filename`（内部自动打开）；**下载的/内存的数据用 `file=`**（bytes 或文件对象）；HTML 远程抓取用 `url=`——**"本地用 filename、远程用 file/url"** 是输入选型一句话。注意：`file=` 传 bytes 与传文件对象都行，但**部分格式分区器对文件对象有 seek 要求**（流式场景要 `io.BytesIO` 包一层）。

**批量输入的姿势**（多文档管道）：**目录 + 循环**是标准形态——`os.listdir`/`glob` 拿到文件列表 → 逐个调分区器（05 篇的注册表模式）→ 每个文档的 Elements 独立处理（清洗/入库）——**"批量 = 循环 + 注册表 + 断点记录"**（10 篇实战的 done.json 就是断点记录）；**性能注意**：逐个解析是顺序的，**批量管道要并发（09 篇并发三纪律）**——"输入姿势从单文档到批量，是原型到生产的距离"。

## 5. 快速调试姿势

**三步调试法**（任何解析问题的起点）：

**第一步：类型分布**——先看解析出了什么：

```python
from collections import Counter
print(Counter(el.category for el in elements))
# Counter({'NarrativeText': 120, 'Title': 15, 'Table': 3, ...})
```

**类型分布是解析质量的晴雨表**：正文占比合理、有标题有表格 = 解析健康；全是一坨 NarrativeText 或大量空元素 = 策略不对（04 篇换策略）。

**第二步：抽样看内容**——打印前 20 个元素的类型 + 文本前 50 字，**看分类对不对、文本干不干净**（乱码/页眉页脚 → 06 篇清洗）。

**第三步：查特定元素**——表格/图片有没有被正确识别（`[el for el in elements if el.category == "Table"]`），坐标与页码是否合理（03 篇 metadata）。

**"先看类型分布，再抽内容，最后查专项"**十分钟定位 90% 的解析问题（10 篇报错速查配合）。

**调试的进阶姿势——抽样脚本化**（多文档管道的质量抽查，02 篇三步的工程化）：

```python
import json
from collections import Counter

def quality_report(elements):
    dist = Counter(el.category for el in elements)
    empty = sum(1 for el in elements if not el.text.strip())
    tables = [el for el in elements if el.category == "Table"]
    return {
        "元素总数": len(elements),
        "类型分布": dict(dist.most_common(5)),
        "空元素数": empty,           # 空元素过多 = 解析失败信号
        "表格数": len(tables),       # 表格缺失 = 策略/参数问题
        "最大文本长度": max((len(el.text) for el in elements), default=0),
    }

print(json.dumps(quality_report(elements), ensure_ascii=False, indent=2))
```

**"质量报告进管道日志"**——每批文档解析后打一份（loguru 留痕，00 篇分工）——**"解析质量是管道指标，不是一次性检查"**（异常自动暴露在监控里）。

## 6. 完整示例：解析 → 检查 → 交接

一个"解析 → 类型检查 → JSON 交接"的完整闭环（把本篇与 03/06 篇串起来）：

```python
from unstructured.partition.docx import partition_docx
from unstructured.staging.base import elements_to_json, elements_from_json

# 1. 解析
elements = partition_docx(filename="guide.docx")

# 2. 检查：类型分布 + 抽样（02 篇三步调试）
from collections import Counter
print(Counter(el.category for el in elements))
for el in elements[:5]:
    print(el.category, "|", el.text[:40])

# 3. 交接：JSON 持久化（管道断点/跨进程）
json_out = elements_to_json(elements)
with open("parsed.json", "w", encoding="utf-8") as f:
    f.write(json_out)

# 4. 恢复（下游处理从 JSON 继续，不用重解析）
with open("parsed.json", encoding="utf-8") as f:
    elements_again = elements_from_json(f.read())
```

**这个闭环的三个要点**：**解析一次、交接多次**——JSON 是管道中间格式（06 篇转换家族，重跑管道不用重新解析——省掉 hi_res 的时间账单）；**检查在交接前**——类型分布不健康就先调策略再交接；**round-trip 可恢复**——`elements_from_json` 还原 Elements 继续处理（清洗/分块）。**"先解析检查，再 JSON 交接，后处理从 JSON 继续"**是文档管道的标准节奏（10 篇实战）。

## 7. 常见坑

**坑一：extras 没装全**——ImportError（`No module named 'pdfminer'` 等）；**按格式装 extras**（第 1 节）。

**坑二：import 老姿势**——`from unstructured.partition.auto import partition` 报错——**0.10.0 已移除，用格式专属分区器**（00 篇误区六）。

**坑三：扫描件默认策略解析为空**——fast 策略对纯图片 PDF 无能为力；**扫描件显式 `strategy="hi_res"` 或 `"ocr_only"`**（04 篇）。

**坑四：表格解析成文本流**——没开表格提取或表格在 hi_res 下才完整；**表格文档用 hi_res + infer_table_structure**（05 篇）。

**坑五：版本漂移**——0.22 教程的 API 在 0.24 行为变化；**锁版本 + 读 changelog**（第 1 节）。

**坑六：把 URL 抓取当通用下载器**——partition_html 的 url 只抓静态 HTML；**要下载 PDF/其他格式用 requests 下载后 file= 传入**（第 4 节）。

**坑七：忽略语言检测结果**——languages 是检测不是强制；**需要特定语言解析时显式 languages 参数**（04 篇 OCR 语言）。

**坑八：URL 抓取忽略 robots/合规**——partition_html 抓网页要遵守 robots.txt 与爬取频率（与 12-Python 爬虫的合规纪律同源）；**"解析他人网页前先想合规"**（数据合规在 01 篇边界的延伸）。
