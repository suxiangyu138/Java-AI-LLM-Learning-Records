## 1. 实战项目：FastAPI 完整日志体系

**项目目标**：给一个 FastAPI 支付服务配上生产级日志——四要素：**文件轮转 + JSON 结构化 + trace_id 全链路 + 第三方库接管**。

**步骤一：日志配置模块**（`app/logging_config.py`）：

```python
import logging
import sys
from loguru import logger

class InterceptHandler(logging.Handler):
    def emit(self, record):
        try:
            level = logger.level(record.levelname).name
        except ValueError:
            level = record.levelno
        frame, depth = logging.currentframe(), 2
        while frame and frame.f_code.co_filename == logging.__file__:
            frame = frame.f_back
            depth += 1
        logger.opt(depth=depth, exception=record.exc_info).log(level, record.getMessage())

def setup_logging():
    logger.remove()
    logger.add("logs/app.jsonl", serialize=True,
               rotation="500 MB", retention="30 days", compression="zip",
               level="INFO", enqueue=True)
    logger.add(sys.stderr, level="DEBUG")
    logging.basicConfig(handlers=[InterceptHandler()], level=0, force=True)
    for name in ("uvicorn", "uvicorn.access", "uvicorn.error",
                 "httpx", "httpcore", "urllib3"):
        lg = logging.getLogger(name)
        lg.handlers = [InterceptHandler()]
        lg.propagate = False
```

**步骤二：中间件注入 trace_id**（`app/middleware.py`）：

```python
import uuid
from starlette.middleware.base import BaseHTTPMiddleware
from loguru import logger

class TraceMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request, call_next):
        trace_id = request.headers.get("X-Trace-ID", uuid.uuid4().hex[:16])
        with logger.contextualize(trace_id=trace_id,
                                  path=request.url.path,
                                  method=request.method):
            try:
                response = await call_next(request)
                logger.info("请求完成，状态 {}", response.status_code)
                response.headers["X-Trace-ID"] = trace_id
            except Exception:
                logger.exception("请求处理失败")
                raise
        return response
```

**步骤三：入口装配**（`main.py`）：

```python
from fastapi import FastAPI
from app.logging_config import setup_logging
from app.middleware import TraceMiddleware
from loguru import logger

setup_logging()          # 启动时一次性配置（02 篇建议）
app = FastAPI()
app.add_middleware(TraceMiddleware)

@app.on_event("shutdown")
async def shutdown():
    logger.complete()    # 07 篇：退出前刷完队列日志
```

**步骤四：验收与验证**（上线前必跑）：

```bash
# 1. 每行是合法 JSON 且带 trace_id（应为全行对象，无解析错误）
jq -e . logs/app.jsonl | head -3
# 2. trace_id 字段存在且能按请求串联
jq -r '.record.extra.trace_id' logs/app.jsonl | sort | uniq -c | head
# 3. uvicorn 的访问日志也进了同一文件（接管成功）
jq -r '.record.name + "|" + .record.level.name' logs/app.jsonl | sort | uniq -c
# 4. 模拟 500 MB 压力写或用小 rotation 验证轮转与压缩
ls -la logs/   # 应出现 .zip 归档与当前 .jsonl
```

**验收三问**：**一**，`logs/app.jsonl` 每行是合法 JSON 且带 `trace_id`；**二**，uvicorn/httpx 的日志格式与业务日志一致（接管成功）；**三**，日志按 500 MB 轮转、30 天清理、zip 压缩。

**把日志体系写进简历**：项目描述里加一条——"搭建基于 loguru 的统一日志体系：JSON 结构化输出 + trace_id 全链路关联 + 标准库日志接管 + 按环境开关的诊断信息，支撑线上问题分钟级定位"——**这一条能同时体现工程规范意识、可观测性思维和 Python 实战能力**，是"强烈推荐"目录里少有的"通用工程加分项"。

## 2. 生产配置模板

复制即用的基线（不分项目）：

```python
import sys, os
from loguru import logger

logger.remove()
logger.add("logs/app_{time:YYYY-MM-DD}.log",
           rotation="00:00",                       # 每天 0 点切分
           retention="30 days",
           compression="zip",
           level="INFO",
           enqueue=True,                           # 多进程安全
           encoding="utf-8",
           backtrace=True,
           diagnose=os.getenv("ENV") != "production",  # 生产关 diagnose
           filter={"": "INFO", "urllib3": "WARNING", "httpx": "WARNING"})
logger.add(sys.stderr, level=os.getenv("LOGURU_LEVEL", "INFO"))
```

配套建议：K8s/Docker 下用环境变量控制级别（06 篇）；审计级日志独立 sink（06 篇三 sink 分流）；敏感字段写入前脱敏（09 篇）。

## 3. 报错速查

| 报错 | 原因 | 解法 |
|------|------|------|
| `ValueError: Level 'info' does not exist` | 级别名小写 | 大写 `"INFO"`（06 篇坑一） |
| `ValueError: sink ... is already added` | 同一 sink 重复 add | 用 `logger.remove(id)` 先移除或复用 handler id |
| `UnicodeEncodeError` | Windows 默认 GBK 编码 | `encoding="utf-8"`（04 篇） |
| 异步 sink 不执行 | 忘配 `enqueue=True` | 异步 sink 必须 enqueue（07 篇坑一） |
| 日志出现两遍 | `propagate` 未关 | `propagate = False`（08 篇坑一） |
| 日志里函数名/行号是 InterceptHandler | depth 未修正 | 保留官方 depth 循环（08 篇坑二） |
| 找不到 `logs/` 目录/日志全无 | 目录创建失败 | 启动时 `os.makedirs(exist_ok=True)` + `catch=False` 暴露（04 篇坑三） |
| 退出时最后日志丢失 | 漏 `complete()` | shutdown 钩子调用（07 篇坑二） |
| 生产日志里有密码/token | diagnose 泄露 | `diagnose=False` + 写入前脱敏（05/09 篇） |

## 4. 面试三范式

**范式一：价值式**——"为什么用 loguru"：标准库配置繁琐且默认行为坑（不配 basicConfig 就静默），loguru 一个 `add()` 收敛 handler/format/filter，轮转、保留、压缩、JSON、多进程安全全是参数级支持，让打日志成为零成本习惯——**团队日志覆盖率从"看心情"变成"默认就有"**。

**范式二：对比式**——"loguru vs 标准库 vs structlog"：标准库灵活但要手写 300 行才凑齐生产能力；loguru 简单优先、覆盖 95% 场景；structlog 是结构化重度场景的架构化方案——**先 loguru，需要时 JSON 输出就是共同语言**（09 篇对比表）。

**范式三：生产式**——"你的项目日志怎么设计的"：回答四件套——**轮转保留压缩（04）+ JSON 结构化与 trace_id（09）+ InterceptHandler 接管第三方（08）+ diagnose 按环境开关与脱敏（05/09）**，再补一句"日志是观测链路最上游，聚合查询交给 Loki/ELK"——能讲出这套的人面试官默认你有生产经验。

**追问应对**（面试官大概率会往下挖的四个点）：问"为什么 enqueue"答"多进程轮转竞态 + 业务线程零阻塞"（07）；问"日志怎么串链路"答"中间件生成 trace_id，contextualize 注入，JSON 按字段查询"（09）；问"如何保证不丢"答"审计级用 blocking=True，普通日志接受尽力而为"（07）；问"日志量怎么控制"答"级别策略 + 轮转压缩 + schema 预算"（04/06/09）——**每一问都有对应的篇目答案，这就是知识体系的价值**。
