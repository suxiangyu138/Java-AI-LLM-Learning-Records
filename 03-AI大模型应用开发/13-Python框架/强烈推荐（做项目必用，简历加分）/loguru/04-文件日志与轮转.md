## 1. 文件 sink 基础

给一个文件路径，loguru 自动创建并追加写入：

```python
logger.add("logs/app.log", encoding="utf-8", level="INFO")
```

文件不存在会自动建目录（`logs/` 不存在也会创建——这是 loguru 对标准库"FileHandler 不会建目录"的贴心改进）。**`encoding="utf-8"` 在 Windows 上是必配项**——默认编码在中文 Windows 是 GBK，日志里的中文和异常信息可能直接 UnicodeEncodeError 或乱码（10 篇报错速查有解）。文件 sink 内部按行写入、行缓冲关闭，性能足够日常场景；日志量大再上 `enqueue=True`（07 篇）。

## 2. rotation：三种轮转模式

轮转 = 当前文件写到一定条件，自动改名归档并开新文件。`rotation` 参数三种写法：

**按大小**——最常用，文件超限即切：

```python
logger.add("logs/app.log", rotation="500 MB")   # 数字+单位
```

**按时间点**——每天定时切（适合"按天归档"的业务习惯）：

```python
logger.add("logs/app.log", rotation="12:00")    # 每天中午 12 点切
```

**按周期**——距上次切分满周期即切：

```python
logger.add("logs/app.log", rotation="1 week")   # 每周切一次
logger.add("logs/app.log", rotation="6 hours")  # 每 6 小时
```

**自定义函数**——返回 True 即触发轮转，最强自由度（比如按"包含某个关键字的日志出现"或"空闲时长"切分）：

```python
def should_rotate(message):
    return "ERROR" in str(message) and "panic" in str(message)

logger.add("logs/app.log", rotation=should_rotate)
```

**选型心法**：大小轮转防"单文件撑爆磁盘"（生产基线：500 MB~1 GB）；时间轮转配合业务归档习惯（每天一份方便按天回溯）；周期轮转适合"日志不多但要求均匀分片"的场景。可以同时满足多个诉求吗？——**不能，rotation 只能设一个值**；想要"既按大小又按天"就上 `{time}` 分片命名（第 5 节），让文件天然按天分。

## 3. retention：过期清理

轮转产生的历史文件不会自动删——`retention` 负责清理，否则磁盘迟早被日志堆满（**这是生产事故高频项：日志不清理 → 磁盘满 → 服务崩溃**）：

```python
logger.add("logs/app.log", rotation="500 MB", retention="10 days")
```

`retention` 的值可以是：**时长**（`"10 days"`、`"1 week, 2 days"`）、**数量**（`5` 保留最近 5 个文件）、**函数**（自定义判断）。loguru 在每次轮转后检查并删除过期文件。两个注意点：**retention 只对"被 loguru 管理的历史文件"生效**（即日志文件名匹配该 sink 的 `{time}` 模式）；如果日志文件被外部工具（logrotate、K8s 的 emptydir 清理）托管，两者别叠加——**同一份日志只允许一个清理者**。

自定义 retention 函数的形态——按文件名的日期模式精细判定（比如"周五的日志多留一周"）：

```python
import re, datetime

def friday_retention(log_file):
    m = re.search(r"\d{4}-\d{2}-\d{2}", log_file.name)
    if not m:
        return False
    d = datetime.date.fromisoformat(m.group())
    return (datetime.date.today() - d).days < 10 or d.weekday() == 4
```

## 4. compression：切分后压缩

轮转归档的同时自动压缩，大幅降低存储成本（文本日志压缩率通常 90%+）：

```python
logger.add("logs/app.log", rotation="500 MB", retention="30 days", compression="zip")
```

`compression` 支持 `zip`、`gz`、`bz2`、`xz`、`tar` 组合（`"tar.gz"`）等格式。压缩是**异步**做的（发生在轮转后的后台步骤），不影响写日志的实时性。**压缩 + 保留的组合是日志治理的黄金搭档**：500 MB 的文本压缩后几十 MB，10 天变 30 天几乎不增加存储——"切分 → 压缩 → 到期删"三步闭环，一行配置解决。

## 5. 命名规律与 {time} 占位

文件名里出现 `{time}` 时，loguru 的行为会变化——**不再"追加写入单文件"，而是按时间戳分文件**：

```python
logger.add("logs/app_{time:YYYY-MM-DD}.log", retention="30 days")
```

这里的时间占位同时做了两件事：**轮转基准**（跨天自动切换新文件，不需要 rotation 参数）和**文件名标识**（归档文件带着日期，retention 靠它识别哪些文件可删）。没有 `{time}` 的固定文件名则是"单文件追加"，轮转时旧文件会加 `.2026-08-10_12-00-00_000000_12345.ext` 之类的后缀改名归档。**两种命名哲学**：`{time}` 分片适合"按天翻日志"的运维习惯，固定名 + rotation 适合"名字永远不变、用文件系统时间管理"的场景——生产推荐前者，排查时一个 `ls` 就能看到日期分片。

## 6. 多进程轮转与 enqueue

**单进程多线程**下轮转安全（loguru 默认线程安全）；**多进程**（`multiprocessing`、`gunicorn` 多 worker、FastAPI 多进程部署）同时写同一个日志文件时，轮转会出现"两个进程抢着建新文件"的竞态。解法就是 `enqueue=True`——日志先进内存队列，由**专门的队列线程**统一落盘和轮转，多进程只有一个写入者：

**另一种绕开竞态的姿势——按实例分文件**：文件名带 `{process}` 字段（`logs/app_{time:YYYY-MM-DD}_{process}.log`），每个进程写自己的文件，天然无竞态，还能按实例排查"哪个 worker 出问题"；代价是文件数量随副本数增长（K8s 30 副本 × 30 天 = 900 个文件），采集端按 glob 聚合成一个查询视图。**选型口诀：副本少（≤4）用 enqueue 统一文件，副本多或要按实例排障用 {process} 分文件**。

```python
logger.add("logs/app.log", rotation="100 MB", enqueue=True)
```

`enqueue=True` 是"多进程部署 + 文件日志"的生产标配（07 篇讲透并发与性能）。代价与取舍：日志延迟写入（毫秒级）、进程崩溃时队列里未落盘的尾部日志可能丢失——对日志本身而言可接受（日志系统承诺的通常是"尽力而为"，但审计类日志另当别论）。

## 7. 生产三坑

**坑一：只配 rotation 不配 retention**——文件一直切、永不删，半年后磁盘满了。**轮转与清理必须成对配置**。

**坑二：rotation 与 {time} 混用语义不清**——`app_{time}.log` + `rotation="500 MB"` 会按"日期切换 + 大小轮转"双条件工作，文件命名会出现日期加后缀的叠加，运维 grep 时容易懵——先用小流量实测一把再上线。

**坑三：容器/CI 里日志路径不存在**——`logs/` 目录创建失败会静默丢日志；用 `logger.add(..., catch=False)` 在配置期暴露问题，或启动时 `os.makedirs("logs", exist_ok=True)` 主动建目录。

**容器化补充**：Docker 里"文件日志 vs stdout"二选一——写文件要管卷挂载与持久化，写 `/dev/stdout`（`logger.add("/dev/stdout")`）则交给 Docker 日志驱动（json-file/journald）统一采集，**轮转与保留由 Docker 侧配置（`max-size/max-file`）负责**——**记住"同一份日志只允许一个清理者"在这两种形态下同样成立，别两边都配轮转**。

> 🎯 **核心要点**：文件日志治理 = **rotation（防单文件膨胀）+ retention（防磁盘打满）+ compression（省存储）+ {time}（按天分片可检索）+ enqueue（多进程安全）**——这五项全是标准库要手写几百行才能凑齐的，loguru 五个参数收工；生产基线模板：`rotation="500 MB", retention="30 days", compression="zip", enqueue=True`。
