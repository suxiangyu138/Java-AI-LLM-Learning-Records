## 1. 性能三招

PyYAML 的性能问题集中在"纯 Python 解析慢"，三招按收益排序：

**第一招：CLoader/CSafeLoader（收益最大）**——libyaml C 扩展，解析 2-10 倍加速（05 篇详讲机制）：

```python
import yaml

Loader = getattr(yaml, "CSafeLoader", yaml.SafeLoader)   # 兼容无 C 环境
data = yaml.load(text, Loader=Loader)                    # C 加速安全加载
```

**兼容写法**：`getattr(yaml, "CSafeLoader", yaml.SafeLoader)`——有 C 用 C、没有退回纯 Python（05 篇坑一）。**安全语义不变**（CSafeLoader ≡ SafeLoader）。**什么时候用**：大配置文件、频繁解析（数据管道、配置热重载）、启动耗时可感知的场景——**"配置只读一次的小项目不必折腾，性能敏感的才上 C 版"**。

**第二招：少解析**——配置**启动读一次进内存**（07 篇规范四），运行期零解析；热重载场景也要**节流**（变更才重载，不每次请求解析）。

**第三招：能 JSON 就 JSON**——**数据管道里的高频数据交换直接用 json 模块**（C 实现，比 PyYAML 纯 Python 快数量级，08 篇）——**"性能敏感的数据交换选 JSON 是格式决策，不是 PyYAML 的锅"**。

## 2. 大文件与流式处理

**大 YAML 的两个现实问题**：纯 Python 解析慢 + 一次性 load 全部进内存。对策：

**多文档流用 safe_load_all 懒加载**（03 篇）——生成器逐个文档处理，不一次性全进内存：

```python
with open("bulk.yaml", encoding="utf-8") as f:
    for doc in yaml.safe_load_all(f):     # 逐文档处理
        process(doc)
```

**单文档超大（几十 MB 级）**：PyYAML 没有"部分解析"API——**对策是换格式**（这么大的结构化数据本就不该用 YAML——**"YAML 适合小而可读，大而密的用 JSON/Parquet"**，08 篇选型表）。**中间量级**（几 MB 配置）：CLoader + 一次读入足够（内存与时间都可控）。**心智**：**"YAML 的舞台是配置文件，不是大数据管道"**——把 YAML 当大数据格式用是选型错误，不是性能 bug。

## 3. 生产错误处理

生产级加载封装（07 篇标准模式的升级版——带位置信息与诊断）：

```python
from yaml.error import MarkedYAMLError, YAMLError

def load_config_safe(path: str) -> dict:
    try:
        with open(path, encoding="utf-8") as f:
            return yaml.safe_load(f) or {}
    except FileNotFoundError:
        return {}
    except MarkedYAMLError as e:      # 语法/构造错误：带行号列号
        raise RuntimeError(
            f"配置文件 {path} 第 {e.problem_mark.line + 1} 行解析失败: "
            f"{e.problem}"          # problem = 具体问题描述
        ) from e
    except YAMLError as e:            # 其他 YAML 错误
        raise RuntimeError(f"配置文件 {path} 解析失败: {e}") from e
```

**MarkedYAMLError 的三个字段**：`problem_mark.line`（行号，从 0 计）、`problem`（问题描述）、`context`（上下文）——**"报错带行号"让配置文件排障从"猜"变"定位"**。生产纪律重申：**配置错误快速失败**（07 篇）——错误信息要可执行（"第 N 行有问题"比"解析失败"有用一百倍）。

## 4. yamllint 与质量门禁

**yamllint 是 YAML 的 linter**（语法 + 风格检查）——CI 里的第一道门禁：

```bash
pip install yamllint
yamllint config/*.yaml              # 检查全部配置文件
yamllint -d "{extends: default, rules: {line-length: disable}}" config.yaml
```

**它查什么**：语法错误（Tab、缩进不一致）、风格问题（行过长、空行、文档头缺失）、规范类（键排序、重复键——**重复键是 YAML 的静默覆盖源**，lint 直接抓）。**生产用法**：CI 流水线加一步 `yamllint`（配置错在 CI 挂，07 篇规范二）；**重复键检查**是它最有价值的规则——`key: 1` 写两遍，safe_load 静默取后值，**人工眼很难发现，lint 一秒定位**。

**常用规则配置**（`.yamllint.yaml`，按团队口味调）：

```yaml
extends: default
rules:
  line-length: {max: 120}          # 默认 80 太严，放宽到 120
  document-start: disable          # 不强制每文件 --- 开头
  key-duplicates: enable           # 重复键必查（最重要的一条）
  indentation: {spaces: 2}         # 缩进统一 2 空格
```

**"extends: default 起手 + 团队差异显式覆盖"**是 yamllint 配置的标准姿势——**规则文件进版本库，全团队一套标准**（lint 的意义就是"把口头约定变成自动检查"）。

**第二道门禁——危险 API 检查**（04 篇规则一）：

```bash
# CI 里 grep 危险加载器用法，出现即失败
! grep -rn "unsafe_load\|Loader=.*[UF]ullLoader\|UnsafeLoader" src/
```

**"lint 查语法、grep 查用法"双门禁**是 PyYAML 项目安全与质量的最小闭环（04 篇规则四）。

## 5. 生产配置检查清单

- [ ] 所有读取走 `safe_load`/`safe_load_all`（无 unsafe/FullLoader/裸 load）
- [ ] 文件用 `encoding="utf-8"` 打开，dump 用 `allow_unicode=True`
- [ ] 空文件 `or {}` 兜底、错误包装带行号、启动快速失败
- [ ] 默认值递归合并 + 多环境 base/覆盖模式
- [ ] 配置校验（pydantic 或断言）——**值合法 ≠ 类型正确**
- [ ] 凭证走环境变量，绝不进 YAML
- [ ] CI：yamllint 语法门禁 + 危险 API grep 门禁
- [ ] 版本锁 `pyyaml>=6.0.3,<7`，pip-audit 定期扫
- [ ] 性能敏感场景用 CSafeLoader（兼容写法）
- [ ] 配置一次性加载，运行期不改配置

## 6. 性能测试方法

```python
import timeit

setup = """
import yaml
text = open("big_config.yaml", encoding="utf-8").read()
"""

pure = timeit.timeit("yaml.safe_load(text)", setup=setup, number=20)
c = timeit.timeit(
    "yaml.load(text, Loader=yaml.CSafeLoader)", setup=setup, number=20)
print(f"纯 Python: {pure:.3f}s / CLoader: {c:.3f}s / 加速比: {pure / c:.1f}x")
```

**方法论**：同数据、同次数、对比纯 Python 与 C 版（05/09 篇的性能基线的实测手段）；**结论驱动决策**——加速比 <1.5 的配置文件不值得上 C 版（复杂度不值），>3 倍的大文件果断换——**"性能调优的第一步是测，不是猜"**。

## 7. 常见坑

**坑一：纯 Python 解析拖垮启动**——大配置文件没上 CLoader；**先测再上**（第 6 节）。

**坑二：重复键静默覆盖**——YAML 里同一键写两遍，后值生效；**yamllint 重复键规则 CI 抓**（第 4 节）。

**坑三：报错没行号**——裸 try/except 吞掉 MarkedYAMLError；**包装时保留 problem_mark.line**（第 3 节）。

**坑四：热重载每次请求都 load**——解析开销 + 配置中途变化；**变更才重载**（第 1 节第二招）。

**坑五：把大 JSON 数据塞 YAML**——性能与体积双输；**换格式是选型决策**（第 2 节）。

**坑六：yamllint 只在本地跑**——"我本地通过了"不是门禁；**lint 必须进 CI 流水线**（第 4 节）。

**坑七：安全扫描只扫版本不扫用法**——pip-audit 干净 ≠ 代码安全；**版本审计 + 用法审计双轨**（04 篇规则三）。

**"生产姿态一句话"**：**配置无小事**——解析带行号、校验必生效、门禁自动化、安全红线内化——**"PyYAML 的代码五分钟能写完，生产细节要按检查清单逐项过"**（第 5 节清单）。**把这些落到本体系**：性能细节在 05（CLoader）与 08（JSON 选型）、错误处理在 03/07、门禁在 04/09——**"生产实践不是单独的一篇，是每篇的生产视角"**。
