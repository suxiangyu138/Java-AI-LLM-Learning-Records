## 1. 实战项目：AI 应用配置方案

**项目目标**：给一个 RAG 应用（LLM + Milvus + 检索）做完整配置体系——**多环境 YAML + 安全加载 + pydantic 校验 + CI 门禁**，验收标准：**换环境只改环境变量，配错启动即报错带行号**。

**步骤一：配置文件**（`config/base.yaml` —— 公共层，07 篇模式）：

```yaml
app:
  name: rag-service
  port: 8080
llm:
  provider: openai
  model: gpt-4o
  temperature: 0.7
  timeout: 30
milvus:
  uri: http://localhost:19530
  collection: docs
retrieval:
  top_k: 5
  similarity_threshold: 0.6
logging:
  level: INFO
  json: false
```

**步骤二：环境覆盖**（`config/prod.yaml` —— 只写差异）：

```yaml
llm:
  model: gpt-4o-mini          # 生产换便宜模型
retrieval:
  top_k: 8
logging:
  level: WARNING
  json: true                  # 生产结构化日志
```

**步骤三：加载 + 合并 + 校验**（`app/config.py`）：

```python
import os
import yaml
from pydantic import BaseModel, Field

BASE_DIR = os.path.dirname(__file__)

def load_raw(path: str) -> dict:
    try:
        with open(path, encoding="utf-8") as f:
            return yaml.safe_load(f) or {}
    except yaml.YAMLError as e:
        raise RuntimeError(f"配置 {path} 解析失败: {e}") from e

def merge(d: dict, o: dict) -> dict:      # 递归合并（07 篇）
    r = dict(d)
    for k, v in o.items():
        r[k] = merge(r[k], v) if isinstance(v, dict) and isinstance(r.get(k), dict) else v
    return r

class LLMConfig(BaseModel):
    provider: str
    model: str
    temperature: float = Field(ge=0, le=2)
    timeout: int = Field(ge=1, le=300)

class MilvusConfig(BaseModel):
    uri: str
    collection: str
    token: str = Field(default="")         # 凭证从环境变量注入，不进 YAML

class AppConfig(BaseModel):
    app: dict
    llm: LLMConfig
    milvus: MilvusConfig
    retrieval: dict
    logging: dict

def load_config() -> AppConfig:
    env = os.getenv("APP_ENV", "dev")
    raw = merge(load_raw(f"{BASE_DIR}/base.yaml"),
                load_raw(f"{BASE_DIR}/{env}.yaml"))
    raw["milvus"]["token"] = os.getenv("MILVUS_TOKEN", "")    # 凭证环境变量
    return AppConfig(**raw)       # 校验失败抛 ValidationError（启动即挂）
```

**验收三问**：**一**，`APP_ENV=prod` 启动后 llm.model 是 prod 覆盖值、其余继承 base（合并正确）；**二**，把 `temperature: 3` 写进配置启动直接 ValidationError 带字段名（校验生效）；**三**，YAML 语法错误时报错含文件名与行号（排障友好）。**加试一题**：CI 里加 `yamllint` 与危险 API grep 双门禁（09 篇）。

**把配置体系写进简历**：项目描述加一条——"**基于 PyYAML 搭建多环境配置体系：安全加载 + 递归合并 + pydantic 校验 + CI 双门禁，配置错误启动即失败并定位到行号**"——这一条同时体现**工程规范意识、安全意识与配置管理实战**，与 loguru 的"日志体系"简历条目形成"**日志 + 配置双工程件**"的组合加分（00 篇分工与 01 篇双地基件）。

## 3. 报错速查

| 报错 | 原因 | 解法 |
|------|------|------|
| `ScannerError: found character '\t'` | Tab 缩进 | 编辑器 Tab 转空格（02 篇坑一） |
| `ParserError` | 结构错（缩进/冒号） | 看报错行号，检查层级（02 篇） |
| `ConstructorError: could not determine a constructor for the tag '!!python/...'` | safe_load 拒绝 Python 标签 | **安全机制在工作**——文件不可信或需受限 constructor（04/05 篇） |
| `RepresenterError` | dump 非基础类型 | 注册 representer 或先转 dict（06 篇坑三） |
| `UnicodeDecodeError`（Windows） | open 没配 utf-8 | `encoding="utf-8"`（03 篇） |
| 中文变 `\uXXXX` | dump 缺 allow_unicode | `allow_unicode=True`（06 篇坑一） |
| 布尔变成字符串/变布尔 | YAML 1.1 yes/no 语义 | 加引号（02 篇坑四） |
| `12:30` 变数字 | 冒号时间戳解析 | 加引号（02 篇坑三） |
| 键序被打乱 | sort_keys 默认 True | `sort_keys=False`（06 篇坑二） |
| 重复键静默覆盖 | YAML 重复键后值生效 | yamllint 重复键规则（09 篇坑二） |
| `ValidationError`（pydantic） | 配置值越界/类型错 | 看错误里的字段名与约束（07 篇第 4 节） |
| `getattr(yaml, "CSafeLoader")` 报 None | 无 C 扩展 | 用 `getattr(..., yaml.SafeLoader)` 兼容（05 篇坑一） |

## 4. 面试三范式

**范式一：价值式**——"为什么用 YAML/PyYAML"：配置可读性 + 锚点/注释/多文档能力，PyYAML 是事实标准实现；**safe_load 安全加载 + pydantic 校验 + 递归合并默认值**构成配置管理的完整闭环——"**人读的配置、机器验的值**"。

**范式二：安全式**——"yaml.load 危险吗"：**历史 RCE 谱系（2017-2021 四个 9.5 级 CVE）→ 6.0 默认 SafeLoader 反转 → 2026 年 6.0.x 无 CVE 但 vcrpy 误用 CLoader 仍中招**——结论："**库版本干净 + 代码用法干净双轨审计**，safe_load 是唯一入口"（04 篇）。

**范式三：生产式**——"配置系统怎么设计的"：回答链路——**多环境 base/覆盖（APP_ENV）+ 递归合并 + pydantic 校验（快速失败）+ 凭证环境变量 + CI 双门禁（yamllint + 危险 API grep）+ CLoader 性能**——能完整讲出这条链 = 有真实生产经验（09 篇检查清单）。

**追问应对**（面试官往下挖的四个点）：问"为什么 safe_load"答"`!!python/` 标签可构造任意对象执行代码——历史四个 9.5 级 CVE，6.0 默认反转，vcrpy 2026 年还在翻车"（04）；问"配置校验怎么做的"答"pydantic 模型声明式校验，越界/类型错启动即失败带字段名"（07）；问"配置改动能热更新吗"答"启动加载一次进内存，动态配置走配置中心——YAML 不负责运行时变更"（09）；问"JSON 为什么不行"答"可读性/注释/锚点/多文档——程序间交换才用 JSON"（08）——**每一问都有对应篇目的答案**。
