## 1. Loader 机制：解析器与构造器

PyYAML 的加载分两阶段，理解这个就理解了安全语义：

**第一阶段：解析（parse）**——把 YAML 文本变成语法树（节点）：映射节点、序列节点、标量节点、带标签的节点——**这一阶段与安全无关**（纯语法）。

**第二阶段：构造（construct）**——把节点变成 Python 对象：标量节点转 str/int/bool、映射节点转 dict、**带 `!!python/` 标签的节点调用对应的 Python 构造函数**——**这一阶段才是安全分水岭**。

**Loader = 解析器 + 一套"标签 → 构造函数"的注册表**。不同 Loader 的区别**不是解析能力**（语法都一样），**而是允许哪些标签被构造**：SafeLoader 的注册表里只有基础类型，UnsafeLoader 的注册表里有 `python/object` 家族——**"Loader 的差异 = 构造函数注册表的差异"**是本文的底层认知。

## 2. 四大家族能力对比

| Loader | 能构造什么 | 安全性 | 使用 |
|--------|-----------|--------|------|
| `BaseLoader` | 只解析不构造（拿到节点/标量） | 最安全（能力最小） | 底层工具 |
| `SafeLoader` | str/int/float/bool/null/list/dict + 基础标签 | **安全（生产唯一）** | ✅ safe_load |
| `FullLoader` | 基础类型 + 大部分标准标签 | ⚠️ 有历史 RCE（5.x 打过两个 9.5 级 CVE） | 不推荐 |
| `UnsafeLoader` | 全部：含 `!!python/object` 家族（任意代码） | ❌ 危险 | 仅可信内部数据 |

**SafeLoader vs FullLoader 的精确差异**：FullLoader 支持 `!!python/name`（引用任意 Python 名字）等**会让解析结果引用任意对象**的标签——**"看起来安全的名字引用"在 5.x 时代被打穿两次**；SafeLoader 连这些都不支持——**"SafeLoader = 只认数据，不认识任何 Python"**。

## 3. SafeLoader 的安全边界

SafeLoader 的能力边界（即"安全"的定义）：

**它能构造**：`str`（含 `!!str` 显式标签）、`int`、`float`、`bool`、`None`、`list`、`dict`、`set`（`!!set`）、`datetime`（`!!timestamp`）、`!!binary`（bytes）——**全部是"纯数据"类型，构造过程不执行任何用户代码**。

**它拒绝**：所有 `!!python/*` 标签——**遇到就抛 `ConstructorError: could not determine a constructor for the tag`**——这个报错不是 bug，**是安全机制在工作**：收到这个错 = 文件里出现了 Python 对象标签 = 文件不可信或配置写错了。

**边界再确认**：SafeLoader 也支持**锚点/别名/合并键**（纯数据结构操作，02 篇）与自定义应用标签（**前提是你只注册了安全的 constructor**，第 5 节）——"**SafeLoader 安全 ≠ 不能扩展，而是扩展必须自己负责安全**"。

## 4. CLoader：C 扩展加速版

**libyaml 绑定**（装包时如果 C 扩展编译成功）提供四个 C 加速版：`CLoader`/`CSafeLoader`/`CFullLoader`/`CUnsafeLoader`——**功能与对应纯 Python 版完全一致，速度 2-10 倍**（解析核心在 C 里跑）。

```python
import yaml

# 性能敏感场景用 C 版（语义与 SafeLoader 完全一致）
data = yaml.load(text, Loader=yaml.CSafeLoader)
# 或简写：没有内置的 safe_c_load，但可以这样注册
yaml.safe_load(text)          # 默认：Python SafeLoader
yaml.load(text, Loader=yaml.CSafeLoader)   # C 加速，语义相同
```

**三个要点**：其一，**提速不改变安全语义**——`CUnsafeLoader` 依旧能执行代码（vcrpy 案例就是 CLoader 中招，04 篇）；其二，**版本差异可能存在于 C 与 Python 实现之间**（细微行为差）——生产上统一用 C 版或统一用 Python 版，别混；其三，**验证 C 扩展是否可用**：`yaml.__with_libyaml__`（03 篇）——**没有 C 扩展时 `CLoader` 不存在，代码要兼容**（`getattr(yaml, "CSafeLoader", yaml.SafeLoader)`）。

**何时值得上 C 版**（决策依据，09 篇有实测方法）：**启动加载的大配置文件**（几 MB 级，纯 Python 解析秒级→毫秒级）、**频繁解析的数据管道**（每批数据都 load）、**配置热重载场景**——**"配置只读一次的小项目不必折腾，性能可感才上 C 版"**；判断标准不是感觉是实测：同数据对比 `timeit` 两种 Loader 的耗时，**加速比 >2 倍才值得引入**（09 篇性能测试）。

## 5. 自定义 constructor：安全姿势

**需求**：配置文件里想用应用自定义标签（如 `!env` 表示"读环境变量"）。**安全姿势**：注册只做"受限操作"的 constructor——**标签 → 明确的纯函数**，而不是"构造任意对象"：

```python
import os, yaml

def env_constructor(loader, node):
    value = loader.construct_scalar(node)
    return os.environ.get(value, "")     # 只读环境变量——受限操作

yaml.SafeLoader.add_constructor("!env", env_constructor)

config = yaml.safe_load("api_key: !env API_KEY")
```

**安全三原则**：其一，**constructor 只做白名单内的受限操作**（读环境变量、查表、格式化——**绝不 eval、绝不 import 任意模块**）；其二，**注册在 SafeLoader 上**（继承其基础安全边界）；其三，**输入仍要校验**——`!env` 读出的值在业务侧还要过校验（07 篇）。**反例**：有人图省事注册 `"!eval"` 构造器——**这就是亲手把自己拉回 RCE**——"自定义 constructor 的唯一安全形式是受限纯函数"。

## 6. YAMLObject：声明式绑定

`yaml.YAMLObject` 让类声明式地绑定 YAML 表示（`yaml_tag` + `from_yaml`/`to_yaml` 类方法）——**自动注册到对应 Loader**：

```python
import yaml

class Point(yaml.YAMLObject):
    yaml_tag = "!point"
    @classmethod
    def from_yaml(cls, loader, node):
        x, y = loader.construct_sequence(node)
        return cls(x, y)

p = yaml.load("!point [1, 2]", Loader=yaml.SafeLoader)   # 需确保构造器安全
```

**注意**：YAMLObject 默认注册到 `yaml.Loader`（完整 Loader）——**要在 SafeLoader 上可用必须显式 `SafeLoader.add_constructor` 或谨慎设计 `from_yaml`**——**"声明式绑定不等于自动安全"**；且 6.0 后 YAMLObject 相关的默认注册行为有调整——**生产里 YAMLObject 的场景极少，优先用第 5 节的显式注册**。

## 7. 常见坑

**坑一：CLoader 不存在**——无 C 扩展环境直接 `NameError`；**用 `getattr(yaml, "CSafeLoader", yaml.SafeLoader)` 兼容**。

**坑二：safe_load 遇到 `!!python/` 标签报 ConstructorError 以为数据坏了**——**这是安全机制在工作**；先确认"这个标签是不是真的需要"，需要就用受限 constructor（第 5 节）而不是换 UnsafeLoader。

**坑三：FullLoader 当 SafeLoader 用**——历史 RCE 的源头；**安全线只有 SafeLoader 一条**（04 篇红线二）。

**坑四：自定义 constructor 里 eval/import**——亲手开 RCE；**constructor 只做受限白名单操作**。

**坑五：C 版与 Python 版混用**——同一进程两种行为可能不一致；**统一一种**。

**坑六：给"内部配置文件"开 UnsafeLoader 特权**——"文件是我写的"不是豁免理由（04 篇红线四）；**内部数据想省事也有更稳的路**：safe_load + 校验，或受限 constructor——**"安全不是身份的奖励，是加载方式的纪律"**。
