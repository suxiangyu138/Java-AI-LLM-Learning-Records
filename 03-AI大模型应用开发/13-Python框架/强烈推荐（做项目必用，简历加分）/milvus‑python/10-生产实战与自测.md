## 1. 实战项目：裸 RAG 全链路

**项目目标**：不依赖 LangChain/LlamaIndex，用 pymilvus 独立实现"文档入库 → 检索 → 拼上下文"的完整链路——**能讲清每一行的意义，就是裸 SDK 毕业**。

**步骤一：连接与 schema**（原型用 Milvus Lite，生产换 uri）：

```python
from pymilvus import MilvusClient, DataType

client = MilvusClient("rag_demo.db")   # 生产：MilvusClient(uri="http://...")

schema = MilvusClient.create_schema(auto_id=False, enable_dynamic_field=True)
schema.add_field("id", datatype=DataType.INT64, is_primary=True)
schema.add_field("title", datatype=DataType.VARCHAR, max_length=512)
schema.add_field("category", datatype=DataType.VARCHAR, max_length=64)
schema.add_field("content", datatype=DataType.VARCHAR, max_length=8192)
schema.add_field("embedding", datatype=DataType.FLOAT_VECTOR, dim=1024)

index_params = client.prepare_index_params()
index_params.add_index("embedding", index_type="HNSW",
                       metric_type="COSINE", params={"M": 16, "efConstruction": 200})

if not client.has_collection("docs"):
    client.create_collection("docs", schema=schema, index_params=index_params)
client.load_collection("docs")
```

**步骤二：批量入库**（chunk 化 + embedding 已就绪时）：

```python
def embed(texts):  # 换成你的 embedding 模型
    return [[0.1] * 1024 for _ in texts]   # 占位——真实项目用 BGE/OpenAI 等

def ingest(chunks, batch_size=2000):
    for i in range(0, len(chunks), batch_size):
        batch = chunks[i:i + batch_size]
        data = [{"id": c["id"], "title": c["title"], "category": c["category"],
                 "content": c["content"], "embedding": embed([c["content"]])[0]}
                for c in batch]
        res = client.insert("docs", data=data)
        assert res["insert_count"] == len(batch), f"批次 {i} 插入失败"
    client.load_collection("docs")   # 插入后确认加载
```

**步骤三：检索 + 过滤**（生产检索姿势）：

```python
def retrieve(query_text, top_k=5, category=None):
    q = embed([query_text])[0]
    filter_expr = f'category == "{category}"' if category else None
    hits = client.search("docs", data=[q], limit=top_k,
                         output_fields=["title", "content", "category"],
                         filter=filter_expr,
                         search_params={"metric_type": "COSINE", "params": {"ef": 128}})[0]
    ctx = [f"【{h['entity']['title']}】{h['entity']['content'][:300]}"
           for h in hits if h["distance"] >= 0.6]   # 阈值防硬凑
    return ctx

context = retrieve("如何部署 Milvus", category="docs")
prompt = f"基于以下资料回答：\n{' '.join(context)}\n问题：如何部署 Milvus？"
```

**步骤四：进阶升级——混合检索**（召回质量不满足时启用，07 篇）：

```python
from pymilvus import RRFRanker

def retrieve_hybrid(query_text, top_k=5):
    dense_q = embed(query_text)[0]                       # 稠密：语义相似
    sparse_q = sparse_embed(query_text)                  # 稀疏：关键词精确（BM25/SPLADE 转换）
    hits = client.hybrid_search(
        "docs",
        reqs=[
            {"query": dense_q, "anns_field": "embedding",
             "limit": 10, "search_params": {"metric_type": "COSINE"}},
            {"query": sparse_q, "anns_field": "sparse_vec",
             "limit": 10, "search_params": {"metric_type": "IP"}},
        ],
        ranker=RRFRanker(k=60), limit=top_k,
        output_fields=["title", "content"])[0]
    return [h["entity"]["content"][:300] for h in hits]
```

**验收三问**：**一**，入库后 `get_collection_stats` 行数正确、search 有结果；**二**，filter 生效（category 过滤后结果全是该分类）；**三**，阈值过滤生效（无关文档被 distance 挡掉）——**三问全过，裸 RAG 链路闭环**。加试一题：**专有名词（如 "LlamaIndex"）召回丢失时，混合检索能否找回？**——这是面试讲 RAG 检索时的黄金例子（稠密管语义、稀疏管精确）。

## 2. 生产配置模板

```python
from pymilvus import MilvusClient

client = MilvusClient(
    uri="http://milvus.prod.internal:19530",
    token=os.getenv("MILVUS_TOKEN"),     # 凭证走环境变量
    timeout=30,                          # 全局超时兜底
)
# 纪律清单：
# 1. 版本锁定 pymilvus==2.6.17 或 >=3.0.1,<3.1（配服务器版本）
# 2. 长驻进程只建一次客户端，全进程复用
# 3. 所有操作显式 timeout（检索 10s / 插入 60s）
# 4. 可重试错误指数退避重试 3 次（业务错误不重试）
# 5. 生产 diagnose：describe_collection 验证 schema、stats 验证行数
# 6. 异步服务用 AsyncMilvusClient（硬纪律）
```

配套建议：连接参数与凭证走环境变量（Docker/K8s 配置化）；批量入库断点续灌（05 篇）；索引选型与参数按数据量决策 + recall 验证（06 篇）。

## 3. 报错速查

| 报错 | 原因 | 解法 |
|------|------|------|
| `ConnectionConfigException` | 连不上服务器 | uri/端口/防火墙，`curl /healthz` 验证（02 篇） |
| `AuthenticationException` | token/账号错 | 检查 token、user/password（02 篇） |
| `ProtocolException` | 客户端与服务器版本不配 | 查配对表，锁版本（01 篇） |
| `CollectionNotExistException` | 集合不存在/拼错名 | `list_collections` 核对 |
| `CollectionAlreadyExistsException` | 重复建同名集合 | 先 `has_collection`（04 篇坑二） |
| `collection not loaded` | 没加载就检索 | `load_collection` + 确认 Loaded（04 篇坑一） |
| `dimension mismatch` | 向量维度与 schema 不符 | 检查 embedding 输出维度（05 篇坑二） |
| filter 表达式语法错 | 值没加引号/字段不存在 | 值加引号、字段核对 schema（08 篇坑二） |
| `unknown-field`（3.0 特性） | 2.6 服务器不支持 3.0 能力 | 确认服务器版本 ≥3.0（01/04 篇） |
| 插入结果 insert_count=0 | 数据被静默拒绝 | 检查返回值与 schema 校验（05 篇坑一） |

## 4. 面试三范式

**范式一：价值式**——"为什么用 Milvus/pymilvus"：RAG 检索需要毫秒级向量召回 + 标量过滤（先过滤再召回），Milvus 是分布式向量库事实标准；pymilvus SDK v2 一个 MilvusClient 统治全部操作，原生异步支持高并发——**"向量检索 + 工程成熟度都达标"**。

**范式二：版本式**——"pymilvus 现状"：SDK v2 重设计（MilvusClient 统一 API + AsyncMilvusClient + schema cache），ORM 旧 API 弃用；2026-08 双线——Milvus 3.0.0（2026-07-29）+ SDK 3.0.1 主线、2.6.x 维护线（2.6.17）——**"版本配对 + 破坏性变更意识"是面试官最想听的**。

**范式三：生产式**——"RAG 检索怎么设计的"：回答链路——schema 四问设计（主键/维度/可查询字段/分区键）→ HNSW 索引 + COSINE → 批量并发入库（检查 insert_count）→ search + filter + 相似度阈值 → 必要时 hybrid_search（稠密 + 稀疏 + RRF）→ 异步服务用 AsyncMilvusClient——**能完整讲出这条链，默认有生产经验**。

**追问应对**（面试官往下挖的四个点）：问"为什么先过滤再召回"答"缩小检索范围、精度与性能双赢，过滤字段 schema 阶段列化"（07）；问"召回质量怎么验证"答"recall@K 抽样测试，95%+ 上线，不及格先调 ef/nprobe 再考虑换索引"（06）；问"版本与升级"答"版本配对表 + 客户端先行服务器跟随 + Loon opt-in 单向需备份"（01）；问"为什么不用 LangChain 封装"答"框架封装适合快速搭建，裸 SDK 适合深度控制与调试——学习期先裸 SDK 懂原理"（00 分工）——**每一问都有对应篇目的答案**。
