## 1. 一句话定位

**LangChain = LLM 应用开发框架——把"模型调用"编排成"应用"的胶水层**：

```text
一句话定位
├── 本质：LLM 应用编排框架（模型/提示词/工具/记忆/Agent 的组装层）
├── 出身：2022 年开源——MIT 许可——100K+ 星标——1000+ 集成
├── 现状：2025-10 发布 1.0（首个 1.x 稳定版——2026 年的基线）
├── 地位：LLM 编排的事实标准（Python 月下载量已超 OpenAI SDK）
└── 比喻：LangChain 是"乐高"——模型/提示词/工具是"积木"，LangChain 是"拼装指南"
    ——"不写 LangChain 也能做 AI 应用——但写了更专业"
```

**定位心智**：**"LangChain 解决的核心问题：LLM 应用不是'一次调用'，是'多组件编排'"**——"**一个 AI 应用 = 模型 + 提示词 + 输出解析 + 记忆 + 工具 + 流程控制——LangChain 把这些'组装'标准化——'自己拼也能拼（手写胶水代码），用框架拼更规范（统一接口）'"**（"框架的价值：① 统一接口（换模型不换代码）；② 组合能力（LCEL 管道）；③ 生态集成（1000+ 现成件）——**'三个价值 = 用框架的理由'"**）；**什么时候用 LangChain**——"简单调用（一次模型请求）直接用 SDK（不需要框架）；复杂应用（链/Agent/RAG/多轮）用 LangChain——**'框架是编排工具，不是必需品（00 篇误区五）'"**（"判断标准：组件多于 3 个 → 用框架——**'编排复杂度决定用不用框架'"**）。

## 2. 解决什么问题

**LangChain 解决的四个"重复造轮子"问题**：

```text
解决四问题
├── ① 模型接入不统一：OpenAI/DeepSeek/本地 vLLM 各有 SDK——切换要改代码
│    → ChatModel 统一接口（03 篇——换模型换一个类名）
├── ② 提示词硬编码：提示词写死在代码里——改提示词要改代码
│    → PromptTemplate 模板化（04 篇——提示词与代码分离）
├── ③ 输出不可靠：模型返回字符串——要解析成 JSON/对象
│    → 结构化输出（05 篇——Pydantic 强制）
└── ④ 多步流程难管理：链式调用/条件分支/Agent 循环——手写复杂
    → LCEL 组合 + LangGraph 编排（06/08 篇——声明式流程）
    ——"四个问题 = 每个 LLM 应用都会遇到的'通用问题'——LangChain 给标准解"
```

**问题心智**：**"四个问题的记忆：'接入/提示词/输出/流程'——LLM 应用的四大通用环节"**——"**为什么是'通用'问题：不管做什么应用（客服/问答/Agent）都会遇到这四件事——LangChain 给标准答案——'自己解决这四个问题 = 重复造轮子（每个项目造一遍）'"**（"框架的价值再确认：不重复造轮子 + 社区共享方案——**'1000+ 集成 = 别人造好的轮子'"**）；**解决方式的定位**——"LangChain 不解决：模型本身（那是模型厂商的）、应用业务（那是你的）——**'LangChain 管'编排'这一层——模型之下、业务之上'"**（"边界清晰 = 用起来不迷路——**'框架的职责：组装，不负责'生产模型'和'业务逻辑'"**）。

## 3. 2026 v1.0 关键变化

**LangChain 1.0（2025-10 发布）——老教程大量过时的原因**：

```text
v1.0 关键变化（新代码必须知道）
├── ① Agent 新姿势：create_agent（LangGraph 底层）替代 create_react_agent
│    —— AgentExecutor 维护模式（至 2026-12）——新代码别用
├── ② 旧 Chain 类移走：LLMChain/SequentialChain → langchain-classic 包
│    —— 新代码用 LCEL（prompt | model | parser——06 篇）
├── ③ 记忆软弃用：ConversationBufferMemory → 短期 messages 注入、
│    长期 LangGraph Checkpointer（07 篇）
├── ④ 框架瘦身：主包减 40%——异步管线吞吐提升约 3 倍
└── ⑤ 分层架构：抽象层（模型接口）+ 组件层（工具链）+ 编排层（LangGraph）
    ——"1.x 的心智：'Agent 优先 + LCEL 组合 + LangGraph 编排'"
```

**v1.0 心智**：**"v1.0 的记忆：'create_agent + LCEL + LangGraph——三新'"**——"**老教程（0.x）的三大过时：AgentExecutor（维护中）、LLMChain（移 classic）、ConversationBufferMemory（软弃用）——'看到这三个名字 → 是旧写法 → 换新姿势'"**（"新姿势速查：Agent 用 create_agent（08 篇）、链用 LCEL（06 篇）、记忆用 messages 注入/Checkpointer（07 篇）——**'三新对三旧——对照记'"**）；**版本的心态**——"1.x 是稳定版（破坏性变更只在主版本）——**'1.x 时代：学会一套写法长期有效（比 0.x 时代稳）'"**（"生态的稳定：v1 之后格局稳定（LangGraph 多代理是杀手锏——08 篇）——**'2026 年学 LangChain 学的是'稳定版'"**）。

## 4. 生态四件套

**LangChain 生态四件套——各管一段（2026 全景）**：

```text
生态四件套
├── LangChain：应用框架（模型/提示词/工具/链——本体系）
├── LangGraph：编排引擎（Agent 的状态机——复杂流程/多代理）
├── Deep Agents：工业级 Agent 框架（可靠性/生产级）
└── LangSmith：可观测性（追踪/调试/成本监控——生产必配）
    ——"四件套的分工：LangChain 组装、LangGraph 编排、Deep Agents 强化、LangSmith 观测"
```

**生态心智**：**"四件套的记忆：'组装/编排/强化/观测'"**——"**学习顺序：先 LangChain（本体系——组装基础）→ 再 LangGraph（复杂编排）→ LangSmith（生产观测——09 篇）——'四件套是递进关系（基础到生产）'"**（"本体系的边界：聚焦 LangChain 本身（组装层）——LangGraph 深入是另一个体系的事（本体系 08 篇提 create_agent 的底层）——**'本体系教'组装'，编排/观测留进阶'"**）；**生态的地位**——"2026 年：51% 受访者已在生产用 Agent、LangChain 是生态基础（Klarna/Cisco 等生产案例）——**'四件套 = 2026 年 Agent 应用的标准栈'"**（"了解即可：知道四件套存在与分工——**'项目的演进：基础用 LangChain、复杂上 LangGraph、生产配 LangSmith'"**）。

**生态的替代与竞品**（选型时知道"别的选项"）："**LlamaIndex**——纯 RAG 场景更简单（文档索引/检索优化——`llama-index` 体系）；**Vercel AI SDK**——TypeScript 用户的选择；**Microsoft Semantic Kernel**——企业级多模态——**'LangChain 的定位：编排最全（1000+ 集成）+ Agent 生态最成熟——简单 RAG 可考虑 LlamaIndex'"**（"选型的判断：'编排复杂度'——组件多/要 Agent 用 LangChain、纯文档问答可 LlamaIndex——**'框架选型 = 需求匹配（本课 01 篇'什么时候用'的深化）'"**）。

**生态的学习心态**（框架学习的三阶段）："**① 会用**——照教程拼链/做 Agent（本体系的毕业标准）；**② 会选**——知道'什么时候用框架/用哪个框架'（需求匹配）；**③ 会排障**——报错归类 + 查文档/Issues（10 篇）——**'三阶段 = 框架学习的完整路径——本体系带你到①+②，③靠实战'"**（"框架的学习法则：'先抄后造'——照官方例子跑通（抄）→ 改造成自己的（造）——**'抄是合法的学习（官方例子是最好的老师）'"**）。
