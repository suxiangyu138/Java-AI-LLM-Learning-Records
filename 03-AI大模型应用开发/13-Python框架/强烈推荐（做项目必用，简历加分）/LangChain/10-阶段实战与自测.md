## 1. 实战项目：智能客服 Agent

**实战项目 = 把本体系九课串成一个"能讲的项目"（简历加分）**：

```text
实战项目（智能客服 Agent——综合全部九课）
├── 数据与知识：RAG（09 篇——产品文档问答——检索增强）
├── 对话：多轮记忆（07 篇——MessagesPlaceholder 短期 + thread_id 长期）
├── 工具：查询订单/计算（08 篇——@tool——Agent 的手脚）
├── 编排：create_agent（08 篇——自主决策）+ LCEL 链（06 篇）
├── 模型：ChatModel（03 篇——接本地 vLLM 或 OpenAI）
├── 输出：结构化（05 篇——订单信息对象）
└── 观测：LangSmith 追踪（09 篇——生产姿势）
```

```python
# 项目核心骨架（简化版）
from langchain.agents import create_agent
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool

@tool
def query_order(order_id: str) -> str:
    """查询订单状态。参数：order_id（订单号）。"""
    return f"订单 {order_id}：已发货，预计明天送达"

@tool
def calculate(expression: str) -> str:
    """计算数学表达式。"""
    return str(eval(expression))

agent = create_agent(
    model=ChatOpenAI(model="gpt-4o-mini"),
    tools=[query_order, calculate],
    system_prompt="你是电商客服助手：查订单用工具，算数用工具，其他友好回答。",
)
# 调用：agent.invoke({"messages": [("user", "订单 12345 到哪了？")]})
```

**实战心智**：**"实战的验收标准：'能讲三分钟'——背景/架构/结论（项目是简历加分的核心）"**——"**验收三看：能跑（Agent 完成任务）、能讲（架构讲清——RAG + Agent + 记忆）、有数字（成本/效果——LangSmith 数据）——'三个验收 = 简历项目的三件套证明'"**（"强烈推荐的实战观：做完整项目（不是 demo——要有真实场景）——**'简历项目 = 解决真实问题的项目（能讲'为什么这么做'）'"**）；**实战的选型**——"项目主题：客服/问答/数据分析 Agent（三选一——真实场景）——**'主题选'你有话说'的（做过/了解业务）——讲得深比做得大重要'"**（"项目的数据：真实数据优先（公开数据集/自己数据——阶段 3 数据来源）——**'真实数据 = 项目可信度'"**）；**实战的简历呈现**——"README 三件套：项目简介（一句话——解决什么问题）、架构图（RAG + Agent + 记忆的流程）、技术亮点（LangChain 1.x 姿势/结构化输出/LangSmith）——**'简历项目 = 代码 + README + 能讲（01 篇四件套的落地）'"**（"面试的讲法：先讲'为什么做'（业务价值）再讲'怎么做'（技术选型）——**'简历项目讲'业务 + 技术'双线'"**）；**实战的验收复盘**——"做完过一遍 10 篇毕业检查单（十二项）——**'自检 = 毕业的最后仪式（与各体系同款）'"**（"复盘的沉淀：把踩的坑写进速查表（10 篇 3 节）——**'项目的产出 = 项目 + 经验（速查表是经验的载体）'"**）。

## 3. 报错速查

**高频报错速查（LangChain 常见坑——十选六）**：

| 报错/现象 | 原因 | 解法 |
|---------|------|------|
| `ImportError: langchain` | 包没装/装错 | `pip install langchain langchain-openai`（按集成装） |
| 模型报 401/403 | API key 没配 | 环境变量配 key（.env——03 篇） |
| 模型 404 | base_url/模型名错 | 查模型名（vLLM /v1/models——09 篇） |
| `ValidationError` | 结构化输出字段不符 | 检查 Pydantic 定义与输入 |
| 老教程代码报错 | 0.x 写法（AgentExecutor 等） | 换 1.x 姿势（create_agent/LCEL——01 篇） |
| 模板 { } 报错 | 花括号转义问题 | 字面花括号用 `{{ }}`（04 篇） |

**速查心智**：**"六条的规律：'环境两条（装包/key）+ 接入两条（模型/结构）+ 版本两条（旧写法/模板）'"**——"**背下六条的'原因列'——报错时先对原因再对解法——'排障的本质是原因归类'"**（"新坑必记——**'速查表是你的，不是我的——我的六条是起点，你的实战坑要补充'"**）。

## 4. 面试演练

**面试问答（LangChain 相关——本体系特有）**：

**Q1：你的项目为什么用 LangChain？**——答：**"我的智能客服项目——需求是'产品文档问答 + 订单查询 + 多轮对话'：① 模型接入统一（ChatModel——本地 vLLM 只改 base_url——01 的编排优势）；② RAG 做知识问答（加载切分 → 向量化 → 检索 → 生成——四步都是现成集成）；③ create_agent 做工具调用（查订单/算数——@tool 定义——自动循环）；④ LCEL 拼链（prompt | model | parser——流式/异步内置）；⑤ LangSmith 追踪（生产可观测——每个调用有轨迹）——不用框架的话这些都要自己写"**——结构：**需求 → 每个环节的框架解 → 对比不用框架**——"答出'每个环节为什么用框架'是项目深度的证明"。

**Q2：LangChain 1.0 和 0.x 有什么区别？**——答：**"三大变化：① Agent——AgentExecutor 维护模式（至 2026-12），新姿势 create_agent（底层跑 LangGraph 状态机——流式/持久化/可观测开箱即用）；② 链——旧 Chain 类（LLMChain/SequentialChain）移 langchain-classic，新代码用 LCEL（prompt | model | parser）；③ 记忆——ConversationBufferMemory 软弃用，短期用 MessagesPlaceholder 消息注入、长期用 LangGraph Checkpointer——主包还瘦身 40%"**——结构：**三变化 + 新姿势**——"答出'三新对三旧'是 2026 年的正确认知"。

**Q3：Chain 和 Agent 怎么选？**——答：**"流程固定用 Chain（LCEL 拼——prompt | model | parser——确定性、便宜）；流程不定用 Agent（create_agent——模型自主决策——多步循环、能调工具——贵、要护栏）——我的项目：文档问答（固定流程）用 Chain；订单查询（要调工具、看情况）用 Agent——先 Chain 后 Agent（能 Chain 就不 Agent）"**——结构：**对比 → 选型规则 → 自己项目实例**——"答出'自己的项目实例'比空讲概念强"。
