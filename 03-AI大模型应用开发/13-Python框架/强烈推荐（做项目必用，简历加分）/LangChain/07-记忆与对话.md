## 1. 记忆的定位

**模型本身无记忆——对话的"记忆"是应用的活**：

```text
记忆的定位
├── 模型的本质：每次调用都是"独立"的（不记得上次说了什么）
├── 记忆 = 应用把"历史消息"喂回模型（模型"看起来"记得）
├── 两种记忆：
│    短期：本次对话的历史消息（注入 prompt）
│    长期：跨对话的状态（用户偏好/历史记录——持久化）
└── 1.x 的变化：内置 Memory 模块软弃用——新姿势（本课 2/3 节）
    ——"记忆的本质：'假装记得'——把历史喂回去"
```

**定位心智**：**"记忆的记忆：'模型无记忆——记忆 = 把历史喂回模型'"**——"**为什么是应用的活：模型是无状态的 API（每次独立）——对话的连续性靠应用维护（存历史 + 喂回）——'模型是'健忘的天才'——应用是'记事本'"**（"记忆的成本：历史越长喂的越多（token 成本 + 上下文长度限制）——**'记忆的工程 = 成本与长度的平衡（本课 4 节）'"**）；**1.x 的变化（重要）**——"0.x 的 ConversationBufferMemory 等内置 Memory 已软弃用——**新姿势：短期用 messages 注入（本课 2 节）、长期用 LangGraph Checkpointer（本课 3 节）——'看到 ConversationBufferMemory 教程 → 旧写法'"**（"01 篇 v1.0 变化③的展开——**'记忆是 1.x 变化最大的领域之一'"**）。

## 2. 短期记忆：消息注入

**短期记忆 = 把历史消息直接注入提示词（1.x 推荐姿势）**：

```python
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_openai import ChatOpenAI
from langchain_core.output_parsers import StrOutputParser

# MessagesPlaceholder：历史消息的"插槽"（对话模板 04 篇的深化）
prompt = ChatPromptTemplate.from_messages([
    ("system", "你是智能客服。"),
    MessagesPlaceholder("history"),           # 历史消息插这里
    ("user", "{input}"),
])

chain = prompt | ChatOpenAI(model="gpt-4o-mini") | StrOutputParser()

# 调用时带上历史（应用自己维护历史列表——messages 注入）
history = [
    ("user", "我想退货"),
    ("assistant", "好的，请提供订单号。"),
]
result = chain.invoke({"history": history, "input": "订单号是 12345"})
# 模型"看到"了历史——知道上下文（"记得"刚才在聊退货）
```

**短期记忆心智**：**"短期记忆的记忆：'MessagesPlaceholder 插历史——应用自己传'"**——"**为什么 1.x 推荐：直接、透明（历史就是你传的消息——没有黑盒状态）——'对比 0.x 的 Memory 类（内部维护状态——黑盒）——注入式'看得见''"**（"应用的责任：自己维护历史列表（每轮对话后把 user/assistant 消息 append 进列表）——**'历史的维护 = 应用的活（框架给插槽，应用给历史）'"**）；**历史的组织**——"历史是消息列表（角色 + 内容——每轮 user/assistant 各一条）——**'历史的格式 = 消息序列（03 篇消息结构）'"**（"token 成本的控制：历史太长要截断（只留最近 N 轮——本课 4 节）——**'记忆的'长度管理'是工程的活'"**）。

## 3. 长期记忆：LangGraph Checkpointer

**长期记忆 = 跨对话持久化（LangGraph Checkpointer——1.x 推荐）**：

```python
# LangGraph Checkpointer：对话状态持久化（重启/跨会话记得）
from langgraph.checkpoint.memory import MemorySaver
from langgraph.graph import MessagesState, StateGraph

# ① 定义图（LangGraph 编排——08 篇 create_agent 的底层机制）
graph = StateGraph(MessagesState)             # 状态 = 消息列表
# ... 定义节点（模型调用等）...
app = graph.compile(checkpointer=MemorySaver())   # ② 配 Checkpointer

# ③ 用 thread_id 标识会话（同一 thread 共享记忆）
config = {"configurable": {"thread_id": "user-123"}}
# 多轮对话：同一 thread_id → 模型"记得"整个会话
# 不同 thread_id → 独立会话（不同用户/不同对话）

# 效果：对话状态持久化（进程重启也在——MemorySaver 内存版/数据库版）
```

**长期记忆心智**：**"Checkpointer 的记忆：'LangGraph 的状态持久化——thread_id 标识会话'"**——"**为什么用 LangGraph：1.x 的记忆走'状态管理'路线（LangGraph 的状态机——08 篇）——Checkpointer 负责'存状态'（对话历史）——'长期记忆 = LangGraph 状态 + Checkpointer'"**（"thread_id 的语义：会话/用户的标识（同一 thread = 同一对话——共享记忆）——**'thread_id = 记忆的'抽屉号'"**）；**Checkpointer 的存储**——"MemorySaver（内存——测试用）/ 数据库版（生产——Postgres 等）——**'生产用数据库 Checkpointer（记忆不丢）'"**（"了解即可：知道'Checkpointer 是 1.x 长期记忆的姿势'——LangGraph 深入是进阶体系的事——**'本课知道'姿势存在 + 基本用法'"**）。

## 4. 记忆的工程问题

**记忆的工程三问题——"有记忆了但不好用"**：

```text
记忆工程三问题
├── ① 长度爆炸：历史无限长 → token 成本涨 + 超上下文限制
│    —— 截断策略：只留最近 N 轮 / 摘要旧历史（滚动摘要）
├── ② 成本控制：历史是重复输入的 token（每次调用都喂）
│    —— 缓存（prompt caching——同一历史前缀缓存省钱）
└── ③ 多会话隔离：不同用户/会话不能串记忆
    —— thread_id 隔离（Checkpointer——本课 3 节）
    ——"记忆的工程 = 长度/成本/隔离的三管理"
```

**工程心智**：**"工程三问题的记忆：'长度/成本/隔离'"**——"**长度管理：历史不能无限长（截断到最近 N 轮——简单；滚动摘要——旧历史总结成一段——复杂但保留信息）——'截断 vs 摘要：简单 vs 保留'"**（"成本管理：历史重复喂 = token 重复计费——**'提示词缓存（prompt caching——`Function Calling 函数调用` 体系提过——同一前缀打折）'"**）；**隔离的重要性**——"用户 A 的记忆不能给用户 B（隐私 + 正确性）——**'thread_id 按用户隔离 = 记忆的安全边界（数据分析阶段 5 方向 C 08 篇隐私的落地）'"**（"了解即可：知道三问题 + 解法方向——**'具体策略（摘要算法/缓存配置）实践时定'"**）。

**记忆的完整对话流程**（多轮对话的落地姿势）："**① 接收用户消息**——应用层收输入；**② 组装消息**——历史（MessagesPlaceholder）+ 新输入 → 模板；**③ 调链**——chain.invoke（模型"看到"历史）；**④ 更新历史**——把本轮 user/assistant 消息 append 进历史列表（应用维护）——**'四步 = 多轮对话的标准循环（记忆的工程实现）'"**（"Agent 场景：create_agent + Checkpointer（thread_id）——循环自动管理记忆（08 篇）——**'手动循环（Chain）vs 自动循环（Agent）——复杂度换省心'"**）。
