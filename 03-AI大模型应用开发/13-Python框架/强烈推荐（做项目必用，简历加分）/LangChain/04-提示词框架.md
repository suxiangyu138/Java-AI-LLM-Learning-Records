## 1. 提示词的定位

**提示词 = LLM 应用的"说明书"——模板化解决"硬编码"问题（01 篇问题②）**：

```text
提示词的定位
├── 硬编码问题：提示词写死在代码里——改提示词要改代码（发版）
├── 模板化解法：提示词模板（变量插值）——改内容不改代码
├── 变量：用户输入/上下文/格式说明——动态插入
└── 管理：提示词与代码分离——改提示词不动代码（运营友好）
    ——"提示词是应用的'说明书'——说明书要能单独改"
```

**定位心智**：**"提示词的记忆：'模板 = 提示词与代码分离'"**——"**为什么重要：提示词的迭代频率高（调效果常改）——硬编码 = 每次改都要动代码（发版成本）——模板化 = 改模板文件（不动代码）——'提示词的'运营化'（产品/运营也能改）'"**（"变量插值：`{topic}` 占位符——invoke 时传入——**'模板 = 提示词的'函数'（参数化）'"**）；**提示词的框架价值**——"LangChain 不只给模板语法——给的是'提示词作为 Runnable'（02 篇——能进管道组合）——**'提示词模板 = 管道的第一环节（06 篇的 prompt | model）'"**（"提示词设计的学问（角色/示例/格式——`02-大模型基础与Prompt工程` 的提示词体系）——**'本课讲'框架用法'，提示词'怎么写好'是 Prompt 工程的课'"**）。

## 2. PromptTemplate：文本模板

**PromptTemplate = 文本型提示词模板（最简单的一类）**：

```python
from langchain_core.prompts import PromptTemplate

# 定义模板（{变量} 占位符）
template = PromptTemplate.from_template(
    "你是{role}。请用{style}的风格回答用户的问题：{question}"
)

# 填充变量（invoke 时传）
prompt = template.invoke({
    "role": "资深数据分析师",
    "style": "简洁专业",
    "question": "什么是 P95 延迟？",
})
print(prompt)     # 填充后的完整提示词（字符串）

# 管道用法（06 篇：prompt | model）
# chain = template | model | parser
```

**PromptTemplate 心智**：**"文本模板的记忆：'from_template + {变量} + invoke 填充'"**——"**模板的价值：① 变量插值（动态内容）；② 复用（同一模板不同变量）；③ 可测试（模板单独测）——'模板 = 提示词的'参数化'"**（"变量的管理：变量名要语义化（role/question——别人看得懂）——**'模板是给团队看的（变量名即文档）'"**）；**模板的边界**——"文本模板适合'单轮指令'（一个角色 + 一个问题）——多角色对话用 ChatPromptTemplate（下节）——**'单轮用 PromptTemplate、多轮用 ChatPromptTemplate'"**（"格式的注意：from_template 里 { } 是变量（要转义的字面花括号用 {{ }}）——**'占位符的转义是新手小坑（09 篇）'"**）。

## 3. ChatPromptTemplate：对话模板

**ChatPromptTemplate = 对话型提示词模板（多角色消息——现代应用的主力）**：

```python
from langchain_core.prompts import ChatPromptTemplate

# 对话模板（多角色消息——和 ChatModel 的消息结构对应）
chat_template = ChatPromptTemplate.from_messages([
    ("system", "你是{role}，用{style}风格回答。"),          # 系统设定
    ("human", "用户问题：{question}"),                       # 用户输入
    ("assistant", "好的，我来回答。"),                       # 示例/历史
    ("human", "请正式回答。"),                               # 追加指令
])

# 填充并转消息（输出是消息序列——直接喂 ChatModel——03 篇）
messages = chat_template.invoke({
    "role": "数据分析专家",
    "style": "专业严谨",
    "question": "什么是置信区间？",
})
# 消息序列（system/human/...——ChatModel 的输入格式）
```

**ChatPromptTemplate 心智**：**"对话模板的记忆：'from_messages + 角色消息列表'"**——"**为什么是主力：ChatModel 的输入是消息序列（03 篇）——ChatPromptTemplate 直接产出消息序列（不用自己拼）——'模板 ↔ 模型的无缝对接'"**（"角色的用法：system（设定——人设/规则）、human（用户）、assistant（历史/示例——少样本示例放这里）——**'角色 = 对话模板的'语法'"**）；**模板的组合**——"多个模板可拼接（MessagesPlaceholder——动态插入消息：历史/工具结果）——**'了解即可：知道'占位符可插历史/工具消息'（07/08 篇用）'"**（"模板与记忆的配合：历史消息动态插入（MessagesPlaceholder——07 篇记忆的机制）——**'对话模板是记忆的载体'"**）。

## 4. 提示词工程管理

**提示词工程管理——模板化之外的"管理姿势"**：

```text
提示词管理四件套
├── ① 模板文件化：提示词放独立文件（prompts/ 目录——不进代码）
├── ② 版本管理：提示词也走 Git（改动可追溯——回滚）
├── ③ 测试评估：提示词改动要有评测（效果对比——不能乱改）
└── ④ 最佳实践沉淀：角色清晰/示例充分/格式明确（Prompt 工程课）
    ——"管理的目的：提示词'可维护、可追溯、可评估'"
```

**管理心智**：**"管理的记忆：'文件化 + 版本 + 测试 + 最佳实践'"**——"**为什么重要：提示词是应用效果的'大头'（同样的模型不同的提示词效果天差地别）——'提示词管理 = 应用效果的'版本控制'"**（"工具：LangSmith 的提示词管理（追踪/对比——09 篇）——**'生产级提示词管理用 LangSmith'"**）；**提示词的评估**——"改提示词要评估（效果变好还是变坏——评测集）——**'提示词是'代码'——改动要测试（和代码同款纪律）'"**（"了解即可：知道'提示词要管理'——具体评估方法（评测集/对比）是 Prompt 工程体系的事——**'本课管'框架用法'，Prompt 工程管'怎么写好'"**）。

**模板的调试与常见坑**："**① 变量缺失报错**——invoke 时没传模板里的变量（KeyError——检查变量名）；**② 花括号转义**——要字面 `{}` 时写 `{{}}`（04 篇 2 节提过）；**③ 模板与模型不匹配**——ChatPromptTemplate 只能喂 ChatModel（不能喂纯 LLM）——**'三个坑 = 模板的新手三连（10 篇速查）'"**（"调试的姿势：先 invoke 模板看输出（填充对不对——再拼链）——**'模板单独测、链再组合（逐步验证——02 篇调试）'"**）。
