## 2. RAG 集成

**RAG（检索增强生成）= 检索 + 生成（LangChain 的经典组合——学习重点 2026）**：

```python
# RAG 四步（LangChain 姿势）
# ① 加载与切分（文档 → 块）
from langchain_community.document_loaders import TextLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter

loader = TextLoader("docs.txt")
docs = loader.load()
splitter = RecursiveCharacterTextSplitter(chunk_size=500, chunk_overlap=50)
chunks = splitter.split_documents(docs)

# ② 向量化 + 存储（块 → 向量库）
from langchain_openai import OpenAIEmbeddings
from langchain_community.vectorstores import Chroma

vectorstore = Chroma.from_documents(chunks, OpenAIEmbeddings())

# ③ 检索（问题 → 相关块）
retriever = vectorstore.as_retriever(search_kwargs={"k": 3})

# ④ 生成（问题 + 检索块 → 回答——LCEL 链）
from langchain_core.prompts import ChatPromptTemplate

prompt = ChatPromptTemplate.from_messages([
    ("system", "只根据提供的资料回答：{context}"),
    ("user", "{question}"),
])
chain = (
    {"context": retriever, "question": lambda x: x["question"]}
    | prompt
    | ChatOpenAI(model="gpt-4o-mini")
    | StrOutputParser()
)
answer = chain.invoke({"question": "文档里说了什么？"})
```

**RAG 心智**：**"RAG 的记忆：'加载切分 → 向量化 → 检索 → 生成——四步'"**——"**RAG 的价值：给模型"外部知识"（私有文档/最新数据——模型不知道的）——'RAG = 模型的'外接知识库'（`04-RAG检索增强生成/` 体系的全景——本课给 LangChain 姿势）'"**（"四步的 LangChain 姿势：每步都有集成件（加载器/切分器/向量库/模型）——**'RAG = 集成生态的'样板组合'"**）；**RAG 的选型**——"向量库选型（Chroma 轻量/Milvus 生产——`08-向量数据库/` 体系）、切分策略（语义切分是 2026 趋势——04-RAG 体系）——**'RAG 的深潜是 RAG 体系的课——本课知道'LangChain 怎么拼 RAG'"**（"学习重点（2026 官方）：LCEL + RAG + LangGraph——**'RAG 是三大重点之二（本课给拼法）'"**）。

## 3. 与 vLLM 配合

**LangChain 与 vLLM 的配合——应用层调模型服务**：

```python
# vLLM 部署模型服务（vLLM 体系——02 篇）
# vllm serve Qwen/Qwen2.5-7B-Instruct-AWQ --quantization awq

# LangChain 接入（ChatOpenAI + base_url——03 篇姿势）
from langchain_openai import ChatOpenAI

model = ChatOpenAI(
    model="Qwen/Qwen2.5-7B-Instruct",        # vLLM 服务的模型名
    base_url="http://localhost:8000/v1",     # vLLM 的 OpenAI 兼容端点
    api_key="sk-no-key",
)

# 之后一切照常（LCEL/Agent/RAG 全用这个 model）
# chain = prompt | model | parser
# agent = create_agent(model, tools) —— 全兼容
```

**vLLM 配合心智**：**"vLLM 配合的记忆：'ChatOpenAI + base_url 一行接 vLLM——其余代码不动'"**——"**为什么零改动：vLLM 完全 OpenAI 兼容（vLLM 体系 05 篇）——LangChain 的 ChatOpenAI 只要 base_url 指向它——'模型服务（vLLM）+ 应用框架（LangChain）的'标准接法'"**（"配合的价值：开源模型自部署（数据不出内网/成本可控）+ LangChain 编排（应用开发效率）——**'生产架构：LangChain 应用 → vLLM 模型服务（分层）'"**）；**配合的注意**——"模型能力差异（开源 vs GPT——05 篇 vLLM 的兼容提醒）——**'接口兼容 ≠ 能力一致——效果要评估'"**（"配合的延伸：Ollama 也能接（同样 OpenAI 兼容——`了解即可/vLLM/08 篇` 生态）——**'模型服务随便换——LangChain 代码不动（ChatModel 统一的价值）'"**）。

## 4. LangSmith：可观测性

**LangSmith = LangChain 的可观测性平台（生产必配——生态四件套）**：

```text
LangSmith 的价值
├── 追踪：每次调用（链/Agent）的完整轨迹（哪个环节慢/错）
├── 调试：出问题看轨迹（定位到具体环节）
├── 评估：提示词/模型改动的效果对比（评测集）
├── 成本：token 用量监控（钱花哪了）
└── 提示词管理：提示词的版本/发布（04 篇管理的工具化）
    ——"LangSmith = LangChain 应用的'监控 + 调试 + 评估'三合一"
```

```python
# 接入（极简——环境变量即启用）
# export LANGCHAIN_TRACING_V2=true
# export LANGCHAIN_API_KEY=ls-xxx
# 之后所有 invoke/stream 自动被追踪（LangSmith 后台看轨迹）

# 生产姿势：链/Agent 全部接追踪 + 评估（效果对比）
```

**LangSmith 心智**：**"LangSmith 的记忆：'追踪/调试/评估/成本——生产必配'"**——"**为什么重要：LLM 应用的'黑盒'问题（模型输出不可预测——出错要能定位）——LangSmith 的轨迹让你看到'哪一步错了/慢在哪'——'LLM 应用的可观测性 = 生产的下限（01 篇生态四件套的观测件）'"**（"评估的价值：提示词/模型改动不能靠感觉（04 篇管理）——评测集对比（改前 vs 改后分数）——**'评估 = 提示词工程的'尺子'"**）；**接入的姿势**——"环境变量开启（几行配置）——**'先接追踪（零成本——白拿），再谈评估（生产进阶）'"**（"了解即可：知道'LangSmith 是生产标配'——**'具体平台操作（后台/评测集）用时学——本课给'为什么 + 怎么接'"**）。

**集成生态的选型姿势**（按项目需求选集成）："**① 定需求**——要什么（RAG → 向量库；Agent → 工具；生产 → LangSmith）；**② 查集成**——官方文档的集成列表（langchain-xxx 包——按需求装）；**③ 验证**——装包 + 配置 + 最小测试（会接一个 = 会接所有）——**'三步 = 集成选型的标准流程'"**（"集成的版本注意：langchain 与 langchain-xxx 版本要兼容（一起升）——**'集成包的版本跟着主包走（10 篇速查）'"**）。

**集成生态的向量库选型速查**（RAG 场景）："**Chroma**——轻量（本地/原型——开箱即用）；**FAISS**——快速（内存索引）；**Milvus**——生产级（大规模/分布式——`08-向量数据库/` 体系）；**Elasticsearch**——已有 ES 的团队（检索 + 向量一体）——**'选型：原型 Chroma、生产 Milvus（规模决定）'"**（"向量库的衔接：LangChain 的集成包（langchain-milvus 等）——装包即接——**'向量库选型深潜是 08-向量数据库 体系的课——本课给'LangChain 姿势'"**）。
