## 1. 序列化全景

pydantic 的序列化是**校验的镜像**：校验是"外部数据 → 模型"，序列化是"模型 → 外部数据"。**序列化不是简单的字段复制**——它有自己的规则层：字段过滤（include/exclude）、别名（by_alias）、round_trip（保持可回读）、计算字段（computed_field）、多态处理（serialize_as_any）——**"模型内部形态 ≠ 对外形态"**是设计序列化时的核心心法：内部可以自由组织，对外输出由序列化参数决定。两条主线：**进内存的用 dict（model_dump）、出网络的用 JSON（model_dump_json）**——两者参数基本一致，按出口选择。

## 2. model_dump：dict 出口

```python
data = order.model_dump()                  # 全量 dict
data = order.model_dump(exclude={"note"})  # 排除字段
data = order.model_dump(include={"id", "total"})  # 只留字段
data = order.model_dump(exclude_none=True) # 排除 None 字段（最常用）
data = order.model_dump(by_alias=True)     # 用别名输出（06 篇）
data = order.model_dump(mode="json")       # JSON 兼容类型（Decimal→str）
```

**参数家族**：`include/exclude`（字段白名单/黑名单——**set 与 dict 嵌套写法都支持**，`exclude={"addr": {"zip"}}` 只排除嵌套字段）、`exclude_none`（空值清理，**下游是数据库/下游接口时几乎必开**）、`by_alias`（对外用别名）、`mode`（**"json" 模式把 Decimal/datetime 等转成 JSON 兼容类型**——进缓存/消息队列的场景高频使用）。**选型主线**：**默认 model_dump() 全量，出库/出接口前按需 exclude_none + include**——"先全量再看需求删"比"每次都写一堆过滤"好维护。

**exclude 的嵌套写法**：`exclude={"addr": {"zip"}}` 只排除嵌套模型的 zip——**字段级过滤支持路径语法**；`exclude={"addr__zip"}`（`__` 路径写法）是 set 简洁版——**"要过滤嵌套字段，路径写法两选一"**。

## 3. model_dump_json：JSON 出口

```python
s = order.model_dump_json()                 # 默认紧凑输出
s = order.model_dump_json(indent=2)         # 格式化（日志/调试）
s = order.model_dump_json(exclude_none=True, by_alias=True)
```

**与 dict 路线的关系**：`model_dump_json()` **不经过 model_dump**——直接在 Rust 层序列化（更快，少一次 Python 对象中间态）；参数与 model_dump 基本同源（exclude/include/exclude_none/by_alias）。**性能提示**：日志/接口输出 JSON 用 model_dump_json 而非 `json.dumps(model_dump())`——**省一次 dict 构造 + 一次 dumps**（08 篇性能）。**编码细节**：默认 ensure_ascii=False 输出 UTF-8（中文友好），无需像 json.dumps 一样手动关 ASCII 转义。

## 4. model_copy：复制与修改

```python
u2 = user.model_copy()                        # 深拷贝（默认深拷贝嵌套）
u2 = user.model_copy(update={"age": 30})      # 复制并改 age
u2 = user.model_copy(deep=False)              # 浅拷贝（嵌套共享）
```

**model_copy 的三个认知**：其一，**默认是深拷贝**——嵌套模型/容器一起复制，改副本不动原对象（与 Python dict 的浅拷贝默认不同——**别拿 `copy.copy(model)` 的直觉套它**）；其二，**update 是"复制 + 单字段替换"惯用法**——"不可变更新"风格，比"复制后逐字段赋值"少一行且语义清晰；其三，**2.14 起的行为优化**——**只深拷贝 update 涉及的字段，其余字段浅拷贝共享**——性能提升，对"复制后只改一个字段"的场景无感知，但"复制后改嵌套结构"的场景要留意（共享的嵌套对象会被两个实例看到）。**生产姿势**：把模型当"不可变值对象"用（配合 frozen，06 篇），每次变更走 model_copy(update=...)。

**与 frozen 的配合**：frozen 模型 + model_copy(update=...) = "不可变更新"惯用法——**改数据永远产生新对象，老对象不可变，并发安全**（06 篇 frozen）；配合 2.14 的"只深拷贝更新字段"优化，热路径的复制成本进一步下降。

## 5. computed_field：计算字段

```python
from pydantic import BaseModel, computed_field

class Order(BaseModel):
    base: float
    tax_rate: float = 0.1

    @computed_field
    @property
    def total(self) -> float:
        return round(self.base * (1 + self.tax_rate), 2)

o = Order(base=100)
o.model_dump()      # {'base': 100.0, 'tax_rate': 0.1, 'total': 110.0}
```

**computed_field 是"派生只读字段"的正解**：**不进校验、不进构造参数，但进序列化输出**——"展示用、不算输入"的字段（总额、年龄、拼接名）都在这里。**与 04 篇"after 校验器里硬塞字段"对比**：computed_field 是只读派生（每次序列化时现算），校验器塞字段是写回模型（有状态）——**"派生展示用 computed_field，需要持久化的计算才用校验器/私有属性"**。**v2.13 新特性**：computed_field 支持 `exclude_if`——按条件跳过该计算字段的输出（如 total 在未定价时排除）。**注意**：computed_field 默认**不参与 model_validate**（不能从 dict 传入）——别拿它当"可选输入字段"。

## 6. 多态序列化：serialize_as_any 与 polymorphic

```python
from typing import Union
from pydantic import BaseModel, SerializeAsAny

class Cat(BaseModel): name: str
class Dog(BaseModel): name: str

class Zoo(BaseModel):
    animals: list[Union[Cat, Dog]]

class ZooAny(BaseModel):
    animals: list[SerializeAsAny[Union[Cat, Dog]]]

z = ZooAny(animals=[Cat(name="咪"), Dog(name="旺")])
print(z.model_dump()["animals"])
# 默认（Zoo）： 丢失子类信息，序列化成 Union 首个成员的结构
# SerializeAsAny：保留各自的完整结构（多态序列化）
```

**多态序列化的场景**：模型里有 `Union[基类, 子类]`（或基类字段被子类实例赋值）时，**默认序列化按"声明的联合类型"而非"实际类型"输出**——子类独有字段会丢。`SerializeAsAny[T]` 显式声明"**按实际类型序列化**"；**v2.13 新增 polymorphic_serialization 选项**（在字段上用 `SerializeAsAny` 之外的模型级配置）解决 2.12 引入 serialize_as_any 时的问题——**"联合类型字段要保留子类信息，就声明 SerializeAsAny"**（错误消息与判别联合结合时尤其重要，07 篇）。

## 7. 序列化上下文与自定义序列化器

**序列化上下文（serialization_context）**：`model_dump(context={"user": current_user})` 把上下文传给字段序列化器——**"输出内容依赖调用方"的场景**（管理员看全量、普通用户看脱敏版）。**自定义序列化器**：

```python
from pydantic import BaseModel, field_serializer

class Secret(BaseModel):
    key: str

    @field_serializer("key")
    def mask(self, v: str) -> str:
        return v[:3] + "***"
```

**field_serializer/model_serializer** 与校验器对称：**序列化时对字段做变换**——脱敏（密钥/手机号）、格式转换（时间戳 → 可读时间）。**生产高频场景**：**日志脱敏与对外脱敏**——"内部存全量，出口看角色"（08 篇生产清单）。**注意方向**：序列化器在 model_dump 时运行，**不影响模型内部值**——"输出变换，不改状态"；也别在序列化器里抛校验类错误——**序列化失败是另一类异常，别和校验混为一谈**。

## 8. 五个常见坑

- **坑一**：`json.dumps(model.model_dump())` 序列化 datetime/Decimal 报错——**用 model_dump(mode="json") 或 model_dump_json()**，它们处理 JSON 兼容转换；
- **坑二**：序列化结果比输入少字段（computed_field 忘声明/被 exclude 误伤）——**对账：model_dump() 字段数 vs 输入字段数**；
- **坑三**：model_copy(update=...) 更新嵌套字段——update 只替换顶层字段，**嵌套修改要先 copy 嵌套对象再整体 update**（`m.model_copy(update={"addr": m.addr.model_copy(update={...})})`）；
- **坑四**：Union 字段序列化丢子类字段——**声明 SerializeAsAny 或判别联合**；
- **坑五**：脱敏写在业务代码里每个出口重复一遍——**集中到 field_serializer，出口自动脱敏**。
