## 1. 实战：订单解析 API 三合一

```python
# app.py —— 一个接口同时演示：pydantic 请求校验 + Settings 配置 + LLM 结构化输出
from fastapi import FastAPI
from pydantic import BaseModel, Field, ValidationError
from pydantic_settings import BaseSettings, SettingsConfigDict
from openai import OpenAI

class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_prefix="APP_", env_file=".env")
    openai_api_key: str          # 密钥只进环境变量

settings = Settings()
client = OpenAI(api_key=settings.openai_api_key)

class OrderInput(BaseModel):              # 请求体：严进 DTO
    model_config = ConfigDict(extra="forbid", populate_by_name=True)
    order_id: str = Field(pattern=r"^A\d{4}$")
    items: list[dict] = Field(min_length=1)
    note: str | None = None

class OrderParsed(BaseModel):             # LLM 结构化输出目标
    order_id: str
    items: list[Item]
    total: float = Field(gt=0)
class Item(BaseModel):
    sku: str; qty: int = Field(ge=1); price: float = Field(gt=0)

app = FastAPI()

@app.post("/orders/parse")
def parse_order(body: OrderInput):        # FastAPI 自动 model_validate_json
    resp = client.chat.completions.create(
        model="deepseek-v4",
        messages=[{"role": "user", "content": f"解析订单：{body.model_dump_json()}"}],
        response_format=OrderParsed,      # pydantic 模型 → JSON Schema
    )
    try:
        parsed = OrderParsed.model_validate_json(resp.choices[0].message.content)
    except ValidationError:
        raise HTTPException(422, "LLM 输出不符合契约")
    return parsed.model_dump()            # 出口：干净 dict
```

**验收三问**：① `curl -X POST .../orders/parse -d '{"order_id":"A1234","items":[{"sku":"P1","qty":2}]}'` 返回解析后的结构化订单；② 传多余字段/非法 order_id 返回 422（extra=forbid + pattern 生效）；③ 换不同模型输出仍被 pydantic 兜住（结构化输出失败返回 422 而非 500）。

**这个接口演示了 pydantic 在 Web + AI 场景的全部位置**：请求入口（OrderInput 契约）、配置层（Settings）、LLM 输出出口（OrderParsed 兜底）、响应出口（model_dump）——**一个文件覆盖本体系八成 API**；想加工具调用就再写一个工具模型塞进 tools 数组（09 篇第 3 节）。

**加试：换模型对比**——把 response_format 的模型换成另一家，验证 pydantic 兜底逻辑不变——"**契约与模型解耦，换模型零代码改动**"是结构化输出的工程价值。

## 2. 生产纪律清单

- **锁版本**：`pydantic==2.13.x`，无 v1 API 残留（grep 五连：`.dict(`/`.parse_obj`/`@validator`/`class Config`/`BaseSettings`）；
- **角色先行**：每个模型先想角色再配 model_config（DTO 严进/配置冻结/实体宽松）；
- **入口唯一**：外部数据只从"校验函数/校验注解"进来，业务代码见不到裸 dict；
- **错误结构化**：ValidationError 按 errors() 记录 loc/type/input，转业务错误码；
- **AI 数据不信任**：LLM 输出一律过 pydantic，失败走重试/兜底/明确报错三选一；
- **配置快速失败**：Settings/env 缺失启动即报错，yaml 配置 model_validate 后使用；
- **版本意识**：升级 pydantic 前读 CHANGELOG——**2.13 的多态序列化行为、2.14 的 Python 3.9 弃用是 2026 已知变更**，升级后全量测试。

## 3. 报错速查十条

| 报错 | 原因 | 修复 |
|------|------|------|
| ImportError: cannot import name 'BaseSettings' from 'pydantic' | v2 起移出主包 | `from pydantic_settings import BaseSettings` |
| AttributeError: 'User' object has no attribute 'dict' | v1 API | `model_dump()` |
| @validator 报错/无效 | v1 校验器 | `@field_validator` + `@classmethod` |
| PydanticUserError: config ... | ConfigDict 写法错误 | 检查键名（orm_mode→from_attributes） |
| ValidationError: field required | 必填字段缺失 | 给默认值或改 Optional；检查别名 |
| ValidationError: extra_forbidden | 多传了字段 | extra 改 ignore/allow，或调用方改 |
| ValueError: Field default cannot be mutable | 可变默认值 | `Field(default_factory=list)` |
| SchemaError: ... discriminator | 判别联合 tag 类型不对 | tag 字段用 Literal/枚举 |
| 输入正确却校验失败 | 别名未开/字段名不匹配 | `populate_by_name=True`；检查 alias |
| 性能突然变慢 | 热路径构造模型/TypeAdapter | 模块级复用；validate_json 直验 |
| 迁移后行为变了（默认值也过校验器/after 不能改字段） | v1→v2 语义差异 | 重读 04 篇迁移对照，逐项排查 |

**三层定位方法论**：先查环境（版本/依赖）→ 再查代码（API 写法/配置）→ 最后查数据（字段/格式）——**环境类（BaseSettings 导入/版本）最先排查，因为 2026 年最大的坑是 v1/v2 混用**。

## 4. 面试三范式

**范式一：价值式**——"我的服务每天处理百万级请求，所有外部输入（HTTP/消息队列/LLM 输出）都经过 pydantic 契约校验：错误在入口拦截、日志结构化、下游零防御代码"——**用工程价值讲，不是背 API**。

**范式二：技术式**——"v2 是 Rust 核心重写，校验比 v1 快 5-50 倍；我的性能实践是 JSON 直验 + TypeAdapter 预热 + 少写 Python 校验器；v1 到 v2 的迁移我用 bump-pydantic 加人工排查校验器行为差异"——**展示深度与版本意识**。

**范式三：AI 式**——"LLM 结构化输出我全链路用 pydantic：response_format 传模型、工具声明用 model_json_schema、llm.yaml 用 model_validate 校验——LLM 输出不可信，pydantic 是最后质检员"——**2026 年最吃香的范式**（追问大概率落在失败处理上——背熟 09 篇第 2 节）。

**追问四连防身**：①"pydantic 和 dataclass 的区别？"——校验/转换/JSON Schema/错误聚合，dataclass 只是容器；②"校验和转换为什么一起发生？"——宽松模式智能转换是设计（"18"→18），strict 关掉它；③"性能热点在哪？"——JSON 解析与校验在 Rust，Python 校验器是插件；④"Union 为什么慢？"——逐个尝试；判别联合按 tag 一步分派；⑤"和 marshmallow/attrs 怎么选？"——生态绑定：FastAPI/OpenAI SDK 全栈 pydantic，选型成本最低，其余库是备选。
