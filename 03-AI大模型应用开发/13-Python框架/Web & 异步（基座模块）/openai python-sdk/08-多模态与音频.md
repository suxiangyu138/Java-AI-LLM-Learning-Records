## 1. 图像输入：视觉理解

多模态模型（gpt-5 系视觉版）可以直接**看图回答**——消息的 content 从字符串变成**内容数组**：

```python
resp = client.chat.completions.create(
    model="gpt-5.2",
    messages=[{
        "role": "user",
        "content": [
            {"type": "text", "text": "这张图里有什么问题？"},     # 文本 + 图片混合
            {"type": "image_url", "image_url": {"url": "https://example.com/photo.jpg"}},
        ],
    }],
)
print(resp.choices[0].message.content)
```

**图像输入两种来源**：其一，**URL**——`{"url": "https://..."}`（公网可达）；其二，**Base64 本地文件**——`{"url": f"data:image/jpeg;base64,{b64}"}`（读文件转 b64）——"**本地图、私网图一律 base64，只有公网图才直接 URL**"。

```python
import base64
with open("invoice.jpg", "rb") as f:
    b64 = base64.b64encode(f.read()).decode()
content = [
    {"type": "text", "text": "提取发票号、金额与开票日期，输出 JSON"},
    {"type": "image_url", "image_url": {"url": f"data:image/jpeg;base64,{b64}"}},
]
# 配 response_format 严格模式（05 篇），发票提取直接结构化输出
```

**"base64 是本地图像的通行证"**——票据 OCR/UI 截图/私有图片全走这条；配合 05 篇结构化输出，图像理解直接产出 JSON 数据。

**典型场景**：票据/合同 OCR 理解、UI 截图找 bug、商品图属性提取、质检看图——"**视觉理解 = 文本 prompt + 图片 content，其余与对话完全一致**"；注意**图片按 token 计费**（分辨率越高越贵），小图先压缩再传——"**多模态的账单看分辨率，别传 4K 原图问'这是什么颜色'**"。

## 2. 图像生成：images API

```python
resp = client.images.generate(
    model="gpt-image-1",          # 2026 图像生成模型
    prompt="水墨风格的山水画，清晨雾气",   # 提示词
    size="1024x1024",
    n=1,
)
url = resp.data[0].url           # 生成结果 URL（或 b64_json）
```

**图像生成要点**：`prompt` 决定一切（描述越具体越好）；`size` 决定分辨率与价格；`n` 一次生成几张（按张计费）；返回 URL 或 `b64_json`（要落盘用 b64，URL 会过期）——"**生成图的成本按张算，先 1 张验证 prompt，再批量**"。

**与图像输入的组合**：**生成图 → 再让模型评价/迭代**——"**先 generate 再 vision，多模态自闭环**"（设计/素材工作流常见）。

## 3. 语音合成：speech

```python
resp = client.audio.speech.create(
    model="gpt-4o-mini-tts",          # 语音合成模型
    voice="alloy",                    # 音色（alloy/echo/fable/onyx/nova/shimmer）
    input="你好，我是你的 AI 助手。",
)
resp.stream_to_file("hello.mp3")      # 直接落盘
# 或 resp.content 拿字节 → 转给前端
```

**TTS 三要素**：`voice` 音色选择（6 种预设）、`input` 文本、输出 mp3/wav 等格式——"**合成是文本到音频的一行转换**"；进阶用法：`instructions` 参数（指定语气/风格）、流式合成（长文本分段）——"**TTS 的体验差异在音色与语气，多试几种 voice**"。

## 4. 语音转写：transcriptions

```python
with open("meeting.mp3", "rb") as f:
    resp = client.audio.transcriptions.create(
        model="whisper-1",            # 转写模型（whisper 系）
        file=f,
        language="zh",                # 指定语言（加速 + 更准）
        response_format="json",       # json/text/srt/vtt 等
    )
print(resp.text)
```

**STT 要点**：`file` 是文件对象（支持 mp3/wav/m4a 等）、`language` 指定语言（中文 `zh`，不指定会自动检测但略慢）、`response_format` 支持 **srt/vtt**（带时间戳字幕格式）——"**会议纪要、客服质检、字幕生成是 STT 三大场景**"；长音频先切片再转写（whisper 有长度上限）——"**STT 的坑在长音频：先切片、后拼接、带时间戳**"。

**切片与拼接的工程细节**：按 60 秒窗口切片（保留 1-2 秒重叠避免断句丢失）→ 逐片转写 → 按时间戳拼接——"**切片是物理的，拼接是逻辑的——每片转出 (text, start, end)，按时间轴合并**"；会议纪要场景还可以把整段转写文本再交给大模型做摘要与要点提取（08 篇全模态工作流）——"**STT 只是第一步，下游的摘要/结构化才是价值**"。

## 5. 场景与选型

| 能力 | API | 典型场景 | 成本直觉 |
|------|-----|---------|---------|
| 图像输入 | chat + image_url | 截图理解/OCR/质检 | 按 token（看分辨率） |
| 图像生成 | images.generate | 素材/设计/配图 | 按张 |
| 语音合成 | audio.speech | 语音助手/播报 | 按字符 |
| 语音转写 | audio.transcriptions | 会议/字幕/质检 | 按分钟 |

**选型四问**：其一，**要理解还是要生成**？——理解走 chat+image，生成走 images；其二，**实时还是离线**？——实时语音助手要 realtime API（更低延迟，07 篇并发同源），离线转写/合成用 audio 家族；其三，**质量还是成本**？——小图/短音频先上便宜配置，质量不达标再升级；其四，**中文场景**——TTS voice 试听对比，STT 显式 `language="zh"`——"**多模态选型 = 场景 × 实时性 × 成本，四问答完选型自动浮现**"。

**多模态与向量检索**：图像嵌入（如 OpenCLIP 系）产出向量后可入 chromadb/faiss 做图文检索——"**SDK 的视觉理解与向量库的图文检索是两个层次：理解是对话，检索是存储**"（06 篇链路同源）。

**全模态工作流参考**（客服质检系统）：**STT 转写通话录音 → 结构化提取（订单/情绪）→ 大模型分析 → TTS 生成答复语音**——"**语音进、数据出、语音回，一条全模态管道**"；每个环节独立可测（转写准确率、提取准确率、合成自然度），分环节优化——"**多模态项目 = 单模态环节的串行拼装，每环先测准再拼接**"。

## 6. 常见坑

1. **私网图片直接 URL**——模型服务端取不到；base64 内联。
2. **4K 原图上传问简单问题**——token 浪费；先压缩再传。
3. **生成图用 URL 落库**——URL 会过期；要持久化用 b64_json。
4. **STT 长音频一次传**——超限报错；先切片（如 60s 一段）再拼接。
5. **STT 不指定语言**——中文识别率下降 + 变慢；`language="zh"`。
6. **TTS 逐条调用**——长文本分段流式合成；批量文本循环调用费时费钱。
7. **多模态模型选错**——普通 gpt-5.x 可能不支持视觉；确认模型支持矩阵。
