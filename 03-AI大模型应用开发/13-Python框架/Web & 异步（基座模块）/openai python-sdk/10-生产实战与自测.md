## 1. 实战：智能问答 Agent 端到端

**场景**：知识库问答 Agent——流式回答、可调用工具、结构化输出、FastAPI 发布。五层结构：

```python
# 第一层：客户端（进程级单例）
from openai import AsyncOpenAI
aclient = AsyncOpenAI(timeout=60.0, max_retries=2)

# 第二层：工具定义（查询型工具，05 篇）
def search_kb(query: str) -> str:
    """知识库检索：查 chromadb 返回相关片段"""
    res = kb_collection.query(query_texts=[query], n_results=3)
    return "\n".join(res["documents"][0])

tools = [{
    "type": "function",
    "function": {
        "name": "search_kb",
        "description": "知识库检索，回答产品问题时使用",
        "parameters": {"type": "object",
                       "properties": {"query": {"type": "string"}},
                       "required": ["query"]},
    },
}]

# 第三层：Agent 循环（工具调用五步，05 篇）
async def agent_loop(messages, max_rounds=8):
    for _ in range(max_rounds):
        resp = await aclient.chat.completions.create(
            model="gpt-5.2", messages=messages, tools=tools, tool_choice="auto")
        msg = resp.choices[0].message
        if resp.choices[0].finish_reason != "tool_calls":
            return msg.content                       # 最终回答
        messages.append(msg)
        for call in msg.tool_calls:
            result = search_kb(**json.loads(call.function.arguments))
            messages.append({"role": "tool", "tool_call_id": call.id,
                             "content": json.dumps(result)})
    return "抱歉，问题太复杂，请简化后重试。"        # 轮数上限兜底

# 第四层：FastAPI 发布（SSE 流式，04/07 篇）
@app.post("/chat")
async def chat(payload: dict):
    async def gen():
        stream = await aclient.chat.completions.create(
            model="gpt-5.2", messages=payload["messages"], stream=True)
        async for chunk in stream:
            if chunk.choices and chunk.choices[0].delta.content:
                yield f"data: {chunk.choices[0].delta.content}\n\n"
    return StreamingResponse(gen(), media_type="text/event-stream")

# 第五层：生产治理（09 篇）——usage 打点日志、429 监控、base_url 备胎、trace_id
```

**验收四问**：其一，**能流式**——SSE 逐 token 到达；其二，**能调工具**——问"产品支持退款吗"触发 search_kb 且回答带来源；其三，**有兜底**——8 轮上限触发友好提示，429 时有降级；其四，**成本可见**——每次调用 usage 落日志，能回答"今天花了多少钱"——"**四问过完，原型与生产的分界线就跨过了**"。

## 2. 生产模板与纪律清单

**骨架**：`AsyncOpenAI 单例 → 工具注册表 → agent 循环（轮数上限）→ SSE 发布 → usage/429/trace 打点`。**纪律清单六条**：

1. **Client 进程单例**，timeout/max_retries 构造时配好（02/09 篇）；
2. **key 只走环境变量**，永不入代码（09 篇）；
3. **工具 description 写触发条件**，工具循环设轮数上限（05 篇）；
4. **流式双层空判断**（choices/delta），finish_reason 确认结束（04 篇）；
5. **信号量贴限流并发**，429/5xx 才重试（07/09 篇）；
6. **usage 全量打点 + trace_id 贯穿**，成本与问题都可追溯（09 篇）。

## 3. 报错速查

| 报错 | 根因 | 处理 |
|------|------|------|
| AuthenticationError (401) | key 错误/过期 | 检查环境变量，轮换 key |
| RateLimitError (429) | 超出 RPM/TPM | 信号量限流 + 退避 + 降级 |
| NotFoundError (404) | 模型/端点不存在 | 查模型名与 API 支持矩阵 |
| BadRequestError (400) | messages/参数非法 | 检查角色/结构/schema |
| APIConnectionError | 网络/超时 | SDK 自动重试，业务层兜底 |
| 流式取 delta 报错 | 没判断空 choices | 双层空判断（04 篇） |
| 工具结果没生效 | 缺 tool_call_id/角色错 | tool 角色 + call_id 回传（05 篇） |
| 模型不支持 responses | 老模型 | 查支持矩阵，换模型（03 篇） |
| 响应截断 | max_completion_tokens 太小 | 调大输出上限（03 篇） |
| 费用异常 | key 泄露/循环调用 | 吊销 key + usage 打点审计（09 篇） |

## 4. 面试三范式

**范式一：价值式**——"openai SDK 是 LLM 应用的第一依赖——我用它交付了知识库问答 Agent：AsyncOpenAI 并发 + 工具调用 + SSE 流式 + FastAPI 发布，生产治理齐备（usage 打点/429 降级）——从原型到生产两周落地"。

**范式二：技术式**——"SDK 的核心是类型化客户端：chat.completions 与 responses 双 API（新项目推荐 responses：previous_response_id 服务端状态 + 内置工具 + 缓存提升 40-80%）；流式双层空判断 + finish_reason 确认；结构化输出走 json_schema 严格模式或 parse() Pydantic 解析；工具循环五步（追加→遍历→执行→回传→轮数上限）——底层是 httpx，重试/限流/类型化异常全内置"。

**范式三：生产式**——"生产四件事：key 环境变量 + 轮换；信号量限流 + 类型化异常分支（重试只给连接/429/5xx）；成本四板斧（prompt 缓存前缀稳定、模型分级、批量、usage 打点）；base_url 备胎降级——一个进程一个 Client，一个请求一条日志，一个 trace 贯穿多轮"。

**追问四连**：chat 与 responses 怎么选？（新项目 responses，存量 chat，参数映射表）→ 流式怎么处理？（双层空判断 + finish_reason + SSE）→ 工具循环的坑？（遍历全部 tool_calls + 轮数上限）→ 成本怎么控？（缓存命中 + 模型分级 + usage 打点）。

**简历呈现写法**：项目段写"基于 OpenAI SDK（gpt-5.x）+ FastAPI 构建智能问答 Agent：工具调用循环 + SSE 流式 + 结构化输出，并发限流治理与 usage 成本打点，p95 首 token 1.2s、日请求 10 万+——"**技术栈 + 能力点 + 量化数据三要素，一段话立住 LLM 应用工程能力**"。
