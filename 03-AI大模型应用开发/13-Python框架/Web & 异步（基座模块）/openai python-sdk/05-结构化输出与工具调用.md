## 1. 结构化输出：两种姿势

LLM 输出是文本，但业务要的是**数据**——提取、分类、路由都要 JSON。两种姿势：

**姿势一：JSON 模式（宽松）**——`response_format={"type": "json_object"}` 保证输出是合法 JSON（不保证字段）：

```python
resp = client.chat.completions.create(
    model="gpt-5.2",
    messages=[{"role": "user", "content": "把这句话转成 JSON：订购了 3 件红色 T 恤"}],
    response_format={"type": "json_object"},
)
import json
data = json.loads(resp.choices[0].message.content)   # 自己解析 + 自己校验字段
```

**姿势二：JSON Schema（严格）**——`response_format={"type": "json_schema", ...}` 用 schema 约束**字段与类型**，模型输出被强制匹配 schema：

```python
schema = {
    "type": "object",
    "properties": {
        "product": {"type": "string"},
        "quantity": {"type": "integer"},
        "color": {"type": "string", "enum": ["红", "蓝", "绿"]},
    },
    "required": ["product", "quantity"],
    "additionalProperties": False,
}
resp = client.chat.completions.create(
    model="gpt-5.2",
    messages=[...],
    response_format={"type": "json_schema",
                     "json_schema": {"name": "order", "schema": schema,
                                     "strict": True}},
)
```

**"JSON 模式保证'是 JSON'，JSON Schema 保证'是你要的 JSON'"**——生产提取任务一律 schema 严格模式；schema 写越细（enum/required/additionalProperties: False），输出越可控（与 Function Calling 体系 05 篇参数校验呼应）。

**严格模式三要素**：`strict: True`（强制 schema 匹配，模型不产出 schema 外内容）、`additionalProperties: False`（禁止未声明字段）、`required` 全标（必填字段不漏）——"**strict 是'硬规则'：它约束的不是概率而是结果**"；代价是 schema 里的 nullable 字段要显式声明 `type: ["string", "null"]`（联合类型）——"**严格模式的字段声明要完整，漏一个联合类型就 400**"。

## 2. parse()：Pydantic 解析封装

SDK 的 `parse()` 把"schema + 解析 + 类型校验"一步到位：

```python
from pydantic import BaseModel, Field

class Order(BaseModel):
    product: str
    quantity: int = Field(ge=1)
    color: str

resp = client.chat.completions.parse(       # parse 是 create 的封装
    model="gpt-5.2",
    messages=[...],
    response_format=Order,                  # 直接传 Pydantic 类！
)
order: Order = resp.choices[0].message.parsed   # 类型化对象，不是 JSON 字符串
print(order.product, order.quantity)
```

**parse() 的三个便利**：其一，**Pydantic 类即 schema**——不用手写 JSON Schema，`response_format=Order` 自动转；其二，**message.parsed 是类型化对象**——直接属性访问，免 json.loads + 手动校验；其三，**message.refusal** 检查模型是否拒绝输出——"**parse() 是生产提取任务的标准姿势：schema 声明、解析、校验一条龙**"。

## 3. 工具定义与调用

工具调用（Function Calling）让模型**不只是说话，还能做事**：

```python
tools = [{
    "type": "function",
    "function": {
        "name": "get_weather",
        "description": "查询指定城市的当前天气",
        "parameters": {
            "type": "object",
            "properties": {"city": {"type": "string"}},
            "required": ["city"],
        },
    },
}]
resp = client.chat.completions.create(
    model="gpt-5.2",
    messages=[{"role": "user", "content": "北京今天天气怎么样？"}],
    tools=tools,
    tool_choice="auto",          # auto 让模型自己决定调不调
)
print(resp.choices[0].finish_reason)   # "tool_calls" —— 模型要调工具！
```

**工具定义的要素**：`name`（64 字符内）、`description`（**写清楚什么时候用**——模型靠它选工具）、`parameters`（JSON Schema，**必填字段标 required**）——"**description 是模型的'工具说明书'，写得好坏决定选得对不对**"（与 Function Calling 体系 04 篇工具设计呼应）。**`pydantic_function_tool()` 辅助**：`from openai.lib import pydantic_function_tool`——Pydantic 类一键转工具定义，"手写 schema 太烦就用它"。

## 4. 完整调用循环

**finish_reason == "tool_calls" 不是终点，是分岔路**：

```python
messages = [{"role": "user", "content": "北京和上海哪个更冷？"}]
tools = [weather_tool]

while True:
    resp = client.chat.completions.create(
        model="gpt-5.2", messages=messages, tools=tools, tool_choice="auto")
    msg = resp.choices[0].message

    if resp.choices[0].finish_reason != "tool_calls":
        print(msg.content)          # 最终回答
        break

    messages.append(msg)            # ① 追加模型的工具调用消息
    for call in msg.tool_calls:     # ② 遍历所有调用（可能多个！）
        result = execute_local(call.function.name,      # 本地执行
                               json.loads(call.function.arguments))
        messages.append({           # ③ 工具结果回传（tool 角色）
            "role": "tool",
            "tool_call_id": call.id,
            "content": json.dumps(result),
        })
    # ④ 带工具结果回到循环头，模型会给出最终回答或继续调用
```

**循环五步铁律**：① 追加 assistant 消息（**整条带 tool_calls 的消息**）；② **遍历全部 tool_calls**（模型一次可能返回多个，只处理第一个是经典 bug）；③ 工具结果用 `tool` 角色 + `tool_call_id` 回传；④ 循环直到 finish_reason != "tool_calls"；⑤ **设置轮数上限**（如 8-12 轮）防死循环——"**模型说'我要调工具'你就执行并回传，这是 Agent 的最小循环**"（Function Calling 体系 03 篇调用循环工程同源）。

**工具执行的安全边界**：模型选工具、你执行——**执行前校验参数**（长度/范围/白名单），敏感操作（删除/下单/转账）加确认步骤，工具结果回传前脱敏——"**工具循环里，模型是'提议者'，你是'执行者'——权限与确认在你这层，别把执行权全交给模型**"（Function Calling 体系 05 篇参数校验与安全同源）。

## 5. 流式与工具

**stream=True 与工具的组合是特殊场景**：**API 会缓冲整个响应，等工具调用完整后再返回**——流式不会逐 token 吐工具参数：

```python
stream = client.chat.completions.create(..., stream=True, tools=tools)
tool_calls = {}      # {index: {"id":..., "name":..., "arguments": 拼接}}
for chunk in stream:
    for tc in (chunk.choices[0].delta.tool_calls or []):
        idx = tc.index                       # 按 index 分组
        tool_calls.setdefault(idx, {"id": tc.id, "name": tc.function.name, "args": ""})
        tool_calls[idx]["args"] += tc.function.arguments or ""   # 增量拼接
```

**"流式 + 工具的真相：先等完整 tool_calls，再走普通循环"**——**工具参数是增量拼接的**（arguments 分片到达，按 index 归组）；工具执行本身不是流式的（本地调用），流式主要服务最终回答——"**前端要打字机效果，后端该缓冲工具段**"。

## 6. responses 中的工具

responses 的工具调用是**平台托管**的：

```python
resp = client.responses.create(
    model="gpt-5.2",
    input="查一下今天 AI 新闻",
    tools=[{"type": "web_search"}],      # 内置工具：平台替你搜索
)
print(resp.output_text)                  # 搜索结果已并入回答
```

**两种工具形态**：其一，**内置工具**（web_search/file_search/code_interpreter）——**平台执行、自动回传**，不用写工具循环——"搜索/读文件/跑代码三件事白嫖平台能力"；其二，**自定义函数工具**——扁平形状 `{type: "function", name, description, parameters}`（03 篇映射表），结果用 `function_call_output` 项回传（带 call_id）——"**responses 把'内置工具'做进协议，自定义工具照旧**"。

**选择直觉**：**通用能力（搜索/代码/读文件）用内置工具**（平台执行、免维护）；**业务专属能力（查库存/下单/查库）用自定义工具**（本地系统、数据不出域）——"**内置工具是'借用平台能力'，自定义工具是'暴露你的能力'——两条线互补不互斥**"。

## 7. 常见坑

1. **只处理 tool_calls[0]**——模型一次返回多个调用；全部遍历。
2. **工具结果忘了带 tool_call_id**——回传校验失败，模型无法关联。
3. **没设轮数上限**——模型可能连环调用，死循环烧钱；8-12 轮上限。
4. **description 写"查询天气"**——模型不知道什么时候用；写清楚触发条件。
5. **流式里等 tool_calls 逐 token**——不会的；先等完整再循环。
6. **parse() 的 schema 没写 required**——模型可能漏字段；Pydantic 必填字段标好。
7. **responses 用嵌套 tool 形状**——校验报错；扁平形状。
