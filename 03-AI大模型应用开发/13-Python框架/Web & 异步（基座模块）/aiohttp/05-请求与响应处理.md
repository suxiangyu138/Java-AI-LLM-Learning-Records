## 1. 请求方法全家桶

`ClientSession` 为每个 HTTP 方法提供同名协程方法：`get`、`post`、`put`、`patch`、`delete`、`head`、`options`。签名高度统一——第一个参数是 URL，其余为可选命名参数（params、headers、json、data、timeout、proxy、allow_redirects 等），因此学会 `get` 就等于学会了全部。

```python
await session.get(url)
await session.post(url, json={"name": "aiohttp"})
await session.put(url, data=b"raw bytes")
await session.delete(url, params={"id": 42})
```

方法选择遵循 HTTP 语义：读用 GET、创建用 POST、整体替换用 PUT、局部修改用 PATCH、删除用 DELETE。REST 风格下方法名即意图，服务端（07 篇）也按同一套语义分发路由。

## 2. 参数传递的四种形态

**查询参数用 `params`**（不要拼进 URL 字符串）：dict 自动编码为 `?k=v&k2=v2`，重复键用 list 值：

```python
await session.get("https://api.example.com/search",
                   params={"q": "python 异步", "page": 1, "tag": ["ai", "http"]})
# → /search?q=python+%E5%BC%82%E6%AD%A5&page=1&tag=ai&tag=http
```

**JSON 体用 `json=`**：自动 `json.dumps` 并设 `Content-Type: application/json`。注意与 `data=` 互斥——`json=` 是它的语法糖，两者同传后写的生效。序列化器可自定义：`json_serialize` 参数可传 orjson 的 `dumps`，性能翻倍。

**表单与文件用 `data=`**：dict 被编码为 `application/x-www-form-urlencoded`（登录表单场景）；`aiohttp.FormData()` 支持文件流与多部分：

```python
data = aiohttp.FormData()
data.add_field("name", "file.pdf")
data.add_field("file", open("file.pdf", "rb"),
               filename="file.pdf", content_type="application/pdf")
await session.post("https://upload.example.com/", data=data)
```

**裸字节流用 `data=b"..."`**：直接作为请求体发送，不设 Content-Type（或自行设置）——适合 API 原始体传输。

## 3. 响应读取与编码

响应体读取有四种形态，按需选择，**不可重复读**（读一次即消费）：

```python
text = await resp.text()              # 文本（自动按 Content-Type 解码，默认 UTF-8）
data = await resp.json()              # JSON → dict/list
raw = await resp.read()               # 全量字节
async for chunk in resp.content:      # 流式分块（04 篇的 StreamReader）
```

`resp.text()` 的编码决策顺序：显式 `text(encoding="gbk")` 参数 → 响应头 charset → 自动检测（cchardet，装了 speedups 才快）→ 默认 UTF-8。中文站点乱码的第一排查点就是编码：响应头没声明时自动检测经常出错，明确传 `encoding=` 最可靠。

`resp.json()` 底层也是全量读取，大 JSON 没有流式解析——JSON 本身必须全量解析，无解。`resp.read()` 返回完整 bytes，适合二进制下载后处理。

响应元数据同样重要：`resp.status`（状态码）、`resp.headers`（响应头，字典式访问）、`resp.real_url`（重定向后的最终 URL）、`resp.url`（请求 URL）。

**响应与请求是一一配对的对象**：`resp.request_info` 持有所在请求的 URL、方法与头，异常处理时用它打印「哪个请求失败了」；`resp.history` 是重定向链（默认跟随时才有内容）；`resp.headers` 大小写不敏感——`resp.headers["Content-Type"]` 与 `resp.headers["content-type"]` 等价。**3.14 还新增两个生产实用属性**：`resp.output_size` 报告实际传输的响应体字节数（含解码前原始体积），`resp.upload_complete` 标记请求体是否已完整上传——批量上传场景用它判断「卡在发送还是等待响应」。这些元数据比日志更精确：状态码只告诉你结果，元数据告诉你过程。

## 4. 流式下载大文件

下载大文件（模型权重、视频、数据集）的正确姿势是流式落盘，不是 `read()` 全量进内存——1GB 文件全量读取直接内存爆掉。规范模板：

```python
async with session.get(url) as resp:
    resp.raise_for_status()
    with open("model.bin", "wb") as f:
        async for chunk in resp.content.iter_chunked(64 * 1024):
            f.write(chunk)
```

`iter_chunked(65536)` 以 64KB 块迭代，边下边写，内存占用恒定。这里不要用普通 `for chunk in resp.content`——aiohttp 3.x 中直接迭代 content 每次可能产生极小块，`iter_chunked` 保证块大小。下载中断可配合 Range 头断点续传：首次记录已写字节，重试时 `headers={"Range": f"bytes={done}-"}`，Append 模式继续写。

## 5. 重定向与错误处理

**上传下载的对称性**：流式下载是「边收边写」，流式上传是「边读边发」——`data` 传异步生成器（06 篇详述），两者共享同一个思想：**不把整个请求体/响应体放进内存**。1GB 文件下载用 `iter_chunked`，1GB 文件上传用生成器，内存占用都是几十 KB 级别。对称性还体现在错误处理上：下载中断重试用 Range 续传，上传中断要服务端支持分块（multipart 或分片）才能续——HTTP 协议本身不对称，工具姿势要跟着协议走。掌握这一对姿势后，「大文件」三个字不再让人恐慌。

**默认跟随重定向**（最多 10 次）。`allow_redirects=False` 关闭后，302 会原样返回给你处理——登录跳转、状态码驱动的流程（如 OAuth）常用。`resp.history` 记录重定向链。

重定向有三个隐藏行为值得注意：跨域重定向会丢弃请求级 `cookies` 参数（3.14 修复，见 04 篇 CVE）；`Authorization` 头跨域重定向时按规范剥离（3.14.3 修复了只剥离首个凭据头的 bug）；POST 跟随 302 时 aiohttp 会改 GET（RFC 语义，注意幂等）。

**错误处理靠 `raise_for_status()`**：

```python
try:
    async with session.get(url) as resp:
        resp.raise_for_status()          # 4xx/5xx → ClientResponseError
        return await resp.json()
except aiohttp.ClientResponseError as e:
    log.error(f"HTTP {e.status}: {e.message}，URL={e.request_info.url}")
except aiohttp.ClientError as e:         # 连接层错误总基类
    log.error(f"网络错误: {e}")
except asyncio.TimeoutError:
    log.error("请求超时")
```

异常层次是排查的罗盘：`ClientResponseError`（对端返回错误码）、`ClientConnectionError`（连不上、被断开）、`ClientPayloadError`（响应体不完整）、`TimeoutError`（超时）。重试只对连接层与超时错误做，对端 4xx 重试是浪费——这个判断见 08 篇。

## 6. 请求头与鉴权

默认头在 session 级配置，全会话生效；单请求 `headers=` 覆盖：

```python
session = aiohttp.ClientSession(
    headers={"User-Agent": "MyBot/1.0", "Accept": "application/json"})
async with session.get(url, headers={"User-Agent": "特殊覆盖"}) as resp: ...
```

**鉴权头三姿势**（按推荐排序）：

```python
# 1. 3.14 推荐：encode_basic_auth 生成头（BasicAuth 已弃用）
from aiohttp import encode_basic_auth
headers = {"Authorization": encode_basic_auth("user", "pass")}

# 2. 直接放 header
headers = {"Authorization": "Bearer <token>"}

# 3. 服务端下发 token：从响应头或 JSON 取，动态注入
async with session.post("/login", json=...) as resp:
    token = (await resp.json())["token"]
```

Bearer token 动态注入是 AI 应用的标准姿势：先登录换 token，后续请求带 `Authorization` 头。token 只放 headers 不放 URL——URL 会进日志、进历史记录，这是泄漏源。

## 7. 常见坑

**坑一：`resp.json()` 对非 JSON 响应报错**。先 `raise_for_status()` 再 `json()`，内容协商失败时（如 502 返回 HTML）报错信息才有意义。

**坑二：响应体重复读取**。`await resp.text()` 后再 `await resp.json()` 第二次是空的——StreamReader 消费即消失，需要两种形态时先 `read()` 拿 bytes 再自行 decode。

**坑三：POST 大文件全量进内存**。`data=open(f)` 传文件对象而非 `data=f.read()`——后者把整个文件读进内存，前者流式发送。

**坑四：query 拼进 URL**。特殊字符、中文不编码直接拼串，服务端收到的参数是坏的——永远用 `params` 参数。

**坑五：忽略 `resp.real_url`**。需要最终地址（短链还原、重定向审计）时用 `resp.real_url`，`resp.url` 只是原始请求地址。

**坑六：编码没指定**。爬虫中文站出现乱码 `锟斤拷`，优先排查 charset——显式传 `encoding=`。
