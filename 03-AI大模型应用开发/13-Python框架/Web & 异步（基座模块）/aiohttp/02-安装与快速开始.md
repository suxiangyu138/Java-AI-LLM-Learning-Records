## 1. 安装与版本锁定

aiohttp 是纯 pip 安装的标准包，但版本必须显式锁定。原因有二：一是 2026 年安全形势严峻，低于 3.14.0 的版本带两个公开 CVE（见 01 篇），锁旧版本等于主动留后门；二是它迭代快（3.13.x 一个季度内出了 5 个补丁），跨版本 API 有弃用迁移。

```bash
pip install "aiohttp==3.14.3"
```

**可选加速组件**：`aiohttp[speedups]` 一次性安装 C 扩展加速件——`aiodns`（异步 DNS 解析，显著提升域名解析速度）、`Brotli`（压缩响应解码）、`backports.zstd`（zstd 解码；3.14 起由 zstandard 改为此包，仅 Python <3.14 需要）、`cchardet`（编码检测）。注意：`[speedups]` 是性能件不是功能件，裸装完全可用，只是高并发场景下 DNS 解析会变成瓶颈。

**Python 版本矩阵**：3.14.0 起支持 Python 3.14（含 free-threading 构建）、3.13、3.12、3.11、3.10，**不再支持 3.9**。用 3.10 以下的老项目需要停在旧版本，同时承担安全风险——能升级就升级。

## 2. 第一个客户端请求

aiohttp 客户端的一切从 `ClientSession` 开始。三条铁律：session 必须 `async with` 管理（保证关闭）、请求必须放进 `async with`（保证连接归还池）、必须 `raise_for_status()`（否则 4xx/5xx 静默通过）。

```python
import asyncio
import aiohttp

async def main():
    async with aiohttp.ClientSession() as session:
        async with session.get("https://api.github.com/zen", timeout=aiohttp.ClientTimeout(total=10)) as resp:
            resp.raise_for_status()
            text = await resp.text()
            print(text)

asyncio.run(main())
```

`asyncio.run(main())` 是 Python 3.7+ 的标准入口：创建事件循环、跑协程、关闭循环。注意不要自己 `get_event_loop()` 再 `run_until_complete`——3.14 里 policy 已弃用，`asyncio.run` 是唯一推荐入口。

**这次请求的幕后**：`session.get(url)` 返回一个协程对象，真正执行发生在 await 之后——事件循环调度它去 DNS 解析（装了 aiodns 则异步解析）、建立 TCP 连接（从连接池取或新建）、发送请求头、等待响应头到达，然后 `async with` 退出时把连接归还连接池（不是关闭）。所以同样一段代码，并发跑 100 个协程时是 100 个请求交错推进：谁的响应先到谁先继续。理解这条流水线，后续 03 篇的并发模型、04 篇的连接管理就都有了落点。

## 3. 第一个服务端

服务端三步：定义处理函数、挂到 Application、run_app。处理函数是协程，接收 `web.Request`，返回 `web.Response`——整个处理过程不阻塞事件循环，这是它能抗高并发的根源。

```python
import aiohttp
from aiohttp import web

async def hello(request: web.Request) -> web.Response:
    return web.json_response({"message": "hello aiohttp"})

app = web.Application()
app.router.add_get("/", hello)

if __name__ == "__main__":
    web.run_app(app, port=8080)
```

运行后访问 `http://localhost:8080/` 即可收到 JSON。`web.run_app` 做了大量幕后工作：启动事件循环、绑定端口、响应 Ctrl+C 优雅关闭——开发期直接用，生产部署见 07 篇。

`web.run_app` 的常用参数也值得先混个脸熟：`host` 默认 `0.0.0.0`（容器内必须显式写，否则外部访问不到）、`port` 默认 8080、`print` 参数控制启动横幅、`access_log` 传 logger 后每条请求自动记访问日志。生产部署时这些参数换一种方式设置（Gunicorn worker），但语义相同——现在熟悉了，后面只是换壳。

## 4. 两端闭环

把客户端与服务端组合起来，验证「异步两端同进程」的能力——这是代理/网关类应用的雏形：

```python
async def proxy(request):
    async with aiohttp.ClientSession() as session:
        async with session.get("https://httpbin.org/get") as resp:
            data = await resp.json()
    return web.json_response(data)

app = web.Application()
app.router.add_get("/proxy", proxy)   # 客户端转发上游
web.run_app(app, port=8080)
```

请求 `/proxy` 时：aiohttp 服务端收到请求 → 同进程的 aiohttp 客户端发起上游请求 → 拿到 JSON 后返回。全程异步、无线程切换，这就是 aiohttp 双件套的独特价值。

**这个闭环再往前一步就是生产形态**：把上游地址、超时、重试次数做成配置，把客户端 session 挂到 app 的 `on_startup`（启动建好、清理关闭），再加一个错误兜底中间件——这就是一个最小可用的 API 网关骨架。aiohttp 官方文档把它叫「proxy 例子」，实际是双件套能力的浓缩演示：同一个进程、同一个事件循环里，服务端与客户端无缝接力。你会在 07 篇把它补全成完整的服务端骨架。

## 5. 环境验证

装完先验证再写代码，三行命令排除环境问题：

```bash
python -c "import aiohttp; print(aiohttp.__version__)"          # 应输出 3.14.3
python -c "import aiohttp; print(aiohttp.__http_impl__)"        # Python 实现或 C 加速
python -c "import sys; print(sys.version)"                       # 确认 Python ≥3.10
```

`__http_impl__` 显示 `python_impl` 或 `c_impl`——C 加速（llhttp 解析器）在 3.14 是默认自带编译的，如果显示纯 Python 版，通常是因为环境没有编译器导致源码安装失败，性能会差数倍。

**验证跑通的闭环标准**：客户端脚本打印出响应、服务端 curl 返回 JSON——两个「最小可运行」都成立后，后面的并发、超时、限流全部是增量修改；先跑通再优化，是这一篇给整个体系的节奏定调。

## 6. 常见安装与运行坑

**先给新手一个兜底流程**：报错先读最后一行（真正的错误永远在末尾），再按「是不是版本问题 → 是不是环境问题（Python 版本/位数/镜像）→ 是不是代码问题」三步定位；大部分「装不上」是镜像或 pip 版本问题，大部分「跑不起来」是事件循环姿势问题（见坑二坑三）。下面的坑按出现频率排序：老版本需要 C 编译器，3.14.x 已提供预编译 wheel，报错通常是 pip 太老或 Python 位数不匹配——先升级 pip 再装。

**坑二：`RuntimeError: Event loop is closed`**。常见于在 Jupyter/交互式环境重复运行脚本——事件循环被关过又跑协程。改用 `asyncio.run` 每次都新建循环即可。

**坑三：Jupyter 里跑 `asyncio.run` 报错**。Notebook 自带事件循环，用 `await main()` 顶层直接 await（Python 3.12+ 的 asyncio 模式）。

**坑四：`speedups` 装不上**。内网环境缺包，用国内镜像加 `-i https://pypi.tuna.tsinghua.edu.cn/simple`；裸装 aiohttp 不装 speedups 也不影响功能。

**坑五：DNS 解析慢到像卡死**。没装 aiodns 时走系统线程解析，并发场景排队——装 `aiohttp[speedups]` 解决。

**坑六：`ssl.SSLCertVerificationError`**。默认校验证书；公司内网自签证书环境可对单个 connector 设 `ssl=False` 或传 `ssl.create_default_context()` 加载自签 CA——全局关验证是安全事故。

**坑七：换版本后 `BasicAuth` 报 DeprecationWarning**。3.14 起弃用，改成 `encode_basic_auth()` 生成头，见 05 篇。

**坑八：`web.run_app` 端口被占**。报 `OSError: [Errno 98]`（Linux）或 `WinError 10048`（Windows），换端口或用 `port=0` 让系统随机分配再读 `TCPSite.port`（3.14 新增）。
