## 1. 完整流程五步

**对齐训练的完整流程——从数据到模型**：

```text
对齐完整流程五步
├── ① 准备数据：SFT 示例 / DPO 偏好对 / GRPO 题库（07 篇）
├── ② 加载底座：基座或 SFT 模型 + tokenizer（transformers——HuggingFace 体系）
├── ③ 配置训练：SFTConfig/DPOConfig/GRPOConfig（本课——配置中心）
├── ④ 跑训练：Trainer 或 CLI（本课——一行命令）
└── ⑤ 评估与交付：评测 + 保存 + 部署（本课——验收）
    ——"五步的骨架：数据 → 模型 → 配置 → 训练 → 验收——每一步都有对应篇"
```

**流程心智**：**"五步的记忆：'数据-模型-配置-训练-验收'"**——"**每一步的'坑'都有对应篇目：数据（07）、模型（HuggingFace 体系）、配置（本课）、训练（03/04/06）、验收（本课）——'流程是地图，篇目是路标'"**（"对齐流程与 SFT/DPO 单方法的流程同构——**'会一个方法的流程 = 会所有方法的流程（换数据换配置而已）'"**）；**流程的决策点**——"① 选方法（SFT/DPO/GRPO——09 篇）；② 选底座（基座 or SFT 产物）；③ 选资源（全精度/QLoRA——本课 4 节）——**'流程中的三个决策 = 对齐项目的三个关键选择'"**（"决策顺序：方法 → 底座 → 资源——**'先定方法再配资源'"**）；**流程的产物**——"对齐模型（适配器或全量）+ 训练日志 + 评估报告——**'交付 = 模型 + 文档（和 bitsandbytes 体系同款交付观）'"**。

## 2. 统一 CLI：一行命令

**v1.0 的统一 CLI——配置化训练的标准姿势**：

```bash
# 一行命令跑 SFT（YAML 配置 + 命令行参数）
trl sft \
  --model Qwen/Qwen2.5-7B \
  --dataset ./sft_data.jsonl \
  --output-dir sft-out \
  --learning-rate 2e-5

# DPO（加偏好对数据）
trl dpo \
  --model ./sft-out \
  --dataset ./pref_data.jsonl \
  --output-dir dpo-out

# GRPO（推理任务）
trl grpo \
  --model ./dpo-out \
  --dataset ./math.jsonl \
  --output-dir grpo-out

# YAML 配置（复杂项目——配置与命令分离）
# trl sft --config sft_config.yaml
```

**CLI 心智**：**"CLI 的记忆：'trl + 方法名 + 参数'——sft/dpo/grpo 三个子命令覆盖高频"**——"**CLI 的价值：不写 Python 代码也能训练（配置化）——'CLI = 对齐训练的'快捷方式'——参数直接传、结果直接存'"**（"CLI 内部还是调 Trainer（API）——**'CLI 是 API 的包装——复杂流程回 API（04 篇姿势二）'"**）；**CLI 的参数**——"模型/数据集/输出目录/学习率（常用四件套）+ YAML 配置（全量参数）——**'小项目命令行传参、大项目 YAML 配置'"**（"YAML 配置的复用：团队共享一套配置模板——**'配置即文档'"**）；**CLI 的工程价值**——"流水线友好（脚本里串命令：sft → dpo → grpo）——**'三步流水线 = 三条命令——对齐训练的'脚本化'"**（"和 Accelerate 集成（FSDP/DeepSpeed 多卡）——**'CLI + 多卡 = 生产级训练的入口'"**）。

## 3. Config 类：配置中心

**Config 类（SFTConfig/DPOConfig/GRPOConfig）——v1.0 的配置统一**：

```python
from trl import DPOConfig
from transformers import TrainingArguments  # 关系：Config 继承 TrainingArguments

# DPOConfig 常用参数（SFT/GRPO 的 Config 同构——方法特有参数不同）
config = DPOConfig(
    # 通用（继承自 TrainingArguments）
    output_dir="dpo-out",
    per_device_train_batch_size=2,
    gradient_accumulation_steps=8,     # 等效大 batch（显存紧时）
    learning_rate=5e-6,
    num_train_epochs=3,
    logging_steps=10,
    save_strategy="steps", save_steps=500,
    # DPO 特有
    beta=0.1,                          # 偏离参考模型程度（04 篇）
    max_length=1024,                   # 总长度
    max_prompt_length=512,             # 问题长度
)
```

**Config 心智**：**"Config 的记忆：'通用参数（transformers 继承）+ 方法特有参数（beta 等）'"**——"**SFT/DPO/GRPO 的 Config 同构（都继承 TrainingArguments）——会一个 Config = 会所有 Config（只差特有参数）——'Config 是 v1.0 的'统一配置语言'"**（"batch/学习率/保存策略是通用三件套——**'通用参数一套，特有参数记三个：SFT 无、DPO 的 beta、GRPO 的 num_generations'"**）；**Config 的继承关系**——"trl 的 Config 继承 transformers.TrainingArguments（复用训练器生态）——**'transformers 的参数 trl 全能用（多卡/精度/日志）'"**（"TrainingArguments 的参数体系（HuggingFace 体系有讲）——**'会 transformers 训练 = 会 trl 配置的 80%'"**）；**Config 的调试**——"打印 config 看参数（`print(config)`）——**'配置排障：打印 Config 看参数对不对（和 bitsandbytes 的 Config 同款思路）'"**。

## 4. QLoRA 结合：单卡对齐

**QLoRA + trl = 消费级显卡跑对齐（2026 单卡对齐的标准姿势）**：

```python
# 完整组合：4bit 底座（bitsandbytes）+ LoRA（peft）+ trl 训练
from trl import DPOTrainer, DPOConfig
from transformers import BitsAndBytesConfig, AutoModelForCausalLM, AutoTokenizer
from peft import LoraConfig
import torch

# ① 4bit 底座（bitsandbytes 四件套——`../bitsandbytes/04-4bit量化.md`）
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.bfloat16,
    bnb_4bit_use_double_quant=True,
)
model = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen2.5-7B", quantization_config=bnb_config, device_map="auto")
ref_model = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen2.5-7B", quantization_config=bnb_config, device_map="auto")

# ② LoRA 适配器（peft——只训这部分）
model = get_peft_model(model, LoraConfig(r=16, target_modules=["q_proj", "v_proj"]))

# ③ trl 训练（和全精度一样的 Trainer——底座 4bit 自动生效）
trainer = DPOTrainer(
    model=model, ref_model=ref_model, tokenizer=tokenizer,
    train_dataset=pref_dataset, args=DPOConfig(output_dir="dpo-out", per_device_train_batch_size=1),
)
trainer.train()
```

**组合心智**：**"组合的记忆：'bitsandbytes 底座 + peft 适配器 + trl 训练'——三件套 = 单卡对齐"**——"**三件套的分工：bitsandbytes 省显存（底座 4bit）、peft 省显存（只训适配器）、trl 管方法（DPO/GRPO）——'显存（前两个）× 方法（trl）——缺一不可'"**（"04/06 篇的组合配置在此汇总——**'本课是 bitsandbytes 体系与 trl 体系的汇合点'"**）；**组合的显存预估**——"7B 模型 QLoRA + DPO：底座 3.5GB（4bit）+ 适配器与训练开销（约 5-8GB）→ 24GB 卡舒适、12GB 卡勉强——**'先算账再开跑（02 篇账本 + 训练开销）——OOM 就减 batch 或换小模型'"**（"1.5B 模型的组合：8GB 卡即可跑（毕业项目首选）——**'小模型起步，验证流程再上大模型'"**）；**组合的产出**——**"训练完保存适配器（几十 MB）+ 合并/部署——'适配器即产品——对齐的产出形态与微调一致'"**；**单卡对齐的现实**——"24GB 卡：QLoRA + DPO 跑 7B（舒适）；12GB：跑 1.5-3B——**'单卡对齐的模型上限：显卡大小决定（02 篇账本）'"**（"消费卡对齐 = 2026 年平民可做（这就是 DPO 流行的硬件原因）——**'QLoRA + DPO = 让对齐从'贵族'变'平民'"**）；**组合的坑**——"ref_model 也要 4bit（显存双倍底座）、device_map 的坑（bitsandbytes 08 篇）、batch 小（显存紧）——**'组合的坑 = 各体系的坑之和——排障查各自的 08/09 篇'"**（"先各自跑通（bitsandbytes 加载 + trl 全精度训练）再组合——**'组合前先单测：分步验证是组合的排障法'"**）。

**训练参数的速查表**（三方法的常用值——写配置时直接查）："**通用**：batch 2-8（显存紧用 1 + 梯度累积）、max_seq_length 1024-2048、save_strategy='steps'（每 500 步存）；**SFT**：learning_rate 2e-5、epochs 3；**DPO**：learning_rate 5e-6、beta 0.1、epochs 1-3（偏好数据少——别多轮过拟合）；**GRPO**：learning_rate 1e-6、num_generations 8、max_completion_length 1024——**'速查表背三个数（学习率）+ 两个参数（beta/组大小）——其他抄默认'"**（"参数的心智：**'对齐训练的参数比预训练温和（小 lr/少轮次）——微调偏好别大动作'"**）。
