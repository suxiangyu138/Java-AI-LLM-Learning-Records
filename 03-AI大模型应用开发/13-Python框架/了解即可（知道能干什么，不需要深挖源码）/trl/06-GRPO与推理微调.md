## 1. GRPO 的定位

**GRPO（Group Relative Policy Optimization 组相对优化）= 用"组内相对分数"做 RL——推理模型的微调标配（DeepSeek-R1 路线）**：

```text
GRPO 的定位
├── 血统：DeepSeek-R1 带火的推理微调方法（Open-R1 复现路线）
├── 创新：去掉价值模型（PPO 四模型 → 两模型）——用"组内相对"算奖励
├── 流程：一个问题生成多个回答（一组）→ 按答案对错打分 →
│        组内相对优劣 → 优化策略（好回答的概率提升）
├── 地位：trl v1.0 稳定层（旗舰 trainer——Async GRPO 2026 新能力）
└── 场景：数学/代码等"答案可判分"的推理任务
    ——"GRPO = 推理模型的'竞赛训练'——答案是裁判，组内比高下"
```

**定位心智**：**"GRPO 的记忆锚点：'竞赛得分'——自己解题 + 机器判分"**——"**PPO 要价值模型估'期望分数'（军师）、GRPO 不需要——直接用'组内回答的分数对比'算优势（一组里答对的相对答错的就是好）——'GRPO 砍掉军师（价值模型）——用同组竞争代替'"**（"为什么能砍：推理任务的答案可判分（对/错）——**'可判分 = 不需要预测分数 = 不需要价值模型'"**）；**GRPO vs DPO 的定位**——"DPO 是离线（学偏好对）、GRPO 是在线（模型自己生成 + 判分）——**'DPO 学'什么好'（静态），GRPO 学'怎么得分'（动态试错）——推理任务要试错（解题思路要探索）'"**（"选型：一般对话用 DPO、推理任务用 GRPO——**'任务类型决定方法（09 篇决策）'"**）；**GRPO 的商业意义**——"R1/O1 类推理模型的微调标配——**'2026 年'推理模型'是热点——GRPO 是它的训练方法'"**（"知道'DeepSeek-R1 用 GRPO' = 知道它的江湖地位"）。

## 2. 一句话原理

**GRPO 的三句话原理**：

```text
GRPO 原理三行话
├── ① 生成组：一个问题让模型生成 N 个回答（组——如 8 个）
├── ② 组内打分：每个回答用"可验证奖励"打分（数学答案对错/代码能否运行）
│    —— 分数的参照系是"组内"（相对——不是绝对阈值）
└── ③ 相对优化：回答分数高于组内均值 → 概率提升；低于 → 压低
    ——"一句话：一组回答比高下——答得比队友好就奖励，比队友差就惩罚"
```

**原理心智**：**"GRPO 的直觉：'组内竞争'——不跟绝对标准比，跟队友比"**——"**绝对标准难定（'多少分算好'）、组内相对好定（'比组内平均好就行'）——'组内相对 = 免去了价值模型（不用预测绝对分数）——这就是 GRPO 的架构优势'"**（"组内比较的稳定性：噪声被平均掉（一组里运气成分互相抵消）——**'组内相对 = 天然的稳健性设计'"**）；**组大小（N）**——"每个问题生成几个回答（8 个是常用值）——**'N 大 = 对比更准但更费算力——N=8 是性价比起点'"**（"N 是 GRPO 的第一参数——**'组大小 = 精度与成本的旋钮'"**）；**与 PPO 的对照**——"PPO 用价值模型（预测分数）、GRPO 用组内均值（代替预测）——**'价值模型是'猜'、组内均值是'算'——能算就不猜'"**（"GRPO 的稳定性来源：少一个'猜'的组件——**'去掉价值模型 = 去掉一个不稳定源'"**）。

## 3. 可验证奖励：推理微调的关键

**可验证奖励（Verifiable Rewards）= 答案能被机器判分的奖励——GRPO 的燃料**：

```text
可验证奖励示例
├── 数学：答案和标准答案比对（对/错）——机器可判
├── 代码：提交代码能否通过测试用例（通过/失败）——机器可判
├── 事实问答：答案是否包含标准事实——半可判
└── 不可判分的（对话质量/写作美感）→ 不适合 GRPO（要奖励模型/人工）
    ——"可验证奖励 = '标准答案'存在的任务——没有标准答案，GRPO 没燃料"
```

**奖励心智**：**"可验证奖励的记忆：'标准答案可机器判分'——数学/代码是天然场景"**——"**R1 的推理能力从哪来：海量数学/代码题（答案可判分）→ GRPO 反复试错 → 模型学会'思考过程'（思维链）——'可验证奖励是推理模型的'健身房'"**（"不可判分的任务（写文章）→ 不能 GRPO（要 DPO/奖励模型）——**'任务的可判分性 = GRPO 的适用边界'"**）；**奖励设计的细节**——"格式奖励（要求输出带'思考过程'——推理模型的格式）、正确性奖励（答案对错）——**'奖励设计 = 引导模型的行为（02 篇奖励黑客的正面应用）'"**（"格式 + 正确性双奖励是推理微调的常见设计——**'会设计奖励 = GRPO 的核心手艺'"**）；**RLVR（Reinforcement Learning with Verifiable Rewards）**——"可验证奖励 RL 的统称（GRPO 是它的主流实现）——**'2026 年后训练流水线的最后一步：SFT → DPO → GRPO/RLVR'"**（01 篇流水线的完整形态——"推理任务加 GRPO，非推理停在 DPO"）。

## 4. trl 的 GRPO

**trl 的 GRPO 使用（v1.0 稳定层——API + CLI）**：

```python
# 姿势一：Python API（需要"奖励函数"——可验证奖励的编码）
from trl import GRPOTrainer, GRPOConfig
from transformers import AutoModelForCausalLM, AutoTokenizer

model = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-7B")   # SFT/DPO 后
tokenizer = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-7B")

def reward_fn(prompts, completions, **kwargs):
    """奖励函数：答案对错 → 1/0（可验证奖励的编码）"""
    rewards = []
    for p, c in zip(prompts, completions):
        answer = extract_answer(c)                    # 提取模型答案
        rewards.append(1.0 if answer == standard_answer(p) else 0.0)
    return rewards

config = GRPOConfig(
    output_dir="grpo-out",
    per_device_train_batch_size=2,
    num_generations=8,          # 组大小 N（每个问题生成几个回答）
    learning_rate=1e-6,         # RL 学习率更小（稳定）
    max_completion_length=1024,
)
trainer = GRPOTrainer(
    model=model, tokenizer=tokenizer,
    reward_funcs=[reward_fn],   # 奖励函数（可验证奖励）
    train_dataset=reasoning_dataset,   # 数学/代码题（问题 + 标准答案）
    args=config,
)
trainer.train()

# 姿势二：统一 CLI（v1.0——奖励函数配置化）
# trl grpo --model Qwen/Qwen2.5-7B --dataset ./math.jsonl --output-dir grpo-out
```

**使用心智**：**"使用记忆：'GRPOTrainer + 奖励函数 + 组大小'——比 DPO 多'奖励函数'这个核心"**——"**GRPO 的独有配置：reward_funcs（你写的判分逻辑——答案对错）+ num_generations（组大小）——'奖励函数是 GRPO 的'裁判'——你写裁判，模型竞赛'"**（"奖励函数 = 把'标准答案'变成'分数'的代码——**'写奖励函数 = GRPO 的主要工作量（判断逻辑要准）'"**）；**GRPO 的工程注意**——"生成 N 个回答 = N 倍算力（生成是 GRPO 的大头）——**'Async GRPO（v1.0 新能力）把生成与训练解耦——吞吐提升'"**（"v1.5.0 的 final-logit softcapping 进一步稳定——**'版本更新带来稳定性的进步——升到最新稳定版'"**）；**GRPO 的验收**——"推理评测集分数（数学/代码 benchmark）——**'GRPO 的验收 = 任务分数（不是对话观感）——推理任务的验收是'分数'"**（"对比 GRPO 前后：同一套数学题的得分——**'分数提升 = 推理能力提升的证明'"**）。
