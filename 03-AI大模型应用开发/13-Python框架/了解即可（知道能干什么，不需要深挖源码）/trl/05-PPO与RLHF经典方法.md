## 1. RLHF 的定位

**RLHF（Reinforcement Learning from Human Feedback 人类反馈强化学习）= 对齐的"经典范式"（PPO 是它的实现）**：

```text
RLHF 的定位
├── 历史：ChatGPT 背后的对齐方法（2022-2023 的明星）
├── 范式：奖励模型打分 + 强化学习优化（让模型追求"高分"）
├── 现状：2026 年仍是前沿实验室的选择（超大偏好数据 + 工程预算）
├── 地位：trl 中已降为实验层（v1.0 的 PPO——trl.experimental）
└── 对比：DPO 是它的"简化替代"（04 篇——效果接近、成本一半）
    ——"RLHF 是'经典'：开创了对齐时代——PPO 是'传说'：知道原理即可"
```

**定位心智**：**"RLHF 的记忆锚点：'奖励模型 + RL'——让模型追求分数"**——"**经典流程：训练一个'裁判'（奖励模型——给回答打分）→ 让模型用 RL 学习'怎么拿高分'——'RLHF = 模型的'应试训练'——为了高分而学习'"**（02 篇奖励黑客的温床——"分数可钻空子——**'RLHF 的优势与风险同源：奖励模型'"**）；**RLHF vs DPO 的定位**——"RLHF 是'正统'（理论上限高——在线生成能探索数据外）、DPO 是'平民'（成本低——离线）——**'2026 年：DPO 是主流、RLHF 是前沿——大多数团队选 DPO（09 篇选型）'"**（"知道 RLHF 的存在与原理 = 理解对齐的'完整图景'——**'经典与主流的差别：经典是历史，主流是现在'"**）；**RLHF 的名字拆解**——"RL（强化学习——试错学）+ HF（人类反馈——人类打分）——**'名字即方法：用人类反馈做强化学习'"**（"术语：RLHF 是范式名，PPO 是算法名（实现 RLHF 的一种算法）——**'RLHF ≈ PPO（在 LLM 对齐语境）——两者常混用'"**）。

## 2. 三阶段流程

**RLHF 三阶段——ChatGPT 对齐的经典流水线**：

```text
RLHF 三阶段
├── 阶段一：SFT——示例数据学格式（03 篇——地基）
├── 阶段二：训练奖励模型（Reward Model）
│    —— 数据：偏好对 → 训练"裁判"（给回答打 0-10 分）
│    —— 产物：奖励模型（判断"好不好"的模型）
└── 阶段三：PPO 强化学习
    —— 策略模型生成回答 → 奖励模型打分 → 优化策略（追求高分）
    ——"三阶段的比喻：SFT 教'说话'、奖励模型是'考官'、PPO 是'备考'"
```

**三阶段心智**：**"三阶段的记忆：'SFT + 考官 + 备考'"**——"**阶段二的产物（奖励模型）是阶段三的'考官'——考官的水平决定备考的效果——'奖励模型的质量 = RLHF 效果的上限（奖励模型瓶颈）'"**（"奖励模型的训练数据是偏好对（和 DPO 同源）——**'DPO 把'建考官'省了——直接让模型自己懂偏好'"**）；**三阶段的成本**——"每阶段都要训练 + 数据——**'RLHF 是'三步工程'——工程成本是 DPO 的 2-3 倍'"**（"显存：阶段三要 4 个模型同时加载（下节）——**'RLHF 的贵：不是方法贵，是工程贵'"**）；**三阶段的变体**——"省略阶段二（无奖励模型）→ 用启发式奖励（长度/关键词）——**'奖励的来源决定 RLHF 的变体——可验证奖励是 2026 的趋势（GRPO——06 篇）'"**（"GRPO 可看作 RLHF 的'现代变体'——**'经典 RLHF 的进化方向：绕开奖励模型'"**）。

## 3. PPO 的四个模型

**PPO 训练要同时加载四个模型——显存黑洞的来源**：

```text
PPO 四模型（同一次训练中都要在显存里）
├── ① 策略模型（Policy）：正在训练的模型（生成回答——主角）
├── ② 参考模型（Reference）：训练前的快照（约束别跑太远——安全带）
├── ③ 奖励模型（Reward）：给回答打分（考官）
└── ④ 价值模型（Value/Critic）：估计"预期分数"（PPO 的配套——算优势）
    ——"四个模型 × 全精度 = 显存爆炸——70B 的 RLHF 要 8×A100（即使 LoRA）"
```

**四模型心智**：**"PPO 四模型的记忆：'主角 + 快照 + 考官 + 军师'"**——"**策略模型是主角（要训的）、参考模型是快照（防跑偏）、奖励模型是考官（打分）、价值模型是军师（估计分数走势）——'四个角色一台戏，显存是舞台——舞台太小演不了'"**（"为什么 70B RLHF 要 8×A100：四模型 × 大参数 = 显存天文数字——**'这是 RLHF 贵族化的根源'"**）；**对比 DPO 的两模型**——"DPO 只要'策略 + 参考'（奖励消去了、价值不需要）——**'DPO 省显存的架构原因：四模型变两模型（04 篇三省的落地）'"**（"GRPO 更狠：只要'策略 + 参考'（无价值模型——06 篇）——**'模型数量的演进：4 → 2 → 2（PPO → DPO/GRPO）'"**）；**LoRA 的缓解**——"四模型都用 LoRA（4bit 底座——`../bitsandbytes/`）能省很多——但仍是最高显存的训练——**'LoRA 让 RLHF 从'不可能'变'勉强'——消费卡仍不现实'"**（"RLHF 的现实门槛：24GB 卡跑 7B PPO 都紧张——**'这就是大多数人选 DPO 的原因'"**）。

## 4. 为什么降为实验层

**trl v1.0 把 PPO 降为实验层——四个原因**：

```text
PPO 降级四原因
├── ① 训练不稳定：PPO 对超参极敏感——学习率稍大输出崩溃——调参噩梦
├── ② 显存黑洞：四模型（上节）——工程门槛高
├── ③ 奖励黑客：有奖励模型 = 有钻空子空间（02 篇）
├── ④ 奖励模型瓶颈：效果被"考官"质量卡住（奖励模型训练难）
└── 结论：v1.0 的立场——"稳定层（SFT/DPO/GRPO）随便用，PPO 谨慎用"
    ——"PPO 不是'不行'，是'难伺候'——库作者帮你把它放进'实验区'"
```

**降级心智**：**"PPO 降级的本质：'稳定性不足'——生产要稳定，实验层是'风险提示'"**——"**trl v1.0 的双稳定性模型：稳定层（语义化版本——生产可用）vs 实验层（无保证——trl.experimental）——'PPO 在实验层 = 官方劝你'别上生产'"**（"官方的态度就是行业的态度：**'2026 年生产对齐用 DPO/GRPO，PPO 留给研究'"**）；**PPO 的"复活"场景**——"超大偏好数据 + 工程预算 + 追求理论极限（前沿实验室）——**'PPO 是'有条件的最优'——条件：数据多 + 钱多 + 人强'"**（"判断自己是不是'有条件'：不是就别碰——**'选方法的现实主义：DPO 够用就别上 PPO'"**）；**了解即可的 PPO 观**——"知道原理（三阶段 + 四模型）、知道地位（实验层）、知道为什么（四原因）——**'PPO 是'对齐的历史课'——懂历史才能懂现在（DPO 为什么流行）'"**。
