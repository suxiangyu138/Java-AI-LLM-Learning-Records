## 1. SFT 的定位

**SFT（Supervised Fine-Tuning 监督微调）= 用"问题-标准答案"示例训练——对齐的第一步**：

```text
SFT 的定位
├── 数据：几千-几万条（问题 + 标准答案）——"示例数据"
├── 教法：模仿——让模型照着示例的格式与风格输出
├── 效果：模型学会"聊天格式/指令跟随/说话风格"
├── 场景：基座模型 → 对话模型的第一步（几乎必做）
└── 在 trl 的位置：稳定层（v1.0）——最基础也最常用
    ——"SFT = 对齐的'地基'——没有 SFT，后续 DPO/GRPO 无从谈起"
```

**定位心智**：**"SFT 的记忆锚点：'抄作业'——给答案学答案"**——"**基座模型会写文章但不会'聊天'（没学过对话格式）——SFT 用'问题-答案'示例教会它——'SFT 前后：从'写文章的天才'到'会聊天的助手'"**（02 篇三步的第一步——"SFT 是'模仿'：深度最浅、成本最低、几乎必做"）；**SFT vs 普通微调**——"普通微调（全量/LoRA）管'学什么'，SFT 特指'对齐用的监督微调'——**'trl 的 SFT 是'对齐语境'的监督微调——数据是对话格式'"**（"术语上：SFT ≈ 对话数据的指令微调——**'指令微调（Instruction Tuning）和 SFT 常混用——都是给示例学格式'"**）；**SFT 的定位局限**——"SFT 只能教'示例里有的'——示例没有的偏好（什么回答更好）学不到——**'SFT 教格式，不教判断——判断是 DPO 的事'**（04 篇衔接）。

## 2. SFT 教什么

**SFT 教的三样东西**（数据设计的三原则）：

```text
SFT 教三样
├── ① 格式：对话模板（角色/分隔符/系统提示）——"会聊天格式"
├── ② 风格：语气/长度/结构（简洁/详细/正式）——"会说人话"
├── ③ 行为：指令跟随（摘要/改写/问答——按指令做）——"会听话"
└── 数据三原则：
    示例质量 > 数量（1000 条好示例 > 10000 条脏示例）
    多样性覆盖场景（客服/写作/编程都要有）
    风格统一（你的产品要什么风格，示例就是什么风格）
    ——"SFT 的产出 = 数据的'风格'——数据像什么，模型就学什么"
```

**教法心智**：**"SFT 的效果完全由数据决定——'示例数据是 SFT 的剧本'"**——"**模型是'复读机'：示例怎么写，它怎么学——示例脏（错别字/坏答案）模型学脏——'数据质量 = SFT 效果的上限'"**（"GIGO（垃圾进垃圾出）在对齐里同样成立——**'SFT 数据清洗是第一步工作'"**）；**示例的多样性**——"只给'写代码'示例的模型只会写代码——**'覆盖产品全场景的示例 = 全面的 SFT'"**（"多样性不够 = 模型偏科——**'SFT 数据的多样性 = 产品的能力边界'"**）；**风格的统一**——"产品要'简洁风'，示例全给'详细风'——模型学成详细风——**'示例风格 = 产品的个性——想要什么个性，给什么示例'"**（"风格是产品的一部分——SFT 是'风格定制'"）。

## 3. 怎么用：trl 的 SFT

**trl 的 SFT 使用（v1.0 统一 CLI + Python API 两种姿势）**：

```python
# 姿势一：Python API（灵活——数据加工后调用）
from trl import SFTTrainer, SFTConfig
from transformers import AutoModelForCausalLM, AutoTokenizer

model = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-7B")
tokenizer = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-7B")

config = SFTConfig(
    output_dir="sft-out",
    per_device_train_batch_size=2,
    learning_rate=2e-5,
    max_seq_length=1024,          # 示例的最大长度
    dataset_text_field="text",    # 数据集里的文本字段
)

trainer = SFTTrainer(
    model=model, tokenizer=tokenizer,
    train_dataset=dataset,        # 数据集（text 字段——对话格式）
    args=config,
)
trainer.train()

# 姿势二：统一 CLI（v1.0 新姿势——YAML 配置 + 一行命令）
# trl sft --model Qwen/Qwen2.5-7B --dataset ./data.jsonl --output-dir sft-out
```

**使用心智**：**"使用记忆：'SFTTrainer + SFTConfig'（API 姿势）或 'trl sft'（CLI 姿势）"**——"**v1.0 的 CLI 是配置化（YAML 写参数）+ API 是脚本化（代码写流程）——'两种姿势选顺手：快速跑用 CLI，复杂流程用 API'"**（"CLI 的姿势：`trl sft --model ... --dataset ...`——**'一行命令跑 SFT = v1.0 的生产级姿势'"**）；**SFT 与 QLoRA 结合**（省显存）——"SFT 也可以配 QLoRA（4bit 底座 + LoRA——`../bitsandbytes/05-QLoRA微调.md` 的配置四件套 + SFTTrainer）——**'消费级显卡跑 SFT = QLoRA + SFTTrainer——2026 单卡对齐的标准姿势'"**（08 篇组合详讲——"本课知道'能组合'，08 篇给完整配置"）；**SFT 的收敛判断**——"loss 下降 + 评测集效果（对话质量）——**'loss 降不代表聊得好——SFT 的验收是'对话测试'不是数字'"**（"跑完让模型聊几句（你的场景）——**'验收 = 亲测，不只看 loss'"**）。

## 4. SFT 与对齐后续的关系

**SFT 是后续对齐的"地基"——三组关系**：

```text
SFT 与后续的关系
├── SFT → DPO：SFT 的产物是 DPO 的起点（先会格式，再学偏好）
│    —— DPO 直接在 SFT 模型上训练（不用从基座开始）
├── SFT 质量影响 DPO：SFT 学歪了，DPO 纠正成本高
│    —— "地基歪了，装修再好看也危险"
└── SFT 独立可用：很多产品只做 SFT（格式够了就上线）
    —— "SFT 是充分必要？——不，SFT 是必要，DPO 是优化"
```

**关系心智**：**"SFT 与 DPO 的关系：'先会说话，再说好话'"**——"**SFT 让模型会聊天（格式）、DPO 让模型说得好（偏好）——顺序不能反（不会格式的模型没法聊偏好）——'SFT 是 DPO 的前置条件'"**（"2026 流水线 SFT → DPO 的顺序是铁律——**'跳过 SFT 直接 DPO = 在沙地上盖楼'"**）；**SFT 的独立价值**——"很多产品 SFT 后直接上线（格式达标就够用）——**'DPO 是'更好'的追求，SFT 是'能用'的底线——先底线后更好'"**（"预算/数据有限：先 SFT 上线，再攒偏好数据做 DPO——**'渐进式对齐：SFT 起步，DPO 迭代'"**）；**了解即可的关系观**——"记住'SFT 先行、DPO 后续、顺序铁律'——**'三步流水线的第一块砖，别跳步'"**。

**SFT 的评估姿势**（怎么知道 SFT 学好了）："**① 对话测试**——问场景问题看格式与风格（是否像示例）；**② 格式检查**——角色/分隔符是否规范（示例格式的复现）；**③ 基准对比**——和 SFT 前模型的输出对比（格式改善 = 学到位）——**'SFT 的验收是'对话观感'——loss 数字是辅助不是标准'"**（"专业评估：用自动化测试集（指令跟随测试）——**'SFT 的评估从'人工看'到'测试集跑'——2026 年指令评测集是标配'"**）。
