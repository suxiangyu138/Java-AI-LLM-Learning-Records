## 1. 实战项目：DPO 对齐全流程

**实战项目 = 把本体系九课串成"亲手训通"的完整对齐流程**：

```text
实战项目三步（从数据到对齐）
├── 第一步：准备偏好对数据（07 篇）
│    50-100 条偏好对（自己的场景——写标注理由）
│    抽检质量（chosen 明显好于 rejected）
├── 第二步：SFT 起步（03 篇——顺序铁律）
│    小模型 SFT（示例数据）——得到"会格式"的底座
└── 第三步：DPO 对齐（04 篇）
    三件套（QLoRA + peft + DPOTrainer）训练
    验证：对齐前后输出对比（同一批问题）
```

```python
# 实战核心代码（第三步——DPO 对齐）
from trl import DPOTrainer, DPOConfig
from transformers import BitsAndBytesConfig, AutoModelForCausalLM, AutoTokenizer
from peft import LoraConfig, get_peft_model
import torch

# ① 4bit 底座（bitsandbytes 四件套）
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True, bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.bfloat16, bnb_4bit_use_double_quant=True)
model = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen2.5-1.5B", quantization_config=bnb_config, device_map="auto")
tokenizer = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-1.5B")
model = get_peft_model(model, LoraConfig(r=8, target_modules=["q_proj", "v_proj"]))

# ② DPO 训练（偏好对数据）
trainer = DPOTrainer(
    model=model, ref_model=AutoModelForCausalLM.from_pretrained(
        "Qwen/Qwen2.5-1.5B", quantization_config=bnb_config, device_map="auto"),
    tokenizer=tokenizer,
    train_dataset=pref_dataset,        # prompt/chosen/rejected
    args=DPOConfig(output_dir="dpo-out", per_device_train_batch_size=1,
                   learning_rate=5e-6, beta=0.1),
)
trainer.train()

# ③ 验证：同一批问题问对齐前后模型——对比输出（对齐效果的直观证据）
```

**实战心智**：**"实战的验收标准：'对齐前后对比'——同一批问题的输出差异"**——"**验收三看：输出更友好吗（格式）、更符合偏好吗（风格）、没变差吗（能力保持）——'对比 = 对齐效果的'体检报告'"**（"了解的验收观：跑通流程 + 记录对比——不深究数学（那是论文的事）——**'你验证的是'怎么用'，不是'为什么这么实现'"**）；**实战的显卡要求**——"1.5B QLoRA + DPO：8GB 显卡起步（和 bitsandbytes 体系同款环境）——**'没显卡：SFT 可 CPU（慢），DPO 建议 GPU'"**（"环境的准备：venv + trl 最新版 + 显卡——**'环境三件套（与 bitsandbytes 00 篇同款）'"**）；**实战的常见卡点**——"字段报错（09 篇速查）、显存不够（减 batch/组大小）、学歪（数据抽检）——**'卡住先查速查表，再查 Issues——别卡在同一个坑两次'"**。

## 3. 报错速查

**高频报错速查（09 篇完整版的精要——十选六）**：

| 报错/现象 | 原因 | 解法 |
|---------|------|------|
| `tokenizer` 参数报错 | 0.12+ 改名 | 用 `processing_class` |
| 老代码整体报错 | 0.x → 1.0 大迁移 | 看 MIGRATION.md |
| `KeyError: 'chosen'` | 字段名错 | 检查 prompt/chosen/rejected |
| loss 不降（不学习） | 数据没配对/lr 太小 | 抽检配对 + lr 升一档 |
| loss 变 NaN | lr 太大/float16 | lr 降一档 + bf16 |
| 学歪（输出怪） | 偏好对质量差 | 数据抽检（chosen 是否真的好） |

**速查心智**：**"六条的规律：'版本两条 + 数据两条 + 训练两条'"**——"**背下六条的'原因列'——报错时先对原因再对解法——'排障的本质是原因归类'"**（"新坑必记（09 篇纪律延续）——**'速查表是你的，不是我的——我的十条是起点，你的实战坑要补充'"**）。

## 4. 面试演练

**面试问答（对齐训练相关——本体系特有）**：

**Q1：让模型"听话"（对齐）你怎么做？**——答：**"对齐三步：① SFT——示例数据教格式与风格（先会说话）；② DPO——偏好对教好坏判断（再说好话——2026 对齐事实标准——不要奖励模型、稳定、显存是 PPO 一半）；③ 可选 GRPO——推理任务（数学/代码答案可判分——DeepSeek-R1 路线）——大多数产品做到 SFT + DPO 就够——实际项目用 QLoRA + DPOTrainer 单卡跑（24GB 卡 7B）——验收是同一批问题的对齐前后对比"**——结构：**三步 → 方法选型 → 工程落地 → 验收**——"答出'DPO 是事实标准、PPO 是实验层'是 2026 年的正确认知"。

**Q2：DPO 和 RLHF（PPO）的区别？怎么选？**——答：**"核心区别：RLHF 要训练奖励模型 + PPO 强化学习（四模型：策略/参考/奖励/价值——显存黑洞、不稳定、奖励黑客风险高）；DPO 发现奖励模型可消去——直接在偏好对上训练（两模型——省一半显存、快 3-5 倍、稳定）——选型：大多数团队 DPO（够用且便宜）；前沿实验室（超大偏好数据 + 预算）才用 PPO 追求理论极限——trl v1.0 把 PPO 降为实验层也印证了这个趋势——推理任务用 GRPO（无价值模型 + 可验证奖励）"**——结构：**对比 → 选型 → 趋势印证 → 补充 GRPO**——"答出'trl v1.0 的方法分层'显示跟进版本"。

**Q3：对齐数据怎么准备？**——答：**"三原则：① 差距明显（chosen 明显好于 rejected——模糊对比学不到）；② 维度聚焦（一次对比一个维度）；③ 标注一致（标注规范文档保证多人标准统一）——格式是 prompt/chosen/rejected 三字段——规模经验：SFT 千级、DPO 万级（5000-50000 条）、GRPO 题目级——数据来源：先找公开数据集（HuggingFace Hub 有现成偏好数据集），业务偏好自己标注或 LLM 生成 + 人工抽检——抽检是数据质量的生命线"**——结构：**三原则 → 格式 → 规模 → 来源 → 质量**——"答出'抽检'显示实战经验"。
