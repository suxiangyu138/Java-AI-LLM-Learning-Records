## 1. DPO 的定位

**DPO（Direct Preference Optimization 直接偏好优化）= 用偏好对直接训练的对齐方法——2026 年对齐事实标准**：

```text
DPO 的定位
├── 数据：偏好对（问题 + 好答案 chosen + 坏答案 rejected）
├── 教法：比较——让模型学"哪个好"（提高好答案的概率、压低坏答案）
├── 相比 RLHF 的三省：
│    省模型：不需要奖励模型（2 个模型 vs PPO 的 4 个）
│    省环节：不需要 RL 循环（像监督学习一样直接训）
│    省显存：约 PPO 的一半（02 篇对比）
├── 地位：2026 对齐事实标准（稳定层——trl v1.0 旗舰 trainer）
└── 场景：有高质量偏好数据的产品团队（大多数人）
    ——"DPO = 对齐的'性价比之王'——效果接近 PPO，成本只有一半"
```

**定位心智**：**"DPO 的记忆锚点：'批改作业'——给好坏答案学判断"**——"**PPO 要'建奖励模型 + RL 循环'（工程重、不稳定），DPO 绕开这一切——直接在偏好对上训练（像 SFT 一样简单）——'DPO 把 RL 问题变成了监督学习问题——这就是它流行的原因'"**（"数学上的故事：DPO 发现 RLHF 的目标函数有闭式解（奖励函数可消去）——**'知道'把 RL 变监督'这句话即可——数学细节是论文的事'"**）；**DPO vs RLHF 的数字**（2026 对比）——"训练速度 3-5 倍、显存约 50%、训练稳定（无 PPO 的崩溃）——**'速度/显存/稳定三赢——除了'理论上限'略低'"**（"PPO 理论上能发现超越人类标注的输出（在线生成）——DPO 是离线（只学数据里有的）——**'选 DPO 还是 PPO：预算与上限的权衡（09 篇）'"**）。

## 2. 一句话原理

**DPO 的一句话原理**：

```text
DPO 原理三行话
├── ① 传统 RLHF：训练奖励模型 → 用 RL 让模型最大化奖励（绕远路）
├── ② DPO 的发现：奖励模型的训练目标可以"代入"策略优化——
│    奖励函数被消掉，只剩下"策略模型 vs 参考模型"的对比
└── ③ 效果：直接让"好答案的概率 > 坏答案的概率"（β 控制差距大小）
    ——"一句话：不用训练奖励模型，直接优化'好答案比坏答案更可能'"
```

**原理心智**：**"DPO 的直觉：'让模型自己长成'偏好判断'"**——"**训练中：好答案的生成概率被推高、坏答案被压低——训练后：模型自带偏好（不用额外奖励模型）——'偏好内化进模型，而不是外包给奖励模型'"**（02 篇奖励黑客的呼应——"没有奖励模型 = 没有黑客温床——**'DPO 的低黑客风险来自架构（无奖励模型）'"**）；**β 参数（beta）**——"控制'偏离参考模型的程度'（相当于 RLHF 的 KL 惩罚力度）——**'β 小 = 激进（学偏好快但可能过度）；β 大 = 保守（稳但学得慢）——默认 0.1 起步'"**（"β 是 DPO 的唯一'感觉参数'——不懂就默认——**'β 调参是 DPO 后期优化的事，起步用默认'"**）；**DPO 的参考模型**——"训练中需要一个参考模型（通常是 SFT 模型本身）——**'DPO 的起点 = SFT 的产物（03 篇顺序铁律的落地）'"**（"参考模型的作用：防止模型'飘'（偏离 SFT 的格式太远）——**'参考模型是 DPO 的'安全带'"**）。

## 3. 怎么用：trl 的 DPO

**trl 的 DPO 使用（v1.0 稳定层——API + CLI 两种姿势）**：

```python
# 姿势一：Python API
from trl import DPOTrainer, DPOConfig
from transformers import AutoModelForCausalLM, AutoTokenizer

model = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-7B")       # SFT 后的模型
ref_model = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-7B")   # 参考模型
tokenizer = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-7B")

config = DPOConfig(
    output_dir="dpo-out",
    per_device_train_batch_size=2,
    learning_rate=5e-6,           # DPO 学习率比 SFT 小（微调偏好）
    beta=0.1,                     # 偏离参考模型的程度
    max_length=1024,              # 问题长度
    max_prompt_length=512,
)

trainer = DPOTrainer(
    model=model, ref_model=ref_model, tokenizer=tokenizer,
    train_dataset=preference_dataset,   # 偏好对数据集（chosen/rejected）
    args=config,
)
trainer.train()

# 姿势二：统一 CLI
# trl dpo --model Qwen/Qwen2.5-7B --dataset ./pref_data.jsonl --output-dir dpo-out
```

**使用心智**：**"使用记忆：'DPOTrainer + 偏好对数据 + 参考模型'——比 SFT 多两样（ref_model + chosen/rejected）"**——"**DPO 与 SFT 的配置差异：数据格式（偏好对 vs 单文本）、学习率（更小——5e-6 vs 2e-5——微调偏好别乱大动作）、参考模型（DPO 独有）——'会 SFT 就会 DPO——差在数据与两个参数'"**（07 篇数据格式详讲——"本课知道'要偏好对'，07 篇给格式"）；**DPO 与 QLoRA 结合**——"QLoRA 四件套 + DPOTrainer（底座 4bit——`../bitsandbytes/` 配置）——**'消费级显卡跑 DPO = QLoRA + DPOTrainer——2026 单卡对齐标准姿势'"**（08 篇组合详讲）；**DPO 的收敛判断**——"loss 下降 + 偏好测试（问偏好场景的问题看输出）——**'DPO 的验收：好答案风格的输出率——对话测试优先'"**（"跑完对比 DPO 前后：同一问题的回答是否'更像好答案'——**'前后对比 = DPO 效果的直观证据'"**）。

## 4. DPO 的局限

**DPO 的局限——知道什么时候它不够**：

```text
DPO 四局限
├── ① 离线方法：训练中看不到模型自己的生成（只能学数据里有的）
│    —— 数据没覆盖的偏好学不到（PPO 在线能探索）
├── ② 极端偏好失效：chosen 远好于 rejected 时效果差（差距太极端）
├── ③ 过拟合 chosen：容易"背"好答案（复读好答案而不是理解偏好）
└── ④ 数据要求：需要高质量偏好对（5000-50000 条——标注成本中等）
    ——"DPO 的局限总结：'数据上限'——它学得再好，也不超过数据的质量"
```

**局限心智**：**"DPO 局限的核心：'离线 = 数据上限'"**——"**DPO 只能学'数据里有的偏好'——数据没标'不该这么答'的场景，它不知道——'PPO 在线生成能发现数据外的（理论），DPO 不能'"**（"大多数场景数据够用（产品偏好是有限的）——**'DPO 的数据上限 vs PPO 的理论上限：大多数产品选前者（够用且便宜）'"**）；**过拟合 chosen 的识别**——"模型输出越来越像'好答案的复读'（风格僵化）——**'对策：数据多样性 + 早停（eval 监控）——别让模型背题'"**（"IPO（DPO 的变体——MSE 损失更抗噪）是抗过拟合的选择——**'知道变体存在，需要时换'"**）；**KTO 的补充**——"没偏好对只有好坏标签（点赞/点踩）→ 用 KTO（不需要成对——04 篇对比）——**'数据形态决定方法：偏好对用 DPO、好坏标签用 KTO'"**（"用户反馈数据（点赞）转 KTO 是 2026 低成本对齐的姿势——**'数据的成本决定方法的选择'"**）。
