## 1. 数据在对齐中的分量

**对齐效果 = 数据质量 × 方法（数据占大头）**：

```text
数据的分量
├── SFT：示例数据决定"格式与风格"（03 篇——剧本论）
├── DPO：偏好对决定"好坏判断"（本课——训练材料）
├── GRPO：题目 + 标准答案决定"推理能力"（06 篇——题库）
└── 共同规律：方法只是"教法"，数据是"教材"——
    "教材烂，再好的教法也教不出好学生"
    ——"对齐的成败 70% 在数据——方法只占 30%"
```

**数据心智**：**"数据心智的锚点：'教材论'——模型是学生，数据是教材"**——"**同样的 DPO 方法：高质量偏好对（认真标注的）vs 随手标的数据——效果天差地别——'先花时间在数据上，再谈方法'"**（"GIGO 在对齐里最明显——**'垃圾偏好进，歪模型出'"**）；**数据的成本**——"偏好对标注贵（要人判断好坏）——**'数据的预算 = 对齐项目的主要预算'"**（"KTO 的低成本价值（04 篇）：好坏标签比偏好对便宜——**'数据成本决定方法选择'"**）；**数据的生命周期**——"数据要持续迭代（模型升级/业务变化要补数据）——**'数据不是一次性的，是持续积累的资产'"**（"用户反馈（点赞/点踩）转 KTO 数据 = 数据的'自来水'——**'好团队把产品使用变成数据来源'"**）。

## 2. 偏好对数据格式

**偏好对的格式（trl DPO 的标准——JSON/JSONL）**：

```json
// preference.jsonl（每行一个样本）
{"prompt": "写一段欢迎词",
 "chosen": "欢迎光临！很高兴为您服务，有什么可以帮您？",
 "rejected": "你好，欢迎。有事说事。"}

{"prompt": "解释什么是量子计算",
 "chosen": "量子计算是利用量子力学原理进行计算的新一代计算方式……",
 "rejected": "量子计算就是很厉害的计算机，比普通电脑快很多。"}
```

```python
# 加载为 trl 用的数据集（HuggingFace datasets 格式）
from datasets import Dataset

data = [
    {"prompt": "写一段欢迎词",
     "chosen": "欢迎光临！很高兴为您服务……",
     "rejected": "你好，欢迎。有事说事。"},
    # ... 更多偏好对
]
dataset = Dataset.from_list(data)          # 三字段：prompt/chosen/rejected

# DPOTrainer 直接吃这个格式（04 篇）
# trainer = DPOTrainer(..., train_dataset=dataset)
```

**格式心智**：**"格式记忆：'三字段'——prompt（问题）+ chosen（好答案）+ rejected（坏答案）"**——"**格式是 DPO 的'接口'——字段名错了训练直接报错（KeyError）——'三字段背下来，数据就能喂'"**（"对话类数据的格式：chosen/rejected 可以是多轮对话（列表）——**'单轮用字符串、多轮用列表——具体看文档'"**）；**格式的细节**——"chosen 与 rejected 是'同一问题的两个回答'（配对——不是随便两个）——**'配对是偏好对的灵魂——不配对 = 训练无效'"**（"好答案 vs 坏答案的差距要'明显'（一眼看出好坏）——**'差距模糊的偏好对是浪费（模型学不到）'"**）；**KTO 的格式**（不需要成对）——"`{"prompt": ..., "completion": ..., "label": true/false}`（好坏标签）——**'数据形态区分方法：偏好对用 DPO、好坏标签用 KTO（04 篇）'"**。

## 3. 数据质量：怎么标好偏好

**偏好标注的质量三原则——"什么样的偏好对是好数据"**：

```text
标注质量三原则
├── ① 差距明显：chosen 明显好于 rejected（一眼能看出）
│    —— 模糊的对比（两个都还行）模型学不到判断
├── ② 维度聚焦：每次只对比"一个维度"（风格/事实/长度）
│    —— 混着对比（这次比风格下次比事实）模型学混乱
└── ③ 一致性：标注者的判断标准统一（不同人标准不同 = 噪声）
    —— "标注规范（怎么算好）写清楚 = 一致性的保障"
    ——"三条原则：明显 / 聚焦 / 一致——标注的三字诀"
```

**质量心智**：**"质量三原则的记忆：'明显、聚焦、一致'"**——"**标注示例：'回答 A 比 B 好，因为 A 更简洁且信息完整'（聚焦一个维度 + 说明理由）——'带理由的标注 = 一致的标注'"**（"标注规范文档（好答案的标准/示例）是团队的标配——**'规范 = 一致性的制度保障'"**）；**标注的姿势**——"人工标注（最准但贵）/ 用户反馈转化（点赞点踩——KTO）/ LLM 标注（用强模型生成偏好对——快但引入强模型偏好）——**'标注方式 = 成本与质量的权衡'"**（"LLM 标注是 2026 主流（强模型 + 提示词生成偏好对——省人力但继承强模型的偏好）——**'知道数据的'出身'（谁标的）很重要'"**）；**脏数据的识别**——"chosen 比 rejected 还差/两个都差/答案与问题无关——**'数据清洗（抽检 + 过滤）是对齐前的必做工序'"**（"抽检 10% 看质量（标注一致性）——**'抽检 = 数据质量的体检'"**）。

## 4. 数据规模与获取

**偏好对要多少数据——规模经验值**：

```text
数据规模经验值（2026 实践）
├── SFT：几千-几万条示例（格式学习——需求最少）
├── DPO：5000-50000 条偏好对（常用区间——太少了学不到偏好）
├── GRPO：题目量看任务（几千题起步 + 可无限生成（合成数据））
└── 规律：方法越'高级'数据需求越大（但都是'千级起步'——不是百万级）
    ——"对齐数据是'千级'量级（不是预训练的 TB 级）——普通人可负担"
```

**规模心智**：**"规模记忆：'SFT 千级、DPO 万级、GRPO 题目级'——都是消费级可做的量级"**——"**预训练要 TB 级数据（只有大厂玩得起）、对齐只要千/万条（个人/小团队做得到）——'对齐是'平民级'的训练——这是它流行的重要原因'"**（"5000 条偏好对的标注成本：人工标注约几万-几十万元（贵）——**'低成本路径：LLM 生成 + 人工抽检（质量与成本的平衡）'"**）；**数据的获取渠道**——"公开数据集（HuggingFace Hub 有现成偏好数据集——搜索 'preference' 标签——1000+ 社区模型带 dpo,trl 标签）——**'先找现成的，再自己造——公开数据是第一步'"**（"领域数据（自己的业务偏好）必须自己造——**'通用偏好用公开数据，业务偏好自己标注'"**）；**合成数据的姿势**——"用强模型生成偏好对（好回答/坏回答）+ 人工校验——**'合成 + 校验 = 2026 数据生产的标配流水线'"**（"合成数据的坑：继承强模型的偏好（不一定适合你的产品）——**'校验是合成数据的生命线'"**）。

## 6. 本节验收

**验收动作**：① 准备 50 条偏好对（自己场景——写标注理由）；② 写标注规范文档（好答案标准）；③ 抽检自己数据的质量（一致性检查）；④ 逛 HuggingFace Hub 找一个现成偏好数据集——**"格式 + 质量 + 规模 = 数据能力"**——**练习纪律**：DPO 前先抽检数据——"数据没抽检 = 训练盲盒"。

> 🎯 **核心要点**：数据 = 对齐成败的 70%（**教材论——垃圾偏好进歪模型出——数据是持续积累的资产**）；**三字段格式（prompt/chosen/rejected——配对是灵魂——差距要明显）**；**质量三原则（明显/聚焦/一致——标注规范是制度保障——LLM 标注继承强模型偏好要校验）**；**规模经验（SFT 千级/DPO 万级/GRPO 题目级——对齐是平民级训练——先找公开数据再自己造——合成+校验是标配流水线）**——"先花时间在数据上，再谈方法"。
