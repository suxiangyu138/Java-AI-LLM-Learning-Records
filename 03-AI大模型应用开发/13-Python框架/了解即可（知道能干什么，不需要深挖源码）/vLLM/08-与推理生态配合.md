## 1. 推理生态全景

**2026 年 LLM 推理引擎四大家族——vLLM 是生产一极**：

```text
推理引擎四大家族（2026）
├── vLLM：生产 GPU 服务（吞吐之王——本体系主角）
├── TGI：HuggingFace 出品——2025-12 进入维护模式（存量）
├── llama.cpp：本地/边缘之王（CPU/苹果/GGUF——MIT）
└── Ollama：上手之王（llama.cpp 封装——一条命令跑模型）
    ——"四家的定位：生产/存量/边缘/上手——vLLM 是生产默认"
```

**全景心智**：**"全景的记忆：'生产 vLLM、边缘 llama.cpp、上手 Ollama、存量 TGI'"**——"**为什么四家共存：'硬件 × 场景'的矩阵——生产 GPU（vLLM）、无 GPU/边缘（llama.cpp）、快速体验（Ollama）、HF 生态存量（TGI）——'没有万能引擎，只有匹配场景'"**（"另有两家：SGLang（RAG 前缀优化——RadixAttention）与 TensorRT-LLM（NVIDIA 极限吞吐——部署复杂）——**'知道存在即可（本课提一句，细节是推理部署体系的事）'"**）；**全景的心智意义**——"选型的起点：先定场景（生产/本地/边缘）再选引擎——**'场景决定引擎，不是引擎决定场景（与量化选型同款逻辑）'"**。

## 2. 四大引擎对比

**四大引擎对比表（选型的核心依据）**：

| 维度 | vLLM | Ollama | llama.cpp | TGI |
|------|------|--------|-----------|-----|
| 定位 | 生产 GPU 服务 | 本地上手 | 本地/边缘 | HF 生态（存量） |
| 吞吐 | 最高（5100 tok/s batch=256） | 低（50 并发 155 tok/s） | 中（单用户） | 中（68-74% GPU 利用率） |
| 连续批处理 | ✅（核心） | ❌ | ❌（基础实现） | ✅（较弱） |
| 多 GPU | ✅（TP） | ❌ | 有限 | ✅ |
| 硬件 | GPU（NVIDIA 为主） | GPU/CPU | 全平台（CPU/苹果/边缘） | GPU |
| 量化 | AWQ/GPTQ/FP8 | GGUF | GGUF（Q4_K_M 甜点） | AWQ/GPTQ |
| 上手难度 | 中（命令启动） | 最低（一条命令） | 中 | 中 |
| 2026 状态 | 活跃（每月大版本） | 活跃 | 活跃 | **维护模式** |

**对比心智**：**"对比的三个记忆点：'vLLM 吞吐碾压、Ollama 上手最快、llama.cpp 平台最广'"**——"**吞吐的差距（2026 实测）：vLLM batch=256 约 5100 tok/s vs Ollama 50 并发 155 tok/s——'连续批处理的有无 = 30 倍的差距（03 篇）'"**（"Ollama 的上手价值：`ollama run llama3` 一条命令（下载+量化+运行）——**'本地体验/原型用 Ollama——生产别用（无连续批处理——08 篇结论）'"**）；**llama.cpp 的独门**——"全平台（CPU/苹果/树莓派）+ GGUF 格式（本地分发事实标准——Q4_K_M 甜点）——**'无 GPU/边缘场景的唯一选择（bitsandbytes 09 篇的 GGUF 结论一致）'"**（"TGI 的定位：HF 生态深度集成（监控/追踪成熟）——**'存量系统继续用、新项目迁移 vLLM/SGLang（本课 4 节）'"**）。

## 3. 选型决策矩阵

**选型决策矩阵（2026 版本——写进笔记的最终答案）**：

```text
选型决策矩阵
├── 生产 GPU 服务（默认） → vLLM（吞吐/支持/社区三最）
├── 本地开发/快速原型 → Ollama（一条命令）
├── CPU/苹果/边缘/离线 → llama.cpp（GGUF——全平台）
├── 结构化工出/RAG 共享前缀 → SGLang（RadixAttention——前缀优势）
├── 追求单模型极限吞吐（NVIDIA） → TensorRT-LLM（部署复杂度极高）
└── 存量 TGI 用户 → 迁移 vLLM 或 SGLang（API 直接替换）
    ——"决策的捷径：'生产 vLLM、其他按场景'——80% 的场景 vLLM 或 Ollama"
```

**矩阵心智**：**"矩阵的记忆：'高频出口两个——生产 vLLM、本地 Ollama'"**——"**大多数人的答案是前两个：生产用 vLLM（吞吐）、本地体验用 Ollama（方便）——'记得住高频出口，低频出口用时再查（与 bitsandbytes 09 篇同款）'"**（"低频出口的记忆：无 GPU 找 llama.cpp、RAG 看 SGLang、极限吞吐 TensorRT-LLM——**'五个出口 = 选型地图'"**）；**矩阵的验证**——"选完实测（吞吐/延迟/稳定性——07 篇压测）——**'决策矩阵给方向，实测给答案（与量化选型同款）'"**（"矩阵的演进：引擎状态会变（TGI 维护模式就是例子）——**'选型要'看状态'（活跃度——和量化生态风险同款）'"**）。

## 4. TGI 的 2026 状态

**TGI（Text Generation Inference）进入维护模式——2026 年的重要事件**：

```text
TGI 维护模式（2025-12-11 官方宣布）
├── 状态：只接受小 bug 修复/文档更新——不再开发新功能
├── 原因：性能落后（GPU 利用率 68-74% vs vLLM 85-92%）+ vLLM 生态壮大
├── 影响：存量部署可继续（稳定）——新项目别选
└── 迁移：vLLM/SGLang 是 API 直接替换（OpenAI 兼容端点一样）
    ——"TGI 的 2026 状态：'老兵不死，只是渐隐'——存量用着，新项目走人"
```

**TGI 心智**：**"TGI 的记忆：'维护模式——2025-12 官方宣布——新项目别选'"**——"**为什么维护：推理引擎的竞争太激烈（vLLM 每月大版本、TGI 跟不上）——'生态的残酷：不活跃 = 被遗忘（与量化生态 AutoGPTQ 停维护同款教训——bitsandbytes 09 篇）'"**（"存量的应对：现有 TGI 部署继续用（稳定）——新需求/新项目迁移 vLLM——**'迁移成本低（OpenAI 兼容 API 直接替换）'"**）；**生态的启示**——"选引擎 = 选生态寿命（活跃度/社区/迭代）——**'vLLM 活跃（每月大版本）= 安全选择（01 篇的地位）'"**（"了解即可：知道'TGI 维护模式'这个 2026 事实——**'选型时排除它（除非存量）'"**）。

**生态的协同使用**（引擎不是单选）："**混合姿势：本地开发用 Ollama（体验模型）→ 生产用 vLLM（同一模型上线）——'开发体验与生产部署用不同引擎（同模型）'"**（"GGUF 生态的衔接：llama.cpp 的 GGUF 模型 vLLM 也能加载（04 篇——格式兼容）——**'模型格式的互通 = 引擎之间'搬运工'"**（"了解即可：知道'引擎可混合 + 格式可互通'——**'选型不是选一个，是配一套'"**）；**生态的学习顺序**——"先 Ollama（体验模型——最快上手）→ 再 vLLM（生产部署——本体系）→ 需要时补 llama.cpp（边缘/CPU）——**'从体验到生产的学习路径——引擎按需学'"**（"生态的面试价值：'生产用 vLLM 为什么'（吞吐/支持/社区）是 2026 年 AI 部署高频题——**'本体系的 08 篇 = 面试的选型答案'"**）。
