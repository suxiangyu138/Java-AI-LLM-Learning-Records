## 1. 排障方法论

**推理引擎排障的第一原则：'日志先行 + 三类排查'**：

```text
排障三分类（按顺序）
├── ① 启动类：起不来（显存不够/格式不对/模型路径错）
├── ② 运行类：跑起来但不对（OOM/慢/生成异常）
└── ③ 版本类：兼容问题（V0 标志移除/版本太老）
    ——"排障顺序：先看启动日志（报什么错）→ 再查配置（显存/格式）→ 后查版本"
```

**方法论心智**：**"排障的第一动作：看启动日志（vllm serve 的完整日志）"**——"**vLLM 的报错信息明确（显存不足/格式不支持/模型加载失败）——'报错第一行 + 最后一行（原因往往在末尾）——与 uvicorn/trl 同款方法论'"**（"日志级别：启动用默认（info）——排障开 debug（更详细）——**'日志是排障的第一现场（uvicorn 08 篇同款）'"**）；**排障的第二动作：最小复现**——"缩小到最小配置（小模型/短上下文）复现——**'问题范围越小越好查（与各体系同款黄金工具）'"**（"最小复现 = 排障的黄金工具——**'能最小复现 = 一半已定位'"**）。

## 2. 启动类问题

**启动三坑——"起不来"的常见原因**：

```text
启动三坑
├── ① CUDA out of memory（显存不足——最常见）：
│    —— 模型太大/上下文太长/gpu-memory 太高
│    —— 解法：量化（04 篇）/减 max-model-len（02 篇）/减 gpu-memory
├── ② 模型格式不支持/加载失败：
│    —— 量化格式不匹配（模型是 AWQ 但没指定 --quantization）
│    —— 模型路径错/HF ID 不存在
└── ③ 版本不兼容：
    —— vLLM 版本太老（模型新架构不支持——升级）
    —— Python/CUDA 版本不匹配（安装失败）
    ——"启动三坑的解法：显存看配置、格式看指定、版本看升级"
```

**启动心智**：**"启动坑的记忆：'显存/格式/版本——三个第一检查'"**——"**显存不足（OOM）的调节顺序：量化（最大头）→ 减 max-model-len → 减 gpu-memory-utilization → 换小模型——'显存调节的旋钮顺序 = 损失最小优先（与 bitsandbytes 08 篇同款）'"**（"格式的坑：量化模型启动要指定 --quantization（04 篇）——**'模型是 AWQ 的但没指定 = 加载失败/静默用错'"**）；**版本问题的识别**——"报错带 'not supported'/'requires' → 版本问题——**'升级 vLLM（01 篇版本演进——0.25.0 最新）'"**（"环境的隔离（venv/Docker——06 篇）——**'版本冲突多在全局环境——隔离是第一防线'"**）。

## 3. 运行类问题

**运行三坑——"跑起来了但不对"**：

```text
运行三坑
├── ① 运行时 OOM（显存尖峰）：
│    —— 并发上来 KV 缓存暴涨（03 篇）——限流/减长度/加显存
├── ② 生成异常（乱码/重复/截断）：
│    —— max-model-len 太短（输出被截）——加长
│    —— 采样参数（temperature 等）不合适
├── ③ 速度慢（延迟高）：
│    —— 没量化（原版 BF16——Marlin 内核没用上——07 篇）
│    —— 前缀没缓存（RAG 场景——03 篇）
└── 共同规律：运行问题 = 配置与场景的匹配问题
    ——"运行慢先查量化，生成怪先查长度与参数"
```

**运行心智**：**"运行坑的核心：'配置与场景的匹配'——vLLM 本身稳定，问题多在配置"**——"**运行时 OOM 的根源：KV 缓存随并发涨（03 篇）——'并发压测找上限（07 篇——安全并发 = 拐点 × 0.8）——限流防 OOM'"**（"生成异常的排查：输出截断查 max-model-len、重复查采样参数（temperature/repetition_penalty）——**'生成的怪 = 参数的问题（了解即可：知道两个参数）'"**）；**速度慢的排查顺序**——"① 量化了吗（没量化 = Marlin 没上——07 篇最大头）；② 场景配置对吗（RAG 用前缀缓存）；③ 压测数字（和参考对比——07 篇）——**'慢先查量化（90% 的情况）'"**。

## 4. 版本与迁移问题

**版本与迁移三坑——"升级/换版本"的坑**：

```text
版本与迁移三坑
├── ① v0.25.0 硬性移除：legacy PagedAttention 代码删除（V0 标志报错）
│    —— 升级前审查 V0 相关参数（--enforce-eager 等标志）
├── ② 大版本行为变化：MRv2 默认（模型行为/性能可能变）
│    —— 升级后压测对比（07 篇——行为回归验证）
└── ③ 硬件/语言版本绑定：Blackwell 要新版本、Python 3.14 要 v0.21.0+
    ——"迁移的姿势：看 release notes + 升级后压测对比"
```

**迁移心智**：**"迁移坑的核心：'vLLM 演进快——升级是'半迁移'"**——"**v0.25.0 的硬性移除：legacy PagedAttention 没了（概念并入 MRv2——03 篇）——V0 回退标志直接报错——'升级前审查自己的启动参数（release notes 的 breaking changes 清单）'"**（"升级的验证：升级后压测对比（吞吐/延迟/生成质量）——**'升级 = 功能升级 + 行为验证（07 篇压测是验证工具）'"**）；**版本绑定的注意**——"新硬件（Blackwell）要新版本（v0.7.3+——01 篇）、新 Python 要新版本（v0.21.0+）——**'硬件/语言升级前查 vLLM 支持（01 篇版本基线）'"**（"锁版本的意义：`pip install vllm==0.25.0`——**'生产锁版本 + 季度性评估升级（与各体系同款）'"**）。

## 5. 报错速查表

**报错速查表（十大高频——本体系的"排障字典"）**：

| 报错/现象 | 原因 | 解法 |
|---------|------|------|
| `CUDA out of memory` | 显存不足 | 量化 → 减长度 → 减 gpu-memory |
| 模型加载失败 | 格式不匹配 | 指定 --quantization（AWQ 模型） |
| `model not found`（404） | 模型名错 | 用 /v1/models 查实际名（05 篇） |
| V0 标志报错 | v0.25.0 移除 legacy | 删 V0 参数（迁移——本课 4 节） |
| 输出截断 | max-model-len 太短 | 加长（显存允许时） |
| 输出重复/乱码 | 采样参数不合适 | 调 temperature/repetition_penalty |
| 速度慢 | 没量化 | 用量化模型（AWQ——Marlin 内核） |
| 安装失败 | CUDA/Python 版本不匹配 | 对齐版本（01 篇基线） |
| 并发高 OOM | KV 缓存暴涨 | 限流（压测安全线——07 篇） |
| 启动超慢 | 正常（模型加载） | 等日志 'startup complete'（02 篇） |

**速查心智**：**"速查表的读法：'先对现象 → 找原因 → 按解法改'——十条覆盖 90% 的 vLLM 问题"**——"**十条的规律：显存三条（OOM/并发/长度）、格式两条（加载/量化）、版本两条（V0/安装）、生成两条（截断/乱码）、模型一条——'报错先归类：显存/格式/版本/生成——四类记忆'"**（"新坑必记（个人版速查表）——**'速查表 = 排障经验的沉淀库'"**）；**查不到的姿势**——"查官方 GitHub Issues（vllm-project/vllm——活跃）+ 文档（docs.vllm.ai）——**'先搜再问——报错信息 + vllm 是搜索姿势（与各体系同款）'"**。
