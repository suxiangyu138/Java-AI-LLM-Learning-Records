## 1. 安装

**安装命令——环境要求先看**：

```bash
# 环境要求（2026）
# GPU：NVIDIA（CUDA）为主——8GB 显存起步（小模型）
# Python：3.10+（0.21.0 起支持 3.14）
# CUDA：与 GPU 匹配（Blackwell 要新版本——01 篇）

# 安装（锁版本——推理引擎版本纪律）
pip install vllm==0.25.0
# 或 uv（更快）
# uv pip install vllm==0.25.0

# Windows 原生支持（v0.21.0+——CUDA 13.0）——但 Linux 仍是主场
```

**安装心智**：**"安装的记忆：'GPU 前置 + 锁版本'——vLLM 是 GPU 引擎"**——"**先确认三件事：有 NVIDIA GPU 吗（没有 → 本地用 Ollama/llama.cpp——08 篇）、显存够吗（8GB 起步——小模型）、CUDA 版本对吗（新卡要新版本）——'环境三查是安装的前提'"**（"vLLM 需要 GPU——**'CPU 场景不是 vLLM 的主场（llama.cpp 才是——08 篇）'"**）；**安装的验证**——"`python -c "import vllm; print(vllm.__version__)"`——**'装没装对，版本命令说话（与 uvicorn 同款姿势）'"**（"安装失败的常见原因：CUDA 版本不匹配/Python 版本太老——**'报错里写着版本要求（09 篇速查）'"**）。

## 2. vllm serve 启动

**vllm serve = 一条命令把模型变成 API 服务（2026 年的标准姿势）**：

```bash
# 启动一个 OpenAI 兼容服务（模型自动下载——HF Hub）
vllm serve Qwen/Qwen2.5-7B-Instruct
# 启动后：http://localhost:8000 就是 OpenAI 兼容 API 端点
# 自动加载 /v1/chat/completions、/v1/completions、/health 等端点

# 常用启动参数
vllm serve Qwen/Qwen2.5-7B-Instruct \
  --port 8000 \                  # 端口（默认 8000）
  --max-model-len 8192 \         # 最大上下文长度（显存换长度）
  --gpu-memory-utilization 0.9 \ # GPU 显存利用率（默认 0.9）
  --quantization awq \           # 量化格式（04/07 篇——生产加速）
  --dtype auto                  # 精度（auto/bfloat16）
```

**启动心智**：**"启动的记忆：'vllm serve 模型名——一条命令出 API'"**——"**vllm serve 的价值：零代码启动（不用写 FastAPI/加载脚本——内置一切）——'模型 → API 的距离 = 一条命令'"**（"底层原理（了解即可）：vllm serve 内部完成模型加载 + 引擎初始化 + API 服务器——**'vllm serve = 加载 + 引擎 + API 三合一'"**）；**模型的来源**——"模型名 = HF Hub 的模型 ID（自动下载）或本地路径——**'本地路径（/models/xxx）适合离线/已下载模型'"**（"下载的模型放哪：HF 缓存目录（HuggingFace 体系讲）或指定路径——**'模型管理是服务的一部分（04 篇）'"**）；**首次启动的等待**——"启动要时间（模型加载 + 引擎初始化——几十秒到几分钟）——**'启动慢是正常的（01 篇 vLLM 的局限——不是 bug）'"**（"看日志确认加载完成（'Application startup complete'）——**'启动完成有日志标志（09 篇）'"**）。

## 3. 测试服务

**测试 = 用 OpenAI SDK 或 curl 调用（验证服务可用）**：

```python
# 测试方式一：OpenAI SDK（标准姿势——05 篇详讲）
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8000/v1",   # vLLM 的端点（换 base_url 即可）
    api_key="sk-no-key-needed",            # vLLM 不需要真实 key（占位）
)

resp = client.chat.completions.create(
    model="Qwen/Qwen2.5-7B-Instruct",       # 模型名（启动时那个）
    messages=[{"role": "user", "content": "你好"}],
)
print(resp.choices[0].message.content)
```

```bash
# 测试方式二：curl（快速验证）
curl http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model": "Qwen/Qwen2.5-7B-Instruct",
       "messages": [{"role": "user", "content": "你好"}]}'
```

**测试心智**：**"测试的记忆：'OpenAI SDK 换 base_url 一行——模型能答 = 服务可用'"**——"**为什么 OpenAI SDK：vLLM 完全兼容 OpenAI API（05 篇详讲）——你的 OpenAI 代码只改 base_url 就能接 vLLM——'接入成本 = 一行配置'"**（"api_key 用占位符（vLLM 不校验 key——本地服务）——**'别纠结 key——占位就行'"**）；**验证三件套**——"① 服务起来（日志 startup complete）；② API 能答（curl/SDK）；③ 并发能扛（压测——07 篇）——**'三个验证 = 服务可用的三件套证明'"**（"`/health` 端点（服务健康检查——vLLM 内置）——**'监控/负载均衡用它（06 篇）'"**）。

## 4. 常用启动参数

**常用参数速查（启动命令的"单词本"）**：

```bash
# 常用参数（按使用频率）
vllm serve <model> \
  --port 8000 \                    # 端口（默认 8000）
  --max-model-len 8192 \           # 最大上下文（显存 ↔ 长度权衡）
  --gpu-memory-utilization 0.9 \   # GPU 显存利用率（0.9 = 90%）
  --quantization awq \             # 量化格式（awq/gptq/fp8——04/07 篇）
  --tensor-parallel-size 2 \       # 张量并行（多卡——04/06 篇）
  --dtype bfloat16 \               # 精度（bfloat16 常用）
  --host 0.0.0.0                   # 监听地址（外部访问——与 uvicorn 同款）
```

**参数心智**：**"参数的记忆：'port/max-model-len/gpu-memory/quantization 四大件'"**——"**max-model-len 的权衡：越长越吃显存（KV 缓存）——'显存不够先减长度（比换模型便宜）'"**（"gpu-memory-utilization：默认 0.9（留 10% 给系统）——**'调高有 OOM 风险、调低浪费显存——0.9 是甜点'"**）；**参数查看**——"`vllm serve --help` 看全部——**'记四大件，其余查 --help（与 uvicorn 同款姿势）'"**（"参数随版本演进（v0.25.0 删 V0 标志——09 篇迁移）——**'新版本看 release notes'"**）；**参数的工程化**——"复杂配置用 YAML/代码启动（vllm serve --config 或 LLM 类 API）——**'命令行是快速姿势，配置化是工程姿势（与 uvicorn 同款）'"**。

**代码启动的姿势**（不只有命令行）："**vLLM 提供 Python API（LLM 类）**——在 Python 代码里直接推理（不启动服务——测试/嵌入场景）：

```python
from vllm import LLM, SamplingParams

llm = LLM(model="Qwen/Qwen2.5-7B-Instruct-AWQ", quantization="awq")  # 加载模型
outputs = llm.generate(["你好", "介绍你自己"], SamplingParams(temperature=0.7, max_tokens=256))
for out in outputs:
    print(out.outputs[0].text)
```
——**'两种姿势：服务（vllm serve——对外 API）与嵌入（LLM 类——代码内推理）——姿势跟着场景走'"**（"了解即可：知道'还有代码姿势'——详细 API 是 vLLM 文档的事（docs.vllm.ai）——**'先会 serve（90% 场景），再会 LLM 类（测试/嵌入）'"**）。

**快速开始的常见疑问**（三个高频问题）："**① 第一次启动要下载模型吗**——模型名是 HF ID 就会自动下载（网络要通——离线用本地路径）；**② 启动后卡住不动**——首次加载要时间（模型加载 + 引擎初始化——几十秒到几分钟——等日志 'startup complete'）；**③ 8000 端口被占**——--port 换端口（与 uvicorn 同款）——**'三个疑问 = 新手的第一批问题——答案都在本课'"**（"卡住先看日志（09 篇——报错信息明确）——**'启动的排障 = 日志第一'"**）。

**快速开始的环境准备**（动手前先备齐）："**① GPU**——NVIDIA 8GB 显存起步（量化小模型——1.5B/7B）；**② 环境**——venv/Docker 隔离（vLLM 依赖多——别装全局）+ 锁版本（vllm==0.25.0）；**③ 模型**——从量化小模型起步（AWQ 版 1.5B/7B——下载快、显存低）——**'环境三件套（GPU/venv/小模型）备齐，第一天就顺'"**（"没 GPU 的替代：本地上手用 Ollama（08 篇——vLLM 的舞台是 GPU）——**'环境决定引擎（08 篇选型）'"**）。

**快速开始的排障预备**（第一天可能遇到的三个问题）："**① 安装报错**——CUDA/Python 版本不匹配（看报错里的版本要求——01 篇基线）；**② 启动报错**——显存不足（减 max-model-len——09 篇速查第一坑）；**③ 调用报错**——模型名不匹配（/v1/models 查实际名——05 篇）——**'三个预备 = 第一天不慌——速查表在手'"**（"排障的通用姿势：报错 → 速查表（09 篇）→ Issues——**'先查再问（与各体系同款）'"**）；**动手前的最后确认**——"显卡驱动/CUDA 就绪（nvidia-smi 正常）+ venv 激活——**'环境确认 30 秒，避免半小时的安装报错'"**。
