## 1. 部署形态全景

**vLLM 的部署形态——从单机到生产架构**：

```text
部署形态四层
├── ① 单机单卡：小模型（7B）——开发/小团队（最简单）
├── ② 单机多卡：大模型（70B——TP 张量并行——04 篇）
├── ③ Docker 容器：标准化部署（镜像 + 环境一致）
└── ④ 生产架构：vLLM + 负载均衡 + 监控（多实例/多服务）
    ——"部署形态跟着规模走：小团队单机、大团队架构"
```

**部署心智**：**"部署的记忆：'单机 → 多卡 → Docker → 架构——形态跟着规模走'"**——"**部署的核心目标：'服务稳定 + 可运维'——和 uvicorn 的生产部署同构（05 篇 uvicorn 的 LLM 版）——'部署的通用逻辑：进程管理 + 健康检查 + 监控'"**（"vLLM 与 uvicorn 的配合：vLLM 本身就是服务器（自带 API）——**'不需要 uvicorn 包一层（vLLM 内置）——vLLM 是'模型服务'的完整件'"**）；**部署的输入输出**——"输入：模型 + 配置；输出：OpenAI 兼容服务（端口 8000）——**'部署 = 把模型变成常驻服务'"**（"部署的产物：服务地址（http://ip:8000——接入方用）——**'部署完交付'服务地址 + 配置文档'"**）。

## 2. 单机部署

**单机单卡 = 小模型的标准姿势（开发/小团队）**：

```bash
# 单机部署（示例——7B 量化模型）
vllm serve Qwen/Qwen2.5-7B-Instruct-AWQ \
  --port 8000 --quantization awq \
  --max-model-len 8192 --gpu-memory-utilization 0.9 \
  --host 0.0.0.0

# 进程管理（挂了自动重启——systemd/Docker——uvicorn 05 篇同款逻辑）
# systemd: Restart=always
# 或直接 Docker（下节）
```

**单机心智**：**"单机的记忆：'一条命令 + 进程管理——小模型够了'"**——"**单机的适用：7B 级（8-24GB 显卡——量化后）——开发/小团队/演示——'先单机跑通，规模大了再升级'"**（"单机的要点：进程管理（systemd/Docker——挂了重启）+ 健康检查（/health——监控）——**'单机也要'生产姿势'（和 uvicorn 05 篇同款）'"**）；**单机的性能**——"7B 量化单卡吞吐：够中小团队用（几百并发内）——**'单机的上限：显卡决定（显存账本——bitsandbytes 02 篇）'"**（"单机不够的信号：延迟涨/并发饱和 → 升级多卡或加实例——**'先单机后扩展（06 篇部署形态的递进）'"**）。

## 3. 多卡部署

**多卡部署 = 大模型的姿势（TP 张量并行——04 篇配置）**：

```bash
# 多卡部署（示例——70B 量化 + 4 卡）
vllm serve Qwen/Qwen2.5-70B-Instruct-AWQ \
  --quantization awq \
  --tensor-parallel-size 4 \      # 4 卡切分（04 篇）
  --gpu-memory-utilization 0.9 \
  --host 0.0.0.0

# 检查：nvidia-smi 看每卡显存（模型被切分——每卡一部分）
```

**多卡心智**：**"多卡的记忆：'TP 切模型——大模型装得下'"**——"**多卡的适用：模型显存 > 单卡（70B 量化 35GB+——单卡 48GB 勉强、多卡舒服）——'先算账（模型大小 vs 卡数）再定 TP（04 篇）'"**（"多卡的环境：服务器级（NVLink 高速互联——04 篇）——**'消费级多卡（PCIe）通信慢——TP 收益打折'"**）；**多卡的注意**——"TP 卡数要模型支持（有些模型限制）——**'先看模型文档的 TP 支持'"**（"多卡 + 量化 + 长上下文 = 生产大模型的三件套——**'70B 生产 = 量化（显存）+ TP（装下）+ max-model-len（上下文）'"**）。

## 4. Docker 部署

**Docker 部署 = 标准化（镜像 + 环境一致——部署的通用姿势）**：

```dockerfile
# Dockerfile（vLLM 服务镜像——示例）
FROM vllm/vllm-openai:latest      # 官方镜像（含 vLLM + OpenAI 服务）

# 启动命令（容器内）
# CMD ["vllm", "serve", "Qwen/Qwen2.5-7B-Instruct", "--host", "0.0.0.0"]
```

```bash
# 运行容器（GPU 透传）
docker run --gpus all \
  -p 8000:8000 \
  -v /models:/models \            # 模型挂载（本地模型）
  vllm/vllm-openai:latest \
  vllm serve Qwen/Qwen2.5-7B-Instruct --host 0.0.0.0

# 容器化组合（Docker Compose——多服务编排）
# vLLM 服务 + Nginx（入口）+ 监控——compose 一键起
```

**Docker 心智**：**"Docker 的记忆：'官方镜像 + --gpus all——环境一致'"**——"**Docker 的价值：环境一致（CUDA/依赖打包——换机器一样跑）——'Docker = 部署的'标准化集装箱'（02 后端 Docker 体系）'"**（"官方镜像 `vllm/vllm-openai`——开箱即用（含 vLLM + OpenAI 服务）——**'先官方镜像，再自己定制'"**）；**Docker 的要点**——"GPU 透传（--gpus all）+ 模型挂载（-v /models）+ 端口映射（-p 8000:8000）——**'三件套 = vLLM 容器化'"**（"Compose 编排（vLLM + Nginx + 监控——多服务）——**'容器化的进阶 = 编排（02 后端 Docker Compose 体系）'"**）。

## 5. 生产架构与检查清单

**生产架构 = vLLM 服务 + 入口 + 监控（多用户场景）**：

```text
生产架构（多用户/公网场景）
└── 用户 → Nginx（入口——负载均衡/HTTPS）→ vLLM 实例（一台或多台）
                                    ↓
                              /health 健康检查 → 负载均衡摘除（挂了的剔除）
                              Prometheus 指标 → 监控/告警（07 篇）
    ——"架构的骨架：入口（Nginx）+ 服务（vLLM）+ 监控（健康/指标）"
```

**生产检查清单（部署前过一遍）**：

```markdown
- [ ] 模型与量化（AWQ/FP8——生产标配）——04 篇
- [ ] 显存规划（max-model-len/gpu-memory——02 篇）
- [ ] 并行配置（单卡/TP——04 篇）
- [ ] 进程管理（systemd/Docker——挂了重启）
- [ ] 健康检查（/health——监控/摘除）
- [ ] 入口（Nginx/负载均衡——多用户）
- [ ] 监控（指标/日志——07/08 篇）
- [ ] 压测验证（吞吐/延迟——07 篇）
```

**架构心智**：**"架构的记忆：'入口 + 服务 + 监控——三段式'"**——"**架构的复用：和 uvicorn 生产架构同构（05 篇 uvicorn）——Nginx 入口/健康检查/进程管理/监控——'LLM 服务的部署 = Web 服务的部署 + 模型特定配置'"**（"vLLM 的监控：Prometheus 指标（vLLM 内置——/metrics）+ 日志——**'和 uvicorn 08 篇同款监控逻辑'"**）；**清单的价值**——"上线不靠感觉靠检查（uvicorn 05 篇同款）——**'每项有对应篇目——清单 = 部署的专业仪式'"**（"能上也要能退：模型/配置的版本管理——**'部署的完整性 = 回滚路径'"**）；**部署的文档三件套**——"架构图（入口 → vLLM → 模型）、配置清单（模型/量化/并行/显存）、运维手册（启动/健康/监控/回滚）——**'部署的交付 = 服务 + 文档（与 uvicorn 10 篇同款——文档是交接资产）'"**（"文档的维护：配置变了文档跟着改——**'文档过期 = 误导后人——部署文档要活'"**）；**部署的验收三问**——"**能访问吗**（API 通——05 篇）、**能扛吗**（压测数字——07 篇）、**能起吗**（kill 后自动重启——进程管理）——**'三问验收 = 部署完成的证明（与 uvicorn 10 篇同款）'"**（"验收的落地：写进部署文档（怎么验证——团队交接标准）——**'验收三问写进文档 = 交接无歧义'"**）。
