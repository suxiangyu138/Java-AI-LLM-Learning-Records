## 3. 与主体系的分工

**与模型推理与部署体系（`../../模型推理与部署/`）的分工**：那个体系是"推理部署全景"（KV Cache/投机采样/量化/压测/成本），本体系是 **vLLM 单库的"了解即可"**——**"推理部署体系是全景地图，本体系是'vLLM 这一引擎'的说明书"**——深度定位：**知道能干什么、怎么用、何时用——不深挖源码**（目录名即定位）。

**与了解即可三件套（`../bitsandbytes/`、`../trl/`、`../uvicorn/`）的分工**：bitsandbytes（量化——省显存底座）、trl（对齐——训练方法）、uvicorn（Web 运行——API 服务器）、**本体系 vLLM（LLM 推理——模型服务的引擎）**——四件套合起来 = **"AI 应用的'训练到部署'底座"**——"uvicorn 跑普通 Web、vLLM 跑 LLM 推理——同是'跑起来'，对象不同"。

**2026-08 基线**：vLLM **v0.25.0**（2026 年重大里程碑——删除 legacy PagedAttention、MRv2 默认）；v0.7.3（2026-04——Blackwell B200 支持）；v0.21.0（2026-05——Python 3.14 + Windows 原生）——**"推理引擎版本演进快——锁版本 + 升级看 release notes"**。

**与了解即可四件套的关系**（本体系在 13-Python框架 的位置）："**四件套 = AI 应用的'训练到部署'底座**——bitsandbytes（量化——省显存）、trl（对齐——训练方法）、uvicorn（Web 运行——API 服务器）、vLLM（LLM 推理——模型服务引擎）——**'训练（trl）+ 省显存（bnb）+ 跑服务（uvicorn/vLLM）= AI 应用全链路'"**（"uvicorn 与 vLLM 的分工：uvicorn 跑普通 Web API、vLLM 跑 LLM 推理 API——**'vLLM 自带 API 服务（不需要 uvicorn 包一层——06 篇）'"**）。

## 6. 常见误区

**误区一：Ollama 能跑就是生产**——"本地 Ollama 够用"——**正确：Ollama 不适合生产（无连续批处理——50 并发掉到 155 tok/s）——生产用 vLLM**（08 篇——"Ollama 是上手工具，vLLM 是生产引擎"）。

**误区二：vLLM 与 HF Transformers 一样**——"都是加载模型跑"——**正确：vLLM 是吞吐优化的推理引擎（PagedAttention + 连续批处理——24× 吞吐）——不是通用训练库**（03 篇）。

**误区三：模型文件随便格式**——"HF 原版直接上"——**正确：生产用量化格式（AWQ/FP8——Marlin 内核加速）**（04/07 篇——"格式决定吞吐"）。

**误区四：API 不兼容 OpenAI**——"接 vLLM 要改代码"——**正确：vLLM 完全 OpenAI 兼容（SDK 只改 base_url 一行）**（05 篇）。

**误区五：单卡小模型才用 vLLM**——"vLLM 是大厂的东西"——**正确：vLLM 单卡/多卡都行（70B 多卡、7B 单卡——消费卡也能跑）**（04/06 篇）。

**误区六：vLLM 只能部署大模型**——"小模型用不上 vLLM"——**正确：小模型（1.5B/7B）用 vLLM 同样有连续批处理收益（多用户服务场景）**（03 篇——"吞吐优化对任何规模的模型服务都有用"）。

**误区七：量化格式随便用**——"哪个量化都行"——**正确：生产用 AWQ/FP8（Marlin 内核加速）；GGUF 是本地生态的格式**（04/07 篇——"格式决定吞吐"）。
