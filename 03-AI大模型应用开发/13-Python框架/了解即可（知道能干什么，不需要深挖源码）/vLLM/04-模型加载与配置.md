## 1. 模型来源与格式

**vLLM 加载模型的来源与格式——三选一**：

```text
模型来源（三选一）
├── ① HF Hub 模型 ID：vllm serve Qwen/Qwen2.5-7B（自动下载——02 篇）
├── ② 本地路径：vllm serve /models/qwen-7b（已下载/离线）
└── ③ 量化文件：本地 GGUF/AWQ 文件（08 篇生态）
    ——"来源三选一：在线用 ID、离线用路径、量化用文件"

格式三选一（决定吞吐）
├── 原版（BF16/FP16）：精度最好、显存最大——小模型/精度敏感
├── 量化（AWQ/GPTQ/FP8）：显存省、吞吐高（Marlin 内核）——生产主流
└── GGUF：llama.cpp 生态格式（vLLM 也支持）——兼容场景
    ——"格式选型：生产用量化（AWQ/FP8），特殊场景用原版/GGUF"
```

**模型心智**：**"模型的记忆：'来源三选一 + 格式三选一'"**——"**来源的选择：在线开发用 ID（方便）、生产/离线用路径（可控）——'来源 = 方便 vs 可控的权衡'"**（"模型的管理：下载到本地统一目录（/models）——**'模型是服务的资产（要管理：版本/来源）'"**）；**格式的选择**——"原版（BF16）：精度优先（小模型显存够）；量化（AWQ/FP8）：生产主流（省显存 + 吞吐高——07 篇 Marlin 内核）；GGUF：兼容生态（llama.cpp 的模型 vLLM 也能吃）——**'格式选型 = 精度 × 显存 × 吞吐的权衡（与 bitsandbytes 09 篇同款逻辑）'"**（"了解的锚点：**'生产用 AWQ/FP8 量化'——这是 2026 年的生产常识（08 篇量化建议）'"**）。

## 2. 量化格式：生产的关键

**量化格式（AWQ/GPTQ/FP8）——生产 vLLM 的标配**：

```python
# 启动时指定量化（02 篇参数）
# vllm serve Qwen/Qwen2.5-7B --quantization awq

# 量化模型的两种来源
# ① Hub 上已量化的模型（模型名带 awq 后缀——直接加载）
# vllm serve TheBloke/Qwen2.5-7B-Instruct-AWQ
# ② 自己量化（AutoAWQ 工具——先量化再部署）
```

```text
量化格式对比（vLLM 场景——2026）
├── AWQ：激活感知量化——精度好 + Marlin 内核加速——生产主流（甜点）
├── GPTQ：经典量化——Marlin 内核也支持——精度略逊 AWQ（08 篇实测）
├── FP8：8bit 浮点——新卡（H100/Blackwell）原生支持——新趋势
└── 共同点：显存省 3/4（4bit）+ 吞吐提升（内核加速——07 篇 +61%）
    ——"量化的记忆：生产用 AWQ（甜点）或 FP8（新卡）——格式决定吞吐"
```

**量化心智**：**"量化的记忆：'生产 = 量化——AWQ 是甜点、FP8 是新趋势'"**——"**为什么生产必须量化：省显存（4bit 省 3/4——同样显卡装更大模型）+ 吞吐高（Marlin 内核加速——07 篇实测 +61%）——'不量化的生产 = 显存浪费 + 吞吐吃亏'"**（"与 bitsandbytes 的分工：bitsandbytes 管'运行时量化'（微调用）；vLLM 吃'预量化文件'（AWQ/GPTQ——bitsandbytes 09 篇的推理侧结论——**'微调用 NF4、推理用 AWQ/GPTQ（vLLM 吃预量化）'"**）；**量化的流程**——"① 选量化格式（AWQ 默认）；② 找量化模型（Hub 带 awq 的）或自己量化（AutoAWQ）；③ 启动指定 --quantization awq——**'三步 = 量化部署的完整流程'"**（"自己量化的姿势（AutoAWQ——校准数据）——**'了解即可：先找现成的量化模型，再谈自己量化'"**）。

## 3. 多卡配置：张量并行

**张量并行（Tensor Parallelism）= 多卡切分模型（装大模型 + 提速）**：

```text
张量并行（TP）
├── 原理：模型权重切到多张卡（每卡一部分）——一起算
├── 配置：--tensor-parallel-size 2（2 卡）/ 4（4 卡）
├── 效果：70B 模型 2 卡 80GB 或 4 卡 48GB 装下（显存叠加）
└── 注意：卡间通信开销（NVLink 快、PCIe 慢）——不是线性加速
    ——"TP = 把一个大模型'拆开'放在多张卡上——拆得越多越快（有通信成本）"
```

```bash
# 多卡启动（示例）
vllm serve Qwen/Qwen2.5-70B-Instruct \
  --tensor-parallel-size 4 \      # 4 张卡切分
  --gpu-memory-utilization 0.9
# 检查 GPU：nvidia-smi 看每卡显存分配（模型被切分）
```

**多卡心智**：**"多卡的记忆：'TP = 切模型——显存叠加、通信有成本'"**——"**TP 的适用：单卡装不下（70B 要 140GB+——4 卡 48GB 或 2 卡 80GB）——'先算账（模型显存 vs 卡数——bitsandbytes 02 篇账本）再定 TP'"**（"TP 的边界：通信开销随卡数涨（8 卡以上收益递减）——**'TP 2-4 卡是甜点、8 卡以上要流水线并行（PP）——了解即可'"**）；**多卡的环境**——"多卡要 NVLink（卡间高速互联——服务器级）——**'消费级多卡（PCIe）通信慢——TP 收益打折'"**（"多机（多台服务器）→ 更大规模（了解即可：存在——细节是部署体系的事）——**'单机多卡是常态、多机是超大规模'"**）。

## 4. 加载配置速查

**加载配置速查表（启动命令的完整版）**：

```bash
# 生产启动完整示例（7B 量化 + 单卡）
vllm serve Qwen/Qwen2.5-7B-Instruct-AWQ \
  --port 8000 \
  --quantization awq \
  --max-model-len 8192 \
  --gpu-memory-utilization 0.9 \
  --dtype bfloat16 \
  --host 0.0.0.0

# 大模型（70B 量化 + 4 卡）
vllm serve Qwen/Qwen2.5-70B-Instruct-AWQ \
  --quantization awq \
  --tensor-parallel-size 4 \
  --gpu-memory-utilization 0.9

# 配置的查看：vllm serve --help（全部参数）
```

**配置心智**：**"配置的记忆：'模型 + 量化 + 显存 + 并行——四个配置定服务'"**——"**配置的决策顺序：① 选模型（7B/70B——显存账本）；② 选量化（AWQ——生产默认）；③ 定显存（max-model-len + gpu-memory）；④ 定并行（单卡/TP）——'四个决策 = 服务配置的骨架'"**（"配置的调试：启动报错先查配置（显存不够/格式不对——09 篇）——**'配置是排障的第一现场'"**）；**配置的工程化**——"复杂配置用 YAML（vllm serve --config）或代码启动（LLM 类——Python 嵌入）——**'命令行是快速姿势、YAML 是工程姿势（与 uvicorn 同款）'"**（"配置的文档化：服务配置写进部署文档（模型/量化/并行——08 篇）——**'配置即文档'"**）；**模型的版本管理**——"模型是服务的资产：记录来源（HF ID/路径）、版本（模型版本）、量化信息（格式/校准）——**'模型卡（来源/版本/配置）与数据来源卡同款思路（数据分析阶段 3 09 篇）'"**（"模型更新的姿势：新版本模型先压测对比再切换（07 篇）——**'模型升级 = 灰度验证（和代码升级同款）'"**）。
