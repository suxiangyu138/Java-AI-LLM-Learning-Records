## 1. 一句话定位

**vLLM = 大模型推理引擎——让 LLM 高效跑起来（高吞吐服务）的服务器软件**：

```text
一句话定位
├── 出身：UC Berkeley 主导（2023 年开源——Apache 2.0）
├── 本质：LLM 推理服务引擎（吞吐优化的"模型服务器"）
├── 场景：把模型变成 OpenAI 兼容 API 服务（生产部署）
├── 地位：生产环境推理的事实标准（2026 年默认选择）
└── 对比：HuggingFace Transformers 是"训练/单次推理"工具，
         vLLM 是"高并发服务"引擎（吞吐差 24 倍）
    ——"Transformers 是'试跑'，vLLM 是'上线'——LLM 服务的事实标准"
```

**定位心智**：**"vLLM 与 Transformers 的分工：'试跑 vs 上线'"**——"**Transformers 适合开发（加载模型跑一句——方便调试）；vLLM 适合生产（高并发服务——吞吐优化）——'开发用 Transformers，生产用 vLLM——两个都学'"**（"vLLM 内部也用 Transformers 的模型定义（加载模型）——**'vLLM 是 Transformers 的'服务化升级'"**）；**vLLM 能做什么**——"① 模型服务化（一条命令出 OpenAI 兼容 API）；② 高吞吐（连续批处理——同时服务多用户）；③ 多卡/多机（大模型装得下）；④ 量化加速（AWQ/FP8——Marlin 内核）——**'四个能力 = 生产推理的四件事'"**（"了解即可的定位：能干什么（四个能力）、怎么用（命令）、何时用（生产）——不深挖 CUDA 内核"）。

## 2. 推理引擎是什么

**推理引擎 = 让模型"高效跑"的软件层（吞吐优化的服务器）**：

```text
推理引擎的层次
├── 应用层：你的代码（调用 API/写业务）
├── 推理引擎（vLLM 的层次）：
│    模型加载（HF 格式/量化格式）
│    内存管理（PagedAttention——KV 缓存分页——03 篇）
│    调度（连续批处理——请求动态进出）
│    加速内核（量化内核/注意力优化）
└── 硬件层：GPU（显存/算力）
    ——"引擎 = 模型与硬件之间的'调度大师'——同样的 GPU，引擎不同吞吐差 24 倍"
```

**引擎心智**：**"引擎的记忆：'调度大师'——同样的硬件，引擎决定跑多快"**——"**为什么引擎重要：LLM 推理的瓶颈在'内存 + 调度'（KV 缓存占显存、请求要排队）——好的引擎把这两件事做到极致——'vLLM 的 PagedAttention（显存碎片 60-80%→4%）+ 连续批处理 = 吞吐革命'"**（03 篇原理详讲——"本课知道'引擎管什么'，03 篇讲'怎么管的'"）；**引擎 vs 框架**——"框架（Transformers）管'模型怎么定义'；引擎（vLLM）管'模型怎么高效跑'——**'框架是'设计图'，引擎是'工厂流水线'"**（"vLLM 复用框架的模型定义（HF 模型）——**'引擎站在框架的肩膀上'"**）；**引擎的输入输出**——"输入：模型（HF/量化格式）+ 配置；输出：OpenAI 兼容 API——**'引擎的产物 = 一个'模型 API 服务'"**（"了解即可：知道'引擎 = 模型 API 服务化'即可——细节 02/05 篇"）。

## 3. 生产事实标准的地位

**vLLM 的生产地位（2026 年数据说话）**：

```text
生产地位（2026 实测）
├── 吞吐：Llama-3-70B 单卡 H100——batch=1 约 58 tok/s、batch=256 约 5100 tok/s
├── GPU 利用率：85-92%（对比 TGI 的 68-74%）
├── 并发：100-150 并发稳定（对比 TGI 的 50-75 饱和）
├── 模型支持：200+ HF 架构（最广——MoE/多模态/长上下文）
├── 生态：社区最大（Apache 2.0）+ 2026 年每月大版本迭代
└── 对比结论：生产 GPU 服务的默认选择（TGI 已维护模式——08 篇）
    ——"2026 年选推理引擎：默认 vLLM——除非有明确的特殊理由"
```

**地位心智**：**"地位的记忆：'默认选择'——2026 年生产推理的默认答案"**——"**为什么默认：吞吐最高档（连续批处理 + PagedAttention）+ 模型支持最广（200+ 架构）+ 社区最活跃——'三最 = 默认选择的理由'"**（"TGI 的 2025-12 进入维护模式（HuggingFace 官方宣布）——**'TGI 用户迁移 vLLM/SGLang（API 直接替换）——08 篇详讲'"**）；**地位的边界**——"追求单模型极限吞吐（NVIDIA 专用）→ TensorRT-LLM（部署复杂度极高）；本地/边缘 → llama.cpp——**'默认 vLLM，特殊场景换（08 篇决策矩阵）'"**（"vLLM 的局限：必须 GPU（无 CPU 推理）、启动较慢、Python 环境——**'知道局限 = 知道什么时候别用'"**）。

## 4. 2026 版本演进

**版本现状（2026-08 检索校准）**：

```text
2026 版本演进
├── v0.25.0（2026 重大里程碑）：
│    Model Runner V2（MRv2）默认——删除 legacy PagedAttention 代码
│    （概念保留——并入新后端）——V0 回退标志报错（硬性移除）
├── v0.23.0（2026-06-15）：Rust 前端生产级（流式/LoRA/工具解析）
│    ——多级 KV 缓存卸载到 CPU/SSD（长上下文省钱）
├── v0.21.0（2026-05-15）：Python 3.14 支持 + Windows 原生支持（CUDA 13）
└── v0.7.3（2026-04）：Blackwell B200 支持——动态分页（4/8/16-token 多尺寸页）
    ——2.2× FP8 吞吐（Llama-3-70B 8 卡）
    ——"2026 节奏：每月大版本——推理引擎在快速演进"
```

**版本心智**：**"版本观：'演进快 + 锁版本'——每月大版本意味着 API/行为在变"**——"**用法：`pip install vllm==0.25.0`（锁版本）+ 升级看 release notes——'推理引擎的版本纪律与 uvicorn/bitsandbytes 同款（稳定 + 锁版本）'"**（"v0.25.0 的硬性变化：legacy PagedAttention 移除——V0 相关参数报错——**'升级前审查 V0 标志（09 篇迁移排障）'"**）；**版本与硬件**——"Blackwell（B200）要新版本（v0.7.3+）；Python 3.14 要 v0.21.0+——**'硬件/语言新 = 引擎版本要新（01 篇版本基线的同款逻辑）'"**；**了解即可的版本观**——"记住'最新 0.25.x + 锁版本'——细节查 release notes——**'引擎的版本纪律：跟着硬件走 + 锁版本保复现'"**。

**vLLM 的适用场景判断**（什么时候"需要"它）："**① 模型上线**——开发调试用 Transformers、生产服务用 vLLM（本课 2 节的分工）；**② 高并发服务**——多用户 API（连续批处理——03 篇）；**③ 大模型部署**——70B 级（TP 多卡——04 篇）；**④ RAG/Agent 服务**——前缀缓存场景（03 篇）——**'四个场景 = vLLM 的用武之地——判断'要不要 vLLM'看这四问'"**（"单次推理/本地体验不需要它（Ollama/Transformers——08 篇）——**'了解即可 = 知道'何时用'和'何时别用'"**）。
