## 1. 量化的本质

**量化 = 用更少的位数存权重——牺牲一点精度换大量显存**：

```text
量化的直觉
├── 原始：每个权重用 16 位（FP16）存——精确但占地方
├── 量化：每个权重用 4 位（NF4）存——粗略但省地方
├── 类比：高清照片（16bit）vs 压缩照片（4bit）——占空间差 4 倍，看着差不多
└── 核心：模型权重的冗余度远大于你的想象——多数权重不需要那么精确
    ——"量化是'精度换空间的交易'——交易划不划算，看省下的显存值不值"
```

**本质心智**：**"量化不是'压缩文件'——是'换一种存法'"**——"权重的值域是有限的（-1 到 1 左右），4bit 能表示 16 个档位（NF4 更聪明——不均匀分档）——**'把连续的值装进有限档位，就是量化'"**；**量化的数学视角**——"一个 FP16 权重 0.723456 → 量化到最近的档位 0.72——**'误差 = 原值与档位的距离——档位设计得越聪明（NF4 按分布），误差越小'"**（04 篇 NF4 的"正态分布分档"就是聪明设计）；**量化的适用性**——"权重适合量化（冗余大），激活（中间结果）适合吗？——**'bitsandbytes 量化的主要是权重——激活的处理是计算精度的事（07 篇）'"**（"了解即可：权重量化是主战场，细节留给 07 篇"）。

## 2. 精度与位数

**精度的世界——记住五种位宽的显存账**：

```text
精度族谱（模型权重常用）
├── FP32（32 位）：全精度——训练的标准（占 4 字节/参数）
├── FP16（16 位）：半精度——推理常用（占 2 字节/参数）
├── BF16（16 位）：脑浮点——训练推荐（指数范围大，抗溢出）
├── INT8（8 位）：8bit 量化（占 1 字节/参数——省一半）
└── INT4/NF4（4 位）：4bit 量化（占 0.5 字节/参数——省 3/4）
    ——"位数的规律：每减一半位数，显存省一半——4bit = FP16 的 1/4"
```

**精度心智**：**"位数的记忆锚点：FP16 是基准（2 字节）、8bit 省一半（1 字节）、4bit 省 3/4（0.5 字节）"**——**"为什么 4bit 最流行：省 3/4 显存 + 精度损失可接受（09 篇实测 PPL 只差 1.7%）——'性价比之王'"**；**BF16 vs FP16**——"BF16 和 FP16 占一样空间，但 BF16 指数范围大（大数不溢出——训练稳定）——**'训练用 BF16（不 NaN）、推理两者都行（07 篇计算精度）'"**；**NF4 的特殊性**——"NF4 不是普通 4bit（INT4 均匀分档），是按正态分布分档（0 附近更密）——**'权重的分布集中在 0 附近——NF4 把档位放在'权重多的地方'——聪明分档 = 更少误差'"**（04 篇详讲）。

## 3. 显存账本

**显存账本 = 模型显存 ≈ 参数数量 × 每参字节**——第一个要会算的公式：

```python
# 显存账本（推理视角——加载模型的最低显存）
def model_vram(params_b, bits=16):
    """参数（十亿）→ 推理显存（GB）"""
    return params_b * (bits / 8)          # 参数 × 字节/参

# 算账：7B 模型各精度
print(f"7B FP16: {model_vram(7, 16):.1f} GB")     # 14 GB
print(f"7B INT8: {model_vram(7, 8):.1f} GB")      # 7 GB
print(f"7B NF4:  {model_vram(7, 4):.1f} GB")      # 3.5 GB
# 13B NF4: 6.5 GB——12GB 显卡能装下
# 70B NF4: 35 GB——80GB 显卡能装下（HuggingFace 体系的"单卡 70B 甜点"）
```

**账本心智**：**"先算账再动手——'我的显卡装得下吗'用公式 3 秒回答"**——**"账本的三条经验线"**——"**推理 = 参数 × 字节/参（本公式）；微调 = 推理 × 3 左右（反向传播要存梯度——05 篇 QLoRA 怎么破）；运行还要加 KV 缓存/激活（长上下文更吃）**"（"账本是'最低需求'——实际运行加 1-2GB 余量——**'显卡 8GB 装 7B 4bit（3.5GB）看起来够——加上下文缓存可能爆——留余量'"**）；**账本的用途**——"买显卡前算（预算决策）、选模型前算（7B 还是 13B）、选量化前算（4bit 够不够）——**'显存账本是 AI 工程的'心算能力'"**（"面试常问：7B 模型 4bit 要多少显存——3.5GB 是标准答案"）。

**训练账本**（微调场景的另一半账）："训练显存 = 权重（推理那份）+ 梯度（同权重大小）+ 优化器状态（再一份——Adam 存两份动量）——**'全量微调 ≈ 推理 × 3-4'"**——"7B 全量微调 56GB+ 就是这么来的——**'QLoRA 的破法：权重 4bit（省 3/4）+ 只训适配器（梯度/优化器只占 1% 参数）——三份钱只付一份'"**（05 篇账本详算——"本课知道'微调为什么更吃显存'，05 篇知道'QLoRA 怎么破'"）；**账本与批次**——"训练显存还随 batch 涨（每样本一份激活）——**'batch 是训练显存的第二变量——账本公式之外，batch 是调节旋钮'"**（08 篇 OOM 的预防——"OOM 第一解法：减 batch"）。

## 4. 量化的代价

**量化不是免费的——三项代价要清楚**：

```text
量化三代价
├── ① 精度损失：4bit 比 FP16 的困惑度损失约 1.7%（09 篇实测——小但存在）
│    —— 复杂任务（代码/长推理）损失更明显
├── ② 速度损失：bitsandbytes 的推理速度慢于专用内核
│    （Marlin-AWQ +61% 吞吐 vs bnb 较慢——09 篇）
└── ③ 兼容性：量化模型对某些操作（特定算子）支持不完整
    ——"三代价的权衡：省显存 × 精度 × 速度——'量化的最优解是刚好够用'"
```

**代价心智**：**"代价的权衡观：'省下的显存 vs 失去的精度/速度'——用场景判断值不值"**——"**推理演示（聊天/跑通）：4bit 完全够（省显存第一）；生产高吞吐：换 GPTQ/AWQ（速度第一）；微调：必须 4bit（只有它能训练）——'不同场景，代价的权重不同'"**（09 篇决策树）；**代价的量化认知**——"精度损失 1.7%（PPL）听起来小——但**复杂任务（代码生成/数学）损失放大**（HumanEval -7.7%）——**'任务越难，量化损失越明显——简单任务随便量化，复杂任务谨慎'"**；**了解即可的代价观**——"知道'有代价'、知道'代价多大'（09 篇数字）、会判断'值不值'——**'量化的决策 = 省显存 × 任务难度 × 速度要求的三方权衡'"**。
