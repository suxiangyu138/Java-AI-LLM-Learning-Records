## 1. 排障方法论

**量化排障的第一原则：'问题分三类，按顺序查'**：

```text
排障三分类（按顺序）
├── ① 环境类：装不上/加载就崩（CUDA 版本/库缺失）
├── ② 配置类：量化没生效/参数报错（版本 API/配置写法）
└── ③ 运行类：训练 NaN/显存 OOM/速度慢（计算精度/batch/内核）
    ——"排障顺序：先环境（装得上吗）→ 再配置（生效了吗）→ 后运行（跑得动吗）"
```

**方法论心智**：**"排障的第一动作：看版本"**——"**`pip show bitsandbytes` + `python -c "import torch; print(torch.__version__)"` + `nvidia-smi`——三个版本信息 10 秒查完——'量化问题 50% 是版本不匹配'"**（"bitsandbytes 与 PyTorch/CUDA 强耦合——版本矩阵是第一个检查项"）；**排障的第二动作：复现最小化**——"用最小代码复现（一个模型 + 一句加载）——**'问题范围越小越好查——大项目报错先缩小到最小复现'"**（"最小复现 = 排障的黄金工具——'能最小复现 = 一半已定位'"）；**排障的记录**——"报错 → 解决 → 记进速查表（本课 5 节）——**'排障经验是量化使用的护城河——记过的坑不再踩'"**（"本课速查表 = 起点——你的实战坑要不断补充"）。

## 2. 安装与环境问题

**安装与环境三坑——最常见的"装不上"**：

```text
安装环境三坑
├── ① CUDA 版本不匹配：bitsandbytes 按 CUDA 版本编译——torch 的 CUDA 和
│    bnb 的要求不一致 → 加载报错（CUDA error / no kernel image）
│    解法：统一 CUDA 生态（torch 用 cu121/cu124 等——和 bnb 兼容的版本）
├── ② Windows 支持：历史上有坑（需要特定版本）——2026 已支持但版本要新
│    解法：用最新版（≥0.43）——老版本 Windows 支持不完整
└── ③ 依赖冲突：torch 版本太老（<2.4——bnb 0.49 要求 2.4+）
    解法：升级 torch（但升级可能破坏其他库——用 venv 隔离）
    ——"安装三坑的共同解法：'版本对齐'——torch/bnb/CUDA 三件套要匹配"
```

**环境心智**：**"环境的记忆点：'三件套版本对齐'——torch 版本 × CUDA 版本 × bitsandbytes 版本"**——"**先 `pip install bitsandbytes`（最新）→ 报错看 'requires torch>=2.4' 之类 → 对齐——'版本信息是安装排障的第一线索'"**（"报错里写着版本要求——**'读报错的第一行，版本信息都在里面'"**）；**环境的隔离**——"量化库版本敏感（升级 torch 可能破坏 transformers/peft）——**'venv 隔离 + requirements 锁版本——量化环境'专房专用'"**（"别在全局环境折腾量化库——'一个项目一个 venv 是量化环境的铁律'"）；**CPU 无 GPU 的情况**——"bnb 支持 CPU（推理）但 4bit 训练要 GPU——**'没 GPU 用 GGUF/llama.cpp 更顺（09 篇选型）——bnb 的舞台是 GPU'"**（"CPU 场景的替代：GGUF（llama.cpp 生态——CPU 优化更好）"）。

## 3. API 与版本问题

**API 与版本三坑——"老教程代码的适配"**：

```text
API 版本三坑
├── ① 旧参数报错：load_in_8bit=True / load_in_4bit=True 直接传 from_pretrained
│    → 新版报错（≥0.43.0 必须用 BitsAndBytesConfig）
│    适配：quantization_config=BitsAndBytesConfig(load_in_4bit=True)
├── ② 版本太老缺功能：4bit 需要 ≥0.39；QLoRA 推荐 ≥0.46.1
│    老版本装 4bit 配置会静默忽略（不报错但没生效——更坑！）
└── ③ API 演进：老教程的 bnb_4bit_compute_dtype=torch.float16 写法（float16 会 NaN）
    ——"三坑的共同解法：'配置一律用新版标准姿势'——别抄老教程"
```

**API 心智**：**"API 坑的核心：'版本演进杀了老教程'"**——"**2023-2024 年的教程大量用旧 API——复制粘贴直接报错——'看到量化报错先想：是不是老 API'"**（"适配口诀：`load_in_4bit=True` 参数 → 包进 `BitsAndBytesConfig`（06 篇）"）；**静默失效的坑（最阴）**——"老版本 + 新配置 = 不报错但量化没生效（显存没省）——**'量化有没有生效，永远用显存数字验证（get_memory_footprint）——不依赖报错'"**（"静默失效的排查：显存对不上预期 = 配置没生效——**'显存数字是量化的'测谎仪'"**）；**float16 的 NaN 坑**（04 篇）——"计算精度 float16 在训练场景 NaN——**'一律 bf16——除非显卡不支持 bf16（老卡）'"**（"老显卡（V100 等）不支持 bf16 → 用 float16 但接受 NaN 风险/降 batch——**'硬件决定配置的下限'"**）。

## 4. 运行问题：NaN/OOM/慢

**运行三坑——"跑起来了但不对"**：

```text
运行三坑
├── ① NaN（loss 变 NaN/输出乱码）：
│    —— float16 计算精度（换 bf16）最常见；其次是学习率太大
├── ② OOM（显存不够）：
│    —— 减 batch（最有效）→ 减 r（LoRA 秩）→ 换更小模型
│    注意：反量化缓冲在第一次 forward 时分配——显存可能突然尖峰
├── ③ 速度慢：
│    —— bnb 推理无专用内核（07 篇）——单用户无感、并发拉胯
│    注意：device_map='auto' 4bit 可能静默拆 CPU——显存将够时指定 device_map
└── ④ 多卡 FSDP：bnb 4bit + FSDP 要 bnb_4bit_quant_storage=torch.uint8（06 篇参数）
    ——"运行三坑的解法：'配置对齐 + 显存余量 + 场景匹配'"
```

**运行心智**：**"NaN 的第一解法：计算精度换 bf16（配置一行）+ 学习率减半"**——"**NaN = 数值爆炸——bf16 指数范围大抗爆炸——'NaN 先查计算精度，再查学习率'"**（"配置四件套（04 篇）为什么写死 bf16——'标准配置防的坑就是这些'"）；**OOM 的调节顺序**——"**batch 减半 → 梯度累积加倍（等效不变）→ r 减半 → 换小模型——'OOM 是显存不够，不是代码错了——调节顺序 = 损失最小优先'"**（"反量化缓冲的尖峰：首次 forward 突然 OOM——**'预跑一次前向（热身）避免训练中爆显存'"**）；**device_map 的坑**——"4bit + auto 静默拆 CPU（训练速度断崖）——**'显存将够时手动 device_map={'': 0}（全 GPU）——别让 auto 自作主张'"**（"HuggingFace 官方文档警告的坑——'拆分是静默的，速度崩了才知道'"）。

## 5. 报错速查表

**报错速查表（十大高频——本体系的"排障字典"）**：

| 报错/现象 | 原因 | 解法 |
|---------|------|------|
| `CUDA error: no kernel image` | CUDA 版本不匹配 | 对齐 torch/CUDA/bnb 三件套版本 |
| `ImportError: bitsandbytes` | 没装/装错环境 | `pip install bitsandbytes`（正确 venv） |
| `load_in_4bit` 参数报错 | 版本 ≥0.43 旧 API | 包进 `BitsAndBytesConfig` |
| 显存没省（和预期差） | 配置静默失效（老版本） | 升级 ≥0.39 + 显存验证 |
| 训练 loss 变 NaN | float16 计算精度 | 换 `bnb_4bit_compute_dtype=torch.bfloat16` |
| 训练中突然 OOM | 反量化缓冲尖峰 | 先跑一次前向热身 + 减 batch |
| 训练速度断崖 | device_map auto 拆 CPU | 手动 `device_map={"": 0}` |
| FSDP 训练报错 | 4bit 存储格式 | `bnb_4bit_quant_storage=torch.uint8` |
| 推理很慢 | bnb 无专用内核 | 生产换 GPTQ/AWQ（09 篇）；单用户忽略 |
| 老显卡不支持 bf16 | 硬件限制 | float16 + 小 batch（接受 NaN 风险） |

**速查心智**：**"速查表的读法：'先对现象 → 找原因 → 按解法改'——十条覆盖 90% 的量化问题"**——**"速查表的使用纪律：'新坑必记'——你的实战坑补充进表（个人版）——'速查表 = 排障经验的沉淀库'"**（"面试讲'我踩过 device_map 拆 CPU 的坑'——**'报错速查是经验的证明'"**）；**速查表的边界**——"查不到就查官方 GitHub Issues（bitsandbytes-foundation——2026 活跃）——**'开源库的 Issues 是最后的排障资源——先搜再问'"**（"搜索姿势：报错信息 + 'bitsandbytes'——**'会搜 Issues 是排障的高级姿势'"**）。
