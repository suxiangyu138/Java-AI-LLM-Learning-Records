## 1. 日志的定位

**日志 = 服务器的"黑匣子"——出问题时查它**：

```text
日志的价值
├── 排障：请求 500 了——日志告诉"哪个请求、什么错"
├── 分析：访问量/慢请求/错误率——服务健康的"体温计"
├── 审计：谁访问了什么（安全合规）
└── 运维：磁盘/重启记录（部署与故障的时间线）
    ——"没有日志的服务器 = 出事了只能猜——日志是运维的第一工具"
```

**日志心智**：**"日志的记忆：'黑匣子'——出事时唯一的证据链"**——"**生产服务器的日志要落盘（文件）——不是终端（终端重启就没了）——'日志落盘 = 运维的底线（09 篇部署检查清单项）'"**（"日志的轮转（文件按天切分——logrotate——日志别无限涨）——**'日志管理 = 落盘 + 轮转'"**）；**日志的分级**——"error（出错）/warning（警告）/info（信息——默认）/debug（调试）——**'生产用 info（够用不吵）、排障开 debug（详细）'"**（"日志太多 = 噪音（找不到重点）；太少 = 没信息——**'日志级别是'信息量的旋钮'"**）。

## 2. 访问日志与错误日志

**uvicorn 的两类日志——访问（谁来了）与错误（出什么事）**：

```bash
# 访问日志（默认开——每个请求一行）
uvicorn app:app --access-log      # 默认开启——请求日志
# INFO: 127.0.0.1:54321 - "GET / HTTP/1.1" 200 OK
# 格式：IP - 方法 路径 状态码（排障/分析的基础数据）

# 错误日志（默认开——应用异常/uvicorn 内部问题）
# ERROR: Exception in ASGI application（应用抛错——堆栈）

# 日志配置（级别/格式/文件）
uvicorn app:app --log-level info --log-config log_config.json
```

```python
# 代码配置日志（落盘示例——logging 配置）
import logging

logging.basicConfig(
    filename="uvicorn.log",           # 落盘（运维底线）
    level=logging.INFO,
    format="%(asctime)s %(levelname)s %(message)s",
)
```

**日志心智**：**"两类日志的记忆：'访问日志看流量、错误日志看故障'"**——"**访问日志（access）：请求记录（IP/路径/状态码）——分析工具（访问量/慢请求）的原料；错误日志（error）：异常堆栈——排障的'第一现场'——'两类日志配合：先看错误日志定位 bug，看访问日志看影响范围'"**（"状态码的读法：200 正常/4xx 客户端错/5xx 服务端错——**'5xx 突然增多 = 应用出 bug（要查错误日志）'"**）；**日志的工程化**——"结构化日志（JSON——机器可读——配合日志平台 ELK/Loki——`02-后端核心技术` 日志体系）——**'了解即可：uvicorn 默认文本日志，生产可配结构化'"**（"日志轮转（logrotate/按天切）——**'日志管理：落盘 + 轮转 + 定期清理'"**）。

## 3. 健康检查

**健康检查 = 告诉"监控/负载均衡"服务器活着且健康**：

```python
# 健康检查端点（FastAPI 应用里写——/health）
from fastapi import FastAPI

app = FastAPI()

@app.get("/health")
def health():
    return {"status": "ok", "version": "1.0.0"}
```

```nginx
# 负载均衡/监控调用 /health（Nginx 场景——05 篇）
# 监控工具（Prometheus + 探针——02 后端监控体系）定期请求 /health
# 返回非 200 → 标记不健康 → 摘除/告警
```

**健康检查心智**：**"健康检查的记忆：'/health 端点 = 服务器的'体检报告'"**——"**两类检查：存活检查（进程活着——uvicorn 起没起）与健康检查（依赖正常——数据库/缓存连得上）——'/health 返回 ok = 能接请求；返回 500 = 有依赖挂了'"**（"健康检查的深化：检查依赖（DB 连通）——**'依赖挂了也返回不健康（避免'活着但残废'）'"**）；**健康检查的使用**——"监控系统定期探（Prometheus/云监控）+ 负载均衡摘除（Nginx/云 LB 把不健康的实例剔除）——**'健康检查 = 自动化运维的'手'"**（"容器编排（Docker/K8s 的 healthcheck——`../../../../02-后端核心技术%20微服务%20分布式%20云原生/11-云原生/`）——**'容器场景的健康检查是标配'"**）。

## 4. 监控集成

**监控集成 = 把 uvicorn 的指标接入监控系统（7×24 看着它）**：

```text
监控四件事
├── ① 进程监控：uvicorn 进程活着吗（systemd/Docker 自带——05 篇）
├── ② 指标监控：QPS/延迟/错误率（Prometheus + 指标端点）
├── ③ 日志监控：错误日志告警（日志平台——ELK/Loki）
└── ④ 健康检查：/health 探活（本课 3 节）
    ——"四件事 = 从'活着'到'健康'的完整监控"
```

```python
# 指标端点（Prometheus 集成示例——了解即可）
# from prometheus_fastapi_instrumentator import Instrumentator
# Instrumentator().instrument(app).expose(app)   # /metrics 端点
# Prometheus 定期抓 /metrics → Grafana 画图 → 告警（QPS 掉/错误率升）
```

**监控心智**：**"监控的记忆：'四件事：进程/指标/日志/健康'"**——"**从'活着'到'健康'的梯度：进程监控（活着吗）→ 健康检查（能接请求吗）→ 指标监控（快吗/错吗）→ 日志（为什么错）——'监控的深度递进'"**（"完整监控体系在 `02-后端核心技术` 的监控章节（Prometheus/Grafana——`../../../../02-后端核心技术%20微服务%20分布式%20云原生/07-工程运维基础/运维/`）——**'本课知道'要监控什么'，监控体系教'怎么搭'"**）；**监控的最小起步**（不用上全套也能做）——"**① 日志落盘 + ② /health 端点 + ③ 手动 curl 探活——三样零成本先做起来——'监控的起点不是 Prometheus，是日志 + 健康检查'"**（"小项目先做最小监控（日志 + 健康），规模大了再上 Prometheus/Grafana——**'监控跟着规模走，先保证看得见'"**）；**监控的告警**——"指标异常 → 告警（QPS 归零/5xx 突增/延迟 P99 超标）——**'告警阈值来自压测基线（06 篇）——阈值拍脑袋 = 告警失灵'"**（"告警的防打扰（同告警抑制——爬虫监控体系的同款纪律）——**'告警疲劳 = 告警失效'"**）；**了解即可的监控观**——"知道'四件事' + 会配健康检查 + 会用现有监控（云监控/Prometheus）——**'监控是'看'的艺术——先保证看得见，再谈看得细'"**。
