## 1. 安装

**安装命令——两种（裸装 vs standard 扩展）**：

```bash
# 裸装（够跑——但性能不是最优）
pip install uvicorn

# standard 扩展（生产推荐——uvloop/httptools/websockets 全家桶）
pip install "uvicorn[standard]"

# 锁版本区间（生产复现）
pip install "uvicorn[standard]>=0.49,<1.0"
```

**安装心智**：**"安装的记忆：'直接 standard'——一次装到位，别裸装再补"**——"**standard 包含三件宝：uvloop（加速事件循环）、httptools（加速 HTTP 解析）、websockets（WebSocket 支持）——'裸装 vs standard：性能差 20-50%（06 篇详讲）——装就装 standard'"**（"环境纪律（`../01-Python语言/pip/` 或 venv 体系）：venv 里装——**'uvicorn 装进项目 venv，别装全局'"**）；**安装的验证**——"`uvicorn --version` 看版本——**'装没装对，版本命令说话'"**（"版本对不上（太老）→ 升级——**'0.38+ 才支持 Python 3.14（01 篇版本基线）'"**）。

## 2. 第一个应用

**3 分钟跑通——写应用 + 启动**：

```python
# app.py——一个最小的 ASGI/FastAPI 应用
from fastapi import FastAPI

app = FastAPI()

@app.get("/")
def home():
    return {"message": "Hello uvicorn!"}

@app.get("/async")
async def async_home():          # 异步端点（uvicorn 的主场）
    return {"message": "async works"}
```

```bash
# 启动（命令行——最常用姿势）
uvicorn app:app --port 8000
# 参数解读：app（文件名）:app（应用对象名）——"module:app"
# 访问 http://127.0.0.1:8000 看到 JSON——第一个应用跑通了
```

**第一个应用心智**：**"启动命令的记忆：'uvicorn 模块:应用'——文件:对象"**——"**`uvicorn app:app` = 文件 app.py 里的 app 对象——'冒号是'文件:对象'的语法——写错（app:myapp）404 或报错'"**（"FastAPI 的 app 是 FastAPI() 实例——**'uvicorn 找的是'ASGI 应用对象'——FastAPI 实例就是"**）；**验证三件套**——"浏览器访问（看到 JSON）+ 终端日志（启动信息 + 请求日志）+ 修改代码热重载（下节）——**'跑通的标志：请求有响应 + 日志有记录'"**（"curl 验证：`curl http://127.0.0.1:8000/`——**'命令行验证比浏览器更专业'"**）；**异步 vs 同步端点**——"async def 端点（异步——uvicorn 的主场）与 def 端点（同步——FastAPI 自动丢线程池）——**'了解即可：uvicorn 让 async 端点'真异步'——同步端点也能跑（FastAPI 转线程池）'"**（"性能差异：async 端点单进程扛高并发（03 篇原理）——**'要性能写 async def'"**）。

## 3. 热重载开发模式

**热重载 = 代码改动自动重启（开发模式的杀手级功能）**：

```bash
# 开发模式启动（--reload）
uvicorn app:app --reload
# 效果：修改 app.py 保存 → uvicorn 自动重启 → 浏览器刷新即见新结果
# 不用手动重启服务器——"改了就能看"的开发体验
```

**热重载心智**：**"热重载的记忆：'--reload = 开发模式'——改了自动重启"**——"**开发体验的价值：改代码 → 保存 → 刷新页面——循环不打断（不用 Ctrl+C 重启）——'热重载 = 开发效率的倍增器'"**（"实现原理（了解即可）：uvicorn 监听文件变化 → 自动重启进程——**'知道'自动重启'即可'"**）；**热重载的边界（重要）**——"**--reload 只用于开发，不上生产**：性能损耗（监听文件）+ 安全隐患（自动重启）——'生产用多 worker（05 篇）——reload 与 workers 不能同时用'"（"`--reload` 与 `--workers` 互斥（报错）——**'开发 reload、生产 workers——两个模式别混'"**）；**热重载的坑**——"改配置类文件（如 .env）不触发重启（看监听范围）——**'热重载没生效：先确认文件在被监听范围'"**（"静态文件（模板/前端）不触发——**'uvicorn 监听的是 Python 文件（默认）'"**）。

## 4. 常用参数速查

**常用参数速查表（启动命令的"单词本"）**：

```bash
# 常用参数（按使用频率）
uvicorn app:app \
  --host 0.0.0.0 \            # 监听地址（0.0.0.0 = 所有网卡——外部可访问）
  --port 8000 \               # 端口（默认 8000）
  --reload \                  # 热重载（开发）
  --workers 4 \               # 多进程（生产——04/05 篇）
  --log-level info \          # 日志级别（debug/info/warning）
  --timeout-keep-alive 5 \    # 长连接超时（06 篇）
  --limit-concurrency 1000    # 并发上限（保护——可选）

# 完整示例（开发）
uvicorn app:app --reload --port 8000

# 完整示例（生产）
uvicorn app:app --host 0.0.0.0 --port 8000 --workers 4
```

**参数心智**：**"参数的记忆：'host/port/reload/workers 四大件'——其他用时查"**——"**host 的坑：默认 127.0.0.1（只能本机访问）——外部访问要 0.0.0.0——'127.0.0.1 vs 0.0.0.0：本机 vs 全网'"**（"部署到服务器/容器忘写 0.0.0.0 = 外面访问不到——**'这是部署第一坑（09 篇速查）'"**）；**参数查看**——"`uvicorn --help` 看全部参数——**'记四大件，其余查 --help'"**（"参数会随版本演进（0.45 加 --reset-contextvars）——**'新版本看 release notes'"**）；**参数的工程化**——"复杂参数用配置文件（uvicorn --app-dir/或代码启动——04 篇）——**'命令行是快速姿势，配置化是工程姿势'"**。

**开发到生产的完整命令流**（02-05 篇的连贯预览）："**开发**：`uvicorn app:app --reload`（热重载迭代）；**测试**：`uvicorn app:app --port 8001`（多开不冲突）；**生产**：`uvicorn app:app --host 0.0.0.0 --workers 4`（多核利用）；**容器**：`CMD ["uvicorn", "app:app", "--host", "0.0.0.0"]`（Docker 标准）——**'一条命令从开发走到生产——参数越来越全，模式越来越稳'"**（"命令流 = 本体系 02/04/05 篇的骨架——**'先会跑（02），再会启动（04），后会部署（05）'"**）。

**热重载的实现细节**（了解即可但有用）："**原理**——uvicorn 监听 Python 文件的变化（watchfiles 库）→ 检测到修改 → 自动重启进程（重载的是'代码'不是'整个服务器'）——'改代码 → 保存 → 自动生效'"（"重载的触发范围：默认监听当前目录的 .py 文件——**'新增文件（新路由模块）也会触发（加了新文件要等重载）'"**）；**重载的性能**——"开发模式的重载有性能损耗（文件监听）——**'这就是它不能上生产的原因之一（02 篇边界）'"**（"重载的排障：改了没生效 → 查文件是否在监听范围 + 保存是否正确（09 篇速查）——**'热重载是开发神器，也是'没生效'时的第一怀疑对象'"**）；**热重载的调试价值**——"报错时改代码 → 自动重启 → 看新日志——**'热重载让'改-跑-看'循环秒级完成——开发效率的倍增器'"**（"配合 debug 日志（--log-level debug）——**'热重载 + debug = 开发排障的黄金组合'"**）；**热重载的边界确认**——"`--reload` 与 `--workers` 互斥（同时用报错）——**'开发 reload、生产 workers——两个模式各管各的（02 篇边界的重申）'"**（"reload 模式下代码启动要传字符串（04 篇的坑）——**'热重载的两个边界记住：不上生产 + 不配 workers'"**）。
