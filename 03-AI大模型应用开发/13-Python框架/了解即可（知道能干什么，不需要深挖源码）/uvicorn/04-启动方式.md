## 1. 四种启动方式

**uvicorn 的四种启动姿势——按场景选**：

```text
四种启动方式
├── ① 命令行：uvicorn app:app（02 篇——快速/开发）
├── ② 代码启动：uvicorn.run()（程序化——脚本/测试/CI）
├── ③ 多 worker：--workers 4（生产——多核利用）
└── ④ Gunicorn 组合：gunicorn -k uvicorn.workers.UvicornWorker（老牌进程管理）
    ——"四种姿势的场景：开发用 ①、脚本用 ②、生产用 ③④——姿势跟着场景走"
```

**启动心智**：**"四种姿势的记忆：'命令/代码/多进程/组合'"**——"**日常开发 ① 就够（命令最简单）、自动化脚本 ②（代码可控）、生产 ③④（多核 + 进程管理）——'启动姿势的复杂度跟着场景走'"**（"四种姿势的内部原理相同（都是 uvicorn 跑 ASGI 应用）——**'姿势是'外壳'，内核一样'"**）；**姿势选择的判断**——"问三个问题：谁启动（人/脚本/系统）、要几个进程（1/N）、谁管进程（uvicorn 自己/Gunicorn/系统）——**'三问定姿势'"**（"系统的服务管理器（systemd/Docker）启动 → 命令行或代码启动都行（05 篇部署）——**'部署姿势 = 启动姿势 + 进程管理'"**）。

## 2. 命令行启动（最常用）

**命令行 = 快速姿势（开发/小部署的首选）**：

```bash
# 基本（02 篇已会）
uvicorn app:app --reload

# 常用组合（开发）
uvicorn app:app --reload --port 8000 --log-level debug

# 常用组合（简单生产）
uvicorn app:app --host 0.0.0.0 --port 8000 --workers 4

# 指定应用目录（应用不在当前目录）
uvicorn app:app --app-dir ./src

# 工厂模式（应用是函数返回的——app 工厂）
uvicorn app:create_app --factory
```

**命令行心智**：**"命令行的记忆：'module:app + 参数'——一行命令跑起来"**——"**命令行的价值：快速（不用写代码）+ 可脚本化（写进部署脚本）——'命令行是 uvicorn 的'默认姿势'"**（"`--app-dir` 的坑：应用在子目录时（src 布局）不指定会 ModuleNotFoundError——**'部署第一坑之一（09 篇速查）'"**）；**工厂模式**——"`--factory`：应用由工厂函数创建（测试/配置化场景）——**'知道存在即可——普通项目用模块级 app'"**（"工厂模式的价值：每次请求新应用（隔离）——**'高级场景（多租户）用——了解即可'"**）；**命令行的限制**——"复杂配置（几十个参数）命令行太长——**'参数多了换配置/代码启动（优雅）'"**。

## 3. 代码启动（程序化）

**代码启动 = uvicorn.run()——脚本/测试/CI 的姿势**：

```python
# 代码启动（uvicorn.run——程序化控制）
import uvicorn

if __name__ == "__main__":
    uvicorn.run(
        "app:app",                # 应用（字符串形式——模块:对象）
        host="0.0.0.0",
        port=8000,
        reload=True,              # 开发
        workers=4,                # 生产（代码启动也能多 worker）
        log_level="info",
    )

# 或直接传应用对象（同进程内——测试常用）
from app import app
uvicorn.run(app, host="127.0.0.1", port=8000)
```

**代码启动心智**：**"代码启动的记忆：'uvicorn.run(应用, 参数)'——配置在代码里"**——"**代码启动的价值：① 配置集中（参数在代码——不用记命令行）；② 可编程（条件/环境变量控制）；③ 测试友好（同进程启动）——'代码启动 = 配置的'代码化'"**（"命令行 vs 代码：等价能力——**'选择看偏好与场景：命令行快、代码可控'"**）；**代码启动的坑**——"**字符串 vs 对象**：`uvicorn.run("app:app")`（字符串——reload 模式必需）vs `uvicorn.run(app)`（对象——不能 reload）——**'reload 模式必须传字符串'"**（"传对象时 reload=True 会报错——**'代码启动的坑之一（09 篇速查）'"**）；**`if __name__ == "__main__"`**——"标准姿势：直接运行此文件时启动（import 时不启动）——**'python main.py 就能启动——部署/测试的标准入口'"**（"Docker 的 CMD 也常是 `python main.py`（05 篇）——**'代码启动 = 容器启动的常用姿势'"**）。

## 4. 多 worker 启动（生产）

**多 worker = 多进程并行——利用多核 CPU（生产标配）**：

```bash
# 命令行多 worker
uvicorn app:app --workers 4
# 代码多 worker
# uvicorn.run("app:app", workers=4)

# worker 数怎么定：≈ CPU 核数
# nproc 看核数（4 核 → --workers 4；8 核 → 8）
# 注意：--reload 与 --workers 不能同时用（互斥）
```

**多 worker 心智**：**"多 worker 的记忆：'worker ≈ CPU 核数'——多了反而慢"**——"**为什么约等于核数：每个 worker 一个进程（独立事件循环）——核数不够时上下文切换浪费——'worker 数 = 核数（4 核 4 worker 是黄金配比）'"**（"worker 不是越多越好（05 篇详讲——'多了反而慢'）——**'先查 nproc 再定 worker'"**）；**多 worker 的语义**——"每个 worker 独立内存（不共享状态——内存 N 倍）——**'有状态应用（内存缓存）要多 worker 慎用（状态不共享）'"**（"无状态 API 多 worker 无压力——**'API 设计成无状态 = 多 worker 友好的前提'"**）；**reload 与 workers 互斥**——"`--reload`（单进程监听文件）vs `--workers`（多进程）——同时用报错——**'开发 reload、生产 workers——两个模式分开（02 篇重申）'"**。

## 5. 启动方式选型

**启动方式选型表（写配置前的最后一步）**：

| 场景 | 姿势 | 理由 |
|------|------|------|
| 本地开发 | 命令行 + --reload | 最快（热重载） |
| 脚本/测试 | 代码启动（uvicorn.run） | 配置代码化 |
| 简单生产 | 命令行 + --workers N | 多核利用 |
| 生产 + 进程管理 | Gunicorn + UvicornWorker | Gunicorn 管 worker/超时/优雅 |
| Docker | 代码启动或命令行（CMD） | 容器标准 |
| systemd 服务 | 命令行（ExecStart） | 系统管理 |

**选型心智**：**"选型的记忆：'开发 reload、生产多 worker、重场景 Gunicorn 组合'"**——"**简单生产：uvicorn --workers 够用；复杂生产（需要优雅停机/worker 管理/超时控制）→ Gunicorn + UvicornWorker（Gunicorn 是'成熟的进程管理器'）——'uvicorn 管协议、Gunicorn 管进程——经典组合（05 篇详讲）'"**（"Gunicorn 组合的姿势：`gunicorn -k uvicorn.workers.UvicornWorker app:app --workers 4`——**'一个命令 = 进程管理 + 协议处理'"**）；**选型的进阶**——"再往上：Docker（容器化）+ systemd（服务管理）+ 负载均衡（多机）——**'启动方式只是部署的第一层（05 篇是完整部署）'"**；**选型的记录**——"把启动命令写进 README/部署文档——**'启动姿势 = 项目的运行文档'"**；**选型的检查**——"选好姿势后验证三件事：能启动（命令对）、能访问（外部通）、能停（优雅）——**'启动姿势的验收 = 起得来 + 连得上 + 停得稳'"**（"验收的落地：部署文档里写清'怎么启动/怎么验证/怎么停'——**'文档三问 = 团队的交接标准'"**）。
