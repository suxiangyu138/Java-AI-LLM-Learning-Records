## 1. 实战项目：部署 API 服务

**实战项目 = 把本体系九课串成"亲手部署"的完整流程**：

```text
实战项目三步（从写代码到生产姿势）
├── 第一步：写应用（02/07 篇）
│    FastAPI 应用（含 async 端点 + /health + lifespan）
│    本地启动验证（uvicorn + 热重载）
├── 第二步：生产配置（04/05/06 篇）
│    多 worker（≈ 核数）+ standard 已装 + 超时限流参数
│    日志落盘 + /health 健康检查
└── 第三步：完整部署（05/08 篇）
    Nginx 反代（转发头 + WebSocket 三件套）
    验证：外部访问 + 优雅停机 + 日志可查
```

```bash
# 实战核心命令（生产姿势汇总）
# ① 开发（第一步）
uvicorn app:app --reload

# ② 生产（第二步——多 worker + 保护参数）
uvicorn app:app --host 0.0.0.0 --port 8000 --workers 4 \
  --timeout-keep-alive 5 --limit-concurrency 1000

# ③ 部署（第三步——systemd 或 Docker 管进程 + Nginx 反代）
# systemd: ExecStart=... uvicorn app:app --workers 4 --host 127.0.0.1 --port 8000
# Nginx: proxy_pass http://127.0.0.1:8000 + 转发头（05 篇）
```

**实战心智**：**"实战的验收标准：'三问'——能访问吗（外部）、能优雅停吗（部署）、日志能查吗（运维）"**——"**验收三看：curl 外部地址（0.0.0.0 + Nginx 路径通）、kill -TERM 观察优雅停机、日志文件有记录——'三个验收 = 生产姿势的三件套证明'"**（"了解即可的实战观：跑通流程 + 记录命令——不深挖 C 实现——**'你验证的是'怎么部署'，不是'内核怎么写的'"**）；**实战的环境**——"本机即可（Linux 最佳——Windows 也能跑（uvloop 回退——06 篇）——**'部署实战优先 Linux（服务器主场）'"**（"虚拟环境：venv（`../01-Python语言/pip/` 或 Python 虚拟环境体系）——**'项目 venv 隔离是实战的第一步'"**）；**实战的常见卡点**——"host 忘配（09 篇速查第一坑）、Nginx 502（三查）、日志没落盘——**'卡住先查速查表——别卡在同一个坑两次'"**；**实战的进阶方向**——"**① 加监控**（08 篇——健康检查 + 日志告警）；**② 加压测**（06 篇——QPS 数字）；**③ 容器化**（Docker 部署——05 篇）；**④ 上 HTTPS**（Nginx 配证书——05 篇）——**'部署跑通后的四步进阶 = 从'能跑'到'专业'"**；**实战的完整文档**——"部署文档三件套：架构图（Nginx → uvicorn → 应用）、启动命令（开发/生产/容器）、运维手册（日志/健康检查/回滚）——**'部署的交付 = 系统 + 文档——文档是团队的交接资产'"**（"文档的维护：部署方式变了文档跟着改——**'文档过期 = 误导后人——部署文档要活'"**）；**实战的自检**——"跑完后过一遍 10 篇毕业检查单（八项）——**'自检 = 毕业的最后仪式'"**。

## 3. 报错速查

**高频报错速查（09 篇完整版的精要——十选六）**：

| 报错/现象 | 原因 | 解法 |
|---------|------|------|
| `ModuleNotFoundError` | 模块/对象名错 | 查 app:app + --app-dir |
| `address already in use` | 端口占用 | 换端口或杀进程 |
| 外部访问不到 | host 是 127.0.0.1 | `--host 0.0.0.0` + 防火墙 |
| 请求 500 | 应用异常 | 看错误日志堆栈 |
| 全部请求卡住 | async 里同步阻塞 | time.sleep → asyncio.sleep |
| Nginx 502 | uvicorn 没起/端口错 | 502 三查（进程/端口/绑定） |

**速查心智**：**"六条的规律：'启动两条 + 运行两条 + 部署两条'"**——"**背下六条的'原因列'——报错时先对原因再对解法——'排障的本质是原因归类'"**（"新坑必记（09 篇纪律延续）——**'速查表是你的，不是我的——我的十条是起点，你的实战坑要补充'"**）。

## 4. 面试演练

**面试问答（Web 服务器相关——本体系特有）**：

**Q1：FastAPI 应用怎么部署到生产？**——答：**"四件套：① 多 worker（--workers 4——约等于 CPU 核数——利用多核）；② Nginx 反代（静态文件/HTTPS/转发头 X-Forwarded——防日志失真）；③ 进程管理（systemd 或 Docker——挂了自动重启）；④ 优雅停机（SIGTERM——先停新再等旧——部署无感）——加配套：日志落盘 + /health 健康检查 + 超时限流参数——启动命令：uvicorn app:app --host 0.0.0.0 --workers 4"**——结构：**四件套 → 配套 → 命令**——"答出'优雅停机 + 健康检查'是生产经验的证明"。

**Q2：uvicorn 和 Gunicorn 的区别？**——答：**"协议不同：uvicorn 是 ASGI 服务器（异步——支持 async/await/WebSocket——FastAPI 的运行时）；Gunicorn 是 WSGI 服务器（同步——Flask/Django 的运行时）——生产常见组合：Gunicorn 管进程（worker 生命周期/超时/优雅重启）+ uvicorn 的 worker 类管协议（gunicorn -k uvicorn.workers.UvicornWorker）——各管一段"**——结构：**协议差异 → 组合姿势**——"答出'组合姿势'显示实战经验"。

**Q3：uvicorn 单进程能扛多少并发？怎么提升？**——答：**"单进程（事件循环）IO 密集场景能扛数千并发——异步模型（等待不占资源）；提升三步：① 应用侧（async def + 无同步阻塞——90% 的瓶颈在应用）；② standard 扩展（uvloop/httptools——C 加速——吞吐 +20-50%）；③ 多 worker（≈ 核数）+ 水平扩展（多实例 + Nginx 负载均衡）——调优按 ROI 排序，压测验证（wrk/locust）"**——结构：**能力 → 三步提升 → 压测验证**——"答出'瓶颈 90% 在应用'是高级认知"。
