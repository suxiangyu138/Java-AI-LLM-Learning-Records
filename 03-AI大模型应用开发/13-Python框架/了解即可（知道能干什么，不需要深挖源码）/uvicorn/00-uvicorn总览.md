## 3. 与主体系的分工

**与 Python 异步 + FastAPI 体系（`../../../01-Python语言/Python%20异步%20+%20FastAPI/`）的分工**：那个体系是"异步 + FastAPI 全栈"（asyncio 原理/FastAPI 全功能/部署），本体系是 **uvicorn 单库的"了解即可"**——**"FastAPI 体系是全景地图，本体系是'服务器'这一站的说明书"**——深度定位：**知道能干什么、怎么用、何时用——不深挖源码**（目录名即定位）。

**与 trl/bitsandbytes 体系（`../trl/`、`../bitsandbytes/`）的同款定位**：三套都是"了解即可"——**"知道能干什么、怎么用、何时用——不深挖实现"**——本体系讲的是"Web 服务的运行底座"（跑起来），不是"训练/量化"（AI 侧）。

**2026-08 基线**：uvicorn **0.52.1**（2026-08-01 发布）；PyPI 总下载 **51 亿+**；Python 3.14 支持（0.38 起）；活跃发布（2026 年每月迭代）——**"服务器是'稳'字当头的软件——用最新稳定版 + 锁版本"**。

## 6. 常见误区

**误区一：uvicorn 就是 FastAPI 的一部分**——"装了 FastAPI 就有 uvicorn"——**正确：两个独立库——FastAPI 写应用、uvicorn 跑应用（01 篇——"写代码的是 FastAPI，跑代码的是 uvicorn"）**。

**误区二：开发模式直接上生产**——"--reload 一直开着跑生产"——**正确：reload 是开发模式（有性能损耗 + 安全问题）——生产用多 worker**（02/05 篇）。

**误区三：worker 越多越好**——"--workers 32 无敌"——**正确：worker 数 ≈ CPU 核数（多了反而慢——上下文切换）**（05 篇——"worker 不是越多越好，是约等于核数"）。

**误区四：uvicorn 直接暴露公网**——"uvicorn 跑 0.0.0.0 就完事"——**正确：uvicorn 是应用服务器——前面要 Nginx 反代（静态/HTTPS/安全）**（05 篇——"uvicorn 管应用，Nginx 管门户"）。

**误区五：不装 standard 扩展**——"uvicorn 裸装就够"——**正确：生产装 uvicorn[standard]（uvloop/httptools 提速——性能差 20-50%）**（06 篇——"standard 是性能标配"）。

**误区六：日志只在终端看**——"启动后不管日志"——**正确：生产日志要落盘 + 轮转（出事了查文件——终端重启就没了）**（08 篇——"看不见的服务器 = 出事了不知道"）。

**误区七：不用健康检查**——"/health 无所谓"——**正确：健康检查是监控/负载均衡的'手'（依赖挂了提前发现）**（08 篇——"从'活着'到'健康'的监控梯度"）。
