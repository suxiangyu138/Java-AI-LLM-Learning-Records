## 1. 安装与版本锁定

```bash
pip install "peft==0.19.1" transformers accelerate datasets
# 训练 + 量化场景（QLoRA 必需，见 08 篇）
pip install bitsandbytes
```

**锁版本是 2026 年的第一纪律**：peft 周更级迭代（0.17 → 0.19 一年三个大版本），且与 transformers 强耦合——**transformers v5 要求 peft ≥ 0.19.1，peft < 0.18 装 transformers v5 直接报兼容错误**；Python 3.9 用户装 peft 会静默回落到 0.17.x（0.18 起弃 3.9）——**`pip install "peft==0.19.1"` 一次性规避全部版本坑**。装完验证：

```bash
python -c "import peft, transformers; print(peft.__version__, transformers.__version__)"
# 期望输出类似：0.19.1 5.12.1
```

**环境建议**：2026 年 Python 项目用 `uv` 或 venv 建独立环境（`uv venv` + `uv pip install "peft==0.19.1" transformers ...`），**别往系统环境里装**；**没 GPU 也能学本体系**——0.5B 级模型 CPU 可训（慢 5-10 倍但管线相同），QLoRA 章节需 GPU 验证（08 篇）；Windows 用户注意 bitsandbytes 已官方支持 CUDA 12.x，装不上先查显卡驱动版本；国内网络建议配 HF 镜像（`HF_ENDPOINT=https://hf-mirror.com`）加速模型下载。

## 2. 最小训练脚本：四个 API 走通

```python
from transformers import AutoModelForSequenceClassification, AutoTokenizer, Trainer, TrainingArguments
from peft import LoraConfig, get_peft_model, TaskType

model = AutoModelForSequenceClassification.from_pretrained("Qwen/Qwen2.5-0.5B", num_labels=2)

lora_config = LoraConfig(
    r=8,                          # 秩数：adapter 的"粗细"
    lora_alpha=16,                # 缩放系数：注入强度
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
    lora_dropout=0.1,
    bias="none",
    task_type=TaskType.SEQ_CLS,
)

peft_model = get_peft_model(model, lora_config)   # ① 包装：冻结底座 + 注入 LoRA
peft_model.print_trainable_parameters()           # ② 验证：可训练参数占比
# trainable params: 442,368 || all params: 496,616,448 || trainable%: 0.0891
```

`print_trainable_parameters()` 是**验收第一命令**：输出可训练参数与占比——**"trainable% 在 0.1%-2% 之间说明注入正常，100% 说明包装失败（模型被整体解冻了）"**。

**逐行读懂这个脚本**：`AutoModelForSequenceClassification` 带 `num_labels=2` 是因为分类任务要重建任务头——**底座模型本身没有任务头，任务头是任务侧的新增结构，PEFT 的冻结机制不冻结它，LoRA 也不注入它**；`TaskType.SEQ_CLS` 告诉 PEFT 这是序列分类任务（决定注入参考与包装子类）；`get_peft_model` 的返回值是 `PeftModelForSequenceClassification`——**PeftModel 家族按任务类型细分**（生成场景是 PeftModelForCausalLM），行为与包装前完全一致。**任务头是 PEFT 里唯一"全量可训"的部分**——它也是 print_trainable_parameters 里那 0.1% 的一部分，这是正常现象，不是注入失败。之后完全走 transformers 标准流程：

```python
training_args = TrainingArguments(
    output_dir="./lora-ckpt", per_device_train_batch_size=8,
    learning_rate=2e-4, num_train_epochs=3,
    bf16=True, save_strategy="epoch", logging_steps=10,
)
trainer = Trainer(model=peft_model, args=training_args, train_dataset=train_ds)
trainer.train()                                   # ③ 训练：循环由 Trainer 管
peft_model.save_pretrained("./lora-ckpt")         # ④ 保存：只存 adapter（~1MB）
```

**与全量训练的唯一区别就是第 ① 行**——包装之后，训练循环、评估、保存全部复用 transformers API——这就是"了解 API 即可"的底气：**会 transformers 训练 = 会 PEFT 训练，多出来的只有 LoraConfig 一个对象**。

## 3. LoraConfig 核心参数第一眼

- **r**：低秩秩数，adapter 的"宽度"，直接决定参数量（r=8 约 0.1% 参数，r=64 约 1%）；主流 8-64。
- **lora_alpha**：缩放系数，注入强度用 `α/r` 放大——经验 `alpha = 2×r`（r=8 → alpha=16）。
- **target_modules**：注入哪些层——**最常见的错误来源**；transformer 架构一般注入 q/k/v/o_proj 四个投影层，模型卡/文档会写明模块名。
- **lora_dropout**：adapter 分支的 dropout，防过拟合，0.05-0.1。
- **task_type**：任务类型（SEQ_CLS/CAUSAL_LM/…），决定注入位置与输出头行为——**生成模型必须 CAUSAL_LM**。
- **bias**：是否训练偏置，默认 none（不训）。

**先背口诀再查表**：`r=8~16` 起步、`alpha=2r`、`target=q/k/v/o`、`dropout=0.1`、分类写 `SEQ_CLS` 生成写 `CAUSAL_LM`——**这个组合能跑通 90% 的入门场景**，其余参数（finetuning_type/init_lora_weights）遇到具体需求再翻 04 篇。

完整参数表见 04 篇——本节的六个是第一课必会的，其余按需查。

## 4. 加载 adapter 推理

```python
from peft import PeftModel
base = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-0.5B")
model = PeftModel.from_pretrained(base, "your-name/your-lora-adapter")  # 本地路径或 Hub 仓库
```

**推理侧对 PEFT 的全部需求就是这个 API**——底座 + adapter 两个输入：底座是冻结的 W，adapter 是训练产物 A、B。三种推理姿势（不合并直接跑 / merge_and_unload 合并 / unload 还原）在 03 与 07 篇详讲，**第一课记住：加载 = `PeftModel.from_pretrained`，无脑可用**。

**一个常见疑惑**：为什么加载时要再传一次底座？——adapter 只有增量，**加载必须"增量 + 底座"才能还原完整模型**（03 篇一致性铁律）；如果底座模型卡写的是"微调版"（如 Qwen2.5-0.5B-Instruct），**adapter 也必须是在这个微调版底座上训练的**——"Instruct 版"与"基础版"是两个不同的底座，混用必报错。

## 5. 快速调试三步

**第一步，验证注入**：`peft_model.print_trainable_parameters()`，可训练占比异常（0% 或 100%）先查 target_modules 拼写与 task_type。

**第二步，验证前向**：拿一个样本 `peft_model(**inputs)` 跑一次前向，**能前向 = 训练能跑**（90% 的训练错误都出在前向阶段）。

**第三步，小步训练**：`per_device_train_batch_size=1` + `max_steps=10` 跑 10 步看 loss 是否下降——**loss 不动先查学习率（LoRA 常用 1e-4~5e-4，比全量微调大 10 倍），loss 为 NaN 查 bf16 与梯度累积**。

**跑通的标志清单**：脚本无报错、trainable% 正常、loss 前 10 步下降、adapter 目录生成、加载回推理有任务效果——**五条全过才算入门**；其中任何一条不过，回到本节对应步骤逐项排查。

## 6. 完整闭环示例

```python
from transformers import AutoModelForCausalLM, AutoTokenizer, Trainer, TrainingArguments
from peft import LoraConfig, get_peft_model, PeftModel
from datasets import load_dataset

model = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-0.5B")
tokenizer = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-0.5B")
ds = load_dataset("tatsu-lab/alpaca", split="train[:200]")   # 任意指令数据

def fmt(x):
    return tokenizer(f"### 指令\n{x['instruction']}\n### 回答\n{x['output']}",
                     truncation=True, max_length=512, padding="max_length")
ds = ds.map(fmt, remove_columns=ds.column_names)

lora_config = LoraConfig(
    r=8, lora_alpha=16, target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
    lora_dropout=0.1, task_type="CAUSAL_LM",
)
peft_model = get_peft_model(model, lora_config)
peft_model.print_trainable_parameters()

trainer = Trainer(
    model=peft_model,
    args=TrainingArguments(
        output_dir="./chat-lora", per_device_train_batch_size=4,
        learning_rate=2e-4, num_train_epochs=1, bf16=True,
        save_strategy="epoch", logging_steps=5, save_only_model=True,
    ),
    train_dataset=ds, tokenizer=tokenizer,
)
trainer.train()
peft_model.save_pretrained("./chat-lora")          # 只存 adapter + adapter_config.json

# 闭环验证：加载回来推理
base = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-0.5B")
chat = PeftModel.from_pretrained(base, "./chat-lora")
chat.eval()
```

**注意 save_only_model=True 只存模型不存优化器**（adapter 场景默认就够）；tokenizer 用 `tokenizer.save_pretrained` 单独保存。整个闭环约 15 行：**"包装 → 训练 → 保存 → 加载"就是 PEFT 的全部日常**。

**CPU/无卡调试替代**：把 `bf16=True` 去掉、`per_device_train_batch_size=1`、模型换 0.5B，全程跑通后再上 GPU——**"先小后大"是训练工程的第一原则**：管线（数据格式/注入/保存加载）的错误在 CPU 上暴露成本最低，GPU 只留来跑量。

## 7. 八个常见坑

- **坑一**：transformers v5 + peft 0.17 混装——版本锁 `peft==0.19.1`（本节 1）。
- **坑二**：target_modules 拼写错（q_proj 写成 query_proj）——不报错但 trainable% = 0%，注入静默失败。
- **坑三**：生成模型 task_type 漏写或写错——影响注入位置，CausalLM 必须 CAUSAL_LM。
- **坑四**：可训练占比 100%——get_peft_model 后忘了用包装后的模型训练，拿底座直接训了。
- **坑五**：学习率照抄全量微调（5e-5）——LoRA 常用 1e-4~5e-4，太小收敛极慢。
- **坑六**：没有 tokenizer.pad_token 的模型报 pad 错——先 `tokenizer.pad_token = tokenizer.eos_token`。
- **坑七**：QLoRA 场景没装 bitsandbytes——加载 4bit 底座直接 ImportError（08 篇）。
- **坑八**：Windows 上 bf16 不支持——先查 GPU 能力（sm80+），老卡用 fp16 或 CPU 小模型调试。
- **坑九**：`uv pip install` 装进系统环境而不是虚拟环境——依赖污染导致版本冲突；**先 `uv venv` 建环境再装**。
- **坑十**：数据集字段名与代码不匹配（x['instruction'] 不存在）——**先 `print(ds[0])` 看字段再写 fmt 函数**。
- **坑十一**：Windows 下 from_pretrained 传反斜杠路径——**路径统一用正斜杠或 pathlib，跨平台可移植**。
