## 1. 方法分类主线

PEFT 方法按"训什么"分四族：**注入式**（在层旁加增量分支——LoRA 及其全家，2026 年绝对主流）；**重参数化**（把梯度/权重当成低秩结构处理——Galore-Plus 线）；**前缀式**（只训输入侧的虚拟 token——Prompt/Prefix Tuning）；**门控式**（按维度缩放激活值——IA3）。**2026 年的事实：LoRA 一族吃掉了 95% 的生产场景**，本体系以 LoRA 家族为主线（04 篇的 finetuning_type 就是它的目录），其余族了解定位即可。微调决策（要不要训、数据怎么做）看 `../../../../09-模型微调与多模态/02-LoRA微调原理与实战.md`——本系列只讲"方法选哪个、API 怎么写"。

## 2. LoRA：事实标准

**LoRA（Low-Rank Adaptation）**：在 W 旁挂低秩分支 A（r×d）、B（d×r），训练只更新 A、B，推理/合并时等效 `W' = W + (α/r)·BA`。**为什么它是事实标准**：其一，**效果经过两年大规模验证**——几乎所有开源指令模型（含 Llama 系、Qwen 系的大量微调版）都是 LoRA 产物；其二，**生态支持最全**——vLLM 动态加载、各种推理框架的 adapter 支持都优先 LoRA 格式；其三，**adapter 极小且可切换**——多 adapter 挂载、加权融合（09 篇 add_weighted_adapter）只有 LoRA 系做得到。**"不会 LoRA 就不会 PEFT"——它是其他所有方法的参考系**。

## 3. QLoRA：单卡微调标准答案

**QLoRA = 4bit 量化底座 + LoRA**：底座 W 用 bitsandbytes 以 4bit NF4 格式加载（双重量化 + 分页优化器 + 梯度 checkpointing 三件套），LoRA 分支保持 bf16 精度训练。**账本对比（70B 量级）**：全量微调需 42GB+ 显存、产出 140GB checkpoint；纯 LoRA 需 20GB 级（底座 fp16 全量驻留）；**QLoRA 压到 10GB 级别**——单卡 24GB 就能微调 70B。**代价**：训练速度慢 30-40%（量化反量化开销），极端精度略降。**2026 年单卡微调的标准姿势就是 QLoRA**，完整配置见 08 篇。

## 4. DoRA / rsLoRA / LoRA-XS：LoRA 的三个补丁

**DoRA（Weight-Decomposed LoRA）**：把增量拆成"幅度 + 方向"两部分分别学——**训练中幅度和方向的更新强度差异大，分开学更稳**。v0.18 优化后宣称 **0.8% 参数平齐全量微调精度**（Llama-4-8B 上比标准 LoRA 高约 2.3 分 MMLU-Pro）。代价：训练慢约 20%、显存略增。**追求精度的默认升级项**（finetuning_type="dora"）。

**rsLoRA**：把缩放从 α/r 改为 α/√r——**高秩（r>64）时标准缩放导致发散，rsLoRA 修复**。代价：低秩时无差别。**"r>64 就用它"是唯一触发条件**（finetuning_type="rslora"）。

**LoRA-XS**：对 A、B 再做一次 SVD 压缩初始化——**再省 15-20% 可训练参数**，精度几乎无损。**边缘设备/显存极限场景**的选项（finetuning_type="lora_xs"）。

**三个补丁的主线认知**：它们都改的是"增量怎么组织"，**API 只差一个 finetuning_type 字符串**——"学会 LoRA，全家族贯通"。

## 5. S-LoRA / SHiRA：稀疏化路线

**S-LoRA（Sparse-LoRA，v0.18）**：训练时用掩码只更新"最影响结果"的少数参数——**宣称收敛快约 1.4 倍**（Mistral-Pro-v2/Llama-4-70B 实测）；适合训练预算紧、数据量大的场景（finetuning_type="slora"）。

**SHiRA（v0.17）**：只训练 1-2% 的权重（稀疏选择 + 高秩内部结构）——**天然稀疏的 adapter，多 adapter 切换开销更低**；v0.17 引入时主打"多 adapter 概念丢失（concept loss）更小"。

**两者共同点**：稀疏化换速度/多适配器友好，**精度一般略逊标准 LoRA**——"追求极致训练效率时才考虑"。

## 6. Galore-Plus 与其他非 LoRA 方法

**Galore-Plus（v0.18）**：走"重参数化"路线——**把梯度本身当作低秩矩阵处理**，优化器状态只存低秩投影——**70B 级模型（Llama-4-70B）单卡 48GB（RTX 6000 Ada）可微调**，不用张量并行/offload。与 LoRA 系的区别：**它训的是真实权重更新而非旁路分支**，理论上限更高、适配器格式不同（不能享受 LoRA 的 vLLM 动态加载生态）——**"大模型单卡全量微调梦想的实现者，但生态工具链不如 LoRA"**。

**前缀式（Prompt/Prefix Tuning）**：冻结全部权重，只训虚拟 token——参数量最少，但 NLG 任务效果显著弱于 LoRA，**2026 年主要用于 embedding 级实验**；**门控式 IA3**：按维度缩放激活，参数量比 LoRA 还少一个量级，但效果不稳、生态支持少——**两者了解即可，生产默认 LoRA 系**。

## 7. 2026 新方法一览

v0.18-0.19 一年内新增的家族成员，**了解一句话定位即可**：**RoAd**（2D 旋转适配，未合并也能极速推理，且是唯一支持混合 batch 内多 adapter 的）；**ALoRA**（按 token 序列选择性激活 adapter，KV-cache 复用场景）；**Arrow/GenKnowSub**（多 LoRA 动态路由选择 + 用"通用知识 adapter"做减法提升任务效果）；**WaveFT**（小波域稀疏更新，图像生成友好）；**DeLoRA**（DoRA 的去发散改良，带 norm cap）；**BD-LoRA/ LoRA-GA/ PVeRA/ PSOFT**（v0.19 新成员，仍在生态观察期）。**认知主线：方法在快速迭代，但 API 形态已收敛——新方法都是进 finetuning_type 的一个新字符串，不会改变你的使用姿势**。

## 8. 选型决策

| 场景 | 选择 | 理由 |
|------|------|------|
| 默认/通用 | LoRA（r=16, α=32） | 生态最全、效果验证最充分 |
| 单卡微调大模型 | QLoRA（4bit + LoRA） | 显存 10GB 级可训 70B |
| 追精度/任务差异大 | DoRA | 0.8% 参数平齐全量精度 |
| r > 64 | rsLoRA | 防高秩发散 |
| 边缘设备/极限省参 | LoRA-XS | 再省 15-20% 参数 |
| 训练预算紧 | S-LoRA | 收敛快 1.4 倍 |
| 70B 级单卡全量式微调 | Galore-Plus | 48GB 单卡可训 |
| 多 adapter 高频切换 | LoRA/SHiRA | 切换生态最好 |

**主线一句话**：**"默认 LoRA；显存紧上 QLoRA；精度不足升 DoRA；r 大换 rsLoRA；其余方法都是特定约束下的备选"**。

## 9. 五个常见坑

- **坑一**：QLoRA 与 DoRA 叠加时显存反而高——DoRA 需要更多激活/额外状态，**量化场景先验证显存再叠加**。
- **坑二**：SLoRA/DoRA 等新方法在 0.17 及以下直接报错——**方法参数依赖版本，锁 0.19.1**。
- **坑三**：把 DoRA 当万能升级——小模型/小数据下 DoRA 收益有限且训练变慢，**先跑 LoRA 基线再决定升级**。
- **坑四**：rsLoRA 在 r=8 用无收益——**rsLoRA 只在高秩才有意义，低秩白白改名**。
- **坑五**：用 Galore-Plus 训练后想上 vLLM——**adapter 格式不兼容 LoRA 生态，部署时要合并或转 LoRA**（v0.19 的转换函数可救）。
