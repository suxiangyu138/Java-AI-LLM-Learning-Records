## 1. 实战一：加载 Hub 上的 adapter 推理

```python
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import PeftModel

# 步骤 1：读模型卡，锁定 Base Model（一致性铁律第一动作）
base_id = "Qwen/Qwen2.5-0.5B-Instruct"
adapter_id = "your-name/your-lora"        # 换成真实仓库

# 步骤 2：加载底座 + adapter
tokenizer = AutoTokenizer.from_pretrained(base_id, trust_remote_code=True)
base = AutoModelForCausalLM.from_pretrained(base_id, trust_remote_code=True)
model = PeftModel.from_pretrained(base, adapter_id)
model.eval()

# 步骤 3：按 chat 模板生成（与训练数据形态一致）
prompt = [{"role": "user", "content": "用一句话解释什么是 LoRA"}]
inputs = tokenizer.apply_chat_template(prompt, tokenize=True,
                                       add_generation_prompt=True,
                                       return_tensors="pt")
out = model.generate(inputs, max_new_tokens=128, do_sample=False)
print(tokenizer.decode(out[0], skip_special_tokens=True))
```

**验收三问**：① 加载无报错（KeyError 查底座一致性）；② 输出体现 adapter 能力（对比同 prompt 的纯底座输出）；③ 结果稳定（重复推理一致）。

**对比代码**（验收的核心证据）：

```python
base_out = base.generate(inputs, max_new_tokens=128)   # 纯底座
lora_out = model.generate(inputs, max_new_tokens=128)  # 挂 adapter
print("底座：", tokenizer.decode(base_out[0], skip_special_tokens=True))
print("adapter：", tokenizer.decode(lora_out[0], skip_special_tokens=True))
```

**adapter 能力 = 两份输出的差异**——差异清晰说明注入生效；无差异先查 active_adapter 与 eval() 态。

## 2. 实战二：QLoRA 微调小模型

```python
from transformers import (AutoModelForCausalLM, AutoTokenizer, Trainer,
                          TrainingArguments, BitsAndBytesConfig)
from peft import LoraConfig, get_peft_model
from datasets import load_dataset

base_id = "Qwen/Qwen2.5-0.5B"
tokenizer = AutoTokenizer.from_pretrained(base_id, padding_side="right")
tokenizer.pad_token = tokenizer.eos_token

model = AutoModelForCausalLM.from_pretrained(base_id,
    quantization_config=BitsAndBytesConfig(
        load_in_4bit=True, bnb_4bit_quant_type="nf4",
        bnb_4bit_compute_dtype="bf16", bnb_4bit_use_double_quant=True),
    device_map="auto")
model = get_peft_model(model, LoraConfig(
    r=16, lora_alpha=32, target_modules=["q_proj","k_proj","v_proj","o_proj"],
    lora_dropout=0.1))
model.print_trainable_parameters()          # 预期 0.1%-1%

ds = load_dataset("databricks/databricks-dolly-15k", split="train[:300]")
def fmt(x):
    msgs = [{"role":"user","content":x["instruction"]},
            {"role":"assistant","content":x["response"]}]
    return tokenizer.apply_chat_template(msgs, tokenize=True,
                                         truncation=True, max_length=512)
ds = ds.map(lambda x: {"input_ids": fmt(x)}, remove_columns=ds.column_names)

trainer = Trainer(model=model, args=TrainingArguments(
    output_dir="./qlora-out", per_device_train_batch_size=1,
    gradient_accumulation_steps=8, learning_rate=2e-4, num_train_epochs=1,
    bf16=True, gradient_checkpointing=True, save_strategy="epoch",
    save_only_model=True, logging_steps=10), train_dataset=ds)
trainer.train()
model.save_pretrained("./qlora-out")
tokenizer.save_pretrained("./qlora-out")
```

**验收三问**：① `print_trainable_parameters` 占比正常（0.1%-1%）；② loss 下降（先 10 步冒烟）；③ adapter 加载回推理有任务效果（抽样对比）。

## 3. 实战三：合并部署与验收

```python
from peft import PeftModel
from transformers import AutoModelForCausalLM

base = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-0.5B-Instruct")
model = PeftModel.from_pretrained(base, "./qlora-out")
merged = model.merge_and_unload()                 # 焊死
merged.save_pretrained("./deploy/final")          # 普通模型，任意框架可加载
# 验收：vLLM / transformers 直接加载，输出与 adapter 模式一致
```

**验收三问**：① 合并后模型可被普通 `from_pretrained` 加载（不依赖 peft）；② 输出与未合并模式一致（对比同 prompt）；③ 推理耗时记录（合并后应无额外开销）。

**合并后的体积账**：7B 底座 fp16 ≈ 14GB（合并后保存的是完整模型）；**adapter 只有 15MB 左右**——"存储换兼容"是合并部署的显性成本；多任务生产场景算总账后常选 vLLM 动态加载（07 篇）——**"合并是兼容性最短路径，动态加载是资源最省路径"**。

## 4. 生产纪律清单

- **锁版本**：`peft==0.19.1` + transformers v5 兼容线，需求文件锁死；
- **一致性先行**：任何 adapter 接入前核对 Base Model/版本/量化配置；
- **验收三问**：加载无错 → 能力生效 → 结果稳定，三段实战各做一遍；
- **先冒烟后全量**：batch=1 + 10 步验证管线，再上全量训练；
- **留档**：评估基线、版本号、训练配置随产物发布；
- **回滚预案**：合并前备份 adapter 目录；动态加载场景旧版本随时可切。

**三层定位方法论**：先查环境（版本/依赖）→ 再查代码（API 拼写/参数）→ 最后查数据（格式/字段）——**报错速查表按这个顺序读**：环境类错误（ImportError/版本）占一半，代码类（KeyError/尺寸）占四成，数据类占一成。

## 5. 报错速查十条

| 报错 | 原因 | 修复 |
|------|------|------|
| KeyError: 'base_model.model...' 缺某层 | target_modules 与模型层名不匹配 / 底座型号不一致 | 打印 named_modules 核对；核对 Base Model |
| size mismatch for lora_A... | adapter 与底座维度不符（型号/版本不一致） | 换正确底座；版本对齐 |
| ImportError: cannot import name 'BitsAndBytesConfig' | bitsandbytes 未装/版本过低 | `pip install bitsandbytes`（≥0.46.1） |
| ValueError: finetuning_type ... unknown | peft < 0.18 | 升级到 0.19.1 |
| RuntimeError: CUDA out of memory | 显存不足 | batch=1 + grad_acc + checkpointing；上 QLoRA |
| ModuleNotFoundError: peft not found | 部署环境缺 PEFT | 合并部署（merge_and_unload）零依赖 |
| TypeError: merge_and_unload() got unexpected kwarg | 老 API 传参 | 按 0.19 签名重写（merge_and_unload() 无参） |
| bf16 not supported on this device | 老 GPU 无 bf16 | 换 fp16；或 CPU 小模型调试 |
| ValueError: Input length exceeds max_length | 数据超长 | 截断/降 max_length；检查 padding |
| adapter_config.json missing | 加载的不是 adapter 目录 | 确认目录含 config + safetensors；或走全量加载 |

## 6. 面试三范式

**范式一：价值式**——"我负责的微调项目里，全量微调显存不够，改用 QLoRA 后单卡 24GB 训 7B，adapter 几十 MB 随发随载，底座升级只需重训 adapter"——**用账本数字讲价值**（显存/存储/迭代周期三个维度）。

**范式二：API 式**——"PEFT 的核心是 LoraConfig → get_peft_model → Trainer → save_pretrained 四步；v0.18 起 finetuning_type 统一方法开关；加载推理就是 PeftModel.from_pretrained 一个 API"——**展示 API 熟练度与版本意识**。

**范式三：生产式**——"生产上单任务合并部署、多任务 vLLM 动态加载；adapter 按'任务-版本'命名、效果基线留档、底座升级先验证再切流"——**展示资产管理与运维思维**。

**追问四连防身**：①"LoRA 为什么有效？"——低秩假设：模型更新的有效自由度远小于参数总量，W' = W + α/r·BA；②"QLoRA 怎么省显存？"——NF4 量化 + 双重量化 + 分页优化器 + LoRA 只算可训练参数；③"r 怎么选？"——8-64 主流，容量看 r、强度看 α/r，高秩配 rsLoRA；④"adapter 挂了为什么报错？"——一致性铁律：型号/版本/量化/依赖四维匹配。

**追问第五连**："adapter 部署后底座升级怎么办？"——先回归验证（一致性铁律）→ 不兼容则重训 adapter → **底座升级与 adapter 升级是两条独立的发布线，必须分别管控**（09 篇审计）。

## 7. 简历呈现

**项目写法示例**："基于 QLoRA 微调 7B 对话模型（PEFT 0.19 + transformers v5 + bitsandbytes）：LoraConfig 注入 q/k/v/o 四投影（r=16, α=32），4bit NF4 单卡微调，可训练参数仅 0.5%；产出 15MB adapter 并发布 HuggingFace Hub，服务端 merge_and_unload 合并部署，响应达标；多任务场景验证 vLLM LoRA 动态加载实现 adapter 即时切换"——**要点：版本精确、账本数字、产物形态、部署路径四要素齐备**。
