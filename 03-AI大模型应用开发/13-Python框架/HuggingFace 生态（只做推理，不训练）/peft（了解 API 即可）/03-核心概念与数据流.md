## 1. 六个核心动作

PEFT 的全部 API 可以收敛成六个动作：**冻结**（get_peft_model 时底座参数 `requires_grad=False`）；**注入**（在 target_modules 指出的层旁插入 LoRA 分支 A、B）；**训练**（只更新 A、B）；**保存**（save_pretrained 只存 A、B + adapter_config.json）；**加载**（PeftModel.from_pretrained 把 A、B 挂回新底座）；**合并**（merge_and_unload 把 A、B 写回 W 并拆掉分支）。理解这六个动作的时间顺序，就是理解 adapter 的生命周期：**底座永远不变，变化的是"挂不挂 adapter、挂几个、挂完是否焊死"**。

## 2. 包装模型：PeftModel 是什么

`get_peft_model(base, config)` 返回的不是新模型，而是一个**包装对象**：它持有底座的引用，把 target_modules 命中的层替换成"带 LoRA 分支的层"（如 `peft.tuners.lora.layer.Linear`）。三个事实值得记住：

**其一，前向兼容**——包装后模型接受同样的输入、输出同样的格式，`model(**inputs)` 用法不变，所以 Trainer 无感接入；**其二，状态分离**——`peft_model.state_dict()` 默认只含可训练参数（A、B），底座参数不参与序列化——这是 adapter 只有几十 MB 的根源；**其三，嵌套透明**——`peft_model.base_model` 还是原模型，需要原始行为时可以直接操作。**"包装"是 PEFT 的架构核心词：不复制模型、不修改原权重，只在旁路挂增量**。

**包装的机制细节**（了解级）：`get_peft_model` 内部遍历 `model.named_modules()`，把 target_modules 命中的层实例替换成 LoRA 层包装（原层被包成 `base_layer`）；冻结通过 `requires_grad_(False)` 实现，**Trainer 构造优化器时只看 `requires_grad=True` 的参数**——这就是"优化器状态只按可训练参数算"的机制来源（06 篇显存账本）；前向时 LoRA 层先算 `base_layer(x)` 再叠加 `(α/r)·BA(x)`。**三个结论**：替换发生在内存里（原权重指针未动）、冻结是动态的（`enable_adapters()/disable_adapters()` 可开关）、包装对外的接口不变（TaskType 决定 PeftModel 子类）。

## 3. 保存与加载：adapter 的文件结构

```text
lora-ckpt/
├── adapter_config.json   # LoraConfig 序列化：r/alpha/target_modules/…
├── adapter_model.safetensors  # A、B 权重（几十 KB ~ 几十 MB）
└── （可选的 trainer_state.json 等训练信息）
```

保存用 `peft_model.save_pretrained("./lora-ckpt")`，加载用 `PeftModel.from_pretrained(base, "./lora-ckpt")`——**adapter_config.json 是关键**：加载时 PEFT 读它重建注入结构（哪些层、多大秩），**如果它记录的 target_modules 与当前底座的层名对不上，直接报错**（KeyError），这就是"一致性铁律"的第一个表现。加载后 `model.active_adapter` 可以查看当前生效的 adapter 名（默认 "default"）。

**保存格式细节**：默认 `.safetensors`（v0.16+ 默认，安全格式防恶意 pickle）；老教程的 `pytorch_model.bin` 仍可兼容加载但**新保存不再产生 bin**。**adapter_config.json 的三个关键字段**：`base_model_name_or_path`（底座声明——加载端一致性检查的依据）、`target_modules`（注入结构）、`finetuning_type`（方法类型，v0.18+）——**这三个字段共同决定"这个 adapter 能挂到哪个模型上"**，也是 07 篇一致性铁律的配置来源。

## 4. 合并与卸载：merge_and_unload / unload

```python
# 姿势一：不合并直接推理（adapter 保持可切换状态）
model = PeftModel.from_pretrained(base, "./lora-ckpt")
out = model.generate(**inputs)          # 推理时逐层做 W = W + (α/r)·BA 的等效计算

# 姿势二：合并进底座，得到"纯底座 + 效果"（部署最常用）
merged = model.merge_and_unload()       # A、B 写回 W，卸载 PEFT 包装
merged.save_pretrained("./merged-model")  # 这就是一个普通 transformers 模型

# 姿势三：拆下 adapter，还原纯净底座
clean = model.unload()
```

三个姿势对应三种场景：**不合并**——要在多个 adapter 间切换、或底座还要继续挂别的 adapter；**合并**——部署时最简路径：合并后模型就是普通 transformers 模型，vLLM/推理服务零感知加载；**卸载**——调试"adapter 到底贡献了什么"（同一输入对比合并前后输出）。**记住 merge_and_unload 的 unload 语义：不是丢弃 adapter，而是把 PEFT 外壳拆掉**——合并是不可逆操作，想保留 adapter 先备份原文件。

## 5. 多 adapter 与命名

一个底座可以挂多个 adapter——**加载时命名**：

```python
model = PeftModel.from_pretrained(base, "./lora-ckpt", adapter_name="legal")
model.load_adapter("./code-lora", adapter_name="code")   # 再挂一个
model.set_adapter("code")          # 切换生效的 adapter
model.active_adapter               # 查看当前
model.disable_adapter()            # 全部停用 = 用纯净底座推理
```

**多 adapter 是 PEFT 相对全量微调的核心竞争力**：同一个底座，几十个 adapter 按需切换，显存只占一份底座 + 一份激活的 adapter；vLLM 的 LoRA 动态加载把这套能力带进了生产服务（07/09 篇）。**注意 set_adapter 只切生效适配器，不卸载不合并**——切换是 O(1) 的。

## 6. 完整数据流

```text
底座 W（冻结）──get_peft_model──> PeftModel（W + A/B 分支）
     │                                  │ Trainer 训练（只更新 A/B）
     │                                  ▼
     │                            adapter 文件（A/B + config，几十 MB）
     │                                  │ PeftModel.from_pretrained
     │                                  ▼
     └──────────── 新底座 W ──── PeftModel（挂载 A/B，可直接推理）
                                      │ merge_and_unload
                                      ▼
                              合并模型（W' = W + α/r·BA，普通模型）
```

**三个关键认知**：其一，**adapter 与底座分离存储**——分发 adapter 必须同时声明底座型号（"这份 adapter 是 Qwen2.5-0.5B 的"）；其二，**合并后模型不可再挂同结构 adapter**（W' 已含一份增量，再挂就是叠两次）；其三，**训练与推理用的是同一套加载机制**——训练时 save_pretrained 出的目录，推理时 from_pretrained 原样加载，**"保存即分发"**。

**训练态与推理态的差异**（一个常被忽略的细节）：PEFT 模型在 `train()` 模式下 LoRA 分支启用 dropout 并累积梯度；`eval()` 模式下 dropout 关闭——**加载 adapter 做推理必须 `model.eval()`**（07 篇坑四）；此外 `disable_adapter()` 在训练中也可用——**"冻结 adapter 只训底座"的反向实验**，是做"adapter 贡献多少"对照组的利器。

## 7. 五个常见坑

- **坑一**：merge_and_unload 后直接拿结果继续 `load_adapter`——合并后的模型结构已变，加载同结构 adapter 会报错；**合并且想保留 adapter，先复制原目录**。
- **坑二**：`PeftModel.from_pretrained` 的底座型号与训练时不符——KeyError/尺寸不匹配，**adapter 与底座是一一对应关系**。
- **坑三**：多 adapter 场景忘了 `set_adapter`——`active_adapter` 仍是 default，切了个寂寞；**切换后必须验证 active_adapter**。
- **坑四**：想省显存却忘了 disable_adapter 后梯度仍计算——**纯推理记得 `model.eval()` + `torch.no_grad()`**。
- **坑五**：save_pretrained 只存了 adapter 没存 tokenizer——**部署端重新 from_pretrained 底座时 tokenizer 缺失；训练完顺手 `tokenizer.save_pretrained`**。
- **坑六**：把保存目录名当 adapter 名用——**目录名只是路径，adapter_name 才是逻辑名**；from_pretrained 加载时默认 adapter_name 是 "default"，多 adapter 场景要显式命名（09 篇）。

> 🎯 **核心要点**：PEFT 心智模型 = **"底座冻结 + 旁路注入"**——训练只更新 A/B，保存只存 A/B，加载只挂 A/B，合并才写回 W；**adapter 与底座分离存储、一一对应——这是理解全部 API 与全部坑的钥匙**。
