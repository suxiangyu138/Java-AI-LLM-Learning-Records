## 1. generate 与自回归循环

生成不是一次前向，而是**自回归循环**：每步只预测下一个 token，把预测结果拼回输入再预测下一个——直到命中停止条件。`generate()` 把这个循环封装成一个调用，内部管理 KV cache（每步增量计算，不重复算历史）、停止判断、多序列（beam/采样多路）。

```python
out = model.generate(
    inputs,
    max_new_tokens=200,
    do_sample=True, temperature=0.7, top_p=0.9,
)
```

理解自回归，三个现象就有了解释：**生成长度线性影响时间**（每 token 一次前向，200 token ≈ 200 步）；**KV cache 决定速度**（增量计算 vs 全量重算，差一个数量级）；**停止条件必须有兜底**（不设上限的生成可能无限循环）。

## 2. 长度控制

| 参数 | 语义 | 说明 |
|------|------|------|
| `max_new_tokens` | 新生成 token 上限 | **v5 起优先**，推荐主用 |
| `max_length` | 输入+生成总长 | 混用时报优先级警告 |
| `min_new_tokens` | 最少生成量 | 防「模型秒停」 |
| `stop_strings` | 字符串停止符 | 命中即停（5.x 支持） |

**v5 的关键变化**：`max_new_tokens` 与 `max_length` 同时传入时，**前者优先**并抛警告——老代码里的 `max_length=200` 语义是「总长 200」，prompt 稍长生成预算就归零，这是「模型什么都不输出」的经典原因。生产统一用 `max_new_tokens` + `stop_strings`（如终止符 `"<|im_end|>"`、`"---"`）：前者兜底上限，后者提前截断，两者结合输出干净。

## 3. 采样策略

**贪心（默认，`do_sample=False`）**：每步选概率最高的 token。确定、快，但重复、单调、无法跳出局部——适合事实性回答与代码生成。

**采样（`do_sample=True`）**：按概率分布随机抽取，配合温度与 top 截断。温度 `temperature` 缩放概率分布：低（0.1-0.3）趋近贪心（确定性任务），高（1.0+）更随机（创意任务）；`top_p` 只保留累积概率达阈值的最小集合（0.9 常用）；`top_k` 只保留前 k 个候选。**三者不是并列选项，而是叠加的过滤器**：概率分布 → top_k 截断 → top_p 截断 → 温度缩放 → 抽样。

**Beam search（`num_beams>1`）**：保留 top-N 条候选路径逐步扩展，整体最优但计算量 N 倍，且长序列质量并不总好——翻译/摘要传统任务适用，生成式对话已基本退出（LLM 采样+温度已够好）。

选型口诀：**事实/代码 → 贪心或低温度采样；创意/对话 → temperature 0.7 + top_p 0.9；多候选 → num_return_sequences**。

## 4. 重复与多样性控制

**停止条件的完整语义**：生成在满足任一条件时停止——**eos token 命中**（模型自主认为回答完成，最常用）、**`stop_strings` 命中**（业务定义的终止符，如 `"<|im_end|>"` 或分隔线）、**`max_new_tokens` 到达**（兜底，防止无限生成）。三层按「先自然停、再业务停、最后硬顶」的优先级协作：正常回答靠 eos 自然结束；格式类任务（JSON 输出、代码块结束）靠 stop_strings 提前截断，输出干净；max_new_tokens 是最后防线。**别只用 max_new_tokens**——模型可能输出完答案后继续废话直到撞上上限，浪费 token 且污染输出。

**`repetition_penalty`**：对已生成 token 的惩罚系数，1.0 不惩罚，1.1-1.2 明显抑制复读。**`no_repeat_ngram_size`**：禁止任何 n-gram 重复出现（如 3 表示任意 3 连 token 不重复）。两者对比：前者全局温和（推荐），后者强硬但可能打断合理重复（如引用）。

```python
out = model.generate(inputs, max_new_tokens=200,
                     repetition_penalty=1.1, no_repeat_ngram_size=0)
```

复读的三层防线：**先查 prompt 问题**（prompt 本身诱导复读，调参无效）→ 再调 repetition_penalty（1.05 起步，每次 +0.05 测试）→ 最后 no_repeat_ngram_size。注意惩罚过重会降低事实性——「抑制重复」与「保持真实」是跷跷板。

## 5. 流式生成

大模型输出动辄数百 token，全量等待用户体验差——流式生成边出边显示。transformers 提供两个现成 streamer：

```python
# 终端流式（调试/CLI）
from transformers import TextStreamer
streamer = TextStreamer(tokenizer, skip_prompt=True, skip_special_tokens=True)
out = model.generate(inputs, max_new_tokens=200, streamer=streamer)

# 程序化流式（Web/API：异步环境）
from transformers import TextIteratorStreamer
from threading import Thread
streamer = TextIteratorStreamer(tokenizer, skip_prompt=True, skip_special_tokens=True)
thread = Thread(target=model.generate, kwargs={"inputs": inputs, "max_new_tokens": 200, "streamer": streamer})
thread.start()
for chunk in streamer:
    print(chunk, end="")          # 每块即输出，可 yield 给 SSE/WebSocket
```

**`TextIteratorStreamer` 必须配线程**：generate 是阻塞调用，不另起线程则没有线程去消费 streamer，死锁。Web 场景的标准组合：线程跑 generate + streamer 喂给 FastAPI 的 SSE 流（配合 [[../../../01-Python语言/Python%20异步%20+%20FastAPI/00-Python异步与FastAPI总览|Python 异步 + FastAPI]] 体系）——这是 LLM Web 应用的骨架。

## 6. 可复现性

采样是有随机性的，实验复现需要固定随机源：

```python
import torch
torch.manual_seed(42)
out = model.generate(inputs, do_sample=True, temperature=0.7, top_p=0.9)
```

`torch.manual_seed` 固定 CPU/GPU 的随机数生成器；注意**贪心模式无需 seed**（无随机）。完整复现还需要固定环境（CUDA 确定性模式 `torch.use_deterministic_algorithms(True)` 有性能代价，实验用）。生产不用复现（每次输出可不同），但**评测、对比实验、回归测试必须固定 seed**——否则两次跑同一个 prompt 输出不同，无法判断是改代码导致的还是随机噪声。

**参数分组的管理习惯**：生成参数（temperature、top_p、max_new_tokens、stop_strings）属于「业务配置」而非「代码」——生产用配置对象统一管理：`model.generation_config` 里设默认值（模型仓库自带），请求级参数覆盖默认，`GenerationConfig` 可以序列化保存/加载。多场景（摘要、对话、代码）各自一套参数组，切换即换配置，而不是在代码里散落魔法数字——这是「生成参数工程化」的标准姿势，也是评测对比实验的基础（同一配置跑多次取均值）。

## 7. 五个坑

**坑一：`max_length` 当新生成量用**。prompt 长则预算归零——v5 用 `max_new_tokens`。

**坑二：`temperature` 设了但 `do_sample` 没开**。temperature 只在采样模式生效，贪心模式静默忽略——参数「设了没生效」的经典案例。

**坑三：beam search 忘记调 `num_beams` 配套**。`num_beams=5` 但 `do_sample=True` 互斥语义混淆——beam 是确定性搜索，采样是随机抽样，两者不要混用。

**坑四：流式生成忘起线程**。TextIteratorStreamer 死锁——线程 + streamer 成对出现。

**坑五：停止条件只有 max_new_tokens**。模型可能提前输出完整答案后继续胡扯——配合 `stop_strings`/eos 提前截断。

**坑六：`num_return_sequences` 与 beam 混配**。多候选输出（`num_return_sequences>1`）与 beam search 的候选数耦合（beam 数 ≤ 候选数）；采样模式下直接配——语义清晰，别把 beam 参数当采样参数配。
