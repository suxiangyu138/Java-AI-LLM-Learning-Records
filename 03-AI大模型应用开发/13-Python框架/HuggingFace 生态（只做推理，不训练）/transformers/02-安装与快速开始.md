## 1. 环境链与版本锁定

transformers 的依赖链是三层：**Python（≥3.10）→ PyTorch（2.x）→ transformers（5.13.1）**，其中 torch 是真正的重量级依赖——它自带 CUDA 运行时，决定你的模型跑在 GPU 还是 CPU。环境事故九成出在这条链上，且事故症状往往在「模型加载时报错」，根因却在「torch 装错了版本」。

版本纪律两条：**transformers 必须锁版本**（月级迭代，行为差异频出）；**torch 版本与 CUDA 驱动匹配**（不是越新越好，是匹配才好）。推荐组合：torch 2.7+（2026 稳定线）+ transformers==5.13.1 + CUDA 12.x 驱动。

## 2. 安装步骤

**第一步，独立虚拟环境**（别装系统 Python，污染环境排查无底洞）：

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
```

**第二步，装 GPU 版 torch**（关键：官方默认源是 CPU 版，GPU 版必须走 CUDA 索引）：

```bash
pip install torch --index-url https://download.pytorch.org/whl/cu128
```

**第三步，锁版本装 transformers**，按需带 extras：

```bash
pip install "transformers==5.13.1" accelerate sentencepiece
# 推理相关 extras：accelerate（device_map 多卡/offload 必需）
#                   sentencepiece（部分模型分词必需）
#                   bitsandbytes（4bit/8bit 量化）
#                   transformers[serving]（serve 服务化，见 09 篇）
```

`accelerate` 几乎必装：`device_map="auto"`、多卡分发、CPU offload 都靠它，裸 transformers 的显存治理能力减半。

**完整环境搭建流程（一次到位）**：

```bash
# 1. 建环境
python -m venv .venv && source .venv/bin/activate
# 2. GPU torch（NVIDIA 卡，CUDA 12.x 驱动）
pip install torch --index-url https://download.pytorch.org/whl/cu128
# 3. 验证 GPU 就绪
python -c "import torch; print(torch.cuda.is_available())"   # 必须 True
# 4. 装 transformers 全家（锁版本）
pip install "transformers==5.13.1" accelerate sentencepiece bitsandbytes
# 5. 验证
python -c "import transformers; print(transformers.__version__)"
```

这个流程里唯一需要「想一下」的是第二步的 `cu128`——它对应 CUDA 12.8 运行时，匹配主流 NVIDIA 驱动（驱动 525+ 即可）。无 GPU 的机器跳过第二步，torch 默认装 CPU 版，推理全走 CPU（08 篇 CPU 优化）。**把「验证」写进流程**是环境搭建的第一纪律：装一步验一步，错了立刻定位在哪一层，而不是全装完再猜。

## 3. CUDA 验证

装完先验证再写代码，三行命令排除环境问题：

```bash
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
# 期望: 2.x.x+cu128 True
nvidia-smi                          # 驱动与 GPU 信息
python -c "import transformers; print(transformers.__version__)"   # 5.13.1
```

`torch.cuda.is_available()` 返回 False 的三种原因：装成了 CPU 版 torch（重装 cu128 索引版）、驱动太老（升级驱动）、CUDA 运行库缺失（torch 自带运行库，此情况少见）。**模型「没跑在 GPU 上」的最常见原因就是 torch 是 CPU 版**——代码没错，环境错了。

## 4. 第一个推理：pipeline

pipeline 是 transformers 最快上手的推理入口：一个函数串起「加载模型→分词→推理→解码→后处理」全流程，适合验证模型能不能用：

```python
from transformers import pipeline

gen = pipeline("text-generation", model="Qwen/Qwen2.5-0.5B-Instruct")
out = gen("今天天气", max_new_tokens=50)
print(out[0]["generated_text"])
```

首次运行会自动从 Hub 下载模型（约 1GB 级），之后走本地缓存。`device` 参数控制设备：`pipeline(..., device=0)` 用 GPU，`device=-1` 强制 CPU。**验证用 0.5B 级小模型**，几分钟内跑通全流程；直接上 7B 会把「环境没配好」和「显存不够」混在一起，排查难度翻倍。

## 5. 第一个完整推理：Auto 家族

pipeline 之外的标准姿势是 Auto 家族三段式——也是生产代码的骨架（pipeline 隐藏了太多控制项，生产要自己掌控）：

```python
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM

model_id = "Qwen/Qwen2.5-0.5B-Instruct"
tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(
    model_id,
    torch_dtype=torch.bfloat16,      # 半精度，显存减半
    device_map="auto",               # 自动放 GPU（accelerate 提供）
)
inputs = tokenizer.apply_chat_template(
    [{"role": "user", "content": "用一句话介绍 transformers"}],
    tokenize=True, return_tensors="pt", add_generation_prompt=True,
).to(model.device)
out = model.generate(inputs, max_new_tokens=100)
print(tokenizer.decode(out[0][inputs.shape[1]:], skip_special_tokens=True))
```

五个要点记牢：**模型类选 `AutoModelForCausalLM`**（通用 AutoModel 没有生成能力）；**tokenizer 与模型配对**（同仓库 ID）；**聊天必须走 `apply_chat_template`**（04 篇详解）；**`torch_dtype=bf16` + `device_map="auto"` 是 7B+ 模型标准加载姿势**；**解码时截掉输入部分**（`[inputs.shape[1]:]`）只输出新生成的 token。

**两种姿势的分工**：pipeline 是「验证器」——确认模型能用、流程能通，代码最短，但加载参数、采样控制、流式输出全部受限；Auto 家族是「生产骨架」——每一环自己掌控，从加载精度到停止条件到流式线程，也是理解 transformers 内部机制的唯一途径。学习路径建议：**先 pipeline 跑通建立信心，再用 Auto 家族重写一遍理解全流程**——两个都要会，因为调试时你需要 pipeline 快速定位「是不是模型问题」，上线时你需要 Auto 家族掌控每一个参数。

## 6. 网络与镜像

模型在 HuggingFace Hub，国内网络访问不稳定——镜像配置是必做项而非可选项：

```python
# 必须在 import transformers 之前设置环境变量
import os
os.environ["HF_ENDPOINT"] = "https://hf-mirror.com"
```

或用命令行 `export HF_ENDPOINT=https://hf-mirror.com`。大模型下载用 `huggingface_hub` 的 `hf_hub_download`/`snapshot_download` 更稳（支持断点续传）。**离线环境**：有网机器上 `snapshot_download` 拉全仓库，拷到离线机，设 `HF_HUB_OFFLINE=1` 后 `from_pretrained` 走本地缓存——生产内网部署的标准流程（03 篇详述）。

## 7. 八个新手坑

**坑一：torch 装了 CPU 版**。`torch.cuda.is_available()` 为 False 的第一原因，重装 cu128 索引版。

**坑九：镜像站点误当成官方源**。`pip install transformers` 没问题（PyPI 有官方包），只有 torch 的 GPU 版必须走 pytorch.org 索引——国内镜像里的 torch 多为 CPU 版，装完无声无息地慢。

**坑十：venv 与系统 Python 混用**。`python` 指向系统解释器而 pip 装在 venv——先 `which python` 确认，再装再验。

**坑十一：pip 与 python 版本不匹配**。`pip install` 装到另一个 Python 的解释器路径——用 `python -m pip` 保证与当前解释器一致；装完立刻 `python -c "import transformers"` 复核版本号与路径归属。

**坑二：版本号没锁**。pip 装到最新 transformers 与教程（写于旧版）行为不符——锁 `==5.13.1`。

**坑三：缺 `sentencepiece`/`protobuf`**。部分模型（Llama 系、多语种）分词依赖它，报错信息隐晦（`AttributeError: module 'tokenizers'`）——装 extras 全量。

**坑四：没装 accelerate 却用 device_map**。`device_map="auto"` 直接报错——`pip install accelerate`。

**坑五：显存不足先怪模型**。7B bf16 需要约 14GB 显存，OOM 先算账（06 篇显存公式）再谈优化。

**坑六：网络报 `ConnectionError`/下载卡死**。设 `HF_ENDPOINT` 镜像 + `HF_HUB_DOWNLOAD_TIMEOUT` 调大。

**坑七：Windows 上 tokenizers 编译报错**。老版本常见；5.x 提供预编译 wheel，先升级 pip 再装。

**坑八：`trust_remote_code` 警告**。新架构模型（社区仓）常要求 `trust_remote_code=True`——只对可信仓库开，这是远程代码执行入口。

**版本与文档的配套意识**：transformers 的在线文档按版本切片（`docs/transformers/v5.13.1/` 独立成档）——查 API 时先确认文档版本与本地版本一致，5.x 的 API 细节与 4.x 已大量不同（如 4.x 的 `max_length` 语义、`use_fast` 参数在 5.x 已取消）。收藏官方文档时把版本号带进 URL；模型卡（Hub 上的 usage 示例）同样标注版本——**「看最新文档」与「用锁定的版本」之间的偏差，是代码与文档对不上的头号来源**。
