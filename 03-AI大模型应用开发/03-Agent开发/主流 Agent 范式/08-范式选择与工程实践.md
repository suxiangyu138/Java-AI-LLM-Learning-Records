## 1. 范式选择决策树

### 1.1 完整决策树

```text
范式选择（从简单到复杂）：

① 流程在设计时可知吗？
   ├── 是 → 工作流（02 模块五种模式）→ 结束
   └── 否 → 继续

② 步骤能预先枚举吗？
   ├── 是（6+ 步可预测）→ Plan-and-Execute（04）
   └── 否 → 继续

③ 任务长度？
   ├── <5 步 → ReAct（03）
   └── 长任务 → 混合（有界 ReAct/重规划）

④ 有验证信号吗？
   ├── 是 → 加反思（Reflexion/Self-Refine，05）
   └── 否 → 不加（自我确认风险）

⑤ 需要隔离/并行/外部视角吗？
   ├── 是 → 多 Agent（07）
   └── 否 → 单 Agent

⑥ 模型足够强吗？
   ├── 是 → Model-Native（06，简化循环）
   └── 否 → 外部显式循环（03-05 增强）
```

### 1.2 关键判断问题

| 问题 | 指向 |
|------|------|
| 能预先写清单吗？ | 能 → PnE；不能 → ReAct |
| 有 pass/fail 信号吗？ | 有 → 反思/评估器 |
| 需要可审计计划吗？ | 是 → 显式 PnE/Orchestrator |
| 单 Agent 够吗？ | 先试单 Agent（强模型） |
| 模型够强吗？ | 不强 → 外部增强 |

```text
选择原则（贯穿全目录）：
  ① 简单优先（停在满足需求的最简层级）
  ② 工作流优先（确定性 > 自主）
  ③ 单 Agent 优先（少即是多）
  ④ 验证器优先（外部信号 > 自我感觉）

2025-2026 的现实：
  多数任务 → 工作流（02）
  Agent 任务 → 模型原生（06）
  显式范式 → 特殊需求（审计/控制）
```

## 2. 安全护栏

### 2.1 护栏清单（Anthropic 推荐）

```text
Agent 护栏（必配）：
  ① 步骤上限（max_steps：防死循环）
  ② 成本预算（token/调用上限）
  ③ 工具 Schema（严格定义，防幻觉）
  ④ 上下文管理（裁剪/总结，防膨胀）
  ⑤ 人工检查点（关键决策/高风险操作）
  ⑥ 日志审计（每步轨迹）

护栏的层次：
  框架级（预算/上限）
  工具级（Schema/权限）
  内容级（输出过滤/合规）
```

### 2.2 工具级护栏

```text
工具设计即安全（Anthropic 经验）：
  ① Schema 精确（参数类型/必需项）
  ② 描述清晰（何时用/何时不用）
  ③ 权限最小（只暴露必要操作）
  ④ 沙箱（危险操作隔离）

示例：
  代码执行工具 → 沙箱容器
  数据库工具 → 只读/限定表
  外部 API → 白名单/限流

2025-2026 实践：
  工具幻觉（模型虚构工具/参数）是主要风险
  → Schema 校验 + 白名单
```

### 2.3 人工检查点

```text
HITL（Human-in-the-Loop）：
  何时插入人工确认：
    ① 不可逆操作（删除/支付/发布）
    ② 高风险决策（安全/合规）
    ③ 结果不确定（需要人类判断）

实现：
  框架暂停 → 人类确认/修改 → 继续
  或：Agent 标记"需确认"节点

权衡：
  检查点多 → 安全但慢
  检查点少 → 快但风险高
  → 按操作风险分级
```

## 3. 成本控制

### 3.1 成本构成

```text
Agent 的成本构成：
  ① Token：输入（上下文）+ 输出（推理/回答）
  ② 调用次数：步数 × 每步调用
  ③ 模型级别：强模型单价高
  ④ 重试/反思：额外轮次

成本驱动因素：
  上下文增长（scratchpad/历史）
  步数（循环长度）
  模型选择（分级）

实测参考（检索共识）：
  10 步 ReAct ≈ 5 步的 2-3 倍 token
  反思范式 ≈ 基础 Agent 的 2 倍
  多 Agent ≈ 单 Agent 的 N 倍（Agent 数）
```

### 3.2 成本优化手段

| 手段 | 效果 | 说明 |
|------|------|------|
| 模型分级 | 30-70% | 简单任务用小模型（Routing） |
| 上下文压缩 | 显著 | 历史总结/裁剪 |
| 步数控制 | 线性 | 预算 + 提前退出 |
| 计划先行 | 3-5 倍 | PnE（长任务） |
| 提示缓存 | 30-50% | 系统提示缓存（Anthropic） |
| 并行控制 | 线性 | 限制并行 Agent 数 |

```text
成本控制框架：
  ① 预算先行（任务前设定上限）
  ② 分级模型（按步骤复杂度）
  ③ 上下文精简（最小必要信息）
  ④ 提前终止（满足即停）

2025-2026 实践：
  提示缓存成为标配（长系统提示）
  模型路由（简单请求 → 小模型）
  → 成本优化是工程化的核心维度
```

## 4. 可观测性与评估

### 4.1 可观测性

```text
Agent 可观测性（生产必需）：
  ① 轨迹记录：每步 Thought/Action/Observation
  ② 成本追踪：token/调用/模型
  ③ 性能指标：成功率/步数/延迟
  ④ 失败日志：错误/异常/重试

实现：
  OpenTelemetry 兼容追踪（2026 标准）
  框架内置（LangGraph/LangSmith 等）
  自研（日志结构化）

六层架构（2026）：
  模型核心/记忆/工具/规划器/运行时/可观测性
  → 可观测性是第六层（生产关键）
```

### 4.2 评估体系

```text
Agent 评估（不止于单次回答）：
  ① 任务成功率（端到端）
  ② 步骤质量（中间步骤正确性）
  ③ 效率（步数/成本）
  ④ 鲁棒性（输入变化/边界情况）
  ⑤ 安全性（越权/有害行为）

评估方法：
  基准集（领域任务 + 标准答案）
  回归测试（迭代防退化）
  人工抽检（质量校准）
  在线指标（生产监控）

2025-2026 实践：
  Agent 评估框架成熟（LangSmith/自研）
  "评估先行"成为 Agent 开发流程
  → 无评估的 Agent 开发 = 盲飞
```

### 4.3 迭代优化循环

```text
Agent 优化循环：
  评估发现问题 → 定位（轨迹分析）
  → 修复（提示/工具/范式）
  → 回归验证 → 部署 → 监控

优化对象：
  提示（任务定义/边界）
  工具（Schema/描述）
  范式（工作流 → 更复杂）
  模型（升级/分级）

关键指标：
  成功率趋势（版本对比）
  成本趋势（优化 ROI）
  P99 延迟（用户体验）
```

## 5. 生产化清单

### 5.1 部署前检查

```text
Agent 生产化检查清单：
  ① 范式选择（决策树过一遍）
  ② 护栏（步骤/成本/人工点）
  ③ 工具 Schema（精确/白名单）
  ④ 可观测性（轨迹/成本/指标）
  ⑤ 评估集（任务/回归）
  ⑥ 降级路径（Agent 失败 → 人工/规则）
  ⑦ 合规（数据/审计）
  ⑧ 成本预算（上限/告警）
```

### 5.2 降级与容错

```text
Agent 的降级设计：
  ① Agent 失败 → 重试（有限次）
  ② 重试失败 → 简化范式（Agent → 工作流）
  ③ 仍失败 → 人工介入（工单/告警）
  ④ 兜底 → 规则/默认答案

容错原则：
  Agent 是"增强"不是"唯一路径"
  → 保留非 Agent 的兜底

2025-2026 实践：
  "受约束的领域专用 Agent + 清晰边界"
  + 人工兜底 = 生产模式
```

### 5.3 演进路线

```text
Agent 项目的演进：
  阶段 1：工作流验证（确定性 MVP）
  阶段 2：加 Agent 能力（动态部分）
  阶段 3：模型升级（强推理模型）
  阶段 4：范式调优（按评估迭代）
  阶段 5：规模扩展（并行/多租户）

原则：
  每个阶段都有评估（数据驱动升级）
  保持简单（不过度设计）
  → 渐进式 Agent 化
```

## 6. 常见失败模式

### 6.1 失败模式清单

| 失败模式 | 表现 | 对策 |
|---------|------|------|
| 循环死锁 | 重复同一行动 | 步骤预算/退出条件 |
| 工具幻觉 | 虚构工具/参数 | Schema 校验/白名单 |
| 上下文膨胀 | 成本飙升/质量下降 | 压缩/总结 |
| 漂移 | 长任务偏离目标 | PnE/检查点 |
| 自我确认 | 反思无效 | 外部验证器 |
| 错误传播 | 前步错误放大 | 每步验证 |
| 过度委派 | 多 Agent 协调崩溃 | 单 Agent 优先 |
| 预算超支 | 成本失控 | 预算先行/告警 |

### 6.2 调试方法论

```text
Agent 调试三步：
  ① 轨迹分析（哪步开始错）
  ② 单步重放（隔离验证）
  ③ 修复验证（回归）

定位工具：
  轨迹查看（Thought/Observation）
  成本分析（哪步最贵）
  对比实验（A/B 提示/工具）

常见误区：
  只测成功路径（边界/失败路径更重要）
  忽视中间步骤（只看最终结果）
  → 步骤级评估（4.2 节）
```

### 6.3 成功模式总结

```text
成功 Agent 的共同特征（2025-2026）：
  ① 简单循环（模型原生/最简外部）
  ② 强模型（能力第一变量）
  ③ 好工具（Schema 设计投入）
  ④ 严格护栏（预算/检查点）
  ⑤ 完整观测（轨迹/成本/评估）
  ⑥ 渐进演进（工作流 → Agent）

"克制"是 Agent 工程的第一美德：
  少 Agent、少步骤、少自由
  → 每增加一个自由度都需理由
```

> 🎯 **核心要点**：Agent 落地 = 决策树选范式（工作流→PnE→ReAct→反思→多 Agent→Model-Native）+ 护栏（预算/工具 Schema/人工点）+ 成本控制（分级/压缩/缓存）+ 可观测评估（轨迹/指标/回归）。失败模式八类（循环/幻觉/膨胀/漂移/确认/传播/过度委派/超支）都有对应对策；成功的关键是"克制"——简单循环 + 强模型 + 好工具 + 严格护栏。

| 评估？ | 任务成功率/步骤质量/效率/鲁棒性 |
| 头号失败？ | 循环死锁与工具幻觉（预算 + Schema） |
