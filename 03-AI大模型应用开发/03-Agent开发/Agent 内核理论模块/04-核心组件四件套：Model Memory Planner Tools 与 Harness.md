## 1. 四件套 + 一个连接件

```text
        ┌─────────────────────────────────────┐
        │           Harness（控制器/运行时）      │
        │  连接四件套 + 决定何时停止              │
        │                                     │
        │  ┌──────┐  ┌────────┐  ┌─────────┐  │
        │  │ Model │  │ Planner │  │  Tools   │  │
        │  │ 决策者 │◀▶│ 规划层   │▶│ 行动层   │  │
        │  └──────┘  └────────┘  └─────────┘  │
        │        ▲                            │
        │  ┌─────┴─────┐                      │
        │  │  Memory    │                      │
        │  │  状态层     │                      │
        │  └───────────┘                      │
        └─────────────────────────────────────┘
```

| 组件 | 角色 | 缺失后果 |
|------|------|---------|
| Model | 基于当前状态推理并选下一步 | 无决策者 |
| Planner | 把大目标拆成有序步骤（可内置于模型） | 长任务无路径 |
| Tools | 模型之外的行动（DB/API/代码/搜索） | 只能空谈 |
| Memory | 保存进度与结果（做了啥/返回啥/剩啥） | 每步从零开始 |
| **Harness** | 连接组件成循环、调用模型、执行工具、**决定停止** | 组件散沙 |

> 🎯 **一句话**：模型是大脑，工具是手脚，记忆是病历，规划是路线图——**Harness 是躯体**（把一切连起来并决定何时停下来）。

## 2. Model：决策者

| 维度 | 说明 |
|------|------|
| 职责 | 推理当前状态，决定下一步（如"订单状态需要查库"） |
| 决策载体 | 文本回答 / tool_calls / 结构化输出 |
| 2026 演进 | 原生推理通道（thinking）；推理深度可调（off→xhigh） |
| 选型注意 | 强模型更贵但更少循环次数——总成本 = 轮数 × 每轮成本 |

> 💡 **成本权衡**：强模型（少轮数×高单价）vs 弱模型（多轮数×低单价）——用真实任务测总成本，不是只看单次调用价。

## 3. Planner：规划层

| 形态 | 说明 | 适合 |
|------|------|------|
| 内置于模型 | 模型能力强时，规划即推理的一部分 | 强模型、短任务 |
| 独立层 | 显式分解大目标为有序步骤 | 长任务、可审计需求 |
| 动态重规划 | 计划执行中失败时重新规划（Plan-Execute-Replan） | 长程任务 |

```text
Planner 的存在性判断：
任务可一步规划完（研究→写作）     → 内置规划足够
任务需逐步反馈修正（长程操作）     → 独立/动态规划层
任务路径完全未知                 → Agent 循环本身承担规划
```

> 💡 **2026 趋势**：模型能力增强 → 规划越来越多"内置于模型"；显式规划层向"重规划"与"可审计"场景收缩（09 篇模型原生转向详述）。

## 4. Tools：行动层

| 维度 | 说明 |
|------|------|
| 类型 | 数据库查询、API 调用、代码执行、搜索、文件操作 |
| 声明 | JSON Schema（名称/描述/参数） |
| 注册 | 工具注册表：schema 进 → 执行 → 结果字符串出 |
| 2026 标准 | MCP 服务器统一接入（"universal adapter"） |
| 规模化 | 工具多时语义发现（向量索引注册表，按语义检索工具） |

> ⚠️ **工具设计铁律**：描述决定调用率（描述不清 = 模型不调）；参数少而清晰；**幂等**（重试安全）——工具设计的细节见[四大核心组件模块](../Agent%20四大核心组件/)。

## 5. Memory：状态层

| 层级 | 内容 | 实现 |
|------|------|------|
| Scratchpad（草稿） | 当前任务/会话上下文 | 消息缓冲 |
| Working（工作） | 任务内跨步骤状态 | 状态对象/变量 |
| Episodic（情节） | 交互历史 | 向量库按会话检索 |
| Long-term（长期） | 持久事实/规则 | 数据库/文件 |

（记忆架构深潜见 05 篇）

## 6. Harness/Controller：连接与终止

| 职责 | 2026 生产实现 |
|------|--------------|
| 状态持久化 | 每模型调用后保存状态 |
| 上下文管理 | 防溢出（压缩/摘要） |
| 任务清单 | todo provider |
| 模式追踪 | plan/execute 双模式 |
| 会话笔记 | 持久会话笔记（file memory） |
| 技能加载 | 渐进式技能加载 |
| 工具审批 | 敏感操作审批门 |
| 追踪 | OpenTelemetry 追踪 |
| **终止** | 轮次/时间/花费上限（03 篇） |

> 🎯 **Harness 的 2026 定位**：护栏（工具授权/速率限制/步数预算/验证实际行为）成为**独立学科**——从"LLM 输入输出过滤"进化为"工具执行层治理"（08 篇详述）。

## 7. 组件边界与 2026 演进

| 组件 | 2024 状态 | 2026 演进 |
|------|----------|----------|
| Model | 决策靠提示词工程 | 原生推理、测试时计算 |
| Planner | 外部框架循环 | 内置于模型 |
| Tools | 自定义 schema | MCP 标准化 + 语义发现 |
| Memory | 简单上下文 | 层级记忆 + 压缩工程 |
| Harness | 薄包装 | 生产运行时（治理内建） |

> 💡 **演进主线**：智能从"外部脚手架"向"模型原生"迁移（规划/推理内化），而 Harness 从"薄包装"向"生产运行时"增厚（治理/持久化/可观测）——**两头收敛：模型更聪明，运行时更可靠**。

## 8. 核心要点

> 🎯 **核心要点**：
> 1. 四件套 + 连接件：Model（决策）/ Planner（规划）/ Tools（行动）/ Memory（状态）/ **Harness（连接 + 终止）**
> 2. Planner 三形态：内置（强模型短任务）/ 独立（可审计长任务）/ 动态重规划（长程修正）
> 3. Tools 2026：MCP 标准化 + 语义发现；描述决定调用率
> 4. Harness 从薄包装 → 生产运行时：状态/压缩/审批/追踪/终止成为标配
> 5. 2026 演进主线：智能向模型原生迁移，运行时向生产级增厚——两头收敛
