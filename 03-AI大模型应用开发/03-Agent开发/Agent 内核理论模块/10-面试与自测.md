## 1. 面试题（10 题带答案范式）

> 内核理论是 Agent 面试的**必考底层**——高频题集中在：定义、循环、终止、记忆、范式与"要不要用 Agent"。

### Q1：什么是 AI Agent？和 Workflow 的区别？

**答案范式（定义 + 判定测试）**：
```text
定义：Agent = 处在循环中的 LLM + 工具 + 记忆，由模型决定下一步
判定测试：下一步由谁决定？
  模型基于观察决定 → Agent；代码硬编码 → Workflow
例子：退款分诊（按观察分支）= Agent；
      检索→生成→摘要（线性链）= Workflow
Anthropic 判据：能预映射决策树就做 Workflow——
  更准、更可控、更便宜
```

### Q2：Agent 循环怎么转？五要素是什么？

**答案范式（五阶段 + 五要素）**：
```text
五阶段：Reason（模型决策）→ Act（发工具调用）→ Execute（执行）
        → Observe（结果回填）→ Repeat/Stop
五要素（缺一即聊天机器人）：增长的消息缓冲 / 工具注册表 /
  停止条件 / 轮次预算 / 观察格式化
铁律：含 tool_calls 的 assistant 消息先于工具结果；
      错误必须是观察不是崩溃
证据：~100 行最小实现即达 SWE-bench 74-76.8%——循环是承重概念
```

### Q3：怎么防止 Agent 无限循环？

**答案范式（终止防御纵深）**：
```text
四类停止：模型信号（end_turn/空 tool_calls）/ max_turns /
          每工具失败上限 / 护栏
max_turns 基线：客服 8-12、通用 15-25、研究 20-30
early-stopping 模式：到上限后追加"基于已有工作给出最佳答案"，
                     无工具再合成一次——防静默失败
防御纵深：6 层重叠（模型信号/轮次/工具失败/token 预算/超时/护栏）
停滞检测：GoalProgress 平线、重复工具调用 = 卡死信号
```

### Q4：Agent 的记忆架构是什么？

**答案范式（四层 + 压缩）**：
```text
四层：Scratchpad（会话缓冲）/ Working（任务状态）/
      Episodic（跨会话向量）/ Long-term（持久精确）
核心论断：多数 Agent 失败源于缺压缩而非缺向量——
  压缩三招：摘要旧轮次 / 丢弃无用结果 / 截断长内容
"会话内学习"真相 = 检索不是权重更新——想记住必须显式写记忆层
召回纪律：只注入相关片段；写入纪律：只存决策结论 + 剪枝
```

### Q5：ReAct 是什么？什么时候不该用？

**答案范式（范式 + 三种跳过）**：
```text
ReAct = Reason + Act 交替（Yao et al. ICLR 2023）——
一切现代 Agent 的变体：thought → action → observation → thought
不该用的三种情况：单次确定性调用（Direct tool-call 足够）、
  已知计划的流程（PnE/DAG）、延迟敏感语音 Agent
2026 默认组合：Native reasoning（thinking 通道）+ ReAct
```

### Q6：Anthropic 的 Task / Workflow / Agent 三分法？

**答案范式（三层 + 四条件）**：
```text
Task = 单次模型调用；Workflow = 预定义控制流多次调用；
Agent = 模型工具循环自主轨迹
系统设计第一决策：需求属于哪层——90% 生产需求是 Task/Workflow
用 Agent 四条件（缺一不用）：任务模糊无法预映射 / 价值覆盖 token /
  瓶颈能力扎实（错误循环累积）/ 错误成本可控
2025 生产之战 Workflow 赢了；企业多 Agent 失败率 41-86.7%
```

### Q7：Agent 为什么贵？成本怎么控？

**答案范式（成本结构 + 控制）**：
```text
贵的原因：探索（试错路径）+ 每轮全量上下文 + 多轮循环
控制：① max_turns/花费预算（硬上限）
     ② 上下文最小化（压缩/渐进式技能加载——可省 ~98.7% token）
     ③ 模型分层（强模型决策 + 廉模型执行）
     ④ early-stopping（到上限合成一次，不白烧）
     ⑤ 范式选型（能 Direct tool-call 不 ReAct，能 PnE 不探索）
```

### Q8：什么是原生推理？对 Agent 工程有什么影响？

**答案范式（native reasoning + 影响）**：
```text
原生推理：模型生成隐藏推理 token（thinking 独立通道），
  Prompt 式 "Let's think step by step" 成历史
通道分离：thinking（内部）/ text（用户）/ toolCall（动作）；深度可调
影响：① 每轮循环更聪明但更贵 ② 循环结构不变 ③ 外部
  分步思考脚手架冗余化 ④ 框架角色转向路由/状态/环境执行
```

### Q9：Memory 和上下文窗口什么关系？为什么压缩 > 向量？

**答案范式（窗口是绑定约束）**：
```text
上下文窗口 = 最重要的受限资源（Anthropic：context engineering
  is the binding constraint）
循环内每步依赖完整上下文——窗口满无压缩 = 失忆/报错
向量检索解决"跨会话"，压缩解决"会话内生存"
→ 多数失败源于缺压缩（会话内），不是缺向量（跨会话）
实践：80% 阈值触发摘要；旧轮次摘要/丢弃/截断
```

### Q10：2026 年 Agent 智能的理论转向是什么？

**答案范式（模型原生 + 工程不变）**：
```text
转向：从"外部编排工作流应用智能"到"模型原生开发智能"
  （LLM + RL + Task；test-time compute 内化；in-the-flow 循环内优化）
工程不变：循环结构 / 终止工程（更贵轮次 → max_turns 更重要）/
  记忆压缩 / 工具层 / 评估（思考轨迹可评：ReasoningQuality 等）
一句话：理论变了，工程原理不贬值——框架从模拟认知转向管环境
```

### 自测答案速查

1. 循环中的 LLM + 工具 + 记忆，模型决定下一步
2. 下一步是模型基于观察决定（Agent）还是代码硬编码（Workflow）
3. Reason → Act → Execute → Observe → Repeat/Stop
4. 退化为聊天机器人；消息缓冲/工具注册表/停止条件/轮次预算/观察格式化
5. 通用 15-25；客服 8-12；研究 20-30
6. 到上限后无工具再调用一次合成最佳答案（防静默失败）
7. Scratchpad / Working / Episodic / Long-term
8. 缺压缩（missing compaction），而非缺向量嵌入
9. 单次确定性调用 / 已知计划流程 / 延迟敏感场景
10. PER 执行中失败重规划；PnE 一次规划不修正
11. 高（反思轮次 × 重试轮次）——质量换成本
12. 规划与执行分离：省往返调用、并行执行、规划可审计
13. 显式分支成本指数级——用原生推理隐式多分支替代
14. 编排者-工人（Orchestrator-Workers）
15. 状态持久化/上下文压缩/任务清单/渐进技能加载/工具审批/追踪/终止
16. 大工具集全载爆上下文（100+ 工具 = 窗口大半）
17. 工具执行层（授权/速率/预算/行为验证），非输出层内容过滤
18. thinking（内部）/ text（用户可见）/ toolCall（动作）
19. 模型原生生成隐藏推理 token、内部分支探索与自纠正
20. 可观测（89%）vs 评估 evals（52%）——评估是生产缺口

## 4. 核心要点

> 🎯 **核心要点**：
> 1. 面试必考底层：**定义（判定测试）→ 循环（五阶段五要素）→ 终止（防御纵深）→ 记忆（四层+压缩）**
> 2. 设计判断是加分项：三分法 + 四条件 + "能预映射就 Workflow"——体现工程成熟度
> 3. 前沿认知要会说：native reasoning / test-time compute / 框架角色转向——但强调"工程原理不贬值"
> 4. 本模块毕业标准：**能徒手讲清 Agent 的底层机制（定义/循环/终止/记忆/范式），并能回答"什么时候该用 Agent、怎么防失控、怎么控成本"——这是所有上层模块的基石**
