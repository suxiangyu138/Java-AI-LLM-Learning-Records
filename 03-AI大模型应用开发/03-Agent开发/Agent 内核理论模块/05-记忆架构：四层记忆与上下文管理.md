## 1. 记忆四层架构

```text
┌─────────────────────────────────────────────────┐
│  Long-term（长期）   持久事实/规则/语气准则         │
│  ── 跨 Agent 共享，数据库/文件存储                  │
├─────────────────────────────────────────────────┤
│  Episodic（情节）    交互历史（向量库，按会话检索）   │
│  ── 跨会话，如按客户 ID 检索                       │
├─────────────────────────────────────────────────┤
│  Working（工作）     任务内跨步骤状态               │
│  ── 状态对象：做了啥/返回啥/剩啥                    │
├─────────────────────────────────────────────────┤
│  Scratchpad（草稿）  当前任务/会话上下文            │
│  ── 消息缓冲                                         │
└─────────────────────────────────────────────────┘
```

| 层级 | 生命周期 | 容量 | 实现 |
|------|:---:|:---:|------|
| Scratchpad | 单会话 | 上下文窗口 | 消息缓冲 |
| Working | 单任务 | 小（结构化） | 状态对象 |
| Episodic | 跨会话 | 大 | 向量库检索 |
| Long-term | 持久 | 大 | 数据库/文件 |

> 🎯 **一句话**：记忆 = 分层的时间线——越靠下越持久、越靠上越快——循环内用 Scratchpad/Working，跨会话用 Episodic/Long-term。

## 2. Scratchpad 与 Working：循环内状态

| 层 | 内容 | 管理要点 |
|----|------|---------|
| Scratchpad | 完整消息历史（user/assistant/tool 轮次） | **压缩/摘要**（见第 4 节） |
| Working | 结构化任务状态（已完成步骤/结果/剩余） | 显式状态对象，供规划与路由读取 |

```text
Working 状态的典型字段：
{ goal, completed_steps: [...], results: {...}, remaining: [...], next_action }
→ 每轮循环更新，供模型与 Harness 读取
```

## 3. Episodic 与 Long-term：跨会话记忆

| 层 | 存储 | 检索 | 典型用途 |
|----|------|------|---------|
| Episodic | 向量库（Embedding 历史） | 相似度召回 | "上次这个客户说过什么" |
| Long-term | 数据库/文件 | 精确查询 | 用户偏好、公司规则、语气准则 |

> ⚠️ **召回纪律**：跨会话检索只注入**与当前任务相关**的片段——全量注入 = 噪声污染（与低代码模块"记忆不是存越多越好"同源原则）。

## 4. 上下文管理：压缩是核心

> **2026 最重要的记忆论断**："**most agent failures trace to missing compaction, not missing embeddings**"——多数 Agent 失败源于缺少压缩，而非缺少向量嵌入。

```text
上下文管理的三招：
① 摘要（Summarize）  旧轮次 → 摘要段落（信息损失可控）
② 丢弃（Drop）      已无用的工具结果/中间推理
③ 压缩（Compress）  冗余内容精简（代码/长文）
→ 目标：窗口内的都是"当前决策需要的信息"
```

| 实践 | 说明 |
|------|------|
| 按会话持久化消息 | 每条对话按 session 主键保存（可恢复/回放） |
| 旧轮次摘要 | 超窗口部分转摘要（保留结论弃过程） |
| 工具结果截断 | 长结果截断/摘要（02 篇观察格式化） |
| 触发时机 | 消息达到窗口比例（如 80%）即触发 |

> 💡 **为什么压缩 > 向量**：循环内每一步都依赖完整上下文——窗口满了却无压缩机制，Agent 会"失忆"或报错；向量检索解决的是跨会话，压缩解决的是**会话内生存**。

## 5. "会话内学习"的真相

| 认知 | 真相 |
|------|------|
| 表面 | Agent 在会话中"学会"了新东西 |
| 机制 | **是检索不是权重更新**——从记忆检索回放，模型权重未变 |
| 含义 | Agent 循环无法改变底层模型（除非训练循环） |
| 推论 | "学习"的质量 = 记忆写入/检索的质量，不是模型变聪明 |

> ⚠️ **设计含义**：想让 Agent "记住"什么，必须**显式写入记忆层**（Episodic/Long-term），不能指望循环自动沉淀——这也是"技能结晶"类机制（新兴 SDK 模块）的价值所在。

## 6. 2026 记忆实践基线

| 实践 | 说明 |
|------|------|
| 会话持久化 | 消息按会话存储（Redis/Postgres），支持恢复 |
| 摘要触发 | 窗口 80% 阈值触发旧轮次摘要 |
| 跨会话检索 | Episodic 向量检索 + Long-term 精确查询 |
| 记忆写入策略 | 只写决策性结论（任务结果/偏好），不写原始对话 |
| 剪枝 | 定期清理过期/低价值记忆 |
| 新基准 | Context-Bench（记忆管理评估）——2026 新基准之一 |

## 7. 记忆设计检查清单

```text
□ 循环内：Scratchpad 有压缩机制（摘要/丢弃/截断）？
□ Working 状态显式且结构化（供规划/路由读取）？
□ 跨会话：Episodic（向量）与 Long-term（精确）分层？
□ 召回过滤：只注入相关片段，防噪声？
□ 写入策略：只存决策性结论，有审计？
□ 剪枝：过期/低价值清理机制？
□ 幂等：记忆写入可重放无副作用？
```

## 8. 核心要点

> 🎯 **核心要点**：
> 1. 记忆四层：Scratchpad（会话）/ Working（任务）/ Episodic（跨会话向量）/ Long-term（持久精确）
> 2. **压缩 > 向量**：多数 Agent 失败源于缺压缩；摘要/丢弃/截断三招保会话内生存
> 3. "会话内学习" = 检索非权重更新——想记住必须显式写记忆层
> 4. 召回纪律：只注相关片段；写入纪律：只存决策结论 + 剪枝 + 审计
