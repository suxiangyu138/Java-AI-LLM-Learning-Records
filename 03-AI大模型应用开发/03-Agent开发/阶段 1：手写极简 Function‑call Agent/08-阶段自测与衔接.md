## 1. 20 道自测题

### 1.1 概念题（每题 30 秒）

1. 模型执行工具吗？谁真正执行？
2. `tool_calls` 返回时，`message.content` 通常是什么？
3. `function.arguments` 是对象还是字符串？为什么？
4. `finish_reason == "tool_calls"` 代表什么？
5. `tool_choice` 有哪四种取值？各自场景？
6. 工具结果回传用哪个字段关联到调用？能自己拼这个值吗？
7. assistant 消息不追加会怎样？
8. DeepSeek thinking 模式多轮调用时，哪个字段必须一起回传？
9. 并行 tool_calls 执行时要注意什么？
10. strict 模式的代价是什么？

### 1.2 代码题（每题 3 分钟）

11. 写出"无工具调用 → 返回回答"的终止判断代码。
12. 写出解析 arguments 并防御坏 JSON 的代码。
13. 注册表长什么样？加一个新工具要改几处？
14. 工具抛异常时，正确做法是什么？给出一行回传格式。
15. 流式拼装 tool_calls 时按什么键分桶？arguments 怎么累积？
16. 指数退避重试的等待时间公式是什么？
17. 为什么写类工具不能盲目重试？
18. 写出 validate_args 的核心思路（不写完整代码，说清三步）。

### 1.3 诊断题（每题 5 分钟）

19. 多轮工具调用后报 400，最可能的原因是什么？怎么排查？
20. 模型反复调用同一个工具不停，怎么处理？

## 2. 自测题答案要点

| # | 要点 |
|:---:|------|
| 1 | 模型只返回"调用意图"，执行永远在你的代码里 |
| 2 | `null`（模型直接调工具，不解释） |
| 3 | 字符串（JSON 编码的文本），必须 `json.loads` |
| 4 | 模型本轮要调工具（不是最终回答） |
| 5 | auto / required / none / 指定工具名 |
| 6 | `tool_call_id`；绝不能拼，必须原样 |
| 7 | 400 报错或协议断裂（tool 消息找不到对应调用） |
| 8 | `reasoning_content`（整体追加 msg 即可） |
| 9 | 结果按 id 一一配对；有状态工具串行 |
| 10 | 参数必须全 required、拒绝复杂 schema（anyOf 等） |
| 11 | `if not msg.tool_calls: return msg.content` |
| 12 | `json.loads` 包 try/except，失败返回 `{}` |
| 13 | 写函数 + 注册一行 + schema 一行；循环零改动 |
| 14 | 错误转 JSON 回传：`{"error": "..."}`，让模型降级 |
| 15 | 按 `tc.index` 分桶；arguments 用 `+=` 累积 |
| 16 | `wait = 2 ** attempt`（可加抖动） |
| 17 | 非幂等操作重试会重复副作用（重复下单） |
| 18 | 白名单只传签名参数 → 必填检查 → 类型断言 |
| 19 | 消息追加违规（assistant 丢失/顺序错）→ 打印追加历史 |
| 20 | 轮数上限兜底 + 检查工具结果是否"可推进" |

**评分标准**：概念题 9/10 + 代码题 6/8 + 诊断题 2/2 = 毕业；否则回头复习对应篇目。

## 3. 报错速查表

| 报错 | 根因 | 定位 |
|------|------|------|
| `BadRequestError: ...` | 消息格式违规 | 03 篇第 3 节（追加铁律） |
| `... tool_call_id ... not found` | id 被改/缺失 | 03 篇第 3 节 |
| `Invalid JSON` 解析失败 | arguments 坏 JSON | 03 篇第 4 节（防御） |
| `429 RateLimitError` | 限流 | 06 篇第 1 节（退避） |
| `APITimeoutError` | 超时过短 | 06 篇第 2 节 |
| 400（thinking 开启后） | reasoning_content 未回传 | 04 篇第 6 节 |
| 模型不调工具 | description 质量差 | 02 篇第 4 节 |
| 工具参数总错 | schema 与函数不同源 | 07 篇第 2 节 |
| 流式后工具调用坏 | 拼接覆盖而非累积 | 06 篇第 5 节 |
| 多轮后上下文爆炸 | 无压缩/无上限 | 阶段 4 + 失败模式 05/06 篇 |

## 5. 通往阶段 2：原生 OpenAI-style Function-call

### 5.1 你已掌握的（本阶段成果）

```text
✅ 协议层：tools 声明 → tool_calls → tool 消息回传
✅ 循环层：终止条件、轮数兜底、消息铁律
✅ 执行层：注册表、参数校验、错误回传
✅ 健壮层：退避重试、超时、幂等、流式拼接
```

### 5.2 阶段 2 要学的（原生能力的边界）

| 能力 | 为什么阶段 1 没做 | 阶段 2 的价值 |
|------|-----------------|--------------|
| 并行调用工程化 | 手写版串行 | 多工具并行执行 + 延迟优化 |
| Structured Output / strict 深度 | 只用 strict 开关 | 结构化输出与工具调用的正确组合 |
| JSON Mode / 提取模式 | 未涉及 | 非工具场景的结构化输出 |
| 流式 + 工具 + 并行全组合 | 只做基础流式 | 生产级流式体验 |
| SDK 高级参数 | 只碰基础 | 温度/频率惩罚/seed 等全参数 |
| Responses API（新路线） | 未涉及 | 2026 新接口形态对比 |

### 5.3 建议复盘方式

```text
把 04 篇的循环代码重新默写一遍（不查资料）→ 对照找差距
把"消息追加铁律"讲给 AI 听（费曼学习法）→ 讲不通的地方就是盲区
跑一遍验收脚本（07 篇第 4 节）→ 确认四验收仍通过
```

> 🎯 **核心要点**：阶段 1 的毕业标准不是"代码能跑"，而是**"协议烂熟于心、坑都踩过、能独立排错"**。带着这个心智模型进入阶段 2——届时你会惊讶于框架帮你做了多少事，也知道那些封装背后是什么。
