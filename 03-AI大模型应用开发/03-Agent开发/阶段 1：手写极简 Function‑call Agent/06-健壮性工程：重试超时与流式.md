## 1. 重试策略：指数退避

API 请求失败的三大原因：限流（429）、瞬时网络错误、服务端 5xx。**指数退避**是最标准的处理：

```python
import time
from openai import OpenAI, APIError, APITimeoutError, RateLimitError

def create_with_retry(client, max_retries=3, **kwargs):
    """带指数退避的请求封装：429/5xx/超时自动重试"""
    for attempt in range(max_retries):
        try:
            return client.chat.completions.create(**kwargs)
        except (RateLimitError, APITimeoutError, APIError) as e:
            if attempt == max_retries - 1:
                raise   # 最后一次失败直接抛
            wait = 2 ** attempt           # 0.5s → 1s → 2s（可加抖动）
            print(f"[重试] 第 {attempt + 1} 次失败: {e}，{wait}s 后重试")
            time.sleep(wait)
    raise RuntimeError("重试耗尽")  # 理论不可达
```

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| 重试次数 | 2-3 | 超过即放弃，避免长时间挂起 |
| 退避基数 | 2^n 秒 | 指数增长，可加 ±20% 抖动（防同步风暴） |
| 尊重 Retry-After | 优先读取响应头 | 429 响应自带建议等待时长 |

> 💡 更省事的方案：SDK 自带 `max_retries` 参数（OpenAI SDK 1.x 默认重试 2 次）——手写版是为了理解机制，生产直接用 SDK 参数。

## 2. 超时管理

| 超时类型 | 推荐值 | 原因 |
|---------|--------|------|
| 连接超时 | 10s | 网络层不通快速失败 |
| 读取超时 | 60s+（thinking 模式 120s+） | 复杂推理/思考模式耗时长 |
| 总超时 | 单轮 180s 上限 | 防整轮挂死 |

```python
client = OpenAI(
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    base_url="https://api.deepseek.com",
    timeout=60.0,          # SDK 统一超时
)
# 或单请求覆盖：
response = client.chat.completions.create(..., timeout=120.0)
```

> ⚠️ **常见误区**：超时设置过短（5s）→ thinking 模式频繁超时 → 触发重试 → 成本翻倍。**超时要按最慢的合法场景配置**。

## 3. 重试的幂等性

**幂等**：同一操作重试多次，结果一致。

| 操作 | 幂等性 | 重试策略 |
|------|--------|---------|
| 读类工具（查天气、读文件） | 幂等 | 放心重试 |
| 写类工具（发消息、下单） | 非幂等 | **绝不盲目重试**——可能重复下单！ |

```text
❌ 危险：工具执行失败 → 直接重试同一操作（写工具可能重复执行）
✅ 正确：读工具重试；写工具先"查询是否已成功"再决定
✅ 或：为写操作生成幂等键（idempotency key），服务端去重
```

> 🎯 **核心要点**：重试的对象是"请求"而不是"操作"。请求可以重试，副作用操作必须幂等——这是阶段 4 生产化的前置纪律。

## 4. 流式响应：基础

流式（`stream=True`）让模型输出逐 token 到达——**首 token 更快、体验更好**。非工具调用场景：

```python
response = client.chat.completions.create(
    model=MODEL,
    messages=messages,
    tools=TOOLS,
    stream=True,
)

collected = ""
for chunk in response:
    delta = chunk.choices[0].delta
    if delta and delta.content:
        collected += delta.content
        print(delta.content, end="", flush=True)   # 逐字打印
```

| 注意点 | 说明 |
|--------|------|
| 流式不能直接拿 `message` 对象 | 要自己**逐块拼装** |
| 拼接方式 | `chunk.choices[0].delta.content` 逐块追加 |
| 工具调用场景 | 见第 5 节（拼接的是 tool_calls 而非 content） |

## 5. 流式 tool_calls 拼接

**关键难点**：流式时 tool_calls 按 `index` 分片到达——每个调用片段的 `id`/`name`/`arguments` 都要按 index 累积拼装：

```python
def stream_tool_calls(client, messages, tools, max_turns=10):
    """流式版循环：tool_calls 按 index 拼装，执行后继续流式"""
    for turn in range(max_turns):
        stream = client.chat.completions.create(
            model=MODEL, messages=messages, tools=tools,
            tool_choice="auto", stream=True,
        )

        # ── 拼装区 ──
        full_content = ""
        tool_calls = {}          # index → {"id":..., "name":..., "arguments": 累积字符串}
        for chunk in stream:
            choices = chunk.choices or []
            if not choices:
                continue
            delta = choices[0].delta
            if delta.content:
                full_content += delta.content
            for tc in (delta.tool_calls or []):
                idx = tc.index                     # ★ 片段的 index（0,1,2...）
                entry = tool_calls.setdefault(idx, {"id": "", "name": "", "arguments": ""})
                if tc.id:
                    entry["id"] = tc.id
                if tc.function and tc.function.name:
                    entry["name"] = tc.function.name
                if tc.function and tc.function.arguments:
                    entry["arguments"] += tc.function.arguments   # ★ 增量拼接

        # ── 终止判断 ──
        if not tool_calls:
            return full_content

        # ── 构造 assistant 消息（与模型返回格式一致）──
        assistant_msg = {
            "role": "assistant",
            "content": full_content or None,
            "tool_calls": [
                {"id": entry["id"], "type": "function",
                 "function": {"name": entry["name"], "arguments": entry["arguments"]}}
                for entry in tool_calls.values()
            ],
        }
        messages.append(assistant_msg)

        # ── 执行并回传 ──
        for entry in tool_calls.values():
            import json
            try:
                args = json.loads(entry["arguments"])
            except json.JSONDecodeError:
                args = {}
            result = execute_tool(entry["name"], args)
            messages.append({"role": "tool", "tool_call_id": entry["id"], "content": result})
```

**拼接三要点**：

| 要点 | 说明 |
|------|------|
| `delta.tool_calls[].index` | 每个片段的编号，**按 index 分桶** |
| `arguments` 增量追加 | 每个 chunk 只带一小段，必须 `+=` 累积 |
| id/name 只出现一次 | 通常在首片段携带，之后片段为空——`if tc.id` 判空再取 |

> ⚠️ **流式拼接的经典 bug**：用"最后一片的 arguments"覆盖整段 → 只拼到最后一小段 → 坏 JSON。**必须是累积拼接**。

## 6. 健壮性配置基线

| 配置 | 推荐值 | 说明 |
|------|--------|------|
| SDK max_retries | 2 | 与手写退避二选一即可 |
| 连接超时 | 10s | 快速失败 |
| 读取超时 | 60s / thinking 120s | 按最慢合法场景 |
| 流式 | 按需开启 | 首 token 体验优先用 |
| 写工具幂等 | 幂等键 / 先查后写 | 防重试副作用 |
| 轮数上限 | 10-25 | 防死循环 |

> 🎯 **核心要点**：健壮性 = 重试（指数退避）+ 超时（按场景配）+ 幂等（副作用防重）+ 流式（体验与协议完整）。四条都做到，Agent 才算"能上真实网络"。
