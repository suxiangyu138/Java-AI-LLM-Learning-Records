## 1. 项目需求

**CLI 智能助手**：一个命令行程序，用户输入自然语言，Agent 自动调用工具完成任务。

| 功能 | 工具 | 说明 |
|------|------|------|
| 查询天气 | `get_weather` | 模拟/真实天气 API |
| 四则运算 | `calculate` | 安全表达式计算 |
| 当前时间 | `get_current_time` | 多时区时间 |
| 读文件 | `read_file` | 读取本地文本文件（安全校验） |
| 写笔记 | `append_note` | 追加笔记到本地文件 |

**验收场景示例**：

```text
> 北京和东京的天气对比一下
> 计算 (15 + 7) * 3 等于多少
> 现在纽约几点？
> 帮我读一下 notes.txt
> 记一条笔记：明天上午十点开会
```

## 2. 架构设计

```text
cli.py（入口：读输入 → 循环 → 打印）
  │
  ├── agent/loop.py        核心循环（04 篇 + 06 篇健壮性）
  ├── agent/tools.py       工具注册表（05 篇）
  ├── agent/retry.py       重试/超时封装（06 篇）
  └── agent/schema.py      从注册表自动生成 TOOLS 声明
```

**关键升级：声明与实现同源**

```python
"""agent/schema.py — 从注册表自动生成 tools 声明，杜绝"声明与实现不一致" """
from agent.tools import REGISTRY

# 约定：每个工具函数带 __tool_schema__ 元数据（或从 docstring+注解生成）
def get_weather(city: str, unit: str = "celsius") -> dict:
    """查询指定城市的当前天气。当用户询问天气、气温、降雨时使用。"""
    ...

def tool_schema() -> list[dict]:
    """从注册表函数生成 tools 数组（简化版：手写映射，生产用 Pydantic）"""
    return [
        {
            "type": "function",
            "function": {
                "name": "get_weather",
                "description": get_weather.__doc__,
                "parameters": {
                    "type": "object",
                    "properties": {
                        "city": {"type": "string", "description": "城市名"},
                        "unit": {"type": "string", "enum": ["celsius", "fahrenheit"]},
                    },
                    "required": ["city"],
                },
            },
        },
        # ... 其余工具同理
    ]
```

> 💡 同源的意义：schema 与执行函数**永远同步**——加工具只改一处。阶段 3 的框架（LangChain @tool 装饰器）就是把这个思想做成了产品。

## 3. 完整代码

```python
"""cli.py — 命令行智能助手入口"""
import json
import sys
from agent.loop import run_agent
from agent.schema import tool_schema

BANNER = """
==========================================
  CLI 智能助手（手写 Function-call Agent）
  输入自然语言指令，输入 exit 退出
==========================================
"""

def main() -> None:
    print(BANNER)
    history = []   # 跨轮次保存对话历史（同一会话内）
    while True:
        try:
            user_input = input("> ").strip()
        except (EOFError, KeyboardInterrupt):
            print("\n再见！")
            break
        if user_input.lower() in ("exit", "quit"):
            print("再见！")
            break
        if not user_input:
            continue

        # 追加用户消息 → 跑循环 → 得到回答
        history.append({"role": "user", "content": user_input})
        answer, history = run_agent(history, tools=tool_schema())
        print(f"\n🤖 {answer}\n")

if __name__ == "__main__":
    main()
```

```python
"""agent/loop.py — 核心循环（04 篇 + 06 篇健壮性整合）"""
import json
from agent.tools import execute_tool
from agent.retry import create_with_retry

MODEL = "deepseek-v4-flash"
MAX_TURNS = 10

def run_agent(messages: list, tools: list) -> tuple[str, list]:
    """运行 Agent 循环，返回 (最终回答, 更新后的消息历史)"""
    for _ in range(MAX_TURNS):
        response = create_with_retry(
            client=None,   # 实际从 config 传入
            model=MODEL, messages=messages, tools=tools, tool_choice="auto",
        )
        msg = response.choices[0].message
        messages.append(msg)

        if not msg.tool_calls:
            return (msg.content or "（无内容）"), messages

        for tc in msg.tool_calls:
            try:
                args = json.loads(tc.function.arguments)
            except json.JSONDecodeError:
                args = {}
            result = execute_tool(tc.function.name, args)
            messages.append({"role": "tool", "tool_call_id": tc.id, "content": result})

    return "（已达最大轮数，请简化问题重试）", messages
```

> ⚠️ 以上为结构示范——完整可运行代码需把 client 初始化、schema 生成、read_file/append_note 的安全校验补齐（扩展任务 1-3 即为此设计）。

## 4. 四验收标准

| # | 验收项 | 判定 |
|:---:|--------|------|
| 1 | 工具触发正确 | 5 个验收场景全部正确触发对应工具并给出合理回答 |
| 2 | 不触发场景正常 | "你好" 等闲聊不触发任何工具 |
| 3 | 错误优雅降级 | 故意让工具失败（不存在的城市/文件），Agent 能向用户说明，不崩溃 |
| 4 | 连续会话正常 | 同一会话内多轮提问（含跨轮工具调用）不报错、不丢上下文 |

**验收测试脚本（建议）**：

```bash
# 1. 触发
echo "北京和东京天气对比" | python cli.py
# 2. 闲聊
echo "你好" | python cli.py
# 3. 降级
echo "查询不存在的城市火星的天气" | python cli.py
# 4. 多轮
printf "帮我读一下 notes.txt\n然后记一条：已确认明天开会\n" | python cli.py
```

## 6. 常见问题

| 问题 | 根因 | 修复 |
|------|------|------|
| 模型总不调工具 | description 写得太模糊 | 按"做什么+何时用+边界"重写描述 |
| 工具参数总是错 | schema 与函数签名不一致 | 用同源生成（schema.py） |
| 多轮后 400 | 消息追加违规 | 检查 assistant/tool 消息铁律（03 篇） |
| 回答卡死 | 循环无终止 | 检查终止条件 + MAX_TURNS |
| 读取大文件把上下文塞爆 | 无大小限制 | read_file 加 1MB 上限，截断返回 |
| 工具报了错模型还继续编 | 错误信息不清晰 | 错误统一 `{"error": ...}` 格式（05 篇） |

> 🎯 **核心要点**：项目验收的"灵魂"是验收 3（优雅降级）——它证明你理解了"错误也是对话的一部分"。**能稳定处理失败的 Agent，才叫工程作品；只能跑通 happy path 的叫作业**。
