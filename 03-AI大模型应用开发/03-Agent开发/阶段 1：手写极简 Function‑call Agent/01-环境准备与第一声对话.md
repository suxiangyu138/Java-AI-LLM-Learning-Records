## 1. 技术选型：用哪家 API

阶段 1 的原则：**选一个 OpenAI 兼容 API**。OpenAI 的 `tools`/`tool_calls` 协议已是事实标准，2026 年所有主流供应商（DeepSeek、Qwen、Moonshot、Kimi、本地 vLLM/Ollama）都兼容它——**学一次协议，到处能用**。

| 供应商 | base_url | 模型（2026-08） | 特点 |
|--------|----------|----------------|------|
| DeepSeek | `https://api.deepseek.com` | `deepseek-v4-pro` / `deepseek-v4-flash` | 便宜、V4-Flash 支持并行调用；本阶段推荐 |
| OpenAI | 默认 | `gpt-4o-mini` 等 | 协议标准制定者 |
| 本地 vLLM/Ollama | 自建 | 任意开源模型 | 零成本，协议同款 |

> 💡 本阶段教程以 **DeepSeek V4** 为例（兼容 OpenAI SDK），OpenAI 用户只需删掉 `base_url` 并换模型名，代码零改动。

## 3. API Key 安全三原则

| # | 原则 | 反例 |
|:---:|------|------|
| 1 | 密钥只放 `.env`，不进代码 | 硬编码在 `.py` 里 |
| 2 | `.env` 必须进 `.gitignore` | 把 `.env` 提交到仓库 |
| 3 | 用环境变量加载，不打印 | `print(client.api_key)` 调试 |

```bash
# .env 文件（不提交）
DEEPSEEK_API_KEY=sk-xxxxxxxx
```

```python
# 加载方式
import os
from dotenv import load_dotenv
load_dotenv()  # 读取 .env

client = OpenAI(
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    base_url="https://api.deepseek.com",
)
```

> ⚠️ 密钥泄露后的补救：立即在控制台吊销并重建 key。先吊销再排查，不要先排查再吊销。

## 4. SDK 还是 requests

| 方式 | 优点 | 缺点 | 本阶段选择 |
|------|------|------|-----------|
| **openai SDK** | 类型提示、自动处理、省事 | 多一层封装 | ✅ 首选 |
| requests 手写 | 完全透明，懂 HTTP 本质 | 要自己拼 URL/headers/解析 | 建议做一次"实验" |

**建议**：正篇用 SDK；额外花 10 分钟用 requests 手动调一次，你会真正理解 SDK 帮你做了什么：

```python
# 实验：requests 手动调用（理解协议本质）
import requests

resp = requests.post(
    "https://api.deepseek.com/chat/completions",
    headers={"Authorization": f"Bearer {os.getenv('DEEPSEEK_API_KEY')}"},
    json={
        "model": "deepseek-v4-flash",
        "messages": [{"role": "user", "content": "你好"}],
    },
    timeout=30,
)
print(resp.json()["choices"][0]["message"]["content"])
```

## 5. 第一个 Chat 请求

```python
import os
from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()

client = OpenAI(
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    base_url="https://api.deepseek.com",
)

response = client.chat.completions.create(
    model="deepseek-v4-flash",
    messages=[
        {"role": "system", "content": "你是一个简洁的助手，回答不超过三句话。"},
        {"role": "user", "content": "请用一句话介绍你自己。"},
    ],
    temperature=0.7,
)

print(response.choices[0].message.content)
```

**跑通的标准**：终端打印出模型的自我介绍。如果报错，查[常见报错速查](#7-常见报错速查)。

## 6. 认识响应结构

```text
response
├── choices[0]
│   ├── message
│   │   ├── role: "assistant"
│   │   ├── content: "你好！..."        ← 文本回答（可能为 None！）
│   │   └── tool_calls: None            ← 阶段 2/3 的主角
│   └── finish_reason: "stop"           ← 结束原因（stop/lenGth/tool_calls）
├── usage
│   ├── prompt_tokens / completion_tokens / total_tokens
│   └── prompt_cache_hit_tokens         ← 缓存命中（成本相关）
└── model: "deepseek-v4-flash"
```

> 💡 **提前记住两个未来高频点**：`content` 可能为 `None`（当模型选择调工具时）；`finish_reason` 是循环终止判断的重要依据。

## 7. 常见报错速查

| 报错 | 含义 | 处理 |
|------|------|------|
| `401 Unauthorized` | key 错误/过期 | 检查 `.env` 加载、key 是否有效 |
| `404` / `Model Not Found` | 模型名错 | 核对模型名（v4-flash vs v4-pro） |
| `429 Rate limit` | 限流 | 稍后重试 / 指数退避（06 篇） |
| `Connection error` | 网络不通 | 检查代理、超时设置 |
| `Invalid URL` | base_url 写错 | DeepSeek 用 `https://api.deepseek.com` 即可 |
| `BadRequest` messages | 消息格式违规 | 最常见于漏加 assistant 消息（03 篇铁律） |

> 🎯 **核心要点**：本模块跑通的标志不是"看懂"，而是"终端能打印出模型回答"。所有后续代码都在这个最小请求上长出来——先把地基打牢。
