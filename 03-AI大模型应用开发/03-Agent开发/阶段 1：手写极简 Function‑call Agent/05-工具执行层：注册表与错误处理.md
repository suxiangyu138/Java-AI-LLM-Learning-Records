## 1. 从 if/elif 到注册表

v1 的 `execute_tool` 用 if/elif 分发——每加一个工具就多一段分支，20 个工具时难以维护。**注册表**用字典把"名字 → 函数"映射起来：

```text
v1 写法（硬编码分发）:         注册表写法（声明式）:
if name == "get_weather":      REGISTRY = {
    ...                            "get_weather": get_weather,
elif name == "calculate":          "calculate": calculate,
    ...                            "get_time": get_time,
elif name == "get_time":       }
    ...                          fn = REGISTRY[name](**args)
```

**注册表的好处**：

```text
① 新工具 = 写函数 + 注册一行，循环零改动
② 工具列表（注册表）与模型声明（TOOLS）同源，可自动生成
③ 天然拦截未知工具（查不到 key 即报错）
```

## 2. 注册表完整实现

```python
"""agent/tools.py — 工具注册表"""
import json


def get_weather(city: str, unit: str = "celsius") -> dict:
    """查询天气（模拟）"""
    return {"city": city, "temperature": 22, "unit": unit, "condition": "sunny"}


def calculate(expr: str) -> dict:
    """计算简单算术表达式（仅限安全表达式，见安全基线）"""
    import ast
    tree = ast.parse(expr, mode="eval")
    # 仅允许数字与四则运算节点
    allowed = (ast.Expression, ast.BinOp, ast.Constant,
               ast.Add, ast.Sub, ast.Mult, ast.Div, ast.UnaryOp, ast.USub)
    if not all(isinstance(n, allowed) for n in ast.walk(tree)):
        raise ValueError("表达式包含不允许的运算")
    return {"result": eval(compile(tree, "<expr>", "eval"))}


def get_current_time(timezone: str = "Asia/Shanghai") -> dict:
    """获取指定时区的当前时间"""
    from datetime import datetime
    import zoneinfo
    tz = zoneinfo.ZoneInfo(timezone)
    return {"timezone": timezone, "time": datetime.now(tz).strftime("%Y-%m-%d %H:%M:%S")}


# ─── 注册表：名字 → 可调用对象 ─────────────────────────────
REGISTRY = {
    "get_weather": get_weather,
    "calculate": calculate,
    "get_current_time": get_current_time,
}


def execute_tool(name: str, args: dict) -> str:
    """执行工具，任何异常都转成 JSON 错误字符串回传"""
    if name not in REGISTRY:
        return json.dumps({"error": f"未知工具: {name}"}, ensure_ascii=False)
    try:
        result = REGISTRY[name](**args)
        return json.dumps(result, ensure_ascii=False)
    except TypeError as e:
        return json.dumps({"error": f"参数错误: {e}"}, ensure_ascii=False)
    except Exception as e:
        return json.dumps({"error": f"执行失败: {type(e).__name__}: {e}"}, ensure_ascii=False)
```

**注册表三原则**：

| 原则 | 实现 |
|------|------|
| 名字唯一 | 注册表 key 与工具声明 name 一一对应 |
| 同源生成 | `TOOLS` 可从注册表自动生成（阶段 7 演示） |
| 异常兜底 | 所有异常捕获，返回 JSON 错误（见第 4 节） |

## 3. 参数校验：永远不信模型

> 模型输出的参数是"概率采样结果"，可能类型错误、缺字段、越界——**执行前必须校验**。

```python
def validate_args(fn, args: dict) -> tuple[dict | None, str]:
    """基于函数签名做轻量校验：多余的字段剔除，缺的字段报错"""
    import inspect
    sig = inspect.signature(fn)
    clean = {}
    for name, param in sig.parameters.items():
        if name in args:
            clean[name] = args[name]
        elif param.default is not inspect.Parameter.empty:
            pass  # 可选参数：不带就由函数默认值处理
        else:
            return None, f"缺少必填参数: {name}"
    return clean, ""
```

| 校验层 | 做法 |
|--------|------|
| 字段白名单 | 只传函数签名里有的参数（**绝不 kwargs 全量透传**——模型可能塞入 schema 外字段） |
| 必填检查 | 缺必填参数 → 返回错误消息给模型重试 |
| 类型检查 | 简单断言（isinstance），复杂用 Pydantic（阶段 4 引入） |

> ⚠️ 恶意/异常输入是真实的：模型可能传 `{"city": {"hack": 1}}`——校验层把这类输入挡在执行函数之外。

## 4. 工具执行异常：错误转 JSON 回传

**关键认知**：工具执行失败 ≠ 对话失败——把错误**作为工具结果喂回模型**，让模型决定怎么办（换参数重试 / 告知用户）：

```text
模型: 调 get_weather(city="不存在市")
你的代码: 执行抛异常 → {"error": "城市不存在: 不存在市"}
    ↓ 作为 tool 消息回传
模型: "抱歉，我查不到这个城市的天气，请确认城市名。"  ← 优雅降级
```

```python
# execute_tool 已经内置：任何异常 → {"error": ...} 字符串
result = execute_tool(name, args)
messages.append({"role": "tool", "tool_call_id": tool_call.id, "content": result})
```

| 异常类型 | 回传内容示例 | 模型应对 |
|---------|------------|---------|
| 参数错误（TypeError） | `{"error": "参数错误: get_weather() missing..."}` | 重新传参 |
| 业务失败（查无数据） | `{"error": "城市不存在: xxx"}` | 告知用户/换参数 |
| 外部 API 失败 | `{"error": "上游超时: TimeoutError"}` | 告知用户失败原因 |

> 🎯 **核心要点**：错误回传把"异常"变成"对话内容"——这是 Agent 优雅降级的关键。**永远不要让工具异常把整个循环炸掉**。

## 5. 工具结果返回规范

工具结果的 `content` 是**字符串**，有两条路：

| 方式 | 写法 | 适用 |
|------|------|------|
| JSON 字符串 | `json.dumps(result, ensure_ascii=False)` | ✅ 推荐：结构清晰，模型好读 |
| 纯文本 | `"北京 22℃ 晴天"` | 简单结果 |

**返回规范**：

```text
✅ {"city": "北京", "temperature": 22}          # 字段名与 schema 一致
✅ {"error": "城市不存在: 不存在市"}              # 错误统一 error 字段
❌ 返回 None / 空字符串                          # 模型会困惑
❌ 返回超长内容（10K+ token）                    # 塞爆上下文（阶段 4 治理）
```

## 6. 安全基线

阶段 1 就该有的底线（深化见 [Tool 工具开发与注册](../Agent%20子组件专项学习/)）：

| 基线 | 做法 | 阶段 1 示例 |
|------|------|------------|
| 不执行模型给的代码 | 绝不 `eval` 模型生成的任意代码 | calculate 用 ast 白名单 |
| 参数白名单 | 只传函数签名内的参数 | validate_args |
| 命令注入防御 | 文件/Shell 类工具禁止拼接用户输入 | 阶段 7 文件工具演示 |
| 网络白名单 | 工具的网络请求只到允许域名 | 阶段 7 天气 API |

> ⚠️ **红线**：模型说"帮我删除文件"时，你的工具没有 delete 工具，它就删不了——**工具面即安全面**，最小工具集就是最小攻击面。

> 🎯 **核心要点**：执行层的三个信念——**注册表声明式扩展、参数永远校验、错误永远回传**。做到这三点，20 个工具与 2 个工具一样稳。
