## 1. 治理的四张网

```text
成本网：预算、配额、缓存、路由 → 花得明白、超了能停
质量网：eval 采样、漂移告警、反馈回流 → 坏了早知道
可用性网：SLO、限流、熔断、fallback → 挂了能撑住
合规网：审计、审批、脱敏、留存 → 查得清、证得明

四张网交叉生效：成本网和可用性网共用"配额限流"，
质量网和可用性网共用"金丝雀回滚信号"——设计时别各建一套
```

## 2. 配额与速率限制

### 2.1 分层限流

| 层 | 手段 | 超限响应 |
|----|------|---------|
| 单请求 | token 上限、成本上限、循环上限 | 中断执行，结构化报错 |
| 单用户 | QPS、并发数（连接级） | 429 + Retry-After |
| 单租户/团队 | 日/月预算 | 429 / 降级 |
| 全局 | 供应商配额镜像 | 熔断 + fallback |

### 2.2 预算扣减语义

```text
预算要"先扣后跑"还是"跑完再扣"？
  先扣：防并发超支（预算竞态），对用户友好（明确拒绝）
  跑完再扣：精确计费，但并发窗口可能超支
  生产建议：预留额度 + 跑完结算（预留 30% 缓冲）

配额必须与"幂等"配合：重试不重复扣费（09 篇 idempotency_key）
```

> ⚠️ **LLM10 无界消耗的治理落点**：per-key 预算（网关层硬上限）、token 长度上限、循环上限、成本遥测告警——四件套缺一不可（08 篇）。

## 3. SLO 定义与健康检查

### 3.1 指标与 SLO 建议

| 指标 | 建议 SLO | 说明 |
|------|---------|------|
| 可用性（错误率） | 99.9%（4xx 排除，5xx/超时算） | 供应商故障计入但分开统计 |
| TTFT p95 | < 1.5s（缓存命中路径 < 500ms） | 缓存失效时允许放宽 |
| 完整响应 p95 | < 10s（长任务走异步，不算） | 短任务才进 SLO |
| 工具失败率 | < 1% | 单一工具失败率高 → 该工具熔断降级 |
| 成本 | 月预算上限（硬） | 预算非 SLO，但比 SLO 更硬 |

### 3.2 优雅降级链

```text
供应商故障 → 网关 fallback（备用供应商）→ 降级回答（"暂时无法查询"）
             → 高影响决策转人工队列 → 限流保护下游

原则：降级也要有 eval 质量基线（降级回答也要可评估）；
     熔断后自动恢复（半开探测），别手动救火
```

## 4. 成本治理闭环

### 4.1 闭环流程

```text
记账（trace 归因）→ 路由（便宜先上）→ 预算（硬上限）→ 复盘（周报归因）

记账：每请求成本按 用户/租户/Agent/模型/路由路径 归因（04 篇）
路由：语义缓存 + 模型路由 + 工具 memoization（07 篇）
预算：三层（单请求/单会话/单用户），80% 预警、100% 熔断
复盘：成本周报——找黑洞（长上下文未缓存、循环超长、大模型小用）
```

### 4.2 成本黑洞自查表

| 黑洞 | 信号 | 止血 |
|------|------|------|
| 缓存命中率低 | < 60% | 前缀稳定化、缓存感知路由（07 篇） |
| 循环超长 | 平均轮数 > 5 | 收紧 max_steps、错误回传优化 |
| 长会话 token 爆炸 | 单会话成本线性涨 | 上下文压缩三件套 |
| 大材小用 | 简单请求全走旗舰模型 | 意图路由（07 篇） |
| 无界消耗攻击 | 单用户成本突增 | per-key 预算硬上限 |

## 5. 质量漂移监控与反馈闭环

### 5.1 漂移监控（质量告警 ≠ 延迟告警）

```text
延迟告警抓基础设施，质量告警抓行为退化——两者都要：

  eval 分数漂移：在线采样评分（06 篇），滚动窗口对比
  模型升级漂移：供应商无声升级 → 行为变化 → 分数下滑
  提示注入攻击面：拒绝率/异常请求率突增
  反馈信号：用户升级率（转人工比例）、差评率、投诉率
```

### 5.2 反馈闭环（防静默退化）

```text
生产 eval 探测到低质量 → 信号回流：
  1. 更新测试用例 / golden set（失败样本入库）
  2. 触发 prompt / 路由 / 子 Agent 调优
  3. 若为金丝雀版本 → 自动回滚（10 篇）

不闭环的后果：Agent 静默退化到用户升级投诉才被发现
```

## 6. 供应商故障预案

```text
预案要素：
  1. fallback 链（网关层）：主 → 备 → 本地降级（07/09 篇）
  2. 关键路径冗余：高影响决策排队人工（不静默失败）
  3. 故障感知：错误率/延迟告警 + 供应商状态页订阅
  4. 演练：季度故障演练（fallback 是否真能接住）
  5. 事后：RCA 复盘 + 指标回填
```

## 7. 审计与合规运营

| 审计项 | 内容 |
|--------|------|
| 操作审计 | 审批记录（approved_by + 理由）、工具调用留痕、模型输出留痕 |
| 数据合规 | 脱敏巡检（trace/日志/数据集）、留存策略执行、租户隔离验证 |
| 版本审计 | 谁在何时把哪个 label 指向哪个版本（10 篇注册表天然带审计） |
| 合规要求 | EU AI Act 第 14 条人类监督（监控+干预能力）、GDPR/个保法数据处理记录 |

## 8. 治理仪表盘

```text
一张屏看四网（示例面板）：
  成本：今日/本月花费、环比、按用户 Top10、按 Agent Top5、缓存命中率
  质量：在线 eval 分数趋势、拒绝率、升级率、边界样本数
  可用性：错误率、TTFT p95、工具失败率、fallback 触发次数
  配额：各 key 剩余预算、被限流请求数、429 分布

告警分级：
  P1（立即）：预算 100% 熔断 / 质量分 3pp 下滑 / 供应商全挂
  P2（当日）：预算 80% / 工具失败率 > 1% / 漂移预警
  P3（周会）：成本环比 +10% / 缓存命中率下滑 / 长尾延迟
```
