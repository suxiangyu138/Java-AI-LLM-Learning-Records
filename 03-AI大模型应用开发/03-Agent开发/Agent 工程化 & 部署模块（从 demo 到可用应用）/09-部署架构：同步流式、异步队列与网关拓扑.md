## 1. 三种服务形态的选型

```text
2026 选型口诀："用户盯着屏幕就流式，回头再来就用队列"

同步（请求-响应）  ：短任务（<几秒），直接返回
流式（SSE）        ：用户实时看着进度，长过程逐步呈现
异步（队列）       ：任务分钟级/更久，用户稍后回来拿结果

同一 Agent 可三形态并存：短查询同步、复杂任务转异步、过程实时流式
```

| 维度 | 同步 | 流式 | 异步 |
|------|------|------|------|
| 延迟体验 | 等完整结果 | 首 token 秒出 | 立即返回 job_id |
| 吞吐 | 低（连接占着） | 低-中 | 高（与连接解耦） |
| 可靠性 | 中（连接断即丢） | 中（可重连恢复） | 高（队列持久化 + 重试） |
| 典型场景 | 简单问答、工具直查 | 对话、过程可视化 | 报告生成、批量处理、多步 Agent |

## 2. 同步形态：短任务的默认选择

```text
API: POST /chat  →  完整响应（或轻量流式）
适用：单轮查询、缓存命中路径、意图分类

注意：
  - 网关层超时（如 30s）必须大于 Agent 最大执行时间
  - 同步请求内部也要有预算（token/轮数上限，见 07/08 篇）
  - 请求级别：幂等键 + 重试语义（用户重复提交不重复执行副作用）
```

## 3. 流式形态：SSE 实时进度

### 3.1 流什么

```text
Agent 流式 ≠ 只流文本：
  - 文本 token（模型生成）
  - 状态事件：开始/工具调用/工具完成/步骤切换/结束
  - 过程数据：查到了什么、正在做什么（用户信任感关键）
```

### 3.2 SSE 实现要点

```text
  POST /chat/stream → SSE（text/event-stream）
  事件信封：{"schema_version": 1, "run_id": "...", "type": "tool_call", ...}
  事件编号：递增 seq（客户端去重）
  心跳：30s 注释行保活（Nginx 缓冲/代理超时注意）
  断线：Last-Event-ID 重连（服务端保留近期事件）
```

> ⚠️ **代理层陷阱**：SSE 经过 Nginx/网关必须关闭缓冲（`proxy_buffering off`）、超时调大、HTTP/1.1 或 HTTP/2 全双工；中间任何缓冲层都会把流式变成"攒够再发"。

## 4. 异步形态：队列 + 事件回放

### 4.1 标准接口

```text
POST /jobs                 → {job_id, status_url, events_url, cancel_url}
GET  /jobs/{id}            → 状态查询（queued/running/succeeded/failed/cancelled）
GET  /jobs/{id}/events     → SSE 订阅（事件流回放）
POST /jobs/{id}/cancel     → 显式取消

特性要求：
  idempotency_key：重复提交不重复执行（防双扣款/双工单）
  持久化：任务状态与产物落库——pod 重启/滚动发布不丢任务
  超时预算：per-hop 上限（单 Agent 任务）+ end-to-end 上限（用户可见总时长的天花板）
  终态兜底：最后事件丢失时客户端能靠终态接口恢复
```

### 4.2 队列选型

| 方案 | 适用 | 备注 |
|------|------|------|
| Redis Streams | 中规模、自托管 | 队列 + SSE 事件回放一体（生产案例多用） |
| SQS / Google Pub-Sub | 云原生、Serverless | 托管、免运维；事件回放另配 |
| Celery + Redis/Rabbit | Python 生态成熟 | 与 FastAPI/Django 配合好 |
| Kafka | 大规模、事件溯源 | 重；事件回放天然强 |

### 4.3 关键设计决策

```text
1. 先落库再应答：任务持久化成功后才返回 job_id（serverless 丢 ID 即丢工作）
2. 事件即日志：SSE 事件流 = 审计记录 = 回放源（一份数据三用途）
3. 子任务委派：orchestrator 委派前先持久化中间产物，下一跳失败可恢复
4. 取消语义：cancel 是"停止调度 + 终止执行 + 标记终态"，不是杀死连接
```

## 5. Execution Registry：解耦执行与连接

```text
模式（2026 生产实践）：
  Agent 在后台 asyncio.Task 中执行，事件写入内存缓冲
  SSE 连接"订阅"缓冲尾部，带游标（cursor）断线重连回放
  Execution 对象记录：状态机（RUNNING/COMPLETED/ERROR/STOPPED）
                     递增 event_id、订阅者数、唤醒事件

  - 执行生命周期 ≠ 连接生命周期：用户关网页，Agent 继续跑
  - 缓冲溢出：MAX_EVENTS=10000，超限截断最旧 20%，发 buffer_truncated 标记
  - 单实例适用；多实例时缓冲换 Redis Streams（跨实例订阅）
```

> 🎯 **收益**：把"长时间 Agent 执行"从"脆弱的 HTTP 连接生命周期"中解放——这是异步形态能扛住真实生产的关键。

## 6. 模型网关：统一入口

```text
架构位置：应用 → 模型网关（LiteLLM Proxy / 自研）→ 各供应商

网关职责：
  1. OpenAI 兼容统一协议（SDK/业务代码零改动换模型）
  2. 路由：逻辑名 → 物理模型（按成本/能力分流）
  3. fallback：主模型故障/限流 → 备用供应商（三层级）
  4. 治理：per-key 预算（429）、限流、灰度比例
  5. 可观测：统一 token/成本计费（成本归因的唯一权威）

安全：master_key + 虚拟 key（每客户端一把，可吊销、可限预算）
     内网部署、反代 TLS（详见 LiteLLM 体系）
```

> 网关细节（config 五块、虚拟 key、fallback 层级）见 [LiteLLM 多模型适配](../../02-大模型基础与Prompt工程/LiteLLM%20多模型适配/00-LiteLLM知识体系总览.md)。

## 7. 容器化与水平扩展

### 7.1 无状态原则

```text
应用容器必须无状态（会话/任务状态在外部存储）：
  - 会话/记忆 → Redis/DB（02 篇 AgentState 可序列化）
  - 任务事件 → Redis Streams/DB
  - 语义缓存 → Redis/向量库
水平扩展 = 加副本；滚动发布 = 杀旧起新，不丢任何状态
```

### 7.2 K8s 部署要点

| 项 | 配置 |
|----|------|
| 探针 | readiness（LLM 健康探测）/ liveness（线程死锁探测）|
| 扩缩容 | HPA：同步/流式按 QPS + P99；异步按队列深度 |
| 资源 | 请求/限制合理（LLM SDK 内存缓冲、并发协程数对应 CPU） |
| 优雅停机 | preStop 排空 + SIGTERM 处理（不再收新任务、完成在途或回队） |
| 网络 | 出口白名单（仅供应商域名）、TLS 终止在 Ingress |

> 💡 虚拟线程/异步模型注意：CPU 密集解析与 IO 密集调用混跑时，worker 数与协程并发数分别调优；流式服务连接数大但 CPU 低，要防连接数把容器拖垮（连接级限流）。

## 8. MCP Server 的部署

```text
本地（stdio）：仅限开发/同机；RCE 风险高（MCP STDIO RCE ≥10 CVE），生产禁用
远程（Streamable HTTP）：生产标准——
  - HTTP 传输 + 会话保持
  - 认证：Bearer token / OAuth 2.1（按 MCP 规范）
  - 部署：独立容器、独立凭据、最小权限（08 篇供应链）
  - 与 Agent 同机部署：保持低延迟，避免 MCP 往返成为瓶颈
```

## 9. 发布策略与优雅停机

| 策略 | 适用 | 工具 |
|------|------|------|
| 滚动 | 常规发布 | K8s Deployment 默认 |
| 蓝绿 | 快速全量回滚需求 | 两套环境 + 切流 |
| 金丝雀 | 质量敏感（Agent 必用） | Argo Rollouts / Flagger + 在线 eval 信号（06 篇） |
| 影子 | 新版本先只记录不服务 | 对比新旧输出（10 篇 shadow 阶段） |

> ⚠️ **Agent 发布与普通发布不同**：代码没变，prompt/模型变了也是发布（行为变更）。发布决策依据在线 eval 分数（2-3pp 下滑自动回滚），不是仅看错误率——见 [10-版本管理与发布](10-版本管理与发布：Prompt、模型与代码协同演进.md)。

## 10. 落地检查单

```text
□ 三形态选型明确：短任务同步、过程流式、长任务异步
□ 异步：job 接口齐全（提交/状态/事件/取消）、幂等键、终态兜底
□ 执行与连接解耦（Execution Registry 或等价物）
□ SSE：事件信封 + seq + 心跳 + Last-Event-ID 重连，代理缓冲已关
□ 模型网关就位：统一协议、fallback、虚拟 key、预算
□ 容器无状态，HPA 指标正确（队列深度/连接数）
□ 优雅停机：在途任务完成或回队
□ MCP 生产走 Streamable HTTP + 认证，stdio 仅限开发
□ 金丝雀发布 + 在线 eval 自动回滚信号已通
```
