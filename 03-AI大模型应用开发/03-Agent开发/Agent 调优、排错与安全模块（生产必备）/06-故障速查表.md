## 1. 使用说明

```text
查表三步：
① 按症状归类（A-F 六大类）
② 定位现象 → 看根因与修复
③ 修复后补评估用例（阶段 4）→ 沉淀到回归集

原则：速查表给"最可能根因"，排错方法论（05 篇）给"证明它是根因"的流程
```

## 2. A 类：循环与终止故障

| # | 现象 | 根因 | 修复 |
|:---:|------|------|------|
| A1 | 同一工具连续调用 8-47 次 | 工具失败无终态标记 | 错误响应标 `retry: false` + 循环计数器提示 |
| A2 | Agent 不停止 | recursion_limit 缺失/过大 | 显式设置（2-3× 正常需求） |
| A3 | A→B→A→B 交替循环 | 多 Agent 交接死循环 | 交接模式检测（阶段 5 03 篇） |
| A4 | 重试风暴烧钱 | 无评估重试 | 修复循环 ≤3 次 + 退避 + 降级（阶段 4） |
| A5 | 熔断触发但用户卡死 | 熔断无恢复路径 | 熔断给提示 + 重新开始 |
| A6 | 轮数正常但成本爆炸 | 单轮输出超长 | max_completion_tokens 上限 |

## 3. B 类：工具调用故障

| # | 现象 | 根因 | 修复 |
|:---:|------|------|------|
| B1 | 模型从不调某工具 | docstring/description 太差 | "做什么+何时用+边界"公式 |
| B2 | 参数总错 | schema 与函数签名脱节 | 同源生成 / strict / enum |
| B3 | 参数幻觉（无来源） | 模型猜参数 | 描述明示"不知道就问用户" |
| B4 | 工具选择混淆 | 工具职责重叠 | 拆分/合并/文档化边界 |
| B5 | 工具报错但模型重复同错 | 错误信息不清晰 | 错误带具体原因+建议 |
| B6 | 并行结果错位 | 按位置配对 | 按 tool_call_id 配对（阶段 2） |
| B7 | 工具执行慢 | 工具 I/O 是瓶颈？ | 先测：工具 I/O 通常只占 9%（02 篇） |
| B8 | 工具结果污染后续 | 结果过大/含噪声 | 结果截断 + 摘要 + 落盘引用 |
| B9 | 调用不存在工具 | 模型幻觉工具名 | 未知工具返回错误 + 工具名固定 |

## 4. C 类：上下文与记忆故障

| # | 现象 | 根因 | 修复 |
|:---:|------|------|------|
| C1 | 请求 400 超限 | 上下文超窗口 | 预算监控 + 压缩触发（阶段 4 04 篇） |
| C2 | 忘了前几轮 | 滑动窗口裸用 | 保首尾 + 摘要 + 外部记忆 |
| C3 | 关键数值丢失 | 压缩丢精确值 | 压缩前写入外部存储（Mem0 模式） |
| C4 | 上下文越长质量越差 | Lost-in-the-Middle | 关键信息首尾 + 信息密度优先 |
| C5 | 截断导致坏 JSON | max_tokens 无余量 | 输出预留 15% + 检查 finish_reason |
| C6 | 缓存命中率 <50% | 前缀污染 | 冻结 system prompt + 工具顺序固定 |
| C7 | 子 Agent 上下文串扰 | 共享 messages | checkpointer 隔离 + 精选传递 |
| C8 | 压缩后行为突变 | 摘要失真 | 原文落盘可恢复 + 摘要保数值纪律 |

## 5. D 类：质量与幻觉故障

| # | 现象 | 根因 | 修复 |
|:---:|------|------|------|
| D1 | 回答与文档矛盾 | 检索质量差 | 重排 + 过滤 + 信息密度（03 篇失败模式） |
| D2 | 编造事实 | 无据硬答 | 无据拒答 + 强制引用 + 验证层 |
| D3 | 引用伪造 | 引用无约束 | 引用必须来自系统注入集合 |
| D4 | 输出不一致 | 采样参数不合适 | temperature 归因后调整（04 篇） |
| D5 | 回答变差（无改动） | 模型升级/漂移 | 灰度对比 + 版本化 + 评估门禁 |
| D6 | 拒绝回答该答的 | 约束过严/误判 | 拒答率监控 + 边界校准 |
| D7 | 结构对但值错 | strict 只保结构 | 语义校验链（业务规则） |
| D8 | judge 评分与人工矛盾 | judge 未校准 | pin 版本 + kappa ≥0.75 校准（阶段 4） |

## 6. E 类：成本与性能故障

| # | 现象 | 根因 | 修复 |
|:---:|------|------|------|
| E1 | 账单隔夜翻倍 | 死循环/重试风暴 | 日预算 + spend-rate 告警（03 篇） |
| E2 | 首 token 慢 | 缓存未命中 | 前缀冻结 + 缓存感知路由（02 篇） |
| E3 | 每会话成本高 | 历史全量重发 | 压缩 + 动态工具过滤 + memoization |
| E4 | 延迟波动大 | 路由抖动 | 缓存感知路由 + 负载均衡兜底 |
| E5 | 多 Agent 成本超预期 | 整树成本没算 | 预算按调用树汇总（阶段 5） |
| E6 | 长会话成本失控 | O(N²) 重发 | 压缩 + 缓存断点 + 会话轮数上限 |
| E7 | 流量高峰超限 | 无队列/限流 | 队列平滑 + 并发信号量 |

## 7. F 类：安全与合规故障

| # | 现象 | 根因 | 修复 |
|:---:|------|------|------|
| F1 | 模型输出 system prompt | 提示词泄露 | 金丝雀 token + 输出检测（失败模式 08 篇） |
| F2 | 注入命中 | 内容未降权 | 检索/工具输出按不可信处理 |
| F3 | 越权工具调用 | 权限分级缺失 | 策略引擎 + L0-L3 分级（阶段 4 05 篇） |
| F4 | 数据外泄 | 无外发白名单 | egress 白名单 + 敏感检测 |
| F5 | 恶意 MCP 服务器 | 未过安全审查 | MCP 安全基线六条（阶段 5 06 篇） |
| F6 | 敏感数据入日志 | 埋点未脱敏 | SDK 层脱敏（摄入前） |
| F7 | 合规审查不过 | 无 HITL | EU AI Act 第 14 条：人工监督节点（阶段 4 08 篇） |
| F8 | 审计缺失 | 动作无留痕 | 全动作留痕（谁/何时/何工具/何参数） |

> 🎯 **核心要点**：速查表的正确用法 = **"先查表止血，再走方法论根治"**。44 条现象对应 44 个最常见根因——每条修复后都要补评估用例，让速查表里的故障"永不复发"。背熟六大类首条（A1 死循环、B1 工具描述、C1 上下文超限、D1 检索质量、E1 成本熔断、F1 提示词泄露）——它们是每类的"头号敌人"。
