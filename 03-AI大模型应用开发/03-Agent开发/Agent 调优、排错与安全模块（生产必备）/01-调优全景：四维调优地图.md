## 1. 四维调优地图

| 维度 | 关注指标 | 核心杠杆 | 本篇 |
|------|---------|---------|:---:|
| 延迟 | TTFT、TBT、总耗时 | 缓存路由、流式、并行、模型路由 | 02 |
| 成本 | 每会话成本、缓存命中率 | 缓存经济学、memoization、模型分级 | 03 |
| 质量 | judge 分数、工具准确率、幻觉率 | prompt、schema、参数、A/B | 04 |
| 可靠性 | 失败率、熔断触发率 | 排错体系、护栏（05-07 篇） | 05-07 |

```text
四维的耦合关系（2026 关键认知）：
├─ 延迟↑ 通常伴随 成本↓（缓存命中/模型降档）
├─ 质量↑ 通常伴随 成本↑（更强模型/更多轮数）
├─ 可靠性↑ 通常伴随 成本↑（验证层/多Agent审查）
└─ 调优的本质：四维的帕累托权衡，不是单点极值
```

> 🎯 **核心要点**：调优的第一原则 = **先测量再优化**。2026 数据：缓存感知路由能把 TTFT 提升 57×——但如果你不知道自己的缓存命中率，就不知道这个杠杆在不在你手里。

## 2. 收益排序：先调哪个

按"投入产出比"排序的 2026 生产共识：

| 排序 | 调优项 | 收益 | 成本 | 时机 |
|:---:|--------|------|:---:|------|
| ① | Prompt Caching 前缀冻结 | 成本 -85-90%、TTFT -50-70% | 极低 | 立即 |
| ② | 缓存感知路由（自托管） | TTFT 最高 57× | 中 | 有推理集群时 |
| ③ | 模型分级路由 | 成本 -30-50% | 低 | 立即 |
| ④ | 工具结果 memoization | 服务成本最大杠杆之一 | 中 | 工具调用密集时 |
| ⑤ | 流式体验 | 感知延迟大幅改善 | 低 | 立即 |
| ⑥ | 并行工具执行 | 延迟 -1.6-1.8× | 低 | 多独立调用时 |
| ⑦ | 上下文压缩 | 成本 + 质量双改善 | 中 | 长会话时 |
| ⑧ | 结构化输出 | 质量 + 可靠性 | 低 | 立即 |

> 💡 **调优的"20/80"**：①②③ 三项做完，延迟与成本的主要收益就到手了——先做免费的高杠杆，再谈架构级优化。

## 3. 标准调优流程

```text
① 测量（1 周基线）     —— 四维指标采集（延迟/成本/质量/可靠性）
② 定位（瓶颈在哪维）   —— 对照基线找异常维度
③ 假设（根因是什么）   —— 数据驱动的假设（不猜）
④ 实验（小流量验证）   —— 金丝雀/灰度验证（阶段 4 门禁）
⑤ 全量（评估通过后）   —— 版本化 + 回滚就绪
⑥ 复盘（效果 vs 预期） —— 记录收益，沉淀到基线
```

| 阶段 | 产出 | 反模式 |
|------|------|--------|
| 测量 | 四维基线报告 | 没数据就开调 |
| 定位 | 瓶颈维度清单 | 眉毛胡子一把抓 |
| 假设 | 可验证假设 | 凭感觉改 prompt |
| 实验 | 对比数据 | 直接全量上线 |
| 全量 | 版本化记录 | 无回滚方案 |
| 复盘 | 收益报告 | 调完不记录 |

## 4. 指标先行：没有数据不调优

**最小指标集（上线即有）**：

```python
"""metrics_min.py — 四维最小指标集（阶段 4 可观测的调优版）"""
MINIMAL_METRICS = {
    # 延迟

# 每个指标要能回答：
# 基线是多少？目标是多少？变化发生在哪个版本？
# 没有这三问的指标，只是装饰品
```

| 指标纪律 | 说明 |
|---------|------|
| 基线先立 | 调优前先有 1 周基线 |

| 分组视图 | 按模型/prompt 版本/工具分组（2026 铁律） |
| 告警有接收者 | 指标没接告警 = 没指标 |

## 5. 调优的边界

| 边界 | 说明 |
|------|------|
| 别牺牲可靠性换延迟 | 缓存路由 + 熔断并存，不是二选一 |
| 别牺牲质量换成本 | 模型降档必须过评估门禁（阶段 4） |
| 别过度调优 | 单次 10ms 的优化不值得引入架构复杂度 |
| 瓶颈意识 | 工具 I/O 只占 ~9% 端到端时间——别优化工具调用本身，优化推理与上下文 |
| 成本意识 | 优化本身有成本（人力/复杂度）——用 ROI 决定 |

> 🎯 **核心要点**：调优全景 = **四维地图 + 收益排序 + 测量流程 + 边界意识**。记住三句话：先测量、先做免费杠杆、别为 10ms 引入复杂度。四维是帕累托权衡——每次调优都写清"用哪一维换了哪一维"。
