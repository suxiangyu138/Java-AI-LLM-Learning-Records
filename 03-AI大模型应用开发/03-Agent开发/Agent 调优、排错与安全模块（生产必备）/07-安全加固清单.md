## 1. 加固清单使用法

```text
使用时机：上线前 / 每季度复查 / 事故后复盘
用法：逐项核查 → 未过项进整改清单 → 整改后复检

原则（2026 安全共识）：
├─ 模型负责"想"，系统负责"批"（一切决策在模型外）
├─ 纵深防御：假设单层必被绕过
├─ 默认拒绝：未显式允许 = 禁止
└─ 提示词不是安全机制（它是建议，不是执法）
```

## 9. 应急响应流程

```text
① 发现（告警/上报）
② 止血（优先级）：
   ├─ kill switch 禁用 Agent
   ├─ 回滚版本（prompt/工具/配置版本化）
   └─ 转人工流程
③ 取证：完整 trace + 失败样本（外部遥测为准，不信 Agent 自报）
④ 根因：变更关联 + 对照组对比（05 篇五步法）
⑤ 修复：补评估用例（安全用例 + 回归）+ 修复代码
⑥ 复盘：四段式（现象/根因/措施/验证）+ 更新速查表

安全事件特殊动作：
├─ 金丝雀触发 → 定位泄露面 → 轮换密钥
├─ 注入命中 → 评估影响面（工具权限/数据）
└─ 数据外泄 → 合规申报流程
```

> 🎯 **核心要点**：安全加固 = **七大类 38 项逐项核查 + 应急流程就绪**。2026 合规窗口（EU AI Act 生效）让 HITL 与审计成为硬要求；MCP 供应链事件（STDIO RCE）让"来源白名单 + 输入消毒"成为必查项。加固清单的终点不是"勾完"，是"整改闭环"——未过项必须进整改清单并复检。
