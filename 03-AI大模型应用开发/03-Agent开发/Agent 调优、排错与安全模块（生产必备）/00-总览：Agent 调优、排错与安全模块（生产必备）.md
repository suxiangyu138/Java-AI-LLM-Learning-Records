## 5. 核心概念速查

| 概念 | 一句话 | 关键数字 |
|------|--------|---------|
| 缓存感知路由 | 按 KV 缓存前缀哈希路由请求（不盲目轮询） | TTFT 提升最高 57×；轮询下缓存命中率可跌至 8% |
| Prompt Caching | 稳定前缀命中缓存 | 输入成本省 ~85-90%，TTFT 降 50-70% |
| 缓存回本点 | 5 分钟缓存读 2 次回本；1 小时读 3 次回本 | 命中率目标 >80% |
| 工具结果 memoization | 相同工具+参数的结果缓存复用 | 服务成本最大杠杆之一 |
| trace-first 排错 | 先看 trace 再猜原因 | prompt hash 秒判 prompt 是否变了 |
| 会话级指标 | 解析率/升级率/目标完成率（非单请求指标） | 排错主视角 |
| 卡死循环 | 同一工具连续调用 8-47 次 | 结构化错误标记 `retry: false` |
| 级联故障 | 单根因引发 41% 生产 bug（Pathfinder） | 上下文/token 管理是主根因 |
| 多 Agent 协调故障 | 多 Agent 系统 ~23% 故障是协调问题 | 交接 payload 必须可检查 |
| 加固清单 | 生产安全基线逐项核查 | 7 大类 30+ 项 |

## 7. 2026 版本窗口

> 本模块以 2026-08 为基准：
>
> - **缓存感知路由**：2026 生产延迟优化第一大杠杆——盲轮询"主动有害"（缓存命中率可跌至 8%、TTFT p90 差 57×）；vLLM Router / llm-d（CNCF Sandbox）/ NVIDIA Dynamo 为参考实现
> - **Prompt Caching 经济学**：Anthropic 命中省 ~85% 成本 + TTFT 降 50-70%（写成本 125-200%，5 分钟缓存读 2 次回本）；OpenAI ≥1024 token 前缀自动缓存省 ~90%；Gemini 隐式免费
> - **排错方法论**：trace-first 成为 2026 标准——prompt hash + 全量工具结果（截断 ~8KB）+ 会话回放；Pathfinder（ACM 2026）发现 41% 生产 bug 是级联故障（上下文/token 管理为主根因）
> - **自动 RCA**：Monte Carlo Troubleshooting Agent 等 AI 排错工具可把 30-60 分钟人工排查压缩到分钟级
> - **安全**：EU AI Act 第 14 条 2026-08-02 生效；MCP STDIO RCE 事件（≥10 CVE）后安全基线升级（见 07 篇）
