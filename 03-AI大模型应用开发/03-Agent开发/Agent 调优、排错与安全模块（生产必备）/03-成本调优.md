## 1. 成本构成拆解

```text
Agent 成本 = Σ(模型调用) × (输入 token × 单价 + 输出 token × 单价)

2026 关键认知：
├─ 输入成本通常占大头（历史全量重发 + 工具结果 + 检索内容）
├─ 输出单价通常是输入的数倍（但输出量小）
├─ Agent 成本随轮数近二次增长（阶段 2 05 篇 O(N²)）
└─ → 成本优化的主战场：输入 token 量 + 模型选择
```

| 成本项 | 占比（典型） | 杠杆 |
|--------|:---:|------|
| 输入 token（历史重发） | 30-50% | 缓存、压缩 |
| 输入 token（工具/检索内容） | 20-30% | memoization、落盘引用 |
| 模型单价 | —— | 分级路由 |
| 输出 token | 10-20% | 长度控制 |
| 重试/死循环 | 5-20%（事故时爆表） | 熔断、修复循环纪律 |

> 🎯 **核心要点**：成本优化的三条主线——**减少重发（缓存/压缩）、降低单价（路由/分级）、防止失控（预算/熔断）**。2026 最贵的事故仍是"重试风暴 + 死循环"（一夜 3× 账单）。

## 2. 杠杆一：Prompt Caching 经济学

### 2.1 回本计算

```python
"""cache_economics.py — 缓存回本核算"""
def cache_breakeven(write_cost_multiplier: float, hit_saving: float,
                    reads_per_ttl: int) -> float:
    """判断缓存是否划算：读次数是否够回本"""
    # 写一次成本 = 基数 × 写乘数；每命中省 = 基数 × 省比例
    cost_if_cached = write_cost_multiplier + reads_per_ttl * (1 - hit_saving)
    cost_if_uncached = reads_per_ttl
    return cost_if_cached  # < cost_if_uncached 时划算

# Anthropic 5 分钟缓存：写 1.25×，命中省 0.85×
# 读 2 次：1.25 + 2×0.15 = 1.55 vs 2 → ✅ 回本
# Anthropic 1 小时缓存：写 2.0×，读 3 次：2.0 + 3×0.15 = 2.45 vs 3 → ✅ 回本
```

| 场景 | 结论 |
|------|------|
| 会话 ≥2-3 轮且前缀稳定 | 缓存必开 |
| 单次 prompt | 不缓存（写成本纯亏） |
| 前缀含随机 token | 永不命中，白写 |
| 长会话 + 1 小时 TTL | 必开（多次命中摊薄写成本） |

### 2.2 命中率治理

```text
稳态目标：>80% 读命中率
<50% → 查前缀污染（谁在改 system prompt / 工具顺序）
监控：cache_hit_rate 按环境/模型分组
```

## 3. 杠杆二：模型分级路由

```text
原则：任务难度与模型档位匹配——简单任务用廉价模型
```

| 层 | 模型 | 用在哪 | 省 |
|:---:|------|--------|:---:|
| L0 廉价 | flash/nano/haiku | 路由分类、意图识别、简单提取 | 60-90% |
| L1 标准 | pro/sonnet | 常规工具调用、对话 | 基线 |
| L2 旗舰 | 最强模型 | 规划、复杂推理、终审 | 只在高价值处 |

```python
"""model_routing.py — 分级路由"""
def route_model(task: str) -> str:
    """按任务类型选择模型档位（规则版；生产可加学习型路由）"""
    if task in ("classify", "extract_simple", "rewrite"):
        return "deepseek-v4-flash"        # L0：简单任务
    if task in ("plan", "complex_reasoning"):
        return "deepseek-v4-pro"          # L2：复杂推理
    return "deepseek-v4-pro"              # L1：常规（按需配置）
```

| 2026 进阶 | 说明 |
|-----------|------|
| 学习型路由 | pi-smart-router 类：按校准的 P(success) 选廉价层（≥30 条样本才信任） |
| 自适应 | 按任务复杂度动态选档（观测 → 评分 → 决策） |
| 路由评估 | 降档必须过评估门禁（阶段 4：质量不回归才允许省钱） |

## 4. 杠杆三：工具结果 memoization

> "工具结果 memoization 是 Agent 服务成本最大的即时杠杆"——arXiv 2605.27744（2026）

```python
"""tool_memo.py — 工具结果缓存（相同调用不重复付费）"""
import hashlib
import json


class ToolMemo:
    """按 (工具名, 参数哈希) 缓存结果；幂等工具专属"""

    def __init__(self, ttl_seconds=300):
        self._cache = {}
        self.ttl = ttl_seconds

    def key(self, name: str, args: dict) -> str:
        payload = json.dumps({"n": name, "a": args}, sort_keys=True)
        return hashlib.sha256(payload.encode()).hexdigest()

    def call(self, name: str, args: dict, execute):
        k = self.key(name, args)
        hit = self._cache.get(k)
        if hit and hit["ts"] + self.ttl > now():
            return hit["result"]                    # 命中：零成本
        result = execute(name, args)                # 未命中：执行
        self._cache[k] = {"result": result, "ts": now()}
        return result
```

| memoization 纪律 | 说明 |
|-----------------|------|
| 只缓存幂等工具 | 写/副作用工具绝不缓存 |
| TTL 管理 | 数据有实效性（天气 5 分钟、文档永久） |
| 缓存键 | (工具名, 参数哈希)——参数全量参与 |
| 命中监控 | memo 命中率是成本报告的一部分 |

## 6. 预算体系：会话/账户/告警三层

```python
"""cost_budget.py — 三层预算（阶段 4 05 篇的调优版）"""
class BudgetTier:
    """会话级 + 日级 + 速率告警"""

    def __init__(self, session=2.0, daily=50.0, spend_alert_rate=2.0):
        self.session_budget = session          # $/会话
        self.daily_budget = daily              # $/天
        self.spend_alert_rate = spend_alert_rate  # 速率告警：$/小时

    def check(self, session_spend, daily_spend, hourly_rate) -> bool:
        if session_spend >= self.session_budget:
            return False                       # 会话级熔断
        if daily_spend >= self.daily_budget:
            return False                       # 日级熔断
        if hourly_rate > self.spend_alert_rate:
            alert("spend-rate 异常")            # 告警不阻断（早期发现）
        return True
```

| 层 | 作用 | 触发 |
|:---:|------|------|
| 会话预算 | 防单次事故 | 超限即停 |
| 日预算 | 防隔夜失控 | 超限即停 + 告警 |
| spend-rate 告警 | 早期发现 | $0.5/h → $10/h 分钟级发现 |

> ⚠️ **告警先行**：预算熔断是最后防线，spend-rate 告警是第一道发现——正常 $0.5/小时的 Agent 突然 $10/小时，几分钟内就该收到告警（阶段 4 结论）。

## 7. 成本监控指标

| 指标 | 目标 | 告警 |
|------|------|------|
| 每会话成本 | 基线 ±20% | 异常攀升 |
| 缓存命中率 | >80% | <50% |
| memo 命中率 | >30%（工具密集时） | 突降 |
| 重试率 | <3% | 突增 = 风暴前兆 |
| 每完成任务成本 | 成本/质量平衡 | 上升 = 质量没换到 |
| 成本按模型分组 | 每档模型花费占比 | 旗舰占比过高 |

> 🎯 **核心要点**：成本调优四杠杆 + 一体系——**缓存（-85%）、路由（-50%）、memo（工具密集场景）、上下文（-20-30%）、预算体系（防失控）**。成本优化的终极目标不是"最便宜"，是"**每完成任务的成本 × 质量"最优**——省钱的每一步都要过评估门禁。
