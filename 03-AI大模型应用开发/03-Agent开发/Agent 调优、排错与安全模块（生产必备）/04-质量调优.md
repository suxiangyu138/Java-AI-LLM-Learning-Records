## 1. 质量问题的归因分层

回答质量差，先归因再动手（2026 排错经验）：

```text
质量问题归因六层（从外到内）：
① 输入层：用户问题本身有歧义？       → 提示引导/澄清
② 检索层：上下文材料对不对？         → 检索质量（最常见！）
③ 模型层：模型能力够不够？           → 换模型/升级
④ 提示层：指令清不清楚？             → prompt 调优
⑤ 约束层：schema/工具定义好不好？    → 工具调优
⑥ 评估层：是真的差还是评估偏差？     → judge 校准（阶段 4 06 篇）
```

> 🎯 **核心要点**：**归因优先于调参**——2026 经验：大部分"回答变差"是检索或输入问题，不是模型/prompt 问题。先跑六层归因，再动任何参数。

## 2. 调优对象一：Prompt

| 手法 | 做法 | 适用 |
|------|------|------|
| 指令精确化 | "只基于文档回答"→"每个事实句必须带 [D编号]" | 幻觉类 |
| 示例注入 | 加 few-shot 示例（2-5 个） | 格式/风格类 |
| 角色与边界 | 明确角色 + 明确不做的事 | 越界类 |
| 约束前置+后置 | 关键约束开头声明 + 结尾复述 | 长会话约束衰减 |
| 分解提示 | 一个复杂任务拆成多轮简单任务 | 复杂推理 |

```text
Prompt 调优的纪律：
├─ 一次只改一个变量（改完跑评估对比）
├─ 每次改动版本化（prompt v2026-08-03）
├─ 改动必须过 CI 评估门禁（阶段 4 四门禁）
└─ 反面教材：一次改 5 处 → 不知道哪个生效
```

## 3. 调优对象二：Schema 与工具定义

| 症状 | 根因 | 调法 |
|------|------|------|
| 工具参数总错 | schema 类型/描述不清 | enum 约束 + 参数描述实例化 |
| 模型不调工具 | description 模糊 | "做什么 + 何时用 + 边界"公式 |
| 工具选择混淆 | 工具职责重叠 | 合并/拆分/职责文档化 |
| 参数幻觉 | 模型猜参数 | 描述里明示"不知道就问用户" |
| 输出缺字段 | 字段描述不足 | 字段加 description + 默认值语义 |

```python
# 工具描述调优前后对比
BEFORE = """查询天气。"""
AFTER = """查询指定城市的当前天气。当用户询问天气、气温、降雨、出行建议时使用。
参数 city 必须是已支持城市（北京/上海/广州/深圳），其他城市返回错误。
若用户未指定城市，不要猜测，先向用户确认。"""
```

## 4. 调优对象三：采样参数

| 症状 | 参数调整 | 说明 |
|------|---------|------|
| 输出随机不一致 | temperature 0.2 → 0.1/0 | 工具/提取场景固定低值 |
| 输出死板 | temperature 0.7 → 0.9+ | 创意场景 |
| 重复车轱辘 | frequency_penalty 0.3-0.5 | 长文生成 |
| 话题跑偏 | presence_penalty 微调 | 多样性 |
| 输出不稳定 | seed 固定（测试） | 回归对比用 |

> ⚠️ 纪律（阶段 2 结论）：**temperature 与 top_p 二选一**；惩罚类参数与工具场景冲突；参数调整后必须跑评估对比。

## 5. 调优对象四：检索与上下文

| 症状 | 调法 |
|------|------|
| 回答与文档矛盾 | 重排器、召回过滤、信息密度优先 |
| 关键信息淹没 | Lost-in-the-Middle：关键内容放首尾 |
| 上下文太长质量降 | 压缩 + 只传相关块（5 个好的 > 20 个勉强） |
| 引用错误 | 引用强制 + 落库可回查 |
| 幻觉率上升 | 无据拒答 + 验证层（失败模式 03 篇） |

> 💡 检索是质量的第一杠杆（与延迟的成本调优不同，这里它是质量）——**先修输入，再管输出**（失败模式体系结论）。

## 6. A/B 灰度验证

```python
"""ab_test.py — Prompt/模型变更的 A/B 灰度（2026 标准流程）"""
# ① 金丝雀：1-5% 流量跑新版本
# ② 在线采样评估：同款 judge 打分（阶段 4 06 篇）
# ③ 决策门禁：
#    - 聚合分数不回归（>1% 阻断）
#    - 单项不回归（>3-5% 阻断）
#    - 安全类任何 PASS→FAIL 即阻断
# ④ 全量 or 回滚（版本化支持一键回滚）

def canary_decision(scores_new, scores_old, safety_flags) -> str:
    if safety_flags:
        return "block"                    # 安全回归 = 硬阻断
    if mean(scores_new) < mean(scores_old) - 0.01:
        return "block"                    # 聚合回归
    return "promote"
```

| 步骤 | 产出 |
|------|------|
| 基线采集 | 变更前 1 周数据 |
| 金丝雀 | 1-5% 流量 + 评估 |
| 对比 | 逐标准 diff（correctness +2%, tone -1%） |
| 决策 | 门禁自动 + 人工复核 |
| 记录 | 版本化 + 收益复盘 |

## 7. 质量调优决策树

```text
回答质量差 → 六层归因：
① 输入歧义？ → 澄清引导
② 检索不对？ → 检索调优（重排/过滤）⭐⭐⭐⭐ 最常见
③ 模型不够？ → 升级模型/换推理模型
④ 指令不清？ → prompt 调优（一次一变量）
⑤ schema 差？ → 工具调优（描述/enum）
⑥ 评估偏差？ → judge 校准后再判

每个调整 → A/B 灰度 → 评估门禁 → 版本化
```

> 🎯 **核心要点**：质量调优 = **归因六层 + 四类对象 + A/B 纪律**。记忆三句话：先归因再调参、一次只改一个变量、每个改动过门禁。质量是四维中最难量化的一维——judge 校准（阶段 4）是它的地基。
