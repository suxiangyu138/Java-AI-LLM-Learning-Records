## 5. 调优专用

| 工具 | 用途 | 数据 |
|------|------|------|
| vLLM Router | 前缀感知路由 | HashTrie/xxhash64，O(1) 查找 |
| llm-d（CNCF Sandbox） | K8s 原生缓存路由 | TTFT p90 57× 提升实测 |
| NVIDIA Dynamo | 推理分离 + KV 路由 | prefill/decode 分离 |
| pi-smart-router | 成本感知分层路由 | 校准 P(success)，≥30 样本信任 |
| QUARTZ | SLO 感知路由 | 分位数成本代理 + 队列感知 |

> 💡 调优工具属于**自托管推理栈**——API 用户（DeepSeek/OpenAI）的主战场是 prompt caching（02 篇）而非这些路由器。

## 6. 排错专用

| 工具 | 用途 | 价值 |
|------|------|------|
| Monte Carlo Troubleshooting Agent | 自动 RCA | 失败 trace 对比基线 + 部署事件关联（30-60 分钟 → 分钟级） |
| agent-triage（开源） | 策略提取 + 根因分类 | prompt 策略级诊断 |

| 失败样本回流 | 问题会话 → 黄金集 | 评估闭环（阶段 4） |

## 7. 选型主线

```text
预算有限 / 开源优先？
├─ 是 → Langfuse（追踪）+ DeepEval/Promptfoo（评估）+ OTel 自建
├─ LangChain 栈 → LangSmith（追踪+评估一体）
└─ 企业合规 → Langfuse 自托管 + Braintrust（可选）
自托管推理？→ vLLM Router / llm-d（缓存路由）
多供应商？→ LiteLLM / Portkey 网关
AI 排错？→ Monte Carlo TSA（商业）或 agent-triage（开源）
```

**最小可用组合（上线即可）**：

```text
追踪：Langfuse 或 LangSmith（二选一）
评估：自建 pytest + judge（五模式）+ golden dataset
网关：LiteLLM（多供应商）
排错：trace 平台 + 失败样本回流 + 速查表（06 篇）
调优：prompt caching 基线（02/03 篇）
```

> 🎯 **核心要点**：工具箱的秩序 = **追踪打底、评估做闸、网关统一、调优按栈、排错加速**。最贵的工具是"买了不用的平台"——2026 共识：工具花 1-2 周接入，**真正的工作量在数据集与校准**（阶段 4 结论：硬核不是工具）。
