## 2. 生产部署清单

| 领域 | 项 | 要点 |
|---|---|---|
| 拓扑 | 前后端分离 | Agent 引擎独立服务，UI 只走 HTTP/SSE（或 WS）；引擎可水平扩展 |
| 反向代理 | Nginx | SSE 路径 `proxy_buffering off` + `X-Accel-Buffering: no`；WS 路径配 Upgrade 头 |
| 会话持久化 | 数据库 | 消息/状态落库（SQLite→PG 迁移路径）；Chainlit Data Layer / Open WebUI PG |
| 多用户隔离 | 会话+数据 | 按用户隔离会话；**禁止把用户 A 的上下文泄漏给 B**（常见事故） |
| 鉴权 | 认证 | 密码/OAuth/SSO（LobeChat Better Auth、Open WebUI OIDC+SCIM）；内网≠免鉴权 |
| 限流 | 用量控制 | 按用户/会话限流（token 数与请求频率）；防止 API key 被盗刷 |
| 成本 | 中断控制 | 客户端失联 60s 超时中止生成；空闲清理任务 |
| 安全 | 输入输出 | 提示注入防御（工具参数校验）；渲染侧 XSS（Markdown 白名单）；工具结果脱敏后再进 UI |
| 可观测 | 日志/追踪 | 会话级 trace（请求 id 贯穿 UI→引擎→模型）；记录每步工具调用耗时 |
| 部署形态 | 容器 | 官方镜像 + 固定版本 tag；升级前备份（Open WebUI 0.11 必须备份 DB） |

### 2.1 安全专项：界面层最容易漏的三件事

| 风险面 | 攻击路径 | 防线 |
|---|---|---|
| 渲染 XSS | 模型输出/工具结果含恶意 HTML，`innerHTML` 直接拼接 | 渲染前 HTML 转义（marked 默认转义）；Markdown 白名单（禁 script/iframe）；外部 CDN 脚本带 SRI |
| 提示注入直达 UI | 网页/文档中的恶意指令被 Agent 采信，UI 把它当"结论"展示 | 工具结果与指令分域渲染（结果区禁用可点击执行元素）；敏感操作走审批（HITL） |
| 控制接口滥用 | 停止/审批/分支接口未鉴权，被外部调用 | 控制端点与业务端点同权校验（Cookie/Session/Token）；审批签名一次性有效 |

> 💡 详见体系 [08-Agent 专属界面](08-Agent专属界面：思考过程与工具调用可视化.md) 第 7 节（安全与治理红线）与[幻觉、格式错误、安全、token 超限](../../幻觉、格式错误、安全、token%20超限/00-Agent四大失败模式知识体系总览.md)体系的提示注入篇。

## 3. 性能优化：流式体验三件套

| 指标 | 优化 | 手段 |
|---|---|---|
| 首 token 延迟（TTFT） | 最小化 | 就近选模型端点、关闭不必要中间件、避免首包缓冲 |
| 渲染帧率 | 每帧批量 | token 累积 + requestAnimationFrame 合并；虚拟列表渲染长消息 |
| 长回复体验 | 分段渲染 | Markdown 每 ~1000 字分段解析渲染，避免整段重排；代码块延迟高亮 |

### 3.1 可观测性三指标（上线后必看）

| 指标 | 定义 | 异常信号 |
|---|---|---|
| TTFT（首 token 延迟） | 发出请求到首个 token 落地 | >3s：模型端慢 or 代理缓冲 |
| TPS（tokens/秒） | 流式生成速率 | 突然下降：限流/排队/网络抖动 |
| 工具调用失败率 | 工具出错占比 | 上升：上游 API 变更 or 参数错误 |

落地：请求 id（`X-Request-Id`）贯穿 UI→引擎→模型；工具调用记开始/结束/耗时；错误事件（`error` 流内事件）计数告警。免费方案 Prometheus + Grafana，或 LLM 可观测平台（Langfuse 等）。

## 4. 12 避坑清单

| # | 坑 | 后果 | 解法 |
|---|---|---|---|
| 1 | SSE 路径没关代理缓冲 | 打字机变整段吐 | 缓冲三件套（见 02 篇 7 节） |
| 2 | 无双向需求硬上 WebSocket | 代理穿透/重连/扩容全都要重做 | SSE + POST 写路径 |
| 3 | 工具调用按 chunk 直接 JSON.parse | 解析异常、参数丢失 | 按调用 id 累积缓冲 |
| 4 | 错误写在响应头之后（HTTP 状态码） | 用户看到空白 | 流内 error 事件 |
| 5 | Streamlit 状态放局部变量 | 每次 rerun 丢失 | session_state 统一管 |
| 6 | Chainlit 不配认证直接公网 | 模型被盗刷 | 必须配认证（默认公开） |
| 7 | 过程可视化全量展开 | 用户过载、泄露内部提示词 | 渐进式披露（08 篇） |
| 8 | 只给答案不给引用 | 信任崩塌 | RAG 必须带 citation |
| 9 | 客户端失联不中断生成 | 白烧 token | 超时 abort |
| 10 | 会话上下文跨用户泄漏 | 数据事故 | 按用户隔离 + 测试验证 |
| 11 | 生产环境用 latest 镜像 tag | 升级炸库 | 锁版本 + 备份 |
| 12 | 只测 happy path | 断线/限流/超时没处理 | 故障演练：断网、429、长流截断 |

## 5. 面试题（高频 12 题 + 答题要点）

| 题 | 答题要点 |
|---|---|
| 1. 聊天流式怎么实现？ | SSE 事件流：后端 StreamingResponse 透传模型流 → 前端 EventSource 增量渲染；打字机效果的三个关键（不缓冲、flush、rAF 批量） |
| 2. SSE 和 WebSocket 怎么选？ | 单向流默认 SSE（HTTP 友好/自动重连/轻量）；双向需求（取消/审批/语音/多 Agent）才 WebSocket；混合模式最佳 |
| 3. SSE 首包为什么慢/卡？ | 代理缓冲（Nginx `proxy_buffering off`、`Cache-Control: no-cache`、X-Accel-Buffering）；心跳防空闲断开 |
| 4. 工具调用参数乱码/半截？ | 流式部分 JSON 按 id 累积再解析；失败时把错误 JSON 回传给模型（80% 卡死由此消除） |
| 5. Agent 界面和聊天界面区别？ | 过程可视化（工具卡片/思考块/引用）+ 控制平面（中断/审批/检查点）；渐进式披露原则 |
| 6. 如何让用户相信 Agent 的答案？ | 引用溯源（citation）、工具过程可审计、错误透明（流内 error 而非空白） |
| 7. 多用户部署注意什么？ | 会话隔离、数据落库、鉴权/限流、水平扩展时会话粘滞或 Redis Pub/Sub |
| 8. 你在项目中怎么选型界面框架？ | 按阶段：验证期 Streamlit/Gradio → 产品期 Chainlit（Python）或 AI SDK（前端）；选型看"对话/数据/多模态/定制/团队"五维 |
| 9. SSE 的心跳和重连怎么设计？ | 每 15-30s 发 `: ping` 注释行防代理空闲断开；事件带 `id` + `Last-Event-ID` 续传；前端兜底 3s 无事件提示"继续等待/停止" |
| 10. 工具审批（HITL）在界面上怎么实现？ | 危险工具标记 `needs_approval` → 事件流发 approval 请求 → UI 弹确认卡 → 用户批准走写路径（POST）回传 → Agent 继续；拒绝则回传拒绝原因让模型调整。AI SDK 的 needsApproval 与 Chainlit Action 都是此模式 |
| 11. Streamlit rerun 模型会导致什么坑？ | 脚本每次交互全量重跑：局部变量清零、组件状态靠返回值、缓存跨用户共享——所以状态必须集中到 session_state，跨用户数据落库 |
| 12. 为什么说"UI 是控制平面"？ | 现代 Agent 界面除渲染外还承担中断、审批、检查点、分支、回放——协议侧由控制事件（POST 写路径）支撑，设计时把 UI 当作 Agent 的遥控器而非显示器 |

## 6. 落地检查单（上线前逐项打勾）

```text
□ SSE 路径反代缓冲已关，首 token < 1s
□ 工具调用错误能回流给模型；流内 error 事件有 UI 呈现
□ 停止生成可中止上游模型请求（不白烧钱）
□ 多用户会话隔离经过测试（A 用户看不到 B 的上下文）
□ 鉴权+限流已配置；内网部署也非默认公开
□ RAG 答案带可点击引用
□ 思考/工具过程默认折叠，敏感内容脱敏
□ 断线重连有兜底（自动重连 + 3s 静默提示）
□ 生产镜像锁版本，数据库有备份演练
□ 会话级可观测（trace id 贯穿 UI→引擎→模型）
```
