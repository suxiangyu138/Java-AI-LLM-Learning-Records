# 搜索引擎原理与检索基础

> 爬虫 → 索引 → 排序是搜索引擎的百年不变骨架；2026 的新变化是"专为 AI 答案设计的 Grounding 索引"。理解原理才能用好 API。

## 1. 三阶段流水线

```text
爬虫（Crawl）→ 索引（Index）→ 排序（Rank）→ SERP
     ↓              ↓              ↓
  发现网页       建立倒排索引    打分排序
```

### 1.1 爬虫：发现与获取

| 机制 | 说明 |
|---|---|
| URL Frontier | 分布式优先队列，按 `(priority DESC, next_crawl_time)` 分区，按 `domain_hash` 做每主机限速 |
| 礼貌策略（Politeness） | 每主机最多一个并发请求 + 主机特定延迟 + 自适应退避 + 处理 429/503 |
| 爬取预算 | 大站（1 万+ URL）须避免浪费：去重、防 faceted URL、防会话 ID、防 4xx |
| 发现方式 | 内链、外链、XML sitemap（`lastmod`）、RSS、**IndexNow**（Bing/Yandex 支持，Google 不支持） |
| 渲染 | Googlebot 用 Web Rendering Service 渲染 JS——服务端渲染内容索引更快更稳 |

> 💡 robots.txt 是爬虫的"交通规则"——Agent 自建爬虫必须遵守（见 [08](08-搜索安全与内容信任.md) 合规部分）。

### 1.2 索引：倒排索引

- **倒排索引（Inverted Index）**：词项 → 文档列表（posting list）的映射，是搜索的核心数据结构
- 压缩技术：delta-encoded 文档 ID、variable-byte 词频、delta-encoded 位置（短语查询用）
- **增量索引**：Google Caffeine（2010）用 Percolator（Bigtable 上的跨行 ACID + observers）替代批处理——文档在结果中的"年龄"减半、单文档延迟提升 ~100×
- 存储矩阵：网页存 Bigtable、倒排索引存自定义分片、URL Frontier 存分布式队列、查询缓存用 Memcached 类、PageRank 存 Bigtable
- 移动优先索引（2020-09 起）：默认用移动版页面索引与排序

### 1.3 排序：打分模型

| 算法 | 原理 | 用途 |
|---|---|---|
| TF-IDF | 词频 × 逆文档频率 | 经典相关性基线 |
| BM25 | TF-IDF 增强：词频饱和 + 文档长度归一化（k1=1.2, b=0.75） | **Elasticsearch 默认** |
| PageRank | 随机游走模型：入链传递权威（阻尼因子 0.85） | 页面质量 |
| 现代排序 | 200+ 信号：Core Web Vitals（LCP<2.5s、INP<200ms、CLS<0.1）、E-E-A-T、时新性、实体权威 | Google 实际排序 |

**复合打分示意**：

```text
final_score = α·BM25 相关性(0.40) + β·PageRank/域名权威(0.30)
            + γ·时新性(0.15) + δ·个性化(0.10) + ε·本地化(0.05)
```

## 2. 语义搜索与向量检索

- 传统搜索匹配"词"，语义搜索匹配"意"：Embedding 把查询与文档投影到向量空间，按余弦相似度检索
- 2026 现状：主流引擎（Google/Bing）已是"关键词 + 语义"混合；**Exa 等 AI 搜索引擎完全向量化**（neural 模式）
- 语义检索的代价：延迟更高（~1.5s）、精确事实查询可能"过度联想"（找相似≠找正确）

## 3. 2026 新形态：AI Grounding 索引

| 维度 | 传统索引 | AI Grounding 索引（Bing 等） |
|---|---|---|
| 检索单位 | 整页 | **段落（passage）级** |
| 目标 | 结果相关性（蓝色链接排序） | **合成答案的证据质量** |
| 核心要求 | 相关性 | 事实保真、来源清晰、时新、能表达矛盾 |
| 失败处理 | 排名靠后 | **"弃答（abstention）而非合成"** |
| 评价指标 | 点击率/排名 | 引用次数、Grounding 查询数（Bing AI Performance 面板，2026-02） |

**对 Agent 的含义**：

- 段落级检索更适合 RAG/上下文拼接——搜到"一段可用证据"而非"一页要清洗"
- `data-nosnippet`（2025-10）让发布者把部分内容排除出 AI 答案但仍保持收录
- **GEO（Generative Engine Optimization）**：内容方开始为"被 AI 引用"而优化——与 Agent 侧"内容信任"直接相关（见 [08](08-搜索安全与内容信任.md)）

## 4. 对 Agent 开发的实用结论

1. **SERP ≠ 答案**：搜索 API 返回的是"候选链接 + 摘要"，不是事实——Agent 必须 fetch 原文再综合
2. **索引有界**：任何 API 都受索引覆盖限制（Brave 独立索引对长尾查询有洞；Exa 对实时新闻弱）——生产用多家互补
3. **排序可被操纵**：PageRank 时代靠链接，AI 时代靠投毒——搜索结果的"排名高"不等于"可信"（见 [08](08-搜索安全与内容信任.md)）
4. **段落级 > 整页级**：选择返回"LLM-ready 片段"的 API（Tavily/Exa）比拿整页自己清洗省事省 token

## 面试速记

1. 搜索引擎三阶段：爬虫（礼貌+预算）、索引（倒排+增量）、排序（BM25+PageRank+200 信号）。
2. BM25 是 ES 默认：TF 饱和 + 长度归一化；PageRank 是入链权威模型（阻尼 0.85）。
3. 语义搜索基于 Embedding 相似度，找"意"不找"词"；Exa 全向量化，精确事实查询反而弱。
4. AI Grounding 索引：段落级检索、事实保真、弃答优先于瞎答；`data-nosnippet` 可排除。
5. SERP 是候选不是答案；排序可被 SEO 操纵——Agent 必须 fetch 原文 + 交叉验证。
