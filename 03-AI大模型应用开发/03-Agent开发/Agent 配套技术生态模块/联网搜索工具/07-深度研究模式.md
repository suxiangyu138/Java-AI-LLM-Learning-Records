# 深度研究（Deep Research）模式

> 搜索能力的终极形态：把"搜索"升级为"研究"——多轮搜索、并行抓取、事实验证、报告写作的自主流水线。2026 各家方案与基准实测。

## 1. 通用八步流水线（架构共识）

```text
1. 答案格式检测    分类"什么样的答案才算答对"（对比表/综述/带引用的论断）
2. 查询规划        生成分层查询（最多 3 层递归深度，planner agent）
3. 并行抓取        所有 URL 并发 fetch
4. 可信度评分      每来源 0-100 打分（域名权威/时新性/相关性）
5. MMR 多样性过滤  最大边际相关：高可信 + 观点多样
6. 事实验证循环    每条论断回源核对
7. 报告写作        按结构化格式综合
8. 批判修正循环    领域专家/对抗/来源保真/数学逻辑四类 critic 迭代
```

> 💡 与普通多轮搜索的区别：**有验证与批判环节**——研究不是"搜到就写"，而是"每条断言都有来源支撑、经对抗审查"。

## 2. 各家方案对比（2026）

| 方案 | 架构 | 亮点 | 局限 |
|---|---|---|---|
| **OpenAI Deep Research**（o4-mini-deep-research） | 模型内建 `web_search_preview` + `code_interpreter` 工具 | Responses API 原生、后台模式+轮询 | DeepResearch Bench 46.45；DRACO 41.9%、SimpleQA 20.2%，性价比低 |
| **Claude Research** | Claude Cowork 桌面 Agent（2026-01） | 沙箱 VM + 浏览器控制 + MCP 应用连接 | RACE 45，低于 Gemini/OpenAI |
| **Gemini 2.5 Pro（Deep Research）** | Grounding + 深度检索 | **RACE 49.71（最高之一）** | 依赖 Google 生态 |
| **Perplexity Sonar Deep Research** | 搜索 API 深度模式 | **性价比之王**：~$0.06/次、3 分钟、DRACO 70.5%、SimpleQA 93.9%、引用准确率 90.24% | 深度不如大模型组合 |
| **Perplexity Computer**（2026-02） | **19 模型编排**：Model Council 路由子任务给最优模型（Claude Opus 4.6 推理、Gemini 深度研究、GPT-5.2 长上下文搜索、Grok 轻量） | 模型即专家；隔离计算环境 + 子 Agent 并行；任务可跑数小时到数月 | 中途中途切换模型可能不一致；上下文填满后漂移 |
| **Tavily Research** | `/research` 端点（async） | **RACE 52.44（榜单第一）** | 与 Google 索引重叠 |
| **开源**（deepthink-js / deep-researcher-reflect-evolve） | 上述八步流水线实现 | 免费自托管、可插拔模型 | 需自管基础设施 |

## 4. 关键实现细节（自建时）

### 4.1 状态与记忆

- 集中式记忆：**保留数字/日期/证据**（不丢数据是研究 Agent 的核心）
- 顺序反思（sequential reflection）：每步生成计划 → 反思调整 → 执行
- 候选交叉（candidates crossover）：多个研究分支的发现互相补充

### 4.2 异步与预算

| 项 | 规范 |
|---|---|
| 后台模式 | 任务即发即回 task_id，`research_status` 轮询 |
| 批并发 | 子查询并行（1-32），按索引容量限流 |
| 成本上限 | 会话级 spending cap（Perplexity Computer 支持按模型设上限） |
| 时间上限 | 总时长预算（分钟级到小时级） |

### 4.3 MCP 化（研究能力即插即用）

```bash
# 把深度研究变成 MCP 工具，Claude Code / Codex / Gemini CLI 一行接入
claude mcp add deep-research -- npx deep-research-mcp
# deep-research-hub-mcp：Perplexity 默认 + OpenAI 升级兜底
```

统一返回结构：report、citations、reasoning steps、task_id、execution time——**研究结果可审计**。

## 5. 自建 vs 托管研究

| 维度 | 托管（Perplexity Sonar / OpenAI DR） | 自建八步流水线 |
|---|---|---|
| 成本 | 低（$0.06-0.9/次） | 模型+抓取成本自担 |
| 可控 | 黑盒（不可见中间步骤） | 全可见可调 |
| 定制 | 固定流程 | 可改验证/批判环节 |
| 数据 | 走第三方 | 不出内网 |
| 适用 | 快速交付 | 合规/深度定制 |

## 6. 研究 Agent 的失败模式

| 失败模式 | 对策 |
|---|---|
| 来源偏差（只采信首个高排名源） | MMR 多样性 + 交叉验证 |
| 事实漂移（长任务中前后矛盾） | 集中式证据记忆 + 每断言回源 |
| 上下文填满 | 分阶段压缩 + 结构化工单（task_budget） |
| 搜索循环失控 | 终止四条件（见 [06](06-Agent搜索策略与查询工程.md)） |
| 投毒内容混入 | 内容信任层 + 数据-指令边界（见 [08](08-搜索安全与内容信任.md)） |

## 面试速记

1. 深度研究八步：格式检测→查询规划→并行抓取→可信度评分→MMR 过滤→事实验证→写作→批判循环。
2. 榜单：Tavily 52.44 > Gemini 2.5 Pro 49.71 > OpenAI 46.45 > Claude 45；但生产性价比 Perplexity Sonar 最优（$0.06、3 分钟、DRACO 70.5%）。
3. Perplexity Computer：19 模型编排（Model Council 路由），模型即专家。
4. 关键实现：集中式证据记忆、顺序反思、候选交叉、异步+预算上限。
5. 研究可审计：MCP 返回 report/citations/reasoning steps/task_id。
