# Agent 搜索策略与查询工程

> 搜索质量不在 API，在策略：查询改写、多轮/并行搜索、重排过滤、采集循环——把"一次搜索"升级为"一次研究"。

## 1. 为什么需要策略层

原生搜索工具解决了"会不会搜"，但**搜得好不好取决于策略**：

| 无策略 | 有策略 |
|---|---|
| 用户原话直接搜 | 改写为多角度查询 |
| 一轮搜索就答 | 多轮迭代 + 交叉验证 |
| 结果全塞上下文 | 重排过滤只留高信任 |
| 一条查询串 | 并行 3-5 条覆盖不同角度 |

## 2. 查询改写（Query Rewriting）

把 Agent 的子任务意图翻译为搜索引擎友好的查询：

| 技巧 | 示例 |
|---|---|
| 拆解多意图 | "对比 RAG 方案选型" → "RAG 向量数据库对比 2026" + "RAG 选型 避坑" |
| 补全上下文 | "它的价格？" → "LangChain4j 定价 2026" |
| 加限定词 | 版本号/年份/地域（"Spring AI 2.0 中文文档"） |
| 中英文双查 | 中文 + 英文查询互补（中文生态/英文一手资料） |
| 实体化 | 把口语变成专有名词（"那个国产向量库" → "Milvus"） |

```text
用户问题："现在做大模型应用用哪个框架好"
改写 1："AI agent 框架对比 2026 LangChain LangGraph 趋势"
改写 2："大模型应用开发框架 选型 2026"
改写 3："agent framework comparison 2026"
```

> 💡 查询改写本身是一个 LLM 调用（成本低），效果显著——研究类任务可改写出 3-5 条并行查询。

## 3. 多轮搜索与搜索规划

### 3.1 单轮 vs 多轮

| 模式 | 适用 | 流程 |
|---|---|---|
| 单轮（1-3 次） | 事实查询 | 搜 → 提取 → 答 |
| 多轮（5-15 次） | 复杂问题/研究 | 搜 → 读 → 发现子问题 → 再搜 → 交叉验证 → 答 |
| 规划式 | 大主题 | 先规划子问题清单 → 逐个子问题搜索 → 汇总 |

### 3.2 Claude 原生多轮语义

- `max_uses` 控制单请求搜索次数：简单查询 1-3、多实体研究 10+
- 多轮会话 `encrypted_content` 必须原样回传（否则 400）
- 长搜索返回 `pause_turn` → 原样回传继续（服务端内部完成多步再 checkpoint）

### 3.3 规划式搜索（研究任务标准姿势）

```text
1. 分解：把主问题拆成 3-8 个子问题（实体/对比/时间线/坑点）
2. 规划：每个子问题 → 1-3 条查询串
3. 执行：并行发查询（asyncio.gather 或 pi-codex-search 1-32 并行）
4. 阅读：提取原文，标注每条的"子问题归属"
5. 验证：冲突信息再搜佐证
6. 综合：按子问题组织答案，逐条带引用
```

## 4. 重排与过滤（内容信任层）

搜索结果必须过滤后才能进上下文：

| 过滤器 | 规则 |
|---|---|
| 域名白/黑名单 | `allowed_domains`（官方文档/权威媒体）+ `blocked_domains`（已知恶意） |
| 信任评分 | 域名权威（edu/gov/官方域名加分）+ 交叉验证（多源一致）+ 时新性 |
| 相关性重排 | Tavily relevance score / MMR 多样性（去冗余保留观点差异） |
| 内容预处理 | 去广告/导航/脚本；只保留正文段落；**剥离 HTML 注释与隐藏样式**（防注入，见 [08](08-搜索安全与内容信任.md)） |
| 长度截断 | 每条内容 ≤4000 字符；只保留匹配段落 |

```python
# 信任评分示意
def trust_score(source: dict) -> float:
    score = 0.0
    score += 0.3 if source["domain"] in TRUSTED_DOMAINS else 0
    score += 0.2 * source.get("relevance_score", 0)     # Tavily 相关性
    score += 0.3 if source.get("date") and fresh(source["date"]) else 0
    score += 0.2 * cross_validation_count(source)       # 多源一致度
    return score
```

## 5. 采集循环（信息收集回路）

```text
┌──────────────┐   子问题    ┌──────────────┐
│ 查询规划      │ ──────────→ │ 并行搜索      │
└──────────────┘             └──────┬───────┘
      ↑                             ↓
┌──────────────┐   新线索    ┌──────────────┐
│ 综合与回答    │ ←────────── │ 提取+过滤     │
└──────────────┘             └──────────────┘
```

**循环终止条件**（防死循环）：

1. 子问题全部有答案（≥1 个高信任来源）
2. 达到搜索次数上限（`max_uses` / 预算）
3. 连续 2 轮无新信息（信息饱和）
4. 总时间/成本超预算

## 6. 新鲜度策略

| 场景 | 新鲜度要求 | 策略 |
|---|---|---|
| 版本/价格/新闻 | 小时级 | 禁用缓存（`live`/`external_web_access: live`），时间过滤（`time_range`） |
| 教程/文档 | 周级 | 缓存 24h，优先官方域 |
| 稳定知识 | 月级 | 模型知识优先，搜索兜底 |

## 7. 实战质量对比（有无策略的差距）

| 指标 | 无策略 | 有策略（改写+并行+验证） |
|---|---|---|
| 查询数/任务 | 1-2 | 5-15 |
| 事实错误 | 常见 | 交叉验证后大幅下降 |
| 覆盖率 | 单角度 | 多角度（中英/实体/时间线） |
| Token 消耗 | 全塞（高） | 过滤后（低） |

## 面试速记

1. 查询改写四技巧：拆意图、补上下文、加限定、中英双查。
2. 规划式搜索六步：分解→规划→并行执行→阅读→验证→综合。
3. 过滤层四件事：域名黑白名单、信任评分、MMR 去冗余、剥离隐藏内容。
4. 循环终止四条件：子问题有答案/次数上限/信息饱和/预算超限。
5. 新鲜度分三档：小时级（live）/周级（缓存 24h）/月级（模型知识优先）。
