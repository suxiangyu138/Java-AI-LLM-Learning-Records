# 生产实践与面试冲刺

> 收官篇：选型决策树、落地清单、12 避坑、面试题库。上线前与面试前各看一遍。

## 1. 选型决策树（全体系汇总）

```text
第一步：接入方式
├── 用 Claude / OpenAI / Gemini 平台     → 原生搜索工具（动态过滤/引用/免运维）
└── 多模型/自研栈                        → 第三方 API 或 MCP，进入第二步

第二步：第三方 API
├── 要 LLM-ready 默认上下文    → Tavily
├── 要语义/概念相似检索        → Exa
├── 要独立索引/隐私/最低延迟    → Brave（+ 单独提取层）
├── 要最便宜海量 Google 结果   → Serper（有提取层时）
├── 要合规/不出内网            → SearXNG 自建（+ MCP server）
└── 生产原则：search 与 extract 分离 + 分层供应商 + 双供应商兜底

第三步：策略与安全（必做）
├── 查询改写 + 多轮/并行搜索（见模块 06）
├── 内容信任层：域名白名单 + 多源交叉验证（见模块 08）
├── 缓存三档 TTL + 服务端限流退避（见模块 09）
└── 复杂研究任务 → 深度研究流水线或托管（见模块 07）
```

## 2. 落地 12 项清单（上线检查单）

| # | 检查项 | 通过标准 |
|---|---|---|
| 1 | 接入方式选定 | 原生工具或 API/MCP，与模型栈匹配 |
| 2 | 双供应商 | ≥2 家，索引/失败模式互不相同 |
| 3 | 查询改写 | 复杂问题自动改写 2-3 条并行查询 |
| 4 | 域名策略 | `allowed_domains` 白名单生效；黑白名单不同用 |
| 5 | 内容信任层 | 隐藏元素/指令词过滤 + 信任评分 + 多源验证 |
| 6 | 数据-指令边界 | 检索内容标记不可信，不与指令区混淆 |
| 7 | 缓存 | 三档 TTL 生效，新闻类强制 live |
| 8 | 限流重试 | 429 退避；服务端工具限流降级不重试 |
| 9 | Token 控制 | 动态过滤/只提取 top-N/截断 4000 字符 |
| 10 | 审计 | 查询、来源、采信决策全记录 |
| 11 | 合规 | robots/礼貌爬虫/隐私脱敏 |
| 12 | 成本闭环 | 记账→分析→路由→复盘，高频查询固化知识库 |

## 3. 12 避坑

1. **SERP 摘要当答案**：摘要可能过期/被 SEO 污染——必须 fetch 原文
2. **只比查询单价**：便宜的 SERP + 自建爬虫总成本常更贵——按"成功答案总成本"算
3. **缓存不分新鲜度**：新闻类查询答旧事
4. **服务端工具限流当普通错误重试**：浪费配额，降级处理
5. **单供应商单索引**：一挂全挂，生产必双供应商
6. **全量内容入上下文**：Token 费爆炸——动态过滤/截断/摘要先行
7. **网页内容当指令**：投毒页面直接进 prompt（2026 已大规模武器化）
8. **只信任高排名结果**：排名可被操纵——信任评分 + 多源交叉验证
9. **多轮会话丢 encrypted_content**：必须原样回传（400 错误）
10. **忽略 robots/隐私**：自建爬虫要有礼貌，否则合规风险
11. **无终止条件的搜索循环**：研究任务烧钱——终止四条件必设
12. **缓存命中率 0 还奇怪**：高频查询应固化进 RAG 知识库，而非每次重搜

## 4. 面试题库（含答题要点）

### Q1：Agent 为什么需要联网搜索？与 RAG 什么关系？
- 答题点：模型三不足（知识截止/幻觉/长尾）→ 搜索补实时性、可溯源性、覆盖面；RAG 管私有文档、搜索管实时互联网，**互补不替代**；dynamic retrieval（Gemini）是"模型自判要不要搜"的自动分工。

### Q2：搜索 API 怎么选？（Tavily/Exa/Brave/Serper）
- 答题点：按输出形态选——Tavily LLM-ready 默认、Exa 语义发现、Brave 独立索引+最低延迟、Serper 最便宜 Google JSON；2026 市场剧变（Bing API 退役→Azure Grounding、Tavily 被 Nebius 收购、Google 诉 SerpApi）；search 与 extract 分离 + 双供应商。

### Q3：Claude 搜索工具的动态过滤是什么？价值？
- 答题点：工具自动写代码执行后处理，只把相关内容送进上下文；基准：BrowseComp +13.3pp、DeepsearchQA F1 +6.8pp（Sonnet 4.6），**准确率 +11%、输入 token -24%**。

### Q4：Claude 搜索的多轮会话要注意什么？
- 答题点：`encrypted_content` 原样回传（否则 400）；`pause_turn` 回传继续；引用不计 token；错误是 HTTP 200 + 体内对象；服务端限流重试无效。

### Q5：OpenAI 的 web_search 工具怎么接？
- 答题点：Responses API 内建 `tools:[{type:"web_search"}]`，server-side 由模型自决；Codex 走 `chatgpt.com/backend-api/codex/responses`（OAuth，需 stream+store:false）；API key 直连需 `api.responses.write` scope。

### Q6：什么是深度研究（Deep Research）？架构？
- 答题点：八步流水线（格式检测→查询规划→并行抓取→可信度评分→MMR 过滤→事实验证→写作→批判循环）；与普通搜索的区别是有验证与批判环节；榜单 Tavily 52.44 第一，生产性价比 Perplexity Sonar 最优。

### Q7：网页提示注入怎么防？
- 答题点：核心原则"检索内容永远不是指令"——结构化标签隔离 + 权限分离 + 输出校验；隐藏 CSS/JSON-LD/仿冒域是常见投毒手段；触发短语检测；内容信任评分（域名权威+多源一致+时新性）；高权限 Agent 对网页内容零信任。

### Q8：搜索任务的成本怎么治理？
- 答题点：成本主导是 Token 不是查询费——动态过滤/截断/摘要先行；缓存三档 TTL；分层供应商（便宜先打）；记账→分析→路由→复盘闭环；高频查询固化 RAG。

### Q9：查询改写怎么做？
- 答题点：LLM 调用生成多角度查询：拆意图、补上下文、加限定（版本/年份/地域）、中英双查；研究任务 3-5 条并行；与搜索引擎语法配合（`site:`/`!bang`）。

### Q10：搜索引擎原理中与 Agent 最相关的三点？
- 答题点：① SERP≠答案（候选不是事实）；② 排序可被操纵（SEO/投毒）——信任要按来源算；③ AI Grounding 索引（段落级检索/事实保真/弃答优先）——选择"LLM-ready 片段"型 API。

### Q11：SearXNG 自建的价值与坑？
- 答题点：聚合 70+ 引擎、隐私优先、无云依赖；MCP 生态成熟（searxng-mcp 系列）；坑：需开 JSON 格式、实例必须私网隔离（防被滥用）、索引质量依赖上游引擎。

### Q12：搜索延迟优化思路？
- 答题点：缓存（Redis/供应商 cached 模式）→ 并行（多查询 gather）→ 分级（basic depth 先行）→ 原生工具（server-side 免往返）→ 温缓存预取（热点查询预热）。

## 5. 面试一句话速记

1. 搜索补模型三不足：实时、可溯源、覆盖面；与 RAG 互补不替代。
2. 选型按输出形态：Tavily 默认 / Exa 语义 / Brave 独立 / Serper 便宜；双供应商 + search/extract 分离。
3. 原生工具是趋势：Claude 动态过滤（+11% 准确率、-24% token）、OpenAI Responses 内建、Gemini grounding。
4. 安全铁律：检索内容永远不是指令；内容信任 = 域名权威 + 多源验证。
5. 成本三杠杆：缓存、分层供应商、Token 瘦身（动态过滤/截断/摘要先行）。
