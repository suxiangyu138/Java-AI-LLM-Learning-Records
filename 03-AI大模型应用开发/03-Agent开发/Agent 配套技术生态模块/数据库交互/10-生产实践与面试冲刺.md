# 生产实践与面试冲刺

> 从"能查"到"能上"：选型决策树、生产部署基线、12 避坑、面试题与落地检查单——数据库交互体系收官篇。

## 1. 选型决策树总览

```text
                    Agent 需要数据库？
                        │
     ┌──────────────────┼──────────────────┐
     │                  │                  │
  读查询？           写操作？           记忆存储？
     │                  │                  │
  ├─只读角色+读副本 ─┐ ├─HITL审批闭环 ───┐ ├─短期状态 → Redis KV/检查点
  ├─工具链四件套 ───┼─┤ ├─独立写账号 ────┼─┤
  └─自研或MCP服务器 ┘ └─幂等+审计 ───────┘ ├─聊天历史 → 关系表(有界读)
     │                                    ├─长期事实 → claim 表+混合检索
  Java 栈 → LangChain4j(09)               └─一库化 → PG/Redis 全装
  Python/通用 → LangChain/MCP(04/08)
```

| 场景 | 方案 | 篇 |
|---|---|---|
| 快速接入现成库 | MCP 数据库服务器（DBHub/mcp-multi-db） | 08 |
| 深度定制查询 Agent | 自研工具链四件套 + 口径注入 | 04/06 |
| Java 生产后端 | LangChain4j 双 Agent + JSQLParser | 09 |
| 会话/状态持久化 | Redis + 关系表（有界读取） | 05 |
| 写业务数据 | 审批工具 + 独立账号 + 幂等 | 07 |
| 数据分析问答 | 读副本 + few-shot + 结果叙事 | 06 |

## 2. 生产部署基线

| 领域 | 基线 |
|---|---|
| 数据库账号 | 专用只读角色（GRANT SELECT ONLY）+ 独立写账号（DML only，无 DDL） |
| 数据源 | 查询走读副本；写走主库且必须审批 |
| 连接池 | HikariCP，Agent 专用池 4-8 连接，语句超时 10s |
| 守卫层 | AST 校验（仅 SELECT）+ 表白名单 + 强制 LIMIT + 敏感列过滤 |
| 错误处理 | 驱动报错脱敏回喂；重试 ≤3 次；工具调用 ≤12 次/轮 |
| 审计 | 查询日志（SQL/耗时/行数）+ 写操作全量审计（提议/批准/快照） |
| 限流 | 每会话 QPS 限制；慢查询告警（>5s） |
| 凭据 | 连接串环境变量注入，不进代码库；定期轮换 |
| 可观测 | 请求 id 贯穿 UI→Agent→工具→DB；SQL 审计看板 |
| 降级 | 数据库不可用时返回"查询服务暂不可用"，不裸报错 |

## 3. 12 避坑清单

| # | 坑 | 后果 | 解法 |
|---|---|---|---|
| 1 | 用会话级 read_only 当安全机制 | 任何用户可 SET 回 off | 数据库角色授权（03 篇） |
| 2 | 给只读任务配写账号 | 注入即删库 | OWASP LLM06：权限最小化 |
| 3 | 字符串关键词过滤当防线 | `SELECT side_effect()` 绕过 | AST 校验 + 数据库层兜底 |
| 4 | 全库 schema 灌上下文 | 准确率暴跌、token 爆炸 | 按域拆分 ≤20 表 + 按需加载 |
| 5 | 无 LIMIT 执行 | 全表扫描拖垮生产 | 强制钳制 + 超时 |
| 6 | 拼接 SQL | 注入 | 参数化绑定 + 单条语句 |
| 7 | 报错直接回喂模型 | 泄露表结构/连接信息 | 错误脱敏后再回喂 |
| 8 | 写操作无审批 | 一次幻觉毁数据 | HITL 审批闭环 + 一次性令牌 |
| 9 | 写操作无幂等 | 重试双倍扣款 | 唯一键/条件更新/批次号 |
| 10 | 记忆全量回灌 | token 失控、信噪崩塌 | 记忆管理器 + 有界读取 |
| 11 | 不审计写操作 | 出事故无法追责 | 全量审计 + 变更快照 |
| 12 | 忽视数据口径 | 数据"对"但业务上错 | 口径注入 + few-shot 覆盖 |

## 3.5 容量与预算规划

| 项 | 基准建议 |
|---|---|
| 查询并发 | Agent 专用池 4-8 连接，同会话并发 1-2 |
| 单查询预算 | LIMIT ≤200、耗时 ≤10s、结果回传 ≤4KB |
| 工具调用预算 | 单轮 ≤12 次、同一错误重试 ≤3 次 |
| Schema 预算 | 单次上下文 ≤20 表、描述含样例行 |
| 缓存 TTL | 查询缓存 60s、schema 缓存 5min |
| 告警阈值 | 慢查询 >5s、守卫拦截率 >5%、单轮调用 >12 |
| 回归保障 | schema 变更后跑回归问题集（20-50 条），准确率回退即拦截上线（含口径调整场景） |

预算数字随库规模与模型档位调整，但原则固定：**先设上限再上线，宁可拒绝也不失控**。

## 4. 面试题（高频 10 题 + 答题要点）

| 题 | 答题要点 |
|---|---|
| 1. Agent 怎么安全地查数据库？ | 三层：数据库只读角色（GRANT SELECT ONLY）→ 应用层 AST 校验（仅 SELECT/表白名单/LIMIT）→ 审计；提示词约束不算安全机制 |
| 2. Text-to-SQL 现状如何？ | BIRD 执行准确率人类 93%，SOTA 75%+（XiYan-SQL/CYANSQL）；企业 schema 仅 ~39%——差距在业务规则与 schema 复杂度，靠口径注入与 few-shot 弥补 |
| 3. 防止 Agent 删库有哪些手段？ | 权限最小化（无 DDL 权限）+ 写工具 HITL 审批 + SQL 指纹令牌 + 条件更新幂等 + 审计快照 |
| 4. 提示注入怎么影响数据库工具？ | 网页/文档藏指令 → Agent 执行恶意 SELECT 或触发写工具；防线=只读权限（注入也只能读）+ 敏感列授权层隐藏 + 写操作审批 |
| 5. 怎么给模型提供 schema？ | 按业务域拆分（≤20 表/次）+ 表职责清单 + 每表样例行（理解脏数据）+ 口径文档 + 动态检索历史成功 SQL 作 few-shot |
| 6. SQL 生成错了怎么办？ | 执行反馈闭环：报错脱敏回喂 → 重写重试（≤3 次）；错误信息附"工具使用建议"（如"列名不存在，先 describe_table"） |
| 7. Agent 记忆存在哪？ | 分层：聊天历史（关系表有界读）+ 短期状态（Redis KV/检查点）+ 长期事实（claim 表状态机+混合检索 RRF）；记忆管理器挑最小有用包 |
| 8. 会话历史的 Token 怎么控制？ | 有界读取（history_size=N 不删行）+ 滚动摘要 + 工具结果截断（4KB）+ 全量保留入库供审计 |
| 9. MCP 数据库服务器和自研工具怎么选？ | MCP 快（DBHub 2 工具 1.4k tokens、安全默认）适合快速接入；自研适合深度定制（口径/审批）；生产可混合 |
| 10. Java 侧怎么做？ | LangChain4j 三模式（@AiService/双 Agent/ContentRetriever）；JSQLParser AST 校验 + 表白名单 + 只读数据源 + OTel 审计 |

## 5. 落地检查单（上线前逐项打勾）

```text
□ 数据库层：专用只读角色 + 写账号分离（无 DDL/FILE）
□ 查询走读副本（有则用）；连接串环境变量注入
□ AST 校验 + 表白名单 + 强制 LIMIT + 敏感列过滤
□ 所有输入参数化；错误脱敏后回喂模型
□ 写操作 HITL 审批（一次性令牌 + SQL 指纹）+ 幂等设计 + 全量审计
□ schema 按域拆分 + 样例行 + 口径注入 + few-shot
□ 工具调用上限 12 次、单查询超时 10s、慢查询告警
□ 记忆分层（历史有界读/KV/claim）+ 记忆管理器
□ 请求 id 贯穿全链路；SQL 审计看板可用
□ 故障演练：DB 宕机、慢查询风暴、注入探测各一次
```
