## 4. 核心概念速查

| 概念 | 一句话定义 |
|---|---|
| Text-to-SQL（NL2SQL） | 自然语言 → SQL 的自动转换；Agent 查询业务库的核心能力 |
| BIRD 基准 | 95 个真实库、12751 条问答的 Text-to-SQL 事实标准（执行准确率） |
| 执行准确率（EX） | 生成的 SQL 真实执行结果与标准答案一致的占比 |
| Schema 链接（Schema Linking） | 把问题中的实体/属性映射到真实表与列（Text-to-SQL 关键前处理） |
| 执行反馈（Execution Feedback） | 把 SQL 报错信息回喂模型重写（自纠错闭环） |
| OWASP LLM06 | "过度代理"：给了 Agent 超出任务所需的权限（如写权限） |
| 只读角色（Read-only Role） | 数据库层 GRANT SELECT ONLY，**唯一可靠的只读防线** |
| 双层强制（Two-layer） | SQL 文本守卫（应用层）+ 只读事务（数据库层）叠加 |
| SQL 文本守卫 | 白名单 SELECT/WITH/EXPLAIN、黑名单 DML/DDL、强制 LIMIT、AST 解析 |
| 参数化查询 | `$1..$N` 占位符绑定值，值永不被当作 SQL 解释 |
| 记忆管理器（Memory Manager） | 决定存什么/取什么/摘要什么/喂多少进上下文的策略层 |
| 检查点（Checkpoint） | LangGraph 等框架按步保存图状态（历史/工具结果），可恢复回放 |
| Claim 生命周期 | 事实记忆状态机 PROPOSED→ACCEPTED→DEPRECATED，冲突即废弃 |
| 混合检索（Hybrid + RRF） | 向量+关键词+图遍历+时效多路召回，互惠排名融合排序 |
| 数据库 MCP 服务器 | 通过 MCP 协议把数据库操作暴露为 Agent 工具的进程（DBHub 等） |

## 5. 2026 生态基准

> 📅 基准窗口：2026-08。版本与事实以各模块【参考来源】为准。

- **Text-to-SQL 现状**：BIRD 执行准确率人类 92.96%，SOTA 为 XiYan-SQL 75.63%（2026-04 IEEE TKDE）、CYANSQL 73.47%（ICDE 2026）、Arctic-Text2SQL-R1（32B，71.83%）；**企业鸿沟明显**——BIRD-Ent 仅 ~39.1%、Spider 2.0 低于 60%；趋势=测试时扩展（多生成器+执行反馈排名）、RL 执行奖励、schema linking、上下文层（指标口径/合法连接/业务规则）。
- **安全共识**：提示词无法约束权限，只有数据库角色能（OWASP LLM06 过度代理）；防线强度排序：会话标志（可绕过）< 角色授权 < 列级授权/视图 < RLS < 读副本；PG 用 `pg_read_all_data`、MySQL 专属用户+SELECT ONLY、SQLite URI `mode=ro`；双层强制（文本守卫+只读事务）+ 参数化 + 审计。
- **MCP 数据库服务器爆发**：DBHub（bytebase，Claude Code 官方文档示例，默认仅 2 个工具约 1.4k tokens）、mcp-multi-db（只读默认）、talk-sql（DDL 可建表）、mcp-alchemy（SQLAlchemy 九库）、database-mcp（执行回滚快照）、any-db-mcp（readonly/readwrite/full 三权限档）、safedb-mcp（白名单+PII 脱敏+审计）。
- **LangChain 模式成熟**：SQLDatabaseToolkit 四工具（list_tables/schema/query_checker/query）+ 系统提示规范（先看表、禁 SELECT *、查前复查、禁 DML）；DeepAgents 引入渐进式披露（query-writing/schema-exploration 技能按需加载）。
- **Java 侧成熟**：LangChain4j 三模式——@AiService 声明式、Supervisor+SqlAgent 双 Agent、SqlDatabaseContentRetriever（@Experimental 且明确警告只读）；JSQLParser AST 校验 + 表白名单成为标配；企业案例如腾讯云栈（Java 17 + Boot 3.2 + LangChain4j + Qwen/GLM + HikariCP + OTel）平均查询准确率 89%。
- **记忆持久化转向"一库化"**：向量+聊天历史+语义缓存合并进一个数据库（Oracle AI Database/Snowflake/Redis）；关系表成为知识图谱的事实载体（实体/claim 表 + 递归 CTE 遍历）；聊天历史有界读取（history_size 截断而不删行）防 token 失控。
- **共识**：Agent 碰数据库的第一原则是**"读为主、写必审、权限最小"**——只读默认，写操作走 HITL 审批，权限在数据库层收紧而非提示词。
