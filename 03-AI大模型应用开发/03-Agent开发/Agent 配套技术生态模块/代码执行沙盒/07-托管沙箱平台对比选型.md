# 托管沙箱平台对比选型

> 不自建、按量付费的托管沙箱（E2B/Modal/Daytona/Vercel/Cloudflare/开源自建）——2026 年 Agent 团队的默认起点。五大商业平台 + 开源自建 + 决策树。

## 1. 商业平台全景

| 平台 | 隔离 | 冷启动 | 会话 | GPU | 卖点 | 2026 状态 |
|---|---|---|---|---|---|---|
| **E2B** | Firecracker 微VM | ~150ms | Pro 24h / Base 1h | 无 | 1B+ 沙箱、7M 月下载、模板即代码、代码解释器事实标准 | 开源（Apache 2.0）、CLI v2.13.3（2026-07-15） |
| **Modal** | gVisor 容器 | <1s | 24h | **T4→B200 全系** | 100k+ 并发、1000 创建/秒、ML/推理/训练一体 | 按核秒计费 ~$0.000014/核/秒（1vCPU+2GB ≈ $0.119/h） |
| **Daytona** | 容器+快照 | ~90ms | **无限** | 可选 | 有状态、SSH/预览 URL、暂停恢复 | SOC2 Type I、15min 闲置自停、7 天自动归档 |
| **Vercel Sandbox** | Firecracker 微VM | 毫秒级 | Pro 24h | 无 | **活动 CPU 计费**、VPC peering、BYOC | GA；$0.128/CPU-h（1vCPU+2GB ≈ $0.149/h）、单区域 iad1 |
| **Cloudflare** | 容器（Workers 生态） | 2-3s | 10min 休眠即亡 | 无 | 边缘全球分布、Durable Objects/KV/R2 原生 | $5/月起、TypeScript 优先 |

### 关键差异速判

- **要 GPU / 大规模 ML**：Modal（E2B/Vercel/Cloudflare 均无 GPU）
- **要有状态长任务 / 开发环境**：Daytona（90ms 冷启动 + 无限时长 + 快照）
- **要最硬隔离**：E2B / Vercel（Firecracker）
- **要边缘全球分发**：Cloudflare
- **要省成本**：Vercel 活动 CPU 计费（空闲不花钱）

## 2. E2B 详解（代码解释器事实标准）

- **模板**：`base`（基础命令/文件）；`code-interpreter-v1`（数据分析/代码执行，默认 2 vCPU / 2GB 内存 / 10GB 盘 / 端口 5000）
- **SDK**：Python + TS/JS；`run_code` 跨调用保上下文（变量/import/函数持久）；文件 API 全量（list/read/write/makeDir/remove）
- **会话**：默认临时，pause/resume beta；生命周期 webhook + 指标；auto-pause
- **部署**：BYOC（AWS 企业）、自托管 Terraform（AWS/GCP）、US/EU 双区域数据驻留
- **生态**：LangChain/LangGraph/LlamaIndex/AutoGen/CrewAI/Vercel AI SDK 全支持；Claude Code/Codex/OpenCode CLI 兼容；LLM 无关（OpenAI/Anthropic/DeepSeek 等）
- **定价**：Hobby 免费 + $100 赠额 + 20 并发；Pro $150/月（100 并发）；Enterprise（RBAC/SLA/合规）
- **局限**：无 GPU；会话 24h 封顶；BYOC 仅 AWS 企业

## 3. 开源自建方案

| 项目 | 定位 | 亮点 |
|---|---|---|
| **OpenSandbox**（阿里，CNCF Landscape 2026 初） | K8s 原生沙箱运行时 | **BatchSandbox：100 个沙箱 0.92s 创建**（传统 76s，O(1) 批量）；gVisor/Kata/Firecracker 多 runtime；命令/文件系统/代码解释器环境；ingress 网关+路由策略+每沙箱 egress 控制+凭据库；Python/Java/Go/TS/C#/C++ SDK + CLI + MCP server；`pids_limit` 512 防 fork 炸弹 |
| **kubernetes-sigs/agent-sandbox** | 标准 CRD/控制器 | Sandbox/SandboxTemplate/SandboxClaim/**SandboxWarmPool**（预创建降冷启动）；gVisor+Kata；stable identity + 持久存储；2026 路线：v1beta1、TS/Go SDK、MCP server、OTel |
| **agent-sandbox/agent-sandbox** | E2B 协议兼容替代 | REST+MCP、Web UI、Blueprint/Template 层、Sandbox Pool、暂停/恢复、快照、scale-to-zero；`kubectl apply -f install.yaml` 即装（K8s 1.26+） |

> 💡 开源自建三问：有没有 K8s 运维能力？是否需要 E2B 生态兼容（选 agent-sandbox）？是否需要批量高吞吐（选 OpenSandbox）？

## 4. 平台安全机制对比（2026）

| 平台 | 文件控制 | 网络过滤 | 命令中介 | 凭据保护 |
|---|---|---|---|---|
| Vercel | Landlock + 网络代理 + shell shim | 网络边界注入凭据 | ✓ | 零信任 secrets 注入 |
| Daytona | 同上（full 模式） | ✓ | ✓ | 加密注入 |
| Cloudflare | 同上 | 自定义 egress 代理（审计/重路由/改流量） | ✓ | 零信任 secrets |
| Modal | ptrace 拦截（gVisor 缺 Landlock/seccomp user-notify） | 网络代理 | ✓ | ✓ |

- 共同能力：文件访问控制、网络过滤、命令中介、密钥过滤、DLP——`@agentsh/secure-sandbox` 包统一封装四家
- 差异根因：gVisor 平台不支持 Landlock/seccomp user-notify → Modal 用 ptrace；Landlock 系平台用 Landlock+代理+shim

## 5. Agent 平台联动（2026-05 新格局）

- **Claude Managed Agents 自托管沙箱**（2026-05-19 公测，Code w/ Claude London）：编排留在 Anthropic，工具执行落到企业控制的沙箱（Cloudflare/Daytona/Modal/Vercel 均为 launch partner）——"**解耦大脑与双手**"；企业网络策略/审计/安全工具生效，文件永不离开企业边界
- **MCP Tunnels**（research preview）：轻量网关单条出站加密连接触达私有 MCP server，无需入站防火墙规则/公网暴露——数据库/工单/知识库内网接入

## 6. 选型决策树

```text
要 GPU / 大规模 ML？        ──→ Modal
要有状态长任务开发环境？     ──→ Daytona
要最强隔离 + 代码解释器？    ──→ E2B / Vercel
要在 Vercel 生态内？         ──→ Vercel Sandbox
要边缘全球 + 已有 CF 栈？    ──→ Cloudflare
有 K8s 团队想自建？          ──→ OpenSandbox / agent-sandbox
企业数据不出内网？           ──→ 自托管（BYOC/开源）或 Claude 自托管沙箱
```

## 面试速记

1. 五平台五卖点：E2B 微VM 解释器、Modal GPU 并发、Daytona 有状态、Vercel 活动 CPU 计费、Cloudflare 边缘。
2. GPU 是分水岭：E2B/Vercel/Cloudflare 无 GPU，Modal 有全系（T4→B200）。
3. OpenSandbox BatchSandbox：100 个沙箱 0.92s（O(1) 批量创建，etcd 单对象写）。
4. 2026-05 Claude Managed Agents 自托管沙箱 + MCP Tunnels：编排与执行解耦、内网 MCP 无暴露接入。
5. 安全机制分两派：Landlock+代理+shim（Vercel/Daytona/CF）vs ptrace（Modal，gVisor 限制）。
