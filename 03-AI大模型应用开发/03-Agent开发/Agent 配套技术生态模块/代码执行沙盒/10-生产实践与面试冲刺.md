# 生产实践与面试冲刺

> 收官篇：选型决策树、落地 12 项清单、12 避坑、面试题库（含答题范式）。上线前与面试前各看一遍。

## 1. 选型决策树（全体系汇总）

```text
第一步：代码可信度
├── 可信内部代码        → L3 容器（docker run 最佳实践模板，见模块 03）
└── 不可信（LLM 生成）  → 进入第二步

第二步：部署形态
├── 想托管（快）：
│   ├── 要 GPU/ML      → Modal
│   ├── 有状态长任务    → Daytona
│   ├── 最强隔离+解释器 → E2B / Vercel Sandbox
│   ├── Vercel 生态    → Vercel Sandbox
│   └── 边缘全球        → Cloudflare
├── 想自建（合规/内网）：
│   ├── 有 K8s         → OpenSandbox（批量） / kubernetes-sigs（标准 CRD） / agent-sandbox（E2B 兼容）
│   └── 单机/轻量       → NsJail / bwrap + gVisor runtime（升级容器）

第三步：安全加固（必做，见模块 09）
├── 出站白名单 + DNS 过滤 + 元数据端点丢弃
├── 凭据短时化 + 网络边界注入
├── 只读根 + 禁符号链接 + 资源配额
└── OTel 审计 + 补丁纪律 + 高险人审
```

## 2. 落地 12 项清单（上线检查单）

| # | 检查项 | 通过标准 |
|---|---|---|
| 1 | 隔离层级选定 | 与威胁等级匹配（见模块 01 选型原则） |
| 2 | 沙箱默认拒绝 | 只读根、白名单可写、网络默认关闭 |
| 3 | 保护路径 | `.git`/凭据目录递归只读 |
| 4 | 符号链接 | 可写区禁创建区外 symlink |
| 5 | 资源配额 | 内存/PID/CPU 绑定会话（pids ≤512） |
| 6 | 超时三层 | 执行/会话/总任务超时均已配置 |
| 7 | 密钥管理 | 零信任注入、不落盘、短时化 |
| 8 | DNS 过滤 | 出站 DNS 白名单 + 异常告警 |
| 9 | 审计 | OTel 全量日志进 SIEM（prompt/工具/网络事件） |
| 10 | 补丁纪律 | 沙箱组件升级流程 + 版本固定（template_id） |
| 11 | 温池 | 生产级冷启动达标（≤500ms 或快照恢复） |
| 12 | 逃生演练 | 每季度一次"提示注入→逃逸"红队演练 |

## 3. 12 避坑

1. **不 kill 沙箱** → 计费/资源泄漏；`with`/`try-finally` 或生命周期钩子兜底
2. **`latest` 模板** → 行为漂移；固定 `template_id` 并版本化缓存
3. **沙箱内放密钥** → 逃逸即失守；凭据网络边界注入 + 短时化
4. **Pyodide 当安全边界** → RCE（CVE-2026-24002）；不可信 Python 上 OS 层隔离
5. **只用 seccomp 黑名单** → `io_uring` 等新调用扩大攻击面；黑名单兜底+白名单核心
6. **忘了 `NO_NEW_PRIVS`** → setuid 提权路径敞开
7. **单层沙箱**（只有 bwrap/只有容器）→ 组合拳：namespace+seccomp+LSM+cgroup
8. **URL 层当权限层**（JupyterHub 教训）→ kernel 启动加 scope 检查 + 配额注入
9. **忽略 DNS 信道** → DNS 隧道外泄（AWS AgentCore 案例）；出站 DNS 必须过滤
10. **过滤器用正则硬写** → SOCKS5 空字节/进程替换绕过；规范化 parser + 枚举参数形态
11. **只设执行超时不设会话超时** → 僵尸会话累积
12. **MCP server 不沙箱化** → 工具调用即宿主调用（MCP loopback 提权案例）

## 4. 面试题库（含答题要点）

### Q1：Agent 为什么必须沙盒化？不沙盒化会怎样？
- 答题点：LLM 输出不可信（幻觉/提示注入/工具输出污染）→ 恶意代码直接以宿主权限执行 → 凭据窃取/内网横向/持久化；2026-05 微软 Semantic Kernel 宿主级 RCE 为证。
- 升华：沙盒是语义防线（对齐/提示词）失效后的**最后物理防线**。

### Q2：容器 vs gVisor vs Firecracker，怎么选？
- 答题点：三者的隔离本质（共享内核/用户态内核/独立内核）→ 启动与开销（<1s/50-100ms/125ms）→ 攻破成本递增 → 不可信代码业界默认 Firecracker；gVisor 适合无 KVM 环境（ChatGPT 案例）。

### Q3：gVisor 的原理是什么？为什么 ChatGPT 用它？
- 答题点：Sentry 用户态重实现 ~237/350 syscall + Gofer 9P 文件中介 + seccomp 白名单 53-68 syscall；Systrap 默认免 KVM；K8s 节点本身是 VM 无 /dev/kvm → Firecracker 不可用。

### Q4：Firecracker 凭什么做到 125ms 启动？
- 答题点：KVM 硬件虚拟化 + Rust VMM + **极简设备模型**（最小设备集、无传统 BIOS/PCI 负担）+ 内核直接引导；~5MB 内存开销 → 高密度多租户；AWS Lambda 15 万亿次/月验证。

### Q5：2026 年沙箱最典型的攻击链？
- 答题点：间接提示注入（恶意文件/网页）→ 模型生成恶意代码 → 沙箱内执行 → 逃逸（symlink/TOCTOU/进程替换）→ 凭据窃取 → DNS 隧道外泄；OpenClaw 四连环（CVSS 9.6）为链式范例。

### Q6：为什么 Pyodide 不能当安全边界？
- 答题点：Pyodide 内 Python 可执行任意 JS（污染运行时/读写文件/OOM）；CVE-2026-24002 实证；Pydantic mcp-run-python 官方归档声明；语言级沙箱只隔 OS 不隔 JS 运行时。

### Q7：沙箱的"纵深防御"具体指什么？
- 答题点：四类 OS 原语（namespace 视图/cgroup 资源/seccomp 调用/LSM 路径）+ 网络策略（白名单/代理/DNS 过滤）+ 权限（最小权限/短时凭据）+ 审计（OTel/SIEM）——单层失效不致命。

### Q8：评估一个沙箱产品，你验证哪些信道？
- 答题点：文件系统（读写范围/保护路径/symlink）、网络（出站/DNS/代理绕过）、进程（ptrace/信号）、IPC（MCP/共享内存）、资源（配额）、时钟（侧信道）；**按信道逐项实测**，不信"完全隔离"声明（AWS AgentCore DNS 案例）。

### Q9：快照恢复的价值与原理？
- 答题点：冻结内存+磁盘状态 → 秒级恢复；长任务续跑、调试复现、冷启动优化、环境克隆；Firecracker/Lambda MicroVMs/Daytona 均依赖。

### Q10：自建 vs 托管沙箱？
- 答题点：托管（E2B/Modal/Daytona/Vercel/Cloudflare）快、按量、免运维，但数据出境/合规/GPU（Modal 独有）受限；自建（OpenSandbox/agent-sandbox/NsJail+gVisor）可控、成本低、需 K8s 运维能力；企业敏感数据默认自建/自托管。

### Q11：Claude Code / Codex 的沙箱设计理念？
- 答题点：两级——工具级沙箱（Claude Code sandboxed Bash：bubblewrap/Seatbelt；Codex read-only/workspace-write/danger-full-access 三策略）+ 环境级隔离（容器/VM/sandbox-runtime）；**平台原语组合**（macOS Seatbelt / Linux Landlock+seccomp+bwrap / Windows 受限 token+ACL）；提示注入防御 + 高险审批。

### Q12：MCP 与沙盒的关系？
- 答题点：MCP 让 LLM 调工具，工具执行点=新信任边界；MCP server 必须沙箱化（Wassette WASM 化）；MCP Tunnels 内网接入不暴露公网；OpenClaw MCP loopback 提权是反面教材。

## 5. 面试一句话速记

1. 沙盒=不可信代码的最后物理防线；2026 默认微VM，容器只配可信代码。
2. 攻击链：间接注入→执行→逃逸→凭据→DNS 外泄；按信道验证隔离声明。
3. 选型：GPU→Modal，有状态→Daytona，硬隔离→E2B/Vercel，自建→OpenSandbox/NsJail+gVisor。
4. 落地七件事：网络/DNS 过滤、最小权限短时凭据、只读根禁 symlink、配额、审计、补丁、人审。
