## 4. 核心概念速查

| 概念 | 一句话定义 |
|---|---|
| 文档解析（Parsing） | 把文档文件变成文本与结构（版面/表格/层级）的完整过程 |
| 文本层提取 | 直接从 PDF 内部文本层取字（快、免费、无 OCR）——仅适用于数字化 PDF |
| OCR | 从图像/扫描件中识别文字；2026 年已与版面分析一体化 |
| 版面分析（Layout Analysis） | 识别文档元素（标题/段落/表格/图表/页眉页脚）与阅读顺序 |
| VLM 直读 | 多模态大模型把页面当图像"看一眼"直接输出结构化内容 |
| NID | 阅读顺序误差指标（Reading Order）；TEDS = 表格结构准确率；MHS = 标题层级 |
| TEDS | 表格结构相似度（Tree-Edit-Distance based），表格识别的事实指标 |
| 分块（Chunking） | 把文档切成可检索片段；2026 共识=按标题结构切，不按字符数硬切 |
| 原子块（Atomic Unit） | 表格/代码块等不可分割单元——永远不能从中间断开 |
| Heading Path | 分块携带的标题路径元数据（如 `["安装", "配置"]`），孤块也能有上下文 |
| 路由式解析 | 按文档类型/页面复杂度分发到不同引擎（PyMuPDF/Docling/OCR/VLM） |
| 扫描 PDF | 纯图像 PDF，文本层为空——PyMuPDF 等会静默返回空文本的陷阱 |
| 跨页表格 | 跨多页的表格，解析时需合并回一个逻辑表再入库 |

## 5. 2026 生态基准

> 📅 基准窗口：2026-08。版本与事实以各模块【参考来源】为准。

- **解析质量基准**（opendataloader-bench 语料，2026-07 最新重跑）：Docling 2.110 综合 0.877-0.89（MIT，表格 TEDS 0.89 开源最强）；pymupdf4llm 1.28 速度最快（0.01-0.05s/页，AGPL，表格弱 TEDS 0.54-0.61、无 OCR）；Unstructured 企业向（Apache）；商用 Nutrient API 0.93；**路由式混合（pdfmux/OpenDataLoader）免费工具里最强 ~0.905**。
- **OCR 格局剧变**：PaddleOCR-VL-1.6（2026-05，0.9B 参数）OmniDocBench 96.33% 全球第一（超 Gemini-3 Pro/DeepSeek-OCR2/GPT-5.2），111 语言、版面分析一体化（PP-DocLayoutV2/V3）、跨页表格自动合并、公式转 LaTeX、支持不规则多边形框；开源自部署（需 PaddlePaddle 3.2.1+）。
- **VLM 直读成为新范式**：arXiv 2026-03 实证"强多模态模型图像直读可媲美 OCR 增强"；开源小模型（GOT-OCR 2.0 580M、PaddleOCR-VL 0.9B、dots.ocr 1.7B、Nemotron Parse 2.0、olmOCR 2）单卡可部署；权衡=延迟（秒/页）、成本（按 token）、幻觉（需交叉验证）——**生产共识是混合路由：简单文档走快库/OCR，复杂版面走 VLM**。
- **分块共识成型**：两阶段流水线（版面感知提取 → 结构感知分块）；Markdown 为规范中间格式；标题边界分块 + heading path 元数据；表格永不分摊（原子块/按行分块+摘要块）；跨页表格先合并；复杂表格 JSON 为规范、Markdown 为衍生。
- **许可证成为选型硬约束**：AGPL（PyMuPDF/marker）企业常直接排除；MIT（Docling）/Apache（Unstructured）宽松。
- **共识**：没有单一工具全赢——"快、准、便宜"三选二；生产架构从"一个库"转向**路由式混合引擎**。
