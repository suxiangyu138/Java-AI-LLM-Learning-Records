# 生产实践与面试冲刺

> 从"能解析"到"能上"：选型决策树、生产基线、质量评估、12 避坑、面试题与落地检查单——文档解析体系收官篇。

## 1. 选型决策树总览

```text
               文档到达
                   │
          ┌────────┴────────┐
          │  有文本层吗？     │
          ├─是──────────────┼─否→ OCR/VLM（05/06）
          │  表格重吗？       │
          ├─轻→ pymupdf4llm（快）     └─扫描件→ PaddleOCR-VL
          └─重→ Docling（准）            └─疑难/手写→ VLM 直读
                   │
          分块（08）：标题感知 + 原子块 + heading path
                   │
          入库：向量库 / 数据库 / Agent 上下文
```

| 场景 | 方案 | 篇 |
|---|---|---|
| 数字化文本 PDF 批量 | pymupdf4llm 快路径 | 03 |
| 表格重文档（财报/手册） | Docling（TEDS 0.89） | 03/07 |
| 扫描件/中文复杂文档 | PaddleOCR-VL-1.6（96.33%） | 05 |
| 疑难页/文档问答 | VLM 直读兜底（<5% 页面） | 06 |
| Office 文档 | python-docx/pptx/openpyxl | 04 |
| 混合档案库 | 路由式混合（免费最强 ~0.905） | 02/09 |
| RAG 入库 | 结构感知分块 + 元数据 | 08 |

## 2. 生产基线

| 领域 | 基线 |
|---|---|
| 路由 | 扩展名+文本层试读+表格密度启发式；失败逐级升级（快→准→VLM） |
| 引擎 | PyMuPDF（快）+ Docling（表格）+ PaddleOCR-VL（扫描）+ VLM（兜底） |
| 许可证 | 商用/发布前确认：AGPL（PyMuPDF）是否可接受，否则换 MIT/Apache |
| 缓存 | 文件哈希缓存解析结果（7 天 TTL）；增量入库 |
| 错误 | 扫描/加密/损坏/超大显式报错并给"下一步" |
| 分块 | 标题感知 + 原子块保护 + heading path + 元数据 |
| 质量 | 自有 20-50 文档小基准，NID/TEDS/字段级跟踪 |
| 安全 | 沙箱解析；敏感文档不出内网；脱敏入库 |
| 审计 | 每次解析记录引擎/耗时/页数/结果大小 |
| 可观测 | 路由分布（各引擎占比）、失败率、缓存命中率 |

## 3. 质量评估体系

| 层 | 指标 | 工具 |
|---|---|---|
| 提取 | NID（阅读顺序）、字符错误率 | opendataloader-bench 类 |
| 表格 | TEDS、单元格抽查 | 自建标注集 |
| 分块 | 检索命中率、原子性断言 | RAG 评估集 |
| 端到端 | 问答正确率（20-50 题） | 业务回归集 |

> 💡 评估节奏：每次换引擎/升级版本跑一次自有基准——公开基准位次只是参考，**你的文档分布下的分数才是选型依据**。

## 4. 12 避坑清单

| # | 坑 | 后果 | 解法 |
|---|---|---|---|
| 1 | 扫描 PDF 直接提取 | 静默空文本，下游"资料里没有" | 文本层试读 + 显式路由 OCR |
| 2 | 表格被摊平 | 行列关系毁，问答乱答 | 表格专用引擎 + 原子块（07/08） |
| 3 | 跨页表格不合并 | 检索残缺 | 合并后再分块 |
| 4 | 忽略许可证 | AGPL 传染风险 | 选型先查 MIT/Apache |
| 5 | 全量送 VLM | 账单爆炸+延迟 | 路由：VLM 只兜底 <5% |
| 6 | VLM 结果不验证 | 幻觉字段进业务 | 交叉验证 + 置信度路由 |
| 7 | 按字符数硬切 | 语义破碎 | 标题感知分块 |
| 8 | 无 heading path | 孤块无上下文 | 元数据挂载 |
| 9 | 无缓存重复解析 | 贵引擎反复烧钱 | 文件哈希缓存 |
| 10 | 解析器裸奔公网 | 恶意文档漏洞 | 沙箱执行 |
| 11 | 不测解析质量 | 换版本悄悄变差 | 自有基准回归 |
| 12 | 把解析结果当真理 | 引擎错误无人知 | 置信度 + 抽检 + 审计 |

## 5. 面试题（高频 12 题 + 答题要点）

| 题 | 答题要点 |
|---|---|
| 1. PDF 解析为什么难？ | PDF 按坐标存内容无逻辑结构——要恢复阅读顺序/表格/标题层级；扫描件无文本层需 OCR |
| 2. 解析工具怎么选？ | 按文档类型路由：数字化文本 PyMuPDF（快）、表格 Docling（TEDS 0.89）、扫描 PaddleOCR-VL、疑难 VLM 兜底；参考基准位次+许可证 |
| 3. 扫描件怎么处理？ | 检测文本层（试读为空→路由 OCR）；PaddleOCR-VL-1.6（96.33% SOTA，版面+表格+公式一体） |
| 4. VLM 直读 vs OCR？ | VLM 语义强但随机/贵/慢/可幻觉；OCR 确定/便宜/版面盲；生产=混合路由，VLM 只兜底疑难页 |
| 5. 表格怎么进 RAG？ | 不摊平；整表块或按行分块+摘要块；跨页先合并；复杂表格 JSON 规范 Markdown 衍生 |
| 6. 分块怎么切？ | 两阶段：版面感知提取→结构感知分块；标题边界切+软上限；表格/代码原子块永不切穿；heading path 元数据 |
| 7. 解析质量怎么评估？ | NID（顺序）/TEDS（表格）/字段级准确率；自建 20-50 文档小基准回归 |
| 8. 提示注入（文档内指令）怎么防？ | 文档内容与指令分域；解析结果不执行；RAG 检索内容当数据不当指令；沙箱隔离解析器 |
| 9. Agent 的文档工具链怎么设计？ | 路由入口+四工具（extract/docling/ocr/vlm）；显式失败给"下一步"；缓存幂等；审计 |
| 10. 大批量文档入库怎么优化？ | 增量解析（只处理变更）+ 文件哈希缓存 + 路由（大部分走快路径）+ 批量并行 + 幂等 |
| 11. 解析质量和 RAG 质量怎么联动？ | 解析是 RAG 的输入层：NID（顺序）/TEDS（表格）直接决定分块与检索质量；用"问答正确率"做端到端回归，任何解析引擎变更必须跑 |
| 12. 文档里的提示注入怎么防？ | 文档内容当数据不当指令；解析结果分域渲染；敏感操作审批；解析器沙箱隔离 |

## 6.5 演进趋势展望（2026-2027）

| 趋势 | 现状 | 影响 |
|---|---|---|
| 解析 Agent 化（Agentic Extraction） | DeepLearning.AI 已开课；解析器会"自纠错重试" | 路由工具链升级为"会自我修复的解析器" |
| 端到端多模态小模型 | 0.9B-7B 直读模型成熟 | 自托管 VLM 成本趋零 |
| 版面分析 + VLM 融合 | PP-DocLayout + VL 一体化 | "解析"与"理解"边界模糊 |
| 表格规范标准化 | JSON 规范 + 原子块成为默认 | 引擎可替换性增强 |
| 许可证趋严 | AGPL 排查成为企业标配 | 选型更倾向 MIT/Apache |

> 💡 对工程师的启示：**把解析层做成"可插拔引擎 + 统一契约"**——2026-2027 的引擎迭代会非常快，契约化（统一输出 schema）才能跟上节奏，而不是被引擎绑定。

## 7. 落地检查单（上线前逐项打勾）

```text
□ 路由入口：文本层试读 + 表格密度 + 扫描件识别
□ 扫描件显式路由 OCR，无静默空文本
□ 表格走专用引擎，跨页合并，从未摊平
□ 分块：标题感知 + 原子块 + heading path + 元数据
□ 自有基准 20-50 文档：NID/TEDS/问答正确率有基线
□ 缓存（文件哈希）+ 增量入库 + 幂等
□ 许可证已确认（AGPL 风险排除）
□ 解析在沙箱执行；敏感文档不出内网
□ VLM 兜底带交叉验证；低置信度转人工
□ 审计：引擎/耗时/页数/结果大小全记录
□ 故障演练：扫描件、加密、损坏、超大文档各一次
```
