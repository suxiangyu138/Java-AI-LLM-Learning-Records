## 1. 为什么 Agent 评估"不一样"

Agent 评估的三个不可回避特性（LangChain Deep Agent，2026-06）：

| 特性 | 含义 | 对评估设计的影响 |
|------|------|----------------|
| 非确定性 | 同一任务 9/10 成功 | 单次 pass/fail 无意义 → 批量 + 统计显著 |
| 错误传播 | 第 3 步错误污染下游 | 只评最终答案找不到根因 → 分层评估 |
| 创造性解法 | 模型走通测试作者没想到的路 | 硬编码期望步骤误杀有效输出 → 只门禁核心行为 |

> 🎯 **核心要点**：评估设计是"Agent 项目上线前死亡"的第一原因（2026 共识）。评估不是"跑个测试"——是**与模型行为共同演化的系统工程**。

## 2. golden dataset：最重要的资产

> "golden dataset 是你拥有的最重要的工件"——LangChain 2026

### 2.1 构建流程

| 步骤 | 做法 | 量级 |
|------|------|:---:|
| ① 用例定义 | 5-10 个核心用例 × 每用例 3-5 条 | 30-50 条 |
| ② 边界收集 | 从生产日志取：错别字/多语言/非常规意图 | +30-50 条 |
| ③ 专家标注 | 领域专家（非开发者）写参考答案 | $1-5/条（通用）$5-20（专业） |
| ④ 一致性复核 | 标注分歧 >10% = 任务定义不清 | 复核至一致 |
| ⑤ 持续维护 | 每季度从生产 trace 新增、淘汰过期、年度重标 | 15% 季度刷新 |

**金融参考架构（400 条）**：60% 生产日志 + 20% LLM 生成困难用例 + 20% 红队输出；分层含对抗用例；每季度刷新 15%。

### 2.2 版本化纪律

```text
golden/v2026-05 ← 版本化（冻结 + 季度新版本）
60-90 天不发新版本 = 数据集悄悄失效（不再抓住真实失败）
防止污染：评估数据不进训练集/微调集
难度分层：30% 困难用例
```

> 💡 成本基准：100-200 题通用域 $300-2000；专业域 3-5×。**一条被提前抓住的回归，够付整套评估体系一年的钱**——评估是保险，不是功能。

## 3. LLM-as-Judge：校准的艺术

### 3.1 校准四步

| 步 | 做法 | 目标 |
|:---:|------|------|
| 1 | **pin judge 模型**：日期化模型 ID（如 `gpt-4o-2024-08-06`），季度显式升级 | 浮动的 judge 是"今天过明天挂"的头号原因 |
| 2 | 人工专家标 ~100 条 | 迭代 rubric 至 Cohen's kappa ≥ 0.75 |
| 3 | 人工纠错 → few-shot：专家纠正的错判成为评估器 prompt 的训练信号 | 持续改进 |
| 4 | 持续追踪 judge-人工一致性 | 发现偏差类别 |

### 3.2 分层评分策略

```text
确定性代码检查  —— 规则约束（SQL 危险关键字、schema、正则）→ 硬门禁
LLM-as-Judge   —— 内容质量（主观）→ 回归/对比
人工审查       —— 定期校准 + 高利害决策兜底（不做批量化）
```

### 3.3 已知偏差

| 偏差 | 缓解 |
|------|------|
| 位置偏差 | 对比评分打乱顺序 |
| 冗长偏差 | 长度归一化 |
| 自我偏好 | 不用被评模型自己当 judge |
| 漂移 | pin 版本 + 定期重校准 |

## 4. Agent 评估五模式

LangChain Deep Agent（与 Anthropic 联合，2026）定义五模式覆盖全部场景：

| 模式 | 内容 | 例子 | 成本 |
|:---:|------|------|:---:|
| 1 单步单元 | 只测第一个决策 | text-to-SQL：调 schema 工具而非幻觉？ | 低 |
| 2 逐点定制 | 每用例不同评分逻辑 | 数字题用字符串匹配，分析题用 judge | 中 |
| 3 全轨迹 | 跑完整 Agent，只门禁核心行为与最终结果 | 不检查执行顺序（防误杀创造解法） | 高 |
| 4 多轮对话 | 条件逻辑：后续轮仅在前轮有效时运行 | 不硬编码对话路径 | 中 |
| 5 安全状态 | 扫描所有中间输出 | SQL INSERT/DELETE 危险操作 | 低 |

```python
"""tests/test_agent_modes.py — 五模式最小骨架（LangSmith 同步）"""
import pytest
from langsmith import unit  # 或 plain pytest + 打分函数


@unit  # 模式 1：单步单元——只验证第一个决策
def test_first_decision(agent):
    result = agent.invoke({"messages": [("user", "查用户表里有多少人")]})
    calls = [m.tool_calls for m in result["messages"] if getattr(m, "tool_calls", None)]
    assert calls and calls[0][0]["name"] == "query_database"   # 调了工具而非幻觉


def test_end_to_end(agent):      # 模式 3：全轨迹——只门禁最终结果
    result = agent.invoke({"messages": [("user", GOLDEN_Q1)]})
    assert score_final(result["messages"][-1].content, GOLDEN_A1) >= 0.8


def test_safety_scan(agent):     # 模式 5：安全状态——扫描中间输出
    result = agent.invoke({"messages": [("user", RED_TEAM_Q)]})
    dangerous = scan_for_dangerous_ops(result["messages"])   # 正则/规则
    assert not dangerous
```

**测试集分目的**：

```text
能力评估（capability）：新功能，初始通过率低 OK
回归评估（regression）：已验证场景必须 ~100% 通过；任何下降 = 回归信号
```

## 5. CI/CD 四门禁

**门禁模式**：prompt 变更、模型升级、检索配置改动 → 必须过评估套件（2026 最有效模式）：

| 门禁 | 规则 |
|:---:|------|
| 1 | 聚合分数回归 ≤1% |
| 2 | 单项标准回归 ≤3-5% |
| 3 | 安全类任何用例 PASS→FAIL 即阻断 |
| 4 | 每 PR 评估预算硬上限（有团队月省 $4k+） |

**统计严谨性**：

```text
阻断条件：均值下降 + Welch t 检验（p<0.05）+ 超过噪声底（|Δ|≥0.03）
确定性失败与安全断言 → 硬阻断
主观轴与单次波动（judge 方差内）→ 告警不阻断
7 日滚动结果提交 git（对比历史而非单点）
```

**呈现**：PR 上贴逐标准 diff 表（"correctness +2%, tone -1%"）——工程师看到增量修复更快。目标：**模型和 prompt 变更像 schema 迁移一样"无聊"**。

```python
"""ci/gate.py — 门禁脚本（退出码契约：0 过 / 2 硬阻断 / 3 告警 / 6 重试）"""
import sys


def run_gate(scores_old: list[float], scores_new: list[float]) -> int:
    from scipy import stats
    # 门禁 1：聚合回归
    if (mean(scores_new) - mean(scores_old)) < -0.01:
        return 2                       # 硬阻断
    # 统计显著性
    t, p = stats.ttest_ind(scores_new, scores_old)
    if p < 0.05 and mean(scores_new) - mean(scores_old) < -0.03:
        return 2
    return 0
```

## 6. 在线评估：采样与回流

```text
离线评估预测，在线评估确认 —— 同一套 scorer 两个场地

在线采样策略（百万级 trace 参考）：
├─ 错误/升级会话：100% 评估
├─ 正常会话：5% 采样
└─ 高频重复会话：1%（控制成本）
```

| 机制 | 做法 | 收益 |
|------|------|------|
| 采样评估 | 生产 trace 5-10% 用 CI 同款 scorer | 20 分钟检出忠实度回归 |
| 失败回流 | 问题 trace → 人工标注 → golden dataset 新样本 | 评估闭环 |
| trace 回放 | 近期生产 trace 每晚跑评估 | 比静态数据集更快抓住漂移 |
| 金丝雀 | 新 prompt 1-5% 流量灰度 | 上线前确认 |
| 线程级评估 | 多轮会话整体评分（意图/结果/轨迹） | 发现"对的结果、错的过程" |

> ⚠️ **线程级评估**：Agent 可能通过问题路径到达正确最终答案（错工具/多余循环/约束违规）——只评最终答案会放过。

> 🎯 **核心要点**：评估体系五件套——**golden dataset（资产）+ Judge（校准）+ 五模式（覆盖）+ 四门禁（执行）+ 在线采样（确认）**。硬核不是工具，是**构建数据集并验证 judge 与人类一致**。"没有门禁的评估 = 只有仪表盘，没有流水线。"
