## 2. 策略一：窗口预算管理

```python
"""agent/context_budget.py — 上下文用量监控与触发"""
class ContextBudget:
    """监控每轮上下文占用，触发压缩/落盘"""

    def __init__(self, window_size=128_000, compact_ratio=0.75):
        self.window_size = window_size
        self.compact_ratio = compact_ratio   # 75% 触发压缩（预留余量）

    def usage(self, messages) -> int:
        """估算当前 token 占用（粗估：中文≈1.5字/token，英文≈0.75词/token）"""
        total = 0
        for m in messages:
            content = m.get("content") or ""
            total += len(content) // 2 if any('一' <= c <= '鿿' for c in content) \
                else len(content) // 4
        return total

    def should_compact(self, messages) -> bool:
        return self.usage(messages) > self.window_size * self.compact_ratio

    def reserve_for_output(self, max_tokens: int) -> bool:
        """输出余量检查：max_tokens 超过剩余窗口 → 截断风险"""
        return max_tokens < self.window_size * 0.15
```

| 阈值 | 值 | 原因 |
|------|:---:|------|
| 压缩触发 | 窗口 70-85% | 预留摘要调用与输出空间 |
| 输出预留 | 15% | 防截断 → 坏 JSON（格式工程联动） |
| 大结果落盘 | >20K token | Deep Agents 模式 |

## 3. 策略二：压缩摘要（代码）

```python
"""agent/compactor.py — 压缩摘要 + 原文落盘（write-before-compact）"""
import json
from pathlib import Path

class Compactor:
    """把旧消息压缩成结构化摘要，原文写盘可恢复"""

    FIELDS = ["task_overview", "current_state", "important_discoveries",
              "next_steps", "context_to_preserve"]

    def __init__(self, model, archive_dir: Path):
        self.model = model
        self.archive_dir = archive_dir

    def compact(self, old_messages: list, session_id: str) -> list:
        # ① 原文先落盘（压缩可回退的前提）
        archive_path = self.archive_dir / f"{session_id}_{timestamp()}.json"
        archive_path.write_text(json.dumps(old_messages, ensure_ascii=False),
                                encoding="utf-8")

        # ② 生成结构化摘要（五字段模板）
        prompt = self._build_prompt(old_messages)
        summary = self.model.invoke(prompt)

        # ③ 摘要替换旧消息（保留最近 N 条原文）
        return [{"role": "system", "content": f"【历史摘要】\n{summary}"}] + old_messages[-5:]

    def _build_prompt(self, messages) -> str:
        text = "\n".join(m.get("content", "") for m in messages)
        return (f"把以下对话压缩为结构化摘要，严格按五字段：\n"
                f"{json.dumps(self.FIELDS, ensure_ascii=False)}\n"
                f"必须保留：精确数值、路径、版本号、错误字符串、阻塞关系。\n"
                f"对话内容：\n{text[:20000]}")     # 摘要输入截断控制成本
```

| 摘要纪律 | 原因 |
|---------|------|
| 原文先落盘 | 压缩可回退（write-before-compact） |
| 五字段模板 | 结构化、可恢复（AgentScope 风格） |
| 保全精确值 | 防"压缩诱发幻觉"（摘要丢数值 → Agent 脑补） |
| 输入截断 | 摘要调用本身成本可控 |

## 4. 策略三：外部记忆（代码）

```python
"""agent/memory.py — 每轮写入先于压缩（Mem0 模式）"""
from langgraph.store.memory import InMemoryStore
from langchain_core.tools import tool, InjectedStore

@tool
def remember_fact(fact: str, store: InjectedStore) -> str:
    """记住关键事实。当用户告知偏好、约束、精确数值时使用。"""
    store.put(("facts", "default"), timestamp(), {"fact": fact})
    return "已记住"

@tool
def recall_facts(store: InjectedStore) -> str:
    """回忆全部已记住的事实。当需要用户历史偏好/约束时使用。"""
    items = store.search(("facts", "default"))
    return "\n".join(f"- {i.value['fact']}" for i in items) or "暂无记录"
```

**必须写入的类型**（每轮结束检查清单）：

```text
✅ 精确数值：阈值、端口、版本号、错误码
✅ 硬约束：用户禁止项、合规要求
✅ 决策理由：为什么选 A 方案
✅ 跨任务依赖：任务 B 依赖任务 A 的输出
✅ 隐含偏好：用户喜欢简洁/详细
```

## 5. Deep Agents 三层压缩模式

LangChain Deep Agents（2026-01）的三层压缩是生产级参考：

```text
第一层：大工具响应（>20K token）→ 落盘文件，上下文只留路径 + 10 行预览
第二层：85% 阈值 → 旧的写/编辑工具调用截断为文件指针
第三层：LLM 摘要兜底（完整原文写文件系统，可 read_file 恢复精确细节）
```

```python
"""agent/deep_agents_pattern.py — 大结果落盘（第一层）"""
import json
from pathlib import Path

ARTIFACT_DIR = Path("./artifacts")

def store_large_result(result: str, tool_name: str) -> str:
    """>20K 的结果落盘，返回引用路径（上下文只留 10 行预览）"""
    if len(result) <= 20_000:
        return result                            # 小结果直塞
    path = ARTIFACT_DIR / f"{tool_name}_{timestamp()}.txt"
    path.write_text(result, encoding="utf-8")
    preview = "\n".join(result.splitlines()[:10])
    return json.dumps({"large_result": str(path), "preview": preview},
                      ensure_ascii=False)

@tool
def read_artifact(path: str) -> str:
    """读取大结果文件全文。当工具返回 large_result 路径时按需调用。"""
    return Path(path).read_text(encoding="utf-8")
```

> ⚠️ **落盘路径安全**：read_artifact 必须做路径白名单校验（防路径穿越）——工具面即安全面（阶段 1 教训的工程版）。

## 6. Prompt Caching 工程

```python
"""agent/cache_discipline.py — 缓存纪律（2026 成本治理）"""
CACHE_RULES = """
前缀冻结铁律：
1. system prompt 永不动态修改（动态内容放 user 区或消息末尾）
2. 工具定义固定顺序（顺序变 = 前缀变 = 缓存全失效）
3. 检索结果/动态数据放在固定前缀之后
4. 关键上下文放开头（缓存按前缀命中）
5. 每环境监控 cache hit 率，<50% 预警
"""
```

| 破坏者 | 后果 |
|--------|------|
| system prompt 塞时间戳/随机数 | 每轮缓存全失效 |
| 动态调整工具顺序 | 前缀漂移 |
| user-first 排序 | 缓存前缀不可用 |
| 检索结果放固定前缀之前 | 前缀含可变内容 |

## 7. token 预算配置基线

| 配置项 | 推荐值 |
|--------|--------|
| 有效上下文上限 | 窗口的 25-50%（设计目标） |
| 压缩触发 | 70-85% |
| 大结果落盘 | >20K token |
| 输出预留 | 15% |
| 轮数熔断 | 25（联动 01 篇） |
| 缓存命中率告警 | <50% |
| 记忆写入时机 | 每轮结束（先于压缩） |

> 🎯 **核心要点**：上下文工程 = **预算 + 压缩 + 记忆 + 缓存**四件套的代码化。检验你的 Agent：上下文用量有人算吗？超阈值会触发什么？关键数值压缩前落库了吗？缓存前缀冻结了吗？四问全"是"，Token 超限才算被管理。
