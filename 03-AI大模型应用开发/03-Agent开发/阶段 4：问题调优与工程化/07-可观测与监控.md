## 1. 可观测的独特性：Agent 自报不可信

> "Agent 失败时，往往连失败日志都是错的。"——MLflow 2026

| 自报缺陷 | 表现 |
|---------|------|
| 编造合理错误 | 输出"看起来很合理的失败解释"而非真实原因 |
| 静默失败 | 工具返回空但 Agent 继续 |
| 漏报/误报 | 状态判断不可靠 |

**结论**：遥测必须基于**外部契约**——独立于 Agent 推理过程的记录：工具调用结果、状态转移、成本。每个步骤都是可独立查询的审计对象（EU AI Act 第 14 条人工监督要求）。

## 2. OTel GenAI 语义约定

2026 年 OTel 已有 GenAI 专属语义约定，主流平台直接摄入：

```text
gen_ai.prompt / gen_ai.completion     —— 提示与补全
gen_ai.usage.input_tokens / output_tokens —— token 用量
gen_ai.system                          —— 模型供应商
gen_ai.operation.name                  —— 操作名（chat/tool）
```

```python
"""agent/otel_setup.py — OTel 三行接入（框架零配置/手写显式埋点）"""
from opentelemetry import trace
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import BatchSpanExporter
from opentelemetry.sdk.trace.export import ConsoleSpanExporter, SimpleSpanProcessor

provider = TracerProvider()
provider.add_span_processor(SimpleSpanProcessor(ConsoleSpanExporter()))
trace.set_tracer_provider(provider)
tracer = trace.get_tracer("agent.phase4")

# 用法：Agent 循环关键步骤打 span
with tracer.start_as_current_span("tool_call") as span:
    span.set_attribute("tool.name", tool_name)
    span.set_attribute("tool.args", str(args)[:500])     # 脱敏截断
    result = execute(tool_name, args)
    span.set_attribute("tool.ok", "error" not in result)
```

## 3. 四层遥测

| 层 | 内容 | 回答的问题 |
|:---:|------|-----------|
| Agent/框架层 | 推理步骤、模型调用、工具调用 | 它做了什么？ |
| 服务层 | 记忆读写、网关鉴权、身份/策略判定 | 谁允许的？ |
| 基础设施层 | 容器指标、Lambda 执行 | 资源够吗？ |
| 应用层 | 跨 Agent 业务指标 | 业务正常吗？ |

```text
每层都有独立的 span 类型与指标——排查时先问"是哪一层"：
模型调用失败 → Agent 层 span
策略误拦截 → 服务层（策略判定记录）
资源不足 → 基础设施层
业务异常 → 应用层
```

> 🎯 **核心要点**：四层遥测的纪律——**同一次故障从四层各自取证**。搜索工具失败 30% 不体现在延迟指标里，但摧毁回答质量——必须按工具分维度监控失败率（Agent 层），而不只是整体成功率。

## 4. 关键指标与 pager 告警

### 4.1 指标全景

| 类别 | 指标 |
|------|------|
| 执行 | 每阶段耗时（span timing）、完成/错误计数、工具调用次数 |
| 质量 | 幻觉率采样（忠实度）、无引用率、judge 分数 |
| 安全 | 注入命中数、金丝雀触发、敏感数据命中、guardrail 命中率 |
| 成本 | 会话成本、缓存命中率、token 数、spend-rate |
| 边界 | 轮数分布、上下文占用、截断率 |

### 4.2 pager 告警设计（2026 实战）

> 告警必须**多指标取最小 + 产品信号**——单一指标扛不住 Goodhart 定律。

| 凌晨 3 点的 pager | 阈值 | 含义 |
|------------------|------|------|
| 采样忠实度 < 0.90 | 幻觉在发生 | 应用在编造 |
| PII 泄露 guardrail 命中率 > 0.5% | 合规事故进行中 | 立即处理 |
| spend-rate 异常（$0.5/h → $10/h） | 死循环/成本失控 | 熔断先行 |
| 单工具失败率 > 20% | 工具问题非模型问题 | 检查上游 |
| 会话轮数超基线 2σ | 循环迹象 | 检查终止逻辑 |

**告警纪律**：

```text
① 每次失败/升级事件 100% 评估（含 judge）
② 成本在摄入时打标签（事后查询 trace 成本不可行——太慢）
③ 敏感数据在 SDK 层脱敏（不出边界），不在平台层
④ 原始响应保留 7-30 天；评分摘要永久
⑤ 100% 请求埋点（span：检索/重排/生成/护栏）
```

## 5. 成本标签与数据保留

```python
"""agent/cost_tagging.py — 摄入时成本打标签（事后查询太慢）"""
def tag_cost(span, usage) -> None:
    """在 span 摄入时计算并打上成本标签"""
    cost = estimate_cost(usage.prompt_tokens, usage.completion_tokens)
    span.set_attribute("cost.usd", cost)
    span.set_attribute("tokens.input", usage.prompt_tokens)
    span.set_attribute("tokens.output", usage.completion_tokens)
    span.set_attribute("tokens.cache_hit", usage.prompt_cache_hit_tokens or 0)
```

| 数据 | 保留策略 |
|------|---------|
| 原始响应 | 7-30 天（排障） |
| 评分摘要 | 永久（趋势分析） |
| 成本标签 | 永久（成本趋势） |
| 敏感字段 | 摄入前脱敏（SDK 层） |

## 6. 工具链选型

| 工具 | 定位 | 选型理由 |
|------|------|---------|
| LangSmith | LangChain 栈原生 | 框架栈首选（$39/席位） |
| Langfuse | OSS 可自托管 | 合规要求自托管（数据不出 VPC） |
| Arize Phoenix | OSS 追踪 | OTel 原生 |
| AgentOps | Agent 会话回放 | 多 Agent 协作复盘 |
| Grafana/Prometheus | 基础设施指标 | 与四层遥测组合 |
| Datadog/CloudWatch | 云原生 | 已有基础设施 |

> 💡 **选型主线**：追踪平台解决"发生了什么"，评估平台解决"是否该发生"——两者配合（LangSmith/Langfuse 同时提供；评估深度见 06 篇）。

> 🎯 **核心要点**：可观测 = **外部契约埋点 + 四层遥测 + 多指标告警**。检验你的 Agent：工具结果外部记录了吗？成本摄入时打标签了吗？三个 pager 阈值配了吗？告警接人了还是只进仪表盘？（**没有接收者的告警 = 没有告警**）
