## 2. 学习目标与验收标准

### 2.1 目标

| 目标 | 说明 |
|------|------|
| 失败治理落地 | 四大失败模式从"知识"变成"代码"：预算熔断、修复循环、注入防护 |
| 评估体系 | golden dataset 构建、LLM-as-Judge 校准、五评估模式、CI 门禁 |
| 可观测 | OTel 追踪、关键指标、pager 告警阈值 |
| 部署发布 | HITL 设计、渐进自主、部署清单、事故响应 |

### 2.2 毕业检查单

| # | 检查项 |
|:---:|--------|
| 1 | 为 Agent 配置了成本/轮数/工具调用三重熔断 |
| 2 | 构建 ≥50 条 golden dataset（含 30% 困难用例）并版本化 |
| 3 | LLM-as-Judge 用人工样本校准过（kappa ≥ 0.75 或记录偏差） |
| 4 | CI 门禁：prompt/模型变更必须过评估套件（四门禁） |
| 5 | 生产 trace 采样评估（5-10%）与失败样本回流闭环 |
| 6 | OTel 追踪 + 成本标签 + 关键告警（幻觉率/注入命中率） |
| 7 | HITL 一等节点（低置信/高利害/不可逆三触发） |
| 8 | 走完 12 项部署清单 |

## 7. 2026 版本窗口

> 本阶段以 2026-08 为基准：
>
> - **EU AI Act 第 14 条（人工监督）2026-08-02 生效**：高风险 AI 系统必须有人类监督——Agent 的 HITL 从"最佳实践"升级为"合规要求"
> - **LangChain Deep Agent 框架（2026-06，与 AWS 联合）**：定义 Agent 评估五模式（单步单元/逐点定制/全轨迹/多轮/安全状态）
> - **LLM-as-Judge 校准**：pin 日期化模型 ID、Cohen's kappa ≥ 0.75、来自人工纠错的 few-shot
> - **OTel GenAI 语义约定**（gen_ai.prompt/usage 等）为行业标准
> - **Promptfoo 2026-03 被 OpenAI 收购**（工具链格局变化）
> - **评估成本基准**：golden dataset 100-200 题 $300-2000；每日评估 $30-60/月
> - Gartner：40%+ Agent 项目 2027 前取消（生产化能力是生死线）
