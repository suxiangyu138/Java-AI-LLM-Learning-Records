## 1. 安全工程的三个代码落点

```text
落点一：输入侧（请求前）  —— 注入过滤、内容降权、角色隔离
落点二：执行侧（请求中）  —— 策略引擎拦截、权限分级、状态机
落点三：输出侧（请求后）  —— 外发白名单、敏感数据检测、审计日志
```

> 🎯 **核心要点**：安全 = 三个落点 + 一个原则——**模型负责"想"，系统负责"批"**。一切安全决策在模型外的确定性代码里（失败模式 08 篇共识）。

## 2. 输入防护：注入过滤与内容降权

```python
"""agent/input_guard.py — 输入侧防护（请求前）"""
import re

INJECTION_PATTERNS = [
    r"ignore (all |previous |prior )?instructions?",
    r"you are now",
    r"new instructions?[:\s]",
    r"system\s*:",
    r"role\s*=\s*[\"']?system",
    r"forget (everything|all previous)",
    r"act as an? (unrestricted|developer|admin)",
]


def check_injection(text: str) -> tuple[bool, list[str]]:
    """注入模式检测：命中返回 (True, 命中模式)"""
    hits = [p for p in INJECTION_PATTERNS if re.search(p, text, re.IGNORECASE)]
    return bool(hits), hits


def sanitize_content(content: str, role: str = "user") -> str:
    """内容降权：所有外部内容一律按不可信数据处理"""
    # ① 不可信内容标注（结构化边界，服务端分隔）
    return f"<untrusted_content source=\"{role}\">\n{content}\n</untrusted_content>"
```

| 防护 | 做法 |
|------|------|
| 模式检测 | 正则命中即标记（不阻断，交策略引擎决定） |
| 内容降权 | 外部内容包 `<untrusted>` 标记（服务端分隔，不靠模型自觉） |
| Unicode 规范化 | 防同形字符绕过（`unicodedata.normalize`） |
| 角色隔离 | 检索/工具内容只进 user 角色，绝不进 system |

## 3. 策略引擎：确定性执法

策略引擎在**每次工具动作前**拦截（亚毫秒），prompt 是建议、引擎是执法：

```python
"""agent/policy_engine.py — 确定性策略引擎（OPA 风格简化版）"""
from enum import Enum


class ActionLevel(Enum):
    READ = "read"          # 只读：自动执行
    SAFE_WRITE = "safe"    # 受限写：自动（幂等+可回滚）
    RISKY_WRITE = "risky"  # 高影响：人工确认
    ADMIN = "admin"        # 管理：禁止 Agent


TOOL_LEVELS = {
    "search": ActionLevel.READ,
    "get_weather": ActionLevel.READ,
    "read_file": ActionLevel.READ,
    "create_draft": ActionLevel.SAFE_WRITE,
    "send_email": ActionLevel.RISKY_WRITE,
    "delete_record": ActionLevel.RISKY_WRITE,
    "change_config": ActionLevel.ADMIN,
}


class PolicyEngine:
    """动作拦截：未授权 → 拒绝；高危 → 转人工"""

    def __init__(self, approve_callback=None):
        self.approve_callback = approve_callback

    def decide(self, tool_name: str, args: dict, session_role: str) -> tuple[bool, str]:
        level = TOOL_LEVELS.get(tool_name, ActionLevel.READ)
        if level == ActionLevel.ADMIN:
            return False, "管理操作禁止 Agent 执行"
        if level == ActionLevel.RISKY_WRITE:
            # 高危动作 → 人工确认（HITL，08 篇展开）
            if self.approve_callback:
                ok = self.approve_callback(tool_name, args)
                return (ok, "已批准" if ok else "人工拒绝")
            return False, "高危动作需人工确认"
        return True, ""

    # 接入：工具执行前调用 decide()，拒绝即拦截
```

| 引擎原则 | 实现 |
|---------|------|
| 优先级 | 拒绝列表 → 允许列表 → 限流（严格顺序） |
| 分级 | 只读自动 / 受限写自动 / 高影响确认 / 管理禁止 |
| 终止开关 | kill switch：循环检测/策略违规 → 立即终止（不可覆盖） |

## 4. 权限模型：最小权限与分级

```python
"""agent/permissions.py — 会话级权限与身份"""
SESSION_ROLES = {
    "user": {"tools": ["search", "get_weather", "read_file", "create_draft"]},
    "support": {"tools": ["search", "get_weather", "read_file",
                          "create_draft", "send_email"]},
    "admin": {"tools": "__all__"},       # 管理角色也受策略引擎约束
}


def tool_allowed(session_role: str, tool_name: str) -> bool:
    perms = SESSION_ROLES.get(session_role, {}).get("tools", [])
    return perms == "__all__" or tool_name in perms
```

| 2026 安全事实 | 应对 |
|--------------|------|
| 非人身份已超人类账号 100:1（最高 144:1） | 每个 Agent 独立身份 + 目的绑定凭据 |
| 凭据生命周期分钟-小时级 | 任务完成自动吊销 |
| 两成非人身份无人管理 | 身份清单 + 定期审计 |

> 💡 **工具面即安全面**（阶段 1 红线）：Agent 没有 delete 工具就删不了——最小工具集 + 分级 = 最小攻击面。

## 5. 输出防护：外发白名单与敏感检测

```python
"""agent/output_guard.py — 输出侧防护（请求后）"""
import re

ALLOWED_EGRESS_DOMAINS = {
    "api.example.com", "cdn.example.com",
}

SENSITIVE_PATTERNS = {
    "api_key": r"(sk-|key=)[A-Za-z0-9]{20,}",
    "id_card": r"\d{17}[\dXx]",
    "phone": r"1[3-9]\d{9}",
}


def check_egress(url: str) -> bool:
    """外发白名单：不在名单内的域名一律拒绝（防数据外泄）"""
    from urllib.parse import urlparse
    return urlparse(url).netloc in ALLOWED_EGRESS_DOMAINS


def check_sensitive(text: str) -> list[str]:
    """敏感数据检测：命中即告警/阻断"""
    return [name for name, pat in SENSITIVE_PATTERNS.items()
            if re.search(pat, text)]
```

| 输出防护 | 做法 |
|---------|------|
| 外发白名单 | 工具网络请求只允许名单域名 |
| 敏感检测 | 输出中检测密钥/证件/手机号 |
| 动作确认 | 高危动作（发送/删除）二次确认 |
| 审计日志 | 谁/何时/何工具/何参数全留痕 |

## 6. 成本控制工程

```python
"""agent/cost_control.py — 成本三层防线"""
class CostController:
    """会话级 + 账户级 + 熔断三层预算"""

    def __init__(self, session_budget=2.0, daily_budget=50.0,
                 alert_callback=None):
        self.session_budget = session_budget
        self.daily_budget = daily_budget
        self.alert = alert_callback
        self.session_spend = 0.0
        self.daily_spend = 0.0

    def check(self) -> bool:
        """每次 API 调用前检查"""
        if self.session_spend >= self.session_budget:
            return False                      # 会话级：超限即停
        if self.daily_spend >= self.daily_budget:
            self._alert("日预算耗尽")
            return False                      # 账户级：超限即停（throttle/suspend）
        return True

    def record(self, cost: float):
        self.session_spend += cost
        self.daily_spend += cost

    def _alert(self, msg):
        if self.alert:
            self.alert(msg)
```

| 成本手段 | 收益 |
|---------|------|
| 会话/日预算熔断 | 防注入驱动循环、重试风暴 |
| 模型路由（简单任务用廉价模型） | 大模型成本省 50%+ |
| Prompt Caching 前缀冻结 | 命中省 50-90% |
| 动态工具过滤 | 省 8-20% 输入 |
| 流式 + 用户取消 | 中断即省 |
| 成本/完成任务指标 | 发现质量 vs 成本失衡 |

> ⚠️ **告警先行**：spend-rate 告警能在几十分钟内发现"正常 $0.5/小时的 Agent 突然 $10/小时"——预算熔断是最后防线，告警是第一道发现。

| 检查项 | 标准 |
