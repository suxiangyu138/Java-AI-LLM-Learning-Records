## 1. 格式可靠性的四层防线（代码版）

```text
第一层：生成期约束（strict/约束解码）  —— 坏 JSON 物理不可能
第二层：校验（schema + 语义）          —— 结构对 + 值可信
第三层：修复循环（带反馈重试）          —— 校验失败自愈（≤3 次）
第四层：降级路径（换模型/转人工）       —— 修不好不硬撑
```

> 🎯 **核心要点**：四层防线的目标不是"零失败"（不可能），是**"失败的成本可接受"**——前两层定成功率，后两层定失败成本。

## 2. 基线配置：从"尽力"到"硬约束"

```python
"""agent/format_baseline.py — 格式基线配置（2026 生产默认）"""
from openai import OpenAI

client = OpenAI(timeout=60.0, max_retries=2)

# ① 工具参数：strict 工具 schema（OpenAI）
# ② 非工具结构化输出：json_schema + strict（OpenAI）
# ③ 兼容供应商（DeepSeek 等）：强制工具提取（tool_choice 锁定）
# ④ 解析：防御式 json.loads（永远保留）

def safe_parse(raw: str) -> dict:
    """防御式解析：坏 JSON / 非 dict / 截断都兜住"""
    if not raw or not raw.strip():
        return {}
    try:
        data = json.loads(raw)
        return data if isinstance(data, dict) else {}
    except json.JSONDecodeError as e:
        log_format_failure(raw, e)          # 记录失败样本（监控喂数据）
        return {}
```

**格式基线四件套**（2026 生产标准）：

| 件 | 配置 |
|:---:|------|
| 工具参数 | strict（OpenAI）/ tool_choice 锁定（兼容） |
| 输出上限 | max_tokens 预留 5-15%（防截断 → 坏 JSON 误判） |
| 解析防御 | safe_parse 永远存在（哪怕 strict 也保留） |
| 失败记录 | 每次格式失败记日志（is_json_pass_rate 数据源） |

## 3. 修复循环的工程化

```python
"""agent/repair.py — 带反馈的修复循环（生产版）"""
import time


def call_with_repair(gen, validate, max_retries=3, backoff=True):
    """通用修复循环：带错误反馈 + 指数退避 + 降级出口

    Args:
        gen: 生成函数（携带上次错误信息）
        validate: 校验函数（返回 (ok, error)）
    """
    last_error = None
    for attempt in range(max_retries):
        raw = gen(last_error)                     # ★ 每次携带错误反馈
        if raw is None or not raw.strip():
            last_error = "输出为空，请重新生成"
            continue
        ok, err = validate(raw)
        if ok:
            return raw
        last_error = err
        if backoff:
            time.sleep(2 ** attempt)              # 指数退避
    return None                                   # → 降级路径（换模型/转人工）


# 使用示例
def extract_with_repair(client, text, schema):
    def gen(last_error):
        prompt = text
        if last_error:
            prompt += f"\n（上次输出不符合要求：{last_error}，请修正）"
        resp = client.chat.completions.create(
            model="deepseek-v4-flash", messages=[{"role": "user", "content": prompt}],
            response_format={"type": "json_object"},
        )
        return resp.choices[0].message.content

    def validate(raw):
        import json
        try:
            data = json.loads(raw)
        except json.JSONDecodeError as e:
            return False, f"JSON 解析失败: {e}"
        missing = [k for k in schema if k not in data]
        if missing:
            return False, f"缺少字段: {missing}"
        return True, ""

    result = call_with_repair(gen, validate)
    return result   # None → 触发降级路径
```

| 工程化要点 | 说明 |
|-----------|------|
| 错误反馈 | 每次重试携带具体错误（不是原样重发） |
| 上限 3 次 | 超 3 次模型倾向重复同一错误（2026 共识） |
| 指数退避 | 2^attempt 秒，防风暴 |
| 降级出口 | None → 换模型/转人工/记录失败样本 |

## 4. 重试风暴防护

> ⚠️ **真实事故复盘**（失败模式 04 篇）：catch 处理器对同一错误反复重试，一夜 token 花费翻 3 倍——循环里没有合法性评估。

```python
"""agent/retry_policy.py — 重试纪律（防风暴）"""
class RetryPolicy:
    """重试三问：值得吗？带了反馈吗？到上限了吗？"""

    def __init__(self, max_attempts=3, base_delay=0.5, max_delay=8):
        self.max_attempts = max_attempts
        self.base_delay = base_delay
        self.max_delay = max_delay

    def should_retry(self, attempt: int, error: Exception) -> bool:
        """只对可恢复错误重试（429/5xx/超时），业务错误不重试"""
        if attempt >= self.max_attempts:
            return False
        if isinstance(error, (RateLimitError, APITimeoutError, APIError)):
            return True
        return False                    # 业务错误/格式错误 → 走修复循环，不走重试

    def delay(self, attempt: int) -> float:
        return min(self.base_delay * (2 ** attempt), self.max_delay)
```

**重试 vs 修复的分工**：

```text
网络/限流错误（429/5xx/超时）  → 重试（指数退避）
格式/语义错误（坏 JSON/缺字段） → 修复循环（带反馈重试）
业务错误（查无数据）           → 直接回传，不重试
```

> 💡 **错层是风暴之源**：把格式错误当网络错误重试 = 同一坏 prompt 反复烧钱。

## 5. 幂等：写操作的底线

```python
"""agent/idempotency.py — 写操作的幂等键"""
import uuid


def make_idempotency_key(session_id: str, operation: str, args: dict) -> str:
    """写操作唯一键：会话 + 操作 + 参数哈希"""
    import hashlib, json
    payload = json.dumps({"session": session_id, "op": operation,
                          "args": args}, sort_keys=True)
    return hashlib.sha256(payload.encode()).hexdigest()


def execute_idempotent(execute_fn, key_store, op_key: str, *args, **kwargs):
    """先查后写：同键已执行过 → 直接返回上次结果（不重复执行）"""
    if key_store.exists(op_key):
        return key_store.get(op_key)          # 幂等命中
    result = execute_fn(*args, **kwargs)      # 首次执行
    key_store.set(op_key, result)
    return result
```

| 场景 | 幂等方案 |
|------|---------|
| 写工具重试 | 幂等键 + 服务端去重 |
| 转账/下单 | 业务幂等键（订单号） |
| 发消息 | 先查后发（避免重复消息） |
| 文件写 | 内容哈希 + 存在即跳过 |

## 6. 格式监控指标

| 指标 | 定义 | 告警阈值 |
|------|------|---------|
| is_json_pass_rate | JSON 解析通过率（按模型/版本分组） | <95% 告警 |
| repair_rate | 修复循环触发率 | 突增 = prompt/schema 回归 |
| retry_rate | 网络重试率 | 突增 = 供应商问题 |
| format_drift | 模型换版后通过率对比 | 版本切换必查 |
| truncation_rate | finish_reason=length 比例 | >1% 告警（截断→坏JSON链） |

> 🎯 **核心要点**：格式工程的三句口诀——**strict 定成功、修复定成本、监控定回归**。格式通过率必须按模型/prompt 版本分组跟踪——2026 教训：模型升级静默改变格式习惯，只有分组指标能抓住。
