## 1. 从原理到代码的落差

失败模式体系（11 篇）讲的是"是什么、怎么防"；本阶段解决"防的代码写在哪"：

```text
失败模式体系的产出：知识（五道防线、注入七技术、压缩四策略...）
本阶段的产出：     代码（熔断器、校验器、策略引擎、采样器...）

落差原因：防御是"横切关注点"——散落在循环各处，不是一段集中代码
```

> 🎯 **核心要点**：生产化 = 把防御从"文档里的清单"变成"代码里的机制"。**没有熔断器的 Agent 不是不完整，是危险**——一次死循环 = 一夜烧光预算（真实案例）。

## 2. 三层防御框架

```text
第一层：请求前（预防）   —— 输入过滤、工具声明质量、预算预检
第二层：请求中（约束）   —— 结构化输出、轮数上限、工具分级
第三层：请求后（检测）   —— 输出校验、引用检查、采样评估
```

| 层 | 防御对象 | 机制 | 对应失败模式篇 |
|:---:|---------|------|:---:|
| 请求前 | 注入/坏输入 | 输入分类、白名单 | 07 |
| 请求中 | 格式/token/越权 | strict、熔断、分级 | 04/05/06 |
| 请求后 | 幻觉/错误结果 | 校验、验证层、评估 | 02/03 |

**三层都在模型外**——这是 2026 的安全共识：prompt 是建议，机制是执法（失败模式 08 篇）。

## 3. 三重熔断：成本/轮数/动作

```python
"""agent_guard.py — 三重熔断器（生产 Agent 的保命索）"""
import time
from dataclasses import dataclass


@dataclass
class CircuitBreaker:
    max_turns: int = 25          # ① 轮数熔断
    max_cost_usd: float = 2.0    # ② 成本熔断（按会话）
    max_tool_calls: int = 60     # ③ 工具调用熔断
    alert_callback=None          # 熔断时回调（告警）

    def __init__(self):
        self.turn = 0
        self.cost = 0.0
        self.tool_calls = 0

    def check(self) -> bool:
        """每轮开始前检查；False = 应终止"""
        if self.turn >= self.max_turns:
            self._trip("轮数超限")
            return False
        if self.cost >= self.max_cost_usd:
            self._trip("成本超限")
            return False
        if self.tool_calls >= self.max_tool_calls:
            self._trip("工具调用超限")
            return False
        return True

    def record(self, cost: float = 0, tool_calls: int = 0):
        self.turn += 1
        self.cost += cost
        self.tool_calls += tool_calls

    def _trip(self, reason: str):
        if self.alert_callback:
            self.alert_callback(reason)
        print(f"[熔断] {reason}")

    # 用法：循环每轮 check()，API 返回后 record(usage)
```

| 熔断 | 典型值 | 防什么 |
|------|:---:|------|
| 轮数 | 25（2-3× 正常需求） | 死循环、注入驱动的循环 |
| 成本 | $2/会话（按业务） | 重试风暴、大上下文轰炸 |
| 工具调用 | 60/会话 | 批量调用攻击、失控循环 |

> ⚠️ **熔断位置纪律**：预算检查放**基础设施层**（代码），不是 prompt 里写"别烧太多钱"——模型不读你的预算。

## 4. 治理优先级排序

按"投资回报率"排治理顺序（2026 生产实践）：

```text
① 成本/轮数熔断        —— 半小时内做完，防最贵的事故（一夜 3× 账单）
② 结构化输出（strict）  —— 一小时，消灭第一大失败源（解析类 ~38%）
③ 重试纪律（≤3 次+退避） —— 一小时，防重试风暴
④ 输出校验/错误回传     —— 两小时，让错误变成对话
⑤ 注入防护（白名单/策略）—— 半天的活，安全底线
⑥ 幻觉验证层            —— 按场景投入（高危场景优先）
⑦ 评估体系（06 篇）     —— 持续投入，生产化的长期引擎
```

> 💡 **先止血再体检**：①②③ 是止血（防止最贵事故），④⑤ 是体检（防止慢性中毒），⑥⑦ 是长期健康管理。

## 5. 落地模板：production_agent.py

把熔断器接入 create_agent 循环（框架版 + 手写版双轨）：

```python
"""production_agent.py — 带三重熔断的 Agent 模板（LangGraph 版）"""
from langgraph.checkpoint.memory import InMemorySaver
from langchain.agents import create_agent
from agent_guard import CircuitBreaker

class GuardedAgent:
    """对 create_agent 做熔断包装（基于中间件/钩子思想）"""

    def __init__(self, model, tools, system_prompt,
                 breaker: CircuitBreaker | None = None):
        self.breaker = breaker or CircuitBreaker()
        self.agent = create_agent(
            model=model,
            tools=tools,
            system_prompt=system_prompt,
            checkpointer=InMemorySaver(),
            recursion_limit=self.breaker.max_turns,   # 第一重保险
        )

    def invoke(self, message: str, session: str, usage_fn=None):
        if not self.breaker.check():
            return "（会话已达安全限制，请重新开始）"
        result = self.agent.invoke(
            {"messages": [("user", message)]},
            config={"configurable": {"thread_id": session}},
        )
        # usage_fn：从 trace 统计成本（07 篇），此处简化
        cost = usage_fn(result) if usage_fn else 0.0
        calls = count_tool_calls(result)
        self.breaker.record(cost=cost, tool_calls=calls)
        return result["messages"][-1].content


def count_tool_calls(result: dict) -> int:
    """统计本轮工具调用次数（评估/监控用）"""
    return sum(
        1 for m in result["messages"]
        if getattr(m, "tool_calls", None)
    )
```

## 6. 常见坑速查

| 坑 | 现象 | 修复 |
|----|------|------|
| 熔断只设轮数不设成本 | 单轮巨量输出烧钱 | 成本熔断必须独立 |
| 熔断回调静默 | 熔断了没人知道 | alert 回调接告警通道 |
| recursion_limit 过大 | 死循环兜不住 | 2-3× 正常需求 |
| 预算检查在 prompt 里 | 模型不执行 | 代码层强制 |
| 熔断后无恢复路径 | 用户卡死 | 熔断给用户提示 + 重新开始 |
| 只治单一失败 | 四大失败联动 | 用三层防御框架整体设计 |

> 🎯 **核心要点**：失败治理总成的第一步不是"修"，是**"挡"**——三重熔断让最贵的事故（成本爆炸、死循环）物理上不可能发生。先挡后治，其余治理在 02-05 篇展开。
