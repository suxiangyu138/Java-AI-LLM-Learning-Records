## 1. 为什么需要外部遥测

> "Agent 失败时，往往连失败日志都是错的。"——MLflow 2026 监控指南

**Agent 自报的三大不可信**：

| 自报缺陷 | 表现 |
|---------|------|
| 编造合理错误 | Agent 会输出"看起来很合理的失败解释"而非真实原因 |
| 漏报 | 静默失败（工具返回空但 Agent 继续） |
| 误报 | 把正常状态报成失败 |

**结论**：监控必须基于**外部遥测契约**——独立于 Agent 推理过程，记录工具调用结果与状态转移：

```text
外部遥测契约：
├─ 工具调用：工具名、入参、出参、成功/失败、耗时
├─ 状态转移：每轮 Agent 状态机变化
├─ 成本：每轮 token、累计会话成本
└─ 边界：轮数、重试次数、上下文占用
```

## 2. Agent 会话级追踪

### 2.1 追踪粒度：三个层级

| 层级 | 内容 | 诊断价值 |
|------|------|---------|
| Session | 整个 Agent 会话：目标、轮数、结果 | 成功/失败、成本 |
| Span | 单轮：工具调用、模型调用 | 哪步失败 |
| Event | 工具入参出参、状态转移 | 为什么失败 |

### 2.2 实现（OpenTelemetry）

| 要素 | 做法 |
|------|------|
| 主 span | Agent 会话（属性：goal、session_id） |
| 子 span | 每次工具调用 + 每次 LLM 调用 |
| 属性 | 工具名、参数、返回摘要、token 数 |
| 关联 | trace_id 贯穿会话、会话转人工可查 |

> 💡 2026 趋势：部分框架（如 Strands）把 OTel 做成**一等公民**——零配置默认全链路追踪。选型时可把"OTel 集成深度"作为评估项（框架横评中 PydanticAI / Strands 得分最高）。

## 3. 关键监控指标

### 3.1 失败模式专用指标

| 失败模式 | 指标 | 告警阈值（参考） |
|---------|------|----------------|
| 幻觉 | 无引用回答率、USR 抽样 | 上升趋势即告警 |
| 格式错误 | **is_json_pass_rate**（按模型/prompt 版本分组） | <95% 告警；版本切换后突降 = 格式漂移 |
| Token 超限 | 400 拒绝率、输出截断率、上下文占用率 | 拒绝率 >0.1% |
| 安全 | 注入命中数、可疑外发、金丝雀触发 | 金丝雀触发 = 立即告警 |
| 通用 | 工具失败率（按工具分） | 某工具 >20% = 工具问题非模型问题 |
| 通用 | 会话轮数分布 | 超过基线 2σ 告警（循环迹象） |
| 成本 | 会话级成本、缓存命中率 | 成本异常攀升、命中率 <50% |

> ⚠️ **关键洞察**：搜索工具失败 30% 不会体现在延迟指标里，但会**摧毁回答质量**——必须按工具分维度监控失败率，而非只看整体成功率。

### 3.2 边界与熔断

| 边界 | 配置 |
|------|------|
| 轮数上限 | ~25 轮（超限触发压缩/终止） |
| 成本熔断 | 会话预算 + 账户三级预算 |
| 重试熔断 | 单轮重试 ≤3 次 + 指数退避 |

## 4. LLM-as-Judge：能力与陷阱

### 4.1 为什么需要它

| 方案 | 吞吐 | 成本 |
|------|------|------|
| 纯人工评估 | 50-100 条 trace/小时 | 高 |
| 规则评估 | 快但只覆盖客观项 | 低 |
| LLM-as-Judge | 规模化（1000 请求/天 → 10-20 人工小时/天） | 中 |

### 4.2 已知偏差（2026）

| 偏差 | 表现 | 对策 |
|------|------|------|
| 冗长偏差 | 长输出得分偏高 | 长度归一化、打分时隐藏长度信号 |
| 模型漂移 | 评分标准随模型行为变化 | 定期重校准 |
| 单评 vs 对比不一致 | 个体评分与两两对比结果矛盾 | 版本比较用 pairwise |
| 领域退化 | MT-Bench 上 >80% 一致，专业领域暴跌 | 用自己标注样本校准 |
| 确认偏差 | 验证者倾向同意被验证者 | 信息不对称隔离（见 03 篇 MARCH） |

### 4.3 校准最佳实践（LangChain 2026）

| 实践 | 说明 |
|------|------|
| 先校准 | 用 ≥20 条人工标注样本校准 judge |
| 分层使用 | 客观项（工具调用、正则、schema）用**确定性代码评估**；主观项才用 LLM judge |
| 二元优先 | 2 档（通过/失败）优于 1-5 分档 |
| 带理由 | judge 输出必须带判定理由（便于争议诊断） |
| 元评估 | 用 FailProbe 类工具检验 judge 与人工一致性（McNemar 检验 p<0.05 才算回归） |
| 人工兜底 | 高利害/争议样本人工复审 |

## 5. 评估体系：离线 → 在线闭环

### 5.1 三时点评估

| 时点 | 目的 | 做法 |
|------|------|------|
| 离线（开发期） | 已知场景验证 | 黄金数据集 + 回归集 |
| 预合并（CI） | 防回归 | 每次 prompt/模型/工具变更跑回归 |
| 在线（生产） | 发现未知失败 | 10% 采样 trace + 失败样本回流 |

### 5.2 闭环：生产 → 回归集

```text
生产 trace → 采样 10% → LLM judge + 规则检测 → 发现问题 trace
→ 人工标注 → 成为黄金数据集新样本 → 下一轮回归测试覆盖
```

### 5.3 评估维度（单维度 pass/fail 不够）

> 简单 pass/fail 漏掉 65-93% 的安全问题（AWS eval demo 结论）。多维度评估：

| 维度 | 检查内容 |
|------|---------|
| 正确性 | 最终输出正确 |
| 工具使用 | 工具选得对、参数正确 |
| 推理路径 | 中间步骤安全、无越权 |
| 成本效率 | 轮数、token 在预算内 |
| 过程安全 | 无注入命中、无敏感数据外泄 |

### 5.4 层级评估（Agentic CLEAR，IBM，ACL 2026）

| 层级 | 粒度 | 发现 |
|------|------|------|
| System | 整系统行为 | 跨会话失败模式 |
| Node | 单步（工具/决策） | 哪类步骤爱失败 |
| Trace | 完整轨迹 | 轨迹级评价 |

在 AppWorld/GAIA/SWE-bench/TAU-bench 上自动发现 195 个重复问题——**不预定义分类**，动态聚合浮现模式。

## 6. 失败分类与自动化检测

### 6.1 FailProbe 14 类失败（规则引擎，零 LLM 调用）

```text
wrong_tool（选错工具）/ bad_params（参数错误）/
hallucinated_call（幻觉式调用）/ context_overflow（上下文溢出）/
infinite_loop（死循环）/ task_failed（任务失败）/ timeout（超时）/
parse_error（解析错误）/ schema_violation（schema 违规）/ ...
```

> 💡 规则分类器零成本可覆盖客观失败；LLM judge 只留作语义正确性判定——**分工是成本与可靠性的平衡点**。

### 6.2 根因分析：对比优于单看

AgentFixer（ACM AGENT '26）发现：**成功 vs 失败轨迹对比**在 46.2% 的案例中比单看失败轨迹定位更准；没有任何案例中单看更好。

```text
诊断流程升级：
❌ 单看失败 trace 找原因
✅ 同时回放一个同任务成功 trace 做差分 → 定位分歧点
```

## 7. 工具链全景

| 工具 | 定位 | 特点 |
|------|------|------|
| Langfuse | 追踪 + 评估 | 自托管、OTel 基础、GDPR 友好 |
| LangSmith | 追踪 + 评估 + 数据集 | 黄金数据集、回归评分 |
| Helicone | 轻量代理 | 快速部署、请求级观测 |
| AgentOps | Agent 会话回放 | 多 Agent 工作流 replay |
| TruLens | 评估优先 | RAG 指标 |
| Braintrust | 协作评估 | 数据集协作、评分回归 |
| Portkey | 多供应商网关 | 路由 + 观测 + 成本 |
| Comet Opik | ML+LLM 统一 | 训练与推理统一追踪 |
| Arize Phoenix | 开源追踪 | OTel 原生 |
| Agentic CLEAR | 层级评估 | 自动失败模式发现 |
| FailProbe | judge 元评估 | 统计显著性回归判定 |
| OPA Rego / Cedar | 策略内核 | 动作级确定性拦截 |

> 🎯 **核心要点**：可观测性与评估的分工——**评估回答"输出是否符合标准"，遥测回答"上游是否静默损坏"**。两者互补：质量事故可能出在摄取、检索、生成任何一层，评估分数必须能回溯到完整上下文（拉了哪些数据、调了哪些工具、每步怎么走的）。
