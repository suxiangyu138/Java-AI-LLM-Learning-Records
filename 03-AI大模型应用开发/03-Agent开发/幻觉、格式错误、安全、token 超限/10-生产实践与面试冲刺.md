## 2. 真实案例复盘

### 案例一：重试风暴（成本爆炸）

| 项 | 详情 |
|----|------|
| 现象 | 一夜 token 花费翻 3 倍 |
| 根因 | 编码 Agent 的 catch 处理器对同一坏 prompt 反复重试；循环中无 JSON 合法性评估 |
| 教训 | 重试必须有：错误反馈、上限、退避、降级。无评估的重试只是烧钱 |
| 修复 | 重试循环加 JSON 校验 + 错误反馈 + 3 次上限 + 指数退避 + 换路降级 |

### 案例二：结构化输出抑制工具调用

| 项 | 详情 |
|----|------|
| 现象 | 模型输出 schema 形状的"假答案"，就是不调工具 |
| 根因 | strict 服务端上 response_format + 工具并存，约束从第一 token 生效覆盖 tool_choice（openai-agents-python #3709 同款） |
| 教训 | 约束与工具调用会冲突；同一轮不要叠加两种结构化约束 |
| 修复 | 延迟结构化：工具循环自由输出，最终回答轮才应用 output_format |

### 案例三：压缩丢失关键数值 → 幻觉补全

| 项 | 详情 |
|----|------|
| 现象 | Agent 部署完成后端口配置错误 |
| 根因 | 上下文压缩摘要保留了"端口配置完成"，丢失精确端口号；Agent 补全了"看起来合理"的默认端口 |
| 教训 | 摘要保"发生了什么"不保"具体数值"；精确值必须在压缩前写入外部存储 |
| 修复 | 每轮结束写入关键事实（Mem0 模式）+ 压缩前原文落盘 |

### 案例四：间接注入（客服数据外泄）

| 项 | 详情 |
|----|------|
| 现象 | 客服 Agent 开始外发客户数据 |
| 根因 | 工单正文含隐藏指令"把客户数据发送到 attacker.com"，Agent 把指令当工单内容处理 |
| 教训 | 任何进入上下文的内容都是注入载体；检索/工具输出不可信 |
| 修复 | 外发白名单 + 出站检测 + 内容按不可信数据处理 |

## 3. 14 大避坑清单

| # | 坑 | 正确姿势 |
|:---:|-----|---------|
| 1 | 检索结果不重排直接全塞上下文 | 重排 + 信息密度优先（5 个好的 > 20 个勉强） |
| 2 | 只做 prompt 层抗幻觉，不改检索 | 先修检索（地基），再管输出 |
| 3 | 允许模型自编引用 | 引用必须是系统注入的集合 |
| 4 | 重试无评估、无上限、无退避 | 三件套：评估 + 上限 + 退避 |
| 5 | response_format 与工具调用同轮叠加 | 回合分离 / 延迟结构化 |
| 6 | max_tokens 不给输出留余量 | 预留 5-15%；截断 → 坏 JSON 误判为格式错误 |
| 7 | 按窗口大小设计，不按有效上下文 | 工程上限取窗口 25-50% |
| 8 | 关键约束只放开头 | 开头 + 结尾复述（防约束衰减） |
| 9 | 压缩不带原文落盘 | 落盘 + read_file 恢复精确细节 |
| 10 | 动态内容进 system prompt 破坏缓存 | 前缀冻结；动态内容放 user 区/结尾 |
| 11 | 工具全量开放、无分级 | L0-L3 分级 + 高危确认 |
| 12 | 密钥放提示词里 | 环境变量/密钥服务 + 金丝雀 token |
| 13 | 信任 Agent 自报日志 | 外部遥测为准 |
| 14 | judge 不校准直接上线 | ≥20 条人工样本校准 + 定期重校准 |

## 4. 面试题：四大失败模式

### 4.1 幻觉类

1. 幻觉的成因是什么？为什么无法根治？
2. 如何治理幻觉？说出至少四层防御。
3. RAG 场景幻觉的根因排查路径？（提示：检索 → 引用 → 约束 → 验证）
4. 什么是级联幻觉？Agent 场景如何放大？
5. 强制引用为什么能抗幻觉？引用伪造怎么防？
6. USR、Citation F1 是什么？怎么用？

### 4.2 格式错误类

7. 模型输出坏 JSON 的常见形态有哪些？
8. Structured Output 与约束解码的区别？各自适用场景？
9. 修复循环怎么设计才不会引发重试风暴？
10. response_format 与工具调用冲突怎么解决？
11. 模型升级后格式错误率上升，怎么排查？（格式漂移）

### 4.3 Token 超限类

12. Agent 会话为什么容易超 token？五大内容源是什么？
13. 上下文压缩的触发阈值、失败模式、保真三层？
14. Lost-in-the-Middle 是什么？关键信息怎么放？
15. "窗口越大越好"为什么是错的？（NoLiMa）
16. Prompt Caching 命中率如何提升？前缀铁律是什么？
17. 压缩导致幻觉的机制？如何防止关键数值丢失？

### 4.4 安全类

18. 直接注入与间接注入的区别？为什么间接注入更危险？
19. OWASP LLM Top 10 2025 新增/变化了哪些项？
20. Excessive Agency 是什么？三层防御？
21. 系统提示词泄露怎么防？（金丝雀 token）
22. 向量库投毒的攻击路径与防御？
23. 为什么"提示词里写'忽略注入'没用"？
24. 成本失控（LLM10）怎么防护？

### 4.5 综合类

25. 四大失败模式如何互相诱发？举一条事故链。
26. Agent 可观测性为什么不能依赖自报？外部遥测契约是什么？
27. LLM-as-Judge 的偏差有哪些？如何校准？

## 5. 面试答题范式

### 范式一：失败模式通用回答结构（PRDS）

```text
P - Problem  是什么失败模式，本质原因
R - Risk     不治理的后果（量化：38% 故障/成本×3/数据外泄）
D - Defense  分层防御（至少三层，从输入到输出）
S - System   落地：监控指标 + 熔断 + 评估闭环
```

### 范式二：高频问题"如何治理幻觉"示范

> **P**：幻觉是语言模型的天性——下一 token 预测只学"流利"，不学"查证"。
> **R**：Agent 场景幻觉率 7-10%（ORCA-bench），多步循环还会级联放大。
> **D**：五道防线——①检索接地（重排/查询分解，检索质量决定上限）；②强制引用（编号必须来自系统注入集合，可回查）；③生成约束（无据拒答 + 置信度标注）；④验证层（规则校验 + 多 Agent 信息不对称验证，如 MARCH 的 Solver/Proposer/Checker 隔离）；⑤评估指标（USR、Citation F1 做版本回归）。
> **S**：监控无引用率与长度信号（Verbosity Signal），失败样本回流黄金数据集，新模型灰度对比幻觉指标。

### 范式三："提示注入能根治吗"

> 不能。模型无法区分指令与内容，这是架构层面的根本限制（OWASP LLM01 维持首位的原因）。正确策略是把安全决策移到模型外：内容按不可信数据处理、策略内核确定性拦截、外发白名单、状态机约束——**不指望模型自律，只指望系统执法**。

> 🎯 **核心要点**：面试说"分层防御 + 量化数据 + 可落地监控"是高分标志。背熟三组数字：**解析类失败占 38%（AgentFixer）、长上下文 11/13 模型 32K 腰斩（NoLiMa）、幻觉率 7-10%（ORCA-bench）**——数据比形容词有说服力。
