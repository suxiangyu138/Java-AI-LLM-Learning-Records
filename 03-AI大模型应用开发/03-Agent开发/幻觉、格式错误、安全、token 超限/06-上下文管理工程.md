## 1. 四大策略全景

| 策略 | 原理 | token 效率 | 信息保真 | 实现成本 | 代表 |
|------|------|:---:|:---:|:---:|------|
| 滑动窗口 | 丢最旧消息，保留最近 | ★★★★ | ★★（数字遗忘） | 最低 | 各框架默认 |
| 压缩摘要 | LLM 把旧消息压成摘要 | ★★★★★ | ★★★（有损） | 中 | Docker Agent / Deep Agents |
| 结构化状态 | 只留 JSON scratchpad（目标/事实/错误） | ★★★★★ | ★★★★（依赖 schema） | 中 | LangGraph 等 |
| 外部记忆 | 状态落库，按需检索 | ★★★★（每轮省，检索有开销） | ★★★★★ | 高 | Mem0 / 向量库 |

**黄金原则**：

> 上下文 = 工作记忆。压缩的粒度由"这些信息本轮还需要吗"决定，不是由"它们多重要"决定。

## 2. 策略一：滑动窗口

**实现**：丢最旧消息，保留最近 N 条；系统指令"锁定"在顶部。

| 优点 | 缺点 |
|------|------|
| 零成本、零延迟 | 数字遗忘（digital amnesia）：早期任务信息全丢 |
| 实现最简单 | Agent 可能循环（忘了做过的事重做） |

**适用**：短会话、无状态工具（查询型 Agent）、对早期信息不敏感的场景。

> ⚠️ 裸滑动窗口在 Agent 场景几乎总是不够——但它是其他策略的**底座**（压缩/状态都在窗口之上工作）。

## 3. 策略二：压缩摘要（Compaction）

**原理**：到达阈值时，把旧消息交给 LLM 生成摘要，摘要替代原文。

```text
原文（10K token） → LLM 摘要（1K token） → 摘要入上下文，原文落盘
```

**触发阈值（2026 各框架）**：

| 框架 | 触发点 | 说明 |
|------|--------|------|
| Docker Agent | 窗口 90% | 支持手动 /compact 命令 |
| Deep Agents | 85% | 三层压缩（见 3.3） |
| AgentScope | `trigger_ratio`（≤0.9） | 预留 10% 给摘要生成调用本身 |
| 通用建议 | 60-80% | 别等满才压 |

**摘要的五字段结构化模板（AgentScope 风格）**：

| 字段 | 内容 |
|------|------|
| task_overview | 任务总览 |
| current_state | 当前状态 |
| important_discoveries | 重要发现 |
| next_steps | 下一步计划 |
| context_to_preserve | 必须保留的上下文 |

### 3.1 压缩的四大已知失败模式（2026 论文总结）

| 失败模式 | 表现 |
|---------|------|
| 不可预测的有损性 | 摘要丢什么不可控 |
| 因果结构破坏 | 步骤间依赖关系丢失 |
| 阻塞性模型成本 | 摘要调用本身贵（长文本要全读） |
| **压缩诱发幻觉** | 摘要生成时编造细节，Agent 把摘要当事实 |

### 3.2 保真三层模型

```text
原始历史（everything）→ 压缩（compacted，保留大部分细节）→ 摘要（summary，最损）
```

**摘要的危险特征**：保留"发生了什么"，丢失"具体数值"——精确路径、错误字符串、版本号、阻塞关系。后果：Agent 用"看起来合理"的数值补全 → **压缩间接导致幻觉**。

### 3.3 Deep Agents 三层压缩（LangChain，2026-01）

```text
第一层：大工具响应（>20K token）→ 落盘文件，上下文只留路径 + 10 行预览
第二层：85% 阈值 → 旧的写/编辑工具调用截断为文件指针
第三层：LLM 摘要兜底（完整原文写文件系统，Agent 可 read_file 恢复精确细节）
```

> 💡 **工程启示**：压缩前先落盘（write-before-compact）——原文始终可恢复，压缩风险从"不可逆"降为"可回退"。

## 4. 策略三：结构化状态

**原理**：丢弃原始转录，只保留开发者定义的 JSON scratchpad：

```json
{
  "goal": "迁移订单服务到新集群",
  "facts": {"old_ip": "10.0.0.5", "new_cluster": "prod-3"},
  "errors": ["503 on healthcheck 3 times"],
  "done": ["备份完成", "配置迁移完成"]
}
```

| 优点 | 缺点 |
|------|------|
| token 效率最高 | 依赖开发者 schema，未定义变量被忽略 |
| 确定性最强 | 维护成本高 |
| 便于调试 | 需要事件→状态更新的映射代码 |

**适用**：状态明确的任务型 Agent（迁移、部署、运维），以及**压缩的搭档**——压缩摘要生成后，把结构化状态提取出来常驻。

## 5. 策略四：外部记忆（RAG/向量库）

**原理**：持久状态（历史决策、用户偏好、既往结果）放外部存储，按需检索注入：

| 存储 | 适用 |
|------|------|
| 向量库 | 语义检索（过去对话、文档） |
| 键值/关系库 | 精确事实（用户偏好、配置） |
| 文件系统 | 大内容（原始转录、日志） |
| Mem0 类记忆服务 | 自动抽取 + 注入 |

**每轮流程**：

```text
新事件 → 提取关键事实 → 写入外部存储
下轮 → 检索相关记忆 → 注入系统提示词 → 生成
```

## 6. 2026 前沿：结构化上下文驱逐

**Structured Context Eviction（CWL，2026 论文）**：替代摘要的确定性方案——Agent 把轨迹标注为带类型、带依赖链的"episodes"，超预算时由**无 LLM 的确定性策略**按优先级驱逐。

| 对比 | 摘要压缩 | 结构化驱逐 |
|------|---------|-----------|
| 驱逐决策 | LLM（有损、不可预测） | 确定性规则（无 LLM） |
| 因果结构 | 可能破坏 | 依赖链保存 |
| 成本 | 阻塞性摘要调用 | 近零 |
| 实验数据 | —— | 8000 万 token 89 个连续任务无退化 |

> ⚠️ 属于 2026 研究前沿，生产参考为主；工程上可借鉴其"保留用户轮次 + 驱逐已持久化的动作轮次"原则。

## 7. 写入先于压缩：Mem0 模式

**核心纪律**：关键事实**每轮**写入持久存储，而不是压缩时才写（太晚了）。

| 必须写入的类型 | 示例 |
|---------------|------|
| 精确数值 | 阈值、端口、版本号、错误码 |
| 硬约束 | 用户禁止项、合规要求 |
| 决策理由 | 为什么选 A 方案 |
| 跨任务依赖 | 任务 B 依赖任务 A 的输出 |
| 隐含偏好 | 用户喜欢简洁回答 |

> 🎯 **核心要点**：压缩是"事后补救"，写入是"事前保全"。生产 Agent 的正确节奏：**每轮结束先写记忆，再决定是否压缩**。

## 8. Prompt Caching 与成本治理

### 8.1 机制

供应商对**相同前缀**命中缓存（输入价格降低 50-90%）：

| 缓存纪律（铁律） | 原因 |
|----------------|------|
| 前缀稳定：系统提示词不增删 | 任何前缀变动 = 全部缓存失效 |
| 工具定义固定排序 | 顺序变 = 前缀变 |
| 关键上下文放开头 | 缓存按前缀命中 |
| 冻结 system prompt | 动态内容放 user 区或结尾 |
| 监控 cache hit 率 | 命中率骤降 = 有前缀污染 |

### 8.2 常见缓存破坏者

```text
❌ 每轮往系统提示词里塞时间戳/随机信息
❌ 动态调整工具定义顺序
❌ 用户第一的 prompt 排序（user-first ordering）
❌ 把可变上下文（检索结果）放在固定前缀之前
```

### 8.3 成本治理三板斧

| 手段 | 效果 |
|------|------|
| Prompt Caching | 成本降 50-90%（长前缀场景） |
| 压缩 + 状态 + 外部记忆 | 累积历史不再全量重发 |
| 动态工具过滤 | 每轮只发相关工具定义（省 8-20%） |

## 9. 生产配置基线

| 配置项 | 推荐值 | 说明 |
|--------|--------|------|
| 压缩触发阈值 | 窗口 70-85% | 预留余量给摘要调用与输出 |
| 大工具结果阈值 | >20K token 落盘 | Deep Agents 模式 |
| 会话轮数熔断 | ~25 轮 | 超限触发压缩/总结 |
| 成本熔断 | 会话级预算上限 | 超限即停（防重试风暴） |
| 记忆写入时机 | 每轮结束 | 不等到压缩 |
| 缓存健康检查 | 每环境一次 | 命中率 <50% 预警 |
| 有效上下文上限 | 窗口的 25-50% | 设计目标而非硬上限 |
| 关键约束位置 | 开头 + 结尾复述 | 防约束衰减 |

> 🎯 **核心要点**：上下文管理的终极形态是**"窗口只装本轮需要的东西"**——四策略组合使用（滑动窗口打底 + 压缩保近期 + 状态保关键 + 外部记忆保长期），配缓存与熔断控制成本。任何单一策略都无法覆盖长会话。
