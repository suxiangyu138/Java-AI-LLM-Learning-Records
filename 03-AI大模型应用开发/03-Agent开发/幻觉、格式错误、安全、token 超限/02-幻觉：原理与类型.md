## 1. 幻觉的本质

幻觉（Hallucination）= 模型生成**流畅但错误**的内容。它之所以必然发生，源于语言模型的底层机制：

| 机制 | 说明 | 后果 |
|------|------|------|
| 下一 token 预测 | 模型只学习"下一个 token 概率"，不学习"事实数据库" | 输出是概率性的，不是查证性的 |
| 知识压缩 | 训练时把海量语料压缩进权重 | 细节被"压扁"，时间、数字、名称最易失真 |
| 训练截止 | 知识停留于训练截止日 | 新鲜事实只能靠外部输入 |
| 上下文与权重的冲突 | 上下文说 A、权重记 B | 模型可能"坚持权重记忆"（忠实性幻觉） |
| 指令优先还是内容优先 | 无法绝对区分指令与数据 | 被引导生成与事实不符的内容 |

> 🎯 **核心要点**：幻觉不是 bug，是模型的**默认行为**。一个不产生幻觉的模型，本质是"没有知识却懂语言"的模型。生产系统必须默认输出"不可全信"。

## 2. 四维类型学

| 维度 | 类型 | 定义 | 例子 | 根因偏向 |
|------|------|------|------|---------|
| 事实性 | 事实幻觉 | 输出与**外部世界事实**不符 | "Redis 8.0 发布于 2023 年" | 知识压缩失真/训练截止 |
| 忠实性 | 上下文幻觉 | 输出与**给定的上下文**不符 | 检索文档说 A，模型回答 B | 上下文未接地/权重覆盖上下文 |
| 忠实性 | 指令幻觉 | 输出违背**系统指令**约束 | 要求"只能回答基于文档"仍编造 | 指令遵循能力弱 |
| 推理性 | 推理幻觉 | 中间推理步骤错误 | 多步计算中间一步算错 | 推理能力不足 |
| 结构性 | 关联幻觉 | 相关但错误的内容 | 生成了"看起来对"的实体关系 | 语义接近但来源混杂 |

**按严重程度排序（生产视角）**：

```text
最严重：指令幻觉 > 上下文幻觉 > 事实幻觉 > 推理幻觉 > 关联幻觉
        ↑ 直接破坏 Agent 契约          ↑ 影响输出质量但可验证
```

> ⚠️ **判定顺序**：判断"模型错没错"先问——它违背指令了吗？违背上下文了吗？最后才问它违背世界事实了吗？

## 3. 幻觉的成因机制

### 3.1 五类成因

| 成因 | 机制 | 出现场景 |
|------|------|---------|
| 数据不足/覆盖稀疏 | 训练语料中该知识出现极少 | 长尾知识、小众领域 |
| 上下文噪声 | 检索到无关内容干扰生成 | RAG 召回质量差 |
| 上下文过长 | 关键信息淹没，注意力被稀释 | 长对话、大文档 |
| 模型能力边界 | 推理/规划能力不足 | 多跳推理、数学 |
| 对抗诱导 | 被提示注入引导 | 恶意输入 |

### 3.2 检索视角的幻觉放大（Agentic RAG 特有）

- **检索无关性幻觉**：召回内容与问题无关，模型被迫"硬答"→ 编造
- **检索矛盾性幻觉**：多路召回内容互相矛盾 → 模型取其一，可能取错
- **检索遗漏性幻觉**：该召回没召回 → 模型"脑补"

## 4. Agent 场景的特殊性：级联幻觉

### 4.1 为什么 Agent 比单轮对话更易幻觉

| Agent 特性 | 幻觉风险 |
|-----------|---------|
| 多步循环 | 中间步骤错误被后续步骤当成"事实"传播 |
| 工具结果入上下文 | 工具返回的数据本身有误 → 模型基于错误数据推理 |
| 上下文不断累积 | 早期信息被压缩/滑出 → 模型补全"看起来合理"的缺失 |
| 子 Agent 传递 | 上游 Agent 的幻觉输出成为下游的"可信输入" |

### 4.2 级联幻觉（CHARM 框架，2026）

CHARM 将级联幻觉定义为 Agentic RAG 中**幻觉在步骤间传播放大的独立失败模式**，提出四型分类：

| 类型 | 特征 | 典型链路 |
|------|------|---------|
| 传播型 | 单步幻觉沿依赖链传播 | 计划错了 → 每一步都按错计划执行 |
| 累积型 | 每步轻微偏差逐步累加 | 每轮检索都偏一点 → 最终完全跑题 |
| 放大型 | 后续步骤把幻觉当输入强化 | 工具返回幻觉参数 → 结果更离谱 |
| 复合型 | 多种类型混合 | 实际生产最常见 |

**治理思路（架构级）**：检测代理不依赖主链路的输出做判定（信息不对称），并对多步推理管线设置**中断点**——步骤间校验不通过即停，不把错误传给下游。

### 4.3 多 Agent 场景的"确认偏差"

用 LLM 当验证者有个陷阱：验证者看到 Solver 的完整输出后，倾向于"同意"它（确认偏差）。MARCH（ACL 2026）的解法是**信息不对称验证**：

```text
Solver（生成回答）→ Proposer（把回答拆成原子命题）
                     → Checker（只看证据，不看 Solver 输出，逐命题验证）
```

> 💡 **工程启示**：多 Agent 验证的关键不是"多一个 LLM"，而是**切断验证者的信息来源**——让验证者只看证据，不看被验证者说了什么。

## 5. 长上下文与幻觉

2026 年的关键发现（ai-engineer-roadmap 整理）：

| 发现 | 数据/机制 |
|------|---------|
| 上下文越长，幻觉率越高 | 即使关键信息位置最优，上下文长度增加本身就会抬升幻觉率 |
| Lost-in-the-Middle | 中间位置的信息利用率显著低于首尾 |
| "五个高度相关的块 > 二十个勉强相关的块" | 积极过滤比堆量更有效 |
| 高利害场景倾向激进过滤 | 宁可"检索不到"也不给模型噪声 |

**工程推论**：
- 上下文不是越大越好——**信息密度**决定输出质量
- 关键文档放首尾（并配合缓存友好排序）
- 高利害场景用"召回→重排→严格过滤"而非"召回→全塞入"

## 6. "Verbosity Signal"：不确定性的代理指标

PARROT AI 研究（Applied Sciences 2026）发现一个可操作的信号：

> 回答长度与不确定性正相关（r = 0.81）——模型"话越多"，越可能是在编造。

| 信号 | 用法 |
|------|------|
| 回答长度激增 | 触发"需验证"标记，转人工/二次检索 |
| 引用缺失 | 强制引用场景下无引用 = 高幻觉风险 |
| 自相矛盾 | 同一回答内部前后矛盾 = 推理不稳 |

> ⚠️ **反面发现**：Expert Chain-of-Thought（专家思维链）在医学 RAG 场景反而**增加**了未支持句比例（USR 95-100%）——模型优先内部诊断逻辑而非上下文。提示策略与模型架构同等重要。
