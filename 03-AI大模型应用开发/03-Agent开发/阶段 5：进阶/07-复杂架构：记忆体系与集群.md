## 1. 分层记忆体系

规模化 Agent 的记忆不是"一个存储"，是**四层金字塔**：

```text
第一层：工作记忆（上下文窗口）      —— 本轮任务，易失
第二层：会话记忆（checkpointer）    —— 本会话，持久
第三层：团队记忆（共享 store）      —— 全 Agent 团队，按需注入
第四层：组织记忆（知识库/向量库）   —— 跨团队长期资产
```

| 层 | 生命周期 | 读写方式 | 技术 |
|:---:|---------|---------|------|
| 工作记忆 | 单轮 | 上下文直接读写 | 窗口管理（阶段 4） |
| 会话记忆 | 会话 | checkpointer | SQLite/Postgres |
| 团队记忆 | 任务周期 | 工具显式读写 | store（04 篇） |
| 组织记忆 | 长期 | 检索注入 | 向量库 + RAG |

> 🎯 **核心要点**：四层的选择原则——**数据放它"最该活多久"的那层**。常犯错误：把组织记忆塞进会话记忆（膨胀）、把会话记忆塞进工作记忆（超限）、把团队记忆当全局（污染）。

## 2. 记忆写入管线

规模化系统的记忆写入不是"想写就写"——是**流水线**：

```text
事件发生 → ① 相关性过滤 → ② 验证（防级联幻觉）→ ③ 去重/合并
        → ④ 分层落位（会话/团队/组织）→ ⑤ 索引 → ⑥ 审计
```

```python
"""memory_pipeline.py — 记忆写入管线"""
class MemoryPipeline:
    def write(self, event: dict) -> str:
        # ① 相关性过滤（低成本规则）
        if not is_relevant(event):
            return "skipped"
        # ② 验证（防错误事实毒化全队）
        if not self.verify_fact(event["fact"]):
            return "rejected: 验证未通过"
        # ③ 去重（同事实不重复写）
        if self.exists(event["fact"]):
            return "duplicate"
        # ④ 分层落位
        layer = self.choose_layer(event)      # 会话/团队/组织
        self.store[layer].put(event["key"], event["fact"])
        # ⑥ 审计
        audit("memory_write", layer, event)
        return f"written:{layer}"
```

| 管线环节 | 防什么 |
|---------|--------|
| 相关性过滤 | 噪声入库（记忆膨胀） |
| 验证 | 幻觉写入 → 级联污染（04 篇共享记忆警告） |
| 去重 | 重复事实冲突 |
| 分层 | 数据放错层（寿命错配） |
| 审计 | 谁写的什么（可追溯） |

## 3. 并行扩展：fan-out 工程

批量同构任务的多 Agent 并行：

```python
"""fanout.py — 并行 fan-out/fan-in（阶段 2 asyncio 的多 Agent 版）"""
import asyncio


async def fan_out_agents(items: list, worker_agent, concurrency: int = 8):
    """把任务分片并发交给 Worker Agent，收集全部结果"""
    semaphore = asyncio.Semaphore(concurrency)   # 限流（防超供应商配额）

    async def process(item):
        async with semaphore:
            result = await worker_agent.ainvoke({"messages": [("user", item)]})
            return {"item": item, "output": result["messages"][-1].content}

    results = await asyncio.gather(*[process(i) for i in items],
                                   return_exceptions=True)
    # 部分失败处理：成功归成功，失败标记（阶段 4 纪律）
    return [r for r in results if not isinstance(r, Exception)]


# 100 份文档摘要：8 并发 → 全部完成
# outputs = await fan_out_agents(docs, summary_agent, concurrency=8)
```

| 并行工程要点 | 说明 |
|------------|------|
| 信号量限流 | 并发 ≤ 配额（阶段 2 教训） |
| 部分失败 | 失败项标记，不炸整批（阶段 4 纪律） |
| 结果按 id | 与输入项一一对应（乱序到达） |
| 成本 | 并行 × 每任务成本 = 预算 × 并发（熔断要乘系数） |

> ⚠️ **并行放大成本与限流**：100 任务 × 8 并发 = 瞬时 8 倍成本率——**预算熔断必须按"任务数 × 单价 × 并发"预估**。

## 4. Agent 集群架构

规模化部署形态（2026 生产）：

```text
┌──────────────────────────────────────────┐
│ 入口/网关：路由、限流、鉴权                    │
├──────────────────────────────────────────┤
│ 编排层（无状态，可水平扩展）                    │
│  ├─ Supervisor 实例池（负载均衡）              │
│  └─ 任务队列（Kafka/Redis Stream）            │
├──────────────────────────────────────────┤
│ Worker 池（可水平扩展）                       │
│  ├─ 专业 Agent 实例池（按类型分池）             │
│  └─ MCP 服务器（受管、白名单）                 │
├──────────────────────────────────────────┤
│ 共享层                                       │
│  ├─ Checkpointer 存储（Postgres）            │
│  ├─ 团队/组织记忆（向量库 + 关系库）            │
│  └─ 遥测（OTel + 追踪平台）                   │
└──────────────────────────────────────────┘
```

| 集群要素 | 2026 实践 |
|---------|----------|
| 编排无状态 | MCP 无状态设计 + LangGraph 检查点外置 → 水平扩展 |
| 队列解耦 | 长任务走消息队列（不阻塞 HTTP） |
| Worker 分池 | 按任务类型分池（模型/工具不同） |
| 存储共享 | checkpointer 用 Postgres（多实例共享） |
| 遥测统一 | OTel 贯穿所有层（阶段 4 四层遥测） |

## 5. 规模化系统的六大失败

| # | 失败 | 表现 | 防御 |
|:---:|------|------|------|
| 1 | 级联幻觉 | 上游幻觉沿团队传播放大 | 记忆写入验证 + 信息不对称审查 |
| 2 | 上下文漂移 | 多 Agent 共享上下文互相污染 | 隔离 + 精选传递 |
| 3 | 成本失控 | 并行 × 多 Agent 指数烧钱 | 整树预算 + 并发限流 |
| 4 | 状态不一致 | 多实例共享状态竞争 | Postgres 检查点 + 事务 |
| 5 | 注入扩散 | 一个工具中毒全队遭殃 | 输出降权 + MCP 安全基线 |
| 6 | 调试地狱 | 跨 Agent 故障定位困难 | 层级 trace + 路由审计 |

> ⚠️ **规模化的真相**：复杂度不随规模线性增长，而是**平方增长**（N 个 Agent 有 N² 个交互面）——六大失败就是交互面的六大漏洞。每加一个 Agent，先问"它的交互面谁管"。

## 6. 架构演进路线图

```text
单 Agent（阶段 1-3 成果）
  → 生产化单 Agent（阶段 4：熔断/评估/可观测）
  → 多 Agent（Supervisor/Handoffs，本阶段 02-04）
  → 规模化（fan-out/集群/共享记忆，本阶段 03/04/07）
  → 组织级（多团队 + 治理 + 合规，2027 方向）

每步的门槛：
  单→多：职责分离设计 + 循环预防
  多→规模化：无状态编排 + 共享存储 + 预算乘系数
  规模化→组织级：治理平台 + 身份 + 合规审计
```

> 🎯 **核心要点**：复杂架构 = **分层记忆 + 写入管线 + 并行纪律 + 集群形态**，全部建立在阶段 4 的生产化底座上。演进路线图的核心原则：**每一步都先解决"交互面"再谈"加 Agent"**——规模是最后一个问题，信任是第一个。
