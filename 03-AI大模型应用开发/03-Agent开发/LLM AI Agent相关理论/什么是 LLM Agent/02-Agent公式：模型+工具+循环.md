# Agent 公式：模型+工具+循环

> 理论篇：「Agent = LLM + Tools + Loop」的完整拆解——为什么三个要素缺一不可、Anthropic 的 Augmented LLM 基础块、以及"为什么同一模型在不同 Agent 产品里表现差异巨大"的公式解释力。

## 1. 公式总览

最被广泛引用的 Agent 公式（2026 共识）：

```text
Agent = LLM + Tools + Loop
          模型    工具    循环
         决策     手脚     自主性
```

| 要素 | 提供什么 | 没有它的后果 |
|---|---|---|
| **LLM** | 理解指令、推理规划、决策判断 | 工具再强没人"指挥"，退化为普通 API 调用 |
| **Tools** | 查数据、写文件、跑代码、调外部系统 | 模型只会输出文本，**退化为聊天机器人** |
| **Loop** | 多步迭代、环境反馈、持续到目标完成 | 每次只能做一步，**退化为单次函数调用** |

> 🎯 核心要点：**LLM 只产生文本（意图），工具让意图变成行动，循环让行动能持续收敛到目标。** 三者合起来才是"Agent"；缺任何一个，系统就落回上一级形态（对话/程序/脚本）。

## 2. 为什么"模型"是核心但不充分

- **LLM 是唯一具备通用推理能力的组件**：能理解模糊指令、拆解目标、根据反馈调整策略——这是规则代码做不到的。
- **但 LLM 天然有三大局限**，必须靠公式另外两件补齐：

| LLM 局限 | 本质 | 由谁补齐 |
|---|---|---|
| 只出文本，不能行动 | 训练目标是预测下一个 token | 工具（行动）+ 循环（执行） |
| 知识截止 + 内部知识有幻觉 | 参数记忆有时效与错误 | 工具（检索外部事实） |
| 单次推理无记忆延续 | 无状态、上下文窗口有限 | 循环（上下文回填）+ 记忆组件 |

> 💡 Anthropic 的术语：**Augmented LLM（增强 LLM）**是 Agent 系统的基础构建块——"LLM + 检索、工具、记忆等增强能力"。单个增强 LLM 调用不是 Agent；**Agent 是在此基础上由模型驱动循环**。

## 3. 工具（Tools）：Agent 的"手和脚"

| 维度 | 内容 |
|---|---|
| 工具形态 | API 调用、代码解释器、数据库查询、文件系统、浏览器、搜索、其他 Agent |
| 交互协议 | Function Calling（OpenAI 风格协议）→ 2026 年 **MCP**（统一 JSON-RPC，工具即插即用）成为事实标准 |
| 关键机制 | 工具描述（JSON Schema）进入模型上下文，模型输出结构化调用意图，Harness 执行并把结果回填 |
| 设计要点 | 工具描述要和提示词一样认真写（Anthropic：给模型足够 token 思考、格式贴近自然文本、做 poka-yoke 防错设计） |

> ⚠️ 注意区分：**工具是 Agent 的组成部分，不是 Agent 本身**。只会调用工具（比如收到指令就调一次）而没有循环决策的，是"工具型工作流"，不是 Agent。

## 4. 循环（Loop）：Agent 的"自主性"

- **循环是公式里唯一让系统"自己动起来"的要素**：模型每轮输出→判断是否要调工具→执行→把观察结果送回上下文→模型再决策……直到满足终止条件。
- 最简形态：**"一个 LLM 在 while 循环里调用工具"**（业界常用大白话定义）。
- 循环的关键工程点（详见 03 篇）：

| 工程点 | 问题 | 手段 |
|---|---|---|
| 终止 | 不停止会无限烧钱 | 最大迭代数 / token 预算 / 无进展检测 / 目标达成检查 |
| 角色序列 | 消息格式错会被提供商拒绝 | User→Assistant→Tool→... 严格交替 |
| 上下文增长 | 每轮全量回填越来越贵 | 压缩 / 截断 / 记忆外置 |
| 可观测 | 多轮失败难定位 | 事件系统 / 追踪日志 |

## 5. 公式的局限：为什么"模型 + 工具"解释不了差异

> 🎯 面试加分点：**"Agent = LLM + Tools + Loop"只适合入门**——它解释了模型为何能查数据、发邮件、跑代码，却解释不了**为什么同一个模型在不同 Agent 产品中表现差异巨大**。真正的答案在 01 篇的三层拆解：Harness（循环引擎 + Scaffolding）才是差异化的主战场。

| 同一模型，差异来源 | 机制 |
|---|---|
| Scaffolding 不同 | 系统提示词、工具描述质量、格式约束——决定模型"发挥上限" |
| 循环策略不同 | 终止条件、重试、上下文管理——决定"能否稳定收敛" |
| 工具工程质量不同 | 工具描述、防错设计（poka-yoke）、错误回传——决定"执行成功率" |
| 记忆与上下文策略不同 | 压缩、外置记忆、相关性过滤——决定"长任务不掉线" |

> 💡 2026 行业共识一句话：**"2026 年的 AI 竞争，不再是关于谁的模型更聪明，而是谁的系统更可靠"**——模型同质化时代，Agent 的差异在工程（Harness/Loop），不在模型。

## 6. 面试速记

| 问题 | 一句话答案 |
|---|---|
| Agent 公式？ | Agent = LLM + Tools + Loop（模型 + 工具 + 循环） |
| 为什么缺一不可？ | 模型出意图、工具给行动、循环给持续收敛——缺一退回低一级形态 |
| 模型有什么天然局限？ | 只出文本、知识有时效有幻觉、无状态 |
| 什么是 Augmented LLM？ | LLM + 检索/工具/记忆的增强块（Anthropic 基础构建块）——但单次调用不是 Agent |
| 工具层 2026 的关键变化？ | MCP 成为事实标准——工具即插即用 |
| 循环的最简形态？ | "LLM 在 while 循环里调用工具" |
| 循环的四个工程点？ | 终止条件 / 角色序列 / 上下文管理 / 可观测 |
| 公式的局限？ | 解释不了同一模型在不同 Agent 产品中的巨大差异——差异在 Harness |
| 2026 竞争重心？ | 谁的模型更聪明 → 谁的系统更可靠（工程竞争） |
