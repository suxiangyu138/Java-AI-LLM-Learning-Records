## 2. 十六题冲刺

### 【概念组】

**Q1. 什么是 LLM Agent？一句话+拆解。**
> 答：以 LLM 为认知核心，通过工具连接外部世界，在"感知-思考-行动-观察"的自主闭环中推进目标直至完成的系统。拆四个要件：LLM 决策、工具行动、自主闭环、终止条件。官方口径引 Anthropic"LLM 动态掌控自身流程与工具使用"。

**Q2. 最精确的 Agent 定义？**
> 答：Hugging Face 三层拆解——Agent = Model + Scaffolding + Harness。Model 是裸 LLM（只会出文本）；Scaffolding 是模型看到的一切（提示词/工具描述/格式约束）；Harness 是循环引擎（调用模型/分发工具/判断停止）。社区简化：Agent = Model + Harness。

**Q3. Agent 的本质是什么？**
> 答：一种**运行范式**，不是产品、不是算法——任何软件内部可以跑 Agent 范式；本质是"目标驱动的多步自主闭环"（输入一次→生成一次 ≠ Agent；目标→多步行动→反馈→交付 = Agent）。

### 【机制组】

**Q4. Agent = LLM + Tools + Loop 怎么理解？为什么缺一不可？**
> 答：模型出意图（只会生成文本）、工具让意图变成行动、循环让行动持续收敛到目标。缺模型→普通 API；缺工具→聊天机器人；缺循环→单次函数调用。

**Q5. 说说 Agent 的核心循环（ReAct）。**
> 答：Thought（思考当前状态与下一步）→ Action（选工具给参数）→ Observation（工具结果回填）→ 回到 Thought。两个方向：Reason to Act（推理指导行动）与 Act to Reason（行动结果反哺推理）。最简形态"LLM 在 while 循环里调工具"。

**Q6. Agent 如何防止死循环？**
> 答：多层终止条件叠加——目标达成检查、最大迭代上限（通常 8-12 轮）、token/成本预算、无进展检测、时间上限、人工介入检查点。反面案例：四个 LangChain Agent 循环 11 天烧 $47K。

**Q7. 什么是 Loop 工程？**
> 答：2026 年共识——设计"让模型持续工作的机制"（目标怎么给、反馈怎么闭环、边界怎么设、何时停），取代"精心写提示词"。Anthropic 公开 Claude Code 四原语：turn-based（回合制）/ goal-based（目标驱动）/ time-based（定时）/ proactive（主动式）。

### 【边界组】

**Q8. Agent 和 Chatbot 的区别？**
> 答：Chatbot 一次问答（无工具、无行动闭环）；Agent 承接目标（多步行动+环境反馈+终止条件）。能调工具≠Agent，多轮对话≠Agent。

**Q9. Agent 和 Workflow 的区别？**
> 答：分界线是**流程归谁控制**——代码预定义路径=Workflow（提示链/路由/并行/编排器-工人/评估-优化五种）；模型动态掌控=Agent。RAG 管道是典型 Workflow，不是 Agent。

**Q10. 什么不算 Agent（agentwashing）？**
> 答：Gartner 警告——把依赖人工的助手包装成自主 Agent 是 agentwashing。用两个硬指标甄别：自主闭环（自己决定下一步）与动态控制（模型决定流程与工具）。单纯 RAG 问答、固定提示链都不算。

**Q11. 什么时候不该用 Agent？**
> 答：Anthropic 简单性原则——步骤固定→Workflow 或单次调用；无环境反馈→循环失去意义；成功不可衡量→无法迭代；失败代价不可控→人工在环；延迟/成本敏感→Agent 以延迟成本换任务性能，换不起就不上。

### 【共识组】

**Q12. 2026 年各家怎么定义 Agent？**
> 答：共识区四要件（自主决策+工具交互+闭环迭代+边界）；Anthropic"动态掌控"；OpenAI"智能完成任务"（六组件：Models/Tools/Knowledge&Memory/CUA/Guardrails/Orchestration）；Gartner"任务型自主系统"；HF"Model+Scaffolding+Harness"。

**Q13. 2026 Agent 行业趋势怎么看？**
> 答：双面回答——乐观面：Gartner 预测 2026 年 40% 企业应用内置任务型 Agent、2035 年 Agentic AI 驱动 $4500 亿收入；冷静面：Hype Cycle 显示 Agentic AI 处于期望膨胀峰值、完全自主 Agent 对企业多数场景尚未就绪、治理/安全/成本是三大悬顶问题。产业重心已从参数竞赛转向 Agent 工程化落地。

**Q14. Agent 的评价标准变了吗？**
> 答：变了（WAIC 2026 共识）——不再看 Benchmark 跑分，而是真实业务流中**自主规划 + 工具调用 + 闭环执行的成功率**。配套共识：MCP 成工具连接事实标准、Loop 工程成主流。

### 【场景组】

**Q15. Agent 有哪些分类？主流是哪类？**
> 答：按自主程度（辅助/半自主/全自主）× 任务范围（任务型/通用）× 结构（单/多）分类。2026 主流是**任务型 Agent**（一个任务做精做透）——Gartner 40% 预测的主角。

**Q16. 什么场景最适合上 Agent？怎么选？**
> 答：Anthropic 三特征——成功可衡量（测试/解决/验收）+ 环境反馈可迭代 + 失败代价可控。最先成熟：编码（测试闭环）与客服（成功可计量）。单 Agent 起步，可分解+需并行+协调成本 < 收益才上多 Agent（Manager / Orchestrator-workers / Handoff）。

## 3. 金句弹药库（背 5 句就够）

| 金句 | 用在哪 |
|---|---|
| "Agent 不是模型更聪明了，而是系统让模型在自主闭环里'干活'" | 开头定调 |
| "LLM 只产生意图，工具让意图变成行动，循环让行动收敛到目标" | Q4 |
| "Chatbot 回答'你问我答'，Agent 承接'帮我办成'" | Q8 |
| "分界线不在用没用模型，在流程归谁控制" | Q9 |
| "2026 的 AI 竞争，不再是关于谁的模型更聪明，而是谁的系统更可靠" | Q13 收尾 |
| "Prompt 决定怎么答，Harness/Loop 决定怎么干活，MCP 决定怎么接，Guardrails 决定边界" | 综合题 |
| "Agent 以延迟和成本换任务性能；换不来或换不起，就不该上" | Q11 |
