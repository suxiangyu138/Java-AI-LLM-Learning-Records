## 2. 二十题冲刺

### 【流程组】

**Q1. 讲讲函数调用的完整流程。**
> 答：七步——① 工具声明（tools 数组注入）；② 模型决策（调/不调）；③ 提议输出（tool_calls）；④ Harness 执行（解析+校验+调用）；⑤ 结果回传（role:"tool"）；⑥ 再推理；⑦ 定稿或循环。本质是**两轮模式**：提议轮 + 定稿轮——模型只出意图，执行永远是 Harness 的活。

**Q2. 三铁律？**
> 答：A. arguments 是 JSON 字符串必须 json.loads；B. tool_call_id 原样复制（case-sensitive，不匹配 400）；C. assistant 与 tool 两条消息都必须追加回 messages（顺序 assistant 在前）。

**Q3. 一次调用循环几次 API 请求？**
> 答：每个工具调用迭代一次独立请求——5 步循环 ≈ 10 次调用；重试必须指数退避。

### 【细节组】

**Q4. content=None 是错误吗？**
> 答：不是——是"模型选了工具而非文本"的正常信号；对应 tool_calls 非空。判空用 `if message.tool_calls:`（空列表≠None）。

**Q5. tool_call_id 为什么必须原样复制？**
> 答：它是 case-sensitive UUID，服务端用它配对"哪个提议对应哪个结果"；重建/索引会失配 → 400。

**Q6. tool 消息的 content 要求？**
> 答：必须是字符串（一般 json.dumps 结果）——非字符串 TypeError；大结果要截断（"Rows 1-10 of 250"），因为每轮都会被重新 token 化。

**Q7. tool_choice 四值？**
> 答：auto（默认自主）/ none（禁止调用）/ required（必须调一次）/ 指定函数名（强制调某工具）——路由与提取场景用强制调用。

**Q8. 工具描述为什么重要？**
> 答：它是模型唯一的使用说明书——描述是调用准确度第一大因素；要素：做什么/何时用/何时不用/参数含义/正反例（反例标注比正例更有效）。

**Q9. schema 五铁律？**
> 答：枚举不自由串 / 数值加范围 / 字段名无歧义 / additionalProperties:false / 参数级描述；避免 oneOf（弱模型选错分支）。

### 【循环组】

**Q10. 怎么把函数调用做成 Agent？**
> 答：五步循环——调模型→判空（无 tool_calls 即输出答案）→解析执行→回传→回到①；终止条件：零调用自然出口为主 + 轮次上限（8-12）/成本预算/无进展检测/人工介入兜底。

**Q11. 循环为什么必须设上限？**
> 答：循环的默认行为是"继续"不是"停止"——$47K 案例（四 Agent 循环 11 天）；刹车必须由 Harness 装。

**Q12. 工具执行失败怎么处理？**
> 答：结构化错误回传（error_code/message/recoverable/suggested_action）——让模型自修复，消除约 80% 卡死；不要返回空结果（模型无推理依据）。

**Q13. 多轮循环的上下文怎么管？**
> 答：滚动截断 + 摘要压缩 + 工具结果截断（每轮全量重读是成本主体）。

### 【进阶组】

**Q14. 并行调用什么时候能用？**
> 答：无依赖才并行（A 的结果是 B 的参数就不能）；拿不准串行——并行是 2026 新失败面（模型假设未就绪结果）。

**Q15. 流式工具调用怎么聚合？（手撕）**
> 答：按 index 分桶（accumulator[index] = {id, name, arguments}）→ ID 缺失自生成 call_<index> → 函数名后到缓存不报错 → arguments 跨块 += → 流完按 index 排序、跳过空名、json.loads → 执行；收尾判据 finish_reason="tool_calls"。

**Q16. 推理模型怎么影响函数调用？**
> 答：先思后调——计划内建 thinking，外部轮次 8-12 → 2-3；thinking 服务端生成不可调试；DeepSeek 的 reasoning_content 必须回传否则 400；成本 2-5×（按难度路由）。

**Q17. 强制调用注意什么？**
> 答：strict 与并行组合下可能失效需验证；强制不保证参数质量——执行前校验不可省。

### 【避坑组】

**Q18. 最常踩的五个坑？**
> 答：① arguments 未解析；② tool_call_id 不匹配（400）；③ 漏追加 assistant 消息；④ content 非字符串（TypeError）；⑤ 判空用 is not None。

**Q19. 400 排查口诀？**
> 答：先协议（tools/消息格式）、后配对（tool_call_id）、再顺序（assistant→tool）——Chat Completions 与 Responses 格式混用是 invalid parameter 最常见根因。

**Q20. 工具层可靠性怎么度量？**
> 答：三指标分离——JSONValidation（schema 符合）/ FunctionCallAccuracy（名称/结构/类型/语义）/ ToolSelectionAccuracy（工具选对没）——聚合指标掩盖根因。

## 4. 手撕题模板（流式聚合器，面试必写）

```python
def aggregate_tool_calls(stream):
    acc = {}                                  # index → 分桶
    for chunk in stream:
        for tc in chunk.choices[0].delta.tool_calls or []:
            a = acc.setdefault(tc.index, {"id": None, "name": "", "arguments": ""})
            if tc.id: a["id"] = tc.id
            if tc.function:
                a["name"] += tc.function.name or ""
                a["arguments"] += tc.function.arguments or ""
    calls = [a for _, a in sorted(acc.items()) if a["name"]]   # 排序 + 跳过空名
    return [{**c, "arguments": json.loads(c["arguments"] or "{}")} for c in calls]
```
