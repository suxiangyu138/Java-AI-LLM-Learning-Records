# 高级形态：并行-强制-流式

> 背诵篇：流程的三个进阶形态——**并行调用（parallel_tool_calls）、强制调用（tool_choice）、流式聚合（streaming index）**。流式是面试手撕题的高频考点。

## 1. 30 秒背诵卡

| 形态 | 背诵版一句话 |
|---|---|
| 并行调用 | 模型一次提议多个 tool_calls——**无依赖才并行**（有依赖串行） |
| 强制调用 | tool_choice=required/指定函数——路由与提取场景走工具出口 |
| 流式聚合 | 工具调用**分片到达**——按 index 聚合、跨块拼接 arguments |
| 流式判据 | `finish_reason="tool_calls"` = 本轮以工具提议收尾 |
| ID 可能缺失 | 流式首块可能无 ID——自生成 `call_<index>` |
| 函数名可能后到 | 首块可能只有 ID + 部分参数——**缺名不是致命错** |
| buffer 兜底 | `buffer_streamed_tool_calls=True` 流完再合成完整块（部分提供商不可靠） |
| 并行新失败面 | 模型可能假设调用 B 时 A 的结果已就绪——依赖必须串行 |

## 2. 并行调用（parallel_tool_calls）

| 维度 | 内容 |
|---|---|
| 机制 | 模型一次输出多个 tool_calls，Harness 并行执行（asyncio.gather） |
| 依赖判定 | **无依赖**（互不读取对方结果）→ 并行；**有依赖** → 协议层关并行或 Harness 串行 |
| 收益 | 白拿吞吐——一次往返完成 N 个独立查询 |
| 回传 | 每条 tool 消息各配各的 ID（见 04 篇） |
| 风险 | 模型假设"B 的输入用了 A 的结果"——结果未就绪 → 错误执行 |

> 💡 判定口诀：**"A 的结果是 B 的参数 → 不能并行"**；拿不准就串行（安全默认）。

## 3. 强制调用（tool_choice）

| 场景 | 用法 | 机制 |
|---|---|---|
| 路由 | `tool_choice="required"` | 强制走工具出口（分类器工具接收输入返回类别） |
| 提取 | 指定函数 + 严格 schema | 用工具协议强制 JSON 输出（结构化输出替代方案） |
| 防误调 | `tool_choice="none"` | 有 tools 但不许调（只白给上下文） |

> ⚠️ 2026 细节：**strict + 并行组合下强制调用可能失效**（strict 模式与 parallel 互斥/需验证）；强制调用不保证参数质量——**执行前校验不可省**。

## 4. 流式聚合（面试手撕高频）

```python
# 流式工具调用的聚合器模式（背诵版）
accumulator = {}          # index → 部分工具调用
for chunk in stream:
    if chunk.choices[0].delta.tool_calls:
        for tc in chunk.choices[0].delta.tool_calls:
            idx = tc.index                          # ★ index 标识
            acc = accumulator.setdefault(idx, {"id": None, "name": "", "arguments": ""})
            if tc.id:    acc["id"] = tc.id          # ID 可能首块缺失/后到
            if tc.function and tc.function.name:
                acc["name"] += tc.function.name     # 函数名可能后到（分块）
            if tc.function and tc.function.arguments:
                acc["arguments"] += tc.function.arguments   # 跨块拼接
# 流结束后：按 index 排序 → 跳过空名 → json.loads(arguments) → 执行
```

| 流式细节 | 规则 |
|---|---|
| 标识 | 每个 delta 的 `tool_calls[i].index`——按 index 分桶 |
| ID | 可能缺失/后到——缺失则自生成 `call_<index>` |
| 函数名 | 可能后到——**缺名先缓存，不是致命错误** |
| arguments | 字符串片段——跨块 `+=` 拼接，流完再 `json.loads` |
| 排序 | 按 index 排序输出；跳过空名条目 |
| 收尾 | `finish_reason == "tool_calls"` 确认是工具提议轮 |
| 兜底 | 提供商不可靠 → `buffer_streamed_tool_calls=True`（流完合成完整块） |

> 🎯 核心要点（背诵版）：**流式的本质是把"一个完整 tool_calls"拆成 N 个分片**——聚合器按 index 分桶、跨块拼接；写手撕题时先画聚合器结构（index→{id,name,arguments}），再写"流完再解析"的收尾。

## 5. 三形态的选型对照（面试）

| 形态 | 何时用 | 面试一句话 |
|---|---|---|
| 并行 | 独立查询、吞吐优先 | 无依赖白拿吞吐，有依赖必须串行 |
| 强制 | 路由/提取/防误调 | 工具出口当结构化出口用 |
| 流式 | 长任务、体验优先 | 分片到达按 index 拼，流完再执行 |

## 6. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 并行调用的前提？ | 无依赖——A 的结果是 B 的参数就不能并行 |
| 强制调用怎么用？ | tool_choice=required/指定函数——路由与提取场景 |
| 流式怎么聚合？ | 按 index 分桶 + arguments 跨块拼接 + 流完再解析 |
| 流式收尾判据？ | finish_reason="tool_calls" |
| 函数名后到怎么办？ | 缓存不报错——缺名不是致命错（2026 常见坑） |
| buffer 兜底？ | buffer_streamed_tool_calls=True——流完合成完整块 |
