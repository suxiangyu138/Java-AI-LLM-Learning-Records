# 七步流程总图：完整生命周期

> 背诵篇：**一次函数调用的完整生命周期**——七步 + 两轮模式 + 角色分工。面试"讲讲函数调用的完整流程"的标准答案，也是本体系的总纲。

## 1. 七步总图（背诵版）

```text
一次工具调用的完整生命周期：
  ① 工具声明    Harness 把 tools 数组（JSON Schema）注入请求
  ② 模型决策    模型权衡：调工具 or 直接回答
  ③ 提议输出    message.tool_calls = [{id, function:{name, arguments}}]
  ④ Harness 执行  json.loads(arguments) → 校验 → 调用真实函数 → 得结果
  ⑤ 结果回传    {role:"tool", tool_call_id, content} 追加回消息列表
  ⑥ 再推理      模型综合"工具结果 + 历史"决定下一步
  ⑦ 定稿/循环   tool_calls 为空 → 输出最终答案；否则回到③
```

| 步 | 谁负责 | 产物 | 背诵要点 |
|---|---|---|---|
| ① 工具声明 | Harness（开发者） | tools 数组 | 描述决定调用质量（schema > 模型） |
| ② 模型决策 | LLM | 调/不调的判断 | 判断依据：工具描述 + 用户意图 |
| ③ 提议输出 | LLM | `tool_calls` 数组 | **arguments 是 JSON 字符串** |
| ④ 执行 | Harness（代码） | 真实函数结果 | **模型从不执行函数** |
| ⑤ 回传 | Harness（代码） | `role:"tool"` 消息 | **tool_call_id 原样复制** |
| ⑥ 再推理 | LLM | 下一轮决策 | 工具结果就是 ground truth |
| ⑦ 定稿/循环 | LLM + Harness | 最终答案 / 继续循环 | 零调用 = 自然出口 |

## 2. 两轮模式（理论核心）

> 🎯 核心要点（背诵版）：**函数调用是"两轮模式"**——第一轮：用户问题 → 模型提议（tool_calls）；第二轮：工具结果回传 → 模型定稿。**每次工具调用迭代 = 一次独立 API 请求**（5 步循环 ≈ 10 次调用，所以重试要指数退避）。

```text
第一轮（提议）：
  请求: system + user + tools → 响应: assistant(tool_calls)
第二轮（定稿）：
  请求: ... + assistant(tool_calls) + tool(结果) → 响应: assistant(最终答案)
```

## 3. 角色分工：模型 vs Harness（面试必背）

| 职责 | 模型（LLM） | Harness（你的代码） |
|---|---|---|
| 工具是什么 | 读描述理解 | 声明 schema、写真实函数 |
| 调不调、调哪个、参数是什么 | **决策 + 生成**（tool_calls） | —— |
| 执行 | ❌ 绝不执行 | ✅ 解析、校验、调用 |
| 结果 | 读回传内容 | 格式化、截断、回传 |
| 状态 | 无状态（每次请求独立） | 维护 messages 上下文 |

> ⚠️ 2026 铁律（面试第一句）：**"模型只输出意图（tool_calls），执行是 Harness 的活"**——所有"模型调用了函数"的说法都是比喻；真实执行发生在你的代码里。这一分工是安全的基石（模型不可信，参数要校验）。

## 4. 一次调用中的消息序列（时序图）

```text
用户
  │  "帮我查上海天气"
  ▼
Harness ──①请求(system+user+tools)──► LLM
  ▲                                   │
  │  ③assistant(tool_calls: get_weather)◄┘
  │
  │  ④json.loads({"city":"上海"}) → 调天气 API
  │  ⑤tool(tool_call_id, "多云 25°C")
  │
  │  ⑥请求(历史+assistant+tool) ──────► LLM
  │                                    │
  ◄── ⑦assistant("上海今天多云，25°C")◄──┘
  ▼
用户 ← "上海今天多云，25°C"
```

## 5. 三铁律（本体系总纲，贯穿后续各篇）

| 铁律 | 内容 | 违反后果 |
|---|---|---|
| A | `arguments` 是 **JSON 字符串**——执行前必须 `json.loads` | 直接把字符串当参数 → 类型错误 |
| B | `tool_call_id` **原样复制**（case-sensitive，不重建不索引） | 不匹配 → **400 错误** |
| C | **assistant 消息与 tool 消息都必须追加**回 messages | 漏一条 → 断上下文/请求被拒 |

## 6. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 函数调用完整流程？ | 声明→决策→提议（tool_calls）→执行→回传（tool）→再推理→定稿/循环 |
| 两轮模式？ | 提议轮 + 定稿轮——每次工具调用迭代 = 一次独立 API 请求 |
| 模型执行函数吗？ | 绝不——只输出意图，执行是 Harness 的活 |
| 三铁律？ | arguments 是 JSON 字符串 / tool_call_id 原样复制 / 两条消息都要追加 |
| 零调用意味着什么？ | 自然出口——模型认为无需工具，输出最终答案 |
| 一次循环几次调用？ | 5 步循环 ≈ 10 次 API 请求（重试要退避） |
