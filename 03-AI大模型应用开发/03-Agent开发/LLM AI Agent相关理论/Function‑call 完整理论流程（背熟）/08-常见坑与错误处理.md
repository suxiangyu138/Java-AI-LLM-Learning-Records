# 常见坑与错误处理

> 背诵篇：**生产中最常踩的十二个坑 + 400 错误族 + 修复对照**——面试"你踩过什么坑"的标准弹药库。详见 [Function Calling 基石 08 篇](..%2F..%2F..%2F02-大模型基础与Prompt工程%2FFunction%20Calling%20函数调用%E3%80%90Agent%20基石%E3%80%91%2F08-主流模型实现对比.md)（模型差异）。

## 1. 十二坑速查表（面试弹药）

| # | 坑 | 表现 | 修复 |
|---|---|---|---|
| 1 | **arguments 未解析** | 把 JSON 字符串直接当参数 | 执行前 `json.loads` + schema 校验 |
| 2 | **tool_call_id 不匹配** | 400 错误 | 原样复制（不重建不索引） |
| 3 | **漏追加 assistant 消息** | 上下文断裂/请求被拒 | assistant（含 tool_calls）与 tool 都追加 |
| 4 | **content 非字符串** | TypeError | `json.dumps(result)` |
| 5 | **判空用 `is not None`** | 空列表误判为"有调用" | `if message.tool_calls:` |
| 6 | **消息顺序错误** | 非法顺序（assistant 文本插在 tool_calls 与 tool 之间） | assistant(tool_calls) → tool → assistant |
| 7 | **流式缺函数名当致命错** | 聚合器崩 | 缺名先缓存（后到）——2026 常见坑 |
| 8 | **流式 ID 缺失** | 回传无 ID 可配对 | 自生成 `call_<index>` |
| 9 | **结果过大不截断** | 每轮重新 token 化——成本爆炸 | 截断 + 摘要（"Rows 1-10 of 250"） |
| 10 | **Chat Completions/Responses 格式混用** | "invalid parameter" SDK 报错 | 两协议格式不可混用（最常见报错源） |
| 11 | **DeepSeek 推理模式漏回传 reasoning_content** | 400 | 连同 thinking 一起回传 |
| 12 | **有依赖的调用并行** | 模型假设 A 结果已就绪 → 错误执行 | 无依赖才并行；拿不准串行 |

## 2. 400 错误族诊断（面试排查题）

| 错误形态 | 大概率根因 | 排查顺序 |
|---|---|---|
| 400 invalid parameter | 协议格式混用（坑 10）/ schema 非法 | 先查 tools 结构 → 再查消息格式 |
| 400 tool_call_id mismatch | ID 重建/索引错误（坑 2） | 检查回传代码是否用 `tc.id` |
| 400 missing tool message | 漏追加（坑 3） | 检查循环里 append 顺序 |
| 400 reasoning_content 缺失 | DeepSeek 推理模式（坑 11） | 检查封装层是否保留该字段 |
| TypeError（客户端） | content 非字符串（坑 4） | json.dumps 所有结果 |
| 无限循环/高账单 | 终止条件缺失 | 加轮次/预算/无进展检测 |

> 🎯 排查口诀（背诵版）：**"先协议、后配对、再顺序"**——400 一律先查：① tools 与消息格式对不对（协议）；② tool_call_id 是否原样（配对）；③ assistant/tool 顺序与追加（顺序）。

## 3. 工具层可靠性三指标（度量坑）

| 指标 | 度量什么 | 与坑的对应 |
|---|---|---|
| JSONValidation | schema 符合性 | 坑 1/4（参数与类型） |
| FunctionCallAccuracy | 名称/结构/类型/语义综合 | 坑 12（调用逻辑） |
| ToolSelectionAccuracy | 工具选对没有 | 选错工具（目录治理） |

## 4. 防御式编码清单（生产基线）

```text
执行函数前的五道防线（背诵版）：
  ① 解析：json.loads(arguments)（失败 → 结构化错误回传）
  ② 校验：参数对 schema（类型/必填/枚举/范围）
  ③ 授权：权限检查（该 Agent 能调此工具？）
  ④ 执行：try/except + 超时（指数退避重试）
  ⑤ 回传：结果截断 + json.dumps + 结构化错误（失败时）
```

## 5. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 最常见的坑？ | 未解析 arguments / ID 不匹配 / 漏追加消息 / content 非字符串 |
| 400 排查口诀？ | 先协议、后配对、再顺序 |
| 流式两个坑？ | 函数名后到（缓存不报错）+ ID 缺失（自生成） |
| 格式混用后果？ | invalid parameter——Chat Completions 与 Responses 不可混 |
| 执行前防线？ | 解析→校验→授权→执行→回传（五道） |
| 怎么度量踩没踩坑？ | 三指标：JSONValidation / FunctionCallAccuracy / ToolSelectionAccuracy |
