# 推理模型与函数调用

> 背诵篇：**推理模型（thinking）改变函数调用的节奏与细节**——先思后调、thinking 不传给循环、DeepSeek reasoning_content 回传铁律、外部轮次减少。面试"推理模型怎么影响函数调用"的答案。

## 1. 30 秒背诵卡

| 概念 | 背诵版一句话 |
|---|---|
| 先思后调 | 推理模型先内部思考（thinking tokens）再决定调哪个工具——计划在脑内完成 |
| 思考不进循环 | thinking 在服务端生成——**不返回给 Harness**，不可日志调试 |
| 内部计划 | 复杂任务的工具序列在 thinking 内规划好——外部轮次从 8-12 降到 2-3 |
| reasoning_content | DeepSeek 等模型的思考内容字段——**必须原样回传**否则 400 |
| 隐藏但计费 | thinking tokens 计费——Agent 开推理通常多发 2-5 倍 token |
| 工具调用期间思考 | 部分模型支持 thinking 贯穿工具调用（interleaved thinking） |
| 决策质量 | 推理提高"每步工具选择质量"——不消除循环与终止条件 |

## 2. 推理模型下的调用节奏（理论对比）

```text
普通模型：
  用户 → 调工具1 → 看结果 → 调工具2 → 看结果 → ...（外部 8-12 轮）

推理模型：
  用户 → [thinking: 规划工具序列] → 调工具1 → 看结果 → [thinking: 调整] → 调工具2
        → 外部轮次 2-3 轮——计划在脑内，执行在外部
```

| 维度 | 普通模型 | 推理模型 |
|---|---|---|
| 计划位置 | 外部（ReAct 显式思考文本） | **内部（thinking tokens）** |
| 外部轮次 | 8-12（复杂任务） | 2-3（内部已规划） |
| 工具选择质量 | 基线 | 更高（thinking 内权衡） |
| 可观测性 | 思考文本可见（可调试） | **不可见**（不可日志） |
| 成本 | 基线 | 2-5× token（thinking 计费） |

> 🎯 核心要点（背诵版）：**推理模型把"计划"从外部循环搬进内部 thinking——外部轮次变少，但循环不消失**（执行、反馈、终止仍在外部）；代价是 thinking 不可见不可调试 + 成本上升。金句："推理提高每步决策质量，不消除 Agent 循环"（与 [LLM 大脑篇](..%2F四大核心组件（面试必背）%2F01-LLM大脑：推理决策（面试必背）.md) 呼应）。

## 3. DeepSeek reasoning_content 铁律

| 要点 | 内容 |
|---|---|
| 现象 | DeepSeek 等模型响应含 `reasoning_content`（思考内容）与 `content`（正式回答） |
| 铁律 | **包含 tool_calls 的 assistant 消息必须连同 reasoning_content 一起回传**——漏掉会 400 |
| 原因 | 协议要求保持对话上下文完整（思考链与工具调用配对） |
| 其他模型 | OpenAI/Anthropic 的 thinking 默认不返回（服务端），无需回传 |

> ⚠️ 2026 踩坑点：国产模型（DeepSeek 系）推理模式 + 函数调用组合时，**"忘回传 reasoning_content"是 400 错误的第一大来源**；封装层要统一处理（存 reasoning_content 字段随消息原样带出）。

## 4. 流式下的 thinking 处理

| 细节 | 规则 |
|---|---|
| 字段 | 流式 delta 含 reasoning_content 增量（DeepSeek）或 thinking 块（部分模型） |
| 展示 | 可流式展示"思考中"给用户（体验）——但不能当最终输出 |
| 收尾 | finish_reason 仍判工具调用轮（tool_calls）或文本轮 |
| 聚合 | reasoning 增量独立聚合，不混入 arguments 拼接 |

## 5. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 推理模型怎么影响函数调用？ | 先思后调——计划内建，外部轮次 8-12 → 2-3 |
| thinking 能调试吗？ | 不能——服务端生成、不返回 Harness（DeepSeek 例外需回传） |
| reasoning_content 铁律？ | DeepSeek 必须原样回传否则 400——封装层统一处理 |
| 推理消除循环吗？ | 不——执行/反馈/终止仍在外部；只提高每步质量 |
| 成本影响？ | 2-5× token（thinking 计费）——按任务难度路由 |
| 循环终止还重要吗？ | 更重要——推理模型"更会继续"，刹车不能省 |
