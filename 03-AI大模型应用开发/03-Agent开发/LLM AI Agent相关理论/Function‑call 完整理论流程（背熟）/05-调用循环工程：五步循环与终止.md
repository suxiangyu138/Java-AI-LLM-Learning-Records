# 调用循环工程：五步循环与终止

> 背诵篇：流程第⑥⑦步——**把单次调用扩展成 Agent 循环**：五步循环、终止条件、错误回传、上下文管理。面试"怎么把函数调用做成 Agent"的标准骨架。工程深潜见 [Function Calling 基石 03 篇](..%2F..%2F..%2F02-大模型基础与Prompt工程%2FFunction%20Calling%20函数调用%E3%80%90Agent%20基石%E3%80%91%2F03-调用循环工程.md)。

## 1. 30 秒背诵卡

| 概念 | 背诵版一句话 |
|---|---|
| 五步循环 | ① 调模型 → ② 判空（无 tool_calls 则退出）→ ③ 解析执行 → ④ 回传 → ⑤ 回到① |
| 自然出口 | **零调用 = 循环自然终止**——模型认为无需工具，输出最终答案 |
| 硬上限 | 8-12 轮社区经验值——超出强制终止（防死循环烧钱） |
| 错误回传 | 工具失败转结构化 JSON 回传模型——**消除 ~80% 卡死** |
| 上下文管理 | 每轮全量历史重新 token 化——压缩/截断/摘要三件套 |
| 轮次成本 | 每轮一次 API 请求——5 步循环 ≈ 10 次调用（退避重试） |
| 可观测 | 每轮留痕（thought/action/observation）——排错前提 |

## 2. 五步循环（背诵版代码）

```python
messages = [{"role": "system", "content": SYSTEM}, {"role": "user", "content": TASK}]
for step in range(MAX_STEPS):                    # ② 硬上限（8-12 轮）
    resp = client.chat.completions.create(        # ① 调模型
        model=MODEL, messages=messages, tools=TOOLS)
    msg = resp.choices[0].message
    if not msg.tool_calls:                        # ② 判空：零调用 = 自然出口
        return msg.content                        #    → 输出最终答案
    messages.append(msg)                          # ③ 追加 assistant（含 tool_calls）
    for tc in msg.tool_calls:                     # ④ 解析 → 执行
        try:
            result = execute(tc)
        except Exception as e:
            result = {"error": str(e), "recoverable": True}   # 错误回传
        messages.append({                          # ⑤ 回传 tool 消息
            "role": "tool", "tool_call_id": tc.id, "content": json.dumps(result)})
# 超出硬上限 → 强制终止（不得无限循环）
raise AgentLoopError("超过最大轮次")
```

| 步 | 内容 | 铁律 |
|---|---|---|
| ① 调用 | create(messages, tools) | 每次全量历史 |
| ② 判空 | `if not msg.tool_calls:` → 返回 | **自然出口**（不要判 content） |
| ③ 追加 | assistant 消息入列 | 漏掉 = 断上下文 |
| ④ 执行 | 解析+校验+调用（try/except） | 失败转结构化错误回传 |
| ⑤ 回传 | tool 消息入列 | 回到① |

## 3. 终止条件（循环的"刹车"）

| 条件 | 机制 | 优先级 |
|---|---|---|
| 零调用自然出口 | 模型无 tool_calls → 定稿 | 首选（正常路径） |
| 最大轮次上限 | `for step in range(MAX_STEPS)` | 硬性兜底（8-12） |
| 无进展检测 | 连续 N 轮相同工具/相同参数 | 检测"原地打转" |
| 成本预算 | 累计 token 超限即停 | 钱是第一约束 |
| 目标达成检查 | 结果校验器确认完成 | 提前终止（省轮次） |
| 人工介入 | 高影响操作检查点 | 最高优先级 |

> ⚠️ 反面案例（面试弹药）：**四 LangChain Agent 循环 11 天烧 $47K**——终止条件缺失的代价。循环的默认行为是"继续"不是"停止"，刹车必须由 Harness 装。

## 4. 错误回传：让模型自修复

| 做法 | 示例 | 效果 |
|---|---|---|
| 结构化错误 | `{"error_code":"rate_limited","retry_after":30,"recoverable":true}` | 模型知道"等 30 秒重试" |
| 错误消息 | `{"error_code":"NOT_FOUND","message":"订单不存在","suggested_action":"查订单列表"}` | 模型走正确分支 |
| 空结果警告 | 空数组比结构化错误更糟 | 模型无推理依据 |

> 🎯 核心要点（背诵版）：**工具失败不是终点——把错误结构化回传给模型，让它自己决定重试/换工具/放弃**；这消除了约 80% 的"卡死"（模型瞎猜下一步）。

## 5. 上下文管理（多轮循环的隐形成本）

| 手段 | 机制 | 适用 |
|---|---|---|
| 滚动截断 | 窗口内保留最近 N 轮 | 短任务 |
| 摘要压缩 | 历史 → 任务状态卡（关键事实/已完成/下一步） | 中长任务 |
| 记忆外置 | 关键信息存外部记忆，按需注入 | 长任务（配合记忆组件） |
| 工具结果截断 | 4KB 摘要（"Rows 1-10 of 250"） | 所有循环 |

> 💡 2026 经验：**每轮全量重读是循环成本的主体**——复杂任务工具结果常占上下文大头；截断 + 摘要可省 50%+ token（详见 [成本优化](..%2F..%2F..%2F02-大模型基础与Prompt工程%2FFunction%20Calling%20函数调用%E3%80%90Agent%20基石%E3%80%91%2F09-生产实践与成本优化.md)）。

## 6. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 五步循环？ | 调模型→判空→执行→回传→循环（硬上限兜底） |
| 循环怎么终止？ | 零调用自然出口为主 + 轮次/预算/无进展/人工兜底 |
| 工具失败怎么办？ | 结构化错误回传模型——自修复，消除 80% 卡死 |
| 为什么轮次要设限？ | 循环默认继续——$47K 案例的教训 |
| 上下文怎么管？ | 滚动截断 + 摘要 + 工具结果截断（每轮全量重读是成本主体） |
| 一轮循环几次请求？ | 每个工具调用一次 API 请求——5 步 ≈ 10 次 |
