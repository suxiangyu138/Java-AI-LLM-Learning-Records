## 3. 区分方法论：三条主线

| 主线 | 判据 | 例子 |
|---|---|---|
| 谁控制循环 | 人类/开发者/模型 | Chatbot（人）vs Workflow（开发者）vs Agent（模型） |
| 什么进上下文 | 常驻/按需/外部 | 长上下文（全量）vs RAG（检索）vs 微调（权重） |
| 改什么 | 参数/提示/存储/流程 | 微调（参数）vs 提示（上下文）vs 记忆（存储） |

> 🎯 核心要点：**面试辨析三步——"先问谁控制、再问知识在哪、最后问改什么"**——三条主线覆盖 90% 的概念对；答不出控制者的概念辨析就是背定义。

## 5. 2026 生态基准

> 📅 基准窗口：2026-08。版本与事实以各模块【参考来源】为准。

- **四分类定型**：LLM（文本引擎）/Chatbot（对话+暂停等待）/Workflow（确定性预定义步骤）/Agent（模型控制循环）——**"谁控制循环"是第一判据**；Agent 定义特征 = **"授权的自主性"**（不是智能，是在边界内的自主规划/工具/验证）。
- **Agent 三问测试**（2026 实用判据）：① 能不经用户提示决定下一步吗？② 能用改状态的工具（创建/更新/提交）吗？③ 能验证结果并调整计划吗？——多数"否"就是助手/工作流。
- **2026 Agent 可用的原因**：不是单一模型突破，是**栈的持久迁移**——推理模型（规划/自检）+ run loops（多步到退出条件）+ MCP（工具标准化）+ 长上下文（100K-1M）+ 经济性；**难点不在模型在 harness**（循环/会话状态/工具权限/护栏/遥测）。
- **四大架构选型**：长上下文赢 <50K-100K 稳定语料（context rot 98%→64%、lost-in-the-middle）；RAG 是 90% 知识库场景默认（检索质量是 #1 失败点）；微调赢"行为"（**"Fine-tuning 是 Form、RAG 是 Fact"**）；Agent 赢"行动"（最贵最慢 500ms-3s+）——**组合是答案**（客服：微调路由 + RAG 检索 + Agent 行动 + 上下文管理）。
- **反模式编目**：简单 Q&A 用 Agent（零收益加成本）；微调加知识（最普遍误用——模型自信地幻觉更新信息）；未验证简单方案先建 Agent；v0 过度工程（先有评估器再谈架构）。
- **与体系分工**：[经典 Agent 范式](..%2F经典%20Agent%20范式（理论，面试高频）%2F00-经典Agent范式理论总览.md) 讲范式本体；本体系讲**概念对辨析**（面试混淆点）；各组件深化体系（Tool/记忆/编排）管机制细节。
