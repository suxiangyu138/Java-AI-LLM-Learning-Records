# 面试混淆点冲刺

> 收官篇：15 题概念辨析冲刺——每题一个混淆点，可直接背诵。

## Q1：LLM、Chatbot、Workflow、Agent 怎么区分？

> 第一判据"谁控制循环"：LLM 是文本引擎（组件）；Chatbot 人类驱动（答完就等）；Workflow 开发者驱动（路径预编码，LLM 只是流水线一步）；Agent 模型驱动（自主决定下一步）。一图：LLM"写解释"、Chatbot"答完就等"、Workflow"脚本+判断烘焙"、Agent"替你做"。

## Q2：Agent 三问测试？

> ① 能不经用户提示决定下一步吗？② 能用改状态的工具（创建/更新/提交）吗？③ 能验证结果并调整计划吗？——多数"否"就是助手/工作流。"能写邮件但不能发送/记 CRM/三天后跟进 = Chatbot 不是 Agent"。

## Q3：Agent 的定义特征？

> **授权的自主性（authorized autonomy）——不是智能**：在显式边界（护栏）内自主规划/工具/验证；组成：LLM（决策）+ 工具（行动）+ 记忆（状态）+ 控制循环；2026 难点不在模型在 harness（循环/会话/权限/护栏/遥测）。

## Q4：函数调用、工具、MCP、Skills？

> 四层叠加非替代：FC 是协议（怎么调）、工具是格式（调什么）、MCP 是基础设施（任何客户端连任何服务器——USB-C）、Skills 是判断（何时/顺序/条件，含护栏）。"FC 是基础能力、MCP 标准化基础设施、Skills 编码判断"；Tools 给动作、Skills 给判断（能力 vs 胜任力）。

## Q5：ReAct 与 Plan-and-Execute？

> 决策时机：ReAct 每步边想边做（控制流未知）；Plan-Execute 计划阶段一次（长程可分解）。成本：N×强 vs 1×强+N×便宜；失败：无限循环 vs 计划脆弱（re-plan 门兜底）；实证：Plan-Execute +27% 完成/-42% 工具调用。

## Q6：反思、重试、重规划？

> 治三层：动作层（重试——瞬时故障要同样结果）、策略层（反思——推理缺陷要不同结果）、路线层（重规划——计划失效换路径）。级联：反思发现计划失效→重规划；重试只针对基础设施（重试率 >5% 修契约）。

## Q7：记忆、上下文、知识库？

> 归属判据：上下文是窗口（当前装配）、记忆是 Agent 的（跨会话自产）、知识库是组织的（外部权威）。关系：知识库检索→装配进上下文→提取沉淀成记忆→召回再注入；长上下文（全量塞入 <50K-100K）vs RAG（按需检索）——context rot 98%→64%。

## Q8：编排、编排舞、编排器？

> 前两个是模式（怎么组织），第三个是组件（用什么做）：编排=中央控制（审计/单点）、编排舞=事件自治（弹性/难审计）、编排器=引擎（Temporal/Agent Executor——不决定组织方式）。生产混合：审计步骤编排、弹性步骤编排舞。

## Q9：Agent、多智能体、子 Agent？

> 数量+关系：Agent 单数独立；多智能体对等协作（A2A，各自目标）；子 Agent 从属委派（预算隔离）。"对方有自己的目标 = 多智能体；只执行你的任务 = 子 Agent"；'子'是从属关系不是能力大小；多 Agent 代价 3-10x token。

## Q10：RAG、微调、长上下文、Agent？

> 考试类比：长上下文=全书带进考场、RAG=开卷+图书管理员、微调=学一学期（冻结）、Agent=去做事。关键："微调是 Form（行为）、RAG 是 Fact（事实）"——微调加知识是最普遍误用；组合是答案（微调路由+RAG 检索+Agent 行动）。

## Q11：推理模型与普通模型？

> 推理模型 = 普通模型 + 思考机制（thinking tokens 隐藏但计费）。选型：多步可验证（数学/代码/规划）→ 推理；查找/摘要/高量分类 → 普通；递减收益（high→max 平）——"有正确的思考量"；路由自动降档省 50-80%。

## Q12：思考与反思？

> 时机与归属：思考是模型内部自省（回答前、内建、隐藏）；反思是系统外部评估-改进循环（回答后、组件可叠加、显式）。"先内隐后外显"——推理模型的 thinking 是内隐反思，Reflexion 是外显反思。

## Q13：CoT 与 ReAct？

> CoT 纯推理（中间步骤，不碰世界）；ReAct 推理+行动（工具结果接地）。2026：前沿模型推理内建后显式 CoT 提示不再帮助（HumanEval -15pp）；ReAct 底层循环仍承载工具调用（原生化）；ToT 是 CoT 的树扩展（三 yes 规则才上）。

## Q14：上下文工程与提示词工程？

> 提示词工程塑造"提示词里的词"；上下文工程设计"整个信息环境"（系统提示/检索知识/工具输出/历史/文件——一切进窗口的）。公式：context = Assemble(指令, 知识, 工具, 记忆, 状态, 查询)；"每个提示是被装配的，不是被写的"。

## Q15：范式路由与范式选型？

> 范式路由（2026 新理论）：Select-then-Solve 18K 运行实证——**无单一范式主导**（ReAct GAIA +44pp、CoT HumanEval -15pp）；oracle 每任务选择 +17.1pp、学习式路由器 +2.8pp——"范式是配置选择不是架构选择"；生产：评估驱动选范式 + 混合（执行形态+反思+重规划）。

## 答题范式

| 原则 | 说明 |
|---|---|
| 先判据后定义 | "谁控制循环""治哪层""归属"——判据比定义高级 |
| 带数据 | "3-10x""+27%""98%→64%""+17.1pp"——实证碾压空谈 |
| 说关系 | 叠加/层/级联——概念间关系比孤立定义重要 |
| 落工程 | 补一句"生产上我怎么做"（三问测试/决策规则/组合） |
| 提边界 | 何时不用：简单 Q&A 不用 Agent、无 oracle 不反思 |
