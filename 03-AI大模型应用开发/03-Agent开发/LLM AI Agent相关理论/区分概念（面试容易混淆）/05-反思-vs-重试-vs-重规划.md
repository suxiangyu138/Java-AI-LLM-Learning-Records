# 反思 vs 重试 vs 重规划

> 辨析篇：三个"修正"概念——**治什么病、改什么层**。深潜见 [Planner 05 篇](..%2F..%2FAgent%20子组件专项学习%2FPlanner%20规划器%2F05-重规划：观察驱动的计划修正.md) 与 [Reflection 01 篇](..%2F..%2FAgent%20子组件专项学习%2FReflection%20反思模块%2F01-反思全景：自我修正的边界.md)。

## 1. 三概念对比

| 维度 | 重试（Retry） | 反思（Reflection） | 重规划（Re-planning） |
|---|---|---|---|
| 治什么 | 瞬时故障（手抖） | 推理缺陷（脑子没想全） | 计划失效（路线错） |
| 改什么层 | 原样重跑 | 策略（怎么做） | 路线（走哪条） |
| 要什么结果 | **同样结果**（transient） | 不同结果（sampling） | 新路径 |
| 触发 | 失败 | 失败+关键步骤后 | 执行失败/环境变化 |
| 成本 | 低（重放） | 中（每轮+1 调用） | 中（重规划调用） |
| 前置 | 幂等保证 | oracle（可验证） | 计划表示可修订 |

> 🎯 核心要点：**三个概念治三层病——动作层（重试）、策略层（反思）、路线层（重规划）**；面试答对比先答"治哪层"，再答机制。

## 2. 混淆点 1：重试 vs 反思

| 判断 | 重试 | 反思 |
|---|---|---|
| 网络超时 | ✅ 重试（要同样结果） | ❌（重试即可） |
| 输出质量差 | ❌（重试同样错） | ✅ 反思（要不同结果） |
| 工具返回错误 | 看类型（基础设施可重试） | 业务失败不重试——反思换法 |

> ⚠️ 2026 铁律：**"重试只针对安全失败（基础设施）；反思针对推理失败"**——重试率 >5% 修契约不堆重试（Tool 06 篇）；把反思当重试 = 每轮从零开始（没利用批评）。

## 3. 混淆点 2：反思 vs 重规划

| 判断 | 反思 | 重规划 |
|---|---|---|
| 输出不对 | ✅ 反思（改做法） | ❌（先反思再决定） |
| 计划失效 | 反思发现（诊断） | ✅ 重规划（修正） |
| 环境变化 | ❌ | ✅ |
| 级联 | 反思发现计划问题 → 触发重规划 | 消费反思的诊断 |

> 💡 面试表述：**"反思是诊断器，重规划是修正器"**——反思发现问题（"计划假设失效"）→ 重规划执行修正（"换路径"）；先反思后重规划是标准级联（Planner 05 篇）。

## 4. 混淆点 3：重试 vs 重规划

| 维度 | 重试 | 重规划 |
|---|---|---|
| 对象 | 单次调用 | 整个计划 |
| 假设 | 操作本身没错（环境抖） | 计划本身错了（假设失效） |
| 例子 | 超时重发请求 | 工具被禁用→换备用链 |
| 成本 | 单调用 | 多步重排 |

> 🎯 一句话：**"重试假设'刚才只是运气不好'，重规划承认'计划想错了'"**——重试治执行、重规划治计划。

## 5. 生产级联（2026）

```text
失败处理级联：
  失败 → 分类（基础设施？→ 重试；推理？→ 反思；计划？→ 重规划）
  → 反思发现计划失效 → 重规划
  → 多轮无进展 → 人工升级（Guardrails 09 篇）
```

| 环节 | 预算 |
|---|---|
| 重试 | 指数退避 + 重试预算 |
| 反思 | 2-3 轮 + 最佳回滚 |
| 重规划 | 计入 max_iterations |
| 人工 | 出口（多轮无进展） |

> 💡 与 Orchestrator 05 篇联动：**三修正都在预算内**——重试/反思/重规划都是"循环内的成本"，全局预算防组合失控（$47,000 事故的防御）。

## 6. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 三概念治哪层？ | 动作层（重试）/策略层（反思）/路线层（重规划） |
| 重试要什么结果？ | 同样结果（transient） |
| 反思要什么结果？ | 不同结果（sampling） |
| 重试 vs 反思？ | 手抖 vs 脑子没想全 |
| 反思 vs 重规划？ | 诊断器 vs 修正器——先反思后重规划 |
| 重试 vs 重规划？ | 运气不好 vs 计划想错 |
| 重试率红线？ | >5% 修契约不堆重试 |
| 级联？ | 分类→重试/反思/重规划→人工出口 |
| 预算？ | 三修正都在循环内 |
| 与 $47,000 关系？ | 预算防组合失控 |
