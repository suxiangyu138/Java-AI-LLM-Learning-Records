# 评估与可观测性缺陷

> 背诵篇：**"看不见的失败"——Agent 的评估与可观测性缺陷**：沉默失败、不可复现、漂移、评估无 oracle。面试"为什么 Agent 难运维"的答案。

## 1. 30 秒背诵卡

| 概念 | 背诵版一句话 |
|---|---|
| 沉默失败 | Agent 报成功但输出错/卡住——89% 损坏的 API 集成无即时告警 |
| 不可复现 | 同一输入多次运行结果不同——非确定性（非确定性预算） |
| 失败不可见 | 失败与成功在 ~75% 完成前**统计上不可区分**（漂移系数 +0.227） |
| 无堆栈跟踪 | 错误以"看似合理文本"在 Agent 间传播——无法像调试程序定位 |
| 评估无 oracle | 开放任务无标准答案——"答得好不好"难定义（oracle 前提） |
| 法官漂移 | 评估 Agent 标准随使用漂移（Cohen's kappa ~0.6 需人工校准） |
| 可见性赤字 | 仅 21% 企业有运行时可见性（88% 遇袭的对照） |
| 治理方向 | 步骤级追踪 + 四层评估 + Agentic SRE（SLO 量化） |

## 2. 面试高频问题（背诵版）

**Q1. 为什么说 Agent 的失败是"看不见"的？**
> 答：三重不可见——① **无堆栈跟踪**：错误以自然语言文本在步骤间传递（幻觉、错误前提、推理漂移），没有异常对象可捕获；② **沉默失败**：Agent 倾向于"报告成功"（幻觉式恢复），89% 损坏的 API 集成无即时告警；③ **统计不可区分**：2026-02 研究显示失败与成功运行在 75% 完成前无法区分（漂移系数 +0.227，每次偏差使下次偏差概率 +23 点）——**你只能在预算耗尽后知道失败了**。

**Q2. Agent 为什么难评估？**
> 答：三个原因——① **非确定性**：同一输入多次运行结果不同（GPT-4o 8 次运行全成功概率 <25%），单次跑分不可靠；② **无 oracle**：开放任务没有标准答案——"这个调研 Agent 答得好不好"难定义（反思组件同理：无 oracle 反思会空转）；③ **评估对象分层**：检索/轨迹/生成/路由四层失败是不同病灶，聚合指标掩盖根因（检索差 vs 答错是两回事）。2026 共识：**先有评估器再谈 Agent 架构**（无评估的优化是盲调）。

**Q3. 生产里怎么"看见"Agent？（可观测性三件套）**
> 答：① **步骤级追踪**：每步留痕（thought/action/observation 落日志），全链路 OTel span——查询→路由→每次检索→评估→生成可回放；② **四层指标**：检索层（recall@k/context relevance）+ 轨迹层（任务完成/步数/检索次数分布）+ 生成层（faithfulness/groundedness）+ 路由层（tool-selection accuracy）；③ **SLO 量化（Agentic SRE）**：把 Agent 当"非确定性微服务"——成功率 <95% 告警、交接延迟 >30s 红旗、工具调用保真度跟踪——**没有指标就没有事故响应**。

**Q4. 评估器本身会坏吗？**
> 答：会——**法官漂移（judge drift）**：LLM 评估器/相关性判断 Agent 的标准随使用漂移（有时越来越松、有时越来越偏）。治理：定期用 50-100 条人工标注校准（目标 Cohen's kappa ~0.6）；四层评估各配独立评估器（同一模型既执行又评估 = 单一盲区，见 01 篇）。

## 3. 评估分层与工具（理论图）

```text
四层评估（各层独立指标，同 OTel span）：
  检索层：recall@k、context relevance      —— 检到对的东西了吗
  轨迹层：任务完成率、步数效率、检索次数分布 —— 循环走对了吗（over/under-retrieval）
  生成层：faithfulness、groundedness        —— 答案忠于证据吗
  路由层：tool-selection accuracy           —— 工具/路径选对了吗
```

| 缺陷 | 表现 | 治理 |
|---|---|---|
| 非确定性 | 同输入不同输出 | 多次运行取分布（5-8 次）+ 统计口径 |
| 无 oracle | 开放任务难判好坏 | 拆子任务找可验证部分 + 人工抽检 |
| 法官漂移 | 评估标准漂移 | 人工标注校准（kappa ~0.6） |
| 单一盲区 | 同一模型执行+评估 | 独立评估器/模型 |
| 无追踪 | 失败无法回放 | 步骤级 OTel span 全链路 |
