# 幻觉：自信地胡说

> 背诵篇：**Agent 场景下幻觉为什么更危险**——四类幻觉、循环放大机制、LLM09 Misinformation 法律后果。机制深潜见 [幻觉、格式错误、安全、token 超限 02/03 篇](..%2F..%2F幻觉、格式错误、安全、token%20超限%2F02-幻觉：原理与类型.md)。

## 1. 30 秒背诵卡

| 概念 | 背诵版一句话 |
|---|---|
| 幻觉 | 模型生成"不存在/不真实"的内容，且**语气自信**（权威语气 + 编造 = 最危险组合） |
| 四类幻觉 | 事实错误 / 逻辑矛盾 / 指令违反 / 凭空编造（出处在 Agent 场景最常见） |
| Agent 放大 | 幻觉结论被**循环回收**——检索-行动-反思中"复习"错误，越错越自信 |
| 检索侧幻觉 | 检索对但答错（生成失败）——RAG 治不了这半 |
| 法律后果 | 2026 LLM Top 10 把 Overreliance 重构为 **LLM09 Misinformation**——幻觉=安全漏洞 |
| 真实案例 | Air Canada 败诉（聊天机器人错退款政策）；律师引用编造判例；恶意包注册幻觉名称 |
| 治理三件套 | 接地（grounding）/ 验证（faithfulness 判断）/ 知边界（不知道就说不知道） |

## 2. 面试高频问题（背诵版）

**Q1. Agent 场景下幻觉为什么比单次对话更危险？**
> 答：三个放大——① **权威执行**：Agent 不是"建议"而是"行动"，幻觉内容会触发真实操作（发错邮件、下错单）；② **循环放大**：幻觉结论被回收进下一轮（检索-行动-反思），错误被"复习"增强——"persuasively wrong context gets promoted into action"（有说服力的错误上下文被提升为行动依据）；③ **复合传播**：一个 Agent 的幻觉成为另一个 Agent 的输入（01 篇确认偏差/级联失败）。

**Q2. 幻觉在 RAG Agent 里还会发生吗？**
> 答：会——RAG 只治"召回失败"那一半。幻觉分两类：**检索到错的**（召回失败，相关性评估+CRAG 可治）与**检索到对的但模型答错/编造**（生成失败，需 faithfulness 校验——Self-RAG 思路）。此外还有"检索不可达"（知识库没有 → 模型宁编不认）。金句：**"RAG 减少幻觉，但绝不消除幻觉——检索对≠答得对"**。

**Q3. 2026 年幻觉为什么被升格为"安全漏洞"？**
> 答：2026 LLM Top 10 把 Overreliance 重构为 **LLM09 Misinformation（错误信息）**——因为幻觉有了真实的法律与运营后果：Air Canada 因聊天机器人给出错误的退款政策被起诉并败诉；律师在法庭文件中引用 ChatGPT 编造的判例；攻击者**注册幻觉出来的包名**投放恶意包（供应链攻击新形态）。面试表述："幻觉从质量问题变成合规与安全风险——错误信息可被诉讼、可被武器化"。

**Q4. 怎么治理 Agent 幻觉？**
> 答：三层——① **接地**（grounding）：事实任务必须检索注入（RAG），不靠参数记忆硬答；② **验证**：faithfulness 判断（生成内容是否忠于证据）+ 检索相关性评估（结果不够就重检，CRAG 思路）；③ **边界纪律**：明确"不知道就说不知道"，禁止编造补偿（2026 实证：Agent 会"幻觉式恢复"——编造表单数据代替停下来求助，比幻觉本身更糟）。

## 3. 幻觉的循环放大机制（理论图）

```text
单次对话：编造一句 → 用户识破（人可纠错）
Agent 循环：
  编造"事实" → 当作前提继续推理 → 检索更多"证据"（围绕错误假设）→ 更自信
  → 触发行动（发信/下单/写码）→ 错误被固化为"已完成"
  无人工在环：没有人说"这是错的"
```

| 环节 | 放大机制 |
|---|---|
| 前提固化 | 编造事实被当作推理前提，后续全部基于它 |
| 证据自洽 | 检索围绕错误假设进行，找到"支持性证据"（越搜越像真的） |
| 行动固化 | 触发真实操作后，"已完成"状态让错误难以回滚 |
| 无纠错环 | 无人工/无 oracle 验证 → 错误一路到底 |
