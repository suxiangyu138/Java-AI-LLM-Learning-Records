# 循环失控：死循环与成本黑洞

> 背诵篇：**Agent 自主性最昂贵的缺陷——循环失控**：$47K 案例、三周采购死循环、成本放大的三个隐藏乘数。面试"Agent 有什么风险"的第一论据。

## 1. 30 秒背诵卡

| 概念 | 背诵版一句话 |
|---|---|
| 循环失控 | Agent 卡在重复执行同一失败子任务，无限消耗资源 |
| 经典案例 | 四 LangChain Agent 循环 11 天烧 **$47,000** |
| 极端案例 | 制造采购 Agent 卡死循环 **三周**（IBM CIO 手册，2025-10） |
| 行业定性 | IBM：死循环 + 级联决策错误 = 企业多 Agent 系统**首要失败模式** |
| 沉默失败 | 89% 损坏的 API 集成无即时告警——循环正在烧钱时无人知道 |
| 三个隐藏乘数 | 每轮全量上下文重读 / 重复摘要 / 冗长工具输出 |
| 并发放大 | 未封顶的并行用户把"几次慢运行"变成"计费事故" |
| 本质 | 循环有"动力"（模型永远能想出下一步）缺"刹车"（终止条件） |

## 2. 面试高频问题（背诵版）

**Q1. Agent 为什么会死循环？**
> 答：三个原因——① **模型总有"下一步"**：LLM 面对失败任务倾向于再试一次（换个说法重试），不像程序会抛异常停下；② **失败子任务不可跳过**：卡在 CAPTCHA/弹窗/验证失败上，反复重试同一动作；③ **缺终止条件**：没设最大轮次/无进展检测/成本预算——"循环有动力没刹车"。社区名言：**Agent 循环的默认行为是继续，不是停止**。

**Q2. 循环失控的真实代价？**
> 答：三层——① **直接成本**：$47K（11 天）/ 三周死循环——每次循环都在调模型、重读全量上下文；② **隐藏乘数**：每轮把整个对话历史重新喂给模型（上下文成本随轮次线性涨）、重复摘要、冗长工具输出——**成本不是线性增长，是每轮全量重读的指数感觉**；③ **并发放大**：用户/任务无上限并行时，"几次慢运行"瞬间变成"计费事故"。

**Q3. 怎么防死循环？（六个刹车）**
> 答：终止条件六件套——① 最大迭代上限（硬轮数，最可靠）；② token/成本预算（累计超限即停）；③ 无进展检测（连续 N 轮相同工具/相同输出 → 判定循环）；④ 时间上限（墙上时钟兜底）；⑤ 目标达成检查（反思出口：完成自检）；⑥ 人工介入检查点（高影响动作必须确认）。生产基线：**迭代上限 + 成本预算 + 无进展检测三件套**。

**Q4. 为什么循环失控很难被及时发现？**
> 答：**沉默失败**——Agent 报"成功"但输出是错的、或者默默卡住，无告警（实证：89% 损坏的 API 集成无即时告警）。原因：① 循环在"正常调用"模型/工具（没有异常可抓）；② 无步骤级追踪时，人看到的只是"一直在跑"；③ 失败与成功在 75% 完成前统计上不可区分（01 篇）——**你以为它在思考，其实它在原地打转**。对策：步骤级可观测 + 断路器 Agent（见 08 篇）。

## 3. 成本放大机制（理论图）

```text
一次"卡住"的循环：
  第 1 轮：调用模型（上下文 2K）→ 调工具 → 失败
  第 2 轮：调用模型（上下文 4K，重读历史）→ 同一工具 → 失败
  第 10 轮：上下文 20K+ 全量重读 → 同一工具 → 失败
  ...
  成本 ∝ 轮数 × 每轮全量上下文——不是线性，是每轮都在"重读全书"
```

| 隐藏乘数 | 机制 | 对策 |
|---|---|---|
| 上下文重读 | 每轮把全部历史喂回模型 | 上下文压缩 / 摘要 / 窗口截断 |
| 重复工具输出 | 冗长工具结果反复注入 | 工具输出截断（4KB 摘要） |
| 重复摘要 | 每轮重新摘要（越轮越多） | 只摘要一次 + 增量 |
| 并行无上限 | 任务并发放大计费 | 并发上限 + 预算池 |
| 无退出路径 | 失败任务不标记"放弃" | 失败计数 → 超过阈值改人工 |
