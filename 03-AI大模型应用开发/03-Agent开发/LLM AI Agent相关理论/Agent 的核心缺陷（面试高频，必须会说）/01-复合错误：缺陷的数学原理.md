# 复合错误：缺陷的数学原理

> 理论篇：**Agent 缺陷的根源数学——错误相乘而非相加**。0.95^n 问题、Lusser 定律、非确定性预算、级联失败。面试"为什么 Agent 不可靠"的数学答案。

## 1. 核心数学：成功率相乘

| 单步成功率 | 5 步 | 10 步 | 20 步 | 30 步 |
|---|---|---|---|---|
| 95%/步 | ~77% | ~60% | ~36% | ~21% |
| 90%/步 | ~59% | ~35% | ~12% | ~4% |
| 98%/步 | ~90% | ~82% | ~67% | ~55% |

> 🎯 核心要点（背诵版）：**Agent 系统成功率 = 各步成功率的乘积（Lusser 定律）**——95% 的"看起来不错"的单步成功率，串 20 步后只剩 36%。每多一步，都在消耗"可靠性预算"。这是 Agent 与普通程序的根本差异：普通程序一步错会抛异常停下，Agent 会"带着错误继续走"。

## 2. 关键实证数据（面试弹药）

| 实证 | 数据 | 含义 |
|---|---|---|
| 90%/步 × 10 步任务 | 总成功率 20-35%（×15 步 ~20%） | 看似高的单步精度在长任务上崩盘 |
| 98%/Agent × 10 Agent（Lusser） | ~81.7%（3 Agent ~94.1%） | 多 Agent 每加一个都拖系统精度 |
| GPT-4o 同一零售任务跑 8 次 | 单次 ~65%，8 次全成功 **<25%** | 可靠性是"可消耗资源"（非确定性预算） |
| 真实 agentic 工作流 | 63% 失败率（2026 实证） | 企业级数据 |
| MIT（2025-08） | 95% 企业生成式 AI 试点失败 | 多数败在组合与架构 |

> 💡 **非确定性预算（Non-Determinism Budget）**：把系统可靠性想成预算——每次模型决策、每个未校验的边界都消耗预算；预算耗尽 = 失败。**失败与成功运行在 ~75% 完成前统计上不可区分**（2026-02 漂移研究），所以"预算还剩多少"无法事先知道。

## 3. 错误为什么"相乘"而不"相加"（理论机制）

| 机制 | 说明 | 例子 |
|---|---|---|
| 错误传播 | 上一步的错误输出成为下一步的错误输入 | 查询改写错 → 检索错 → 生成错（每一步都在错的基础上继续） |
| 级联失败 | 一个 Agent 的坏输出变成另一个 Agent 的坏输入，跨线程放大 | swarm 中 A 的幻觉被 B 当真继续加工 |
| 确认偏差（conformity bias） | 下游 Agent 顺从上游自信的断言，不反驳 | 一个错误结论被锁定为"事实共识" |
| 单一盲区（monoculture） | 同一模型既规划又验证 | 计划与检查共享同一盲点——"自己查自己"查不出 |
| 自信放大 | 推理越强，错的越自信（inverse scaling under noise） | "更有能力的推理产生更自信的错误"并在循环中回收放大 |

> ⚠️ 关键洞察：**错误传播是无声的——"没有堆栈跟踪、没有告警"**（89% 损坏的 API 集成无即时告警）；Agent 之间以"看似合理的文本"传递错误，人无法像调试程序一样定位。

## 4. 复合错误的三种放大形态

| 形态 | 机制 | 后果 |
|---|---|---|
| 串行放大 | 多步任务中错误沿链传播 | 成功率指数衰减（0.95^n） |
| 并行放大 | 多 Agent 并行，一个错的输出污染多个分支 | 级联失败（Cascade Failures） |
| 循环放大 | 错误结果被回收进下一轮循环（检索-行动-反思） | 错误被"复习"增强（persuasively wrong context gets promoted into action） |

## 5. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 为什么 Agent 不可靠？ | 成功率相乘（Lusser 定律）——95%/步 ×20 步 ≈ 36% |
| 关键实证数字？ | 90%×10 步 20-35%；98%×10 Agent 81.7%；8 次全成功 <25%；63% 工作流失败 |
| 非确定性预算？ | 可靠性是可消耗资源——失败与成功在 75% 前不可区分 |
| 错误为什么相乘？ | 错误传播无告警 + 确认偏差 + 单一盲区 + 自信放大 |
| 2026 核心判断？ | 缺陷不在模型质量，在组合与架构（MIT 95% 试点失败） |
| 与普通程序的区别？ | 程序一步错就抛异常停；Agent 带错继续走，且无堆栈跟踪 |
