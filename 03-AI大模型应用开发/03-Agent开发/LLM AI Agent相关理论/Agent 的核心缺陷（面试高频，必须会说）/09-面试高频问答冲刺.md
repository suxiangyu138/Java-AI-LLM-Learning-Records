# 面试高频问答冲刺

> 冲刺篇：「Agent 的核心缺陷」主题面试集训——20 题 + 答题范式 + 金句弹药库。内容源自本体系 01-08 篇，按"总述→分缺陷→应对"三段组织。

| 题型 | 范式 | 例子 |

## 2. 二十题冲刺

### 【总述组】

**Q1. Agent 的核心缺陷是什么？一句话。**
> 答：**"Agent 的缺陷不是模型笨，是'把不可靠的组件串成系统'——错误会相乘，不是相加"**。三层结构：组件层（幻觉/工具不可靠/记忆污染）、系统层（复合错误/循环失控/上下文退化）、信任层（不可观测/安全漏洞/难评估）。

**Q2. 为什么 Agent 比普通程序不可靠？**
> 答：普通程序一步错会抛异常停下；Agent 会"带着错误继续走"且无堆栈跟踪——错误以自然语言在步骤间传播（幻觉、错误前提、推理漂移），成功率是各步之积（Lusser 定律）：95%/步 ×10 步 ≈ 60%、×20 步 ≈ 36%。

**Q3. 关键数据弹药有哪些？**
> 答：① 数学：0.95^10≈60%、0.95^20≈36%、98%×10 Agent≈81.7%、GPT-4o 8 次全成功 <25%；② 成本：$47K 循环 / 三周死循环；③ 工具：payload 幻觉 38%、多轮掉 30-60pp；④ 安全：88% 遇袭/21% 可见性/97% 预期/6% 预算；⑤ 上下文：rot 98%→64%；⑥ 现实：63% 工作流失败、MIT 95% 试点失败。

### 【分缺陷组】

**Q4. 复合错误为什么"相乘"？**
> 答：错误传播无告警 + 确认偏差（下游顺从上游）+ 单一盲区（同模型执行又评估）+ 自信放大（越强越自信地错）——每一步都在错误基础上继续，四机制把单步错误放大为系统失败。

**Q5. Agent 场景下幻觉为什么更危险？**
> 答：三重放大——权威执行（幻觉触发真实操作）、循环放大（错误被检索-行动-反思"复习"）、复合传播（一个 Agent 的幻觉成为另一个的输入）。2026 升格：LLM09 Misinformation——Air Canada 因聊天机器人败诉、律师引用编造判例。

**Q6. 循环失控的原因与代价？**
> 答：模型总有"下一步"+ 失败子任务不可跳过 + 缺终止条件——循环有动力没刹车。代价：$47K（11 天）/ 三周采购循环 + 每轮全量上下文重读的隐藏乘数 + 并行无上限。**Agent 循环的默认行为是继续，不是停止**。

**Q7. 什么是 context rot？**
> 答：长任务上下文增长导致早期信息稀释，模型丢失"任务模型"——任务越做越差；实证 98%→64%；**更多上下文可能更糟**（干扰项）。治理：压缩摘要 + re-grounding（每 ~9 步，-80% 失真）。

**Q8. 工具层最大的失败来源？**
> 答：payload 幻觉（模型凭记忆重建嵌套 schema，~38% 生产失败）+ 多轮编排退化（BFCL V4 掉 30-60pp，顺序选工具是序列决策问题）+ 幻觉式恢复（编造补偿代替求助）。

**Q9. 为什么提示注入是"结构性"问题？**
> 答：① 权限继承——Agent 带凭据行动，攻击者继承权限；② 命令与数据在同一 token 流、无可靠边界（OWASP：不可根治，映射 Agentic Top 10 中 6 类）。**目标不是防住注入，是控制爆炸半径**。

**Q10. 致命三要素？**
> 答：私有数据访问 + 接触不可信内容 + 对外通信——三者同时具备时，任何一次注入都变数据外传工具（Simon Willison）。设计评估时先查这三个条件。

**Q11. Agent 的失败为什么"看不见"？**
> 答：无堆栈跟踪 + 沉默失败（89% 无告警）+ 失败与成功在 75% 前统计上不可区分（漂移 +0.227）——只能在预算耗尽后知道失败。

**Q12. Agent 为什么难评估？**
> 答：非确定性（同输入不同输出，8 次全成功 <25%）+ 无 oracle（开放任务无标准答案）+ 四层病灶聚合掩盖根因。2026 共识：**先有评估器再谈架构**。

### 【应对组】

**Q13. 应对的总框架？**
> 答：三层防线——预防（契约化工具/最小权限/终止条件：少犯）、检测（步骤级追踪/四层指标/断路器：看见）、遏制（校验门/隔离/回滚/人工接管：不扩大）。**核心：错误无法根治，让错误便宜**。

**Q14. 六大战术？**
> 答：校验门（不传未验证状态）/ 断路器 Agent（小模型监控争论>3 轮/停滞/礼貌螺旋）/ 确定性外壳（能代码化就代码化）/ re-grounding（每 ~9 步，-80% 失真）/ 检查点-验证（最后安全点续跑）/ 人工在环（确认门+转人工）。

**Q15. 怎么防死循环？**
> 答：终止条件六件套——迭代上限 / 成本预算 / 无进展检测 / 时间上限 / 目标达成检查 / 人工介入；生产基线三件套（迭代+预算+无进展）+ 断路器 Agent 兜底。

**Q16. Agent 安全怎么防护？**
> 答：五层——最小权限（每 Agent 独立身份+每调用校验）/ 人工确认门（不可逆动作）/ 内容隔离（不可信内容与指令分离）/ 外传控制（URL 白名单+DLP）/ 运行时监控（机器速度+临时凭据——攻击分钟级完成）。

**Q17. Agentic SRE 怎么管？**
> 答：把 Agent 当非确定性微服务——成功率 <95% 告警、交接延迟 >30s 红旗、工具保真度跟踪、**cost per successful outcome**（成本>价值就降自主度）；事故响应：隔离（撤写权限）→快照→回滚→复盘（四层评估定位）。

**Q18. 编排怎么选才不放大缺陷？**
> 答：正式编排框架 + 校验门（失败率降 3.2×）；Planner-Worker-Judge（独立验证防单一盲区）；**复杂度不是复杂度**——一个强 Agent + 计算机控制常常打败脆弱的五 Agent 链；先最简形态+验证边界。

**Q19. 多 Agent 特有的失败模式？**
> 答：级联失败（一个 Agent 坏输出成为链上所有输入）、确认偏差锁定假共识、通信不安全（ASI07）、并行交叉污染——多 Agent 每加一个都按 Lusser 定律拖低系统精度（98%×10≈81.7%）。

**Q20. 面试最后怎么收尾？**
> 答：金句收尾——"Agent 缺陷的本质是概率性组件串成系统；我的应对是三层防线——预防让它少犯、检测让它被看见、遏制让它不扩大；2026 的判断是：**可靠性的钥匙不在更强的模型，在确定性脚手架、校验边界与可观测性**。"

| "注入无法根治——目标是控制爆炸半径" | 安全 |

## 4. 进阶追问（加分项）

| 追问 | 加分回答 |
|---|---|
| 推理模型能解决这些缺陷吗？ | 部分——thinking 内建提高单步质量（少犯），但循环失控/安全/可观测与思考无关——推理越强越要护栏（自信放大） |
| Agent 和微服务运维有什么区别？ | 微服务是确定性的（错误可复现、有堆栈）；Agent 非确定性+无堆栈+沉默失败——所以要 SLO/追踪/断路器（Agentic SRE） |
| 什么场景不该上 Agent？ | 失败代价不可控/无 oracle 可验证/延迟敏感/成本>价值——先 Workflow（Anthropic 简单性原则） |
| 怎么评估一个 Agent 好不好？ | 四层分离评估（检索/轨迹/生成/路由）+ 多次运行取分布 + 人工抽检校准 + cost per successful outcome |
