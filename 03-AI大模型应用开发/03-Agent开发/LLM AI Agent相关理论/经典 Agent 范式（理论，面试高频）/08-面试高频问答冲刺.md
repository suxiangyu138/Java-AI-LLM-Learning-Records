# 面试高频问答冲刺

> 收官篇：经典范式的 15 题面试冲刺——理论 + 对比 + 选型全覆盖，可直接背诵。

## Q1：Agent 范式演进的三代？

> 提示工程（会答：CoT/Few-shot）→ 推理范式（会想：ToT/GoT/PAL）→ Agent 范式（会做：ReAct/Plan-Execute/Reflexion）——**叠加非取代**；2026 第四阶段：范式路由（每任务选范式）；驱动是模型能力内建（推理模型让外部脚手架部分冗余）。

## Q2：ReAct 是什么？优劣？

> 推理与行动交织循环（Thought→Action→Observation，Yao 2022）——Agent 范式奠基。优：简单（while+单调用）/灵活/可解释/接地降幻觉；劣：无全局视图/无限循环风险（四 Agent 循环 11 天 $47,000）/高 token/长程规划弱。2026：原生化（底层循环不变、文本提示成历史）——保留给信息收集与未知流任务。

## Q3：ReAct 与 CoT 区别？

> CoT 纯推理（中间步骤，不碰世界）；ReAct 推理+行动（工具结果接地推理）。2026 前沿模型推理内建后 CoT 显式提示不再帮助（HumanEval -15pp），ReAct 的循环形态仍承载工具调用。

## Q4：Plan-and-Execute 与 ReAct 怎么选？

> 长程可分解/静态可预测 → Plan-Execute（+27% 完成、-42% 工具调用、-35% 时间；1×强+N×便宜）；控制流未知/动态 → ReAct（边想边做）。Plan-Execute 固有代价：计划脆弱——re-plan 门（每 K 步/低置信）是标配（BabyAGI/Devin）。

## Q5：Reflexion 是什么？前提？

> 语言化自我批评 + 情景记忆（Shinn 2023，verbal RL）——HumanEval 91% vs 80%。**前提：可验证 oracle**（测试/编译器/ground truth）——无 oracle 退化为自证偏见；三因子公式：oracle × 评判器独立性 × 修订执行力。

## Q6：Reflexion 与 Self-Refine 区别？

> 反馈来源外部性：Reflexion 用外部反馈（测试/工具——可靠）；Self-Refine 用模型自己的批评（同模型同盲区——2026 不推荐单独用）。"自我反思不能作为自己的评判器"（GSM8K 实证自我修正下降）。

## Q7：ToT 是什么？什么时候值得用？

> 树搜索推理（Yao 2023：生成候选+评估+搜索，Game of 24 4%→74%）。**三 yes 规则**：① CoT <50%？② 失败是前 1-2 步错误承诺？③ 有忠实评估器 + 容忍 3-30x token？——两个或更少 yes 留在 CoT；2026 推理模型内部搜索通常打败外部 ToT（外部保留：可观察分支/可转向/搜索即 API/成本上限）。

## Q8：推理模型改变了什么？

> 推理内建（o 系列/R1/Claude thinking 内部多步推理）——显式 CoT/ReAct 脚手架部分冗余；ToT 被内部搜索超越；外部范式从"主引擎"变"工程工具"；新问题：何时显式、何时内建（范式路由）。

## Q9：范式路由（Select-then-Solve）？

> 2026 新理论：六范式 × 四模型 × 十基准 18K 运行——**无单一范式主导**（ReAct GAIA +44pp、CoT HumanEval -15pp）；oracle 每任务选择 +17.1pp；学习式路由器 +2.8pp（47.6%→53.1%）；零样本自路由仅 GPT-5 有效。"范式是配置选择不是架构选择"。

## Q10：五生产形态？

> 单 Agent ReAct（起步）/Plan-and-Execute（长程）/层级监督（多域路由）/Maker-Checker（行动者+验证者——幻觉结构性防御）/网络 Swarm（对等协作）。生产原则：从最简单开始，基线暴露失败再升级。

## Q11：范式怎么选？（决策树）

> 长程可分解 → Plan-Execute；控制流未知 → ReAct；高价值可重复+oracle → 加 Reflexion；幻觉敏感 → Maker-Checker；简单任务 → 直接/CoT；不确定 → 评估集跑范式对比（数据说话）。

## Q12：范式的成本模型？

> ReAct：N 步 × 强模型（每步重决策浪费）；Plan-Execute：1×强 + N×便宜（强思考压缩到计划）；Reflexion：每轮 +1 调用（高价值才值）；ToT：3-30x token（三 yes 才上）；推理模型：思考 token 计费（路由+旋钮）——"选对范式 > 选对模型"。

## Q13：范式融合怎么搭？

> ReAct+CoT（动态+可见推理）、ToT+Reflexion（全局优化+动态调整）、Plan-Execute+Reflection（长程+关键步质量）、ReAct+推理模型（信息收集外部循环+深度分析内建）、Reflexion 持续学习（程序记忆跨会话更新）——2026 默认混合。

## Q14：范式与组件的关系？

> 范式是"行为模式"（理论层），组件是"工程构件"（实现层）：ReAct 对应 Tool 执行循环（Tool 06 篇）、Plan-Execute 对应 Planner 组件、Reflexion 对应 Reflection 组件、ToT 可落为 Planner+Evaluator 协作——范式是理论，组件是落地。

## Q15：2026 范式理论前沿？

> 范式路由（Select-then-Solve）、SwiReasoning（隐式/显式切换 +57-79% token 效率）、FoT（统一推理框架）、Long CoT 调查（深度推理特征）、overthinking 治理（限思考块）、Maker-Checker 幻觉防御、多范式融合——范式从"选一个"走向"每任务组合"。

## 答题范式

| 原则 | 说明 |
|---|---|
| 结构优先 | 机制 → 实证 → 对比 → 选型 |
| 带数据 | "+27%""4%→74%""$47,000""+17.1pp"——实证碾压空谈 |
| 说权衡 | "ReAct 灵活但无全局""Plan 高效但计划脆弱（re-plan 兜底）" |
| 落工程 | 补一句"生产上我怎么做"（re-plan 门/防循环/评估驱动选型） |
| 提边界 | 何时不用：简单任务不浪费范式；无 oracle 不加反思 |
