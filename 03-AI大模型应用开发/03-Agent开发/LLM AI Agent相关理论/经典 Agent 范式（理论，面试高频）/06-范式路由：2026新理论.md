# 范式路由：2026 新理论

> 理论篇：**"没有单一范式主导，范式选择是每任务的决策"**——Select-then-Solve 的实证与新理论（2026 面试加分点）。

## 1. 核心实证：Select-then-Solve（arXiv 2604.06753，2026）

| 项 | 说明 |
|---|---|
| 规模 | 六范式（Direct/CoT/ReAct/Plan-Execute/Reflection/ReCode）× 四前沿模型 × 十基准 ≈ **18,000 次运行** |
| 关键发现 1 | **推理结构在部分任务大赢、部分任务大亏**——ReAct 在 GAIA 超 Direct **44pp**；CoT 在 HumanEval **降 15pp** |
| 关键发现 2 | **无单一范式主导**——oracle 每任务选择超最佳固定范式平均 **17.1pp** |
| 关键发现 3 | 学习式轻量路由器（embedding 基）47.6%→53.1%——超最佳固定范式 2.8pp、恢复 oracle 差距的 37% |
| 关键发现 4 | **零样本自路由只对 GPT-5 有效**——弱模型自选失败 |

> 🎯 核心要点：**"范式不是架构选择，是配置选择"**——固定用 ReAct 或 Plan-Execute 等于放弃 17pp 潜在收益；2026 理论转向"每任务选范式"（学习式路由器）。

## 2. 为什么没有单一范式主导

| 任务特征 | 适合范式 |
|---|---|
| 信息收集（GAIA 类） | ReAct（行动接地） |
| 代码生成（HumanEval 类） | 推理模型/直接（CoT 反而伤） |
| 长程可分解 | Plan-Execute |
| 高价值可重复 | 加 Reflection |
| 错误修复循环 | ReCode |

> ⚠️ 关键洞察：**"范式与任务的匹配度 > 范式本身的强弱"**——CoT 在数学强但在代码是负收益；"选对范式比选对模型更重要"（2026 中文来源共识）。

## 3. 路由器机制

```text
范式路由（2026）：
  任务输入 → 嵌入 → 轻量路由器（学习式分类器）
    → 选范式（Direct/CoT/ReAct/Plan-Execute/...）
    → 执行 → 评估 → 反馈优化路由器
```

| 路由器类型 | 效果 | 状态 |
|---|---|---|
| Oracle（每任务最优） | +17.1pp | 理论上限 |
| 学习式路由器（embedding 基） | +2.8pp（vs 最佳固定） | 2026 推荐 |
| 零样本自路由（模型自选） | 仅 GPT-5 有效 | 弱模型失败 |
| 规则路由（按任务类型） | 部分有效 | 简单场景 |

> 💡 路由器是"范式层的 Router 组件"（LLM 大脑 06 篇按轮路由的范式级版本）——学习式选择替代人工固定；2026 仍早期，但方向明确（恢复 oracle 差距的 37%）。

## 4. 范式融合：2026 趋势

| 融合 | 机制 |
|---|---|
| ReAct + CoT | 动态响应 + 可见推理 |
| ToT + Reflexion | 全局优化 + 动态调整 |
| Plan-Execute + Reflection | 长程 + 关键步质量 |
| ReAct + 推理模型 | 深度分析内建 + 信息收集外部循环 |
| Reflexion 持续学习 | 程序记忆跨会话更新（免全量微调） |

> 🎯 核心要点：**2026 范式实践 = 组合而非单选**——"混合范式"成为默认（LLM 大脑 05 篇按轮路由、本体系 07 篇五生产形态）；范式路由与范式融合是同一趋势的两面（选对 + 组合对）。

## 5. 生产启示

| 启示 | 落地 |
|---|---|
| 别固定单一范式 | 评估集上跑范式对比（Select-then-Solve 方法论） |
| 从简单开始 | 单 Agent ReAct 起步——多范式只在基线暴露失败时加 |
| 路由器渐进 | 先规则路由（任务类型）→ 再学习式 |
| 评估驱动 | 每范式跑同评估集——数据说话（Evaluation 09 篇） |

> ⚠️ 2026 理论边界：**范式路由的评估成本**——跑六范式对比 = 6x 评估成本；路由器的收益（+2.8pp）要在评估预算内权衡；"范式路由"是方向，不是每团队都要上（先规则后学习）。
