# 面试高频问答冲刺

> 冲刺篇：「Agent × RAG」主题面试集训——18 题 + 答题范式 + 金句弹药库。内容源自本体系 01-08 篇，按"分工→边界→融合→选型"四段组织。

## 2. 十八题冲刺

### 【分工组】

**Q1. RAG 和 Agent 是什么关系？**
> 答：正交的两种能力——RAG 回答"知道什么"（知识：事实/时效/私有数据），Agent 回答"做什么"（行动：多步/工具/目标）。四象限：直接生成 / 工具型 Agent / 纯 RAG / **Agentic RAG（融合主形态）**。它们不是能力高低档，是不同问题的解。

**Q2. 为什么"有了 Agent 还要 RAG"？**
> 答：Agent 解决不了知识问题——幻觉、知识截止、私有数据依旧存在；推理模型无内置持久记忆（MAI-Thinking-1 实证）。思考归模型（test-time compute）、知识归检索（RAG）、行动归循环（Agent）——三者正交各管一段。

**Q3. 融合的本质是什么？**
> 答：把检索从"流水线的固定步骤"重铸为"Agent 决策空间里的可调用工具"——检索获得判断力（何时检、检什么、检几次、够不够），Agent 获得知识供给。2026 一句话：Agentic RAG 已是严肃 Agent 技术栈的默认检索形态。

### 【边界组】

**Q4. 纯 RAG 什么时候必然失效？**
> 答：四类查询——多跳（查了再查）、歧义（问清楚再答）、迭代（换了再找）、跨文档综合（拼了才全）。判定口诀：**"一次检索能答 = RAG；要查了再查/问清楚/换了再找/拼了才全 = 必须 Agent 介入"**。

**Q5. RAG 单次检索的上限数据？**
> 答：CRAG/MultiHop-RAG 基准多跳问题 **50-60% 上限**；AgenticRAGTracer 最难关 GPT-5 精确匹配仅 **22.6%**——失败源于推理链过早坍缩或过度延伸（链管理问题，非单次检索质量）。

**Q6. 纯 RAG 的三个失效场景？**
> 答：强制检索（简单问题也检，浪费+污染）、检索失败硬用（差结果进上下文，比不检更糟）、无评估环节（幻觉无法拦截）。RAG 幻觉分两类：召回失败与生成失败——后者需要反思机制（Agent 化）。

**Q7. Agent 的知识缺口？怎么补？**
> 答：四类——幻觉/知识截止/私有数据/外部状态。四条来源：参数记忆/上下文注入/RAG 检索（2026 默认）/微调。金句：**微调是 Form（行为）、RAG 是 Fact（事实）——"微调加知识"是最普遍误用**。

### 【融合组】

**Q8. 四种融合模式？**
> 答：① RAG 即工具（检索封装成 Agent 工具）；② 流程智能化（判断力拆进 RAG 流水线六决策点）；③ 记忆合一（知识库 = 长期记忆实现）；④ 编排多源（主管 Agent 分派多知识库并行综合）。

**Q9. Agentic RAG 的理论内核？**
> 答：检索决策化五决策点——**检不检 / 检什么 / 怎么检 / 够不够 / 不够怎么办**。纯 RAG 只有"怎么检"是技术决策；Agentic RAG 把其余四个全变成模型决策。

**Q10. CRAG 与 Self-RAG 的区别？**
> 答：CRAG 检索后纠正（五 Agent：检索/相关性评估/查询精化/外部兜底/响应综合——评估 Agent 是裁判）；Self-RAG 反思贯穿生成全程（边生成边自查 faithfulness）。共同前提：检索域天然有 oracle（文档即证据），所以反思比开放任务更可靠。

**Q11. Agent in RAG 的六决策点？**
> 答：路由分类器（Adaptive RAG 分流）/查询改写/检索器选择（learned policy）/相关性评估/纠正（CRAG 式）/faithfulness 校验——不付完整循环成本，逐个智能化。

**Q12. 为什么用户查询不能直接检索？**
> 答：用户语言≠检索语言——检索器是词面/语义匹配器不是意图理解器；需要指代消解、口语化转检索友好、多路查询、子问题分解。

**Q13. 记忆与 RAG 什么关系？**
> 答：**技术同构、语义不同、生产常合一**——记忆是"Agent 自身状态"（会变，要时间戳+遗忘+防投毒），知识库是"组织知识"（相对稳定）；共用同一检索栈（混合检索/图记忆），生产上长期记忆往往就实现为 RAG 检索系统。

### 【选型组】

**Q14. 七种融合架构模式？**
> 答：Naive / Advanced / Self-RAG / Graph RAG / Adaptive RAG / Agentic RAG / Multi-Agent RAG——决策化深度递增、成本递增（1× → 40×+）。

**Q15. 生产推荐入口？**
> 答：**Adaptive RAG（查询分类器分流）**——简单查询付 1×、多跳查询掉进 agentic 路径付 20-40×，整体账单远低于全量 Agentic。2026 推荐基线。

**Q16. 融合的成本账怎么算？**
> 答：token 预算（复杂查询典型 8 倍 naive、最高 40×）＋检索预算（≤4 次、评估 ≤2 轮）＋延迟预算（每轮 +200-500ms 向量/+300-800ms 重排，端到端 5-15s 可接受？）。

**Q17. 融合系统的评估怎么分层？**
> 答：四层——检索层（recall@k/context relevance）/轨迹层（任务完成/检索次数分布）/生成层（faithfulness/groundedness）/路由层（tool-selection accuracy）——同 OTel span 全链路追踪，评估器定期人工校准（kappa ~0.6）防 drift。

**Q18. 2026 融合反模式？**
> 答：① 简单 Q&A 上 Agentic RAG（20-40× 换零收益）；② 无评估器先谈架构；③ v0 过度工程（先 Adaptive 起步，数据驱动升级）；④ 检索器固定不路由（语义查询跑 BM25 = 工具误路由）。

## 4. 进阶追问（加分项）

| 追问 | 加分回答 |
|---|---|
| 推理模型对 RAG 的影响？ | 推理内建提升"怎么答"，RAG 依然解决"答什么"——思考与知识正交；长上下文不能取代按需检索（context rot） |
| Agentic RAG 的幻觉还有吗？ | 有——检索对但答错（生成失败）用 faithfulness 校验；检索错用相关性评估+CRAG 纠正；"无 oracle"环节仍有风险 |
| 怎么防 over-retrieval？ | 硬步骤预算 ~4 次 + 无进展检测 + 证据充分即停（防过度延伸）——检索次数是成本函数不是质量函数 |
| 企业落地顺序？ | Advanced RAG → Adaptive → Agentic → Multi-Agent → 记忆融合——评估数据驱动升级 |
| 与 GraphRAG 的关系？ | 关系型查询选图索引、语义查询选向量——Index-Retrieve-Fuse-Generate 四阶段框架内选型；Agent 可按查询在两者间路由 |
