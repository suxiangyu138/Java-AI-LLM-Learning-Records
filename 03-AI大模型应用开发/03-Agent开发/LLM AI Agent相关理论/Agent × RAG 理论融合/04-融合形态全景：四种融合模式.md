# 融合形态全景：四种融合模式

> 理论篇：Agent 与 RAG 融合的**四种形态**（RAG 即工具 / 流程智能化 / 记忆合一 / 编排多源）——机制、适用、代表，以及融合谱（naive RAG → agentic RAG 的连续演化）。工程实现见 [RAG 体系 10-RAG 与 Agent 结合](..%2F..%2F..%2F04-RAG检索增强生成%2F10-RAG与Agent结合.md)。

## 1. 四种融合模式总表（面试背诵版）

| 模式 | 方向 | 机制 | 一句话 |
|---|---|---|---|
| **RAG 即工具** | RAG → 融入 Agent | 检索封装为 Agent 的工具，Agent 决策调用 | "检索变成 Agent 的一个技能" |
| **流程智能化** | Agent → 融入 RAG | RAG 流水线的决策点由模型/分类器接管 | "检索流水线长出判断力" |
| **记忆合一** | RAG ↔ 记忆组件 | 知识库 = Agent 长期记忆的实现 | "知识库就是记忆的存储" |
| **编排多源** | Agent 编排多个 RAG/检索源 | 主管 Agent 分派多域检索并行综合 | "一个大脑管多个知识库" |

## 2. 模式一：RAG 即工具（Agentic RAG 核心形态）

```text
Agent 循环：
  Thought → 需要事实？→ 调用 retrieval(query) → 观察结果
                        → 结果够？→ 生成答案
                        → 不够 → 改写查询再检 / 换源 / 放弃
```

| 维度 | 内容 |
|---|---|
| 机制 | 检索（+重排）封装为工具，schema 声明"何时用、怎么填参" |
| Agent 决策点 | 检不检 / 检什么 / 检几次 / 结果够不够 / 不够怎么办 |
| 适用 | 多跳、歧义、迭代任务（02 篇的四类查询） |
| 代表 | LangGraph、OpenAI Agents SDK、任何 MCP 驱动 Agent（2026 默认） |
| 成本 | 复杂查询 20-40× naive RAG |

## 3. 模式二：流程智能化（Agent in RAG）

| 决策点 | 传统 RAG | 智能化 RAG |
|---|---|---|
| 查询进入 | 直接检索 | **路由分类器**（简单→快速路径，复杂→agentic 路径——Adaptive RAG） |
| 查询使用 | 原文 | **改写/拆解/多路查询**（query rewriting） |
| 检索器选择 | 固定一个 | **按查询选**（BM25/稠密/混合/图——learned policy） |
| 结果评估 | 不评估 | **相关性判断**（够不够准？） |
| 失败处理 | 硬用 | **纠正**（CRAG：换源重检/外部检索兜底） |
| 生成校验 | 不校验 | **faithfulness 反思**（Self-RAG：判断是否 grounded） |

> 🎯 理论要点：**模式二是"把 Agent 的判断力拆进 RAG 流水线的每个环节"**——不引入完整循环，只在关键点加决策。适合"不想为一次问答付出完整 Agent 循环成本"的生产场景。

## 4. 模式三：记忆合一（知识库即记忆）

```text
Agent 记忆四层：
  工作记忆（上下文窗口）── 短期（会话缓冲）── 长期（语义/情景/程序）── 归档
                                                │
                长期记忆的语义层 = RAG 检索系统（向量库/图/混合检索）
                RAG 知识库 = 组织级"长期语义记忆"（静态知识、多用户共享）
```

| 视角 | 记忆组件 | RAG 知识库 |
|---|---|---|
| 语义 | Agent 自身状态（偏好/轨迹/结论） | 组织外部知识（文档/制度/手册） |
| 生命周期 | 随 Agent 会话演化 | 独立维护（索引更新） |
| 技术 | **同构**：混合检索/图记忆/向量库 | **同构**：同一套检索基础设施 |
| 生产 | 常合一：长期记忆直接实现为 RAG 检索 | 常合一：知识库同时服务记忆与问答 |

> 💡 面试答"Agent 的记忆和 RAG 什么关系"：**技术同构、语义不同、生产常合一**——记忆管"我记住了什么"（动态状态），RAG 管"组织知道什么"（静态知识）；两者共用检索栈（BM25+向量+RRF），在实现上往往是一个系统。详见 07 篇。

## 5. 模式四：编排多源（Multi-Agent RAG）

| 维度 | 内容 |
|---|---|
| 机制 | 主管（supervisor）Agent 把查询拆给多个专业检索子 Agent（不同域知识库），并行检索后综合 |
| 适用 | 跨域查询（技术+财务+法务）、多知识库组织 |
| 理论依据 | 单一索引检索精度随规模下降——分域索引 + 主管路由更准 |
| 代表 | OpenAI Agents SDK manager 模式、CrewAI 多角色 |
| 风险 | 协调成本（误路由/重复检索）——单源够用别上多源 |

## 6. 融合谱：从 naive RAG 到全 Agent（连续演化）

| 阶段 | 形态 | 决策能力 | 成本 |
|---|---|---|---|
| 1 | Naive RAG | 无（强制一次检索） | 1× |
| 2 | Advanced RAG（混合检索+重排） | 无（流水线优化） | 2-4× |
| 3 | 智能化 RAG（路由/改写/纠正） | 部分（流水线内决策点） | 3-8× |
| 4 | Agentic RAG（检索即工具+循环） | 完整（Agent 决策） | 8-40× |
| 5 | Multi-Agent RAG（多域编排） | 完整 + 编排 | 40×+ |

> 🎯 2026 理论结论：**融合不是二选一，是沿着融合谱选择"决策化的深度"**——从"零决策"到"完整决策"，决策越多能力越强、成本越高；选型本质是在"失效概率 × 失效代价"与"决策成本"之间取平衡（08 篇决策树）。

## 7. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 四种融合模式？ | RAG 即工具 / 流程智能化 / 记忆合一 / 编排多源 |
| 模式一的本质？ | 检索变成 Agent 决策空间里的可调用工具 |
| 模式二把决策拆在哪？ | 路由/改写/选检索器/评估/纠正/校验——六决策点 |
| 模式三的关键？ | 知识库 = 长期记忆实现——技术同构、语义不同、生产合一 |
| 模式四的适用？ | 跨域多知识库——主管 Agent 拆解并行检索综合 |
| 融合谱？ | naive → advanced → 智能化 → agentic → multi-agent——决策化深度递增、成本递增 |
