# 融合架构模式与选型决策

> 理论篇：Agent × RAG 的**架构模式全景与选型决策**——按查询复杂度/成本/延迟/幻觉容忍度路由的 2026 模式指南、决策树、成本预算方法。与 [区分概念 08](..%2F区分概念（面试容易混淆）%2F08-RAG-vs-微调-vs-长上下文-vs-Agent.md)（四大架构选型）分工：本表管"融合后选哪个模式"。

## 1. 七种架构模式全景（2026 模式指南）

| 模式 | 机制 | 适用 | 延迟 | 相对成本 |
|---|---|---|---|---|
| **Naive RAG** | 一次检索+生成 | 简单事实查询 | <1s | 1× |
| **Advanced RAG** | 混合检索+重排 | 混合查询需 >85% 精度 | 1-2s | 2-4× |
| **Self-RAG** | 生成全程反思 | 幻觉不可接受的高风险场景 | 2-4s | 3-6× |
| **Graph RAG** | 图索引（+混合） | 实体关系丰富/跨文档关联 | 2-5s | 3-8× |
| **Adaptive RAG** | 查询分类器路由 | **混合复杂度生产负载（2026 推荐基线）** | 0.5-15s 按路径 | 1-8× 均值低 |
| **Agentic RAG** | 检索即工具+循环 | 多跳/复杂综合/可容忍 5s+ | 5-15s | 8-40× |
| **Multi-Agent RAG** | 主管+专业检索子 Agent | 跨域查询、多知识库 | 10s+ | 40×+ |

> 🎯 核心要点（背诵版）：**2026 生产推荐路径——"先 Adaptive RAG（分类器分流），复杂查询才掉进 Agentic 路径"**：简单查询付 1× 成本，多跳查询付 20-40× 成本，整体账单远低于"全量 Agentic"。

## 2. 选型决策树（面试答题框架）

```text
查询进来：
  ├─ 需要外部知识吗？
  │    ├─ 不需要 → 直接生成（或 Adaptive RAG 的简单路径）
  │    └─ 需要 → 继续
  ├─ 多跳/歧义/需澄清？
  │    ├─ 否 → Advanced RAG（混合检索+重排）够吗？
  │    │        ├─ 够 → Advanced RAG
  │    │        └─ 幻觉不可接受？→ Self-RAG（反思校验）
  │    └─ 是 → 继续
  ├─ 实体关系复杂？→ Graph RAG（或混合向量+图）
  ├─ 需要迭代检索/多轮？→ Agentic RAG（检索即工具）
  ├─ 跨域多知识库？→ Multi-Agent RAG（主管编排）
  └─ 生产混合负载？→ Adaptive RAG（分类器分流全局入口）
```

| 决策问题 | 选 A | 选 B |
|---|---|---|
| 查询复杂度 | 简单 → Naive/Advanced | 复杂 → Agentic |
| 幻觉容忍度 | 可容忍 → 常规 | 不可容忍 → Self-RAG |
| 关系密度 | 低 → 向量 | 高 → 图/混合 |
| 多域 | 单库 → 单 Agent | 多库 → Multi-Agent |
| 负载混合 | 同质 → 单模式 | 混合 → Adaptive 路由 |

## 3. 成本预算理论：先算账再融合

| 预算项 | 方法 |
|---|---|
| token 预算 | 预估每轮全量上下文 × 轮数（Agentic 复杂查询典型 8 倍 naive） |
| 检索预算 | 检索次数 ≤4、评估轮次 ≤2（超 = 设计问题） |
| 延迟预算 | 每轮向量 +200-500ms、重排 +300-800ms；端到端 5-15s 是否可接受 |
| 治理预算 | 每步 span 追踪 + 四层评估（检索/轨迹/生成/路由） |

> ⚠️ 2026 反模式（面试避坑题）：① 简单 Q&A 上 Agentic RAG（20-40× 成本换零收益）；② 无评估器先谈架构（先有评估再调优）；③ v0 过度工程（先 Adaptive RAG 起步，数据证明不够再升级）；④ 检索器固定不路由（语义查询跑 BM25 = 工具误路由）。

## 4. 可观测与评估：融合系统的"仪表盘"

| 层 | 指标 | 回答的问题 |
|---|---|---|
| 检索层 | recall@k、context relevance | 检到对的东西了吗 |
| 轨迹层 | 任务完成率、检索次数分布 | 循环走对了吗（over/under-retrieval 检测） |
| 生成层 | faithfulness、groundedness | 答案忠于证据吗 |
| 路由层 | tool-selection accuracy | 检索工具/路径选对了吗 |

> 💡 生产实践：所有指标挂同一 OTel span——查询 → 路由决策 → 每次检索 → 评估 → 生成的完整链路可回放；**评估器校准**（50-100 条人工标签，Cohen's kappa ~0.6 目标）防 judge drift。

## 5. 融合架构演进路径（企业落地）

| 阶段 | 形态 | 何时升级 |
|---|---|---|
| 1 | Advanced RAG | 起步（成本最低、可快速上线） |
| 2 | Adaptive RAG | 混合负载出现、账单分化 |
| 3 | Agentic RAG | 多跳查询占比上升、评估证明单次检索不足 |
| 4 | Multi-Agent RAG | 跨域知识库需求、单一索引精度不足 |
| 5 | 记忆融合（知识库即记忆） | 需要跨会话个性化与状态 |

> 🎯 演进原则（Anthropic 简单性原则在融合域的应用）：**"只有实证能改进结果时才增加复杂度"**——先最简形态上线，用评估数据驱动升级，而不是一开始就搭全套。

## 6. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 七种模式？ | Naive/Advanced/Self-RAG/Graph/Adaptive/Agentic/Multi-Agent RAG |
| 生产推荐入口？ | Adaptive RAG（分类器分流）——简单付 1×、复杂付 20-40× |
| 选型四问？ | 复杂度/幻觉容忍/关系密度/多域 |
| 成本预算？ | 检索 ≤4 次、评估 ≤2 轮、端到端 5-15s 是否可接受 |
| 反模式？ | 简单 Q&A 上 Agentic / 无评估先谈架构 / 检索器不路由 |
| 演进路径？ | Advanced → Adaptive → Agentic → Multi-Agent → 记忆融合——数据驱动升级 |
