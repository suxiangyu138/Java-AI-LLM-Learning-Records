# RAG 的失效边界：何时必须 Agent 介入

> 理论篇：纯 RAG 在哪些任务上必然失效——多跳/歧义/迭代/多源四类查询的失败机制与实证数据，以及"失效边界 = Agent 介入条件"的理论推导。工程实现见 [RAG 体系 17-AgenticRAG 与自我反思](..%2F..%2F..%2F04-RAG检索增强生成%2F17-AgenticRAG与自我反思.md)。

## 1. 单次检索的理论上限

| 基准 | 单次检索成绩 | 含义 |
|---|---|---|
| CRAG / MultiHop-RAG（多跳问答） | **50-60% 上限** | 单次检索在多跳问题上必然失败近半 |
| AgenticRAGTracer（2026，1,305 条多跳验证） | 最难关卡 GPT-5 精确匹配仅 **22.6%** | 最强模型也扛不住复杂多跳 |
| 失败根因（hop-aware 诊断） | 推理链**过早坍缩**或**过度延伸** | 不是检索不到，是"链断了" |

> 🎯 核心要点：**RAG 的失效不是检索质量问题，而是"单次检索"这个交互模式的结构性上限**——需要"用 A 的结果去查 B"的任务，任何单次流水线都做不了。这就是 Agent 介入的理论依据：多跳 = 需要循环。

## 2. 四类必须 Agent 介入的查询（理论分类）

| 查询类型 | 机制 | 例子 | 为什么单次 RAG 必败 |
|---|---|---|---|
| **多跳（Multi-hop）** | 查 A → 用 A 的结果查 B → 综合 | "查这个项目的负责人，再查他负责的其他项目" | 单次检索拿不到链条 |
| **歧义澄清（Clarification）** | 问题本身不明确，需要追问 | "给我推荐个方案"（哪个领域？什么约束？） | 没有澄清对话能力 |
| **迭代精化（Iterative）** | 初次结果差，要换词/换源重查 | "搜'服务降级'没找到，试试'熔断'" | 无重检索机制 |
| **跨文档综合（Synthesis）** | 结论分散在多个文档 | "总结各部门 2026 上半年预算执行" | 单次召回片段拼接不完整 |

> 💡 判定口诀（面试可背）：**"一次检索能答 = RAG；要'查了再查'、'问清楚再答'、'换了再找'、'拼了才全' = 必须 Agent 介入"**。

## 3. 纯 RAG 的三个经典失效场景（理论模型）

| 失效场景 | 机制 | 后果 |
|---|---|---|
| 强制检索（总是检） | 简单问题也走检索 | 浪费 + 无关上下文污染生成 |
| 检索失败不处理（硬用） | 检索结果差也拼进上下文 | 生成被污染（比不检索更糟） |
| 无评估环节（拿来就用） | 不判断结果相关性与充分性 | 幻觉无法被拦截（RAG 仍有幻觉） |

> ⚠️ 关键洞察：**RAG 的幻觉分两类——检索到的内容错（召回失败）与检索到的对但模型答错（生成失败）**；纯 RAG 只能缓解前者的一半（靠相关性评估），后者需要反思/校验机制（Self-RAG 的 faithfulness 判断）——这类机制本身就是 Agent 化（评估-决策-再行动）。

## 4. "何时 Agent 介入"的判定表（面试答题框架）

| 信号 | 判定 | 介入形态 |
|---|---|---|
| 问题可分解为多个子查询 | 多跳 | 检索作为工具 + 循环 |
| 用户输入含糊/有歧义 | 需澄清 | 对话式澄清（Agent 追问） |
| 首次检索结果相关性低 | 需重检索 | 改写查询/换检索器（CRAG） |
| 答案需要跨文档综合 | 需多源综合 | 多次检索 + 综合生成 |
| 事实型单次问答 | **不需要** | 纯 RAG（别过度工程） |
| 延迟 <500ms 硬约束 | **不需要** | 纯 RAG（Agent 循环 5-15s） |

## 5. 成本边界（融合不是免费）

| 形态 | 典型成本 | 延迟 |
|---|---|---|
| 纯 RAG | 1×（基线） | <1s |
| Agentic RAG（复杂查询） | **20-40×**（4 轮检索+重排；典型 token 8 倍） | 5-15s |
| 每轮检索增量 | 向量 +200-500ms / 重排 +300-800ms | —— |

> 🎯 理论结论：**Agent 介入的判据 = 单次 RAG 失效概率 × 失效代价 > 循环成本**。简单事实问答（失效概率低）用 RAG；多跳任务（失效概率高）必须 Agent——但也要先算账：一次"查了再查"值不值 8 倍 token。

## 6. 面试速记

| 问题 | 一句话答案 |
|---|---|
| RAG 单次检索的上限？ | 多跳问题 50-60%（CRAG/MultiHop-RAG）；AgenticRAGTracer 最难关 GPT-5 仅 22.6% |
| 四类必须 Agent 的查询？ | 多跳 / 歧义澄清 / 迭代精化 / 跨文档综合 |
| 纯 RAG 三个失效场景？ | 强制检索浪费 / 检索失败硬用 / 无评估环节 |
| 判定口诀？ | 一次检索能答=RAG；查了再查/问清楚/换了再找/拼了才全=Agent |
| 介入的代价？ | 复杂查询 20-40× 成本、5-15s 延迟——先算账再融合 |
