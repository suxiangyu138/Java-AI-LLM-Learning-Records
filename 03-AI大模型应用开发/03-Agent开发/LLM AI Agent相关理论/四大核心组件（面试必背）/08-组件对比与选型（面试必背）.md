# 组件对比与选型（面试必背）

> 背诵篇：组件之间的对比与易混点 + 组件能力选型决策 + 常见误区。概念对深度辨析见 [区分概念体系](../区分概念（面试容易混淆）/00-区分概念总览.md)（本表管组件层，该体系管概念层）。

## 1. 组件 vs 组件：六组高频对比

| 对比 | 一句话区别 | 易混点 |
|---|---|---|
| 大脑 vs 循环 | 大脑管"想得对不对"，循环管"系统动不动" | 推理模型提高决策质量，**不消除**循环 |
| 规划 vs 反思 | 规划管"怎么拆"，反思管"拆得/做得对不对" | 反思的三大出口之一就是"重规划"——联动 |
| 工具 vs 行动 | 工具是"能力声明"，行动是"执行与反馈" | 深潜版分两篇；面试答"工具行动"一体也行 |
| 记忆 vs 上下文 | 记忆是"我记住了什么"（跨轮状态），上下文是"这轮看什么"（窗口内容） | 工作记忆 = 上下文窗口，但概念不同层 |
| 反思 vs 重试 | 反思是结构化批评-改进；重试是原样再来 | 反思失败会退化为重试——必须有评估依据 |
| 规划 vs 计划 | 规划是能力（拆解+编排），计划是产物（步骤列表） | "计划是假设"——执行偏离必须 re-plan |

## 2. 组件能力选型决策树（面试答题框架）

```text
组件怎么选？按"任务特性"逐问：
  ├─ 任务多步可验证？ → 是：推理模型大脑 + 反思组件（oracle 可验证）
  │                    否：快速模型大脑，少反思（空转风险）
  ├─ 任务结构可知？   → 是：Plan-and-Execute
  │                    否：自适应规划（re-plan 门必须）
  ├─ 跨会话状态需要？ → 是：长期记忆（混合检索/图记忆）
  │                    否：工作记忆 + 短期缓冲足够
  ├─ 需要外部行动？   → 是：工具组件（schema 铁律 + <20 工具）
  │                    否：纯生成任务，不需要 Agent
  └─ 失败代价高？     → 是：人工确认门 + 沙箱 + 幂等
                       否：放手跑 + 终止条件兜底
```

| 决策点 | 选 A 的判据 | 选 B 的判据 |
|---|---|---|
| 推理模型 vs 快速模型 | 多步可验证（坏计划浪费工具调用） | 查找/摘要/分类（成本延迟主导） |
| Plan-Execute vs 自适应 | 结构可知（步骤稳定） | 结构不可知（会偏离需修正） |
| 反思开 vs 关 | 高价值 + oracle + 错误代价高 | 低价值 / 无验证信号 / 延迟敏感 |
| 长期记忆 vs 短期 | 跨会话需要（偏好/历史/知识） | 单会话内完成 |
| 工具多 vs 少 | 任务天然多系统 | **<20 活动工具**——用检索/合并治理 |
| 单 Agent vs 多 Agent | 任务简单（先单后多） | 可分解+需并行+协调成本 < 收益 |

## 3. 组件成熟度对比（2026 生产视角）

| 组件 | 成熟度 | 2026 主战场 | 生产红线 |
|---|---|---|---|
| LLM 大脑 | ★★★★★ | 推理模型路由 / thinking 成本 | 别全量开 thinking（最大成本错误） |
| 工具组件 | ★★★★☆ | schema 契约化 / MCP 标准化 | 描述写不好 = 准确度崩 |
| 行动组件 | ★★★★☆ | 错误回传 / 幂等 / 护栏 | 写操作不幂等 = 事故 |
| 记忆组件 | ★★★☆☆ | 混合检索 / 图记忆 / 治理 | 纯向量库丢关系时效 |
| 规划组件 | ★★★☆☆ | 前瞻反思 / 动态行动空间 | 无 re-plan = 计划失效硬执行 |
| 反思组件 | ★★★☆☆ | 前瞻反思 / 独立批评者 | 无 oracle 空转烧钱 |

## 4. 常见误区总表（面试"避坑"题）

| 误区 | 正解 |
|---|---|
| "最强模型 + 全部工具 = 最强 Agent" | 模型同质化 2026——Harness/组件工程质量才是差异 |
| "反思 = 让模型再想想" | 必须有独立批评者 + 验证信号，否则是重试 |
| "记忆 = 向量库" | 纯向量丢关系与时效——混合检索/图记忆是 2026 趋势 |
| "工具描述随便写" | 描述是工具调用准确度第一大因素 |
| "计划写完就执行到底" | 计划是假设——偏离必须 re-plan |
| "thinking 打开就完事" | 收益递减——按难度路由是成本正解 |
| "上下文越长记忆越好" | 注入预算纪律——灌满窗口规划退化 |
| "多 Agent 比单 Agent 强" | 先单后多——协调成本常被低估 |

## 5. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 规划 vs 反思？ | 怎么拆 vs 对不对——联动（重规划出口） |
| 工具 vs 行动？ | 能力声明 vs 执行反馈 |
| 记忆 vs 上下文？ | 我记住了什么 vs 这轮看什么 |
| 选型主线？ | 按任务特性逐问：可验证/结构可知/跨会话/外部行动/代价 |
| 2026 最被高估/低估？ | 高估：多 Agent 与全量 thinking；低估：工具工程与记忆治理 |
