# 组件协作循环：一图背熟

> 背诵篇：**"四组件不是四个模块，是一个循环里的四个角色"**——一次任务的组件完整走位、四种耦合、失败模式速查。面试"画一下 Agent 运行流程"的标准答案。

## 1. 一次任务的组件走位（面试手绘图）

```text
用户目标
  │
  ▼
┌────────────────────────────────────────────────┐
│  LLM 大脑（决策）：理解目标，决定下一步            │
│   ├─→ 规划组件：目标 → 步骤列表（怎么拆）         │
│   ├─→ 记忆组件：检索历史/偏好 → 注入上下文（记得什么）│
│   └─→ 行动组件：调工具执行 → 收集观察（做什么）     │
│                                                │
│  ── 循环 ←── 反思组件：评估结果 → 继续/重试/重规划   │
│       │                                        │
│       └─→ 记忆回写：新事实/结果 → 长期记忆          │
└────────────────────────────────────────────────┘
  │
  ▼
最终答案 / 产物
```

| 阶段 | 主导组件 | 产出 | 面试要点 |
|---|---|---|---|
| 理解 | LLM 大脑 + 记忆 | 任务理解 + 相关上下文 | 记忆先于规划（上下文预算纪律） |
| 规划 | 规划组件 | 步骤列表（可执行） | 动态规划产出"下一步"而非一次性长计划 |
| 执行 | 行动/工具组件 | 观察结果（工具输出） | 结果校验 + 结构化错误回传 |
| 评估 | 反思组件 | 继续/重试/重规划决策 | 独立批评者 + 迭代上限 |
| 收尾 | LLM 大脑 + 记忆 | 最终答案 + 记忆回写 | 关键事实/失败教训落长期记忆 |

> 🎯 核心要点（背诵版）：**同一轮任务里，大脑决策 → 规划分解 → 记忆供给上下文 → 工具执行 → 反思校准 → 记忆回写，循环往复直到任务完成。** 一次"完成"的判断 = 目标达成检查（反思出口）+ 终止条件（迭代上限/成本预算）。

## 2. 四种组件耦合（面试常考）

| 耦合 | 例子 | 设计要点 |
|---|---|---|
| 大脑 ↔ 规划 | 大脑按计划逐步决策 | 计划以结构化 JSON 传递（可解析、可审计） |
| 记忆 ↔ 大脑 | 上下文注入 | 记忆管理器决定注入多少（注入多少 > 存多少） |
| 工具 ↔ 大脑 | Function Calling 声明 | **工具 schema 描述决定调用质量（schema > 模型，2026 共识）** |
| 反思 ↔ 规划 | 重规划触发 | 反思结论回写计划（re-plan 门） |

## 3. 耦合失败模式速查（面试"Agent 为什么坏"）

| 失败模式 | 根因 | 修复方向 |
|---|---|---|
| 目标漂移（goal drift） | 计划丢失/被遗忘 | 计划常驻上下文 + 每轮对照目标 |
| 上下文灌满 | 记忆注入无预算 | 注入预算 + 压缩/截断 + 记忆外置 |
| 工具乱调 | 工具描述含糊/目录太大 | schema 铁律 + <20 活动工具 |
| 反思空转 | 无 oracle / 无独立批评者 | 独立批评者 + 验证信号 + 迭代上限 |
| 循环失控 | 无终止条件 | 终止条件六件套（目标/轮次/预算/无进展/时限/人工） |
| 计划失效不修 | 无 re-plan 门 | 偏离监测 + 反思联动重规划 |
| 记忆污染 | 写入无校验 | 白盒记忆 + 时间戳 + 防投毒 |
| 错误复合放大 | 自主性无护栏 | 人工确认门 + 沙箱 + 权限最小化 |

## 4. 质量主线（面试"组件怎么调优"）

| 主线 | 问题 | 对应组件 | 2026 关键手段 |
|---|---|---|---|
| 决策质量 | 大脑想得对不对 | LLM 大脑 | 推理模型路由 + thinking 旋钮 |
| 计划质量 | 分解好不好、评估准不准 | 规划/反思 | 前瞻反思 + 重规划机制 |
| 执行质量 | 上下文全不全、工具灵不灵 | 记忆/工具/行动 | 混合检索 + schema 契约化 + 错误回传 |

## 5. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 组件怎么协作？ | 大脑决策→规划分解→记忆供给→工具执行→反思校准→记忆回写（循环） |
| 四种耦合？ | 大脑↔规划（JSON 计划）/记忆↔大脑（注入）/工具↔大脑（schema）/反思↔规划（重规划） |
| 最常见的失败模式？ | 目标漂移 / 上下文灌满 / 工具乱调 / 反思空转 / 循环失控 |
| 为什么 schema > 模型？ | 工具描述决定调用质量——模型再强也猜不出含糊的工具契约 |
| 怎么判断完成？ | 反思出口（目标达成检查）+ 终止条件（轮次/预算）双保险 |
| 调优三条主线？ | 决策质量（大脑）/计划质量（规划反思）/执行质量（记忆工具行动） |
