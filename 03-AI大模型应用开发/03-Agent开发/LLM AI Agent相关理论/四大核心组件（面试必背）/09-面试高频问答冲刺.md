# 面试高频问答冲刺

> 冲刺篇：「四大核心组件」主题面试集训——20 题 + 答题范式 + 金句弹药库。内容源自本体系 01-08 篇，按"背诵卡→机制→对比→选型"四段组织。

## 1. 答题范式（先背框架）

| 题型 | 范式 | 例子 |
|---|---|---|
| 组件定位题 | 角色一句话 → 类比 → 回答的问题 | "记忆组件？"→海马体→"我记住了什么" |
| 机制题 | 循环图 → 关键环节 → 工程点 | "工具怎么工作？"→schema→执行→回填→治理 |
| 对比题 | 分界线一句话 → 对照表 → 易混点 | "规划 vs 反思？"→怎么拆 vs 对不对 |
| 失败题 | 现象 → 根因 → 修复 | "Agent 为什么坏？"→目标漂移→计划常驻 |
| 选型题 | 任务特性逐问 → 决策 → 代价 | "要不要反思？"→oracle→成本→迭代上限 |

## 2. 二十题冲刺

### 【背诵卡组】

**Q1. Agent 的四大核心组件是什么？**
> 答：LLM 大脑（推理决策）+ 规划反思（拆解与评估）+ 记忆（跨轮信息保持）+ 工具行动（连接外部世界）——类比：大脑/参谋部/海马体/手和脚。出处 Lilian Weng（OpenAI, 2023）综述；关键：**四组件不是一个堆里的四个模块，是一个循环里的四个角色**。

**Q2. 每组件回答什么问题？**
> 答：大脑——"下一步做什么、怎么想"；规划反思——"任务怎么拆、做得对不对"；记忆——"我记住了什么、上下文是什么"；工具行动——"怎么执行、效果如何"。

**Q3. LLM 大脑在 2026 年的关键升级？**
> 答：推理模型内建思考（thinking tokens）——提高每步决策质量；但不消除循环；成本靠"按难度路由 + thinking 旋钮"控制（收益递减：no→medium 陡、high→max 平）。

### 【机制组】

**Q4. 一次任务的组件走位？**
> 答：大脑决策 → 规划分解（步骤列表）→ 记忆供给（检索注入上下文）→ 工具执行（收集观察）→ 反思评估（继续/重试/重规划）→ 记忆回写 → 循环直到目标达成 + 终止条件。

**Q5. 四种组件耦合？**
> 答：大脑↔规划（结构化 JSON 计划传递）；记忆↔大脑（注入预算——注入多少 > 存多少）；工具↔大脑（**schema 决定调用质量——schema > 模型**）；反思↔规划（重规划触发，re-plan 门）。

**Q6. 工具调用的完整机制？**
> 答：schema 声明（工具描述进上下文）→ 模型选工具给参数（结构化输出）→ Harness 执行 → 结果校验 → 观察回填 → 模型再决策。协议层：Function-Calling → 2026 MCP 标准化。

**Q7. 记忆的"写入-召回-整合"？**
> 答：写入（对话/结果/教训落库，定期压缩提升语义层）；召回（相关性 + 新鲜度指数衰减 + 重要性三因子）；整合（注入决策上下文，记忆管理器定注入量）。生产加合并与遗忘（短压长凝闭环）。

**Q8. 反思循环的结构？**
> 答：生成 → 批评（独立批评者：独立 prompt/模型/oracle）→ 改进 → 再生成；显式迭代上限；三大出口：继续/重试/重规划。

### 【对比组】

**Q9. 规划 vs 反思？**
> 答：规划管"怎么拆"（目标→步骤），反思管"对不对"（评估结果）——反思结论驱动重规划，二者联动不重叠。

**Q10. 工具 vs 行动？**
> 答：工具是"能力声明"（有什么、schema 是什么），行动是"执行与反馈"（调用、收集结果、判断成败）——合称"手和脚"。

**Q11. 记忆 vs 上下文 vs 知识库？**
> 答：上下文="这轮看什么"（窗口内容）；记忆="我记住了什么"（跨轮状态：偏好/轨迹/结论）；知识库="我能查什么"（外部静态知识，RAG 注入）。工作记忆 = 上下文窗口，但概念不同层。

**Q12. 反思 vs 重试？**
> 答：反思是结构化批评-改进（消除系统性错误，Reflexion HumanEval 91%）；重试是原样再来（错因未消除）。反思失败会退化为重试——必须有评估依据。

**Q13. 推理模型 vs 普通模型（大脑选型）？**
> 答：多步可验证任务（数学/代码/工具序列）用推理；查找/摘要/分类用快速模型——按难度路由，不全用推理（省 50-80% 输出 token 的实证）。

### 【失败与治理组】

**Q14. 工具调用最大的失败来源？**
> 答：① payload 幻觉（~38% 生产失败——模型凭记忆重建嵌套 schema）；② 多轮工具编排（BFCL V4 比单轮掉 30-60pp）。对策：schema 扁平化 + 代码抽象层（复杂工作流 token 减 9 倍）+ 结构化错误回传。

**Q15. 工具 schema 五铁律？**
> 答：枚举不自由串 / 数值加范围 / 字段名无歧义 / additionalProperties:false 收口 / 参数级描述按重要性排序；避 oneOf（弱模型选错分支）。

**Q16. 记忆为什么不能只用向量库？**
> 答：丢关系与时效——DMR 基准向量 RAG 60-70% vs 时序知识图谱 94.8%。生产标配混合检索（BM25+向量+RRF 融合 + 时间过滤）。

**Q17. 为什么写操作必须幂等？**
> 答：Agent 重试/网络失败/循环二次调用是常态——重复转账、重复建单是灾难。写操作带 idempotency key，服务端按键去重（调用两次=一次）。

**Q18. 反思组件什么时候不该开？**
> 答：无 oracle（无验证信号会空转）、低价值任务（反思每轮一次完整调用）、延迟敏感场景——先判断"值不值得反思"。

### 【选型组】

**Q19. 给我一个 Agent，怎么选组件？**
> 答：按任务特性逐问——多步可验证？（推理模型大脑 + 反思）结构可知？（Plan-Execute vs 自适应）跨会话？（长期记忆 vs 短期）外部行动？（工具 + 行动，schema 铁律）失败代价？（人工确认门 + 沙箱 + 幂等）。先单 Agent，复杂再升级。

**Q20. 2026 年组件工程最被低估/高估的？**
> 答：高估——多 Agent（协调成本被低估，先单后多）与全量 thinking（收益递减）；低估——工具工程（描述/schema/治理，38% 失败根因）与记忆治理（写入校验/遗忘/防投毒——脏记忆比无记忆危害更大）。

## 3. 金句弹药库（背 6 句）

| 金句 | 用在哪 |
|---|---|
| "四组件不是一个堆里的四个模块，是一个循环里的四个角色" | 总起 |
| "schema > 模型——工具描述决定调用质量" | 工具题 |
| "注入多少比存多少重要" | 记忆题 |
| "计划是假设——偏离必须 re-plan" | 规划题 |
| "反思失败会退化为重试——必须有评估依据" | 反思题 |
| "重试当常态设计——写操作必须幂等" | 行动题 |
| "never let a reasoning model make unvalidated state changes" | 安全题 |
| "脏记忆比无记忆危害更大" | 治理题 |

## 4. 进阶追问（加分项）

| 追问 | 加分回答 |
|---|---|
| 同一模型为什么不同 Agent 产品差异巨大？ | 差异在 Harness/Scaffolding：工具工程、记忆策略、循环设计（见 [什么是 LLM Agent 02 篇](../什么是%20LLM%20Agent%2F02-Agent公式：模型+工具+循环.md)） |
| 推理模型会让哪些组件消失？ | 部分内建（计划/自纠错/工具选择进 thinking），但执行/反馈/终止仍在循环——编排层缩小不消失 |
| 记忆系统 2026 怎么设计？ | 四层架构 + 混合检索 + 图记忆补关系时效 + 白盒可调试 + 治理闭环 |
| 工具怎么和 MCP 结合？ | 工具=能力声明，MCP=连接协议（JSON-RPC 即插即用）——注册进 MCP server，客户端统一调用 |
| 组件质量怎么度量？ | 三条主线分别度量：决策（推理路由指标）/计划（任务成功率+重规划率）/执行（三指标：JSON 校验/调用准确/工具选择） |
