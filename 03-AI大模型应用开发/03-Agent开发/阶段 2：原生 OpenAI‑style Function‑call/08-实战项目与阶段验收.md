## 1. 项目需求

**双模式查询助手**：同一入口，两种模式自动切换——对话查询（Agent 工具循环）与结构化提取（Strict 输出），全部用阶段 2 原生能力。

| 功能 | 能力 | 涉及篇目 |
|------|------|---------|
| 多城市天气对比 | 并行工具调用 + asyncio | 04 |
| 流式回答 | 流式 + 工具 + 并行全组合 | 05 |
| 订单信息提取 | strict json_schema + `.parse()` | 02/03 |
| 工具参数校验 | strict 工具 schema | 02 |
| 优雅降级 | 部分失败处理 | 04 |
| 用户取消 | 流式中断省钱 | 05 |

**验收场景示例**：

```text
> 北京、上海、广州三地天气对比一下        ← 并行 + 流式
> 帮我提取这条信息：苹果手机 3 台，单价 5999 元，今天下单
> 你好                                 ← 纯对话，不触发工具
> 查询火星天气                          ← 优雅降级
```

## 2. 架构设计：双模式 Agent

```text
main.py（入口：指令路由 → 模式选择）
  │
  ├── agent/loop.py      流式 + 并行工具循环（04/05 篇整合）
  ├── agent/extract.py   strict 提取模式（02/03 篇）
  ├── agent/tools.py     工具注册表 + strict schema（02 篇）
  └── agent/stream.py    流式渲染（05 篇）

模式路由：检测到"提取意图"关键词（提取/帮我记/结构化）→ 提取模式
         否则 → 工具循环模式
```

**模式路由的工程原则**：

```text
✅ 简单关键词启发式（规则）→ 0 成本、确定性
✅ 更高级：小模型分类（一个调用判断模式）
❌ 不要：让主 Agent 自己"顺便判断"（耦合）
```

## 3. 核心代码

```python
"""agent/extract.py — strict 提取模式（02/03 篇落地）"""
from openai import OpenAI
from pydantic import BaseModel, Field


class OrderInfo(BaseModel):
    product: str = Field(description="商品名称")
    quantity: int = Field(description="数量")
    unit_price: float = Field(description="单价（元）")
    note: str | None = Field(default=None, description="备注，可空")


def extract_order(client: OpenAI, text: str) -> OrderInfo:
    """strict + parse 提取，失败带错误重试 ≤3 次"""
    messages = [{"role": "user", "content": text}]
    for attempt in range(3):
        resp = client.beta.chat.completions.parse(
            model="gpt-4o-mini",
            messages=messages,
            response_format=OrderInfo,
        )
        msg = resp.choices[0].message
        if msg.refusal:
            raise ValueError(f"模型拒绝: {msg.refusal}")
        if msg.parsed is not None:
            return msg.parsed
        messages.append({
            "role": "user",
            "content": "（上一次输出不合 schema，请重新输出正确的结构化结果）",
        })
    raise ValueError("3 次尝试均失败")
```

```python
"""agent/loop.py — 流式 + 并行循环（04/05 篇落地，骨架）"""
import asyncio, json

async def stream_agent(client, messages, tools, model="gpt-4o-mini",
                       max_turns=10) -> str:
    """返回最终回答；过程中打印流式文本"""
    for _ in range(max_turns):
        stream = client.chat.completions.create(
            model=model, messages=messages, tools=tools,
            stream=True, parallel_tool_calls=True,
        )
        full, calls = "", {}
        for chunk in stream:
            for d in (chunk.choices or [{}]):
                delta = d.get("delta") if isinstance(d, dict) else getattr(d, "delta", None)
                if delta and getattr(delta, "content", None):
                    full += delta.content
                    print(delta.content, end="", flush=True)
                for tc in (getattr(delta, "tool_calls", None) or []):
                    e = calls.setdefault(tc.index, {"id": "", "name": "", "args": ""})
                    if tc.id: e["id"] = tc.id
                    if tc.function and tc.function.name: e["name"] = tc.function.name
                    if tc.function and tc.function.arguments:
                        e["args"] += tc.function.arguments
        if not calls:
            return full
        messages.append({"role": "assistant", "content": full or None,
                         "tool_calls": [{"id": e["id"], "type": "function",
                                         "function": {"name": e["name"],
                                                      "arguments": e["args"]}}
                                        for e in calls.values()]})
        async def run(e):
            try:
                args = json.loads(e["args"] or "{}")
                content = execute_tool(e["name"], args)
            except Exception as ex:
                content = json.dumps({"error": str(ex)}, ensure_ascii=False)
            return {"role": "tool", "tool_call_id": e["id"], "content": content}
        messages.extend(await asyncio.gather(*[run(e) for e in calls.values()]))
    return "（已达最大轮数）"
```

> ⚠️ 以上为结构示范；完整代码需补齐 tools.py（strict 工具 schema）与 main.py 路由，见扩展任务 1-3。

## 4. 六项验收标准

| # | 验收项 | 判定 |
|:---:|--------|------|
| 1 | 并行 + 流式 | "三地天气对比"触发 3 个并行工具调用，回答流式输出 |
| 2 | strict 提取 | "苹果手机 3 台 5999 元"提取出正确的 OrderInfo 结构化结果 |
| 3 | 纯对话不触发 | "你好"不调工具，正常流式回答 |
| 4 | 优雅降级 | "火星天气"→ 工具返回错误 → Agent 向用户说明，不崩溃 |

| 6 | 模式路由正确 | 提取意图与对话意图各走各的模式，无串扰 |

## 6. 常见问题

| 问题 | 根因 | 修复 |
|------|------|------|
| 提取结果结构对但值错 | strict 保证结构不保证语义 | 校验链加业务规则（价格>0 等） |
| 并行后结果错位 | 按位置而非按 id 配对 | 按 tool_call_id 配对（04 篇） |
| 流式拼装坏 JSON | arguments 覆盖而非累积 | `+=` 累积（05 篇） |
| 提取与工具循环叠加出假答案 | response_format 抑制工具调用 | 回合分离（03 篇组合矩阵） |
| 流式 + 取消没生效 | 没处理中断 | 取消即终止生成（省 token） |
| 迁移 Responses 报校验错 | 用了旧 tool 消息格式 | 改 function_call_output（07 篇） |
