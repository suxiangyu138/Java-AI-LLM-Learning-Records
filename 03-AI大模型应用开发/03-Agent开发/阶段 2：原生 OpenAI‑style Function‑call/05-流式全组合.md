## 1. 组合全景：流式的三种形态

```text
形态一：流式纯文本          —— 用户看到逐字输出（最简单）
形态二：流式 + 工具调用     —— 流中携带 tool_calls 增量（阶段 1 已学基础）
形态三：流式 + 工具 + 并行  —— 多 index 分桶 + 并发执行 + 流式回传（本章重点）
附加：流式 + 结构化输出     —— partial JSON 解析（感知延迟降 2.1×）
```

> 🎯 **核心要点**：流式不是"体验装饰"——它改变了产品形态（首字快、可打断、可进度展示）。但与工具调用叠加时，拼装正确性 > 流式体验：**先拼对，再流式**。

## 2. 形态一：流式纯文本

```python
stream = client.chat.completions.create(
    model="gpt-4o-mini", messages=messages, stream=True,
)
full = ""
for chunk in stream:
    delta = chunk.choices[0].delta
    if delta and delta.content:
        full += delta.content
        print(delta.content, end="", flush=True)
```

| 注意 | 说明 |
|------|------|
| 空 delta | 首块常为 role 信息，content 为 None——判空 |
| `choices` 为空 | 流结束时的 usage 块没有 choices——判空 |
| 拼接 | 逐 chunk `+=`，最终得到完整文本 |

## 3. 形态二：流式 + 工具调用

工具调用在流式中按 **index 分桶、增量拼装**（阶段 1 已学，此处回顾要点）：

```python
tool_calls = {}    # index → {"id","name","arguments"}，arguments 增量累积
for chunk in stream:
    for tc in (chunk.choices[0].delta.tool_calls or []):
        entry = tool_calls.setdefault(tc.index, {"id": "", "name": "", "arguments": ""})
        if tc.id:                entry["id"] = tc.id
        if tc.function and tc.function.name:
            entry["name"] = tc.function.name
        if tc.function and tc.function.arguments:
            entry["arguments"] += tc.function.arguments    # ★ 必须 +=
```

**拼装完成的终止判断**：

```python
if not tool_calls:      # 无工具调用 → 输出 full_content
    return full_content
# 有工具调用 → 组装 assistant 消息 → 执行 → 回传 → 下一轮
assistant_msg = {
    "role": "assistant",
    "content": full_content or None,
    "tool_calls": [{"id": e["id"], "type": "function",
                    "function": {"name": e["name"], "arguments": e["arguments"]}}
                   for e in tool_calls.values()],
}
```

> ⚠️ 拼装后的 assistant 消息格式必须**与服务端返回的 message 结构一致**（id/type/function 嵌套）——否则回传 400。

## 4. 形态三：流式 + 工具 + 并行

完整循环（合并 04 篇的 asyncio 并发）：

```python
import asyncio, json

async def stream_agent(messages, tools, max_turns=10):
    for turn in range(max_turns):
        stream = client.chat.completions.create(
            model="deepseek-v4-flash", messages=messages, tools=tools,
            stream=True, parallel_tool_calls=True,
        )
        full_content, tool_calls = "", {}
        for chunk in stream:
            choices = chunk.choices or []
            if not choices:
                continue
            delta = choices[0].delta
            if delta.content:
                full_content += delta.content
            for tc in (delta.tool_calls or []):
                entry = tool_calls.setdefault(tc.index, {"id": "", "name": "", "arguments": ""})
                if tc.id:                entry["id"] = tc.id
                if tc.function and tc.function.name:
                    entry["name"] = tc.function.name
                if tc.function and tc.function.arguments:
                    entry["arguments"] += tc.function.arguments

        if not tool_calls:
            return full_content

        messages.append({
            "role": "assistant",
            "content": full_content or None,
            "tool_calls": [{"id": e["id"], "type": "function",
                            "function": {"name": e["name"], "arguments": e["arguments"]}}
                           for e in tool_calls.values()],
        })

        # 并发执行（04 篇 run_parallel_tools）
        async def exec_one(e):
            try:
                args = json.loads(e["arguments"] or "{}")
                return {"tool_call_id": e["id"],
                        "content": execute_tool(e["name"], args)}
            except Exception as ex:
                return {"tool_call_id": e["id"],
                        "content": json.dumps({"error": str(ex)}, ensure_ascii=False)}

        results = await asyncio.gather(*[exec_one(e) for e in tool_calls.values()])
        messages.extend([{"role": "tool", **r} for r in results])
    return "（已达最大轮数）"
```

## 5. partial JSON：流式中解析结构化输出

**痛点**：流式输出 JSON 时，中途每个片段都不是合法 JSON——传统做法等完整输出。**partial JSON 解析**让结构随流成型（实测感知延迟降 **2.1×**）：

| 库 | 语言 | 说明 |
|----|------|------|
| `jiter` | Python | Instructor 配套的增量 JSON 解析 |
| `partial-json` | TypeScript | JS 生态标准 |
| OpenAI SDK 内部 | —— | `.parse()` 的流式版（`parsed` 逐块更新） |

```python
# 概念演示：增量解析器逐块喂入，随时取"当前合法部分"
from jiter import from_json  # 或 instructor.partial_json_parser

accumulator = ""
for chunk in stream:
    delta = chunk.choices[0].delta
    if delta and delta.content:
        accumulator += delta.content
        try:
            partial = from_json(accumulator)      # 解析"到目前为止合法的部分"
            render_partial(partial)                # 前端逐步渲染
        except Exception:
            pass                                   # 未闭合属正常，继续累积
```

> ⚠️ **partial JSON 的边界**：中途解析只是"尽力而为"——**最终完整 JSON 仍要整体校验一次**。增量解析只用于渲染，不用于决策。

## 6. 终轮结构化收尾

流式 + 工具循环 + 最终结构化输出的组合（黄金法则：**循环轮自由，终轮结构化**）：

```python
# 循环内：自由输出（流式）
# 循环结束（无工具调用）后：若需要结构化，发一轮收尾请求
final = client.beta.chat.completions.parse(
    model="gpt-4o-mini",
    messages=messages + [{"role": "assistant", "content": "请将上述回答整理为 JSON"}],
    response_format=SummaryReport,          # Pydantic 模型
)
summary = final.choices[0].message.parsed
```

| 场景 | 是否终轮结构化 |
|------|:---:|
| 面向用户展示 | 否（流式文本更友好） |
| 下游系统消费 | 是（保证结构） |
| 两端都要 | 流式展示 + 终轮结构化并存（成本 +1 轮） |

## 7. 体验优化与指标

| 指标 | 目标 | 手段 |
|------|------|------|
| 首 token 延迟（TTFT） | <1s | 流式 + 预热 schema |
| 完整输出延迟 | 逐 token 可见 | 流式本身 |
| 结构化感知延迟 | -2.1× | partial JSON |
| 工具轮次透明 | 用户可见"正在查询…" | 流式工具事件提示 |

**流式 × 成本的取舍**：流式不改变总 token 数（成本不变）；但中途打断可省——**用户取消时停止生成 = 真实省钱**。

> 🎯 **核心要点**：流式全组合的工程清单——**按 index 分桶、arguments 增量拼装、assistant 消息结构一致、并发执行按 id 配对、partial JSON 只渲染不决策、终轮结构化收尾**。六步全对，就是生产级流式 Agent。
