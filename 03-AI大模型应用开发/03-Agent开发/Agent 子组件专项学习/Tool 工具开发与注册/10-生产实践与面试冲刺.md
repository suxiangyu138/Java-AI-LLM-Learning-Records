# 生产实践与面试冲刺

> 收官篇：把 01-09 的规范收敛成**可执行的落地清单**。2026 生产基线：契约优先、<20 工具、动态发现兜底、四层安全、多重预算、失败记忆——缺一项就上线，事故只是时间问题。

## 1. 生产落地清单（上线前逐项打勾）

### 1.1 契约层

| 检查项 | 标准 |
|---|---|
| 工具命名 | 动词开头、动作-对象、域前缀、无 do_xxx 泛名 |
| 描述质量 | 3-4 句 + 示例 + 边界（何时不用）；描述自测三连通过 |
| 描述去重 | 注册表冲突检测开启，无重叠描述 |
| schema | 扁平、全参数描述、枚举/边界、additionalProperties:false |
| 参数数量 | 最小化（≤5 个/工具为佳） |
| strict | 生产工具开启（可选参数改写为 required+null） |
| token 预算 | 单工具 100-200 token；工具总数 <20 |

### 1.2 注册与发现层

| 检查项 | 标准 |
|---|---|
| 注册表 | name → 定义+执行器+元数据；lookup O(1) |
| 冲突检测 | 重名/描述重叠/schema 冲突注册期 fail-fast |
| 过滤 | 权限/域/风险过滤在注册层完成 |
| 动态发现 | 工具 >20 启用 namespace/tool_search 或 Provider |
| 数量治理 | 单上下文 10-15；>30 拆子 Agent |

### 1.3 执行层

| 检查项 | 标准 |
|---|---|
| 调用循环 | 五步：解析→校验→授权→执行→回传 |
| 循环不变量 | 每调用恰一结果；消息顺序正确 |
| 结构化错误 | 错误码+信息+hint 回传；坏调用不中断整轮 |
| 重试策略 | 只重试基础设施故障；指数退避 |
| 预算 | max_iterations 15-25、wall-clock、成本、结果字符全设 |
| 并行 | 仅独立只读并行；危险工具串行+逐次确认 |

### 1.4 反馈层

| 检查项 | 标准 |
|---|---|
| 结果截断 | 旧消息优先 + 阈值 + 头尾保留 |
| 失败记忆 | 失败签名记录 + 约束播种（blame 分类） |
| 上下文管理 | turn-atomic pruning；配对守卫；估算器偏高 |
| 结果清理 | 已消费结果清理/摘要；事实钉扎 |

### 1.5 安全层

| 检查项 | 标准 |
|---|---|
| 注册期校验 | 描述来源/Unicode lint/schema 合法性/哈希 |
| 授权 | 最小权限、角色过滤、每调用独立授权 |
| 确认模式 | L3+ 强制人工确认（不可关闭） |
| 参数安全 | 参数化执行，零字符串拼接 SQL/Shell |
| 结果脱敏 | 结果注入前脱敏、隐藏字段剥离 |
| 行为检测 | 调用风暴/跨域异常/序列异常告警 |
| 审计 | 全量留痕 + 确认流记录 + 事件预案 |

### 1.6 可观测层

| 检查项 | 标准 |
|---|---|
| 调用 span | OTel tool_call：name/call_id/arguments/result |
| 指标 | 校验通过率、重试率（<5%）、选择准确率、成本 |
| 门禁 | CI 跑工具契约测试（LLM 模拟调用回归） |

## 2. 十二大避坑（按事故概率排序）

| # | 坑 | 后果 | 解法 |
|---|---|---|---|
| 1 | 描述模糊（"处理数据"） | 选错工具/该调不调 | 示例+边界+3-4 句（03 篇） |
| 2 | 工具无限堆积不治理 | 上下文膨胀、准确率崩 | <20 红线 + namespace + 定期下线（05 篇） |
| 3 | 模型输出直接执行 | 注入/越权 | 校验-授权-执行三关（06 篇） |
| 4 | 错误抛异常进循环 | 循环崩溃/卡死 | 结构化 observation 回传（06 篇） |
| 5 | 无限循环无预算 | 成本爆炸/失控操作 | max_iterations + early stopping（06 篇） |
| 6 | 截最新结果保上下文 | 模型误判工具失败、重复调用 | 旧消息优先头尾保留（07 篇） |
| 7 | 压缩拆散 tool-call/result | API 拒收 | turn-atomic pruning（07 篇） |
| 8 | 不记失败、模型重复踩坑 | 重试风暴/死循环 | 失败签名 + blame 分类（07 篇） |
| 9 | 确认模式可关闭 | 注入直通危险操作（CVE-2025-53773） | L3+ 强制确认（08 篇） |
| 10 | 工具内部字符串拼接 | SQL/命令注入 | 参数化执行（08 篇） |
| 11 | 结果不脱敏直接回注 | 结果注入扩散 | 脱敏+隐藏字段剥离+敏感工具只回结论（08 篇） |
| 12 | 只测单元测试 | 契约缺陷上线才发现 | LLM 模拟调用测试 + CI 门禁（10 篇） |

> 🎯 核心要点：12 坑的根因只有三个——**契约差（1-2）、执行弱（3-5、9-10）、反馈乱（6-8、11）**。按 03/06/07/08 篇的规范做，12 坑自动消失。

## 3. 指标体系：工具质量怎么度量

| 指标 | 计算 | 目标 |
|---|---|---|
| 选择准确率 | 正确调用数/调用数 | >90%（可按工具分桶看） |
| 参数通过率 | 首调通过校验比例 | >95% |
| 重试率 | 重试调用数/调用总数 | <5% |
| 结果消费率 | 引用结果轮次占比 | 高 |
| 加载-调用比 | 声明工具中被调用比例 | 高（低 = 声明冗余） |
| 定义成本占比 | 工具定义 token/总 token | <10% |
| 授权拒绝率 | 拒绝/请求 | 跟踪（突增 = 越权试探） |
| 净成功率 | 任务完成率（含工具环节） | 按任务类型基线 |

> 💡 最容易被忽视的两个：**加载-调用比**（声明了 50 个只用 5 个 = 发现层没生效）和**授权拒绝率**（突增可能是注入试探，也可能是权限模型太紧——都要查）。

## 4. 面试题（14 题 + 答题范式）

### 4.1 基础（必答）

**Q1：工具、函数调用、MCP 三者的关系？**
> 工具是概念（模型请求、宿主执行的外部能力封装）；函数调用是协议层（怎么声明、怎么回传）；MCP 是分发层（一次定义多宿主）。工具定义三要素：name + description + JSON Schema。

**Q2：模型看得见工具的什么？为什么描述重要？**
> 只有 name、description、schema——永远看不见实现。描述决定"该不该调、调哪个"；描述含示例可提升约 25% 选择准确率；模糊描述 = 选错工具。

**Q3：工具注册表要设计哪些内容？**
> name → 定义 + 执行器 + 元数据（权限/风险/版本/tag）；注册期冲突检测（重名/描述重叠/schema）；过滤与治理（权限/域/下线流程）；静态校验（防 tool poisoning）。

### 4.2 进阶（加分）

**Q4：工具数量多了怎么办？**
> 三件套：静态过滤（权限/域）→ namespace 化/tool_search 动态发现 → >30 拆子 Agent。单上下文 10-15 个是准确率边界。

**Q5：tool_search 是什么？hosted 和 client 模式区别？**
> OpenAI Responses API 运行时工具发现：defer_loading + 模型先搜后调。hosted = 服务端在声明范围内搜；client = 应用按状态搜（租户/权限在应用侧）。

**Q6：调用循环的不变量？**
> 每调用恰一结果；tool_calls 消息先于结果追加；结果引用已有 call_id；坏调用单独标记不 abort 整轮；错误转结构化 observation。

**Q7：什么时候并行执行工具？**
> 独立且只读可以并行（白拿吞吐）；有数据依赖必须串行；危险工具绝不批量并行（逐次确认）。

**Q8：截断工具结果的正确姿势？**
> 旧消息优先 + 阈值触发 + 头尾保留（约 67% token 减少）。绝不能先截最新结果——那是当前决策最相关的输入，截了模型会误判工具失败。

**Q9：重复失败怎么治理？**
> 失败签名提取 + 约束播种（checkProposal 拦截/recordOutcome 登记/isDone 收敛）；blame 分类：Agent 故障约束、基础设施故障只记录——防止搜索空间被毒化。

### 4.3 安全与架构（拉开差距）

**Q10：tool poisoning 是什么？为什么 2026 是头号威胁？**
> 恶意工具定义/描述劫持模型选择的攻击。威胁建模 DREAD 9.0/10 排名第一；6/7 主流客户端对工具元数据不做静态校验；自适应攻击下提示词级防御缓解 <50%——必须架构化防御。

**Q11：五道安全防线？**
> 注册期静态校验（防进来）→ 执行前授权+确认模式（防乱来）→ 行为异常检测（防失控）→ 结果脱敏回注（防扩散）→ 审计响应（可追责）。危险级工具确认模式不可关闭（CVE-2025-53773 教训）。

**Q12：工具内部怎么防注入？**
> 参数化执行（参数绑定/预编译），绝不字符串拼接 SQL/Shell/路径；工具参数是模型提供的不可信数据，与外部用户输入同等对待。

**Q13：Spring AI 和 LangChain4j 工具机制差异？**
> 注解都是 @Tool+参数注解；Spring AI 靠 Bean 自动扫描 + ToolCallbacks.from()；LangChain4j 靠 AiServices.builder().tools() + DynamicToolProvider；LangGraph4j 双框架集成且可 internalToolExecutionEnabled(false) 接管执行。

**Q14：一个工具从开发到下线全流程？**
> 开发（函数+描述+schema）→ 注册（冲突检测+静态校验）→ 声明（按需注入）→ 执行（校验/授权/执行/回传）→ 治理（指标+审计）→ 下线（禁用→观察→删定义）。

### 4.4 答题范式

| 原则 | 说明 |
|---|---|
| 结构优先 | 概念 → 机制 → 权衡 → 落地（四段式） |

## 6. 面试速记（终极压缩）

1. **契约优先**：模型只见 name/description/schema——描述含示例 +25%，参数最小化，<20 工具。
2. **注册-发现-声明解耦**：注册全量保存、发现按需检索（tool_search/namespace）、声明只给能用的。
3. **执行三关**：校验→授权→执行；模型输出不可信；结构化错误回传；多重预算防失控。
4. **反馈有序**：旧消息优先截断、turn-atomic 剪除、失败签名记忆（blame 分类）。
5. **安全架构化**：tool poisoning DREAD 9.0/10；五道防线；确认模式不可关；参数化执行。
