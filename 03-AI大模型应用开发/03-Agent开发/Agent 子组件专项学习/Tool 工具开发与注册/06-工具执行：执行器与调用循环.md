# 工具执行：执行器与调用循环

> 执行 = 宿主把模型的结构化请求变成真实动作。2026 工程共识：**执行器是安全边界、循环不变量是正确性底线、预算是防失控护栏**。模型永远不直接执行——它发出请求，执行器校验、授权、执行、回传。本章给出一套可直接落地的调用循环规范。

## 1. 执行器的职责

| 职责 | 具体动作 |
|---|---|
| 解析 | arguments JSON 解析（OpenAI 字符串形态） |
| 校验 | 参数形状/枚举/类型（strict 之外的语义校验） |
| 授权 | 权限检查、确认模式判断（08 篇） |
| 执行 | 调用真实函数，带超时与预算 |
| 回传 | 结果转字符串 observation 返回模型（模型处理文本，不处理对象） |
| 审计 | 记录调用参数、结果、耗时 |

> 🎯 核心要点：执行器的第一原则——**模型输出是不可信输入**。把它当外部用户输入处理：校验、授权、限流、审计一个不能少（08 篇安全展开）。

## 2. 五步调用循环

```text
1. 解析工具调用（tool_call 数组）
2. 校验每个调用（JSON 解析 + schema 校验）
3. 逐调用授权（权限/确认模式）
4. 执行（并行或串行，带超时）
5. 回传结果 → 追加消息 → 回到模型
```

| 步骤 | 关键决策 | 反例 |
|---|---|---|
| 解析 | 坏 JSON 单独标记，不中断整轮 | 一个坏参数 abort 全部调用 |
| 校验 | 结构校验先行，业务校验后置 | 跳过校验直接执行 |
| 授权 | 每调用独立决策 | 批量授权（权限放大） |
| 执行 | 并行白拿吞吐；有依赖则串行 | 无脑并行（依赖断裂） |
| 回传 | 每个调用恰好一个结果 | 丢失/重复结果（API 拒收） |

> ⚠️ 循环不变量（2026 共识）：① 每个 tool_call 恰好一个结果；② 含 tool_calls 的 assistant 消息必须**先于**结果追加（顺序颠倒 → API 验证错误）；③ 结果必须引用已存在的 tool_call_id。

## 3. 并行执行：什么时候并行

| 场景 | 策略 |
|---|---|
| 独立只读调用 | ✅ 并行（asyncio.gather / 并发执行器）——白拿吞吐 |
| 有数据依赖 | ❌ 串行或协议层关并行（parallel_tool_calls=false） |
| 危险工具 | 永远不并行批量授权——逐调用确认 |
| 顺序敏感（先读后写） | 串行 |
| 数量控制 | max_parallel_tool_calls 设上限 |

> 💡 并行是优化不是默认：**默认串行更可控**，确认瓶颈后按"独立且只读"判定并行。LangChain4j `.executeToolsConcurrently()` 一行开启（09 篇）。

## 4. 超时与重试：失败的分类学

| 失败类型 | 例子 | 是否重试 | 回传内容 |
|---|---|---|---|
| 参数错误 | schema 不符、缺字段 | ❌（重试同样错） | invalid_arguments + 期望格式 |
| 工具不存在 | unknown_tool | ❌ | 工具列表提示 |
| 业务失败 | 余额不足、无权限 | ❌ | 业务错误信息 |
| 基础设施故障 | 超时、限流、网络 | ✅ 指数退避 | 可重试错误 |
| 权限拒绝 | 授权失败 | ❌（转人工） | 拒绝原因 |

> 🎯 核心要点：**重试只针对安全失败**（基础设施故障）——重试参数错误是浪费、重试业务失败是放大。重试率 >5% 时优先修契约或模型，而不是堆重试（07 篇重复失败检测）。

## 5. 结构化错误返回：失败也是反馈

```jsonc
// 错误结果也是工具结果（observation），让模型自我纠正
{ "status": "error", "code": "invalid_arguments",
  "message": "参数 labels 必须是枚举值之一：bug/feature/docs，收到 'urgent'",
  "hint": "检查 labels 取值后重试；其他参数保持原样" }
```

| 规范 | 说明 |
|---|---|
| 永远返回、不抛异常 | 抛异常进循环 = 循环崩溃；返回字符串 = 模型可恢复 |
| 错误码 + 信息 + 提示 | 模型按"提示"修，比按"报错"修准 |
| 坏调用不 abort 整轮 | 标记失败、跳过、补错误结果——其余正常执行 |
| 拒绝/取消/超时都成 observation | 模型需要知道"发生了什么"才能决定下一步 |
| 结果字符串化 | 模型处理文本——返回 JSON 字符串而非对象 |

## 6. 预算：防失控的多重护栏

| 预算项 | 典型值 | 作用 |
|---|---|---|
| max_iterations | 15-25 步 | 最重要护栏——防无限循环 |
| max_tool_calls | 单轮调用数上限 | 防调用风暴 |
| max_parallel_tool_calls | 并发上限 | 防资源耗尽 |
| max_wall_time_seconds | ~300s | 防慢工具/挂起 |
| max_tool_result_chars | 单结果截断上限 | 防上下文爆掉（07 篇） |
| max_total_cost | $2/run 类 | 防成本失控 |
| max_retries | 单调用重试上限 | 防重试风暴 |

```text
early stopping 模式（迭代上限触发时）：
  追加消息："已达到最大步数。基于已完成的工作给出最佳答案。"
  → 最后一次无工具调用，让模型综合收尾
  → 结构化终止：{status:"stopped", reason:"step_limit_reached",
                 completed:false, next_safe_action:"询问用户是否扩大预算"}
```

> ⚠️ 2026 教训（真实事故）：Copilot 一次创建 1526 个 git worktree（创建失败无记忆）、$8 成本重复读同一文件 1000 次、压缩循环抹掉失败证据——**所有事故都可被"预算 + 重复失败检测"拦下**（07 篇）。

## 7. 执行器的可观测性

| 观测点 | 指标 |
|---|---|
| 调用跨度 | OTel GenAI `tool_call` span：tool name、call id、arguments、result |
| 质量指标 | 校验通过率、重试率、失败模式分布 |
| 治理指标 | 每工具调用量、token 成本、延迟 |
| 安全指标 | 授权拒绝率、危险工具调用次数、确认模式触发率 |
| SLO | 重试率 <5%；校验通过率趋势不下降 |

> 💡 2026 标准：**校验通过率进门禁**——CI 上跑工具契约测试（LLM 模拟调用），回归就失败。工具要"用 LLM 测试"，不只是单元测试（10 篇）。

## 8. 常见误区

| 误区 | 真相 |
|---|---|
| "模型调用直接执行" | 必须走 校验→授权→执行 三关，模型输出不可信 |
| "错误就抛异常" | 抛异常 = 循环崩溃；返回结构化 observation = 模型自我纠正 |
| "重试解决一切" | 只重试基础设施故障；重试率 >5% 是契约问题 |
| "并行永远更快" | 有依赖的并行 = 错误；危险工具绝不批量并行 |
| "循环不会失控" | 必须多重预算：步数/时间/成本/字符，缺一不可 |
| "结果返回对象就行" | 模型处理文本——结果必须字符串化 |
| "授权一次通过全局有效" | 每调用独立授权，危险操作逐次确认 |

## 9. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 执行器五步？ | 解析 → 校验 → 授权 → 执行 → 回传 |
| 循环不变量？ | 每调用恰一结果；tool_calls 消息先追加；结果引用已有 call_id |
| 什么时候并行？ | 独立且只读；有依赖串行；危险工具不批量并行 |
| 重试规则？ | 只重试基础设施故障；参数/业务失败不重试 |
| 结构化错误怎么做？ | 返回 status+code+message+hint，模型按提示修 |
| 为什么坏调用不中断整轮？ | 标记跳过+补错误结果，其余正常执行 |
| 最重要护栏？ | max_iterations（15-25）——防无限循环 |
| early stopping？ | 到上限时无工具再调一次，让模型综合收尾 |
| 预算有哪些？ | 步数/调用数/并发/墙钟/结果字符/成本/重试 |
| 执行器第一原则？ | 模型输出不可信——当外部用户输入处理 |
| 结果为什么字符串化？ | 模型处理文本不处理对象 |
| 观测什么？ | tool_call span、校验通过率、重试率（<5% SLO） |
