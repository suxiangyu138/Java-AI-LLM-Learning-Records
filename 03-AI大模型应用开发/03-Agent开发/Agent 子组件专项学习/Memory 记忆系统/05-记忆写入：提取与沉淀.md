# 记忆写入：提取与沉淀

> 写入是记忆系统的入口：对话里 90% 是噪音，1% 是值得记住的事实。2026 年范式转变：**单遍 ADD-only 提取**取代两遍对账式——只做加法，不删不改，快一半且不毁原事实。

## 1. 写入的两个问题

| 问题 | 说明 |
|---|---|
| 提取什么 | 从对话中提炼值得长期记住的事实 |
| 什么时候写 | 触发时机与写入频率 |

> 🎯 核心要点：写入的目标不是"记住全部"，是**"以最少的事实覆盖最多未来需求"**——每一条记忆都应该通过"以后还用得上吗"的检验。

## 2. 单遍 ADD-only 提取（2026 范式）

| 维度 | 旧：两遍对账式 | 新：单遍 ADD-only |
|---|---|---|
| 流程 | ①候选提取 ②与旧记忆比对→增改删 | 一次 LLM 调用只做新增 |
| 延迟 | 慢（两次调用） | **减半** |
| 原事实 | 覆盖/删除会毁信息 | 新旧并存，都能追溯 |
| 模型精力 | 花在 diff 上 | 全花在理解输入上 |
| 演进能力 | 只看到"最终态" | 能看到"怎么演变的" |

```python
# 单遍 ADD-only 提取骨架
EXTRACT_PROMPT = """从对话中提取值得长期记住的事实。
规则：
1. 只提取用户表达的事实/偏好/决定（如"我住在上海""我喜欢简洁回答"）
2. 一句一个事实，不合并、不推断
3. 不确定的标记低置信度
4. 不要修改已有记忆（系统会处理）

对话：
{conversation}
输出 JSON：{{"facts": [{{"text", "entity", "confidence"}}]}}"""

def extract_facts(conversation: str) -> list[dict]:
    result = llm.generate(EXTRACT_PROMPT.format(conversation=conversation))
    return validate_and_store(result.facts)   # 只 ADD，不比对
```

> 💡 关键洞察：**两遍对账的"删除"是有害的**——"用户说喜欢 A，后来改口 B"时，A 与 B 并存才有完整时序（07 篇处理矛盾），对账删除会丢掉"曾经喜欢 A"这个信息。

## 3. Agent 生成的事实是一等公民

| 事实来源 | 旧处理 | 新处理 |
|---|---|---|
| 用户陈述 | ✅ 提取 | ✅ 提取 |
| Agent 承诺/动作 | ❌ 忽略（"已订好 3 月 3 日航班"丢了） | ✅ 同等权重入库 |

| Agent 事实的价值 | 例子 |
|---|---|
| 承诺追踪 | "我会明天发报告" → 后续会话可追问 |
| 状态延续 | "已取消订单 1023" → 用户问起能答 |
| 跨任务协同 | 多 Agent 共享动作事实 |

> ⚠️ Agent 事实也意味着 Agent 的错误陈述会入记忆——**提取时标注来源角色（user/agent）**，Agent 来源的事实置信度降低或需验证。

## 4. 提取质量：三个维度

| 维度 | 问题 | 治理 |
|---|---|---|
| 完整性 | 该记的没记 | 提取提示词覆盖事实类型 |
| 准确性 | 记错了 | 低置信度标记 + 人工抽检 |
| 噪音率 | 记了一堆废话 | 提取规则（只记事实/偏好/决定） |

```text
提取质量测试集（自建）：
  30-50 段对话（含：偏好/事实/决定/承诺/闲聊）
  → 人工标注"应提取事实" → 对比系统提取
  → 指标：召回率（该记的记到没）+ 精确率（记的都是该记的吗）
```

| 高频提取错误 | 表现 |
|---|---|
| 过度提取 | 把闲聊/临时状态记成事实 |
| 时间敏感事实 | "用户这周忙"当成永久偏好 |
| 推断过度 | "他喜欢 Python"从一次聊天推断 |
| 实体错位 | 事实归错用户/实体 |

## 5. 写入触发时机

| 触发 | 做法 | 频率 |
|---|---|---|
| 对话结束 | 整段提取 | 低 |
| 每 N 轮 | 增量提取 | 中 |
| 事件后 | 任务完成/状态变化后立即提取 | 按事件 |
| 实时流式 | 每轮边聊边提 | 高（成本高） |

> 💡 工程折中：**增量提取（每 3-5 轮）+ 会话结束全量提取**是 2026 主流——实时提取成本高且重复，事后全量又延迟大。

## 6. 实体链接：给记忆装"关系网"

| 步骤 | 做法 | 价值 |
|---|---|---|
| 实体抽取 | 从事实中识别实体（人/物/地点/组织） | 召回锚点 |
| 实体嵌入 | 实体向量化 | 跨记忆语义关联 |
| 链接 | 同实体多事实关联 | 图谱遍历 |

```text
实体链接的召回收益：
  "用户喜欢 Python"（事实 A）+ "用户在用 LangChain"（事实 B）
  → 实体 user:42 关联 → 问"用户会什么技术"时 A、B 同时召回
```

## 7. 写入监控指标

| 指标 | 信号 |
|---|---|
| 提取召回率/精确率 | 下降 → 提示词/模型退化 |
| 每会话写入量 | 过高 → 提取过度 |
| 写入→召回命中率 | 低 → 写入与召回脱节 |
| 事实冲突率 | 高 → 提取粒度/时序问题（07 篇） |
| 提取延迟 | 高 → 批量/异步化 |

## 8. 提取提示词模板详解（可直接落地）

| 要素 | 模板写法 | 作用 |
|---|---|---|
| 事实类型定义 | "偏好/事实/决定/承诺，非闲聊" | 过滤噪音 |
| 一句一事实 | "每条输出只含一个事实" | 粒度可控 |
| 实体标注 | "标注事实归属实体（人/物/组织）" | 实体链接输入 |
| 来源角色 | "标注是用户说的还是 Agent 做的" | Agent 事实降权 |
| 置信度 | "不确定的标 confidence<0.7" | 状态机输入 |
| 时间敏感提示 | "临时状态（本周忙）标 valid_until" | 防永久化 |
| 禁止对账 | "不要修改已有记忆" | ADD-only 纪律 |

```text
输出 JSON 契约：
{"facts": [{"text": "...", "entity": "user:42", "source": "user|agent",
            "confidence": 0.9, "valid_until": null}]}
```

## 9. 写入管道完整示例（异步化）

```python
async def memory_write_pipeline(conversation: list, user_id: str):
    # ① 增量触发判断（每 3-5 轮）
    if len(conversation) % 4 != 0:
        return
    # ② 异步提取（不阻塞对话）
    facts = await asyncio.to_thread(extract_facts, conversation[-8:])
    # ③ 脱敏 → 冲突检测 → 事务入库（05/07/08 篇组合）
    for fact in facts:
        sanitized = sanitize_claim(fact.text)
        ingest_claim(user_id, sanitized, fact)
    # ④ 指标上报
    metrics.extracted(len(facts), facts_quality(facts))
```

## 10. 写入常见坑速查

| 坑 | 现象 | 解法 |
|---|---|---|
| 全量实时提取 | 每轮都调 LLM 提取 | 增量（3-5 轮）+ 会话末全量 |
| 提取无 schema | 输出乱 | JSON 契约强制 |
| 噪音入库 | 闲聊变记忆 | 事实类型白名单 |
| 时间敏感永久化 | "本周忙"成永久偏好 | valid_until 标注 |
| 不脱敏 | PII 入库 | 写入路径脱敏（08 篇） |
| 同步阻塞 | 对话卡顿 | 异步提取 |
| 无质量测试集 | 退化不可知 | 提取测试集回归 |

## 11. 提取与反思组件的协作

| 协作点 | 说明 |
|---|---|
| 反思结论入记忆 | 失败教训（"先 describe 再查询"）由反思组件产出 → 提取入记忆 |
| 提取质量反馈 | 召回命中率低的提取 → 反思提取策略（换提示词/模型） |
| 冲突回执 | 提取到与已有记忆矛盾的事实 → 触发冲突处理（07 篇） |
| 提取评估器 | 用独立模型抽查提取质量（"这条事实值得记吗"） |

```text
闭环价值：提取不是单向管道——
  "提取 → 召回 → 反馈（命中率/冲突率）→ 调提取" 
  让提取质量持续进化（呼应反思组件的 oracle 思想）
```

> 💡 提取与反思的边界：**提取负责"沉淀新事实"，反思负责"校准旧经验"**——两者都写记忆，但写入触发不同（提取=对话内容，反思=任务结果），别混成一步。

## 12. 提取成本核算

| 项 | 估算 | 说明 |
|---|---|---|
| 单次提取 | 1 次 LLM 调用（输入 8-16 轮对话） | 增量提取 |
| 提取 token | 输入（对话）× 1 + 输出（事实） | 可控 |
| 频率 | 每 3-5 轮 1 次 + 会话末 1 次 | 每会话约 3-5 次 |
| 每会话成本 | 3-5 × 单次成本 | 占总成本 5-15% |

```text
成本优化顺序：
  ① 异步化（不阻塞对话，延迟成本归零）
  ② 增量提取（减调用次数）
  ③ 短对话不提取（<3 轮跳过）
  ④ 模型降档（提取用便宜模型——提取是模式化任务）
```

> 💡 提取用便宜模型是 2026 通行做法：提取是"模式化任务"（事实识别），中档模型即可——把前沿模型留给决策与理解。提取模型与决策模型分离还有一个好处：**换决策模型不影响已沉淀的记忆格式**（提取契约稳定），记忆成为跨模型资产。同理，提取提示词的版本要纳入契约管理——提示词变更会改变提取行为，需要回归测试。

> 🎯 核心要点：写入的三大纪律——**只做加法（ADD-only，不毁原事实）、只记事实（不记闲聊）、只记值得的（通过"以后还用吗"检验）**。提取是记忆系统质量的上游：提取错了，后面召回与维护全错。
