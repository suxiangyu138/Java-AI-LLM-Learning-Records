# 记忆召回：检索与注入

> 召回是记忆系统的主战场——"存储≠记忆"（2026 共识）：存得再好，取不出来等于没有。本章讲透三信号融合检索、注入装配与信噪控制。

## 1. 召回的两个环节

```text
检索（Retrieval）：从记忆库找出候选
  → 注入（Injection）：把候选装配进上下文（受预算约束）
```

| 环节 | 目标 | 失败表现 |
|---|---|---|
| 检索 | 召回相关候选（可以多） | 该记的找不到 |
| 注入 | 装配"最小有用包"（必须精） | 噪声淹没信号 |

> 🎯 核心要点：**检索可以放宽（召回率优先），注入必须收紧（精确率优先）**——两环节目标不同，别用一个参数管到底。

## 2. 三信号融合检索

| 信号 | 原理 | 覆盖 |
|---|---|---|
| 语义 | 向量相似度 | 同义改写 |
| 关键词 | BM25/词频 | 精确词、专有名词 |
| 实体 | 实体链接匹配 | 同名实体多事实 |

```text
检索流程：
  问题 → 三路并行（向量 TopK / BM25 TopK / 实体命中）
    → 合并去重 → RRF 融合排序 → 按预算截断 TopN
```

```python
def recall(query: str, budget=10) -> list[dict]:
    semantic = vector_topk(query, k=20)          # 语义
    keyword  = bm25_topk(query, k=20)            # 关键词
    entities = entity_lookup(query, k=10)        # 实体
    fused = rrf_merge(semantic, keyword, entities)  # RRF 融合
    return fused[:budget]                        # 预算截断
```

| 融合方法 | 特点 |
|---|---|
| RRF（互惠排名融合） | 无参、稳健、默认推荐 |
| 加权求和 | 可调权重但易过拟合 |
| 重排模型 | 准但贵（高价值场景） |

## 3. 注入装配：记忆管理器

```text
装配优先级（注入预算内）：
  ① 当前问题直接相关（检索命中）
  ② 活跃决策/未完成任务
  ③ 用户核心偏好
  ④ 近期事件（时效加权）
  ⑤ 滚动摘要（兜底）
```

| 注入参数 | 默认建议 |
|---|---|
| 注入预算 | 上下文的 10-15% |
| 单条长度 | ≤1-2 行（事实级） |
| 格式 | 结构化列表（带来源标签） |
| 排序 | 相关度优先 |

```python
def inject_memories(context: list, query: str, budget_tokens=3000):
    memories = recall(query)
    pack = []
    for m in memories[:budget_tokens // avg_token(m)]:
        pack.append(f"[记忆] {m.claim}（来源：{m.evidence[:40]}）")
    return context + pack      # 注入位置：上下文尾部（缓存友好）
```

> 💡 注入格式要点：**给每条记忆带来源/时间标签**——模型能区分"记忆 vs 当前对话"，减少把记忆当指令的风险（08 篇）。

## 4. 信噪控制：召回质量的生死线

| 噪声来源 | 治理 |
|---|---|
| 相似但无关 | 语义阈值（低于阈值不注入） |
| 过期事实 | state=DEPRECATED 过滤（07 篇） |
| 重复事实 | 去重（同实体同 claim） |
| 实体混淆 | 实体链接校验 |
| 跨用户记忆 | agent_id 隔离（08 篇） |

| 信噪指标 | 目标 |
|---|---|
| 注入噪声率 | <20%（抽查） |
| 召回命中率 | ≥90%（自建测试集） |
| 注入 token/轮 | 稳定在预算内 |

## 5. 召回时机：什么时候查记忆

| 时机 | 做法 | 成本 |
|---|---|---|
| 每轮必查 | 每轮注入相关记忆 | 高（默认不用） |
| 问题前查 | 用户消息到达时检索 | 中（主流） |
| 工具结果后查 | 结合上下文再查 | 中 |
| 按需查 | 模型判断需要时（记忆工具） | 低（Letta 模式） |

> 💡 两种模式对比：**自动注入（每轮检索）** 体验稳但费 token；**按需调用（模型自己调记忆工具）** 省 token 但依赖模型判断。2026 主流是自动注入 + 按需工具双轨（Mem0 默认自动，Letta 让 Agent 自主）。

## 6. 召回性能与成本

| 指标 | 2026 标杆 |
|---|---|
| 检索延迟 | p50 <1s（Mem0 ~0.88s） |
| 检索 token | <7K/次（Mem0）vs 全上下文 25K+ |
| 索引规模 | BEAM-10M（千万 token）可用 |

| 优化 | 做法 |
|---|---|
| 异步检索 | 不阻塞对话首 token |
| 缓存 | 相同问题检索结果 TTL 缓存 |
| 索引分层 | 热门记忆常驻，冷记忆按需 |
| 截断优先 | 多召回少注入（预算内） |

## 7. 召回监控指标

| 指标 | 信号 |
|---|---|
| 命中率 | 用户提及历史事实能否注入 |
| 噪声率 | 注入无关项占比 |
| 检索延迟 | p50/p95 |
| 注入 token/轮 | 预算漂移检测 |
| 召回-回答质量 | 有/无记忆注入的 A/B 对比 |

## 8. 注入格式示例与设计

| 注入条目 | 格式 | 要点 |
|---|---|---|
| 结构化事实 | `[记忆] 用户偏好：简洁回答（来源：对话 08-09，置信 0.9）` | 带来源+置信 |
| 语义片段 | `[知识] <片段摘要>（来源：文档 2026-07，页码 3）` | 带引用 |
| 事件 | `[事件] 订单 1023 已于 08-05 取消` | 带时间 |
| 决策 | `[决策] 本季度目标：营收 +15%（用户确认）` | 带确认标记 |

| 格式设计原则 | 作用 |
|---|---|
| 前缀标注类型 | 模型区分记忆/知识/事件 |
| 带来源 | 可溯源、可质疑 |
| 带时间 | 时效判断 |
| 长度 ≤2 行 | 注入预算内 |
| 无指令性内容 | 防注入（08 篇） |

## 9. 召回常见坑速查

| 坑 | 现象 | 解法 |
|---|---|---|
| 单路向量召回 | 精确词/实体丢失 | 三信号融合 |
| 无预算截断 | 注入过载 | 预算装配 |
| 检索不隔离 | 跨用户泄漏 | agent_id 过滤（双处） |
| 过期事实召回 | 旧偏好误导 | state 过滤（07 篇） |
| 阈值过松 | 噪声注入 | 语义阈值 + 抽查 |
| 每轮全量召回 | token 浪费 | 缓存 + 按需 |
| 融合无去重 | 同事实重复注入 | RRF 后去重 |
| 注入位置漂移 | 缓存失效 | 固定尾部注入 |

## 10. 召回价值评测：A/B 协议

| 组 | 配置 | 测什么 |
|---|---|---|
| A 组（基线） | 无记忆注入 | 无记忆时的回答质量 |
| B 组（记忆） | 记忆注入开启 | 记忆带来的增量 |
| C 组（全量） | 全部历史注入 | 对照"有界注入"的优势 |

```text
评测协议：
  ① 同一 50 问题集（含"依赖历史事实"的问题）
  ② 三组各自回答 → 同一判题协议评分
  ③ 指标：正确率提升 / 注入 token 成本 / 延迟
  ④ 结论：记忆 ROI = B 组提升 - C 组成本

典型结论：B 组显著优于 A 组（记忆有用）、
         C 组略优于 B 但 token 成本翻倍（有界注入更优）
```

## 11. 召回参数调优指南

| 参数 | 默认 | 调优方向 |
|---|---|---|
| 语义阈值 | 0.5-0.7 | 噪声高 → 调高；漏召 → 调低 |
| TopK | 10-20（候选） | 预算允许 → 调大候选 |
| 注入预算 | 3-5K token | 决策质量差 → 略增 |
| RRF 常数 k | 60 | 少动（稳健） |
| 时效半衰期 | 30 天 | 偏好变化快 → 缩短 |
| 置信度门槛 | 0.6 | 噪音记忆 → 调高 |
| 注入条数 | 5-10 条 | 决策质量差且预算足 → 略增 |
| 缓存 TTL | 60s | 高频重复问题 → 调长 |

```text
调优方法：一次只动一个参数 + 自建集回归
  严禁"参数全家桶一起改"（无法归因）
  调优记录：参数/指标/结论 入文档（可复现）
```

**召回延迟预算**：检索必须在对话首 token 前完成（或异步不阻塞）——p50 <1s 是 2026 标杆（Mem0 ~0.88s）。超过 2s 的召回会直接伤害用户体验，优先优化：索引命中、缓存、异步化，而非调参。

**召回与注入的职责表**（面试速记）：

| 环节 | 目标 | 手段 | 监控 |
|---|---|---|---|
| 检索 | 召回率高（可以多） | 三信号融合、放宽阈值 | 命中率 |
| 注入 | 精确率高（必须精） | 预算装配、优先级、去重 | 噪声率、token |

（第 11 行第十一问：召回链路的事件追踪——检索日志与注入日志配对，回答"这条记忆是谁、何时、为何进上下文的"，是记忆审计的基础设施。）

> 🎯 核心要点：召回是记忆系统里 ROI 最高的优化点——**同样的存储，召回做得好，记忆"活了"**。2026 年标杆：三信号融合 + RRF + 预算装配，缺一不可。
