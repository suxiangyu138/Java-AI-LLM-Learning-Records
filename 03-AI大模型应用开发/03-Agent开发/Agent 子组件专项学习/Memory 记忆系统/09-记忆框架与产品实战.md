# 记忆框架与产品实战

> 记忆产品 2026 三强：Mem0（SDK）、Letta（运行时）、Zep（时序图谱）。本章给出深度对比、接入实战与自研路线——"先用产品跑通，再按需自研"是 2026 主流路径。

## 1. 三强对比总表（2026-08 基准）

| 维度 | Mem0 v3 | Letta（MemGPT 续） | Zep/Graphiti |
|---|---|---|---|
| 定位 | 记忆即 SDK | 记忆即运行时 | 记忆即时序图谱 |
| 架构 | 事实提取 + 向量/实体召回 | OS 三阶（core/recall/archival） | 双时间戳知识图谱 |
| 记忆操作 | ADD/UPDATE/DELETE/NOOP | Agent 自主（core_memory_append 等） | 图谱边 + 时效 |
| 检索 | 三信号融合（语义/BM25/实体） | 分层检索（recall+archival） | 语义+BM25+图遍历 |
| 时序能力 | 有（时间标注） | 弱 | **最强（点查询）** |
| 基准（供应商口径） | LoCoMo 91.6-92.5 | LoCoMo ~74 | LongMemEval 63.8（独立评估） |
| 认证 | 无 | 无 | **SOC 2/HIPAA/GDPR** |
| 许可证 | Apache-2.0 | Apache-2.0 | Apache-2.0（Graphiti） |
| 接入成本 | 极低（3 个调用点） | 高（迁移 2-6 周） | 中 |
| 锁死风险 | 低 | 高 | 中 |
| 适合 | 快速加记忆 | 长驻自主 Agent | 时序敏感/合规 |

> 🎯 核心要点：三家的本质区别是**记忆归谁管**——Mem0 归你的应用管（SDK 嵌进去）、Letta 归运行时管（Agent 自主）、Zep 归图谱管（时间敏感）。选型先问"记忆的控制权该在哪"。

## 2. Mem0 接入实战（5 分钟）

```python
# pip install mem0ai
from mem0 import Memory

m = Memory.from_config({"llm": {"provider": "openai", "config": {"model": "gpt-5.x"}},
                        "embedder": {"provider": "openai"}})

# 三个调用点：搜索 → 添加 → 检索
m.add("用户说：我住在上海，喜欢简洁回答", user_id="u42")   # 写入（自动提取）
relevant = m.search("用户住哪？", user_id="u42")          # 召回（三信号融合）
# 每轮把 relevant 注入上下文即可
```

| 特性 | 说明 |
|---|---|
| 多租户 | user_id/agent_id/session_id 命名空间 |
| 自托管 | Docker Compose + 仪表盘 + 鉴权默认开 |
| 异步 | 提取与检索异步（不阻塞） |
| 生态 | LangChain/CrewAI/AutoGen 原生集成 |
| 成本 | 检索 <7K token/次（token 效率卖点） |

## 3. Letta 接入实战（运行时托管）

```python
# 新项目：@letta-ai/letta-code（Node 22.19+），legacy 仓库已冻结
from letta_client import Letta

client = Letta(base_url="http://localhost:8283")   # 自托管服务
agent = client.agents.create(name="research-agent",
    memory_blocks=["用户核心事实..."],              # core memory（常驻）
    tools=["web_search", "archival_memory_insert"])

# Agent 自主管理记忆：调用 archival_memory_insert 等工具
```

| 特性 | 说明 |
|---|---|
| OS 三阶 | core（RAM，常驻）/ recall（文件系统，可搜索历史）/ archival（硬盘，向量） |
| 自主管理 | Agent 自己决定记忆升降级（无需人工） |
| 服务化 | REST API，多 Agent 共享记忆 |
| 代价 | 锁死高（迁移 2-6 周）+ 每轮记忆工具调用的 token |

## 4. Zep/Graphiti 接入实战（时序图谱）

```python
# Graphiti 开源引擎：双时间戳图谱
from graphiti import Graphiti

graph = Graphiti(uri="neo4j://localhost:7687",
                 llm=..., embedder=...)
graph.add_episode("用户说：我搬去北京了", entity_type="user:42")
result = graph.search("用户住哪？", limit=5)        # 语义+BM25+图遍历融合
# 点查询：graph.temporal_search("用户 2026-06 住哪", as_of="2026-06-30")
```

| 特性 | 说明 |
|---|---|
| 双时间戳 | event_time + ingested_at，演变可查 |
| 点查询 | "某时刻的事实"是一等查询 |
| 合规 | 唯一带认证（SOC2/HIPAA/GDPR）的产品 |
| 基础设施 | Neo4j 5.26/FalkorDB/Neptune |

## 5. 自研路线（数据不出内网/深度定制）

| 阶段 | 组成 | 对应本体系篇 |
|---|---|---|
| 1. 最小可用 | SQLite/Redis：chat 表 + claims 表 + 简单召回 | 03/04 |
| 2. 提取上线 | 单遍 ADD-only 提取 + 实体链接 | 05 |
| 3. 检索升级 | 三信号融合 + RRF + 注入预算 | 06 |
| 4. 维护成熟 | claim 生命周期 + 双时间戳 + 遗忘 | 07 |
| 5. 治理完备 | 脱敏/隔离/审计/用户 veto | 08 |

> 💡 自研 vs 产品的判据：**记忆不是核心差异化时用产品（Mem0 起步），记忆是产品卖点时自研**（如"记住你的一切"型产品）。自研路线图与[数据库交互](../../Agent%20配套技术生态模块/数据库交互/05-Agent结构化记忆：会话与状态持久化.md) 05 篇的存储方案衔接。

## 6. 混合架构：产品 + 自研组合

| 层 | 用产品还是自研 | 理由 |
|---|---|---|
| 提取 | 产品（Mem0 提取 API） | 提取是成熟能力 |
| 存储 | 自研（PG 一库化） | 数据不出内网 |
| 召回 | 产品（Mem0 检索 API）或自研 | 按预算 |
| 治理 | 自研 | 合规细节定制 |

## 7. 选型决策树

```text
要快速给现有 Agent 加记忆？→ Mem0
要长驻自主 Agent（周/月级）？→ Letta
事实随时间变化是核心？→ Zep/Graphiti
要合规认证？→ Zep
数据不出内网/深度定制？→ 自研（本体系组合）
先小后大？→ Mem0 起步，需求升级再换
```

| 选型补充 | 说明 |
|---|---|
| 预算有限 | Mem0 免费层（1 万条记忆/月）起步 |
| 团队 Java 栈 | 记忆产品多为 Python/TS SDK——Java 侧建议自研（PG 一库化） |
| 离线/无外网 | 自研或自托管（Mem0 自托管服务器） |
| 多 Agent 共享记忆 | Letta（多 Agent 共享内存）/ Zep（图谱共享） |

> 🎯 核心要点：记忆产品的 2026 成熟度已足够"直接消费"——**先想清楚控制权归属（应用/运行时/图谱）与合规需求，再选产品；产品跑通后再按需自研**。别上来就自建，也别迷信单一供应商基准分（协议陷阱见 10 篇）。

## 8. 自研路线的成本对照

| 阶段 | 工作量 | 与产品对比 |
|---|---|---|
| 1. 最小可用（chat+claims+简单召回） | 1-2 天 | Mem0 接入 5 分钟 |
| 2. 提取上线（ADD-only+实体链接） | 2-3 天 | Mem0 内建 |
| 3. 检索升级（三信号+RRF） | 2-3 天 | Mem0 内建 |
| 4. 维护成熟（生命周期+时序） | 3-5 天 | Zep 内建 |
| 5. 治理完备（脱敏/隔离/审计/veto） | 3-5 天 | 产品需评估 |

```text
自研的总账：11-16 人日换"完全可控 + 数据不出内网 + 零订阅费"
产品账：小时级接入，但受产品能力边界约束 + 订阅费 + 数据外发
判据：记忆是核心差异化 → 自研；否则 → 产品
```

## 9. 接入常见坑速查

| 坑 | 现象 | 解法 |
|---|---|---|
| 全量迁移产品 | 历史数据格式不兼容 | 先小流量试跑 |
| 迷信供应商基准 | 协议陷阱误判 | 同协议对比 + 自建集 |
| 产品锁死无退路 | 迁移 2-6 周（Letta） | 组件契约 + 适配层 |
| 自托管不设鉴权 | 记忆裸奔 | Mem0 默认鉴权别关 |
| 记忆库无备份 | 记忆丢失 | 与业务库同备份策略 |
| 混用多产品 | 记忆分家 | 单一入口 + 统一契约 |
| 合规后置 | 认证需求难补 | 上线前确认 |
