# 记忆系统全景：Agent 的分水岭

> 记忆是"Agent"与"无状态提示词系统"的唯一分界线。2026 年共识：**存什么不重要，怎么取才重要**（"Storage Is Not Memory"，arXiv 2605.04897）——本体系第一篇立起全景，后续各篇逐一深潜。

## 1. 记忆的三类角色

| 角色 | 回答的问题 | 载体 | 成败影响 |
|---|---|---|---|
| 上下文 | "刚才聊到哪了" | 工作记忆（上下文窗口） | 每轮体验 |
| 连续性 | "上次任务进展如何" | 情景记忆（历史/检查点） | 长任务成败 |
| 个性化 | "这个用户是谁、偏好什么" | 长期记忆（向量/事实表） | 产品价值 |

> 🎯 核心要点：三层记忆对应三种需求——**省 token（工作）、全留痕（情景）、准召回（长期）**。把三层混为一谈是记忆系统最常见的架构错误。

## 2. 为什么"原始对话 RAG"是错的

| 方案 | 问题 | 后果 |
|---|---|---|
| 把全部对话历史塞进上下文 | 窗口爆炸 | 长会话必然失败 |
| 对话历史向量化后 RAG | 检索到"段落"而非"事实" | 信噪崩塌 |
| 原始对话直接检索 | 无关系感知 | "张三"与"张总的订单"连不上 |
| 无矛盾处理 | 新旧事实同时召回 | 自相矛盾的回答 |

| 缺陷（2026 实证） | 表现 |
|---|---|
| 信噪比崩塌 | 检索的是段落不是事实，噪声淹没信号 |
| 无关系感知 | 语义相似 ≠ 结构相关 |
| 无矛盾检测 | 新偏好与旧偏好同时存在 |
| 无时效概念 | 过期记忆无法失效 |

> 🎯 核心要点：**记忆不等于历史，记忆是"从历史中提炼的事实"**——原始对话是原料，事实提取是加工，召回是上桌。只做"存+检索原文"的记忆系统，在 2026 年已被证实不合格。

## 3. 记忆系统的完整流水线

```text
对话/行为
  → ① 写入（提取）：单遍 ADD-only 提取事实（05 篇）
  → ② 存储：分层（向量/关系表/图谱）（04 篇）
  → ③ 召回：三信号融合检索（06 篇）
  → ④ 注入：记忆管理器装配进上下文（02/06 篇）
  → ⑤ 维护：冲突检测/时序/遗忘（07 篇）
  → ⑥ 治理：安全/合规/审计（08 篇）
```

| 环节 | 2026 关键结论 | 对应篇 |
|---|---|---|
| 写入 | 单遍 ADD-only 优于两遍对账 | 05 |
| 召回 | 三信号融合优于单路 | 06 |
| 维护 | 双时间戳 + claim 生命周期 | 07 |
| 治理 | PII 脱敏 + 用户隔离 + 审计 | 08 |

## 4. 2026 三大流派：SDK / 运行时 / 时序图谱

| 流派 | 代表 | 定位 | 记忆哲学 | 适合 |
|---|---|---|---|---|
| 记忆即 SDK | Mem0 | 记忆层独立组件 | 事实提取 + 向量/实体召回 | 现有应用快速接入 |
| 记忆即运行时 | Letta | 整个 Agent 运行时 | Agent 自主管理记忆（OS 三阶） | 长驻自主 Agent |
| 记忆即时序图谱 | Zep/Graphiti | 时间感知图谱 | 双时间戳，历史可查 | 事实随时间变化的场景 |

| 选型速判 | 结论 |
|---|---|
| 快速给现有 Agent 加记忆 | Mem0（5 分钟接入） |
| 长驻自主 Agent（周/月级） | Letta（运行时托管） |
| "什么时候是事实"是关键 | Zep（时序图谱） |
| 要合规认证（SOC2/HIPAA/GDPR） | Zep（唯一有认证） |
| 深度定制/数据不出内网 | 自研（04-08 篇组合） |

> 💡 2026 主流建议：**先用 Mem0 起步（快），需求升级到时序推理换 Zep，要自持运行时选 Letta**——三家的切换成本递增，先小后大。

## 5. 记忆系统质量的三条主线

| 主线 | 问题 | 失败表现 |
|---|---|---|
| 提取质量 | 事实提炼得准不准 | 记错/漏记/记了一堆噪音 |
| 召回质量 | 需要时能不能找到 | 该记住的没注入 |
| 维护质量 | 记忆会不会过期/矛盾 | 旧事实误导新决策 |

> 🎯 核心要点：记忆系统的**评测比实现更难**——LoCoMo 等基准的协议陷阱（判题宽松度/答案模型）可使同系统分数差 30 分（见 10 篇评测节），生产评估必须"协议固定 + 自建场景集"。

## 6. 心智模型：记忆是"资产"不是"缓存"

| 维度 | 缓存思维（错） | 资产思维（对） |
|---|---|---|
| 目标 | 存得越多越好 | 提取准、召回准、维护好 |
| 结构 | 原文堆着 | 事实级结构化 |
| 生命周期 | 满了就删 | 状态机（新增/废弃/遗忘） |
| 成本 | 存储成本 | 检索 token 效率 |
| 治理 | 无 | 脱敏/隔离/审计 |

> 🎯 核心要点：**记忆系统的预算不在存储，在检索 token**（Mem0 <7K/次 vs 全上下文 25K+ 是 2026 的标杆数字）——"每次检索省 token"是记忆系统的核心经济指标。

## 7. 记忆系统十问自检

| # | 问题 | 不合格的答案 |
|---|---|---|
| 1 | 三层记忆分工明确吗？ | "都是历史，都存着" |
| 2 | 有记忆管理器吗？ | "每轮全量注入" |
| 3 | 提取是单遍 ADD-only 吗？ | "两遍对账，会删旧事实" |
| 4 | 召回是融合检索吗？ | "只有向量" |
| 5 | 注入有预算吗？ | "能塞多少塞多少" |
| 6 | 事实有状态机吗？ | "没有废弃概念" |
| 7 | 有双时间戳吗？ | "只有一个时间" |
| 8 | 跨用户隔离了吗？ | "存储隔离了，召回忘了" |
| 9 | PII 脱敏在哪做？ | "召回时过滤" |
| 10 | 评测协议固定吗？ | "看供应商榜单" |
| 11 | 检索 token 有预算吗？ | "每轮全量召回忆" |
| 12 | 记忆变更可回放吗？ | "没想过回放" |
| 13 | 记忆产品选型有依据吗？ | "看星标最高的" |

> 💡 十问全过 = L3 成熟度（对照[四大核心组件](../../Agent%20四大核心组件/05-记忆组件：短中长时记忆架构.md) 05 篇的成熟度模型）；答不出 3 个以上 = 记忆系统还是"缓存"，不是"资产"。速记口诀：**"分层存、单遍写、融合取、状态管、双时戳、双隔离、预算控、协议测"**——八字诀即本体系全貌。

## 8. 常见误区

| 误区 | 真相 |
|---|---|
| "记忆=向量数据库" | 向量只管语义召回；事实/偏好走结构化 |
| "存得越多越好" | 噪音淹没信号，提取克制才是质量 |
| "历史就是记忆" | 历史是原料，提取出的事实才是记忆 |
| "记忆是一次性设计" | 写入/召回/维护是持续工程（评测+回归） |
| "记忆产品开箱即用" | 产品解决管道，业务质量靠场景集评测 |
| "忘了就删" | 归档优先，删除只用于合规 |
| "记忆是后端的事" | 注入格式/预算直接影响对话质量——前后端都要懂 |
| "记忆产品能测一切" | 供应商基准有协议陷阱，必须自建场景集 |
