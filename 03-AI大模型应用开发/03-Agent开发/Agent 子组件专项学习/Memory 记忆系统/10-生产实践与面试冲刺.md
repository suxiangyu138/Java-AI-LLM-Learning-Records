# 生产实践与面试冲刺

> 从"能记"到"可靠"：评测协议、生产基线、12 避坑、面试题与落地检查单——记忆系统体系收官篇。

## 1. 评测：记忆系统的"考试纪律"

### 1.1 基准与协议陷阱

| 基准 | 测什么 | 规模 | 2026 警示 |
|---|---|---|---|
| LoCoMo | 长会话回忆（单跳/多跳/时序） | ~300 轮/9K token/35 会话 | **可被刷分**（激进检索+大窗口+前沿模型） |
| LongMemEval | 长上下文记忆 | 长文档+长会话 | 判题宽松度影响大 |
| BEAM-1M/10M | 百万 token 级生产场景 | 1M/10M token | **最贴近生产** |

| 协议变量 | 影响 | 控制 |
|---|---|---|
| 判题提示词 | 同系统差 30 分（True Memory 93 vs mem0 61.4 对照实验） | 固定判题协议 |
| 答案模型 | 判题模型强弱 | 固定 |
| 注入粒度 | 检索难易 | 固定 |
| 排除类别 | LoCoMo adversarial 是否排除 | 与官方一致 |
| 温度 | 单次运行 | temperature=0 |

> ⚠️ 2026 实测教训：**同一系统在不同评测协议下得分差 30 分**——任何"分数对比"必须同协议才有意义；供应商自报分只能作参考，不能当选型依据。

### 1.2 自建评测集（生产必做）

```text
50-80 个问题场景：
  ✓ 用户提到的历史事实（单跳）
  ✓ 跨会话组合推理（多跳）
  ✓ 时间变化的事实（"他现在住哪"）
  ✓ 该忘记的（废弃事实不注入）
  ✓ 隔离测试（A 用户查不到 B 的记忆）
```

## 2. 生产基线（记忆系统）

| 领域 | 基线 |
|---|---|
| 写入 | 单遍 ADD-only、提取召回率 ≥90%、噪声率 <20% |
| 召回 | 三信号融合 + RRF、命中率 ≥90%、注入噪声 <20% |
| 注入 | 预算 10-15%、每轮 token 稳定 |
| 维护 | 冲突写入时检测、DEPRECATED 归档不删 |
| 治理 | PII 写入脱敏、跨用户隔离测试通过、审计开启 |
| 成本 | 检索 <7K token/次（对标）、写入异步化 |
| 评测 | 提取/召回/注入指标入 CI（每次变更跑回归） |

## 2.1 记忆系统演进趋势（2026-2027）

| 趋势 | 现状 | 影响 |
|---|---|---|
| 检索中心架构 | "Storage Is Not Memory" 成共识 | 召回投资 > 存储投资 |
| 单遍提取 | ADD-only 替代两遍对账 | 提取延迟减半 |
| 时序记忆 | 双时间戳成产品卖点（Zep） | 点查询成为需求 |
| 记忆产品化 | SDK/运行时/图谱三流派成熟 | 自研门槛降低 |
| 记忆治理立法化 | GDPR/HIPAA 执行趋严 | veto/脱敏成硬需求 |
| BEAM 化评测 | 百万 token 规模基准上位 | 生产相关性提升 |

> 💡 对工程师的启示：记忆系统的**核心竞争力在"召回与维护"而非"存储"**——2026-2027 的投入顺序：召回优化 > 提取打磨 > 维护自动化 > 存储扩容。

**与体系内其他子组件的关系**：记忆是其他子组件（反思教训、规划经验、工具使用记录）的共同落点——[Reflection 反思模块](../Reflection%20反思模块/)、[Planner 规划器](../Planner%20规划器/)、[Tool 工具开发与注册](../Tool%20工具开发与注册/) 的产出都可以写入记忆，本体系是其存储与召回底座。这也意味着：**记忆系统的稳定性是其他子组件有效性的前提**——反思教训存不住，反思等于白做；规划经验取不出，规划无法进化。

## 3. 12 避坑清单

| # | 坑 | 后果 | 解法 |
|---|---|---|---|
| 1 | 原始对话 RAG 当记忆 | 信噪崩塌 | 事实提取（05 篇） |
| 2 | 两遍对账式提取 | 慢且毁原事实 | 单遍 ADD-only |
| 3 | 全量历史注入 | 窗口爆炸 | 有界读取 + 摘要 |
| 4 | 覆盖式更新 | 演变不可查 | supersedes 链 |
| 5 | 无状态机 | 新旧不分 | claim 生命周期 |
| 6 | 召回层忘隔离 | 跨用户泄露 | 存储+召回双过滤 |
| 7 | PII 入库 | 隐私事故 | 写入路径脱敏 |
| 8 | 记忆当指令 | 注入操控 | 格式标注 + 分域 |
| 9 | 单时间戳 | 时序不可查 | 双时间戳 |
| 10 | 遗忘=删除 | 审计断链 | 归档优先 |
| 11 | 供应商基准当依据 | 协议陷阱误判 | 同协议对比 + 自建集 |
| 12 | 无用户 veto | 信任崩塌 | 查看/删除/关闭 |

## 4. 面试题（高频 12 题 + 答题要点）

| 题 | 答题要点 |
|---|---|
| 1. Agent 记忆分几层？ | 工作记忆（上下文，省 token）/情景（历史+检查点，全留痕）/长期（事实+知识，准召回）；记忆管理器装配 |
| 2. 为什么对话历史 RAG 不行？ | 检索段落非事实、无关系感知、无矛盾检测、无时效——信噪崩塌 |
| 3. 记忆怎么写入？ | 单遍 ADD-only 提取：一次调用只新增；Agent 事实一等公民；实体链接；写入事务+幂等 |
| 4. 记忆怎么召回？ | 三信号融合（语义/BM25/实体）+ RRF + 注入预算；检索放宽、注入收紧 |
| 5. 事实矛盾怎么处理？ | claim 生命周期（PROPOSED→ACCEPTED→DEPRECATED）+ supersedes 链；保存时检测而非召回时仲裁 |
| 6. 双时间戳是什么？ | event_time（事实成立）+ ingested_at（得知）；支撑点查询与时效加权 |
| 7. 上下文超窗怎么治理？ | 有界读取 + 滚动摘要 + 注入预算 + 提示词冻结缓存；事实单独存不走摘要 |
| 8. 记忆安全有哪些防线？ | PII 写入脱敏、agent_id 存储+召回双隔离、注入格式标注、保留策略、用户 veto、审计 |
| 9. Mem0/Letta/Zep 区别？ | SDK（应用管）/运行时（Agent 管）/时序图谱（时间敏感）；Mem0 快、Letta 锁死高、Zep 合规强 |
| 10. 记忆系统怎么评测？ | LoCoMo/LongMemEval/BEAM；协议陷阱（判题宽松度可差 30 分）；自建场景集 + 固定协议 |
| 11. 记忆成本怎么控？ | 检索 token 效率（<7K/次 对标）、注入预算、异步提取、缓存、分层索引 |
| 12. 遗忘机制怎么设计？ | 状态废弃（归档不删）+ 置信度降级 + 时间衰减 + 保留期 + 用户删除；"降权归档"而非删除 |

## 5. 落地检查单（上线前逐项打勾）

```text
□ 三层记忆分工明确（工作/情景/长期），记忆管理器装配优先级配置
□ 写入：单遍 ADD-only + 实体链接 + 事务 + 幂等 + 异步
□ 召回：三信号融合 + RRF + 注入预算 + 信噪控制
□ 维护：claim 生命周期 + 双时间戳 + 保存时冲突检测
□ 治理：PII 写入脱敏 + 存储召回双隔离（跨用户测试通过）+ 审计
□ 用户控制权：查看/删除/关闭可用
□ 评测：自建场景集 + 固定协议 + 定期回归（提取/召回/注入指标）
□ 成本：检索 token 监控 + 注入预算 + 缓存
□ 选型：产品（Mem0/Letta/Zep）或自研路线明确，合规需求确认
□ 故障演练：注入攻击、跨用户检索、记忆污染各一次
```
