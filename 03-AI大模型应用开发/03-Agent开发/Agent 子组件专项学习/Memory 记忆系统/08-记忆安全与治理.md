# 记忆安全与治理

> 记忆是 Agent 最敏感的数据——它包含用户隐私、个人偏好、业务事实。2026 年治理共识：**PII 脱敏、按用户隔离、注入防御、保留策略、用户控制权**五件套，缺一不可。

## 1. 记忆安全的威胁模型

| 威胁 | 路径 | 后果 |
|---|---|---|
| 记忆泄露 | 跨用户注入/导出 | 隐私事故 |
| 记忆污染 | 注入指令进入记忆 → 后续决策被劫持 | 行为操控 |
| 记忆窃取 | 通过 Agent 诱导套取他人记忆 | 数据泄露 |
| 记忆滥用 | 无授权场景使用敏感记忆 | 合规违规 |
| 记忆膨胀 | 无保留策略 | 存储/成本失控 |

> 🎯 核心要点：记忆是"持久的攻击面"——提示注入危害一次对话，记忆污染危害**所有未来对话**。记忆安全的价值高于普通数据安全。

## 2. PII 脱敏：入库前处理

| 数据 | 处理 |
|---|---|
| 邮箱/手机号 | 哈希化（可逆查询用 HMAC） |
| 地址/身份证 | 掩码（省/市级别）或拒绝入库 |
| 金融信息 | 拒绝入库（或加密+最小化） |
| 健康信息 | 合规要求（GDPR/HIPAA） |
| 自由文本 | 提取时识别 PII 并替换 |

```python
def sanitize_claim(text: str) -> str:
    text = re.sub(EMAIL_RE, "[email]", text)
    text = re.sub(PHONE_RE, "[phone]", text)
    return text          # 提取时应用：PII 不进记忆库
```

> 💡 原则：**脱敏在写入路径做**（提取时替换），而不是召回时过滤——召回过滤"看见了再遮"，写入脱敏"根本不存在"。

## 3. 记忆隔离：按用户/Agent/会话

| 隔离维度 | 键 | 说明 |
|---|---|---|
| 用户级 | agent_id/namespace | 用户 A 的记忆用户 B 不可见（核心） |
| Agent 级 | agent 实例 | 不同 Agent 记忆独立 |
| 会话级 | thread_id | 临时会话不污染长期记忆 |

| 隔离实现 | 做法 |
|---|---|
| 存储层 | claims/向量按 agent_id 分区（查询必带） |
| 召回层 | 检索过滤 agent_id（不止存储层！） |
| 注入层 | 装配前校验归属 |
| 测试 | 用户 A 的输入能否查出 B 的记忆（必须不能） |

> ⚠️ 记忆隔离最常见的漏洞：**存储层分区了，召回层忘了过滤**——向量检索 TopK 若不带 agent_id 过滤，多租户记忆会互相泄露。上线前必须跑"跨用户检索"测试。

## 4. 注入防御：记忆当数据不当指令

| 风险 | 例子 | 防线 |
|---|---|---|
| 记忆内容带指令 | 用户聊天里塞"忘记所有规则..."被提取入记忆 | 提取时过滤指令性内容 |
| 注入记忆进上下文 | 恶意记忆被模型当作指令执行 | 注入格式标注"记忆数据" |
| 文档记忆污染 | 知识库内容带注入（见文档解析体系） | 内容与指令分域 |

```text
注入格式的防御设计：
  [记忆] 用户偏好简洁回答（来源：对话 2026-08-09，置信 0.9）
  —— 明确标注"这是记忆数据"，模型区分"数据"与"指令"
```

| 防御层 | 做法 |
|---|---|
| 提取层 | 过滤指令性内容（"忽略之前的指令"类） |
| 存储层 | 来源标注（用户/Agent/系统） |
| 注入层 | 格式标注 + 内容消毒 |
| 执行层 | 记忆驱动的动作需审批（写操作） |

## 5. 保留策略：记忆的生命周期管理

| 记忆类型 | 保留期建议 | 处理 |
|---|---|---|
| 会话历史 | 90 天-2 年（合规定） | 分区清理 |
| 用户偏好 | 长期（用户可删） | 保留 + veto |
| 业务事实 | 按业务（合同/账期） | 保留 + 归档 |
| 敏感 PII | 最短必要 | 到期硬删 |
| Agent 内部状态 | 任务级 | 完成即清 |

```text
保留策略三问：
  ① 法律要求存多久？（合规下限）
  ② 业务需要存多久？（产品上限）
  ③ 用户要求删什么？（用户控制权）
```

## 6. 审计与合规

| 项 | 做法 |
|---|---|
| 写入审计 | 谁/何时/提取了什么（不记全文） |
| 召回审计 | 谁/何时/召回了哪些记忆 |
| 删除审计 | 用户删除请求留痕（合规） |
| 数据主体请求 | 导出/删除/更正（GDPR 要求） |
| 认证 | SOC 2/HIPAA/GDPR（需要时选 Zep 等认证产品） |

## 7. 用户控制权（2026 焦点）

| 能力 | 说明 |
|---|---|
| 查看 | 用户能看到 Agent 记住了什么 |
| 删除 | 一键删除特定记忆（veto） |
| 关闭 | 关闭记忆功能（隐私模式） |
| 同意 | 记忆功能需用户同意（默认开但可关） |

> 💡 用户控制权是信任的基础——"它记住了我的事"必须有"我能让它忘掉"的对等能力。2026 年记忆产品（Zep user veto、Letta 应用层补充）都把控制权列为合规焦点。

## 8. 安全治理自检清单

```text
□ PII 在写入路径脱敏（非召回过滤）
□ 记忆按 agent_id 隔离，召回层也过滤（跨用户检索测试通过）
□ 注入格式标注"记忆数据"，指令性内容提取时过滤
□ 保留策略明确（合规下限/业务上限/用户删除）
□ 写入/召回审计开启
□ 用户控制权（查看/删除/关闭）可用
□ 记忆驱动的写操作走审批（衔接数据库交互 07 篇）
□ 合规认证需求评估（选型时确认）
```

> 🎯 核心要点：记忆治理的黄金法则——**"记住"要克制（最小化+脱敏）、"隔离"要彻底（存储+召回双过滤）、"忘记"要可控（用户 veto+保留策略）**。治理不是上线后的补丁，是记忆架构的第一性需求。

## 9. 治理常见坑速查

| 坑 | 现象 | 解法 |
|---|---|---|
| 脱敏在召回时做 | 敏感数据已入库 | 写入路径脱敏 |
| 召回层忘过滤 | 跨用户泄露 | 双处过滤 + 专项测试 |
| 记忆当指令 | 注入操控 | 前缀标注 + 分域 |
| 无保留策略 | 无限膨胀 | 三层保留期（08 篇 5 节） |
| 审计记全文 | 日志泄密 | 只记元数据 |
| 用户无删除权 | 合规/信任风险 | veto 能力 |
| 合规需求后置 | 选型错误 | 上线前确认认证需求 |
| 删除不留痕 | 合规违规 | 删除审计 |

## 10. 治理落地流程（从零到完备）

| 阶段 | 动作 | 时间 |
|---|---|---|
| 1. 威胁建模 | 明确记忆类型与敏感级别 | 半天 |
| 2. 写入防线 | PII 脱敏接入提取管道 | 1 天 |
| 3. 隔离防线 | agent_id 存储+召回双过滤 + 跨用户测试 | 1 天 |
| 4. 注入防线 | 格式标注 + 指令性内容过滤 | 半天 |
| 5. 生命周期 | 保留策略 + 归档清理任务 | 1 天 |
| 6. 用户控制 | 查看/删除/关闭功能 | 1-2 天 |
| 7. 审计合规 | 审计日志 + 合规认证评估 | 按需 |

```text
治理成熟度判定：
  L1：能存（无治理）→ L2：能防（脱敏+隔离）
  → L3：能管（保留+用户控制）→ L4：能证（审计+认证）
  对外产品至少 L3；受监管行业 L4
```

## 11. 记忆安全测试清单（上线前必跑）

| 测试 | 验证点 |
|---|---|
| 跨用户检索 | 用户 A 的问题能否查出用户 B 的记忆（必须不能） |
| 注入演练 | 对话中塞"忘记规则"指令 → 不入记忆、不执行 |
| 脱敏抽检 | 入库样本中无明文 PII |
| 越权导出 | 非法调用记忆 API → 拒绝 |
| 删除请求 | 用户删除后 → 召回不再命中 + 删除留痕 |
| 保留策略 | 超期数据 → 被清理（含备份） |
| 审计完整性 | 写入/召回/删除日志可查 |

> 💡 记忆安全测试应进 CI 回归——**记忆是持久攻击面，一次漏洞影响所有用户的所有未来对话**。与[幻觉、格式错误、安全、token 超限](../../幻觉、格式错误、安全、token%20超限/00-Agent四大失败模式知识体系总览.md)体系的提示注入篇联动：记忆污染是"持久化注入"，比单轮注入危害更大。
