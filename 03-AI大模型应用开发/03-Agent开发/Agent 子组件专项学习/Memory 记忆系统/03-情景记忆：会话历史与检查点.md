# 情景记忆：会话历史与检查点

> 情景记忆 = "发生过什么"的完整留痕：聊天历史（结构化表）+ 检查点（任务状态快照）。工作记忆负责"给模型看"，情景记忆负责"全留着、能恢复、可回放"。

## 1. 情景记忆的两大载体

| 载体 | 存什么 | 服务谁 | 粒度 |
|---|---|---|---|
| 聊天历史表 | 消息/工具调用/结果 | 上下文重建、审计、训练 | 条（消息级） |
| 检查点（Checkpoint） | 任务状态快照 | 崩溃恢复、回放、分支 | 步（任务级） |

> 🎯 核心要点：**历史是"对话的记录"，检查点是"任务的状态"**——前者回答"说过什么"，后者回答"干到哪了"。长任务 Agent 两者都要。

## 2. 聊天历史存储设计

```sql
CREATE TABLE chat_messages (
    id         BIGSERIAL PRIMARY KEY,
    thread_id  TEXT NOT NULL,            -- 会话（用户+会话维度）
    role       TEXT NOT NULL,            -- user/assistant/tool
    content    TEXT,
    meta       JSONB,                    -- token 数/工具调用/模型
    created_at TIMESTAMPTZ DEFAULT now()
);
CREATE INDEX idx_thread ON chat_messages (thread_id, id);
```

| 设计决策 | 说明 |
|---|---|
| 有界读取 | 读取只取最近 N 条（02 篇），**不删行** |
| 索引 | (thread_id, id) 复合索引，恢复 O(log n) |
| 元数据 | token 数入 meta（预算计算不再重数） |
| 分区 | 按月分区，保留策略按区清理 |
| 并发 | 数千会话并行读写无冲突（行级隔离） |

> 💡 持久化细节（连接池/迁移/备份）见[数据库交互](../../Agent%20配套技术生态模块/数据库交互/05-Agent结构化记忆：会话与状态持久化.md) 05 篇——聊天历史是"关系表最标准的应用"。

## 3. 检查点：任务状态快照

| 检查点存什么 | 例子 | 价值 |
|---|---|---|
| 图状态 | 消息、计划、中间结果 | 崩溃恢复 |
| 循环计数 | 当前步骤/轮次 | 续跑不重头 |
| 预算余额 | 剩余 token/步骤 | 恢复后预算延续 |
| 时间戳 | 最后活跃 | 会话过期判定 |

```python
# LangGraph 示例：检查点即插即用
from langgraph.checkpoint.redis import RedisSaver

checkpointer = RedisSaver.from_conn_info(host="redis", port=6379)
app = graph.compile(checkpointer=checkpointer)

config = {"configurable": {"thread_id": "user-42-task-7"}}
# 中途崩溃 → 同一 thread_id 重新 invoke → 从断点恢复
```

| 检查点能力 | 应用 |
|---|---|
| 断点续跑 | 长任务崩溃恢复 |
| 回放 | 调试（重放每一步） |
| 分支 | 从某步 fork 新路径（探索） |
| 跨设备 | 换设备续聊 |
| 时间旅行 | 回到历史状态重来 |

## 4. 事件记忆：情景的另一种形态

| 形态 | 内容 | 存储 | 用途 |
|---|---|---|---|
| 原始事件流 | 完整日志 | 审计存储 | 追责、重放 |
| 事件摘要 | 每任务一段摘要 | 情景表 | 快速回顾 |
| 教训记忆 | 失败+反思结论 | 情景表（带标签） | 跨任务学习（Reflexion） |

```text
教训记忆示例（反思组件的产出，见四大核心组件 04 篇）：
  {event: "SQL 查询报列名错误", lesson: "先 describe_table 再写查询",
   tags: ["db", "lesson"], created: 2026-08-09}
```

## 5. 记忆衰减：情景的自然生命周期

| 层级 | 保留期建议 | 处理 |
|---|---|---|
| 原始消息 | 按合规（90 天-2 年） | 分区清理 |
| 任务摘要 | 长期 | 保留 |
| 教训记忆 | 长期 | 保留 + 去重 |
| 过时事件 | 即时 | 归档（不删，降权） |

> ⚠️ 记忆衰减 ≠ 直接删除：**归档优先**（保留审计价值），只有合规要求才硬删。2026 年共识——"记忆管理是降权与归档的艺术，不是删除的艺术"。

## 6. 情景记忆的恢复场景

| 场景 | 恢复动作 |
|---|---|
| 页面刷新 | 拉最近 N 条历史 → 重建上下文 |
| 会话中断 | 检查点恢复任务状态 |
| 用户换设备 | thread_id 维度拉全量 |
| 审计查询 | 按时间/关键词查原始事件 |
| 模型升级重放 | 回放历史重生成（评测用） |

## 7. 常见坑速查

| 坑 | 现象 | 解法 |
|---|---|---|
| 历史不落库 | 重启全丢 | 消息表 + 写入即持久化 |
| 只存不读 | 存储膨胀 | 有界读取 + 摘要 |
| 检查点存全量 | 状态爆炸 | 只存必要状态（08 篇 3.1 纪律） |
| 无 thread_id | 多设备串台 | 会话隔离键 |
| 事件不审计 | 事故无据 | 原始事件流留痕 |
| 恢复不重建预算 | 续跑烧穿预算 | 预算余额入检查点 |

## 8. 多模态情景记忆

| 内容类型 | 存储 | 还原 |
|---|---|---|
| 文本消息 | 文本列 | 直接 |
| 图片/文件引用 | 对象存储路径 + 元数据 | 按需取回 |
| 工具结果（大） | 摘要入库 + 原文对象存储 | 需要时取原文 |
| 语音 | 转写文本 + 音频路径 | 转写为主 |

> 💡 多模态原则：**上下文里只放"引用与摘要"，正文在对象存储**——工作记忆省 token，情景记忆保完整，两层各司其职（衔接[文档解析](../../Agent%20配套技术生态模块/文档解析/00-文档解析总览.md)体系的产物存储）。

## 9. 与工作记忆的衔接（视图 vs 全量）

```text
情景记忆（全量）──有界读取──→ 工作记忆（视图）
  完整历史/检查点            最近 N 条 + 摘要 + 注入记忆
      ↑                              ↓
   审计/恢复/回放              模型决策使用
```

| 衔接规则 | 说明 |
|---|---|
| 写入一次，读两个视图 | 历史只存一份，按需投影 |
| 恢复先重建工作记忆 | 检查点 → 有界读取 → 上下文 |
| 审计不经上下文 | 原始事件只走查询通道 |

## 10. 检查点实现注意：粒度与成本的平衡

| 检查策略 | 恢复精度 | 存储成本 | 适用 |
|---|---|---|---|
| 每步全量 | 精确到步 | 高（状态 × 步数） | 高价值长任务 |
| 每 N 步 | 丢失 N 步内进展 | 中 | 默认推荐 |
| 关键节点 | 只存里程碑 | 低 | 批量任务 |
| 无检查点 | 无法恢复 | 零 | 短任务（≤3 步） |

```text
检查点粒度决策公式：
  状态大小 × 步数 × 恢复需求
  —— 恢复需求低的任务，每 N 步足够（崩溃后从最近检查点继续，
     丢失的中间结果可重新执行或标记为部分完成）
```

> 💡 检查点不只是"恢复工具"，还是"回放与分支的基础设施"——调试（重放每一步）、探索（从历史点 fork）都依赖它，粒度选择要兼顾这几种用途。

## 11. 清理与归档任务（定期维护）

| 任务 | 频率 | 内容 |
|---|---|---|
| 消息分区清理 | 月度 | 超保留期分区删除（合规） |
| 摘要重建 | 会话结束后 | 生成会话级摘要 |
| 检查点归档 | 任务完成后 | 完成任务的检查点压缩 |
| 事件去重 | 周度 | 重复事件合并 |
| 存储统计 | 周度 | 各表容量/增长趋势 |

```text
清理任务的设计原则：
  归档优先于删除（保留审计价值）
  删除仅按保留策略（合规）
  清理不影响在线服务（低峰执行）
```

> 💡 情景记忆的容量规划：每条消息 ~200-500B + 索引，10 万用户 × 平均 500 条消息 ≈ 数十 GB 级——分区 + 归档可控制增长，但**"全量保留"的合规价值要明确**：没有审计需求时，别让情景记忆无限膨胀。容量规划的时间线：**上线前建模（本表公式）→ 每月复核增长率 → 超预期即启动归档**，比"满了再想办法"便宜得多。

> 🎯 核心要点：情景记忆的价值在"关键时刻"——崩溃恢复、审计追责、用户回顾，平时静默。**它不需要"好看"，需要"完整、可恢复、可回放"**——这就是为什么它和工作记忆（要省）的工程要求完全不同。
