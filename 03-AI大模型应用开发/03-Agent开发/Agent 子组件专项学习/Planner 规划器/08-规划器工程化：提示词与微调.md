# 规划器工程化：提示词与微调

> 规划器的能力从哪来？2026 年四条路：**提示词（零成本基线）→ 验证增强（工程加成）→ 微调（SFT/GRPO/QLoRA）→ 模型升级（最贵）**。本章给出提示词模板与微调路线图。

## 1. 规划器能力的四条路径

| 路径 | 成本 | 提升幅度 | 适用 |
|---|---|---|---|
| 提示词工程 | 低（人时） | 中 | 所有项目（基线） |
| 验证增强 | 低（代码） | 高（VOLTS：7%→76%） | 所有项目（必做） |
| 微调（SFT/GRPO/QLoRA） | 中（数据+GPU） | 高（MagicAgent：超 GPT-5.2） | 场景固定、批量大 |
| 换更强模型 | 高（调用费） | 中（PlanningBench：GPT-5.4 63%） | 预算充足 |

> 🎯 核心要点：**ROI 排序是"验证增强 > 提示词 > 微调 > 换模型"**——VOLTS 证明小模型+验证能反超 GPT-4o 十倍（76% vs 7%），先工程后模型。

## 2. 规划提示词模板（生产可用）

```text
你是一名资深规划师。将用户目标分解为可执行步骤。

【硬性规则】
1. 只使用提供的工具清单中的工具，禁止编造
2. 每步是单个可执行动作，总步数不超过 {max_steps}
3. 每步包含：summary(做什么)、tool(工具名)、params(参数)、
   depends_on(依赖步骤)、success_criteria(完成判定)
4. 把约束写进涉及的步骤（约束：{constraints}）
5. 最后一步直接产出最终答案
6. 输出严格 JSON（schema 见下），不输出任何其他内容

【工具清单】
{tools_schema}

【目标】
{goal}

【上下文】
{context}
```

| 要素 | 作用 |
|---|---|
| 工具清单约束 | 防动作 schema 幻觉（06 篇） |
| 成功标准 | 每步可验证（06 篇） |
| 约束下放 | 防耦合约束失败（02 篇） |
| 步数上限 | 粒度纪律 |
| JSON 契约 | 衔接 Output Parser（03 篇） |

## 3. 微调路线：三种方法对比

| 方法 | 原理 | 数据需求 | 效果（2026 实测） |
|---|---|---|---|
| SFT | 监督微调（规划样本） | 数千条 | 基础提升 |
| SFT + GRPO | 强化学习（执行奖励） | SFT 基础上 | Planner 工具选择 SOTA（AAAI 2026） |
| QLoRA | 4bit 低秩微调 | ~1700 例 | 描述免推理、输入 -82.6%（Gemma E4B） |

| 微调收益 | 说明 |
|---|---|
| 规划质量 | 工具选择/分解准确率提升 |
| 成本下降 | 小模型替代大模型（QLoRA：Qwen3-4B 省 62% 内存/快 2.5 倍） |
| 描述免推理 | 工具知识内化到权重（无需工具目录进提示词） |
| 场景特化 | 固定业务域的规划模式固化 |

## 4. 微调数据从哪来

| 数据源 | 做法 |
|---|---|
| 真实轨迹 | 生产日志（规划→执行→结果）筛选成功样本 |
| 合成数据 | LLM 生成规划样本（PlanningBench 可扩展生成） |
| 验证过滤 | 只留"验证通过"的样本（RL 训练信号稳定） |
| 失败样本 | 错误规划 + 修正后正确规划（DPO 偏好对） |

> 💡 2026 关键实践：**用可验证数据做 RL 训练信号**（PlanningBench 实证：确定性最优解的 RL 提升泛化）——"验证器产出训练标签"是规划微调的数据工程核心。

## 5. 规划器选型决策树

```text
预算有限？→ 提示词 + 验证增强（先用，多数场景够）
场景固定 + 批量大？→ QLoRA 小模型微调（降本）
质量要求极高 + 有标注团队？→ SFT+GRPO 专训规划器
预算充足 + 快速验证？→ 前沿模型（GPT-5.x 等）
```
| 信号 | 选型 |
|---|---|
| 首计划成功率 <60% 且提示词已优化 | 考虑微调 |
| 场景每年变 | 不微调（微调数据会过时） |
| 规划调用量大（>10 万/月） | 微调降本（小模型） |
| 工具经常新增 | 提示词路线（微调要重训） |

## 6. 规划器工程化的完整清单

```text
□ 提示词：工具约束 + 成功标准 + 约束下放 + JSON 契约
□ 验证增强：工具注册表校验 + 状态机 + 约束检查（06 篇）
□ 评测集：自建 30-60 任务 + 首计划成功率基线（07 篇）
□ 监控：重规划率、无效动作率、成本/任务（07 篇指标）
□ 微调决策：场景固定性 + 批量 + 基线成绩三问
□ 数据管线：真实轨迹 + 合成 + 验证过滤
□ 回归：微调后跑同一评测集（防退化）
```

> 🎯 核心要点：规划器工程化的次序是**"提示词打底 → 验证增强加持 → 评测定基线 → 微调按需"**——不要跳过前两步直接微调（微调在"错误基线上"只会固化错误）。

## 7. 常见坑速查

| 坑 | 现象 | 解法 |
|---|---|---|
| 跳过验证直接微调 | 固化错误模式 | 先验证增强 |
| 微调数据不过滤 | 错误样本训练 | 验证过滤 |
| 场景变化还微调 | 数据过时 | 评估场景稳定性 |
| 工具新增不重训 | 新工具不会用 | 提示词兜底 + 定期重训 |
| 微调后不回归 | 通用能力退化 | 双评测集 |
| QLoRA 全量重训 | 浪费 | 只训规划头/适配器 |
| 提示词与微调脱节 | 双轨不一致 | 同契约同数据源 |

## 8. 微调成本账（决策参考）

| 项 | QLoRA 小模型 | SFT+GRPO 专训 | 前沿模型按需 |
|---|---|---|---|
| 数据成本 | 低（~1700 例） | 高（万级+标注） | 0 |
| GPU 成本 | 低（单卡 4bit） | 中-高 | 0 |
| 推理成本 | 低（省 62% 内存/快 2.5x） | 低 | 高（按 token） |
| 维护成本 | 中（重训） | 高（数据管线） | 低 |
| 质量 | 中-高（描述免推理） | 高（SOTA） | 高（GPT-5.4 63%） |
| 适合 | 场景固定+量大 | 质量天花板 | 快速验证/多变 |

> 💡 决策公式：**微调 ROI = 推理量 × 单次节省 / (数据+GPU+维护成本)**——推理量 <10 万/月时，微调通常不划算（提示词+验证增强先顶住）。

## 9. 微调常见误区

| 误区 | 真相 |
|---|---|
| "微调=换模型" | 微调是"场景特化"，通用能力交给基座 |
| "数据越多越好" | 验证过滤过的数据 > 海量脏数据 |
| "微调一次终身" | 场景/工具变化要重训（定期评估） |
| "小模型微调不如大模型" | QLoRA+验证可反超大模型（VOLTS） |
| "微调后不用评测" | 双评测集（场景+通用）防退化 |
| "跳过提示词直接微调" | 错误基线只会固化错误 |

## 10. 规划器工程化决策速查

| 场景 | 方案 |
|---|---|
| 项目启动（0-1） | 提示词 + 验证增强 + 自建评测集 |
| 质量瓶颈（首计划 <60%） | 先查分解/粒度 → 再考虑微调 |
| 成本瓶颈（调用量大） | QLoRA 小模型 |
| 质量天花板（业务高价值） | SFT+GRPO 专训 |
| 场景多变/工具常新增 | 提示词路线（微调不划算） |

## 11. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 规划器能力四条路？ | 提示词（基线）→ 验证增强（ROI 最高）→ 微调（场景特化）→ 换模型（最贵） |
| 微调三种方法？ | SFT（监督）、SFT+GRPO（执行奖励）、QLoRA（4bit 低秩小模型） |
| QLoRA 的收益？ | 描述免推理、输入 -82.6%、省 62% 内存快 2.5x |
| 微调数据从哪来？ | 真实轨迹 + 合成 + **验证过滤**（只留验证通过的样本） |
| 什么时候微调？ | 场景固定 + 批量大（>10 万/月）+ 基线低（首计划 <60%） |
| 微调前必做？ | 提示词 + 验证增强 + 评测基线——别在错误基线上微调 |
| 提示词六要素？ | 工具清单约束/成功标准/约束下放/步数上限/JSON 契约/收尾步骤 |
