# 规划器全景：规划在 Agent 中的角色

> 规划器是 Agent 的"参谋部"：把目标变成步骤。2026 年现状：规划是 Agent 最弱环节（长程退化、级联失败），但也是 ROI 最高的工程点——"分解与调整能力比单步准确率更决定任务完成率"（Mano-P 部署实证）。

## 1. 规划器的职责边界

| 职责 | 具体 | 非职责 |
|---|---|---|
| 任务分解 | 目标 → 步骤列表 | 不负责执行（执行器） |
| 依赖编排 | 步骤先后/并行关系 | 不负责结果判断（反思） |
| 计划维护 | 进度追踪/重规划 | 不负责上下文供给（记忆） |
| 成功标准 | 每步可验证的目标 | 不负责最终答案（大脑） |

> 🎯 核心要点：**规划器只回答"做什么、按什么顺序"**——"怎么做"交给执行器，"做得对不对"交给反思，"做之前知道什么"交给记忆。职责不清的规划器会变成"第二个大脑"，造成决策混乱。

## 2. 规划 vs 决策：两个时间尺度的分工

| 维度 | 规划（Plan） | 决策（Act） |
|---|---|---|
| 时间尺度 | 任务级（秒-分钟） | 步骤级（毫秒-秒） |
| 频率 | 任务开始/重规划时 | 每轮循环 |
| 输出 | 步骤列表 | 单个动作 |
| 承担者 | 规划器（可独立模型） | 大脑（主决策） |

```text
分工模式：
  规划器出计划 → 大脑按计划逐轮决策 → 观察偏离 → 规划器重规划
  （规划管"全局路线"，决策管"当前一脚"）
```

| 分工错误 | 后果 |
|---|---|
| 规划器过度细化 | 计划 vs 现实漂移快（每步都要重规划） |
| 大脑无视计划 | 计划形同虚设（goal drift） |
| 无规划直接决策 | 长任务迷失（步骤多了记不住目标） |

## 3. 规划在 Agent 中的位置（2026 现状）

| 层面 | 现状 | 含义 |
|---|---|---|
| 窄域有界任务 | ✅ 生产可用 | 客服/查询/流水线类 |
| 长程任务 | ⚠️ 显著退化 | 多步依赖+环境变化 |
| 开放网页导航 | ❌ 14% vs 人类 78% | 远未成熟 |
| 多 Agent 协调规划 | ❌ 12-24 个月 | 研究阶段 |

> ⚠️ Gartner 警示：**>40% Agentic 项目 2027 前将被取消，规划不可靠是核心驱动因素**——规划器不是"锦上添花"，是项目成败的命门。

## 4. 规划的三种粒度（按任务选）

| 粒度 | 计划形态 | 适用 | 成本 |
|---|---|---|---|
| 粗粒度 | 3-5 个阶段 | 长任务（阶段内自由发挥） | 低 |
| 中粒度 | 8-12 个步骤 | 标准任务（默认） | 中 |
| 细粒度 | 20+ 步骤 | 流水线/确定性任务 | 高（易漂移） |

> 🎯 核心要点：**规划粒度要与任务的不可预知性成反比**——任务越不可预知，计划越要粗（细计划会迅速过时）；任务越可预知，计划越可细（流水线类）。

## 5. 规划器的三种形态

| 形态 | 实现 | 适合 |
|---|---|---|
| 内联规划（ReAct 式） | 大脑每轮"想一步" | 短任务（≤3 步） |
| 显式规划器 | 独立规划模型/提示词 | 长任务（默认） |
| 混合（Plan+Act） | 规划器出阶段 + 大脑细化 | 复杂任务（最优） |

> 💡 显式规划器的核心收益：**规划与执行分离后可以独立优化**——规划器用强模型（1-2 次调用），执行器用便宜模型（N 次调用）——"成本下降、质量不降"（2026 共识）。

## 6. 规划失败的代价（为什么值得专门研究）

| 失败 | 代价 |
|---|---|
| 级联失败 | 早期一步错 → 后续全错（无回滚） |
| 进度误判 | 提前终止（活没干完）或冗余循环（白烧钱） |
| 动作幻觉 | 貌似合理实则错误的动作序列 |
| 重规划成本 | 每次重规划 1-2 次 LLM 调用 |

> 🎯 核心要点：**规划错误是"放大器"**——一步规划错，浪费 N 步执行。规划器的工程价值 = 避免"执行了 10 步才发现第 2 步就错了"。

## 7. 规划器的输入输出契约

| 输入 | 说明 |
|---|---|
| 目标（goal） | 用户任务描述（结构化） |
| 上下文（context） | 记忆注入（用户/历史/约束） |
| 工具清单 | 可用工具及 schema（规划的"零件"） |
| 约束（constraints） | 预算/时间/资源限制 |

| 输出 | 说明 |
|---|---|
| 步骤列表 | step/summary/action/tool |
| 依赖关系 | 先后/并行（DAG） |
| 成功标准 | 每步可验证目标 |
| 终止条件 | 完成判定 |

> 💡 规划契约的 schema 化（JSON）是规划器与[Output Parser 输出解析器](../Output%20Parser%20输出解析器/00-OutputParser输出解析器总览.md)体系的接口——计划即输出，也要走"strict + 校验 + 失败修复"全流程（03 篇详述）。

## 8. 常见误区

| 误区 | 真相 |
|---|---|
| "规划器=第二个大脑" | 规划只管步骤与顺序，决策仍是大脑的 |
| "计划越细越好" | 细计划在不可预知任务上迅速过时 |
| "有规划就不用 ReAct" | 短任务（≤3 步）规划是负收益 |
| "规划失败是模型不行" | 多数是验证缺失（VOLTS：验证让小模型反超） |
| "一次规划一劳永逸" | 计划是假设，重规划是常态 |
| "规划器要最贵模型" | 规划 1-2 次调用贵可接受，执行器才要便宜 |

## 9. 规划器成熟度模型

| 成熟度 | 分解 | 验证 | 重规划 | 评测 |
|---|---|---|---|---|
| L1 | 内联（ReAct 式） | 无 | 无 | 无 |
| L2 | 显式计划 JSON | 工具校验 | 有（全量重写） | 人工 |
| L3 | 粒度匹配+约束下放 | 验证增强 | 力度分级+锚定 | 自建集 |
| L4 | 混合（ReWOO+动态） | 全量验证链 | 预算内自适应 | 轨迹级+CI |

**判断你的规划器在几级**：三问——① 计划能验证吗？（L1 不能）② 重规划会漂移吗？（L2 会）③ 评测测过程吗？（L3 才测轨迹）。对外产品至少 L3。

## 10. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 规划器是什么？ | 目标→步骤的分解器，只管"做什么、按什么顺序" |
| 规划 vs 决策？ | 规划管任务级路线，决策管步骤级动作 |
| 规划器最怕什么？ | 级联失败（一步错步步错）——靠验证防 |
| 2026 规划现状？ | 长程退化明显，窄域可用；Gartner >40% 项目取消 |
| 规划器要独立模型吗？ | 规划 1-2 次调用用强模型，执行器便宜模型（成本最优） |
| 什么时候不需要规划器？ | 短任务（≤3 步），ReAct 直想更省 |
| 规划器成熟度速查？ | L1 能跑 → L2 能稳（验证）→ L3 能优（重规划+评测）→ L4 能证（轨迹 CI） |
| 规划器投入顺序？ | 验证增强 > 分解质量 > 模式选型 > 评测回归 > 微调——别把可靠性押在换模型上 |
