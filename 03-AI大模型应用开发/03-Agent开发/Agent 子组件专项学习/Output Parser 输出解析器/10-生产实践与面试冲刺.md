# 生产实践与面试冲刺

> 从"能解析"到"可靠解析"：语义级评测、模式矩阵、12 避坑、面试题与落地检查单——输出解析器体系收官篇。

## 1. 评测：从解析率到语义质量（2026 范式）

### 1.1 评测维度

| 维度 | 测什么 | 说明 |
|---|---|---|
| Schema 合规率 | 输出符合 schema 的比例 | strict 下应近 100%（不是终点） |
| 字段级语义分 | 每个字段的值正确率 | **真正的质量指标**（2026 转向） |
| 完整性 | 字段缺失率（schema 过但空） | 静默失败检测 |
| 枚举合规 | 枚举值正确率 | 合规≠正确 |
| 重试率 | 失败后重试占比 | 成本审计（被头榜掩盖） |
| 端到端 | 消费端正确率 | 最终检验 |

> ⚠️ 2026 关键警示：**"99.5% 解析率 + 枚举坍缩"劣于"96% 解析率 + 诚实答案"**——别把 schema 合规率当成功标准（FutureAGI 评测结论）。

### 1.2 模式矩阵（按模式对比而非按模型）

```text
同一批 200 条生产轨迹 → 分别在以下模式跑：
  OpenAI strict / 普通 JSON / Anthropic tool use / Gemini responseSchema
  → 矩阵对比：schema 合规 + 语义分 + 重试率
  → 找出"静默失败格"：schema 合规但语义分低（最危险）
```

| 模式 | schema 合规 | 语义分 | 重试率 |
|---|---|---|---|
| strict | 高 | ？ | 低 |
| 普通 JSON | 中 | ？ | 中 |
| tool use | 中 | ？ | 中 |

> 💡 模式矩阵的价值：**同模型不同模式差异显著**——选"模式"与选"模型"同等重要；跨提供商无平价假设（OpenAI strict 好用 ≠ Gemini 同样）。

### 1.3 评测协议固定

| 协议项 | 固定 |
|---|---|
| 判题提示词 | 同一条 |
| 判题模型 | 同一个 |
| 采样参数 | temperature=0 |
| 测试集 | 镜像生产 schema 复杂度（50 字段嵌套也要测） |

## 2. 生产基线（输出解析器）

| 领域 | 基线 |
|---|---|
| 格式 | strict 模式默认；无 strict 用提示词+修复 fallback |
| 校验 | schema + 业务 + 安全三层 100% 覆盖 |
| 失败 | 分类先行；修复 ≤2 次；重试 ≤3 次带反馈 |
| 流式 | 决策攒完再解析；渲染部分解析；最终校验兜底 |
| 契约 | 语义命名 + 枚举兜底 + 版本化 |
| 成本 | 重试率监控；单任务解析成本上限 |
| 评测 | 模式矩阵 + 语义分 + 自建集回归 |

## 2.1 演进趋势（2026-2027）

| 趋势 | 现状 | 影响 |
|---|---|---|
| strict 普及化 | 采样级约束成默认 | 解析率不再是问题，语义成焦点 |
| 语义评测上位 | 字段级打分替代解析率 | 评测体系重建 |
| 流式结构化 | 补丁协议/部分解析成熟 | 实时 UI 驱动结构化输出 |
| 探针测试制度化 | 厂商强制力验证成标配 | "兼容≠同能力"落地 |
| 契约工程化 | schema+规则+描述一体化 | 契约即文档 |
| 多模态结构化 | 图像/音频输出结构约束 | 解析器扩展 |

> 💡 对工程师的启示：**2026-2027 的解析器投资顺序**——语义校验与评测 > 失败处理闭环 > 流式体验 > 契约简化。格式问题（strict）已被采样层解决大半，剩余价值在"数据对不对、失败好不好救"。

## 3. 12 避坑清单

| # | 坑 | 后果 | 解法 |
|---|---|---|---|
| 1 | 只解析不校验 | 静默错误 | 三层校验 |
| 2 | 把解析率当质量 | 枚举坍缩不察 | 语义评测 |
| 3 | 盲目重试 | 重试风暴 | 失败分类（refused/truncated 不重试） |
| 4 | strict 当免校验 | 语义错漏 | strict+校验双层 |
| 5 | 兼容厂商当真 strict | 违规输出通过 | 探针测试 |
| 6 | 顶层数组 | strict 拒绝 | 包 object |
| 7 | 可选字段写 required | schema 被拒 | null union |
| 8 | 流式 chunk 直接 parse | 抛异常 | 累积/部分解析 |
| 9 | 工具参数不回传错误 | 模型重复错 | tool 消息回传 |
| 10 | 大契约硬上 | 准确率暴跌 | 拆分 |
| 11 | 契约变更不回归 | 消费端坏 | 版本化+评测集 |
| 12 | 输出当指令 | 注入执行 | 分域原则 |

## 4. 面试题（高频 12 题 + 答题要点）

| 题 | 答题要点 |
|---|---|
| 1. 结构化输出怎么保证？ | strict 模式（采样层约束：必填/类型/枚举/嵌套）；无 strict 用 tool use 强制或提示词+修复 fallback |
| 2. strict 和 JSON mode 区别？ | JSON mode 只保证合法 JSON；strict 保证 schema 合规（约束解码） |
| 3. strict 的 schema 有什么限制？ | 全字段必填（null union 表达可选）、顶层 object、additionalProperties:false、≤5 层嵌套、无重叠 union |
| 4. 模型输出错了怎么办？ | 失败分类（refused/partial/truncated/degraded）→ 修复工具 → 反馈重试 → fallback 链 → 错误契约 |
| 5. 流式 JSON 怎么解析？ | 攒完再解析（决策）/修复流/部分解析（渲染）；按 index 累积工具参数 |
| 6. 各家 strict 差异？ | OpenAI 采样级；Anthropic tool use 提示词级；Gemini responseSchema 有 union 缺陷；兼容厂商实测为准 |
| 7. 工具参数怎么解析？ | tool_calls 按 index 累积 arguments → 完整后 parse → schema+业务校验 → 错误回传闭环 |
| 8. strict 下并行调用？ | 并行失效（规范限制）——需要时关 strict 或批量参数 |
| 9. 校验和解析的区别？ | 解析管语法（文本→对象）；校验管语义（对象→正确性）；strict 保格式不保正确 |
| 10. 输出注入怎么防？ | 输出当数据不当指令；前端转义；工具参数化；入库消毒 |
| 11. 评测解析器质量？ | 语义分 > 解析率；模式矩阵（strict/JSON/tool use）；镜像生产复杂度；协议固定 |
| 12. 契约怎么设计？ | 语义命名+描述、枚举+unknown 兜底、拆分大契约、版本化、契约与校验同文件 |

## 5. 落地检查单（上线前逐项打勾）

```text
□ strict 默认开启（不支持时 fallback 链就位）
□ 三层校验 100% 覆盖（schema/业务/安全）
□ 失败分类器就位（refused/truncated 不盲目重试）
□ 反馈重试（错误回传带 hint）≤3 次
□ 流式策略按输出类型选择（决策攒完/渲染部分解析）
□ 工具参数累积 + 校验 + 错误回传闭环
□ 契约：语义命名/枚举兜底/版本化
□ 模式矩阵评测（至少 OpenAI strict + 一个 fallback）
□ 重试率与解析成本监控
□ 探针测试（故意错误 schema 验证强制力）
□ 跨用户/跨敏感内容安全测试
□ 消费端（前端/数据库）契约一致性确认
```
