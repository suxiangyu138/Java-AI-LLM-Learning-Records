# 框架中的输出解析器

> 框架把"解析-校验-类型化"打包成一行 API：Pydantic/Zod schema 自动推导、类型安全输出。但框架封装不解决语义正确性——"框架给管道，业务给校验"。

## 1. 框架解析器的能力全景

| 能力 | 说明 |
|---|---|
| Schema 推导 | Pydantic/Zod 模型 → JSON Schema 自动生成 |
| 类型化输出 | 解析结果直接是类型化对象（非裸 dict） |
| 重试封装 | 解析失败自动重试（带反馈） |
| Strict 集成 | 框架层透传 strict 配置 |
| 流式支持 | 部分框架支持流式对象（AI SDK streamObject） |

> 🎯 核心要点：框架解析器的价值是**"省掉样板代码 + 类型安全"**——但"值对不对"从来不是框架的职责，是业务校验的职责。

## 2. LangChain：PydanticOutputParser 家族

```python
from langchain.output_parsers import PydanticOutputParser
from langchain_core.pydantic_v1 import BaseModel, Field
from langchain_core.prompts import PromptTemplate

class Order(BaseModel):
    order_id: str = Field(description="订单号")
    amount: float = Field(description="金额")
    status: str = Field(description="状态", enum=["paid", "pending"])

parser = PydanticOutputParser(pydantic_object=Order)   # schema 自动推导
prompt = PromptTemplate(
    template="解析订单：{input}\n{format_instructions}",   # 指令自动注入
    input_variables=["input"],
    partial_variables={"format_instructions": parser.get_format_instructions()})

chain = prompt | llm | parser        # 输出直接是 Order 对象
```

| LangChain 解析器 | 用途 |
|---|---|
| PydanticOutputParser | 类型化输出（主流） |
| JSONOutputParser | 纯 JSON（无类型） |
| StructuredOutputParser | 轻量 schema |
| CommaSeparatedListOutputParser | 列表 |
| 框架级 `.with_structured_output()` | 现代推荐（自动走 strict 当支持时） |

> 💡 现代用法：`llm.with_structured_output(Order)`——LangChain 自动选 strict 模式（支持时）或提示词 fallback，比手拼 OutputParser 更省心。

## 3. Spring AI / LangChain4j（Java 侧）

```java
// Spring AI：结构化输出（Structured Output）
record Order(String orderId, double amount, String status) {}

StructuredOutput<Order> output = chatClient.prompt()
    .user("解析订单：...")
    .call()
    .entity(Order.class);          // 类型化输出（内部 JSON → record）

// 失败处理：Resilience4j 重试 + 业务校验
Order order = retryTemplate.execute(
    () -> chatClient.prompt().user(q).call().entity(Order.class));
```

```java
// LangChain4j：@UserMessage + 类型化返回
public record Order(String orderId, double amount, String status) {}

@AiService
interface OrderParser {
    Order parseOrder(@UserMessage String text);
}
```

| Java 侧要点 | 说明 |
|---|---|
| record 即契约 | Java 17 record 定义输出结构 |
| 校验分层 | 框架管解析，JSR 380/手动校验管语义 |
| 重试 | Resilience4j 封装（防重试风暴） |
| 流式 | 末尾解析（Java 生态流式结构化较少） |

## 4. 框架解析器的局限（2026 实测认知）

| 局限 | 表现 | 解法 |
|---|---|---|
| 不保证语义 | schema 过但值错 | 业务校验（08 篇） |
| 重试可能盲目 | 框架默认重试无反馈 | 自定义重试策略（04 篇） |
| 大 schema 退化 | 50 字段嵌套准确率暴跌 | 契约简化（09 篇） |
| 跨模型不一致 | 换模型行为变 | 按模式评测（10 篇） |
| 错误信息含糊 | "解析失败"无细节 | 错误契约 + 日志 |

> ⚠️ 框架封装最大的坑：**"with_structured_output 一下就好了"的错觉**——框架内部的重试/fallback 不可见，失败被静默吞掉。上线前必须做"故意输出错误"的探针测试，确认框架行为符合预期。

## 5. 框架解析器的监控

| 指标 | 信号 |
|---|---|
| 解析失败率（分模式） | 升高 → 模型/提示词退化 |
| 重试率 | 升高 → 首生成质量下降 |
| 语义校验通过率 | 降低 → 契约与模型不匹配 |
| 类型转换错误 | 升高 → schema 定义问题 |
| 流式对象延迟 | 首对象时间 |

## 6. 选型速查

| 栈 | 推荐 |
|---|---|
| Python + LangChain | `with_structured_output(PydanticModel)` |
| Python 原生 | Pydantic + 手写解析（本体系组合） |
| TypeScript | Vercel AI SDK `generateObject/streamObject` + Zod |
| Java + Spring AI | `chatClient.call().entity(Record.class)` |
| Java + LangChain4j | @AiService 类型化返回 |

> 🎯 核心要点：框架解析器是"管道基础设施"——**schema 推导与类型化省 80% 样板代码，但语义校验、失败分类、重试预算这三件事框架都不替你决定**。框架 + 本体系组合 = 完整方案。

## 7. 常见坑速查

| 坑 | 现象 | 解法 |
|---|---|---|
| 依赖框架重试 | 盲目重试风暴 | 自定义反馈重试 |
| 忽略语义校验 | schema 过值错 | 业务校验必接 |
| 大契约硬塞 | 准确率暴跌 | 契约简化拆分 |
| 换模型不回归 | 解析行为变 | 模式评测矩阵 |
| 错误被吞 | 静默失败 | 错误契约透出 |
| 流式末尾不校验 | 流式数据带错 | 最终校验兜底 |

## 8. 框架内部机制：with_structured_output 的五步

```text
① schema 推导：Pydantic/Zod 模型 → JSON Schema
② 模式选择：模型支持 strict → 用 response_format；否则提示词注入
③ 生成：按选定模式调用（strict 或提示词约束）
④ 解析：JSON → 类型化对象（Pydantic 校验 + 类型转换）
⑤ 返回：类型安全对象 or 抛解析异常（由上层重试）
```

| 框架隐藏细节 | 你需要做的 |
|---|---|
| 模式自动选择 | 探针确认所选模式真的强制 |
| 重试行为 | 确认重试是否带反馈（无则自定义） |
| 类型转换 | 确认转换规则（数字字符串？） |
| 异常类型 | 按错误类型分流（02 篇 9 节） |

> 💡 框架封装越"智能"，越要"知情"——**自动选模式可能选到不强制 strict 的路径**（如模型不支持时静默降级提示词）。生产配置应显式指定模式（strict: true 或明确 fallback），不依赖框架默认。

## 9. 多框架对比速查（2026-08）

| 维度 | LangChain | Spring AI | LangChain4j | AI SDK (TS) |
|---|---|---|---|---|
| 类型化 | Pydantic | record | record | Zod |
| Strict 集成 | with_structured_output | 透传 | 透传 | generateObject |
| 流式对象 | 无（自行组装） | 无 | 无 | **streamObject** |
| 重试 | 外部封装 | Resilience4j | 外部 | 外部 |
| 错误契约 | 异常 | 异常 | 异常 | 异常 |

> 🎯 核心要点：框架解析器是"80% 样板代码的消灭者"，但**模式选择、语义校验、失败分类、流式策略这四件事要显式掌控**——"框架替我解析了"是最危险的放松。框架内建的解析器适合标准场景；深度定制（错误契约、教训记忆化）建议在框架外自建一层解析壳，框架只负责生成——"框架生成 + 自建解析"是 2026 生产常见组合。判断是否自建解析壳：问"我需要错误契约回传吗？需要教训记忆化吗？"——任一为是，就在框架外加壳。
