# 过程奖励模型与前沿

> 反思的前沿从"事后自评"走向"过程打分"：**PRM（过程奖励模型）**给每一步打分，而非只评结果。2026 年实证：结果奖励太稀疏（多步场景仅 66.77% 准确）——步骤级反馈是长任务反思的破局方向。

## 1. ORM vs PRM：结果 vs 过程

| 维度 | ORM（结果奖励） | PRM（过程奖励） |
|---|---|---|
| 打分对象 | 最终结果 | 每一步骤 |
| 反馈粒度 | 稀疏（任务结束时） | 密集（每步可纠） |
| 长任务表现 | 弱（66.77% 准确率） | 强（步骤级定位） |
| 训练信号 | 结果对错 | 步骤对错（需标注/推理） |
| 反思用途 | 事后总结 | **步骤级即时纠正** |

> 🎯 核心要点：PRM 的价值是**"在错误发生的那一步就喊停"**——而不是任务结束后说"你第 3 步错了"。长任务（10+ 步）是 PRM 的主场。

## 2. 2026 PRM 体系

| 模型/基准 | 能力 |
|---|---|
| AgentPRM（NeurIPS 2025） | 每步双指标：Promise（离目标多近）+ Progress（比现状进步多少） |
| ThinkPRM | "思考验证器"（验证推理步骤） |
| ToolPRMBench | 工具使用场景的 PRM 评测标准化 |
| ORM 局限 | 多步 Agentic RAG 场景仅 66.77% 准确（太稀疏） |

```text
AgentPRM 双指标的意义：
  Promise = "这一步在朝目标推进吗"（方向性）
  Progress = "这一步比上一步好吗"（增量性）
  两个维度分开打分 → 批评更精准（"方向对但没推进" vs "推进了但方向偏"）
```

## 3. PRM 与反思的整合

```text
PRM 驱动的反思循环：
  执行步骤 → PRM 打分（promise/progress）→ 低分步骤
  → 精准批评（"第 3 步 promise 低：查询条件可能错误"）
  → 局部重做该步（不重做全任务）→ 再打分
  —— 反思从"任务级重来"变成"步骤级纠偏"
```

| 整合收益 | 说明 |
|---|---|
| 定位精准 | 批评指向具体步骤（非泛泛） |
| 成本节约 | 只重做低分步骤（非全任务） |
| 即时性 | 每步可干预（非事后） |

## 4. LATS：树搜索 + 反思（复杂决策前沿）

| 要素 | 说明 |
|---|---|
| 机制 | MCTS 树搜索 + 失败轨迹反思 |
| 反馈 | 环境 + 树探索（多路径） |
| 优势 | 单轨迹反思 vs 多路径探索（更优） |
| 代价 | 计算成本远高（多路径 × 每路径步骤） |

> 💡 LATS 的选型判据：**"试错成本低 + 结果价值高"才值得树搜索**——探索型任务（研究/调试）适合；流水线任务（确定性）用单轨迹反思即可。

## 5. 反思前沿的演进主线

```text
2023 Reflexion（语言批评+记忆）
  → 2024 Self-Refine（自我批评）→ 实证：自我修正会下降
  → 2025 CRITIC（外部知识）→ LATS（树搜索）
  → 2025-2026 PRM（过程奖励，步骤级）
  → 2026 多智能体（MARS 角色评判/ReTAS 视角对齐）
  主线：反馈越来越外部、越来越细粒度、越来越结构化
```

| 演进维度 | 方向 |
|---|---|
| 反馈来源 | 内部 → 外部（工具/多智能体） |
| 反馈粒度 | 结果 → 步骤（PRM） |
| 反馈形式 | 自由文本 → 结构化（token/评分） |
| 反思主体 | 单 Agent → 多 Agent（角色/视角） |

## 6. 前沿技术的落地判断

| 技术 | 成熟度 | 生产建议 |
|---|---|---|
| PRM 自训 | 研究-早期 | 有标注团队可试（长任务场景） |
| 现成 PRM | 少 | 用 AgentPRM 系开源模型 |
| LATS | 研究 | 高价值探索任务才用 |
| MARS 多评判 | 研究-早期 | 高价值任务抽样用 |
| 级联+外部验证 | 成熟 | **生产默认**（06/09 篇） |

> 🎯 核心要点：**前沿 ≠ 生产**——PRM/LATS/MARS 是高价值场景的"进阶选项"，生产的默认仍是"级联 + 外部验证 + 独立评判器"（06/09 篇）——先把成熟手段用足，再上前沿。

## 7. 常见坑速查

| 坑 | 现象 | 解法 |
|---|---|---|
| 结果奖励当过程 | 长任务反馈稀疏 | PRM 步骤级 |
| PRM 未训练就上 | 打分不准 | 验证 PRM 校准 |
| LATS 无预算 | 成本爆炸 | 限量/高价值才用 |
| 多智能体无角色 | 反馈同质 | 角色感知（MARS） |
| 前沿当默认 | 复杂度失控 | 成熟手段先用足 |
| PRM 与反思脱节 | 打了分不改 | 低分步骤闭环 |
| 忽略 ORM 局限 | 66.77% 假象 | 长任务用 PRM |

## 8. PRM 落地五步

| 步骤 | 做法 |
|---|---|
| ① 任务选型 | 长任务（10+ 步）才需要 PRM（短任务 ORM 够） |
| ② 数据标注 | 步骤级标注（对/错/方向）或 LLM 推理标注 |
| ③ 训练 | 步骤级奖励模型（AgentPRM 双指标风格） |
| ④ 校准 | 验证 PRM 打分与真实结果一致率 |
| ⑤ 整合 | 低分步骤 → 精准批评 → 局部重做（反思闭环） |

```text
PRM 的成本账：
  标注成本（步骤级标注 > 结果级）
  训练成本（奖励模型训练）
  收益：长任务纠错精准 + 避免全任务重做
  判据：任务越长、重做越贵 → PRM 越值
```

## 9. 前沿选型速查

| 需求 | 选型 |
|---|---|
| 长任务步骤级反馈 | PRM（AgentPRM 风格） |
| 探索型复杂决策 | LATS（树搜索） |
| 多视角批评 | PR-CoT（提示词级） |
| 多智能体评判 | MARS（角色集成） |
| 视角一致性 | ReTAS（辩证对齐） |
| 评判器自我进化 | CoNL（元评估） |

## 10. 面试速记

| 问题 | 一句话答案 |
|---|---|
| PRM vs ORM？ | 过程奖励（步骤级）vs 结果奖励（稀疏，多步仅 66.77%） |
| AgentPRM 双指标？ | Promise（离目标多近）+ Progress（比现状进步多少） |
| PRM 与反思整合？ | 低分步骤 → 精准批评 → 局部重做（不重做全任务） |
| LATS 是什么？ | MCTS 树搜索 + 失败轨迹反思（多路径，贵） |
| 前沿演进主线？ | 反馈越来越外部/细粒度/结构化（Reflexion→CRITIC→PRM→多智能体） |
| 前沿怎么落地？ | 先成熟手段（级联+外部验证）用足，前沿按价值上 |
| ORM 局限量化？ | 多步 Agentic RAG 场景仅 66.77% 准确——结果级信号太稀疏 |
| PRM 与 Planner 衔接？ | PRM 步骤打分 = Planner 步骤状态机的"质量维度"（成功标准 + 打分） |
| PRM 数据从哪来？ | 步骤级标注（人工/LLM 推理）+ 执行反馈（自动）——标注成本是主要门槛 |
| PRM 的失败模式？ | 打分偏差（奖励黑客）——校准测试 + 与真实结果对比 |
| 前沿落地判据？ | 任务长度 × 重做成本 × 价值——三高才上前沿（PRM/LATS） |
| PRM 与 ORM 的选型？ | 短任务（≤5 步）ORM 够；长任务（10+ 步）PRM 才值 |
| PRM 评测？ | 校准测试（PRM 打分 vs 真实结果一致率）+ ToolPRMBench 类基准 |
| PRM 与 Planner 成功标准？ | PRM 打分可作 success_criteria 的"软版本"（步骤级质量信号） |
| 前沿的工程门槛？ | 数据标注（PRM）/ 算力（LATS）/ 多模型（MARS）——按资源选 |

## 8.5 前沿技术决策表

| 场景 | 技术 | 判断依据 |
|---|---|---|
| 长任务步骤纠错 | PRM | 任务 ≥10 步 + 重做贵 |
| 探索型决策 | LATS | 试错成本低 + 结果价值高 |
| 事实幻觉 | CRITIC/检索验证 | 知识密集 |
| 多视角批评 | PR-CoT | 需要全面性 |
| 多智能体评判 | MARS | 高价值任务 + 预算足 |
| 评判器训练 | CoNL | 无外部基准 |
