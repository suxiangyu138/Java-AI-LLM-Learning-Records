# 反思触发与轮次控制

> 反思的成本是 LLM 调用——触发时机与轮次上限决定"花多少赚多少"。2026 年实证：**第 1 轮捕获 70-80% 的改进，第 5 轮进入过优化**——默认 2-3 轮 + 最佳版本回滚。

## 1. 触发时机：什么时候启动反思

| 触发 | 说明 | 频率 |
|---|---|---|
| 失败后 | 测试不过/工具报错 | 按失败 |
| 里程碑 | 每 N 步小结 | 固定节奏 |
| 完成时 | 最终输出自评 | 每次（有 oracle 时） |
| 用户质疑 | 用户反馈"这不对" | 事件驱动 |
| 无触发（内嵌） | 模型自带 thinking | 持续（低成本） |

> 🎯 核心要点：**触发优先级 = "失败优先、完成次之、节奏兜底"**——失败后反思（有针对性的问题）ROI 最高；完成时自评只在有 oracle 时做（否则是自我安慰）。

## 2. 轮次控制：2-3 轮是甜蜜点

| 轮次 | 收益（2026 实证） |
|---|---|
| 第 1 轮 | 捕获 70-80% 可达改进（最高 ROI） |
| 第 2 轮 | 边际改进（少量） |
| 第 3 轮 | 接近持平 |
| 第 5 轮 | **过优化开始**（编造风格问题，真实问题耗尽后） |
| 无上限 | 比 2 轮循环更差（无限漂移/过度编辑） |

```text
轮次控制设计：
  max_rounds = 2-3（默认）
  早期退出：评判 pass → 立即停止
  最佳版本回滚：每轮存 best_version，最终返回 best（防退化）
  分数回退检测：score 下降 → 回滚并停止
```

```python
def reflect_loop(prompt, draft, critic, max_rounds=3):
    best = {"version": draft, "score": -1}
    for i in range(max_rounds):
        critique = critic(draft)
        if critique.verdict == "pass":
            return draft                     # 早期退出
        draft = revise(prompt, draft, critique)
        score = critic(draft).score
        if score > best["score"]:
            best = {"version": draft, "score": score}   # 最佳版本跟踪
        elif score < best["score"] - 0.05:
            return best["version"]           # 分数回退 → 回滚
    return best["version"]                   # 上限 → 返回最佳
```

## 3. 级联反思：便宜检查先行（省 50-80%）

```text
级联链（省钱核心）：
  ① 规则检查（正则/schema）→ 过 → 无需反思
  ② 小模型检查 → 过 → 无需反思
  ③ 大模型评判 → 过 → 收尾
  ④ 反思修订 → 重新验证
  只有"便宜层不过"才升级——大部分输出在第 1-2 层就过了
```

| 级联层 | 成本 | 通过率假设 |
|---|---|---|
| 规则检查 | ~0 | 60%（表层错误） |
| 小模型检查 | 低 | 25% |
| 大模型评判 | 高 | 10% |
| 反思修订 | 最高 | 5%（真正需要） |

> 💡 级联的本质：**"多数输出不需要反思"**——反思只留给真正失败的小尾巴。实测可省 50-80% 反思成本。

## 4. 回滚机制：反思的"后悔药"

| 回滚场景 | 机制 |
|---|---|
| 修订后分数下降 | 返回上一版（best-version 跟踪） |
| 修订引入新错误 | 版本对比 + 差异审查 |
| 非重置任务（已发邮件） | 不可回滚 → 反思前置（行动前反思） |
| 多轮漂移 | 回到第 1 轮版本 |

> ⚠️ 非重置任务（sent email/已写入数据库）**不能用重试式反思**——这类任务要么反思前置（行动前自评），要么行动后轻量自评（不重做）。

## 5. 反思预算

| 项 | 默认 | 防什么 |
|---|---|---|
| max_rounds | 2-3 | 过优化 |
| 反思成本/任务 | 上限 | 成本失控 |
| 触发冷却 | 连续失败才升级 | 每步都反思 |
| 级联层 | 先便宜后贵 | 大模型浪费 |
| 回滚 | best-version | 退化 |

## 6. 与重规划的轮次配合

| 场景 | 反思轮 | 重规划轮 |
|---|---|---|
| 单步失败 | 反思该步做法 | 不必重规划 |
| 连续失败 | 反思 + 重规划（换路） | 触发 |
| 计划漂移 | 反思策略 + 重规划路线 | 必触发 |

> 💡 配合原则：**先反思（改做法）再重规划（改路线）**——反思解决"怎么做"，重规划解决"做什么"；反思 2 轮无效再重规划（Planner 05 篇衔接）。

## 7. 常见坑速查

| 坑 | 现象 | 解法 |
|---|---|---|
| 无轮次上限 | 无限漂移 | max_rounds=2-3 |
| 无回滚 | 好版本被改坏 | best-version |
| 每步都反思 | 成本爆炸 | 触发纪律+级联 |
| 非重置任务重试 | 已发邮件重发 | 反思前置 |
| 反思不落地 | 批评了没改 | 强制修订 |
| 无早期退出 | pass 了还循环 | verdict 分流 |
| 反思轮=重规划轮混 | 机制打架 | 先反思后重规划 |

> 🎯 核心要点：轮次控制三件套——**上限（2-3 轮）+ 退出（pass 即停）+ 回滚（best-version）**——无上限的反思循环通常比 2 轮循环更差（2026 实证），"少而准"是反思的成本哲学。

## 8. 触发与轮次决策树

```text
输出完成
 ├─ 有 oracle（测试/标准）？→ 完成后验证 → 失败 → 反思（2-3 轮）
 ├─ 无 oracle 有独立评判器？→ 完成时评判 → fail → 反思（≤2 轮）
 ├─ 表层任务（格式）？→ 规则检查 → 过 → 不反思
 ├─ 短任务（≤3 步）？→ 不反思（成本 > 收益）
 └─ 非重置任务（已发邮件）？→ 反思前置（行动前自评）
```

| 分支 | 轮次 | 关键 |
|---|---|---|
| 有 oracle | 2-3 | 外部验证驱动 |
| 独立评判器 | ≤2 | 评判器校准过 |
| 规则检查 | 0-1 | 级联（09 篇） |
| 短任务 | 0 | 别加 |
| 非重置 | 前置 | 行动前自评 |

## 9. 轮次控制案例走查

```text
任务：生成一段带引用的分析（有检索 oracle）
① 草稿完成 → 级联：schema 检查 ✅（结构过）
② 检索验证：3 个引用中 1 个核验失败 → 触发反思（第 1 轮）
③ 反思：批评"引用 B 无法核验，建议替换" → 修订（换引用）
④ 重新验证：3/3 通过 → 早期退出（只花了 1 轮）
⑤ 返回修订版 + 记录：反思 1 轮、成本 1×评判+1×修订
—— 级联 + 早期退出让"需要反思的任务"只花 1 轮
```

## 10. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 反思什么时候触发？ | 失败后 > 完成时 > 里程碑——失败优先 ROI 最高 |
| 反思几轮最好？ | 2-3（第 1 轮 70-80% 收益，第 5 轮过优化） |
| 级联反思是什么？ | 规则→小模型→大模型→反思，便宜先过（省 50-80%） |
| 回滚机制？ | best-version 跟踪 + 分数回退即回滚 |
| 非重置任务？ | 反思前置（行动前自评），不能事后重试 |
| 反思与重规划？ | 先反思（改做法）再重规划（改路线），反思 2 轮无效才重规划 |
| 反思触发频率控制？ | 触发冷却 + 级联分层——"多数输出不需要反思"是省钱前提 |
| 反思轮次监控？ | 轮次分布（>3 轮占比）进仪表盘——上限失效的早期信号 |
| 反思前置场景？ | 非重置任务（已发邮件/已写入库）——行动前自评是唯一时机 |
| 反思触发五类？ | 失败后/里程碑/完成时/用户质疑/内嵌 thinking——"失败优先"ROI 最高 |
| 早期退出机制？ | verdict=pass 立即停止——"多数输出一轮都不用"是轮次控制的关键 |
| 与级联的关系？ | 轮次上限管"反思内循环"，级联管"是否进入反思"——两层各自设限 |

## 9.5 触发配置参考

| 配置项 | 默认 | 说明 |
|---|---|---|
| 失败触发 | 开启 | 工具失败/测试不过 |
| 完成时自评 | 仅 oracle 任务 | 无 oracle 关闭 |
| 里程碑小结 | 每 3-5 步 | 长任务开启 |
| 用户质疑 | 开启 | 事件驱动 |
| 内嵌 thinking | 按模型 | 推理模型自带 |

## 9.6 轮次与成本的关系

| 配置 | 每任务反思成本 | 收益 |
|---|---|---|
| 0 轮（无反思） | 0 | 基线 |
| 1 轮 | 1×评判 + 1×修订 | 70-80% 可达收益 |
| 2 轮 | 2×评判 + 2×修订 | +10-20% |
| 3 轮 | 3×评判 + 3×修订 | +5% 以内 |
| 5 轮 | 5×评判 + 5×修订 | **负收益**（过优化） |

> 💡 轮次-成本曲线是"反思性价比"的核心——**第 1 轮是最高性价比，第 3 轮后每轮都在亏**。配置 2-3 轮 + 早期退出 = 用 1.5-2 轮的平均成本拿 90%+ 收益。
