# 反思全景：自我修正的边界

> 反思 = Agent 评估自己的输出并改进。2026 年最重要的认知反转：**自我反思不可信**（同模型同盲区），可靠评估必须外部化。本章立起边界——什么时候反思有用、什么时候是自我安慰。

## 1. 反思的三组件架构

| 组件 | 职责 | 例子 |
|---|---|---|
| Actor（演员） | 生成输出/行动 | 写答案、调工具 |
| Evaluator（评判器） | 评估输出质量 | 跑测试/规则/LLM 评判 |
| Self-Reflection（反思器） | 分析错在哪、怎么改 | 生成改进建议 |

```text
Reflexion 循环：
  Actor 尝试 → Evaluator 评估（测试/外部反馈）
  → 失败 → Self-Reflection 分析（"我忽略了 X"）
  → 教训入情景记忆 → Actor 再尝试（避开已知错误）
```

> 🎯 核心要点：反思 ≠ "重新想一遍"，而是**"评估 + 分析 + 记忆改进"三件事**——缺了 Evaluator（客观评估）的"反思"只是重试，缺了记忆的"反思"每轮从零开始。

## 2. 2026 认知反转：自我反思不可信

| 证据 | 结论 |
|---|---|
| Kamoi（TACL 2024） | 自我修正使 GSM8K 数学**成绩下降**（对改错） |
| 2026 信息论论证 | 生成器与评判器共享相关错误 → 自评证据力弱 |
| 一致性陷阱 | 迭代自省放大信心而非增加信息 |
| 进度幻影（Zenodo 2026） | 自评分门退化为"全接受"，56% 声称改进实际零变化 |

| 自我反思可信的情形 | 不可信的情形 |
|---|---|
| 表层错误（格式/风格） | 开放式推理 |
| 不同提示词角度创造真正独立 | 知识密集任务 |
| 有外部可验证标准（测试/schema） | 同模型自评自答 |

> ⚠️ 2026 金句：**"自我反思不能作为自己的评判器"**——"LLM 不能自我修正推理"（Kamoi 论文标题）是 2024 就有的实证，2026 的共识是"把评估交给外部"。

## 3. 适用边界：什么时候该加反思

| 任务特征 | 结论 | 理由 |
|---|---|---|
| 有测试/编译器/标准答案 | ✅ 加（Reflexion 主场） | 外部反馈真实 |
| 有独立评判器可用 | ✅ 加（用独立模型） | 打破同模型盲区 |
| 代码/检索验证类 | ✅ 加 | 执行可判对错 |
| 开放写作/创意 | ⚠️ 谨慎 | 自评无效，人工评审 |
| 短任务（≤3 步） | ❌ 不加 | 成本 > 收益 |
| 无 oracle 无人工 | ❌ 不加 | 加了是自我安慰 |

> 🎯 核心要点：反思的收益公式——**"反思收益 = oracle 质量 × 评判器独立性 × 修订执行力"**——三因子任一为零，反思都是白花钱（四大核心组件 04 篇同款结论的深化）。

## 4. 反思 vs 相邻概念

| 概念 | 区别 |
|---|---|
| 反思 vs 重试 | 重试治"手抖"（原样再跑），反思治"脑子没想全"（先评再改） |
| 反思 vs 重规划 | 重规划改路线（计划），反思改策略（做法）——Planner 05 篇 |
| 反思 vs 推理（thinking） | 推理模型内部思考，反思是显式的评估-改进循环 |
| 反思 vs 评判 | 评判是"打分"，反思是"打分 + 分析 + 改进" |

## 5. 反思系统的质量三问

| 问题 | 决定 |
|---|---|
| 谁评估？（评判器独立性） | 同模型 = 盲区；独立模型/规则 = 可信 |
| 评什么？（oracle 真实性） | 外部信号 vs 自我感觉 |
| 改什么？（修订执行力） | 批评落地为修改，而非"收到" |

> 💡 三问是反思系统的"体检"——答不出"谁评估"的反思系统，大概率是自我安慰循环。

## 6. 反思的成本意识

| 成本画像（2026） | 推理开销 | 准确率提升 |
|---|---|---|
| 内隐提示词反思 | ~2x | +2-13% |
| 外部评判器/工具 | ~3-4x | +3-23% |
| 微调 distilled | 最小 | +10-30% |

> ⚠️ 2026 评测要求：**收益与成本都要报**——"+4 分但 8% 正确改错 + 延迟 3 倍"与"+2 分干净提升"不是同一个系统（08 篇三指标）。

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "反思=重试" | 重试无评估，反思先评再改 |
| "自我反思可靠" | 同模型同盲区（实证下降） |
| "反思轮数越多越好" | 第 1 轮捕获 70-80%，第 5 轮过优化 |
| "反思不用成本" | 2-4 倍推理开销，必须记账 |
| "所有任务都适合" | 无 oracle 任务是自我安慰 |
| "反思结论会自动生效" | 需要"按批评修订"的强制步骤 |

## 8. 反思系统成熟度模型

| 成熟度 | 评判器 | 反馈 | 轮次 | 评测 |
|---|---|---|---|---|
| L1 | 无（直接重试） | 无 | 无限 | 无 |
| L2 | 自我评判 | 内部 | 有上限 | 平均分 |
| L3 | 独立模型/规则 | 外部验证 | 2-3 + 回滚 | 三指标 |
| L4 | 多智能体 + out-of-band | 外部 + 真实世界 | 级联 + 蒸馏 | CI 回归 |

**判断你的反思系统在几级**：三问——① 谁评估？（L1 没人）② 反馈外部吗？（L2 自评）③ 评测测对改错吗？（L3 才测）——对外产品至少 L3。

## 9. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 反思是什么？ | Actor+Evaluator+Reflection 三组件：评估→分析→记忆改进 |
| 反思和重试？ | 重试原样再跑，反思先评再改 |
| 自我反思可靠吗？ | 不可靠（同模型同盲区；GSM8K 实证下降）——评估外部化 |
| 反思收益公式？ | oracle 质量 × 评判器独立性 × 修订执行力 |
| 什么时候不加反思？ | 无 oracle/短任务（≤3 步）/开放生成 |
| 反思成本？ | 2x（内隐）~3-4x（外部）——必须记账 |
| 反思与重规划？ | 反思改策略（做法），重规划改路线（计划）；先反思后重规划（Planner 05 篇） |
| 反思教训去哪？ | 情景记忆（跨轮）+ 长期记忆（跨任务）——Memory 05 篇写入纪律 |
| 反思与推理模型？ | 推理模型 thinking 是内隐反思；显式反思是"评估-改进循环"——先内隐后外显 |
| 反思系统的健康信号？ | 净提升为正 + 过度修正 <3% + 反思成本占比可控——三者是"反思体检" |
| 反思适用一句话？ | "有外部可验证标准才值得反思"——oracle 是反思的许可证 |
| 反思系统体检三问？ | 谁评估（独立性）、评什么（oracle 真实性）、改什么（修订执行力）——三问即体检 |
| 反思的价值定位？ | 不是"让输出更好"的万能药，是"有验证时让输出可靠"的工程组件 |
