# 反思工程化：级联与成本

> 反思的工程问题 = 成本问题。2026 年三件套：**级联反思（省 50-80%）、成本画像（2x/3-4x/distilled）、最佳版本回滚**。让反思"花小钱办大事"。

## 1. 级联反思：便宜检查先行

```text
级联链（多数输出在第 1-2 层就通过）：
  ① 规则检查（正则/schema）→ 过 → 结束（省 100%）
  ② 小模型检查 → 过 → 结束（省 80%）
  ③ 大模型评判 → 过 → 结束（省 50%）
  ④ 反思修订（只有真失败才到这）→ 重新验证
```

| 级联层 | 成本 | 典型通过率 | 省下的反思 |
|---|---|---|---|
| 规则检查 | ~0 | 60% | 60% 输出免反思 |
| 小模型检查 | 低 | 25% | 85% 累计 |
| 大模型评判 | 高 | 10% | 95% 累计 |
| 反思修订 | 最高 | 5% | 只处理真失败 |

> 🎯 核心要点：级联的本质是**"反思是稀缺资源，只给真失败"**——大部分输出"不需要反思"（表层就对），实测可省 50-80% 反思成本。

## 2. 成本画像（2026 基准）

| 方案 | 推理开销 | 准确率提升 | 适用 |
|---|---|---|---|
| 内隐提示词反思 | ~2x | +2-13% | 快速接入 |
| 外部评判器/工具 | ~3-4x | +3-23% | 质量优先 |
| 微调 distilled | 最小（1x） | +10-30% | 场景固定 |
| 级联反思 | 0.3-0.5x | 接近全量 | **生产默认** |

> ⚠️ 成本纪律：**反思成本必须计入任务总成本并监控**——"反思轮次分布""反思成本/任务"两个指标进仪表盘（与 Planner 10 篇的成本治理呼应）。

## 3. Distilled 反思：把反思炼进权重

| 步骤 | 做法 |
|---|---|
| ① 收集三元组 | （草稿, 批评, 修订）真实反思轨迹 |
| ② 训练 | SFT/DPO 偏好对（修订优于草稿） |
| ③ 推理 | 单遍输出精修（无批评调用） |
| ④ 效果 | 1x 成本 + 10-30% 提升 |

```text
Distilled 的适用判据：
  场景固定（反思模式稳定）→ 蒸馏值得
  场景多变 → 蒸馏数据会过时（每变一次重训）
  与 Planner 08 篇微调路线同哲学：先验证再蒸馏
```

> 💡 Distilled 是"反思的终局形态"——把"多轮反思"压缩成"一次生成"，成本从 2-4x 回到 1x。但前提是反思模式稳定（场景固定），否则蒸馏的是过时模式。

## 4. 反思与模型家族分工

| 角色 | 模型建议 | 理由 |
|---|---|---|
| 生成器 | 业务模型 | 主任务 |
| 评判器 | **不同家族**模型 | 打破共享盲区 |
| 反思器 | 中档推理 | 分析改进不需最强 |
| 规则检查 | 代码 | 零成本 |

> 💡 "不同模型家族"的工程含义：**生成用 A 厂商、评判用 B 厂商**——同一家族的模型可能共享训练数据与错误模式，独立性打折。

## 5. 反思的监控仪表盘

| 指标 | 信号 |
|---|---|
| 反思触发率 | 过高 → 级联失效/生成质量下降 |
| 轮次分布 | >3 轮占比高 → 上限失效 |
| 反思成本/任务 | 超预算 |
| 净提升（三指标） | 为负 → 反思在帮倒忙 |
| 过度修正率 | >3% |
| 级联各层通过率 | 分布漂移 → 调整阈值 |

## 6. 反思工程化的完整清单

```text
□ 级联：规则 → 小模型 → 大模型 → 反思（省 50-80%）
□ 轮次：2-3 上限 + 早期退出 + best-version 回滚
□ 评判器：独立模型家族 + rubric + 校准测试
□ 外部验证：能验证的都验证（06 篇）
□ 评测：三指标 + A/B 无反思基线（08 篇）
□ 成本：反思成本/任务监控 + 预算
□ distilled 决策：场景固定 + 基线成绩 + 数据管线
□ 非重置任务：反思前置（行动前自评）
```

## 7. 常见坑速查

| 坑 | 现象 | 解法 |
|---|---|---|
| 无级联全量反思 | 成本翻倍 | 级联链 |
| 成本不监控 | 白烧钱 | 成本/任务指标 |
| 蒸馏场景漂移 | 精修退化 | 场景固定才蒸馏 |
| 同家族评判 | 盲区共享 | 跨家族 |
| 反思无回滚 | 好版本被改坏 | best-version |
| 触发过频 | 每步都反思 | 触发纪律 |
| 反思成本进总账 | 预算失控 | 监控+上限 |

## 8. 级联反思实现骨架

```python
def cascade_reflect(output, rules, small_critic, big_critic, max_rounds=2):
    # ① 规则层（0 成本）
    if rule_check(output, rules):                # 60% 输出在这层过
        return output, {"layer": "rules", "cost": 0}
    # ② 小模型层（低）
    if small_critic(output).verdict == "pass":   # 再放行 25%
        return output, {"layer": "small", "cost": 1}
    # ③ 大模型评判 + 反思（高，只给真失败）
    best = output
    for i in range(max_rounds):
        critique = big_critic(best)
        if critique.verdict == "pass":
            return best, {"layer": "big", "rounds": i + 1, "cost": i + 2}
        revised = revise(best, critique)
        if score(revised) <= score(best):        # 回滚保护
            return best, {"layer": "big", "rolled_back": True}
        best = revised
    return best, {"layer": "big", "rounds": max_rounds}
```

| 实现要点 | 说明 |
|---|---|
| 分层返回 | 记录每层通过（成本审计） |
| 回滚保护 | 分数不升即回滚 |
| 轮次上限 | max_rounds=2 |
| 成本留痕 | 每层 cost 记录（监控输入） |

## 9. 成本对比完整账（决策用）

| 方案 | 10 万输出/月成本 | 相对 |
|---|---|---|
| 无反思 | 10 万 × 1x | 基线 |
| 全量反思（2 轮） | 10 万 × 3x | +200% |
| 级联反思 | 10 万 × 0.4x | -60% |
| Distilled | 10 万 × 1x + 训练 | +训练一次 |

> 💡 决策公式：**级联 = 全量的 1/7 成本，拿到 80-90% 的收益**（多数输出表层就对）；Distilled 适合"长期稳定 + 反思模式固定"的场景，训练成本摊到月均后仍最优。

## 10. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 反思怎么省钱？ | 级联（规则→小→大→反思）省 50-80% |
| 成本画像？ | 内隐 2x / 外部 3-4x / distilled 1x / 级联 0.3-0.5x |
| Distilled 是什么？ | （草稿,批评,修订）三元组训练 → 单遍精修（1x） |
| 模型家族分工？ | 生成 A 厂商、评判 B 厂商（破共享盲区） |
| 监控什么？ | 反思触发率/轮次分布/成本每任务/净提升 |
| 终极成本目标？ | "用 0.3-0.5x 拿到接近全量收益"（级联）+ "炼进 1x"（蒸馏） |
| 级联与三指标联动？ | 级联后净提升应保持（只省触发不省质量）——对比全量反思的三指标 |
| 蒸馏判据？ | 场景固定 + 反思模式稳定 + 基线三指标为正——三者齐才蒸馏 |
| 级联阈值怎么调？ | 看各层通过率分布——规则层通过率下降说明生成质量退化 |
| 反思成本占任务比？ | 目标 <20%——超了先查级联配置再查轮次 |
| 模型家族选择？ | 生成与评判尽量异厂商（DeepSeek 生成 + Claude 评判等组合） |

## 8.5 级联配置调优

| 配置项 | 默认 | 调优信号 |
|---|---|---|
| 规则层阈值 | 严格 | 误杀率高 → 放宽 |
| 小模型选择 | 中档 | 漏检率高 → 换强 |
| 大模型触发率 | 10% | 过高 → 上层漏检 |
| 反思轮次 | 2 | 收益不足 → 3（有 oracle） |
| 回滚阈值 | 分数不升即滚 | 抖动 → 加容忍度 |

## 8.6 反思的部署形态

| 形态 | 说明 | 适用 |
|---|---|---|
| 内联（同进程） | 反思作为 Agent 循环的一部分 | 默认 |
| 独立服务 | 评判/反思独立部署（模型家族分离） | 跨模型/独立扩展 |
| 异步 | 反思不阻塞主流程（完成后异步改进） | 低延迟优先 |
| 离线批量 | 批量反思（蒸馏数据采集） | 蒸馏/评测 |

> 💡 部署形态与成本直接相关：**内联默认、独立服务保模型家族分离、异步保体验、离线为蒸馏供料**——四种形态对应四个目标，按需组合。
