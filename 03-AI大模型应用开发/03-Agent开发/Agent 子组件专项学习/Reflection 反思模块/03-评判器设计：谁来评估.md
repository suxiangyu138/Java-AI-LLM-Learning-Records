# 评判器设计：谁来评估

> 反思的可靠性 = 评判器的可靠性。2026 年共识：**评判器必须是"独立的"**（不同模型/规则/外部信号）——同模型自评是循环论证。本章讲透评判器层级、偏差与多智能体评判。

## 1. 评判器可靠性层级

| 层级 | 评判器 | 可靠性 | 成本 | 适用 |
|---|---|---|---|---|
| L1 | 规则/测试/断言 | 最高（真 oracle） | 0 | 可验证任务（首选） |
| L2 | 外部工具验证 | 高 | 工具成本 | 事实/执行验证 |
| L3 | 独立模型评判器 | 中-高 | LLM 调用 | 无规则场景 |
| L4 | 自我评判 | 低（盲区） | LLM 调用 | 表层改进 |
| L5 | 不评判 | 0 | 0 | 短任务 |

> 🎯 核心要点：**可靠性排序与成本排序相反**——工程上按"能上多高上多高"：有测试用测试（L1），没测试用独立模型（L3），自我评判（L4）只在表层改进时用。

## 2. 评判器偏差目录（2026 实证）

| 偏差 | 表现 | 缓解 |
|---|---|---|
| 确认偏误 | 自我评判强化自己的错误 | 独立模型 |
| 谄媚批评 | 弱提示词评判器回"看起来不错" | 规则约束（rubric）+ 校准 |
| 演员-观察者不对称 | 自己归因外部，看别人归因内部（>20% 场景） | 辩证对齐/多视角 |
| 冗长偏差 | 越长越好（LLM-as-Judge 通病） | 评分标准明确 |
| 从众（majority-wrong） | 3/5 样本同幻觉时多数票选错 | 交叉验证而非投票 |
| 接受一切 | 自评分门退化为 accept-all（进度幻影） | out-of-band 评估（06 篇） |

> ⚠️ 演员-观察者不对称（ReTAS，ACL 2026）：**同一个 Agent 反思自己时归因外部（"工具问题"），审计别人时归因内部（"它没检查"）**——>20% 场景触发——多智能体评判也需要"视角一致"训练。

## 3. 独立评判器的工程实现

```python
# 生成器与评判器分离（不同模型家族）
GENERATOR = "deepseek-v4"          # 生成
CRITIC = "claude-sonnet-5"         # 评判（不同家族！）

def reflect_and_revise(prompt, draft, rubric):
    critique = llm_critic(CRITIC, f"{rubric}\n草稿：{draft}\n请批评：")
    return llm_generate(GENERATOR, f"{prompt}\n\n草稿：{draft}\n\n批评：{critique}\n请修订：")
```

| 独立评判要点 | 说明 |
|---|---|
| 不同模型家族 | 打破共享盲区（同家族也可能共享训练数据） |
| 评判提示词独立 | 不共享生成器的上下文 |
| Rubric 绑定 | 评分标准明确（防谄媚/冗长偏差） |
| 校准 | 评判器自身质量需评测（CoNL 元评估思想） |

## 4. 多智能体评判（2026 前沿）

| 方案 | 机制 | 收益 |
|---|---|---|
| MARS | 角色感知评判集成（多角色评判器） | 反馈多样性 +76%，+4.5% 准确率（5.2% token 成本） |
| PR-CoT | 多视角反思（逻辑/完整/伦理/替代方案） | 84% 一致性、21% 纠错 |
| GSAR | 批评限于"可验证声明" | 防无根据批评 |
| CoNL | 元评估：批评质量=能否帮他人改进 | 无外部基准也能训练评判器 |

```text
多智能体评判的工程启示：
  多评判器 = 多样性（MARS 实证 +76%）
  但成本也乘 N → 按价值分级（高价值任务才用）
  评判器质量也要被评（元评估）
```

## 5. 评判器输出契约（与 Output Parser 衔接）

```json
{
  "verdict": "fail",                    // pass/fail/uncertain
  "issues": [{"severity": "high", "claim": "引用不实",
              "evidence": "来源无法核验", "suggestion": "删除或替换"}],
  "score": 0.4,
  "confidence": 0.8
}
```

| 契约字段 | 作用 |
|---|---|
| verdict | 可编程分流（pass→收尾/fail→修订/uncertain→人工） |
| issues 结构化 | 修订器直接消费（非自由文本） |
| evidence | 批评有据（防无根据批评） |
| confidence | 低置信评判 → 转人工 |

> 💡 评判器输出也要结构化（strict schema 校验）——**"批评质量"与"生成质量"同样需要契约化**，否则修订器无法可靠消费批评。

## 6. 评判器的评测（评判评判器）

| 方法 | 做法 |
|---|---|
| 校准测试 | 评判器 pass/fail 与真值一致率 |
| 偏差检测 | 已知错例能否被评判器抓出 |
| 多样性 | 多评判器意见分歧度（MARS 方法） |
| 元评估 | 批评是否帮修订器改进（CoNL） |
| 金标准集 | 人工标注的"该过/该拒"样本集 |

> 🎯 核心要点：评判器是反思系统的"质检员"，质检员自己也要质检——**"评判器校准测试"应该进 CI**（同生成器评测同权重）。一个"全接受"的评判器比没有评判器更危险（进度幻影）。

## 7. 常见坑速查

| 坑 | 现象 | 解法 |
|---|---|---|
| 同模型评判 | 循环论证 | 独立模型/规则 |
| 无 rubric | 谄媚/冗长偏差 | 评分标准绑定 |
| 评判输出自由文本 | 修订器无法消费 | 结构化契约 |
| 评判器不评测 | 全接受/全拒绝 | 校准测试进 CI |
| 多评判器无角色 | 反馈同质 | 角色感知（MARS） |
| 评判成本无预算 | N 评判器 × N 轮 | 分级使用 |
| 批评无证据 | 无根据批评 | evidence 字段 |

## 8. Rubric 模板（防谄媚的评分标准）

```text
评分标准（Rubric）示例：
  1. 事实准确性（40 分）：每个声明必须可核验；编造扣全分
  2. 完整性（30 分）：用户问题全部回答；遗漏扣分
  3. 逻辑一致性（20 分）：前后矛盾扣分
  4. 格式合规（10 分）：按输出契约
  评分规则：只评"错误"不评"风格"；无证据的批评视为无效
```

| Rubric 要点 | 作用 |
|---|---|
| 维度+权重 | 评判聚焦（防泛泛） |
| 只评错误不评风格 | 防过度修正（05 篇） |
| 证据要求 | 防无根据批评 |
| 分数规则明确 | 可校准可复现 |

## 9. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 评判器层级？ | 规则>工具>独立模型>自我——能上多高上多高 |
| 评判器偏差有哪些？ | 确认偏误/谄媚/演员-观察者不对称/冗长偏差/accept-all |
| 独立评判器怎么做？ | 不同模型家族 + 独立提示词 + rubric + 校准测试 |
| 多智能体评判？ | MARS 角色集成（多样性 +76%）、ReTAS 视角对齐 |
| 评判器输出？ | 结构化契约（verdict/issues/evidence/score） |
| 评判器要评测吗？ | 必须（校准测试进 CI）——全接受的评判器比没有更危险 |
| 评判器输出契约？ | verdict/issues(evidence)/score/confidence——structured（衔接 Output Parser 体系） |
| 多评判器成本？ | N 评判器 × N 轮——按任务价值分级使用 |
| 评判器校准怎么做？ | 已知对错样本集跑评判器，一致率 >85% 才算校准合格 |
| 评判器与反思器分工？ | 评判器"打分+指出问题"（判），反思器"分析+改进建议"（改）——角色分离防串 |
| 评判器 prompt 要点？ | rubric 前置 + 只评错误不评风格 + 证据要求 + 输出契约（4 件套） |
| 多评判器一致性？ | 分歧高时以规则/外部验证为准（grounded 优先） |
| 评判器 prompt 四件套？ | rubric 前置 + 只评错误 + 证据要求 + 输出契约——缺一件就有偏差 |
| 评判器健康监控？ | 通过率分布 + 校准一致率 + 分歧率——三指标进仪表盘 |
