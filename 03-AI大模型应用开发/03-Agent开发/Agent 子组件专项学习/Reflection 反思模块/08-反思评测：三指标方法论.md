# 反思评测：三指标方法论

> 平均分掩盖反思的失败（对改错被平均掉）。2026 年评测标准：**三指标——pre/post delta（每题）、过度修正率、成本每提升**——回答"反思到底赚了多少"。

## 1. 为什么平均分不够

| 平均分掩盖的 | 例子 |
|---|---|
| 对改错 | +4 分平均 = 8% 正确改错 + 12% 错改对 |
| 白烧钱 | 3 倍延迟换 2 分（可能不值得） |
| 漂移 | 平均不变但输出变了（风格对冲） |

> 🎯 核心要点：**反思评测要回答"每道题上发生了什么"，不是"总体涨了多少"**——平均分是"广告语"，三指标才是"审计报告"。

## 2. 三指标详解

### 指标 1：pre/post delta（每题）

| 分类 | 含义 |
|---|---|
| 提升（lift） | 基线错 → 反思后对（真收益） |
| 漂移（drift） | 基线对 → 反思后错（过度修正） |
| 持平 | 都对或都错（反思无效部分） |

```text
delta 报告格式：
  基线错误率 40% → 反思后 34%（平均 -6 分）
  其中：lift 12%（错改对）+ drift 6%（对改错）
  —— "-6 分"掩盖了"12% 赚、6% 亏"的真实结构
```

### 指标 2：过度修正率

| 定义 | 已正确样本中被改错的比例 |
|---|---|
| 目标 | <3%（2026 参考） |
| 检测 | 评测集必须含"已正确样本"（多数团队缺） |
| 含义 | 反思"帮倒忙"的比例 |

### 指标 3：成本每提升（cost-per-improvement）

| 定义 | 总成本（token/延迟/调用）÷ 净提升题数 |
|---|---|
| 对比 | 不同反思方案的性价比 |
| 报告 | 2 分干净提升 vs 4 分但 3 倍成本——分开报 |

> ⚠️ 2026 金句：**"提升 4 分但 8% 正确改错 + 延迟 3 倍的系统，与干净提升 2 分的系统不是同一个系统"**——三指标齐报才是完整画像。

## 3. 评测集设计

| 样本类型 | 用途 | 占比建议 |
|---|---|---|
| 基线错误样本 | 测 lift（真收益） | 50% |
| 基线正确样本 | 测 drift（过度修正） | 30% |
| 边界样本 | 测稳定性 | 20% |
| 失败注入 | 工具故障/数据缺失 | 附加 |

> 💡 多数团队的评测集只有"错误样本"——**没有正确样本就无法测过度修正**，这是反思评测的最大缺口。

## 4. 评测协议固定

| 协议项 | 固定 |
|---|---|
| 任务集 | 版本化（含正确+错误样本） |
| 评判 | 确定性（规则/测试）优先，LLM 判题需校准 |
| 采样 | temperature=0 |
| 轮次 | 与生产一致（2-3 轮） |
| 报告 | 三指标齐报 + 分轮次 |

## 5. 反思评测的 CI 集成

```text
CI 触发：反思提示词/评判器/轮次策略变更
  → 同一评测集重跑 → 三指标对比
  → 门禁：drift 率上升 >1% 拦截 / 成本每提升恶化拦截
```

| 指标 | 门禁建议 |
|---|---|
| 净提升 | 必须 >0（否则反思在帮倒忙） |
| 过度修正率 | <3% |
| 成本每提升 | 对比基线（恶化 >20% 拦截） |

## 6. 反思 vs 无反思的 A/B（终极问题）

| 组 | 配置 |
|---|---|
| A 组 | 无反思（基线） |
| B 组 | 有反思（2-3 轮） |
| C 组 | 反思 + 外部验证 |

```text
A/B 结论判读：
  B 优于 A → 反思有价值（记三指标）
  B 不优于 A → 反思在浪费钱（拆除或重构）
  C 优于 B → 外部验证是反思的放大器（06 篇）
```

> 🎯 核心要点：反思评测的终极问题是**"不加反思会不会更好"**——2024-2026 的实证多次给出"会更好"的答案（GSM8K 下降）——所以 A/B 是反思上线的必过关卡，不是可选项。

## 7. 常见坑速查

| 坑 | 现象 | 解法 |
|---|---|---|
| 只报平均分 | 对改错被掩盖 | 三指标 |
| 评测集无正确样本 | drift 不可测 | 30% 正确样本 |
| 成本不报 | 白烧钱 | 成本每提升 |
| 协议不固定 | 版本不可比 | 锁定 |
| 无 A/B | 不知道值不值 | 基线对比 |
| LLM 判题未校准 | 判分漂移 | 确定性优先 |

## 8. 三指标计算示例

```text
评测集 100 题（50 错误样本 + 30 正确样本 + 20 边界样本）：
  基线错误 40 题 → 反思后对 30 题（lift 30）
  基线正确 60 题 → 反思后错 4 题（drift 4）

  平均分视角：错误率 40% → 34%（-6 分，看起来不错）
  三指标视角：
    净提升 = lift - drift = 26 题
    过度修正率 = drift / 基线正确 = 4/60 = 6.7%（超 3% 门禁！）
    成本每提升 = 反思总成本 / 26 题

  结论：平均分"好看"，但过度修正率 6.7% 说明反思在伤害正确样本
  —— 这正是"平均分掩盖对改错"的标准案例
```

## 9. 反思评测报告模板

| 报告项 | 内容 |
|---|---|
| 基线 | 无反思错误率（A/B 对照） |
| 三指标 | lift / drift / 成本每提升 |
| 分轮次 | 第 1/2/3 轮的边际收益 |
| 失败注入 | 工具故障/数据缺失下表现 |
| 门禁结果 | 净提升>0 / drift<3% / 成本达标 |
| 结论 | 上/下/调整反思方案 |

## 10. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 为什么平均分不够？ | 对改错被平均掉（+4 分可能是 8% 改错换 12% 改对） |
| 三指标？ | pre/post delta（lift/drift）+ 过度修正率 + 成本每提升 |
| 评测集要求？ | 含正确样本（30%）——没有就测不了 drift |
| 反思上线的必过关？ | A/B（无反思基线）——2024-2026 多次实证"不加更好" |
| CI 门禁？ | 净提升>0 / drift<3% / 成本恶化 >20% 拦截 |
| 终极问题？ | "不加反思会不会更好"——A/B 是必答 |
| 评测集组成？ | 50% 错误样本（测 lift）+ 30% 正确样本（测 drift）+ 20% 边界 |
| 三指标与成本联动？ | 成本每提升 = 总成本 ÷ 净提升——不同方案性价比对比的基础 |
| 门禁默认值？ | 净提升 >0 / 过度修正率 <3% / 成本恶化 <20%——三门槛齐设 |
| 分轮次报告的价值？ | 第 1 轮收益占比（70-80%）——验证 2-3 轮配置是否最优 |
| 边界样本测什么？ | 临界任务稳定性（同输入多次结果一致性） |

## 8.5 反思评测的常见失败

| 评测失败 | 表现 | 解法 |
|---|---|---|
| 判题主观 | LLM 判题波动 | 确定性判定优先 |
| 样本漂移 | 评测集随时间过时 | 版本化 + 定期更新 |
| 只测单一方案 | 无 A/B 基线 | 三组对照（无/有/有+验证） |
| 忽略成本 | 白烧钱不知 | 成本每提升 |
| 门禁不设 | 退化静默 | 三门槛 CI |

## 8.6 反思评测与其他子组件的衔接

| 衔接 | 说明 |
|---|---|
| Output Parser | 评判器输出契约（verdict/issues/evidence）走 strict 校验 |
| Planner | 反思评测的 drift 与规划重规划率联动（改策略是否有效） |
| Memory | 反思教训的"记忆命中率"（教训是否真的在下次生效） |
| 工具 | 外部验证的覆盖率与通过率（06 篇指标） |

> 💡 反思评测不是孤岛——**"教训是否生效"需要记忆系统的命中数据、"改策略是否有效"需要规划器的重规划率**——跨模块指标才是反思的完整价值证明。
