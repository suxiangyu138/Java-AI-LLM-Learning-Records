# 生产实践与面试冲刺

> 从"会反思"到"可靠反思"：生产基线、12 避坑、面试题与落地检查单——反思模块体系收官篇。

## 1. 生产基线（反思模块）

| 领域 | 基线 |
|---|---|
| 评判器 | 独立模型家族 + rubric + 校准测试进 CI |
| 反馈来源 | 外部验证优先（测试/检索/schema），自评仅表层 |
| 轮次 | 2-3 上限 + 早期退出 + best-version 回滚 |
| 级联 | 规则 → 小模型 → 大模型 → 反思（省 50-80%） |
| 评测 | 三指标（pre/post delta / 过度修正率 / 成本每提升）|
| 成本 | 反思成本/任务监控；A/B 无反思基线 |
| 失败防护 | 过度修正 <3%、结构雪球（最简 schema）、进度幻影（out-of-band）|

## 2. 12 避坑清单

| # | 坑 | 后果 | 解法 |
|---|---|---|---|
| 1 | 自我反思当可靠评估 | 对改错、循环论证 | 独立评判器/外部验证 |
| 2 | 无 oracle 硬上反思 | 自我安慰 | oracle 条件（01 篇） |
| 3 | 反思轮数无上限 | 无限漂移 | 2-3 轮 + 回滚 |
| 4 | 无 best-version 回滚 | 好版本被改坏 | 回滚机制 |
| 5 | 评测只报平均分 | 对改错被掩盖 | 三指标 |
| 6 | 评测集无正确样本 | drift 不可测 | 30% 正确样本 |
| 7 | 全量反思无级联 | 成本翻倍 | 级联链（省 50-80%） |
| 8 | 自由文本反思 | 幻觉雪球 | 结构化批评（verdict/issue/evidence） |
| 9 | 反思 schema 过复杂 | 对齐税（50%→38%） | 最简契约 |
| 10 | 自评当业务验收 | 进度幻影 | out-of-band 评估 |
| 11 | 同家族模型评判 | 盲区共享 | 跨家族 |
| 12 | 非重置任务重试式反思 | 已发邮件重发 | 反思前置 |

## 2.1 与体系其他模块的协作

| 模块 | 反思协作点 |
|---|---|
| 四大核心组件 | 反思是四组件之一（04 篇概览） |
| Planner 规划器 | 先反思（改做法）后重规划（改路线）；PER 的 Reflect |
| Memory 记忆系统 | 反思教训入记忆（跨任务经验） |
| Output Parser | 评判器输出契约（verdict/issues/evidence） |
| 工具组件 | 外部验证的"工具库"（配套生态模块） |

> 💡 反思的"邻居"关系：**教训写给记忆、批评走解析器契约、验证用配套工具、与规划器分工**——接线完整，反思才"活"在系统里。

## 2.2 面试速记（本体系一页纸）

| 主题 | 核心结论 |
|---|---|
| 定位 | 评估→分析→记忆改进三组件；≠重试 |
| 机制 | Reflexion（外部反馈）> Self-Refine（自评）；CRITIC/LATS/PRM 谱系 |
| 评判器 | 规则>工具>独立模型>自我；跨家族 + rubric |
| 轮次 | 2-3 上限 + 早期退出 + best-version 回滚 |
| 失败 | 过度修正/幻觉雪球/对齐税/进度幻影——"看起来在改进" |
| 外部验证 | "通过了测试"优于"我觉得对"；out-of-band 结构性需求 |
| 评测 | 三指标（lift/drift/成本每提升）+ A/B 基线 |
| 成本 | 级联省 50-80% + distilled 1x |
| 前沿 | PRM 步骤级 > ORM；先成熟手段用足 |
| 一页纸口诀 | 评估外部化、批评结构化、轮次 2-3、评测三指标、成本靠级联 |
| 反思上线三关？ | oracle 条件 → 三指标 A/B → 级联成本达标——三关过才上线 |

## 3. 面试题（高频 12 题 + 答题要点）

| 题 | 答题要点 |
|---|---|
| 1. 反思是什么？ | Actor+Evaluator+Self-Reflection 三组件；评估→分析→记忆改进；≠重试 |
| 2. Reflexion 原理？ | 语言化自我批评（不更新权重）+ 外部反馈 + 情景记忆；代码任务 +10-20pp |
| 3. Self-Refine vs Reflexion？ | 自我批评 vs 外部反馈——反馈来源决定可靠性，Reflexion 更可靠 |
| 4. 自我反思可靠吗？ | 不可靠（Kamoi：GSM8K 下降；同模型同盲区；一致性陷阱）——评估必须外部化 |
| 5. 评判器怎么设计？ | 层级：规则>工具>独立模型>自我；rubric 防谄媚；跨模型家族 |
| 6. 反思轮数怎么定？ | 2-3 轮（第 1 轮 70-80% 收益，第 5 轮过优化）+ 早期退出 + best-version |
| 7. 反思会怎么失败？ | 过度修正/幻觉雪球/结构雪球（对齐税）/进度幻影——共同点"看起来在改进" |
| 8. 反思怎么评测？ | 三指标：pre/post delta + 过度修正率 + 成本每提升；评测集含正确样本 |
| 9. 外部验证是什么？ | 测试/检索/schema 验证——"这通过了测试"优于"我觉得对"；out-of-band 是结构性需求 |
| 10. PRM 是什么？ | 过程奖励模型（步骤级打分）vs ORM（结果级太稀疏 66.77%）；AgentPRM Promise/Progress |
| 11. 反思成本怎么控？ | 级联（省 50-80%）+ 轮次上限 + 成本监控 + distilled（1x） |
| 12. 反思和重规划区别？ | 反思改策略（做法），重规划改路线（计划）；先反思后重规划 |

## 4. 演进趋势（2026-2027）

| 趋势 | 现状 | 影响 |
|---|---|---|
| 评估外部化 | out-of-band 成共识 | 自评被淘汰 |
| PRM 普及 | 步骤级奖励成熟 | 长任务反思精准化 |
| 多智能体评判 | MARS 角色集成 | 反馈多样性 |
| Distilled 反思 | 训练化 | 反思成本 1x |
| 级联标配 | 便宜先行 | 成本大降 |

> 💡 工程启示：**2026-2027 反思的投入顺序——外部验证 > 级联降本 > 三指标评测 > 独立评判器 > PRM/蒸馏前沿**。反思的可靠性不在"反思多聪明"，在"评估多客观"。

## 5. 落地检查单（上线前逐项打勾）

```text
□ oracle 条件确认（有外部可验证标准才上反思）
□ 评判器：独立模型家族 + rubric + 校准测试
□ 级联链：规则 → 小模型 → 大模型 → 反思（省钱）
□ 轮次：2-3 上限 + 早期退出 + best-version 回滚
□ 外部验证：可验证的都验证（测试/检索/schema）
□ 结构化批评：verdict + issues(evidence) + score（最简 schema）
□ 评测：三指标 + 正确样本集 + A/B 无反思基线
□ 成本：反思成本/任务监控 + 预算
□ 失败防护演练：对改错、幻觉雪球、进度幻影各一次
□ 非重置任务反思前置
□ 与 Planner 配合：先反思后重规划
□ 反思教训入记忆（跨任务收益）
```
