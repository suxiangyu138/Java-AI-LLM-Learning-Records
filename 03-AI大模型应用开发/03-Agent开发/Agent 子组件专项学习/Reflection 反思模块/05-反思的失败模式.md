# 反思的失败模式

> 反思会失败——而且失败得很隐蔽（对改错、白烧钱、看起来在进步）。2026 年失败模式目录：**过度修正、幻觉雪球、结构雪球、进度幻影**。认识失败模式，才能让反思"不帮倒忙"。

## 1. 失败模式总表

| 失败模式 | 机制 | 危害 | 检测 |
|---|---|---|---|
| 过度修正 | 把正确改错（误报→对冲/丢细节/新错误） | 正确率下降 | pre/post delta（08 篇） |
| 幻觉雪球 | 自由文本反思递归美化早期错误 | 错误根深蒂固 | 反思内容审查 |
| 结构雪球/对齐税 | 强制结构化反思降低准确率 | 语法对齐语义错 | 有/无结构 A/B |
| 进度幻影 | 自评分门 accept-all | 真实停滞被掩盖 | out-of-band 评估 |
| 谄媚批评 | 评判器"看起来不错" | 反思无效 | 校准测试 |
| 无停止规则 | 无限循环/过度编辑 | 成本失控 | 轮次上限 |
| 同模型盲区 | 生成器=评判器 | 循环论证 | 独立评判器 |
| 多跳抖动 | Reflexion 在多跳检索上反复 | 结果不稳定 | 轨迹稳定性 |

> 🎯 核心要点：反思失败的共同特征是**"看起来在改进，实际上在变差"**——所以 2026 年评测的第一原则是"测对改错率"（08 篇），而不是只看平均分。

## 2. 过度修正：最隐蔽的失败

| 现象 | 例子 |
|---|---|
| 正确改错 | 测试通过 → 反思挑刺 → 改出 bug |
| 对冲化 | 明确答案被改成"可能/也许" |
| 细节丢失 | 修订删掉关键信息 |
| 新错误引入 | 修 A 引入 B |

```text
过度修正的根因：
  反思器看到"任何可改进空间"就改（无法区分"可优化"与"错误"）
  缓解：rubric 只评"错误"不评"风格"；分数回退即回滚（04 篇）
```

> ⚠️ 多数团队从不测过度修正——因为评测集偏向已知失败样本（没有"正确但被改错"的样本）。**自建评测集必须包含"已正确的样本"**（08 篇）。

## 3. 幻觉雪球：错误被递归美化

| 阶段 | 过程 |
|---|---|
| ① 早期错误 | 第一步推理错了 |
| ② 自由文本反思 | 反思"我的推理是对的，只是..." |
| ③ 递归美化 | 每轮反思都在为错误找理由 |
| ④ 根深蒂固 | 错误被"论证"得更自信 |

> 💡 幻觉雪球的防线：**反思输出约束为结构化批评（issue + evidence）**而非自由文本"分析"——没有证据的 claim 不进入反思（GSAR 的"可验证声明"思想）。

## 4. 结构雪球 / 对齐税（2026 实证）

| 实证 | 数据 |
|---|---|
| Qwen3-8B + HotpotQA | 约束解码强制结构化反思：准确率 50% → **38%** |
| 机制 | 满足格式规则的认知负担 → 掉进格式陷阱 |
| 结论 | 语法对齐 ≠ 语义正确 |

```text
对齐税的工程启示：
  结构化反思（JSON）的收益（可消费/可校验）与代价（认知负担）要权衡
  缓解：① 格式简单（少嵌套）② 生成与结构化分离
       （先生成自由文本，再单独转结构化）
```

> ⚠️ 与 Output Parser 体系的张力：结构化输出是"工程必需"，但反思场景的**认知负担成本实证存在**——反思的 schema 应该"最简可用"（verdict + issues + evidence），别上复杂嵌套。

## 5. 进度幻影：自评的"全接受"陷阱

| 实证（Zenodo 2026） | 数据 |
|---|---|
| 长程自主循环自我评分 | 54 个循环全部声称"改进" |
| 实测 | 56% 的循环 delta 为零或负 |
| 自评分门退化 | accept-all（全接受） |
| 侵蚀 | 最好状态被侵蚀 19% |
| 最强 in-band 评判器 | 仍接受 44% 真实回退、拒绝 38% 真实改进 |

> 🎯 核心要点：**当成功信号在记录之外（真实世界目标），任何"看记录自评"的评判器都会产生进度幻影**——out-of-band 评估（用真实世界结果验证）是结构性需求，不是可选项（06 篇）。

## 6. 失败模式的检测方法

| 失败 | 检测 |
|---|---|
| 过度修正 | 正确样本集 pre/post delta（08 篇） |
| 幻觉雪球 | 反思内容证据审查（无证据 claim 计数） |
| 结构雪球 | 结构化 vs 自由格式 A/B |
| 进度幻影 | out-of-band 对比（真实结果 vs 自评） |
| 谄媚 | 已知错例评判器抓出率（校准测试） |
| 无停止 | 轮次分布监控（>3 轮占比） |
| 同模型盲区 | 独立评判器抽样对比 |

## 7. 常见坑速查

| 坑 | 现象 | 解法 |
|---|---|---|
| 只报平均分 | 对改错被掩盖 | 三指标（08 篇） |
| 反思自由文本 | 雪球 | 结构化批评 |
| schema 过复杂 | 对齐税 | 最简契约 |
| 自评当验收 | 进度幻影 | out-of-band |
| 不测正确样本 | 过度修正不可见 | 正样本入评测集 |
| 无轮次上限 | 无停止 | 2-3 轮 |
| 同模型评判 | 盲区 | 独立评判器 |

## 8. 失败检测清单（上线前演练）

```text
□ 对改错演练：正确样本集跑反思，drift 率 <3%
□ 雪球演练：给反思器一个错误草稿，检查批评是否"美化"错误
□ 对齐税演练：结构化 vs 自由格式 A/B（对比准确率）
□ 幻影演练：自评结果与真实结果对比（out-of-band）
□ 谄媚演练：已知错例喂评判器，抓出率 >80%
□ 漂移演练：无上限跑 10 轮，观察退化（验证上限必要性）
```

| 演练 | 通过标准 |
|---|---|
| 对改错 | drift <3% |
| 雪球 | 无证据 claim 为 0 |
| 对齐税 | 结构化不劣于自由格式 |
| 幻影 | 自评与真实一致率 >80% |
| 谄媚 | 抓出率 >80% |
| 漂移 | 5 轮后无退化 |

## 9. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 反思失败模式？ | 过度修正/幻觉雪球/结构雪球（对齐税）/进度幻影 |
| 过度修正是什么？ | 把正确的改错——多数团队从不测（评测集缺正确样本） |
| 对齐税实证？ | Qwen3 结构化反思 50%→38%——schema 最简可用 |
| 进度幻影？ | 自评分门 accept-all（56% 声称改进零变化）——out-of-band |
| 失败共同特征？ | "看起来在改进，实际在变差"——测对改错率 |
| 共同解药？ | 外部化：评估/批评/评测全部外部锚定 |
| 反思失败能预防吗？ | 部分能：轮次上限（漂移）、结构化批评（雪球）、最简 schema（对齐税）、out-of-band（幻影） |
| 失败检测进 CI？ | 对改错/谄媚/幻影演练应进回归（05 篇清单） |
| 过度修正的根因？ | 反思器分不清"可优化"与"错误"——rubric 只评错误不评风格 |
| 进度幻影的解法？ | out-of-band（真实世界结果）——放大评判器规模无效（最强 in-band 仍错 44%） |
| 失败模式与成本？ | 每种失败都在烧钱（对改错=白烧+倒退）——检测失败=省钱 |
| 反思失败预防优先级？ | 轮次上限（最易）> 结构化批评 > 最简 schema > out-of-band（最难） |

> 🎯 核心要点：反思失败模式的共同解药是**"外部化"**——评估外部化（独立/out-of-band）、批评结构化（防雪球）、评测外部化（正样本+delta）——反思越"自嗨"，越需要外部锚点。
