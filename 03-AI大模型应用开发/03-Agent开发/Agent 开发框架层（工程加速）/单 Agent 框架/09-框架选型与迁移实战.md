## 1. 同需求五实现：订单查询 Agent

```text
需求：单 Agent——用户报订单号 → 查订单状态 → 结构化返回
工具：search_orders(order_id) → {status, items}
约束：输出必须含 order_id/status/items；失败要友好提示
```

### 1.1 LangGraph（显式图）

```python
from langchain.agents import create_agent
from langgraph.checkpoint.memory import InMemorySaver

agent = create_agent(
    model=chat_model,
    tools=[search_orders],
    system_prompt="你是订单助手。查不到订单时明确告知。",
)
result = agent.invoke(
    {"messages": [{"role": "user", "content": "查一下 #8823"}]},
    {"configurable": {"thread_id": "s-1"}},
)
```

**特征**：想要 HITL/恢复 → 下沉 StateGraph 加 interrupt；checkpointer 换 PostgresSaver 即生产。

### 1.2 OpenAI Agents SDK（轻量原语）

```python
from agents import Agent, Runner

agent = Agent(
    name="OrderAssistant",
    instructions="查不到订单时明确告知。",
    tools=[search_orders],
)
result = await Runner.run(agent, "查一下 #8823", session=SQLiteSession(conversation_id="c-1"))
print(result.final_output)
```

**特征**：最少代码；要护栏加 input_guardrails；要多实例共享会话换 RedisSession。

### 1.3 Smolagents（代码执行）

```python
from smolagents import CodeAgent, tool

@tool
def search_orders(order_id: str) -> str:
    """查询订单状态。参数：订单号。返回状态文本。"""
    return fetch_status(order_id)

agent = CodeAgent(tools=[search_orders], model=model, max_steps=5)
agent.run("查一下 #8823 的状态")
```

**特征**：模型可能写出"循环处理多个订单"的代码——一步多查；`max_steps=5` 防跑飞；生产加远程沙箱。

### 1.4 Pydantic AI（类型安全）

```python
from pydantic_ai import Agent, RunContext
from pydantic import BaseModel

class OrderResult(BaseModel):
    order_id: str
    status: str
    items: list[str]

agent = Agent(model=model, output_type=OrderResult, system_prompt="你是订单助手。")
@agent.tool
async def search_orders(ctx: RunContext, order_id: str) -> OrderResult:
    return OrderResult(**fetch(order_id))

result = await agent.run("查一下 #8823")
assert isinstance(result.output, OrderResult)   # 类型保证
```

**特征**：输出结构由 Pydantic 强制——下游解析零风险；deps 注入 DB 会话。

### 1.5 Claude Agent SDK（完整 harness）

```python
from claude_agent_sdk import query, ClaudeAgentOptions, ResultMessage

async for msg in query(
    prompt="查一下 #8823 的订单状态并报告",
    options=ClaudeAgentOptions(
        tools=["Read", "Grep", "Bash"],        # 内置工具按需裁剪
        allowed_tools=["Bash", "Read", "Grep"],
        max_turns=10,
    ),
):
    if isinstance(msg, ResultMessage) and msg.subtype == "success":
        print(msg.result)
```

**特征**：甚至不用自定义工具——模型直接用 Bash/Read 查数据；文件/命令类任务 harness 全包。

## 2. 五实现的取舍对照

| 维度 | LangGraph | OpenAI SDK | Smolagents | Pydantic AI | Claude SDK |
|------|-----------|-----------|-----------|-------------|-----------|
| 代码量（此例） | 中 | 最少 | 中 | 中 | 最少（无自定义工具） |
| 输出保证 | 模型层 | 弱 | 无强制 | 最强 | output_format 可加 |
| 扩展 HITL | 一行 interrupt | 人工 Agent | 自建 | 回调自建 | hooks/批准回调 |
| 生产持久化 | PostgresSaver | RedisSession | 自建 | message_history | session_store |
| 运行形态 | 自己进程 | 自己进程 | 沙箱执行 | 自己进程 | 捆绑 Claude Code 二进制 |

> 🎯 **同一需求五条路都通**——选型差异在"下一步需求"上：要审批选 LangGraph/Claude SDK；要强类型选 Pydantic AI；要少写代码选 OpenAI SDK/Claude SDK；要处理文件选 Claude SDK/Smolagents。

## 3. 框架迁移方法论

```text
为什么迁移要方法论：框架是 harness——换了框架，行为（prompt 效果、
工具调用模式、上下文管理）全变。没有基线就迁移 = 盲切。

五步迁移：
  1. 抽象工具层（不变）——工具按 MCP/纯函数实现，与框架解耦
  2. 建立评估基线——golden set 在新旧框架各跑一遍（工程化模块 06 篇）
  3. 影子运行——新框架跑真实流量只记录不服务（工程化模块 10 篇 shadow）
  4. 金丝雀切换——5% 流量走新框架，评估分数 + 成本对比
  5. 全量 + 保留旧框架热备 24h——回滚=切回
```

**迁移决策记录（ADR）要素**：

```text
□ 现状与痛点（为什么迁）
□ 候选框架对比（本模块 01/08 篇）
□ 选型理由与代价（明确放弃什么）
□ 迁移路径与回滚方案
□ 验收标准（评估基线数字）
```

## 4. 迁移的五个陷阱

| 陷阱 | 症状 | 修复 |
|------|------|------|
| 无基线迁移 | 换框架后质量变化无法归因 | 先建 golden set 评估基线 |
| 工具层耦合 | 工具里混了框架 API 调用 | 工具纯函数化 + MCP 化 |
| 一次性切换 | 坏了无法回滚 | shadow → canary → 热备 |
| 忽略 harness 差异 | 同样的 prompt 行为完全不同 | prompt/评估按框架重调（版本快照） |
| 迁移 = 重写业务 | 业务逻辑跟着框架走 | 业务逻辑进工具/确定性代码，框架只管循环 |

## 5. 组合架构实战

```text
案例：生产客服 Agent（多框架组合，2026 常见形态）

  Claude Agent SDK 主循环（完整 harness + hooks 审批门 + 自动压缩）
  ├─ 工具层：MCP server（订单/退款，一次实现）
  ├─ 结构化输出：output_format json_schema（SDK 原生）
  ├─ 退款审批：PreToolUse hook + canUseTool（人工批准）
  └─ 子 Agent：AgentDefinition（代码审查等专项，最小工具集）

  另一团队同需求用：
  LangGraph 编排（显式状态流 + PostgresSaver 恢复）
  └─ 结构化工具输出用 Pydantic AI 风格类型（手写 Pydantic 校验）

结论：组合按"每层选最强"——编排层/工具层/输出层可异构，
      MCP 与标准协议是粘合剂
```
