## 1. 分层架构总览

所有低代码 Agent 平台（Dify/n8n/Langflow/百炼/Coze）的架构都可抽象为六层：

```text
┌─────────────────────────────────────────────────┐
│ 编辑层    画布 / 表单 / 对话式构建（所见即所得）    │
├─────────────────────────────────────────────────┤
│ 模型层    流程模型（JSON/YAML 序列化的节点图）      │
├─────────────────────────────────────────────────┤
│ 执行引擎  节点调度：DAG 执行 或 Agent 循环         │
├─────────────────────────────────────────────────┤
│ Agent 运行时  工具循环 / 沙箱 / 记忆管理          │
├─────────────────────────────────────────────────┤
│ 发布层    API / Web App / Webhook / MCP Server   │
├─────────────────────────────────────────────────┤
│ 可观测    日志 / 追踪 / 评估 / 用量与成本          │
└─────────────────────────────────────────────────┘
```

> 🎯 **理解低代码平台 = 理解这张图**：低代码不是"没有代码"，而是"平台把六层都做了，你用画布配置"。选平台时逐一问：每一层强不强？

## 2. 编辑层：画布与流程模型

| 构建方式 | 代表 | 特点 |
|---------|------|------|
| 节点画布（拖拽连线） | Dify Workflow、n8n、Flowise、Langflow | 精确可控，技术使用者友好 |
| 对话式（Prompt 生成） | Coze 扣子、百炼 Agent 2.0 | 自然语言描述生成，业务人员友好 |
| 表单配置 | Copilot Studio | 面向企业存量场景 |

**流程模型的本质**：画布上的图最终序列化为结构化数据（JSON/YAML），其中：

```text
流程模型三要素：
节点（Node）      = 一个执行单元（LLM 调用/HTTP/代码/条件/知识检索）
边（Edge）        = 数据流与控制流（决定执行顺序）
变量（Variable）  = 节点间的数据传递（输入/输出/全局变量）
```

> 💡 **通用性红利**：流程模型可序列化 = 可版本管理、可导出、可被程序调用——Langflow 1.9 的版本管理、EDB 的不可变 bundle、Langflow 的 MCP 导出都建立在这一层。

## 3. 执行引擎：DAG 与 Agent 循环

平台执行引擎分两种范式：

### 3.1 确定性 DAG 执行（Workflow）

```text
节点 A → 节点 B →（条件分支）→ 节点 C / 节点 D → 节点 E
特点：路径确定、可预测、可审计
适用：固定 SOP（客服流程、审批流、数据管道）
代表：Dify Workflow / n8n / Langflow 流程
```

### 3.2 自主 Agent 循环（Agent）

```text
用户输入 → 模型规划（选工具）→ 执行工具 → 观察结果 → 再规划…
                                  ↑_______________│
                                    （循环直到终止）
特点：路径由模型决定、灵活但不可精确预测
适用：开放式任务（调研、多步推理、代码执行）
代表：Dify Agent（ReAct/Function Calling）、n8n AI Agent 节点、
      百炼 Agent 2.0（规划-执行-反思）、Coze Agent
```

### 3.3 两者的融合（2026 主流形态）

```text
Dify 1.16：Agent 可作为 Workflow 节点（确定流程中嵌自主环节）
n8n 2.x：Agent 作为执行者，工作流作为 Agent 工具
→ 双向嵌套成为共识：确定性的给自主的兜底，自主的给确定性的补灵活
```

## 4. Agent 运行时：工具循环与沙箱

| 能力 | 说明 | 2026 事实 |
|------|------|----------|
| 工具循环 | 模型决策→调用→结果回传的循环实现 | 各家均实现，差异在细节（并行调用、错误回传） |
| 沙箱执行 | 代码类工具的安全执行环境 | Dify 1.16 完整 Linux 沙箱；百炼内置工具沙箱（bash/write/read/edit/glob/grep） |
| 记忆管理 | 会话历史、长期记忆 | n8n 记忆后端（Redis/Postgres/内存）；Dify 会话记忆偏浅 |
| 终止条件 | 最大迭代/自然结束 | Dify 1.11.3 新增 AgentMaxIterationError 健壮性处理 |
| HITL | 人工介入挂起/恢复 | n8n 2.33 HITL 暂停/恢复；代码框架 interrupt() 四形态更全 |
| Skills | SOP 化能力封装 | Dify Skills、Coze Agent Skills、n8n 工作流即工具 |

> ⚠️ **沙箱安全基线**：凡平台提供代码执行（Dify Agent 沙箱、百炼内置工具），生产部署必须确认沙箱隔离强度——参照单 Agent 框架模块 Smolagents 的五层沙箱思路评估。

## 5. RAG 集成层

| 平台 | RAG 能力 | 强度 |
|------|---------|:---:|
| Dify | 内置完整流水线（摄取/分块/Embedding/检索/重排）+ MongoDB Atlas/Voyage AI 原生节点 + 多模态检索 | ●●● |
| 百炼 | 知识库作为 Agent 技能，自主规划调用 | ●●● |
| Coze | 知识库（RAG）上传构建，Agent 检索 | ●● |
| Langflow | 组件级（8+ 向量库、Embedding 组件自由拼装） | ●● |
| n8n | 弱（需外部向量库节点组合） | ● |
| SaaS（Lindy 等） | 平台内置上传/连接 | ●● |

> 💡 **RAG 强度的本质差异**：Dify/百炼把 RAG 做成"产品内置能力"（数据集管理、批量 re-index、检索配置）；n8n/Langflow 把 RAG 做成"组件拼装"（灵活但要自己设计）。**要产品级 RAG 选前者，要定制化 RAG 选后者**。

## 6. 工具与 MCP 接入层

2026 年所有主流平台都通过 MCP 开放工具生态：

| 平台 | MCP 能力 |
|------|---------|
| Dify | 协议升级至 2025-06-18：版本协商、结构化工具输出、动态 HTTP 头注入（请求级鉴权） |
| 百炼 | MCP 工具一站式接入（知识库/工作流/插件均可作为 MCP 服务） |
| n8n | MCP 连接失败对 Agent 非阻塞（容错）；agents 支持 MCP 可发现（availableInMCP） |
| Langflow | 流程一键导出为 MCP Server（反向：平台作为 MCP 服务方） |
| Coze | 插件生态 + MCP 接入 |

```text
MCP 的双向角色：
消费方向：平台 Agent 调用外部 MCP 工具（Dify/百炼/n8n）
提供方向：平台的流程/Agent 导出为 MCP 服务（Langflow）
→ 平台与编码 Agent 生态通过 MCP 双向打通
```

## 7. 发布层：API / Web App / Webhook / MCP

| 发布形态 | 代表 | 适用 |
|---------|------|------|
| API（带密钥与限流） | Dify API 网关 | 产品集成（对外交付） |
| 托管 Web App | Dify Web App（可自定义占位文本）、Coze 发布 | 直接给用户用 |
| Webhook 触发 | n8n 原生（触发型自动化） | 事件驱动（表单/消息/定时） |
| MCP Server | Langflow 一键导出 | 给编码 Agent 当工具 |
| 嵌入 | Flowise 托管 Widget | 网站嵌入聊天 |

> 🎯 **发布层决定了"平台即终态"的可行性**：Dify 的 API 网关 + 用量分析是它"产品化"的根；n8n 的 Webhook 是它"自动化"的根——按你的交付形态选平台。

## 8. 可观测：日志、追踪、评估

| 能力 | 各平台情况 |
|------|-----------|
| 运行日志 | 全部有（节点级执行日志） |
| 追踪 | Dify 有调用链路追踪；n8n 有 trace 模态（Instance AI trace）；Langflow 较弱 |
| 评估 | n8n 2.33 支持一等公民 Agent 的 Evals；Dify 有提示词调优与评估工具 |
| 用量成本 | Dify 统一计费分析；百炼云计量 |
| 外部可观测 | 通用 OTel 输出（各平台支持度不一） |

> 💡 **可观测的差距在"生产级"**：原型验证阶段日志够用；一旦进生产，优先选带追踪+评估+成本分析的平台（Dify 最强），或自行接 OTel/监控体系（参见 [工程化 & 部署模块](../../Agent%20工程化%20&%20部署模块（从%20demo%20到可用应用）/)）。

## 10. 核心要点

> 🎯 **核心要点**：
> 1. 低代码平台 = **六层架构**（编辑/模型/执行/Agent 运行时/RAG/发布/可观测）都替你做了，你只配置画布
> 2. 两种执行范式：**DAG 确定性流程** vs **Agent 自主循环**——2026 主流是双向嵌套（Agent 在流程里、流程在 Agent 里）
> 3. 2026 设计共识：**一切能力都是工具**（知识库/MCP/内置动作统一为工具），模型自主编排
> 4. MCP 是平台与编码 Agent 生态的双向桥梁：平台消费 MCP 工具（Dify/百炼），平台也能导出为 MCP（Langflow）
> 5. 选平台时按层打分：要产品级 RAG 选 Dify/百炼，要自动化触发选 n8n，要 MCP 导出选 Langflow
