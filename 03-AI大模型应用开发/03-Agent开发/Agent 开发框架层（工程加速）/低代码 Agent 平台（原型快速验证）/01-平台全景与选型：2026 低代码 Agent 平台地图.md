## 1. 平台分类全景

2026 年低代码 Agent 平台按**部署形态**与**生态归属**可分为三大阵营，加上一个 2026 年才被 Gartner 正式定义的品类：

| 阵营 | 代表平台 | 部署形态 | 典型使用者 | 核心优势 |
|------|---------|---------|-----------|---------|
| 开源自托管 | Dify、n8n、Langflow、Flowise、Botpress | 自建 Docker/K8s | 技术团队、有数据合规要求的企业 | 数据自主、可定制、免平台费 |
| 云厂商/国产 | 阿里云百炼、Coze 扣子、Microsoft Copilot Studio、Google Agent Builder | 云托管 | 云生态内用户、业务人员 | 与云产品深度集成、开箱即用 |
| SaaS 新锐 | Lindy、Relevance AI、Voiceflow | 纯 SaaS | 业务团队、运营人员 | 上手最快、模板最全、自带治理 |
| 大厂 Agent 平台 | Microsoft Agent Framework、Salesforce Agentforce、Oracle AI Agent Studio | 云托管 | 存量生态企业 | 与既有系统（CRM/ERP）打通 |

> 💡 **一条关键认知**：2026 年这些平台已不是"选一个"的关系——Gartner 数据显示 **51% 的 IT 负责人正在运行多供应商 AI Agent 战略**，多数团队会用 2-3 个平台分工。

## 2. 开源自托管阵营

### 2.1 Dify（GitHub ~147k stars）

- **定位**：最"产品化"的开源 LLM 应用平台——被称为 "LLM 应用的后端即服务"，把 Prompt IDE、工作流/Agent/聊天机器人构建器、知识库与 RAG 流水线、托管聊天 UI、API 网关（带密钥与限流）、用量分析打包成一个开源平台
- **2026 里程碑**：v1.16.0（2026-07-19）发布 **Dify Agent（开放 Beta）**——Agent 在完整 Linux 沙箱中运行（可装包、执行 Python、操作文件、调 API），支持 Agent Builder、Skills 系统、Workflow 中 Agent 作为一等公民节点
- **许可**：修改版 Apache 2.0（多租户托管给他人使用需书面许可，无转售条款）
- **部署**：多容器 Docker Compose（自带 Postgres 与向量库），2-4 GB 内存最低，4-8 GB 推荐
- **适合**：要交付一个"能跑的用户产品"（带用户、密钥、看板、RAG、分析）的场景

### 2.2 n8n（GitHub ~194.6k stars）

- **定位**：通用节点式自动化平台（TypeScript），AI 作为一等公民叠加——核心优势是**集成**：~400+ 应用连接器（Slack、HubSpot、Postgres、S3、Notion、HTTP）
- **2026 里程碑**：2.0（2026-01）原生 LangChain 集成，工作流可被 Agent 当"工具"调用；2.33.0（2026-07-28）AI Agent 节点从预览转正为 V1，支持结构化输出推断、HITL 暂停/恢复
- **许可**：Sustainable Use License（源代码可见，内部使用与修改免费，对外商业化需商业协议）
- **部署**：单容器轻量（1-2 GB 内存最低，2-4 GB 推荐）
- **适合**："把 AI 接到现有业务系统"（CRM/邮件/数据库）的自动化场景

### 2.3 Langflow（GitHub ~150k stars，2026-08-04 达 152,826）

- **定位**：Python 版可视化流程构建器，围绕 LangChain Python 生态；2024 年被 DataStax 收购，2025 年随 DataStax 并入 IBM
- **2026 里程碑**：1.9（2026-04-13）Flow DevOps Toolkit SDK（`lfx init` 命令行做版本/测试/部署）、流程版本管理、**一键导出流程为 MCP Server**（让 Claude Code 等 CLI 编码 Agent 把流程当工具调用）——这被社区称为其最稀缺的能力
- **许可**：MIT（最宽松）
- **适合**：Python 运行时、希望可视化原型能直接映射到 LangChain 对象、或要把流程导出 MCP 供编码 Agent 调用的团队

### 2.4 Flowise（GitHub ~54.1k stars）

- **定位**：TypeScript/Node.js 拖拽构建器，包装 LangChainJS，聚焦小而精的 LLM 应用（知识库聊天机器人、搜索助手、内部工具）
- **2026 动态**：2025-08 被 Workday 收购，仍可自托管（Apache 2.0），但许可证条款需持续关注；画布在 ~30 节点后性能下降
- **适合**：最快路径出一个聊天机器人/RAG MVP，原型期很香，成长到大型流程会受限

### 2.5 Botpress（MIT 开源）

- **定位**：对话式 AI 平台，视觉流程设计 + 多 LLM 支持 + 可自托管，面向想要完全掌控基础设施与数据的开发者团队；但偏聊天场景，后台办公自动化不是重点
- **2026 动态**：2026-05 重构为按对话计费的方案（Free：100 对话/月；Plus ~$150/月）
- **适合**：开发者主导、要自托管对话 Agent 的团队

## 4. SaaS 与新一代平台阵营

Gartner 2026 首发 **No-Code Agent Builders（NCAB）** 品类，定义为"SaaS 交付、提供集成设计与运行时环境、无需编码即可构建发布管理 AI Agent"的平台，核心构建方式为**可视化拖拽和/或对话式（Prompt 式）**。

| 平台 | 一句话定位 | 2026 事实 | 价格锚点 |
|------|-----------|----------|---------|
| Lindy | "AI 员工"平台：Agent 像员工一样干活（邮件/日程/CRM/多步流程），非聊天机器人 | 2026 榜单最高分 8.6/10；SOC 2/GDPR/HIPAA/PIPEDA 合规；纯云无自托管 | Plus $49.99/月起 |
| Relevance AI | 面向销售/市场团队的 Agent 团队编排 | 400+ 模板、2000+ 集成、MCP 支持、BYO API Key | 免费档 200 actions/月 |
| Voiceflow | 面向客户的对话 Agent（聊天/语音/WhatsApp）视觉画布 | 50 万+ 团队使用，免费档最实用；不适合后台自动化 | 免费档 + 用量计费 |
| Tray.ai | 企业集成 + 无代码 Agent 构建 | 被 Gartner 评为 Pioneer | 企业报价 |
| Zapier/Asana/Atlassian/Creatio | 从各自领域（工作流/协作/CRM）延伸 Agent 能力 | Gartner 划为 Specialist（专精但欠深度） | 订阅制 |

> 💡 **SaaS 平台的取舍**：上手最快、治理最全（SOC 2 等），但数据过第三方、锁定期风险高——Lindy 一个中等复杂 Agent 迁移重建需 1-3 小时。

## 5. Gartner NCAB 市场格局

Gartner 2026 年《No-Code Agent Builders 新兴市场象限》核心结论：

```text
市场态势：42% 企业 2026 年计划部署 AI Agent（2025 年仅 17% 在生产中）
          → 部署率一年翻倍以上

象限分布：
├── Pacesetter（领跑者）── 微软 / Google / AWS
│   └── 优势：深度集成、既有信任、公民开发生态
│   └── 风险：许可昂贵、强制升级
├── Pioneer（先驱）── Tray.ai、GenAI 原生新锐
│   └── 优势：模型无关、多 Agent 体系
│   └── 风险：规模化、差异化、融资
├── Specialist（专家）── Asana / Atlassian / Creatio / SnapLogic / Zapier
│   └── 优势：领域深度（协作/工作流/集成）
│   └── 风险：Agent 能力深度不足
└── 关键判断：编排差距（治理/多系统连接/RBAC/安全/审计）才是落地障碍
            → "不是技术问题，是编排问题"
```

**2028 前瞻**：Gartner 预测到 2028 年，**公民开发者构建和维护的 AI Agent 将超过传统开发者构建的应用、机器人与工作流的总和**——治理就绪的基础设施应成为 IT 规划的优先级。

## 6. 选型决策树

```text
要做一个 Agent 想法，怎么选平台？

第一问：数据能否出内网？
├── 不能（合规/数据主权）→ 开源自托管阵营
│   ├── 要交付"产品"（用户/密钥/看板/RAG）→ Dify
│   ├── 要连业务系统自动化 → n8n
│   ├── 要 Python 生态 / 导出 MCP 给编码 Agent → Langflow
│   └── 只要对话机器人 MVP → Flowise / Botpress
└── 能（云上 OK）
    ├── 用阿里云全家桶 / Qwen 模型 → 阿里云百炼
    ├── 用字节生态 / 要最快零代码演示 → Coze 扣子
    ├── 用 M365/Teams 存量 → Copilot Studio
    ├── 业务人员自建（不经过开发）→ Lindy / Relevance AI / Voiceflow
    └── 团队已重度使用某 SaaS（Zapier/Asana 等）→ 其内置 Agent 能力

第二问（定完阵营后）：这个 Agent 的生产形态是什么？
├── 只验证想法（1-3 天）→ 低代码平台就是终态，不用迁移
├── 验证后要进生产且流量可控 → 平台自带发布（Dify Web App/API、n8n Webhook）
└── 验证后需要深度定制/复杂状态/高并发 → 迁移到代码框架（见 09 篇）
```

> 🎯 **选型黄金法则**："按任务选，不按演示选"——要连 X 到 Y 用 n8n；要最快出聊天 MVP 用 Flowise/Coze；要 Python 原生流程用 Langflow；要完整 LLM 产品（RAG+用户+分析）用 Dify；要业务人员自己动手用 Lindy 类 SaaS。

## 7. 多平台组合模式

2026 年主流团队的实际用法是 2-3 个平台组合：

| 组合 | 用法 | 适用 |
|------|------|------|
| n8n + Dify | n8n 管业务自动化触发，Dify 管 RAG/Agent 产品 | 中型企业典型 |
| Langflow + Claude Code | Langflow 拖流程 → 一键导出 MCP Server → 编码 Agent 调用 | AI 团队工程化 |
| Coze + 百炼 | Coze 快速演示给业务方 → 百炼落地到阿里云生产 | 国产云生态 |
| Dify（原型）→ LangGraph（生产） | 低代码验证 → 代码框架重写（09 篇详述迁移） | 需要复杂状态管理时 |

> ⚠️ **组合红线**：不要为同一个流程维护两套平台实现——平台间用 **MCP 协议** 互操作（Dify 1.16 已升级 MCP 2025-06-18 协议、Langflow 可导出 MCP Server），而不是复制粘贴流程。

## 8. 核心要点

> 🎯 **核心要点**：
> 1. 2026 低代码 Agent 平台分三大阵营：**开源自托管（Dify/n8n/Langflow/Flowise）**、**云厂商（百炼/Coze/Copilot Studio）**、**SaaS 新锐（Lindy/Relevance/Voiceflow）**——按数据主权、生态归属、构建者身份三问选型
> 2. Gartner 2026 年首次定义 NCAB 品类，**42% 企业今年部署 AI Agent**，编排差距（治理）才是落地最大障碍
> 3. 低代码平台在本体系中的角色是"**原型快速验证**"：1-3 天验证需求与流程，验证后按生产形态决定平台即终态或迁移代码框架（09 篇）
> 4. 多平台用 MCP 互操作，**不要为同一流程维护两套实现**
