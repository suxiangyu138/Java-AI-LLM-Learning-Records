## 1. 面试题（10 题带答案范式）

> 面试高频题集中在三块：**平台选型**、**低代码 vs 代码**、**机制原理**。以下答案范式可直接背诵变形。

### Q1：低代码 Agent 平台有哪些？如何选型？

**答案范式（分层回答）**：
```text
分三类答：
① 开源自托管：Dify（产品化最强：Workflow+RAG+API 网关一体）、
   n8n（400+ 集成，AI 自动化）、Langflow（Python 生态，MCP 一键导出）、
   Flowise（Node 快速 MVP）
② 云厂商：阿里云百炼（Agent 2.0，Qwen 生态）、Coze 扣子（字节，零代码+AI 团队协作）、
   Copilot Studio（微软，M365 生态）
③ SaaS 新锐：Lindy、Relevance AI、Voiceflow（业务人员自建）

选型三问：数据能否出内网？构建者是谁（业务/技术）？交付形态是什么
（产品/自动化/流程给编码 Agent 用）？
```

### Q2：什么时候用低代码平台，什么时候直接写代码框架？

**答案范式（背结论 + 举信号）**：
```text
用低代码：需求不确定期（验证）、流程中等复杂度（DAG 可表达）、
          平台发布能力覆盖、吞吐在平台能力内、团队无深度定制需求
直接写码：复杂状态管理（状态机/时间旅行）、细粒度控制、高并发、
          深度集成自有代码、CI 测试要求、许可受限
一句话：低代码先验证需求（1-3 天），迁移信号出现再写码——
       迁移 = 逐节点翻译 + 补齐平台内置的可靠性（重试/限流/记忆，占迁移 40-60% 工时）
```

### Q3：Dify 和 n8n 怎么选？

**答案范式（一句话定位差）**：
```text
n8n = 集成 + 一点智能：业务自动化（CRM/邮件/数据库连接），Agent 当执行者
Dify = 智能 + 一点集成：完整 LLM 产品（内置 RAG/用户/密钥/分析）
判据：问题本质是"连接"还是"产品"——连接选 n8n，产品选 Dify
```

### Q4：2026 年低代码 Agent 平台有哪些趋势/变化？（考察时效性）

**答案范式（4 个趋势点）**：
```text
① Gartner 2026 首发 NCAB 品类：42% 企业今年部署 AI Agent（2025 仅 17%）
② Agent 成为平台一等公民：Dify 1.16 Agent 沙箱（Linux 沙箱+Skills）、
   n8n 2.33 Agent 节点转正、百炼 Agent 2.0 工具统一化
③ MCP 双向打通：平台消费 MCP 工具（Dify 2025-06-18 协议），
   平台导出为 MCP（Langflow 一键导出，152k stars 推手）
④ 编排/治理是落地最大障碍：不是技术问题，是编排问题；注意 Agent 蔓延
```

### Q5：低代码平台的 Agent 和代码框架的 Agent，底层循环有什么区别？

**答案范式（机制同源论）**：
```text
底层循环一致：模型规划 → 选工具 → 执行 → 观察 → 再规划（ReAct/Function Calling）
区别在实现层：
平台把循环做成产品（可视化配置、内置沙箱、日志、记忆管理）
代码框架把循环交给开发者（interrupt()/checkpointer/自定义终止条件）
→ 平台 = 封装好的循环，代码 = 可改的循环
```

### Q6：什么是 Agent Skills？和工具/插件什么区别？

**答案范式（三层概念）**：
```text
工具/插件 = 单一能力（发邮件、查天气）
Skills = 完整作业程序（SOP：先查库存 → 生成报价 → 发邮件 → 记 CRM）
示例：Dify 1.14/1.16 Skills 系统（Skill Editor + @工具内联调用）、
      Coze Agent Skills（12 领域 300+ 技能，无代码拖拽配置）
价值：领域最佳实践资产化，Agent 按需调用而非每次重建提示词
```

### Q7：Langflow 的 MCP 一键导出是什么？有什么价值？

**答案范式（价值四层）**：
```text
是什么：把画布上的流程封装成标准 MCP Server，暴露为工具
谁调用：Claude Desktop、Claude Code、Codex、OpenClaw 等任意 MCP 客户端
价值：① 非技术人员的流程变成编码 Agent 可调用的工具（零胶水代码）
     ② 流程迭代在画布上做，Agent 代码不用改
     ③ 跨角色协作：业务画流程，开发者跑流程
     ④ 2026 年 Langflow GitHub 152k stars 的直接推手
```

### Q8：企业落地低代码 Agent 平台，最大的坑是什么？

**答案范式（治理优先）**：
```text
不是技术坑，是编排坑（Gartner 结论）：
① 治理缺口：权限/审批/审计/责任归属未定义
② Agent 蔓延：从 1 个到几十个，清单/所有权/成本不可见
③ 许可红线：Dify 修改 Apache（多租户转售需许可）、
   n8n Sustainable Use（对外商业化需商业协议）
④ 锁定：SaaS 迁移成本（Lindy 一个 Agent 重建 1-3 小时）
对策：先建治理（注册表/审批/成本标签/权限最小化）再铺量
```

### Q9：百炼 Agent 2.0 相比 1.0 改了什么？（考察国产平台）

**答案范式（两个核心变化）**：
```text
① 工具统一化：知识库、MCP 等全部统一为工具，Agent 自主规划调用顺序
   （1.0 是先检索知识库再决策是否调 MCP，固定顺序）
② 过程透明：完整展示每一轮"规划-执行-反思"链路（1.0 只展示最终结果）
配套：内置工具沙箱（bash/write/read/edit/glob/grep）、
      百炼 CLI（2026-05 开源，原生支持 Claude Code/Qoder/OpenClaw）
```

### Q10：一个客服知识库 Agent，低代码怎么搭？关键参数怎么调？

**答案范式（流程 + 调参要点）**：
```text
搭建：知识库上传 → 分块 → Embedding → 检索 → 重排 → LLM 生成 → 引用来源 → 发布 API
调参要点：① 分块大小与重叠（检索粒度）② TopK 与重排阈值（召回精度）
         ③ 温度调低（客服场景 0.1-0.3）④ 引用约束（无依据明确说不知道）
         ⑤ 防幻觉：检索不到禁止编造 + 工具调用失败重试
验收：20 用例完成率 ≥ 80%、检索命中率 ≥ 80%、无依据回答率 < 5%
```

## 2. 自测题（20 道）

4. Dify 最新版本与发布时间？核心更新是什么？
5. Coze 扣子 3.0 的三大核心变化是什么？
6. n8n 的 AI Agent 节点在 2.33 发生了什么变化？
7. Langflow 的杀手锏能力是什么？它基于什么语言生态？
8. 百炼 Agent 2.0 相比 1.0 的两个核心变化是什么？

### 机制（9-14）

9. 低代码平台从画布到运行时分几层？各层是什么？
10. DAG 确定性执行与 Agent 自主循环的区别？2026 年的融合形态是什么？
11. Dify 1.16 的 Agent 沙箱是什么？对标什么设计？
12. "一切能力都是工具"这句话在 2026 年指什么？举例两个平台。
13. MCP 在低代码平台中有哪两个方向（消费/提供）？各举一例。
14. Agent Skills 与工具/插件的区别？举一个 Dify 或 Coze 的例子。

### 选型与实战（15-20）

15. 数据不能出内网、要交付完整产品（带用户/密钥/RAG）——选什么平台？为什么？
16. 业务部门（非技术）想自建销售助手 Agent——两个推荐与理由。
17. 什么时候"平台即终态"不用迁移？列出 3 个条件。
18. 列出至少 4 个迁移信号。
19. 迁移代码框架时，平台内置而代码框架需要自建的可靠性能力有哪些？（至少 3 个）
20. 混合架构（模式 C）中，平台和代码框架各管什么？用什么协议连接？

### 自测答案速查

1. 开源（Dify/n8n/Langflow/Flowise）、云厂商（百炼/Coze/Copilot Studio）、SaaS（Lindy/Relevance AI/Voiceflow）
2. No-Code Agent Builders；SaaS 交付、集成设计与运行时、无需编码、可视化拖拽和/或对话式构建
3. 42%（2026）vs 17%（2025 生产）
4. v1.16.0（2026-07-19）；Dify Agent 开放 Beta（Linux 沙箱/Skills/Workflow 一等公民）、MCP 2025-06-18、GPT-5.6 Responses
5. AI 团队协作架构（一人/多人+多 Agent）、本地 Agent 一键接入（Claude Code/Codex CLI/OpenClaw）、项目空间与三端协同
6. 从预览节点转正为 V1（GA）；新增结构化输出推断、HITL 暂停/恢复、已验证社区节点作工具
7. 流程一键导出 MCP Server（让编码 Agent 调用）；Python/LangChain
8. 工具统一化（知识库/MCP 均为工具，自主编排）；过程透明（规划-执行-反思全链路展示）
9. 六层：编辑层/模型层/执行引擎/Agent 运行时/发布层/可观测
10. 路径确定可审计 vs 路径由模型决定；双向嵌套（Agent 在 Workflow 节点中，Workflow 作为 Agent 工具）
11. 完整 Linux 沙箱（Python/装包/文件/API）；对标 Claude Code 的代码 Agent 体验
12. 知识库/MCP/内置动作统一为工具由模型自主编排；Dify Agent、百炼 Agent 2.0
13. 消费：Dify/百炼/n8n 调外部 MCP 工具；提供：Langflow 流程导出为 MCP Server
14. 工具=单一能力，Skills=SOP 化作业程序；Dify Skills（Skill Editor）、Coze Agent Skills（12 领域 300+）
15. Dify——开源自托管 + 内置 RAG + API 网关/密钥/分析（注意转售条款）
16. Coze 扣子（零代码+技能商店）或 Lindy（业务自动化模板全、合规全）
17. 中等复杂度 DAG 可表达、平台发布能力覆盖、吞吐在能力内、许可满足商用
18. 复杂状态、细粒度控制、性能瓶颈、深度集成、测试要求、许可受限、平台演进风险
19. 重试与超时、限流、日志与追踪、记忆持久化、评估、部署与扩容
20. 平台管确定性流程（稳定可审计），代码框架管复杂决策；MCP 协议连接（平台导出/消费 MCP）


## 4. 核心要点

> 🎯 **核心要点**：
> 1. 面试主战场：**选型**（三问）、**低代码 vs 代码**（信号论）、**机制**（六层/双循环/MCP/Skills）
> 2. 时效性是加分项：Gartner NCAB 42% 数字、Dify 1.16、Coze 3.0、n8n 2.33 是 2026-08 的"当前事实"
> 3. 企业题答治理：编排差距 + Agent 蔓延 + 许可红线 + 锁定成本——这是面试官最想听的"落地感"
> 4. 本模块毕业标准：**能独立用低代码平台 1-3 天验证一个 Agent 想法，并给出"平台即终态/迁移"的数据化决策**
