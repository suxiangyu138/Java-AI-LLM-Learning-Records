## 1. 平台定位与版本演进

Coze 扣子是字节跳动的一站式零代码/低代码 AI Agent 开发平台（2024-02-01 上线），用户无需编程基础，通过自然语言描述或可视化拖拽即可创建 AI 助手、聊天机器人、工作流和专业技能 Agent。

```text
演进时间线：
2024-02  1.0 上线 ── 零代码 Bot 搭建平台（国内 coze.cn / 海外 coze.com）
2025-07  开源 ── Apache 2.0 协议可商用；核心项目 Coze Studio（可视化开发工具）
         + Coze Loop（全链路管理工具）
2026-01-19  2.0 ── 全局重构，定位转向"职场 AI"，推出四大核心能力：
         Agent Skills / Agent Plan / Agent Coding / Agent Office
2026-04-07  2.5 ── Agent World 协作平台：为 Agent 配备云电脑、云手机、专属邮箱
2026-06-01  3.0 ── 当前最新：AI 团队协作架构、本地 Agent 接入、项目空间、三端协同
```

> 🎯 **一句话定位**：从"零代码 Bot 搭建"进化为"AI Agent 原生协作操作系统"——2026 年的扣子不再只是开发工具，而是"一人+多 Agent"、"多人+多 Agent"协同干活的工作形态。

## 2. 零代码 Agent 开发能力

| 能力 | 说明 |
|------|------|
| 零代码创建 | 自然语言描述需求即可生成 Agent（对话式构建） |
| 可视化拖拽 | 拖拽创建智能体与工作流，无需编程基础 |
| 多模型切换 | 底层接入豆包、GPT、Claude 等大模型，可切换 |
| 插件生态 | 60+ 内置插件（搜索、天气、图像、办公等） |
| 知识库（RAG） | 上传文档构建知识库，Agent 检索回答 |
| 扣子编程（Vibe Coding） | 云端一站式 Vibe Coding 平台：连续对话构建智能体/工作流/网站/移动应用，一键部署上线 |

> 💡 **与代码框架的关键差异**：扣子的"构建"是**对话式 + 拖拽式**，业务人员（市场/运营/HR）可直接上手——这是它和 Dify/n8n（仍偏技术使用者）的核心定位差。

## 3. Agent Skills：领域最佳实践的封装

Agent Skills 是 2.0 推出的核心创新，也是扣子区别于其他平台的能力：

| 维度 | 说明 |
|------|------|
| 是什么 | 把领域最佳实践封装为可复用技能模块 |
| 配置方式 | 无代码拖拽配置（业务人员可做） |
| 技能商店 | 覆盖 12 个领域、300+ 预设技能 |
| 典型场景 | 金融投研、法务、科研、自媒体、医疗、企业服务等行业的"专家助手"模板 |
| 一键创建 | 从行业模板一键创建垂直专家 Agent（如法务助理 Agent） |

```text
Skills vs 插件：
插件 = 单一 API 能力（地图、天气、翻译）
Skills = 一套完整作业流程（含提示词 + 工具编排 + 输出规范）
例：投研 Skill = 数据抓取 → 财报解析 → 行业对比 → 研报生成
```

## 4. 工作流编排

- **可组合节点**：LLM、自定义代码、判断逻辑、知识库检索、HTTP 请求等节点
- **拖拽搭建**：复杂工作流无需写代码
- **与 Agent 结合**：工作流可被 Agent 调用，Agent 可被工作流调用（互相嵌套）

> 工作流设计思路与 Dify Workflow 一致（确定性流程），但扣子的入口更偏业务用户——适合"业务人员设计流程、开发人员兜底排错"的协作模式。

## 5. 3.0 AI 团队协作架构

3.0 的核心突破是**基于 AI 团队协作的全新架构**：

| 能力 | 说明 |
|------|------|
| 协同模式 | "一人+多Agent" 与 "多人+多Agent" 两种协作模式 |
| Agent 调度 | Agent 可被创建、接入、随时调度 |
| 项目空间 | 任务放入项目空间拆解、分配、沉淀 |
| 多 Agent 分工 | 在项目中 @多个 Agent + Prompt，专家 Agent 分工协作完成任务 |
| 云电脑方案 | Agent 运行在云电脑中，无需配置复杂环境，长期稳定在线 |

```text
3.0 的架构心智：
1.0 = 单个 Bot 生成器
2.0 = Agent 技能包 + 编程
3.0 = 项目空间里的 Agent 团队（人 + 多个 Agent 一起完成项目）
→ 对标 Multi-Agent 编排框架（如 CrewAI），但零代码化
```

## 6. 本地 Agent 一键接入

3.0 支持将本地 Agent 工具一键接入扣子：

- **支持工具**：Claude Code、Codex CLI、OpenClaw 等本地 Agent/CLI 工具
- **接入方式**：一键接入后进入同一项目空间，与其他 Agent 围绕共同目标协作
- **远程控制**：手机端可远程处理电脑中的本地文件（授权前提下）
- **意义**：把"本地编码 Agent"与"云端业务 Agent"纳入同一协作空间——这是国产平台里少见的"混合 Agent 编排"能力

> ⚠️ **注意**：此能力与百炼 CLI 化（原生支持 Claude Code/Qoder/OpenClaw）思路相同——2026 年各大平台都在打通"本地 CLI Agent ↔ 云端平台"的边界。

## 7. 项目空间与三端协同

| 能力 | 说明 |
|------|------|
| 项目空间 | 目标、成员、Agent、文件统一管理，复杂任务在统一上下文推进 |
| 编程项目 | 多人协作开发网页、App、小程序 |
| 视频项目 | 基于 Seedance 2.0 的剧本、分镜、视频、音乐全流程生成 |
| 三端协同 | 手机端（iOS/Android）、电脑端（Mac/Windows）、网页端（coze.cn）实时同步 |
| 断点续做 | 任务不会因设备切换中断 |

## 8. 开源与生态

- **开源协议**：Apache 2.0（可商用），2025-07-26 宣布
- **核心项目**：Coze Studio（可视化开发工具）+ Coze Loop（全链路管理工具）
- **模型生态**：底层接入豆包、GPT、Claude、DeepSeek 等多模型，支持切换
- **技能生态**：12 领域 300+ 预设技能 + 行业垂直模板（金融、法务、科研、自媒体等）

> 💡 **开源的意义**：企业可以在自己的基础设施上部署扣子核心组件，同时保留云端生态（技能商店、模板市场）——降低数据合规门槛，但开源版与云端版的完整度差异需要实测确认。

## 9. 局限与适用边界

| 局限 | 表现 | 应对 |
|------|------|------|
| 云端依赖 | 完整体验依赖云端（云电脑/云手机/技能商店） | 自托管只覆盖部分能力 |
| 平台锁定 | 工作流/技能难以直接迁移到代码框架 | 验证后按 09 篇迁移路线评估 |
| 深度定制 | 复杂状态/图编排/底层控制弱于代码框架 | 重逻辑场景用 LangGraph 等 |
| 版本迭代快 | 2.0→2.5→3.0 半年三版，功能变动大 | 以官方文档为准，追踪发布说明 |
| 企业治理 | 大规模团队下的 RBAC/审计能力需实测 | 企业版/私有化评估 |

> 🎯 **适用结论**：扣子 = **"零代码 + 演示 + 业务人员自建"三合一**——给业务方快速演示、让非技术同事自己搭 Agent、以及需要多 Agent 协作演示时，它是本体系五篇里最"无门槛"的选择。生产级深度定制仍要回到代码框架。

## 10. 核心要点

> 🎯 **核心要点**：
> 1. 扣子 3.0（2026-06-01）的定位从"Bot 生成器"升级为"AI 团队协作 OS"：项目空间 + 多 Agent 分工 + 本地 Agent 接入
> 2. 核心差异化能力：**Agent Skills**（领域 SOP 封装，无代码拖拽配置）+ **扣子编程**（Vibe Coding 云端开发）
> 3. 与开源阵营的定位差：扣子面向**业务人员零代码**，Dify/n8n 面向**技术使用者低代码**
> 4. 2025-07 已开源（Apache 2.0），但完整生态依赖云端——企业落地先确认自托管边界
