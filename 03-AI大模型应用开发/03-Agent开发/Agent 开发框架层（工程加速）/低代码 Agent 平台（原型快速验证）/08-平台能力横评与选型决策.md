## 2. 许可协议对比（企业红线）

| 平台 | 许可 | 商业使用限制 | 风险点 |
|------|------|-------------|-------|
| Dify | 修改版 Apache 2.0 | 可商用；**多租户托管给其他客户需书面许可**（无转售条款） | 做 SaaS 产品时先确认 |
| n8n | Sustainable Use License | 内部使用/修改免费；**对外商业化托管需商业协议** | 给客户部署时注意 |
| Langflow | MIT | 无限制（最宽松） | 无 |
| Flowise | Apache 2.0 | 无限制（当前） | Workday 收购后条款可能演进 |
| Coze 扣子 | Apache 2.0（开源部分） | 开源组件可商用 | 云端生态与开源版能力差需实测 |
| 百炼 | 云服务协议 | 按云服务条款 | 数据出云 |
| Copilot Studio | 订阅制 | 按席位许可 | 许可成本高、强制升级 |
| Lindy | SaaS 订阅 | 按订阅 | 数据过第三方、无自托管 |

> 🎯 **许可红线速查**：MIT（Langflow）> Apache（Flowise/Coze 开源）> 修改 Apache（Dify 注意转售条款）> Sustainable Use（n8n 注意商业化）> 云订阅（Lindy/Copilot Studio）。

## 3. 成本对比

### 3.1 自托管基础设施成本（~1000 次 AI 调用/天规模）

| 平台 | 内存要求 | 月基础设施成本估算 |
|------|---------|------------------|
| n8n | 1-2 GB 最低，2-4 GB 推荐 | $30-100/月（单容器 VPS） |
| Flowise | 1-2 GB | $30-100/月 |
| Langflow | 2-4 GB | $50-120/月 |
| Dify | 2-4 GB 最低，4-8 GB 推荐（多容器） | $100-200/月 |

> 对比：同规模托管 Cloud 约 $150-300/月——**自托管省 4-10 倍**（n8n 官方口径），但多容器平台（Dify）的运维成本需要算进人力。

### 3.2 云/SaaS 订阅价格锚点（2026-08）

| 平台 | 价格锚点 |
|------|---------|
| n8n Cloud | Starter ~€20/月（年付） |
| Dify Cloud | Sandbox 免费（限额）；Professional ~$59/月 |
| Lindy | Plus $49.99/月、Pro $99.99/月、Max $199.99/月（无免费档） |
| Relevance AI | 免费档 200 actions/月；Pro $19/月；Team $234/月 |
| Botpress | Free 100 对话/月；Plus ~$150/月（2026-05 重构后） |
| Voiceflow | 免费档 + 用量计费（免费档品类里最实用） |

> 💡 **成本心智**：AI 平台的成本大头永远在**模型调用**，平台订阅是小头——选型优先看"能不能用上你的模型 API（BYO Key）与成本可控性"，再看平台费。

## 4. 场景化选型决策树

```text
你的 Agent 想法，落到哪个平台？

① 数据能否出内网？
├─ 必须内网/私有化 → 开源自托管：Dify / n8n / Langflow / Flowise（按 ②③ 细分）
└─ 可以上云 →
    ├─ 国内合规 + 阿里云生态 → 百炼
    ├─ 字节生态 / 业务人员零代码 → Coze 扣子
    ├─ M365/Teams 存量 → Copilot Studio
    └─ 业务部门自己用 → Lindy / Relevance AI / Voiceflow

②（开源自托管）交付形态是什么？
├─ 完整产品（用户/密钥/RAG/分析）→ Dify
├─ 触发型业务自动化（连 CRM/邮件/DB）→ n8n
├─ Python 生态 / MCP 导出给编码 Agent → Langflow
└─ 聊天机器人快速 MVP → Flowise / Botpress

③（自托管）工程化与规模？
├─ 图级状态 / 复杂 HITL / 高并发 / 深度定制 → 直接代码框架（LangGraph 等，见 09 篇）
└─ 中等复杂度 → 上述平台即终态
```

**一句话版**：RAG 产品 → Dify；业务自动化 → n8n；Python/MCP → Langflow；零代码演示 → Coze；云生态 → 百炼/Copilot；业务自建 → Lindy。

## 5. 评分卡：同一需求在四平台实现对比

以"**客服知识库 Agent**"（问题分类 → RAG 检索 → 生成回答 → 满意度回访工单）为例：

| 环节 | Dify | Coze | n8n | Langflow |
|------|------|------|-----|----------|
| 知识库上传与分块 | 内置数据集，拖拽完成 | 上传即用 | 需外部向量库节点 | 组件拼装 |
| 问题分类 | Workflow 条件分支 | 工作流节点 | 条件节点 | 组件 |
| RAG 检索生成 | 内置检索节点+重排 | 知识库技能 | 向量库+LLM 节点 | 组件 |
| 回访工单 | HTTP/自定义工具 | 插件/工作流 | **原生 CRM 连接器** | 组件 |
| 上线 | Web App/API 一键 | 一键发布 | Webhook 接客服系统 | API 运行 |
| 评估 | 提示词调优+分析 | 平台分析 | Evals（2.33+） | 较弱 |
| 难度评级 | ★★ | ★（最低） | ★★★ | ★★★ |

> 🎯 **评分卡结论**：同一个需求，Coze 最快（业务人员可做），Dify 最完整（产品级交付），n8n 在"回访工单"这类系统连接环节最强——**选型看你的瓶颈环节在哪一层**。

## 6. 动手验证方法论：两周 PoC 评估法

不要只信对比表——用真实需求两周验证：

```text
第 1-2 天  需求切片：选 1 个最有代表性的核心流程（含 1 次 RAG + 1 次工具调用）
第 3-5 天  候选 2-3 个平台各实现一次（记录耗时/坑）
第 6-8 天  压力测试：并发 20 请求、长会话 50 轮、失败注入（断网/限流）
第 9-10 天 治理验证：权限模型、审计日志、密钥管理、成本统计
第 11-14 天 决策：按五维评分卡打分 + 迁移成本评估（见 09 篇）
```

**评估打分维度**（每项 1-5 分，加权）：
1. 功能匹配（30%）——核心需求覆盖度
2. 工程质量（20%）——稳定性、可观测、评估
3. 团队适配（20%）——构建者是技术还是业务
4. 成本与许可（15%）——总拥有成本 + 红线
5. 演进风险（15%）——锁定、收购、版本节奏

## 7. 常见选型误区

| 误区 | 真相 |
|------|------|
| "低代码 = 玩具，只能演示" | 2026 年低代码平台已生产化（Dify API 网关/Langflow DevOps/ n8n Queue Mode）——是否"玩具"取决于平台与场景匹配度 |
| "选一个平台就够了" | 51% 的 IT 负责人跑多供应商策略；用 MCP 互操作组合 2-3 个 |
| "画布都差不多" | 执行引擎差异巨大：DAG vs Agent 循环、内置 RAG vs 组件拼装、有沙箱 vs 无沙箱 |
| "开源 = 免费" | 自托管的人力运维成本常被忽略；且许可有商用红线（Dify 转售/n8n 商业化） |
| "SaaS 上手快就选它" | 锁定与迁移成本高（Lindy 一个 Agent 重建 1-3 小时）；数据合规先过 |
| "版本号新 = 更好" | 高频迭代平台（Dify 2-4 周一版）要盯破坏性变更（如 1.16 Responses 切换） |

## 8. 核心要点

> 🎯 **核心要点**：
> 1. 五维横评的结论一句话：**RAG 产品→Dify；业务自动化→n8n；Python/MCP→Langflow；零代码演示→Coze；云生态→百炼/Copilot；业务自建→Lindy**
> 2. 许可红线不能漏：Dify 转售条款、n8n Sustainable Use、Langflow MIT 最宽松——做 SaaS 前逐条确认
> 3. 自托管比云省 4-10 倍基础设施费，但多容器平台要算人力运维
> 4. 对比表只是起点——用"两周 PoC 评估法"以真实需求验证，按五维加权打分决策
