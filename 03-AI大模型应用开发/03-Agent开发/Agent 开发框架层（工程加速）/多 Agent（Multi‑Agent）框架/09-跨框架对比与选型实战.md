## 2. 核心机制逐项对比

| 机制 | LangGraph | CrewAI | MAF | AG2 | ADK |
|------|-----------|--------|-----|-----|-----|
| 编排范式 | 显式图（状态机） | 角色化 Crew | 群聊/层级 | 群聊/事件流 | 自由循环 + 2.0 工作流 |
| 多 Agent 推荐实现 | **subagents（@tool 包装）** | sequential/hierarchical | GroupChat | GroupChat/MemoryStream | 工作流节点 |
| 持久化 | checkpointer（time-travel） | checkpointing（1.14+） | 有 | 存储多后端 | 需显式外部存储 |
| HITL | interrupt() 四形态 | 全局配置（Flows） | 有 | HumanProxy 遗产 | 2.0 节点 |
| 记忆 | MemorySaver/InMemoryStore | 四类记忆（短/长/实体/上下文） | 有 | 多后端 | Memory Bank |
| 独特能力 | **time-travel 调试** | 角色抽象 + Flows | .NET 对称 | 事件驱动重构 | 多语言 + Vertex 集成 |

## 3. 同一需求：三框架实现对照

需求：**研究+写作+审查三 Agent 内容流水线**（Supervisor 模式）

| 环节 | LangGraph（subagents） | CrewAI | MAF |
|------|------------------------|--------|-----|
| 定义角色 | 3 个 `create_agent` | 3 个 `Agent(role=...)` | 3 个 `Agent(name=...)` |
| 编排 | 编排者 Agent + 3 个 @tool | `Process.hierarchical`（自动 Manager） | GroupChat |
| 路由 | 编排者选工具（模型决策） | Manager 自动分发 | 对话轮转 |
| 持久化 | `compile(checkpointer=...)` | `kickoff(from_checkpoint=...)` | 平台/自建 |
| 人工介入 | `interrupt()` 审批节点 | Flows 全局 HITL | HumanProxy 风格 |
| 难度 | ★★★（状态机） | ★（最快） | ★★ |

> 🎯 **对照结论**：同一个需求，CrewAI 一小时出活（但编排不可见），LangGraph 半天出活（编排完全显式可审计）——**原型选 CrewAI，生产编排透明性要求高选 LangGraph**。

## 4. 选型决策树回顾

```text
① 语言/云栈绑定？
├─ Google/多语言 → ADK
├─ Azure/.NET → MAF
├─ 无绑定 → ②
② 核心需求？
├─ 长流程/状态机/审计 → LangGraph
├─ 最快原型/内容流水线 → CrewAI
├─ 会话式转交 → OpenAI SDK
├─ 群聊/研究 → AG2
└─ 极简（2-4 角色）→ 单 Agent 工具化嵌套（06 篇）
```

## 5. AutoGen 存量迁移路线

```text
迁移决策树：
语言栈？
├─ Python 存量 AutoGen v0.2 代码
│   ├─ 求无缝 → AG2（API 兼容，pip install autogen 已指向）
│   └─ 求生产支持 → MAF（重写量中等）
├─ .NET → MAF
└─ 无存量包袱 → 直接选新框架（LangGraph/CrewAI）

迁移三步：
1. 盘点能力清单（GroupChat/HumanProxy/工具调用/人机交互模式）
2. 映射到新框架（群聊 → MAF GroupChat 或 AG2；Supervisor → LangGraph）
3. 评估成本模型（群聊 20+ 调用/交互 → 重构时问"真需要多 Agent 吗"）
```

> ⚠️ **时间窗口**：经典 AutoGen 2026 Q3 预期 API 弃用——存量项目建议 2026 年内完成迁移规划，避免弃用后安全补丁停滞。

## 6. 与低代码平台的对照

| 维度 | 代码多 Agent 框架 | 低代码平台多 Agent |
|------|------------------|-------------------|
| 代表 | LangGraph/CrewAI | Dify 多 Agent、Coze 3.0 团队协作 |
| 编排方式 | 代码显式图/角色 | 画布/对话配置 |
| 可控性 | ●●● | ●● |
| 上手 | 慢 | 快（业务人员可做） |
| 生产深度 | ●●●（持久化/审计） | ●●（平台内置部分） |
| 协作范式 | Supervisor/Swarm 等 | Agent 节点嵌套/团队空间 |
| 适用阶段 | 生产/复杂 | 验证/中等 |

> 💡 **协同用法**：低代码平台验证多 Agent 需求（Coze 3.0 的 @多 Agent 协作）→ 验证后迁移代码框架（LangGraph）；或平台管确定性流程 + 代码框架管复杂决策（详见[低代码模块 09 篇](../低代码%20Agent%20平台（原型快速验证）/09-原型快速验证实战：从验证到迁移.md)）。

## 7. 两周验证法

```text
第 1-2 天  需求切片：1 个核心多 Agent 闭环（含 1 次路由 + 1 次移交）
第 3-5 天  候选 2 框架各实现一次（记录耗时/坑）
第 6-8 天  编排健壮性：路由错误注入、移交循环、中间失败
第 9-10 天 持久化验证：中断恢复、回放、审计
第 11-14 天 决策：五维评分卡 + 成本模型（token 估算）

评分维度（加权）：编排表达力 25% / 持久化 20% / 可观测 15% /
               团队适配 15% / 成本 15% / 演进风险 10%
```

## 8. 核心要点

> 🎯 **核心要点**：
> 1. 横评一句话：**生产编排 → LangGraph；最快原型 → CrewAI；Google 栈 → ADK；微软栈 → MAF；会话转交 → OpenAI SDK**
> 2. 同一需求三实现对照：CrewAI 小时级出活但编排不可见，LangGraph 半天级出活但完全可审计——按"编排透明性"需求取舍
> 3. AutoGen 存量：Python 无缝 → AG2；生产支持 → MAF；2026 Q3 弃用前完成迁移规划
> 4. 与低代码平台是互补关系：平台验证 → 框架生产；别忘"单 Agent 工具化嵌套"轻量方案
