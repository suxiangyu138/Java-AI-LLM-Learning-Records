## 1. 面试题（10 题带答案范式）

> 面试高频题集中在三块：**多 Agent 值不值得**、**范式与防失控**、**2026 框架格局**。

### Q1：什么时候该用多 Agent？什么时候不该用？

**答案范式（判断清单）**：
```text
该拆：角色差异大（研究/写作/审查）、需并行独立子任务、
      专业领域隔离（提示词/工具隔离）、独立状态边界、清晰人机协作点
不该拆：同一角色重复工作、串行单链路、上下文可共享、
        无人工介入需求 → 单 Agent + 工具链更优
一句话：多 Agent 是手段不是目的；成本通常数倍于单 Agent，
        先问"一个 Agent + 好工具链能否解决"
```

### Q2：多 Agent 编排有哪些模式？各适合什么规模？

**答案范式（五模式速答）**：
```text
Supervisor（中心化，3-10）：编排者路由分发，企业最常见，可追踪
Swarm（去中心化，5-15）：handoff 直接移交，适合开放式对话，需强护栏
Handoff 链（顺序，2-5）：任务依次传递，简单可预测
Router（分类分发，1-3）：一次分类调用决定分支
层级网络（10-30+）：Supervisor 嵌套 Supervisor
经验：90% 场景用 Supervisor 或 Router 就够
```

### Q3：Swarm 模式有什么风险？怎么防？

**答案范式（四件套护栏）**：
```text
风险：移交循环（无限烧钱）、死胡同（无人可接）、无界移交
护栏：① 循环检测（拒绝移交给 trace 中已出现的 peer）
     ② Hop 预算（MAX_HOPS 硬上限）
     ③ 死胡同升级（无 peer 匹配时走兜底）
     ④ 人工升级（循环/死胡同/预算耗尽 → Human 节点）
⚠️ 护栏是成本控制的一部分：无护栏的 swarm 失败模式是静默烧钱
```

### Q4：LangGraph 2026 年有什么重要变化？

**答案范式（三个变化）**：
```text
① langgraph-supervisor 包弃用 → subagents 模式：
   create_agent 编排者 + Worker 包装为 @tool（subagent.invoke）
   统一"工具调用 = 子 Agent 调用"心智
② @langchain/langgraph-swarm npm v1.0.2（JS 侧 swarm）
③ SDK 0.3.14（2026-05）；checkpointer 成为强制项（swarm 无它即失忆）
额外：time-travel 调试仍是独有能力（回退→改状态→重放）
```

### Q5：AutoGen 现在是什么状态？新项目还能用吗？

**答案范式（三分裂）**：
```text
AutoGen 已三分裂：
① 经典 AutoGen：维护模式（2025-10 起），2026 Q3 预期 API 弃用
② AG2：社区 fork（原班人马），Apache 2.0，向 v1.0，
   pip install autogen 已指向它，事件驱动（MemoryStream）
③ Microsoft Agent Framework：官方继任者（AutoGen+SK 合并），
   1.0 GA（2026-04-03），MIT，Python/.NET
新项目跳过 AutoGen：Python 续接用 AG2，Azure 企业用 MAF，
其余选 LangGraph/CrewAI
```

### Q6：LangGraph 和 CrewAI 怎么选？

**答案范式（一句话定位差）**：
```text
LangGraph = 显式图状态机：生产编排标杆（~38% 份额）、
            checkpointer/time-travel、可观测最成熟
CrewAI = 角色化抽象：原型最快（小时级）、Flows 生产化、
         但编排不可见、可观测弱
判据：编排透明性/审计要求高 → LangGraph；最快出活 → CrewAI
      （原型验证后可迁 LangGraph）
```

### Q7：多 Agent 系统的成本为什么高？怎么控制？

**答案范式（四大放大器 + 四控制）**：
```text
放大器：① 重复上下文（多 Agent 重复读同一上下文，最大头）
       ② 角色扮演开销（CrewAI role/backstory 提示词膨胀）
       ③ 移交开销（handoff 传整个会话）
       ④ 无界循环（无预算的 swarm）
控制：模型分层（强模型编排 + 廉模型干活）、上下文最小化、
      移交瘦身（传摘要）、hop/轮次/token 硬预算
```

### Q8：MCP 和 A2A 什么区别？多 Agent 里各起什么作用？

**答案范式（两层协议）**：
```text
MCP = Agent↔工具协议（请求-响应，97M+ 月下载，事实标准）
A2A = Agent↔Agent 协作协议（Agent Card 发现 / Task 生命周期 /
      流式更新 / poll-stream-push）
多 Agent 中：MCP 解决"工具共享与子 Agent 即工具"，
            A2A 解决"跨厂商编排"（LangGraph 编排者 → ADK/ CrewAI）
同框架内不需要 A2A（对象调用更快）；异构接入才需要
```

### Q9：多 Agent 的可观测要注意什么？

**答案范式（嵌套追踪）**：
```text
① 追踪 ID 贯穿全链路（一次用户请求一个 traceId）
② 每次路由/移交记录（from/to/reason/result）
③ 失败信号（移交失败、循环触发、hop 耗尽、人工升级）
④ 关键：子 Agent 嵌套调用日志必须支持嵌套展开——
   扁平日志无法定位"哪个子 Agent 失败导致整体失败"
```

### Q10：2026 年多 Agent 框架格局一句话总结？

**答案范式（格局 + 趋势）**：
```text
四强 + 双原生：LangGraph（生产 ~38%）/ CrewAI（原型 ~12%）/
              MAF（微软栈）/ ADK（Google 栈）+ OpenAI/Claude 原生
三趋势：① 价值向运营迁移（可观测/评估比框架选型重要）
       ② 记忆全体未解（无生产级长期记忆）
       ③ 协议收敛（MCP 工具层 + A2A 协作层成为标配）
Gartner：2026 年底 40% 企业应用含任务特定 AI Agent
```

## 2. 自测题（20 道）

### 基础（1-8）

1. 2026 Q1 生产部署份额第一的多 Agent 框架是？约多少？
2. AutoGen 三分裂指哪三个实体？各自状态？
3. Microsoft Agent Framework 1.0 GA 的时间？由什么合并而来？
4. CrewAI 四大原语是什么？
5. LangGraph 2026 弃用了哪个包？推荐什么模式替代？
6. Google ADK 支持哪四种语言的 SDK？
7. ADK 2.0 workflow runtime 补齐了什么能力？
8. 经典 AutoGen 的 v0.7.5 是什么节点？

### 范式（9-14）

9. Supervisor 与 Swarm 的核心区别？
10. Swarm 的四件套护栏是什么？
11. "子 Agent 包装为 @tool" 属于哪个模式？优点是什么？
12. Router 与 Supervisor 的适用差异？
13. Handoff 链适合多少 Agent？典型场景？
14. 层级网络适合什么规模？

### 生产（15-20）

15. 多 Agent 成本四大放大器是什么？
16. 模型分层的做法是什么？（编排者/Worker 的模型策略）
17. 多 Agent 评估的五个编排层指标是什么？
18. 为什么说"没有任何框架达到生产级长期记忆"？自建要点？
19. MCP 与 A2A 各解决什么问题？
20. 存量 AutoGen 项目两个迁移选项？各自适用？

### 自测答案速查

1. LangGraph，~38%（2026 Q1 估计）
2. 经典 AutoGen（维护模式）/ AG2（社区 fork，活跃）/ MAF（官方继任者）
3. 2026-04-03；AutoGen + Semantic Kernel 合并
4. Agent / Task / Crew / Process
5. langgraph-supervisor 包；subagents 模式（子 Agent 包装为 @tool）
6. Python / Java / Go / TypeScript
7. 确定性执行 / Fan-out / 重试 / HITL
8. 最后一个带新功能的版本（2025-09-30）；此后维护模式
9. 中心化路由 vs 去中心化 handoff 移交；Swarm 灵活但需护栏
10. 循环检测 / 死胡同升级 / Hop 预算 / 人工升级
11. subagents 模式；统一"工具调用=子 Agent 调用"心智，可复用可追踪
12. Router 一次分类分发即结束；Supervisor 编排者全程参与决策
13. 2-5 个；数据清洗→分析→报告等顺序流水线
14. 10-30+ Agent 的组织型编排
15. 重复上下文 / 角色扮演开销 / 移交开销 / 无界循环
16. 强模型（Opus 级）做编排，快/廉模型（Haiku 级）做 Worker
17. 路由准确率 / 移交次数分布 / 循环触发率 / 每任务 token / 人工介入率
18. 语义检索+剪枝未生产级；自建：只存决策结论 + 召回过滤 + 定期剪枝 + 审计
19. MCP=Agent↔工具（事实标准）；A2A=Agent↔Agent（跨厂商协作）
20. AG2（无缝，API 兼容）/ MAF（生产支持，重写量中等）

## 4. 核心要点

> 🎯 **核心要点**：
> 1. 面试主战场：**值不值得拆**（判断清单）、**范式**（五模式+护栏）、**2026 格局**（AutoGen 三分裂/份额）
> 2. 时效性是加分项：LangGraph subagents 取代、MAF 1.0 GA、ADK 2.0 是 2026-08 的"当前事实"
> 3. 生产题答运营：记忆未解、可观测嵌套、成本四放大器、护栏=成本控制
> 4. 本模块毕业标准：**能独立判断一个需求是否拆多 Agent、选对范式与框架、并给出防失控与成本方案**
