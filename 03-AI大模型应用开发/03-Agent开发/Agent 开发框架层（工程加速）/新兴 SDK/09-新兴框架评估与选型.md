## 1. 评估的起点：先定义问题

```text
评估新框架前的三问（先于看框架）：
① 当前方案的痛点是什么？（性能/体量/生态/控制力）
② 新框架声称解决什么？（对比主流框架的差异化）
③ 痛点是否值得迁移成本？（学习/迁移/生态损失）

如果三问答不上来 → 不需要新框架（雷达记录即可）
答得上来 → 进入评估雷达
```

> 🎯 **评估的本质**：不是"这个框架好不好"，而是"**这个框架的差异化是否命中我的真实痛点**"。

## 2. 评估雷达：五问五查

```text
五问（功能层）：
① 解决了吗？——差异化是否真实（还是主流框架也能做）
② 生产证据？——有无真实生产部署（不是 demo/基准宣称）
③ 边界在哪？——体量/能力/生态的限制是什么
④ 兼容如何？——MCP/A2A 接入、模型 provider、语言栈
⑤ 治理如何？——沙箱/策略/检查点是否内建

五查（工程层）：
① star/commit/issue 响应（活跃度，警惕刷星）
② 许可证（MIT/Apache/自定义——商用红线）
③ 安全审计（CVE 修复记录、沙箱评估）
④ 维护者（公司背书 vs 单人——bus factor）
⑤ 文档质量（示例/教程/API 稳定度）
```

## 3. 量化评分卡

| 维度 | 权重 | 打分要点（1-5） |
|------|:---:|----------------|
| 痛点命中 | 25% | 差异化是否命中你的真实问题 |
| 生产就绪 | 20% | 生产部署证据、稳定性 |
| 工程健康 | 15% | 活跃度、维护者、许可 |
| 集成成本 | 15% | MCP/A2A、模型 provider、语言栈 |
| 迁移成本 | 15% | 学习曲线、生态损失 |
| 演进风险 | 10% | 版本波动、被收购/停更风险 |

> 💡 **打分纪律**：权重固定、证据驱动（没证据 = 低分）；总分 < 3.5 不采用；3.5-4 试用；≥4 可立项。

## 4. 采用决策树：用 vs 不用的边界

```text
新框架值得采用吗？
├─ 主流框架可解决（差异不真实）→ 不采用（主流框架 + 最佳实践）
├─ 解决但只是"更轻"（体量优势）→ 权衡：轻量的代价（生态/配套）
│   ├─ 学习/教学/嵌入 → 可用（PocketFlow 类）
│   └─ 生产系统 → 谨慎（需自补运行时能力）
├─ 解决且"新能力"（自进化/技能结晶等）→ 局部借鉴或小范围试点
└─ 解决且"新范式"（Agent OS/协议）→ 关注趋势，等成熟（协议层可先行）

边界一句话：生产系统默认主流框架；
          新框架用于 学习/教学/嵌入/试点/借鉴机制
```

## 5. 回到主流：什么时候主流框架更优

| 场景 | 选择 | 理由 |
|------|------|------|
| 生产多 Agent 编排 | LangGraph | 持久化/可观测/审计最成熟 |
| 快速原型 | CrewAI | 角色化小时级出活 |
| 生产工具链 | Claude Code 系 | 生态最完整 |
| 跨厂商协作 | A2A v1.0 协议 | 标准先行 |
| 平台能力接入 | 百炼 CLI 等 | 能力即服务 |
| 新兴框架 | 学习/试点/借鉴 | 雷达心态 |

> 🎯 **结论**：新兴 SDK 的正确位置是"**主流的补充**"——它给主流框架注入新机制（策略内建、技能结晶、协议化），但 2026 年生产主干仍是主流框架。

## 6. 踩坑清单

| 坑 | 表现 | 避免 |
|----|------|------|
| 刷星陷阱 | 高 star 无实质维护 | 看 commit 与 issue 响应 |
| 宣称迷信 | 基准分数当生产证据 | 独立复现 + 真实工作流 |
| 单人依赖 | 核心维护者退出即停更 | 评估 bus factor，选公司背书 |
| 体量迷信 | "100 行"当"生产就绪" | 轻量 ≠ 可靠，运行时能力另算 |
| 生态错觉 | 框架火 = 生态全 | 确认连接器/集成真实存在 |
| 无许可 | 无 License 不能商用 | 商用前逐条确认 |

## 7. 两周验证法（新兴框架版）

```text
第 1-2 天  痛点定义 + 雷达评估（五问五查 + 评分卡）
第 3-5 天  用真实需求的最小闭环实现（对比主流框架同实现）
第 6-8 天  可靠性：失败注入（断网/限流/长会话）
第 9-10 天 治理验证：沙箱/策略/检查点是否内建可用
第 11-14 天 决策：评分卡 + 迁移成本 + 生态影响
```

## 8. 核心要点

> 🎯 **核心要点**：
> 1. 评估起点是**痛点定义**，不是框架清单——差异化不命中痛点就不需要
> 2. 评估雷达：五问（差异化/生产证据/边界/兼容/治理）+ 五查（活跃度/许可/安全/维护者/文档）
> 3. 评分卡权重固定、证据驱动；<3.5 不采用，≥4 可立项
> 4. 新兴框架的位置 = 学习/试点/借鉴；**生产主干默认主流框架**
> 5. 防六坑：刷星/宣称/单人/体量/生态/许可
