# LLM 大脑：推理决策核心

> 四大组件之"大脑"：模型 + 提示词构成推理决策核心。2026 年的选型已经从"选最强模型"变成"按角色分工选模型"——规划用强推理，执行用便宜模型，成本与质量兼得。

## 1. 大脑的职责边界

| 职责 | 具体 | 非职责（别让大脑干） |
|---|---|---|
| 决策 | 下一步行动、工具选择 | 不该由它保证正确性（用工具校验） |
| 推理 | 理解目标、推导结论 | 不该由它记忆（用记忆组件） |
| 计划 | 任务分解（与规划组件协作） | 不该由它执行（用行动组件） |
| 评估 | 反思结论（与反思组件协作） | 不该由它扛全部质量（组件各负其责） |

> 🎯 核心要点：**大脑只做"决策"一件事**——把记忆、规划、执行、校验交给其他组件，模型输出就只是"下一步动作"，边界清晰才可调试。

## 2. 模型选型：按角色分工（2026 共识）

| 角色 | 推荐模型档位 | 理由 | 参考 |
|---|---|---|---|
| 规划器/主决策 | 前沿推理模型 | 分解与推理质量决定上限 | GPT-5/Claude Sonnet/DeepSeek V4 |
| 执行器 | 便宜模型（可 14B 开源） | 执行是模式化工作，贵模型浪费 | Qwen3/Llama 开源 |
| 反思器 | 中档推理模型 | 评估需要推理但不需最强 | 中档 |
| 工具密集任务 | 工具调用强模型 | schema 遵循能力 > 通用智能 | Function Calling 基准 |

```text
经典分工：前沿模型规划（每任务 1-2 次调用）
         + 便宜模型执行（每步骤 1 次调用）
         成本下降显著、质量不降（2026 实测共识）
```

## 3. 推理能力：从"直接答"到"想好了再答"

| 模式 | 机制 | 适用 | 成本 |
|---|---|---|---|
| 直接生成 | 一步出答案 | 简单任务 | 最低 |
| CoT（思维链） | 先推理后回答 | 中等复杂 | 中 |
| 推理模型（Reasoming） | 模型内部长思维（DeepSeek R1 类） | 复杂推理/规划 | 高（thinking tokens） |
| 多步循环 | Agent 循环多轮决策 | 任务型 | 最高 |

| 选型 | 何时用 |
|---|---|
| 普通模型 + 提示词 CoT | 大多数业务场景（可控、便宜） |
| 推理模型 | 数学/代码/长链规划（DeepSeek V4 等性价比高） |
| 推理模型 + 工具 | 复杂 Agent（2026 主流：DeepSeek/Claude thinking + 工具循环） |

> ⚠️ 推理模型的 thinking tokens 会拉高延迟与成本——**简单任务别开 thinking**（API 支持按需开关）；工具调用场景注意 reasoning_content 回传（部分厂商不传会 400，见 Function Calling 体系）。

## 4. 决策风格：temperature 与采样参数

| 参数 | Agent 场景建议 | 理由 |
|---|---|---|
| temperature | 0-0.3（决策）| 决策要稳定可复现 |
| 0.7-1.0（创意生成） | 头脑风暴类任务 |
| top_p | 保持默认/0.9 | 少调 |
| max_tokens | 按角色设定 | 规划输出 JSON 需留足空间 |
| seed/缓存 | 可复现场景用 | 测试与 A/B |

> 💡 经验法则：**Agent 里 90% 的调用应接近确定性（temperature≤0.3）**——把"创造性"留给专门的创意任务，不要污染决策链路。

## 5. 结构化输出：大脑与组件的契约

| 场景 | 结构化要求 | 实现 |
|---|---|---|
| 规划组件 | JSON 步骤列表（step/summary/action） | 强制 JSON Schema |
| 工具调用 | tool_calls 结构（协议级） | Function Calling 原生 |
| 反思组件 | 结论+理由+建议 | JSON Schema |
| 最终回答 | 答案+引用 | 结构化输出（answer/citations） |

```python
# 示例：规划输出的 JSON Schema（大脑→规划组件契约）
PLAN_SCHEMA = {
    "type": "object",
    "properties": {
        "steps": {"type": "array", "items": {
            "type": "object",
            "properties": {
                "step": {"type": "integer"},
                "summary": {"type": "string"},   # 步骤目标
                "action": {"type": "string"},    # 动作类型
                "tool": {"type": "string"}       # 建议工具（可空）
            },
            "required": ["step", "summary"]}}},
    "required": ["steps"]
}
```

> 💡 结构化输出是"组件间契约"的实现载体——大脑的每个产出都有 schema，其他组件才能稳定消费（详见 Function Calling 体系的结构化输出篇）。

## 6. 大脑的提示词工程要点

| 要点 | 做法 |
|---|---|
| 角色定位 | 明确"你是决策者，不是执行者" |
| 决策输入 | 只喂决策需要的信息（记忆管理器裁剪） |
| 输出约束 | 结构化 schema + 只输出 JSON |
| 工具说明 | 每个工具描述"做什么/何时用/边界"（schema 比模型重要） |
| 失败指令 | 工具失败时的下一步指示 |
| 上下文预算 | 提示词主体冻结（利于缓存，降本 50-90%） |

> 🎯 核心要点：大脑的设计原则是**"决策信息完备、决策动作单一、输出契约明确"**——提示词冻结 + 工具描述打磨 + 结构化输出，三者是 2026 年"大脑调优"的三大杠杆，优先级高于换模型。

## 7. 大脑组件的可观测性

| 指标 | 信号 |
|---|---|
| 每任务决策轮数 | 过多 → 规划/记忆问题（不是模型问题） |
| 决策改变率 | 反复推翻 → 上下文不稳/推理弱 |
| 工具选择正确率 | 下降 → schema 描述待改 |
| 思维链质量抽检 | 人工抽查决策理由 |
| 成本/任务 | 超预算 → 角色分工调整（换便宜执行器） |

## 8. 本地模型 vs 云模型（大脑选型的第二维）

| 维度 | 云模型 | 本地/自托管 |
|---|---|---|
| 推理能力 | 前沿（GPT-5/Claude/DeepSeek V4） | 中档（Qwen3/Llama/GLM 开源） |
| 数据合规 | 需评估出境 | 数据不出内网 |
| 延迟 | 网络往返 | 取决于 GPU |
| 成本 | 按 token | 固定 GPU + 电费 |
| 工具调用 | 原生强 | 中档开源已可用（14B+） |
| 适用 | 生产高价值 | 合规/降本/离线 |

| 场景 | 推荐 |
|---|---|
| 对外产品主决策 | 云前沿模型 |
| 涉密/合规 | 本地 32B+ 开源 |
| 批量执行器 | 本地 14B 开源（便宜量大） |
| 混合 | 规划云、执行本地（成本最优） |

## 9. 大脑的常见坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 决策输入不全 | 模型反复问"信息在哪" | 检查记忆注入与工具返回 |
| 决策输入过载 | 模型迷失/忽略关键指令 | 记忆管理器裁剪 |
| 输出不规范 | 解析失败/字段缺失 | 强制 JSON Schema + strict |
| 简单任务开 thinking | 延迟成本翻倍 | 按任务开关推理模式 |
| 提示词经常改 | 缓存失效成本涨 | 冻结 system 层，变化走变量 |
| 模型不跟工具描述 | 乱调工具 | 打磨描述（比换模型有效） |
