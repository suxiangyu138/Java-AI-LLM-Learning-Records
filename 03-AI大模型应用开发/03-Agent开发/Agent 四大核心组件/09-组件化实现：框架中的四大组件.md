# 组件化实现：框架中的四大组件

> 四组件是概念，框架是实现。本章给出主流框架（LangChain/LangGraph/Spring AI/LangChain4j/轻量自研）中四组件的映射表与实现骨架——会映射，才能在框架间自由迁移。

## 1. 框架 × 四组件映射表

| 框架 | LLM 大脑 | 规划 | 记忆 | 工具 |
|---|---|---|---|---|
| LangChain | ChatModel/Agent | AgentExecutor 循环 | Memory 接口（Buffer/Summary） | Tool 接口 + Toolkit |
| LangGraph | 节点中的 LLM | 图节点显式编排 | Checkpointer + Store | ToolNode |
| Spring AI | ChatClient | Agent Advisors（编排） | ChatMemory 接口 | @Tool 注解 |
| LangChain4j | ChatLanguageModel | AiServices + Tool Execution | ChatMemoryStore | @Tool 注解 |
| 轻量自研 | 任意模型 API | 手写循环 | 自管存储 | 注册表（06 篇） |

> 🎯 核心要点：**框架差异在"编排层"，四组件本体各框架大同小异**——会一个框架的四组件，迁移到另一个只是换个 API 名。

## 2. LangGraph：显式图编排（生产主流）

```python
from langgraph.graph import StateGraph, END
from langgraph.checkpoint.memory import MemorySaver

def decide(state):        # 大脑：下一步决策
    return {"next": "tools" if state.get("plan") else "planner"}

def planner(state):       # 规划组件
    return {"plan": plan_model.invoke(...)}

def tools_node(state):    # 工具/行动组件
    return {"observation": execute_tool(state)}

def reflect(state):       # 反思组件
    return {"plan": replan(state)}     # 重规划回写

graph = StateGraph(State)
graph.add_node("planner", planner).add_node("tools", tools_node).add_node("reflect", reflect)
graph.add_edge("planner", "tools").add_edge("tools", "reflect")
graph.add_conditional_edges("reflect", decide, {"tools": "tools", END: END})
app = graph.compile(checkpointer=MemorySaver())   # 记忆：检查点
```

| LangGraph 机制 | 对应组件 |
|---|---|
| 图节点 | 组件编排 |
| State | 工作记忆（任务状态） |
| Checkpointer | 情景记忆（断点恢复） |
| Store | 长期记忆（跨线程 KV） |
| Conditional edges | 大脑决策路由 |

## 5. 轻量自研：四组件最小实现

```python
class MiniAgent:
    def __init__(self, llm, tools: dict, memory, max_steps=8):
        self.llm, self.tools, self.memory = llm, tools, memory
        self.max_steps = max_steps

    def run(self, goal: str) -> str:
        context = self.memory.load(goal)          # ① 记忆召回
        for i in range(self.max_steps):
            decision = self.llm.decide(goal, context)   # ② 大脑决策
            if decision["type"] == "answer":
                self.memory.save(goal, decision["text"])  # ⑤ 记忆回写
                return decision["text"]
            tool_name = decision["tool"]; args = decision["args"]
            result = call_tool(self.tools, tool_name, args)   # ③ 工具执行
            context.append(f"观察：{result}")      # ④ 观察回传
        return "达到步骤上限"
```

| 自研要点 | 说明 |
|---|---|
| 决策结构化 | 工具调用/回答二选一（JSON） |
| 记忆接口 | load/save 两个方法（可换实现） |
| 步骤上限 | 必须（防死循环） |
| 观察精炼 | 截断但不失真 |

> 💡 自研的价值是"把四组件边界刻在骨子里"——建议学习者手写一遍 50 行 MiniAgent，再进框架就不迷路（与[阶段 1：手写极简 Function-call Agent](../阶段%201：手写极简%20Function‑call%20Agent/00-阶段总览：手写极简Function-call%20Agent.md) 呼应）。

## 6. 组件接口设计建议（可移植性）

| 组件 | 建议接口 |
|---|---|
| 记忆 | `load(key) -> list` / `save(key, content)` / `search(query, top_k)` |
| 工具 | `name/description/schema/execute(params) -> result`（06 篇） |
| 规划 | `plan(goal, context) -> steps` / `replan(goal, plan, observation)` |
| 反思 | `reflect(goal, trace) -> verdict`（有 oracle 才接） |

```text
接口稳定的收益：引擎可换（OpenAI↔DeepSeek↔本地）、
                记忆可换（Redis↔PG↔Mem0）、工具可换（自研↔MCP）
                ——组件级解耦，Agent 才可演进
```

## 6.5 组件契约清单（框架迁移的通行证）

| 组件 | 接口契约 | 迁移时检查 |
|---|---|---|
| 记忆 | load/save/search | 各框架 Memory 接口映射 |
| 工具 | name/desc/schema/execute | 注解 vs 类 vs 注册表 |
| 规划 | plan/replan | 显式节点 vs 循环内嵌 |
| 反思 | reflect（oracle 可选） | 钩子/节点位置 |
| 状态 | 消息/计划/预算 | State schema 统一 |

```text
迁移步骤建议：
  ① 先按契约抽出组件实现（与框架解耦）
  ② 再写新框架的适配层（几行代码的事）
  ③ 最后切框架，跑回归（任务成功率 + 成本基线）
  组件契约化 = 框架切换零重写
```

## 7. 框架选型速查

| 需求 | 选型 |
|---|---|
| Python 生产、复杂图编排 | LangGraph |
| Python 快速开发 | LangChain Agent |
| Java 后端 | Spring AI / LangChain4j |
| 学习底层 | 手写 MiniAgent（50 行） |
| 多 Agent 复杂系统 | LangGraph + 专用运行时 |

> 🎯 核心要点：**框架选型看"编排层"不看"组件层"**——四组件到处都有，差异在编排表达力（图 vs 链 vs 声明式）与生态（MCP/记忆产品接入）。把四组件接口设计好，框架只是外壳。

## 8. 框架迁移案例：LangChain → LangGraph

| 步骤 | LangChain 写法 | LangGraph 写法 |
|---|---|---|
| 记忆 | `ConversationBufferMemory` | Checkpointer（自动） |
| 工具 | `toolkit.get_tools()` | ToolNode 注册 |
| 循环 | AgentExecutor 隐式 | 显式图（可控） |
| 反思 | 无内建 | 自定义 reflect 节点 |
| 状态 | 消息列表 | State schema（显式） |

| 迁移注意 | 说明 |
|---|---|
| 记忆迁移 | Buffer 内存态 → Checkpointer 持久态（行为变化要测） |
| 工具迁移 | 工具类可复用，注册方式不同 |
| 循环控制 | 隐式 → 显式是最大收益（可加预算/审批节点） |
| 回归 | 任务成功率 + 成本基线对比后再切 |

> 💡 LangGraph 的核心价值不是"更高级"，是**把循环变成显式图**——预算节点、审批节点、反思节点都成为可加可删的图元素，这正是四组件"编排层"的表达力所在。迁移时保留 LangChain 的工具类与提示词（组件层不变），只重写编排层，回归成本最低。
