# 生产实践与面试冲刺

> 从"组件齐全"到"组件可靠"：组件监控、预算治理、12 避坑、面试题与落地检查单——四大组件体系收官篇。

## 1. 组件级调优顺序（先修什么）

```text
① 记忆（上下文对不对）→ ② 工具（执行灵不灵）
→ ③ 规划（分解好不好）→ ④ 反思（校准有没有）
→ ⑤ 模型（决策强不强）← 最后才换
```

| 优先级 | 组件 | 典型修复 | 成本 |
|---|---|---|---|
| 1 | 记忆 | 注入裁剪、记忆管理器 | 低 |
| 2 | 工具 | schema 打磨、错误回传 | 低 |
| 3 | 规划 | 分解粒度、Replan 触发 | 中 |
| 4 | 反思 | 接 oracle、独立评判器 | 中 |
| 5 | 模型 | 换强推理模型 | 高 |

> 🎯 核心要点：**大多数"Agent 不行"是前三项**——先按组件归因再花钱换模型，这是 2026 年 Agent 调优的第一方法论。

## 2. 生产基线（四组件）

| 组件 | 基线 |
|---|---|
| 大脑 | temperature≤0.3、结构化输出、提示词冻结（缓存友好） |
| 规划 | 步骤上限 8-12、目标锚定、Replanner 上下文裁剪 |
| 记忆 | 分层 + 管理器、有界读取、claim 生命周期、PII 脱敏 |
| 工具 | schema 三件套（做什么/何时用/边界）、参数校验、审计 |
| 行动 | 超时、重试退避、Step Budget、写操作审批 |
| 跨组件 | 请求 id 贯穿、组件级事件流、成本/任务监控 |

## 3. 预算治理（2026 硬需求）

| 层 | 预算 | 防什么 |
|---|---|---|
| 单次调用 | max_tokens 限制 | 单次输出失控 |
| 单任务 | 步骤上限 8-12 | 循环 |
| 单任务 | 成本上限（$ 或 token） | 50-500 次级联（$5-50 事故） |
| 会话 | 总 token 预算 | 长会话烧钱 |
| 账户 | 每日限额 | 全局限流 |

```text
预算配置四件套：步骤数 + 成本上限 + 时间上限 + 用户中断
少一个 = 有一个洞（最常漏的是成本上限）
```

## 4. 12 避坑清单

| # | 坑 | 后果 | 解法 |
|---|---|---|---|
| 1 | 无记忆管理器全量注入 | 上下文爆炸、信噪崩塌 | 分层记忆 + 优先级装配 |
| 2 | 工具描述含糊 | 模型乱选工具 | schema 三件套打磨 |
| 3 | 模型输出不校验直接执行 | 参数注入/越权 | 执行层重新校验 |
| 4 | 写操作无审批 | 不可逆事故 | HITL + 幂等（07 篇） |
| 5 | 无 Step Budget | $5-50 级联烧钱 | 预算四件套 |
| 6 | 反思无 oracle | 自我确认偏差 | 有可验证基准才加反思 |
| 7 | 把重试当反思 | 失败原因没变重复失败 | 先归因再决定重试/反思 |
| 8 | Planner 塞全部历史 | context blow-up | 只传必要状态 |
| 9 | 目标不锚定 | goal drift（子代理跑偏） | 每轮 replan 注入原目标 |
| 10 | 静态计划硬撑动态任务 | 观察不符计划仍执行 | 观察驱动重规划 |
| 11 | 问题都怪模型 | 组件真问题没修 | 组件级归因（08 篇 4 节） |
| 12 | 无组件级可观测 | 故障无法回放 | 组件事件流 + 请求 id |

## 5. 面试题（高频 12 题 + 答题要点）

| 题 | 答题要点 |
|---|---|
| 1. Agent 由哪四大组件构成？ | LLM 大脑（推理决策）+ 规划（任务分解）+ 记忆（上下文）+ 工具行动（执行）；反思在循环中校准 |
| 2. 四组件怎么协作？ | ReAct 循环：决策→执行→观察→记忆回写→反思→重规划；计划有状态、失败有归因 |
| 3. Plan-and-Execute 和 ReAct 区别？ | PnE 规划执行分离（长任务、前沿规划+便宜执行）；ReAct 边想边做（短任务默认）；静态可预知用 ReWOO 最省 |
| 4. 反思什么时候不该加？ | 无可验证 oracle 时——自我评估退化为自我确认偏差；有测试集/编译器/标准答案才值得 |
| 5. 记忆为什么分层？ | 工作记忆（上下文，要省）/情景（会话，要全）/长期（跨会话，要准）；记忆管理器挑最小有用包 |
| 6. 上下文超窗怎么处理？ | 有界读取 + 滚动摘要 + 工具结果截断 + 记忆管理器装配优先级；提示词冻结利于缓存 |
| 7. 工具调用失败怎么处理？ | 瞬时错误退避重试；逻辑错误回传模型调整（脱敏+建议）；写操作幂等后才能重试；预算内终止 |
| 8. 怎么防止 Agent 失控烧钱？ | Step Budget 四件套：步骤数+成本+时间上限+用户中断；每层循环都有上限 |
| 9. 目标漂移怎么防？ | 原始目标锚定（每轮 replan 注入）+ 计划状态可见 + 里程碑检查 |
| 10. 组件排查怎么归因？ | 答非所问→记忆；步骤乱序→规划；工具失败→工具；重复失败→反思；死循环→终止条件 |
| 11. 框架怎么映射四组件？ | LangGraph（节点=编排/State=工作记忆/Checkpointer=情景/Store=长期）；Spring AI（ChatClient/@Tool/ChatMemory/Advisor） |
| 12. 模型选型怎么分工？ | 规划用前沿、执行用便宜（成本降质量不降）；简单任务别开 thinking；工具密集看 Function Calling 能力 |

## 6. 组件 SLA 参考（可观测基线）

| 组件 | 参考 SLA |
|---|---|
| 大脑 | 决策成功率 ≥95%（抽检）；输出 schema 合规率 100% |
| 规划 | 计划执行完成率 ≥80%；重规划频率 <30% |
| 记忆 | 注入命中率（用户提及历史事实能查到）≥90% |
| 工具 | 工具调用成功率 ≥95%（瞬时错误外）；参数校验拦截率跟踪 |
| 行动 | 任务完成率基线（按任务集）；终止原因分布：正常 ≥80% |
| 成本 | 成本/任务 P95 有上限；超预算任务数 <1% |
| 安全 | 工具越权尝试拦截率 100%；写操作审批覆盖率 100% |
| 合规 | 记忆 PII 脱敏率 100%；审计日志完整率 ≥99% |
| 回归 | 组件变更后任务成功率回退 >3% 即拦截 | 与基线对比自动门禁 |
| 可观测 | 组件事件流覆盖率 100%；故障可回放到组件级 | 请求 id 贯穿 |
| 组件变更 | 每次只改一个组件 + 全量回归 | 多组件同改无法归因 |

> 💡 SLA 不是拍脑袋——**先跑 2 周基线再定数字**；组件指标用于回归（改任何组件后对比），不用于营销。

## 7. 落地检查单（上线前逐项打勾）

```text
□ 记忆：分层 + 管理器 + 有界读取 + PII 脱敏
□ 工具：schema 三件套 + 参数校验 + 审计日志
□ 规划：步骤上限 + 目标锚定 + Replanner 上下文裁剪
□ 反思：仅在有 oracle 处启用；独立评判器或规则评判器
□ 行动：超时 + 重试退避 + 写操作审批 + 沙箱
□ 预算：Step Budget 四件套配置并测试
□ 可观测：组件事件流 + 请求 id 贯穿
□ 组件级归因演练：注入五种故障各一次
□ 回归：任务成功率基线 + 成本/任务基线
□ 安全：工具越权测试、记忆隔离测试
```
