# 生产冲刺：落地清单与面试

> 收官篇：把 01-09 收敛成可执行清单与面试弹药。2026 生产基线：**swarm 取代单体、混合编排 + DAG、A2A/MCP 分层、零信任交接、轨迹级评估**——多 Agent 是工程决策不是架构时尚；token 乘数与级联风险是两大守恒律。

## 1. 生产落地清单（上线前逐项打勾）

### 1.1 决策与拓扑

| 检查项 | 标准 |
|---|---|
| 多 Agent 必要性 | 决策矩阵通过（域×权限×并行×隔离，01 篇） |
| 拓扑选型 | 按任务特征：路由→hub、分解→层级、固定→管线 |
| 混合编排 | 审计步骤编排 + 弹性步骤编排舞 |
| DAG 约束 | 有向无环 + 执行者不互调不回调 |
| 无状态 | Agent 无状态、系统保状态 |

### 1.2 协议与交接

| 检查项 | 标准 |
|---|---|
| 协议分层 | A2A 协作 + MCP 工具（不自定义） |
| Agent Card | 版本化 + 签名 + 严格 IO 校验 |
| 交接形态 | 明确任务交接优先（tasks/send），不迭代来回 |
| 交接状态 | 类型化状态 + 来源链 + 预算余量 |
| 完成验证 | 执行验证（不信自报） |

### 1.3 框架与安全

| 检查项 | 标准 |
|---|---|
| 框架选型 | 不选维护模式框架（AutoGen）；看维护状态不看 star |
| 零信任交接 | mTLS + OAuth2 + 每次调用认证 |
| 运行时可干预 | 执行边界设闸（工具/权限/记忆） |
| 断路器 | 循环语言签名监控（agent tennis/停滞） |
| 共享内存 | 加密签名写（防毒化） |
| 分级 IR | 隔离→快照→回滚预案 |

### 1.4 评估与观测

| 检查项 | 标准 |
|---|---|
| 轨迹级评估 | 轨迹 vs 单步通过率缺口监控 |
| 级联场景 | 注入传播/交接误判进评测集（ACIArena 方法论） |
| Agentic SLO | 成功率/交接延迟 30s/工具保真——进告警 |
| 分布式追踪 | W3C traceparent 跨框架传播 |
| 角色评估 | 每 Agent 职责完成度 |

## 2. 十二大避坑

| # | 坑 | 后果 | 解法 |
|---|---|---|---|
| 1 | 为酷上多 Agent | 3-10x token 白付 | 决策矩阵（01 篇） |
| 2 | 纯编排或纯编排舞 | 单点脆弱或不可审计 | 混合（02 篇） |
| 3 | 执行者互调 | 循环依赖/九日循环 | DAG 约束（02 篇） |
| 4 | 自定义协议 | 迁移成本+生态隔绝 | A2A/MCP 标准（03/04 篇） |
| 5 | 交接传全历史 | O(n²) token + 上下文碎片 | 类型化状态（05 篇） |
| 6 | 信交接报告 | 假完成毁编排 | 执行验证（05 篇） |
| 7 | 群聊默认广播 | token 乘数放大 | 定向优先（06 篇） |
| 8 | 按 star 选框架 | 选到维护模式 | 看维护状态（07 篇） |
| 9 | 内部流量可信 | 级联/注入传播 | 零信任交接（08 篇） |
| 10 | 监控但不干预 | 检测了不能停 | 运行时可干预（08 篇） |
| 11 | 单步 eval 管多 Agent | 12% 传播错误不可见 | 轨迹级评估（09 篇） |
| 12 | 每框架各看各的 | 级联无法归因 | traceparent 统一轨迹（09 篇） |

> 🎯 核心要点：12 坑根因是三个——**决策冲动（1-2、8）、交接粗糙（4-7、9）、观测断层（10-12）**。按 01/02/05/08/09 篇规范做，12 坑自动消失。

## 3. 指标体系

| 指标 | 计算 | 目标 |
|---|---|---|
| Token 乘数 | 多 Agent token / 单 Agent 基线 | 3-10x 内且可控 |
| 交接延迟 | 每次交接耗时 | <30s（SLO） |
| 交接次数 | 任务生命周期交接总数 | 最小化（乘数监控） |
| 级联率 | 轨迹通过率 - 单步通过率缺口 | 趋 0 |
| 路由正确率 | Triage 分配正确比 | >95%（第一指标） |
| 假完成率 | 报告完成但状态矛盾比 | 趋 0 |
| 循环事件 | 断路器触发次数 | 趋 0 |
| 审计完整度 | 交接可追溯比 | 100% |

> 💡 最该盯的两个：**级联率缺口**（多 Agent 特有健康信号）与**交接延迟**（乘数与体验的复合指标）。

## 4. 面试题（14 题 + 答题范式）

### 4.1 基础（必答）

**Q1：swarm 为什么取代单体？**
> 决策负担分而治之——Triage 路由 + 窄专家：每个 Agent 最小上下文 + 专业化 + 权限隔离；"几十个工具的上下文让任何模型变笨"（Tool 05 篇数量治理的架构级解）。

**Q2：编排 vs 编排舞？**
> 中央控制器（可审计/单点脆弱）vs 事件自治（弹性/难追溯）——生产刻意混合：审计步骤编排、弹性步骤编排舞；DAG 约束防循环（执行者不互调不回调）。

**Q3：多 Agent 代价？**
> token 3-10x（每次交接新调用）、延迟叠加、级联失败 12%、治理复杂度（87% 优先互操作 vs 7-8% 成熟治理）——"单 Agent+好工具通常胜过编排糟糕的多 Agent"。

### 4.2 进阶（加分）

**Q4：A2A 协议？**
> Agent 间通信开放标准（Linux Foundation，150+ 组织，Spec 1.0.0）：Agent Card 发现（/.well-known/agent.json）、JSON-RPC 2.0（message/send、tasks/send）、Task 生命周期、OAuth2/mTLS 安全——"Agent 界 HTTP"；与 MCP 分层互补（垂直工具/水平协作）。

**Q5：token 乘数怎么控？**
> 明确任务交接优先（tasks/send）不迭代来回；交接传类型化状态不传历史（O(n²)→O(n)）；群聊定向不广播；模型分层 + 缓存 + 最大轮次（Tool 06 预算）。

**Q6：级联失败？**
> 上游错误经信任交接传播放大——每步都合理、整条轨迹是虚构（规划器幻觉工具名→执行器调空→恢复 Agent 编理由→汇总报成功）；~12% 长运行含单步评估从不标记的错误；客服退款→欺诈案例。

**Q7：A2A vs MCP？**
> MCP 垂直（Agent→工具，client-server）；A2A 水平（Agent↔Agent 对等）；分层组合——编排 Agent 用 A2A 委派专家、专家用 MCP 调后端（信用检查/库存）。USB-C vs HTTP 类比。

**Q8：五结构缺陷？**
> 协调延迟（交接序列化累积）/上下文碎片（第三代摘要）/幻觉传播（捏造被洗白成证据）/API drift（维护倍增）/审计碎片（N 日志重建）——架构性质，设计规避。

### 4.3 安全与评估（拉开差距）

**Q9：多 Agent 安全为什么单点护栏不够？**
> 级联在交接点发生——每个 Agent 输入输出都干净仍可整条轨迹虚构；tool-chaining 91%（单授权组合越权）、内存毒化 94%、Morris-II 蠕虫、ACI 级联注入——需要零信任交接 + 运行时可干预 + 加密共享内存。

**Q10：零信任交接怎么落地？**
> mTLS + OAuth2（发送者约束令牌）+ 每次 A2A 调用单独认证授权——内部流量当外部流量；Agent Card securitySchemes 声明；W3C Trace Context 传播可观测。

**Q11：级联怎么评估？**
> 轨迹级评估——轨迹通过率 vs 单步通过率缺口是检测信号；ACIArena（1356 用例）：拓扑评估不足、需角色设计与受控交互、简化环境防御不迁移；Agentic SLO（成功率/交接 30s/工具保真）进告警。

**Q12：框架选型？**
> AutoGen 维护模式（v0.7.5 最后）→ MAF 继任（2026-04 1.0 GA）；LangGraph 状态机/time-travel 调试（生产标杆）、CrewAI 角色原型（token 3-5x，Flows 上生产）；benchmark：MAF 9.87/93s/7K tokens 最优——别按 star 选。

**Q13：协调机制选型？**
> 群聊（多视角，最贵——历史重读税）/投票（并行独立，跨家族破自判）/仲裁（争议触发，可人工升级）——协调是最后手段：能交接不群聊、能定向不广播。

**Q14：协议栈全景？**
> LSP 符号/MCP 工具/A2A 协作/ACP 安全联邦演进；ACP：Agent Cards + 混合发现（本地广播+联盟链 DHT）+ 四阶段协商（PROBE→BID→COMMIT→Settlement）；IETF AIPROTO 立项 + NIST 标准倡议——互操作≠互信，治理自补。

## 6. 面试速记（终极压缩）

1. **Swarm 取代单体**：Triage + 窄专家——决策负担分而治之；多 Agent 是决策不是时尚（token 3-10x）。
2. **协议分层**：A2A 水平协作（Agent Card/tasks）+ MCP 垂直工具——能标准不自定义；互操作≠互信。
3. **交接是信任边界**：零信任（内部当外部）+ 执行验证（不信自报）+ 类型化状态（不传历史）。
4. **级联是主导威胁**：12% 传播错误单步不标记——轨迹级评估（通过率缺口）+ 断路器 + 运行时可干预。
5. **框架看维护状态**：AutoGen 维护模式、MAF 继任；LangGraph 生产标杆（time-travel）、CrewAI 原型（Flows 生产）。
