# 任务分配与交接

> 交接 = 多 Agent 系统的"血液"——任务从 A 流到 B 的每一次转移。2026 两大课题：**token 乘数效应**（每次交接触发新 LLM 调用，多 Agent 3-10x 单 Agent）与**交接即信任边界**（交接点是最小再验证处——级联失败的高发地，08 篇）。本章给任务分配与交接完整设计。

## 1. 任务分配：Triage 路由

| 环节 | 机制 |
|---|---|
| Triage 判定 | 路由 Agent 判定任务域与专家匹配 |
| 专家选择 | 技能匹配（Agent Card 能力发现，03 篇） |
| 上下文裁剪 | 只传任务相关上下文（防污染） |
| 预算分配 | 每子任务 token/成本预算（观测 05 篇） |

> 🎯 核心要点：**分配的失败模式是"路由错"**——客服案例：入站 Agent 误分类（邮件签名注入）→ 路由到欺诈队列 → 下游放大——单步都合理、整体是错误（08 篇级联）。路由正确性是分配的第一指标。

## 2. 交接语义：三种形态

| 形态 | 机制 | 成本 | 适用 |
|---|---|---|---|
| 委派（Delegate） | 任务+上下文 → 专家 → 结果回传 | 1 次交接 | 明确定义子任务 |
| 对话（Conversation） | message/send 多轮往返 | 每轮新调用 | 需要协商的协作 |
| 事件（Event） | 发布-订阅（编排舞，02 篇） | 解耦 | 松散耦合 |

> ⚠️ 2026 交接铁律：**用 A2A 做明确任务交接，不做迭代式来回对话**（token 乘数最小化）——"任务有明确定义的完成状态"的交接（tasks/send）优于"聊到共识"的交接（message/send 往返）。

## 3. Token 乘数效应

| 数据点 | 值 |
|---|---|
| 多 Agent vs 单 Agent token | **3-10x** |
| 每次交接 | 新 LLM 调用（上下文重读） |
| GroupChat 税 | 管理器每轮重读完整聊天历史（AutoGen 案例） |
| 降本措施 | 状态裁剪/模型分层/缓存/最大轮次（Tool 06 预算） |

> 💡 乘数来源：交接不仅"调用一次"，还重读上下文——**交接传状态不传历史**（感知 08 篇 state-carry 同源）：类型化状态 O(n)，全历史 O(n²)。

## 4. 交接状态设计

| 要素 | 内容 |
|---|---|
| 任务上下文 | 目标/约束/输入（最小集） |
| 类型化状态 | 结构化进度/产物（非自由文本） |
| 来源链 | 谁派的/依据什么（审计，09 篇） |
| 预算余量 | 剩余 token/成本（防透支） |
| 截止与优先级 | 时间约束 |

> 🎯 核心要点：**交接质量决定下游起点**——"下游 Agent 消费第三代摘要"（上下文碎片，08 篇五结构缺陷）的根源是交接状态劣化；交接传高保真类型化状态 + 来源链，下游才有可验证基础。

## 5. 假完成报告：交接的信任问题

| 现象 | 机制 | 防御 |
|---|---|---|
| 假完成 | Agent 报告完成但系统状态矛盾 | 执行验证（评估 03 篇） |
| 乐观汇报 | 未验证就报成功 | 状态检查强制 |
| 模糊失败 | 失败含糊其辞 | 结构化错误（Tool 06 篇） |

> ⚠️ 2026 铁律（遥测契约同源，观测 06 篇）：**"不信 Agent 自报"**——交接完成要执行验证（查数据库状态/测试套件），不靠"我完成了"；假完成报告是编排可靠性的大敌。

## 6. 交接的可观测

| 观测点 | 内容 |
|---|---|
| 交接延迟 | 每次交接耗时（SLO 30 秒阈值，09 篇） |
| 交接次数 | 任务生命周期总交接数（乘数监控） |
| 失败率 | 交接失败分布（分形态） |
| 状态保真 | 下游消费的状态与上游产出的一致率 |
| 上下文碎片 | 交接后信息损失评估 |

> 💡 与感知 06 篇衔接：**"交接失败高发在不知道对方完成到什么程度"**——交接消息要带感知级状态（进度/产物/依赖），不只"完成/失败"；W3C Trace Context 跨 Agent 传播让交接可追踪（09 篇）。

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "交接免费" | 每次交接新 LLM 调用——token 乘数 3-10x |
| "传全历史保真" | 传类型化状态——O(n²)→O(n) |
| "信交接报告" | 假完成要执行验证——不信自报 |
| "路由错了也没事" | 路由错是级联源头——路由正确性第一指标 |
| "对话式交接好" | 明确任务交接优于来回对话——tasks/send 优先 |
| "交接传摘要够" | 第三代摘要=上下文碎片——高保真状态+来源链 |
| "交接不用观测" | 交接延迟/次数/失败率是核心 SLO |

## 8. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 交接三形态？ | 委派（1 次）/对话（每轮）/事件（解耦） |
| Token 乘数？ | 3-10x 单 Agent——每次交接新调用 |
| 交接铁律？ | A2A 明确任务交接，不迭代来回 |
| 传什么？ | 类型化状态不传历史——O(n²)→O(n) |
| 路由失败案例？ | 邮件签名注入→误分类→欺诈队列→放大 |
| 假完成？ | 报告完成但状态矛盾——执行验证 |
| GroupChat 税？ | 管理器每轮重读完整历史 |
| 交接状态要素？ | 任务上下文/类型化状态/来源链/预算/截止 |
| 与感知 06 衔接？ | 交接带感知级状态——不只完成/失败 |
| 交接观测？ | 延迟 30s SLO/次数/失败率/状态保真 |
| 上下文碎片根源？ | 交接状态劣化——第三代摘要 |
| 与 08 篇关系？ | 交接点是最小再验证处——级联高发地 |
