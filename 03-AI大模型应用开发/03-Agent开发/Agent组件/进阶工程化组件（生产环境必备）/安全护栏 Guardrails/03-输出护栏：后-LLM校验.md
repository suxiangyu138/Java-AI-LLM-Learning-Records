# 输出护栏：后-LLM 校验

> 输出护栏 = 模型返回后、送达用户或下游前的校验闸：幻觉检测、毒性/内容安全、格式合规、输出 PII 检查。2026 最强模式：**护栏即反馈**——检测到问题不只是一拦了之，而是定向修正回喂模型、重检、直到通过。本章给输出护栏的完整设计。

## 1. 输出护栏的四类职责

| 职责 | 防什么 | 典型手段 |
|---|---|---|
| 幻觉检测 | 无支撑断言（与上下文不符） | 上下文蕴含校验（LLM judge） |
| 毒性/内容安全 | 仇恨言论、危险内容 | 专用分类器（05 篇） |
| 格式合规 | 结构不符（JSON/表格/长度） | schema 校验（衔接 Output Parser） |
| 输出 PII | 模型回吐记忆中的 PII | 正则 + NER |

> 🎯 核心要点：输出侧是**成本刻意区**——幻觉/毒性模型判断每次都要花钱，按"该判断是否真的需要"开与关。可逆低危输出轻查，不可逆高风险输出全查。

## 2. 三种修复策略：refrain / fix / reask

| 策略 | 做法 | 适用 | 代价 |
|---|---|---|---|
| Refrain（拒绝） | 不返回，给策略安全后备 | 确定违规（毒性/违禁话题） | 用户零输出 |
| Fix（修正） | 自动修复后返回（脱敏/替换/格式修复） | PII 脱敏、格式错误 | 修复逻辑成本 |
| Reask（重问） | 把问题反馈给模型重答 | 幻觉、质量不足 | 一次额外调用 |

```python
# 输出护栏修复路由（示意）
def output_guardrail(model_output):
    if toxicity(model_output) > T_TOXIC:            # 确定违规
        return REFRAIN, "该回答无法提供，请换个问题"
    if has_pii(model_output):                        # 可修复
        return FIX, redact(model_output)             # 自动脱敏
    if not supported_by_context(model_output):       # 幻觉风险
        return REASK, "以下陈述无支撑，请修正后重答：..."  # 回喂模型
    return PASS, model_output
```

> ⚠️ Reask 的循环控制：reask 必须带重试上限（如 2-3 次）——无限重问 = 延迟与成本失控；达上限转 REFRAIN 或人工。

## 3. 护栏即反馈：2026 的质保模式

| 传统模式 | 护栏即反馈模式 |
|---|---|
| 检测 → 拦截 → 用户拿到后备响应 | 检测 → **定向修正提示回喂模型** → 重检 → 通过或达上限 |
| 护栏是"闸门" | 护栏是"质检员+教练" |
| 每次失败都损失质量 | 失败转化为修订，质量内建到循环里 |

```text
幻觉检测回喂示例：
  检测："此回答中『退款 48 小时内到账』无上下文支撑"
  回喂："你引用了未经验证的退款时效。若上下文中无此信息，
         请删除该断言或仅基于已有信息重述。"
  重检 → 通过或达重试上限
```

> 🎯 核心要点：**护栏即反馈把幻觉检测变成质量保证**——无需人工介入，每次失败都在循环内修复。2026 生产案例：客服 Agent 用此模式捕获无支撑断言并自动修正，用户从未看到错误版本。

## 4. 幻觉检测的实现选择

| 方案 | 机制 | 成本 | 适用 |
|---|---|---|---|
| 上下文蕴含检查 | 断言 vs 上下文 蕴含判定（LLM judge） | 每次输出一次调用 | 高价值输出 |
| 引用强制 | 要求输出带引用，无引用即不通过 | 结构检查 | 知识密集 Agent |
| 检索交叉验证 | 断言与检索块交叉比对 | 检索成本 | RAG 场景 |
| 规则断言 | 数字/日期/专名格式校验 | ~0 | 结构化字段 |

> 💡 幻觉检测的边界：**检查"是否被上下文支撑"，不检查"是否真实"**——上下文本身可能错。要真值校验需外部验证（Reflection 06 篇"反思与工具：外部验证"是本问题的深化）。

## 5. 输出护栏的成本刻意清单

| 场景 | 检查 | 成本策略 |
|---|---|---|
| 低危高频（闲聊） | 毒性轻查 + 格式检查 | 分类器/规则，无 LLM |
| 中危（建议/信息） | + 基础幻觉抽查 | 采样检查（10%） |
| 高危（金融/医疗建议） | 全量幻觉 + 内容安全 | 每输出必查（LLM judge） |
| 不可逆（执行指令） | 全量 + 人工确认衔接 | 最高规格 |

> ⚠️ 成本记账：模型支撑的检查（LLM judge）才是预算主体——"诚实预算是数模型支撑的检查数，不是数框架"（2026 框架对比共识）。

## 6. 输出护栏与相邻体系的分工

| 相邻体系 | 分工 |
|---|---|
| Output Parser 输出解析器 | 解析器管"结构契约"（格式/解析/重试）；输出护栏管"内容安全"（毒性/幻觉/PII）——格式合规是两者的交界 |
| Reflection 反思模块 | 反思是"自评改进"；输出护栏是"外部策略校验"——护栏回喂是反思的一种外部化形式 |
| 评估模块（Eval） | 评测是离线衡量；护栏是运行时执行——评测集喂护栏阈值校准（08 篇） |

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "输出检查全部用 LLM 最准" | 成本爆炸——按风险开模型判断，低危用分类器/规则 |
| "Refrain 最安全" | 过度 Refrain = 产品不可用——FPR 是要衡量的（08 篇） |
| "Reask 无限重试" | 必须上限——否则延迟与成本失控 |
| "幻觉检测=事实检测" | 护栏查"上下文支撑"，不查"世界真实性"——真值靠外部验证 |
| "格式检查重复了解析器" | 解析器管解析，护栏管安全——格式合规是交界不是重复 |
| "输出侧检查一次就够" | 流式输出要分段检查——完整内容出来后还要终检 |
| "护栏决策不用记账" | 干预要发遥测：触发率、修复率、误报——没有账目无法改进 |

## 8. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 输出护栏查什么？ | 幻觉、毒性、格式、输出 PII |

| Reask 循环控制？ | 重试上限 2-3 次，达上限转 Refrain/人工 |
| 护栏即反馈是什么？ | 检测→定向修正回喂→重检——把拦截变质量保证 |
| 幻觉检测查什么？ | 断言是否被上下文支撑——不查世界真实性 |
| 为什么输出侧成本刻意？ | 模型判断每次花钱——按风险开关 |
| 流式输出怎么查？ | 分段检查 + 完整内容终检 |
| 与 Output Parser 分工？ | 解析器管结构契约，护栏管内容安全 |
| 与 Reflection 分工？ | 反思自评改进，护栏外部策略校验——回喂是反思外部化 |
