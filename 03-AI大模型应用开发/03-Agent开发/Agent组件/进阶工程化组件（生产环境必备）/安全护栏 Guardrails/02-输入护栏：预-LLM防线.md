# 输入护栏：预-LLM 防线

> 输入护栏 = 用户输入与装配好的上下文到达模型前的那道闸：PII 检测脱敏、敏感数据阻断、注入/越狱筛查。2026 铁律：**热路径上的输入检查必须快而确定**（正则/规则/轻分类器 5-15ms）；LLM 判断不进输入路径。本章给输入护栏的完整设计。

## 1. 输入护栏的三类职责

| 职责 | 防什么 | 典型手段 |
|---|---|---|
| PII 检测与脱敏 | 客户数据未经脱敏发给外部模型厂商 | 正则 + 实体识别（Presidio）+ 脱敏替换 |
| 敏感数据阻断 | 信用卡号、凭据、专有数据泄露 | 模式匹配 + 关键词规则 |
| 注入/越狱检测 | 直接注入（"忽略之前指令"）、越狱模板 | 规则 + 专用分类器 |

> 🎯 核心要点：输入护栏的典型业务价值——**让数据不出企业边界**：航空公司客服场景，PII 脱敏发生在对话离开企业环境之前，这是生产可部署的前提（2026 实证案例）。

## 2. 为什么输入侧要"快而确定"

| 约束 | 原因 |
|---|---|
| 热路径 | 每次 LLM 调用都过——延迟直接乘到总时延上 |
| 确定性 | 规则/正则结果可复现、可测试、可解释；模型判断有随机性 |
| 无 LLM 依赖 | 输入侧 LLM 判断 = 递归风险（护栏自己用模型=又要护栏）+ 成本 |
| 分级承担 | 规则拦"确定坏"，分类器拦"可能坏"，重判断留给输出侧/人工 |

```text
输入路径延迟预算（2026 参考）：
  正则 PII 检测     ~1ms 级
  规则注入筛查     ~1ms 级
  DistilBERT 级分类器 5-15ms（首道过滤）
  LLM 判断         数百 ms —— 不进热路径
```

> ⚠️ 例外声明：确有必须用模型判断的输入场景（复杂语义注入），做法是**降级为异步旁路或二级检查**——主路径保持确定性，模型判断只在触发后启用。

## 3. PII 检测与脱敏设计

| 步骤 | 做法 | 例子 |
|---|---|---|
| 检测 | 正则（邮箱/手机/卡号）+ NER 实体识别 | `138-xxxx-xxxx`、`VISA 4111 **** ****` |
| 分类 | 按类型与敏感度分级 | 高风险（凭据）vs 低风险（昵称） |
| 处置 | 阻断 / 脱敏替换 / 泛化 | `customer@x.com` → `[EMAIL]` |
| 记录 | 脱敏计数与位置入遥测 | 审计脱敏率 |

| 敏感级 | 处置策略 | 例子 |
|---|---|---|
| 绝对禁止 | 直接阻断 | 明文密码、API key、身份证号 |
| 可脱敏 | 替换后放行 | 邮箱、手机号（匿名化） |
| 可保留 | 原样放行（企业内网） | 内部工号（仅内部模型） |

> 💡 与输出护栏的分工：输入侧脱敏防"数据流出企业"；输出侧 PII 检查防"模型吐出记忆中的 PII"——两侧都要，防的是不同的事。

## 4. 注入与越狱检测：手段谱系

| 手段 | 延迟 | 检测率 | 适用 |
|---|---|---|---|
| 关键词/正则规则 | ~1ms | 低（漏变体） | 第一道快速闸 |
| 专用分类器（DistilBERT 级） | 5-15ms | 中 | 首道过滤标配 |
| Prompt Guard 类（86M 级） | ~10ms | 中（直接注入好、间接注入盲区见 05 篇） | 直接注入 |
| LLM-as-judge | 数百 ms | 最高（也最贵） | 高风险输入/旁路复核 |
| 激活探针 | 低 | 间接注入最高 99%（05 篇） | 前沿方案 |

> ⚠️ 2026 实证必须知道：**Meta Prompt Guard 2 对间接注入检测率仅 7-37%**——输入侧只能覆盖"直接输入攻击"，检索文档、工具返回里的间接注入要 retrieval rail 与执行层负责（04/05 篇）。

## 5. 输入护栏的实现形态

```python
# 输入护栏最小流水线（示意）
def input_guardrail(user_input, retrieved_chunks):
    # 1. 快速规则闸
    if blocklist_regex.match(user_input):        # 命中硬黑名单
        return BLOCK, "输入包含被禁止内容"
    # 2. PII 脱敏（先脱敏再进模型，防数据出界）
    redacted = redact_pii(user_input)            # Presidio/正则
    # 3. 注入分类器（轻模型）
    if injection_score(user_input) > THRESHOLD:  # DistilBERT 级
        return FLAG, "疑似注入，转人工复核"
    # 4. 检索块筛查（retrieval rail 入口）
    for chunk in retrieved_chunks:
        if unsafe_source(chunk):                 # 源验证/脱敏
            chunk = sanitize(chunk)
    return PASS, (redacted, safe_chunks)
```

| 决策 | 语义 | 后续 |
|---|---|---|
| PASS | 放行（已脱敏） | 进模型 |
| FLAG | 疑似攻击 | 转人工复核 / 降级回答 |
| BLOCK | 确定违规 | 拒绝 + 策略安全后备 + 审计 |

> 🎯 核心要点：输入护栏的决策语义要**分级**——不是只有"放/拦"两态。疑似（FLAG）走人工或降级，确定违规（BLOCK）直接拒——两级都记录。

## 6. 多轮与装配上下文的输入检查

| 检查点 | 内容 | 注意 |
|---|---|---|
| 单条用户输入 | 直接注入检测 | 主检查点 |
| 历史消息 | 跨轮攻击（毒化在上一轮） | 增量重检成本高——对高敏感 Agent 启用 |
| 检索块 | 间接注入（RAG 文档） | retrieval rail：源验证、隔离标记 |
| 工具返回 | 结果内嵌指令（08 篇工具安全） | 结果脱敏、隐藏字段剥离 |
| system prompt | 完整性校验（防篡改） | 哈希校验、配置审计 |

> ⚠️ 多轮代价：历史重检是 O(轮次×成本)——2026 实践是**按风险分级**：低风险会话只查当前输入，高风险会话（可执行操作）全上下文检查。

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "输入检查用最强模型" | 热路径延迟炸弹——规则优先，模型判断降级为旁路 |
| "正则管住一切注入" | 注入变体无限——正则只做第一道，分类器接第二道 |
| "PII 脱敏一次就够" | 输入侧脱敏防出界、输出侧防回吐——两侧独立 |
| "输入检查覆盖间接注入" | Prompt Guard 2 实证 7-37%——间接注入靠 retrieval/执行层 |
| "FLAG 和 BLOCK 一样" | FLAG 转人工/降级，BLOCK 直接拒——两态语义不同 |
| "脱敏=删除" | 脱敏要保留可读性（匿名化）与可审计性（记录） |
| "输入侧检查后输出侧不用查" | 幻觉/毒性/输出 PII 是模型生成问题，与输入无关 |

## 8. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 输入护栏做什么？ | 入模型前：PII 脱敏、敏感阻断、注入/越狱筛查 |
| 为什么输入侧要快？ | 热路径每次调用都过——5-15ms 预算，规则优先 |
| 输入侧能防间接注入吗？ | 不能——Prompt Guard 2 实证 7-37%，归 retrieval/执行层 |
| PII 处置分级？ | 阻断（凭据）/脱敏（邮箱手机）/保留（内部数据） |
| 输入护栏决策语义？ | PASS/FLAG（人工复核）/BLOCK（拒绝）三级 |
| 多轮怎么查？ | 低风险只查当前，高风险全上下文重检 |
| 输入侧 LLM 判断？ | 不进热路径——除非必须，则异步旁路 |
| 与输出护栏分工？ | 输入防数据出界，输出防模型回吐 |
| Presidio 是什么？ | 开源 PII 检测脱敏库（正则+NER） |
| 直接 vs 间接注入？ | 直接=用户输入攻击；间接=检索/工具内容攻击（更危险） |
| 输入护栏延迟参考？ | 正则 ~1ms、轻分类器 5-15ms |
| 第一道快速闸用什么？ | 关键词/正则黑名单 + 规则 |
