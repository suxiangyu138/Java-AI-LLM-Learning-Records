# 护栏分类器选型：从通用到专用

> 护栏的"眼睛"——分类器决定检测率与误报率。2026 两大结论：**通用毒性过滤（Perspective 类）挡不住 LLM 场景攻击，专用分类器（Llama Guard 3/ShieldGemma/Aegis Guard）是标配**；**2026 实证发现头部分类器对间接注入与工具攻击检测率仅 7-37%**，激活探针达到 99%。本章给选型决策。

## 1. 为什么通用毒性过滤不够

| 通用过滤的问题 | 例子 |
|---|---|
| 为社媒审核设计，非 LLM 交互 | 礼貌式越狱（温和地教撬锁步骤）不被判毒 |
| 粗分类法 | 单标签"毒性"无法表达"上下文相关"违规 |
| 误伤敏感话题 | 正当讨论（医疗/教育）被误拦 |
| 无 LLM 特有威胁 | 不识别注入、越狱、引导泄露 |

> 🎯 核心要点：**专用分类器 = 在 LLM 交互数据上训练、用细粒度分类法**——三巨头：Llama Guard 3（多标签）、ShieldGemma（概率分档）、Aegis Guard（上下文感知）。

## 2. 专用分类器三巨头

| 维度 | Llama Guard 3（Meta） | ShieldGemma（Google） | Aegis Guard（NVIDIA） |
|---|---|---|---|
| 输出 | 多标签安全判定 | 概率打分（按类别设阈值） | 分类 + 上下文类别 |
| 分类法 | MLCommons 对齐（8 语言） | 11 类安全风险 | 绝对不安全 vs 上下文相关 |
| 尺寸 | 1B/8B/11B | 2B/9B/27B | 变体 |
| 特点 | 开源权重、生态最广 | 阈值可调、粒度细 | 上下文感知最强 |
| 适用 | 输入输出通用 | 需要精细控制误报 | 内容语义多变场景 |

> 💡 选型口诀：**要生态选 Llama Guard 3，要阈值控制选 ShieldGemma，要上下文语义选 Aegis Guard**——三者都是开源权重，可自托管，适合内网部署。

## 3. 2026 盲区实证：间接注入检测率 7-37%

| 分类器 | 直接注入 | 间接注入/工具攻击 | 根因 |
|---|---|---|---|
| Llama Prompt Guard 2（86M） | 尚可 | **7-37%** | 扁平文本处理，无聊天模板/结构边界——攻击可借角色扮演头或上下文切换提示（InjecAgent/BIPIA 数据集） |
| Llama Guard 3（8B） | 尚可 | **7-37%** | 强制 user/assistant 交替、无 tool 角色支持——`role: tool`/`role: ipython` 消息直接聊天模板报错，无法评估 |
| LLM-as-judge | 尚可 | 同样失败 | 与模型共享注意力模式（一致性陷阱，Reflection 01 篇同源结论） |

> ⚠️ 2026 结论：**内容分类器对"内容来自检索/工具"的 Agent 攻击集体失明**——这不是调参能修的，是架构问题（模板不支持工具角色）。间接注入的防线在 retrieval rail（源隔离）与执行层（动作校验），不在分类器。

## 4. 突破方案：激活探针

| 项 | 说明 |
|---|---|
| 原理 | 在 LLM 残差流隐藏态上训练线性探针/逻辑回归（如第 31 层用户消息最后 token） |
| 优势 | 原生包含聊天模板与工具 schema 理解；结构边界可见 |
| 效果 | 对间接注入与工具注入检测达 **99%**（2026 实证） |
| 代价 | 需访问模型内部状态——托管 API 不可用，仅自托管模型 |
| 定位 | 前沿方案：2026 尚在研究阶段，但已明确方向 |

> 💡 工程判断：自托管 + 高安全要求的 Agent 可评估激活探针；走托管 API 的企业只能用分类器 + 架构隔离组合。

## 5. 分类器选型决策树

```text
场景判断：
├─ 数据不出内网 → 开源权重自托管（Llama Guard 3 / ShieldGemma / Aegis）
├─ 要求零误报可控 → ShieldGemma（概率+阈值调优）
├─ 内容语义复杂 → Aegis Guard（上下文感知）
├─ 走托管 API：
│   ├─ Azure → Prompt Shields（直接+间接注入，文档面）
│   ├─ OpenAI → moderation（omni，免费额度）
│   ├─ 专业注入防护 → Lakera Guard（商用）
│   ├─ AWS → Bedrock Guardrails
│   └─ GCP → Model Armor
└─ 间接注入高发（RAG/工具）→ 架构隔离优先，分类器兜底
```

> 🎯 核心要点：分类器选型是**隐私 × 召回 × 延迟 × 生态的权衡**，没有唯一答案——决策树先定"数据能不能出内网"，再定"走开源还是托管"。

## 6. 延迟与召回的现实数据（2026 评测）

| 方案 | 延迟 | 特点 |
|---|---|---|
| 多层级流水线（规则+轻分类） | 2.5ms | 0% FPR，但绕过率 46.34%（教育导师基准） |
| NeMo 自检（模型判断） | 1.3-1.5s | 0% 绕过，但 FPR 16.22% |
| Prompt Guard 2 | ~10ms | 绕过 38.48%、FPR 3.60% |
| DistilBERT 级分类器 | 5-15ms | 泛化基准：80.6% recall / 9.5% FPR（heldout） |

> ⚠️ 没有免费的午餐：**绕过率 × FPR × 延迟是三角权衡**——0 绕过必然高误报或高延迟；生产按业务容忍度选工作点（08 篇阈值校准）。

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "通用毒性过滤能防 LLM 攻击" | 为社媒设计——礼貌越狱/引导泄露全漏 |
| "Llama Guard 3 全场景最强" | 对间接注入/工具攻击 7-37%——模板不支持工具角色 |
| "分类器调参能补架构盲区" | 7-37% 是架构问题（无结构边界）——补不了 |
| "延迟越低保召回就放弃" | 三角权衡——按业务选工作点，不是单点最优 |
| "托管 API 检测率最高" | 托管=不可访问内部状态——激活探针用不了 |
| "一个分类器走天下" | 多层：规则第一道、专用分类器第二道、LLM judge 高风险第三道 |
| "FPR 不关我事" | FPR 直接杀产品体验（16.22% FPR 意味着每 6 条误拦 1 条） |

## 8. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 为什么不用通用毒性过滤？ | 为社媒设计：礼貌越狱漏、粗分类、误伤敏感话题 |
| 三大专用分类器？ | Llama Guard 3（多标签生态）/ ShieldGemma（概率阈值）/ Aegis Guard（上下文感知） |
| 2026 盲区实证？ | Prompt Guard 2 与 Llama Guard 3 对间接注入/工具攻击仅 7-37% |
| 盲区根因？ | 扁平文本无结构边界 + 聊天模板不支持 tool 角色 |
| 激活探针是什么？ | 残差流隐藏态线性探针——间接注入检测 99% |
| 激活探针代价？ | 需访问模型内部状态——仅自托管可用 |
| 托管 API 有哪些？ | Azure Prompt Shields / OpenAI moderation / Lakera / Bedrock / Model Armor |
| 三角权衡？ | 绕过率 × FPR × 延迟——按业务容忍度选工作点 |
| 多层分类怎么搭？ | 规则→专用分类器→LLM judge（高风险） |
| 零误报的代价？ | 多层级流水线 0% FPR 但 46.34% 绕过——拦截率≠安全 |
| 间接注入防线在哪？ | 架构隔离（源验证/工具校验）优先——分类器兜底 |
| 自托管与托管的取舍？ | 数据出不出内网是第一决策——决定了开源 vs API |
