# 护栏评测：从基准到生产

> 评测 = 回答"护栏到底防住了多少、误伤了多少、值不值"。2026 最重要发现：**标准评测严重高估护栏性能（LODO 显示 AUC 虚高 8.4 点）**；生产指标三件套 = 绕过率 + FPR + 延迟。本章给从基准到生产的评测方法论。

## 1. 基准的谎言：LODO 评估（ICLR 2026）

| 项 | 说明 |
|---|---|
| 问题 | 标准同源 train/test 切分严重高估分类器性能 |
| LODO | Leave-One-Dataset-Out：训练时留出**整个数据集**评估泛化 |
| 数据 | 18 数据集（有害请求/越狱/间接注入/提取攻击） |
| 发现 | 聚合指标 AUC 虚高 **8.4 点**；单数据集差距 1-25% |
| 根因 | 28% 的 SAE 特征是与数据集组成的捷径（非语义信号） |

> ⚠️ 2026 金句：**"基准会撒谎"**——护栏厂商报的 AUC 多是同源切分测的；采购/选型时要求 LODO 或 heldout 评估数据，否则实际性能可能差 8-25 点。

## 2. 生产指标三件套

| 指标 | 定义 | 为什么关键 |
|---|---|---|
| 绕过率 | 攻击通过护栏的比例 | 安全的直接度量（Recall 的另一面） |
| FPR | 良性请求被误拦比例 | 产品可用性度量——16.22% FPR 每 6 条误拦 1 条 |
| 延迟开销 | 护栏增加的平均延迟 | 成本与体验度量 |

> 🎯 核心要点：**三件套必须同时报**——只报绕过率是自欺（0 绕过可轻易用 100% FPR 换）；只报 FPR 是失职（全放过当然 0 FPR）。2026 评测规范（llm-fw）：直接/间接注入**分开报、永不平均**。

## 3. 2026 实测数据：防御的现实工作点

| 方案 | 绕过率 | FPR | 延迟 | 特征 |
|---|---|---|---|---|
| 多层级流水线 | 46.34% | 0.00% | 2.5ms | 极端保守配置 |
| NeMo 自检 | 0% | 16.22% | 1.3-1.5s | 模型判断，极端严格 |
| Prompt Guard 2 | 38.48% | 3.60% | ~10ms | 轻量均衡 |
| DistilBERT 级分类器 | 19.4%（heldout） | 9.5% | 5-15ms | 泛化基准（llm-fw） |

> 💡 读表方法：**没有全能方案**——生产设计是"按业务容忍度选工作点"：零容忍领域（金融合规）接受高 FPR 换 0 绕过；高频低危场景接受部分绕过换低延迟。多层叠加改变的是形状，不是消除三角。

## 4. 阈值校准：别用默认 t=0.5

| 校准步骤 | 做法 |
|---|---|
| 收集部署代表数据 | 真实流量采样 + 注入攻击样本（heldout） |
| 遍历阈值 | 画 PR 曲线/ROC，找业务最优工作点 |
| 按分布校准 | 目标分布（你的用户语言/场景）决定阈值，不是全局默认 |
| 交叉验证 | 分层 bootstrap 置信区间 + McNemar 显著性检验（2026 评测规范） |
| 灰度验证 | shadow 流量对照后落地（07 篇） |

> ⚠️ 阈值是护栏的"旋钮"——**同一个分类器，阈值不同就是不同的护栏**。默认 0.5 通常不是业务最优；生产必须做分布校准。

## 5. 评测协议：统计严谨性（2026 规范）

| 要素 | 要求 |
|---|---|
| 分层 bootstrap 置信区间 | 性能数字带区间，不带点估计 |
| McNemar 配对检验 | 两个护栏方案显著性对比 |
| 多 seed 敏感性 | 训练随机性影响量化 |
| 同一数据切分 | 所有方案同一 split 同 instrumentation |
| 威胁模型分报 | 直接 vs 间接注入永不平均（行为差异巨大） |

> 🎯 核心要点：2026 评测协议向传统 ML 严谨性看齐——**护栏也是模型，选型决策要有统计依据**。教育导师基准（arXiv 2605.06669，480 查询：369 注入 + 111 良性）是协议范本。

## 6. 从基准到生产：三层评测

| 层 | 内容 | 频率 |
|---|---|---|
| 基准层 | 公开基准 + LODO 评估（选型） | 选型时 |
| 构建层 | 红队演练、对抗性评测集、CI 回归（注入样本集进流水线） | 每次迭代 |
| 运行层 | 线上监控：拦截率、FPR、误拦审计、逃逸样本收集 | 持续 |

```text
逃逸样本闭环：
  线上逃逸样本（红队/误报审计发现）
    → 入评测集（去重）
    → 重训/调参/换模型
    → CI 回归通过
    → 灰度上线
```

> 💡 **逃逸闭环是护栏进化的引擎**：没有样本闭环的护栏 6 个月后就是废铁——攻击者在进化，评测集必须同步进化。

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "厂商报的 AUC 可信" | 同源切分虚高 8.4 点——要 LODO/heldout 数据 |
| "0 绕过就是好护栏" | 可能用 100% FPR 换的——三件套同时看 |
| "默认阈值 0.5 够用" | 按目标分布校准——默认不是业务最优 |
| "直接间接注入一个数" | 分开报永不平均——威胁模型完全不同 |
| "评测一次管一年" | 攻击在进化——评测集必须持续补样本 |
| "FPR 高一点没关系" | 16.22% FPR = 每 6 条误拦 1 条——产品杀手 |
| "红队是安全部门的事" | 构建层评测（CI 对抗样本回归）是工程常态 |

## 8. 面试速记

| 问题 | 一句话答案 |
|---|---|
| LODO 是什么？ | Leave-One-Dataset-Out：留整数据集评估泛化 |
| LODO 发现什么？ | 标准评测 AUC 虚高 8.4 点，单数据集差 1-25% |
| 生产三件套？ | 绕过率 + FPR + 延迟——必须同时报 |
| 为什么分开报直接/间接？ | 威胁模型不同，永不平均 |
| 阈值怎么定？ | 目标分布 heldout 数据遍历 + 业务最优工作点 |
| 2026 评测协议？ | bootstrap 置信区间 + McNemar 检验 + 多 seed |
| 三层评测？ | 基准层（选型）/ 构建层（红队 CI）/ 运行层（监控） |
| 逃逸闭环？ | 逃逸样本→评测集→重训→CI→灰度 |
| 0 绕过可信吗？ | 可能是极端 FPR 换的——三件套验证 |
| 默认 t=0.5 问题？ | 非目标分布最优——必须校准 |
| 教育导师基准是什么？ | 480 查询（369 注入+111 良性）的防御评测协议范本 |
| 评测与 07 篇关系？ | 评测出阈值与开关决策，编排按决策落地 |
