# 上下文装配：感知的产出工程

> 上下文装配 = 把感知结果组装成模型看到的提示的工程——2026 公认的一等学科。核心公式：**context = Assemble(指令, 知识, 工具, 记忆, 状态, 查询)**。实证基础：U 型注意力（关键内容放中间比不检索更糟）、五失败模式、预计算上下文（成本 -3.6x）。本章给装配的完整工程规范。

## 1. 装配的两条铁律

| 铁律 | 实证 |
|---|---|
| 上下文是有限预算 | 每个预载 token 挤占一个推理 token——预载要证明自己 |
| 先切噪声与体积 | 体积比窗口大小更决定质量：40%→80% 填充精度 94%→61% |

> 🎯 核心要点：装配工程师的工作是**"找到让期望结果概率最大化的最小高信号 token 集"**（Anthropic 定义）——不是"把信息放进去"，而是"把不放的信息筛出去"。

## 2. U 型注意力：位置即策略

| 实证 | 数据 |
|---|---|
| 注意力两端强中间弱 | 20 文档 QA：相关文档居中 → 精度 -20% |
| 埋进中段比不检索更糟 | GPT-3.5：答案在第 10/20 文档 52.9% < 无文档 56.1% |
| Attention Sinks | 初始 token 不管内容都获得超高注意力 |

```text
装配位置策略：
  窗口首部 —— 最关键的全局约束（任务、时间、安全规则、身份）
  窗口尾部 —— 收尾提醒（复述关键约束）
  窗口中部 —— 参考资料（schema、示例、低优先级知识）
```

> ⚠️ 反模式警示：**把系统角色/锅炉板放最顶部 = 浪费最高注意力位置**——首部必须是最关键的约束，不是模板。

## 3. 装配策略工具箱（2026）

| 策略 | 做法 | 收益 |
|---|---|---|
| JIT 加载 | 预载通用（角色/约束）；条件内容（技能/文件）按需工具调用 | 省上下文成本 |
| 子 Agent 预算隔离 | 子 Agent 独立窗口：研究子 Agent 读 50 文件不占协调者 | 预算隔离 |
| 分层压缩 | 大工具响应先卸载（文件引用+摘要）再摘要历史 | 逐级保真 |
| State-carry | 类型化持久状态经 state-read 工具携带，不重放完整轨迹 | O(n²)→O(n) |
| Prompt caching 纪律 | 静态内容在前、变化内容在后；机器上下文移出 system prompt 共享缓存 | 缓存命中率 |
| 选择性倒带摘要 | 近期轮次逐字保留，远期选择性摘要 | 保真+省 token |

> 🎯 核心要点：策略组合不是叠加，是**按场景路由**——高保真场景（金融）保真优先、长程场景（编码）压缩优先、实时场景（语音）延迟优先（Memory 02 篇工作记忆管理互补）。

## 4. 预计算上下文：Knowledge Indicators（Elasticsearch 2026）

| 项 | 说明 |
|---|---|
| 问题 | 原始正文进窗口，Agent 读得慢、读得贵 |
| 方案 | 预提取原子化事实单元（knowledge indicator）：Agent 读一句就 commit |
| 效果 | 成本 **-3.6x**/问题；精度 62.5% → 69.8% |
| 消歧增强 | 自动生成消歧 KI（每次失败由 LLM 生成，护栏限定必须包含正确答案与错误预测）→ 精度 **91.7%** |
| 意义 | **"给 Agent 结论，不给过程"**——装配层做预提取，推理层只消费 |

> 💡 与 RAG 的衔接：KI 是 RAG 召回块的"装配后处理"——召回块 → 预提取 KI → 只把 KI 装配进窗口。检索管召回，装配管提纯（RAG 15 篇"上下文压缩"同源）。

## 5. 装配的五失败模式体检（03 篇机制 → 本篇检查单）

| 失败 | 装配期检查 |
|---|---|
| 毒化 | 装配内容来源可信？矛盾信息有优先级吗？ |
| 分心 | 历史/工具输出该压缩吗？该卸载吗？ |
| 混淆 | 工具/文档子集够小吗？（Tool 05 篇过滤） |
| 冲突 | 同窗口矛盾信息检测了吗？ |
| 腐烂 | 窗口修剪是整轮原子进行吗？（Memory 03 篇 turn-atomic） |

> ⚠️ 装配检查单是**每次装配都跑**的：五个"否"才是合格装配——不是上线前检查一次。

## 6. Turn-level 决策：每轮的五选项

| 选项 | 语义 | 触发 |
|---|---|---|
| Continue | 继续累积上下文 | 正常进展 |
| Rewind | 回退到检查点 | 发现路径错误 |
| Clear | 清空本轮上下文 | 任务切换 |
| Compact | 压缩历史 | 预算将满 |
| Delegate | 委派子 Agent | 任务适合隔离 |

> 🎯 核心要点：**每个完成的回合都是分支点**——装配不是"进窗口就完事"，而是每轮按进展做五选一决策。生产 Agent 的上下文治理 = 把这些决策自动化（Memory 02 篇同款思路）。

## 7. 自学习上下文：ACE（2026）

| 项 | 说明 |
|---|---|
| 机制 | "上下文剧本"（可复用子弹列表注入）+ Reflector 批评轨迹 + Curator 提议 ADD/UPDATE/REMOVE |
| 应用 | 确定性（非 LLM）合并——编辑经过验证才落地 |
| 效果 | Demo 精度 44.4% → 83.3%（在线学习，无人工标签） |
| 意义 | 装配内容从"手写"走向"从执行信号自进化" |

> ⚠️ 自学习装配的边界：**合并必须是确定性的**（非 LLM）——LLM 直接改装配内容会引入不稳定与注入面（Guardrails 05 篇同源：确定性控件）。

## 8. 常见误区

| 误区 | 真相 |
|---|---|
| "提示=提示词工程" | 上下文工程 ⊃ 提示词工程——整个信息环境都是装配对象 |
| "全量放进去最稳" | 埋中段比不检索更糟（U 型实证） |
| "system prompt 放最前" | 首部给最关键约束——锅炉板浪费 attention sink |
| "压缩只是省 token" | 正确压缩还提升质量（上下文腐烂）——但激进压缩有精度税 |
| "KI 是缓存优化" | KI 是语义级预计算（-3.6x 成本 +29 点精度） |
| "装配一次定终身" | 每轮五选一（continue/rewind/clear/compact/delegate） |
| "LLM 自己管理上下文" | 确定性控件管理——LLM 参与会引入不稳定 |

## 9. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 上下文装配？ | 把感知结果组装成窗口的一等学科：最小高信号 token 集 |
| 两条铁律？ | 预载是预算；先切噪声体积再想窗口大小 |
| U 型注意力？ | 两端强中间弱——关键放首尾，参考放中间 |
| Attention sink？ | 初始 token 注意力最高——放最关键约束 |
| JIT 加载？ | 预载通用+条件内容按需工具调用 |
| 子 Agent 预算隔离？ | 子 Agent 独立窗口——研究 50 文件不占协调者 |
| KI？ | 预提取事实单元：成本 -3.6x、精度 62.5%→91.7% |
| State-carry？ | 携带类型化状态不重放轨迹：O(n²)→O(n) |
| turn-level 五选项？ | continue/rewind/clear/compact/delegate |
| 装配检查单？ | 五失败体检：毒化/分心/混淆/冲突/腐烂 |
| 自学习装配边界？ | 合并必须确定性——LLM 直改引入不稳定 |
| 缓存纪律？ | 静态在前变化在后；机器上下文移出 system prompt |
