# 感知管道：从原始输入到结构化上下文

> 感知管道 = 连接器 → 嵌入 → 特征提取 → 上下文装配的四段流水线设计。2026 两大课题：**感知压缩**（输入侧 token 优化的四法族）与**实时延迟预算**（视觉 112ms/音频 98ms/文本 17ms 级）。本章给管道设计的完整工程规范。

## 1. 管道四段详解

| 段 | 设计要点 | 技术选型 |
|---|---|---|
| 连接器 | 数据源接入规范：鉴权、限流、重试、增量 | REST/WebSocket/DB 连接池/文件监听/流式订阅 |
| 嵌入 | 各模态向量化：文本/图像/音频统一向量空间 | embedding 模型、视觉编码器、音频编码器 |
| 特征提取 | 从向量/原始数据中识别任务相关模式 | NER、意图分类、GUI 元素检测、时间对齐 |
| 上下文装配 | 组装最终窗口：选择/排序/压缩/缓存 | 上下文工程（08 篇全展开） |

> 🎯 核心要点：四段各自独立演进——换 embedding 不动连接器、换装配策略不动特征提取。**管道设计的第一原则是解耦**，否则任何一段升级都要重搭整条线。

## 2. 感知压缩：四方法族（SJTU 2026 调研）

| 方法族 | 机制 | 例子 | 适用 |
|---|---|---|---|
| Transformation | 格式转换降 token | JSON→紧凑 schema、代码压缩、翻译 | 结构型数据 |
| Token Selection | 只保留相关 token | 关键帧选择、Top-k 检索、token 修剪 | 长视频/长文档 |
| Token Aggregation | 聚合相似 token | 聚类、摘要、块合并 | 冗余输入 |
| Token Resampling | 按重要性重采样 | 自适应采样率、重要性加权 | 流式输入 |

> ⚠️ 压缩的代价实证（2026 必须知道）：**JSON→TOON/TRON 省 27% token 但精度回归 9-14 点；源码压缩省 42% 输入但 SWE-bench 从 50% 掉到 38%**——压缩不是免费的，精度账先算再上（08 篇）。

## 3. 实时感知的延迟预算（2026 参考）

| 模态 | 延迟预算 | 条件 | 加速手段 |
|---|---|---|---|
| 文本 | 17ms | 编码级 | 轻量编码 |
| 视觉 | 112ms | ≤4K/30fps | NPU（Ascend 310B/Jetson Orin NX） |
| 音频 | 98ms | VAD 激活后 | VAD 门控（无声不编码） |
| 端到端 | 80ms | 视频感知压缩+动态码率（WAIC 2026 实证） | 压缩+流控 |

> 💡 延迟预算的分配逻辑：**"先降频再降码"**——能少感知就少感知（主动感知，07 篇），不得不感知再压缩码率（视觉压缩），最后才是硬件加速。

## 4. 连接器设计规范

| 规范 | 内容 |
|---|---|
| 统一抽象 | 所有数据源暴露同构接口（stream/query/subscribe） |
| 增量感知 | 只感知变化（日志尾随、状态 diff）——不重复全量 |
| 鉴权最小化 | 连接器只持有必要凭据（Guardrails 09 篇 JIT 衔接） |
| 限流与重试 | 上游限流要感知层兜底（指数退避） |
| 源标记 | 每条感知数据带来源标记（可信度/隔离信号，Guardrails 04 篇衔接） |

> 🎯 核心要点：**连接器是注入面的一线**——感知数据带着来源标记进管道，护栏才能区分"用户说的/检索来的/工具返回的"，这是间接注入隔离的基础（Guardrails 02/07 篇）。

## 5. 特征提取：从数据到信号

| 层 | 提取什么 | 产出 |
|---|---|---|
| 低级 | 实体、时间、数字 | 结构化字段 |
| 中级 | 意图、情感、话题 | 语义标签 |
| 高级 | 事件关系、计划相关性 | 决策输入 |
| 跨模态 | 时间对齐（语音↔视频） | 统一意图表示（05 篇） |

> 💡 特征提取不是越多越好：**提取的每个字段都是潜在噪声**——只提取"影响下一步决策"的特征（与 Planner 的接口：感知供给决策所需状态，不给无关信息）。

## 6. 机器数据的感知：HYVE 混合视图（2026）

| 项 | 说明 |
|---|---|
| 问题 | 日志/指标/遥测等机器数据体量大、结构重复，直接进上下文浪费 |
| 方案 | 预处理阶段检测重复结构→物化到请求级数据存储→转为混合列式/行式视图→只暴露最相关表示 |
| 后处理 | 查询数据存储补回被省略信息；有界 LLM 调用做 SQL 增强合成 |
| 效果 | token 减 **50-90%** 质量不降；图表生成精度 +132%；延迟 -83% |

> 🎯 核心要点：HYVE 示范了"**感知层的工程红利**"——机器数据不用全文进窗口，先结构化成视图再选择性暴露。这比换模型/扩窗口便宜一个数量级。

## 7. 管道可观测性

| 指标 | 内容 |
|---|---|
| 感知成本 | 每模态 token/请求、延迟分解 |
| 信号利用率 | 装配进窗口的信息中被实际引用的比例 |
| 压缩比 | 输入原始量 vs 窗口量 |
| 失败率 | 连接器错误、解析失败（分源统计） |
| 噪声水平 | 装配内容的信噪比评估（抽样） |

> ⚠️ 与 Memory 02 篇（工作记忆：上下文窗口管理）的分工：感知管道管"输入怎么处理进窗口"，工作记忆管"窗口里的内容怎么维护/淘汰"——入口与治理相邻但不同层。

## 8. 常见误区

| 误区 | 真相 |
|---|---|
| "全量进窗口最保真" | 冗余=噪声——压缩四法族是标配，关键是精度账 |
| "压缩免费" | 源码压缩省 42% 但 SWE-bench 掉 12 点——先测再上 |
| "延迟靠硬件" | 先降频（主动感知）再降码（压缩）最后硬件 |
| "连接器越多越好" | 每个连接器都是注入面——最小化+来源标记 |
| "特征全提取" | 只提取影响决策的——每个无关字段都是噪声 |
| "机器数据直接进窗口" | HYVE 类方案 50-90% token 减量质量不降 |
| "感知成本不统计" | 感知是 token 大户——压缩比/信噪比必须监控 |

| 特征提取原则？ | 只提取影响决策的——无关字段都是噪声 |
