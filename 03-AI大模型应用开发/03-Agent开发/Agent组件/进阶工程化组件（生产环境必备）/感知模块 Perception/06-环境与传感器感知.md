# 环境与传感器感知

> 环境感知 = Agent 对"运行环境"的感知：系统状态、时间与时机、物理传感器、其他 Agent。这是感知模块中**最容易被忽略却最影响行动正确性**的部分——一个不知道"现在几点、我在哪个环境、有没有权限"的 Agent，推理再强也会在第一步翻车。本章给环境感知全景。

## 1. 环境感知的四种类型

| 类型 | 感知内容 | 例子 |
|---|---|---|
| 系统状态 | 文件/进程/网络/配置/凭据环境 | 当前目录、磁盘空间、API 可达性 |
| 时间与时机 | 时刻、时区、会话进度、截止时间 | 现在是几点、任务还剩多久 |
| 物理传感器 | 摄像头/麦克风/LiDAR/IMU/设备状态 | 机器人前方障碍、可穿戴心跳 |
| 多 Agent 环境 | 其他 Agent 的存在/状态/能力 | 哪个 Agent 可接管、谁在等待 |

> 🎯 核心要点：**环境感知是"行动的许可证"**——规划器决定"做什么"、环境感知决定"现在能不能做、在哪里做"。缺环境感知的行动 = 盲人开车（Tool 06 篇的授权步与之衔接）。

## 2. 系统状态感知：软件 Agent 的"本体感"

| 感知项 | 实现 | 用途 |
|---|---|---|
| 工作目录/文件系统 | 文件工具（Tool 体系） | 读写定位 |
| 运行环境 | 环境变量/配置探测 | 环境判断（prod/dev） |
| 资源状态 | 磁盘/内存/连接池查询 | 决策前检查 |
| 权限状态 | 凭据可用性探测 | 授权预判（Guardrails 09 篇 JIT 衔接） |
| 网络拓扑 | 服务发现/可达性检查 | 依赖判断 |

> ⚠️ 2026 工程警示：**环境感知要"探测"不要"假设"**——假设"有权限"再被拒是浪费一轮；先探测凭据再行动是生产 Agent 的基本素养（与 Tool 06 篇"结构化错误回传"互补：探测防错，回传纠错）。

## 3. 时序感知：时间即上下文

| 维度 | 内容 |
|---|---|
| 绝对时间 | 当前时刻/时区——影响"现在该不该做" |
| 相对进度 | 会话已用时、任务剩余预算（Tool 06 预算衔接） |
| 截止与窗口 | 任务截止时间、窗口期（如促销时段） |
| 时序一致性 | 数据新鲜度（感知内容的时间戳）——旧数据要标"过时" |

> 💡 时序感知的经典错误：**Agent 不知道"今天星期几"**（模型的训练截止）——把"当前时间"显式注入上下文是最便宜的感知增强，却常被遗漏（08 篇注意：时间要放窗口首部，因为它是全局约束）。

## 4. 物理传感器感知：从虚拟到具身

| 传感器 | 感知内容 | 2026 进展 |
|---|---|---|
| 摄像头 | 视觉场景（05 篇） | 统一 Omni 入口 |
| 麦克风 | 语音/环境声 | VAD + 流式 |
| LiDAR | 空间点云 | WAIC 2026：物理 AI 标配融合 |
| IMU | 运动状态 | 机器人导航 |
| 设备状态 | 电量/温度/连接 | 可穿戴 Agent（ContextAgent） |

> 🎯 核心要点：**具身感知的融合原则——"不是只看摄像头"**（WAIC 2026 共识）：LiDAR 点云 + 音频 + 视频 + 设备状态的综合理解才构成物理世界感知；单模态视觉是具身感知的残缺形态。

## 5. 环境驱动的主动服务：ContextAgent（NeurIPS 2025）

| 项 | 说明 |
|---|---|
| 场景 | 可穿戴设备（视频+音频）海量感官数据 |
| 机制 | 从海量感知中提取多维上下文 → 结合历史人设 → 预测何时需要主动服务 |
| 特征 | **被动感知环境 + 主动发起服务**——感知不只是响应输入，而是预判需求 |
| 意义 | 环境感知的最高形态：从"感知-响应"到"感知-预判-主动" |

> 💡 ContextAgent 打开的问题：**"Agent 何时该自己说话"**——这在主动服务场景（健康提醒、日程预判）是产品核心。与 Planner 的衔接：感知预判 → 规划器决定是否介入。

## 6. 多 Agent 环境感知

| 感知项 | 内容 |
|---|---|
| 拓扑 | 谁存在、谁空闲、谁擅长什么 |
| 交接状态 | 子 Agent 完成度、下一步依赖（Orchestrator 组件衔接） |
| 能力协商 | 可用工具/权限范围（A2A 协议侧） |
| 冲突检测 | 两个 Agent 是否操作同一资源 |

> ⚠️ Multi-Agent 体系的感知盲区：Agent 常把"其他 Agent 的状态"当黑盒——**交接失败率高发在"不知道对方完成到什么程度"**。多 Agent 协作组件的交接消息要包含感知级状态（进度/产物/依赖），不只是"完成/失败"。

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "环境感知=系统信息" | 时序/传感器/多 Agent 都是环境——四类都影响行动 |
| "权限假设有就行" | 探测优先——被拒一轮是浪费 |
| "时间不用注入" | 模型不知道今天几号——时间是最便宜的感知增强 |
| "视觉=全部物理感知" | 融合原则：LiDAR+音频+视频+状态 |
| "感知是被动的" | ContextAgent：感知-预判-主动是 2026 方向 |
| "交接只看结果" | 要感知级状态（进度/产物）——否则交接像黑盒 |
| "环境感知可后补" | 缺失环境感知的行动是盲人开车——先感知后行动 |

## 8. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 环境感知四类？ | 系统状态/时间时机/物理传感器/多 Agent 环境 |
| 为什么时间要注入？ | 模型训练截止不知道今天——最便宜感知增强 |
| 探测 vs 假设？ | 先探测凭据/环境再行动——防浪费一轮 |
| 具身融合原则？ | 不只摄像头：LiDAR+音频+视频+设备状态 |
| ContextAgent？ | 可穿戴海量感知→预判主动服务（NeurIPS 2025） |
| 多 Agent 交接盲区？ | 不知道对方完成度——交接要感知级状态 |
| 环境感知定位？ | 行动的许可证——决定"现在能不能做" |
| 时序感知维度？ | 绝对时间/相对进度/截止窗口/数据新鲜度 |
| 与授权衔接？ | 环境探测预判授权（JIT 权限前置） |
| 与 Planner 衔接？ | 感知供给世界状态，规划决定下一步 |
| 传感器有哪些？ | 摄像头/麦克风/LiDAR/IMU/设备状态 |
| 环境感知最高形态？ | 感知-预判-主动（不只是感知-响应） |
