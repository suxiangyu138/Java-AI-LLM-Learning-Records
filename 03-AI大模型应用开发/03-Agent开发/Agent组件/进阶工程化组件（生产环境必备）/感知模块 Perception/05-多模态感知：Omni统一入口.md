# 多模态感知：Omni 统一入口

> 多模态感知 = 把视觉/音频/文本放进一个感知入口。2026 范式转移：**从"ASR+LLM+TTS 拼装"走向"原生 Omni 模型"**——单一模型统一各模态，消除延迟/上下文碎片/成本三座大山；全双工实时流式成为语音 Agent 标配。本章给 Omni 感知全景。

## 1. 拼装架构的三大痛点

| 痛点 | 机制 |
|---|---|
| 延迟叠加 | 语音→文本→推理→文本→语音，每跳一次模型调用 |
| 上下文碎片 | 各模态独立处理，跨模态信息丢失（语气/情绪/视觉上下文） |
| 成本叠加 | 多个模型各付一次推理费 |

> 🎯 核心要点：拼装的本质问题是**"模态在模型外拼接"**——2026 的答案是"模态在模型内统一"（Omni），让跨模态注意力原生发生。

## 2. Omni 模型双雄（2026）

| 维度 | NVIDIA Nemotron 3 Nano Omni | 小米 MiMo-V2-Omni |
|---|---|---|
| 发布 | 2026-04 | 2026 |
| 架构 | 30B-A3B 混合 MoE（视觉+音频编码器内置） | 原生统一 omni-modal |
| 吞吐 | 最高 **9x** 于其他开源 omni 模型 | — |
| 关键能力 | 1920×1080 原生 GUI 输入、文档智能、音视频推理单流 | SWE-Bench/OmniGAIA/MM-BrowserComp 达领先水平 |
| 卖点 | 无需独立感知模型 | **"无 omni 税"**：多模态不牺牲 Agent 基准 |

> 💡 "omni 税"概念：传统多模态模型在纯文本/Agent 任务上通常打折——MiMo-V2-Omni 的核心主张是"全能且不付税"，这是 omni 落地的关键条件。

## 3. 统一感知流水线：X-OmniClaw（2026）

```text
X-OmniClaw Omni 感知入口：
  摄像头画面 + 屏幕投影 ──→ 视觉证据
  语音输入 ────────────→ ASR 实时转录
  ──→ 时间对齐模块（时间戳对齐音视频）──→ 结构化多模态意图表示
  ──→ VLM 结合用户查询解释场景 ──→ 展开为结构化意图
```

| 要素 | 说明 |
|---|---|
| 一体多模态 | 手机 = 第一人称多模态系统（相机+屏幕+麦克风单管道） |
| 时间对齐 | 语音与视频按时间戳对齐——跨模态语义绑定 |
| 意图表示 | 原始输入 → 结构化意图（不是逐段翻译） |
| 意义 | 统一入口模板：UI 状态 + 视觉场景 + 语音一个管道进入 |

> 🎯 核心要点：**统一入口的关键不是"多模态模型"，是"时间对齐 + 意图结构化"**——把语音/视觉在时间轴上对齐后分解成结构化意图，推理层消费的是意图不是原始流。

## 4. 实时全双工：语音 Agent 的感知形态

| 项 | 说明 |
|---|---|
| 协议 | OpenAI Realtime API（WebRTC）等全双工通道 |
| 能力 | 摄像头画面与语音同时处理 + 打断支持 |
| 感知预算 | 音频 98ms（VAD 激活）、视觉 112ms（≤4K/30fps）、文本 17ms |
| 流式 | 边感知边推理边生成——打断时感知立即切换 |

> ⚠️ 全双工的感知难点：**打断管理**——用户插话时感知层要立刻放弃当前输入转向新输入（VAD + 流式切换），这是拼装架构（整句识别）做不到的。

## 5. 音频感知：从 ASR 到音频推理

| 层 | 能力 | 2026 进展 |
|---|---|---|
| 语音识别 | ASR 实时转录（VAD 门控） | 流式识别成熟 |
| 音频理解 | 语气/情绪/场景声学 | VISA 视觉增强音频推理（Interspeech 2026，77.40%） |
| 语音交互 | 全双工对话（Realtime API） | 生产标配 |
| 音频 Agent | 音频为感知主体的 Agent 任务 | ARC Agent Track（Interspeech 2026） |

> 💡 音频感知的进阶形态：**"以音频为中心"的 Agent**（会议分析、环境监听）——感知主体是声学信号而非文字，推理层做跨模态路由（VISA 的分层路由：声学/感知/语义/文化四层）。

## 6. 多模态 RAG 与感知的边界

| 体系 | 职责 |
|---|---|
| 多模态 RAG（RAG 19 篇） | 检索侧：多模态知识存储与召回 |
| 多模态感知（本篇） | 输入侧：多模态原始输入的实时处理管道 |

> 🎯 核心要点：一个管"怎么找到多模态知识"，一个管"怎么接收多模态输入"——检索与感知是两条不同的管道，但共享向量空间（嵌入层）设计。

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "拼装架构也能用" | 延迟/上下文碎片/成本三座大山——Omni 是 2026 方向 |
| "Omni=换个大模型" | Omni 是架构（统一模态+时间对齐+流式），不只是模型 |
| "多模态必有 omni 税" | MiMo-V2-Omni 实证无税——选型要查 Agent 基准 |
| "全双工=语音对话" | 全双工是感知形态（打断/流式切换），不是聊天功能 |
| "音频=ASR" | 音频理解（情绪/场景）与音频 Agent 是更高层 |
| "Omni 只适合语音助手" | 30B 级 omni 已覆盖 GUI/文档/音视频推理（Nemotron） |
| "时间对齐是可选优化" | 跨模态语义绑定靠对齐——不做对齐等于各说各话 |
