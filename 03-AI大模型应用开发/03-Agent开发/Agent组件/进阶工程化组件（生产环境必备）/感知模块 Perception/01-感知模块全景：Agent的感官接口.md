# 感知模块全景：Agent 的感官接口

> 感知 = Agent 的感官接口：把环境原始输入（文本/图像/音频/传感器/系统状态）转化为结构化上下文。2026 定位：感知是五组件之一（感知/推理规划/记忆/行动/反馈），连续循环运行；最大趋势是**从"被动全量摄入"走向"主动按需感知"**。本章立起全景与边界。

## 1. 感知模块的定位

| 项 | 说明 |
|---|---|
| 定义 | 摄取环境原始数据 → 转换为推理引擎可用的结构化上下文 |
| 组件 | 连接器（数据源接入）→ 嵌入（向量化）→ 特征提取 → 上下文装配 |
| 循环 | 感知与推理/记忆/行动/反馈组成连续循环——不是一次性前置步骤 |
| 产出 | 每个提示都是被**装配**的：context = Assemble(指令, 知识, 工具, 记忆, 状态, 查询) |

> 🎯 核心要点：**感知的产出是"上下文"，不是"数据"**——Agent 不关心原始日志有多全，只关心装配进窗口的信息信噪比（08 篇：纯噪声比不检索还差，8.0% vs 23.6%）。

## 2. 感知的四段管道

```text
原始输入 ──→ 连接器（Connector）──→ 嵌入/特征提取 ──→ 上下文装配（Assembly）──→ 模型
  API/DB/文件/流         数据源接入          语义向量化/模式识别       结构化产出注入窗口
```

| 段 | 职责 | 例子 |
|---|---|---|
| 连接器 | 接入数据源 | REST API、数据库、文件系统、流式数据、传感器 |
| 嵌入 | 输入向量化 | 文本 embedding、图像编码、音频编码 |
| 特征提取 | 识别相关模式 | 实体、意图、GUI 元素、时间对齐 |
| 上下文装配 | 组装推理输入 | 提示构造、顺序、压缩、缓存（08 篇） |

> 💡 判断是否属于感知：**"环境信息进入 Agent 的第一站"就是感知**——RAG 检索是感知的一种通道（知识型感知），工具结果是感知的一种来源（执行反馈型感知），用户输入是核心感知源。

## 3. 被动感知 vs 主动感知

| 维度 | 被动感知 | 主动感知（2026 主流） |
|---|---|---|
| 策略 | 全量摄入再处理 | 按当前推理需求选择性请求 |
| token 成本 | 高（无关信息也进窗口） | 低（Perceive Before Reasoning：**-57.1%** 同准确率） |
| 可靠性 | 噪声稀释相关信号 | 只保留高信号输入 |
| 例子 | 视频全帧进模型 | 只观察与任务相关的片段（有界观察 2-3 轮，07 篇） |
| 适用 | 短输入/低噪场景 | 长输入/多模态/高噪场景 |

> 🎯 核心要点：主动感知的本质是**"感知也是决策"**——Agent 决定"看什么、何时看、看到什么程度"，感知不再是机械前置步骤，而是与推理交织的循环（07 篇深潜）。

## 4. 感知与相邻组件的分工

| 组件 | 分工 | 边界例子 |
|---|---|---|
| RAG 检索 | 知识型感知通道（查询→召回） | 检索管"找知识"，感知管"所有输入的一站" |
| 记忆系统 | 感知之后：把观察存入工作/长期记忆 | 感知装配当前窗口，记忆跨轮/跨任务 |
| 输入护栏 | 感知管道上的拦截点 | 先感知（清洗/脱敏）后护栏（拦截）或反过来，见 §5 |
| Output Parser | 输出侧对称组件 | 感知管"进来的"，解析器管"出去的" |
| 规划器 | 消费感知产出做决策 | 感知供给"世界状态"，规划决定"下一步" |
| 工具执行 | 工具结果是感知的反馈源 | 执行后感知结果 → 装配 → 推理 |

> ⚠️ 最容易混淆的三对：**感知 vs RAG**（RAG 是感知的检索子通道）、**感知 vs 记忆**（感知是入口，记忆是存储）、**感知 vs 解析器**（输入侧 vs 输出侧）。

## 5. 感知与护栏的先后顺序

| 顺序 | 场景 | 理由 |
|---|---|---|
| 护栏 → 感知 | 外部输入（用户消息） | 先拦注入/PII 再处理，防攻击内容进管道 |
| 感知 → 护栏 | 检索块/工具结果 | 先结构化隔离再校验内容（间接注入防线） |
| 双轨 | 高敏感输入 | 两侧都查（Guardrails 02/07 篇） |

> 🎯 核心要点：**护栏与感知的顺序取决于数据可信度**——不可信的原始输入先过闸，可信的内部数据先处理再校验。顺序错了等于给攻击开了管道侧门。

## 6. 感知的 2026 趋势总览

| 趋势 | 表现 |
|---|---|
| 统一多模态 | Omni 单管道（UI+视觉+语音）替代多模型拼装（05 篇） |
| 主动感知 | 按需观察、有界轮次、Perceive 工具化（07 篇） |
| 原生实时 | 全双工流式，子 100ms 延迟目标（05 篇） |
| 上下文工程化 | 装配成为一等学科：U 型注意力、五失败模式（08 篇） |
| 感知压缩 | 输入侧四法族优化 token（02 篇） |
| 具身扩展 | 传感器融合（LiDAR/IMU/设备状态）（06 篇） |

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "感知=预处理" | 感知是连续循环组件，不是一次性前置步骤 |
| "全量摄入最安全" | 噪声稀释信号——纯噪声比不检索还差 15 个点 |
| "感知是模型的事" | 感知管道（连接器/装配/压缩）是工程组件——模型只消费装配结果 |
| "RAG 就是全部感知" | RAG 是检索子通道；用户输入/工具结果/传感器都是感知源 |
| "感知和记忆一样" | 感知管窗口入口，记忆管跨轮存储——入口与存储不同层 |
| "被动感知够了" | 长输入下主动感知省 57% token 且准确率不降 |
| "护栏放感知后就行" | 顺序取决于数据可信度——外部输入先过闸 |

## 8. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 感知模块是什么？ | Agent 感官接口：原始环境输入→结构化上下文的管道 |
| 四段管道？ | 连接器→嵌入→特征提取→上下文装配 |
| 感知产出是什么？ | 上下文（高信号 token 集），不是原始数据 |
| 被动 vs 主动感知？ | 全量摄入 vs 按需观察——主动省 57% token 准确率不变 |
| 与 RAG 分工？ | RAG 是感知的检索子通道 |
| 与记忆分工？ | 感知是窗口入口，记忆是跨轮存储 |
| 与护栏顺序？ | 外部输入先拦后处理；内部数据先处理再校验 |
| 感知是前置步骤吗？ | 不是——与推理/记忆/行动/反馈组成连续循环 |
| 五组件？ | 感知/推理规划/记忆/行动/反馈 |
| 2026 最大趋势？ | 被动→主动感知、Omni 统一入口、上下文工程化 |
| 上下文装配公式？ | context = Assemble(指令, 知识, 工具, 记忆, 状态, 查询) |
| 感知质量第一指标？ | 信噪比——噪声比无信息更伤推理 |
