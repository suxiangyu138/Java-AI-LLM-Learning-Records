# 评估工程化：CI 门禁与持续评估

> 工程化 = 让评估成为**开发流程的一部分**：eval-driven development（评估套件即规范、分数即发布判定、PR 按分数差门禁）。2026 铁律：**不失败构建的评估框架是研究工具不是生产评估**；**同一 evaluator 定义必须跑离线/CI/在线三处**（防漂移）。本章给评估工程化完整设计。

## 1. Eval-Driven Development

| 传统模式 | Eval-Driven 模式 |
|---|---|
| 先开发后评估 | 评估套件先于开发——是工作的"规格书" |
| 评估是验证 | 分数是发布判定 |
| 人工看报告 | PR 按分数差自动门禁 |
| 上线前跑一次 | 每次变更都回归 |

> 🎯 核心要点：**评估套件 = 活的规格书**——开发改提示/代码时，评估套件定义"什么叫好"；分数差是唯一发布判定。这让评估从"质量部的事"变成"开发流程的一部分"。

## 2. CI 门禁配置

| 门禁项 | 参数 | 说明 |
|---|---|---|
| 通过率 | `minPassRate 0.95` | 低于阈值构建失败 |
| 回归 | `maxRegressions 0` | 不允许分数下降 |
| 触发 | 每 PR（提示/代码变更） | 前后对比 eval |
| 报告 | PR 评论交互视图 | Promptfoo GitHub Action 模式 |
| 缓存 | LLM 调用缓存 | 门禁成本控制 |

> ⚠️ 门禁粒度：**会话级指标门禁**（04 篇）——逐轮门禁噪声大；门禁样本要与生产分布一致（golden + 生产种子混合，05 篇）。

## 3. 评估一致性：三处同定义

```text
同一 evaluator 定义必须跑三处：
  离线数据集（notebook/脚本）──┐
  CI 门禁（PR 回归）          ├── 同一 evaluator 定义
  在线生产（采样判分）        ──┘
  防漂移：离线过了在线崩 = 定义不一致
```

| 处 | 用途 | 常见错误 |
|---|---|---|
| 离线 | 选型/探索/校准 | 与生产指标定义不同 |
| CI | 回归门禁 | 样本与生产分布不同 |
| 在线 | 漂移监控 | 与 CI 用不同 judge/rubric |

> 🎯 核心要点：**"同一 evaluator 定义"是防漂移的根**——judge 模型/rubric/版本三处一致（02 篇锁定）；离线过了在线崩的团队，先查定义一致性。

## 4. 版本化治理

| 对象 | 版本化要求 |
|---|---|
| evaluator 定义 | 改定义即改指标——版本化 + 变更流程 |
| 提示词/rubric | 与 evaluator 同版本 |
| 数据集 | tag/hash/门禁（05 篇） |
| 分数 | 带上下文持久化——可重放可重算（08 篇） |
| 结果 | 新旧同跑报 delta——防"换尺子"假提升（06 篇） |

> 💡 与观测体系联动：**分数写 span 属性 + evaluator 版本进 span**——跨版本分数可比性靠 span 元数据（观测 06 篇）。

## 5. 生产失败模式（2026 编目）

| 失败模式 | 机制 | 防御 |
|---|---|---|
| Response-only 评分 | 只评最终答案 | 轨迹+会话评估（03/04 篇） |
| 聚合掩盖 | 总完成率隐藏分维度回归 | 分维度指标 |
| Mock 工具无错误恢复 | "happy-path eval 0.95，生产 429 风暴 0.30" | 错误注入测试（Tool 06 篇） |
| 冻结测试集 | 数据集不更新 | Error Feed 周更（05 篇） |
| Eval/trace 分离 | 评估与观测不同工具无 join | 共享数据平面（观测 06 篇） |

> ⚠️ **Mock 工具的差距是最大的坑**——评估时工具 100% 成功、生产 429/超时/失败——**错误路径必须进评估集**（工具失败/超时/重试场景）；"happy-path 0.95 生产 0.30"是 2026 高频事故。

## 6. 持续评估流水线

| 环节 | 频率 | 产出 |
|---|---|---|
| CI 回归 | 每次 PR | 分数差报告 |
| 生产采样判分 | 持续（10-20%） | 质量趋势 |
| 失败样本回流 | 周更 | 数据集更新（05 篇） |
| 阈值告警 | 实时 | 质量告警（观测 09 篇） |
| 人工抽查 | 定期 | 校准 + 疑难评审 |

> 🎯 核心要点：**评估是流水线不是事件**——CI 门禁管"每次变更"、在线判分管"持续漂移"、样本回滚管"数据集老化"；三个频率缺一，评估链条断裂。

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "评估框架装了就有门禁" | 不失败构建 = 研究工具——门禁要配置 |
| "门禁用单轮指标" | 会话级门禁——单轮噪声大 |
| "离线在线两套定义" | 三处同定义——防漂移的根 |
| "mock 工具够用" | 错误路径必须进评估——429 风暴教训 |
| "数据集冻结" | 周更——老化即失真 |
| "评估与观测分离" | 共享数据平面——join 是排障前提 |
| "改 rubric 无感" | 版本化+新旧同跑——防换尺子 |

## 8. 面试速记

| 问题 | 一句话答案 |
|---|---|
| Eval-driven？ | 评估套件即规格书、分数即发布判定、PR 门禁 |
| 门禁参数？ | minPassRate 0.95 + maxRegressions 0 |
| 三处同定义？ | 离线/CI/在线同一 evaluator——防漂移的根 |
| 版本化什么？ | evaluator 定义/提示词/数据集/分数上下文 |
| Mock 工具差距？ | happy-path 0.95 生产 0.30——错误路径进评估集 |
| 生产失败五模式？ | response-only/聚合掩盖/mock 无错误/冻结集/eval-trace 分离 |
| 评估是事件吗？ | 流水线——PR 回归/在线判分/样本回流三频率 |
| 分数可重放？ | 带上下文持久化——版本化铁律 |
| 与观测集成？ | 分数写 span + evaluator 版本进 span |
| 门禁样本？ | golden + 生产种子混合——分布一致 |
| 换尺子？ | 新旧同跑报 delta |
| 排障前提？ | eval 与 trace 可 join——共享数据平面 |
