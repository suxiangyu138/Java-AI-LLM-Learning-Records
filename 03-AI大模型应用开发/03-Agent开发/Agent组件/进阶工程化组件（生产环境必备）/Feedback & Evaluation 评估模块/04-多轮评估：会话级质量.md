# 多轮评估：会话级质量

> 多轮评估 = 在整段会话层面度量质量——2026 最容易被做错的评估维度。**逐轮打分再平均是错误做法**（每轮都赢但目标没达成 = 平均分高）；pass^k 成为非确定性标准信号；tau-bench/tau2-bench/MultiChallenge 是基准三件套。本章给多轮评估完整设计。

## 1. 为什么多轮评估独立成维度

| 单轮评估的盲区 | 会话级问题的例子 |
|---|---|
| 每轮各自健康 | 第 1 轮识别问题、第 2 轮检索对、第 3 轮没用上 |
| 平均分掩盖失败 | 每轮都"答得不错"但目标从未达成 |
| 无跨轮依赖检查 | 第 N 轮没用第 N-1 轮信息 |
| 无状态验证 | 会话结束系统状态未变（执行验证 03 篇） |

> 🎯 核心要点：**会话是一个整体系统，不是轮次的集合**——"赢了每一轮、输了整场"是多轮评估要抓的第一失败模式；会话级指标 + 会话级门禁是 2026 标准（CI 按会话级指标门禁，逐轮门禁噪声太大）。

## 2. 多轮基准三件套

| 基准 | 场景 | 特点 |
|---|---|---|
| tau-bench | 客服（零售/航空） | 多轮工具使用 + 策略指南 + **验证最终答案 AND 数据库状态** |
| tau2-bench | 电信排障 | 双控设置 + **pass^k 指标**（重复 k 次全通过） |
| MultiChallenge | 通用多轮 | 指令保持/推理记忆/自洽/可靠版本编辑（RVE）；2026 更新：Gemini 2.5 Pro judge（+5pp 人机一致） |

> 💡 补充基准：SWE-Bench（软件工程，执行式）与 AgentBench（多环境：OS/DB/Web/游戏）——**环境越真实，评估越接近生产**。

## 3. 会话级指标族

| 指标 | 含义 |
|---|---|
| Conversation Completeness | 会话目标是否最终达成 |
| Knowledge Retention | 跨轮知识保持（第 N 轮用对第 1 轮信息） |
| Role Adherence | 角色一致性 |
| Persona Match | 人设匹配 |
| Turn Coherence | 轮间连贯性 |
| 目标达成 | 最终状态验证（03 篇执行验证的会话版） |

> ⚠️ 2026 规范：**会话级指标 + 单轮指标并用**——会话级管"成没成"，单轮管"每步对不对"；但**CI 门禁用会话级**（逐轮门禁噪声大、误报多）。

## 4. pass^k：非确定性的度量

| 项 | 说明 |
|---|---|
| 定义 | 同一任务重复 k 次，全部通过的比例 |
| 来源 | tau2-bench 引入，2026 成为标准一致性信号 |
| 测什么 | Agent 的非确定性——同任务 10 次跑 7 次成 ≠ 可靠 |
| 用途 | 可靠性对比、回归检测、容量规划 |
| 与单次通过率的区别 | 单次通过率掩盖抖动——pass^k 度量"稳定地好" |

> 🎯 核心要点：**Agent 是概率系统，"一次跑对"没有工程意义**——pass^k 把可靠性变成可度量的数；生产评估的通过率必须标注 k。

## 5. 多轮评估实践规范

| 规范 | 内容 |
|---|---|
| 场景数量 | 手写 5 条不够——**20-50 场景** + 显式人设，或用 simulator 生成 |
| 数据集组织 | happy path / 边界 / 对抗性三类（05 篇） |
| 评估粒度 | 单轮判分 + 会话轨迹判分（thread 级） |
| 静默失败 | 全会话跑安全指标（PII 泄漏、漏披露）——不只用户可见拒绝 |
| 数据集版本化 | 变更时 tag/hash/门禁回归 |
| 指标一致性 | simulator 与生产定义一致——锁定 judge/rubric/版本 |

> ⚠️ 2026 陷阱清单：逐轮独立打分取平均（赢了每轮输了整场）；手写 5 条用例；自评无对照；忽略静默失败；数据集冻结；simulator 与生产指标不一致——六陷阱覆盖了多轮评估的大部分翻车现场。

## 6. 多轮评估的工程化

| 环节 | 做法 |
|---|---|
| 采集 | thread 级 trace（观测 02 篇 conversation.id 关联） |
| 打分 | 会话指标（§3）+ 单轮指标 + 安全指标 |
| 生成 | simulator 生成多轮场景（人设 + 用户行为模型） |
| 门禁 | 会话级指标 CI 门禁（09 篇） |
| 闭环 | 生产失败会话 → 数据集（05 篇） |

> 💡 与观测体系衔接：**多轮评估跑在 thread 上**（观测 02 篇 threads）——conversation.id 是会话级评估的数据前提；观测的会话级成本/轮次指标与评估的会话级质量指标是同一会话的两个侧面。

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "逐轮平均=会话质量" | 赢了每轮输了整场——会话级指标 |
| "单次通过率够用" | pass^k 度量稳定地好——标注 k |
| "5 条用例够了" | 20-50 场景 + simulator |
| "门禁用单轮" | 会话级门禁——单轮噪声大 |
| "只看用户可见拒绝" | 静默失败（PII/漏披露）全会话跑 |
| "数据集不用版本化" | tag/hash/门禁——变更即回归 |
| "simulator 与生产两套指标" | 定义必须一致——锁定版本 |

## 8. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 为什么逐轮平均错？ | 赢了每轮输了整场——会话级指标 |
| 会话级指标族？ | Completeness/Knowledge Retention/Role/Perseverance/Coherence |
| tau-bench 范式？ | 客服多轮 + 验证最终答案和数据库状态 |
| pass^k？ | 重复 k 次全通过——非确定性度量，2026 标准 |
| MultiChallenge？ | 指令保持/推理记忆/自洽/RVE——2026 judge 升级 +5pp |
| 场景数量？ | 20-50 场景 + simulator——5 条不够 |
| 静默失败？ | 全会话安全指标——不只用户可见拒绝 |
| CI 门禁用什么？ | 会话级指标——单轮噪声大 |
| 多轮评估原料？ | thread 级 trace（conversation.id） |
| 三类用例？ | happy path/边界/对抗性 |
| 数据集版本化？ | tag/hash/门禁回归 |
| 与观测关系？ | 会话质量与成本/轮次是同一会话两个侧面 |
