# 在线评估与反馈环

> 在线评估 = 生产流量上的持续判分；反馈环 = 人工反馈驱动改进的飞轮。2026 三件套：**采样判分（10-20%）+ 标注队列 + judge 校准（人类纠正当 ground truth）**；闭环实证——PsiArena 三边反馈自反思 **+141%**、AutoLibra 开放式反馈自动转指标。本章给在线评估与反馈环完整设计。

## 1. 在线评估架构

```text
在线评估流水线：
  生产 trace（全量采样）
    → 确定性检查（schema/规则，毫秒级）
    → LLM-judge 采样判分（10-20%，定性维度）
    → 分数写 span 属性（观测 06 篇）
    → 低分/异常 → 标注队列 → 人工评审
    → 评审结果 → 校准 judge + 入数据集（05 篇）
```

| 环节 | 做法 |
|---|---|
| 采样 | 10-20%（全量成本失控）——按规则过滤（全用户流量 vs 内部测试低采样） |
| 双评分 | inline（实时粗查）+ deferred（异步深查） |
| 判分 | 确定性 + judge 组合（02 篇 tier） |
| 回写 | 分数进 span——与 trace 同查 |

> 🎯 核心要点：**在线评估 = "烟感探测器"**（LangChain 比喻）——不是离线评估的替代，是生产质量漂移的早期预警；离线测"能不能用"，在线测"还在不在用"。

## 2. 人工反馈三机制

| 机制 | 做法 | 工具 |
|---|---|---|
| 标注队列 | 低分/负反馈 trace 路由评审者打分纠错 | 标注系统 |
| judge 校准 | 人类纠正当 ground truth → few-shot 校准 judge | LangChain 校准流程 |
| Review Apps | 领域专家反馈入评估集（同评分器复用 dev/prod） | MLflow 3 |

> ⚠️ 2026 关键：**自动化不替代人工，人工校准自动化**——评审者画像分层（通用标注员 → 领域专家抓自动化漏掉的失败）；校准的一致性指标持续追踪（人机一致率趋势）。

## 3. Judge 校准流程

| 步骤 | 内容 |
|---|---|
| 1. 收集纠错 | 人类修正 judge 判分（标注队列产出） |
| 2. 构建 few-shot | 纠错样本 → few-shot 示例校准 judge |
| 3. 验证 | 校准前后人机一致率对比（同数据集） |
| 4. 持续 | 一致性指标监控——judge 漂移检测（02 篇） |

> 🎯 核心要点：**校准是把"人的判断"注入 judge 的唯一正规途径**——不校准的 judge 分数 = 未经检验的自动化判断；校准是循环的（一致性下降 → 重新校准）。

## 4. 闭环系统实证（2026）

| 系统 | 机制 | 效果 |
|---|---|---|
| PsiArena（AAAI 2026） | 25 轮咨询会话三边反馈（来访者/督导/咨询师，33 维度）→ 自反思重写 | **+141%** |
| AutoLibra（ICLR 2026） | 开放式反馈（"别点禁用的按钮"）→ 聚类正负行为 → 自动生成评估指标 | 自调节改进 |
| GEN-EVALLM | 人类反馈 → RL 复合奖励模型 → 动态对齐偏好 | 持续对齐 |
| 编码 Agent 加速 | Agent 分析 eval 运行、解释胜负、起草下一版提示 | 迭代对话化 |

> 💡 前沿信号：**反馈环正在自动化**——从"人工→数据集→改进"升级为"反馈→指标→RL/反思→改进"；但自动化的前提是评估与反馈基础扎实（先有人工闭环，再自动化）。

## 5. 评估飞轮（Databricks 2026）

```text
评估飞轮（五环）：
  部署 → 观测（trace） → 自动判分（judge）
    → 人工评审（标注/Review Apps）
    → 改进（提示/代码/数据集）
    → 回归验证 → 再部署
```

| 环节 | 产出 |
|---|---|
| 部署 | 生产流量 |
| 观测 | trace 原料（观测体系） |
| 判分 | 质量分数 |
| 评审 | ground truth + 校准 |
| 改进 | 新版本 + 新用例 |

> 🎯 核心要点：**飞轮的燃料是"失败样本"**——没有样本回流，飞轮空转；三环共享方法论（观测的 trace、护栏的逃逸、评估的数据集——05 篇）。

## 6. 操作规范

| 规范 | 内容 |
|---|---|
| 采样目标 | 全用户流量优先；内部测试低采样 |
| 评分放置 | inline 快查（延迟预算内）+ deferred 深查（隔离延迟） |
| 版本化 | evaluator 定义/提示词/rubric 版本化——改定义即改指标 |
| 持久化 | 分数带上下文（应用版本/evaluator 版本/record ID/span）——可重算 |
| 提示生命周期 | staging→prod 流水线；基线对比；漂移检测自动回滚（Arize） |
| 线程级 | 全会话评估——不只最终答案（04 篇） |

> ⚠️ 版本化铁律：**分数必须可重放**——"评估器定义/提示词/rubric 改了，旧分数就无法解释"；持久化上下文（版本/ID/span）是重算与回归分析的前提。

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "在线评估=离线评估复用" | 在线是烟感探测器——采样+实时；离线是体检 |
| "自动化替代人工" | 人工校准自动化——评审者分层 |
| "校准一次就够" | 一致性持续监控——judge 漂移重校准 |
| "全量判分最准" | 成本失控——10-20% 采样 + 双评分 |
| "反馈环手动就行" | 2026 正在自动化（PsiArena/AutoLibra）——先人工后自动化 |
| "分数不存版本" | 版本化铁律——不可重放的分数是废数据 |
| "反馈不进数据集" | 评审结果入数据集（05 篇）——飞轮燃料 |
