# 生产冲刺：落地清单与面试

> 收官篇：把 01-09 收敛成可执行清单与面试弹药。2026 生产基线：**轨迹是评估单位 + judge 锁定混合 + 生产种子数据集 + 三处同定义 CI 门禁 + 在线反馈闭环**——评估不是打分，是"失败→改进"的飞轮。

## 1. 生产落地清单（上线前逐项打勾）

### 1.1 评估维度

| 检查项 | 标准 |
|---|---|
| 输出评估 | 相关性/忠实度/语气（judge 采样） |
| 轨迹评估 | Tool Correctness/Argument Correctness/顺序（03 篇） |
| 会话评估 | 会话级指标 + pass^k（04 篇） |
| 执行验证 | 数据库状态/测试套件（非文本检查） |
| 安全维度 | 注入/PII/毒性覆盖全会话 |

### 1.2 Judge 工程

| 检查项 | 标准 |
|---|---|
| 混合 judge | 跨家族（防自判偏见） |
| 分解 rubric | G-Eval 链式模式 |
| 锁定 | judge 模型/版本/温度/rubric 文本 |
| 分层 tier | 确定性→分类器→前沿仲裁 |
| 校准 | 人类纠错 → few-shot → 一致性监控 |

### 1.3 数据与门禁

| 检查项 | 标准 |
|---|---|
| 数据集 | 黄金集打底 + 生产种子周更（ground truth 含工具调用） |
| 三类用例 | happy/edge/adversarial |
| 版本化 | 数据集 tag/hash/门禁 |
| CI 门禁 | minPassRate 0.95 + maxRegressions 0 |
| 三处同定义 | 离线/CI/在线同一 evaluator |

### 1.4 在线闭环

| 检查项 | 标准 |
|---|---|
| 采样判分 | 10-20% + 双评分（inline/deferred） |
| 标注队列 | 低分/负反馈路由人工 |
| 反馈入集 | 评审结果回流数据集（飞轮） |
| 错误注入 | 工具失败/超时/重试进评估集 |
| 分数持久化 | 带上下文（版本/ID/span）可重放 |

## 2. 十二大避坑

| # | 坑 | 后果 | 解法 |
|---|---|---|---|
| 1 | 只评最终答案 | 正确输出掩盖错误推理 | 轨迹评估（03 篇） |
| 2 | 逐轮平均当会话分 | 赢了每轮输了整场 | 会话级指标（04 篇） |
| 3 | judge 同族自评 | 自判偏见 | 混合家族（02 篇） |
| 4 | rubric 一句话 | 分数无判别力 | 分解式 rubric（02 篇） |
| 5 | judge 升级无感 | 分数漂移 | 锁定一切 + 变更流程（02 篇） |
| 6 | ground truth 只存答案 | 轨迹错误测不出 | 含工具调用+推理步骤（05 篇） |
| 7 | 数据集冻结 | 6 个月后失真 | Error Feed 周更（05 篇） |
| 8 | 同名指标互换 | 分数不可比 | 四元组锁定（06 篇） |
| 9 | 无 CI 门禁 | 评估是装饰 | minPassRate + maxRegressions（09 篇） |
| 10 | mock 工具无错误路径 | 生产 0.30 崩盘 | 错误注入进评估（09 篇） |
| 11 | 全量 judge 判分 | 成本失控 | 采样 10-20% + 分层 tier（02/08 篇） |
| 12 | 反馈不进数据集 | 飞轮空转 | 评审入集 + 闭环（08 篇） |

> 🎯 核心要点：12 坑根因是三个——**评估维度不全（1-2、6、8）、judge 不可靠（3-5）、工程化缺失（7、9-12）**。按 02/03/04/05/09 篇规范做，12 坑自动消失。

## 3. 指标体系

| 指标 | 计算 | 目标 |
|---|---|---|
| 通过率 | minPassRate | ≥0.95（门禁） |
| 回归数 | maxRegressions | 0 |
| 人机一致率 | judge vs 人工标注 | 追踪趋势（校准健康） |
| pass^k | 重复 k 次全通过比例 | 按任务标注 k |
| 轨迹正确率 | 工具选择/参数正确比 | 分维度监控 |
| 静默失败率 | 未被用户可见的失败 | 趋 0（安全指标） |
| 评估成本 | 每样本 judge 费用 | 预算内（10K traces ≈ $200-600/月） |
| 闭环转化率 | 失败转评估集比例 | 高（飞轮健康） |

> 💡 最该盯的两个：**人机一致率**（judge 可信度的体温计）与**闭环转化率**（评估是否产生改进——不转化的评估是报表）。

## 4. 面试题（14 题 + 答题范式）

### 4.1 基础（必答）

**Q1：为什么输出评测不够？**
> 正确输出可以掩盖错误的推理——标准 pass/fail 漏 65-93% 安全问题。轨迹是评估单位：工具选对了吗、参数对吗、顺序对吗（TRAJECT-Bench）。

**Q2：LLM-as-Judge 四失败模式？**
> 长度偏见（>90% 偏好长答案）、位置偏见（70% 首位偏好）、自判偏见（同族膨胀）、延迟成本。解法：混合家族 + 分解 rubric + 锁定版本 + 分层 tier。

**Q3：四类度量？**
> 输出（答得怎样）/轨迹（做得怎样）/会话（成没成）/系统（值不值）——2026 从选一个度量走向四层组合。

### 4.2 进阶（加分）

**Q4：轨迹指标族？**
> Task Completion/Tool Correctness/Argument Correctness/Step Efficiency/Plan Adherence；irrelevance bucket（不该调时调了——BFCL v3 修正）；执行验证（查库/跑测试）优于文本检查。

**Q5：多轮评估为什么不能逐轮平均？**
> 赢了每轮输了整场——会话级指标（Completeness/Knowledge Retention）；pass^k 度量非确定性；CI 门禁用会话级（单轮噪声大）。

**Q6：生产种子数据集？**
> 失败 trace 转测试用例，修正后的轨迹为 ground truth（含工具调用与推理步骤，不只答案）；周更 Error Feed 防老化；黄金集有分布漂移/无 ground truth 的结构局限。

**Q7：同名指标陷阱？**
> "DeepEval 的 Faithfulness ≠ Ragas 的 Faithfulness"——不同 judge 提示词不同分数。指标 = 名称+实现+版本+judge 配置四元组；报告必须带齐。

**Q8：三框架对比？**
> DeepEval（pytest 断言、v3.9.7 agent 指标领先）、Promptfoo（CLI 矩阵 + 40+ 红队插件、OpenAI 收购保持 MIT）、Ragas（指标库非平台、RAG 参考 + tool call F1）；"跑哪两个"而非"哪个最好"。

### 4.3 架构与闭环（拉开差距）

**Q9：eval-driven development？**
> 评估套件即规格书、分数即发布判定、PR 按分数差门禁（minPassRate 0.95 + maxRegressions 0）；不失败构建的框架是研究工具。

**Q10：三处同定义？**
> 离线/CI/在线同一 evaluator 定义（judge/rubric/版本锁定）——防"离线过了在线崩"；评估与观测共享数据平面（分数写 span）。

**Q11：在线评估与反馈环？**
> 采样 10-20% 判分（烟感探测器）+ 标注队列 + judge 校准（人类纠错→few-shot→一致性监控）；闭环实证：PsiArena 三边反馈 +141%、AutoLibra 开放反馈转指标；评估飞轮：部署→观测→判分→评审→改进→回归。

**Q12：judge 校准流程？**
> 人类纠正当 ground truth → few-shot 校准 → 新旧人机一致率对比 → 持续监控；校准是循环的——一致性下降重新校准；评审者分层（通用标注员→领域专家）。

**Q13：评估成本怎么控？**
> 采样 10-20% + 分层 tier（确定性→分类器→前沿仲裁）+ 便宜 judge（省 60-80%）+ 缓存；10K traces/天 ≈ $200-600/月（GPT-4o 级）——成本是评估工程第一约束。

**Q14：生产失败五模式？**
> Response-only 评分/聚合掩盖/mock 无错误恢复（0.95→0.30 崩盘）/冻结测试集/eval-trace 分离——五模式是评估工程的体检表。

### 4.4 答题范式

| 原则 | 说明 |
|---|---|
| 结构优先 | 定义 → 机制 → 实证 → 工程（四段式） |
| 带数据 | "65-93%""+141%""0.95/0"——实证碾压空谈 |
| 说权衡 | "采样 10-20% 换成本可控""分层 tier 精度换延迟" |
| 落工程 | 补一句"生产上我怎么做"（锁定版本/Error Feed/双评分） |
| 提边界 | 何时不做：小团队从最终答案评分起步，逐步加轨迹 |

## 6. 面试速记（终极压缩）

1. **轨迹是评估单位**：正确输出掩盖错误推理——工具选择/参数/顺序 + 执行验证（状态为证）。
2. **Judge 四纪律**：混合家族防自判、分解 rubric、锁定版本、分层 tier——80% 人机一致是聚合值。
3. **数据集活资产**：黄金集打底 + 失败 trace 转用例（ground truth 含工具调用）周更——冻结即失真。
4. **工程化三件套**：CI 门禁（0.95/0）+ 三处同定义 + 版本化——不失败构建是研究工具。
5. **闭环是飞轮**：采样判分 → 标注校准 → 反馈入集 → 改进回归——PsiArena +141% 证明闭环价值。
