# 生产冲刺：落地清单与面试

> 收官篇：把 01-09 收敛成可执行清单与面试弹药。2026 生产基线：**OTel 互操作 + 四支柱 + session 单位 + tail 采样 + 质量告警 + 闭环**——可观测的目标不是仪表盘，是"每个失败都变成改进"。

## 1. 生产落地清单（上线前逐项打勾）

### 1.1 追踪层

| 检查项 | 标准 |
|---|---|
| Trace 结构 | 会话 span → 推理 span → 工具 span（子挂触发推理步） |
| Agent span | create_agent（含 version）+ invoke_agent |
| 会话关联 | conversation.id 传播进下游系统 span |
| 插桩方式 | 框架插桩器优先，无手写 span |
| RAG 场景 | Embedding/Retrieval/Generation 三段隔离 |

### 1.2 语义与指标层

| 检查项 | 标准 |
|---|---|
| OTel 输出 | gen_ai.* 语义（STABILITY_OPT_IN 固定版本） |
| Span 完整度 | >95% 审计通过 |
| 四类指标 | 基础设施/成本/循环/质量齐备 |
| 工具级指标 | 分工具失败率（不是总体） |
| Turn 预算 | 25 轮上限 + 双峰联动告警 |

### 1.3 评估层

| 检查项 | 标准 |
|---|---|
| 遥测契约 | 工具结果从执行层采集，不信自报 |
| 三级评估 | 单步 + 全轮 + 多轮（thread） |
| LLM-judge | 10-20% 采样 + 分数写 span 属性 |
| 评估预算 | Trust Tax 已计入成本治理 |
| 评估器校准 | 自定义评估器与人工对齐 |

### 1.4 治理层

| 检查项 | 标准 |
|---|---|
| 采样 | tail-based（100% 错误/低分/高成本 + 1-10% 干净） |
| 脱敏 | collector 层集中脱敏 |
| 保留分层 | Hot 14-30 天 / Warm 90 天 / Cold 1-7 年 |
| 成本断路器 | 会话级预算 + 陡增熔断 |
| 告警 | 健康 + 质量 + 循环三类齐备、附 trace 链接 |
| 闭环 | 失败→分流→人审→eval 回归 |

## 2. 十二大避坑

| # | 坑 | 后果 | 解法 |
|---|---|---|---|
| 1 | 只接日志不接 trace | 决策质量不可见 | 四支柱（01 篇） |
| 2 | 以 request 为观测单位 | 会话漂移漏掉 | session 单位（01 篇） |
| 3 | conversation.id 不传播 | 全栈视角缺失 | 传播进下游 span（02 篇） |
| 4 | 手写 span | 规模漏埋 | 框架插桩器（02 篇） |
| 5 | 成本看单调用 | 意外账单 | 会话级核算 + 断路器（05 篇） |
| 6 | 不看工具级失败率 | 搜索工具 30% 失败被掩盖 | 分工具指标（04 篇） |
| 7 | 不信自报的对面——信自报 | 隐藏失败模式 | 遥测契约（06 篇） |
| 8 | 只评最终回答 | 抓不住工具选错 | 三级粒度（06 篇） |
| 9 | head-based 采样 | 丢失败证据 | tail-based（08 篇） |
| 10 | 应用层脱敏 | 策略分散不可审计 | collector 集中（08 篇） |
| 11 | 告警只看健康 | 决策问题失明 | 质量 + 循环告警（09 篇） |
| 12 | 失败发 Slack | 改进无闭环 | 失败→eval/实验（09 篇） |

> 🎯 核心要点：12 坑根因是三个——**观测维度不全（1-4、8）、治理单位错（5-6、9）、闭环缺失（7、10-12）**。按 01/02/05/06/08/09 篇规范做，12 坑自动消失。

## 3. 指标体系

| 指标 | 计算 | 目标 |
|---|---|---|
| Span 完整度 | 属性齐全 span 占比 | >95% |
| 会话成本 | 会话级 token/费用 | 预算内 + 告警前置 |
| 轮次命中率 | 达 25 轮上限会话占比 | 低（突增 = 回归） |
| 工具失败率 | 分工具失败占比 | <5%（工具级） |
| 评估分 | LLM-judge 采样均分 | 阈值内 + 趋势监控 |
| 重试率 | 重试调用占比 | <5% |
| 采样覆盖率 | 保留 trace 占总量比 | 诊断覆盖达标 |
| 闭环转化率 | 失败转 eval 样本比例 | 高（失败即资产） |

> 💡 最该盯的两个：**工具失败率**（决策质量隐藏杀手）与**闭环转化率**（可观测是否产生行动——仪表盘再美不转化 = 装饰）。

## 4. 面试题（14 题 + 答题范式）

### 4.1 基础（必答）

**Q1：Agent 可观测为什么需要四支柱？**
> Agent 非确定性——日志/指标回答"发生什么、多快多贵"，评估回答"好不好"，监控实时告警，优化闭环。四支柱：Trace/Evaluate/Monitor/Optimize；只做 Trace 的团队="有录像没裁判"。

**Q2：为什么 session 是观测单位？**
> request 健康会话漂移是常见假象——第 1 轮识别问题、第 2 轮检索对、第 3 轮没用上，三个 request 各自健康整个会话失败。会话级成本/质量/轮次只有 session 轨迹能暴露。

**Q3：Trace 层次模型？**
> 会话 span → 推理 span → 工具 span（子挂触发它的推理步）。工具 span 是归因的关键——"哪步决策导致哪个调用"。

### 4.2 进阶（加分）

**Q4：gen_ai.* 语义约定？**
> OTel GenAI 属性：operation.name、provider/model、usage tokens、cost（微美元）、cache、agent id/name/version、conversation.id——换后端改配置不改代码；OTel 记录不评估。

**Q5：四类指标？**
> 基础设施（延迟/token）/成本（会话级）/循环迭代（轮次、工具失败率）/质量（eval）——工具失败率 30% 不显示在延迟里，分工具统计是 Agent 特有雷达。

**Q6：turn 预算与双峰联动？**
> 25 轮会话上限；P99 延迟与轮次命中率同时飙升 → 几乎总是提示回归或新坏工具——两个独立指标同时异常指向根因。

**Q7：tail-based 采样？**
> head 随机丢 = 丢失败证据（失败稀有且高价值）。tail：100% 错误/低分/高成本 + 1-10% 干净；dev 全量做评估集素材。

**Q8：遥测契约？**
> 工具结果从执行层采集，独立于 Agent 内部推理——遇错模型常产出"看似合理"输出，自报不可信。

### 4.3 架构与治理（拉开差距）

**Q9：三平台选型？**
> Langfuse（MIT 核心、框架无关、1M events ~$101）、LangSmith（LangChain 原生、~$2,514）、Phoenix（ELv2 source-available、单容器）。"开源"≠OSI 开源是采购陷阱；双工具模式（trace 层 + eval 层）是主流。

**Q10：质量告警与评估持续化？**
> 评估分阈值告警（Agent 特有）；评估是持续流水线——"上个月通过的 eval 说明不了这周"；LLM-judge 采样 10-20%，Trust Tax 要预算（~$260K/年 @500K traces/天）。

**Q11：成本治理三件套？**
> span 级记账（gen_ai.usage.cost）→ 会话级核算 → 断路器/层级预算；浪费归因（LangCost：重复读取/故障级联/静默误用——按成本排序修复清单）；降本第一步是缓存纪律。

**Q12：traces→fixes 闭环？**
> 生产失败→自动分流（Engine：分组/根因/起草）→人审签字→eval 回归→灰度。"生产失败应该变成 eval 样本/实验/治理事件，不是 Slack 线程"。

**Q13：数据治理？**
> collector 层脱敏（策略集中）+ 保留分层（14-30 天 hot/90 天 warm/1-7 年 cold）+ span 爆炸治理（采样+层级压缩）+ conversation.id 传播防多轮丢失。

**Q14：治理内核与可观测关系？**
> OPA Rego/Cedar 亚毫秒确定性拦截（执行），观测记录/评估（观察）——同一动作双视角；提示词只做引导不做主治理层。

### 4.4 答题范式

| 原则 | 说明 |
|---|---|
| 结构优先 | 定义 → 机制 → 实证 → 工程（四段式） |
| 带数据 | "1M events $101 vs $2,514""25 轮""95% 完整度"——实证碾压空谈 |
| 说权衡 | "评估采样 10-20% 换 Trust Tax 可控""head 简单但丢证据" |
| 落工程 | 补一句"生产上我怎么做"（完整度审计/双峰告警/闭环转化） |
| 提边界 | 何时不做：小规模 Agent 单 trace 工具起步，不上全套平台 |

## 6. 面试速记（终极压缩）

1. **四支柱**：Trace（做了什么）+ Evaluate（好不好）+ Monitor（出事没）+ Optimize（改什么）——只做 Trace 是"有录像没裁判"。
2. **Session 单位**：request 健康会话漂移是常态——成本/质量/轮次都在会话层看。
3. **OTel 互操作**：gen_ai.* 语义换后端改配置；OTel 记录不评估——评估是上层。
4. **治理三件套**：tail 采样（保证据）+ collector 脱敏（策略集中）+ 会话级成本断路器（防账单）。
5. **闭环**：失败即资产——自动分流 → 人审 → eval 回归；"生产失败变成 eval 样本，不是 Slack 线程"。
