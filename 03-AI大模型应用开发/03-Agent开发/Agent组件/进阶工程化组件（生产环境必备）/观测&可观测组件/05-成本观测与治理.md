# 成本观测与治理

> 成本 = Agent 可观测的**第一性问题**——Agent 每次推理都是钱，循环失控的账单比故障更常见。2026 三件套：**span 级成本记账（gen_ai.usage.cost）+ 会话级核算 + 断路器/预算层级**；工具侧：AgentMesh 断路器、LangCost 浪费归因、Noctrace 上下文健康分。本章给成本观测与治理完整设计。

## 1. 为什么成本是 Agent 第一性问题

| Agent 成本特征 | 后果 |
|---|---|
| 每步都是模型调用 | 一次任务 = 多次计费（规划+工具+反思+重试） |
| 循环天然会失控 | 无预算 = 无限循环账单（Tool 06 篇教训：$8 读同一文件 1000 次） |
| 成本随模型升级漂移 | 换模型/改提示 = 成本结构突变 |
| 会话聚合是账单单位 | 单调用正常、会话爆炸（04 篇） |

> 🎯 核心要点：**成本是观测对象不是财务问题**——成本异常模式（重复调用、无用检索、过度反思）直接暴露 Agent 行为缺陷；成本治理与质量治理共享同一套 trace（05 篇浪费归因）。

## 2. Span 级成本记账

| 项 | 说明 |
|---|---|
| 属性 | `gen_ai.usage.cost`（微美元）、input/output/cache_read 分列 |
| 位置 | 模型调用 span 上（03 篇语义约定） |
| 汇总 | trace 级求和 → 会话级聚合（02 篇结构） |
| 前提 | 定价表内置（36-50+ 模型，2026 工具内置） |

> 💡 span 级成本的审计价值：**"这轮会话的 $3.2 花在哪了"可逐 span 回答**——成本归因粒度到单个模型调用是治理的前提。

## 3. 会话级核算与预算

| 机制 | 说明 |
|---|---|
| 会话聚合 | 跨轮 token/成本合计——意外账单的源头（04 篇） |
| 会话预算 | 每会话成本上限（按任务类型差异化） |
| 层级预算 | 网关层层次结构：全局 → 团队 → 会话（Guardrails 09 篇 JIT 同构） |
| 告警先行 | 阈值告警在账单前触发——别等月底 |
| 断路器 | 陡增自动熔断（AgentMesh 原生能力） |

> ⚠️ 2026 教训（Vercel）：**"单调用看着正常、会话模式失控"是账单惊吓的标准剧本**——会话级成本是预算控制的有效单位，不是调用级。

## 4. 浪费归因：LangCost 类工具

| 检测模式 | 机制 | 例子 |
|---|---|---|
| Token 浪费 | 重复读取同一文件/重复调用 | $8 读同一文件 1000 次（有 trace 特征） |
| 故障级联 | 失败后的重试风暴 | 重试率 >5%（Tool 06 篇联动） |
| 静默误用 | 无异常但低效的工具使用 | 大模型做简单格式化 |
| 无用检索 | 检索块未被引用 | 信号利用率（感知 02 篇联动） |

> 🎯 核心要点：**浪费归因 = 成本 × 行为缺陷**——LangCost 类工具把"花了多少钱"升级为"为什么花、哪里浪费、先修哪个"（按成本排序的修复清单）。这是成本治理从记账到优化的升级。

## 5. 编码 Agent 成本观测：Noctrace 模式

| 能力 | 说明 |
|---|---|
| 上下文健康分 | 上下文窗口使用健康度评分 |
| Token-drift 检测 | 上下文漂移检测（越用越乱） |
| 循环/重读检测 | 重复工具调用实时识别（02 篇循环检测的编码 Agent 版） |
| 水瀑布时间线 | DevTools 风格工具调用瀑布 + 每行 USD 成本 |

> 💡 编码 Agent（Claude Code/Codex CLI 类）是成本失控高发区——**上下文健康分 + 重读检测**是两个最实用的信号：上下文腐烂是隐性成本放大器（感知 08 篇上下文五失败联动）。

## 6. 成本工具生态（2026）

| 工具 | 定位 | 特点 |
|---|---|---|
| AgentMesh | 多 Agent 成本治理 | 每 Agent token/错误/延迟仪表盘 + 原生断路器 |
| LangCost | 成本智能 + 故障归因 | 36 模型定价、按成本排序 CLI 报告 |
| Helicone | 零代码代理成本层 | 自动捕获延迟/token/错误——代理会漏 Agent 间消息 |
| Noctrace | 编码 Agent 本地观测 | 零配置、上下文健康、重读检测 |
| MLflow AI Gateway | 跨供应商网关 | 限流 + 成本预算执行 |
| spanlens/LLMTap | 轻量 SDK/代理 | 父-子 span + 50+ 模型定价 |

> 🎯 核心要点：**代理型（proxy）成本工具适合快速起步但漏 Agent 间消息**——多 Agent 场景要 trace 层工具 + 代理层成本组合（2026 共识：Helicone 类作成本层、trace 工具作行为层）。

## 7. 成本治理闭环

```text
成本治理闭环：
  span 级记账 → 会话聚合 → 预算/断路器
  → 告警（超阈值）
  → 浪费归因（LangCost 报告：按成本排序）
  → 修复（提示/工具/缓存/模型降级）
  → 回归验证（成本基线对比）
```

| 环节 | 产出 |
|---|---|
| 记账 | 成本基线（每 Agent/任务类型） |
| 预警 | 阈值告警（会话/团队/全局） |
| 归因 | 按成本排序的修复清单 |
| 修复 | 缓存命中优化、模型降级、循环收敛（Tool 06 预算） |
| 验证 | 修复后成本基线对比 |

> 💡 与 Function Calling 09 篇（prompt caching 降本）衔接：**缓存是最便宜的降本**——工具定义稳定前缀 + 缓存断点可降 50-90% 重复成本；成本治理从"记账"到"优化"的第一步通常是缓存纪律。

## 8. 常见误区

| 误区 | 真相 |
|---|---|
| "成本是财务的事" | 成本异常暴露行为缺陷——是观测对象 |
| "看总账单就行" | span 级归因才能回答"$3.2 花哪了" |
| "单调用限流够了" | 会话模式失控才是账单剧本——单位是会话 |
| "断路器可选" | 成本陡增熔断是防失控硬件——必装 |
| "代理工具全覆盖" | 代理漏 Agent 间消息——多 Agent 要 trace 层组合 |
| "成本治理=记账" | 浪费归因（按成本排序修复清单）才是治理 |
| "降本=换便宜模型" | 缓存纪律（50-90%）是第一步——比换模型安全 |

## 9. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 为什么成本是第一性问题？ | 每步模型调用、循环天然失控、会话聚合是账单单位 |
| span 级成本？ | gen_ai.usage.cost 微美元——归因到单调用 |
| 意外账单标准剧本？ | 单调用正常、会话模式失控——治理单位是会话 |
| 断路器？ | 成本陡增自动熔断（AgentMesh）——防失控硬件 |
| 浪费归因？ | 重复读取/故障级联/静默误用/无用检索——按成本排序修复 |
| Noctrace 关键信号？ | 上下文健康分 + 重读检测（编码 Agent） |
| 代理成本工具局限？ | 漏 Agent 间消息——trace 层 + 代理层组合 |
| 降本第一步？ | 缓存纪律（50-90%）——比换模型安全 |
| 成本治理闭环？ | 记账→预警→归因→修复→验证 |
| 层级预算？ | 全局→团队→会话——网关层执行 |
| 与 Tool 06 联动？ | 预算（max_iterations/成本上限）是执行侧，观测侧记账归因 |
| 成本与质量共享什么？ | 同一套 trace——成本异常也是行为信号 |
