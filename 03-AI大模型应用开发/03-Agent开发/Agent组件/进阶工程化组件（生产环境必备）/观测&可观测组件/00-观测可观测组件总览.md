# 观测&可观测组件知识体系总览

> 定位：Agent 生产工程化组件之「观测与可观测性」——Trace（执行树）+ Evaluate（质量层）+ Monitor（实时监控）+ Optimize（闭环优化）四支柱。2026 核心共识：**Agent 非确定性，传统日志/指标观测量不出"决策好不好"**；OTel GenAI 语义约定成为跨厂商互操作契约；**session 是观测单位，不是 request**。总览做索引与速查，子主题各一篇。

## 4. 核心概念速查

| 概念 | 一句话定义 |
|---|---|
| 可观测四支柱 | Trace（执行树）+ Evaluate（质量）+ Monitor（监控）+ Optimize（闭环） |
| Session | 多轮会话的观测单位——request 健康但会话漂移是常见假象 |
| Trace | 输入到输出的完整执行树（每个步骤一个 span/run） |
| gen_ai.* | OTel GenAI 语义约定属性命名空间（跨厂商互操作契约） |
| create_agent / invoke_agent | Agent 两类 span：初始化（ID/版本）与执行（会话/输入输出） |
| gen_ai.conversation.id | 把跨 trace 的 span 绑成一个会话的关联键 |
| OpenInference | 8 种 span kind：CHAIN/LLM/RETRIEVER/TOOL/AGENT/EMBEDDING/RERANKER |
| 遥测契约 | 规定必须采集的状态转移/工具结果——**不信 Agent 自报** |
| 四类指标 | 基础设施/成本/循环迭代/质量（质量靠 eval 不是日志） |
| Turn 预算 | 会话轮次上限（常见 25 轮）——超限触发人工介入 |
| 成本断路器 | 会话级成本上限，阻止失控执行 |
| LLM-as-judge | 10-20% 采样线上流量自动打分（准确性/相关性/指令遵循） |
| Tail-based 采样 | 100% 保留错误/低分/高成本，1-10% 干净 trace |
| Evaluation Trust Tax | 外部 LLM judge 的成本（~$260K/年 @500K traces/天） |
| 质量告警 | 评估分跌破阈值告警——不是只看延迟/错误率 |
| 治理内核 | OPA Rego/Cedar 确定性策略检查（毫秒级拦截） |
| Span 完整度 | <95% 时仪表盘撒谎——补属性是最快收益 |

## 5. 2026 生态基准

> 📅 基准窗口：2026-08。版本与事实以各模块【参考来源】为准。

- **四支柱定型**：Microsoft Foundry（Build 2026）把 Agent 可观测组织为 Trace/Evaluate/Monitor/Optimize 四支柱；LangChain 三支柱（监控追踪/指标评估/真实世界分析）同向——**"决策好不好"是观测对象，不只是"步骤失败没"**。
- **OTel 成为互操作契约**：GenAI 语义约定（gen_ai.*）覆盖 operation/provider/model/usage/cost（微美元）/缓存/agent（id/name/version）/conversation.id；后端切换（Phoenix/Langfuse/Datadog/Honeycomb）从改代码变成改配置；OpenInference 8 种 span kind 并行；各平台在摄入期把旧 schema 规范化为 gen_ai.*。
- **Session 是观测单位**：request 健康、会话漂移是常见假象——会话级成本核算、25 轮 turn 预算、会话级质量（跨轮失败模式只能会话轨迹暴露）。
- **采样策略反转**：head-based 默认丢弃是 LLM 系统的错误默认——失败稀有且高价值；tail-based 优先（100% 错误/低分/高成本 + 1-10% 干净）。
- **平台格局**：Langfuse（MIT 核心，ClickHouse 2026-01 收购，1M events ~$101/mo，Experiments CI/CD 2026-05）vs LangSmith（闭源 LangChain 深度集成，1M events ~$2514/mo，Fleet 2026-03）vs Phoenix（ELv2 source-available，单容器自托管，CLI prompt 2026-01）；**"开源"≠"OSI 开源"是采购陷阱**（Phoenix ELv2、Langfuse 企业目录商业许可）。
- **成本治理产品化**：AgentMesh（多 Agent 成本断路器）、LangCost（token 浪费归因）、Noctrace（编码 Agent 上下文健康分/token-drift/循环检测）、Helicone（零代码代理成本层）、AI Gateway（跨供应商预算）——**成本是 Agent 观测的第一性问题**。
- **评估是持续流水线**：不是上线门禁——"上个月通过的 eval 说明不了这周"（Vercel）；LLM-judge 采样 10-20% + 人工抽查 + 失败转 eval 样本；Evaluation Trust Tax 是隐形成本（~$260K/年）。
- **治理进决策管道**：确定性策略内核（OPA Rego/Cedar）毫秒级拦截动作；提示词只做引导不做治理主层（与 Guardrails 09 篇同源）。
- **与体系分工**：[日志监控指标](..%2F..%2F..%2F..%2F..%2F02-后端核心技术%20微服务%20分布式%20云原生%2F07-工程运维基础%2F运维%2F日志监控指标%2F00-日志监控指标总览.md) 管 JVM/Java/OTel 基础设施层；本体系管 LLM/Agent 应用层（gen_ai 语义/Agent 追踪/成本/评估）；[安全护栏 Guardrails](..%2F安全护栏%20Guardrails%2F00-安全护栏Guardrails总览.md) 管拦截，本体系管观察——拦截与观察互补。
