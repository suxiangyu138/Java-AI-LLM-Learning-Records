# 指标：四类指标体系

> 指标 = Agent 健康的量化仪表。2026 分类：**基础设施/成本/循环迭代/质量**四类——前两类传统就有，后两类是 Agent 特有；质量指标靠 eval 不靠日志。关键机制：**turn 预算（25 轮）与成本断路器**是防失控双闸。本章给指标体系完整设计。

## 1. 四类指标地图

| 类别 | 指标 | 传统 | Agent 特有 |
|---|---|---|---|
| 基础设施 | 延迟（P99）、错误率、token 用量 | ✅ | — |
| 成本 | 会话级 token/API 费用 | ✅（会话级是 Agent 特有） | 部分 |
| 循环迭代 | 每会话轮次、工具调用频率/失败率 | — | ✅ |
| 质量 | 任务完成、幻觉率、接地性（eval） | — | ✅ |

> 🎯 核心要点：**前两类告诉你"系统活着吗、贵不贵"，后两类告诉你"干得对吗、要出事吗"**——只盯前两类的团队在 Agent 场景会漏掉最贵的故障（选错工具不报错）。

## 2. 循环迭代指标：Agent 特有雷达

| 指标 | 信号 | 响应 |
|---|---|---|
| 每会话轮次数 | 突增 = 提示回归或坏工具 | 检查最近提示/工具变更 |
| 工具调用频率（分工具） | 某工具使用率突变 | 行为漂移 |
| 工具失败率（分工具） | **搜索工具失败 30% 不显示在延迟里** | 修复工具或替换 |
| 计划-执行周期数 | 规划循环放大 | 规划器回归（Planner 06 篇） |
| 重试率 | >5% = 契约或模型问题（Tool 06 篇） | 修契约不堆重试 |

> ⚠️ 关键洞察：**工具级失败率是"隐藏杀手"**——总体延迟/错误率被平滑掩盖，只有分工具统计才暴露。这是 Agent 指标与后端指标的本质差异。

## 3. Turn 预算：会话轮次上限

| 项 | 说明 |
|---|---|
| 规则 | 每会话轮次上限（常见 **25 轮**），超限触发人工介入 |
| 目的 | 防无限循环（Tool 06 篇 max_iterations 的会话级版本） |
| 告警联动 | P99 延迟与轮次命中率**同时飙升** → 几乎总是提示回归或新坏工具（MLflow） |
| 终止语义 | 结构化终止 + 人工介入（Tool 06 篇 early stopping 模式） |

> 🎯 核心要点：**轮次命中率与延迟的双峰联动是最高价值的复合信号**——两个独立指标同时异常，指向根因的概率极高（提示回归/坏工具），比单指标告警可靠得多。

## 4. 成本断路器：预算硬闸

| 机制 | 说明 |
|---|---|
| 会话级成本限制 | 每会话成本上限，超限终止 |
| 层级预算 | 网关层设层次预算——失控循环在账单到达前被拒 |
| 告警先行 | 会话成本阈值告警——别等账单（05 篇） |
| 断路器 | 成本陡增自动熔断（AgentMesh 类） |

> ⚠️ 2026 教训：**意外账单几乎都是"单调用看着正常、会话模式失控"**——单调用成本正常不代表会话健康；成本治理的单位必须是会话（05 篇）。

## 5. 质量指标：靠 eval 不靠日志

| 指标 | 来源 | 粒度 |
|---|---|---|
| 任务完成率 | eval（LLM-judge/代码检查） | 单轮/全轮/多轮 |
| 解决率 | 客服类人工/自动标注 | 会话 |
| 升级频率 | 业务埋点 | 会话 |
| 幻觉率 | eval 采样（10-20%） | 单轮 |
| 接地性 | 引用/来源检查 | 单轮 |

> 💡 质量指标的铁律：**日志测不出来**——"模型输出是否幻觉"没有日志字段，只能评估层采样打分（06 篇）。质量指标是 eval 的输出，不是指标的第四类别名。

## 6. 指标 → 告警映射

| 信号 | 告警 | 严重级 |
|---|---|---|
| 轮次命中率突增 | 循环失控预警 | P1 |
| 工具失败率 >阈值 | 工具故障 | P1（影响质量） |
| 会话成本超阈值 | 成本告警 | P2 |
| 评估分跌破阈值 | 质量告警（09 篇） | P1 |
| 重试率 >5% | 契约回归 | P2 |
| P99 延迟 + 轮次双升 | 提示/工具回归 | P1 |

> 🎯 核心要点：**告警是质量优先不是健康优先**——传统"延迟/错误率"告警之外，Agent 必须加"质量告警"（评估分阈值）与"循环告警"（轮次/成本）——这两类是 Agent 事故的主要形态（09 篇）。

## 7. 指标治理规范

| 规范 | 内容 |
|---|---|
| 基数控制 | 工具名/Agent 名做属性——标签基数可控（与日志监控指标体系同规） |
| 分桶统计 | 按 Agent/工具/模型版本分桶——漂移可定位 |
| 保留策略 | 指标可长期保留（比 trace 便宜） |
| 与 trace 联动 | 指标异常 → drill-down 进具体 trace（09 篇） |

> 💡 指标与 trace 的分工：**指标回答"现在整体怎样"，trace 回答"这一个为什么"**——从仪表盘 drill-down 到 trace 是排障的标准动作（09 篇闭环）。

## 8. 常见误区

| 误区 | 真相 |
|---|---|
| "延迟错误率管够" | 工具失败率/质量指标是 Agent 特有——不盯会漏最贵故障 |
| "成本看单调用" | 意外账单在会话模式——单位是会话 |
| "轮次上限够了" | 上限要有告警联动——双峰信号是最高价值 |
| "质量指标写日志" | 日志测不出"好不好"——eval 采样打分 |
| "指标告警只看健康" | 质量告警（评估分）+ 循环告警（轮次/成本）是 Agent 特有 |
| "工具失败率总体看" | 分工具统计——总体平滑掩盖单工具 30% 失败 |
| "指标全量保留" | 指标便宜可长期；trace 贵要分层（08 篇） |

## 9. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 四类指标？ | 基础设施/成本/循环迭代/质量 |
| 工具级失败率为什么重要？ | 单工具 30% 失败被总体平滑——分工具才暴露 |
| Turn 预算？ | 会话轮次上限（常见 25 轮）——超限人工介入 |
| 双峰联动？ | P99 延迟+轮次命中率同升 → 提示回归/坏工具 |
| 成本断路器？ | 会话级成本上限——失控在账单前被拒 |
| 意外账单根因？ | 单调用正常、会话模式失控——治理单位是会话 |
| 质量指标来源？ | eval 采样打分——日志测不出来 |
| Agent 特有告警？ | 质量告警（评估分阈值）+ 循环告警（轮次/成本） |
| 重试率红线？ | >5% = 契约或模型问题 |
| 指标与 trace 分工？ | 指标答整体，trace 答这一个——drill-down 排障 |
| 基数控制？ | 工具名/Agent 名属性——与日志体系同规 |
| 与 05 篇关系？ | 成本断路器是成本治理的机制入口 |
