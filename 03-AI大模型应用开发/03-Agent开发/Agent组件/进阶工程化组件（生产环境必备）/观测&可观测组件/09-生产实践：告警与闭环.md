# 生产实践：告警与闭环

> 生产实践 = 让观测**产生行动**：质量告警（不只看健康）、traces→fixes 闭环（失败变改进）、治理内核（确定性拦截）。2026 共识：**可观测是连续循环不是被动仪表盘**——"生产失败应该变成 eval 样本/实验/治理事件，不是 Slack 线程"。本章给生产告警与闭环完整设计。

## 1. 告警体系：健康 + 质量 + 循环三类

| 类别 | 触发 | 严重级 | 例子 |
|---|---|---|---|
| 健康告警 | 延迟/错误率/token 异常 | P1-P2 | P99 飙升 |
| 质量告警 | 评估分跌破阈值 | P1 | 幻觉率突增、任务完成率下降 |
| 循环告警 | 轮次/成本异常 | P1 | 轮次命中率突增、成本陡增（04 篇） |

> 🎯 核心要点：**质量告警是 Agent 特有**（06 篇）——评估分阈值告警；传统"延迟/错误率"健康告警对 Agent 决策问题失明（选错工具不报错）。三类都要：健康告警管系统、质量告警管决策、循环告警管失控。

## 2. Traces → Fixes 闭环

```text
闭环（2026 标准）：
  生产 trace（失败/低分/高成本）
    → 自动分流（Engine 类：分组同类失败、诊断根因、起草修复）
    → 人审签字（修复草案 + 新增评估）
    → eval 验证（修复进评测集回归）
    → 灰度上线（观测修复效果）
```

| 环节 | 做法 |
|---|---|
| 分流 | 自动分组同类失败 → 命名 issue → 根因诊断（LangSmith Engine） |
| 证据 | 失败 trace 附截图/span/根因链 |
| 起草 | 提示/代码修复草案 + 对应评估 |
| 人审 | 人类签字（自动化 triage 不是全自动部署） |
| 回归 | 修复样本进评测集——防复发 |

> ⚠️ 2026 金句（LangChain）：**"生产失败应该变成 eval、保存的示例、实验或治理事件——不是 Slack 线程"**——闭环的起点是"失败即资产"，终点是"回归即防线"。

## 3. 评估是持续流水线

| 传统模式 | 2026 模式 |
|---|---|
| 上线前跑一次 eval | 生产采样流量持续评分（10-20%） |
| "上线通过就放心" | **"上个月通过的 eval 说明不了这周"**（Vercel） |
| 人工看仪表盘 | 自动评分 + 人工抽查 + 告警 |
| 评估与观测分离 | 评估分写 span 属性——与 trace 同查 |

> 🎯 核心要点：**评估的时态问题——模型/工具/流量一直在变，评估必须持续**。持续评估 = 采样判分 + 阈值告警 + 失败样本回流；这是质量告警的数据源（§1）。

## 4. 治理内核：确定性拦截进决策管道

| 项 | 说明 |
|---|---|
| 机制 | 确定性策略检查（OPA Rego/Cedar）拦截每个动作 |
| 性能 | 亚毫秒级（sub-ms） |
| 拦截对象 | 目标劫持、未授权工具调用、越界动作 |
| 与提示词分工 | **"别把提示词级安全指令当主治理层"**——内核管执行、提示词管引导 |
| 联动 | Guardrails 09 篇治理 + 本体系观测——拦截决策与结果都发遥测 |

> ⚠️ 与 Guardrails 体系的分工确认：**治理内核是"执行"（拦截），本体系是"观察"（记录/评估）**——同一个动作既有内核决策 trace 又有行为评估，双视角是 2026 生产标准。

## 5. Span 完整度审计：体检第一步

| 步骤 | 内容 |
|---|---|
| 完整度报表 | 每类型 span 属性齐全率（03 篇） |
| 审计节奏 | 持续（新代码路径悄悄丢 span） |
| 修复 | 补缺失属性（最快收益） |
| 门禁 | 新插桩 PR 带完整度检查 |

> 💡 完整度是闭环的前提：**分流/归因/评估都在不完整 trace 上工作 = 结论是猜测**。生产排障顺序永远先查完整度再查问题。

## 6. 生产告警与响应规范

| 规范 | 内容 |
|---|---|
| 告警降噪 | 聚合同类告警（会话级不刷屏单调用） |
| 分级路由 | P1 走电话/即时通道，P2 工单 |
| 告警内容 | 附 trace 链接——从告警直达证据 |
| 事后复盘 | 失败 trace 转 eval 样本 + 根因文档（闭环 §2） |
| 告警可测 | 告警规则本身进评测集（防误报风暴） |

> 🎯 核心要点：**告警要能"点到 trace"**——告警不带 trace 链接 = 排障第一分钟浪费在找证据；2026 平台标准是聚合指标 → drill-down trace 一步到位（Observe 六表面之一）。

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "告警只看健康" | 质量/循环告警是 Agent 特有——决策问题健康告警看不见 |
| "失败发群里" | 失败是资产——转 eval 样本/实验/治理事件 |
| "eval 上线跑一次" | 持续流水线——每周都在变 |
| "自动 triage 全自动" | 自动分流 + 人类签字——修复要人审 |
| "提示词管治理" | 内核管执行（确定性），提示词管引导 |
| "观测=看仪表盘" | 闭环：观测→归因→修复→回归 |
| "完整度差不多" | <95% 结论是猜测——先审计再分析 |
| "告警越灵敏越好" | 误报风暴毁告警文化——规则进评测集 |

## 8. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 三类告警？ | 健康（系统）/质量（决策）/循环（失控） |
| 质量告警是什么？ | 评估分阈值告警——Agent 特有 |
| Traces→Fixes 闭环？ | 失败→自动分流→人审→eval 回归→灰度 |
| 失败是资产？ | 生产失败变 eval/示例/实验/治理事件，不是 Slack 线程 |
| eval 持续化？ | 采样评分持续跑——上个月过的说明不了这周 |
| 治理内核？ | OPA Rego/Cedar 亚毫秒拦截——内核管执行提示词管引导 |
| 与 Guardrails 分工？ | 内核拦截（执行），本体系观察（记录/评估） |
| 完整度审计？ | <95% 结论是猜测——体检第一步 |
| 告警规范？ | 附 trace 链接、分级路由、规则进评测集 |
| 自动 triage 边界？ | 自动分流 + 人类签字 |
| 闭环起点？ | 失败即资产 |
| 告警与 trace 关系？ | 聚合指标 → drill-down trace 一步到位 |
