# 调度与并发：程序级调度

> 调度 = 多个 Agent 程序在有限算力上的"操作系统"问题。2026 范式转移：**从请求级调度走向程序级调度**（把整个 LLM 轮→工具→轮 循环当调度单位）——解决请求级路由器看不见的缓存占用爆炸与工具边界背压。本章给调度与并发完整设计。

## 1. 为什么请求级调度不够

| 请求级调度的问题 | 程序级调度的答案 |
|---|---|
| 缓存占用爆炸 | N 个 Agent × 轮间空闲持有的上下文（KV cache） |
| 无工具边界背压 | 只能取消/排队在途请求——都比在自然暂停点挂起差 |
| 会话内断链 | 同一 Agent 的轮次被不同机器处理 |

> 🎯 核心要点：**调度单位 = Agent 程序（LLM turn → tool call → next turn 循环）**——按 session_id/trajectory_id 分组；程序状态机 (REASONING|ACTING)×(ACTIVE|PAUSED)（NVIDIA ThunderAgent/Dynamo）。

## 2. 工具边界暂停/恢复（2026 核心机制）

| 语义 | 说明 |
|---|---|
| 暂停是逻辑的 | 无解码抢占——在途轮次完成后挂起 |
| 暂停点 | ACTING 程序在工具边界暂停（自然暂停点） |
| 恢复 | 贪心 + BFD 打包——最小 token 程序先恢复 + 临时优先提升 |
| 防饥饿 | 强制恢复超时 |
| 防振荡 | 三带控制环：软降级带 [0.80, 0.95) 负优先级 → 硬暂停；恢复带滞后余量 |

> 💡 暂停优先序：**最小 ACTING 先暂停、REASONING 在下个工具边界暂停**——暂停"即将做副作用"的程序比暂停"正在推理"的更安全（副作用面小）。

## 3. OS 启发调度原语（HiveMind 2026）

| 原语 | 机制 | 防什么 |
|---|---|---|
| 准入控制 | 并发超过阈值拒绝新程序 | 过载崩溃 |
| 限流追踪 | 速率限制状态跟踪 | 突发 |
| AIMD 背压 + 断路器 | 加法增/乘法减 + 熔断 | 雪崩 |
| 令牌预算管理 | 每程序 token 预算 | 成本失控 |
| 优先级队列 | 优先级调度 | 饥饿/重要任务滞后 |

> 🎯 核心要点：**Agent 调度 = 传统 OS 调度原语 × LLM 特性**——五个原语全部来自 OS（准入/限流/背压/预算/优先级），但应用对象是"程序"而非"进程"；2026 的调度器是"操作系统移植"。

## 4. 队列设计：Lane-aware FIFO（OpenClaw 2026）

| 机制 | 规则 |
|---|---|
| 车道感知 FIFO | 每车道并发上限（默认未配置 1、主 4、子 Agent 8）+ 全局 cap |
| 每会话车道 | 保证单会话同时只有一个 run 触碰 |
| 队列模式 | steer（立即注入）/followup（下轮）/collect（合并为一轮，默认）/steer-backlog/interrupt |
| 溢出策略 | debounceMs（等安静）/cap（排队上限）/drop:summarize（丢弃并摘要注入） |

> ⚠️ **每会话车道是正确性机制不是优化**——防"两个 run 同时写同一会话"（单写者，06 篇）；collect 模式（合并消息为一轮）是 token 优化的核心（少轮次 = 少调用）。

## 5. 依赖感知并行：DAG 遍历（DynAMO 2026）

| 项 | 说明 |
|---|---|
| 机制 | 规划时 schema 验证 LLM 计划 → 拓扑 DAG 遍历执行 |
| 故障隔离 | 运行时失败不级联（拓扑隔离） |
| 效果 | 中位延迟 **-1.6x**；并行执行方差 **-60%** |
| 现实 | LLM 推理 + 编排仍占 >90% 端到端延迟——并发调度省的是编排间隙 |
| 警示 | 高并发负载导致不稳定——准入控制必需 |

> 🎯 核心要点：**DAG 并行省的是"编排间隙"不是"推理时间"**（推理占 90%+）——收益在方差降低（可预测性）与吞吐；高并发必须有准入控制（§3 联动）。

## 6. 生命周期确定性

| 机制 | 说明 |
|---|---|
| 会话头 | x-dynamo-session-id/parent-session-id/final（Dynamo） |
| 终止标记 | trajectory_final: true 确定性释放簿记 |
| 自愈 | close 未达 → token 权重衰减自愈调度影响 |
| 重放优先 | 重启重放事件日志——不信任快照（02 篇） |

> 💡 生命周期确定性的价值：**簿记泄漏 = 资源泄漏**——"程序结束未标记"会让调度器永远保留其状态；termination 标记 + 衰减自愈是生产调度器的卫生机制。

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "请求级调度够" | 缓存爆炸 + 无工具边界背压——程序级 |
| "暂停=抢占" | 暂停是逻辑的——在途轮次完成后再挂起 |
| "并发越多越快" | 推理占 90%+——DAG 省编排间隙，高并发需准入 |
| "队列只是排序" | 车道隔离是正确性机制——防同会话并发写 |
| "collect 模式多余" | 合并消息省轮次——token 优化核心 |
| "簿记不用管" | 终止标记+衰减——防资源泄漏 |
| "调度与幂等无关" | 并发调度放大重复副作用——幂等必需（05 篇） |

## 8. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 程序级调度？ | 以整个 Agent 循环为调度单位（按 session 分组） |
| 请求级缺什么？ | 缓存占用爆炸 + 工具边界背压 |
| 暂停语义？ | 逻辑暂停——在途完成再挂起 |
| 恢复策略？ | 贪心 BFD 打包 + 强制恢复超时防饥饿 |
| 三带控制环？ | 软降级 → 硬暂停 → 滞后恢复——防振荡 |
| OS 五原语？ | 准入/限流/AIMD 背压/令牌预算/优先级 |
| Lane-aware？ | 每会话车道上限——防同会话并发写 |
| 溢出策略？ | debounce/cap/drop:summarize |
| DAG 并行收益？ | 延迟 -1.6x、方差 -60%——省编排间隙 |
| 推理占比？ | >90% 端到端延迟——并发收益有限 |
| 生命周期？ | trajectory_final 标记 + 权重衰减自愈 |
| 与 05 篇关系？ | 并发放大重复副作用——幂等必需 |
