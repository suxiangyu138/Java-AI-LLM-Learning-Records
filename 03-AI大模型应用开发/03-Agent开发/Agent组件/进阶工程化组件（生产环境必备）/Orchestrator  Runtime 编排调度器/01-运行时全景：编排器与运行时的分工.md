# 运行时全景：编排器与运行时的分工

> 运行时 = Agent 的"操作系统"：执行引擎、状态、调度、恢复。2026 核心认知：**"持久性、编排与可恢复性是任何企业生产 Agent 的真正阻碍"**——不是模型能力，是运行时可靠性；Agent 非确定性打破了经典可靠性假设。本章立起全景：三层分工与持久三问题。

## 1. 三层分工：框架 / 编排器 / 运行时

| 层 | 职责 | 例子 |
|---|---|---|
| 框架（Agent Logic） | Agent 行为建模：图/角色/工具路由 | LangGraph、CrewAI、MAF |
| 编排器（Orchestration） | 任务编排、流程控制、多步组合 | LangGraph Platform、工作流引擎 |
| 运行时（Runtime） | 执行引擎：持久化、调度、恢复、隔离 | Temporal、Agent Executor、Catalyst |

> 🎯 核心要点：**框架管"Agent 是什么"，运行时管"Agent 怎么活"**——框架写死循环/工具路由，运行时保证崩溃后继续、并发不坏、重试不重复；2026 的失败大多在运行时层，不在框架层。

## 2. 持久三问题：生产阻碍的根源

| 问题 | 表现 |
|---|---|
| 状态丢失 | Pod 重启 Agent 丢状态（丢失进度/上下文） |
| 并发破坏 | 多组件并发写会话状态 → 会话损坏 |
| 不可恢复 | 网络抖动后工作流无法恢复 |

> ⚠️ 2026 金句（分析界共识）：**"durability, orchestration, resumability 是任何企业生产 Agent 的真正阻碍"**——原型框架（demo 可用）与生产运行时（崩溃可恢复）之间是太平洋。

## 3. 非确定性：经典可靠性假设的失效

| 经典假设 | Agent 现实 |
|---|---|
| 重试返回相同结果 | LLM 每次重试推理不同（05 篇） |
| checkpoint 可精确恢复 | 非确定性节点输出不可重放（02 篇） |
| 幂等天然成立 | 工具副作用需显式幂等键（05 篇） |
| 失败可复现 | 同一输入不同轨迹（随机采样） |

> 🎯 核心要点：**运行时不是"搬经典工作流引擎"，是重新设计**——事件日志重放（记录已发生的）、幂等包装（防重复副作用）、意图-执行分离（推理与执行分层）——2026 的持久执行全部围绕非确定性设计。

## 4. 运行时职责清单

| 职责 | 内容 |
|---|---|
| 执行引擎 | LLM 轮→工具→轮 循环（Tool 06 篇衔接） |
| 持久化 | 事件日志 + 快照（02 篇） |
| 调度 | 程序级调度、并发控制（04 篇） |
| 一致性 | 单写者会话状态（06 篇） |
| 恢复 | 崩溃/断线恢复（03 篇） |
| 隔离 | 沙箱 + 最小权限（09 篇） |
| 可观测 | 任务血统 + OTel（观测体系） |

> 💡 运行时与 Tool 06 篇的分工：Tool 06 管"循环内单调用的纪律"（校验/授权/超时）；本体系管"循环本身的生存性"（崩溃恢复/并发/幂等）——一个是纪律，一个是生命支持。

## 5. 运行时选型的决策前提

| 场景 | 运行时需求 |
|---|---|
| 短任务 <30s 单步 | 框架自带 checkpoint 够用（08 篇） |
| 长任务 >30s | 持久执行必需 |
| 3+ 外部系统调用 | Temporal 级耐久性 |
| 生产副作用（支付/部署） | 持久执行 + 幂等 + 审计 |
| 多租户并发 | 调度 + 车道隔离 + 单写者 |

> 🎯 核心要点：**运行时选型 = 任务时延 × 外部调用数 × 副作用等级**——"大多数编排工作流不需要 Temporal 的耐久性等级"（2026 共识）；过度上运行时与不上一样是错误。

## 6. 2026 运行时格局

| 形态 | 代表 |
|---|---|
| 开源分布式运行时 | Google Agent Executor（2026-05） |
| 持久执行引擎 | Temporal、Kitaru、contd.ai |
| 可验证执行 | Diagrid Catalyst 2.0（加密签名） |
| 控制平面 | Kheish（调用者/执行分离 + 审计） |
| 计算层 | Agent Substrate（K8s agent-first） |

> 💡 行业逻辑：**云厂商开源工具层、基础设施赚钱**——"上面的工具必须开源，否则没人信任"；但运行时基础设施不解决治理（问责/可解释/策略仍要监管层）。

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "框架=运行时" | 框架管行为，运行时管生存——demo 与生产差在运行时 |
| "checkpoint 就是持久" | 框架 checkpoint ≠ 持久执行（MAF 缺陷，03 篇） |
| "经典工作流引擎直接搬" | 非确定性打破假设——重新设计 |
| "短任务也要全量运行时" | 30s 内框架 checkpoint 够——过度与不足同错 |
| "运行时解决治理" | 运行时管执行，治理要监管层 |
| "崩溃=重跑" | 重跑有重复副作用——幂等 + 重放 |
| "运行时是基础设施的活" | 架构师必须懂——选型五测试（08 篇） |

| 与 Tool 06 分工？ | 06 管循环内纪律，本体系管循环生存性 |
| 选型前提？ | 时延×外部调用×副作用等级 |
| 30s 规则？ | 短任务框架 checkpoint 够用 |
| Google Agent Executor？ | 2026-05 开源分布式运行时 |
| 行业逻辑？ | 云厂商开源工具层、基础设施赚钱 |

| 崩溃≠？ | 重跑——幂等+重放 |
