# 状态与会话一致性

> 会话状态 = 多轮 Agent 的"记忆载体"——并发下的一致性是最难的问题。2026 机制定型：**单写者架构**（防多组件并发写破坏）、**存储三模式**（事件存储/命名空间向量库/文档快照）、**SecretRef**（凭据不注入明文）。本章给状态与一致性完整设计。

## 1. 单写者架构：并发一致的答案

| 项 | 说明 |
|---|---|
| 问题 | 分布式工作流多组件并发更新共享会话状态 → 损坏 |
| 机制 | 内建单写者——同一会话同一时刻只有一个写者（Agent Executor） |
| 配合 | 每会话车道（04 篇队列）——调度层防并发触碰 |
| 类比 | 数据库单主复制——写串行、读可并行 |

> 🎯 核心要点：**会话一致性 = 调度（车道）+ 存储（单写者）双保险**——调度层防"两个 run 触碰同一会话"，存储层防"一个 run 内多组件并发写"；任一层失守都会损坏会话。

## 2. 存储三模式（Orgn 2026）

| 模式 | 用途 | 特点 |
|---|---|---|
| 追加式事件存储 | 任务执行日志 | 重放/审计（02 篇） |
| 命名空间向量库 | 语义检索 | 跨命名空间查询有界 |
| 文档快照存储（版本引用） | 文档状态 | 消除并发写的读写不一致 |

> 💡 三模式的组合逻辑：**事件存储管"发生了什么"、向量库管"怎么找回"、快照管"当前是什么"**——并发下的读写不一致由"版本引用"（快照 + 版本号）消除（读旧版本不阻塞写）。

## 3. 会话生命周期

| 阶段 | 状态管理 |
|---|---|
| 创建 | 会话 ID + 车道分配（04 篇） |
| 运行 | 单写者 + checkpoint（03 篇） |
| 暂停/恢复 | 工具边界暂停（04 篇）+ checkpoint 恢复 |
| 终止 | trajectory_final 标记 + 簿记释放（04 篇） |
| 归档 | 事件存储保留（观测 08 篇保留分层） |

> 🎯 核心要点：**会话生命周期 = 调度的对象 + 状态的生命线**——每个阶段都要"状态在哪、谁在写"的明确答案；生命周期不确定性是资源泄漏与并发损坏的来源。

## 4. SecretRef：凭据不注入

| 项 | 说明 |
|---|---|
| 问题 | 明文凭据进 Agent 上下文 → 经工具输出/日志/下游 Agent 泄漏 |
| 机制 | 只传 SecretRef 占位符——执行时解析（不落地上下文） |
| 配合 | 最小权限沙箱 + 硬件强制（09 篇） |
| 收益 | 凭据永不出现在 trace/日志/交接中 |

> ⚠️ 2026 安全基线：**"绝不向 Agent 上下文注入原始秘密值"**——明文进上下文 = 泄漏到工具输出/日志/下游 Agent 的三条通道；SecretRef 模式与 Guardrails 08 篇（凭据环境变量）衔接。

## 5. 状态设计规范

| 规范 | 内容 |
|---|---|
| 类型化状态 | 结构化（非自由文本）——可校验可恢复 |
| 版本化 | 状态 schema 版本——迁移可控 |
| 最小化 | 只存决策所需（感知 02 篇够用原则） |
| 来源链 | 状态带来源（谁写的/依据什么）——审计 |
| 幂等更新 | 状态更新幂等（05 篇） |

> 💡 状态与 Memory 体系分工：**运行时状态（本体系）管"执行进度/中间产物"；记忆系统管"跨任务知识"**——一个管 run 的生命，一个管 Agent 的学习；别混（Memory 01 篇定位联动）。

## 6. 并发场景的排障

| 症状 | 根因 | 检查 |
|---|---|---|
| 会话损坏 | 双写者 | 车道配置/单写者开关 |
| 状态丢失 | checkpoint 粒度/恢复模式 | 03 篇 |
| 读到旧状态 | 读写不一致 | 版本引用/快照存储 |
| 凭据泄漏 | 明文注入 | SecretRef 审计 |
| 会话泄漏 | 未终止 | trajectory_final 检查 |

> 🎯 核心要点：**并发 bug 的症状在状态、根因在调度/存储**——"会话损坏"查车道与单写者、"读到旧"查版本引用；排障顺序先调度层再存储层。

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "并发写没事" | 会话损坏——单写者 + 车道 |
| "状态存明文简单" | 凭据泄漏三通道——SecretRef |
| "状态自由文本" | 类型化可校验——自由文本不可恢复 |
| "快照解决一切" | 版本引用消除读写不一致——不是快照 |
| "状态不版本化" | schema 迁移失控 |
| "会话结束不用标记" | 簿记泄漏——trajectory_final |
| "运行时状态=记忆" | 运行时管 run 生命，记忆管跨任务学习 |

## 8. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 单写者？ | 同会话同时一写者——防并发写破坏 |
| 双保险？ | 调度车道 + 存储单写者 |
| 存储三模式？ | 事件存储（发生了什么）/向量库（怎么找回）/快照（当前是什么） |
| 读写不一致？ | 版本引用——读旧版本不阻塞写 |
| SecretRef？ | 占位符执行时解析——凭据不进上下文 |
| 明文注入后果？ | 工具输出/日志/下游三通道泄漏 |
| 生命周期五阶段？ | 创建/运行/暂停恢复/终止/归档 |
| 状态规范？ | 类型化/版本化/最小化/来源链/幂等 |
| 与记忆分工？ | 运行时管 run 生命，记忆管跨任务学习 |
| 会话损坏查什么？ | 车道配置 + 单写者开关 |
| 读到旧状态？ | 版本引用/快照存储 |
| 凭据泄漏审计？ | SecretRef 使用审计 |
