# 渐进披露与紧凑设计

> 紧凑 = 系统提示词的"体型管理"——上下文是预算（感知 08 篇），system prompt 每多一个 token 都挤占推理。2026 设计规范：**渐进披露**（~100 token 元数据常驻 + Skill 文件按需加载，保留 10K+ token 知识）与 **<2000 token 纪律**。本章给紧凑设计完整规范。

## 1. 为什么紧凑是硬需求

| 数据 | 含义 |
|---|---|
| <2000 token 纪律 | >4000 token 是 2026 反例（注意力稀释） |
| 每 token 挤占推理 | 上下文是预算（感知 08 篇铁律） |
| 长 system prompt 衰减 | 靠后约束遵循率下降（01 篇位置原则） |
| 成本线性 | 每轮都带——token 成本直接乘轮次 |

> 🎯 核心要点：**system prompt 是每轮都付钱的固定成本**——紧凑设计 = 直接省成本 + 提升遵循率；"把细节全塞进 system prompt"是 2026 最常见的提示词错误之一。

## 2. 渐进披露：元数据 + Skill 文件

```text
渐进披露架构：
  system prompt（常驻）：
    ~100 token 元数据 —— 角色一句话 + Skill 索引（名称+触发条件）
    ↓ 按需加载
  Skill 文件（按需）：
    完整知识/规程（10K+ token 级别）
    ↓ 触发后
  注入上下文参与当前轮
```

| 层 | 内容 | token |
|---|---|---|
| 常驻元数据 | 角色 + Skill 索引 | ~100 |
| 按需 Skill | 完整规程/知识 | 10K+（不常驻） |
| 触发机制 | 任务匹配 Skill 描述时加载 | 类似 Tool 05 篇动态发现 |

> 💡 渐进披露 = **提示词版的"动态工具发现"**（Tool 05 篇 tool_search 同源思想）——"只把当前任务需要的知识装进窗口"；Agent Executor/Skill 体系的 2026 标配（`/skills` 目录、CLAUDE.md 索引模式）。

## 3. 瘦身技巧（2026 实战验证）

| 技巧 | 做法 | 收益 |
|---|---|---|
| 去版本标签 | 删"v3 新增：..."历史标注 | 模型不在乎谁加的 |
| 去重复规则 | 每条规则只在一处 | 重复稀释遵循 |
| 软化标记 | MUST/NEVER 减少 | 新模型对柔和语言更可靠（01 篇） |
| 动态数据外置 | 优先级/截止时间走实时源 | 不硬编码过期 |
| 示例精选 | 只留最有区分度的 | 示例有边际收益递减 |
| 细节外移 | 完整规程进 Skill/参考文档 | 主提示保持精干 |

> ⚠️ 2026 实证：**软化标记（dial back aggressive markers）在实战中有效**——"新模型遵循柔和语言更可靠"（oakoss 从 165 个生产提示词提炼）；MUST/NEVER 留给真正的安全关键（04 篇硬约束）。

## 4. 紧凑与完整性的权衡

| 维度 | 紧凑优先 | 完整优先 |
|---|---|---|
| 遵循率 | 高（无稀释） | 低（长提示衰减） |
| 覆盖 | 依赖 Skill 触发 | 全量在窗口 |
| 成本 | 低 | 高（每轮全带） |
| 适用 | 知识丰富场景 | 无 Skill 体系的小 Agent |

> 🎯 核心要点：**紧凑不牺牲完整性——靠"分层"而非"删减"**：常驻层精干、按需层丰富（渐进披露）；没有 Skill 体系时，取舍标准 = 知识价值 × 触发率 vs token 成本。

## 5. 与相邻体系的联动

| 体系 | 联动 |
|---|---|
| 感知 08 篇 | 上下文装配铁律——system prompt 是装配的首部（attention sink） |
| Tool 05 篇 | 动态发现同源思想——Skill 按需加载 |
| Memory 06 篇 | 关键规则钉不可压缩区（02 篇漂移防御） |
| 评估 09 篇 | 紧凑版与完整版 A/B——用评估决定而非直觉 |

> 💡 紧凑设计的验证方式：**不是"看着短就行"，是"A/B 后遵循率不降"**——评估体系（09 篇 CI 门禁）是紧凑化的安全网。

## 6. 常见误区

| 误区 | 真相 |
|---|---|
| "细节全塞 system" | >4000 token 反例——渐进披露 |
| "瘦身=删内容" | 分层外移——常驻精干、按需丰富 |
| "版本标签有用" | 模型不在乎——删 |
| "重复规则更保险" | 重复稀释遵循——每条一处 |
| "MUST 越多越安全" | 过度硬化降遵循——留给安全关键 |
| "硬编码数据" | 动态数据走实时源 |
| "紧凑=凭感觉" | A/B 验证——遵循率不降才算成功 |
