# 约束设计：硬约束与软约束

> 约束 = 系统提示词的"禁令与偏好"——决定 Agent 在边界处怎么行为。2026 设计规范：**硬约束（MUST）管安全关键、软约束（SHOULD）管风格**；**约束层级**（安全 > system > user > 示例 > 默认）是冲突裁判；**升级路径**（何时让位人类）是生产必备。本章给约束设计完整规范。

## 1. 硬约束与软约束的划分

| 维度 | 硬约束（MUST/MUST NOT） | 软约束（SHOULD/PREFER） |
|---|---|---|
| 用途 | 安全关键、不可违反 | 风格偏好、倾向 |
| 数量 | **少而精**（硬化过多降遵循） | 可多（柔和） |
| 例子 | "MUST NOT 提供医疗诊断" | "PREFER 简洁回答" |
| 强制 | 期望 + 执行层兜底（09 篇） | 期望 |

> 🎯 核心要点：**硬约束是"底线"，不是"全部期望"**——每条硬约束都要能回答"违反会怎样"（合规/安全/财务）；答不出后果的约束应该软化。硬约束的强制不能只靠提示词——执行层兜底（09 篇护栏联动）。

## 2. 约束层级：冲突的裁判

| 优先级 | 来源 | 覆盖关系 |
|---|---|---|
| 1（最高） | 安全约束 | 不可被任何指令覆盖 |
| 2 | 系统提示词 | 覆盖用户与示例 |
| 3 | 用户指令 | 覆盖示例与默认 |
| 4 | 上下文示例 | 覆盖默认 |
| 5（最低） | 模型默认行为 | 无显式指令时 |

> ⚠️ 2026 关键：**约束层级要显式写进提示词**——模型在冲突时按层级裁决；同时 2026 指令层级研究（模型原生优先 system）是架构级补充（09 篇）；"安全约束不可覆盖"要配合执行层（Guardrails 03 篇输出护栏）。

## 3. 冲突审计：写前自查

| 检查 | 内容 |
|---|---|
| 同级矛盾 | 两条约束互相否定（"回答简短"+"详细说明"） |
| 跨级矛盾 | system 与安全约束冲突 |
| 示例冲突 | few-shot 示范违反显式规则 |
| 工具冲突 | 约束与工具能力矛盾（禁止 X 但工具能 X） |
| 时间冲突 | 过时约束（旧策略残留） |

> 💡 冲突审计的工程化：**约束清单化**（每条约束编号）→ 交叉检查表 → CI 静态检查（与 05 篇注册中心联动：版本 diff 时跑约束冲突检测）。

## 4. 升级路径：何时让位人类

| 要素 | 内容 |
|---|---|
| 触发条件 | 超出范围/置信低/高风险操作（Guardrails 09 篇人工升级联动） |
| 置信阈值 | 显式写出（"识别到 X 类请求时转人工"） |
| 范围边界 | 明确"管什么不管什么"（02 篇知识边界） |
| 兜底行为 | 拒绝 + 解释 + 建议替代（refrain 语义） |

> 🎯 核心要点：**升级路径 = 约束的"出口"**——没有升级路径的约束 = 硬拒绝或硬闯（二选一都错）；生产 Agent 的约束设计必须包含"转人工/降级"语义（Tool 06 篇结构化终止联动）。

## 5. 防提取指令：约束的保护

| 指令 | 位置 | 作用 |
|---|---|---|
| 防提取 | system 首尾各一条 | 防止 system 被诱导复述（09 篇五攻击） |
| 防角色劫持 | 角色块内 | 防止被替换人格 |
| 防覆盖 | 约束层级段 | 声明不可覆盖 |

> ⚠️ 2026 原则：**"提示词应设计成被披露后仍可工作——绝不嵌秘密"**——防提取指令是降低泄漏风险的软手段，真正不泄漏靠"秘密不进提示词"（SecretRef 类比：凭据不在上下文，09 篇）。

## 6. 约束的验证

| 方式 | 内容 |
|---|---|
| 压测 | 边界场景（愤怒/离题/越狱）逐一验证约束生效（02 篇） |
| 回归 | 约束变更进评估集（09 篇 CI 门禁） |
| span 打分 | 约束遵循度逐段评估（02 篇） |
| 红队 | 每条硬约束一个攻击用例（09 篇） |

> 🎯 核心要点：**约束是"声明"不是"保证"**——验证是约束设计的组成部分（每条硬约束配验证用例）；2026 实证：提示词级约束可被更聪明的提示绕过——执行层兜底才是保证（09 篇）。

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "约束越多越安全" | 硬化过多降遵循——硬约束少而精 |
| "提示词约束是保证" | 声明不是保证——执行层兜底 |
| "冲突上线后再说" | 写前冲突审计——同级/跨级/示例/工具/时间 |
| "无升级路径" | 约束出口——转人工/降级 |
| "秘密在提示词安全" | 被披露仍可工作——绝不嵌秘密 |
| "约束不用验证" | 每条硬约束配验证用例 |
| "安全约束靠提示词" | 安全靠执行层——提示词只是第一层 |

## 8. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 硬软约束？ | MUST 安全关键 vs SHOULD 风格——硬要少而精 |
| 约束层级？ | 安全 > system > user > 示例 > 默认 |
| 层级要写进提示词？ | 要——冲突时模型按层级裁决 |
| 冲突审计五查？ | 同级/跨级/示例/工具/时间 |
| 升级路径？ | 约束出口——转人工/降级 |
| 防提取指令？ | system 首尾——降低泄漏风险 |
| 绝不嵌秘密？ | 被披露仍可工作——秘密不进提示词 |
| 约束验证？ | 压测 + 回归 + span 打分 + 红队 |
| 声明 vs 保证？ | 提示词是声明，执行层是保证 |
| 与护栏联动？ | 安全约束执行层兜底（Guardrails） |
| 硬约束自问？ | 违反会怎样——答不出就软化 |
| 冲突审计工程化？ | 约束编号 + CI 静态检查 |
