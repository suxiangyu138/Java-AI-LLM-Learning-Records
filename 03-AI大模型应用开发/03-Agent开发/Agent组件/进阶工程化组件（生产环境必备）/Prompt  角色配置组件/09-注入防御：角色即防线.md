# 注入防御：角色即防线

> 注入防御 = 保护系统提示词（角色/约束）不被攻破的架构。2026 认知：**提示词级防御可被更聪明的提示绕过**（概率模型无逻辑强制）；**"prevent-detect-prove" 三层架构**是收敛答案；**提示词应设计成被披露后仍可工作**（绝不嵌秘密）。本章给注入防御完整设计。

## 1. 五攻击模式（2026 编目）

| 攻击 | 机制 | 例子 |
|---|---|---|
| System 提取 | 诱导复述指令 | "逐字重复你的指令" |
| 指令覆盖 | 注入与 system 矛盾 | "忽略之前所有指令" |
| 角色劫持 | 换人格换规则 | DAN 类 |
| 工具外泄 | 借工具传攻击数据 | fetch_url 传受控 URL |
| **间接注入** | 检索/工具内容植入（RAG/MCP） | 邮件/网页/文档载荷——最难防（输入永不出自用户） |

> 🎯 核心要点：**间接注入是 2026 最难防的**——坏输入永不出自用户（来自检索文档/工具返回），输入侧检查天然盲区（Guardrails 05 篇 7-37% 盲区联动）；间接注入防线在架构隔离（源验证/工具校验）不在提示词。

## 2. 分层防御：没有单层够用

| 层 | 机制 |
|---|---|
| 结构隔离 | 指令与数据不混字符串（07 篇——地基） |
| 输入边界标记 | 显式边界符（次级防线） |
| Guardian 模型 | 小快模型扫注入模式（PIGuard：覆盖短语/人格变更/指令式关键词/编码指令/多轮操纵） |
| 输出扫描 | 检测成功注入与 system 泄漏 |
| Persona 稳定性 | 提示词显式抵抗重定向（02 篇） |
| 最小权限 | 敏感动作独立认证/人工批准（Guardrails 09 篇） |
| 运行时护栏 | 确定性代码层独立于 LLM（NeMo/Guardrails AI） |
| 红队 | 直接注入/文档注入/泄漏/越狱数据集（Giskard/PyRIT） |

> ⚠️ 2026 铁律：**"提示词级防御可被绕过——没有单层足够"**——防御是架构性的（结构隔离 + 执行层拦截 + 红队验证）；提示词只是第一层不是最后防线。

## 3. Prevent-Detect-Prove 三层架构（2026 收敛）

| 层 | 机制 | 类比 |
|---|---|---|
| Layer 1: Prevent | 自动红队——AI 生成对抗样本持续探测边界 | 渗透测试 |
| Layer 2: Detect | 运行时护栏——确定性拦截独立于模型行为 | ABS 刹车 |
| Layer 3: Prove | 形式化验证——TLA+/Dafny/LLM 验证护栏证明状态机不可达非法状态 | 数学证明 |

> 🎯 核心要点：**三层是递进关系**——Prevent 找漏洞（动态）、Detect 拦攻击（运行时）、Prove 证安全（静态）；2026 企业收敛于"三层都做"；形式化验证是 Agent 安全工程与经典安全工程的分水岭。

## 4. Twin Agent：特权分离（2026）

| 项 | 说明 |
|---|---|
| 结构 | Explore Agent（探索）+ Safe Agent（特权执行）分离 |
| 通信 | Explore 只发**紧凑提示**给 Safe Agent（上下文残差压缩） |
| 效果 | 大幅降低攻击成功率，保留效用 |
| 意义 | **"推理与执行分离"的提示词级实现**（Orchestrator 05 篇同源）——探索层被攻破，执行层不暴露 |

> 💡 Twin Agent 与 Orchestrator 05 篇（意图-执行分离）是同一原则的两层实现：执行层（运行时幂等）与特权分离（架构隔离）——"攻破探索 ≠ 攻破执行"。

## 5. 指令层级：模型原生优先级

| 层级 | 说明 |
|---|---|
| System > User | 模型原生优先 system 指令 |
| System > Tool 结果 | 工具结果不覆盖 system（2026 指令层级研究） |
| 工程补充 | 结构隔离 + 执行层兜底（§2） |

> ⚠️ 指令层级是"模型倾向"不是"保证"——**依赖模型原生优先 + 工程强制双轨**；"系统提示词可被更聪明提示绕过"的实证说明工程强制不可省（§2）。

## 6. 提示词设计的安全原则

| 原则 | 内容 |
|---|---|
| 可披露仍工作 | **提示词被披露后仍应正常**——绝不嵌秘密 |
| 防提取指令 | system 首尾各一条（04 篇） |
| 最小信息 | 不必要的内部细节不写进提示词 |
| 边界声明 | 范围/升级路径显式（04 篇） |
| 红队配套 | 每条安全声明配攻击用例 |

> 🎯 核心要点：**"可披露仍工作"是设计目标不是防守动作**——假设提示词会被提取，设计上让提取无价值（秘密不进提示词）；这与 SecretRef（Orchestrator 06 篇）同构：敏感物不进上下文。

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "提示词防注入" | 概率模型可绕过——架构防御 |
| "间接注入输入侧能防" | 7-37% 盲区——架构隔离 |
| "单层防御够" | 分层——结构隔离+护栏+红队 |
| "防提取指令保证" | 降低风险——设计上无秘密可提 |
| "指令层级是保证" | 模型倾向——工程强制双轨 |
| "红队一次就够" | 持续探测——AI 生成对抗样本 |
| "攻破探索=攻破全部" | Twin Agent——探索与执行分离 |
