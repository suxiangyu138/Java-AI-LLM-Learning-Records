# 生命周期：部署-漂移-回滚

> 生命周期 = 提示词版本从候选到生产到退役的治理。2026 三件套：**Git 标签标记生产版本**（production-2026-04-07）、**按版本漂移检测**（trace 必须带 prompt.version）、**回滚 = 指针变更秒级**（MTTR -70%）。本章给生命周期完整设计。

## 1. 部署：版本晋升流程

```text
晋升流程：
  候选版本（dev）
    → 评估门禁（回归 + A/B，05 篇）
    → staging 验证
    → Git 标签（production-YYYY-MM-DD）
    → 生产加载（按名+标签）
    → 灰度（按用户/流量百分比）
```

| 环节 | 产物 |
|---|---|
| 提交 | 版本 + 提交信息（行为意图） |
| 门禁 | 评估结果（05 篇） |
| 标签 | production-2026-04-07（永久标记"哪天跑了什么"） |
| 灰度 | 渐进流量 + 自动回滚条件 |

> 🎯 核心要点：**Git 标签是"哪天线上跑什么"的永久证据**——事故复盘/合规审计/版本比对都靠它；"prompt 版本与日期"的映射是 2026 生产标配（与观测 trace 时间戳对齐）。

## 2. 按版本漂移检测

| 机制 | 内容 |
|---|---|
| 每版本滚动均值 | 每 prompt 版本独立 rubric 滚动均值——**聚合告警漏按版本回归** |
| trace 属性 | span 必须带 prompt.id/prompt.version/prompt.variant/prompt.template_hash——**没有 version 其他都不工作** |
| template_hash | 捕获同版本内内容漂移（版本没变但内容变了） |
| Cohort 切片 | 按版本/变体/层级/地区切片——全局聚合掩盖细分回归 |

> ⚠️ 2026 关键：**漂移检测的最小单位是"版本"不是"全局"**——"prompt.variant 与 prompt.version 不是一回事"（变体=实验分支，版本=发布单元）；没有 version 属性的 trace 无法归因任何回归。

## 3. 漂移类型与响应

| 漂移类型 | 信号 | 响应 |
|---|---|---|
| 版本回归 | 该版本评分下降 | 评估门禁拦截 + 回滚 |
| 内容漂移 | template_hash 变化 | 变更审计 |
| 环境漂移 | dev/staging/prod 行为不一致 | 环境标记检查 |
| 模型漂移 | 模型升级导致提示词失效 | 回归测试（模型版本联动） |
| 数据漂移 | 输入分布变化 | Cohort 切片分析 |

> 🎯 核心要点：**漂移是多源的**——提示词没变行为也可能变（模型/数据/环境）；漂移检测的链路：trace 属性（观测）→ 版本聚合（分析）→ 门禁/回滚（治理）——三环缺一，漂移不可见。

## 4. 回滚：秒级指针变更

| 项 | 说明 |
|---|---|
| 机制 | 注册中心指针重指向旧版本——**不是代码重部署** |
| 速度 | 下一次调用即生效（秒级） |
| 触发 | 自动（灰度评估回归自动回滚）/手动 |
| 审计 | 注册中心 promote 动作留痕（谁/何时/为何） |
| 实证 | 采用提示词管理面的团队回滚 MTTR **-70%** |

> 💡 回滚的经济性：**"回滚应该是秒级指针变更，不是代码重部署"**——代码部署 30 分钟 vs 指针变更 3 秒；这决定了提示词变更的风险形态（低风险可频繁迭代）。

## 5. 灰度与自动回滚

| 机制 | 内容 |
|---|---|
| 分用户灰度 | 按用户/流量百分比渐进 |
| 评估自动回滚 | 灰度期间 rubric 回归 → 自动切回稳定变体（LaunchDarkly AgentControl 模式） |
| 底线 | 接地性/质量低于阈值自动切回 |
| 观测联动 | 观测信号喂控制面（观测 09 篇闭环） |

> 🎯 核心要点：**灰度 = "小范围付学费"**——回归在 1% 流量时发现并在 3 秒内回滚，成本趋零；"评估信号 → 控制面 → 自动切流"是 2026 提示词部署的标准闭环。

## 6. 生命周期与观测的衔接

| 观测属性 | 作用 |
|---|---|
| prompt.id | 提示词身份 |
| prompt.version | 版本归因（必填） |
| prompt.variant | 实验分支 |
| prompt.template_hash | 内容漂移 |
| 模型版本 | 模型漂移归因 |

> ⚠️ 与观测 06 篇衔接：**评估分数写 span 属性（含 prompt 版本）**——"评估 + 版本 + trace 三合一"是漂移检测的数据前提（评估 09 篇三处同定义联动）。

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "聚合告警够" | 聚合掩盖按版本回归——每版本独立 |
| "version 可选" | 没有 version 其他属性都不工作——必填 |
| "variant=version" | 变体=实验分支，版本=发布单元 |
| "回滚=重部署" | 指针变更秒级——MTTR -70% |
| "灰度只在发版" | 灰度 + 自动回滚——小范围付学费 |
| "漂移=提示词问题" | 模型/数据/环境都漂移——多源 |
| "标签可省" | production 日期标签是事故证据 |

## 8. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 晋升流程？ | 候选→门禁→staging→标签→灰度 |
| Git 标签？ | production-2026-04-07——"哪天跑了什么" |
| 漂移最小单位？ | 版本——聚合告警漏回归 |
| trace 四属性？ | id/version/variant/template_hash |
| template_hash？ | 捕获同版本内内容漂移 |
| 漂移多源？ | 版本/内容/环境/模型/数据 |
| 回滚机制？ | 注册中心指针——秒级非重部署 |
| MTTR？ | -70%（采用提示词管理面的团队） |
| 自动回滚？ | 灰度期间评估回归→自动切流 |
| 与观测衔接？ | 评估分数+版本+span 三合一 |
| variant vs version？ | 实验分支 vs 发布单元 |
| 三环？ | trace 属性→版本聚合→门禁回滚 |
