# 反思组件是什么

> 概念速记：Agent 的"做后复盘"。完整版见 [Reflection 反思模块 01 篇](..%2F..%2F..%2FAgent%20子组件专项学习%2FReflection%20反思模块%2F01-反思全景：自我修正的边界.md)。

## 核心定义

反思 = 评估自己的输出 → 分析错因 → 改进后重试。**反思 ≠ 重试**：重试治"手抖"（原样再跑），反思治"脑子没想全"（先评再改）。

| 维度 | 重试 | 反思 |
|---|---|---|
| 触发 | 失败 | 失败 + 关键步骤后 |
| 动作 | 原样再跑 | 评估→分析→改进 |
| 例子 | 网络超时重发 | "我考虑合规风险了吗？增长假设成立吗？" |

## Reflexion：语言化自我批评

| 项 | 说明 |
|---|---|
| 机制 | 无权重更新的语言化自我批评（verbal RL）——批评写进情景记忆 |
| 奠基实证 | HumanEval **91%** vs 80% 基线——语言化反馈有效 |
| 循环 | Actor 尝试 → Evaluator 评估 → Self-Reflection 分析 → 教训入记忆 → 再试 |
| 2026 状态 | 认知反转延续：**自我反思不可信**（同模型同盲区）——可靠评估外部化 |

> ⚠️ **Oracle 前提（2026 铁律）**：**只有可验证标准（测试/编译器/ground truth）才加反思**——无 oracle 时批评退化为自证偏见（"看起来不错"循环）；代码/检索验证类任务适合，开放写作不适合（Reflection 01 篇边界表）。

## 轮次控制

| 模式 | 轮次 | 超限后果 |
|---|---|---|
| Act-then-reflect（复盘） | 2-3 轮 | 过优化（把对的改错） |
| 迭代精化（解空间探索） | 3-5 轮 | 成本失控 |
| 规则 | 第 1 轮捕获 70-80% 改进 | 硬上限 + 最佳版本回滚 |

> 💡 与 [Orchestrator](..%2F..%2F进阶工程化组件（生产环境必备）%2FOrchestrator%20%20Runtime%20编排调度器%2F00-OrchestratorRuntime编排调度器总览.md) 预算联动：反思轮次是 max_iterations 的一部分——"反思也是预算内的循环"。

## 反思三问（体检）

| 问题 | 决定 |
|---|---|
| 谁评估？（评判器独立性） | 同模型 = 盲区；独立模型/规则 = 可信 |
| 评什么？（oracle 真实性） | 外部信号 vs 自我感觉 |
| 改什么？（修订执行力） | 批评落地为修改，而非"收到" |

> 🎯 一句话：**"有外部可验证标准才值得反思"**——oracle 是反思的许可证；答不出"谁评估"的反思系统大概率是自我安慰循环。

## 面试速记

| 问题 | 一句话答案 |
|---|---|
| 反思 vs 重试？ | 重试原样再跑，反思先评再改 |
| Reflexion？ | 语言化自我批评——HumanEval 91% vs 80% |
| Oracle 前提？ | 只有可验证标准才加反思——无 oracle 是自证偏见 |
| 轮次控制？ | 2-3 轮复盘、3-5 轮精化——超限过优化 |
| 2026 认知？ | 自我反思不可信——评估外部化 |
| 三问体检？ | 谁评估/评什么/改什么 |
| 与规划关系？ | 失败触发重规划（观察驱动修正） |
| 与预算联动？ | 反思轮次是 max_iterations 的一部分 |
