# 实战速查：失败模式与误区

> 概念速记：规划反思的生产红线。深潜见 [Planner 06 篇](..%2F..%2F..%2FAgent%20子组件专项学习%2FPlanner%20规划器%2F06-规划器的失败模式与治理.md) 与 [Reflection 05 篇](..%2F..%2F..%2FAgent%20子组件专项学习%2FReflection%20反思模块%2F05-反思的失败模式.md)。

## 规划失败模式（PlanBench-XL 实证，2026）

| 失败模式 | 机制 | 数据 |
|---|---|---|
| **Irrecoverable Drift** | 部分进展后偏离所有有效路径、难回溯 | GPT-4o >70% 失败属此类 |
| 静默失败 / Value Contamination | 无错误信号的错误值被当真理——"价值污染"级联 | 静默失败最具破坏性 |
| 工具选择瓶颈 | 过度依赖最近检索的工具而非最相关 | 历史中已有工具仍选错 |
| 阻塞崩溃 | 关键工具不可用时无法重规划 | GPT-5.4：51.90% → **11.36%** |

> ⚠️ 2026 关键：**"Agent 缺乏验证工具输出的怀疑心"**——静默失败下 Agent 把错误数据纳入状态继续规划（value contamination）；防御 = 工具输出验证 + 怀疑心提示（[Tool 体系](..%2F..%2F..%2FAgent%20子组件专项学习%2FTool%20工具开发与注册%2F00-Tool工具开发与注册总览.md) 06 篇联动）。

## 反思失败模式

| 模式 | 机制 |
|---|---|
| 过度修正 | 把本来对的改错（轮次超限） |
| 自证偏见 | 无 oracle 时批评自我确认 |
| 谄媚批评 | 弱评判器回"看起来不错" |
| 结构税 | 强制结构化反思降低准确率（Qwen3 实证 50%→38%） |

## 生产护栏

| 护栏 | 内容 |
|---|---|
| 步数预算 | max_steps——一次无界查询可级联数百次调用（$5-50） |
| 成本上限 | 反思/重规划轮次计入预算（[Orchestrator](..%2F..%2F进阶工程化组件（生产环境必备）%2FOrchestrator%20%20Runtime%20编排调度器%2F00-OrchestratorRuntime编排调度器总览.md) 05 篇） |
| Checkpoint | 长任务可回滚（Orchestrator 03 篇） |
| 高风险计划 | 人工批准后再执行（Guardrails 确认模式） |
| 破坏动作 | 可逆优先 |

## 混合模式：生产常态

| 场景 | 模式 |
|---|---|
| 简单/探索任务 | ReAct |
| 复杂长任务/多步依赖 | Plan-Execute（全局结构清晰，但计划会过期——需重规划） |
| 关键步骤后 | Reflect（稳质量，但加成本延迟） |
| 失败 | 触发重规划 |
| 高风险 | 人工确认 |

> 🎯 一句话：**"从最简单模式开始，穷尽确定性替代后才毕业到 Agent"**——规划反思是叠加件不是默认件。

## 三大误区

| 误区 | 真相 |
|---|---|
| "反思=重试" | 重试无评估，反思先评再改 |
| "无 oracle 也加反思" | 自证偏见——oracle 是许可证 |
| "计划一次性完美" | 计划会过期——重规划是标配（静默失败最险） |

## 面试速记

| 问题 | 一句话答案 |
|---|---|
| 主要规划失败？ | Irrecoverable Drift（>70% GPT-4o 失败） |
| 静默失败？ | 无错误信号的错误值——value contamination 级联 |
| 阻塞崩溃数据？ | GPT-5.4 51.90%→11.36% |
| 反思失败？ | 过度修正/自证偏见/谄媚/结构税 |
| 护栏？ | max_steps/成本上限/checkpoint/人工批准 |
| 混合模式？ | ReAct 简单/Plan-Execute 复杂/Reflect 关键步 |
| 生产原则？ | 从最简单开始，穷尽确定性替代才上 Agent |
| 怀疑心？ | 验证工具输出——防 value contamination |
| 结构税？ | 强制结构化反思降准确率（50%→38%） |
| 与预算联动？ | 反思轮次计入 max_iterations |
