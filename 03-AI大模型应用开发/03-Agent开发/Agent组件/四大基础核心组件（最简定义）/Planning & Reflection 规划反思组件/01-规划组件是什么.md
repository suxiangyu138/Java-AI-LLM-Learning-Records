# 规划组件是什么

> 概念速记：Agent 的"想清楚再做"。完整版见 [Planner 规划器 01 篇](..%2F..%2F..%2FAgent%20子组件专项学习%2FPlanner%20规划器%2F01-规划器全景.md)。

## 核心定义

规划 = 在行动前决定"分几步、按什么顺序、用什么工具"——把大目标分解为可执行子任务（与 [LLM 大脑](..%2FLLM大脑（推理决策模块）%2F00-LLM大脑最简定义总览.md) 的区分：大脑做"单步决策"，规划做"多步路线"）。

| 模式 | 机制 | 适用 |
|---|---|---|
| ReAct 循环 | 边想边做（Thought→Action→Observation） | 控制流未知/探索型任务（默认） |
| Plan-Execute | 先出完整计划 → 逐步执行 | 多步数据管道/跨源研究/依赖管理 |

> 💡 Plan-Execute 工程要点（2026）：**计划用结构化输出（JSON schema）**——编排代码先验证计划再执行；规划与执行可用**分离的专用 Agent**（强分解能力的 planner + 深工具访问的 executor）。

## 任务分解：规划的核心动作

```text
任务分解（图式规划，2026）：
  自然语言目标
    → LLM 分解子任务（原子化）
    → 确定局部优先级关系
    → 转为全局依赖图（DAG）
    → 按依赖执行 + 子结果比对触发自我修正
```

| 2026 进展 | 机制 |
|---|---|
| 图式规划 | 分解 + 局部优先级 → 全局依赖（DAG 执行，Orchestrator 04 篇联动） |
| SPIRAL（AAAI 2026） | Planner/Simulator/Critic 三 Agent 进 MCTS——DailyLifeAPIs 83.6%（+16 点） |
| ComAgent | 感知-规划-行动-反思闭环（多 LLM 协作） |

## 规划与大脑的分工

| 组件 | 管什么 |
|---|---|
| LLM 大脑 | 单步推理决策（这一步做什么） |
| 规划组件 | 多步路线（整体分几步、依赖顺序） |
| 执行循环 | 按计划逐步执行 + 观察（Tool 06 篇） |
| 重规划 | 执行失败 → 检测中断 → 修订计划（02 篇反思联动） |

> 🎯 一句话：**"大脑想每一步，规划想整条路"**——两者都靠执行反馈修正（重规划是规划的纠错机制）。

## 面试速记

| 问题 | 一句话答案 |
|---|---|
| 规划是什么？ | 行动前决定步骤/顺序/工具——多步路线 |
| ReAct vs Plan-Execute？ | 边想边做 vs 先计划后执行——未知流 vs 多步依赖 |
| Plan-Execute 要点？ | 结构化输出验证计划 + 规划执行分离 Agent |
| 任务分解？ | 目标→子任务→局部优先级→全局依赖图 |
| SPIRAL？ | 三 Agent（Planner/Simulator/Critic）进 MCTS——+16 点 |
| 与大脑分工？ | 大脑想单步，规划想整条路 |
| 与重规划？ | 执行失败→修订计划——规划的纠错机制 |
| 与 Orchestrator 联动？ | DAG 依赖执行（图式规划） |
