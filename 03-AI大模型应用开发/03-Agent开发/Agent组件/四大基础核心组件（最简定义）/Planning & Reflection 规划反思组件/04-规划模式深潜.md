# 规划模式深潜

> 深化篇：规划模式的工程细节——模式谱系、计划表示、规划执行分离。完整版见 [Planner 规划器 02-04 篇](..%2F..%2F..%2FAgent%20子组件专项学习%2FPlanner%20规划器%2F02-任务分解：规划的核心技能.md)。

## 1. 生产模式谱系（从简到繁）

```text
生产模式谱系（2026）：
  Prompt chaining → Routing → Parallelization
    → Orchestrator-Workers → Evaluator-Optimizer → 全自主 Agent
  原则：从最简单开始——"穷尽确定性替代后才毕业到 Agent"
```

| 模式 | 机制 | 适用 |
|---|---|---|
| Prompt chaining | 固定顺序提示 | 确定性流程 |
| Routing | 分类分发 | 多任务类型 |
| Parallelization | 并行扇出 | 独立子任务 |
| Orchestrator-Workers | 中央分解+委派 | 动态子任务 |
| Evaluator-Optimizer | 生成+评估循环 | 迭代质量 |
| 全自主 Agent | 自主循环 | 无确定替代时 |

> 🎯 核心要点：**规划不是"直接上 Agent"，是模式谱系的渐进**——2026 生产共识："从最简单模式开始，穷尽确定性替代后才毕业到 Agent"（Engineering Handbook）；过度规划 = 成本与复杂度浪费。

## 2. 计划表示：数据结构

| 表示 | 结构 | 适用 |
|---|---|---|
| 步骤列表 | [{step, tool, args}] | 简单流程 |
| 依赖图（DAG） | 节点+依赖边 | 并行/依赖任务（Orchestrator 04 篇） |
| 层级计划 | 目标→子目标树 | 大任务分解 |
| 条件计划 | 步骤带条件分支 | 不确定性任务 |

> ⚠️ 2026 工程要点：**计划用结构化输出（JSON schema）**——编排代码先验证计划再执行（Plan-Execute 的工程前提）；计划即数据（可校验/可审计/可重放）而非自由文本。

## 3. 规划与执行分离

| 角色 | 职责 | 选型 |
|---|---|---|
| Planner | 分解目标、定顺序 | 强分解能力模型（推理模型） |
| Executor | 逐步执行、调工具 | 深工具访问模型 |
| 协调者 | 验证计划、监控执行 | 编排层（确定性代码） |

> 💡 2026 实证：**规划与执行用分离专用 Agent 是生产主流**（Microsoft Learn 2026）——"专用 planner（强分解）vs 分析 Agent（深工具访问）"；分离的好处：可独立升级/评估/回滚（PromptOps 05 篇）。

## 4. 任务分解深潜

| 分解质量维度 | 好 | 差 |
|---|---|---|
| 原子性 | 子任务单动作可验证 | 子任务仍是大目标 |
| 依赖清晰 | 依赖关系显式（DAG） | 顺序隐含 |
| 可验证 | 每步有验收标准 | 无法判断完成 |
| 规模适中 | 5-10 步 | 过度拆分（50 步）或过粗（2 步） |

> 🎯 一句话：**"分解质量决定规划质量"**——图式规划（LLM 分解 + 局部优先级 → 全局依赖）是 2026 主流；分解失败 = 后续全部失真（Planner 06 篇失败模式）。

## 5. 2026 规划前沿

| 方向 | 机制 |
|---|---|
| SPIRAL（AAAI 2026） | Planner/Simulator/Critic 三 Agent 进 MCTS——DailyLifeAPIs 83.6%（+16 点） |
| 图式规划 | 分解+依赖图执行——子结果比对触发自我修正 |
| AgentFlow | planner/executor/verifier/generator 四模块流内优化（7B 超 GPT-4o） |
| 世界模型规划 | LLM 提候选 + 世界模型模拟 + LLM 修正（IMPLEMENT） |

## 6. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 模式谱系？ | chaining→routing→parallel→orchestrator→evaluator→agent |
| 生产原则？ | 从最简单开始，穷尽确定性替代才上 Agent |
| 计划表示？ | 步骤列表/DAG/层级/条件——结构化输出 |
| 规划执行分离？ | 专用 planner + executor——可独立升级 |
| 分解四维？ | 原子性/依赖/可验证/规模 |
| SPIRAL？ | 三 Agent MCTS——+16 点 |
| 计划即数据？ | JSON schema 验证——可校验可审计 |
| 分解失败后果？ | 后续全部失真 |
| 与 Orchestrator 联动？ | DAG 依赖执行 |
| 过度规划？ | 成本复杂度浪费——谱系渐进 |
