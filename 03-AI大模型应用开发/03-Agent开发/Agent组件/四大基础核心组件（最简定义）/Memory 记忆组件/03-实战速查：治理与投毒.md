# 实战速查：治理与投毒

> 概念速记：记忆的生产红线——企业治理与投毒防御。深潜见 [Memory 记忆系统 08 篇](..%2F..%2F..%2FAgent%20子组件专项学习%2FMemory%20记忆系统%2F08-记忆安全与治理.md) 与 [Guardrails](..%2F..%2F进阶工程化组件（生产环境必备）%2F安全护栏%20Guardrails%2F00-安全护栏Guardrails总览.md)。

## 记忆投毒：2026 顶级威胁

| 项 | 说明 |
|---|---|
| 机制 | 攻击者把恶意内容持久化进长时存储——**跨会话持续生效**（原始内容删除后仍在） |
| 与注入区别 | 会话注入是一次性；投毒是持久 + 延迟 + 重复失效 |
| **Sleeper 投毒**（2026-05） | 外部内容诱使记忆管理器持久化伪造"用户记忆"，后续会话检索即生效——GPT-5.5 注入率 **99.8%**、检索率 94-98% |
| MAFIA（2026-08） | 仅查询访问 + 普通写回路径即可投毒——**写时审计与检索时检测不足** |
| 向量注入 | 直接注入向量库：**100% 持久**、60-80% 检索率 |
| 多模态投毒（Lucid） | 不可见图像扰动——61.6% 成功率（黑盒） |

> ⚠️ 2026 金句：**"LLM 无法可靠区分指令与数据——一旦进上下文，检索记忆可被读成命令"**；投毒比注入危险因为它持久。

## 防御九条

| # | 防御 |
|---|---|
| 1 | 外部内容不可直接授权记忆写入（显式用户确认 + 来源展示） |
| 2 | 来源标记与信任标签——未信任记忆不可成为权威指令 |
| 3 | 记忆隔离（按用户/会话分库）——防跨会话污染 |
| 4 | 写入前验证（扫描指令模式）——OWASP 记忆隔离模式 |
| 5 | 检索后验证（对照来源交互）——高影响动作门控当前会话意图 |
| 6 | 指令层级（system > 记忆内容）——Prompt 09 篇联动 |
| 7 | 用户可见控制（查看/纠正/删除记忆） |
| 8 | 定期审计（异常/不支持条目） |
| 9 | CI 红队（Garak/Promptfoo/PyRIT——对抗样本进流水线） |

## 企业治理三件套

| 治理项 | 内容 |
|---|---|
| 来源与版本 | 每条记忆带来源时间戳/提取方法/置信度；版本历史可回滚 |
| 范围与隔离 | 私有/团队/组织/客户四级范围；RBAC 最小权限；租户隔离在目录层不在缓存前缀 |
| 保留与审计 | 分层保留策略；定期审计纠正错误记忆——**Git 式记忆工作流**（公司所有、可审、可移植） |

> 💡 2026 陷阱警示（Atlan）：**"把记忆当向量库问题是陷阱"**——向量检索不告诉你哪个匹配是权威/过期/租户可读；治理要目录（metadata graph）而非裸索引。

## 三大误区

| 误区 | 真相 |
|---|---|
| "向量库=记忆" | 记忆是治理对象——来源/版本/隔离才是主体 |
| "写时审计够" | MAFIA 证明不足——检索后验证 + 隔离 |
| "记忆自动沉淀" | 显式管道 + 写入确认——不是自动发生 |

|---|---|
| 投毒 vs 注入？ | 投毒持久跨会话——更危险 |

| MAFIA 证明什么？ | 写时审计与检索时检测不足 |
| 防御第一原则？ | 外部内容不可直接授权写入 |
| 记忆隔离？ | 按用户/会话分库——防跨会话污染 |
| 治理三件套？ | 来源版本/范围隔离/保留审计 |
| 向量库陷阱？ | 检索不告诉权威/过期/租户 |
| Git 式记忆？ | 公司所有、可审、可移植 |
