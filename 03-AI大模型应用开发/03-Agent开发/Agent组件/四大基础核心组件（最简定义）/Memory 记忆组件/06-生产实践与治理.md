# 生产实践与治理

> 深化篇：记忆的生产落地——企业治理、成本、投毒防御工程。完整版见 [Memory 记忆系统 08 篇](..%2F..%2F..%2FAgent%20子组件专项学习%2FMemory%20记忆系统%2F08-记忆安全与治理.md)。

## 1. 企业治理框架（2026）

| 治理项 | 内容 |
|---|---|
| 来源标记 | 每条记忆带来源时间戳/提取方法/置信度 |
| 范围分级 | 私有/团队/组织/客户四级 |
| 版本历史 | 高影响记忆变更可审可回滚 |
| 权限 | RBAC 最小权限（Guardrails 09 篇 JIT 联动） |
| 保留策略 | 分层保留（按记忆层差异化） |
| 审计 | 定期识别纠正错误记忆 |
| 工作流 | **Git 式记忆**——公司所有、可审、可移植 |

> 🎯 核心要点：**记忆是治理对象不是检索问题**（Atlan 2026）——"向量库视角"是陷阱：向量检索不告诉你哪个匹配是权威/过期/租户可读；治理要目录（metadata graph）而非裸索引。

## 2. 记忆投毒防御工程（03 篇速记 → 本篇工程化）

| 防线 | 工程实现 |
|---|---|
| 写入控制 | 外部内容不可直接授权写入——显式确认 + 来源展示 |
| 隔离 | 按用户/会话分库（防跨会话污染） |
| 验证 | 写入前扫描指令模式（OWASP 记忆隔离） |
| 检索后验证 | 高影响动作门控当前会话意图（不凭记忆单独授权） |
| 指令层级 | system > 记忆内容（Prompt 09 篇） |
| 用户可见 | 记忆查看/纠正/删除界面 |
| CI 红队 | Garak/Promptfoo/PyRIT 对抗样本进流水线 |

> ⚠️ 2026 实证：**MAFIA 证明写时审计 + 检索时检测不足**（仅查询访问 + 普通写回路径即可投毒）——防御必须"隔离 + 检索后验证 + 指令层级"组合，单点不足。

## 3. 成本模型

| 成本项 | 说明 |
|---|---|
| 存储 | 向量库/知识图/日志 |
| 嵌入生成 | 写入时 embedding 费用 |
| 检索 | 每轮检索调用 |
| 优化 | 结构化记忆减少重复全上下文提示——**降 token** |
| 基准 | 2026 缺成熟成本框架——按工作负载自benchmark |

> 💡 记忆成本与收益的平衡：**"记忆是省 token 的投资"**——结构化记忆（04 篇类型化 + 05 篇摘要）减少重复全上下文提示；StructMem 延迟合成省 18x 写入 token（05 篇）；成本账要按"省了多少重复调用"算（观测 05 篇成本联动）。

## 4. 生产检查单

| 检查 | 标准 |
|---|---|
| 类型划分 | 语义/情景/程序分库（04 篇） |
| 写入确认 | 外部内容来源记忆有确认（03 篇） |
| 检索算子 | 混合候选 + 时间算子（05 篇） |
| 整合任务 | 后台定期巩固（StructMem 类） |
| 来源标记 | 100% 记忆带来源 |
| 租户隔离 | 目录层隔离（非缓存前缀） |
| 审计 | 定期审计 + 用户可见控制 |
| 红队 | 对抗样本 CI（Sleeper/MAFIA 场景） |

## 5. 常见生产问题

| 问题 | 根因 | 解法 |
|---|---|---|
| 记忆膨胀 | 无整合任务 | 层次整合 + 摘要修剪（05 篇） |
| 跨会话污染 | 无隔离 | 按用户/会话分库 |
| 陈旧记忆误导 | 无有效性窗口 | Zep 类有效性失效 + 审计 |
| 投毒生效 | 写入无控制 | 显式确认 + 隔离 + 检索后验证 |
| 成本失控 | 嵌入/检索无预算 | 结构化 + 延迟合成 + 预算 |

## 6. 面试速记

| 问题 | 一句话答案 |
|---|---|
| 治理七项？ | 来源/范围/版本/权限/保留/审计/Git 式工作流 |
| 向量库陷阱？ | 检索不告诉权威/过期/租户 |
| MAFIA 证明？ | 写时审计与检索时检测不足 |
| 防御组合？ | 隔离+检索后验证+指令层级 |
| 成本优化？ | 结构化记忆减重复提示 + 延迟合成 |
| 记忆是投资？ | 省 token 的长期投资——按省了多少重复算 |
| 生产检查单首项？ | 类型划分（语义/情景/程序分库） |
| 记忆膨胀？ | 整合任务缺失 |
| 陈旧记忆？ | 有效性窗口 + 审计 |
| 与 Guardrails 联动？ | JIT 权限 + 记忆护栏 |
