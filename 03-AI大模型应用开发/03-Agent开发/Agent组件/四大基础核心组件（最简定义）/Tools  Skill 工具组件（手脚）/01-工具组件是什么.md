# 工具组件是什么

> 概念速记：Agent 的"手"。完整版见 [Tool 工具开发与注册 01 篇](..%2F..%2F..%2FAgent%20子组件专项学习%2FTool%20工具开发与注册%2F01-工具全景：Agent的能力边界.md)。

## 核心定义

工具 = Agent 可调用的外部函数/服务——模型不执行，只发结构化请求（决策-执行分离）。与 [LLM 大脑](..%2FLLM大脑（推理决策模块）%2F00-LLM大脑最简定义总览.md) 的分工：**大脑想（决策），手做（执行）**。

```text
工具调用流程：
  ① 声明：工具定义（name+描述+schema）注入上下文
  ② 选择：模型输出 tool_calls（工具名+参数）
  ③ 执行：宿主校验授权后执行（模型不碰真实世界）
  ④ 回注：结果回上下文 → 继续推理
```

> 🎯 一句话：**"模型建议，宿主执行"**——安全边界（校验/授权/审计）全在执行层（Tool 01 篇）。

## 五类能力速查

| 能力 | 类型 | 作用 |
|---|---|---|
| 工具（Tool） | 动作 | 可调用函数（搜索/文件/API/代码执行） |
| MCP 服务器 | 动作 | 远程工具服务器（统一协议，Linux Foundation） |
| Apps | 动作 | SaaS 平台集成（Gmail/Slack/Jira） |
| Skills | **判断** | 领域专长注入提示词——"如何思考"（SKILL.md） |
| Knowledge | 事实 | RAG 检索的事实 |

> ⚠️ 关键区分（2026）：**Tools/MCP/Apps 给新"动作"；Skills/Knowledge 塑"推理与上下文"**——动作扩展能力，判断扩展胜任力（02 篇展开）。

## 与相邻组件分工

| 组件 | 分工 |
|---|---|
| 大脑（LLM） | 决策调不调、调哪个、传什么参数 |
| 工具（手脚） | 执行动作 + 返回结果 |
| 记忆 | 工具结果可写入（结果即经验） |
| 护栏 | 执行前拦截（危险工具确认模式） |
| 规划 | 工具调用顺序由计划编排（依赖关系） |

> 💡 2026 趋势：**工具已从本地函数扩展到 MCP 服务器、浏览器动作、数据库写入、代码解释器、子 Agent（A2A）**——"手脚"的概念在膨胀（Multi-Agent 03 篇）。
