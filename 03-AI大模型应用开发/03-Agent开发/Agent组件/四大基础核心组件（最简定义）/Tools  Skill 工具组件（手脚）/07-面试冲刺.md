# 面试冲刺

> 深化篇：Tools & Skill 的 10 题面试冲刺——覆盖本组件全部知识点，可直接背诵。

## Q1：工具组件定位？

> Agent 的"手"——可调用的外部函数/服务。核心机制：决策-执行分离（模型发结构化请求 tool_calls、宿主校验执行、结果回注）；流程四步：声明→选择→执行→回注。"模型建议，宿主执行"——安全边界（校验/授权/审计）全在执行层。

## Q2：五类能力？

> 工具（动作：可调用函数）/MCP 服务器（远程工具统一协议）/Apps（SaaS 集成）/Skills（判断：SKILL.md 如何思考）/Knowledge（事实：RAG）。关键区分：**Tools/MCP/Apps 给新"动作"，Skills/Knowledge 塑"推理与上下文"**——动作扩展能力，判断扩展胜任力。

## Q3：Tools vs Skills vs MCP？

> 四层定位：FC（基础协议：让模型知道有哪些函数）→ Tools（标准化格式：name+描述+schema）→ MCP（基础设施："USB-C for AI"，Linux Foundation）→ Skills（判断层：何时/顺序/条件 + 护栏）。"FC 是基础能力、MCP 标准化工具基础设施、Skills 编码判断"——叠加不是替代。

## Q4：工具契约三要素？

> name（动词开头唯一标识）+ description（1-3 句何时用 + 示例 +25%）+ parameters（全参数描述/枚举/约束/additionalProperties:false）。**模型永远看不见实现，只看到契约**；描述决定"该不该调"、schema 决定"参数怎么填"；数量红线：<20 建议、30 硬拒绝、10-15 单上下文准确率边界。

## Q5：执行器怎么保证安全？

> 五步循环（解析→校验→授权→执行→回传）+ 第一原则（模型输出不可信，当外部用户输入处理）+ 结构化错误返回（错误码+信息+提示，模型可恢复）+ 重试只针对基础设施故障（参数/业务失败不重试）+ 循环不变量（每调用恰一结果、消息顺序）。

## Q6：危险工具怎么治理？

> 风险分级：只读自动/写节流/危险**强制确认模式**（不可关闭——CVE-2025-53773 教训：auto-approve 移除确认 → 注入直通危险工具）/特权人工接管；五道防线：注册期静态校验（防 tool poisoning）→ 执行前授权 → 参数安全（白名单+参数化执行，绝不拼接 SQL/Shell）→ 行为检测 → 审计留痕。

## Q7：工具评估怎么做？

> 三指标独立测：ToolSelectionAccuracy（选对没）/FunctionCallAccuracy（参数有效没）/JSONValidation（schema 符合没）；BFCL v3 前沿 88-94%，**差距在 irrelevance（不该调时调）与 missing-tool（该调没调）桶**；工具要"用 LLM 测试"（契约测试进 CI）不只单元测试；tool_call span 观测 + 循环检测。

## Q8：Skills 是什么？与工具什么关系？

> skill = recipe（SKILL.md）：编码"何时/顺序/条件调哪些工具"（含护栏——"未完成步骤 1-2 绝不批退款"）——工具 schema 表达不了的判断层；渐进披露（~100 token 元数据常驻 + 按需加载）解决 token 膨胀；2026 实证：MCP+Skills 组合安全关键任务 100% 成功率（基线 0%）、Arize 显示 MCP 贵 6x 慢 5x——**生产 use both**。

## Q9：工具数量多了怎么办？

> 三件套：静态过滤（权限/域）→ namespace/动态发现（tool_search 按需加载）→ >30 拆子 Agent；单上下文 10-15 个准确率边界；"工具列表不是越多越好，而是越精越好"——让模型每次只面对可分辨的候选集（20 个工具 × 150 token = 3000 token 是显性成本，选择混淆是隐性成本）。

## Q10：2026 工具生态趋势？

> MCP 成为主导传输（前沿 SDK 原生消费）；并行与依赖调用成为前沿默认；工具扩展到浏览器动作/数据库写入/代码解释器/子 Agent（A2A）；Skills 走向开放标准（Anthropic 形式化）；评估必须动态 MCP 目录快照（非静态工具列表）；工具与提示词/记忆/护栏/观测四接口集成（PromptOps 07 篇）。

## 答题范式

| 原则 | 说明 |
|---|---|
| 结构优先 | 定位 → 机制 → 契约 → 安全 → 评估 |
| 带数据 | "+25%""88-94%""6x""100%"——实证碾压空谈 |
| 说权衡 | "并行快但冲突复杂——顺序默认""use both（正确性差不多效率差 6 倍）" |
| 落工程 | 补一句"生产上我怎么做"（契约测试 CI/确认模式/循环检测） |
| 提边界 | 何时不用工具：自包含任务；何时不用 Skills：单次调用 |
