# 实战速查：选型与误区

> 概念速记：LLM 大脑的工程速查——什么时候用推理模型、成本怎么控、三大误区。协议与成本细节见 [Function Calling 体系](..%2F..%2F..%2F..%2F02-大模型基础与Prompt工程%2FFunction%20Calling%20函数调用【Agent%20基石】%2F00-FunctionCalling知识体系总览.md)。

## 选型：推理模型 vs 普通模型

| 任务 | 选型 |
|---|---|
| 多步/可验证（数学、代码、Agent 规划/工具排序） | 推理模型 |
| 查找/摘要/高量分类 | 快速普通模型 |
| 混合 | 路由（GPT-5 实时路由自动选 fast/deep） |

> 🎯 一句话：**"用推理模型做多步可验证任务，用快速模型做查找摘要"**——路由是 2026 成本控制的正解。

## 成本三旋钮

| 旋钮 | 内容 |
|---|---|
| 思考量 | budget_tokens/reasoning_effort——按任务难度调（有正确思考量） |
| 路由 | 简单任务走快速模型（省 50-80% 输出 token） |
| 蒸馏 | 把推理模型产出的高质量轨迹蒸馏给小模型（Reflection 09 篇） |

> 💡 递减收益提醒：high→max 几乎无增益——"花在思考上的钱过了拐点就是浪费"（Snell 计算最优）。

## 三大误区

| 误区 | 真相 |
|---|---|
| "推理模型=完整 Agent" | 只提高单步质量——多步仍要循环（01 篇） |
| "thinking 越多越好" | 递减收益——路由 + 调旋钮才是正解 |
| "thinking 可调试" | 服务端内部——只看到最终输出（02 篇） |

## 2026 阵容速查

| 模型 | 特点 |
|---|---|
| GPT-5 thinking | 实时路由（fast/deep）、省 50-80% 输出 token |
| Claude thinking | budget_tokens（8k-16k 起步） |
| DeepSeek-R1 | 开源、完整推理轨迹 |
| Trinity-Large-Thinking | 398B MoE、PinchBench 91.9%（#2）、比 Opus-4.6 便宜 96% |
| MAI-Thinking-1 | 256K 上下文、**无内置持久记忆**——生产要外部记忆层（Mem0 类） |

> ⚠️ 2026 关键限制：**推理模型无内置持久记忆**——跨请求即忘；生产 Agent 处理多天会话必须接记忆层（[Memory 记忆系统](..%2F..%2F..%2FAgent%20子组件专项学习%2FMemory%20记忆系统%2F00-Memory记忆系统总览.md)）。

## 面试速记

| 问题 | 一句话答案 |
|---|---|
| 什么时候用推理模型？ | 多步可验证任务；查找摘要用快速模型 |
| 成本三旋钮？ | 思考量/路由/蒸馏 |
| 递减收益？ | high→max 平——过了拐点浪费 |
| 三大误区？ | 推理=Agent/thinking 越多越好/thinking 可调试 |
| MAI-Thinking-1 限制？ | 无内置记忆——外部记忆层 |
| 最便宜推理模型？ | Trinity（比 Opus-4.6 便宜 96%） |
