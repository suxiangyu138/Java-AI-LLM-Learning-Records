## 1. 记忆的两层语义

```text
第一层：跨轮记忆（checkpointer）
    —— 同一会话内，多轮对话之间记得住（agent 调用之间）

第二层：跨会话存储（store）
    —— 会话结束后，长期事实仍可访问（跨用户/跨天）
```

| 层 | 手写方案（阶段 1/2） | 框架方案 | 存储位置 |
|----|--------------------|---------|---------|
| 跨轮 | 客户端维护 messages 全量重发 | checkpointer | 内存/SQLite/Postgres |
| 跨会话 | 外部存储 + 检索注入 | store | BaseStore 实现 |

> 🎯 **核心要点**：checkpointer 解决"会话连续性"，store 解决"长期记忆"。两者不要混用——checkpointer 存的是对话历史，store 存的是提取的事实。

## 2. checkpointer：跨轮记忆

```python
from langgraph.checkpoint.memory import InMemorySaver

checkpointer = InMemorySaver()          # 内存版（开发用）

agent = create_agent(
    model=model,
    tools=tools,
    system_prompt="...",
    checkpointer=checkpointer,          # ← 一行开启跨轮记忆
)

# 多轮对话：同一 thread_id = 同一会话
r1 = agent.invoke({"messages": [("user", "我叫小明")]},
                  config={"configurable": {"thread_id": "sess-001"}})
r2 = agent.invoke({"messages": [("user", "我叫什么？")]},
                  config={"configurable": {"thread_id": "sess-001"}})   # 记得
r3 = agent.invoke({"messages": [("user", "我叫什么？")]},
                  config={"configurable": {"thread_id": "sess-002"}})   # 不记得（新会话）
```

| 元素 | 说明 |
|------|------|
| `thread_id` | 会话标识：同 id = 同一对话，自动续上历史 |
| 持久化后端 | InMemorySaver（开发）/ SQLiteSaver / PostgresSaver（生产） |
| 行为 | 每轮自动保存完整状态（含中间工具结果） |

> 💡 **与手写对照**：checkpointer = "你手动维护 messages 并落库"的产品化——thread_id 就是你的 session_id。

## 3. store：跨会话存储

```python
from langgraph.store.memory import InMemoryStore
from langchain_core.tools import tool, InjectedStore

store = InMemoryStore()                 # 开发用；生产用 PostgresStore 等

@tool
def remember_fact(fact: str, store: InjectedStore) -> str:
    """记住用户告知的事实。当用户说"记住/以后注意"时使用。"""
    store.put(("facts", "default"), "latest", {"fact": fact})
    return "已记住"

@tool
def recall_fact(store: InjectedStore) -> str:
    """回忆用户告知过的事实。当用户询问之前告知的事情时使用。"""
    item = store.get(("facts", "default"), "latest")
    return item.value["fact"] if item else "暂无记录"

agent = create_agent(
    model=model,
    tools=[remember_fact, recall_fact],
    store=store,                        # ← 一行开启跨会话存储
)
```

| 要素 | 说明 |
|------|------|
| `InjectedStore` | 工具内注入 store 访问（模型看不到该参数） |
| 命名空间 | `("facts", "default")` 键路径组织 |
| 后端 | InMemoryStore（开发）/ PostgresStore（生产） |

> ⚠️ **与 checkpointer 的分工**：store 内容**不会**自动进上下文——只有工具主动读取时才注入。这正是"按需检索"（阶段 2/失败模式体系的外部记忆原则）的框架化。

## 4. 在 create_agent 中使用

完整组合示例：

```python
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.store.memory import InMemoryStore

agent = create_agent(
    model=model,
    tools=tools,
    system_prompt="...",
    checkpointer=InMemorySaver(),       # 跨轮对话记忆
    store=InMemoryStore(),              # 跨会话事实存储
    recursion_limit=25,
)

# 调用统一带 config
result = agent.invoke(
    {"messages": [("user", "记住我住在北京")]},
    config={"configurable": {"thread_id": "sess-001"}},
)
```

**生产后端选型**：

| 后端 | 用途 | 场景 |
|------|------|------|
| InMemorySaver/Store | 开发/单机测试 | 学习阶段 |
| SQLiteSaver | 单机持久 | 本地工具 |
| PostgresSaver/Store | 生产 | 多实例共享、需要事务 |
| Redis 等自定义 | 按需 | 已有基础设施 |

## 5. 与手写记忆方案对照

| 维度 | 手写（阶段 2/失败模式 06 篇） | 框架 |
|------|---------------------------|------|
| 跨轮历史 | 客户端 messages 数组全量重发 | checkpointer 自动保存/恢复 |
| 跨会话事实 | 外部存储 + 每轮写入 + 检索注入 | store + InjectedStore 工具 |
| 上下文压缩 | 手写摘要/滑动窗口 | 框架记忆工具链（阶段 4 深化） |
| 代码量 | 中（存储 + 检索 + 注入三层） | 2 个参数 |
| 透明性 | 全透明 | 黑盒（需理解状态快照） |

> 💡 **框架帮你做的**：状态快照自动落库、恢复、thread 隔离——这些是手写时最容易出错（消息残缺、会话串扰）的部分。

## 6. 常见坑速查

| 坑 | 现象 | 修复 |
|----|------|------|
| invoke 忘传 thread_id | 每次都是新会话 | config 必带 thread_id |
| 用错 checkpointer 类型 | 内存版重启即丢 | 生产换 SQLite/Postgres |
| store 与 checkpointer 混用 | 存错位置 | 先想清楚：对话历史 vs 事实 |
| 工具忘加 InjectedStore 参数 | store 注入失败 | 参数类型必须 InjectedStore |
| 依赖默认 InMemory | 多进程不一致 | 生产显式选 Postgres 后端 |
| 记忆内容不可信 | 注入攻击面（失败模式 07 篇） | 记忆内容按不可信数据处理 |

> 🎯 **核心要点**：记忆的框架化 = **checkpointer 管会话、store 管事实**。心智与手写一致（工作记忆 vs 长期存储），只是从"自己写存储层"变成"选后端 + 传参"。
