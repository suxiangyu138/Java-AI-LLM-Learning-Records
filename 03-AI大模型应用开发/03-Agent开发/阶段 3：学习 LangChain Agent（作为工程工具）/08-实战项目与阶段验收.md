## 1. 项目需求：重写双模式助手

把阶段 2 的"双模式查询助手"用 LangChain 1.0 重写：

| 功能 | 阶段 2（原生） | 阶段 3（框架） |
|------|--------------|---------------|
| 多城市天气对比 | 手写并行 + asyncio | `create_agent` + version="v2" |
| 流式回答 | 手写事件拼装 | `agent.stream(stream_mode="values")` |
| 订单提取 | strict + `.parse()` | `response_format` + Pydantic |
| 记忆 | 手写历史维护 | `checkpointer` |
| 优雅降级 | 手写错误回传 | ToolNode 内置 |

**核心收获**：同一需求两种实现，逐行对照后回答三个问题：

```text
① 框架省了多少代码？（对照每行）
② 框架引入了什么约束？（版本/黑盒/依赖）
③ 哪些能力框架给不了，必须原生/手写？（语义校验、refusal 业务处理）
```

## 2. 核心代码（LangChain 版）

```python
"""agent_lc.py — 阶段 3 双模式助手（LangChain 1.0）"""
from langchain.agents import create_agent
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool
from langgraph.checkpoint.memory import InMemorySaver
from pydantic import BaseModel, Field

# ─── 工具（@tool，docstring 铁律） ─────────────────────────
SUPPORTED_CITIES = {"北京", "上海", "广州", "深圳"}

@tool
def get_weather(city: str) -> str:
    """查询指定城市的当前天气。当用户询问天气、气温、降雨时使用。

    Args:
        city: 城市名（支持：北京、上海、广州、深圳）

    Returns:
        天气 JSON 字符串；不支持的市返回错误说明。
    """
    if city not in SUPPORTED_CITIES:
        return f"错误：不支持的城市 {city}，支持 {sorted(SUPPORTED_CITIES)}"
    return f'{{"city": "{city}", "temperature": 22, "condition": "sunny"}}'


# ─── 结构化输出模型 ────────────────────────────────────────
class OrderInfo(BaseModel):
    product: str = Field(description="商品名称")
    quantity: int = Field(description="数量")
    unit_price: float = Field(description="单价（元）")


# ─── Agent 组装 ────────────────────────────────────────────
model = ChatOpenAI(
    model="deepseek-v4-flash",
    base_url="https://api.deepseek.com",
    api_key="sk-...",          # 生产用环境变量
    temperature=0.1,            # 工具场景低温度（阶段 2 纪律）
)

query_agent = create_agent(
    model=model,
    tools=[get_weather],
    system_prompt="你是一个天气助手，用中文回答，简洁明了。",
    checkpointer=InMemorySaver(),          # 跨轮记忆
    recursion_limit=20,                     # 循环保护
)

extract_agent = create_agent(
    model=model,
    tools=[],
    system_prompt="你是一个信息提取器，只输出结构化结果。",
    response_format=OrderInfo,              # 终轮结构化
)

# ─── 模式路由 + 调用 ───────────────────────────────────────
def route(text: str):
    return "extract" if ("提取" in text or "记一下" in text) else "query"

def run(text: str, session: str = "s-001"):
    agent = extract_agent if route(text) == "extract" else query_agent
    result = agent.invoke(
        {"messages": [("user", text)]},
        config={"configurable": {"thread_id": session}},
    )
    return result["messages"][-1].content

if __name__ == "__main__":
    print(run("北京、上海、广州三地天气对比一下"))
    print(run("提取：苹果手机 3 台，单价 5999 元"))
    print(run("刚才问的哪三地？"))        # checkpointer 记忆验证
```

> ⚠️ 以上为结构示范——完整代码需补：环境变量、流式打印版（agent.stream）、两个 agent 的模型实例隔离、与阶段 2 版本的逐行对照笔记（验收第 6 项）。

## 3. 三向对比表：手写 vs 原生 vs 框架

| 维度 | 手写（阶段 1） | 原生（阶段 2） | 框架（阶段 3） |
|------|:---:|:---:|:---:|
| 基础循环代码 | 60 行 | 60 行 | 3 行 |
| 流式 + 工具拼装 | ~50 行 | ~50 行 | 参数 |
| 并行执行 | 手写 asyncio | 手写 asyncio | version="v2" |
| 记忆/持久化 | 手写存储层 | 手写存储层 | checkpointer |
| 结构化输出 | 手写 schema + 修复 | strict + parse | response_format |
| 错误回传 | 手写 try/except | 手写 try/except | ToolNode 内置 |
| 可观测 | 打印 | 打印 + 自定义 | stream + LangSmith |
| 多供应商 | 手写适配 | OpenAI 系通吃 | 包即用 |
| 版本风险 | 无 | 无 | 框架版本漂移 |
| 黑盒程度 | 全透明 | 全透明 | 需理解（04 篇） |
| 新能力响应 | 手写实现 | 供应商跟进最快 | 适配滞后（如 Responses） |

**代码量总账（同需求）**：手写 ~200 行 / 原生 ~150 行 / 框架 ~60 行——但**复杂度不在行数**，而在维护成本与可控性。

## 5. 选型结论：什么时候用哪个

| 场景 | 推荐 | 理由 |
|------|------|------|
| 学习协议/面试底层 | 手写 | 心智模型 |
| 单工具查询、内部脚本 | 原生 SDK | 零依赖、全透明 |
| 生产 Agent（记忆/流式/可观测） | **框架** | 生产能力密集 |
| 多供应商生产 | 框架（或网关） | 统一接入 |
| 需要供应商新能力（Responses） | 原生 | 框架适配滞后 |
| 多 Agent/人审/复杂拓扑 | LangGraph StateGraph | 节点级控制 |

**2026 生产共识**：**组合使用**——LangChain 1.0 create_agent 起步（省 70% 样板），节点级需求下沉 StateGraph，供应商新能力直连原生 API，关键路径用框架，能力盲区用原生补。
