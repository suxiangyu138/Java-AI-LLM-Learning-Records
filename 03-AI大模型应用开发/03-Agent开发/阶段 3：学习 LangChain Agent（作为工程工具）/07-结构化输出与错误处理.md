## 1. 三条结构化路线（框架版）

| 路线 | 框架 API | 底层 | 对应阶段 2 |
|------|---------|------|-----------|
| strict 式 | `response_format`（Pydantic schema） | 供应商 strict/约束解码 | Structured Output |
| 提取式 | `with_structured_output(method="json_mode")` | JSON Mode | JSON Mode |
| 工具式 | `bind_tools` + 强制 tool_choice | 协议层 | 强制工具提取 |

> 🎯 **核心要点**：框架没有发明新协议——它把阶段 2 的三条路线变成了**统一的参数化 API**，底层仍走原生能力。

## 2. create_agent 的 response_format

```python
from pydantic import BaseModel, Field

class WeatherSummary(BaseModel):
    cities: list[str] = Field(description="查询的城市列表")
    comparison: str = Field(description="天气对比结论")
    recommendation: str | None = Field(default=None, description="出行建议，可空")

agent = create_agent(
    model=model,
    tools=tools,
    system_prompt="你是一个天气助手。",
    response_format=WeatherSummary,     # ← 最终回答强制结构化
)

result = agent.invoke({"messages": [("user", "对比北京和上海天气")]})
last = result["messages"][-1]
print(last.content)                      # 结构化 JSON 字符串
# 或经 parse：result["structured_response"] 按框架版本可用
```

| 要点 | 说明 |
|------|------|
| 生效位置 | 最终回答轮（循环内工具轮不受约束）——**回合分离的框架化**（阶段 2 黄金法则） |
| 输入 | Pydantic 模型（自动转 strict schema） |
| 底层 | 供应商 structured output 能力 |

## 3. with_structured_output 详解

```python
from pydantic import BaseModel

class Plan(BaseModel):
    steps: list[str]
    risk: str

# 方式一：单模型绑定（非 Agent 场景）
structured_model = model.with_structured_output(Plan)
plan = structured_model.invoke("制定一个部署计划")
print(plan.steps)                     # 类型化对象

# 方式二：指定方法
structured_model = model.with_structured_output(
    Plan,
    method="json_mode",               # "json_mode" / "function_calling" / "json_schema"
)
```

| method | 底层 | 返回 | 适用 |
|--------|------|------|------|
| `json_schema`（默认，OpenAI） | strict | 类型化对象 | OpenAI 系 |
| `json_mode` | JSON Mode | dict（需手动校验） | 兼容供应商 |
| `function_calling` | 工具调用伪装 | 类型化对象 | 无 strict 供应商 |

> 💡 与阶段 2 对照：`method` 参数 = 阶段 2 03 篇"三条结构化路线"的框架化表达——选 method 就是选路线。

## 4. 循环保护：recursion_limit 与错误容错

### 4.1 recursion_limit

```python
agent = create_agent(
    model=model,
    tools=tools,
    system_prompt="...",
    recursion_limit=25,        # ★ 循环步数上限（防死循环）
)
```

| 场景 | 推荐值 |
|------|:---:|
| 简单查询 Agent | 10-15 |
| 多步工具任务 | 20-25 |
| 复杂规划 Agent | 30+（配合预算熔断） |

### 4.2 工具错误的框架化处理

框架内置的容错链（= 你手写的三件套产品化）：

```text
手写（阶段 1）：execute_tool try/except → {"error": ...} 回传
框架：ToolNode 自动捕获异常 → 错误作为工具结果回传 → 模型自行降级
```

```python
# 工具内主动失败（保持错误信息清晰）：
@tool
def get_weather(city: str) -> str:
    """查询指定城市的当前天气。当用户询问天气、气温、降雨时使用。"""
    if city not in SUPPORTED_CITIES:
        return f"错误：不支持的城市 {city}，支持的城市有 {SUPPORTED_CITIES}"   # 回传给模型
    return f"{city} 22℃ 晴天"
```

| 层 | 框架行为 | 你手写的等价物 |
|----|---------|--------------|
| 工具异常 | ToolNode 捕获转回传 | execute_tool try/except |
| 模型解析错误 | 框架可配解析容错 | 修复循环 |
| 循环上限 | recursion_limit | MAX_TURNS |
| 业务失败 | 工具主动返回错误信息 | 错误转 JSON 回传 |

### 4.3 解析容错

```python
# 老 API（AgentExecutor 时代）的解析容错参数——create_agent 时代已由框架内置
# 但仍要理解：模型输出坏 JSON 时，框架怎么兜？
# 2026 答案：create_agent 走原生工具调用协议（结构受控）+ strict schema，
# 解析失败概率已从"prompt 时代"大幅下降；残余失败靠错误回传 → 重试循环
```

> ⚠️ **2026 视角**：框架的"解析容错"重点不在 JSON 修复（阶段 1 的手工修复循环），而在**协议层保证 + 错误回传 + 循环上限**——这三层是生产 Agent 的默认配置。

## 5. 与阶段 2 原生能力对照

| 能力 | 原生（阶段 2） | 框架（阶段 3） |
|------|--------------|---------------|
| strict 结构化 | `response_format` + `.parse()` | `response_format` 参数 + Pydantic |
| JSON 提取 | 强制 tool_choice | `with_structured_output(method=...)` |
| 回合分离 | 手动两段（循环 + 终轮） | response_format 自动终轮生效 |
| 修复循环 | 手写 ≤3 次重试 | ToolNode 错误回传 + 模型自愈 |
| 截断处理 | 检查 finish_reason | 框架暴露 + 需自建校验 |
| refusal | `message.refusal` 显式检查 | 框架透传（校验仍在业务层） |

> 💡 **框架没帮你做的**：语义校验（值对错）、refusal 的业务处理、截断的观测——这些仍在你的代码里（阶段 4 的评估与护栏）。

## 6. 常见坑速查

| 坑 | 现象 | 修复 |
|----|------|------|
| response_format 与工具循环冲突 | 工具调用被抑制 | 确认框架版本行为；需要时手动两段式 |
| Pydantic 字段未全 required | strict 报错 | 用 `type: [...] | None` 表达可选 |
| 忘设 recursion_limit | 死循环烧钱 | 显式设置（10-25） |
| 工具返回中文/None | 结果格式异常 | 返回 str（统一转 JSON 字符串） |
| with_structured_output 方法不匹配供应商 | 报错/行为异常 | 按供应商选 method（03 篇对照） |
| 错误信息太模糊 | 模型重复同一错误 | 工具错误信息带具体原因 + 建议 |

> 🎯 **核心要点**：框架把"格式保证"做成了参数，但**"语义正确"永远是业务层的责任**——response_format 保证结构合法，你的校验链保证值可信。两层缺一不可（与阶段 2 结论一致，只是实现换成了参数）。
