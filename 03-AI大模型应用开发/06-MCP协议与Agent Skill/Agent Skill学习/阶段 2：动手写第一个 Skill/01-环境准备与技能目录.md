## 1. 技能存放位置

### 三级位置（Claude Code）

| 位置 | 范围 | 用途 |
|---|---|---|
| `.claude/skills/`（项目级） | 当前项目 | 项目技能（可提交 git 共享） |
| `~/.claude/skills/`（用户级） | 当前用户 | 个人技能 |
| 插件级 | 随插件分发 | 生态技能 |

```
优先级（更具体优先）：
项目级 > 用户级 > 插件级
同名技能：项目级覆盖用户级
```

### 位置选择

```
个人常用技能 → ~/.claude/skills/
项目特定技能 → .claude/skills/（随仓库走，团队共享）
```

## 2. 发现路径实操

### 创建技能目录

```bash
# 用户级（个人技能）
mkdir -p ~/.claude/skills/my-skill

# 项目级（项目技能）
mkdir -p .claude/skills/my-skill
```

### 目录结构

```
my-skill/
├── SKILL.md          # 必需
├── scripts/          # 可选
├── references/       # 可选
└── assets/           # 可选
```

### 路径错误排查

```
常见错误：
① 放错层级（.claude/skill 而非 skills）
② SKILL.md 拼写（必须大写 SKILL）
③ 嵌套过深（SKILL.md 必须在技能目录根）
④ 技能目录名与 name 不一致
```

## 3. 查看技能清单

### 三种查看方式

| 方式 | 操作 | 用途 |
|---|---|---|
| 对话询问 | 问"What skills are available?" | 看已加载技能 |
| 斜杠菜单 | 输入框敲 `/skills` | 可视化菜单 + 启用开关 |
| 环境检查 | `/doctor` | 检查描述预算溢出 |

### /skills 菜单能力

```
查看所有技能（启用状态）
切换每个技能的启用/禁用
（菜单里点选即可）
```

### /doctor 的意义

```
技能装太多 → description 预算溢出 → description 被截断 → 触发失灵
/doctor 体检：检查描述预算是否溢出
```

## 4. 启用与禁用

### 为什么需要禁用

```
某些技能不该自动触发（有副作用的）：
部署/提交/发消息类 → 应禁自动触发（手动调用）
（对应 frontmatter 的 disable-model-invocation，04 篇详述）
```

### 禁用方式

```
① /skills 菜单切换
② frontmatter 字段控制（disable-model-invocation/user-invocable）
```

### 启用状态确认

```
写完技能后：
① /skills 菜单确认出现
② 问"What skills are available?" 看是否列出
③ 说触发词测试（05 篇）
```

## 5. 环境检查清单

| 项 | 检查 | ✅ |
|---|---|---|
| 目录位置 | 在 .claude/skills/ 或 ~/.claude/skills/ | ☐ |
| SKILL.md | 拼写正确、在技能目录根 | ☐ |
| 技能可见 | /skills 菜单或对话询问能列出 | ☐ |
| name 一致 | frontmatter name = 目录名 | ☐ |
| 描述预算 | /doctor 无溢出警告 | ☐ |
| 启用状态 | 技能处于启用（可自动触发） | ☐ |

### 排错顺序

```
看不到技能？
① 路径对吗？（skills 拼写/层级）
② 重启会话了吗？（新技能要新会话加载）
③ 描述预算溢出？（/doctor）
④ 同名覆盖？（优先级检查）
```

## 6. 面试高频问法

| 问题 | 回答要点 |
|---|---|
| 技能放哪？ | 项目级 .claude/skills/ 或用户级 ~/.claude/skills/ |
| 优先级？ | 项目 > 用户 > 插件（更具体优先） |
| 怎么确认加载？ | /skills 菜单 / What skills are available? |
| /doctor 查什么？ | 描述预算溢出（技能多时） |
| 怎么禁用自动触发？ | /skills 菜单或 frontmatter 字段 |
| 新技能看不到？ | 路径/重启/预算/同名四查 |

### 面试加分表达

> "放技能就两个位置：项目级 .claude/skills/（随仓库共享）和用户级 ~/.claude/skills/（个人）。验证加载用 /skills 菜单或直接问"What skills are available?"。踩过两个坑：SKILL.md 拼写必须大写、装太多技能 description 预算溢出会被截断（/doctor 能查）——放对位置是触发的前提。"

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "技能放哪都行" | 位置决定作用范围（项目/用户） |
| "SKILL.md 大小写无所谓" | 必须大写（skill.md 不识别） |
| "装越多越好" | 描述预算有限（/doctor 查溢出） |
| "改技能立即生效" | 新会话才加载（重启） |
| "同名技能共存" | 优先级覆盖（项目 > 用户 > 插件） |

## 8. 本仓库技能目录观察

### 实操观察（学完本模块做）

```
① 打开本仓库 .claude/skills/ 目录（6 个技能）
② 逐个看目录结构（SKILL.md + 可选配套）
③ 看 frontmatter（name/description 怎么写）
④ 观察正文结构（规则/步骤/输出）
——"看现成的"是写技能最快的入门
```

### 观察清单

| 技能 | 看什么 |
|---|---|
| markdown-doc-generator | description 风格 + 篇幅分档 |
| doc-quality / verify-docs | 校验流程的正文写法 |
| tech-research | 强制检索的规则写法 |
| java-review / interview-prep | 检查清单类技能结构 |

> 🎯 核心要点：两级位置（项目/用户）+ 插件级；优先级项目 > 用户 > 插件；查看三方式（对话询问//skills 菜单//doctor 预算检查）；禁用自动触发（菜单或 frontmatter）；新技能看不到四查（路径/重启/预算/同名）；SKILL.md 大写 + 目录根；看现成技能（本仓库 6 个）是入门最快路径。
