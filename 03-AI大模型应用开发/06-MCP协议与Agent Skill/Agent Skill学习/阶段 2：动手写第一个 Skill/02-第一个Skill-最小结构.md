## 1. 最小技能的结构

```
一个技能 = 一个目录 + 一个 SKILL.md（必需）
scripts/references/assets 都是可选的（后续再加）
```

| 元素 | 最小技能 |
|---|---|
| 目录 | ✅（名字 = 技能名） |
| SKILL.md | ✅（frontmatter + 正文） |
| scripts/ | 暂不需要 |
| references/ | 暂不需要 |
| assets/ | 暂不需要 |

> 最小可用优先：先跑通"能触发"，再丰富内容（阶段 3）。

## 2. 创建步骤

```bash
# 1. 创建目录（用户级示例）
mkdir -p ~/.claude/skills/hello-skill

# 2. 创建 SKILL.md
touch ~/.claude/skills/hello-skill/SKILL.md
```

```
3. 编辑 SKILL.md（frontmatter + 正文）
4. 新会话（让技能被加载）
5. 说触发词测试
```

### 创建顺序（建议）

```
① 目录（名字先定好）
② frontmatter（name + description）
③ 正文（先写"何时使用" + "执行步骤"）
④ 新会话测试触发
⑤ 迭代（03/04 篇深化）
```

## 3. frontmatter 实操

### 最小必填

```markdown
---
name: hello-skill
description: 输出问候语。用于用户打招呼或需要友好开场时。
---
```

| 字段 | 本示例 | 规则 |
|---|---|---|
| name | hello-skill | kebab-case，= 目录名 |
| description | 做什么 + 何时用 | ≤1024 字符 |

### 建议加上的字段

```markdown
---
name: hello-skill
description: 输出问候语。用于用户打招呼或需要友好开场时。
version: 0.1.0
allowed-tools: []          # 本技能不需要工具
---
```

```
version：SemVer（x.y.z）——技能也版本化
allowed-tools：[] 空 = 不需要工具（安全默认）
```

## 4. 正文：先写什么

### 最小正文（两个部分起步）

```markdown
# hello-skill

## 何时使用
- 用户打招呼（"你好""嗨"等）
- 需要友好开场时

## 执行步骤
1. 根据用户语气选择问候语
2. 简短友好地回应
3. 询问是否需要帮助
```

### 为什么"何时使用"先行

```
正文加载后（L2），Agent 第一步是确认"这个技能适不适合"
"何时使用"是确认依据（与 description 呼应）
```

## 5. 最小示例全解

### 完整 SKILL.md

```markdown
---
name: hello-skill
description: 输出友好的问候语。用于用户打招呼（你好/嗨/hello）、
  或对话需要友好开场时。简短回应并询问需求。
version: 0.1.0
allowed-tools: []
---

# hello-skill

## 何时使用
- 用户打招呼（"你好""嗨""hello"等）
- 需要友好开场时

## 执行步骤
1. 识别用户语气（正式/随意）
2. 用匹配的语气问候
3. 询问是否需要帮助

## 输出
- 一句问候 + 一句需求询问（简短）
```

### 示例解读

| 部分 | 作用 |
|---|---|
| frontmatter | 元数据（发现与匹配） |
| 何时使用 | 触发后的确认 |
| 执行步骤 | 怎么做（编号顺序） |
| 输出 | 结果格式 |

## 6. 常见错误

| 错误 | 后果 | 修正 |
|---|---|---|
| name 与目录不一致 | 无法被发现 | 保持一致 |
| description 太笼统 | 永不触发 | 写"做什么+何时用" |
| 正文只有一句 | 执行没指导 | 至少"何时使用+步骤" |
| 忘了新会话 | 技能不加载 | 新会话测试 |
| 文件名小写 skill.md | 不识别 | 必须 SKILL.md |

## 7. 面试高频问法

| 问题 | 回答要点 |
|---|---|
| 最小技能几个文件？ | 一个 SKILL.md |
| frontmatter 最小？ | name + description |
| version 格式？ | SemVer（x.y.z） |
| allowed-tools 空？ | 表示不需要工具（安全默认） |
| 正文最少写什么？ | 何时使用 + 执行步骤 |
| 为什么先写"何时使用"？ | 触发后的确认依据 |

### 面试加分表达

> "最小技能就是一个目录 + 一个 SKILL.md：frontmatter 写 name（与目录一致）和 description（做什么+何时用），正文先写"何时使用"和"执行步骤"两段就够跑通触发。我建议 allowed-tools 从空开始（不需要就不给），version 用 SemVer 从 0.1.0 起步——安全与版本意识第一天就养成。"

## 8. 常见误区

| 误区 | 真相 |
|---|---|
| "目录名随便起" | 必须与 name 一致（发现依赖） |
| "description 之后补" | 先写——它是触发的钥匙 |
| "正文一次写全" | 最小可用优先（先触发再丰富） |
| "字段越多越好" | 最小优先（version/allowed-tools 起步） |
| "写完就完事" | 新会话 + 触发测试是必须步骤 |

## 9. 从最小到生产级的演进路径

```
最小技能（本阶段）
  ├─ 目录 + SKILL.md（frontmatter + 简版正文）
  ↓
可用技能（本阶段完成）
  ├─ description 优化（触发词）→ 正文七部分 → 验证
  ↓
生产级技能（阶段 3）
  ├─ scripts/（脚本）→ references/（资料）→ assets/（模板）
  ├─ allowed-tools 精细配置 → 测试体系 → 版本管理
```

| 阶段 | 标志 |
|---|---|
| 最小 | 能触发（哪怕内容少） |
| 可用 | 触发 + 功能达标 |
| 生产级 | 多文件 + 安全 + 测试 + 版本 |

> 演进原则：**先跑通再丰富**——最小结构触发后，逐层加内容（每次验证），别一上来追求完整。

> 🎯 核心要点：最小技能 = 目录 + SKILL.md；frontmatter 最小（name+description）；建议加 version + allowed-tools；正文最少"何时使用 + 执行步骤"；创建顺序（目录→frontmatter→正文→新会话→测试）；六个常见错误（尤其 name 一致性/description 笼统/SKILL 大写）；演进路径（最小→可用→生产级），先跑通再丰富。
