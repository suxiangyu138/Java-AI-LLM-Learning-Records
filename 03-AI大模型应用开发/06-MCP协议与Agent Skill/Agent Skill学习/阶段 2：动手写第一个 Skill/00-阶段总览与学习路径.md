## 1. 本阶段定位

五阶段路径的"第一次动手"——目标是跑通"创建 → 触发 → 执行"全流程：

```
阶段1 概念 → 阶段2 第一个 Skill（本阶段）→ 阶段3 进阶 → 阶段4 框架 → 阶段5 工程
```

| 对比项 | 阶段 1 | 阶段 2 |
|---|---|---|
| 任务 | 理解规范 | 写出能触发的技能 |
| 产出 | 概念图 | 可用的 SKILL.md + 验证记录 |
| 技术 | 零代码 | Markdown + 基础命令 |
| 验收 | 20 自测 | 技能真实触发并完成一个任务 |

### 阶段 2 的核心挑战

```
手写技能最容易翻的车：写完不知道触不触发，全靠玄学
→ 本阶段的重点不是"写"，是"写 + 验证"
```

## 4. 学习计划与目标

### 三天计划

| 天 | 内容 | 目标 |
|---|---|---|
| Day 1 | 01 环境 + 02 最小结构 + 03 description | 写出第一个 SKILL.md |
| Day 2 | 04 正文 + 05 验证 | 技能能触发能执行 |
| Day 3 | 06 实战 + 07 进阶 + 08 自测 | 完整技能 + 毕业 |

### 动手任务（贯穿三天）

```
① 选主题：从"我的重复流程"中选一个（如文档生成/代码审查）
② 写：目录 + SKILL.md（frontmatter + 正文）
③ 验：触发测试（说触发词 → 技能激活？）
④ 改：按验证结果迭代 description/正文
⑤ 收：完成一个真实任务 + 记录验证结果
```

## 5. 常见疑问快答

| 疑问 | 回答 |
|---|---|
| 需要会写代码吗？ | 基础 Markdown 即可；脚本可选（阶段 3 深化） |
| 技能放哪？ | 项目 `.claude/skills/` 或用户 `~/.claude/skills/` |
| 怎么知道技能触发了？ | 对话中观察；问"What skills are available?" |
| 触发不了怎么办？ | 三步排查：说法/description/启用状态 |
| 用 skill-creator 吗？ | 可用（向导式兜坑），但本阶段先手写理解原理 |
| 技能会干扰日常吗？ | description 写好不会（只匹配对应任务） |

## 6. 毕业标准

- [ ] 自己的 SKILL.md 通过触发测试（说触发词能激活）
- [ ] 技能完成一个真实任务（不是空壳）
- [ ] 能讲清 description 为什么这样写（触发公式）
- [ ] 会用三步排查表解决"不触发"问题
- [ ] 20 道自测题正确率 ≥ 80%

## 7. 常见失败画像与关键数据

### 失败画像

| 失败画像 | 现象 | 预防 |
|---|---|---|
| 永不触发型 | description 缺触发词 | 03 篇公式 + 触发词收集 |
| 写而不验型 | 写完不知道触不触发 | 05 篇三维验证 |

### 一句话定位总结

```
阶段 2 = "从知道 Skill 到做出 Skill"
```

### 面试价值

```
阶段 2 的面试价值：
① 能讲"写技能"的完整流程（六步法）
② 能讲 description 为什么是钥匙（触发机制）
③ 能讲验证方法（不靠玄学，数据说话）
④ 有真实技能作品（比空谈概念有说服力）
——会写会验 = 不只是"知道"Skill
```

### 学习心态

```
阶段 2 的核心不是"写"，是"写 + 验证"：
写完必须验证（触发/功能/性能）——不靠玄学
一次一变量迭代——改 description 或正文，别一起改
先跑通再丰富——最小可用优先，再逐层加
```
