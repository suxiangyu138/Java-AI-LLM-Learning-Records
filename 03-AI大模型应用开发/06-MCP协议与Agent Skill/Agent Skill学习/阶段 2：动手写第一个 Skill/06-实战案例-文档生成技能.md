## 1. 案例设定与需求

### 场景

```
目标：一个"生成学习向 Markdown 技术文档"的技能
用户：写学习笔记/技术文章的人（本仓库场景）
```

### 需求拆解

| 需求 | 说明 |
|---|---|
| 输出 | 高密度 Markdown 技术文档 |
| 触发 | 用户要求生成/整理文档时 |
| 规范 | 表格优先、代码标注语言、锚点匹配 |
| 自检 | 写完检查（围栏/锚点/表格） |

## 2. 本仓库技能对照

### 真实案例（.claude/skills/markdown-doc-generator/）

```
本仓库已有同款技能——写技能前先"拆解现成的"：
① 看它的 SKILL.md（frontmatter + 正文结构）
② 看它怎么组织 references（如有）
③ 观察它的 description 写法（触发词）
```

### 拆解要点

```
markdown-doc-generator 的启示：
① description：做什么 + 何时用 + 风格（高密度/表格优先）
② 正文：结构原则/表格规范/代码块规范（声明式规则）
③ 篇幅约束：按场景分档（3000-8000/800-1500...）
——真实技能 = 阶段 1-4 规范的全部实践
```

## 3. 第一步：目录与 frontmatter

```bash
mkdir -p ~/.claude/skills/doc-generator
```

```markdown
---
name: doc-generator
description: 生成学习向 Markdown 技术文档。用于用户要求
  写笔记/技术文章/知识体系文档时。高密度、表格优先、代码标注语言。
version: 0.1.0
allowed-tools:
  - read_file
  - write_file
---
```

### 设计说明

| 字段 | 为什么 |
|---|---|
| name | doc-generator（= 目录名） |
| description | 做什么 + 何时用 + 风格关键词 |
| allowed-tools | 读写文件（最小权限） |

## 4. 第二步：description（触发钥匙）

### 触发词设计

```
用户会怎么说：
"写个笔记" / "生成技术文章" / "整理成文档"
"做一份学习文档" / "写篇总结"
```

### 最终 description

```markdown
description: 生成学习向 Markdown 技术文档。用于用户要求
  写笔记、技术文章、知识体系、学习总结时——包括"整理成文档"
  "做成笔记""写篇技术文章"等说法。按高密度风格输出，
  表格优先、代码块标注语言、目录锚点匹配。
```

### 设计检查（对照 03 篇公式）

| 要素 | 本案例 |
|---|---|
| 做什么 | 生成学习向 Markdown 文档 |
| 何时用 | 写笔记/文章/知识体系时 |
| 触发词 | 笔记/文章/整理/总结 + 同义说法 |

## 5. 第三步：正文（执行手册）

```markdown
# doc-generator

## 何时使用
- 用户要求生成/整理技术文档
- 包括"笔记""文章""总结""知识体系"等说法

## 文档类型与篇幅
| 类型 | 篇幅 |
|---|---|
| 知识体系系列 | 单篇 3000-8000 字 |
| 单篇笔记 | 800-1500 字 |
| 概念速记 | 300-600 字 |

## 写作规则（声明式）
- 标题：`#` 一级，`##` 二级，最多 `###`
- 表格优先于大段文字（对比/速查用表格）
- 代码块必须标注语言（如 ```python）
- 目录锚点与标题 slug 匹配
- 不写废话套话（信息密度优先）

## 输出格式
- 完整 Markdown 文档（可直接归档）
- 文档末尾自检：围栏配对/锚点/表格

## 错误处理
| 情况 | 处理 |
|---|---|
| 用户没给主题 | 询问主题与文档类型 |
| 篇幅不明确 | 按类型默认值 |

## 示例
输入："写个 Python 装饰器的笔记"
输出：单篇笔记（800-1500 字，含对比表与示例代码）
```

### 正文设计说明

| 部分 | 作用 |
|---|---|
| 何时使用 | 触发后的确认 |
| 类型与篇幅 | 关键决策（先定类型） |
| 写作规则 | 声明式规则（行为边界） |
| 输出格式 | 交付物定义 |
| 错误处理 | 异常兜底 |
| 示例 | 输入输出示范 |

## 6. 第四步：验证与迭代

### 验证流程（05 篇方法）

```
① 新会话 → 说"帮我写个学习笔记" → 触发？
② 让技能生成一篇笔记 → 对照输出格式验收
③ 边界测试（没给主题 → 询问？）
④ 回归（改 description 后重测）
```

### 验证记录表

| 测试 | 结果 | 迭代 |
|---|---|---|
| 直接触发（写笔记） | ✅ | — |
| 间接触发（整理成文档） | ✅ | — |
| 边界（无关任务） | 不触发 ✅ | — |
| 功能（生成质量） | ⚠️ 表格偏少 | 正文加"表格优先"强调 |
| 回归 | ✅ | version 0.1.1 |

### 常见迭代点

```
触发差 → 加触发词（03 篇）
质量差 → 强化规则（04 篇声明式）
加载重 → 拆 references（阶段 3）
```

## 7. 面试高频问法

| 问题 | 回答要点 |
|---|---|
| 写技能的完整流程？ | 需求→目录→frontmatter→description→正文→验证迭代 |
| description 怎么设计？ | 公式三要素 + 触发词收集 |
| 正文最关键的部分？ | 规则（声明式）+ 输出格式 |
| 验证怎么闭环？ | 触发/功能/边界/回归 |
| 怎么证明技能有效？ | 验证记录表（测试→结果→迭代） |
| 参考什么写？ | 先拆解现成技能（本仓库 6 个） |

### 面试加分表达

> "写技能的完整流程我总结为六步：需求拆解→目录与 frontmatter→description（触发钥匙，收集用户说法做触发词）→正文（声明式规则 + 输出格式）→验证（触发/功能/边界/回归）→迭代（一次一变量）。写之前先拆解现成技能——本仓库就有 6 个真实案例可对照，比从零想高效得多。"

> 🎯 核心要点：六步流程（需求→结构→description→正文→验证→迭代）；先拆解现成技能（本仓库 6 个是最好的教材）；description 触发词从用户说法收集；正文声明式规则 + 输出格式 + 错误处理；验证四测（直接/间接/边界/回归）+ 记录表；一次一变量迭代。

## 8. 常见误区

| 误区 | 真相 |
|---|---|
| "案例抄完就是会" | 要按自己的场景重做（触发词不同） |
| "一步写完整技能" | 六步流程一步步来（先触发再丰富） |
| "验证记录可省" | 记录是迭代与面试的证据 |
| "只测触发不测功能" | 触发 ≠ 干得好（功能必须验收） |
| "版本号随便" | SemVer 递增（改动留痕） |
