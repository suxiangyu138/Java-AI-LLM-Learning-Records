## 1. 动手任务一：选型与设计

### 任务目标

从"你的重复流程"中选一个主题，完成技能设计（不写代码）。

### 选型检查（阶段 1 的 07 篇）

| 检查 | 你的答案 |
|---|---|
| 可复用？（多次发生） | ______ |
| 有流程？（固定步骤） | ______ |
| Agent 该会？（做事知识） | ______ |
| 触发场景？（用户会怎么说） | ______ |

### 设计产出

```
① 技能名（kebab-case）
② description 草稿（公式三要素）
③ 正文大纲（规则/步骤/输出）
④ 触发词清单（5 个用户说法）
```

### 主题参考

```
文档生成 / 代码审查 / 提交信息规范 / 环境初始化 / 笔记整理
（本仓库 6 个技能可作参考：doc-quality/interview-prep 等）
```

## 2. 动手任务二：编写与触发

### 编写步骤

```
① mkdir 技能目录（~/.claude/skills/你的技能名）
② 写 SKILL.md（frontmatter + 正文）
③ 新会话（确保加载）
④ 说触发词测试触发
```

### 触发测试记录

| 测试说法 | 触发？ | 观察 |
|---|---|---|
| 直接说法：______ | ☐ | |
| 同义说法：______ | ☐ | |
| 间接说法：______ | ☐ | |
| 无关任务（应不触发） | ☐ | |

### 失败排查（05 篇三步）

```
① 说法含糊？→ 用技能触发词直接说
② description 不匹配？→ 对照公式改写
③ 没启用？→ /skills 菜单 + /doctor
```

## 3. 动手任务三：验证与迭代

### 功能验证

```
① 让技能完成一个真实任务
② 对照"输出格式"验收
③ 边界测试（异常输入）
④ 记录结果
```

### 迭代两轮

```
第一轮：基于验证结果改（一次一变量）
第二轮：回归（重测触发 + 功能）
version 递增（0.1.0 → 0.1.1）
```

### 验证记录表（交付物）

```
技能名：______ 版本：______
触发测试：直接/间接/边界 结果
功能测试：任务/输出/边界 结果
迭代记录：改了什么/为什么/回归结果
```

## 4. 20 道自测题

### 环境与结构（1-6）

1. 技能放哪两个位置？优先级？
2. SKILL.md 拼写为什么关键？
3. frontmatter 必填字段及规则？
4. 最小正文包含什么？
5. version 格式？
6. allowed-tools 空列表含义？

### description（7-11）

7. description 为什么是"触发钥匙"？
8. 写作公式？
9. 坏 description 三种？
10. undertrigger 是什么？怎么应对？
11. 触发词从哪来？

### 正文与触发（12-17）

12. 正文七部分？最小必写？
13. 声明式 vs 程序式？
14. 步骤上限？
15. 触发流程四阶段？
16. 验证三维？
17. 三步排查？

### 进阶（18-20）

18. $ARGUMENTS 与 CLAUDE_SKILL_DIR？
19. U 形注意力怎么用？
20. 何时禁自动触发？

### 参考答案（简版）

1. 项目 .claude/skills/ 与用户 ~/.claude/skills/；项目 > 用户 > 插件
2. 拼错（skill.md）不识别
3. name（≤64 kebab-case = 目录名）+ description（≤1024）
4. 何时使用 + 执行步骤 + 输出格式
5. SemVer（x.y.z）
6. 不需要工具（安全默认）
7. L1 只加载它，匹配靠它（正文不参与匹配）
8. 做什么 + 何时用 + 触发词
9. 笼统 / 缺触发词 / 写自己
10. 模型触发不足倾向——写得带催促感（"即使没明确要求"）
11. 用户会怎么说（口语/同义/间接）
12. 概述/前置/步骤/输出/错误/示例/资源；概述+步骤+输出
13. bullet 规则默认；编号只用于严格顺序
14. 10-15 步（超出拆子流程）
15. INSTALL→STARTUP→ACTIVATE→EXECUTE
16. 触发/功能/性能
17. 说法 → 匹配 → 环境
18. $ARGUMENTS 斜杠输入；CLAUDE_SKILL_DIR 技能路径（引用配套必用）
19. 关键规则放首因区+近因区（双位置换说法）
20. 有副作用操作（部署/提交/发消息）

### 评分与行动

| 得分 | 结论 |
|---|---|
| 16-20 | 达标，进入阶段 3 |
| 12-15 | 复习错题对应篇 |
| <12 | 重做动手任务 + 重读 01-07 |

## 6. 下一阶段预告

**阶段 3：进阶 Skill 开发**——从"能用的技能"到"生产级技能"：

- 多文件结构（scripts/references/assets 实战）
- 脚本编写与工具调用
- allowed-tools 精细配置
- 技能质量评估与测试体系
- 复杂技能设计模式

### 进入阶段 3 前的准备

1. 保留你的技能与验证记录（阶段 3 的升级对象）
2. 想一个"需要脚本"的技能需求（阶段 3 会写）
3. 收集你遇到的技能问题（触发不准/执行不稳等）

> 🎯 阶段 2 毕业标准总结：**能写（结构完整）、能触发（验证通过）、能干活（功能达标）、能迭代（记录留痕）**——四项齐备，进入阶段 3。

### 项目故事模板（面试用）

> "我写过一个文档生成技能：需求拆解（高密度 Markdown 输出）→ 目录与 frontmatter（allowed-tools 最小权限）→ description 按公式写（做什么+何时用+触发词'笔记/文章/整理'）→ 正文声明式规则 + 输出格式 + 错误处理 → 验证四测（直接/间接/边界/回归）→ 发现表格偏少，一次一变量强化规则后回归通过。产出：一个真实可用的技能 + 完整验证记录。"

### 常见失败与应对

| 失败 | 应对 |
|---|---|
| 技能不触发 | 三步排查（说法→匹配→环境） |
| 触发但执行差 | 强化正文规则（声明式） |
| 改了没效果 | 一次一变量 + 回归 |
| 验证靠感觉 | 用记录表（数据说话） |
