## 1. 参数与动态上下文

### $ARGUMENTS

```
斜杠调用时的输入：
/your-skill 参数内容 → $ARGUMENTS 替换全部输入
$1、$2 → 按位置取参
```

```markdown
## 执行步骤
1. 读取文件：$1
2. 对 $ARGUMENTS 中提到的内容生成文档
```

### 反引号注入（加载时执行）

```
`!git log --oneline -20` 可在加载时执行 shell：
把真实输出插入提示词（动态上下文）
```

```markdown
## 前置条件
最近提交：
`!git log --oneline -5`
```

> ⚠️ 反引号注入有执行风险——技能作者要用、使用者要审查（阶段 1 的 06 篇）。

## 2. 变量速查

| 变量 | 含义 | 用途 |
|---|---|---|
| $ARGUMENTS | 斜杠调用全部输入 | 参数传递 |
| $1/$2 | 按位置取参 | 指定参数 |
| ${CLAUDE_SKILL_DIR} | 技能目录绝对路径 | 引用 references/ 文件必用 |
| 反引号注入 | 加载时执行命令 | 动态上下文 |

### CLAUDE_SKILL_DIR 示例

```markdown
## 执行步骤
1. 读取模板：${CLAUDE_SKILL_DIR}/assets/templates/blog.md
2. 按模板生成文档
```

```
为什么必须用它：
技能目录路径在运行时才确定（不同安装位置）
硬编码路径 = 技能不可移植
```

## 3. U 形注意力布局

### 模型注意力的 U 形曲线

```
模型对指令的注意力：
开头 20%（首因区）→ 强
中间 → 弱（易被忽略）
结尾 20%（近因区）→ 强
```

### 布局策略

| 区域 | 放什么 |
|---|---|
| 开头（首因区） | 身份、哲学、关键约束 |
| 中间 | 次要细节 |
| 结尾（近因区） | 强化关键规则、质量检查 |

### 双位置强调

```
关键规则要在顶部和结尾双位置、换说法强调：
开头："输出必须表格优先"
结尾："最后检查：是否用了表格？代码是否标注语言？"
——中间被忽略也不怕，两端有保险
```

## 4. references 路由列表

### 问题

```
references/ 有多个文档时：
Agent 可能过度读取（浪费）或跳过（缺信息）
```

### 解法：路由列表

```markdown
## 参考资料（按需读取）
| 文件 | 内容 | 何时读 |
|---|---|---|
| references/风格指南.md | 写作风格细节 | 风格不确定时 |
| references/模板示例.md | 完整示例 | 需要参考结构时 |
| references/常见错误.md | 易错点 | 输出不达标时 |
```

### 路由列表的价值

```
① 控制加载：Agent 按"何时读"判断（L3 按需）
② 防过度读取：不用全读
③ 防跳过：列出来提醒存在
```

## 5. 高级 frontmatter 字段

| 字段 | 作用 | 场景 |
|---|---|---|
| disable-model-invocation: true | 禁自动触发（只手动） | 有副作用的技能（部署/提交/发消息） |
| user-invocable: false | 从斜杠菜单隐藏 | Claude 自动触发但用户不手动 |
| context: fork | 子代理隔离上下文运行 | 沙箱验证/信息搜集/对比实验 |
| model | 指定模型 | 特殊需求 |
| paths | 限定适用路径 | 项目特定 |
| hooks | 生命周期钩子 | 自动化 |

### 何时禁用自动触发

```
有副作用的操作（危险）：
✅ 部署、提交、发消息、花钱
→ disable-model-invocation: true（只手动 /skill-name）
```

## 6. 进阶技巧清单

| 技巧 | 要点 |
|---|---|
| 每条指令挣位置 | 删掉不影响输出就删（竞争上下文） |
| 表格测试法 | 删一列丢含义才用表格，否则 KV 列表（查找任务 +8.8pp） |
| 错误写成正面指令 | "Use X"而非"Don't use Y" |
| 关键规则双位置 | 首因区 + 近因区换说法 |
| references 路由列表 | 防过度读取/跳过 |
| 参数化 | $ARGUMENTS 让技能可复用 |
| 版本化 | version 递增（改动留痕） |

## 7. 面试高频问法

| 问题 | 回答要点 |
|---|---|
| $ARGUMENTS 是什么？ | 斜杠调用的输入（$1/$2 位置取参） |
| CLAUDE_SKILL_DIR？ | 技能目录路径（引用配套必用） |
| U 形注意力？ | 首因/近因区放关键（双位置强调） |
| references 路由列表？ | 防过度读取与跳过 |
| 何时禁自动触发？ | 有副作用操作（部署/提交） |
| context: fork？ | 子代理隔离运行 |

### 面试加分表达

> "进阶技巧的核心是'管理注意力与加载'：U 形注意力决定布局（关键规则在首因区+近因区双位置强调）、references 路由列表控制按需加载（防过度读取或跳过）、$ARGUMENTS 和 CLAUDE_SKILL_DIR 让技能参数化可移植。安全上，有副作用的技能（部署/提交）必须 disable-model-invocation 只手动调用。"

> 🎯 核心要点：参数三件套（$ARGUMENTS/位置参/CLAUDE_SKILL_DIR）；反引号注入（动态但有风险）；U 形注意力（首因+近因双位置）；references 路由列表（何时读什么）；高级 frontmatter（disable-model-invocation/context: fork）；进阶清单七条（挣位置/表格测试法/正面指令）。

## 8. 常见误区

| 误区 | 真相 |
|---|---|
| "参数是必须的" | 多数技能不需要——按需加 |
| "反引号注入随便用" | 有执行风险——审查与限制 |
| "所有规则放开头" | U 形布局：首因+近因双位置 |
| "references 越多越好" | 路由列表控制加载（防过度读取） |
| "进阶技巧一步到位" | 先跑通再优化（最小可用优先） |
