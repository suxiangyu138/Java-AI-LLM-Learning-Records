## 1. 为什么叫新一代 npm

### npm 的类比

```
npm 做了什么：包的发布/安装/版本管理/依赖声明
Agent Skills 正在做同样的事：
技能 = 包 / Marketplace = 注册表 / 安装器 = npm install
```

| npm 概念 | 技能生态对应 |
|---|---|
| npm 包 | SKILL.md 技能 |
| npm registry | Marketplace |
| npm install | 平台安装器（Codex /skills 等） |
| 版本管理 | SKILL.md version（SemVer） |
| 依赖声明 | 技能依赖（脚本/工具/MCP） |

### 意义的深度

```
① 资产化：技能可发布/复用/交易（不是一次性提示词）
② 生态化：40 平台共享同一格式（跨生态流通）
③ 工程化：版本/依赖/安全（像软件一样治理）
——"新一代 npm"不是比喻，是事实
```

## 2. 三大 Marketplace

| 市场 | 规模 | 安全扫描 | 特点 |
|---|---|---|---|
| SkillsMP | 351K+ 技能 | 无 | 数量最多 |
| Skills.sh | 83K+ | 有（Snyk） | Vercel 出品、CLI 安装 |
| ClawHub | 约 3.2K | 强制审查 | 最精选（OpenClaw） |

### 选择逻辑

```
数量优先 → SkillsMP（351K）
安全优先 → Skills.sh（Snyk 扫描）/ ClawHub（强制审查）
精选优先 → ClawHub（小而精）
```

### 对比要点

```
① 规模与质量是权衡：越大越杂、越小越精
② 安全扫描是分水岭：Snyk 扫描 > 无扫描
③ 审查机制：ClawHub 强制审查最严
——下载前看安全（阶段 1 的 06 篇）
```

```

③ 大型库按需取（别全装）
```

## 4. 安全扫描生态

### 扫描的轻量性

```
技能元数据扫描：仅约 100 Token
激活时加载：不超 5K Token
——扫描成本极低（可常态化）
```

### 扫描与审查

```
① Snyk 扫描（Skills.sh）：自动化检测
② 人工审查（ClawHub）：强制
③ 安装前自审（阶段 1 的八项清单）
——三层安全网（市场/平台/个人）
```

### 安全现状

```
36% 社区技能有缺陷（ToxicSkills）：
无扫描市场（SkillsMP）风险最高
——选择有扫描的市场 = 第一道防线
```

## 5. 发布流程

### 发布步骤

```
① 完成技能（阶段 2/3 的方法）
② 跨平台测试（阶段 4 的 05 篇）
③ 版本化（SemVer）
④ 选市场（按安全/受众）
⑤ 上传/登记
⑥ 维护（issue/更新/版本）
```

### 发布清单

| 项 | 检查 |
|---|---|
| 规范合规 | 评分 ≥75（skill-test-skill） |
| 跨平台 | 至少两平台测试 |
| 安全 | 脚本审查 + allowed-tools |
| 文档 | description/使用说明 |
| 版本 | SemVer + changelog |

### 发布者的责任

```
① 质量：技能达到可发布标准
② 安全：脚本无缺陷（36% 的教训）
③ 维护：issue 响应/版本更新
④ 透明：能力边界写清楚
——发布技能 = 承担软件维护责任
```

## 6. 安装与使用

### 安装方式

| 方式 | 平台 | 说明 |
|---|---|---|
| CLI 安装器 | Codex /skills | 市场内安装 |
| 手动拷贝 | 通用 | 放 .agents/skills/ 等 |
| 分发工具 | 跨平台 | 自动分发多目录 |

### 安装后检查（阶段 1 的 06 篇）

```
① 来源可信（官方/知名作者）
② 脚本审查（逐行）
③ allowed-tools 生效（有配置）
④ 版本锁定（防漂移）
```

### 使用纪律

```
① 技能是依赖（像 npm 包——审查后使用）
② 版本升级要回归（技能更新 = 行为变化）
③ 不用就卸载（减少描述预算占用）
```

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "市场大就是好" | 351K 无扫描 = 风险最高 |
| "官方库不用审" | 相对可靠但仍要过目 |
| "安装即信任" | 像 npm install（审查依赖） |
| "发布就完事" | 维护责任（issue/版本） |
| "技能不用版本" | 依赖治理（SemVer 必要） |

| 问题 | 回答要点 |

| 三大市场？ | SkillsMP 数量/Skills.sh 扫描/ClawHub 精选 |

### 面试加分表达

> "Agent Skills 是'新一代 npm'：技能像包（SemVer 版本）、Marketplace 像 registry、安装器像 npm install。三大市场有明确权衡——SkillsMP 351K 无扫描、Skills.sh 83K 带 Snyk 扫描、ClawHub 3.2K 强制审查。我的选择逻辑是安全优先：有扫描的市场 + 官方库优先 + 安装前自审（36% 缺陷率的教训）。发布者要承担维护责任，不是传上去就完事。"

> 🎯 核心要点：新一代 npm（发布/安装/版本/依赖四对齐）；三大市场权衡（规模 vs 安全 vs 精选）；官方库优先（可信 + 教学）；扫描轻量（100 Token 可常态化）；发布流程 + 发布者责任；安装后审查纪律（像依赖治理）；安全三层（市场/平台/个人）。
