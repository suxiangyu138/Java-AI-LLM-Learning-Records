## 1. 组合模型回顾

### 三层组合（阶段 1 的 05 篇）

```
Skills（知识：怎么做）
Agent（身份：我是谁）
MCP 工具（能力：能做什么）
Commands（编排：固定流程）
```

### 组合的本质

```
技能指导"调哪些 MCP 工具、按什么顺序"
MCP 提供"实际执行能力"
——知识驱动能力（装配图 + 零件）
```

## 2. 组合实战模式

### 模式一：检索问答组合

```
技能：知识库问答流程（怎么写答案）
MCP 工具：检索/向量库工具
执行：技能指导 → 调检索工具 → 组装答案
```

### 模式二：Git 工作流组合

```
技能：提交规范流程（怎么提交）
MCP 工具：GitHub/Git 工具
执行：技能规则 → 调 git 工具 → 规范提交
```

### 模式三：数据处理组合

```
技能：数据处理流程（步骤）
MCP 工具：数据库/文件工具
执行：技能步骤 → 调工具 → 产出数据
```

### 组合原则

```
① 技能管"流程与规则"（判断）
② MCP 管"执行能力"（动作）
③ 别在技能里实现工具（引用即可）
```

## 3. 技能中的 MCP 引用

### 引用方式

```markdown
## 执行步骤
1. 调用 GitHub 工具获取 PR 信息（MCP: github）
2. 按审查规则分析
3. 输出问题清单
```

### 引用规范

```
① 写明工具名（Agent 知道调哪个）
② 写明用途（获取什么）
③ 写明输出（下一步用）
——技能与 MCP 的接口清晰
```

### allowed-tools 限定（Claude Code）

```yaml
allowed-tools:
  - read_file
  - mcp__github__get_pull_request   # 只允许特定 MCP 工具
```

## 4. 跨平台组合注意

### MCP 配置差异

```
各平台 MCP 配置位置不同：
.claude/settings.json / .codex/config.toml / ...
——技能引用 MCP 工具，但配置在平台层
```

### 跨平台策略

```
① 技能写"通用能力"（检索/提交/查询）
② MCP 工具按平台配置（实现差异平台处理）
③ 技能不绑定具体 MCP 服务器（可替换）
——技能与工具解耦（换工具不换技能）
```

### 降级处理

```
某平台没有对应 MCP 工具：
① 技能说明"无工具时的替代做法"（如手动步骤）
② 或提示缺少能力（不静默失败）
——组合要设计"降级路径"
```

## 5. 安全组合

### 安全边界

```
技能 + MCP 的安全组合：
① 技能层：allowed-tools 白名单（Claude）
② MCP 层：服务器权限（只读/范围）
③ 流程层：危险操作审批（HITL）
——三层边界（技能/工具/流程）
```

### 组合风险

```
① 技能滥用 MCP（调不该调的工具）
② MCP 工具被技能诱导（提示注入）
③ 跨平台白名单失效（降级）
——安全设计要覆盖组合场景
```

### 安全实践

```
① 技能 allowed-tools 限定 MCP 范围（可行平台）
② MCP 服务器最小权限（只读优先）
③ 危险 MCP 操作审批（HITL）
④ 跨平台测试降级（无白名单时）
```

## 6. 组合评估

### 组合的适用判断

```
组合的工作流示例（知识库问答 Agent）：
① 技能触发（用户问知识库问题）
② 技能指导调用检索工具（MCP）
③ 工具返回结果 → 技能规则组装答案
④ 输出带溯源的回答
——技能与 MCP 各司其职（判断 + 动作）
```

```
什么时候需要组合？
① 技能要执行外部操作（检索/提交/写库）→ 需要 MCP
② 技能只有知识无动作 → 不需要
③ 外部操作一次性的 → 直接调用（不必做技能）
——"有外部操作需求时组合是必需"
```

### 评估什么

```
① 组合是否生效（技能触发 → MCP 调用）
② 流程是否顺畅（工具结果被正确使用）
③ 降级是否可用（无工具时）
④ 安全边界是否守住
```

### 评估方法

```
跨平台测试矩阵 + 真实任务验收：
| 场景 | 技能触发 | MCP 调用 | 输出 |
| PR 审查 | ✅ | ✅ github | ✅ 清单 |
| 无工具平台 | ✅ | 降级手动 | ✅ 提示 |
```

### 组合的 ROI

```
组合的价值 vs 单独技能：
① 单独技能：只有知识（无法执行外部操作）
② 组合：知识 + 能力（完整闭环）
——有外部操作需求时组合是必需
```

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "技能里实现工具" | 技能引用工具（不实现） |
| "绑定特定 MCP" | 解耦（换工具不换技能） |
| "无工具也硬跑" | 设计降级路径（提示替代） |
| "白名单跨平台有效" | 部分平台降级（实测） |
| "组合不用评估" | 组合场景单独测（触发/调用/降级） |

## 8. 面试高频问法

| 问题 | 回答要点 |
|---|---|
| 组合模型？ | 技能知识 + MCP 能力 + Agent 身份 |
| 技能怎么引用 MCP？ | 写明工具名/用途/输出 |
| 跨平台组合注意？ | MCP 配置平台层（技能解耦） |
| 安全边界？ | 技能/工具/流程三层 |
| 降级设计？ | 无工具时替代做法或提示 |
| 组合评估？ | 触发/调用/降级/安全四测 |

### 面试加分表达

> "技能与 MCP 的组合是 Agent 能力的标准形态：技能管流程与规则（判断），MCP 管执行能力（动作），技能引用工具但不绑定——换工具不换技能。跨平台注意 MCP 配置在平台层（技能写通用能力），并设计降级路径（无工具时的替代做法）。安全三层：技能 allowed-tools、MCP 最小权限、危险操作审批。"

> 🎯 核心要点：组合 = 技能知识 + MCP 能力（装配图 + 零件）；引用规范（工具名/用途/输出）；跨平台解耦（技能不绑定 MCP）+ 降级路径；安全三层（技能白名单/MCP 权限/流程审批）；组合四测（触发/调用/降级/安全）；有外部操作需求时组合是必需。
