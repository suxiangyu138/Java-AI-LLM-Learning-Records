## 1. 目录碎片化问题

### 一个格式多个目录

```
.claude/skills/    # Claude Code
.codex/skills/     # Codex CLI
.github/skills/    # GitHub Copilot
.gemini/skills/    # Gemini CLI
.cursor/skills/    # Cursor
.opencode/skills/  # OpenCode
```

```
问题：同一份技能要放多个目录？
——碎片化（每工具一份拷贝 = 维护噩梦）
```

### 碎片化的代价

```
① 重复维护（改一处要同步 N 处）
② 版本漂移（各处版本不一致）
③ 安装复杂（每个工具单独拷）
——需要"一份技能多处可用"的机制
```

## 2. 通用总线：.agents/skills/

### 关键发现

```
每个 agent 都读取 .agents/skills/ 作为备援路径：
→ 该目录就是"通用总线"
→ 跨 agent 写技能就放那里
```

### 为什么是总线

```
.agents/skills/ 被所有工具读取（备援）：
放一份 → 所有工具都能发现
→ 解决碎片化（一份技能全平台）
```

### 使用

```
跨平台技能：
mkdir -p .agents/skills/my-skill/
（放一份，各工具都能读）
```

## 3. 跨 Agent 四条规则

### 规则一：只用核心 frontmatter

```
仅 name + description：
allowed-tools → 仅 Claude Code/OpenCode 支持
disable-model-invocation → 仅 Claude Code
——跨平台技能只用两个必填（其他会降级）
```

### 规则二：不写 agent 专属工具名

```
写"结果"而非"API"：
✅ 运行 `pnpm test`（通用命令）
❌ 使用 Bash 工具（agent 专属抽象）
——写人类可读的操作，不写工具名
```

### 规则三：项目根相对路径

```
绝不用绝对路径或 agent 配置目录结构：
✅ ./scripts/check.py（项目根相对）
❌ /home/user/.claude/...（绝对路径）
——可移植（任何环境都能跑）
```

### 规则四：至少在两个 agent 上测试

```
① Claude Code（功能最全，主测试）
② Codex 或 Gemini（第二验证）
——"能跑通常其他也能跑"但有例外（降级）
```

## 4. 专属字段的降级

### 降级机制

```
跨平台时专属字段静默降级：
allowed-tools：仅部分平台生效（其他忽略）
disable-model-invocation：仅 Claude
context: fork：仅 Claude
——不报错，但不生效（静默）
```

### 降级的风险

```
① 安全降级：allowed-tools 不生效 = 无白名单
   （Copilot 上安全敏感技能要小心）
② 行为降级：手动触发变自动（disable 失效）
③ 依赖降级：子代理/钩子缺失
```

### 处理策略

```
① 核心功能只用通用字段（name/description/正文）
② 专属能力做成"增强"（有则用，无则降级）
③ 降级验证：每个平台实测（不假设）
```

## 5. 安装方案

| 方案 | 做法 | 适用 |
|---|---|---|
| 通用总线 | 放 .agents/skills/（所有 agent 读） | **推荐** |
| Symlink | 标准位置加符号链接 | 简单立即可用 |
| 分发工具 | agent-skill-creator（14+ 目录自动分发） | 多平台 |

### 方案选择

```
个人跨平台 → .agents/skills/（主目录）
已有标准位置 → Symlink（迁移）
多工具维护 → 分发工具（自动化）
```

### 通用总线 + 分发

```
主目录 .agents/skills/ + 分发工具同步各平台目录：
一份源技能 → 自动分发 → 各工具可用
（对应"新一代 npm"的发布机制）
```

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "放各平台目录最稳" | 碎片化——用 .agents/skills/ 总线 |
| "专属字段没关系" | 静默降级（安全/行为风险） |
| "绝对路径没问题" | 可移植性杀手 |
| "测一个平台够" | 至少两个（降级验证） |
| "写工具名没问题" | 写"结果"（工具抽象各不同） |

## 8. 面试高频问法

| 问题 | 回答要点 |
|---|---|
| 目录碎片化？ | 六平台六个目录（重复维护） |
| .agents/skills/ 为什么是总线？ | 所有 agent 读取（备援路径） |
| 跨 Agent 四规则？ | 核心 frontmatter/通用写法/相对路径/双平台测 |
| 专属字段降级？ | 静默不生效（安全/行为风险） |
| 安装方案？ | 总线/Symlink/分发工具 |
| 测试策略？ | 主平台 + 第二验证 + 降级清单 |

### 面试加分表达

> "跨平台技能的关键是通用总线：每个 agent 都读 .agents/skills/ 作为备援，放一份所有工具都能发现——解决目录碎片化。四条规则：只用核心 frontmatter（专属字段静默降级）、不写 agent 专属工具名（写'结果'）、项目根相对路径、至少在两个 agent 测试。降级要实测不假设——Copilot 上 allowed-tools 不生效，安全敏感技能要小心。"

> 🎯 核心要点：目录碎片化（六目录）→ .agents/skills/ 通用总线（一份全平台）；跨 Agent 四规则（核心 frontmatter/通用写法/相对路径/双平台测）；专属字段静默降级（安全与行为风险）；安装三方案（总线/Symlink/分发工具）；测试矩阵（主平台 + 第二验证 + 降级清单）。
