# 05 与 MCP 工具的关系

> 最容易混淆的一对：MCP 暴露"能调用的工具"（functions），Agent Skills 打包"怎么用的知识"（know-how）——它们是互补的两层，不是替代关系；MCP 学习体系的"工具"与这里的"技能"组合成 Agent 的完整能力。

## 1. 核心区分：工具 vs 知识

```
MCP：暴露可调用的工具（functions）——"能做什么"
Agent Skills：打包使用知识（know-how）——"怎么做、何时做、按什么顺序"
```

### 一句话

| 维度 | MCP 工具 | Agent Skills |
|---|---|---|
| 回答 | 有什么能力 | 怎么用这些能力 |
| 类比 | 工具箱里的工具 | 工具的使用手册 |
| 加载 | 调用时执行 | 渐进式加载 |

### 类比

```
MCP 工具 = 扳手（一个函数，调用了就用）
Agent Skill = 修车手册（教你怎么用扳手完成维修）
技能可以引用工具：Skill 正文里写"调用 xxx 工具，按此顺序..."
```

## 2. 对比维度详解

| 维度 | MCP | Agent Skills |
|---|---|---|
| 形态 | 服务器 + 工具（JSON schema） | 文件夹 + SKILL.md |
| 协议 | MCP 协议（stdio/HTTP） | 开放文件格式（Markdown） |
| 内容 | 可执行函数 | 指令/步骤/知识 |
| 执行 | 运行时调用 | 上下文加载 |
| 加载策略 | 注册即用 | 渐进式披露 |
| 安全 | 服务器权限 | allowed-tools 限定 |
| 学习位置 | MCP学习体系 | 本体系 |

### 关键认知

```
一个技能可以用多个 MCP 工具：
Skill 说"先调 search 工具查资料，再调 write 工具写文档"
工具是零件，技能是装配图
```

## 3. 组合模式

### 标准组合（2026 实践）

```
Agent 的完整能力 = 工具（MCP）+ 知识（Skills）
Agent 定义 = 身份 + 技能引用 + 工具注册
```

```
用户任务
  → Agent 匹配 Skill（description）
  → Skill 正文指导执行（步骤）
  → 执行中调用 MCP 工具（函数）
  → 完成
```

### 组合示例（文档技能 + 工具）

```
Skill: doc-generator（知识：文档怎么写）
MCP 工具：filesystem（读写文件）、git（提交）
执行流程：
① Skill 正文：确认文档类型 → 读模板
② 调 filesystem 读模板文件
③ 按 Skill 规范写文档
④ 调 git 提交（如果 Skill 规定）
```

### 组合的价值

```
知识复用（Skill）+ 能力复用（MCP 工具）= 组件化
换工具不换技能（Skill 引用的工具可替换）
```

## 4. 三层架构：Skills / Agent / Commands

### 2026 实践的三层划分

| 层 | 承载 | 类比 |
|---|---|---|
| Skills | 领域知识（怎么做事） | 知识库 |
| Agent 定义 | 身份 + 技能引用 | 岗位 |
| Commands | 编排逻辑（流程） | 流程脚本 |

### 各层的职责

```
Skills：承载"任务知识"（何时用、怎么用）
Agent：承载"身份"和技能引用（我是谁、我会什么）
Commands：承载"编排逻辑"（固定流程的快捷指令）
```

### 三层关系

```
Agent 引用 Skills（身份绑定能力）
Commands 调用/组合 Skills（流程编排）
三层各司其职，避免"一个文件塞所有"
```

## 5. 实际工作流中的分工

### 场景：生成技术文档

```
① 用户要求 → Agent 的 description 匹配到 doc-generator 技能
② Skill 正文加载（L2）→ 指导流程
③ 流程中调用 MCP 工具（读模板/写文件/查规范）
④ 复杂流程由 Command 编排（多技能组合）
```

### 分工总结

| 环节 | 谁负责 |
|---|---|
| 识别任务 | description（Skill） |
| 指导执行 | 正文（Skill） |
| 实际执行 | 工具（MCP） |
| 固定流程 | Command |

## 6. 常见误区

| 误区 | 真相 |
|---|---|
| "Skill 替代 MCP" | 互补两层（知识 vs 工具） |
| "MCP 替代 Skill" | 工具没有"何时用"的知识 |
| "Skill 里写工具实现" | 技能引用工具，不实现工具 |
| "有 MCP 不需要 Skill" | 工具再多，没有使用知识也是堆零件 |
| "两者选一个学" | 双标准组合是 Agent 标配 |

## 7. 面试高频问法

| 问题 | 回答要点 |
|---|---|
| MCP 与 Skills 关系？ | 工具（functions）vs 知识（know-how），互补 |
| 技能能调 MCP 工具吗？ | 能——技能指导"调哪些工具、按什么顺序" |
| 三层架构？ | Skills（知识）/Agent（身份）/Commands（编排） |
| 组合模式？ | Agent 匹配技能 → 技能指导 → 工具执行 |
| 学了 MCP 还要学 Skill？ | 要——两者组合才是 Agent 完整能力 |

### 面试加分表达

> "MCP 和 Agent Skills 是互补的两层：MCP 给 Agent '能调用的工具'（functions），Skills 给'怎么用的知识'（know-how）——工具是零件，技能是装配图。标准组合是 Agent 匹配技能（description）、技能指导执行（正文）、执行调用 MCP 工具。加上 Commands 做编排，三层架构各司其职。"

## 8. 组合实现示例

### 技能引用 MCP 工具（正文写法）

```markdown
---
name: release-manager
description: 发布管理技能。用于版本发布时执行标准发布流程。
allowed-tools:
  - mcp:github
  - bash:read-only
---

# 发布管理

## 执行步骤
1. 调用 github 工具的 list_releases 查看当前版本
2. 按语义化版本规则确定新版本号
3. 调用 github 工具的 create_release 创建发布
4. 验证发布成功（list_releases 确认）

## 注意事项
- 发布前必须确认 changelog 完整
- 危险操作（删除 release）需人工确认
```

```
执行逻辑：
Skill 正文（知识）→ 指导调用 github MCP 工具（能力）
allowed-tools 限定：只能用 github 工具 + 只读 bash
```

### 组合的价值落地

```
① 知识封装：发布流程的"怎么发"在技能里
② 能力复用：github 工具通过 MCP 接入（不用重写）
③ 权限可控：allowed-tools 限定技能可用工具
```

## 9. 常见误区

| 误区 | 真相 |
|---|---|
| "技能内嵌工具实现" | 技能引用工具，不实现（MCP 负责） |
| "MCP 是技能的附属" | 两者独立标准，互补组合 |
| "有 Skill 就不用 MCP" | 技能没有"能做什么"（工具层缺失） |
| "有 MCP 就不用 Skill" | 工具堆零件，没有使用知识 |
| "组合 = 硬编码" | 技能引用的工具可替换（解耦） |

> 🎯 核心要点：MCP（functions）vs Skills（know-how）互补不替代；技能引用工具（零件 + 装配图）；三层架构（Skills 知识/Agent 身份/Commands 编排）；组合模式（匹配→指导→执行）；发布管理示例展示"知识指导 + 工具执行 + 权限限定"；双标准组合是 Agent 能力标配。
