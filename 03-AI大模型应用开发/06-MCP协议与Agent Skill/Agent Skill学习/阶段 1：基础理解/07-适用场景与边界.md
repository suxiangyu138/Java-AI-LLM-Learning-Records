# 07 适用场景与边界

> 不是所有知识都适合做成 Skill：有固定步骤、可复用、Agent 用得上的是甜区；一次性的、靠对话就能讲的、需要实时数据的要谨慎——判断口诀："可复用 × 有流程 × Agent 该会"。

## 1. 适合做 Skill 的特征

### 三个特征（缺一不可）

| 特征 | 说明 |
|---|---|
| 可复用 | 同一任务会多次发生 |
| 有流程 | 有明确的步骤/规范（不是纯闲聊） |
| Agent 该会 | 是"做事的知识"而非"对话技巧" |

### 特征详解

```
可复用：一次写、多次用（否则不值得打包）
有流程：步骤可编号、规范可描述（否则只是 prompt）
Agent 该会：让 Agent 更会做事（而非更会聊天）
```

## 2. 典型适用场景

| 场景 | 为什么适合 |
|---|---|
| 代码审查 | 固定检查项 + 规范（本仓库就有） |
| 文档生成 | 固定模板 + 写作规范 |
| 项目脚手架 | 固定结构 + 命令序列 |
| 部署流程 | 固定步骤 + 命令 |
| 领域规范执行 | 业务规则 + 检查清单 |
| 数据处理流程 | 固定处理步骤 |

### 场景的共同点

```
全是"有标准答案的流程"：
步骤固定 / 规范明确 / 可反复执行
```

## 3. 不适合的场景

| 场景 | 为什么不适合 |
|---|---|
| 一次性任务 | 打包成本 > 复用收益 |
| 纯对话技巧 | 那是 Prompt 工程的事 |
| 实时数据查询 | 该用工具（MCP）而非知识 |
| 高度个性化 | 每次都不一样，无固定流程 |
| 模型本就会的 | 通用知识不需要教 |

### 不适合的共同点

```
无固定流程 / 不可复用 / 模型已会 / 实时性要求
```

## 4. 判断决策树

```
这个知识要教 Agent？
├─ 任务会多次发生？
│   ├─ 否 → 别做（一次性）
│   └─ 是 ↓
├─ 有固定步骤/规范？
│   ├─ 否 → 是对话技巧 → Prompt 工程
│   └─ 是 ↓
├─ 是"做事的知识"？
│   ├─ 否 → 模型已会 → 别做
│   └─ 是 ↓
├─ 需要实时数据？
│   ├─ 是 → 用工具（MCP）
│   └─ 否 ↓
└─ ✅ 适合做 Skill
```

### 口诀

```
"可复用 × 有流程 × Agent 该会"——三问全是通过
实时数据 → MCP；对话技巧 → Prompt；一次性 → 别做
```

## 5. Skill 与 Prompt 工程的分工

| 维度 | Prompt 工程 | Agent Skills |
|---|---|---|
| 内容 | 对话行为（怎么说） | 任务流程（怎么做） |
| 形态 | 系统提示词 | 技能文件夹 |
| 复用 | 复制粘贴 | 打包加载 |
| 规模 | 短（几千 token） | 可大（配套文件） |
| 匹配 | 常驻 | description 触发 |
| 适合 | 角色/风格/通用行为 | 具体任务流程 |

### 分工原则

```
角色与风格 → Prompt（常驻，每任务都要）
任务流程 → Skill（按需，匹配才加载）
大而具体的知识 → Skill（渐进式披露承载）
```

## 6. 边界案例

### 案例 A：代码风格规范

```
做成 Skill？✅
理由：可复用（每个项目）、有流程（检查项）、Agent 该会
```

### 案例 B：天气查询

```
做成 Skill？❌（应该用 MCP 工具）
理由：实时数据——工具返回，不是知识
```

### 案例 C：面试答题技巧

```
做成 Skill？⚠️
理由：有流程（答题框架）可复用 → 可做
但偏对话技巧 → Prompt 更轻量
判断：看"是否多次需要完整流程"
```

### 案例 D：一次性迁移脚本

```
做成 Skill？❌
理由：一次性——写完即弃（脚本可以留，别打包成技能）
```

## 7. 面试高频问法

| 问题 | 回答要点 |
|---|---|
| 什么适合做 Skill？ | 可复用 × 有流程 × Agent 该会 |
| 什么不适合？ | 一次性/纯对话/模型已会/实时数据 |
| 与 Prompt 分工？ | 角色风格用 Prompt，任务流程用 Skill |
| 实时数据怎么办？ | 用 MCP 工具（不是知识） |
| 判断口诀？ | 三问 + 实时数据归工具 |

### 面试加分表达

> "判断一个知识适不适合做 Skill 用三问：任务会多次发生吗（可复用）？有固定步骤吗（有流程）？是做事的知识吗（Agent 该会）？三问全是通过才做。实时数据走 MCP 工具、对话技巧走 Prompt 工程——Skill 的甜区是'固定流程的任务知识'，这是它和工具、提示词的边界。"

## 8. 常见误区

| 误区 | 真相 |
|---|---|
| "什么都能做 Skill" | 三特征缺一不可（可复用/有流程/该会） |
| "Skill 越多越好" | 每个技能有维护与上下文成本 |
| "实时数据也做成 Skill" | 该用 MCP 工具（知识 vs 数据） |
| "通用知识值得打包" | 模型已会的别教（浪费） |
| "一次写好永久有效" | 流程变了要更新（版本管理） |

## 9. 判断练习

### 一句话定位总结

```
Skill 的甜区 = "固定流程的任务知识"
工具管"能做什么"（MCP）、提示词管"怎么说"（Prompt）、
技能管"怎么做"（Skill）——三者分工，别混层
```

### 技能规模与维护成本

```
每个技能都有成本（诚实清单）：
① 维护：流程变了要更新（版本管理）
② 上下文：L1 的 description 常驻（技能数 × description）
③ 质量：烂技能误导 Agent（比没有更糟）
④ 安全：每个技能都是攻击面（审查成本）
规模建议：
起步 3-5 个高质量技能（别贪多）
成熟后按领域组织（阶段 5 治理）
```

### 与 Prompt 工程的组合实践

```
同任务可分层：
角色行为 → Prompt（常驻）
任务流程 → Skill（按需）
实时能力 → MCP 工具
例：代码审查
Prompt：审查者的角色与语气
Skill：审查步骤与检查项
MCP：git 只读工具
三层各司其职——不把所有东西塞进一层
```

对以下场景判断：做 Skill / 用 MCP / 用 Prompt / 别做？

| 场景 | 判断 | 理由 |
|---|---|---|
| 数据库查询接口 | MCP 工具 | 实时数据 + 可调用函数 |
| 周报生成流程 | ✅ Skill | 可复用 + 有流程 |
| 系统提示词（角色设定） | Prompt | 常驻对话行为 |
| 一次性数据清洗 | 别做 | 一次性 |
| 代码提交规范检查 | ✅ Skill | 可复用 + 固定检查项 |
| 通用数学解释 | 别做 | 模型已会 |
| 天气查询 | MCP 工具 | 实时数据 |
| 项目初始化脚手架 | ✅ Skill | 固定结构 + 命令序列 |

**练习价值**：形成"下意识判断"——先问三特征，再分工具/Prompt/技能。

> 🎯 核心要点：适合三特征（可复用/有流程/Agent 该会）；不适合四类（一次性/纯对话/模型已会/实时数据）；分工（角色风格 Prompt、任务流程 Skill、实时数据 MCP）；判断决策树 + 口诀；八连判断练习校准直觉；边界案例四则加深理解。
