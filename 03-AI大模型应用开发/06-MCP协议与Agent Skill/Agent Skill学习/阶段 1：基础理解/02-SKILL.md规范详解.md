## 1. 目录结构

```
my-skill/
├── SKILL.md          # 必需：元数据（YAML frontmatter）+ 使用说明
├── scripts/          # 可选：可执行代码
├── references/       # 可选：参考资料和文档
└── assets/           # 可选：模板、资源、schema
```

| 文件/目录 | 必需 | 用途 |
|---|---|---|
| SKILL.md | ✅ | 技能入口（元数据 + 指令） |
| scripts/ | 可选 | 可执行代码（脚本/程序） |
| references/ | 可选 | 详细参考资料 |
| assets/ | 可选 | 模板/资源/schema |

> 最小技能 = 一个 SKILL.md 文件；复杂技能 = 文件夹多文件。

## 2. YAML frontmatter 必填字段

### 两个必填字段

```markdown
---
name: my-skill
description: 创建高密度 Markdown 技术文档。用于需要生成学习笔记、
  技术文档、知识体系时。包含文档结构模板与写作规范。
---
```

| 字段 | 规则 | 说明 |
|---|---|---|
| name | 必填，≤64 字符，仅小写字母/数字/连字符 | **必须与父目录名一致** |
| description | 必填，≤1024 字符 | 说明"做什么"和"何时使用" |

### description 的重要性（触发匹配）

```
description 是 Agent 判断"这个技能适不适合当前任务"的唯一依据：
① 写清做什么（动词开头）
② 写清何时用（触发场景）
③ 含丰富触发关键词（匹配更容易）
④ 别写"如何使用"（那是正文的事）
```

## 3. 可选字段

| 字段 | 说明 |
|---|---|
| license | 许可协议（分发合规） |
| compatibility | 兼容性说明（≤500 字符） |
| metadata | 自定义元数据 |
| allowed-tools | **限定技能可调用的工具范围**（安全） |
| version | 版本号 |

### allowed-tools（安全重点）

```yaml
---
name: safe-doc-skill
description: 文档处理技能
allowed-tools:
  - read_file
  - write_file
  - bash:read-only    # 只读命令
---
```

```
意义：限定技能只能用指定工具（最小权限）
防：技能脚本调用危险工具（如删除命令）
对应"工具白名单"安全思想
```

## 4. 正文规范

### 正文要求

| 规范 | 说明 |
|---|---|
| 行数 | 建议 ≤500 行（约 5000 tokens） |
| 内容 | Agent 读取的操作指令 |
| 拆分 | 详细内容放 references/ 等配套文件 |

### 编写建议（官方实践）

| 建议 | 例子 |
|---|---|
| 步骤用编号 | 1. 2. 3.（明确执行顺序） |
| 代码给确切模板 | 完整代码而非描述 |
| 大体积数据放文件 | 模板/数据进 assets/（不塞正文） |
| description 丰富触发词 | 覆盖各种问法 |

### 正文结构示例

```markdown
# 文档生成技能

## 何时使用
- 用户要求生成学习笔记/技术文档
- 需要按仓库规范输出 Markdown

## 执行步骤
1. 确认文档类型（知识体系/单篇笔记/速记）
2. 读取对应模板（assets/templates/）
3. 按写作规范填充内容
4. 自检（围栏/锚点/表格）

## 注意事项
- 代码块必须标注语言
- 结尾附参考来源
```

## 5. 发现路径

### 三级优先级

| 优先级 | 路径 | 范围 |
|---|---|---|
| 1 | 项目级 `.claude/skills/` 或 `.github/skills/` | 当前项目 |
| 2 | 用户级 `~/.claude/skills/` | 当前用户 |
| 3 | 插件级 | 随插件包分发 |

```
发现逻辑：项目级优先（项目特定技能）→ 用户级（个人技能）→ 插件级（生态技能）
同名冲突：优先级高的覆盖
```

### 发现与加载的分离

```
发现：启动时扫描路径（只读 L1 元数据）
加载：任务触发时读正文（L2）
执行：按需读配套（L3）
（渐进式披露——03 篇详述）
```

## 6. 命名与组织规则

### 命名规则

```
name 规则：
① 小写字母/数字/连字符（kebab-case）
② ≤64 字符
③ 与父目录名一致
例：my-skill / code-review / doc-generator
```

### 组织建议

```
技能库组织（阶段 5 详述）：
按领域分目录：/docs /code /ops
命名语义化：动词-对象（generate-doc / review-code）
版本管理：技能随代码库进 git
```

## 7. 面试高频问法

| 问题 | 回答要点 |
|---|---|
| Skill 目录结构？ | SKILL.md 必需 + scripts/references/assets 可选 |
| frontmatter 必填？ | name（≤64，与目录一致）+ description（≤1024） |
| description 为什么重要？ | 任务匹配的唯一依据（触发词） |
| allowed-tools？ | 限定工具范围（最小权限安全） |
| 正文行数限制？ | ≤500 行（约 5000 tokens），细节拆配套文件 |
| 发现路径？ | 项目级 → 用户级 → 插件级 |

### 面试加分表达

> "SKILL.md 的设计核心是'元数据与内容分离'：frontmatter 只有 name 和 description 两个必填——description 是 Agent 匹配任务的唯一依据，所以要写触发场景和关键词；正文限制 500 行，细节拆到 references/assets。加上 allowed-tools 做最小权限，整个规范就是为'可发现、可加载、可安全执行'设计的。"

## 8. 完整示例与易错点

### 最小完整示例

```markdown
---
name: doc-generator
description: 生成学习向 Markdown 技术文档。用于需要创建学习笔记、
  技术文章、知识体系文档时。按仓库规范输出高密度、表格优先的文档。
license: MIT
allowed-tools:
  - read_file
  - write_file
---

# 文档生成技能

## 何时使用
- 用户要求生成/整理技术文档
- 需要按知识库规范输出

## 执行步骤
1. 确认文档类型（知识体系/单篇笔记/速记）
2. 读取模板（assets/templates/）
3. 按规范填充内容
4. 自检（围栏/锚点/表格）
```

### 易错点

| 易错 | 后果 | 修正 |
|---|---|---|
| name 与目录不一致 | 无法被发现 | 保持一致 |
| description 写"如何使用" | 匹配失效 | 写"做什么/何时用" |
| 正文超长 | L2 加载过重 | ≤500 行，拆配套 |
| 省略 allowed-tools | 技能可调任何工具 | 最小权限 |
| 大文件塞正文 | 渐进式披露失效 | 放 assets/ |

## 9. 常见误区

| 误区 | 真相 |
|---|---|
| "frontmatter 字段越多越好" | 必填只有 name/description，其余按需 |
| "正文越详细越好" | 500 行上限——细节拆配套 |
| "目录名随便" | 必须与 name 一致（发现依赖） |
| "description 一句话够" | 触发匹配靠它——写场景与关键词 |
| "allowed-tools 可选可不选" | 安全必配（06 篇） |

> 🎯 核心要点：SKILL.md = frontmatter（name/description 必填）+ 正文（≤500 行）；description 是匹配钥匙（触发词）；allowed-tools 最小权限；发现路径三级（项目/用户/插件）；命名 kebab-case 与目录一致；正文规范（编号步骤/确切代码/大文件拆出）；五个易错点 + 完整示例直接可抄。
