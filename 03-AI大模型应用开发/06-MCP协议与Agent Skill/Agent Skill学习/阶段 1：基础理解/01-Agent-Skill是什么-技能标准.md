## 1. Agent Skills 的定义

| 维度 | 说明 |
|---|---|
| 是什么 | 把任务知识打包为可移植 SKILL.md 文件夹的开放标准 |
| 发起方 | Anthropic（2025-10-16 发布，2025-12-18 开放标准） |
| 维护 | agentskills.io 社区共同维护 |
| 状态 | 2026-05-27 复审进入 "established"（成熟）阶段 |
| 核心文件 | SKILL.md（frontmatter 元数据 + 使用说明） |
| 本质 | 给 Agent 的"技能说明"——何时用、怎么用、按什么顺序 |

一句话定义：

> Agent Skills 是一个**工具无关的开放标准**，把完成某类任务的知识（步骤、脚本、参考资料）打包进一个标准文件夹，让任何兼容的 AI 编码工具（Claude Code/Codex/Gemini CLI/Copilot 等）按需发现和加载。

## 2. 解决的痛点

### 模型的能力边界

```
模型天生会的：语言理解、代码生成、通用推理
模型不会的：你的业务规范、你的工具用法、你的流程顺序
```

### 传统方式的缺陷

| 方式 | 缺陷 |
|---|---|
| 全塞进 system prompt | 上下文爆炸、互相干扰 |
| 每次对话口头解释 | 不可复用、易遗漏 |
| 写在项目文档里 | Agent 不知道何时该读 |

### Skill 的解法

```
把知识打包 → 可发现（description 匹配）→ 按需加载（渐进式披露）
→ 可复用（跨项目）→ 可移植（跨工具）
```

## 3. 起源与开放标准化

| 时间 | 事件 | 意义 |
|---|---|---|
| 2025-10-16 | Anthropic 企业级发布 Agent Skills | "Equipping agents for the real world" |
| 2025-12-18 | 以开放标准形式发布规范 | 从产品功能走向行业标准 |
| 2025-12-22 | 正式开放该标准 | 第三方可自由实现 |
| 2026-05-27 | 复审进入 established 阶段 | 标准成熟 |

### 为什么开放

```
Anthropic 的选择：把技能格式开放为行业标准
（类似 MCP 的开放路线——生态共赢）
收益：40+ 平台采用 → 技能一次编写到处运行
```

## 4. 与 Prompt / 工具 / MCP 的区别

| 维度 | Prompt 工程 | 工具（MCP） | Agent Skills |
|---|---|---|---|
| 内容 | 对话指令 | 可调用函数 | **任务知识（know-how）** |
| 回答什么 | "怎么说" | "能做什么" | **"怎么做、何时做、按什么顺序"** |
| 形态 | 文本 | API/函数 | 文件夹（md+脚本+资源） |
| 加载 | 全量 | 调用时 | 渐进式（三级） |
| 复用 | 复制粘贴 | 注册调用 | 打包复用 |
| 跨工具 | 否 | MCP 标准 | **开放标准（40+ 平台）** |

### 三者关系（关键认知）

```
Prompt：告诉 Agent 怎么说话
工具（MCP）：给 Agent 能用的手
Skill：教 Agent 怎么用手做事（含工具的使用方法）
```

## 5. 心智模型：给 Agent 的上岗手册

```
想象新员工入职：
① 简历（description）：他会什么——用于匹配任务
② 上岗手册（SKILL.md）：具体怎么做事——用到才看
③ 工具手册（scripts/references）：细节——需要时翻

Agent Skills = 这套"入职体系"的标准格式
```

### 心智模型的意义

```
理解这个类比，后面全顺：
匹配靠 description（简历）
执行靠正文（手册）
细节靠配套文件（工具手册）
加载靠渐进式披露（用到才看，不浪费注意力）
```

## 6. 面试高频问法

| 问题 | 回答要点 |
|---|---|
| Agent Skills 是什么？ | 任务知识打包为 SKILL.md 的开放标准 |
| 谁发起的？ | Anthropic（2025-10 发布，2025-12 开放） |
| 解决什么痛点？ | 模型不懂业务知识——可复用可移植的技能包 |
| 与 Prompt 区别？ | Prompt 是"怎么说"，Skill 是"怎么做" |
| 与 MCP 区别？ | MCP 是可调用工具，Skill 是使用知识（互补） |
| 为什么开放？ | 生态共赢（40+ 平台采用，一次编写到处运行） |

### 面试加分表达

> "Agent Skills 的本质是'任务知识的结构化打包'：模型天生会推理但不会你的业务，Skill 用标准文件夹（SKILL.md）把'何时用、怎么用、按什么顺序'装进去。它的三个关键设计——开放标准（40+ 平台可移植）、渐进式披露（省上下文）、与 MCP 互补（工具 vs 知识）——让它成为 Agent 能力扩展的标配。"

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "Skill 就是 Prompt" | Prompt 是"怎么说"，Skill 是"怎么做"（含流程与脚本） |
| "Skill 就是脚本" | 脚本是零件，Skill 是"脚本+使用说明"的打包 |
| "只能 Claude 用" | 开放标准——40+ 平台 |
| "必须写代码" | 纯知识技能（SKILL.md）也行 |
| "技能越多越好" | 有成本——渐进式披露缓解但不免费 |
| "社区技能直接信" | 36% 有缺陷——必须审查（06 篇） |

## 8. 经典应用场景

| 场景 | Skill 的姿势 |
|---|---|
| 代码审查 | 固定检查项 + 规范 + 命令 |
| 文档生成 | 模板 + 写作规范 + 自检清单 |
| 项目脚手架 | 目录结构 + 命令序列 |
| 部署流程 | 步骤 + 检查 + 回滚 |
| 领域规范 | 业务规则 + 检查清单 |
| 数据处理 | 固定处理流程 + 脚本 |

### 与本仓库技能体系的关系

```
本仓库已有大量"技能实践"可以对照：
- .claude/skills/ 下的技能（markdown-doc-generator 等）
- 各知识体系的"自检/校验"技能（doc-quality 等）
看它们 = 看 SKILL.md 的实战案例（frontmatter/正文/配套）
阶段 2 将带你从"用技能"走向"写技能"
```

### 场景落地骨架（代码审查）

```
① description：审查代码改动，用于提交前/PR 时
② 正文：检查项（正确性/边界/安全）→ 输出格式
③ 配套：检查清单模板（references/）
④ allowed-tools：read 类 + git 只读
```

> 🎯 核心要点：Agent Skills = 任务知识打包为可移植 SKILL.md 的开放标准（Anthropic 发起，2025-12 开放，40+ 平台采用）；解决"模型不懂业务知识"的痛点；与 Prompt（怎么说）/MCP（能做什么）互补——Skill 是"怎么做"；心智模型 = 给 Agent 的上岗手册（简历/手册/工具手册三级）；六个误区 + 代码审查骨架校准认知。
