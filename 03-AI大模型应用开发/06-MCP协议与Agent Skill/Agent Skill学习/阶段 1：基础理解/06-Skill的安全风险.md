## 1. 为什么技能有安全风险

### 技能的本质

```
技能 = 指令 + 脚本 + 资源
Agent 加载后"按技能说的做"——技能内容就是指令来源
```

### 风险根源

```
① 技能可含脚本（scripts/）——可执行代码
② SKILL.md 正文是"指令"——可诱导 Agent 行为
③ 技能来自社区（第三方）——来源不可信
④ Agent 会"信任"技能（像信任工具）
```

### 对比软件依赖

```
安装 Python 包：审查依赖、锁版本、扫描漏洞
安装技能：同样需要审查——但目前生态审查更少
```

## 2. ToxicSkills 审计数据

### 2026-02 Snyk 审计

```
扫描范围：3,984 个技能
发现：36% 至少存在一个安全缺陷
风险集中：社区发布的技能
```

### 缺陷类型

| 类型 | 说明 |
|---|---|
| 危险脚本 | scripts/ 含恶意/危险代码 |
| 敏感信息 | 技能内嵌密钥/凭据 |
| 指令注入 | SKILL.md 诱导危险操作 |
| 依赖风险 | 引用不安全的依赖 |

### 审计的启示

```
36% 的缺陷率 = 技能生态的"供应链风险"
安装第三方技能 = 引入潜在恶意代码（与 pip install 同理）
```

## 3. 攻击面：隐藏指令劫持

### 攻击原理

```
攻击者构造 SKILL.md：
① description 写得"人畜无害"（能通过匹配）
② 正文隐藏恶意指令（诱导 Agent 执行危险操作）
③ Agent 加载正文 → 按指令执行 → 被劫持
```

### 攻击链条

```
用户安装恶意技能
  → 任务触发技能（description 匹配）
  → 正文隐藏指令加载
  → Agent 执行恶意指令（如读取密钥/执行危险命令）
  → 数据泄露/系统受损
```

### 为什么难防

```
① 正文是"给 Agent 的指令"——难以程序化区分好坏
② description 可伪装（匹配层看不出恶意）
③ Agent 对技能内容的信任（工具式信任）
```

## 4. 风险场景分类

| 场景 | 风险 |
|---|---|
| 社区技能 | 恶意/缺陷脚本 |
| 供应链 | 技能依赖的库/服务 |
| 提示注入 | 技能内容诱导 |
| 数据泄露 | 技能读取敏感文件 |
| 权限滥用 | 技能调用危险工具 |

### 风险等级

| 等级 | 场景 |
|---|---|
| 高 | 含脚本的社区技能、隐藏指令 |
| 中 | 引用外部服务的技能 |
| 低 | 纯知识技能（无脚本无外部） |

## 5. 防御清单

### 安装前审查（像审查依赖一样）

| 审查项 | 说明 |
|---|---|
| 来源可信 | 官方库（anthropics/skills）/知名作者 |
| 脚本审查 | 读 scripts/ 每个文件（别只信描述） |
| 依赖审查 | 技能引用的库/服务是否可信 |
| 权限最小化 | allowed-tools 限定（下节） |
| 版本锁定 | 固定技能版本（防漂移） |
| 敏感信息 | 检查是否内嵌密钥 |

### 运行中防御

```
① allowed-tools 白名单（技能只能用指定工具）
② 危险操作人审（技能触发高危动作前确认）
③ 沙箱/只读模式（实验技能）
④ 审计日志（技能执行留痕）
```

### 组织级（阶段 5 详述）

```
技能仓库治理：内部技能库（审核后发布）
CI 扫描：技能入库前自动检查
黑白名单：允许/禁止的技能列表
```

## 6. 安全设计：allowed-tools

### 机制回顾（02 篇）

```yaml
---
name: safe-skill
description: 文档处理技能
allowed-tools:
  - read_file
  - write_file
---
```

### 价值

```
限定技能可调用的工具范围（最小权限）：
恶意/缺陷技能即使加载，也只能用白名单工具
→ 攻击面收窄（工具层的第二道防线）
```

### 设计原则

| 原则 | 说明 |
|---|---|
| 最小权限 | 只给任务必需的工具 |
| 只读优先 | 能只读不写 |
| 危险工具默认拒绝 | 删除/执行/网络默认不给 |
| 与 HITL 组合 | 高危操作人审 |

## 7. 面试高频问法

| 问题 | 回答要点 |
|---|---|
| 技能有什么安全风险？ | 可执行脚本 + 指令内容 + 第三方来源 |
| ToxicSkills 数据？ | 3984 个技能 36% 有缺陷（2026-02） |
| 隐藏指令劫持？ | description 伪装 + 正文藏恶意指令 |
| 怎么防御？ | 来源审查/脚本审查/allowed-tools/人审 |
| allowed-tools 作用？ | 最小权限（工具白名单） |
| 安装技能像什么？ | 像审查软件依赖（供应链风险） |

### 面试加分表达

> "技能安全是'供应链风险'：ToxicSkills 审计 3984 个技能 36% 有缺陷，还有 description 伪装 + 正文藏指令的劫持攻击。防御分三层：安装前审查（来源/脚本/依赖，像审软件依赖）、运行中限制（allowed-tools 最小权限 + 危险操作人审）、组织治理（内部技能库审核 + CI 扫描）。"

## 8. 安全审查清单模板

### 安装前审查（逐项核对）

| 审查项 | 检查 | ✅ |
|---|---|---|
| 来源 | 官方库/知名作者/可信渠道 | ☐ |
| 描述与实现一致 | 正文没做 description 没提的事 | ☐ |
| 脚本逐行读 | scripts/ 每个文件（无恶意/危险命令） | ☐ |
| 隐藏指令 | 正文无诱导性指令（读取密钥/外传数据） | ☐ |
| 依赖 | 引用的库/服务可信 | ☐ |
| 敏感信息 | 无内嵌密钥/凭据 | ☐ |
| allowed-tools | 已限定最小工具范围 | ☐ |
| 版本 | 可锁定（防上游漂移） | ☐ |

### 运行时防御（配置核对）

```
① allowed-tools 生效（技能只能用白名单）
② 危险操作人审（删除/写库/外发前确认）
③ 审计日志（技能执行留痕）
④ 敏感数据脱敏（日志不含密钥）
```

## 9. 常见误区

| 误区 | 真相 |
|---|---|
| "官方库绝对安全" | 相对可靠，仍需审查（36% 是社区为主） |
| "只看 description 就行" | 必须读正文与脚本 |
| "allowed-tools 可后补" | 从第一天就配（最小权限） |
| "纯知识技能没风险" | 正文可藏指令（隐藏劫持） |
| "技能不更新就安全" | 依赖/环境变化引入新风险（定期复查） |

> 🎯 核心要点：技能 = 可执行指令（有供应链风险）；ToxicSkills 36% 缺陷率；隐藏指令劫持（description 伪装 + 正文藏指令）；防御三层（安装审查/运行限制/组织治理）；八项审查清单直接可用；allowed-tools 最小权限是工具层第二道防线；安装技能 = 审查软件依赖。
