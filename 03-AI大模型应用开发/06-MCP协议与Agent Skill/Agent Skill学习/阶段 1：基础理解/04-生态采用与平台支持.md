## 1. 采用全景

### 2026 年采用状态

```
约 40 个平台支持 Agent Skills 标准（2026 初）
覆盖：AI 编码工具、IDE、云平台、Agent 框架
```

| 类别 | 平台 |
|---|---|
| Anthropic 系 | Claude Code、Claude.ai、Anthropic API |
| OpenAI 系 | Codex、ChatGPT |


## 3. 跨工具可移植性

### 可移植性的含义

```
技能 = 平台无关的文件夹（SKILL.md + 配套）
同一技能可在不同工具加载执行（若平台实现标准）
```

### 确认口径（重要）

```
跨工具可移植性仅对"已发布实现文档"的工具获得确认
——不是所有号称支持的工具都完整实现标准
选技能/写技能时：确认目标平台的实现程度
```

### 可移植性的价值

| 价值 | 说明 |
|---|---|
| 资产复用 | 技能库一次编写多处运行 |
| 团队迁移 | 换工具不换技能 |
| 生态共享 | 社区技能直接使用 |
| 降低锁定 | 不被单一工具绑定 |

## 4. 为什么能成为标准

### 标准的要素（与 MCP 对比）

| 要素 | Agent Skills | MCP |
|---|---|---|
| 发起 | Anthropic | Anthropic |
| 开放 | 2025-12 | 开放 |
| 采用 | 40+ 平台 | 广泛 |
| 定位 | 任务知识格式 | 工具协议 |
| 竞争 | 无强对手 | 部分竞争（A2A 等） |

### 成功原因

```
① 简单：一个文件夹 + 一个 md（门槛极低）
② 解决真痛点：任务知识标准化（谁都缺）
③ 发起方让利：开放为行业标准（生态共赢）
④ 与 MCP 互补：不冲突（工具 vs 知识）
⑤ 渐进式披露：技术上优雅（不爆上下文）
```

## 5. 生态启示

### 对开发者的意义

```
① 技能是资产：按标准写 = 长期可复用
② 平台选择：支持标准与否是选型因素
③ 社区红利：40+ 平台生态的技能库
④ 双标准组合：MCP（工具）+ Skills（知识）是 Agent 标配
```

### 生态趋势（2026）

```
Agent 能力扩展的标准组合：
MCP = 工具的 HTTP 标准
Agent Skills = 知识的 Markdown 标准
工具与知识分离 → 生态可独立发展
```

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "所有平台支持程度一样" | 实现有差异——查文档确认 |
| "官方库技能都安全" | 官方库可靠些，但仍要审查（36% 数据） |
| "40 平台 = 全部功能一致" | 可移植性对"已发布实现文档"确认 |
| "标准会一直不变" | 演进中（2026-05 established）——关注更新 |
| "写一次处处完美运行" | 跨工具要测试（各平台实现差异） |

## 8. 生态版图与选择建议

### 生态版图

```
发起方：Anthropic（Claude Code 原生）
大厂采用：OpenAI（Codex/ChatGPT）、Google（Gemini CLI）、微软（Copilot）
IDE：Cursor/VS Code/JetBrains Junie
框架/云：Snowflake Cortex Code/OpenCode/Kiro
社区：anthropics/skills + 第三方技能库
```

### 平台选择建议

| 需求 | 选择 |
|---|---|
| 标准原生体验 | Claude Code（发起方实现最全） |
| OpenAI 生态 | Codex/ChatGPT |
| Google 生态 | Gemini CLI |
| 微软/企业 | Copilot |
| 多平台复用 | 按标准写技能（可移植） |

### 技能作者的策略

```
① 按标准写（不绑定平台特性）
② 在主流平台测试（Claude Code + 一个其他）
③ 跨工具验证可移植性
④ 关注标准更新（established 阶段仍演进）
```

> 🎯 核心要点：约 40 平台采用（Anthropic/OpenAI/Google/微软/IDE 全覆盖）；可移植性红利（一次编写到处运行，但要确认平台实现）；成为标准五因（简单/真痛点/开放/与 MCP 互补/渐进式披露）；生态趋势 = MCP（工具）+ Skills（知识）双标准组合；技能作者策略（按标准写 + 多平台测试 + 关注演进）。
