## 1. references 的定位

### 装什么

```
references/ = 不需要每次读的深度知识：
① 边界情况细节
② 深度背景/原理
③ 大表格/长列表
④ 具体操作手册
```

### 与渐进式披露的关系

```
references 是 L3（按需加载）：
正文（L2）说"什么时候读哪个文件"
文件本身（L3）读到才进上下文
——references 组织 = 控制 L3 的加载效率
```

### 组织目标

```
让 Agent"读得准、读得少"：
读得准：指针明确（读哪个文件）
读得少：只读需要的（不整目录扫描）
```

## 2. JIT 指针：明确告诉何时读

### 什么是 JIT 指针

```
在 SKILL.md 正文中明确写：
"遇到 XXX 情况时，先读 references/xxx.md"
——不模糊地说"参考文档"，而是精确指路
```

### 好与坏对比

```markdown
# 坏（模糊）
## 参考资料
- references/edge-cases.md
- references/style.md

# 好（JIT 指针）
## 执行步骤
1. 生成文档主体
2. 若涉及表格转换，读 references/table-rules.md
3. 若输出不达标，读 references/常见错误.md
```

### 指针三要素

| 要素 | 例子 |
|---|---|
| 触发条件 | 若涉及表格转换 |
| 明确文件 | references/table-rules.md |
| 读取目的 | 处理表格规则 |

## 3. 一层深度原则

### 为什么一层

```
链式嵌套的问题：
SKILL.md → advanced.md → details.md
Agent 可能只部分预览嵌套文件（深层易跳过）

一层深度：
SKILL.md → references/edge-cases.md（直接可达）
```

### 组织方法

```
所有引用文件直接放 references/ 根（或一层子目录）：
✅ references/edge-cases.md
✅ references/style/overview.md（一层子目录可接受）
❌ references/a.md → 引 b.md → 引 c.md（链式）
```

### 判断标准

```
从 SKILL.md 出发，一跳能到 = 可接受
需要两跳以上 = 拆平或合并
```

## 4. 大文件组织

### 超过 100 行的引用文件

```
加目录（文件内）：
# 边界情况
- 1. 编码问题
- 2. 特殊字符
- 3. 平台差异
——Agent 可跳读（不用整读）
```

### 大文件拆分

```
超过几百行 → 按主题拆多个小文件：
references/
├── edge-cases.md       # 边界情况
├── style-guide.md      # 风格
└── platform-notes.md   # 平台差异
——每个文件一个主题（路由更准）
```

### 加载控制

```
指针粒度 = 文件级（不是目录级）：
让 Agent 读 references/edge-cases.md
而不是"读 references/ 目录"
——目录级扫描 = 全部加载（渐进式披露失效）
```

## 5. Defer to --help 模式

### 是什么

```
SKILL.md 只列 80% 的常用操作：
其余告诉 Agent 运行 tool --help（按需获取）
```

### 示例

```markdown
## 常用操作
- 生成文档：python gen.py --type note 主题
- 校验：python check.py 文件.md

## 完整参数
运行 `python gen.py --help` 查看全部参数
```

### 价值

```
① SKILL.md 保持精简（不列全参数）
② 细节按需获取（--help 触发时）
③ 工具自身文档维护（不复制到 SKILL.md）
```

## 6. 路由列表设计

### 路由列表（回顾阶段 2 的 07 篇）

```markdown
## 参考资料（按需读取）
| 文件 | 内容 | 何时读 |
|---|---|---|
| references/表格规则.md | 表格转换细节 | 涉及表格时 |
| references/常见错误.md | 易错点清单 | 输出不达标时 |
| references/风格指南.md | 风格细节 | 风格不确定时 |
```

### 路由列表三要素

| 要素 | 作用 |
|---|---|
| 文件 | 明确路径（一层深度） |
| 内容 | 一句话说明（判断相关） |
| 何时读 | 触发条件（JIT 指针） |

### 路由的价值

```
① 防过度读取（何时读明确）
② 防跳过（列出来提醒存在）
③ 控制加载（L3 按需）
```

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "references 越多越好" | 每个引用是加载负担（只留必要） |
| "说'参考文档'就行" | 要 JIT 指针（何时读哪个） |
| "嵌套没问题" | 一层深度（深层易跳过） |
| "目录级读取" | 文件级指针（防全加载） |
| "--help 是偷懒" | 是精简与维护的正道 |

## 8. 面试高频问法

| 问题 | 回答要点 |
|---|---|
| references 装什么？ | 不需要每次读的深度知识 |
| JIT 指针？ | 明确"何时读哪个文件" |
| 一层深度？ | 防嵌套跳过（一跳可达） |
| 大文件怎么处理？ | 加目录/按主题拆分 |
| --help 模式？ | SKILL.md 只列常用，细节 help |
| 路由列表？ | 文件+内容+何时读 |

### 面试加分表达

> "references 的组织目标是'读得准、读得少'：JIT 指针在正文里精确写'遇到 X 读 references/Y.md'，而不是模糊说参考文档；保持一层深度（链式嵌套 Agent 会跳过）；超 100 行加目录、超几百行按主题拆文件。配合 --help 模式（SKILL.md 只列 80% 常用）和路由列表（文件+内容+何时读），L3 加载完全可控。"

> 🎯 核心要点：references = L3 按需加载（读得准读得少）；JIT 指针三要素（触发条件/文件/目的）；一层深度（一跳可达）；大文件加目录/按主题拆；--help 模式（精简 + 自维护）；路由列表（文件/内容/何时读）；文件级指针防目录级全加载。
