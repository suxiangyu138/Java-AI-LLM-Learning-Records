## 1. assets 的定位

### 装什么

```
assets/ = 可复用的素材：
① 模板（生成时填充）
② schema（结构化输出定义）
③ 示例资源（参考结构）
④ 静态素材（图标/图片）
```

### 与 references 的区别

| 维度 | references | assets |
|---|---|---|
| 内容 | 知识（读） | 素材（用） |
| 目的 | 理解 | 填充/复用 |
| 例子 | 风格指南 | 文档模板 |

### 一句话

```
references = 怎么做的知识
assets = 直接用的素材
```

## 2. 模板设计原则

### 模板质量自检

```
① 骨架完整？（标题/章节/结尾都齐）
② 占位符清晰？（语义化 + 有清单）
③ 示例内嵌？（每节有模仿依据）
④ 与正文一致？（规则不冲突）
⑤ 填充有检查？（占位符是否填全）
——模板是输出质量的下限，值得认真
```

| 原则 | 说明 |
|---|---|
| 骨架完整 | 结构齐全（标题/章节/结尾） |
| 占位符清晰 | {{变量}} 或 ____ 明确 |
| 示例内嵌 | 每节给示例（模仿依据） |
| 与正文一致 | 模板与 SKILL.md 规则不冲突 |

### 模板示例（文档模板）

```markdown
# {{标题}}

> {{一句话定位}}

## 📚 目录

1. [{{章节一}}](#{{章节一锚点}})

## 1. {{章节一}}

### 1.1 {{子节}}
{{内容——表格优先，代码标注语言}}

---

<!-- 模板尾部导航占位符：指向后续文档（文件名生成时填充） -->
```

## 3. 参数化模板

### 占位符约定

| 占位符 | 含义 | 例子 |
|---|---|---|
| {{变量}} | 必填内容 | {{标题}} {{主题}} |
| {{可选}} | 视情况 | {{可选：应用场景}} |
| ____ | 填空（代码/路径） | ____ |

### 参数化流程

```
① SKILL.md 说"读取模板 + 填写占位符"
② 模板列出所有占位符（Agent 知道要填什么）
③ 生成时按上下文填充
——"生成"变成"填空"（确定性更高）
```

### 参数化要点

```
① 占位符命名语义化（{{标题}} 而非 {{x}}）
② 模板头部列占位符清单（Agent 检查完整性）
③ 可选占位符标注（不强制）
```

## 4. schema 与结构化输出

### 为什么需要 schema

```
结构化输出（JSON 等）：
schema 定义字段与类型 → 输出可靠可解析
（对应"脚本返回结构化数据"的文档化）
```

### schema 示例

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "type": "object",
  "properties": {
    "title": { "type": "string", "description": "文档标题" },
    "type": { "enum": ["知识体系", "单篇笔记", "速记"] },
    "sections": { "type": "array", "items": { "type": "string" } }
  },
  "required": ["title", "type", "sections"]
}
```

### schema 的使用

```
① assets/schema/doc_meta.json（存放）
② SKILL.md 指向（JIT 指针）
③ 输出前校验（脚本或规则）
——结构化输出的"契约"
```

## 5. 模板与正文的分工

### 与 references 的边界

```
assets 与 references 的边界判断：
要"填"的 → assets（模板/骨架）
要"读"的 → references（知识/细节）
例：文档模板 → assets；写作规范 → references
——同一技能两者可共存（各管一类）
```

| 内容 | 放哪 |
|---|---|
| 流程与决策 | SKILL.md 正文 |
| 输出骨架 | assets/模板 |
| 结构化契约 | assets/schema |
| 填充规则 | SKILL.md 或 references |

### 分工原则

```
正文说"用什么模板、怎么填"
模板提供"骨架"
schema 约束"结构"
——三层分离（决策/骨架/契约）
```

### 示例流程

```
1. 读 assets/templates/单篇笔记模板.md（骨架）
2. 按 SKILL.md 的填充规则填写占位符
3. 按 assets/schema/doc_meta.json 校验元数据
——决策在正文、骨架在模板、契约在 schema
```

## 6. 常见误区

| 误区 | 真相 |
|---|---|
| "模板可有可无" | 模板定输出质量下限（必做） |
| "占位符随意" | 语义化 + 清单（Agent 检查） |
| "schema 是过度设计" | 结构化输出需要契约 |
| "模板与正文重复" | 分工：正文决策/模板骨架 |
| "assets 塞一堆" | 每个素材要有用（垃圾进垃圾出） |

## 7. 面试高频问法

| 问题 | 回答要点 |
|---|---|
| assets 装什么？ | 模板/schema/示例/静态素材 |
| 与 references 区别？ | 知识（读）vs 素材（用） |
| 参数化模板？ | 占位符填充（{{变量}}） |
| 为什么 schema？ | 结构化输出契约（可靠可解析） |
| 三层分工？ | 正文决策/模板骨架/schema 契约 |
| 模板设计要点？ | 骨架完整/占位符清晰/示例内嵌 |

### 面试加分表达

> "assets 的价值是'让生成变填空'：模板提供输出骨架（占位符语义化 + 头部清单让 Agent 检查完整性）、schema 提供结构化契约（字段类型 required 定义）、示例内嵌提供模仿依据。三层分离：正文管决策（用什么模板怎么填）、模板管骨架、schema 管契约——输出质量的下限由模板决定，所以模板必须认真设计。"

> 🎯 核心要点：assets 装模板/schema/示例；与 references 分工（知识 vs 素材）；参数化模板（占位符语义化 + 清单）；schema 结构化契约（输出可靠可解析）；三层分工（决策/骨架/契约）；模板定输出质量下限。
