## 1. 组合原语不捆绑工作流

### 核心原则

```
一个技能 = 一个能力或一个学科
多个小技能运行时组合（Agent 按需加载）
一个大技能僵硬（一次全加载，不可组合）
```

### 拆分 vs 捆绑

| 方式 | 例子 | 问题 |
|---|---|---|
| 捆绑 | 一个"文档全流程"技能 | 写笔记也要加载全套（浪费） |
| 组合 | 文档生成 + 文档校验 + 文档发布 | 按需组合（各管一段） |

### 组合的实现

```
技能间通过"输出 → 输入"衔接：
① 文档生成技能产出文档
② 校验技能消费文档（JIT 触发）
③ 发布技能处理通过校验的
——Agent 按需加载每个（L2 只加载触发的那几个）
```

### 组合的价值

```
① 按需加载（渐进式披露生效）
② 独立迭代（改校验不影响生成）
③ 灵活组合（不同任务不同搭配）
```

## 2. 严格度匹配任务脆弱性

### 原则

```
指令的严格度 = 任务脆弱性：
越关键/越一致性重要 → 越要精确（脚本/严格步骤）
越宽松/越需要判断 → 越宽松（自然语言启发式）
```

### 严格度阶梯

| 严格度 | 形式 | 适用 |
|---|---|---|
| 宽松 | 自然语言启发式 | 代码审查（需要判断） |
| 中等 | 伪代码/模板 | 报告格式（有标准结构） |
| 严格 | 精确脚本/严格步骤 | 迁移/文档修补（一致性关键） |

### 匹配示例

```
代码审查 → 宽松（检查项启发式）
报告生成 → 中等（模板 + 填充规则）
文档迁移 → 严格（脚本 + 精确步骤）
——严格度跟脆弱性走，别一刀切
```

## 3. State-check before action

### 原则

```
先验证状态再分支，不要假设 setup 已完成：
执行前检查"前置条件是否满足"
不满足 → 处理（安装/提示/跳过）
```

### 示例

```markdown
## 执行步骤
1. 检查目标目录存在（不存在则创建）
2. 检查依赖已安装（缺失则提示安装命令）
3. 检查输入文件格式（不匹配则报错）
——先检查再行动（假设 = bug）
```

### State-check 的价值

```
① 可靠性：不假设环境（可移植）
② 错误提前：问题在行动前暴露
③ 可恢复：给出处理路径（安装/创建）
```

## 4. 可复用性设计

### 原则

```
可复用技能不应包含项目特定假设：
命令、路径、约束都来自项目 → 技能失效
```

### 项目上下文分离

```
项目本地现实与技能分离：
技能内：project.skill.template.md（通用模板）
项目内：project.skill.md（项目现实：命令/路径/约束）
——技能可移植，项目可定制
```

### 分离的好处

```
① 技能跨项目复用（不绑死一个项目）
② 项目差异外置（不动技能本体）
③ 团队共享（技能 + 各项目覆盖）
```

### 可移植检查

```
技能里的"硬编码"检查：
❌ 命令：cd /home/user/project && ...
❌ 路径：/tmp/build/...
✅ 参数化：${CLAUDE_SKILL_DIR} / CLI 参数
```

## 5. 跨会话持久化

### 原则

```
技能可写入仓库级文件供未来 Agent 使用：
CONTEXT.md / ADR / 决策日志
——技能不只服务当前会话，沉淀给未来
```

### 示例

```markdown
## 执行步骤
3. 将关键决策写入 CONTEXT.md（追加）
——未来 Agent 读取（跨会话知识积累）
```

### 持久化的价值

```
① 记忆跨会话（技能是"活的"）
② 决策可追溯（ADR 记录）
③ 团队共享（仓库级文件）
```

## 6. 完整设计模式示例

```markdown
---
name: safe-deploy
description: 安全部署检查。用于用户提到部署/上线/发布时。
  （只写 what/when，不写 how）
version: 1.2.0
allowed-tools:
  - read_file
  - Bash(python:*)
  - Bash(ls:*)
---

# safe-deploy

## 何时使用
- 用户要求部署/上线/发布

## 前置检查（State-check）
1. 确认项目配置存在（缺失则报错并提示）
2. 确认依赖清单可读

## 执行步骤（严格步骤——部署一致性关键）
1. 运行预检脚本：python ${CLAUDE_SKILL_DIR}/scripts/precheck.py
2. 若退出码非 0，按输出修复后重跑
3. 生成部署清单（用 assets/templates/部署清单模板.md）
4. 将部署记录追加到 CONTEXT.md

## 输出
- 部署清单（模板填充 + 预检结果）
```

### 模式解读

```
① 组合：预检/生成/记录可拆（一个技能一个能力）
② 严格度：部署 = 严格（脚本 + 精确步骤）
③ State-check：前置检查先行
④ 可移植：CLAUDE_SKILL_DIR + 无硬编码
⑤ 持久化：写 CONTEXT.md（跨会话）
```

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "大而全的技能专业" | 组合原语（大技能僵硬） |
| "所有任务严格步骤" | 严格度匹配脆弱性 |
| "假设环境就绪" | State-check（先查再动） |
| "技能绑定项目" | 项目上下文分离（可移植） |
| "技能只服务当下" | 跨会话持久化（沉淀） |

## 8. 面试高频问法

| 问题 | 回答要点 |
|---|---|
| 组合原语？ | 一个技能一个能力，运行时组合 |
| 严格度怎么定？ | 匹配任务脆弱性（越关键越严格） |
| State-check？ | 先验证状态再行动（不假设） |
| 可移植设计？ | 项目上下文分离（template + 项目覆盖） |
| 跨会话持久化？ | 写 CONTEXT.md/ADR（沉淀给未来） |
| 完整模式？ | 组合+严格度+State-check+可移植+持久化 |

### 面试加分表达

> "复杂技能设计遵循五个模式：组合原语（一个技能一个能力，运行时组合——大技能僵硬）、严格度匹配脆弱性（部署用脚本+精确步骤，代码审查用宽松启发式）、State-check before action（先验证再分支，不假设环境）、项目上下文分离（template 通用 + 项目覆盖，技能可移植）、跨会话持久化（写 CONTEXT.md/ADR 沉淀给未来 Agent）。"

> 🎯 核心要点：组合原语（一个技能一个能力）；严格度匹配脆弱性（宽松→严格阶梯）；State-check（先查再动）；项目上下文分离（可移植）；跨会话持久化（CONTEXT.md/ADR）；完整示例（safe-deploy 五模式落地）；可移植检查（无硬编码）。
