## 1. 动手任务一：技能拆分升级

### 任务目标

把阶段 2 的技能升级为多文件结构。

### 分析清单

| 内容 | 现在的技能里 | 应该去哪 |
|---|---|---|
| 判断力（流程/规则） | ______ | SKILL.md 保留 |
| 确定性操作（解析/校验） | ______ | scripts/ |
| 深度细节（边界/背景） | ______ | references/ |
| 模板/骨架 | ______ | assets/ |

### 拆分步骤

```
① 列出技能的所有内容（逐条）
② 按上表归类
③ 移到对应目录（脚本/文档/模板）
④ SKILL.md 加 JIT 指针（何时读哪个）
⑤ 验证：功能不退化（回归）
```

### 拆分检查

- [ ] SKILL.md ≤500 行
- [ ] references 一层深度
- [ ] 指针明确（何时读哪个）
- [ ] 无硬编码路径

## 2. 动手任务二：脚本化与测试

### 脚本化步骤

```
① 选一个确定性操作（校验/转换/解析）
② 写脚本（CLI 参数 + 退出码 + 可解析输出）
③ SKILL.md 加调用步骤（${CLAUDE_SKILL_DIR}）
④ 配置 allowed-tools（Bash(python:*)）
```

### 测试要求

```
① 正常路径（预期输入 → 预期输出）
② 边界（空输入/缺文件）
③ 异常（错误输入 → 清晰报错）
④ 幂等（跑两次结果一致）
```

### 安全审查（脚本提交前）

- [ ] 无危险命令
- [ ] 无硬编码路径
- [ ] 输入有校验
- [ ] 依赖明确

## 3. 动手任务三：对比评估

### 评估设置

```
① 准备 2-5 条真实测试 prompt
② baseline：裸 Claude（或旧版本）
③ with-skill：加载技能后
④ 记录：pass rate / 耗时 / token
```

### 评估记录表

| 指标 | baseline | with-skill | 变化 |
|---|---|---|---|
| pass rate | ______ | ______ | ______ |
| 耗时 | ______ | ______ | ______ |
| token | ______ | ______ | ______ |
| 触发 F1 | — | ______ | — |

### 评估工具参考

```
① 手工对比（本任务）：测试 prompt × with/baseline
② skilltest CLI：eval/check（mock 响应 + 质量门）
③ skill-test-skill：规范评分（六维）
——手工起步，工具深化（06 篇）
```

### 一句话总结

```
阶段 3 实战 = "把技能工程化"：
拆（多文件）→ 写（脚本带测试）→ 配（最小权限）
→ 测（对比评估）→ 结（数据结论）
——每一步都有产出物，毕业有据可查
```

### 评估结论

```
技能是否值得用？（pass rate 提升？）
需要改什么？（触发/执行/效率）
改完重测（回归）——一次一变量
```

## 4. 20 道自测题

### 多文件结构（1-6）

1. 三个可选目录的分工？
2. 何时写脚本？（脆弱/重复/易错）
3. 扁平布局允许吗？
4. references 为什么一层深度？
5. SKILL.md 行数红线？
6. assets 与 references 区别？

### scripts（7-10）

7. 脚本语言怎么选？
8. 脚本接口三要点？
9. 怎么调脚本路径？
10. 脚本为什么必须带测试？

### 安全与评估（11-16）

11. allowed-tools 作用域语法？
12. 配置原则？
13. 对比评估怎么做？
14. baseline 是什么？
15. skill-test-skill 六维？
16. 验证循环？

### 设计模式（17-20）

17. 组合原语？
18. 严格度怎么定？
19. State-check？
20. 项目上下文分离？

### 参考答案（简版）

1. scripts 确定性/references 知识/assets 素材
2. 脆弱/重复/易错的操作
3. 允许（规范不惩罚）
4. 链式嵌套易被跳过
5. ≤500 行
6. 知识（读）vs 素材（用）
7. Python 通用/Shell 简单/Go 云原生
8. CLI 参数/退出码/可解析输出
9. ${CLAUDE_SKILL_DIR}
10. 无测试是负债（改了不知道坏没坏）
11. Bash(命令:*) 命令级
12. 最小权限/只读优先/危险拒绝
13. 2-5 prompt × with/baseline 聚合指标
14. 裸 Claude 或旧版本快照
15. 六维 100 分（frontmatter 30 最大）
16. verify → fix → re-verify
17. 一个技能一个能力，运行时组合
18. 匹配任务脆弱性（越关键越严格）
19. 先验证状态再行动
20. 模板通用 + 项目覆盖（可移植）

### 评分与行动

| 得分 | 结论 |
|---|---|
| 16-20 | 达标，进入阶段 4 |
| 12-15 | 复习错题对应篇 |
| <12 | 重做动手任务 + 重读 01-07 |
