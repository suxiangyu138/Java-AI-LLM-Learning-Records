## 1. allowed-tools 机制

### 是什么

```
allowed-tools：技能无需权限即可使用的工具（白名单）
不在列表的工具 → 触发权限确认（或拒绝）
```

### 与权限模型的关系

```
默认：技能调工具走权限确认
allowed-tools 配置后：白名单内免确认
——配置 = 减少打扰 + 限定边界
```

### frontmatter 位置

```yaml
---
name: safe-skill
description: 文档处理技能
allowed-tools:
  - read_file
  - write_file
  - Bash(python:*)
---
```

## 2. 作用域语法

### 语法形态

| 语法 | 含义 | 例子 |
|---|---|---|
| 工具名 | 整个工具 | read_file / write_file |
| Bash(命令:*) | 命令前缀匹配 | Bash(python:*) 只允许 python |
| Bash(gh:*) | GitHub CLI | Bash(gh:*) |
| 带路径 | 限定目录 | Bash(ls:./data/*) |

### 作用域设计

```
精确到命令（最小权限）：
❌ Bash(*)          # 所有 shell 命令（太宽）
✅ Bash(python:*)   # 只允许运行 python
✅ Bash(gh:*)       # 只允许 GitHub CLI
```

### 示例配置

```yaml
allowed-tools:
  - read_file
  - Bash(python:*)          # 跑技能脚本
  - Bash(ls:*)              # 查看目录（只读）
  # 不包含：写库/删除/网络等危险命令
```

## 3. 配置原则

| 原则 | 说明 |
|---|---|
| 最小权限 | 只给任务必需的工具 |
| 命令级作用域 | Bash(具体命令:*) 而非 Bash(*) |
| 只读优先 | 能读不写（ls/read 优先） |
| 危险默认拒绝 | 删除/网络/写库不默认给 |
| 有 references 必配 | 建议加 Read, Grep（防权限弹窗） |

### 配置流程

```
① 列出技能任务需要的工具
② 最小化（只留必需的）
③ 精确化（命令级作用域）
④ 测试（跑一遍确认不弹窗不越权）
```

### references 技能的建议

```
有 references/ 的技能：
allowed-tools: Read, Grep
——Agent 读取引用文件免弹窗（体验）
```

## 4. 与其他安全机制的配合

### 与供应链审查的衔接

```
技能安全全链路（阶段 1 的 06 篇 → 本阶段）：
① 安装前：供应链审查（来源/脚本/依赖）
② 运行中：allowed-tools 白名单（本篇）
③ 流程上：权限确认 + HITL 审批
——allowed-tools 是"运行中"的核心防线
```

### 三层防线

```
① allowed-tools（工具白名单）——技能层
② 权限确认（未列工具弹窗）——用户层
③ HITL/审批（危险操作人审）——流程层
```

### 配合示例

```
技能 allowed-tools 只给读与 python：
脚本想写文件 → 未在白名单 → 权限确认（用户把关）
写库操作 → 需要审批（流程把关）
——白名单 + 确认 + 审批三层
```

### 与阶段 1 的 06 篇呼应

```
技能安全 = 供应链审查（安装前）+ 运行限制（allowed-tools）+ 流程审批
allowed-tools 是"运行限制"的核心实现
```

## 5. 实验性状态与谨慎使用

### 2025-12 开放标准时

```
allowed-tools 被标记为 experimental：
字段仍演进中（实现差异）
```

### 谨慎使用的原因

```
① 跨平台实现可能不一致（experimental）
② 配置错误 = 权限过宽或技能不可用
③ 依赖平台对字段的支持程度
```

### 使用建议

```
① 先理解再配置（作用域语法）
② 配置后测试（不弹窗 + 不越权）
③ 关注平台文档（experimental 演进）
④ 默认偏保守（少给比多给安全）
```

## 6. 常见误区

| 误区 | 真相 |
|---|---|
| "Bash(*) 方便" | 权限过宽（最小权限原则） |
| "allowed-tools 是必填" | 可选（experimental）——但建议配 |
| "配了就不用管" | 要测试 + 关注演进 |
| "所有技能都要配" | 纯知识技能可空（不需要工具） |
| "工具名就行" | 命令级作用域更精确 |
