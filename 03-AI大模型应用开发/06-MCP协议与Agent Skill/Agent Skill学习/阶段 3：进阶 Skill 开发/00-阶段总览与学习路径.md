## 1. 本阶段定位

五阶段路径的"专业化"一站——从"能触发能干活"到"可靠、可测、可复用"：

```
阶段1 概念 → 阶段2 第一个 Skill → 阶段3 进阶开发（本阶段）→ 阶段4 框架 → 阶段5 工程
```

| 对比项 | 阶段 2 | 阶段 3 |
|---|---|---|
| 结构 | 单文件（SKILL.md） | 多文件（scripts/references/assets） |
| 可靠性 | 能执行 | **确定性（脚本）** |
| 验证 | 手动三维测试 | **可重复对比评估** |
| 安全 | allowed-tools 基础 | 精细作用域配置 |
| 复用 | 单场景 | **可移植设计** |

### 阶段 3 的核心转变

```
阶段 2：技能"能用"（能触发能干活）
阶段 3：技能"可靠"（确定性操作交给脚本、内容按需加载、质量可评测）
——从"提示词的文件夹"到"工程化的技能"
```

## 5. 进阶核心认知

### 三条主线（贯穿本阶段）

| 主线 | 内容 |
|---|---|
| 确定性进代码 | 脆弱/重复/易错的操作写成脚本（markdown 只留判断力） |
| 内容按需加载 | references/assets 用 JIT 指针（什么时候读什么） |
| 质量可评测 | 对比 eval（有 baseline 的 pass rate）替代"感觉不错" |

### 2026 最佳实践速览（本阶段展开）

```
① description 是路由契约：只写 what/when，绝不写 how（80-150 字符）
② Bash-first, prose-second：具体命令示例优于散文
③ 严格度匹配任务脆弱性：越关键越要精确脚本
④ 组合原语不捆绑工作流：一个技能一个能力
⑤ 脚本必须带测试：无测试的脚本是负债
```

## 6. 毕业标准

- [ ] 技能升级为多文件结构（scripts/references/assets 合理分工）
- [ ] 确定性操作已脚本化（且脚本有测试）
- [ ] references 有 JIT 指针与路由列表
- [ ] allowed-tools 精细配置（作用域 + 最小权限）
- [ ] 跑过一次对比评估（with-skill vs baseline，有数据）
- [ ] 20 道自测题正确率 ≥ 80%

## 7. 常见疑问快答与关键数据

### 常见疑问

| 疑问 | 回答 |
|---|---|
| 阶段 3 与阶段 2 的核心区别？ | 阶段 2 能用，阶段 3 可靠（脚本+评估） |
| 必须写脚本吗？ | 有确定性操作就要（没有可跳过） |
| 评估是必须的吗？ | 2026 起是（对比数据替代感觉） |
| 需要会 Python 吗？ | 基础即可（脚本也可用 Shell） |
| allowed-tools 必配？ | 建议配（experimental 但推荐） |

### 关键数据速记

| 数据 | 数值 |
|---|---|
| SKILL.md 红线 | ≤500 行 |
| references 深度 | 一层 |
| 大文件分界 | 100 行加目录/几百行拆分 |
