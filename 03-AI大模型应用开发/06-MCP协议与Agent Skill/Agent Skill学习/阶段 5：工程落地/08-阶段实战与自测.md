## 1. 动手任务一：搭建技能库

### 任务目标

把阶段 4 的跨平台技能纳入一个可治理的技能库。

### 建库步骤

```
① 建仓库结构（skills/ + templates/ + 校验脚本）
② 技能入库（规范布局）
③ 补元数据（skill.yaml：接口/依赖/owner）
④ 建新技能模板（从模板生成规范技能）
⑤ 写 README 索引（技能清单）
```

### 建库检查清单

| 项 | 检查 |
|---|---|
| 布局 | skills/ 集中 + 每技能一目录 | ☐ |
| 命名 | kebab-case = 目录 = name | ☐ |
| 元数据 | skill.yaml（接口/依赖/owner） | ☐ |
| 模板 | 新技能从模板生成 | ☐ |
| 索引 | README 列出全部 | ☐ |

## 2. 动手任务二：配置质量门禁

### 门禁配置

```bash
# 技能级门禁（对单个技能）
skill-guard validate skills/你的技能
skill-guard secure skills/你的技能
skill-guard conflict skills/你的技能

# 合并门禁（全部）
skill-guard check
```

### 门禁检查

| 检查项 | 结果 |
|---|---|
| validate（格式 + 评分） | 达标分数：______ |
| secure（危险模式） | 风险项：______ |
| conflict（触发词重叠） | 重叠：______ |
| 修复项 | ______ |

### 评估测试

```
skill-guard test（针对兼容端点）：
① 准备评估 prompt（提交时套件）
② 跑 with/without 对比
③ 记录：准确率/效率
```

## 3. 动手任务三：CI 与所有权

### CI 配置

```
① 提交时：lint + link check + secure + conflict
② 合并前：check（合并门禁）
③ 每周：monitor（漂移检测）+ 回归
——三步 CI（提交/合并/持续）
```

### 所有权登记

```
① 确定你的技能 owner（你）
② skill.yaml 登记 owner
③ 明确维护职责（依赖更新/issue 响应）
④ 建变更记录（changelog）
```

### 交付物（阶段 5 产出）

```
① 技能库（规范 + 模板 + 索引）
② 门禁配置（validate/secure/conflict）
③ CI 流程（提交/合并/每周）
④ 所有权（owner + changelog）
⑤ 评估数据（with/without）
```

## 6. 全路径总结

### 五阶段一句话

```
阶段1：Agent Skills 是任务知识的标准打包（SKILL.md）
阶段2：能写能触发能验证（最小可用）
阶段3：确定性进代码、内容按需加载、质量可评测
阶段4：一份 SKILL.md 跨平台可跑、可分发
阶段5：技能是资产（规范/门禁/所有权/生命周期）
```

### 核心认知（贯穿全程）

```
① 技能 = 知识 + 流程 + 门禁的封装（新一代 npm）
② description 是触发的钥匙（路由契约）
③ 渐进式披露是上下文经济的基础
④ 技能是"活的产品"（评估/版本/废弃）
⑤ 从拼模型到拼技能（2026 趋势）
```

### 与 MCP 学习体系的收官

```
双标准组合（MCP 工具 + Agent Skills 知识）：
MCP 学习体系（工具怎么开发）
本体系（知识怎么打包）
= Agent 能力扩展的完整图景
```
