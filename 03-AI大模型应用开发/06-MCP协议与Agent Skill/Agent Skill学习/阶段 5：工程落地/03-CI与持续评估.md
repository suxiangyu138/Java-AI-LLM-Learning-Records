## 1. Google 的工程实践（标杆）

### 为什么是标杆

```
2026-08 Google Cloud 公开其 Agent Skills 工程实践：
从构建、测试到规模化（企业级完整流程）
——大厂实践 = 工程落地的参照系
```

### 核心原则

```
① 标准化仓库布局（01 篇）
② 优先引用远程 MCP 工具（内置 auth/IAM 治理）
③ 提交时自动化检查
④ 持续评估（提交时 + 每周）
⑤ 技能即产品（所有权明确）
```

### 可借鉴点

```
① 自动化检查进提交（合并前拦截）
② 评估常态化（不是一次验收）
③ 双维度量化（准确 + 效率）
④ 所有权分工（maintainer/owner）
```

## 2. 提交时自动化检查

### 三类检查

| 检查 | 内容 |
|---|---|
| Linters | frontmatter 元数据/行数/目录布局/命名 |
| Link Checkers | 合并前测试所有 URL（消除 404 与幻觉链接） |
| AI 辅助清单 | 验证指令遵循结构模式和护栏 |

### Linters 的价值

```
规范自动化执行（01 篇的落地）：
提交时 lint → 不合规进不了
——规范从"文档"到"强制"
```

### Link Checkers 的价值

```
幻觉链接（技能引用不存在的 URL）：
合并前全测 → 消除 404
——技能内容的可信度基线
```

### AI 辅助清单

```
用 AI 验证 AI 技能：
结构模式（七部分）与护栏（安全）自动核对
——技能审查的 AI 化
```

## 3. 持续评估体系

### 两层评估

| 层 | 时机 | 内容 |
|---|---|---|
| 提交时评估 | 每次提交 | 作者必须提供显式评估 prompt 套件 + 评分标准 |
| 每周质量检查 | 每周 | 定时任务全库回归 |

### 提交时评估的要求

```
作者义务：
① 提供显式评估 prompt 套件（测什么）
② 提供评分标准（怎么算过）
——提交技能 = 提交评估方案
```

### 每周回归

```
定时任务全库评估：
所有技能重跑（with/without 对比）
发现退化（模型/依赖/平台变化）
——持续质量（技能是活的产品）
```

## 4. 双维度评估

### 两个维度

| 维度 | 指标 |
|---|---|
| 准确性 | 响应质量、任务完成率 |
| 效率 | token 消耗、完成时间 |

### with/without 对比

```
每个技能评估：
with-skill vs without-skill（裸 agent）
→ 技能到底带来多少提升（量化）
——技能价值的证明
```

### 统计显著性

```
多种 agent 框架上多次运行：
避免单次偶然（统计显著才可信）
——评估的科学性
```

## 5. CI 管道设计

### 管道阶段

```
技能提交 → ① lint（规范）→ ② link check（URL）
→ ③ secure（安全）→ ④ conflict（触发词）
→ ⑤ eval（提交时评估）→ 合并
```

### 门禁配置（skill-guard 组合）

```yaml
# CI 门禁（参考）
steps:
  - skill-guard validate      # 格式 + 评分
  - skill-guard secure        # 危险模式
  - skill-guard conflict      # 触发词重叠
  - skill-guard check         # 合并门禁（+evals）
  - link-check                # URL 检查
```

### 每周任务

```
cron 定时：
① 全库回归（with/without 对比）
② monitor 漂移检测
③ 生成周报（退化/提升）
——CI 不只是"合并前"，是"持续中"
```

## 6. 评估报告与迭代

### 与阶段 3 的评估衔接

```
评估升级（阶段 3 → 阶段 5）：
阶段 3：个人技能评估（对比 eval）
阶段 5：团队持续评估（CI + 每周回归）
——同一方法论，不同规模
评估套件（阶段 3 的产出）→ CI 直接复用
```

### 评估报告

```
每次评估输出：
① 技能清单 + 评分
② with/without 对比数据
③ 退化项（需修复）
④ 提升项（确认保留）
——数据驱动迭代
```

### 迭代闭环

```
评估发现退化 → 修复 → 回归 → 更新评分
——技能是"活的产品"（持续迭代）
```

### 报告用途

```
① 发布依据（达标才能发）
② 治理记录（审计轨迹）
③ 迭代输入（改什么）
——评估报告 = 治理的"账本"
```

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "CI 只管合并前" | 每周回归 + monitor（持续中） |
| "评估一次够" | 提交时 + 每周（双层） |
| "只测准确" | 准确 + 效率双维度 |
| "单次结果可信" | 多框架多次（统计显著） |
| "技能提交无义务" | 提交 = 提交评估套件 |
