## 1. 安全治理的定位

### 从个人到企业

```
个人：安装前自审（阶段 1 的八项清单）
企业：系统化扫描（全库自动检查）
——安全从"自觉"到"强制"
```

### 企业安全痛点

```
① prompt 注入（技能隐藏指令劫持 Agent）
② 数据泄露（技能读取/外传敏感数据）
③ 权限提升（技能滥用工具/命令）
——三大风险需要系统化检测
```

### 治理层级

```
① 安装前：来源审查（个人）
② 入库时：扫描门禁（企业）
③ 运行中：白名单 + 审批（平台）
——三层防线（个人/企业/平台）
```

## 2. 危险模式扫描

### 扫描内容（skill-guard secure）

```
① 脚本目录（scripts/ 内容逐项）
② prompt 注入模式（SKILL.md 隐藏指令）
③ 危险命令（删除/网络/外传）
```

### 危险命令清单

| 类别 | 例子 |
|---|---|
| 破坏性 | rm -rf / 覆盖关键文件 |
| 外传 | curl 发送数据到外部 |
| 管道 shell | curl x | sh（执行远程脚本） |
| 提权 | sudo 无授权使用 |
| 网络 | 非预期网络调用 |

### 扫描实现

```
正则/规则匹配 + 语义检查：
skill-guard secure skills/
# 输出：发现的风险项（级别）
```

## 3. 注入与伪装检测

### 隐藏字符攻击

```
① 隐藏/bidi 字符（不可见方向控制字符）
② 同形字攻击（相似字符伪装）
——恶意指令藏在"看不见"的地方
```

### 检测方式

```
资产安全套件（governance-toolkit）：
隐藏/bidi 字符检测
同形字攻击检测
——扫描看不见的恶意
```

### prompt 注入模式

```
SKILL.md 正文中的隐藏指令：
① 指令伪装（看起来像文档，实为指令）
② 越权诱导（诱导 Agent 执行危险操作）
③ 数据外传（诱导读取并发送敏感信息）
——阶段 1 的"隐藏指令劫持"的系统化检测
```

## 4. 内联密钥检测

### 风险

```
技能内嵌密钥（API Key/Token）：
① 仓库泄露（技能进 git = 密钥泄露）
② 供应链风险（他人技能含密钥）
——密钥检测是扫描必备项
```

### 检测内容

```
常见密钥模式：
API Key / Token / 私钥 / 密码
格式匹配（sk-xxx 等）+ 熵检测（高随机性）
```

### 处置

```
发现内联密钥：
① 阻止合并（门禁）
② 提示移除（换环境变量/Secret 引用）
③ 若已泄露（轮换密钥）
——密钥零容忍
```

## 5. 安全评分与标准

### 安全评分

```
0-100 安全评分（扫描输出）：
基于国际标准（OWASP LLM Top 10、MITRE ATLAS）
——安全数字化（阈值门禁）
```

### 参考标准

| 标准 | 关注 |
|---|---|
| OWASP LLM Top 10 | 提示注入/数据泄露/供应链等 |
| MITRE ATLAS | 对抗性攻击知识库 |

### 评分落地

```
测试环境部署扫描服务：
① PR 合并前强制检查
② 输出 0-100 安全评分
③ 低于阈值阻止合并
——安全门禁（像代码扫描）
```

### 流水线集成

```
通用插件嵌入：
Jenkins / GitLab 等流水线
——自动化扫描（不靠人工）
```

## 6. 安全基线

### 与阶段 1 的 06 篇衔接

```
安全认知升级（阶段 1 → 阶段 5）：
阶段 1：个人安装前审查（八项清单）
阶段 5：企业系统化扫描（全库自动）
——同一个风险，不同治理粒度
个人技能：自审即可
企业技能：扫描 + 门禁 + 审计
```

### 企业技能安全基线

| 基线 | 说明 |
|---|---|
| 零密钥 | 内联密钥零容忍 |
| 零隐藏字符 | bidi/同形字检测 |
| 命令白名单 | 危险命令扫描 |
| 最小权限 | allowed-tools 配置 |
| 来源可信 | 只收录审查过的技能 |
| 定期重扫 | 全库安全回归 |

### 与生命周期结合

```
安全贯穿生命周期：
入库时（扫描）→ 使用中（monitor）→ 更新时（重扫）
——安全不是一次检查，是持续状态
```

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "扫描一次就安全" | 技能/依赖变化要重扫 |
| "只查脚本" | 正文隐藏指令也要查（注入） |
| "密钥小事" | 零容忍（泄露即轮换） |
| "自研扫描够" | 对齐标准（OWASP/MITRE） |
| "安全是安全团队的事" | 作者提交时就要过扫描 |

| 问题 | 回答要点 |

### 面试加分表达

> "企业级安全治理从'个人审查'升级为'系统化扫描'：skill-guard secure 扫危险模式（scripts/ 内容、prompt 注入、危险命令）、资产安全套件检测隐藏/bidi 字符与同形字攻击、密钥检测零容忍（模式+熵）。安全评分对齐国际标准（OWASP LLM Top 10/MITRE ATLAS），0-100 分数做 PR 合并门禁，Jenkins/GitLab 插件自动化。安全是持续状态——入库扫描、使用 monitor、更新重扫。"

> 🎯 核心要点：企业三层防线（个人/企业/平台）；secure 扫危险模式；注入检测（隐藏字符/同形字/伪装指令）；密钥零容忍（模式+熵）；安全评分（OWASP/MITRE 对齐 + 0-100 门禁）；流水线集成（Jenkins/GitLab）；安全是持续状态（入库/使用/更新全程）。
