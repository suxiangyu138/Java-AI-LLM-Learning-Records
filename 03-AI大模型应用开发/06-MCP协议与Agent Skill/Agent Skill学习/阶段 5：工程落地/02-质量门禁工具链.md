## 1. 为什么需要门禁工具

### 人工把关的问题

```
技能多了（几十上百）：
① 人工审查不现实（每技能逐项）
② 标准不一（人各看法不同）
③ 遗漏必然（无系统检查）
——需要自动化门禁
```

### 门禁工具的价值

| 价值 | 说明 |
|---|---|
| 一致性 | 同一标准批量检查 |
| 全面性 | 格式/安全/冲突/评估全覆盖 |
| 可重复 | CI 中自动跑（不靠人） |
| 演进 | 规则可更新（工具版本化） |

### 2026 生态

```
质量门禁工具爆发（安全扫描工具一周 4000+ 星）：
skill-guard（全生命周期门禁）
skill-governance-toolkit（治理工具包）
——治理自动化成为共识
```

## 2. skill-guard 七命令

| 命令 | 功能 |
|---|---|
| validate | 格式合规 + 质量评分 |
| secure | 危险模式扫描 |
| conflict | 触发词重叠检测 |
| test | 针对兼容端点跑 evals |
| check | 合并门禁（validate+secure+conflict） |
| monitor | 定时重跑 evals（漂移检测） |
| catalog | 技能注册表（可搜索） |

```
七命令覆盖生命周期：
提交前（validate/secure/conflict）
合并前（check）
持续（monitor）
发现（catalog）
```

## 3. validate：格式与评分

### 检查内容

```
① SKILL.md 存在
② frontmatter YAML 合规
③ name/description 字段有效
④ 目录命名匹配（目录名 = name）
⑤ "Use when" 触发提示存在
⑥ 正文路径完整性
```

### 质量评分

```
validate 输出质量分（合规 + 质量）：
低于阈值 → 不通过（门禁）
——规范数字化（分数说话）
```

### 使用

```bash
skill-guard validate skills/code-review
# 输出：合规检查 + 质量评分
```

## 4. secure 与 conflict

### secure：危险模式扫描

```
检查：
① 脚本目录（scripts/ 内容）
② prompt 注入模式（SKILL.md 隐藏指令）
③ 危险命令（删除/网络/外传）
——安全基线（阶段 1 的 06 篇自动化）
```

### conflict：触发词重叠

```
检测与现有技能的 description 触发词重叠：
两个技能抢同一任务 → 行为不确定
→ 发现重叠（调整触发词或合并）
```

### 门禁组合

```bash
skill-guard check  # validate + secure + conflict（合并门禁）
# 配置 endpoint 时还会跑 agent evals（test）
```

## 5. test 与 monitor

### test：agent evals

```
针对 OpenAI 兼容端点运行评估：
支持注入方式：custom_hook / directory_copy / git_push
——真实 agent 行为验证（不只是静态检查）
```

### monitor：漂移检测

```
通过 cron/CI 定时重跑 evals：
技能漂移（外部依赖变化/模型行为变化）→ 检测
——持续质量（不是一次门禁）
```

### 漂移的意义

```
技能是"活的产品"：
今天好的技能，明天可能漂移（依赖/模型/平台变化）
monitor = 持续体检（定期重测）
```

## 6. skill-governance-toolkit

### 六工具

| 工具 | 功能 |
|---|---|
| skill-find | 技能发现 |
| skill-evaluate | 单技能 0-100 评分（9 维） |
| skill-compare | 技能对比 |
| library-audit | 整库审计（6 类违规） |
| skill-build-portable | 可移植构建 |
| integration-init | 集成初始化 |

### 评分维度（9 维）

```
包括 D9 Safety（安全维度）：
格式/文档/触发/安全/可移植性等
——单技能全面评分
```

### library-audit 六类违规

```
① 交接问题 ② token 预算 ③ 命名
④ 可移植性标签 ⑤ 多工具兼容 ⑥ 安全基线
——整库体检（发现系统性问题）
```

### 三种交付模式

```
CLI（CI 门禁）
MCP（AI agent 作为工具调用）
Docker（沙箱化）
——按场景选交付
```

### changed-only 门禁

```
sgt ci-init --github / --gitlab：
只检查变更的技能（PR 门禁高效）
——增量检查（大库友好）
```

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "门禁只查格式" | 覆盖安全/冲突/评估（七命令） |
| "一次检查够" | monitor 持续检测漂移 |
| "静态检查就够" | test 跑真实 agent evals |
| "工具选一个" | 可组合（guard + toolkit） |
| "评分是摆设" | 阈值门禁（分数说话） |

## 8. 面试高频问法

| 问题 | 回答要点 |

| secure 查什么？ | 危险模式/注入/危险命令 |
| monitor 是什么？ | 定时重跑 evals（漂移检测） |

### 面试加分表达

> "质量门禁是治理自动化的核心：skill-guard 七命令覆盖全生命周期——validate（格式+评分）、secure（危险模式/注入扫描）、conflict（触发词重叠）、test（真实 agent evals）、check（合并门禁）、monitor（定时重测防漂移）、catalog（注册表）。skill-governance-toolkit 补上 9 维评分（含安全）与整库审计（6 类违规），支持 changed-only PR 门禁。质量从'人把关'到'门禁自动化'。"

> 🎯 核心要点：门禁自动化（一致性/全面/可重复）；skill-guard 七命令（validate→catalog 全生命周期）；secure 安全扫描 + conflict 触发词重叠；test 真实 evals + monitor 漂移检测；toolkit（9 维评分/6 类审计/三种交付/changed-only）；技能是"活的产品"（持续体检）。
