## 1. 为什么技能需要生命周期

### 一次性的问题

```
技能写完就完事？
① 没有标准（质量靠自觉）
② 没有门禁（问题带到使用）
③ 没有版本（改了什么不知道）
④ 没有废弃（坏技能永远在）
——需要全周期治理
```

### 生命周期的价值

```
① 每阶段有产出（可检查）
② 每阶段有门禁（质量把关）
③ 版本可追溯（改动留痕）
④ 废弃有流程（清理干净）
——技能 = 活的产品（持续管理）
```

### 2026 实践

```
生产级技能仓库的生命周期：
DEFINE → DEVELOP → SHIP（简化版）
DEFINE → PLAN → BUILD → VERIFY → REVIEW → SHIP（六阶段版）
——"技能 = 工作流程 + 质量门禁 + 最佳实践的标准化封装"
```

## 2. 六阶段生命周期

### 六阶段总览

| 阶段 | 做什么 | 产出 |
|---|---|---|
| DEFINE | 需求澄清与范围界定 | 规格说明 |
| PLAN | 设计技能结构 | 设计方案 |
| BUILD | 实现技能 | SKILL.md + 配套 |
| VERIFY | 测试验证 | 评估数据 |
| REVIEW | 审查 | 审查意见 |
| SHIP | 发布 | 发布版本 |

### 每阶段对应斜杠命令

```
/spec（DEFINE）/plan（PLAN）/build（BUILD）
/test（VERIFY）/review（REVIEW）/ship（SHIP）
——生命周期工具化（斜杠命令驱动）
```

### 核心理念

```
技能 = 工作流程 + 质量门禁 + 最佳实践的标准化封装
每阶段 = 一个可检查的节点
```

## 3. 每阶段的产出与门禁

### DEFINE：需求与范围

```
产出：规格说明（做什么/不做什么）
门禁：范围明确（避免膨胀）
——先定义再开发（不做"边写边想"）
```

### PLAN：设计

```
产出：技能结构设计（目录/正文/脚本/评估方案）
门禁：结构合规（模板/规范）
——设计先行（阶段 3 的结构原则）
```

### BUILD：实现

```
产出：SKILL.md + scripts/references/assets
门禁：质量门禁（validate/secure）
——实现过门禁（阶段 3 的方法）
```

### VERIFY：测试

```
产出：评估数据（with/without 对比）
门禁：达标（评分/阈值）
——数据说话（阶段 3 的 06 篇）
```

### REVIEW：审查

```
产出：审查意见
门禁：通过（人工或 AI 辅助）
——第二双眼睛（代码审查同款）
```

### SHIP：发布

```
产出：发布版本（SemVer + changelog）
门禁：全部前置通过
——合规发布（阶段 4 的分发）
```

## 4. 版本策略

### SemVer

```
x.y.z：
major（破坏性变更）/ minor（新功能）/ patch（修复）
例：1.2.0 → 2.0.0（破坏性）
```

### 版本实践

```
① 每次变更递增（minor/patch）
② 破坏性变更升 major
③ changelog 记录（改了什么）
④ 版本锁定（使用者固定版本）
——版本 = 变更的账本
```

### 版本与依赖

```
技能依赖声明（skill.yaml）：
依赖的工具/模型/MCP 版本
依赖变化 → 技能可能漂移（monitor 检测）
——依赖管理像软件包
```

## 5. 废弃管理

### 为什么需要废弃

```
坏技能/被替代技能/无人用的技能：
不清理 → 占描述预算 + 误导使用者
——需要明确的废弃流程
```

### 废弃流程

```
① 标记 deprecated（frontmatter/文档）
② 说明替代品（指向新技能）
③ 保留期（给迁移时间）
④ 删除/归档（清理）
——平滑废弃（不突然消失）
```

### 废弃注意

```
① 使用者要能发现废弃（标记醒目）
② 替代路径要清晰（别断供）
③ 数据保留（历史版本/文档）
——废弃 = 负责任的清理
```

## 6. 7 步部署流程

### 标准化部署（百度实践）

```
① 环境准备（云服务器 + 安全组限制访问）
② 初始化技能仓库（拉取基础模板）
③ 定义技能元数据（name/version/inputs/outputs）
④ 配置行为约束（系统提示限制操作范围）
⑤ CI/CD 集成（门禁/发布）
⑥ 安全扫描（合并前强制）
⑦ 发布流程（版本化发布）
```

### 部署要点

```
① 环境隔离（安全组限制）
② 模板起步（规范内建）
③ 元数据完整（接口定义）
④ 门禁强制（CI 前置）
⑤ 安全扫描（入库前）
——从零到生产的标准化路径
```

### 与五阶段学习路径的映射

```
7 步部署 = 阶段 2-5 的综合：
模板（阶段 2）→ 元数据（阶段 1/5）→ 门禁（阶段 3）
→ 跨平台（阶段 4）→ 安全（阶段 1/5）
——学习路径的工程化落地
```

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| "写完就发布" | 六阶段每步有门禁 |
| "版本随意" | SemVer（变更账本） |
| "废弃直接删" | 标记 + 替代 + 保留期 |
| "生命周期是文档" | 工具化（斜杠命令驱动） |
| "部署一次完事" | 持续（monitor/更新/重扫） |
