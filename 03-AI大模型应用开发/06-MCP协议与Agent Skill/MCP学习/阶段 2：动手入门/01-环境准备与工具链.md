## 1. 环境要求速查

| 组件 | 版本要求 | 说明 |
|---|---|---|
| Python | 3.10+（推荐 3.12+） | 官方 mcp SDK 与 fastmcp 均要求 3.10+ |
| Node.js | 18+（推荐 20.19+/22.12+） | TS SDK 18+；Inspector 需 18+ |
| uv（可选） | 最新 | Python 环境/依赖管理，比 pip+venv 快 10 倍 |
| npm | 随 Node | 安装 TS SDK 与 Inspector |
| 编辑器 | 任意 | VS Code / JetBrains 均可 |

> 💡 本仓库 Python 虚拟环境体系（`03-AI.../Python虚拟环境/`）推荐 uv——下面所有示例用它；不熟悉 uv 也可以用 `python -m venv`。

## 2. SDK 选型：三条路线

| 路线 | 包 | 版本（2026-08） | 适合 | 学习建议 |
|---|---|---|---|---|
| Python 高层 | `fastmcp` | 3.1.x | 快速写工具、追求少样板 | **本阶段主路线** |
| Python 官方 | `mcp` | 1.26 | 底层控制、自定义传输 | 阶段 3 再深入 |
| TypeScript | `@modelcontextprotocol/sdk` | 1.27.1 | 前端/Node 生态 | 本阶段做对照 |

**三条路线的关系**：

```text
fastmcp（高层，推荐入门）
   └── 基于 ──> mcp（官方 SDK，底层）
TS SDK（官方，独立实现，Zod 生态）
```

- fastmcp 的优点：`@mcp.tool` 装饰器自动从函数签名+docstring 生成 JSON Schema，内置 FastMCP 类、自动类型校验（Pydantic）。
- 官方 mcp SDK 的优点：协议层完全可控（Server 类、请求处理器），适合生产级与学习协议细节。
- TS SDK：TypeScript 团队的选择；`McpServer` 高层 API + Zod schema 定义工具参数。

## 3. Python 环境安装

```bash
# 1) 安装 uv（Windows PowerShell / Linux）
curl -LsSf https://astral.sh/uv/install.sh | sh
# Windows 可用: pip install uv

# 2) 建项目并锁定 Python 版本
uv init mcp-demo && cd mcp-demo
uv python pin 3.12

# 3) 安装依赖（主路线：fastmcp）
uv add fastmcp
# 对照路线：官方 SDK
# uv add "mcp[cli]"

# 4) 验证
uv run python -c "import fastmcp; print(fastmcp.__version__)"
```

**验证输出预期**：`3.1.x`（fastmcp 3.x 系列，2026-02-18 发布 3.0，含 OAuth/OpenTelemetry/composition 能力）。

> ⚠️ 常见坑：Windows 上 `curl | sh` 不可用，直接用 `pip install uv`；装完新开终端让 PATH 生效。

## 4. Node 与 TypeScript 环境

```bash
# 1) 安装 Node 22 LTS（推荐用 nvm 或官方安装包）
node -v   # v22.x

# 2) 建项目
mkdir mcp-ts-demo && cd mcp-ts-demo
npm init -y

# 3) 安装 TS SDK（v1.27.1 稳定版）
npm i @modelcontextprotocol/sdk zod

# 4) 验证
node -e "console.log(require('@modelcontextprotocol/sdk/package.json').version)"
# 输出 1.27.1
```

## 5. 2026-07-28 规范的 v2 迁移预告

**背景**：MCP 协议 2026-07-28 规范定稿（无状态革命，阶段 1 的 04 篇已详解），官方 SDK 随之进入 v2 测试阶段。**本阶段学习用 v1 稳定版完全没问题**，但要了解迁移路径：

| 语言 | v1（当前稳定） | v2（2026-07-28 规范对应） |
|---|---|---|
| TypeScript | `@modelcontextprotocol/sdk` 1.27.x | **拆分为两个新包**：`@modelcontextprotocol/server` + `@modelcontextprotocol/client`（全新安装，不是版本升级） |
| Python | `mcp` 1.26（类名 `FastMCP`） | `mcp 2.0.0b1`：**`FastMCP` 重命名为 `MCPServer`** |

**v2 三个弃用特性（12 个月后移除）**：

| 弃用特性 | 替代方案 |
|---|---|
| Roots（根目录声明） | 工具参数或资源 URI |
| Sampling（模型采样请求） | 直接调用 LLM 供应商 API |
| Logging（协议内日志） | stderr 或 OpenTelemetry |

**行动建议**：
- 本阶段学习用 v1（生态成熟、教程多）。
- 生产项目新建时评估 v2 beta（官方提供 `mcp-migration` 风险评估工具；TS 有 `npx @modelcontextprotocol/codemod@beta v1-to-v2 .` 机械迁移）。
- 面试口径：**"2026-07-28 规范移除会话与握手，SDK 进入 v2 阶段——TS 拆包、Python 改类名，但 v1 仍稳定可用。"**

## 6. 工具链全景

| 工具 | 用途 | 本阶段角色 |
|---|---|---|
| fastmcp | 写 Python Server/Client | 主力 |
| mcp CLI | `mcp` 官方 SDK 自带命令（dev/run） | 调试辅助 |
| MCP Inspector | 可视化调试 Server | 05 篇 |
| Claude Code | 接入真实客户端验证 | 06 篇 |
| curl | 手测 Streamable HTTP | 04 篇 |
| uvicorn | fastmcp HTTP 模式内置服务 | 04 篇（无需手装） |

**动手前确认清单**：

- [ ] `uv run python -c "import fastmcp"` 无报错
- [ ] `npx @modelcontextprotocol/inspector --version` 可执行（Node 18+）
- [ ] 新建项目目录 `mcp-demo/` 已初始化
- [ ] 编辑器终端使用 UTF-8（Windows 中文路径/注释不乱码）

> 🎯 **核心要点**：工具链只有三个决策——Python 选 fastmcp 3.x（入门）、TS 选官方 SDK 1.27 + Zod（对照）、版本认知记住"v1 稳定、v2 在路上"（2026-07-28 规范：TS 拆包 / Python 改名）。配好这三样，阶段 2 后面 7 篇全是写代码与调试。
