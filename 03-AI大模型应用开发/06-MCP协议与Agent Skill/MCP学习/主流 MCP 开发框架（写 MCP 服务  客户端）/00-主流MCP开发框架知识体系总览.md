## 3. 学习路线推荐

**路线 A：全景速览（2-3 小时）**
01 → 07 → 08 的自测部分。建立"语言×框架×场景"的选型心智，能回答"写 MCP 用什么语言什么框架"。

**路线 B：主力语言深潜（推荐，半天-1 天）**
01 → 你的主力语言篇（Java 开发者必读 04，Python 读 02，前端读 03）→ 07 → 08。**用主力语言完整实现一个 Server 并跑通客户端**——本库 Java 后端主线，建议 Java 篇全读。

**路线 C：全生态工程师（1-2 天）**
01 → 02 → 03 → 04 → 05 → 06 → 07 → 08。横向对比六大生态，建立"框架选型顾问"级认知——面试"为什么选这个框架"的弹药库。

> 💡 与阶段体系的关系：`阶段 2：动手入门` 用 FastMCP 跑通最小链路，`阶段 3/4` 用生产级视角使用框架——**本体系补充"框架本身"的横向视角**：FastMCP 之外还有哪些选择、各语言生态如何、v2 迁移怎么走。

## 5. 核心概念速查

| 概念 | 一句话速记 |
|---|---|
| Tier 1 SDK | 官方指定 100% 协议合规：TypeScript/Python/Go(官方)/C# |
| Tier 2 SDK | Java/Rust（合规性次一级，仍在官方维护） |
| Tier 3 SDK | Swift/Ruby/PHP（社区/官方低优先） |
| day-one 合规 | 2026-07-28 无状态规范发布当天即支持（Tier 1 全部做到） |
| TS v2 拆包 | `@modelcontextprotocol/sdk` 拆为 `server` + `client` 两包 |
| Python v2 改名 | `FastMCP` 类改名为 `MCPServer`（官方 mcp 包内） |
| FastMCP | PrefectHQ 的 Python 高层框架（3.x），非官方但最流行 |
| Zod | TS 生态 Schema 库：类型即工具 Schema（自动转 JSON Schema） |
| MCP Java SDK | 官方 Java SDK（io.modelcontextprotocol.sdk），与 Spring AI 合作维护 |
| Spring AI starters | spring-ai-starter-mcp-server/client 等，注解式 MCP 开发 |
| @Tool 注解 | Spring AI：方法标注即工具（自动注册） |
| mark3labs/mcp-go | Go 社区最流行框架（~8.3k 星），高层声明式 |
| 官方 go-sdk | Anthropic+Google 维护，Tier 1，底层但保证协议合规 |
| csharp-sdk | 官方 C# SDK，Tier 1，`dotnet add package ModelContextProtocol` |
| rmcp | 官方 Rust SDK（Tier 2，beta） |
| mcp-migration | Python 官方 v1→v2 迁移扫描工具 |
| v1-to-v2 codemod | TS 官方迁移工具：`npx @modelcontextprotocol/codemod@beta v1-to-v2` |
| Stateless | 2026-07-28 规范：无握手无会话，v2 SDK 全部按此重写 |
| 采用数据 | Tier 1 四 SDK 月下载约 5 亿；TS/Python 累计各破 10 亿 |

## 6. 常见疑问快答与关键数据

### 常见疑问

| 疑问 | 回答 |
|---|---|
| 写 MCP 一定要用官方 SDK 吗？ | 不一定——社区框架（FastMCP/mark3labs）基于官方 SDK 且效率更高；官方用于协议保证 |
| FastMCP 是官方的吗？ | 不是——PrefectHQ 维护；官方 Python SDK 的 v2 高层类叫 MCPServer |
| 该学几个框架？ | 主力语言一个精通 + 08 篇对照理解共性——框架高度同构，会一个其他半天上手 |
| v2 必须立刻迁移吗？ | 不必——12 个月弃用窗口 + 双代兼容；新项目直接 v2，存量按部署需求评估 |
| Java 写 MCP 选什么？ | Spring AI starter（@Tool 注解 + STATELESS 模式），本库主线的答案 |
| 框架会频繁换吗？ | 协议是稳定层，框架是可换层——GitLab 从社区框架迁官方 SDK 是有界重构 |
| 与阶段 2/3 用的 FastMCP 什么关系？ | 本体系是横向视角：FastMCP 之外还有哪些选择、怎么选 |

### 学习心态

```
框架知识体系的定位：不是"学某个框架的教程"，而是"框架选择的方法论"
01 看世界（Tier/全景）→ 02-06 看生态（各语言）
→ 07 做决策（选型/迁移）→ 08 验能力（对照/自测）
核心产出：看到任何 MCP 项目，能判断"它为什么选这个框架、对不对"
```

**为什么需要"框架视角"**：阶段 2-4 全程只用了 FastMCP——如果只停留在"会用 FastMCP"，遇到"Java 团队要做 MCP""Go 基础设施要不要官方 SDK""v2 迁移怎么走"这类真实问题就会卡住。本体系的产出不是"多会几个框架"，而是**"在任何框架面前都能快速上手、都能判断选型对错"的迁移能力**——五要素共性（08 篇）与三层心智（01 篇）就是这套能力的两个支点。读完本体系再回头看阶段 2 的 FastMCP 代码，你会看到它背后的协议、生态与选型逻辑——**从"会用"到"看懂"，是框架知识体系的真正门槛**。

## 10. 本体系的阅读地图与版本提醒

**阅读地图**（与知识库其他体系的联动）：本体系是"框架横向视角"，与 `MCP学习/` 下的主体系（协议字典）、阶段 1-4（学习路径）构成完整三角——**协议知识（主体系）+ 工程能力（阶段体系）+ 框架视野（本体系）**三者齐备，才是完整的 MCP 知识结构。Java 后端读者建议与 `02-.../06-Spring全家桶/Spring AI` 体系联动（Spring AI 的 MCP 集成细节在那套体系里有完整模块）；AI 应用开发者可与 `Agent Skill学习` 体系联动（技能与框架的组合模式）。

**版本提醒**：本体系所有版本数据以 2026-08 为基准（TS v1.29/Python v1.28/FastMCP 3.4/Java SDK 1.1.0/Spring AI 2.0.0-M3/go-sdk v1.2+/csharp-sdk 稳定）；**框架版本迭代快于协议版本**——使用前先核对各生态篇的"版本基线"小节，重要项目锁定版本并订阅官方 changelog。2026-07-28 规范是当前分水岭：Tier 1 已 day-one，v2 稳定版预计 2026-08 起陆续发布——**本体系结论在 v2 稳定前依然有效，迁移相关结论以 07 篇清单为准**。

**最后的话**：框架知识体系与其他知识体系最大的不同是"保质期"——协议知识可以吃五年，框架版本半年一变。所以本体系教你的核心不是"记住 FastMCP 的 API"（它会变），而是三样不变的东西：**Tier 心智**（合规承诺怎么分级）、**五要素共性**（任何框架怎么快速上手）、**选型方法论**（决策树与迁移清单）。版本会过时，这三样不会——**带着这三样去看任何框架的文档，你读到的不是"新 API"，而是"老朋友换了身衣服"**。这就是本体系的最终交付。

**本体系的三个使用场景**（读完后怎么用）：① **选型场景**——团队要写 MCP 时，跑 07 篇决策树（团队栈→端→官方/社区），用 02-06 篇对号入座，把结论写进 ADR；② **学习场景**——遇到新框架，用 08 篇"五问法"（实例/注册/Schema/Handler/传输）一小时上手，对照本体系各篇的代码形态找对应物；③ **面试场景**——用"锚点思维"（06 篇）讲选型逻辑，用"三层表达"（02 篇）讲工具熟练度，用 01 篇十条判断收尾。**三个场景覆盖"做选择、学新东西、讲清楚"三个高频动作**——本体系不是读完就完的教程，而是可以反复查阅的决策手册。

**阅读顺序建议**：时间紧（2 小时）读 00 + 01 + 07 + 08 的自测——拿到"选型方法论 + 十条判断"；时间中（半天）加读主力语言篇——拿到"能写代码"；时间充裕（1-2 天）全读——拿到"六生态顾问级视野"。**每篇的读法**：先看"核心要点"（粗体句），再扫表格（速查面），最后补代码与问答（落地样）——与阶段体系的读法一致：核心要点是锚、表格是面、代码是样。**各篇的"完成标准"**：读完一篇能脱稿讲出核心要点粗体句 + 回答该篇"常见问题快答"（02-06 篇均有）——讲得出才算读完，这是与阶段体系一致的毕业标准。**总完成标准（本体系毕业）**：20 道自测 ≥80% + 主力语言独立写 Server + 能现场走选型决策树——三项齐备即毕业，可进入真实项目的框架实践。**与主体系的分工确认**：本体系聚焦"框架"（Tier/生态/选型/迁移），协议细节（原语/传输/生命周期）查 `MCP/` 主体系 00-08，工程实践（认证/无状态/测试/部署）查阶段 3，项目组合（MCP+Skill）查阶段 4——**四个视角各有归属，本体系是"选框架"的入口**：先选对框架，再按主体系与阶段体系把框架用好。**阅读完成的最终检验**：合上本体系，能回答三个问题——① 给一个场景（语言+端+合规要求）能说出框架与理由；② 给一个新框架能在 1 小时内上手（五问法）；③ 给一个存量 Server 能评估 v2 迁移的成本与路径（七步清单）——**三个"能"全部成立，本体系的价值就兑现了：不是记住了九篇文档，而是拥有了三套可迁移的方法**。
