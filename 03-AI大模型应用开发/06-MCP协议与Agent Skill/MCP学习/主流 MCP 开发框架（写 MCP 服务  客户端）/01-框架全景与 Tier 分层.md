## 1. 官方 Tier 体系

MCP 官方对 SDK 的分级（决定"协议合规保证"的等级）：

| Tier | 语言 | 合规承诺 | 维护方 | 2026 状态 |
|---|---|---|---|---|
| Tier 1 | TypeScript | 100% 协议合规 | Anthropic | v1.29 稳定；v2 拆包 alpha |
| Tier 1 | Python | 100% | Anthropic | v1.28 稳定；v2.0.0b1 beta |
| Tier 1 | Go（官方） | 100% | Anthropic + Google | v1.2+ 稳定（2026 初发布） |
| Tier 1 | C# | 100% | Microsoft（社区） | 稳定成熟 |
| Tier 2 | Java | 高（次一级） | 官方 + Spring AI 团队 | 1.1.0 GA（2026-03） |
| Tier 2 | Rust | 高（beta） | 官方 | beta（rmcp） |
| Tier 3 | Swift/Ruby/PHP | 社区级 | 官方低优先 | 活跃度低 |
| TBD | Kotlin | 待定 | — | 规划中 |

**Tier 的工程含义**：Tier 1 = "2026-07-28 规范发布当天就能用新协议"（day-one 合规）；Tier 2 = 合规性次一级、跟进稍慢；Tier 3 = 靠社区。**选框架的第一问不是"哪个好用"，而是"你的协议合规要求是几级"**——做基础设施选 Tier 1，做业务 Server Tier 1/2 都够。

**一个重要的"官方"澄清**：`MCP/` 主体系与阶段体系用的 FastMCP 是 **PrefectHQ 的社区框架**（非官方），但它建立在官方 mcp SDK 之上；官方 Python SDK 自带的高层类在 v2 中改名 `MCPServer`——**"官方 vs 社区"的边界在 Python 生态尤其需要分清**（02 篇详述）。

## 3. 2026-07-28 规范与 SDK 时间线

2026-07-28 是 MCP 发布以来最大的协议修订（无状态革命），SDK 跟进时间线：

| 时间 | 事件 |
|---|---|
| 2026-02 | Python SDK v1.26（正确性）→ v1.28（3.14 支持）；TS v1.27.1（安全修复） |
| 2026-02-18 | FastMCP 3.0（OAuth/OTel/组合） |
| 2026-03 | Java SDK 1.0.0 GA → 1.1.0（2025-06-18 规范）；Spring AI 2.0.0-M3（MCP 注解迁入核心） |
| 2026-07-28 | **规范定稿**：四个 Tier 1 SDK 同日发布 beta（TS/Python/Go/C#） |
| 2026-08 起 | Tier 1 稳定版陆续发布（约 4-6 周后）；v2 成为主线 |
| 未来 12 个月 | 旧特性（Roots/Sampling/Logging）弃用窗口 |

**v2 的本质变化**：不是"加功能"而是"为无状态重写"——TS 拆包、Python 改名 MCPServer、Go/C# 按新协议重写。**v2 迁移是 2026 下半年所有 MCP 开发者的必修课**（07 篇迁移清单）。

| 数据点 | 数值 | 含义 |
|---|---|---|
| Tier 1 四 SDK 月下载 | 约 5 亿次 | MCP 是 AI 基建事实标准 |
| TS/Python 累计下载 | 各破 10 亿 | 双雄主导 |
| TS v1.29 依赖项目 | 3.47 万+ | 生态最大 |

| csharp-sdk | ~4.1k 星、Tier 1 | .NET 唯一官方解 |

**采用数据的解读**：① **生态集中**——TS/Python 吃掉大头，其余语言在各自阵营（Java 进 Spring AI、Go 进 CLI/基础设施、C# 进 .NET）；② **社区框架仍然重要**——FastMCP 与 mark3labs 的高层 API 是"应用层开发"的主流选择，官方 SDK 偏底层；③ **迁移是常态**——GitLab CLI 的迁移证明"框架可以换，协议不换"（07 篇迁移方法论）。

## 5. 框架选择的三层心智

选框架的三层决策（本体系的核心心法）：

| 层 | 问题 | 答案来源 |
|---|---|---|
| 第一层：语言 | 团队会什么？部署生态是什么？ | 团队技术栈（Java 后端选 Java，见 04 篇） |
| 第二层：官方 vs 社区 | 要协议保证还是开发效率？ | 01 篇 Tier 体系 + 07 篇对比矩阵 |
| 第三层：高层 vs 底层 | 写业务 Server 还是写基础设施？ | 各生态篇（02-06） |

**三层心智示例**（本库 Java 后端的典型决策）：
- 第一层：Java（团队主线，Spring 生态）；
- 第二层：官方 Java SDK（Tier 2 合规 + Spring AI 合作维护，比社区框架稳）；
- 第三层：业务 Server 用 Spring AI starters（高层注解），协议深度定制用 Java SDK 底层类。

## 6. 各生态定位详表

同一问题"你的语言在 MCP 里是什么角色"，六生态各自答案：

| 语言 | 生态角色 | 一句话定位 | 典型使用者 |
|---|---|---|---|
| TypeScript | 参考实现 | 协议行为基准，前端/全栈主场 | 前端团队、全栈 Agent 应用 |
| Python | AI 开发者主力 | 数据/AI 生态最顺，FastMCP 效率高 | AI 工程师、数据团队 |
| Java | 企业后端 | Spring 生态无缝，注解式成本最低 | 企业后端团队（本库主线） |
| Go | 基础设施 | 单二进制部署，CLI/网关场景 | 平台团队、CLI 工具 |
| C# | .NET 企业 | 银行/制造/政府场景唯一官方解 | .NET 企业 |
| Rust | 高性能边缘 | 性能+安全，beta 状态慎上生产 | 基础设施/嵌入式 |

**定位判断法**：问"你的组织已经在用什么语言栈"——**MCP 框架的选型 80% 由既有技术栈决定**，框架差异只影响剩下 20%（官方/社区、高层/底层）。

## 7. 采用数据深读

| 信号 | 解读 |
|---|---|
| GitLab CLI 迁移 | 社区框架 → 官方 SDK 的真实案例："长期支持"驱动，迁移约 1 天 |
| AWS/Cloudflare/Microsoft 采用 | 超大规模云把 MCP 当基础设施——协议稳定性有巨头背书 |
| TS/Python 各破 10 亿下载 | 双雄格局短期不会变——新语言生态要追赶的是这两个 |
| Java 企业需求 | Tier 2 但 Spring AI 的集成深度让它实际使用率很高 |
| Rust beta 状态 | 性能派的选择，但"2026-07-28 规范 beta 跟进"意味着还在追赶 |

**采用数据的另一面**：下载量与星标反映"生态热度"，但不直接等于"生产可靠性"——官方注册表对 Server 的扫描显示 41% 零认证、33% 高危漏洞（阶段 3 数据），**框架热度和使用安全是两回事**。选框架时热度决定"遇到问题有多少人帮你"，Tier 决定"协议会不会掉队"，安全实践（认证/审计/依赖扫描）则完全取决于你的实现——三个维度缺一不可。这也是为什么本体系强调"框架是手段、协议是目的"：**再热的框架也替代不了你自己的安全与测试纪律**。

**2026 框架格局的十个判断**（本体系的浓缩结论）：① Tier 1 四语言是默认答案；② TS/Python 双雄短期不变；③ Java 靠 Spring AI 集成深度补 Tier 2 短板；④ Go 的社区/官方双轨将长期并存；⑤ C# 是唯一"官方即唯一"；⑥ Rust 双 beta 等规范稳定收敛；⑦ v2 迁移是 2026 下半年主线；⑧ 认证能力成为框架差异化新战场；⑨ 社区框架的合规时间线是选型风险项；⑩ 协议是稳定层、框架是可换层——十个判断覆盖本体系全部结论，面试前背熟这十条，框架问题基本无死角。

**Tier 体系的历史与未来**：Tier 体系诞生于 2026-07-28 规范定稿前后（规范 10 周 RC 期同步给 SDK 定级），是官方对"协议合规承诺"的制度化——**它的出现本身是 MCP 走向成熟的标志**（协议有了分级治理）。未来可能的演变：① Kotlin 定级后 JVM 阵营更完整；② Tier 3 语言若有社区爆发可能升 Tier 2（Swift 的 Apple 生态是潜在候选）；③ v2 稳定后 Tier 1 的"day-one"承诺会成为新常态（新规范发布当天四语言齐发）——**Tier 是动态的**，本体系 2026-08 的快照结论需要按季度复核；复核的方法就是 01 篇的框架：看官方 Tier 表更新、看各语言 day-one 记录、看社区框架合规时间线。

**生态全景的"画面感"**：把 01 篇的内容浓缩成一句话画面——**MCP 的框架世界是一个"Tier 金字塔 + 语言分阵营"的稳定结构**：塔尖是四个 Tier 1 语言（TS/Python 双雄带头），塔身是 Java/Rust（各有阵营：Spring/性能），塔基是 Tier 3（等待技术栈锁定的召唤）；每个语言阵营内部又分"官方 vs 社区"两派（Python 的 FastMCP/官方、Go 的 mark3labs/官方、C# 无竞争）——**这张"金字塔 + 阵营"画面就是框架全景的心智模型**，比任何表格都好记、好讲、好扩展（新框架出现时，先问它落在金字塔哪层、属于哪个阵营）。**01 篇的完成标准**：能脱稿画出 Tier 金字塔（语言+状态）、讲出三层选型心智（团队栈→端→官方/社区）、背出十条判断——三项齐备，框架全景篇毕业，可以进入 02-06 篇的生态深潜。**全体系的完成标准**（与 08 篇呼应）：30 道自测 ≥80% + 主力语言与第二语言各写一个 Server（1 小时目标）+ 能向团队讲一次"为什么选这个框架"（ADR 口头版）——三项齐备，"主流 MCP 开发框架"体系毕业。

**数据的一句话结论**：**生态头部集中（TS/Python）+ 各语言按阵营归位（Java→Spring、Go→基础设施、C#→.NET）——选框架先认阵营，再比细节**。

## 8. 常见误区

| 误区 | 真相 |
|---|---|
| "官方 SDK 一定最好用" | 官方保证的是合规不是效率——业务开发社区高层框架（FastMCP）更顺手 |
| "FastMCP 是官方维护" | PrefectHQ 社区维护，虽基于官方 SDK |
| "Tier 2 不能用" | Tier 2（Java/Rust）完全可生产，只是合规跟进晚于 Tier 1 |
| "v2 发布就要全量迁" | 12 个月弃用窗口 + 双代兼容——节奏由部署需求定 |
| "框架选了不能换" | 协议是稳定层，框架迁移是有界重构（GitLab 案例） |
| "下载量=质量" | 下载量反映生态规模，Tier 反映合规承诺——两个维度分开看 |

**Tier 体系之外的选型变量**：Tier 是"合规承诺"的分级，但真实选型还有三个变量——**维护活跃度**（提交频率/issue 关闭率，mark3labs 90% 关闭率是加分）、**文档与教程密度**（决定团队上手速度）、**与你现有基础设施的集成度**（Spring AI 之于 Spring、Express 之于 Node）。这三个变量在 Tier 表里看不到，却常常是"业务选型"的决定因素——**完整选型 = Tier（合规底线）× 效率（社区/高层）× 集成（生态耦合）三维决策**。本体系各生态篇（02-06）都在补这三维：Python 讲 FastMCP 的扩展能力（效率维），Java 讲 Spring 集成（集成维），Go 讲双轨维护状态（活跃度维）——读完各篇再回头看 Tier 表，你会看到一张"三维立体"的框架地图而非一张平面分级表。

**关于"官方"的澄清**：Go 生态的"官方 SDK"（modelcontextprotocol/go-sdk）是 Anthropic 与 Google 联合维护的 Tier 1 实现，而社区框架 mark3labs/mcp-go 虽然使用人数更多，却不在官方 Tier 体系内——**"官方"的含义是"协议合规有承诺"，不是"用的人多"**。这一点在 Python（FastMCP 非官方）、Go（mark3labs 非官方）两处最容易混淆；C# 是唯一"官方即唯一"的生态（csharp-sdk 无社区竞争对手），选型最省心。**记住：Tier 体系是"合规承诺"的分级，不是"流行度"的排名——做基础设施看 Tier，做业务看效率，两者都要时先 Tier 后效率**。

## 9. 生态发展简史

各生态的 MCP 演进时间线（理解"为什么是现在这个格局"）：

| 时间 | 事件 |
|---|---|
| 2024-11 | MCP 开源；TS/Python 官方 SDK 起步 |
| 2025 | TS/Python 成熟；mark3labs/mcp-go 崛起（GitHub 官方 Server 采用） |
| 2025-11 | 2025-11-25 规范（Streamable HTTP 成远程标准） |
| 2026-02 | Java SDK 1.0.0 GA；FastMCP 3.0；TS v1.27.1 |
| 2026-03 | Java SDK 1.1.0；Spring AI 2.0.0-M3（MCP 官方化）；官方 go-sdk 发布 |
| 2026-07-28 | 无状态规范定稿；四 Tier 1 SDK day-one beta |

**简史的启示**：**格局由"谁先到"与"谁官方化"共同塑造**——mark3labs 早到一年成为 Go 社区共识（官方 SDK 后来也难撼动应用层）；Spring AI 官方化让 Java 生态一步到位；**2026-07-28 是格局重塑点**（Tier 1 全部 day-one，社区框架的合规时间线成为选型分水岭）。

## 10. 生态观察与面试速记

**生态观察**（2026 框架格局的五个判断）：
1. TS/Python 双雄格局短期不变（累计下载各破 10 亿）；
2. Go 的"社区 vs 官方"是唯一双轨博弈（其余语言各归其位）；
3. Java 靠 Spring AI 的集成深度弥补 Tier 2 的位置；
4. v2 重写是 2026 下半年主线（四 Tier 1 同时 beta）；
5. 认证能力成为框架差异化的新战场（FastMCP/TS 内建 vs Java 靠 Security）。

**面试速记**：
1. Tier 1 = TS/Python/Go(官方)/C#，day-one 合规；Tier 2 = Java/Rust。
2. 三层选型：团队栈 → 官方/社区 → 高层/底层。
3. 框架格局由"先到"与"官方化"塑造（mark3labs 早到、Spring AI 官方化）。
4. 采用数据：月 5 亿下载、TS/Python 各破 10 亿。
5. 金句：协议是稳定层，框架是可换层；Tier 是选型宪法，技术栈是先决变量。

> 🎯 **核心要点**：框架全景 = 官方 Tier 体系（Tier 1 四语言 day-one 合规）+ 语言生态地图（六生态各有定位：参考实现/AI 主力/企业后端/基础设施/.NET/高性能）+ 生态简史（先到与官方化塑造格局）+ 2026-07-28 时间线（v2 重写是主线）+ 采用数据（月 5 亿下载、大厂背书、GitLab 迁移案例）+ 三层选型心智（语言→官方/社区→高层/底层）。**第一问永远是"协议合规要几级"，第二问才是"哪个 API 好用"**——Tier 是框架选择的宪法级变量，而"团队技术栈"是 Tier 之前的先决变量。
