## 1. README 交付规范

README 是项目的第一印象，结构六段式：

```markdown
# 智能客服 Agent（MCP + Agent Skill 组合实战）

> 基于 MCP（工具）与 Agent Skill（流程）的智能客服：自然语言对话完成
> 订单查询/改单/退款/投诉升级/报表，支持 MRTR 人工确认与只读安全默认。

## 功能
- 5 个业务场景：查询/改单/退款/升级/报表（附演示命令）
- 工具层：6 个 MCP 工具（阶段 3 生产级标准）
- 流程层：3 个 Agent Skill（SKILL.md，政策知识外置）

## 架构
（架构图，见 docs/architecture.md）
一句话：编排器负责意图与流程，MCP 提供工具，Skill 提供知识，三层分离。

## 快速开始
1. 安装：pip install -e . ; 2. 造数据：python -m data.seed
3. 启动：python -m orchestrator.main（或 Claude Code 接入）

## 测试与质量
pytest tests/（三层测试：工具/技能/场景，mock LLM 确定性回归）
成本基线：单次对话 <10K token（约 0.01-0.05 元）

## 安全
只读默认、写操作 MRTR 确认、审计日志、无密钥入库（详见 docs/security.md）
```

**README 三原则**：① 首屏 30 秒讲清"这是什么 + 亮点是什么"；② 快速开始 3 步能跑；③ **测试与安全写进 README**（可信度信号，08 篇第 5 节同款"安全透明度"）。

## 2. 架构图与设计决策记录

**docs/architecture.md 双件套**：

**架构图**（02 篇三层图的成稿版）：三层框 + 数据流箭头 + 关键组件标注（编排器/Server/Skill/LLM/数据），**图的验收：不读代码能讲清一次对话的旅程**。

**设计决策记录（ADR）**——面试时"为什么这么设计"的弹药库：

| 决策 | 选项 | 选择 | 理由 |
|---|---|---|---|
| 编排模式 | 编排器 vs 指挥官 vs 三层 | 编排器 | 单 Agent 串行场景，可测性最好 |
| Skill 路由 | 关键词 vs 语义嵌入 | 关键词 | 5 个技能够用零成本；>10 升级嵌入（93.8%） |
| 工具/技能分工 | 政策进 Skill vs 进代码 | Skill | 政策可读可审可改（改文件生效） |
| 确认机制 | 代码内确认 vs MRTR | MRTR | 阶段 3 协议级模式复用 |
| Server 传输 | stdio vs HTTP | stdio（一体）/HTTP（扩展） | 演示简单；分离部署已具备 |
| 数据 | sqlite vs 真实 API | sqlite + 桩 | 可复现（测试与演示） |

**ADR 的价值**：面试官问"为什么"时，有记录的决策 = 有思考的过程——**"我考虑过 X 和 Y，因为 Z 选了 Y"比"我用了 Y"高一个档次**。

## 3. 演示脚本设计

5 分钟演示的标准节奏（面试/评审通用）：

| 时间 | 环节 | 内容 |
|---|---|---|
| 0:00-0:30 | 定位 | "这是一个 MCP+Skill 组合的智能客服，三句话讲完架构" |
| 0:30-2:00 | 场景演示 | 3 个剧本：查询（读工具）→ 退款（写工具+MRTR 确认）→ 投诉升级（Skill 流程） |
| 2:00-3:00 | 工程亮点 | 展示测试跑绿（三层测试）、成本数字（<10K token）、安全（只读默认） |
| 3:00-4:00 | 架构深挖 | 讲 ADR 两三个：为什么 Skill 装政策、为什么 MRTR |
| 4:00-5:00 | 扩展愿景 | Skills Over MCP / 指挥官模式 / 分离部署（07 篇扩展方向） |

**演示纪律**：① **提前录制关键剧本**（真实 LLM 有波动，录屏保底）；② 演示用确定性种子数据（01 篇边界样本）；③ 备好"翻车预案"（工具超时/LLM 漂移时的口头补救）；④ 结束时给"下一步"（扩展方向），把讨论引向你擅长的领域。

## 4. 作品集包装

**作品集三件套**（GitHub 项目页）：

| 组件 | 内容 |
|---|---|
| 项目主页 | README（六段式）+ 架构图 + 演示 GIF（CLI 录屏） |
| 文档 | docs/：architecture.md（ADR）+ requirements.md + security.md |
| 可复现性 | 一键启动脚本 + 种子数据 + 测试全绿徽章（CI） |

**作品集可信度信号**（面试官快速判断）：有测试（CI 徽章）、有文档（ADR）、有安全说明（只读默认）、有成本数据（token 记账）——**这四个信号比"功能多"值钱**，它们证明"这不是玩具"。

**双体系呈现**：项目同时展示 MCP（工具层）与 Agent Skill（流程层）两套能力——面试 AI 应用岗位时，能讲"工具与流程如何分工"是 2026 年的差异化优势（阶段 1 的双标准知识在此变现）。

## 5. 面试讲解路线

**10 分钟讲项目的最优顺序**（由浅入深、每层留钩子）：

```text
1. 一句话定位（30 秒）——"MCP 提供工具，Skill 提供流程，我做了一个客服 Agent"
2. 场景演示（2 分钟）——最精彩剧本：退款（涉及确认与政策）
3. 架构图（2 分钟）——三层 + 数据流，讲清"决策模型做、执行代码管"
4. 深度一：为什么工具与技能分开？（1 分钟）——原子可复用 vs 流程可改
5. 深度二：无状态与确认怎么落地？（1 分钟）——MRTR、句柄、只读默认
6. 深度三：LLM 不确定性怎么治理？（1 分钟）——元工具约束 + mock 测试 + 工具即事实
7. 成本与安全（1 分钟）——<10K token、审计日志、注入防护
8. 扩展与复盘（1 分钟）——Skills Over MCP、指挥官模式、踩过的坑
```

**钩子设计**：每讲一层留一个问题给面试官接（"您可能会问为什么用 MRTR…"），把对话引向你准备好的 ADR——**主动引导 > 被动应答**。

## 6. 简历一句话与项目亮点

**简历一句话**（项目栏）：

```text
智能客服 Agent（MCP + Agent Skill 组合）：
基于 MCP 提供 6 个业务工具、Agent Skill 封装 3 个业务流程，实现查询/退款/投诉升级
全链路，支持 MRTR 人工确认与只读安全默认；三层测试体系（工具/技能/场景）保证可回归，
单次对话成本 <10K token；架构采用编排器模式，状态无状态化支持水平扩展。
```

**项目亮点清单**（面试抽题自测）：① 三层架构与分层纪律；② 工具/技能映射矩阵（需求→能力）；③ MRTR 与只读默认（安全设计）；④ mock LLM 确定性测试（质量工程）；⑤ 成本记账与告警（工程素养）；⑥ 无状态与部署红利；⑦ 双体系（MCP+Skill）分工心智；⑧ Skills Over MCP 前沿视野。

## 7. 面试追问应对表

面试官常见追问与应对（08 篇第 5 节路线的补全）：

| 追问 | 应对要点 |
|---|---|
| "为什么不用现成框架？" | 自研编排器为了可测可讲；抽象层（llm.py）留了换框架的口子 |
| "LLM 答错了怎么办？" | 三层防御：元工具约束决策、工具即事实、mock 测试回归 |
| "政策改了怎么生效？" | Skill 是文件：改 SKILL.md 一行即生效（政策外置的红利） |
| "多用户并发呢？" | 无状态架构（阶段 3）：编排层会话外置 + Server 轮询可扩 |
| "成本怎么控制？" | 渐进式披露 + 工具数收敛 + 摘要压缩 + 成本告警 |
| "提示注入呢？" | 只读默认 + MRTR 确认 + 外发隔离 + 防幻觉剧本 |
| "和普通 API 服务什么区别？" | 调用者是模型：Schema 即接口、确认即护栏、审计即证据 |
| "下一步做什么？" | 指挥官模式/Skills Over MCP/分离部署（08 篇三个方向） |

**应对原则**：**每个追问都回到"设计决策"**（ADR）——追问不是考你代码，是考你"为什么这么设计"。答"因为 X 场景需要 Y，所以我做了 Z"永远好过"我用的这个库"。

## 8. 项目复盘模板

项目结束后用复盘模板沉淀（简历素材 + 下次项目经验）：

| 维度 | 问题 | 本项目的答案示例 |
|---|---|---|
| 时间 | 时间花在哪？ | 编排器决策调试 > 工具开发 > 部署 |

| 改进 | 重做会怎么改？ | 先写决策提示词测试再写编排器 |
| 复用 | 哪些资产可带走？ | 三层测试框架、编排器骨架、ADR 模板 |

**复盘的价值**：项目本身是作品，复盘是方法论——**面试讲"踩过的坑"比讲"成功的功能"更有说服力**（08 篇第 6 节简历的素材源）。

## 9. 常见交付翻车与规避

| 翻车 | 规避 |
|---|---|
| 演示时 LLM 漂移 | 录屏保底 + 种子数据 + 低温度（06/08 篇） |
| 面试讲太深没人接 | 钩子设计：每层留问题，观察对方兴趣再深入 |
| README 太长没人看 | 首屏 30 秒原则：定位 + 亮点 + 快速开始 |
| 项目推不动（依赖挂） | 全本地化（sqlite + 桩 + DeepSeek 只需一个 Key） |
| 代码能跑但讲不清 | 架构图 + ADR 双件套是"讲清"的前提 |

## 10. 面试五问演练（模拟面试）

对镜/录音演练这五组问题，练到脱稿：

| 问题 | 30 秒回答要点 |
|---|---|
| 介绍一下你的项目 | 定位句 + 三亮点（MCP 工具/Skill 流程/编排器）+ 一个数字（<10K token） |
| 架构怎么设计的？ | 三层图口头画 + 一次对话的数据流 + 分层纪律 |
| 遇到的最大困难？ | 真实 LLM 漂移 → 三层治理（元工具/mock 测试/录屏保底） |
| 为什么工具和技能分开？ | 原子可复用 vs 流程可改（政策改文件即生效） |

**演练标准**：每问 30 秒内讲完要点、不卡壳、不跑题——**练过的回答是"有结构的思考"，没练过的是"现场回忆"**。

## 11. 简历量化建议

简历项目栏的量化技巧（08 篇第 6 节补全）：

| 维度 | 量化表达 |
|---|---|
| 规模 | 6 工具 + 3 Skill + 5 场景，三层测试 58 用例 |
| 质量 | 覆盖率 87%，mock 确定性回归，发布门禁三件套 |
| 成本 | 单次对话 <10K token（约 0.01-0.05 元） |
| 安全 | 只读默认 + MRTR 确认 + 注入防护测试 |
| 架构 | 编排器模式 + 无状态设计（支持水平扩展） |

**量化原则**：**每个亮点配一个数字**——"做了三层测试"不如"58 个用例、覆盖率 87%、mock 确定性回归"；"控制了成本"不如"单次对话 <10K token、成本告警自动拦截"。数字是工程素养的压缩包。

## 14. 交付篇面试速记

1. README 首屏 30 秒：定位 + 亮点 + 快速开始——别让人翻三屏才知道项目是什么。
2. ADR = "为什么"的弹药库：每个追问回到设计决策（考虑过 X/Y，因为 Z 选 Y）。
3. 演示三件套：录屏保底（真实 LLM 有波动）+ 种子数据（边界全覆盖）+ 翻车预案（口头补救）。
4. 量化每个亮点：58 用例/覆盖率 87%/单次 <10K token——数字是工程素养的压缩包。
5. 讲解时间盒：30 秒电梯版 → 10 分钟技术版 → 20 分钟系统设计版，内容宁可少而深。
6. 复盘即方法论：时间花在哪/返工最多处/差点翻车的事——坑讲出来就是加分项。

> 🎯 **核心要点**：交付 = README 六段式 + 架构图与 ADR + 5 分钟演示脚本（录屏保底）+ 作品集三件套 + 10 分钟面试路线（钩子引导）+ 追问应对表（每个追问回到设计决策）+ 模拟面试演练（五问脱稿）+ 时间盒模板（30 秒到 20 分钟裁剪）+ 面试官评估表自查 + 量化简历 + 复盘模板。**验收标准：一个完全没参与项目的面试官，10 分钟内听完能复述"这个项目解决了什么问题、为什么这么设计"**——讲得清 = 做得出，交付是工程的最后一公里。
