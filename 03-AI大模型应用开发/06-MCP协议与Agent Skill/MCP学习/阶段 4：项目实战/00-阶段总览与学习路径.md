## 1. 本阶段定位

MCP 四阶段路径的终点站——把前三阶段的能力组合成一个完整项目：

| 阶段 | 名称 | 核心任务 | 产出 |
|---|---|---|---|
| 1 | 基础认知 | 概念、架构、原语、安全 | 能讲清 MCP 是什么 |
| 2 | 动手入门 | 跑通最小 Server/Client | 本地 MCP 对话 |
| 3 | 进阶实战 | 生产级 Server/认证/传输 | 可部署的 MCP |
| 4 | 项目实战（本阶段） | 完整项目集成 | 项目级 MCP 应用 |

> 本阶段的产出不是"又一个 Server"，而是**一个完整的智能体应用**：MCP 提供工具（库），Agent Skill 提供流程（程序），LLM 是语言——三者组合成"能解决真实业务问题的项目"。同时这是双体系交汇点：与平行的 `Agent Skill学习` 五阶段体系在此合流，完成"工具 + 知识"的完整交付。

## 6. 核心概念速查

| 概念 | 一句话速记 |
|---|---|
| Skill 是程序 | 流程/知识封装（SKILL.md），MCP 是库（工具），LLM 是语言 |
| 决策框架 | 确定性流程→Skill；实时数据/外部动作→MCP；两者组合 |
| SKILL.md | YAML frontmatter（name/description 激活开关）+ Markdown 流程体 |
| 渐进式披露 | 三层：发现（~100 token）→ 激活（<5000 token）→ 按需加载 |
| allowed-tools | Skill 声明允许使用的工具集（治理） |
| 编排器模式 | orchestrator + LLM + Skills + MCP，自然语言任务驱动 |
| 指挥官模式 | 主 Agent 用 Skills 规划，子 Agent 执行，MCP 交付 |
| 三层架构 | 交互层（意图理解）/ 编排层（任务路由）/ 执行层（Skills+MCP） |
| 工具映射矩阵 | 需求 → 原子操作 → 工具（MCP）/流程（Skill）的映射表 |
| 场景剧本测试 | 端到端业务场景脚本（输入→期望输出） |
| MCP token 成本 | 5 Server 58 工具 ≈ 5.5 万 token；Tool Search 降 85% |
| Skill 链 | 技能 A 输出 → 技能 B 输入（csv-insights → monthly-report） |
| Skills Over MCP | SEP-2640 草案：技能库经 MCP 分发（skill-router-mcp） |
| 语义路由 | 技能匹配从关键词（77.1%）升级为语义嵌入（93.8% top-1） |
| 交付物 | README + 架构图 + 演示脚本 + 自测报告 |

## 7. 常见疑问快答与关键数据

### 常见疑问

| 疑问 | 回答 |
|---|---|
| 与阶段 3 的项目有什么不同？ | 阶段 3 交付"可部署的 Server"；阶段 4 交付"能解决业务问题的应用"——多了编排器、Skill、完整交付 |
| 必须从零写编排器吗？ | 本项目自研编排器是为了"可测可讲"；生产可换 Agent SDK/框架（05 篇留了抽象层） |
| Skill 和 MCP 哪个更重要？ | 互补：没有工具的 Skill 是空谈，没有 Skill 的工具是散件——本阶段的价值在组合 |
| 项目用什么业务都行吗？ | 选题四原则满足即可（01 篇）；客服只是示例，方法可迁移 |
| 要接真实 LLM 吗？ | 要（DeepSeek 等便宜供应商）；mock LLM 只用于测试（06 篇） |
| 毕业后还能扩展吗？ | 08 篇给出三个方向：多客户端/指挥官/Skills Over MCP |

### 关键数据速记

| 数据 | 数值 |
|---|---|
| 工具数 | 6 个（5-7 最优区间） |
| Skill 数 | 3 个（退款/升级/话术） |
| 场景剧本 | 5 个（查询/改单/退款/升级/报表） |

| 循环上限 | 8 步（防失控） |
| 上下文窗口 | 10 轮后摘要压缩 |
| 分层 | 三层（交互/编排/执行） |
| 编排模式 | 编排器模式（本项目） |

## 13. 版本基线说明

| 项 | 基线 |
|---|---|
| MCP 规范 | 2026-07-28（无状态）；MRTR/SEP-2322 为本项目确认机制 |
| MCP SDK | FastMCP 3.x / 官方 mcp SDK 1.x |
| Agent Skill 格式 | SKILL.md（YAML frontmatter + Markdown），与 Agent Skill 体系一致 |
| LLM | DeepSeek（OpenAI 兼容）为默认，llm.py 抽象可换 |
| 数据 | sqlite + 桩服务（本地可复现） |
| 部署 | Docker Compose 一体容器起步 |

**一致性说明**：本阶段的"双体系"（MCP 工具 + Agent Skill）与 `Agent Skill学习` 体系的 SKILL.md 规范完全一致；协议细节若与主体系旧文档冲突，以官方规范与本阶段为准。**毕业定义**：完成本阶段全部检查单 + 20+30 自测 ≥80% + 独立讲清四阶段知识地图——满足三者即"MCP 学习"体系毕业，可凭此进入 Agent Skill 体系的深化或真实生产项目。**本阶段的学习模式**：与前三阶段不同，阶段 4 是"项目驱动"——先立项目再学方法，每篇文档在项目进行到对应环节时阅读并落地（01 在立项时、04 在写技能时、08 在交付前）；**一次读完再开工是常见误区**，边做边读、做一步学一步，产出与理解同步增长。**配套建议**：本阶段与 `Agent Skill学习/阶段 5：工程落地` 并行阅读（技能库组织/CI/安全治理对应 04/06/07 篇），两体系在"工程化"层面互相印证——读完本阶段，MCP 与 Agent Skill 双体系的知识地图即完整闭环。**学习投入建议**：阶段 4 的产出物（需求文档/架构图/测试报告/演示）均可进入个人作品集——**投入产出比最高的部分是 05 编排器与 09 综合实战**（能力证明最直接），时间紧张时优先保这两篇。
