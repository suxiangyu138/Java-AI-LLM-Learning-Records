## 1. 终极实战：从空目录到交付

**任务**：不依赖本系列文档，独立完成"智能客服 Agent"全流程——考验的不是写代码，而是**按文档顺序把每篇的产出物串起来**：

```text
01 篇产出：需求文档（功能清单 + 映射矩阵 + 验收标准）→ docs/requirements.md
02 篇产出：架构设计（三层图 + ADR + 目录结构）→ docs/architecture.md
03 篇产出：order_server（6 工具，阶段 3 标准）→ mcp_servers/
04 篇产出：三个 SKILL.md（渐进式披露 + 工具引用）→ skills/
05 篇产出：编排器（Agent 循环 + 双入口）→ orchestrator/
06 篇产出：三层测试 + 剧本 + 成本测试 → tests/
07 篇产出：Docker 部署 + 监控 + 上线检查单 → Dockerfile + docs/ops.md
08 篇产出：README + 演示脚本 + 面试路线 → README.md + docs/demo.md
```

**时间盒**：完整走一遍 8-12 小时（分 2-3 天）；**每篇的"核心要点"是完成标准**——做到"讲得出 + 做得出"才算该篇通过。

## 2. 实战步骤一：文档先行

先写 docs/requirements.md 与 docs/architecture.md（01/02 篇），**代码之前文档定稿**：

1. **需求文档**：5 个场景剧本写全（含边界用例：不存在订单/超期退款/未授权改单/多意图/恶劣语气）；
2. **映射矩阵**：需求 ↔ 工具 ↔ Skill ↔ 人工确认，四列全填；
3. **架构图**：三层 + 数据流，能对图讲清一次退款旅程；
4. **ADR 至少 3 条**：编排模式/工具技能分工/确认机制（08 篇表）。

**验收**：文档给一个没参加项目的人看，他能说出"这个项目做什么、为什么这样设计"——文档先行是阶段 4 与普通项目的最大区别（02 篇纪律）。

## 3. 实战步骤二：代码落地

按依赖顺序实现（03→04→05）：

| 顺序 | 组件 | 完成标准 |
|---|---|---|
| 1 | 数据层 + 种子 | 4 个订单覆盖全部边界（03 篇） |
| 2 | order_server | 6 工具全绿（阶段 3 标准：Schema/错误码/只读默认） |
| 3 | 三个 Skill | SKILL.md 格式校验通过（frontmatter/allowed-tools/步骤完整） |
| 4 | 编排器 | 元工具决策 + MCP 客户端 + Skill 执行 + MRTR |
| 5 | 双入口 | CLI 跑通 5 剧本；Claude Code 接入跑通 |

**代码阶段的纪律**：每个组件完成立刻写测试（06 篇三层体系的工具层/技能层），**不留"先跑通后补测试"的债**——阶段 4 的测试债比代码债更致命（回归成本）。

## 4. 实战步骤三：测试与部署

1. **三层测试**：工具层（复用阶段 3）→ 技能层（mock LLM 断言调用序列）→ 场景层（5 剧本 + 防幻觉剧本）；
2. **成本测试**：真实 LLM 跑一遍，记录单次 token（验收 <10K）；
3. **安全回归**：注入/越权/只读默认/日志脱敏（06 篇第 5 节）；
4. **容器化**：Docker 构建 + 健康检查 + 优雅退出 + sqlite 挂卷；
5. **上线检查单**：07 篇 10 项逐项打钩。

**验收**：`pytest` 全绿 + 部署环境重跑 5 剧本 + 成本报告在手。

## 5. 实战步骤四：交付与演示

1. **README** 六段式写全（08 篇规范）；
2. **演示脚本**：5 分钟版（3 剧本 + 工程亮点 + 扩展愿景），**录屏保底**；
3. **面试路线**：10 分钟讲解练两遍（对着镜子/录音）；
4. **复盘四问**：时间花在哪 / 哪些检查是形式 / 回滚过吗 / 敢给别人用吗（阶段 3 同款）。

**最终验收**：一个不懂代码的人看完 README 能跑起来；一个面试官听 10 分钟能复述项目价值。

## 7. 自测题参考答案

1. 动作/流程/数据/规模四原则；纯查询没有"状态变更"验证不了写工具与确认机制。
2. 需求/功能 → MCP 工具 → Agent Skill → 人工确认点。
3. 编排层通过 Skill 与工具接口访问执行层，不直接写数据库。
4. 客服是单任务串行+少量分支；编排器单进程可测性最好，复杂度留给 Skill 与工具。
5. 存在性（NOT_FOUND）→ 状态（CONFLICT）→ 条件（政策/权限）。
6. 触发条件在工具返回（needs_human）；确认文案在 Skill（怎么问）。
7. name（与目录同名）、description（激活开关）、allowed-tools、可选 user-invocable 等。
8. 政策可读可审可改（合规部门审文件而非代码），改一行文件即生效。
9. 发现层 ~100 token/Skill；激活层 <5000 token/Skill；执行层按需加载。
10. LLM 读上下文决定下一步（决策），但 Skill/工具的调用权在编排层代码（执行）。
11. 把模型输出收敛到枚举动作（call_skill/ask_confirm/answer），防幻觉乱调。
12. 历史截断、摘要压缩、事实回读（状态类问题重查工具，不信任历史）。
13. 工具层完全确定；技能层可控（mock LLM）；场景层概率性（真实 LLM）。
14. 不该调的工具没调（如不存在订单 → 只查单不退款）。
15. mock LLM 进 CI 做确定性回归主力；真实 LLM 低温度发版前跑关键剧本。
16. 编排器 McpClient 的 stdio/http 传输切换（05 篇双传输）。
17. token 是 LLM 应用的直接成本（烧钱/次），传统服务没有此维度。
18. "考虑过 X 和 Y，因为 Z 选 Y"——展示思考过程而非结果。
19. 真实 LLM 波动/工具超时的口头补救方案；录屏保底。
20. 技术栈（MCP+Skill）、核心能力（工具+流程）、工程指标（测试/成本/安全）、架构模式。

25. ADR 与 README 的分工是什么？（08 篇）
26. 如果退款政策从 7 天改为 30 天，需要改哪些文件？（03/04/06 篇）
27. Skills Over MCP 解决什么问题？（07 篇）
28. 演示脚本为什么必须"录屏保底"？（06/08 篇）
29. 指挥官模式下主 Agent 与子 Agent 的 Skill 使用差异？（02 篇）
30. 四阶段学完，你判断一个"生产级 MCP 应用"的标准是什么？（全篇）

**附加题参考答案**：
21. 工具决定"要不要确认"（needs_human），Skill 决定"怎么问"（文案）——触发与呈现分离。
22. 例：模型"记得"订单已退款，但实际未退——工具返回是唯一事实源，每次判断重查，杜绝记忆偏差。
23. mock 测不了"真实模型是否按提示词执行"；真实 LLM 用于发版前关键剧本冒烟。
24. 一体：多客户端共享时进程耦合（一挂全挂）；分离：需认证/网关（阶段 3 全套）部署复杂度上升。
25. README 面向使用者（怎么用），ADR 面向设计者（为什么这么设计）。
26. 改 SKILL.md 政策行 + 种子数据（30 天边界样本）+ 剧本期望（06 篇矩阵行）——文件级变更，代码零改动。
27. 技能库经 MCP 协议分发与语义路由（技能 >10 个、多客户端共享时的治理问题）。
28. 真实 LLM 有概率波动，演示翻车不可控；录屏保证演示确定性。
29. 主 Agent 用 Skills 做规划（流程拆解），子 Agent 按规划执行具体任务（各自加载所需技能）。
30. 开放性答案：需求可溯源、架构可讲清、测试可回归、成本可对账、安全有护栏、交付可演示。

## 7.6 实战常见卡点与解决

| 卡点 | 现象 | 解决 |
|---|---|---|
| 决策乱调技能 | 输入"查订单"却进了投诉流程 | 检查路由触发词（04 篇第 7 节）与决策提示词（05 篇第 7 节） |
| 工具参数编造 | 订单号与输入不符 | 确认 Schema 传给 LLM（05 篇第 3 节）；加参数断言测试 |
| 确认循环 | 反复问确认不执行 | 检查 needs_human 传递链（03 篇第 5 节） |
| Skill 不生效 | 改了 SKILL.md 没变化 | 确认技能加载路径（镜像内 vs 动态目录，07 篇） |
| 真实 LLM 漂移 | 同一输入两次结果不同 | mock 进 CI 保回归；真实冒烟看业务结果非文案 |
| 成本超预算 | 单次对话 >10K token | 查循环次数（决策提示词）、技能描述冗余（04 篇第 6 节） |

**卡点共性**：大部分卡点不是"代码 bug"而是"**契约不一致**"——工具 Schema 与 Skill 引用不一致、Skill 触发词与路由不一致、确认标志与编排层传递不一致。**排障先对齐契约（映射矩阵），再查代码**。

## 7.7 毕业面试速记（20 条）

1. Skill 是程序，MCP 是库，LLM 是语言——双体系分工第一句。
2. 决策框架：确定性流程→Skill；实时数据/外部动作→MCP。
3. 选题四原则：动作/流程/数据/规模。
4. 映射矩阵四列：需求→工具→Skill→人工确认。
5. 三层架构：交互/编排/执行，编排不碰库。
6. 编排器模式：决策模型做、执行代码管、8 步上限。
7. 元工具约束：模型输出收敛到枚举，防幻觉第一道闸。
8. 工具即事实：状态判断永远查工具，不靠模型记忆。
9. 政策进 Skill：文件级变更（改一行生效），可读可审。
10. 确认机制：触发条件在工具（needs_human），文案在 Skill。
11. 渐进式披露：发现 ~100 token、激活 <5000、按需加载。
12. 上下文三机制：截断、摘要、事实回读。
13. 三层测试：工具确定、技能可控、场景概率（mock+真实）。
14. 防幻觉剧本：断言"不该调的工具没调"。
15. 成本是指标：单次 <10K token，超预算即失败。
16. 无状态红利：会话外置 + 轮询可扩（阶段 3 资产）。
17. 一体容器起步，分离部署是扩展（触发条件驱动）。
18. 成本告警是 LLM 应用特色（token 是直接成本）。
19. ADR = 设计决策记录（"为什么"的弹药库）。
20. 面试讲坑：LLM 漂移 → 元工具 + mock + 录屏保底。

## 8. 毕业检查单与四阶段总结

**毕业检查单**（全部打钩才毕业）：

- [ ] docs/：requirements + architecture（含 ADR）+ security
- [ ] 6 工具 + 3 Skill + 编排器 + 双入口全部落地
- [ ] pytest 全绿（三层测试 + 成本 + 安全回归）
- [ ] 5 剧本部署环境重跑通过；单次对话 <10K token
- [ ] Docker 上线 + 监控（含成本告警）+ 上线检查单 10 项
- [ ] README 六段式 + 5 分钟演示脚本 + 录屏
- [ ] 20 自测 ≥80%；10 分钟面试讲解练过两遍

**四阶段总结**：

```
阶段1 基础认知   概念地基：MCP 是什么/三原语/无状态/双标准
阶段2 动手入门   链路打通：最小 Server/Client/HTTP/调试/接入
阶段3 进阶实战   生产级：架构/认证/无状态/安全/测试/部署/分发
阶段4 项目实战   完整交付：需求→架构→工具→技能→编排→测试→上线→讲解
                                      ↓
                    毕业能力：能用 MCP+Skill 独立交付可上线、可讲解的智能体应用
```

> 🎯 **最终要点**：阶段 4 的全部价值在"**组合**"——阶段 1-3 教的是零件，本阶段教的是整机。毕业的标准不是"代码能跑"，而是：**需求讲得清（01）、架构画得出（02）、工具经得起测（03/06）、流程改得动（04）、对话跑得通（05）、上线稳得住（07）、项目讲得明（08）**。四阶段走完，你拥有的不是"MCP 知识"，而是"用 MCP + Agent Skill 交付智能体应用"的完整工程能力——工具是库，技能是程序，而你，是架构师。
