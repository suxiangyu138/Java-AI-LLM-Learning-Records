# 03 核心原语：工具、资源与提示

> MCP Server 暴露的三种能力：Tools（模型调用的函数）、Resources（注入上下文的可读数据）、Prompts（用户选择的模板）——理解三原语就理解了 MCP 的能力模型。

## 1. 三原语总览

```
MCP Server 暴露的三种能力：
Tools（工具）：模型可调用的函数
Resources（资源）：模型可读的数据
Prompts（提示）：用户可选的模板
```

| 原语 | 谁触发 | 模型能否自主用 | 类比 |
|---|---|---|---|
| Tools | 模型 | ✅ 自主调用 | 双手（能做） |
| Resources | 模型/用户 | ✅ 上下文注入 | 资料（能看） |
| Prompts | 用户 | ❌ 用户选择 | 快捷方式（能选） |

## 2. Tools：工具

### 是什么

```
可执行函数（模型调用）：
输入参数 → 执行 → 返回结果
（对应 Function Calling 的工具概念）
```

### 特点

| 特点 | 说明 |
|---|---|
| 模型驱动 | 模型决定何时调用 |
| 有副作用 | 执行动作（写库/发消息） |
| 参数校验 | JSON Schema 定义 |
| 结果回传 | 作为消息给模型 |

### 示例

```
search_documents（检索）/ create_issue（建工单）
send_message（发消息）/ query_db（查库）
——Tools = 模型的"手脚"
```

### 与 Agent Skill 的关系

```
MCP Tools = 可调用工具（functions）
Agent Skills = 使用知识（know-how）
工具是零件，技能是装配图（Agent Skill 阶段 1 的 05 篇）
```

## 3. Resources：资源

### 是什么

```
可读数据（注入上下文）：
文件内容、数据库查询结果、API 返回
——模型"看得到"但不"执行"
```

### 特点

| 特点 | 说明 |
|---|---|
| 只读 | 提供数据（无副作用） |
| 上下文注入 | 内容进入模型上下文 |
| URI 寻址 | 唯一标识（file:// 等） |
| 订阅通知 | 变化时通知（subscriptions） |

### 示例

```
文档内容（file://docs/guide.md）
用户信息（user://profile）
实时数据（realtime://stock/price）
——Resources = 模型的"资料库"
```

## 4. Prompts：提示

### 是什么

```
可复用提示模板（用户选择）：
预定义的交互模式（输入 → 组装 → 调用）
——用户触发（模型不自主用）
```

### 特点

| 特点 | 说明 |
|---|---|
| 用户驱动 | 用户选择/触发 |
| 模板化 | 参数化提示 |
| 流程封装 | 多步交互的起点 |
| 与 Agent Skill 区分 | Skill 是 Agent 自动匹配，Prompt 是用户主动选 |

### 示例

```
"总结这个文件"（模板：读取 → 总结 → 输出）
"生成周报"（模板：收集 → 格式化）
——Prompts = 用户的"快捷方式"
```

## 5. 三原语对比

| 维度 | Tools | Resources | Prompts |
|---|---|---|---|
| 本质 | 函数（执行） | 数据（读取） | 模板（选择） |
| 触发方 | 模型自主 | 模型/用户 | 用户 |
| 副作用 | 有 | 无 | 无 |
| 模型能力 | 调用 | 读取 | 不直接 |
| 类比 | 双手 | 资料库 | 快捷方式 |
| 对应 | Function Calling | RAG 数据层 | 提示词模板 |

### 三原语配合

```
典型流程：
① Resources 提供数据（上下文）
② Tools 执行动作（操作）
③ Prompts 组织交互（入口）
——三原语覆盖"读-做-选"三类能力
```

## 6. 与 Function Calling 的关系

### 三原语的配合示例

```
知识库问答场景：
① Prompts：用户选"问答"模板（入口）
② Resources：注入文档内容（上下文）
③ Tools：调用检索工具（获取更多）
——三原语各司其职（选-读-做）
```

### 对应关系

```
Function Calling：模型调函数的机制（单模型私有）
MCP Tools：同一机制的标准化（跨模型开放）
——MCP = Function Calling 的"开放协议版"
```

| 维度 | Function Calling | MCP Tools |
|---|---|---|
| 范围 | 单供应商 | 开放标准 |
| 工具定义 | 供应商格式 | 统一 JSON Schema |
| 复用 | 绑定模型 | 跨模型/应用 |
| 发现 | 静态注册 | discover 动态 |

### 认知

```
学了 Function Calling（本仓库有体系）→ MCP Tools 是它的开放版
Tools 是 MCP 与 Function Calling 的交汇点
——理解其一，另一个顺理成章
```

## 7. 面试高频问法

| 问题 | 回答要点 |
|---|---|
| 三原语？ | Tools/Resources/Prompts |
| Tools 特点？ | 模型自主调用、有副作用 |
| Resources 特点？ | 只读数据、上下文注入 |
| Prompts 特点？ | 用户选择、模板化 |
| 三原语类比？ | 双手/资料库/快捷方式 |
| 与 Function Calling？ | MCP Tools 是开放协议版 |

### 面试加分表达

> "MCP 三原语覆盖模型的三类能力需求：Tools 是模型自主调用的函数（有副作用，对应 Function Calling 的开放协议版）、Resources 是只读数据（注入上下文，URI 寻址 + 订阅通知）、Prompts 是用户选择的模板（快捷方式）。类比：双手、资料库、快捷方式。与 Agent Skills 的关系：MCP 管'能做什么'（工具），Skills 管'怎么做'（知识）——双标准互补。"

> 🎯 核心要点：三原语（Tools 执行/Resources 读取/Prompts 选择）；触发方不同（模型自主/模型用户/用户）；类比（双手/资料库/快捷方式）；MCP Tools = Function Calling 开放协议版；与 Agent Skills 双标准（工具 vs 知识）；三原语配合覆盖"读-做-选"。
