# 01 MCP 是什么：模型上下文协议

> MCP（Model Context Protocol）的定位一句话："给 AI 应用接外部能力用的开放协议"——把工具、数据、提示词用统一格式接到模型上，像 USB-C 一样即插即用。

## 1. MCP 的定义

| 维度 | 说明 |
|---|---|
| 全称 | Model Context Protocol（模型上下文协议） |
| 是什么 | 模型与外部工具/数据/提示的开放协议 |
| 发起 | Anthropic（2024-11 开源） |
| 治理 | 开放治理（社区共同演进） |
| 最新规范 | 2026-07-28（重大修订） |
| 定位 | "AI 应用的 USB-C"（统一连接标准） |

一句话定义：

> MCP 定义了一个标准方式：AI 应用（Host）通过客户端（Client）连接外部能力（Server），让模型能调用工具、读取资源、使用提示词——三方用统一的 JSON-RPC 消息通信。

## 2. 解决的痛点

### 集成碎片化

```
没有 MCP 之前：
每个 AI 应用 × 每个工具 = 单独集成
N 个应用 × M 个工具 = N×M 个适配器
```

### MCP 的解法

```
一个标准协议：
工具只实现一次（MCP Server）
任何支持 MCP 的应用都能用
N×M 变成 N+M（复用）
```

### 对比表

| 维度 | 传统集成 | MCP |
|---|---|---|
| 集成方式 | 每对单独开发 | 标准协议一次实现 |
| 复用 | 低（绑定） | 高（即插即用） |
| 生态 | 碎片化 | 统一市场 |
| 变更 | 应用侧全改 | 服务器侧更新 |

### 演进主线

```
本地（stdio）→ 远程（HTTP+SSE）→ 无状态（Streamable HTTP）
从"会话式"到"REST 风格"（2026-07-28）
```

## 4. 心智模型：AI 的 USB-C

### USB-C 类比

```
USB-C 之前：每设备一种线（碎片化）
USB-C 之后：一种线通吃（标准化）

MCP 之前：每工具单独集成
MCP 之后：一种协议通吃（即插即用）
```

### 类比延伸

### 演进中的协议（版本日期标识）

```
MCP 规范以日期标识版本（非 1.0 式语义化）：
2025-03-26 / 2025-11-25 / 2026-07-28
——每次修订都带来能力变化（04 篇详述 2026 大修订）
```

### 类比延伸

```
USB 设备 = MCP Server（实现标准接口）
USB 接口 = MCP Client（应用侧）
设备即插即用 = 工具即连即用
——"写一次，处处用"
```

### 为什么这个类比重要

```
面试/解释的第一句话：
"MCP 是 AI 应用的 USB-C——统一模型接外部能力的标准"
——类比让抽象概念立刻可理解
```

## 5. 与传统 API 集成的区别

### 与主体系的分工（MCP/ 目录）

```
本阶段与 MCP/ 主体系的分工：
主体系（MCP/ 00-08）：协议规范/原语详解/开发实战（字典）
本阶段：概念教学（是什么→架构→原语→传输→生态）
——学习推进走阶段体系，查细节翻主体系
```

| 维度 | 传统 API | MCP |
|---|---|---|
| 服务对象 | 应用代码调用 | **模型动态调用** |
| 接口标准 | 各自定义 | **统一协议** |
| 发现机制 | 文档手动对接 | **server/discover 自动发现** |
| 能力类型 | 业务接口 | 工具/资源/提示（模型语义） |
| 生态 | 碎片 | 统一市场 |

### 常见误区

| 误区 | 真相 |
|---|---|
| "MCP 是 API 的替代" | 是给模型用的接口标准（服务对象不同） |
| "MCP 只有 Anthropic 用" | 行业标准（大厂跟进） |
| "协议已定型" | 持续演进（2026-07 大修订） |
| "MCP 只是工具" | 还有资源与提示（三原语） |
| "学了 Function Calling 够了" | MCP 是开放标准版（跨模型） |

### 关键区别

```
传统 API：给"程序"用的接口（写死调用）
MCP：给"模型"用的接口（模型自主发现调用）
——MCP 是"模型时代"的接口标准
```

| 一句话解释？ | AI 应用的 USB-C |

### 面试加分表达

> "MCP 是 AI 应用的 USB-C：一个开放协议统一模型接外部工具/数据/提示的方式。没有它之前，每个应用×每个工具要单独集成（N×M）；有了它，工具实现一次（MCP Server）任何支持的应用都能用（N+M）。它是给'模型'用的接口标准——模型通过 server/discover 自动发现能力，而不是传统 API 那样写死调用。最新规范 2026-07-28 做了无状态革命（04 篇）"

> 🎯 核心要点：MCP = 模型与外部能力的开放协议（USB-C 类比）；解决集成碎片化（N×M→N+M）；Anthropic 2024-11 发起、开放治理；演进主线（stdio→HTTP+SSE→无状态）；给模型用的接口（自主发现 vs 写死调用）；最新规范 2026-07-28。
