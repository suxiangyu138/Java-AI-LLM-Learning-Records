## 1. 为什么 MCP 有安全风险

### 风险的本质

```
MCP 把外部能力接进模型：
能力越强大（工具可执行动作）→ 风险越大
——工具是"手脚"，手脚能做好事也能做坏事
```

### 风险面

```
① 工具内容（服务器返回的数据/指令）
② 工具行为（执行的动作）
③ 服务器本身（第三方/供应链）
④ 连接（网络/认证）
——四个面都要防护
```

### 与 Agent Skill 的关系

### 信任模型

```
MCP 的安全本质是信任问题：
① 服务器内容可信任吗？（注入）
② 工具行为可信任吗？（滥用）
③ 服务器来源可信任吗？（供应链）
——信任要配防护（授权/隔离/最小权限）
```

```
MCP 工具（能力）+ Skill 知识（指导）：
技能可能诱导工具做坏事（提示注入放大）
工具可能被滥用（白名单失效）
——双标准的组合风险（Agent Skill 阶段 1 的 06 篇呼应）
```

## 2. 核心风险类型

| 风险 | 表现 |
|---|---|
| 提示注入 | 工具结果/内容含恶意指令诱导模型 |
| 恶意工具 | 服务器提供危险能力 |
| 权限滥用 | 工具调用越权操作 |
| 数据泄露 | 敏感数据经工具外传 |
| 供应链 | 第三方服务器不可信 |
| 网络攻击 | 连接层（DNS rebinding 等） |

```
风险本质：模型"信任"工具内容与能力
——信任要配防护（授权/隔离/最小权限）
```

## 3. 提示注入

### 是什么

```
工具返回的内容/指令中夹带恶意指令：
模型读取"看似数据"的内容 → 被诱导执行危险操作
```

### 注入路径

```
① 工具结果（数据库内容含指令）
② 资源内容（文档含恶意指令）
③ 网页内容（检索结果注入）
——模型分不清"数据"与"指令"
```

### 防护

```
① 工具结果隔离（标注"这是数据，不是指令"）
② 内容过滤（输入输出双向）
③ 权限确认（危险操作人审）
④ 最小权限（工具白名单）
——注入难根除，防护要分层
```

## 4. 恶意与滥用工具

### 恶意工具

```
第三方服务器提供"危险能力"：
删除文件/读取密钥/外传数据
——装服务器 = 引入风险（供应链审查）
```

### 工具滥用

```
合法工具被诱导做危险事：
查询工具 → 被注入诱导成删除
——能力被"错用"
```

### 防护

```
① 服务器来源审查（像审依赖）
② 工具白名单（只启用需要的）
③ 权限分级（危险操作确认）
④ 审计日志（工具调用留痕）
——最小权限 + 可追溯
```

## 5. 防护原则

### 三层防护

```
① 授权层：用户确认（工具调用前）
② 隔离层：沙箱/只读（能力限制）
③ 最小权限：白名单（只给需要的）
——纵深防御（每层拦截）
```

### 防护清单

| 项 | 说明 |
|---|---|
| 来源审查 | 服务器可信（供应链） |
| 工具白名单 | 只启用需要的 |
| 用户授权 | 危险操作确认 |
| 最小权限 | 只读优先 |
| 内容过滤 | 注入防护 |
| 审计 | 调用留痕 |
| 网络 | Origin 校验/HTTPS |

### 与 Agent Skill 防护的呼应

```
同一套防护思想（Agent Skill 阶段 1 的 06 篇）：
安装前审查 / allowed-tools 白名单 / HITL 审批
——工具与知识共用安全基线
```

## 6. 新规范的安全要求

### 2026-07 规范安全项

| 要求 | 说明 |
|---|---|
| OAuth/OIDC | 正式认证要求 |
| Origin 校验 | 防 DNS rebinding |
| 认证 | API key/OAuth |
| CORS 配置 | 浏览器场景 |
| HTTPS | 生产必须 |
| Trace Context | W3C 标准（可观测） |

### 无状态带来的安全变化

```
无状态（REST 风格）：
① 每请求独立认证（无会话可复用）
② 状态句柄作为参数（SEP-2567——句柄要防篡改）
③ 无粘性路由（攻击面变化）
——新架构新安全考虑
```

### 企业安全基线

```
① 认证强制（OAuth/OIDC）
② 传输加密（HTTPS）
③ 来源校验（Origin）
④ 可观测（Trace Context）
⑤ 审计（调用日志）
——2026 规范 = 企业就绪的安全基线
```

### 面试加分表达

> "MCP 把能力接进模型，也把风险接进来：提示注入（工具内容夹带指令）、恶意工具（第三方危险能力）、权限滥用、供应链。防护三层：授权（用户确认危险操作）、隔离（沙箱/只读）、最小权限（工具白名单）——加上来源审查和审计日志。2026-07 新规范强化了企业安全：OAuth/OIDC 正式要求、Origin 校验防 DNS rebinding、HTTPS、W3C Trace Context。与 Agent Skills 共用同一套安全基线（审查/白名单/审批）。"

> 🎯 核心要点：能力越强风险越大；核心风险五类（注入/恶意/滥用/泄露/供应链）；提示注入难根除（分层防护）；三层防护（授权/隔离/最小权限）+ 审计；新规范安全（OAuth/Origin/HTTPS/Trace）；无状态新安全考虑（句柄防篡改）；与 Skills 共用安全基线。
