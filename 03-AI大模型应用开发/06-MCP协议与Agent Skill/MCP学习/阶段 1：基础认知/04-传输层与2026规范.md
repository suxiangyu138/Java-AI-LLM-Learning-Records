## 1. 传输层总览

| 传输 | 场景 | 状态 |
|---|---|---|
| stdio | 本地子进程 | 稳定（本地标准） |
| Streamable HTTP | 远程服务 | **推荐（当前标准）** |
| HTTP+SSE | 旧远程方案 | **已废弃（Deprecated）** |

```
传输选择：
本地工具 → stdio
远程服务 → Streamable HTTP
新实现 → 别用 HTTP+SSE（废弃）
```

## 2. stdio：本地传输

### 是什么

```
标准输入输出通信：
Host 启动 Server 子进程 → stdin/stdout 传 JSON-RPC
```

### 特点

| 特点 | 说明 |
|---|---|
| 本地 | 无网络（安全） |
| 简单 | 进程间管道 |
| 适用 | 文件系统/本地工具 |
| 限制 | 只能本机（无法远程） |

### 示例场景

```
Claude Code 启动文件系统 Server（子进程）
——本地工具的默认传输
```

## 3. Streamable HTTP：远程传输

### 是什么

```
基于 HTTP 的远程传输（当前推荐）：
POST JSON-RPC 请求 → 响应（含流式）
```

### 特点（2026-07 新规范）

| 特点 | 说明 |
|---|---|
| 无状态 | 无会话无握手（REST 风格） |
| 请求头 | Mcp-Method/Mcp-Name 标准头 |
| 自定义头 | x-mcp-header 传递 |
| 订阅 | subscriptions/listen（单一 POST 流） |
| 部署 | 水平扩展/serverless 友好 |

### 无状态的意义

```
① 水平扩展（无粘性会话）
② serverless 部署（无状态函数）
③ 标准 REST 模式（运维熟悉）
④ 代理友好（简单转发）
——无状态 = 企业部署的关键
```

## 4. 2026-07-28 规范：无状态革命

### 核心变更

| 变更 | 旧（2025-11-25） | 新（2026-07-28） |
|---|---|---|
| 会话 | Mcp-Session-Id 头 | **移除（无会话）** |
| 握手 | initialize/initialized | **移除（每请求带版本/能力）** |
| 发现 | 无显式机制 | **server/discover** |
| 订阅 | GET 端点 + subscribe | **subscriptions/listen** |
| SSE 恢复 | Last-Event-ID | **移除（重新发起）** |
| HTTP+SSE | 弃用中 | **正式废弃（Deprecated）** |

### 每请求携带

```
每个请求通过 _meta 携带：
① 协议版本（io.modelcontextprotocol/protocolVersion）
② 客户端能力（clientCapabilities）
版本不匹配 → UnsupportedProtocolVersionError
——无握手如何协商？请求级协商
```

### 状态跨调用的处理

```
需要跨调用状态的服务器：
服务器签发的句柄作为普通工具参数（SEP-2567）
——状态显式传递（不靠协议会话）
```

## 5. 兼容性分代

### 三代实现

| 代 | 规范版本 | 特征 |
|---|---|---|
| modern（现代） | 2026-07-28+ | 无状态 |
| legacy（遗留） | 2025-11-25 及之前 | 会话式 |
| dual-era（双代） | 两者都支持 | 自动回退 |

### 回退机制

```
客户端先尝试现代请求：
收到 400 且响应体不是可识别的现代 JSON-RPC 错误
→ 回退到旧版 initialize 握手
——兼容策略（渐进迁移）
```

### 实践建议

```
新实现：modern（只做无状态）
存量迁移：dual-era（双代过渡）→ 逐步转 modern
兼容验证：Stacklok 企业就绪指南（迁移评估）
```

## 6. 迁移影响

### 受影响最大的工作负载

```
① 依赖会话 ID（Mcp-Session-Id）
② 粘性路由（会话绑定）
③ 初始化握手（initialize）
④ SSE 行为（Last-Event-ID 恢复）
——这些设计需要改造
```

### 迁移步骤

```
① 服务器：transport="streamable-http"
② 客户端：streamablehttp_client + 消息处理器
③ 兼容期：同时托管新旧传输
④ 验证：企业就绪指南（评估/迁移/验证）
——渐进迁移（不搞一刀切）
```

### 安全与运维（2026 新规范）

```
① Origin 头校验（防 DNS rebinding）
② localhost 绑定（本地安全）
③ 认证（API key/OAuth——新规范 OAuth/OIDC 要求）
④ CORS 配置（浏览器场景）
⑤ HTTPS（生产必须）
⑥ W3C Trace Context（OpenTelemetry 兼容追踪）
——无状态时代的运维基线
```

## 7. 面试高频问法

| 问题 | 回答要点 |
|---|---|
| 三种传输？ | stdio 本地/Streamable HTTP 远程/HTTP+SSE 废弃 |
| Streamable HTTP 特点？ | 无状态 REST 风格、标准头、serverless 友好 |
| 2026-07 最大变更？ | 移除会话与握手（无状态革命） |
| 每请求带什么？ | _meta 协议版本 + 客户端能力 |
| 兼容分代？ | modern/legacy/dual-era（自动回退） |
| 迁移注意？ | 依赖会话/粘性路由/握手的要改造 |

### 面试加分表达

> "2026-07-28 是 MCP 最大的规范修订——无状态革命：移除 Mcp-Session-Id 会话与 initialize 握手，每请求通过 _meta 携带协议版本和客户端能力（版本不匹配返回 UnsupportedProtocolVersionError），server/discover 做显式发现，subscriptions/listen 取代 GET 订阅端点，HTTP+SSE 正式废弃。无状态让 MCP 可以水平扩展、部署 serverless，符合标准 REST 模式。兼容分代：modern/legacy/dual-era，客户端先试现代请求失败自动回退旧握手。"

> 🎯 核心要点：三种传输（stdio/Streamable HTTP/HTTP+SSE 废弃）；2026-07 无状态革命（移除会话握手/请求级协商/discover/新订阅）；无状态价值（水平扩展/serverless/REST）；分代兼容（modern/legacy/dual-era 自动回退）；迁移影响（会话/粘性/握手改造 + 渐进）；新规范安全基线（Origin/OAuth/CORS/HTTPS/Trace）。
