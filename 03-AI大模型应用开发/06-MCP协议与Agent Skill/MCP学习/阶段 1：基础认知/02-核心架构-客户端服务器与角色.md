# 02 核心架构：客户端、服务器与角色

> MCP 的全部架构就是三要素：Host（宿主应用）、Client（连接器）、Server（能力提供者）——三方用统一 JSON-RPC 消息通信，Host 管交互、Client 管连接、Server 管能力。

## 1. 三要素架构

```
┌─────────────────────────────────────┐
│ Host（宿主应用：Claude Code/IDE 等）  │
│  ┌───────────┐    ┌──────────────┐  │
│  │ Client 1  │    │  Client 2    │  │  ← 一个 Host 多个 Client
│  └─────┬─────┘    └──────┬───────┘  │
└────────┼──────────────────┼─────────┘
         │ JSON-RPC         │ JSON-RPC
    ┌────▼─────┐      ┌─────▼──────┐
    │ Server 1 │      │  Server 2  │    ← 本地（stdio）/远程（HTTP）
    └──────────┘      └────────────┘
```

| 要素 | 角色 | 类比 |
|---|---|---|
| Host | 宿主应用（用户交互） | 应用本体 |
| Client | 连接服务器（协议） | 适配器/接口 |
| Server | 提供能力（工具/资源/提示） | 外设 |

## 2. Host：宿主应用

### 是什么

```
用户与之交互的应用：
Claude Code / IDE / 桌面应用 / 网页应用
```

### 职责

| 职责 | 说明 |
|---|---|
| 用户交互 | 用户输入/输出的入口 |
| 管理多个 Client | 一个 Host 可连多个服务器 |
| 连接策略 | 允许/拒绝哪些服务器 |
| 权限控制 | 用户授权（工具调用确认） |

### 典型 Host

```
Claude Code（Anthropic）
其他 AI IDE/Agent 工具（阶段 4 的平台）
自建应用（阶段 2/4 实现）
——Host 是"应用层"
```

## 3. Client：连接器

### 是什么

```
Host 内嵌的协议连接器：
负责与 Server 建立连接、交换消息
（一个 Host 一个或多个 Client）
```

### 职责

| 职责 | 说明 |
|---|---|
| 连接 Server | 建立/维护连接 |
| 协议处理 | JSON-RPC 消息编解码 |
| 请求转发 | 模型请求 → Server |
| 响应处理 | Server 结果 → Host/模型 |

### Client 与 Host 的关系

```
Client 是 Host 的一部分（内嵌）：
Host = 应用外壳（交互）
Client = 协议内核（通信）
——理解 MCP 开发 = 写 Client（阶段 2/4）
```

## 4. Server：能力提供者

### 是什么

```
提供工具/资源/提示的进程：
本地进程（stdio）或远程服务（HTTP）
```

### 职责

| 职责 | 说明 |
|---|---|
| 暴露能力 | 工具（可调用）/资源（可读）/提示（模板） |
| 处理请求 | 执行工具/返回资源/提供提示 |
| 发布更新 | 资源变化通知（subscriptions） |
| 发现机制 | server/discover（2026-07 新规范） |

### Server 的形态

```
本地：文件系统工具（stdio 子进程）
远程：数据库/API/搜索（Streamable HTTP）
——Server 是"能力提供方"
```

## 5. 通信模型

### JSON-RPC 消息

```
三方通信基于 JSON-RPC 2.0：
请求（request）/响应（response）/通知（notification）
——统一消息格式（跨语言/平台）
```

### 通信流程（2026-07 新规范）

```
旧：initialize 握手 → 建立会话 → 调用
新：每请求带版本/能力（_meta）→ server/discover 发现 → 调用
（无状态：无会话无握手——04 篇详述）
```

### 能力协商

```
客户端能力（clientCapabilities）随请求携带：
服务器知道客户端支持什么（工具/资源/提示）
——能力协商（动态适配）
```

## 6. 架构设计原则

### 一个 Host 多 Client 的实践

```
典型场景：Claude Code 同时连多个 Server：
文件系统 Server（本地 stdio）
数据库 Server（远程 HTTP）
搜索 Server（远程 HTTP）
——每个 Client 一个连接（能力按需接入）
```

| 原则 | 说明 |
|---|---|
| 解耦 | Host/Client/Server 独立演进 |
| 复用 | Server 一次实现多处使用 |
| 标准 | 统一协议（跨语言/平台） |
| 无状态 | 2026-07 起 REST 风格（水平扩展） |
| 安全 | 用户授权（工具调用确认） |

### 架构的价值

```
① 一个 Server 服务所有 Host（写一次处处用）
② Host 换模型不换 Server（模型无关）
③ 能力独立部署（Server 可独立扩展）
——分层让生态可生长
```

## 7. 面试高频问法

| 问题 | 回答要点 |
|---|---|
| 三要素？ | Host（应用）/Client（连接）/Server（能力） |
| Host 职责？ | 交互 + 管理 Client + 权限 |
| Client 与 Host 关系？ | Client 内嵌于 Host（协议内核） |
| Server 提供什么？ | 工具/资源/提示（三原语） |
| 通信协议？ | JSON-RPC 2.0 |
| 架构价值？ | 写一次处处用 + 模型无关 + 独立部署 |

### 面试加分表达

> "MCP 架构三要素：Host 是宿主应用（交互入口、管理多个 Client、控制权限），Client 是内嵌的协议连接器（JSON-RPC 编解码），Server 是能力提供方（工具/资源/提示）。通信基于 JSON-RPC 2.0，2026-07 新规范后每请求携带版本与能力（无状态），server/discover 负责发现。架构价值：一个 Server 服务所有 Host、换模型不换 Server、能力独立部署。"

> 🎯 核心要点：三要素（Host 交互/Client 连接/Server 能力）；一个 Host 多 Client；JSON-RPC 2.0 统一消息；2026-07 无状态（每请求带版本能力 + discover）；架构价值（写一次处处用/模型无关/独立部署）；开发 MCP = 写 Client（阶段 2/4）。
