## 1. 实战项目：订单助手 Server

**需求**：为一个电商团队构建"订单助手"MCP Server，供 Claude Code 与自定义客户端使用。

| 需求项 | 要求 |
|---|---|
| 工具 | 查订单（只读）、查物流（只读）、更新订单状态（写，需授权） |
| 认证 | Bearer 令牌（生产接 OAuth 授权服务器） |
| 状态 | 无状态：跨请求状态用句柄（订单号即句柄） |
| 安全 | 只读默认；写操作需确认；日志脱敏 |
| 部署 | Docker + HTTP 传输；CI 自动测试 |

**技术栈**：FastMCP 3.x + Python 3.12 + pytest + Docker + GitHub Actions。

```python
    issuer="https://auth.myorg.com/",

class AuditMiddleware(Middleware):

```

## 10. 完整可运行代码（集成 01-08 全部要点）

```python
# order_server/__init__.py —— 最终成品：生产级订单助手
import asyncio
from contextlib import asynccontextmanager
from fastmcp import FastMCP, Context, Depends, ToolResult
from fastmcp.middleware import Middleware, MessageContext
from fastmcp.security import JWTVerifier
from pydantic_settings import BaseSettings

# ---- 01 配置：环境外置 + 启动校验 ----
class Settings(BaseSettings):
    model_config = {"env_prefix": "MCP_"}
    database_url: str
    shipping_api_key: str
    read_only: bool = True
    jwks_url: str = ""

cfg = Settings()

# ---- 01 生命周期 ----
@asynccontextmanager
async def lifespan(server):
    db = await OrderRepo.connect(cfg.database_url)
    yield {"db": db}
    await db.close()

def get_db():
    return Context().lifespan_context["db"]

# ---- 02 认证（配置了 jwks 才启用） ----
auth = JWTVerifier(issuer="https://auth.myorg.com",
                   jwks_url=cfg.jwks_url,
                   required_audience="mcp-order") if cfg.jwks_url else None

# ---- 01 中间件：审计（记键不记值） ----
class Audit(Middleware):
    async def before(self, ctx: MessageContext):
        user = ctx.auth.user if ctx.auth else "anon"
        print(f"AUDIT user={user} tool={ctx.message.name} "
              f"args={list(ctx.message.arguments)}")

mcp = FastMCP("order-assistant", lifespan=lifespan,
              middleware=[Audit()], auth=auth)

# ---- 04 工具：Schema 规范 + 错误码 + 只读默认 ----
@mcp.tool
def get_order(order_id: str, include_items: bool = False, db=Depends(get_db)) -> ToolResult:
    """按订单号查询订单。

    何时用：用户问订单状态/金额/商品时。
    何时不用：物流查 get_shipping；商品查 get_product。
    边界：平台内部单号。
    """
    row = db.fetch(order_id)
    if row is None:
        return ToolResult(is_error=True, content="订单不存在",
                          structured_content={"code": "NOT_FOUND"})
    return ToolResult(content=str(row), structured_content={"code": "OK"})

@mcp.tool(tags={"write"})
def update_order_status(order_id: str, status: str, db=Depends(get_db)) -> ToolResult:
    """更新订单状态（写操作，需显式启用 + 人工确认）。

    支持：paid/shipped/completed/cancelled。
    """
    if cfg.read_only:
        return ToolResult(is_error=True, content="当前为只读模式")
    db.update_status(order_id, status)
    return ToolResult(content=f"订单 {order_id} 已更新为 {status}")

if cfg.read_only:
    mcp.disable(tags={"write"})          # 05 只读默认

if __name__ == "__main__":
    mcp.run(transport="http", host="0.0.0.0", port=8080)
```

## 10.5 自测题参考答案（前 10 题详解）

1. lifespan 是框架管理的资源生命周期（启动初始化/关闭清理），全局变量是进程级隐式状态——前者生命周期明确、可注入可测试，后者无生命周期、跨请求污染。
2. Depends 注入让工具依赖（DB/API）可在测试中替换为 mock，工具逻辑与基础设施解耦。
3. 审计/日志只记录参数名与哈希，不记录令牌、密钥、PII 的具体值。
4. 预期业务失败（非法输入/外部拒绝）用 ToolResult(is_error) 带错误码；代码缺陷与基础设施故障抛异常（配日志与 trace）。
5. MCP Server 是资源服务器（验签 Bearer），授权服务器独立（发令牌），两者分离。
6. SEP-2468 防 mix-up 攻击（恶意服务器诱导客户端连到自己的授权服务器）；客户端必须实现。
7. RFC 9728 元数据发布在 `/.well-known/oauth-protected-resource`，声明授权服务器地址与受众，供客户端发现。
8. CIMD 以 HTTPS URL 为客户端 ID + 自描述文档；DCR 是授权服务器动态注册。DCR 已进入 12 个月弃用窗口。
9. aud 校验防止"A 服务器的令牌调 B 服务器工具"的跨资源重放（RFC 8707）。
10. initialize/initialized 握手（SEP-2575）与 Mcp-Session-Id 头（SEP-2567）。

## 10.6 自测题参考答案（11-21 题详解）

11. server/discover 是服务器必须实现的显式发现 RPC：广播协议版本、能力与身份，客户端可先调用做版本选择，stdio 下可作向后兼容探测。
12. 三步：工具返回 InputRequiredResult（resultType=input_required + inputRequests + requestState）→ 客户端处理输入 → 客户端带 inputResponses 重发原调用，服务器以 requestState 识别续集。
13. 显式句柄（服务器铸造的 basket_id/job_id 等标识），状态存在服务器侧存储，句柄作为普通工具参数传递。
14. dual-era = 同时支持 modern（2026-07+ 无状态）与 legacy（≤2025-11 握手会话）；SDK 默认显式请求无状态而非默认，保证旧客户端可协商降级。
15. 超过 25-50 个需治理；三个手段：合并（灵活单工具）、动态加载（按用户/租户裁剪）、code mode（沙箱执行，token 降 99.9%）。
16. 长任务（超时之外）返回任务句柄，客户端轮询 tasks/get 获取进度与结果——句柄+轮询模式。
17. 游标（next_token）不依赖"总页数"等易变状态，数据变化时仍稳定，是无状态句柄模式的自然延伸。
18. Tools=执行动作（有副作用），Resources=只读数据面，Prompts=可复用提示模板。
19. 传播链：恶意数据 → 工具返回 → 模型采信 → 诱导调用危险工具。第一道防御是数据-指令分离（输出加分隔/提示词声明不可信）。
20. SSRF 三防：协议白名单（仅 https）、解析后 IP 校验（防 DNS 重绑定）、重定向限制（防跳内网）。
21. 证据数据：SSRF 36.7%、高危 33%、零认证 41%——注册表只验证"你是谁发布"，不验证"工具安不安全"。

## 11.5 项目复盘四问

做完订单助手项目，用四问复盘（这也是阶段 4 项目实战的预演）：

1. **时间花在哪了？**——典型分布：认证与安全 > 部署 > 工具逻辑。认这个账：生产级的大头从来不在业务代码。
2. **哪些检查是"形式"？**——如果某个验收步骤你跳过也觉得没事，说明验收清单需要重新设计（要么它没意义，要么你没意识到风险）。
3. **回滚过吗？**——没有回滚过的"生产"是运气；至少在演练里做过一次（07 篇故障演练）。
4. **敢给别人用吗？**——"敢给同事用"是阶段 3 毕业的试金石：文档齐全、报错可懂、故障可恢复、密钥可撤销。

## 11.7 毕业标准的含义

**"敢给同事用"的三层含义**：① 文档层——README 装得上、错误报得懂；② 工程层——有测试、有 CI、可回滚；③ 安全层——密钥可撤销、写操作受控、审计可查。**三层都过，才算阶段 3 毕业**——这个标准比"代码能跑"高出一个维度：它衡量的是"别人能否在没有你的情况下安全地使用它"。

**毕业后的定位**：阶段 3 交付的"可部署 MCP"是阶段 4 的原材料——阶段 4 项目实战将把 MCP Server 与 Agent Skill 组合进完整项目（工具原子、知识可组合）。**现在把 Server 的架构、认证、测试、部署做扎实，阶段 4 只需做集成，不需要返工**。

**自测使用说明**：20+ 道自测题覆盖全部 8 个内容篇目，建议"先作答再对照答案"——答错的题回对应篇目精读对应小节（每题的答案里都标了篇目与概念）。**自测不是考分，是定位薄弱点**：错题集中在哪篇，就说明哪篇的概念还没落地——补读 + 重做对应实战步骤（如认证错题多 → 重做 02 篇的 curl 三连与 scope 设计）。全部通过后，用"面试速记"做每日背诵（每篇 5-6 条，10 分钟一轮），进阶段 4 前做到**不用看文档也能讲清每条**。

## 12. 常见错误与解决

| 错误 | 原因 | 解决 |
|---|---|---|
| 启动报缺少环境变量 | 配置启动校验生效（01 篇） | 补全 `MCP_*` 环境变量 |
| 工具列表为空但代码有工具 | 写工具被 `mcp.disable(tags={"write"})` 全禁用 | 检查 read_only 配置 |
| 401 但令牌有效 | aud/iss 校验失败 | 检查受众配置与签发方（02 篇） |
| 集成测试端口冲突 | CI 并行 | 随机端口（`port=0`）+ fixture |
| 部署后客户端连不上 | .well-known 未透传 | 反代配置（07 篇） |
| 发布后注册表查不到 | server.json 校验失败/命名空间未验证 | `mcp-publisher validate`（08 篇） |
