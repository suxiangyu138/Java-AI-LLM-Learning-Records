## 1. 选型决策框架

> 🎯 **全系列最重要的一张决策图**——复杂度决定框架，不为编排而编排：

```text
开始：你的任务是什么？
│
├─ 固定步骤、直线/简单分支（≤3 步）？
│   └─ YES → LCEL（10-30 行搞定）             ← [[02-LCEL表达式语言]]
│
├─ 需要模型自主决策、动态调用工具（3-8 步循环）？
│   ├─ 单 Agent + 工具集 → create_agent        ← [[05-Agent开发]]
│   └─ 多 Agent 分工 → create_agent + handoffs
│
├─ 需要多阶段流程、人工审批、并行分支（5-20 步）？
│   └─ YES → LangGraph 显式状态机              ← [[06-LangGraph编排]]
│
└─ 需要外部知识 → 任意方案 + RAG 流水线         ← [[04-RAG构建]]

三条金句
├── 「for 循环用 LCEL，while 循环用 Agent」
├── 「create_agent 解决 80% 场景，LangGraph 留给 20% 复杂编排」
└── 「先跑通，再优化；先简单，再复杂」
```

**选型对照表**：

| 需求 | LCEL | create_agent | LangGraph |
|------|:---:|:---:|:---:|
| 单轮 QA / 固定管道 | ✅ 首选 | 过重 | 过重 |
| 多工具自主调用 | 需手写循环 | ✅ 首选 | 可（冗余） |
| 多轮记忆 | 手动注入 | ✅ 内置 | ✅ |
| 人工审批 | 手动实现 | Middleware | ✅ interrupt |
| 并行分支 | ✅ RunnableParallel | ❌ | ✅ |
| 时间旅行/回放 | ❌ | ✅ 部分 | ✅ 原生 |
| 学习成本 | 低 | 中 | 高 |

## 3. 0→1 项目实战流程

> 🎯 **从需求到上线的五阶段**——先做对，再做好：

```text
Phase 1 需求界定（0.5 天）
├── 明确场景：客服 / 知识库问答 / 数据分析 / 工作流
├── 明确边界：数据源、工具集、审批点、用户规模
└── 产出：场景清单 + 选型草案（用第 1 节决策图）

Phase 2 最小可行（2-3 天）
├── 数据准备：加载 → 切块 → 嵌入 → 建索引（若 RAG）
├── 工具开发：按 [[05]] 四原则写工具 + 单测
├── 组装：create_agent 或 LCEL 链跑通「能答」
└── 产出：能跑的最小 Demo（不优化）

Phase 3 质量打磨（3-5 天）
├── 建黄金集（30-50 条）：问题 + 标准答案 + 依据文档
├── 按 [[04-第9节]] 定位失败环节：先验检索再调生成
├── 迭代 Prompt：LangSmith 对比版本效果
└── 产出：黄金集通过率 ≥90%（可自定义阈值）

Phase 4 工程化（2-3 天）
├── 中间件：PII 脱敏 / 工具重试 / HITL 审批
├── 持久化：Postgres Saver + thread_id 规范
├── 安全：鉴权（wrap_tool_call）、限额、审计日志
└── 产出：可部署版本（见 [[05-第9节]] checklist）

Phase 5 上线观测（持续）
├── LangSmith 生产 trace：失败率、token 成本、延迟分位
├── 定期回归：每改一次 Prompt/切块 → 重跑黄金集
└── 灰度：新版本与旧版本并行对比（A/B）
```

## 4. 四大典型架构模式

| 模式 | 构成 | 代码量 | 适用 |
|------|------|:---:|------|
| ① 对话机器人 | create_agent + checkpointer + 无工具 | ~20 行 | 闲聊/陪伴/内部助手 |
| ② 知识库问答 | RAG 流水线（LCEL 链） | ~40 行 | 文档问答、客服 |
| ③ 工具型 Agent | create_agent + 业务工具集 | ~50 行 | 数据分析、订票、运维 |
| ④ 多阶段工作流 | LangGraph + 多 Agent/多审批 | 100+ 行 | 营销策划、风控、研发流程 |

```python
# 模式 ② + ③ 组合（2026 最常见生产形态：Agentic RAG）
from langchain.agents import create_agent

@tool
def search_docs(query: str) -> str:
    """知识库检索：问题涉及产品文档时调用"""
    return "\n".join(d.page_content for d in retriever.invoke(query))

agent = create_agent(
    model="openai:gpt-5.5",
    tools=[search_docs, query_orders, get_stock],
    middleware=[PIIMiddleware(), ToolRetryMiddleware()],
    checkpointer=SqliteSaver.from_conn_string("agent.db"),
)
```

## 5. 0.x → 1.x 迁移

> ⚠️ **迁移成本最高的是「路径依赖」**——0.x 教程代码（LLMChain、AgentExecutor、output_parser 全家桶）在新项目里全部要换写法：

```text
迁移对照表（高频替换）
├── LLMChain + SequentialChain    → LCEL 链（prompt | model | parser）
├── AgentExecutor                 → create_agent（参数化）
├── create_react_agent            → create_agent
├── .output_parser / parse()      → response_format（结构化主循环）
├── ChatOpenAI(model="gpt-4o")    → model="openai:gpt-5.5"（字符串）或显式对象
├── .run()                        → .invoke()
├── stream_mode="messages"        → stream_events(version="v3")
└── langchain.vectorstores.*      → langchain-community 0.4 / 独立包

迁移顺序建议
├── ① 先迁移模型层（Provider 包 + 统一字符串）
├── ② 再迁移链层（LCEL 重写）
├── ③ Agent 层最后（create_agent 重写 + Middleware 替换手动逻辑）
└── 每步跑黄金集回归，别一次性大爆炸迁移
```

**迁移检查清单**：

```text
□ Python 3.10+（3.9 已不支持）
□ langchain 1.3.x + langchain-core 1.3.x
□ AgentExecutor 全部移除（维护期至 2026.12，新代码禁用）
□ 结构化输出用 response_format（省一次调用）
□ 流式用 v3 事件流
□ langchain-community 用 0.4 独立版本
□ 本地模型走 OpenAI 兼容端点（base_url）
```

## 6. 面试高频题（2026）

### 🟢 概念题

**Q1：LangChain 和 LangGraph 的区别？**

```text
答：同一技术栈的两个抽象层，不是替代关系。
├── LangChain = Agent 框架：模型封装/工具抽象/LCEL 组件/create_agent
├── LangGraph = 编排运行时：显式状态机/Checkpointer 持久化/HITL/Time Travel
├── create_agent 底层就是 LangGraph 图
└── 选型：for 循环（直线）用 LCEL，while 循环（自主决策）用 Agent，
   多阶段+审批+并行用 LangGraph
```

**Q2：LCEL 是什么？为什么用管道符？**

```text
答：LCEL 是声明式组合语言。管道符把 Runnable 串成链，
├── ① 统一协议：invoke/ainvoke/batch/stream 六方法同源
├── ② 自动适配：组件间输入输出自动转换
├── ③ 自动优化：并行执行 + 流式传递
└── ④ 可观测：LangSmith 自动追踪
```

**Q3：RAG 为什么能减少幻觉？完全消除吗？**

```text
答：RAG 让答案基于检索到的外部知识（有据可依），显著降低幻觉概率。
但 ① 检索不到正确文档 ② 模型生成时偏离上下文 ③ 文档本身错误
→ 仍会出错。因此必须：忠实度约束 Prompt + 评估（RAGAS）+ 溯源引用。
```

**Q4：Agent 和 Chain（LCEL 链）的区别？**

```text
答：Chain 流程是开发者写死的（for 循环）；
Agent 由模型自主决策流程（while 循环）：思考→行动→观察 直到结束。
确定性任务用 Chain（可预测/便宜），动态任务用 Agent（灵活/贵）。
```

### 🔵 场景题

**Q5：多轮对话如何保记忆？**

```text
答：create_agent 传 checkpointer（Sqlite/Postgres Saver），
调用时带 thread_id，状态自动持久化恢复。
长对话用 SummarizationMiddleware 自动摘要压缩，
避免上下文溢出（成本/延迟/漂移三问题）。
```

**Q6：工具调用失败怎么处理？**

```text
答：三层防御：
├── ① 工具返回「错误说明字符串」——模型可读，自主修正重试
├── ② ToolRetryMiddleware 指数退避自动重试（只重试可重试异常）
├── ③ ToolErrorMiddleware（v1.3）标准化异常 + with_fallbacks 降级链
└── 高危工具挂 HITL——失败时转人工，而不是无限重试
```

**Q7：RAG 检索质量差怎么排查？**

```text
答：按概率顺序排查（先验检索再调生成）：
├── ① retriever.invoke() 肉眼看召回是否相关
├── ② 不相关 → 切块粒度/重叠、重排（Rerank）、换嵌入模型
├── ③ 相关但答错 → 改 Prompt（强约束只依据上下文）
├── ④ 引用错误 → 补 metadata 溯源
└── ⑤ 用黄金集 + RAGAS 指标量化，回归防劣化
```

**Q8：如何做生产级 Agent？**

```text
答：可观测（LangSmith 全量 trace）+ 重试（中间件）
+ 安全（PII 脱敏/工具鉴权）+ 审批（HITL 覆盖高危）
+ 限额（max_tokens/循环上限）+ 评估（黄金集回归）+ 成本看板。
```

### 🟣 代码题

**Q9：手写一个带工具的 Agent**

```python
from langchain.agents import create_agent
from langgraph.checkpoint.memory import InMemorySaver

@tool
def get_weather(city: str) -> str:
    """查询城市天气"""
    return f"{city}: 25°C"

agent = create_agent(
    model="openai:gpt-5.5",
    tools=[get_weather],
    checkpointer=InMemorySaver(),
)
result = agent.invoke({"messages": [{"role": "user", "content": "上海天气"}]})
print(result["messages"][-1].content)
```

**Q10：手写 RAG 检索链**

chain = (
    {"context": retriever, "question": RunnablePassthrough()}
    | ChatPromptTemplate.from_messages([
        ("system", "只依据上下文回答，不知道就说明。\n\n{context}"),
        ("user", "{question}"),
    ])
    | ChatOpenAI(model="gpt-5.5", temperature=0.1)
    | StrOutputParser()
)
