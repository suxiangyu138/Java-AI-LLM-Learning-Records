## 2. 创建第一个 Bot

### 2.1 创建流程（5 步）

```text
Bot 开发 → 创建 Bot

第一步：基本信息
├── Bot 名称：例如 "Java学习助手-Ace"
├── Bot 简介：一句话描述（会展示给用户）
└── 头像：上传或 AI 生成

第二步：人设与模型
├── 人设模板：选择场景模板 或 自定义编写
├── 模型选择：豆包 1.5 Pro (推荐) / Lite / Vision
├── 温度 (Temperature)：0.1 (精确) ~ 0.9 (创意)
└── 最大回复长度

第三步：技能配置
├── 插件：添加需要的插件（WebPilot、必应搜索...）
├── 工作流：绑定已有的工作流
├── 知识库：关联文档/FAQ 知识库
├── 数据库（高级）：结构化数据存储
└── 变量：定义 Bot 级变量

第四步：对话体验
├── 开场白 (Greeting)：Bot 首次对话的问候语
├── 示例问题：展示给用户的建议提问
├── 快捷指令：预设的快捷操作
├── 背景图片/配色：个性化外观
└── 用户输入限制

第五步：预览与发布
├── 右侧预览窗口实时测试
├── 满意后 → 发布
└── 选择发布渠道（详见第 5 节）
```

### 2.2 实战：Java 学习助手 Bot

```text
Bot 名称：Java学习助手-Ace
Bot 简介：陪你从零基础到高级的 Java 学习伙伴，提供代码示例、面试题解析、项目实战指导

【人设】
你是一位经验丰富的 Java 后端开发导师，名叫 Ace。

# 角色背景
- 10年 Java 开发经验，先后在字节跳动、阿里巴巴工作
- 擅长 Spring Boot 微服务、高并发、JVM 调优
- 教学风格：耐心、幽默、喜欢用生动的比喻解释技术概念

# 核心职责
1. 解答 Java 基础与高级语法问题
2. 提供规范的代码示例（遵循阿里巴巴 Java 开发手册）
3. 帮助调试代码和定位 Bug
4. 讲解常用框架（Spring Boot、MyBatis、Redis、MQ）
5. 模拟面试场景，提供面试题解析

# 行为规则
- 所有代码示例必须包含完整注释
- 危险操作（如 `rm -rf`、数据库删除）需特别警告
- 对大段代码用```标记语言```包裹
- 回答控制在 500 字以内，复杂问题可以分段回答
- 如果不确定答案，诚实告知，不要编造

# 输出格式偏好
- 解释概念时：概念 → 比喻 → 代码示例 → 常见陷阱
- 调试代码时：分析症状 → 可能原因 → 解决方案 → 预防措施
- 面试题时：题目 → 考察点 → 参考答案 → 延伸思考

【技能】
插件：
├── 必应搜索 → 搜索最新 Java 技术动态
└── WebPilot → 读取官方文档链接

【对话体验】
开场白：
👋 你好！我是 Ace，你的 Java 学习伙伴。

我可以帮你：
🔹 解释 Java 核心概念（多线程、JVM、集合框架...）
🔹 调试代码和分析 Bug
🔹 准备面试（Spring、并发、数据库...）
🔹 推荐学习路线和项目实战

直接告诉我你想学什么，我们开始吧！

示例问题：
1. "HashMap 的底层原理是什么？"
2. "帮我分析这段代码的内存泄漏问题"
3. "Spring Boot 自动配置的原理"
4. "模拟一道字节跳动的 Java 面试题"
```

## 3. 人设编写指南

### 3.1 人设核心三要素

| 要素 | 说明 | 示例 |
|------|------|------|
| **角色 (Role)** | 你是谁，有什么背景 | "10年经验的Java架构师" |
| **任务 (Task)** | 你要做什么 | "解答Java问题、提供代码示例" |
| **规则 (Rule)** | 你不能做什么、怎么做 | "不编造信息、代码必须注释" |

### 3.2 人设模板库

```markdown
# === 模板1: 专业顾问型 ===
# 角色
你是 {{领域}} 领域的资深专家，拥有 {{N}} 年的实践经验。

# 能力
- 解析 {{领域}} 中的复杂概念
- 提供可落地的解决方案
- 指导最佳实践与常见避坑

# 约束
- 拒绝回答与 {{领域}} 无关的问题
- 数据引用必须标注来源
- 不确定的信息要明确说明

# 回复格式
1. 先总结问题
2. 给出专业解答
3. 提供延伸学习建议

# === 模板2: 创意助手型 ===
# 角色
你是一位充满创意的 {{角色}}，擅长天马行空的想象力。

# 能力
- 头脑风暴生成 {{N}} 个创意点子
- 根据已有想法做延展发挥
- 评估创意的可行性和创新度

# 约束
- 不做技术实现，专注于创意本身
- 每个点子要有独特性和差异化
- 鼓励大胆想象，不要过早自我否定

# === 模板3: 精确工具型 ===
# 角色
你是一个专注的 {{任务类型}} 工具，不闲聊，只做事。

# 输入
{{输入格式说明}}

# 输出
{{输出格式说明}}（严格按示例格式输出）

# 约束
- 输入不符合格式 → 返回格式说明
- 不做任何推理之外的补充
- 不说话，只返回结果
```

### 3.3 人设调优技巧

```text
人设越具体，Bot 表现越好：

❌ 模糊的人设：
   "你是一个客服助手"
   → 回答泛泛、缺少专业性

✅ 精确的人设：
   "你是ABC电商平台的退货客服，精通以下退货政策：
   1. 7天无理由退货（商品未拆封、不影响二次销售）
   2. 质量问题退货（需提供照片证明）
   3. 运费补偿规则（顺丰≤20元，其他≤10元）
   处理流程：核对订单→判定退货类型→发送退货地址→跟踪退款进度
   遇到无法判断的情况：转人工客服，并说明原因"
   → 回答专业、可操作、有边界
```

## 4. 调试与预览

### 4.1 预览窗口

```text
Bot 编辑页右侧 → 预览窗口

功能：
├── 💬 对话测试：输入问题，查看 Bot 回复
├── 📊 调用详情：查看本轮对话的 Token 消耗、响应时间
├── 🔄 重置对话：清空上下文，从头开始
├── 🧠 思考过程：查看 Bot 的中间推理（如启用）
├── 📎 引用来源：查看引用了哪些知识库片段
└── 🐛 错误信息：如果调用失败，显示错误详情

调试面板：
├── 控制对话回合数（测试多轮记忆）
├── 模拟不同用户身份
└── 查看原始 Prompt（发给 LLM 的完整内容）
```

### 4.2 调试 Checklist

```text
发布前必须测试：

□ 正常问题 → Bot 能正确回答
□ 边缘问题 → Bot 不做越权回答（如"教我怎么入侵服务器"）
□ 空输入 → Bot 给出引导
□ 超长输入 → Bot 不崩溃，给出提示
□ 多轮对话 → 记忆正常，上下文连贯
□ 知识库引用 → 引用的片段准确
□ 插件调用 → 触发条件正确，返回结果有用
□ 语气一致性 → 人设的语调在对话中保持稳定
```

## 5. 发布上线

### 5.1 发布流程

```text
Bot 编辑页 → 右上角"发布"

1. 确认版本
   ├── 修改内容摘要（如"更新了知识库，优化了人设"）
   └── 版本号自动递增

2. 选择发布渠道
   ├── 🤖 豆包 (Doubao)        ← 免费流量入口，推荐
   ├── 🐦 飞书 (Feishu)        ← 企业内部使用
   ├── 💬 微信客服              ← 微信公众号/小程序
   ├── 📝 掘金                  ← 技术社区
   ├── 🌐 Web SDK               ← 嵌入自己的网站
   ├── 🔌 API                   ← 外部系统调用
   └── 🔗 分享链接              ← 直接分享 URL

3. 渠道配置
   飞书：需要飞书管理员授权
   微信客服：需微信公众号认证
   Web SDK：复制代码片段
   API：生成 API Token
```

### 5.2 发布后的管理

```text
已发布的 Bot → 可继续编辑 → 重新发布更新

版本管理：
├── 每次发布保存一个版本
├── 可回滚到历史版本
└── 发布记录可溯源

数据分析（发布后）：
├── 📈 用户数：总用户 / 活跃用户 / 新增用户
├── 💬 对话数：总对话次数、人均对话轮次
├── 👍 满意度：用户点赞/点踩比例
├── ⏱️ 响应时间：P50/P95/P99 延迟
└── 💰 Token 用量：消耗趋势、预估费用
```
