## 1. 记忆体系总览

| 记忆类型 | 内容 | 位置 | 稳定性要求 |
|---|---|---|---|
| R1 Thought Harvest | R1 思维链回收记录 | 会话内回放 | 追加型 |
| Persistent Memory | 项目约定、架构决策 | `.reasonix/memory.md` | 字节级稳定 |
| Skills | 可复用技能脚本 | 固定位置 | 字节级稳定 |

三条线共用同一设计原则：**记忆与技能都服务于前缀缓存**——放在固定前缀里的内容必须可复现、可哈希。

## 2. R1 Thought Harvest 思维链回收

DeepSeek R1 系列模型会在 `<think>` 标签内输出数千字的思维链（reasoning）。Reasonix 把这些"思考过程"回收利用：

### 解决的问题

| 问题 | 说明 |
|---|---|
| 思考泄露 | 思维链可能泄露不应出现的中间信息 |
| 语法畸形 | `<think>` 标签格式不规则，直接丢弃浪费 |

### 机制

- 回收 `<think>` 标签内的思考内容
- 形成**可回放的思维链记录**（Thought Harvest 记录）
- 后续轮次可引用之前的思考结论，避免重复推理

价值：思考是"已支付成本的推理产物"——回收后同一问题不需要再想一遍（也省 token）。

## 3. Persistent Memory 持久记忆

### 工作机制

- 文件：`.reasonix/memory.md`（项目级）+ 全局记忆（`/memory` 命令管理）
- 加载时机：会话启动时加载项目约定与架构决策
- 位置：**固定前缀内**（对应 03 篇的不可变前缀区域）
- 会话内保持字节级稳定——不追加新记忆不重写

### 适合写入的内容

| 类别 | 示例 |
|---|---|
| 项目约定 | 技术栈、目录结构、代码风格 |
| 架构决策 | 为什么用 A 不用 B（ADR 精简版） |
| 工作流偏好 | 提交前必须跑测试、CHANGELOG 规范 |
| 高危文件 | 哪些文件不允许自动修改 |

### /memory 命令

- 查看当前记忆
- 更新项目级/全局级记忆
- 记忆写入后即成为前缀一部分，对缓存命中率有贡献

> ⚠️ 与 Claude Code 对照：Claude Code 的 CLAUDE.md 每次会话读取（内容变化会破坏 Reasonix 前缀）——Reasonix 的 memory 强调"会话内冻结"，要改约定就改文件、新会话生效。

## 4. Skills 技能系统

Skills 是**用 Markdown frontmatter 编写的可复用脚本**：

```markdown
---
name: code-review
description: 审查代码改动，输出问题清单
runAs: subagent
---

# 审查步骤
1. 读取改动 diff
2. 检查：正确性 / 边界 / 安全隐患
3. 输出：问题清单 + 修改建议
```

| 字段 | 说明 |
|---|---|
| `name` | 技能名 |
| `description` | 触发场景描述 |
| `runAs: subagent` | **隔离子循环运行**（不污染主会话前缀） |

### 设计要点

- 技能模板**固定在 prompt 的固定位置加载**——维持缓存稳定（直接呼应 03 篇）
- `runAs: subagent` 让技能在独立上下文中运行，结果回到主会话——既复用能力又不破坏主前缀
- 创建方式：`/skill new` 交互式生成，也可手写文件

## 5. 缓存视角下的记忆与技能设计

理解 Reasonix 的记忆/技能系统，必须回到缓存视角：

| 设计决策 | 缓存原因 |
|---|---|
| 记忆放固定前缀 | 前缀必须字节稳定才能命中 |
| 技能固定位置加载 | 位置变化 = 前缀变化 |
| 技能 subagent 运行 | 主会话前缀不被技能内容污染 |
| 会话内记忆冻结 | 中途改写 = 前缀失效 |
| R1 思维回收 | 思考结论复用，减少重复推理 token |

> 🎯 核心要点：通用 Agent 的记忆/技能设计问"怎么让 AI 更懂我"，Reasonix 多问一句"怎么让前缀更稳"——同样是记忆文件，放对位置（前缀）是资产，放错位置（日志中段）是破坏者。
