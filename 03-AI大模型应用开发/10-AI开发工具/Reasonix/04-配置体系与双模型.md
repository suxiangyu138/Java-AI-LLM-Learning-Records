## 1. 配置驱动哲学

| 对比项 | Reasonix | 传统 Agent |
|---|---|---|
| 模型 | `reasonix.toml` 声明，不硬编码 | 内置/默认模型写死 |
| 工具 | 声明启用 | 全部默认启用 |
| 插件 | 声明挂载 | 需手动注册 |
| 自定义 | 任意 OpenAI 兼容端点加一行 | 供应商白名单 |

好处：

- **零代码扩展**：换模型、加工具、挂插件都是配置改动，不改程序
- **仓库级复现**：配置文件随仓库走，团队共享同一套 Agent 行为
- **缓存友好**：配置确定的工具集/排序是前缀稳定的前提（见 03 篇）

## 2. 配置文件总览

| 位置 | 作用域 | 用途 |
|---|---|---|
| `~/.reasonix/config.json` | 全局 | API Key 等全局设置 |
| `reasonix.toml` | 项目级 | 模型/工具/插件/hooks 全声明 |
| `.reasonix/` 目录 | 项目级 | 记忆文件（memory.md）、技能等 |

三层配置的职责划分：全局放密钥与个人偏好，项目级放团队约定，目录级放动态产物（记忆、checkpoint）。

## 3. 核心配置项详解

```toml
# reasonix.toml 核心配置示例
planMode = true                # 先展示计划，批准后才改文件
autoCheckpoint = true          # 逻辑断点自动 git commit，便于回退

[memory]
file = ".reasonix/memory.md"   # 持久记忆：项目约定与架构决策

[mcp.servers]                  # MCP 服务器（stdio 型）
[mcp.servers.github]
command = "npx"
args = ["-y", "@modelcontextprotocol/server-github"]

[hooks]                        # 生命周期钩子
afterEdit = "npm run lint"     # 每次编辑后自动 lint
afterSession = "git add -A"    # 会话结束自动暂存
```

| 配置项 | 说明 | 典型值 |
|---|---|---|
| `planMode` | 先计划后执行，大型重构必备 | `true`（复杂任务开） |
| `autoCheckpoint` | 逻辑断点自动 git commit | `true` |
| `memory.file` | 持久记忆文件路径 | `.reasonix/memory.md` |
| `hooks` | 生命周期 shell 命令 | afterEdit/afterSession |
| `mcp.servers` | MCP 服务器声明 | stdio JSON-RPC |
| `skills` | 技能模板声明 | 固定在 prompt 固定位置加载 |

> 💡 `planMode` 与 `autoCheckpoint` 是生产环境黄金组合：计划门禁防止乱改，自动 checkpoint 保证随时可回退——两条安全网都启用后，可以让 Agent 放手干。

## 4. Executor + Planner 双模型

Reasonix 支持"执行器 + 规划器"双模型组合：

```
┌──────────────┐     计划      ┌──────────────┐
│   Planner    │ ────────────▶ │   Executor   │
│  (规划器)     │              │  (执行器)      │
│  战略/拆解    │              │  战术/实现     │
└──────────────┘              └──────────────┘
   各自独立前缀缓存               各自独立前缀缓存
```

| 角色 | 职责 | 选型建议 |
|---|---|---|
| Planner | 理解需求、拆解任务、制定计划 | 推理强的模型（Reasoner/Pro） |
| Executor | 执行工具调用、写代码 | 快而省的模型（Flash） |

价值：

- **分工降本**：规划次数少（每任务几次）用强模型，执行次数多（每轮多次）用便宜模型
- **缓存独立**：两个角色的上下文各自稳定，互不污染前缀

## 5. OpenAI 兼容端点接入

任意 OpenAI 兼容 endpoint **加一行配置**即可用：

```toml
[providers.myprovider]
base_url = "https://api.example.com/v1"
api_key = "sk-..."
model = "my-model"
```

| 场景 | 配置方式 |
|---|---|
| DeepSeek 官方 | 默认支持，配 DEEPSEEK_API_KEY |
| 第三方 OpenAI 兼容 | `[providers.xxx]` 声明 base_url + key |
| 本地模型（vLLM/Ollama） | base_url 指向本地端点 |
| Kimi K3（v1.18+） | 官方 Kimi 国内/全球 API 及 OpenCode Go |

## 6. Hooks 生命周期钩子

| 钩子 | 触发时机 | 典型用途 |
|---|---|---|
| `afterEdit` | 每次文件编辑后 | 自动 lint、格式化 |
| `afterSession` | 会话结束后 | 自动 git add、清理临时文件 |

与 Claude Code hooks 的对照：Reasonix 的 hooks 是配置内声明（TOML），Claude Code 是 settings.json 内声明——理念一致（shell 命令挂生命周期），实现位置不同。

> 🎯 核心要点：配置驱动的意义被很多用户低估——`reasonix.toml` 里的一行 `planMode = true` + 一个 `afterEdit` 钩子，效果抵得上十条口头叮嘱 Agent 的对话轮次，而且不破坏缓存前缀。
