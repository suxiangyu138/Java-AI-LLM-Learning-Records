## 2. 成本对比实证

| 指标 | Reasonix | Claude Code |
|---|---|---|
| 单日 435M token 编码会话 | 约 **$12**（缓存命中） | 约 $61（README 估算同量级） |
| 单功能开发 | $0.14-0.28 | $15-30（API 直连） |
| 单任务 | 约 $0.08 | 约 $0.34 |
| 日常会话 | Flash $0.03-0.08 / Pro $0.14-0.35 | 订阅制或按量 |

缓存命中率口径：

| 工具 | 日常命中率 |
|---|---|
| Reasonix | 81-96.7%（实测最高 99.82%） |
| 通用 Agent（Claude Code/Cursor/Aider 跑 DeepSeek） | 通常不足 20%（每轮重排改写 prompt 破坏前缀） |

> ⚠️ 评测中立性提示：Reasonix 与 Claude Code 的官方对比报告各有偏向（Reasonix 忽略 Claude Code + CC Switch 的缓存配置方案，Claude Code 对 Reasonix 的 Memory/Skills 优势降权）——取双方都承认的事实：缓存架构差异真实存在，但通用工具 + 正确配置也能获得较高命中率。

## 4. 选型决策树

```
需要 AI 编程 Agent？
├─ 追求最强推理与生态 → Claude Code（成本最高）
├─ 预算敏感 + DeepSeek 用户
│   ├─ 长会话高频迭代 → Reasonix（成本甜区）
│   ├─ 需要多模型自由切换 → Aider
│   └─ 数据不出本机/私有化 → Reasonix / Aider
├─ 喜欢编辑器内交互 → Cursor
└─ 国内直连 + 极致成本 → Reasonix（中文原生、免梯子）
```

## 5. 双工具组合策略

社区推荐的组合方案：

```
Reasonix 承担 80% 日常编码（改需求、补测试、修 Bug、写文档）
Claude Code 处理 20% 复杂场景（大型重构、疑难调试、架构设计）
```

| 分工 | 工具 | 理由 |
|---|---|---|
| 日常迭代 | Reasonix | 成本 1/4，缓存命中率 90%+，中文原生 |
| 复杂推理 | Claude Code | 推理质量上限最高，生态工具全 |
| 兜底 | 任一 + DeepSeek API | 极端成本敏感时两者都用 DeepSeek |

组合的理论基础：**"模型 + 代理的工程组合正在替代单纯的模型性能"**——Reasonix 的缓存工程 + Claude 的推理质量，各取所长。

## 6. 面试速记

1. Reasonix 是 **esengine 出品的开源（MIT）终端 AI 编码 Agent**，专为 DeepSeek 设计（30k+ stars），定位"DeepSeek 生态的 Claude Code"。
2. 核心机制是**缓存优先架构**：把 DeepSeek 前缀缓存作为架构级不变量——上下文分三区（不可变前缀/只追加日志/临时草稿区），只追加不重写，实测命中率 99.82%，成本降到 2 折（$61 → $12）。
3. 通用 Agent 命中率只有 20-60% 的原因：压缩历史、重排消息、注入时间戳破坏前缀字节连续性——"为了省 100 个 token 损失 10000 个 token 的缓存"。
4. 工程细节：Tool-Call Repair 四轮工序修复 DeepSeek 工具调用故障（消失/畸形/风暴/截断）；Cost Control 默认 Flash + `/pro` 单轮升级 + 失败自动升级。
5. 取舍：牺牲模型通用性与任务拆解自主性，换取 DeepSeek 极限成本效率；速度与复杂任务自主性不如 Claude Code。社区主流方案是"Reasonix 80% 日常 + Claude Code 20% 复杂"。
