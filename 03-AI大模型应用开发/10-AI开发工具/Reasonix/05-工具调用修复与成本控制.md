## 1. DeepSeek 工具调用的四类故障

Reasonix 明确列出 DeepSeek 模型在工具调用上的四个已知故障模式：

| 故障类型 | 表现 | 危害 |
|---|---|---|
| 调用消失 | 工具调用 JSON 在最终消息中消失 | Agent 以为调用了，实际没执行 |
| JSON 畸形 | 参数 JSON 语法错误（引号/括号缺失） | 工具执行直接失败 |
| 调用风暴 | 同一工具反复调用且参数完全相同 | token 浪费 + 执行重复操作 |
| JSON 截断 | 输出被截断，JSON 不完整 | 解析失败，卡死 |

> ⚠️ 这些是 DeepSeek 模型的已知弱点而非偶然 bug——通用 Agent 遇到即报错重试（浪费轮次 + 破坏前缀），Reasonix 的做法是执行前修复。

## 2. Tool-Call Repair 四轮工序

四轮处理在**真正执行前**完成修复：

```text
原始输出 → ① 修复消失 → ② 修复畸形 → ③ 修复风暴 → ④ 修复截断 → 执行
```

| 轮次 | 修复目标 | 策略 |
|---|---|---|
| ① | 调用消失 | 从历史中找回被遗漏的工具调用声明 |
| ② | JSON 畸形 | 语法级修复：补全引号、括号、逗号 |
| ③ | 调用风暴 | 去重：合并参数完全相同的重复调用 |
| ④ | JSON 截断 | 基于 schema 补全截断部分 |

修复后的干净工具调用再进入执行循环——**修复发生在缓存之外**（草稿区），不污染前缀（对应 03 篇三区划分中"归入日志前需经 Tool-Call Repair 提炼"）。

## 3. Cost Control 三级策略

| 层级 | 策略 | 效果 |
|---|---|---|
| 默认 | 优先使用 **v4 flash**（便宜模型） | 日常任务成本 $0.03-0.08 |
| 按需 | 困难任务 `/pro` 切 **v4 pro** | 单轮高质量，跑完自动切回 |
| 兜底 | 失败信号自动升级 | 失败轮次自动切 pro 重试 |

设计逻辑：

- 大部分编码任务不需要最强推理——flash 足够
- 只在"当前任务确实难"时花钱升级，且升级是**单轮的、临时的**（`/pro`）
- 升级决策不依赖用户判断，也由失败信号自动触发

## 4. /pro 与 /preset 模型切换

| 命令 | 行为 | 成本影响 |
|---|---|---|
| `/pro` | 下一轮切 v4 pro，跑完自动回 flash | 单轮高价 |
| `/preset max` | 整个会话升级 v4 pro | 全程高价 |
| `/preset fast` | 回到默认 flash 路由 | 恢复低价 |

典型成本：

| 会话类型 | 成本范围 |
|---|---|
| Flash 会话 | $0.03-0.08 |
| Pro 会话 | $0.14-0.35 |

> 💡 使用建议：**默认 flash 推进，卡住了再 `/pro`**——大多数"卡住"发生在测试失败、编译错误这类具体问题上，pro 的推理能力正好补上。

## 5. 失败信号自动升级

自动化升级策略：

- 监控失败次数（工具执行失败、验证失败）
- 失败次数达警戒线后，当前轮次**剩余部分自动切到 pro**
- 切换后继续执行，不中断用户操作

与手动 `/pro` 的关系：手动升级是"人判断这活难"，自动升级是"系统判断这活总失败"——两层互补，覆盖主观与客观两类升级需求。

## 6. 成本仪表与统计

```bash
reasonix stats
```

统计内容：

| 指标 | 含义 |
|---|---|
| turns | 会话轮次 |
| cache hit | 缓存命中率（核心指标！） |
| cost | 实际花费 |
| 节省对比 | 与 Claude Code 同等任务的价格对比 |

桌面版（Tauri）实时显示：底部 cost / cache / token 计量表，多标签页会话各看各的。

> 🎯 核心要点：Reasonix 的成本控制是"**策略分层 + 自动兜底**"——默认便宜、按需贵、失败自动升级，用户无需关心每轮该用哪个模型；同时 `/stats` 把缓存命中率作为一等指标呈现，让"省没省"一目了然。
