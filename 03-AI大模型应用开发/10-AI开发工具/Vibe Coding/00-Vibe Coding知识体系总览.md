## 4. 核心概念速查

| 概念 | 一句话解释 |
|------|-----------|
| **Vibe Coding** | 2025.02 Karpathy 提出：只描述意图、由 AI 写代码、靠运行效果迭代 |
| **意图工程** | 用分层自然语言（业务意图/技术约束/验收标准）替代传统 PRD |
| **AI 全能开发** | 2026 范式：Vibe Coding + Agent 覆盖需求→编码→测试→部署全链路 |
| **纯粹模式** | 完全信任 AI、追求极致速度，适用于原型与 Demo |
| **负责任模式** | 把 AI 当 pair programmer，人工审查 + 测试，适用于生产级 |
| **上下文腐烂** | 上下文过多时模型无法判断优先级，反而降低生成质量 |
| **AI Slop** | 不可维护的 AI 生成代码泛滥，非标准化开发返工 +72%（McKinsey） |
| **Slopsquatting** | 攻击者注册 AI 幻觉出的不存在的包名实施供应链攻击 |
| **BYOK** | Bring Your Own Key：自带模型密钥换取成本透明与模型自由 |
| **规则先行** | Vibe Coding 效率上限取决于前置工程规范，而非 Prompt 精细度 |

## 5. 一图看懂：Vibe Coding 与传统开发

| 维度 | 传统开发 | Vibe Coding（2026） |
|------|---------|---------------------|
| 输入 | 详细 PRD + 技术设计文档 | 分层意图描述（意图工程） |
| 写码者 | 程序员 | AI 智能体（多 Agent 协同） |
| 人的角色 | 编码执行者 | **意图架构师**（定义/审查/决策） |
| 迭代方式 | 编码 → 编译 → 调试 | 生成 → 运行 → 反馈闭环 |
| MVP 周期 | 7-10 天 | 4-8 小时（效率 10x+） |
| 核心风险 | 人力成本高 | 技术债 / AI Slop / 供应链攻击 |
| 适用上限 | 无 | 核心交易/强监管场景慎用 |

---

> 💡 **一句话总结**：Vibe Coding 不是「零代码」神话，而是「低代码 + AI 增强」——把程序员从键盘上解放出来，放到更高维度的意图定义、架构决策与质量把控上。
