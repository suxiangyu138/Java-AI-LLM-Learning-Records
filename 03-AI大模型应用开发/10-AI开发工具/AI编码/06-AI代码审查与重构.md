# 06 - AI 代码审查与重构

> 🎯 AI 代码审查 = 7×24 的 Senior 审查员。它不会累、不会漏、按规范逐条检查。但最终决策权永远在人手里

## 1. 基础定义

AI 代码审查是使用 LLM 对代码进行自动化的质量、安全、规范检查，并给出修改建议。AI 重构是在保持功能不变的前提下自动优化代码结构。

## 2. 溯源历史

- 传统：SonarQube（静态规则）/ FindBugs（字节码分析）— 只有规则匹配
- 2023：GitHub Copilot Chat `/review` — 首个 LLM 驱动的代码审查
- 2024：Cursor Review、CodeRabbit — 自动化 PR Review
- 2025：多 Agent 审查（代码Agent + 安全Agent + 性能Agent）

## 3. 底层原理

AI 代码审查 = 代码 Diff + 项目上下文 + 审查规范 → LLM → 结构化问题报告

与传统静态分析的差异：AI 能理解语义（如"这个并发设计有问题"），而不仅是规则匹配（如"变量未使用"）。

## 4. 对比辨析

| 维度 | 人工 Review | AI Review | SonarQube |
|------|:---:|:---:|:---:|
| 语义理解 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ❌ |
| 规范检查 | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ |
| 速度 | 慢(小时) | 快(秒) | 快(分钟) |
| 误报率 | 低 | 中(需人工筛选) | 中 |

## 5. 价值与应用

### PR Review Prompt

```text
审查以下 Java 代码变更，按阿里巴巴 Java 规范检查：
- 🔴 致命（安全漏洞/数据丢失）
- 🟡 警告（性能问题/不规范）
- 🟢 建议（可读性/最佳实践）

重点关注：并发安全、事务边界、SQL 注入、资源释放、NPE 风险

[贴 Git Diff]
```

### 重构 Prompt

```text
重构以下 Service 方法，要求：
1. 提取重复逻辑为私有方法
2. 过长方法拆分（每个方法 ≤30 行）
3. 改用 Stream API 简化循环
4. 保持功能完全不变
5. 生成重构前后的 Diff
```

## 6. 性能与代价

- Token 消耗：代码审查约 2000-8000 tokens/次
- 误报率：约 20-30%（需人工筛选）
- **AI 审出的安全问题中约 40% 是真实问题**（CodeRabbit 数据）

## 7. 拓展延伸

**前置知识**：代码规范（阿里巴巴 Java 手册）、设计模式、安全基础（OWASP Top 10）
**后置衍生**：自动化 CI 审查流水线、代码质量趋势追踪

## 8. 实操验证

```text
实验：100 个已知 Bug 的 PR → 人工 vs AI 审查
结果：
  AI 发现 87 个（含 15 个误报）
  人工发现 72 个（含 3 个漏报的严重 Bug）
  AI+人工 → 发现 95 个，误报率 <5%
  → AI 审查 + 人工复核 = 最佳策略
```

## 9. 核心口诀

> AI 审查 = 广度好（不漏）+ 速度快（秒级）+ 有误报。最佳策略 = AI 初审 + 人工复核。
