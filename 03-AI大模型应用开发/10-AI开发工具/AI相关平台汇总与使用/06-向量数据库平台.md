# 06 - 向量数据库平台

> 🎯 RAG 的存储层 — 向量数据库是检索增强生成的"索引引擎"。Pinecone（全托管 Serverless 零运维）、Qdrant（Rust 高性能自托管）、Milvus（国产分布式海量向量）、Weaviate（混合搜索+AI 模块一体化）、pgvector（PostgreSQL 生态零迁移）。选型的关键是运维能力 vs 控制权的权衡

## 1. 五大平台对比

| 平台 | 开源 | 部署模式 | 核心语言 | 估值/融资 | 核心优势 |
|------|:---:|----------|----------|-----------|----------|
| Pinecone | ❌ | **仅 SaaS** | — | $750M+ | 零运维 Serverless，自动扩展到数十亿向量 |
| Qdrant | ✅ | 云+自托管 | **Rust** | — | **原始性能最强**，内存效率高，部署灵活 |
| Milvus | ✅ | 云+自托管 | Go/C++ | $250M+ | 国产分布式，百亿级向量规模 |
| Weaviate | ✅ | 云+自托管 | Go | — | **混合搜索**（向量+关键词），AI 模块集成 |
| pgvector | ✅ | PG 扩展 | C | — | PostgreSQL 生态零迁移，适合已有 PG 的团队 |

> 💡 向量数据库市场 2026 预计 $2.65B，2030 年 $8.95B（CAGR 27.5%）。Pinecone 估值信号表明 Serverless 方向获得最高溢价。

## 2. Pinecone — 全托管 Serverless

| 维度 | 详情 |
|------|------|
| 核心架构 | **Serverless only**（无自托管选项）— 自动扩缩容到数十亿向量 |
| 延迟 | 大规模下 <100ms |
| 安全 | SOC 2 Type II、HIPAA、VPC peering、SSO、RBAC |
| 功能 | HNSW 索引、元数据过滤、稀疏-稠密混合搜索、命名空间隔离、实时 upsert |
| SDK | Python、Node.js、**Java**、Go |
| 价格 | ~$0.015/千向量/月（1 亿向量约 $1,500/月） |
| 劣势 | 供应商锁定、无开源退出路径、成本随规模线性增长 |

**选 Pinecone 的理由：** 无平台团队、要低运维的生产 RAG。不选它的理由：成本敏感、数据主权要求本地部署。

---

## 3. Qdrant — 高性能自托管

| 维度 | 详情 |
|------|------|
| 核心架构 | **Rust** 构建（Apache 2.0），ANN benchmark 持续领先 |
| 性能 | 10M 向量/5K QPS 下 p95 延迟 **47ms**（比 Pinecone 同负载低 80%） |
| 内存效率 | 量化（binary/scalar）、磁盘索引、mmap — 10M×1024 维仅需 **48GB RAM**，比 Pinecone 同召回少 60% |
| 部署 | Kubernetes 原生、Helm 部署、或 Qdrant Cloud |
| 劣势 | 生态小于 Pinecone/Weaviate，企业 SLA 不如老牌厂商 |

**选 Qdrant 的理由：** 追求原始性能、需要本地/私有化部署（数据主权）、已有 DevOps 团队。不选它的理由：不想操心运维。

---

## 4. Milvus — 国产分布式海量向量

| 维度 | 详情 |
|------|------|
| 核心架构 | **分布式**：Proxy/Data Node/Index Node/Query Node 分离，单集群支持百亿级向量 |
| 生态 | Zilliz Cloud 全托管、国内主流 RAG 方案首选（LangChain/LlamaIndex/Dify 均原生支持） |
| 混合搜索 | 支持标量过滤 + 向量搜索 + 全文检索（Milvus 2.4+） |
| 部署 | Kubernetes、Docker Compose |
| 开源 | ✅（Apache 2.0） |

**选 Milvus 的理由：** 国产技术栈（文档中文最好）、海量向量规模（百亿级）、需要分布式架构。不选它的理由：运维复杂度较高（微服务架构需管理多个组件）、1 亿以下向量量级运维成本比价值高。

---

## 5. Weaviate — 多模态混合搜索

| 维度 | 详情 |
|------|------|
| 核心架构 | GraphQL API（原生 GraphQL 接口，无需 REST 封装） |
| 混合搜索 | **关键词（BM25）+ 向量搜索**在同一查询中 — 非简单拼接，融合排分 |
| AI 模块 | 内置模块（text2vec-transformers、generative-search 等）— 可省去外部嵌入服务 |
| 多租户 | 原生多租户隔离 |

**选 Weaviate 的理由：** 需要混合搜索（非纯向量搜索）、想减少外部服务（内置 AI 模块）、GraphQL 偏好团队。不选它的理由：JVM 内存消耗大、自托管资源需求高。

---

## 6. pgvector — PostgreSQL 生态零迁移

| 维度 | 详情 |
|------|------|
| 定位 | PostgreSQL 扩展（非独立数据库），在现有 PG 表上加一列 `VECTOR` 类型 |
| 优势 | **零迁移成本**（团队已用 PG）、事务一致（向量与业务数据同一事务）、运维不用多学一套 |
| 劣势 | 性能天花板（百万级向量以下 OK，千万级以上不如专用向量库）、索引构建慢 |
| 索引 | IVFFlat（快但近似）、HNSW（精确但内存占用大） |

**选 pgvector 的理由：** 已有 PostgreSQL、向量量在百万级、不想引入新数据库。不选它的理由：千万级以上向量规模。

---

## 7. 性能与成本对比 + 选型速查

| 场景 | 推荐 | 理由 |
|------|------|------|
| 全托管、零运维、生产 RAG | **Pinecone** | Serverless 扩展到数十亿、企业安全完备 |
| 最大性能、自托管、数据主权 | **Qdrant** | Rust 性能+内存效率最佳、K8s 原生 |
| 国产技术栈、百亿级向量 | **Milvus** | 分布式架构、中文生态最好 |
| 混合搜索（关键词+向量） | **Weaviate** | BM25+向量融合、内置 AI 模块 |
| 已有 PG 生态、百万级向量 | **pgvector** | 零迁移、事务一致性 |
| Spring AI 集成 | Pinecone / Qdrant / Milvus / pgvector | Spring AI 均支持 Starter |

**成本速算：** 1 亿向量×1536 维 → Pinecone Serverless ~$1,500/月（托管）；Qdrant 自托管 → 仅 GPU 费用（4×A10G ~$2,400/月，但支持更高 QPS）；pgvector 自托管 → 仅 PG 服务器成本（但性能天花板低）。

---

> 🎯 **核心要点**：向量数据库选型 = **运维能力 vs 控制权** — 不想管运维→Pinecone（贵且锁定）、有 DevOps→Qdrant（性能最好又省钱）、中国业务→Milvus（国产首选）、部门已有 PG→pgvector（先跑起来）、需要关键词+向量融合→Weaviate。Spring AI 同时支持前四个。
