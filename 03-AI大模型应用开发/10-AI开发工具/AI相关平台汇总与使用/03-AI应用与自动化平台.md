## 1. 四平台定位对比

| 维度 | Coze（扣子） | Dify | Make | n8n |
|------|-------------|------|------|-----|
| 出品 | 字节跳动 | 开源社区 | Make（原Integromat） | 开源社区 |
| 部署 | 仅云端 | 云端+**开源本地** | 仅云端 | 云端+**开源本地** |
| 定位 | 对话 Agent 搭建 | **知识库+RAG** | 通用工作流自动化 | 通用工作流自动化 |
| 核心优势 | 约700插件、字节生态 | 知识库/RAG 检索 | **3000+** 应用插件 | 约500节点、自定义代码 |
| 适合人群 | 快速搭 AI 聊天机器人 | 企业知识库/RAG应用 | 个人/零基础小白 | 企业私有化+业务流程 |
| 代码要求 | 零代码→低代码 | 零代码→低代码 | 零代码 | 低代码（JS/Python） |
| 文件系统 | `/Coze/`（8 文件） | `/Dify/`（7 文件） | 本文件 | 本文件 |

> 💡 Coze 和 Dify 各有完整深度系统（在 `03-AI大模型应用开发/` 下），此处只做对比选型。

## 2. Coze vs Dify：AI 应用开发双雄

| 对比维度 | Coze | Dify |
|----------|------|------|
| **核心侧重** | 对话智能体 | 知识库/RAG |
| 模型支持 | 豆包默认 + 接入第三方 | 接入 OpenAI/Claude/国产 等 |
| 工作流 | 可视化编排 | 可视化编排 + Agent 策略 |
| 插件 | ~700 个 + 自定义 | 工具 API + 自定义 |
| 知识库 | 支持 | **核心优势**（多种分块策略） |
| 发布渠道 | 豆包/飞书/微信/API | Web/API/iframe 嵌入 |
| 私有化部署 | ❌ | ✅ |
| 最佳场景 | 快速搭客服/聊天机器人 | 企业知识库问答系统 |

## 3. Make vs n8n：自动化平台之战

| 对比维度 | Make | n8n |
|----------|------|-----|
| **应用连接数** | **3000+**（业界最多） | ~500 个 |
| 可视化 | 拖拽式、零代码 | 拖拽式 + 代码节点 |
| 自托管 | ❌（仅云端） | ✅（Docker/K8s） |
| 自定义扩展 | 有限 | **JS/Python 代码节点** |
| 学习曲线 | 最低 | 中等 |
| AI 融合 | 成熟（原生 AI 节点） | 需手动接入 API |
| 定价模式 | 订阅制（按操作量） | 开源免费 + 云托管付费 |
| 最佳场景 | 个人/小团队轻量自动化 | 企业级复杂业务流程（需私有化+代码扩展） |

## 4. 选型决策树

```text
问题 1：你需要 AI 功能吗（LLM/知识库/Agent）？
  ├── 需要 → 问题 2
  │   ├── 侧重知识库/RAG → Dify
  │   └── 侧重对话聊天 Agent → Coze
  │
  └── 不需要（纯流程自动化） → 问题 3
      ├── 需要私有化部署 → n8n
      ├── 零基础、快速上手 → Make
      └── 需要代码扩展 + 复杂业务流程 → n8n
```

**追问：** Coze 也可以做知识库，为什么 Dify 更侧重？→ Dify 的知识库设计更深（多种分块策略/检索模式/召回评估），Coze 的知识库是配套能力而非核心竞争力。

---

> 🎯 **核心要点**：AI 应用类平台选型三步 — ① **先定要不要 RAG**（要→Dify、不要→看对话需求）② **再看要不要私有化**（要→Dify/n8n、不要→Coze/Make）③ **最后看团队技术能力**（零代码→Make/Coze、会代码→n8n）。
