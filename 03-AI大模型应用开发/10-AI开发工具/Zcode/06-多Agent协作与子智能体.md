## 1. 多 Agent 协作模型

ZCode 的多 Agent 分为三个层次：

```
层次 1：多任务并行    多个独立 Agent 任务同时跑（分组管理）
层次 2：子智能体分工  主 Agent 内派生子代理，独立上下文
层次 3：多端协同      远程控制（手机扫码）+ Bot Channel（微信/飞书）
```

| 层次 | 机制 | 典型场景 |
|---|---|---|
| 多任务并行 | 每个任务独立 Agent 会话 | "修 Bug"与"写测试"并行 |
| 子智能体 | 主 Agent 自动派生子代理 | 大范围检索、独立小功能 |
| 多端协同 | 扫码/聊天工具接管对话 | 通勤路上发需求，到家验收 |

## 2. 分组任务并行管理

（详见 04 篇任务工作区三视图，此处聚焦并行策略）

并行建议：

- 任务按领域分组：前端 / 后端 / 测试，互不干扰
- 批量暂停/恢复：高峰期统一暂停省额度，非高峰统一恢复
- 拖拽管理：完成的任务拖到"已完成"分组，归档（3/7/14/30 天）
- 并行上限意识：并行任务数 × 上下文占用 = 总占用，同时跑太多会互相拖慢

> ⚠️ 并行任务共享一个工作区时，**避免两个任务同时改同一个文件**——Agent 之间没有文件锁，可能互相覆盖。按目录/模块划分任务边界。

## 3. 内置子智能体

v3.2.0 起 ZCode 内置两个子智能体（Sub-agents）：

| 子智能体 | 定位 | 权限 | 适用 |
|---|---|---|---|
| general-purpose | 通用型 | 完整工具权限 | 独立实现小功能、并行整理文件 |
| Explore | 只读调研专家 | 只读搜索 | 大范围检索、调用链梳理 |

特点：

- 每个子智能体可独立配置不同模型供应商（如把 Explore 的模型切到低价 DeepSeek 省额度）
- 主 Agent 判断任务需要独立上下文或并行调研时自动启动
- 子智能体完成后结果汇总回主对话

## 4. 自定义子智能体

"设置 → 子智能体"可创建自定义子智能体（Beta），配置项：

| 配置项 | 说明 |
|---|---|
| 名称 | 自定义标识 |
| 颜色 | 对话中视觉区分 |
| 模型 | 独立模型/供应商 |
| 工具 | 可用的工具集 |
| 系统提示词 | 角色与职责定义 |

示例：创建一个"测试专家"子智能体——系统提示词限定为"只负责分析代码并编写单元测试，遵循 AAA 结构，断言优先"，模型用低成本档。

## 5. 子智能体触发机制

| 触发场景 | 主 Agent 行为 |
|---|---|
| 需要独立上下文 | 派生子代理处理，避免污染主上下文 |
| 并行调研 | 同时派多个 Explore 分别检索不同模块 |
| 独立小功能 | 派 general-purpose 独立实现 |
| 完成 | 结果汇总回主对话，主 Agent 继续收尾 |

使用技巧：

- 主动要求："先派 Explore 调研一下支付模块的调用链"——比让主 Agent 慢慢翻文件快
- 分工降本：查资料/读代码类任务交给低配模型子代理，GLM-5.2 专注主任务（参考 03 篇成本优化）

## 6. 远程控制与 Bot Channel

### 远程控制（Remote Control）

- 入口：左下角手机图标生成二维码
- 能力：手机扫码查看任务进度、补充需求、追问、中止任务
- 限制：同一时间只支持一个手机页面连接

适用：长任务挂机时出门，手机上跟进进度、补充需求。

### Bot Channel

| 渠道 | 状态 |
|---|---|
| 微信 | 支持绑定 |
| 飞书 | 支持绑定 |
| 钉钉 | 后续支持 |
| Discord | 后续支持 |

能力：在聊天工具里直接查看进度、发指令，实现"通勤路上发需求，到家 AI 已写好"。

> 💡 多端协同的定位是"跟进与轻指令"：复杂代码修改还是桌面端舒服，手机上适合暂停/恢复、补充需求、验收结果。
