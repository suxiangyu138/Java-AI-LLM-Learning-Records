## 1. 上下文工程总览

Agent 每轮任务消耗的 token 主要来自上下文：项目约定 + 任务对话 + 工具结果。上下文工程就是让 Agent"看到该看的、按约定干活、不浪费额度"：

| 机制 | 解决的问题 | 本质 |
|---|---|---|
| AGENTS.md | Agent 不了解项目约定，乱写代码 | 持续指令 |
| Skill | 重复任务每次都重新解释 | 复用模板 |
| Command | 常用提示词反复输入 | 快捷指令 |
| 符号体系 | 自然语言描述文件/对话太长 | 精确定位 |
| /compact | 长会话上下文膨胀 | 压缩历史 |

## 2. AGENTS.md 项目指令文件

### 两级配置

| 位置 | 生效范围 | 内容示例 |
|---|---|---|
| `~/.zcode/AGENTS.md` | 全局所有项目 | 个人代码风格偏好 |
| `<workspace>/AGENTS.md` | 当前工作区项目 | 技术栈、目录结构、规范 |

### 推荐写入内容

| 类别 | 示例 |
|---|---|
| 技术栈 | 后端 Spring Boot 3.5 + MyBatis-Plus，前端 Vue3 + TS |
| 目录结构 | controller 只做参数校验，业务逻辑在 service 层 |
| 代码风格 | 4 空格缩进、方法不超 50 行、注释用中文 |
| 提交前验证 | 必须跑 `mvn test` 且全部通过 |
| 高风险文件 | `application-prod.yml` 不允许自动修改，需人工确认 |

### 注意事项

- **ZCode 不会把 CLAUDE.md 当持续指令读**：Claude Code 迁移用户注意，CLAUDE.md 只会在首次迁移（onboarding）时一次性转成 AGENTS.md
- 从 Claude Code / Codex 迁移：可导入已有配置
- AGENTS.md 写得越具体，Agent 出错率越低——实测用户反馈这是最有效的提效手段

> 🎯 核心要点：AGENTS.md 是"零成本提效"杠杆——花 10 分钟写技术栈与红线，省下后面无数次纠正 Agent 的对话轮次。

## 3. Skill 技能机制

Skill 是一套完整的工作说明（含触发场景、处理步骤、输出要求），用 `$skill-name` 调用。

### 目录结构与最小示例

```
~/.zcode/skills/<skill-name>/SKILL.md
```

最小 SKILL.md 包含：

```markdown
---
name: code-review
description: 审查代码改动，输出问题清单
---

# 审查步骤
1. 读取改动 diff
2. 检查：正确性 / 边界 / 安全隐患
3. 输出：问题清单 + 修改建议
```

| 字段 | 必填 | 说明 |
|---|---|---|
| name | 是 | 技能名（`$name` 调用） |
| description | 是 | 一句话描述触发场景 |
| 正文 | 是 | 处理步骤、输出要求 |

### 使用与管理

- 调用：对话中输入 `$skill-name`
- 刷新：设置 → 技能 → 刷新启用
- 导入：支持从 Claude Code、Codex CLI 等工具导入已有技能
- 通用技能支持自 v2.13.0 起

## 4. Command 快捷命令

Command 是存一段常用提示词，用 `/command-name` 调用。

| 对比项 | Command | Skill |
|---|---|---|
| 本质 | 一段提示词 | 一套工作说明 |
| 结构 | 单段文本 | name + description + 步骤 |
| 调用 | `/command-name` | `$skill-name` |
| 适用 | 固定话术 | 复杂流程化任务 |

内置命令示例：

| 命令 | 功能 |
|---|---|
| `/goal` | 管理目标模式（05 篇详述） |
| `/compact` | 压缩对话上下文 |

## 5. 符号体系与上下文降本

（04 篇已列全符号，此处聚焦"为什么省"）

| 符号 | 省什么 |
|---|---|
| `@文件` | 省去"帮我找到 XX 文件"的来回 |
| `#对话` | 省去粘贴历史结论 |
| `/命令` | 省去重复输入固定话术 |
| `$技能` | 省去重新解释处理流程 |
| `+附件` | 省去文字描述图片/文档内容 |

实测经验：熟练使用符号体系后，任务轮次可减少 20-30%，直接反映在 Token 额度消耗上。

## 6. 上下文压缩与长任务管理

### /compact 压缩

- 作用：压缩当前对话历史，保留关键结论
- 时机：状态看板出现上下文占用提醒时；长任务进行中
- 注意：压缩会丢失细节，复杂任务建议先让 Agent 输出"当前进展摘要"再压缩

### 长任务上下文管理清单

1. 目标先行：设 Goal 模式（05 篇），明确验收标准
2. 符号定位：全程用 `@` 引用，避免让 Agent 重新搜索
3. 分支任务：独立子任务派子智能体，别堆在主对话（06 篇）
4. 及时压缩：上下文占用提醒出现即 `/compact`
5. 收尾归档：任务完成拖入归档分组，别在旧任务里开新需求

### 与 Claude Code 的对照（迁移视角）

| Claude Code | ZCode |
|---|---|
| CLAUDE.md（全局 + 项目） | AGENTS.md（`~/.zcode/AGENTS.md` + 工作区） |
| ~/.claude/skills/ | ~/.zcode/skills/（SKILL.md 同构） |
| 斜杠命令 `/xxx` | Command `/xxx` + Skill `$xxx` 双轨 |
| /compact | /compact（同名） |
| MCP 配置 ~/.claude.json | ~/.zcode/cli/config.json（见 08 篇） |
