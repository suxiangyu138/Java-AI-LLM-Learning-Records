# 05 - 五大扩展点详解

## 1. 五大扩展点总览与选型

| 扩展点 | 触发方式 | 存放位置 | 典型用途 |
|--------|----------|----------|----------|
| **Commands** | 用户输入 `/name` | `.opencode/commands/*.md` | 提示词模板、快捷指令 |
| **Agents** | Tab 切换 / `@<name>` 提及 | `.opencode/agents/<name>.md` | 完整角色 + 权限 + 独立模型 |
| **Skills** | 模型按描述自动发现 | `.opencode/skills/<name>/SKILL.md` | 知识包、流程模板 |
| **Plugins** | 生命周期事件 | `.opencode/plugins/*.{js,ts}` | 代码级自动化（可执行任意代码） |
| **MCP** | 提示驱动的外部工具调用 | `opencode.json → mcp` | 连接外部系统/服务 |

**选型判断逻辑：**

```text
用户输入 /name 且只是提示词模板？→ Commands
需要完整角色 + 工具权限？→ Agents
需要模型自动按需发现？→ Skills
OpenCode 内部事件且是本地代码？→ Plugins
连接外部系统/服务？→ MCP

最成熟的工作流通常组合 2-3 种扩展点
```

## 2. 自定义命令 Commands

```markdown
# .opencode/commands/review.md
---
description: 对当前分支的代码进行审查
---

对当前分支相对于 main 的变更进行代码审查：
1. git diff main...HEAD 获取变更
2. 检查：逻辑错误、安全问题、性能问题、代码规范
3. 按严重程度输出 Review 报告
4. 输出格式：
   - 🔴 严重（必须修复）
   - 🟡 建议（应修复）
   - 🟢 可选（可优化）
```

```markdown
# .opencode/commands/commit.md
---
description: 生成规范的提交信息
---

分析当前 git diff，生成符合 Conventional Commits 规范的提交信息：
格式：<type>(<scope>): <subject>
类型：feat/fix/docs/style/refactor/test/chore
```

```bash
# 使用方式
/commit        # 触发自定义命令
/review        # 代码审查命令
```

## 3. 自定义 Agent

```markdown
# .opencode/agents/reviewer.md
---
name: reviewer
description: 资深代码审查专家，检查代码质量和潜在 bug
model: anthropic/claude-haiku-4-5     # 指定独立模型（省钱）
tools:
  - read
  - grep
  - bash
permissions:
  edit: deny                          # 审查者不修改代码
  bash: ask
---

你是资深代码审查专家，擅长发现潜在 bug 和安全问题。

审查流程：
1. 读取变更文件
2. 检查维度：
   - 逻辑错误（边界条件、空指针、并发问题）
   - 安全问题（注入、越权、敏感信息泄露）
   - 性能问题（N+1 查询、循环内 DB 调用）
   - 代码规范（命名、注释、异常处理）
3. 输出按严重程度排序的 Review 报告
4. 每个问题给出：位置 + 问题 + 修复建议
```

```markdown
# .opencode/agents/researcher.md
---
name: researcher
description: 技术调研专家，研究 API 文档和最佳实践
model: openai/gpt-5-turbo
tools:
  - webfetch
  - read
  - grep
permissions:
  edit: deny
---

你是技术调研专家。调研流程：
1. 明确调研目标
2. 通过 webfetch 查阅官方文档
3. 交叉验证多个来源
4. 输出：技术方案对比 + 推荐 + 示例代码
```

```bash
# 使用：Tab 切换 或 @提及
@reviewer "审查我最近的提交"
@researcher "调研 Spring AI 2.0 的 RAG 最佳实践"
```

## 4. Skills 技能系统

```text
Skills 定位：打包的"能力知识包"，模型按描述自动发现（渐进式披露，不占满上下文）

存放位置：
├── 全局：~/.config/opencode/skills/<name>/SKILL.md
├── 项目：.opencode/skills/<name>/SKILL.md
└── 兼容：~/.claude/skills/ 和 ~/.agents/skills/（自动读取）

与 MCP 的区别：
├── MCP：连接外部工具的"线协议"（程序化）
└── Skills：按需注入的"精选工作流与指令"（文档化）
```

```markdown
# .opencode/skills/deep-research/SKILL.md
---
name: deep-research
description: 深度研究技能，用于调查复杂主题并生成结构化报告
---

## 触发
用户要求"研究""调研""调查"某主题

## 工作流
1. 将主题拆解为 3-5 个子问题
2. 对每个子问题：
   - 使用 webfetch 搜索最新资料
   - 记录来源和关键信息
3. 汇总并交叉验证信息
4. 输出结构化报告：
   - 摘要（1 段）
   - 关键发现（表格）
   - 结论与建议
   - 参考资料列表
```

**第三方 Skills 包：** `@omagents/omagents` 捆绑 14 个 superpowers 技能 + deep-research/github-triage/refactor 等，首创"loop engineering"（持久化任务队列）。

## 5. Plugins 插件系统

```typescript
// .opencode/plugins/custom.ts — 生命周期钩子插件
import { OpenCode } from 'opencode';

export const plugin: OpenCode.Plugin = {
  name: 'custom-plugin',

  // 工具调用前钩子
  async onToolCall(params) {
    const { tool, input } = params;
    if (tool === 'bash' && input.includes('rm -rf')) {
      return { cancelled: true };       // 拦截危险命令
    }
  },

  // 文件编辑后钩子
  async onFileEdit(params) {
    const { file } = params;
    if (file.path.endsWith('.java')) {
      await checkJavaStyle(file);       // 自定义代码风格检查
    }
  },

  // 会话结束钩子
  async onSessionEnd(params) {
    await logUsage(params);              // 记录 Token 消耗
  }
};
```

```json
// opencode.json 注册插件
{
  "plugin": [
    "@omagents/omagents",            // npm 包插件
    "./plugins/custom.ts"           // 本地插件
  ]
}
```

> ⚠️ **插件可执行任意代码，具有完整用户权限 — 安装前必须审计。**

## 6. MCP 外部工具集成

```json
// opencode.json — MCP 配置
{
  "mcp": {
    // ① 本地 MCP（通过命令启动）
    "context7": {
      "type": "local",
      "command": ["npx", "mcp-query-docs"],  // 库文档查询
      "enabled": true
    },

    // ② 远程 MCP（HTTP/SSE）
    "target-system": {
      "type": "remote",
      "url": "http://localhost:8080/sse",
      "enabled": true
    },

    // ③ GitHub 集成
    "github": {
      "type": "local",
      "command": ["npx", "mcp-github"],
      "env": { "GITHUB_TOKEN": "${GITHUB_TOKEN}" },
      "enabled": true
    }
  }
}
```

**MCP 工作流：** 模型看到可用工具 → 决定调用 → 传参 → 读取结果 → 继续推理。MCP 是"会思考的 AI"与"能行动的 AI"之间的桥梁。

**常用 MCP：** context7（库文档）、websearch（网络搜索）、github（PR/Issue）、agentmemory（记忆）、codegraph（代码图谱）。

## 7. 组合实战：完整工作流

```text
场景：团队代码审查流程自动化

组合：Command（/review）+ Agent（reviewer）+ MCP（github）

① 开发者运行 /review
   → 触发自定义命令 → 读取 git diff

② 调用 @reviewer Agent
   → 独立模型（haiku 省钱）
   → 只读权限（edit: deny）

③ reviewer 通过 MCP 连接 GitHub
   → 获取 PR 上下文 → 对照变更 → 生成 Review

④ 输出报告 → 开发者确认 → 提交评论到 PR

收益：审查成本降低 80%（haiku vs sonnet）、标准化审查维度
```

> 🎯 **核心要点**：五大扩展点选型口诀 — **用户触发→Command、角色权限→Agent、自动发现→Skill、代码事件→Plugin、外部系统→MCP**。生产最常用的组合：`/review` 命令 + `reviewer` Agent（独立轻量模型）+ GitHub MCP = 自动化代码审查流水线。⚠️ 插件有完整用户权限，安装前必须审计。
