# 01 - OpenClaw 概述与核心定位

## 1. OpenClaw 是什么

| 维度 | 详情 |
|------|------|
| 全称 | OpenClaw（前身 ClawdBot → Moltbot，2026.01.30 定名） |
| 创建者 | Peter Steinberger（奥地利，2025.11） |
| 许可证 | **MIT 开源** |
| GitHub | **37 万+ Star**（2026.05） |
| 技术栈 | Node.js（Gateway）+ TypeScript |
| 定位 | **AI 执行引擎**，而非聊天机器人 |
| 比喻 | "云端大脑（LLM）+ 本地肢体（执行端）" |

```text
OpenClaw 不是：
  ❌ 一个大模型（它不训练模型）
  ❌ 一个聊天机器人（聊天只是入口之一）
  ❌ 一个 RAG 平台（RAG 是它的一项能力）

OpenClaw 是：
  ✅ 大模型聚合器（接 OpenAI/Claude/Gemini/DeepSeek/通义/Ollama...任意切换）
  ✅ AI 执行引擎（自然语言 → 文件操作/浏览器控制/代码执行/消息发送）
  ✅ 私有化部署的个人 AI 管家（本地运行，数据不出电脑）
```

## 2. 九大核心能力全景

| # | 能力 | 说明 | 示例 |
|---|------|------|------|
| 1 | **多模型聚合** | 接 20+ 模型，任意切换/自动降级 | GPT-5 ↔ Claude ↔ DeepSeek 一键切 |
| 2 | **文件与办公自动化** | 自然语言操作本地文件 | "把 Downloads 里所有 PDF 移到 Documents/Reports" |
| 3 | **浏览器自动化** | 自动打开网页/点击/填表/截图 | "打开京东，搜 iPhone 16，截图价格发我" |
| 4 | **代码生成与执行** | 生成脚本→运行→调试→提交 Git | "写一个监控 CPU 的脚本并部署为 Cron" |
| 5 | **多渠道接入** | 数十个通讯平台统一回复 | 手机 WhatsApp 发消息→电脑执行→结果回 WhatsApp |
| 6 | **定时与主动服务** | Cron 作业 + 心跳主动检查 | "每天早上 9 点推送今日待办" |
| 7 | **Skills 技能系统** | 4.4 万个可安装技能包 | `openclaw skills install pdf-toolkit` |
| 8 | **多 Agent 协作** | 主子 Agent 并行执行 | 一个搜资料、一个写报告、一个发邮件 |
| 9 | **记忆与偏好学习** | MEMORY.md 持久化，越用越懂你 | 记住你的代码风格/命名习惯/常用工具 |

## 3. 与 Coze/Dify/n8n 的定位差异

| 对比 | OpenClaw | Coze | Dify | n8n |
|------|----------|------|------|-----|
| 核心定位 | **AI 执行引擎**（操控电脑） | 对话 Agent 搭建 | 知识库 RAG 平台 | 工作流自动化 |
| 运行位置 | **本地电脑**（127.0.0.1） | 云端 | 云端/自托管 | 云端/自托管 |
| 操控能力 | ✅ 文件/浏览器/Shell/Cron | ❌ | ❌ | ❌（API 调用） |
| 模型聚合 | ✅ 20+ 模型自由切换 | 豆包为主 | ✅ 多模型 | 需手动配置 |
| 渠道接入 | ✅ WhatsApp/Telegram/飞书/微信等 | ✅ 豆包/飞书/微信 | API | Webhook |
| 开源 | ✅ MIT | ❌ | ✅ | ✅ |
| 适合场景 | 个人 AI 管家、本地自动化 | 快速搭聊天机器人 | 企业知识库问答 | 业务流程自动化 |

## 4. 核心工作流程

```text
用户发消息（WhatsApp/Telegram/Web UI/CLI）
        ↓
  Channel Plugin 接收
        ↓
  Gateway（127.0.0.1:18789）接收消息
   ├── 身份验证（Token + Device Identity）
   ├── Session 查找/创建（按渠道+用户隔离）
   └── 路由到对应 Agent
        ↓
  Agent Loop（ReAct 循环）
   ├── ① 加载 Skills（扫描可用 SKILL.md）
   ├── ② 构建 System Prompt（注入 Skills/Memory/工具列表）
   ├── ③ 调用 LLM（通过配置的模型）
   ├── ④ LLM 返回 → 需要执行工具？
   │   ├── 是 → Pi-embedded 执行（Shell/浏览器/文件操作）
   │   │        → 结果返回 LLM → goto ③
   │   └── 否 → 生成最终回复
   └── ⑤ 更新 Memory（记录到 MEMORY.md 或日记忆）
        ↓
  Gateway 将回复通过原渠道发回
```

---

> 🎯 **核心要点**：OpenClaw 的三个"不"与三个"是" — **不是大模型、不是聊天机器人、不是 RAG 平台**；**是大模型聚合器、是 AI 执行引擎、是本地 AI 管家**。与 Coze/Dify/n8n 的最大区别：它能真正操控你的电脑（文件/浏览器/Shell/Cron），其他平台只能通过 API 调用外部服务。
