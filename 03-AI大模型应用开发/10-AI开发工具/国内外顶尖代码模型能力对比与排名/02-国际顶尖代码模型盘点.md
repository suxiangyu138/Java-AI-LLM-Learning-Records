## 1. Claude Opus 5 — Anthropic 的"平民战神"

### 1.1 发布时间与定位

2026 年 7 月 24 日发布，定位"让每个人都用得起的旗舰模型"。价格仅为 Fable 5 的一半，但在多个基准上持平甚至超越。

| 维度 | Opus 5 | 上一代 Opus 4.8 | Fable 5 |
|------|:---:|:---:|:---:|
| 发布时间 | 2026.07.24 | 2026.03 | 2025.11 |
| API 输入价格 | $15/M tokens | $15/M | $30/M |
| API 输出价格 | $75/M tokens | $75/M | $150/M |
| SWE-bench Pro | **79.2%** | 69.2% | 80.0% |
| Frontier-Bench | **43.3%** 🥇 | 21.1% | 33.7% |
| DeepSWE pass@1 | ~65% | 未测试 | 69.9% |
| 上下文 | 200K | 200K | 200K |

### 1.2 代码能力深度分析

```text
Opus 5 的三重革命：

1. Agent 编程能力翻倍
   Frontier-Bench：21.1% → 43.3%（翻倍！）
   超越 GPT-5.6 Sol (34.4%) 和 Fable 5 (33.7%)
   → 规划→执行→验证的 Agent 闭环能力质变

2. 代码可维护性领先
   SlopCodeBench：24%（Opus 4.8 仅 6%）
   虽然也不及格，但已是所有模型中的最高分
   → 写的代码"更干净"（虽然还有巨大进步空间）

3. Java/Spring 生态理解
   作为 Claude 家族成员，继承了 Claude 对 Java 生态的深度理解
   在 SWE-bench Pro Java 变体上表现接近 Fable 5
```

### 1.3 适用场景与定价策略

```text
✅ 最佳场景：
  • Java 企业级开发（代码质量 + 架构理解）
  • Agent 自动化编程（Frontier-Bench 第一）
  • 复杂 Bug 修复（SWE-bench Pro 79.2%）
  • 代码审查（发现隐蔽问题能力强）

⚠️ 不是最佳：
  • 追求极致性价比 → Kimi K3 / DeepSeek V4 Pro 更便宜
  • 超大上下文需求 → Gemini 3 Pro (1M vs 200K)
  • 中文代码场景 → Qwen3.7-Max 更懂中文

💰 一句话：$15/$75 的价格，Fable 5 级别的性能，性价比远超同门旗舰
```

## 2. Claude Fable 5 — 代码理解的天花板

### 2.1 定位

Anthropic 的超旗舰，追求极致能力而非性价比。DeepSWE pass@1 69.9% 说明其"一次性就能正确理解复杂工程问题"的能力无人能及。

| 关键指标 | 分数 | 排名 |
|------|:---:|:---:|
| SWE-bench Pro | 80.0% | 🥈 |
| DeepSWE pass@1 | 69.9% | 🥇 |
| Code Arena | 1631 | 🥈（被 Kimi K3 超越） |

### 2.2 为什么 Fable 5 在 DeepSWE 上最强？

```text
DeepSWE 的与众不同：
— 不是"改一行代码"（SWE-bench 很多任务是）
— 而是"理解这个项目的设计意图，然后做符合意图的修改"

Fable 5 的优势：
— 深层推理能力（理解"为什么代码这样写"）
— 一次性正确率最高（pass@1 = 69.9%，比 Kimi K3 pass@1 68.5% 略高）

局限：
— pass@4 被 Kimi K3 反超（89.4% vs ~85%）
— 意味着"多次重试"策略下，Kimi K3 更划算
— 价格是 Kimi K3 的 ~6 倍
```

## 3. Claude Sonnet 5 — 性价比版 Opus

### 3.1 定位

2026 年 7 月 1 日发布，定位"最能干活的 Sonnet"。价格只需 Opus 5 的 ~60%，但代码能力大幅接近。

| 维度 | Sonnet 5 | Sonnet 4.6 | Opus 5 |
|------|:---:|:---:|:---:|
| SWE-bench Pro | 63.2% | 58.1% | 79.2% |
| Terminal-Bench 2.1 | **80.4%** | 67.0% | ~75% |
| A-CODE-LLM | **0.707** | — | 0.691 (4.8) |

> ⚠️ **Tokenizer 变化**：Sonnet 5 更换了 Tokenizer，实际 Token 消耗增加 27-42%，虽然单价不变但总成本上升。

### 3.2 Sonnet 5 的独特优势

```text
Terminal-Bench 80.4% — 终端 Agent 编程能力突出
→ 在 Claude Code 中作为"打工人 Agent"非常合适
→ 批量任务/自动化脚本场景的首选

A-CODE-LLM 0.707 — Agent 编程评分超过 Opus 4.8
→ 说明在"性价比 Agent"这个维度上，Sonnet 5 已经超越了上一代旗舰
```

## 4. GPT-5.6 Sol — OpenAI 的 Agent 旗舰

### 4.1 定位

OpenAI 的最新一代旗舰模型，在综合编程能力上依然是顶级水平。

| 关键指标 | 分数 | 说明 |
|------|:---:|------|
| 综合编程指数 | 78.3 | 全榜第二 |
| Code Arena | 1618 | 第三（被 Kimi K3 超越） |
| SWE-bench Pro | ~65%（推测） | 弱于 Claude 家族 |
| Frontier-Bench | 34.4% | 弱于 Opus 5 |
| A-CODE-LLM | ~0.70 | 中上水平 |

### 4.2 优势与短板

```text
✅ 优势：
  • 生态最完整 — ChatGPT/API/Copilot/GitHub 深度集成
  • 多模态辅助 — 截图→代码，UI→前端代码
  • 中文能力 — 仅次于国产模型
  • 速度 — 响应速度优秀

⚠️ 短板：
  • SWE-bench Pro 落后 Claude 家族
  • Frontier-Bench 被 Opus 5 大幅超越（34.4% vs 43.3%）
  • Code Arena 盲测首次被开源模型（Kimi K3）超越
  • 价格较高，性价比不如 DeepSeek/Kimi
```

## 5. Gemini 3 Pro/Flash — Google 的 1M 上下文利器

### 5.1 双模型定位

| 维度 | Gemini 3 Pro | Gemini 3 Flash |
|------|:---:|:---:|
| 上下文 | 1M | 1M |
| LiveCodeBench (高推理) | **92%** | — |
| SWE-bench Verified (高推理) | — | **75.8%** |
| 成本/任务 | $0.50+ | **$0.36** |

### 5.2 独特优势

```text
1M 上下文的杀手级应用：
  • 一次性阅读整个 Spring Boot 项目的所有源码
  • 跨 50+ 文件的架构分析
  • 全量代码审查（不用切块）
  • 大型配置文件的理解和修改

局限：
  • Java 代码质量不及 Claude 家族
  • Agent 编程能力弱于 Opus 5/Grok 4.5
  • 长上下文中细节把握不如短文本
```

## 6. Grok 4.5 — xAI 的 Agent 性能暗马

### 6.1 定位

2026 年 xAI 最新代码模型，在 A-CODE-LLM 基准上以 0.732 登顶——"用最少的成本完成最多的编程任务"。

| 关键指标 | 分数 | 说明 |
|------|:---:|------|
| A-CODE-LLM | **0.732** 🥇 | 全榜第一 |
| 平均成本/任务 | **$0.46** | 极低 |
| LiveCodeBench | ~88% | 仅次于 DeepSeek |
| SWE-bench Pro | ~55%（推测） | 弱于 Claude 家族 |

### 6.2 Grok 4.5 的"性价比 Agent"优势

```text
A-CODE-LLM 的评测逻辑：
  得分 = 任务完成度 × 成本效率

Grok 4.5 = 0.732
  成本 $0.46/任务 + 中上等完成质量 = 综合性价比第一

对比：
  Claude Sonnet 5 = 0.707 ($2.23/任务 — 贵 5×)
  Claude Opus 4.8 = 0.702 ($1.67/任务)
  Grok 4.3 = 0.702 ($0.51/任务)

结论：如果你需要大量 Agent 编程任务，Grok 4.5 是 2026 年最佳性价比选择
```
