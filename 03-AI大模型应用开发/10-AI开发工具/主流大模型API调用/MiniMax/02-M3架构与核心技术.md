## 2. MSA 稀疏注意力

**MSA（MiniMax Sparse Attention）— 自研两阶段稀疏注意力架构：**

```text
第一阶段：轻量索引（Block Max Pooling）
  → 用轻量索引 query 对 KV 缓存做 Block Max Pooling
  → 选出 Top-k 个关键块

第二阶段：稀疏注意力
  → 只对选中的 Top-k 块执行稀疏注意力
  → 其余块跳过（省计算）

vs 其他稀疏方案：
├── vs DSA/MoBA：KV 分块更精细，有效上下文覆盖更高
├── vs Flash-Sparse-Attention：算子层 KV outer gather 快 4 倍+
└── vs Flash-MoBA：同上

效果：
├── 1M 上下文每 token 计算量 = 上代 1/20
├── Prefilling 加速 9 倍+
├── Decoding 加速 15 倍+
└── 能力与全注意力基本持平
```

> ⚠️ 注意：并非所有推理引擎都支持 MSA — 不支持的会回退到密集注意力而丧失速度优势。

## 3. 原生多模态训练

```text
传统多模态（后期拼接）：
  先训练文本模型 → 再接入视觉编码器 → 微调
  问题：模态理解割裂、上下文窗口分开

M3 原生多模态（Day 1 交错训练）：
  从预训练 Step 0 开始进行文本+图像+视频交错训练
  ├── 图像和视频 token 与文本共享同一 token 池
  ├── 共享同一上下文窗口
  ├── 预训练数据重构（100 万亿量级）
  └── 大量使用 Interleaved Data（交错数据）

能力：
├── 图片输入（理解/分析/提取）
├── 视频输入（理解/总结）
├── 输出为文本
└── 电脑桌面操作（Computer Use）
```

## 4. Agentic 训练方法

```text

交互式用户模拟器框架：
├── 模拟真实开发者的行为

├── SWE-Bench Pro 59.0%
├── Terminal Bench 2.1：66.0%
├── BrowseComp：83.5（超 Opus 4.7 的 79.3）
└── MCP Atlas：74.2%
```
