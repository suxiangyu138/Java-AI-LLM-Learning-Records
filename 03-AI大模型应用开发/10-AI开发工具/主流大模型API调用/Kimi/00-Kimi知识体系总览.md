## 4. 与 DeepSeek 的生态定位对比

| 对比 | Kimi | DeepSeek |
|------|------|----------|
| 出品 | 月之暗面（Moonshot AI） | 深度求索（DeepSeek） |

| 最佳场景 | 长链路 Agent、深度调研、代码 | 高并发低成本 API |

## 6. 核心概念速查

| 概念 | 一句话 |
|------|--------|
| MoE | 混合专家架构：总参数 1T、激活 32B、256 专家、Top-K=8 |
| 长程编码 | 连续编码 13 小时、4000+ 行代码、吞吐提升 12.9 倍 |
| Agent Swarm | 300 个子 Agent 协作、4000 步协作，端到端交付文档/PPT |
| 深度思考 | `reasoning_content` 字段返回思考内容（与 content 分离） |
| Context Caching | 自动开启的上下文缓存，重复前缀成本降 75%+ |
| Claw Groups | 异构 Agent 协作生态（K2.6 当协调者） |
| 256K 上下文 | K2.6 的上下文窗口（输入=输出=262,144 tokens） |
| K3 | 旗舰：2.8T 参数、1M 上下文、视觉、思考默认开启 |

---

> 🎯 **核心要点**：Kimi 的 2026 年定位 = **开源编程旗舰（K2.6 对标 GPT-5.4）+ 长链路 Agent 王者（300 子 Agent/5 天自主运行）**。开发者最关心的三件事：OpenAI 兼容 API（改 base_url 即用）、深度思考字段（reasoning_content）、上下文缓存（省 75% 成本）。选型速记：长链路 Agent 任务→K2.6、纯编码→K2.7 Code、全能旗舰→K3。
