## 1. 实战项目：流式客服 Agent（Java 端到端）

**目标**：基于豆包 Seed 2.1 Pro + 官方 SDK 构建客服 Agent，支持工具调用（查订单/退换货政策）与 SSE 流式输出，成本受控。

```java
// ① 配置：ArkService 单例 Bean
@Configuration
public class ArkConfig {
    @Bean
    public ArkService arkService() {
        return ArkService.builder()
                .apiKey(System.getenv("ARK_API_KEY"))
                .region("cn-beijing")
                .readTimeout(90, TimeUnit.SECONDS)
                .build();
    }
}
```

```java
// ② 工具注册：订单查询（模型不执行工具，服务端执行）
@Component
public class OrderTool {
    public String queryOrder(String orderId) {
        // 查 DB/外部系统，返回订单状态 JSON
        return "{'orderId': '" + orderId + "', 'status': '已发货'}";
    }
}
```

```java
// ③ Agent 循环：工具调用 + 思考 + 流式（核心骨架）
@Service
public class AgentService {
    @Autowired private ArkService ark;
    @Autowired private OrderTool orderTool;

    public void chat(String question, SseEmitter emitter) {
        List<ChatMessage> messages = new ArrayList<>();
        messages.add(ChatMessage.system("你是客服助手，可用工具查订单。回复简洁。"));
        messages.add(ChatMessage.user(question));

        for (int turn = 0; turn < 8; turn++) {          // 轮次上限
            ChatCompletionRequest req = ChatCompletionRequest.builder()
                    .model("doubao-seed-2-1-pro-260623")
                    .messages(messages)
                    .tools(List.of(orderToolDef()))      // 工具定义
                    .build();

            ChatCompletionResult resp = ark.chatCompletion(req);   // 非流式取完整响应
            AssistantMessage msg = resp.getChoices().get(0).getMessage();

            if (msg.getToolCalls() != null && !msg.getToolCalls().isEmpty()) {
                messages.add(msg);                       // 完整回传 assistant（含 tool_calls）
                for (ToolCall tc : msg.getToolCalls()) {
                    String result = "query_order".equals(tc.getFunction().getName())
                            ? orderTool.queryOrder(parseOrderId(tc.getFunction().getArguments()))
                            : "{}";
                    messages.add(ChatMessage.tool(tc.getId(), result));   // tool_call_id 匹配
                }
            } else {
                emitter.send(SseEmitter.event().data(msg.getContent()));  // 最终回答
                emitter.complete();
                return;
            }
        }
        emitter.completeWithError(new RuntimeException("超过轮次上限"));
    }
}
```

```java
// ④ 流式出口：控制器返回 SSE（生产改用 streamChatCompletion 逐 token 推送）
@PostMapping("/agent/chat", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public SseEmitter agentChat(@RequestBody String question) {
    SseEmitter emitter = new SseEmitter(120_000L);
    agentService.chat(question, emitter);
    return emitter;
}
```

**成本控制三处落地**：轮次上限 8（防死循环烧钱）、简单问题在提示词中引导直接回答（减少思考/工具轮次）、usage 打点记录每次调用的 token 消耗。

**扩展任务（选做，练透整体系，完成后即达生产级）**：① 把最终回答改为 `streamChatCompletion` 逐 token 推送，对比首 token 延迟；② 加 thinking enabled 并在前端分"思考/回答"两区渲染；③ 接入 JSON Schema 让工具参数经 Pydantic/Jackson 强类型校验；④ 模拟 429 验证降级链切换；⑤ 用 Seed 1.6 Vision 给客服加"截图提问"入口；⑥ 接入扣子 Bot 对比编排成本。做完全部扩展即达到生产级豆包开发水平。

## 3. 报错速查十条

| # | 错误 | 根因 | 解法 |
|---|------|------|------|
| 1 | 401 | Key 错误/缺签名 | 核对完整密钥；Java 用官方 SDK |
| 2 | 404 | 未填 model / base_url 拼错 | 显式 model；标准 API 用 /api/v3 |
| 3 | 403 | region 错/子账号未授权 | region 与开通地域一致；补 UID 头 + IAM |
| 4 | 429 | TPM/RPM 超限 | 退避重试 + 降级链 + TPM 保障包 |
| 5 | 400 thinking 顶层 | 非标准参数位置错 | 放 extra_body |
| 6 | 400 只传 system | messages 缺 user | 至少一条 user 消息 |
| 7 | Spring 卡住无响应 | SDK 默认流式 | 显式 .stream(false) |
| 8 | finish_reason=length | max_completion_tokens 被思考占满 | 调大上限或关思考 |
| 9 | 工具 JSON 解析失败 | 流式分片未累积完整 | 等流结束再解析 |
| 10 | Coding Plan 按量计费 | 误用 /api/v3 端点 | 换 /api/coding/v3 |

## 4. 面试三范式

**价值式**：豆包解决什么问题？——国内开发者需要"对标 GPT-5.5 级能力 + 可承受价格 + 国内合规 + 全模态"的模型服务，豆包用 MoE 架构效率 + 平台规模把价格打到国际旗舰的 1/5，且火山方舟托管全国产模型，一套 API 完成多模型降级。

**技术式**：核心机制？——MoE 稀疏激活（效率 7 倍）+ UltraMem 访存优化（降 83%）支撑低价；thinking 三模式控制推理（reasoning_content 分离返回、多轮回传纪律）；Deep Think 用搜索/沙盒做验证循环；缓存命中 1.2 元是长上下文降本核心。

**生产式**：你踩过什么坑？——Java 必须官方 SDK（签名头）；SDK 默认流式导致 Spring 卡住；region 必填；思考 token 按输出计费要 disabled；429 需降级链（切 Turbo/Mini/第三方）。

**追问四连**：thinking 与 Deep Think 区别？缓存命中条件？并行工具前提？MaaS 平台与单模型厂商的运维差异？
