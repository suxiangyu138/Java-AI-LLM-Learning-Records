## 1. 应用类型与创建流程

### 1.1 四种应用类型

```text
Dify 首页 → 创建应用 → 选择类型

┌──────────────────────────────────────────────────────┐
│ 类型          │ 交互模式      │ 典型场景             │
├──────────────────────────────────────────────────────┤
│ 聊天助手      │ 多轮对话      │ 客服、知识问答       │
│ Agent         │ 多轮对话+工具 │ 数据分析、自动化     │
│ 文本生成      │ 单次输入输出  │ 翻译、摘要、文案     │
│ 工作流        │ 可视化编排    │ 复杂多步骤流程       │
└──────────────────────────────────────────────────────┘
```

### 1.2 创建聊天助手（最常用）

```text
步骤：

1. 首页 → 创建应用 → 聊天助手 → 命名

2. 右侧模型选择：
   ├── 推理模型：GPT-4o / DeepSeek-V4-Pro
   └── 温度：0.7 (创意) ~ 0.1 (精确)

3. 提示词编排区（核心！）
   ├── 系统提示词：定义 AI 角色、行为规则
   ├── 上下文：关联知识库（RAG）
   ├── 变量：用户输入、对话历史、自定义变量
   └── 文件上传：支持图片、文档作为输入

4. 调试与预览（右侧）
   ├── 输入测试问题
   ├── 查看响应、Token 消耗、延迟
   └── 检查知识库引用来源

5. 发布
   ├── 运行 (Run) → 生成 API 地址
   └── 嵌入 → iframe 代码片段
```

## 2. 提示词编排核心

### 2.1 系统提示词（System Prompt）

系统提示词定义 AI 的角色边界和行为规则，是决定 AI 表现质量的最关键因素。

```jinja2
# 角色
你叫"小D"，是{{company_name}}公司的智能客服助手。

# 专业领域
你精通以下领域：
1. 产品功能与使用指南
2. 账户与订单问题
3. 退款与售后政策

# 行为规则
- 始终使用友好、专业的语气
- 如果问题超出你的知识范围，诚实告知并建议联系人工客服
- 不要编造产品功能或价格信息
- 回答时优先引用知识库中的信息
- 如果用户询问价格，务必确认是最新价格
- 回答尽量简洁，控制在 200 字以内

# 当前上下文
今天是{{current_date}}
用户是{{user_level}}会员
```

### 2.2 提示词技巧

| 技巧 | 说明 | 示例 |
|------|------|------|
| **角色定义** | 明确"你是谁"和"你不是谁" | "你是技术专家，不是销售" |
| **输出格式** | 指定 JSON/Markdown/表格 | "请以 JSON 格式返回" |
| **Few-Shot** | 给出 2-3 个示例 | 示例1... | 示例2... |
| **思维链** | 要求逐步推理 | "请一步步思考，最后给出答案" |
| **约束条件** | 明确不能做的事 | "不要编造你不知道的信息" |
| **知识引用** | 引用知识库 | "如果知识库中有相关信息，请引用" |
| **语气控制** | 设置回答风格 | "用小学生能懂的语言解释" |
| **语言控制** | 强制语言输出 | "始终用中文回答" |

### 2.3 用户提示词模板（User Prompt Template）

```jinja2
{# 用户提示词模板 —— 控制发给 LLM 的最终消息格式 #}

{# 1. 上下文引用 #}
参考以下信息回答用户问题：

{% if context %}
{{context}}
{% endif %}

{# 2. 对话历史 #}
对话历史：
{% for message in conversation_history %}
- {{message.role}}: {{message.content}}
{% endfor %}

{# 3. 当前问题 #}
用户问题：{{query}}

{# 4. 文件内容 #}
{% if files %}
用户上传了以下文件：
{% for file in files %}
文件名: {{file.name}}
类型: {{file.type}}
内容: {{file.content}}
{% endfor %}
{% endif %}

{# 5. 答案要求 #}
请基于以上信息，用简洁清晰的中文回答。如果信息不足，请说明。
```

## 3. 上下文与变量系统

### 3.1 上下文类型

```text
Dify 中的上下文来源：

├── 知识库 (Knowledge Base)
│   └── 关联一个或多个 Dataset，自动检索相关片段
│
├── 变量 (Variables)
│   ├── 系统变量：
│   │   ├── {{#query#}}         → 用户当前输入
│   │   ├── {{#conversation_id#}} → 对话 ID
│   │   ├── {{#user_id#}}       → 用户标识
│   │   ├── {{#app_id#}}        → 应用 ID
│   │   ├── {{#context#}}       → 知识库检索结果
│   │   └── {{#files#}}         → 用户上传的文件
│   │
│   └── 自定义变量：
│       ├── 文本变量  {{variable_name}}
│       ├── 段落变量  {{paragraph_var}}
│       ├── 下拉选项  预定义选项值
│       └── 数字变量  {{number_var}}
│
└── API 参数
    └── 调用 API 时通过 inputs 字段传入
```

### 3.2 变量在提示词中的使用

```jinja2
{# === 系统提示词中使用变量 === #}
你是{{company_name}}的专业客服。
今天的日期是{{current_date}}。
用户级别：{{user_level}}
用户偏好语言：{{language}}

{# === 知识库上下文 === #}
{% if context %}
以下是知识库中的相关信息：
---
{{context}}
---
{% endif %}

{# === 条件判断 === #}
{% if user_level == "vip" %}
请优先处理此 VIP 用户的问题，语气要特别热情。
{% elif user_level == "new" %}
请多给新用户一些引导和耐心。
{% endif %}

{# === 注释（不会发给 LLM）=== #}
{# 这些是内部注释，用户看不到 #}
```

### 3.3 API 调用时传递变量

```json
// POST /v1/chat-messages
{
  "inputs": {
    "company_name": "ABC科技有限公司",
    "user_level": "vip",
    "language": "zh-CN",
    "current_date": "2026-07-30"
  },
  "query": "我的订单什么时候发货？",
  "response_mode": "streaming",
  "user": "user-12345"
}
```

## 4. 对话记忆管理

### 4.1 记忆策略配置

```text
应用设置 → 对话设置 → 记忆

记忆策略选项：

1. 短期记忆 (Short-term Memory) ← 默认
   ├── 窗口大小：最近 N 轮对话
   └── 例如：保留最近 10 轮 → 窗口满后丢弃最旧的

2. 长期记忆 (Long-term Memory) ← Dify 1.0+
   ├── 自动总结关键信息
   ├── 跨会话持久化
   └── 类似个性化"用户画像"

3. 对话变量 (Conversation Variables)
   ├── 在对话中动态修改变量值
   └── 用于记录用户偏好、进度等
```

### 4.2 记忆窗口配置

```text
推理模型设置：

窗口大小 = 决定携带多少历史消息给 LLM

影响因素：
├── 窗口越大 → 上下文越全 → 回答更连贯
├── 窗口越大 → Token 消耗越多 → 成本越高
├── 窗口越大 → 可能超出模型上下文限制
└── 窗口越小 → 可能忘记前面说过的话

推荐设置：
├── DeepSeek-V4 (1M context)：窗口 = 50-100 轮
├── GPT-4o (128K)：窗口 = 20-40 轮
├── GPT-4o-mini (128K)：窗口 = 20-40 轮
└── 本地 Ollama (4K-32K)：窗口 = 5-10 轮
```

### 4.3 对话变量（高级用法）

```text
场景：多步骤信息收集（如预约表单）

对话变量：
├── step: "collect_name" | "collect_phone" | "confirm" | "done"
├── customer_name: ""
├── customer_phone: ""
└── appointment_time: ""

工作流程：
1. step = "collect_name" → 收集姓名 → 更新 customer_name
2. step = "collect_phone" → 收集电话 → 更新 customer_phone
3. step = "confirm" → 确认信息 → 用户确认
4. step = "done" → 完成预约 → 调用 API 保存
```

## 5. 日志、标注与迭代改进

### 5.1 日志查看

```text
Dify 内置日志系统：

应用 → 日志与标注

每条记录包含：
├── 用户输入（query）
├── AI 输出（answer）
├── Token 消耗（prompt_tokens + completion_tokens）
├── 延迟（latency）
├── 知识库引用（如果有）
├── 用户反馈（👍/👎）
└── 标注状态

筛选：
├── 按时间范围
├── 按用户反馈
├── 按关键词搜索
└── 按标注状态
```

### 5.2 标注改进流程

```text
标注 = 标记好的对话，用于改进提示词或微调模型

操作流程：
1. 查看用户对话记录
2. 找到不理想的回复 → 点击"标注"
3. 修改为期望的正确回复
4. 保存标注

改进策略：
├── 分析被 👎 最多的对话 → 优化提示词
├── 查看用户真实提问方式 → 补充知识库文档
├── 批量标注 → 用于未来模型微调
└── 定期审查标注质量
```

### 5.3 成本分析

```text
日志 → 成本分析视图

追踪维度：
├── 总 Token 消耗（按天/周/月）
├── 单次对话平均成本
├── 模型成本分布（GPT-4o vs GPT-4o-mini）
├── Embedding Token 消耗
└── 预估月费用

优化建议：
├── GPT-4o-mini 代替 GPT-4o 处理简单问题 → 省 90%
├── 减少知识库上下文片段数 → 每轮少几百 Token
├── 减少记忆窗口大小 → 每轮少几千 Token
└── 缓存常用知识 → 减少重复 Embedding
```
