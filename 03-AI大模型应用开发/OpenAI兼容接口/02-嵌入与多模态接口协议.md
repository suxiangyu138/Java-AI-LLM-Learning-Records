## 1. OpenAI API 端点全景图

```text
https://api.openai.com/v1/

├── /chat/completions      ← 对话补全（核心）         ✅ 几乎所有兼容实现
├── /embeddings            ← 文本向量化                ✅ 主流都支持
├── /models                ← 列出可用模型              ✅ 主流都支持
├── /images/generations    ← 图片生成（DALL·E）       ⚠️ 少数实现
├── /images/edits          ← 图片编辑                  ❌ 极少兼容
├── /audio/transcriptions  ← 语音转文字（Whisper）     ⚠️ 少数实现
├── /audio/speech          ← 文字转语音（TTS）         ❌ 极少兼容
├── /moderations           ← 内容审核                  ❌ 基本无兼容
├── /files                 ← 文件管理（微调）          ⚠️ 少数实现
└── /fine_tuning/jobs      ← 微调任务                  ⚠️ 少数实现
```

> 🎯 实战中 90% 的调用集中在 `/chat/completions` 和 `/embeddings` 两个端点。

## 2. Embeddings API

### 2.1 端点与请求

```text
POST https://api.openai.com/v1/embeddings
```

```json
{
  "model": "text-embedding-3-small",
  "input": "Java is a statically-typed programming language",
  "encoding_format": "float",
  "dimensions": 512
}
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|:---:|------|
| `model` | string | ✅ | 嵌入模型 ID |
| `input` | string/array | ✅ | 单条文本或文本数组（最多 2048 条） |
| `encoding_format` | string | ❌ | `float`（默认）或 `base64` |
| `dimensions` | int | ❌ | 输出维度（仅 `text-embedding-3` 系列支持） |
| `user` | string | ❌ | 终端用户标识 |

### 2.2 响应格式

```json
{
  "object": "list",
  "data": [
    {
      "object": "embedding",
      "index": 0,
      "embedding": [
        0.0023, -0.0091, 0.0152, ...  // 512 或 1536 维
      ]
    }
  ],
  "model": "text-embedding-3-small",
  "usage": {
    "prompt_tokens": 8,
    "total_tokens": 8
  }
}
```

### 2.3 OpenAI 嵌入模型对比

| 模型 | 维度 | 每美元 Token | 特点 |
|------|:---:|:---:|------|
| `text-embedding-3-small` | 512/1536 | ~62,500 | 性价比最高 |
| `text-embedding-3-large` | 256/1024/3072 | ~9,615 | 精度最高 |
| `text-embedding-ada-002` | 1536 | ~3,000 | 旧版（已不推荐） |

### 2.4 兼容实现的 Embeddings 模型

```
vLLM    → 需要加载 embedding 专用模型（如 bge-large-zh）
Ollama  → nomic-embed-text, bge-m3, mxbai-embed-large
LocalAI → 支持 OpenAI 兼容的 /v1/embeddings
智谱    → embedding-2
DeepSeek → ❌ 不提供公有 Embedding API
```

### 2.5 Java 调用示例

```java
// 使用 Spring AI 的 EmbeddingClient
@Autowired
private EmbeddingModel embeddingModel;

public float[] embed(String text) {
    return embeddingModel.embed(text);  // 自动使用配置的模型
}

// 直接 HTTP 调用
public List<Float> embedWithOkHttp(String text, String baseUrl) {
    String body = String.format(
        "{\"model\":\"text-embedding-3-small\",\"input\":\"%s\"}", text);
    Request request = new Request.Builder()
        .url(baseUrl + "/v1/embeddings")
        .post(RequestBody.create(body, MediaType.parse("application/json")))
        .header("Authorization", "Bearer " + apiKey)
        .build();
    // ... 解析响应
}
```

## 3. Images API

### 3.1 图片生成

```text
POST https://api.openai.com/v1/images/generations
```

```json
{
  "model": "dall-e-3",
  "prompt": "A serene Japanese garden with a koi pond, cherry blossoms falling",
  "n": 1,
  "size": "1024x1024",
  "quality": "standard",
  "style": "vivid",
  "response_format": "url"
}
```

| 参数 | 说明 |
|------|------|
| `model` | `dall-e-2` / `dall-e-3` |
| `size` | dall-e-2: 256/512/1024; dall-e-3: 1024x1024, 1792x1024, 1024x1792 |
| `quality` | `standard` / `hd`（仅 dall-e-3） |
| `style` | `vivid`（超现实）/ `natural`（写实）（仅 dall-e-3） |
| `response_format` | `url`（默认，1小时有效）/ `b64_json` |

### 3.2 兼容实现

```text
✅ 支持图片生成的兼容接口：
  - Stable Diffusion WebUI (AGPL) → 可通过扩展提供 OpenAI 兼容端点
  - LocalAI → 内置 Stable Diffusion 后端
  - 智谱 CogView → 有独立 API（非 OpenAI 格式）

❌ 不提供图片生成的：
  - vLLM, Ollama, llama.cpp → 专注文本 LLM
  - DeepSeek → 无图片生成模型
```

> 💡 图片生成的 OpenAI 兼容做得很有限。生产环境建议直接用 Stable Diffusion API 或 Midjourney API，不做兼容层。

## 4. Audio API（TTS + STT）

### 4.1 语音合成（TTS）

```text
POST https://api.openai.com/v1/audio/speech
```

```json
{
  "model": "tts-1-hd",
  "input": "欢迎使用 Java AI 学习系统，今天我们来讨论 Spring AI 的核心概念。",
  "voice": "alloy",
  "speed": 1.0,
  "response_format": "mp3"
}
```

| 参数 | 选项 |
|------|------|
| `model` | `tts-1`（快速）/ `tts-1-hd`（高质）/ `gpt-4o-mini-tts` |
| `voice` | `alloy`, `echo`, `fable`, `onyx`, `nova`, `shimmer` |
| `speed` | 0.25 ~ 4.0 |
| `response_format` | `mp3`, `opus`, `aac`, `flac`, `wav`, `pcm` |

> ⚠️ **注意**：TTS 端点的 `Content-Type` 是 application/json，但**响应是二进制音频流**，不是 JSON。

### 4.2 语音转文字（STT / Whisper）

```text
POST https://api.openai.com/v1/audio/transcriptions
Content-Type: multipart/form-data
```

```bash
curl https://api.openai.com/v1/audio/transcriptions \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -F file="@audio.mp3" \
  -F model="whisper-1" \
  -F language="zh" \
  -F response_format="verbose_json"
```

| 参数 | 说明 |
|------|------|
| `file` | 音频文件（mp3, wav, m4a, webm, mp4 等） |
| `model` | 目前仅 `whisper-1` |
| `language` | ISO 639-1 语言代码 |
| `response_format` | `json`, `text`, `srt`, `verbose_json`, `vtt` |

### 4.3 兼容实现情况

```text
✅ 有兼容实现的：
  - LocalAI → Whisper 后端（/v1/audio/transcriptions）
  - Faster-Whisper → 可通过 LocalAI 暴露

❌ 基本无兼容实现的：
  - TTS API → OpenAI 专有模型，无开源等价物
  - vLLM / Ollama / llama.cpp → 纯文本引擎
```

## 5. Models API

### 5.1 列出模型

```text
GET https://api.openai.com/v1/models
```

```json
// 响应
{
  "object": "list",
  "data": [
    {
      "id": "gpt-4o",
      "object": "model",
      "created": 1715367049,
      "owned_by": "system"
    },
    {
      "id": "text-embedding-3-small",
      "object": "model",
      "created": 1706044800,
      "owned_by": "system"
    }
  ]
}
```

### 5.2 检索单个模型

```text
GET https://api.openai.com/v1/models/gpt-4o
```

### 5.3 兼容实现的 Models 端点

```
vLLM    → 返回当前加载的模型（--served-model-name 决定）
Ollama  → 返回本地已 pull 的模型列表
One-API → 返回网关配置的所有渠道模型
```

> 💡 `/v1/models` 是健康检查的好端点——能返回模型列表说明服务活着的。

## 6. Files API 与 Fine-tuning

### 6.1 文件上传

```text
POST https://api.openai.com/v1/files
Content-Type: multipart/form-data
```

用于微调数据上传、Assistants API 文件管理等场景。

### 6.2 微调任务

```text
POST https://api.openai.com/v1/fine_tuning/jobs
```

```json
{
  "model": "gpt-4o-2024-08-06",
  "training_file": "file-abc123",
  "hyperparameters": {
    "n_epochs": 3,
    "batch_size": 4,
    "learning_rate_multiplier": 1.8
  }
}
```

### 6.3 兼容实现

```text
❌ 基本没有兼容 OpenAI Fine-tuning API 的实现。
原因：每个框架的微调流程、数据格式、超参数完全不同。

实际方案：
  → LLaMA-Factory → 独立的微调 Web UI + API
  → Unsloth       → Colab/本地微调，有自己的 API
  → Axolotl       → YAML 配置驱动微调
```

## 7. 兼容接口实现差异矩阵

| 端点 | OpenAI | DeepSeek | vLLM | Ollama | LocalAI | 智谱 | 通义千问 |
|------|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| `/chat/completions` | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| `/embeddings` | ✅ | ❌ | ✅ | ✅ | ✅ | ✅ | ✅ |
| `/models` | ✅ | ✅ | ✅ | ⚠️ | ✅ | ⚠️ | ⚠️ |
| `/images/generations` | ✅ | ❌ | ❌ | ❌ | ✅ | ⚠️ CogView | ✅ 通义万相 |
| `/audio/transcriptions` | ✅ | ❌ | ❌ | ❌ | ✅ | ❌ | ⚠️ Paraformer |
| `/audio/speech` | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ | ⚠️ CosyVoice |
| `/files` | ✅ | ❌ | ❌ | ❌ | ⚠️ | ❌ | ❌ |
| `/fine_tuning/jobs` | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ | ⚠️ |

> 🎯 **实战建议**：架构上只假设 `/chat/completions` 和 `/embeddings` 可兼容对接。Image/Audio 等能力走各厂商原生 API，不强制套 OpenAI 兼容层。
