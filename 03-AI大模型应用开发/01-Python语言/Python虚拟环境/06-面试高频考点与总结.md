## 1. 面试高频题与答题框架

### 1.1 原理类

**Q1：Python 虚拟环境是什么？为什么需要？**

```text
答题框架：
① 定义：隔离的 Python 运行环境（独立解释器链接 + 独立 site-packages）
② 本质：不是复制解释器，而是"链接 + 覆盖"（pyvenv.cfg 指向基础 Python）
③ 三大问题：版本冲突（项目 A/B 依赖不同）/权限（全局装不了）/不可复现
④ 标准：PEP 405（venv 是实现）
⑤ 加分：sys.prefix vs sys.base_prefix 判断是否在环境中
```

**Q2：pyvenv.cfg 是什么？虚拟环境为什么不能移动？**

```text
① pyvenv.cfg：虚拟环境的身份配置文件
② 三个关键字段：home（基础解释器绝对路径）/
   include-system-site-packages（隔离开关）/version
③ 不能移动：home 是绝对路径 → 换机器/目录路径失效
④ 正确做法：删除 .venv 重新创建（秒级）
⑤ 铁律：.venv 永不提交 Git（提交锁文件）
```

**Q3：activate 激活的实质是什么？**

```text
① 本质：修改 PATH 环境变量，把虚拟环境 bin/Scripts 前置
② 三件事：PATH 前置 / 设置 VIRTUAL_ENV / 提示符 (venv)
③ 局限：忘记激活 = 装错环境（经典事故）
④ 2026 解法：uv run / poetry run 免激活直接运行
⑤ 加分：CI/Docker 中天然免激活
```

### 1.2 工具类

**Q4：venv、conda、uv、Poetry 有什么区别？如何选？**

```text
① venv：标准库兜底（零安装、受限环境）
② conda：跨语言二进制包管理器（CUDA/GDAL 原生依赖场景）
③ uv：Rust 六合一（快 10-100 倍 + Python 管理），2026 新项目默认
④ Poetry：成熟锁文件 + PyPI 发布，存量项目保持
⑤ 选型一句话：新项目 uv，原生依赖 conda，受限环境 venv，存量 Poetry 不动
```

**Q5：uv 为什么这么快？**

```text
① Rust 编译执行：无 Python 启动开销
② 全局内容寻址缓存：wheel 跨项目复用
③ 并行元数据拉取：并发解析
④ 数据：冷装 50 依赖 2-5 秒 vs pip 30-50 秒（快 10-100 倍）
⑤ 加分：uv 一个工具替代 pip/venv/pyenv/pip-tools/pipx/poetry 大部分功能
```

**Q6：锁文件和 requirements.txt 有什么区别？**

```text
① requirements.txt：版本列表（flask==3.0.3），无哈希、传递依赖未锁定
② 锁文件（uv.lock）：完整依赖树 + 精确版本 + 哈希校验
③ 价值：100% 可复现（同锁文件 = 同环境）
④ 实践：uv.lock 提交 Git；uv sync --frozen 确定性构建
⑤ 注意：uv.lock 和 poetry.lock 不可互用
```

**Q7：pyproject.toml 的作用？**

```text
① PEP 621 标准项目配置文件（元数据 + 依赖 + 构建）
② 单一事实源：工具间可迁移（uv/Poetry/pdm/hatch 都读 [project]）
③ 依赖组：[project.optional-dependencies] / [dependency-groups]
④ 2026 趋势：新项目不用 pyproject.toml = 技术债
```

### 1.3 场景类

**Q8：conda 和 pip 混用要注意什么？**

```text
① 冲突根源：各自维护 site-packages 元数据，同包不同版本互看不见
② 黄金规则：先 conda 后 pip；conda 能装的不用 pip 装
③ 分工：原生依赖（CUDA/GCC）→ conda；纯 Python → pip/uv
④ 记录：environment.yml 的 pip 段记录 pip 包
⑤ 2026 组合：conda 管环境 + uv 装纯 Python 包
```

**Q9：Docker 里怎么管理 Python 环境？**

```text
① 用虚拟环境（uv 推荐）：uv sync --frozen --no-dev → COPY .venv
② 三铁律：容器内用 venv / 不用 conda / 依赖层独立 COPY
③ PEP 668：现代镜像拒绝全局 pip install
④ 多阶段构建：builder 装依赖 + 运行镜像只复制 .venv
⑤ 收益：体积小、构建快、可复现
```

**Q10：CI 中如何保证环境可复现？**

```text
① uv 项目：uv sync --frozen（锁文件过期即失败）
② conda 项目：environment-file 指定 + conda activate
③ 缓存：uv cache 持久化（提速 30-90 秒）
④ 多版本：uv python install 多版本 + uv run --python 测试
⑤ 铁律：CI 中禁止重新解析依赖（一切从锁文件出发）
```

**Q11：requirements.txt 项目如何迁移到 uv？**

```text
① uv init（生成 pyproject.toml + .venv）
② uv add -r requirements.txt（导入依赖）
③ uv lock（生成锁文件）
④ uv sync（同步环境）
⑤ 迁移收益：速度 10-100 倍 + 可复现 + 免激活
补充：Poetry 迁移用 uvx migrate-to-uv；Pipenv 直接迁 uv（绕开 Poetry）
```

**Q12：虚拟环境排查故障的思路？**

```text
万能三步：
① 我在哪？which python / conda env list
② 装的什么？pip list / uv pip list
③ 和锁文件一致吗？uv sync --frozen（自动修复）
常见：忘记激活（PATH 检查）、conda 覆盖 pip 包（顺序规则）、
     PEP 668（用 venv）、.venv 拷贝（重建）
```

## 2. 选型决策树

```text
选择环境工具
 │
 ├─ 需要 CUDA/GCC/GDAL 等原生依赖吗？
 │   ├─ 是 → conda/mamba（内层可配 uv 装纯 Python 包）
 │   └─ 否 → 下一步
 │
 ├─ 环境受限制（无法装第三方工具）？
 │   ├─ 是 → venv（标准库兜底）
 │   └─ 否 → 下一步
 │
 ├─ 新项目？→ uv（2026 默认）
 │
 ├─ 现有项目 CI 正常？
 │   ├─ Poetry 项目 → 保持 Poetry
 │   ├─ Pipenv 项目 → 迁 uv（Pipenv 维护模式）
 │   ├─ venv + requirements → 迁 uv
 │   └─ conda 纯 Python → 迁 uv
 │
 ├─ 发布 PyPI 库？→ uv / Poetry（发布流程）
 │
 └─ 全局 CLI 工具？→ uv tool install（替代 pipx）
```

## 3. 五大常见误区

| # | 误区 | 真相 |
|---|------|------|
| 1 | 「虚拟环境复制了一份 Python」 | 链接 + 覆盖（home 指向基础解释器），毫秒级创建 |
| 2 | 「.venv 要提交 Git 共享」 | 绝对路径不可移植——提交锁文件，clone 后 uv sync |
| 3 | 「conda 比 venv 高级，全用 conda」 | conda 是跨语言工具，纯 Python 项目 uv 更快更准 |
| 4 | 「锁文件可手动编辑」 | 锁文件由工具生成——手动改 = 破坏一致性 |
| 5 | 「激活是运行 Python 的前提」 | 免激活（uv run/poetry run）更安全，激活只是 PATH 技巧 |

## 4. 一句话总结全系列

```text
01 原理：本质 = 链接 + 覆盖；PEP 405 统一标准；pyvenv.cfg 一个文件读透所有工具
02 venv：标准库兜底（零安装/受限环境/教学）；requirements.txt 无锁文件是边界
03 conda：跨语言二进制管理器（CUDA 场景必用）；先 conda 后 pip 黄金规则
04 uv：2026 默认（Rust 六合一/快 10-100 倍/自带 Python）；锁文件提交 Git
05 实践：conda+uv 协同、CI --frozen、Docker 用 venv 不用 conda、四条迁移路径
06 面试：12 题框架 + 决策树 + 避坑清单
```

> 🎯 **系列总结**：虚拟环境是所有 Python 工程的"地基工程"——**原理只有一套（PEP 405），工具选择随场景**。2026 年记住一句话：新项目用 uv，原生依赖用 conda，受限环境用 venv，健康存量项目不动。地基打牢，上层的一切（AI 开发、数据分析、Web 后端）才稳。
