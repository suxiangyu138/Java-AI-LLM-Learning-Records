## 1. 为什么需要推理引擎？

```text
直接加载模型（HuggingFace Transformers）的问题：
├── 内存浪费：KV Cache 预分配固定大小 → 大部分空闲
├── 吞吐低：单个请求占满 GPU，后续请求排队
└── 无优化：无连续批处理（Continuous Batching）、无量化

推理引擎解决的核心问题：
├── PagedAttention：KV Cache 按需分页（类似 OS 虚拟内存）→ 内存利用率 +2-4x
├── Continuous Batching：动态批处理 → 吞吐量 +10x
├── 量化（GPTQ/AWQ/FP8）：降低显存 → 更小的 GPU 跑更大的模型
└── 多 LoRA 适配器：一个基座模型同时服务多个微调变体
```

## 2. vLLM — 高吞吐标杆

| 维度 | 详情 |
|------|------|
| 核心技术 | **PagedAttention**（KV Cache 分页管理，显存利用率提升 2-4 倍） |
| 吞吐量 | 比 HuggingFace Transformers 高 **24 倍** |
| 兼容性 | OpenAI 兼容 API（一行 `base_url` 切换） |
| 量化 | GPTQ、AWQ、FP8、INT8 |
| 部署 | Docker、pip、K8s |
| 适用 | 生产级高并发、大模型 API 服务 |

```bash
# 一行启动 OpenAI 兼容的 API 服务
pip install vllm
vllm serve Qwen/Qwen3-7B --port 8000

# 客户端调用（与 OpenAI SDK 完全兼容）
from openai import OpenAI
client = OpenAI(base_url="http://localhost:8000/v1", api_key="not-needed")
response = client.chat.completions.create(
    model="Qwen/Qwen3-7B",
    messages=[{"role": "user", "content": "Hello!"}]
)
```

## 3. TGI — HuggingFace 原生

| 维度 | 详情 |
|------|------|
| 来源 | HuggingFace 官方（Text Generation Inference） |
| 优势 | **与 HF Hub 深度集成**（一条命令拉取并部署任何 HF 模型） |
| 技术 | 连续批处理、Flash Attention、张量并行、量化（bitsandbytes/GPTQ） |
| 水印 | 内置 Watermark 防止 AI 生成内容滥用 |
| 适用 | HF 生态深度用户、需要官方支持的生产环境 |

```bash
# Docker 部署
docker run -p 8080:80 \
  -e MODEL_ID=meta-llama/Llama-4-Maverick-17B-128E \
  ghcr.io/huggingface/text-generation-inference
```

## 4. Ollama — 本地零门槛

| 维度 | 详情 |
|------|------|
| 定位 | 本地一键运行大模型（Mac/Windows/Linux） |
| 优势 | **零配置**（`ollama run qwen3` 一条命令）、自动 GPU 加速、Modelfile 自定义 |
| 模型库 | 官方维护数百个模型（Llama/DeepSeek/Qwen/Mistral 等） |
| 适用 | 本地开发测试、个人使用、小规模部署 |

```bash
# 安装 → 运行 → API 调用
brew install ollama            # macOS
ollama run qwen3:latest        # 启动
ollama pull deepseek-r1:7b     # 拉取模型

# API 调用（OpenAI 兼容：http://localhost:11434/v1）
curl http://localhost:11434/api/generate -d '{
  "model": "qwen3:latest", "prompt": "你好", "stream": false
}'
```

## 5. 其他引擎速览

## 6. 选型对比与成本估算

| 场景 | 推荐引擎 | 理由 |
|------|----------|------|
| **本地开发测试** | Ollama | 零配置，一条命令 |
| **生产高并发 API** | **vLLM** | 吞吐最高、OpenAI 兼容 |
| **HF 生态深度用户** | TGI | HF Hub 无缝集成 |
| **消费级硬件/边缘** | llama.cpp / Ollama | CPU 友好、GGUF 量化 |
| **NVIDIA 深度优化** | TensorRT-LLM | 极致 GPU 性能 |
| **CPU Only 部署** | llama.cpp | 纯 CPU、低资源 |

**成本估算（7B 模型）：** vLLM 单卡 A10G（24GB）= 可支撑 ~10 QPS（FP16）→ 月成本 ~$500-800/卡；Ollama 本地 M1 Mac = 可跑 2-3 QPS → 零额外成本。

> 🎯 **核心要点**：推理引擎选型三步 — **① 本地开发→Ollama ② 生产部署→vLLM（OpenAI 兼容 API）③ 极致性能/深度定制→TensorRT-LLM**。所有主流引擎都提供 OpenAI 兼容 API，切换成本极低。
