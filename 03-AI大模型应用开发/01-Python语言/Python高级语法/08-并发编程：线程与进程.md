## 1. GIL 全局解释器锁

```text
GIL (Global Interpreter Lock)：
  → 同一时刻，只有一个线程执行 Python 字节码
  → 多线程无法利用多核 CPU 并行计算
  → 但 I/O 操作会释放 GIL（所以多线程对 I/O 密集仍有意义）

对比 Java：
  Java: 真正的多线程并行（JVM 没有 GIL）
  Python: 多线程 ≠ 并行计算，只是并发 I/O
```

```python
# GIL 的直观演示
# CPU 密集: 多线程反而更慢（线程切换开销）
# I/O 密集: 多线程有效（GIL 在等待 I/O 时释放）
```

## 2. 多线程 threading

```python
from concurrent.futures import ThreadPoolExecutor
import requests

# 推荐：用 ThreadPoolExecutor（Java 的 ExecutorService）
def download(url):
    return requests.get(url).text[:100]

urls = [...1000个URL...]

with ThreadPoolExecutor(max_workers=20) as executor:
    results = list(executor.map(download, urls))  # 并发下载！

# 带回调
def process_result(future):
    print(f"完成: {future.result()[:50]}")

with ThreadPoolExecutor(max_workers=10) as executor:
    for url in urls:
        future = executor.submit(download, url)
        future.add_done_callback(process_result)
```

## 3. 多进程 multiprocessing

```python
from concurrent.futures import ProcessPoolExecutor

# CPU 密集：必须用多进程（绕过 GIL）
def heavy_computation(data):
    return sum(i**2 for i in range(10_000_000))

# N 个 CPU 核心 = N 倍速度
with ProcessPoolExecutor() as executor:
    results = list(executor.map(heavy_computation, datasets))

# 共享内存（大数据传递效率）
from multiprocessing import shared_memory
shm = shared_memory.SharedMemory(create=True, size=1024*1024*100)
# 多个进程共享同一块内存（避免 pickle 序列化开销）
```

## 4. 并发方案选择

```text
你的场景？
│
├── I/O 密集（API调用/文件读写/爬虫）
│   ├── 现代风格 → asyncio（协程，最推荐）
│   └── 传统风格 → ThreadPoolExecutor
│
├── CPU 密集（数据处理/模型推理不批处理）
│   └── ProcessPoolExecutor（多进程，绕过 GIL）
│
├── 混合型（既有 I/O 又有 CPU）
│   └── asyncio + ProcessPoolExecutor（run_in_executor）
│
└── 需要共享大量数据
    └── multiprocessing.shared_memory
```

```python
# 混合：asyncio 中调用 CPU 密集任务
async def mixed_workflow():
    loop = asyncio.get_running_loop()

    # 在进程池中跑 CPU 密集任务（不阻塞事件循环）
    result = await loop.run_in_executor(
        ProcessPoolExecutor(),
        heavy_computation, data
    )
    # 继续异步 I/O...
    api_result = await fetch_from_api(result)
    return api_result
```

## 核心要点回顾

- GIL = 同一时刻只有一个线程执行 Python 代码
- I/O 密集 → asyncio（首选）或 ThreadPoolExecutor
- CPU 密集 → ProcessPoolExecutor（打破 GIL）
- 混合型 → `loop.run_in_executor(ProcessPoolExecutor(), ...)`
- 多进程数据传递用 `shared_memory`（避免 pickle 开销）
