## 1. typing — 类型注解体系

```python
from typing import Optional, Union, Literal, TypedDict

# ① 基础注解（Python 3.10+ 用 X | None 替代 Optional[X]）
def call_llm(
    prompt: str,
    model: str = "gpt-5-turbo",
    temperature: float | None = None,          # 可选参数
    max_tokens: int = 1024
) -> str:                                      # 返回值类型
    ...

# ② Literal：限制参数取值（AI 场景：限定模型名）
ModelName = Literal["gpt-5-turbo", "claude-sonnet-4-5", "qwen3"]
def select_model(name: ModelName) -> None: ...

# ③ TypedDict：类型化字典（IDE 自动补全 + 类型检查）
class LLMResponse(TypedDict):
    content: str
    model: str
    tokens_used: int
    finish_reason: str

resp: LLMResponse = {"content": "...", "model": "gpt-5", ...}
```

## 2. dataclasses — 数据载体（替代手写 __init__）

```python
from dataclasses import dataclass, field

@dataclass
class ModelConfig:
    name: str
    temperature: float = 0.7
    max_tokens: int = 4096
    top_p: float = 1.0
    extra_params: dict = field(default_factory=dict)  # 可变默认值必须用 field

# 自动生成 __init__/__repr__/__eq__
config = ModelConfig(name="gpt-5-turbo", temperature=0.3)
print(config)   # ModelConfig(name='gpt-5-turbo', temperature=0.3, ...)

# 与 JSON 互转（AI API 通信的桥梁）
import dataclasses, json
json.dumps(dataclasses.asdict(config))       # dataclass → JSON
```

## 3. Pydantic — AI 项目的类型校验事实标准

Pydantic 不是标准库，但在 AI 项目中几乎"标配" — 因为它能自动验证 LLM 的结构化输出：

```python
from pydantic import BaseModel, Field

class OrderExtraction(BaseModel):
    product: str = Field(description="商品名称")
    quantity: int = Field(ge=1, description="数量，至少为1")
    urgency: Literal["low", "medium", "high"]

# LLM 结构化输出（OpenAI/FastAPI 均深度集成 Pydantic）
# ChatClient 自动校验 + 反序列化
order = chat_client.prompt()
    .user("帮我下单3台MacBook Pro，紧急")
    .entities(OrderExtraction.class)
    .call().entity()
# → OrderExtraction(product="MacBook Pro", quantity=3, urgency="high")
```

**Pydantic vs dataclasses：** dataclasses 是"纯数据容器"；Pydantic 是"数据容器 + 自动校验 + JSON Schema 生成 + LLM 结构化输出支持"。

## 4. enum / abc / Protocol 速览

```python
# enum：受限枚举（AI 场景：模型提供商、消息角色等）
from enum import Enum
class Role(str, Enum):
    SYSTEM = "system"
    USER = "user"
    ASSISTANT = "assistant"

class ModelProvider(str, Enum):
    OPENAI = "openai"
    ANTHROPIC = "anthropic"

# abc：抽象基类（定义接口契约）
from abc import ABC, abstractmethod
class LLMClient(ABC):
    @abstractmethod
    async def chat(self, messages: list) -> str: ...
    @abstractmethod
    async def stream(self, messages: list): ...

# Protocol：结构化子类型（鸭子类型的类型化版本）
from typing import Protocol
class Embeddable(Protocol):
    def embed(self, text: str) -> list[float]: ...
# 任何实现了 embed(text) 的对象都满足 Embeddable 接口
```

## 5. AI 项目中的类型系统最佳实践

```text
数据层选型指南：

API 通信的请求/响应      → Pydantic BaseModel（自动校验 + 序列化）
项目内部纯数据传递        → dataclasses（轻量、零依赖）
配置对象                 → dataclasses + field 默认值
接口契约                 → ABC 或 Protocol
有限选项（模型/角色/状态）→ Enum
函数签名                 → typing 注解 + Pyright 检查
```

> 🎯 **核心要点**：Python 类型系统在 AI 项目里的四个核心用法 — **① Pydantic 接管 LLM 结构化输出（自动校验）② dataclasses 做轻量数据载体 ③ Enum 约束有限选项（模型名/角色）④ TypedDict 给字典加类型**。类型注解不仅防 Bug，更能让 IDE 自动补全 AI API 的参数。
