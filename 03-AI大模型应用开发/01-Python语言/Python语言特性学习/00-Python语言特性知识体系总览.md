## 3. Python 特性分层全景图

```text
   ┌───────────────────────────────────────────────────────────────────┐
   │  第五层 · 应用表达层                                                │
   │  推导式 / 解包 / 切片 / 海象 / match / f-string / 标准库五件套        │
   │  ← 13 Pythonic 写法                                                │
   └───────────────────────────────────────────────────────────────────┘
                                   ↑ 建立在协议之上
   ┌───────────────────────────────────────────────────────────────────┐
   │  第四层 · 协议层（Python 的「接口」）                                │
   │  迭代协议 __iter__/__next__     上下文协议 __enter__/__exit__        │
   │  描述符协议 __get__/__set__     容器协议 __len__/__getitem__         │
   │  比较哈希 __eq__/__hash__       算术协议 __add__/__matmul__          │
   │  可调用 __call__                异步协议 __aenter__/__anext__        │
   │  ← 06 迭代 / 08 上下文与描述符 / 09 魔术方法                          │
   └───────────────────────────────────────────────────────────────────┘
                                   ↑ 由对象模型支撑
   ┌───────────────────────────────────────────────────────────────────┐
   │  第三层 · 抽象构造层                                                │
   │  函数（一等对象、闭包、装饰器） 类（MRO/super/元类/dataclass）        │
   │  类型注解（TypeVar/Protocol/Pydantic）                              │
   │  ← 04 函数 / 05 OOP / 07 元编程 / 10 类型系统                        │
   └───────────────────────────────────────────────────────────────────┘
                                   ↑ 依赖命名与对象语义
   ┌───────────────────────────────────────────────────────────────────┐
   │  第二层 · 语义基础层                                                │
   │  一切皆对象（id/type/value）  名字绑定（标签而非盒子）                │
   │  LEGB 作用域 + cell 闭包       可变性与传对象引用                     │
   │  ← 02 对象模型 / 03 作用域                                          │
   └───────────────────────────────────────────────────────────────────┘
                                   ↑ 运行在虚拟机上
   ┌───────────────────────────────────────────────────────────────────┐
   │  第一层 · 运行时底座                                                │
   │  源码→AST→字节码→PVM eval loop      引用计数 + 分代 GC + pymalloc     │
   │  GIL / 事件循环 / free-threading                                    │
   │  ← 01 执行模型 / 11 内存管理 / 12 并发模型                           │
   └───────────────────────────────────────────────────────────────────┘
```

> 🎯 **自下而上是「为什么」，自上而下是「怎么用」**。第五层的每一个语法糖都能追溯到第四层的某个协议，而协议的行为由第二层的对象语义决定，最终由第一层的虚拟机实现。想真正解释「为什么 `a[1:3]` 不报越界错」「为什么 `cached_property` 只算一次」，必须往下走两层。

## 4. 核心特性速查（Java 对照）

### 4.1 语义层对照

| 主题 | Java | Python | 差异要点 |
|------|------|--------|---------|
| 变量 | 有类型的存储位置 | 指向对象的名字 | Python 的 `a = b` 是贴标签，不拷贝 |
| 传参 | 值传递（对象传引用副本） | 传对象引用（call by sharing） | 改内容影响调用方，重新赋值不影响 |
| 基本类型 | `int` 在栈上，8 字节 | `int` 是堆对象，28 字节起 | Python 无原生栈值，这是慢的根因之一 |
| 相等 | `==` 比引用，`equals` 比值 | `is` 比身份，`==` 比值 | 语义正好错位，`is` ≈ Java 的 `==` |
| 哈希契约 | `equals`/`hashCode` | `__eq__`/`__hash__` | 重写 `__eq__` 会把 `__hash__` 置 None |
| null | `null` | `None`（单例对象） | 必须用 `is None` 判断 |
| 字符串不可变 | ✅ | ✅ | 都需要 `join`/`StringBuilder` 避免 O(n²) |
| 常量 | `final` | 约定大写 + `Final` 注解 | Python 无强制不可变 |

### 4.2 抽象层对照

| 主题 | Java | Python |
|------|------|--------|
| 接口契约 | `interface` + `implements`（名义） | 鸭子类型 / `Protocol`（结构） |
| 抽象类 | `abstract class` | `abc.ABC` + `@abstractmethod` |
| 静态方法 | `static` | `@staticmethod` |
| 工厂方法 | `static` 工厂（无多态） | `@classmethod`（`cls` 自动适配子类）✅ |
| 多继承 | 只有接口可多继承 | 类可多继承 + C3 线性化 MRO |
| 调用父类 | `super.m()` = 直接父类 | `super().m()` = **MRO 下一个类** |
| 访问控制 | `private`/`protected` 强制 | `_x` 约定 / `__x` 名字修饰（非隔离） |
| 属性封装 | getter/setter 方法 | `@property`（调用方写法不变）✅ |
| 数据类 | `record`（14+） | `@dataclass` / `NamedTuple` |
| 泛型 | `<T>` + 类型擦除 | `[T]`（3.12+）/ `TypeVar`，运行时无约束 |
| 注解/元数据 | `@Annotation` + 反射 | 装饰器（**直接改行为**）/ `Annotated` |
| 类的元信息 | `Class<?>` + 反射 API | 元类 / `type()` / `__init_subclass__` |
| 枚举 | `enum` | `enum.Enum` / `StrEnum`（3.11+） |
| 不可变对象 | 全 `final` 字段 | `@dataclass(frozen=True)` / `NamedTuple` |

### 4.3 特性层对照

| 主题 | Java | Python |
|------|------|--------|
| Lambda | 只能引用 effectively-final 变量 | 闭包捕获**变量**（延迟绑定陷阱）⚠️ |
| 函数式 | `Stream` API | 生成器 + `itertools` + 推导式 |
| 惰性序列 | `Stream`（一次性） | 生成器（一次性）+ `yield from` |
| 资源管理 | `try-with-resources` + `AutoCloseable` | `with` + `__enter__`/`__exit__` |
| 运算符重载 | ❌ 不支持 | ✅ `__add__`/`__matmul__` 等全套 |
| 一等函数 | 函数式接口包装 | 函数本身是对象 |
| 反射 | `Class.getMethod` 等重型 API | `getattr`/`setattr`/`dir` 日常工具 |
| 装饰增强 | AOP / 动态代理 / 字节码增强 | 装饰器（语言原生）✅ |
| 模式匹配 | `switch` 模式（21+） | `match`（3.10+，可解构 dict/对象） |
| 字符串模板 | `"a" + b` / `String.format` | f-string（`{x=}` 调试神器） |

### 4.4 运行时层对照

| 主题 | Java | Python |
|------|------|--------|
| 编译产物 | `.class`（JVM 字节码） | `.pyc`（Code Object） |
| 优化 | JIT（C1/C2）+ 逃逸分析 | 无 JIT（3.13 起实验性）+ 3.11 自适应特化 |
| GC | 可达性分析 + 分代复制 + 压缩整理 | **引用计数为主** + 分代标记清除兜底 |
| 内存归还 | 取决于收集器 | pymalloc arena 全空才归还 |
| 弱引用 | `WeakReference` / `WeakHashMap` | `weakref.ref` / `WeakValueDictionary` |
| 并行 CPU | 线程真并行 | ❌ GIL 限制 → 用多进程 |
| 海量 I/O | 虚拟线程（21+，透明） | asyncio 协程（需 `async/await` 染色） |
| 线程池 | `ExecutorService` | `ThreadPoolExecutor` / `ProcessPoolExecutor` |
| Future | `CompletableFuture` | `concurrent.futures.Future` / `asyncio.Task` |
| 线程局部 | `ThreadLocal` | `threading.local()` / `contextvars`（协程用） |
| 类型安全 | 编译器强制 | 注解仅供工具；运行时校验靠 Pydantic |

| 3.13 | 2024 | **free-threading 实验版（PEP 703）**、实验性 JIT、新 REPL、`Doc`、移除 19 个死模块 | 12 / 01 |
| 3.14 | 2025 | **free-threading 正式支持**、**延迟注解求值（PEP 649/749）**、`interpreters` 模块（PEP 734）、模板字符串（PEP 750）、Linux 默认 `forkserver` | 12 / 10 |

```text
   两条主线在 2026 年的走向：

   性能线：3.11 自适应特化 → 3.13 实验 JIT → 3.14+ JIT 成熟
          「Faster CPython」项目目标：相对 3.10 提速 5 倍

   并发线：3.12 per-interpreter GIL → 3.13 free-threading 实验
          → 3.14 正式支持 → 3.15+ 目标成为默认构建
```

> ⚠️ 生产选型建议（2026.07）：**3.12 是当前最稳的生产版本**（生态最全 + 性能已大幅提升）；3.13/3.14 的 free-threading 构建仍需确认所有 C 扩展（尤其 numpy/torch/pandas）已适配。写代码时以 3.10+ 为语法基线（`match`、`X | Y` 都可用）是比较务实的选择。
