## 1. 装饰器的本质

装饰器就是**一个接受函数、返回函数的可调用对象**，`@` 只是语法糖：

```python
def log(func):
    def wrapper(*args, **kwargs):
        print(f"→ {func.__name__}")
        result = func(*args, **kwargs)
        print(f"← {result}")
        return result
    return wrapper

@log
def add(a, b): return a + b

# 完全等价于：
# def add(a, b): return a + b
# add = log(add)

add(1, 2)
# → add
# ← 3
```

```text
   装饰前            装饰后
   ─────            ─────
   add ──→ [原函数]   add ──→ [wrapper] ──闭包持有──→ [原函数]
                              │
                       名字 add 被重新绑定到 wrapper
```

三个必备要素：

| 要素 | 作用 | 缺失后果 |
|------|------|---------|
| `*args, **kwargs` | 接受任意签名 | 只能装饰特定签名的函数 |
| `return func(...)` | 转发返回值 | 被装饰函数返回值全变 `None` |
| `@functools.wraps` | 保留元信息 | 函数名/文档/签名全丢 |

## 2. functools.wraps 与元信息

```python
import functools

def bad(func):
    def wrapper(*a, **kw): return func(*a, **kw)
    return wrapper

def good(func):
    @functools.wraps(func)                # ← 关键
    def wrapper(*a, **kw): return func(*a, **kw)
    return wrapper

@bad
def f1(): "文档1"
@good
def f2(): "文档2"

print(f1.__name__, f1.__doc__)      # wrapper None      ❌
print(f2.__name__, f2.__doc__)      # f2 文档2           ✅
print(f2.__wrapped__)               # <function f2>     ✅ 能拿到原函数
```

`wraps` 复制的内容：

| 复制项 | 说明 |
|-------|------|
| `__name__` `__qualname__` | 函数名、限定名 |
| `__doc__` | 文档字符串 |
| `__module__` | 所属模块 |
| `__annotations__` | 类型注解（Pydantic/FastAPI 依赖） |
| `__dict__` | 更新（非替换）自定义属性 |
| `__wrapped__` | 指向原函数，供 `inspect` 穿透 |

```python
# 不加 wraps 会破坏的真实场景
import inspect
print(inspect.signature(f1))    # (*a, **kw)      ← FastAPI 拿不到真实参数！
print(inspect.signature(f2))    # ()              ← 正确
```

> ⚠️ 在 FastAPI / Click / Pytest 这类**靠签名内省工作的框架**里，漏写 `@wraps` 会导致路由参数解析失败、CLI 选项丢失。这不是「代码不优雅」而是「功能坏了」。

## 3. 带参数的装饰器

需要三层嵌套：**参数层 → 装饰器层 → 包装层**。

```python
import functools, time

def retry(max_attempts=3, delay=1.0, exceptions=(Exception,)):
    def decorator(func):                                  # 真正的装饰器
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            last_exc = None
            for attempt in range(1, max_attempts + 1):
                try:
                    return func(*args, **kwargs)
                except exceptions as e:
                    last_exc = e
                    if attempt < max_attempts:
                        print(f"第 {attempt} 次失败，{delay}s 后重试")
                        time.sleep(delay * attempt)       # 指数退避
            raise last_exc
        return wrapper
    return decorator

@retry(max_attempts=3, delay=0.5, exceptions=(TimeoutError, ConnectionError))
def call_llm(prompt: str) -> str:
    ...
```

```text
   @retry(max_attempts=3)
   def call_llm(): ...

   脱糖过程：
   ① retry(max_attempts=3)  →  返回 decorator
   ② decorator(call_llm)     →  返回 wrapper
   ③ call_llm = wrapper
```

### 3.1 兼容「带参数」和「不带参数」两种写法

```python
def timed(func=None, *, unit="s"):
    if func is None:                          # 带参调用：@timed(unit="ms")
        return functools.partial(timed, unit=unit)

    @functools.wraps(func)                    # 无参调用：@timed
    def wrapper(*args, **kwargs):
        t0 = time.perf_counter()
        r = func(*args, **kwargs)
        dt = time.perf_counter() - t0
        print(f"{func.__name__}: {dt*1000:.1f}ms" if unit == "ms" else f"{dt:.3f}s")
        return r
    return wrapper

@timed                    # ✅ 都能用
def a(): pass
@timed(unit="ms")         # ✅
def b(): pass
```

## 4. 类装饰器与装饰类

### 4.1 用类实现装饰器（可维护状态）

```python
class RateLimiter:
    """令牌桶限流装饰器，实例持有状态"""
    def __init__(self, calls_per_sec=2):
        self.interval = 1.0 / calls_per_sec
        self.last_call = 0.0

    def __call__(self, func):                     # 接受被装饰函数
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            wait = self.interval - (time.perf_counter() - self.last_call)
            if wait > 0: time.sleep(wait)
            self.last_call = time.perf_counter()
            return func(*args, **kwargs)
        return wrapper

@RateLimiter(calls_per_sec=2)                     # 每秒最多 2 次
def call_api(x): return x
```

```python
# 更简单的形态：__init__ 接函数，__call__ 做包装
class CountCalls:
    def __init__(self, func):
        functools.update_wrapper(self, func)      # 类装饰器用 update_wrapper
        self.func, self.count = func, 0
    def __call__(self, *args, **kwargs):
        self.count += 1
        return self.func(*args, **kwargs)

@CountCalls
def f(): pass
f(); f()
print(f.count)      # 2
```

> ⚠️ 用类装饰**实例方法**会踩坑：`self` 变成了装饰器实例而非对象实例，需要额外实现 `__get__` 走描述符协议（见 [08 章](./08-上下文管理器与描述符.md)）。装饰方法时优先用函数式装饰器。

### 4.2 装饰类（返回改造后的类）

```python
def singleton(cls):
    instances = {}
    @functools.wraps(cls)
    def get_instance(*args, **kwargs):
        if cls not in instances:
            instances[cls] = cls(*args, **kwargs)
        return instances[cls]
    return get_instance

@singleton
class ModelPool:
    def __init__(self): print("加载模型（只应出现一次）")

a, b = ModelPool(), ModelPool()
print(a is b)        # True
```

```python
# 注册表模式（AI 框架里到处都是）
MODEL_REGISTRY = {}

def register_model(name):
    def decorator(cls):
        MODEL_REGISTRY[name] = cls
        cls.model_name = name          # 也可以往类上注入属性
        return cls                     # ← 返回原类，不做替换
    return decorator

@register_model("bert")
class BertModel: pass

@register_model("gpt")
class GPTModel: pass

print(MODEL_REGISTRY)     # {'bert': <class BertModel>, 'gpt': <class GPTModel>}
```

| 装饰目标 | 装饰器返回 | 典型用途 |
|---------|-----------|---------|
| 函数 → 函数 | 包装函数 | 日志、重试、缓存、计时、鉴权 |
| 函数 → 其他对象 | 描述符/类实例 | `property`、`staticmethod` |
| 类 → 原类（改造后） | 同一个类 | 注册表、注入方法、`@dataclass` |
| 类 → 新对象 | 工厂函数 | 单例 |

## 5. 装饰器执行顺序

```python
def A(f):
    print("A 装饰时")
    def w(*a): print("A 调用时"); return f(*a)
    return w

def B(f):
    print("B 装饰时")
    def w(*a): print("B 调用时"); return f(*a)
    return w

@A          # 外层
@B          # 内层
def hello(): print("hello")
# 装饰时输出（自下而上）：
# B 装饰时
# A 装饰时

hello()
# 调用时输出（自上而下）：
# A 调用时
# B 调用时
# hello
```

```text
   @A
   @B
   def hello(): ...

   等价于 hello = A(B(hello))

   装饰阶段：B 先执行（离函数近） ↑ 自下而上
   调用阶段：A 先执行（在最外层） ↓ 自上而下
   
   像洋葱：A[ B[ hello ] ]
```

顺序有实际影响的例子：

```python
# ✅ 正确：先鉴权再缓存（未授权不该命中缓存）
@requires_auth
@lru_cache(maxsize=128)
def get_user_data(uid): ...

# ❌ 错误：缓存在外，第一次通过鉴权后所有人都能拿到缓存结果
@lru_cache(maxsize=128)
@requires_auth
def get_user_data(uid): ...
```

```python
# 框架规定的固定顺序：@property 系列必须在最外层
class C:
    @property           # 必须最外
    @functools.lru_cache(maxsize=1)
    def expensive(self): return compute()
```

> 🎯 记忆法：**装饰器像穿衣服——先穿的（下面的）贴身，后穿的（上面的）在外**。请求进来先碰到最外层。

## 6. functools 工具箱

| 工具 | 作用 | 备注 |
|------|------|------|
| `wraps` / `update_wrapper` | 复制元信息 | 写装饰器必用 |
| `lru_cache(maxsize=128)` | LRU 缓存 | 参数必须可哈希 |
| `cache` | 无上限缓存（3.9+） | = `lru_cache(maxsize=None)` |
| `cached_property` | 实例级惰性属性（3.8+） | 只算一次，存进 `__dict__` |
| `partial` / `partialmethod` | 固定参数 | 可 pickle |
| `singledispatch` | 基于首参类型的函数重载 | 类似 Java 方法重载 |
| `total_ordering` | 补全比较运算符 | 只写 `__eq__` + `__lt__` |
| `reduce` | 折叠 | 慎用，可读性差 |

```python
from functools import lru_cache, cached_property, singledispatch, total_ordering

# ① lru_cache：递归 DP / 昂贵的纯函数
@lru_cache(maxsize=1024)
def embed(text: str) -> tuple:              # 返回值也最好可哈希/不可变
    return tuple(model.encode(text))
print(embed.cache_info())                   # hits/misses/maxsize/currsize
embed.cache_clear()

# ② cached_property：实例级懒加载（模型权重、DB 连接）
class Service:
    @cached_property
    def model(self):
        print("加载中...")                   # 只执行一次
        return load_model()
s = Service()
s.model; s.model                            # 第二次直接读 s.__dict__['model']

# ③ singledispatch：按类型分派
@singledispatch
def to_json(obj): raise TypeError(f"不支持 {type(obj)}")
@to_json.register
def _(obj: dict): return json.dumps(obj)
@to_json.register
def _(obj: list): return json.dumps(obj)
@to_json.register
def _(obj: str): return json.dumps({"text": obj})

# ④ total_ordering：写 2 个方法得到 6 个
@total_ordering
class Version:
    def __init__(self, v): self.v = tuple(map(int, v.split(".")))
    def __eq__(self, o): return self.v == o.v
    def __lt__(self, o): return self.v < o.v
print(Version("1.2.0") >= Version("1.1.9"))   # True（自动推导）
```

> ⚠️ `lru_cache` 用在**实例方法**上会持有 `self` 的强引用，导致实例永远不被回收（内存泄漏）。实例级缓存请用 `cached_property`，或把方法改成模块级纯函数。

## 7. 元类：类的创建流程

**元类是「创建类的类」**。`class` 关键字本质上是在调用元类。

### 7.1 类创建的完整流程

```text
   执行 class Foo(Base, metaclass=Meta): body
   
   ① 确定元类：显式 metaclass= → 否则取最派生基类的类型 → 否则 type
   ② 准备命名空间：ns = Meta.__prepare__(name, bases, **kwds)   默认返回 dict
   ③ 执行类体：在 ns 中执行 body（方法、类变量都写进 ns）
   ④ 创建类对象：Foo = Meta(name, bases, ns, **kwds)
        └─ 内部依次调 Meta.__call__ → Meta.__new__ → Meta.__init__
   ⑤ 触发钩子：基类的 __init_subclass__、类内描述符的 __set_name__
   ⑥ 应用类装饰器（如果有，自下而上）
```

```python
class Meta(type):
    @classmethod
    def __prepare__(mcls, name, bases, **kwds):
        print(f"① prepare {name}")
        return {}                                  # 可返回 OrderedDict 等

    def __new__(mcls, name, bases, ns, **kwds):
        print(f"② new {name}, 成员: {list(ns)}")
        ns["injected"] = "由元类注入"                # ← 在类创建前改造
        return super().__new__(mcls, name, bases, ns)

    def __init__(cls, name, bases, ns, **kwds):
        print(f"③ init {name}")
        super().__init__(name, bases, ns)

    def __call__(cls, *args, **kwargs):            # 拦截「实例化」
        print(f"④ 创建 {cls.__name__} 的实例")
        return super().__call__(*args, **kwargs)

class Foo(metaclass=Meta):
    x = 1
    def m(self): pass

# ① prepare Foo
# ② new Foo, 成员: ['__module__', '__qualname__', 'x', 'm']
# ③ init Foo
print(Foo.injected)     # 由元类注入
Foo()                   # ④ 创建 Foo 的实例
```

| 方法 | 时机 | 用途 |
|------|------|------|
| `__prepare__` | 执行类体**之前** | 控制命名空间类型（记录定义顺序等） |
| `__new__` | 创建类对象 | **改造类**：注入成员、校验、修改基类 |
| `__init__` | 类对象已创建 | 注册类、初始化类级状态 |
| `__call__` | **实例化**类时 | 控制实例创建（单例、实例缓存） |

### 7.2 元类实战

```python
# ① 抽象方法强制（ABCMeta 的简化原理）
class RequireMethods(type):
    required = ("forward",)
    def __new__(mcls, name, bases, ns):
        cls = super().__new__(mcls, name, bases, ns)
        if bases:                                        # 跳过基类自身
            for m in mcls.required:
                if not callable(getattr(cls, m, None)):
                    raise TypeError(f"{name} 必须实现 {m}()")
        return cls

class Layer(metaclass=RequireMethods): pass
class Linear(Layer):
    def forward(self, x): return x
# class Bad(Layer): pass    → TypeError: Bad 必须实现 forward()
```

```python
# ② 单例（比装饰器版更彻底：isinstance 仍正常工作）
class Singleton(type):
    _instances = {}
    def __call__(cls, *args, **kwargs):
        if cls not in cls._instances:
            cls._instances[cls] = super().__call__(*args, **kwargs)
        return cls._instances[cls]

class Config(metaclass=Singleton):
    def __init__(self): self.data = {}

print(Config() is Config())              # True
print(isinstance(Config(), Config))      # True ← 装饰器版单例做不到
```

```python
# ③ 自动注册（Django Model / SQLAlchemy 的核心手法）
class RegistryMeta(type):
    registry = {}
    def __init__(cls, name, bases, ns):
        super().__init__(name, bases, ns)
        if bases:                                        # 不注册基类
            RegistryMeta.registry[name.lower()] = cls

class Plugin(metaclass=RegistryMeta): pass
class EmailPlugin(Plugin): pass
class SmsPlugin(Plugin): pass
print(RegistryMeta.registry)     # {'emailplugin': ..., 'smsplugin': ...}
```

> ⚠️ Tim Peters 的名言：「如果你不确定是否需要元类，那就不需要。」元类会让代码难以理解和调试，**优先考虑 `__init_subclass__`、类装饰器、描述符**这三个更轻量的方案。真正需要元类的场景：ORM 字段映射、需要控制 `__prepare__`、需要拦截实例化。

## 8. __init_subclass__ 与 __set_name__

Python 3.6 引入的两个钩子（PEP 487），覆盖了绝大多数原本需要元类的场景：

### 8.1 `__init_subclass__`：子类创建时的钩子

```python
class Plugin:
    registry = {}

    def __init_subclass__(cls, /, name=None, enabled=True, **kwargs):
        super().__init_subclass__(**kwargs)
        if enabled:
            key = name or cls.__name__.lower()
            Plugin.registry[key] = cls
            cls.plugin_name = key

class EmailPlugin(Plugin, name="email"): pass      # ← 可传类关键字参数
class SmsPlugin(Plugin): pass
class DebugPlugin(Plugin, enabled=False): pass     # 不注册

print(Plugin.registry)              # {'email': ..., 'smsplugin': ...}
print(EmailPlugin.plugin_name)      # email
```

`__init_subclass__` **隐式是类方法**，不需要写 `@classmethod`。

```python
# 用它做子类校验，比元类清晰得多
class Model:
    def __init_subclass__(cls, **kw):
        super().__init_subclass__(**kw)
        if not hasattr(cls, "table_name"):
            raise TypeError(f"{cls.__name__} 必须定义 table_name")

class User(Model):
    table_name = "users"
# class Bad(Model): pass   → TypeError
```

### 8.2 `__set_name__`：描述符自动获知属性名

```python
class Field:
    def __set_name__(self, owner, name):        # 类创建时自动调用
        self.name = name                        # 不用手写 Field("age")
        self.private = f"_{name}"
        print(f"Field 绑定到 {owner.__name__}.{name}")

    def __get__(self, obj, objtype=None):
        return getattr(obj, self.private, None) if obj else self

    def __set__(self, obj, value):
        setattr(obj, self.private, value)

class User:
    name = Field()        # Field 绑定到 User.name
    age = Field()         # Field 绑定到 User.age

u = User(); u.age = 30
print(u.age, u._age)      # 30 30
```

| 方案 | 复杂度 | 适用 |
|------|:-----:|------|
| `__init_subclass__` | 低 | 子类注册、校验、注入类属性 |
| `__set_name__` | 低 | 描述符获知自己的属性名 |
| 类装饰器 | 低 | 一次性改造某个类（`@dataclass`） |
| 描述符 | 中 | 属性级的校验/计算/代理 |
| **元类** | 高 | 需控制命名空间或拦截实例化 |

> 🎯 决策顺序：**类装饰器 → `__init_subclass__` → 描述符 → 元类**。从上往下试，能用上面的就别用下面的。

## 9. 反射与动态执行

### 9.1 属性反射四件套

```python
class Obj:
    def __init__(self): self.x = 1
    def m(self): return "m"

o = Obj()
print(getattr(o, "x"))                  # 1
print(getattr(o, "missing", "默认值"))    # 默认值（无默认值则 AttributeError）
setattr(o, "y", 2);  print(o.y)         # 2
print(hasattr(o, "m"))                  # True
delattr(o, "y")

# 动态调用方法（插件分发的常见写法）
method = getattr(o, "m", None)
if callable(method): print(method())    # m
```

```python
# 实战：字符串驱动的路由分发
class Handler:
    def handle_text(self, d): return f"文本: {d}"
    def handle_image(self, d): return f"图片: {d}"

    def dispatch(self, kind, data):
        fn = getattr(self, f"handle_{kind}", None)
        if fn is None: raise ValueError(f"不支持的类型: {kind}")
        return fn(data)

print(Handler().dispatch("text", "hi"))     # 文本: hi
```

### 9.2 模块与类的内省

```python
import importlib, inspect

# 动态导入（插件系统 / 按配置加载模型）
mod = importlib.import_module("json")
print(mod.dumps({"a": 1}))

cls = getattr(importlib.import_module("collections"), "OrderedDict")
print(cls())

# 内省
print([n for n, v in inspect.getmembers(Handler, inspect.isfunction)])
# ['dispatch', 'handle_image', 'handle_text']
print(inspect.getsource(Handler.dispatch)[:40])
print(Handler.__dict__.keys())
```

| 工具 | 用途 |
|------|------|
| `dir(obj)` | 列出所有属性名 |
| `vars(obj)` / `obj.__dict__` | 实例属性字典 |
| `type(obj)` / `isinstance` / `issubclass` | 类型判断 |
| `inspect.getmembers/signature/getsource` | 深度内省 |
| `importlib.import_module` | 动态导入 |
| `globals()` / `locals()` | 命名空间字典 |

### 9.3 exec / eval：能用但别用

```python
print(eval("1 + 2"))                       # 3    只能求值表达式
exec("def f(): return 42")                 # 可执行语句
print(f())                                 # 42

# ❌ 绝对不要 eval 外部输入
# eval(user_input)   → 任意代码执行漏洞（__import__('os').system('rm -rf /')）

# ✅ 解析结构化字面量用 ast.literal_eval
import ast, json
print(ast.literal_eval("{'a': [1, 2]}"))   # 只允许字面量，安全
print(json.loads('{"a": [1, 2]}'))         # JSON 场景首选
```

| 需求 | 应该用 |
|------|-------|
| 解析配置/字面量 | `json.loads` / `ast.literal_eval` / `tomllib` |
| 按名字取对象 | `getattr` / 字典映射 |
| 动态加载模块 | `importlib` |
| 动态造类 | `type(name, bases, ns)` |
| 真的要编译代码 | `compile` + `exec`，且输入必须完全可信 |

> ⚠️ `eval`/`exec` 是安全审计的红线。Python 里几乎所有「看起来需要 eval」的需求都有安全替代方案。

## 10. 核心要点回顾

- 装饰器 = **接受函数返回函数**；`@` 只是 `f = deco(f)` 的语法糖
- 三件套缺一不可：`*args/**kwargs` 透传、`return` 转发、`@functools.wraps`
- 漏写 `wraps` 会让 FastAPI/Click 等**靠签名工作的框架直接坏掉**
- 带参装饰器 = **三层嵌套**；`func=None` + `partial` 可兼容两种写法
- 装饰器顺序：**装饰时自下而上，调用时自上而下**（洋葱模型）
- `lru_cache` 装饰实例方法会**泄漏实例**，实例级缓存用 `cached_property`
- 类创建流程：`__prepare__` → 执行类体 → `__new__` → `__init__` → `__init_subclass__`/`__set_name__` → 类装饰器
- 元类 `__new__` 改造类，`__call__` 拦截实例化（单例的正确做法）
- **优先级：类装饰器 → `__init_subclass__` → 描述符 → 元类**
- 反射用 `getattr`/`importlib`；**永远不要 `eval` 外部输入**，改用 `ast.literal_eval`
