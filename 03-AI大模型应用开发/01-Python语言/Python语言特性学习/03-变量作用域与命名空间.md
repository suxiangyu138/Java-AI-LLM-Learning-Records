## 1. 命名空间的本质

命名空间就是**一个从名字到对象的字典**。Python 没有「变量声明」，只有「往命名空间里塞键值对」。

```python
x = 10
def f():
    y = 20
    print(locals())     # {'y': 20}         ← 局部命名空间
print(globals()['x'])   # 10                ← 全局（模块级）命名空间
f()

import builtins
print(len(dir(builtins)))   # 150+          ← 内置命名空间
```

| 命名空间 | 载体 | 生命周期 | 查看方式 |
|---------|------|---------|---------|
| 内置（Built-in） | `builtins` 模块 | 解释器启动到退出 | `dir(builtins)` |
| 全局（Global） | 模块的 `__dict__` | 模块导入到解释器退出 | `globals()` |
| 局部（Local） | 函数调用帧 | 单次函数调用 | `locals()` |
| 闭包（Enclosing） | `cell` 对象 | 被内层函数引用期间 | `f.__closure__` |

> ⚠️ `locals()` 在函数内返回的是**快照字典**，改它不会影响真实局部变量（CPython 局部变量存在数组里，靠索引访问）；`globals()` 返回的是真实字典，改它有效。

## 2. LEGB 查找规则

名字解析按 **L → E → G → B** 顺序，找到即停，全找不到抛 `NameError`：

```text
┌─────────────────────────────────────────┐
│ B  Built-in    内置：print / len / int   │
│ ┌─────────────────────────────────────┐ │
│ │ G  Global    模块级变量               │ │
│ │ ┌─────────────────────────────────┐ │ │
│ │ │ E  Enclosing  外层函数的局部       │ │ │
│ │ │ ┌─────────────────────────────┐ │ │ │
│ │ │ │ L  Local   当前函数局部       │ │ │ │
│ │ │ └─────────────────────────────┘ │ │ │
│ │ └─────────────────────────────────┘ │ │
│ └─────────────────────────────────────┘ │
└─────────────────────────────────────────┘
       查找方向：由内向外 ↑（只读时）
```

```python
x = "global"

def outer():
    x = "enclosing"
    def inner():
        # x = "local"          # 取消注释则打印 local
        print(x)               # enclosing
    inner()

outer()
```

关键点：**Python 在编译期就静态决定了每个名字属于哪个作用域**，不是运行时才查。

```python
import dis
def f():
    a = 1
    print(a, x)
dis.dis(f)
# LOAD_FAST   a       ← 编译期已知是局部变量（数组索引访问，快）
# LOAD_GLOBAL x       ← 编译期已知是全局（字典查找，慢）
```

> 💡 这解释了一个性能技巧：热循环里把 `len` 这类内置函数赋给局部变量（`_len = len`），能把 `LOAD_GLOBAL` 换成 `LOAD_FAST`。Python 3.11+ 对 `LOAD_GLOBAL` 做了内联缓存，收益已经不大了。

### 2.1 UnboundLocalError 的成因

```python
count = 0
def bad():
    print(count)    # UnboundLocalError: cannot access local variable 'count'
    count += 1      # ← 因为这行赋值，编译器把整个函数里的 count 都判定为局部变量

def good():
    global count
    print(count)    # 0
    count += 1
```

规则：**函数体内只要出现对某个名字的赋值（包括 `+=`、`for x in`、`with as x`、`except as x`），该名字在整个函数内就是局部变量**，除非用 `global` / `nonlocal` 声明。

## 3. global 与 nonlocal

| 关键字 | 作用 | 目标作用域 | 常见场景 |
|--------|------|-----------|---------|
| `global x` | 声明 x 是模块级变量 | Global | 修改模块级配置、计数器 |
| `nonlocal x` | 声明 x 属于最近的外层函数 | Enclosing | 闭包内累加状态、装饰器计数 |

```python
def counter_factory():
    count = 0
    def increment():
        nonlocal count      # 没有它就是 UnboundLocalError
        count += 1
        return count
    return increment

c = counter_factory()
print(c(), c(), c())        # 1 2 3
```

```python
# nonlocal 要求外层必须已存在该名字，且不能跳到模块级
def f():
    def g():
        nonlocal y          # SyntaxError: no binding for nonlocal 'y' found
        y = 1
    g()
```

> 🎯 工程实践：`global` 基本是代码异味，优先用类属性、闭包或显式传参。`nonlocal` 在写装饰器时反而很常用。

## 4. 闭包机制与 cell 对象

闭包 = **函数 + 它捕获的外层变量环境**。CPython 用 `cell` 对象实现捕获：

```python
def make_adder(n):
    def adder(x):
        return x + n            # n 来自外层 → 形成闭包
    return adder

add5 = make_adder(5)
print(add5(10))                 # 15 —— make_adder 早已返回，n 依然存活

print(add5.__closure__)         # (<cell at 0x...: int object at 0x...>,)
print(add5.__closure__[0].cell_contents)   # 5
print(add5.__code__.co_freevars)           # ('n',)  自由变量名
```

```text
   make_adder(5) 执行完毕，栈帧销毁，但：

   ┌──────────────┐
   │ adder 函数对象│
   │  __code__    │──→ 字节码（LOAD_DEREF n）
   │  __closure__ │──→ (cell,) ──→ ┌─────────┐
   └──────────────┘                │ int 5   │  refcnt 被 cell 持有
                                   └─────────┘
   cell 保证了变量不随栈帧一起消失
```

判定一个函数是否闭包：`__closure__ is not None`。

| 概念 | 字节码指令 | 说明 |
|------|-----------|------|
| 局部变量 | `LOAD_FAST` | 数组索引，最快 |
| 闭包变量（内层读） | `LOAD_DEREF` | through cell，稍慢 |
| 闭包变量（外层） | `MAKE_CELL` / `STORE_DEREF` | 外层被捕获的变量升级为 cell |
| 全局变量 | `LOAD_GLOBAL` | 字典查找 |

## 5. 闭包延迟绑定陷阱

**最高频的 Python 面试陷阱题**，没有例外：

```python
funcs = []
for i in range(3):
    funcs.append(lambda: i)         # 捕获的是变量 i，不是 i 当时的值

print([f() for f in funcs])         # [2, 2, 2] —— 不是 [0, 1, 2]！
```

原因：**闭包捕获的是变量（cell），不是值**。循环结束时 `i` 已经是 2，三个 lambda 共享同一个 `i`。

三种修法：

```python
# 方案 1：默认参数（定义时求值，最常用）
funcs = [lambda i=i: i for i in range(3)]
print([f() for f in funcs])              # [0, 1, 2]

# 方案 2：functools.partial（语义更清晰）
from functools import partial
funcs = [partial(lambda x: x, i) for i in range(3)]

# 方案 3：额外一层工厂函数（每次调用产生独立作用域）
def make(i):
    return lambda: i
funcs = [make(i) for i in range(3)]
```

```python
# 变体：类方法里的同样问题
class Handler:
    def __init__(self):
        self.callbacks = []
        for name in ["a", "b"]:
            self.callbacks.append(lambda: print(name))   # 都打印 b
            # 修正：lambda name=name: print(name)
```

对照 Java：Java 的 lambda 要求捕获的局部变量 **effectively final**，编译期就禁止了这类写法——这是「静态约束 vs 动态灵活」的典型取舍。

> ⚠️ 这个陷阱在实际项目里高频出现于：注册回调、构建路由表、批量生成装饰器、Tkinter/PyQt 绑定按钮事件。看到「循环里创建函数」就要警觉。

## 6. 类作用域的特殊性

类体是一个**独立的、不参与 LEGB 嵌套链**的作用域。这导致几个反直觉行为：

```python
# 陷阱 1：方法内看不到类变量（必须用 self. 或 类名.）
class A:
    x = 1
    def show(self):
        # print(x)        # NameError！类作用域不是 enclosing scope
        print(self.x)     # ✅ 1
        print(A.x)        # ✅ 1
```

```python
# 陷阱 2：推导式 / 生成器表达式访问不到类变量
class B:
    values = [1, 2, 3]
    factor = 10
    # doubled = [v * factor for v in values]
    #   → NameError: name 'factor' is not defined
    #   原因：推导式自带一层函数作用域，跳过类作用域直接找全局
    #   注意 values 能访问是因为它作为「最外层可迭代对象」在类作用域求值

    doubled = [v * f for f in (factor,) for v in values]   # ✅ 变通写法
```

```python
# 陷阱 3：类体内可以引用先前定义的类变量（顺序执行）
class C:
    a = 1
    b = a + 1        # ✅ 2 —— 类体就是顺序执行的代码块
    print(locals())  # {'__module__':..., 'a': 1, 'b': 2}
```

| 作用域类型 | 参与 LEGB 链 | 说明 |
|-----------|:-----------:|------|
| 模块 | ✅ (G) | 全局命名空间 |
| 函数 | ✅ (L/E) | 可嵌套形成闭包 |
| **类** | ❌ | 只在类体执行期存在，之后变成类的 `__dict__` |
| 推导式/生成器表达式 | ✅ (L) | 自带一层隐式函数作用域 |
| 模块顶层的 `if`/`for`/`with` | — | 不产生新作用域（不同于 Java 的块作用域） |

```python
# Python 没有块级作用域
for i in range(3):
    pass
print(i)            # 2 —— 循环变量泄漏到外层（Java 里 i 已出作用域）

if True:
    tmp = 1
print(tmp)          # 1
```

> 💡 Python 3.12 起，推导式的实现被内联优化（PEP 709），但**作用域语义没变**——上面的陷阱 2 依然存在。

## 7. 名称重整与私有约定

Python 没有 `private`/`protected` 关键字，只有命名约定 + 一个编译期技巧。

| 写法 | 名称 | 实际效果 | 语义 |
|------|------|---------|------|
| `name` | 公开 | 无限制 | 公开 API |
| `_name` | 单下划线 | **无任何强制**，仅约定 | 内部使用，`import *` 不导出 |
| `__name` | 双下划线 | **名称重整**为 `_ClassName__name` | 避免子类意外覆盖 |
| `__name__` | 首尾双下划线 | 不重整 | 语言保留（魔术方法/属性） |

```python
class Base:
    def __init__(self):
        self.public = 1
        self._internal = 2       # 约定：别从外部动
        self.__private = 3       # 重整为 _Base__private

b = Base()
print(b.public, b._internal)     # 1 2  —— _internal 照样能访问
# print(b.__private)             # AttributeError
print(b._Base__private)          # 3    —— 重整后的真名，能访问
print(vars(b))                   # {'public':1,'_internal':2,'_Base__private':3}
```

```python
# 名称重整的真正用途：防止子类命名冲突，不是「安全」
class Parent:
    def __init__(self): self.__data = "parent"
    def show(self): print(self.__data)     # 编译期就绑死 _Parent__data

class Child(Parent):
    def __init__(self):
        super().__init__()
        self.__data = "child"              # 存成 _Child__data，互不干扰

Child().show()                             # parent —— 父类逻辑不被污染
```

> 🎯 结论：Python 的私有性是**「我们都是成年人」的约定**（consenting adults），靠文档和 `_` 前缀表达意图，不靠编译器强制。Java 转过来别指望 `__` 等于 `private`——它只是防冲突的重整，不是访问控制。

## 8. 核心要点回顾

- 命名空间本质是**名字到对象的字典**；`globals()` 可写，函数内 `locals()` 是快照
- 名字解析遵循 **LEGB**，且**编译期就静态确定**（`LOAD_FAST` vs `LOAD_GLOBAL`）
- 函数内**只要出现赋值**，该名字全函数视为局部 → `UnboundLocalError` 的成因
- `global` 指向模块级，`nonlocal` 指向最近外层函数；后者是写装饰器的常用工具
- 闭包 = 函数 + `cell` 对象；`__closure__` / `co_freevars` 可自省
- **延迟绑定陷阱**：循环里建闭包捕获的是变量不是值 → 用 `i=i` 默认参数固化
- **类作用域不参与 LEGB**：方法内要用 `self.x`；推导式看不见类变量
- Python **没有块级作用域**，`for`/`if` 的变量会泄漏到外层
- `__name` 是**名称重整**（防子类冲突），不是访问控制；私有性靠约定
