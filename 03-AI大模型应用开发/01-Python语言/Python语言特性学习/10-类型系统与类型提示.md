## 1. 注解的本质：运行时不生效

**这是最重要的一条**：类型注解只是存进 `__annotations__` 的元数据，解释器不检查、不转换、不报错。

```python
def add(a: int, b: int) -> int:
    return a + b

print(add("hello", "world"))     # helloworld  —— 运行时完全不报错！
print(add.__annotations__)       # {'a': int, 'b': int, 'return': int}
```

```python
# 变量注解也一样
x: int = "字符串"                 # 运行时合法
y: int                           # 只声明不赋值 → 不创建变量
# print(y)                       # NameError
print(__annotations__)           # {'x': int, 'y': int}  模块级注解字典
```

| 谁在用注解 | 用途 |
|-----------|------|
| **mypy / pyright** | 静态检查，CI 里拦住类型错误 |
| **IDE**（PyCharm/VSCode） | 自动补全、跳转、重构 |
| **Pydantic / FastAPI** | **运行时**读取注解做校验和序列化 |
| `dataclasses` | 生成 `__init__` 的字段列表 |
| 阅读者 | 最重要的一条：文档 |

```python
# 想在运行时拿到「解析后的」类型（处理字符串形式的前向引用）
from typing import get_type_hints
class Node:
    next: "Node | None"          # 字符串形式，避免 NameError
    value: int
print(get_type_hints(Node))      # {'next': Node | None, 'value': int}
print(Node.__annotations__)      # {'next': 'Node | None', 'value': int} ← 未解析
```

> 💡 Python 3.14 起 `from __future__ import annotations` 的行为成为默认（PEP 649/749），所有注解**延迟求值**，写前向引用不再需要加引号。3.13 及之前可以手动加这个 future import 获得同样效果。

## 2. 基础类型标注

```python
# 变量
name: str = "Tom"
age: int = 30
score: float = 95.5
active: bool = True
data: bytes = b"raw"

# 函数
def greet(name: str, times: int = 1) -> str:
    return f"Hi {name}! " * times

def log(msg: str) -> None:                    # 无返回值用 None
    print(msg)

def crash() -> "NoReturn":                    # 永不正常返回
    raise RuntimeError

# 类
class User:
    id: int                                   # 类级注解（dataclass 会读它）
    name: str
    def __init__(self, id: int, name: str) -> None:
        self.id, self.name = id, name
```

| 场景 | 写法 |
|------|------|
| 无返回值 | `-> None` |
| 永不返回（只抛异常/`sys.exit`） | `-> NoReturn` / `-> Never`（3.11+） |
| 任意类型（放弃检查） | `Any` |
| 未知类型（安全的 Any） | `object`（只能用 object 的方法） |
| 返回自身类型 | `-> Self`（3.11+，替代 `-> "MyClass"`） |

```python
from typing import Self
class Builder:
    def add(self, x: int) -> Self:            # 链式调用的正确标注
        return self
    @classmethod
    def create(cls) -> Self:                  # 子类调用时类型也正确
        return cls()
```

## 3. 容器与联合类型

### 3.1 内置泛型（3.9+ 推荐）

```python
# ✅ 3.9+ 直接用内置类型（PEP 585）
names: list[str] = ["a", "b"]
scores: dict[str, float] = {"a": 1.0}
pair: tuple[int, str] = (1, "a")
items: set[int] = {1, 2}
matrix: list[list[float]] = [[1.0]]

# ❌ 3.8 及之前的老写法（typing.List 等已废弃，但仍可用）
from typing import List, Dict
old: List[str] = []
```

```python
# tuple 的两种形态
fixed: tuple[int, str, bool] = (1, "a", True)      # 固定长度、每位类型不同
variable: tuple[int, ...] = (1, 2, 3, 4)           # 任意长度、同类型
```

### 3.2 联合类型与可选

```python
# ✅ 3.10+ 用 |（PEP 604）
def parse(x: str | int) -> float | None:
    ...

def find(uid: int) -> User | None:                 # 可能返回 None
    ...

# ❌ 老写法
from typing import Union, Optional
def parse_old(x: Union[str, int]) -> Optional[float]: ...
# Optional[X] 就是 X | None，不是「可选参数」的意思！
```

```python
# 常见误解：Optional 与「有默认值」无关
def f(a: int | None = None):        # 既可选，也可为 None ✅
def g(a: int | None):              # 必传，但可以传 None ✅
def h(a: int = 0):                 # 可选，但不能传 None ✅
```

### 3.3 可调用与迭代器

```python
from typing import Callable, Iterator, Iterable, Sequence, Mapping
from collections.abc import Callable as ABCCallable   # 3.9+ 推荐从 abc 导

# 函数类型
handler: Callable[[int, str], bool]        # (int, str) -> bool
noargs: Callable[[], None]                 # () -> None
anyargs: Callable[..., int]                # 任意参数 -> int

def apply(fn: Callable[[int], int], items: list[int]) -> list[int]:
    return [fn(x) for x in items]

# 生成器
def gen() -> Iterator[int]:                # 只 yield → 用 Iterator
    yield 1

from typing import Generator
def gen2() -> Generator[int, str, bool]:   # yield 类型, send 类型, return 类型
    x = yield 1
    return True
```

> 🎯 **参数用抽象类型，返回值用具体类型**。参数标 `Iterable[str]`/`Sequence[int]`/`Mapping[str, int]` 让调用方更自由；返回值标 `list[str]`/`dict[str, int]` 让使用方知道能做什么。这条原则等价于 Java 的「接受接口、返回实现」。

## 4. 泛型与 TypeVar

### 4.1 PEP 695 新语法（3.12+）

```python
# ✅ 3.12+ 简洁语法
def first[T](items: list[T]) -> T | None:
    return items[0] if items else None

class Stack[T]:
    def __init__(self) -> None:
        self._items: list[T] = []
    def push(self, item: T) -> None: self._items.append(item)
    def pop(self) -> T: return self._items.pop()

type Vector = list[float]                # 类型别名的新写法
type Pair[T] = tuple[T, T]               # 泛型别名

s: Stack[int] = Stack()
s.push(1)
# s.push("a")   ← mypy 报错
```

```python
# 3.11 及之前的写法
from typing import TypeVar, Generic
T = TypeVar("T")

def first(items: list[T]) -> T | None:
    return items[0] if items else None

class Stack(Generic[T]):
    def __init__(self) -> None: self._items: list[T] = []
```

### 4.2 约束与边界

```python
from typing import TypeVar

# ① 约束（constraints）：只能是列出的类型之一
AnyStr = TypeVar("AnyStr", str, bytes)
def concat(a: AnyStr, b: AnyStr) -> AnyStr:      # 两个参数必须同类型
    return a + b
concat("a", "b")        # ✅
concat(b"a", b"b")      # ✅
# concat("a", b"b")     # ❌ mypy 报错

# ② 边界（bound）：必须是该类型的子类
from numbers import Number
NumT = TypeVar("NumT", bound=Number)
def total(items: list[NumT]) -> NumT: ...

# 3.12+ 新语法
def concat2[S: (str, bytes)](a: S, b: S) -> S: return a + b    # 约束
def total2[N: Number](items: list[N]) -> N: ...                # 边界
```

### 4.3 协变与逆变

```python
from typing import TypeVar
T_co = TypeVar("T_co", covariant=True)      # 协变：只读容器
T_contra = TypeVar("T_contra", contravariant=True)   # 逆变：只写/消费者

# 直觉：
#   list[Dog] 不能当 list[Animal] 用（可变 → 不变，invariant）
#   Sequence[Dog] 可以当 Sequence[Animal] 用（只读 → 协变）
#   Callable[[Animal], None] 可以当 Callable[[Dog], None] 用（参数逆变）
```

| 概念 | 含义 | 例子 |
|------|------|------|
| 不变（invariant） | `C[Dog]` 与 `C[Animal]` 无关 | `list`、`dict`（可变容器） |
| 协变（covariant） | `Dog <: Animal ⟹ C[Dog] <: C[Animal]` | `Sequence`、`tuple`、返回值位置 |
| 逆变（contravariant） | `Dog <: Animal ⟹ C[Animal] <: C[Dog]` | `Callable` 的参数位置 |

> 💡 这套规则和 Java 的 `List<? extends T>` / `List<? super T>` 是同一套理论（PECS 原则）。日常写业务代码不用深究，写库的时候才需要。

## 5. Protocol 结构化子类型

```python
from typing import Protocol, runtime_checkable

class SupportsEmbed(Protocol):
    """任何有 embed 方法的对象都满足此协议——无需继承"""
    def embed(self, text: str) -> list[float]: ...

class Retriever(Protocol):
    def search(self, query: str, top_k: int = 5) -> list[str]: ...
    @property
    def name(self) -> str: ...              # 也能声明属性

def build_pipeline(embedder: SupportsEmbed, retriever: Retriever) -> None:
    ...                                     # mypy 会检查传入对象的结构

class OpenAIEmbedder:                       # 不继承任何东西
    def embed(self, text: str) -> list[float]: return [0.1]

build_pipeline(OpenAIEmbedder(), SomeRetriever())     # ✅ 结构匹配即可
```

```python
# runtime_checkable：让 isinstance 也能用（只检查方法是否存在，不检查签名）
@runtime_checkable
class Closeable(Protocol):
    def close(self) -> None: ...

print(isinstance(open("f.txt"), Closeable))    # True
```

| 对比 | ABC（名义） | Protocol（结构化） |
|------|-----------|------------------|
| 需要继承 | ✅ | ❌ |
| 检查时机 | 运行时（实例化） | 静态（mypy） |
| 能约束第三方类 | 需 `register()` | ✅ 天然 |
| `isinstance` | 默认支持 | 需 `@runtime_checkable`，且只查方法名 |
| 适用 | 项目内部框架骨架 | 库边界、依赖注入、对接外部 SDK |

> 🎯 AI 项目里对接多家模型 SDK（OpenAI / Anthropic / 本地 vLLM）时，用 Protocol 描述「我需要什么能力」比强迫所有 SDK 继承一个基类现实得多。

## 6. 特殊类型工具

```python
from typing import (Literal, Final, TypedDict, NamedTuple, Annotated,
                    overload, cast, TypeGuard, Never, ClassVar)

# ① Literal：限定为特定字面量
def set_mode(mode: Literal["train", "eval", "predict"]) -> None: ...
set_mode("train")          # ✅
# set_mode("test")         # ❌ mypy 报错

Device = Literal["cpu", "cuda", "mps"]

# ② Final：常量（不可重新赋值）
MAX_TOKENS: Final = 4096
class C:
    VERSION: Final[str] = "1.0"

# ③ ClassVar：类变量（dataclass 不会当成字段）
from dataclasses import dataclass
@dataclass
class Config:
    registry: ClassVar[dict] = {}          # 类级共享，不进 __init__
    name: str

# ④ TypedDict：给字典结构标类型（处理 JSON 时很有用）
class Message(TypedDict):
    role: Literal["system", "user", "assistant"]
    content: str

class RequestBody(TypedDict, total=False):     # total=False → 所有键可选
    model: str
    messages: list[Message]
    temperature: float

msgs: list[Message] = [{"role": "user", "content": "hi"}]

# ⑤ Annotated：给类型附加元数据（Pydantic/FastAPI 大量使用）
from typing import Annotated
Temperature = Annotated[float, "范围 0.0-2.0"]
def gen(temp: Annotated[float, "0-2"] = 0.7) -> str: ...

# ⑥ overload：同名不同签名（仅供检查器，实现只能有一个）
@overload
def parse(x: str) -> str: ...
@overload
def parse(x: int) -> int: ...
def parse(x): return x                     # 实际实现

# ⑦ TypeGuard：自定义类型收窄
def is_str_list(v: list[object]) -> TypeGuard[list[str]]:
    return all(isinstance(x, str) for x in v)

def process(items: list[object]) -> None:
    if is_str_list(items):
        print(items[0].upper())            # mypy 知道这里是 list[str]

# ⑧ cast：告诉检查器「相信我」（运行时零开销、零检查）
from typing import cast
data = cast(dict[str, int], json.loads(raw))
```

## 7. 静态检查工具链

| 工具 | 定位 | 特点 |
|------|------|------|
| **mypy** | 事实标准 | 生态最全、插件多（Django/SQLAlchemy），速度中等 |
| **pyright / Pylance** | 微软出品 | 极快（TS 实现）、VSCode 内置、推断更强 |
| **ty**（Astral） | 新一代 | Rust 实现，极快，与 ruff 同源，2026 年仍在快速迭代 |
| **ruff** | Linter/Formatter | 不做类型检查，但能查注解风格问题；替代 flake8+isort+black |

```bash
pip install mypy
mypy src/                          # 检查目录
mypy --strict src/                 # 最严格模式（新项目推荐直接上）
mypy --ignore-missing-imports .    # 忽略无 stub 的第三方库
```

```toml
# pyproject.toml —— 推荐配置
[tool.mypy]
python_version = "3.12"
strict = true                       # 打开全部严格开关
warn_unreachable = true
warn_return_any = true
show_error_codes = true
plugins = ["pydantic.mypy"]

[[tool.mypy.overrides]]             # 对无 stub 的库放宽
module = ["torch.*", "transformers.*"]
ignore_missing_imports = true

[tool.ruff]
line-length = 100
target-version = "py312"
[tool.ruff.lint]
select = ["E", "F", "I", "UP", "B", "SIM", "ANN"]   # ANN = 注解完整性检查
```

```python
# 局部屏蔽
x = some_untyped_call()      # type: ignore[no-any-return]
reveal_type(x)               # mypy 专用：打印它推断出的类型（运行时会 NameError）

from typing import TYPE_CHECKING
if TYPE_CHECKING:            # 只在检查时导入，避免循环导入 / 运行时开销
    from heavy_module import HeavyClass

def process(x: "HeavyClass") -> None: ...
```

| 渐进式引入策略 | 做法 |
|--------------|------|
| 第 1 步 | 新代码必须带注解，老代码不动（`--ignore-missing-imports`） |
| 第 2 步 | 核心模块开 `strict`，用 `overrides` 白名单放宽其余部分 |
| 第 3 步 | CI 里加 `mypy --strict`，禁止新增 `type: ignore` |
| 第 4 步 | 用 `--disallow-untyped-defs` 逐模块推进全覆盖 |

> ⚠️ 类型检查器**不是运行时保护**。外部输入（HTTP 请求、JSON 文件、LLM 返回的结构化数据）必须用 Pydantic 一类工具在运行时校验，注解本身挡不住任何脏数据。

## 8. Pydantic：运行时校验

Pydantic v2 用注解在**运行时**做校验和类型转换，核心引擎是 Rust 写的（比 v1 快 5-50 倍）。这是 FastAPI 的地基，也是 LLM 结构化输出的标准方案。

```python
from pydantic import BaseModel, Field, field_validator, model_validator, ConfigDict
from typing import Literal, Annotated

class LLMRequest(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=False, str_strip_whitespace=True)

    model: str = Field(..., min_length=1, description="模型名")
    prompt: str = Field(..., max_length=32000)
    temperature: float = Field(0.7, ge=0.0, le=2.0)
    max_tokens: int = Field(1024, gt=0, le=128000)
    stop: list[str] | None = None
    mode: Literal["chat", "completion"] = "chat"

    @field_validator("model")
    @classmethod
    def check_model(cls, v: str) -> str:
        allowed = {"claude-opus-5", "claude-sonnet-5", "gpt-4o"}
        if v not in allowed:
            raise ValueError(f"不支持的模型 {v}，可选：{allowed}")
        return v

    @model_validator(mode="after")
    def check_combo(self):
        if self.mode == "completion" and self.temperature > 1.0:
            raise ValueError("completion 模式下 temperature 不应超过 1.0")
        return self

# 校验 + 自动类型转换
req = LLMRequest(model="claude-opus-5", prompt="hi", temperature="0.9")
print(req.temperature, type(req.temperature))     # 0.9 <class 'float'>  ← 字符串自动转
print(req.model_dump())                            # → dict
print(req.model_dump_json())                       # → JSON 字符串

# 校验失败给出结构化错误
try:
    LLMRequest(model="unknown", prompt="", temperature=5)
except Exception as e:
    print(e)      # 逐字段列出 type / loc / msg
```

```python
# Annotated + 复用约束
from annotated_types import Ge, Le
Temperature = Annotated[float, Ge(0), Le(2)]
NonEmptyStr = Annotated[str, Field(min_length=1)]

class Config(BaseModel):
    temp: Temperature = 0.7
    name: NonEmptyStr
```

```python
# LLM 结构化输出的标准套路
class Entity(BaseModel):
    name: str
    type: Literal["PERSON", "ORG", "LOC"]
    confidence: float = Field(ge=0, le=1)

class ExtractResult(BaseModel):
    entities: list[Entity]
    summary: str

print(ExtractResult.model_json_schema())      # 生成 JSON Schema → 塞给模型的 tool 定义
result = ExtractResult.model_validate_json(llm_raw_output)    # 解析并校验模型输出
```

| 方案 | 运行时校验 | 类型转换 | 性能 | 适用 |
|------|:---------:|:-------:|------|------|
| 纯注解 + mypy | ❌ | ❌ | 零开销 | 内部代码 |
| `dataclass` | ❌ | ❌ | 快 | 内部数据容器 |
| `dataclass` + `__post_init__` 手写校验 | ✅ | 手写 | 快 | 简单场景 |
| **Pydantic** | ✅ | ✅ | 快（Rust core） | **API 边界、配置、LLM 输出** |
| `attrs` + validators | ✅ | 需 converter | 快 | 不想引入 Pydantic 时 |

```python
# pydantic-settings：从环境变量/.env 读配置并校验
from pydantic_settings import BaseSettings, SettingsConfigDict

class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=".env", env_prefix="APP_")
    api_key: str                        # 缺失则启动即报错，而非运行到一半才炸
    base_url: str = "https://api.anthropic.com"
    timeout: int = 30
    debug: bool = False

settings = Settings()                   # 读 APP_API_KEY / APP_BASE_URL ...
```

> 🎯 `dataclass` 与 Pydantic 的分工：**内部数据结构用 `dataclass`（零开销），系统边界用 Pydantic（校验一切外来数据）**。不要给内部高频对象套 Pydantic，校验开销会累积。

## 9. 核心要点回顾

- 注解**运行时完全不生效**，只是 `__annotations__` 里的元数据
- 3.9+ 用内置泛型 `list[str]`，3.10+ 用 `X | None` 代替 `Optional[X]`
- `Optional[X]` 表示「可以是 None」，与「参数可省略」无关
- **参数标抽象类型（`Iterable`/`Sequence`/`Mapping`），返回值标具体类型（`list`/`dict`）**
- 3.12+ 泛型新写法 `def f[T](...)` / `class C[T]` / `type Alias = ...`，不再需要 `TypeVar` + `Generic`
- `Protocol` = 结构化子类型，对接第三方 SDK 的首选；ABC = 名义子类型，适合项目内框架骨架
- `Self`（3.11+）标注链式调用和 `classmethod` 工厂
- `TypedDict` 给 JSON 结构标类型，`Literal` 限定枚举值，`Final` 声明常量
- `cast` 只影响检查器，运行时零作用；`TypeGuard` 才是可执行的类型收窄
- `if TYPE_CHECKING:` 导入只为注解服务的重型模块，避免循环导入
- 静态检查（mypy）与运行时校验（Pydantic）是两回事，**外部输入必须运行时校验**
- 内部数据用 `dataclass`，边界数据用 Pydantic
