## 1. 异步 HTTP：httpx vs aiohttp 选型

| 维度 | **httpx** | **aiohttp** |
|------|-----------|-------------|
| 定位 | 现代化 HTTP 客户端（requests 的异步继承者） | 全功能框架（客户端 + 服务端） |
| API 风格 | 与 requests 几乎一致（迁移成本低） | 专有 API |
| 连接复用 | AsyncClient 自动连接池 | ClientSession 连接池 |
| 特性 | HTTP/2、类型标注完善、可直接被 FastAPI TestClient 复用 | 流式/WebSocket 服务端能力强 |
| 生态现状（2026） | ⭐ 新项目首选 | 稳定维护，WebSocket 强项 |

> 🎯 **核心要点**：**写爬虫/API 调用 → httpx（首选）**；需要 WebSocket 双向或流式服务端 → aiohttp。requests 是同步基线；httpx 是它的异步直系后代，API 几乎可以照搬。

## 2. httpx 实战：连接复用与并发请求

### 2.1 客户端复用（最重要的一条）

```python
import asyncio
import httpx

# ❌ 反模式：每请求新建客户端（每次都要重建连接池/TLS 握手）
async def bad():
    for url in urls:
        r = await httpx.AsyncClient().get(url)     # 每次新建/销毁客户端

# ✅ 正解：复用 AsyncClient（连接池 + HTTP/2 + 超时配置一次到位）
async def good():
    limits = httpx.Limits(max_connections=100, max_keepalive_connections=20)
    timeout = httpx.Timeout(connect=5.0, read=15.0, write=15.0, pool=5.0)

    async with httpx.AsyncClient(
        limits=limits,
        timeout=timeout,
        headers={"User-Agent": "my-service/1.0"},
        follow_redirects=True,
    ) as client:
        async with asyncio.TaskGroup() as tg:
            tasks = [tg.create_task(fetch_one(client, u)) for u in urls]

async def fetch_one(client: httpx.AsyncClient, url: str):
    resp = await client.get(url)
    resp.raise_for_status()          # 4xx/5xx 抛异常
    return resp.json()
```

| 配置 | 作用 | 推荐值 |
|------|------|--------|
| `limits.max_connections` | 连接池上限 | 100-200 |
| `limits.max_keepalive_connections` | 复用空闲连接上限 | 20-50 |
| `timeout` | 连接/读/写/池四段超时 | connect 5s / read 15s |
| `follow_redirects` | 自动跟随 302 | True |
| `http2=True` | HTTP/2 多路复用 | 视目标支持 |

> 💡 **AsyncClient 要全局复用**：在 FastAPI 里用 lifespan 创建、存进 `app.state.client`（08 章）；在爬虫里用上下文管理器贯穿整个抓取会话——每次新建客户端 = 每次都丢连接池，性能差一个量级。

### 2.2 并发请求三形态

```python
# 形态一：顺序（慢）
results = [await client.get(u) for u in urls]

# 形态二：并发（gather）
results = await asyncio.gather(*(client.get(u) for u in urls))

# 形态三：并发 + 限流 + 背压（生产标准）
async def fetch_all(client, urls, concurrency=20):
    sem = asyncio.Semaphore(concurrency)
    async def one(u):
        async with sem:
            r = await client.get(u)
            r.raise_for_status()
            return r.json()
    async with asyncio.TaskGroup() as tg:
        tasks = [tg.create_task(one(u)) for u in urls]
    return [t.result() for t in tasks]
```

## 3. 异步数据库：asyncpg 与驱动选型

| 驱动 | 说明 | 适用 |
|------|------|------|
| **asyncpg** | PostgreSQL 最快的异步驱动（纯 C 加速） | 直连 PG、极致性能 |
| **SQLAlchemy async**（asyncpg 方言） | 2.0 官方异步 ORM | ⭐ FastAPI 生产首选（07 章详解） |
| aiomysql / asyncmy | MySQL 异步驱动 | MySQL 场景 |
| Datasette/sqlite 异步 | aiosqlite | SQLite 轻量场景 |

```python
import asyncio, asyncpg

async def main():
    # 连接池（生产必须，不能每请求新建连接）
    pool = await asyncpg.create_pool(
        "postgresql://user:pass@localhost/db",
        min_size=5, max_size=30,
        max_queries=5000,                    # 超量重编译预准备语句
        max_inactive_connection_lifetime=300,  # 空闲 5 分钟回收
        command_timeout=60,
    )

    async with pool.acquire() as conn:       # 用完自动归还（异常也归还）
        rows = await conn.fetch("SELECT * FROM users WHERE id = $1", 42)
        async with conn.transaction():       # 事务
            await conn.execute("UPDATE users SET name=$1 WHERE id=$2", "x", 42)

    await pool.close()
```

| 要点 | 说明 |
|------|------|
| **必须用连接池** | 每请求新建连接 = 性能灾难（500 RPS × 50ms = 25000 连接，PG 上限 200-500） |
| `acquire()` 上下文 | 自动归还连接，异常也归还 |
| `$1` 参数占位 | asyncpg 用 `$n` 而非 `%s` |
| 事务 | `async with conn.transaction()`，异常自动回滚 |
| 预编译 | asyncpg 自动预准备语句（max_queries 控制重编译） |

> ⚠️ 连接池参数三个铁律：`pool_pre_ping`（SQLAlchemy 侧）/`max_inactive_connection_lifetime`（asyncpg 侧）防死连接；池大小 × worker 数 ≤ 数据库 max_connections；`TooManyConnectionsError` = 池太大或连接泄漏（07 章排查表）。

## 4. Redis 异步客户端与缓存实战

```python
# redis-py 官方异步客户端（redis>=4.2 起）
import redis.asyncio as aioredis

async def main():
    r = aioredis.from_url("redis://localhost:6379/0", decode_responses=True)

    # 缓存读（防击穿：SETNX 加锁）
    cached = await r.get("user:42")
    if cached is None:
        # 回源数据库...
        await r.set("user:42", payload, ex=300)     # 5 分钟过期
    # 分布式锁（简单版；生产用 Redlock 或 Lua 脚本）
    if await r.set("lock:user:42", "1", nx=True, ex=10):
        try:
            await update_user()
        finally:
            await r.delete("lock:user:42")

    await r.aclose()
```

| API 形态 | 说明 |
|---------|------|
| `redis.asyncio` | 官方异步客户端（与同步客户端 API 同构，await 即可） |
| `from_url(..., decode_responses=True)` | 自动解码字节串 |
| `nx=True` | SETNX 原子占位（分布式锁/缓存防击穿） |
| 连接池 | 自动管理（默认池），lifespan 中建全局实例 |

> 💡 Redis 操作本来就是微秒级 IO，异步的意义是**取消 GIL 切换开销 + 事件循环内无阻塞**——高并发缓存服务（AI 应用、限流器）必须用异步客户端，同步客户端在高 QPS 下会显著拖慢事件循环。

## 5. 异步文件与杂项：aiofiles 等

```python
import aiofiles

async def write_log(path, content):
    async with aiofiles.open(path, "a", encoding="utf-8") as f:
        await f.write(content)          # 异步写文件（大文件/高频率日志）

# 常用异步工具速查
asyncio.to_thread(open, ...)            # 兜底：同步文件操作丢线程池
anyio.Path                          # 异步路径操作（aiofiles 作者的跨后端方案）
asyncio.subprocess                  # 异步子进程（比 subprocess 不阻塞）
```

| 操作 | 异步方案 | 何时必须异步 |
|------|---------|-------------|
| 大文件读写 | aiofiles / to_thread | 文件大或频率高（日志/上传下载） |
| 子进程 | `asyncio.create_subprocess_exec` | 执行外部命令（ffmpeg、git 等） |
| 系统调用/同步 SDK | `asyncio.to_thread` | 一切没有异步替代品的同步调用 |

## 6. 异步库兼容矩阵：同步 vs 异步对照

| 领域 | 同步（阻塞） | 异步（await） | 结论 |
|------|------------|--------------|------|
| HTTP | requests | **httpx** / aiohttp | 首选 httpx |
| PostgreSQL | psycopg2 | **asyncpg** / SQLAlchemy async | 首选 SQLAlchemy async |
| MySQL | pymysql | aiomysql / asyncmy | SQLAlchemy async 方言 |
| Redis | redis (sync) | **redis.asyncio** | 官方自带 |
| MongoDB | pymongo | motor | motor 官方 |
| ORM | SQLAlchemy sync | **SQLAlchemy 2.0 async** | 07 章 |
| 文件 | open() | aiofiles / to_thread | to_thread 兜底 |
| 消息队列 | pika | aio-pika | 需要时再看 |
| 无替代品 | 各种 SDK | `asyncio.to_thread` | **永远的最后手段** |

> 🎯 **核心要点**：选型顺序 = **真异步库优先（httpx/asyncpg/motor）→ 官方异步封装（redis.asyncio）→ to_thread 桥接（最后手段）**。注意：**别在 async 函数里调同步库**——那会让"异步服务"变成"带异步外衣的同步服务"（07 章 MissingGreenlet 一类的错误全因此而来）。

## 7. 异步错误处理与重试模式

```python
import asyncio, httpx

async def fetch_with_retry(client, url, retries=3, backoff=0.5):
    for attempt in range(retries):
        try:
            async with asyncio.timeout(10):
                resp = await client.get(url)
            if resp.status_code == 429:                 # 限流：退避重试
                await asyncio.sleep(backoff * (2 ** attempt))
                continue
            resp.raise_for_status()
            return resp
        except (httpx.TimeoutException, httpx.TransportError) as e:
            if attempt == retries - 1:
                raise
            await asyncio.sleep(backoff * (2 ** attempt))   # 指数退避
    raise RuntimeError(f"重试耗尽: {url}")
```

| 异常类型 | 来源 | 处理 |
|---------|------|------|
| `asyncio.TimeoutError` | asyncio.timeout | 重试或降级 |
| `httpx.TimeoutException` | 客户端超时配置 | 重试（注意幂等性） |
| `httpx.TransportError` | 连接层失败 | 重试 |
| `httpx.HTTPStatusError` | 4xx/5xx | 4xx 一般不重试（429 除外） |
| 业务错误 | 响应内容 | 业务层处理 |

> ⚠️ 重试纪律（与阶段 4/5 爬虫一致）：**写操作重试必须幂等**（唯一键/UUID 幂等键）；429 要读 `Retry-After` 头；重试要有上限 + 指数退避 + 抖动（jitter），否则风暴放大。

## 8. 核心要点

| 序号 | 要点 |
|:---:|------|
| 1 | HTTP 用 httpx（requests 的异步直系）；WebSocket 服务端才考虑 aiohttp |
| 2 | AsyncClient 全局复用（连接池）；并发三件套：信号量 + TaskGroup + 超时 |
| 3 | 数据库必须连接池（asyncpg / SQLAlchemy async），acquire 上下文自动归还 |
| 4 | Redis 用官方 redis.asyncio；nx=True 做缓存防击穿与分布式锁 |
| 5 | 文件/子进程/无异步替代的 SDK → aiofiles / asyncio.to_thread |
| 6 | 选型顺序：真异步库 → 官方异步封装 → to_thread 桥接 |
| 7 | 重试：指数退避 + 上限 + 幂等 + 429 读 Retry-After |
| 8 | 核心思想：**异步生态已成熟，一切 IO 都有 await 版本；to_thread 是兜底不是默认** |
