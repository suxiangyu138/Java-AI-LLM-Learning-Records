## 1. 依赖注入：为什么是 FastAPI 的灵魂

**依赖注入（DI）= 函数的依赖参数化**：端点不自己"找"会话/认证/配置，而是**声明需要什么**，框架负责注入。

```python
# 传统写法：每个端点自己创建/关闭连接（重复 + 难测）
@app.get("/users/{uid}")
def get_user(uid: int):
    db = create_connection()        # 端点自己造依赖
    try:
        return db.query_user(uid)
    finally:
        db.close()

# FastAPI 写法：声明依赖，框架注入
@app.get("/users/{uid}")
def get_user(uid: int, db: AsyncSession = Depends(get_db)):
    return await db.query_user(uid)     # db 哪来的？Depends(get_db) 注入
```

| 收益 | 说明 |
|------|------|
| 消除重复 | 认证/会话/配置只写一次 |
| 可测试 | 测试里替换依赖（依赖覆盖） |
| 可组合 | 依赖可以依赖依赖（树形组装） |
| 类型安全 | 注入对象带类型，IDE 全提示 |
| 自动文档 | OpenAPI 里可见安全方案 |

> 🎯 **核心要点**：把"每个端点都要的横切资源"（认证、数据库会话、当前用户、配置）做成依赖——**端点函数只表达业务，不管理资源**。

## 2. Depends 基础：函数依赖与可复用依赖

```python
from fastapi import Depends, FastAPI, Query

app = FastAPI()


# ① 最简单的依赖：函数返回注入值
async def get_pagination(
    page: int = Query(1, ge=1),
    size: int = Query(20, ge=1, le=100),
) -> tuple[int, int]:
    return page, size


# ② 依赖可以依赖依赖（树形）
async def get_current_user(
    auth: str = Depends(get_authorization),     # 认证依赖
    page: tuple[int, int] = Depends(get_pagination),
) -> User:
    ...


# ③ 端点使用：直接注入（依赖在端点执行前解析完毕）
@app.get("/users")
async def list_users(
    pagination: tuple[int, int] = Depends(get_pagination),
    user: User = Depends(get_current_user),
):
    page, size = pagination
    return {"page": page, "size": size, "user": user.name}
```

**依赖解析顺序（面试常问）**：路由匹配 → 依赖树**深度优先解析**（get_authorization → get_current_user → 端点）→ 依赖抛错则短路（认证失败直接 401，端点不执行）。

## 3. yield 依赖：资源生命周期（数据库会话）

**`yield` 依赖 = 进入时创建 + 退出时清理**（资源生命周期管理，Starlette 1.x 推荐方式）：

```python
from typing import AsyncGenerator
from fastapi import Depends


async def get_db() -> AsyncGenerator[AsyncSession, None]:
    async with AsyncSessionLocal() as session:      # 会话工厂（07 章）
        try:
            yield session                           # 注入给端点
            await session.commit()                  # 端点正常 → 提交
        except Exception:
            await session.rollback()                # 端点异常 → 回滚
            raise


@app.get("/users/{uid}")
async def get_user(uid: int, db: AsyncSession = Depends(get_db)):
    return await db.get(User, uid)
```

| yield 依赖要点 | 说明 |
|---------------|------|
| 创建在 yield 前 | 连接/会话在依赖进入时建立 |
| 清理在 yield 后 | **无论端点成败都执行**（异常时也走到清理） |
| 提交/回滚 | 成功 commit、异常 rollback（上例模式） |
| 异常传播 | 清理代码里的异常覆盖原异常（注意） |
| 测试替换 | 测试中 Depends 覆盖换成内存库/伪会话 |

> 🎯 **核心要点**：**所有"用完要还"的资源都用 yield 依赖**——数据库会话、HTTP 客户端、文件句柄。yield 后的代码是"确保执行"的清理段（类似上下文管理器），这是 FastAPI 里最常用的模式（07 章数据库全链路基于它）。

## 4. 依赖作用域与缓存

```python
from fastapi import Depends

# 默认：请求级缓存 —— 同一请求内多次 Depends(get_x) 只执行一次
@app.get("/a")
async def a(x: X = Depends(get_x), y: X = Depends(get_x)):
    # get_x 在本请求内只跑一次，x is y == True
    ...

# 需要每次都执行：use_cache=False
async def a(x: X = Depends(get_x, use_cache=False)):
    ...
```

| 作用域 | 行为 | 用途 |
|--------|------|------|
| 请求级（默认） | 同一请求内重复注入 = 缓存复用 | 认证/会话（只查一次） |
| 无缓存（use_cache=False） | 每次独立执行 | 计数器/日志类 |
| 全局单例 | lifespan 里建 app.state 资源 | 客户端/连接池（04 章 §5） |

> 💡 **不要用依赖做全局状态**：请求级缓存 ≠ 全局缓存。全局缓存/共享状态放 `app.state`（lifespan 创建），依赖只是"取用"它。

## 5. 认证方案全景：Session vs JWT vs OAuth2

| 方案 | 机制 | 适用 | 注意 |
|------|------|------|------|
| Session + Cookie | 服务端存会话，Cookie 存 ID | 传统 Web 应用 | 需 Redis 存会话、CSRF 防护 |
| **JWT（Bearer）** | 客户端持签名的 token | ⭐ 前后端分离/移动端/微服务 | 无状态、可撤销困难、防 XSS 窃取 |
| OAuth2 授权码 | 第三方授权协议 | 对接 GitHub/微信等 | 标准流程 + 回调 |
| API Key | 静态密钥 | 内部服务/爬虫接口 | 简单但可审计性差 |

> 🎯 **核心要点**：**自建 API 首选 JWT**（无状态、跨服务、移动端友好）；对接第三方登录用 OAuth2 授权码；纯内网服务用 API Key 就够。**安全基线**：JWT 走 HTTPS、短有效期（15min-2h）+ refresh token、密钥放环境变量。

## 6. JWT 认证完整实现

```python
# app/security.py —— JWT 全链路（生产模板）
import os
from datetime import datetime, timedelta, timezone
from typing import Annotated

import jwt
from fastapi import Depends, HTTPException, status
from fastapi.security import OAuth2PasswordBearer

SECRET_KEY = os.environ["JWT_SECRET"]              # 生产必须环境变量（≥32 字节随机）
ALGORITHM = "HS256"
ACCESS_TOKEN_EXPIRE = timedelta(hours=2)

oauth2_scheme = OAuth2PasswordBearer(tokenUrl="/auth/login")   # 声明 Bearer 方案


def create_token(user_id: int, role: str) -> str:
    payload = {
        "sub": str(user_id),
        "role": role,
        "iat": datetime.now(timezone.utc),
        "exp": datetime.now(timezone.utc) + ACCESS_TOKEN_EXPIRE,
    }
    return jwt.encode(payload, SECRET_KEY, algorithm=ALGORITHM)


async def get_current_user(
    token: Annotated[str, Depends(oauth2_scheme)],
) -> User:
    credentials_error = HTTPException(
        status_code=status.HTTP_401_UNAUTHORIZED,
        detail="认证失败",
        headers={"WWW-Authenticate": "Bearer"},     # ⚠️ 401 必须带此头
    )
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
        uid = int(payload["sub"])
    except jwt.PyJWTError:
        raise credentials_error
    user = await repo.get_user(uid)                 # 每次请求查库（或缓存）
    if user is None:
        raise credentials_error
    return user
```

```python
# app/routers/auth.py —— 登录端点
@app.post("/auth/login")
async def login(form: Annotated[OAuth2PasswordRequestForm, Depends()]):
    user = await repo.verify_credentials(form.username, form.password)
    if user is None:
        raise HTTPException(401, "用户名或密码错误")
    return {"access_token": create_token(user.id, user.role), "token_type": "bearer"}

# 受保护端点：只需声明依赖
@app.get("/me")
async def me(user: User = Depends(get_current_user)):
    return {"id": user.id, "name": user.name}
```

| JWT 安全要点 | 说明 |
|-------------|------|
| 密钥管理 | 环境变量/密钥系统，代码零明文 |
| 过期时间 | 2h 内（高频服务可 15min）+ refresh 机制 |
| 算法固定 | `algorithms=[ALGORITHM]` 防 alg 混淆攻击 |
| 401 响应头 | `WWW-Authenticate: Bearer` 是协议要求 |
| 载荷最小化 | 只放 sub/role/exp，**不放密码等敏感数据** |
| 可撤销方案 | 需要踢人时引入 token 版本号/黑名单（Redis） |

## 7. 角色权限与资源授权

```python
from typing import Annotated, Literal

Role = Literal["admin", "editor", "user"]


def require_role(required: Role):
    """依赖工厂：返回"检查角色的依赖"（闭包模式）"""
    async def checker(user: User = Depends(get_current_user)) -> User:
        if user.role != required and user.role != "admin":
            raise HTTPException(403, "权限不足")
        return user
    return checker


@app.get("/admin/stats")
async def admin_stats(_: Annotated[User, Depends(require_role("admin"))]):
    return {"secret": "..."}


# 资源级授权：看 owner 字段
@app.delete("/orders/{order_id}")
async def delete_order(
    order_id: int,
    user: Annotated[User, Depends(get_current_user)],
    db: AsyncSession = Depends(get_db),
):
    order = await db.get(Order, order_id)
    if order is None:
        raise HTTPException(404, "订单不存在")
    if order.owner_id != user.id and user.role != "admin":
        raise HTTPException(403, "只能操作自己的订单")     # IDOR 防护
    await db.delete(order)
    return {"ok": True}
```

| 授权层级 | 检查什么 | 典型错误 |
|---------|---------|---------|
| 认证 | 你是谁（token 有效性） | 401 |
| 角色 | 你的身份等级 | 403 |
| 资源 | 这个资源属于你吗 | 403（**IDOR** 漏洞高发点） |

> ⚠️ **越权（IDOR）是 API 最高频漏洞**（OWASP 2025 Top 10 上榜）：只做登录认证、不做资源归属校验 = 任何人都能操作别人的数据。**每个"操作具体资源"的端点都要查 owner**（上例 delete_order 的第三层检查）。

## 8. 认证安全基线

| # | 基线 | 说明 |
|:---:|------|------|
| 1 | 全站 HTTPS | 生产必须（证书/反代见 09 章） |
| 2 | 密钥环境变量化 | JWT_SECRET/DB 密码零明文 |
| 3 | 密码哈希 | bcrypt/argon2（**禁止**明文/MD5/SHA1） |
| 4 | 登录限流 | 失败次数限制 + 锁定（防爆破） |
| 5 | 短 token 有效期 | 2h + refresh；敏感操作二次校验 |
| 6 | 404/401 区分模糊 | 防用户枚举（"用户不存在" vs "密码错误"） |
| 7 | CORS 白名单 | 08 章：allowed_origins 精确配置 |
| 8 | 敏感字段过滤 | response_model 层杜绝密码 hash 泄漏（05 章） |
| 9 | 审计日志 | 登录/改密/删数据全记录（08 章 OTel） |

> 🎯 **核心要点**：认证 = "你是谁"（401），授权 = "你能干嘛"（403），**两者都要做、都要测**——多数被攻破的 API 不是认证破的，是授权漏的。

## 9. 核心要点

| 序号 | 要点 |
|:---:|------|
| 1 | DI 让端点"只声明、不管理"：认证/会话/配置全部依赖化 |
| 2 | 依赖树深度优先解析，依赖抛错即短路 |
| 3 | yield 依赖 = 资源生命周期（建→用→必清理）；DB 会话提交/回滚模式 |
| 4 | 默认请求级缓存；全局单例放 app.state |
| 5 | 自建 API 首选 JWT（无状态），对接三方用 OAuth2 |
| 6 | JWT 基线：环境变量密钥、短有效期、固定算法、WWW-Authenticate 头 |
| 7 | 三层授权：认证 401 / 角色 403 / 资源归属（防 IDOR） |
| 8 | 安全基线九条：HTTPS、密钥外置、bcrypt、限流、审计日志 |
