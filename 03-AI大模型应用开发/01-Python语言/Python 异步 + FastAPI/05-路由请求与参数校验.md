## 1. 参数三源：路径 / 查询 / 请求体

```python
from fastapi import FastAPI, Path, Query, Body

app = FastAPI()


@app.get("/items/{item_id}")
async def get_item(
    item_id: int = Path(ge=1, description="商品 ID"),          # ① 路径参数
    verbose: bool = Query(False, description="是否返回详情"),    # ② 查询参数
    lang: str = Query("zh", pattern=r"^(zh|en)$"),              # 查询参数带正则
):
    return {"item_id": item_id, "verbose": verbose, "lang": lang}


@app.post("/items")
async def create_item(
    payload: ItemIn = Body(...),                                 # ③ 请求体（Pydantic 模型）
    x_request_id: str | None = Header(None),                     # ④ 请求头
    debug: bool | None = Cookie(None, alias="debug_mode"),       # ⑤ Cookie
):
    return {"received": payload, "req_id": x_request_id}
```

| 数据源 | 声明方式 | 注意 |
|--------|---------|------|
| 路径参数 | 函数参数 + `Path()` | 类型转换失败 = 422（不是 404！） |
| 查询参数 | 默认值参数 + `Query()` | `?page=2&size=10` |
| 请求体 | Pydantic 模型 + `Body()` | JSON；单值用 `Body(...)` 包 |
| Header | `Header(None)` | 大小写不敏感，`-` 自动转 `_` |
| Cookie | `Cookie(None, alias=...)` | alias 指定原始名 |
| 文件上传 | `UploadFile` / `File()` | 08 章 |

> 🎯 **核心要点**：FastAPI 的魔法 = **"类型注解即校验"**。参数声明 = 文档（OpenAPI）+ 校验（422）+ 序列化三合一。工程上**所有入参都声明校验**（pattern/ge/le/枚举），坏数据在入口就被拦下，业务代码不用再防御。

## 2. Pydantic v2 请求模型

```python
from pydantic import BaseModel, Field, EmailStr
from datetime import datetime
from typing import Literal


class ItemIn(BaseModel):
    name: str = Field(min_length=2, max_length=64, description="商品名")
    price: float = Field(gt=0, le=100000, description="价格（分）")
    stock: int = Field(ge=0, default=0)
    tags: list[str] = Field(default_factory=list, max_length=10)
    status: Literal["on", "off"] = "on"          # 枚举字符串
    category_id: int | None = None               # 可选字段
    created_at: datetime | None = None           # 自动解析 ISO 时间

class ItemOut(BaseModel):                        # 响应模型（04 章 §1：0.130 走 Rust 序列化）
    id: int
    name: str
    price: float
```

| v2 特性 | 说明 |
|---------|------|
| 严格模式可选 | `model_config = ConfigDict(strict=True)` |
| 字段约束 | `Field(min_length/ge/le/pattern/max_length)` |
| 类型收紧 | `int | None`、`list[str]`、`Literal`、`datetime` 自动解析 |
| 自定义类型 | `EmailStr`（需 email-validator）、`UUID`、`Decimal` |
| 别名 | `Field(alias="sku_id")` + `populate_by_name=True` |

> ⚠️ 一个经典歧义：请求体 JSON 字段名与 Python 关键字/保留冲突时用 alias；**不要**用 `dict` 或 `Any` 接收请求体——校验全废、文档全废。

## 3. 校验规则：Field 约束与自定义校验

```python
from pydantic import BaseModel, Field, field_validator, model_validator


class OrderIn(BaseModel):
    coupon: str | None = None
    items: list[int] = Field(min_length=1)

    @field_validator("coupon")                        # 单字段校验
    @classmethod
    def normalize_coupon(cls, v):
        if v is None:
            return v
        v = v.strip().upper()
        if not v.startswith("CPN"):
            raise ValueError("优惠码格式错误")          # 抛 ValueError → 422
        return v

    @model_validator(mode="after")                    # 跨字段校验
    def check_total(self):
        if self.coupon and len(self.items) < 2:
            raise ValueError("优惠券至少需要 2 件商品")
        return self
```

| 校验层级 | 手段 | 触发时机 |
|---------|------|---------|
| 类型/约束 | 注解 + Field | 反序列化时 |
| 字段级 | `field_validator` | 该字段校验后 |
| 模型级 | `model_validator(mode="after")` | 全部字段校验后 |
| 依赖上下文 | Depends + Query（06 章） | 请求组装时 |

> 🎯 **核心要点**：**校验器里抛 `ValueError` = 返回 422 校验失败**；业务规则校验（库存不足、优惠券不可用）应放业务层抛 HTTPException（§5）——"格式错误"归 Pydantic，"业务不成立"归业务代码，职责分明。

## 4. 响应模型：response_model 与序列化

```python
@app.post("/items", response_model=ItemOut, status_code=201)
async def create_item(payload: ItemIn) -> ItemOut:
    # 内部数据可能含敏感字段（如 db 对象/密码 hash）
    return {"id": 1, "name": payload.name, "price": payload.price}

@app.get("/items/{item_id}", response_model=ItemOut)
async def get_item(item_id: int) -> ItemOut:
    return await repo.get(item_id)          # ORM 对象直接返回也能被序列化
```

**为什么必须写 response_model**（04 章 §1 的性能 + 安全双收益）：

| 收益 | 说明 |
|------|------|
| 性能 | 0.130 起走 Pydantic Rust 序列化，2 倍+ |
| 安全 | **自动过滤未声明字段**（防把密码/内部字段漏出去） |
| 文档 | OpenAPI 响应结构完整，前端可生成类型 |
| 类型保障 | 出参结构稳定，内部改动不影响契约 |

> ⚠️ 响应模型的两个坑：(1) 字段名必须匹配（dict 键与模型字段一致），否则静默缺字段；(2) `response_model_exclude_unset=True` 控制"未设置字段是否输出"——API 版本兼容常用 `exclude_none=True`。

## 5. 错误处理：HTTPException 与 422

```python
from fastapi import HTTPException, status


@app.get("/items/{item_id}")
async def get_item(item_id: int):
    item = await repo.get(item_id)
    if item is None:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail=f"商品 {item_id} 不存在",
            headers={"X-Error-Code": "ITEM_NOT_FOUND"},   # 自定义头（排查追踪）
        )
    return item
```

| 错误场景 | 状态码 | 处理方式 |
|---------|:---:|---------|
| 参数格式错误 | 422 | 自动（Pydantic），无需写代码 |
| 资源不存在 | 404 | `HTTPException(404, ...)` |
| 无权限/未认证 | 401/403 | 06 章安全依赖 |
| 业务冲突 | 409 | HTTPException |
| 第三方调用失败 | 502/504 | 08 章网关/重试 |
| 未捕获异常 | 500 | 08 章全局处理器 |

> 💡 422 vs 400 的约定：FastAPI 默认参数校验失败返回 **422**（Unprocessable Entity），与 Django REST/Spring 的 400 不同——联调文档以 422 为准。业务校验（如库存不足）按 REST 语义用 400/409。

## 6. v2 陷阱：Union 解析与类型转换

**0.128 纯 v2 时代最常踩的坑**：

```python
# ❌ v1 里能用的写法：int | str 联合 → v2 按"第一个匹配"策略，这里永远解析成 str
@app.get("/search")
async def search(q: int | str = 0):          # q="abc" 不报错、q=123 也变 str
    return {"q": q, "type": type(q).__name__}

# ✅ 正确姿势：用显式类型 + field_validator 做智能转换
@app.get("/search2")
async def search2(
    q: str = Query("", description="支持 id 或关键词"),
):
    q = q.strip()
    if q.isdigit():
        qid = int(q)                         # 显式转换分支
        return {"mode": "id", "value": qid}
    return {"mode": "keyword", "value": q}
```

| v2 行为 | 影响 | 对策 |
|---------|------|------|
| Union 含 str 时按 str 解析 | 数字查询参数被当字符串 | 显式 `Literal`/`str` + 手动转换 |
| 宽松模式默认开启 | `"123"` → int 自动转换 | 需严格时 `ConfigDict(strict=True)` |
| 校验错误信息聚合 | 一处多个错误 | 前端按 `detail[].loc` 定位 |

> ⚠️ 迁移提醒（0.126/0.128 破坏性）：老项目从 FastAPI 0.11x 升级到 0.128+，重点回归**联合类型参数、pydantic.v1 命名空间、自定义校验器**三块。

## 7. 参数校验工程规范

| 规范 | 说明 |
|------|------|
| 入参必声明 | 所有参数带类型 + 约束（含默认值） |
| 分页参数统一 | `page: int = Query(1, ge=1)` + `size: int = Query(20, ge=1, le=100)` |
| 枚举用 Literal | 别用自由字符串 |
| ID 用 int/UUID | 不用 str 裸收（防注入面） |
| 时间统一 datetime | 不手写字符串格式 |
| 响应必配 response_model | 性能 + 安全双收益 |
| 业务校验分层 | 格式 → Pydantic；业务 → 业务层 |
| 错误码可追踪 | headers 带 X-Error-Code（08 章日志关联） |

> 🎯 **核心要点**：**API 的边界就是校验的边界**——入口处拦下一切坏数据，业务代码就只剩"处理好事"一种路径。这是 FastAPI 体系里性价比最高的工程习惯。

## 8. 核心要点

| 序号 | 要点 |
|:---:|------|
| 1 | 参数三源 + Header/Cookie：类型注解 = 校验 + 文档 + 序列化 |
| 2 | Pydantic v2 模型：Field 约束 + field_validator + model_validator |
| 3 | 格式错误抛 ValueError → 422；业务不成立抛 HTTPException → 4xx |
| 4 | response_model 必写：Rust 序列化 2 倍 + 敏感字段自动过滤 |
| 5 | Union 含 str 在 v2 按 str 解析——显式类型 + 手动转换 |
| 6 | 校验分层：格式归 Pydantic，业务归业务层 |
| 7 | 0.128+ 迁移重点：联合参数、v1 命名空间、自定义校验器 |
