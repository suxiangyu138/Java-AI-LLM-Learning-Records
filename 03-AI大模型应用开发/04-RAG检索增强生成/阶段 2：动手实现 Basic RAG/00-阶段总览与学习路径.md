## 1. 本阶段定位

阶段 1 建立了概念地基，本阶段的目标是**亲手跑通最小闭环**：

```
阶段1 概念地基 → 阶段2 最小闭环（本阶段）→ 阶段3 调优 → 阶段4 高级
```

| 对比项 | 阶段 1 | 阶段 2 |
|---|---|---|
| 任务 | 理解 RAG 是什么 | 亲手实现一个能回答问题的 RAG |
| 产出 | 概念图、自测 | 本地可跑的代码 + 问答 Demo |
| 技术 | 零代码 | Python（主）+ Java（对照） |
| 验收 | 20 自测 ≥80% | 提问真实文档，答案有依据 |

### 毕业标准（先看目标再动手）

- [ ] 能用中文文档（如一篇产品说明）建库并正确问答
- [ ] 能讲清自己写的每一行代码在链路中的角色
- [ ] 能通过调 chunk_size / Top-K 观察回答质量变化
- [ ] 常见报错（模型下载/中文乱码/维度不符）能独立排查

## 3. 双技术栈说明

| 维度 | Python（主） | Java（对照） |
|---|---|---|
| 组件 | sentence-transformers + FAISS | Spring AI 2.0 + pgvector |
| 适用 | 原型快、AI 生态全 | 已有 Java 后端、企业生产 |
| LLM | DeepSeek API（OpenAI 兼容） | DeepSeek（OpenAI 兼容）+ QuestionAnswerAdvisor |
| 本阶段重点 | 全流程动手，理解每一步 | 看架构映射，掌握 Spring AI 的 RAG 自动装配 |

> 建议：**以 Python 为主理解原理**（每行代码都可见），Java 作为对照掌握企业实现（阶段 3/4 及生产以 Java 为主）。

## 5. 常见疑问快答

| 疑问 | 回答 |
|---|---|
| 必须用 GPU 吗？ | 不需要。BGE-small 在 CPU 上几十秒完成千级文档索引，问答秒级 |
| 必须用向量数据库吗？ | 本阶段 FAISS（内存库）足够；pgvector 在 05 篇作对照 |
| 必须连大模型 API 吗？ | 检索部分不需要；生成部分可先用免费/本地模型替代 |
| 为什么用 BGE 不用通用模型？ | 中文近义词相似度 0.72 → 0.95+（详见 04 篇数据） |
