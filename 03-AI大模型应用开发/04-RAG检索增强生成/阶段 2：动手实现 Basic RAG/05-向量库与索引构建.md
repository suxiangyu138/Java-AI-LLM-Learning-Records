## 1. FAISS 是什么

FAISS（Facebook AI Similarity Search）是 Meta 开源的向量相似度检索库：

| 维度 | 说明 |
|---|---|
| 定位 | 内存向量索引 + ANN（近似最近邻）搜索 |
| 形态 | 库（非服务），进程内使用 |
| 适用 | 单机、万级-千万级向量 |
| 特点 | 快（毫秒级）、支持 GPU、索引类型丰富 |

> 本阶段用 FAISS 的意义：**零部署**（pip 即用）且索引原理可见——理解 FAISS 后，换 Milvus/pgvector 只是换 API。

## 2. 索引类型选择

| 索引 | 类型 | 特点 | 适用 |
|---|---|---|---|
| IndexFlatIP | 暴力精确 | 精确检索、慢（万级可接受） | 小库、验证 |
| IndexHNSWFlat | 图索引 | 快、召回率高 | 本阶段推荐 |
| IndexIVFFlat | 倒排+量化 | 亿级扩展 | 大规模（阶段 3） |

```python
import faiss

dim = 1024  # BGE-large-zh 维度（必须与模型一致！）

# 方式一：精确索引（小库验证用）
index = faiss.IndexFlatIP(dim)

# 方式二：HNSW 图索引（推荐，万级以上快）
index = faiss.IndexHNSWFlat(dim, 32)   # 32 个邻居
index.hnsw.efConstruction = 40         # 建索引质量（越大越慢越准）
index.hnsw.efSearch = 64               # 检索深度（越大越慢越准）
```

> ⚠️ **维度铁律**：索引维度必须等于 Embedding 维度（bge-large-zh = 1024）。不一致会直接报错或静默错误。

## 3. 建库与持久化

```python
import numpy as np
import json

class VectorStore:
    def __init__(self, dim: int = 1024):
        self.index = faiss.IndexHNSWFlat(dim, 32)
        self.chunks: list[dict] = []   # 与向量一一对应：id → 切片+元数据

    def add(self, vectors: np.ndarray, chunks: list[dict]):
        """向量入库 + 记录元数据（顺序一一对应）"""
        assert vectors.shape[1] == self.index.d, "维度不一致！"
        self.index.add(vectors)
        self.chunks.extend(chunks)

    def save(self, index_path: str = "index.bin", meta_path: str = "chunks.json"):
        faiss.write_index(self.index, index_path)
        with open(meta_path, "w", encoding="utf-8") as f:
            json.dump(self.chunks, f, ensure_ascii=False, indent=2)

    def load(self, index_path: str = "index.bin", meta_path: str = "chunks.json"):
        self.index = faiss.read_index(index_path)
        with open(meta_path, "r", encoding="utf-8") as f:
            self.chunks = json.load(f)
```

持久化结构：

```
index.bin       # FAISS 索引（向量二进制）
chunks.json     # 元数据（与向量 id 顺序一一对应）
```

> 💡 关键心智：**FAISS 只存向量，不存文本**——检索返回的是向量 id，必须用元数据文件把 id 映射回原文。id 与 chunks 列表的**顺序对应**是必须守住的约定。

## 4. 检索 API

```python
def search(self, query_vec: np.ndarray, k: int = 5) -> list[dict]:
    """查询向量 → Top-K 相似 → 返回切片+相似度"""
    distances, ids = self.index.search(query_vec, k)
    results = []
    for dist, idx in zip(distances[0], ids[0]):
        if idx == -1:   # FAISS 空位标记
            continue
        results.append({
            "chunk": self.chunks[idx],
            "score": float(dist),   # 内积 = 余弦相似度（归一化后）
        })
    return results
```

| API | 说明 |
|---|---|
| index.add(vectors) | 入库（float32，二维矩阵） |
| index.search(qvec, k) | 检索 Top-K，返回 (距离, id) |
| index.ntotal | 库中向量总数 |
| faiss.write_index / read_index | 持久化/加载 |

## 5. pgvector 生产对照

生产环境（Java/多实例）用 PostgreSQL + pgvector 替代内存 FAISS：

```sql
-- 建表（Spring AI 自动迁移或手建）
CREATE TABLE document_chunks (
    id BIGSERIAL PRIMARY KEY,
    content TEXT NOT NULL,
    embedding vector(1024) NOT NULL,   -- 维度必须与模型一致
    metadata JSONB DEFAULT '{}'
);

-- HNSW 索引（pgvector 0.5+）
CREATE INDEX ON document_chunks
    USING hnsw (embedding vector_cosine_ops);

-- 检索 Top-K（余弦相似度）
SELECT content, 1 - (embedding <=> :query_vec) AS similarity
FROM document_chunks
ORDER BY embedding <=> :query_vec
LIMIT 5;
```

| 维度 | FAISS（本阶段） | pgvector（生产） |
|---|---|---|
| 形态 | 内存库 | 数据库表 |
| 文本与向量 | 分离（两份文件） | 同表（content + embedding） |
| 过滤 | 不支持 | SQL WHERE 过滤（元数据条件） |
| 多实例 | 不共享 | 天然共享 |
| 事务/备份 | 无 | ACID + 备份 |

> 🎯 核心要点：FAISS 与 pgvector 的对比本质是"**内存工具 vs 数据库方案**"——原型用 FAISS 理解原理，生产上 pgvector 的 SQL 过滤、事务、多实例共享都是硬需求。阶段 2 先跑通 FAISS，阶段 3 再上 pgvector 调优。
