## 1. 支持的格式与加载方式

| 格式 | 加载库 | 示例 |
|---|---|---|
| TXT / MD | 内置 open() | 最简单 |
| PDF | pypdf / pdfplumber | 合同、报告 |
| Word | python-docx | 内部文档 |
| HTML | BeautifulSoup | 网页、帮助中心 |
| CSV/JSON | csv/json | 结构化数据 |

### 代码示例：多格式统一加载

```python
from pathlib import Path

def load_text(path: Path) -> str:
    """统一入口：按扩展名分派加载器，返回纯文本"""
    suffix = path.suffix.lower()
    if suffix in (".txt", ".md"):
        return path.read_text(encoding="utf-8")
    elif suffix == ".pdf":
        from pypdf import PdfReader
        reader = PdfReader(str(path))
        return "\n".join(page.extract_text() or "" for page in reader.pages)
    elif suffix == ".docx":
        from docx import Document
        return "\n".join(p.text for p in Document(str(path)).paragraphs)
    elif suffix == ".html":
        from bs4 import BeautifulSoup
        return BeautifulSoup(path.read_text(encoding="utf-8"), "html.parser").get_text()
    else:
        raise ValueError(f"不支持的格式: {suffix}")
```

### 各格式的加载陷阱

| 格式 | 陷阱 | 对策 |
|---|---|---|
| PDF | 扫描件（图片型）extract_text 返回空 | 需要 OCR（阶段 3） |
| PDF | 表格提取后结构丢失 | 专用表格解析（pdfplumber 的 extract_table） |
| Word | 批注/修订混入正文 | 先另存为纯文本或用 python-docx 过滤 |
| HTML | 导航/广告噪音 | 先定位正文容器再提取（`article`/`main` 选择器） |
| CSV/JSON | 一行即一条记录，不适合按字符切片 | 按记录切块 + 保留结构化字段 |

> ⚠️ PDF 提取的坑：扫描件（图片型 PDF）extract_text 返回空——需要 OCR（阶段 3 处理）；表格型 PDF 提取后结构丢失（金融研报类注意）。

## 2. 文本清洗

清洗四步（核心代码）：

```python
import re

def clean_text(text: str) -> str:
    """四步清洗：统一空白 → 去控制字符 → 去多余空行 → 去行内噪音"""
    text = re.sub(r"\s+", " ", text)              # 1. 多空白统一为单空格
    text = re.sub(r"[\x00-\x08\x0b\x0c\x0e-\x1f]", "", text)  # 2. 去控制字符
    text = re.sub(r"\n{3,}", "\n\n", text)        # 3. 多余空行压缩
    text = re.sub(r"[​‎‏﻿]", "", text)   # 4. 去零宽字符/BOM
    return text.strip()
```

| 清洗项 | 处理内容 | 为什么 |
|---|---|---|
| 空白统一 | 全角/半角空格、制表符 | 切片边界稳定 |
| 控制字符 | \x00 等不可见字符 | 向量化前必须去除 |
| 零宽字符 | BOM、​ | 隐藏字符污染相似度 |
| 页眉页脚 | "第 X 页 / 公司内部资料" | 检索噪音（简单场景可手动正则去） |
| 超链接/图片说明 | markdown 链接语法 | 保留标题、去掉链接噪音 |

### 进阶清洗（按文档类型）

| 文档类型 | 额外清洗 |
|---|---|
| Markdown | 保留标题层级（`#` → 元数据 section），去掉代码块内噪音 |
| HTML | 去掉 script/style 标签内容、导航链接 |
| 报表类 | 保留表格结构（转成"字段：值"文本） |
| 代码文档 | 保留代码块本身（代码也是知识） |

> ⚠️ 清洗要克制：**只去掉影响检索的噪音，不要过度改写原文**——检索内容最终要展示给用户/模型，过度清洗会丢失原始信息。

## 3. 元数据设计

元数据 = 每个切片附带的结构化标签，检索后用于溯源与过滤：

```python
from dataclasses import dataclass

@dataclass
class Chunk:
    text: str           # 切片文本（向量化的对象）
    doc_id: str         # 所属文档 ID
    title: str          # 文档标题
    page: int           # 页码（PDF）
    section: str        # 章节
```

| 字段 | 用途 |
|---|---|
| doc_id | 溯源：答案指向哪份文档 |
| title / section | 引用标注：显示来源 |
| page | 定位：人工复核跳转 |
| updated_at | 增量更新判断 |

### 元数据设计原则

| 原则 | 说明 |
|---|---|
| 少而精 | 只存检索/溯源/过滤用得上的字段 |
| 可排序 | 时间、版本号等字段类型明确（排序过滤用） |
| 不存大文本 | 原文已经在 text 里，元数据只放标签 |
| 统一 schema | 多文档源共用一个字段结构（阶段 3 多库路由依赖它） |

> 💡 元数据是"免费的可解释性"——本阶段就带上，阶段 3 的过滤检索、溯源引用全部依赖它。

## 5. 加载质量自检

| 自检项 | 方法 | 达标 |
|---|---|---|
| 内容完整 | 对比原文与提取文本字数 | 缺失 <5% |
| 无乱码 | 抽查特殊字符（全角/引号/emoji） | 无 � |
| 结构保留 | 标题/段落分隔正确 | 可辨认章节 |
| 无噪音 | 页眉页脚/导航/广告已去除 | 无残留 |
| 编码统一 | 全部 UTF-8 | 无混合编码 |

### 自检脚本示例

```python
def audit_docs(data_dir: Path):
    """加载质量抽查：输出每个文档的字数与异常信号"""
    for path in data_dir.iterdir():
        raw = path.read_text(encoding="utf-8", errors="replace")
        text = clean_text(load_text(path))
        signals = []
        if "�" in text: signals.append("乱码")
        if len(text) < 50: signals.append("过短")
        if "第" in text and "页" in text and len(text) > 1000: signals.append("可能含页眉")
        print(f"{path.name}: 原文{len(raw)}字 → 清洗后{len(text)}字 {signals}")
```

## 6. 完整数据流水线示例

把 02 篇的零件串成一条可复用流水线：

```python
"""数据流水线：目录 → 加载 → 清洗 → 切片 → 元数据 → 落盘"""
import json
from pathlib import Path

def pipeline(data_dir: Path, out_path: Path) -> list[dict]:
    """一次跑完加载-清洗-切片-元数据，输出 chunks.json"""
    chunks = []
    for path in data_dir.iterdir():
        if path.suffix.lower() not in (".txt", ".md"):
            continue  # 扩展点：接入 PDF/HTML 加载器
        try:
            text = load_text(path)      # 1. 加载
            text = clean_text(text)     # 2. 清洗
        except Exception as e:
            print(f"[跳过] {path.name}: {e}")   # 坏文件不阻塞流水线
            continue
        pieces = fixed_chunk(text)      # 3. 切片
        for i, piece in enumerate(pieces):
            chunks.append({
                "text": piece,
                "meta": {"title": path.stem, "part": i, "updated_at": "2026-08-09"},
            })
    out_path.write_text(json.dumps(chunks, ensure_ascii=False, indent=2), encoding="utf-8")
    print(f"流水线完成：{len(chunks)} 块 → {out_path}")
    return chunks
```

### 流水线设计要点

| 设计点 | 为什么 |
|---|---|
| 坏文件跳过不中断 | 一个坏 PDF 不该毁掉整批 |
| 输出可重建 | 重新跑一遍得到相同结果（幂等） |
| 记录 updated_at | 增量更新的基础（阶段 3） |
| 单文件失败打印 | 可观测：知道哪些被跳过 |
| 元数据带 part | 溯源到"第几块" |

### 流水线测试方法

```
1. 放 1 个好文档 + 1 个坏文件（如 .pdf 扫描件）
2. 跑流水线 → 好文档入库，坏文件打印跳过
3. 检查 chunks.json 结构完整、无乱码
4. 重跑一遍 → 结果一致（幂等验证）
```

> 🎯 核心要点：**文档加载与清洗是 RAG 里最"脏"但最决定质量的环节**——解析失败、清洗不干净，后面切片和检索都会放大问题。宁可加载慢一点，不要脏数据进库。用"流水线 + 坏文件跳过 + 幂等"组织数据准备，后续阶段直接复用。
