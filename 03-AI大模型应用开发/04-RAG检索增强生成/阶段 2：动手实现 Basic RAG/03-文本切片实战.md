## 1. 切片的核心权衡

| 切片大小 | 优点 | 缺点 |
|---|---|---|
| 过大（1000+ token） | 语义完整、上下文信息足 | 检索粒度粗、单块噪音多、浪费上下文 |
| 过小（100- 字符） | 定位精准 | 语义被切断、上下文碎片化（阶段 1 的"碎片化"痛点） |
| 适中（300-512 字符） | 语义完整 + 定位够准 | 需按文档类型微调 |

核心矛盾：**切片是"定位精度"与"语义完整"的平衡**——同一知识库，不同文档类型最优切片不同。

## 2. 三种切片实现

### 2.1 固定滑动窗口（入门）

```python
def fixed_chunk(text: str, chunk_size: int = 300, overlap: int = 50) -> list[str]:
    """按字符数滑动窗口切块，overlap 保留边界语义"""
    chunks = []
    start = 0
    while start < len(text):
        chunks.append(text[start:start + chunk_size])
        start += chunk_size - overlap
    return chunks
```

- 优点：实现 5 行、速度极快
- 缺点：**感知不到语义边界**——可能把一句话从中间切开

### 2.2 递归字符切片（推荐入门用）

按"段落 → 句子 → 词"层级递归切分，优先在语义边界断开：

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,        # 目标块大小（字符）
    chunk_overlap=80,      # 重叠
    separators=["\n\n", "\n", "。", "！", "？", "，", " ", ""],
    length_function=len,
)

chunks = splitter.split_text(clean_text)
```

- 分隔符按优先级尝试：先按段落断，不够小再按句子断——**断裂点尽量落在语义边界**
- 适合 80% 场景，中文注意把标点加入分隔符

### 2.3 语义切块（BGE 相似度断点）

按段落单元计算相邻语义相似度，相似度低处即主题切换点：

```python
import numpy as np

def semantic_chunk(text: str, model, threshold: float = 0.55) -> list[str]:
    """按空行拆段落 → BGE 算相邻段落相似度 → 低相似处为断点"""
    paragraphs = [p.strip() for p in text.split("\n\n") if p.strip()]

    if len(paragraphs) <= 1:
        return paragraphs or [text]

    vecs = model.encode(paragraphs, normalize_embeddings=True)
    sims = np.array([np.dot(vecs[i], vecs[i + 1]) for i in range(len(vecs) - 1)])

    chunks, current = [], []
    for i, para in enumerate(paragraphs):
        current.append(para)
        if i < len(sims) and sims[i] < threshold:
            chunks.append("\n\n".join(current))  # 主题切换，收尾当前块
            current = []
    if current:
        chunks.append("\n\n".join(current))
    return chunks
```

- 优点：**感知主题边界**，长文档质量最好
- 代价：需要一次额外 Embedding 计算
- 适用：Markdown 结构清晰的长文档、研究报告

## 3. 关键参数与实验

### 参数速查

| 参数 | 本阶段推荐 | 影响 |
|---|---|---|
| chunk_size | 300-512 字符 | 检索粒度 + 上下文占用 |
| chunk_overlap | 50-100 字符（约 15-20%） | 边界语义连续性 |
| 分隔符顺序 | 段落 > 句子 > 标点 > 空格 | 断点质量 |

### 实验模板（感受参数影响）

```python
for size in [200, 400, 800]:
    chunks = fixed_chunk(clean_text, chunk_size=size, overlap=int(size * 0.2))
    print(f"size={size}: {len(chunks)} 块, 平均 {sum(len(c) for c in chunks) / len(chunks):.0f} 字符")
    # 再打印第 2 块，肉眼检查断点是否在语义完整处
```

观察点：

1. 块数随 size 增大而减少（预期）
2. **断点质量**：size=800 时断点更完整，size=200 时可能出现"一句话被切开"
3. 回答质量：对同一问题分别用不同切片建库，看哪个答案更完整

## 4. 切片质量自检法

| 自检项 | 方法 | 达标 |
|---|---|---|
| 断点完整性 | 随机抽 5 块，看是否从句子中间开始 | 无截断句子 |
| 主题纯度 | 单块是否混杂多个无关主题 | 每块单一主题 |
| 信息完整性 | 关键实体/数字是否在块内完整 | 数字不跨块断裂 |
| 覆盖率 | 全部块拼接 ≈ 原文档 | 内容零丢失 |

> 🎯 核心要点：切片没有"最优参数"，只有"匹配文档"——先固定窗口跑通，再按文档类型选递归/语义切块。**自检法是本阶段的真正产出**：能判断切得好不好，调优才有方向（阶段 3 深化）。
