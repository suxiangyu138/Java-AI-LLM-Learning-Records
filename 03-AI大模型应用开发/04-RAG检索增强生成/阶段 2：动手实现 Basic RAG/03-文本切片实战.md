## 1. 切片的核心权衡

| 切片大小 | 优点 | 缺点 |
|---|---|---|
| 过大（1000+ token） | 语义完整、上下文信息足 | 检索粒度粗、单块噪音多、浪费上下文 |
| 过小（100- 字符） | 定位精准 | 语义被切断、上下文碎片化（阶段 1 的"碎片化"痛点） |
| 适中（300-512 字符） | 语义完整 + 定位够准 | 需按文档类型微调 |

核心矛盾：**切片是"定位精度"与"语义完整"的平衡**——同一知识库，不同文档类型最优切片不同。

### 为什么切片这么重要（量化视角）

| 场景 | 影响 |
|---|---|
| 切片太碎 | 答案所需的上下文被拆散 → 检索命中 3 个碎片拼不齐 → 答案残缺 |
| 切片太大 | 单块 2000 字只命中其中 50 字有效 → Top-K 占满上下文 → 噪音挤压有用信息 |
| 切点不好 | "价格是 100 元"被切成两半 → 数字信息断裂（阶段 1 自检法的典型场景） |

## 2. 三种切片实现

### 2.1 固定滑动窗口（入门）

```python
def fixed_chunk(text: str, chunk_size: int = 300, overlap: int = 50) -> list[str]:
    """按字符数滑动窗口切块，overlap 保留边界语义"""
    chunks = []
    start = 0
    while start < len(text):
        chunks.append(text[start:start + chunk_size])
        start += chunk_size - overlap
    return chunks
```

- 优点：实现 5 行、速度极快
- 缺点：**感知不到语义边界**——可能把一句话从中间切开

### 2.2 递归字符切片（推荐入门用）

按"段落 → 句子 → 词"层级递归切分，优先在语义边界断开：

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,        # 目标块大小（字符）
    chunk_overlap=80,      # 重叠
    separators=["\n\n", "\n", "。", "！", "？", "，", " ", ""],
    length_function=len,
)

chunks = splitter.split_text(clean_text)
```

- 分隔符按优先级尝试：先按段落断，不够小再按句子断——**断裂点尽量落在语义边界**
- 适合 80% 场景，中文注意把标点加入分隔符

**分隔符优先级原理**：

```text
输入 3000 字文档，目标 500 字/块：
① 优先按 \n\n（段落）切 → 一段 300 字：收下
② 段落超过 500 字 → 按 \n（行）再切
③ 还超 → 按 。！？（句子）切
④ 还超 → 按 ，（短语）切 → 空格 → 硬切
```

### 2.3 语义切块（BGE 相似度断点）

按段落单元计算相邻语义相似度，相似度低处即主题切换点：

```python
import numpy as np

def semantic_chunk(text: str, model, threshold: float = 0.55) -> list[str]:
    """按空行拆段落 → BGE 算相邻段落相似度 → 低相似处为断点"""
    paragraphs = [p.strip() for p in text.split("\n\n") if p.strip()]

    if len(paragraphs) <= 1:
        return paragraphs or [text]

    vecs = model.encode(paragraphs, normalize_embeddings=True)
    sims = np.array([np.dot(vecs[i], vecs[i + 1]) for i in range(len(vecs) - 1)])

    chunks, current = [], []
    for i, para in enumerate(paragraphs):
        current.append(para)
        if i < len(sims) and sims[i] < threshold:
            chunks.append("\n\n".join(current))  # 主题切换，收尾当前块
            current = []
    if current:
        chunks.append("\n\n".join(current))
    return chunks
```

- 优点：**感知主题边界**，长文档质量最好
- 代价：需要一次额外 Embedding 计算
- 适用：Markdown 结构清晰的长文档、研究报告

### 三种切片对比总表

| 方法 | 复杂度 | 质量 | 速度 | 适用 |
|---|---|---|---|---|
| 固定窗口 | ★ | ★★ | 最快 | 验证、纯文本 |
| 递归字符 | ★★ | ★★★ | 快 | 通用默认 |
| 语义切块 | ★★★ | ★★★★ | 慢（多一次编码） | 长文档、研究报告 |

## 3. 关键参数与实验

### 参数速查

| 参数 | 本阶段推荐 | 影响 |
|---|---|---|
| chunk_size | 300-512 字符 | 检索粒度 + 上下文占用 |
| chunk_overlap | 50-100 字符（约 15-20%） | 边界语义连续性 |
| 分隔符顺序 | 段落 > 句子 > 标点 > 空格 | 断点质量 |

### 实验模板（感受参数影响）

```python
for size in [200, 400, 800]:
    chunks = fixed_chunk(clean_text, chunk_size=size, overlap=int(size * 0.2))
    print(f"size={size}: {len(chunks)} 块, 平均 {sum(len(c) for c in chunks) / len(chunks):.0f} 字符")
    # 再打印第 2 块，肉眼检查断点是否在语义完整处
```

观察点：

1. 块数随 size 增大而减少（预期）
2. **断点质量**：size=800 时断点更完整，size=200 时可能出现"一句话被切开"
3. 回答质量：对同一问题分别用不同切片建库，看哪个答案更完整

## 4. 切片质量自检法

| 自检项 | 方法 | 达标 |
|---|---|---|
| 断点完整性 | 随机抽 5 块，看是否从句子中间开始 | 无截断句子 |
| 主题纯度 | 单块是否混杂多个无关主题 | 每块单一主题 |
| 信息完整性 | 关键实体/数字是否在块内完整 | 数字不跨块断裂 |
| 覆盖率 | 全部块拼接 ≈ 原文档 | 内容零丢失 |

### 自检脚本

```python
import re

def audit_chunks(chunks: list[str], original: str) -> dict:
    """四维自检：断点/纯度/信息/覆盖"""
    # 断点：抽查块首是否以句号类标点开头（应避免）
    bad_starts = [c[:10] for c in chunks if re.match(r"^[，。；、]", c)]
    # 覆盖：拼接后与原文字符数对比
    joined = "".join(chunks)
    return {
        "块数": len(chunks),
        "疑似截断起点": bad_starts[:3],
        "覆盖率": f"{len(joined)}/{len(original)} = {len(joined) / max(len(original), 1):.1%}",
    }
```

## 5. 切片的常见误区

| 误区 | 正解 |
|---|---|
| chunk_size 越大越好 | 大块语义完整但噪音多——追求"够用的小块" |
| overlap 越大越好 | 重叠是重复 token——15-20% 平衡，别超 50% |
| 一种切片走天下 | 按文档类型选：FAQ 小块、长报告语义切块 |
| 切片后不检查 | 必须跑自检法——切坏了检索必坏 |
| 数字/表格被切断 | 特殊内容（表格、公式）单独处理或整体保留 |

### 特殊内容的切片策略（提前了解）

| 内容 | 策略 |
|---|---|
| 表格 | 整表一块（不切断行） |
| 代码块 | 代码块整体保留 |
| 长数字序列 | 不可切——切了必碎 |
| 标题+正文 | 标题随正文（元数据记 section） |

## 6. 切片选择决策树

```
我的文档是什么类型？
├─ 纯文本（无结构）→ 固定窗口 / 递归切片
├─ Markdown/结构化 → 递归切片（保留标题层级）
├─ 长报告（研究报告/论文）
│   ├─ 结构清晰 → 语义切块（主题断点）
│   └─ 结构混乱 → 递归切片 + overlap 加大
├─ FAQ/条目型 → 每条目一块（按空行切）
├─ 表格密集（报表）→ 整表一块 + 特殊处理
└─ 代码文档 → 代码块整体保留 + 注释跟随
```

### 文档类型 × 参数速查

| 文档类型 | 首选方法 | chunk_size | overlap |
|---|---|---|---|
| 产品说明/FAQ | 递归切片 | 300-400 | 15% |
| 研究报告 | 语义切块 | 500-800 | 10% |
| 合同/法规 | 递归切片（按条款） | 200-400 | 20% |
| 代码文档 | 递归 + 代码保护 | 300-500 | 10% |
| 聊天记录 | 按对话轮次 | 100-200 | 0% |

### 参数调优的正确顺序（阶段 3 会深化）

```
1. 先定"方法"（固定/递归/语义）→ 2. 再定 size → 3. 后定 overlap
不要同时改多个参数——一次只改一个，记录效果
```

> 🎯 核心要点：切片没有"最优参数"，只有"匹配文档"——先固定窗口跑通，再按文档类型选递归/语义切块。**自检法是本阶段的真正产出**：能判断切得好不好，调优才有方向（阶段 3 深化）。选型先定方法、再定 size、后定 overlap。
