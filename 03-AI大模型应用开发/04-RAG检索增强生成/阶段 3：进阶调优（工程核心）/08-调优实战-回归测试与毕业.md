## 1. 实战：一轮完整的调优闭环

### 实战设定

- 系统：阶段 2 的 rag.py（基线）
- 测试集：30 问（含多轮、口语、精确词三类）
- 目标：端到端质量提升 ≥20%，且每层收益可归因

### 闭环六步（本实战照做）

```
① 量基线：跑测试集，记录四指标
② 定位瓶颈：faithfulness/precision/recall 拆开看
③ 选工具：按瓶颈选层（查询/检索/排序/数据）
④ 逐层叠加：一次一层，每层跑评估
⑤ 填累积提升表：只留指标上升的层
⑥ 回归与收尾：全量回归 + 记录决策
```

### 实战记录（示例，供对照）

| 步骤 | 配置 | context precision | context recall | faithfulness | 成本/查询 |
|---|---|---|---|---|---|
| 基线 | 纯向量 Top-5 | 0.60 | 0.55 | 0.92 | 0.010 |
| +查询改写 | 多轮指代消解 | 0.63 | 0.58 | 0.92 | 0.012 |
| +混合检索 | BM25+向量 RRF | 0.65 | 0.75 | 0.93 | 0.012 |
| +Rerank | bge-reranker-v2-m3 | 0.78 | 0.72 | 0.94 | 0.013 |
| +上下文精炼 | 截断+去重 | 0.78 | 0.72 | 0.95 | 0.010 |
| +父子索引 | 小块检索大块生成 | 0.80 | 0.78 | 0.95 | 0.011 |

**决策**：保留全部 5 层（每层指标上升）；若某层下降 → 撤掉。

### 实战要点

| 要点 | 说明 |
|---|---|
| 一次一层 | 同时改两层，指标无法归因 |
| 记录一切 | 配置、指标、成本都进表 |
| 怀疑直觉 | "感觉变好了"不作数，指标说话 |
| 关注成本 | 质量提升 20% 但成本翻倍 → 需要权衡 |

## 2. 累积提升表（黄金工具）

### 什么是累积提升表

在固定语料、固定测试集上，从最简配置开始逐层叠加，**每层只保留真正带来收益的部分**：

```
BM25 alone → dense alone → hybrid(RRF) → +reranker → +HyDE
每层测量：Recall@5 / MRR / 端到端指标
```

### 为什么叫"累积"

| 层 | 配置 | 指标 | 增量 | 保留？ |
|---|---|---|---|---|
| L0 | 基线 | 0.55 | — | 是 |
| L1 | +混合 | 0.72 | +0.17 | 是 |
| L2 | +Rerank | 0.80 | +0.08 | 是 |
| L3 | +HyDE | 0.65 | **-0.15** | **否（撤掉）** |

### 累积提升表的三个纪律

1. **每层独立评估**：新层与"当前最优配置"对比（不是与基线）
2. **只留正收益**：负收益层立即撤掉（如上面的 HyDE）
3. **记录代价**：延迟/成本也要进表（收益小代价大也撤）

### 填表模板

| 层 | 配置 | 检索指标 | 端到端 | 延迟 | 成本 | 保留 |
|---|---|---|---|---|---|---|
| L0 | 基线 | | | | | 是 |
| L1 | +改写 | | | | | |
| L2 | +混合 | | | | | |
| L3 | +Rerank | | | | | |
| L4 | +精炼 | | | | | |
| L5 | +父子 | | | | | |

## 3. 回归测试体系

### 回归测试的目标

```
防止"修好 A 弄坏 B"：
每次改动（代码/参数/数据）→ 跑全量测试集 → 指标不降
```

### 三层回归

| 层 | 内容 | 频率 |
|---|---|---|
| 单元回归 | 检索/评估函数正确性 | 每次提交 |
| 质量回归 | 测试集四指标 | 每次 PR（CI 门禁） |
| 数据回归 | 治理指标（06 篇） | 每次索引更新 |

### CI 门禁配置（示例）

```
每次 PR：
  ① 跑测试集 → 四指标 ≥ 阈值 → 不达标 CI 失败
  ② 基线对比 → 指标下降 > 5% → CI 失败
  ③ 跑通冒烟测试（3 个核心问题）
```

### 回归测试的坑

| 坑 | 对策 |
|---|---|
| 测试集与训练同源 | 测试集独立于调优过程 |
| 指标波动误判 | 跑 2-3 次取均值 |
| 只测质量不测延迟 | 加延迟回归（P95） |
| 测试集不更新 | 新场景持续扩充 |

## 4. 调优决策的复盘框架

### 复盘四问（每次调优后）

```
① 我改了什么？（配置变更记录）
② 指标变化是什么？（数据）
③ 为什么变？（归因：哪层起的作用）
④ 值得保留吗？（收益 vs 代价）
```

### 决策记录模板

```markdown
## 调优记录 2026-08-09
- 改动：混合检索权重 BM25:0.4 / Dense:0.6
- 指标：recall 0.55→0.75，precision 0.60→0.65
- 归因：精确词查询召回率大幅提升（BM25 补盲区）
- 代价：检索延迟 +20ms（可接受）
- 结论：保留，权重扫描确认 0.4/0.6 最优
```

### 复盘的价值

- 团队协作：别人能看懂你的调优历史
- 避免重复踩坑：三个月后回看"当时为什么这么选"
- 面试素材：完整的调优闭环案例是最佳项目故事

## 5. 20 道自测题

### 评估与流程（1-6）

1. RAGAS 四指标是哪四个？各自衡量什么？
2. 哪个指标需要 ground truth？为什么？
3. faithfulness 高但 context precision 低，瓶颈在哪？
4. 测试集最少要多少问题？为什么？
5. 累积提升表的三个纪律？
6. LLM-as-judge 的两个已知陷阱？

### 查询与检索（7-13）

7. 查询改写主要解决什么问题？（指代/口语/不完整）
8. Multi-Query 的代价是什么？
9. HyDE 的原理是什么？为什么"有时更好"？
10. BM25 擅长什么？向量检索擅长什么？
11. RRF 融合为什么不需要归一化分数？
12. 混合检索初召回为什么取 50 而不是 10？
13. 混合检索最常见的错误是什么？（两路不同分块集合）

### 排序与数据（14-17）

14. Bi-Encoder 与 Cross-Encoder 的区别？
15. 什么指标形态说明"需要 Rerank"？（Recall@50 好但 Recall@5 差）
16. 父子文档索引解决什么矛盾？（精度 vs 完整）
17. 元数据过滤的作用？过滤为空怎么办？（回退）

### 工程与治理（18-20）

18. 增量更新的核心思路？（只处理变化文档）
19. 三级缓存是哪三级？收益最大的是哪级？
20. 知识库治理四维度指标？（新鲜度/完整/质量/时效）

### 参考答案（简版）

1. Faithfulness（忠实）/Answer Relevancy（切题）/Context Precision（精度）/Context Recall（召回）
2. Context Recall——需要参考答案判断知识点覆盖
3. 检索层瓶颈——召回的块排序/相关性有问题
4. 30-50 起步——太少波动大，无法区分改动效果
5. 独立评估/只留正收益/记录代价
6. 同族互评虚高 5-12 分；judge 版本漂移
7. 补全指代、统一术语、让查询可独立检索
8. 检索次数×(n+1) + 一次 LLM 调用
9. 用"假设答案文档"向量检索，缩小查询-文档分布差异；词汇不匹配时才有效
10. BM25 精确词/型号/人名；向量语义/同义
11. 只看排名不看分数，天然免尺度问题
12. 候选池太小会限制重排效果
13. BM25 与向量使用不同分块集合
14. Bi-Encoder 分开编码（可预计算）；Cross-Encoder 拼接编码（精排用）
15. Recall@50 好但 Recall@5 差
16. 小块精确检索（精度）+ 大块提供上下文（完整）
17. 按业务约束过滤（时间/部门）；回退到不过滤结果
18. 新增只算新增、修改删旧建新、删除只删对应
19. L1 答案 / L2 检索 / L3 Embedding；L1 收益最大
20. 新鲜度/完整性/质量/时效

### 评分与行动

| 得分 | 结论 | 行动 |
|---|---|---|
| 16-20 | 达标 | 进入阶段 4 |
| 12-15 | 基本达标 | 复习错题对应模块 |
| <12 | 未达标 | 重读 01-07 对应篇 + 重跑实战 |

## 7. 项目故事化：把调优写成面试素材

### 为什么需要故事化

面试官要的不是"我会 RAG"，是"**你能把 RAG 调好**"——完整的调优闭环案例就是最好的证明。

### 五段式项目故事模板

```
① 背景：知识库问答场景，300 篇文档，用户投诉答非所问
② 基线：建 50 问测试集，四指标基线（precision 0.60 / recall 0.55）
③ 定位：faithfulness 0.92 高、precision 低 → 瓶颈在检索
④ 调优：混合检索（recall 0.55→0.75）+ Rerank（precision 0.60→0.78）
        + HyDE 实测负收益撤掉（决策故事）
⑤ 结果：四指标达标、成本降 40%（缓存+精炼）、CI 门禁防退化
```

### 故事中的三个"决策点"（面试官最爱追问）

| 决策点 | 展示的能力 |
|---|---|
| 为什么先建测试集？ | 评估意识（不是上来就调） |
| 为什么撤掉 HyDE？ | 数据决策（不是堆技术） |
| 为什么上缓存？ | 成本意识（不是只管效果） |

### 常见追问与防御

| 追问 | 防御 |
|---|---|
| 指标具体多少？ | 背出你实战填表的数字（哪怕不完美） |
| 为什么选 bge-reranker-v2-m3？ | 中文多语言实测好 + 本地可跑 |
| 缓存失效怎么办？ | TTL + 主动失效 + 版本化 key |
| 测试集怎么来的？ | 真实咨询 + 合成扩充 + 人工策展 |
| 再给你三个月做什么？ | 生产漂移检测（ARES）+ 多模态扩展 + Agentic 路由 |

### 故事化检查清单

- [ ] 有基线数字（不是"感觉变好了"）
- [ ] 有瓶颈定位逻辑（指标拆解）
- [ ] 有正负收益决策（HyDE 撤掉的故事）
- [ ] 有工程落地（缓存/监控/CI）
- [ ] 能被追问 5 个问题以上
