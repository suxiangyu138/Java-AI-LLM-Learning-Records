## 2. 调优全景图：四大优化层

```
┌─────────────────────────────────────────────────┐
│ 层 0：评估层（先建测试集与基线，一切调优的前提）   │
│   RAGAS 四指标 / 累积提升表 / 回归测试            │
├─────────────────────────────────────────────────┤
│ 层 1：查询层（问题进检索前先加工）                 │
│   查询改写 / 多路查询 / HyDE / 意图路由           │
├─────────────────────────────────────────────────┤
│ 层 2：检索层（召回更多、更准）                     │
│   混合检索（BM25+向量）/ RRF 融合 / 粗召回扩容     │
├─────────────────────────────────────────────────┤
│ 层 3：排序与数据层（精排 + 数据升级）              │
│   Rerank 精排 / 上下文压缩 / 父子索引 / 增量更新   │
└─────────────────────────────────────────────────┘
```

四大层的依赖关系：

```
评估层在下面（地基）：没有测量，一切优化都是玄学
查询层在上面（输入）：问题质量决定检索上限
检索层是核心（召回）：召回不到，排序和生成都白搭
排序与数据层是放大器：把"有"变"准"、"准"变"快"
```

> 为什么评估层在底层：阶段 3 的第一课就是"先建测试集再调优"——因为 2026 年行业共识已经明确：**不评估就叠加技术，是 RAG 项目最常见的失败原因**。所有调优手段都有代价，只有测量能告诉你"哪一层值得付代价"。

## 6. 调优的黄金纪律

阶段 3 全篇贯穿三条纪律：

| 纪律 | 内容 | 违背的后果 |
|---|---|---|
| 评估先行 | 没有测试集就不调优 | 调了也不知道有没有用 |
| 一次一层 | 每次只改一个环节 | 指标变化无法归因 |
| 只留有收益的 | 用累积提升表逐层测量，无收益的层撤掉 | 复杂度爆炸、成本失控 |

这三条纪律直接来自 2026 年行业实践共识：**"Advanced RAG 技术不是更好，而是有时更好"**——HyDE 在某查询上把 context precision 从 0 提升到 0.80，在另一查询上把 Recall 从 0.80 暴跌到 0.17。技术是"有代价的工具"，不是"免费升级"。

## 8. 常见失败画像与预防

| 失败画像 | 现象 | 预防（本阶段内） |
|---|---|---|
| 玄学调参型 | 同时改 5 个参数，不知道哪个有效 | 黄金纪律二：一次一层 |
| 技术堆叠型 | 全部技术都上，成本爆炸指标没涨 | 累积提升表只留正收益层 |
| 不建基线型 | 调了几个月说不出"从多少到多少" | 01 篇先建基线再动手 |
| 只看单例型 | 一个查询变好了就宣布成功 | 测试集全量跑，不看单例 |
| 无回归型 | 上线后质量悄悄退化 | CI 门禁 + 每周漂移检测 |
| 成本失控型 | 质量上去了，成本翻了三倍 | 每层记录代价，收益小于代价撤掉 |

### 防失败三原则

1. **评估先行**：没有测试集就没有调优资格（01 篇）
2. **一次一层**：改什么测什么，指标可归因
3. **只留正收益**：累积提升表是唯一的"技术准入门槛"

## 9. 本阶段的面试价值

### 为什么这是面试重点区

RAG 面试 60% 的问题落在阶段 3：调优方法论、指标、决策逻辑——因为企业招人就是要会"把 RAG 调好"，而不是"知道 RAG 是什么"。

### 面试必会清单

| 主题 | 必会表达 |
|---|---|
| 调优方法论 | "先建测试集量基线，再逐层优化，用累积提升表只留正收益层" |
| 指标 | 四指标 + 各自衡量什么 + 谁需要真值 |
| 瓶颈定位 | "faithfulness 高 precision 低 → 检索瓶颈" |
| 混合检索 | BM25 补关键词盲区 + RRF 免尺度融合 + 同一分块集合 |
| Rerank | 粗召回 50 + Cross-Encoder 精排 5 |
| 技术取舍 | "HyDE 有时更好——我们实测负收益所以撤了"（有决策故事的杀伤力最大） |
| 工程化 | 三级缓存 + 增量更新 + CI 门禁 |

### 讲项目故事的模板

> "我的 RAG 项目：先建了 50 问测试集量基线（precision 0.60），定位到检索瓶颈后逐层叠加——混合检索让 recall 从 0.55 到 0.75，Rerank 让 precision 到 0.78，HyDE 实测负收益撤掉。最终上线前四指标达标，成本通过三级缓存降了 40%。"

这套模板同时展示了：评估能力、定位能力、决策能力、工程能力——比背概念强一个量级。
