# 03 RAG vs 微调 vs 长上下文

> 三大知识注入方案：RAG（外挂知识）、微调（改写参数）、长上下文（整文塞入）——选型决策树 + 组合策略，面试必考。

## 1. 三方案本质对比

| 方案 | 本质 | 一句话 |
|---|---|---|
| RAG | 知识放外部库，检索后注入提示词 | 先翻书再回答 |
| 微调 | 把知识/风格压进模型参数 | 把知识背进脑子里 |
| 长上下文 | 把整篇文档直接塞进上下文窗口 | 开卷考试（全带进考场） |

### 各自优势与硬伤

| 方案 | 优势 | 硬伤 |
|---|---|---|
| RAG | 低成本、实时更新、可溯源、无泄露风险 | 受检索质量限制、多一跳延迟 |
| 微调 | 风格稳定、响应快、领域能力内化 | 成本高、更新慢、有数据泄露风险 |
| 长上下文 | 保留完整上下文、无需切片、理解全局 | Token 成本极高、长文注意力下降、无法溯源 |

## 2. 细节对比表

| 维度 | RAG | 微调 | 长上下文 |
|---|---|---|---|
| 知识更新 | 秒级（换文档即可） | 月级（重新训练） | 即时（换 Prompt 即可） |
| 成本 | 向量化 + 检索基建 | 训练算力 + 数据工程 | 每次请求按 token 计费 |
| 可解释性 | ✅ 可引用来源 | ❌ 黑盒 | ✅ 内容可见但无定位 |
| 适用知识量 | 大（百万级文档） | 小（聚焦领域） | 受窗口限制（可达百万 token） |
| 数据安全 | 私有数据不出系统 | 数据进入模型参数（泄露风险） | 数据进请求（需加密通道） |
| 典型场景 | 知识库问答、客服、搜索 | 风格/格式/领域适配、代码 | 单文档深读（合同、论文） |
| 质量瓶颈 | 检索召回质量 | 训练数据质量 | 窗口内信息利用效率 |

## 3. 选型决策树

```
需要给 LLM 注入知识？
├─ 知识需频繁更新 / 数据敏感 / 必须可溯源 → RAG ✅
├─ 需要特定风格/格式/领域能力内化
│   ├─ 知识量大且更新少 → 微调（或 RAG+微调组合）
│   └─ 数据敏感不允许训练 → RAG
├─ 单文档深度分析（合同/论文/长报告）
│   ├─ 文档长但一次能装下 → 长上下文（成本允许时）
│   └─ 文档超长或需跨文档 → RAG（切片 + 检索）
└─ 高频问答 + 知识变化快 → RAG ✅（事实类）或 RAG+微调（风格+事实）
```

### 场景对照速查

| 场景 | 推荐 | 理由 |
|---|---|---|
| 企业知识库问答 | RAG | 更新频繁、需溯源 |
| 客服机器人话术风格 | RAG + 微调 | 事实走 RAG，风格走微调 |
| 法律合同审查 | 长上下文 + RAG | 全文理解 + 条款检索 |
| 代码风格迁移 | 微调 | 风格内化、响应快 |
| 实时新闻问答 | RAG | 知识秒级更新 |

## 4. 组合使用策略

2026 年行业实践已不再是"三选一"，而是**组合**：

| 组合 | 结构 | 场景 |
|---|---|---|
| RAG + 微调 | 微调管风格/格式，RAG 管事实 | 客服（风格统一 + 事实实时） |
| RAG + 长上下文 | 长上下文管整体理解，RAG 管精准定位 | 合同审查（先全文再定位条款） |
| 微调 + 长上下文 | 微调管领域语言，长上下文塞资料 | 专业写作 |

组合设计原则：

- **事实与风格分离**：事实类问题永远走 RAG（可溯源），风格类能力走微调（参数内化）
- **成本分层**：高频简单问答走便宜路径，低频复杂任务走高成本路径
- **安全优先**：私有数据一律不进入训练（微调禁用），只走 RAG 本地检索

## 5. 面试高频问法

| 问题 | 回答要点 |
|---|---|
| RAG 和微调的区别？ | 知识存储位置：外挂检索 vs 参数内化；更新成本：秒级 vs 月级 |
| 为什么 RAG 治幻觉微调治不了？ | 微调改变参数分布仍可能编造；RAG 给模型真实文本依据、可引用 |
| 长上下文会取代 RAG 吗？ | 不会——成本差异悬殊；窗口再大也是每次全价输入，RAG 只付检索命中部分（详见根目录 18 篇"长上下文时代 RAG 定位之争"） |
| 什么场景必须用微调？ | 特定输出格式、领域语言风格、低延迟高频调用、无法接受检索延迟 |
| 三者的最佳组合？ | 事实走 RAG、风格走微调、长文档走长上下文，按成本与场景分层 |

> 🎯 核心要点：**RAG 是"事实基础设施"，微调是"能力内化"，长上下文是"上下文宽松"**——三者不是竞争关系，是分工关系。面试答"选型"时先说决策维度（更新频率/安全/溯源/成本），再给结论。
