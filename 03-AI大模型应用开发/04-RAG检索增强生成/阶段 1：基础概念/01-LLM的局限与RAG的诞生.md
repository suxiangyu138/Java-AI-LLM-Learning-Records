## 1. LLM 的三大局限

| 痛点 | 表现 | 后果 |
|---|---|---|
| 幻觉 | 自信地编造不存在的事实（人名、数据、事件） | 答案不可信，生产场景致命 |
| 知识冻结 | 知识截止于训练数据日期，不知新事件 | 时效性问题无法回答 |
| 私有数据盲区 | 不了解企业文档、专有知识 | 企业内部场景不可用 |

### 1.1 幻觉（Hallucination）

- 定义：LLM 生成的内容在事实上不存在或与事实不符，且表达"自信"
- 成因：模型本质是"按概率接续文本"，不区分"知道"与"编造"；训练数据中的错误、常识缺失都会被"合理"地补全
- 危害分级：

| 场景 | 幻觉危害 |
|---|---|
| 闲聊/头脑风暴 | 无实质危害 |
| 代码生成 | 引入不存在的 API/方法，编译失败可发现 |
| 客服/知识问答 | 给出错误政策/价格，直接产生业务事故 |
| 医疗/法律/金融 | 致命——错误建议可能导致严重后果 |

### 1.2 知识冻结（Knowledge Cutoff）

- 模型训练完成后知识固定，新知识无法自然进入
- 例子：让训练于 2025 年的模型回答 2026 年的新政策——只能编
- 重新训练成本极高（数据、算力、周期以月计），不可作为常规更新手段

### 1.3 私有数据盲区

- 企业内部文档（SOP、产品手册、历史工单）从未进入训练数据
- 直接提问必然"一本正经地胡说"
- 数据敏感场景（金融、医疗、政务）**不允许**用私有数据训练大模型

## 2. 幻觉的深层成因

理解幻觉为什么"治不好"，需要看模型的训练与推理机制：

### 2.1 训练目标：预测下一个词

LLM 的训练目标是最大化下一个 token 的概率（语言建模损失）。模型学会的是"这段文本最可能怎么接"，而不是"这句话在事实上是否正确"：

```text
训练目标：P(下一个词 | 前文)
本质：学的是文本分布，不是事实数据库
```

- 事实性只是文本分布的一个副产品——高频出现的事实容易被记住
- 长尾事实（小众知识、新事件、具体数字）在训练数据中出现少，模型只能"合理猜测"

### 2.2 采样机制：概率选择

推理时按概率采样，即使正确答案概率最高，低概率的"编造项"也可能被选中：

| 因素 | 对幻觉的影响 |
|---|---|
| temperature 高 | 低概率 token 更容易被选，发散编造 |
| 低困惑度区间 | 模型"过于自信"地填上常见但错误的补全 |
| 上下文不足 | 信息缺失时模型倾向"填满"而非"留白" |

### 2.3 幻觉类型学

| 类型 | 说明 | 例子 |
|---|---|---|
| 事实性幻觉 | 编造不存在的事实 | 编一个不存在的政策条款 |
| 忠实性幻觉 | 与给定上下文矛盾 | 检索给了 A 数据，模型答 B |
| 逻辑性幻觉 | 推理链条断裂 | 计算错误、因果颠倒 |

> 💡 重要认知：**忠实性幻觉与 RAG 直接相关**——检索内容明明正确，模型却不遵循、另编一套。这解释了为什么 RAG 里要设计"只依据参考资料"的强约束 Prompt（阶段 2 的 06 篇）。

## 3. 局限的本质：知识存在参数里

理解三大局限的关键视角：

```
LLM 的知识 = 训练时压进参数的静态知识
问题：参数不可在线修改、知识不可追溯来源、更新必须重训
```

| 特征 | 影响 |
|---|---|
| 知识以参数形式存储 | 无法"增删改查"单条知识 |
| 无来源引用机制 | 无法回答"你凭什么这么说" |
| 更新 = 重训 | 时效与成本不可接受 |

对比知识库（数据库/文档）与模型参数：

| 维度 | 模型参数 | 知识库 |
|---|---|---|
| 读取方式 | 前向传播（不可控） | 检索（可控、可过滤） |
| 更新成本 | 重训（周/月级） | 写入（秒级） |
| 单条修改 | 不可能 | 增删改一条 |
| 溯源 | 无 | 有原文可指 |
| 容量 | 受模型大小限制 | 理论上无限 |

这正是 RAG 的切入点：**把知识从参数里搬出来，放到可检索的外部存储中**——参数只负责"理解与生成"，知识由外部系统提供。

## 4. RAG 的诞生：给 LLM 装外脑

- 概念起源：2020 年 Lewis 等人论文《Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks》首次提出
- 核心思想：**"先检索、再生成"**——生成前先从外部知识库检索相关内容，作为依据注入提示词
- 一句话：**给 LLM 装上一个"外脑"（可检索的知识库），回答时先翻书再开口**

诞生背景（2020-2026 演化）：

| 时间 | 节点 |
|---|---|
| 2020 | Lewis 论文提出 RAG 雏形（检索器 + 生成器联合） |
| 2022-2023 | ChatGPT 爆发，LLM 落地需求倒逼解决幻觉/私有数据问题 |
| 2023 | Naive RAG 广泛实践，LangChain/LlamaIndex 框架出现 |
| 2024 | Advanced RAG（查询改写/混合检索/重排）成为工程主流 |
| 2025 | Agentic RAG 兴起；长上下文模型冲击 RAG 的必要性之争 |
| 2026 | GraphRAG/多模态/流式 RAG/RAG 2.0 并存，RAG 进入"按场景选形态"阶段 |

为什么是 2023 年爆发：ChatGPT 让"人人可用 LLM"成为现实，企业第一个问题就是"怎么让 LLM 用我们的知识回答"——RAG 以"低成本 + 免训练 + 可解释"成为唯一立刻可行的方案。

## 5. RAG 的解决思路映射

| 痛点 | RAG 的解法 |
|---|---|
| 幻觉 | 答案以检索到的真实文本为依据，可引用来源，编造空间被压缩 |
| 知识冻结 | 知识库可随时更新（新增/删除文档），无需重新训练 |
| 私有数据盲区 | 企业文档入库检索，私有知识无需进入模型参数 |

### RAG 解决问题的边界（诚实清单）

| RAG 能做什么 | RAG 不能做什么 |
|---|---|
| 让答案基于给定文档 | 保证答案 100% 正确（检索错→答案错） |
| 知识秒级更新 | 提升模型本身的推理/创作能力 |
| 私有数据不出系统 | 替代领域微调的风格内化 |
| 提供来源引用 | 修复"检索到但模型不遵循"的忠实性幻觉 |

> ⚠️ 理解精度：RAG **显著降低幻觉概率，但不消除幻觉**——检索质量差时，模型仍可能忽略或曲解检索内容（详见 07 篇"挑战与边界"）。

## 6. 为什么 RAG 成了 LLM 落地最成熟范式

与替代方案（微调、长上下文）相比，RAG 的四大优势（详细对比见 03 篇）：

| 优势 | 说明 |
|---|---|
| 低成本 | 无需训练，只需向量化 + 检索基础设施 |
| 高实时性 | 知识库更新即时生效 |
| 可解释 | 答案可追溯来源，审计友好 |
| 无泄露风险 | 私有数据不进入模型参数，安全边界清晰 |

### 行业数据佐证（2026 视角）

- 企业内部知识问答、客服、搜索引擎增强是 RAG 最高频的三类落地场景
- 主流 Agent 框架（LangChain/LlamaIndex/Spring AI）都将 RAG 作为一等公民能力内置
- "长上下文会取代 RAG"的争论在 2025-2026 年反复出现，但结论趋于一致：**两者互补而非替代**（成本差异悬殊，详见根目录 18 篇）

2026 年行业共识：RAG 是**企业知识密集场景（客服、搜索、内部问答）的默认首选方案**，微调用于风格/领域适配，长上下文用于单文档深度分析——三者在具体系统中常组合使用（详见 03 篇）。

### 面试视角：三句话回答"为什么需要 RAG"

1. LLM 有三大硬伤：幻觉、知识冻结、私有数据盲区——根源是"知识压死在参数里"
2. RAG 把知识搬到外部库：更新秒级、答案可溯源、私有数据不训练
3. 与微调/长上下文是分工关系：事实走 RAG，风格走微调，长文档走长上下文

## 7. 面试追问防御

主问题"为什么需要 RAG"讲完后，面试官常见的追问与防御：

| 追问 | 防御要点 |
|---|---|
| 幻觉真的能被 RAG 治住吗？ | 显著降低不根除——四来源分类 + 四道防线（07 篇） |
| 为什么微调治不了幻觉？ | 微调改参数分布仍可能编造；RAG 给真实文本依据 |
| 知识库更新了，模型需要重新训练吗？ | 不需要——这正是 RAG 的核心优势（知识在库不在参数） |
| 检索质量差怎么办？ | 先定位到层（数据/检索/生成），再按对应手段优化（阶段 3） |
| 私有数据放向量库安全吗？ | 向量不可逆推原文；但仍是明文加密更稳（根目录 20 篇） |
| RAG 会被长上下文取代吗？ | 不会——成本差异悬殊 + 跨文档聚合能力（根目录 18 篇） |

### 追问防御的总原则

```
不背答案，讲逻辑：
被追问 → 拆成"现象 → 根因 → 对策"三段
例：幻觉 → 四来源 → 分层治理
```

> 🎯 核心要点：RAG 的本质是**知识的存储位置迁移**——把"知识在参数里"变成"知识在库里、参数管理解"。这一句话理解到位，后面的链路、选型、优化全部顺理成章。面试被追问时，用"现象→根因→对策"结构讲逻辑，不背答案。
