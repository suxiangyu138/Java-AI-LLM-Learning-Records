## 1. 概念串讲演练（三分钟讲清 RAG）

三分钟口头讲稿模板（推荐背诵框架，用自己的话复述）：

```
第 1 句（定义）：RAG 是检索增强生成——生成前先从知识库检索相关内容作为依据。

第 2 句（为什么）：LLM 有三硬伤——幻觉、知识冻结、私有数据盲区；
RAG 把知识从参数搬到外部库，可实时更新、可溯源、不用训练。

第 3 句（怎么做）：三步——离线索引（切片+向量化入库）、
在线检索（问题向量化+Top-K 召回）、生成（检索结果拼 Prompt 交给 LLM）。

第 4 句（选型）：vs 微调（知识位置不同：外挂 vs 参数）；
vs 长上下文（成本不同：检索命中 vs 全量塞入）。

第 5 句（演进）：Naive（基线）→ Advanced（加优化模块）→
Modular（任意编排）→ Agentic（自主决策）→ 2026 前沿（GraphRAG/多模态/流式/RAG 2.0）。

第 6 句（边界）：RAG 治"必须基于文档回答"的问题；
检索质量决定答案上限，幻觉降低但不根除。
```

### 演练评分标准

| 维度 | 满分表现 |
|---|---|
| 完整度 | 六句框架齐全 |
| 流畅度 | 无卡壳、无"嗯…" |
| 深度 | 能接住追问（如"检索不到怎么办"） |
| 时长 | 2-3 分钟 |

## 3. 20 道自测题

### 基础概念（1-8）

1. RAG 的三个英文单词全称与中文含义？
2. RAG 解决 LLM 的哪三大痛点？
3. RAG 三步流程的名称与顺序？
4. 索引阶段要做哪四件事？
5. 检索阶段返回什么？（Top-K 片段）
6. 生成阶段如何组装 Prompt？（检索片段 + 问题）
7. 为什么说"检索质量决定答案上限"？
8. 向量数据库里存了什么？（向量 + 原文/元数据）

### 对比选型（9-14）

9. RAG 与微调的本质区别是什么？（知识存储位置）
10. 什么场景必须用微调？（风格内化、低延迟）
11. 长上下文为什么不能完全替代 RAG？（成本差异）
12. 中文 Embedding 模型首选哪些？（BGE-M3 / BGE-large-zh）
13. 已有 PostgreSQL 业务，向量库怎么选？（pgvector）
14. 数据保密要求高时，哪三层要本地化？（Embedding/向量库/LLM）

### 演进与边界（15-20）

15. Naive RAG 的三大瓶颈？（语义鸿沟/碎片化/知识滞后）
16. Advanced RAG 的三类优化模块？（查询改写/混合检索/重排压缩）
17. Agentic RAG 相比传统 RAG 的核心区别？（动态决策 vs 固定流程）
18. GraphRAG 解决什么问题？（多跳关系推理）
19. RAG 为什么不能根除幻觉？举两个来源。
20. 什么时候不该用 RAG？举两个场景。

### 参考答案（简版）

1. Retrieval-Augmented Generation 检索增强生成
2. 幻觉 / 知识冻结 / 私有数据盲区
3. 索引 Indexing → 检索 Retrieval → 生成 Generation
4. 解析文档 → 切片 → Embedding 向量化 → 入库
5. 最相似的 Top-K 文本片段（含原文）
6. 检索片段 + 用户问题拼进 Prompt 再交给 LLM
7. 检索不到正确内容时，生成只能在错误上下文上编造
8. 向量（检索用）+ 原文与元数据（生成与溯源用）
9. 知识在外部库（外挂）vs 压进参数（内化）
10. 固定输出格式 / 领域语言风格 / 高频低延迟
11. 长上下文每次全价输入全部文档，RAG 只检索命中部分
12. BGE-M3 / BGE-large-zh
13. pgvector（零新增组件）
14. Embedding 模型、向量库、LLM 全部本地部署
15. 语义鸿沟 / 上下文碎片化（3 文档以上连贯性降 42%）/ 动态知识滞后
16. 查询改写（HyDE 等）/ 混合检索（BM25+Dense）/ 重排序与上下文压缩
17. 按需多轮检索、工具调用、自我评估反思，流程动态
18. 实体关系显式建模，支持"CEO 母校"类多跳链式推理
19. 检索不到时只能编；检索到但模型不遵循/错误推断
20. 纯创作/原创推理；固定风格输出；知识全在模型内

## 4. 扩展思考题（面试深挖准备）

答对 20 道后，挑战以下深挖题（不附答案，带着问题进阶段 2/3 找答案）：

1. 检索 Top-K 里"有答案但排第 8"（K=5 漏掉），你会改哪些参数？
2. 中文文档用通用英文 Embedding 模型，会出现什么现象？为什么？
3. RAG 的答案可以溯源到"第几节"，是哪两个环节的功劳？
4. 如果知识库同时有 3 份互相矛盾的政策文档，RAG 会怎样？如何设计？
5. 为什么说"评估困难"是 RAG 最容易被忽视的挑战？

### 核心结论清单（背诵版）

| 主题 | 一句话结论 |
|---|---|
| RAG 本质 | 知识存储位置迁移：参数 → 外部库 |
| 三步流程 | 索引 → 检索 → 生成 |
| 检索地位 | 答案上限由检索决定 |
| 三方案 | RAG 管事实 / 微调管风格 / 长上下文管全局 |
| 中文 Embedding | BGE 系列首选 |
| 演进逻辑 | 每个阶段解决上一阶段痛点 |
| 适用判断 | "答案必须出自某文档" = RAG 甜区 |
| 边界 | 幻觉降低不根除；检索错则答案错 |
| 生产铁律 | 先评估再调优；数据治理先行 |
