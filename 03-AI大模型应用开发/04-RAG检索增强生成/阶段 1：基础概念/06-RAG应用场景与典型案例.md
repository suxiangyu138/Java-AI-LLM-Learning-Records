## 1. 场景共性判断法

判断业务是否适合 RAG 的三问：

| 问题 | 适合 RAG | 不适合 RAG |
|---|---|---|
| 答案是否来自已有文档？ | 是（SOP、手册、政策） | 否（需模型原创推理） |
| 知识是否频繁更新？ | 是（RAG 更新秒级） | 否（固定风格/格式任务） |
| 是否需要引用来源？ | 是（可溯源） | 否（闲聊/头脑风暴） |

> 一句话：**"回答必须基于某份文档"的场景 = RAG 甜区**。

### 判断法的反面用例（帮助理解边界）

| 场景 | 判断结果 | 为什么 |
|---|---|---|
| "帮我写一首诗" | 不适合 | 原创创作，不需要文档依据 |
| "计算 2025 年各月环比" | 视数据而定 | 数据在库里→RAG 查数；纯推理→直接 LLM |
| "按公司规范回复投诉邮件" | 适合 | 规范文档 + 需要引据 |
| "解释 Java 泛型擦除" | 不一定 | 通用知识模型已有，检索纯属多余 |

## 2. 八大典型场景

| 场景 | 知识来源 | RAG 的价值 |
|---|---|---|
| 企业知识库问答 | 内部文档、SOP、wiki | 私有知识注入 + 可溯源 |
| 智能客服 | 产品手册、FAQ、政策 | 实时更新 + 一致性回答 |
| 搜索引擎增强 | 网页、数据库 | 语义召回 + 生成式摘要 |
| 合规与合同审查 | 法规、合同文本 | 条款定位 + 引用标注 |
| 金融研报问答 | 年报、研报、行情 | 数字准确 + 出处可查 |
| 医疗辅助 | 指南、文献 | 答案有据（辅助，非诊断） |
| 代码库问答 | 源码、文档 | 私有代码语义检索 |
| 电商多模态问答 | 商品图 + 描述 | 图像+文本联合检索 |

### 场景分类的三个层次

| 层次 | 说明 | 例子 |
|---|---|---|
| 单文档问答 | 一个文档内的问答 | 合同条款询问 |
| 多文档聚合 | 跨文档整合回答 | "近三年年报的营收趋势" |
| 知识体系问答 | 组织级知识库 | 全公司 SOP 查询 |

分层决定了检索架构的复杂度：单文档→基础 RAG；多文档→多路召回+融合；知识体系→Agentic 路由。

## 3. 行业案例拆解

### 案例一：企业内部知识库（最典型）

```
场景：员工问"差旅报销标准是什么"
数据：行政 SOP 文档库（PDF + Word，持续更新）
架构：文档入库 → 切片 → BGE 向量化 → Milvus 检索 → DeepSeek 生成 + 引用
收益：HR/行政咨询量下降 60%+，答案附文档出处
```

关键点：知识更新频率高（政策常变）→ 只能用 RAG（微调做不到秒级更新）。

**落地细节清单**：

| 环节 | 细节 |
|---|---|
| 数据 | SOP 文档版本管理（过期版本必须清理） |
| 检索 | 元数据过滤（按部门/文类） |
| 生成 | 引用标注到"第几版第几节" |
| 评估 | 用历史咨询记录构建测试集 |

### 案例二：智能客服

```
场景：用户问"退款多久到账"
架构：产品手册 + 历史工单入库 → 混合检索（关键词+向量）→ Rerank → LLM 生成
难点：语义鸿沟（"退钱""refund""退款"同义不同词）→ 混合检索 + 查询改写
收益：拦截 70%+ 重复咨询，话术统一
```

关键点：客服是"事实+风格"双需求 → RAG 管事实、微调/提示词管话术风格。

**客服场景特有的设计**：

| 设计点 | 做法 |
|---|---|
| 拒答策略 | 检索不到 → 转人工（不能硬答） |
| 情绪处理 | 投诉场景先共情再答事实 |
| 会话历史 | 多轮对话携带上下文 |
| 数据合规 | 通话/工单脱敏后才能入库 |

### 案例三：金融研报问答

```
场景："某公司 2025 年营收增速是多少"
架构：研报解析（表格处理）→ 切片 → 检索 → 生成 + 数字来源标注
难点：数字准确性要求高、表格数据易丢 → 专用解析 + 答案校验
收益：分析师检索时间从小时级降到分钟级
```

关键点：数字敏感场景必须有**引用溯源 + 答案校验**，否则幻觉代价极高。

**数字敏感场景的可靠性三板斧**：

1. 解析层：表格专用解析（PDF 表格→结构化）
2. 检索层：数字查询改写（"营收增速"→"revenue growth"）
3. 生成层：答案校验（提取回答中的数字与来源比对）

## 4. 场景画像速查

| 画像 | 特征 | RAG 形态 |
|---|---|---|
| 知识问答型 | 文档全、问题固定 | 基础 RAG |
| 实时更新型 | 知识时变（政策/价格） | RAG + 流式同步（CDC） |
| 多源整合型 | 多个知识库 | Agentic RAG（路由 + 多 Agent） |
| 关系推理型 | 需多跳推理 | GraphRAG |
| 多模态型 | 图/音/视 + 文本 | 多模态 RAG |
| 深度分析型 | 长文档单问 | 长上下文 + RAG 混合 |

### 画像与架构的映射逻辑

```
看场景 → 定画像 → 选架构 → 配组件

"客服" → 实时更新型 + 知识问答型 → 基础 RAG + 增量同步 + 混合检索
"投研" → 深度分析型 + 关系推理型 → 长上下文 + GraphRAG + 表格解析
"法务" → 知识问答型 + 多源整合型 → RAG + 条款定位 + 引用标注
```

## 5. 场景落地路径

### 从验证到上线的四步

| 步骤 | 做什么 | 产出 |
|---|---|---|
| 1. 场景验证 | 选 50 个真实问题测召回 | 可行/不可行判断 |
| 2. 最小闭环 | 阶段 2 的 Basic RAG | 跑通 Demo |
| 3. 工程化 | 阶段 3：混合检索/重排/评估 | 可上线的质量 |
| 4. 生产化 | 阶段 4：Agentic/监控/治理 | 生产系统 |

### 落地常见失败模式

| 失败模式 | 根因 | 对策 |
|---|---|---|
| 答案质量差 | 跳过评估直接上线 | 先建测试集再调优 |
| 检索全不中 | 文档本身脏/不完整 | 先治理数据再建库 |
| 用户不用 | 回答没有引用/不信任 | 溯源展示 + 置信度提示 |
| 维护崩溃 | 文档更新无流程 | 增量更新 + 版本管理 |

## 6. 场景判断演练（10 连问）

对每个场景快速判断：适不适合 RAG？理由？

| # | 场景 | 判断 | 理由 |
|---|---|---|---|
| 1 | 员工查差旅报销标准 | ✅ | 答案在 SOP 文档、需溯源 |
| 2 | 帮用户写情书 | ❌ | 原创创作 |
| 3 | 客服查退款政策 | ✅ | 政策文档 + 实时更新 |
| 4 | 解释什么是 HashMap | ❌ | 模型通用知识已有 |
| 5 | 审查合同中的赔偿条款 | ✅ | 条款定位 + 引用 |
| 6 | 生成商品卖点文案 | ❌ | 创作 + 风格任务（微调更合适） |
| 7 | 查询公司去年营收数据 | ✅ | 年报文档 + 数字溯源 |
| 8 | 实时播报股价变动 | ⚠️ | 需要流式 RAG（CDC） |
| 9 | 分析 500 页论文的核心论点 | ⚠️ | 长上下文 + RAG 混合更合适 |
| 10 | 回答"你的名字是什么" | ❌ | 系统信息，不需要检索 |

**演练价值**：10 连问的训练目标是形成"下意识判断"——看到场景先想"答案在哪份文档里"，而不是"要不要用 RAG"。判断对了，架构自然对。

### 判断口诀

```
一找文档：答案要出自某份文档 → RAG
二看时效：知识常变 → RAG（微调做不到）
三问溯源：需要引用 → RAG
四查能力：模型本来就会 → 别用 RAG
```

> 🎯 核心要点：面试讲场景，先给"共性判断法"（三问），再给一个完整案例（数据→架构→难点→收益）——比罗列十个场景有说服力得多。日常判断用"一找文档、二看时效、三问溯源、四查能力"口诀。
