## 1. 演进主线总览

```
Naive RAG（2023 基线）→ Advanced RAG（加优化模块）→ Modular RAG（任意编排）
                                                    → Agentic RAG（自主决策）
                                                    → 2026 前沿：GraphRAG / 多模态 / 流式 / RAG 2.0
```

演进动因一句话：**每个阶段都在解决上一阶段暴露的痛点**——Naive 的检索质量差 → Advanced 加模块；模块多了流程僵化 → Modular 任意编排；静态流程不能应对复杂问题 → Agentic 自主决策。

| 阶段 | 出现时间 | 解决的核心问题 | 代价 |
|---|---|---|---|
| Naive RAG | 2023 | 从 0 到 1 可用 | 检索质量差、流程僵化 |
| Advanced RAG | 2023-2024 | 检索质量、上下文利用 | 模块多、配置复杂 |
| Modular RAG | 2024 | 流程僵化 | 设计复杂度转移到架构 |
| Agentic RAG | 2025 | 复杂问题自主决策 | 成本高、不确定性 |
| 2026 前沿 | 2025-2026 | 关系推理/多模态/时效 | 各方向取舍不同 |

## 2. Naive RAG（朴素 RAG）

架构：查询解析 → 文档检索 → 答案生成（检索一次、生成一次，无反馈）

```
用户问题 → [检索一次] → Top-K 片段 → [拼接] → LLM → 答案
```

### 三大瓶颈（阶段 1 必须背）

| 瓶颈 | 说明 | 数据/例证 |
|---|---|---|
| 语义鸿沟 | 关键词检索难以处理"语义相同、用词不同" | 问"怎么退款"vs 文档写"退费流程" |
| 上下文碎片化 | 召回片段缺乏连贯性，拼凑答案逻辑断裂 | **检索结果超过 3 个独立文档时，连贯性评分下降 42%** |
| 动态知识滞后 | 知识库离线更新，无法及时捕获最新事件 | 新闻、政策类问题过时 |

### 其他问题清单

| 问题 | 说明 |
|---|---|
| 检索精度低 | 词法匹配误召回无关文档 |
| 上下文冗长 | Top-K 拼接超过 LLM 窗口或挤占指令空间 |
| 生成质量不稳定 | 同一问题不同片段组合，答案波动 |
| 无反馈机制 | 一次检索失败没有补救路径 |
| 无评估闭环 | 不知道检索/生成哪个环节差 |

## 3. Advanced RAG（高级 RAG）

在 Naive 基础上增加优化模块，分三个环节：

| 环节 | 优化模块 | 代表技术 |
|---|---|---|
| 查询侧 | 查询重写 | HyDE、Query2Doc（把模糊查询改写为精准检索式） |
| 检索侧 | 混合检索 / 多路召回 | BM25 + Dense 融合、父子文档索引、多向量索引 |
| 排序侧 | 重排序 / 上下文压缩 | BGE-Reranker、Cohere Rerank；LongLLMLingua 去冗余 |

### 优化模块与痛点映射

| 痛点 | Advanced 解法 | 效果 |
|---|---|---|
| 语义鸿沟 | 查询改写（HyDE 等） | 检索召回率提升 |
| 检索精度低 | 混合检索（BM25 + 向量） | 词法+语义互补 |
| 召回乱序 | Rerank 精排 | Top-N 质量提升 |
| 上下文冗长 | 压缩/精选 | 省 token + 减少噪音 |
| 信息分散 | 父子文档索引 | 小块定位 + 大块补上下文 |

### 工程优化方向

- **查询理解增强**：多模态查询解析、查询重写机制
- **检索策略升级**："粗选-精选"分层检索（效率提升 3 倍、保持 92% 召回率）；增量更新使知识延迟控制在分钟级
- **生成控制优化**：动态上下文窗口管理、答案三重校验

## 4. Modular RAG（模块化 RAG）

核心思想：把 RAG 拆成**可自由编排的模块**（检索、路由、重排、验证、记忆等），按任务需求组装流程：

| 流程模式 | 说明 | 示例 |
|---|---|---|
| 线性 | 检索→生成（基础） | 简单问答 |
| 条件分支 | 按问题类型走不同路径 | 简单问题直答、复杂问题检索 |
| 分支并行 | 多路检索同时进行 | 多知识库并行召回 |
| 循环 | 检索→生成→评估→再检索 | 反思循环、多轮迭代 |

```
Modular RAG = 积木（模块）+ 流程图（编排）
```

意义：从"固定流水线"走向"可编程流程"——为 Agentic RAG 提供了结构基础。

### 模块清单（可编排单元）

| 模块 | 职责 |
|---|---|
| 查询改写 | 优化检索前的问题 |
| 路由 | 决定走哪个检索路径/知识库 |
| 检索 | 从向量库/关键词取回候选 |
| 重排 | 对候选精排 |
| 压缩 | 精简上下文 |
| 验证 | 检查答案依据 |
| 记忆 | 多轮对话状态 |
| 融合 | 多路结果合并 |

## 5. Agentic RAG（智能体 RAG）

把 AI Agent 的决策能力引入 RAG：

| 能力 | 说明 |
|---|---|
| 路由决策 | 自动判断问题类型，选择合适知识库或工具 |
| 工具调用 | 检索之外还能调 API、数据库、计算工具 |
| 多 Agent 协作 | 多个专业 Agent 分别检索不同领域再整合 |
| 反思验证 | Self-RAG：评估检索结果是否足够，不足主动再检索 |
| 迭代优化 | 多轮"检索-生成-验证"循环直到满意 |

### 典型差异

| 维度 | 传统 RAG | Agentic RAG |
|---|---|---|
| 检索次数 | 固定一次 | 按需多轮 |
| 流程 | 静态 | 动态决策 |
| 成本 | 低 | 高（多轮调用） |
| 复杂问题能力 | 弱 | 强 |
| 可预测性 | 高 | 中（决策不确定性） |

### 适用与不适用的判断

| 适用 Agentic | 不适用 Agentic |
|---|---|
| 问题需要多步推理 | 简单 FAQ（杀鸡用牛刀） |
| 知识分散多个库 | 单库精确检索 |
| 需要工具配合（计算/API） | 纯文本问答 |
| 用户问题千变万化 | 问题模式固定 |

## 6. 2026 前沿方向

| 方向 | 核心思想 | 代表/数据 |
|---|---|---|
| Adaptive RAG | 按问题复杂度动态决定是否检索、检索次数、数据源 | 准确率提升 40%，同时降本 |
| GraphRAG | 知识图谱显式建模实体与关系，支持多跳推理 | 微软 GraphRAG 框架（"公司 CEO 的母校"类链式问题） |
| MiA-RAG | 检索前先为长文档生成全局摘要（全局视图）指导检索 | 长文档场景 |
| 实时流式 RAG | 监听数据库变更日志（CDC）实现知识秒级同步 | 金融行情、物流、工单 |
| 多模态 RAG | 检索/生成扩展到图像、音频、视频，CLIP 等统一向量空间 | 医疗影像、电商多模态问答 |
| RAG 2.0 | 检索器与生成器**端到端联合训练** | 复杂问题准确率 +31%、事实一致性 2.3 倍 |

### 各前沿方向解决什么问题

| 方向 | 解决的问题 |
|---|---|
| Adaptive | 检索成本浪费（简单问题也检索） |
| Graph | 单跳检索解决不了的关系链推理 |
| MiA | 长文档的全局信息缺失 |
| 流式 | 知识时效性（分钟级同步） |
| 多模态 | 知识不只在文本里 |
| RAG 2.0 | 检索器与生成器互相不配合（独立优化非全局最优） |

## 7. 演进规律总结

### 规律一：痛点驱动

```
每个阶段 = 上一阶段的痛点 + 一个解法
Naive 检索差 → Advanced 模块化优化
Advanced 流程僵 → Modular 编排
Modular 静态 → Agentic 决策
Agentic 单文本 → Graph/多模态
```

### 规律二：复杂度上移

```
RAG 的复杂度从"模型"上移到"系统"：
Naive：模型能力决定质量
Advanced：工程模块决定质量
Agentic：架构决策决定质量
```

### 规律三：能力不变，形态变

底层"检索增强生成"三步链路从未改变——变的是**谁来检索、检索几次、怎么用结果**。

### 面试表达模板

"RAG 的演进我理解是一条痛点驱动线：Naive 解决了'有'的问题但检索质量差；Advanced 通过查询改写、混合检索、重排把质量提上来；Modular 把流程变成可编排的；Agentic 让系统自己决定怎么检索；2026 年则分化出 GraphRAG、多模态、流式、RAG 2.0 等按场景选的形态。"

## 8. 演进与面试：版本化答题

### 版本答题框架（说演进必用）

```
"RAG 演进我分四个阶段看：
① Naive：检索→拼接→生成，能用了但检索质量差
② Advanced：给三个环节加模块（查询改写/混合检索/重排压缩）
③ Modular + Agentic：流程可编排 + 自主决策
④ 2026：按场景分化——Graph 管关系、多模态管媒体、流式管时效、RAG 2.0 管端到端"
```
