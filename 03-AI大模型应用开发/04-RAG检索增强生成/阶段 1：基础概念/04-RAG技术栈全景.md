## 1. 四件套总览

| 组件 | 职责 | 决策关键 |
|---|---|---|
| Embedding 模型 | 文本↔向量互转 | 语言能力、维度、成本、是否本地 |
| 向量数据库 | 存储 + ANN 检索 | 规模、部署方式、已有基础设施 |
| LLM | 基于上下文生成 | 推理质量、成本、上下文窗口 |
| 编排框架 | 串起索引与查询流程 | 生态、团队语言、复杂需求 |

选型核心逻辑：**先定规模与部署约束，再选组件**——数据量、是否上云、是否信创，决定了 90% 的选择。

## 2. Embedding 模型选型

| 模型 | 特点 | 适用 |
|---|---|---|
| BGE-M3 | 多语言、多粒度、多功能（稠密+稀疏） | 中文场景首选之一 |
| BGE-large-zh | 中文专精，效果好 | 纯中文知识库 |
| text-embedding-3 | OpenAI 生态，API 方便 | 已用 OpenAI 体系 |
| voyage/Cohere embed | 长文本/多语言商业方案 | 海外生产 |
| 本地部署 BGE 系列 | 数据不出内网 | 保密要求高 |

选型要点：

- **中文场景优先 BGE-M3 / BGE-large-zh**（开源、免费、效果好）
- **数据保密要求高 → 本地部署**（Embedding 请求不出内网）
- 维度与成本：高维更准但更贵（存储与检索成本随维度上升）
- 检索效果验证：用你的业务样本测试相似度排序质量，不要只看榜单

## 3. 向量数据库选型

| 方案 | 定位 | 适用规模 |
|---|---|---|
| Chroma / FAISS | 本地/快速验证 | 原型、个人项目、小规模 |
| pgvector | PostgreSQL 扩展 | 已有 PG 业务、中小规模 |
| Qdrant / Milvus Lite | 中小规模生产 | 起步生产的平衡点 |
| Milvus | 大规模企业级 | 百万级向量、高并发 |
| Pinecone | 托管 SaaS | 不想运维、预算充足 |
| Elasticsearch | 全文 + 向量一体 | 已有 ES 业务（混合检索天然支持） |

选型决策：

```
验证原型 → Chroma/FAISS
已有 PG → pgvector（零新增组件）
中小规模 → Qdrant / Milvus Lite
大规模/企业 → Milvus
不运维 → Pinecone
已有 ES → ES 8.x（关键词+向量一体）
```

> 💡 国内生产环境常见组合：Milvus（独立向量库）或 pgvector（复用 PG），配合 ES 做混合检索——阶段 3 详解。

## 4. LLM 选型

| 模型 | 特点 | 适用 |
|---|---|---|
| Claude 系列 | 推理质量顶尖、长上下文 | 高质量问答 |
| GPT 系列 | 生态成熟、工具调用好 | 通用生产 |
| DeepSeek | 中文强、价格低、开源 | 成本敏感 + 中文 |
| Qwen 系列 | 中文强、开源、部署灵活 | 国产化/私有化 |
| Gemini 系列 | 超长上下文 | 长文档场景 |

选型要点：

- **RAG 对 LLM 的核心要求是"会读上下文"**：能严格遵循"只依据检索内容回答"
- 国产方案（DeepSeek/Qwen）在中文 RAG 场景性价比高
- 上下文窗口决定单次能塞多少检索片段（详见 02 篇术语表）

## 5. RAG 编排框架选型

| 框架 | 特点 | 适用 |
|---|---|---|
| LangChain | 生态最全、组件多 | 通用、快速集成 |
| LlamaIndex | 专注 RAG、组件粒度细 | RAG 深度定制 |
| Haystack | 企业级、生产友好 | 企业项目 |
| Spring AI | Java 官方生态 | Java 后端团队 |
| Dify / FastGPT / Coze | 低代码平台 | 非工程团队、快速交付 |

选型要点：

- **Python 团队**：LangChain（生态全）或 LlamaIndex（RAG 专精）
- **Java 团队**：Spring AI（与 Spring Boot 无缝）
- **低代码**：Dify 等平台拖拽搭 RAG 应用
- 2026 年趋势：框架在变薄——向量库原生能力 + LLM 直调也越来越常见（阶段 2 会演示"零框架"最小链路）

## 6. 完整选型组合示例

| 场景 | Embedding | 向量库 | LLM | 框架 |
|---|---|---|---|---|
| 个人知识库（快） | BGE-large-zh | Chroma | DeepSeek | 无/LangChain |
| 中小公司客服 | BGE-M3 | Qdrant | Qwen | LangChain |
| 企业级大规模 | BGE-M3 | Milvus + ES | DeepSeek/Qwen | LlamaIndex/Haystack |
| Java 后端团队 | BGE-M3 | pgvector | DeepSeek | Spring AI |
| 保密内网 | 本地 BGE | Milvus 私有化 | 私有化 Qwen/DeepSeek | Haystack |

> 🎯 核心要点：技术栈没有"最好"，只有"匹配"——先回答三个问题：数据量多大？能不能上云/必须内网？团队用什么语言？答案出来，四件套基本定型。
