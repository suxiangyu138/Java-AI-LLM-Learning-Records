## 1. 本阶段定位

RAG 四阶段路径中的**第一阶段**：建立完整、正确的概念地基。

| 阶段 | 名称 | 核心任务 | 产出 |
|---|---|---|---|
| 1 | 基础概念（本篇系） | 概念、原理、选型、演进 | 能给别人讲清 RAG 是什么 |
| 2 | 动手实现 Basic RAG | 从零搭一条最小链路 | 能跑通一个本地 RAG |
| 3 | 进阶调优（工程核心） | 切片/检索/重排/评估调优 | 能诊断并优化 RAG 质量 |
| 4 | 高级 RAG | GraphRAG/Agentic/多模态 | 能设计生产级 RAG 架构 |

> 本阶段**零代码**，但概念必须深——检索与生成的分工、为什么 RAG 治幻觉、三方案如何选型，这些理解不到位，后面动手全是返工。

## 6. 核心概念速查

| 概念 | 一句话速记 |
|---|---|
| RAG | 检索增强生成：检索外部知识 + 生成答案，给 LLM 装"外脑" |
| 幻觉 | LLM 自信地编造不存在的事实，RAG 的核心解决目标之一 |
| 知识冻结 | LLM 知识截止于训练数据，RAG 让知识可实时更新 |
| 私有数据盲区 | LLM 不了解企业文档/专有知识，RAG 注入私有知识 |
| 索引（Indexing） | 文档切片→Embedding→存入向量库 |
| 检索（Retrieval） | 查询向量化→向量库 Top-K 召回 |
| 生成（Generation） | 检索结果 + 问题拼 Prompt → LLM 生成带依据答案 |
| Naive RAG | 朴素 RAG：检索→拼接→生成，基线形态 |
| Advanced RAG | 高级 RAG：查询改写/混合检索/重排/压缩等优化模块 |
| Agentic RAG | 智能体 RAG：路由决策、多 Agent、迭代反思检索 |
| Embedding | 把文本映射为向量的模型，语义检索的基础 |
| 向量数据库 | 存储与检索向量的数据库（FAISS/Milvus/pgvector 等） |
| Top-K | 检索返回最相似的 K 个片段 |
| Rerank | 对召回结果二次精排，提升准确率 |
| GraphRAG | 知识图谱增强的 RAG，支持多跳推理 |
| RAG 2.0 | 检索器与生成器端到端联合训练的下一代 RAG |
