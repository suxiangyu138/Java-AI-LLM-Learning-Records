## 1. 六类核心挑战

| 挑战 | 表现 | 严重度 |
|---|---|---|
| 检索质量不足 | 召回不到相关文档，答案必错 | 致命（源头错误） |
| 幻觉残留 | 检索到了但模型不引用，仍编造 | 高 |
| 上下文碎片化 | 多个片段拼凑，逻辑断裂 | 中高 |
| 评估困难 | 答案质量难以自动化度量 | 高（无从优化） |
| 延迟与成本 | 检索一跳 + 长上下文生成 | 中 |
| 知识库治理 | 脏数据、重复、过期文档污染检索 | 高 |

### 挑战间的传导链

```
知识库治理差 → 检索质量差 → 答案错误 → 用户不信任 → 项目失败

评估困难是横切问题：没有度量，就无法知道哪一环坏了
```

理解这个传导链很重要：**RAG 的失败很少是单一环节**——通常根因在数据层，暴露在生成层。

## 2. Naive RAG 的失效模式

| 失效模式 | 场景示例 | 后果 |
|---|---|---|
| 召回失败 | 问法用词与文档不一致 | 检索不到 → 模型瞎答 |
| 召回无关 | Top-K 里混入不相关片段 | 上下文污染 → 答案跑偏 |
| 召回碎片 | 关键信息分散在多个切片 | 拼不出完整答案 |
| 检索到但被忽略 | 片段里有答案但模型没看 | 幻觉残留 |

### 四类失效的排查口诀

```
召回失败 → 查 Embedding/切片/查询改写
召回无关 → 查知识库质量/Top-K 大小/阈值
召回碎片 → 查切片策略（重叠/父子索引）
被忽略   → 查 Prompt 约束/上下文位置
```

失效的本质：**RAG 的答案上限由检索决定，生成只能在下限之上工作**——检索 Top-K 里没有正确内容，再强的 LLM 也救不回来。

## 3. 幻觉为什么不能根除

| 幻觉来源 | 机理 |
|---|---|
| 检索不到 | 知识库缺内容，模型只能编 |
| 检索错 | 召回无关内容，模型被带偏 |
| 上下文被忽略 | 模型"没看"或"不遵循"检索内容（指令遵循不足） |
| 推理性幻觉 | 模型在检索内容之外做了错误推断/补全 |

### 四来源对应的治理位置

| 来源 | 治理层 | 手段 |
|---|---|---|
| 检索不到 | 数据层 | 知识库扩充、查询改写 |
| 检索错 | 检索层 | 混合检索、重排、阈值 |
| 上下文被忽略 | 生成层 | Prompt 强约束、低温度 |
| 推理性幻觉 | 生成层 | 拒答策略、答案校验 |

关键认知：

- RAG 把幻觉概率**大幅降低**（有依据可引用），但**不保证为零**
- 生产级 RAG 必须配套：**答案校验 + 引用标注 + 拒答机制**（检索置信度低时明确"知识库中没有相关内容"）
- 幻觉治理是系统工程：检索优化（阶段 3）+ 生成约束 + 评估闭环（根目录 20 篇评估体系深化）

### 幻觉残留的量化观

| 手段 | 幻觉率影响（经验区间） |
|---|---|
| 无 RAG 直接问 | 基线（如 15-30%，视任务） |
| + 基础 RAG | 显著下降（如 5-10%） |
| + 强约束 Prompt + 引用 | 再降（如 2-5%） |
| + 拒答 + 校验 | 逼近零（但牺牲覆盖率） |

> 💡 工程取舍：**"零幻觉"与"有答必对"不可兼得**——拒答越多覆盖率越低。生产上按业务容忍度在"准确率"与"覆盖率"之间取平衡点。

## 4. 生产环境的四道防线

| 防线 | 机制 | 作用 |
|---|---|---|
| 检索防线 | 混合检索 + 重排 + 阈值 | 保证进上下文的是对的 |
| 生成防线 | 强约束 Prompt + 低温度 | 保证模型遵循资料 |
| 校验防线 | 答案事实校验（数字/实体比对） | 拦截明显错误 |
| 拒答防线 | 置信度低时明说"没有" | 避免硬编 |

四道防线的关系：**越靠前的防线成本越低、收益越大**——检索防线做好了，后面的防线压力大减。

## 5. 什么时候不该用 RAG

| 情况 | 为什么不适合 | 替代 |
|---|---|---|
| 需要原创推理/创作 | 检索限制创造性 | 直接 LLM |
| 高频低延迟调用 | 检索多一跳延迟 | 微调（能力内化） |
| 固定风格/格式输出 | 检索无用武之地 | 微调 |
| 知识完全在模型内 | 检索纯属多余 | 直接 LLM |
| 知识库质量极差 | 垃圾进垃圾出 | 先做数据治理 |
| 单文档深度理解 | 切片破坏全局语义 | 长上下文 |

### 边界判断口诀

> **"RAG 是事实类问题的地基，不是所有问题的答案"**——先判断问题类型，再决定架构。

| 问题类型 | 判断依据 | 方案 |
|---|---|---|
| 事实类（基于文档） | 答案必须出自某文档 | RAG |
| 能力类（模型已有） | 通用知识、无需外部资料 | 直接 LLM |
| 风格类（需要内化） | 输出格式/语气要求稳定 | 微调 |
| 全局类（整文理解） | 单文档、需要跨章节 | 长上下文 |

## 6. 挑战 → 对策映射

| 挑战 | 对策 | 学习位置 |
|---|---|---|
| 检索质量不足 | 混合检索、查询改写、Rerank | 阶段 3 / 根目录 14-15 篇 |
| 幻觉残留 | 答案校验、拒答、引用标注 | 阶段 3 / 根目录 20 篇 |
| 上下文碎片化 | 父子文档索引、上下文压缩 | 阶段 3 / 根目录 15 篇 |
| 评估困难 | RAGAS 等评估体系 | 阶段 3 / 根目录 20 篇 |
| 延迟与成本 | 缓存、粗选-精选分层检索 | 根目录 21 篇 |
| 知识库治理 | 去重、版本管理、定期清理 | 阶段 2/3 数据管线 |

### 面试表达模板

"RAG 上线前我会先问自己四个问题：数据干净吗？检索能命中的问题占多少？答错一个问题的代价多大？能不能接受拒答？这四个答案决定了 RAG 的形态——从基础 RAG 到带四道防线的生产系统。"

## 7. 失效案例复盘（三个真实教训）

### 案例 A：知识库没更新（"上周的政策呢？"）

```
现象：员工问新政策，系统回答旧版本
根因：文档更新流程缺失，库里还是 3 个月前的版本
教训：RAG 的"实时"是"入库才实时"——知识库更新必须配套文档管理流程
对策：增量更新 + 版本元数据 + 过期文档清理（阶段 3 数据治理）
```

### 案例 B：Top-K 全不相关（"答非所问"）

```
现象：问"退款"，返回的却是"物流"内容
根因：切片太大（1000 字/块），单块混了多个主题；且没有阈值过滤
教训：切片粒度 + 阈值是基础防线——先看 Top-K 再调 Prompt
对策：缩小切片 + 语义切块 + 相似度阈值（08 篇任务三）
```

### 案例 C：数字对不上（"报表问答翻车"）

```
现象：问"去年营收"，回答的数字和年报对不上
根因：表格解析丢失结构 + 数字跨块断裂 + 无答案校验
教训：数字敏感场景，解析、切片、校验三层都要专门设计
对策：表格专用解析 + 数字不切断 + 答案校验（阶段 3/4）
```

### 案例复盘方法论

```
复盘四问：
① 哪一层先坏的？（数据/检索/生成）
② 根因是什么？（不是表象）
③ 防复发手段是什么？（不是一次性修复）
④ 如何提前发现？（监控/评估，阶段 3）
```

> 🎯 核心要点：本阶段的最后一课——**RAG 不是"做了就完事"，而是"上线才刚开始"**。理解六类挑战与边界，是进入阶段 2 动手实现时带上的"问题清单"。三个案例对应三个最常踩的坑：更新流程、切片粒度、数字解析。
