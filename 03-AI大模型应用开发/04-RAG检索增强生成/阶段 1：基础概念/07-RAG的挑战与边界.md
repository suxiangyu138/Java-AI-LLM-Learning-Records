## 1. 六类核心挑战

| 挑战 | 表现 | 严重度 |
|---|---|---|
| 检索质量不足 | 召回不到相关文档，答案必错 | 致命（源头错误） |
| 幻觉残留 | 检索到了但模型不引用，仍编造 | 高 |
| 上下文碎片化 | 多个片段拼凑，逻辑断裂 | 中高 |
| 评估困难 | 答案质量难以自动化度量 | 高（无从优化） |
| 延迟与成本 | 检索一跳 + 长上下文生成 | 中 |
| 知识库治理 | 脏数据、重复、过期文档污染检索 | 高 |

## 2. Naive RAG 的失效模式

| 失效模式 | 场景示例 | 后果 |
|---|---|---|
| 召回失败 | 问法用词与文档不一致 | 检索不到 → 模型瞎答 |
| 召回无关 | Top-K 里混入不相关片段 | 上下文污染 → 答案跑偏 |
| 召回碎片 | 关键信息分散在多个切片 | 拼不出完整答案 |
| 检索到但被忽略 | 片段里有答案但模型没看 | 幻觉残留 |

失效的本质：**RAG 的答案上限由检索决定，生成只能在下限之上工作**——检索 Top-K 里没有正确内容，再强的 LLM 也救不回来。

## 3. 幻觉为什么不能根除

| 幻觉来源 | 机理 |
|---|---|
| 检索不到 | 知识库缺内容，模型只能编 |
| 检索错 | 召回无关内容，模型被带偏 |
| 上下文被忽略 | 模型"没看"或"不遵循"检索内容（指令遵循不足） |
| 推理性幻觉 | 模型在检索内容之外做了错误推断/补全 |

关键认知：

- RAG 把幻觉概率**大幅降低**（有依据可引用），但**不保证为零**
- 生产级 RAG 必须配套：**答案校验 + 引用标注 + 拒答机制**（检索置信度低时明确"知识库中没有相关内容"）
- 幻觉治理是系统工程：检索优化（阶段 3）+ 生成约束 + 评估闭环（根目录 20 篇评估体系深化）

## 4. 什么时候不该用 RAG

| 情况 | 为什么不适合 | 替代 |
|---|---|---|
| 需要原创推理/创作 | 检索限制创造性 | 直接 LLM |
| 高频低延迟调用 | 检索多一跳延迟 | 微调（能力内化） |
| 固定风格/格式输出 | 检索无用武之地 | 微调 |
| 知识完全在模型内 | 检索纯属多余 | 直接 LLM |
| 知识库质量极差 | 垃圾进垃圾出 | 先做数据治理 |
| 单文档深度理解 | 切片破坏全局语义 | 长上下文 |

边界判断口诀：**"RAG 是事实类问题的地基，不是所有问题的答案"**——先判断问题类型，再决定架构。

## 5. 挑战 → 对策映射

| 挑战 | 对策 | 学习位置 |
|---|---|---|
| 检索质量不足 | 混合检索、查询改写、Rerank | 阶段 3 / 根目录 14-15 篇 |
| 幻觉残留 | 答案校验、拒答、引用标注 | 阶段 3 / 根目录 20 篇 |
| 上下文碎片化 | 父子文档索引、上下文压缩 | 阶段 3 / 根目录 15 篇 |
| 评估困难 | RAGAS 等评估体系 | 阶段 3 / 根目录 20 篇 |
| 延迟与成本 | 缓存、粗选-精选分层检索 | 根目录 21 篇 |
| 知识库治理 | 去重、版本管理、定期清理 | 阶段 2/3 数据管线 |

> 🎯 核心要点：本阶段的最后一课——**RAG 不是"做了就完事"，而是"上线才刚开始"**。理解六类挑战与边界，是进入阶段 2 动手实现时带上的"问题清单"。
