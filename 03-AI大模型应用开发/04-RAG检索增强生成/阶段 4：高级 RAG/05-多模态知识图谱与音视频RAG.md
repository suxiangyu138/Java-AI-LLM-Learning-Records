## 1. 为什么需要多模态知识图谱

### 文本 RAG 的盲区

| 知识形态 | 文本 RAG 的表现 |
|---|---|
| 视频内容 | 完全不可见 |
| 音频/会议记录 | 不可见 |
| 图片中的关系 | 单图检索可以，跨图关系不行 |
| 时间动态信息 | 无法表达"何时发生" |

### 多模态知识图谱（M³KG-RAG）的目标

```
把音视频等非文本内容也变成"可检索的知识"：
音频 → 转写文本
视频 → 帧描述文本
多模态 → 实体-关系三元组（带时间锚定）
→ 进入统一图谱检索
```

### 价值场景

| 场景 | 价值 |
|---|---|
| 会议记录问答 | "上次会上谁提了预算问题" |
| 监控/培训视频 | "安全培训第几分钟讲了防护" |
| 医疗影像+病历 | 影像发现与病史关联 |
| 客服录音分析 | 高频问题定位到录音时间点 |

## 2. 音视频 RAG 的管线

### 标准多流管线

```
音视频输入
  ├─ ASR 转写（Whisper）→ 音频文本
  ├─ 视觉 LLM 帧描述（视频帧 → 持续描述）
  └─ 场景/事件切分（镜头检测）
    → Agent 自动提取实体（人物/事件/动作）
    → 构建知识图谱三元组（时间锚定）
    → 统一检索
```

| 环节 | 工具/技术 | 产出 |
|---|---|---|
| 语音转写 | Whisper（ASR） | 音频文本 + 时间戳 |
| 帧描述 | 视觉 LLM | 画面持续描述 |
| 实体提取 | Agent + LLM | 人物/事件/动作三元组 |
| 时间锚定 | 时间戳映射 | 每个知识关联时间点 |

### 时间戳的作用（关键差异）

```
文本 RAG：检索到"哪段文字"
音视频 RAG：检索到"第几分几秒"——可直接跳转验证
```

## 3. 多模态三元组与时间锚定

### 三元组扩展

```text
文本三元组：（李明）-[提出]->（预算削减）
多模态三元组：（李明）-["提出"@12:34]->（预算削减）
                             ↑ 时间锚定
```

### 时间锚定的价值

| 价值 | 说明 |
|---|---|
| 精确溯源 | 回答附"视频 12:34"的深度链接 |
| 事实验证 | 用户直接跳到原视频核对 |
| 时序推理 | "先发生了什么后发生了什么" |
| 动态知识 | 事件顺序本身就是知识 |

### 示例查询

```
问题："培训视频里怎么演示防护操作的？"
图谱检索 →（防护操作）-["演示"@05:20]->（安全主管）
回答 + 链接：见视频 05:20-07:45
```

## 4. Agentic 解析与分块

### Agentic 解析（2026 演进）

传统机械 OCR 被淘汰（"Garbage In = Garbage Out"）：

| 方案 | 做法 | 适用 |
|---|---|---|
| Unstructured.io | 大规模标准文本批处理 | 常规文档 |
| LlamaParse / Docling | VLM 直接"看"页面图像，重绘表格为 Markdown/JSON | 财报/合同等复杂 PDF |

### Agentic 分块

```
固定大小分块（500 token/块）被视为"机械切肉"（破坏语义）
SOTA：根据内容语义密度自动调整分块大小
```

| 分块方式 | 特点 |
|---|---|
| 固定大小 | 简单但切断语义 |
| 语义密度自适应 | 密集处小块、松散处大块 |
| Agent 辅助 | LLM 判断块边界（贵但准） |

### Agentic 管线的代价

| 代价 | 说明 |
|---|---|
| 解析成本 | 视觉模型每页调用 |
| 分块成本 | LLM 判断边界 |
| 延迟 | 入库管线更重 |
| 收益 | 复杂文档质量显著提升（财报表格重绘） |

## 5. 多模态生成与跨模态对齐

### 跨模态对齐（统一向量空间）

```
CLIP 类模型：文本与图像映射到同一向量空间
→ "红色跑车" 与 跑车图片向量距离近
→ 图文联合检索成为可能
```

### 多模态生成

| 模态 | 检索后生成 |
|---|---|
| 图像 | 视觉 LLM 看图回答（GPT-4o/Qwen-VL） |
| 视频 | 帧序列 + 时间锚定 → 视觉 LLM |
| 音频 | 转写文本 + 原音频片段 |
| 图文混排 | 页面图像直接喂视觉 LLM |

### 图文混合检索示例（电商）

```
问题："带完工地下室和围栏院子的房子"
检索：文本（地下室/围栏）→ 候选房产
    + 图像（院子图片 patch）→ 视觉匹配
融合：跨模态评分 → 返回最匹配房产
```

## 6. 落地场景与代价

### 落地场景清单

| 场景 | 模态 | 关键设计 |
|---|---|---|
| 会议记录问答 | 音频 | ASR + 说话人分离 + 时间锚定 |
| 培训视频检索 | 视频 | 帧描述 + 事件三元组 |
| 财报/合同 | 图像+文本 | Docling 重绘表格 + ColPali |
| 客服录音分析 | 音频 | 转写 + 意图提取 |
| 医疗影像 | 图像+文本 | 影像特征 + 病史关联 |

### 落地代价

| 维度 | 代价 |
|---|---|
| 计算 | ASR + 视觉 LLM 帧描述（视频处理昂贵） |
| 存储 | 视频帧描述/三元组膨胀 |
| 管线复杂度 | 多流并行 + 时间对齐 |
| 评估 | 多模态测试集构建难 |

### 技术选型速查

| 内容类型 | 首选方案 | 备选 |
|---|---|---|
| 语音/会议 | ASR + 说话人分离 + 时间锚定 | 纯转写文本 RAG |
| 培训视频 | 帧采样描述 + 事件三元组 | 字幕文本 RAG |
| 图文混排文档 | Docling 重绘 + ColPali | OCR + 文本嵌入 |
| 监控视频 | 事件检测 + 时间锚定 | 人工标注 |
| 多语言音频 | 多语 ASR + 翻译后图谱 | 单语 RAG |

### 决策建议

```
先问：知识真的在音视频里吗？
├─ 有转写文本可用 → 文本 RAG 就够（别过度设计）
├─ 内容以画面为主（视频）→ 需要帧描述 + 图谱
└─ 内容在表格/图表（财报）→ Docling/ColPali 优先
```

## 7. 面试高频问法

| 问题 | 回答要点 |
|---|---|
| 音视频 RAG 怎么做？ | ASR 转写 + 视觉帧描述 → 三元组图谱（时间锚定） |
| 时间锚定是什么？ | 每个知识关联时间戳，回答可跳转到"第几分几秒" |
| Agentic 解析解决什么？ | 复杂 PDF 表格重绘（VLM 看图），替代机械 OCR |
| 跨模态检索怎么做？ | 统一向量空间（CLIP 类）+ 多路检索融合 |
| 什么场景才需要？ | 知识真在音视频/图表里——有转写就别过度设计 |
| 多模态生成模型？ | 视觉 LLM（GPT-4o/Qwen-VL），页面图像直接输入 |

### 面试加分表达

> "多模态 RAG 的关键不是'加个视觉模型'，而是时间锚定——让检索结果可跳转到原始音视频的精确时间点，这是文本 RAG 没有的验证能力。落地前先确认知识是否真的需要多模态，避免过度设计。"

## 8. 会议纪要场景实战案例

### 场景设定

```
企业周会录音 500 小时，员工要问：
"上次会上谁提了预算问题？""Q2 的目标有哪些变化？"
```

### 架构

```
录音 → Whisper 转写（含时间戳 + 说话人分离）
  → 三元组提取（人物/事件/决策/时间锚定）
  → 知识图谱 + 转写文本双索引
  → 查询：图谱查关系 + 文本检索细节
  → 回答：结论 + 跳转链接（"会议记录 23:40"）
```

### 设计要点

| 要点 | 说明 |
|---|---|
| 说话人分离 | 区分"谁说的"（回答归属问题） |
| 决策/待办提取 | 结构化动作项（不止问答，还产出待办） |
| 时间锚定 | 每个三元组带时间戳（溯源） |
| 增量入库 | 每周新录音只处理新增 |
| 权限 | 会议级别访问控制（机密会议不可查） |

### 收益

```
检索型问题：秒级回答（人工翻录音 10 分钟起）
溯源验证：点击跳到 23:40（信任建立）
待办提取：每周自动生成行动项清单
```

## 9. 多模态评估的特殊性

### 评估维度扩展

| 维度 | 文本 RAG | 多模态 RAG |
|---|---|---|
| 检索质量 | 文本相关 | 文本 + 视觉相关 |
| 转写质量 | — | WER（词错误率） |
| 描述质量 | — | 帧描述忠实度 |
| 时间精度 | — | 锚定偏移误差 |
| 端到端 | 四指标 | 四指标 + 多模态变体 |

### 测试集构建难点

```
多模态测试集更贵更难：
- 需要人工标注"答案出自哪段音视频的哪个时间点"
- 视觉问题需要图文对齐标注
- 建议：先小规模（20-30 问）验证可行性再扩展
```

### 评估工具

| 工具 | 用途 |
|---|---|
| WER | 转写质量 |
| 视觉问答基准 | 视觉理解质量 |
| 人工抽查 | 时间锚定准确性 |
| RAGAS 扩展 | 端到端（多模态语料） |

## 10. 多模态常见误区

| 误区 | 真相 |
|---|---|
| "录音必须上多模态图谱" | 有转写文本可用 → 文本 RAG 就够 |
| "视频全量帧描述" | 按场景/镜头采样描述，控制成本 |
| "ASR 转写即真相" | WER 误差进入下游——转写质量要先验 |
| "时间锚定可有可无" | 它是多模态 RAG 溯源与信任的核心 |
| "多模态评估和文本一样" | 多了转写/描述/时间精度三类维度 |
| "处理完一劳永逸" | 增量入库（新录音/新视频）持续维护 |

### 决策口诀

```
"知识真在音视频/图表里吗？"
├─ 有转写可用 → 文本 RAG（别过度设计）
├─ 内容以画面为主 → 帧描述 + 图谱
└─ 表格图表 → Docling/ColPali
```

> 🎯 核心要点：多模态知识图谱 = 音视频转写/描述 + 三元组提取 + 时间锚定——回答可精确溯源到"第几分几秒"；会议场景要加说话人分离与权限控制；多模态评估多出四类维度（转写/描述/时间精度）；决策口诀"知识真在音视频里吗"，有转写就别过度设计。
