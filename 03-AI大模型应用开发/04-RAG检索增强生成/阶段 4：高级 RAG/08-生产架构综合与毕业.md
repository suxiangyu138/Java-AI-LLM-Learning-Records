## 1. 全栈生产架构设计

### 2026 年生产参考架构（范式融合）

```
┌────────────────────────────────────────────┐
│ 查询入口                                     │
│  └→ Router（Agentic 路由）                  │
│     ├─ 简单问题 → 直接回答（省成本）          │
│     ├─ 事实查询 → 经典 RAG 路径              │
│     │   混合检索 → Rerank → 生成             │
│     ├─ 多跳/全局 → GraphRAG 路径             │
│     │   图谱检索 + 社区摘要（LightRAG）       │
│     ├─ 复杂文档 → 多模态路径（ColPali）       │
│     │   两阶段检索 → 视觉 LLM 生成            │
│     └─ 综合问题 → Agent 多步（反思循环）      │
├────────────────────────────────────────────┤
│ 数据层                                      │
│  文档 → 多模态解析 → 文本/图像向量 → 图谱     │
│  增量更新 + 治理监控（阶段 3）                │
├────────────────────────────────────────────┤
│ 评估与运维                                   │
│  RAGAS 四指标（CI 门禁）+ 漂移检测 + 成本监控  │
└────────────────────────────────────────────┘
```

### 架构设计原则（贯穿四阶段的总结）

| 原则 | 出处 |
|---|---|
| 评估先行 | 阶段 3 黄金纪律 |
| 一次一层 | 阶段 3 |
| 只留有收益的 | 阶段 3 累积提升表 |
| 范式按场景选 | 阶段 4 三问 |
| 数据治理优先 | 阶段 3（stale 数据是头号根因） |
| 成本分层 | 阶段 3 缓存/模型分层 |
| 安全评估 | 阶段 4（图谱提取攻击） |

## 2. 范式总选型决策树

```
我的场景？
├─ 知识形态
│   ├─ 纯文本 → 文本 RAG（经典）
│   ├─ 图表/扫描件 → 多模态（ColPali/Docling）
│   └─ 音视频 → 多模态图谱（时间锚定）
├─ 问题复杂度
│   ├─ 单跳事实 → 经典 RAG
│   ├─ 多跳/关系 → GraphRAG（LightRAG 起步）
│   └─ 多步多源 → Agentic RAG
├─ 语料规模与更新
│   ├─ 小语料单文档 → 长上下文
│   ├─ 百万级 → RAG（检索才可扩展）
│   └─ 高频变化 → 经典 RAG + 增量（LightRAG 若用图）
└─ 资源约束
    ├─ 有训练资源 + 垂直固定 → RAG 2.0 候选
    └─ 快速上线 → 经典 RAG 起步（范式后加）
```

### 决策组合示例

| 场景 | 推荐架构 |
|---|---|
| 企业客服 | 经典 RAG + 混合检索 + Rerank + 缓存 |
| 研报投研 | GraphRAG（LightRAG）+ ColPali + 数字校验 |
| 合同审查 | 长上下文融合（整章进窗口）+ 条款定位 |
| 培训视频问答 | 多模态图谱 + 时间锚定 |
| 医疗垂直问答 | RAG 2.0 联合训练 + 拒答防线 |

## 3. 综合实战：一个真实的架构选型

### 场景设定

```
某企业要建"制度问答系统"：
- 3000 份制度文档（政策类，每月更新）
- 问题：员工查政策（单事实为主）+ 高管要趋势总结（全局）
- 要求：答案必须可溯源、响应 <3s、成本可控
```

### 选型过程（照做）

```
① 知识形态 → 纯文本（无图表需求）→ 不需要多模态
② 问题复杂度 → 单事实为主 + 少量全局 → 经典 RAG + GraphRAG 全局路径
③ 语料更新 → 月更高频 → 增量索引必须（LightRAG 若用图）
④ 资源 → 无训练预算 → 不上 RAG 2.0
⑤ 结论：混合路由——事实走经典 RAG，趋势总结走 LightRAG 全局
```

### 架构落地清单

| 组件 | 选型 | 理由 |
|---|---|---|
| 检索基线 | 混合检索 + Rerank | 阶段 3 标配 |
| 全局路径 | LightRAG | 成本可控 + 增量 |
| 增量更新 | 内容指纹管线 | 月更高频 |
| 评估 | RAGAS + CI 门禁 | 质量防线 |
| 缓存 | L1 答案缓存 | 高频政策查询 |
| 溯源 | 元数据引用 | 硬性要求 |

### 实战产出格式

```
架构决策记录：场景 → 三问 → 范式 → 组件 → 验证
```

## 4. 四阶段知识全景图

```
阶段 1 概念：为什么/是什么/选哪个/演进
  ↓
阶段 2 闭环：加载→切片→向量化→检索→生成
  ↓
阶段 3 调优：评估先行→查询→检索→排序→数据→工程
  ↓
阶段 4 架构：Graph / Agentic / 多模态 / 融合 / RAG 2.0
```

### 一页总结（面试背诵版）

| 层 | 一句话 |
|---|---|
| 定位 | RAG = 知识外挂，事实基础设施 |
| 流程 | 索引→检索→生成，检索决定上限 |
| 调优 | 评估先行、一次一层、只留有收益的 |
| 混合 | BM25+向量+RRF，生产基线 |
| 重排 | 粗召回 50 + 精排 5 |
| 图 | 多跳/全局用 Graph，LightRAG 起步 |
| Agent | 路由+反思+多 Agent，成本三板斧 |
| 多模态 | ColPali 免 OCR，两阶段+量化 |
| 融合 | 先宽检索、再慷慨纳入 |
| 未来 | RAG 2.0 垂直端到端 |

## 5. 20 道自测题

### GraphRAG（1-6）

1. 纯向量 RAG 在复杂问答的准确率与 GraphRAG 对比？（<45% vs 89%+）
2. Local Search 与 Global Search 各自解决什么？
3. Global Search 的实现机制？（社区摘要 Map-Reduce）
4. GraphRAG 成本塌缩的两个关键版本与各自创新？
5. 多跳评测（IEEE 2026）的结论？
6. 图谱提取攻击是什么？影响多大？

### Agentic 与多模态（7-13）

7. Agentic RAG 相比传统 RAG 的核心能力？
8. Self-Reflection 循环的三个评估维度？
9. Agentic 成本控制三板斧？
10. ColPali 的核心机制？（页面 patch + MaxSim 延迟交互）
11. ColPali 的存储代价与对策？
12. 传统文档 RAG 的三重信息损失？
13. 时间锚定解决了什么？

### 长上下文与 RAG 2.0（14-17）

14. 长上下文替代不了 RAG 的四个理由？
15. Lost in the Middle 是什么？
16. 2026 融合共识是什么？（先宽检索、再慷慨纳入）
17. RAG 2.0 解决什么结构性矛盾？收益数据？

### 综合（18-20）

18. 范式选型三问？
19. 知识形态（文本/图表/音视频）分别对应什么范式？
20. 全栈生产架构的六个组件？

### 参考答案（简版）

1. <45% vs 89%+
2. Local 查具体事实；Global 做全局总结
3. 每个社区摘要 Map（评估相关）→ Reduce（汇总）→ LLM 回答
4. LazyGraphRAG 摘要延迟到查询时（查询省 700 倍）；LightRAG 双层索引免社区摘要（索引省 6000 倍）
5. LightRAG 混合架构 0.653 > 纯向量 0.542；实体整合与双层检索是关键
6. AGEA 黑盒查询可恢复 90% 实体关系，需鉴权限流审计
7. 路由决策/工具调用/多 Agent/反思验证/迭代优化
8. 检索充分性/答案依据性/完整性
9. 路由分流/轮数上限/模型分层
10. 整页分 32×32 patch 编码，查询 token 与 patch MaxSim 评分
11. 约 1000 倍单向量；量化/压缩（HPC/Light-ColPali）+ 两阶段检索
12. OCR 误差（85-90%）/图像转译损失（30-50% 语义）/上下文断裂
13. 答案可溯源到"第几分几秒"，精确验证 + 时序推理
14. 规模/更新/成本（100 倍级）/可审计性 + 注意力衰减
15. 长文中部信息被忽略（primacy/recency 效应）
16. RAG 宽检索文档集 + 长上下文容纳完整文档
17. 相似度 ≠ 有用性（检索生成目标不一致）；准确率 +31%、一致性 2.3 倍
18. 查询形态/语料结构/变更频率
19. 文本→经典；图表扫描→ColPali；音视频→多模态图谱
20. 路由/检索/图谱/多模态/评估/缓存监控

| 12-15 | 复习错题对应模块 |

## 7. 面试总攻略

### RAG 面试五问必会

```
① 什么是 RAG？（定义 + 三步）
② 为什么用 RAG？（三痛点 + 与微调/长上下文对比）
③ 怎么评估？（四指标 + 测试集 + 基线）
④ 怎么调优？（累积提升表 + 一次一层）
⑤ 高级范式怎么选？（三问 + 范式边界）
```

### 项目故事总模板（四阶段合成）

> "我做过一个制度问答系统：3000 份文档、月更。先建 50 问测试集量基线（precision 0.60），定位检索瓶颈后逐层调优——混合检索让 recall 到 0.75，Rerank 让 precision 到 0.78，HyDE 实测负收益撤掉。全局总结类问题加了 LightRAG 路径，趋势问答从答不出来到可回答。上线后 RAGAS 进 CI、答案缓存把成本降了 40%。"

### 面试禁忌

| 禁忌 | 正解 |
|---|---|
| 说"GraphRAG 一定更好" | 给评测数据 + 适用边界 |
| 只讲概念不讲数据 | 背关键数字（成本塌缩/准确率） |
| 没有决策故事 | 准备"撤掉 HyDE"这类决策 |
| 不懂代价 | 每种技术先说代价再说收益 |

> 🎯 四阶段毕业总标准：**概念能讲、代码能跑、调优有数据、架构有决策**——四项齐备，RAG 从入门到架构级，毕业。
