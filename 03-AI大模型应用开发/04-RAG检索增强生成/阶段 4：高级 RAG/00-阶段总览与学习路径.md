## 2. 高级 RAG 全景图

```
2026 年 RAG 范式版图
│
├── 经典 RAG（阶段 2/3）    向量 + 混合检索 + 重排
│   └── 适用：事实查询、知识库问答（仍是最广泛基线）
│
├── GraphRAG（01/02 篇）     知识图谱 + 社区摘要
│   ├── 微软 GraphRAG：Local + Global Search
│   ├── LazyGraphRAG / LightRAG：成本塌缩版
│   └── Agentic GraphRAG：路由 + 反思
│
├── Agentic RAG（03 篇）     Agent 决策 + 多步检索
│   ├── Router 路由 / Self-Reflection / 多 Agent
│   └── 适用：复杂多步问题、多知识库
│
├── 多模态 RAG（04/05 篇）   图像/PDF/音视频
│   ├── ColPali 延迟交互检索
│   ├── 多模态知识图谱（时间锚定）
│   └── 适用：财报/幻灯片/影像
│
├── 长上下文融合（06 篇）    先宽检索 + 慷慨纳入
│   └── RAG 检索文档集，长上下文容纳完整文档
│
└── RAG 2.0（07 篇）         检索器与生成器端到端联合训练
    └── 适用：垂直领域深度优化
```

### 范式的选择本质

```
不是"哪个更好"，是"哪个匹配场景"：
查询形态（查找型 vs 综合型）
语料结构（实体密集 vs 扁平）
变更频率（静态 vs 高频）
```

## 6. 2026 年格局一句话总结

| 范式 | 一句话定位 |
|---|---|
| 经典 RAG | 事实查询的事实标准（仍然最广泛） |
| GraphRAG | 复杂推理的答案——但用 LightRAG 的价签 |
| Agentic RAG | 让系统自己决定"怎么查" |
| 多模态 RAG | 让系统"看得见"文档（ColPali 免 OCR） |
| 长上下文融合 | 不是替代，是"先宽检索、再慷慨纳入" |
| RAG 2.0 | 端到端联合训练，垂直领域深挖 |

### 学习心态建议

```
高级 RAG 阶段最容易犯的错：用"追逐新名词"代替"理解决策逻辑"
正确心态：
  每个范式先问四个问题再学细节——
  ① 它解决什么问题？（动机）
  ② 它的代价是什么？（成本/延迟/复杂度）
  ③ 什么场景才值得？（适用边界）
  ④ 怎么验证它有效？（评估）
带着这四问读 01-07 篇，08 篇自然水到渠成
```

### 贯穿全阶段的核心认知

```
1. 高级 ≠ 更好：每种范式有自己的代价（成本/延迟/复杂度）
2. 评估不变：范式再高级，也要测试集与基线说话
3. 场景决定架构：先问"查询形态/语料结构/变更频率"三问
4. 2026 融合趋势：向量 + 图 + Agent 混合路由是生产常态
```

## 7. 常见疑问快答

| 疑问 | 回答 |
|---|---|
| GraphRAG 很贵吗？ | 2024 年贵（$33,000 大语料），2026 年成本塌缩三个数量级——LazyGraphRAG 查询成本低 700 倍、LightRAG 索引低 6000 倍 |
| 多模态必须用 ColPali 吗？ | 不必须——OCR+文本嵌入仍然便宜够用；ColPali 适合复杂文档（图表/幻灯片） |
| Agentic RAG 成本可控吗？ | 多轮调用成本线性上升，用"复杂度路由"控制（简单问题不走 Agent） |
| 长上下文会取代 RAG 吗？ | 不会——成本差 100 倍级、注意力衰减、可审计性都是 RAG 的底牌；融合是答案 |
| 学完能面试了吗？ | 本阶段补齐了"架构视野"——RAG 面试的最高阶问题都在这里 |

## 8. 常见失败画像与预防

| 失败画像 | 现象 | 预防 |
|---|---|---|
| 跟风堆范式型 | "GraphRAG 火就全上 GraphRAG" | 三问选型：查询/语料/变更 |
| 成本失控型 | 完整 GraphRAG 建全量社区摘要 | LightRAG/Lazy 起步 |
| 范式替代型 | 以为高级范式替代阶段 3 基线 | 混合检索仍是生产基线 |
| 多模态过度型 | 纯文本语料上 ColPali | 先确认"知识真在图表里吗" |
| 忽视安全型 | 图谱裸奔上线 | 图谱提取攻击防御（02 篇） |
| 无评估型 | 范式切换不看测试集 | 高级范式同样累积提升表 |

### 防失败三原则

1. **三问先行**：查询形态/语料结构/变更频率——不问就选型 = 赌博
2. **基线不变**：高级范式是"在基线上加"，不是"替代基线"
3. **数据说话**：范式再高级，也要自己的测试集验证
