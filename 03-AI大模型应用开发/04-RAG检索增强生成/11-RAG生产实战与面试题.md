## 2. 生产避坑 TOP 10

| # | 坑 | 现象 | 解决 |
|---|------|------|------|
| 1 | **切片太大** | 检索结果不精准 | chunk_size 500-800 |
| 2 | **未做查询改写** | 口语化问题检索不到 | LLM 改写 + Multi-Query |
| 3 | **只用 Dense 检索** | 专有名词/数字匹配差 | 加 BM25 混合检索 |
| 4 | **未加 Rerank** | 相关文档排在后面 | Cross-Encoder 精排 |
| 5 | **Embedding 模型混用** | 检索结果随机 | 入库和查询用同一模型 |
| 6 | **文档未预处理** | PDF 页眉页脚干扰检索 | 清洗管线 |
| 7 | **忽视元数据** | 无法按来源/时间过滤 | 索引时保留元数据 |
| 8 | **未做评估** | 不知道改好了还是改坏了 | RAGAS 定期评估 |
| 9 | **无缓存** | 重复查询反复检索+生成 | Redis 缓存高频问答 |
| 10 | **Prompt 未约束** | LLM 编造不在文档中的信息 | "只基于提供的资料回答" |

## 3. 性能优化清单

```text
RAG 性能优化路径：

  检索加速：
    □ 用 HNSW 索引替代 Flat
    □ 向量量化 (IVF+PQ)
    □ Embedding 缓存（SQLite/Redis）
    □ 预计算文档向量（离线批量）

  生成加速：
    □ 用 GPT-4o-mini 替代 GPT-4o（简单问题）
    □ 流式输出 (streaming)
    □ Prompt 压缩（精简 context）

  并发提升：
    □ 异步 Embedding 调用
    □ LLM 并发请求池
    □ 检索-生成流水线并行
```

## 4. 高频面试题

### Q1: RAG 的核心链路是什么？

```text
离线：文档加载 → 切片 → Embedding → 向量数据库
在线：用户问题 → Embedding → 向量检索 → Top-K文档 → 拼Prompt → LLM生成
```

### Q2: RAG 和微调有什么区别？什么时候用哪个？

```text
RAG：外挂知识库，即时更新，可溯源，成本低
微调：知识融入模型参数，需重训，不可溯源，但推理快

选择：
  知识频繁更新 → RAG
  领域风格固定 → 微调
  最佳 → RAG（知识）+ 微调（风格）
```

### Q3: 怎么提高 RAG 的检索精度？

```text
① 切片优化（合适的 chunk_size + overlap）
② 查询改写（LLM 改写口语化查询）
③ 混合检索（Dense + BM25）
④ Rerank（Cross-Encoder 精排）
⑤ 多粒度索引（小粒度检索+大粒度上下文）
```

### Q4: 怎么评估 RAG 系统的好坏？

```text
用 RAGAS 框架评估三个维度：
  ① Faithfulness：回答是否忠实于检索内容
  ② Answer Relevancy：回答是否切题
  ③ Context Precision/Recall：检索是否找到相关信息
```

### Q5: 如何处理 RAG 检索不到相关文档的情况？

```text
① 降低相似度阈值 → 放更多结果进来
② 查询改写 → 换角度搜索
③ 降级到 Web Search
④ 告诉用户"未找到相关信息"（优于编造答案）
⑤ 多路召回兜底
```

## 核心要点回顾

- 生产 RAG = API网关 + 混合检索 + Rerank + LLM + 缓存 + 评估
- TOP10 避坑：从切片大小到模型混用，从缺少评估到 Prompt 无约束
- 性能优化：检索加速（HNSW+缓存）+ 生成加速（小模型+流式）
- 面试核心：RAG链路、vs微调、检索精度提升、RAGAS评估
