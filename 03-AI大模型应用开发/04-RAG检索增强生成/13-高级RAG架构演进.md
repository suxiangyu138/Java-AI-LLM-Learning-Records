## 1. 五代演进全景

```text
RAG 五代演进（2023 → 2026）：

① Naive RAG（2023）
   文档 → 切块 → 向量化 → 相似检索 → 拼上下文 → LLM
   局限：查询表达差、召回噪声、无重排、无评估

② Advanced RAG（2023-2024）
   + 查询改写（HyDE/多查询）
   + 混合检索（BM25 + Dense + RRF）
   + 重排序（Cross-Encoder）
   + 元数据过滤、索引优化
   局限：仍是"固定流水线"——不能按问题动态调整

③ Modular RAG（2024）
   模块化流水线：索引/检索/融合/生成可插拔
   → 按场景组合模块（路由、任务分解、记忆模块可选）
   代表：LangChain/LlamaIndex 的组件化

④ Graph + Agentic（2024-2025）
   GraphRAG：实体/关系图谱 → 全局观（"总结三年战略演变"类问题）
   Agentic RAG：检索变成 Agent 的工具（自主决策/多跳/反思）
   代表：微软 GraphRAG、LlamaIndex ReActAgent

⑤ Contextual Retrieval（2026 Q2，Anthropic）
   给每个文档块生成"上下文描述"再编码
   → 检索失败率降 49%（+BM25+重排后 67%）
   代表：Anthropic 官方方案、开源化推进中
```

> 🎯 **核心要点**：演进主线 = "**从'查得全'（Naive→Advanced）到'查得对'（Modular）到'查得懂'（Graph/Agentic）到'块即上下文'（Contextual）**"——每一代都在解决上一代暴露的质量瓶颈。

## 2. Naive RAG 的局限与"死亡"讨论

**2026 年 4 月硅谷 AI Engineering Summit**：圆桌论坛《The Death of Naive RAG》——专家共识：**"文本切片 + 向量相似度"的朴素 RAG 在企业复杂知识处理上已"彻底破产"**。

**Naive RAG 的六大失效场景**：

| 场景 | 失效原因 |
|------|---------|
| 多跳推理（"报销政策里审批额度谁定"） | 单次检索拿不到跨文档链条 |
| 全局问题（"总结公司三年战略演变"） | 向量检索只回局部块，无全局视角 |
| 精确术语查询 | 语义检索对专名/编号召回差 |
| 查询-文档表述不一致 | "少年在瓜田刺猹" vs 文档里是"闰土" |
| 表格/PDF 复杂结构 | 切块破坏结构语义 |
| 检索噪声 | Top-5 里混入无关块 → 幻觉放大 |

**"死亡"讨论的工程含义**（不是 RAG 死了，是朴素 RAG 死了）：

```text
2026 年生产底线（不再可选的选项）：
  ✅ 混合检索（BM25 + Dense + RRF）—— 基础系统已覆盖
  ✅ Cross-Encoder 重排 —— 召回 20 → Top-5
  ✅ 查询改写（至少一种：HyDE/Step-back/分解）
  ✅ 评估体系（RAGAS 类）—— 没有评估的 RAG 无法迭代
可选进阶：
  → GraphRAG（全局问题）/ Agentic（多跳）/ Contextual（块质量）
```

> 🎯 **核心要点**：**"Naive RAG 之死" = "基础配置不再算配置"**——2026 年混合检索+重排+查询改写是入场券而非加分项。面试答"RAG 现状"时先引用这个讨论，再给生产底线清单 = 明显加分。

## 3. 2026 三大范式：Agentic / Graph / Memory

**2026 年知识引擎的"三驾马车"**（三种能力取向，可组合）：

| 范式 | 能力 | 核心机制 | 代表 | 适合 |
|------|------|---------|------|------|
| **Agentic RAG** | 自主性 | 检索即工具、任务分解、动态路由、自我反思 | LlamaIndex ReActAgent | 多跳/工具组合类问题 |
| **GraphRAG** | 全局观 | 实体/关系图谱 + 社区摘要 | 微软 GraphRAG（8 万+ Star） | 全局总结/关系推理 |
| **Memory** | 长期记忆 | 语义/情景/程序三层记忆 | Mem0、Zep | 跨会话个性化 Agent |

**三者如何协同**（2026 生产架构示例）：

```text
用户问题
  → Router（路由层）
    ├── 单点事实 → 向量 RAG（快）
    ├── 全局总结 → GraphRAG Global Search（图谱）
    ├── 多跳推理 → Agentic RAG（工具链 + 反思）
    └── 个性化/历史相关 → Memory 检索（Mem0/Zep）
  → 重排 + 上下文压缩 → LLM 生成
```

> 🎯 **核心要点**：三大范式不是竞争而是**互补**——"问题-策略映射"（什么类型的问题走什么检索路径）是 2026 年 RAG 架构设计的核心方法论（详见 05/06 模块）。

## 4. Contextual Retrieval：第五代核心（2026）

**Anthropic 于 2026 Q2 提出的方案**——解决"块脱离上下文"问题：

```text
问题：切块后每个块丢失文档语境
  例：块内容是"第 4 步：设置超时时间"
      —— 脱离文档后，检索系统不知道"第 4 步"属于哪个配置流程

解法：给每个块自动生成"上下文描述"（LLM 生成）
  块 + 上下文描述 → 一起编码（Embedding + BM25 都加）
  → 检索时块自带语境 → 命中率大幅提升
```

**效果数据（Anthropic 实测）**：

| 方案 | 检索失败率下降 |
|------|:-------------:|
| 仅 Contextual Embedding | -49% |
| + Contextual BM25 | -35%（累计更多） |
| + Reranking | **累计 -67%** |

**实现要点**：

```text
① 上下文描述生成：用 LLM 对"块 + 前后文/标题"生成 50-100 token 的语境描述
   （一次离线成本，索引时完成）
② 编码策略：embedding 模型对"上下文描述 + 块内容"联合编码
③ BM25 侧：同样使用增强后的文本
④ 与重排叠加：Contextual 解决"召回不到"，重排解决"召回不准"——互补
```

> 🎯 **核心要点**：Contextual Retrieval 的本质 = "**块质量工程**"——不换模型、不换检索算法，靠"给块补语境"把召回失败率砍半。它让 2026 年 RAG 的优化重点从"检索侧"转向"**索引侧（块 + 描述）**"。

## 5. 架构演进的方法论：问题-策略映射

**五代演进的终极方法论 = 按问题类型选策略**（2026 共识）：

| 问题类型 | 特征 | 推荐策略 |
|---------|------|---------|
| 单点事实查询 | "XX 的客服电话" | 向量 RAG + 混合检索 |
| 精确术语查询 | "MS-102 文档在哪" | BM25 优先 + 稀疏向量 |
| 多跳推理 | "A 的负责人审批 B 的预算" | **Agentic RAG**（工具链） |
| 全局总结 | "总结所有季度报告" | **GraphRAG Global** |
| 跨文档关系 | "哪些供应商参与过项目 X" | GraphRAG Local / 图谱查询 |
| 单文档深读 | "这份合同第 5 节说了什么" | **长上下文直接输入**（<1M token） |
| 多文档综合 | "对比三家方案" | 混合：检索 50K-200K 再推理 |
| 个性化/会话 | "我上次问过什么" | Memory 检索（Mem0/Zep） |

**架构决策的评估闭环**（贯穿本体系）：

```text
问题分类 → 策略选择 → 离线评估（黄金集）→ 指标对比 → 调整或换策略
（评估体系见 08 模块 —— 没有评估，策略选择就是"拍脑袋"）
```

> 🎯 **核心要点**：2026 年 RAG 架构师的日常 = "**问题-策略映射表 + 评估闭环**"——不是"用哪个框架"，而是"这种问题该走哪条检索路径"。这张映射表是本体系所有模块的公共骨架。

**映射表的使用流程**（生产落地四步）：

```text
① 问题分类：对线上查询日志打标签（单点/术语/多跳/全局/跨文档/会话）
   → 统计各类占比（决定投入方向：全局问题占 30% 才值得上 GraphRAG）
② 策略配置：为每类问题配置检索路径（向量/混合/图谱/Agentic/长上下文）
③ 评估验证：黄金集分类型评测（各类问题的 Hit Rate 单独看）
④ 迭代优化：按"占比 × 失败率"排序优化优先级（先打占比大且失败多的）
```

**2026 常见架构模式速查**（映射表的落地形态）：

| 模式 | 构成 | 适用规模 |
|------|------|---------|
| 基础混合 | 混合检索 + 重排 | 小型知识库（<10 万块） |
| 模块化 | + 路由 + 查询改写 + 缓存 | 中型生产（标准） |
| 增强 | + GraphRAG/Agentic 通道 | 复杂知识（全局/多跳占比高） |
| 全栈 | 双模态 + 图谱 + Agentic + 评估闭环 | 企业级文档智能 |

> 💡 演进不是"换架构"，而是"**按问题占比叠加能力**"——每个新模式都只为"映射表中某类问题"服务，用评估数据决定加不加。

**演进投入的量化决策**（2026 实践）：

```text
每项新能力上线的决策公式：
  投入收益 = 该类问题占比 × 该类问题当前失败率 × 能力带来的失败率降幅
            − 新增成本（索引/查询/运维）

示例：
  GraphRAG 投入 = 全局问题占比(30%) × 全局失败率(60%) × 预期降幅(50%)
               − 索引成本(数十美元/百万字 + 更新负担)
  → 占比低或更新频繁时算出来是负数 → 不上（用 LightRAG 或混合检索替代）
```

> 🎯 深化层的所有模块都遵循同一个决策逻辑：**先量化问题占比与失败率，再算能力投入的收益**——这也是本体系与基础系统最大的方法论差异。
