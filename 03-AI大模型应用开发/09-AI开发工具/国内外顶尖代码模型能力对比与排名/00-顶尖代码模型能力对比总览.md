## 1. 为什么需要代码模型专项对比

通用 AI 模型的综合评分 ≠ 代码能力评分。2026 年头部模型在不同代码基准上排名剧烈变化——同一个模型在 SWE-bench Verified 第一，在 SWE-bench Pro 可能掉到第五。

```text
为什么代码能力需要独立评估？

1. 代码是"精确的艺术"
   翻译错一个字可以接受，代码错一个符号就编译失败
   → 对模型的精确性要求远高于文本生成

2. 代码需要"工程化理解"
   不是生成孤立的函数，而是理解整个项目：
   包结构、依赖关系、设计模式、框架约定
   → SWE-bench Pro / DeepSWE 这类基准专门测这个

3. 代码有"生态壁垒"
   Claude Opus 5 写 Python 和写 Java 的体验完全不同
   对 Spring Boot 的理解 ≠ 对 FastAPI 的理解
   → 语言和框架生态深度差异巨大

4. 2026 年新趋势：Agent 编程能力
   GPT-5.6 Sol / Claude Sonnet 5 / Grok 4.5 都能"自主开发"
   但 A-CODE-LLM 基准显示：自主性和可靠性差距悬殊
```
