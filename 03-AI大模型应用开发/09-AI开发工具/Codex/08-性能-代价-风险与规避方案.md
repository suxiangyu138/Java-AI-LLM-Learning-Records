# 08 - 性能、代价、风险与规避方案

> 🎯 工程落地必须算的账——Codex 省时间但费 Token、强但有幻觉、快但不一定合规

---

## 1. 优势

1. **多语言覆盖全面**：Java/Python 后端开发适配度极高
2. **Token 效率高**：批量开发任务推理成本更低，约 Claude 的 1/4
3. **云端独立沙箱**：代码执行安全隔离，不污染本地环境
4. **完整 Agent 闭环**：自动测试、迭代修复，减少人工调试
5. **深度打通 OpenAI 生态**：可联网查阅最新技术文档

---

## 2. 缺陷与代价

### 代码幻觉

小众框架、内部私有 SDK 容易生成不存在的 API、错误调用逻辑。

**示例**：公司内部有一个 `com.company.internal.DataEncryptor` 类，Codex 不知道它的真实 API，会"编造"一个看起来很合理的但不存在的调用方式。

### 大型架构短板

百万行级复杂系统全局架构设计能力弱于 Claude Code。

### 开源合规风险

训练数据包含大量开源代码，生成代码可能存在许可证冲突：
- GPL 代码训练的模型 → 产出的代码是否受 GPL 约束？→ 尚无法律定论
- 企业使用需搭配开源代码扫描工具（如 FOSSA、Snyk）

### 资源成本

复杂工程长任务云端推理消耗大量 Token。估算：一个中等复杂度的 CRUD 模块（含测试）约消耗 50K-200K tokens → 约 $0.25-$1（GPT-4o 定价）。

### 安全隐患

输入包含数据库密钥、隐私业务数据时，存在数据泄露风险。

## 3. 规避方案

```text
① 输入需求尽量细化，明确框架版本、项目规范
   → "用 Spring Boot 3.2 + MyBatis Plus 3.5 + JDK 17"
   → 而非 "用 Spring Boot"

② 企业场景三件套：
   a) 人工代码审查（Codex 生成的每行代码 => PR Review）
   b) 开源合规扫描（FOSSA/Snyk 检测许可证冲突）
   c) 安全测试（SAST + 依赖 CVE 扫描）

③ 敏感凭证脱敏：
   → 数据库密码 → "your_password_here"
   → API Key → "your_api_key_here"
   → 真实用户数据 → 假数据

④ 超大项目分模块交付：
   → 不要一次让它重构整个项目
   → 按模块/按功能拆分，每次 3-5 个文件
   → 提升架构准确性

⑤ 联网搜索增强：
   → 开启联网后，新版本框架 API 准确率大幅提升
```

## 4. 成本优化策略

| 策略 | 做法 | 节省 |
|------|------|:---:|
| 任务分层 | 简单任务用 Codex CLI（免费） | 100% |
| 批量合并 | 多个小需求合并为一次会话 | 20-30% |
| 预缓存 | 相似项目结构用模板 | 10-20% |
| 选择模型 | 非关键任务用 GPT-4o-mini | 95% |

## 5. 风险矩阵

| 风险 | 概率 | 影响 | 缓解后风险 |
|------|:---:|:---:|:---:|
| 代码幻觉 | 中 | 中 | 低（Review + 规范约束） |
| 开源合规 | 中 | 高 | 中（扫描工具） |
| 数据泄露 | 低 | 高 | 低（脱敏） |
| 成本失控 | 中 | 低 | 低（监控+限流） |
