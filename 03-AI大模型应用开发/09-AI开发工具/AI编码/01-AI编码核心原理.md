# 01 - AI 编码核心原理

> 🎯 AI 怎么"猜"对你要写的代码？FIM 训练、Repo 级上下文、RAG 检索增强 — 这三个核心技术让 AI 补全从 5% 准确率提升到 35%+

## 1. 基础定义

**标准定义**：AI 代码补全是一种基于大语言模型的代码生成技术，根据当前编辑上下文预测开发者将要编写的代码。

**核心本质**：条件概率模型 — `P(下一段代码 | 当前文件 + 相关文件 + 光标位置)`。

**区分边界**：补全（实时嵌入 IDE）≠ 对话式编程（Chat 窗口交互）≠ Agent 模式（自主多步执行）。

## 2. 溯源历史

```text
2021: GitHub Copilot 基于 Codex(GPT-3 fine-tuned) → 准确率 ~25%
2022: Copilot 升级到 GPT-3.5 → 多文件上下文
2023: StarCoder/CodeLlama 开源模型 → 本地部署成为可能
2024: FIM 训练成为标配、Repo-level 上下文 → 准确率 ~35%
2025: Agent 模式 (Cursor/Copilot Agent) → 自主编辑+终端执行
```

**提出者**：GitHub/OpenAI — Codex 论文《Evaluating Large Language Models Trained on Code》(2021)

## 3. 底层原理

### FIM 训练 (Fill-in-the-Middle)

```text
传统自回归模型：只能根据上文生成下文
FIM 训练：根据"上文+下文"填补中间

训练格式：
  <PRE> 上文代码 <SUF> 下文代码 <MID> 被挖掉的代码

推理时：
  光标前代码 → <PRE> 部分
  光标后代码 → <SUF> 部分
  模型预测 → <MID> 部分（补全内容）
```

### Repo 级上下文检索

```text
补全不只依赖当前文件 → 要用整个仓库的信息

  技术栈：
  ① 代码索引：解析 AST/依赖图 → 找相关代码片段
  ② 语义检索：代码 Embedding → 相似功能检索
  ③ 最近编辑：最近修改的文件 → 权重更高
  
  上下文窗口管理：将最相关的文件拼接到 Prompt 中
```

## 4. 对比辨析

| 维度 | AI 补全 | 传统 IDE 补全 | 对话式编程 |
|------|:---:|:---:|:---:|
| 原理 | LLM 概率预测 | 静态分析+索引 | LLM 对话 |
| 粒度 | 行~函数级 | token~行级 | 文件~项目级 |
| 上下文 | 多文件+项目级 | 当前文件 | 用户描述 |
| 延迟 | 100-500ms | <10ms | 1-5s |
| 准确率 | 30-45% | 90%+(但范围小) | 取决于 Prompt |

**常见误区**：AI 补全不是"搜索已有代码"而是"生成新代码"。它可能生成训练数据中从未出现过的组合。

## 5. 价值与应用

- 核心作用：将重复性编码（CRUD/测试/模板）效率提升 3-10 倍
- 落地场景：日常编码加速、新语言学习、代码翻译、遗留系统重构

## 6. 性能与代价

- 推理延迟：100-500ms（超过 500ms 体验明显下降）
- 显存占用：7B 模型约 5-8GB（量化后）
- 优缺点：快但不可完全信任，需人工审查

## 7. 实操验证

```python
# FIM 训练的最小示例
prompt = "<PRE> def add(a, b):\n    <SUF>\n    return result <MID>"
# 模型预测: "result = a + b"
```
