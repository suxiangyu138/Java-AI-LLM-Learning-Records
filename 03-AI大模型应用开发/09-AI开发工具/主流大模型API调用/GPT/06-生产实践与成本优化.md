## 1. 显式缓存 Prompt Caching

```python
# GPT-5.6 支持显式缓存（prompt_cache_options）
response = client.responses.create(
    model="gpt-5.6-terra",
    input=[
        {"type": "message", "role": "user", "content": [
            {"type": "input_text", "text": LONG_SYSTEM_PROMPT,       # 稳定前缀
             "cache_control": {"type": "explicit", "ttl": "1h"}},    # ★ 显式缓存
            {"type": "input_text", "text": user_message}             # 动态部分
        ]}
    ]
)

# 查看缓存命中
print(response.usage.input_tokens_details.cached_tokens)
```

**缓存定价与 ROI：**

| 项 | 价格 | 说明 |
|----|:---:|------|
| 未缓存输入 | 标准价（$2.50/M Terra） | 基准 |
| **缓存读取** | **0.1× 标准**（90% 折扣） | 命中后极便宜 |
| 缓存写入 | 1.25× 标准 | 首次写入 |
| 保留时长 | 至少 30 分钟 | explicit + ttl |

**缓存策略：**
```text
① 稳定 system prompt / 知识库前缀 → 标记显式缓存
② 动态内容放后面（保持前缀一致 → 命中率高）
③ 监控 cached_tokens 确认命中
④ 相同前缀重复请求 → 大幅降本
```

## 2. Batch API 半价

```python
# 创建批量任务
batch = client.batches.create(
    input_file_id=file_id,              # 先上传 JSONL 文件（Responses 格式）
    endpoint="/v1/responses",
    completion_window="24h"
)
print(f"Batch ID: {batch.id}")

# 查询状态
status = client.batches.retrieve(batch.id)
print(status.status)                    # validating/in_progress/completed/failed

# 下载结果
if status.status == "completed":
    result = client.files.content(status.output_file_id)
```

**Batch 特性：**
- **50% 折扣**（所有 Token）
- 24 小时内完成
- 可与缓存叠加
- 适合：批量分类/翻译/评价/嵌入

## 3. 分层模型路由

```python
class GPTRouter:
    """按任务复杂度路由，省 60-80% 成本"""

    def route(self, task_type: str, input_text: str):
        if task_type == "simple":          # 分类/提取/路由
            return self.call("gpt-5.6-luna", "none")
        elif task_type == "standard":      # 对话/分析
            return self.call("gpt-5.6-terra", "medium")
        elif task_type == "complex":       # 代码/深度分析
            return self.call("gpt-5.6-terra", "high")
        else:                              # 极难/科研
            return self.call("gpt-5.6-sol", "xhigh")
```

**推荐分配（成本最优）：**

| 任务占比 | 模型 | effort | 说明 |
|:---:|------|:---:|------|
| 60% | Luna | low | 简单任务 $1/$6 |
| 30% | Terra | medium | 主力 $2.50/$15 |
| 8% | Terra | high | 复杂分析 |
| 2% | Sol | xhigh/max | 极难任务 $5/$30 |

## 4. GPT-5.5 → Terra 迁移指南

**OpenAI 官方警告："将迁移视为一次调优过程，而不仅仅是更改模型标识符。"**

```text
迁移五步：

① 抽取测试集：从生产日志抽取 20-50 个代表性任务
② 离线 A/B：同一任务分别用 GPT-5.5 和 Terra 跑
   对比：质量评分 + Token 计数 + 延迟
③ 调整 effort：Terra 建议尝试降低一档（可能仍保持质量）
④ 清理 Prompt：GPT-5.6 输出更简洁 → 移除"请简洁"等指令
⑤ 检查缓存：重新评估缓存使用情况（Terra 缓存价不同）

分层上线：
├── 常规批量任务 → Terra
├── 高难度任务 → 保留 Sol/GPT-5.5
└── 低难度高并发 → 降级 Luna
```

**迁移对比要点：**

| 对比项 | GPT-5.5 | Terra | 处理 |
|--------|---------|-------|------|
| 价格 | $5/$30 | **$2.50/$15（半价）** | 直接收益 |
| 上下文 | 200K | 1M | 规格对齐 |
| 输出 | 冗长 | **更简洁** | 清理 Prompt |
| 性能 | 83.4% | **84.3%**（Terminal-Bench） | 更强 |
| effort | 旧档位 | 新六档 | 重新测试 |

## 5. 限流与错误处理

```python
import time
from openai import RateLimitError

def call_with_backoff(fn, max_retries=5):
    for attempt in range(max_retries):
        try:
            return fn()
        except RateLimitError:
            wait = 2 ** attempt + 0.5
            time.sleep(wait)
        except Exception:
            raise
```

| 错误 | 处理 |
|------|------|
| 429（限流） | 指数退避 + 检查 Tier |
| 529（过载） | 退避重试 |
| 400（参数） | 检查 reasoning/effort/tools 格式 |
| 长上下文溢价 | >272K → 2× 输入 1.5× 输出，拆分请求 |
