## 1. MoE 架构核心参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 总参数量 | **~1T（万亿）** | 全部专家参数之和 |
| 激活参数 | **32B（320 亿）** | 每次推理实际参与的参数 |
| 专家数量 | **256** | 分工处理不同类型知识 |
| Top-K | **8** | 每次激活 8 个专家 |
| 上下文窗口 | 262,144 tokens（256K） | 输入=输出 |
| 输入模态 | 文本、图片、视频 | 多模态 |
| 架构基础 | K2 的打磨版 | 非全新架构 |

```text
MoE 的精髓：花 32B 的算力，获得 1T 参数的知识
├── 256 个专家 = 256 个"专科医生"
├── 路由网络 = "分诊台"（决定让哪 8 个专家处理当前 token）
└── 训练时专家共享 token → 知识复用，不重复学习
```

## 2. 256 专家与路由机制

```text
路由工作原理：

① token 输入 → 路由网络（router）计算 256 个专家的相关性得分
② 取 Top-8 专家（Top-K=8）
③ 8 个专家并行处理 → 加权求和输出
④ 不同 token 走不同专家 → 知识分工

路由的工程挑战：
├── 负载均衡：专家使用率不均 → 部分专家过载/闲置
├── 专家坍缩：部分专家学不到东西 → 需要正则约束
└── 训练稳定性：大规模 MoE 训练难收敛 → K2 系列已验证可行
```

**为什么 256 专家 + Top-8：**
- 更多专家 → 知识容量更大（总参数 1T）
- Top-8 激活 → 计算成本可控（激活 32B ≈ 中等模型成本）
- 训练数据量大时专家分工更细（代码/数学/中文/多模态各司其职）

## 3. 后训练专项优化

K2.6 是 K2 的"打磨版" — 针对三个方向做了专项后训练：

| 优化方向 | 解决的问题 | 效果 |
|----------|-----------|------|
| **工具调用稳定性** | Agent 场景工具调用频繁出错 | Toolathlon +79.9% |
| **长指令遵循** | 复杂多步指令执行不完整 | Terminal-Bench +31.3% |
| **多轮对话一致性** | 长对话中遗忘/跑题 | 13 小时编码不偏离 |

```text
后训练流水线（典型）：
├── SFT（监督微调）：用高质量"工具调用+推理轨迹"数据
├── RL（强化学习）：让模型学会"何时调用工具/何时停止"
├── 安全对齐：拒绝有害指令
└── 长程稳定性：模拟 4000+ 步 Agent 任务训练
```

## 4. 长程编码的技术支撑

**实测案例（K2.6 的核心卖点）：**

| 案例 | 时长 | 数据 | 结果 |
|------|:---:|------|------|
| Zig 语言优化 LLM 推理 | 12 小时 | 4000+ 次工具调用、14 轮迭代 | 吞吐从 ~15 → ~193 tokens/s（**12.9 倍**） |
| 重构金融撮合引擎 | 13 小时 | 迭代 12 种策略 | 中位吞吐提升 **185%** |

**长程编码的技术支撑：**

```text
① 长上下文（256K）→ 13 小时的任务上下文完整保留
② 稳定工具调用 → 4000+ 次命令执行不失控
③ 多轮一致性 → 每次迭代记住前一轮的结果和方向
④ 自主决策 → 遇到编译错误自动修复、重试、换方案
```

## 5. 多模态输入设计

| 模态 | 支持 | 典型场景 |
|------|:---:|------|
| 文本 | ✅ | 常规问答/编码 |
| 图片 | ✅ | 截图调试、图表理解、UI 审查 |
| 视频 | ✅ | 视频内容理解 |

**多模态应用示例：**
- 截图 → 定位 UI 布局 Bug → 给出 CSS 修复（K3 实测）
- 图片文档 → 提取信息 → 结构化输出
- 视频 → 内容摘要 → 事件识别
