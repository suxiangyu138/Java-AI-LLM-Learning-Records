# Claude Code 实战技巧与最佳实践

> **核心摘要**：如何用 Claude Code 事半功倍？有哪些隐藏技巧？生产环境怎么用？本文涵盖高效交互、项目配置、上下文管理、Git 工作流、安全实践等全方位指南。

---

## 1. 高效交互技巧

### 1.1 给 Claude Code 搭好"舞台"

| 好的做法 | 避免的做法 |
|---------|-----------|
| 项目根目录放 CLAUDE.md | 塞入无关文件浪费上下文 |
| .gitignore 排除 build/ 和 node_modules/ | 项目无 README 或 CLAUDE.md |
| 目录结构清晰，命名规范 | 文件和目录命名混乱 |

### 1.2 描述需求的高效方式

```
❌ 太模糊："帮我改一下登录功能"
✅ 好的："在 UserController 的 login 方法中，增加手机号验证码登录方式，
       复用现有的 JWT token 生成逻辑。验证码存在 Redis..."
```

### 1.3 利用管道模式

```bash
# 分析错误日志
cat error.log | claude -p "分析这些错误，按原因分类，给出修复优先级"

# 审查 staged 改动
git diff --cached | claude -p "review 这些改动，重点关注安全问题"

# 生成 commit message
git diff --cached | claude -p "为这些改动生成 conventional commit 格式的 message"
```

## 2. 上下文管理策略

| 操作 | 触发条件 |
|------|---------|
| `/compact` | 对话很长、Token 接近上限、AI 响应变慢 |
| Agent 子代理 | 探索性搜索、独立并行任务、需要上下文隔离 |

## 3. Git 工作流集成

```bash
# 日常开发流程
git status                        # 确认当前状态
"在 UserService.java 中增加 findByPhone 方法"
git diff                          # 查看改动
/commit                           # 自动生成规范 message
"push 到远程"

# PR 流程
/pr                                # 自动生成标题和描述
/review                            # 多层级代码审查
"修复 review 中指出的 NPE 问题"
```

## 4. 安全最佳实践

```json
{
  "permissions": {
    "deny": [
      "Bash(rm -rf *)",            // 递归删除
      "Bash(git push --force *)",  // 强制推送
      "Bash(git reset --hard *)",  // 强制重置
      "Bash(docker rm -f *)",      // 强制删除容器
      "Bash(curl *)",              // 外发请求
      "Bash(chmod 777 *)"          // 宽松权限
    ]
  }
}
```

## 5. 效率量化

| 任务 | 人工 | Claude Code | 节省 |
|------|------|-------------|------|
| 代码审查 + 修复 | 80 分钟 | 17 分钟 | ~80% |
| 全项目重构 | 数小时 | 数十分钟 | ~60% |
| 跨文件修改 | 30 分钟 | 5 分钟 | ~83% |

## 核心要点回顾

- 好的 CLAUDE.md = Claude Code 效率翻倍
- 描述需求 = 指定文件 + 明确边界 + 给出约束
- 管道模式：`cat file | claude -p "分析"`
- 权限配置：allow 读+搜索+git，deny rm+force push
- 提效命令：`/review` 审查、`/commit` 提交、`/pr` 创建 PR
- 多文件重构：分步进行，每步验证
