## 1. requirements.txt 的局限

```
问题：pip freeze 只锁定当前环境的全部包，不区分"你主动装的"和"被动拉进来的"

你有 requirements.txt:
  torch==2.4.0
  transformers==4.44.0
  numpy==1.26.4
  ... 共 50 个包

3 个月后重装 → 传递依赖变了 → 💥 行为不一致

解决方案：
  requirements.in (你主动装的)
       ↓ pip-compile
  requirements.txt (精确锁定的完整依赖树)
```

## 2. pip-tools 精确锁定

```bash
pip install pip-tools

# 1. 创建 requirements.in（只写直接依赖）
cat > requirements.in << 'EOF'
torch>=2.4.0
transformers
datasets
numpy<2.0
EOF

# 2. 生成锁定的 requirements.txt
pip-compile requirements.in
# → 生成 requirements.txt 含完整依赖树 + hash

# 3. 同步安装（确保环境与 lock 文件一致）
pip-sync requirements.txt

# 4. 更新依赖
pip-compile --upgrade requirements.in
```

```text
# 生成的 requirements.txt 示例
torch==2.4.1 \
    --hash=sha256:abc123...
transformers==4.44.2 \
    --hash=sha256:def456...
datasets==2.20.0 \
    --hash=sha256:ghi789...
numpy==1.26.4 \
    --hash=sha256:jkl012...
# ... 所有传递依赖全部锁定 + hash
```

## 3. 版本约束语法

| 语法 | 含义 | 示例 |
|------|------|------|
| `==1.2.3` | 精确版本 | `numpy==1.26.4` |
| `>=1.0,<2.0` | 范围 | `torch>=2.0,<3.0` |
| `~=1.4.2` | 兼容版本（≥1.4.2, <1.5.0） | `django~=4.2` |
| `!=1.2.3` | 排除版本 | `numpy!=2.0.0` |
| `>=1.0` | 最低版本 | `transformers>=4.40` |

```text
# requirements.in 最佳实践
# 1. 核心框架：精确范围
torch>=2.4.0,<2.5.0

# 2. 活跃库：宽松
transformers>=4.40

# 3. 稳定库：兼容锁定
numpy~=1.26.0

# 4. 工具库：宽松
black>=24.0
```

## 4. 依赖冲突解决

### 4.1 诊断

```bash
# 1. 检查当前环境冲突
pip check

# 2. 预检查（安装前看会不会冲突）
pip install --dry-run package==x.y.z

# 3. 查看依赖解析过程
pip install --verbose package

# 4. 可视化冲突
pipdeptree
# transformers 4.44.0
#   ├── numpy>=1.17 [required: >=1.17, installed: 2.0.0] ⚠️
```

### 4.2 解决策略

```text
Step 1: 定位冲突
  pip check → 找到冲突的包 A 和 B

Step 2: 查兼容矩阵
  A 的 setup.cfg/pyproject.toml → 看依赖约束
  B 的 setup.cfg/pyproject.toml → 看依赖约束

Step 3: 策略选择
  ├── 降级 A → 满足 B 的约束
  ├── 升级 B → 满足 A 的约束
  ├── 换替代包 → 用 C 替代 A
  └── 最后手段 → 把冲突的包设为 optional extra
```

## 核心要点回顾

- `pip freeze` 不精确，生产用 pip-tools 或 Poetry lock
- `pip-compile` + `pip-sync` = 确定性构建
- 版本约束四档：精确(==) / 范围(>=<) / 兼容(~=) / 宽松(>=)
- 冲突解决流程：定位 → 查矩阵 → 降级/升级/替换
