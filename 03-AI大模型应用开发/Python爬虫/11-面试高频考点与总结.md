## 1. 高频面试题

### Q1（⭐⭐⭐⭐⭐）: 动态渲染页面怎么爬？

> 1. 先 F12 Network 找 Ajax API → 直接请求 API（最优）
> 2. 找不到 API → Selenium / Playwright 模拟浏览器
> 3. 等待策略：显式等待 visibility / clickable → `networkidle` → `time.sleep()`（最后手段）
> 4. Playwright 优于 Selenium：内置自动等待、网络拦截、更快

### Q2: 遇到反爬怎么处理？

> 按低成本到高成本排查：
> 1. **Headers**：完整复制浏览器 Headers（包括 Sec-* 系列）
> 2. **频率**：加延迟（1-3s）+ 随机化
> 3. **IP**：代理池轮换
> 4. **验证码**：ddddocr（免费）→ 打码平台
> 5. **TLS 指纹**：curl_cffi impersonate（过 Cloudflare）
> 6. **终极方案**：Playwright 有头模式

### Q3: Scrapy 的架构？各组件干什么？

```text
Engine（引擎） → 控制数据流
Scheduler（调度器） → URL 去重 + 队列
Downloader（下载器） → 异步发送请求
Spider（爬虫） → 解析响应，提取数据和新 URL
Pipeline（管道） → 清洗 + 存储
Middleware（中间件） → 拦截请求/响应（IP/UA/重试）
```

### Q4: 同步 vs 异步爬虫的区别？什么时候用哪个？

| 维度 | 同步 (Requests) | 异步 (aiohttp) |
|------|:---:|:---:|
| 实现 | 顺序执行 | 协程并发 |
| 1000 页面耗时 | ~1000s | ~10s |
| 代码复杂度 | 低 | 中 |
| 适用 | < 100 页面 / 原型 | > 100 页面 / 生产 |

### Q5: 怎么保证数据不重复？

> 1. URL 去重：Bloom Filter（内存高效）→ Redis Set（分布式）
> 2. 数据去重：数据库 UNIQUE 索引 + ON DUPLICATE KEY UPDATE
> 3. 内容去重：对关键字段取哈希

### Q6: 爬虫怎么部署到服务器？

> 1. Docker Compose：crawler + MySQL + Redis 一条命令
> 2. 定时：APScheduler（Python）/ crontab（Linux）/ K8s CronJob
> 3. 监控：成功率 + 速率 + 失败率 → 企微/钉钉告警
> 4. 断点续爬：checkpoint 文件记录进度

### Q7: 爬虫的 robots.txt 要不要遵守？

> - 公开数据 + 个人学习 = 建议遵守 + 加延迟
> - 商业用途 = 必须评估法律风险
> - 原则：尊重 robots.txt + 不加服务器负担 + 不爬用户隐私数据

### Q8: IP 被封了怎么办？

> 1. 验证：curl 测试 → 确认是 IP 被封
> 2. 换 IP：ADSL 重拨 / 代理池 / 云函数（换出口 IP）
> 3. 降低频率：增加 DOWNLOAD_DELAY + 开启 AUTOTHROTTLE
> 4. 终极：住宅代理（贵但最真实）

## 2. 全系列知识地图

| 文件 | 一句话精华 |
|------|-----------|
| 01-HTTP基础 | 请求行+头+空行+体，Headers 是反爬第一关 |

| 08-数据存储 | executemany 批量写，Pipeline 清洗链，Bloom Filter 去重 |
| 09-AI+爬虫 | LLM 替代规则提取，DeepSeek ¥1 处理 1000 页 |

## 核心要点回顾

- 面试核心：架构设计能力 > 工具使用熟练度 > 反爬对抗经验
- 问题排查套路：URL 能访问吗？Headers 对吗？频率太快？IP 被封？JS 渲染？
- 爬虫架构 = 请求 + 解析 + 存储 + 调度 + 监控
- 工程化 = Docker + 定时 + 断点 + 告警
- LLM 是爬虫的倍增器：替代 80% 的规则编写工作
