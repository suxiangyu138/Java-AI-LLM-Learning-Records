## 1. 综合项目：智能客服 Agent（端到端）

**需求**：订单查询 + 物流跟踪 + 退款申请（确认制）+ 多轮会话，SSE 流式，DeepSeek/OpenAI 双供应商，成本可观测。

### 1.1 架构设计

```text
前端（SSE）→ FastAPI（/agent 流式端点）
              ├── 循环引擎（max 8 轮，工具错误回传）
              ├── 工具注册表（6 个工具：get_order / get_logistics /
              │                 search_orders / propose_refund /
              │                 execute_refund / ask_human）
              ├── 校验层（Pydantic + 业务规则 + 权限）
              ├── 供应商适配器（OpenAI / DeepSeek 双通道）
              └── 可观测（每轮日志 + 成本统计 + 审计）
```

### 1.2 核心代码（本体系全部能力的收口）

```python
# app/tools/order_tools.py —— 工具注册（04 章装饰器 + 05 章安全）
import json, uuid
from app.registry import tool, validate_args
from app.schemas import GetOrderArgs, ProposeRefundArgs, ExecuteRefundArgs
from app.models import PydanticOrderArgs


# ① 只读工具：查询订单
@tool(
    "get_order",
    "按订单号查询订单状态与物流。当用户询问订单进度、物流时使用。"
    "订单号必须是 11 位数字。",
    {"type": "object", "properties": {
        "order_id": {"type": "string", "description": "11 位数字订单号"},
        "limit": {"type": "integer", "default": 5, "minimum": 1, "maximum": 20}},
     "required": ["order_id"]},
)
async def get_order(order_id: str, limit: int = 5) -> dict:
    order = await repo.get_order(order_id)               # 业务校验
    if order is None:
        return {"error": {"code": "ORDER_NOT_FOUND", "message": "订单不存在，请核对订单号"}}
    return {"ok": True, "data": truncate(order.to_dict(), limit)}   # 截断（07 章）


# ② 危险工具：两段式（05 章 §5）
_pending_refunds: dict[str, dict] = {}

@tool("propose_refund", "提出退款方案（不执行）。所有退款必须先提议，用户确认后执行。", ...)
async def propose_refund(order_id: str, amount: float, reason: str) -> dict:
    order = await repo.get_order(order_id)
    if order.status not in ("pending", "paid"):
        return {"error": {"code": "STATUS_BLOCKED", "message": "当前状态不可退款"}}
    token = uuid.uuid4().hex[:12]                       # 一次性确认令牌
    _pending_refunds[token] = {"order_id": order_id, "amount": amount, "reason": reason}
    return {"ok": True, "proposal": {...}, "confirm_token": token,
            "message": "请向用户确认是否执行退款"}

@tool("execute_refund", "执行已确认的退款。仅当用户明确同意退款方案后调用。", ...)
async def execute_refund(confirm_token: str) -> dict:
    proposal = _pending_refunds.pop(confirm_token, None)
    if proposal is None:
        return {"error": {"code": "BAD_TOKEN", "message": "确认令牌无效"}}
    await payment.refund(**proposal)                     # 真实执行
    return {"ok": True, "data": {"refund_id": ...}}
```

```python
# app/agent/loop.py —— 循环引擎（03 章完整实现 + 07 章流式）
async def run_agent_stream(messages: list):
    for turn in range(MAX_TURNS):
        resp = await provider.chat(messages, tools=get_tools(), stream=True)
        msg, calls, reasoning = await assemble_stream(resp)   # 07 章 §1

        if not calls:                                   # 无调用 = 完成
            yield {"type": "text_delta", "content": msg.content}
            return

        for call in calls:                              # 工具执行
            yield {"type": "tool_call", "name": call.name}
            result = await safe_execute(call)           # 03 章错误回传
            yield {"type": "tool_result", "name": call.name, "ok": result.get("ok")}
            messages.append(build_result_msg(call, result))   # 02 章回传

        # DeepSeek 思考模式：回传 reasoning_content（07 章 §3）
        if reasoning:
            messages[-1]["reasoning_content"] = reasoning
    yield {"type": "error", "message": "已达最大轮数"}
```

```python
# app/main.py —— FastAPI 流式端点（07 章 §6 + FastAPI 体系）
from fastapi import FastAPI
from fastapi.responses import StreamingResponse
from app.agent.loop import run_agent_stream
from app.core.security import get_current_user

app = FastAPI()

@app.post("/agent")
async def agent_endpoint(req: UserMessage, user=Depends(get_current_user)):
    messages = [{"role": "user", "content": req.message}]
    async def gen():
        async for event in run_agent_stream(messages):
            yield f"data: {json.dumps(event, ensure_ascii=False)}\n\n"
    return StreamingResponse(gen(), media_type="text/event-stream")
```

### 1.3 验收指标

| 指标 | 通过线 |
|------|--------|
| 查询链路 | 查订单 → 物流 → 最终回答，2-4 轮完成 |
| 危险操作 | 退款必须"提议 → 用户确认 → 执行"三阶段，无绕过路径 |
| 错误自愈 | 订单号格式错 → 模型读错误后自行修正参数 |
| 安全 | 无 token 401；他人订单越权被拦；日志无敏感字段 |
| 流式 | SSE 四阶段事件（思考/调用/结果/回答）时序正确 |
| 成本 | 缓存命中下会话成本在预算内（日志可查每轮成本） |
| 双供应商 | 配置切换 OpenAI/DeepSeek 零代码改动（适配层） |

> 🎯 **核心要点**：项目把 02-09 章全部串起来——**协议（02）→ 循环（03）→ 工具设计（04）→ 安全（05）→ 模式（06）→ 流式（07）→ 适配（08）→ 成本（09）**。验收的关键不是"能对话"，是"危险操作有闸门、错误能自愈、成本可解释、平台可切换"。

## 2. 20 道自测题

**A. 概念题**

1. 模型真的执行函数吗？（不——只输出调用意图，执行永远是代码）
2. tool_calls 里的 arguments 是什么类型？（JSON 字符串，需 json.loads）
3. 为什么必须循环处理 tool_calls？（并行调用默认开启，可能有多个）
4. 回传工具结果用什么角色 + 什么配对键？（role=tool + tool_call_id）
5. tool_choice 四种取值与适用场景？（auto/required/指定/none）
6. strict 模式的三个硬性规则？（additionalProperties:false / 全 required / null 联合）
7. Anthropic 与 OpenAI 的三个字段差异？（input_schema / tool_use 块 / tool_use_id）
8. 为什么说"模型输出不可信"？（幻觉参数/提示注入/越权）

**B. 场景题（写代码/设计）**

9. 写出并行 tool_calls 的 asyncio 并发执行骨架。
10. 危险操作（退款）的两段式设计？
11. 工具结果超 4KB 怎么办？（截断 + _truncated + 总数 + 摘要）
12. DeepSeek thinking 模式多轮工具调用为什么 400？怎么修？
13. 提示注入的三层防线？
14. 工具 50+ 的三个处理方案？（角色拆分/工具发现/检索）
15. 写出工具注册表装饰器的骨架。
16. 缓存铁律哪五条？（不增删工具/固定排序/冻结 system/动态走消息/不换模型）

**C. 排查题**

17. 工具调用后模型"失忆"（回答与工具结果无关）？（assistant 消息没原样回传）
18. 同样的会话突然成本翻倍？（工具集被改动，缓存失效）
19. Agent 卡在循环里一直调用工具？（轮数上限缺失 + 错误没回传）
20. 某工具偶尔参数报错？（三层校验只做了 schema，没做 Pydantic/业务校验）

> 💡 自测标准：A 全对 + B 能写出来 + C 能定位 = 本体系毕业；B 卡壳回对应章节，C 卡壳回 02/03/05/09 章。

## 4. 高频面试题与答题范式

**Q1：Function Calling 的原理？**
> 范式：模型输出结构化调用指令（name + JSON 参数）→ 不执行 → 代码校验执行 → 结果回传 → 循环。强调"决策与执行分离"与 Agent 基石地位。

**Q2：tool_calls 处理有哪些坑？**
> 范式：① arguments 是 JSON 字符串要 loads；② 必须循环（并行调用）；③ assistant 消息原样回传；④ 结果按 tool_call_id 配对；⑤ 流式按 index 增量拼接。

**Q3：如何保证工具参数安全？**
> 范式：三层校验（strict 格式 → Pydantic 结构 → 业务语义/权限）+ 确认-执行模式 + 提示注入防线 + 审计。核心观点：模型输出不可信。

**Q4：并行调用怎么用？**
> 范式：无依赖并发（asyncio.gather 提速）；有依赖/严格模式/危险操作关 parallel_tool_calls；处理代码永远按数组。

**Q5：Agent 循环如何终止与容错？**
> 范式：零调用 = 自然出口；轮数 8-12 上限 + 预算兜底；工具错误转 JSON 回传（模型自愈）——"错误回传消除 80% 卡死"。

**Q6：如何控制 Agent 成本？**
> 范式：成本 = 轮数 × 全量上下文 × 单价；prompt caching（工具前缀稳定 + 断点，50-90% 降本）+ 工具结果截断 + 角色拆分 + 模型路由。

**Q7：DeepSeek/OpenAI/Anthropic 工具调用差异？**
> 范式：OpenAI 是事实标准（strict/并行/Responses）；Anthropic 块结构 + 显式缓存；DeepSeek OpenAI 兼容 + thinking 模式回传 reasoning_content 的坑；统一适配层收敛。

**Q8：提示注入怎么防？**
> 范式：威胁模型（数据夹带指令）→ 防线（工具结果标记为数据 + 危险工具绑定用户明确意图 + 参数白名单 + 权限收敛 + 人类确认）。
