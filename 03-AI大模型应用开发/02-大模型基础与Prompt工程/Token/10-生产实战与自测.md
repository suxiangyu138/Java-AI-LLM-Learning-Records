## 1. 实战：LLM 网关三合一

```python
# token_gateway.py —— 成本估算 + token 预算 + 窗口管理三合一
import tiktoken
from transformers import AutoTokenizer

# ① 按模型路由的计数器（08 篇第 3 节）
_OPENAI_ENC = {"gpt-5.4": "o200k_base", "gpt-4o": "o200k_base", "gpt-4": "cl100k_base"}
_OPENAI = {m: tiktoken.get_encoding(e) for m, e in _OPENAI_ENC.items()}
_HF = {"qwen2.5-7b": AutoTokenizer.from_pretrained("Qwen/Qwen2.5-7B")}

def count_tokens(model: str, text: str) -> int:
    if model in _OPENAI:
        return len(_OPENAI[model].encode(text))
    if model in _HF:
        return len(_HF[model].encode(text, add_special_tokens=False))
    raise KeyError(f"未知模型 {model}，先注册 tokenizer")

# ② 窗口管理器（07 篇三策略：截断兜底 + 压缩降级）
MAX_HISTORY_TOKENS = 8000
def trim_history(model: str, history: list[dict], max_tokens: int = MAX_HISTORY_TOKENS) -> list[dict]:
    """超限时丢最旧消息（保留首条与最近 5 条）。"""
    total = sum(count_tokens(model, m["content"]) for m in history)
    if total <= max_tokens:
        return history
    return [history[0]] + history[-5:]     # 首轮任务定义 + 最近 5 轮

# ③ 成本估算器（06 篇公式）
PRICES = {"gpt-5.4": {"input": 2.50, "output": 15.00, "cache": 0.25},
          "deepseek-v4-flash": {"input": 0.14, "output": 0.28, "cache": 0.0028}}
def estimate_cost(model: str, prompt_tokens: int, output_tokens: int, cache_hit: int = 0) -> float:
    p = PRICES[model]
    return ((prompt_tokens - cache_hit) * p["input"] + cache_hit * p["cache"]
            + output_tokens * p["output"]) / 1e6
```

**验收三问**：① 同一文本在 gpt-5.4 与 qwen2.5-7b 上计数不同（计数器按模型路由生效）；② 超长历史被截断且首轮保留（窗口管理生效）；③ 估算结果与真实 usage 对得上（成本公式正确）。

## 2. 生产纪律清单

- **锁版本**：tiktoken 0.13.0 锁死；tokenizer 文件哈希进 CI 指纹（08 篇第 4 节）；
- **按模型路由**：`count_tokens(model, text)` 统一入口，新模型先注册再上线；
- **客户端先截**：窗口超限客户端截断，不把 400 当兜底（07 篇第 5 节）；
- **usage 落库**：每次响应 usage 进日志/数据库，成本看板从 usage 聚合（06 篇第 4 节）；
- **稳定内容前置**：系统提示/工具定义放 prompt 开头且顺序固定（07 篇缓存纪律）；
- **预算三闸**：单次 max_tokens + 单租户月预算 + 日成本告警（06 篇第 5 节）；
- **升级必测**：模型/tiktoken 升级先跑同一批语料的 token 对比（05 篇第 6 节）。

## 3. 报错速查十条

| 报错 | 原因 | 修复 |
|------|------|------|
| KeyError: model not found（encoding_for_model） | 非 OpenAI 官方模型名 | 换 get_encoding 或 HF tokenizer（04 篇坑二） |
| ImportError: tiktoken / VC++ 14.0 | 未装/Windows 无编译器 | pip 安装；`onlybinary:all:` 强制 wheel |
| 计数突然变化（同代码同文本） | tiktoken 版本被升级 | 锁 0.13.0；对比新旧版本计数 |
| 生成乱码/答非所问 | tokenizer 与模型不匹配 | AutoTokenizer 用模型仓库对应版本（08 篇） |
| 400 context_length_exceeded | 输入超窗口 | 客户端 trim_history 后再发（07 篇） |
| 预算超支无告警 | usage 未落库/告警只看绝对值 | 落库 + 每千次请求成本趋势（06 篇） |
| 缓存命中率为 0 | 动态内容在 prompt 前面/工具顺序变 | 稳定内容前置 + 固定排序（07 篇） |
| 中文文本 token 数异常高 | 用英文系数估算 | 按语言分列估算 + 实测校准（05 篇） |
| 输出被截断一半 | max_tokens 过小 | 调大或流式；确认输出上限口径 |
| 成本看板与账单对不上 | 估算器当账单 | 以 usage 为结算口径（06 篇） |

（十类错误里环境与口径类占六成——**先查版本锁定与模型路由，再查业务逻辑**。）

## 4. 面试三范式

**范式一：价值式**——"我把应用的 token 成本降了 60%：输出 max_tokens 收紧 + 缓存命中率从 20% 提到 80%（稳定内容前置）+ 简单任务降级到 mini 档"——**用可量化的成本数字讲价值**（06 篇优化优先级）。

**范式二：原理式**——"token 是子词不是单词，byte-level BPE 从 256 字节起步保证零 <UNK>；模型慢在 decode 的串行，KV cache 按 token 吃显存——长上下文是显存与成本的双重账"——**展示算法与性能的深度**（02/09 篇）。

**范式三：工程式**——"我做了个网关：按模型路由计数、usage 落库出成本看板、窗口超限自动截断 + 缓存纪律保证折扣命中——成本与质量两条线都有数据"——**展示系统思维**（10 篇实战）。

**追问四连防身**：①"中文为什么 token 多？"——词表语料配比 + 单字信息密度，大词表收窄但不消除（05 篇）；②"tiktoken 升级为什么漂移？"——词表更新，同一文本编码结果变，生产锁版本（04 篇）；③"窗口越大越好吗？"——不是：显存（KV cache）、成本（1M 填满 $0.14-$5）、效果（长上下文"迷失在中间"）三面看（07 篇）；④"缓存命中率怎么提？"——稳定内容前置、工具固定排序、动态内容后置（07 篇第 6 节）。

## 5. 简历呈现

**项目写法示例**："基于 tiktoken 0.13 + HF tokenizers 构建 LLM 网关：按模型路由的 token 计数器（OpenAI 系/开源系分线），usage 落库驱动的成本看板（模型 × 租户 × 功能三维），窗口管理器（截断兜底 + 摘要降级 + 缓存命中率 80%）；上线后单次请求成本降 60%、成本预测误差 <5%"——**要点：版本精确、路由清晰、数字量化、双向收益（成本 + 质量）**。
