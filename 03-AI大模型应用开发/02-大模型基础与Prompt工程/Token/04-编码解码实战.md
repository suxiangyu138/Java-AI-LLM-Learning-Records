## 1. 工具全景：tiktoken / HF tokenizers / puretiktoken

**计数场景三选一**：**tiktoken**（OpenAI 官方，Rust 核心，5.7-8.1M tok/s——**OpenAI 系模型计数标准**）；**HF tokenizers**（HuggingFace 的 Rust 实现，`AutoTokenizer` 背后的引擎——**非 OpenAI 模型（Llama/Qwen/DeepSeek）计数标准**）；**puretiktoken**（2026 新工具，零依赖纯 Python，逐字节兼容 tiktoken——**受限环境/无 Rust 轮子的地方**）。**选型主线**：**模型是哪家的就用哪家的 tokenizer**——OpenAI 系用 tiktoken、开源系用 HF——"**tokenizer 跟着模型走，工具跟着 tokenizer 走**"（08 篇详讲）。

## 2. tiktoken 安装与版本锁定

```bash
pip install "tiktoken==0.13.0"
```

**版本纪律是 2026 第一课**：tiktoken 快速迭代（0.7 → 0.12 → 0.13，一年内多个版本），**升级可能让同一文本的 token 计数漂移最高 ±12%**（词表更新）——**成本预测、预算告警、prompt 长度校验全部依赖稳定的计数，生产必须锁版本**；锁法：`requirements.txt` 写死 + CI 里 `pip check` 验证。**Windows 安装坑**：报 "Microsoft Visual C++ 14.0 required" 时用 `pip install onlybinary:all: tiktoken` 强制预编译 wheel（00 篇误区三的实操版）。装完验证：

```bash
python -c "import tiktoken; print(tiktoken.__version__)"   # 0.13.0
```

锁版本后把 tiktoken 与 transformers 的版本一起写进环境清单——**"tokenizer 版本指纹"是环境指纹的一部分**（08 篇版本纪律）。

## 3. 核心 API

```python
import tiktoken

# ① 拿编码器：两条路
enc = tiktoken.get_encoding("o200k_base")          # 直接按编码名（快）
enc = tiktoken.encoding_for_model("gpt-5.4")       # 按模型名映射（慢一点，首次查表）

# ② 编码：文本 → ID 列表
ids = enc.encode("Hello world")
ids_with_special = enc.encode("Hello <|endoftext|>", allowed_special="all")

# ③ 解码：ID → 文本
text = enc.decode(ids)                             # 无损还原
text = enc.decode_single_token_bytes([ids[0]])     # 单个 token 的原始字节

# ④ 词表信息
n = enc.n_vocab                                     # 词表大小（o200k_base = 200,019）
```

**四个关键点**：其一，**`get_encoding` 比 `encoding_for_model` 快**——前者直取，后者先按模型名查表（高吞吐场景用前者）；其二，**`allowed_special` 控制特殊 token 处理**——默认特殊 token 文本会被拆成普通子词，显式声明才按特殊 token 编码——**"模型名变了就换编码"**：gpt-4o/GPT-5 系用 o200k_base，GPT-3.5/GPT-4 用 cl100k_base；其三，**decode 是无损的**——encode 后 decode 必还原原文（byte-level 的保证）；其四，**count 高频写法**：`len(enc.encode(text))`——**别自己造轮子，encode 的返回长度就是权威计数**。

**编码的完整链路**（与 API 调用衔接）：**① 组装文本**（messages → 模板拼接，07 篇）→ **② encode 计数**（预算检查：超窗口先 trim，07 篇）→ **③ 调 API** → **④ 响应后对账**（usage 的 prompt/completion 与你预估的差距，06 篇）——**"计数不是终点，是预算与对账的输入"**；**round-trip 验证**：`enc.decode(enc.encode(text)) == text` 恒真（byte-level 保证），但**特殊 token 场景要带 allowed_special 重跑**——"**验证写进测试，别等生产炸**"。

## 4. HF AutoTokenizer 侧

```python
from transformers import AutoTokenizer

tok = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-7B")   # 开源系标准入口
ids = tok.encode("你好世界", add_special_tokens=True)     # 默认加 BOS/EOS
count = len(tok.encode("你好世界", add_special_tokens=False))

# 聊天模板（角色 token 的正确打开方式，03 篇坑三）
msgs = [{"role": "user", "content": "你好"}]
input_ids = tok.apply_chat_template(msgs, tokenize=True, add_generation_prompt=True)
```

**与 tiktoken 的差别**：**HF 侧的 encode 默认加特殊 token**（add_special_tokens=True），tiktoken 默认不处理——**计费时注意口径**：API 计费包含特殊 token 吗？**以供应商文档为准，估算时建议都算上**（06 篇）；`apply_chat_template` 是模板的权威实现——**"手拼模板 = 自己发明语言"**（03 篇坑三）。**tokenizer 文件随模型仓库发布**——`tokenizer.json`/`tokenizer.model`/`tokenizer_config.json`，**版本与模型权重同仓库同版本**（08 篇版本纪律）。

**开源模型的计数口径**：**用 AutoTokenizer 数开源模型文本时，注意聊天模板本身会加 token**（角色标记、BOS/EOS）——**"模板的 token 也是 token"**：估算实际请求成本时，`apply_chat_template` 后的完整输入再计数，别只数消息正文（07 篇窗口账本同源）。

## 5. 性能：缓存与吞吐

```python
# 首次实例化约 50ms（加载词表），之后调用微秒级
enc = tiktoken.get_encoding("o200k_base")    # 模块级缓存，别在热路径里重复取

# 批量编码（比循环单条 encode 快）
texts = ["..." for _ in range(1000)]
ids_list = enc.encode_batch(texts)
```

**性能三招**：其一，**缓存 encoding 对象**——首次加载约 50ms，热路径反复 `encoding_for_model` 是白送延迟；其二，**`encode_batch` 批量编码**——一次调用处理一批文本（Rust 层批量），比循环快数倍——**批量计数/批量 prompt 长度校验的标配**；其三，**能复用就用计数缓存**——同一 prompt 多次调用时按 prompt 哈希缓存 token 数（06 篇预算中间件）。**吞吐参考**：tiktoken Rust 核心 5.7-8.1M tok/s——**计数几乎不成为瓶颈**；卡瓶颈时查是不是在热路径里反复取编码器。

**计数的准确性 vs 性能的权衡**：encode 是精确计数，但几十万字符的大文本仍有毫秒级成本——**超长文本快速预检**：先按"字符数 × 语言系数"粗估（05 篇），接近窗口边界再精确 encode——"**粗筛用系数，精算用 encode**"；**计数缓存**：同一 prompt 多次调用时按内容哈希缓存 token 数——"**聊天场景的提示词长度检查从'每次重算'变'查表'**"，长会话每轮检查的延迟基本归零。

## 6. 受限环境的替代：puretiktoken

**puretiktoken（2026 新工具）**：零依赖纯 Python、**逐字节兼容 tiktoken**（cl100k_base/o200k_base 的 encode/decode 结果与官方一致），**运行在 Pyodide/WASM、ARM/musl、离线沙箱**等 tiktoken 装不了的环境。性能：0.7-1.3M tok/s（比 Rust 版慢 7-15 倍）——**"受限环境的救命稻草，正常环境还是用官方版"**。同类还有 **turbobpe**（预编译 BPE wheels，含 CPython 3.14t）。**选型判断**：能装官方 tiktoken 就用官方（性能 + 生态）；**装不了再 puretiktoken**——"**替代品解决'能不能跑'，官方版解决'跑得稳'**"；CI/离线环境的用法：**把 puretiktoken 预装进镜像**，测试断言用它做"逐字节一致的计数回归"——"**官方版跑生产，puretiktoken 跑受限环境与回归**"。

## 7. 八个常见坑

- **坑一**：tiktoken 不锁版本——升级计数漂移 ±12%，成本预测全乱；**锁 0.13.0**（第 2 节）；
- **坑二**：`encoding_for_model("claude-sonnet-4.6")`——**KeyError；只认 OpenAI 官方模型名**，其他厂商用 HF tokenizer（第 4 节）；
- **坑三**：拿 tiktoken 数开源模型的文本——**tokenizer 不同，数字不可比**（08 篇）；开源模型用 HF；
- **坑四**：`encode` 不传 `allowed_special`——特殊 token 文本被拆碎；**需要按特殊 token 处理时显式声明**；
- **坑五**：热路径里反复 `encoding_for_model`——**首次查表 + 实例化开销；模块级 get_encoding 一次**；
- **坑六**：单条循环 encode 千条文本——**encode_batch 批量处理**（第 5 节）；
- **坑七**：推理模型（o1/o3 类）用 tiktoken 数完就当账单——**显示 token 数与计费数可能不同，以 API usage 为准**（06 篇）；
- **坑八**：Windows 装 tiktoken 报 VC++ 错——**onlybinary 强制预编译 wheel**（第 2 节）；
- **坑九**：数开源模型文本只用消息正文——**聊天模板会加角色/BOS token；apply_chat_template 后计数**（第 4 节）；
- **坑十**：round-trip 验证不带特殊 token 场景——**生产炸了才发现 allowed_special 漏配；测试覆盖特殊文本**（第 3 节）。
