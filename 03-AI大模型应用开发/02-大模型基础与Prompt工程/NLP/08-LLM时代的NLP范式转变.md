## 1. 范式的根本变化

```text
传统 NLP 范式：

  ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
  │ 数据收集  │ → │  数据标注  │ → │ 训练模型  │ → │  部署推理  │
  │ (万-百万) │   │ (人力+$$) │   │ (GPU天)  │   │ (专用服务) │
  └──────────┘   └──────────┘   └──────────┘   └──────────┘

  每个任务重复一次 → M 个任务 = M 个模型 = M 倍成本

LLM 新范式：

  ┌──────────┐   ┌──────────┐   ┌──────────┐
  │ Prompt   │ → │   LLM    │ → │   结果    │
  │ (几句话)  │   │ (通用模型)│   │ (直接使用)│
  └──────────┘   └──────────┘   └──────────┘

  M 个任务 = 1 个模型 + M 个 Prompt → 成本接近常数
```

### 核心转变对比

| 维度 | 传统 NLP | LLM 时代 |
|------|----------|----------|
| **任务切换** | 训练新模型 | 换 Prompt |
| **数据需求** | 几千~百万标注数据 | 0~几条示例 |
| **模型数量** | 每个任务一个 | 一个通用模型 |
| **开发周期** | 数天~数周 | 数分钟~数小时 |
| **技能重心** | 模型训练/调参 | Prompt Engineering/RAG |
| **精度上限** | 专用模型高 | 通用模型高+ |
| **灵活性** | 固定任务 | 任意自然语言指令 |

## 2. 哪些 NLP 任务被颠覆

### 2.1 被完全重塑的任务

| 任务 | 传统方式 | LLM 方式 | 颠覆程度 |
|------|----------|----------|:---:|
| **文本分类** | BERT 微调 | 零样本 Prompt | ⭐⭐⭐⭐⭐ |
| **情感分析** | 专用分类器 | "判断这条评论的情感" | ⭐⭐⭐⭐⭐ |
| **NER** | BiLSTM-CRF | "提取所有人名和地名" | ⭐⭐⭐⭐⭐ |
| **文本摘要** | Seq2Seq | "总结以下内容" | ⭐⭐⭐⭐⭐ |
| **机器翻译** | NMT 模型 | "翻译成英文" | ⭐⭐⭐⭐ |
| **问答** | 检索+抽取 | RAG → LLM 生成 | ⭐⭐⭐⭐⭐ |

### 2.2 新出现的能力

```text
LLM 带来的 NLP 新范式：

① 指令遵循：模型理解自然语言指令而非固定API
   "用幽默风格写一封辞职信" — 传统系统无法处理

② 上下文学习 (In-Context Learning)：
   给几个示例 → 模型学会模式 → 无需微调

③ 思维链推理 (Chain-of-Thought)：
   "让我们一步步分析" → 模型展示推理过程

④ 工具使用 (Tool Use / Function Calling)：
   模型决定何时调用外部 API/数据库/Search
```

## 3. 哪些 NLP 技术仍有价值

```text
LLM 没有"消灭"传统 NLP，而是重新定位了它们的价值：

仍有价值的：

  ✅ 分词/Tokenizer — LLM 底层就是 BPE Tokenizer
  ✅ 文本清洗管线 — 预处理仍需要（去除 HTML/特殊字符）
  ✅ TF-IDF/BM25 — 混合检索中的关键词匹配组件
  ✅ 向量数据库 — RAG 的核心基础设施
  ✅ Embedding 模型 — BGE-M3 等专用 Embedding 模型
  ✅ 评估指标 — BLEU/ROUGE/F1 仍用于自动化评估

被替代的：

  ❌ 为单个任务训练专用分类模型（BERT 微调可能被 Prompt 替代）
  ❌ 复杂特征工程（LLM 自动提取特征）
  ❌ 规则式 NLP 系统（正则匹配除外）
```

## 4. NLP 工程师的技能转型

```text
传统 NLP 工程师技能集：
  → 分词/词性标注/NER
  → 特征工程（TF-IDF/N-gram/句法特征）
  → 模型训练（BiLSTM/BERT微调）
  → 评估（交叉验证/错误分析）

LLM 时代 NLP 工程师技能集：
  → Prompt Engineering（最重要！）
  → RAG 架构设计（检索+生成）
  → 模型选型与评估（选择合适 LLM）
  → Agent 设计（工具调用/任务编排）
  → 数据工程（RAG 文档处理/清洗）

传统技能没有白费：
  ✅ 理解 NLP 任务本质 → 写出更好的 Prompt
  ✅ 理解评估指标 → 正确验证 LLM 输出
  ✅ 理解分词/Embedding → 优化 RAG 检索
```

## 5. 未来展望

```text
NLP 的未来趋势：

① 模型继续变大 → 更多任务被"吞并"
   分类/NER/翻译 → 全被 LLM 吸收

② 多模态统一
   文本+图片+语音 → 一个模型处理所有

③ Agent 自主化
   LLM 不仅是"回答问题"，而是"执行任务"

④ 小模型逆袭
   Phi-3 / Qwen-1.8B → 手机/边缘设备跑 NLP

⑤ 领域特化
   虽然通用 LLM 很强，但金融/医疗/法律仍需领域适配

对 Java 后端+LLM 开发者：
  → 学好 Prompt Engineering 和 RAG → 这是 LLM 时代的编程语言
  → 传统 NLP 知识作为"内功" → 帮助更深理解 LLM 的能力和边界
```

---

## 核心要点回顾

- LLM 统一了 NLP 任务 → Prompt 替代了模型训练
- 传统 NLP 中分词/Embedding/评估指标仍有价值
- NLP 工程师技能转型：从训练模型 → Prompt Engineering + RAG
- 被颠覆的是"为每个任务训练模型"的模式，而非 NLP 的基本原理
