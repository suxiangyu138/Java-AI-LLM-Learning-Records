## 1. 框架演进史

```text
深度学习框架十年：

  2012 — Caffe (Berkeley)：第一个流行的 DL 框架
        → 配置文件定义网络，不需要写代码
        → 统治 CV 领域 2012-2016

  2015 — TensorFlow (Google)：工业级分布式训练
        → 静态计算图 → 先定义再运行
        → 统治工业界 2016-2019

  2016 — PyTorch (Facebook/Meta)：动态计算图
        → Define-by-Run → 写 Python 就是建图
        → 学术圈迅速接受 → 2020 年后全面超越 TF

  2018 — TensorFlow 2.0：紧急转向动态图（Eager Execution）
        → 但为时已晚，PyTorch 生态已成

  2020 — JAX (Google)：函数式 + 自动微分 + JIT 编译
        → Google 的新赌注（替代内部 TF 使用）
        → TPU 上性能极致

  2023 — PyTorch 2.0：torch.compile() 追赶 JAX 的编译优势
        → 补齐性能短板
```

## 2. PyTorch vs TensorFlow 深度对比

| 维度 | PyTorch | TensorFlow |
|------|---------|------------|
| **设计哲学** | Pythonic、直觉优先 | 工程化、生产优先 |
| **计算图** | 动态图（Define-by-Run） | 静态图→动态（TF2） |
| **调试** | Python 原生 pdb ✅ | tf.debugging（TF1 地狱） |
| **部署** | TorchScript/ONNX | TF Serving/TFLite |
| **生态** | HuggingFace/LLaMA/vLLM | 仅 Google 内部 |
| **学术论文** | 90%+ 使用 | 罕见 |
| **API 稳定性** | 良好 | TF1→TF2 大迁移灾难 |
| **LLM 支持** | **统治地位** | 几乎为零 |

### PyTorch 胜出的关键原因

```text
① 动态图 → 调试友好
   写 PyTorch = 写 Python → print/breakpoint 直接工作
   写 TF1.x = 建图 + Session.run() → 两步分离，调试噩梦

② 学术圈选择 → 正向飞轮
   论文用 PyTorch → 开源模型用 PyTorch → 工业界跟进
   → HuggingFace/LLaMA/LoRA 全部 PyTorch

③ API 设计
   PyTorch：Pythonic，符合程序员直觉
   TF：过度工程化（tf.data/tf.estimator/tf.keras 多套API混乱）

④ TF1→TF2 迁移灾难
   破坏性 API 变更 → 大量项目困在 TF1 → 加速转向 PyTorch
```

## 3. JAX：新的挑战者

```text
JAX = 函数式 + XLA 编译 + NumPy 接口

核心特性：
  ✅ 函数式编程（无副作用 → 可 JIT 编译）
  ✅ jit() 编译 → 接近手写 CUDA 的性能
  ✅ vmap() 自动向量化 → 无需手写 batch 维度
  ✅ pmap() 自动并行 → 多 GPU 简单

劣势：
  ❌ 函数式思维门槛高（无 PyTorch 的直觉性）
  ❌ 生态远不如 PyTorch
  ❌ 调试困难（编译后的代码无法交互调试）

当前定位：
  Google DeepMind → 全部用 JAX（Gemini/Gemma 训练）
  前沿研究 → 需要极致性能的场景
  LLM 应用开发 → 仍以 PyTorch 为主
```

## 4. LLM 时代的框架格局

```text
LLM 全栈的框架选择：

  预训练：      PyTorch (80%) + JAX (20%，主要在 Google)
  微调：        PyTorch + HuggingFace (统治)
  推理：        vLLM / TensorRT-LLM (底层 PyTorch)
  量化：        llama.cpp / GGUF (C++，独立)
  Agent/RAG：   LangChain / LlamaIndex (上层，底层调 PyTorch/API)

结论：LLM 开发 = PyTorch。JAX 是前沿研究选项，非工程首选。
```

## 5. Java 后端的 DL 框架选择

```text
Java 后端部署 DL 模型的主要路径：

  ① 独立推理服务（推荐）
    PyTorch 训练 → vLLM/Ollama 部署 → Java HTTP 调用
    → 语言无关，最灵活

  ② ONNX Runtime Java
    PyTorch → ONNX → ONNX Runtime Java API
    → 直接嵌入 Java 进程，适合小模型

  ③ DJL (Deep Java Library)
    AWS 出品 → 统一 PyTorch/TF/ONNX 的 Java API
    → 但社区活跃度有限

  ④ TensorFlow Java
    → TF 在 Java 端几乎已死，不推荐

  推荐方案：
    大模型 → 独立部署 + HTTP/gRPC 调用
    小模型（<100MB）→ ONNX Runtime Java
```

## 6. 2026 框架格局：PyTorch 2.x 与 JAX 现状

**框架现状（2026 检索核实）**：

| 维度 | PyTorch（2.12） | JAX（0.9.x） |
|------|:---------------:|:------------:|
| 归属 | PyTorch 基金会/Linux 基金会 | Google DeepMind |
| 范式 | 命令式 + torch.compile（Dynamo→Inductor→Triton） | 函数式（jit/grad/vmap/pmap 可组合） |
| 研究采用率 | ~75%（NeurIPS 论文） | 前沿项目（Gemini/AlphaFold） |
| 性能 | 编译器栈已大幅缩小差距 | TPU 快 1.2-2.5 倍、GPU 快 1.1-1.8 倍（大规模） |
| 生态 | HuggingFace/vLLM/Lightning/TorchAO | Flax/Optax（较小） |
| LLM 权重 | **事实标准（权重都发 PyTorch 格式）** | 少数 |

**PyTorch 2.12 关键新特性**（2025-2026）：

```text
① 统一图 API：torch.accelerator.Graph —— 设备无关的图捕获与重放（CUDA/XPU 统一）
② MX 量化导出：torch.export.save 支持 Microscaling 量化 —— 边缘部署激进压缩
③ 性能：批量特征分解最高提速 100 倍；融合 Adagrad；CUDA 图控制流改进
④ 生态扩展：2025 年新增 16 家基金会成员（Snowflake/Dell/Qualcomm）
```

**选型建议（2026 共识）**：

```text
默认 PyTorch：绝大多数场景（LLM 微调/部署/CV/表格 —— 权重生态决定一切）
选 JAX：Google Cloud TPU 大规模训练 / 函数式前沿研究（元学习、物理仿真）
组合策略：Torch 3.0 + JAX 2.0 覆盖约 90% 场景（注意 JAX 需 CUDA 12.3+）
长期关注：MLIR 生态（未来 5 年基础设施）
```

> 🎯 **核心要点**：2026 框架格局一句话 = "**PyTorch 赢在生态（权重与工具链），JAX 赢在性能（TPU 与函数式）**"——LLM 开发的默认答案是 PyTorch（权重格式即标准），JAX 是特定场景的差异化选择。

## 7. 框架选型决策树

```text
你的场景是什么？
├── LLM 微调/部署 → PyTorch（权重生态 = 事实标准）✅
├── CV/表格数据 → PyTorch（torchvision/生态最全）✅
├── TPU 大规模训练 → JAX（性能优势 1.2-2.5 倍）✅
├── 前沿函数式研究（元学习/物理仿真）→ JAX
├── Java 后端推理 → ONNX Runtime（跨框架导出）
├── 边缘设备 → 量化导出（TorchAO / MX 量化）
└── 多框架协作 → 训练 PyTorch + 推理 ONNX/vLLM

关键判断依据（按优先级）：
① 权重/模型生态（能不能拿到预训练模型）
② 团队熟悉度（维护成本）
③ 部署链路（训练 → 推理是否顺畅）
④ 性能需求（TPU/GPU 规模）
```

> 🎯 **核心要点**：选型第一问不是"哪个框架强"，而是"**哪个框架能拿到我要的模型**"——PyTorch 的统治力来自生态飞轮（权重 → 工具 → 人才 → 更多权重），这一格局 2026 年依然稳固（PyTorch 2.12 的硬件无关 API 进一步巩固）。

## 核心要点回顾

- Caffe (2012) → TensorFlow (2015) → PyTorch (2016) → JAX (2020)
- PyTorch 胜在动态图+Pythonic+学术生态飞轮
- JAX 是 Google 的新宠，函数式 + 极致编译性能
- LLM 开发 = PyTorch，推理 = vLLM/Ollama
- Java 端：大模型用独立服务 + HTTP，小模型用 ONNX Runtime
