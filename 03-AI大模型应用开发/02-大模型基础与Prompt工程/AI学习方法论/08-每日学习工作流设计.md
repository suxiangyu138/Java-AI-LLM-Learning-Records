## 1. 为什么需要固定的工作流

大脑是习惯机器。固定时间执行固定任务能够带来三重收益：

- **降低启动阻力**：无需决策"接下来做什么"，直接进入执行状态
- **形成神经回路**：重复触发相同的学习模式，加速习惯养成
- **更快进入心流**：减少注意力切换的成本，保持深度专注

> **重点**：工作流的核心价值不在于工具本身，而在于建立可重复的、自我强化的学习系统。

## 2. 日节奏

### 2.1 早晨：技术知识速通（30 分钟）

```text
07:30-08:00
├── 5 分钟：Perplexity 搜索
│   └── "2026年 [目标领域] 最新动态"
│       例："Spring Boot 3.x 最新特性"
│
├── 10 分钟：ChatGPT 生成学习计划
│   └── "列出今天我该学的 3 个知识点，每个 1 句话说明为什么重要"
│
└── 15 分钟：Claude 深度学习 1 个核心概念
    └── 用结构化模板深度提问（参考 [02-结构化提问与知识速通](02-结构化提问与知识速通.md)）
```

**产出**：每日 1 个知识卡片（Markdown 格式笔记）

### 2.2 白天：项目实战编码

```text
09:00-18:00（穿插使用 AI）
├── 写代码前
│   └── 先用纸笔（或白板）画业务流程图
│       → AI 不参与设计，只参与实现
│
├── 编码中
│   ├── GitHub Copilot：CRUD 模板代码，Tab 补全
│   ├── Cursor：复杂逻辑，Ctrl+K 生成初版
│   └── 关键业务逻辑：自己手写，不用 AI
│
├── 遇到 Bug
│   ├── 先看错误栈 2 分钟
│   ├── 无法定位 → Cursor Chat 或 ChatGPT 诊断
│   └── 参考 [03-AI辅助代码调试](03-AI辅助代码调试.md)
│
└── 代码提交前
    └── Cursor → "Review 这段代码，找出潜在的 Bug 和性能问题"
```

> **重点**：AI 是编码加速器，而非设计替代品。**关键业务逻辑必须手写**，以确保对核心代码的完全掌控。
>
> **注意**：代码审查（Code Review）应当在每次提交前执行一次，而非累计多日功能后一次完成，以降低 Bug 定位成本。

### 2.3 晚上：算法刷题 + 复盘（2 小时）

```text
20:00-22:00
├── 1 小时：LeetCode 3 道题
│   ├── 前 10 分钟/题：自己写
│   └── 卡住的题 → 参考 [04-AI教练模式刷题](04-AI教练模式刷题.md) AI 教练模式
│
├── 30 分钟：让 AI 出变种题巩固
│   └── "基于今天做的 3 道题，各出 1 道变种，不给答案"
│
└── 30 分钟：今日复盘
    └── 用 AI 整理今日笔记（粘贴零散记录 → AI 结构化整理）
```

## 3. 周节奏

| 时间 | 活动 | AI 角色 |
|------|------|---------|
| 周一复盘 | 回顾上周学习内容，规划本周目标 | AI 生成周计划 |
| 周二至周五 | 按日节奏执行 | AI 全程辅助 |
| 周六上午 | **集中编码半日**：完成一个 Mini 项目 | Cursor 结对编程 |
| 周六下午 | **技术博客写作** | AI 辅助写作 |
| 周日上午 | **源码阅读半日** | Claude 导读（参考 [05-AI源码导读加速](05-AI源码导读加速.md)） |
| 周日下午 | **自由探索**：浏览 GitHub Trending / 观看技术视频 | Perplexity 延展调研 |

### 3.1 周末重点：技术总结输出

```text
周六下午流程：
1. 回顾本周笔记（AI 已整理好的 Markdown）
2. 选定 1 个最有价值的主题
3. ChatGPT → "基于以下笔记，生成技术博客大纲"
4. Cursor → 写初稿
5. ChatGPT → "请 review 这篇文章，指出逻辑漏洞和表述不清的地方"
6. 修改后发布至 GitHub Pages / 掘金 / 博客园
```

> **重点**：技术博客是"输出倒逼输入"的核心实践。每篇博客的价值包括：丰富简历、检验知识掌握程度、建立被动人脉（面试官可能通过文章找到你）。

## 4. 月节奏

| 活动 | 时间 | 说明 |
|------|------|------|
| 月度技术总结 | 月末周末 | 用 AI 生成月度学习报告 |
| 技术栈查漏补缺 | 月末 | 提示词示例："基于我的学习记录，哪些技术点还没覆盖？" |
| 下月学习规划 | 月末 | 提示词示例："基于 2026 年 Java 后端趋势，下月我该重点学什么？" |
| GitHub 提交检查 | 每周日 | 确保每周有 3 次以上的 commit |

### 4.1 月度学习报告模板

```text
让 AI 基于你的笔记生成：

本月掌握的新技术点：[列表]
本月解决的典型 Bug：[列表 + 根因分析]
刷题进度：Easy [N] / Medium [N] / Hard [N]
项目进展：[完成功能 / 遇到的问题 / 架构改进]
下月重点：基于能力短板，AI 推荐 3 个学习方向
```

## 5. 碎片时间利用

| 碎片时长 | 做什么 | 工具 |
|----------|--------|------|
| 5 分钟 | 用 Perplexity 搜索 1 个技术概念 | 手机 |
| 10 分钟 | 回顾 AI 整理的昨日笔记 | 手机 |
| 15 分钟 | 完成 1 道 LeetCode Easy 题目 | 手机 / 平板 |
| 20 分钟 | 通过 ChatGPT 对话学习 1 个 Java 知识点 | 手机 |

> **重点**：碎片时间的价值在于积累而非突击。每天 3-4 个碎片时段即可完成约 1 小时的有效学习，长期坚持效果显著。

## 6. 关键原则

1. **固定时间做固定事**：降低启动阻力，消除"接下来学什么"的决策成本。
2. **AI 做知识整理，人做知识消化**：笔记由 AI 代写，但人必须通读一遍确保理解。
3. **输出倒逼输入**：周末必须产出一篇技术博客或一个可运行的 Demo 项目。
4. **每周检查 GitHub 绿点**：绿点是学习习惯的可视化反馈指标，每周至少 3 次 commit。

---

## 7. 核心要点回顾

- 每日工作流划分为三个时段：早晨速通（30 分钟）、白天实战编码、晚上算法与复盘（2 小时），覆盖"输入-实践-巩固"的完整学习闭环。
- 每周节奏以"工作日执行 + 周末输出"为框架，周末集中完成 Mini 项目、技术博客和源码阅读。
- 每月执行技术总结与查漏补缺，使用结构化模板生成学习报告，确保学习方向持续对齐技术趋势。
- 碎片时间以 5-20 分钟为单位分级利用，覆盖概念搜索、笔记回顾、算法练习和技术对话。
- 四条关键原则贯穿始终：固定时段、AI 辅助整理、输出倒逼输入、GitHub 绿点可视化追踪。
- AI 工具按角色分工：**Perplexity** 用于快速检索，**ChatGPT** 用于计划生成与内容审校，**Claude** 用于深度概念理解，**Cursor** 与 **GitHub Copilot** 用于编码辅助，**LeetCode** 用于算法训练。
