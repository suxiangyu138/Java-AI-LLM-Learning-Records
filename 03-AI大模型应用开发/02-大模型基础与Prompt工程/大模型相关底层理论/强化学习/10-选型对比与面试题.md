# 10-选型对比与面试题

> 后训练方案没有"最好"，只有"匹配"。SFT 学格式，DPO 学偏好，PPO 做在线对齐，GRPO + RLVR 激发推理，各有明确适用边界。选错方案，不是效果差一点，而是成本翻几倍还达不到目标。

## 1. 方案全景

| 方案 | 数据类型 | 是否需要采样 | 是否需要 RM | 典型用途 |
|------|---------|:-----------:|:-----------:|---------|
| SFT | 指令-回答对 | 否 | 否 | 学格式、学领域知识 |
| DPO | 偏好对 | 否 | 否 | 学偏好，中小规模 |
| ORPO | 偏好对 | 否 | 否 | SFT + 偏好一步完成 |
| KTO | 好/坏标签 | 否 | 否 | 只有单条反馈 |
| RLHF-PPO | 偏好对 + 在线采样 | 是 | 是 | 通用对齐 |
| GRPO | 可验证/偏好奖励 | 是 | 可选 | 推理、代码、Agent |
| RLVR | 可验证奖励 | 是 | 否 | 数学、代码、工具调用 |

一句话概括各自的位置：

```text
SFT：教模型"怎么说"
DPO：教模型"哪个说法更好"，离线
PPO：教模型"怎么说得更好"，在线，成本高
GRPO：教模型"怎么比同组其他人说得更好"，省掉 Critic
RLVR：用"对不对"代替"好不好"，把奖励变成可验证
```

## 2. 选型决策树

```text
任务有可验证的正确答案吗？
├── 有（数学、代码、结构化输出、工具调用）
│   ├── 数据量足够、要激发推理 → RLVR + GRPO
│   └── 只需格式对齐 → SFT
│
└── 没有（写作、对话、主观质量）
    ├── 有偏好对数据
    │   ├── 预算有限、离线 → DPO / ORPO
    │   └── 追求上限、可在线采样 → PPO-RLHF / GRPO + RM
    │
    └── 只有好/坏标签 → KTO
```

四个判断问题：

```text
问题一：奖励能不能程序化验证？
问题二：有没有偏好数据？
问题三：能否承受在线采样成本？
问题四：目标是"学会格式"还是"提升能力上限"？
```

## 3. 成本对比

以 7B 模型为例的粗略量级（相对值）：

| 方案 | 显存 | 采样成本 | 数据成本 | 训练稳定性 | 效果上限 |
|------|:---:|:-------:|:-------:|:---------:|:-------:|
| SFT | 1x | 无 | 高（写回答） | 高 | 中 |
| DPO | 2x | 无 | 中（排序） | 高 | 中高 |
| PPO | 4x | 高 | 中 | 中 | 高 |
| GRPO | 3x | 高 | 中 | 中 | 高 |
| RLVR | 3x | 高 | 低（规则） | 中 | 高（可验证任务） |

成本结构的关键差异：

```text
SFT/DPO：
  成本主要在数据
  训练一次，离线完成

PPO/GRPO/RLVR：
  成本主要在采样
  训练多轮，每轮都要生成
  采样吞吐决定总时长
```

## 4. 组合策略

实际生产很少只用一种方案：

```text
组合一：SFT → DPO
  先学格式与领域知识，再学偏好
  成本低，适合中小团队

组合二：SFT → RLVR → 拒绝采样 SFT
  推理模型标准管线
  先冷启动，再 RL 激发，最后蒸馏固化

组合三：SFT → PPO-RLHF → DPO
  在线对齐提升上限，DPO 稳定收尾

组合四：RLVR + RM 混合奖励
  规则保正确性，RM 管质量
  适合既要正确又要好读的场景
```

> **提示**：组合不是越多越好。每增加一个阶段，都要有独立的评估证明它带来了增量。没有增量就砍掉，否则只是增加成本与不确定性。

## 5. 面试题 12 道

### 题 1：SFT、DPO、PPO 的区别

**详细版**

SFT 是监督学习，数据是指令-回答对，损失是下一个 token 的交叉熵，学的是"照着标准答案说"。DPO 用偏好对，把 RLHF 的闭式最优解转成分类损失，让好回答的 log 概率相对参考模型上升、坏回答下降，不需要奖励模型和采样。PPO 是在线 RL，需要奖励模型打分、需要采样、需要 Critic 估价值，用裁剪目标限制更新幅度，能力上限最高但成本也最高。

**简短版**

SFT 学模仿，DPO 学偏好（离线），PPO 学优化（在线）。成本与上限依次上升。

**追问预案**

- 问：DPO 为什么不需要 RM？答：它把奖励表示成策略与参考模型的 log 比率，代入 Bradley-Terry 后直接优化策略。
- 问：什么时候必须用 PPO？答：需要在线探索、奖励可在线计算、追求能力上限时。
- 问：SFT 能替代 DPO 吗？答：不能，SFT 学不到"两个都不错的回答里哪个更好"。

### 题 2：RLHF 的三阶段

**详细版**

SFT 让模型学会指令跟随；奖励模型用成对偏好数据训练，损失是 $-\log\sigma(r_w-r_l)$；PPO 阶段用 RM 打分，最大化奖励减 KL 偏离。KL 防止模型跑到分布外、防止能力退化。三阶段的数据量依次递减，但训练复杂度依次上升。

**简短版**

SFT → 奖励模型 → PPO 对齐，KL 约束防跑偏。

**追问预案**

- 问：奖励模型怎么评估？答：留出集偏好准确率、校准性、对抗鲁棒性、与下游指标相关性。
- 问：KL 系数怎么定？答：实验确定，常用 0.01-0.1，可自适应。
- 问：能跳过 SFT 吗？答：不行，没有 SFT 的模型输出格式混乱，RM 打分没有意义。

### 题 3：PPO 的裁剪机制

**详细版**

PPO 用重要性采样比率 $\rho=\pi_\theta/\pi_{old}$ 衡量新旧策略差异，目标取未裁剪与裁剪目标的最小值。对优势为正的动作，$\rho$ 超过 $1+\epsilon$ 后梯度归零；对优势为负的动作，$\rho$ 低于 $1-\epsilon$ 后同理。它只限制"朝有利方向走太远"，不阻止"朝不利方向修正"。

**简短版**

clip 把比率限制在 $[1-\epsilon,1+\epsilon]$，防止单次更新过大，$\epsilon$ 常取 0.2。

**追问预案**

- 问：为什么用 min 而不是直接 clip？答：min 保证目标不会比未裁剪更悲观，同时保留修正方向的梯度。
- 问：裁剪一定比 KL 惩罚好吗？答：不一定，KL 惩罚更平滑，裁剪更简单，实践两者都有。
- 问：$\epsilon$ 太大太小会怎样？答：太大限制弱、易崩；太小更新慢、样本效率低。

### 题 4：GRPO 的原理

**详细版**

GRPO 对每个 prompt 采样 G 个回答，用组内奖励的均值和标准差标准化得到优势，替代 PPO 的 Critic。目标仍是裁剪的重要性采样目标加 KL。它把四模型压到三模型，显存降约四分之一，超参数少一个。代价是每 prompt 要采样 G 次，且组内全对/全错时不产生梯度。

**简短版**

组内平均当基线，省掉 Critic，用采样换显存。

**追问预案**

- 问：G 怎么选？答：常 8-16，太小基线噪声大，太大采样成本高。
- 问：为什么全对/全错没梯度？答：方差为 0，标准化后优势全 0。
- 问：GRPO 能用于连续控制吗？答：可以但不划算，采样成本高于训练 Critic。

### 题 5：GRPO 的问题与 DAPO

**详细版**

GRPO 有四个问题：全对/全错组零梯度；长度偏差；std 归一化让中等难度题权重过大；token 级比率在长序列上不稳定。DAPO 对应四项修正：Clip-Higher 解耦上下界提高探索；动态采样过滤零梯度组；token 级损失让每个 token 等权；超长奖励塑形减少截断噪声。

**简短版**

零梯度、长度偏差、难度偏差、比率不稳。DAPO 用 Clip-Higher、动态采样、token 级损失、超长塑形修。

**追问预案**

- 问：动态采样会不会无限循环？答：要设最大重采样次数，超过就跳过。
- 问：Token-level 损失为什么更好？答：避免长回答被长度归一化平均掉，让每个 token 都有梯度。
- 问：DAPO 论文效果如何？答：报告 DAPO-32B 在 AIME 2024 达 50 分，但只在特定设置成立。

### 题 6：GSPO 为什么用序列级比率

**详细版**

token 级比率在长序列上连乘容易爆炸或消失，MoE 路由变化会放大波动。GSPO 用整段回答的几何平均作为比率，粒度与序列级奖励一致，训练更稳定，长 CoT 与 MoE 场景收益明显。代价是无法做 token 级精细信用分配。

**简短版**

序列级几何平均比率，抑制长序列与 MoE 的比率波动，Qwen3 采用。

**追问预案**

- 问：GSPO 和 GRPO 的裁剪一样吗？答：形式类似，但比率对象从 token 变成序列。
- 问：GSPO 适合什么任务？答：整段质量由结果决定的任务，如数学、代码。
- 问：为什么 MoE 更需要 GSPO？答：路由变化导致 token 级比率剧烈波动。

### 题 7：什么是 RLVR

**详细版**

RLVR 用可程序化验证的奖励做 RL，比如数学答案比对、代码单元测试、格式校验、工具返回结果。它不需要奖励模型，成本低、可扩展，适合有明确对错的任务。DeepSeek-R1 的推理能力就是靠 RLVR + GRPO 激发的。局限是只适用于可验证任务，开放式写作仍需 RM。

**简短版**

用规则/单测/答案比对做奖励，替代人类偏好，成本低、可验证。

**追问预案**

- 问：RLVR 会奖励黑客吗？答：会，比如代码直接输出测试期望值，需要隐藏测试与人工审核。
- 问：没有标准答案怎么办？答：混合奖励，规则保底线，RM 管质量。
- 问：RLVR 需要 KL 吗？答：可验证任务可放松甚至 zero-KL，但通用能力仍需保护。

### 题 8：DPO 的推导

**详细版**

RLHF 目标的最优策略有闭式解，策略正比于参考模型乘以奖励的指数。反解出奖励，得到奖励等于 β 乘策略与参考模型的 log 比率加常数。代入 Bradley-Terry 后，配分函数抵消，只剩策略与参考模型的 log 比率差，于是可以直接用偏好数据做分类。

**简短版**

RLHF 最优解反解奖励，代入 BT，得到策略 log 比率差的 sigmoid 损失。

**追问预案**

- 问：β 的作用？答：控制偏离参考模型的程度，越大越保守。
- 问：DPO 为什么会长度偏差？答：偏好数据里长回答常被偏好，模型学到长度与质量相关。
- 问：DPO 能在线吗？答：标准 DPO 离线，有在线变体（迭代 DPO）。

### 题 9：奖励黑客怎么防

**详细版**

四层：KL 约束限制分布偏移；奖励集成降低单模型偏差；过程奖励与可验证奖励减少可钻的空子；人工抽检与红队持续校准。还要在奖励设计上防具体模式：长度偏好加长度惩罚，谄媚加纠正样本，格式刷分把格式与内容分开评。

**简短版**

KL 约束、奖励集成、可验证奖励、人工抽检，再针对具体模式加惩罚。

**追问预案**

- 问：KL 能根治吗？答：不能，只能减缓，奖励与目标的缝隙永远存在。
- 问：怎么发现奖励黑客？答：奖励涨但人工评估不涨，或输出模式异常单一。
- 问：过程奖励为什么更稳？答：每步可验证，模型难以用整段结果蒙混。

### 题 10：后训练怎么选方案

**详细版**

先看奖励能否验证：能，优先 RLVR + GRPO；不能，看有没有偏好数据：有就 DPO 或 PPO，没有就 SFT 或 KTO。再看成本：预算有限用 DPO，追求上限用 PPO/GRPO。最后看目标：学格式用 SFT，提能力用 RL。实际生产常组合：SFT → RLVR → 拒绝采样 SFT。

**简短版**

可验证选 RLVR，有偏好选 DPO/PPO，只学格式选 SFT，生产常组合。

**追问预案**

- 问：小团队怎么起步？答：SFT + DPO，成本最低，效果可预期。
- 问：什么时候值得上 GRPO？答：有可验证任务、有采样预算、SFT/DPO 已到瓶颈。
- 问：怎么证明 RL 有效？答：固定评估集，对比基线，看 Pass@1 与人工评估。

### 题 11：RL 训练不稳定怎么办

**详细版**

先看指标：approx_kl 是否超阈值、熵是否骤降、奖励是否暴涨、长度是否失控、梯度是否爆炸。对应处理：降学习率、调 clip、加 KL、加熵奖励、长度惩罚、梯度裁剪。数据侧查零梯度组比例、难度分布、奖励异常样本。系统侧查权重同步、采样引擎、奖励服务延迟。

**简短版**

看 KL、熵、奖励、长度、梯度五个指标，分别调学习率、clip、KL、温度、惩罚。

**追问预案**

- 问：loss NaN 怎么查？答：先降学习率与加梯度裁剪，再查异常数据与数值溢出。
- 问：熵崩塌怎么办？答：提高温度、Clip-Higher、加熵奖励、检查奖励是否过于单一。
- 问：奖励不涨怎么办？答：查题目难度、零梯度组比例、学习率、奖励是否有区分度。

### 题 12：RL 的评估怎么做

**详细版**

三层：自动指标（Pass@1、单测通过率、格式合规率）、AI 裁判（LLM-as-a-Judge，控制位置与长度偏差）、人工评估（成对比较、专家评审）。还要做通用能力回测，防止偏科；做分布外测试，防止过拟合训练集；做长尾分析，防止只看平均分。

**简短版**

自动指标 + AI 裁判 + 人工评估，再加通用能力回测与长尾分析。

**追问预案**

- 问：Pass@1 和 Pass@k 的区别？答：一次正确率 vs k 次中至少一次正确，后者反映潜力。
- 问：LLM 裁判有什么偏差？答：位置偏差、长度偏差、自我偏好。
- 问：怎么防止测试集泄漏？答：严格隔离、定期换题、人工审核高频题。

## 6. 答题模板

回答后训练问题时，用"目标 → 方案 → 取舍 → 落地"四段：

```text
第一段：目标
  "这个任务要解决的是格式对齐、偏好对齐，还是能力激发？"

第二段：方案
  "格式用 SFT，偏好用 DPO/PPO，可验证能力用 RLVR + GRPO。"

第三段：取舍
  "DPO 便宜但离线，PPO 上限高但四模型，GRPO 省 Critic 但采样贵。"

第四段：落地
  "先 SFT 冷启动，再 RLVR，最后拒绝采样固化；评估用 Pass@1 + 人工。"
```

这个模板能把任何追问拉回"目标-方案-取舍"的框架，避免陷入参数细节。

## 7. 小结

| 方案 | 一句话 |
|------|--------|
| SFT | 学格式与知识，成本最低 |
| DPO | 学偏好，离线，性价比高 |
| PPO | 在线对齐，上限高，成本最高 |
| GRPO | 去 Critic，采样换显存 |
| RLVR | 可验证奖励，推理模型标配 |
| 组合 | SFT → RLVR → 拒绝采样 SFT |
