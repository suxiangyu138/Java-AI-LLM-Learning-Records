## 1. 20 道自测题

**A. 概念题（快速过）**

1. LiteLLM 的双形态与适用场景？（SDK=代码统一；Proxy=治理统一）
2. model_list 里的 model_name 与 litellm_params.model 的关系？（逻辑名 ↔ 物理模型）
3. 2026 基准版本与两个里程碑能力？（v1.94.0：Router Plugins/成本页；v1.83.14：Prompt compression/Memory API）
4. Rust 迁移的收益？（15 倍吞吐、11 倍省内存、配置客户端全兼容）
5. 虚拟 key 能限制什么？（模型白名单/预算/TPM/RPM/并发/团队归属）
6. 数据面/控制面分离是什么？（2026-05 组件化部署，管理慢查询不拖请求处理）

**B. 场景题（写代码/配置）**

7. 写出一行切换 OpenAI/Claude/DeepSeek 的代码。
8. 写出 model_list 双供应商 fallback 的配置。
9. 生产 Proxy 的 docker-compose 要素？（锁定版本镜像/密钥环境变量/PG 数据卷/健康检查）
10. 如何给"客服组"发一个限预算 300 元/月、只能用 pro-llm 的虚拟 key？（/key/generate 参数）
11. FastAPI 里 LiteLLM 的正确用法？（lifespan 建 Router + acompletion + SSE）
12. Java 后端怎么接？（OpenAI Java SDK + base_url + 虚拟 key）
13. 成本治理的闭环？（记账 → 路由 → 预算 → 复盘）
14. 缓存三大纪律？（敏感不缓/时效不缓/阈值测试）

**C. 排查题（给现象找原因）**

15. 网关重启后虚拟 key 全失效？（没配数据库——PG 持久化）
16. 某供应商请求全失败？（没配 fallback——同逻辑名加备模型）
17. async 环境响应超慢？（用了同步 completion——acompletion）
18. 调用方 401？（虚拟 key 错误/未传；master_key 未设）
19. 成本报表全是"未归属"？（metadata 没传 user_id/team）
20. 缓存命中率为 0？（缓存没配/配置了 Redis 但没开；prompt 前缀不稳定）

> 💡 自测标准：A 全对 + B 能写出来 + C 能定位 = 本体系毕业；B 卡壳回对应章节，C 卡壳回 05/06/07 章。

## 3. 高频面试题与答题范式

**Q1：多模型接入你是怎么做的？（项目深挖题）**
> 范式：痛点（切换/key/成本）→ LiteLLM 双形态（先 SDK 后 Proxy）→ 架构（Nginx + 多实例 + PG + Redis）→ 治理（虚拟 key/预算/记账）→ 收益数据（fallback 故障无感/成本周报）。体现"从代码到生产"的完整闭环。

**Q2：LiteLLM 和 One-API 怎么选？**
> 范式：定位差异（开发者适配层 vs 管理平台）→ 语言/生态（Python 框架集成 vs Go 单体 UI）→ 场景（Python 栈选 LiteLLM、重 UI 管理选 One-API）→ 共同点（OpenAI 兼容、迁移成本低）。

**Q3：虚拟 key 是什么？解决了什么问题？**
> 范式：定义（网关分发的受限 key）→ 能力（模型白名单/预算/TPM-RPM/可撤销）→ 价值（真实 key 不出网关、泄露面收敛、按调用方治理）。延伸：master_key 安全基线。

**Q4：供应商故障怎么保证业务不挂？**
> 范式：同逻辑名多模型 fallback → 重试/健康检查/冷却 → 多供应商至少双备 → 网关 HA（多实例）+ 数据面/控制面分离。核心观点：真正的 HA 在供应商层。

**Q5：模型成本怎么控制？**
> 范式：记账（response_cost/Spend Logs）→ 路由（cheap 兜底）→ 预算（三级）→ 缓存（响应/语义/供应商）→ 压缩（长上下文）→ 复盘（周报四指标）。核心观点：先记账再省钱。

**Q6：Proxy 生产部署要注意什么？**
> 范式：Docker 锁定版本 + 密钥环境变量 + PG 持久化 + Redis + OTel 监控 + 内网部署 + 升级流程。给完整清单（09 章落地检查单）。

**Q7：LiteLLM 的性能怎么样？**
> 范式：Python 网关基准（可接受）→ Rust 迁移（453→6782 RPS、359MB→32MB、sub-1ms 开销）→ 配置/API 全兼容 → 生产等稳定版。体现对 2026 基础设施动态的了解。

**Q8：自研适配层 vs LiteLLM？**
> 范式：覆盖范围（100+ vs 3-5）→ 成本（小时级 vs 周-月级）→ 维护（社区 vs 自己）→ 自研的唯一理由（覆盖不了的场景）。核心观点：先评估现成，再决定自研。
