## 1. 三件套：Config / Tokenizer / Model

```python
from transformers import AutoConfig, AutoTokenizer, AutoModelForCausalLM

# ① Config：只读架构配置（不下载权重，轻量）
config = AutoConfig.from_pretrained("Qwen/Qwen2.5-7B-Instruct")
print(config.hidden_size, config.num_hidden_layers, config.vocab_size)

# ② Tokenizer：文本 ↔ 词元
tokenizer = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-7B-Instruct")

# ③ Model：权重 + 前向计算
model = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen2.5-7B-Instruct",
    device_map="auto",                # 自动放 GPU
    torch_dtype="auto",               # 自动选精度（读 config）
)
```

| 组件 | 职责 | 什么时候用 |
|------|------|-----------|
| Config | 架构参数（层数/维度/注意力头） | 轻量检查/调试 |
| Tokenizer | 文本 ↔ token_id（含模板） | 每次推理必用 |
| Model | 权重与前向 | 推理/微调 |

> 🎯 **核心要点**：**三件套各管一段，全部用 Auto 类**——`AutoXxx.from_pretrained(model_id)` 自动读取仓库配置选择正确实现。这是 HF 生态"一行代码换模型"能力的来源：换 `model_id` 就换整个模型。

## 2. Auto 类与模型家族

```python
# 任务 → Auto 类映射（选错类 = 加载失败或行为错误）
AutoModelForCausalLM       # 因果语言模型（对话/生成）→ GPT/Qwen/LLaMA/DeepSeek
AutoModelForSeq2SeqLM      # 序列到序列（翻译/摘要）→ T5/BART
AutoModelForMaskedLM       # 掩码语言模型（BERT 类）
AutoModelForSequenceClassification  # 分类（情感/意图）
AutoModelForTokenClassification     # 序列标注（NER）
AutoModelForQuestionAnswering       # 抽取式问答
AutoModel                      # 通用底座（无任务头，嵌入/研究用）
AutoModelForImageClassification   # 视觉分类
```

| 家族 | 架构 | 任务 |
|------|------|------|
| GPT/Qwen/LLaMA/DeepSeek/Mistral | Decoder-only | 生成/对话/代码 |
| BERT/RoBERTa/DeBERTa | Encoder-only | 分类/NER/向量 |
| T5/BART | Encoder-Decoder | 翻译/摘要 |
| Whisper | 语音 | 转写 |
| CLIP | 多模态 | 图文匹配 |

> ⚠️ 经典错误：**对话模型用 `AutoModel` 而不是 `AutoModelForCausalLM`**——`AutoModel` 没有语言建模头，`generate` 直接报错。加载前先看模型卡确认架构类型（01 章模型卡四步读）。

## 3. 设备与精度：device_map 与 dtype

### 3.1 device_map

| 值 | 行为 | 场景 |
|----|------|------|
| `"auto"` | 自动分配（优先 GPU，显存不够自动分片） | ⭐ 默认推荐 |
| `"cpu"` | 全部 CPU | 无 GPU/调试 |
| `"mps"` | Apple Silicon | Mac |
| `"cuda:0"` | 指定单卡 | 多卡手动控制 |
| dict | `{"": "cuda:0", "layers.10": "cuda:1"}` | 手动分片 |

### 3.2 torch_dtype（精度）

```python
import torch

# 自动：读 config 的默认精度（大模型通常是 bf16）
model = AutoModelForCausalLM.from_pretrained(..., torch_dtype="auto")

# 显式：bf16（训练/推理大模型首选）
model = AutoModelForCausalLM.from_pretrained(..., torch_dtype=torch.bfloat16)

# fp16：旧卡兼容
# fp32：小模型/最高精度（显存翻倍）
```

| 精度 | 显存 | 速度 | 适用 |
|------|:---:|:---:|------|
| fp32 | 4 字节/参数 | 基准 | 小模型/调试 |
| fp16 | 2 字节/参数 | 快 | 老 GPU（V100 等） |
| **bf16** | 2 字节/参数 | 快且稳 | ⭐ 2026 大模型标准（范围大不溢出） |
| 4bit/8bit | 0.5-1 字节/参数 | 中 | 单卡跑大模型（§4） |

> 🎯 **核心要点**：**bf16 是大模型默认精度**（与训练精度一致，不溢出）；显存公式：**7B 模型 bf16 ≈ 14GB 显存**（7×2 字节），量化 4bit ≈ 4GB。选卡/买卡前先算这笔账（09 章显存规划）。

## 4. 量化加载：单卡跑大模型

```python
from transformers import AutoModelForCausalLM, BitsAndBytesConfig
import torch

# 4bit NF4 量化：24G 卡跑 70B
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",        # nf4（推荐）或 fp4
    bnb_4bit_compute_dtype=torch.bfloat16,   # 计算精度（保质量）
    bnb_4bit_use_double_quant=True,   # 双重量化（更省显存）
)

model = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen2.5-72B-Instruct",
    quantization_config=bnb_config,
    device_map="auto",
)
```

| 量化方案 | 显存（7B） | 质量损失 | 适用 |
|---------|:---:|:---:|------|
| bf16 | 14GB | 无 | 有卡就用 |
| 8bit | 7-8GB | 极小 | 显存紧张 |
| 4bit NF4 | 4-5GB | 小（可接受） | ⭐ 单卡/QLoRA 标准 |
| 2bit | 2-3GB | 明显 | 极限场景 |

> 💡 量化决策：**推理场景 4bit NF4 是甜点**（质量损失小、显存省 70%）；微调场景 4bit + LoRA = QLoRA（06 章）；**追求质量且显存够，直接用 bf16**。v5 起量化是一等公民，加载即量化（02 章 §5）。

## 5. 多卡并行：device_map 的自动分片

```python
# 单机多卡：device_map="auto" 自动张量并行分片
model = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen2.5-72B-Instruct",
    device_map="auto",              # 自动按显存分到多卡
)

# 检查分布
print(model.hf_device_map)
# {'model.embed_tokens': 0, 'model.layers.0': 0, ..., 'model.layers.40': 1, ...}
```

| 并行方式 | 工具 | 场景 |
|---------|------|------|
| 单卡 | 直接加载 | 模型 ≤ 单卡显存 |
| 多卡张量并行 | `device_map="auto"`（accelerate） | 单机多卡推理 |
| 多机 | accelerate 配置 | 大集群 |
| 推理引擎 | vLLM（张量并行） | 生产高吞吐 |

> ⚠️ 多卡注意：`device_map="auto"` 用 **accelerate** 的推理分片（每卡放部分层）——推理够用；**训练/微调的多卡要用 `accelerate launch` 的 DDP/FSDP**（05 章）。两者不是一个东西，别混。

## 6. v5 动态加载实战

```python
# v5 完整加载姿势：融合 + 量化 + 并行一步到位
model = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen2.5-72B-Instruct",
    device_map="auto",                          # 多卡分片
    torch_dtype=torch.bfloat16,
    quantization_config=bnb_config,             # 加载时量化（可选）
    attn_implementation="flash_attention_2",    # 注意力加速（GPU 支持时）
    fuse_qkv=True,                              # v5：加载时融合 QKV
    fuse_moe=True,                              # v5：加载时融合 MoE 专家
)

# 加载即优化：一次调用完成 分片+精度+量化+注意力+融合
```

| v5 加载参数 | 作用 |
|------------|------|
| `fuse_qkv` | QKV 投影合并（推理加速） |
| `fuse_moe` | MoE 专家投影融合 |
| `attn_implementation` | sdpa / flash_attention_2 / paged_attention |
| `quantization_config` | 加载时量化 |
| `device_map` | 分片/设备分配 |

> 🎯 **核心要点**：v5 的 `from_pretrained` 是"**加载 + 优化**"一体入口——分片、精度、量化、注意力、融合全部参数化。写生产加载代码时把 v5 参数表过一遍，别只写 `from_pretrained(id)`。

## 7. 加载常见坑

| # | 坑 | 现象 | 解法 |
|:---:|-----|------|------|
| 1 | Auto 类选错 | 加载成功但 generate 报错/输出乱 | 按任务选类（§2 表） |
| 2 | 没配镜像 | 下载卡死/ConnectionError | HF_ENDPOINT（01 章） |
| 3 | gated 没登录 | 401/403 | 同意许可 + login（01 章） |
| 4 | 显存不足 OOM | CUDA out of memory | 4bit 量化 / 多卡 / 小模型 |
| 5 | dtype 溢出 | 生成 NaN/乱码 | bf16（范围大）+ 量化计算精度 bf16 |
| 6 | 多卡手动分片错 | 某卡爆显存 | device_map="auto" 别手动 |
| 7 | flash attn 不兼容 | 报错/回退慢 | 换 sdpa / 检查 GPU 架构（Ampere+） |
| 8 | 缓存磁盘满 | 下载失败/无法加载 | HF_HOME 独立盘 + scan-cache（01 章） |
| 9 | v4 老代码 | 弃用警告 | 迁移清单（02 章 §6） |
| 10 | 模型太大网络中断 | 下载失败 | hfd.sh 多线程 + 断点续传 |

## 8. 核心要点

| 序号 | 要点 |
|:---:|------|
| 1 | 三件套：Config 轻量 / Tokenizer 转换 / Model 计算，全用 Auto 类 |
| 2 | 对话模型必须 AutoModelForCausalLM（AutoModel 无生成头） |
| 3 | device_map="auto" + torch_dtype="auto" 是加载标配 |
| 4 | bf16 是大模型标准精度；显存 = 参数量 × 字节数 |
| 5 | 4bit NF4 = 单卡跑大模型的甜点（质量损失小） |
| 6 | 多卡推理用 device_map 自动分片；训练多卡用 accelerate launch |
| 7 | v5 加载即优化：fuse_qkv/fuse_moe/attention/量化一体 |
| 8 | 十大坑：类选错/镜像/gated/OOM/dtype/缓存盘满 |
