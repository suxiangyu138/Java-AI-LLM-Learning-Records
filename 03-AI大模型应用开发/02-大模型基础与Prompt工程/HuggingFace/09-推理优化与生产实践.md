## 1. 显存规划：选卡先算账

**显存公式**：

```text
推理显存 ≈ 参数内存 + KV 缓存 + 激活
  参数内存 = 参数量 × 字节数（bf16=2 / 8bit=1 / 4bit=0.5）
  KV 缓存 ≈ 2 × 层数 × 头数 × 头维度 × 序列长度 × 2 字节

微调显存 ≈ 参数内存 × 3（模型+梯度+优化器，全量）/ LoRA 只加适配层

例：7B 模型
  bf16 推理 ≈ 14GB + KV（2K 上下文约 1GB） → 16G 卡刚够，24G 舒适
  4bit 推理 ≈ 4GB + KV                        → 8G 卡可跑
  QLoRA 微调 ≈ 10GB                           → 24G 卡舒服
```

| 卡型 | 显存 | 能干的事（2026） |
|------|:---:|-----------------|
| RTX 3060/4060 | 12G | 7B 4bit 推理 / 3B 微调 |
| RTX 3090/4090 | 24G | 7B QLoRA / 13B 4bit 推理 |
| A100/A800 | 40-80G | 13B 全量 / 70B 4bit 推理 |
| H100/H800 | 80G+ | 70B 全量/多卡训练 |

> 🎯 **核心要点**：**先算账再买卡**——`参数量 × 字节数` 是硬底线，KV 缓存与上下文长度是隐藏开销。买卡问三句：跑多大模型？什么精度？多长上下文？

## 2. 推理优化手段全景

| # | 手段 | 收益 | 代价 | 章节 |
|:---:|------|:---:|------|:---:|
| 1 | bf16 精度 | 显存减半 vs fp32 | 无 | 03 |
| 2 | **4bit 量化** | 显存省 70% | 质量略降 | 03 |
| 3 | Flash Attention | 加速 + 省 KV 显存 | GPU 需 Ampere+ | 03 |
| 4 | v5 融合加载 | QKV/MoE 融合提速 | 加载时一次 | 02/03 |
| 5 | KV 缓存复用 | 多轮对话省重算 | 需管理 | 04 |
| 6 | 连续批处理 | 吞吐翻倍（服务） | 服务端 | 04 |
| 7 | 分页注意力 | 长上下文省显存 | 服务端 | 04 |
| 8 | vLLM | 吞吐 3-10 倍 | 换引擎 | 04 §6 |
| 9 | 投机采样 | 生成加速 | 需草稿模型 | 推理部署体系 |
| 10 | 量化蒸馏 | 小模型逼近大模型 | 训练成本 | 深度学习体系 |

> 💡 优化顺序建议：**先量化（最大显存收益）→ 再注意力（Flash）→ 再引擎（vLLM）**——每步压测对比（04 章 §7 基线），别一次全上分不清谁的效果。

## 3. 下载与镜像治理

```bash
# 生产服务器第一配置（01 章 §5 深化）
export HF_ENDPOINT=https://hf-mirror.com        # 必须早于任何 import
export HF_HOME=/data/hf                          # 大容量盘
export HF_HUB_DOWNLOAD_TIMEOUT=60                # 防网络抖动挂起

# 大模型落地用多线程 + 断点续传
./hfd.sh Qwen/Qwen2.5-72B-Instruct -x 16 --local-dir /data/models/qwen-72b
```

| 场景 | 治理手段 |
|------|---------|
| 单机开发 | HF_ENDPOINT 环境变量 |
| 团队 | 内网缓存（MinIO/R2/OSS + hf 缓存目录共享） |
| 生产部署 | 预下载 + 离线包（`--local-dir` 打包） |
| CI | 缓存卷挂载（Actions cache） |

> ⚠️ **生产服务器不能现下模型**——发布流程：预下载到制品库 → 部署时本地加载。70B 模型下载 4 小时的事故版本，都是"上线时才拉"。

## 4. 缓存与磁盘治理

```bash
# 磁盘杀手三件套：
#   ① 模型缓存（HF_HOME/hub）   ② 数据集缓存（HF_HOME/datasets）
#   ③ 训练检查点（output_dir）

# 体检
du -sh /data/hf/hub/* /data/hf/datasets/* 2>/dev/null | sort -h | tail -10
huggingface-cli scan-cache          # 模型缓存清单（未引用快照）

# 清理
huggingface-cli delete-cache        # 交互式清理
rm -rf /data/hf/hub/models--old--model   # 定向删除
```

| 治理规则 | 做法 |
|---------|------|
| 独立分区 | HF_HOME 放独立磁盘，监控占用 |
| 定期清理 | scan-cache 月度例行 |
| 检查点上限 | save_total_limit=3（05 章） |
| 生产只读 | 生产环境模型目录只读（防误写） |
| 告警 | 磁盘 > 80% 告警（运维体系） |

> 💡 磁盘事故的典型剧本：训练跑 3 天 → 检查点把盘写满 → 训练崩溃 + 白训。**磁盘监控与 save_total_limit 是训练服务的生死线**。

## 5. 环境与依赖治理

```bash
# 2026 推荐环境：uv + Python 3.10-3.14（Python 虚拟环境体系）
uv venv -p 3.12 .venv
uv pip install torch transformers peft datasets accelerate bitsandbytes gradio

# GPU 环境验证三件套
python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"
python -c "import transformers; print(transformers.__version__)"    # 5.x
nvidia-smi    # 驱动/显存

# 关键版本匹配
# torch ↔ CUDA 驱动版本匹配（PyTorch 官方安装命令为准）
# bitsandbytes ≥ 0.46.1（v5 量化要求，02 章）
# transformers 5.x ↔ huggingface_hub ≥ 1.0
```

| 依赖 | 版本要求（2026） | 原因 |
|------|----------------|------|
| transformers | 5.x（或锁定 minor） | v5 重构 |
| huggingface_hub | ≥1.0.0 | v5 依赖（HTTP 换 httpx） |
| bitsandbytes | ≥0.46.1 | v5 量化下限 |
| torch | 与 CUDA 匹配 | 驱动兼容 |
| gradio | 锁定 Space 版本 | 升级破坏兼容 |

> 🎯 **核心要点**：**环境 = 版本矩阵问题**。2026 标准：uv + Python 3.12 + transformers 5.x + bitsandbytes ≥0.46.1。升级前查迁移指南（02 章 §6），别盲目 latest。
