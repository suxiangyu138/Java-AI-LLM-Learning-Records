## 2. vLLM：生产级 OpenAI 兼容服务器

### 2.1 一句话定位

> vLLM 是目前生产环境部署 LLM 的事实标准，其 OpenAI Compatible Server 是**兼容度最高、性能最好**的开源实现。

### 2.2 启动 OpenAI 兼容服务

```bash
# 基础启动
python -m vllm.entrypoints.openai.api_server \
  --model Qwen/Qwen2.5-7B-Instruct \
  --served-model-name qwen2.5-7b \
  --port 8000

# 生产级启动（优化版）
python -m vllm.entrypoints.openai.api_server \
  --model Qwen/Qwen2.5-72B-Instruct-AWQ \
  --served-model-name qwen2.5-72b \
  --tensor-parallel-size 4 \
  --gpu-memory-utilization 0.95 \
  --max-model-len 32768 \
  --enable-prefix-caching \
  --port 8000 \
  --api-key sk-prod-xxxxx
```

### 2.3 关键参数

| 参数 | 说明 | 建议值 |
|------|------|--------|
| `--tensor-parallel-size` | GPU 张量并行数 | 等于 GPU 数量 |
| `--gpu-memory-utilization` | GPU 显存利用率 | 0.90~0.95 |
| `--max-model-len` | 最大上下文长度 | 按需（影响显存） |
| `--enable-prefix-caching` | 前缀缓存（提升吞吐） | 开启 |
| `--enable-chunked-prefill` | 分块预填充 | 高并发场景开启 |
| `--api-key` | API 鉴权 | 生产必设 |
| `--served-model-name` | 对外模型名 | 设置友好名称 |

### 2.4 调用验证

```bash
curl http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-prod-xxxxx" \
  -d '{
    "model": "qwen2.5-7b",
    "messages": [{"role": "user", "content": "Hello!"}]
  }'
```

### 2.5 vLLM OpenAI 兼容支持度

```text
✅ 完整支持：
  /v1/chat/completions     → 消息格式、流式、json_mode
  /v1/completions          → 传统文本补全（向后兼容）
  /v1/embeddings           → 需加载 embedding 模型
  /v1/models               → 列出加载的模型
  Tool Calling             → 需模型原生支持 function calling
  Vision                   → 需加载多模态模型（LLaVA 等）

⚠️ 部分支持：
  logprobs                 → 需启动时指定
  n > 1                    → 支持但损耗性能
  seed                     → 支持

❌ 不支持：
  json_schema (Structured Output) → OpenAI 专有
  TTS / STT / Images              → 纯文本引擎
```

## 3. Ollama：本地一键部署首选

### 3.1 一句话定位

> Ollama 让本地运行大模型变得像 `docker run` 一样简单，内置 OpenAI 兼容端点，是开发测试的首选。

### 3.2 开启 OpenAI 兼容端点

Ollama 0.1.24+ 版本内置 OpenAI 兼容 API，默认监听 `localhost:11434`：

```bash
# 拉取模型
ollama pull qwen2.5:7b

# Ollama 默认已启动服务，OpenAI 端点自动可用
# 验证兼容端点
curl http://localhost:11434/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen2.5:7b",
    "messages": [{"role": "user", "content": "用 Java 写一个冒泡排序"}],
    "stream": false
  }'
```

### 3.3 关键环境变量

```bash
# 服务监听地址（默认仅 localhost）
export OLLAMA_HOST=0.0.0.0:11434

# 模型目录
export OLLAMA_MODELS=/data/ollama/models

# 并发请求数
export OLLAMA_NUM_PARALLEL=4

# 最大加载模型数
export OLLAMA_MAX_LOADED_MODELS=2

# GPU 层数（强制使用 GPU）
export OLLAMA_NUM_GPU=999
```

### 3.4 Ollama + Java 集成

```java
// Spring AI 配置
spring.ai.openai.base-url=http://localhost:11434
spring.ai.openai.api-key=ollama           // Ollama 不需要真实 key
spring.ai.openai.chat.options.model=qwen2.5:7b

// LangChain4j 配置
OpenAiChatModel model = OpenAiChatModel.builder()
    .baseUrl("http://localhost:11434/v1")
    .apiKey("ollama")
    .modelName("qwen2.5:7b")
    .build();
```

### 3.5 Ollama 兼容性注意事项

```text
⚠️ system role：早期版本可能不支持，建议 Ollama ≥ 0.1.24
⚠️ Tool Calling：需模型原生支持（qwen2.5, llama3.1, mistral 等）
⚠️ Vision：需专用模型（llava, llama3.2-vision, minicpm-v 等）
⚠️ 并发限制：默认 NUM_PARALLEL=1，生产需调大
⚠️ 无 Embeddings：Ollama 的 /v1/embeddings 支持有限，建议用专用 embedding 模型
```

## 4. LiteLLM：多模型统一调用层

### 4.1 一句话定位

> LiteLLM 是一个 Python 库，将 100+ LLM 提供商的 API 调用**翻译为 OpenAI 格式**。你写 OpenAI 格式代码，它负责翻译成各厂商的原生 API。

### 4.2 作为库使用

```python
from litellm import completion

# 统一用 OpenAI 格式调用任何模型
response = completion(
    model="deepseek/deepseek-chat",  # LiteLLM 路由格式
    messages=[{"role": "user", "content": "Hello!"}]
)

# model 路由规则：provider/model_name
# openai/gpt-4o          → OpenAI 原生 API
# deepseek/deepseek-chat → DeepSeek API
# ollama/qwen2.5:7b      → 本地 Ollama
# together_ai/meta-llama  → Together AI
# bedrock/anthropic.claude → AWS Bedrock
```

### 4.3 作为 Proxy Server（API 网关）

```bash
# 启动 LiteLLM Proxy
litellm --model openai/gpt-4o \
        --model deepseek/deepseek-chat \
        --model ollama/qwen2.5:7b \
        --port 4000

# 现在可以用统一的 OpenAI 格式调用
curl http://localhost:4000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-litellm" \
  -d '{
    "model": "deepseek-chat",    // LiteLLM 会自动路由到 DeepSeek
    "messages": [{"role": "user", "content": "Hello!"}]
  }'
```

### 4.4 LiteLLM 核心价值

```text
场景 1：代码只写一次，模型任意切换
  List<String> models = List.of("gpt-4o", "deepseek-chat", "qwen-max");
  for (String m : models) {
      // 同一份代码，改 model 参数即可
  }

场景 2：成本优化，自动降级
  LiteLLM Router:
    优先 → gpt-4o（最佳质量）
    降级 → gpt-4o-mini（成本节省 90%）
    兜底 → 本地 qwen2.5:7b（零 API 费用）

场景 3：A/B 测试
  灰度 10% 流量到新模型，对比质量和延迟
```

## 5. llama.cpp Server

### 5.1 一句话定位

> llama.cpp 是 C++ 实现的极致轻量推理引擎，CPU friendly，其 server 模式内置 OpenAI 兼容 API。

### 5.2 启动 OpenAI 兼容服务

```bash
# 编译 server
cmake -B build && cmake --build build --config Release -t llama-server

# 启动服务
./build/bin/llama-server \
  -m models/qwen2.5-7b-q4_k_m.gguf \
  --host 0.0.0.0 \
  --port 8080 \
  -c 4096 \           # 上下文长度
  -ngl 99 \           # GPU 层数
  -np 4               # 并行处理数
```

### 5.3 llama.cpp 独特能力

```text
✅ Grammar-based Sampling
   → 用 GBNF 语法强制输出格式，比 JSON Mode 更严格
   → 例：强制输出合法 SQL、JSON、特定格式

✅ 极致 CPU 推理
   → 在普通笔记本 CPU 上运行 7B 模型，速度可达 10+ tokens/s

✅ GGUF 量化生态
   → q4_k_m, q5_k_m, q8_0 等丰富量化变体

⚠️ Tool Calling 限制
   → 需要模型本身在训练时支持 function calling 格式
   → 不支持的模型可以用 prompt engineering 模拟
```

### 5.4 GBNF 语法示例

```gbnf
# 强制输出 JSON 对象
root ::= object
object ::= "{" ws pair ("," ws pair)* "}"
pair ::= string ":" value
string ::= "\"" [A-Za-z0-9_ ]+ "\""
value ::= string | number | "true" | "false" | "null"
number ::= [0-9]+
ws ::= [ \t\n]*
```

## 6. LocalAI：即插即用替换

### 6.1 一句话定位

> LocalAI 的目标是成为 OpenAI API 的**完全 drop-in replacement**——把 `api.openai.com` 改成 `localhost:8080`，代码零改动。

### 6.2 启动

```bash
# Docker 一键启动
docker run -p 8080:8080 \
  -v $PWD/models:/build/models \
  localai/localai:latest \
  --models-path /build/models

# 或使用 Docker Compose
# 配置 model YAML 文件后启动
```

### 6.3 支持的端点（最全）

```text
✅ /v1/chat/completions     → 对话
✅ /v1/embeddings            → 嵌入
✅ /v1/images/generations    → 图片生成（Stable Diffusion）
✅ /v1/audio/transcriptions  → 语音转文字（Whisper）
✅ /v1/audio/speech          → 文字转语音
✅ /v1/models                 → 模型列表
```

> LocalAI 是最接近"完整 OpenAI 替换"的开源方案。

## 8. DeepSeek / 智谱 / 通义千问：商业 API 兼容

### 8.1 DeepSeek API

```text
base_url: https://api.deepseek.com/v1
特点：
  ✅ 完全兼容 OpenAI Chat Completions 格式
  ✅ 支持 Streaming、Tool Calling、JSON Mode
  ✅ deepseek-reasoner（R1）支持 reasoning tokens
  ❌ 不支持 Vision
  ❌ 不支持 Embeddings（无公有 API）
```

```java
// Spring AI 配置 DeepSeek
spring.ai.openai.base-url=https://api.deepseek.com
spring.ai.openai.api-key=${DEEPSEEK_API_KEY}
spring.ai.openai.chat.options.model=deepseek-chat
```

### 8.2 智谱 GLM

```text
base_url: https://open.bigmodel.cn/api/paas/v4
特点：
  ✅ 兼容 Chat Completions
  ✅ 支持 Tool Calling、Vision（GLM-4V）
  ✅ 支持 Embeddings
  ⚠️ 有细微差异（extra body 参数等）
```

### 8.3 通义千问

```text
base_url: https://dashscope.aliyuncs.com/compatible-mode/v1
特点：
  ✅ 兼容 Chat Completions（需开启 compatible-mode）
  ✅ 支持 Tool Calling、Vision（Qwen-VL）
  ✅ 支持 Embeddings
  ⚠️ 原生 API 非 OpenAI 格式，需加 /compatible-mode 路径
```

## 9. 选型决策树

```text
你的需求是什么？
│
├── 我要本地跑模型做开发测试
│   └── → Ollama（最简单，1 条命令）
│
├── 我要生产环境高并发部署
│   ├── 单 GPU → vLLM
│   ├── 多 GPU → vLLM + tensor-parallel
│   └── CPU only → llama.cpp server
│
├── 我要统一接入多个模型提供商
│   ├── Python 技术栈 → LiteLLM Proxy
│   └── 需要 Web 管理 → One-API / New-API
│
├── 我要完整替换 OpenAI（含图片、语音）
│   └── → LocalAI（最全的端点覆盖）
│
└── 我调用商业 API（DeepSeek/智谱等）
    └── → 直接改 base_url + api_key 即可
```

---

> 🎯 **核心要点**：vLLM 是生产环境的首选，Ollama 是开发环境的首选，LiteLLM 是多模型场景的粘合剂。三者互补，而非替代。
