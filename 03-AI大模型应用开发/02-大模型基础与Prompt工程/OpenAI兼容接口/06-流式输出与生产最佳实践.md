## 1. 流式输出深度解析

### 1.1 为什么需要流式输出

```text
非流式（stream: false）：
  用户等待 ────────────────────────[全部生成完]→ 一次性返回
  耗时 8 秒，首字 8 秒

流式（stream: true）：
  用户等待 ──[首token]─[token2]─[token3]─...→ 逐 token 返回
  耗时 8 秒，首字 0.3 秒

感知体验差距：
  非流式 → 用户盯着空白看了 8 秒
  流式   → 用户看到文字在"打字"，等待感知大幅降低
```

### 1.2 SSE 协议细节

```text
Content-Type: text/event-stream

SSE 标准格式：
  data: <json>\n\n

关键规则：
  1. 每行以 "data: " 开头（注意空格）
  2. 以 "\n\n" 结尾
  3. 最后一条是 "data: [DONE]"
  4. JSON 中的 content 可能是空字符串 ""（非 null）
  5. delta.content 和 delta.tool_calls 互斥：
     - 文本 token → delta.content 有值，delta.tool_calls 为 null
     - 工具调用 → delta.content 为 null，delta.tool_calls 有值
```

### 1.3 Chunk 类型完整枚举

```java
/**
 * SSE 流中可能出现的所有 delta 组合
 */
public enum ChunkType {

    // 1. 第一个 chunk：只有 role
    // {"delta": {"role": "assistant", "content": ""}}

    // 2. 文本 chunk：正常内容
    // {"delta": {"content": "Hello"}}

    // 3. 空文本 chunk：（某些实现会发）
    // {"delta": {"content": ""}}

    // 4. 工具调用开始：tool_calls 出现
    // {"delta": {"tool_calls": [{"index": 0, "id": "call_xxx",
    //   "type": "function", "function": {"name": "get_weather",
    //   "arguments": ""}}]}}

    // 5. 工具参数 chunk：按 fragment 拼接
    // {"delta": {"tool_calls": [{"index": 0,
    //   "function": {"arguments": "{\"loc"}}]}}

    // 6. 结束 chunk：只有 finish_reason
    // {"delta": {}, "finish_reason": "stop"}

    // 7. usage chunk（部分实现）：
    // {"delta": {}, "finish_reason": "stop",
    //  "usage": {"prompt_tokens": 10, "completion_tokens": 5}}
}
```

## 2. SSE 解析：常见陷阱与正确姿势

### 2.1 陷阱清单

```text
陷阱 1：用 \n 分割行
  → SSE 用 \n\n 分割事件，但 JSON 内容中可能包含 \n
  → 错误：line.split("\n")  → 会把 JSON 拆碎
  → 正确：按 \n\n 分割事件，再用 \n 解析每条 data 行

陷阱 2：假设 data: 后面一定是完整 JSON
  → SSE 允许多行 data（用于长事件），虽然 OpenAI 不用
  → 正确：拼接同一事件的所有 data: 行，再解析

陷阱 3：content 是 "" 时当作 null 跳过
  → 第一个 chunk 的 content 是 "" 但有 role 信息
  → 正确：区分 content="" 和 content==null

陷阱 4：不处理 tool_calls 流
  → 模型可能突然切换到 tool_calls，你的解析器要有准备
  → 正确：检测 delta.tool_calls 非空时切换到工具调用模式

陷阱 5：网络中断时无重连
  → WiFi 切换、代理超时都会中断 SSE 连接
  → 正确：实现断线重连 + 已接收内容的去重
```

### 2.2 正确的 SSE 解析器（Java）

```java
/**
 * 生产级 SSE 解析器 — 处理所有边界情况
 */
public class RobustSSEParser {

    private final StringBuilder contentBuffer = new StringBuilder();
    private final Map<Integer, ToolCallBuilder> toolCallBuilders = 
        new HashMap<>();
    private String finishReason = null;
    private TokenUsage usage = null;

    /**
     * 处理一行 SSE 数据
     */
    public void onLine(String line) {
        // 跳过非 data 行（event:, id:, retry: 等）
        if (!line.startsWith("data: ")) {
            return;
        }

        String data = line.substring(6);  // 去掉 "data: "

        // [DONE] 信号
        if ("[DONE]".equals(data)) {
            this.finishReason = "stop";  // [DONE] 意味着结束
            return;
        }

        // 解析 JSON
        try {
            JsonNode chunk = parseJson(data);
            processChunk(chunk);
        } catch (Exception e) {
            log.warn("SSE JSON 解析失败: {}", data, e);
        }
    }

    private void processChunk(JsonNode chunk) {
        JsonNode choices = chunk.path("choices");
        if (choices.isEmpty()) return;

        JsonNode choice = choices.get(0);
        JsonNode delta = choice.path("delta");

        // 处理文本 content
        JsonNode contentNode = delta.path("content");
        if (!contentNode.isNull() && contentNode.asText() != null) {
            contentBuffer.append(contentNode.asText());
        }

        // 处理 tool_calls
        JsonNode toolCalls = delta.path("tool_calls");
        if (!toolCalls.isNull() && toolCalls.isArray()) {
            for (JsonNode tc : toolCalls) {
                int index = tc.path("index").asInt();
                toolCallBuilders
                    .computeIfAbsent(index, k -> new ToolCallBuilder())
                    .append(tc);
            }
        }

        // 处理 finish_reason
        JsonNode fr = choice.path("finish_reason");
        if (!fr.isNull()) {
            this.finishReason = fr.asText();
        }

        // 处理 usage（如果有）
        JsonNode usageNode = chunk.path("usage");
        if (!usageNode.isNull()) {
            this.usage = parseUsage(usageNode);
        }
    }

    /**
     * 判断流是否结束
     */
    public boolean isDone() {
        return finishReason != null;
    }

    /**
     * 获取完整文本
     */
    public String getFullContent() {
        return contentBuffer.toString();
    }

    /**
     * 获取完成的工具调用
     */
    public List<ToolCall> getToolCalls() {
        return toolCallBuilders.values().stream()
            .map(ToolCallBuilder::build)
            .filter(tc -> tc.getArguments() != null)
            .collect(Collectors.toList());
    }
}

/**
 * 工具调用 builder：处理分 chunk 到达的 JSON
 */
class ToolCallBuilder {
    private String id;
    private String name;
    private final StringBuilder arguments = new StringBuilder();

    void append(JsonNode tc) {
        if (tc.has("id") && !tc.get("id").isNull()) {
            this.id = tc.get("id").asText();
        }
        JsonNode func = tc.path("function");
        if (func.has("name") && !func.get("name").isNull()) {
            this.name = func.get("name").asText();
        }
        JsonNode args = func.path("arguments");
        if (!args.isNull()) {
            this.arguments.append(args.asText());
        }
    }

    ToolCall build() {
        return new ToolCall(id, name, arguments.toString());
    }
}
```

```java
/**
 * 跨模型的 Tool Calling 适配层
 */
public class ToolCallingAdapter {

    /**
     * 允许的最大参数 schema 深度（嵌套层级）
     * DeepSeek: 建议 ≤ 3
     * GPT-4o: 支持更深的嵌套
     */
    private static final int MAX_SCHEMA_DEPTH = 3;

    /**
     * 构建跨平台兼容的 Tool 定义
     */
    public static ToolDefinition buildCompatibleTool(
            String name, String description, 
            JsonSchema schema, Set<String> knownIssues) {

        // 降级策略 1：展平深层嵌套
        schema = flattenDeepNesting(schema, MAX_SCHEMA_DEPTH);

        // 降级策略 2：移除不支持的 schema 关键字
        if (knownIssues.contains("no-strict-format")) {
            schema = removeStrictKeywords(schema);
        }

        // 降级策略 3：简化参数描述（某些模型对长描述处理不好）
        schema = truncateDescriptions(schema, 150);

        return ToolDefinition.builder()
            .name(name)
            .description(
                description.length() > 200 
                    ? description.substring(0, 197) + "..." 
                    : description)
            .inputSchema(schema)
            .build();
    }
}
```

### 3.3 Tool Call 参数解析的坑

```text
坑 1：arguments 是 JSON 字符串，不是 JSON 对象
  在 stream 中，arguments 是碎片化的 JSON 字符串逐 chunk 到达
  → 需要拼接所有 fragment 后再 parse

坑 2：部分模型在单次调用中混合 content + tool_calls
  某些模型会在 tool_calls 的同时填充 content = "我来帮你查询..."
  → 不要假设 content 和 tool_calls 互斥

坑 3：tool_call_id 的格式不一致
  OpenAI: "call_abc123"
  DeepSeek: "call_abc123"（相同前缀）
  vLLM 某些版本: "chatcmpl-tool-xxx"
  → 不要依赖 id 格式，只保证在一次调用内唯一即可
```

## 4. 容灾与高可用设计

### 4.1 多层容灾架构

```text
Layer 1: 重试（Retry）
  → 瞬时错误（429 Rate Limit, 503 Service Unavailable）
  → 指数退避：1s → 2s → 4s → 8s

Layer 2: 模型降级（Fallback）
  → 同一渠道内部降级：GPT-4o → GPT-4o-mini
  → 速度快 3x，成本降 90%

Layer 3: 渠道切换（Failover）
  → OpenAI 不可用 → 切换到 DeepSeek
  → 需要预配置多渠道

Layer 4: 本地兜底（Local Backup）
  → 所有云端都挂了 → 本地 Ollama / vLLM
  → 质量下降，但服务不中断
```

### 4.2 Resilience4j 实现

```java
@Service
public class ResilientChatService {

    private final OpenAiChatModel primaryModel;
    private final OpenAiChatModel fallbackModel;
    private final OpenAiChatModel localModel;

    // 重试配置
    private final Retry retry = RetryConfig.<String>custom()
        .maxAttempts(3)
        .waitDuration(Duration.ofSeconds(1))
        .exponentialBackoff(2, Duration.ofSeconds(10))
        .retryOnException(e -> isRetryable(e))
        .build();

    // 断路器配置
    private final CircuitBreaker circuitBreaker = 
        CircuitBreakerConfig.<String>custom()
            .failureRateThreshold(50)       // 50% 失败率触发
            .waitDurationInOpenState(Duration.ofSeconds(30))
            .slidingWindowSize(10)
            .build();

    // 时间限制器
    private final TimeLimiter timeLimiter = 
        TimeLimiterConfig.custom()
            .timeoutDuration(Duration.ofSeconds(60))
            .build();

    @CircuitBreaker(name = "chat")
    @Retry(name = "chat")
    @TimeLimiter(name = "chat")
    public String chatWithResilience(String userMessage) {
        try {
            return primaryModel.call(userMessage);
        } catch (Exception e) {
            log.error("主模型失败，降级: {}", e.getMessage());
            try {
                return fallbackModel.call(userMessage);
            } catch (Exception e2) {
                log.error("降级模型也失败，兜底本地: {}", e2.getMessage());
                return localModel.call(userMessage);
            }
        }
    }

    private boolean isRetryable(Throwable e) {
        if (e instanceof HttpClientErrorException http) {
            return http.getStatusCode() == HttpStatus.TOO_MANY_REQUESTS  // 429
                || http.getStatusCode() == HttpStatus.SERVICE_UNAVAILABLE; // 503
        }
        return false;  // 4xx 不重试（除非 429），5xx 重试
    }
}
```

```java
/**
 * Spring AI 中实现模型降级链

@Component
public class ModelFallbackChain {

    private final List<NamedModel> models;  // 按优先级排序

    public ModelFallbackChain(
            OpenAiChatModel deepseekModel,
            OpenAiChatModel openaiModel,
            OpenAiChatModel localModel) {
        this.models = List.of(
            new NamedModel("DeepSeek", deepseekModel),
            new NamedModel("GPT-4o", openaiModel),
            new NamedModel("Local-Qwen", localModel)
        );
    }

    public String chat(String message) {
        for (NamedModel namedModel : models) {
            try {
                long start = System.currentTimeMillis();
                String result = namedModel.model().call(message);
                long latency = System.currentTimeMillis() - start;
                
                log.info("模型 {} 响应成功, 延迟 {}ms", 
                    namedModel.name(), latency);
                return result;
            } catch (Exception e) {
                log.warn("模型 {} 调用失败: {}", 
                    namedModel.name(), e.getMessage());
                // 继续尝试下一个模型
            }
        }
        throw new RuntimeException("所有模型调用失败");
    }
}

record NamedModel(String name, OpenAiChatModel model) {}
```

```java
/**
 * Token 预算管理：防止单个会话消耗过多
 */
@Service
public class TokenBudgetService {

    // 每个用户每天的 Token 预算
    private static final long DAILY_TOKEN_BUDGET = 1_000_000;

    // 单次请求上限
    private static final int MAX_TOKENS_PER_REQUEST = 16_384;

    private final RedisTemplate<String, String> redis;

    /**
     * 请求前检查预算
     */
    public boolean tryAcquire(String userId, int estimatedTokens) {
        String key = "token:budget:" + userId + ":" + 
            LocalDate.now().toString();

        Long used = redis.opsForValue()
            .increment(key, estimatedTokens);
        
        // 设置过期时间（第二天凌晨过期）
        redis.expireAt(key, 
            LocalDate.now().plusDays(1).atStartOfDay()
                .toInstant(ZoneOffset.UTC));

        return used != null && used <= DAILY_TOKEN_BUDGET;
    }

    /**
     * 实际消耗结算（请求完成后调整）
     */
    public void settle(String userId, int actualTokens, int estimatedTokens) {
        String key = "token:budget:" + userId + ":" + 
            LocalDate.now().toString();
        long diff = actualTokens - estimatedTokens;
        if (diff != 0) {
            redis.opsForValue().increment(key, diff);
        }
    }
}
```

## 6. 监控与可观测性

### 6.1 核心监控指标

```text
RED 方法论：
  Rate      → 每秒请求数（QPS）
  Errors    → 错误率（4xx / 5xx）
  Duration  → 延迟（P50 / P95 / P99）

LLM 特有指标：
  ├── Tokens Per Second (TPS)    → 生成速度
  ├── Time To First Token (TTFT) → 首 token 延迟
  ├── Tokens Per Request         → 每次请求的 Token 分布
  ├── Cost Per Request           → 每次请求的成本
  ├── Cache Hit Rate             → Prompt Cache 命中率
  └── Finish Reason Distribution → stop vs length vs content_filter
```

```java
            .register(registry);

            .description("首 Token 延迟")
            .register(registry);
        this.promptTokensCounter = Counter.builder("llm.tokens.prompt")
            .description("Prompt Token 总数")
            .register(registry);
        this.completionTokensCounter = Counter.builder("llm.tokens.completion")
            .description("Completion Token 总数")
            .register(registry);

    /**
     * 记录一次完整的 LLM 调用
     */
    public void recordCall(String model, String status,

            .increment(completionTokens);
    }
}
```

## 7. 延迟优化策略

### 7.1 TTFT（首 Token 延迟）优化

```text
TTFT 影响因素：
  1. Prompt 长度 → Prompt Cache 命中可大幅降低
  2. 模型大小   → 小模型 TTFT 更低
  3. 服务负载   → 排队时间
  4. 网络延迟   → 就近部署

优化手段：
  ├── Prompt Cache：固定的 system prompt 放在最前面
  │   OpenAI 自动缓存前缀，DeepSeek 支持 disk_cache
  │
  ├── 流式输出：TTFT 不变，但用户感知延迟大幅降低
  │
  ├── 模型降级：简单任务用小模型
  │   gpt-4o-mini → TTFT ~0.3s
  │   gpt-4o       → TTFT ~0.8s
  │
  └── 就近部署：本地 vLLM → TTFT ~0.1s
```

### 7.2 Prompt Cache 妙用

```java
/**
 * 最大化 Prompt Cache 命中率
 * 规则：缓存命中的部分是前缀，所以把不变的内容放在最前面
 */
public String buildCacheablePrompt(String userId, String question) {

    // ✅ 正确：固定 system prompt 在最前面
    String systemPrompt = "你是专业的 Java 技术顾问..." +
        "你精通 Spring Boot、MyBatis、微服务架构..." +
        "你擅长用简洁的代码示例说明问题...";

    // 这 500+ tokens 的 system prompt 会被缓存

    // ❌ 错误：把变化的 user context 放在 system 前面
    // 如果 user context 每次不同，整个前缀缓存失效

    return systemPrompt + "\n\n" +
           "用户问题：" + question;
}
```

## 8. 安全检查清单

### 8.1 生产上线前检查

```text
□ API Key 管理
  □ Key 存储在环境变量或 Vault，不硬编码
  □ 定期轮换 API Key
  □ 每个环境使用不同的 Key

□ 网络安全
  □ 生产环境启用 HTTPS（TLS 1.2+）
  □ 内网 vLLM/Ollama 不暴露到公网
  □ API Key 不在日志/错误消息中输出

□ 输入安全
  □ Prompt Injection 防护（输入清洗、边界指令）
  □ 用户输入长度限制
  □ 敏感信息脱敏（手机号、身份证等）

□ 输出安全
  □ 内容安全过滤（违法/违规内容拦截）
  □ 输出长度限制
  □ JSON / 代码注入防护

□ 合规
  □ 用户数据不出境（使用国内 API 或本地部署）
  □ 日志保留策略（不保存用户查询内容）
  □ 用户同意条款（如适用）
```
