## 1. 高频面试题

### Q1（⭐⭐⭐⭐⭐）: 画一个 ReAct Agent 的循环流程图，并解释每个状态

```
            ┌─────────┐
     ┌─────→│  THINK  │←─────────┐
     │      └────┬────┘          │
     │           │               │
 需要工具    可以直接回答     工具结果返回
     │           │               │
     │      ┌────▼────┐    ┌────┴────┐
     └──────│   ACT   │───→│ OBSERVE │
            └────────┘    └─────────┘
                 │
            超时/超步数
                 │
            ┌────▼────┐
            │ 终止+降级 │
            └─────────┘

THINK:  LLM 分析现状 → "需要查天气" 或 "信息够了直接回答"
ACT:    生成工具调用 → get_weather("北京")
OBSERVE: 执行工具 → 获得结果 → 回填 → 回到 THINK
```

### Q2: 怎么防止 Agent 死循环？

> 三层防御：
> 1. **重复检测**：连续 3 次相同工具调用 → 提示"尝试不同方法"
> 2. **振荡检测**：A→B→A→B 模式 → 提示突破循环
> 3. **硬上限**：max_steps=10 + timeout=300s → 强制终止+返回部分结果

### Q3: Reflexion 的核心循环是什么？为什么有效？

> Attempt → Evaluate → Reflect → Retry
> 有效原因：把"错误"转化为"学习信号"——不是盲目重试，而是分析失败原因 → 形成改进策略 → 带着教训重试
> HumanEval: +21.2%（不换模型，只加反射循环）

### Q4: Function Calling 的并行和串行怎么选？

> 工具间无依赖 → 并行（省时间）
> 工具间有依赖 → 串行（B 需要 A 的输出）
> 不确定 → 乐观并行，失败回退串行

### Q5: 多 Agent 协作怎么控制 Token 成本？

> 1. 用不同等级模型（大模型决策，小模型执行）
> 2. 子 Agent 只返回摘要
> 3. 并行执行（不等，同时跑）
> 4. 消息总线只传结构化数据，不传全文

### Q6: DPO 和 RLHF 的循环差异？

| 维度 | RLHF | DPO |
|------|:---:|:---:|
| 循环复杂度 | SFT→RM→PPO 三阶段 | 直接优化 |
| 所需模型数 | 4 | 1-2 |
| 训练稳定性 | 低 | 高 |
| 谁在用 | GPT-4, Claude | Llama 3, Qwen |

### Q7: 怎么设计一个"数据飞轮"？

> 1. 冷启动：GPT-4 代跑 → 收集数据
> 2. 隐性反馈采集：采纳率、追问率、修改率
> 3. 中速循环：每周用新数据微调
> 4. 监控：有机增长 > 30% = 飞轮在转

### Q8: 记忆系统的 Frozen Snapshot 是什么？为什么用？

> 会话开始时读取记忆 → 拍快照 → 注入 System Prompt
> 会话内写入只持久化到磁盘，不更新 System Prompt
> 原因：System Prompt 不变 → 前缀缓存稳定 → API 成本降 90%

## 2. 设计题模板

### "设计一个智能客服的 Agent 循环"

```text
架构层次：

L1 执行循环（ReAct）：
  用户提问 → 意图识别 → 路由(售前/售后/投诉)
  → 检索知识库 → 如需查订单 → Function Calling
  → 生成回答 → 用户不满意 → 转人工

L2 改进循环（Reflexion）：
  用户点踩 → 记录失败原因 → 分类(知识盲区/理解错误/格式问题)
  → 更新知识库 → 下次同类问题改进

L3 飞轮循环（Data Flywheel）：
  用户交互 → 高质量对话 → 每周标注 100 条
  → 微调模型 → 自动解决率提升

L4 工程保障：
  → 单轮超时: 5s → 降级到快捷回复
  → 死循环: max 3 次查知识库 → 转人工
  → 熔断: API 连续失败 > 5 → 切换到备用模型
```

## 3. 全系列知识地图

| 文件 | 一句话精华 |

## 核心要点回顾

- 循环设计 = 正常流程 + 异常处理 + 降级策略
- 面试三层次：画图(能描述) → 设计(会选参数) → 防错(有工程意识)
- 死循环是 Agent 最高频问题，三层防御是必答项
- 所有循环必须有 max_steps、timeout、budget 三大硬上限
