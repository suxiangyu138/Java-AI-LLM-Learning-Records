## 3. 为什么必须学透 Milvus

1. **RAG 的存储引擎标配**：企业级 RAG 系统的向量存储，Milvus 是国内与全球采用率最高的开源选择——Spring AI、LangChain4j、LangChain、Dify 全部官方集成。
2. **2026 年刚完成代际升级**：**Milvus 3.0（2026-07-16 GA）** 的 Lake-Native 架构（外部集合直读数据湖、快照、StructList 多向量）是向量数据库史上最大更新——**老教程的 2.x 内容已不完整，本体系按 3.0 现状撰写**。
3. **混合检索是 RAG 质量的胜负手**：稠密向量（语义）+ 稀疏向量（BM25 关键词）的混合检索（2.5+ 原生支持）显著提升召回——这是 2025 年后 RAG 工程的核心技能。
4. **Java 生态集成是后端人的强项**：Spring AI 的 `VectorStore` 与 LangChain4j 的 `langchain4j-milvus` 让 Java 开发者无缝接入向量检索——本体系给 Java 视角的完整链路。
5. **面试新热点**：向量数据库是 AI 应用面试的高频新题——索引原理、混合检索、3.0 新特性，答得深就是加分项。

## 4. 核心概念速查

### 4.1 核心概念

| 概念 | 一句话 | 类比（关系型） |
|------|--------|--------------|
| Collection | 向量数据的容器（表） | 表 |
| Schema | 字段与类型定义（含向量字段） | 建表语句 |
| 向量字段 | FLOAT_VECTOR 等（维数声明） | 特殊列 |
| 分区（Partition） | Collection 内部分组 | 分区表 |
| 分片（Shard） | 数据水平切分（主键哈希） | 分表 |
| 索引（Index） | 加速 ANN 检索的数据结构 | 索引 |
| 度量（Metric） | L2/IP/COSINE 相似度算法 | 排序规则 |

### 4.2 索引类型速查

| 索引 | 适用规模 | 召回 | 内存 | 场景 |
|------|:-------:|:----:|:----:|------|
| FLAT | <10 万 | 100% | 高 | 精确检索/小数据 |
| IVF_FLAT | 百万级 | 高 | 中 | 通用入门 |
| IVF_SQ8 | 百万级 | 中高 | 低（省 70%） | 内存受限 |
| **HNSW** | 千万级 | 高 | 较高 | **生产首选** |
| DiskANN | 亿级 | 高 | 低（磁盘） | 超大规模 |

### 4.3 版本时间线（时效性重点）

| 版本 | 时间 | 关键变化 |
|------|:----:|---------|
| 2.4 | 2024 | 分区键、upsert、流式 API |
| **2.5** | 2025 | **内置 Sparse-BM25 全文检索**、TEXT_MATCH、RRF 混合检索 |
| **2.6** | 2025 Q1 | 内存降 72%、检索快 4 倍（<50ms）、写入吞吐 2.5 倍 |
| **3.0** | **2026-07-16 GA** | **Lake-Native 架构**：外部集合、Loon 存储、快照、StructList、SINDI |
| 3.1 | 2026 年底规划 | 谓词下推、PK 去重、UDF 等 |

## 6. 学习路线推荐

**路线一：快速上手（1~2 天，对应模块 01-03）**
定位与版本 → 核心概念 → 部署（Milvus Lite 起步，零成本）；用 pymilvus 或 Spring AI 跑通"写入 → 检索"最小链路。

**路线二：进阶深化（1 周，对应模块 04-07）**
Schema 设计 → 索引调优 → 混合检索 → 生态集成；用 Spring AI + Milvus 搭一个完整 RAG 应用（文档入库 → 混合检索 → LLM 回答）。

**路线三：生产实战（对应模块 08-09）**
监控与性能 → 多租户与快照 → 面试冲刺；结合 `04-向量数据库/` 的索引原理补齐底层认知。

> 🎯 **核心要点**：Milvus 的学习终点 = "**会建 Schema、会选索引、会混合检索、会看监控**"——四件事覆盖从原型到生产的全部链路；3.0 的 Lake-Native 概念是 2026 年的新加分点。
