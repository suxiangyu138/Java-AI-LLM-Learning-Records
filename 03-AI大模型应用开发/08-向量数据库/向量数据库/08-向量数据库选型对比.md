## 2. 选型决策树

```text
选择向量数据库：

  原型阶段 → Chroma（最简单）
  
  生产环境：
    ├── 向量 < 100万, 嵌入式 → FAISS（性能极致）
    ├── 向量 > 100万, 需分布式 → Milvus（最成熟）
    ├── 零运维要求 → Pinecone（SaaS 首选）
    ├── 需复杂过滤 → Qdrant（过滤最强）
    └── 需自动向量化 → Weaviate（内置 Embedding）
  
  特殊需求：
    ├── GPU 加速 → FAISS / Milvus
    ├── Java SDK → Milvus / Pinecone / Qdrant
    └── 数据隐私 → 自建 Milvus / Qdrant
```

### Java 后端选型建议

```text
Milvus：Java SDK 最成熟 → 首选
Pinecone：REST API → 语言无关
Qdrant：Java Client + gRPC

不推荐：Chroma（无 Java SDK）、FAISS（C++ 库，需 JNI）
```

## 3. 成本分析

### 自建成本（Milvus 100万向量）

| 资源 | 规格 | 月成本 |
|------|------|:---:|
| 云服务器 | 8C16G | ¥400 |
| 对象存储 | 100GB | ¥15 |
| 带宽 | 5Mbps | ¥100 |
| 运维人力 | 0.2 人 | ¥2000 |
| **合计** | | **~¥2500/月** |

### 云服务成本（Pinecone 100万向量）

| 方案 | 配置 | 月成本 |
|------|------|:---:|
| Pinecone Serverless | 100万 × 1024维 | ~$70/月 |
| Zilliz Cloud (Milvus) | 同等配置 | ~$50/月 |

```text
结论：
  → <100 万向量 → 自建更划算
  → >100 万向量 + 小团队 → 云服务性价比更高（省运维）
  → 数据敏感 → 无价 → 必须自建
```

## 6. 2026 选型决策框架

**核心判断标准（2026 共识）——不是"谁快"，而是数据架构**：

```text
第一问：向量数据与关系数据的关联程度？
  → 频繁关联订单/用户/权限等结构化数据 → 融合型（pgvector/SQL+AI）
  → 纯向量检索 + 上亿数据 → 独立向量库（Milvus/Qdrant）
第二问：现有技术栈？
  → 已有 Postgres 且 <5000 万向量 → pgvector（零新增基础设施）
  → 已有 Elasticsearch → 搜索扩展（向量一体）
第三问：运维能力与预算？
  → 有运维团队 → 自建（Milvus/Qdrant）
  → 无运维/快速上线 → 托管（Pinecone/Zilliz Cloud）
第四问：检索形态？
  → 混合检索刚需 → Weaviate/Qdrant（原生 BM25+RRF）
  → 过滤占比高 → Qdrant（原生过滤索引）
  → 亿级/高 QPS → Milvus（云原生 + DiskANN）
```

**六维评估清单**（2026 推荐）：

```text
① 性能：P50/P95/P99 延迟 + 召回率（真实数据）
② 扩展性：水平扩展/亿级支持（DiskANN 等）
③ 混合检索：BM25+稠密+RRF 是否原生
④ 生态集成：Spring AI/LangChain4j/框架支持
⑤ 数据一致性：事务/更新/删除语义
⑥ 部署与合规：自建/托管、数据主权、许可证

最终动作：用真实数据（含真实过滤条件）做 POC 验证，别信基准测试
```

> 🎯 **核心要点**：2026 选型 = "**数据关联度 → 技术栈 → 运维 → 检索形态**"四问 + 六维评估 + POC 验证——**"最好的新基础设施往往就是不加新基础设施"**（pgvector 默认起点）。

## 7. 选型速查卡（一页版）

**按场景直接查答案**：

| 你的情况 | 首选 | 备选 |
|---------|:----:|:----:|
| 已有 Postgres，<5000 万向量 | **pgvector** | Milvus |
| 快速验证原型 | Chroma / Pinecone | FAISS |
| 自托管 + 性能/过滤 | **Qdrant** | Milvus |
| 混合检索刚需 | **Weaviate** | Qdrant |
| 亿级/高 QPS | **Milvus** | 云托管 |
| 数据强关联关系表 | **pgvector**（SQL 融合） | 融合型库 |
| 嵌入式/离线 | FAISS | LanceDB |
| 无运维 + 可锁定 | Pinecone | Zilliz Cloud |

**一句话决策口诀（2026）**：

```text
"数据关系强选融合（pgvector）、自托管性能选 Qdrant、
 混合检索选 Weaviate、亿级高并发选 Milvus、
 快速验证 Chroma/Pinecone、嵌入式离线 FAISS"
```

**POC 验证清单**（选型最后一步）：

```text
□ 真实数据（规模 ≥ 生产量的 10%）
□ 真实过滤条件（租户/状态/时间）
□ 真实查询分布（Top 高频问题）
□ 测三指标：P95 延迟 / Recall@10 / 写入吞吐
□ 对比 2-3 个候选（同数据同查询）
```

> 🎯 **核心要点**：选型终局 = "**场景速查卡（一页答案）+ 决策口诀 + POC 验证**"——**速查卡给方向、POC 给数据**；2026 共识：不 POC 的选型都是拍脑袋。

## 8. 成本分析速查

**各方案的 TCO 维度**（选型必算的账）：

| 方案 | 硬件/许可 | 运维成本 | 规模化成本 |
|------|:---------:|:--------:|:----------:|
| pgvector | 复用现有 PG | 极低 | 5000 万上限后需迁移 |
| Qdrant（自建） | 低（Rust 高效） | 中 | 中等（单机可撑千万级） |
| Milvus（自建） | 中（组件多） | **高（运维团队）** | 低（亿级水平扩展） |
| Pinecone | — | 零 | **高（规模化成本）** |
| Zilliz Cloud | — | 零 | 中（按量） |
| FAISS | 零（库） | 低 | 不适合在线规模化 |

**成本决策要点**：

```text
① 中小规模（<千万）自托管：Qdrant 性价比最高（Rust 省资源）
② 已有 Postgres：pgvector 零新增（先跑通再迁移）
③ 亿级：自建 Milvus（运维成本换规模化成本）或托管
④ 快速验证：Pinecone（验证后评估是否迁移）
⑤ 隐含成本：迁移成本（重入库）> 库本身差价 —— 选型一次到位

2026 共识：成本不是"谁便宜"而是"总拥有成本（TCO）"：
  硬件 + 运维人力 + 迁移风险 + 规模化曲线 四项合计
```

> 🎯 **核心要点**：成本分析 = "**TCO 四维（硬件/运维/迁移/规模化）**"——**"重入库的迁移成本往往大于库差价"**是选型一次到位的核心理由；中小规模 Qdrant、亿级 Milvus、已有 PG 用 pgvector 是 2026 的三个默认答案。

## 核心要点回顾

- 原型 Chroma、生产 Milvus、零运维 Pinecone、过滤 Qdrant
- Java 后端首选 Milvus（SDK 最成熟）
- 自建 vs 云：<100万自建划算，>100万+小团队云服务更优
