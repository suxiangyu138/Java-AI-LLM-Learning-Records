# 安装与快速开始

> Docker 一条命令起 Redis 8，FT.CREATE 建索引 + FT.SEARCH 查询的最小闭环——半小时跑通搜索与向量检索

## 1. 安装形态：Docker 与二进制

Redis 8 的安装与 Redis 本体一致（能力内置，无额外模块）：

```bash
# Docker（推荐）：Redis 8 官方镜像，能力全内置
docker run -d --name redis8 \
  -p 6379:6379 -p 8001:8001 \
  -v $(pwd)/redis-data:/data \
  redis:8.0.6

# 验证：搜索命令可用即证明内置
docker exec -it redis8 redis-cli FT._LIST
# (empty array)  ← 无索引但命令存在 = 内置生效
```

两个端口的分工：**6379** = Redis 协议（客户端连接）；**8001** = Redis Insight Web UI（可视化浏览数据、索引、向量——排查与演示利器）。注意 **`redis/redis-stack` 镜像已停更**（Stack 维护版 2025-12 终止），新项目一律用 `redis:8.x` 官方镜像——老教程的 Stack 镜像安装方式已失效。

Docker 部署的三个生产增强：**持久化**（`--appendonly yes` 开启 AOF——向量数据丢失不可接受，纯缓存场景才可关）；**内存限制**（`--maxmemory` 按预算设、`--maxmemory-policy noeviction`——向量场景禁止淘汰，见 02 篇）；**配置外置**（`-v redis.conf:/usr/local/etc/redis/redis.conf` 挂载配置——生产参数（ACL/持久化/内存）集中在配置文件管理，不靠命令行散配）。

非 Docker 部署（K8s/裸机）：官方 Helm chart（`redis/redis` 或 Redis Enterprise Operator）；裸机用发行版包（Ubuntu `redis-server` 8.x 源）——**验证"8.x"版本**（`redis-server --version` 与 `FT._LIST` 命令存在性双确认），老版本 Redis（6/7 无模块）跑 `FT.SEARCH` 直接报 Unknown command。

## 2. 最小闭环：建索引 + 写入 + 搜索

```bash
# 1. 建索引：JSON 文档，索引 title（全文）与 category（枚举）
FT.CREATE idx:docs ON JSON PREFIX 1 doc:
  SCHEMA
    $.title AS title TEXT
    $.category AS category TAG

# 2. 写入数据（原生 JSON 命令，索引自动同步）
JSON.SET doc:1 $ '{"title": "JVM 内存模型详解", "category": "jvm"}'
JSON.SET doc:2 $ '{"title": "Redis 8 向量搜索实战", "category": "redis"}'

# 3. 查询：全文搜索 + 过滤
FT.SEARCH idx:docs "@title:向量" DIALECT 2
FT.SEARCH idx:docs "@category:{jvm}" DIALECT 2
```

三步理解：**索引是旁路的**（写入走 `JSON.SET`，索引自动更新）；**查询语法是类 Lucene 的**（`@title:向量` 全文、`@category:{jvm}` 枚举精确）；**`DIALECT 2` 是查询方言版本**（Redis 8 默认，支持 KNN/聚合等高级语法——老教程的 DIALECT 1 语法部分失效）。

## 3. 向量检索最小闭环

```bash
# 1. 建含向量字段的索引
FT.CREATE idx:vec ON JSON PREFIX 1 item:
  SCHEMA
    $.embedding AS embedding VECTOR HNSW 6 TYPE FLOAT32 DIM 4 DISTANCE_METRIC COSINE
    $.name AS name TEXT

# 2. 写入带向量的文档（JSON 数组浮点数）
JSON.SET item:1 $ '{"name": "苹果", "embedding": [0.1, 0.2, 0.3, 0.4]}'
JSON.SET item:2 $ '{"name": "香蕉", "embedding": [0.9, 0.8, 0.7, 0.6]}'

# 3. KNN 检索：返回最相似的 top-2
FT.SEARCH idx:vec "*=>[KNN 2 @embedding $vec]"
  PARAMS 2 vec "QUERY_EMBEDDING_BYTES"
  SORTBY __embedding_score
  DIALECT 2
```

向量查询的三要素：**`*=>[KNN k @字段 $参数]` 是 KNN 子句**（`*` 是"不过滤"占位）；**`PARAMS` 传向量字节**（Hash 存二进制、JSON 查询时同样要二进制 blob——应用层负责把浮点数组转字节）；**`__embedding_score` 是距离字段**（越小越相似，可用 `AS score` 改名）。

## 4. Hash 存储形态与客户端连接

JSON 是推荐的文档形态，**Hash 形态同样支持**（向量存二进制）：

```bash
FT.CREATE idx:h ON HASH PREFIX 1 doc:
  SCHEMA embedding VECTOR HNSW 6 TYPE FLOAT32 DIM 4 DISTANCE_METRIC COSINE name TEXT

# Hash 写入：向量是二进制 blob（应用层序列化 float32）
HSET doc:1 embedding "\x3d\xcc\xcc\x3e\x66\x66\x3f\x33\x33" name "苹果"
```

两种形态的选型：**JSON**（嵌套结构 + JSONPath + 可读性好，生产推荐）；**Hash**（扁平字段 + 二进制向量，极致紧凑）。查询侧一致（都传字节 blob），**写侧序列化不同**（JSON 数组 vs 二进制）——跨形态迁移时这是最常见报错点。

**客户端连接**（Java 视角）：Jedis/Lettuce/Redisson 均兼容 Redis 8（FT.* 命令走原生命令通道）；Spring Data Redis 的 `RedisTemplate` 可直接执行 `FT.SEARCH`（`execute` 原生命令）；Redis Insight（8001）可视化浏览索引与向量——排查"数据进没进索引"用 Insight 比 redis-cli 直观一个量级。

## 5. 命令族速查

| 命令族 | 职责 | 高频命令 |
|--------|------|---------|
| `FT.CREATE`/`FT.SEARCH`/`FT.AGGREGATE` | 索引与查询 | 建索引、检索、聚合 |
| `FT._LIST`/`FT.INFO` | 索引管理 | 列索引、看配置 |
| `FT.ALTER`/`FT.DROPINDEX` | 索引变更 | 加字段、删索引 |
| `JSON.*` | JSON 文档 | SET/GET/MERGE/ARRAPPEND |
| `VADD`/`VSIM`/`VCARD` | Vector Set（beta） | 向量集增删查 |

**弃用命令族**（还在用必须改）：`FT.ADD`/`FT.SAFEADD`/`FT.DEL`/`FT.GET`/`FT.MGET`/`FT.SYNADD`/`FT.DROP`——全部被 `FT.CREATE`+`FT.SEARCH` 模式取代；`FT.SYNADD` 用 `FT.SYNUPDATE` 替代。存量脚本迁移时全局搜索这些命令替换（10 篇迁移清单）。

## 6. 向量字节生成（应用侧必会）

KNN 查询的 `PARAMS` 传的是**向量字节 blob**，应用层负责把浮点数组转字节。Python 与 Java 的标准做法：

```python
import struct

# Python：float32 数组 → 字节（Redis 端 TYPE FLOAT32 对应）
def vec_to_blob(vec):
    return struct.pack(f"{len(vec)}f", *vec)   # 大端/小端按平台，Redis 用原生序

# 查询
FT.SEARCH("idx:vec", f"*=>[KNN 5 @embedding $vec]",
          params={"vec": vec_to_blob(query_vec)},
          sortby="__embedding_score", dialect=2)
```

```java
// Java：float[] → byte[]（ByteBuffer 大端序）
byte[] blob = new byte[dim * 4];
ByteBuffer.wrap(blob).order(ByteOrder.BIG_ENDIAN).asFloatBuffer().put(vector);
```

三个注意：**字节数必须 = DIM × 4**（float32 每维 4 字节，报维度错误先查这里）；**端序与模型输出一致**（同一模型同一端序，跨语言迁移时核对）；**不要手拼字符串**（用语言原生序列化，Python `struct`/Java `ByteBuffer`——手拼 hex 字符串最容易出错）。

## 7. 快速排错四板斧

- **"Unknown command 'FT.SEARCH'"**：连接的是老 Redis（<8 且无模块）——确认镜像版本与客户端连接地址。
- **"Index not found"**：索引名错误或还没建——`FT._LIST` 核对。
- **"Dialect version mismatch"**：查询方言与索引不匹配——统一 `DIALECT 2`。
- **维度报错**：向量字节数与 `DIM` 不符（4 维要 16 字节 float32）——核对模型输出与 DIM。

排错心智：**先 `FT.INFO` 看索引配置**（字段/类型/DIM 全在），再验证数据（`JSON.GET` 看文档是否进 PREFIX 匹配），最后查查询语法——配置 → 数据 → 语法三层，比乱试快一个量级。

客户端连接的版本陷阱：**老客户端库（Jedis 3.x/Lettuce 6.x 时代）不认识 FT./JSON./TS. 命令族会报 Unknown command**——Redis 8 与客户端库的版本匹配检查（客户端升级到 2025+ 版本）；云托管实例（Redis Cloud/托管平台）的版本确认用 `INFO server` 的 `redis_version` 字段，**不要假设托管平台已升级 8.x**（部分平台仍是 7.x 无模块）。排查"命令不存在"时先分清楚：是服务器没有能力（版本低）还是客户端不支持（库太老）——两端版本都要确认。

快速上手的三句话总结：**一条 Docker 命令起服务**（`redis:8.x`，能力全内置）；**三个命令跑通检索**（FT.CREATE 建索引 → JSON.SET 写数据 → FT.SEARCH 查结果）；**两个排错入口**（`FT._LIST` 看索引存在、`FT.INFO` 看配置细节）——本体系后续篇目都是在这套最小闭环上加深：全文检索字段（04）、向量索引参数（05）、混合查询（06）、数据扩展（07）、Java 集成（08）。

最小闭环的验收标准（跑通即毕业）：**建索引 → 写 3 条数据 → 全文查中 1 条 → 过滤查中 1 条 → KNN 返回 top-2 且分数合理**——五个动作全过，Redis 8 的搜索能力骨架就掌握了；后续所有高级特性（混合查询/聚合/Vector Set/Spring AI）都是在这五个动作上做加法。

学习路径对照（四套向量库体系的第一课都是"最小闭环"）：Chroma 是 `PersistentClient + add/query`、PgVector 是 `CREATE EXTENSION + <=>`、Qdrant 是 `create_collection + query_points`、Redis 8 是 `FT.CREATE + FT.SEARCH`——**"建容器/索引 → 写入 → 相似检索"是四套体系共用的骨架**，学会 Redis 8 的这五个动作，另三套的第一课可以半小时内扫完（知识可迁移性，与各体系 03 篇的结论一致）。

> 🎯 **核心要点**：`redis:8.x` 镜像替代已停更的 Stack 镜像；FT.CREATE + JSON.SET + FT.SEARCH 三命令闭环；KNN 三要素（子句/PARAMS/距离字段）；`DIALECT 2` 是 8 的统一方言；弃用命令族（FT.ADD 等）存量脚本必改。
