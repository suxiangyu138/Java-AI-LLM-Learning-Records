## 1. 知识体系导图

```
WorkBuddy AI 工作搭子
│
├── 🏗️ 架构哲学层
│   ├── 模型 = 无状态函数（核心抽象）
│   ├── Harness 工程（驾驭 · 约束 · 整合）
│   └── 四层能力模型（Tools → MCP → Skill → Plugin）
│
├── 🧠 上下文工程层
│   ├── 写入（Write）—— 主动注入目标、规则、环境
│   ├── 选择（Select）—— 按需筛选放入窗口
│   ├── 检索（Retrieve）—— 从历史/资料库捞取
│   ├── 压缩（Compress）—— 长内容外置，留结论
│   └── 隔离（Isolate）—— Sub-agent 处理旁支
│
├── 🔧 工具与协议层
│   ├── Function Call —— 模型与外部系统的结构化协议
│   ├── MCP 协议 —— Resources / Tools / Prompts 三原语
│   ├── MCP Apps —— 工具返回交互式 UI（2026）
│   └── 权限边界 —— Sandbox / Approval Gate / Allowlist
│
├── 📦 能力封装层
│   ├── Skill —— 任务执行流程模板（可版本化、可回滚）
│   ├── Plugin —— MCP + Skills + Rules + Hooks 组合包
│   └── 分发与安装 —— 能力即代码，可共享复用
│
├── 🗄️ 记忆与状态层
│   ├── 五类长期记忆（事实/知识/行为/偏好/延续）
│   ├── 作用域层级（会话 → 项目 → 用户 → 团队）
│   └── 记忆写入门槛（作用域越大，晋升越严格）
│
├── 🤝 多 Agent 协作层
│   ├── 专家团模式（角色分工 + 并行研究 + 汇总整合）
│   ├── 双 Agent 跨机协作（共享信箱 + 三权分立）
│   ├── 软件开发闭环（PM → 架构 → 开发 → 测试）
│   └── 通信协议（交接文件规范、Token 铁律）
│
├── 💰 成本控制层
│   ├── 三层降级架构（LLM → 规则引擎 → 人工兜底）
│   ├── JSON 截断 / 超时白烧 / 格式兼容 / Mock 测试
│   └── 成本对比（高效果 ~3.7M vs 高性价比 ~0.8M）
│
└── 🚀 实战落地层
    ├── 环境搭建与配置
    ├── 第一个 WorkBuddy 项目
    ├── 知识库接入（IMA / RAG）
    └── 常见踩坑与解决方案
```

## 3. 学习路线推荐

### 🟢 入门路线（1-2 天）

```
01 概念与架构哲学 → 08 实战搭建与落地
```

先理解"模型是无状态函数"这一核心抽象，再动手搭建第一个 WorkBuddy 项目。建立感性认知后，遇到具体问题再到对应模块深挖。

### 🟡 进阶路线（3-5 天）

```
01 概念与架构 → 03 工具调用与 MCP → 07 成本控制 → 04 Skill 与 Plugin → 06 多 Agent 协作
```

适合已有 LLM 应用开发经验的开发者。重点掌握 MCP 协议集成、成本降级设计、以及多 Agent 编排能力。

### 🔴 深入路线（1-2 周）

```
01 → 02 → 03 → 04 → 05 → 06 → 07 → 08（全模块通读 + 动手实践）
```

面向平台开发者或架构师。深入理解 Harness 工程和上下文管理的设计哲学，掌握 Skill/Plugin 的分发体系，能独立设计多 Agent 协作系统。

## 4. 核心概念速查

| 概念 | 一句话定义 | 详细模块 |
|------|-----------|:---:|
| **Harness 工程** | 驾驭（Steer）+ 约束（Constrain）+ 整合（Integrate）的工程机制，让模型能力转化为可靠产品 | [02](02-Harness工程与上下文管理.md) |
| **模型无状态** | 模型 = 输入上下文 → 输出文字的函数，状态由外部工程层维护 | [01](01-WorkBuddy概念与架构哲学.md) |
| **Context Engineering** | 设计什么信息、以什么形式、放在什么位置进入上下文，何时更新或移出 | [02](02-Harness工程与上下文管理.md) |
| **MCP** | Model Context Protocol，Anthropic 发布的标准化连接协议，三种原语：Resources/Tools/Prompts | [03](03-工具调用与MCP集成.md) |
| **Skill** | 将一类任务的执行流程沉淀为可复用的版本化模板 | [04](04-Skill与Plugin能力体系.md) |
| **Plugin** | MCP + Skills + Rules + Hooks 的组合能力包，可安装分发 | [04](04-Skill与Plugin能力体系.md) |
| **ReAct 循环** | 模型判断 → 工具调用 → 观察结果 → 再判断的多轮执行模式 | [01](01-WorkBuddy概念与架构哲学.md) |
| **专家团** | 多个 Agent 按角色分工，并行研究后由汇总 Agent 整合输出的协作模式 | [06](06-多Agent协作与编排.md) |
| **三层降级** | L1 LLM → L2 规则引擎 → L3 人工兜底，保证 LLM 不可用时系统仍可用 | [07](07-成本控制与性能优化.md) |
| **Token 铁律** | 不寒暄、不复述、不解释常识；引用而非转述；单次预算设限 | [06](06-多Agent协作与编排.md) |
| **Prompt Cache** | 稳定的 System Prompt 和工具定义放前面 → 动态内容追加后面 → 提高缓存命中率 | [02](02-Harness工程与上下文管理.md) |
| **程序性记忆边界** | 不将局部工作方法自动纳入长期记忆，避免局部经验误升为通用策略 | [05](05-记忆系统与状态管理.md) |

---

> 🎯 **核心要点**：WorkBuddy 的本质不是"更好的 Prompt"，而是一套让模型从"能说"到"能做"的完整工程体系。理解模型的无状态性，掌握 Harness 工程的三个维度（驾驭、约束、整合），是构建可靠 AI Agent 产品的关键。
