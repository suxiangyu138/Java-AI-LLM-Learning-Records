## 2. 第一个 WorkBuddy Agent

### 2.1 目标

创建一个能够**自动审查 Git 变更**的 Agent。

### 2.2 Step 1：定义 Agent

```yaml
# skills/code-review.skill.yaml
name: "代码审查"
version: "1.0.0"
description: "自动审查 Git 暂存区的代码变更"

steps:
  - id: "get_diff"
    name: "获取变更"
    tool: "git_diff"
    args:
      staged: true
      context_lines: 3

  - id: "analyze"
    name: "多维度分析"
    depends_on: ["get_diff"]
    tool: "llm_analyze"
    prompt: |
      你是资深代码审查专家。对以下 Git diff 进行审查：

      ## 检查清单
      1. **安全**：SQL 注入、XSS、敏感信息泄露、不安全加密
      2. **逻辑**：空指针、边界条件、异常处理
      3. **性能**：N+1 查询、不必要对象创建、同步阻塞
      4. **规范**：命名、注释、代码结构

      ## 输出格式
      | 级别 | 文件 | 行号 | 问题 | 建议 |

      每个问题必须包含具体的修复代码示例。

  - id: "report"
    name: "生成报告"
    depends_on: ["analyze"]
    output:
      format: "markdown"
      file: "review-report-{timestamp}.md"
```

## 3. MCP Server 实战

### 3.1 目标

创建一个 **GitHub Issues MCP Server**，让 WorkBuddy 能查询和创建 Issue。

### 3.2 实现

```python
# mcp-servers/github_issues/server.py
"""
GitHub Issues MCP Server
提供 Resources 和 Tools 两种能力：
- Resources: 读取 Issue 列表和详情
- Tools: 创建和更新 Issue
"""

import json
import os
import sys
import requests
from typing import Any

GITHUB_TOKEN = os.environ.get("GITHUB_TOKEN", "")
GITHUB_REPO = os.environ.get("GITHUB_REPO", "")
BASE_URL = f"https://api.github.com/repos/{GITHUB_REPO}"

HEADERS = {
    "Authorization": f"Bearer {GITHUB_TOKEN}",
    "Accept": "application/vnd.github+json",
    "X-GitHub-Api-Version": "2022-11-28"
}


def list_tools() -> dict:
    """返回可用工具列表"""
    return {
        "tools": [
            {
                "name": "list_issues",
                "description": "获取仓库的 Issue 列表，支持按状态（open/closed/all）过滤",
                "inputSchema": {
                    "type": "object",
                    "properties": {
                        "state": {
                            "type": "string",
                            "enum": ["open", "closed", "all"],
                            "description": "Issue 状态过滤"
                        },
                        "labels": {
                            "type": "string",
                            "description": "按标签过滤，逗号分隔"
                        },
                        "per_page": {
                            "type": "integer",
                            "description": "每页返回数量，默认 10，最大 100",
                            "default": 10
                        }
                    }
                }
            },
            {
                "name": "get_issue",
                "description": "获取指定 Issue 的详细信息，包括标题、内容、标签、评论",
                "inputSchema": {
                    "type": "object",
                    "properties": {
                        "issue_number": {
                            "type": "integer",
                            "description": "Issue 编号"
                        }
                    },
                    "required": ["issue_number"]
                }
            },
            {
                "name": "create_issue",
                "description": "在仓库中创建一个新的 Issue。需要用户确认后才能执行",
                "inputSchema": {
                    "type": "object",
                    "properties": {
                        "title": {
                            "type": "string",
                            "description": "Issue 标题"
                        },
                        "body": {
                            "type": "string",
                            "description": "Issue 内容（支持 Markdown）"
                        },
                        "labels": {
                            "type": "array",
                            "items": {"type": "string"},
                            "description": "标签列表"
                        },
                        "assignees": {
                            "type": "array",
                            "items": {"type": "string"},
                            "description": "负责人列表（GitHub 用户名）"
                        }
                    },
                    "required": ["title"]
                }
            }
        ]
    }


def call_tool(name: str, arguments: dict) -> str:
    """执行工具调用"""
    try:
        if name == "list_issues":
            return list_github_issues(arguments)
        elif name == "get_issue":
            return get_github_issue(arguments)
        elif name == "create_issue":
            return create_github_issue(arguments)
        else:
            return f"❌ 未知工具：{name}"
    except requests.RequestException as e:
        return f"❌ API 请求失败：{str(e)}"
    except Exception as e:
        return f"❌ 执行失败：{str(e)}"


def list_github_issues(args: dict) -> str:
    """列出 GitHub Issues"""
    params = {
        "state": args.get("state", "open"),
        "per_page": min(args.get("per_page", 10), 100)
    }
    if args.get("labels"):
        params["labels"] = args["labels"]

    resp = requests.get(f"{BASE_URL}/issues", headers=HEADERS, params=params)
    resp.raise_for_status()

    issues = resp.json()
    if not issues:
        return "📭 没有找到符合条件的 Issue"

    lines = [f"## Issues ({params['state']})\n"]
    for issue in issues:
        labels = " ".join(f"`{l['name']}`" for l in issue.get("labels", []))
        lines.append(
            f"- [#{issue['number']}]({issue['html_url']}) "
            f"{issue['title']} {labels} "
            f"(@{issue['user']['login']})"
        )

    return "\n".join(lines)


def get_github_issue(args: dict) -> str:
    """获取单个 Issue 详情"""
    number = args["issue_number"]
    resp = requests.get(f"{BASE_URL}/issues/{number}", headers=HEADERS)
    resp.raise_for_status()

    issue = resp.json()
    return f"""## #{issue['number']} {issue['title']}

**状态**：{issue['state']} | **作者**：@{issue['user']['login']}
**创建**：{issue['created_at']} | **更新**：{issue['updated_at']}

{issue.get('body', '_(无描述)_')}
"""


def create_github_issue(args: dict) -> str:
    """创建 GitHub Issue"""
    payload = {
        "title": args["title"],
        "body": args.get("body", "")
    }
    if args.get("labels"):
        payload["labels"] = args["labels"]
    if args.get("assignees"):
        payload["assignees"] = args["assignees"]

    resp = requests.post(
        f"{BASE_URL}/issues",
        headers=HEADERS,
        json=payload
    )
    resp.raise_for_status()

    issue = resp.json()
    return f"✅ Issue 已创建：[#{issue['number']}]({issue['html_url']})"


def handle_request(request: dict) -> dict:
    """MCP JSON-RPC 请求处理入口"""
    method = request.get("method")

    if method == "tools/list":
        return list_tools()

    elif method == "tools/call":
        params = request.get("params", {})
        tool_name = params.get("name", "")
        arguments = params.get("arguments", {})

        result_text = call_tool(tool_name, arguments)
        return {
            "content": [{"type": "text", "text": result_text}]
        }

    return {"error": f"Unknown method: {method}"}


if __name__ == "__main__":
    # stdio 模式：读取 JSON-RPC 请求，返回 JSON-RPC 响应
    for line in sys.stdin:
        if not line.strip():
            continue
        try:
            request = json.loads(line)
            response = handle_request(request)
            sys.stdout.write(json.dumps(response) + "\n")
            sys.stdout.flush()
        except json.JSONDecodeError:
            sys.stderr.write(f"Invalid JSON: {line}\n")
            sys.stderr.flush()
```

# orchestration/blog-writing.yaml
name: "技术博客自动写作"
description: "从技术笔记自动生成结构化博客文章"

pipeline:
  # 阶段 1：并行研究
  - stage: "research"
    mode: parallel
    agents:
      - role: "背景研究员"
        tools: ["web_search", "knowledge_base_search"]
        prompt: |
          研究主题"{topic}"的：
          1. 业界现状和发展趋势
          2. 主流解决方案对比
          3. 最佳实践总结
          输出：结构化研究笔记（Markdown）

      - role: "代码研究员"
        tools: ["read_file", "grep", "knowledge_base_search"]
        prompt: |
          搜集主题"{topic}"相关的：
          1. 核心代码示例（可运行的）
          2. 配置文件模板
          3. 常见错误和修复方法
          输出：代码示例集合（带注释）

      - role: "读者需求研究员"
        tools: ["web_search"]
        prompt: |
          分析目标读者（{audience}）：
          1. 他们最想解决什么问题？
          2. 他们的技术水平如何？
          3. 什么内容形式最受欢迎？
          输出：读者需求分析

  # 阶段 2：大纲设计
  - stage: "outline"
    depends_on: ["research"]
    agents:
      - role: "主编"
        prompt: |
          基于三位研究员的结果，设计博客大纲：
          1. 标题（3 个备选，要求有吸引力）
          2. 结构（引言 → 正文 4-6 节 → 总结）
          3. 每节要点（2-3 个关键点）
          4. 标注需要代码示例的位置

  # 阶段 3：初稿撰写
  - stage: "draft"
    depends_on: ["outline"]
    agents:
      - role: "撰稿人"
        prompt: |
          按大纲撰写初稿：
          - 字数：2000-3000 字
          - 风格：技术博客，通俗易懂
          - 代码示例：完整可运行，带注释

  # 阶段 4：质量审查

      - role: "技术审稿人"

      - role: "编辑审稿人"
        prompt: "检查逻辑连贯性、可读性、排版"

  # 阶段 5：终稿
  - stage: "finalize"
    depends_on: ["review"]
    agents:
      - role: "终审编辑"
        prompt: "根据审稿意见修改，输出最终成稿"

quality_gates:
  - "字数 2000-3000"
  - "至少 3 个可运行的代码示例"
  - "无错别字和语法错误"
  - "所有技术术语使用正确"

## 6. 常见踩坑与解决方案

### 6.1 踩坑汇总

| 序号 | 坑 | 现象 | 根因 | 解决方案 |
|:---:|------|------|------|---------|
| 1 | **上下文溢出** | Agent 突然"失忆"，循环重复 | 上下文窗口超出限制 | 启用对话摘要 + 设置最大轮次 |
| 2 | **工具权限不足** | 所有文件操作都弹确认框 | 权限配置过于保守 | 区分安全等级，低风险自动通过 |
| 3 | **MCP Server 失联** | 对话中工具突然不可用 | Server 进程崩溃 | 健康检查 + 自动重启 |
| 4 | **编码问题** | Windows 下中文乱码 | 默认编码不一致 | 统一 UTF-8，配置 `chcp 65001` |
| 5 | **记忆污染** | 过时信息反复出现 | 记忆未更新或衰减 | 定期审查 + 设置有效期 |
| 6 | **Agent 死循环** | 工具调用→失败→重试→失败... | 无退出条件 | 设置 max_retry=3 + 降级策略 |
| 7 | **知识库检索不准** | 检索结果不相关 | 分块策略不当 | 用语义分块代替固定长度分块 |
| 8 | **多 Agent 结果冲突** | 不同 Agent 给出矛盾结论 | 缺少仲裁机制 | 增加仲裁 Agent + 记录分歧 |

### 6.2 Windows 环境特有问题

```text
Windows 下常见问题及解决：

1. 路径分隔符
   ❌ C:\Users\xxx\projects
   ✅ 统一使用正斜杠或 Path 对象

2. 换行符
   ❌ \r\n (CRLF) 在某些工具中解析异常
   ✅ .gitattributes 设置 text=auto

3. 编码
   ❌ GBK 编码文件在 MCP Server 中乱码
   ✅ 所有文件保存为 UTF-8

4. 权限
   ❌ 某些目录需要管理员权限
   ✅ 项目目录放在用户目录下

5. 进程通信
   ❌ stdio 模式在某些终端下不稳定
   ✅ 使用 SSE 模式替代 stdio
```

### 7.2 常见问题排查

```text
问题：Agent 回答质量突然下降
排查路径：
1. 检查上下文是否溢出 → workbuddy debug context --last
2. 检查是否触发了降级 → 查看日志中的 "degrade" 关键字
3. 检查 Prompt 是否被截断 → workbuddy debug prompt --last
4. 检查记忆是否污染 → workbuddy debug memory --list-recent

问题：工具调用总是失败
排查路径：
1. 检查 MCP Server 状态 → workbuddy mcp status
2. 查看工具调用日志 → workbuddy debug tools --last
3. 手动测试工具 → workbuddy mcp test <tool-name> <args>
4. 检查权限配置 → workbuddy config show safety

问题：成本异常飙升
排查路径：
1. 查看 Credit 消耗分布 → workbuddy cost breakdown --today
2. 检查是否有异常重试 → 日志中搜索 "retry"
3. 检查测试是否误调真实 LLM → CI 日志
4. 查看降级触发率 → workbuddy cost degrade-stats
```
