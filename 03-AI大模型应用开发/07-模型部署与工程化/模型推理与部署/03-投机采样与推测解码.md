# 03 - 投机采样与推测解码

> 🎯 投机采样 = 小模型"猜"+大模型"验" — 不损失精度的前提下提速 2-3×，是推理加速的免费午餐

## 原理

```text
LLM 自回归生成慢的根本原因：
  → 每次只生成 1 个 token → 100 tokens = 100 次串行推理

投机采样 (Speculative Decoding)：
  ① 小模型快速"猜"出 K 个候选 token（一次前向）
  ② 大模型"验证"这 K 个 token（一次前向）
  ③ 接受正确的 → 跳过→ 从第一个错的重新猜

  大模型 1 次前向 = 验证 K 个 token ≈ K× 加速
  K 通常 3-8 → 加速 2-3×
```

## 为什么"免费"

```text
投机采样不改变输出分布！
  → 大模型验证时拒绝了错误的猜测
  → 最终输出的概率分布与原始完全一致
  → 零精度损失 ✅
```

## 小模型选择

| 方案 | 加速比 | 显存开销 |
|------|:---:|:---:|
| 同系列小模型(Qwen-0.5B猜Qwen-7B验) | 2-3× | +0.5GB |
| 独立小模型 | 2-2.5× | +1-2GB |
| 模型自身的浅层输出 | 1.5-2× | 0 |
| EAGLE(特征级推测) | 3-4× | +1GB |

## 使用

```python
# vLLM 投机采样
llm = LLM(model="Qwen/Qwen2-7B",
          speculative_model="Qwen/Qwen2-0.5B",  # 猜测模型
          num_speculative_tokens=5)              # 每次猜 5 个

# llama.cpp 投机采样
llama-cli -m qwen2-7b.Q4_K_M.gguf \
          -md qwen2-0.5b.Q4_K_M.gguf \  # draft model
          -ngl 99
```

## 加速比影响因素

```text
加速比取决于：
  ① 小模型的"猜对率" — 越高越快
  ② 生成内容的"可预测性" — 代码 > 普通文本 > 创意写作
  ③ K 的大小 — 过大则验证慢，过小则加速少

典型加速比：
  代码补全：3-5×
  通用对话：2-3×
  创意写作：1.5-2×
```

## 5. 投机采样速查

**主流方案对比**（2026）：

| 方案 | 草稿模型 | 验证 | 加速效果 |
|------|---------|------|:--------:|
| 早期投机采样 | 小模型 | 目标模型单次前向 | 2-3x |
| **Medusa** | 模型头（多头预测） | 单次前向 | 2-3x |
| **EAGLE** | 特征级草稿 | 单次前向 | 2-4x |
| Self-Speculative | 自蒸馏草稿 | 单次前向 | 2x |

**适用场景速查**：

```text
适合：生成长文本（摘要/代码/报告）—— 生成阶段占大头
不适合：短输出（分类/短问答）—— 草稿开销 > 收益
批处理场景：vLLM 中与连续批处理叠加（注意显存：草稿模型也占显存）

2026 状态：vLLM 内置 Medusa/EAGLE 支持——"开箱即用"而非自研
```

**权衡速查**：

```text
收益：单请求延迟降低 2-3x（生成长文本时）
代价：显存增加（草稿模型/头）+ 采样复杂度
决策：生成长文本且延迟敏感 → 启用；否则跳过
```

> 🎯 **核心要点**：投机采样 = "**草稿加速 + 单次验证**"——**Medusa/EAGLE 是 2026 主流（vLLM 内置）**；适合"生成长文本 + 延迟敏感"场景，短输出不值得。

## 6. 投机采样实现速查

**vLLM 启用投机采样**：

```bash
# Medusa（多头预测）
vllm serve Qwen/Qwen2.5-7B-Instruct \
  --speculative-model Qwen/Qwen2.5-7B-Medusa \
  --speculative-draft-tensor-parallel-size 1

# EAGLE（特征级草稿）
vllm serve Qwen/Qwen2.5-7B-Instruct \
  --speculative-model Qwen/Qwen2.5-7B-EAGLE \
  --speculative-draft-tensor-parallel-size 1
```

**验证与监控**：

```text
① 加速比：同负载对比（启用 vs 关闭的 TPOT）
② 质量回归：黄金集对比（草稿模型不能影响最终输出质量）
③ 显存检查：草稿模型占显存（预算内）
④ 场景确认：生成长文本才有效（短输出无收益）

常见问题：
  草稿质量差 → 拒绝率高 → 无加速（换更好的草稿模型）
  显存不足 → 草稿模型放不下（小模型或用 EAGLE 头）
```

> 🎯 **核心要点**：投机采样实践 = "**vLLM 两参数启用（Medusa/EAGLE）+ 四步验证（加速比/质量/显存/场景）**"——**"拒绝率高=白占显存"是核心检查点**；短输出场景直接跳过。

## 7. 总结速查

```text
投机采样核心记忆：
  原理：草稿模型猜 N 个 token + 目标模型单次验证
  收益：生成长文本延迟降 2-3x（TPOT 优化）
  方案：Medusa（多头）/ EAGLE（特征级）—— vLLM 内置
  适用：长文本 + 延迟敏感；短输出不值得
  代价：草稿模型占显存 + 拒绝率风险

面试话术：
  "投机采样用草稿模型预测多个 token，
   目标模型一次前向验证——接受则加速，
   拒绝则回退——生成长文本时 TPOT 降低 2-3 倍"
```

> 🎯 **核心要点**：投机采样 = "**猜 N 验一次 + 接受/拒绝机制**"——**一句话面试话术 + 适用场景判断（长文本才值得）**是本文件核心；2026 年 vLLM 内置（Medusa/EAGLE）无需自研。

## 8. 投机采样面试题补充

| # | 追问 | 速答 |
|:-:|------|------|
| 1 | 草稿模型怎么选？ | 小同源模型（同 tokenizer）/ Medusa 头 / EAGLE 特征 |
| 2 | 接受率低怎么办？ | 换更好的草稿/降草稿长度（投机长度） |
| 3 | 和批处理叠加？ | 可叠加（批内每个请求各自投机）——注意显存 |
| 4 | 影响输出质量吗？ | 不影响（验证机制保证与目标模型一致） |
| 5 | 短输出为什么无效？ | 草稿开销 > 加速收益（生成 token 少） |
| 6 | 2026 状态？ | vLLM 内置 Medusa/EAGLE——开箱即用 |

> 🎯 **核心要点**：投机追问六题 = "**选型（草稿）+ 调优（接受率）+ 叠加（批处理）+ 质量（验证保证）**"——**"不影响质量（验证机制）"是面试易错点**（很多人以为投机采样会降质量）。
