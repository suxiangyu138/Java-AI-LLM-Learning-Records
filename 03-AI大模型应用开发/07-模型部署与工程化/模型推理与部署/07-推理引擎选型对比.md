## 5. 2026 引擎格局速查

**引擎市场现状（2026-08 检索核实）**：

| 引擎 | 份额（参考） | 定位 | 2026 状态 |
|------|:-----------:|------|:---------:|
| **vLLM** | ~45% | GPU 生产默认首选 | ✅ v0.22 V1 |
| TensorRT-LLM | ~25% | NVIDIA 极致性能 | ✅ v1.3（FP4） |
| SGLang | ~17% | 高吞吐黑马 | ✅ 增长最快 |
| Ollama/llama.cpp | — | 本地/边缘 | ✅ |
| **TGI** | — | HuggingFace 方案 | ⚠️ **维护模式（2026-03）** |

**选型决策树（2026）**：

```text
生产 GPU 服务？
├── 是 → 前缀共享重（RAG/多轮）？→ 是 → SGLang
│          └→ 否 → NVIDIA 极致需求？→ 是 → TRT-LLM（需团队）
│                      └→ 否 → vLLM（默认）
├── 本地/原型 → Ollama
├── 边缘/CPU → llama.cpp
└── Apple Silicon → MLX

演进路径：Ollama 验证 → vLLM 生产 → 极致再 TRT-LLM
```

**SGLang 的差异化优势**（为什么值得关注）：

```text
① RadixAttention 前缀共享缓存（RAG/多轮对话场景吞吐大幅提升）
② XGrammar 受限解码（JSON 结构化输出 2x）
③ DeepSeek V3/R1 KV Cache 降 35%
④ 专家并行（MoE 模型）成熟
采用：xAI（Grok）、LMSYS Arena
```

> 🎯 **核心要点**：2026 选型 = "**vLLM 默认 + SGLang 前缀/结构化 + TRT-LLM 极致 + TGI 退役**"——**新项目默认 vLLM，前缀共享重的场景认真评估 SGLang**（2026 主线之争）。

## 6. 引擎对比速查卡

**六引擎一页对比（2026）**：

| 引擎 | 吞吐（70B/H100） | 硬件 | 部署成本 | 定位 |
|------|:---------------:|:----:|:--------:|------|
| vLLM | 1000-2000 tok/s | 最广 | 低 | 生产默认 |
| TensorRT-LLM | 2500-4000+ | NVIDIA | 高（编译） | 极致 |
| SGLang | 极高（3.1x） | 广 | 低 | 前缀/结构化 |
| Ollama | 低 | 跨平台 | 极低 | 本地 |
| llama.cpp | 低 | 最广 | 极低 | 边缘/CPU |
| TGI | 800-1500 | GPU | 中 | **已退役** |

**迁移路径速查**：

```text
Ollama → vLLM：模型格式（GGUF→HF）+ 量化重评估（API 零改动）
vLLM → SGLang：前缀共享场景（RAG 重负载）
vLLM → TRT-LLM：极致吞吐（需 CUDA 团队，慎重）

TGI 迁移：直接换 vLLM（生态兼容，OpenAI API 一致）
```

> 🎯 **核心要点**：引擎速查 = "**六引擎一页对比 + 迁移路径**"——**vLLM 是迁移枢纽**（从 Ollama/TGI 迁来、必要时迁往 SGLang/TRT-LLM）；API 层 OpenAI 兼容让引擎切换成本集中在"模型格式与量化"。

> 🎯 **核心要点**：引擎选型总结 = "**默认 vLLM + 黑马 SGLang + 极致 TRT-LLM + TGI 退役**"——**一句话面试话术**覆盖 2026 格局；与部署工具 00 总览的引擎速查一致。

## 8. 引擎面试题补充

| # | 追问 | 速答 |
|:-:|------|------|
| 1 | vLLM 为什么是默认？ | 批处理/KV/前缀内置 + OpenAI 兼容 + 硬件最广 |

| 6 | 2026 主线之争？ | vLLM vs SGLang（前缀缓存效率）——TRT 日益小众 |

> 🎯 **核心要点**：引擎追问六题 = "**默认理由（vLLM）+ 场景选型（SGLang/TRT）+ 隐藏成本（编译）+ 切换成本（API 兼容）**"——**"引擎切换成本集中在模型格式与量化、API 零改动"**是 2026 关键认知。
