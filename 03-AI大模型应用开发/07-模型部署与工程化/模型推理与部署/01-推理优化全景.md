# 01 - 推理优化全景

> 🎯 LLM 推理是三维优化问题 — 显存、延迟、吞吐，三者互相制约。优化之前先画"雷达图"，明确核心瓶颈

## 三大优化维度

```text
显存 (Memory)：能不能跑？
  → 模型权重 + KV Cache + 中间激活
  → 优化：量化(INT4/INT8)、PagedAttention、CPU Offload

延迟 (Latency)：快不快？（单次请求）
  → Prefill(输入编码) + Decode(逐token生成)
  → 优化：投机采样、FlashAttention、CUDA Graph

吞吐 (Throughput)：能处理多少？（并发请求）
  → QPS = 并发 / 平均延迟
  → 优化：连续批处理、动态Batching、Tensor Parallelism
```

## 模型加载的显存占用

```python
# 加载 Qwen2-7B 的显存计算
params = 7_000_000_000
bytes_per_param_fp16 = 2
model_weight_gb = params * bytes_per_param_fp16 / 1e9  # 14 GB

# KV Cache 显存
# = 2 × layers × hidden_dim × max_seq_len × bytes × batch
kv_cache_gb = 2 * 32 * 4096 * 8192 * 2 * 8 / 1e9  # ~34 GB (8并发,8K上下文)

print(f"模型权重: {model_weight_gb:.1f} GB")
print(f"KV Cache:  {kv_cache_gb:.1f} GB")
print(f"总计:      {model_weight_gb + kv_cache_gb:.1f} GB")
# 总显存 ≈ 14 + 34 = 48 GB → 需要 A100 (80GB) 或双卡！
```

## 优化技术全景

| 技术 | 优化维度 | 收益 | 代价 |
|------|:---:|:---:|------|
| **FlashAttention** | 显存+速度 | 2-4× | 无 |
| **PagedAttention** | 显存利用率 | 2-4× | 无 |
| **INT8 量化** | 显存 | 2× | <0.5%精度 |
| **INT4 量化** | 显存 | 4× | <3%精度 |
| **投机采样** | 延迟 | 2-3× | 需小模型 |
| **连续批处理** | 吞吐 | 5-10× | 无 |
| **Tensor Parallelism** | 显存(分片) | N× | 通信开销 |

## 优化决策树

```text
显存不够？→ 量化(INT4/INT8) + PagedAttention
延迟太高？→ 投机采样 + FlashAttention + CUDA Graph
吞吐太低？→ 连续批处理 + Tensor Parallelism
三者都要？→ vLLM/TensorRT-LLM（开箱即用以上所有）
```

## 5. 推理优化技术全景表

**推理优化的四大维度**（2026 完整地图）：

| 维度 | 技术 | 解决的问题 | 收益量级 |
|------|------|-----------|:--------:|
| **计算优化** | FlashAttention / 算子融合 / CUDA Graph | 注意力计算效率 | 2-5x |
| **显存优化** | KV Cache 管理 / PagedAttention / 量化 | 显存瓶颈（长上下文） | 2-8x 容量 |
| **调度优化** | 连续批处理 / 前缀缓存 / 投机采样 | 吞吐与延迟 | 2-4x 吞吐 |
| **服务优化** | 流式 / 网关 / 弹性伸缩 | 感知延迟与成本 | 感知 10x |

**优化优先级（2026 共识）**：

```text
第一步：批处理（连续批处理）—— 吞吐提升最大、成本最低
第二步：KV Cache 优化（PagedAttention/前缀缓存）—— 长上下文关键
第三步：量化（FP8/INT4）—— 显存与吞吐双赢
第四步：投机采样 —— 单请求延迟（生成长文本时）
第五步：算子级（FlashAttention）—— 引擎已内置，无需自研

关键认知：引擎（vLLM）已内置前三步——
  你的优化空间在"配置与部署"而非"重写引擎"
```

**延迟 vs 吞吐的权衡**（推理优化的根本矛盾）：

```text
批处理越大 → 吞吐越高，但单请求延迟越高
连续批处理 → 动态平衡（2026 引擎默认方案）
选择依据：交互式（延迟优先，小批）+ 批处理式（吞吐优先，大批）
```

> 🎯 **核心要点**：推理优化全景 = "**计算/显存/调度/服务四维 + 五步优先级**"——**2026 年 90% 的收益来自"用对引擎配置"而非"自研优化"**；延迟与吞吐的权衡是贯穿所有优化的主线。

## 6. 优化工具速查

**推理优化工具链**（2026）：

| 工具 | 用途 | 层级 |
|------|------|------|
| vLLM | 引擎（批处理/KV/前缀缓存内置） | 引擎层 |
| NVIDIA Nsight | 算子级性能分析 | 计算层 |
| nvtop/DCGM | GPU 利用率监控 | 资源层 |
| JFR/自定义指标 | 服务层延迟分析 | 服务层 |

**优化验证方法**：

```text
① 基线：未优化配置的 TTFT/吞吐/显存
② 单变量实验：一次只改一个参数（批大小/量化/前缀缓存）
③ 黄金集回归：优化后质量不变（量化必须验证）
④ 压测确认：真实负载下的 P95（别只看平均）

常见陷阱：
  只测平均不测 P95（长尾被掩盖）
  只测吞吐不测延迟（交互场景失真）
  量化后不测质量（掉点不可见）
```

> 🎯 **核心要点**：优化工具 = "**引擎内置（前三步）+ 分析工具（Nsight/DCGM）+ 单变量实验**"——**"一次只改一个变量 + 黄金集回归 + P95 压测"**是优化验证的三条铁律。

## 7. 优化决策速查（按场景）

**场景 → 优化动作速查**（2026 实践）：

| 场景 | 首要优化 | 次要优化 |
|------|---------|---------|
| 交互式聊天（延迟敏感） | 流式 + 前缀缓存 | 小批 + 投机采样 |
| RAG 问答（前缀共享） | **前缀缓存** | 混合检索 + 缓存 |
| 批量生成（吞吐优先） | 大批 + 连续批处理 | 量化 |
| 长文档处理（KV 压力） | KV 量化 + 限长 | 滑动窗口 |
| 成本敏感 | 模型分级 + 量化 | 语义缓存 |
| 极致延迟（生成长文本） | 投机采样 | 小模型草稿 |

**优化投入产出比排序**（2026 共识）：

```text
① 引擎配置（批处理/前缀缓存）—— 免费，先做
② 量化（FP8）—— 低成本高收益
③ 缓存（语义/前缀）—— 中成本，重复场景高收益
④ 模型分级/蒸馏 —— 架构级，收益最大
⑤ 投机采样/算子优化 —— 延迟极致场景
```

> 🎯 **核心要点**：优化决策 = "**按场景选动作（六场景表）+ 按 ROI 排序（配置→量化→缓存→分级）**"——**先免费后付费、先配置后架构**是 2026 优化投入的铁律。

## 9. 四维优化速查卡

| 维度 | 核心问题 | 代表技术 | 收益 | 优先级 |
|------|---------|---------|:----:|:------:|
| 计算 | 注意力/算子效率 | FlashAttention/融合 | 2-5x | 引擎内置 |
| 显存 | KV 容量 | PagedAttention/量化 | 2-8x 容量 | 高 |
| 调度 | 吞吐与等待 | 连续批处理/前缀缓存 | 2-4x | **最高** |
| 服务 | 感知延迟 | 流式/弹性 | 感知 10x | 高 |

**"为什么 90% 收益来自配置"**（2026 核心认知）：

```text
引擎（vLLM）已内置：连续批处理 + PagedAttention + 前缀缓存
→ 你的工作 = 打开开关（参数）+ 按负载调优（批大小/量化）
→ 而非重写引擎（自研 = 重复造轮子 + 踩坑）

例外（需要自研/深调）：极致延迟（投机采样选型）、
特殊硬件（非 NVIDIA）、特殊算子（新架构）
```

> 🎯 **核心要点**：四维速查卡 = "**计算/显存/调度/服务 + 优先级（调度最高）**"——**"打开引擎开关"是 2026 的第一优化动作**；自研只在"极致/特殊硬件/新架构"三例外。
