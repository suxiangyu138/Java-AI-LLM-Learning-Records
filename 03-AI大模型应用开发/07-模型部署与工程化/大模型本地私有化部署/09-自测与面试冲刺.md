## 3. 面试 8 题与答题范式

### Q1：讲讲大模型私有化部署的整体方案

**范式**：决策 → 架构 → 安全三段式。先讲该不该私有化（数据敏感/用量/模型能力三问），再讲技术栈（Ollama 开发 + vLLM 生产 + 网关 + Open WebUI），最后讲安全与运维（五层防线 + 三指标）。
**金句**：私有化不是技术问题，是"数据安全 × 用量 × 能力"的权衡问题。

### Q2：显存怎么估算？32B 模型要什么配置？

**范式**：公式 → 代入 → 余量。权重 = B×2（FP16），量化除以 4；KV 缓存随上下文与并发增长；实需 ×1.5-2。32B：FP16 64GB、INT4 20-24GB → 单张 48GB 或 2 卡。
**要点**：主动补一句"量化比选引擎影响更大"——面试官最想听的洞察。

### Q3：Ollama 和 vLLM 怎么选？

**范式**：场景二分。开发/个人/小团队 → Ollama（极简、跨平台、MLX）；生产高并发 → vLLM（PagedAttention + 连续批处理，单卡 50-100 并发）；二者 OpenAI 兼容 API 无缝切换。
**要点**：说清"vLLM 优势只在负载下体现"，避免"vLLM 全面更好"的错误认知。

### Q4：私有化部署怎么保证数据安全？

**范式**：五层防线 + 三条最易翻车线。传输（TLS 1.3）→ 存储（AES-256/HSM）→ 访问（SSO+RBAC+租户隔离）→ 行为（审计+日志脱敏）→ 供应链（官方+校验和+拒 pickle）。翻车线：日志默认记录输入输出、模型文件供应链攻击面、RAG 权限要在检索层过滤。
**金句**：本地部署 ≠ 自动安全，安全责任随部署转移。

### Q5：模型量化是怎么回事？怎么选档位？

**范式**：目的（省显存 1/3-1/4）→ 格式（GGUF 轻量/AWQ GPU/FP8 新硬件）→ 档位（Q4 默认、Q8 质量敏感、Q3 以下极端）→ 注意（不可逆、决策一次做对）。
**要点**：顺带讲 FP16→INT4 的显存换算（8B：14GB→4.5GB）。

### Q6：流式对话在网关层会出什么问题？

**范式**：SSE 特性 → 三个必配。代理缓冲导致不即时（关 buffering）、长连接超时（调长）、认证透传；再加限流与审计。
**要点**：能说出"proxy_buffering off"这个具体配置，就说明真做过。

### Q7：模型更新怎么灰度上线？

**范式**：五步流程。评测（业务用例+安全回归）→ 预下载验哈希 → 网关路由 10% 灰度 → 全量 + 保留回滚窗口 → 回收旧模型。
**要点**：强调"量化档位变更 = 一次完整发布"，以及"质量只能靠抽检，自动指标看不到"。

### Q8：私有化部署到底贵不贵？

**范式**：TCO 四要素 + 联动判断。硬件折旧 + 电费 + 人力 + 更新；与用量预测联动；高频高用量才划算；32B 量化 + 1-2 卡覆盖 80% 场景。
**金句**：算力利用率是成本关键，满血模型 ≠ 最优解。

## 4. 面试速记卡

```
显存公式：权重 = B×位宽/8，实需 ×1.5-2
量化：FP16 8B=14GB → INT4 ≈4.5GB（Q4 默认档）
引擎：Ollama 开发 / vLLM 生产（PagedAttention+连续批处理）/ LM Studio 评测
安全五层：传输/存储/访问/行为/供应链
三条翻车线：日志记输入输出 / pickle 供应链 / RAG 权限在检索层
网关三必配：关缓冲 / 长超时 / 认证透传
TCO 四件：折旧+电费+人力+更新，联动用量预测
国产：昇腾 910B 64GB，CANN 栈，OpenAI 兼容 API 零改动
```

```text
□ 能算任何模型的显存需求（公式 + 余量）

□ 能讲清五层安全防线与三条翻车线
□ 能说出 Ollama 生产化三件套与网关三必配
□ 能设计模型灰度更新流程与回滚
□ 能算 TCO 并与用量预测联动
□ 面试 8 题脱稿 ≥ 6 题
```

> 🎯 **核心要点**：私有化面试的底层逻辑是"决策 + 工程 + 安全"三块拼图——决策看四问框架、工程看显存公式与引擎对比、安全看五层防线。答题范式统一是"机制 → 场景 → 代价"：先讲原理，再讲它适配什么场景，最后讲代价与坑。显存公式、网关三必配、日志翻车线这三条具体到能脱口而出，就与其他候选人拉开了差距。
