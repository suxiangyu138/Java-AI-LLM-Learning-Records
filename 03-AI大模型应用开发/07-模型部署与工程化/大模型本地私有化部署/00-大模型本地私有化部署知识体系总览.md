## 4. 核心概念速查

| 概念 | 一句话定义 |
|---|---|
| 私有化部署 | 模型权重与推理全部运行在企业自有硬件上，数据不出域 |
| 数据不出域 | 核心红线：业务数据永不离开内网/本地环境 |
| 量化 | 把模型权重从 FP16 压到 INT4/INT8，显存降 1/3-1/4，精度损失可控 |
| GGUF | llama.cpp 系量化格式，Ollama/LM Studio 原生支持，社区事实标准 |
| AWQ/GPTQ | 面向 GPU 的量化方案，vLLM 生产环境常用 |
| FP8 | 新一代硬件（H100/5090 等）原生支持的量化精度，质量损失最小 |
| OpenAI 兼容 API | 各引擎统一的 REST 接口，换引擎只改 base_url |
| TTFT | 首 token 延迟，交互体验的关键指标 |
| 信创 | 国产化替代（昇腾/鲲鹏/飞腾等），满足党政/金融合规 |
| TCO | 总拥有成本：硬件 + 电费 + 运维 + 模型更新 |

### 4.1 阅读约定与版本基线

本体系以 2026-08 生态现状为基线：Ollama v0.31.2（v0.30.0 起底层切换 llama.cpp、原生支持 HF GGUF、Vulkan 默认启用）、vLLM 为生产首选引擎、LM Studio 0.4.x 用于评测、信创昇腾方案已量产。文中"量化档位"均指 GGUF 系命名（Q4_K_M 等），"OpenAI 兼容 API"指各引擎统一的 REST 接口。数据与结论可在文末参考来源溯源；硬件价格与模型版本随市场波动，落地前按当时行情复核。

阅读建议：非技术决策者重点读 01（决策）与 03（硬件），工程师重点读 02/05/06，安全合规人员重点读 07，运维读 08——每篇独立成文，也可按 00 的学习路线顺序通读。篇幅统一约 2000 字，单篇 15 分钟内可读完，适合碎片化学习与面试前快速过一遍。

## 5. 与兄弟体系的分工

| 体系 | 位置 | 分工 |
|---|---|---|
| **本体系** | `07-模型部署与工程化/大模型本地私有化部署/` | **方案决策视角**：该不该私有化、选什么组合、硬件怎么配、安全怎么保 |
| 部署工具（12 篇） | `07-模型部署与工程化/部署工具/` | 工具链视角：Docker/K8s/vLLM/Ollama/TRT/MLOps 各工具怎么用 |
| 模型推理与部署（11 篇） | `07-模型部署与工程化/模型推理与部署/` | 性能视角：KV Cache/投机采样/量化原理/压测 |

> 🎯 **核心要点**：私有化部署 = 四问决策（要不要/选什么/配多少/怎么保安全）+ 一条主线（方案选型 → 硬件 → 模型 → 部署 → 安全 → 运维）。2026 年的务实答案是：中小场景 32B 量化 + 1-2 张大显存卡最划算，开发用 Ollama、生产用 vLLM、前面加网关，全部走 OpenAI 兼容 API。
