# 07 数据安全与合规

> 私有化的安全承诺不是"模型装在内网就安全了"，而是五层防线全部落地的结果：传输、存储、访问、行为、供应链——缺一层，数据不出域就是空话。

## 1. 安全责任模型

私有化部署最大的安全误区是"本地部署 = 自动安全"。事实是：**安全责任随部署一起从云厂商转移到企业自己身上**。云厂商提供的安全能力（认证、WAF、审计、密钥管理、合规认证）在私有化方案里全部默认不存在，需要自己补齐。

```text
责任边界对比：
云端 API：数据安全 → 服务商（条款+认证）+ 企业（合规使用）
私有化：  数据安全 → 企业 100% 自担（硬件+网络+应用+数据四层全包）
```

## 2. 传输与存储加密

| 层 | 措施 | 说明 |
|---|---|---|
| 传输 | TLS 1.3 强制 | 内网也建议启用；禁用弱密码套件 |
| 存储 | AES-256 加密模型权重与数据 | 密钥管理用 HSM（硬件安全模块）或 KMS |
| 磁盘 | 全盘加密（LUKS/BitLocker） | 防物理窃取 |
| 备份 | 备份也加密 | 备份介质失窃 = 数据泄露 |

内网不等于安全：横向渗透、日志落盘、备份外带都是数据出域的实际路径。加密的优先级：**备份与日志先加密**（最容易外带的两条路），再谈权重文件。

## 3. 访问控制与审计

| 控制 | 实现 |
|---|---|
| 认证 | OIDC 对接企业 SSO（统一身份）或独立账号体系 |
| 授权 | RBAC 角色模型：admin/operator/user 分级，API 级权限 |
| 隔离 | 多部门多租户隔离（数据与配额双隔离） |
| 审计 | 全量调用日志：谁/何时/什么模型/参数摘要/结果类型 |

审计是"行为面不出域"的落地：能回答"谁在什么时候把什么数据喂给了模型"。日志要点：记录调用者身份、模型名、参数摘要（脱敏后）、结果类型、耗时——敏感字段（完整提示词、完整响应）默认不落盘或脱敏落盘。

## 4. 日志与数据泄露面

日志是私有化最容易忽略的泄露通道：

```text
泄露面清单：
□ 推理服务日志（可能记录完整提示词与响应）
□ 网关访问日志（URL/参数可能含敏感文本）
□ 监控系统指标标签（如把提示词当 label）
□ 错误堆栈（异常信息可能带输入内容）
□ 模型缓存与 KV 缓存落盘
□ Open WebUI 会话数据库
```

治理原则：**默认不记录完整输入输出**；确需记录（审计要求）则加密存储 + 定期轮换 + 最小访问权限；监控指标标签禁止携带业务文本；错误信息脱敏后返回给调用方。

## 5. 提示注入与滥用防护

私有化模型同样面临提示注入（数据里的指令被模型执行）与滥用风险：

| 风险 | 场景 | 防护 |
|---|---|---|
| 提示注入 | 知识库文档里藏"忽略前面指令" | 系统提示词强边界 + 输入净化 + 输出过滤 |
| 敏感信息泄漏 | 诱导模型输出训练数据/内部知识 | RAG 场景按文档权限过滤，最小化注入 |
| 滥用消耗 | 无限调用打满 GPU | 网关限流 + 配额（按用户/按部门） |
| 越狱 | 绕过安全对齐 | 敏感场景加输出审查层（关键词/分类器） |

企业知识库场景的黄金规则：**RAG 检索阶段按权限过滤文档，不把无权限文档送进上下文**——权限在检索层解决，比在模型层事后补救可靠得多。

## 6. 供应链安全

| 环节 | 风险 | 防护 |
|---|---|---|
| 模型下载 | 仿冒/篡改/投毒 | 只从官方组织下载；核对 SHA 校验和 |
| 模型格式 | pickle 恶意代码 | 只用 GGUF/safetensors，拒绝 pickle |
| 镜像依赖 | 基础镜像漏洞 | 用官方镜像 + 定期扫描（Trivy 等） |
| 运行时 | 组件 CVE | 引擎/网关定期升级，关注安全通告 |

敏感行业的补充动作：新模型上线前跑"安全回归"（越狱、注入、敏感信息泄漏、有害内容生成四类测试），通过后才接入业务。

## 7. 合规检查单

```text
□ 数据面：业务数据只进内网，无任何外呼（断网验证一次）
□ 传输：TLS 1.3，无明文端口暴露
□ 存储：权重/数据/备份加密，密钥入 HSM/KMS
□ 访问：SSO 统一认证 + RBAC 分级 + 租户隔离
□ 行为：全量审计日志（脱敏），可回答"谁喂了什么数据"
□ 日志：默认不落完整输入输出，指标标签无业务文本
□ 供应链：官方模型 + 校验和 + 安全回归 + 依赖扫描
□ 网络：防火墙收敛端口，管理面与数据面分离
```

### 7.1 合规落地的组织动作

安全不仅是技术配置，还需要三个组织层面的动作落地。第一个是**权限最小化的定期审计**：每季度复核一次谁有模型服务的管理权限、哪些账号能看审计日志、知识库文档的权限分级是否被绕过——权限漂移是内网环境的常态。第二个是**安全事件响应预案**：定义"数据可能出域"的触发条件（外呼尝试、异常大批量调用、日志泄露告警），并预写处置步骤（断网、冻结账号、取证、复盘），出事时按剧本走而不是现场想。第三个是**供应商与模型台账**：记录每个模型的来源、版本、校验和、上线日期、负责团队——供应链安全的前提是可追溯。

这三个动作不需要额外系统，靠文档 + 定期会议就能落地，但价值很大：它们把"安全策略"从纸面变成可执行的日常。

## 8. 本模块小结

> 🎯 **核心要点**：私有化安全 = 五层防线（传输/存储/访问/行为/供应链）全部落地 + 责任模型清醒（安全责任 100% 在企业自己）。三条最容易翻车的线：日志默认会记录输入输出（必须默认不落/脱敏）、模型文件是供应链攻击面（只收 GGUF/safetensors + 校验和）、RAG 权限要在检索层过滤（不是模型层补救）。检查单八项全过，"数据不出域"才不是空话。
