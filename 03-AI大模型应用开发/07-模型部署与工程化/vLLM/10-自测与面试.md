## 3. 面试 8 题与答题范式

### Q1：vLLM 为什么快？

**范式**：机制 → 量化收益 → 协同。三大机制逐一展开（PagedAttention 显存省 60-80% → 并发 50-100；连续批处理利用率 85-95% → 吞吐 3-23 倍；前缀缓存命中 70-95% → 成本降 70%+），最后点出三者协同关系。
**金句**：快不是单个技巧，是"显存装得下、GPU 不空转、重复不算第二遍"三层架构。

### Q2：PagedAttention 的原理？

**范式**：痛点（连续预留 + 碎片）→ 类比（OS 虚拟内存分页）→ 机制（固定页 + 页表映射）→ 三个收益（按需分配/碎片消失/页共享）→ 演进（v0.25 并入 MRv2）。
**要点**：能说"页共享是前缀缓存的地基"是加分项。

### Q3：连续批处理和静态批处理区别？

**范式**：三代演进（静态→动态→连续）→ 机制（每轮迭代重调度）→ 收益（利用率 60% → 85-95%）→ 配套（Chunked Prefill 防长输入阻塞）。
**要点**：补一句"吞吐与单请求延迟的权衡"体现深度。

### Q4：显存怎么规划？KV 缓存怎么估算？

**范式**：公式 → 实例代入 → 分配原则。每 token KV 公式 + Llama3-70B ≈ 320KB/token + 100 用户 × 4K ≈ 125GB → 结论：先定 `--max-model-len`，再分配权重/KV 比例。
**要点**：主动提到"权重 + KV 共用显存池，比例失衡是头号配置错误"。

### Q5：前缀缓存在什么场景有用？

**范式**：原理（复用共享前缀 KV 页）→ 场景表（Agent 70-95% / 多租户 30-60% / RAG 0-15%）→ 为什么 RAG 低 → 三个控制点（空间/驱逐/cache_salt）。
**金句**：固定前缀越长、复用越频繁，收益越大。

### Q6：怎么调优一个慢的 vLLM 服务？

**范式**：先判瓶颈（ops:byte）→ 按序叠加（内建 → KV 量化 → 推测解码/TP）→ 每步验证 → 监控指标验证（TTFT/ITL）。
**要点**：强调"先判瓶颈再动手，方向错了越调越差"——这是调优面试的核心得分点。

### Q7：怎么选量化方式？

**范式**：决策树（新卡 FP8 / 显存紧 AWQ / 求稳 INT8 / 充足 FP16）→ KV 独立量化优先 → 匹配纪律 → 质量回归（2-5% 门槛）。
**要点**：能说"KV 量化精度影响最小、先做它"是区分度所在。

### Q8：扩缩容按什么信号？

**范式**：反直觉点（不按 GPU 利用率）→ 原因（滞后 + 冷启动 30-60s）→ 正确信号（队列深度）→ 阈值设计。
**金句**：GPU 利用率飙升时队列已经堆起来了，扩容永远晚一步。

## 4. 面试速记卡

```
三大机制：PagedAttention(显存) / 连续批处理(吞吐) / 前缀缓存(成本)
显存公式：KV/token = 2×层×KV heads×head_dim×字节（70B≈320KB）
瓶颈判定：ops:byte <50 内存 / >200 计算
调优顺序：内建 → KV量化 → 前缀缓存 → 推测解码 → TP → FP8
监控：TTFT<500ms / ITL<50ms / 队列深度触发扩缩容
量化：FP8 新卡 / AWQ 4bit / INT8 求稳 / KV 量化先做
推测解码：接受率>50% 开，<50% 关，高温默认关
版本线：v0.25 MRv2 默认 / v0.23 Rust 前端 / v0.21 thinking budget
边界：仅 Linux+NVIDIA；并发是氧气，单用户用 Ollama
```

### 4.1 备考建议

本模块 20 道自测题建议分两轮完成：第一轮通做（不限时），标记错题；第二轮只做错题（限时 30 分钟），检验是否真正掌握而非记住答案。面试 8 题按"机制 → 参数 → 场景"三段式组织答案——先讲原理（60% 时间），再落到参数（20%），最后讲场景适配（20%），这个结构既显深度又显实战。考前对照速记卡自查一遍：三大机制、显存公式、瓶颈判定、调优顺序、监控指标、量化决策、推测解码条件、版本线，八个考点全部能脱口而出即可上场。
