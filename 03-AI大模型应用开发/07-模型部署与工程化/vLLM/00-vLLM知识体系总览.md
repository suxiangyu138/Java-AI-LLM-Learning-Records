## 4. 核心概念速查

| 概念 | 一句话定义 |
|---|---|
| PagedAttention | 把 KV 缓存按页管理（类 OS 虚拟内存），碎片从 60-80% 降至 4% 以下 |
| 连续批处理 | 请求完成即出批、新请求随时进批，GPU 利用率 85-95% |
| Chunked Prefill | 长 prefill 切块与 decode 交错，避免长输入阻塞 |
| CUDA Graphs | 图捕获消除 kernel 启动开销，显著提速短请求 |
| 前缀缓存 | 复用共享前缀（system prompt）的 KV 缓存，Agent 场景命中 70-95% |
| KV Offload | KV 缓存溢出时卸载到 CPU/SSD，显存超卖换速度 |
| 张量并行 | 模型按层内切分到多卡，需 NVLink 优先 |
| 推测解码 | 小模型草拟、大模型验证，延迟敏感场景提速 1.5-2.5 倍 |
| thinking budget | 推理模型（DeepSeek-R1 类）的思考预算控制（v0.21+） |
| TTFT / ITL | 首 token 延迟 / token 间延迟，生产监控两大指标 |
| MRv2 | Model Runner V2（v0.25 默认执行路径，PagedAttention 概念并入） |

### 4.1 阅读约定与学习产出

本体系以 2026-08 生态为基线：vLLM v0.25.0（MRv2 默认执行路径）、v0.23.0（Rust 前端）、v0.21.0（thinking budget/KV Offload）。文中"生产参数"以 `vllm serve` 命令行为准，Python API（`LLM` 类）参数同名对应。版本迭代快，落地前以官方 release notes 与 `vllm --help` 为准；量化模型与硬件价格随市场波动，按当时行情复核。

读完本体系应具备四层能力：认知层（三大机制的原理与收益）、部署层（四组参数配出生产服务）、优化层（瓶颈判定与调优顺序）、治理层（监控指标与扩缩容策略）——四层对应 01-03、04、05-09、10 四段，也是面试考查的四个维度。每篇篇幅约 2000 字、15 分钟可读完，适合碎片化学习。

### 4.2 学习顺序的三种切法

按目标不同，本体系有三种读法。快速落地型（急着把服务跑起来）：00 → 04 → 06 → 07，先会部署再补原理，部署篇的因果链（上下文 → KV → 显存 → 并发）能覆盖 80% 的配置场景。面试突击型：00 速查 → 10 自测 → 回补 02/03/08，三大机制与调优框架是考点核心，原理篇要精读。工程深耕型：全篇顺序通读，重点在 05（前缀缓存是 Agent 场景的利润中心）与 08（调优闭环方法论）——这两篇是"会用"与"调好"的分水岭。无论哪种读法，建议每篇 15 分钟读完、随读随在 10 篇的自测题里自检，读完全套后 20 题应能答对 16 题以上。

### 4.3 常见误区速排

| 误区 | 事实 |
|---|---|
| "vLLM 是通用部署工具" | 仅 Linux+NVIDIA，是吞吐引擎不是部署工具 |
| "单用户也用 vLLM" | 并发是氧气，单用户选 Ollama |
| "显存够就开到 0.98" | 要留 5-10% 给 CUDA Graphs 与运行时 |
| "加 TP 能解决并发不够" | TP 解决显存，并发不够加副本 |
| "前缀缓存什么都省" | 重复占比低于 20% 的场景不值得开 |
| "量化损失无所谓" | 业务用例回归下降超 2-5% 必须退档 |

## 5. 与兄弟体系的分工

| 体系 | 位置 | 分工 |
|---|---|---|
| **本体系** | `07-模型部署与工程化/vLLM/` | **单一引擎深潜**：原理 → 部署 → 调优 → 生产 |
| 部署工具（12 篇） | `07-模型部署与工程化/部署工具/` | 工具链全景：vLLM 只是其中一篇的入门级 |
| 模型推理与部署（11 篇） | `07-模型部署与工程化/模型推理与部署/` | 通用推理优化理论：KV Cache/投机采样/量化原理 |
| 大模型本地私有化部署（10 篇） | `07-模型部署与工程化/大模型本地私有化部署/` | 方案决策视角：vLLM 是生产首选引擎 |

> 🎯 **核心要点**：vLLM 的全部价值浓缩在三个机制——PagedAttention（显存省 60-80%）、连续批处理（吞吐 3-23 倍）、前缀缓存（成本降 70%+）。2026 年 v0.25.0 把 PagedAttention 概念并入 MRv2 执行路径、legacy 代码移除，标志着引擎进入"性能由新一代内核承载"的阶段。生产调优的思维框架：先判瓶颈（内存还是计算），再按顺序叠加优化，最后用 TTFT/ITL 与队列深度监控验证。
