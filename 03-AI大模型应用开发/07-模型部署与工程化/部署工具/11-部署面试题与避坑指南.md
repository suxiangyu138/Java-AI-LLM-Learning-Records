### 高频面试题

**Q1: vLLM 为什么比 HuggingFace 推理快？**
```text
PagedAttention(显存利用率30%→90%) + 连续批处理(动态拼batch) + CUDA Kernel优化
```

**Q2: Docker 和 K8s 什么关系？**
```text
Docker：容器化 → 解决环境一致性
K8s：容器编排 → 解决大规模部署、自动扩缩、滚动更新
```

**Q3: 怎么实现 LLM 服务的零停机更新？**
```text
滚动更新(maxSurge=1,maxUnavailable=0) 或 蓝绿部署(切换Service)
```

**Q4: ONNX 和 TensorRT 有什么区别？**
```text
ONNX：跨平台通用格式(CPU/GPU/多语言)
TensorRT：NVIDIA GPU 专用 → 图优化+INT8 → 极致性能
两者互补：PyTorch→ONNX→TensorRT Engine
```

**Q5: 怎么选择推理引擎？**
```text
追求吞吐 → vLLM
追求极致延迟 → TensorRT-LLM
跨平台/非NVIDIA → ONNX Runtime
个人开发 → Ollama
```

## 6. 2026 新题速答（时效性）

| 新题 | 速答 |
|------|------|
| 2026 推理引擎怎么选？ | vLLM 默认（45% 份额）；SGLang 前缀/结构化；TRT-LLM 极致 NVIDIA；Ollama 本地；**TGI 已维护模式** |
| vLLM V1 引擎是什么？ | v0.7+ 默认的架构重写引擎（FP8 自动校准/长上下文优化） |
| Ollama 能上生产吗？ | 不能——无连续批处理/张量并行，本地验证用 |
| FP8 量化的价值？ | 2026 全方位赢家：吞吐↑延迟↓显存↓（H100 最优） |
| TTFT/TPOT 是什么？ | 首 token 延迟/每 token 生成时间——LLM 核心监控指标 |
| 为什么"换引擎不如调配置"？ | 批处理/量化/提示词优化的收益往往大于换引擎（2026 共识） |
| LLM 灰度与普通灰度的差异？ | 评估（质量/安全）+ 显存双份 + 行为漂移回滚 |
| 模型漂移怎么测？ | 输入 Embedding 分布对比 + 输出抽样评估 |

**避坑清单补充（2026）**：

```text
① 别选 TGI（维护模式）——新项目用 vLLM/SGLang
② 别用 Ollama 扛生产并发
③ 别盲目上 TensorRT-LLM（编译成本 + 独占）
④ GPU 场景 HPA 别按 CPU 配（模型加载慢）
⑤ 监控别只看 CPU/内存（必须 TTFT/吞吐/KV 显存）
⑥ 模型别打包进镜像（挂载外部存储）
```

> 🎯 **核心要点**：2026 部署面试 = "**引擎格局（vLLM 默认/TGI 退休）+ LLM 特有指标（TTFT/TPOT）+ LLM 特有运维（显存/漂移/灰度）**"三个新题源——掌握本体系的 2026 速查即可覆盖。

## 7. 高频面试题完整速答（新增 10 题）

| # | 问题 | 速答要点 |
|:-:|------|---------|
| 11 | PagedAttention 原理？ | KV Cache 分页管理（操作系统虚拟内存思想），显存利用率 95%+ |
| 12 | 连续批处理是什么？ | 请求动态进出批（不等整批完成），吞吐 2-4x |
| 13 | 张量并行 vs 数据并行？ | TP 切分权重到多卡（大模型单卡放不下）；DP 每卡完整副本 |
| 14 | 为什么 GPU 部署要 toolkit？ | Docker 默认无法访问 GPU——nvidia-container-toolkit 提供运行时 |
| 15 | 模型加载为什么慢？ | 权重读取 + 显存分配 + 图优化——大模型分钟级（K8s 弹性受限原因） |
| 16 | KV Cache 是什么？ | 注意力计算的键值缓存（随生成长度增长）——显存大头 |
| 17 | FP8 与 INT8 区别？ | FP8 动态范围大（LLM 友好）；INT8 需校准（旧方案） |
| 18 | 怎么估算显存？ | 权重（参数×2 字节 FP16）+ KV Cache（上下文×层数×头数×2） |
| 19 | SSE 与 WebSocket 选哪个？ | LLM 流式用 SSE（单向推送足够、HTTP 生态）；双向交互才 WebSocket |
| 20 | 模型量化后怎么验证？ | 黄金集精度对比（掉点 >1% 回退）+ 线上质量抽样 |

**面试答题框架**（部署类通用）：

```text
"怎么部署一个 LLM 服务？"
① 引擎选型：vLLM（默认）——理由（批处理/生态/OpenAI 兼容）
② 服务化：OpenAI 兼容 API + SSE 流式
③ 容器化：官方镜像 + --gpus all + 模型挂载
④ 生产化：K8s + GPU 调度 + 监控（TTFT/吞吐）+ 灰度
⑤ 评估：黄金集质量门禁 + 漂移监控
—— 五段式覆盖"选型→服务→部署→运维→质量"
```

> 🎯 **核心要点**：部署面试 = "**引擎选型（vLLM 默认）+ 三大机制（PagedAttention/连续批处理/KV Cache）+ LLM 运维（显存/流式/灰度）**"——五段式答题框架覆盖 90% 部署题。

## 8. 部署完整流程图（面试画图题）

**"LLM 从训练到上线"的完整流程图**（面试必画）：

```text
微调训练（GPU）
  → 评估（黄金集门禁）→ 不达标回炉
  → 模型注册（MLflow：权重+配置+评测）
  → 推理引擎（vLLM：PagedAttention + 连续批处理）
  → 服务化（OpenAI 兼容 API + SSE 流式）
  → 容器化（Docker：--gpus all + 模型挂载）
  → 编排（K8s：GPU 调度 + PV 挂模型）
  → 灰度（金丝雀 5% → 评估 → 全量）
  → 监控（TTFT/吞吐/KV 显存/漂移）
  → 反馈（质量评估 → 迭代）

关键决策点（每步的"为什么"）：
  引擎：vLLM（批处理/生态/OpenAI 兼容）
  流式：SSE（首 token 感知延迟）
  灰度：金丝雀（显存约束下最稳）
  监控：TTFT 是用户感知核心
```

**避坑总结（2026 更新版 TOP 12）**：

```text
① 别选 TGI（维护模式）⑥ 模型别打包进镜像
② 别用 Ollama 扛生产     ⑦ GPU HPA 别按 CPU
③ 别盲目 TensorRT-LLM   ⑧ 上下文 num_ctx 默认太小
④ 监控别只看 CPU/内存    ⑨ 灰度别忘显存双份
⑤ 流式必须 SSE           ⑩ 回滚要含"行为漂移"
⑪ 评估门禁必须有         ⑫ 量化后必须黄金集验证
```

> 🎯 **核心要点**：部署面试巅峰题 = "**画完整流程图 + 讲清每个决策点的为什么**"——本文件的流程图 + TOP 12 避坑是终极复习材料；能画图 + 讲权衡 = 部署面试满分。

```text

"Ollama 验证 → vLLM 生产 → 极致性能再考虑 TRT-LLM"

```
