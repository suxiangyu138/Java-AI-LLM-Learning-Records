## 3. 核心概念速查

### 3.1 推理核心指标

| 指标 | 含义 | 参考 |
|------|------|------|
| TTFT（首 token 延迟） | 用户感知延迟的核心 | 流式场景 <500ms |
| TPOT（每 token 生成时间） | 生成速度 | 20-50ms/token（70B H100 量级） |
| 吞吐量（tok/s） | 总生成速度 | vLLM 1000-2000 tok/s（70B） |
| 显存占用 | KV Cache + 权重 | PagedAttention 显存利用率 95%+ |

### 3.2 推理引擎速查

| 引擎 | 定位 | 2026 状态 |
|------|------|:---------:|
| **vLLM** | 生产默认首选 | ✅ 活跃（v0.22 V1） |
| TensorRT-LLM | NVIDIA 极致性能 | ✅ 活跃（v1.3） |
| SGLang | 高吞吐黑马 | ✅ 增长最快 |
| Ollama | 本地开发 | ✅ 活跃（v0.24） |
| llama.cpp | 边缘/CPU | ✅ 活跃 |
| **TGI** | 曾经的 HuggingFace 方案 | ⚠️ **维护模式（2026-03）** |

### 3.3 部署链路速查

```text
模型 → 推理引擎（vLLM/Ollama/TRT-LLM）
→ 服务化（FastAPI/gRPC/OpenAI 兼容 API）
→ 容器（Docker）→ 编排（K8s + GPU 调度）
→ 监控（Prometheus + LLM 指标）→ 灰度（金丝雀/蓝绿）
```

## 4. 2026 推理引擎格局速查

**引擎市场分化定型（2026-08 检索核实）**：

| 引擎 | 部署份额（参考） | 一句话定位 |
|------|:---------------:|-----------|
| **vLLM** | ~45% | GPU 生产默认首选（"无聊但正确的答案"） |
| TensorRT-LLM | ~25% | NVIDIA 极致性能（代价：编译成本/独占） |
| SGLang | ~17% | 高吞吐增长最快（DeepSeek 快 3.1x、前缀共享） |
| Ollama/llama.cpp | — | 本地/边缘（非生产服务） |
| **TGI** | — | **已进维护模式（2026-03-21）**——新项目别用 |

**选型矩阵（2026 共识）**：

```text
本地原型 → Ollama
生产（5-20 并发）→ vLLM
前缀共享重（RAG/多轮）→ SGLang
极致吞吐 + NVIDIA → TensorRT-LLM
边缘/CPU → llama.cpp
Apple Silicon → MLX

演进路径：Ollama 验证 → vLLM 生产 → 极致性能再考虑 TRT-LLM
核心原则：先定义工作负载，再选引擎，最后定硬件
```

> ⚠️ 老教程注意：**TGI 已进入维护模式**（2026-03-21 归档），官方建议新项目改用 vLLM/SGLang/llama.cpp——**2025 年前的部署教程若以 TGI 为主，需更新**。

## 6. 常见误区

| 误区 | 真相 |
|------|------|
| "Ollama 能用于生产" | 无连续批处理/张量并行——**本地开发工具，不是生产服务层** |
| "TGI 还是主流方案" | **2026-03 已进入维护模式**——新项目用 vLLM/SGLang |
| "TensorRT-LLM 最快所以选它" | 编译成本（30-60 分钟/次）+ NVIDIA 独占——**对大多数人是错误选择** |
| "换引擎就能提速" | **部署配置（批处理/量化/提示词）影响往往大于换引擎** |
| "模型部署和普通服务一样" | LLM 特有：KV Cache 显存、流式、TTFT、GPU 调度 |
| "量化一定掉精度" | FP8/FP4 是 2026 全方位赢家（吞吐↑延迟↓显存↓） |
| "本地模型比 API 便宜" | 要算 TCO：GPU 成本 vs API 成本 + 运维人力 |
| "监控看 CPU/内存就够" | LLM 必须看 TTFT/TPOT/KV Cache 显存/吞吐 |
