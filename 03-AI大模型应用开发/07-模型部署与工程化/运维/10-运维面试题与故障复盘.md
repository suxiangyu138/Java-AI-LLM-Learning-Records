# 10 - 运维面试题与故障复盘

> 🎯 LLM 运维面试逃不开的题目 + 3 个血泪教训级的真实故障复盘

## 故障复盘

### 案例 1：GPU 显存碎片导致 Pod Pending

```text
现象：4 个 GPU 节点各剩 1 张空闲卡，需要 2 卡的 Pod 一直 Pending
根因：碎片化 → 没有单个节点有 2 张连续空闲 GPU
解决：
  → 紧急：手动驱逐低优先级 Pod → 腾出 2 卡
  → 长期：Volcano 调度器(支持 Gang Scheduling) + GPU 池化
教训：不能用默认 K8s 调度器管理 GPU 集群
```

### 案例 2：模型更新后回答质量断崖下降

```text
现象：v3 模型上线后，用户负面反馈率从 2% 飙升到 15%
根因：LoRA Adapter 与 Base Model 版本不匹配（v3 Adapter 是用 v2 Base 训的）
解决：回滚到 v2 → 用 v3 Base 重新训练 Adapter → 灰度验证 → 重新上线
教训：模型版本三件套(Base+Adapter+Prompt) 必须原子化绑定
```

### 案例 3：凌晨 3 点 Token 费用暴涨

```text
现象：凌晨 3 点 API 调用量暴增 → 1 小时消耗 $800
根因：某个用户的爬虫脚本陷入死循环 → 每秒 50 次请求
解决：
  → 紧急封禁用户 → 成本截断
  → 后续加：用户级限流(20/min) + 异常检测(用量突增告警)
教训：没有用户级限流 = 给所有人买单
```

## 高频面试题

**Q1: GPU OOM 排查思路？**
```text
① nvidia-smi 确认显存占用 ② 检查 max_model_len/并发数
③ 检查 KV Cache 大小 ④ 是否有僵尸进程
解决：减参数/量化/PagedAttention/换大显存
```

**Q2: 模型版本回滚怎么保证无损？**
```text
蓝绿部署(新老各一套) → 流量切回老版本 → 老模型权重+配置+Prompt完整保留
→ 不需要重新下载/加载 → 秒级回滚
```

**Q3: LLM 日志该怎么设计？**
```text
结构化(JSON) + 字段：user/model/tokens/cost/latency/version/status
+ 审计日志(不可篡改) + 常规日志(可查询)
```

**Q4: 怎么降低 LLM API 成本？**
```text
分层模型(mini→pro) + 语义缓存 + Prompt压缩 + 量化本地部署
```
