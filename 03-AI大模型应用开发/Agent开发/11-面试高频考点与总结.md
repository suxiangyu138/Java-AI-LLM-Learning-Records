## 1. 面试高频题与答题框架

### 1.1 概念类

**Q1：什么是 Agent？它和 LLM 应用的区别？**

```text
① 定义：感知-规划-行动-记忆闭环的自主系统
② 区别三件套：多步循环（while-loop）/工具调用（副作用）/状态管理（记忆）
③ 反面：Agent ≠ 大模型 + API 调用（聊天机器人加函数不是 Agent）
④ 判定五问：自主决策？调用工具？多步目标？记忆？从结果学习？
⑤ 加分：P-A-M-E 四层架构
```

**Q2：请介绍 Agent 的经典设计模式。**

```text
① 五大架构：ReAct（基础）/Plan-Execute（契约）/Reflexion（批判）/
   Tree-of-Thoughts（搜索）/Multi-Agent（分工）
② 2026 新范式：H-V-R（假设→验证→反思，置信度阈值 0.7）
③ 选型铁律：ReAct 起步 → 数据证明不足再叠加 → 单 Agent 不行才多 Agent
④ 加分：每个模式配 token 成本（Reflexion×2/ToT×k/Multi-Agent×15）
```

**Q3：H-V-R 和 ReAct 的区别？为什么 2026 年受关注？**

```text
① ReAct 缺陷：无自我纠错，推理偏差会一错到底
② H-V-R 三阶段：假设（生成方案）→ 验证（执行+置信度）→ 反思（修正重试）
③ 对比：ReAct 单步推理决策；H-V-R 用执行验证数据决策
④ 价值：高可靠性生产 Agent 优先（成本：多了验证步骤）
```

### 1.2 架构类

**Q4：P-A-M-E 四层架构是什么？每层的实现？**

```text
① 感知层：多模态理解（文本/图像/屏幕/API 流）
② 行动层：工具调用（Function Calling/MCP）
③ 记忆层：短期（上下文窗口）/长期（向量库/Agentic RAG）
④ 规划层：推理循环（ReAct/H-V-R/自我反思）
⑤ 加分：四层齐全才是完整智能体；只做感知+行动 = 高级 API 调用器
```

**Q5：记忆系统如何设计？**

```text
① 三类记忆：短期（工作记忆）/长期（情节记忆）/程序性（技能）
② 双写策略：Redis（TTL 10min，直接注入）+ 向量库（语义检索+时间衰减）
③ 上下文压缩：两阶段（会话内摘要 + 会话间沉淀）
④ Checkpointer：状态持久化（断点恢复/时间旅行调试）
⑤ 安全：防记忆投毒（只读 + 变更审批）
```

**Q6：工具调用如何实现？MCP 是什么？**

```text
① Function Calling：模型输出结构化调用指令 → 程序校验执行（模型提议、程序执行）
② 工具注册表：统一入口 + schema 校验 + 分级权限 + 调用上限 + 留痕
③ MCP：工具生态标准协议（Client-Server 架构）
④ MCP v2.0：完整 JSON Schema/多因素认证/异步并发/多 Agent 支持
⑤ 加分：工具即产品（清晰描述/结构化错误/幂等）
```

### 1.3 多 Agent 类

**Q7：多 Agent 有哪些协作模式？**

```text
① 四种：职能分工（路由）/Planner（拆解+可恢复）/Supervisor-Worker（层级治理）/去中心化共识（总线+投票）
② Planner 核心价值：可中断可恢复（第 4 步失败只重做第 4 步）
③ 数据：代码审查 8min→2.5min、误判 15%→4%
④ 注意：token 15 倍——先证明单 Agent 不够再上多 Agent
```

**Q8：多 Agent 系统的常见失败模式？**

```text
① 握手循环 → 所有者 + 交接预算
② 级联错误（一错传染全部）→ 验证器防火墙
③ 上下文膨胀 → 只回传摘要
④ 资源冲突 → 锁/队列/事务门
⑤ 成本失控 → token 预算 + 每任务成本指标
```

### 1.4 工程类

**Q9：Agent 如何测试？评估指标有哪些？**

```text
① 范式差异：概率性输出 → 统计性质量评估（不是断言测试）
② 五维指标：任务完成率/工具调用准确率/轨迹对齐度/端到端延迟/幻觉率
③ 轨迹对齐度：执行路径与最优路径的编辑距离（防"结果碰巧对"）
④ 铁律：先建评估集（50 用例）再开发；评估入门禁
⑤ LLM-as-Judge 陷阱：自评放水 → 验证器独立进程
```

**Q10：Agent 的因果链追踪怎么实现？**

```text
① 为什么：多 Agent 故障可能由 10 步前的决策引发，日志无法关联
② 实现三要素：trace_id（全链路）/span（单次调用）/parent_span_id（因果链）
③ 埋点：每次模型调用/工具调用/状态转换
④ 价值：定位"工具超时还是模型幻觉"；金句：胜出团队是遥测最好的团队
```

**Q11：Agent 安全如何防护？**

```text
① 七大风险 + 致命三要素（私有数据+不可信内容+外部通信）
② Guardrails：独立小模型守卫（输入：注入检测/输出：敏感信息检测）
③ HITL：高危操作人工审批，超时默认拒绝
④ 最小权限：白名单工具 + 资源范围 + 会话凭据
⑤ 纵深防御：隔离承重 + 行为控制可安全失败
```

**Q12：Agent 从原型到生产要解决什么问题？**

```text
① 同步 → 异步（事件驱动微服务，延迟可降 60%）
② 三大挑战：循环死路（上限+检测）/安全越权（守卫+隔离）/成本失控（路由+预算）
③ 成本优化：小模型路由（简单任务小模型，成本降 50%+）
④ 部署：灰度发布（影子→金丝雀→全量）+ 可观测三支柱
⑤ 金句：把复杂工作流塞进同步 REST API 是原型转生产最常见的失败模式
```

### 1.5 综合类

**Q13：框架如何选型？**

```text
① 谱系：代码优先（LangGraph/AutoGen/CrewAI/Agent SDK）vs 低代码（Dify/Coze）
② 场景：复杂流程→LangGraph；多 Agent 研究→AutoGen；角色协作→CrewAI；
   业务快速落地→Dify；零代码→Coze；官方生态→对应 SDK
③ 学习：自研轻量循环（懂原理）→ LangGraph（生产主力）
④ 加分：选型看失败场景表现（Autono 93.3% vs 3.3% 证明 Harness 能力）
```

**Q14：描述你开发过的 Agent 项目（STAR）。**

```text
S 场景：售后处理 Agent（电商）
T 任务：自动分类退款换货，复杂升级人工
A 行动：意图工程定义 → 评估集先行 → LangGraph 图编排 →
        MCP 工具 + HITL 审批 → 灰度发布
R 结果：成功率 >90%，退款 100% 人工复核，P95 <10s，
        事故转评估用例（持续改进）
加分：讲清楚一个具体的技术难点与解法
```

**Q15：Agent 开发的未来趋势？**

```text
① 2024 Prompt+工具 → 2025 有状态图 → 2026 系统工程（记忆/共识/安全/评估）
② 趋势：持久化记忆、去中心化协作、安全围栏标配、Agent 平台化
③ 与 Harness 融合：治理/评估/可观测成为开发一部分
④ 个人定位：Agent 工程化能力（开发+评估+治理一体）
```

## 2. 开放题：Agent 的边界

> 开放题考察深度思考：Agent 的能力边界与伦理边界。

```text
观点框架：
① 能力边界：工具决定行动边界，记忆决定连续性，评估决定可信度
② 知识边界：训练时知识 + RAG 增强——时效性内容必须外部检索
③ 责任边界：HITL 保证关键决策有人负责（Agent 不该单独做资金/医疗决策）
④ 社会边界：Agent 替代执行，但不替代判断与责任
⑤ 结论：Agent 工程的核心问题不是"能做多强"，而是"边界设在哪"
```

> 🎯 **答题金句**：Agent 的可靠性 = 模型能力 × Harness 工程——强模型 + 弱管控不如中模型 + 强管控。

## 3. 五大常见误区

| # | 误区 | 真相 |
|---|------|------|
| 1 | 「Agent = 大模型 + 函数调用」 | 缺循环/状态/记忆/安全的只是 LLM 应用 |
| 2 | 「多 Agent 一定比单 Agent 好」 | token 15 倍，收益必须大于成本，数据驱动升级 |
| 3 | 「让模型自评任务完成」 | 自评放水——验证器独立进程 |
| 4 | 「框架越流行越好」 | 看失败场景表现与 Harness 能力（Autono 案例） |
| 5 | 「原型能跑就能上线」 | 同步→异步、评估、安全、可观测缺一不可 |

## 5. 30 天精进路线

| 阶段 | 时间 | 目标 | 检验标准 |
