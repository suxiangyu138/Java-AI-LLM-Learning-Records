## 1. 什么是 Agent

**Agent（智能体）**：一个能**感知环境、做出规划、采取行动、并基于结果调整**的自主系统。它以大模型为核心大脑，通过工具与外部世界交互，通过记忆维持长期目标。

> ⚠️ **最常见误区**：`Agent = 大模型 + API 调用`——这是「聊天机器人加个函数」，不是 Agent。真正的 Agent 需要四层结构：感知、规划、行动、记忆，以及围绕它们的**状态管理、安全围栏、评估体系**——这些构成 Agent 的「操作系统」。

### 1.1 Agent 的判定标准

```text
Agent 五问自检
├── ① 它能自主决策吗？（不是每次调用都由人指定动作）
├── ② 它能调用工具吗？（读文件/查库/发消息/执行命令）
├── ③ 它有多步目标吗？（能拆解并跟踪子目标）
├── ④ 它有记忆吗？（跨步骤/跨会话记住状态）
└── ⑤ 它能从结果学习吗？（根据反馈修正策略）
5 个「是」→ 真 Agent；少于 3 个 → 只是 LLM 应用
```

## 2. Agent 与 LLM 的本质区别

| 维度 | LLM（大模型） | Agent（智能体） |
|------|--------------|----------------|
| 本质 | 概率推理引擎 | **自主行动系统** |
| 输入输出 | 文本 → 文本 | 感知环境 → 采取行动 |
| 循环 | 单次推理 | **多步循环（思考-行动-观察）** |
| 状态 | 无状态（每次独立） | **有状态（记忆 + 进度）** |
| 工具 | 无 | **有（工具调用）** |
| 副作用 | 无 | **有（真实世界影响）** |
| 失败模式 | 输出质量差 | **执行失控/越权/漂移** |

> 🎯 **本质区别**：LLM 是「会说话的」，Agent 是「会做事的」。从「说话」到「做事」，多出来的不是模型能力，而是**循环、状态、工具、安全**四大工程组件。

## 3. P-A-M-E 四层架构

2026 年主流智能体遵循**感知（Perception）- 行动（Action）- 记忆（Memory）- 规划（Planning）**四位一体架构：

```
┌──────────────────────────────────────────────┐
│ ④ 规划层（Planning）——大脑                     │
│    ReAct 循环 / CoT/ToT 任务拆解 / 自我反思      │
├──────────────────────────────────────────────┤
│ ③ 记忆层（Memory）——经验                       │
│    短期：上下文窗口 + KV Cache 压缩              │
│    长期：Agentic RAG（自主决定何时检索）          │
├──────────────────────────────────────────────┤
│ ② 行动层（Action）——手脚                       │
│    Function Calling / MCP 协议 / 工具执行       │
├──────────────────────────────────────────────┤
│ ① 感知层（Perception）——五官                   │
│    文本 / 图像 / GUI 屏幕 / 结构化 API 流         │
└──────────────────────────────────────────────┘
```

### 3.1 各层职责与关键组件

| 层 | 职责 | 关键技术 | 常见实现 |
|---|------|---------|---------|
| **感知层** | 理解环境输入 | 多模态理解、意图识别 | Vision API、屏幕解析 |
| **行动层** | 执行动作 | 工具调用、参数校验 | Function Calling、MCP |
| **记忆层** | 存储与检索经验 | 短期窗口 + 长期向量 | Redis、向量数据库 |
| **规划层** | 决策与拆解 | 推理循环、反思 | ReAct、H-V-R |

> 💡 四层不是可选装：只做感知+行动（无记忆无规划）= 高级 API 调用器；四层齐全才是「智能体」的完整形态。

## 4. Agent 的核心循环

### 4.1 基础循环

```
Agent 核心循环（while-loop）
        ┌──────────────────────────┐
        │                          ↓
   感知环境 → 规划下一步 → 采取行动 → 观察结果 → 判断是否完成
        │                          │
        │        ← 未完成，继续 ←──┘
        └── 完成 → 输出结果
```

| 循环要素 | 说明 | 工程注意 |
|---------|------|---------|
| **感知** | 读取当前状态/上下文 | 上下文管理（防腐烂） |
| **规划** | 决定下一步动作 | 循环上限（防死循环） |
| **行动** | 调用工具执行 | 权限校验（防越权） |
| **观察** | 获取执行结果 | 结果校验（防幻觉） |
| **终止** | 判断任务完成 | 客观验收标准（防自评） |

### 4.2 循环的工程化

```python
# 核心循环骨架（伪代码）
def run_agent(task, max_steps=20):
    state = {"task": task, "history": []}
    for step in range(max_steps):          # 循环上限
        action = plan(state)               # 规划：模型决策
        result = execute(action)           # 行动：工具执行
        state["history"].append(result)    # 观察：记录结果
        if is_done(state):                 # 终止：客观判断
            return state
    raise TimeoutError(f"超过 {max_steps} 步")  # 超时干预
```

## 5. 能力边界与设计原则

### 5.1 Agent 的能力边界（2026）

| 能力域 | 强项 | 弱项 |
|--------|------|------|
| 语言/推理 | 强（复杂指令理解） | 数学精度、长链推理漂移 |
| 工具调用 | 强（结构化工具有效） | 模糊/动态接口易错 |
| 知识 | 训练时知识 + RAG 增强 | 时效性、幻觉编造 |
| 自我纠错 | 弱（需要 H-V-R/Reflexion 模式） | 一错到底（裸 ReAct） |
| 长任务 | 中（依赖记忆设计） | 上下文溢出、目标漂移 |

### 5.2 设计五原则

```text
Agent 设计五原则
├── ① 任务原子化：大任务拆小任务，每个任务上下文完整
├── ② 工具最小化：只给需要的工具（最小权限）
├── ③ 记忆显式化：状态外部化，不依赖上下文窗口
├── ④ 验收客观化：完成标准用代码判断，不让模型自评
└── ⑤ 失败可恢复：每步可重试、可回滚、可断点续跑
```

## 6. 2026 范式升级

### 6.1 代际演进

```text
Agent 开发代际
├── 2024：Prompt + 工具调用（LangChain Chain）
│   └── 缺陷：无状态、线性执行、无法中途干预
├── 2025：有状态图控编程（LangGraph/AutoGen）
│   └── 进展：状态管理 + 复杂流程编排
└── 2026：系统工程
    ├── 原生模型能力（长上下文/推理）
    ├── 持久化记忆（双写策略）
    ├── 去中心化协作（共识机制）
    └── 安全围栏（Guardrails 成为标配）
```

### 6.2 2026 的关键变化

| 变化 | 说明 |
|------|------|
| **记忆持久化** | 从「上下文窗口」到「持久化记忆系统」 |
| **去中心化协作** | 从中心调度器到消息总线 + 共识 |
| **安全围栏标配** | Guardrails 不再可选，纳入开发流程 |
| **评估工程化** | 轨迹对齐、因果链追踪成为硬指标 |

> 🎯 **总结**：2026 年的 Agent 开发 = 四层架构（P-A-M-E）× 核心循环（while-loop）× 工程化（状态/安全/评估）——三者缺一不可。

---

## 7. 核心要点

> 🎯 **核心要点**：
> 1. Agent ≠ 大模型 + API：状态管理、记忆持久化、安全围栏是其「操作系统」
> 2. P-A-M-E 四层架构（感知/行动/记忆/规划）是完整形态的标配
> 3. 核心循环五要素：感知→规划→行动→观察→终止，工程化重点在循环上限/权限/客观验收
> 4. 2026 范式升级：持久化记忆 + 去中心化协作 + 安全围栏 + 评估工程化
