# 00 - Harness Engineering 知识体系总览

> 🎯 Harness Engineering（驾驭工程）是 2026 年 AI 工程化的第三代范式——焦点从「调教模型」转向「构建确保 Agent 在企业系统中稳定工作的运行管控体系」。核心公式：**Agent = Model + Harness**——模型决定能力上限，Harness 决定稳定下限

> 🎯 本系列共 **8 篇**，从概念演进到运行管控体系、从安全纵深防御到治理合规、从测试评估到企业落地，覆盖 Harness 工程全链路

## 4. 核心概念速查

| 概念 | 一句话解释 |
|------|-----------|
| **Harness** | 独立于大模型的、由代码/配置/执行规则组成的 Agent 运行管控体系 |
| **Agent = Model + Harness** | 模型定能力上限，Harness 定稳定下限 |
| **控制论治理器** | Martin Fowler 对 Harness 的定义：前馈 + 反馈调控智能体行为 |
| **三代演进** | Prompt 工程（2022-24）→ 上下文工程（2025）→ Harness 工程（2026） |
| **三大基础属性** | 可执行性、可检查性、有状态性（arXiv 2605.18747） |
| **Agent DLC** | Agent 开发生命周期：构建→测试→存储→部署→运行→治理 |
| **AIBOM** | AI 物料清单：捕获模型、工具与依赖，供应链透明化 |
| **四层隔离模型** | 镜像加固→进程隔离→密钥隔离→网络隔离（瑞士奶酪模型） |
| **AI Evals** | Agent 感知的质量门禁：评估正确性/性能/安全性并接入 CD |
| **验证器独立进程** | 生成器与评估器不得处于同一上下文窗口 |

## 5. 一图看懂：三代范式演进

| 维度 | Prompt Engineering | Context Engineering | **Harness Engineering** |
|------|-------------------|---------------------|------------------------|
| 时代 | 2022-2024 | 2025 | **2026** |
| 焦点 | 雕琢语言 | 管理信息 | **管控行为** |
| 对象 | 单次生成 | 对话上下文 | **主动执行任务的 Agent** |
| 核心问题 | 如何把指令说清楚 | 如何把信息喂合适 | **如何确保执行稳定可控** |
| 代表性失败 | 输出不对 | 输出好但语境漂移 | Agent 乱执行/被攻陷/不可审计 |
| 工程形态 | 提示词模板 | 上下文管理工具 | **运行管控体系（运行时+治理）** |

---

> 💡 **一句话总结**：Prompt 决定模型「想得好不好」，Context 决定模型「看得准不准」，Harness 决定 Agent **「做得好不好、乱不乱来、出事了能不能查」**——2026 年企业 AI 落地的成败战场在 Harness。
