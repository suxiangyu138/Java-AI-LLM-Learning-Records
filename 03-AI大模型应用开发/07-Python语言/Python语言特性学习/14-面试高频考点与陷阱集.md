## 1. 语言机制类（15 题）

**Q1. Python 是解释型还是编译型语言？** 🔥🔥🔥

两者都有。源码先被**编译**成字节码（`.pyc`），再由 PVM **解释**执行。所以 Python 是「编译到字节码 + 解释执行」，和 Java 的「编译到 class + JVM 执行」结构相同；区别在于 Python 的编译是隐式的、每次运行自动完成，且不做 JIT（CPython 3.13 起有实验性 JIT）。

**Q2. `.pyc` 文件是什么？什么时候生成？**

`__pycache__/module.cpython-312.pyc`，存的是序列化后的 Code Object + 魔数 + 源文件时间戳/哈希。**只有被 import 的模块会缓存**，直接运行的主脚本不生成。源文件改动后（时间戳或哈希不匹配）自动重新编译。

**Q3. Python 为什么慢？** 🔥🔥🔥

四个层面：① 动态类型 → 每次操作都要查类型、做多重分派；② 一切皆对象 → 一个 int 也是 28 字节的堆对象，没有原生栈值；③ 解释执行 → 无 JIT（3.13 起才有实验性）；④ GIL → 纯 Python 多线程无法并行。对策是把热点交给 C 层（numpy/torch）或换实现（PyPy）。

**Q4. `dis` 模块有什么用？**

反汇编字节码。实战价值：解释 `LOAD_FAST` vs `LOAD_GLOBAL` 的性能差异、验证常量折叠、看清 `a += b` 与 `a = a + b` 的区别、理解闭包的 `LOAD_DEREF`。

**Q5. CPython / PyPy / Jython / GraalPy 的区别？**

CPython 是 C 实现的参考实现（生态最全）；PyPy 用 RPython + JIT，纯 Python 计算快 4-10 倍但 C 扩展兼容性差；Jython/IronPython 跑在 JVM/.NET 上；GraalPy 跑在 GraalVM 上、可与 Java 互操作；MicroPython 面向嵌入式。

**Q6. `is` 和 `==` 的区别？** 🔥🔥🔥

`is` 比较 `id()`（是否同一对象），`==` 调用 `__eq__`（值是否相等）。**只有 `None`、`True`、`False`、枚举成员、哨兵对象该用 `is`**。小整数池 `[-5, 256]` 和字符串驻留会让 `is` 在小值上"看起来"正确，这是最典型的伪成功。

**Q7. 可变对象与不可变对象？**

不可变：`int/float/str/bytes/tuple/frozenset/bool/None`。可变：`list/dict/set/bytearray/自定义类实例`。判断依据是「能否在不改变 `id` 的前提下改变内容」。

**Q8. Python 的参数传递是值传递还是引用传递？** 🔥🔥🔥

都不是，是**传对象引用**（call by sharing）。形参和实参绑定同一对象：改变可变对象的内容会影响调用方；重新赋值形参不会。

**Q9. 深拷贝与浅拷贝？** 🔥🔥

浅拷贝（`list(x)` / `x[:]` / `copy.copy`）只复制最外层容器，内层元素共享；深拷贝（`copy.deepcopy`）递归复制，用 `memo` 字典处理循环引用。不可变对象的深拷贝返回自身。

**Q10. `__new__` 和 `__init__` 的区别？** 🔥🔥

`__new__` 是静态方法，负责**创建**并返回实例；`__init__` 负责**初始化**，返回必须是 None。`__new__` 若不返回本类实例，`__init__` 不会被调用。用途：继承 `int/str/tuple` 等不可变类型、单例、享元。

**Q11. `str` 和 `bytes` 的关系？**

`str` 是 Unicode 码点序列，`bytes` 是原始字节序列。`str.encode(encoding)` → bytes，`bytes.decode(encoding)` → str。Python 3 不做隐式转换，这是 Py2→Py3 最大的破坏性变更。

**Q12. `sys.argv`、`if __name__ == "__main__"` 的作用？**

模块被直接运行时 `__name__ == "__main__"`，被 import 时等于模块名。它让模块既能当脚本又能当库；在 Windows/macOS 上用 `multiprocessing` 时它是**必需的**（spawn 会重新 import 主模块）。

**Q13. 模块的导入机制？循环导入怎么解决？** 🔥

`sys.modules` 缓存 → `sys.path` 搜索 → 编译执行模块顶层代码 → 绑定名字。循环导入的解决：① 重构，抽公共部分到第三个模块；② 把 import 移到函数内部（延迟导入）；③ 只为类型注解的导入放进 `if TYPE_CHECKING:`。

**Q14. `import a.b` 与 `from a import b` 的区别？**

前者绑定 `a`，访问要写 `a.b`；后者直接绑定 `b`。循环导入时 `from a import b` 更容易失败（要求 `b` 此刻已定义），`import a` 更宽松。

**Q15. Python 2 和 3 的主要区别？**

`print` 成为函数、`str`/`bytes` 严格分离、整除 `/` 变真除法、`range` 返回惰性对象、字典默认有序（3.7+）、类型注解、f-string、异常链 `raise from`、`super()` 无参调用。

## 2. 对象与作用域类（12 题）

**Q16. 什么是 LEGB？** 🔥🔥🔥

名字查找顺序：**Local → Enclosing → Global → Built-in**。编译期就决定用哪条指令：局部变量 `LOAD_FAST`（数组下标，最快）、闭包变量 `LOAD_DEREF`、全局/内置 `LOAD_GLOBAL`（字典查找）。**类作用域不在 LEGB 链中**——方法体看不到类变量，必须写 `self.x` 或 `Cls.x`。

**Q17. `global` 和 `nonlocal` 的区别？** 🔥🔥

`global` 声明使用模块级变量；`nonlocal` 声明使用**最近的外层函数**作用域变量（不含全局）。两者都只是改变绑定目标，不创建变量。

**Q18. 为什么会出现 `UnboundLocalError`？** 🔥🔥🔥

函数体内任何位置对某名字有赋值，该名字整个函数内都是局部变量（编译期决定）；在赋值前读取就报此错。

```python
x = 10
def f():
    print(x)      # UnboundLocalError
    x = 20        # ← 这行让 x 变成局部变量
```

**Q19. 什么是闭包？Python 怎么实现？** 🔥🔥🔥

内层函数引用了外层函数的局部变量，外层返回后该变量仍存活。实现机制是 **cell 对象**：被引用的变量存进 cell，函数的 `__closure__` 元组持有这些 cell，`co_freevars` 记录名字。

**Q20. 闭包的延迟绑定陷阱？** 🔥🔥🔥

```python
fs = [lambda: i for i in range(3)]
print([f() for f in fs])     # [2, 2, 2] 不是 [0,1,2]
```
闭包捕获的是**变量**（cell）而非值，调用时才求值，此时 `i` 已是 2。三种修复：`lambda i=i: i`（默认值在定义时求值）、`functools.partial(lambda x: x, i)`、用工厂函数多创建一层作用域。Java 的 lambda 强制 effectively-final，从语言层面禁止了这个坑。

**Q21. 装饰器里为什么要用 `functools.wraps`？** 🔥🔥

不加会丢掉原函数的 `__name__`/`__doc__`/`__module__`/`__qualname__`/`__annotations__`/`__wrapped__`。后果不只是文档难看：FastAPI 靠签名做依赖注入、Click 靠签名生成 CLI、Sphinx 靠 docstring 生成文档——都会直接坏掉。

**Q22. `a, b = b, a` 的原理？**

右侧先构造一个 tuple（或用 `ROT_TWO`/`SWAP` 字节码优化），再解包赋给左侧。因为求值在赋值之前，所以不需要临时变量。

**Q23. 名字修饰（name mangling）是什么？**

类体内以两个下划线开头、结尾不超过一个下划线的名字 `__x` 会被改写为 `_ClassName__x`。目的是避免子类意外覆盖，**不是访问控制**——外部仍可通过 `obj._ClassName__x` 访问。Python 没有真正的 private。

**Q24. `__slots__` 的作用和代价？** 🔥🔥

用固定的描述符槽位替代每实例的 `__dict__`。收益：内存降 40-60%、属性访问更快。代价：不能动态加属性、默认不支持弱引用（需显式加 `__weakref__`）、多继承受限、子类不声明 `__slots__` 就会重新获得 `__dict__`（收益归零）。

**Q25. 为什么字典是有序的？**

3.6 是实现细节（紧凑数组 + 索引表的新实现的副产品），3.7 起写入语言规范成为保证。这个实现同时省了约 20-25% 内存。

**Q26. 什么样的对象可以做字典的 key？** 🔥🔥

可哈希对象：实现 `__hash__` 且不为 None，通常还需要 `__eq__`。三条契约：① `a == b ⟹ hash(a) == hash(b)`；② 对象生命周期内 hash 不变；③ 只重写 `__eq__` 会让 `__hash__` 变成 None（实例不可哈希）。

**Q27. `sorted` 是稳定排序吗？用的什么算法？**

是稳定排序，用 **Timsort**（归并 + 插入的混合，由 Tim Peters 为 Python 发明，后被 Java 的 `Arrays.sort(Object[])` 采用）。稳定性让多级排序可以「从次要键到主要键」多趟排。

## 3. OOP 与协议类（12 题）

**Q28. 什么是 MRO？C3 线性化如何计算？** 🔥🔥🔥

MRO 是属性查找的类顺序。C3 规则：`L[C] = C + merge(L[父1], L[父2], ..., [父1, 父2, ...])`。merge 每轮取第一个候选表的表头，若它不出现在其他表的**尾部**则取出，否则换下一个表的表头。保证：局部优先级顺序 + 单调性。

**Q29. `super()` 到底调用了谁？** 🔥🔥🔥

不是"父类"，而是**MRO 中当前类的下一个类**。

```python
class A:
    def m(self): print("A")
class B(A):
    def m(self): print("B"); super().m()
class C(A):
    def m(self): print("C"); super().m()
class D(B, C): pass
D().m()          # B → C → A   ← B 的 super() 调到了 C，不是 A！
print([c.__name__ for c in D.__mro__])   # ['D','B','C','A','object']
```
这就是菱形继承下 `A.m()` 只执行一次的原因（协作式多继承）。

**Q30. 无参 `super()` 怎么工作的？**

编译器发现类体内使用了 `super` 或 `__class__`，就把当前类塞进函数的 `__closure__`（隐式 `__class__` 单元），运行时 `super()` 等价于 `super(__class__, self)`。所以它不能在类外的普通函数里用。

**Q31. `@classmethod` 和 `@staticmethod` 的区别？** 🔥🔥

`classmethod` 第一参数是 `cls`（子类调用时是子类，适合做多态工厂）；`staticmethod` 不接收隐式参数（就是个挂在类命名空间的普通函数）。对应 Java：`static` 方法约等于 `staticmethod`，但 Java 没有 `classmethod` 的多态能力。

**Q32. ABC 和 Protocol 的区别？** 🔥🔥

ABC 是**名义**子类型（必须继承，运行时实例化时检查抽象方法），Protocol 是**结构**子类型（只要方法签名匹配，静态检查通过，无需继承）。对接第三方 SDK 用 Protocol，项目内框架骨架用 ABC。

**Q33. 描述符是什么？优先级顺序？** 🔥🔥🔥

实现了 `__get__`/`__set__`/`__delete__` 任一的类。查找优先级：

```text
类型的数据描述符（有 __set__/__delete__）
  > 实例 __dict__
    > 类型的非数据描述符（只有 __get__）/ 普通类属性
      > __getattr__
```
这条链解释了：`property` 为什么无法被实例属性覆盖（数据描述符）、`cached_property` 为什么只算一次（非数据描述符，第一次后被实例 `__dict__` 遮蔽）、方法为什么能自动绑定 `self`（函数是非数据描述符，`__get__` 返回 bound method）。

**Q34. `property` 的原理？**

`property` 是一个数据描述符类。`@property` 把方法替换成 property 实例，`@x.setter` 返回一个带 setter 的新 property。访问 `obj.x` 时因为它是数据描述符，优先于实例字典，从而拦截到 `__get__`。

**Q35. `__getattr__` 和 `__getattribute__` 的区别？** 🔥🔥

`__getattribute__` 拦截**所有**属性访问（含成功的），实现里必须用 `super().__getattribute__()` 否则无限递归；`__getattr__` 只在常规查找**失败后**兜底，用来做代理、懒加载、动态属性。

**Q36. 元类是什么？什么时候用？** 🔥🔥

元类是「类的类」，控制类的创建。类创建流程：确定元类 → `__prepare__` 返回命名空间 → 执行类体 → 元类 `__new__` → 元类 `__init__`；实例化时走元类的 `__call__`。**优先级顺序应该是：类装饰器 → `__init_subclass__` → 描述符 → 元类**。ORM（Django/SQLAlchemy）、序列化框架（Pydantic v1）、ABC 都用元类。

**Q37. `__init_subclass__` 比元类好在哪？** 🔥

PEP 487 引入。它是普通 classmethod，写法简单、无元类冲突风险（多继承时元类必须兼容），能覆盖 80% 的「子类注册/校验」需求。

**Q38. `dataclass`、`NamedTuple`、`TypedDict`、Pydantic 怎么选？** 🔥🔥

| 需求 | 选择 |
|------|------|
| 可变数据容器、内部使用 | `@dataclass` |
| 不可变、可哈希、能当 tuple 用 | `NamedTuple` / `@dataclass(frozen=True)` |
| 就是个 dict，只想标注类型 | `TypedDict` |
| **需要运行时校验/序列化（API 边界、LLM 输出）** | **Pydantic** |
| 百万级实例，内存敏感 | `@dataclass(slots=True)` |

**Q39. Mixin 的正确用法？**

Mixin 只提供方法、不定义 `__init__`、不持有状态、不单独实例化。**写在基类左侧**（`class C(LoggerMixin, Base)`），因为 MRO 从左到右，左侧才能覆盖 Base 的方法。多继承里所有类都要用 `**kwargs` 转发 `super().__init__()` 才能协作。

## 4. 生成器与装饰器类（10 题）

**Q40. 迭代器和可迭代对象的区别？** 🔥🔥🔥

可迭代对象（Iterable）实现 `__iter__`；迭代器（Iterator）同时实现 `__iter__`（返回 self）和 `__next__`。`list` 是可迭代但不是迭代器（可以反复遍历）；`iter(list)` 得到的迭代器是**一次性**的。

**Q41. 生成器的优势？** 🔥🔥🔥

① 惰性求值，**常量内存**处理无限/超大数据；② 代码比手写迭代器类短得多（自动维护状态机）；③ 可组合成流水线。代价：只能遍历一次、不能索引、不能取长度。

**Q42. `yield` 与 `return` 的区别？函数怎么变成生成器？**

编译器看到函数体内有 `yield` 就给 code object 打上 `CO_GENERATOR` 标志，调用它返回生成器对象而不执行任何代码。`yield` 挂起并保留栈帧，`return` 在生成器里会触发 `StopIteration(value)`。

**Q43. `send()` 怎么用？为什么要先 `next()`？** 🔥

`send(v)` 让 `x = yield` 表达式的值变成 v 并恢复执行。第一次必须 `next(gen)`（或 `send(None)`）**预激**，把执行推进到第一个 `yield` 处，否则 `TypeError`。

**Q44. `yield from` 的三个作用？** 🔥🔥

① 委托迭代（替代 `for x in sub: yield x`）；② **双向转发** `send()`/`throw()` 给子生成器；③ 接收子生成器 `return` 的值（`result = yield from sub()`）。第 ②③ 点是 `for` 循环写法做不到的，也是 `async/await` 的语法基础。

**Q45. 装饰器的本质？三层装饰器怎么写？** 🔥🔥🔥

本质是高阶函数：接收函数返回函数，`@d` 等价于 `f = d(f)`。带参数的装饰器需要三层：最外层收装饰器参数、中层收函数、内层收调用参数。

**Q46. 多个装饰器的执行顺序？** 🔥🔥

装饰（自下而上）：`@a @b def f` → `f = a(b(f))`。调用（自外而内，洋葱模型）：`a` 的前置 → `b` 的前置 → `f` → `b` 的后置 → `a` 的后置。**顺序有语义**：`@auth` 必须在 `@cache` 外层，否则未授权用户能命中缓存。

**Q47. `lru_cache` 的坑？** 🔥

① 装实例方法会把 `self` 作为 key，导致实例永不释放（内存泄漏）；② 参数必须可哈希（不能传 list/dict）；③ `maxsize=None` 无上限；④ 不区分 `f(1)` 和 `f(x=1)`（不同 key）；⑤ 缓存的可变返回值被调用方改动会污染缓存。

**Q48. 类装饰器 vs 函数装饰器？**

装饰函数：函数装饰器更轻；需要状态就用带 `__call__` 的类。装饰类：类装饰器（如 `@dataclass`）在类创建完成后修改它，比元类简单，且不参与继承。

**Q49. 上下文管理器的两种实现方式？** 🔥🔥

① 类：实现 `__enter__`/`__exit__`；② `@contextlib.contextmanager` 装饰生成器，`yield` 前是 enter、`yield` 后是 exit（**必须放 `try/finally`**，否则异常时清理代码不执行）。`__exit__` 返回真值会**吞掉异常**——忘了 `return False` 是常见 bug。

## 5. 内存与并发类（14 题）

**Q50. Python 的垃圾回收机制？** 🔥🔥🔥

**引用计数为主**（归零立即释放，确定性好）+ **分代标记清除为辅**（专门处理循环引用，三代阈值 700/10/10）。GC 只追踪容器对象。与 JVM 对比：JVM 用可达性分析 + 分代复制，会移动对象做内存整理；CPython 不移动对象。

**Q51. 引用计数的缺点？**

① 无法回收循环引用（需分代 GC 兜底）；② 每次赋值/传参都要改计数，有性能开销；③ 计数字段占内存；④ free-threading 下需要原子操作或有偏计数。

**Q52. 什么情况会内存泄漏？** 🔥🔥

真正的泄漏几乎都是「**强引用被长生命周期容器持有**」：模块级 dict/list 只增不减、无上限缓存、事件监听器未注销、`lru_cache` 装实例方法、保存了异常的 `__traceback__`。循环引用不算永久泄漏（GC 能收），但会延迟释放。

**Q53. 怎么排查内存问题？** 🔥

`gc.collect()` 试探是否循环引用积压 → `objgraph.show_growth()` 找出增长的类型 → `gc.get_referrers()` 找出持有者 → `tracemalloc` 快照对比定位分配代码行。生产环境首选 `tracemalloc`（标准库自带）或 `memray`。

**Q54. `sys.getsizeof` 准确吗？**

只算对象自身的「壳」，**不递归**算引用的内容。`getsizeof([[0]*1000]*100)` 只有几百字节。要真实大小用 `pympler.asizeof`。

**Q55. weakref 有什么用？** 🔥

不增加引用计数，因此不阻止回收。三个主场：`WeakValueDictionary` 做缓存（值死了条目自动删）、`WeakKeyDictionary` 给第三方对象挂元数据、给树/图的反向指针打破循环引用。`weakref.finalize` 是 `__del__` 的可靠替代。

**Q56. GIL 是什么？为什么存在？** 🔥🔥🔥

保护解释器内部状态（尤其是**非原子的引用计数**）的全局互斥锁，同一进程内同一时刻只有一个线程执行字节码。存在原因：保护 refcount、简化 C 扩展、单线程性能优于细粒度锁。

**Q57. GIL 什么时候释放？** 🔥🔥

① I/O 操作前（read/write/socket/sleep）；② C 扩展显式释放（numpy/torch 的大计算）；③ 每 5ms（`sys.getswitchinterval()`）请求切换。所以**I/O 密集和 numpy 计算用多线程是有效的**。

**Q58. 有了 GIL 还需要加锁吗？** 🔥🔥

需要。GIL 只保证单条字节码原子，不保证复合操作。`count += 1` 是 LOAD-ADD-STORE 三步，可被打断。单条 `list.append` / `dict.__setitem__` 是原子的，但 `d[k] = d.get(k,0)+1` 不是。

**Q59. 多线程、多进程、协程怎么选？** 🔥🔥🔥

CPU 密集 → 多进程（或改用 numpy/Cython 绕开 GIL）；I/O 密集且任务数百以内 → 线程池（改造成本最低）；I/O 密集且上万并发 → asyncio（单位内存低 2-3 个数量级）；混合 → asyncio + `run_in_executor` 卸载 CPU 部分。

**Q60. 协程比线程好在哪？** 🔥🔥

① 单位开销 KB 级 vs 线程 MB 级栈；② 用户态切换，无系统调用；③ **协作式调度，切换点只在 `await`**，所以 await 之间的代码天然原子，几乎不需要锁。代价：需要全链路异步库（函数染色），一个同步阻塞调用就冻结整个事件循环。

**Q61. `async`/`await` 的底层是什么？** 🔥🔥

协程对象和生成器共享底层机制（都有 `send`/`throw`/`close`，只是 code flag 不同）。`await` 本质是 `yield from` 的语义升级：让出控制权给事件循环，并登记恢复条件（I/O 就绪或定时器到期）。事件循环 = `selector`(epoll/kqueue/IOCP) + 定时器堆 + ready 队列的单线程调度器。

**Q62. asyncio 里最容易犯的错？** 🔥🔥

① 在协程里调同步阻塞函数（`time.sleep`/`requests.get`）→ 冻结整个循环，应用 `asyncio.to_thread`；② 忘记 await（协程对象不执行）；③ 串行 await 而不用 `gather`；④ 不加 `Semaphore` 限流被 API 封；⑤ `create_task` 后不保留引用 → 任务可能被 GC。

**Q63. free-threading（PEP 703）会带来什么？** 🔥

3.13 实验性、3.14 正式支持但非默认。收益：纯 Python 多线程真并行。代价：单线程性能下降、C 扩展需声明兼容、**原本被 GIL 掩盖的数据竞争会真实暴露**。不要指望老代码自动变快。

## 6. 陷阱代码 15 道

先自己推断输出，再看答案。

```python
# 【1】可变默认参数 🔥🔥🔥
def add(x, lst=[]):
    lst.append(x); return lst
print(add(1)); print(add(2)); print(add(3))
```
> `[1]` `[1, 2]` `[1, 2, 3]`。默认值在**函数定义时求值一次**，存在 `func.__defaults__` 里被所有调用共享。修复：`def add(x, lst=None): lst = [] if lst is None else lst`。

```python
# 【2】闭包延迟绑定 🔥🔥🔥
fs = [lambda: i for i in range(3)]
print([f() for f in fs])
```
> `[2, 2, 2]`。闭包捕获变量而非值。修复：`lambda i=i: i`。

```python
# 【3】乘法浅拷贝 🔥🔥
m = [[0] * 3] * 3
m[0][0] = 1
print(m)
```
> `[[1,0,0], [1,0,0], [1,0,0]]`。外层 `*3` 复制的是**同一个内层列表的引用**。修复：`[[0]*3 for _ in range(3)]`。

```python
# 【4】小整数池 🔥🔥
a, b = 256, 256
c, d = 257, 257
print(a is b, c is d)
```
> `True False`（脚本文件里因常量折叠可能都是 True，交互式解释器里是 `True False`）。`[-5, 256]` 被缓存。**结论：数值比较永远用 `==`**。

```python
# 【5】+= 的分裂行为 🔥🔥
t = ([1, 2], [3])
try: t[0] += [9]
except TypeError as e: print("异常:", e)
print(t)
```
> 抛 `TypeError: 'tuple' object does not support item assignment`，但 `t` 已变成 `([1,2,9], [3])`！`+=` 先调 `list.__iadd__`（原地成功），再执行 `t[0] = result`（失败）。修复：`t[0].extend([9])`。

```python
# 【6】遍历时修改 🔥🔥
xs = [1, 2, 3, 4, 5, 6]
for x in xs:
    if x % 2 == 0: xs.remove(x)
print(xs)
```
> `[1, 3, 5]`（这次凑巧对了）。但 `[1,2,2,3]` 会得到 `[1,2,3]`——漏删。索引在移动。修复：`xs = [x for x in xs if x % 2]` 或倒序遍历。

```python
# 【7】类变量共享 🔥🔥
class Dog:
    tricks = []
    def add(self, t): self.tricks.append(t)
d1, d2 = Dog(), Dog()
d1.add("sit")
print(d2.tricks)
```
> `['sit']`。可变类变量被所有实例共享。`append` 是修改而非赋值，不会创建实例属性。修复：在 `__init__` 里 `self.tricks = []`。

```python
# 【8】except 变量作用域
try: raise ValueError("x")
except ValueError as e: pass
print(e)
```
> `NameError`。Python 3 在 except 块结束时隐式 `del e`（防止 traceback 引起循环引用）。要用就先存到别的变量。

```python
# 【9】布尔是整数子类 🔥
print(True + True, isinstance(True, int))
print({1: "a", True: "b", 1.0: "c"})
print(sum([True, True, False]))
```
> `2 True` / `{1: 'c'}` / `2`。`bool` 继承 `int`，且 `hash(1)==hash(True)==hash(1.0)` 且三者 `==` 相等 → 字典里是同一个 key，值被反复覆盖。

```python
# 【10】默认参数与类型注解无关
def f(x: int = "not an int") -> int: return x
print(f(), type(f()))
```
> `not an int <class 'str'>`。注解运行时不检查。

```python
# 【11】链式比较的陷阱
print(1 in [1, 2] == True)
```
> `False`。链式比较展开为 `(1 in [1,2]) and ([1,2] == True)` → `True and False`。

```python
# 【12】字符串驻留不可靠 🔥
a = "hello world"
b = "hello world"
c = "hello" + " " + "world"
d = "".join(["hello", " ", "world"])
print(a is b, a is c, a is d)
```
> `True True False`。含空格的字面量在同一编译单元里会被驻留，常量折叠也生效；但**运行时构造**的字符串不驻留。永远用 `==`。

```python
# 【13】生成器一次性 🔥🔥
g = (x for x in range(3))
print(list(g), list(g))
print(sum(g))
```
> `[0,1,2] []` / `0`。迭代器耗尽后不会重置。需要多次遍历就存成 list，或用返回生成器的函数。

```python
# 【14】set/dict 推导式里的作用域
x = "outer"
lst = [x for x in range(3)]
print(x)
```
> `outer`。Python 3 的推导式有独立作用域（3.12 起被内联但仍隔离），不会泄漏循环变量。Python 2 会输出 `2`。

```python
# 【15】finally 覆盖 return 🔥
def f():
    try: return 1
    finally: return 2
print(f())

def g():
    for i in range(3):
        try: return i
        finally: print("cleanup", i)
print(g())
```
> `2` / `cleanup 0` 然后 `0`。`finally` 里的 `return` 会**覆盖** try 里的返回值（同理 `break`/`continue` 也会吞掉异常）。永远不要在 `finally` 里 return。

```python
# 【1】带参数的重试装饰器（保留元信息 + 指数退避）🔥🔥🔥
import functools, time, random

def retry(times=3, delay=1.0, backoff=2.0, exceptions=(Exception,), jitter=True):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            wait, last = delay, None
            for attempt in range(1, times + 1):
                try:
                    return func(*args, **kwargs)
                except exceptions as e:
                    last = e
                    if attempt == times: break
                    sleep = wait * (1 + random.random() * 0.1) if jitter else wait
                    print(f"[{func.__name__}] 第 {attempt} 次失败: {e}，{sleep:.2f}s 后重试")
                    time.sleep(sleep)
                    wait *= backoff
            raise last
        return wrapper
    return decorator

@retry(times=3, delay=0.1, exceptions=(ConnectionError, TimeoutError))
def call_llm(prompt): ...
```

```python
# 【2】线程安全的单例（三种写法）🔥🔥
# 方案 A：模块级变量 —— 最 Pythonic，模块天然是单例
# config.py 里直接 settings = Settings()

# 方案 B：__new__ + 双重检查锁
import threading
class Singleton:
    _inst, _lock = None, threading.Lock()
    def __new__(cls, *a, **kw):
        if cls._inst is None:
            with cls._lock:
                if cls._inst is None:                 # 双重检查
                    cls._inst = super().__new__(cls)
        return cls._inst
    def __init__(self, v=None):
        if getattr(self, "_ready", False): return     # 防止重复初始化
        self.v, self._ready = v, True

# 方案 C：装饰器（可复用，但破坏 isinstance 语义要注意）
def singleton(cls):
    instances, lock = {}, threading.Lock()
    @functools.wraps(cls)
    def get(*a, **kw):
        if cls not in instances:
            with lock:
                if cls not in instances: instances[cls] = cls(*a, **kw)
        return instances[cls]
    return get
```

```python
# 【3】LRU 缓存（OrderedDict 版 + 双向链表版）🔥🔥🔥
from collections import OrderedDict

class LRUCache:
    def __init__(self, capacity: int):
        self.cap, self.d = capacity, OrderedDict()
    def get(self, key, default=None):
        if key not in self.d: return default
        self.d.move_to_end(key)                       # 命中 → 移到最新端
        return self.d[key]
    def put(self, key, value):
        if key in self.d: self.d.move_to_end(key)
        self.d[key] = value
        if len(self.d) > self.cap:
            self.d.popitem(last=False)                # 淘汰最旧
```

```python
# 双向链表 + 哈希表版（面试常要求不用 OrderedDict）
class Node:
    __slots__ = ("k", "v", "prev", "next")
    def __init__(self, k=None, v=None): self.k, self.v, self.prev, self.next = k, v, None, None

class LRUCache2:
    def __init__(self, capacity):
        self.cap, self.map = capacity, {}
        self.head, self.tail = Node(), Node()         # 哨兵节点，省掉边界判断
        self.head.next, self.tail.prev = self.tail, self.head

    def _remove(self, n):
        n.prev.next, n.next.prev = n.next, n.prev

    def _add_front(self, n):
        n.next, n.prev = self.head.next, self.head
        self.head.next.prev = self.head.next = n

    def get(self, k):
        if k not in self.map: return -1
        n = self.map[k]; self._remove(n); self._add_front(n)
        return n.v

    def put(self, k, v):
        if k in self.map:
            n = self.map[k]; n.v = v; self._remove(n); self._add_front(n); return
        if len(self.map) >= self.cap:
            lru = self.tail.prev
            self._remove(lru); del self.map[lru.k]
        n = Node(k, v); self.map[k] = n; self._add_front(n)
# get / put 均 O(1)
```

```python
def my_range(start, stop=None, step=1):
```

```python
# 【5】上下文管理器：两种写法实现同一个计时器 🔥🔥
import time, contextlib

class Timer:                                          # 类写法：可保存状态
    def __init__(self, name="任务"): self.name = name
    def __enter__(self):
        self.t = time.perf_counter(); return self
    def __exit__(self, exc_type, exc_val, tb):
        self.elapsed = time.perf_counter() - self.t
        status = "失败" if exc_type else "完成"
        print(f"[{self.name}] {status}，耗时 {self.elapsed:.3f}s")
        return False                                  # ← 不吞异常

@contextlib.contextmanager
def timer(name="任务"):                                # 生成器写法：更短
    t = time.perf_counter()
    try:
        yield
    finally:                                          # ← 必须 finally，否则异常时不打印
        print(f"[{name}] 耗时 {time.perf_counter() - t:.3f}s")

with Timer("推理") as t:
    time.sleep(0.1)
print(t.elapsed)

with timer("训练"):
    time.sleep(0.1)
```

**结构化答题四步法**

```text
① 一句话定义     ——「GIL 是一把保护解释器内部状态的全局互斥锁」
② 为什么这样设计 ——「因为引用计数的增减不是原子操作」
③ 举一个例子/数字 ——「4 线程跑纯 Python 计算不会比单线程快，甚至更慢」
④ 实践中怎么应对  ——「CPU 密集用多进程，或把计算下沉到 numpy」
```

**加分动作**

- 主动给出**版本差异**：「3.7 起字典有序写进规范」「3.11 有了 TaskGroup」「3.14 free-threading 正式支持」
- 主动说**代价**而不只说优点：「`__slots__` 省内存，但不能动态加属性、默认不支持弱引用」
- 主动关联**真实项目**：「FastAPI 的依赖注入依赖 `inspect.signature`，所以装饰器必须 `functools.wraps`」
- 承认边界：「这块我只在 X 场景用过，Y 的细节我不确定」比编造强得多

**必须避免**

- 说"Python 没有多线程"（错，只是纯 Python 计算不并行）
- 说"`is` 比 `==` 快所以用 `is`"（语义完全不同）
- 说"注解能保证类型安全"（运行时不生效）
- 说"`__slots__` 是为了封装"（是为了省内存）
