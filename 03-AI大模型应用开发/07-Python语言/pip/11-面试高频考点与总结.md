## 1. 高频面试题

### Q1: requirements.txt 和 poetry.lock 有什么区别？

> - `requirements.txt`：列出包名+版本，但不区分"直接依赖"和"传递依赖"，依赖树可能漂移
> - `poetry.lock`：精确锁定整个依赖树 + hash 校验，保证所有环境安装完全相同的版本
> - 生产环境：pip-tools 的 `requirements.txt`（含 hash）或 Poetry lock

### Q2: 怎么排查 "在我电脑上能跑，到你电脑上就报错"？

> 1. `pip freeze` 对比两边环境差异
> 2. 检查 Python 版本 `python --version`
> 3. 检查操作系统差异（Windows/Linux/macOS）
> 4. 检查 CUDA 版本（GPU 相关错误）`nvidia-smi`
> 5. 终极方案：Docker 统一环境

### Q3: venv 和 conda 怎么选？

> - `venv`：纯 Python 项目，轻量，Python 内置
> - `conda`：AI/科学计算项目，管理 CUDA + Python + C 库一体
> - 推荐：AI 项目用 conda 管理 CUDA，再 pip 装 Python 包

### Q4: pip install 太慢怎么办？

> 1. 换国内镜像源（清华/阿里云）
> 2. 用 `--no-cache-dir` 排查缓存损坏
> 3. 优先找 `.whl`（预编译）而非源码
> 4. 内网搭建 PyPI 缓存/私服

### Q5: 依赖冲突怎么解决？

> 1. `pip check` 定位冲突包
> 2. `pipdeptree` 看依赖树，找到冲突的传递依赖
> 3. 降级/升级其中一个包到兼容版本
> 4. 如果无法解决：换替代包 或 fork 源码修改 `setup.cfg`

### Q6: Docker 中 Python 依赖怎么管理？

> 1. COPY requirements.txt 在 COPY 代码之前（利用层缓存）
> 2. `pip install --no-cache-dir` 减小镜像体积
> 3. 开发/生产分离 requirements 文件
> 4. AI 项目用 `nvidia/cuda` 基础镜像

## 核心要点回顾

- "环境问题"的根 = 没有虚拟环境 + 依赖未锁定 + CUDA 版本不匹配
- 面试必须展示：虚拟环境意识 + 依赖锁定 + 排查方法论
- Docker = 终极"在我电脑上能跑"解决方案
- AI 项目依赖管理的特殊性：CUDA + PyTorch 版本强耦合
