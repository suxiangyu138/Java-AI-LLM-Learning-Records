## 1. 为什么需要模型编辑

```text
大模型部署后面临的现实问题：

问题 1：知识过时
  → GPT-3.5 知识截止 2021 年 9 月
  → "最新的 Java 版本是什么？" → 回答 Java 17（实际已到 Java 21）

问题 2：事实错误
  → 模型误以为斑马皮肤是肉色 → 需要修正
  → "世界上最高的山是？" → 可能答错

问题 3：偏见与安全
  → 职业刻板印象、性别偏见
  → 生成有害/违规内容

传统解决方案的困境：
  重新训练 → 成本 $100K~$10M，时间数周
  全量微调 → 灾难性遗忘，破坏通用能力
  模型编辑 → 精准、低成本、不影响其他知识 ✅
```

## 3. 外部扩展法

### 3.1 知识缓存法

```text
核心思路：维护一个"正确答案"缓存库，模型优先查缓存

实现：
  缓存 = {"斑马皮肤是什么颜色？": "黑色",
         "Java最新版本是什么？": "Java 21 (LTS)"}
  
  推理时：用户问题 → 先查缓存 → 命中 → 直接返回
                               → 未命中 → 正常推理

优点：简单安全，零风险
缺点：只能处理精确匹配，泛化差
```

### 3.2 RAG 作为"持续编辑"方案

```text
RAG = 最实用的"外部扩展"模型编辑方案

为什么 RAG 比模型编辑更实用？
  ✅ 知识库可随时更新（增删改文档即可）
  ✅ 零模型风险（模型参数不动）
  ✅ 可溯源（知道答案来自哪个文档）
  ✅ 处理范围广（不只是问答对）
  ✅ 生态成熟（LangChain/LlamaIndex）

RAG 三件套：
  ① 文档切割 → ② 向量化入库 → ③ 检索+生成
```

## 4. 内部修改法

### 4.1 元学习法

```text
核心思路：训练一个"编辑器"来编辑模型

  让模型学会"如何被编辑"：
  ① 准备大量编辑任务（旧知识 → 新知识）
  ② 训练一个超网络，预测参数变化 ΔW
  ③ 应用 ΔW 到目标模型

  效果：少量样本即可快速完成新编辑
```

### 4.2 定位编辑法（ROME/MEMIT）

```text
核心思路：精准定位存储目标知识的神经元，局部修改

步骤：
  ① 因果追踪（Causal Tracing）
     通过分析每层的激活值，找出存储目标事实的神经元位置

  ② 定位知识所在的 MLP 层
     研究发现：FFN 中间层存储了大量事实知识

  ③ 局部参数修改
     用约束优化方法，仅修改定位到的少量权重

  ④ 验证
     确保修改后：目标知识正确 + 无关知识不受影响

代表方法：
  ROME (Rank-One Model Editing)：修改单条事实
  MEMIT (Mass Editing Memory in Transformer)：批量修改
```

## 5. 模型编辑 vs RAG vs 微调

| 维度 | 模型编辑 | RAG | LoRA 微调 |
|------|:---:|:---:|:---:|
| **修改模型** | ✅（局部） | ❌ | ✅（Adapter） |
| **知识生效** | 即时 | 即时 | 需要训练 |
| **泛化能力** | 中 | 中（依赖检索） | 高 |
| **副作用风险** | 中 | 低 | 中 |
| **推理开销** | 无 | 有（检索延迟） | 无（可合并） |
| **成本** | 低 | 低 | 中 |
| **适用规模** | 少量事实 | 大量文档 | 领域适配 |
| **成熟度** | 实验阶段 | 生产可用 ✅ | 生产可用 ✅ |

```text
推荐策略：

少量精确事实 → 模型编辑（ROME/MEMIT）
大量私有知识 → RAG（最实用）
领域/风格适配 → LoRA 微调
知识更新频率高 → RAG（即时更新文档）
```

## 6. 机器遗忘 Unlearning

### 6.1 什么是机器遗忘

```text
机器遗忘（Machine Unlearning）：
  让模型"忘记"特定的训练数据或能力

为什么需要遗忘？
  ✅ 隐私法规（GDPR"被遗忘权"）
  ✅ 删除泄露的个人信息
  ✅ 移除有害/偏见知识
  ✅ 忘记版权保护的训练数据
```

### 6.2 遗忘方法

| 方法 | 原理 | 效果 |
|------|------|:---:|
| **数据重训练** | 删掉数据重新训练 | 完美但不可行 |
| **梯度上升** | 对目标数据反向优化（"反学习"） | 效果一般 |
| **知识蒸馏遗忘** | 学生模型排除了敏感知识 | 较可靠 |
| **参数隔离** | 用 LoRA 隔离敏感知识，删除即可 | 实际可行 |

> 💡 目前机器遗忘仍是研究热点，没有一劳永逸的成熟方案。实际中更推荐从数据源头控制 + RAG 隔离敏感信息。

## 7. 大模型幻觉治理

### 7.1 幻觉的分类

```text
幻觉（Hallucination）= 模型生成看似合理但不符合事实的内容

类型 1：事实性幻觉
  问："2024 年诺贝尔物理学奖得主是谁？"
  答："2024 年诺贝尔物理学奖授予了..."（实则未公布）→ 编造

类型 2：忠实性幻觉
  输入："请根据上文总结..." → 输出与上文矛盾的内容

类型 3：逻辑性幻觉
  推理链中存在跳跃或矛盾
```

### 7.2 幻觉治理方案

| 方案 | 说明 | 效果 |
|------|------|:---:|
| **RAG 检索增强** | 先查资料再回答 | ⭐⭐⭐⭐⭐ |
| **Prompt 约束** | "不知道就说不知道" | ⭐⭐⭐ |
| **Fact-Checking** | 用外部工具验证关键事实 | ⭐⭐⭐⭐ |
| **多模型交叉验证** | 多个模型独立回答→投票 | ⭐⭐⭐ |
| **CoT 验证** | 模型自检推理链 | ⭐⭐⭐ |
| **更好的训练数据** | 数据清洗更严格 | ⭐⭐⭐⭐ |
| **RLHF 诚实对齐** | 奖励模型在不确定时说"不知道" | ⭐⭐⭐⭐ |

> 🎯 RAG 是目前最有效、最实用的幻觉治理方案 — 让模型"有据可查"。

## 8. 高频面试题

### Q1: 大模型为什么会产生幻觉？

```text
本质原因：
  ① LLM 是概率生成模型，不是知识库 → 目标是"说得像"，不是"说得对"
  ② 训练数据中的噪声、矛盾、错误 → 被模型学习
  ③ 长尾知识记忆不准确（低频事实容易被"平滑"掉）
  ④ 解码策略（高 temperature、top-p 采样）引入随机性
  ⑤ 知识截断 → 不知道训练后发生的事情
```

### Q2: RLHF 的完整流程是什么？

```text
① SFT：Base Model + 人工标注指令数据 → Instruct Model
② 收集偏好：SFT Model 对同一 Prompt 生成 N 个回答 → 人类排序
③ 训练 RM：用排序数据训练 Reward Model，学会"打分"
④ PPO 优化：以 RM 为奖励信号 + KL 约束，用 PPO 优化 SFT Model
```

### Q3: LoRA 为什么能大幅减少训练参数？

```text
核心假设：微调时的权重更新矩阵 ΔW 是"低秩"的

  W_new = W_pretrained + ΔW
  ΔW ≈ B × A  （B: d×r, A: r×d, r << d）

  原 ΔW: d × d = 4096 × 4096 = 16.8M 参数
  LoRA: d×r + r×d = 4096×8 + 8×4096 = 65K 参数
  → 参数减少 256×
```

### Q4: 模型量化为什么几乎不损失效果？

```text
① LLM 权重分布接近正态 → 可以用更少的 bit 精确表示
② 推理时很多权重"没那么重要" → 精度损失影响小
③ 量化感知训练（QAT）在训练时就考虑量化 → 效果更好
④ 4-bit 是临界点 → 4-bit 以上几乎无损，2-bit 以下明显下降
```

### Q5: Decoder-Only 为什么成为主流？

```text
① 生成能力强（对话/代码/写作的核心需求）
② Scaling 友好：越大越强，没有明显瓶颈
③ 架构简单：去掉 Encoder 和 Cross-Attention
④ 统一预训练任务（Next Token Prediction）
⑤ 生态效应：最好的模型（GPT-4）是 Decoder-Only → 其他跟进
```

## 核心要点回顾

- 模型编辑 = 精准打补丁，外部扩展（不改参数）+ 内部修改（局部改参）
- RAG 是最实用的"持续知识更新"方案（即时、安全、可溯源）
- 幻觉治理：RAG > 约束 Prompt > 事实检查 > RLHF 诚实对齐
- 机器遗忘仍在研究阶段，实践中更推荐 RAG 隔离敏感信息
- 模型编辑 vs RAG vs 微调：各有所长，按场景组合使用
