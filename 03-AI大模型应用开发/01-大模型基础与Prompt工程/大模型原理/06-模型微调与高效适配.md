## 1. 全量微调 vs 高效微调

```text
全量微调（Full Fine-Tuning）：
  → 更新模型所有参数
  → 效果好，但代价巨大
  → 70B 模型：需 ~140GB 显存（仅模型权重）
  → 需要 4~8 张 A100(80GB)

高效微调（PEFT, Parameter-Efficient Fine-Tuning）：
  → 只更新少量参数（<1%）
  → 效果接近全量微调
  → 7B 模型：消费级显卡即可（RTX 4090 24GB）
  → 个人开发者可及
```

| 维度 | 全量微调 | LoRA | QLoRA |
|------|----------|------|-------|
| **修改参数比例** | 100% | 0.1%~1% | 0.1%~1% |
| **显存需求 (7B)** | ~60GB | ~16GB | ~8GB |
| **训练速度** | 慢 | 快 | 中 |
| **效果** | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ |
| **可合并** | — | ✅ | ✅ |
| **多任务切换** | 一套权重 | 换 Adapter | 换 Adapter |

## 2. LoRA：低秩适应

### 2.1 核心原理

```text
LoRA = Low-Rank Adaptation（Hu et al., ICLR 2022）

核心假设：
  微调时的权重更新 ΔW 是"低秩"的
  → 不需要存储完整的 ΔW
  → 用两个小矩阵相乘来近似

数学：
  原始前向：h = W₀x
  LoRA 前向：h = W₀x + BAx
                   └── W₀ 冻结不动
                       └── BA 是低秩分解矩阵

  W₀: (d × d)    如 4096 × 4096 = 16.8M 参数
  B:  (d × r)    如 4096 × 8 = 32K
  A:  (r × d)    如 8 × 4096 = 32K
  → 只训练 BA 的 64K 参数（原参数的 0.4%！）
```

### 2.2 关键参数

| 参数 | 说明 | 典型值 |
|------|------|--------|
| **r (rank)** | 低秩矩阵的秩 | 4 / 8 / 16 / 32 |
| **alpha** | 缩放系数 | 16 / 32（通常 α = 2r） |
| **target_modules** | 应用 LoRA 的层 | q_proj, v_proj（注意力层） |
| **dropout** | Dropout 比例 | 0.05 ~ 0.1 |

```text
r 的选择：
  r=4： 极轻量，快速实验
  r=8： 通用推荐，效果好且参数少
  r=16：更好的效果，更大的文件
  r=32+：接近全量微调效果，但收益递减

经验法则：r=8, alpha=16 → 大多数场景的好起点
```

### 2.3 LoRA 应用位置

```text
通常只在 Attention 层加 LoRA：

  Q 投影 (query):  ✅ 必加
  K 投影 (key):    ✅ 建议加
  V 投影 (value):  ✅ 必加
  O 投影 (output): ⚠️ 可选

是否加 FFN 层？
  → 实验表明 Attn 层 LoRA 已足够
  → 加 FFN 效果提升有限，参数翻倍
  → 除非特定领域知识注入，一般不加
```

### 2.4 LoRA 代码示例

```python
from peft import LoraConfig, get_peft_model
from transformers import AutoModelForCausalLM

model = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2-7B")

lora_config = LoraConfig(
    r=8,                        # rank
    lora_alpha=16,              # 缩放
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
    lora_dropout=0.05,
    task_type="CAUSAL_LM"
)

model = get_peft_model(model, lora_config)
model.print_trainable_parameters()
# 输出: trainable params: 8,388,608 || all params: 7,078,658,048 || trainable%: 0.1185%
```

## 3. QLoRA：量化 LoRA

### 3.1 核心原理

```text
QLoRA = Quantized LoRA（Dettmers et al., NeurIPS 2023）

核心创新：将基座模型量化为 4-bit，进一步降低显存

技术栈：
  ① 4-bit NormalFloat (NF4)：专为正态分布权重设计的 4-bit 量化格式
  ② 双重量化（Double Quantization）：量化常数也量化，再省 ~0.4 bit/参数
  ③ 分页优化器（Paged Optimizer）：利用 CPU 内存处理梯度峰值

效果：
  LLaMA-65B + QLoRA 4-bit：
    → 单张 48GB GPU 可微调！
    → 效果接近 16-bit 全量微调
```

### 3.2 QLoRA vs LoRA

| 维度 | LoRA | QLoRA |
|------|------|-------|
| **基座精度** | FP16/BF16 | 4-bit (NF4) |
| **显存需求 (7B)** | ~16GB | ~6GB |
| **显存需求 (70B)** | ~48GB | ~20GB |
| **训练速度** | 快 | 慢 30~50% |
| **效果** | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ |
| **适用** | 单卡 24GB+ | 消费级显卡 |

### 3.3 QLoRA 代码

```python
from transformers import BitsAndBytesConfig
import torch

# 4-bit 量化配置
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",         # NF4 量化
    bnb_4bit_compute_dtype=torch.bfloat16,
    bnb_4bit_use_double_quant=True,    # 双重量化
)

model = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen2-7B",
    quantization_config=bnb_config,
    device_map="auto"
)

# LoRA 配置同上
model = get_peft_model(model, lora_config)
```

## 4. PEFT 方法全景

### 4.1 四种主流 PEFT 方法

| 方法 | 原理 | 可训练参数 | 推理开销 |
|------|------|:---:|:---:|
| **LoRA/QLoRA** | 低秩分解 + 旁路矩阵 | <1% | 可合并为0 |
| **Adapter** | 在层间插入小型网络 | 3~5% | 有 |
| **Prefix Tuning** | 在输入前加可学习向量 | <1% | 占用上下文 |
| **Prompt Tuning** | 学一组软 Prompt | <0.1% | 占用上下文 |

### 4.2 方法对比

```text
LoRA 系列（最推荐）：
  ✅ 效果最好
  ✅ 可合并到原权重（推理零开销）
  ✅ 多 LoRA 快速切换（换 Adapter 文件即可）
  ✅ 社区最活跃，工具最成熟

Adapter：
  → 推理有额外计算开销
  → 效果略逊于 LoRA
  → 已被 LoRA 替代趋势

Prefix/Prompt Tuning：
  → 占用宝贵的上下文空间
  → 对大模型（>10B）效果还行
  → 适用于无法修改模型的场景（如 API 调用）
```

## 5. 微调实战流程

### 5.1 标准流程

```text
微调七步法：

① 明确目标
   → 是什么任务？（对话/分类/代码/知识注入）
   → 需要多大模型？（7B/14B/72B）

② 准备数据
   → 格式：instruction-input-output / conversations
   → 数量：500~100K 条，质量 > 数量
   → 格式统一，去除噪声

③ 选择基座模型
   → 中文 → Qwen/ChatGLM
   → 英文 → LLaMA/Mistral
   → 代码 → DeepSeek-Coder

④ 配置 LoRA
   → r=8, alpha=16（起步推荐）
   → target_modules: q_proj, v_proj

⑤ 训练
   → epoch=1~3（小数据 3，大数据 1）
   → lr=2e-4（LoRA 常用）
   → batch_size=4~16（视显存而定）

⑥ 评估
   → 留 10% 数据做测试集
   → 人工评估 + 自动评估（BLEU/ROUGE/GPT-Eval）

⑦ 部署
   → 合并 LoRA：model.merge_and_unload()
   → 导出为 GGUF/ONNX 等格式
   → 或保留 LoRA Adapter 按需加载
```

### 5.2 数据格式

```json
// Alpaca 格式（最常用）
[
  {
    "instruction": "将以下Java代码改为Stream API写法",
    "input": "List<String> result = new ArrayList<>(); for(String s : list) { if(s.length() > 3) { result.add(s); } }",
    "output": "List<String> result = list.stream().filter(s -> s.length() > 3).collect(Collectors.toList());"
  }
]

// ShareGPT 格式（多轮对话）
[
  {
    "conversations": [
      {"from": "human", "value": "什么是Java的多态？"},
      {"from": "gpt", "value": "多态是..."},
      {"from": "human", "value": "能举个例子吗？"},
      {"from": "gpt", "value": "好的..."}
    ]
  }
]
```

### 5.3 训练数据集推荐

| 数据集 | 规模 | 用途 | 语言 |
|------|:---:|------|:---:|
| Alpaca | 52K | 通用指令微调 | 英文 |
| BELLE | 100万+ | 中文指令微调 | 中文 |
| ShareGPT | ~90K | 多轮对话 | 多语言 |
| OpenOrca | ~1M | 推理增强 | 英文 |
| CodeAlpaca | 20K | 代码微调 | 英文 |

## 6. 灾难性遗忘与防控

### 6.1 什么是灾难性遗忘

```text
灾难性遗忘（Catastrophic Forgetting）：
  模型在学习新任务时，丢失了原有的通用能力

表现：
  微调前的 LLM：能写诗、翻译、推理、编程
  医疗微调后：只会回答医疗问题，忘了怎么写代码
  
原因：
  新数据分布与预训练数据分布差异大
  学习率过高/训练太久
```

### 6.2 防控方案

| 方案 | 说明 |
|------|------|
| **混合回放** | 在微调数据中混入 5~10% 通用数据 |
| **小学习率** | LoRA 用 2e-4，全量微调用 1e-5 |
| **早停** | epoch=1~3，不要训太多轮 |
| **多任务训练** | 同时训练多个领域，而非逐个 |
| **LoRA 天然优势** | 冻结基座权重 → 从根本上避免遗忘 |

> 🎯 LoRA 不修改原始权重 → 天然抗遗忘。这也是 LoRA 比全量微调更安全的重要原因之一。

## 核心要点回顾

- LoRA = 低秩矩阵旁路，修改 <1% 参数，达到全量微调 90%+ 效果
- QLoRA = LoRA + 4-bit 量化 → 单张消费显卡可微调 70B 模型
- LoRA 核心参数：r=8, alpha=16, target=q_proj+v_proj
- 微调关键：数据质量 > 数量，epoch=1~3，lr=2e-4
- LoRA 天然抗灾难性遗忘（冻结基座）
- 多 LoRA 可快速切换 → 一个模型适配多种场景
