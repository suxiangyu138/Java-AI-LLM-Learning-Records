### 2.2 统一调用示例

```python
# 所有平台基本兼容 OpenAI 接口格式
from openai import OpenAI

# 可切换不同平台
client = OpenAI(
    api_key="your-api-key",
    base_url="https://api.deepseek.com"  # DeepSeek
    # base_url="https://dashscope.aliyuncs.com/compatible-mode/v1" # 阿里

    model="deepseek-chat",
    messages=[{"role": "user", "content": "解释 Java 多态"}],
    temperature=0.7,
    max_tokens=1024
)

print(response.choices[0].message.content)
```

## 3. 本地部署：Ollama

### 3.1 Ollama 是什么

```text
Ollama = 一键本地部署 LLM 的工具

特点：
  ✅ 一行命令启动模型
  ✅ 自动下载+量化+运行
  ✅ 内置 OpenAI 兼容 API
  ✅ 支持 GPU 加速（CUDA/Metal）
  ✅ 跨平台（Linux/macOS/Windows）
```

### 3.2 常用命令

```bash
# 安装（macOS/Linux）
curl -fsSL https://ollama.com/install.sh | sh

# 拉取并运行模型
ollama run qwen2:7b           # Qwen-7B（4-bit量化）
ollama run llama3.1:8b        # LLaMA 3.1-8B
ollama run deepseek-r1:7b     # DeepSeek-R1-7B
ollama run qwen2:72b          # 需要 ~40GB 显存

# 查看已下载模型
ollama list

# 自定义 Modelfile
ollama create my-model -f Modelfile

# API 方式调用（兼容 OpenAI 格式）
curl http://localhost:11434/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"qwen2:7b","messages":[{"role":"user","content":"hello"}]}'
```

## 4. 企业级部署：vLLM

### 4.1 为什么需要 vLLM

```text
原始 HuggingFace Transformers 推理的问题：
  ❌ 没有 KV Cache 管理 → 显存碎片
  ❌ 没有连续批处理 → GPU 利用率低（~30%）
  ❌ 没有优化的 Attention Kernel → 慢

vLLM 的解决方案：
  ✅ PagedAttention → KV Cache 按"页"管理，零碎片
  ✅ Continuous Batching → 动态拼batch，GPU 利用率 80%+
  ✅ 优化的 CUDA Kernel → FlashAttention, FlashInfer
  ✅ 高并发：单卡 A100 支持数百并发
```

### 4.2 PagedAttention 原理

```text
PagedAttention = 借鉴 OS 虚拟内存分页的思想

传统方式：
  KV Cache 连续存储 → 预留最大长度空间 → 大量浪费

PagedAttention：
  KV Cache 分成固定大小的"页"（Page）
  → 多个请求共享显存池
  → 按需分配页，不浪费
  → 显存利用率提升 2~4×

类比：
  传统 = malloc(max_len) → 大部分人只用 20%
  PagedAttention = 按需分配物理页 → 接近 100% 利用率
```

### 4.3 vLLM 使用

```python
from vllm import LLM, SamplingParams

# 加载模型
llm = LLM(
    model="Qwen/Qwen2-7B-Instruct",
    tensor_parallel_size=1,     # 单卡
    max_model_len=8192,         # 上下文长度
    gpu_memory_utilization=0.9  # GPU 显存利用率
)

# 批量推理
prompts = [
    "解释 Java 多态",
    "Spring Boot 自动配置原理",
    "如何设计高并发系统"
]

sampling_params = SamplingParams(
    temperature=0.7,
    top_p=0.9,
    max_tokens=512
)

outputs = llm.generate(prompts, sampling_params)
for output in outputs:
    print(output.outputs[0].text)
```

## 6. 推理加速技术

| 技术 | 原理 | 加速比 |
|------|------|:---:|
| **FlashAttention** | 减少 HBM 读写，分块计算 | 2~4× |
| **KV Cache** | 缓存已计算的 Key/Value | 避免重复计算 |
| **Speculative Decoding** | 小模型"猜"多个 token，大模型验证 | 2~3× |
| **Continuous Batching** | 动态拼接请求批次 | GPU 利用率 2× |
| **Tensor Parallelism** | 张量切分到多 GPU | 支持超大模型 |
| **Pipeline Parallelism** | 不同层放不同 GPU | 同上 |

### FlashAttention 核心思想

```text
GPU 存储层级（由近到远、由快到慢）：
  SRAM (片上) > HBM (显存) > CPU RAM > Disk
  19TB/s       1.5TB/s    12.8GB/s

传统 Attention 的瓶颈：
  → QK^T 结果矩阵太大，必须写到 HBM
  → softmax 需要从 HBM 读回 → 写入 → 读回
  → 显存带宽是瓶颈

FlashAttention 的做法：
  → 分块（tiling）：把大矩阵切成小块，每次在 SRAM 中计算
  → 在线 softmax：不需要全量数据，逐块计算归一化
  → 结果：显存读写量从 O(n²) 降到 O(n)
```

## 7. 选型决策树

```text
需不需要部署模型？
  │
  ├── 不需要 → 公有云 API
  │   ├── 追求效果 → GPT-4o / Claude 3.5 Sonnet
  │   ├── 追求性价比 → DeepSeek / GPT-4o-mini
  │   └── 中文场景 → Qwen-Max / GLM-4
  │
  └── 需要自己部署
      │
      ├── 个人开发/学习
      │   ├── 有 GPU（≥8GB）→ Ollama + Qwen2-7B (Q4)
      │   └── 无 GPU → Ollama + Qwen2-1.5B (CPU)
      │
      └── 企业/高并发
          ├── 需高吞吐 → vLLM + A100/H100
          ├── 需极致优化 → TensorRT-LLM
          └── 需快速上手 → Ollama API 模式
```

## 核心要点回顾

- 三种部署：公有 API（零维护）、Ollama 本地（简单免费）、vLLM 企业（高并发）
- 量化可在几乎不损失效果的情况下将模型缩小 4~8 倍
- QLoRA 用 4-bit 量化让 70B 模型可单卡微调
- vLLM 的 PagedAttention 使 GPU 显存利用率从 30% 提升到 80%+
- FlashAttention 通过分块计算和 SRAM 优化，将显存读写从 O(n²) 降到 O(n)
- Ollama 是个人开发者最好的入口，一行命令即可本地运行大模型
