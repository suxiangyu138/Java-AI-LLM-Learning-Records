## 2. 预训练 Pre-training

### 2.1 核心要素

| 要素 | 说明 |
|------|------|
| **目标** | 学习语言的统计规律，掌握语法、常识、推理 |
| **数据** | 网页、书籍、论文、代码、维基 → 数万亿 token |
| **任务** | 自监督 — 预测下一个 token（Next Token Prediction） |
| **算力** | 数千张 A100/H100 GPU，持续数周到数月 |
| **产出** | Base Model（只会续写，不会对话） |

### 2.2 预训练任务

```text
GPT 系列（Decoder-Only）：自回归语言建模 (CLM)
  输入："今天天气真"
  预测：→ "好"  →  "，"

BERT 系列（Encoder-Only）：掩码语言建模 (MLM)
  输入："今天 [MASK] 真 [MASK] ，适合 [MASK] 游"
  预测：→ "天气"  →  "好"  →  "出"

当前主流：Decoder-Only + CLM，简单有效且 Scaling 友好
```

### 2.3 预训练数据组成

```text
典型 LLM 训练数据配比（以 LLaMA 为例）：

  CommonCrawl（网页）    ████████████████████ 67%
  C4（清洗后网页）        ████████ 15%
  GitHub（代码）          █████ 4.5%
  Wikipedia（维基）       ███ 4.5%

为什么加入代码？
  → 代码有严密的逻辑结构和长距离依赖

```

## 3. 监督微调 SFT

### 3.1 什么是 SFT

```text
SFT = 用高质量的人工标注"输入→输出"对，训练 Base Model 遵循指令

Base Model 的问题：
  输入："解释一下什么是 Transformer"
  输出："解释一下什么是 Transformer 是一种深度学习架构..." 
        ↑ Base Model 会续写你的话，而不是回答问题！

SFT 后：
  输入："解释一下什么是 Transformer"
  输出："Transformer 是 2017 年 Google 提出的深度学习架构，核心是自注意力机制..."
        ↑ 学会了"遵循指令"
```

### 3.2 SFT 数据示例

```json
{
  "instruction": "将以下 Java 代码改写为更简洁的写法",
  "input": "List<String> result = new ArrayList<>(); for(String s : list) { if(s.length() > 3) { result.add(s); } }",
  "output": "List<String> result = list.stream().filter(s -> s.length() > 3).collect(Collectors.toList());"
}
```

### 3.3 SFT 关键要点

| 要点 | 说明 |
|------|------|
| **数据量** | 1万~100万条高质量样本，质量 > 数量 |
| **多样性** | 覆盖各种任务：问答、翻译、代码、总结、写作 |
| **格式统一** | 通常用 ChatML 或 ShareGPT 格式 |
| **过拟合** | 小数据量 epoch=1~3，过多会"背答案"丢失泛化 |
| **学习率** | 比预训练高 10~100 倍（如 2e-5） |

## 4. RLHF 人类对齐

### 4.1 为什么需要 RLHF

```text
SFT 之后的问题：
  ❌ 可能生成有害/偏见/违规内容
  ❌ 不会拒绝不合理的请求
  ❌ 输出风格不统一（太长/太短/太啰嗦）
  ❌ 偏好不明确（不知道用户喜欢什么风格）

RLHF 的目标：让模型输出"人类喜欢的"回答
```

### 4.2 RLHF 四步流程

```text
Step 1: SFT 模型（已完成）
  Base Model + 标注数据 → SFT Model

Step 2: 收集人类偏好数据
  对同一个 prompt，让 SFT Model 生成 4 个回答
  人类标注员排序：最佳 → 次佳 → 次差 → 最差

  Prompt: "如何学习 Java？"
  Response A: "首先学基础语法，然后..."
  Response B: "直接看视频..."
  Response C: "Java 是一门很棒的..."
  Response D: "我不确定..."
  
  标注：A > C > B > D

Step 3: 训练奖励模型 (Reward Model)
  输入：(prompt, response) → 输出：一个分数
  训练目标：让 RM 的打分与人类排序一致
  损失函数：Pairwise Ranking Loss

Step 4: PPO 强化学习
  用 RM 作为奖励信号，用 PPO 算法优化 SFT Model
  同时加 KL 惩罚：模型不能偏离 SFT 太远（防止"作弊"）

  目标函数：
    max E[RM(prompt, response) - β × KL(π_RL || π_SFT)]
                ↑ 回答好             ↑ 别跑偏
```

### 4.3 PPO 算法简介

```text
PPO（Proximal Policy Optimization）= 近端策略优化

核心思想：
  每次更新时，限制新策略与旧策略的差异
  → 用 clipping 机制防止更新过大
  → 训练更稳定，是目前 RLHF 的主流算法

简化理解：
  → LLM 生成回答 → RM 打分 → 高分回答鼓励、低分回答抑制
  → 但不能一下子变得太多（KL 约束）
  → 循环 N 轮
```

## 5. RLAIF AI 对齐

```text
RLAIF = 用 AI 替代人类做偏好标注

流程对比：
  RLHF:  人类读回答 → 排序 → 训练 RM
  RLAIF: AI（如 GPT-4）读回答 → 排序 → 训练 RM

优势：
  ✅ 成本低，速度快
  ✅ 可扩展（AI 可以无限标注）
  ✅ 一致性高（人类标注存在主观差异）

劣势：
  ⚠️ AI 标注有偏差（偏好较长回答等）
  ⚠️ 需要宪法 AI（Constitutional AI）约束原则

代表：Claude 使用 Constitutional AI + RLAIF
```

## 6. 训练成本与 Scaling Law

### 6.1 典型训练成本

| 模型 | 参数量 | GPU | 训练时间 | 预估成本 |
|------|:---:|------|:---:|------|
| GPT-3 | 175B | 10,000 V100 | 数月 | ~$4.6M |
| LLaMA-65B | 65B | 2,048 A100 | 21 天 | ~$2M |
| LLaMA-2 70B | 70B | 2,000 A100 | ~30 天 | ~$3M |
| GPT-4 | ~1.8T(MoE) | ~25,000 A100 | 90-100 天 | ~$100M+ |

### 6.2 Scaling Law（缩放定律）

```text
Chinchilla Scaling Law（DeepMind, 2022）：

  最优训练：Token 数 ≈ 20 × 参数量

  即：10B 参数 → 200B token → 最优（不欠拟合不过拟合）

  常见误区：
  ❌ 参数越大越好
  ✅ 参数量和数据量要匹配增长

  LLaMA 系列的实践：
  → 用远超 Chinchilla 的 token 量训练小模型
  → LLaMA-7B 训了 1T token（远超 140B 的 Chinchilla 最优）
  → 结果：小模型 + 多数据 > 大模型 + 少数据
```

## 7. 数据预处理管线

```text
原始数据 → 可用训练数据：

① 数据收集
   网页抓取、书籍电子化、代码仓库爬取

② 去重
   MinHash / SimHash 检测重复文档 → 删除

③ 质量过滤
   - 语言检测（去除非目标语言）
   - 困惑度过滤（去掉低质量文本）
   - 规则过滤（长度、特殊符号比例）

④ 隐私清洗
   删除 PII（邮箱、电话、身份证号）

⑤ 分词
   BPE / SentencePiece → Tokenize → 生成 Token ID 序列

⑥ 打包
   将不同文档的 token 拼接，填满 context window
```

## 核心要点回顾

- LLM 训练三阶段：预训练（学知识）→ SFT（学指令）→ RLHF（学偏好）
- 预训练：万亿 token、千卡 GPU、自监督 Next-Token-Prediction
- SFT：高质量指令数据，教会模型"回答问题"而非"续写"
- RLHF：人类排序 → 训练 RM → PPO 优化 → 输出符合人类偏好
- Scaling Law：token 数 ≈ 20 × 参数量，数据比参数更稀缺
- RLAIF 用 AI 替代人类标注，成本和效率革命
