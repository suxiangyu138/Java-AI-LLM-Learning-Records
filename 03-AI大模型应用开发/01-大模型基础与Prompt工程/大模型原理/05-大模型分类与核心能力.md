## 1. 按训练阶段分类

```text
训练阶段决定了模型的"人格"：

Base Model（基座）
  → 预训练产物，只会续写
  → "解释Transformer"→"解释Transformer是一种..."（续写你的话）
  → 不适合直接使用

Instruct Model（指令模型）
  → Base + SFT 微调
  → "解释Transformer"→"Transformer是2017年..."（回答问题）
  → 能理解指令，但风格不稳定

Chat Model（对话模型）
  → Instruct + RLHF 对齐
  → 会聊天、会拒绝、输出风格统一
  → ⭐ 用户直接使用的形态
```

| 类型 | 训练阶段 | 行为特征 | 代表 |
|------|:---:|------|------|
| **Base** | 仅预训练 | 续写文本 | LLaMA-7B (base) |
| **Instruct** | +SFT | 遵循指令 | Qwen-7B-Instruct |
| **Chat** | +RLHF | 安全对话 | Qwen-7B-Chat, ChatGPT |

## 2. 按应用场景分类

### 2.1 五大类型

| 类型 | 说明 | 代表 |
|------|------|------|
| **通用大模型** | 面向广泛任务 | GPT-4、Claude、Qwen-Max |
| **代码大模型** | 代码生成/审查/补全 | CodeLlama、DeepSeek-Coder、Qwen-Coder |
| **数学/推理** | 复杂逻辑推理 | OpenAI o1、DeepSeek-R1 |
| **垂直领域** | 金融/医疗/法律/教育 | FinBERT、BioBERT、LawGPT |
| **Embedding 模型** | 文本转向量 | BGE-M3、Qwen-Embedding |

### 2.2 代码大模型独特性

```text
代码模型为什么单独训练？

✅ 代码有精确的语法和逻辑约束 → 和自然语言不同
✅ 代码有长距离依赖（函数调用、变量引用）→ 类似推理
✅ 预训练中加入代码 → 能显著提升通用推理能力
   → LLaMA 的实验：代码数据占 4.5%，但效果很明显

代表：
  CodeLlama (Meta): 基于 LLaMA-2 继续训练代码数据
  DeepSeek-Coder: 从头训练的代码大模型，1.3B~33B
  Qwen-Coder: 通义千问的代码版本
```

## 4. 按参数规模分类

| 级别 | 参数量 | 部署方式 | 代表 | 典型场景 |
|------|:---:|------|------|------|
| **超大** | >100B | 多机多卡集群 | GPT-4、Claude Opus | 云端 API |
| **大** | 30B~100B | 单机多卡（A100×4+） | Qwen-72B、LLaMA-70B | 企业私有化 |
| **中** | 7B~30B | 单卡（A100/4090） | Qwen-14B、LLaMA-13B | 本地微调 |
| **小** | <7B | CPU/消费级 GPU | Qwen-1.8B、Phi-3 | 端侧/嵌入式 |
| **MoE** | 总参大/激活少 | 灵活 | Mixtral 8×7B | 高效推理 |

### MoE（混合专家）详解

```text
MoE = Mixture of Experts

传统模型：
  每个 token 经过全部参数 → 大模型推理成本高

MoE 模型：
  总参数：100B（8 个专家 × 12.5B 每个）
  激活参数：~14B（每次只用 2 个专家）
  
  每个 token → 路由器选择最相关的 2 个专家 → 只激活 14B
  → 100B 模型的能力，14B 的推理成本

代表：
  Mixtral 8×7B: 总 46.7B, 激活 12.9B
  GPT-4:    总 ~1.8T (8×220B), 激活 ~280B
  Qwen-Max: 总 72B+, 激活 20B+
```

## 5. 核心能力指标

### 5.1 关键指标

| 指标 | 说明 | 典型值 |
|------|------|--------|
| **参数量** | 模型可训练参数总数 | 7B ~ 1.8T |
| **上下文窗口** | 单次可处理的最大 token 数 | 4K ~ 1M |
| **词表大小** | 可识别的 token 种类数 | 32K ~ 128K |
| **推理速度** | tokens/sec | 10 ~ 200 t/s |
| **MMLU 得分** | 多任务语言理解基准 | 60% ~ 90%+ |
| **HumanEval** | 代码生成能力基准 | 30% ~ 90%+ |

### 5.2 上下文窗口演进

```text
GPT-3 (2020):        2,048 tokens
GPT-3.5 (2022):      4,096 tokens  →  16K (GPT-3.5-turbo-16k)
GPT-4 (2023):        8K → 32K → 128K
Claude 3 (2024):     200K tokens
Gemini 1.5 (2024):   1M tokens（百万级！）
Qwen 2.5 (2024):     128K tokens

长上下文的代价：
  → Attention 计算量 O(n²)
  → 需要更多显存
  → KV Cache 也随长度线性增长

解决方案：
  → FlashAttention（减少显存读写）
  → Ring Attention（分布式长上下文）
  → RoPE 位置编码外推
```

### 5.3 Token 与成本

```text
Token 是 LLM 的计费基础单位

中文：1 个汉字 ≈ 1.5 ~ 2 token
英文：1 个单词 ≈ 1 ~ 2 token
代码：1 个字符 ≈ 0.3 ~ 0.5 token

价格示例（2024）：
  GPT-4o:      输入 $5/1M tokens, 输出 $15/1M tokens
  Claude Opus: 输入 $15/1M tokens, 输出 $75/1M tokens
  DeepSeek-V2: 输入 ¥1/1M tokens, 输出 ¥2/1M tokens ← 极低

一个典型对话（10轮 × 500 tokens）：消耗 ~5000 input + ~3000 output tokens
  GPT-4o: ~$0.07
  DeepSeek: ~¥0.011 (~$0.0015)
```

## 核心要点回顾

- 模型分级：Base（续写）→ Instruct（遵循指令）→ Chat（安全对话）
- 五大分类：通用、代码、推理、垂直、Embedding
- MoE 用"总参大+激活少"实现高性能低成本的平衡
- 上下文窗口从 2K 扩展到 1M，FlashAttention 是关键使能技术
- 选模型 = 选能力边界和成本边界的交集
