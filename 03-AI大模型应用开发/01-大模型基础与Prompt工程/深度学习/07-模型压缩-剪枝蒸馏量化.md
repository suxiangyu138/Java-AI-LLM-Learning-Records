## 1. 为什么需要模型压缩

```text
大模型部署的三大瓶颈：

  ① 显存：LLaMA-7B FP32 ≈ 28GB → 消费级显卡放不下
  ② 延迟：大模型推理慢 → 用户等不了
  ③ 功耗：数据中心电费惊人

压缩目标：
  减小模型体积 + 加快推理速度 + 尽量保持精度
```

## 2. 剪枝 Pruning

### 2.1 原理

```text
剪枝 = 删除模型中"不重要"的权重或结构

  非结构化剪枝 (Unstructured)：
    删除绝对值最小的权重 → 变成稀疏矩阵
    → 需要稀疏计算硬件支持

  结构化剪枝 (Structured)：
    删除整行/整列/整个通道
    → 直接变成更小的密集矩阵 → 通用硬件即可加速

LLM 中的剪枝：
  SparseGPT / Wanda：无需重训 → 一次性剪 50% 参数 → 精度损失 < 1%
```

### 2.2 剪枝流程

```text
剪枝三步法：

  ① 评估重要性：按权重大小 / 梯度 / Hessian 等指标排序
  ② 删除不重要的：设阈值 → 低于阈值的权重归零
  ③ 微调恢复：少量训练 → 恢复精度损失
     (或使用无需微调的方法：SparseGPT)

剪枝比例 vs 精度：
  10-20%：几乎无损
  30-50%：轻微损失
  50-70%：需微调恢复
```

## 3. 知识蒸馏 Knowledge Distillation

### 3.1 原理

```text
知识蒸馏 = 大模型（教师）教小模型（学生）

  教师模型 (Teacher)：大模型，精度高
  学生模型 (Student)：小模型，精度不够但快

蒸馏过程：
  ① 教师对训练数据生成"软标签"（概率分布，而非硬标签）
  ② 学生同时学习：硬标签（正确答案）+ 软标签（教师的"思考方式"）

  Loss = α × CE(学生输出, 硬标签) + (1-α) × KL(教师软标签, 学生输出)

为什么软标签有效？
  → 硬标签：只有正确答案是 1，其他是 0
  → 软标签：正确答案 0.9，相似答案也有概率
    → 学生学会了"哪些答案是相似的" → 泛化更好
```

### 3.2 LLM 蒸馏

```text
LLM 知识蒸馏：

  → GPT-4 → GPT-4o-mini（较小但保留大部分能力）
  → DeepSeek-R1 → 蒸馏出 7B/14B 推理模型
  → 教师模型生成高质量训练数据 → 学生模型微调

步骤：
  ① 用教师模型生成大量高质量回复
  ② 用这些回复 SFT 学生模型
  ③ 可选：再用教师的输出分布做 KL 蒸馏
```

## 4. 量化 Quantization

### 4.1 原理

```text
量化 = 将 FP32 参数映射到更低精度 (INT8/INT4)

  FP32：每个参数 32 位 → 7B模型 ≈ 28GB
  INT8：每个参数 8 位  → 7B模型 ≈ 7GB（减少 75%）
  INT4：每个参数 4 位  → 7B模型 ≈ 3.5GB（减少 87%）

量化参数 = 缩放因子 S + 零点 Z：
  q = round(x / S + Z)
  x' = S × (q - Z)  ← 近似值

精度损失：
  INT8：几乎无损 (<0.5%)
  INT4：轻微损失 (<2-3%)
  INT2：明显损失，不推荐
```

### 4.2 LLM 量化方法

| 方法 | 说明 | 需要校准数据 | 适用 |
|------|------|:---:|------|
| **GPTQ** | 逐层最优脑手术量化 | ✅ 需要 | GPU 推理 |
| **AWQ** | 激活感知量化 | ✅ 需要 | GPU 推理 |
| **GGUF** | llama.cpp 格式 | ❌ | CPU/混合推理 |
| **BitsAndBytes** | HuggingFace 集成 | ❌ | QLoRA 训练 |
| **SmoothQuant** | 平滑激活值 | ✅ 需要 | W8A8 量化 |

## 5. LLM 压缩实战

```text
LLM 压缩推荐组合：

  部署场景        → 剪枝 + 量化
  微调场景        → QLoRA（4-bit量化 + LoRA）
  追求精度        → 仅 INT8 量化
  极限压缩        → 剪枝(50%) + 蒸馏 + INT4量化
  本地部署(Ollama) → GGUF Q4_K_M 格式

常见压缩链：
  HuggingFace 模型 → GPTQ INT4 → 推理部署
  HuggingFace 模型 → GGUF Q4 → Ollama 本地运行
  HuggingFace 模型 → BitsAndBytes 4-bit → QLoRA 微调

对 Java 后端开发者：
  → 量化用 GGUF/Ollama（最简单）
  → 精度要求高用 GPTQ/AWQ（需 GPU）
```

## 核心要点回顾

- 剪枝 = 删除不重要权重 → 网络变稀疏/变小
- 蒸馏 = 大模型教小模型 → 保留"软知识"
- 量化 = FP32→INT8/INT4 → 显存/带宽大幅减少
- LLM 压缩三件套：SparseGPT(剪枝) + Distillation(蒸馏) + GPTQ(量化)
- 本地部署首选 GGUF Q4_K_M（效果/大小平衡最优）
