## 1. 浮点数与误差

### 1.1 浮点数的本质

```text
计算机用有限位数表示实数 → 必然有误差

IEEE 754 浮点数标准：
  FP32（单精度）：1 符号位 + 8 指数位 + 23 尾数位
  FP16（半精度）：1 + 5 + 10
  BF16（Brain Float）：1 + 8 + 7（与 FP32 指数相同，截断尾数）

能表示多少个数？
  FP32 能表示约 4×10⁹ 个不同的数
  → 但实数有无穷多个！
  → 大部分实数只能"近似"表示
```

### 1.2 经典浮点陷阱

```python
# 陷阱 1：0.1 + 0.2 ≠ 0.3
print(0.1 + 0.2)  # 0.30000000000000004！

# 原因：0.1 在二进制中是无限循环小数
# 0.1(10) = 0.0001100110011...(2) → 只能截断

# 陷阱 2：大数吃小数
a = 1e10
b = 1e-10
for _ in range(1000000):
    a += b
print(a - 1e10)  # 0.0！加了 100 万次但什么都没改变

# 原因：b << a 的精度范围 → b 被"吞掉"

# 陷阱 3：相减相消
x = 1.000000000000001
y = 1.000000000000000
print(x - y)  # 浮点结果精度很差
```

### 1.3 LLM 中的精度选择

| 精度 | 位数 | 7B 模型大小 | 适用场景 |
|------|:---:|------|------|
| **FP32** | 32 bit | 28 GB | 训练基准（已淘汰） |
| **FP16** | 16 bit | 14 GB | 推理常用 |
| **BF16** | 16 bit | 14 GB | **训练标配**（动态范围大） |
| **INT8** | 8 bit | 7 GB | 推理加速（轻微损失） |
| **INT4** | 4 bit | 3.5 GB | 本地部署（QLoRA 用） |

```text
BF16 vs FP16 — 为什么 LLM 训练用 BF16？

  FP16: 指数 5 位 → 范围 [6e-8, 65504]  → 容易溢出！
  BF16: 指数 8 位 → 范围 [1e-38, 3e38] → 与 FP32 相同

  BF16 牺牲了尾数精度（7 vs 10 位），但保留了 FP32 的动态范围
  → 对大模型训练来说，动态范围比精度更重要
```

## 2. 数值稳定性

### 2.1 Softmax 的数值稳定实现

```python
import numpy as np

# 不稳定的实现
def softmax_unstable(x):
    exp_x = np.exp(x)  # 如果 x 很大 → exp 溢出 → inf
    return exp_x / exp_x.sum()

# 稳定的实现
def softmax_stable(x):
    x_max = np.max(x)              # 减去最大值
    exp_x = np.exp(x - x_max)      # 最大值变成 exp(0)=1，不会溢出
    return exp_x / exp_x.sum()

# 测试
x = np.array([1000, 1000, 1000])
# softmax_unstable(x)  # 溢出！ RuntimeWarning: overflow
print(softmax_stable(x))  # [0.333, 0.333, 0.333] ✅
```

### 2.2 交叉熵的数值稳定实现

```python
# PyTorch 的 CrossEntropyLoss 内置了数值稳定技巧
# 内部实现 ≈ log_softmax + nll_loss

# 不稳定：先算 softmax 再算 log
def cross_entropy_unstable(logits, target):
    probs = softmax_unstable(logits)   # 可能溢出
    return -np.log(probs[target])      # log(0) → -inf

# 稳定：log_softmax 融合
def log_softmax(x):
    x_max = np.max(x)
    return x - x_max - np.log(np.sum(np.exp(x - x_max)))
    # 等价于 log(softmax(x))，但数值稳定
```

### 2.3 其他常见数值稳定性技巧

| 问题 | 解决方案 |
|------|---------|
| $\exp(x)$ 溢出 | 减去 max(x) |
| $\log(0)$ → -inf | 加小量 $\epsilon$ (1e-7~1e-10) |
| $\sqrt{x}$ (x<0) | `sqrt(max(x, 0))` 或加 $\epsilon$ |
| $x/y$ (y=0) | 加 $\epsilon$ 或梯度裁剪 |
| 梯度消失 | 使用 ReLU/GELU 代替 Sigmoid |
| 梯度爆炸 | 梯度裁剪 `clip_grad_norm_` |

## 3. 矩阵数值计算

### 3.1 矩阵求逆的代价

```text
矩阵求逆的复杂度：O(n³)

  n=100   → 10⁶ 次运算  → 瞬间
  n=1000  → 10⁹ 次运算  → 秒级
  n=10000 → 10¹² 次运算 → 小时级
  n=4096  → LLaMA 的 d_model → 求解一个线性方程尚且昂贵

LLM 为什么不求逆：
  ❌ 权重矩阵几千维 → 求逆代价 O(n³) → 无法承受
  ✅ 用迭代优化（梯度下降）代替直接求解
  ✅ AdamW 避免二阶优化（不需要海森逆矩阵）
```

### 3.2 矩阵分解的数值方法

| 分解 | 复杂度 | 用途 |
|------|:---:|------|
| **SVD** | O(mn²) | PCA 降维、LoRA 分析、推荐系统 |
| **QR 分解** | O(n³) | 线性方程求解、最小二乘 |
| **Cholesky 分解** | O(n³/3) | 对称正定矩阵的加速求解 |
| **LU 分解** | O(n³/3) | 方阵求逆 |

### 3.3 条件数与病态问题

```text
矩阵的条件数 κ(A) = |A| × |A⁻¹|

  κ 小（接近1）：良态 → 数值求解稳定
  κ 大（>>1）： 病态 → 小误差被放大

LLM 中的体现：
  → 权重矩阵的条件数影响训练稳定性
  → 条件数大 → 梯度更新方向不可靠
  → 权重初始化、LayerNorm 等方法帮助控制条件数
```

## 4. 迭代求解与收敛

### 4.1 梯度下降就是迭代法

```text
梯度下降是一个迭代求解器：

  θ_{k+1} = θ_k - η × ∇L(θ_k)

  迭代停止条件：
    ✅ |θ_k - θ_{k-1}| < 阈值（参数不再变化）
    ✅ |∇L(θ_k)| < 阈值（梯度接近零）
    ✅ Loss 不再下降
    ✅ 达到最大迭代次数
```

### 4.2 收敛诊断

```python
# 训练时的收敛监控
def train_step(model, batch, optimizer):
    loss = model(batch)
    optimizer.zero_grad()
    loss.backward()
    
    # 梯度范数 → 衡量收敛程度
    grad_norm = sum(p.grad.norm() for p in model.parameters())
    
    # 梯度裁剪（数值稳定性）
    torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
    
    optimizer.step()
    return loss.item(), grad_norm

# 正常收敛：loss ↓, grad_norm ↓（逐渐减小）
# 发散：loss ↑, grad_norm ↑ → 学习率太大
# 停滞：loss 不变, grad_norm 小 → 收敛到局部最优点或鞍点
```

## 5. LLM 推理中的数值问题

### 5.1 FlashAttention 的数值技巧

```text
FlashAttention 需要兼容的数值技巧：

  分块计算 softmax 时，每块无法知道全局 max
  → 在线 softmax（online softmax）：
    逐块计算，动态更新 max 和 sum
    通过对已计算部分的"修正"实现全局效果

这一技巧让 FlashAttention 在保持数值稳定的前提下
大幅减少了 HBM 读写量 → 速度提升 2~4×
```

### 5.2 KV Cache 的数值累积

```text
KV Cache 存储大量的 Key 和 Value 向量

量化 KV Cache：
  → KV Cache 占用大量显存（长序列时超过模型权重）
  → 用 INT8/INT4 量化 KV Cache
  → 关键：量化策略必须数值稳定，否则逐 token 误差累积 → 输出崩溃
```

### 5.3 半精度训练的注意事项

```text
FP16/BF16 混合精度训练：

  → 权重用 FP32 存储（master copy）
  → 前向传播用 FP16/BF16（加速）
  → 反向传播的梯度用 FP16/BF16
  → 梯度更新时将 FP16 梯度加到 FP32 权重上

  Loss Scaling（FP16 必需）：
  FP16 能表示的最小正数 ≈ 6e-8
  → 梯度可能下溢 → 乘以一个大数（如 1024）再反向传播
  → 更新权重前再除回去

  BF16 不需要 Loss Scaling（动态范围与 FP32 相同）
```

## 6. Java 中的数值计算

```java
// Java 中的浮点精度
double a = 0.1;
double b = 0.2;
System.out.println(a + b);  // 0.30000000000000004  ← 同样的问题

// BigDecimal → 精确小数（金融计算）
BigDecimal bd = new BigDecimal("0.1").add(new BigDecimal("0.2"));
System.out.println(bd);  // 0.3 ✅

// 但是在 AI 推理中 → BigDecimal 太慢 → 必须用 float/double
```

### 6.2 模型推理的数值验证

```java
// 比较 PyTorch 导出模型和 Java 推理结果
public class NumericalVerify {
    // 由于硬件/库的差异，结果不会完全一致
    public boolean verify(float[] pythonOutput, float[] javaOutput) {
        double maxDiff = 0;
        for (int i = 0; i < pythonOutput.length; i++) {
            maxDiff = Math.max(maxDiff, Math.abs(pythonOutput[i] - javaOutput[i]));
        }
        // 允许的误差范围（FP32 推理通常 < 1e-4）
        return maxDiff < 1e-4;
    }
}
```

## 核心要点回顾

- 浮点数有精度限制 → 0.1+0.2≠0.3，大数吃小数，相减相消
- Softmax 和交叉熵需要数值稳定实现（减去最大值）
- BF16 保留 FP32 的动态范围，是 LLM 训练标配
- 梯度裁剪、Loss Scaling 是混合精度训练的必备技巧
- 对 Java 后端开发者：理解浮点误差来源，知道数值稳定性的概念即可
