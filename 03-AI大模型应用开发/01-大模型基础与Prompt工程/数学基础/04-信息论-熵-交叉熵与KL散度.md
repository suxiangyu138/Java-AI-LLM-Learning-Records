## 1. 信息量：量化"信息"

### 1.1 定义与直觉

```text
自信息量（Self-Information）：

  I(x) = -log P(x)

直觉——"越不可能发生的事件，信息量越大"：

  "太阳从东边升起"    → P ≈ 1.0  → I ≈ 0     → 废话
  "今天下雨了"         → P = 0.3  → I = 1.74  → 有些信息量
  "中彩票头奖了"       → P ≈ 10⁻⁸ → I = 26.6  → 爆炸性新闻

单位：
  log₂ → bit（比特）
  logₑ → nat（奈特）
  NLP/LLM 常用 nat（因为与 e 的数学性质配合更好）
```

### 1.2 对数底的选择

| 底 | 单位 | 使用场景 |
|:---:|------|------|
| **2** | bit | 通信理论、信息压缩 |
| **e** | nat | **LLM/NLP 领域标准**（PyTorch 的 CrossEntropyLoss 默认用 e） |
| **10** | hartley | 几乎没有 |

```python
import torch

# PyTorch 的交叉熵默认用自然对数（底 e）
loss = torch.nn.CrossEntropyLoss()  # 内部用 log_e
```

## 2. 熵：不确定性的度量

### 2.1 定义

```text
熵（Entropy）= 信息量的期望值

  H(X) = E[I(x)] = -Σ P(x) log P(x)

直觉：
  熵 = 系统的"不确定性"或"混乱程度"

  → H 大 = 很混乱，难以预测
  → H 小 = 很确定，容易预测

极端情况：
  确定分布 P = [1, 0, 0, 0] → H = -1×log(1) = 0（完全确定）
  均匀分布 P = [0.25, 0.25, 0.25, 0.25] → H = log(4) ≈ 1.39（最大不确定性）
```

### 2.2 计算示例

```python
import numpy as np

def entropy(probs):
    """计算概率分布的熵（单位：nat）"""
    # 过滤掉 0 概率项（0 × log(0) = 0）
    probs = probs[probs > 0]
    return -np.sum(probs * np.log(probs))

# 确定分布 → 低熵
print(f"确定分布: {entropy(np.array([1.0, 0.0, 0.0, 0.0])):.4f}")   # 0.0000

# 中等分布 → 中熵
print(f"中等分布: {entropy(np.array([0.5, 0.3, 0.1, 0.1])):.4f}")   # 1.0889

# 均匀分布 → 最大熵
print(f"均匀分布: {entropy(np.array([0.25, 0.25, 0.25, 0.25])):.4f}") # 1.3863
```

### 2.3 熵在 LLM 中的应用

| 应用 | 说明 |
|------|------|
| **模型评估** | 熵越低 → 模型对下一个 token 越"确定" → 通常越好 |
| **数据筛选** | 训练数据中高熵文本 → 可能是噪声 → 清洗掉 |
| **熵校准** | 模型的熵应该与准确率正相关 → 熵高时应说"我不确定" |
| **Beam Search** | 用熵/困惑度评估生成路径好坏 |

## 3. 交叉熵：两大分布的距离

### 3.1 定义

```text
交叉熵（Cross-Entropy）：

  H(p, q) = -Σ p(x) × log q(x)

  p = 真实分布（标签）
  q = 预测分布（模型输出）

直觉：
  用分布 q 来"编码"分布 p → 表示的"效率"
  
  q 在 p 概率大的地方概率也大 → log q(x) 接近 0 → 交叉熵小 ✅
  q 在 p 概率大的地方概率小 → log q(x) 很负 → 交叉熵大 ❌
```

### 3.2 LLM 训练中的交叉熵

```text
LLM 训练每一步 = 计算交叉熵损失

  上下文: "The cat sat on the"
  真实下一个 token: "mat"（词表中 ID=3847）
  
  p = [0, 0, ..., 1(位置3847), ..., 0]  ← one-hot 向量
  
  模型输出 logits → Softmax → q
  
  Loss = -log q[3847]  ← 交叉熵在 one-hot 标签下的简化形式

训练目标：
  最小化 Loss → 最大化 q[3847] → 模型越来越"确定"正确答案
```

```python
import torch
import torch.nn.functional as F

# 模拟 LLM 的一个训练 step
vocab_size = 50000
logits = torch.randn(1, vocab_size)   # 模型输出的 raw logits
target = torch.tensor([3847])          # 正确答案的 token ID

# 交叉熵损失
loss = F.cross_entropy(logits, target)  # 内部自动做 softmax + nll
print(f"Loss: {loss.item():.4f}")
```

### 3.3 为什么交叉熵优于 MSE

```text
分类任务中交叉熵 vs MSE：

交叉熵 + Softmax 输出的梯度：
  ∂L/∂zᵢ = qᵢ - pᵢ  ← 简洁！预测 - 真实
  
MSE + Softmax 输出的梯度：
  ∂L/∂zᵢ = 2(qᵢ - pᵢ) × qᵢ(1 - qᵢ)  ← sigmoid 导数项导致梯度饱和
  
结论：
  ✅ 交叉熵的梯度线性 → 训练快，不饱和
  ❌ MSE + Softmax 组合易饱和 → 训练慢
```

## 4. KL 散度：非对称分布差异

### 4.1 定义

```text
KL 散度（Kullback-Leibler Divergence）：

  KL(P || Q) = Σ P(x) × log(P(x) / Q(x))

  = Σ P(x) log P(x) - Σ P(x) log Q(x)
  = -H(P) + H(P, Q)

直觉：
  用分布 Q 来"近似"分布 P → 丢失了多少信息
  → KL 散度越小，Q 越接近 P

非对称性（重要！）：
  KL(P || Q) ≠ KL(Q || P)
  
  KL(true || model) → "模型要覆盖真实分布的所有模式" → 追求 recall
  KL(model || true) → "模型不要超出真实分布" → 追求 precision
```

### 4.2 KL 散度在 RLHF 中的核心作用

```text
RLHF 的目标函数：

  max E[Reward Model(回答)] - β × KL(π_RL || π_SFT)
      └── 回答质量好 ──┘       └── 但不要偏离太远 ──┘

为什么需要 KL 散度约束？

没有 KL 约束时：
  → RL 优化器学会"作弊"
  → 生成"asdfghjkl"→ Reward Model 误判高分（RM 有缺陷）
  → 或生成过度谄媚的回答 → RM 喜欢但用户不喜欢
  → 模型崩溃（Reward Hacking）

加上 KL 约束后：
  → π_RL 不能偏离 π_SFT 太远
  → 保证回答仍然"像人话"
  → β 控制约束强度：大=保守，小=激进
```

### 4.3 已知分布间的 KL 散度

```python
import numpy as np

def kl_divergence(p, q):
    """KL(P || Q)"""
    # 过滤掉 p=0 的项
    mask = p > 0
    return np.sum(p[mask] * np.log(p[mask] / q[mask]))

# 例子：模型预测 vs 真实标签
p_true = np.array([0.9, 0.05, 0.05])  # 真实：高度确定
q_good = np.array([0.8, 0.1,  0.1 ])  # 好的预测
q_bad  = np.array([0.3, 0.35, 0.35])  # 差的预测

print(f"KL(true || good): {kl_divergence(p_true, q_good):.4f}")  # 0.025
print(f"KL(true || bad):  {kl_divergence(p_true, q_bad):.4f}")   # 1.017
```

### 4.4 KL 散度在模型蒸馏中的应用

```text
知识蒸馏（Knowledge Distillation）：

  教师模型（大）→ 产生软标签 q_teacher（概率分布，不是硬标签）
  学生模型（小）→ 学习匹配教师的输出分布

  Loss = α × CrossEntropy(学生输出, 硬标签)
       + (1-α) × T² × KL(教师输出/T || 学生输出/T)
              └── 温度 T 软化分布，让学生学习"暗知识" ──┘
```

## 5. 交叉熵 vs KL 散度的关系

### 5.1 核心恒等式

```text
  H(p, q) = H(p) + KL(p || q)

  交叉熵 = 真实分布的熵 + KL 散度

推导：
  H(p, q) = -Σ p log q
          = -Σ p log p + Σ p log p - Σ p log q
          = H(p) + Σ p log(p/q)
          = H(p) + KL(p || q)
          └─┬─┘   └────┬────┘
          固定常数   可优化的部分

→ 最小化交叉熵 = 最小化 KL 散度（对于固定 p）
```

### 5.2 PP（困惑度）与信息论

```text
困惑度 Perplexity = exp(交叉熵)

  PPL = exp(H(p, q)) = exp(-1/N × Σ log P(w_t | w_{<t}))

PPL 的直觉：
  → 模型看到上文后，平均要从多少个选项中"猜"下一个词
  → PPL=10 → 平均 10 选 1 → 不错
  → PPL=100 → 平均 100 选 1 → 较差

PPL 与熵的关系：
  如果模型完美 → q=p → H(p,q)=H(p) → PPL = exp(H(p))
  即：最优模型的困惑度 = 真实语言的熵
  → 这是语言的"不可压缩性"下限
```

## 6. 联合熵、条件熵与互信息

### 6.1 定义

```text
联合熵：H(X, Y) = -Σ P(x, y) log P(x, y)
  → 两个随机变量一起的"总不确定性"

条件熵：H(Y | X) = -Σ P(x, y) log P(y | x)
  → 已知 X 后，Y 还剩多少不确定性
  → NLP：已知上文后，下一个词的"平均不确定性"

互信息：I(X; Y) = H(X) + H(Y) - H(X, Y)
                = H(Y) - H(Y | X)
  → X 减少了 Y 多少不确定性
  → NLP：上下文"提供了多少关于下一个词的信息"
```

### 6.2 互信息在 NLP 中的应用

```text
语言建模视角：
  I(上文; 下一个词) = H(下一个词) - H(下一个词 | 上文)

  H(下一个词)：词表中每个词的概率均匀吗？→ 很大
  H(下一个词|上文)：给定上下文后模型有多确定？→ 越小越好

  → 好的语言模型让 H(下一个词|上文) 尽量小
  → 即：I(上文; 下一个词) 尽量大（上下文提供了大量信息）
```

## 7. LLM 中的信息论全景

| 概念 | 公式 | LLM 中的应用 |
|------|------|------------|
| **信息量** | $-\log P(x)$ | 事件的重要程度 |
| **熵** | $-\sum P \log P$ | 模型的不确定性校准 |
| **交叉熵** | $-\sum P \log Q$ | **训练的损失函数** |
| **KL 散度** | $\sum P \log(P/Q)$ | **RLHF 对齐约束**、知识蒸馏 |
| **困惑度** | $\exp(\text{CE})$ | **评估模型质量的核心指标** |
| **互信息** | $I(X;Y)=H(Y)-H(Y\|X)$ | 特征选择、表示学习 |

```text
LLM 生命周期中的信息论：

  ① 预训练：
     Loss = CrossEntropy(pred, target)
     → 最小化交叉熵 → 最大化似然

  ② RLHF 对齐：
     Reward = RM_score - β × KL(π_new || π_old)
     → KL 散度约束防止模型"变味"

  ③ 评估：
     PPL = exp(CrossEntropy)
     → 低困惑度 = 好模型

  ④ 蒸馏：
     Loss = CE(硬标签) + KL(教师 || 学生)
     → KL 散度传递教师知识
```

## 核心要点回顾

- 熵 H(P) = 系统的不确定性；交叉熵 H(P,Q) = 用 Q 表示 P 的代价
- LLM 训练 = 最小化交叉熵 = 最大化对数似然
- KL 散度 = RLHF 的灵魂 — 防止模型在强化学习阶段"跑偏"
- 困惑度 PPL = 模型质量的黄金指标，越低越好
- 交叉熵的梯度比 MSE 更好 → 这是分类任务不用 MSE 的数学原因
