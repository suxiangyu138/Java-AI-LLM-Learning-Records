## 1. 什么是机器学习

### 1.1 经典定义

```text
Tom Mitchell (1997)：
  "A computer program is said to learn from experience E
   with respect to some class of tasks T and performance
   measure P, if its performance at tasks in T, as measured
   by P, improves with experience E."

三要素：
  T (Task)：要解决的任务（分类、回归、聚类）
  E (Experience)：训练数据
  P (Performance)：评估指标（准确率、F1、RMSE）
```

### 1.2 与传统编程的区别

```text
传统编程：
  数据 + 规则 → 程序 → 输出
  例：if x > 0.5 → "猫" else → "狗"（人工写规则）

机器学习：
  数据 + 输出 → 程序（模型）→ 新数据 → 预测
  例：1000 张标注图片 → 训练模型 → 新图片 → 自动判断猫狗

核心转变：机器从数据中自动发现规则，而非人工编写规则
```

## 2. 三大学习范式

### 2.1 监督学习

```text
监督学习：每个训练样本都有标签

分类（离散标签）：
  输入："这封邮件包含..."  →  输出：spam / not spam
  算法：逻辑回归、决策树、SVM、神经网络

回归（连续值）：
  输入："房子面积 100㎡，3 室 2 厅"  →  输出：500 万
  算法：线性回归、决策树回归、XGBoost

LLM 训练本质是监督学习：
  输入：上文 → 输出：下一个 token（标签就是语料中真实的 next token）
```

### 2.2 无监督学习

```text
无监督学习：训练样本没有标签，机器自己找结构

聚类：
  输入：10 万用户行为数据（无标签）→ 输出：5 个用户群
  算法：K-Means、DBSCAN、层次聚类

降维：
  输入：768 维 Embedding 向量 → 输出：2 维（可视化）
  算法：PCA、t-SNE、UMAP

LLM 中的无监督学习：
  → 预训练本质是自监督（输入=标签），介于监督和无监督之间
  → Embedding 的对比学习也属于自监督
```

### 2.3 强化学习

```text
强化学习：Agent 在环境中试错，通过奖励信号学习

  状态 → 动作 → 奖励 → 新状态 → ...

  核心：在延迟奖励下学习最优策略

LLM 中的应用：
  → RLHF：Reward Model 提供奖励 → PPO 优化 LLM 策略
```

### 2.4 三种范式对比

| 维度 | 监督学习 | 无监督学习 | 强化学习 |
|------|:---:|:---:|:---:|
| **数据标签** | ✅ 有 | ❌ 无 | 环境反馈 |
| **目标** | 学习输入→输出映射 | 发现数据结构 | 最大化长期奖励 |
| **典型任务** | 分类、回归 | 聚类、降维 | 游戏、机器人、RLHF |
| **LLM 中** | SFT 微调 | 预训练（自监督） | RLHF 对齐 |

## 3. 训练-验证-测试分割

### 3.1 为什么需要分割

```text
如果只用训练集评估模型：
  → 模型背下所有训练数据 → 准确率 100%
  → 新数据上 → 准确率 60% → 过拟合！

必须用模型从未见过的数据来评估 → 测试集
```

### 3.2 标准分割

```text
数据集分割（典型比例）：

  训练集 (Train)：  60-80%  → 用来训练模型参数
  验证集 (Val)：    10-20%  → 用来调超参数、选模型
  测试集 (Test)：   10-20%  → 最终评估，只能用一次！

原则：
  ✅ 测试集在整个开发过程中只能使用一次（最终评估）
  ✅ 用验证集做模型选择和超参数调优
  ❌ 绝不根据测试集结果回头调模型（数据泄露）
```

### 3.3 交叉验证

```python
from sklearn.model_selection import cross_val_score, KFold
from sklearn.ensemble import RandomForestClassifier

# K 折交叉验证 — 小数据集必备
model = RandomForestClassifier()
kfold = KFold(n_splits=5, shuffle=True)

scores = cross_val_score(model, X, y, cv=kfold, scoring='accuracy')
print(f"5 折 CV 准确率: {scores.mean():.3f} ± {scores.std():.3f}")

# 为什么用交叉验证？
# → 小数据集单次划分不稳定（划分方式影响结果）
# → K 折平均更可靠
```

## 4. 偏差与方差

### 4.1 核心定义

```text
偏差 (Bias)：模型预测值与真实值的"系统性偏离"
  → 高偏差 = 模型太简单 → 欠拟合
  → 例：用直线拟合抛物线 → 永远拟合不好

方差 (Variance)：模型对训练数据微调的"敏感度"
  → 高方差 = 模型太复杂 → 过拟合
  → 例：20 次多项式拟合 10 个点 → 完美拟合训练数据但泛化差
```

### 4.2 偏差-方差权衡

```text
                ┌── 欠拟合 ──┬── 最佳 ──┬── 过拟合 ──┐
                │            │          │            │
  Bias          │   高        │   中     │    低      │
  Variance      │   低        │   中     │    高      │
  Train Error   │   高        │   低     │   极低     │
  Test Error    │   高        │   低     │    高      │
                │            │          │            │
  模型复杂度：   简单 ←──────────────────────────→ 复杂

关键：最小化 Test Error → 找到偏差和方差的最佳平衡点
```

```python
# 学习曲线 — 判断偏差/方差
from sklearn.model_selection import learning_curve

train_sizes, train_scores, val_scores = learning_curve(
    model, X, y, cv=5, train_sizes=np.linspace(0.1, 1.0, 10)
)

# 高偏差（欠拟合）→ train 和 val 误差都高且接近
# 高方差（过拟合）→ train 误差低但 val 误差高（大 gap）
# 正常 → train 和 val 误差都低且接近
```

## 5. 特征工程基础

| 技术 | 说明 | 示例 |
|------|------|------|
| **归一化** | 缩放到 [0, 1] | MinMaxScaler |
| **标准化** | 均值 0 方差 1 | StandardScaler → LLM 的 LayerNorm |
| **One-Hot 编码** | 类别→向量 | 颜色：红→[1,0,0] |
| **缺失值处理** | 填充/删除 | 均值填充、中位数填充 |
| **特征交叉** | 组合特征 | 年龄×收入 → 新特征 |

> 💡 深度学习（LLM）的优势之一就是自动特征提取，不需要人工做特征工程。

## 6. ML 与 LLM 的关系

```text
LLM 的核心技术都源于 ML/DL：

  ML 概念              →  LLM 中的对应
  ─────────────────────────────────
  监督学习              →  SFT 微调
  自监督学习            →  预训练 (Next Token Prediction)
  强化学习              →  RLHF 对齐
  交叉验证              →  LLM 评估 (Holdout 验证集)
  过拟合                →  模型背答案、灾难性遗忘
  偏差-方差权衡         →  模型大小 vs 泛化能力
  梯度下降              →  LLM 训练的根本算法
  交叉熵                →  LLM 训练损失函数
```

## 核心要点回顾

- 机器学习 = 从数据中自动学习规律，取代人工编写规则
- 三大范式：监督（有标签）、无监督（无标签）、强化（环境反馈）
- 训练/验证/测试分割是防止过拟合的第一道防线
- 偏差 = 欠拟合，方差 = 过拟合，目标是 Total Error 最小
- LLM 是 ML/DL 的集大成者 — 几乎所有 ML 概念都能在 LLM 中找到对应
