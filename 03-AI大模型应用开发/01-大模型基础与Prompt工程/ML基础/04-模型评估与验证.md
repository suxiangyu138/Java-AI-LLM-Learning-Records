## 1. 分类评估指标

### 1.1 准确率及其陷阱

```text
准确率 Accuracy = 正确预测数 / 总样本数

陷阱：类别不平衡时准确率有误导性

  例：100 个样本中 95 个正类、5 个负类
  模型全部预测为"正类" → 准确率 95%！
  → 但对 5 个负类一个都没识别 → 模型没用

结论：类别不平衡时，只看准确率 = 自欺欺人
```

### 1.2 精确率与召回率

```text
Precision（精确率）= TP / (TP + FP)
  → 预测为正的样本中，真正为正的比例
  → "宁可漏掉，不可错杀"

Recall（召回率）= TP / (TP + FN)
  → 所有真实正样本中，被正确识别的比例
  → "宁可错杀，不可漏掉"

F1-Score = 2 × P × R / (P + R)
  → 精确率和召回率的调和平均
  → 两者同等重要时的综合指标

TP = 预测正、实际正   FP = 预测正、实际负
FN = 预测负、实际正   TN = 预测负、实际负
```

```text
场景选择：
  垃圾邮件过滤 → 高 Precision（正常邮件不能误杀）
  癌症筛查 → 高 Recall（病人不能漏诊）
  通用分类 → F1-Score
```

## 2. 混淆矩阵与衍生指标

### 2.1 混淆矩阵

```python
from sklearn.metrics import confusion_matrix, classification_report

y_true = [0, 1, 0, 1, 1, 0, 1, 0, 1, 0]
y_pred = [0, 1, 1, 1, 0, 0, 1, 0, 1, 0]

cm = confusion_matrix(y_true, y_pred)
print(cm)
# [[4 1]    ← 实际 0：4 个预测正确，1 个预测为 1
#  [1 4]]   ← 实际 1：1 个预测为 0，4 个预测正确

# 完整报告
print(classification_report(y_true, y_pred, target_names=['负类', '正类']))
#               precision    recall  f1-score   support
#        负类       0.80      0.80      0.80         5
#        正类       0.80      0.80      0.80         5
#     accuracy                           0.80        10
```

### 2.2 各指标速查

| 指标 | 公式 | 含义 | 关注场景 |
|------|------|------|----------|
| Accuracy | (TP+TN)/Total | 整体正确率 | 类别均衡 |
| Precision | TP/(TP+FP) | 预测为正中有多少对 | 误报代价高 |
| Recall | TP/(TP+FN) | 真实正中有多少被找到 | 漏报代价高 |
| F1 | 2PR/(P+R) | P 和 R 的调和平均 | 通用 |
| Specificity | TN/(TN+FP) | 真实负中有多少被找到 | 配合 Recall |

## 3. ROC 曲线与 AUC

### 3.1 ROC 曲线

```text
ROC 曲线 = 在不同阈值下画 TPR vs FPR

  TPR (True Positive Rate) = Recall = TP/(TP+FN)
  FPR (False Positive Rate) = FP/(FP+TN)

  阈值 = 0：全部判正 → TPR=1, FPR=1 → 右上角
  阈值 = 1：全部判负 → TPR=0, FPR=0 → 左下角
  
  → 曲线越靠近左上角越好
```

```python
from sklearn.metrics import roc_curve, roc_auc_score

# 计算 ROC
fpr, tpr, thresholds = roc_curve(y_true, y_scores)
auc = roc_auc_score(y_true, y_scores)

print(f"AUC: {auc:.3f}")  # 0.5=随机, 0.8=不错, 0.9+=优秀
```

### 3.2 AUC 的含义

```text
AUC (Area Under Curve) = ROC 曲线下面积

直观理解：
  随机抽取一个正样本和一个负样本
  AUC = 模型给正样本打分高于负样本的概率

  AUC = 1.0 → 完美分类
  AUC = 0.9 → 优秀
  AUC = 0.7 → 一般
  AUC = 0.5 → 和随机猜一样
  AUC < 0.5 → 比随机猜还差（反向预测）
```

## 4. 回归评估指标

| 指标 | 公式 | 特点 |
|------|------|------|
| **MSE** | $\frac{1}{n}\sum(y-\hat{y})^2$ | 惩罚大误差（平方） |
| **RMSE** | $\sqrt{\text{MSE}}$ | 与原数据同单位 |
| **MAE** | $\frac{1}{n}\sum\|y-\hat{y}\|$ | 对异常值不敏感 |
| **R²** | $1 - \frac{\text{SSE}}{\text{SST}}$ | 越接近 1 越好 |

```text
选择：
  → 异常值敏感 → MAE
  → 大误差要严惩 → MSE
  → 向业务解释 → RMSE（单位一致）
```

## 5. 交叉验证策略

### 5.1 三种 CV 策略

| 策略 | 原理 | 适用 |
|------|------|------|
| **K-Fold** | 分 K 份，轮流做验证集 | 通用 |
| **Stratified K-Fold** | 保持每折类别比例 | **分类任务首选** |
| **Time Series Split** | 用过去预测未来 | 时间序列 |

```python
from sklearn.model_selection import StratifiedKFold, cross_validate

skf = StratifiedKFold(n_splits=5, shuffle=True)
scores = cross_validate(model, X, y, cv=skf, 
                        scoring=['accuracy', 'f1', 'roc_auc'])

print(f"Accuracy: {scores['test_accuracy'].mean():.3f}")
print(f"F1:       {scores['test_f1'].mean():.3f}")
print(f"AUC:      {scores['test_roc_auc'].mean():.3f}")
```

### 5.2 为什么 LLM 不做交叉验证

```text
LLM 训练的特殊性：
  ❌ 训练一次耗时数周/数月 → 5 折 = 5 次训练 → 不可能
  ❌ 数十亿参数 → 多次训练成本无法承受
  
  LLM 的做法：
  ✅ 一次划分：Train / Val / Test 固定分割
  ✅ 用 Val 集调超参数，Test 集最终评估（只用一次）
  ✅ 多 benchmark 综合评估（MMLU、HumanEval...）
```

## 6. LLM 评估的特殊性

### 6.1 传统 ML vs LLM 评估

| 维度 | 传统 ML | LLM |
|------|---------|-----|
| **任务** | 单一任务 | 通用任务 |
| **评估** | Accuracy/F1/AUC | MMLU/HumanEval/MT-Bench |
| **验证** | 交叉验证 | 单次 Holdout |
| **主观性** | 客观对错 | 有主观成分（风格/创意） |

### 6.2 LLM 常用评估指标

| 指标 | 衡量什么 | 类型 |
|------|----------|:---:|
| **MMLU** | 多领域知识理解 | 客观 |
| **HumanEval** | 代码生成正确率 | 客观 |
| **MT-Bench** | 多轮对话质量（GPT-4 打分） | 主观 |
| **Perplexity** | 语言建模质量 | 客观 |
| **Chatbot Arena** | 人类偏好投票 | 主观 |

---

## 核心要点回顾

- 类别不均衡 → 不用 Accuracy → 用 F1 / AUC
- ROC-AUC = 模型给正样本打分高于负样本的概率
- 分类 CV 用 StratifiedKFold，时序用 TimeSeriesSplit
- LLM 不适用传统 CV（训练太贵），用多 benchmark 综合评估
- Precision 关心"预测对了多少"，Recall 关心"找到了多少"
