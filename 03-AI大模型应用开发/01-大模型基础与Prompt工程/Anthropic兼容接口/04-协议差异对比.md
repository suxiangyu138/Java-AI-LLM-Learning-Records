## 1. 请求结构对比

### 1.1 整体结构

| 维度 | Anthropic Messages API | OpenAI Chat Completions |
|------|----------------------|------------------------|
| 端点 | `POST /v1/messages` | `POST /v1/chat/completions` |
| 认证 | `x-api-key` Header | `Authorization: Bearer` Header |
| 版本 | `anthropic-version` Header | URL 路径版本控制（无独立头） |
| 请求体根字段 | `messages`, `system` 分开 | `messages` 内包含 system role |

### 1.2 System Prompt 差异

**Anthropic**（独立字段）：

```json
{
  "system": "You are a helpful assistant.",
  "messages": [
    {"role": "user", "content": "Hello"}
  ]
}
```

**OpenAI**（messages 内）：

```json
{
  "messages": [
    {"role": "system", "content": "You are a helpful assistant."},
    {"role": "user", "content": "Hello"}
  ]
}
```

**兼容映射**：

```text
Anthropic system → OpenAI: messages[0] with role=system（网关自动转换）
OpenAI system → Anthropic: 需要提取首条 system 消息，设置为独立 system 字段
```

### 1.3 多模态输入

**Anthropic**（content block 数组）：

```json
{
  "role": "user",
  "content": [
    {"type": "image", "source": {"type": "base64", "media_type": "image/jpeg", "data": "..."}}
  ]
}
```

**OpenAI**（content 数组 + image_url）：

```json
{
  "role": "user",
  "content": [
    {"type": "image_url", "image_url": {"url": "data:image/jpeg;base64,..."}}
  ]
}
```

**差异要点**：

| 特性 | Anthropic | OpenAI |
|------|-----------|--------|
| 图片格式 | `type: image` + `source` | `type: image_url` + `image_url.url` |
| MIME 类型 | `source.media_type` | 编码在 data URL 中 |
| URL 支持 | 支持 base64 和 URL | 支持 base64、URL 和文件名 |
| 图片多轮 | 支持，content block 灵活组合 | 支持，content 数组 |

## 2. 响应结构对比

### 2.1 基本结构

| 字段 | Anthropic | OpenAI | 说明 |
|------|-----------|--------|------|
| 顶级 ID | `id` | `id` | 两者都有，格式不同 |
| 顶级对象类型 | `type: "message"` | `object: "chat.completion"` | 命名不同 |
| 角色 | `role: "assistant"` | `choices[0].message.role` | 位置不同 |
| 内容位置 | `content[0].text` | `choices[0].message.content` | 格式不同 |
| 停止原因 | `stop_reason` | `choices[0].finish_reason` | 命名不同 |
| Token 用量 | `usage.input_tokens` + `usage.output_tokens` | `usage.prompt_tokens` + `usage.completion_tokens` | 命名不同 |

### 2.2 响应示例对比

**Anthropic**：

```json
{
  "id": "msg_01ABC",
  "type": "message",
  "role": "assistant",
  "content": [{"type": "text", "text": "Hello!"}],
  "model": "claude-sonnet-5-20251001",
  "stop_reason": "end_turn",
  "usage": {
    "input_tokens": 10,
    "output_tokens": 5
  }
}
```

**OpenAI**：

```json
{
  "id": "chatcmpl-ABC123",
  "object": "chat.completion",
  "choices": [
    {
      "index": 0,
      "message": {"role": "assistant", "content": "Hello!"},
      "finish_reason": "stop"
    }
  ],
  "model": "gpt-4o",
  "usage": {
    "prompt_tokens": 10,
    "completion_tokens": 5
  }
}
```

## 3. 流式格式对比

### 3.1 事件/Chunk 结构

| 特性 | Anthropic (SSE Events) | OpenAI (SSE Chunks) |
|------|----------------------|-------------------|
| 消息开始 | `event: message_start` | `choices[0].delta.role` |
| 内容增量 | `event: content_block_delta` + `delta.text` | `choices[0].delta.content` |
| 消息结束 | `event: message_stop` | `[DONE]` |
| 心跳 | `event: ping` | ❌ 无心跳 |

### 3.2 流式关键差异

```text
Anthropic 流式:
  - 每个 event 有独立的事件类型
  - 内容可能分多个 content block
  - 支持 thinking block 的流式
  
OpenAI 流式:
  - 所有数据在 data: 行内
  - 通过 choices[0].delta 区分角色和内容
  - 结束标记为 data: [DONE]
```

### 3.3 兼容实现要点

网关（如 one-api）在转换流式输出时：

```
OpenAI → Anthropic:
  data: {"choices":[{"delta":{"role":"assistant"}}]}
  → event: content_block_start (创建 text block)

  data: {"choices":[{"delta":{"content":"Hello"}}]}
  → event: content_block_delta (delta.text = "Hello")

  data: [DONE]
  → event: message_delta + event: message_stop
```

## 4. Tool Use 对比

### 4.1 工具定义

| 特性 | Anthropic | OpenAI |
|------|-----------|--------|
| 参数位置 | `tools` 数组 | `tools` 数组 |
| 参数结构 | `input_schema` | `parameters`（JSON Schema） |
| 强制调用 | `tool_choice: {"type": "tool", "name": "x"}` | `tool_choice: {"type": "function", "function": {"name": "x"}}` |
| 并行调用 | 原生支持多个 tool_use block | 支持 `parallel_tool_calls` |

### 4.2 工具调用响应对比

**Anthropic**：

```json
{
  "content": [
    {"type": "text", "text": "I'll check the weather."},
    {
      "type": "tool_use",
      "id": "toolu_01ABC",
      "name": "get_weather",
      "input": {"location": "Beijing"}
    }
  ],
  "stop_reason": "tool_use"
}
```

**OpenAI**：

```json
{
  "choices": [{
    "message": {
      "content": "I'll check the weather.",
      "tool_calls": [{
        "id": "call_ABC",
        "type": "function",
        "function": {
          "name": "get_weather",
          "arguments": "{\"location\": \"Beijing\"}"
        }
      }]
    },
    "finish_reason": "tool_calls"
  }]
}
```

### 4.3 工具结果提交

**Anthropic**（tool_result content block）：

```json
{
  "role": "user",
  "content": [
    {
      "type": "tool_result",
      "tool_use_id": "toolu_01ABC",
      "content": "28°C, Sunny"
    }
  ]
}
```

**OpenAI**（tool role）：

```json
{
  "role": "tool",
  "tool_call_id": "call_ABC",
  "content": "28°C, Sunny"
}
```

> 💡 **兼容关键**：Tool Use 的转换是网关中最复杂的部分。Anthropic 的 `tool_use_id` 前缀为 `toolu_`，OpenAI 的 `tool_call_id` 格式不同，需要正确映射。

## 5. 关键字段映射表

### 5.1 请求字段映射

| Anthropic | OpenAI | 转换规则 |
|-----------|--------|---------|
| `model` | `model` | 直接映射 |
| `messages[].role: "user"` | `messages[].role: "user"` | 直接映射 |
| `messages[].role: "assistant"` | `messages[].role: "assistant"` | 直接映射 |
| `system` | `messages[0].role: "system"` | 提取/合并 |
| `max_tokens` | `max_tokens` | 直接映射 |
| `temperature` | `temperature` | 直接映射 |
| `top_p` | `top_p` | 直接映射 |
| `stop_sequences` | `stop` | 数组格式相同 |
| `stream: true` | `stream: true` | 直接映射 |
| `tools[].input_schema` | `tools[].function.parameters` | 嵌套结构调整 |
| `tool_choice.type: "tool"` | `tool_choice.type: "function"` | 类型名不同 |

### 5.2 响应字段映射

| Anthropic | OpenAI | 说明 |
|-----------|--------|------|
| `id` | `id` | 格式不同，需保留映射 |
| `content[].type: "text"` → `.text` | `choices[0].message.content` | 位置差异大 |
| `stop_reason: "end_turn"` | `finish_reason: "stop"` | 命名+值不同 |
| `stop_reason: "tool_use"` | `finish_reason: "tool_calls"` | 命名+值不同 |
| `stop_reason: "max_tokens"` | `finish_reason: "length"` | 值不同 |
| `usage.input_tokens` | `usage.prompt_tokens` | 命名不同 |
| `usage.output_tokens` | `usage.completion_tokens` | 命名不同 |

### 5.3 角色映射表

| Anthropic | OpenAI | 说明 |
|-----------|--------|------|
| `user` | `user` | ✅ 一致 |
| `assistant` | `assistant` | ✅ 一致 |
| ❌ 无 `system` role | `system` | Anthropic 使用独立字段 |
| ❌ 无 `tool` role | `tool` | Anthropic 使用 tool_result block |

## 6. 常见兼容问题

### 6.1 content 类型不匹配

**问题**：使用 Anthropic SDK 时，响应内容被包装在 `content[0].text` 中，而 OpenAI 原生在 `choices[0].message.content`。

**解决**：使用统一响应模型封装，或通过 SDK 抽象层（如 Spring AI 的 ChatClient）。

### 6.2 system prompt 在 images 之后

**问题**：OpenAI 的 system 消息必须在 user 消息之前；Anthropic 的 system 是独立字段，无顺序问题。

**解决**：One-api 网关自动处理顺序；手动转换时注意提取 system 消息。

### 6.3 Stop Sequences 格式

**问题**：Anthropic 的 `stop_sequences` 是数组；OpenAI 的 `stop` 接受字符串或字符串数组。

**解决**：统一转换为字符串数组。

### 6.4 Token 计数差异

**问题**：不同模型的 tokenizer 不同，同一文本在不同模型下的 token 数可能差异较大。

```text
Anthropic tokenizer ≠ DeepSeek tokenizer ≠ OpenAI tokenizer
Token 计数不可跨模型比较，仅用于同一模型的成本估算
```

### 6.5 未知参数拒绝

**问题**：部分兼容服务遇到不支持的参数会报错（如 `metadata`, `top_k`）。

**解决**：使用网关时，网关应过滤掉目标服务不支持的参数；直接调用时需查阅目标服务的兼容文档。

---

> 🎯 **核心要点**：Anthropic 与 OpenAI 的协议差异主要集中在：**system prompt 位置**、**content 结构**（block 数组 vs 字符串）、**tool_use 格式**（tool_result block vs tool role）、以及 **流式事件模型**（event 类型 vs data chunk）。理解这些差异是正确使用兼容接口和配置网关的基础。
