## 1. 高频面试题

### Q1（⭐⭐⭐⭐⭐）: 项目中接入大模型 API，你怎么做技术选型？

> **标准回答**：我按五个维度评估——
> 1. **任务匹配度**：推理深度（复杂→Claude/GPT-4o，简单→DeepSeek V3）、中文质量（强→Qwen/Kimi）
> 2. **成本约束**：日调用量 × 单价 = 日成本，预算紧张→DeepSeek（GPT 1/50 价格）
> 3. **延迟要求**：实时对话 → Haiku/GPT-4o-mini，批处理 → 可以等
> 4. **合规需求**：金融/政务→国产模型（GLM/文心），海外→GPT/Claude
> 5. **集成成本**：优先选 OpenAI 兼容的（DeepSeek/Qwen/GLM），迁移成本为零
>
> **最终决策**：通常选一个主力模型（80% 流量）+ 一个备选模型（降级用）+ 本地模型（极端省钱场景）

### Q2: OpenAI 和 Claude API 的核心差异？

| 维度 | OpenAI | Claude |
|------|--------|--------|
| System Prompt | `role: "system"` in messages | 独立 `system` 参数 |
| max_tokens | 可选 | **必填** |
| Function Calling | `tool_calls` JSON | `tool_use` block |
| 结果回填 | `role: "tool"` message | `tool_result` block |
| 上下文长度 | 128K | **200K** |
| 多模态 | `image_url` | `source.type: "base64"` |
| 独有能力 | GPTs/Assistants API | Computer Use |

### Q3: 流式输出 (SSE) 怎么实现？

> 1. 客户端设置 `stream: true`
> 2. 服务端返回 `text/event-stream`，每行 `data: {"choices":[{"delta":{"content":"..."}}]}`
> 3. 客户端逐行解析 → 实时展示（打字机效果）
> 4. JDK 11+ 用 `HttpClient` + `BodySubscriber`，Spring 用 `WebClient` + `Flux`
> 5. **关键**：需要处理 `[DONE]` 终止信号、断线重连、超时

### Q4: 怎么保证 API 调用的稳定性？

```text
稳定性三板斧：
├── 1. 重试策略：指数退避 (1s→2s→4s→8s)，最多 3 次
├── 2. 降级方案：主模型挂了 → 自动切备选模型 → 再挂就本地缓存应答
└── 3. 熔断机制：连续失败 N 次 → 熔断器打开 → 快速失败返回降级响应
```

### Q5: Function Calling 一次调用多个工具 vs 分步调用？

| 场景 | 策略 | 原因 |
|------|------|------|
| 工具之间无依赖 | **并行** | 节省延迟（2 个 1s 调 = 1s 总时间） |
| 工具之间有依赖 | 串行 | 后续工具需要前一个的结果 |
| 不确定是否有依赖 | 先并行，失败再串行 | 乐观并行的容错策略 |

### Q6: API Key 安全怎么保证？

```text
安全层级：
├── L1 存储：环境变量/Secrets Manager，永不硬编码
├── L2 传输：HTTPS + TLS 1.3
├── L3 访问：API Key 按服务/场景拆分（读 Key / 写 Key）
├── L4 监控：异常用量告警（单分钟 > N 次 → 自动停用）
└── L5 轮换：定期轮换 Key，旧 Key 立即失效
```

### Q7: 多个模型 API 怎么统一封装？

> 我通常设计三层架构：
> 1. **统一接口层**：`LLMClient.chat(prompt)`，应用层不感知模型差异
> 2. **适配器层**：`OpenAIAdapter` / `ClaudeAdapter` / `HermesAdapter`，各自实现 FC 转换
> 3. **路由层**：`ModelRouter.route(query)` → 根据意图/复杂度选模型
>
> 关键代码量：适配器 ~50 行/平台，路由 ~30 行

### Q8: 100 万 DAU 的 AI 产品，API 成本怎么估算？

```text
假设：
- DAU 100 万，日活中 10% 使用 AI = 10 万日活跃 AI 用户
- 每人每天平均 5 次调用，每次 500 输入 + 800 输出 tokens
- 输入: 10万 × 5 × 500 = 2.5 亿 tokens/天
- 输出: 10万 × 5 × 800 = 4 亿 tokens/天

成本对比：
├── GPT-4o： (2.5亿 × $2.5 + 4亿 × $10) / 1M = $4,625/天 ≈ $138,750/月
├── Claude Sonnet：(2.5亿 × $3 + 4亿 × $15) / 1M = $6,750/天 ≈ $202,500/月
├── DeepSeek V3：(2.5亿 × $0.27 + 4亿 × $1.10) / 1M = $507/天 ≈ $15,225/月
└── 自部署 Hermes 8B：GPU(A100 $3.5/h) × 10台 × 720h = $25,200/月

结论：DeepSeek V3 最省钱，但需考虑并发限制和国内合规
```

## 2. 选型答辩模板

### 2.1 "你会选哪个模型" 回答框架

```
第一部分：理解需求（10秒）
  "我先确认一下：这个场景是 _____，日调用量大约 _____，
   对延迟的要求是 _____，预算大概是 _____。"

第二部分：给出方案（30秒）
  "基于这些条件，我的推荐是 _____（主力）+ _____（备选）。
   理由是：1. ______ 2. ______ 3. ______"

第三部分：风险说明（10秒）
  "这个方案的潜在风险是 ______，我们可以通过 ______ 来规避"
```

### 2.2 场景速查

| 如果面试官说... | 推荐回答 |
|---|---|
| "我们要做智能客服" | 主力 DeepSeek V3（便宜+够用）+ 本地 Qwen 7B（敏感问题兜底）+ Function Calling 查订单 |
| "我们要做代码审查" | 主力 Claude Sonnet（代码理解强）+ GPT-4o（备选）+ Git Diff → LLM → PR Comment 流水线 |
| "我们要做多语言翻译" | DeepSeek V3（多语言不差+便宜）或 GPT-4o（质量最高） |
| "预算很少，但要做 AI" | DeepSeek V3 API（$15/月/万人）+ 本地 Ollama Qwen 7B（免费）混合路由 |
| "数据不能出内网" | Ollama 部署 Qwen 2.5 或 Hermes 3 + vLLM 生产化 |

## 核心要点回顾

- 选型五维度：任务匹配 × 成本 × 延迟 × 合规 × 集成成本
- OpenAI vs Claude 最大差异：system prompt 位置、max_tokens 必填、FC 格式
- 稳定性三板斧：重试(指数退避) → 降级(备选模型) → 熔断(快速失败)
- API Key 安全：环境变量 + HTTPS + 权限拆分 + 用量监控 + 定期轮换
- 成本估算公式：日活 × AI使用率 × 日均调用 × (输入+输出tokens) × 单价
- 面试框架：先确认需求 → 给方案+理由 → 说明风险+对策
