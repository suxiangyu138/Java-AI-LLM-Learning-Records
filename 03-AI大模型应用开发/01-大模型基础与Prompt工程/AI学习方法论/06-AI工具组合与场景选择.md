## 1. 工具能力边界概览

每个 AI 工具的设计目标和能力边界不同，没有单一工具能胜任所有场景。

| 工具 | 核心优势 | 核心劣势 |
|------|----------|----------|
| **ChatGPT** | 通用性强，代码生成优秀 | 长上下文能力弱，知识存在截止日期 |
| **Claude** | 长文档分析，深度推理 | 无实时搜索，代码补全体验不如 Copilot |
| **Perplexity** | 实时搜索 + 引用来源 | 代码能力弱于 ChatGPT / Claude |
| **GitHub Copilot** | IDE 内代码补全流畅 | 不会解释原理，不会架构设计 |
| **Cursor** | AI 结对编程，理解项目上下文 | 需要项目加载，不适合临时问答 |

> **重点**：工具选择的核心理念是"把合适的任务交给最擅长的工具"，而非依赖单一 AI 解决所有问题。

## 2. 场景 x 工具决策矩阵

### 2.1 学习知识场景

| 场景 | 首选工具 | 选型理由 |
|------|----------|----------|
| Java SE 基础概念 | ChatGPT | 回答结构化，代码示例丰富 |
| 算法题讲解 | ChatGPT | 思路讲解清晰，多解法对比 |
| Spring 原理深入 | Claude | 能处理长调用链，深度追问不崩溃 |
| 阅读论文 / 技术规范 | Claude | 长文本分析能力强，能提取关键信息 |
| 查询最新技术趋势 | Perplexity | 实时搜索，带引用来源 |
| 技术选型调研 | Perplexity | 可对比不同框架最新版本特性 |
| 寻找开源项目 / 替代方案 | Perplexity | 实时搜索 GitHub 及技术社区 |

### 2.2 编码场景

| 场景 | 首选工具 | 选型理由 |
|------|----------|----------|
| 编写 CRUD 模板代码 | GitHub Copilot | Tab 键补全，不打断心流 |
| 编写 SQL / 配置文件 | GitHub Copilot | 上下文感知，补全准确 |
| 重构复杂代码 | Cursor | 理解整个项目，支持重命名 / 提取方法 |
| 调试 Bug | Cursor + ChatGPT | Cursor 定位代码，ChatGPT 诊断原因 |
| 生成单元测试 | Cursor | 一键生成覆盖所有分支的测试用例 |
| 编写复杂业务逻辑 | **开发者自行编写，AI 仅做 Review** | 核心业务逻辑不能外包 |

> **注意**：复杂业务逻辑应始终由开发者主导编写。AI 缺乏对业务领域和隐含规则的深度理解，将核心逻辑外包给 AI 会引入难以追踪的隐性缺陷。

## 3. 三大组合拳流程

### 3.1 组合拳 1：学新技术

```text
Step 1: Perplexity
        查询 → "2026 年 Spring AI 最新教程推荐"
        产出 → 最新、最权威的学习资源列表

Step 2: ChatGPT
        提问 → "我是 Java 后端，用以下结构输出 Spring AI 学习路线..."
        产出 → 结构化学习路线，含前置知识、学习阶段、实践项目

Step 3: Cursor
        操作 → 新建 Demo 项目，跟随学习路线编码实践
        辅助 → 遇到问题直接 @Cursor 提问
```

### 3.2 组合拳 2：调试复杂 Bug

```text
Step 1: Cursor
        操作 → 定位 Bug 相关代码，选中后执行 "Explain Code"
        目标 → 确保开发者充分理解代码意图

Step 2: ChatGPT
        输入 → 错误堆栈 + 运行环境信息 + 相关代码片段
        产出 → 初步诊断结论和修复方案

Step 3: Claude
        提示 → "请审查 ChatGPT 的方案，找出潜在漏洞"
        产出 → 深度分析报告，重点关注边界条件和异常路径

Step 4: ChatGPT（第二轮）
        提示 → "Claude 发现了 X 问题，请重新生成方案"
        产出 → 修复漏洞后的完整实施方案
```

### 3.3 组合拳 3：刷算法题

```text
Step 1: 自主思考
        时间 → 10-15 分钟
        产出 → 暴力解法或伪代码（不依赖 AI）

Step 2: ChatGPT
        提示 → "我的思路是 X，哪里错了？如何优化？"
        产出 → 在现有思维上修正，给出多种优化解法

Step 3: ChatGPT（巩固）
        提示 → "请出 2 道同类型变种题，不给答案"
        目标 → 检验是否真正理解算法思想

Step 4: 间隔重复（3 天后）
        提示 → "上次做的 #42 接雨水，请再出 1 道同类题"
        原理 → 间隔重复，巩固长期记忆
```

> **重点**：算法能力提升的关键是"先自己思考，再借助 AI 校正和深化"。直接让 AI 给出答案会削弱主动思考的训练效果。

以下为每周 AI 工具的时间投入分布建议，按使用占比排序：

```text
ChatGPT     ████████░░  40%  — 核心技术学习 + 算法 + 问题诊断
Cursor      ██████░░░░  30%  — 编码实现 + 代码重构 + 测试生成
Claude      ████░░░░░░  15%  — 源码阅读 + 技术方案设计评审
Perplexity  ██░░░░░░░░  10%  — 技术调研 + 趋势跟踪
```

## 5. 费用优化方案

### 定价对比

| 工具 | 免费方案 | 付费方案 | 推荐意见 |
|------|----------|----------|----------|
| ChatGPT | GPT-4o 有限次数 | Plus $20 / 月 | 值得付费，日均成本不足 1 元人民币 |
| Claude | Sonnet 免费额度 | Pro $20 / 月 | 需要长文本分析时按需付费 |
| Perplexity | 基础搜索免费 | Pro $20 / 月 | 免费版已满足绝大多数场景 |
| GitHub Copilot | 学生认证免费 | $10 / 月 | 优先使用学生认证 |
| Cursor | Hobby 免费版 | Pro $20 / 月 | 免费版提供 2 000 次补全 / 月 |

### 推荐方案

**最低成本方案（零成本）**：GitHub Copilot（学生认证）+ Cursor 免费版 + ChatGPT 免费额度 = **¥0 / 月**

**推荐方案（高性价比）**：ChatGPT Plus（$20）+ Cursor Pro（$20）= **$40 / 月**，覆盖约 90% 研发场景

> **重点**：建议优先使用各工具的免费额度，确认高频使用后再决定付费订阅，避免为低频使用的工具持续付费。

## 核心要点回顾

- 单一 AI 工具无法覆盖所有场景，应根据工具能力边界做场景化选型
- ChatGPT 适合通用问答和代码生成，Claude 适合长文本深度分析，Perplexity 适合实时信息检索，Copilot 适合 IDE 内代码补全，Cursor 适合项目级结对编程
- 复杂业务逻辑应由开发者主导编写，AI 仅承担代码审查角色
- 算法训练应采用"先自主思考、后 AI 校正"的模式，配合间隔重复巩固长期记忆
- 调试 Bug 时可利用多工具交叉验证：Cursor 定位、ChatGPT 诊断、Claude 审查
- 费用策略上推荐"先免费后付费"，ChatGPT Plus + Cursor Pro 的组合可覆盖 90% 场景
