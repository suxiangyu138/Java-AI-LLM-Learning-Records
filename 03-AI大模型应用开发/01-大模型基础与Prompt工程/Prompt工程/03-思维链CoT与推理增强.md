## 1. 什么是思维链 CoT

### 1.1 核心思想

```text
CoT (Chain-of-Thought) = 让模型在给出最终答案之前，先展示推理过程

普通 Prompt：
  "小明有 5 个苹果，买了 3 个，吃了 2 个，还剩几个？"
  → 模型直接答："6 个" ← 可能对也可能错

CoT Prompt：
  "小明有 5 个苹果，买了 3 个，吃了 2 个，还剩几个？
   让我们一步步思考。"
  → 模型输出：
    "小明最初有 5 个苹果。
     买了 3 个后，一共有 5 + 3 = 8 个苹果。
     吃了 2 个后，还剩 8 - 2 = 6 个苹果。
     答案是 6 个。" ← 几乎不会错
```

### 1.2 为什么 CoT 有效

```text
CoT 有效的原因：

① 将复杂问题分解为简单步骤
   → 每步只需要"浅层推理"→ 降低错误率

② 中间步骤提供"自查"机会
   → 模型能看到自己的推理链 → 发现矛盾 → 自我纠正

③ Token 路径依赖
   → 自回归生成中，前面的 token 影响后面的 token
   → 推理过程 token → 约束答案 token 的生成空间

④ 类比于人类的 System 2 思维
   → 快思考（直觉回答）vs 慢思考（逐步推理）
   → CoT 强制模型进入"慢思考"模式
```

## 2. Few-Shot CoT

### 2.1 模式

```text
Few-Shot CoT = 示例中包含推理过程

示例模板：
  Q: [问题]
  A: 让我们一步步思考。
     第一步：...
     第二步：...
     因此，答案是 [X]。

给出 2-3 个带推理过程的示例，模型会模仿这种模式
```

### 2.2 示例

```text
Few-Shot CoT Prompt：

  Q: 一个班有 30 个学生，其中 18 个喜欢数学，15 个喜欢英语，
     两个都喜欢的有 8 人。有多少人两种都不喜欢？
  A: 让我们一步步思考。
     喜欢数学的 = 18 人
     喜欢英语的 = 15 人
     两个都喜欢的 = 8 人
     至少喜欢一种的 = 18 + 15 - 8 = 25 人
     两种都不喜欢的 = 30 - 25 = 5 人
     答案是 5 人。

  Q: 一个农场有鸡和兔共 35 只，共有 94 只脚。
     鸡和兔各有多少只？
  A: 让我们一步步思考。
     设鸡为 x 只，兔为 y 只
     x + y = 35
     2x + 4y = 94
     从第一个方程：y = 35 - x
     代入第二个：2x + 4(35 - x) = 94
     2x + 140 - 4x = 94
     -2x = -46
     x = 23
     y = 35 - 23 = 12
     答案是 23 只鸡和 12 只兔。

  Q: [你的新问题]
  A: 让我们一步步思考。
```

## 3. Zero-Shot CoT

### 3.1 一句话魔法

```text
Zero-Shot CoT = 不需要示例，只需加一句 "Let's think step by step"

这是 Kojima et al. (2022) 的惊人发现：
  在所有推理任务上，仅加一句话就大幅提升准确率

  数学推理 (GSM8K)：  标准 60% → Zero-Shot-CoT 75%
  常识推理 (StrategyQA)：标准 62% → Zero-Shot-CoT 68%
```

### 3.2 对比

```python
# 标准 Prompt
prompt_standard = "一个数加上 12 等于 35，这个数是多少？"

# Zero-Shot CoT
prompt_cot = """一个数加上 12 等于 35，这个数是多少？

让我们一步步思考。"""

# Zero-Shot CoT 变体（有时更稳定）
prompt_cot_v2 = """一个数加上 12 等于 35，这个数是多少？

请按以下步骤回答：
1. 理解问题
2. 列出已知条件
3. 推导计算过程
4. 给出最终答案"""
```

## 4. Least-to-Most Prompting

### 4.1 原理

```text
Least-to-Most = 对超复杂问题，先拆分成子问题，逐个解决

流程：
  ① 让模型将复杂问题分解为子问题
  ② 逐个解决子问题（每个子问题的答案作为下一个的输入）
  ③ 最终汇总

适用于：需要多步推理、子问题之间相互依赖
```

### 4.2 示例

```text
复杂问题："一个公司有 3 个部门，A 部门 20 人平均工资 8000，
           B 部门 15 人平均工资 9500，C 部门 10 人平均工资 12000。
           如果整个公司平均涨薪 10%，涨薪后总工资支出是多少？"

Least-to-Most：
  Step 1: 计算各部门总工资
    → A: 20×8000 = 160,000
    → B: 15×9500 = 142,500
    → C: 10×12000 = 120,000

  Step 2: 计算公司总工资
    → 160,000 + 142,500 + 120,000 = 422,500

  Step 3: 计算涨薪后总工资
    → 422,500 × 1.10 = 464,750

  答案：464,750 元
```

## 5. Self-Consistency 自洽性

### 5.1 原理

```text
Self-Consistency = 多次采样 + 投票选最一致的答案

流程：
  ① 对同一问题，用 CoT 生成多条推理路径（temperature > 0）
  ② 每条路径给出一个答案
  ③ 选择出现频率最高的答案

为什么有效？
  → 正确的推理路径通常多于错误的
  → 多数投票消除单次推理的随机错误
  → 代价：推理成本 × N
```

```python
def self_consistency(llm, question, n_samples=5):
    """Self-Consistency：多次采样投票"""
    answers = []
    
    for _ in range(n_samples):
        prompt = f"{question}\n\n让我们一步步思考。"
        response = llm(prompt, temperature=0.7)  # 非零温度！
        # 提取最终答案
        answer = extract_final_answer(response)
        answers.append(answer)
    
    # 投票选出最频繁的答案
    from collections import Counter
    return Counter(answers).most_common(1)[0][0]
```

### 5.2 何时使用

```text
✅ 适合 Self-Consistency：
  → 数学推理题（答案唯一确定）
  → 逻辑推理题
  → 代码生成（多次生成→选能通过测试的）

❌ 不适合：
  → 创意写作（没有"正确答案"）
  → 对话生成（每次回答都应该自然变化）
  → Token 预算紧张时（成本 × N）
```

## 6. CoT 的适用与局限

### 6.1 什么任务需要 CoT

| 任务 | 需要 CoT？ | 原因 |
|------|:---:|------|
| 数学推理 | ✅ 必须 | 多步计算 |
| 逻辑推理 | ✅ 必须 | 需要推理链 |
| 复杂分类 | ✅ 推荐 | 需要分步分析 |
| 情感分析 | ❌ 不需要 | 直觉判断即可 |
| 简单翻译 | ❌ 不需要 | 不需要推理 |
| 代码生成 | ⚠️ 看情况 | 复杂逻辑需要 |

### 6.2 CoT 的局限

```text
① 某些模型不擅长 CoT
   → 小模型（<7B）的 CoT 可能反而更差
   → 需要模型有基本的推理能力

② Token 消耗增加
   → CoT 的推理过程占用输出 token
   → 成本增加 2-5×

③ 可能产生"可信但错误"的推理
   → 推理过程看起来合理，但实际有逻辑漏洞
   → Self-Consistency 可以部分缓解

④ 不适用于所有任务
   → 简单任务用 CoT → 过度复杂化 → 反而可能出错
```

---

## 核心要点回顾

- CoT = 让模型展示推理过程再给答案 → 推理准确率大幅提升
- Zero-Shot CoT：只加 "Let's think step by step" → 最简单有效
- Few-Shot CoT：给带推理的示例 → 效果更好但 Token 消耗大
- Self-Consistency：多次采样投票 → 进一步消除随机错误
- Least-to-Most：超复杂问题先拆解再逐个解决
