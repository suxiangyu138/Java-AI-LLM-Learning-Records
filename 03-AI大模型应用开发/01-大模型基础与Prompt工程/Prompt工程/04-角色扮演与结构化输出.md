## 1. 角色扮演深度技巧

### 1.1 角色设定公式

```text
角色设定 = 身份 + 场景 + 视角 + 风格

  身份：你是什么角色（架构师/面试官/代码审查员）
  场景：在什么情境下（Code Review/技术分享/故障排查）
  视角：从什么角度看问题（设计者/使用者/维护者）
  风格：用什么方式表达（简洁直接/循循善诱/批判性）
```

### 1.2 Java 后端开发常用角色

| 角色 | Prompt 片段 | 适用场景 |
|------|------------|----------|
| **Java 架构师** | "你是 10 年经验的 Java 架构师，擅长高并发和微服务" | 系统设计、技术选型 |
| **代码审查员** | "你是严格的代码审查员，按阿里巴巴 Java 规范审查" | Code Review |
| **面试官** | "你是大厂 Java 后端面试官，面试 P7 级别候选人" | 模拟面试 |
| **技术作家** | "你是擅长把复杂概念讲清楚的技术作家" | 写文档/Blog |
| **调试助手** | "你是资深 SRE，擅长排查线上故障" | 故障分析 |

### 1.3 多角色切换

```text
技巧：同一对话中切换角色，获得多视角分析

  "现在切换到「安全审计员」角色，从 OWASP Top 10 角度审查这段代码"
  "现在切换到「性能优化专家」角色，分析这段代码的性能瓶颈"
  "现在切换回「架构师」角色，综合以上意见给出最终方案"

好处：
  ✅ 每个角色聚焦特定维度 → 分析更深入
  ✅ 避免单一角色的认知盲区
```

## 3. JSON 模式与 Function Calling

### 3.1 强制 JSON 输出

```python
from openai import OpenAI

client = OpenAI()

# 方式 1：Prompt 约束（不够可靠）
prompt = """提取以下文本中的人名和邮箱，用 JSON 格式返回：
{"persons": [{"name": "...", "email": "..."}]}

文本：张三 (zhangsan@example.com) 和李四 (lisi@test.com)"""

# 方式 2：JSON Mode（OpenAI，更可靠）
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": prompt}],
    response_format={"type": "json_object"}  # 强制 JSON
)

# 方式 3：Function Calling（最可靠）
tools = [{
    "type": "function",
    "function": {
        "name": "extract_persons",
        "parameters": {
            "type": "object",
            "properties": {
                "persons": {
                    "type": "array",
                    "items": {
                        "type": "object",
                        "properties": {
                            "name": {"type": "string"},
                            "email": {"type": "string"}
                        }
                    }
                }
            }
        }
    }
}]
```

### 3.2 JSON 格式约束技巧

```text
让 LLM 输出合法 JSON 的技巧：

  ① 提供 Schema 示例（比描述更有效）
  ② 强调 "只输出 JSON，不要任何额外文字"
  ③ 用 Field 描述约束取值空间
  ④ 给出边界 case 的示例

Prompt 示例：
  "返回以下格式的 JSON，不要包含任何额外文字或 markdown 标记：
  {
    'score': <0-100的整数>,
    'summary': '<50字以内的总结>',
    'tags': ['<标签1>', '<标签2>', ...]
  }"
```

## 4. 输出校验与容错

```python
import json

def safe_json_parse(llm_output):
    """容错解析 LLM 输出的 JSON"""
    # ① 去除 markdown 标记
    text = llm_output.strip()
    if text.startswith("```json"):
        text = text[7:]
    if text.startswith("```"):
        text = text[3:]
    if text.endswith("```"):
        text = text[:-3]
    
    # ② 尝试解析
    try:
        return json.loads(text.strip())
    except json.JSONDecodeError:
        # ③ 尝试提取 {...} 块
        import re
        match = re.search(r'\{.*\}', text, re.DOTALL)
        if match:
            try:
                return json.loads(match.group())
            except:
                pass
    
    return None  # 解析失败
```

## 核心要点回顾

- 角色 = 身份 + 场景 + 视角 + 风格 → 决定输出深度和角度
- 格式约束用"示例"比用"描述"更可靠
- JSON Mode / Function Calling 是程序对接的最可靠方式
- 始终对 LLM 的结构化输出做容错解析（markdown 标记、不完整 JSON）
