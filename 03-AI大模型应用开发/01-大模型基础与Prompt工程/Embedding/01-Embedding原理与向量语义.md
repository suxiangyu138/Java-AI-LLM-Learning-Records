## 1. 什么是 Embedding

### 1.1 一句话定义

```text
Embedding = 将非结构化数据（文本/图片/音频）映射为固定长度的浮点数向量，
使得语义相近的内容在向量空间中距离也相近。
```

### 1.2 直观示例

```text
"今天天气真好"  →  [0.12, -0.34, 0.56, ..., 0.78]   (1536维)
"今日阳光明媚"  →  [0.11, -0.33, 0.58, ..., 0.77]   ← 向量非常接近！
"数据库连接超时" →  [-0.45, 0.67, -0.23, ..., -0.12] ← 向量远离

人类视角："今天天气真好" 和 "今日阳光明媚" 说的是同一件事
机器视角：两个向量几乎重合 → "它们语义相近"
```

### 1.3 为什么需要 Embedding

```text
传统关键词检索的困境：
  搜索"轿车" → 匹配不到"汽车"、"小轿车"、"四轮车"
  → 只能做字面匹配，无法理解语义

Embedding 的突破：
  搜索"轿车" → 转成向量 → 与"汽车"的向量相似度 0.95 → 匹配！
  → 理解语义，而非字面
```

## 2. 语义空间的直觉

### 2.1 向量空间中的"语义簇"

```text
高维向量空间（可视化降维到 2D）：

             ● 晴天          ← 天气簇
          ● 阳光      ● 多云
                    ● 下雨
              
                              ● SELECT      ← 数据库簇
                           ● INSERT   ● JOIN
                              ● 索引
              
         ● 开心    ● 快乐       ← 情感簇
            ● 高兴
```

### 2.2 向量的"方向"就是"语义"

```text
Embedding 空间中，方向 = 语义特征

经典例子（word2vec）：
  vec("国王") - vec("男人") + vec("女人") ≈ vec("王后")
  
  这个向量运算揭示了：
  "国王"去掉"男性"语义 + 加上"女性"语义 → "王后"

  向量不仅能编码"是什么"，还能编码"属性"和"关系"
```

## 3. 相似度度量：三种方法

### 3.1 余弦相似度（最常用）

```text
余弦相似度：
  cos(a, b) = (a · b) / (|a| × |b|)

  取值范围：[-1, 1]
  1  = 方向完全相同（最相似）
  0  = 正交（无关）
  -1 = 方向完全相反

优势：
  ✅ 只关心方向，不关心长度
  ✅ "长文章"和"短问题"也可比较
  ✅ RAG 默认度量
```

### 3.2 欧氏距离

```text
欧氏距离：
  d(a, b) = |a - b|₂ = √(Σ(aᵢ - bᵢ)²)

  数值越小越相似

劣势：
  ❌ 受向量长度影响大
  ❌ 需要向量归一化后使用
```

### 3.3 内积（点积）

```text
内积：
  a · b = Σ aᵢbᵢ

  数值越大越相似

劣势：
  ❌ 长向量天然内积大 → 不公平
  ❌ 通常需要归一化后使用
```

### 3.4 三者在 RAG 中的选择

```python
import numpy as np

def cosine_similarity(a, b):
    """RAG 最常用"""
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

def euclidean_distance(a, b):
    """需配合归一化"""
    return np.linalg.norm(np.array(a) - np.array(b))

# RAG 默认选余弦相似度 → 对长度不敏感，比较公平
```

## 4. Embedding 模型的训练原理

### 4.1 对比学习

```text
Embedding 模型的核心训练方法：对比学习（Contrastive Learning）

目标：让相似文本的向量拉近，不相似文本的向量拉远

训练样本（三元组）：
  (锚点, 正例, 负例)
  ("猫", "猫咪", "汽车")

损失函数（Triplet Loss）：
  Loss = max(0, d(锚点, 正例) - d(锚点, 负例) + margin)
  
  含义：正例距离必须比负例距离小至少 margin
  → 强制"猫"比"汽车"更接近"猫咪"
```

### 4.2 训练数据来源

```text
Embedding 模型的数据来自：

① 自然配对：问答对、搜索点击对 → "query"和"点击结果"拉近
② 数据增强：同义词替换、回译 → 构造正例
③ 对比采样：batch 内其他样本作为负例 → 拉开不相关文本

代表模型训练数据量：
  BGE-M3：多语言、亿万级文本对
  text-embedding-3：未公开，但推测使用了海量搜索和对话数据
```

## 5. LLM vs Embedding 模型

| 维度 | LLM（GPT/Qwen） | Embedding 模型（BGE-M3） |
|------|:---:|:---:|
| **输入** | 文本 | 文本 |
| **输出** | 自然语言文本 | 浮点数向量 |
| **核心能力** | 生成、推理、对话 | 语义相似度计算 |
| **能否聊天** | ✅ | ❌ |
| **能否检索** | ❌（需要外部向量库） | ✅ |
| **典型维度** | — | 768 / 1024 / 1536 |
| **在 RAG 中** | 生成回答 | 检索相关文档 |

> 💡 LLM 和 Embedding 模型是搭档关系 — Embedding 负责"找到相关文档"，LLM 负责"基于文档生成回答"。

## 6. 核心参数

| 参数 | 说明 | 典型值 |
|------|------|:---:|
| **向量维度 (dim)** | 每个文本生成的向量长度 | 768 / 1024 / 1536 / 4096 |
| **最大输入长度** | 单次可编码的最大 token 数 | 512 / 8192 |
| **归一化** | 向量是否缩放到单位长度 | True（推荐开启） |
| **批处理大小** | 一次请求处理多少条文本 | 100 ~ 2048 |

```text
维度选择：
  → 768 维：轻量，中文场景 m3e-base
  → 1024 维：通用，BGE-M3、Qwen-Embedding
  → 1536 维：OpenAI text-embedding-3-small
  → 3072 维：OpenAI text-embedding-3-large（精度高但存储大）

维度越高 → 语义表达能力越强 → 但存储和检索计算量也越大
```

## 核心要点回顾

- Embedding 将文本映射为固定长度向量，语义相近 → 向量距离近
- 余弦相似度是 RAG 检索的默认度量方法
- 对比学习是 Embedding 模型的核心训练方式
- LLM 负责生成，Embedding 模型负责检索 — 两者是搭档
- 向量维度是精度和成本的 trade-off：768~1536 是常见选择
