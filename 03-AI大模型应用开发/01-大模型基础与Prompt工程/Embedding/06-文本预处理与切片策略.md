## 1. 为什么需要切片

### 1.1 Embedding 模型的长度限制

```text
所有 Embedding 模型都有最大输入长度限制：

  BGE-M3:              8192 tokens
  text-embedding-3:    8192 tokens
  m3e-base:            512 tokens

一篇技术文档可能 50000 tokens → 必须切片！

直接切？✓ 但怎么切 → 决定了检索质量
```

### 1.2 切片的核心矛盾

```text
切片太大（如 2000 tokens/块）：
  ✅ 包含完整上下文 → 语义丰富
  ❌ 含大量无关信息 → 检索精度下降
  ❌ 向量"稀释" → 具体问题匹配不准

切片太小（如 100 tokens/块）：
  ✅ 信息密度高 → 检索精准
  ❌ 上下文断裂 → "这个"、"它"等指代无法解析
  ❌ 块数暴增 → 存储和检索成本增加

黄金平衡：根据文档类型和模型上下文窗口调整
```

## 2. 固定长度切片

### 2.1 最简实现

```python
def fixed_size_chunk(text: str, chunk_size=512, overlap=50):
    """固定长度切片 — 最基础的方式"""
    words = text.split()  # 英文按空格
    chunks = []
    
    for i in range(0, len(words), chunk_size - overlap):
        chunk = " ".join(words[i:i + chunk_size])
        chunks.append(chunk)
    
    return chunks
```

### 2.2 中文固定长度切片

```python
def chinese_fixed_chunk(text: str, chunk_size=500, overlap=50):
    """中文按字符数切片"""
    chunks = []
    start = 0
    while start < len(text):
        end = min(start + chunk_size, len(text))
        chunks.append(text[start:end])
        start = end - overlap  # 重叠
    return chunks
```

### 2.3 优劣

| 优势 | 劣势 |
|------|------|
| 实现简单 | 句子被切断 → 语义断裂 |
| 块大小均匀 | 不考虑段落结构 |
| 适合规范文档 | 不适合对话/代码 |

## 3. 语义切片

### 3.1 按句子边界切分

```python
import re

def sentence_chunk(text: str, max_sentences=5):
    """按句子切分，保证句子完整性"""
    # 中英文句子分割
    sentences = re.split(r'(?<=[。！？.!?])\s*', text)
    sentences = [s.strip() for s in sentences if s.strip()]
    
    chunks = []
    for i in range(0, len(sentences), max_sentences):
        chunk = "".join(sentences[i:i + max_sentences])
        chunks.append(chunk)
    
    return chunks
```

### 3.2 基于 Embedding 相似度的自适应切片

```python
import numpy as np

def semantic_chunk(text: str, embed_fn, threshold=0.7):
    """基于语义相似度的自适应切片
    相邻句子相似度低于阈值 → 切分点
    """
    sentences = re.split(r'(?<=[。！？.!?])\s*', text)
    sentences = [s.strip() for s in sentences if s.strip()]
    
    if len(sentences) <= 1:
        return [text]
    
    # 计算相邻句子 Embedding 相似度
    embeddings = embed_fn(sentences)
    similarities = []
    for i in range(len(embeddings) - 1):
        sim = np.dot(embeddings[i], embeddings[i+1]) / (
            np.linalg.norm(embeddings[i]) * np.linalg.norm(embeddings[i+1])
        )
        similarities.append(sim)
    
    # 相似度低的地方切分
    chunks = []
    current = [sentences[0]]
    for i, sim in enumerate(similarities):
        if sim < threshold:  # 语义转折 → 切开
            chunks.append("".join(current))
            current = [sentences[i+1]]
        else:
            current.append(sentences[i+1])
    
    if current:
        chunks.append("".join(current))
    
    return chunks
```

## 4. 递归切片

### 4.1 LangChain RecursiveCharacterTextSplitter

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter

# LangChain 的递归切片 — 生产中最常用
splitter = RecursiveCharacterTextSplitter(
    separators=["\n\n", "\n", "。", "！", "？", ".", "!", "?", " ", ""],
    chunk_size=500,
    chunk_overlap=50,
    length_function=len,
)

text = "这是一段很长的文档...（省略50000字）"
chunks = splitter.split_text(text)

print(f"切出 {len(chunks)} 个块")
print(f"前3块大小: {[len(c) for c in chunks[:3]]}")
```

### 4.2 递归切片的优先级

```text
递归切片按优先级尝试分隔符：

  ① "\n\n"  → 段落分隔（最优）
  ② "\n"    → 换行
  ③ "。"    → 中文句号
  ④ "！"   → 中文感叹号
  ⑤ "？"   → 中文问号
  ⑥ "."    → 英文句号
  ⑦ " "    → 空格
  ⑧ ""     → 字符级（最后手段）

大块用高优先级分隔符切，小块用字符级切
→ 保证块大小 ≤ chunk_size
→ 尽量在自然边界切开
```

## 5. 切片重叠策略

### 5.1 为什么需要重叠

```text
问题：关键信息正好在切片边界上

  Chunk 1: "...数据库连接池的核心参数是"
  Chunk 2: "maxActive 和 maxIdle..."

  搜索"数据库连接池 maxActive" → Chunk 1 没有 "maxActive"、Chunk 2 没有"连接池"
  → 两个都检索不到！

解决：overlap=50 → Chunk 1 末尾 50 字 = Chunk 2 开头 50 字
  Chunk 1: "...数据库连接池的核心参数是 maxActive 和"
  Chunk 2: "核心参数是 maxActive 和 maxIdle..."
  → 两个都可能检索到
```

### 5.2 重叠大小的选择

| 重叠 | 适用场景 | 代价 |
|:---:|------|------|
| 0 | 高度结构化的文档（API 文档） | 可能遗漏边界信息 |
| 10% | 通用文档 | 存储增加 10% |
| 20% | 对话/叙述性文本 | 存储增加 20% |
| 50% | 问答对数据集 | 存储翻倍 |

> 💡 通常 10-15% 的 overlap 是性价比最优的选择。

## 6. 文本预处理管线

### 6.1 完整预处理流程

```python
import re

def preprocess_pipeline(text: str) -> str:
    """RAG 文档预处理管线"""
    
    # ① 去除多余空白
    text = re.sub(r'\s+', ' ', text)
    
    # ② 统一换行符
    text = text.replace('\r\n', '\n').replace('\r', '\n')
    
    # ③ 去除页码/页眉/页脚（PDF 常见）
    text = re.sub(r'^\d+\s*$', '', text, flags=re.MULTILINE)
    text = re.sub(r'Page \d+ of \d+', '', text)
    
    # ④ 去除特殊字符（保留中文标点和常用符号）
    # text = re.sub(r'[^一-鿿\w\s。，！？、；：""''（）]', '', text)
    
    # ⑤ 截断超长空白段落
    text = re.sub(r'\n{3,}', '\n\n', text)
    
    return text.strip()
```

### 6.2 不同文档类型的预处理

| 文档类型 | 特殊处理 |
|----------|---------|
| **PDF** | 去除页眉页脚、修复换行断裂、OCR 后纠错 |
| **HTML** | 去除标签、保留标题层级（h1-h6→Chunk 元数据） |
| **Markdown** | 保留标题、代码块单独处理（不切片） |
| **代码** | 按函数/类边界切片、保留 import 语句 |
| **对话** | 保留角色标签、按对话轮次切片 |

## 7. 切片策略对比与选型

| 策略 | 精度 | 实现难度 | 适用场景 |
|------|:---:|:---:|------|
| **固定长度** | ⭐⭐ | ⭐ | 规范文档、快速原型 |
| **按句子** | ⭐⭐⭐ | ⭐⭐ | 通用场景 |
| **语义自适应** | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ | 高精度 RAG |
| **递归切片** | ⭐⭐⭐⭐ | ⭐⭐ | **生产推荐** |
| **Markdown 感知** | ⭐⭐⭐⭐ | ⭐⭐⭐ | 技术文档 |

```text
生产推荐组合：
  LangChain RecursiveCharacterTextSplitter + 10% overlap + 500-800 chunk_size
  → 覆盖 90% 的场景，效果稳定
```

## 核心要点回顾

- 切片粒度是 RAG 精度的关键变量 — 太粗太细都影响检索质量
- 递归切片（RecursiveCharacterTextSplitter）是生产首选
- 10-15% 重叠可有效避免边界信息丢失
- 语义自适应切片精度最高但实现复杂
- 不同文档类型需要不同的预处理管线
