## 1. 读写全景

数据分析的输入 = **把外部数据变成 DataFrame**（`pd.read_*` 家族），输出 = **把 DataFrame 存成文件**（`df.to_*` 家族）——**一个 read 函数 = 一套格式**——本课学四大格式（CSV/JSON/Excel/SQLite——覆盖 90% 场景），数据库与接口留到阶段 3（数据来源）。

## 2. read_csv 第一课

```python
import pandas as pd

df = pd.read_csv("titanic.csv")        # 读 CSV → DataFrame
df.head()                              # 看前 5 行（第一动作！）
df.info()                              # 列名/类型/非空计数（第二动作）
```

**read_csv 最常踩的五个坑**（新手 80% 报错都在这）：

| 坑 | 现象 | 解法 |
|------|------|------|
| 路径错误 | FileNotFoundError | 用绝对路径或 `os.chdir()` 到数据目录 |
| 编码不对 | UnicodeDecodeError | `encoding="utf-8"` 或 `"gbk"`（第 4 节） |
| 分隔符不对 | 一列变一串 | `sep=";"` 或 `sep="\t"`（制表符） |
| 首行不是表头 | 第一行成了数据 | `header=None` + 自己 `names=[...]` |
| 脏数据多 | 类型全变 object | `dtype` 指定 + 阶段 2 清洗 |

**读入后的三动作**（每次读数据都做）：`head()` 看长相、`info()` 看结构与缺失、`describe()` 看数值分布（阶段 2 深讲）——**"先看再算"是读数据的纪律**。

## 3. 四大格式对照

| 格式 | 特点 | 读 | 写 | 用途 |
|------|------|----|----|------|
| CSV | 纯文本、逗号分隔 | `read_csv` | `to_csv` | 通用交换格式（第一优先） |
| JSON | 嵌套结构、键值 | `read_json` | `to_json` | 接口数据/嵌套表 |
| Excel | 多 sheet、样式 | `read_excel` | `to_excel` | 业务报表/交付（需 openpyxl） |
| SQLite | 单文件数据库 | `read_sql` | `to_sql` | 结构化查询/大数据（阶段 3 深潜） |

**选型纪律**：**能 CSV 就 CSV**（最通用、无依赖、Git 友好）；**接口数据用 JSON**（`json_normalize` 展平嵌套——阶段 3）；**业务交付用 Excel**（`sheet_name` 参数选 sheet）；**结构化查询用 SQLite**（内存 → `sqlite:///:memory:`）。

```python
df.to_csv("out.csv", index=False, encoding="utf-8-sig")   # 写 CSV——index=False 是铁律！
```

**`index=False` 为什么是铁律**：默认会把行索引也写进文件（多一列无名列——重读回来全是脏数据）——**写出的文件要"能读回原样"**（写→读→对比 = 验证闭环）。

## 4. 编码与乱码

**编码是中文数据的第一杀手**——文件有编码、Python 有编码、终端有编码——**三处不一致 = 乱码**：

| 编码 | 是什么 | 什么时候用 |
|------|--------|-----------|
| UTF-8 | 全球标准（PEP 686 将成 Python 默认） | 新文件/接口/跨平台 |
| GBK/GB2312 | 中文旧标准（Windows 老文件） | 老 Excel/老 CSV 导出 |
| utf-8-sig | UTF-8 + BOM 头 | 写 CSV 给 Excel 打开（防乱码） |

**乱码排查三步**：先试 `utf-8` → 报错试 `gbk` → 还不行用 `errors="replace"` 看内容猜——**"编码是文件属性，不是猜的——看文件的来源约定"**（爬虫/数据库导出通常 UTF-8、老业务系统导出通常 GBK——`../../12-Python爬虫/阶段 1：前置基础（必备）/05-数据格式与编码.md` 的乱码四步法同样适用）。

## 5. 写入与导出

**导出铁律**（写给协作/交付的纪律）：

- **数据文件**：CSV + `index=False` + `encoding="utf-8-sig"`（Excel 友好）
- **报表文件**：Excel（`df.to_excel("report.xlsx", sheet_name="销售")`——多 sheet 用 `ExcelWriter`）
- **中间结果**：CSV 即可（JSON 只用于接口形态）
- **验证闭环**：导出后 `pd.read_csv` 读回对比（`df.equals`）——**"写出的文件必须能读回原样"**

## 6. read_csv 参数速查与大数据文件

**read_csv 高频参数**（记住这六个——覆盖 90% 场景）：

```python
df = pd.read_csv(
    "data.csv",
    sep=",",              # 分隔符（默认逗号——制表符用 sep="\t"）
    encoding="utf-8",     # 编码（乱码改 "gbk"——第 4 节）
    usecols=["id", "age", "fare"],   # 只读需要的列（省内存——最小化原则）
    nrows=1000,           # 只读前 1000 行（先摸数据——大文件试探）
    parse_dates=["date"], # 指定时间列（省得再转换）
    dtype={"id": "int32"},# 指定类型（省内存）
)
```

**大文件怎么读**（几十 GB 超出内存时——阶段 5 深潜，先立概念）：

```python
chunks = pd.read_csv("huge.csv", chunksize=100_000)   # 分块读
stats = [chunk["sales"].sum() for chunk in chunks]     # 逐块算再汇总
```

**分块心智**：**"算不动就分块、分块还不行就换工具"**（SQL/数据库——阶段 3 数据来源）——内存不是无限的，"一行装不下"是常态——**先 `nrows` 试探、再 `usecols` 瘦身、最后 `chunksize` 分块**——这是大数据三步曲。

**路径处理（pathlib）**：

```python
from pathlib import Path
DATA = Path("data") / "raw" / "titanic.csv"   # 跨平台路径（反斜杠/正斜杠通吃）
DATA.exists()                                 # True 先确认存在（防 FileNotFoundError）
```

**路径纪律**：**脚本里用相对路径 + 固定工作目录**（`os.chdir()` 或 Path——不写死 `D:\张三\桌面\...` 的绝对路径——换机器就废）；**文件名含日期/版本**（`sales_20260810.csv`——防覆盖）。

## 7. Excel 多 sheet 与 JSON 展平

**Excel 多 sheet 读写**（业务报表最常见——一个文件多个表）：

```python
# 读：指定 sheet
df = pd.read_excel("report.xlsx", sheet_name="销售")        # 按名取
all_sheets = pd.read_excel("report.xlsx", sheet_name=None)  # 全部 → 字典 {sheet名: df}

# 写：多 sheet
with pd.ExcelWriter("out.xlsx") as writer:      # with 自动保存关闭
    df_sales.to_excel(writer, sheet_name="销售", index=False)
    df_user.to_excel(writer, sheet_name="用户", index=False)
```

**JSON 展平**（接口数据是嵌套的——`json_normalize` 摊平）：

```python
data = [{"id": 1, "profile": {"age": 22, "city": "上海"}, "orders": [10, 20]}]
pd.json_normalize(data)                    # profile.age → 独立列（嵌套变平）
pd.json_normalize(data, record_path="orders", meta=["id"])   # 列表字段展开成多行
```

**JSON 心智**：**"接口返回的嵌套结构不是表，是树的切片"**——`json_normalize`（读嵌套）与 `record_path`（展开列表）是"树转表"的两把刀——阶段 3 数据来源深潜。

## 8. 读取的健壮性

**真实项目的数据文件没有完美的**——读取代码要能回答"文件坏了怎么办"：

```python
try:
    df = pd.read_csv("sales.csv", encoding="utf-8")
except UnicodeDecodeError:
    df = pd.read_csv("sales.csv", encoding="gbk")     # 编码降级重试
except FileNotFoundError:
    print("文件不存在——检查路径")                       # 显式报错不静默
```

**健壮性纪律**：**读文件是可预测异常**（一定会遇到——必须 try 兜底）；**"能降级就降级、不能就大声报错"**（编码可以降级重试、文件不存在必须大声说——**静默失败是数据管道最危险的 bug**）；**脚本化时读文件必包 try**（阶段 4 实战的数据管道要求——"数据管道不能一坏就崩且无人知"）。

**健壮性的三问**（写完读取代码自问）：文件不存在会怎样？编码不对会怎样？列不存在会怎样？（`usecols` 写了不存在的列——报错还是静默？——**答案是报错（KeyError）——这是好事：早暴露早修**）——**"健壮的代码不是不报错，是'该报错时报对的错'"**（该静默的降级、该响的报警——报错也是设计的一部分）。
