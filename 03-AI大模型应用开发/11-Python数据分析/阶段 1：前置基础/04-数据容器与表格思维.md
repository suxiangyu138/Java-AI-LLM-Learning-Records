## 1. 从容器到表格

上一课的容器是**一维**的（list 是一列数）——但真实数据是**二维**的：**行 = 样本（每个人/每笔订单）、列 = 特征（年龄/票价/性别）**——数据容器（list/dict）能表示一维，**二维表格需要新的心智**——这就是 DataFrame 的诞生理由（阶段 2 的主角，本课先建立"表格心智"）。

## 2. 二维表的三种 Python 表示

```python
# 方式一：列表套列表（行优先）
table = [[1, "男", 22], [2, "女", 35], [3, "女", 41]]
table[1][2]        # 35 —— 第 1 行第 2 列（索引易错）

# 方式二：字典套列表（列优先——数据分析推荐！）
data = {
    "id":   [1, 2, 3],
    "sex":  ["男", "女", "女"],
    "age":  [22, 35, 41],
}
data["age"]        # [22, 35, 41] —— 按列取，直观
```

**关键结论**：**"列优先"字典（列名 → 列值列表）是 DataFrame 的原型**——Pandas 的 `pd.DataFrame(data)` 一步就能把字典变成表格——**"会写列优先字典 = 已经会构造 DataFrame"**（阶段 2 的第一行代码）。

## 3. DataFrame 心智迁移

**DataFrame = 带标签的二维表**（`pd.DataFrame(data)` 创建）：

| | id | sex | age |
|---:|:---:|:---:|:---:|
| **0** | 1 | 男 | 22 |
| **1** | 2 | 女 | 35 |
| **2** | 3 | 女 | 41 |

**心智迁移四步**：**行 = 样本**（index 行索引——默认 0,1,2...）；**列 = 特征**（column 列名——id/sex/age）；**单元格 = 值**（`df.loc[1, "age"]` 按标签取）；**操作按"整列/整行"为单位**（`df["age"]` 取一列、`df["age"].mean()` 算列均值）——**"从'循环遍历每个值'升级为'整列思考'"**——这是阶段 2 Pandas 的核心思维（向量化——快 100 倍且代码更短）。

## 4. 表格四要素

一张好表（数据分析视角）必须说清四件事：

| 要素 | 含义 | 问自己 |
|------|------|--------|
| 样本 | 一行是什么 | 每行是一个人还是一笔订单？ |
| 特征 | 一列是什么 | 每列的单位是什么（元/岁/次）？ |
| 范围 | 表覆盖什么 | 时间范围？地区？抽样还是全量？ |
| 质量 | 数据可信吗 | 有缺失/重复/异常吗？（`06-数据类型与缺失值.md`） |

**"拿到任何表先答四要素"**——答不出 = 表还没看懂（这是 `02-数据分析全流程与心智模型.md` 问题卡的一部分）。

**表格思维的终极形态**：一张表 = 一个"可编程的视图"——**表是数据在分析中的"通用语言"**（CSV 读进来是表、SQL 查出来是表、接口数据展平后是表——万物皆可成表）——**"把一切数据变成表 = 分析的第一能力"**（阶段 3 数据来源就是在练这个——本课先立"表是通用语言"的心智）。

## 5. 表格思维 vs Excel 思维

| 维度 | Excel 思维 | 表格思维（DataFrame） |
|------|-----------|---------------------|
| 操作单位 | 单元格/选区（点选） | 整列/整组（代码表达） |
| 重复操作 | 拖拽公式 | 函数/流水线（可复用） |
| 大表 | 卡顿 | 内存计算（百万行级） |
| 可复现 | 手动操作不可回放 | 脚本即过程（回放/审计） |
| 协作 | 一人一文件 | 代码 + 数据（Git 可管） |

**迁移心法**：**"Excel 里你点过的每一个动作，都要能找到对应的代码"**（筛选 = `df[df.age > 30]`、求和 = `df["age"].sum()`、数据透视 = `groupby`——阶段 2 逐个对应）——**"不是 Excel 不好，是表格思维能自动化 Excel 的手工"**——Excel 继续用于看数/汇报，分析用 DataFrame（顶层主体系 `../02-数据分析三件套速查.md` 有速查对照）。

## 6. 长表 vs 宽表（表形选择）

真实数据的两种表形——**选错表形 = 分析处处别扭**：

| 表形 | 特征 | 什么时候用 |
|------|------|-----------|
| 宽表 | 一个指标多列（1 月/2 月/3 月各一列） | 人看的报表/Excel 展示 |
| 长表 | 一个指标多行（月份在"列"字段里） | **数据分析默认**（groupby/画图/透视都要长表） |

```python
# 宽表（人类友好）
#   id  1月  2月  3月
#    1   10   12   11

# 长表（分析友好——tidy data）
#   id  month  sales
#    1   1月     10
#    1   2月     12
#    1   3月     11
```

**tidy data 三原则**（数据分析的表形黄金标准）：每列一个变量、每行一个观测、每格一个值——**"你的数据是长表吗？"是阶段 2 分组分析前的第一问**——宽表转长表（`melt`）与长表转宽表（`pivot`）是阶段 2 必学操作——本课先建立"长表优先"的心智。

## 7. 索引与切片概念

**表格的"定位"体系**（阶段 2 的 `loc/iloc` 概念预演）：

```python
# 位置定位（第几行第几列——iloc）
# df.iloc[1, 2]      → 第 1 行第 2 列（数字索引，左闭右开）
# 标签定位（名字定位——loc）
# df.loc[1, "age"]   → 行标签 1、列名 age
```

**三条心智**：**行有"位置"和"标签"两套身份**（默认一致——重排后分裂）；**切片左闭右开**（`iloc[1:3]` 取 1、2 行——和 list 一致）；**列定位优先用名字**（`df["age"]` 比"第几列"可读——列名就是代码注释）。

## 8. 列名规范

**列名是表格的"API"**——数据分析第一规范（所有后续代码都引用列名）：

| 规范 | 好 | 坏 |
|------|----|----|
| 小写 + 下划线 | `survived` / `fare_usd` | `Survived?` / `Fare(USD)` |
| 无空格 | `passenger_id` | `passenger id` |
| 语义完整 | `ticket_price` | `tp` |
| 单位入名 | `fare_usd` / `age_years` | `fare`（元？美元？） |

**列名修正**（阶段 2 前先学会）：

```python
df.columns = [c.strip().lower().replace(" ", "_") for c in df.columns]   # 一行规范化
```

**列名纪律**：**"列名写错 = 代码全错"**（引用不存在列名直接 KeyError）；**拿到表先看列名**（`df.columns`——`05` 篇报错速查的 KeyError 解法）；**列名带单位**（`fare_usd` 让分析自文档化）。

> 🎯 **核心要点**：表格 = 行（样本）× 列（特征）——"列优先"字典是 DataFrame 原型；DataFrame 心智 = 整列思考（向量化——快且短）；表格四要素（样本/特征/范围/质量——拿到表先答）；Excel 思维 → 表格思维 = 从"点选"到"代码可复现"——**"数据分析的货币是表格——表格思维是第一课的核心迁移"**。
