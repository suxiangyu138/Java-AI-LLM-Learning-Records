## 1. 为什么数据分析用 Jupyter

数据分析是**探索式工作**（跑一步看一步——图表、中间结果随时可见）——普通 IDE 的"写完整个脚本再跑"不适合探索；Jupyter 的**单元格交互**（代码 + 结果 + 图表 + 笔记同屏）天生匹配——**"Jupyter = 探索的画布 + 记录的笔记本 + 交付的报告"**（一个文件三身份）——环境安装见 `01-Python环境与数据分析工具箱.md`（`jupyter lab` 启动，JupyterLab ≥4.5）。

## 2. 单元格模型

**Notebook = 单元格的序列**（两种基本类型）：

- **代码单元格**（Code）：写 Python——`Shift+Enter` 运行并进入下一格；输出（打印/表格/图）显示在单元格下方
- **Markdown 单元格**：写笔记/标题/说明——**数据分析笔记的主角**（记录"为什么这么做"——结论和代码一样重要）

```python
# 代码单元格——输出直接显示在下方
import pandas as pd
df = pd.read_csv("titanic.csv")
df.head()
```

**工程纪律**：**一个单元格一个主题**（读数据一格、清洗一格、分析一格——出错好定位）；**运行顺序 ≠ 书写顺序**（单元格可乱序执行——**"内核状态"是隐藏变量**：最坑的 bug 来源）；**"Restart & Run All"（重启清空重跑全部）是最佳自检**——能从头到尾跑通 = notebook 可信（这是面试展示的第一标准）。

## 3. Markdown 与输出

```markdown
# 泰坦尼克 EDA            ← 标题（一级）
## 1. 数据概览             ← 章节（二/三级）
**问题**：票价分布如何？    ← 加粗/斜体
- 样本 891 人、12 列      ← 列表
> 结论：票价右偏，多数人低于 30 美元   ← 引用（结论醒目）
`df.head()` 输出见上       ← 行内代码
```

**Markdown 纪律**：**先写问题再写代码**（`## 问题` → 代码 → `> 结论`——每个分析块都"问题-代码-结论"三段式）；**结论用引用块**（`>` 醒目——汇报时一眼看到）；**图表后必写一句话解读**（图不是成果，**"图的解读"才是成果**——`08-数据素养与伦理.md`）。

## 4. 魔法命令

**魔法命令 = `%` 开头的增强指令**（Jupyter 独有——`%` 行魔法、`%%` 单元格魔法）：

```python
%matplotlib inline      # 画图内嵌显示（Matplotlib 第一步——不执行图不显示！）
%time df.describe()     # 计时（性能分析）
%%timeit df.sum()       # 多次计时取均值（对比性能）
!pip list               # 执行 shell 命令（!开头）
%ls / %pwd              # 文件操作
%whos                   # 查看当前变量（排查"变量哪来的"）
```

**高频三件**：`%matplotlib inline`（画图必先执行——漏了图不显示）、`!pip install xxx`（缺包不退出 notebook 直接装）、`%time`（哪个步骤慢——性能第一诊断）。**注意**：魔法命令是 **IPython 专属**——普通 `.py` 文件里用不了（脚本里用 `# %%` 注释分节是另一套——VS Code 支持）。

## 5. 快捷键与效率

**必会快捷键**（鼠标流 → 键盘流的分水岭）：

| 快捷键 | 功能 | 说明 |
|--------|------|------|
| `Shift+Enter` | 运行当前格并下移 | 最高频 |
| `A` / `B` | 上方/下方插入单元格 | 命令模式下 |
| `M` / `Y` | 切换 Markdown / Code | 命令模式下 |
| `D D` | 删除单元格 | 连续按两次 D |
| `Ctrl+Enter` | 运行不移动 | 调试时 |
| `Esc` → `F` | 查找替换 | 命令模式 |

**效率纪律**：**先进入命令模式（Esc）再按字母键**（A/B/M/Y 都是命令模式快捷键——编辑模式下会打字母进代码——新手第一坑）；**保存靠自动**（Jupyter 自动保存，但重大节点 `Ctrl+S` 一下）。

## 6. 导出与交付

**导出三形态**（File → Save and Export Notebook As）：

- **HTML**：交付给非技术同事看（图表 + 结论完整呈现——**汇报主力**）
- **Markdown**：归档到知识库/博客（本课程笔记的产出格式）
- **.py 脚本**：把 notebook 转成可定时执行的脚本（自动化——主体系 `../10-数据报表与自动化.md`）

**交付纪律**：**导出前 Restart & Run All**（保证交付的是"能跑的结果"不是"历史偶然"）；**删除敏感输出**（个人数据/密钥——`08-数据素养与伦理.md` 隐私纪律）；**命名语义化**（`titanic_eda_v2.ipynb`——版本号是协作礼貌）。

## 7. 工作区管理与版本控制

**工作区纪律**（一个数据分析项目的目录规范）：

```text
my-analysis/
├── data/          ← 原始数据（只读不改！）
├── notebooks/     ← notebook 文件（titanic_eda.ipynb）
├── output/        ← 导出物（HTML/图片/清洗后数据）
└── requirements.txt   ← 环境锁（01 篇）
```

**三区纪律**：**原始数据永不修改**（清洗结果写到 output/——原始文件是"证据"，改了就说不清）；**notebook 归 notebooks/**（项目根目录不散放）；**输出物带版本**（`eda_v2.html`）。

**多 notebook 项目的组织**：一个分析项目可能有多个 notebook（清洗、探索、汇报分工）——**按"处理顺序"编号**（`01_clean.ipynb`、`02_explore.ipynb`、`03_report.ipynb`）——**"文件名即流程"**（读者按编号就能理解分析管线——阶段 4 实战项目的组织模板）。

**notebook 的 Git 问题**：`.ipynb` 是 JSON——**diff 难读**（一处改动一大片）；解决方案：**每个 notebook 一个文件、提交信息写明"第几轮分析"**；**敏感数据不进 Git**（`.gitignore` 加 `data/*.csv`——`08-数据素养与伦理.md` 隐私纪律）；**大输出清空再提交**（`Clear All Outputs`——输出可重跑、代码才入库）。

## 8. Notebook 十大戒律

1. **一个单元格一个主题**——出错好定位（`02` 节）
2. **先写问题再写代码**——Markdown 先行（`03` 节）
3. **图后必写解读**——图不是成果、解读才是（`03` 节）
4. **魔法命令画图先行**——`%matplotlib inline` 漏了图不显示（`04` 节）
5. **内核状态是隐藏变量**——重启清空重跑是最好的自检（`02` 节）
6. **导出前 Restart & Run All**——交付"能跑的结果"（`06` 节）
7. **原始数据永不修改**——清洗结果写 output/（`07` 节）
8. **文件名语义化 + 版本号**——`titanic_eda_v2.ipynb`（`07` 节）
9. **敏感输出不交付**——脱敏 + 不进 Git（`07` 节 + `08-数据素养与伦理.md`）
10. **一个项目一个目录**——data/notebooks/output/ 三区（`07` 节）

**戒律心智**：**notebook 是"作品"不是"草稿纸"**——观众（面试官/同事/未来的你）要能从头读到尾——**"能交付的 notebook = 每一个单元格都能说出为什么"**。
