## 1. 实验思维

**背景**：电商 App 想改"商品页按钮颜色/文案"，运营直觉"红色更醒目"——**拍脑袋上线上错呢？A/B 测试给答案**。

**实验思维（本项目核心）**：

```text
观察 vs 实验
├── 观察（前六项目）：看数据怎么说——相关性（漏斗流失、留存下降）
└── 实验（本项目）：控制变量、随机分组——因果性（改版导致转化提升）
    ——"观察回答'发生了什么'，实验回答'是不是因为它'——改版效果必须用实验验证"
```

**实验心智**：**"实验三要素：随机分组、对照组、预先设计"**——随机分组（用户 50/50 进 A 版/B 版——排除"想买的人刚好点了新版"的偏差）、对照组（B 版 = 老版本——没有对照的实验是自嗨）、**预先设计**（先定假设/指标/样本量再跑——**"实验最忌讳'跑完再想怎么分析'"**）；**本项目的"数据"用模拟生成**（`../阶段%203：数据来源（数据从哪里来）/08-数据模拟与合成.md`——真实的 A/B 数据是公司的，模拟数据练方法）。

## 2. 实验设计：先设计再跑

**实验设计文档（跑数据之前先写，六要素）**：

```text
实验设计卡
① 假设：红色按钮（A）转化率 > 蓝色按钮（B）
② 主指标：支付转化率（唯一主指标！其他指标只作参考）
③ 分组：50/50 随机（按 user_id 哈希分桶）
④ 最小可检测提升 MDE：相对提升 10%（太小测不出，太大不值得做）
⑤ 样本量：先算（下节）——决定实验要跑多久
⑥ 时长：≥14 天（跑满 2 个完整业务周期——周效应）
```

```python
# 模拟实验数据（真实场景来自埋点表：user_id, variant, converted）
import numpy as np
import pandas as pd

rng = np.random.default_rng(42)
n_per_group = 5000
conv_b, conv_a = 0.20, 0.22        # 对照组 20%，实验组 22%（+10% 相对提升）

data = pd.DataFrame({
    "user_id": np.arange(1, 2 * n_per_group + 1),
    "variant": ["A"] * n_per_group + ["B"] * n_per_group,
})
data["converted"] = data["variant"].map(
    lambda v: rng.binomial(1, conv_a if v == "A" else conv_b))
```

**设计心智**：**"一个实验一个主指标"**——盯 10 个指标总会有一个"碰巧显著"（多重比较陷阱——**"主指标是实验的宪法，其他指标是参考消息"**）；**MDE 是实验的'分辨率'**——想测出 1% 的提升需要几万人，测 10% 只需要几千人——**"先定分辨率再算样本量，顺序不能反"**；**时长 ≥ 2 个完整周期**（周效应/月初效应——"跑 3 天的实验结论不可信"）。

## 3. 样本量计算

**实验前必算样本量（power analysis——2026 年实验分析的第一纪律）**：

```python
from scipy.stats import norm
import math

def required_n(baseline, mde_rel, alpha=0.05, power=0.8):
    """算每组所需样本量：baseline 对照转化率、mde_rel 相对提升、α 显著水平、power 检验力"""
    p1 = baseline * (1 + mde_rel)              # 实验组预期转化率
    p0 = baseline
    z_a = norm.ppf(1 - alpha / 2)              # 1.96（双侧）
    z_b = norm.ppf(power)                      # 0.84
    p_pool = (p0 + p1) / 2
    n = ((z_a * math.sqrt(2 * p_pool * (1 - p_pool))
          + z_b * math.sqrt(p0 * (1 - p0) + p1 * (1 - p1))) ** 2 / (p1 - p0) ** 2)
    return math.ceil(n)

n = required_n(baseline=0.20, mde_rel=0.10)
print(f"每组需要 {n} 人（总 {2 * n}），按日均 500 新用户约 {2 * n / 500:.0f} 天")   # 每组约 4600 人
```

**样本量心智**：**"样本量 = 检验力（power）的保障"**——标准配置 **α=0.05（5% 假阳性）、power=0.8（80% 检出率）**——power 不足的实验（20-30%）会漏掉真实效果——**"power 0.8 的含义：效果真实存在时，80% 的概率能测出来"**；**样本量决定实验时长**（算出来 5000 人/组，日均 500 人 → 10 天——**"实验不是'跑两周'，是'跑到样本量够'"**）；**MDE 越小样本量越大**（想测 5% 提升是 10% 的 4 倍人）——**"业务决策需要多小的提升，样本量就是多少"**。

## 4. 检验与分析

**数据跑完，先体检再检验**：

```python
# ① 体检：分组是否 50/50（样本量失配 = 分流故障，先修再分析）
counts = data.groupby("variant")["user_id"].count()
print(counts, counts["A"] / counts["B"])          # 应接近 1.0

# ② 比率检验：两组转化率
from statsmodels.stats.proportion import proportions_ztest

conv = data.groupby("variant")["converted"].agg(["sum", "count"])
z, p = proportions_ztest(count=conv["sum"], nobs=conv["count"])
print(f"A {conv['sum']['A']/conv['count']['A']:.1%} vs "
      f"B {conv['sum']['B']/conv['count']['B']:.1%}, p = {p:.4f}")

# ③ 连续指标（客单价等）用 t 检验：Welch（equal_var=False——方差不假设相等）
from scipy.stats import ttest_ind
# t, p = ttest_ind(group_a["revenue"], group_b["revenue"], equal_var=False)
```

**检验心智**：**"比率指标（转化率）用 z 检验/卡方，连续指标（金额）用 t 检验"**——`proportions_ztest` 吃汇总数（count/nobs——不用构造大布尔数组）；**`equal_var=False`（Welch）是连续指标的标准姿势**（A/B 组方差很少相等——2026 实践共识）；**p < 0.05 是'统计显著'的门槛**——**"p 值回答'差异是不是碰巧'，不回答'差异有没有用'"**（效应量见下节——**"p=0.001 但提升 0.3%——显著但没用"**）。

## 5. 效应量与置信区间

**2026 年实验报告的标准：p 值 + 效应量 + 置信区间三件套**：

```python
# 效应量（比率差的置信区间——差异的可信范围）
from statsmodels.stats.proportion import proportion_confint
from statsmodels.stats.proportion import confint_proportions_2indep

nA, xA = conv["count"]["A"], conv["sum"]["A"]
nB, xB = conv["count"]["B"], conv["sum"]["B"]
pA, pB = xA / nA, xB / nB
lo, hi = confint_proportions_2indep(xA, nA, xB, nB)
rel = (pA - pB) / pB
print(f"绝对提升 {pA-pB:.2%}（相对 {rel:.1%}），95% CI [{lo:.2%}, {hi:.2%}]")

# Cohen's d（连续指标的效应量）
# d = (mean_a - mean_b) / pooled_std；d > 0.2 才有实际意义
```

**效应量心智**：**"报告三件套：p 值（显著吗）+ 效应量（多大）+ CI（可信范围）"**——CI 不跨 0 = 显著且幅度可信（"提升 1.5%-3.5%"——**"CI 给的是'提升的范围'，比单个点估计诚实得多"**）；**效应量看'有没有用'**——转化率相对提升 10%（1.5pp 以上）才算值得上线——**"统计显著 ≠ 业务显著"**（2026 实验报告共识——"p 值是守门员，效应量是裁判"）。

## 6. 常见陷阱与结论报告

**实验分析的四大经典陷阱（写进报告就是专业度）**：

1. **偷看（peeking）**——每天看结果、一显著就停——**"偷看会让假阳性率暴涨到 20%+——预先定样本量/时长，到点才看"**
2. **多重比较**——盯 10 个指标，总有一个碰巧显著——**"只报主指标，其他标注'探索性'"**
3. **样本量失配**——53/47 不是 50/50——**"分流有问题，先修再分析"**
4. **过早停止**——跑 3 天就下结论——**"周效应没跑完的结论不可信"**

**结论报告**：

```markdown
# A/B 测试分析报告：红色按钮 vs 蓝色按钮

## 结论
1. 结果：A 组转化率 22.1% vs B 组 20.0%，绝对提升 2.1pp（相对 +10.5%），
   p=0.011（统计显著），95% CI [0.5%, 3.7%]——跨过 1.5pp 的决策线，建议上线。
2. 稳健性：主指标显著；客单价（探索性指标）无显著差异；无异常分流（50.1/49.9）。
3. 建议：全量上线 A 版本；2 周后复测留存确认无副作用；后续可做文案 + 颜色的叠加实验。

## 局限
实验 14 天（2 个完整周期）；模拟数据演示方法，真实结论需真实数据；
未覆盖移动端（本次仅 Web 端）。
```

**报告心智**：**"实验报告 = 结果（数字）+ 稳健性（体检）+ 决策（上不上线）"**——"p=0.011 且 CI 不含 0"是"显著"的完整证据链；**"inconclusive（无结论）是合法结论"**——样本量没跑够/效果太小测不出——**"实验没测出显著 ≠ 没有效果，可能是效果小于 MDE——说'再跑大样本'比硬编结论专业"**；**上线前问三件事**：效应够不够大（业务线）、有没有副作用（留存复测）、样本够不够（power）。

## 7. 本节验收

**验收动作**：① 写实验设计卡（六要素）；② 算样本量并定实验时长；③ 模拟数据完成体检 + 检验 + 效应量三件套；④ 报告含陷阱检查（偷看/多重比较/失配/早停）——**"设计 + 样本量 + 检验 + 效应量 = 实验分析能力"**——**练习纪律**：先写设计卡再碰数据——"没设计的实验是掷骰子"。

> 🎯 **核心要点**：高级项目七 = 科学方法——观察给假设、实验给证据（随机分组/对照组/预先设计）；实验设计六要素（主指标唯一/MDE 分辨率/时长≥2 周期）；**样本量 power analysis（α=0.05、power=0.8——先算样本再定时长）**；检验选型（比率 z 检验/连续 Welch t 检验）；**报告三件套（p 值 + 效应量 + CI——统计显著 ≠ 业务显著）**；四大陷阱（偷看/多重比较/失配/早停）+ inconclusive 是合法结论——**"p 值是守门员，效应量是裁判"**。
