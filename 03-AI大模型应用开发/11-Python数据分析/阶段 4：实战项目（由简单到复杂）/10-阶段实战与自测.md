## 1. 毕业项目：自选主题完整交付

**毕业项目 = 不给你数据、不给你题目——自己选题、自己找数据、自己做完**（01 篇方法论的总验收）：

```text
毕业项目选题方向（三选一）
├── 方向 A（电商/用户）：用户复购预测 + 分层运营建议（综合 03/04/07/09 篇）
├── 方向 B（金融/时序）：某指数趋势分析 + 策略回测（综合 05 篇 + 阶段 3 API）
└── 方向 C（自由命题）：自己感兴趣的领域（体育/教育/政务数据——真实兴趣才有深度）
```

**毕业项目验收标准（七步闭环全部走完 + 三件套交付）**：

```markdown
# 毕业项目自检清单
- [ ] ① 问题卡：一个核心问题 + 边界（"不做的事"写清）
- [ ] ② 数据：真实数据（公开数据集/API/自采——阶段 3 六路）+
        来源卡（许可/时间/口径——阶段 3 09 篇）
- [ ] ③ 清洗：流水线每步留理由 + 前后行数留痕
- [ ] ④ 分析：至少三种方法（分组/时序/漏斗/分层任选）+ 一图一结论
- [ ] ⑤ 结论：三段式（现象→原因→建议）+ 局限
- [ ] ⑥ 交付：代码 + 报告 + README（作品集条目）+ Git 提交
- [ ] ⑦ 复盘：收获/卡点/下一步——写进 README 末尾
```

**毕业项目心智**：**"毕业项目 = 你给面试官的第一印象"**——选题建议：**真实数据 > 模拟数据、有结论 > 炫技、能讲清 > 分数高**（"面试官不问'模型多少分'，问'为什么这么做'——**'做得完 + 讲得清'比'做得炫'重要"**）；**项目不求大**——"用户复购预测"做到"清洗+特征+基线模型+评估"就够完整——**"完整的小项目 > 烂尾的大项目"**。

## 3. 报错速查 10 条

| 报错/现象 | 原因 | 解法 |
|---------|------|------|
| `ValueError: operands could not be broadcast` | 数组形状不匹配 | 检查列/Series 长度（常见：`pd.cut` 后和 df 对齐问题） |
| `KeyError: 'xxx'` | 列名/索引名错 | `df.columns` 打印核对（merge 后列名带后缀 `_x/_y` 了） |
| `SettingWithCopyWarning` | 链式赋值 | 用 `df.loc[条件, 列] = 值`（阶段 2 02 篇） |
| `DataConversionWarning` | 类型隐式转换 | 显式 `astype`/`to_numeric` |
| 时间序列画图横轴乱序 | 日期没解析/没排序 | `to_datetime` + `sort_values`（05 篇时序四步） |
| `ImportError: No module named 'akshare'` | 环境没装 | 检查 venv（阶段 1 环境课）——`pip install akshare` |
| AKShare 接口报错/空返回 | 源站改版/版本旧 | `pip install -U akshare`（锁版本 + 看官方文档变更说明） |
| `NaN` 进模型报错 | 特征还有缺失 | 建模前 `X.isna().sum()` 检查（09 篇——模型不吃 NaN） |
| 随机森林结果每次不同 | 没设 random_state | 所有模型/切分设 `random_state=42`（09 篇铁律） |
| 实验 p 值巨大/永远不显著 | 样本量不够 | 回头做 power analysis（08 篇——先算样本再跑） |

**报错心智**：**"项目报错和练习报错是同一批报错"**——速查表里 10 条覆盖了项目型报错的 80%——**"报错不可怕，可怕的是不记——把新报错加进自己的速查表"**（阶段 3 10 篇同款纪律）。

## 5. 面试演练

**项目面试的标准问答范式（每个项目都能讲 3 分钟）**：

**Q1：挑一个你最满意的项目讲讲？**——答：**"我做了用户复购预测项目——背景是运营需要'该给谁发券'的名单；数据是 XX 数据集（来源卡记录许可与口径）；清洗重点解决 X 问题（缺失/口径）；分析发现复购与 X 强相关；模型用逻辑回归做基线（准确率 0.78），随机森林提升到 0.82（AUC 0.86）；结论是建议运营按'模型概率 + 成本线'圈名单；局限是样本量小、预测≠因果"**——结构：**背景 → 数据 → 方法 → 数字 → 结论 → 局限**——"六段式 = 面试项目的万能骨架——每个数字都要能回答'怎么来的'"。

**Q2：做数据分析你遇到过最难的坑？**——答：**"漏斗分析时'埋点覆盖率'没验证，差点把漏报当真实流失——后来加了对账（事件数 vs 数据库订单数），发现漏报 15%——教训是'先验证数据完整性再做分析'——现在我每个项目第一件事是体检+对账"**——结构：**坑（具体）→ 发现（怎么发现）→ 修复（怎么解决）→ 沉淀（成了什么习惯）**——"面试官要的是'复盘能力'，不是'完美的坑'"。

**Q3：你怎么证明你的分析是靠谱的？**——答：**"四个层面：① 数据层——来源卡+体检+对账（行数/口径核对）；② 方法层——结论跟数据走，写不清的写'无法判断'；③ 验证层——因果结论要有实验设计（A/B），相关结论写清是相关；④ 交付层——结论三段式+局限明示"**——**"靠谱不是'都对'，是'每个判断都有依据、每个局限都说在前面'"**。
