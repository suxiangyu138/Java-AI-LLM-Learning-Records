## 1. 背景与管道思维

**背景**：某信息站每天更新一批"房价挂牌数据"，公司想"每天早上自动拿新数据、存库、出日报"——**这就是数据管道（pipeline）**。

**管道思维（本项目核心心智）**：

```text
一次分析 vs 数据管道
├── 一次分析：手动拿数据 → 分析 → 出报告 → 结束（前三项目）
└── 数据管道：采集器自动跑 → 数据入库 → 增量更新 → 定时分析 → 报告自动出
    ——"一次分析是手工活，管道是自动化生产线"
```

**管道心智**：**"管道 = 把'拿数据'从'人肉操作'变成'程序每天自动做'"**——管道五要素：**采集（怎么拿）→ 存储（放哪）→ 增量（只拿新的）→ 分析（出什么）→ 调度（什么时候跑）**——本项目的价值：**"数据管道是分析师的'资产管理'——管道跑起来，你的数据天天在涨、报告天天在出"**（面试讲"我搭过自动化数据管道"是中级分析师的分水岭）。

## 2. 管道架构四环节

```text
数据管道架构
├── ① 采集器（fetch.py）——定时抓取新数据（API/网页——阶段 3 05/06 篇）
├── ② 存储（SQLite 表）——数据落库（唯一键防重——爬虫阶段 3 的 UNIQUE 思路）
├── ③ 增量逻辑——每次只拿"上次之后"的新数据（断点续采）
└── ④ 分析器（report.py）——对全库数据出周期报告（03 篇模板的函数化）
```

**架构心智**：**"四环节各司其职，每环节一个脚本/函数"**——`fetch.py`（拿）→ `store.py`（存）→ `report.py`（分析）——**"管道设计的第一原则：环节解耦——采集器挂了不影响已有数据，分析器重跑不重复采集"**；存储选 SQLite（单文件、零配置——`../阶段%203：数据来源（数据从哪里来）/04-数据库读取.md` 的本地库首选）——**"管道先跑通再谈分布式——单机 SQLite 够用 99% 的个人项目"**。

## 3. 采集与存储

```python
# fetch.py——采集器（以公开 API 为例；静态网页用 pd.read_html 同思路——阶段 3）
import requests, pandas as pd

def fetch_new(page=1, per=50):
    resp = requests.get("https://api.example.com/listings",
                        params={"page": page, "per": per}, timeout=(3, 15))
    resp.raise_for_status()
    return pd.json_normalize(resp.json()["data"])   # JSON → DataFrame（阶段 3 05 篇）

# store.py——存储（建表 + 唯一键去重）
import sqlite3
from sqlalchemy import create_engine

engine = create_engine("sqlite:///data/listings.db")
def init_db():
    with engine.begin() as conn:     # 建表（UNIQUE 唯一键 = 去重的数据库级兜底）
        conn.exec_driver_sql("""
            CREATE TABLE IF NOT EXISTS listings (
                id TEXT PRIMARY KEY,       -- 唯一键：源头 id
                title TEXT, price REAL, date TEXT,
                fetched_at TEXT
            )""")

def store(df):
    df.to_sql("listings", engine, if_exists="append", index=False)
```

**采集存储心智**：**"唯一键（PRIMARY KEY/UNIQUE）是管道去重的第一道防线"**——源头给的 `id` 就是唯一键——**"重复采集不可怕，可怕的是重复入库"**（爬虫阶段 3 的 UNIQUE-INSERT 策略——`../../../12-Python爬虫/阶段%203：数据存储/`）；`to_sql` 一次入库、`if_exists="append"` 追加——**"存储层做对，增量逻辑才省心"**。

## 4. 增量更新：断点续采

**核心：每次只拿"上次之后"的数据**：

```python
# fetch 前先读断点（上次采到哪）
import json, os

MARK_FILE = "data/checkpoint.json"
def load_checkpoint():
    if os.path.exists(MARK_FILE):
        return json.load(open(MARK_FILE))     # {"last_id": "xxx", "last_date": "2026-08-09"}
    return {}

def fetch_incremental():
    cp = load_checkpoint()
    new_rows = []
    page = 1
    while True:
        batch = fetch_new(page=page)
        if batch.empty:
            break
        # 只保留"比断点新"的数据（id 或时间断点——阶段 3 04 篇）
        fresh = batch[batch["id"] > cp.get("last_id", "")]
        if fresh.empty and page > 1:
            break                              # 这一页没有新的 = 拿到头了
        new_rows.append(fresh)
        page += 1
    if new_rows:
        all_new = pd.concat(new_rows)
        store(all_new)
        json.dump({"last_id": all_new["id"].max()}, open(MARK_FILE, "w"))  # 更新断点
    print(f"本次新增 {len(all_new) if new_rows else 0} 条")
```

**增量心智**：**"断点（checkpoint）是增量的灵魂"**——记住"上次拿到哪"，下次只拿新的——**"断点必须持久化（文件/表），进程重启不能丢"**（阶段 3 04 篇的 watermark 概念落地）；**id 断点比时间断点稳**（防迟到数据——"id 单调递增是天生的好断点"）；**分页拿数据时"本页没有新数据就停"**——避免翻到最后页——**"增量逻辑写对，管道天天跑也轻快"**。

## 5. 管道数据与周期分析

**分析器对全库数据出报告（03 篇模板的函数化复用）**：

```python
# report.py——分析器
import pandas as pd

def daily_report():
    df = pd.read_sql("SELECT * FROM listings", engine)
    df["date"] = pd.to_datetime(df["date"])

    latest = df["date"].max()                       # 最新一天
    today = df[df["date"] == latest]
    yesterday = df[df["date"] == (latest - pd.Timedelta(days=1))]

    report = f"""# 房价挂牌日报（{latest.date()}）
- 累计挂牌：{len(df):,} 条（数据管道运行 {df['date'].nunique()} 天）
- 今日新增：{len(today)} 条 | 均价 {today['price'].mean():,.0f}
- 环比：均价 {'↑' if today['price'].mean() > yesterday['price'].mean() else '↓'}
  {today['price'].mean():,.0f} vs {yesterday['price'].mean():,.0f}
"""
    open(f"reports/daily_{latest.date()}.md", "w", encoding="utf-8").write(report)
    return report
```

**分析心智**：**"管道积累的数据 = 时间序列"**——每天 append 的数据自然长成趋势分析素材（`df['date'].nunique()` 是管道健康度指标——"管道跑了多少天，数据就有多长"）；**报告模板参数化**（日期自动、环比自动）——**"周期报告写一次，天天自动出"**；**管道数据也要体检**——每天检查 `len(today)` 与昨日对比（突然 0 条 = 采集器挂了——**"数据量突变是管道的第一报警信号"**，监控见下节）。

## 6. 调度与监控

**管道要"自动跑 + 看得见"**：

```text
调度与监控
├── 调度：Windows 任务计划程序 / Linux cron（每天 08:00 跑 fetch → report）
│   cron 示例：0 8 * * * cd /path && python pipeline.py >> logs/run.log 2>&1
├── 监控：三件事
│   ① 数据量：今天新增 0 条 → 报警（采集挂了）
│   ② 日志：每次运行写 log（成功/失败/新增条数）
│   ③ 断点检查：checkpoint 日期是否"今天"（没更新 = 没跑）
└── 重跑：管道失败后重跑不产生重复数据（唯一键 + 断点兜底）
```

**调度心智**：**"管道跑起来是第一步，看得见是第二步"**——日志（每次运行留痕——`../阶段%203：数据来源（数据从哪里来）/07-日志与半结构化文本.md` 的日志解析反过来用：先写日志）；**"新增 0 条"报警**是管道监控的核心信号（数据源改版/网络挂了都会表现为 0 条——**"数据量为 0 的第一反应：检查源，不是检查分析"**）；**幂等重跑**（唯一键去重 + 断点更新——重跑不重复）——**"管道设计得好，失败只是重跑一次的事"**。
