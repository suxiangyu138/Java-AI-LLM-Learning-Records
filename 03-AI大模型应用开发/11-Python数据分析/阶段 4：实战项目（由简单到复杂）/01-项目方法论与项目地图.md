## 1. 项目七步闭环

**一个"完整的数据分析项目"不是"跑通代码"——是七步闭环走完**：

```text
项目七步闭环
① 定义问题：问什么？（一个项目只回答一个问题——问题定义决定成败 50%）
② 获取数据：数据从哪来？（阶段 3 的六路来源）
③ 清洗加工：数据能用吗？（缺失/类型/异常）
④ 探索分析：数据在说什么？（分组/聚合/对比）
⑤ 得出结论：答案是什么？（结论三段式：现象→原因→建议）
⑥ 交付呈现：怎么讲给人听？（报告/图表/看板）
⑦ 复盘沉淀：学到了什么？（归档/复盘/下一步）
```

**闭环心智**：**"七步缺一步，项目就是残的"**——最常见的残：跳过 ① 直接拿数据乱跑（没有问题的分析是流水账）、跳过 ⑥（结论只在 notebook 里没人看）、跳过 ⑦（做完不归档等于白做）——**"项目 = 从问题出发，回到问题解决"**；注意 ①②③④ 是**可循环的**——分析到一半发现数据不够/问题要细化，回头改问题卡很正常（阶段 1 的 EDA 七步可迭代同款——`../阶段%201：前置基础/02-数据分析全流程与心智模型.md`）——**"闭环不是直线，是螺旋——每转一圈离答案更近"**。

## 2. 项目分级：由简单到复杂

**本阶段的 8 个项目按"复杂度阶梯"排好**，每级解决"上一级的短板"：

| 级别 | 项目 | 复杂度来源 | 练的核心能力 |
|:---:|------|-----------|-------------|
| 入门 | 02 泰坦尼克完整分析 | 单文件、已知数据 | 全流程走通 + 报告 |
| 入门 | 03 销售报表分析 | 文件 + 业务指标 | 业务思维（指标怎么算） |
| 初级 | 04 用户行为漏斗 | 多来源 + 事件数据 | 漏斗思维 + 流失诊断 |
| 初级 | 05 金融时序分析 | 外部 API + 时序 | 数据获取 + 时序建模 |
| 中级 | 06 数据管道项目 | 采集+存储+自动化 | 管道思维（不是一次分析） |
| 中级 | 07 经营 Dashboard | 多表 + 指标体系 | 指标体系 + 交互呈现 |
| 高级 | 08 A/B 测试分析 | 统计设计 + 推断 | 实验思维（科学方法） |
| 高级 | 09 ML 项目入门 | 特征工程 + 建模 | 预测思维（衔接阶段 5） |

**分级心智**：**"项目复杂度跟着能力走，别跳级"**——泰坦尼克没做利索直接做 A/B 测试，会两头空——**"每级项目练一个'新肌肉'，前一级的肌肉是后一级的支撑"**；复杂度来源总结成一句话：**单文件 → 多文件 → 多来源 → 外部数据 → 自动化 → 交互 → 推断 → 预测**——"从'有什么分析什么'到'设计实验验证假设'，就是分析师到科学家的距离"。

## 3. 交付三件套

**每个项目必交付三件套**（本阶段所有篇目的验收标准）：

1. **代码**——可复现的 notebook/脚本（分节注释，重跑能出同样结果——种子/版本固定）
2. **报告**——人话写的结论（Markdown/PDF——**"报告是给决策者看的，不是给自己看的"**——结论三段式：现象→原因→建议）
3. **作品集条目**——README（一句话项目介绍 + 数据来源 + 结论摘要 + 图表截图 + 运行方式）——**"作品集条目 = 项目的简历"**

**三件套心智**：**"代码证明你会做，报告证明你会讲，作品集条目证明你会交付"**——面试官看项目，先看 README（30 秒判断你做没做过真项目），再翻代码（判断代码习惯），最后听你讲（判断业务思维）——**"三件套是给面试官准备的，也是给三个月后的自己准备的"**；报告结构模板：**背景（为什么做）→ 数据（从哪来/怎么处理）→ 分析（怎么查的）→ 结论（发现了什么）→ 建议（怎么办）→ 局限（哪里不完美）**——"有局限的报告比完美的报告更可信"。

## 4. 作品集意识

**作品集 = 你作为分析师的"证据链"**——2026 年求职市场，**项目作品比证书更能说服面试官**：

```text
作品集四件套（毕业时应该攒齐）
├── 9 个项目（本阶段 8 个 + 毕业项目 1 个）
├── 每个项目三件套（代码/报告/作品集条目）
├── 作品集索引（README 总览——按难度/方向排列）
└── GitHub 主页（代码托管 + README 展示——面试官的第一站）
```

**作品集心智**：**"做完一个归档一个，毕业时自然成型"**——归档动作三件事：**代码进 Git（带 commit 历史——过程也是证据）、报告转 PDF、README 写清楚**（02 篇实操）；**作品集不是堆数量**——8 个同质化的销售分析不如"入门 2 + 初级 2 + 中级 2 + 高级 2"的梯度——**"作品集的含金量 = 梯度 × 深度 × 讲得清"**；**每个项目都要能讲 3 分钟**（背景→方法→结论→数字——面试问答的标准结构，10 篇会练）。

## 5. 练习 5 题

1. 项目七步闭环是哪七步？最常见的"残"是哪几步？
2. 为什么说"没有问题的分析是流水账"？
3. 四级项目各自练什么核心能力？
4. 交付三件套是什么？报告的核心结构？
5. 作品集四件套是什么？为什么"梯度"比"数量"重要？

## 6. 本节验收

**验收动作**：① 默写七步闭环；② 对照四级表格给自己定"现在该做哪级"；③ 规划毕业项目方向（主题/数据来源/问题）并写进问题卡——**"闭环 + 分级 + 三件套 = 项目心智建立"**——**练习纪律**：从 02 篇起，每个项目都按七步走、都交付三件套——"方法论不练，只是听了十个字"。

> 🎯 **核心要点**：项目七步闭环（定义问题→获取→清洗→分析→结论→交付→复盘——①⑥⑦ 是最常残的三步）；四级项目由简单到复杂（单文件→多源→自动化→推断→预测）；交付三件套（代码/报告/作品集条目——报告结论三段式 + 写局限）；作品集意识（9 项目 + 索引 + GitHub——梯度比数量重要）——**"会做分析和会做项目是两回事——项目 = 代码 + 讲得清的故事"**。
