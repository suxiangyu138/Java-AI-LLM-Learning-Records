## 1. 业务背景与问题

**背景**：某连锁零售公司给运营团队一份 2026 年 1-7 月销售明细（每行一笔订单），要"月度经营分析报告"——**这就是分析师最常见的工作形态：报表分析**。

**问题卡**：

```text
问题卡
- 核心问题：7 个月经营状况如何？哪些方面需要运营关注？
- 子问题 1：GMV 月度趋势——增长还是下滑？有季节性吗？
- 子问题 2：哪些商品/品类贡献最大？（TOP 分析与二八法则）
- 子问题 3：哪些区域表现差？（区域对比）
- 不做的事：预测下月销量（那是 09 篇 ML 的事）；归因分析（无实验数据）
```

**背景心智**：**"报表分析的问题来自业务方，但问题卡要自己写"**——业务方说"做个月报"，你要翻译成"3 个子问题"——**"把模糊需求翻译成可分析问题，是分析师的第一生产力"**；数据用模拟生成（`../阶段%203：数据来源（数据从哪里来）/08-数据模拟与合成.md` 的业务模拟——也可以找真实公开数据，但本项目重点是"分析流程"，模拟数据可复现、可验收。

## 2. 指标体系：先定指标再算数

**报表分析的第一件事不是写代码，是定指标**——指标是分析的"语言"：

```text
销售分析核心指标
├── GMV（成交总额）= Σ订单金额——总量指标
├── 订单量 = COUNT 订单——规模指标
├── 客单价 = GMV / 订单量——质量指标（人均花多少）
├── 复购率 = 二次及以上购买用户 / 总用户——健康指标
└── 品类占比 = 品类 GMV / 总 GMV——结构指标
```

**指标心智**：**"先定义、再计算、口径要写死"**——`客单价`是"GMV/订单量"还是"GMV/用户数"？口径不同结论不同（`../阶段%203：数据来源（数据从哪里来）/09-数据质量与来源管理.md` 的数据契约——**"指标口径是分析师的合同条款"**）；**指标之间要配合看**——"GMV 涨了"要看是"订单量涨了"还是"客单价涨了"（前者是拉新有效，后者是客单提升——运营动作完全不同）——**"单看一个指标会骗人，指标组合讲真话"**。

## 3. 数据获取与清洗

```python
import pandas as pd

df = pd.read_csv("data/raw/sales_2026_01to07.csv", encoding="utf-8-sig",
                 dtype={"order_id": "str"})          # 订单号防科学计数法（03 篇的坑）

# 体检
print(df.shape, df.isna().sum(), df.duplicated().sum())

# 清洗流水线
df["order_date"] = pd.to_datetime(df["order_date"])    # ① 日期解析
df["amount"]     = pd.to_numeric(df["amount"], errors="coerce")  # ② 金额类型
df = df.dropna(subset=["amount"])                      # ③ 金额缺失删行（带理由：无法分析的订单）
df["month"] = df["order_date"].dt.to_period("M")       # ④ 造月份列（聚合钥匙）

# ⑤ 指标计算
gmv   = df["amount"].sum()
orders = df["order_id"].nunique()                      # 注意：不是 len(df)！
aov   = gmv / orders                                   # 客单价
print(f"GMV {gmv:,.0f} / 订单 {orders} / 客单价 {aov:.0f}")
```

**清洗心智**：**"订单数用 `nunique()` 不是 `len()`"**——一笔订单可能多行（多商品）——**"数据里'一行'和'一单'的区别，是报表分析的第一个细节"**；**日期解析后立刻造 month 列**（`dt.to_period("M")`——聚合的钥匙，07 篇时序课的日常操作）；**每步清洗留痕**（02 篇的纪律延续——"金额缺失 3 行已删，占比 0.1%，不影响结论"）。

## 4. 月度趋势与 TOP 分析

```python
# 月度 GMV 趋势（月度聚合——groupby + 排序铁律）
monthly = df.groupby("month")["amount"].sum().sort_index()

# 环比变化（shift——阶段 2 时序课）
monthly_growth = monthly.pct_change().round(3)
print(monthly, monthly_growth)

# TOP 商品（贡献度——二八法则验证）
top = df.groupby("product")["amount"].sum().sort_values(ascending=False).head(10)
top_share = top.sum() / df["amount"].sum()
print(f"TOP10 商品贡献 {top_share:.0%} 的 GMV")    # 接近 80%？→ 二八法则

# 可视化
import matplotlib.pyplot as plt
monthly.plot(kind="bar")
plt.title("GMV 月度趋势：6 月回落 12%，7 月回升")
plt.ylabel("GMV（万元）"); plt.tight_layout()
```

**趋势心智**：**"趋势分析三看：看方向（涨跌）、看幅度（环比%）、看异常（哪个月不对劲）"**——"6 月回落 12%"要结合业务解释（大促透支？季节性？——**"数字给现象，业务给解释"**）；**TOP 分析验证二八法则**（"80% 的 GMV 来自 20% 的商品"——验证用 `head(10).sum() / total`——**"二八法则是结论，验证它要有数字"**）；**排序铁律：`sort_values` 显式排序**（groupby 结果默认按键排，但 TOP 分析必须 `ascending=False` 显式写）。

## 5. 品类与区域分析

```python
# 品类结构（占比 + 同比环比）
cat = df.groupby("category")["amount"].agg(["sum", "count"])
cat["share"] = cat["sum"] / cat["sum"].sum()

# 品类 × 月度（二维——发现品类趋势差异）
cat_month = df.pivot_table(index="category", columns="month",
                           values="amount", aggfunc="sum")
# 热力图或折线看：哪些品类在增长、哪些在萎缩

# 区域对比（门店/区域 + 客单价）
region = df.groupby("region").agg(gmv=("amount", "sum"),
                                  orders=("order_id", "nunique"))
region["aov"] = region["gmv"] / region["orders"]
# 区域排名 + 客单价——哪个区域"卖得多但客单低"？
```

**结构心智**：**"品类分析回答'结构怎么变'，区域分析回答'哪差为什么'"**——**pivot_table 是品类×月度的标准工具**（`../阶段%202：核心三大库（必学）/Pandas%20—%20数据分析主力库/04-分组聚合groupby.md`——透视表是报表分析的主力武器）；**区域客单价对比能发现"薄利多销"vs"高客单"两类市场**——"华东客单价 200 但订单少，华北客单价 120 订单多——运营策略要分别定"——**"对比不是排名，是找差异背后的原因"**。

## 6. 结论与建议

**报告结论（三段式——02 篇模板直接复用）**：

```markdown
# 2026 年 1-7 月销售分析报告（摘要版）

## 结论
1. 现象：GMV 累计 1.2 亿，6 月环比回落 12%，7 月回升 8%；TOP10 商品贡献 GMV 的 71%。
2. 原因：6 月回落与 618 大促透支相关（对比去年同期需验证）；品类维度：数码类增长最快（+23%）。
3. 建议：① 8 月备货向 TOP10 倾斜（二八法则落地）；② 华东区域客单高但订单少——投放大促；
③ 建立周报机制（模板见下节）持续监控 6 月式回落。

## 局限
仅有 7 个月数据，季节性判断样本不足；无去年同期数据，6 月回落原因待验证；
复购率未计算（数据缺用户标识）。
```

**建议心智**：**"建议必须可执行、有对象、有数字"**——"备货向 TOP10 倾斜"（有对象：供应链）、"华东投放大促"（有对象：运营）——**"不给建议的分析是半成品，给空泛建议的分析是次品"**；**局限写清"为什么没算"**——"复购率未算因缺用户标识"——**"说明局限的原因，比只写局限更专业"**。

## 7. 周期报告模板

**报表分析的高频形态是"每周/每月重复"——做成模板**：

```python
def monthly_report(month: str, raw_path: str) -> None:
    """生成指定月份销售报告：读取→清洗→指标→图表→Markdown"""
    df = pd.read_csv(raw_path, encoding="utf-8-sig")
    df["order_date"] = pd.to_datetime(df["order_date"])
    df["month"] = df["order_date"].dt.to_period("M")
    mdf = df[df["month"] == month]
    # ...指标计算与图表（同上）...
    report = f"# {month} 销售月报\n\nGMV：{gmv:,.0f} ..."   # 模板渲染
    open(f"reports/{month}_report.md", "w", encoding="utf-8").write(report)

monthly_report("2026-07", "data/raw/sales_2026.csv")
```

**模板心智**：**"周期报表 = 函数化 + 参数化"**——"每月 1 号跑一次 `monthly_report(当月)`"——**"报表分析的最高境界是'下次不用再写'"**；再进一步就是 06 篇的**自动化管道**（定时跑 + 自动发）——**"本项目的模板是管道的雏形"**；模板交付时同步交付"模板使用说明"（参数/依赖/输出——给同事看）。
