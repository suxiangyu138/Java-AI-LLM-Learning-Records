## 1. dtype 是什么

**dtype（data type）= 数组元素的类型**——`np.array` 创建时自动推断，也可显式指定——**"dtype 是数组的'合同'：每个元素必须遵守"**——它是 NumPy 快的根源（定长连续内存——01 篇）——**"列表可以混类型，数组不可以——这就是数组的纪律"**。

## 2. dtype 家族

| dtype | 含义 | 字节 | 范围/说明 |
|-------|------|:---:|---------|
| `int8/16/32/64` | 有符号整数 | 1/2/4/8 | 数字越大范围越大（int64: ±9.2×10^18） |
| `uint8/16/32/64` | 无符号整数 | 1/2/4/8 | 非负（图片像素 0-255 用 uint8） |
| `float16/32/64` | 浮点 | 2/4/8 | float64 = 默认双精度（科学计算标准） |
| `bool` | 布尔 | 1 | True/False（掩码的默认类型——05 篇） |
| `complex64/128` | 复数 | 8/16 | 信号/傅里叶（阶段 3 预演） |
| `str`/`object` | 字符串/对象 | 变长 | 数组里出现它 = 失去速度优势 |

**心智**：**数据分析三件套够用**——整数 `int64`（默认）、小数 `float64`（默认）、布尔 `bool`（掩码）；**`int32`/`float32` 用于省内存**（大数组 08 篇）；**出现 `object` 类型 = 数组失去向量化优势**（该用 Pandas 或先转换）。

## 3. 内存账本

**内存 = size × 每元素字节**（02 篇 nbytes 的展开）：

```python
arr_i64 = np.zeros(10_000_000, dtype="int64")     # 1000 万元素
arr_i32 = np.zeros(10_000_000, dtype="int32")
arr_f32 = np.zeros(10_000_000, dtype="float32")

arr_i64.nbytes / 1e6   # 80 MB
arr_i32.nbytes / 1e6   # 40 MB（int32 省一半！）
arr_f32.nbytes / 1e6   # 40 MB
```

**账本心智**：**省内存的顺序**：**先看"够不够精度"再看"省多少"**——整数计数用 int32 足够（20 亿内）就省一半；**float64 → float32 省一半但精度降**（价格/比例用 float64 稳妥——精度陷阱第 5 节）；**`nbytes` 是体检指标**（怀疑内存问题时先看它——阶段 4 实战的大数据场景）。

## 4. astype 转换

```python
arr = np.array([1, 2, 3])          # int64
arr.astype(float)                  # [1. 2. 3.] float64（复制转换）
arr.astype("float32")              # 指定精度
arr.astype(str)                    # 转字符串（['1' '2' '3']）
np.array([1.2, 2.9]).astype(int)   # [1 2]（截断——不是四舍五入！）
```

**转换心智**：**`astype` 默认复制**（不改变原数组——要生效需赋值 `arr = arr.astype(...)`）；**float → int 是截断不是四舍五入**（`2.9 → 2`——要四舍五入先 `np.round` 再 astype——高频陷阱）；**str ↔ 数值**（`astype(float)` 转不了会报错——先清洗——`../../阶段 1：前置基础/06-数据类型与缺失值.md` 的 to_numeric 纪律在 numpy 里同样成立）。

## 5. 精度陷阱

**浮点不精确是 IEEE 754 的本质**——三个经典陷阱：

```python
0.1 + 0.2 == 0.3        # False！（0.30000000000000004）
np.float32(0.1) + np.float32(0.2)  # 误差更大（float32 精度低）

# 正确比较：用容差
np.isclose(0.1 + 0.2, 0.3)        # True（绝对 + 相对容差）
np.allclose(arr1, arr2)           # 数组版 isclose（比较数组的正确姿势）

# 大数陷阱
1e16 + 1 == 1e16                 # True！（大数精度不足——小数被吞）
```

**精度心智**：**"浮点相等比较是陷阱——永远用 `np.isclose`/`np.allclose`"**（== 比较浮点 = 自找 bug）；**float64 是默认不是因为"更准"，是"更不易踩坑"**（float32 的累积误差在统计计算里会显形）；**大数 + 小数会丢**（1e16 级数据用归一化/减均值——阶段 3 统计预演）。

## 6. nan 与 inf

```python
arr = np.array([1.0, np.nan, 3.0])     # nan = 缺失（04 篇认知的数组版）

arr.mean()          # nan！（nan 传染——默认传播）
np.nanmean(arr)     # 2.0（忽略 nan 求均值）
np.isnan(arr)       # [False True False] 掩码找 nan（阶段 1 的 isna 同款）

np.inf              # 无穷（除零产生——np.array([1]) / 0 → inf 警告）
np.isinf(arr)       # 找 inf
```

**nan/inf 心智**：**nan 传染在数组里同样成立**（聚合函数遇 nan 返回 nan——**用 `np.nan*` 家族**：nanmean/nansum/nanstd）；**`np.isnan` 是唯一正确的判断方式**（`arr == np.nan` 永远 False——和阶段 1 的 isna 同款纪律）；**除零得 inf 不是报错**（是警告 + inf——**先查除数为 0 的场景**）。

## 8. 类型选择决策与 astype 场景

**类型选择的决策树**（"这列数据该用什么 dtype"）：

```text
数据是什么？
├── 整数计数（人数/次数/库存）→ int64（默认）/ int32（省内存）
├── 小数（价格/比例/分数）→ float64（默认——精度优先）
├── 布尔（是否/通过失败）→ bool（1 字节——掩码默认）
├── 类别（性别/舱位/地区）→ object 或 category（Pandas 篇——数组里用 object）
└── 图片像素（0-255 非负整数）→ uint8（图像处理的标准）
```

**astype 高频场景表**（什么情况转什么）：

| 场景 | 转换 | 为什么 |
|------|------|--------|
| 省内存（大数组） | int64→int32、float64→float32 | 省一半内存（04 篇账本） |
| 模型输入 | object→float64 | 机器学习要数值（阶段 5） |
| 图片处理 | float→uint8 | 像素是 0-255 整数 |
| 掩码转换 | 任意→bool | 条件判断标准化 |
| 输出字符串 | 数值→str | 拼接/展示 |

**选择心智**：**"先精度后内存"**（价格/比例永远 float64——float32 的累积误差会在统计里显形）；**"省内存先体检"**（`nbytes`/`memory_usage` 确认是内存问题再降档——不优化不存在的瓶颈——08 篇性能纪律）；**"转换是显式行为"**（`astype` 的结果要赋值才生效——`arr = arr.astype(...)`——忘了赋值 = 白转）。

**dtype 在协作中的角色**（类型不是数组的私事）：**Pandas 的列类型 = numpy dtype**（`df["age"].dtype` 就是底层数组的 dtype——本课认知直接迁移——`../../阶段 1：前置基础/06-数据类型与缺失值.md` 的 Pandas 类型体系 = dtype 的表版）；**read_csv 的 dtype 参数**（`pd.read_csv(..., dtype={"age": "int32"})`——读时就定类型省内存——`../../阶段 1：前置基础/05-数据读写与文件格式.md` 参数速查）；**模型输入的类型要求**（scikit-learn 要 float64——`X.astype(float)` 是机器学习流水线的常规操作——阶段 5 预演）——**"类型是数据流通的'货币'——转换是协作的日常"**——astype 不是麻烦，是"换货币"——**"会选 dtype、会换 dtype = 数据流通无阻"**。

**精度的面试题**："浮点比较为什么不能用 =="——标准答法：**"浮点数是二进制近似存储——0.1 无法精确表示——0.1+0.2 得到 0.30000000000000004——所以 == 比较浮点不可靠——正确用 np.isclose（绝对 + 相对容差）或 np.allclose 比较数组"**——答题结构：**原理 → 现象 → 解法**——"面试考的不是 0.1+0.2 这个数，是'知不知道浮点不精确的本质'"——补一句"float64 是默认也是因为这个——精度优先"显示体系感。

**一句话记住**：dtype 定内存与精度（int64/float64 默认——object 出现 = 失去向量化）——**"浮点比较用 isclose、nan 统计用 nan* 家族、astype 转换要赋值"**——类型是数据流通的货币（float32 省一半内存——精度足够才用——先精度后内存）。

## 9. 本节验收

**验收动作**：① 建三个数组（int64/float32/bool）打印 nbytes 对比；② `astype` 三连（int→float、float→int 看截断、str→float 看报错）；③ `np.isclose` 验证 `0.1+0.2`；④ 造含 nan 数组用 `np.nanmean` 对比 `mean`——**"账本会算 + 精度陷阱亲眼见 = 类型层通过"**——**练习纪律**：精度实验（isclose 对比 ==）亲手做一遍——**"亲眼见过 0.1+0.2 的尾巴，才会记得用 isclose"**——nbytes 账本题算完打印验证（"算的"和"跑的"一致才算对）。

> 🎯 **核心要点**：dtype = 数组合同（同质是快的根源）；家族速查（int64/float64 默认——object 出现 = 失去向量化）；内存账本（size × 字节——int32/float32 省一半——先看精度再看省）；astype 复制转换（float→int 截断不四舍五入）；精度陷阱（浮点 == 必用 isclose/allclose——大数吞小数）；nan/inf（nan 传染用 nan* 家族——isnan 是唯一判断）——**"dtype 决定内存与精度——选错类型是隐性 bug"**。
