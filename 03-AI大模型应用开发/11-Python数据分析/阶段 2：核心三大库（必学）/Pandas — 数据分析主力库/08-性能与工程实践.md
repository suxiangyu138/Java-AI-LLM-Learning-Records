## 1. 性能纪律

**Pandas 性能三纪律**（`../NumPy — 数值计算底层库/08-与Pandas协作与性能.md` 的表版）：

1. **能向量化就不 apply**（np.where/算术/布尔——06 篇实测 100 倍级）
2. **能整列就不逐行**（`df["a"] * 2` 不是循环——NumPy 心智延续）
3. **能内建就不手写**（`value_counts/nlargest/groupby` 都是 C 实现——手写循环是自残）

**测量先行**：

```python
%time df["age"].apply(lambda a: a * 2)      # 慢——先测
%time df["age"] * 2                          # 快——对比
%time df.groupby("Sex")["Survived"].mean()   # 内建——通常没问题
```

**纪律心智**：**"优化前先 %time 测量"**（不测就优化 = 猜——`../../阶段 1：前置基础/07-Jupyter Notebook 实战.md` 的魔法命令）；**"慢的 90% 是 apply/循环"**（先查这两个再查别的）；**"内建函数优先"**（Pandas 的 groupby/value_counts 都是 C 级优化——**手写循环永远比不过内建**）。

## 2. category 类型

**category = 分类类型（重复字符串的省内存之王）**：

```python
df["sex"] = df["sex"].astype("category")     # 转分类
df["sex"].cat.categories                     # 类别列表
df["sex"].cat.codes                          # 编码（0/1——内部）

# 省内存实测
df = pd.DataFrame({"city": ["北京"] * 1_000_000 + ["上海"] * 1_000_000})
df.memory_usage(deep=True)["city"]           # ~170MB（字符串——每个都存全量）
df["city"] = df["city"].astype("category")
df.memory_usage(deep=True)["city"]           # ~2MB（只存类别 + 编码——省 80 倍！）
```

**category 心智**：**"重复多的字符串列 → category 省 10-100 倍内存"**（只存唯一值 + 整数编码——内部就是 `cat.codes`）；**category 还有排序语义**（`astype(pd.CategoricalDtype(categories=["低","中","高"], ordered=True))`——有序分类——分析比字符串快）；**groupby 按 category 更快**（C 级分组）；**注意**：category 列做数值运算要先转回（`astype(int)` 前先看 `cat.categories`）。

## 3. 内存体检

```python
df.info(memory_usage="deep")          # 每列类型 + 内存（含字符串实际大小）
df.memory_usage(deep=True)            # 每列内存明细
df.memory_usage(deep=True).sum() / 1e6   # 总内存（MB）

# 瘦身三件套（03 篇清洗的延伸）
df["price"] = df["price"].astype("float32")    # 1. 降档（省一半）
df["age"] = df["age"].astype("int32")          # 2. 整数降档
df["city"] = df["city"].astype("category")     # 3. 分类化（省最多）
```

**体检心智**：**"怀疑内存问题先 `info(memory_usage="deep")`"**（deep=True 才统计字符串真实大小——默认不算——第一坑）；**瘦身顺序：先 category 再降档**（重复字符串列 category 收益最大——先捡大西瓜）；**"先精度后内存"**（价格/比例保持 float64——省内存不能牺牲正确性——`../NumPy — 数值计算底层库/04-dtype与数值类型.md` 的纪律延续）。

## 4. 链式操作 vs 中间变量

**长流水线的两种写法**——权衡可读性与调试性：

```python
# 链式（Pandas 风格——一行到底——可读但难调试）
result = (
    df[df["age"] > 18]
    .groupby("Sex")
    .agg(avg_fare=("Fare", "mean"))
    .reset_index()
    .sort_values("avg_fare", ascending=False)
)

# 中间变量（调试友好——每步可查）
adults = df[df["age"] > 18]
by_sex = adults.groupby("Sex").agg(avg_fare=("Fare", "mean"))
result = by_sex.reset_index().sort_values("avg_fare", ascending=False)
```

**写法心智**：**"探索阶段用中间变量（每步打印验证）、交付阶段可收敛成链式"**（中间变量 = 调试便利、链式 = 代码整洁——**先中间后链式**）；**链式括号风格**（`(df.xxx.xxx.xxx)` 包一层——可读性关键——每步换行）；**链式里的陷阱**（链式筛选后赋值 = 02 篇的坑——**"链式只读不改"**——要改值拆出来用 loc）。

## 5. 大文件与分块

**表放不下内存时的三板斧**（`../../阶段 1：前置基础/05-数据读写与文件格式.md` 的三步曲落地）：

```python
# 1. 只读需要的（usecols——省最大）
df = pd.read_csv("huge.csv", usecols=["id", "age", "fare"], dtype={"age": "int32"})

# 2. 分块处理（chunksize——逐块算再汇总）
chunks = pd.read_csv("huge.csv", chunksize=100_000)
total = 0
for chunk in chunks:
    total += chunk["sales"].sum()          # 每块算、累加
print(total)

# 3. 换工具（SQL/数据库——阶段 3 数据来源）
# pd.read_sql("SELECT sum(sales) FROM t", engine)
```

**分块心智**：**"先 usecols 瘦身、再 dtype 降档、最后 chunksize 分块"**（三步曲——能瘦身就不分块——分块是最后手段）；**分块 = 逐块聚合再合并**（`for chunk` 循环每块算——**"算不动就分块、分块还不行就换 SQL"**）；**SQL 是终极大文件方案**（`read_sql` 把聚合推给数据库——阶段 3 数据来源深潜）。

## 7. 工程检查单与面试题

**工程化检查单**（大表/慢代码的排查清单——逐条过）：

1. ☐ **apply 换成向量化了吗？**（np.where/算术/布尔——06 篇）
2. ☐ **循环换成内建了吗？**（groupby/value_counts 是 C 级）
3. ☐ **字符串重复列转 category 了吗？**（省 10-100 倍内存）
4. ☐ **dtype 降档了吗？**（int64→int32、float64→float32——先精度后内存）
5. ☐ **只读需要的列了吗？**（usecols——省最大）
6. ☐ **测量了吗？**（%time 优化前后对比——不测不优化）
7. ☐ **内存体检了吗？**（info(memory_usage="deep")）

**面试题**："Pandas 处理大数据慢/内存爆怎么办？"——答：**"三步曲——先 usecols 只读需要的列、再 dtype 降档（float32/int32/category）、最后 chunksize 分块逐块聚合——还不行换 SQL（把聚合推给数据库）——另：能向量化就不 apply（快 100 倍级）——先 %time 测量再优化"**——**答题结构：三板斧（读/类型/分块）→ 升级（SQL）→ 优化纪律（测量）**——"从读数据到运算全覆盖 = 完整答法"。

**练习延伸**：`memory_usage(deep=True)` 和默认的区别？（deep 统计字符串真实大小——默认只算对象引用——**"不 deep 的体检是假的"**——08 篇第 3 节）。

**实战场景**（本课知识在真实分析里的位置）：**"性能与工程是'真实规模'的考验"**——课堂数据几万行随便跑，**生产数据百万行起步**：**亿级日志/订单**（`usecols` 只读需要的列——内存立省 70%）；**重复字符串大表**（地区/设备型号列——`category` 省 80 倍——`info(deep=True)` 体检后立竿见影）；**每日增量处理**（`read_csv(chunksize)` 分块 + 每块处理——定时任务的标准姿势——阶段 4 实战）；**慢查询**（`%time` 定位——apply 换向量化——"慢的 90% 是 apply/循环"）——**"课堂能跑 ≠ 生产能跑——性能意识是职业分水岭"**——面试讲项目时"我处理过 500 万行——用了 category 和分块"是重量级加分。

**工程心态的校正**：**"优化不是炫技，是'让分析跑得动、跑得快、跑得可复现'"**——**跑得动**（内存不爆——category/降档）、**跑得快**（时间可接受——向量化）、**跑得可复现**（代码即过程——`../../阶段 1：前置基础/07-Jupyter Notebook 实战.md` 的 Restart & Run All）——**"性能优化的终点不是快，是'生产可交付'"**——09 篇毕业报告的工程部分就是这三条。
