## 1. 拼表全景

**真实数据 90% 来自多张表**（用户表 + 订单表 + 商品表）——拼表是分析师的日常——**拼表三选**：**上下拼（concat——行变多）**、**按键拼（merge——列变多）**、**变形拼（melt/pivot——长宽互换）**——**"先想'我要行变多还是列变多'，再选函数"**。

## 2. concat 堆叠

```python
# 上下堆叠（行变多——同结构表合并）
df_jan = pd.read_csv("sales_jan.csv")
df_feb = pd.read_csv("sales_feb.csv")
df_all = pd.concat([df_jan, df_feb], ignore_index=True)   # 行拼（列需一致）

# 左右拼接（列变多——同索引表并排）
df_meta = pd.read_csv("users_meta.csv")
df_full = pd.concat([df_jan, df_meta], axis=1)            # axis=1 列拼

# ignore_index 为什么重要
pd.concat([df_a, df_b])                # 索引 0,1,2,0,1,2 重复！
pd.concat([df_a, df_b], ignore_index=True)   # 0,1,2,3,4,5 干净
```

**concat 心智**：**默认行拼（axis=0）、axis=1 列拼**（和 NumPy 的 concatenate 同款——`../NumPy — 数值计算底层库/07-数组操作与变形.md` 的认知直接迁移）；**`ignore_index=True` 是铁律**（不写 = 索引重复——后续操作全乱）；**行拼要求列结构一致**（列名对不上会生成 NaN 列——先 `df.columns` 对比）。

## 3. merge 连接

**merge = SQL join 的 Pandas 版**（按共同键拼列）：

```python
orders = pd.DataFrame({"order_id": [1, 2, 3], "user_id": ["a", "b", "c"], "amount": [100, 200, 300]})
users  = pd.DataFrame({"user_id": ["a", "b", "d"], "name": ["张三", "李四", "王五"]})

df = orders.merge(users, on="user_id", how="inner")   # 按键连接（inner = 交集）
#    order_id user_id  amount name
# 0         1       a     100  张三
# 1         2       b     200  李四

# how 四种：inner 交集 / left 左表全留 / right 右表全留 / outer 并集
orders.merge(users, on="user_id", how="left")    # 订单全留（用户缺失 = NaN）——最常用！
orders.merge(users, on="user_id", how="outer")   # 都留（匹配不上的 NaN）
```

**merge 心智**：**`on` 指定连接键**（不写 on = 灾难——自动用共同列名或笛卡尔积——**"不写 on 的 merge 是灾难"**）；**how 四种语义**（**left 最常用**——"主表全留、辅表补充"——订单为主就 left）；**键名不同用 left_on/right_on**（`orders.merge(users, left_on="user_id", right_on="id")`）；**一对多合并会复制行**（一个用户多个订单 → 用户信息重复——正常现象——"合并后行数会变"）。

## 4. 长宽表转换

**tidy data 的钥匙**（`../../阶段 1：前置基础/04-数据容器与表格思维.md` 的长表优先——现在会转换了）：

```python
# 宽表 → 长表（melt——分析前的标准动作）
wide = pd.DataFrame({"id": [1, 2], "1月": [10, 20], "2月": [15, 25]})
long = wide.melt(id_vars="id", var_name="month", value_name="sales")
#    id month  sales
# 0   1    1月     10
# 1   2    1月     20
# 2   1    2月     15
# 3   2    2月     25

# 长表 → 宽表（pivot——透视/展示用）
wide2 = long.pivot(index="id", columns="month", values="sales")
```

**melt 心智**：**melt = "把多列折叠成一列"**（`id_vars` 保留的列、`var_name` 新列名（原列名）、`value_name` 新值列（原值）——**"宽表进、长表出——列名变成数据"**）；**pivot = melt 的逆操作**（index/columns/values 三参数——和 pivot_table 的区别：pivot 无重复、pivot_table 有重复时聚合——`../../阶段 1：前置基础/04-数据容器与表格思维.md` 的 tidy data 三原则在这里可操作化）；**Seaborn 要长表**（`../Matplotlib  Seaborn — 数据可视化/05-Seaborn统计可视化.md` 的"给 Seaborn 喂长表"——melt 就是喂食器）。

## 5. 拼表常见问题

| 问题 | 现象 | 解法 |
|------|------|------|
| 索引重复 | concat 后索引 0,1,2,0,1,2 | `ignore_index=True` |
| merge 行爆炸 | 行数远超预期 | 检查连接键是否唯一（`duplicated`） |
| 键名不同报错 | KeyError | `left_on/right_on` 指定 |
| 拼出 NaN 列 | 列结构不一致 | 先对齐列名（`df.columns` 对比） |
| 列名冲突 | 两表都有 `name` | `suffixes=("_左", "_右")` 参数 |
| 笛卡尔积 | 没写 on 的 merge | **永远写 on** |

**问题心智**：**"拼表报错/异常 = 先看键"**（连接键是否唯一、是否写 on）；**"拼表后必验证"**（`shape` 前后对比——行数符合预期吗——**"拼完先看行数——多一行少一行都要知道为什么"**）。

## 7. merge 速查与面试题

**merge 参数速查表**（本课收口——连接四件套）：

| 参数 | 作用 | 例子 |
|------|------|------|
| `on` | 共同键（**必写**） | `on="user_id"` |
| `how` | 连接方式 | `"inner"/"left"/"right"/"outer"` |
| `left_on/right_on` | 键名不同时 | `left_on="uid", right_on="id"` |
| `suffixes` | 列名冲突 | `suffixes=("_订单", "_用户")` |
| `validate` | 校验关系 | `validate="one_to_many"`（防行爆炸） |

**面试题**："merge 和 concat 的区别？"——答：**"concat 是堆叠——默认行拼（axis=0）或列拼（axis=1）——不涉及键的匹配；merge 是连接——按共同键匹配行（SQL join 语义）——how 决定保留哪边（left 主表全留）——merge 要写 on、concat 要 ignore_index"**——**答题结构：堆叠 vs 连接 → 各自关键参数 → 场景**——"补一句'一对多合并会复制行'显示对行数变化的认知"。

**练习延伸**：`merge` 和 SQL 的 `JOIN` 什么关系？（inner = INNER JOIN、left = LEFT JOIN——**"会 Pandas merge 就懂 SQL join 一半"**——阶段 3 数据来源的 SQL 预演）。

**实战场景**（本课知识在真实分析里的位置）：**"拼表是分析师的第一道真实考题"**——业务数据的经典拼表场景：**订单 × 用户**（订单表 + 用户表 `merge(on="user_id", how="left")`——订单为主补用户信息）；**明细 × 维度**（销售明细 + 商品维度表——补品类/价格）；**月度表堆叠**（12 个月 CSV `concat(ignore_index=True)`——年度分析）；**宽表转长表**（多列指标 `melt` → 长表 → groupby/Seaborn）——**"真实分析 90% 从两张表开始"**——面试讲项目时"我 merge 了订单和用户表得到完整视图"是标准流程。

**拼表的业务纪律**：**"拼表前先想'主表是谁'"**（订单为主就 how="left" 订单全留——反了会丢订单）；**"一对多合并前先想'会复制行吗'"**（一个用户多订单——merge 后用户信息重复——正常但要知道）；**"拼完必验证"**（`shape` 前后对比 + `isna().sum()` 查拼出的缺失——**"拼表的验收 = 行数对得上、缺失看得懂"**——09 篇报告里 merge 结果要先验证再分析）。

**一句话记住**：拼表三选（concat 行变多/merge 列变多/melt 变形）——**"不写 on 的 merge 是灾难、不写 ignore_index 的 concat 索引乱"**——left 连接主表全留、一对多复制行正常——**"拼完先看行数——多一行少一行都要知道为什么"**。

**melt 面试补充**："宽表和长表什么时候转换？"——答："**分析前转长表**（groupby/Seaborn 都要长表——`../../阶段 1：前置基础/04-数据容器与表格思维.md` 的 tidy data）、**交付/展示时转宽表**（pivot 透视——人看报表方便）——**"长表给机器分析、宽表给人看"**"——09 篇实战的 merge 验证（shape + isna 检查）就是本课"拼完必验证"的落地——**"拼表能力 = 分析师的第一道真实考题——面试的 merge 题必考 how 语义"**（inner/left/right/outer 四选一要能说出区别和场景——**"left = 主表全留、inner = 只留匹配"**是两句话速记——背下来面试不慌，笔试不懵）。

## 8. 本节验收

**验收动作**：① 造两个月销售表 concat（带 ignore_index 验证索引）；② 造订单 + 用户两表做 merge（left 连接——对比 inner）；③ 造宽表 melt 成长表再 pivot 回去；④ 故意制造一次"不写 on 的 merge"看结果——**"三拼 + 一坑 = 合并层通过"**——**练习纪律**：拼表后必打印 shape 验证行数——"拼完先看行数"。

> 🎯 **核心要点**：拼表三选（concat 行变多/merge 列变多/melt 变形——**先想行还是列再选函数**）；concat 铁律（ignore_index=True——列结构一致）；merge = SQL join（on 必写、how 四选、left 最常用、left_on/right_on 键名不同、一对多复制行正常）；melt 宽转长（列名变数据——Seaborn 的喂食器）；pivot 逆操作——**"拼完先看行数——不写 on 的 merge 是灾难"**。
