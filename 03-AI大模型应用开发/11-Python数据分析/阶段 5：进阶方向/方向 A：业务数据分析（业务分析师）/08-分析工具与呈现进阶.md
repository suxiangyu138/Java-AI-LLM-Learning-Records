## 1. 工具全景：各司其职

**2026 业务分析师工具栈（岗位要求总结）**：SQL（必备——窗口函数/多表/调优）、Python（pandas/统计）、Excel（透视表/复杂函数）、BI（至少精通一款）、AI 工具（2026 新增要求）——**分工**：

```text
工具分工
├── SQL：从数仓取数（数据量大的主场——亿级数据只有 SQL 拉得动）
├── Python：深度分析（清洗/建模/批处理——本知识库的前四个阶段）
├── Excel：临时快查（小数据/老板随手要数字/透视表 3 分钟出结果）
├── BI：周期报表与自助分析（仪表盘让业务自己看——阶段 4 07 篇 Streamlit 的公司版）
└── AI：效率加速（SQL 生成/报告初稿/方法建议——2026 岗位明确要求）
    ——"工具不是越多越好，是'场景匹配'——取数用 SQL、深挖用 Python、看板用 BI"
```

**工具心智**：**"分析师的工具观：什么顺手用什么，什么快用什么"**——"老板要个数字用 Excel 3 分钟给；要深度归因用 Python 半小时做；要天天看的上 BI 仪表盘"——**"工具的尊严在场景，不在炫技"**；**SQL 是业务分析师的第一工具**（2026 岗位硬要求：窗口函数、复杂查询、多表关联、调优）——**"Python 是'深加工'，SQL 是'原材料'——不会 SQL 的分析师拿不到原料"**。

## 2. SQL 窗口函数

**窗口函数 = 2026 业务分析师的"必修高数"**——解决"分组内排名/对比"问题（普通 GROUP BY 做不到的）：

```sql
-- 场景 1：每个品类 GMV 排名（ROW_NUMBER——分组内排名）
SELECT category, product,
       SUM(amount) AS gmv,
       ROW_NUMBER() OVER (PARTITION BY category ORDER BY SUM(amount) DESC) AS rn
FROM orders
GROUP BY category, product
ORDER BY category, rn;

-- 场景 2：同环比（LAG——取上一期/去年同期值）
SELECT month, SUM(amount) AS gmv,
       LAG(SUM(amount), 1) OVER (ORDER BY month) AS prev_month,   -- 环比
       LAG(SUM(amount), 12) OVER (ORDER BY month) AS prev_year    -- 同比
FROM orders GROUP BY month ORDER BY month;

-- 场景 3：累计占比（SUM OVER——帕累托/ABC 的 SQL 版）
SELECT product, SUM(amount) AS gmv,
       SUM(SUM(amount)) OVER (ORDER BY SUM(amount) DESC) AS cum_gmv  -- 累计
FROM orders GROUP BY product;
```

**窗口心智**：**"窗口函数三件套：RANK 系列（排名）、LAG/LEAD（前后对比）、SUM/AVG OVER（累计滚动）"**——覆盖业务分析 80% 的"分组内计算"需求；**与 GROUP BY 的区别**：GROUP BY 每组分一行（折叠），窗口函数保留每行明细 + 附加计算列——**"GROUP BY 是折叠，窗口函数是附加"**；**窗口函数的性能**：大数据集上比 Python 快（在库里算——"SQL 能算的别拉回 Python"——阶段 3 04 篇的纪律）；练习：`ROW_NUMBER` vs `RANK` vs `DENSE_RANK` 的区别（并列排名——面试高频）。

## 3. BI 工具

**BI 工具（Tableau/Power BI/FineBI/Quick BI 等）解决"周期报表 + 自助分析"**——2026 岗位要求"至少精通一款"：

```text
BI 工具选型（按公司场景）
├── Tableau：交互最强/最贵——外企与数据团队标配
├── Power BI：微软生态/Excel 衔接好——国内企业普及率高
├── FineBI/Quick BI：国产/易上手/便宜——国内互联网公司多
└── 决策：跟公司生态走（公司用什么学什么——面试问"你们用什么 BI"）
    ——"BI 工具的差异在'生态'不在'能力'——学一款，通三款"
```

**BI 心智**：**"BI 的灵魂不是画图，是'自助分析'——让业务自己拖拽看数，分析师从取数机器解放"**（01 篇定位的呼应——"BI 是分析师的'分身'，把常规问题交给业务自己查"）；**BI 的落地三件事**：**指标口径统一**（BI 里的指标定义必须和指标字典一致——02 篇——"BI 口径乱 = 团队互不信任"）、**分层看板**（高管层/业务层/明细层——阶段 4 07 篇三层看板）、**权限与数据安全**（看板权限按角色——"高管看汇总，运营看明细"）；**BI 的边界**：深度分析（建模/复杂归因）还是回 Python——"BI 做呈现，Python 做深挖——别让 BI 干 Python 的活"。

## 4. 商业图表规范

**商业图表 = 给决策者看的图——三条铁律**（阶段 2 可视化课的企业版）：

1. **图题即结论**——"图题写'华东客单价领先但订单负增长'，不写'客单价对比'"——"看图的人 3 秒知道结论，细节自己看"
2. **标注重点**——箭头/高亮/注释标出关键数据点——"不标注重点的图，重点等于没有"
3. **删繁就简**——最多 3 个系列、无网格线、颜色 ≤5 种（色盲安全——阶段 2 04 篇）——"图上的每一样东西都在抢注意力"

```python
# 商业图表示范（matplotlib/seaborn——阶段 2 已会，这里讲规范）
import matplotlib.pyplot as plt
import seaborn as sns

fig, ax = plt.subplots(figsize=(8, 4))
sns.barplot(data=df, x="region", y="aov", errorbar=None, palette="Blues_d", ax=ax)
ax.annotate("华东客单价领先 20%", xy=(3, max_y), fontsize=11, color="red",
            arrowprops=dict(arrowstyle="->", color="red"))     # 标注重点
ax.set_title("区域客单价对比：华东领先但需关注订单量", fontsize=13)  # 图题即结论
plt.tight_layout()
plt.savefig("fig_region.png", dpi=300, bbox_inches="tight")    # 300dpi 交付
```

**图表心智**：**"商业图表的第一读者是'没时间的人'"**——"老板看图的 3 秒决定了这张图的价值"——**"图是论证的一部分，不是装饰品"**；**图表类型与问题匹配**（阶段 2 03 篇选型课：趋势用线、对比用柱、构成用堆叠、相关用散点——"一图一问"）；**同源数据同配色**（多张图同一指标用同色——"颜色是跨图的记忆锚点"）；**Excel 与 BI 的图表同样适用**这三条——"规范是通用的，工具只是画笔"。

## 5. PPT 汇报规范

**业务分析师的 PPT = 决策工具，不是课件**——四条规范：

```text
PPT 汇报规范
├── 一页一结论：每页一个判断（标题就是结论——"华东订单负增长"不是"华东分析"）
├── 金字塔结构：结论页 → 论据页 → 附录（老板只看前 3 页）
├── 图表配解读：每张图下一行字写"图说明什么"（读者不用猜）
└── 附录放细节：口径/数据表/方法都进附录（正文只留决策信息）
    ——"PPT 的读者 3 分钟看完能拍板，就是好 PPT"
```

**PPT 心智**：**"汇报 PPT 的本质：把 30 页分析压缩成 10 页决策信息"**——**"分析是加法，汇报是减法"**（删掉所有"看起来专业但无关决策"的内容——"背景介绍删、过程细节删、只有结论和建议留"）；**演示比 PPT 重要**——"PPT 是提词器，讲才是交付"（09 篇的讲故事）；**汇报前演练**：讲一遍录音、卡壳处打磨——"汇报是分析师最高频的'面试'——每次汇报都是职场曝光"；**数据与结论分离**——"PPT 讲结论，数据在附录——被追问时翻附录，展示专业性"。

## 6. AI 协作

**2026 年岗位明确要求"AI 协作能力"**——分析师 + AI 的新工作流：

```text
AI 协作工作流（2026 范式）
├── 提效：AI 生成 SQL 初稿/清洗代码（人工校验——"AI 写代码，人审逻辑"）
├── 加速：AI 辅助报告初稿（结论人写、模板 AI 铺——"AI 铺路，人定方向"）
├── 探索：AI 提供分析方法建议（"这个业务问题有什么分析方法"——03 篇方法的加速器）
└── 边界：AI 不背结论（数据口径/业务判断/建议责任都是人的）
    ——"AI 淘汰的是'只会取数'的分析师，淘汰不了'懂业务'的分析师"
```

**AI 协作心智**：**"AI 是分析师的'实习生'——干得快，但判断要你拍板"**——**AI 生成的 SQL/代码必须过三关：跑通、验证结果、理解逻辑**（"AI 写的 group by 漏了维度，你要能看出来"）；**AI 协作的正确姿势：人定问题与口径，AI 加速执行**——"AI 的价值在'省时间'，不在'替思考'"；**提示词的业务化**——把"帮我分析销售"升级成"帮我用量价拆解分析 7 月 GMV 环比下降，数据是这份 CSV，输出归因表格"——**"提示词的质量 = 业务理解的质量"**（01 篇需求五问的 AI 版）。
