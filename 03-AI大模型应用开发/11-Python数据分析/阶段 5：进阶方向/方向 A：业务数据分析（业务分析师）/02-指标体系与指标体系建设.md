## 1. 指标与指标体系的区别

**指标 = 一个数字**（GMV、留存率）；**指标体系 = 指标之间的"关系网"**（北极星 → 子指标 → 过程指标 → 责任人）——**"没有体系的指标是散沙，有体系的指标是结构"**。

```text
电商指标体系示例（三层）
├── 北极星：GMV（一句话：生意规模）
├── 一级拆解：GMV = 流量 × 转化率 × 客单价（杜邦式拆解——03 篇）
└── 二级过程指标：UV/新客占比 → 加购率/支付率 → 件单价/连带率
    ——"上层指标变了，沿着体系往下找，就知道问题出在哪个环节"
```

**体系心智**：**"指标体系的三大规律"**（2026 指标体系方法论）：**① 动态适配**——业务阶段不同，核心指标不同（初创期盯 DAU/MAU 增长，成熟期盯 GMV/客单价，衰退期盯 LTV/流失率——"指标随业务阶段走"）；**② 多维拆解**——电商拆流量/转化/供应链三个维度；**③ 单一北极星**——全员朝一个方向用力——**"指标体系不是越全越好，是越'准'越好——准 = 和当前业务阶段匹配"**。

## 2. 北极星指标

**北极星指标 = 最能体现产品核心价值的"唯一关键指标"**——满足三个条件：

1. **直接反映用户核心价值**——短视频平台是"用户时长"、SaaS 是 MRR（月经常性收入）——"指标和用户价值对不上，团队就跑偏"
2. **具备业务导向性**——教育产品是"完课率"（看完课才算价值发生）——"指标要能指向业务动作"
3. **可量化追踪**——能日粒度追踪、能拆解——"不可拆的北极星是口号"

**北极星心智**：**"北极星指标是全体团队的'同一个方向'"**——产品、运营、技术、分析师都对着它优化——**"选错北极星，全团队的努力都是白费"**（经典反面：只盯下载量不盯激活的团队，下载涨了用户全卸载）；**北极星不是唯一的指标**——它是"第一指标"，OSM 体系围绕它展开——**"北极星 + OSM = 先定方向、再建体系"**（2026 指标体系两步法）。

## 3. OSM 模型：目标-策略-度量

**OSM（Objective 目标 - Strategy 策略 - Measurement 度量）是把大目标拆成可执行动作的三层结构**：

```text
OSM 示例（提升支付转化）
├── O 目标：提升用户支付转化率（目标=北极星的子目标）
├── S 策略：① 优化支付流程（减少跳失）；② 增加促销刺激（优惠券核销）
└── M 度量：支付环节跳失率、优惠券核销率、支付转化率
    ——"每个策略都有度量，每个度量都对应策略——策略不落地的目标是一句空话"
```

```python
# OSM 的落地形态：指标字典里每个指标标注"服务哪个策略"
OSM_TABLE = [
    {"目标": "提升支付转化", "策略": "优化支付流程", "度量": "支付跳失率",
     "口径": "进入支付页到支付成功之间的流失", "负责人": "产品部"},
    {"目标": "提升支付转化", "策略": "促销刺激", "度量": "优惠券核销率",
     "口径": "核销优惠券数 / 发放优惠券数", "负责人": "运营部"},
]
```

**OSM 心智**：**"OSM 的价值：让指标'有爸爸'（策略）'有爷爷'（目标）"**——一个指标挂不上任何策略 = 这个指标没人看——**"指标体系里不允许有'孤儿指标'"**；**指标与策略强关联**是 OSM 的实施要点（金融平台案例：把"提升资产规模"拆成"新客获取+存量留存"两策略，对应"首投率"和"资产复投率"）——**"策略变了指标就变，指标服务于策略不是服务于报表"**。

## 4. KPI 树与 MECE 拆解

**KPI 树 = 把战略目标逐层拆成可执行指标的树状结构**——拆解铁律：**MECE（相互独立、完全穷尽）**：

```text
GMV KPI 树（MECE 拆解——每一层不重不漏）
└── GMV = 流量 × 转化率 × 客单价
    ├── 流量 = 新增 UV + 老客 UV          ← 不重（新老）不漏（全部流量）
    │     └── 新增 UV = 各渠道新增之和     ← 渠道互斥且穷尽
    ├── 转化率 = 首页-详情-加购-支付各步乘积（漏斗——阶段 4 04 篇）
    └── 客单价 = 件单价 × 连带率（件数）
```

**KPI 树心智**：**"MECE 是拆解的纪律"**——拆出来"重复"（新客 UV 和渠道 UV 重叠）或"漏掉"（没算自然流量）都是不合格的树——**"一棵合格的 KPI 树：拆完所有分支加起来等于根"**（验证方法：数据算一遍——`GMV = 新增UV×转化×客单` 应该等于真实 GMV）；**拆解到"有人管"为止**——"每个叶子指标都要有责任人（销售部管收入、市场部管营销费用、商品部管产品结构）——**'拆出来的指标没人跟，等于没拆'"**（杜邦分析落地的同款原则——03 篇）。

## 5. 指标字典与口径治理

**指标字典 = 指标的"身份证 + 户口本"**——指标体系能不能落地，看字典全不全：

```markdown
# 指标字典：GMV
- 定义：成交订单金额总和（含运费，不含退款）
- 口径：订单支付成功时间（非下单时间）；币种 CNY；剔除测试订单
- 口径变更史：2025-07 起含运费；2026-01 起剔除退款订单
- 来源：订单宽表 ods_orders（数仓 DWD 层）
- 维度：日期/渠道/品类/区域/新老客
- 负责人：数据部 张三；确认人：财务部 李四
- 相关指标：GMV 环比/同比、客单价、退款率
```

**字典心智**：**"指标字典至少五要素：定义、口径、来源、负责人、变更史"**——**"口径不清是分析师和业务方吵架的头号原因"**（GMV 含不含运费？按支付还是下单时间？——阶段 4 03 篇"口径写死"的体系化）；**变更史是最容易被忽视的**——"2025-07 起含运费"——不看变更史的人做的同比全是错的——**"口径变更不记录，历史对比全是坑"**；**指标血缘**（这个指标从哪张表来、被谁用）是 2026 数据团队的标配——**"字典是静态的，血缘是动态的——指标体系要'活'"**；进阶：指标字典落到数据仓库的指标层（数仓 ODS-DWD-DWS-ADS 分层里 DWS 层的产出物——04 篇展开）。

## 7. 本节验收

**验收动作**：① 给模拟电商定北极星指标（写清三个条件怎么满足）；② 用 OSM 拆一个业务目标（目标-策略-度量各 2 条）；③ 画一棵 GMV KPI 树并数据验证（MECE）；④ 为 5 个核心指标写指标字典（含变更史）——**"北极星 + OSM + KPI 树 + 字典 = 指标体系能力"**——**练习纪律**：每个指标写字典时必写口径——"字典不写口径，等于没写"。

> 🎯 **核心要点**：指标体系 = 指标的关系网（不是数量堆砌）——三大规律（动态适配/多维拆解/单一北极星）；北极星三条件（反映用户价值/业务导向/可量化）；**OSM（目标-策略-度量——孤儿指标不允许）**；**KPI 树 MECE 拆解（拆完相加等于根 + 叶子有人管）**；指标字典五要素（定义/口径/来源/负责人/变更史——**口径不清是吵架头号原因**）——"单个指标是砖，指标体系是房子"。
