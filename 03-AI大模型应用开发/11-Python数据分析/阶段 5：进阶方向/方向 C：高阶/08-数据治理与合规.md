## 1. 数据治理的定位

**数据治理 = 让数据"可信、可用、可控、可追"的管理体系**——2026 年数据团队的"宪法"：

```text
数据治理四目标
├── 可信：口径统一（指标平台——07 篇）+ 质量监控（阶段 3 09 篇）
├── 可用：数据资产目录（谁知道有什么数据、在哪、能不能用）
├── 可控：权限分级（谁能看什么——最小权限原则）
└── 可追：血缘 + 审计（谁动了什么数据——全过程留痕）
    ——"治理不是'管数据'，是'让数据能放心用'——治理是效率的底座不是障碍"
```

**治理心智**：**"治理的价值公式：治理成本 < 数据事故成本——治理才有意义"**——**"数据事故的代价：泄露（罚款+声誉）、口径打架（决策错误）、权限失控（内鬼）——一次事故的代价远超一年的治理成本"**；**2026 年治理的两个新驱动力**——**① 数据资产入表**（数据作为企业资产记账——治理成为财务要求）；**② AI 合规**（AI 用数据要可解释可审计——EU AI Act——本课第 3 节）——"**治理从'技术规范'升级为'企业底线'"**；**治理的落地层级**——"组织（数据委员会）+ 制度（数据分类分级）+ 工具（数据目录/权限系统）——**'治理是三分制度、七分执行'"**。

## 2. 个人信息保护法

**个保法（PIPL——2021 年施行，2026 年执法常态化）——数据人的合规底线**：

```text
个保法核心要求（分析场景对照）
├── 告知同意：收集个人信息要告知 + 同意（埋点/采集的合规前提）
├── 最小必要：只收集业务必需的数据（"分析不需要身份证号就不收集"）
├── 目的限制：数据用于收集时声明的目的（"收集的订单数据不能卖"）
├── 删除权/可携带权：用户可要求删除/带走自己的数据
└── 敏感信息特殊保护：生物识别/医疗/金融——更高门槛
    ——"个保法的灵魂：'用户的隐私数据不是你的资产，是用户的委托'"
```

**个保法心智**：**"分析师的合规动作四件套"**——**① 数据分类**（哪些是个人信息/敏感信息——分类分级制度）；**② 最小化采集**（爬虫/埋点只拿需要的——阶段 3 06 篇"爬得到≠能用得"的立法依据）；**③ 脱敏后使用**（分析环境用脱敏数据——本课第 4 节）；**④ 权限留痕**（谁看了用户明细——审计日志）——"**'我用数据做分析'不是豁免理由——分析也要合规**"；**2026 执法常态化**——"违规处罚从'警告'到'高额罚款+负责人追责'——**'合规不是法务的事，是每个碰数据的人的事'"**；**与爬虫课程的呼应**（阶段 3 06 篇合规边界）——"robots.txt 是网站规则、个保法是法律底线——**'技术让一切皆有可能，合规让一切有边界'"**。

## 3. EU AI Act 与 AI 合规

**EU AI Act（欧盟人工智能法案——2026 年分阶段生效推进）——AI 时代的合规新规**：

```text
EU AI Act 对数据/AI 岗位的要点
├── 风险分级：AI 系统分四级（不可接受/高风险/有限/最小）——高风险要合规评估
├── 高风险要求：数据治理（训练数据可追溯）、透明性（解释决策）、
│              人工监督、记录留存（日志/审计）
├── 禁止行为：社交评分/诱导性操纵等（明确禁止）
└── 对数据岗的传导：模型卡（方向 B 08 篇）、可解释性（SHAP）、
    公平性审计（群体差异）——从"最佳实践"变"法定要求"
    ——"EU AI Act 的落地：2026 年'可解释、可审计'从加分项变成必选项"
```

**AI 合规心智**：**"EU AI Act 的传导路径：欧盟法规 → 出海企业 → 国内大厂对标 → 行业标准"**——**"做面向全球/AI 相关产品的人，2026 年就要按'高风险 AI'标准要求自己"**（模型卡 + SHAP + 公平性——方向 B 08 篇的合规升级）；**AI 合规的实操清单**——"训练数据来源记录（数据集许可——阶段 3 02 篇五看）、模型版本与解释留痕（MLflow——方向 B 09 篇）、公平性审计报告（方向 B 08 篇）、人工监督流程（高风险决策要人确认）——**'AI 合规 = 把方向 B 的工程实践变成法定文档'"**；**中国视角**——"《生成式人工智能服务管理暂行办法》（2023）+ 数据出境新规（2024-2025）——**'国内外合规要求趋同：可解释、可审计、可追责'"**。

## 4. 脱敏与隐私保护技术

**脱敏 = 让数据"能用但认不出人"**——隐私保护技术的分析师版：

```python
# 脱敏五法（按场景选）
# ① 替换（假名化）：真实姓名 → 随机姓名（Faker——阶段 3 08 篇）
import faker
fake = faker.Faker("zh_CN")
df["name"] = df["name"].apply(lambda _: fake.name())

# ② 遮蔽：手机号 138****5678（保留部分格式信息）
df["phone"] = df["phone"].str.replace(r"(\d{3})\d{4}(\d{4})", r"\1****\2")

# ③ 泛化：精确年龄 → 年龄段（保留统计价值）
df["age"] = pd.cut(df["age"], bins=[0, 18, 30, 45, 60, 100], labels=["<18", "18-30", "30-45", "45-60", "60+"])

# ④ 扰动：数值加噪声（保留分布不保留精确值）
df["income"] = df["income"] * np.random.uniform(0.9, 1.1, len(df))

# ⑤ 哈希（不可逆）：身份证/邮箱 → 哈希值（跨表关联用）
import hashlib
df["user_hash"] = df["email"].apply(lambda e: hashlib.sha256(e.encode()).hexdigest()[:16])
```

**脱敏心智**：**"脱敏的选型原则：'保留分析价值 × 满足合规要求'的平衡"**——**"分析需要精确值就替换/哈希（用户画像需要关联——哈希保关联）、统计需要分布就泛化/扰动（年龄段/噪声）——'脱敏不是毁数据，是给数据'打码'后继续用'"**；**脱敏的三大坑**——**① 假名化 ≠ 匿名化**（"换了名字但'同一个人'的关联还在——重识别风险——组合字段（性别+年龄+地区）可以'拼出人'——**'假名化数据 + 其他数据源 = 可能还原身份'**"）；**② 哈希不够安全**（弱哈希可暴力破解——用带盐哈希/加密）；**③ 脱敏一致性**（"同一个用户的 10 行要脱成同一个假名——**'脱敏的一致性 = 分析关联性的保障'"**）——"脱敏报告要写'用了什么方法、保留了什么'"（来源卡的三级——阶段 3 09 篇）。

## 5. 数据资产治理

**数据资产治理 = 把数据当"资产"管理——目录、分级、生命周期**：

```text
数据资产治理四件事
├── 数据目录：数据资产的"图书馆"——有什么数据/在哪/谁负责/可不可用
├── 分类分级：按敏感度分级（公开/内部/机密/敏感——权限的依据）
├── 生命周期：数据从生到死（创建 → 使用 → 归档 → 销毁——过期数据要销毁）
└── 质量考核：数据质量纳入 KPI（完整性/及时性——阶段 3 09 篇体检的资产版）
    ——"数据目录是'找得到'，分级是'管得住'，生命周期是'不积压'"
```

**资产心智**：**"2026 年数据资产的两种'入表'压力"**——**① 财务入表**（数据资产进资产负债表——企业开始给数据"定价"）；**② AI 入表**（训练数据来源要可审计——Data Agent 的"可信数据基础"——09 篇）——"**治理从'内务整理'升级为'资产化管理'"**；**数据目录的操作价值**——"新员工找数据从'问 10 个人'变成'查目录 10 分钟'——**'目录是数据团队的第一基础设施'"**（方向 A 02 篇指标字典的资产版——"指标字典管'指标'、数据目录管'数据'"）；**分级与权限的落地**——"敏感级：白名单 + 审计；机密级：脱敏后使用；公开级：全员可看——**'最小权限原则：业务需要什么给什么，不多给一分'"**（阶段 3 06 篇"钥匙进环境变量"的组织版）。
