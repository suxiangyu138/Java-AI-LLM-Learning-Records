## 1. 高阶技能树

**高阶数据人 = 分析能力 × 工程能力 × 前沿视野**——五层技能树（2026 年数据岗全景）：

```text
高阶技能树五层
├── 分析层：pandas/SQL/可视化/建模（阶段 1-4 + 方向 A/B——已会）
├── 数据层：数仓/管道/数据质量（本方向 01/02 篇 + 阶段 4 06 篇）
├── 方法层：因果推断/统计深潜/深度学习（本方向 03/04/05 篇）
├── 产品层：指标平台/数据产品/治理合规（本方向 07/08 篇）
└── 前沿层：AI 融合/Data Agent/大模型（本方向 09 篇）
    ——"前四阶段 + 方向 A/B 是'纵向深度'，方向 C 是'横向广度'"
```

**技能树心智**：**"高阶与中级的区别：会'用' vs 会'造'"**——"中级会用 pandas 分析，高阶知道 pandas 的数据从哪来（数仓）、跑不动了换什么（DuckDB）、管不好会怎样（治理）、AI 来了怎么用（融合）"——**"高阶是'知其所以然'的全栈视角"**；**2026 年数据岗的三种去向**（本方向三选一）：**数据架构师**（数据层+产品层）、**资深数据科学家**（方法层）、**AI 应用工程师**（前沿层）——"先有广度再选深度——本方向给你选路的视野"。

## 2. 数仓分层：ODS-DWD-DWS-ADS

**数仓分层 = 数据的"车间流水线"——每层一个加工阶段**（2026 年数据团队的标配架构）：

```text
数仓四层（自底向上）
├── ODS 操作数据层：原始数据落地（原样复制——底片！）
├── DWD 明细数据层：清洗/规范化（口径统一、去重、标准编码）
├── DWS 汇总数据层：宽表/指标（按主题汇总——分析师的主力取数层）
└── ADS 应用数据层：面向应用的结果（报表/看板/模型特征）
    ——"ODS 是仓库，DWD 是清洗间，DWS 是加工厂，ADS 是货架——分析师在货架拿货"
```

```python
# 分析师视角：你的取数在哪个层？——知道"拿的是第几手数据"决定信任度
# ODS 原始 → 可能脏；DWD 清洗过 → 口径对；DWS 汇总过 → 已聚合（问清口径！）
# 阶段 3 04 篇的 read_sql 通常连 DWS/ADS——"问一句'这是哪一层'是分析师的职业习惯"
```

**分层心智**：**"数仓分层的价值：分工（各层各司其职）+ 复用（DWS 一次建、万人用）+ 追溯（从 ADS 能追回 ODS 原始）"**——**"没有分层的数仓 = 每家报表各建各的表，口径互相打架"**（方向 A 02 篇指标字典的数仓版）；**分析师与数仓的协作**——"指标定义在 DWS 层固化（口径统一——02 篇指标字典落地成表）——**'指标字典是方向 A 的文档，DWS 宽表是它的工程实现'"**；**2026 数仓的新变化**——湖仓一体（数据湖 + 数仓融合——Iceberg 表格式 + DuckDB 直接查湖）——"传统数仓 → 湖仓一体：分析师可以直接 SQL 查文件湖"（02 篇 DuckDB 的用武之地）。

## 3. 2026 混合技术栈

**2026 年 Python 数据分析的"混合栈共识"**（不再只有一个工具打天下）：

```text
2026 混合栈（三大件分工）
├── DuckDB 1.5.x：探索层——SQL 直接查文件（Parquet/CSV/湖）
│    —— 超大文件秒查、超内存自动落盘（"SQL 界的 SQLite"）
├── Polars 1.0+：管道层——生产级数据转换（惰性执行/类型安全/流式）
│    —— 比 pandas 快 5 倍+、大数据不炸内存
└── pandas 3.x：收尾层——最后一英里（喂可视化/喂 sklearn——生态兼容）
    ——"DuckDB 探索、Polars 转换、pandas 收尾——Apache Arrow 让三者零拷贝互通"
```

**混合栈心智**：**"混合栈的选型逻辑：工具跟着'数据规模 × 任务类型'走"**——**"超内存数据（>RAM）用 DuckDB（自动落盘）；生产管道用 Polars（惰性+类型安全）；可视化/建模前转 pandas（生态最全）"**——"2026 年的分析师会三件套，不是只会 pandas"；**互操作是混合栈的灵魂**——Apache Arrow 内存格式让三者零拷贝互转（`duckdb.from_df(polars_df)` 直接 SQL 查 Polars 表——"**三个工具不是三座孤岛，是一条流水线**"）；**迁移的成本意识**——"pandas → Polars 有 API 差异（类型契约/函数名）——**'为迁移而迁移是折腾，为规模而迁移是升级'"**（02 篇详讲）。

## 4. 分析师与数据工程的衔接

**分析师和数据工程师的"交界地带"——高阶分析师要懂的分工**：

```text
分工与协作
├── 工程师：建数仓、跑管道、保质量（"数据管道天天跑——阶段 4 06 篇的团队版"）
├── 分析师：提需求、用数据、反馈质量（"我要 DWS 层加一个'新客首购'指标"）
└── 交界三件事（高阶分析师必会）：
│   ① 提需求写清口径（指标字典——方向 A 02 篇——工程师照着建表）
│   ② 用数据先问层（ODS 脏/DWS 聚合——信任度分级）
│   ③ 发现问题反馈（"这个宽表字段对不上"——反馈是质量闭环的起点）
    ——"分析师懂工程，提需求才提得对；工程师懂分析，建表才建得对"
```

**衔接心智**：**"2026 年'分析师 vs 工程师'的边界在模糊"**——"分析师要会写简单的管道（阶段 4 06 篇）、工程师要懂指标（DWS 设计）——**'全能型数据人'是 2026 的溢价标签**"；**面试讲项目时**——"我的项目数据来自数仓 DWS 层（口径统一），管道每日更新，质量用对账监控"——"**答出'数据来自哪层、怎么保证质量'是高级分析师的项目叙事**"（阶段 4 10 篇面试范式的工程版）；**本方向的学习顺序**：01（全景）→ 02（大数据实战）→ 03-09（各专项）——"先有地图，再逐个点亮"。
