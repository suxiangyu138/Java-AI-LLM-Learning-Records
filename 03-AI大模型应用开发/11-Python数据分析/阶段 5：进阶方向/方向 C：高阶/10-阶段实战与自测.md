## 1. 毕业项目：大数据 × 因果 × AI 综合项目

**毕业项目 = 五阶段课程的"毕业设计"**（综合前四个阶段 + 三个方向的全部能力）：

```text
毕业项目要求（"用大数据方法处理大数据、用因果方法证明因果、用 AI 加速全程"）
├── 数据：大数据量真实数据（10GB+ 公开数据或大文件——阶段 3 02 篇 + 02 篇 DuckDB）
├── 分析：完整经营/用户分析（阶段 4 + 方向 A 方法论——量价拆解/漏斗/分层）
├── 因果：一个因果问题（DID/DoWhy——"某政策/动作是否真的有效"——03 篇）
├── 模型：一个预测模型（方向 B 全链路——特征/调参/评估/解释）
├── 呈现：交互式交付（Plotly 仪表盘——06 篇）
└── AI 融合：LLM 辅助全流程（09 篇——记录"人机分工"）
```

**毕业验收标准（模拟"五阶段答辩"）**：

```markdown
# 毕业答辩自检（五阶段总验收）
- [ ] 数据层：DuckDB 处理超内存数据（记录性能数字）+ 来源卡 + 合规检查
- [ ] 分析层：方法论归因 + 业务结论（方向 A 三段式）
- [ ] 因果层：一个因果结论（识别假设 + 反驳检验——03 篇三件套）
- [ ] 模型层：基线对比 + 评估 + SHAP 解释（方向 B 全链路）
- [ ] 呈现层：交互仪表盘（10 秒自发现一个洞察）
- [ ] AI 层：AI 辅助工作流记录（环节/提示词/人改了什么）
- [ ] 答辩：15 分钟讲完整项目 + 问答（技术/业务/合规都能答）
```

**毕业项目心智**：**"毕业项目 = 你职业生涯的'第一块完整拼图'"**——"面试官看它：技术栈全不全（大数据/模型/AI）、思维深不深（因果/批判）、交付硬不硬（可跑可看可讲）——**'做完这个项目，你就是'全栈数据人'"**；**选题建议**——"真实业务数据优先（Kaggle 大赛数据/开放数据——阶段 3 02 篇）——**'有真实问题才有真实难度'"**；**规模的平衡**——"项目完整 > 项目宏大——每个环节都做透，比一个环节炫技强（方向 B 10 篇纪律延续）——**'五阶段课程的毕业设计，是'做完整'不是'做最大'"**。

## 3. 报错速查 10 条

| 报错/现象 | 原因 | 解法 |
|---------|------|------|
| pandas `MemoryError` | 数据超内存 | 换 DuckDB/Polars（02 篇——超内存第一反应） |
| `duckdb.sql()` 找不到变量 | DuckDB 不认识 Python 变量 | 用 `duckdb.from_df(df)` / `register()`（02 篇） |
| Polars `.to_pandas()` 慢 | 全量物化 | 结果大用 `fetchall()`/先聚合再转（02 篇） |
| `plotly write_image` 报错 | 缺 kaleido | `pip install kaleido`（06 篇） |
| 中国地图省份全空 | 省名口径不统一 | 统一"内蒙古/内蒙古自治区"（06 篇） |
| DoWhy `refute` 报错 | 估计器/数据不匹配 | 换 refutation 方法（placebo→random_common_cause→subset） |
| PyTorch 结果不可复现 | 没固定全部种子 | `torch.manual_seed` + random + numpy 三件套（04 篇） |
| PyTorch loss 是 NaN | lr 太大/数据没归一化 | 特征标准化 + lr 降到 0.001（04 篇调试四查） |
| AI 生成的 SQL 结果错 | 语义/口径错 | 对口径 + 跑通验证（09 篇三关） |
| 脱敏后关联对不上 | 脱敏不一致 | 同一用户用同一假名/哈希（08 篇一致性） |

**报错心智**：**"高阶报错的共同规律：'规模变了，工具要变；时代变了，姿势要变'"**——"pandas 报内存错不是 pandas 的错，是该换工具的信号；AI 报错不是 AI 的错，是该加审校的信号——**'报错是升级的信号——新工具/新姿势的提醒'"**——把新坑写进自己的速查表。

## 5. 面试演练

**高阶数据岗面试（本方向特有）**：

**Q1：你的项目数据超过内存，怎么处理？**——答：**"我的项目有 10GB 销售数据——处理分三层：① 探索聚合用 DuckDB 直接在 Parquet 上 SQL 查（零加载，峰值内存 1.5GB）；② 转换管道用 Polars 惰性执行（过滤下推）；③ 建模特征在库里聚合好再转 pandas（喂 sklearn）——三个工具用 Arrow 零拷贝互转——实测比 pandas 方案快 15 倍、内存降 10 倍——关键是'先问要不要全量'——90% 的分析在库里聚合就够了"**——结构：**规模 → 三层方案 → 性能数字 → 方法论（要不要全量）**——"答出数字与方法论，是 2026 年大数据的标准答案"。

**Q2：怎么证明'投放带来增长'而不是巧合？**——答：**"三条路径按可用性选：① 有实验条件做 A/B（黄金标准——随机分配）；② 实验不可行用因果推断——我做过 DID：以'某区域 3 月投放'为处理组、无投放区域为对照，双重差分消掉时间趋势，事件研究图验证平行趋势，政策效应 +2.1%（p 显著）——再补安慰剂检验（随机日期重算无效应）——假设/检验/范围三件套齐全"**——结构：**路径选择 → DID 步骤 → 检验 → 三件套**——"答出'假设+反驳'是因果推断的专业分水岭"。

**Q3：AI 来了，数据分析师会不会被淘汰？**——答：**"会淘汰一部分，淘汰的是'只会取数/做表的'——AI 已经能干这些。留下的分析师做三件事：① 业务理解（AI 不懂我们的行业/用户/口径）；② 批判审校（AI 的结论要人验证——幻觉/口径错是常态）；③ 责任决策（AI 不扛责，人扛——'AI 建议拒单，人签字'）。我的实践：AI 辅助 SQL/报告初稿（省 40% 时间），但结论、口径、局限都是我定——人机协作三原则：AI 干认知活、系统干规则活、人干决策活"**——结构：**观点 → 三类活 → 自身实践 → 三原则**——"答出'具体实践'而不是空喊，是 AI 时代面试的加分项"。
