## 1. 交互可视化的定位

**交互可视化 = 读者可以"自己探索"的图**——2026 年交付的标准形态：

```text
静态图 vs 交互图
├── 静态图（阶段 2 体系）：讲故事——"一图一结论"——适合报告/文档
└── 交互图（本课）：答追问——"读者 hover 看详情、点筛选看子集"——适合看板/演示
    ——"静态图是'演讲'，交互图是'对话'——报告用静态，看板用交互"
```

**定位心智**：**"交互的价值：把'我要问'变成'你自己问'"**——**"老板/业务方看交互看板的三大动作：hover（看具体数字）、点击（筛选维度）、缩放（看细节）——交互让读者从'被动看图'变'主动探索'"**（阶段 4 07 篇 Dashboard 的深化——"看板三层：指标卡/筛选器/图表——交互是筛选器的图版本"）；**工具选型**（2026）：**Plotly**（交互图的 Python 事实标准——本课主角）、**ECharts**（前端生态/国内 BI 常用——`02-后端核心技术` 的报表场景）、**Plotly Dash**（交互看板框架——阶段 4 07 篇 Streamlit 的姊妹）——"Streamlit 最快出看板、Dash 最灵活、Plotly 单图最强——按场景选"。

## 2. Plotly 基础

**Plotly（plotly.py——2026 成熟稳定）——三行出交互图**：

```python
import plotly.express as px

# 一行出交互散点（hover 自动带所有列——鼠标悬停看详情）
fig = px.scatter(df, x="amount", y="age", color="segment",
                 size="frequency", hover_data=["user_id"],
                 title="用户价值分布：金额 × 年龄 × 分层")

# 交互能力（免费获得）：hover 详情 / 缩放拖拽 / 图例点击筛选 / 悬浮工具条
fig.show()                       # 浏览器打开（可交互！）

# 时序交互：悬停看每天数值 + 框选缩放
fig2 = px.line(df_daily, x="date", y="gmv", title="GMV 日趋势（可缩放）")

# 导出：交互 html（给同事看）/ 静态 png（进报告）
fig.write_html("fig_dashboard.html")     # 交互版——双击浏览器打开
fig.write_image("fig_report.png", scale=3)   # 静态版——300dpi 进报告（需 kaleido）
```

**Plotly 心智**：**"Plotly Express 的哲学：一行代码 = 一个交互图"**——**"'color='（分组）、'size='（第三维）、'hover_data='（详情列）——三个参数让二维图变多维探索"**；**交互与静态的双轨交付**——"交互 html 发群/进看板（读者探索），静态 png 进报告（结论固定）——**'同一个图，两种形态，两个读者'"**；**Plotly 与 pandas 无缝**（直接吃 DataFrame——"阶段 2 的可视化课（Matplotlib）讲'怎么画对'，Plotly 讲'怎么画活'——**'Matplotlib 是严谨，Plotly 是灵动——两者都要会'"**；**导出注意**——`write_image` 需要 kaleido 包（"交互图转 png 报错先装 kaleido"——报错速查 10 篇收录）。

## 3. 地理可视化

**地理可视化 = 数据画在地图上——区域差异一眼看穿**：

```python
import plotly.express as px

# 中国地图（省份聚合——choropleth 分级填色图）
fig = px.choropleth(
    df_province,
    locations="province",              # 省份列
    locationmode="china",              # 中国省名模式（需数据为中文省名）
    color="gmv",                       # 颜色 = 指标（颜色深浅 = 数值大小）
    color_continuous_scale="Blues",    # 配色（色盲安全——阶段 2 04 篇纪律）
    title="各省 GMV 分布",
)

# 散点地图（经纬度——门店/用户位置）
fig2 = px.scatter_mapbox(df_stores, lat="lat", lon="lon", size="revenue",
                         color="region", zoom=4,
                         mapbox_style="open-street-map")
fig2.show()
```

**地理可视化心智**：**"地图回答'哪里强、哪里弱'——区域差异是地理图的独有洞察"**——**"省/市维度用 choropleth（分级填色），精确位置用 scatter_mapbox（经纬度散点）"**；**地理数据的准备**——"省份名要统一（'内蒙古' vs '内蒙古自治区'——**'地名口径不统一 = 地图上全空'"**（方向 A 02 篇指标字典的地名版——"地理维度也有口径"）；**地理图表的正确用法**——"地图用于'分布'问题（哪里多/哪里少），不用于'趋势'问题（趋势用线图）——**'一图一问"的选型纪律在地理图上同样成立"**；**中国地图的注意**——"locationmode='china' 需正确数据（或 GeoJSON 自定义）；行政边界数据用官方/标准库（阿里云 DataV 边界数据）——**'地图边界是敏感问题——用官方数据源'"**。

## 4. 交互仪表盘

**交互仪表盘 = 多个交互图的组合 + 全局筛选（阶段 4 07 篇 Streamlit 的 Plotly 深化）**：

```python
import plotly.express as px
import streamlit as st

st.set_page_config(page_title="经营分析", layout="wide")

# 全局筛选（仪表盘的灵魂——一个筛选器联动所有图）
channel = st.sidebar.multiselect("渠道", df["channel"].unique(), default=df["channel"].unique()[:3])
df_f = df[df["channel"].isin(channel)]

# Plotly 图嵌入 Streamlit（交互保持！）
c1, c2 = st.columns(2)
c1.plotly_chart(px.line(df_f, x="date", y="gmv", color="channel",
                        title="GMV 趋势（可缩放/hover）"), use_container_width=True)
c2.plotly_chart(px.bar(df_f, x="category", y="gmv", color="segment",
                       title="品类 × 分层（点击图例筛选）"), use_container_width=True)
```

**仪表盘心智**：**"交互仪表盘三要素：全局筛选器（联动）、多图布局（分工）、hover 详情（追问）"**——**"一个仪表盘的合格线：读者 10 秒能自己发现一个'报告里没写的洞察'"**（"交互的价值验证：业务方自己点出了新结论——这就是交互的意义"）；**性能纪律**——"图多数据大 → 卡——`st.cache_data` 缓存 + 聚合前置（在库里算好再画——02 篇 DuckDB 的配合）——**'仪表盘慢 = 没人看'"**；**部署**（阶段 4 07 篇已学）：Streamlit Cloud/Hugging Face Spaces——"交互看板交付 = 能点 + 有链接"；**Dash vs Streamlit 选型**——"Streamlit（脚本式——分析师最快）、Dash（组件式——复杂布局/前端定制）——**'1 天交付用 Streamlit，1 周打磨用 Dash'"**。

## 5. 可视化设计进阶

**交互时代的设计纪律（静态时代的升级版）**：

```text
交互可视化设计六律
├── ① 默认视图讲结论：打开页面第一眼 = 结论视图（不要全是"待探索"的空白）
├── ② 交互 ≠ 杂乱：交互是"分层揭示"——默认简洁、hover/点击才展开细节
├── ③ 颜色有语义：同一指标跨图同色（方向 A 08 篇纪律）；≤5 色；色盲安全
├── ④ 数字可溯源：hover 里带原始值 + 图下注口径（指标字典链接）
├── ⑤ 性能优先：数据聚合前置（大图慢 = 设计失败）
└── ⑥ 移动端适配：业务方手机看——布局自适应（columns 变单列）
    ——"交互让图'能点'，设计让图'值得点'"
```

**设计心智**：**"交互的陷阱：'能交互' ≠ '设计好'——交互是手段，洞察是目的"**——**"最常见的失败：把 20 个交互图堆一屏——读者无从下手——交互要'分层'：概览 → 筛选 → 钻取"**（"先给结论视图（概览），再给探索入口（筛选），最后给细节（钻取）——交互的三级台阶"）；**交互 + 讲故事**——"看板的第一屏讲结论（默认视图带标注），后面的屏答追问——**'看板也是叙事，不是图库'"**（方向 A 09 篇 SCQA 的看板版——"看板的 S（背景）是概览、C（冲突）是异常标注、A（答案）是钻取建议"）；**设计的验收标准**——"找不懂数据的人看 1 分钟，让他复述'看到了什么'——**'复述清楚 = 设计合格'"**。
