## 1. 部署的定位

**部署 = 把模型接入业务系统（API/批处理）——2026 年 ML 工程师的核心交付**：

```text
模型的生命周期（部署视角）
├── 训练（notebook）：可复现、可记录——MLflow 追踪
├── 注册（registry）：版本管理——哪个模型是"当前生产版"
├── 服务（serving）：API 对外——业务系统调用
└── 监控（monitoring）：漂移检测——什么时候该重训
    ——"训练是 20% 的工作，部署与维护是 80%——MLOps 的真相"
```

**定位心智**：**"训练一个模型需要 1 天，部署好一个模型需要 1 周"**——**"notebook 里的模型只对你自己有用，API 里的模型才对业务有用"**（01 篇"能上线是进阶标志"的落地）；**2026 年 MLOps 工具栈**：**MLflow（追踪/注册/服务——事实标准）**、模型服务（FastAPI/MLflow serve——阶段 2 的 `Python 异步 + FastAPI` 体系复用）、监控（Evidently/自定义——漂移检测）；**部署的四种形态**——**在线 API**（实时决策：风控）、**批处理**（每日跑：预测报表）、**流式**（实时事件：推荐）、**嵌入式**（模型进应用：端侧）——"业务场景决定部署形态"。

## 2. MLflow：实验追踪与模型注册

**MLflow = 2026 年 ML 实验与部署的事实标准**（开源，追踪/注册/服务三合一）：

```python
import mlflow

# ① 实验追踪：每次训练自动记录参数/指标/制品（调参日志的自动化——03 篇纪律落地）
with mlflow.start_run(run_name="lgb_v1"):
    mlflow.log_params({"n_estimators": 500, "learning_rate": 0.05})   # 参数
    mlflow.log_metrics({"f1": 0.82, "auc": 0.88})                     # 指标
    mlflow.log_artifact("fig_importance.png")                         # 制品（图/报告）
    mlflow.sklearn.log_model(model, "model")                          # 模型本体

# ② 模型注册：把好模型登记为"生产候选"（版本化——v1/v2/v3）
# mlflow.register_model("runs:/<run_id>/model", "credit_risk_model")
# 生产切换：设置版本为"Staging/Production"——回滚 = 切版本
```

**MLflow 心智**：**"MLflow 解决'调了 50 次哪次最好'——每次训练自动留档（参数/指标/制品/模型）"**——**"没有实验追踪的 ML 是'做了 50 次实验但只记得最后一次'"**（03 篇"没有日志的调参是玄学"的工程化）；**模型注册是"部署的守门员"**——"谁把模型从 Staging 推到 Production 要记录（谁批准的、什么指标）"——**"模型注册表 = 模型的生产环境 Git"**（版本/回滚/审计）；**MLflow 的边界**——"MLflow 管'实验与模型生命周期'，不管'数据管道'（数据归阶段 4 06 篇管道管）"——"工具各管一段，别混"。

## 3. 模型服务化：API 部署

**把模型包成 API——业务系统用 HTTP 调用**（复用 FastAPI 体系——`../../../01-Python语言/Python%20异步%20+%20FastAPI/` 的 API 开发课）：

```python
# 方案 A：MLflow 一键服务（最快——注册过的模型直接起 API）
# mlflow models serve -m models:/credit_risk_model/Production -p 8000

# 方案 B：FastAPI 自定义服务（灵活——可加解释/日志/业务逻辑）
from fastapi import FastAPI
import mlflow, pandas as pd

app = FastAPI(title="credit-risk-api")
model = mlflow.pyfunc.load_model("models:/credit_risk_model/Production")

@app.post("/predict")
def predict(features: dict):
    df = pd.DataFrame([features])
    proba = model.predict(df)[0]            # 模型预测
    # 业务逻辑：阈值（04 篇——阈值是业务决策）+ 解释（08 篇——SHAP 可选）
    return {"prob": float(proba), "decision": "approve" if proba < 0.5 else "reject"}

# 启动：uvicorn app:app --host 0.0.0.0 --port 8000
```

**服务化心智**：**"API 部署的三件事：输入验证（参数格式/缺失）、预测逻辑（模型+阈值）、输出规范（业务字段）"**——**"上线前必测三样：正常输入、边界输入（缺失/异常值——模型不能崩）、性能（延迟 P99）"**；**pyfunc 统一加载**（模型不管什么框架——`mlflow.pyfunc.load_model` 统一接口——"**换模型版本不换调用代码**"）；**部署的复现纪律**——**锁版本**（模型 + 依赖 + SHAP 解释器版本全锁——"SHAP 0.46.0 和 0.47.0 的序列化可能不兼容——版本不一致 = 部署事故"——08 篇的部署坑落地）；**健康检查**（`/health` 端点 + 启动自检——"服务重启后要能自己发现'模型加载失败'"——阶段 2 FastAPI 体系的双探针）。

## 4. 监控与漂移

**上线后的监控——模型会"过期"（数据变了，模型不准了）**：

```text
监控三件事
├── 性能监控：预测质量（有真值时：准确率/F1 趋势——延迟真值场景：回访/人工复核）
├── 数据漂移：输入分布变了（均值/分布/缺失率——KS 检验/PSI）
└── 解释漂移：SHAP 分布变了（模型"行为"变了——08 篇——最灵敏的报警）
    ——"模型漂移的三个信号：预测分布变了、输入分布变了、解释分布变了"
```

```python
# 漂移检测（简单版：PSI——总体稳定性指数，>0.25 报警）
import numpy as np

def psi(reference, current, bins=10):
    """PSI：参考分布 vs 当前分布的距离——>0.1 留意、>0.25 报警"""
    ref_hist, edges = np.histogram(reference, bins=bins)
    cur_hist, _ = np.histogram(current, bins=edges)
    ref_pct = ref_hist / ref_hist.sum() + 1e-6
    cur_pct = cur_hist / cur_hist.sum() + 1e-6
    return np.sum((cur_pct - ref_pct) * np.log(cur_pct / ref_pct))

print(f"特征 age 的 PSI: {psi(train_age, online_age):.2f}")   # >0.25 数据变了
```

**监控心智**：**"模型漂移的根因三问：业务变了吗（规则/产品）、数据源变了吗（采集口径）、用户变了吗（人群结构）"**——**"漂移检测报警 ≠ 立刻重训——先定位根因再决定"**（"用户变年轻了"可能是好事，不是故障——"监控给信号，分析给判断"）；**延迟真值的监控**（风控的真值要 90 天后才知道——"中间用代理指标：预测分布稳定性 + 抽样人工复核"）；**监控的部署**（每日批处理 + 告警——阶段 4 06 篇管道监控的模型版——"模型监控是数据管道的延伸"）；**报警阈值要定**（"PSI > 0.25 告警、连续 3 天告警自动触发重训申请"——"没有阈值的监控是摆设"）。

## 5. 部署架构与重训闭环

**完整的部署架构 = 数据管道 + 训练 + 注册 + 服务 + 监控的闭环**：

```text
ML 部署闭环（2026 架构）
└── 数据管道（阶段 4 06 篇）→ 特征工程 → 训练（MLflow 追踪）
    → 注册（版本管理）→ API 服务（FastAPI/MLflow serve）
    → 监控（PSI/SHAP 漂移）→ 漂移报警 → 触发重训 → 回到训练
    ——"闭环的价值：模型'自愈'——重训是流程的一部分，不是救火"
```

**架构心智**：**"闭环的两条路"**——**手动重训**（报警 → 数据科学家看 → 决定重训——2026 年多数团队的现实）vs **自动重训**（报警 → 管道自动重训 → 候选版本 → 人审批上线——"自动化重训是方向，人工审批是底线"）；**部署的文档**——"部署文档三件套：模型卡（08 篇——用途/性能/解释/公平性）、运行手册（怎么启动/排查/回滚）、监控面板（三件事怎么看）"——**"模型部署的交付物：模型 + 文档 + 监控——缺一不可"**；**回滚演练**——"版本回滚要练过——生产事故时 30 秒切版本"（"没演练过的回滚 = 事故时的赌命"）；**面试讲部署**——"我的模型上线流程：MLflow 追踪 → 注册 → FastAPI 服务 → PSI 监控 → 漂移自动报警"——"讲得出闭环的 ML 工程师，是高级的"。
