## 1. 集成的思想

**集成 = 训练多个模型、综合它们的预测**——"三个臭皮匠顶个诸葛亮"的数学版：

```text
为什么集成有效
├── 个体有偏：每个模型只看到数据的一个侧面（不同的树看到不同的特征组合）
├── 综合去偏：多数投票/加权平均让"个体错误"互相抵消
└── 理论支撑：方差分解——集成降低方差（Bagging）或偏差（Boosting）
    ——"单模型是'一个人做题'，集成是'一个团队做题'——团队平均分 > 个人最高分（通常）"
```

**思想心智**：**"集成有效的前提：个体之间'有差异'"**——"100 个一模一样的模型集成 = 1 个模型"（**"多样性是集成的燃料"**——随机性（采样/特征扰动）是制造差异的手段）；**集成的代价**：训练/推理成本 × 模型数（"10 个模型的推理延迟是 1 个的 10 倍——延迟敏感场景要权衡"）；**集成的适用**：表格数据 = 集成的主场（树模型天然适合集成——每棵树快、可并行）——"神经网络本身已经是'巨型集成'（层内大量神经元）——所以深度学习里集成收益小"。

## 2. Bagging：并行投票

**Bagging（Bootstrap Aggregating）= 并行训练 + 投票/平均**：

```python
# 随机森林 = 决策树 + Bagging + 特征随机采样（双随机——多样性加倍）
from sklearn.ensemble import RandomForestClassifier

rf = RandomForestClassifier(
    n_estimators=300,        # 树的数量（多 = 更稳，边际递减）
    max_features="sqrt",     # 每棵树只看 sqrt(n) 个特征（特征扰动——关键！）
    max_depth=10,            # 限制深度（防止单棵树过拟合）
    random_state=42,
)
```

**Bagging 心智**：**"Bagging 降的是'方差'（波动）"**——单棵决策树过拟合严重（深度大就背题），森林把多棵树的波动平均掉——**"随机森林 = 把'容易过拟合的树'变成'不会过拟合的森林'"**；**双随机的意义**：行采样（每棵树看不同的样本）+ 列采样（每棵树看不同的特征）——"双随机让树之间差异最大化"；**随机森林 vs 单棵决策树**：可解释性降（一棵树能画出来，森林不能——08 篇 SHAP 补救）——"要解释选单树，要精度选森林"；**随机森林的优势场景**：中小数据、特征多、要鲁棒（对异常值/缺失不敏感）。

## 3. Boosting：串行纠错

**Boosting = 串行训练，每个新模型纠正前一个的错**：

```python
# 思想演示：第 1 棵树学原始数据，第 2 棵树学"第 1 棵的残差"，第 3 棵学"前两棵的残差"...
# 最终预测 = 所有树的加权和（每棵树的学习率加权——防止一步到位过拟合）

# AdaBoost（经典：样本加权——给错分样本加权重）
from sklearn.ensemble import AdaBoostClassifier

# GBDT（梯度提升：用梯度下降拟合残差——现代标准）
from sklearn.ensemble import GradientBoostingClassifier
```

**Boosting 心智**：**"Boosting 降的是'偏差'（系统性误差）"**——"Bagging 是'多个好学生各答各的'，Boosting 是'一个学生反复做错题集'"——**"Boosting = 从'勉强及格'到'不断纠错到优秀'"**；**Boosting 的代价**：串行 = 慢（无法并行）+ 更易过拟合（盯着残差使劲学——**"Boosting 需要正则化（学习率/树深度）来刹车"**）；**Bagging vs Boosting 一句话**：**"Bagging 靠'平均'降波动，Boosting 靠'纠错'提精度——数据噪声大选 Bagging（稳），数据干净选 Boosting（准）"**。

## 4. GBDT 三巨头

**梯度提升家族三巨头（2026 年表格数据的主力军团）**：

```text
GBDT 三巨头
├── XGBoost（2016）：正统先驱——正则化/并行/缺失处理——生态最全
├── LightGBM（2017）：直方图加速——训练最快、内存最省——**2026 表格默认首选**
└── CatBoost（2017）：类别特征原生支持——小样本/高基数类别友好
    ——"三巨头思想同源（梯度提升），工程实现各有绝活——选型看场景"
```

```python
import lightgbm as lgb

model = lgb.LGBMClassifier(
    n_estimators=500, learning_rate=0.05,     # 容量与收敛（03 篇调参四天王）
    num_leaves=31, max_depth=-1,              # 叶子数 = LightGBM 的关键参数
    reg_alpha=0.1, reg_lambda=0.1,            # 正则化（防过拟合刹车）
    random_state=42, verbose=-1,
)
```

**三巨头心智**：**"LightGBM 是 2026 年表格数据的默认首选"**（快 + 准 + 内存省——直方图算法的红利）；**选型差异**：**CatBoost 处理类别特征最优**（直接吃"城市"字符串——省 OneHot——高基数类别场景首选）、**XGBoost 生态最成熟**（文档/社区/部署工具最全——银行等保守场景首选）、**LightGBM 综合最快**（大数据/反复调参首选）——**"先 LightGBM 打底，特殊情况换 CatBoost/XGBoost"**；**三巨头的共同纪律**（03 篇调参课）：early stopping（用验证集早停——`callbacks=[lgb.early_stopping(50)]`——**"早停是最省事的正则化"**）、学习率与树数量联动（学习率小 → 树要多 → 训练慢——"learning_rate 0.01 配 3000 棵树是慢而准的配置"）。

## 5. Stacking：元学习器

**Stacking = 第二层模型学习"如何综合第一层"**——比投票/平均更进一步：

```python
# Stacking 原理（两层）：
# 第 1 层：多个基模型（逻辑回归/随机森林/LightGBM——差异越大越好）
# 第 2 层：元学习器（通常是简单模型——逻辑回归）学习"基模型的预测怎么组合最优"
# 关键：第 2 层的数据必须用"交叉验证预测"（防泄漏——基模型见过测试集就作弊）

from sklearn.ensemble import StackingClassifier

stacking = StackingClassifier(
    estimators=[
        ("lr",  LogisticRegression(max_iter=1000)),
        ("rf",  RandomForestClassifier(n_estimators=200)),
        ("lgb", LGBMClassifier(verbose=-1)),
    ],
    final_estimator=LogisticRegression(),   # 元学习器（简单模型——防过拟合）
    cv=5,                                    # 交叉验证预测（防泄漏）
)
```

**Stacking 心智**：**"Stacking 的收益 = 基模型差异度 × 元学习器克制度"**——**基模型越不同越好**（线性 + 树 + GBDT——覆盖不同"视角"）、**元学习器越简单越好**（逻辑回归——复杂元学习器会过拟合——"第二层学的是'怎么组合'，不是'再学一遍'"）；**Stacking 的代价**：训练复杂度最高（第一层 × 交叉验证 × 第二层——"时间预算不够别 Stacking，LightGBM 单模型已够强"）；**收益预期**：Stacking 比单模型提升通常 1-3%——**"收益不大、复杂度不小——2026 年表格竞赛高手常用，业务落地按需"**（"先确认单模型真的到瓶颈了，再上 Stacking"）。

## 6. 集成选型与边界

**集成选型决策表（写代码前先查）**：

| 场景 | 推荐 | 理由 |
|------|------|------|
| 表格数据默认 | LightGBM | 快准省（GBDT 主力） |
| 特征多/要鲁棒 | 随机森林 | Bagging 抗噪、天然鲁棒 |
| 类别特征多 | CatBoost | 原生类别支持 |
| 要可解释 | 单决策树/线性 + SHAP | 集成可解释性差（08 篇补） |
| 时间预算充足求最优 | Stacking/Optuna 调优 | 最后一公里 |
| 小样本 | 线性/正则化（岭） | 集成在小样本上易过拟合 |

**选型心智**：**"集成的边界：小样本（<1000 行）别上集成——单模型 + 强正则更稳"**（集成需要"多样性"素材——样本少没有素材）；**"集成不是越多越好——模型数量 100 棵后边际收益 ≈ 0"**（n_estimators 500 和 1000 差 0.1%——时间花在特征上更值——**"先特征后集成：特征没做透，集成救不了"**）；**集成结果的诊断**：集成分数 < 单模型 = 有泄漏或基模型太弱——"集成不会魔法般地救活坏数据"（GIGO——垃圾进垃圾出——**"集成的上限还是数据的上限"**）。
