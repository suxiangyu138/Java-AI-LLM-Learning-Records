## 1. 评估的本质：指标跟业务走

**评估指标 = 模型和业务之间的翻译官**——"模型好不好"先问"业务要什么"（阶段 4 08 篇"指标跟着业务代价走"的深化）：

```text
业务目标 → 评估指标
├── 风控（抓坏人）：召回率优先（漏一个坏人损失大）
├── 营销（发券名单）：精确率优先（发错一个人浪费钱）
├── 定价/销量预测：误差优先（RMSE/MAE——金额误差直接对应钱）
└── 排序/推荐：排序指标（AUC/NDCG）
    ——"先问'错了会怎样'，再选指标——业务代价决定指标权重"
```

**评估心智**：**"评估报告的三件套：指标组合 + 分组表现 + 业务解读"**——"准确率 0.85"是单个数字，加上"女性组 0.9、老年组 0.7"（分组表现——发现问题人群）、"对运营的建议是..."（业务解读）才是完整评估——**"单指标评估是偷懒，组合评估才是专业"**；**评估的时机**：训练中（CV）、测试集（最终）、上线后（监控——09 篇）——"评估不是一次性的，是贯穿生命周期的"（01 篇 CRISP-DM 的评估阶段）。

## 2. 回归指标全解

**回归评估五指标——各自回答不同问题**：

```python
from sklearn.metrics import mean_absolute_error, mean_squared_error, r2_score

# ① MAE（平均绝对误差）：直觉、单位一致——"平均差 12 元"（业务最好懂）
# ② MSE（均方误差）：大误差被放大（惩罚离谱预测）——调参常用（梯度友好）
# ③ RMSE（MSE 开方）：回到原单位——"平均差 15 元"（但被大误差拉大）
# ④ MAPE（百分比误差）："平均差 5%"——跨量级可比（注意除零）
# ⑤ R²（决定系数）：解释了多少方差——0.8 = 解释了 80%（不完美但直观）

y_true = [100, 200, 300]; y_pred = [110, 180, 350]
print(f"MAE {mean_absolute_error(y_true, y_pred):.1f}")   # (10+20+50)/3 = 26.7
print(f"RMSE {mean_squared_error(y_true, y_pred)**0.5:.1f}")  # 大误差被放大
print(f"R² {r2_score(y_true, y_pred):.2f}")
```

**回归指标心智**：**"选哪个误差：看'谁在用'"**——给业务看 MAE/MAPE（人话：平均差多少）、调参用 RMSE（惩罚大错）、对比模型用 R²（解释力）——**"MAE 是给老板的，RMSE 是给优化器的"**；**MAPE 的坑**（真实值接近 0 时爆炸——"销量 2 件预测 4 件 = 100% 误差——MAPE 对低值敏感"）；**R² 的坑**（负值 = 比"猜均值"还差——"R² 为负不是'负相关'，是'模型不如瞎猜'"）；**回归的"残差分析"**——"误差分布在哪一段最大？"（高金额段误差大 = 长尾没学好——**"残差分析比总误差更值钱"**——误差集中在哪，改进就在哪）。

## 3. 类别不平衡

**类别不平衡（正样本 1% vs 负样本 99%）——准确率最骗人的场景**：

```python
# 全猜"负"准确率 99%——但业务要的是"找正"
# 处理路径（按顺序）：
# ① 换评估：PR-AUC / 混淆矩阵（先看真相——评估先行！）
from sklearn.metrics import precision_recall_curve, average_precision_score
ap = average_precision_score(y_test, y_proba)     # PR-AUC（不平衡的默认指标）

# ② 调阈值：不调模型，调"决策边界"（默认 0.5 不一定最优）
from sklearn.metrics import precision_recall_curve
prec, rec, thresh = precision_recall_curve(y_test, y_proba)
# 找"精确率 0.8 时"的阈值——业务要多少精确率，阈值跟着定

# ③ 数据/模型层面：class_weight（给少数类加权）/ 采样（SMOTE 过采样）
# ④ 换指标目标：调参时用 f1/pr-auc 而不是 accuracy（03 篇 CV 的 scoring）
```

**不平衡心智**：**"不平衡的处理顺序：先换评估、再调阈值、最后动数据/模型"**——**"90% 的不平衡问题，换评估 + 调阈值就够了——不要一上来 SMOTE"**（采样引入噪声，是最后手段）；**"调阈值是最被忽视的免费午餐"**——默认 0.5 是"五五开"的默认值，不平衡数据的最优阈值常常 0.1-0.3——**"模型输出概率，阈值是业务决策——业务要召回高，阈值放低"**（和方向 A 07 篇"模型做预测，业务做决策"呼应）；**不平衡的检测**：建模前 `y.value_counts(normalize=True)` 一眼看——"类别比 >10:1 就进入不平衡流程"。

## 4. 概率校准

**概率校准 = 让"0.7"真的意味着"70% 会发生"**——模型输出的概率不一定准：

```python
# 校准前：LightGBM 输出的 0.7 可能实际只有 0.5 的概率发生
# 校准方法（sklearn 一行）：
from sklearn.calibration import CalibratedClassifierCV

calibrated = CalibratedClassifierCV(model, method="isotonic", cv=5)
calibrated.fit(X_train, y_train)
# isotonic（保序回归——数据充足时准）/ sigmoid（Platt——小样本稳）

# 校准检查：概率分箱看"预测 0.7 的样本实际正例比例"是否 ≈ 0.7
```

**校准心智**：**"什么时候必须校准：概率本身要用于决策"**——"风控要用'违约概率 0.7'决定批不批——0.7 不准 = 决策全错"（只用来排序则不需要——AUC 只关心排序）；**校准的代价**（额外一层拟合 + 部分信息损失——"不需要概率决策就不校准，加了是负担"）；**校准与评估**——校准度（reliability curve）和区分度（AUC）是两个维度："AUC 高但校准差 = 排序对、绝对值不对"——**"校准回答'概率准吗'，AUC 回答'排序对吗'——两个都要看"**。

## 5. 业务导向的评估框架

**完整评估 = 六步框架（写进评估报告的模板）**：

```markdown
# 模型评估报告（模板）
## 一、业务目标与指标选型
目标：风控拒单（业务代价：漏坏人损失 > 误伤好人）
指标：召回率（目标 0.9）+ PR-AUC + 成本模拟（漏/误的金额）
## 二、总体表现
CV 分数 vs 测试集分数（差距 = 过拟合信号）
## 三、分组表现
按年龄段/金额段分组——哪组表现差（发现问题人群）
## 四、错误分析
混淆矩阵 + 随机抽 20 个错误样本人工看（错误的"形状"）
## 五、业务解读
0.9 召回率意味着什么（每 100 个坏人抓到 90 个——成本算给老板）
## 六、部署建议
阈值设定 + 监控计划（上线后看什么指标——09 篇）
```

**框架心智**：**"评估报告的灵魂：指标选型（业务代价）+ 分组表现（发现问题）+ 错误分析（找改进方向）"**——**"错误分析是评估里最容易被跳过的部分，也是最值钱的"**（抽 20 个错样本看——"错误集中在'新用户'——新用户特征不足，下一步补特征"）；**成本模拟是业务语言的评估**——"把指标翻译成钱：召回率 0.9 = 每月少漏 200 个坏人 = 少损失 40 万"（方向 A 07 篇单位经济思维的 ML 版——**"评估的最终语言是业务语言"**）；**上线后评估**（监控——09 篇）——"模型部署不是评估的结束，是评估的新开始"。
