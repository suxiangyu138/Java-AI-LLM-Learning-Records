## 1. 时序预测的定位

**时序预测 = 用历史序列预测未来值**——业务场景：销量预测（备货）、流量预测（扩容）、收入预测（预算）——**"预测是 ML 里离'钱'最近的场景之一——预测误差 1% 就是真金白银"**。

```text
时序预测的两大流派
├── 统计派：ARIMA/ETS/Theta——数学假设 + 可解释（StatsForecast 家族）
└── 学习派：GBDT 特征工程/深度学习（N-BEATS/TFT）——数据驱动 + 强拟合
    ——"2026 共识：统计派做'强基线'，学习派做'提精度'——先统计后学习"
```

**定位心智**：**"时序预测的第一纪律：基线先行"**——**"用 Naive（拿上次的值）当基线——预测模型打不过 Naive = 白做"**（Nixtla 官方实践反复强调："若模型未优于 Naive 基线则应简化或补充数据"）；**时序预测的常见误区**——"把未来预测当回归做"（随机切分 = 泄漏——本课第 3 节）、"一上来深度学习"（先统计基线——**"深度学习不是默认选项，是最后选项"**）；**预测的边界**——"预测越远越不准（长期预测误差爆炸——先预测 7 天再说 90 天）"、**"预测是概率不是确定"**（给区间不给单点——"销量 1000 ± 150"比"1000"诚实）。

## 2. 数据准备与长格式

**时序数据规范（2026 Nixtla 生态统一格式——三列）**：

```python
import pandas as pd

# 长格式三列：unique_id（序列 id）、ds（时间戳）、y（目标值）
df = pd.DataFrame({
    "unique_id": ["A"] * 365,                          # 序列标识（多序列并列）
    "ds": pd.date_range("2025-01-01", periods=365, freq="D"),
    "y": sales_values,                                 # 目标
})

# 准备三件事：
# ① 频率明确（freq="D"——月=12 周期、周=52 周期——season_length 用）
# ② 缺失检查（时间戳不连续 → 补全或提示）
# ③ 训练/预测切分（时序切分——最后 N 期做测试，不能随机！）
train = df[df["ds"] < "2026-07-01"]
test  = df[df["ds"] >= "2026-07-01"]
```

**准备心智**：**"长格式是 2026 时序库的事实标准"**（statsforecast/neuralforecast/mlforecast 全用 `unique_id/ds/y` 三列——"学一次格式，全生态通用"）；**频率与周期是预测的关键输入**——"日数据月度周期 season_length=30/31、周数据年度周期 52"——**"season_length 设错，季节性模型全错"**；**缺失时间戳**（"中间缺了 3 天——是缺失还是停止营业？"——统计模型对时间戳敏感——先补全（重采样）再预测）；**多序列**（"1000 个 SKU 各 365 天 = 1000 条序列"——StatsForecast 原生支持多序列并行——"单序列练手，多序列实战"）。

## 3. 时序交叉验证

**时序交叉验证 = 滚动窗口——"只允许用过去预测未来"**：

```python
from statsforecast import StatsForecast
# 或手动实现滚动验证：
from sklearn.model_selection import TimeSeriesSplit

# 滚动窗口示意：训练窗口滚动 + 每次预测下一步
# fold1: train=[1..90]   → 预测 91
# fold2: train=[1..91]   → 预测 92（或 [11..101] 滑动）
# fold3: train=[1..92]   → 预测 93 ...

# StatsForecast 内置交叉验证（n_windows=3, h=7：滚动 3 次各预测 7 天）
sf = StatsForecast(models=[model], freq="D", n_jobs=-1)
cv = sf.cross_validation(df=train, h=7, n_windows=3)
# cv 输出每折的预测 vs 真实——直接评估
```

**时序 CV 心智**：**"时序切分的铁律：训练集永远在测试集之前"**——**"随机切分时序 = 用未来预测过去 = 最贵的泄漏"**（02 篇时序泄漏的验证层落地）；**两种窗口**：**扩张窗口**（训练越来越长——信息最大化）vs **滑动窗口**（长度固定——计算省）——"数据少用扩张、数据多用滑动"；**n_windows/h 是验证粒度**（滚动 3 次各预测 7 天 = 检验"7 天预测"的稳定性——"预测多久，就验证多久"）；**时序 CV 的分数**（MASE 等——下节）比单次切分可信——"单次切分可能碰上'恰好简单的未来'——滚动多次是平均成绩"。

## 4. 基线先行：Naive 家族

**预测的第一关：打过 Naive**——三个朴素基线：

```python
# ① Naive：拿"上一个值"当预测（y_t+1 = y_t）——最简单也最难打
# ② SeasonalNaive：拿"上一周期同时刻"的值（周预测 = 上周同日）——有季节性时很强！
# ③ 均值/中位数：拿历史平均——平缓序列的基线

from statsforecast import StatsForecast
from statsforecast.models import Naive, SeasonalNaive

sf = StatsForecast(
    models=[Naive(), SeasonalNaive(season_length=7)],   # 周周期
    freq="D", n_jobs=-1)
sf.fit(train)
forecast = sf.predict(h=7)
print(forecast)      # 三列：ds / Naive / SeasonalNaive
```

**基线心智**：**"SeasonalNaive 是被严重低估的强基线"**——**"有季节性的序列（周/月/年规律），'拿上个周期照抄'往往打赢 80% 的复杂模型"**（Nixtla 案例：电力负荷预测里 Prophet 甚至输给 SeasonalNaive——**"基线都打不过的模型，不配叫模型"**）；**基线先行的工作流**：跑 Naive 家族 → 跑统计模型（AutoARIMA/ETS——下节）→ 跑学习模型——**"每层提升记录对比——预测报告永远带着基线列"**；**业务沟通用基线**——"我们比'拿上周照抄'准了 15%"（老板能听懂基线——"Naive 是预测效果的'锚点'"）。

## 5. StatsForecast：统计预测主力

**StatsForecast（Nixtla 生态，2026 最新 2.0.3，Apache-2.0）——统计预测的主力库**：

```python
from statsforecast import StatsForecast
from statsforecast.models import AutoARIMA, AutoETS, MSTL

# 三件套：AutoARIMA（差分自回归）、AutoETS（指数平滑——季节性强）、MSTL（多季节分解）
sf = StatsForecast(
    models=[AutoARIMA(season_length=7), AutoETS(season_length=7)],
    freq="D", n_jobs=-1)
sf.fit(train)
forecast = sf.predict(h=7)

# 自动选最优模型：Auto 前缀 = 自动搜索超参（不用手调！）
# 性能：AutoARIMA 比 Prophet 快约 500 倍、比 pmdarima 快 20 倍（Numba JIT 重写）
# 规模化：Ray 集群 30 分钟处理 100 万条序列
```

**StatsForecast 心智**：**"Auto 前缀 = 自动选参——统计模型的'调参自动化'（AutoARIMA 自动试差分/阶数）"**——**"Auto 系列是统计派的'默认参数'——统计学家的手艺封装成了参数"**；**模型选型**：**季节性强选 AutoETS/MSTL**（指数平滑是季节性专家）、**趋势+自回归复杂选 AutoARIMA**、**多季节（日+周+年）选 MSTL**（多季节分解——2026 官方教程推荐）；**Prophet 的 2026 定位**：仍是"最广为人知"但**精度与规模化已落后**（逐序列 Stan 拟合慢——AutoARIMA 精度提升 17% 且快 37 倍——Nixtla 基准）——"新项目用 StatsForecast，老 Prophet 管道用 AutoARIMAProphet Adapter 平滑替换"（两行代码换引擎）；**学习派接口一致**（MLForecast 特征工程 / NeuralForecast 深度学习 / TimeGPT 零样本——"同一长格式 + fit/predict——从统计到深度学习无缝升级"）。

## 6. 评估与选型

**时序评估指标——跨序列可比的尺子**：

```python
# ① MASE（平均绝对缩放误差）：和 Naive 比——<1 赢过 Naive、=1 等于、>1 输了
from statsforecast.utils import AirPassengersDF  # 示例数据
# ② sMAPE（对称百分比误差）：百分比可比（比 MAPE 稳——避免除零爆炸）
# ③ 覆盖率（区间预测）：预测区间包含真实值的比例——2026 预测评估标配

# 评估铁律：时序指标选 MASE/sMAPE（跨序列/跨频率可比——MAE/RMSE 单序列还行，跨序列不可比）
# 预测报告结构：模型 vs 基线对比 + MASE + 区间覆盖率 + 业务解读（误差=多少钱）
```

**评估心智**：**"MASE 是时序评估的第一指标——'比 Naive 好多少'是通用语言"**（MAE 100 元在日销 100 万和 1000 的序列上意义完全不同——**"MASE 用基线缩放误差，让'好坏'跨序列可比"**）；**区间预测是 2026 的标配**（"点预测 + 区间（如 80% 置信）——业务备货要的是区间不是单点"——"只给单点的预测报告是半成品"）；**评估的选型路径**：先 MASE 过基线 → 再看业务误差（"误差 5% 对应库存成本多少"——把 MASE 翻译成钱——方向 A 07 篇单位经济思维的预测版）；**选型总结**：**"小数据/要解释 → 统计派（AutoETS/AutoARIMA）；大数据/要精度 → 学习派（LightGBM 特征工程或 NeuralForecast）——2026 共识：先 StatsForecast 建强基线，赢了再升级"**。
