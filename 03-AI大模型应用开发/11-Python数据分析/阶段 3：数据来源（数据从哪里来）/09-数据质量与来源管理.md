## 1. 数据质量的五维评估

**01 篇的来源五问是"拿之前"，这里是"拿之后"的持续评估**——数据质量五个维度（阶段 1 的 GIGO 概念展开）：

```text
数据质量五维
├── 完整性：该有的行/列有没有？（缺行 = 采集不全）
├── 准确性：数值和真值差多远？（口径对不对）
├── 一致性：同一字段跨来源是否统一？（A 库"男"B 库"1"）
├── 时效性：数据新鲜吗？（昨天的订单 vs 三年前的）
└── 可复现性：换台机器重跑能拿到同样数据吗？（种子/版本/接口参数）
```

**五维心智**：**"每次拿数据都过五维"**——完整性用行数对比（和上次/和官方公布的数对比——**"行数对不上是第一个报警信号"**）；准确性靠抽样核对（抽 50 行和原始来源比对）；一致性在 03 篇类型校准时就该发现；时效性看获取时间戳；可复现性靠"获取脚本 + 固定版本"——**"拿数据不是一次性的，是每个分析周期都要重来的——五维评估让它可重复"**。

## 2. 数据契约

**数据契约 = 提供方与使用方的"格式约定"**——解决"上周字段叫 `price`，这周改成 `amt`"的日常灾难：

```python
# 数据契约（简版）——拿数据前先确认三件事
CONTRACT = {
    "来源":    "sales_api",           # 提供方
    "版本":    "v2",                  # 接口/数据集版本
    "字段":    {"order_id": "int", "amount": "float", "date": "date"},
    "更新频率": "每日 02:00",
    "缺失策略": "金额缺失 = 退款订单，不补填",
}
```

**契约心智**：**"契约的核心是'字段、类型、更新频率'三件套"**——写清楚，三个月后 API 升级、字段改名时你有据可查；**契约要落到文件**（README 或 `contract.json`——别只记在脑子里）；**接数据前先验契约**（`assert set(CONTRACT["字段"]) <= set(df.columns)`——字段缺失立刻报错，别让脏数据溜进分析）——**"契约是分析师的护身符：接口改了，你的代码第一个知道"**；进阶方向：正式的数据契约工具（如 Great Expectations——做数据质量断言检查），2026 年已是数据工程标配——**"本课用手写 assert，工程上用框架——思路同源"**。

## 3. 目录与版本管理

**数据文件要"有家可归、有名可查"**——推荐目录结构：

```text
project/
├── data/
│   ├── raw/           原始数据（下载/抓取的原样——永不修改！）
│   │   ├── orders_20260810_kaggle_v2.csv
│   │   └── api_sales_20260810.json
│   ├── processed/     处理后数据（清洗/转换后——可再加工）
│   └── sim/           合成数据（和真实数据物理隔离——08 篇）
├── scripts/           获取脚本（可复现的关键）
│   └── fetch_orders.py
└── README.md          数据来源总说明
```

**目录心智**：**"raw 永远不修改"**是数据管理第一铁律——原始数据是唯一真相，清洗错了可以重来（**"原始数据 = 底片，处理数据 = 照片——底片永远保留"**）；**文件名 = 数据的身份证**：`主题_日期_来源_版本`（`orders_20260810_kaggle_v2.csv`——一看就懂）；**获取脚本和代码一起管理**（git 入库——脚本是数据可复现的钥匙——**"没有脚本的数据是死数据，有脚本的数据是活数据"**）。

## 4. 元数据：数据来源卡

**每个数据集配一张"来源卡"**——数据的身世档案：

```markdown
# 数据来源卡：orders
- 来源：Kaggle 数据集 sales-orders（作者 xxx）
- 下载时间：2026-08-10 14:32
- 版本：v2（2026-06 更新）
- 许可：CC-BY 4.0（可商用，需署名）
- 规模：2.3GB / 8,500,000 行 / 23 列
- 获取方式：kagglehub 下载（脚本 scripts/fetch_orders.py）
- 已知问题：2024-03 前的 amount 含税口径不同（契约注明）
```

**来源卡心智**：**"来源卡回答四个问题：谁给的、什么时候、怎么拿的、能用来干嘛"**——许可（能不能商用/发布——02 篇五看）、已知问题（口径变化——**"前人踩过的坑写进卡里，后人不再踩"**）；来源卡放数据集同目录的 `README.md` 或每个数据集一个 `.md`；**面试讲项目时"我的每个数据集都有来源卡，记录许可和口径"是专业性的标志**——"来源卡 = 分析的可信度证明"。

## 5. 获取后体检清单

**每次数据落地，过一遍体检清单**（获取环节的最后一道闸）：

```python
def data_source_check(df, contract, source):
    """数据获取后体检——返回检查结果列表"""
    checks = []
    checks.append(("行数", len(df)))
    checks.append(("列数", len(df.columns)))
    checks.append(("字段齐全", set(contract["字段"]) <= set(df.columns)))
    checks.append(("缺失率", df.isna().mean().max()))       # 最大缺失率
    checks.append(("重复率", df.duplicated().mean()))
    return checks
```

**体检清单十项**（简化版）：

1. **shape 对得上预期吗**（行数比上次少 20%？报警）
2. **字段齐全**（契约字段都在？）
3. **类型正确**（`df.dtypes`——日期是 datetime？金额是 float？）
4. **缺失率**（`df.isna().mean()`——哪些列缺得离谱）
5. **重复率**（`df.duplicated().sum()`——全列重复？）
6. **数值分布**（`describe()`——负数金额？离谱最大值？）
7. **类别分布**（`value_counts()`——出现"未知"类别？）
8. **时间范围**（min/max 日期——覆盖期对不对）
9. **抽样核对**（抽 20 行和原始来源比对）
10. **记录结果**（体检结果写进来源卡——"体检留痕"）

**体检心智**：**"获取后体检 = 清洗前体检"**——拿到手的瞬间做，把"来源问题"和"数据问题"分开（来源问题回去找提供方，数据问题留给清洗——`../../阶段%202：核心三大库（必学）/Pandas%20—%20数据分析主力库/03-数据清洗.md`）；**体检结果要留痕**（写进来源卡——"这次数据有 3% 缺失"——**"留痕的体检才是体检，不记录等于没做"**）；**行数对比是最便宜最有效的报警**——和上次差 20% 以上，多半是口径/采集出问题了。
