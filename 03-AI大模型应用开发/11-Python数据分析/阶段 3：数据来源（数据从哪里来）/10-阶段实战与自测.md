## 2. 四路汇流完整代码

### 2.1 第一路：文件（CSV 读入 + 体检）

```python
import pandas as pd

users = pd.read_csv("data/raw/users_202607_ops.csv", encoding="utf-8-sig")
print(f"用户数: {len(users)}")          # 体检：行数对比
users = users.rename(columns={"cust_id": "user_id"})   # 口径统一（契约）
```

### 2.2 第二路：数据库（SQLite 取数）

```python
from sqlalchemy import create_engine

engine = create_engine("sqlite:///data/raw/sales.db")
orders = pd.read_sql_query(
    """SELECT user_id, amount, order_date, city
       FROM orders WHERE order_date >= '2026-07-01'
         AND order_date <  '2026-08-01'""",
    engine, params=(),            # 只取所需列 + WHERE 过滤（04 篇纪律）
)
print(f"订单数: {len(orders)}")     # 和上月对比，看是否有量级异常
```

### 2.3 第三路：API（天气数据）

```python
import requests

def fetch_weather(city, start, end):      # 05 篇封装：认证+重试+落地
    resp = requests.get(WEATHER_URL, params={"city": city, "start": start, "end": end},
                        headers={"X-API-Key": API_KEY}, timeout=(3, 15))
    resp.raise_for_status()
    df = pd.json_normalize(resp.json()["data"])
    df.to_parquet(f"data/raw/weather_{city}.parquet", engine="pyarrow")
    return df

weather = pd.concat([fetch_weather(c, "2026-07-01", "2026-07-31")
                     for c in ["北京", "上海", "广州"]])
```

### 2.4 第四路：合成（缺字段补全）

```python
from faker import Faker
fake = Faker("zh_CN"); Faker.seed(42)

users["age_band"] = users["user_id"].apply(lambda _: fake.random_int(18, 65))
# 业务模拟：老用户年龄偏大（08 篇——逻辑要编码进生成，不是纯随机）
```

### 2.5 汇流与质检

```python
df = orders.merge(users[["user_id", "age_band"]], on="user_id", how="left")
df = df.merge(weather, on=["city", "date"], how="left")   # 三表合一（merge 三连）

# 获取后体检（09 篇清单）
print(df.shape, df.isna().mean().max(), df.duplicated().sum())
df.to_parquet("data/processed/sales_aug_report.parquet", engine="pyarrow")
# 来源卡 + 契约 + 获取脚本进 git（09 篇——全部留痕）
```

**汇流心智**：**"merge 之前先统一口径（user_id/city/date 列名与类型）"**——字段不一致的 merge 是行数爆炸/NaN 泛滥的源头（`../../阶段%202：核心三大库（必学）/Pandas%20—%20数据分析主力库/05-合并与连接.md`）；**每路数据落地 raw、汇流产物进 processed**——"四路进、一路出、出处全可查"。

## 4. 报错速查 10 条

| 报错/现象 | 原因 | 解法 |
|---------|------|------|
| `FileNotFoundError` | 路径错 | 先 `os.listdir()` 看实际文件名（中英文/扩展名） |
| `UnicodeDecodeError` | 编码不是 utf-8 | 试 `encoding="gbk"` 或 `encoding="gb18030"` |
| `No module named 'pandas'` | 环境没装 | 检查是否在正确的 venv（阶段 1 环境课） |
| `Expected object or value` | read_json 没写 lines=True | `pd.read_json(path, lines=True)` |
| `OperationalError: no such table` | SQLite 表名错 | `SELECT name FROM sqlite_master` 看表 |
| `OperationalError: no such column` | SQL 列名错 | 先 `PRAGMA table_info(表名)` 看列 |
| HTTP 401/403 | 钥匙问题 | 检查 API Key/Bearer 是否有效（不是重试能解决的） |
| HTTP 429 | 限流 | `Retry-After` + 指数退避 + 减慢请求频率 |
| `KeyError: 'xxx'` | 列名不对 | 契约 assert 前置；打印 `df.columns` 核对 |
| Faker `UniquenessException` | unique 值耗尽 | 加大样本空间或换生成策略 |

**报错心智**：**"报错先读全、再翻译、再动手"**——大多数报错是"名不对/编码不对/参数不对"三类（**"报错是信息，不是灾难——它告诉你哪里和预期不同"**）——**"同一个报错第二次发生，就该写进自己的速查表"**。

## 6. 面试问答 3 题

**Q1：你的项目数据从哪来？**——答：**"四路来源：公开数据集（Kaggle 下载+来源卡记录许可）、公司 SQLite（read_sql 只取所需列+参数化）、开放 API（认证+分页+指数退避重试）、缺口用 Faker 合成补齐——每路落地 raw 目录并写来源卡"**——结构：**来源 → 方式 → 管理**——"答出'来源卡/契约'显示专业度"。

**Q2：数据质量你怎么保证？**——答：**"获取后体检十项（行数对比/字段/类型/缺失/重复/分布）+ 抽样核对原始来源；数据契约用 assert 前置校验；体检结果留痕进来源卡——来源问题回查提供方，数据问题交给清洗阶段"**——**"把质量分成'来源的'和'数据的'，是分析师成熟的标志"**。

**Q3：爬虫课程学了很多，你项目里用到了吗？**——答：**"用到最小闭环：静态表格用 pd.read_html 取数；动态页面先找接口直取（比渲染快 10 倍）；反爬攻坚不在分析师职责内——我判断数据价值后决定值不值得投入采集成本"**——**"'会用但克制'比'全都会'更显职业判断"**。
