## 1. 文本数据三兄弟

**大量数据以"半结构化文本"存在**——不是 CSV 也不是 Excel，但里面有规律可挖。常见三种形态：

```text
文本数据三兄弟
├── JSONL（JSON Lines）：每行一个 JSON 对象——流式/日志/导出首选
├── 日志（log）：时间戳 + 级别 + 消息——系统运行的大事记
└── 定宽文本：列宽固定（如老系统导出）——按列切分
```

**文本心智**：**"文本数据的共同点：有结构但没表头"**——你的工作就是**从文本里认出结构，把它变成表**——**"文本是散装的数据，DataFrame 是装好的箱"**。本课与后端日志体系（`../../../02-后端核心技术%20微服务%20分布式%20云原生/07-工程运维基础/运维/日志监控指标/`——管日志采集与监控）分工：**他们管"日志怎么产、怎么收"，我们管"日志怎么变成分析素材"**。

## 2. JSON Lines：一行一条的流式数据

**JSONL = 每行一个完整 JSON 对象**——日志流、导出文件、数据管道的最爱——**为什么不是大 JSON？**：大 JSON 要整体解析（一个括号错全废），JSONL 一行独立（坏一行丢一行）——**"JSONL 是为流式和容错设计的格式"**：

```python
import pandas as pd

# 读 JSONL：lines=True 是关键（每行一条）
df = pd.read_json("events.jsonl", lines=True)

# 字段不一致时：先读成列表再展开
import json
rows = [json.loads(line) for line in open("events.jsonl", encoding="utf-8")]
df = pd.json_normalize(rows)          # 嵌套字段展开（03/05 篇同款）
```

**JSONL 心智**：**"`lines=True` 是 read_json 读 JSONL 的钥匙"**——忘写了会报"Expected object or value"（它把整文件当一个 JSON 解析，第一行后面全成了垃圾）；**字段不齐（有的行缺某字段）用 json_normalize 兜底**（缺失字段自动变 NaN——`../../阶段%202：核心三大库（必学）/Pandas%20—%20数据分析主力库/03-数据清洗.md` 的缺失值处理）；**超大 JSONL 用 `chunksize` 分块**（`pd.read_json(path, lines=True, chunksize=100_000)`——03 篇分块思路的文本版）。

## 3. 日志解析：正则提取

**日志是"一行一个事件"的文本**——用正则把字段抠出来：

```python
import re
import pandas as pd

line = "2026-08-10 14:23:45,123 ERROR [order-service] 下单失败 order_id=9527 amount=99.5"

# 命名分组提取（(?P<name>...) 是提取的关键）
pattern = (
    r"(?P<time>\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2})"   # 时间戳
    r"\s+(?P<level>\w+)"                                # 级别
    r"\s+\[(?P<service>[^\]]+)\]"                       # 服务名
    r"\s+.*?order_id=(?P<order_id>\d+)"                 # 订单号
    r"\s+amount=(?P<amount>\d+\.?\d*)"                  # 金额
)

rows = []
for line in open("app.log", encoding="utf-8"):
    m = re.search(pattern, line)
    if m:
        rows.append(m.groupdict())      # {"time": ..., "level": ...}

df = pd.DataFrame(rows)
df["time"] = pd.to_datetime(df["time"])   # 字符串 → 时间类型（时序分析的前提）
```

**日志解析心智**：**"正则提取三步：看样本 → 写模式 → 验证边界"**——先拿 5 行真实日志写模式，用 `re.search` 逐个验证（**一行写错模式，全量解析全废——先小样本跑通再全量**）；`(?P<name>...)` 命名分组直接生成字典——**"命名分组是给列名起名"**（列名即代码注释——阶段 1 的列名规范）；**匹配不到的行别丢**——统计一下 `match_count / total_lines`（覆盖率 <90% 说明模式漏了边界情况——**"解析的完成度要量化，别默默丢数据"**）；**级别分布用 value_counts 看一眼**（`df["level"].value_counts()`——ERROR 占比异常高就是事故信号——运维的"告警"在分析里叫"洞察"）。

## 4. 固定宽度文本 read_fwf

**老系统/银行对账等场景常见定宽文本**——每列占固定字符数，靠位置切分：

```python
import pandas as pd

# read_fwf：按"列宽"切分（names 是列名、widths 是每列宽度）
df = pd.read_fwf(
    "account.txt",
    names=["date", "type", "amount", "memo"],
    widths=[8, 4, 12, 30],          # 每列占几格——来自字段说明文档
)
```

**定宽文本心智**：**"widths 必须来自字段文档，不能靠猜"**——猜错一列宽，后面全错位（**"一个格子错位，整行数据错位——这是定宽文本最阴的坑"**）；没有文档时先看最长行/对齐规律推断，验证方式：读出来的 `df["amount"]` 是否全是数字；**现代系统已少用定宽**——遇到多为遗留系统对接——**"老格式少，但踩到要会"**。

## 5. 文本转表格的流程

**所有文本数据走同一个五步流程**：

```python
# ① 探路：head 看 10 行原始文本，确认结构
# ② 建模：写解析模式（正则/分隔符/列宽）
# ③ 小样本验证：解析 100 行，确认字段齐全、类型正确
# ④ 全量解析：跑全文件（带进度与覆盖率统计）
# ⑤ 体检落地：四连击体检 + to_csv/to_parquet 落地
```

**流程心智**：**"探路 → 建模 → 验证 → 全量 → 落地"**是文本解析的完整闭环——**跳过验证直接全量 = 100 万行数据错在同一个模式上**（**"解析错是全量错，不是偶然错"**）；落地格式建议 Parquet（解析一次的产物值得好好存——03 篇）；**解析代码和原始文件都要留档**（09 篇——"三个月后重跑一次解析，代码在、文件在、结果可复现"）。

**日志分析的价值场景**（学会解析，能回答三类问题）：**① 服务健康**——按级别统计错误率趋势（`df["level"].value_counts()` 按天分组——**"错误率爬升比任何监控系统都早发现"**）；**② 用户行为**——访问日志里的路径/耗时字段是天然的漏斗分析素材；**③ 业务审计**——"某订单失败了几次、每次报什么错"——**"日志是系统的日记本——分析师的洞察往往从'翻日记'开始"**——注意：日志字段常常只有后端才知道含义（`order_id=9527` 是谁记的），**拿不准的字段问后端**——"日志的字段字典，写在别人脑子里，问出来就是你的"。
