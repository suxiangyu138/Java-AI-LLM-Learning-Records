## 1. 格式选型：别再什么都塞 CSV

**CSV 是"人类可读"但不是"机器高效"**——阶段 1 只教了 CSV 的读法（最小闭环），生产级读取的第一件事是**选对格式**：

```text
文件格式选型
├── CSV：小文件、要给人看、要交接——人类可读（stage 1 已会）
├── Parquet：大文件、频繁读、要性能——机器高效（本课主角）
├── JSONL：流式日志、一行一条、要追加——每行独立（07 篇）
├── Excel：别人发来的报表——多 sheet 注意（本课）
└── JSON：接口数据、嵌套结构——要展开（本课）
```

**选型心智**：**"数据 <10MB 且偶尔读 → CSV；数据大/反复读 → Parquet；流式追加 → JSONL"**——尤其记住 Parquet 的收益：**体积比 CSV 小 80-90%、读取快 10-100 倍、dtype 类型自动保留**（CSV 读进来 int 变 object 的坑直接消失）——代价是**二进制不可直接看**（要审计给人看时用 CSV）——"Parquet 省的是时间与内存，CSV 省的是眼睛"。

## 2. Parquet：列式存储的新主角

**Parquet = 列式存储**：同一列的数据物理上挨着放，所以"只读三列"时只碰三列的数据块——这就是它快的根本原因。pandas 3.x 读 Parquet 的标准姿势：

```python
import pandas as pd

# 读：指定 columns 只取需要的列 + filters 只取需要的行（谓词下推）
df = pd.read_parquet(
    "sales.parquet",
    engine="pyarrow",                       # 固定引擎，避免环境漂移
    columns=["order_id", "amount", "date"],  # 只读 3 列（省内存的关键）
    filters=[("date", ">=", "2026-01-01")],  # 行级过滤（跳过多余行组）
)

# 写：把 CSV 转成 Parquet（一次性投资）
df.to_parquet("sales.parquet", engine="pyarrow")
```

**Parquet 心智**：**"columns 和 filters 是读 Parquet 的两把钥匙"**——不指定就全量读 = 白用 Parquet；**列存 + 过滤下推让"10GB 数据只花 1GB 内存"成为可能**；写入侧调优影响读取速度 3 倍以上：**row_group_size 建议 64-128MB、按高频过滤字段排序**（比如按时间排序让日期过滤生效）——**"写的时候排好序，读的时候快三倍"**。注意读 Parquet 底层是 pyarrow（`pyarrow.parquet.read_table()`），极度追求速度时可绕过 pandas 直接用 pyarrow 读再转 DataFrame——**"pandas 是家用车，pyarrow 是赛车"**。

## 3. 大 CSV 分块读取

**CSV 太大读不动？三步瘦身**：

```python
# 第一步：先只读一小块探路（nrows——先看结构再定策略）
df_sample = pd.read_csv("big.csv", nrows=1000)

# 第二步：指定列名与类型（dtype——避免 int 变 object 的 DtypeWarning）
df = pd.read_csv("big.csv", usecols=["id", "amount", "date"],
                 dtype={"id": "int64", "amount": "float64"})

# 第三步：分块迭代（chunksize——内存不够时的标准姿势）
for chunk in pd.read_csv("big.csv", chunksize=100_000):
    process(chunk)          # 每块 10 万行，处理完即释放
```

**分块心智**：**"能一次读就不分块，分块是内存不够时的退路"**——`usecols` 只取需要的列永远先做（**"SQL 里少一行，内存里省一块"的 CSV 版**）；`chunksize` 适合"逐块聚合"（求和/计数可以在循环里累加）但不适合"全局排序"（要全量）；pandas 3.x 对 CSV 读取有持续优化（二进制文件对象直读避免多余包装）——**"版本升级就是白赚的性能"**（`../../阶段%201：前置基础/01-Python环境与数据分析工具箱.md` 的版本纪律）。

**CSV 的三个隐藏陷阱**（都源于"CSV 没有类型概念"）：**① 大数字变科学计数法**（订单号 `123456789012` 读成 `1.234568e+11`——先 `dtype={"order_id": "str"}` 指定字符串）；**② 列名被自动改名**（两列都叫 `amount` 会被改成 `amount` 和 `amount.1`——读出来第一眼核对 columns）；**③ 空值混类型**（一列大部分是数字、有几个空，整列变 float——**"一个空值毁掉整列的类型"**）——这三个坑 `Parquet` 天生没有（dtype 写在文件里）——**"CSV 的坑，是选 Parquet 的最好理由"**。

## 4. Excel 多 sheet 与嵌套 JSON

**Excel——多 sheet 是第一个坑**：

```python
# 只读第一个 sheet 是默认，但报表往往有 3 个 sheet
df = pd.read_excel("report.xlsx", sheet_name="销售明细")   # 指定 sheet
sheets = pd.read_excel("report.xlsx", sheet_name=None)      # 全部 sheet → dict
# 返回 {"销售明细": df1, "客户表": df2, ...}——字典按 sheet 名取
```

**嵌套 JSON——接口数据的常态**（`../../阶段%201：前置基础/05-数据读写与文件格式.md` 的 json_normalize 在这里转正）：

```python
import json, pandas as pd

data = json.load(open("orders.json"))   # [{"id":1, "user":{"name":"张三","age":25}, ...}]
df = pd.json_normalize(data)             # 自动展开嵌套的 user 字段 → user.name/user.age 列
```

**两坑心智**：**Excel 一定要问"有几个 sheet"**——漏 sheet 等于漏数据；**嵌套 JSON 用 json_normalize 展开成扁平表**——接口返回的"对象套对象"是常态，`json_normalize` 把嵌套路径变成带点的列名（`user.name`）——**"嵌套 JSON 不是拿来就用的，要先展开成表"**。

## 5. 编码与读取四连击

**编码——中文数据的老朋友**：`read_csv` 乱码先试 `encoding="utf-8"`，报错再试 `"gbk"`/`"gb18030"`（阶段 1 的乱码三步法）；**读前探路比读后补救便宜**——不知道编码时先 `nrows=5` 试读——**"5 行能验证编码，500 万行不行"**。

**读取四连击（每份文件的固定开场）**：

```python
df.shape     # 多大？（行, 列）
df.head()    # 长啥样？
df.info()    # 类型与缺失（读进来的 dtype 对不对）
df.describe()# 数值分布（一眼看出异常）
```

**四连击心智**：**"读进来的瞬间就体检"**——Parquet 读进来 dtype 大概率对，CSV 读进来大概率要调 dtype——**"四连击回答'我读对了吗'，回答不了'数据对吗'（那是阶段 2 清洗的事）"**——本阶段只负责"读进来是对的"，清洗是 `../../阶段%202：核心三大库（必学）/Pandas%20—%20数据分析主力库/03-数据清洗.md` 的事。

**给同事的文件交接建议**（你可能是数据提供方）：**给别人 CSV 时附带列说明**（类型/含义/口径——09 篇契约的轻量版）；**文件命名带日期与版本**（`sales_20260810_v2.csv`）；**同一个分析的原始数据与处理数据分目录放**（raw/processed——09 篇）——**"你顺手写的三行说明，能救同事一下午"**。
