## 1. 保存与加载

### 保存格式对比

| 格式 | 特点 | 适用 |
|---|---|---|
| .pt/.pth（state_dict） | PyTorch 原生 | 训练/实验 |
| safetensors | 安全 + 零拷贝快 | **生产/分享推荐** |
| 全模型保存 | 含结构（pickle 风险） | 少用 |

### 推荐做法

```python
# 保存（推荐 safetensors）
from safetensors.torch import save_file, load_file

save_file(model.state_dict(), "model.safetensors")
state = load_file("model.safetensors")        # 安全（无代码执行风险）
model.load_state_dict(state)

# 或 state_dict + weights_only（PyTorch 原生）
torch.save(model.state_dict(), "model.pt", weights_only=True)
```

> ⚠️ 安全铁律（延续 05 篇）：**只用 `weights_only=True` 或 safetensors 加载**——`torch.load` 默认反序列化任意对象（任意代码执行）；永远不加载来源不明的模型文件（HF 下载也要校验 hash）。

### 保存加载注意

| 注意 | 说明 |
|---|---|
| 只存 state_dict | 不存模型类（结构变化不兼容） |
| 兼容性 | 模型定义与 state_dict 键匹配 |
| 检查点 | 存 model+optimizer+epoch（05 篇） |
| 跨设备 | map_location 加载（cpu 加载 cuda 权重） |

## 2. 导出路线图

```
部署形态 → 导出方式：
PyTorch 生态部署 → torch.export / compile AOT
跨框架部署 → ONNX
C++/移动端 → AOTInductor / TorchScript（存量）
LLM 服务 → vLLM 等专用引擎（见推理体系）
```

| 目标 | 导出 |
|---|---|
| Python 服务（最快） | torch.compile + 直接部署 |
| 预编译免冷启动 | aot_compile |
| 跨框架（Java/.NET/移动） | ONNX |
| C++ 无 Python 环境 | AOTInductor |
| LLM 推理 | 专用引擎（vLLM/TensorRT-LLM） |

## 3. torch.export 与 TorchScript

### TorchScript（存量）

```python
# 旧方式（1.x 时代）
scripted = torch.jit.script(model)
scripted.save("model.pt")
```

```
现状：torch.jit 在 Python 3.14 不保证
官方建议：迁移到 torch.compile / torch.export
```

### torch.export（官方推荐）

```python
import torch

# 导出静态图（生产部署）
exported = torch.export.export(model, (example_input,))
# 保存/加载
torch.export.save(exported, "model.exported")
loaded = torch.export.load("model.exported")
```

### export 的特点

| 特点 | 说明 |
|---|---|
| 静态图 | 追踪后固定（部署确定性） |
| 可移植 | 跨平台加载 |
| 输入约束 | 动态 shape 需指定（dynamic_shapes） |
| 与 compile 关系 | export 输出可被 compile/AOTInductor 消费 |

## 4. ONNX 导出与推理

### 导出

```python
import torch.onnx

torch.onnx.export(
    model,                       # 模型（eval 模式）
    (example_input,),            # 示例输入（定义输入形状）
    "model.onnx",
    input_names=["input"],
    output_names=["output"],
    dynamic_axes={"input": {0: "batch"}, "output": {0: "batch"}},  # 动态 batch
)
```

### 推理（ONNX Runtime）

```python
import onnxruntime as ort

sess = ort.InferenceSession("model.onnx", providers=["CUDAExecutionProvider", "CPUExecutionProvider"])
outputs = sess.run(None, {"input": input_numpy})
```

### ONNX 适用

```
跨语言/平台（Java/C++/.NET/移动）
无 Python 环境部署
性能：ORT 优化（比 eager 快）
LLM 不适用（专用引擎更优）
```

## 5. torch.compile AOT 部署

### aot_compile（2.10 新能力）

```python
# 预编译：消除生产冷启动编译延迟
compiled = torch.compile(model, fullgraph=True)
compiled.aot_compile(example_input)    # 主动追踪+编译+封装

# 序列化到磁盘
compiled.save_compiled_function("model_compiled.pt")

# 其他进程/机器加载（免重编译）
loaded = torch.compiler.load_compiled_function("model_compiled.pt")
```

### AOT 的价值

| 价值 | 说明 |
|---|---|
| 消除冷启动 | 生产首次调用不等待编译 |
| 跨进程复用 | 编译一次到处加载 |
| 交叉编译 | fake tensors 跨设备 |
| 确定性 | 编译结果固定 |

### AOTInductor（C++ 部署）

```
面向 C++ 无 Python 环境（vs aot_compile 留在 Python 运行时）
用于：边缘设备/嵌入式/极致性能
```

## 6. 推理服务化

### 标准推理服务（FastAPI）

```python
from fastapi import FastAPI
import torch

app = FastAPI()
model = load_model("model.safetensors")   # 启动时加载一次
model.eval()

@app.post("/predict")
def predict(data: dict):
    x = torch.tensor(data["x"]).to(device)
    with torch.no_grad():
        logits = model(x)
    return {"logits": logits.tolist()}
```

### 服务化要点

| 要点 | 说明 |
|---|---|
| 模型加载一次 | 全局加载（勿每次请求加载） |
| eval + no_grad | 推理确定性 + 省内存 |
| 批处理 | 请求合并（吞吐） |
| 预热 | 首次请求前 warmup（compile 编译） |
| 监控 | 延迟/吞吐/显存（见推理体系） |

### 与大模型推理的分工

```
小模型/自研模型 → PyTorch 服务（本节）
大模型/LLM → vLLM/TensorRT-LLM（连续批处理/量化）
（详见 `03-AI.../模型推理与部署/` 体系）
```

## 7. 部署形态选型

| 场景 | 方案 |
|---|---|
| Python 服务（小模型） | torch.compile + FastAPI |
| 预编译免冷启动 | aot_compile |
| 跨框架/移动端 | ONNX + ORT |
| C++ 边缘 | AOTInductor |
| LLM | vLLM 等专用引擎 |
| 实验/研究 | state_dict 直接加载 |

### 决策顺序

```
① 部署环境？（Python/C++/跨框架）
② 冷启动要求？（aot_compile）
③ 性能要求？（compile/ORT）
④ LLM？→ 专用引擎
```

## 8. 面试高频问法

| 问题 | 回答要点 |
|---|---|
| 保存推荐什么？ | state_dict + safetensors（安全） |
| torch.load 安全？ | weights_only=True 必加（任意代码执行风险） |
| TorchScript 现状？ | 弃用中——官方迁移 compile/export |
| export 是什么？ | 静态图导出（生产部署） |
| ONNX 适用？ | 跨框架/移动端（LLM 不适用） |
| aot_compile？ | 预编译消除冷启动（2.10） |
| 服务化注意？ | 模型加载一次 + eval + warmup |

### 面试加分表达

> "部署我按'形态决定导出'：Python 服务直接 torch.compile（一行接入），要免冷启动用 aot_compile（2.10 新能力，编译一次跨进程加载），跨框架走 ONNX。安全上只用 safetensors 或 weights_only=True 加载——torch.load 默认会反序列化任意对象，这是任意代码执行漏洞。"

> 🎯 核心要点：保存 safetensors 优先 + weights_only 必加（安全铁律）；TorchScript 弃用（迁移 export/compile）；ONNX 用于跨框架/移动端（LLM 除外）；aot_compile 消除冷启动（编译一次到处加载）；服务化三要点（加载一次/eval/warmup）；大模型走 vLLM 等专用引擎。
