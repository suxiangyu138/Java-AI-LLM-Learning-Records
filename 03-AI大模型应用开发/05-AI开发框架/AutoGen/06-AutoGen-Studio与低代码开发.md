## 1. AutoGen Studio 是什么

| 维度 | 说明 |
|---|---|
| 定位 | AutoGen 的低代码可视化界面 |
| 用户 | 非工程人员（搭 Agent）+ 工程人员（快速原型） |
| 形态 | Web 应用（本地/容器部署） |
| 能力 | 拖拽搭团队、调试消息流、评估效果 |

### 价值

```
① 零代码：拖拽 Agent/工具 → 生成可运行的多 Agent 应用
② 可视化调试：看消息流、看谁说了什么
③ 快速原型：工程人员用它验证思路，再写代码
④ 评估内置：对 Agent 表现打分
```

> 定位提醒：Studio 是"原型与协作工具"，生产级应用还是代码编写（Studio 的配置可导出为代码）。

## 2. 安装与启动

```bash
# 安装（含 Studio 依赖）
pip install "autogenstudio"

# 启动
autogenstudio ui --port 8081
# 浏览器打开 http://localhost:8081
```

### 依赖说明

```
Studio 需要数据库（SQLite 默认）存储配置与运行记录
环境要求与 AgentChat 一致（模型客户端配置在界面里完成）
```

## 3. 核心功能

| 功能 | 说明 |
|---|---|
| Agent 库 | 预置 AssistantAgent/UserProxy 等，可配模型与工具 |
| 团队构建器 | 拖拽组装多 Agent 团队 |
| 会话运行 | 运行对话并查看完整消息流 |
| 评估面板 | 对 Agent 回答打分（LLM 评审） |
| 会话历史 | 保存/回放运行记录 |

### 概念映射（Studio ↔ 代码）

| Studio 概念 | 代码对应 |
|---|---|
| Agent 卡片 | AssistantAgent(...) |
| 团队画布 | RoundRobinGroupChat / SelectorGroupChat |
| 工具注册 | FunctionTool |
| 运行 | team.run_stream() |
| 导出 | 生成 Python 代码 |

## 4. 工作流搭建

### 搭建步骤

```
① 配置模型（界面填 API Key/端点/模型名）
② 创建 Agent（选类型 + 写系统提示 + 挂工具）
③ 组装团队（拖拽 + 选模式）
④ 运行会话（输入任务 → 看消息流）
⑤ 迭代（改提示/工具 → 重跑）
```

### 实践建议

| 建议 | 说明 |
|---|---|
| 先小后大 | 2 个 Agent 验证，再扩展 |
| 系统提示写细 | Studio 里提示词是核心调优手段 |
| 工具先本地测 | 工具注册前单独验证函数 |
| 导出保留 | 调好的配置导出为代码入库 |

## 5. 调试与可观测

### Studio 的调试优势

```
代码调试：print 打断点
Studio 调试：可视化消息流——谁对谁说了什么一目了然
```

### 调试视角

| 看什么 | 发现什么 |
|---|---|
| 消息流 | 哪个 Agent 没说话/说错话 |
| 工具调用 | 工具参数对不对/结果是否被使用 |
| 终止时机 | 是否过早/过晚结束 |
| Token 消耗 | 哪轮最烧钱 |

### 调试方法

```
① 跑一个最小任务（缩小范围）
② 逐轮看消息流（定位问题轮次）
③ 调整对应 Agent 的提示词
④ 重跑对比
```

## 6. 评估与部署

### 内置评估

```
Studio 支持对 Agent 响应做 LLM 评审打分：
- 建立测试问题集
- 批量运行
- LLM 评委打分（质量/相关性等）
```

### 评估的局限

```
内置评估是"快速验证"，不是"生产评估体系"：
生产评估（RAGAS 风格）需要：固定测试集 + 指标定义 + 回归门禁
Studio 评估定位：迭代过程中的快速反馈
```

### 从 Studio 到生产

```
① Studio 原型调通
② 导出代码（自动生成 Python）
③ 工程化：加监控/评估/部署（参考 RAG 阶段 5 体系）
④ 持续迭代回 Studio 验证新想法
```

## 7. 面试高频问法

| 问题 | 回答要点 |
|---|---|
| Studio 解决什么？ | 低代码搭多 Agent：非工程人员可上手，工程快速原型 |
| Studio 能上生产吗？ | 定位是原型工具——生产用导出代码工程化 |
| 调试优势？ | 可视化消息流（谁对谁说了什么） |
| 内置评估够吗？ | 快速验证够；生产评估要自建体系 |
| 与代码开发关系？ | 互补：Studio 验证 → 代码工程化 |

### 面试加分表达

> "AutoGen Studio 是'把多 Agent 搭起来'的最快路径：拖拽组装、可视化看消息流。我的用法是 Studio 验证思路、导出代码工程化——它降低的是原型门槛，不是生产门槛。"

## 8. Studio 与代码开发的对照工作流

### 双轨工作流

```
创意阶段：Studio 拖拽（快速验证想法，非工程人员参与）
工程阶段：导出代码（生产化：监控/评估/部署）
迭代阶段：新想法回 Studio 验证 → 再工程化
```

### 团队协作分工

| 角色 | Studio 用法 |
|---|---|
| 产品/业务 | 搭原型、提需求、看效果 |
| AI 工程师 | 调提示词/工具、导代码、工程化 |
| 测试 | 用 Studio 快速构造测试场景 |

### 从 Studio 导出的工程化清单

```
① 配置版本化（Agent/提示词/工具入库）
② 模型密钥管理（环境变量/Secret）
③ 监控接入（消息流日志/成本统计）
④ 评估体系（测试集 + 指标 + 门禁）
⑤ 部署（容器化 + 服务化）
```

## 9. 常见问题与 FAQ

| 问题 | 回答 |
|---|---|
| Studio 与 LangGraph 的画布区别？ | Studio 是 AutoGen 团队的配置视图；LangGraph 是代码态图 |
| Studio 能管理生产会话吗？ | 原型定位——生产会话管理走应用代码 |
| 工具怎么在 Studio 里加？ | 注册工具函数后界面可选（需要代码定义一次） |
| Studio 评估可靠吗？ | 快速反馈可用；关键结论要人工复核 |
| 多人协作？ | 本地为主；配置可导出共享 |

### 使用建议

```
① 默认先用 2 Agent 验证（别一上来 5 个）
② 系统提示在 Studio 里反复调（它是核心调优旋钮）
③ 每次实验记录"改了什么 → 效果如何"
④ 调好后立刻导出（防配置丢失）
```

> 🎯 核心要点：Studio = 低代码可视化（拖拽 Agent/团队 + 消息流调试 + 内置评估）；定位是原型与协作工具（导出代码才是生产路径）；双轨工作流（Studio 验证 → 代码工程化 → 迭代回流）；调试看"消息流/工具调用/终止时机"四件事；内置评估只用于快速反馈，生产评估走自建体系（测试集 + 指标 + 门禁）。
