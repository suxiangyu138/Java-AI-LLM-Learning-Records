## 1. 五方对比总表

| 维度 | OpenAI SDK | LangGraph | AutoGen | Haystack | LlamaIndex |
|---|---|---|---|---|---|
| 编排范式 | 托管循环 | 图/状态机 | 对话驱动 | 管道 DAG | 事件驱动 |
| 第一抽象 | Agent/Runner | 图 | 对话参与者 | 组件/管道 | 数据/检索 |
| 多 Agent | Handoffs | 图原生 | 群聊 | Agent 组件 | Workflows |

| 会话 | **原生** | 需自建 | 需自建 | 需自建 | 需自建 |

| 流式 | 一等公民 | 支持 | 支持 | 支持 | 支持 |
| 追踪 | 内置 | LangSmith | 需自建 | OTel 原生 | OTel |
| 模型绑定 | Responses（LiteLLM 解绑） | 多 | 多 | 多 | 多 |

### 定位一句话

```
SDK：OpenAI 生态的托管式 Agent（少样板、护栏原生）
LangGraph：图式状态机（复杂 Agent 最专）
AutoGen：对话编排思想（已并入 MAF）
Haystack：生产 RAG 管道（强类型）
LlamaIndex：数据/检索（解析竞争资产）
```

## 3. 混用组合

### 2026 实践组合

| 组合 | 结构 |
|---|---|
| SDK + LlamaIndex | SDK Agent 调检索工具（RAG Agent） |
| SDK + Haystack | SDK Agent 调 Haystack 管道工具 |
| LangGraph + LlamaIndex | 图编排 + 数据层（最常见） |
| SDK + MCP 生态 | 工具生态扩展 |

### 实现思路（SDK + 检索）

```python
from agents import Agent, Runner, function_tool
from llama_index.core import VectorStoreIndex

# 1. LlamaIndex 构建检索
index = VectorStoreIndex.from_documents(documents)
query_engine = index.as_query_engine()

# 2. 包装为 SDK 工具
@function_tool
def search_knowledge(query: str) -> str:
    """检索知识库，参数 query 为问题"""
    return query_engine.query(query).response

# 3. SDK Agent 使用
agent = Agent(
    name="RAGAgent",
    instructions="需要知识库信息时调用 search_knowledge。",
    tools=[search_knowledge],
)
result = Runner.run_sync(agent, "退款政策是什么？")
```

### 混用原则

```
① 各管一段：检索框架管数据、SDK 管 Agent 循环
② 工具接口：字符串进出（边界清晰）
③ 可观测统一：两边接同一追踪
```

## 4. 面试速记

### 核心结论（背诵版）

```
1. SDK = OpenAI 官方托管式 Agent 框架（Swarm 继任者，v0.19.3）
2. 三大原语：Agent / Handoffs / Guardrails
3. 托管循环：Runner 跑（工具/流式/追踪内建），max_turns 必设
4. Handoffs = 移交控制权（一等字段）；Typed 结构化传递
5. Guardrails 双护栏：输入省钱门控（60-80% token）+ 输出校验
6. Sessions 跨运行持久化（InMemory/SQLite/Redis）
7. 生产五件套：Tracing/HITL/Sandbox（Beta）/MCP/LiteLLM
8. 选型：OpenAI 生态 → SDK；复杂图 → LangGraph；RAG → Haystack/LlamaIndex
9. 混用：SDK Agent + LlamaIndex 检索工具（RAG Agent）
10. 与其他框架互补而非替代
```

### 面试高频问题

| 问题 | 回答要点 |
|---|---|
| SDK 与其他框架怎么选？ | OpenAI 托管 vs 图式 vs 对话 vs 数据 |
| Handoffs 与工具区别？ | 控制权移交 vs 单步调用 |
| Guardrails 定位？ | 第二道防线（Prompt 设计优先） |
| 多轮怎么做？ | Session 持久化 |
| 追踪怎么接？ | 默认仪表盘/切 OTel |
| 学习它的前置？ | Function Calling 体系（工具循环原理） |

### 项目故事模板（RAG Agent）

> "我用 SDK 构建了企业客服 Agent：Handoffs 把政策/订单/投诉分给领域 Agent，Typed Handoffs 传订单结构化数据；输入护栏用便宜模型门控（拦截无效请求省 60% token）；Session 按用户隔离支持多轮；LlamaIndex 检索引擎包装成工具提供知识库能力——各框架各管一段，边界清晰。"

## 6. 常见误区

| 误区 | 真相 |
|---|---|
| "只支持 OpenAI 模型" | LiteLLM 100+ Provider |
| "托管 = 全自动" | 护栏/HITL/max_turns 都要自己配 |
| "Handoffs 是工具" | 一等字段（控制权移交） |
| "Sessions 可选" | 多轮没有它 = 冷启动失忆 |
| "SDK 替代一切框架" | 无检索层——互补组合 |
| "Guardrails 够安全" | 第二道防线，Prompt 设计第一 |

## 7. 框架全景总结（05-AI开发框架 家族）

```
本仓库 05-AI开发框架 六个框架体系全景：
┌──────────────────────────────────────────┐
│ 编排层                                    │
│  OpenAI Agents SDK（托管循环）            │
│  LangGraph（图/状态机）                   │
│  AutoGen/MAF（对话编排思想）              │
├──────────────────────────────────────────┤
│ 数据层                                    │
│  LlamaIndex（检索第一抽象）               │
│  Haystack（生产 RAG 管道）                │
├──────────────────────────────────────────┤
│ 组合：编排框架 + 数据框架 = 完整 Agent 系统 │
└──────────────────────────────────────────┘
```

### 学习建议（六框架总览）

```
① 编排三选一深耕：SDK（托管）/LangGraph（图）/AutoGen 思想（对话）
② 数据层二选一：LlamaIndex（数据复杂）/Haystack（生产管道）
③ 组合能力：编排框架 + 数据框架 + MCP 工具 = 生产 Agent
④ 原理前置：Function Calling + Agent 思想 + RAG 阶段 1-5
```

> 🎯 收官总结：OpenAI Agents SDK 是"托管式流程"路线的代表——三大原语（Agent/Handoffs/Guardrails）+ Sessions + 生产五件套；选型看"OpenAI 生态 + 快速上线"；与 RAG 框架互补（检索包装为工具）；六框架全景中它属编排层，与数据层（LlamaIndex/Haystack）组合成完整系统；学它之前先打牢 Function Calling 与 Agent 思想——框架是循环的托管，原理是循环的理解。
