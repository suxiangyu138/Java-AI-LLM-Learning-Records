# 02 核心概念：组件与管道

## 1. 两大核心抽象

| 抽象 | 是什么 | 类比 |
|---|---|---|
| 组件（Component） | 强类型处理单元（输入/输出声明） | 工厂的机器 |
| 管道（Pipeline） | 组件组成的 DAG | 流水线 |

```
组件定义"做什么"（输入 → 处理 → 输出）
管道定义"谁接谁"（数据流向）
```

### 与其他框架的抽象对比

| 框架 | 核心抽象 |
|---|---|
| Haystack | 组件 + 显式管道（DAG） |
| LangChain | Chain / LCEL |
| LangGraph | 图（节点/边/状态） |
| LlamaIndex | Index / QueryEngine |

## 2. 组件：强类型处理单元

### @component 装饰器

```python
from haystack import component
from typing import Dict, List

@component
class DocumentClassifier:
    """示例组件：文档分类"""

    @component.output_types(documents=List[Dict], labels=List[str])
    def run(self, documents: List[Dict], threshold: float = 0.5):
        """输入：documents（文档列表）+ 参数
        输出：documents（分类后）+ labels（标签）"""
        labels = [classify(d) for d in documents]
        return {"documents": documents, "labels": labels}
```

### 组件的三个要素

| 要素 | 说明 |
|---|---|
| @component | 标记为组件（可被管道使用） |
| @component.output_types | 声明输出类型（构建期校验的依据） |
| run() | 核心逻辑；输入带类型注解 |

### 组件与普通函数的区别

```
普通函数：调用方负责传参（错在运行时爆）
组件：接口强类型声明 → 管道构建期检查连接是否匹配
```

### 常见内置组件

| 类别 | 组件 |
|---|---|
| 转换 | TextFileToDocument、PDFToDocument、HTMLToDocument |
| 分割 | DocumentSplitter |
| 嵌入 | SentenceTransformersDocumentEmbedder |
| 检索 | BM25Retriever、EmbeddingRetriever、MultiRetriever |
| 重排 | CrossEncoderRanker |
| 生成 | OpenAIGenerator、HuggingFaceLocalGenerator |
| 提示 | PromptBuilder |
| 路由 | ConditionalRouter、FileTypeRouter |
| 管道 | Agent、SuperComponent |

## 3. 管道：DAG 编排

### 构建管道

```python
from haystack import Pipeline

pipeline = Pipeline()

# 添加组件（带实例名）
pipeline.add_component("converter", TextFileToDocument())
pipeline.add_component("splitter", DocumentSplitter(split_by="word", split_length=200))
pipeline.add_component("embedder", SentenceTransformersDocumentEmbedder())
pipeline.add_component("writer", DocumentWriter(document_store))

# 连接（构建期校验在这里发生）
pipeline.connect("converter.documents", "splitter.documents")
pipeline.connect("splitter.documents", "embedder.documents")
pipeline.connect("embedder.documents", "writer.documents")
```

### 连接语法

```
pipeline.connect("组件A.输出名", "组件B.输入名")
pipeline.connect("组件A", "组件B")      # 单输入/单输出可省略名称
```

### 管道即图

```
converter.documents → splitter.documents → embedder.documents → writer.documents
```

管道结构 = 组件连接图——**审查代码 = 审查图**（生产导向的核心价值）。

## 4. 构建期校验机制

### 为什么是"快速失败"

```
pipeline.connect() 时检查：
① 源组件输出类型 是否匹配 目标组件输入类型
② 输出名/输入名是否存在
不匹配 → 立即抛错（不用等运行）

vs 运行时才发现：错误在线上爆（成本高）
```

### 校验示例

```python
# 类型不匹配：converter 输出 documents(List)，但 splitter 期望其他类型
# connect 时直接报错（不是运行时报错）
pipeline.connect("converter.documents", "splitter.documents")  # 类型检查
```

### 校验的价值

| 价值 | 说明 |
|---|---|
| 错误左移 | 构建期发现，不带到运行期 |
| 管道自文档化 | 连接即结构 |
| 重构安全 | 改组件接口 → 连接处报错提示 |
| 代码审查友好 | review 管道 = review 架构 |

## 5. 数据流与类型

### 管道的执行

```python
result = pipeline.run({"converter": {"sources": ["doc.txt"]}})
# 输入按组件名分组传入
# 输出按组件名分组返回
```

### 数据类型（核心类型）

| 类型 | 用途 |
|---|---|
| Document | 文档（内容 + 元数据 + 嵌入向量） |
| List[Document] | 文档列表（检索/分割的输出） |
| str | 文本（问题/答案） |
| Dict | 结构化数据 |

### 组件连接的"类型契约"

```
每个连接 = 一个类型契约：
converter.documents (List[Document]) → splitter.documents (List[Document])
契约不匹配 → 构建期报错（这就是强类型）
```

## 6. 并行分支与循环

### 并行分支

```python
# 一个输出接到多个组件（并行处理）
pipeline.connect("splitter.documents", "embedder_a.documents")
pipeline.connect("splitter.documents", "embedder_b.documents")
```

```
适用：多路检索（MultiRetriever 内部就是并行）、
     多模型对比、索引与查询分流
```

### 循环（loops）

```
2.x 支持 loops（如"检索 → 生成 → 评估 → 不足再检索"）
实现：条件路由 + 回环连接（生成输出评估不合格 → 回到检索）
对应阶段 3 的"反思循环"与 Self-RAG
```

### 条件路由

```python
# ConditionalRouter：按条件走不同分支
router = ConditionalRouter(routes=[
    {"condition": "{{query_type == 'simple'}}", "output": "direct"},
    {"condition": "{{query_type == 'complex'}}", "output": "rag"},
])
```

## 7. 面试高频问法

| 问题 | 回答要点 |
|---|---|
| Haystack 两大抽象？ | 组件（强类型）+ 管道（DAG） |
| @component 做什么？ | 标记组件 + 声明输出类型 |
| 构建期校验是什么？ | connect() 时检查类型匹配，错误运行前暴露 |
| 管道和 LangChain Chain 区别？ | 显式 DAG + 强类型 vs 松散链式 |
| 并行怎么做？ | 一个输出接多个组件 |
| loops 支持什么？ | 反思循环（检索→生成→评估→再检索） |

### 面试加分表达

> "Haystack 的核心是'把错误左移'：@component 声明强类型接口，pipeline.connect() 在构建期校验类型匹配——类型不匹配根本跑不起来。这种显式管道让代码审查等于架构审查，是它生产导向的根基。"

## 8. 自定义组件实战

```python
"""自定义组件：查询改写（LLM 补全指代）"""
from haystack import component

@component
class QueryRewriter:
    """把口语化/带指代的问题改写为检索友好查询"""

    @component.output_types(query=str)
    def run(self, query: str, history: list[str] | None = None):
        # 简化实现：补全"它/这个"等指代（生产用 LLM 改写）
        rewritten = query
        if history:
            last = history[-1][:30]
            rewritten = f"{query}（结合前文：{last}）"
        return {"query": rewritten}

# 使用：加入查询管道
qa.add_component("rewriter", QueryRewriter())
qa.connect("rewriter.query", "embedder.text")
```

### 自定义组件要点

| 要点 | 说明 |
|---|---|
| @component 必加 | 否则不能进管道 |
| 输出类型声明 | @component.output_types（校验依据） |
| 参数 vs 输入 | 连接传输入；run() 默认参数是配置 |
| 保持纯函数 | 无状态（并行安全） |

> 自定义组件 = 把 RAG 阶段 3 的任意调优逻辑（改写/过滤/校验）封装为管道节点——**框架不限制，生产化就靠这个**。

## 9. 常见误区

| 误区 | 真相 |
|---|---|
| "组件必须用内置的" | 自定义组件很简单（@component 三行） |
| "管道只能线性" | DAG 支持并行/分支/loops |
| "强类型写起来麻烦" | 类型注解是 Python 常规操作 |
| "改了组件要重写管道" | 连接不变则只改组件（接口稳定） |
| "构建期校验是限制" | 是保护（错误左移） |

> 🎯 核心要点：两大抽象（组件 + 管道 DAG）；@component 强类型接口 + connect() 构建期校验 = "错误左移"；管道即图（审查代码 = 审查架构）；数据流靠类型契约（Document/List[Document]/str）；并行分支与 loops（反思循环）都是 DAG 的自然能力；自定义组件把任何调优逻辑封装为节点（框架不限制）。
