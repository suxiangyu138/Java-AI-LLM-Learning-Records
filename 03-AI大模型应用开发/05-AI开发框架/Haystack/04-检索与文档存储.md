## 1. DocumentStore 抽象

### 是什么

```
DocumentStore = 文档存储的统一抽象
不绑定特定向量库——同一套 API 操作 30+ 存储
```

### 核心操作

| 操作 | 方法 |
|---|---|
| 写入 | DocumentWriter（管道组件） |
| 检索 | Retriever（按存储选型） |
| 过滤 | retriever.filters 参数 |
| 删除 | delete_documents |

### Document 结构

```python
Document(
    content="文档内容",           # 文本
    meta={"title": "...", "year": 2026},  # 元数据
    embedding=[0.1, 0.2, ...],   # 向量
    score=0.93,                  # 检索分数（运行时）
)
```

## 2. 存储选型矩阵

| 存储 | 定位 | 适用 |
|---|---|---|
| InMemory | 原型（仅内存） | 学习/测试 |
| Elasticsearch/OpenSearch | 全文+向量一体 | 已有 ES 业务 |
| Qdrant | 独立向量库 | 中小生产 |
| Chroma | 轻量向量库 | 快速验证 |
| Weaviate | 向量+对象 | 中大规模 |
| Pinecone | 托管 SaaS | 不想运维 |
| pgvector | PG 扩展 | 已有 PG |
| MongoDB Atlas | 文档+向量 | 已有 Mongo |
| Milvus | 大规模企业级 | 百万级+ |

### 选型逻辑（与 RAG 阶段 3 一致）

```
原型 → InMemory/Chroma
已有 PG → pgvector
已有 ES → ES（混合检索天然）
中小生产 → Qdrant
大规模 → Milvus
不运维 → Pinecone
```

> 💡 选型原则与 RAG 阶段 3 的 04 篇完全一致——Haystack 只是把"换库"变成"换一个 integration 包"。

## 3. 三类检索器

### BM25Retriever（关键词）

```python
from haystack_integrations.components.retrievers.elasticsearch import ElasticsearchBM25Retriever
# 或 InMemory 的 BM25

retriever = ElasticsearchBM25Retriever(document_store=store, top_k=20)
```

| 特点 | 说明 |
|---|---|
| 词法匹配 | 精确词/型号/人名 |
| 零训练 | 词频统计 |
| 中文 | 需分词配置 |

### EmbeddingRetriever（稠密向量）

```python
# 查询嵌入 + 向量检索
retriever = ChromaEmbeddingRetriever(document_store=store, top_k=20)
```

| 特点 | 说明 |
|---|---|
| 语义匹配 | 同义改写 |
| 依赖 Embedding | 查询与文档同一模型 |
| 维度一致 | 与存储配置匹配 |

### 语义鸿沟的解法

```
BM25 补"精确词"，向量补"语义"——混合才是完整解
（与阶段 3 的 03 篇结论一致）
```

## 4. 混合检索与 RRF

### MultiRetriever（2.x 组件）

```python
from haystack_integrations.components.retrievers.elasticsearch import (
    ElasticsearchBM25Retriever,
    ElasticsearchEmbeddingRetriever,
)
from haystack.components.retrievers import MultiRetriever

hybrid = MultiRetriever(
    retrievers=[
        ElasticsearchBM25Retriever(document_store=store, top_k=20),
        ElasticsearchEmbeddingRetriever(document_store=store, top_k=20),
    ],
    weights=[0.4, 0.6],      # 权重（BM25:向量）
    merge_mode="rrf",        # RRF 融合
)
```

### RRF 融合（回顾阶段 3）

```
score(d) = Σ 1 / (k + rank_i(d))    k=60
只看排名不看分数 → 免尺度问题
权重可调（型号密集场景 BM25 加权）
```

### 混合检索管道

```
query → TextEmbedder（向量化）
      → MultiRetriever（BM25 并行 + 向量并行 → RRF）
      → documents（融合 Top-K）
```

## 5. 重排序与 MultiRetriever

### CrossEncoderRanker

```python
from haystack_integrations.components.rankers.cross_encoder import CrossEncoderRanker

# 粗召回 20 → 精排 5
ranker = CrossEncoderRanker(model_name_or_path="BAAI/bge-reranker-base", top_k=5)
```

### 完整检索管道（粗召回 + 精排）

```
embedder → MultiRetriever(top 20) → ranker(top 5) → prompt
```

### 检索管道设计（生产标准）

| 环节 | 组件 | 参数 |
|---|---|---|
| 查询嵌入 | SentenceTransformersTextEmbedder | 与建库同模型 |
| 粗召回 | MultiRetriever | top_k=20（混合+RRF） |
| 精排 | CrossEncoderRanker | top_k=5（bge-reranker） |
| 上下文 | PromptBuilder | 精排结果拼模板 |

## 6. 检索调优实践

### 调优清单（与阶段 3 对应）

| 调优项 | Haystack 操作 | 阶段 3 对应 |
|---|---|---|
| Top-K | retriever top_k 参数 | 粗召回 50/精排 5 |
| 混合权重 | MultiRetriever weights | 权重扫描 |
| 阈值 | ranker/retriever 过滤 | 阈值过滤 |
| 过滤 | retriever filters（元数据） | 元数据过滤 |
| 查询改写 | 自定义组件（LLM 改写） | 02 篇 |
| 评估 | 内置评估（07 篇） | 评估先行 |

### 元数据过滤示例

```python
retriever = ChromaEmbeddingRetriever(
    document_store=store,
    top_k=10,
    filters={"year": 2026},     # 元数据过滤（阶段 3 的 05 篇）
)
```

### 调优实验方法

```
① 固定测试集（阶段 3 的 01 篇方法）
② 改一个参数 → 跑评估 → 记录
③ 累积提升表（每层只留正收益）
（方法论与阶段 3 完全一致，组件换成 Haystack）
```

## 7. 面试高频问法

| 问题 | 回答要点 |
|---|---|
| DocumentStore 是什么？ | 存储抽象——同一 API 操作 30+ 存储 |
| 三类检索器？ | BM25（词法）/Embedding（语义）/MultiRetriever（混合） |
| 混合怎么融合？ | RRF（排名融合）+ 权重 |
| 精排怎么做？ | CrossEncoderRanker（粗召回后精排） |
| 换存储麻烦吗？ | 换 integration 包 + 配置，管道不变 |
| 检索调优方法？ | 与手写 RAG 一致：测试集 + 一次一层 |

### 面试加分表达

> "检索层我按阶段 3 的标准实践组件化：MultiRetriever 做 BM25+向量混合（RRF 融合、权重可调），CrossEncoderRanker 精排 top-5——粗召回 20 加精排 5 是生产标配。换存储只换 integration 包，管道结构不变，这是 DocumentStore 抽象的价值。"

## 8. 检索管道完整示例

```python
"""生产标准检索管道：混合粗召回 + 精排"""
from haystack import Pipeline
from haystack.components.retrievers import MultiRetriever
from haystack_integrations.components.retrievers.elasticsearch import (
    ElasticsearchBM25Retriever, ElasticsearchEmbeddingRetriever,
)
from haystack_integrations.components.rankers.cross_encoder import CrossEncoderRanker
from haystack_integrations.components.embeddings.sentence_transformers import (
    SentenceTransformersTextEmbedder,
)

retrieval = Pipeline()
retrieval.add_component("embedder", SentenceTransformersTextEmbedder(model="BAAI/bge-small-zh-v1.5"))
retrieval.add_component("retriever", MultiRetriever(
    retrievers=[
        ElasticsearchBM25Retriever(document_store=store, top_k=20),
        ElasticsearchEmbeddingRetriever(document_store=store, top_k=20),
    ],
    weights=[0.4, 0.6],
    merge_mode="rrf",
))
retrieval.add_component("ranker", CrossEncoderRanker(
    model_name_or_path="BAAI/bge-reranker-base", top_k=5,
))

retrieval.connect("embedder.embedding", "retriever.query_embedding")
retrieval.connect("retriever.documents", "ranker.documents")

result = retrieval.run({"embedder": {"text": "退款政策是什么"}})
for doc in result["ranker"]["documents"]:
    print(f"{doc.score:.3f} {doc.content[:60]}")
```

### 示例解读

```
管道 = 阶段 3 检索调优的完整组件化：
嵌入（查询向量化）→ 混合（BM25+向量 RRF）→ 精排（top 5）
参数与手写版一一对应（top_k/weights/merge_mode）
```

## 9. 常见误区

| 误区 | 真相 |
|---|---|
| "InMemory 也能生产" | 仅原型——生产换 ES/Qdrant 等 |
| "混合检索一定更好" | 要评估验证（权重按场景调） |
| "RRF 权重随便设" | 型号密集 60:40、口语 30:70，测试集扫描 |
| "换存储要重写管道" | 换 integration 包，管道结构不变 |
| "检索不好先调生成" | 先看检索输出（分层定位） |

> 🎯 核心要点：DocumentStore = 30+ 存储的统一抽象（换库 = 换 integration 包）；三类检索器（BM25/向量/混合）；混合 = MultiRetriever + RRF + 权重；精排 = CrossEncoderRanker（粗 20 → 精 5）；完整管道即"嵌入→混合→精排"三节点；调优方法与手写 RAG 完全一致（测试集 + 一次一层 + 累积提升表），Haystack 只是组件化。
