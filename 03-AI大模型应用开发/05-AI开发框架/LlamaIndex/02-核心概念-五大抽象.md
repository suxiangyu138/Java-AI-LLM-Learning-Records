## 1. 五大抽象总览

| 抽象 | 回答的问题 | 类比 |
|---|---|---|
| 数据连接器 | 数据从哪来？ | 进货 |
| 节点解析器 | 数据怎么切？ | 分拣 |
| 索引 | 数据怎么存？ | 入库 |
| 查询引擎 | 数据怎么查？ | 出库 |
| Workflows | 流程怎么编排？ | 流水线管理 |

```
连接 → 解析 → 索引 → 检索 → 编排
一条数据管道：LlamaIndex 的所有能力都在这条链上
```

### 与其他框架的抽象对照

| 环节 | LlamaIndex | Haystack | LangChain |
|---|---|---|---|
| 取数 | 连接器（300+） | Converter | Loader |
| 切分 | NodeParser | Splitter | TextSplitter |
| 存储 | Index | DocumentStore | VectorStore |
| 查询 | QueryEngine | Pipeline | Chain/LCEL |

## 2. 数据连接器（LlamaHub）

### 是什么

```
LlamaHub：300+ 数据连接器的生态市场
接入任意数据源：PDF/网页/数据库/API/云盘...
```

### 使用示例

```python
from llama_index.core import SimpleDirectoryReader

# 本地目录（多格式自动识别）
documents = SimpleDirectoryReader("./data").load_data()

# 具体连接器（从 LlamaHub 安装）
# pip install llama-index-readers-database
from llama_index.readers.database import DatabaseReader
```

### 连接器分类

| 类别 | 例子 |
|---|---|
| 文件 | PDF/Word/PPT/Excel |
| 网页 | URL/网页爬取 |
| 数据库 | SQL/向量库 |
| 云服务 | S3/GDrive/Notion/Confluence |
| API | Slack/维基/工单系统 |

> 💡 300+ 连接器是"多源接入"场景选 LlamaIndex 的第一理由——对应 RAG 阶段 2 的"多格式加载"，这里直接生态化。

## 3. 节点解析器（NodeParser）

### 是什么

```
把 Document 切成 Node（检索单元）
Node = 文本块 + 元数据 + 关系（与 RAG 阶段 2 的 Chunk 同义）
```

### 使用

```python
from llama_index.core.node_parser import SentenceSplitter, HierarchicalNodeParser

# 简单切分（句子聚合）
parser = SentenceSplitter(chunk_size=512, chunk_overlap=80)

# 层级分块（内置：父块/子块，对应 RAG 阶段 3 父子索引）
hier_parser = HierarchicalNodeParser.from_defaults(
    chunk_sizes=[2048, 512, 128],   # 多级粒度
)
```

### 解析器类型

| 解析器 | 特点 | 适用 |
|---|---|---|
| SentenceSplitter | 按句子聚合 | 通用默认 |
| TokenTextSplitter | 按 token | 精确控制 |
| HierarchicalNodeParser | 多级父子 | 复杂文档 |
| SemanticSplitter | 语义边界 | 长文档 |
| CodeSplitter | 代码感知 | 代码库 |

> 对应 RAG 阶段 3 的 05 篇（切片升级与父子索引）——LlamaIndex 把这些内置了。

## 4. 索引（Index）

### 四种索引类型

| 索引 | 机制 | 适用 |
|---|---|---|
| VectorStoreIndex | 向量相似度 | **默认首选** |
| SummaryIndex | 顺序摘要 | 小文档全读 |
| KeywordTableIndex | 关键词映射 | 精确词查询 |
| KnowledgeGraphIndex | 实体关系图 | 多跳推理 |

### 向量索引构建（最小）

```python
from llama_index.core import VectorStoreIndex

# 文档 → 切分 → 嵌入 → 索引（一条语句）
index = VectorStoreIndex.from_documents(documents)
# 默认嵌入模型 + 内存存储；生产换 LlamaCloud/Qdrant 等
```

### 索引选型

```
通用 RAG → VectorStoreIndex（默认）
多跳/实体 → KnowledgeGraphIndex
精确词 → KeywordTableIndex
小文档全局 → SummaryIndex
```

## 5. 查询引擎（QueryEngine）

### 是什么

```
QueryEngine = "检索到响应"的流水线：
查询 → 检索（索引）→ 组装上下文 → LLM 生成 → 响应
```

### 使用

```python
# 从索引创建查询引擎
query_engine = index.as_query_engine()

# 查询
response = query_engine.query("退款政策是什么？")
print(response.response)          # 答案
print(response.source_nodes)      # 来源（可溯源）
```

### 查询引擎的能力

| 能力 | 说明 |
|---|---|
| 检索策略 | Top-K/过滤/子问题分解 |
| 响应模式 | 单答案/引用/摘要 |
| 子问题分解 | 多文档查询拆解（deep research） |
| 流式 | response_gen 流式输出 |

### 与手写 RAG 的对应

```
QueryEngine = 阶段 2 的 ask() 函数（检索+组装+生成）
LlamaIndex 把整条查询链路封装为对象
```

## 6. Workflows（编排）

### 是什么

```
Workflows 1.0（2025-06 GA）：事件驱动异步编排
不是 DAG，是"事件传递"——步骤监听事件、发出事件
```

### 与 DAG 的区别

| 维度 | 事件驱动（Workflows） | DAG（Haystack/LangGraph） |
|---|---|---|
| 结构 | 步骤 + 事件 | 节点 + 边 |
| 灵活性 | 高（动态路由） | 中（显式图） |
| 异步 | 原生 | 部分 |
| 调试 | 事件追踪 | 图可视化 |

### 最小示例

```python
from llama_index.core.workflow import (
    Workflow, StartEvent, StopEvent, step,
)

class MyWorkflow(Workflow):
    @step
    async def retrieve(self, ev: StartEvent) -> StopEvent:
        results = index.as_retriever().retrieve(ev.query)
        return StopEvent(result=results)

wf = MyWorkflow(timeout=60)
result = await wf.run(query="问题")
```

## 7. 数据流全景

```
┌────────── 离线（索引） ──────────┐
│  连接器 → 解析器 → 索引          │
│  (LlamaHub) (NodeParser) (Index) │
└──────────────────────────────────┘
            │
┌────────── 在线（查询） ──────────┐
│  查询 → QueryEngine → 响应       │
│  Workflows 编排整个流程          │
└──────────────────────────────────┘
```

### 与 RAG 阶段体系的映射

| RAG 阶段 | LlamaIndex 对应 |
|---|---|
| 阶段 2（加载/切片/向量化/检索/生成） | 连接器/解析器/索引/QueryEngine |
| 阶段 3（父子索引/混合检索/评估） | 层级分块/混合搜索/内置评估器 |
| 阶段 4（Agentic/多模态） | Workflows/LlamaAgents/LlamaParse |

## 8. 面试高频问法

| 问题 | 回答要点 |
|---|---|
| 五大抽象？ | 连接器/解析器/索引/查询引擎/Workflows |
| 四种索引？ | 向量/摘要/关键词/知识图谱 |
| 层级分块？ | HierarchicalNodeParser（父块+子块，父子索引内置） |
| QueryEngine 是什么？ | 检索到响应的封装（查询→检索→生成） |
| Workflows 特点？ | 事件驱动异步（非 DAG） |
| 与手写 RAG 关系？ | 原理一致，全链路封装 |

### 面试加分表达

> "LlamaIndex 的五大抽象就是一条数据管道：连接器取数（300+ 源）、解析器切块（内置层级分块）、索引存储（四种类型）、查询引擎检索生成、Workflows 编排——我手写的 RAG 每个环节都能映射到它的抽象上，它把数据层的工程全部封装了。"

> 🎯 核心要点：五大抽象 = 一条数据管道（连接→解析→索引→查询→编排）；四种索引（向量默认/图谱多跳/关键词精确/摘要全局）；QueryEngine 封装"检索到响应"；Workflows 是事件驱动异步编排（非 DAG）；层级分块/混合搜索等阶段 3 的调优能力全部内置。
