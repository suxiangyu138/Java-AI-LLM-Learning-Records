# 09 - 推理成本分析与优化

> 🎯 LLM 推理成本是持续支出 — API 按 Token 计、自建按 GPU 时计。1000 QPS 日均成本可能差 10 倍

## API 成本计算

| 模型 | 输入/1M tokens | 输出/1M tokens | 1000次对话/天 |
|------|:---:|:---:|:---:|
| GPT-4o | $5 | $15 | ~$7 |
| GPT-4o-mini | $0.15 | $0.60 | ~$0.25 |
| Claude Sonnet | $3 | $15 | ~$6 |
| DeepSeek-V2 | ¥1 | ¥2 | ~¥1 |

## 自建成本计算

```text
A100 (80GB) 云计算实例：~$3/小时

单卡 vLLM 部署 Qwen2-7B：
  QPS ≈ 180 (并发 32)
  每 1M tokens 成本 ≈ $0.05
  → 比 GPT-4o 便宜 100-300×

但需考虑：
  + 运维人力（部署/监控/升级）
  + 显卡闲置时间
  + 电力/机房
```

## API vs 自建 ROI

| 日均 Token | API 月费(GPT-4o-mini) | 自建月费(A100) | 建议 |
|:---:|:---:|:---:|------|
| <10万 | ~$3 | ~$2200 | API |
| 10万-100万 | ~$30 | ~$2200 | API |
| 100万-1000万 | ~$300 | ~$2200 | 可考虑自建 |
| >1000万 | ~$3000+ | ~$2200+ | **自建** |

## 成本优化策略

```text
① 分层模型：简单问题用便宜模型(mini)，复杂问题用贵模型(pro)
② 缓存：相同问题不重复推理 → Redis/Memcached
③ 量化：INT4/INT8 让单卡承载更多并发
④ 批处理：合并请求减少 GPU 空闲
⑤ Spot 实例：非实时任务用抢占式实例 (节省 60-80%)
⑥ 模型选择：Qwen2-7B 够用就别上 72B
```

```python
# 分层路由
def smart_route(query):
    if is_simple(query):      # 简单问候/常识 → mini
        return gpt4o_mini(query)
    elif needs_reasoning(query):  # 复杂推理 → pro
        return gpt4o(query)
    else:
        return local_qwen(query)  # 本地模型
```
