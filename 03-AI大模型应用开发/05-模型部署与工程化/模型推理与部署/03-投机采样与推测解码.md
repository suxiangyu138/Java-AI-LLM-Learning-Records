# 03 - 投机采样与推测解码

> 🎯 投机采样 = 小模型"猜"+大模型"验" — 不损失精度的前提下提速 2-3×，是推理加速的免费午餐

## 原理

```text
LLM 自回归生成慢的根本原因：
  → 每次只生成 1 个 token → 100 tokens = 100 次串行推理

投机采样 (Speculative Decoding)：
  ① 小模型快速"猜"出 K 个候选 token（一次前向）
  ② 大模型"验证"这 K 个 token（一次前向）
  ③ 接受正确的 → 跳过→ 从第一个错的重新猜

  大模型 1 次前向 = 验证 K 个 token ≈ K× 加速
  K 通常 3-8 → 加速 2-3×
```

## 为什么"免费"

```text
投机采样不改变输出分布！
  → 大模型验证时拒绝了错误的猜测
  → 最终输出的概率分布与原始完全一致
  → 零精度损失 ✅
```

## 小模型选择

| 方案 | 加速比 | 显存开销 |
|------|:---:|:---:|
| 同系列小模型(Qwen-0.5B猜Qwen-7B验) | 2-3× | +0.5GB |
| 独立小模型 | 2-2.5× | +1-2GB |
| 模型自身的浅层输出 | 1.5-2× | 0 |
| EAGLE(特征级推测) | 3-4× | +1GB |

## 使用

```python
# vLLM 投机采样
llm = LLM(model="Qwen/Qwen2-7B",
          speculative_model="Qwen/Qwen2-0.5B",  # 猜测模型
          num_speculative_tokens=5)              # 每次猜 5 个

# llama.cpp 投机采样
llama-cli -m qwen2-7b.Q4_K_M.gguf \
          -md qwen2-0.5b.Q4_K_M.gguf \  # draft model
          -ngl 99
```

## 加速比影响因素

```text
加速比取决于：
  ① 小模型的"猜对率" — 越高越快
  ② 生成内容的"可预测性" — 代码 > 普通文本 > 创意写作
  ③ K 的大小 — 过大则验证慢，过小则加速少

典型加速比：
  代码补全：3-5×
  通用对话：2-3×
  创意写作：1.5-2×
```
