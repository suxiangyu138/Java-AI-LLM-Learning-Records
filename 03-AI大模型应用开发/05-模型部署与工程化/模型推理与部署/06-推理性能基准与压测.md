# 06 - 推理性能基准与压测

> 🎯 没压测就上线 = 盲飞 — TTFT、TPOT、QPS、P99 延迟四大指标，locust/wrk/k6 三大工具

## 四大核心指标

| 指标 | 含义 | 目标 |
|------|------|:---:|
| **TTFT** | Time To First Token 首Token延迟 | <1s |
| **TPOT** | Time Per Output Token 每Token生成时间 | <50ms |
| **QPS** | 每秒处理请求数 | >50 |
| **P99 延迟** | 99%请求的端到端延迟 | <5s |

## 5. 压测工具与场景速查

**压测工具对比**（2026）：

| 工具 | 特点 | 适用 |
|------|------|------|
| **vLLM bench** | 引擎内置基准（吞吐/延迟） | 快速对比（首选） |
| vLLM 官方 benchmark | 标准化压测 | 配置对比 |
| **LMCache/perf** | 前缀缓存场景 | RAG 场景 |
| 自研压测 | 真实负载模拟 | 生产验收 |
| Locust/k6 | 通用压测 | 服务层 |

**压测场景矩阵**：

```text
① 单请求：TTFT + TPOT（流式实测）
② 并发固定：50/100/200 并发 → 吞吐 + P95
③ 前缀共享：RAG 场景（系统提示共享）→ 前缀缓存收益
④ 长上下文：8K/32K/128K → KV 显存上限
⑤ 混合负载：真实查询分布（生产镜像）

验收标准（参考）：
  P95 TTFT < 1s（交互式）
  吞吐满足业务峰值 × 1.5 冗余
  无 OOM（KV 显存 < 90%）
```

**压测常见误区**：

```text
❌ 只测平均不测 P95（长尾被掩盖）
❌ 固定上下文测所有场景（长上下文差异巨大）
❌ 测试数据不真实（查询分布失真 → 结论失真）
✅ 黄金集质量回归（压测后质量不变）
```

> 🎯 **核心要点**：压测 = "**vLLM bench 起步 + 五场景矩阵 + P95 验收**"——**"平均 vs P95"与"固定 vs 真实负载"是两个最大误区**；压测后必须跑质量回归（量化/配置改动场景）。

## 6. 压测报告模板与验收

**压测报告标准结构**（生产验收）：

```text
① 测试环境：硬件/引擎版本/模型/量化
② 测试场景：并发/上下文/前缀/混合负载
③ 结果矩阵：
   场景 | 吞吐 | P95 TTFT | P95 TPOT | KV 显存 | 结论
④ 对比基线：与上一版本/不同配置的对比
⑤ 质量回归：黄金集指标（量化/配置改动必测）
⑥ 结论与建议：达标/不达标 + 调优方向

验收标准（参考）：
  交互式：P95 TTFT < 1s
  吞吐：满足业务峰值 × 1.5 冗余
  稳定性：持续 30 分钟无 OOM/无错误率上升
```

**压测自动化**（2026 实践）：

```text
① CI 集成：每次引擎/模型变更跑基准（防回归）
② 基线对比：自动对比上次结果（吞吐下降 >10% 告警）
③ 发布门禁：压测达标才允许上线（与 RAG/Agent 评估门禁同源）
```

> 🎯 **核心要点**：压测验收 = "**标准报告（环境/场景/矩阵/回归）+ 三项验收（TTFT/吞吐/稳定）+ CI 自动化**"——**"每次变更跑基准 + 发布门禁"是 2026 生产标配**（防推理性能回归）。

## 7. 总结速查

```text
压测核心记忆：
  指标：TTFT（感知）/ TPOT（速度）/ 吞吐（容量）/ KV 显存（资源）
  方法：五场景矩阵（单请求/并发/前缀/长上下文/混合）
  验收：P95 TTFT < 1s + 吞吐峰值×1.5 + 30 分钟稳定
  误区：只看平均 / 固定上下文 / 数据不真实
  自动化：CI 基准 + 基线对比 + 发布门禁

面试话术：
  "压测必须看 P95 而非平均——长尾延迟被平均掩盖；
   场景矩阵覆盖并发/前缀/长上下文；
   每次引擎或模型变更跑基准，与基线对比，吞吐下降超 10% 告警"
```

> 🎯 **核心要点**：压测总结 = "**四指标 + 五场景 + P95 验收 + CI 自动化**"——**"P95 而非平均"是最高频考点**；与部署工具 09-监控的指标体系（TTFT/吞吐）联动。
