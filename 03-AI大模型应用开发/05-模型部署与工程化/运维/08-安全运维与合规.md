# 08 - 安全运维与合规

> 🎯 API Key 泄露 = 天价账单，模型被投毒 = 全线崩溃，用户数据泄露 = 法律诉讼。安全运维是 LLM 服务的底线

## 1. API Key 安全管理

```yaml
# K8s Secret 管理 API Key
apiVersion: v1
kind: Secret
metadata:
  name: llm-api-keys
type: Opaque
stringData:
  openai-key: "sk-xxx"
  anthropic-key: "sk-ant-xxx"

# 应用读取
env:
- name: OPENAI_API_KEY
  valueFrom:
    secretKeyRef:
      name: llm-api-keys
      key: openai-key
```

```bash
# 禁止 API Key 写入代码/配置文件
# .gitignore
.env
**/api_keys.json

# Git 泄漏检测 (pre-commit hook)
git-secrets --scan-history  # 扫描历史中是否有泄露的 Key
```

## 2. 模型安全

```text
模型安全威胁矩阵：

  ① 模型文件篡改 → 权重被替换为恶意版本
     防御：文件哈希校验（SHA256）+ 签名验证

  ② 模型反序列化攻击 → pickle/ safetensors 漏洞
     防御：只用 safetensors 格式（不支持代码执行）

  ③ 供应链攻击 → 恶意 HuggingFace 仓库
     防御：固定模型版本 + 校验哈希

  ④ 输出注入 → 模型输出被用于 SQL/命令注入
     防御：输出内容过滤 + 参数化
```

## 3. 数据隐私

```python
class PIIFilter:
    """个人身份信息过滤"""
    PATTERNS = {
        'phone': r'1[3-9]\d{9}',
        'email': r'[\w.-]+@[\w.-]+\.\w+',
        'id_card': r'\d{17}[\dXx]',
        'bank_card': r'\d{16,19}',
    }
    
    def mask_pii(self, text):
        for pii_type, pattern in self.PATTERNS.items():
            text = re.sub(pattern, f'[REDACTED_{pii_type}]', text)
        return text
    
    def should_block(self, text):
        """包含敏感信息 → 拒绝处理"""
        sensitive_keywords = ['密码', 'password', 'token', 'secret']
        return any(kw in text.lower() for kw in sensitive_keywords)
```

## 4. 审计追踪

```text
审计日志必须记录：
  □ 谁（user_id/IP）
  □ 什么时候（timestamp）
  □ 做了什么（API调用类型）
  □ 用了什么模型（model/version）
  □ 消耗了多少 Token（tokens/cost）
  □ 结果是什么（成功/失败/被拦截）

保留策略：
  → 普通日志：90 天
  → 审计日志：1-3 年（取决于合规要求）
  → GDPR 要求：用户可请求删除其数据
  
实现：
  → 审计日志写入 append-only 存储（如 AWS CloudTrail / S3 版本锁定）
  → 禁止修改/删除审计日志
```
