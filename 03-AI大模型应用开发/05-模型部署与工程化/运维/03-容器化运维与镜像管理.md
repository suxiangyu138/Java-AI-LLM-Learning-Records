# 03 - 容器化运维与镜像管理

> 🎯 LLM 镜像动辄 20GB+ — 镜像安全扫描、分层缓存优化、多阶段构建、私有 Registry 管理，每一项都直接关系部署效率

## 1. LLM 镜像分层策略

```dockerfile
# Layer 1: CUDA 基础（很少变）→ 提前缓存
FROM nvidia/cuda:12.4.0-runtime-ubuntu22.04

# Layer 2: 系统依赖（偶尔变）
RUN apt-get update && apt-get install -y python3.11 && rm -rf /var/lib/apt/lists/*

# Layer 3: Python 包（经常变，但与模型独立）
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Layer 4: 应用代码（频繁变）→ 最小化这一层
COPY ./app /app

# Layer 5: 模型权重不进镜像！→ 挂载 Volume 或启动时下载
# ❌ COPY ./model.bin /models/  # 会导致镜像膨胀到 20GB+
# ✅ 启动时从 S3/HF 下载
```

## 2. 镜像安全

```bash
# Trivy 漏洞扫描
trivy image vllm/vllm-openai:v0.6.0

# Docker Scout 分析
docker scout quickview registry.example.com/llm:latest

# 安全最佳实践
# ① 非 root 运行
USER 1000:1000
# ② 固定基础镜像版本（不用 :latest）
FROM nvidia/cuda:12.4.0-runtime-ubuntu22.04
# ③ 最小化攻击面（不用 apt 装无关包）
# ④ 签名镜像
cosign sign --key cosign.key registry.example.com/llm:latest
```

## 3. 私有 Registry

```yaml
# Harbor 私有 Registry
version: '3'
services:
  harbor:
    image: goharbor/harbor:v2.10
    ports: ["443:443"]
    volumes:
      - harbor_data:/data
      - ./harbor.yml:/harbor.yml

# 推送
docker tag llm:latest harbor.example.com/llm/vllm:v0.6.0
docker push harbor.example.com/llm/vllm:v0.6.0
```

## 4. 镜像预热与分发

```bash
# K8s 节点预热（避免启动时下载 20GB）
# 方案 1：DaemonSet 预拉取
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: image-warmer
spec:
  template:
    spec:
      initContainers:
      - name: pull-images
        image: docker:cli
        command: ['sh', '-c', 'docker pull harbor.example.com/llm/vllm:latest']

# 方案 2：使用 Kraken/Dragonfly P2P 分发（大规模集群）
# 避免所有节点同时从 Registry 拉取 → 带宽爆炸
```
