## 1. 限流算法对比

| 算法 | 原理 | 突发容忍 | 内存 | 适用 |
|------|------|:---:|:---:|------|
| **固定窗口** | 每分钟计数重置 | ❌ 边界突刺 | 低 | 简单 |
| **滑动窗口** | 滑动时间窗口计数 | ⚠️ | 中 | 通用 |
| **漏桶** | 固定速率流出 | ❌ | 低 | 平滑 |
| **令牌桶** | 固定速率放令牌 | ✅ | 低 | **推荐** |

```text
令牌桶 = LLM 限流首选

  令牌以固定速率放入桶中（如 100 个/秒）
  桶满则丢弃令牌（容量=最大突发）
  请求需获取令牌才能执行
  无令牌 → 等待或拒绝

优势：允许突发（桶里攒的令牌可以一次性用完）
```

## 2. 令牌桶实现

```python
import time
import asyncio

class TokenBucket:
    def __init__(self, rate, capacity):
        self.rate = rate          # 令牌生成速率（个/秒）
        self.capacity = capacity  # 桶容量（最大突发）
        self.tokens = capacity
        self.last_refill = time.monotonic()
    
    async def acquire(self, tokens=1):
        """获取令牌，无令牌时等待"""
        while True:
            self._refill()
            if self.tokens >= tokens:
                self.tokens -= tokens
                return True
            # 计算等待时间
            wait = (tokens - self.tokens) / self.rate
            await asyncio.sleep(wait)
    
    def try_acquire(self, tokens=1):
        """尝试获取，无令牌立即返回 False"""
        self._refill()
        if self.tokens >= tokens:
            self.tokens -= tokens
            return True
        return False
    
    def _refill(self):
        now = time.monotonic()
        elapsed = now - self.last_refill
        self.tokens = min(self.capacity, self.tokens + elapsed * self.rate)
        self.last_refill = now

# 使用
bucket = TokenBucket(rate=100, capacity=200)  # 100 QPS, 突发200

async def rate_limited_llm_call(prompt):
    await bucket.acquire()
    return await call_llm(prompt)
```

## 3. 分布式限流

```python
# 基于 Redis 的分布式令牌桶
import redis
import time

class DistributedTokenBucket:
    SCRIPT = """
    local key = KEYS[1]
    local rate = tonumber(ARGV[1])
    local capacity = tonumber(ARGV[2])
    local requested = tonumber(ARGV[3])
    local now = tonumber(ARGV[4])
    
    local bucket = redis.call('HMGET', key, 'tokens', 'last_refill')
    local tokens = tonumber(bucket[1]) or capacity
    local last_refill = tonumber(bucket[2]) or now
    
    local elapsed = now - last_refill
    tokens = math.min(capacity, tokens + elapsed * rate)
    
    if tokens >= requested then
        tokens = tokens - requested
        redis.call('HMSET', key, 'tokens', tokens, 'last_refill', now)
        redis.call('EXPIRE', key, 60)
        return 1
    else
        return 0
    end
    """
    
    def __init__(self, redis_client, key, rate, capacity):
        self.redis = redis_client
        self.key = key
        self.rate = rate
        self.capacity = capacity
        self.acquire_script = self.redis.register_script(self.SCRIPT)
    
    def try_acquire(self, tokens=1):
        return bool(self.acquire_script(
            keys=[self.key],
            args=[self.rate, self.capacity, tokens, time.time()]
        ))
```

## 4. LLM 多级限流架构

```text
三级限流架构：

  ① 用户级：每个用户 20 次/分钟
     → 防止单个用户滥用

  ② API Key 级：每个 Key 200 次/分钟
     → 保护 API 配额

  ③ GPU 级：总并发数不超过 GPU 容量的 120%
     → 防止 GPU 过载 → OOM
```

```python
class LLMRateLimiter:
    def __init__(self):
        self.user_limiter = TokenBucket(rate=20/60, capacity=30)    # 每用户20/min
        self.api_limiter = TokenBucket(rate=200/60, capacity=300)   # 每Key 200/min
        self.gpu_limiter = asyncio.Semaphore(8)  # GPU 最大并发 8
    
    async def acquire(self, user_id, api_key):
        # 检查 GPU 并发
        if self.gpu_limiter.locked():
            raise OverloadError("GPU 满载")
        
        # 检查 API Key 配额
        if not self.api_limiter.try_acquire():
            raise RateLimitError("API Key 配额不足")
        
        # 检查用户配额
        if not self.user_limiter.try_acquire():
            raise RateLimitError("用户配额不足，请稍后再试")
```

## 5. 过载保护与背压

```text
过载信号：
  → P99 延迟 > 5s（持续 30s）
  → GPU 利用率 > 95%
  → 请求队列深度 > 500
  → 错误率 > 5%

过载保护动作：
  ① 拒绝新请求（返回 503 + Retry-After）
  ② 降级正在处理的请求（减 max_tokens）
  ③ 释放低优先级请求（取消排队中的非 VIP 请求）

背压 (Backpressure)：
  服务端 → 客户端："我撑不住了，慢一点"
  实现：HTTP 429 Too Many Requests + Retry-After 头
```
