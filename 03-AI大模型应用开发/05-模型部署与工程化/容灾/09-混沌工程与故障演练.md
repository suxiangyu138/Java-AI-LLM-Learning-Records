# 09 - 混沌工程与故障演练

> 🎯 只有主动制造故障，才能确认系统真的能扛住故障 — Chaos Engineering 是容灾体系的"期末考试"

---

## 1. 混沌工程原则

```text
混沌工程五步法：

  ① 定义稳态：什么指标代表"系统正常"？
     → LLM 服务：P99延迟<3s, 错误率<1%, 可用率>99.9%

  ② 假设爆炸范围：这个故障会影响多少用户？
     → 注入 GPU OOM → 预期影响 10% 请求（备机接盘）

  ③ 设计实验：模拟什么故障？
     → 网络延迟+500ms / GPU 降频 / API 返回 500

  ④ 注入故障：在生产环境小范围执行
     → 金丝雀 Pod 注入故障 → 观察 5 分钟

  ⑤ 验证恢复：系统是否按预期自动修复？
     → 熔断器是否打开？流量是否切换？P99是否<阈值？
```

---

## 2. LLM 故障注入实验

| 实验 | 注入方式 | 预期行为 | 验证指标 |
|------|----------|----------|----------|
| **API 超时** | 延迟注入 30s | 熔断→切换备模型 | 切换时间 <1s |
| **API 500** | 50% 请求返回500 | 熔断→切换+告警 | 成功率>95% |
| **GPU OOM** | 填充显存到 99% | 该Pod摘除→新Pod拉起 | 恢复 <60s |
| **模型幻觉率上升** | 替换为旧版模型 | 质量监控告警→自动回滚 | 检测 <2min |
| **全机房断网** | iptables DROP | 流量切到备机房 | 切换 <30s |

## 3. Chaos Mesh 实战

```yaml
# 注入 GPU Pod 网络延迟
apiVersion: chaos-mesh.org/v1alpha1
kind: NetworkChaos
metadata:
  name: llm-pod-delay
spec:
  action: delay
  mode: fixed-percent
  value: "30"           # 30% Pod
  selector:
    labelSelectors:
      app: llm-inference
  delay:
    latency: "2000ms"   # 注入 2 秒延迟
    jitter: "500ms"
  duration: "5m"        # 持续 5 分钟
```

## 4. GameDay 演练计划

```text
季度 GameDay — 全团队参与，4 小时：

  09:00 — 开场：回顾上季度故障、本次实验目标
  09:30 — 实验 1：模拟 OpenAI API 全球宕机 → 验证自动切换
  10:30 — 实验 2：GPU 节点全部故障 → 验证降级策略
  11:30 — 实验 3：流量突增 5 倍 → 验证限流和弹性伸缩
  12:30 — 复盘：记录发现的问题 → 转成 Action Items

GameDay 铁律：
  ① 提前通知所有相关方（包括用户支持团队）
  ② 有"紧急停止"按钮（实验失控时一键终止）
  ③ 出问题不追责（GameDay不是用来考核的）
  ④ 每个实验后立即复盘（趁记忆新鲜）
```
