## 1. 什么是 Agent

```text
AI Agent（智能体）= 以 LLM 为大脑的自主任务执行系统

  传统 LLM：你问 → 它答（被动）
  Agent：你给目标 → 它自己规划 → 调用工具 → 检查结果 → 迭代 → 完成（主动）

类比：
  LLM = 图书馆里百科全书的管理员（知识渊博，但只能回答问题）
  Agent = 项目经理（拿到需求 → 拆解任务 → 协调资源 → 跟踪进度 → 交付）
```

### Agent 的核心能力

```text
① 感知 (Perceive)：理解用户意图和环境状态
② 规划 (Plan)：将复杂目标分解为可执行的步骤
③ 行动 (Act)：调用工具（搜索/API/代码/数据库）执行步骤
④ 反思 (Reflect)：检查执行结果，必要时调整计划
⑤ 记忆 (Remember)：记住历史交互和学到的经验
```

## 2. Agent 四大核心组件

```text
┌─────────────────────────────────────────────────────┐
│                     LLM（大脑）                       │
│         思考、推理、决策、生成                         │
├─────────────────────────────────────────────────────┤
│  规划 (Planning)    │   记忆 (Memory)                 │
│  任务分解/排序      │   短期/长期/工作记忆              │
│  策略选择           │   上下文管理                      │
├─────────────────────────────────────────────────────┤
│  工具 (Tools)       │   行动 (Action)                 │
│  搜索/API/代码/DB   │   执行/观察/反馈                 │
│  工具注册与发现      │   错误处理/重试                  │
└─────────────────────────────────────────────────────┘

四者缺一不可：
  只有 LLM → 聊天机器人
  LLM + 工具 → 增强型 LLM（如 ChatGPT Plugins）
  LLM + 工具 + 规划 + 记忆 + 行动 → Agent ✅
```

## 3. LLM vs Agent

| 维度 | LLM | Agent |
|------|:---:|:---:|
| **交互模式** | 一问一答 | 目标→自主执行 |
| **任务复杂度** | 单步 | 多步、有依赖 |
| **工具使用** | 无或被动 | 主动选择+调用 |
| **记忆** | 仅当前对话 | 跨会话记忆 |
| **错误处理** | 没有 | 检测+反思+重试 |
| **自主性** | 低（被动响应） | 高（自主规划执行） |

```text
举例对比：

  LLM："帮我写一封辞职信" → 直接生成

  Agent："帮我准备离职" →
    ① 规划：写辞职信 → 计算未休年假 → 整理工作交接清单
    ② 工具：查 HR 系统(年假天数)、查公司模板(辞职信格式)
    ③ 执行：生成辞职信 → 计算补偿 → 输出交接清单
    ④ 检查：确认格式正确、数据准确
    ⑤ 输出：完整离职准备包
```

## 4. Skill、Tool、Agent 的区别

| 概念 | 定义 | 示例 |
|------|------|------|
| **Tool** | 原子功能，完成单一操作 | 搜索网页、查询数据库、执行代码 |
| **Skill** | 组合多个 Tool + Prompt 的专用能力 | "SQL 优化 Skill" = 解释计划 + 建议索引 + 改写 SQL |
| **Agent** | 自主决策使用哪些 Skill/Tool 完成目标 | "数据分析 Agent" = 选择数据源 → 写 SQL → 绘图 → 写报告 |

```text
层级关系：
  Tool（原子） → Skill（组合） → Agent（自主编排）

  Agent 决定"用什么 Skill"、Skill 决定"调哪些 Tool"
```

## 5. Agent 的核心挑战

| 挑战 | 说明 | 缓解方案 |
|------|------|----------|
| **幻觉放大** | Agent 的错误决策会产生连锁反应 | 工具返回验证、反思机制 |
| **无限循环** | Agent 可能陷入"思考→行动→失败→再思考"的死循环 | 最大步数限制、超时保护 |
| **安全风险** | Agent 可能执行危险操作（删库/发邮件） | 权限分级、沙箱执行、人工确认 |
| **成本控制** | 多步推理消耗大量 Token | 用便宜模型做简单任务、缓存 |
| **可靠性** | Agent 行为不确定，时好时坏 | 测试套件、回退策略 |

## 6. Agent 能力图谱与评估维度

**Agent 的能力不是"一个模型"，而是"系统能力"**——四大组件各自的评估维度：

| 组件 | 能力 | 评估维度 | 失败表现 |
|------|------|---------|---------|
| 规划 Planning | 任务分解与排序 | 计划合理性、步骤覆盖 | 漏步骤/顺序错 |
| 记忆 Memory | 上下文与知识保持 | 召回准确率、遗忘率 | 答非所问/重复问 |
| 工具 Tool | 调用外部系统 | **ToolSelectionAccuracy** | 选错工具/参数错 |
| 行动 Action | 执行与反馈闭环 | 执行成功率、恢复能力 | 卡死/循环 |

```text
2026 评估共识（评估驱动开发）：
  → 分别度量 ToolSelectionAccuracy / FunctionCallAccuracy / TaskCompletion
  → 不要只用端到端指标（掩盖"工具选错但答案碰对"的问题）
  → 评估细节见 10 号文件与深化文件 15 号
```

**LLM vs Agent 的分界线（2026 视角再确认）**：

```text
LLM：单次推理、无状态、被动响应
Agent：循环推理（Observe-Think-Act）、有状态（记忆）、主动执行
2026 的新认知：两者的边界被"编程 Agent"模糊化——
  Claude Code/Cursor 等 IDE Agent = 工具密集型 Agent 的最大增长面
```

> 🎯 **核心要点**：Agent 的竞争力 = "**连接能力**"（2026 共识：竞争焦点从模型智力转向能连接多少真实业务系统）——四大组件中，**工具系统的质量（ToolSelectionAccuracy）是 2026 年区分度的核心**。

## 7. Agent 的类型谱系

**按"自主程度与规模"分类**（2026 全景）：

| 类型 | 特征 | 例子 | 复杂度 |
|------|------|------|:------:|
| 单轮工具调用 | 一次 LLM + 工具 | Function Calling 应用 | ★ |
| 单 Agent 循环 | ReAct 多步推理 | 客服/搜索 Agent | ★★ |
| 规划型 Agent | Plan-Execute | 数据分析 Agent | ★★★ |
| **多 Agent 协作** | 分工 + 通信 | LangGraph 图 / A2A 跨服务 | ★★★★ |
| **编程 Agent** | 工具密集型 + 长任务 | **Claude Code / Cursor**（2026 最大增长面） | ★★★★★ |

**按"部署形态"分类**（2026 新维度）：

```text
云端 Agent：服务端运行（主流）
端侧 Agent：MCP Server 直接跑在用户设备（AI PC 芯片普及，2026 增长）
     → 敏感数据不出本地（隐私优势）
     → 苹果/微软已在 OS 层提供沙箱化 MCP 运行时
混合：端侧做本地决策 + 云端做重计算
```

> 🎯 **核心要点**：Agent 的类型谱系 = "**自主度（单轮到多 Agent）× 部署（云到端）**"两维展开——2026 年的两个增长点是**编程 Agent**（工具密集）与**端侧 Agent**（隐私敏感场景）。
