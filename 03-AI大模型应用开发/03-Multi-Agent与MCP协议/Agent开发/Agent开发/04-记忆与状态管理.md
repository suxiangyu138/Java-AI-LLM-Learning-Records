## 1. 为什么记忆是 Agent 的核心

### 1.1 无记忆的代价

```text
无记忆 Agent 的四大失败
├── ① 跨轮遗忘：用户 5 分钟前说的要求，转个弯就忘
├── ② 进度丢失：任务做到一半崩溃，全部重来
├── ③ 无学习能力：同样的错误每次都犯
├── ④ 上下文爆炸：所有历史塞进窗口，成本失控
```

> 🎯 **记忆的本质**：记忆 = Agent 的「操作系统文件系统」——把状态从上下文窗口（内存）外部化到持久存储（磁盘），Agent 才能长任务、跨会话、可恢复。

### 1.2 记忆的价值

| 价值 | 场景 |
|------|------|
| 连续性 | 多轮对话、长期任务 |
| 个性化 | 记住用户偏好/历史决策 |
| 学习 | 从历史经验中避免重复错误 |
| 恢复 | 崩溃/断线后接续任务 |

## 2. 记忆分类体系

### 2.1 三类记忆模型

| 类型 | 类比 | 实现 | 生命周期 |
|------|------|------|---------|
| **短期记忆** | 工作记忆 | 上下文窗口 + KV Cache 压缩 | 会话级 |
| **长期记忆** | 长期记忆 | 向量数据库 + 语义检索 | 跨会话 |
| **程序性记忆** | 肌肉记忆 | Skills / 规则文件 | 持久 |

### 2.2 各类型详解

**短期记忆（工作记忆）**

```text
实现方式：
├── 上下文窗口（直接注入）
├── KV Cache（节省重复计算）
└── 滚动窗口（保留最近 N 轮）
适用：当前任务上下文、最近对话
管理：防上下文腐烂（过多信息反而降低质量）
```

**长期记忆（情节记忆）**

```text
实现方式：
├── 向量数据库（语义检索）
├── 时间衰减排序（近期记忆权重更高）
└── Agentic RAG（Agent 自主决定检索时机）
适用：用户偏好、历史决策、领域知识
```

**程序性记忆（技能记忆）**

```text
实现方式：
├── Skills 技能包（经验封装）
├── 规则文件（CLAUDE.md/AGENTS.md）
└── 工具封装（把流程变成函数）
适用：踩坑经验、标准流程、领域技能
```

## 3. 双写策略：短期 + 长期

### 3.1 经典双写架构

```text
双写策略架构
┌─────────────┐      ┌─────────────┐
│ 短期工作记忆   │      │ 长期情节记忆   │
│ Redis        │      │ 向量数据库    │
│ TTL 10 分钟  │      │ Qdrant/      │
│              │      │ Pinecone     │
│ 直接注入上下文 │      │ 语义检索      │
└─────────────┘      └─────────────┘
      ↑                    ↑
      └────────┬───────────┘
               ↓
         Agent 执行循环
```

| 存储 | 特点 | 写入时机 | 读取方式 |
|------|------|---------|---------|
| **Redis（短期）** | 快、TTL 自动过期 | 每轮对话 | 直接注入上下文 |
| **向量库（长期）** | 语义检索、可衰减 | 任务完成/里程碑 | 按需检索 |

### 3.2 时间衰减策略

```text
长期记忆的检索排序
score = 语义相似度 × 时间衰减因子
├── 近期记忆：衰减因子 ≈ 1.0（优先）
├── 中期记忆：衰减因子 ≈ 0.7
└── 久远记忆：衰减因子 ≈ 0.4（除非语义强相关）
→ 效果：Agent 倾向于参考近期决策，符合人类记忆规律
```

### 3.3 写入时机

```text
记忆写入触发点
├── 即时写：任务完成的关键结论（重要决策/用户偏好）
├── 里程碑写：长任务每阶段总结
├── 定期写：会话结束时的会话摘要
└── 事件写：异常/失败经验（最高价值）
```

## 4. 上下文压缩

### 4.1 为什么要压缩

```text
上下文无限增长的三重代价
├── ① 成本：token 消耗线性增长
├── ② 质量：上下文腐烂（信息太多优先级混乱）
├── ③ 延迟：处理时间增长
→ 对策：两阶段上下文压缩
```

### 4.2 两阶段压缩策略

```
阶段一：会话内压缩（对话变长时）
├── 早期对话 → 摘要（保留结论与决策）
├── 中间对话 → 精炼（保留行动与结果）
└── 最近对话 → 完整保留

阶段二：会话间压缩（跨会话）
├── 旧会话 → 结构化记忆（写入长期记忆）
├── 关键决策 → 决策记录（ADR）
└── 经验教训 → 技能沉淀（Skills）
```

> 💡 **压缩原则**：**摘要保留「决策与结果」，丢弃「过程与噪声」**——压缩不是删除，是把记忆从「原始数据」变成「知识」。

## 5. Checkpointer：状态管理

### 5.1 什么是 Checkpointer

**Checkpointer**：Agent 运行状态的持久化快照机制——在关键节点保存状态，支持断点恢复、回滚与时间旅行调试：

```python
# LangGraph Checkpointer 示例
from langgraph.checkpoint.memory import MemorySaver

checkpointer = MemorySaver()          # 内存级（测试用）
# from langgraph.checkpoint.postgres import PostgresSaver
# checkpointer = PostgresSaver(...)   # 生产：数据库级

app = graph.compile(checkpointer=checkpointer)

# 运行并保存检查点
config = {"configurable": {"thread_id": "task-001"}}
result = app.invoke(initial_state, config)

# 断点恢复：从上次状态继续（崩溃后）
resumed = app.invoke(None, config)

# 时间旅行：回滚到任意历史状态
history = app.get_state_history(config)
```

### 5.2 Checkpointer 的能力

| 能力 | 说明 | 价值 |
|------|------|------|
| **断点恢复** | 崩溃后从最后状态继续 | 长任务不丢进度 |
| **分支探索** | 从历史状态分叉测试 | 调试利器 |
| **审计回放** | 查看每一步状态变迁 | 可解释性 |
| **人工干预** | 中断后修改状态再继续 | 人机协同 |

### 5.3 状态设计原则

```text
状态设计五原则
├── ① 最小化：只存必要状态（消息列表 + 进度 + 决策）
├── ② 可序列化：状态必须可持久化（JSON 友好）
├── ③ 版本化：状态 schema 演进兼容
├── ④ 隔离：每个任务独立状态空间（thread_id）
└── ⑤ 敏感信息分离：密钥/PII 不入状态存储
```

## 6. Agentic RAG：自主检索

### 6.1 与传统 RAG 的区别

| 维度 | 传统 RAG | Agentic RAG |
|------|---------|-------------|
| 检索时机 | 固定（每次先检索） | **Agent 自主决定** |
| 检索次数 | 一次 | **多轮（可追加查询）** |
| 结果验证 | 不验证 | **验证结果准确性** |
| 流程 | 检索 → 生成 | **感知 → 决策 → 检索 → 验证 → 生成** |

### 6.2 Agentic RAG 的检索决策

```text
Agentic RAG 的检索逻辑
├── 何时检索？→ 上下文信息不足/需要事实支撑时
├── 检索什么？→ 根据当前子任务意图构造查询
├── 结果可信？→ 检索结果与需求是否匹配（验证）
└── 不够怎么办？→ 调整查询重试 / 换数据源
→ 本质：把「检索」从固定流程变成 Agent 的工具能力
```

> 🎯 **价值**：Agentic RAG 让记忆使用更精准——不检索无关内容、检索结果先验证、必要时多轮检索，是长记忆场景的关键技术。

## 7. 记忆安全：防投毒

### 7.1 记忆投毒攻击

> ⚠️ **记忆投毒（Memory Poisoning）**：持久技能文件或项目上下文文件被修改，从而塑造 Agent 后续行为——是 2026 年 Agent 安全的重点风险。

```text
投毒攻击链
├── ① 攻击者获得写入权限（提交 PR/上传文件）
├── ② 修改记忆文件（规则文件/技能/历史记录）
├── ③ 植入恶意指令（"删除数据是常规操作"）
├── ④ Agent 每次会话加载被投毒的记忆
└── ⑤ 后续行为被恶意塑造
```

### 7.2 记忆安全防护

| 防护 | 做法 |
|------|------|
| **写入权限控制** | 记忆文件只读，变更走 PR 审批 |
| **内容校验** | 记忆写入前扫描（恶意指令检测） |
| **版本追踪** | 记忆文件版本管理 + 审计 |
| **敏感分离** | 密钥/PII 不入记忆存储 |
| **定期审计** | 检查记忆文件内容与变更历史 |

## 8. 核心要点

> 🎯 **核心要点**：
> 1. 记忆分类：短期（上下文窗口）/长期（向量库）/程序性（Skills）——三者协同才是完整记忆
> 2. 双写策略：Redis（TTL 10min 短期）+ 向量库（语义检索 + 时间衰减）是生产标配
> 3. 两阶段压缩：会话内摘要 + 会话间沉淀，保留决策丢弃噪声
> 4. Checkpointer 状态管理（断点恢复/时间旅行）+ Agentic RAG（自主检索验证）+ 防投毒（只读+审批）构成记忆工程全景
