## 1. 循环的五大风险

| 风险 | 表现 | 影响 | 发生概率 |
|------|------|------|:---:|
| **无限循环** | Agent 反复调用同一工具 | CPU/API 费用暴涨 | 中 |
| **Token 爆炸** | 上下文无限增长 | OOM / 成本失控 | 高 |
| **死锁** | Agent A 等 B，B 等 A | 系统挂起 | 低 |
| **级联失败** | 一个工具失败 → 所有后续都错 | 结果完全错误 | 中 |
| **超时** | 任务超过最大允许时间 | 用户流失 | 中 |

## 2. 超时与熔断

### 2.1 三层超时保护

```python
import signal
import asyncio

class TimeoutGuard:
    """三层超时保护"""

    # L1: 单步超时（每个工具调用）
    STEP_TIMEOUT = 30      # 秒

    # L2: 循环超时（整个 ReAct 循环）
    LOOP_TIMEOUT = 300     # 秒（5 分钟）

    # L3: 会话超时（整个会话）
    SESSION_TIMEOUT = 1800 # 秒（30 分钟）

    async def execute_with_guard(self, agent, query):
        try:
            return await asyncio.wait_for(
                agent.run(query),
                timeout=self.LOOP_TIMEOUT
            )
        except asyncio.TimeoutError:
            return {
                "status": "timeout",
                "partial_result": agent.last_output,
                "steps_completed": agent.step_count,
                "message": f"任务在 {self.LOOP_TIMEOUT}s 内未完成，已返回部分结果"
            }
```

### 2.2 熔断器模式

```python
class CircuitBreaker:
    def __init__(self, failure_threshold=5, recovery_timeout=60):
        self.threshold = failure_threshold
        self.recovery = recovery_timeout
        self.failures = 0
        self.last_failure_time = None
        self.state = "CLOSED"   # CLOSED / OPEN / HALF_OPEN

    def call(self, func, *args, **kwargs):
        if self.state == "OPEN":
            if time.time() - self.last_failure_time > self.recovery:
                self.state = "HALF_OPEN"
            else:
                raise Exception("熔断器开启，拒绝调用")

        try:
            result = func(*args, **kwargs)
            if self.state == "HALF_OPEN":
                self.state = "CLOSED"
                self.failures = 0
            return result
        except Exception:
            self.failures += 1
            self.last_failure_time = time.time()
            if self.failures >= self.threshold:
                self.state = "OPEN"
            raise
```

## 3. 死循环检测

```python
class StuckDetector:
    """死循环检测器"""

    def __init__(self, repeat_threshold=3):
        self.recent_actions = []
        self.threshold = repeat_threshold

    def check(self, action: str) -> dict:
        self.recent_actions.append(action)
        if len(self.recent_actions) > 10:
            self.recent_actions.pop(0)

        # 检测 1: 连续重复
        if len(self.recent_actions) >= self.threshold:
            last_n = self.recent_actions[-self.threshold:]
            if len(set(last_n)) == 1:
                return {
                    "stuck": True,
                    "type": "loop",
                    "action": action,
                    "hint": f"已连续 {self.threshold} 次调用 {action}，请尝试不同方法"
                }

        # 检测 2: 振荡（A→B→A→B→A...）
        if len(self.recent_actions) >= 5:
            pattern = self.recent_actions[-5:]
            if pattern[0] == pattern[2] == pattern[4] and \
               pattern[1] == pattern[3] and \
               pattern[0] != pattern[1]:
                return {
                    "stuck": True,
                    "type": "oscillation",
                    "hint": "检测到 A/B 振荡，请尝试突破循环"
                }

        return {"stuck": False}
```

## 4. Token 预算管理

```python
class TokenBudget:
    def __init__(self, max_tokens=100000):
        self.max = max_tokens
        self.used = 0
        self.warning_threshold = 0.7
        self.critical_threshold = 0.9

    def consume(self, tokens: int) -> dict:
        self.used += tokens
        ratio = self.used / self.max

        if ratio >= 1.0:
            return {"action": "stop", "reason": "Token 预算耗尽"}

        if ratio >= self.critical_threshold:
            return {"action": "warn_critical",
                    "message": f"Token 预算已用 {ratio:.0%}，请尽快结束"}

        if ratio >= self.warning_threshold:
            return {"action": "warn",
                    "message": f"Token 预算已用 {ratio:.0%}"}

        return {"action": "continue"}
```

## 核心要点回顾

- 五大风险：无限循环、Token爆炸、死锁、级联失败、超时
- 三层超时：单步(30s) → 循环(5min) → 会话(30min)
- 熔断器：连续失败 N 次 → 打开(拒绝调用) → 半开(试探) → 关闭(恢复)
- 死循环检测：重复检测(连续N次相同) + 振荡检测(A→B→A→B)
- Token 预算：警告阈值 70% + 临界阈值 90% + 硬上限 100%
- 所有循环必须内置这些保障——这不是可选功能，是生产必备
