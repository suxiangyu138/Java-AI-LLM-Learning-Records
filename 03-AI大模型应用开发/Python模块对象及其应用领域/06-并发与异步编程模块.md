## 1. 三种范式对比

| 维度 | asyncio | threading | multiprocessing |
|------|---------|-----------|-----------------|
| 适用 | **IO 密集**（API 调用/网络/文件） | 混合 IO+轻量 CPU | **CPU 密集**（数据处理/计算） |
| 并发模型 | 协程（单线程事件循环） | 多线程（共享内存） | 多进程（独立内存） |
| GIL 影响 | 无（不涉及线程切换） | **有**（Python 线程不适合 CPU 密集） | 无（进程绕过 GIL） |
| 内存开销 | 极低 | 低 | 高（每进程独立 Python 解释器） |
| 通信方式 | — | queue / 共享变量 | Pipe / Queue / 共享内存 |
| AI 场景 | **LLM API 并发调用** | 下载模型/预处理 | 数据并行处理 |

## 2. asyncio — LLM API 并发首选

```python
import asyncio

# ① 基本用法
async def call_llm(prompt: str) -> str:
    await asyncio.sleep(2)   # 模拟 API 调用
    return f"Response for: {prompt[:20]}"

# ② 并发执行（同时调多个 LLM）
async def batch():
    prompts = ["What is AI?", "Explain Python", "Tell a joke"]
    results = await asyncio.gather(*[call_llm(p) for p in prompts])
    return results  # 全部完成才返回

# ③ Semaphore 限流（防 API 限流/爆内存）
async def batch_with_limit(prompts: list[str], max_concurrent=10):
    sem = asyncio.Semaphore(max_concurrent)
    async def bounded(p):
        async with sem: return await call_llm(p)
    return await asyncio.gather(*[bounded(p) for p in prompts])

# ④ 超时控制
async def call_with_timeout(prompt, timeout=30.0):
    try:
        return await asyncio.wait_for(call_llm(prompt), timeout)
    except asyncio.TimeoutError:
        return "请求超时"

# ⑤ 创建后台任务
task = asyncio.create_task(call_llm("long query"))
# 主流程继续... 稍后 result = await task

# 运行入口
asyncio.run(batch())
```

## 3. concurrent.futures — 统一接口

```python
from concurrent.futures import ThreadPoolExecutor, ProcessPoolExecutor

# 线程池（IO 任务）
with ThreadPoolExecutor(max_workers=10) as executor:
    futures = [executor.submit(call_llm, p) for p in prompts]  # 同步函数
    results = [f.result() for f in futures]

# 进程池（CPU 任务）
with ProcessPoolExecutor(max_workers=4) as executor:
    results = list(executor.map(heavy_computation, large_data))

# 与 asyncio 混用
loop = asyncio.get_running_loop()
with ThreadPoolExecutor() as pool:
    result = await loop.run_in_executor(pool, blocking_io_func, arg)
```

## 4. threading — 轻量并发

```python
import threading
from queue import Queue

# 线程 + Queue 生产者消费者模式（AI 场景：下载模型+预处理流水线）
def downloader(urls, queue):
    for url in urls:
        data = download(url)
        queue.put(data)          # 线程安全入队
    queue.put(None)              # 结束信号

def processor(queue):
    while True:
        data = queue.get()
        if data is None: break
        process(data)

q = Queue(maxsize=100)
t1 = threading.Thread(target=downloader, args=(urls, q))
t2 = threading.Thread(target=processor, args=(q,))
t1.start(); t2.start(); t1.join(); t2.join()

# threading.local() — 线程本地存储（类似 ThreadLocal）
tls = threading.local()
tls.db_connection = create_connection()   # 每个线程独立连接
```

## 5. multiprocessing — CPU 密集

```python
from multiprocessing import Pool, cpu_count

# 数据并行：用满所有 CPU 核心
with Pool(processes=cpu_count()) as pool:
    results = pool.map(heavy_computation, large_dataset)

# 进程间通信
from multiprocessing import Queue, Pipe
```

## 6. 选型速查

| 场景 | 选什么 | 理由 |
|------|--------|------|
| 并发调 LLM API | **asyncio** | 天然异步、极低开销 |
| 下载模型 / 文件 IO | threading / asyncio | IO 密集 |
| 数据预处理（大规模） | **multiprocessing** | 绕过 GIL |
| 混合场景（下载+处理流水线） | threading + Queue | 生产者消费者 |
| 简单多任务执行 | concurrent.futures | API 最简单 |
| CPU 密集型科学计算 | numpy/PyTorch（内置多线程） | 不要用 Python 多线程 |

**追问：** asyncio vs threading 选哪个？→ 网络 IO→asyncio；文件 IO（无原生异步 API）→threading+run_in_executor；已有大量同步代码→threading。

---

> 🎯 **核心要点**：AI 应用并发选型口诀 — **调 LLM API 用 asyncio（Semaphore 限流 + gather 并发）→ 数据预处理用 multiprocessing（Pool.map）→ 混合场景用 concurrent.futures（统一接口）**。Python 的 GIL 让多线程不适合 CPU 密集，但 IO 密集没问题。
