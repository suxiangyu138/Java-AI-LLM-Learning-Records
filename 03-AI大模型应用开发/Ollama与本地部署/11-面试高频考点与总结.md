## 1. 高频面试题

### Q1: Ollama vs vLLM 怎么选？

> **标准回答**：
> - **Ollama** = 个人开发/原型/低并发（< 10 QPS），一行命令部署，零运维
> - **vLLM** = 生产高并发（10+ QPS），PagedAttention 提升吞吐 10-20x
> - **混合** = vLLM 主力 + Ollama 备用（不同模型/降级）
> - 关键差异：vLLM 的连续批处理让并发场景的 GPU 利用率从 40% → 90%

### Q2: Q4_K_M vs Q5_K_M 选哪个？

| 维度 | Q4_K_M | Q5_K_M |
|------|:---:|:---:|
| 8B 模型大小 | ~5 GB | ~5.8 GB |
| 质量损失 | < 5% | < 3% |
| 显存门槛 | RTX 3060 12GB | RTX 4060 Ti 16GB |
| 推荐场景 | **日常开发** | 生产环境 |

> **结论**：日常开发和原型用 Q4_K_M（省显存够用），面向用户的生产环境用 Q5_K_M（多花 1GB 显存换更好的回答质量）

### Q3: 怎么估算模型需要的显存？

```text
公式：VRAM = 参数量(B) × 量化位宽(bit) / 8 + KV Cache + Overhead

速算（Q4_K_M）：
  7B → ~5 GB     (RTX 3060 12GB ✅)
  13B → ~8 GB    (RTX 3060 ✅)
  34B → ~20 GB   (RTX 4090 24GB ✅)
  70B → ~51 GB   (A6000 48GB, 2×RTX 3090)
```

### Q4: 数据不能出内网，怎么部署 AI？

> 1. **Ollama 本地部署**：Qwen 2.5 7B (Apache 2.0) / Hermes 3 8B (Llama 3)
> 2. **网络隔离**：防火墙 IP 白名单 + Nginx API Key 鉴权
> 3. **离线安装**：下载 GGUF 文件 → 拷贝到内网 → `ollama create`
> 4. **审核合规**：优先选国产模型（Qwen/GLM），数据不出境

### Q5: 100 人并发调用，怎么设计？

```text
方案：
├── 部署：vLLM (不是 Ollama！Ollama 并发弱)
├── GPU：至少 A100 80GB (70B) 或 RTX 4090 × 2 (8B × 2)
├── 前端：Nginx 负载均衡 + 限流 (100 req/s)
├── 缓存：Redis 缓存相同 Prompt 结果 (TTL 1h)
├── 降级：vLLM 挂了 → Ollama 备用 → 本地缓存兜底
└── 监控：Prometheus + Grafana + 邮件告警
```

### Q6: Docker 部署 Ollama 的 GPU 透传怎么做？

```yaml
deploy:
  resources:
    reservations:
      devices:
        - driver: nvidia
          count: 1
          capabilities: [gpu]
```
> 前提：安装 NVIDIA Container Toolkit + `nvidia-ctk runtime configure`

### Q7: Ollama 的模型文件存在哪？怎么迁移？

```text
Linux:   /usr/share/ollama/.ollama/models/
macOS:   ~/.ollama/models/
Windows: C:\Users\<user>\.ollama\models\

迁移：复制整个 .ollama 目录 → 新机器相同路径 → ollama list 验证
```

### Q8: 怎么让 Ollama 支持远程访问？

```bash
# 1. 设置监听地址
export OLLAMA_HOST=0.0.0.0:11434

# 2. 重启
sudo systemctl restart ollama

# 3. 安全：用 Nginx 反向代理 + HTTPS + API Key（永远不要裸奔）
```

## 2. 选型答辩模板

### "做个本地 AI 服务，你怎么选型？"

```
第一步：需求分析（5秒）
  "先确认：用户量？数据能不能出网？预算？"

第二步：给出方案（15秒）
  "基于X人并发+Y预算+Z合规要求，推荐 Ollama/vLLM + Qwen 7B +
   Q4_K_M 量化 + RTX 4090，月成本约 ¥X"

第三步：解释原因（10秒）
  "选 Qwen 因为 Apache 2.0 商用友好+中文最强；
   选 Q4_K_M 因为 5GB 显存跑 7B，4090 轻松承载；
   选 Ollama 因为并发低不需要 vLLM 的复杂度"

第四步：风险说明（5秒）
  "风险：如果并发量涨到 50+ 需要迁移到 vLLM，但 API 兼容，
   只需改 base_url，业务代码零改动"
```

### 场景速答卡

| 面试官说... | 回答要点 |
|---|---|
| "只有 CPU 服务器" | llama.cpp + Q4_K_M，7B 在 8 核 CPU 上 ~10 tok/s |
| "预算 5000 块" | 二手 RTX 3090 24GB + Qwen 7B Q5_K_M |
| "要做 Function Calling" | Hermes 3 8B (专用 FC 训练) 或 Qwen 2.5 |
| "要处理长文档" | Qwen 2.5 支持 128K，num_ctx 设大 |
| "微调了私有模型" | 导出 GGUF → Ollama Modelfile → 一行部署 |
| "监控怎么做" | Nginx 日志 + Prometheus GPU metrics + 自定义健康脚本 |

## 核心要点回顾

- 选型公式：Ollama（< 10 并发）+ vLLM（10+ 并发）+ llama.cpp（纯 CPU）
- 量化首选 Q4_K_M：5GB 跑 8B，质量损失 < 5%，RTX 3060 就够
- 安全三件套：Nginx 反向代理 + API Key + HTTPS
- 显存估算：参数量(B) × 量化位宽 / 8 + 20% overhead
- 面试框架：需求 → 方案 → 原因 → 风险
