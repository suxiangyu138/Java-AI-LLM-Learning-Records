# 多模态推理部署面试题

> 面试考点："多模态服务为什么慢/贵、怎么优化、什么时候上分离架构、视觉塔量化行不行、Agent 怎么部署"——每题带 2026 实测数字，背熟即得分

## 1. 必问基础 8 题

### Q1：多模态推理和文本推理的差异？为什么慢/贵？

**答案**：差异三条——**多一个编码阶段**（图像先进视觉编码器——额外模型前向）；**视觉 token 的 prefill 膨胀**（一张图 576 到数千 token——prefill 计算量远大于同长度文本——"1 图像 token ≈ 数文本 token 计算"）；**KV cache 的视觉占比**（长视觉输入 → KV 被视觉 token 占据）。**慢/贵的根源**：额外成本集中在**编码 + prefill**——文档负载中大部分计算来自长视觉输入而非回答生成（HSE 2026）——**"多模态推理贵在视觉处理"**。

### Q2：多模态服务的性能第一优化是什么？为什么？

**答案**：**控制视觉 token 数量**（HSE 2026——"是延迟与吞吐最高效的优化——比量化更有效"）——文档负载中视觉输入是计算大头——**减 token = 直接减 prefill**。手段：请求侧（图像缩放/裁剪——免费）；模型侧（动态分辨率——按内容分配 token）；架构侧（投影压缩——LDPNet 144 token）；时序侧（ReVision——截图冗余削减 token -46%）。**验证纪律**：压缩是"有损变更"——压缩后必跑感知回测（HoloCount 类——"省 token 不能以感知崩坏为代价"）。

### Q3：vLLM 的多模态优化特性有哪些？

**答案**：**编码器 CUDA Graphs**（vLLM 0.23.0——ViT 前向捕获为图——消除主机侧内核启动开销——多 token 预算预捕获（2048/4096/8192/13824）+ 贪心装箱）；**编码器数据并行**（`--mm-encoder-tp-mode data`——编码器小、TP 加通信开销——数据并行优于张量并行）；**processor cache**（`--mm-processor-cache-gb`——图像处理结果缓存——同图不重复编码）；**前缀缓存**（Radix 树——公共前缀（含图像）KV 复用）；**分块预填充**（chunked prefill——小规模部署基线）；**多 LoRA 四组件支持**（tower-connector——`多模态/多模态微调（PEFT）/08-多模态微调工程实践.md` 04 节）。

### Q4：E-P-D 分离是什么？什么时候该上？

**答案**：**E-P-D 分离**——编码（E）/预填充（P）/解码（D）分离成独立 vLLM 实例（2026 趋势）——**收益**：专有 prefill 池 **3-4× prefill 吞吐**（ViT 不再打断 prefill 计算）、图像重负载 **1.5-2.5× 吞吐**（128 并发实测）、纯文本请求绕过编码器（TTFT 更低）、独立扩缩——**代价**：跨实例传输（NIXL 连接——RDMA 3-12ms、TCP 约 4 倍）——**盈亏平衡点：64+ 并发 / 96+ GPU**——**"低于 64 并发合设 + chunked prefill 更简单、TTFT 更低"**——架构选择 = 并发规模 × 延迟敏感度（先合设优化、后分离扩展）。

### Q5：多模态量化和文本量化有什么不同？视觉塔能量化吗？

**答案**：**FP8 是 2026 服务默认**（GLM-4.5V 原生 FP8——精度损失最小 + 显存减半）；**视觉塔量化是感知缺陷的放大器**——感知缺陷（计数/小物体/OCR）是视觉编码器精度敏感区——量化视觉塔 = 编码器特征精度下降 = 感知边界进一步缩小——**"视觉塔保持高位宽（BF16/FP8）、语言塔可降到 INT4"**（混合精度——2026 实践）；**量化后必跑感知回测**（HoloCount/OCR——量化验收 = 质量指标 + 感知专项 + 幻觉率三件套）；**GGUF**（mmproj.gguf 投影量化 + MTP 推测——~8× prefill——边缘可移植）；**KV 量化**——视觉 KV 冗余高可剪（剪枝比量化安全——"删冗余 vs 压精度"——视觉 KV 量化保守——精度不足 → 幻觉补全）。

### Q6：多模态缓存策略有哪些？为什么收益大？

**答案**：**多模态重复率天然高于文本**（同一文档页被多次问——处理成本高——缓存消除重复 = 省最大成本项）。三重复用：**图像缓存**（processor cache——图像哈希 → 跳过编码——20GB 级显存——缓存键含编码参数——预处理变即 miss）；**前缀缓存**（公共前缀（系统提示 + 固定图像）的 KV 复用——Radix 树——**前缀缓存感知路由**（图像哈希路由到同副本——"让相同图打同一实例"——路由为缓存服务））；**会话 KV**（多轮保留——早期图像被遗忘的权衡——KV 缓存省成本 vs 关键图重发保准确——按任务选）。**监控**：缓存命中率（命中率低 = 重复率低或路由不对——"命中率是缓存设计的反馈"）。

### Q7：Computer Use Agent 怎么部署？延迟预算多少？

**答案**：CUA 通过**截图感知**（不用 DOM——视觉专用模型——Fara1.5-27B/Holotron-12B）——**架构**：多智能体分工（感知子 Agent → 规划 → 工具执行 → 网关——"模型能力不替代 harness 纪律"）。**每动作延迟预算**：截图捕获 50-150ms + VLM prefill 100-200ms（1080p ≈ 1024 token）+ decode 30-60ms + 动作执行 10-100ms = **200-510ms（热）**——冷启动 15-45s（**至少保持一个节点热**）——"总延迟 = 步数 × 每步"。**ReVision**（时序冗余削减）：连续截图的冗余 patch 不重复编码——**token -46%、成功率 +3%**——延长轨迹历史。**安全**：沙箱隔离/动作白名单/关键动作暂停/视觉注入 = 物理动作劫持（CUA 特化——网页截图藏指令）。

### Q8：多模态服务的监控和文本有什么不同？

**答案**：文本监控 + 模态特化——**服务指标**（分阶段延迟——编码/prefill/decode 分开——`多模态/多模态基础概念/02-多模态推理性能分析.md` 的阶段分解）；**模态特化指标**：图像请求占比（容量规划）、每请求 token 构成（视觉/文本比例——成本先行指标）、**缓存命中率**、**交互阈值**（Agent 场景——同时响应 Agent 数——"比原始吞吐更重要"——固定交互阈值下能撑多少并发 Agent）；**资源**：VRAM 余量（~20% 目标——H200 40-50 会话 vs 59 上限）、主机内存/`/dev/shm`（图像张量传输）；**质量**：评估集在线化（能力/缺陷抽测——`多模态/多模态常见问题与缺陷/09-评估与缺陷检测.md` 的缺陷回归服务化）；**可观测**：阶段 span + token 构成 + 版本号三件套（排障第一手数据）。

## 2. 部署场景题

**场景一**："文档 RAG 服务上线后 P95 延迟 5 秒（预算 2 秒），怎么排查优化？"——按阶段分解定位（`多模态/多模态基础概念/02-多模态推理性能分析.md` 的四步）：**token 预算核对**（文档页的视觉 token 数——高分辨率文档膨胀是首要嫌疑——请求侧压缩（缩放/裁剪）——"控制视觉 token 是第一优化"）；**编码阶段**（processor cache 命中率——同页多次问是否重复编码——缓存命中率低 = 编码重复）；**prefill**（chunked prefill/前缀缓存——公共前缀含页面图——路由一致性）；**量化**（FP8——语言塔——视觉塔保守）——**按"token 压缩 → 缓存 → 内核 → 量化"顺序优化**（先免费后高成本——`多模态/多模态基础概念/03-多模态推理优化.md` 的决策矩阵）。

**场景二**："128 并发图像重负载，合设实例吞吐上不去，怎么办？"——**E-P-D 分离**（128 并发 > 64 盈亏点——图像重负载的分离收益 1.5-2.5×）：编码/prefill/decode 分实例（prefill 专有池 3-4× 吞吐——ViT 不再打断 prefill）——NIXL 连接（RDMA 优先——TCP 开销 4 倍）；配套——编码器 CUDA Graphs + 数据并行编码器 + processor cache（20GB+）+ 前缀缓存路由（同图同副本）——"先榨干单实例（内核优化）再上分离"。

**场景三**："要部署 100 个并发的 computer use Agent，方案怎么给？"——**模型选型**（视觉专用 CUA（Holotron-12B 类——SSM 架构 KV 替代——8.9k tokens/s 并发 100）；**延迟预算**（每动作 200-510ms 热——冷启动保持热节点）；**token 优化**（ReVision 时序冗余削减——截图 token -46%——延长轨迹历史）；**架构**（多智能体分工——感知/规划/执行分离——网关编排——`多模态/多模态基础概念/07-多模态Agent部署.md` 的拓扑）；**安全**（沙箱/动作白名单/关键动作暂停——视觉注入防御）；**监控**（交互阈值——"SLA 内并发 ≥ 100"——VRAM 余量）；**成本**（自托管 vs API 盈亏点——Agent 每轮多模型调用的每 token 账本）。

## 3. 答题范式总结

多模态推理部署题标准答题结构（四步）：**讲差异**（编码阶段/视觉 prefill/KV 占比——先给"为什么贵"）→ **给数字**（576 token/2GB 每会话/200-510ms/64 并发盈亏点/1.5-2.5×）→ **排顺序**（token 压缩第一 → 内核 → 缓存 → 量化 → 分离——
"先免费后高成本"）→ **划边界**（合设 vs 分离/视觉塔量化陷阱/交互阈值）——**"差异 → 数字 → 顺序 → 边界"四件套**；进阶追问导向基础概念（token/架构原理）与多模态微调（模型来源）——部署答得稳，证明既懂模型又懂服务。

> 🎯 **核心要点**：多模态推理部署面试 = 8 题全覆盖（差异/第一优化/vLLM 特性/分离架构/量化陷阱/缓存/Agent/监控）+ 3 场景题（延迟优化/吞吐/Agent 部署）；答题四步 = 差异→数字→顺序→边界；2026 数字弹药——576-5329 token、3-4×（prefill 池）、1.5-2.5×（分离吞吐）、64 并发/96 GPU（盈亏点）、3-12ms（NIXL）、-46% token（ReVision）、200-510ms（每动作）、$125K-190K（自托管年成本）——部署是"模型 × 服务"的交汇点：懂模型才知道优化什么、懂服务才知道怎么优化。
