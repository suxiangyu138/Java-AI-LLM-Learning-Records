## 3. 为什么必须学透多模态推理部署

1. **图像 token 膨胀是 2026 服务的第一挑战**：单张高分辨率图像可膨胀到数千 token——**文档处理负载中大部分计算成本来自长视觉输入而非回答生成**——"控制视觉 token 数量是延迟与吞吐最高效的优化"（HSE 2026 实证——比量化更有效）——本体系 02/03 篇给完整账本与解法。
2. **2026 架构在演进**：**E-P-D 分离**（编码/预填充/解码分离成独立实例——图像重负载 1.5-2.5× 吞吐、专有 prefill 池 3-4× 吞吐——64 并发/96 GPU 是盈亏平衡点）；**编码器 CUDA Graphs**（ViT 前向捕获为图——消除内核启动开销）；**模态感知调度**（Duet-Infer——P99 TTFT -33.7%）——本体系 03/04 篇给全套。
3. **多模态服务的成本是"每 token"账本**：Agent 每轮调用多个模型（感知/规划/工具/检查——每查询多次计量）——**"每 token 成本不随 Agent 使用方式缩放"**（自托管省 50-75%——但最小自托管部署 $125K-190K/年）——本体系 09 篇给成本模型。
4. **多模态量化有"感知陷阱"**：视觉塔量化会放大感知缺陷（`多模态/多模态常见问题与缺陷/02-视觉感知缺陷.md` 的感知边界——量化后更差）——FP8 是 2026 默认（GLM-4.5V 原生 FP8）——**"量化决策必须带感知回测"**——本体系 05 篇给量化全景与陷阱。
5. **Agent 部署是 2026 主战场**：computer use（截图感知——每动作 200-510ms 延迟预算）、ReVision 时序冗余削减（token -46% 且成功率 +3%）、安全（沙箱/白名单）——**"多模态推理的 Agent 化"是本体系的实战收口**（07 篇）。

## 4. 核心概念速查

### 4.1 核心概念

| 概念 | 一句话 | 关键数字 |
|------|--------|---------|
| 图像 token 膨胀 | 高分辨率图像 → 数千 token | 文档负载计算大头 |
| E-P-D 分离 | 编码/预填充/解码分实例 | 64 并发/96 GPU 盈亏点 |
| 编码器 CUDA Graphs | ViT 前向捕获为图 | 消除内核启动开销 |
| 模态感知调度 | 图像/文本任务分优先级 | P99 TTFT -33.7% |
| 前缀缓存路由 | 图像哈希路由到同副本 | KV 命中最大化 |
| processor cache | 图像处理结果缓存 | 20GB+ 专用显存 |
| FP8 | 服务默认量化 | 精度损失最小 |
| ReVision | 截图时序冗余削减 | token -46%、成功率 +3% |
| 交互阈值 | 同时响应 Agent 数 | 比原始吞吐更重要 |
| 每 token 成本 | Agent 的成本账本 | 每查询多次计量 |

### 4.2 部署形态对比

| 形态 | 适用 | 收益 | 代价 |
|------|------|------|------|
| 合设（colocated） | <64 并发/延迟敏感 | 简单、TTFT 低 | 编码器打断 prefill |
| 分离（E-P-D） | >64 并发/吞吐优化 | 1.5-2.5× 吞吐 | NIXL 开销 3-12ms |

### 4.3 常见误区速查

- "量化是第一优化" → 错：token 压缩（视觉 token 预算）比量化更有效（HSE 实证）
- "分离一定更好" → 错：64 并发/96 GPU 以下合设更简单 TTFT 更低
- "视觉塔量化没关系" → 错：感知缺陷被量化放大——量化要带感知回测
- "Agent 成本 = 生成成本" → 错：Agent 每轮多次调用（感知/规划/工具）——每 token 成本账

## 5. 与周边知识的关系

```text
                    ┌── 大模型微调知识体系/推理部署相关/ —— 文本推理方法论（基础层）
多模态体系         ├── 基础概念/ —— 原理层（token/编码器/架构——本体系的"为什么"）
                    ├── 多模态微调（PEFT）/ —— 训练侧（服务对象的来源）
                    ├── 多模态 RAG/ —— 检索侧（服务链路的组成）
                    ├── 多模态常见问题与缺陷/ —— 缺陷（量化/服务要防的）
                    ├── 本体系 —— 推理部署（服务怎么跑）
                    └── 大模型微调知识体系/模型推理与部署/ —— 文本推理部署深潜
```

**本体系与周边知识的分工**：`基础概念` 讲 token/编码器/架构原理（本体系性能分析的"为什么"——图像 token 膨胀的根源在 576 token/patch 粒度）；`多模态微调（PEFT）` 产出服务对象（微调模型 → 本体系部署）；`多模态 RAG` 的检索链路是本体系服务的组成；`常见问题与缺陷` 是服务要防的（量化放大感知缺陷）。读法建议：基础概念（原理）→ 微调（模型）→ 本体系（服务）→ 缺陷（排障）——**"原理 → 训练 → 部署 → 排障"闭环**。

## 6. 学习路线推荐

**路线一：面试速成（半天，对应模块 01-03 + 05 + 10）**
全景 → 性能分析 → 优化 → 量化 → 面试题；掌握"token 膨胀 + E-P-D 分离 + FP8"三大考点。

**路线二：服务入门（1-2 天，对应模块 01-06 + 08）**
全景 → 性能 → 优化 → 架构 → 量化 → 缓存 → 工程化；配合一次 vLLM 多模态服务部署实践。

**路线三：Agent 与生产（对应模块 07-09）**
Agent 部署 → 工程化 → 压测；面向生产与 Agent 场景。

> 🎯 **核心要点**：多模态推理部署的学习终点 = "**懂链路**（编码→投影→prefill→decode）、**懂膨胀**（图像 token 数千——文档负载大头）、**懂优化**（token 压缩第一杠杆/编码器 CUDA Graphs/KV 缓存）、**懂架构**（合设 vs E-P-D 分离——64 并发盈亏点）、**懂量化**（FP8 默认 + 视觉塔感知陷阱）、**懂缓存**（图像/前缀/会话三层）、**懂 Agent**（computer use/截图管理/安全）、**懂度量**（压测/成本模型/交互阈值）"——八件事覆盖多模态服务全貌；记住"**控制视觉 token 数量是最高效的优化**"——一切性能问题的第一杠杆在 token。
