# 多模态推理评估与压测

> 服务的度量：压测方法论（请求分层/并发梯度）、延迟预算（SLA 设计）、成本模型（每 token 账本）、压测工具——"先定 SLA，再测服务"

## 1. 压测方法论

多模态服务的压测（`大模型微调知识体系/模型推理与部署/` 的压测方法论多模态版）：

**请求分层**（多模态压测的核心纪律）：**纯文本/单图/多图/视频**各层单独测——**"单一平均延迟掩盖图像负载的慢"**（`多模态/多模态基础概念/02-多模态推理性能分析.md` 05 节的基线纪律——文本 P95 与图像 P95 可能差数倍——混在一起的平均值无意义）；**图像规格分层**（低/中/高分辨率——1080p 截图 vs 4K 文档——token 数差异——`多模态/多模态基础概念/02-多模态推理性能分析.md` 的 token 估算）。

**并发梯度**：1/16/64/128 并发——测量**每层的延迟曲线与吞吐曲线**——**交互阈值曲线**（Agent 场景——"P99 延迟超过预算时的并发数"——`多模态/多模态基础概念/07-多模态Agent部署.md` 的交互阈值——**"压测的输出不是最大吞吐，是 SLA 内并发"**）。

**压测场景**：文档 RAG（多图检索——`多模态/多模态 RAG/` 的链路压测）、对话（单图多轮）、Agent（截图流——`多模态/多模态基础概念/07-多模态Agent部署.md`）——**"按真实负载构成压测"**（测试负载与生产负载的构成一致——否则压测结论不可迁移）。

## 2. 延迟预算与 SLA

多模态服务的延迟预算（`多模态/多模态基础概念/02-多模态推理性能分析.md` 的实测参考）：**交互型**（对话/Agent——子 2 秒 SLA——多模态生成 +1.5-3s 与子 2 秒的冲突——
`多模态/多模态常见问题与缺陷/07-上下文与工程缺陷.md` 的延迟——**"多模态的交互 SLA 要按阶段定预算"**（编码 100-200ms/prefill 300-500ms/decode 按长度——预算分解）；**批处理型**（离线任务——无 SLA——吞吐优先——`多模态/多模态基础概念/04-多模态服务架构.md` 的分离形态）。

**SLA 设计**：**分位选择**（P50/P95/P99——交互型 P95、批处理 P50）；**按模态分层**（文本/图像/视频的 SLA 分开——图像允许更慢——"SLA 按模态定"）；**预算分解**（每阶段预算 + 总预算——`多模态/多模态基础概念/02-多模态推理性能分析.md` 的阶段分解——"SLA 违反时定位到阶段"——`大模型微调知识体系/模型推理与部署/` 的 SLA 方法论多模态版）。

## 3. 成本模型：每 token 账本

多模态服务的成本模型（`多模态/多模态微调（PEFT）/` 的成本方法论多模态版）：**成本 = Σ（每请求 token × 单价）**——**多模态的 token 构成不同**（视觉 token 多——`多模态/多模态基础概念/06-多模态token与输入处理.md` 的 token 账本）——**成本按 token 构成估算**（图像请求成本 = 文本请求的数倍——`多模态/多模态基础概念/02-多模态推理性能分析.md` 的膨胀）。

**Agent 的成本特化**：**"Agent 每轮调用多个模型"**（感知/规划/工具/检查——每查询多次计量——`多模态/多模态基础概念/07-多模态Agent部署.md`）——**"每 token 成本不随 Agent 使用方式缩放"**——Agent 的成本 = 每查询的模型调用数 × 每调用 token——**成本优化的方向**：token 压缩（每调用）、缓存（重复调用）、小模型（感知子 Agent 用小模型——`多模态/多模态基础概念/07-多模态Agent部署.md` 的多智能体分工——"感知用轻量、推理用重量"）。

**自托管 vs API 成本**：自托管省 50-75%（规模时）——**最小自托管部署 $125K-190K/年**（含运维人力）——`多模态/多模态基础概念/` 的成本账——**"成本模型 = 自托管 vs API 的规模权衡"**（小规模 API 便宜、大规模自托管便宜——盈亏点按调用量算）。

## 4. 压测工具

多模态压测的工具链（`大模型微调知识体系/模型推理与部署/` 的压测工具多模态版）：**通用压测**（`大模型微调知识体系/` 的 wrk 类/自写压测脚本——并发请求模拟）；**推理引擎基准**（vLLM benchmark——
`大模型微调知识体系/` 的离线/在线基准工具）；**多模态负载生成**（图像请求构造——真实截图/文档样本——`多模态/多模态数据集/` 的样本库复用——"压测用真实负载样本"）；**监控集成**（压测期间的指标采集——`多模态/多模态基础概念/08-多模态模型工程化.md` 的监控——阶段分解）。

## 5. 压测的验收标准

多模态压测的验收（压测结束的判定）：**SLA 达标**（各模态分层的 P95 在预算内——`多模态/多模态基础概念/` 的 SLA 设计）；**交互阈值达标**（Agent 场景的目标并发——"SLA 内并发 ≥ 目标"）；
**资源余量**（VRAM ~20% 余量——`多模态/多模态基础概念/08-多模态模型工程化.md` 的资源指标）；**稳定性**（长时压测（1 小时+）的指标平稳——显存泄漏/缓存膨胀的检测——`多模态/多模态常见问题与缺陷/07-上下文与工程缺陷.md` 的泄漏监控多模态版）；**报告**（每层延迟/吞吐/成本曲线 + 瓶颈定位——`大模型微调知识体系/完整微调工程流程/` 的压测报告纪律）。

## 6. 压测的迭代闭环

压测与优化的闭环：**压测 → 瓶颈定位（`多模态/多模态基础概念/02-多模态推理性能分析.md` 的四步）→ 优化（03/05/06 篇的杠杆——token 压缩/内核/缓存/量化）→ 复测**——**"压测是优化的度量衡"**（每次优化前后同负载对比——
`多模态/多模态基础概念/` 的"改前改后同一基准"——token 构成一致的对比才有意义）；**压测的版本纪律**（负载样本/模型版本/引擎版本的记录——"压测可复现"——`大模型微调知识体系/` 的复现纪律）。

> 🎯 **核心要点**：压测方法论——请求分层（文本/单图/多图/视频各测——单一平均掩盖图像慢）+ 并发梯度（1/16/64/128）+ 按真实负载构成（测试与生产一致——否则不可迁移）；延迟预算——交互型按阶段定预算（编码 100-200/prefill/解码——SLA 违反定位到阶段）/批处理吞吐优先——SLA 按模态分层；成本模型——每 token 账本（视觉 token 重——图像请求数倍成本）+ Agent 特化（每轮多模型调用——每 token 成本不随使用方式缩放——优化方向 token 压缩/缓存/小模型分工）+ 自托管 vs API（盈亏点按调用量）；压测工具（通用 + vLLM benchmark + 真实样本）；验收——SLA 达标/交互阈值/资源余量/长时稳定/报告；闭环——压测→定位→优化→复测（"压测是优化的度量衡"）。
