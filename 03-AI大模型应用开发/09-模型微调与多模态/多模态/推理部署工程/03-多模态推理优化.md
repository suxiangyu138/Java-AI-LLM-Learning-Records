# 多模态推理优化

> 优化的杠杆排序：视觉 token 压缩（第一杠杆）、编码器优化（CUDA Graphs/数据并行）、KV cache 优化、prefill 优化（分块/分离）——"先减 token，再优化内核"

## 1. token 压缩：第一杠杆

**视觉 token 压缩是 2026 多模态服务的第一优化**（HSE 2026——"控制视觉 token 数量是延迟与吞吐最高效的优化——比量化更有效"）——**文档负载中视觉输入是计算大头——减 token = 直接减 prefill**。

**压缩手段**（`多模态/多模态基础概念/06-多模态token与输入处理.md` 05 节的压缩在服务侧的落地）：**请求侧**——图像缩放/裁剪（分辨率预算——`多模态/多模态常见问题与缺陷/07-上下文与工程缺陷.md` 的"裁剪去边"）；**模型侧**——动态分辨率（Qwen-VL 系——按内容分配 token）；**架构侧**——投影压缩（LDPNet 类——144 token——`多模态/多模态基础概念/04-投影层与视觉语言桥接.md`）；**时序侧**——视频/截图的冗余削减（ReVision——token -46%——07 篇）——**"压缩的优先级：请求侧（免费）→ 模型侧（配置）→ 架构侧（选型）"**。

**压缩的"应用感知"**：压缩粒度要按应用场景定——**文档 OCR（细粒度文字）压缩要保守**（`多模态/多模态常见问题与缺陷/04-OCR与文档理解缺陷.md` 的字形感知——压缩过度直接毁 OCR）；**对话/通用（粗粒度语义）压缩可激进**——**"压缩与任务的感知需求匹配"**（与 `多模态/多模态基础概念/02-多模态推理性能分析.md` 的"分辨率策略 = 细节需求 × 成本预算"同构——服务侧的压缩配置按应用画像（`多模态/多模态常见问题与缺陷/09-评估与缺陷检测.md` 的缺陷画像——感知敏感的应用压缩保守）。

**压缩的验证**：压缩是"有损变更"——**压缩后跑感知回测**（`多模态/多模态基础概念/06-多模态token与输入处理.md` 的压缩验证纪律——HoloCount 类小样本——"省 token 不能以感知崩坏为代价"）。

## 2. 编码器优化

视觉编码器的推理优化（2026 vLLM 特性）：

**编码器 CUDA Graphs**（vLLM 0.23.0）：**ViT 前向捕获为 CUDA Graphs**（独立于解码器图）——**消除主机侧内核启动开销**（小 batch/小图像时显著）——预捕获多 token 预算图（2048/4096/8192/13824）+ 运行时贪心装箱——数据并行支持（`mm_encoder_tp_mode="data"`——编码器小、TP 加通信开销——**数据并行优于张量并行**）；**视频注意**：Qwen3-VL 视频支持（EVS 剪枝开启时视频 CUDA Graphs 自动禁用）。

**编码器并行**：`--mm-encoder-tp-mode data`——视觉编码器数据并行而非张量并行——**"编码器小、TP 是浪费"**（GLM-4.5V 配方——Duet-Infer 同样）；**编码器缓存**（`--mm-processor-cache-gb`——06 篇——重复图像的处理结果缓存——"同图多次问不重复编码"）。

## 3. KV cache 优化

多模态的 KV cache 优化（视觉 token 常占序列长度大头——`多模态/多模态基础概念/06-多模态token与输入处理.md` 的序列构成）：

**前缀缓存（Prefix Caching）**：公共前缀（系统提示 + 固定图像）的 KV 复用——**Radix 树前缀缓存**（vLLM/Furiosa-LLM 标准特性）——**"多模态的公共前缀常含图像"**（Agent 的固定截图 + 系统提示——缓存收益大）；**前缀缓存感知路由**（06 篇）——图像哈希路由到同副本——KV 命中最大化。

**稀疏 KV 压缩（2026）**：**DeltaKV 压缩 + 视觉 token 剪枝**（Sparse-vLLM）——视觉 token 的 KV 可剪（冗余高）——int4 量化残差 delta——**"视觉 KV 的可压缩性"**（视觉 token 比文本 token 冗余——剪枝空间大）；**混合 KV 缓存**（滑动窗口 + 全局注意力的混合——长上下文模型）。

**KV 容量管理**：`--gpu-memory-utilization=0.95`（最大化 KV 容量——GLM-4.5V 配方）——**"KV 容量 = 并发会话数的上限"**（7B 每会话 4K 上下文约 2GB——`多模态/多模态微调（PEFT）/08-多模态微调工程实践.md` 的会话账本）。

**KV 优化的"模态特化"**：多模态的 KV 优化重点与文本不同——**文本 KV 优化（量化/稀疏）是"精度换容量"；多模态的视觉 KV 优化是"冗余削减"**（视觉 token 的冗余高——DeltaKV 剪枝/ReVision 时序削减——`多模态/多模态基础概念/07-多模态Agent部署.md` 的时序冗余）——**"多模态 KV 的第一优化是剪冗余而非压精度"**（剪枝比量化安全——`多模态/多模态基础概念/05-多模态量化与压缩.md` 04 节的"删冗余 vs 压精度"）。

## 4. prefill 优化

**prefill 是多模态的耗时大头**（长视觉输入）——优化手段：

**分块预填充（Chunked Prefill）**：prefill 切成块与 decode 混排（vLLM 标准——**小规模部署的推荐基线**——`大模型微调知识体系/模型推理与部署/` 的分块方法论多模态版）；**prefill 分离池**（E-P-D 分离——专有 prefill 实例——3-4× prefill 吞吐——04 篇——**大规模吞吐优化的答案**）；**模态感知调度（Duet-Infer，IEEE 2026）**：图像/文本任务分优先级调度——预处理并行 + 共享内存管理器（编码器缓存共享）+ 公平感知调度器——**P99 TTFT -33.7%、端到端延迟 -20%**（单 GPU vLLM 混合负载）——**"调度器懂模态（图像任务优先编码/文本任务快速过）比不懂模态更优"**。

## 5. 推测解码与多模态

**推测解码（Speculative Decoding）**（`大模型微调知识体系/模型推理与部署/` 的推测解码方法论）：多模态的适配——**多模态草稿模型**（草稿模型看同样的图——视觉 token 的处理也要草稿——多模态的推测解码复杂度更高（视觉上下文的一致性））——2026 前沿（HSE 提及）；**GGUF 的 MTP 推测解码**（多 token 预测——GGUF 插件支持——05 篇）。

## 6. 优化决策矩阵

多模态推理优化的决策（按部署规模）：**小规模（<64 并发）**——token 压缩（请求侧）+ 编码器 CUDA Graphs + 数据并行编码器 + processor cache + chunked prefill + 高 GPU 利用率——
**"合设 + 全套内核优化"**；**大规模（>64 并发）**——以上 + **E-P-D 分离**（prefill 池 + decode 池——NIXL 连接）——**"分离是内核优化后的下一步"**（先榨干单实例、再上分离——优化顺序 = 免费 → 内核 → 架构——与 `大模型微调知识体系/训练关键超参 & 显存优化技术/09-训练性能优化.md` 的"先零成本后高成本"同构）。

> 🎯 **核心要点**：token 压缩是第一杠杆（比量化更有效——请求侧免费→模型侧配置→架构侧选型——压缩后感知回测）；编码器优化——CUDA Graphs（消内核启动——多 token 预算预捕获）/数据并行编码器（编码器小 TP 是浪费——mm-encoder-tp-mode data）/processor cache（重复图不重复编码）；KV 优化——前缀缓存（公共前缀含图像——Agent 固定截图收益大）/稀疏 KV 压缩（DeltaKV + 视觉 token 剪枝——视觉 KV 冗余高）/gpu-memory-utilization 0.95；prefill 优化——chunked prefill（小规模基线）/prefill 分离池（大规模 3-4×）/模态感知调度（Duet-Infer P99 TTFT -33.7%）；推测解码多模态（草稿模型也看图——前沿）；决策矩阵——小规模"合设 + 全套内核优化"、大规模再加分离——"先榨干单实例再上分离"。
