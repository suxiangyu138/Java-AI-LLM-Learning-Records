# 多模态缓存策略

> 多模态服务的"重复消除"：图像缓存（processor cache）、前缀缓存路由（图像哈希）、视觉 token 复用、会话 KV 缓存——"多模态的重复请求率远高于文本（同一文档页被多次问）"

## 1. 为什么多模态缓存收益大

多模态应用的**重复率天然高于文本**——同一张图/文档页被多次问（`多模态/多模态常见问题与缺陷/` 的 RAG 场景——同页多次检索）——**重复的处理成本高**（编码 + 视觉 prefill——`多模态/多模态基础概念/02-多模态推理性能分析.md` 的 token 膨胀）——**缓存消除重复 = 直接省最大的成本项**——"多模态缓存是性价比最高的优化之一"（与 token 压缩并列——压缩减"每次的成本"、缓存减"重复的次数"）。

**三重复用机会**：**编码输出**（同图不重复编码——processor cache）；**KV**（同上下文不重复 prefill——前缀缓存）；**推理结果**（同请求不重复推理——请求级缓存——`大模型微调知识体系/模型推理与部署/` 的缓存方法论）。

**缓存的"成本杠杆"定位**：多模态缓存的收益 > 文本缓存——**文本缓存省的是"重复的生成"（便宜）；多模态缓存省的是"重复的编码 + prefill"（贵）**——`多模态/多模态基础概念/02-多模态推理性能分析.md` 的"编码 + prefill 是额外成本大头"——**"缓存省的是最贵的部分"**（缓存命中率是多模态服务成本的第一监控指标——`多模态/多模态基础概念/08-多模态模型工程化.md` 的监控——"缓存设计的好坏直接体现在成本账上"）。

## 2. 图像缓存：processor cache

**多模态处理器缓存（Multimodal Processor Cache）**：视觉编码器的输出缓存（vLLM 的 `--mm-processor-cache-gb`——如 20GB 专用显存；`--mm-processor-cache-type shm`——共享内存缓存——GLM-4.5V 配方）——**机制**：图像哈希（输入图像 → 哈希 → 缓存命中 → 跳过编码直接取特征）——**"同图多次问不重复编码"**（编码是视觉处理的大头——`多模态/多模态基础概念/02-多模态推理性能分析.md` 的编码延迟）。

**缓存的粒度**：**图像级**（整图特征缓存——最常见）；**图像块级**（大图分块的块级缓存——部分变更复用——文档页的局部更新）；**processor 参数**（编码参数（分辨率/预处理）不同 = 缓存键不同——`多模态/多模态基础概念/02-视觉编码器与图像tokenization.md` 的预处理一致性——"预处理变了缓存就 miss"）。

## 3. 前缀缓存与路由

**前缀缓存（Prefix Caching）**：公共前缀（系统提示 + 固定图像）的 KV 复用——**Radix 树前缀缓存**（vLLM/Furiosa-LLM 标准）——多模态的公共前缀**常含图像**（Agent 的固定截图 + 系统提示；文档问答的固定页面图 + 问题模板）——**缓存收益大**（视觉 KV 是大头——`多模态/多模态微调（PEFT）/08-多模态微调工程实践.md` 的 KV 账本）。

**前缀缓存感知路由（2026，llm-d）**：**图像哈希路由到同一副本**——请求共享大视觉上下文时**命中已驻留的编码输出/KV 块**——**"让相同的图打到同一个服务实例"**（分散到不同副本 = 每副本都 miss——路由是缓存的前置条件——**"路由为缓存服务"**（与负载均衡的随机路由不同——缓存感知路由优先一致性）。

## 4. 视觉 token 复用

**视觉 token 的跨请求复用**（多模态特有）：同一图像的视觉 token（编码输出）在多个请求间复用（processor cache 的 KV 侧）——**文档场景的典型**（同一文档页被不同问题引用——视觉 token 相同、文本 token 不同——`多模态/多模态 RAG/05-多模态RAG架构设计.md` 的检索证据——**"检索结果（页面图）的视觉 token 复用是 RAG 服务的缓存红利"**——`多模态/多模态微调（PEFT）/08-多模态微调工程实践.md` 的 RAG 集成）。

**复用的实现**：请求级（同请求内多问题共享——视觉 token 一次编码多次用）；跨请求（processor cache + 前缀路由）；**批内复用**（batch 内同图请求合并编码——编码器 batch 的重复消除）。

## 5. 会话 KV 缓存

**会话级 KV 缓存**（`大模型微调知识体系/模型推理与部署/` 的对话缓存多模态版）：多轮对话的 KV 保留（不重新 prefill 历史）——**多模态的会话缓存注意**：**图像在会话中的位置**（早期图像在长对话中"被遗忘"——`多模态/多模态常见问题与缺陷/07-上下文与工程缺陷.md` 的视觉衰减——缓存保留的是 KV 不是图像本身——**"会话缓存的视觉有效性"**（KV 精度保持 vs 重发图像——`多模态/多模态常见问题与缺陷/07-上下文与工程缺陷.md` 的关键图重发与 KV 缓存的权衡——KV 缓存省成本、重发保准确——按任务选）。

**会话 KV 的容量**：每会话 KV 显存（`多模态/多模态微调（PEFT）/08-多模态微调工程实践.md` 的会话账本——7B 4K 上下文约 2GB——图像多的会话 KV 更大——**"图像会话的 KV 容量规划"**（视觉 token 的 KV 占比——`多模态/多模态基础概念/06-多模态token与输入处理.md`）。

## 6. 缓存策略设计

多模态缓存的设计清单：**缓存键**（图像哈希 + 编码参数——`多模态/多模态基础概念/02-视觉编码器与图像tokenization.md` 的预处理一致性）；**缓存层**（图像级/前缀级/请求级——
按重复模式选——文档 RAG 图像级 + 前缀级、对话会话级）；**路由配合**（缓存感知路由——图像哈希路由）；**失效策略**（图像更新（文档变更）→ 哈希变 → 自然失效；
模型升级 → 编码输出变 → 全量失效——`多模态/多模态微调（PEFT）/08-多模态微调工程实践.md` 的底座版本一致性——"换模型 = 缓存失效"）；**命中率监控**（缓存命中率是服务指标——命中率低 = 重复率低（缓存没必要）或路由不对（缓存没被利用）——**"命中率是缓存设计的反馈"**）。

> 🎯 **核心要点**：多模态重复率天然高（同文档页多次问——处理成本高——缓存消除重复 = 省最大成本项）；三重复用（编码输出/KV/推理结果）；图像缓存——processor cache（图像哈希 → 跳过编码——20GB 级显存——缓存键含编码参数——预处理变即 miss）；前缀缓存路由——图像哈希路由到同副本（"让相同图打同一实例"——路由为缓存服务）；视觉 token 复用——文档 RAG 的缓存红利（检索页面图的 token 复用）；会话 KV——早期图像被遗忘的权衡（KV 缓存省成本 vs 关键图重发保准确——按任务选）；缓存设计——键/层/路由/失效（换模型全量失效）/命中率监控——"命中率是缓存设计的反馈"。
