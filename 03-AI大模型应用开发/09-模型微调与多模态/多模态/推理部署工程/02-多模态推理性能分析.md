# 多模态推理性能分析

> 性能问题的坐标系：延迟四阶段构成（编码/prefill/decode）、图像 token 膨胀的量化（factor 公式）、吞吐与并发、瓶颈定位——"先测对，再优化"

## 1. 延迟构成：四阶段分解

多模态请求的延迟 = **编码延迟 + 投影延迟 + prefill 延迟 + decode 延迟**（01 篇的链路在此量化）：

**编码延迟**：视觉编码器前向（图像数量/分辨率决定——1 张 1080p 截图约 1024 视觉 token——`多模态/多模态基础概念/02-视觉编码器与图像tokenization.md`）；**prefill 延迟**：输入序列（视觉 + 文本）一次前向（**token 数决定**——多模态的 prefill 远长于文本）；**decode 延迟**：逐 token 生成（**回答长度决定**——内存带宽受限——`大模型微调知识体系/模型推理与部署/` 的 decode 分析）。

**实测参考**（computer use 场景——07 篇）：截图捕获 50-150ms、VLM prefill 100-200ms（1080p ≈ 1024 token）、decode 30-60ms、动作执行 10-100ms——**每动作 200-510ms（热）**——**"延迟预算按阶段分解"**（每阶段有量化、瓶颈在哪一目了然——`多模态/多模态微调（PEFT）/08-多模态微调工程实践.md` 的三段计时方法论多模态版）。

## 2. 图像 token 膨胀：性能第一问题

**图像 token 膨胀**：单张高分辨率图像可膨胀到**数千 token**（1024² 约 5329——`多模态/多模态基础概念/02-视觉编码器与图像tokenization.md` 02 节）——**文档处理负载中大部分计算成本来自长视觉输入而非回答生成**（HSE 2026——**"控制视觉 token 数量是延迟与吞吐最高效的优化"**——比量化更有效）。

**token 估算公式**（模型相关）：**维度公式**——Qwen 2.5 用 `(Width × Height) / 784`（factor）、Qwen 3.5 用 /1024——**固定分配**——Gemma 4 每图像固定 280 token——**"token 估算进服务的容量规划"**（请求的视觉 token 数可预估——`多模态/多模态基础概念/06-多模态token与输入处理.md` 的 token 账本在服务侧的落地）。

**膨胀的三个来源**：**分辨率**（高分辨率图 = 高 token——`多模态/多模态基础概念/02-视觉编码器与图像tokenization.md` 的分辨率权衡）；**多图**（N 张图 = N 倍 token——`多模态/多模态常见问题与缺陷/07-上下文与工程缺陷.md` 的多图）；**视频**（帧数 × 每帧——`多模态/多模态基础概念/06-多模态token与输入处理.md` 的视频 token）——**"token 预算 = 分辨率 × 图数 × 帧数"**。

## 3. 吞吐与并发

多模态的吞吐指标（与文本同构 + 多模态特化）：**tokens/s**（文本 token 计——**视觉 token 的计算权重不同**——`多模态/多模态微调（PEFT）/08-多模态微调工程实践.md` 的"1 图像 ≈ 数文本"）；
**请求/秒**（多模态请求的完成率——图像负载的实用指标）；**交互阈值**（Agent 场景——**同时响应的 Agent 数**——比原始吞吐更重要——07/08 篇——"固定交互阈值下能撑多少并发 Agent"）。

**并发的影响**：并发上升 → prefill 与 decode 争抢（合设形态——`多模态/多模态基础概念/` 的 batch 混排——chunked prefill 缓解——03 篇）；**"多模态的并发瓶颈常在 prefill"**（视觉输入重——prefill 占 GPU 时间长——分离架构的动机——04 篇）。

## 4. 瓶颈定位：四步法

多模态性能瓶颈的定位（`大模型微调知识体系/训练关键超参 & 显存优化技术/09-训练性能优化.md` 的 profiling 方法论多模态版）：**1) 阶段分解计时**（编码/prefill/decode 各多少——
日志/探针——**"哪段占比异常高，瓶颈在哪段"**）；**2) token 预算核对**（请求的视觉 token 数 vs 预期——
膨胀异常的请求（超大图/多图）先拦）；**3) GPU 利用率**（编码与 prefill 的 GPU 利用率——利用率低 = 内核启动开销（CUDA Graphs 的动机——03 篇）/主机传输瓶颈）；**4) 对比基线**（同请求的文本版 vs 图像版延迟差——**"多模态的额外延迟 = 图像版 - 文本版"**——额外成本定位）。

**常见瓶颈清单**：编码器内核启动开销（小图多图场景——`多模态/多模态基础概念/` 的编码器 CUDA Graphs 动机）；主机-GPU 传输（图像张量——`多模态/多模态微调（PEFT）/08-多模态微调工程实践.md` 的主机内存）；KV cache 容量（长会话——`大模型微调知识体系/模型推理与部署/` 的 KV 管理）；prefill 队列（并发高——分离架构的动机）——**"瓶颈清单 + 阶段分解 = 快速定位"**。

**性能数据的"负载构成"维度**：同服务的性能随负载构成变化——**图像占比高的时段（文档批量处理）与文本占比高的时段（对话峰值）的延迟曲线不同**——**"性能分析要带负载构成"**（`多模态/多模态基础概念/08-多模态模型工程化.md` 的图像请求占比监控——容量规划与性能分析的共同输入——"没有负载构成的性能结论不可迁移"）。

## 5. 压测前的基线

性能分析的基线（`大模型微调知识体系/完整微调工程流程/08-模型评估与验收.md` 的基线纪律多模态版）：**请求类型分层**（纯文本/单图/多图/视频——各层单独测——**"单一平均延迟掩盖图像负载的慢"**）；**并发梯度**（1/16/64/128——交互阈值曲线的测量——09 篇）；**token 构成记录**（每请求的视觉/文本 token 数——**"token 构成是性能数据的坐标"**——没有 token 构成的延迟数据无法对比）。

## 6. 性能分析的工具

多模态性能的工具链：**vLLM 日志**（每请求的 prefill/decode 统计——vLLM 自带）；**推理引擎探针**（阶段计时——编码器/语言塔分开统计）；**GPU 工具**（`nvidia-smi`/Nsight——
编码与 prefill 的利用率）；**端到端监控**（`大模型微调知识体系/` 的监控方法论——请求延迟分解上报）——**"阶段分解 + token 构成 + GPU 利用率"三件套**是性能分析的标配（与 `多模态/多模态常见问题与缺陷/07-上下文与工程缺陷.md` 的延迟分解呼应）。

> 🎯 **核心要点**：延迟四阶段（编码/prefill/decode——投影轻量）——"延迟预算按阶段分解"（computer use 实测 200-510ms/动作）；图像 token 膨胀是第一问题（数千 token——文档负载计算大头——"控制视觉 token 是最高效优化"——比量化更有效）；token 估算公式（Qwen 2.5 /784、Qwen 3.5 /1024、Gemma 4 固定 280）——进容量规划；膨胀三来源（分辨率/多图/视频——"token 预算 = 分辨率×图数×帧数"）；吞吐——tokens/s（视觉权重）/请求/秒/交互阈值（Agent 场景）；瓶颈四步（阶段分解/token 核对/GPU 利用率/对比基线——"额外延迟 = 图像版 - 文本版"）；常见瓶颈清单（编码器内核启动/主机传输/KV 容量/prefill 队列）；压测基线——请求分层 + 并发梯度 + token 构成记录。
