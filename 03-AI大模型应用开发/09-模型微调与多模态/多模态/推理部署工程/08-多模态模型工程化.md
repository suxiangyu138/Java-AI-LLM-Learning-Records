# 多模态模型工程化

> 服务的运维层：版本管理（模型/编码器/缓存版本）、A/B 与灰度、监控指标（延迟/交互阈值/VRAM 余量）、可观测性——"多模态服务的运维 = 文本运维 + 模态特化"

## 1. 版本管理

多模态模型的版本管理（`大模型微调知识体系/完整微调工程流程/09-导出部署与上线运维.md` 的版本方法论多模态版）：

**模型版本**（微调产物——`多模态/多模态微调（PEFT）/` 的训练结果——注册表管理——底座/数据/配方可追溯）；**编码器版本**（视觉塔的独立版本——换编码器 = 感知能力变化 + 投影重新对齐——`多模态/多模态微调（PEFT）/04-多模态微调配方.md` 的阶段一——**"编码器版本是独立的变更单元"**）；**缓存版本**（编码输出缓存的版本——模型升级 → 缓存失效——`多模态/多模态基础概念/06-多模态缓存策略.md` 的失效策略——**"换模型必须清缓存"**（旧编码输出与新版不匹配——静默错误的来源））。

**多组件版本矩阵**：VLM 的三组件（编码器/投影/语言塔）可独立升级——**"组件版本矩阵"**（如：编码器 v2 + 投影 v1 + 语言塔 v3 的组合——兼容性验证——`多模态/多模态微调（PEFT）/02-VLM结构与可微调部件.md` 的组件耦合——**"矩阵的每一项变更都要验证组合"**）。

## 2. A/B 与灰度

多模态服务的 A/B 与灰度（`大模型微调知识体系/完整微调工程流程/09-导出部署与上线运维.md` 04 节的灰度方法论多模态版）：**A/B 的评估**——模型质量（任务分/缺陷——`多模态/多模态基础概念/09-多模态能力评估与基准.md`）+ 服务指标（延迟/成本）+ **模态专项**（感知/幻觉——
量化或编码器变更时必测——`多模态/多模态常见问题与缺陷/09-评估与缺陷检测.md` 的缺陷画像）；**灰度放量**（5% → 100%——
每档对比业务指标——`多模态/多模态微调（PEFT）/` 的 RAG/Agent 场景的端到端指标——任务成功率）；**回滚**（模型版本回退 + 缓存失效 + 适配器版本——`多模态/多模态微调（PEFT）/08-多模态微调工程实践.md` 的多 LoRA 回滚——"回滚是秒级切适配器还是重部署全模型——按部署形态"）。

## 3. 监控指标

多模态服务的监控指标（`大模型微调知识体系/` 的监控方法论多模态版）：

**服务指标**（与文本同构）：延迟分位（TTFT/TPOT——`大模型微调知识体系/模型推理与部署/`）、吞吐、错误率——**分阶段**（编码/prefill/decode 延迟分开——`多模态/多模态基础概念/02-多模态推理性能分析.md` 的阶段分解）；**模态特化指标**：**图像请求占比**（负载构成——容量规划）、**每请求 token 构成**（视觉/文本比例——成本先行指标）、**缓存命中率**（`多模态/多模态基础概念/06-多模态缓存策略.md`——命中率低 = 缓存设计问题）、**交互阈值**（Agent 场景——同时响应 Agent 数——`多模态/多模态基础概念/07-多模态Agent部署.md`——"比原始吞吐更重要"）；**资源指标**：**VRAM 余量**（目标 ~20% 余量——H200 40-50 会话 vs 59 上限——`多模态/多模态基础概念/01-多模态推理全景与定位.md` 的会话账本）、主机内存/`/dev/shm`（图像张量传输）。

**质量监控**：**质量漂移**（在线任务指标——端到端——`多模态/多模态基础概念/09-多模态能力评估与基准.md` 的评估集抽测）；**缺陷监控**（幻觉/感知的定期抽测——`多模态/多模态常见问题与缺陷/09-评估与缺陷检测.md` 的缺陷回归——服务侧的质量监控 = 评估集的在线化）。

## 4. 可观测性

多模态的可观测性（`大模型微调知识体系/` 的可观测性方法论多模态版——`大模型微调知识体系/日志监控指标/` 体系）：**追踪**（traceId 贯穿——请求的编码/prefill/decode 分段 span——
`多模态/多模态基础概念/02-多模态推理性能分析.md` 的阶段分解可观测化）；**日志**（请求的模态/图像数/token 构成/缓存命中/模型版本——`多模态/多模态基础概念/` 的版本追溯——"多模态日志的字段比文本多"）；**指标**（第 3 节的监控指标——Prometheus 类）；**告警**（延迟 P99 超预算/缓存命中率骤降/VRAM 余量告急——`多模态/多模态基础概念/09-多模态推理评估与压测.md` 的 SLA 告警）。

**排障的可观测性**：多模态排障（`多模态/多模态常见问题与缺陷/01-问题全景与诊断方法论.md` 的三通道定位）需要可观测数据支撑——**"阶段 span + token 构成 + 版本号"三件套**是排障的第一手数据（"哪个阶段慢/多少 token/哪个模型版本"——`多模态/多模态基础概念/02-多模态推理性能分析.md` 的瓶颈四步在运维侧的数据基础）。

## 5. 容量与扩缩

多模态的容量规划与自动扩缩（`大模型微调知识体系/完整微调工程流程/04-环境搭建与工具链选型.md` 的硬件方法论多模态版）：**容量公式**（会话数 = 显存 ÷（权重 + 每会话 KV）——`多模态/多模态基础概念/01-多模态推理全景与定位.md` 05 节——
图像会话的 KV 更大——**"图像请求占比进容量规划"**）；**扩缩策略**（按交互阈值/请求率扩缩——Agent 场景按同时 Agent 数——**"扩缩到零"**（2026 实践——低成本——`多模态/多模态基础概念/` 的自托管成本账）；**预热管理**（冷启动 15-45s——扩缩的预热缓冲——"扩出来的实例要预热时间"）。

## 6. 工程化检查清单

多模态服务上线的工程化检查：**版本完整**（模型/编码器/缓存版本矩阵记录——变更可追溯）；**A/B 基建**（流量切分 + 双评估（质量 + 服务））；**监控齐备**（服务/模态/质量三组指标——
`多模态/多模态基础概念/` 的监控清单）；**可观测**（阶段 span/token 构成/版本号三件套）；**容量规划**（图像占比进公式）；**回滚演练**（模型回退 + 缓存失效演练——`多模态/多模态微调（PEFT）/08-多模态微调工程实践.md` 的"没演练过的回滚预案等于没有预案"多模态版）——**六项全过才生产**（与 `大模型微调知识体系/完整微调工程流程/` 的门禁纪律同构）。

> 🎯 **核心要点**：版本管理——模型/编码器/缓存三版本（编码器独立变更单元/换模型清缓存——静默错误来源）/组件版本矩阵（三组件可独立升级——组合验证）；A/B 与灰度——双评估（质量 + 服务）+ 模态专项（量化/编码器变更必测感知幻觉）+ 回滚（缓存失效配合）；监控——服务指标（分阶段延迟）+ 模态特化（图像占比/token 构成/缓存命中率/交互阈值）+ 资源（VRAM 20% 余量）+ 质量（评估集在线化）；可观测——阶段 span + token 构成 + 版本号三件套（排障第一手数据）；容量——会话数公式（图像占比进规划）/扩缩到零/预热缓冲；六查——版本/AB/监控/可观测/容量/回滚演练。
