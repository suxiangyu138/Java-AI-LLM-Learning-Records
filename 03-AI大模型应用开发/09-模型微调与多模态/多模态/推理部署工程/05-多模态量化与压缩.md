# 多模态量化与压缩

> 服务的成本杠杆：FP8 默认（GLM-4.5V 原生）、视觉塔量化的感知陷阱、GGUF/INT4、KV cache 量化——"量化决策必须带感知回测"

## 1. FP8：2026 服务默认

**FP8 是 2026 多模态服务的推荐默认量化**（GLM-4.5V 配方——"FP8 是成本高效服务的最低精度损失选择 vs BF16"——GLM-4.5V 原生 FP8 + 专家并行 4×H100/H200 部署）——**为什么 FP8 是默认**：精度损失最小（vs INT4）、显存减半（vs BF16——Nemotron 3 Nano Omni 25GB FP8 单 A100/H100 40GB 可跑）、生态成熟（vLLM 原生支持）——**"BF16 → FP8 是服务默认的第一级量化"**。

**量化的成本收益**（`大模型微调知识体系/` 的量化方法论多模态版）：**权重量化**（FP8/INT4——权重显存减半——会话数翻倍——`多模态/多模态微调（PEFT）/08-多模态微调工程实践.md` 的会话账本：7B BF16 17GB → INT4 9GB——50 → 80-100 会话）；**激活/计算量化**（精度敏感——多模态的感知依赖激活精度——慎用）。

## 2. 视觉塔量化的感知陷阱

**视觉塔量化 = 感知缺陷的放大器**（多模态量化的特有陷阱——`多模态/多模态常见问题与缺陷/02-视觉感知缺陷.md` 的感知边界被量化放大）：

**机制**：感知缺陷（计数/小物体/OCR——`多模态/多模态常见问题与缺陷/04-OCR与文档理解缺陷.md`）是视觉编码器精度敏感区——**量化视觉塔 = 编码器的特征精度下降 = 感知边界进一步缩小**——"模型本来就看不清小物体，量化后更看不清"（`多模态/多模态微调（PEFT）/03-LoRA在多模态上的应用.md` 05 节的"视觉塔精度敏感保持更高位宽"在服务侧的对应）。

**实践的取舍**：**语言塔量化（FP8/INT4）——感知影响小（视觉特征已在语言嵌入空间）**；**视觉塔量化——感知影响大（原始像素处理精度）**——**"视觉塔保持更高位宽（BF16/FP8）、语言塔可降到 INT4"**（混合精度——2026 实践）；**量化后必跑感知回测**（HoloCount 类小样本——量化前后的感知对比——`多模态/多模态基础概念/09-多模态能力评估与基准.md` 的感知轴——**"量化验收 = 质量指标 + 感知专项"**）。

## 3. GGUF 与 INT4

**GGUF 量化**（vLLM GGUF 插件——2026 支持所有 GGUF 量化类型）：**mmproj-*.gguf**（多模态投影权重文件——自动视觉支持）；**MTP 推测解码**（多 token 预测）；**~8× 更快的 prefill**（MMQ 内核——多模态量化内核——小 batch 时）——**"GGUF 让多模态模型的可移植量化（CPU/边缘）成为可能"**（`大模型微调知识体系/模型推理与部署/` 的 GGUF 方法论多模态版——投影权重的 GGUF 化是 VLM 特有）。

**INT4**：权重 INT4（会话数翻倍——成本最优）——**注意**：INT4 的激活精度损失在多模态被感知放大（视觉 token 的处理）——**"INT4 用于语言塔、视觉塔保持高位宽"**（与第 2 节的混合精度一致——`大模型微调知识体系/模型推理与部署/` 的量化分层）。

## 4. KV cache 量化

**KV cache 量化**（`大模型微调知识体系/模型推理与部署/` 的 KV 量化方法论）：多模态的 KV 大头是**视觉 token**（`多模态/多模态基础概念/06-多模态token与输入处理.md` 的序列构成）——**视觉 KV 的可压缩性高**（视觉 token 冗余高——Sparse-vLLM 的 DeltaKV 压缩 + 视觉 token 剪枝——`多模态/多模态微调（PEFT）/08-多模态微调工程实践.md` 的 KV 优化）——**KV 量化的收益**（KV 显存减半 → 会话数翻倍——高并发的杠杆）。

**KV 量化的风险**：**视觉 KV 的精度敏感**（图像细节在 KV 里——量化丢细节 = 回答时"记不清图"——`多模态/多模态常见问题与缺陷/03-视觉幻觉.md` 的幻觉风险（KV 精度不足 → 模型补全））——**"视觉 KV 量化要保守"**（先量文本 KV 区域、视觉 KV 保持精度——或视觉 token 剪枝替代量化——剪枝是"删冗余"、量化是"压精度"——剪枝更安全）。

## 5. 量化与精度的选择矩阵

多模态量化的选择（按模型规模 × 精度敏感度）：

| 场景 | 推荐 |
|------|------|
| 通用服务（默认） | 语言塔 FP8 + 视觉塔 BF16/FP8（混合） |
| 成本极致 | 语言塔 INT4 + 视觉塔 FP8（感知回测必须） |
| 边缘/可移植 | GGUF（mmproj.gguf + MTP） |
| 高并发 | KV 量化/剪枝（视觉 KV 保守） |
| 感知敏感（文档/医疗） | 全 BF16 或仅语言塔 FP8（视觉塔不动） |

**选择纪律**：**量化是"有损变更"**（`大模型微调知识体系/微调常见问题/08-量化与部署问题.md` 的量化损伤方法论多模态版——PPL 掩盖/领域评估门禁——多模态的量化验收 = **质量指标（PPL/任务分）+ 感知专项（HoloCount/OCR）+ 幻觉率**三件套——`多模态/多模态常见问题与缺陷/09-评估与缺陷检测.md` 的缺陷画像）。

## 6. 量化与训练的联动

量化与训练的联动（`大模型微调知识体系/训练关键超参 & 显存优化技术/07-量化微调技术.md` 的 QAT 方法论多模态版）：**QAT（量化感知训练）**——训练时模拟目标量化——多模态的 QAT 注意**视觉塔的 QAT 敏感**（视觉塔 QAT 的精度恢复收益——
`多模态/多模态微调（PEFT）/` 的塔 LoRA 讨论）；**train-serve 精度对齐**（`大模型微调知识体系/微调常见问题/07-效果不达预期问题.md` 的错配——
训练 BF16 服务 INT4 会抹掉微调技能——**多模态的精度错配还会叠加感知损失**——"训练 BF16 + 服务 INT4 = 微调技能丢失 + 感知退化"——`多模态/多模态常见问题与缺陷/07-效果不达预期问题.md` 的精度错配多模态版——**训练时就定服务精度**（QAT 或同精度验证）。

**量化的"服务-训练"协作**：量化决策不该只发生在服务侧——部署形态影响训练决策（`多模态/多模态微调（PEFT）/09-多模态微调评估.md` 的评估链路——服务精度是训练验收的一部分——微调模型在目标服务精度上评估——`大模型微调知识体系/完整微调工程流程/08-模型评估与验收.md` 03 节的服务路径评估多模态版——训练验收就带 FP8/INT4 的评估——"服务侧量化不是部署后的事，训练时就定"）。

> 🎯 **核心要点**：FP8 是 2026 服务默认（GLM-4.5V 原生——精度损失最小 + 显存减半——"BF16→FP8 是第一级量化"）；视觉塔量化 = 感知缺陷放大器（编码器精度敏感区——"视觉塔保持高位宽（BF16/FP8）、语言塔可 INT4"——混合精度——量化后必跑感知回测）；GGUF（mmproj.gguf 投影量化 + MTP 推测——~8× prefill——边缘可移植）；KV 量化——视觉 KV 冗余高可剪（剪枝比量化安全——"删冗余 vs 压精度"）——视觉 KV 量化保守（精度不足 → 幻觉补全）；选择矩阵（默认 FP8 混合/成本 INT4/边缘 GGUF/感知敏感全 BF16）；纪律——量化验收三件套（质量 + 感知 + 幻觉）+ QAT 视觉塔敏感 + train-serve 精度对齐（训练时定服务精度——多模态错配叠加感知损失）。
