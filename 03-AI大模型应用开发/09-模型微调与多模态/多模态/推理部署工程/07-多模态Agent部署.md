# 多模态 Agent 部署

> 2026 部署主战场：computer use 架构（截图感知）、每动作延迟预算、ReVision 时序冗余削减（token -46%）、安全（沙箱/白名单）——"多模态推理的 Agent 化"

## 1. Computer Use 架构

**Computer Use Agent（CUA）**：通过**截图感知**操作计算机/浏览器（不用 DOM）——`多模态/多模态基础概念/07-指令遵循与多模态推理.md` 的多模态 Agent 在部署侧的形态——**2026 生态**：Fara1.5-27B（27B 视觉专用 CUA——262K 上下文——结构化工具调用（点击/输入/滚动））、Holotron-12B（WebVoyager 80.5%——8.9k tokens/s 并发 100）、各家的 computer use。

**架构形态**（2026 实践）：**多智能体分工**（感知子 Agent → 规划/推理 Agent → 工具执行 → 验证 → 网关）——**"模型能力不替代 harness 纪律"**（`多模态/多模态基础概念/07-指令遵循与多模态推理.md` 的能力阶梯——感知/规划/执行分离——各用所长的部署形态——`多模态/多模态微调（PEFT）/08-多模态微调工程实践.md` 的感知-推理分离在 Agent 的落地）。

**感知的部署注意**：CUA 的感知是"截图 + grounding"（`多模态/多模态基础概念/07-指令遵循与多模态推理.md` 的坐标输出——点击位置）——**感知错误的代价放大**（`多模态/多模态常见问题与缺陷/01-问题全景与诊断方法论.md`——看错按钮 = 点错操作——**"CUA 的感知要求高于对话"**（部署验收的感知专项——`多模态/多模态常见问题与缺陷/02-视觉感知缺陷.md`）。

## 2. 每动作延迟预算

CUA 的延迟预算（2026 实测——`多模态/多模态基础概念/02-多模态推理性能分析.md` 01 节）：**截图捕获 50-150ms → VLM prefill 100-200ms（1080p ≈ 1024 token）→ decode 30-60ms → 动作执行 10-100ms**——**每动作 200-510ms（热）**——冷启动（VLM 加载）15-45 秒——**"至少保持一个节点热"**（冷启动超出交互预算）。

**预算的含义**：**每动作的延迟预算 = 多步骤任务的总时长的分母**（100 步任务 × 300ms = 30 秒——"长任务的总延迟 = 步数 × 每步"）——**优化方向**：减每步（token 压缩/缓存——03/06 篇）、减步数（ReVision 的冗余削减——第 3 节——更少的截图 = 更少的步骤）——**"Agent 的延迟优化 = 每步预算 + 步数"**。

**预算的"分阶段定"纪律**：CUA 的每步预算按阶段分解（截图/prefill/decode/执行各一段——`多模态/多模态基础概念/02-多模态推理性能分析.md` 的阶段分解）——**"预算违反时定位到阶段"**（prefill 超了查 token 压缩、截图超了查捕获管线——`多模态/多模态基础概念/09-多模态推理评估与压测.md` 的 SLA 定位——Agent 场景的 SLA 是"每步"而非"每请求"（交互粒度为动作）。

## 3. ReVision：时序冗余削减

**ReVision（2026）**：**跨截图的时序视觉冗余削减**——连续截图的冗余视觉 patch（画面没变的区域）被移除——**token 使用平均 -46%、成功率 +3%**——**"截图不是每张都全量"**（画面变化小的区域不重复编码——时序冗余的消除——`多模态/多模态基础概念/06-多模态token与输入处理.md` 的 token 压缩在时序维度的扩展）。

**意义**：**固定上下文/计算预算下延长轨迹历史**（Agent 的截图 token 少 → 更长会话/更多历史——`多模态/多模态常见问题与缺陷/07-上下文与工程缺陷.md` 的上下文预算）；**NVIDIA EVS（高效视频采样）**同类（视频/截图的密集视觉 token 压缩）——**"时序冗余是 Agent 视觉成本的隐藏大头"**（每步截图 × 变化率——削减后每步 token 大降）。

## 4. CUA 的安全部署

**CUA 的安全是物理动作安全**（点击/输入/滚动是真实操作——`多模态/多模态常见问题与缺陷/08-多模态安全与攻击面.md` 的多模态安全 + 动作安全的叠加）：

**沙箱隔离**（Fara1.5 的 MagenticLite 类）：每会话网络隔离（`多模态/多模态微调（PEFT）/08-多模态微调工程实践.md` 的权限隔离）、独立用户数据目录/文件系统隔离；**动作白名单**（可执行动作的允许列表——`多模态/多模态基础概念/07-指令遵循与多模态推理.md` 的工具调用限制）；**关键动作暂停**（Fara1.5 的 critical-points 设计——不可逆动作（删除/提交/支付）暂停等用户确认）；**限流与速率限制**；**视觉注入防御**（`多模态/多模态常见问题与缺陷/08-多模态安全与攻击面.md`——网页截图藏指令——CUA 被劫持——**"CUA 的视觉注入 = 物理动作劫持"**——提示夹层/输入清洗在 Agent 的落地）。

## 5. 部署形态与资源

CUA 的部署资源（`多模态/多模态基础概念/` 的资源基线）：**视觉专用模型**（Fara1.5-27B 类——27B 视觉专用——262K 上下文——每会话 KV 容量）；**SSM/混合架构**（Holotron-12B/Nemotron——
状态空间模型常驻状态替代 KV——显存大幅降低——更大有效 batch——8.9k tokens/s 并发 100）；**多智能体拓扑**（感知/规划分离——`多模态/多模态微调（PEFT）/` 的多模型服务——`多模态/多模态基础概念/07-多模态token与输入处理.md` 的网关编排）；**主机资源**（截图处理——高主机内存——`多模态/多模态基础概念/01-多模态推理全景与定位.md` 05 节）。

## 6. CUA 的评估与监控

CUA 的评估（`多模态/多模态基础概念/09-多模态推理评估与压测.md` 的 Agent 特化）：**任务成功率**（WebVoyager 类——端到端任务完成率——Holotron 80.5%）；
**每步正确率**（动作/坐标的准确性——grounding 评估——`多模态/多模态基础概念/07-指令遵循与多模态推理.md` 的 RefCOCO 类）；**交互阈值**（同时响应的 Agent 数——`多模态/多模态基础概念/08-多模态模型工程化.md`——比原始吞吐更重要——"固定交互阈值下能撑多少并发 Agent"）；**安全事件**（越权动作/注入命中率——`多模态/多模态常见问题与缺陷/08-多模态安全与攻击面.md` 的监控）——**"CUA 的验收 = 任务成功率 + 交互阈值 + 安全事件三件套"**。

> 🎯 **核心要点**：CUA 通过截图感知（不用 DOM）——多智能体分工（感知/规划/执行分离——"模型能力不替代 harness 纪律"）——感知要求高于对话（看错 = 点错）；每动作延迟预算——200-510ms 热（截图 50-150 + prefill 100-200 + decode 30-60 + 执行 10-100）——冷启动 15-45s 保持热——"总延迟 = 步数 × 每步"；ReVision——时序冗余削减（token -46% 成功率 +3%——截图的冗余 patch 不重复编码——延长轨迹历史——"时序冗余是 Agent 视觉成本隐藏大头"）；安全——沙箱隔离/动作白名单/关键动作暂停/视觉注入 = 物理动作劫持（CUA 特化）；部署——视觉专用模型/SSM 混合架构（KV 替代——8.9k tokens/s 并发 100）/网关编排；验收三件套——任务成功率 + 交互阈值 + 安全事件。
