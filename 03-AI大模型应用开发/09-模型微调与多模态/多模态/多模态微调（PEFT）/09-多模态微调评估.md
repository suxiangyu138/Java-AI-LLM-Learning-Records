# 多模态微调评估

> 多模态微调的验收：能力/缺陷双评估集、MM-Bench/POPE 类基准、融合回测进门禁、冻结策略的评估验证——"多模态微调验收 = 能力提升 + 缺陷不增 + 融合不破"三线

## 1. 双评估集：能力与缺陷

多模态微调的评估集（`多模态/多模态数据集/08-多模态评估数据.md` 的四类评估集在此收口）——**能力与缺陷分开建**（能力测上限、缺陷测下限——`多模态/多模态常见问题与缺陷/09-评估与缺陷检测.md` 01 节）：

**能力评估集**：任务指标（图文 QA/描述质量/领域任务——按应用需求——`多模态/多模态数据集/08-多模态评估数据.md` 02 节）；**缺陷评估集**：幻觉探测（POPE 类/空目标）、感知测试（计数/小物体——HoloCount 类子集）、对齐测试（图文矛盾）、融合回测（图像描述与底座对比——06 篇）——**"能力评估说提升、缺陷评估说代价"**——微调验收必须同时看两边（单看能力提升 = 可能隐藏了缺陷恶化）。

## 2. 基准地图

多模态微调评估的公共基准（2026）：

**能力基准**：MM-Bench（多模态指令遵循——冻结消融的度量，00 篇）、MM-Vet、MMMU（大学多模态理解）、WebQA/MultiModalQA（图文 QA——`多模态/多模态常见问题与缺陷/` 的基准）——**按任务选**（通用对话 MM-Bench/MM-Vet、知识推理 MMMU）；**缺陷基准**：POPE（幻觉探测——DPO 的核心改善目标，07 篇）、HoloCount（计数——感知）、PerceptionBench（10 项原子能力——`多模态/多模态常见问题与缺陷/09-评估与缺陷检测.md` 的缺陷画像）——**"能力基准选型 + 缺陷基准防退化"**。

**领域基准**：按应用定制（文档/医疗/显微镜——`多模态/多模态数据集/08-多模态评估数据.md` 的评估集构建——金标 + 缺陷回归）。

**基准的"任务匹配"纪律**：公共基准测的是"通用能力"——**微调是任务特化的，评估也要任务特化**——"用 MM-Bench 评估文档微调"是错配（文档微调的目标是文档任务，MM-Bench 的通用对话题目测不出文档能力提升）——**评估集 = 任务评估集（测提升）+ 通用基准（测退化）**（`大模型微调知识体系/完整微调工程流程/08-模型评估与验收.md` 的"任务指标 + 通用回测"双测——多模态版：任务评估集测"微调目标"、通用能力/缺陷/融合三回测测"代价"）。

## 3. 融合回测：多模态微调的门禁特项

**融合回测**（多模态微调验收的独有维度——06 篇的融合破坏检测在此成为门禁项）：微调前后跑同一组"纯视觉理解"任务（图像描述质量/定位/跨模态引用）——**与底座逐位对比**（gemma4-31B 的"图像描述逐位一致"标准）——**门禁规则**：融合指标相对底座下降超阈值（如描述质量显著下降）→ 回炉（降 lr/层选择性 LoRA/混通用数据）——**"能力提升 + 融合不破"是微调成功的双条件**（单条件不算成功——能力涨了但看图能力崩了 = 失败的微调）。

## 4. 评估流程

多模态微调的评估流程（`大模型微调知识体系/完整微调工程流程/08-模型评估与验收.md` 的多模态版）：

**eval-first**：微调前先测**三基线**（能力基线/缺陷基线/融合基线——06 篇的"三通道基线"）——**没有基线无法判断"变差"**（多模态微调的融合/感知退化只能靠前后对比发现）；**训练中监控**（阶段门禁——SFT 后、DPO 后各测一次——`大模型微调知识体系/完整微调工程流程/07-训练过程监控与干预.md` 的干预纪律多模态版）；**最终验收**（三线全测：能力提升达标？缺陷不增？融合不破？——**三线门禁**）。

**验收报告**（`大模型微调知识体系/完整微调工程流程/08-模型评估与验收.md` 03 节的报告多模态版）：能力分数（vs 基线）、缺陷分数（vs 基线）、融合分数（vs 底座）、评估集版本、冻结配置（组件/层选择）、配方（lr/epoch）——**"配置可追溯"**（微调报告要能回答"怎么微调的"——组件/层/数据/配方四要素）。

## 5. 冻结策略的评估验证

冻结策略（02/03 篇的组件选择）的评估验证：**组件消融评估**（对比"冻塔 vs 训塔"在任务上的差异——按任务数据定——消融的 MM-Bench 数据是参考，自己的任务要自己测）；**层选择评估**（层选择性 LoRA 的融合回测 vs 全层 LoRA——
"保护融合的收益"量化）；**感知专项评估**（训塔后感知能力是否真的提升——HoloCount/领域感知测试——"塔 LoRA 花了参数，感知收益要验证"）——**"冻结策略的选择要用评估说话"**（不是抄默认就完事——默认档是起点，任务特化要验证）。

## 6. 验收门禁汇总

多模态微调的上线门禁（三线 + 工程）：**能力线**（任务指标相对基线提升达标——`大模型微调知识体系/完整微调工程流程/03-评估先行基线建立.md` 的门禁标准多模态版）；**缺陷线**（幻觉/感知/对齐三类缺陷不增——缺陷回归集——`多模态/多模态常见问题与缺陷/09-评估与缺陷检测.md` 03 节）；**融合线**（融合回测不破——06 篇）；**工程线**（08 篇的六查）——**四线全过才上线**。

**回炉方向**（按失败线定）：能力不达 → 查数据/配方；缺陷恶化 → 查数据质量/加 DPO；融合破坏 → 降 lr/层选择性/混通用数据——**"失败线决定回炉方向"**（与文本微调的分层诊断同构——`大模型微调知识体系/完整微调工程流程/08-模型评估与验收.md` 04 节）。

> 🎯 **核心要点**：双评估集（能力测上限/缺陷测下限——单看能力提升会隐藏缺陷恶化）；基准地图（能力 MM-Bench/MM-Vet/MMMU——缺陷 POPE/HoloCount/PerceptionBench——能力选型 + 缺陷防退化）；融合回测是门禁特项（图像描述与底座逐位对比——"能力提升 + 融合不破"是成功双条件）；评估流程——eval-first 三基线（能力/缺陷/融合）→ 训练中阶段门禁 → 三线最终验收——验收报告含冻结配置（组件/层/数据/配方四要素可追溯）；冻结策略用评估验证（组件消融/层选择融合对比/塔 LoRA 感知收益验证）；四线门禁（能力/缺陷/融合/工程）——失败线决定回炉方向。
