# 多模态微调工程实践

> 多模态微调的落地：显存账本（视觉塔的额外开销）、训练时间、模态长度分组采样的实现、vLLM 多 LoRA（tower-connector 支持）、部署与版本——"工程细节决定微调能不能跑起来"

## 1. 显存账本：多模态的额外开销

多模态微调的显存（`大模型微调知识体系/训练关键超参 & 显存优化技术/06-显存账本与优化技术.md` 的多模态版）——**在文本账本（权重/梯度/优化器状态/激活值）之上，多模态多了视觉塔与图像 token 的激活值**：

**视觉塔权重**：7B VLM 的视觉塔（CLIP 类 ~300-400M 参数）——全量微调时也占显存（梯度 + 优化器状态）——**LoRA 冻塔的显存红利**（视觉塔只前向——省视觉塔的梯度与状态）；**图像 token 激活值**：图像进语言塔的 token 数百到上千（`多模态/多模态常见问题与缺陷/07-上下文与工程缺陷.md` 的 token 账本）——**图像 token 的激活值显存 = 文本 token 的数倍**（每 token 的激活成本——`大模型微调知识体系/基础概念/03-Transformer与参数基础.md` 的激活值论述）——**"多模态的显存瓶颈常在图像 token 的激活值"**（batch 里图越多，激活值越大）。

**省显存组合**（多模态版）：QLoRA（语言塔 4bit——**视觉塔量化注意**（03 篇 05 节——视觉塔精度敏感，量化用更高位宽或保持 bf16））+ 梯度检查点（图像 token 激活值是检查点的最大受益者）+ 模态长度分组（图像样本独立 batch 控制激活值峰值）+ 降 batch。

## 2. 训练时间与吞吐

多模态微调的训练时间（`大模型微调知识体系/训练关键超参 & 显存优化技术/09-训练性能优化.md` 的多模态版）：**图像 token 的吞吐成本**（图像 token 的 prefill 计算量大——"1 个图像 token ≈ 数个文本 token 的计算成本"——`多模态/多模态常见问题与缺陷/07-上下文与工程缺陷.md` 01 节）——**多模态训练吞吐 = 文本吞吐的 1/2-1/4**（同样 batch 下）。

**时间估算**：66.5 万指令样本的 LLaVA SFT 阶段 ≈ 8×A100 数小时（参考：对齐阶段 12-20 小时）；**QLoRA 单卡**（7B 级 VLM——`大模型微调知识体系/完整微调工程流程/04-环境搭建与工具链选型.md` 的硬件参考）——**预算公式同文本**（总 token ÷ 吞吐 + 余量——图像 token 按加权计算）。

## 3. 训练配置的落地

多模态训练配置的落地要点（04 篇配方的工程化）：**模态长度分组采样**——LLaVATrainer 的实现（图像/文本样本分 batch）——训练器的自定义（`大模型微调知识体系/完整微调工程流程/06-训练配置与启动.md` 的 Trainer 配置多模态版——
分组采样的 DataCollator 自定义）；**投影层独立 lr**（mm_projector_lr——四组优化器参数——`大模型微调知识体系/完整微调工程流程/06-训练配置与启动.md` 的 optimizer 参数分组）。

**数据加载**（`多模态/多模态数据集/07-数据格式与处理.md` 05 节的 WebDataset 流式——图像按 ID 加载 + 预处理（分辨率/裁剪——训练与推理一致，`多模态/多模态数据集/07-数据格式与处理.md` 01 节）——**图像加载是 dataloader 瓶颈**（`大模型微调知识体系/训练关键超参 & 显存优化技术/09-训练性能优化.md` 的 worker 方法论多模态版）。

## 4. vLLM 多 LoRA：四组件服务

**vLLM 的 LoRA 服务扩展**（2026）：`--enable-tower-connector-lora`（Llama 4 Vision 类）——**四组件同时 LoRA 服务**（塔/连接器 MLP/投影/语言塔——03 篇）——**多 LoRA 服务（`大模型微调知识体系/PEFT 参数高效微调（面试高频）/08-PEFT生产实践.md`）的多模态版**：一个底座 + 多个多模态适配器（各适配器含四组件的 LoRA 权重——`modules_to_save` 约束同样适用（投影层全秩张量要 null——`大模型微调知识体系/完整微调工程流程/09-导出部署与上线运维.md` 01 节的硬约束）。

**多模态多 LoRA 的注意**：适配器体积（四组件的 LoRA 比纯语言塔大——投影层若全秩训练则不能多 LoRA）；**底座版本一致性**（`大模型微调知识体系/PEFT 参数高效微调（面试高频）/08-PEFT生产实践.md` 03 节——视觉塔/投影层版本绑定——"换视觉塔 = 适配器重验证"）。

## 5. 部署与推理

多模态微调模型的部署（`多模态/推理部署工程/` 体系——此处给微调相关）：**合并部署**（语言塔 LoRA 合并 + 投影层合并——**投影层也要合并**（非 LoRA 的投影层权重随模型保存——SafeMLLM 的 non_lora_trainables.bin 在部署时要一起加载）——
"合并 = 语言塔 LoRA + 投影层全量"的完整模型）；**量化部署**（`多模态/多模态常见问题与缺陷/08-量化与部署问题.md` 的量化损伤——**视觉塔量化对感知的影响**（`多模态/多模态常见问题与缺陷/04-OCR与文档理解缺陷.md` 的感知边界——量化放大——视觉塔部署时保持更高位宽）；**推理配置**（图像输入格式/分辨率——训练推理一致性——`多模态/多模态数据集/07-数据格式与处理.md` 01 节）。

## 6. 工程验收清单

多模态微调上线的工程检查：**显存预算**（图像 token 激活值计入——batch 规划）；**吞吐达标**（图像 token 加权——排期准确）；**训练推理一致**（图像预处理/帧采样/模板三一致——
`多模态/多模态数据集/07-数据格式与处理.md` 的验收）；**合并完整**（语言塔 LoRA + 投影层——non_lora_trainables 一起）；**多 LoRA 兼容**（四组件适配器的 modules_to_save 检查）；**评估走服务路径**（`大模型微调知识体系/完整微调工程流程/08-模型评估与验收.md` 03 节——多模态版：图像输入的服务路径评估）——**六项全过才上线**（与文本微调的验收纪律同构，多模态版）。

> 🎯 **核心要点**：显存账本——多模态多视觉塔权重与图像 token 激活值（瓶颈常在图像 token 激活值——QLoRA 注意视觉塔量化精度 + 梯度检查点最大受益者是图像激活 + 模态分组控峰值）；吞吐——图像 token 计算成本数倍于文本（多模态吞吐 1/2-1/4）；配置落地——模态长度分组采样（DataCollator 自定义）+ 投影层独立 lr（四组优化器参数）；vLLM 四组件 LoRA（tower-connector——多 LoRA 服务多模态版——投影层全秩的 modules_to_save 约束）；部署——合并要含投影层（non_lora_trainables）+ 视觉塔量化敏感；验收六查（显存/吞吐/三一致/合并完整/多 LoRA 兼容/服务路径评估）。
