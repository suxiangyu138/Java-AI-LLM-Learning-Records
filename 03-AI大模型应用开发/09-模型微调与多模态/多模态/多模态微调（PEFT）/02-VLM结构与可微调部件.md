# VLM 结构与可微调部件

> 多模态微调的地基：三组件（视觉塔/投影层/语言塔）的结构与职责、冻结策略（默认冻视觉塔的两个理由）、LoRA 目标模块的多模态版——"先懂结构，再谈微调哪里"

## 1. 三组件结构与职责

现代 VLM（LLaVA 类）的三组件（架构细节在 `多模态/LLaVA 类多模态大模型核心架构（面试必背）/` 体系，此处给微调视角）：

**视觉塔（Vision Tower/Encoder）**：图像编码器（CLIP/SigLIP/Swin-B/Pixtral encoder 类）——把像素变成视觉特征（patch 级）——**负责"看见"**（感知能力——`多模态/多模态常见问题与缺陷/02-视觉感知缺陷.md` 的感知边界与视觉塔直接相关）；参数占比高（87.7M 级，7B 模型的 ~1%）。

**投影层（Projector/Connector）**：桥接视觉特征与语言模型的嵌入空间（MLP 类，~20M 参数）——**负责"对齐"**（把视觉特征的"语言"翻译成语言塔懂的"语言"——`多模态/多模态数据集/01-多模态数据集全景与定位.md` 的对齐概念在结构上的载体）；LLaVA 原始配方里投影层是两阶段的"主角"（04 篇）。

**语言塔（Language Model）**：transformer 解码器堆栈（LLaMA/Qwen 类）——负责"理解与生成"——**行为校准的主战场**（格式/风格/指令遵循）。

**三组件的参数占比与微调成本**：语言塔占绝对大头（7B 模型 ~95%+）、视觉塔 ~1%（300-400M 级）、投影层 ~0.3%（~20M）——**微调成本的分配**：全量微调三组件都算梯度（成本按参数占比分配）；LoRA 冻塔时**视觉塔只前向**（省视觉塔的梯度与优化器状态——`多模态/多模态微调（PEFT）/08-多模态微调工程实践.md` 的显存账本）——**"冻塔省的不只是参数，是视觉塔的梯度与状态"**——LoRA 在 VLM 上的显存红利比文本模型更显著（多冻了一个组件）。

**微调视角的组件职责**：**视觉塔管感知、投影层管对齐、语言塔管行为**——"微调哪里" = "校准哪层能力"——任务缺感知 → 塔；缺对齐 → 投影层；缺行为 → 语言塔（01 篇的决策框架在此细化）。

## 2. 默认冻结策略：冻视觉塔

**2026 默认：视觉塔冻结 + LoRA 语言塔（+ 投影层可训）**——冻结视觉塔的两个理由（The Neural Base 明确）：

**理由一：浪费适配器**——把 LoRA 用在冻结的 CLIP 编码器上，"把适配器浪费在上游不会更新的特征上"——视觉塔特征不会因为塔 LoRA 而改变（上游不变，下游白改）；**理由二：破坏对齐**——微调视觉塔"破坏视觉-语言对齐"且"引入训练不稳定"——视觉塔是对齐模型（CLIP 类），它的特征空间是语言塔训练的基础——**动视觉塔 = 动对齐的基础**（`多模态/多模态常见问题与缺陷/06-跨模态对齐与语言先验.md` 的对齐脆弱性在训练侧的体现）。

**投影层的处理**：**"总是可训练"**（SafeMLLM 类实践：投影层权重单独保存 non_lora_trainables.bin）——投影层是"对齐的微调旋钮"（任务相关的对齐校准）——**默认可训、需要保对齐时冻结**（03 篇的塔/连接器 LoRA 讨论）。

**可训练参数验证**：LoRA 语言塔后**确认可训练参数占比 0.1-0.5%**（教程明确要求）——占比异常 = 目标模块配错（视觉塔被误加进去）。

## 3. LoRA 目标模块（多模态版）

VLM 的 LoRA 目标模块选择（`大模型微调知识体系/PEFT 参数高效微调（面试高频）/04-LoRA配置工程.md` 的多模态版）：

**语言塔内**（默认）：注意力投影 `q_proj/k_proj/v_proj/o_proj` + 可选 MLP（`gate_proj/up_proj/down_proj`——Llama 类；`fc1/fc2` 其他类）——**与文本微调相同的模块选择**；**投影层**（默认可训——全参数训练或 LoRA——`mm_projector_lr` 独立学习率，04 篇）；**视觉塔**（默认不训——目标模块里**不要**出现 `vision_encoder.attention.*` 类——教程明确警告）。

**r/alpha 的多模态参考**：通用指令微调 r=8/α=16（7B 模型约 5000 万参数）；专门领域（医学/OCR/大语料）r=16-32——**与文本微调的 r 经验同构**（`大模型微调知识体系/PEFT 参数高效微调（面试高频）/04-LoRA配置工程.md` 01 节）。

**目标模块的"多模态检查"**：配完 LoRA 后跑两个检查——**参数占比**（0.1-0.6%——视觉塔被误配的第一信号）；**组件清单**（打印目标模块清单确认"只有语言塔模块"（默认）——`q_proj` 等出现在视觉塔路径（`vision_encoder.*`）即误配——**"目标模块的可视化检查"是 VLM LoRA 配置的必做项**（文本微调没有这个坑——多模态专属的配置检查）。

## 4. 冻结策略的消融依据

冻结策略的选择有量化依据（LLaVA-1.6 Mistral-7B，MM-Bench 消融，00 篇速查表）：

| 配置 | 可训练参数 | 准确率 | 解读 |
|------|:---:|:---:|------|
| 全冻 + 只训投影 | ~7M | 38.2 | 投影层容量不够——行为校准必须在语言塔 |
| 冻视觉塔 + LoRA 语言塔 | 64M | 56.8 | **性价比最优（默认）** |
| 视觉塔放开 + LoRA 语言塔 | 124M | 58.4 | +1.6 点但参数翻倍——值得吗？按任务 |
| 全量微调 | 7.5B | 60.1 | 上限但成本/风险最高 |

**读法**：**LoRA 语言塔是性价比拐点**（56.8 vs 全量 60.1——3.3 点差距）；**放开视觉塔的 +1.6 点**是"视觉能力收益"的量化（领域视觉任务可能值、通用任务不值——按任务定）；**只训投影层远弱于 LoRA**（38.2——"投影层不是行为校准的旋钮"）。

## 5. 组件微调的决策清单

组件选择的标准流程：**1) 任务类型定位**（行为校准 → 语言塔；领域视觉 → 考虑塔；对齐敏感 → 保投影层冻结）；**2) 数据量**（<1M 冻语言塔（教程建议）——小数据全量语言塔会过拟合）；
**3) 融合保护评估**（微调后跑"融合能力回测"——图像描述质量与底座逐位对比（`06-多模态微调的常见问题.md` 的融合回测）——**"每轮微调都要问：视觉-语言融合被破坏了吗"**）；**4) 可训练参数验证**（0.1-0.6%——组件配错的第一信号）。

> 🎯 **核心要点**：三组件职责——视觉塔管感知/投影层管对齐/语言塔管行为——"微调哪里 = 校准哪层能力"；默认冻结策略——冻视觉塔 + LoRA 语言塔（+ 投影层可训）——两个理由（浪费适配器/破坏对齐——视觉塔是语言塔训练的对齐基础）；可训练参数验证 0.1-0.5%（目标模块配错的第一信号——不要出现 vision_encoder 模块）；消融依据——LoRA 语言塔 56.8 是性价比拐点（vs 全量 60.1）、放开视觉塔 +1.6 点按任务定、只训投影层 38.2 最弱（行为校准必须在语言塔）；决策清单——任务定位/数据量/融合保护回测/参数占比四步。
