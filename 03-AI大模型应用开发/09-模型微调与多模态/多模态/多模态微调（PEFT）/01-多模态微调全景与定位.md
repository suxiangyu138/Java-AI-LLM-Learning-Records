# 多模态微调全景与定位

> 多模态微调是什么、与文本微调的根本差异（三组件）、微调类型与决策边界——先判断"该不该微调多模态模型"，再学"怎么微调"

## 1. 什么是多模态微调

**多模态微调**：在预训练的多模态模型（VLM 类——视觉语言模型）上继续训练，使其在特定多模态任务/领域上表现更好——与文本微调（`大模型微调知识体系/`）同构的"迁移学习"逻辑，但**对象从单一语言模型变成"视觉塔 + 投影层 + 语言塔"的三组件系统**。

**与文本微调的根本差异**：文本模型只有一个组件（语言塔）；VLM 有三个组件——**"微调哪里"的选择维度多了一层**：可以只微调语言塔（默认）、加投影层（常见）、甚至微调视觉塔（专门视觉域）——**文本微调的"r/alpha/lr"问题，多模态微调还要加上"哪个组件"的问题**——这是本体系与文本微调体系的根本分工。

**多模态微调解决的场景**：**视觉指令遵循**（让模型按指令看图回答——LLaVA 类）；**文档理解**（OCR/版面/表格——`多模态/多模态 RAG/` 的生成侧）；**领域视觉**（医学影像/显微镜/遥感）；**音频/视频理解**；**具身（VLA）**——**"行为校准"与文本微调同构（`大模型微调知识体系/边界判断（非常关键，面试必问）/` 的知识 vs 行为诊断同样适用：知识缺口归 RAG、行为缺口才微调）**。

**多模态微调的"双保险"属性**：微调前先确认两件事——**RAG 试过没有**（知识类需求先检索——`多模态/多模态 RAG/` 的决策门槛）；**Prompt 试过没有**（多模态提示的零成本方案——"图 + 文本指令"能解决的行为先试）——**"多模态微调是 RAG 与 Prompt 之后的第三选项"**（与文本微调同构，`大模型微调知识体系/边界判断（非常关键，面试必问）/01-微调决策全景与判断框架.md` 的决策顺序多模态版）。

## 2. 微调类型

多模态微调的类型谱系（与文本微调同构，多模态版）：

**全量微调**：三组件全训（7.5B 参数级）——上限最高（消融 60.1）、成本最高、破坏融合风险最大——数据 50k+ 或极致质量时考虑；**PEFT（LoRA/QLoRA）**：冻视觉塔 + LoRA 语言塔（默认，0.1-0.6%）——消融 56.8（距全量 3 个点）、成本低一个量级——**1k-50k 数据的默认**；**只训投影层**：全冻 + 只训投影（~7M 参数）——消融 38.2（最弱——投影层太小，容量不够）——**只做"对齐校准"或极小数据时的兜底**。

**消融的启示**（LLaVA-1.6，MM-Bench）：**LoRA 语言塔（56.8）vs 全量（60.1）只差 3.3 个点**——PEFT 在 VLM 上的性价比同样惊人（与文本微调 98% 实证同构）；**只训投影层（38.2）远低于 LoRA**——"投影层不是万能旋钮，行为校准必须在语言塔上做"。

## 3. 决策边界：该不该微调多模态模型

与文本微调同构的决策框架（`大模型微调知识体系/边界判断（非常关键，面试必问）/` 的多模态版）：

**先试不改权重的方案**：**Prompt 工程**（多模态提示——图 + 文本指令——能解决的行为先试）；**多模态 RAG**（`多模态/多模态 RAG/`——知识类需求（文档事实/图库检索）优先 RAG——"RAG 管知识、微调管行为"的边界在多模态同样成立）；**上下文工程**（多图/长上下文能塞下的先塞）。

**再判断微调的必要性**：**行为缺口**（格式/风格/领域术语）→ 微调；**知识缺口**（事实/时效/私有数据）→ RAG（微调注入知识同样增加幻觉——`多模态/多模态常见问题与缺陷/03-视觉幻觉.md` 的缺陷在多模态微调中被数据放大——训练数据含幻觉 → 模型学幻觉，`多模态/多模态数据集/03-多模态指令数据.md` 的幻觉污染）。

**多模态特有的决策因素**：**视觉能力依赖**（任务依赖细粒度视觉（医学影像/小物体）→ 微调可能需要塔 LoRA——`多模态/多模态常见问题与缺陷/02-视觉感知缺陷.md` 的感知边界——**"底座看不见的，微调也教不会"**（视觉塔的感知上限是硬边界——除非塔 LoRA 或换底座）；**融合保护**（微调会破坏视觉-语言融合——`06-多模态微调的常见问题.md`——"保护融合的成本"要计入决策）。

## 4. 微调 vs RAG 的边界（多模态版）

2026 生产共识（与 `多模态/多模态 RAG/01-多模态RAG全景与定位.md` 的决策门槛对应）：

| 需求 | 方案 |
|------|------|
| 文档事实查询（"合同第 3 页的条款"） | 多模态 RAG（检索证据） |
| 图表趋势问答（"图 3 的趋势"） | RAG + VLM 生成（检索到图再理解） |
| 视觉行为校准（"按公司格式描述图片"） | 微调（行为固化） |
| 领域视觉能力（"显微镜下的细胞分类"） | 微调（塔 LoRA——感知能力补） |
| 两者混合 | RAG 管知识 + 微调管行为 |

**判断口诀**："**要可溯源的知识 → RAG；要稳定的行为 → 微调；要新的视觉能力 → 塔 LoRA 或换底座**"——微调是最后手段（与文本微调同构，`大模型微调知识体系/边界判断（非常关键，面试必问）/01-微调决策全景与判断框架.md`）。

## 5. 2026 生态快照

多模态微调的工具链已成熟（`大模型微调知识体系/完整微调工程流程/04-环境搭建与工具链选型.md` 的多模态版）：**框架**（LLaVA 类训练脚本/TRL 的 VLM 支持/各家训练库）；**vLLM 服务**（多 LoRA 支持扩展到塔/连接器——
`03-LoRA在多模态上的应用.md` 08 篇）；**数据**（多模态数据集体系）；**评估**（MM-Bench/POPE 类基准，09 篇）——**2026 年做多模态微调是"配方组装"而非"从零开发"**（与 `多模态/多模态 RAG/08-多模态RAG工程实现.md` 的"组装而非造轮子"同构）。

> 🎯 **核心要点**：多模态微调 = 在 VLM（三组件系统）上继续训练——与文本微调的根本差异是"微调哪里"多了一层（视觉塔/投影层/语言塔）；类型谱系——全量（60.1 消融上限）/PEFT 默认（56.8，差 3.3 点）/只训投影（38.2 最弱——行为校准必须在语言塔）；决策边界——知识归 RAG、行为才微调、视觉能力依赖塔 LoRA 或换底座（"底座看不见的微调教不会"）、融合保护成本计入决策；口诀——"要可溯源的知识 → RAG；要稳定的行为 → 微调；要新的视觉能力 → 塔 LoRA 或换底座"；2026 工具链成熟——配方组装而非从零开发。
