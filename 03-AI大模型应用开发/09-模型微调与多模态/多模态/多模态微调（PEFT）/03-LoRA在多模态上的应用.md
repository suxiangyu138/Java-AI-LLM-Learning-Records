# LoRA 在多模态上的应用

> LoRA 的 VLM 特殊用法：LM-only LoRA 默认（0.1-0.6%）、2026 两个新趋势（层选择性 LoRA 保护融合、塔/连接器 LoRA 适配视觉域）、何时训视觉塔——"通用 LoRA 原理 + 多模态组件选择"

## 1. LM-only LoRA：默认配方

**2026 默认**：LoRA 只作用于**语言塔**（注意力 + MLP 投影），视觉塔与投影层冻结——可训练参数 **0.1-0.6%**：

**实践案例**：FrndoBrain-1.0.1-24B（2026）——QLoRA 微调 Mistral 3.2 24B Instruct，**只适配语言塔的注意力与 MLP 权重**，Pixtral 视觉编码器与多模态投影层冻结（0.38% 可训练）；code-trainer-vision-adapter——冻 Swin-B 视觉塔（87.7M）→ 训 MLP 投影层（2.1M）→ Qwen2.5-Coder-1.5B 上 LoRA（r=16/α=32）——**"塔冻、投影训、塔上 LoRA"的标准三段**。

**与文本 LoRA 的差异**：LoRA 原理完全一样（`大模型微调知识体系/PEFT 参数高效微调（面试高频）/02-LoRA原理深潜.md`）——差异在**目标模块的作用域**（语言塔内）+ **组件间的冻结搭配**——**"LoRA 是同一把工具，多模态给了它更多的挂载点"**。

**LoRA 与视觉塔的关系**：视觉塔冻结时，**LoRA 仍然"间接影响"视觉处理**——语言塔的 LoRA 改变视觉特征在语言塔里的解释方式（`多模态/多模态常见问题与缺陷/06-跨模态对齐与语言先验.md` 的对齐——语言塔是视觉特征的"消费者"）——**"冻塔不是不动视觉，是不动视觉的编码"**——视觉特征不变、解释变化——这正是"冻塔 + 语言塔 LoRA"能改善视觉任务（如图文问答）的机制：**任务行为（怎么用视觉特征）改了，视觉编码（看到什么）没改**——理解这一点，组件选择就有了机制基础。

## 2. 趋势一：层选择性 LoRA（保护融合）

**层选择性 LoRA（2026 新兴）**：只微调语言塔的**上半层堆栈**、冻结下半层——**gemma4-31B 实证**（autotrust，2026）：编码微调只对语言塔 30-59 层（上半）加 LoRA、0-29 层冻结（"多模态融合/视觉特征处理不动"）、视觉编码器（mmproj）全冻——**理由**："大多数多模态模型的编码微调会破坏预训练学到的视觉-语言融合"——**结果**：图像描述质量与底座逐位一致（融合零破坏）、编码 pass@1 **+15.9 点**、仅 0.20% 参数可训练（61.2M/31.27B）。

**机制**：视觉-语言融合主要发生在**下半层**（视觉特征注入语言塔的早期层）——下半层冻结 = 融合路径不动；上半层微调 = 行为校准——**"融合在下、行为在上"的分层认知**——与 `大模型微调知识体系/基础概念/03-Transformer与参数基础.md` 的"顶层敏感"论述呼应（多模态版：**语言塔的层间分工**——下层保融合、上层改行为）。

**工程含义**：**编码/知识密集类微调（代码/数学/工具）优先考虑层选择性 LoRA**（融合破坏风险高的任务类型）；LoRA 目标模块正则用 `language_model.layers.{30..59}.(self_attn|mlp).(q_proj|...)` 类模式。

## 3. 趋势二：塔/连接器 LoRA（适配视觉域）

**塔/连接器 LoRA（2026 新兴）**：LoRA 扩展到**视觉塔与连接器**——vLLM PR #35147（Llama 4 Vision）：新增 `--enable-tower-connector-lora`——四组模块都可 LoRA：**塔**（视觉编码器注意力 `vision_model.model.layers.*.self_attn`）、**连接器 MLP**（`vision_adapter.mlp` 的 fc1/fc2）、**多模态投影**（`multi_modal_projector` 的 linear_1）、**语言塔**——**基础设施（vLLM 服务）已支持四组件同时 LoRA**（`08-多模态微调工程实践.md` 的部署）。

**何时训视觉塔**（2026 判据）：**专门视觉域**——MicroLens 实证（Gemma 4 E2B，2026）：**视觉塔与语言塔同时可训**（r=16/α=32，0.58% 可训练），显微镜识别取得强领域准确率——**"通用任务冻塔、专门视觉域训塔"**——领域视觉任务（医学影像/显微镜/遥感/视觉提示定位）的感知需求超出通用视觉塔能力（`多模态/多模态常见问题与缺陷/02-视觉感知缺陷.md` 的感知边界——**塔 LoRA 是"补感知"的手段**）。

**代价与风险**：训塔的代价——参数翻倍（消融 64M → 124M）、对齐风险（02 篇的理由二——"动视觉塔 = 动对齐基础"）——**训塔前必须评估"任务是否需要新感知能力"**（先测底座在任务上的感知表现——底座能看清就不训塔——`多模态/多模态常见问题与缺陷/01-问题全景与诊断方法论.md` 的感知验证）。

**塔 LoRA 的"补感知"边界**：塔 LoRA 能补的感知是"**适配**"而非"**创造**"——视觉塔的 patch 粒度/编码结构是硬边界（`多模态/多模态常见问题与缺陷/02-视觉感知缺陷.md` 的小物体 <32px 是编码器结构决定）——**塔 LoRA 可以让塔"更懂领域特征"，但不能让塔"看见结构上看不见的东西"**——感知需求超出编码器结构时（极细粒度/超小物体），换更高分辨率编码器/换底座是更有效的方案——**"塔 LoRA 是校准不是魔法"**。

## 4. 组合矩阵：四组件的 LoRA 状态

| 组件 | 默认 | 变体 A（层选择性） | 变体 B（塔 LoRA） |
|------|------|------|------|
| 视觉塔 | 冻结 | 冻结 | **LoRA**（专门视觉域） |
| 连接器/投影 | 可训（全参数或 LoRA） | 冻结 | LoRA |
| 语言塔下半层 | LoRA | **冻结**（保融合） | LoRA |
| 语言塔上半层 | LoRA | **LoRA** | LoRA |

**选择逻辑**：通用行为校准 → 默认；编码/知识密集 → 层选择性（保融合）；专门视觉域 → 塔 LoRA（补感知）——**"按任务的感知与融合需求选组合"**。

## 5. LoRA 配置的多模态要点

**r/α**：通用 r=8/α=16、领域 r=16-32（`大模型微调知识体系/PEFT 参数高效微调（面试高频）/04-LoRA配置工程.md` 01 节）；**α 与 lr 的耦合**（多模态的 lr 配方——04 篇的 1e-3/2e-5——**α 缩放与阶段 lr 的关系要一起调**）；**QLoRA**（4bit 量化底座 + LoRA——`大模型微调知识体系/PEFT 参数高效微调（面试高频）/06-QLoRA深潜.md`——**VLM 的 QLoRA 注意：视觉塔的量化**（视觉塔也 4bit 时感知精度损失——`多模态/多模态常见问题与缺陷/02-视觉感知缺陷.md` 的感知边界被量化放大——**视觉塔精度敏感时保持更高位宽**——工程细节在 08 篇）。

## 6. 2026 实践总结

LoRA 在多模态的 2026 共识：**默认 LM-only（0.1-0.6%）**；两个新方向按任务选——**层选择性（保融合）与塔 LoRA（补感知）**；基础设施已就绪（vLLM 四组件 LoRA 支持）；**"LoRA 的通用原理不变，变的是挂载点的选择"**——面试答"多模态 LoRA"先讲通用原理（低秩/intrinsic dim）再讲组件选择（默认/趋势/判据）——结构是"原理 + 挂载"两层。

> 🎯 **核心要点**：默认 LM-only LoRA（0.1-0.6%，塔冻投影训塔上 LoRA 三段）；趋势一——层选择性 LoRA（下半层冻结保融合/上半层微调改行为——gemma4-31B 实证：图像描述逐位一致 + 编码 pass@1 +15.9、0.20% 参数）——"融合在下、行为在上"；趋势二——塔/连接器 LoRA（vLLM 四组件支持——专门视觉域才训塔：MicroLens 显微镜实证 0.58%——"通用任务冻塔、专门视觉域训塔"）；组合矩阵按任务选（默认/层选择性/塔 LoRA）；配置要点——r 通用 8 领域 16-32、QLoRA 注意视觉塔量化精度；一句话——"LoRA 原理不变，变的是挂载点"——答案结构 = 通用原理 + 组件选择。
