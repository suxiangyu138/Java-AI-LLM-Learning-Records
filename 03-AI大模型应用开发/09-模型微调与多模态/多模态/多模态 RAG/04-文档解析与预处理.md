# 文档解析与预处理

> 多模态 RAG 的"摄入第一关"：PDF 解析、OCR、版面分析、表格/图表提取、坐标保留——解析质量决定检索上限，"丢失的信息检索不到"

## 1. 解析的目标与分层

多模态 RAG 的摄入不是"把 PDF 变成文本"，而是**保留文档的结构信息**——解析管线按"信息保真度"分层：

**文本层**：可提取文本（原生 PDF 文本/OCR 结果）——给文本检索与抽取用。
**布局层**：版面分析（标题/段落/图表/表格的区域与坐标）——给"定位"用（ColPali 找到页面后，靠坐标定位答案区域）。
**结构层**：表格结构（行列/合并单元格）、图表类型（柱状/折线/饼图）、阅读顺序——给"理解"用（图表进 VLM、表格保持结构）。

**核心原则**：**解析是"为检索服务"的**——文本层给文本通道、布局层给定位、结构层给理解通道——**"扁平化文本"（解析成一大段文字）是信息损失最大的一步**（图表丢失、布局丢失、阅读顺序错乱——OCR 管线的三大失败，01 篇）。

**解析与 ColPali 的关系澄清**：ColPali 直接索引页面像素（03 篇）**不意味着解析不再需要**——解析从"检索入口"降级为"抽取与定位工具"：ColPali 找到页面后，需要解析层从页面里抽文本/表格/图表（带坐标）——**"像素负责检索、解析负责抽取"是 2026 的组合姿势**；纯文本页仍走解析索引（成本比视觉索引低一个数量级，08 篇选择性视觉化）——**解析的地位从"唯一入口"变成"分层工具"**。

## 2. PDF 解析与 OCR

**原生 PDF vs 扫描件**：原生 PDF 有文本层（可直接提取，用 PyMuPDF/pdfplumber 类）；扫描件只有像素（必须 OCR）。**混合文档**（部分原生部分扫描）需要按页判断（有文本层用文本、无则 OCR）。

**OCR 选型**：PaddleOCR（中文强、开源）、Tesseract（经典）、云 OCR（文档质量差时）——**OCR 的精度瓶颈在版面而非字符**（字符识别率 99% 但版面重构错误率远高）——OCR 输出必须带**坐标框**（bbox），后续定位与结构重建依赖坐标。

**OCR 的已知失败**：图表（识别成乱码文本）、视觉分组（框线/配色信息丢失）、合并单元格（结构错乱）、阅读顺序（多栏页面串行）——**OCR 文本是"尽力而为的代理"，不是文档本身**——这正是 ColPali"直接看像素"的价值（03 篇）——**OCR 与 ColPali 的分工：ColPali 检索页面、OCR 从页面抽文本**（05 篇）。

## 3. 版面分析（Layout Analysis）

**版面分析**：识别页面的语义区域（标题/正文/图表/表格/页眉页脚）及其坐标——工具：LayoutLM 类模型、Docling（IBM 开源，版面+结构一体）、MMORE（2026 开源管线，15+ 文件类型，速度与版面保真度超 Docling）。

**为什么坐标关键**：ColPali 检索返回"页面级"命中——**页面太大，答案在页面的某个区域**——需要坐标把"候选页面"收窄到"答案区域"（05 篇证据图的 region 概念）——**"页面级命中 + 区域级定位"是文档 RAG 的二级漏斗**（先检页面、再定区域——2026 共识：页面级命中常常太粗，必须保留坐标）。

**阅读顺序**：多栏/复杂排版的正确阅读顺序重建——解析器的隐藏难点（顺序错 = 上下文错乱 = 检索到"读不通"的块）。

## 4. 表格与图表提取

**表格**（06 篇详述）：规则工具（Tabula/Camelot——快但复杂布局脆）vs 模型（Table Transformer DETR——图像里检测表格边界与单元格结构）vs 一体化（Unstructured.io 启发式+ML；PaddleOCR 文本 + TableBank 结构，转 Markdown 保留结构）——**表格的验收标准：Markdown 转换后结构无损**（行列/合并单元格/表头）。

**图表**（06 篇详述）：**按类型差异化提取**——柱状/折线/饼图 → VLM 描述 + 数据表提取；流程图 → VLM 结构化提取（节点+边）；架构图 → VLM 描述 + 实体提取；散点图 → 趋势描述 + 原始数据——**图表提取的目标是"双表示"**（文本描述 + 原图嵌入，双通道可检索）。

## 5. 解析管线工程化

**MMORE 类管线形态**（2026 开源标准）：输入 15+ 文件类型（PDF/表格/图片/音频/视频）→ 类型分流 → 解析（文本/版面/结构三层）→ 统一中间格式（含坐标与元数据）→ 下游索引——**管线可复现**（parser 版本进元数据——"这页是谁解析的、什么版本"可审计，05 篇证据图）。

**解析质量检查**：抽样人工看三类输出——文本层（错字率/丢字率）、版面层（区域框准不准）、结构层（表格 Markdown 无损？图表类型识别对？）——**"解析完不检查 = 没解析"**（与 `../大模型微调知识体系/数据集体系（非常重要）/04-数据清洗.md` 的验收纪律同构）；**增量解析**（文档更新只重解析变更页——大库的常态需求）。

**解析器选型的权衡**：规则工具（Tabula 类——快、免费、复杂布局脆）vs 模型（Table Transformer 类——准、需要 GPU）vs 商业/云解析（贵、省运维、文档类型覆盖广）——**选型判据**：文档复杂度（简单表格规则工具够、复杂版面上模型）、文档量（小库规则工具、大库模型/云）、预算——**"先跑 100 页样本对比"**（各工具在同一样本上的结构无损率——抽样验收，选型不靠文档宣传）。

## 6. 解析与检索的配合

**解析 → 检索的"保真度链"**：解析保留的信息 → 索引的内容 → 检索能命中的内容——**每层损失都不可逆**（文本层丢了图表 → 文本检索永远命中不了图表内容；坐标丢了 → 区域定位失效）——**"解析质量决定检索上限"是摄入环节的第一原则**；2026 的组合姿势：**ColPali 直接索引页面像素（绕开解析损失）+ OCR/解析负责"命中后的抽取"**——检索用保真度最高的形态（像素）、抽取用结构化最好的形态（解析）——两个环节各用最优工具。

> 🎯 **核心要点**：解析分层——文本层（检索/抽取）+ 布局层（坐标定位）+ 结构层（表格/图表理解）——"扁平化文本"是信息损失最大一步；原生 PDF 直接提取、扫描件 OCR（带坐标）、混合文档按页判断；OCR 瓶颈在版面不在字符（图表/合并单元格/阅读顺序三大失败）；版面分析输出语义区域+坐标——"页面级命中 + 区域级定位"二级漏斗；表格/图表按类型差异化提取（双表示目标）；MMORE 类管线（15+ 类型、可复现、parser 版本进元数据）；"解析保真度链"——每层损失不可逆，检索用像素（ColPali）、抽取用解析（OCR）——各用最优工具。
