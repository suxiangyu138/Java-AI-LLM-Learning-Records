# 多模态 RAG 评估与挑战

> 评估的"检索先行"纪律、三类基准（ViDoRe/WebQA/MultiModalQA）、多模态的失败模式——幻觉、跨模态对齐、提示注入安全——评估维度比文本 RAG 多一层"视觉正确性"

## 1. 检索先行：评估的第一纪律

**检索先行（Retrieval-first）**：多模态 RAG 的评估**先评检索、再评生成**——"证据没被召回，再强的 VLM 也答不对"（ACL 2026 与生产实践的一致结论）——**检索质量是地基**（忠实度 <0.80 的检索集，再好的生成模型也救不回来）。

**分层的评估顺序**：**检索层**（召回率/命中率——"证据找到了没有"）→ **生成层**（回答质量——"证据用对了没有"）→ **端到端**（业务指标）——**前一层不过关，后一层的分数没有意义**（检索都没召回，回答"好"是蒙对的）——与 `03-AI大模型应用开发/02-RAG检索增强生成/` 的评估方法论同构，多模态的差异在"检索单元"（页面/图表 vs 文本块）与"生成侧"（VLM vs LLM）。

## 2. 三类基准

**检索基准：ViDoRe（V3）**——视觉文档检索的标准评测（03 篇详述）：BEIR 格式、页面级、非抽取式查询、nDCG@10 + 吞吐——**"检索模型的 MMLU"**——选型/评估的公共裁判；**自己的文档库用 ViDoRe 格式组织本地基准**（corpus/queries/qrels 三件套 + 人工标注相关对——评估集构建的 `../大模型微调知识体系/数据集体系（非常重要）/` 方法论在此复用）。

**QA 基准：WebQA / MultiModalQA**——多模态问答的标准评测（图文混合推理——"图里的信息 + 文里的信息联合回答"）；2026 参考成绩（轻量 MLLM 框架）：WebQA 60.7-83.4（EM/Acc/F1/ER 四指标）、MultiModalQA 69.2-89.6——**多模态 QA 基准测"检索 + 推理"的联合能力**（跨模态证据的组合使用）。

**领域基准**：PubMedQA（生物医学 RAG——MMORE 类管线的评测）、图表专项（趋势/数值/结构三查，06 篇第 5 节）——**按领域与内容类型定制评估集**是生产常态。

## 3. 多模态的失败模式

**模态解耦**：图像/视频与文本的语义空间异构（百度 2026 分析）——**跨模态的"对齐失败"**（文本查询命中不了视觉内容、视觉查询命中不了文本内容）——根源是检索模型的对齐粒度不够（CLIP 类全局对齐 vs 文档的细粒度需求——03 篇 ColPali 的意义）。

**结构化信息丢失**：表格/流程图在转换中被压平（04/06 篇的解析损失）——**"丢失的信息检索不到"**——失败在摄入期、暴露在查询期。

**时间依赖缺失**：视频/长文档的时序信息被忽略（07 篇）——"变化过程"类查询答不了。

**上下文碎片化**：多跳推理的证据分散（图 1 的数值 + 表 2 的对比 + 正文的结论）——**证据冲突**（不同来源数据不一致）与**上下文碎片**（证据拼不齐）——2026 解法：检索-验证-再检索循环、查询改写、证据评分、知识图推理路径（05 篇 Agentic 扩展）。

## 4. 幻觉：多模态的新形态

多模态 RAG 的幻觉比文本多两类：

**视觉幻觉（看图编数）**：VLM 看图表时"报出不存在的数值/趋势"——图表数值类回答的专项风险（06 篇的数值三查）——**缓解**：数值类问题强制"数据表提取"而非"看图直接答"（描述给趋势、数据表给数值——双表示的用途）；**引用来源**（回答带图表引用，可核对）。

**跨模态幻觉（张冠李戴）**：回答引用了错误的图表/页面（检索到了 A 图、回答用了 B 图的内容）——**证据与回答的对应验证**（检索结果的引用追踪——"回答引用的证据是检索返回的证据"）。

**缓解的工程化**：**引用强制**（每个视觉证据带来源标记——图号/页码/坐标）；**数值核验**（数据表提取 vs 图表的自动比对）；**检索先行评估兜底**（检索错误被生成放大——检索层先修，`03-AI大模型应用开发/02-RAG检索增强生成/` 的幻觉方法论的多模态版）。

## 5. 多模态安全：提示注入的新面

**多模态内容都是不可信输入**（ACL 2026 明确）：**文档文本、OCR 输出、图像描述、像素本身都可能藏提示注入**——"把指令写在图里"（视觉提示注入——模型看图时"读到"了注入指令）；OCR 文本注入（扫描件里藏指令）；音频注入（转写文本里藏指令）——**注入面比文本 RAG 多（每个模态都是一个注入通道）**。

**防线**：**权限传播**（证据图元数据的访问控制——05 篇）；**注入检测**（OCR/描述文本过注入过滤器——文本 RAG 的检测方法复用）；**输出隔离**（VLM 输出与系统指令分离——"图里的指令不是系统指令"）；**审计**（证据引用记录——注入来源可追溯）——**多模态安全 = 文本安全的每层 + 每个模态的独立防线**。

## 6. 评估的工程化

**评估集构建**（多模态版）：三类样本——**文本查询→文本证据**（纯文本链路）；**文本查询→视觉证据**（"营收趋势"→图表）；**视觉查询→视觉证据**（"图 3 显示什么"→图表）——**按查询类型分层评估**（单一指标的假象：全库召回 0.9 但视觉查询召回 0.4——分通道看）；**检索与生成的联合评估**（检索召回 + 生成正确——联合矩阵：检索对生成错（引用错）/检索错生成对（蒙对）/双对/双错——四象限定位问题在检索还是生成）。

**2026 提醒**：多模态评估的"成本"更高（VLM 推理贵、视觉证据人工标注难）——**评估集小而精**（每类查询 50-100 条，重点覆盖视觉查询与边界案例）；评估先行（`../大模型微调知识体系/完整微调工程流程/03-评估先行基线建立.md` 的纪律——先建评估再建系统）。

> 🎯 **核心要点**：检索先行是评估第一纪律（证据没召回 VLM 答不对）——分层评估（检索→生成→端到端）；三类基准——ViDoRe（检索，V3）/WebQA-MultiModalQA（QA）/领域定制；多模态失败模式——模态解耦（对齐失败）、结构化丢失（摄入期损失）、时序缺失、上下文碎片与证据冲突（Agentic 解法）；幻觉新形态——看图编数（数值类强制数据表提取）、跨模态张冠李戴（引用追踪）；安全——每个模态都是注入通道（图里藏指令/OCR 注入），权限传播 + 注入检测 + 输出隔离；评估工程化——按查询类型分层 + 检索生成四象限联合矩阵 + 评估集小而精。
