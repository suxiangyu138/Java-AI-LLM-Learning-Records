# ColPali 与后期交互

> 2026 文档 RAG 的核心技术：ColPali 家族怎么工作（不 OCR 直接以页面为检索单元）、ViDoRe 基准（V3）、效率问题与池化解法——"视觉文档检索"从研究到生产

## 1. ColPali 是什么

**ColPali**（ColBERT + PaliGemma，Faysse et al., 2025）是**后期交互视觉文档检索模型**：不 OCR、不转文本，**直接把 PDF 页面图像作为检索单元**——页面进视觉编码器（PaliGemma 类 VLM 的视觉塔），产出 ~700-1024 个 **patch 级嵌入向量**（每个图像 patch 一个 128 维向量）——检索时查询的每个 token 向量与页面的所有 patch 向量做 **MaxSim**（最大相似度求和）——**查询的一个词总能匹配到页面上最相关的视觉区域**（02 篇的多向量原理在此落地）。

**为什么能赢 OCR 管线**：OCR 先把页面转文本（图表/布局/视觉分组丢失），ColPali 直接看页面——**检索的是"像素里有什么"而不是"OCR 认为写了什么"**——布局复杂页面（图表、表格、信息图、多语言）的检索精度显著提升——实测在 ViDoRe 多数文档域超越此前 SOTA。

## 2. ColPali 家族（2026）

| 模型 | 规模 | 说明 |
|------|:---:|------|
| ColPali-v1.3 | 3B | 原版（PaliGemma 3B 底座） |
| ColQwen2.5-v0.2 | 3B | Qwen2-VL 底座 |
| ColSmol-500M | 0.5B | 轻量（单消费卡可跑） |
| ColQwen3.5-4.5B-v3 | 4.5B | 2026 新（128 维、LoRA 微调，ViDoRe V3 排名前列） |
| webAI-ColVec1 / nemotron-colembed-vl | 4B-9B | 2026 新竞争者（ViDoRe V3 前五） |

**家族共性**：都是"视觉 VLM 底座 + 后期交互训练"（LoRA 微调为主）——**底座换新、训练目标不变**；2026 年 4B-9B 模型竞争激烈（ViDoRe V3 leaderboard 前排差距 <2 分）——**选型看 ViDoRe 排名 + 自己的硬件**（500M-3B 单消费卡可跑、4B+ 需要更好硬件，08 篇成本）。

## 3. ViDoRe 基准

**ViDoRe（Visual Document Retrieval）** 是视觉文档检索的标准评测，2026 年迭代到 **V3**（公开 leaderboard）：

- **v2**：页面级基准——真实、非抽取式查询（"2024 年营收增长"而非"查找营收数字"），多种文档类型（ESG 报告/生物医学讲义/经济报告等子集）。
- **V3**：BEIR 格式（corpus/queries/qrels 分离，many-to-many 相关映射，语料级评估）——如 `vidore_v3_finance_en`（~2942 页、1854 查询）。
- **指标**：nDCG@10/Recall@k + 吞吐（QPS）——**质量与效率同时排名**（2026 年 4 月快照：nemotron-colembed-vl-8b 63.42 居首，ColQwen3.5-4.5B 61.46 居第 6 且是 4B 级前三）。

**工程含义**：**ViDoRe 是"视觉文档检索的 MMLU"**——选型/评估/发布新模型的公共裁判；评估自己的文档库时用 ViDoRe 格式组织本地基准（09 篇）。

**ViDoRe 的读榜方法**：看榜三件事——**同规模对比**（4B 级比 4B 级——跨规模比分数没意义，ColQwen3.5-4.5B 是 4B 级前三）；**nDCG 与 QPS 一起看**（质量与效率双指标——"质量略低但吞吐 3 倍"可能是更优生产选择，08 篇成本）；**榜单日期**（V3 排名变化快——选型时看最新快照，本页 4 月数据仅作参考，`03-AI大模型应用开发/` 的时效检索纪律）——**读榜 = 同规模 + 双指标 + 看日期**。

## 4. 效率问题：每页 1000 个向量的规模化挑战

ColPali 的核心短板：**每页 ~700-1024 个 patch 向量**——百万页文档 ≈ 10 亿向量——**存储 8-10 倍于单向量、检索计算量大**（对比：单向量 bi-encoder 每页 1 个 1536 维向量）——规模化瓶颈在向量数量而非模型。

**2026 解法：Visual RAG Toolkit（arXiv 2602.12510）**——**训练无关的静态空间池化**（Matryoshka 嵌入启发）：对 patch 嵌入做滑窗平均池化，产出紧凑的 **tile 级（每页 ~13-32 向量）与全局（单向量）表示**——每页同时存三种"命名向量"（完整多向量/平均池化/全局池化）——**多阶段检索**：先用池化向量预取 Top-K（MaxSim），再用完整 patch 向量精确重排（Qdrant 的 prefetch+query API 服务端执行）；三级级联再加全局池化预取。

**实测**：存储从"每页千级向量"降到"数十级"（向量对比二次方减少）、**吞吐提升 ~4 倍（QPS）**、ViDoRe v2 的 NDCG/Recall 损失极小（主要在大 k 时敏感）——**无需再训练/适配器/蒸馏**，ColSmol-500M/ColPali-v1.3/ColQwen2.5 单消费卡或 Apple Silicon 可跑——**"视觉文档检索规模化"从数据中心门槛降到个人笔记本**。

## 5. ColPali 的适用边界

**适合**：布局复杂文档（法律/医疗/金融——图表表格多、版面信息关键）、多语言文档（不依赖 OCR 语言模型）、扫描件（直接看像素）；**不适合**：自然图像库（语义检索 CLIP 更好——ColPali 是"文档检索"不是"图像检索"）、纯文本（标准 RAG 更快更便宜）、需要逐字抽取的场景（检索后仍需 OCR/解析补抽取，04 篇）。

**ColPali 的多语言与跨域能力**：视觉检索不依赖 OCR 语言模型——**换语言/换领域不用重新训练 OCR 或词典**（页面像素是"语言无关"的）——多语言文档库（中英日混排）、垂直领域（法律/医疗术语）是 ColPali 的天然优势场景；**局限**：手写体/低质量扫描件的像素质量决定检索质量（像素太差，任何视觉模型都难）——**"像素质量是视觉检索的地基"**（与 OCR 的扫描质量约束同构）。

**混合姿势**：生产系统里 ColPali 与 OCR 并存——**ColPali 负责"找到对的页面"，OCR/解析负责"从页面里抽取答案"**（05 篇的检索-解析分工）——检索与抽取是两件事，别用一个模型全包。

**ColPali 的查询形态**：查询在检索时也要过视觉编码器（查询文本渲染成图像或直接文本-视觉联合编码）——**查询编码是轻量的**（一个查询几个 token 向量，在线计算毫秒级）；**查询改写对 ColPali 的意义**：与文本 RAG 一样，查询改写（`03-AI大模型应用开发/02-RAG检索增强生成/` 的查询改写方法论）对视觉检索同样有效——"2024 营收"改写成"2024 年营收增长趋势"后视觉匹配更好——**检索前处理（查询改写/扩展）是视觉检索的隐藏杠杆**。

## 6. 2026 前沿

**Argus-Retriever**（2026）：视觉 LLM 后期交互 + 区域感知查询条件 MoE——在 ViDoRe ColPali 与 VDR 多语言数据上训练——"区域感知"让 patch 匹配更精细（查询匹配到页面的语义区域而非散点）；**方向**：多向量检索的"精度继续提、成本继续降"双线并进——**2026 年选型时先看 ViDoRe V3 最新排名**（本页快照是 4 月数据，`03-AI大模型应用开发/` 的时效检索纪律在此适用）。

> 🎯 **核心要点**：ColPali = 后期交互视觉文档检索（页面图像 → ~700-1024 个 patch 向量 + 查询 MaxSim）——不 OCR 直接看像素，布局复杂页面精度显著提升；家族（ColPali/ColQwen/ColSmol/4B-9B 新竞争者）——底座换新、训练目标不变；ViDoRe V3 是公共裁判（BEIR 格式 + nDCG@10 + QPS）；效率解法——训练无关池化（每页千级 → 数十级向量）+ 多阶段检索（池化预取 + 精确重排）——吞吐 4 倍、单消费卡可跑；边界——布局文档适合、自然图像/纯文本不适合；混合姿势——ColPali 找页面、OCR 抽答案。
