# 表格与图表 RAG

> 文档 RAG 的两大硬骨头：表格（结构保真）与图表（视觉理解）——表格是"原子单元"，图表要"类型化提取 + 双表示"

## 1. 表格 RAG：为什么难

表格在文档 RAG 里是**最容易被破坏的结构**——文本化过程中行列关系、合并单元格、表头层级全部丢失——"把表格变成一大段文字"后，检索命中率与回答准确率都崩（表格语义在"结构"里不在"文字"里：`"营收" | "利润"` 的关系靠列对齐表达，不是靠文字）。

**两条铁律**（2026 生产共识）：

**表格是原子单元**：**绝不跨块切分**——一个表格要么完整在一个 chunk 里，要么不索引（切碎的表格 = 检索到"半张表" = 回答必然错）——分块器要识别表格边界（04 篇的结构层解析），表格块跳过通用切分。

**整表进上下文**：生成阶段把**完整表格**（Markdown 保结构）交给 LLM——"检索到表格"不是"检索到表格的一部分"，VLM/LLM 需要整表才能做行列推理（`04-向量数据库/` 的分块方法论在表格上的例外）。

## 2. 表格的解析与表示

**解析三层**（04 篇结构层）：检测（表格在哪——Table Transformer DETR 类从图像检测边界）→ 结构（行列/合并单元格——TableBank/Table Transformer 结构头）→ 序列化（转 Markdown/HTML 保留结构——LLM 最友好的形态）。

**工具选型**：规则工具（Tabula/Camelot——快、复杂布局脆）；模型（Table Transformer）；一体化（Unstructured.io、PaddleOCR 文本 + TableBank 结构）——**验收标准：Markdown 转换后结构无损**（列对齐、合并单元格、表头层级都在）。

**嵌入形态**：完整 Markdown 表单一个嵌入（文本通道）+ 表格图像嵌入（视觉通道，双表示见第 4 节）——**表格可被文本查询命中（"利润表 2024"）也可被视觉查询命中（"这张表的结构"）**。

**表格的查询形态特化**：表格查询有三类——**定位类**（"利润表在哪一页"——检索表格标题/上下文）、**抽取类**（"2024 年营收多少"——检索后整表进 LLM 行列推理）、**比较类**（"去年和今年利润对比"——可能需要多张表联合）——**抽取与比较类查询的难点不在检索在推理**（表找到了、数值取不出/取错）——**表格 RAG 的评估要按查询形态分层**（定位/抽取/比较三类分别测——09 篇的按查询类型分层评估在表格上的落地）。

## 3. 图表 RAG：类型化提取

图表（柱状/折线/饼图/流程图/架构图/散点图/甘特图）的语义在**视觉形态**里（趋势/对比/关系）——文本化（OCR 转文字）必然丢失——**类型化提取**（2026 生产实践）：

| 图表类型 | 提取方式 |
|---------|---------|
| 柱状/折线/饼图 | VLM 描述 + 数据表提取（数值序列） |
| 流程图 | VLM 结构化提取（节点 + 边） |
| 架构图 | VLM 描述 + 实体提取 |
| 散点图 | VLM 趋势描述 + 原始数据 |
| 甘特图 | VLM 结构化提取（时间线） |

**提取的产出**：文本描述（"2024 年营收同比增长 15%，Q4 最高"）+ 结构化数据（数据表）——**"图表的两种答案形态"**：趋势类问题用描述、数值类问题用数据表——提取让图表"可被文本检索"（描述进文本索引）。

**提取质量的验收**：描述与图的**一致性抽查**（VLM 生成的描述与原图对比——"描述说增长、图显示下降"是提取错误的最坏形态，会直接污染检索与回答）；数据表与图的**数值核验**（抽样对比数据表数值与图上的标注值——VLM 看图取数会编）——**"提取即答案的代理，代理错了答案就错"**（与双表示的"描述用于检索"同一条质量链：描述是检索代理、数据表是回答代理——代理质量必须验证）。

## 4. 双表示策略：图表的双通道

图表（及表格）的**双表示（dual representation）**：每个图表存两个表示——

- **文本表示**：VLM 生成的描述 + 数据表（进文本索引——被文本查询命中："营收趋势怎么样"）。
- **视觉表示**：原图 + CLIP/SigLIP 嵌入（进视觉索引——被视觉查询命中："这张图长什么样"）。

**双表示的价值**：**文本查询与视觉查询都能命中同一张图表**（单表示只能被一类查询命中）；**检索到哪个表示就返回哪个**（文本查询返回描述 + 原图引用、视觉查询返回原图）——**"描述用于检索、原图用于回答"**：检索阶段用轻量的文本描述（快、便宜），回答阶段用原图（VLM 直接看原图比看描述准——描述是"索引代理"，原图是"证据本体"）。

## 5. 图表的评估特化

图表 RAG 的评估与文本不同（09 篇展开，此处给图表专项）：

**检索评估**：图表级命中率（"图表检索到没有"——ViDoRe 类基准的图表子集）；**回答评估**：趋势正确性（"增长/下降/持平"判断对错——描述类回答的专项指标）、数值正确性（数据表提取的数值与图一致——幻觉高发区，VLM 看图报数容易编）；**结构评估**：流程图的节点边完整性（结构化提取的验收）——**"图表回答三查"：趋势对、数值对、结构对**——图表 RAG 的验收比文本多"视觉正确性"维度（09 篇）。

## 6. 表格与图表的生产检查清单

摄入侧：**表格原子性**（分块器不切表格——抽样验证无跨块表格）；**图表覆盖率**（抽样统计图表被提取的比例——漏提取 = 不可检索）；**双表示完整性**（每个图表都有文本 + 视觉两个表示——缺一个 = 少一个通道）；**描述质量**（VLM 描述抽样人工看——描述错了检索就错，描述是"检索的代理"必须准）。

查询侧：**图表查询的命中验证**（用图表类测试查询回归——"图 3 的趋势"类查询的召回）；**回答的视觉验证**（抽查回答是否与图一致——VLM 看图编数是 2026 高频失败，09 篇）。**六项检查**是图表表格 RAG 的验收底线。

> 🎯 **核心要点**：表格两条铁律——原子单元（绝不跨块切分）+ 整表进上下文（Markdown 保结构）；解析三层（检测→结构→序列化）+ 工具选型 + 无损验收；图表类型化提取（柱状饼图→描述+数据表、流程图→节点边、散点图→趋势+数据）——趋势类用描述、数值类用数据表；双表示策略——文本描述进文本索引（检索代理）+ 原图 CLIP 嵌入进视觉索引——"描述用于检索、原图用于回答"；图表评估三查（趋势对/数值对/结构对）；六项生产检查（表格原子性/图表覆盖/双表示完整/描述质量/查询命中/回答视觉验证）。
