# LLaVA-OneVision：统一多场景

> LLaVA 的"全场景"尝试：SigLIP + Qwen-2 换装、Higher-AnyRes 场景自适应融合、单图/多图/交错/视频统一、三阶段课程 + 分离 lr——"一个模型吃所有场景"

## 1. 换装：SigLIP + Qwen-2

OneVision（2024）对三组件的升级（`多模态/多模态基础概念/05-视觉语言模型VLM架构.md` 的组件演进在 LLaVA 的落地）：
**视觉编码器从 CLIP 换 SigLIP（SO400M）**（`多模态/多模态基础概念/03-跨模态对齐与对比学习.md` 的 SigLIP——sigmoid 损失更稳——感知与对齐的升级）；**语言塔从 Vicuna 换 Qwen-2**（`多模态/多模态基础概念/` 的语言塔——Qwen 系底座质量——`多模态/多模态基础概念/01-LLaVA家族演进史.md` 的底座主线）；**投影延续 MLP**（`多模态/多模态基础概念/04-投影层与视觉语言桥接.md` 的 MLP——1.5 的默认延续）——**"组件升级、架构范式不变"**（三组件 + LLM 自注意力融合——`多模态/多模态基础概念/02-LLaVA1.5经典配方.md` 的核心——OneVision 是"更好的组件 + 更广的场景"）。

## 2. Higher-AnyRes：场景自适应融合

**Higher-AnyRes**：AnyRes 的升级——**裁剪策略与 token 池按分辨率/场景动态适配**（`多模态/多模态基础概念/03-LLaVA-NeXT动态分辨率.md` 的 AnyRes 扩展）——**token 预算跨场景对齐**（单图最多 729×(9+1) token（anyres_max_9）；视频 196 token/帧）——**支持 2304² 输入**——**"token 预算按场景定"**（单图/多图/视频各场景的 token 分配统一规划——`多模态/多模态基础概念/06-多模态token与输入处理.md` 的 token 预算）。

**token 预算对齐的意义**：**跨场景的一致性**（不同场景的 token 分配可比较——训练与推理的预算一致——`多模态/多模态微调（PEFT）/09-多模态微调评估.md` 的一致性纪律）——"多场景模型需要统一的 token 语言"（视频 196 token/帧 vs 单图 729 token——按场景分配但规则统一）。

## 3. 统一多场景

**OneVision 的核心：一个模型处理所有场景**——**单图/多图/交错图文/视频**（`多模态/多模态基础概念/` 的能力阶梯扩展——从"看图说话"到"看多种模态"）——**发布 0.5B/7B/72B 三规模**——**"统一的意义"**：一个模型替代多个专用模型（对话模型 + 视频模型 + 文档模型合一——`多模态/多模态推理部署工程/04-多模态服务架构.md` 的单模型服务——部署简化）。

**统一的技术基础**：**视觉 token 的序列化统一**（单图/多图/视频都变成"视觉 token 序列 + 文本 token"——`多模态/多模态基础概念/06-多模态token与输入处理.md` 的 token 化——LLM 自注意力统一处理（`多模态/多模态基础概念/02-LLaVA1.5经典配方.md` 的融合机制——统一场景不需要新机制——只要输入 token 化统一）。

**统一的工程含义**：**部署简化**（一个模型替代多个专用模型——`多模态/多模态推理部署工程/04-多模态服务架构.md` 的单模型服务——对话/视频/文档合一）；**微调简化**（一个模型微调覆盖多场景——`多模态/多模态微调（PEFT）/05-多模态微调的类型.md` 的多任务）；**评估复杂化**（多场景评估集——`多模态/多模态基础概念/09-多模态能力评估与基准.md` 的场景分层——"统一模型的评估要按场景分测"（单图/多图/视频各测——`多模态/多模态常见问题与缺陷/09-评估与缺陷检测.md` 的分层纪律）。

## 4. 三阶段课程

OneVision 的训练（多阶段课程、每阶段一个 epoch——`多模态/多模态微调（PEFT）/04-多模态微调配方.md` 的配方演进）：
**Stage-1**（558K LCS 图文对——投影层对齐——`多模态/多模态基础概念/02-LLaVA1.5经典配方.md` 的阶段一延续）；**Stage-1.5**（4M 高质量样本——详细描述/OCR/知识——`多模态/多模态基础概念/03-LLaVA-NeXT动态分辨率.md` 的 Stage-1.5 扩展——约 350 万自标注图 + 110 万 OCR/文本 + 23.5 万语言 SFT）；**Stage-2**（3.2M 单图指令 + 1.6M OneVision 样本（单图/多图/视频指令——约 0.35M 视频）——总量约 5.2M）——**"课程：对齐 → 知识 → 多场景指令"**（`多模态/多模态基础概念/01-LLaVA家族演进史.md` 的数据主线——158K → 5.2M）。

**数据规模的意义**：5.2M 的多阶段课程（`多模态/多模态数据集/03-多模态指令数据.md` 的数据方法论——规模与结构化的双演进——`多模态/多模态数据集/01-多模态数据集全景与定位.md` 的"精选 + 增强"趋势——OneVision 是数据规模化的代表）。

**数据规模的"可复现性"**：5.2M 的规模是 OneVision-1.5 民主化（4 天/$16K——`多模态/多模态基础概念/05-OneVision-1.5与2.md` 01 节）的基础——**"数据管线开放了，规模才可复现"**（`多模态/多模态数据集/05-构建管线与合成数据.md` 的管线可重跑——OneVision 系列把"数据管线 + 训练栈 + 权重"全开放——**"规模不是障碍，管线才是"**（有管线，中小团队可复现 5.2M 的构建——`多模态/多模态数据集/` 的 manifest 纪律——数据管线的开放是民主化的另一半）。

## 5. 分离 lr

**OneVision 的分离学习率**：**视觉组件 AdamW 2e-6、语言组件 AdamW 1e-5**——**视觉学习率远低于语言**（视觉塔解冻时的小步长——`多模态/多模态微调（PEFT）/04-多模态微调配方.md` 的投影层独立 lr 演进——OneVision 的视觉 lr 2e-6 说明"视觉塔若训必须极小步"（保护对齐——`多模态/多模态微调（PEFT）/02-VLM结构与可微调部件.md` 的破坏对齐理由——**"分离 lr = 不同组件不同保护等级"**——语言的保护等级低于视觉（视觉更脆弱——动一点就破坏对齐）。

## 6. 面试必答：OneVision 与 1.5 的区别

面试"OneVision vs 1.5"的答案：**组件**（CLIP → SigLIP、Vicuna → Qwen-2）；
**分辨率**（固定 336 → Higher-AnyRes 2304²）；**场景**（单图 → 单图/多图/交错/视频统一）；**数据**（760K → 5.2M 三阶段课程）；**lr**（统一 2e-5 → 分离 2e-6/1e-5）——**"五个维度各升一级"**（组件/分辨率/场景/数据/训练——`多模态/多模态基础概念/01-LLaVA家族演进史.md` 的五条主线在 OneVision 的集中落地——OneVision 是 LLaVA 家族的"集大成"版本）。

> 🎯 **核心要点**：换装——SigLIP（感知对齐升级）+ Qwen-2（语言升级）+ MLP 延续——"组件升级、架构范式不变"；Higher-AnyRes——裁剪策略与 token 池场景自适应（单图 729×(9+1)/视频 196 帧——token 预算跨场景对齐——"多场景模型需要统一的 token 语言"）；统一多场景——单图/多图/交错/视频一个模型（视觉 token 序列化统一 + LLM 自注意力——不需要新机制）；三阶段课程——558K 对齐 → 4M 知识 → 5.2M 指令（0.35M 视频——"对齐 → 知识 → 多场景指令"）；分离 lr——视觉 2e-6/语言 1e-5（视觉更脆弱——"动一点就破坏对齐"——不同保护等级）；面试五维度对比（组件/分辨率/场景/数据/lr）——OneVision 是"集大成"版本。
