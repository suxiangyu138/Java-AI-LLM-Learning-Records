# 架构解剖：组件细节

> LLaVA 三组件的深潜：视觉编码器（CLIP vs SigLIP 的选择逻辑）、MLP 投影的演进与细节、语言塔（Vicuna → Qwen 的底座选择）、融合机制（LLM 自注意力为什么够）——"组件细节是面试与微调的共同基础"

## 1. 视觉编码器：CLIP vs SigLIP

LLaVA 家族的编码器选择（`多模态/多模态基础概念/02-视觉编码器与图像tokenization.md` 的编码器家族在 LLaVA 的落地）：

**CLIP ViT-L/336**（1.5）：对比学习预训练（`多模态/多模态基础概念/03-跨模态对齐与对比学习.md` 的 InfoNCE）——336² 分辨率 576 token——**1.5 时代的默认**；**SigLIP SO400M**（OneVision）：sigmoid 损失（`多模态/多模态基础概念/03-跨模态对齐与对比学习.md` 的 SigLIP——更稳更高效）——**OneVision 换装的理由**（对齐质量与鲁棒性——`多模态/多模态基础概念/02-视觉编码器与图像tokenization.md` 的 SigLIP-2 演进线的前站）；**OneVision-Encoder**（2）：自研（codec 对齐稀疏性——`多模态/多模态基础概念/05-OneVision-1.5与2.md` 02 节）。

**选择逻辑**：**"编码器是感知的上限"**（`多模态/多模态常见问题与缺陷/02-视觉感知缺陷.md` 的结构根源——patch 粒度/对齐质量——换编码器是感知跃迁——`多模态/多模态微调（PEFT）/03-LoRA在多模态上的应用.md` 的"换编码器 > 塔 LoRA"）——**LLaVA 的编码器演进（CLIP → SigLIP → 自研）是感知升级的路线**。

**编码器选择的工程注意**：**换编码器的连锁**（换编码器 = 视觉特征空间变化 = 投影层重新对齐——`多模态/多模态微调（PEFT）/04-多模态微调配方.md` 的阶段一——"编码器是低频高成本的组件决策"）；**编码器的部署影响**（`多模态/多模态推理部署工程/05-多模态量化与压缩.md` 的视觉塔量化——编码器精度敏感——部署时视觉塔保持高位宽——**"编码器的选择贯穿训练与部署"**（架构决策的连锁效应——`多模态/多模态微调（PEFT）/02-VLM结构与可微调部件.md` 的组件版本矩阵）。

## 2. MLP 投影：演进与细节

**MLP 投影**（`多模态/多模态基础概念/04-投影层与视觉语言桥接.md` 的 MLP——LLaVA 的投影延续）：**1.5 的两层 MLP（Linear → GELU → Linear）**——从 1.0 的单层线性升级（更强的映射——`多模态/多模态基础概念/04-投影层与视觉语言桥接.md` 的对齐质量）；**细节**：`mlp2x_gelu` 形态（中间维度 2 倍隐藏）——**"浅层可训练投影"**（NeXT 的表述——投影是唯一"浅"的可训组件——`多模态/多模态微调（PEFT）/02-VLM结构与可微调部件.md` 的"投影层总是可训练"）。

**投影的微调地位**（`多模态/多模态微调（PEFT）/02-VLM结构与可微调部件.md` 03 节）：**non_lora_trainables.bin**（投影层全量权重单独保存——微调时始终可训练——`多模态/多模态微调（PEFT）/08-多模态微调工程实践.md` 的合并含投影层）——**"投影是任务校准的第一旋钮"**（比语言塔轻量、比编码器安全——`多模态/多模态基础概念/04-投影层与视觉语言桥接.md` 04 节）。

## 3. 语言塔：Vicuna → Qwen

**语言塔的底座选择**（`多模态/多模态基础概念/01-LLaVA家族演进史.md` 的底座主线）：**Vicuna-7B/13B**（1.5——LLaMA 微调的对话模型——`大模型微调知识体系/` 的语言塔概念）；**Qwen-2**（OneVision）；**Qwen-3**（OneVision-2）——**选择逻辑**：**底座质量决定语言上限**（`多模态/多模态基础概念/01-多模态模型全景与定位.md` 的"语言 × 感知 × 对齐"——NeXT 消融实证"LLM 规模关键"——`多模态/多模态基础概念/03-LLaVA-NeXT动态分辨率.md` 03 节）——**"换底座 = 换语言维度的上限"**。

**底座切换的代价**：换底座 = 投影层重新对齐（`多模态/多模态微调（PEFT）/04-多模态微调配方.md` 的阶段一——"换语言塔 = 重新对齐投影"——组件耦合——`多模态/多模态微调（PEFT）/02-VLM结构与可微调部件.md` 05 节的组件版本矩阵）。

## 4. 融合机制：LLM 自注意力

**LLaVA 的融合机制**（架构的核心设计决策）：**视觉 token 与文本 token 拼接 → LLM 的自注意力统一处理——无交叉注意力适配器**——**"所有跨模态混合由 LLM 自注意力完成"**（1.5 与 NeXT 都明确表述——`多模态/多模态基础概念/02-LLaVA1.5经典配方.md` 01 节）。

**为什么"不需要交叉注意力"**：LLM 的自注意力已经够用（视觉 token 与文本 token 在同一序列——注意力自然跨模态交互——`大模型微调知识体系/基础概念/03-Transformer与参数基础.md` 的自注意力——"拼接 + 自注意力 = 最简融合"）——**与早期模型（BLIP-2 的 Q-Former）的对比**：Q-Former 是显式的跨模态桥（`多模态/多模态基础概念/04-投影层与视觉语言桥接.md` 的 Q-Former）；LLaVA 选择"让 LLM 自己学融合"——**"融合的职责交给 LLM"**（LLM 的容量足够学跨模态交互——简化架构）——**面试加分点**："为什么 LLaVA 不用交叉注意力"——答"拼接 + LLM 自注意力已够，架构更简"。

## 5. 组件与微调的对应

组件细节与微调策略的对应（`多模态/多模态微调（PEFT）/` 的组件职责）：**编码器**（CLIP/SigLIP——冻结默认——
专门视觉域训塔——`多模态/多模态微调（PEFT）/03-LoRA在多模态上的应用.md`）；
**投影**（MLP——始终可训练——阶段一主角——`多模态/多模态微调（PEFT）/04-多模态微调配方.md`）；**语言塔**（Vicuna/Qwen——LoRA 默认——层选择性——`多模态/多模态微调（PEFT）/03-LoRA在多模态上的应用.md` 02 节）——**"组件的架构细节决定微调的选择"**（冻什么/训什么/怎么训都从组件性质推出来——`多模态/多模态微调（PEFT）/02-VLM结构与可微调部件.md` 的决策清单）。

## 6. 面试必答：LLaVA 架构三问

面试的架构三问（本体系的浓缩）：**1) 架构是什么**（三组件 + 拼接 + LLM 自注意力——无交叉注意力）；**2) 为什么这样设计**（组件可替换/训练可分阶段/融合交给 LLM——
`多模态/多模态基础概念/05-视觉语言模型VLM架构.md` 的模块化优势）；**3) 组件怎么演进**（CLIP→SigLIP→自研、Vicuna→Qwen-3、线性→MLP——`多模态/多模态基础概念/01-LLaVA家族演进史.md` 的主线）——**"架构三问 = 是什么 → 为什么 → 怎么变"**（面试通用结构）。

> 🎯 **核心要点**：编码器——CLIP（1.5）→ SigLIP（OneVision）→ 自研（2）——"编码器是感知上限——换编码器是感知跃迁"；投影——两层 MLP（Linear→GELU→Linear——mlp2x_gelu）——浅层可训（non_lora_trainables——任务校准第一旋钮）；语言塔——Vicuna → Qwen-2 → Qwen-3（底座质量决定语言上限——换底座 = 重新对齐投影）；融合——拼接 + LLM 自注意力（无交叉注意力——"让 LLM 自己学融合"——vs Q-Former 的对比）；组件 ↔ 微调对应（冻塔/训投影/LoRA 语言塔——架构细节决定微调选择）；面试三问——是什么 → 为什么 → 怎么变。
