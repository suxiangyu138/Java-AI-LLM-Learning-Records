# LLaVA 家族演进史

> 开源多模态的"史记"：LLaVA 1.0 → 1.5 → NeXT/1.6 → o1 → OneVision → OneVision-1.5 → OneVision-2——演进主线（分辨率/投影/数据/底座/范围）——"读演进史 = 读 VLM 的设计空间"

## 1. 版本时间线

LLaVA 家族的版本演进（2023-2026）：

| 版本 | 时间 | 关键创新 |
|------|:---:|---------|
| LLaVA 1.0 | 2023-04 | 线性投影 + GPT-4 生成指令数据（开创性） |
| LLaVA 1.5 | 2023-10 | MLP 投影、336²、760K 数据——**经典配方** |
| LLaVA-NeXT/1.6 | 2024-02 | AnyRes 动态分辨率、Stage-1.5 |
| LLaVA-o1 | 2024-11 | 阶段级 beam search（推理 +8.9%） |
| OneVision | 2024 | SigLIP + Qwen-2、单图/多图/视频统一 |
| OneVision-1.5 | 2025 | 民主化（4 天/$16K 全开源） |
| OneVision-2 | 2026 | OneVision-Encoder（感知智能） |

**读史方法**：每个版本解决一个"上一版本的不足"——**"演进史 = 缺陷驱动"**（与 `多模态/基础概念/05-视觉语言模型VLM架构.md` 的"每条主线解决一个缺陷"同构——`多模态/多模态常见问题与缺陷/` 的缺陷是演进的驱动力）。

**家族的重要性**（面试开篇）：LLaVA 家族是**开源多模态的事实标准**——从 1.5 的"经典配方"到 OneVision-2 的"感知智能"——**"frozen 编码器 + MLP + LLM 微调"成为整个领域的默认起点**（`多模态/多模态微调（PEFT）/01-多模态微调全景与定位.md` 的微调对象——绝大多数开源 VLM 的架构基础——`多模态/基础概念/05-视觉语言模型VLM架构.md` 的模块化范式在 LLaVA 家族的定型）——**"学 LLaVA = 学 VLM 架构的通用框架"**。

**演进的"场景驱动"**：每条主线背后是应用场景的驱动——**分辨率主线 = 文档/图表场景**（`多模态/多模态常见问题与缺陷/04-OCR与文档理解缺陷.md` 的细粒度）；**范围主线 = Agent/视频场景**（`多模态/多模态微调（PEFT）/05-多模态微调的类型.md` 的任务类型）；**数据主线 = 能力覆盖**（`多模态/多模态数据集/03-多模态指令数据.md` 的配比）——**"演进的方向 = 应用的需求"**（面试答演进时带上"解决什么场景问题"——深度加分）。

**演进的学习方法**：读 LLaVA 演进史的正确姿势——**每个版本问三件事**：**"解决了什么问题"**（缺陷驱动——`多模态/多模态常见问题与缺陷/` 的缺陷映射）、**"改了什么"**（五条主线中的哪条）、**"代价是什么"**（新版本引入的新权衡——如 OneVision 的统一带来评估复杂化——`多模态/多模态基础概念/09-多模态能力评估与基准.md` 的场景分层）——**"演进史 = 权衡史"**（每个设计决策都有代价——面试答演进时带出"代价"是深度标志）。

## 2. 演进主线一：分辨率

**分辨率是感知的第一维度**（`多模态/多模态基础概念/02-视觉编码器与图像tokenization.md` 的分辨率权衡）：**224²（1.0）→ 336²（1.5——视觉 token 256 → 576）→ 动态 AnyRes（NeXT——按内容分块、2304² 上限）→ Higher-AnyRes（OneVision——场景自适应）**——**"分辨率从固定到动态"**——文档/图表/OCR 场景的感知需求（`多模态/多模态常见问题与缺陷/04-OCR与文档理解缺陷.md` 的细粒度）驱动——**"演进的第一主线是'看得更清楚'"**。

## 3. 演进主线二：投影层

**投影层从线性到 MLP**（`多模态/多模态基础概念/04-投影层与视觉语言桥接.md` 的投影演进在 LLaVA 家族的落地）：**1.0 的单层线性投影 → 1.5 的两层 MLP（Linear → GELU → Linear）**——**"更强的视觉-语言映射"**（`多模态/多模态基础概念/` 的对齐质量——投影是"翻译官"——翻译质量决定图文一致）——**"1.5 的 MLP 成为领域默认投影"**（后续版本延续）。

## 4. 演进主线三：数据

**数据从 158K 到 5.2M 的多阶段课程**（`多模态/多模态数据集/03-多模态指令数据.md` 的数据方法论在 LLaVA 的落地）：**1.0 的 158K GPT-4 生成指令 → 1.5 的 760K（558K 描述 + 158K 对话 + 50K GQA 等）→ NeXT 的 Stage-1.5（高质量知识学习）→ OneVision 的 5.2M（3.2M 单图指令 + 1.6M OneVision 多场景 + 0.35M 视频）**——**"数据规模与结构化（多阶段课程）双演进"**（`多模态/多模态数据集/08-多模态评估数据.md` 的评估集同步演进——基准分数随数据提升）。

## 5. 演进主线四：底座

**语言塔从 Vicuna 到 Qwen 系**（`多模态/多模态基础概念/` 的语言塔演进）：**1.5 的 Vicuna-7B/13B → NeXT 的多种底座 → OneVision 的 Qwen-2 → OneVision-2 的 Qwen-3**——**"LLM 底座的质量决定 VLM 的上限"**（NeXT 的消融实证——LLM 规模对多模态能力关键——`多模态/多模态基础概念/01-多模态模型全景与定位.md` 的"能力上限 = 语言 × 感知 × 对齐"——底座是语言维度的上限）；**视觉编码器从 CLIP 到 SigLIP**（OneVision 换装——`多模态/多模态基础概念/03-跨模态对齐与对比学习.md` 的 SigLIP 改进）。

## 6. 演进主线五：范围

**从单图聊天到统一多场景**：**1.x 的单图对话 → OneVision 的单图/多图/交错图文/视频统一**（`多模态/多模态基础概念/` 的能力阶梯——从"看图说话"到"看多种模态说话"）——**"范围的扩展 = 应用场景的扩展"**（文档多图/视频理解/Agent 截图——`多模态/多模态微调（PEFT）/05-多模态微调的类型.md` 的任务类型）——**OneVision 是"一个模型吃所有场景"的尝试**（与 `多模态/多模态基础概念/` 的统一模型趋势呼应）。

## 7. 演进史的面试意义

**面试答"LLaVA 演进"的结构**：**版本时间线（7 版）→ 五条主线（分辨率/投影/数据/底座/范围）→ 每条主线的"解决什么问题"**——**"演进史 = 设计空间的全景"**（面试官问架构演进是想看"是否理解设计决策的动机"——`多模态/多模态常见问题与缺陷/` 的缺陷驱动视角加分）——**"LLaVA 的演进是 VLM 设计的最优学习材料"**（每一版都是完整的设计实验——答案在演进里）。

**演进史的"知识库串联"**：LLaVA 的每条演进主线都能在知识库找到对应——**分辨率主线**（`多模态/多模态推理部署工程/02-多模态推理性能分析.md` 的 token 膨胀——AnyRes 的 token 动态）；**数据主线**（`多模态/多模态数据集/03-多模态指令数据.md` 的指令数据方法论）；**底座主线**（`多模态/多模态微调（PEFT）/02-VLM结构与可微调部件.md` 的组件职责）——**"读 LLaVA 演进 = 串联多模态知识库"**（每个版本是一堂多模态课——演进史是本体系与各应用体系的交汇点——面试答演进时自然带出相关知识点的深度）。

> 🎯 **核心要点**：七版本时间线（1.0 开创 → 1.5 经典 → NeXT AnyRes → o1 推理 → OneVision 统一 → 1.5 民主化 → 2 感知智能）；五条演进主线——分辨率（224→336→AnyRes 2304²——"看得更清楚"）/投影（线性→MLP——"翻译更强"）/数据（158K→5.2M 多阶段课程）/底座（Vicuna→Qwen-3——语言上限）+ 编码器（CLIP→SigLIP）/范围（单图→统一多场景）；"演进史 = 缺陷驱动 + 设计空间全景"——面试答演进先给时间线再给主线再给动机。
