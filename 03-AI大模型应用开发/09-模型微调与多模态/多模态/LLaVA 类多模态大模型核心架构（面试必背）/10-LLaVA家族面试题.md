# LLaVA 家族面试题

> 多模态面试的最高频区："LLaVA 架构怎么设计、两阶段训练为什么、AnyRes 是什么、OneVision 和 1.5 的区别、为什么 LLaVA 重要"——每题带演进实证，背熟即得分

## 1. 必问基础 8 题

### Q1：LLaVA 的架构是什么？

**答案**：三组件 + 融合——**视觉编码器**（CLIP ViT-L/336——1.5；SigLIP——OneVision；OneVision-Encoder——2）、**投影层**（两层 MLP——Linear → GELU → Linear）、**语言塔**（Vicuna——1.5；Qwen-2/3——OneVision 系）——**融合机制**：视觉 token 与文本 token **拼接进同一序列，由 LLM 的自注意力统一处理——无交叉注意力适配器**（"所有跨模态混合由 LLM 自注意力完成"）。**组件职责**：编码器管感知（冻结）、投影管对齐（阶段一训）、语言塔管行为（阶段二微调）——"三组件 + LLM 自注意力融合"是 LLaVA 范式的核心。

### Q2：为什么 LLaVA 用两阶段训练？lr 为什么差 50 倍？

**答案**：两阶段解决两个问题——**阶段一解决"对齐"**（只训投影层——558K 图文对——lr 1e-3——投影从零学编码器特征与语言嵌入的映射）；**阶段二解决"行为"**（放开语言塔——665K 指令数据——lr 2e-5——语言塔学指令遵循）。**lr 差 50 倍的原因**：阶段一投影是全新组件（大 lr 快收敛）、阶段二语言塔已有能力（小 lr 保护——`大模型微调知识体系/基础概念/05-优化器与梯度更新.md` 的"底座已收敛"）——**"同一个模型的两个阶段，学习率是两个世界"**——一句话总结："**先让模型看懂图，再教它按指令说**"。

### Q3：LLaVA 1.5 为什么是里程碑？

**答案**：**四个验证**——**架构定型**（三组件 + LLM 自注意力融合——后续 VLM 的骨架）；**配方验证**（两阶段 + lr 50 倍差——训练方法论的基准）；**数据验证**（GPT-4 生成指令数据可行——"开源模型的训练数据可以来自闭源模型生成"——2026 主流的源头）；**效果验证**（13B 规模接近 GPT-4V——VQA/GQA/POPE SOTA——开源追赶的证明）——**"组合创新的典范"**（组件都是现成的——组合 + 配方验证——1.5 定义了开源多模态的默认起点。

### Q4：AnyRes 是什么？解决什么问题？

**答案**：AnyRes（LLaVA-NeXT/1.6，2024）——**通过子图裁剪策略实现动态分辨率**——图像按内容分块（大图切小块）→ 各块按固定分辨率处理 → 池化融合——**去除固定输入限制**（1.5 的 336² → 任意分辨率，输入分辨率提升 4 倍、支持多宽高比、2304² 上限）——**解决什么问题**：固定分辨率的细粒度不足——文档/图表/OCR 场景（`多模态/多模态常见问题与缺陷/04-OCR与文档理解缺陷.md` 的细粒度——高分辨率文档被压缩）——**"不动架构、只动输入处理"**（三组件不变——分辨率是独立于架构的性能维度——`多模态/多模态常见问题与缺陷/02-视觉感知缺陷.md` 的输入侧缓解的架构级验证）。

### Q5：LLaVA-OneVision 和 1.5 的区别？

**答案**：**五个维度各升一级**——**组件**（CLIP → SigLIP、Vicuna → Qwen-2）；**分辨率**（固定 336 → Higher-AnyRes 2304²——裁剪策略与 token 池场景自适应——单图 729×(9+1)/视频 196 token 帧）；**场景**（单图 → 单图/多图/交错/视频统一——"一个模型吃所有场景"）；**数据**（760K → 5.2M 三阶段课程——558K 对齐 → 4M 知识 → 3.2M 单图 + 1.6M 多场景指令）；**训练**（统一 lr → 分离 lr——视觉 2e-6/语言 1e-5——视觉更脆弱）——**"OneVision 是 LLaVA 家族的集大成版本"**（五条演进主线集中落地）。

### Q6：LLaVA 家族的演进主线是什么？

**答案**：**五条主线**——**分辨率**（224 → 336 → AnyRes 2304²——"看得更清楚"）；**投影**（线性 → 两层 MLP——"翻译更强"）；**数据**（158K → 760K → 5.2M 多阶段课程——"教得更多更结构化"）；**底座**（Vicuna → Qwen-2 → Qwen-3 + 编码器 CLIP → SigLIP → 自研——"组件升级"）；**范围**（单图 → 统一多场景——"场景更广"）——**"演进史 = 缺陷驱动 + 设计空间全景"**（每个版本解决上一版本的不足——`多模态/多模态基础概念/01-LLaVA家族演进史.md`）。

### Q7：为什么 LLaVA 不用交叉注意力（vs Q-Former）？

**答案**：**拼接 + LLM 自注意力已够**——视觉 token 与文本 token 在同一序列，LLM 的自注意力自然跨模态交互（`大模型微调知识体系/基础概念/03-Transformer与参数基础.md` 的自注意力——"让 LLM 自己学融合"）——**架构更简**（无额外桥接组件——`多模态/多模态基础概念/06-架构解剖组件细节.md` 04 节）——**vs BLIP-2/Q-Former**：Q-Former 是显式的跨模态桥（压缩 + 对齐——`多模态/多模态基础概念/04-投影层与视觉语言桥接.md` 的 Q-Former——32 token 压缩）——LLaVA 选择"LLM 容量足够学跨模态交互"——**"融合的职责交给 LLM"**（架构简化的设计决策——OneVision 延续）。

### Q8：微调 LLaVA 系模型要注意什么？

**答案**：**组件策略**（`多模态/多模态微调（PEFT）/` 的 LLaVA 应用）——**默认冻塔 + LoRA 语言塔**（0.1-0.6%——LLaVA 架构天然适配 LoRA——冻塔省视觉塔梯度与状态——单卡微调标准组合）；**投影层始终可训练**（non_lora_trainables.bin——`多模态/多模态微调（PEFT）/02-VLM结构与可微调部件.md` 03 节）；**两阶段可合并**（现成底座跳过阶段一——直接 SFT lr 2e-5——`多模态/多模态微调（PEFT）/04-多模态微调配方.md` 06 节）；**层选择性**（编码类微调——下半层冻结保融合——gemma4 实证——`多模态/多模态微调（PEFT）/03-LoRA在多模态上的应用.md` 02 节）；**QLoRA**（视觉塔保持高位宽——`多模态/多模态微调（PEFT）/08-多模态微调工程实践.md`）；**验收**（能力 + 缺陷 + 融合三线——`多模态/多模态微调（PEFT）/09-多模态微调评估.md`）。

## 2. 架构理解场景题

**场景一**："面试官问'如果让你设计一个开源 VLM，你怎么做'？"——**按 LLaVA 配方回答**：三组件（现成编码器 CLIP/SigLIP + 两层 MLP + 现成 LLM——"组件用现成的，验证组合"）；两阶段训练（对齐 1e-3 → SFT 2e-5——`多模态/多模态基础概念/07-训练配方深潜.md`）；数据（GPT-4/强模型生成三类指令 + 过滤——`多模态/多模态基础概念/08-数据配方深潜.md`）；增强（动态分辨率——文档/图表场景）；验收（能力 + 缺陷双评估——`多模态/多模态基础概念/09-多模态能力评估与基准.md`）——**"设计题 = 默写 LLaVA 配方 + 按场景调整"**。

**场景二**："为什么开源模型和闭源（GPT-4V/Gemini）差距大？"——**差距在数据与规模，不在架构**——架构范式一致（GPT-4V 也是模块化——CLIP 派生编码器——`多模态/多模态基础概念/05-视觉语言模型VLM架构.md` 01 节）——闭源优势 = 海量数据 + 大算力（MMMU：Gemini 72.5 vs LLaVA-NeXT 48.2——约 24 点）——**"开源追赶的是数据与算力"**（LLaVA 证明架构不是瓶颈——`多模态/多模态基础概念/09-与其他模型对比.md` 05 节——OneVision-1.5 的民主化（4 天/$16K）是缩小数据/算力差距的尝试）。

**场景三**："要用 LLaVA 系做文档理解微调，怎么配？"——**组件**（冻塔 + LoRA 语言塔 + 投影可训——`多模态/多模态微调（PEFT）/` 的默认）；**分辨率**（AnyRes 类动态分辨率——文档细粒度——`多模态/多模态基础概念/03-LLaVA-NeXT动态分辨率.md` 的感知基础）；**数据**（文档指令数据——版面/表格/图文关系标注——`多模态/多模态数据集/07-数据格式与处理.md` 04 节）；**验收**（文档专项——数字必对——`多模态/多模态常见问题与缺陷/04-OCR与文档理解缺陷.md` 05 节 + 融合回测——`多模态/多模态微调（PEFT）/09-多模态微调评估.md` 03 节）；**部署**（vLLM——AnyRes 的 token 预算进容量规划——`多模态/多模态推理部署工程/02-多模态推理性能分析.md`）。

## 3. 答题范式总结

LLaVA 架构题标准答题结构（四步）：**讲架构**（三组件 + 拼接 + LLM 自注意力——先给框架）→ **讲配方**（两阶段 lr 50 倍差——
训练的关键数字）→ **讲演进**（分辨率/投影/数据/底座/范围五主线——版本对比）→ **划定位**（开源基线——其他是演进变体——微调/选型的含义）——**"架构 → 配方 → 演进 → 定位"四件套**；进阶追问导向微调（组件策略）与基础概念（通用 VLM 框架）——LLaVA 答得稳，多模态面试的架构关就过了。

> 🎯 **核心要点**：LLaVA 面试 = 8 题全覆盖（架构/两阶段/里程碑/AnyRes/OneVision 对比/演进主线/融合机制/微调注意）+ 3 场景题（设计题/闭源差距/文档微调）；答题四步 = 架构→配方→演进→定位；2026 数字弹药——336² 576 token、1e-3→2e-5（50 倍）、760K（558K+158K+50K）、2304²（AnyRes）、5.2M（OneVision）、2e-6/1e-5（分离 lr）、4 天/$16K（1.5 民主化）、72.5 vs 48.2（闭源差距）——LLaVA 是"架构 + 配方 + 演进"的三合一考点：架构给框架、配方给数字、演进给深度。
