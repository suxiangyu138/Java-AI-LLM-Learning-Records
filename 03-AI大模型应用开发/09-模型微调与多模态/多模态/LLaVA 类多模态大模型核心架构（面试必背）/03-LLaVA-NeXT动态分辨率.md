# LLaVA-NeXT：动态分辨率

> LLaVA 1.5 的感知升级：AnyRes 动态分辨率（2304² 上限）、Stage-1.5 知识学习、分辨率/数据/底座系统消融——"文档与图表看得清了"

## 1. AnyRes：动态分辨率

**AnyRes（Any Resolution）**：LLaVA-NeXT/1.6（2024-02）的核心创新——**通过子图裁剪策略实现动态分辨率**——图像按内容分块（`多模态/多模态基础概念/02-视觉编码器与图像tokenization.md` 的分块思想）——**去除固定输入限制**（1.5 的 336² 固定 → NeXT 的任意分辨率裁剪 + 池化）——**v1.6 输入分辨率提升 4 倍、支持多种宽高比**——**"文档、图表、OCR 场景的感知需求"**（`多模态/多模态常见问题与缺陷/04-OCR与文档理解缺陷.md` 的细粒度——固定分辨率时高分辨率文档被压缩——AnyRes 按内容分配）。

**AnyRes 的机制**：图像 → 分块（子图）→ 每块按固定分辨率处理 → 池化融合——**"大图切小块、小块各自看清"**——token 数随内容动态（简单图少 token、复杂图多——`多模态/多模态基础概念/06-多模态token与输入处理.md` 的 token 压缩思想的反向——按需分配）。

**AnyRes 的意义**：**分辨率从"固定"到"动态"**（`多模态/多模态基础概念/02-视觉编码器与图像tokenization.md` 的分辨率权衡——高分辨率细节 vs token 成本——AnyRes 是"细节需求驱动"的分配）——**"感知能力的架构级提升"**（不用换编码器、用输入处理提升感知——`多模态/多模态常见问题与缺陷/02-视觉感知缺陷.md` 的输入侧缓解）。

**AnyRes 的部署含义**：动态分辨率 = **token 数随输入动态变化**（`多模态/多模态推理部署工程/02-多模态推理性能分析.md` 的 token 估算——文档页的 AnyRes token 数随内容复杂度波动——**"服务的容量规划要按 AnyRes 的 token 分布而非固定值"**（`多模态/多模态推理部署工程/08-多模态模型工程化.md` 的容量公式——图像占比 + token 分布——AnyRes 让多模态服务的负载更可预测地不可预测（内容驱动）——vLLM 类引擎的 AnyRes 支持是部署前提（`多模态/多模态推理部署工程/04-多模态服务架构.md` 的引擎就绪检查）。

## 2. Stage-1.5：知识学习

**Stage-1.5（高质量知识学习）**：NeXT 引入的中间阶段——在阶段一（对齐）与阶段二（SFT）之间——**高质量知识样本**（详细描述/OCR/知识——`多模态/多模态数据集/08-多模态评估数据.md` 的数据分层）——**"阶段从两段到三段"**（对齐 → 知识 → 指令——`多模态/多模态微调（PEFT）/04-多模态微调配方.md` 的三阶段趋势的早期形态——LLaVA-NeXT 的 1.5 阶段是 DPO 三阶段（预训练 → SFT → DPO）之外的另一条三阶段路径——**"知识学习在行为学习之前"**（先懂内容再学形式）。

## 3. 系统消融：分辨率/数据/底座

NeXT 做了系统消融（`多模态/多模态微调（PEFT）/01-超参全景与调参方法论.md` 的消融方法论）：**分辨率**（336 → AnyRes 的提升量化——
文档/OCR 任务的收益）；**token 数量**（token 预算与效果的关系）；**数据混合**（不同数据配比的效果差异）；**训练阶段**（两段 vs 三段）；**底座规模**——**"LLM 规模对多模态能力至关重要"**（`多模态/多模态基础概念/01-多模态模型全景与定位.md` 的"语言 × 感知 × 对齐"——语言维度的实证——底座从 7B 到 13B 的提升显著）。

**消融的意义**：**"配方中的每个变量都被测过"**（NeXT 把"LLaVA 配方"从经验变成有数据的科学——`多模态/多模态微调（PEFT）/09-多模态微调评估.md` 的冻结消融方法论源头——后续 VLM 的消融实验范式）。

**消融的"决策价值"**：NeXT 的消融结论可直接用于工程决策——**"LLM 规模关键"**（`多模态/多模态基础概念/01-多模态模型全景与定位.md` 的选型——底座规模优先于其他变量——预算有限先买底座）；**"分辨率收益显著"**（文档任务的分辨率投入回报高——`多模态/多模态微调（PEFT）/09-多模态微调评估.md` 的组件选择——消融是"预算分配的指南"——**"消融数据 = 决策数据"**（`多模态/多模态基础概念/01-超参全景与调参方法论.md` 的"默认值是起点"——NeXT 的消融给了"该往哪个方向调"的证据）。

## 4. 架构保持

NeXT **保持三模块设计**（`多模态/多模态基础概念/05-视觉语言模型VLM架构.md` 的模块化）：**frozen 视觉编码器 + 浅层可训投影 + 预训练 LLM**——
**所有跨模态混合由 LLM 自注意力处理（无交叉注意力适配器）**——**"架构不变、输入处理升级"**——**"NeXT 证明了分辨率是独立于架构的性能维度"**（不动三组件、只动输入处理——感知大幅提升——`多模态/多模态常见问题与缺陷/02-视觉感知缺陷.md` 的"输入侧缓解"的架构级验证）。

## 5. 面试必答：AnyRes 是什么

面试"AnyRes"的标准答案：**定义**（子图裁剪的动态分辨率——任意分辨率图像按内容分块处理）；**机制**（大图切块 → 各块固定分辨率处理 → 池化融合——
token 按内容动态分配）；**解决什么**（固定分辨率的细粒度不足——文档/图表/OCR——`多模态/多模态基础概念/02-视觉编码器与图像tokenization.md` 的分辨率权衡）；**影响**（输入分辨率 4 倍、宽高比自适应——感知架构级提升——不动架构只动输入）——**"定义 → 机制 → 问题 → 影响"四段式**（面试通用结构）。

## 6. NeXT 的影响

LLaVA-NeXT 的影响：**动态分辨率成为标配**（后续开源 VLM 普遍采用 AnyRes 类机制——`多模态/多模态基础概念/05-视觉语言模型VLM架构.md` 的 Qwen-VL 动态分辨率同路线）；
**三阶段趋势**（Stage-1.5 的知识学习——`多模态/多模态微调（PEFT）/04-多模态微调配方.md` 的配方演进）；**消融范式**（配方科学化）——**"NeXT 是 1.5 配方到 OneVision 统一的桥梁"**（1.5 定骨架、NeXT 补感知、OneVision 扩场景）。

> 🎯 **核心要点**：AnyRes——子图裁剪动态分辨率（大图切块 + 池化——token 按内容分配——文档图表 OCR 的感知升级——"不动架构只动输入处理"）；Stage-1.5——高质量知识学习（对齐 → 知识 → 指令的三阶段——"先懂内容再学形式"）；系统消融——分辨率/token/数据/底座——"LLM 规模对多模态能力至关重要"（语言维度的实证）；架构保持——三模块 + LLM 自注意力（无交叉注意力）；面试四段式（定义 → 机制 → 问题 → 影响）；影响——动态分辨率成标配/三阶段趋势/消融范式——"NeXT 是 1.5 到 OneVision 的桥梁"。
