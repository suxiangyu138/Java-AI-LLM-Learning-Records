# 多模态模型全景与定位

> 多模态模型家族的类型地图：VLM（理解）、生成模型（创作）、VLA（具身）、统一模型（全模态）——与单模态模型的差异、2026 生态快照——"多模态不是单一模型，是一个家族"

## 1. 类型全景

多模态模型家族按"输入/输出形态"分四大类（2026 全景）：

**视觉语言模型（VLM）**：图像/视频输入 + 文本输出（看图理解/问答/描述）——**理解家族的主流**——GPT-4V、Claude、Gemini、Qwen-VL、LLaVA、InternVL——架构：视觉编码器 + 投影层 + 语言塔（05 篇）；**多模态语言模型（MLLM）**：音频加入（语音理解）——Qwen-OMNI 类。

**多模态生成模型**：文本/图像输入 + 图像/视频/音频输出——**创作家族**——图像生成（DiT 类）、视频生成（Sora 类）、语音生成——架构：扩散 Transformer（DiT）/统一自回归（08 篇）。

**视觉-语言-动作模型（VLA）**：视觉/语言输入 + 动作输出——**具身家族**——机器人/智能体——InstructVLA 类（`多模态/多模态微调（PEFT）/05-多模态微调的类型.md` 04 节）。

**统一模型（Unified）**：任意模态输入 → 任意模态输出——**全模态家族**——NEO-ov（理解统一）、UniAR（图像生成+理解）、Archon（数字人全模态）——2026 前沿（05/08 篇）。

**分类的意义**：**"多模态"不是单一模型，是家族**——理解/生成/具身/统一的架构与能力不同——面试与工程先分清"哪类多模态模型"再谈技术细节。

## 2. 与单模态模型的差异

多模态模型（以 VLM 为例）与文本 LLM 的根本差异（三条）：

**多一个感知层**：输入先过视觉编码器（感知——`多模态/多模态常见问题与缺陷/01-问题全景与诊断方法论.md` 的"不可靠感知层"）——**"模型看到的"可能不是真实的图**（感知缺陷/注意力衰减）；**多一个对齐层**：投影层把视觉特征翻译进语言嵌入空间——**对齐质量决定图文一致**（`多模态/多模态常见问题与缺陷/06-跨模态对齐与语言先验.md`）；**多一种 token**：视觉 token（patch 级——02 篇）与文本 token 共存——**token 成本与计算特性不同**（`多模态/多模态常见问题与缺陷/07-上下文与工程缺陷.md`）。

**推论**：多模态模型 = **LLM + 感知 + 对齐**——文本模型的推理能力 + 视觉的感知能力 + 桥接的对齐质量——**"多模态的能力上限 = 语言能力 × 感知能力 × 对齐质量"**（三者相乘，一项短板拉低整体——这解释了 `多模态/多模态常见问题与缺陷/` 的"强语言掩盖弱视觉"：语言强但感知弱时，整体被感知拖累但表面流畅）。

**"×"关系的工程含义**：**改进短板比加强长板收益大**——感知弱时补感知（换编码器/分块高分辨率）比加强语言更有效——**"能力改进的杠杆在短板"**（与 `大模型微调知识体系/` 的"数据决定天花板"同理——多模态的短板决定整体上限）——排查与训练都要先找短板（`多模态/多模态常见问题与缺陷/01-问题全景与诊断方法论.md` 的三通道定位——语言/视觉/跨模态哪个弱先补哪个）。

## 3. 2026 生态快照

多模态模型的 2026 生态（理解家族为主，`09-多模态能力评估与基准.md` 的基准数据支撑）：

**闭源**：GPT-4V/5 系（CLIP 派生编码器）、Gemini 系（内部编码器——MMMU 72.5 领先）、Claude 系、Qwen-VL-Max（SigLIP + Q-Former + Qwen2，72B——MMMU 67.3）——**闭源仍领先**（数据与训练规模）；**开源**：Qwen3-VL（SigLIP-2 + DeepStack——开源标杆）、LLaVA-NeXT（SigLIP + MLP + Qwen2-7B——开放生态）、InternVL3、Pixtral（原生 ViT 变分辨率）、Molmo（CLIP + Q-Former）、NVLM（OCR 92%）、Llama 3.2 Vision（MetaCLIP）——**开源追赶**（MMMU 48-65 区间）。

**格局判断**：**理解家族成熟**（VLM 是生产主力）；**生成家族活跃**（DiT 统一——08 篇）；**统一家族前沿**（原生架构——05 篇）；**"多模态 Agent"整合**（理解 + 工具 + grounding——07 篇）——2026 年"多模态"的主战场在理解家族的生产落地（RAG/微调/排障体系都围绕 VLM）。

**知识库的"家族分工"**：本仓库的多模态体系（`多模态/` 下各子体系）围绕**理解家族**展开（RAG/微调/数据集/缺陷/概念）——**生成家族与统一家族是知识库的延伸方向**（08 篇给概念基础——生成模型体系若后续建设以此为起点）——**"概念层为全家族服务、应用层聚焦理解家族"**是本体系与其他体系的定位分工。

## 4. 能力维度的定位

多模态模型的能力维度（09 篇的评估框架预览）：**感知**（看见什么——编码器决定）；**理解**（看懂什么——投影 + 语言塔）；**推理**（想通什么——语言塔）；**生成**（创作什么——生成家族）；**对齐**（图文一致——投影与训练）——**每个维度对应本体系的一个章节**（感知→02 篇、对齐→03/04 篇、推理→07 篇、生成→08 篇）——**"能力维度是知识体系的地图"**（读多模态文档时先定位"在讲哪个维度"）。

## 5. 选型的顶层视角

多模态模型选型（`多模态/多模态常见问题与缺陷/09-评估与缺陷检测.md` 的缺陷画像 + `多模态/多模态微调（PEFT）/09-多模态微调评估.md` 的基准）的顶层逻辑：**任务类型**（理解/生成/具身——先定家族）；**能力需求**（感知细粒度？推理强？——按能力维度选）；**资源**（闭源 API vs 开源自部署——显存/成本）；**缺陷容忍**（安全敏感看幻觉/对齐分数）。

**"家族 → 能力 → 资源 → 缺陷"四层选型**是顶层框架（细节在各应用体系）。

**选型的"概念层先行"**：四层选型的第一步"家族"与第二步"能力"都依赖概念层的知识——**不懂 VLM 架构（三组件）无法判断能力需求、不懂对齐（CLIP）无法理解缺陷分数**——**"概念层是选型的理论基础"**（`多模态/多模态微调（PEFT）/01-多模态微调全景与定位.md` 的决策框架与 `多模态/多模态常见问题与缺陷/09-评估与缺陷检测.md` 的缺陷画像都以概念层的架构/对齐知识为地基——本体系是其他体系"为什么"的答案）。

> 🎯 **核心要点**：四大类——VLM 理解（主流）/生成（DiT）/VLA 具身/统一（前沿）——"多模态是家族不是单一模型"；与单模态差异三条——多感知层（不可靠感知）/多对齐层（投影）/多种 token（视觉 token）——"能力上限 = 语言 × 感知 × 对齐"（相乘关系——一项短板拉低整体）；2026 生态——闭源领先（Gemini MMMU 72.5）/开源追赶（Qwen3-VL 标杆/NVLM OCR 92%）；能力维度是知识体系地图（感知→编码器/对齐→投影/推理→语言塔）；选型四层——家族 → 能力 → 资源 → 缺陷。
