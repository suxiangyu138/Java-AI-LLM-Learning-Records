# 视觉语言模型（VLM）架构

> VLM 的架构全景：LLaVA 类模块化（标准范式）、Qwen3-VL（SigLIP-2/Interleaved-MRoPE/DeepStack）、MoE 变体、原生统一（NEO-ov）——"模块化是主流、原生是前沿"

## 1. LLaVA 类模块化：标准范式

**模块化 VLM 的标准架构**（2026 主流——GPT-4V/LLaVA/Qwen-VL/Claude/Gemini 一致）：**视觉编码器 → 投影层 → 语言塔**——图像 → patch 特征（02 篇）→ 投影进语言嵌入空间（04 篇）→ 与文本 token 拼接 → decoder-only Transformer 处理（`大模型微调知识体系/基础概念/03-Transformer与参数基础.md` 的语言塔）。

**流水线一句话**：`图像 → 576 视觉 token → 投影 → [<img>视觉token</img> 文本token] → 语言塔生成回答`——**"模块化 = 三个组件各司其职 + 拼装"**——组件职责（`多模态/多模态微调（PEFT）/02-VLM结构与可微调部件.md` 的塔管感知/投影管对齐/塔管行为）。

**模块化的优势**：**组件可替换**（换编码器/投影/语言塔——演进成本低）；**训练可分阶段**（`多模态/多模态微调（PEFT）/04-多模态微调配方.md` 的两阶段）；**生态成熟**（微调/RAG/部署工具围绕模块化）。

**模块化的代价**：**组件间的不匹配**（编码器特征空间与语言塔嵌入空间的映射质量依赖投影——`多模态/多模态微调（PEFT）/06-多模态微调的常见问题.md` 的对齐漂移）；**融合的浅层性**（单点注入的信息损失——DeepStack 的改进动机——04 篇）；**组件升级的连锁**（换语言塔 = 投影层重新对齐——`多模态/多模态微调（PEFT）/04-多模态微调配方.md` 的阶段一——"模块化的自由度也有成本"）。

## 2. Qwen3-VL：2026 开源标杆

**Qwen3-VL**（2026 家族，2B-235B）——模块化 + 2026 创新的代表：

**架构**：SigLIP-2 ViT 视觉编码器（02/03 篇）+ decoder-only 语言塔 + **多级融合连接**（DeepStack——04 篇）；**Interleaved-MRoPE**（多维旋转位置编码）：位置编码在**时间/高度/宽度三轴交错**（x/y 空间坐标 + 帧序号 t）——**视频与文档定位的改进**（帧间位置与帧内位置同时编码——`多模态/多模态常见问题与缺陷/05-空间与关系推理缺陷.md` 的坐标定位问题在架构侧的缓解）；**文本时间戳对齐**：显式时间戳 token——视频时间推理改进（`多模态/多模态常见问题与缺陷/07-上下文与工程缺陷.md` 的视频时间线缺口在架构侧的进展）。

**规模**：稠密 2B-32B、MoE 235B（30B-A3B 12 专家/层；235B-A22B 64 专家/层 top-2 路由）——上下文最长 256K token；**训练**：四阶段预训练（粗图文对齐 → 区域描述 → 视频时序建模 → 图文视频联合）→ SFT → 强到弱蒸馏（42% 参数保留 98.6% 能力）→ 多维奖励模型 PPO——**"架构 + 训练 + 对齐"的完整配方标杆**。

**Qwen3-VL 的知识库意义**：它同时是**架构标杆**（DeepStack/MRoPE——本体系）与**微调对象**（`多模态/多模态微调（PEFT）/` 的 Qwen 系微调——冻结策略/配方围绕它的三组件）——**"读 Qwen3-VL 技术报告 = 读多模态架构的 2026 综述"**（社区推荐的第一份技术报告——`多模态/多模态基础概念/` 各篇的架构素材来源之一）。

## 3. MoE 变体

**MoE（Mixture of Experts）VLM**：语言塔用专家混合（`大模型微调知识体系/基础概念/03-Transformer与参数基础.md` 的 MoE 概念多模态版）——**Qwen3-VL-235B-A22B**（64 专家 top-2——激活 22B）——**"稀疏激活"**：总参数 235B、每 token 激活 22B——**效果（接近稠密大模型）+ 成本（每 token 只跑 1/10）**。

**MoE VLM 的注意**：**微调**（`大模型微调知识体系/PEFT 参数高效微调（面试高频）/` 的 MoE LoRA——Unsloth 类框架支持 MoE 训练——`大模型微调知识体系/完整微调工程流程/04-环境搭建与工具链选型.md` 01 节）；**显存**（总参数决定——235B 的权重显存仍大——量化/分布式——`大模型微调知识体系/训练关键超参 & 显存优化技术/`）；**部署**（MoE 推理的显存与调度——`多模态/推理部署工程/`）。

**MoE 与多模态的"成本账"**：MoE 的稀疏激活对多模态尤其有价值——**视觉 token 的推理成本高**（`多模态/多模态微调（PEFT）/08-多模态微调工程实践.md` 的"1 图像 token ≈ 数文本 token"）——**MoE 让每个视觉 token 也只激活 1/10 参数**——"多模态的 token 重 + MoE 的每 token 轻"的组合是 2026 大模型多模态推理的成本解药——**"MoE 是多模态成本问题的一个答案"**（与 token 压缩并列——压缩减 token 数、MoE 减每 token 成本——两个杠杆可叠加）。

## 4. 原生统一架构：NEO-ov

**NEO-ov（Native One-Vision，2026）**：挑战模块化范式——**消除所有外部编码器、适配器、事后融合**——单一 monolithic decoder-only transformer：图像通过**轻量卷积 patch 嵌入层**（两层卷积）直接变成视觉 token（包裹 `<img>` 标记）与文本 token 联合处理——**单模型支持单图/多图/视频/空间推理**。

**原生 vs 模块化的现状**（2026）：**原生架构在统一感知任务上仍落后于成熟模块化系统**（NEO-ov 自述）——**"原生是方向、模块化是现实"**——模块化的组件可替换/可分阶段训练优势仍在；原生的"无桥接"消除对齐层（04 篇的桥接消失演进）——**前沿研究、生产未到**。

## 5. 架构选型视角

VLM 架构选型（工程视角）：**生产主力**（模块化——LLaVA 类/Qwen-VL 系——工具链成熟）；**前沿关注**（MoE——大模型成本优化；原生统一——研究跟踪）；**架构与微调的耦合**（组件结构决定冻结策略——
`多模态/多模态微调（PEFT）/02-VLM结构与可微调部件.md`；MoE 的 LoRA 注意——`大模型微调知识体系/PEFT 参数高效微调（面试高频）/`）；**架构与缺陷的耦合**（位置编码/注入方式决定感知与融合——`多模态/多模态常见问题与缺陷/` 的结构根源）。

## 6. 架构演进主线（2026 总结）

VLM 架构的演进主线：**视觉骨干**（CLIP → SigLIP-2——03 篇）；**桥接**（MLP 单点 → DeepStack 跨层 → 原生消失——04 篇）；**位置编码**（1D → MRoPE 三维——
视频/文档）；**规模**（稠密 → MoE 稀疏——235B）；**范式**（模块化 → 原生统一探索）——**"每条主线都在解决一个缺陷或成本问题"**（MRoPE 解空间定位、DeepStack 解融合、MoE 解成本——`多模态/多模态常见问题与缺陷/` 的缺陷是架构演进的第一驱动力——读架构论文时先问"它解决什么缺陷"）。

> 🎯 **核心要点**：LLaVA 类模块化是标准范式（编码器→投影→语言塔——"三组件拼装"——组件可替换/分阶段训练/生态成熟）；Qwen3-VL 是 2026 标杆（SigLIP-2 + DeepStack + Interleaved-MRoPE 三维位置编码解视频文档定位 + 时间戳 token + 四阶段训练 + 蒸馏 98.6%/42% 参数 + MoE 235B）；MoE 变体（稀疏激活——总参 235B 激活 22B——成本优化——微调/显存/部署注意）；原生统一 NEO-ov（无编码器无投影——卷积 patch 嵌入——"原生是方向、模块化是现实"——2026 仍落后）；演进主线——骨干/桥接/位置编码/规模/范式五条线——"每条线都在解决一个缺陷或成本问题"——读架构先问"解决什么缺陷"。
