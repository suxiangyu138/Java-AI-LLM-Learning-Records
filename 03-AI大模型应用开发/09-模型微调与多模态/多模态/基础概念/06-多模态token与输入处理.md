# 多模态 token 与输入处理

> 多模态的"语言单位"：图像 token 序列、视频帧 + 时间戳、音频 token、特殊 token（`<img>`）——token 是算账的货币、模板的要素、成本与上下文的根源

## 1. 图像 token 序列

**图像 token 序列**：图像 → 视觉 token（`<img>` 包裹）→ 与文本 token 拼接成输入序列——**token 数 = (H/patch)×(W/patch)**（02 篇——336²@14 = 576）——**"一张图顶几千字"**（`多模态/多模态常见问题与缺陷/07-上下文与工程缺陷.md` 的 token 账本根源）。

**token 序列的构成**：**特殊 token**（`<img>` 开始/结束标记——模型识别"这是图像"的边界）；**视觉 token**（patch 特征投影——04 篇）；**文本 token**（问题/指令）——**序列形态**：`<img> 576 个视觉token </img> 文本token...`——**模板（`多模态/多模态数据集/07-数据格式与处理.md` 03 节的多模态 chat template）决定 token 序列的排列**。

**图像 token 的三特性**（与文本 token 的关键差异）：**不可切断**（图像是整体——打包/切分时视觉 token 是原子单元——`多模态/多模态数据集/07-数据格式与处理.md` 05 节）；**计算成本高**（1 个图像 token ≈ 数个文本 token 计算——`多模态/多模态微调（PEFT）/08-多模态微调工程实践.md` 01 节）；**维度高**（视觉 token 是连续向量——非词表离散 token——`大模型微调知识体系/基础概念/04-损失函数与训练目标.md` 的交叉熵只算文本 token——**视觉 token 不参与 loss 计算**（它们是输入不是输出））。

## 2. 视频帧与时间戳

**视频的 token 化**：视频 = 帧序列——每帧采样（`多模态/多模态数据集/07-数据格式与处理.md` 02 节的帧采样）→ 每帧视觉 token → **时间维度进序列**：

**时间戳 token（2026）**：显式时间戳 token（Qwen3-VL 的 Textual Timestamp Alignment——`多模态/多模态微调（PEFT）/05-视觉语言模型VLM架构.md` 02 节）——模型知道"第几帧"——**视频时序推理的架构支持**（`多模态/多模态常见问题与缺陷/07-上下文与工程缺陷.md` 的视频时间线缺口在 token 层的解决）；**Interleaved-MRoPE**（三维位置编码——时间/高度/宽度——`多模态/多模态微调（PEFT）/05-视觉语言模型VLM架构.md` 02 节）——**"视频 token 的定位信息 = 时间轴位置编码"**。

**视频的 token 预算**：每帧数百 token × 帧数——**10 秒视频 8 帧 ≈ 数千 token**（`多模态/多模态常见问题与缺陷/07-上下文与工程缺陷.md` 的 token 预算公式——帧数 × 每帧——**视频的 token 成本是图像的数倍**）。

## 3. 音频 token

**音频的 token 化**：音频 → 语音 token（**语音编码器**——Whisper 类 ASR 转文本 / 音频 tokenizer 转离散 token——`多模态/多模态数据集/04-视频与音频数据集.md` 的转写形态）——**音频进 VLM 的两种路径**：**转写路径**（音频 → 文本 → 文本 token——主流——`多模态/多模态 RAG/07-音频与视频RAG.md` 的转写优先）；**原生 token 路径**（音频 → 离散音频 token → 与文本 token 联合——Qwen-OMNI 类全模态模型——**音频 token 的时序对齐**（帧级 token 与文本的对应））。

**音频 token 的注意**：**转写丢失**（说话人/语气——`多模态/多模态 RAG/07-音频与视频RAG.md` 01 节——token 化的信息取舍）；**音频 token 的成本**（音频 token 也是"重 token"——`多模态/多模态微调（PEFT）/08-多模态微调工程实践.md` 的显存账本延伸）——**"音频 tokenization 仍不如图像-文本成熟"**（2026 现状——音视频联合 tokenization 是开放问题，08 篇）。

## 4. 特殊 token 的体系

多模态的特殊 token 体系（`大模型微调知识体系/基础概念/08-指令数据与对话格式基础.md` 的 chat template 多模态版）：**图像标记**（`<img>`/`<image>` 类——
开始/结束）；**视频标记**（`<video>` 类 + 时间戳 token）；**音频标记**（`<audio>` 类）；**位置/坐标 token**（bbox/points/polygons——Qwen2.5-VL 的 grounding 输出——`多模态/多模态微调（PEFT）/07-指令遵循与多模态推理.md` 07 篇）。

**"特殊 token 是模板的骨架"**——训练与推理必须同模板（`多模态/多模态数据集/07-数据格式与处理.md` 03 节的模板一致性——**多模态模板错误 = 模型不认识图像标记 = 输出垃圾**——`大模型微调知识体系/微调常见问题/02-模板与格式类问题.md` 的多模态版——模板问题在多模态更隐蔽：图像标记错位不像文本模板那样肉眼可见）。

## 5. token 压缩与效率

**token 压缩（2026 热点）**：视觉 token 太多 → 上下文/成本压力——三路线：**投影压缩**（LDPNet-V2——144 token 同效果——04 篇）；**合并降采样**（Qwen2.5-VL 的 28×28 patch 合并 2×2——token 减 4 倍）；**动态分配**（Pixtral 变分辨率——按图像复杂度分配 token——02 篇）——**"压缩 vs 感知的权衡"**（压缩丢细节——`多模态/多模态常见问题与缺陷/02-视觉感知缺陷.md` 的感知边界——**"压缩的极限由任务细节需求定"**）。

**压缩的工程价值**：上下文节省（多图/长文档场景）；计算节省（`多模态/多模态微调（PEFT）/08-多模态微调工程实践.md` 的吞吐——**"token 压缩是成本优化的第一杠杆"**——比换模型便宜）。

**压缩的验证纪律**：压缩方案（换投影/降采样/动态分配）是"有损变更"——**压缩后必须跑感知回测**（`多模态/多模态常见问题与缺陷/02-视觉感知缺陷.md` 的感知专项——"压缩省了 token 但感知掉了吗"——用 HoloCount 类小样本验证——**"省成本不能以感知崩坏为代价"**——`多模态/多模态微调（PEFT）/09-多模态微调评估.md` 的缺陷线门禁在压缩场景的复用）。

## 6. token 处理的一致性纪律

多模态 token 处理的一致性（`多模态/多模态数据集/07-数据格式与处理.md` 的验收）：**训练-推理一致**（模板/分辨率/帧采样三一致——训练 512 推理 1024 = 模型看到不同的图）；
**打包约束**（视觉 token 不可切断——`多模态/多模态数据集/07-数据格式与处理.md` 05 节）；**渲染 diff 的图像版**（训练推理的 token 序列逐位对比——`大模型微调知识体系/基础概念/08-指令数据与对话格式基础.md` 03 节）——**"token 处理的一致性 = 模型行为的确定性"**（不一致 = 模型在推理时看到没见过的东西）。

> 🎯 **核心要点**：图像 token 序列——`<img>` + 576 视觉 token + 文本（模板决定排列）；三特性——不可切断（原子单元）/计算成本高（1 图像 ≈ 数文本）/维度高（视觉 token 是输入不参与 loss）；视频——帧采样 + 时间戳 token（Qwen3-VL）+ MRoPE 三维定位——视频 token 成本 = 帧数 × 每帧；音频——转写路径（主流）vs 原生 token 路径（Qwen-OMNI）——音视频 tokenization 仍不成熟；特殊 token 体系（图像/视频/音频/坐标标记）——模板骨架——一致性铁律；token 压缩三路线（投影/合并/动态）——"压缩 vs 感知权衡"——成本优化第一杠杆；一致性纪律——训练推理三一致 + 打包约束 + 渲染 diff。
