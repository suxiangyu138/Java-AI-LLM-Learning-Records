# 投影层与视觉-语言桥接

> 多模态的"翻译官"：MLP/Q-Former/LDPNet 三种投影、token 压缩（144 vs 576）、特征注入（DeepStack 跨层融合）——"桥接的质量决定图文一致"

## 1. 投影层是什么

**投影层（Projector/Connector）**：把视觉编码器的特征"翻译"进语言模型的嵌入空间——**视觉-语言的桥**——视觉特征（patch 级向量）与语言嵌入（token 级向量）**维度不同、语义空间不同**——投影层做映射（`多模态/多模态微调（PEFT）/02-VLM结构与可微调部件.md` 的"投影层管对齐"——结构上的对齐载体）。

**桥接的形态**：**MLP 投影**（简单两层 MLP——`mlp2x_gelu` 类——LLaVA/Pixtral/Qwen-VL 系）；**Q-Former**（12 层 transformer——把图像 patch 压缩成 32 个可学习查询 token——BLIP-2/InstructBLIP/Qwen-VL-Max）；**LDPNet-V2**（2026——144 token 达到 576 token 的效果——压缩桥接）——**"桥的类型决定 token 数量与对齐质量"**。

**桥接的微调地位**：投影层是 `多模态/多模态微调（PEFT）/` 中"总是可训练"的组件（`多模态/多模态微调（PEFT）/02-VLM结构与可微调部件.md` 的 non_lora_trainables）——**"桥是任务校准的第一旋钮"**（比语言塔更轻量、比视觉塔更安全——任务相关的对齐校准先动桥）——两阶段配方的阶段一主角（`多模态/多模态微调（PEFT）/04-多模态微调配方.md`）。

## 2. 三种投影的对比

| 投影 | 机制 | token 数 | 使用者 | 特点 |
|------|------|:---:|--------|------|
| MLP | 两层 MLP 直接映射 | 576（不压缩） | LLaVA/Qwen-VL | 简单、不压缩、token 多 |
| Q-Former | 查询 token 压缩 | 32 | BLIP-2/Qwen-VL-Max | 强压缩、需对齐训练 |
| LDPNet-V2 | 轻量压缩 | 144 | 2026 研究 | 4-5 倍少 token 同效果 |

**对比实证**（12 种投影配置——Qwen-3B/7B × CLIP/SigLIP × 三种投影）：**最佳（MM-Bench 81.4%）是 Qwen-7B + SigLIP + LDPNet-V2（仅 144 token）**——比 MLP 少 4-5 倍 token 还更好；Q-Former 只到 73.5%（训练数据不足时受限）——**"投影不是越复杂越好，token 压缩与对齐质量要平衡"**。

**实证的读法**：**编码器与投影的协同**（最佳组合是 SigLIP + LDPNet——编码器质量与投影压缩协同——单换一个不够）；**投影与训练数据的耦合**（Q-Former 的 73.5% 是"训练数据不足"——复杂投影需要更多对齐训练——`多模态/多模态微调（PEFT）/04-多模态微调配方.md` 的阶段一数据量决定投影选择——**"投影的复杂度要匹配可用的对齐数据"**——数据少的项目别选 Q-Former 类重投影）。

**token 压缩的意义**：144 vs 576 token——**上下文节省 4 倍**（`多模态/多模态常见问题与缺陷/07-上下文与工程缺陷.md` 的 token 账本——长文档多图场景 token 预算翻倍）；**计算节省**（视觉 token 计算成本——`多模态/多模态微调（PEFT）/08-多模态微调工程实践.md` 的吞吐——**"投影层的选择是成本与质量的平衡"**）。

## 3. 特征注入：在哪里"放"视觉特征

投影后的视觉 token **注入语言塔的位置**是桥接的另一半：

**单点注入（经典）**：视觉 token 拼在文本 token 前面（`<img>特征</img> 文本`——LLaVA 类）——**简单但有两个问题**：**浅层注入的注意力坍缩**（视觉 token 全堆在开头——注意力集中在视觉区）；**顶层融合的语义扭曲**（只在最后注入——视觉语义与语言语义融合不充分）。

**DeepStack 跨层融合（2026，Qwen3-VL）**：**ViT 多个抽象层的特征（如 1/3/5 层）注入语言塔的前几层**（cross-attention + 自适应门控）——**"多层次、跨层注入"**——解决浅层注入坍缩与顶层注入扭曲——**实证：显存 -37%、推理延迟 -29%、VQA/RefCOCO/TextCaps 分数提升**——**"注入位置是融合质量的架构决定"**（`多模态/多模态微调（PEFT）/06-多模态微调的常见问题.md` 的融合破坏在架构侧的对应：融合编码在语言塔下半层——DeepStack 的设计与此呼应）。

## 4. 桥接的微调视角

投影层在微调中的角色（`多模态/多模态微调（PEFT）/` 的组件职责）：**两阶段配方的阶段一主角**（只训投影层对齐——`多模态/多模态微调（PEFT）/04-多模态微调配方.md` 的 lr 1e-3）；
**总是可训练**（SafeMLLM 的 non_lora_trainables——`多模态/多模态微调（PEFT）/02-VLM结构与可微调部件.md` 02 节）；**对齐漂移的旋钮**（投影层被改写 → 对齐漂移——`多模态/多模态微调（PEFT）/06-多模态微调的常见问题.md` 03 节——对齐敏感时冻结投影层）。

**换投影层的代价**：换投影 = 重新对齐（阶段一重训——`多模态/多模态微调（PEFT）/04-多模态微调配方.md` 的"换编码器/投影层时需要阶段一"）——**"投影层的选择是低频高成本决策"**（改一次重新对齐——选型要慎重）。

## 5. 桥接与缺陷

桥接质量与缺陷的对应（`多模态/多模态常见问题与缺陷/` 的结构根源）：**对齐问题**（图文矛盾/引用错误——`多模态/多模态常见问题与缺陷/06-跨模态对齐与语言先验.md`——桥接弱时视觉特征"翻译"不到位——
模型"看见了但没用对"）；**融合破坏**（`多模态/多模态微调（PEFT）/06-多模态微调的常见问题.md` 01 节——微调改写桥接路径——层选择性 LoRA 保护）；**token 压缩的信息损失**（强压缩投影丢细节——小物体/细粒度感知——`多模态/多模态常见问题与缺陷/02-视觉感知缺陷.md`——"压缩与感知的权衡"）。

## 6. 桥接的 2026 演进

**跨层注入（CLI，ECCV 2026）**：一对一桥接 → **动态多对多连接**（每个语言塔层按需查询完整视觉层次）——AMP（基于 LoRA 的自适应多投影——调和不同视觉层的特征）+ AGF（自适应门控融合）——LLaVA-OneVision/1.5 上验证、仅 1.3% 推理显存开销；**原生统一架构的桥接消失**（NEO-ov——无投影层——图像直接 patch 卷积嵌入进语言 token 流——`多模态/多模态微调（PEFT）/05-视觉语言模型VLM架构.md` 05 篇）——**"桥接从单点 → 跨层 → 消失"的演进线**（模块化的桥接被原生统一挑战）。

> 🎯 **核心要点**：投影层 = 视觉-语言翻译官（维度/语义空间映射——`多模态/多模态微调（PEFT）/02-VLM结构与可微调部件.md` 的对齐载体）；三种投影——MLP（576 token 不压缩）/Q-Former（32 token 强压缩）/LDPNet-V2（144 token 同效果——MM-Bench 81.4% 最佳——"压缩与质量平衡"）；特征注入——单点注入的两问题（浅层坍缩/顶层扭曲）→ DeepStack 跨层融合（多层特征注入前几层 + 门控——显存 -37%/延迟 -29%——"注入位置决定融合质量"）；微调视角——阶段一主角/总是可训练/换投影 = 重新对齐（低频高成本决策）；桥接与缺陷——对齐问题/融合破坏/token 压缩信息损失；演进——CLI 动态多对多 → 原生统一桥接消失——"单点 → 跨层 → 消失"。
