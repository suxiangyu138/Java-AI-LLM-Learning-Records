# 视觉编码器与图像 tokenization

> 多模态的"眼睛"：ViT 视觉编码器、patch 与视觉 token、分辨率与 token 数（336×336@14 = 576）、编码器家族（CLIP/SigLIP/Pixtral）——感知能力的结构根源

## 1. 视觉编码器：图像怎么变成特征

**视觉编码器（Vision Encoder）**：把图像像素变成特征向量的模型——VLM 的"眼睛"——主流形态是 **ViT（Vision Transformer）**：图像切成 **patch（图像块）**（如 14×14 像素一块）→ 每个 patch 线性投影成向量 → 经过 Transformer 层（自注意力——`大模型微调知识体系/基础概念/03-Transformer与参数基础.md` 的架构在视觉上的应用）→ 输出 patch 级特征。

**关键认知：patch 粒度决定感知上限**——patch 14 意味着"14×14 像素内的小物体/细节"被压缩成一个向量——**感知缺陷（`多模态/多模态常见问题与缺陷/02-视觉感知缺陷.md` 的小物体 <32px）的结构根源在 patch 粒度**——"编码器看不见的，模型永远看不见"（`多模态/多模态微调（PEFT）/03-LoRA在多模态上的应用.md` 的"塔 LoRA 是校准不是魔法"由此而来）。

## 2. 视觉 token：patch 级特征

**视觉 token（Visual Tokens）**：patch 级特征向量——图像进语言模型的"语言单位"——**token 数 = (H/patch) × (W/patch)**：

**实例**：336×336 图像、patch 14 → **24×24 = 576 个视觉 token**；1024×1024、patch 14 → 73×73 ≈ 5329 个（高分辨率爆炸）；Qwen2.5-VL 的 28×28 patch 合并 2×2 → token 数减少约 4 倍——**"分辨率 × patch 决定 token 预算"**——这是 `多模态/多模态常见问题与缺陷/07-上下文与工程缺陷.md` 的 token 账本（一张图 576 token ≈ 顶几千字）的根源。

**视觉 token 的特性**：**不可压缩为文本**（是连续向量——`多模态/多模态微调（PEFT）/07-多模态偏好对齐DPO.md` 的"图像 token 不可切断"）；**计算成本高于文本 token**（`多模态/多模态微调（PEFT）/08-多模态微调工程实践.md` 的"1 个图像 token ≈ 数个文本 token 计算"——视觉 token 走完整的视觉-语言处理路径）。

**视觉 token 与文本 token 的本质差异**：文本 token 来自**离散词表**（可枚举——`大模型微调知识体系/基础概念/04-损失函数与训练目标.md` 的交叉熵在词表上）；视觉 token 是**连续向量**（不可枚举——来自图像的投影）——**"文本 token 是离散的符号、视觉 token 是连续的感知"**——这个差异解释了：**loss 只算文本 token**（连续向量无法做分类损失——除非离散化——08 篇 UniAR 的 BSQ 视觉 tokenizer 正是"把视觉连续向量离散化"——统一理解与生成的关键）；**检索的相似度计算**（视觉 token 用余弦/内积而非词表匹配——`多模态/多模态 RAG/02-视觉检索基础.md`）。

## 3. 编码器家族（2026）

| 编码器 | 训练 | 使用者 | 特点 |
|--------|------|--------|------|
| CLIP | 对比学习（03 篇） | LLaVA/InternVL/GPT-4V | 细粒度理解基准 |
| SigLIP | sigmoid 损失 | PaliGemma/LLaVA-NeXT | 更稳更高效 |
| SigLIP-2 | 鲁棒对比 | **Qwen3-VL** | 零样本/局部语义/遮挡鲁棒/跨域泛化 |
| Pixtral-ViT | 原生 | Pixtral（1B） | **变分辨率设计** |
| MetaCLIP | 数据驱动 | Llama 3.2 90B Vision | 数据组合改进 |

**选型要点**：**CLIP/SigLIP 是 VLM 的主流骨干**（SigLIP 是 CLIP 的现代改进——sigmoid 损失训练更稳，03 篇）；**Pixtral 的变分辨率**（不同分辨率图像不同 patch 分配——解决固定分辨率的信息浪费）；**SigLIP-2 的鲁棒性**（遮挡/局部语义——`多模态/多模态常见问题与缺陷/02-视觉感知缺陷.md` 的感知缺陷缓解在编码器侧的进展）。

**编码器的"任务匹配"**：通用图文（CLIP/SigLIP 足够——语义对齐）；细粒度感知密集（文档/医学——高分辨率/变分辨率编码器优先——`多模态/多模态微调（PEFT）/05-多模态微调的类型.md` 的文档任务选型）；视频（视频编码器——时间维度——`多模态/多模态微调（PEFT）/06-多模态token与输入处理.md` 的帧处理）——**"编码器按任务的感知需求选"**（与 `多模态/多模态微调（PEFT）/03-LoRA在多模态上的应用.md` 的"感知需求决定塔 LoRA"同构——编码器是感知的硬件、塔 LoRA 是感知的软件）。

## 4. 分辨率与感知的权衡

**分辨率的双刃**：**高分辨率** → 更多 token（细节可见但成本爆炸——1024² 约 5329 token）；**低分辨率** → 少 token（便宜但细节丢失——`多模态/多模态常见问题与缺陷/02-视觉感知缺陷.md` 的小物体硬边界）。

**2026 解法**：**变分辨率**（Pixtral 类——按图像内容分配 patch——简单图少 token、复杂图多 token）；**动态分辨率**（Qwen2.5-VL 类——保持宽高比缩放到模型支持的分辨率集合）；**分块高分辨率**（`多模态/多模态 RAG/04-文档解析与预处理.md` 的大图切块——细节任务分块处理）；**token 压缩**（04 篇的 LDPNet——144 token 达到 576 token 的效果）——**"分辨率策略 = 细节需求 × 成本预算"**（`多模态/多模态数据集/07-数据格式与处理.md` 01 节的预处理）。

## 5. 编码器与感知缺陷

感知缺陷（`多模态/多模态常见问题与缺陷/02-视觉感知缺陷.md`）的编码器根源：**计数失败**（高密度场景——patch 粒度无法区分重叠物体——Halo effect 的注意力机制在编码器层）；
**小物体**（<32px——patch 14 时 2 个 patch 都不到——信息被压缩丢失）；**OCR 弱**（`多模态/多模态常见问题与缺陷/04-OCR与文档理解缺陷.md` 的字符形状感知——patch 粒度对细文字不友好）——**"编码器是感知缺陷的第一根源"**——缓解的输入侧手段（分块/放大/高分辨率）本质是"绕过编码器的粒度限制"（`多模态/多模态常见问题与缺陷/02-视觉感知缺陷.md` 05 节的工程应对）。

## 6. 编码器的微调视角

编码器在微调中的角色（`多模态/多模态微调（PEFT）/02-VLM结构与可微调部件.md` 的组件职责）：**默认冻结**（两个理由——浪费适配器/破坏对齐——02 篇）；**专门视觉域才训**（塔 LoRA——
`多模态/多模态微调（PEFT）/03-LoRA在多模态上的应用.md` 03 节——显微镜等感知需求超出通用编码器）；**换编码器的代价**（换编码器 = 重新对齐投影层——`多模态/多模态微调（PEFT）/04-多模态微调配方.md` 的"阶段一在对齐换编码器时需要"）——**"编码器的选择是感知能力的上限选择"**（换编码器比塔 LoRA 是更大的感知跃迁——代价是重新对齐）。

> 🎯 **核心要点**：视觉编码器 = VLM 的眼睛（ViT——图像切 patch → Transformer → patch 特征）；**patch 粒度决定感知上限**（感知缺陷的结构根源——14×14 patch 内细节被压缩）；视觉 token = patch 特征（token 数 = (H/patch)×(W/patch)——336²@14 = 576——`多模态/多模态常见问题与缺陷/07-上下文与工程缺陷.md` 账本的根源）；编码器家族——CLIP/SigLIP 主流、SigLIP-2 鲁棒（Qwen3-VL）、Pixtral 变分辨率；分辨率权衡——高分辨率细节 vs token 成本——2026 解法（变分辨率/动态分辨率/分块/token 压缩）；感知缺陷的编码器根源（计数/小物体/OCR 都是 patch 粒度问题——输入侧缓解是"绕过粒度限制"）；微调视角——默认冻结/专门视觉域训塔/换编码器是感知跃迁（代价重新对齐）。
