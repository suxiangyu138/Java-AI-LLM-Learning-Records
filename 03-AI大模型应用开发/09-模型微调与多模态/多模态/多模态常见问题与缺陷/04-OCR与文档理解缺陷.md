# OCR 与文档理解缺陷

> MLLM 的 OCR 弱点全景：字符形状感知弱（靠语义猜词）、版面/手写体/扫描件、对文档应用的影响——以及"专用 OCR 优先"的工程结论

## 1. MLLM 的 OCR 为什么弱

MLLM（多模态大模型）的 OCR 能力与专用 OCR 有本质差异——2026 研究（"On the Hidden Mystery of OCR in Large Multimodal Models"）的核心发现：**MLLM 主要依赖语义理解来识别单词，对单个字符形状的感知能力差**——"认字靠猜意思，不是看字形"。

**表现**：常见词/上下文词识别好（语义辅助）、生僻词/无上下文词识别差（只能看字形——正好是弱项）；**感知基准（PerceptionBench）**：OCR 类目最强的 Claude-Fable-5 与 Gemini-3.1-Pro 也只有 64.3%——**MLLM 的 OCR 是"语义猜词"，不是"字形识别"**。

**与专用 OCR 的对比**：专用 OCR（PaddleOCR/Tesseract 类，`多模态/多模态 RAG/04-文档解析与预处理.md`）是字形识别优先（字符级模型）——**"字形准确率"MLLM 不如专用 OCR，但"语义理解"专用 OCR 没有**——**OCR 任务的正确姿势：专用 OCR 负责识字、MLLM 负责理解**（各用所长）。

## 2. 文档理解的具体缺陷

文档场景（PDF/扫描件/截图）中 MLLM 的四个高频缺陷：

**版面理解错**：多栏文档的阅读顺序错乱（MLLM 按视觉顺序读，非语义顺序）；页眉页脚/表格与正文的边界混淆——**"版式结构"是视觉布局问题，MLLM 的布局感知弱于专用版面分析**（LayoutLM 类，`多模态/多模态 RAG/04-文档解析与预处理.md` 03 节）。

**表格读错**：行列对应错（MLLM 读表常"读一行漏一行"或列错位——与计数缺陷同源：细粒度空间区分弱）；合并单元格结构丢失——**表格任务专用表格解析（Table Transformer 类）更可靠**（`多模态/多模态 RAG/06-表格与图表RAG.md`）。

**手写体**：手写文字识别率显著低于印刷体（字形变化大，语义辅助失效——手写没有"常见词"的稳定形态）；**扫描件质量敏感**：低分辨率/倾斜/阴影扫描件识别率骤降（感知边界，02 篇）。

**数字与符号**：数字串（金额/账号/日期）与特殊符号识别错误——**语义辅助对数字无效**（数字没有"意思"可猜）——"1 与 7、0 与 O"混淆是高频错误——**文档场景的数字错误代价最高**（金额/日期错 = 业务事故）。

## 3. 对多模态 RAG 的影响

OCR 缺陷直接影响文档 RAG（`多模态/多模态 RAG/`）——**"检索到的页面文字是错的"**：ColPali 检索页面（像素级，不受 OCR 缺陷影响）后，抽取阶段用 OCR/解析——**OCR 错误进入回答**（`多模态/多模态 RAG/04-文档解析与预处理.md` 的"解析保真度链"——OCR 是抽取的输入，错了回答就错）。

**2026 组合姿势的缺陷视角**：ColPali 的像素检索绕开了 OCR 的"检索阶段缺陷"（不 OCR 也能找到页面）；但**抽取阶段仍依赖 OCR/解析**（页面找到了，文字还得读出来）——**"检索绕开 OCR、抽取离不开 OCR"**——抽取的 OCR 缺陷是文档 RAG 的残余短板（数字/手写/扫描件——高价值错误集中区，`多模态/多模态 RAG/07-音频与视频RAG.md` 的"高风险实体校验"思想在此复用：数字/日期/金额抽取后抽验）。

## 4. 缓解：什么时候用 MLLM 的 OCR、什么时候用专用 OCR

**选型判据**（按任务）：

| 任务 | 选择 |
|------|------|
| 通用文档文字抽取 | 专用 OCR（PaddleOCR 类，字形优先） |
| 语义理解（这段文字讲什么） | MLLM（理解是强项） |
| 数字/账号/日期抽取 | 专用 OCR + 后校验（数字语义辅助无效） |
| 手写体 | 专用手写 OCR（专用模型）或 MLLM 兜底（两者都弱，按模型选） |
| 复杂版面（多栏/表格） | 专用版面分析 + 专用表格解析（结构优先） |
| 端到端文档问答 | MLLM（检索/解析组件输出结构化事实后） |

**核心结论**：**"识字"用专用 OCR、"理解"用 MLLM**——端到端"图直接问"只在文档简单时可靠；生产文档应用的标准姿势是**解析管线（专用工具）输出结构化事实 → MLLM 基于事实回答**（与 03 篇的"检测-生成分离"同构——**感知任务与推理任务分离是文档应用的第一原则**）。

**多语言与特殊文档**：MLLM 的 OCR 在多语言场景的"语义猜词"失效更明显（非母语词汇没有语言先验可猜——只能看字形）——**多语言文档的 OCR 选型：语言专属 OCR 或按语言路由**（`多模态/多模态 RAG/03-ColPali与后期交互.md` 的"像素检索语言无关"对比——检索可以不 OCR、抽取必须按语言选 OCR）；**表单/票据类**（结构化版式）——专用表单解析（模板 + OCR 字段定位）远比 MLLM 直接读可靠——**"文档类型决定工具组合"**（复杂文档 = 解析管线 + MLLM 理解层）。

## 5. OCR 缺陷的验证与监控

文档应用的 OCR 缺陷监控：**高风险实体抽验**（数字/日期/金额——抽取后自动校验（与原文比对或规则校验）——"金额与格式不符"类规则能抓一批）；**OCR 置信度记录**（专用 OCR 的置信度分数随结果存储——低置信度区域标记人工复核）。

**端到端正确率回归**（文档问答的抽取正确率——"数字类问题的回答正确率"是独立监控指标——`多模态/多模态 RAG/09-多模态RAG评估与挑战.md` 的检索先行纪律的文档版：**抽取先行**——抽取错了回答必错）。

## 6. 2026 现状总结

MLLM 的 OCR 在**语义辅助场景**可用（常见词、上下文明确）——**在字形依赖场景不可靠**（生僻词、数字、手写、低质量扫描）——2026 年没有"MLLM 的 OCR 赶上专用 OCR"的迹象（语义猜词机制决定）；**文档任务的工程结论**：解析管线（专用工具）仍是生产标配，MLLM 是"理解层"不是"识别层"——**"识别归专用、理解归 MLLM、数字必校验"**是文档应用的十二条军规。

> 🎯 **核心要点**：MLLM OCR 弱在"字形感知"（语义猜词机制——生僻词/数字/手写失效）；感知基准 OCR 最强仅 64.3%；文档四缺陷——版面顺序/表格错位/手写与扫描/数字符号（数字无语义可猜、错误代价最高）；对 RAG 的影响——检索绕开 OCR（ColPali 像素）、抽取离不开 OCR（残余短板，数字抽验补）；选型判据——识字专用 OCR、理解 MLLM、数字必校验、复杂版面专用分析；核心结论——"识别归专用、理解归 MLLM、数字必校验"；监控——高风险实体抽验 + 置信度记录 + 抽取先行评估。
