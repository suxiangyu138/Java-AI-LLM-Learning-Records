# 常见问题面试题

> 面试官最爱问"你微调时踩过什么坑、怎么排查的"——排障类面试题考的不是知识，是方法论：症状→诊断→修复的完整闭环 + 2026 最新案例

## 1. 必问基础 8 题

### Q1：微调踩过最大的坑是什么？怎么排查的？

**答案**（推荐组合答案）：讲**chat template 不匹配**（2026 第一大静默杀手）——症状是训练 loss 正常下降、评估正常，但推理输出垃圾/工具调用 0 次；排查用**渲染 diff**（同一样本分别用训练/推理模式渲染成 token 序列逐字节对比，发现角色标记/think 块不对称）+ nonce 测试（4 样本 + 不可能标签，模型背题都做不到 = 链路有问题）；修复后把"渲染抽检 + 对称性验证"写进启动检查清单。

**加分点**：用 2026 真实案例（Qwen3 的 think 块在工具轮次被丢弃，修复只需两行；Gemma4 新模板与 Unsloth 旧模板不匹配）——案例比方法更有说服力。

### Q2：训练 loss 不降，怎么排查？

**答案**：原因树按概率排——数据问题（第一嫌疑：masking 掩错位置/标签错位/样本单一——nonce 测试 + 单样本过拟合测试验证）→ 学习率过低（看 lr 曲线、临时升 3-5 倍诊断）→ 梯度被掩码吞掉（grad norm 为 0）→ 损失计算问题（loss 恒为常数 = 权重没更新）。纪律：一次只改一个变量、小步快跑验证、修复进 git。

### Q3：训练出现 NaN 怎么办？

**答案**：立即停（止损）→ 按序排查——学习率过高（降 3-5 倍，最常见）→ 数据问题（NaN/脏样本）→ fp16 溢出（换 bf16，2026 标准）→ 优化器状态错位（断点恢复错误）。细节：**定位第一个 NaN 的 step**（wandb 曲线），从 NaN 前的 checkpoint 重训而不是从头。

### Q4：微调后模型变笨了（通用能力退化），什么原因？怎么处理？

**答案**：灾难性遗忘——小数据 + 大模型 + 多 epoch 的高危组合（`../基础概念/09-评估基础损失曲线与过拟合.md` 03 节）。检测：通用能力回测（微调前后同一组通用题）+ 标准基准回归检查（>1-2% 即确认）。修复按序：降 epoch（1-2）→ 混入 ~10% 通用数据（`../数据集体系（非常重要）/08-数据平衡与多样性.md` 05 节）→ 低学习率 → LoRA 冻结底座。2026 机制补充：持续训练里的**神经元替换/剪枝**是遗忘元凶（只增不改实验：0.00% vs 8.34% 掉点）。

### Q5：OOM 怎么调试？为什么按这个顺序？

**答案**：五步按序——QLoRA（省 75% 显存，最大杠杆）→ 降 batch（降到 1，配梯度累积）→ 梯度检查点（省 30% 费 20% 速度）→ 降 max_seq_length（激活值随长度线性增长）→ 换小模型。顺序逻辑：前四步"保留方案"（不改模型与效果假设），第五步才"改变方案"——每步都有显存账本依据（`../基础概念/03-Transformer与参数基础.md` 05 节）。

### Q6：量化后模型变差了，但 PPL 没怎么变，为什么？

**答案**：**PPL 是平均预测质量，量化损伤是特定能力损坏**——两者不相关（2026 实锤：PPL 只动 0.04、多步任务完成率掉 7 点、约束保持率崩 19 点，失败集中在长序列）。量化误差集中在注意力投影（长程依赖关键路径）。修复：领域评估集（含长序列/多步的程序化 pass/fail）做硬门禁，PPL/MMLU 不能当验收指标；换量化方案（GPTQ → AWQ + 长序列校准样本，恢复至 79.3%）；终极方案 QAT（恢复 45-70% 损失，2/3-bit 必须）。

### Q7：微调后训练集表现好、上线效果差，怎么排查？

**答案**：按序查四个方向——**评估与训练同源泄漏**（评估集与合成训练数据同 seed，评估虚高；先建评估集再生成训练数据）→ **train-serve 精度不匹配**（BF16 训 INT4 服务：同一适配器 BF16 23 胜、INT4 2 胜——训练时就把部署精度计入）→ **评估走服务路径**（评估用训练内存态 vs 上线产物不一致）→ **评估集与真实请求分布错位**（线上请求 embedding 与评估集分布对比）。核心原则："上线产物用什么配置评估，就用什么配置服务"。

### Q8：排查问题的方法论是什么？

**答案**：五步法——**复现**（最小场景 + 完整错误信息）→ **隔离**（换组件定位环节）→ **假设**（按概率排序，一次验一个）→ **验证**（最便宜的实验：nonce 测试/渲染 diff/小步数冒烟）→ **记录**（修复进 git + debug 记录沉淀）。元纪律：**先诊断再动手**（别用改配置掩盖 bug）；止损优先（判定训练已坏该停就停）。

## 2. 排障场景题

**场景一**："训练 2 小时后发现 eval loss 反弹、train loss 还在降，模型开始复读训练数据，怎么办？"——过拟合三信号（train→0/eval 背离/复读）：立即 early stopping，用 `load_best_model_at_end` 找回最优 checkpoint；下一轮降 epoch（3→1-2）或降学习率；查数据重复率（重复样本是复读根源，`../数据集体系（非常重要）/05-数据去重与污染检测.md`）。

**场景二**："微调模型在 benchmark 上 21:11 赢过小模型，上线后 2:23 惨败，用户投诉主语错乱，怎么查？"——train-serve 精度不匹配（2026 经典案例）：第一动作拿同一适配器在 BF16 底座与 INT4 底座分别评估对比（23 胜 vs 2 胜 = 确认）；修复：训练与部署精度对齐（QAT 或部署 BF16）；教训：benchmark 只测训练精度，**部署精度评估要进评估矩阵**（评估走服务路径）。

**场景三**："工具调用微调后，模型偶尔不调用工具直接编答案，怎么定位？"——按序查：模板渲染 diff（工具轮次的角色标记/think 块对称性——Qwen3 案例：工具轮次裸渲染导致模型学到错误格式线索）；工具数据边界（失败案例缺失——模型没见过"该调用却调用不了"的处理）；stop token 掩码（EOS 不在掩码内 = 无限生成干扰）。修复对应：模板统一 → 数据补失败案例 → 掩码修正。

## 3. 答题范式总结

排障题标准答题结构（四步）：**讲症状**（具体现象 + 什么正常什么不正常——"loss 正常下降但推理崩"比"模型坏了"专业）→ **给诊断**（有序假设 + 验证手段——渲染 diff/nonce 测试/精度对比）→ **讲根因**（2026 案例佐证：模板不对称/train-serve 错配/PPL 掩盖）→ **说预防**（检查清单/门禁/对齐——"预防"是排障答案的加分终章）。

> 🎯 **核心要点**：排障面试 = 8 题全覆盖（模板杀手/数据泄漏/NaN/OOM/遗忘/量化损伤/上线变差/五步法）+ 3 场景题（过拟合/精度错配/工具调用）；答题四步 = 症状→诊断→根因（带 2026 案例）→预防；**面试官要的不是答案，是方法论**——"先诊断再动手 + 一次一个变量 + 修复进 git"的纪律比背过的案例更值钱；进阶追问导向数据体系（泄漏/去重）与工程流程（门禁/服务路径）——排障能力是微调经验的最佳证明。
