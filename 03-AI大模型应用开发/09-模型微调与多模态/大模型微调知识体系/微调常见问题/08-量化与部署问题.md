# 量化与部署问题

> 部署期的坑最贵（已上线才发现）：量化损伤 PPL 看不见、LoRA+量化底座组合偶发失败、合并精度错误、服务行为与评估不一致——领域评估是硬门禁，QAT 是终极方案

## 1. 量化质量损失：PPL 看不见的损伤

**症状**：量化后 PPL 几乎没动（3.81 → 3.85）、MMLU 只掉 0.5，但**多步任务完成率掉 7 点**（81.2% → 74.1%）、约束保持率崩 19 点（88% → 69%）——失败集中在长序列（6+ 步，模型要在 ~400 token 内保持约束），恰好是 Agent 工作流最看重的能力。

**根因**：量化误差集中在注意力投影（长程依赖的关键路径）——PPL 是"平均预测质量"，量化损伤是"特定能力损坏"，两者不相关。

**诊断与修复**：**PPL 和通用基准（MMLU）不能当量化验收指标**——领域评估集（含长序列/多步任务的程序化 pass/fail 检查）才是硬门禁（`../完整微调工程流程/08-模型评估与验收.md` 01 节）；换量化方案（案例：GPTQ → AWQ + 1024 条偏长序列校准样本，恢复至 79.3%）；候选构建与 FP16 参考后端做影子对比（shadow test）。

## 2. LoRA + 量化底座：组合偶发失败

**症状**：同一 LoRA 适配器在不同底座上行为迥异——2026 实锤案例：Llama-3.1-8B AWQ 量化底座 + LoRA 服务，45% 请求的预期标签不在 top-20 logprobs、AUROC 从 0.98 崩到 0.58；**同一套 LoRA 在 AWQ 的 Mistral 上正常（0.97），AWQ 底座不加 LoRA 也正常**——失败是"Llama × AWQ × LoRA"三重交集特有（同底座的 FP8/NVFP4 量化则正常）。

**结论**：**量化方案必须与微调适配器联合验证**——不能假设"量化 OK + LoRA OK = 组合 OK"；上线前用领域评估集在"目标量化底座 + LoRA"组合上全量验收（评估走服务路径）。**排查提示**：遇到"适配器在 A 底座正常、B 底座崩"，先按"架构 × 量化方案 × 适配器"三个维度隔离（换架构/换量化/去掉适配器逐一对比）——组合类问题的定位靠"换变量"，不靠读代码。

## 3. 合并与导出错误

合并（merge_and_unload）相关的三个高频坑（`../完整微调工程流程/09-导出部署与上线运维.md` 01-02 节）：

**精度错误**：用 4-bit 量化底座合并（合并要求 float16 加载——量化底座合并会损精度）；**症状**：合并后模型输出退化。**修复**：float16 重载重合并。

**checkpoint 选错**：用最后一步 checkpoint 而非最优 eval loss checkpoint（`load_best_model_at_end`）——两者数值差异是"离线评估与线上不一致"的常见来源；导出时记录 export_metadata（哪个 checkpoint、什么配置）。

**合并后未重验**：合并过程引入数值差异（通常小但可能大）——**合并后必须重跑验收冒烟**（`../完整微调工程流程/09-导出部署与上线运维.md` 02 节）；服务启动前验证 config.json 与权重文件存在。

## 4. 量化引发幻觉与推理崩溃

**症状**：量化后模型幻觉激增（视觉模型 FP8 量化后完全失去图像理解——"看到"图里没有的狮子/狗；推理模型 Q6_K 下长思维链时输出损坏语法 + 幻觉终端命令，死循环访问不存在的目录）。

**2026 机制认知**：**微调让模型对量化更脆弱**——同一模型未微调版量化后正常，微调版量化后崩（视觉对齐被量化破坏）；长思维链 + 高温（temperature 1.0）+ 量化 = 严重 logit 漂移。

**修复**：微调模型量化前必须做"量化 + 微调"联合验收（领域评估集 + 长序列场景）；降默认温度（0.7）；长思维链任务慎用低 bit 量化；**终极方案是 QAT（量化感知训练）**——训练时模拟目标量化（fake quantization），模型学会在低精度下正确输出，可恢复 45-70% 的量化损失（Gemma3-4B GPQA 恢复 66.9%）；**QAT 不是可选项的边界**：2-bit/3-bit 边缘部署必须 QAT；QAT 要求训练前就确定部署位深（训练与部署决策耦合，`../完整微调工程流程/02-需求分析与方案设计.md` 03 节）。

**量化的性价比分层**（决策参考）：8-bit 量化对微调模型损伤通常可接受（大多数任务掉点 <2%，直接部署）；4-bit（INT4/NF4）开始出现"特定能力损坏"风险（长序列/约束保持）——上领域评估验证，不过就上 QAT 或降需求；2-3-bit 边缘部署直接规划 QAT——**位深越低，量化方案越要"训练期介入"而不是"部署期补救"**。

## 5. 服务异常与"上线后变差"

部署期的最后一类：服务层问题导致的"上线变差"——**服务行为与评估行为不一致**。排查链：服务配置（温度/max_tokens/采样参数与评估配置不一致——评估温度 0、服务温度 0.7 会让结果系统性不同）；vLLM 与评估路径差异（`../完整微调工程流程/08-模型评估与验收.md` 03 节：评估必须走服务路径）。

**多 LoRA 服务配置**（`modules_to_save` 非空导致适配器加载失败或行为异常，`../完整微调工程流程/09-导出部署与上线运维.md` 01 节）；量化底座组合（第 2 节）。

排查顺序从"最便宜"开始：先比服务配置与评估配置（读配置即可）→ 再比服务路径与评估路径（同请求对比输出）→ 再查多 LoRA 与量化组合（换底座对比）——前两步通常能定位 80% 的服务层问题。

**统一原则**：**"将要上线的产物"用什么配置评估，就用什么配置服务**——精度、温度、采样、模板四者全对齐，"评估与上线一致"是部署可信的前提（`../完整微调工程流程/08-模型评估与验收.md` 05 节）。

**部署问题的"验证矩阵"**（上线前跑一遍）：产物（合并 vs 适配器）× 精度（BF16 vs 目标量化）× 路径（本地评估 vs 服务评估）三个维度的交叉验证——每个交叉点跑领域评估集冒烟；**最省事的做法：把"部署精度评估"直接做进评估矩阵**（`../完整微调工程流程/08-模型评估与验收.md` 01 节），训练验收时就测"部署形态"，上线前只剩服务冒烟。

> 🎯 **核心要点**：量化损伤 PPL 看不见（PPL 0.04、任务 -7 点）——领域评估（长序列/多步程序化检查）是硬门禁，AWQ+长序列校准可恢复；LoRA+量化底座要联合验证（Llama×AWQ×LoRA 组合失败案例）；合并三坑——float16 重载、最优 checkpoint、合并后重验；量化引发幻觉/推理崩溃 = 微调让模型对量化更脆弱，QAT（恢复 45-70%）是终极方案、2/3-bit 必用；服务与评估四对齐（精度/温度/采样/模板）——"上线产物用什么配置评估就用什么配置服务"。
