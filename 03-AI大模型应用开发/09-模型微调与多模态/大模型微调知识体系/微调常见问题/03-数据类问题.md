# 数据类问题

> 数据是"最贵的坑"产区：同源泄漏伪造评估、重复样本伪造 eval loss、负样本缺失导致误报爆炸、格式错误毒化训练——症状在训练后，根因在数据准备期

## 1. 训练/评估同源泄漏

**症状**：训练 loss 正常、评估分数漂亮，上线效果崩。**根因**：评估集与训练集同源——最常见的是**评估集与合成训练数据来自同一批 seed prompt**（语义相同但文本不同，MinHash 都抓不到），模型"见过"评估题的语义，评估分数虚高。

**诊断**：语义级相似度检查——把训练集与评估集 embedding 后查最近邻重叠（MinHash 只抓文本重复，语义重叠要靠 embedding，`../数据集体系（非常重要）/05-数据去重与污染检测.md` 04 节）；更简单的信号：评估分数显著高于线上表现（差 >5 个点就要怀疑泄漏）。

**预防**：**评估集先用真实/人工数据建，再生成合成训练数据**（构建顺序本身就是防线）；合成数据的 seed prompt 与评估集严格隔离；跨时段采样（时间靠后的样本做评估，`../基础概念/09-评估基础损失曲线与过拟合.md` 06 节）。

## 2. 重复样本与"假评估"

**症状**：训练 loss 异常低、模型复读训练样本、验证 loss 与训练 loss 背离不明显（因为验证集也有重复）。**根因**：重复样本无形提高权重（`../数据集体系（非常重要）/05-数据去重与污染检测.md` 01 节）——模型对重复内容过度学习，输出"复读倾向"。

**诊断**：抽样哈希统计重复率（>5% 即高）；minhash 查近似重复（模板化生成数据的高发区）；模型输出探测——问训练集里的样本，看是否逐字复读。

**修复**：三级去重（精确/模糊/语义）跑全量；**注意先切分再去重与先去重再切分的顺序**（先去重再切分，防验证集混入同源样本）；重复率不高时别为"流程完整"白跑重去重（ICLR 2026 TRIM 提醒，`../数据集体系（非常重要）/05-数据去重与污染检测.md` 06 节）。

## 3. 负样本缺失与误报爆炸

**症状**：微调后的分类/检测模型"什么都说 yes"——假阳性率飙升，真实输入的误报远高于测试集表现。**根因**：训练集只有正样本（或正负比严重失衡），模型只学到正类边界。

**诊断**：统计训练集类别分布（正负比、难易比）；在真实请求分布上做误报测试（测试集只放"容易题"会掩盖）。

**修复**：完整检测数据集 = 正样本 + 弱负样本 + **硬负样本** + 歧义样本，按生产真实比例配比（`../数据集体系（非常重要）/08-数据平衡与多样性.md`）；硬负样本（看似正类、实为负类）是关键——没有硬负样本，模型在真实输入的误报必然爆炸；focal loss 可动态降低易样本权重、把梯度集中到难样本（训练侧配合）。

## 4. 数据格式错误

**症状**：报错（schema 校验失败）或静默污染（字段错位、角色错误但能训练）。**根因**：转换脚本 bug、来源数据格式混杂（Alpaca/ShareGPT/CSV 混用）、特殊 token 双重处理（02 篇坑四）。

**诊断**：schema 校验全量跑（role 合法性/消息配对/tool 序列）；**往返一致性测试**（messages → 渲染 → 反解析，内容应一致）；渲染抽检 20 条人工看（`../数据集体系（非常重要）/06-数据格式与转换.md` 04 节）。

**修复**：修转换脚本（进 git）→ 全量重新转换 → 三条验证线重跑；**格式错误的修复要重跑整条数据流水线**，不能只修错误样本（流水线可重跑的价值在此兑现，`../完整微调工程流程/05-数据准备与训练集构建.md` 01 节）。

## 5. 数据质量问题导致的"效果偏科"

**症状**：模型在部分任务上表现好、部分任务上完全不会；或整体"学到一半"。**根因**：类别失衡（某类样本占比过高/过低）、质量不齐（噪声样本稀释学习信号）、边界样本缺失（只会"容易题"）。

**诊断**：类别分布统计（与真实请求分布对比）；分项评估（每类任务单独算指标——偏科一眼可见）；judge 分数分布体检（全 5 分 = 标准太松，全 2 分 = 标准太严，`../数据集体系（非常重要）/07-数据质量评估与筛选.md` 03 节）。

**偏科的"漏斗式"定位**：先看"哪类任务差"（分项评估）→ 再看"该类任务的数据占比与质量"（类别统计 + 该类样本抽检）→ 再看"该类任务的边界覆盖"（该类样本里有没有困难/边界样本）——漏斗三步把"偏科"定位到"缺数据 / 数据差 / 缺边界"三个根因之一，再对症修复（配比 / 清洗 / 补边界）。

**修复**：按真实请求分布重配比（`../数据集体系（非常重要）/08-数据平衡与多样性.md`）；补边界样本（拒答/极端格式/模糊输入）；质量过滤（红旗清单 + LLM judge 淘汰底部 10-20%）。**数据问题的修复优先级**：泄漏 > 重复 > 负样本 > 格式 > 配比——先修"伪造评估"的问题（否则后续修复无法验证）；每修一类，重新跑数据流水线 + 更新 manifest（`../完整微调工程流程/05-数据准备与训练集构建.md` 03 节）。

**数据问题的预防性检查**（每次数据迭代必做四项）：训练/评估同源抽样对比（embedding 最近邻）、重复率统计（抽样哈希）、类别分布报告、judge 分数分布体检——四项全是脚本化的廉价检查，**跑在训练前**（`../完整微调工程流程/05-数据准备与训练集构建.md` 01 节流水线内），比出问题后再查省一个数量级。

> 🎯 **核心要点**：数据五类问题——同源泄漏（评估虚高，先建评估集再生成训练数据）、重复（复读 + 假 eval，三级去重）、负样本缺失（误报爆炸，硬负样本必配）、格式错误（静默污染，三条验证线）、偏科（配比与质量，分项评估）；修复优先级：泄漏 > 重复 > 负样本 > 格式 > 配比；所有修复重跑数据流水线并更新 manifest——数据问题的症状在训练后，根因在数据准备期。
