# 效果不达预期问题

> "微调完了但效果不行"的四种形态：没提升、变差了、幻觉增加、格式不稳定——2026 年最重要的发现：很多"变差"不是训练问题，是 train-serve 精度不匹配

## 1. 没提升：先问三个"对不对"

微调后任务指标没提升，按序查：

**需求定义对不对**（`../完整微调工程流程/02-需求分析与方案设计.md`）：任务定义模糊（"更专业"没翻译成可测指标）、指标选错（测了格式没测语气——指标没覆盖核心需求）。**查法**：回到需求文档对账，指标与业务价值能否对上。

**该不该微调对不对**（`../边界判断（非常关键，面试必问）/`）：知识缺口用微调必然无效（知识归 RAG）；Prompt 没试直接微调（可能 Prompt 就够了，微调是重复投入）；数据量 <500-1000 条（Prompt/few-shot 可能更优）。

**数据与训练对不对**：数据量不足/质量差（先采样人工看质量，`../完整微调工程流程/05-数据准备与训练集构建.md` 05 节）；epoch 不够（<1 时行为没固化）；学习率过低（学不进去）。**查法**：nonce 测试（链路没问题）+ 单样本过拟合测试（10 条训 50 步 loss 应显著降）+ 小验证集快速迭代（50 条数据训 100 步，看方向对不对再全量）。

## 2. 变差了：train-serve 精度不匹配（2026 关键发现）

**症状**：benchmark 上"明星学员"（8B 翻译模型 21:11 赢小模型），上线后 2:23 惨败——主语错乱、极性翻转等严重缺陷。

**根因**（2026 实锤案例）：**训练精度与部署精度不一致**——模型 BF16 训练、INT4 部署，微调出来的"技能"在量化后被抹掉：同一适配器在 BF16 底座上 23 胜、INT4 底座上 2 胜（40 项里 22 项严重缺陷）。**训练与部署精度对齐后，8B 的优势恢复**。

**诊断**：同一适配器分别在 BF16 与量化底座上评估对比（差值大 = 精度错配）；**训练时就把部署精度"计入成本"**（训练与部署同精度测试）。

**修复**：训练/部署精度对齐（部署 INT4 就训 INT4 兼容的方案——QAT 量化感知训练，`../完整微调工程流程/06-训练配置与启动.md` 02 节）；或部署用与训练一致的精度（BF16 服务成本高但保效果）；评估矩阵增加"部署精度评估"维度（评估走服务路径，`../完整微调工程流程/08-模型评估与验收.md` 03 节）。

## 3. 幻觉增加：先分"知识幻觉"与"行为幻觉"

微调后幻觉变多是高频投诉，先分清两种：

**知识幻觉**（编造事实/引用/数字）：**微调的本质边界**（`../边界判断（非常关键，面试必问）/03-微调vsRAG.md`）——把知识类样本塞进训练集，模型学会"自信地编造"（Ovadia 研究：事实性内容微调反而增加幻觉）。**修复**：知识类需求走 RAG；训练集剔除事实类样本（或改为行为类样本——格式/流程而非事实）。

**行为幻觉**（编造不存在的工具/命令/流程）：训练数据里的工具调用失败案例缺失（模型只见过成功调用，没见过"工具不存在"的处理）；Agent 类数据的边界覆盖不足（`../数据集体系（非常重要）/02-数据集类型全景.md` 05 节）。**修复**：工具数据补失败案例；拒答边界样本（"做不到"要会直说）。

**诊断顺序**：先判断幻觉内容属于"知识"还是"行为"（内容特征：事实类 vs 动作类）→ 知识类查数据构成（事实样本是否混入训练集）→ 行为类查边界覆盖。

**幻觉与评估的盲区**：幻觉类问题在"平均指标"下看不见（编造 5% 的引用，准确率只掉一点）——幻觉评估要用专项指标：引用来源可验证率（事实类）、工具调用合法性（行为类）、拒答正确率（边界类）——**评估集里必须有幻觉探测样本**（构造"模型应该拒答/应说不知道"的样本，看它是否诚实），否则幻觉问题要到线上才暴露。

## 4. 格式不稳定：时好时坏

**症状**：JSON 输出有时对有时错、格式时好时坏。排查链：

**模板问题**（第一嫌疑，02 篇）：训练/推理渲染不一致——格式问题的第一嫌疑永远是模板（2026 实锤为"第一大静默杀手"），渲染 diff + nonce 测试确认。

**数据问题**：格式样本一致性差（同一字段多种格式的样本混训——模型学到"两种都对"）；负样本/坏格式样本缺失（模型没见过"错误格式"的样子，不知道边界）。**修复**：格式样本统一 + 边界样本（错误输入→正确输出、正确输入→错误输出的拒答）。

**训练问题**：epoch 不足（格式没固化）；数据量不足（格式模式没学全）；评估指标问题（只测了"平均正确率"没测"最差场景"——格式问题用最差 10% 的解析率评估才看得见）。

## 5. 效果问题的诊断纪律

效果问题最怕"瞎调"（改数据、改超参、换模型一起上，无法归因）。标准动作：**先复现**（评估脚本固定，重跑确认"变差"不是评估波动——评估环境漂移也会造成"变差"假象，`../完整微调工程流程/08-模型评估与验收.md` 02 节）；**再分层**（需求/决策/数据/训练/部署五层，每层有确认手段——需求对账、边界判断复核、数据抽检、nonce 测试、精度对比）；**最后修复**（一次一层）。

**"效果不行"的排查顺序：先查不该微调（边界判断）→ 再查没测对（评估）→ 再查数据 → 再查训练 → 最后查部署**——前两层是免费的（读文档、跑评估），后三层要花算力（重训重测）；从免费的开始查，能省掉大半次重训。

> 🎯 **核心要点**：没提升先问三"对不对"（需求/边界/数据训练）；变差的第一嫌疑是 train-serve 精度不匹配（BF16 训 INT4 服务，胜率 23:2 翻转为 2:23——训练时就把部署精度计入）；幻觉分知识类（归 RAG，训练剔除事实样本）与行为类（补失败案例与边界覆盖）；格式不稳定先查模板再查数据（格式样本一致性 + 边界样本）；效果排查顺序：边界判断→评估→数据→训练→部署，前两层免费后三层花算力——一次改一层，先复现再动手。
