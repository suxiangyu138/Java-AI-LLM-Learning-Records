# PEFT 选型与边界

> 方法模块的收口：PEFT vs 全量的决策依据、方法间选型地图、PEFT 不够的三个信号、PEFT 与 RAG 的组合——选型有依据，边界划清楚

## 1. PEFT vs 全量：决策依据

"用 PEFT 还是全量"的决策由三个变量决定（阈值判断详见 `../边界判断（非常关键，面试必问）/06-全量微调vsPEFTvsQLoRA.md`）：

**数据量**：1k-50k → PEFT 默认（98% 收益实证，`../PEFT 参数高效微调（面试高频）/01-PEFT全景与定位.md`）；50k+ → 全量可竞争（数据充足时全量的容量优势显现）；<1k → Prompt 更优（PEFT 也有过拟合风险）。

**任务复杂度**：格式/风格/行为校准 → PEFT 足够（intrinsic dim 低）；复杂推理链/大领域迁移（继续预训练式）→ 全量或继续预训练（`../边界判断（非常关键，面试必问）/05-微调vs继续预训练.md`）。

**资源约束**：显存（LoRA 1.1 倍 vs 全量 5 倍权重）、时间（全量 70B 需多卡数天 vs QLoRA 单卡小时级）、GPU 数量（单卡只能 PEFT 路线）——**资源约束通常是第一决定因素**（`../边界判断（非常关键，面试必问）/09-成本收益量化与混合策略.md` 的 ROI 方法）。

**决策顺序**：先问"数据量"（门槛）→ 再问"任务复杂度"（容量需求）→ 最后看"资源"（可行性）——三问全过才值得全量。

## 2. 方法间选型地图

PEFT 家族内部的选型（01/03/05 篇的方法全景在此收口）：

| 场景 | 选择 |
|------|------|
| 默认（绝大多数） | LoRA（r=16、alpha==r） |
| 单卡大模型/显存紧张 | QLoRA（慢 30-40% 换显存） |
| 复杂任务接近全量 | QLoRA + DoRA（简单任务谨慎） |
| 大秩稳定 | rsLoRA（α/√r） |
| 极端省参 + NLU 分类 | Prompt Tuning |
| 生成任务层级引导 | Prefix Tuning |
| 极低资源简单任务 | BitFit / IA3 |
| 不确定 | 先调好 vanilla LoRA 再对比（2026 审计结论） |

**选型的两个纪律**：**先调好基线再比方法**（"Learning Rate Matters"：变体收益可能来自超参敏感，`../PEFT 参数高效微调（面试高频）/03-LoRA变体家族.md` 05 节）；**选型靠基准不靠信仰**（FLAN-T5-XL 结论：无普适最优，`../PEFT 参数高效微调（面试高频）/05-其他PEFT方法.md` 06 节）。

**选型的地图更新纪律**：PEFT 方法地图是 2026 年**变化最快的知识区**（自适应秩、新量化格式、审计论文不断改写结论）——本表是 2026-08 快照，**半年后选型前先检索再决策**（`03-AI大模型应用开发/` 的 tech-research 纪律）——"方法选型"比"原理"更容易过时：原理（低秩/intrinsic dim）五年内稳定，选型表（哪个变体最好）每年都在变。

## 3. PEFT 不够的三个信号

什么时候"PEFT 到顶了"、该换方案（换全量/继续预训练/重新审视需求）：

**信号一：r 升到 64 且调好超参，任务指标仍不达**——容量约束（任务 intrinsic dim 超出低秩表达范围）——换全量或重新审视任务定义（`../完整微调工程流程/02-需求分析与方案设计.md` 的"该不该微调"复核）。

**信号二：知识类需求（事实/时效/私有数据）**——PEFT 不更新知识截止（模型训练后的新知识权重里没有）——**这是"换方案"不是"换方法"**：归 RAG（`../边界判断（非常关键，面试必问）/03-微调vsRAG.md`）。

**信号三：领域整体迁移（术语体系/文体全面改变）**——PEFT 的行为校准不够——考虑继续预训练（50 万+ 领域文本门槛，`../边界判断（非常关键，面试必问）/05-微调vs继续预训练.md`）或换领域底座。

**共性**：三个信号都是"方法解决不了任务本质"——**先诊断是"方法问题"还是"需求问题"再换**（`../微调常见问题/07-效果不达预期问题.md` 02 节的分层诊断：需求/决策/数据/训练/部署五层）。

**信号出现的时机**：信号一（容量）出现在"调参后期"（r 升满、lr 调好仍不达）；信号二（知识）出现在"需求分析期"就该排除（不该等到训练后才发现）；信号三（领域迁移）出现在"方案设计期"（领域特殊性评估，`../完整微调工程流程/02-需求分析与方案设计.md` 04 节的技术预检）——**三个信号的最佳处理时机不同：信号二、三应该在训练前拦截，信号一在训练后止损**——"边界的价值在提前"：能早排除的边界不要等到花了算力再发现。

## 4. PEFT 与 RAG 的组合

2026 年的生产主流不是单选而是组合——**PEFT 管行为、RAG 管知识**（微软 form/facts/orchestrate 的混合策略，`../边界判断（非常关键，面试必问）/09-成本收益量化与混合策略.md`）：

**组合形态**：LoRA 适配器教"回答结构"（JSON 格式、话术风格、流程规范）+ RAG 提供"当前事实"（检索到的证据注入上下文）——**两者互补不冲突**（PEFT 改权重、RAG 改上下文）。

**组合的价值**：解决"PEFT 不更新知识截止"的边界（信号二）——知识实时性归 RAG，行为一致性归 PEFT——**各管各的，都不越界**；适配器可以专门针对"RAG 输出后的格式化"训练（检索增强 + 格式微调的经典组合）。

**组合的工程形态**：RAG 管道（检索 → 注入上下文）在推理侧，适配器在模型侧——**两者在服务层相遇**（请求先检索、上下文注入、适配器模型生成）；多 LoRA 架构下可以"同一底座 + 多适配器 × 多检索配置"（按场景组合，`../PEFT 参数高效微调（面试高频）/08-PEFT生产实践.md` 04 节的路由粒度论述）——**组合不是"加在一起"，是"分层各管各的"**：检索层管事实、适配器层管格式、路由层管场景——2026 生产架构（微软 form/facts/orchestrate）的模型侧落地。

## 5. 选型的最终检查

一次选型的完整检查（决策记录，`../完整微调工程流程/02-需求分析与方案设计.md` 05 节）：**需求复核**（行为 vs 知识——知识先排除 RAG）；**数据量定位**（<1k Prompt / 1k-50k PEFT / 50k+ 全量可竞争）；
**复杂度定位**（简单行为 LoRA、复杂推理考虑全量）；**资源核算**（显存/时间/GPU 三账）；**方法选型**（默认 LoRA → 按场景换变体/其他方法）；**边界检查**（三个信号是否命中）——六步走完，选型有据可查。

> 🎯 **核心要点**：PEFT vs 全量三问——数据量（1k-50k PEFT 默认）、任务复杂度（低 intrinsic dim 行为 PEFT 够）、资源（显存/时间通常是第一决定因素）；方法间选型地图按场景走（默认 LoRA、显存紧 QLoRA、复杂任务 QLoRA+DoRA、大秩 rsLoRA）；PEFT 不够三信号——r=64 调好仍不达（容量）、知识需求（归 RAG）、领域整体迁移（继续预训练）——先诊断方法还是需求问题；组合主流——PEFT 管行为、RAG 管知识（form/facts 分工）；选型六步检查进决策记录。
