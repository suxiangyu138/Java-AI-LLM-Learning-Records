# 大模型训练三阶段范式

> 理解"模型是怎么造出来的"才能理解"微调是哪一步"：预训练 → SFT → 偏好对齐，2026 年扩展为五步流水线

## 1. 经典三段论：预训练 → SFT → 对齐

大模型的标准训练范式由三个阶段构成，每个阶段回答一个不同的问题：

**阶段一：预训练（Pretraining）**。在万亿级 web 语料上做自监督 next-token 预测（见 `04-损失函数与训练目标.md`）。产出"底座模型"（Base Model），具备语言与世界的通用能力。这个阶段解决的是**能力**问题——"模型知不知道语法、常识、推理"。成本极高（数千万美元级），企业几乎不参与。

**阶段二：监督微调（SFT，Supervised Fine-Tuning）**。用人工/合成的高质量"指令-回答"对做监督学习。产出"指令模型"（Instruction-tuned Model），学会按指令作答、对话格式、结构化输出。这个阶段解决的是**行为**问题——"模型会不会按人的要求干活"。SFT 是微调知识体系的主角，也是企业落地最常见的微调形态。

**阶段三：偏好对齐（Alignment）**。用人类偏好数据（哪个回答更好）训练，让模型输出"符合人类偏好"的内容。经典方法是 RLHF（奖励模型 + PPO），2026 年主流是 DPO（直接偏好优化）。这个阶段解决的是**价值观**问题——"模型答得好不好、该不该这么答"。

三个阶段的顺序不能颠倒：没有 SFT 教格式，对齐无从谈起；没有对齐，SFT 模型只会模仿示范行为、不保证安全与偏好。2026 年表述：**预训练提供能力基础，后训练（SFT+对齐）塑造可用性**——后训练现在被认为是模型"好不好用"的主要决定因素。

## 2. 2026 扩展版流水线

2026 年的前沿后训练流水线已从三段扩展为更细的链条：

```text
预训练底座 → SFT → 偏好优化（DPO/IPO/KTO）→ RL 强化（GRPO/PPO）→ RLVR（可验证奖励强化）→ 对齐模型
```

新增环节各自解决的问题：

**偏好优化**：DPO 直接偏好优化，用"选中的回答 vs 被拒的回答"配对数据训练，**不需要单独的奖励模型**——2026 年成为偏好对齐的主流选择，比 PPO 简单稳定。变体还包括 IPO（抗标签噪声）、KTO（只需要赞/踩二值反馈）、SimPO（去掉参考模型）、ORPO（SFT 与偏好优化合并为一步）。

**RL 强化（GRPO）**：DeepSeek-R1 带火的方法——对同一 prompt 采样 8-64 个回答，按组内相对优劣算奖励，**砍掉了 RLHF 里的 critic 模型**，显存减半，特别适合推理类任务。DAPO 等变体进一步稳定长程推理训练。

**RLVR（可验证奖励强化）**：数学（答案对不对）、代码（测试过不过）、工具调用（成功与否）这类**程序可验证**的任务，用 Python 解释器当裁判，替代人工偏好标注——DeepSeek-R1 证明纯 RLVR 可以涌现推理能力，各家的"思考模型"（thinking models）基本都走这条路。

注意区分：这段流水线是**前沿实验室**的完整后训练配方；企业微调落点与它不同——见第 3 节。

## 3. 企业微调的落点：第 2 步

对绝大多数企业场景，上面的完整流水线是过度配置。企业微调的落点几乎都是 **SFT 这一步**（最多加一个 DPO）：

- **需要改的是行为**（格式、语气、流程）→ SFT 足够，数据是"指令-回答"对，OpenAI/各家平台开放的 fine-tuning API 走的就是这条路。
- **需要偏好排序**（回答好坏差异明显、能给出配对数据）→ SFT 之后加 DPO，2026 年的标准组合是"QLoRA SFT → DPO → 评估"（见 `07-微调方法全景图谱.md`）。
- **需要推理能力**（数学/代码/复杂推理）→ 才考虑 GRPO/RLVR 路线，这需要大算力与可验证的奖励信号，通常超出企业落地范围，交给前沿模型。

判断"该不该微调、该走哪步"的完整框架在边界判断体系（`../边界判断（非常关键，面试必问）/`），本篇只建立概念：**三段论是地基，2026 流水线是前沿，企业落点是 SFT（+DPO）**。

## 4. 各阶段的数据与成本量级

| 阶段 | 数据形态 | 规模参考 | 成本量级 |
|------|---------|---------|---------|
| 预训练 | 纯文本语料（自监督） | 万亿 token | 千万美元级，企业不碰 |
| SFT | 指令-回答对 | 千-百万条（Nemotron 3 Super 用 700 万条精选） | 万元-十万元级（PEFT 可大幅压缩） |
| DPO | 偏好对（chosen/rejected） | 万-十万对 | 中等 |
| RLHF/PPO | 人类反馈 + 奖励模型 | 与 SFT 同量级 | 高（需要 reward model + critic） |
| GRPO/RLVR | 采样回答 + 可验证奖励 | 推理类任务 | 前沿实验室 |

SFT 与偏好优化阶段都可以用 PEFT（LoRA/QLoRA）大幅降低成本——这是执行层体系（`../PEFT 参数高效微调（面试高频）/`、`../训练关键超参 & 显存优化技术/`）的主场。

## 5. 阶段产物：Base / Chat / Reasoning 模型

三阶段范式在每个阶段产出的模型形态不同，拿到手里的"底座"其实是不同阶段的产物——**选错起点是微调常见的第一步错误**：

**Base 模型**（阶段一产物）：只会续写，不会按指令作答——问它问题它会继续编文本。能力上限最高（没被后训练"驯化"），但需要提示技巧才能使用，一般不直接面向用户。典型如 Qwen3-Base、Llama-3.1-Base。

**Chat/Instruct 模型**（阶段二三产物）：走完了 SFT + 偏好对齐，开箱即用——这就是日常对话的产品模型。**企业微调最常见的起点**：拿 chat 模型继续做领域 SFT（增量校准行为）。注意：在 chat 模型上继续微调可能破坏原有对齐（重演灾难性遗忘的一部分，见 09 篇），所以 2026 年指南常建议"底座选 chat 版，微调注意保留对齐行为"。

**Reasoning 模型**（2026 新形态，阶段四产物）：RLVR 训练出的"思考模型"，输出前会生成内部思考过程（thinking/reasoning trace），数学/代码/复杂推理显著更强。微调这类模型有特殊注意点：思考格式要保留（训练数据需含思考轨迹或关闭思考的开关）、输出 token 预算增大（推理成本上升）。

**选底座三判据**：需求与底座能力匹配（推理需求选 Reasoning、通用对话选 Chat、需要完全自由的行为校准才考虑 Base）；许可协议（商用条款、开源协议）；生态与工具链（家族模型的微调工具与社区数据是否成熟）。

> 🎯 **核心要点**：经典三段（预训练=能力、SFT=行为、对齐=价值观）是理解一切微调文档的坐标轴；2026 扩展链（DPO→GRPO→RLVR）是前沿方向；企业 99% 的落点在 SFT（+DPO）——先分清"我在哪一段"，再谈怎么做。
