# 损失函数与训练目标

> 训练的一切都是围绕损失函数转的：loss 怎么算、困惑度是什么、SFT 与预训练的损失有何区别——看懂 loss 是看懂训练日志的第一步

## 1. 训练目标：next-token 预测

LLM 的预训练目标是**自监督的 next-token 预测**：给定序列的前 t 个 token，预测第 t+1 个 token 是谁。训练目标不来自人工标注——把输入序列错开一位，前面部分当输入、后面部分当标签即可，这就是"自监督"的含义：**数据天然带标签**。

训练时，模型对每个位置输出一个在词表（vocab，现代模型常见 128K-151K）上的概率分布，然后与真实的下一个 token 对比计算损失。

为什么"预测下一个词"能学到世界知识：预测本身是一个强约束——要预测"下雨了"后面更可能接"记得带伞"，模型必须从语料中学习语言的共现规律、事实关联与推理链条。

学界对能力涌现的主流解释之一就是：万亿级 next-token 预测在隐式地要求模型建模"语言背后的世界"——数学推理、常识、代码语义都在这个目标下被压缩进权重。理解这一点才能理解微调的边界：**微调改的是同一套目标的局部校准，底座里没有的世界知识，微调也造不出来**。

公式形态：

```text
Loss = -1/(B×T) × Σ log P(token_t+1 | tokens_1...t)
```

其中 B 是 batch 中的序列数，T 是序列长度——**对 batch 内所有序列的所有位置取平均**。实现上，logits 从形状 (B, T, V) 展平成 (B·T, V)，目标展平为 (B·T)，然后调用交叉熵函数一次算完。

## 2. 交叉熵：预测分布 vs 真实 token

交叉熵（Cross-Entropy）衡量"模型预测的分布"与"真实 token 分布"的差异。对每个位置，真实答案是一个 one-hot 的 token，所以交叉熵退化为**负对数似然**：真实 token 的概率越高，损失越小；模型越不确定（概率摊平），损失越大。

两个边界值得记住：

**随机初始化时 loss ≈ log(vocab_size)**。模型刚开始什么都不会，对每个位置输出近似均匀分布，词表 128K 时 loss ≈ 11.8。这给训练提供了一个"起点刻度"——loss 从 11 降到 2 才是真学到了，从 11 降到 10 可能只是热身。

**完美预测时 loss → 0**。但如果 loss 真的逼近 0，几乎必然是过拟合（模型把训练样本背下来了），这是 `09-评估基础损失曲线与过拟合.md` 的核心话题。

## 3. 困惑度：loss 的人类可读版本

困惑度（Perplexity，PPL）是交叉熵的指数：**PPL = exp(loss)**。含义：PPL=10 表示模型在每个位置"像是在 10 个等可能的 token 中选一个"——值越小，预测越确定。现代预训练模型在多样化 web 语料上 PPL 通常 6-10。因为指数放大差异，PPL 的微小改善（如 8 → 7）对应 loss 的明显下降，汇报时常用 PPL 而非裸 loss。

PPL 在微调中的实操含义：SFT 模型的 PPL 通常显著低于底座（学会了目标分布的形态）；但 **PPL 下降只说明"输出更符合目标数据分布"，不等于任务变好**——模型可能只是"说得更流畅"而内容更差。所以 PPL 适合做训练监控与早停信号（见 09 篇），任务好坏必须看任务指标（格式正确率、回答准确率），不能只看 PPL。

## 4. SFT 的损失：同一个交叉熵，多一个掩码

SFT（监督微调）用的还是自回归交叉熵损失，但有一个关键差异：**prompt masking（提示词掩码）**。对话样本由 system/user/assistant 消息组成，模型只需要学习**生成 assistant 的回答**，不需要学习"预测 user 的提问"——所以 user（及 system）部分的 token 在损失计算中被掩掉：

实现上，被掩码位置的 label 设为 **-100**（PyTorch 交叉熵的忽略索引），该位置不产生梯度。多轮对话有两种掩码策略：**只训练最后一轮 assistant 回答**（final-turn only），或**训练所有 assistant 轮次并掩码 user 轮次**——前者更省算力、防止模型在早期轮次上浪费容量，后者在长对话任务中更稳。

SFT 与预训练的另两个差异是**量级**：SFT 用更小的 batch size、更低的学习率（低 1-2 个数量级），因为底座已经收敛，大步长会破坏已有权重（见 `05-优化器与梯度更新.md`）。

## 5. 损失函数的演进：SFT → DPO → RL

损失函数定义了训练目标——微调方法家族（见 `07-微调方法全景图谱.md`）的演进，本质上是损失函数的三次升级：

**SFT 的损失 = 交叉熵（模仿）**。目标是最小化"预测分布 vs 示范答案"的差异——模型学的是"照着示范做"。局限：只能模仿数据里出现过的好回答，无法超越示范，也不知道"为什么这个回答好"。

**DPO 的损失 = 偏好对的对数几率比（偏好）**。用（chosen 回答, rejected 回答）配对，损失让模型提高选中回答的相对概率、降低被拒回答的相对概率——本质是把 RLHF 的奖励函数重写成一个可直接优化的分类目标，**不需要奖励模型**。模型学的是"哪种回答更被偏好"，示范无需完美，好坏对比即可。

**RL 家族的损失 = 期望奖励（奖励）**。目标从"预测正确的下一个 token"变成"产出高奖励的 token 序列"——GRPO 用组内相对优劣当奖励、RLVR 用程序验证（测试通过/答案正确）当奖励。模型从"照做"升级为"探索并发现更好的做法"。

一句话收束：**三阶段范式（模仿 → 偏好 → 奖励）对应损失函数的三种形态（交叉熵 → 偏好损失 → 期望奖励）**——面试被问"DPO 和 SFT 的损失有什么不同"时，从这条主线回答最清晰。

## 6. 2026 研究视角：loss 收敛的瓶颈

2026 年论文（Liu et al., arXiv:2602.03685，"Universal One-third Time Scaling"）为 LLM 训练的 loss 收敛规律给出机理性解释：**softmax + 交叉熵在拟合尖峰分布（如 next-token 分布）时，梯度天然以幂律消失，导致 loss 以"时间 1/3 次方"的普适指数收敛**。

这解释了为什么大模型 loss 下降后期越来越慢（幂律尾巴），也是训练效率优化（更优的 batch 调度、学习率扫描）的研究动机。

入门阶段的含义：**loss 曲线后期平坦是正常现象，不是训练坏了**——判断"该不该停"要看验证集与任务指标，不能只盯 loss 下降速度（详见 09 篇）。

> 🎯 **核心要点**：预训练与 SFT 共用同一套自回归交叉熵损失（Loss = -1/(B·T) Σ log P）；随机初始化 loss ≈ log(vocab)、PPL = exp(loss) 现代模型 6-10；SFT 的关键差异是 prompt masking（label=-100 掩掉 user）；loss 后期幂律收敛是常态——"loss 降"不是成功的充分条件。
