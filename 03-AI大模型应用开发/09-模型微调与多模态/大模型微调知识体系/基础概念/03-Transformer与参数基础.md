# Transformer 与参数基础（微调视角）

> 微调不需要手推注意力公式，但必须知道"权重在哪、有多少、微调改的是哪些矩阵"——参数视角是理解 LoRA/显存/量化的一切前提

## 1. 架构一句话版

2026 年主流大模型（Qwen、Llama、DeepSeek 等）几乎全部是 **decoder-only Transformer**：只保留 Transformer 的解码器，用**因果掩码**（causal mask）保证生成时只看前面的 token。核心组件只有四样：

**多头自注意力**（Multi-Head Self-Attention）：输入通过 Q/K/V 三个投影矩阵变换后做加权求和，让每个 token 都能"看到"它前面的 token 并决定关注谁——这是模型理解上下文的机制。直观理解：Q 是"我想找什么"（查询），K 是"我有什么"（被查询的索引），V 是"找到了给我什么"（实际内容）——每个 token 用 Q 去匹配前面所有 token 的 K，得到注意力权重，再按权重加权取 V。多头 = 多种"找法"并行：有的头找语法角色、有的头找指代关系、有的头找实体关联，最后拼回一个综合表示。

**前馈网络**（FFN）：对每个 token 位置独立做非线性变换，通常是隐藏宽度 4 倍的 MLP，现代实现用门控激活（SwiGLU）。参数占大头（约 2/3）。

**归一化**：每个子层前后加 RMSNorm/LayerNorm，稳定训练。现代模型用 Pre-Norm 布局（先归一化再计算）。

**位置编码**：给 token 加位置信息，现代标准是旋转位置编码（RoPE）。

此外还有残差连接（跳过子层直连，解决深层梯度消失）。自注意力的计算复杂度是 O(n²d)（n 为序列长度），这驱动了 FlashAttention 等长上下文优化——也解释了为什么**训练时的 max_seq_length 会直接影响推理时 KV cache 的显存占用**：在 8192 token 下微调的模型，无法在按 2048 token 配置的服务环境里高效部署（见第 4 节）。

## 2. 权重是什么：参数矩阵构成

模型的所有"知识"都存储在**参数矩阵**里。以隐藏维度 h 表示，单个 Transformer 层的参数构成：

| 组件 | 参数规模 | 说明 |
|------|---------|------|
| 注意力 Q/K/V 投影 | 3 × h² | 每个头的 Q、K、V 投影 |
| 注意力输出投影 | h² | 多头结果合并 |
| FFN 两层 | ~8h² | h → 4h → h |
| 归一化 | ~2h | γ/β 缩放偏置 |
| 单层合计 | **~12h²** | 不含 embedding |

embedding 层是另一大头：词表大小 × 隐藏维度（如 151k × 4096 ≈ 6 亿参数）。所以"模型参数量"= embedding + 层数 × 单层参数——**微调要更新的就是这些矩阵里的数字**。

embedding 为什么值得单独认识：它占 7B 模型总参数的 8-10%，且大词表在训练（embedding 梯度要存显存）与推理（词表 logits 计算）中都是固定开销——这也是 2026 年部分模型用中小词表 + 高效子词拆分控制成本的动机。

**词表是模型的固有结构，不能随意增删**：改词表 = 改 embedding 矩阵维度 = 需要重新预训练该层。微调阶段无法"给模型加新词"——只能靠改写让模型学会用已有词表达。

另外注意主流 2026 架构的变体：**GQA**（分组查询注意力，减少 KV cache 显存，Qwen/Llama 系标配）、**MoE**（专家混合，激活一部分参数，DeepSeek 系，训练推理都更快但显存要求高）、**混合架构**（Transformer + SSM/Mamba 段，长上下文探索方向）——这些不影响"权重是矩阵"的微调视角，但影响显存账本与推理性能，选底座时要知道。

## 3. 微调改的是哪些权重

理解"微调改权重"在参数层面具体化之后，三个重要推论：

**第一，全量微调改所有矩阵**。所有层的 Q/K/V、FFN、归一化、embedding 全部更新——能力上限最高，但每层都要存梯度与优化器状态，显存成本约是推理的 3 倍（见 `05-优化器与梯度更新.md` 与超参体系）。

**第二，LoRA 只改低秩补丁**。冻结底座所有矩阵，只训练低秩增量矩阵（W = W₀ + BA），可训练参数通常只有全量的 **0.1%-1%**，效果接近全量微调，存储与显存大幅下降——这是 PEFT 体系（`../PEFT 参数高效微调（面试高频）/`）的主角，其原理完全建立在"权重是矩阵"这个认识上。

**第三，不同层对微调的敏感度不同**。实践与 2026 研究都表明：顶层（靠近输出的层）对指令遵循影响最大，底层相对通用——这也是 LoRA 可以选择性加在某些层、以及部分研究建议对特定层用不同学习率的依据。入门阶段记住结论即可：**微调的本质操作是更新参数矩阵，方法差异在于"更新哪些、更新多少"**。

## 4. 微调视角的关键约束

**KV cache 约束**：推理时每生成一个 token 都要缓存历史 K/V 向量，显存随序列长度线性增长。训练时选的 max_seq_length 决定了推理环境的 KV cache 预算——训练与部署配置不是独立的，这是微调工程师最常忽略的架构约束。

**参数量与硬件**：从权重到显存的完整账本（推理/全量/LoRA/QLoRA 四档成本）见本章第 5 节，具体算法在 `../训练关键超参 & 显存优化技术/` 体系。

## 5. 从参数量看训练成本

参数概念最实用的落点是**算显存账**。FP16 下每个参数占 2 字节，从参数量可以直接推算出各方案的成本量级：

- **推理**：只需模型权重。7B 模型 ≈ 14GB，单卡 24GB 即可服务。
- **全量微调**：权重 + 梯度 + AdamW 优化器状态（每参数多存 3 份：一阶矩、二阶矩、权重衰减）≈ **4-5 倍权重** ≈ 56-70GB——7B 全量微调需要单卡 80GB 或双卡，70B 全量微调需要多卡集群。
- **LoRA**：底座冻结（只需前向，梯度只对 0.1-1% 的适配层算），≈ 权重 + 少量状态 ≈ 15-16GB——7B 单卡 24GB 可训。
- **QLoRA**：4-bit 量化底座（每参数 0.5 字节）+ LoRA 适配层 ≈ 4GB 权重 + 适配器——**7B 单卡 10GB 内、65B 单卡可训**，是 2026 年单卡微调的事实标准。

三个量级对比解释了微调工程的一个核心事实：**训练显存是推理的 3-4 倍，所以企业微调默认 PEFT**——全量微调不是"更好"而是"更贵且更险"（更多参数被扰动，遗忘风险更高，见 09 篇）。完整的显存账本（激活值、序列长度影响、量化方案对比）在 `../训练关键超参 & 显存优化技术/` 体系。

> 🎯 **核心要点**：主流大模型 = decoder-only Transformer（注意力 + FFN + 归一化 + RoPE）；权重就是参数矩阵，单层 ~12h² + embedding 大头；微调 = 更新矩阵（全量 vs LoRA 低秩补丁）；max_seq_length 决定推理 KV cache——参数视角是理解 LoRA、显存、量化的共同地基。
