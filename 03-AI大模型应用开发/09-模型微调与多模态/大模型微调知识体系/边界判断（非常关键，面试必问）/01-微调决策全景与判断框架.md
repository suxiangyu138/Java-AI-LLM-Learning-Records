# 微调决策全景与判断框架

> 边界判断的总纲：知识缺口 vs 行为缺口诊断、决策顺序、五问法——先判断做不做，再学怎么做

## 1. 核心诊断：知识缺口 vs 行为缺口

2026 年所有微调决策指导的共同起点是一个二分诊断：**模型的差距是"知道什么"还是"怎么做"**。

**知识缺口**（Knowledge gap）：模型缺少事实、信息过时、需要客户私有数据、回答需要引用来源——特征是"答案不对或编造"。这类缺口用 **RAG** 解决，不用微调。原因：微调把知识"冻结在训练时点"（训练后的新知识又没了），而 RAG 保持知识实时且可溯源；研究（Ovadia 2023）表明在事实性内容上微调**反而增加幻觉**——微调注入知识的代价是模型开始"自信地编造"。

**行为缺口**（Behavioral gap）：语气、格式、一致性、拒答行为、回复结构——特征是"内容对但形态不对"。这类缺口**先 Prompt 工程**，提示词无法可靠关闭时才考虑微调。

判断口诀：**"它不知道" → RAG；"它不按规矩来" → Prompt 先试，微调兜底**。企业 AI 最贵的错误就是**用微调解决知识问题**——方向错了，后面全错。

## 2. 决策顺序：Prompt → RAG → Tools → 微调

推荐的严格递进顺序（2026 生产指导一致）：

```text
1. Prompt 工程       —— 零成本，试行为缺口
2. RAG              —— 知识缺口，事实/时效/私有数据
3. 工具调用（Tools） —— 需要动作（查询/计算/写库）
4. 微调              —— 以上都试过仍有关键缺口，最后动用
```

每前进一步，复杂度、成本、治理负担都上一个台阶。经验事实：**企业需求中很大比例靠规范的 Prompt 就能解决**——而且"Prompt + 上下文"配合提示缓存（缓存读成本约输入 10%）可能比维护一个微调模型更便宜。

三步先行的理由：**Prompt 无权重风险**（改文字即可回滚）；**RAG 无训练成本**（检索管道，知识实时）；**Tools 扩展能力边界**（模型不会的可以调用会做的）。微调是唯一改变权重的杠杆——改错要重训，治理最重，所以最后。

## 3. 五问判断法

面试与工程通用的五个问题，逐个过完即得决策：

1. **差距是知识还是行为？** 知识 → RAG；行为 → 继续问。
2. **Prompt 能可靠关闭吗？** 能 → Prompt；不能 → 继续问。
3. **数据量够吗？** <1000 例 → Prompt/few-shot 更优；1k-50k → PEFT；50k+ → 全量可竞争（07 篇阈值）。
4. **变化频率？** 需求/知识频繁变化 → RAG/上下文（微调重训周期是摩擦）；稳定 → 微调可考虑。
5. **团队与治理？** 无 ML 基础设施 → 别微调；强监管行业 → 先轻杠杆（微调把模型本身变成受治理产物）。

五问全过仍指向微调，才进入"微调怎么做"（PEFT/QLoRA/数据集，见同级子体系）。

## 4. 微调真正该用的场景

Prompt/RAG/Tools 都试过之后，微调的合理场景有六类（2026 共识）：

1. **一致性结构化输出**：JSON/模板/CSV/工作流格式，基座模型不可靠时——微调让格式 99% 稳定。
2. **风格/语气/人格强制**：品牌声音、客服话术一致性——百万级对外交互的质量底线。
3. **领域专属输出格式**：临床笔记结构化抽取、专业代码生成——基座无法原生产出。
4. **降低 prompt 长度与单次推理成本**：规模化的每请求成本优化（行为固化进权重，不再每请求带长指令）。
5. **模型蒸馏**：小模型在窄任务上逼近大模型——成本下降一个量级。
6. **评估/推理模式标准化**：审计、评审、合规工作流的固定推理范式。

共同特征：**"行为"而非"知识"**——六类全是"怎么输出"的稳定模式，没有一类是"知道什么"。

## 5. 不该微调的六种情况（反面清单）

1. **知识注入**：事实/私有数据 → RAG（微调注入增加幻觉）。
2. **快速变化的需求**：重训周期是摩擦——需求月更，微调跟不上。
3. **小团队无 ML 基础设施**：训练/评估/监控闭环是硬门槛。
4. **当捷径**：把微调当 shortcut 的团队"稳定地产出脆弱昂贵的系统"。
5. **强监管行业（金融/医疗/法律/药企）**：除非轻杠杆全失败——微调让模型本身成为受治理产物（训练数据溯源、版本历史、评估证据、监控、审计就绪）。
6. **数据不足**：<1000 例且 token 重叠高 → Prompt 更优（07 篇）。

反面清单的作用是**止损**：看到任一条件成立，微调决策就该被否决或推迟——边界判断的第一能力是"说不"。

边界判断的元原则：**先排除，再选择**——六不该清单是排除法（任一命中即否决），六该清单是选择法（全过才入场）；排除法成本为零（读一遍清单），选择法成本极高（训练+评估+部署）——**决策成本不对称，所以排除优先**。面试答"你怎么判断"时先背排除清单再讲选择场景，逻辑顺序本身就是加分项。

## 6. 2026 现状：边界在移动

三个趋势让"边界判断"比老教程更复杂也更关键：**长上下文模型**（上下文放得下更多知识——部分"知识缺口"被上下文工程吸收，见 04 篇）；**提示缓存降价**（缓存读约输入 10% 成本——"Prompt + 上下文"路径的经济性上升）；**2026 实证研究**（无普遍最优策略，最优选择随任务复杂度切换：低复杂度召回 RAG 优、多步推理 RAG/微调相当、创意综合微调最优，见 03 篇）——**边界判断不是静态口诀，是随模型能力与成本结构演进的动态决策**。

> 🎯 **核心要点**：诊断（知识→RAG、行为→Prompt 先试）→ 排序（Prompt→RAG→Tools→微调）→ 五问（知识/行为、Prompt 可靠性、数据量、变化频率、团队治理）→ 六该六不该对照；微调是最后手段，企业最贵的错误是用微调解决知识问题。
