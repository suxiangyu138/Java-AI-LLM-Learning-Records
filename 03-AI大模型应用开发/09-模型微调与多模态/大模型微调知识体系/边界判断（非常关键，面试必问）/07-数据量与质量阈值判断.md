# 数据量与质量阈值判断

> 500-1000 例的 prompt 分水岭、token 重叠检查、质量优先原则、chat-tuned 基座的信号需求——"数据够不够"的量化判断

## 1. 数据量阶梯：从 Prompt 到继续预训练

数据量是边界判断的第一量化维度（2026 共识的收敛结论）：

| 数据量 | 推荐策略 | 逻辑 |
|:------:|---------|------|
| <500-1000 例 | Prompt/few-shot | 信号不足，微调匹配不了提示词 |
| 1k-50k | **PEFT（LoRA）** | 行为模式有足够统计信号 |
| 50k+ | 全量微调可竞争 | 容量需求浮现 |
| 500k+ | 继续预训练候选 | 知识分布需要改变 |

关键的第一道分水岭：**<1000 例时，Prompt 工程或 few-shot 通常匹配甚至超越微调**——原因：少量样本的"模式"提示词就能表达，而微调要承担过拟合与遗忘风险；微调"只在你有足够样本展示清晰、一致的规律时才有效"。

## 2. token 重叠检查：微调前的必做实验

数据 <1000 例时，先做**token 重叠检查**再决定：计算数据与模型预训练分布的 token 重叠度（BERTScore 或 embedding 相似度）——**重叠度 >70% 说明模型"已经知道"这些模式，提示词就能激活，微调是浪费**；重叠度低（领域新词/新格式多）才值得微调。

```text
重叠检查流程：
1. 采样数据（几百条）→ 与基座模型生成的同主题文本做相似度
2. 重叠 >70% → Prompt/few-shot（模型已内化该模式）
3. 重叠 30-70% → 微调候选（模式半新，LoRA 可注入）
4. 重叠 <30% → 评估继续预训练（模式太新，微调容量可能不够）
```

工程含义：**"数据少"不自动等于"别微调"**——领域格式全新（低重叠）时 500 例微调也可能有效；"数据少 + 高重叠"才是 Prompt 的明确信号。面试答"500 条数据要不要微调"时，先问重叠度再回答，就是深度。

## 3. 质量优先：1000-10000 指令对是 SFT 常用量

SFT 的数据量共识：**1000-10000 高质量指令-响应对**是常用区间，**质量严格优先于数量**——坏数据在 SFT 的代价被放大（05 篇：SFT 有效窗口后模型会重新学习噪声模式）。

质量的四个维度：**一致性**（同一任务同一格式——模型学的就是规律，不一致 = 无规律可学）；**正确性**（响应正确——错答案被内化后很难纠正）；**覆盖性**（任务分布覆盖——只覆盖 10% 任务形态，上线只对这 10% 有效）；**去重**（重复样本放大权重偏差——同质数据会让模型过拟合到重复模式）。

质量检查清单（微调前必过）：**格式一致性抽检**（同任务 50 条对比格式）；**正确性抽检**（领域专家抽样）；**多样性统计**（任务类型/长度/难度分布）；**去重**（相似度去重）。与同级 `数据集体系` 子体系的分工：那边讲"怎么构建与清洗"，本体系讲"多少量、什么质才值得微调"。

质量与数量的权衡曲线（决策视角）：**数量翻倍的质量收益递减**（5000 条高质量 > 5 万条脏数据——脏数据的错误模式被 SFT 窗口后放大学习）；**质量的四查成本远低于重训成本**（花一天清洗 vs 花一周重训 + 上线后返工——质量检查是 ROI 最高的前置投入）；**"先跑起来再加数据"的迭代纪律**（小量高质量起步 → 上线验证 → 按失败样本补数据——数据是迭代出来的，不是一次攒够的——与 08 篇止损闭环配合）。

## 4. chat-tuned 基座的信号需求下降

一个重要修正：**基座类型决定数据需求**——instruction-tuned 基座（已会指令跟随）与 chat-tuned 基座（ChatGPT/Claude 类，已精通对话格式）的微调信号需求不同。

- **instruction-tuned 基座**：相似域 50k+、新域 5k+（经验规则）。
- **chat-tuned 基座**：信号需求**降 5-10×**——模型已理解指令格式，微调只需要注入领域模式而非重新教格式。

工程含义：**用 chat-tuned 基座时，5k-10k 高质量样本即可覆盖多数领域行为**（对应 1k-50k 阶梯的中段）；数据量不足时优先选 chat-tuned 基座而非加数据——**基座选择是数据需求的第一变量**（选型时先问"用哪个基座"，再算数据量）。

## 5. 数据量判断的完整流程

```text
1. 基座类型？ → chat-tuned：需求降 5-10×；instruction-tuned：按阶梯
2. 数据量？ → <1000：重叠检查；1k-50k：PEFT；50k+：全量候选
3. 重叠度？ → >70%：Prompt；30-70%：微调；<30%：继续预训练候选
4. 质量？ → 一致性/正确性/覆盖性/去重四查
5. 迭代 → 先小量验证（500-1000 例试训）再扩量（08 篇止损配合）
```

流程的落点：**数据判断不是"够不够"的单点，是"基座 × 量 × 重叠 × 质"的四维评估**——任何一维不达标，微调决策就要打问号。先小量试训（几百例 + 1-2 epoch）验证"模式是否可学"，是数据量判断的最经济实验——比全量跑完才发现不行省一个量级。

小量试训的验收标准（判断"模式可学"的三个信号）：**训练 loss 显著下降**（几百例上 loss 都不动 → 模式学不进，先查数据质量或换方式）；**验证集有提升**（哪怕小——说明方向对，扩量有回报）；**输出形态对**（生成的格式/风格符合目标——行为模式"学会了"的直观证据）。三信号全过 → 扩量；任一不过 → 回到数据质量检查（质量四查）而不是盲目加数据——**试训是数据判断的"最小可行实验"**，成本小时级，避免周级的错误投入。试训的工程细节：**用与生产同分布的采样**（试训集从真实任务分布抽样，别用精心挑选的"完美样本"——试训验证的是"真实数据下模式可学吗"）；**试训结果存档**（loss 曲线、验证指标、样本清单——扩量时对比，防止"扩量后反而变差"无从归因）；**试训阈值明确**（"loss 降多少、验证提升多少算过"写进计划再跑——没有阈值的小实验等于没做）。

> 🎯 **核心要点**：<1000 例 Prompt 更优、1k-50k PEFT 默认、50k+ 全量候选、500k+ 继续预训练；重叠 >70% 提示词即够、<30% 考虑继续预训练；SFT 常用 1000-10000 高质量对且质量四查（一致性/正确性/覆盖性/去重）；chat-tuned 基座需求降 5-10×——数据判断是"基座 × 量 × 重叠 × 质"四维评估。
