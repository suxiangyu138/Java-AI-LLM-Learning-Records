# 成本收益量化与混合策略

> 三策略成本对比与 ROI 计算、混合默认（fine-tune for form）、蒸馏小模型化、强监管行业的治理边界——决策者的量化工具

## 1. 三策略成本对比

边界判断的最后一道是算账（2026 数据）：

| 维度 | Prompt | RAG | 微调 |
|------|--------|-----|------|
| 落地时间 | 低（小时级） | 中（检索管道） | 高（训练+评估+部署） |
| 复杂度 | 低 | 中 | 高 |
| 成本 | 低（每 token） | 中（检索基建+存储） | **高（训练算力+托管）** |
| 擅长 | 引导行为/快速迭代 | 事实准确/动态数据 | 行为一致性/风格/短 prompt |

微调的成本构成：**训练成本**（LoRA 约 $0.8-3/百万训练 token；QLoRA 更低）**+ 托管成本**（微调模型长期部署）**+ 重训成本**（基座升级/需求变化——模型漂移：专业化损害通用能力）。RAG 的成本构成：**检索基建 + 存储 + 每请求上下文 token**（提示缓存把重复前缀降到约 10% 输入成本）。

## 2. ROI 计算框架

量化判据不是"贵不贵"，是"每单位收益的成本"：

```text
Prompt + 缓存方案：
  每请求成本 ≈ 输入 token × 单价（缓存后前缀 ≈ 10%）
  收益 = 达到业务指标（格式合规率/回答准确率）

微调方案：
  总成本 = 训练摊销（训练成本 ÷ 预计请求量）+ 每请求推理（无冗余 prompt）
  收益 = 同上（+ 行为一致性带来的隐性收益）

决策：微调总成本 < Prompt 方案成本的场景
  —— 请求量大 + 每请求冗余 token 多（长 system prompt）+ 缓存命中率低
```

典型场景：**百万级日请求的客服系统**——每条请求带 2K token 行为指令，微调内化后省 2K × 百万 × 单价，训练成本几小时内回本；**千级日请求的内部工具**——训练成本永远回不了本，Prompt 完胜。**ROI 公式的第一变量是请求量**。

## 3. 混合默认：fine-tune for form, retrieve for facts, prompt to orchestrate

2026 生产指导（微软）的混合公式：**微调管形式（form）、RAG 管事实（facts）、Prompt 管编排（orchestrate）**——三者分层组合是生产默认，不是单选题。

```text
微调层：品牌语气、输出格式、领域行为（稳定、高频、可内化）
RAG 层：事实、文档、实时知识（动态、需溯源）
Prompt 层：会话策略、守卫规则、临时指令（变化、场景相关）
```

混合的适用信号：**知识频繁变化但响应必须遵循严格领域逻辑**（法规问答：格式微调 + 法规检索 + 场景提示）；**监管要求溯源与精度并存**（金融：微调保格式、RAG 保事实来源、Prompt 保合规约束）。混合的成本与治理是三者之和——**"能单选就别混合"是反方向纪律**：单一策略达标时，混合是过度工程。

混合架构的评估验收（三层各自达标才算混合成功）：**微调层**——格式/风格合规率（不含知识正确性——知识归 RAG 管，别用混合架构掩盖微调层缺陷）；**RAG 层**——检索命中率与答案溯源率（事实类问题的引用覆盖）；**Prompt 层**——场景指令的生效率（守卫规则/临时指令是否被遵守）。三层的指标分开看、分开验收——**混合架构的排障也要分层**：格式错查微调、事实错查检索、规则错查 Prompt——"混合出问题"先定位层，再动那层的方案。

混合架构的演进路径（避免一上来就全上）：**先 Prompt + RAG 双层**（覆盖多数需求）→ 行为缺口稳定浮现后加微调层 → 治理要求出现时补 Prompt 守卫层——**分层是叠加出来的，不是设计出来的**，每加一层都有指标证据（该层缺陷率触发），与 08 篇"信号驱动"纪律同源。

## 4. 蒸馏与小模型化：微调的降本形态

微调的隐藏价值是**蒸馏**：大模型（教师）生成标注 → 小模型（学生）微调——小模型在窄任务上逼近大模型，成本下降一个量级。

```text
蒸馏流程：大模型产出一致性标注 → 小模型 PEFT/全量微调 → 评估逼近度 → 部署
适用：高请求量 + 任务窄 + 行为可内化（格式/风格/抽取）
不适用：任务宽泛 + 需要通用推理（蒸馏丢失泛化）
```

边界判断：**蒸馏是"微调该不该做"的放大器**——行为缺口 + 高请求量时，蒸馏让微调的 ROI 显著提升（小模型推理成本低 5-10×）；任务宽泛时蒸馏是负资产。面试答"微调的价值"时主动引蒸馏场景，是成本视角的加分点。

## 5. 强监管行业的治理边界

金融/医疗/法律/药企的微调决策多一道硬约束：**微调把模型本身变成受治理产物**——需要训练数据溯源、版本历史、评估证据、监控、审计就绪，而 Prompt/RAG 的治理面小一个量级（提示词可审、检索可溯源）。

强监管场景的决策顺序：**轻杠杆全失败前不动微调**；必须微调时建立治理闭环：**数据治理**（标注来源/授权/版本）；**评估治理**（held-out 基准 + 幻觉率 + 合规审查）；**发布治理**（灰度 + 回滚 + 监控）；**审计就绪**（每次模型更新的完整档案）。**"能不做就不做"是强监管场景的第一原则**——微调的治理成本可能超过功能收益。

## 6. 成本决策的完整流程

```text
1. 缺口类型确认（知识/行为——01 篇）
2. 轻杠杆全试（Prompt/RAG/Tools——02/03/04 篇）
3. 数据量与基座评估（07 篇）
4. ROI 算账（请求量 × 冗余 token vs 训练摊销）
5. 混合 or 单选（达标优先单选，不达标看分层）
6. 治理约束检查（强监管 → 治理闭环成本）
```

流程的落点：**边界判断的终局是"ROI + 治理"双账**——技术可行（数据够、方式对）之外，经济可行（算得回本）与治理可行（管得住）缺一不可；面试答"为什么最终没微调"时给出"ROI 算不过 Prompt 方案 + 监管治理成本"的量化理由，就是决策者的成熟度。

成本敏感场景的省钱清单（微调已定的情况下）：**QLoRA 替代全量**（4-bit 量化省显存与算力，质量损失多数任务可接受）；**小模型优先**（7B 微调成本远低于 70B——任务窄时先试小模型 + 蒸馏路径）；**训练数据复用**（微调产生的标注可复用于评估集与后续迭代——一次标注多次使用）；**按量部署**（微调模型用 serverless 推理，低流量时段不产生固定托管成本）。省钱清单的落点：**"决定微调"之后还有一层成本优化**——微调决策的 ROI 账，在方式与部署层还能再优化一档。

> 🎯 **核心要点**：三策略成本对比（微调最贵：训练+托管+重训）；ROI 第一变量是请求量（百万级日请求微调回本、千级 Prompt 完胜）；混合默认公式 form/facts/orchestrate（能单选别混合）；蒸馏是微调 ROI 放大器（高请求+窄任务）；强监管场景"能不做就不做"+ 治理闭环；终局是 ROI + 治理双账。
