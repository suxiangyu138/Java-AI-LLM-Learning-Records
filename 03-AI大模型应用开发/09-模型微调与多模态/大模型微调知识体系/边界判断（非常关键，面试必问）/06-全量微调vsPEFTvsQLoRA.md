# 全量微调 vs PEFT vs QLoRA

> 参数效率的边界：1k-50k 数据 PEFT 默认、50k+ 全量可竞争、QLoRA 把大模型拉回单卡——显存预算决策树

## 1. 三种方式的本质差异

| 方式 | 训练参数 | 显存 | 典型场景 |
|------|---------|------|---------|
| 全量微调 | 全部权重 | 最高（优化器状态占大头） | 数据 50k+、有算力 |
| PEFT（LoRA） | 约 0.1%（适配器） | 约 1/3（7B 可单卡） | **1k-50k 默认** |
| QLoRA | 约 0.1% + 4-bit 量化 | 极低（48GB 单卡训 65B） | 大模型 + 单卡 |

全量微调的本质：更新全部权重——能力上限最高（可学习复杂新行为），但**优化器状态占显存大头**（Adam 的动量和方差 ≈ 参数量的 2 倍额外显存），且**全量更新 = 灾难性遗忘风险最大**（08 篇：小数据 + 全量 + 大模型 2 epoch 即遗忘）。

PEFT（LoRA）的本质：冻结原权重，只训练低秩适配器（W = W0 + BA，B 和 A 是小矩阵）——**训练参数约少 10000 倍、显存约 1/3、推理无延迟惩罚**（适配器合并回权重）；遗忘风险大幅降低（权重改动受限）。

QLoRA 的本质：LoRA + 4-bit 量化基座——**显存再降一个量级**（65B 模型 48GB 单卡可训），代价是量化带来的少量精度损失（通常可接受）。

## 2. 数据量边界：1k-50k vs 50k+

数据量决定方式（2026 共识）：

**1k-50k 高质量样本 → PEFT（LoRA）是默认**：数据量不足以支撑全量微调的统计信号，且 LoRA 的容量对"行为模式"足够——训练快、显存省、遗忘少、成本低（约 $0.8-3/百万训练 token）。

**50k+ → 全量微调开始可竞争**：数据量足够支撑全量更新的复杂行为学习；PEFT 的容量（低秩假设）可能在超大数据集上成为瓶颈——**50k 是"PEFT 容量够不够"的分水岭，不是绝对真理，但经验上稳定**。

两个补充判断：**任务复杂度**（格式对齐 1k 就够、复杂推理/长文风格 10k+ 起）；**数据多样性**（同质数据小量即可、异构数据要更多——与 07 篇质量优先原则一致）。

## 3. 显存预算决策树

```text
模型规模？
├── ≤7B → 全量微调可行（单卡/多卡），但默认仍 PEFT（省时省电）
├── 7B-13B → PEFT（LoRA）单卡可训；全量需多卡
└── >13B（65B/70B）→ QLoRA 单卡（48GB）或 PEFT 多卡
数据量？
├── <50k → 一律 PEFT/QLoRA（全量无必要）
└── ≥50k → 评估全量（有算力）vs PEFT（省算力，测容量瓶颈）
```

显存快算：**全量 ≈ 参数 ×（权重 2B + 梯度 2B + 优化器状态 2×4B Adam）**（7B 全量 ≈ 56GB+）；**LoRA ≈ 基座权重 + 小适配器 + 激活**（7B ≈ 16-24GB 单卡）；**QLoRA ≈ 4-bit 基座 + 适配器**（7B ≈ 6-10GB，65B ≈ 48GB）。公式的价值：**部署前先算显存账**，别等 OOM——显存账也是训练环境选型的依据（本地单卡 vs 云上多卡 vs 租卡平台），账算清了再买卡。

## 4. LoRA 的能力边界与失效信号

LoRA 不是万能，三个已知边界：**低秩容量**（复杂新知识/长程推理模式可能学不进——r 值调大（16→64）缓解，但显存涨）；**与全量的质量差距**（数据充足 + 任务复杂时差距显现——50k+ 数据评估全量的原因）；**遗忘仍可能**（受限但未消除——大模型 + 小数据 + 多 epoch 仍会遗忘，08 篇止损照样适用）。

失效信号与止损：**验证集不提升但训练 loss 降**（过拟合开始）；**领域外能力下降**（遗忘开始）；**特定任务不收敛**（容量不足 → 调大 r 或换全量）。三个信号对应三个动作：early stopping、加正则/回退、升级方式——**"LoRA 跑不起来"不一定是数据问题，可能是容量问题**。

LoRA 调参的边界意识（r 值选型的取舍）：**r 小（8-16）**——省显存、防过拟合，适合格式/风格类浅行为；**r 大（32-64）**——容量更大，适合复杂推理/长文模式，但显存涨、过拟合风险升；**r 不是越大越好**（低秩假设的边际收益递减——r 到 64 后多数任务收益消失）；**alpha 与 r 联动**（alpha = 2×r 是常见起点，scaling 因子影响适配器强度）。选型流程：**r 8 起步 → 不收敛升 r → 收敛但欠拟合升 epoch → 过拟合降 lr**——与 08 篇的止损闭环同构。

## 5. 工程选型速查

| 条件 | 选择 | 理由 |
|------|------|------|
| 数据 <1k | 别微调（Prompt） | 07 篇阈值 |
| 1k-50k + 行为 | **LoRA** | 默认，成本/效果最佳 |
| 1k-50k + 大模型（>13B） | **QLoRA** | 单卡可行 |
| 50k+ + 有算力 | 全量（或 LoRA 对比测） | 容量竞争点 |
| 显存极受限 | QLoRA | 4-bit 压缩 |
| 需要完全保通用能力 | LoRA（+ 低 lr） | 权重改动受限 |

速查表的用法：**先按数据量定方式，再按显存定 LoRA/QLoRA，最后按任务复杂度验证容量**——三步走完，方式选择不再是玄学。与同级 `PEFT 参数高效微调` 子体系的分工：本体系管"选哪种"，那边管"LoRA 怎么做"。

方式选择的常见误区（面试与工程都必避）：**"全量一定更好"**——数据不足时全量是灾难（过拟合 + 遗忘，08 篇），LoRA 在 1k-50k 区间多数任务打平或超越全量；**"QLoRA 有损就别用"**——4-bit 量化的精度损失在行为类任务上通常不可感知，显存收益是实打实的；**"LoRA 只能小任务"**——LoRA 已用于 70B+ 模型的复杂任务微调，容量边界远大于直觉；**"方式选完就固定"**——数据迭代后方式可升级（LoRA → 全量），方式选择是迭代不是一锤定音。四个误区对应四个修正——**方式选择的成熟度 = 数据量驱动 + 显存约束 + 迭代视角**。面试答"你怎么选微调方式"的标准模板：**"数据量决定方式（1k-50k 走 LoRA、50k+ 评估全量），显存决定量化（单卡走 QLoRA），任务复杂度验证容量（r 值从 8 起步迭代）"**——数据量、显存、任务三个维度各给一句，比背参数表可信。

> 🎯 **核心要点**：1k-50k → PEFT 默认、50k+ → 全量可竞争、大模型 + 单卡 → QLoRA；全量显存大头是优化器状态（7B ≈ 56GB+）、LoRA 约 1/3、QLoRA 再降一级；LoRA 三边界（低秩容量/质量差距/遗忘仍可能）；显存快算公式 + 数据量 + 任务复杂度三步选型。
