# 失败信号与止损边界

> 过拟合三信号、灾难性遗忘（小数据+大模型 2 epoch 即发）、SFT 窄有效窗口、early stopping 与训练配方——会止损比会跑起来更值钱

## 1. 过拟合的三个信号

过拟合是微调最常见的失败形态，三个可测信号：

1. **损失背离**：训练 loss 持续下降，验证 loss 平台或上升——最经典的信号（loss 曲线背离即过拟合开始）。
2. **分布外退化**：域内测试表现好，输入稍有偏移（换措辞/换来源/换时段）就明显下降——泛化失败的信号。
3. **复读训练样例**：输出紧密复现训练示例的措辞，新输入上生成重复、低质量文本——权重偏离预训练太远的信号。

**loss 曲线的欺骗性**：仅 50 个示例微调 35 个 epoch，训练 loss 可以持续下降，但生产数据上灾难性失败——**验证集必须是真正 held-out 的**（不同时间段或不同来源的数据），同源分割的验证集会掩盖过拟合。

## 2. 灾难性遗忘：小数据 + 大模型的高危组合

灾难性遗忘的机制：微调把所有权重推向窄任务，预训练知识被当作噪声覆盖。**高危条件：小数据集（<1000 例）+ 高容量模型（7B+）+ 多 epoch——2 个 epoch 就可能发生**，极端案例：任务准确率 99%，但模型答不出基础无关问题。

检测方法（逐 epoch 执行）：**预训练任务 held-out 集评估**（不是微调任务的验证集）——分数下降而任务 loss 下降，就是遗忘正在发生；训练后对比通用文本的 perplexity 与 epoch-0 checkpoint；微调后跑标准基准（通用能力对比）量化知识保留度。

缓解手段：**LoRA/PEFT**（权重改动受限，最有效）；**低学习率**（1e-5 或更低）；**EWC 正则**（弹性权重固化，保护重要参数）；**replay 混合**（微调 batch 里混入通用示例）。注意：**小而同质数据集上的激进全量微调，遗忘无法完全消除**——这是"为什么小数据默认 LoRA"的根本原因（06 篇数据量边界同源）。

2026 研究的机制补充（面试深度）：**TMLR 2026 论文**提出把 token 分为"正向（正常训练）与负向（显式遗忘）"两类——显式遗忘机制让微调在学习目标任务的同时主动遗忘噪声模式，改进微调效果；**SPT 论文（2603.16177）**的过拟合缩放定律给出了"给定算力下最优领域数据重复次数"——遗忘不是玄学，是有缩放定律可循的工程量。两个机制的落点：**遗忘的治理从"事后缓解"走向"训练机制内建"**——面试答遗忘话题时引这两个 2026 机制，就是时效深度。

## 3. SFT 的窄有效窗口（2026 研究）

2026 年 6 月论文（arXiv 2605.17967）的机制结论：**同质数据上 SFT 主要起去噪作用，有效窗口只有前几百到约 1000 训练步**——之后模型重新学习噪声交互模式，测试性能不再提升，且这种过拟合"在损失差距中不可见"。

```text
训练步数 vs 效果（同质数据）：
0-1000 步    → 去噪，有效提升
1000 步+     → 重新学习噪声，无效甚至有害（损失差距不可见）
```

三个工程推论：**训练步数是止损的第一参数**（1000 步附近必须验证，别迷信"多训几轮"）；**数据质量决定窗口后的行为**（脏数据在窗口后被放大学习）；**loss 不是监控的唯一指标**（同质数据下 loss 不可见——要用 held-out 任务指标 + 通用能力指标双线监控）。

## 4. Early Stopping 与训练配方

止损的执行层是 early stopping 与配方：

| 数据量 | epoch 建议 | 学习率建议 |
|:------:|-----------|-----------|
| <100 例 | **1 epoch**（最佳常出现在 epoch 1） | 低（防过拟合） |
| 1k-10k | 约 3 epoch | 2e-5 ~ 5e-5 |
| 100k+ 大而精 | 5-10 epoch | 按实验 |

生产配方（LoRA 常用）：**3 epoch + lr 5e-4 + warmup_steps = min(500, 数据集大小)**。early stopping 纪律：**验证 loss 平台或上升即停**；用 patience（连续 3 次验证 loss 上升才停）避免单次波动误停——`EarlyStoppingCallback(patience=2, threshold=0.001)` 是 HuggingFace 的落地形态。注意：**单次 spike 不代表过拟合**，patience 防误杀。

## 5. 止损的完整流程

```text
训练前：基线（基座能力指标 + 任务指标）、held-out 验证集（跨时段/来源）
训练中：逐 epoch 三监控——任务验证 loss / 通用能力指标 / 复读抽查
触发条件：
  · 验证 loss 背离 → early stopping（patience 3）
  · 通用能力下降 → 降 lr / 加正则 / 换 LoRA（若全量）
  · 1000 步无提升 → 检查数据质量（同质数据窗口已过）
  · 复读出现 → 回退 checkpoint / 减 epoch
训练后：全量评估（任务 + 通用 + 幻觉率），不达标回退
```

止损的本质：**微调是"试错 + 回退"的循环，不是"一把梭"**——每个信号对应明确动作，checkpoint 保留（epoch 级）是回退的基础设施。与同级 `微调常见问题` 子体系的分工：那边讲"坑怎么排"，本体系讲"信号怎么读、什么时候停"。

止损的配套基础设施（没有这些，信号读了也没用）：**epoch 级 checkpoint**（每个 epoch 存档——回退到"通用能力还在"的版本，是遗忘事故的止血点）；**训练日志自动采集**（loss/验证指标/通用基准三线进看板——人工盯 loss 会漏，自动化才可靠）；**评估集冻结**（任务评估集 + 通用能力集在训练期间不可变——集子换了，指标对比就失去意义）；**发布门禁**（评估不达标不允许部署——止损的终点是"不合格的模型进不了生产"，把止损前置到发布流程）。落点：**止损不是训练时的技巧，是训练前后的工程体系**——checkpoint、监控、评估、门禁四件套齐了，止损才闭环。面试答"微调失败了怎么办"的模板：**"先归因（过拟合/遗忘/数据/容量四类信号各看什么指标）→ 再动作（early stopping/降 lr/换 LoRA/查数据）→ 后回退（checkpoint 回滚 + 发布门禁拦截）"**——有归因有动作有回退，比"重训一次"成熟一个量级。

> 🎯 **核心要点**：过拟合三信号（loss 背离/分布外退化/复读样例）且 loss 可欺骗（验证集要 held-out 跨时段）；灾难性遗忘高危组合（<1000 例 + 7B+ + 2 epoch）用 LoRA/低 lr/EWC/replay 缓解；SFT 窄窗口（前几百到 1000 步）后是隐形过拟合；配方（小数据 1 epoch、中等 3 epoch）+ patience early stopping；止损是"信号 → 动作 → 回退"的闭环。
