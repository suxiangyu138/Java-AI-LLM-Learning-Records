# 微调 vs RAG

> 知识缺口是 RAG 的主场——事实、时效、私有数据；微调注入知识的幻觉风险；2026 实证研究的动态边界

## 1. 知识缺口 = RAG 主场

RAG 解决三类知识缺口：**事实缺失**（模型不知道的具体信息）、**时效变化**（信息更新了，模型权重还是旧的）、**私有数据**（客户专属、内部文档——不在任何公开训练集里）。

RAG 相对微调注入知识的四个结构性优势：

1. **知识实时**：检索管道更新即可，无需重训——文档更新分钟级生效。
2. **可溯源**：回答带引用来源，审计与纠错有据——知识可信度的底线。
3. **无幻觉放大**：模型只基于检索到的上下文作答，编造空间被压缩。
4. **成本可控**：无训练成本，增量是检索管道与存储——与数据量解耦（检索复杂度随索引优化，而非随数据线性重训）。

判断口诀：**"它不知道" → RAG；"它知道但输出不对" → 行为问题，回 Prompt/微调轨道**。

## 2. 微调注入知识的幻觉风险

研究（Ovadia 2023）的核心发现常被引为决策依据：**在事实性内容上微调，幻觉率不降反升**——机制分析：微调把事实压进权重，等于教模型"自信地生成这些内容"，但没有教会它"区分知道与不知道"；遇到训练外变体时，模型按"训练分布"编造得更加流畅。

三个工程含义：**知识型场景默认 RAG**（微调不是第一选项，是最后选项）；**混合场景把知识放 RAG 层**（微调只负责形式，事实由检索供给——09 篇的 form/facts 分层）；**确实要微调知识时**（如私有术语表）用"知识 + 行为混合数据"并在评估中单列幻觉率指标（08 篇的评估纪律）。

RAG 的适用边界也要说清（避免"无脑 RAG"）：**知识可检索**（有结构化文档/知识库——散落在对话里的隐性知识 RAG 无从检索）；**检索质量达标**（切分与召回质量决定答案质量——检索垃圾 = 答案垃圾，RAG 的瓶颈在检索侧不在生成侧）；**延迟可接受**（检索链路加一跳，延迟敏感场景评估缓存）。三个边界任一不满足，RAG 不是自动最优——**"知识缺口用 RAG"是方向正确，落地质量靠检索工程**。

## 3. 2026 实证研究：边界随任务复杂度移动

2026 年 5 月发表的地理学实证研究（Annals of the American Association of Geographers）把三种策略概念化为：**引用（RAG）、内化（微调）、激活（Prompt）**——跨多个 LLM 的实验结论是**没有普遍最优策略**，最优选择随任务认知复杂度切换：

| 任务复杂度 | 最优策略 | 说明 |
|-----------|---------|------|
| 低复杂度召回 | **RAG 优** | 事实检索，微调/Prompt 也有效 |
| 多步推理 | RAG 与微调相当 | Prompt 开始吃力 |
| 创意综合（最高要求） | **微调最优** | Prompt 退化到基线 |

面试与工程的双重含义：**"RAG 永远比微调好"是过时认知**——低复杂度召回是 RAG 主场，但创意综合（风格化长文、领域创意生成）微调反而最优；**边界判断要按任务类型分而治之**，不能一个策略打天下。

任务分类的实操框架（把"任务复杂度"落地）：**任务清单拆解**（把业务拆成任务类型：事实问答 / 文档摘要 / 格式抽取 / 风格生成 / 多步推理——每类按复杂度归位）；**逐类选策略**（事实问答 → RAG；格式抽取 → Prompt/微调；风格生成 → 微调候选；多步推理 → RAG + 推理增强）；**混合任务按占比定主策略**（80% 事实问答 + 20% 风格生成 → RAG 为主 + 风格 Prompt 兜底，微调只在风格占比高时入场）。落点：**策略选择是任务级的，不是系统级的**——一个系统内可以"RAG 主 + 微调辅 + Prompt 编排"共存（09 篇混合架构）。

## 4. 知识型场景的混合姿势

知识 + 行为的真实需求几乎总是混合的，2026 生产默认是分层：**RAG 供给事实，微调（或 Prompt）控制形式**。

```text
查询 → RAG 检索（事实/文档/引用）→ 组装上下文
     → 行为控制层（微调模型 or Prompt）→ 按领域格式生成
     → 输出带引用来源（溯源）
```

典型的混合案例：**客服系统**——产品知识实时更新（RAG 管），回复语气与工单格式固定（微调管），对话策略动态（Prompt 管）。判断要点：**知识变化频率决定 RAG 的价值**（知识月更 → RAG 必须；知识十年不变 → 微调内化可接受）；**事实重要性决定溯源需求**（要审计 → RAG；不要 → 可权衡）。

## 5. 面试高频追问：RAG 的短板与微调的机会窗口

面试官常追问"RAG 有什么短板，是不是微调的机会"——三个标准回答：**检索质量瓶颈**（召回不达标的场景，微调可部分兜底——如教模型"先判断是否需要检索"）；**上下文窗口压力**（大文档库检索结果拼不进窗口——微调内化高频知识可减负，但低频知识仍靠 RAG）；**延迟与成本**（检索链路多一跳——对延迟敏感且知识静态的场景，微调内化值得评估）。回答的落点：**RAG 短板 ≠ 微调主场**——先看短板是不是"行为缺口"（是才轮到微调），知识场景的 RAG 短板（检索质量）应优化检索而非换微调。

> 🎯 **核心要点**：知识缺口三类（事实/时效/私有）是 RAG 主场，四优势（实时/溯源/无幻觉放大/成本解耦）；微调注入知识增加幻觉（Ovadia）；2026 实证无普遍最优——低复杂度 RAG 优、创意综合微调优；生产默认是"RAG 管事实 + 行为层管形式"分层；RAG 短板不等于微调机会，先判缺口类型。
