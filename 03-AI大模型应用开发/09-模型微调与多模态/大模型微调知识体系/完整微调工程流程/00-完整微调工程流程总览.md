## 3. 为什么必须学透工程流程

1. **微调是流程工程不是单点技术**：微调失败的最大原因不是"不会训练"，而是流程断裂——没定指标就训（无法验收）、没建基线就上（无法证明提升）、没有监控就跑长任务（故障浪费算力）。本体系把端到端流程拆成九阶段，每阶段有输入、有产物、有验收点。
2. **2026 年的门槛在流程不在技术**：框架能力已经成熟（QLoRA 单卡可训 7B-14B，工具链齐全）——框架对比的实测数据（Unsloth 2.8 倍速、35% 省显存）和组合模式（Unsloth 加速 + TRL 对齐）直接决定工程效率，本体系 04 篇给完整决策矩阵。
3. **评估先行是 2026 的核心纪律**：先定考卷再训练——验收标准预设（自定义评估集提升 >3%、标准基准回归 <1%）在训练前写好，训练后按门禁决策上不上线。没有门禁的微调是"自嗨式微调"。
4. **部署不是最后一步而是另一段工程**：LoRA 合并（float16、merge_and_unload）、量化（GGUF/AWQ）、vLLM 服务（单模型 vs 多 LoRA）各有坑（vLLM 不支持 modules_to_save、合并不可逆），本体系 09 篇全给。
5. **面试的最后一问往往是工程题**："完整微调一个模型要几步""训练崩了怎么排""上线怎么验收"——本体系 10 篇把工程面试题全部覆盖。

## 4. 核心概念速查

### 4.1 核心概念

| 概念 | 一句话 | 关键数字 |
|------|--------|---------|
| 九阶段流水线 | 需求→评估先行→数据→训练→验收→部署→上线→迭代 | 每阶段有产物 |
| 指标先行 | 先定任务与评估指标再动数据 | 分类 F1/生成 BLEU/LLM judge |
| eval-first | 先建基线再训练 | 门禁：>3% 提升、<1% 回归 |
| QLoRA | 4-bit 量化 + LoRA | 省 ~75% 显存 |
| 门禁 | 对比基线的验收标准 | 提升 >3% 且无显著回归 |
| merge_and_unload | LoRA 合并进底座 | 必须 float16、不可逆 |
| 多 LoRA 服务 | 一个底座动态挂多个适配器 | 开销 2-5% |
| 监控三件套 | wandb + 日志 + 系统指标 | 长任务强制 |
| OOM 调试顺序 | QLoRA→降 batch→梯度检查点→降长度→换小模型 | 五步按序 |
| 断点续训 | resume_from_checkpoint | 长任务必备 |

### 4.2 框架速查（2026 实测，LLaMA 3.1 8B LoRA 4-bit）

| 框架 | Tokens/s | 显存 | 定位 |
|------|:---:|:---:|------|
| Unsloth | ~4,200（2.8x） | ~8GB | 速度与省显存之王 |
| Axolotl | ~1,500 | ~16GB | YAML 可复现生产 |
| LLaMA-Factory | ~1,480 | ~16GB | 模型支持最广 + WebUI |
| TRL | ~1,450 | ~18GB | 官方对齐训练（DPO/GRPO） |

### 4.3 常见误区速查

- "先训完再想怎么评估" → 错：评估先行，没有基线就没有验收
- "框架选一个用到死" → 错：2026 标准是组合（Unsloth 加速 + TRL 对齐）
- "训练 loss 降了就能上线" → 错：要过验收门禁（对比基线）
- "LoRA 不用合并直接部署" → 错：vLLM 加载 PEFT 适配器有硬约束

## 5. 与周边知识的关系

```text
                    ┌── 边界判断/ —— 决策层：要不要微调（流程第 1 步的输入）
大模型微调知识体系 ├── 基础概念/ —— 概念层：原理（流程各阶段的"为什么"）
                    ├── 数据集体系/ —— 数据模块：第 5 阶段（数据准备）的完整方法论
                    ├── PEFT / 超参 / 常见问题/ —— 训练细节：第 6-7 阶段的深潜
                    └── 03-AI.../模型推理与部署/ —— 部署深潜：第 9 阶段的下游
```

**本体系与同级子体系的分工**：`数据集体系` 是"数据怎么做"（本体系第 5 阶段引用它）、`PEFT` 是"参数怎么调"（第 6 阶段引用它）、`训练关键超参` 是"超参怎么选"（第 6-7 阶段引用它）、本体系是**把它们串起来的流水线**——回答"每一步做什么、产出什么、怎么验收"。读法建议：先读本体系建立全局，再按阶段进对应子体系深潜。

## 6. 学习路线推荐

**路线一：工程全貌（1 天，对应模块 01-03 + 08 + 10）**
阶段划分 → 需求与指标 → 评估先行 → 验收 → 面试题；建立"端到端"心智模型，面试工程题全覆盖。

**路线二：动手实操（2-3 天，对应模块 04-09）**
环境与框架 → 数据 → 训练 → 监控 → 验收 → 部署；配合一次真实微调（QLoRA SFT）完整走一遍流水线。

**路线三：生产负责人（对应模块 02-03 + 07-09）**
需求与门禁 → 监控干预 → 验收 → 部署运维；面向生产交付，重点是门禁与迭代闭环。

> 🎯 **核心要点**：工程流程的学习终点 = "**会拆解**（九阶段流水线）、**会先行**（指标先行 + 评估先行 + 门禁预设）、**会选型**（框架组合与硬件）、**会监控**（三件套 + OOM 五步）、**会验收**（对比基线的门禁决策）、**会交付**（合并/量化/服务/灰度）"——六件事把微调从"跑脚本"升级为"做工程"；记住"每一步有产物，每一步可验证"是全流程的第一原则。
