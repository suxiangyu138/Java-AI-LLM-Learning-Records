# 训练配置与启动

> 流程第 6 阶段：LoRA/QLoRA 配置（r/alpha/量化）、训练脚本骨架、启动前检查清单——配置决定训练成败，启动检查决定算力浪费

## 1. LoRA 配置：r、alpha 与目标模块

LoRA 核心配置三件（原理在 `../PEFT 参数高效微调（面试高频）/` 体系，此处给工程默认）：

**秩 r**：低秩矩阵的维度。r=8 轻量（省显存、改动小）、r=16 通用默认（2026 大量配方默认）、r=32-64 用于复杂任务（更多容量，配 rsLoRA 稳定大秩训练）。经验：**小数据（<1k）r=8 起步，常规 16，任务复杂再升**——r 不是越大越好，大 r 在数据不足时更快过拟合。

**缩放 alpha**：LoRA 的缩放系数（W = W₀ + (alpha/r)·BA）。2026 年共识：**alpha == r（缩放 1.0）**——老配方"alpha 是 r 的两倍"已不推荐（alpha/r 决定有效学习率，1.0 是当前校准值）；改 alpha 等价于改该模块的学习率，调参时二选一别双调。

**目标模块**：默认 attn 的 q/k/v/o（`modules_to_save` 之外纯低秩部分）；`modules_to_save`（embed_tokens、lm_head、norm）会破坏 vLLM 多 LoRA 兼容（09 篇硬约束）——**要部署多 LoRA 服务就别配 modules_to_save**。

**什么时候加模块**：默认 q/k/v/o 覆盖绝大多数任务；任务对"输出词表分布"敏感（术语/风格强约束）可加 lm_head；长上下文任务可加 o_proj 或升秩——**加模块的代价是显存与过拟合风险**（每加一个模块就多一批可训练参数），优先升 r 而非加模块，是 2026 的通用经验。DoRA（幅度+方向分解）在低秩时稳定带来 1-4% 收益且推理零额外开销，复杂任务可尝试（框架支持时）。

**dropout**：默认 0.05-0.1；2026 研究提示 LoRA dropout 在短训练里作为正则不可靠（`../基础概念/06-训练循环Epoch-Batch-Step.md` 03 节），过拟合优先降 epoch 而非加 dropout。

## 2. QLoRA 配置：4-bit 量化

QLoRA = 4-bit 量化底座 + LoRA 适配层（省显存 ~75%，`../基础概念/03-Transformer与参数基础.md` 05 节）：

- **量化配置**：`BitsAndBytesConfig`（load_in_4bit=True、bnb_4bit_quant_type="nf4"、bnb_4bit_compute_dtype=bf16、bnb_4bit_use_double_quant=True）——NF4 + 双量化是 2026 标准；**注意底座用 4-bit 加载是训练期策略，导出合并时必须 float16 加载**（09 篇）。
- **配套省显存**：8-bit 优化器（bitsandbytes，优化器状态砍半）、梯度检查点（gradient checkpointing，省 ~30% 显存费 ~20% 速度）、4-bit 优化器（极致省显存场景）。
- **适用边界**：QLoRA 效果接近 LoRA/全量（2026 大量实证），7B-14B 单卡甜点；**训练与推理的量化是两回事**——训练期 4-bit 是省显存手段，推理期量化（GGUF/AWQ）是部署手段，不要混。

**混合精度**：训练统一用 bf16 计算（compute_dtype="bf16"）——bf16 范围大不易溢出，是 2026 训练的事实标准（fp16 在 loss scale 管理不当时常出 NaN，07 篇排查时先查精度配置）；权重存储 fp16/bf16，优化器状态 fp32（Adam 数值敏感）——三精度分工是标准配置。

## 3. 训练脚本骨架（QLoRA SFT 最小配方）

```python
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
from peft import LoraConfig, get_peft_model
from trl import SFTConfig, SFTTrainer

bnb = BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4",
                         bnb_4bit_compute_dtype="bf16", bnb_4bit_use_double_quant=True)
model = AutoModelForCausalLM.from_pretrained("Qwen/Qwen3-8B", quantization_config=bnb)
lora = LoraConfig(r=16, lora_alpha=16, target_modules=["q_proj","k_proj","v_proj","o_proj"],
                  lora_dropout=0.05)
train_cfg = SFTConfig(output_dir="runs/cust-sft-v3", per_device_train_batch_size=4,
                      gradient_accumulation_steps=4, learning_rate=2e-4, num_train_epochs=2,
                      warmup_ratio=0.03, lr_scheduler_type="cosine", logging_steps=50,
                      eval_steps=200, save_steps=500, load_best_model_at_end=True,
                      metric_for_best_model="eval_loss", report_to=["wandb"])
trainer = SFTTrainer(model=model, args=train_cfg, train_dataset=train_ds,
                     eval_dataset=eval_ds, tokenizer=tokenizer)
trainer.train()
```

关键点：**配置全部走 Trainer 参数而非手写训练循环**（epoch 1-3、lr 2e-4、warmup 0.03、cosine 调度的原理见 `../基础概念/` 05-06 篇）；`load_best_model_at_end` 按 eval_loss 自动保存最优；`report_to` 接监控（07 篇）。

**学习率与 epoch 的配合**：epoch 决定"数据见几遍"，学习率决定"每次见学多猛"——低 epoch + 高 lr 学不牢，高 epoch + 低 lr 学得慢且易遗忘。2026 起点组合：epoch 2-3 + lr 2e-4 + cosine 调度；**过拟合优先降 epoch、欠拟合优先升 lr，方向别反**（调参逻辑见 `../训练关键超参 & 显存优化技术/` 体系）。

**数据加载配置**：shuffle 默认开启 + 固定 seed（多卡可复现）；dataloader 的 num_workers 与 persistent_workers 减少加载抖动（吞吐骤降先查 dataloader 瓶颈）；序列长度由 `max_seq_length` 截断 + packing 处理长尾样本（`../基础概念/06-训练循环Epoch-Batch-Step.md` 06 节）。

## 4. 分布式配置：多卡与模型并行

单卡放不下的三种升级路径：**数据并行**（多卡同一份数据不同 batch，DeepSpeed ZeRO-2/3，最常用）；**模型并行**（张量并行，全量微调大模型）；**CPU offload**（ZeRO-3 把优化器状态放 CPU，显存极限场景）。

要点：batch 按"每卡"配（`per_device_train_batch_size`），有效 batch = 每卡 × 卡数 × 梯度累积（`../基础概念/06-训练循环Epoch-Batch-Step.md` 02 节）；多卡随机种子固定（可复现）；多节点注意 NCCL 环境变量与共享存储（checkpoint 挂共享盘）。

**分布式前先确认是否真的需要**：QLoRA 把绝大多数 7B-14B 场景压进单卡（RTX 4090/5090），多卡增加的复杂度（通信、同步、排障）是实打实的工程成本——单卡能跑就不上分布式，这是 2026 年最容易被忽视的效率建议。

**断点配置**：save_steps 500-1000、save_total_limit 3、`resume_from_checkpoint`（恢复时 scheduler 从保存 step 继续，不要重新预热）——长任务断电/超时是常态，断点是第一道保险（`../基础概念/06-训练循环Epoch-Batch-Step.md` 07 节）。

## 5. 启动前检查清单

正式启动前的十分钟检查（每项都有明确失败后果）：

1. **冒烟训练**：50 步小跑——数据加载/模板渲染/掩码/长度无报错（05 篇）。
2. **显存预检**：`nvidia-smi` 确认可用显存；首次 step 的峰值显存（日志/监控）不超过 90%（超了先降 batch 或开梯度检查点）。
3. **梯度检查**：前几十步 grad norm 有界（不 NaN/不爆炸）；loss 初始值合理（≈ 底座在该数据的交叉熵量级，`../基础概念/04-损失函数与训练目标.md` 02 节）。
4. **日志与监控确认**：wandb 在线（07 篇监控三件套）、日志目录可写、checkpoint 目录权限。
5. **配置归档**：训练配置 + 数据 manifest 版本 + 环境版本写入实验记录——"每一步有产物"的第六阶段产物。归档的载体：训练配置存 git、实验记录表（日期/模型/数据版本/超参/结果链接）字段固定——**十秒可查"某版模型怎么训出来的"**是归档的验收标准。

**eval 与 save 的步数关系**：eval_steps 与 save_steps 对齐或为其约一半——保证"最优 eval loss 的 checkpoint"总是被保存过（`load_best_model_at_end` 依赖这点）；eval 太频繁浪费算力（eval 也吃显存与时间），数据量大时 eval_steps 可放宽。

**启动错误速查**（按出现频率）：`bitsandbytes` 与 CUDA 不匹配（4-bit 加载报错第一嫌疑，按版本矩阵重装）；`tokenizer` 词表与模型不匹配（换底座必须换 tokenizer，混用报 embedding 维度错误）；transformers/peft 小版本不兼容（`pip check` + 固定版本矩阵）；`max_seq_length` 超模型支持长度（报 RoPE 维度错误，查模型 config 的 max_position_embeddings）；分布式端口冲突（多任务共机时 `MASTER_PORT` 冲突报 NCCL 错误）——**报错信息最后一行 + 完整 traceback 是排障起点**（07 篇工作流）。

> 🎯 **核心要点**：LoRA 配置 = r=16 默认（小数据 8、复杂任务 32-64）+ alpha==r（2026 共识）+ 目标模块 q/k/v/o（要部署多 LoRA 别配 modules_to_save）；QLoRA = NF4 + 双量化 + 8bit 优化器 + 梯度检查点，训练期量化与部署期量化是两回事；脚本骨架全走 Trainer 参数（epoch 1-3/lr 2e-4/cosine/load_best）；分布式先数据并行；启动前五查（冒烟/显存/梯度/监控/归档）防算力浪费。
