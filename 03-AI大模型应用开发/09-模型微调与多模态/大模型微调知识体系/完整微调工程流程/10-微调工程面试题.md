# 微调工程面试题

> 微调面试的工程题集中在"完整流程怎么走、训练崩了怎么排、怎么验收、怎么上线"——每题给标准答案与 2026 工程实践，背熟即得分

## 1. 必问基础 8 题

### Q1：完整微调一个模型，从需求到上线要经过哪些阶段？

**答案**：九阶段——需求分析（任务定义 + 指标 + 约束）→ 评估先行（金标评估集 + 底座基线 + 门禁预设）→ 方案设计（底座/方法/框架/预算）→ 环境搭建（可复现）→ 数据准备（种子→合成→清洗→去重→格式→manifest）→ 训练配置与启动（LoRA 配置 + 冒烟）→ 训练监控（三件套 + 干预）→ 模型验收（评估矩阵 + 门禁）→ 导出部署与迭代（合并/服务/灰度/回流）。

**加分点**：强调"评估必须先于训练"（没有基线就没有验收对象）和"每一步有产物，每一步可验证"——比背阶段名多一层工程思想。

### Q2：为什么要指标先行、评估先行？具体怎么做？

**答案**：指标先行 = 需求分析阶段就定义可计算的评估指标（分类 F1、生成 BLEU/ROUGE + LLM judge、推理 Pass@k、结构化输出 JSON 解析率）——指标决定"好坏怎么算"，没有指标训练完无法验收。评估先行 = 训练前完成三件事：金标评估集（从需求规范生成，300-800 条，版本化管理）、底座基线报告（同套评估脚本 + Prompt 基线）、验收门禁预设（>3% 提升、<1% 标准基准回归）。**门禁写在训练前防止事后找理由**。

### Q3：四大微调框架怎么选？2026 年推荐的组合？

**答案**：Unsloth（速度 2.8 倍、省显存 35%，单卡原型首选）、TRL（HF 官方，DPO/GRPO/RLHF 对齐训练标准）、LLaMA-Factory（模型支持最广 + WebUI，快速探索）、Axolotl（YAML 可复现，生产配置）。组合模式：**Unsloth 做 SFT 加速 + TRL 做 DPO 对齐**（2026 标准配方 QLoRA SFT → DPO → 评估）；生产编排用 LLaMA-Factory（CLI）+ Unsloth 后端。"快速原型用 Unsloth，规模后切稳定框架"是通用建议。

### Q4：LoRA 的 r 和 alpha 怎么配？2026 年有什么共识？

**答案**：r 是低秩矩阵维度——小数据（<1k）r=8 起步、常规 r=16、复杂任务 r=32-64（配 rsLoRA 稳定大秩）；r 不是越大越好，数据不足时大 r 更快过拟合。alpha 是缩放系数（W = W₀ + (alpha/r)·BA）——**2026 共识 alpha == r（缩放 1.0）**，老配方"alpha 是 r 的两倍"已不推荐；改 alpha 等价于改该模块的有效学习率，调参二选一别双调。

### Q5：训练中 loss 出现 NaN 或 grad norm 飙升，怎么排查？

**答案**：先诊断再动手（别用改配置掩盖 bug）。NaN 排查顺序：降学习率（3-5 倍）排除数值发散 → 查数据（NaN/脏样本/重复样本）→ 查精度（bf16 溢出换 fp32 或调 loss scale）。grad norm 飙升：**先查数据**（重复/脏样本是第一嫌疑）再查梯度裁剪配置。**止损优先**：判定训练已坏（eval 连续背离、loss 发散）该停就停——省下算力用于排查。修复进 git 不临时覆盖，修复后重跑冒烟。

### Q6：OOM 怎么调？调试顺序的依据是什么？

**答案**：五步按序——启用 QLoRA（省 ~75% 显存，最大杠杆）→ 降 batch size（降到 1，配梯度累积补回有效 batch）→ 开梯度检查点（省 ~30% 显存、费 ~20% 速度）→ 降 max_seq_length（激活值随序列长度线性增长）→ 换小模型（7B → 1-3B）。顺序逻辑：前四步"保留方案"（不改模型与效果假设），第五步才"改变方案"——每一步都有显存账本依据（推理 1 份、LoRA ~1.1 份、全量 4-5 份权重）。

### Q7：LoRA 训练完怎么部署？合并和多 LoRA 服务怎么选？

**答案**：两条路径。**合并**：float16 加载底座（不能用 4-bit，会损精度）→ `merge_and_unload()` → 保存完整模型 → vLLM 直接服务；合并不可逆（回退只能从原始底座重来），合并后必须重验（checkpoint 选择差异是离线评估与线上不一致的常见来源）。**动态多 LoRA**：底座常驻、按请求热挂适配器（多变体场景），vLLM 硬约束——`enable_lora=True` + 适配器预注册 + **modules_to_save 必须为 null**（全秩张量 vLLM 不支持）。选型：单模型合并、多变体动态挂（还白得秒级回滚）。

### Q8：微调模型怎么验收？门禁标准是什么？

**答案**：评估矩阵四维度——任务指标（评估集）、通用能力回测（MMLU 类，防遗忘）、LLM judge（软质量）、人工双盲（最终裁判）。对比用三线：底座裸跑 vs 底座+Prompt vs 微调模型——**增量是对 Prompt 基线的增量**（Prompt 能解决的不算微调功劳）。门禁：自定义评估集提升 >3%、标准基准回归 <1%、业务指标达标、人工双盲胜出——结果只有"上线/回炉"两种，验收报告归档。

## 2. 工程场景题

**场景一**："训练跑了两小时，发现 eval loss 从 1.4 开始反弹，train loss 还在降，怎么办？"——过拟合信号（train-eval gap 拉大）：立即检查 wandb 曲线确认拐点 step → early stopping，用 `load_best_model_at_end` 找最优 checkpoint → 本轮止损完成；下一轮降 epoch（2→1）或降学习率；同时查数据（是否重复样本多）。如果是小数据+大模型，考虑混入通用数据防遗忘。

**场景二**："微调模型评估集分数提升了 8%，但线上灰度用户反馈反而变差了，怎么排查？"——评估与线上不一致，按序排查：**评估路径 vs 服务路径差异**（合并后的模型重验了吗？评估用的是训练产物还是上线产物）；**评估集与真实请求分布错位**（线上请求 embedding 与评估集分布对比，MMD 检测——评估集缺覆盖 = 考卷漏题）；**灰度监控指标**（任务成功率 vs 评估指标的对应关系）。修复：补评估集分布对齐（失败案例先补评估集），再重跑回归。

**场景三**："团队要微调 70B 模型，只有一台 48GB 显卡，怎么给方案？"——先算显存账：QLoRA（4-bit）70B 权重约 36-40GB + 适配器，48GB **极限可行但很紧**（激活值空间不足，需降 batch 到 1 + 梯度检查点 + 8bit 优化器）；更务实的选择：**降底座到 32B**（RTX 6000 Pro 级 QLoRA 更稳）或 **14B 级别先验证效果**（数据/效果验证用 14B，规模化再升 70B——2026 年常见策略：小模型验证、大模型投产）；同时建议检查需求是否真的需要 70B（底座能力匹配度评估，`../基础概念/02-大模型训练三阶段范式.md` 04 节）。

## 3. 答题范式总结

工程题标准答题结构（四步）：**说流程**（问题落在九阶段的哪一段）→ **给顺序**（处理动作按序：诊断→修复→验证）→ **带数字**（>3% 门禁、5 步 OOM、r=16/alpha==r、float16 合并）→ **讲边界**（什么时候该止损/该回炉/该重审——工程思维的关键是"知道什么时候停"）。

> 🎯 **核心要点**：工程面试 = 8 题全覆盖（九阶段/评估先行/框架组合/LoRA 配置/NaN 排查/OOM 五步/部署两路径/验收门禁）；答题四步 = 流程→顺序→数字→边界；场景题先定位阶段（训练中/验收时/上线后）再开方；进阶追问会导向数据集体系（数据）与 PEFT/超参体系（训练细节）——工程答得稳，证明的不只是知识，是做过项目。
