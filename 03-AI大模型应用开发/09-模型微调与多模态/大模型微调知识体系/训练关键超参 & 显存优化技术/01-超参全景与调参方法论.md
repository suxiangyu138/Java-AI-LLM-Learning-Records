# 超参全景与调参方法论

> 超参体系的入口：超参分类地图、2026 年 Baseten 后训练科学的三个核心结论、三种搜索方法（网格/进化/语言引导贝叶斯）——超参是经验问题，不是信仰问题

## 1. 超参分类地图

微调超参按作用对象分四类：

**训练结构超参**：epoch（数据见几遍）、batch size（每步样本数）、梯度累积（显存受限时的等效放大）、max_seq_length（序列长度——同时是显存与覆盖度的权衡）。

**优化器超参**：学习率（最重要的单个超参）、warmup 比例、调度器类型（cosine/linear/constant）、weight decay、梯度裁剪（max_grad_norm）、优化器选择（AdamW/8bit/Adafactor）。

**数据相关超参**：packing 开关、shuffle、seed、数据混合比例（业务/通用配比）。

**方法相关超参**（LoRA 家族）：秩 r、缩放 alpha、dropout、目标模块、量化配置（NF4/FP8/位深）。

四类超参的"可调空间"不同：**结构类与优化器类对效果影响最大**（lr/epoch/batch），方法类次之（r/alpha），数据类多为工程开关——调参的精力分配应该向影响大的倾斜，**先定结构与优化器，再精调方法参数**。

## 2. 2026 实证：Baseten 后训练科学

Baseten 2026 年 6 月发布的后训练科学研究，用受控单变量扫描（Qwen3/Llama，稠密与 MoE，0.6B-235B，四个真实客户数据集，LoRA 与全量）给出了三个颠覆直觉的结论：

**结论一：LoRA 学习率跨规模稳定**。最优 LoRA 学习率在从 0.6B 到 235B 的模型上**基本持平**（两个数量级的模型规模，lr 量级不变）——这意味着"2e-4 起步"可以跨模型迁移，不用每次从头扫。这是调参实践里最有用的一个结论。

**结论二：batch size 是成本杠杆，不是质量杠杆**。batch size 对最终质量的影响远小于学习率——它更像"算力成本与训练稳定性的权衡"（大 batch 稳定但贵，小 batch + 累积便宜）——**batch 的默认策略"每卡 1-2 + 梯度累积"是安全的**，调参精力不该花在 batch 上。

**结论三：LoRA 恢复全量微调收益的中位数 98%**。可训练参数少几个数量级，收益只差 2%——这是 PEFT 路线的质量背书（阈值判断见边界判断 06 篇）。

研究还覆盖：训多少 epoch 开始侵蚀通用指令遵循（见 04 篇）、验证 loss 是否忠实排序下游质量（见 05 篇）、几何感知优化器能否胜过 AdamW（结论：多数场景不能——AdamW 仍是标准）。

## 3. 搜索方法：从手动到自动

超参选择正在从"继承传说"走向"系统搜索"，2026 年三种方法并存：

**网格/粗扫-细扫**（经典）：先粗扫宽范围（lr 跨一个数量级，如 1e-6~2e-5、epoch 1-3 粗调），锁定最优区间后细扫；并行跑多个候选（各用少量步数/小数据代理评估）→ 最优者全量训练 → held-out 验证。**这是最实用的起步方法**——2-3 个变量的网格成本可接受。

**进化搜索（AlphaEvolve）**：LLM 以代码形式提出 LoRA 配置（只改 EVOLVE-BLOCK 标记内的参数），真实训练跑分（如 200 步 LoRA bf16）驱动下一代——搜索范围示例：r 4-64、alpha 8-128、dropout 0-0.2、lr 1e-5~1e-3、scheduler 四选、warmup 0-0.1、weight_decay 0-0.1、优化器三选、max_grad_norm 0.1-5.0。**适合预算充足、效果追求极致的场景**。

**语言引导贝叶斯优化（ICML 2026）**：把 LoRA 配置写成带领域解释的文本描述，用冻结 LLM + 可学习 token + 投影层构建连续搜索空间——用 10% 数据代理评估砍掉单次试验成本，约 30 次试验内显著超越默认配置与传统 HPO。**适合 LoRA 组合空间巨大（4.5 万+ 配置）的精细调优**。

## 4. 调参顺序与预算分配

调参不是"全参数乱扫"，而是**分层推进**（与 `../完整微调工程流程/02-需求分析与方案设计.md` 的预算理念一致）：

1. **先定结构**（免费层）：epoch 1-3、batch 每卡 1-2 + 累积、max_seq_length 按数据分布——这些先用安全默认，不动。
2. **再调学习率**（核心层）：用粗扫-细扫定 lr（最影响质量），其他参数固定——**lr 是唯一值得单独精调的超参**。
3. **后调方法参数**（精调层）：LoRA r/alpha（复杂任务升 r）、warmup/调度（lr 定了再配）、weight decay。
4. **最后才碰数据相关**（工程层）：packing、混入比例——这些多与显存/遗忘相关，不解决质量问题。

预算原则：**搜索用代理评估（小步数/小数据），最终验证用全量**——代理评估的成本是正式训练的 1/10 甚至更少；每轮搜索记录（配置 + 分数）进实验表，多轮之间可比（`../完整微调工程流程/06-训练配置与启动.md` 05 节）。

**代理评估的可靠性前提**：代理分数（小步数训练）与全量分数的排序要一致——先做一次校准实验（跑 3-5 个配置的代理 + 全量，对比排序是否一致）；**代理评估只用于"淘汰明显差的"**，最终决策必须全量验证（代理排序前 2 名经常互换）。这个校准一次投入，后续每轮搜索都受益——是"搜索预算"里最值得花的一笔。

## 5. 2026 的调参纪律

Baseten 研究的核心信息：**超参选择是经验问题，应该带测量与不确定性，而不是默认值信仰**——抄别人配置必须带验证集复验（同一个 2e-4，你的数据/任务可能最优在 8e-5）；"默认值"是起点不是终点（copy-paste 默认 = 放弃了 10-20% 的潜在提升）。
同时注意**超参迁移研究的进展**（Apple arXiv:2512.22382 跨模块/宽度/深度/batch/时长的迁移）——未来可能"一套超参多场景复用"，2026 年仍需各自验证。

**调参的"数字资产"**：每次调参实验都产出"配置 + 分数"的数据对——按任务/数据/模型组织成调参记录表（`../完整微调工程流程/06-训练配置与启动.md` 05 节）；**同一类任务的调参记录跨项目复用**（客服类任务的最优 lr 区间、代码类任务的 r 选择——"上次的经验"是比默认值更好的起点）；记录表积累到 10+ 条后，可以画"lr vs 分数"散点图发现自己的经验规律——**调参记录是团队的隐性知识显性化**。

> 🎯 **核心要点**：超参四类（结构/优化器/数据/方法），精力向影响大的倾斜（lr > epoch/batch > r/alpha）；Baseten 三结论——lr 跨规模稳定、batch 是成本杠杆、LoRA 恢复 98%；搜索三方法——粗扫-细扫（起步）/AlphaEvolve 进化（极致）/语言引导贝叶斯（组合空间大）；调参分层推进（结构→lr→方法→数据），代理评估省成本；纪律 = 超参是经验问题，默认值是起点不是终点，抄配置必须复验。
