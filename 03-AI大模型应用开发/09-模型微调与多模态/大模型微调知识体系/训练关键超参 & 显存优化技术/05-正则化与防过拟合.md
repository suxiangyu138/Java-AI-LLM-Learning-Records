# 正则化与防过拟合

> 防过拟合的手段谱系：weight decay、dropout（含 LoRA dropout 的 2026 疑点）、label smoothing、早停与数据侧手段——先改数据与训练量，再谈正则

## 1. 过拟合的根因与手段谱系

过拟合 = 模型容量 > 数据信息量（`../微调常见问题/05-训练问题过拟合遗忘与震荡.md` 01 节）。防过拟合手段按"动哪一层"分三类：

**数据侧**（最优先）：增数据量/多样性、去重（重复样本是复读根源，`../数据集体系（非常重要）/05-数据去重与污染检测.md`）、补边界样本——数据问题不解决，正则只是掩盖。

**训练侧**（次优先）：降 epoch（第一旋钮，04 篇）、降学习率（更小步长不易钻进训练集尖峰）、早停（04 篇）。

**正则侧**（最后）：weight decay、dropout、label smoothing——**顺序逻辑：数据与训练量是"治本"，正则是"治标"**；过拟合先查数据/降 epoch，正则作为补充手段。

## 2. weight decay：唯一"默认开"的正则

weight decay（权重衰减，AdamW 中解耦实现，`../基础概念/05-优化器与梯度更新.md` 02 节）把权重向零收缩——**抑制大权重、平滑决策边界**。LLM 微调的标准值 **wd=0.1**（AdamW 惯例，全量与 LoRA 通用）。

工程注意：wd 与 lr 耦合（大 lr 下 wd 的相对影响更大，02 篇第 5 节）；**wd 不是越大越好**——过大权重被压得太小，容量受损（表现类似欠拟合）；0.1 是"默认开、极少动"的正则——调参预算几乎不用花在 wd 上。

## 3. dropout：LLM 微调里的"可疑正则"

dropout（随机丢弃神经元）是深度学习的经典正则，但在 LLM 微调里地位特殊：

**LoRA dropout**（适配器层随机丢弃）：2026 研究提示**在短训练里作为正则不可靠**——微调训练短（1-3 epoch），dropout 的随机性主要变成"学习噪声"而非"正则化"；默认 0.05-0.1，过拟合时优先降 epoch 而非加 dropout（`../基础概念/06-训练循环Epoch-Batch-Step.md` 03 节）。

**底座 dropout**：预训练底座已带（如 0.1），微调时**一般不动**——动底座 dropout 等于改底座行为，风险大于收益。

**结论**：dropout 是"看着像正则、实际收益存疑"的手段——2026 共识：**微调的正则优先级 = wd（默认开）> 降 epoch > dropout（谨慎）**。

## 4. label smoothing：软标签的取舍

label smoothing（标签平滑）把 one-hot 标签软化（如 0.9/0.1 分配），防止模型对训练标签过度自信——**对过拟合的直接症状（过度自信/复读）有缓解**。

**LLM 微调的现状**：label smoothing 在 LLM 微调中**使用率低**——原因：LLM 目标是 next-token 预测，平滑后模型"自信度"下降可能影响生成质量（低自信 → 输出更模糊）；主流配方（TRL/Unsloth/LLaMA-Factory 默认）都不开。**适用场景**：标签噪声明显的数据集（标注质量参差）——平滑相当于"承认标签不完全可信"；干净数据不需要。

## 5. 验证 loss 的忠实性：2026 开放问题

Baseten 2026 研究提出的问题：**验证 loss 是否忠实排序下游质量？**——loss 平坦度与任务指标的关系未完全清楚（`../基础概念/09-评估基础损失曲线与过拟合.md` 05 节）。
工程含义：**防过拟合的判据不能只靠 loss**——"验证 loss 还降"不保证任务指标还涨（摩擦签名实证：loss 穿过坍缩不告警，`../微调常见问题/05-训练问题过拟合遗忘与震荡.md` 01 节）；**正则与早停的决策要以"任务指标 + 通用回测"为准，loss 是辅助信号**。

## 6. 防过拟合决策清单

一次过拟合排查的标准动作序列：**确认过拟合**（三信号：train→0/eval 背离/复读，`../基础概念/09-评估基础损失曲线与过拟合.md` 02 节）→ **先查数据**（重复率统计、数据量 vs 模型容量——小数据 + 大模型是过拟合温床）→ **降 epoch**（第一旋钮）→ **降 lr**（第二旋钮）。

**再加正则**（wd 已开 → 谨慎加 LoRA dropout → label smoothing 留给标签噪声场景）→ **早停兜底**（load_best_model_at_end 自动选最优）——每步一个小验证（分项评估看是否缓解），一次只动一个变量（`../完整微调工程流程/07-训练过程监控与干预.md` 02 节）。

**正则化的代价意识**：正则手段都有代价——wd 过大压容量（表现似欠拟合）、dropout 引入学习噪声（短训练里像干扰）、label smoothing 降低输出自信度——**正则不是免费的"防过拟合保险"**，加了要复验效果（分项评估对比加与不加）；"过拟合就全套正则上"是最贵的错误（无法归因哪个有效，还可能引入新问题）——一次一个，每个都验证。

**防过拟合的"数据优先"原则**：多数过拟合的根因是数据（重复/不足/分布窄）而非缺正则——数据侧修好（去重、扩充、补边界）后过拟合往往自行缓解；**正则只在数据与训练量都优化后仍过拟合时才上**——"先数据、再训练量、最后正则"是防过拟合的完整顺序（`../数据集体系（非常重要）/05-数据去重与污染检测.md` 01 节）。

**LoRA 的天然正则**：LoRA 低秩约束本身就是一种正则（参数量少、可表达空间受限——`../基础概念/07-微调方法全景图谱.md` 的容量论述）——**LoRA 微调的过拟合阈值天然低于全量微调**（同样的数据，LoRA 更晚过拟合）；这个事实的双面性：LoRA 过拟合时"降 r"是一个被低估的旋钮（降低容量 = 降低记忆能力，`../PEFT 参数高效微调（面试高频）/` 体系的 r 选择论述）——**r 既是容量旋钮也是正则旋钮**，过拟合时先降 r 再考虑加 dropout（顺序与"降 epoch 优先"一致：先减容量后加正则）。

**正则在多阶段流水线中的位置**：SFT → DPO 流水线（`../基础概念/07-微调方法全景图谱.md` 07 节）里，**正则主要在 SFT 阶段起作用**（DPO 的偏好损失自带对比约束，过拟合形态不同）；DPO 阶段"过拟合"的表现是**偏好分布过度集中**（所有回答都倾向同一种风格）——缓解手段是数据多样性（`../数据集体系（非常重要）/02-数据集类型全景.md` 03 节）而非 dropout——**不同阶段的"过拟合"要按阶段对症**。

> 🎯 **核心要点**：防过拟合手段分三层——数据侧（增/去重/补边界）> 训练侧（降 epoch/降 lr/早停）> 正则侧（wd/dropout/label smoothing）；wd=0.1 默认开极少动；LoRA dropout 短训练正则不可靠（2026）；label smoothing 低使用率（留给标签噪声场景）；验证 loss 的忠实性是开放问题——防过拟合判据以任务指标 + 通用回测为准；决策序列 = 确认信号 → 查数据 → 降 epoch → 降 lr → 正则补充 → 早停兜底。
