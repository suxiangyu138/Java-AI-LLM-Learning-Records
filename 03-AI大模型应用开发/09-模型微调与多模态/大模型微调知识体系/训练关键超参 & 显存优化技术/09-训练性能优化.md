# 训练性能优化

> 吞吐优化的杠杆排序、训练时间估算与成本、profiling 方法——先查零成本配置（packing），再谈换框架；"慢"要对照理论值判断

## 1. 吞吐优化的杠杆排序

训练变慢时按"投入产出比"从高到低排查（`../微调常见问题/06-显存与性能问题.md` 03 节）：

**零成本配置（第一优先级）**：**packing 开没开**（短样本 padding 浪费消除，吞吐可能翻倍——`../基础概念/06-训练循环Epoch-Batch-Step.md` 06 节）；dataloader 的 num_workers/persistent_workers（数据加载跟上 GPU）；bf16 混合精度（`../完整微调工程流程/06-训练配置与启动.md` 02 节）。

**低代价配置（第二优先级）**：FlashAttention（长序列收益大，`../完整微调工程流程/06-训练配置与启动.md` 06 篇 03 节）；梯度检查点的密度（每层都查点比选择性重算慢得多——默认即可，不用调最密）；序列长度匹配（max_seq_length 远超数据实际长度 = 白烧算力——先看数据长度分布再定）。

**中代价优化（第三优先级）**：fused kernel（融合算子减少内存往返，NVIDIA Transformer Engine 类）；torch.compile（2027 展望成默认——2026 年实验性开启，收益模型相关）；多卡（08 篇决策树——先确认单卡已榨干）。

**高代价（最后）**：换框架（Unsloth 类加速内核——收益大但引入新依赖与坑，`../完整微调工程流程/04-环境搭建与工具链选型.md` 02 节）。

## 2. 训练时间估算

训练前先估时间（决定排期与预算）：

**公式**：总 token 数 ÷ 吞吐 = 小时数。总 token = 样本数 × epoch × 平均序列长度；吞吐按框架实测基准（QLoRA 7B 单卡约 1500-4200 tokens/s，`../完整微调工程流程/04-环境搭建与工具链选型.md` 01 节）。

**实例**：1 万条 × 2 epoch × 500 token = 1000 万 token ÷ 2000 tokens/s ≈ 1.4 小时（7B 单卡）——**微调单轮通常是小时级**（全量微调 70B 才到天级：约 5 天，多卡集群）。

**估算的误差来源**：实际吞吐受数据加载/长度分布影响（估 70-80% 折扣）；eval/save 步骤占时间（eval_steps 频率高会显著加时长）；多卡通信（08 篇通信成本）。**估算公式 + 30% 余量 = 排期数字**（重训余量再 ×2-3，`../完整微调工程流程/02-需求分析与方案设计.md` 03 节）。

## 3. Profiling：找到真正的瓶颈

优化前先 profile——**别猜瓶颈，测瓶颈**：

**GPU 利用率**：`nvidia-smi` / wandb 系统指标——利用率 <60% 持续 = 数据管线或通信瓶颈（CPU 侧 profile：dataloader 是否占满）；利用率 90%+ 但吞吐低 = 计算侧问题（内核效率）。

**逐段计时**：训练循环分三段计时——数据加载（dataloader 时间）、前向+反向（计算时间）、优化器 step（更新时间）——**哪段占比异常高，瓶颈就在哪**（常见反直觉：数据加载 30%+ 是"训练慢"的头号隐藏原因）。

**框架级工具**：`torch.profiler`（算子级分析——看哪个 kernel 耗时）；Nsight Systems（CUDA 级）；`torch.cuda.memory_summary()`（显存分布）；**2026 提醒**：profile 整个流水线——dataloader 和存储瓶颈可能主导 GPU 时间，"一台好用的 GPU 胜过四台用不好的 GPU"（`../完整微调工程流程/04-环境搭建与工具链选型.md` 03 节）。

## 4. 成本优化：算力账本

训练成本 = GPU 时长 × 单价，三条省钱路径：

**省时长**：packing/FlashAttention/精度配置（第 1 节零成本项先做）；小模型验证（14B 验证效果、70B 投产——"小模型验证、大模型投产"是 2026 标准策略，`../完整微调工程流程/02-需求分析与方案设计.md` 03 节）；代理评估（搜索用小数据/小步数，01 篇第 4 节）。

**省单价**：按需云 GPU vs 自购卡（波动需求用按需，`../完整微调工程流程/04-环境搭建与工具链选型.md` 03 节）；错峰（云厂商低谷时段折扣）；**别让 GPU 空转**（dataloader 瓶颈 = GPU 在等数据 = 在烧钱）。

**省重训**：评估先行（门禁预设防无效重训，`../完整微调工程流程/03-评估先行基线建立.md` 04 节）；监控止损（训练坏了该停就停，`../完整微调工程流程/07-训练过程监控与干预.md` 02 节）——**最贵的训练是"训错了还训完"**。

## 5. 性能优化的验证纪律

性能优化的验收与效果优化一样要测量：**改前改后同一基准**（同数据同 batch 的 tokens/s 对比——吞吐的测量口径要统一：每秒 token 数而非每秒步数，步长不同的配置不可比）；**单变量验证**（packing 与 FlashAttention 一起开，不知道谁起效）；**记录**（每项优化的前后吞吐进实验表——性能优化的历史是团队知识资产，`../完整微调工程流程/06-训练配置与启动.md` 05 节）。

**2026 提醒**：性能优化的收益有边际递减——把 packing 等零成本项做满后，继续优化的投入产出比急剧下降；**优化到什么程度"够用"**：训练时长符合排期即可停（别为 10% 提速投入三天）——性能优化是工程决策，不是竞赛。

**性能优化的典型收益参考**（2026 实测量级）：packing 开/关——短样本任务吞吐 1.5-2×（最高性价比）；FlashAttention——长序列（>4K）1.5-2.5×（短序列无感）；bf16 vs fp16——1.1-1.2×（附赠数值稳定）；梯度检查点——**负收益**（费 20% 速度，只在显存必须时用）；Unsloth 类内核——2-3×（换框架的成本与坑，`../完整微调工程流程/04-环境搭建与工具链选型.md` 02 节）——**先做前三个，检查点是"不得已"不是"优化"**。

**性能与质量的边界**：优化手段分两类——**无损优化**（packing/FlashAttention/worker——不影响训练语义）与**有损优化**（梯度检查点费时间、降精度费质量）——**优化顺序永远"先无损后损"**；任何"有损"优化（降精度/降长度）后都要过验证集（与效果优化同待遇）——"省了 30% 时间掉了 5 分"是性能优化的最差交易。

**性能优化的"速查路径"**（遇到"训练慢"直接按此走）：1）确认慢（对照理论吞吐，`../微调常见问题/06-显存与性能问题.md` 03 节）——不慢不动；2）零成本三件（packing/worker/bf16）；3）profile 定位（GPU 利用率 + 三段计时）；4）针对性优化（数据瓶颈查加载、计算瓶颈查内核/长度）；5）记录前后吞吐——**五步走完还没解决，才轮到换框架/上多卡**（高代价手段最后动用）。

> 🎯 **核心要点**：吞吐杠杆排序——零成本（packing/worker/bf16）→ 低代价（FlashAttention/长度匹配）→ 中代价（fused kernel/compile）→ 高代价（换框架）；时间估算 = 总 token ÷ 吞吐 + 30% 余量（微调小时级、全量 70B 天级）；profiling 先测再猜（GPU 利用率 <60% 查数据管线、三段计时找瓶颈、dataloader 30%+ 是隐藏头号原因）；成本三路径——省时长（小模型验证/代理评估）/省单价（按需云/错峰）/省重训（门禁 + 止损）；优化要测量（同基准单变量）、够用即停——性能优化是工程决策不是竞赛。
