# Epoch 与早停

> 训练量的两个旋钮：epoch 决定"数据见几遍"（1-3 惯例），早停决定"何时停止"（验证 loss 为准）——2026 研究量化了"训多少 epoch 开始侵蚀通用能力"

## 1. 1-3 epoch 惯例的实证基础

SFT 的 epoch 数有非常稳定的共识：**1-3 个**（概念与机制在 `../基础概念/06-训练循环Epoch-Batch-Step.md` 03 节）。选择逻辑：

- **数据量大（10k+）且质量高** → 1 epoch 足够（每条见一次就能学到模式）。
- **数据量中等（1k-10k）** → 2-3 epoch。
- **数据量小（<1k）** → 也**不超过 3**——小数据 + 多 epoch = 背题（模型容量远超数据信息量，`../微调常见问题/05-训练问题过拟合遗忘与震荡.md` 01 节）。

**为什么超过 3 就危险**：训练从"学规律"滑向"背样本"——训练 loss 可继续降（记忆在加深）但验证 loss 背离（泛化在退化）；**Baseten 2026 专门量化了"训多少 epoch 开始侵蚀通用指令遵循"**——过训练（overtraining）是真实风险，且侵蚀点随数据与模型不同，**无法用一个固定数字回答，必须盯验证集**。

## 2. 早停（early stopping）：标准实现

早停是"训练多少"的最终答案——**不是固定 epoch，而是验证 loss 说了算**。标准实现（2026 训练器配置）：

**触发条件**：验证 loss 连续 2-3 个评估点不降反升（`../完整微调工程流程/07-训练过程监控与干预.md` 02 节）；或 train-eval gap 超过历史差距的 1.5 倍（过拟合确认信号）。

**checkpoint 选择**：`load_best_model_at_end=True` + `metric_for_best_model="eval_loss"` + `greater_is_better=False`——自动保存验证 loss 最优的 checkpoint（不是最后一个）——**"最优 checkpoint"与"最后 checkpoint"的数值差异是离线评估与线上不一致的常见来源**（`../完整微调工程流程/08-模型评估与验收.md` 03 节）。

**早停的工程细节**：eval_steps 100-500（评估太疏会错过最优窗口）；**eval_steps 与 save_steps 对齐**（保证最优评估点的 checkpoint 一定被保存过）；早停后重训大训练量时从最优 checkpoint 继续（而不是从头）。

## 3. 过训练侵蚀：2026 量化研究

Baseten 2026 的"训多少 epoch 侵蚀通用指令遵循"研究回答了"多训的代价具体是什么"：**通用指令遵循能力在某个 epoch 点后开始下滑**（任务指标可能还在涨——任务与通用能力的拐点不同步），侵蚀点与数据质量/数量相关。配合另一条证据（`../微调常见问题/05-训练问题过拟合遗忘与震荡.md` 01 节摩擦签名）：**in-task loss 会穿过坍缩不告警**——"训练 loss 还在降"不能作为"还能继续训"的证据。

**工程含义**：epoch 的上限由"通用能力回测"决定，不由"训练 loss 是否还降"决定——**回测要训练中跑**（10-20% 处首次，之后每 20-30% 复测，`../微调常见问题/05-训练问题过拟合遗忘与震荡.md` 02 节），发现通用分开始下滑就是"该停了"的信号，哪怕任务指标还在涨。

## 4. 课程式训练：epoch 内的进阶玩法

2026 年一个可选的 epoch 内策略是**课程式训练**（curriculum）：先学简单样本（格式示范），后学困难样本（长文本/模糊指令/多步推理）——多 epoch 时每轮按难度重新排序（`../数据集体系（非常重要）/08-数据平衡与多样性.md` 04 节的 10/70/20 难度分层在此落地）。
收益：训练更稳（前期不被困难样本轰击）、收敛更快；代价：实现复杂度（难度排序 + 调度器）。**默认固定配比（均匀混合）仍是稳妥选择**，课程式是数据分布特殊时的优化项。

## 5. epoch 与相邻超参的联动

**与 lr 联动**：epoch 增加 → 总步数增加 → warmup 步数按比例增加（3%）；lr 本身不必因 epoch 变化（调度器按步数缩放）。**与数据联动**：数据增补（迭代回流）后 epoch 可能需重新定（新数据分布下旧 epoch 数不一定最优——`../完整微调工程流程/09-导出部署与上线运维.md` 05 节的周更闭环每次都要重定 epoch，用早停代替拍脑袋）。

**与遗忘联动**：epoch 是灾难性遗忘的第一调节旋钮（`../微调常见问题/05-训练问题过拟合遗忘与震荡.md` 02 节）——遗忘信号出现（通用回测下滑）时**先降 epoch 再动其他**（数据混入是第二旋钮）。

## 6. 实操：一次完整训练量的决策

1. **起步**：epoch 2-3（中等数据默认）或 1（大数据），配早停配置（load_best + eval_steps 对齐）。
2. **训练中**：盯验证 loss 拐点 + 通用回测（10-20% 处首次）。
3. **训练后**：用最优 checkpoint 验收（不是最后 checkpoint）；若任务未达标且无过拟合信号 → 下轮升 epoch（或查数据）；若有遗忘/过拟合信号 → 下轮降 epoch（或混通用数据）。
4. **记录**：epoch、最优 checkpoint 的 step、验证 loss 曲线进实验表——训练量的决策链全程可追溯（`../完整微调工程流程/06-训练配置与启动.md` 05 节）。**5. 复查**：最优 checkpoint 的任务指标若仍不达标，先回查"数据量是否匹配任务复杂度"（数据不足时调 epoch 没用——先补数据再训，`../数据集体系（非常重要）/01-数据角色与质量第一性原理.md` 02 节）。

**epoch 的常见误区**：**"epoch 越多学得越牢"**（错——过 3 后是背题，`../基础概念/06-训练循环Epoch-Batch-Step.md` 03 节）；**"数据少就多训几轮"**（错——小数据多 epoch 是过拟合温床，正确做法是混通用数据或换小模型）；**"最后一个 checkpoint 就是最好的"**（错——最优 checkpoint 按验证 loss 选，两差可达数个 epoch 的训练量）；**"早停就是训练失败"**（错——早停是正常流程，找到最优停止点是训练成功的标志，不是失败）——四个误区对应四条正确认知：训练量看验证集、小数据靠数据策略、最优 checkpoint 自动选、早停是纪律。

**epoch 与数据规模的联动实例**：1 万条数据训 2 epoch 与 5 万条训 1 epoch 的"总见面次数"接近（2 万 vs 5 万次），但**大数据的 1 epoch 通常更优**——大数据本身的多样性就是"多次训练"的替代品（每条见一次即可学到模式，`../基础概念/06-训练循环Epoch-Batch-Step.md` 03 节）；反过来说，**数据量翻倍时先考虑降 epoch**（不是保持 3 硬训）——"数据多训得少"是 epoch 与数据的第一联动。

> 🎯 **核心要点**：1-3 epoch 惯例（大数据 1、中等 2-3、小数据不超 3）；超过 3 从"学规律"滑向"背样本"；Baseten 2026 量化过训练侵蚀——"训练 loss 还降"不是继续训的证据，通用回测才是；早停标准实现（连续 2-3 点不降 + load_best_model_at_end + eval/save 对齐）；课程式训练是可选优化项；epoch 与 lr 联动（warmup 比例）、与遗忘联动（第一旋钮）；完整决策链——起步 2-3、盯回测、用最优 checkpoint、记录全链。
