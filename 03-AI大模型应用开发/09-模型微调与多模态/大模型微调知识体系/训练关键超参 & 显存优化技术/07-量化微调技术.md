# 量化微调技术

> 训练期量化的全景：QLoRA NF4 标准配方（13B 单卡 18GB）、NVFP4/MXFP4 新兴格局（2026 MoE 大模型单卡）、QAT 与精度权衡——训练期量化与部署期量化是两回事

## 1. QLoRA：训练期量化的标准

QLoRA = **4-bit 量化底座 + LoRA 适配层**（原理在 `../PEFT 参数高效微调（面试高频）/` 体系，此处给配方与数字）：

**标准配方**（BitsAndBytesConfig）：`load_in_4bit=True`、`bnb_4bit_quant_type="nf4"`（NormalFloat4——4bit 的事实标准，对正态分布权重最优）、`bnb_4bit_compute_dtype="bf16"`（计算精度不被量化拖累）、`bnb_4bit_use_double_quant=True`（双量化再省 ~0.5bit/参数）。

**显存数字**：基础 ~4.5bit/参数（NF4 + 双量化），Llama-2-13B 单卡 RTX 4090 约 18GB、GPT-NeoX-20B 约 12GB（4bit）——**单卡 24GB 训 13B、40GB 训 33B 级**是 2026 单卡甜点。

**稳定性要点**：冻结底座参数；**非量化参数（LayerNorm、lm_head 输出）转 fp32**（防精度丢失）；FSDP 场景设 `bnb_4bit_quant_storage="bf16"`（4bit 层与常规层同形分片，否则分片失败）。

**效果**：QLoRA 效果接近 LoRA/全量（Baseten 2026：LoRA 恢复全量收益 98% 中位数，QLoRA 在其上再省显存）——**训练期量化是"几乎免费的显存杠杆"**（实测损伤常在噪声内，除非数据/任务特别敏感）。

**量化与训练稳定性的关系**：4bit 底座 + bf16 计算——**稳定性问题集中在"计算精度"而非"存储精度"**：compute_dtype 用 bf16 保证梯度质量（fp16 在 QLoRA 下更易溢出，`../微调常见问题/04-训练问题loss不降NaN与发散.md` 02 节）；非量化层（norm/lm_head）转 fp32 防精度丢失（07 篇配方要点）——**QLoRA 的 NaN/发散问题先查 compute_dtype 与 fp32 层配置**，而不是怀疑量化本身。

**NF4 vs FP8 的选型**：NF4（4bit，NormalFloat4）——QLoRA 标准，单卡甜点，生态最成熟；FP8——精度更高（8bit），但显存省得少（约 50% 而非 75%），用于"显存够但想要更高精度"的场景（FP8 训练 2026 在 Unsloth 等框架可用）；**选择逻辑：显存是瓶颈 → NF4；精度敏感 + 显存够 → FP8**——两个方案的训练脚本差异很小（一个配置项），可以各跑一次对比（量化方案的效果验证见第 5 节）。

## 2. NVFP4/MXFP4：2026 新兴格局

2026 年训练期量化的重要新玩家是 **NVFP4**（NVIDIA FP4）与 **MXFP4**：

**NVFP4 是什么**：NVIDIA 的 FP4 格式（2-bit 尾数 + 指数），配合特定硬件（Blackwell 类）实现训练/服务一体化；Axolotl 已列 QAT 支持（int8/int4/FP8/NVFP4/MXFP4）与 **NVFP4/MXFP4 MoE LoRA**；FastGRPO 是 NVFP4 专用训练/推理运行时（megakernels + 自定义 MoE 内核 + 激活检查点流式 offload——解码时异步把中间激活挪到 CPU RAM，反向往回拉，计算与通信重叠）。

**价值**：**MoE 大模型（30B-120B 级）单卡（DGX Spark 128GB 统一内存）训练/服务成为可能**——NVIDIA 实测 Nemotron-3-Super-120B NVFP4 训练峰值 93.2GB（否则装不下）——代价是训练速度下降。

**2026 现状**：NVFP4 是前沿工具链（Axolotl/FastGRPO 支持），**QLoRA NF4 仍是通用默认**；NVFP4 的适用边界是"MoE 大模型 + 单卡/少卡"场景。

## 3. 量化与精度的权衡

**训练期量化 vs 部署期量化是两回事**（`../完整微调工程流程/06-训练配置与启动.md` 02 节）：训练期量化是省显存手段（影响训练稳定性），部署期量化是省服务成本手段（影响推理质量）——**训练时用的量化方案不需要与部署一致**；但训练与部署精度错配（BF16 训 INT4 服务）会抹掉微调技能（`../微调常见问题/07-效果不达预期问题.md` 02 节）。

**量化损伤分层**（部署侧，`../微调常见问题/08-量化与部署问题.md` 06 节）：8bit 多数任务可接受（<2% 掉点）；4bit 出现特定能力损坏风险（长序列/约束保持）；2-3bit 必须 QAT——**位深越低，量化越要训练期介入**。

## 4. QAT：量化感知训练

**QAT（Quantization-Aware Training）**：训练时用 fake quantization 模块模拟目标量化（前向按量化精度计算、梯度正常反传）——**模型学会在低精度下正确输出**，可恢复 45-70% 的量化损失（Gemma3-4B GPQA 恢复 66.9%、Gemma3-12B BBH 45.5%、NVFP4 QAT 71.6%）。

**适用边界**：部署位深 ≤4bit 时强烈建议；**2-3bit 边缘部署必须 QAT**；QAT 要求**训练前就确定部署位深**（训练与部署决策耦合，`../完整微调工程流程/02-需求分析与方案设计.md` 03 节）——**"先训后量"的流程在低 bit 场景要改成"训即量"**。

## 5. 量化的效果验证

量化微调的效果验证三个层次：**训练稳定性**（loss 曲线与 BF16 基线对比——量化引起的训练不稳定先于效果出现）；**任务效果**（领域评估集对比 BF16 基线——损伤在噪声内可接受）；**部署一致性**（评估走服务路径的"目标量化 + 适配器"组合—
—`../微调常见问题/08-量化与部署问题.md` 02 节的联合验证）。**三层都过才可上线**——量化方案的选择不是"能不能训"，是"训完 + 部署后的效果能不能过门禁"（`../完整微调工程流程/08-模型评估与验收.md` 03 节）。

## 6. 量化选型决策树

```text
单卡 7B-14B        → QLoRA NF4（标准，24GB 内）
单卡 20B-33B       → QLoRA NF4 + 检查点 + 8bit 优化器（40GB 级）
MoE 30B-120B 少卡  → NVFP4/MXFP4（2026 前沿，DGX Spark 级）
部署 ≤4bit         → 训练期就 QAT（训练与部署耦合）
精度敏感任务       → 训练 BF16，部署同精度或 8bit（别跨档）
```

**量化方案变更的回归测试**：量化配置（NF4→FP8、加双量化、换 compute_dtype）是"有损变更"——每次变更后跑小验证集回归（loss 曲线 + 任务指标与变更前对比，差异在噪声内才可接受）；**"量化省显存但不验证"是最常见的量化事故**——省下来的显存买的是"未经验证的新风险"（`../微调常见问题/08-量化与部署问题.md` 01 节的三层验证：稳定/任务/部署组合）。

**量化微调与数据规模的关系**：小数据（<1k 条）微调 + 4bit 量化——量化噪声占比相对更大（模型学的内容少，量化的"干扰"更显著）——**小数据场景优先考虑 FP8 或 BF16**（显存允许时）；大数据（10k+）场景 NF4 的噪声被大量数据稀释，效果差异常在噪声内——**量化位深的选择与数据规模耦合**：数据越少，精度越要保守。**量化与任务类型的耦合**：结构化输出（JSON 格式）与工具调用任务对量化更敏感（格式的精确性被量化噪声干扰）——这类任务量化后务必跑格式解析率专项评估（`../微调常见问题/08-量化与部署问题.md` 01 节）。

> 🎯 **核心要点**：QLoRA NF4 标准配方（nf4 + bf16 compute + 双量化，~4.5bit/参数，13B 单卡 18GB）；稳定性三要点（冻结底座/非量化层转 fp32/FSDP 用 bnb_4bit_quant_storage=bf16）；NVFP4/MXFP4 是 2026 新兴（MoE 大模型单卡，FastGRPO 流式检查点）；训练期量化与部署期量化是两回事，但精度错配会抹掉微调技能；QAT 恢复 45-70%、低 bit 必用、训练前定部署位深；效果三层验证（稳定/任务/部署组合）；选型决策树按模型规模与部署位深走。
