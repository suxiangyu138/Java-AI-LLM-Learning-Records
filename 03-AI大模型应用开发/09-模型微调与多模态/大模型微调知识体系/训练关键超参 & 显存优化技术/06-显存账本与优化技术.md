# 显存账本与优化技术

> 显存是一切训练决策的物理约束：四部分账本（权重/梯度/优化器状态/激活值）+ 优化技术谱系（梯度检查点/FlashAttention/8bit 优化器/packing）——先算账再调参

## 1. 显存四部分账本

训练时 GPU 显存被四类对象占用，**每一项都有独立的省钱方案**：

| 部分 | 是什么 | 规模 | 省钱方案 |
|------|--------|------|---------|
| 权重 | 模型参数（FP16 每参数 2B） | 7B ≈ 14GB | 量化（QLoRA 4bit ≈ 4GB） |
| 梯度 | 反向传播的梯度 | ≈ 权重大小 | LoRA 只算适配层梯度 |
| 优化器状态 | AdamW 每参数 3 份（一阶/二阶/权重衰减） | ≈ 3 × 权重 | 8bit 优化器（砍半以上） |
| 激活值 | 前向传播的中间结果 | 随序列长度线性增长 | 梯度检查点（省 30%+） |

**全量微调总额 ≈ 5 倍权重**（权重 + 梯度 + 3 份状态），**LoRA ≈ 1.1 倍**（权重 + 适配层少量状态），**QLoRA ≈ 0.5 倍**（4bit 权重 + 适配器）——账本是"单卡能训多大"的答案（`../基础概念/03-Transformer与参数基础.md` 05 节的四档成本在此展开）。

## 2. 梯度检查点：重算换显存

梯度检查点（gradient checkpointing）**不存全部激活值**——前向时只存少量检查点，反向需要时**重算**中间激活——省 ~30% 显存（可到 50%+）、费 ~20% 速度。

工程要点：**PEFT 的 `prepare_model_for_kbit_training()` 默认开启**（量化模型标配）；`use_reentrant=False`（新版推荐）；**长序列场景收益最大**（激活值随长度线性增长）；"省显存让 batch/长度翻倍 → 总墙钟时间反而下降"是它"费速度却省时间"的悖论（`../完整微调工程流程/06-训练配置与启动.md` 02 节）。

## 3. FlashAttention：长序列的显存与速度双赢

FlashAttention 用两个核心思想攻显存墙：**tiling（分块）**——Q/K/V 分块在 SRAM 计算，不物化完整的 N×N 注意力矩阵（32K 上下文时完整矩阵可达 4GB）。

**recomputation（重算）**——反向时重算中间注意力矩阵换显存。效果：BERT-base 训练提速 2-4 倍，序列越长收益越大；FlashAttention-2 加了并行度优化，2026 年主流框架（Axolotl 等）支持 FA 2/3/4、Xformers、Flex Attention、SageAttention 全家桶。

**适用**：长上下文训练（>4K）显存与速度收益显著；短序列场景收益有限——**配置前先看 max_seq_length 与数据长度分布**。

## 4. 8bit 优化器：优化器状态砍半

优化器状态占全量微调显存的 ~60%（3 份 × 权重）——**8bit 优化器**（bitsandbytes 的 8bit Adam）把状态压缩到 8 位，状态显存砍半以上，总显存省 ~25-30%（QLoRA 方案标配，`../基础概念/05-优化器与梯度更新.md` 04 节）。2026 新进展：FlashAdamW 等内存高效优化器（arXiv 2602.23349）继续压状态显存——**优化器状态是"可压缩"的显存大户**。

## 5. 省显存套餐与组合

按"收益 × 代价"排序的标准套餐（可叠加）：

**QLoRA（-75%）**：4bit 量化底座（NF4 + 双量化）——最大杠杆，7B-14B 单卡甜点（07 篇详述）。**梯度检查点（-30%）**：重算换显存，费 20% 速度。**8bit 优化器（-25~30% 状态）**：QLoRA 标配。**packing（效率而非显存）**：消除 padding 浪费——短样本场景吞吐可翻倍，常比"花哨技巧"更有效（`../基础概念/06-训练循环Epoch-Batch-Step.md` 06 节）。**降 batch/降长度**：按比例省（按账本算）。

**组合实例**：QLoRA + 检查点 + 8bit 优化器 + packing = 单卡 24GB 训 13B 的标准配置（激活值控制好，13B 约 18GB）；显存极限场景再加降长度/降 batch。

**激活值显存的细节**（常被低估的部分）：激活值显存 = 每 token 激活 × 序列长度 × batch × 层数——**长序列 + 大 batch 是激活值大户**（这也是"max_seq_length 超配"是最隐蔽显存浪费的原因：max 8K 但 90% 样本 1K，激活值预算按 8K 配）；FlashAttention 减少的是注意力矩阵（O(n²) 部分），**FFN 激活（O(n) 部分）仍占大头**——长上下文场景"梯度检查点 + FlashAttention"是组合标配（检查点省 FFN 激活、FlashAttention 省注意力矩阵，互补）。

**长序列场景的显存组合**（>8K 上下文微调）：QLoRA + 梯度检查点 + FlashAttention + packing（长文档分段）+ 必要时降 batch——**五个杠杆按序叠加**，8K+ 上下文单卡 24GB 训 7B 是 2026 常规配置；再长（32K+）考虑 FlashAttention 级联 + 序列并行（08 篇）或 offload。

**显存的"预算表"写法**（决策工具）：训练前写一张预算表——权重（模型规模 × 位宽字节）、梯度（LoRA 则≈0）、优化器状态（参数 × 3 × 优化器位宽）、激活值（每 token 激活 × 长度 × batch × 层数，实际跑 1 步看 memory_summary 校准）、预留（10-15% 余量）——**五列相加 < 卡显存 = 方案可行**；预算表挂在训练记录里，OOM 时第一件事就是对照预算表找"超支项"（`../微调常见问题/06-显存与性能问题.md` 05 节）——"算账"从口头纪律变成书面工具。

**记忆化与显存的另一层关联**：显存紧张 → 降 batch/降长度 → 数据"见法"变化（`../基础概念/06-训练循环Epoch-Batch-Step.md` 01 节公式）——**省显存的操作会影响训练动力学**（有效 batch 变小 → 梯度噪声变大 → 收敛形态变化），所以"省显存后要复验曲线"（loss 形态与改前对比，异常则回退某项）——省显存不是"无副作用的配置变更"，是训练配方的一部分。

## 6. 分布式分片：账本的"除法"

多卡场景的显存优化是**分片**（shard）——DeepSpeed ZeRO / FSDP 把权重/梯度/状态分片到各卡（08 篇详述）：FSDP FULL_SHARD 下每卡显存 ≈ 单卡方案 ÷ 卡数（+ 通信开销）。

**70B 全量微调从单卡装不下变成 8×A100 可训**。分片是"账本除法"，量化/检查点是"账本乘法省"——两者可组合（QLoRA + FSDP 是 70B 级微调的标准组合，`../完整微调工程流程/06-训练配置与启动.md` 04 节）。

## 7. 显存优化的决策流程

一次"显存不够"的标准决策：**先算账**（四部分各占多少——`torch.cuda.memory_summary()` 看实际分布）→ **按最大项省**（账本里最大的部分用对应的方案：权重大 → 量化；
激活值大 → 检查点/降长度；状态大 → 8bit 优化器）→ **组合叠加**（套餐）→ **最后才分片/换小模型**（引入分布式复杂度或牺牲模型规模）——"先算账再调参"是显存问题的第一纪律（`../微调常见问题/06-显存与性能问题.md` 05 节）。

> 🎯 **核心要点**：显存四部分账本（权重/梯度/优化器状态/激活值）各有省钱方案——量化省权重、LoRA 省梯度、8bit 优化器省状态、检查点省激活；全量 ≈ 5 倍权重、LoRA ≈ 1.1 倍、QLoRA ≈ 0.5 倍；梯度检查点省 30% 费 20%（PEFT 默认开）；FlashAttention 长序列双赢（分块 + 重算）；packing 常被低估（短样本翻倍）；分片是"账本除法"可与量化组合（QLoRA+FSDP 训 70B）；决策 = 算账 → 按最大项省 → 组合 → 最后分片/换模型。
