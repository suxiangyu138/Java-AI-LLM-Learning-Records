# 批量大小与梯度累积

> 2026 年的颠覆认知：batch size 是"成本杠杆"不是"质量杠杆"——每卡 1-2 + 梯度累积是安全默认；有效 batch 的算法与 lr 的耦合关系一次讲清

## 1. 2026 实证：batch 是成本杠杆

Baseten 2026 后训练科学对 batch size 的结论是**反直觉的**：batch size 对最终质量的影响远小于学习率——它更像"算力成本与训练稳定性的权衡"（大 batch 梯度更稳但显存/算力开销大；小 batch + 累积便宜且质量差异在噪声内）。

工程含义：**调参精力不该花在 batch 上**——每卡 1-2 + 梯度累积是安全默认（质量不输大 batch，成本更低）；batch 的调整理由是"显存装得下吗"和"训练稳吗"，不是"质量能提升吗"。

## 2. 梯度累积：显存受限的标准解法

显存装不下大 batch 时，**梯度累积**（gradient accumulation）是标准解法：每吃一个 micro-batch 算一次梯度但不更新，累积 N 步后统一更新一次——等效于 batch size ×N（原理与 `../基础概念/06-训练循环Epoch-Batch-Step.md` 02 节一致）。

实现三要点：**loss 除以累积步数再反传**（否则等效 lr 被放大——最常踩的坑）；**累积步数与 eval/save 的对齐**（eval/save 按"更新步"计，不是按 micro-batch 计，日志里容易混淆）；**梯度裁剪在累积后统一做**（`../基础概念/05-优化器与梯度更新.md` 04 节）。

常见组合（2026）：`per_device_train_batch_size=2` + `gradient_accumulation_steps=4`（有效 batch 8）；显存极限场景 batch 1 + 累积 8。

## 3. 有效 batch：多卡与累积的统一口径

**有效 batch = 每卡 batch × 卡数 × 梯度累积步数**——这是所有实验对比的统一口径：两轮实验"每卡 4 × 1 卡 × 1"与"每卡 2 × 2 卡 × 1"的有效 batch 相同（8），可比；**跨实验记录有效 batch**（而不是只看 per_device 值），否则"为什么这轮效果好"无法归因（`../完整微调工程流程/07-训练过程监控与干预.md` 04 节）。

有效 batch 与 lr 的耦合（`../基础概念/06-训练循环Epoch-Batch-Step.md` 02 节 + 02 篇第 5 节）：有效 batch 放大 → 每步梯度更稳 → 等效 lr 应同步放大（线性缩放规则）；实操中"改 batch 不动 lr"也常见（Baseten 提示质量差异在噪声内）——**记住耦合关系，但不必每次严格缩放**。

## 4. 2026 研究：batch 的动态调度

ICLR 2026 的 batch 调度研究（Fast Catch-up, Late Switching）给 batch 增加了动态维度：**简单任务 batch 可以全程递增；困难任务先用小 batch、训练后期再切大 batch**——利用"从小切大后 loss 快速追平"的 catch-up 效应，大 batch 可以安全地推迟到后期使用，省数据且不掉性能（1.1B 模型、1T token 规模的预训练验证）。

**微调场景的落地**：固定 batch + 监控仍是稳妥默认（微调规模通常不需要动态调度）；理解这项研究的意义在于——**batch 的动态调节空间比想象的灵活**，显存紧张时"前期小 batch 后期升 batch"是可行选项（如果训练器支持中途调 batch）。

**batch 与 DPO 的特化**：偏好优化（DPO）的训练对 batch 构成有额外要求——**每个 batch 内的 chosen/rejected 对要完整配对**（配对数据被拆到不同 batch = 对比信号丢失，训练器会处理但日志要确认）；DPO 的有效 batch 通常比 SFT 小（对比对本身信息密度高）——**SFT 的 batch 经验不能直接套 DPO**，`../基础概念/07-微调方法全景图谱.md` 07 节的阶段组合要分阶段配 batch。

## 5. batch 与梯度质量的边界

小 batch 的梯度噪声有正反两面：**好处**——噪声提供隐式正则（泛化更好，深度学习中的经典观察）；**坏处**——训练不稳（loss 震荡加剧，`../微调常见问题/05-训练问题过拟合遗忘与震荡.md` 03 节）、极端样本的梯度更容易造成尖峰。
**边界判据**：训练稳定（loss 趋势清晰、grad norm 有界）时，小 batch 安全；**震荡加剧/发散前兆时，先升有效 batch**（降 lr 之外的第二个调节旋钮）——batch 是稳定性的杠杆，不是质量的杠杆。

## 6. 实操检查清单

batch 相关的落地检查：**日志统一**（记录有效 batch，不记录 per_device 值）；**累积与 eval 对齐**（eval_steps 按更新步；`../完整微调工程流程/06-训练配置与启动.md` 05 节）；
**显存账本对照**（batch 每翻倍，激活值显存近线性增长——OOM 时先降 batch 再降长度，`../微调常见问题/06-显存与性能问题.md` 01 节）；**跨实验可比**（同数据集同有效 batch 的两次实验才能对比 lr 效果）。四件事都是"工程卫生"，不花算力、防归因错误。

**batch 与显存的账本关系**：激活值显存随"每卡 batch × 序列长度"近似线性增长——**"降 batch 还是降长度"的决策看数据长度分布**：多数样本短（长度浪费为主）先降 max_seq_length，多数样本长（batch 浪费为主）先降 batch。

**数据加载与 batch 的配合**：batch 由 dataloader 按 shuffle 顺序组批——shuffle 失效（数据顺序固定）会让 batch 构成重复（同一批样本反复组在一起，等效"局部过拟合"）；多 worker 加载固定 seed 保证 batch 组成可复现；**packing 与 batch 的关系**：packing 把样本拼成等长序列后，batch 的"样本数"变成"序列数"——显存按序列数算（`../基础概念/06-训练循环Epoch-Batch-Step.md` 06 节）。

**batch 的"步数成本"直觉**：总步数 = 样本 × epoch ÷ 有效 batch——有效 batch 翻倍则步数减半（训练墙钟时间近减半，`../基础概念/06-训练循环Epoch-Batch-Step.md` 01 节公式）——**batch 是"时间 × 显存"的权衡**：显存允许时加大 batch 省时间（质量不变，Baseten 结论），显存紧张时小 batch + 累积（时间不变，质量不变）——**batch 的调节不影响质量，只影响时间与显存，这正是"成本杠杆"的完整含义**。

**batch 稳定性调节的实操**：loss 震荡加剧时先升有效 batch（每卡 2 → 4 或累积 4 → 8）——观察 100-200 步振幅是否收敛；**batch 与 lr 同升的注意**：有效 batch 翻倍时若同步放大 lr（线性缩放规则），训练曲线可能跳动（两个变量同时变）——**一次只动一个**：先升 batch 观察稳定性，不稳再考虑 lr 缩放（`../完整微调工程流程/07-训练过程监控与干预.md` 02 节）。

> 🎯 **核心要点**：batch 是成本杠杆不是质量杠杆（Baseten 2026）——每卡 1-2 + 累积是安全默认；梯度累积三要点（loss 除累积/与 eval 对齐/裁剪后置）；有效 batch = 每卡 × 卡 × 累积，跨实验统一口径；ICLR 2026 动态 batch（困难任务后期切大）说明 batch 调节空间比想象的灵活；小 batch 的隐式正则 vs 稳定性权衡——震荡加剧先升有效 batch；实操四查（日志/对齐/账本/可比）防归因错误。
