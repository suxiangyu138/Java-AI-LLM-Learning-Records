# 数据集类型全景

> 微调方法的每种形态对应一类数据：SFT 指令对、DPO 偏好对、继续预训练纯文本、工具调用轨迹、评估集——先认清数据形态，再谈构建

## 1. 数据形态与方法的对应

数据不是"一个东西"，而是按训练方法区分的**五类形态**（方法全景见 `../基础概念/07-微调方法全景图谱.md`）：

| 数据类别 | 最小单元 | 用于方法 | 规模参考 |
|---------|---------|---------|---------|
| SFT 指令数据 | （指令，回答）对 | SFT | 千-万级 |
| 偏好数据 | （prompt, chosen, rejected）三元组 | DPO/RLHF | 万级 |
| 继续预训练数据 | 纯文本 | 继续预训练 | 50 万+ 条 |
| 工具调用数据 | 对话 + 工具调用轨迹 | SFT（工具增强） | 千-万级 |
| 评估集 | 任务样本 + 参考答案 | 一切训练前后 | 数百条 |

判断"该用哪类数据"由边界判断体系决定（`../边界判断（非常关键，面试必问）/`）：行为缺口 → SFT 指令对；偏好排序 → 偏好数据；知识注入 → 不做数据走 RAG。**数据形态不是自由选择，是方法选定的产物**。

数据形态与损失函数严格对应（损失机制见 `../基础概念/04-损失函数与训练目标.md` 05 节）：SFT 数据喂交叉熵（教模仿）、偏好数据喂对数几率比损失（教偏好）、RL 类数据喂期望奖励（教探索）——**换训练方法必须换数据形态**，拿 SFT 数据硬训 DPO 在技术上跑不通（没有 chosen/rejected 对），拿偏好数据训 SFT 则浪费了对比信息。

## 2. SFT 指令数据：微调的主粮

形态最小单元是（指令，回答）对，标准结构（概念层详解见 `../基础概念/08-指令数据与对话格式基础.md`）：

```json
{"messages": [
  {"role": "system", "content": "你是客服，回答简短专业"},
  {"role": "user", "content": "退货流程是什么？"},
  {"role": "assistant", "content": "订单页点退货，7 天内免运费……"}
]}
```

工程要点：每条样本最终都要是 messages 形态（多轮对话原生支持）；system 提示语要多样性（至少 10 个不同版本，防止模型对 system 过拟合）；回答长度分布要合理（平均 50-200 token，过长过短都是信号）。这类数据的构建全流程（获取/清洗/评估）是本体系 03-08 篇的主角。

## 3. 偏好数据：DPO/RLHF 的原料

形态是三元组 prompt/chosen/rejected：同一 prompt 下，"选中的回答"（chosen）与"被拒的回答"（rejected）成对出现，训练目标是提高 chosen 的相对概率。

**2026 年最重要的数据结论**（NeurIPS 2025《What Matters in Data for DPO?》）：**chosen 回答的质量是主导因素，rejected 的质量影响相对有限**——chosen 质量提升，无论 rejected 如何都稳定涨分。工程含义：构建偏好数据的精力应该砸在"保证 chosen 真正优秀"上，而不是"制造对比度"——刻意造烂 rejected 收益甚微。

获取路径（详见 03 篇）：真实人类反馈（线上赞踩/人工标注，最可靠）、合成偏好对（大模型生成 + judge 裁决，可规模化）、复用现有数据集（UltraFeedback 等，注意其 GPT-4 打分有"偏好长回答"的系统性偏差）。

偏好数据的质量标准比 SFT 数据多一条：**chosen 与 rejected 必须存在可感知的差异**——两个回答质量接近（如都 80 分）的"假对比对"会让模型学不到任何偏好信号，浪费数据容量；质量差异应该至少跨一档（好与较好以上）。合成偏好对常用置信度过滤（如 judge 打分差距 margin > 0.15 才保留）正是为了淘汰这种"假对比对"。

## 4. 继续预训练数据：纯文本形态

形态最简单也最特殊：**纯文本，无指令对**——训练目标就是 next-token 预测（`../基础概念/04-损失函数与训练目标.md`），模型学习的是领域知识分布（术语、文体、文档结构），不改变行为。

适用场景：领域术语体系独特（法律文书、医学文献、企业内部文档）、底座完全没见过这类文本。

质量要求与 SFT 数据不同：领域文本要**权威**（官方文档/行业标准优先于论坛帖）、**覆盖面全**（不同文体、年代、作者的样本都要有）、**与底座知识错位度高**（与通用语料重叠的内容学了也白学）。

错位度可以先量化：抽样做相似度统计，错位度低的领域（底座已很懂）继续预训练收益小，直接考虑 SFT 或 RAG 即可。**数据量门槛高**（2026 共识 50 万条起，见边界判断 05 篇），且与 RAG 的边界要分清（`../边界判断（非常关键，面试必问）/05-微调vs继续预训练.md`）——只做知识注入时 RAG 性价比高得多，继续预训练是"行为也要领域化"时才考虑的选项。

## 5. 工具调用数据：Agent 时代的增量

形态是在 SFT 对话基础上扩展工具轨迹：对话中插入 `<|tool_call|>`/`<|tool_result|>` 标记（或家族特有格式），模型学习"什么情况下调用什么工具、参数怎么填、结果怎么用"。

工程要点（与 `../基础概念/08-指令数据与对话格式基础.md` 07 节衔接）：**arguments 必须合法 JSON**（解析失败是 Agent 链路第一大错误源）；工具名/参数名全数据一致；工具结果完整不截断；调用失败的案例也要进数据（模型要学会错误处理与补救），只放成功案例的模型在真实 Agent 环境里不会处理失败。

## 6. 评估集：独立于训练数据的第五类

评估集是**唯一不进训练、只进评估**的数据：每类任务放数百条金标样本（人工编写/审核），用于训练前基线、训练中监控、训练后验收与回归。

与训练数据的三条硬隔离：**不重叠**（训练集里出现过评估样本 = 评估失真）；**不参与清洗过滤流程的"优化目标"**（不能让 judge 见过评估答案）；**跨时段采样**（生产会遇到未来输入，评估集要包含时间靠后的样本，原则见 `../基础概念/09-评估基础损失曲线与过拟合.md`）。评估集在数据体系中的角色是"度量衡"——其他四类数据都在为它服务。

> 🎯 **核心要点**：数据形态由训练方法决定——SFT 指令对（主粮）、DPO 偏好对（chosen 质量主导，NeurIPS 2025）、继续预训练纯文本（50 万+ 门槛）、工具轨迹（JSON 合法性铁律）、评估集（金标 + 三硬隔离）；判断用什么数据先看边界判断体系——数据形态不是自由选择。
