# 数据平衡与多样性

> 单条数据合格 ≠ 集合健康：类别配比、embedding 聚类选择、难度分层、防遗忘混入——多样性决定模型"覆盖多广"，平衡决定"不偏科"

## 1. 为什么多样性是硬指标

质量四维（01 篇）里的"多样性"在集合层面落地为两类问题：**类别分布**（任务类型配比）与**语义覆盖**（向量空间覆盖面）。多样性不足的后果：

- 类别失衡 → 模型对高频类别过拟合（"偏科"），低频类别几乎不会。
- 语义覆盖窄 → 模型只会"训练集附近"的输入，真实请求一旦偏离（换个说法、换个场景）就崩——**多样性缺口在测试集上暴露为"看着 loss 不错、上线效果差"**。

2026 年的共识表述：**多样性是泛化的必要条件**——模型的泛化能力上限由训练数据的语义覆盖决定，覆盖不到的输入，模型只能靠底座"硬猜"。

## 2. 类别配比：通用助手基准表

通用助手的标准配比（2026 参考，微软与社区工作流一致）：

| 类别 | 占比 | 说明 |
|------|:---:|------|
| 开放式问答 | 20% | 观点/解释/规划类 |
| 事实问答 | 20% | 知识/查询类（注意：业务知识归 RAG） |
| 推理/数学 | 15% | 逻辑与计算 |
| 代码 | 15% | 生成/解释/调试 |
| 摘要 | 10% | 压缩与要点提取 |
| 创意写作 | 10% | 风格化内容 |
| 约束指令遵循 | 10% | 格式/模板/规则类 |

两个使用要点：**领域模型按业务重配**（客服模型把开放式问答与约束指令占比调高，代码模型把代码提到 40%+）；**配比要对照真实请求分布**——有线上日志的按日志统计配比，没有的用上述基准起步。

三个领域配比实例：**客服助手**——开放式问答 30%（话术自由度高）、约束指令遵循 25%（格式/流程类）、事实问答 20%（业务知识，但注意知识归 RAG 边界）、其余 25%；**代码生成**——代码 45%（含单测与重构变体）、推理 15%、约束指令 15%、其余 25%；**金融文档**——摘要 30%（长文档压缩）、约束指令 25%（报告模板）、抽取 20%（字段级结构化）、其余 25%。

**配比不是拍脑袋**：每类都对应一个真实线上场景，配比即"模型能力预算"——预算给错类别，模型就在错误的方向上"偏科"。

## 3. 语义多样性：embedding 聚类选择

类别配比管不住"同一类别内的语义重复"——两个"代码"样本可能都覆盖列表推导，而数据库查询无人覆盖。**类别检查看不见的多样性缺口，embedding 能看见**：

做法（2026 标准）：把所有候选样本 embedding 化（预训练 encoder）→ 聚类（KMeans，簇数按目标规模定）→ 每簇按比例采样（或选簇心最近样本）——最大化向量空间覆盖面。

**facility location 最大化**是更优变体：一个带 (1-1/e) 近似保证的贪心子模优化——目标函数直接度量"选中集合的覆盖面积"，比 KMeans 均匀采样更能贴近"最大化覆盖"这个目标。工程上先 KMeans 起步，覆盖仍不满意再上 facility location。

**与去重的关系**：语义去重（05 篇）是"删重复"，聚类选择是"选代表"——同一套 embedding 基础设施，两个用途。区别在目标：去重保"没有冗余"，选择保"覆盖最大"。实践中常合并为一步："聚类 → 每簇去重 → 按熵选代表"。

## 4. 难度分层：课程式采样

数据难度分布影响训练节奏。2026 年参考分层：**易/中/难 10/70/20**——10% 简单样本（格式示范、教学）、70% 中等（主流任务）、20% 困难（长文本、模糊指令、多步推理）。分层做法：用困惑度/长度/任务复杂度做难度代理指标（`perplexity + 多样性指标（type-token ratio）+ 领域相关性（BM25）`三维评分是 2026 参考方案），按难度分桶。

为什么需要困难样本：**难度缺口 = 能力缺口**——训练集只放简单样本，模型在困难输入上只能退化到底座水平。为什么不能全是困难样本：训练前期被困难样本轰击，loss 震荡、收敛慢——课程式（curriculum）采样（简单先学、困难后学）是 2026 可选的进阶做法，固定配比是稳定默认。

## 5. 防遗忘混入：通用数据的"比例税"

灾难性遗忘（`../基础概念/09-评估基础损失曲线与过拟合.md` 03 节）要求训练集**主动混入通用能力数据**——这"税"不能省：约 10% 的普通对话/通用问答混入业务数据，保持模型的通用能力（闲聊、常识、礼貌）。

三个要点：**混入数据要多样化**（单一来源的通用数据救不了遗忘）；**业务数据占比越高，通用数据混入比越高**（全业务微调时 10% 可能不够，按通用能力回测结果调整，回测方法见 `../基础概念/09-评估基础损失曲线与过拟合.md`）；**混入来源**优先选高质量通用指令集（Alpaca/Dolly 类）而非随便抓的对话——通用数据也有质量要求。

**混入方式**：用采样器按固定比例混入（每 batch 按比例抽取业务/通用样本），而不是把通用数据简单拼接在文件头部——拼接式混入会让训练前期全是通用数据、后期全是业务数据，学习节奏错乱。

## 6. 平衡的验证方法

配比做完要验证，两个手段：

**分布可视化**：对训练集做 embedding 降维（UMAP/t-SNE）或按类别统计——看类别是否均衡、簇是否明显缺失（"空白区域" = 覆盖缺口）。**回测对比**：训练后跑类别分项评估（每类别单独算指标）——发现某类别显著差，回查该类别数据量与质量。**在线分布对比**：有真实请求日志的，把请求 embedding 与训练集 embedding 分布对比（最大均值差异 MMD 类指标）——分布错位（训练集 vs 真实请求）是"上线崩"的最早预警，合成数据路线尤其要查这一项（03 篇模式坍缩风险的量化手段）。

> 🎯 **核心要点**：多样性 = 类别配比（通用基准 20/20/15/15/10/10/10，领域按业务重配）+ 语义覆盖（embedding 聚类/facility location 选代表）；难度分层 10/70/20 课程式采样；10% 通用数据是防遗忘的"比例税"；验证三板斧——UMAP 可视化、类别分项回测、线上分布对比（MMD）——分布错位是上线崩的最早预警。
