# 03-超参数工程：秩、缩放与模块选择

> 定位：LoRA 的超参数数量少但联动性强，最难的是"改一个破坏另一个"的隐式依赖。本文给出 2026 年实证基线与调参顺序，重点是 rank/alpha 比例这个单一最关键的旋钮。

## 调参的第一原则：先钉比例，再动秩

有效更新幅度由 **α/r 比例**决定而非 α 单独取值。因此正确的实验顺序是：先固定比例（1.0 或 2.0），再按显存预算迭代 r（4 → 8 → 16 → 32）。最典型的事故是"r 从 8 提到 16 想涨效果，α 忘了从 16 提到 32"——有效缩放从 2.0 降到 1.0，效果反而倒退，还误判为"秩没用"。基线速查（2026 Unsloth 实测基准）：

| 秩 | 适用场景 | 8B 模型可训练比例 | 显存/时间代价 |
|---|---|---|---|
| 8 | 快速验证、窄任务 | ~0.1% | 基线 |
| 16 | SFT 通用甜点（默认） | ~0.21% | 基线 |
| 32 | 质量优先、24GB 卡安全区 | ~0.42% | 约为 r=16 的 2 倍 |
| 64-128 | 复杂推理、GRPO/DPO 强化训练 | ~0.84%+ | 显存时间线性上涨 |

unsloth 的 RL 推理默认 max_lora_rank=64；8GB 显卡建议 r=16/α=16。注意"更高秩 ≈ 更高上限但边际收益递减"，先 16 验证数据质量，再决定是否加秩。

## target_modules：全部线性层，不是只训注意力

早期教程流行只挂 q_proj/v_proj 省显存，2026 年的共识是：**注意力四件套 + FFN 三件套全挂（q/k/v/o/gate/up/down）才能逼近全参微调质量**，因为 FFN 承载了大部分知识注入。部分层训练（κ-LoRA 的研究）证明可省一半参数量而不掉精度，但依据是预训练权重的条件数排序（选 top 50% 病态矩阵），不是随意跳过——随意挑层训练掉点明显。

## 模块选择的实证与折中

全挂 7 层的"完整基线"之外，工程上存在两种合理的折中：**只挂注意力四件套**（QKV+O）——省约 40% 可训练参数，适合推理/风格类任务，实证掉点可接受；**选择性跳过深层 FFN**——深层 FFN 与事实性知识注入强相关，跳过会显著降低指令遵循质量。判断模块重要性不必靠猜测：2026 年的 κ-LoRA 研究给出系统方法——对预训练权重算条件数（最大/最小奇异值之比），条件数大的矩阵（谱上"欠发育"方向多）承载主要微调收益，只挂 top 50% 就能保精度省一半参数。想做模块裁剪，先跑一次这个分析，而不是凭感觉删层。

## 收敛类超参基线（2026 实测）

| 超参 | 基线 | 说明 |
|---|---|---|
| 学习率 | SFT 2e-4；RL(DPO/GRPO) 5e-6 | 遗忘严重降到 1e-5~5e-5 |
| dropout | 0（Unsloth 默认）；数据 >100K 用 0.05；过拟合用 0.1 | dropout 不为正则化，为防灾难性遗忘 |
| bias | "none" | 训 bias 无实际收益，白耗显存 |
| weight decay | 0.01（0.01-0.1 区间） | — |
| 优化器 | adamw_8bit | 省 ~75% 优化器显存，质量损失可忽略 |
| warmup | 3%-10% 步数 + cosine 衰减 | — |
| batch | 有效批次 8-32，梯度累积自由用 | 物理 batch 1-2 + 累积 8 常见 |

## use_rslora 与 loftq：两个值得知道的开关

**use_rslora=True** 把缩放从 α/r 改为 α/√r，秩升高时更新幅度不会线性放大，高秩训练更稳。代价是它与旧版检查点不兼容，中途开关会破坏续训。**loftq_config** 用预训练权重的奇异向量初始化 A/B（替代随机初始化），收敛更快、小数据下精度更高，但初始化瞬间需要全量权重参与分解，内存出现一次峰值；PEFT 0.18 之后 loftq 初始化也有了性能改进。两者可叠加（loftq 初始 + rslora 缩放），2026 年的 RL 场景推荐组合。

## 任务类型与超参映射

不同任务对超参的敏感度差异巨大，先分类再调参能省一半时间：**风格/格式类任务**（统一输出结构、语气迁移）——内在维度极低，r=4-8 足够，LR 可以偏大（5e-4 量级），重点是数据代表性而非容量；**知识类任务**（领域事实、协议规范）——依赖 FFN 层承载，r=16-32，必须全层挂载，LR 保守（1e-4-2e-4）；**推理类任务**（数学、代码）——需要多方向交互，r=32-64 起步，配合 rsLoRA 稳定高秩，LR 再降一档；**偏好/RL 类**（DPO/GRPO）——r=16-64（Unsloth 建议 max 64），LR 直接取 5e-6 量级，不要沿用 SFT 的 LR。映射表的用途不是照抄数字，而是建立"任务特征 → 容量需求 → 超参量级"的推理链，遇到新任务先对号入座。

## 超参联动的扫描方法

推荐三段式扫描，每段只动一个变量，避免多变量耦合导致"不知道是谁起的作用"：第一段固定 r=16/α=16/全层挂载，扫学习率（2e-4 为锚点，上下各两个量级：5e-5、1e-4、2e-4、5e-4、1e-3），选验证集最优；第二段固定最优 LR，扫秩（8/16/32），同时保持 α/r 比例不变；第三段如仍不足，再试 dropout（0/0.05/0.1）与 use_rslora。小模型（135M-1.7B）跑完整扫描成本低，2026 年已有 Auto-SFT 类工具自动完成"扫参-评测-上传最佳结果"的闭环；大模型则用对数网格抽 3-5 个点即可——目标不是找到全局最优，而是确认"当前配置不在明显次优区"。

## dropout 的定位修正

LoRA 的 dropout 与常规深度学习里的 dropout 语义不同：它加在 A 的输出、B 的输入之间（即对低秩旁路做随机丢弃），作用是打散"适配器对训练样本的逐点记忆"——所以它防的是灾难性遗忘，不是防过拟合（LoRA 参数极少，过拟合主要来自数据重复而非容量）。这个定位修正带来两个实践推论：小数据集（<1000 条）场景 dropout 0.1 几乎必用，因为逐点记忆风险最高；而大数据集（>100K）时 0.05 即可，过高的 dropout 会稀释有效信号导致欠拟合。Unsloth 默认 0 的考量是速度（dropout 有额外 kernel 开销）——默认值适合"先跑通"阶段，正式训练按数据量设置。另一个隐藏点：dropout 开启时推理必须关闭（PEFT 自动处理），合并权重时 dropout 直接消失，不影响部署。

## 数据量决定下限

LoRA 是"表示复用"而非"知识重建"，所以数据需求远低于全参：窄任务（风格迁移、单一格式）500-1000 条干净样本即可；通用指令微调 5000-10000 条。数据质量优先于数量——去重、污染检查（与评测集 overlap 检测）比加数据更有效。序列长度按数据集 token 长度的 ~95 分位设置，盲目拉满 max_seq_len 浪费计算。

## 数据质量的三道工序

数据对 LoRA 的边际影响大于任何超参，三道工序缺一不可。**去重**：语义去重（Embedding 聚类或 MinHash）优先于文本去重——指令微调数据里的"同一意思多种说法"最容易让模型记住模板而非能力；重复样本多到一定程度会直接拉高过拟合。**污染检查**：把评测集样本（或其改写变体）与训练集做 overlap 检测，污染样本混入训练会让评估分数虚高 5-20 个点，是"微调效果好到不真实"的第一怀疑对象。**质量抽查**：至少人工通读 50-100 条，检查 chat template 是否套对、标签是否错位、是否混入系统提示词——这三类错误不会报错，只会静默毒化训练。一句话：先用 500 条高质量数据跑通冒烟，再决定是否扩充到 5000 条，不要一上来就堆量。

## 复现纪律

固定 random_state（Unsloth 默认 3407）；验证适配器权重是否更新用 checksum/hash 而非 np.allclose（A 矩阵变化微小，allclose 可能漏检"其实没训上"的假成功）。实验记录必须含 r、α、use_rslora、loftq 与 LR 五项，缺失任何一项都无法复现——这也是 2026 年"变体优劣之争"很多结论互相矛盾的最大原因（未控制学习率变量）。

> 🎯 **核心要点**：调参优先级是"比例 > 秩 > 学习率 > 模块选择 > 其余"。全部线性层挂载 + α/r 钉死 1.0 或 2.0 + SFT 用 2e-4 起步，就已经在 95% 的最优性能区间内；再往上优化的是数据质量，不是参数。记住"每动一个超参，其余全部冻结"的纪律——LoRA 超参联动性强，多变量同时调整的实验结论永远无法归因。任务类型决定超参量级的映射（风格/知识/推理/RL 四类）值得先对号入座再调参。
