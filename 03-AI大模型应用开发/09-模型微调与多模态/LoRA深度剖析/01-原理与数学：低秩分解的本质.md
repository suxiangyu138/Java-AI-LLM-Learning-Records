# 01-原理与数学：低秩分解的本质

> 定位：LoRA 的全部设计都浓缩在一条公式里——冻结预训练权重，学习一个低秩增量。本文把这条公式拆到每个符号，并回答"为什么低秩是安全的"。

## 核心公式

预训练权重 W₀ 为 d_in × d_out 矩阵。LoRA 冻结 W₀，为它附加一个低秩增量：

```text
h = W₀x + ΔWx = W₀x + BAx
```

其中 B 是 d_out × r，A 是 r × d_in，秩 r 远小于 min(d_in, d_out)。关键约束：**r 是硬上限，ΔW 的秩最多等于 r**。训练只更新 B 和 A，W₀ 全程不动，训练结束后权重总量只增加 2×d×r 个参数。

这个分解的直觉来自矩阵的奇异值分解：任意矩阵 W 可写为 UΣVᵀ，保留前 r 个奇异值即得最佳 r 秩近似。LoRA 等于假设"微调产生的变化"本身就是个低秩矩阵——这个假设被后续大量实验证实，也决定了 r 取 8~64 就够用，而不是动辄上万维。

## 两个决定成败的初始化细节

**B 初始化为零，A 随机高斯**。这样训练开始瞬间 ΔW = BA = 0，模型输出与预训练完全一致，不会因"随机增量"打乱已学好的表示；梯度经 B 回流时也不会在第一步就把损失炸掉。若 B、A 都随机初始化，等于给每个目标层叠了一份额外的随机扰动，微调初期效果会明显退化。

**缩放因子 α**。实际前向计算为：

```text
h = W₀x + (α/r) · BAx
```

α 是输出方向的缩放常数，训练中不回传梯度。理解 α 的正确姿势是把它和 r 绑在一起：真正影响行为的是比例 α/r。实践中两个基线——α=r（比例 1.0，PEFT 默认）与 α=2r（比例 2.0）——覆盖绝大多数场景。若中途把 r 从 8 提到 16 而 α 保持 16 不变，有效缩放从 2.0 掉到 1.0，实验不可复现，这是最常见的调参事故。

## 秩的边界：为什么秩 1 也有价值

低秩不等于"能力差"——秩的语义要按层解读。一个 d×d 权重矩阵的有效更新如果主要沿单一方向（例如把"输出语言风格统一"这类任务，几乎所有层的变化都可用一个主方向近似），秩 1 的 ΔW = uvᵀ 就能承载它。风格迁移、格式统一类任务用 r=2-4 就能收敛，正是这个原因；而数学推理、代码生成这类需要大量正交方向交互的任务，r 必须到 32-128。理解这一点对"秩不够时该做什么"很重要：提秩前先判断任务是"方向单一"（提数据）还是"交互复杂"（提秩），方向错了白烧显存。

## 训练时的显存账目

LoRA 的省显存不只在权重存储。Adam 优化器对每个可训练参数维护两个状态（m、v，各 4 字节 fp32），加上梯度拷贝，全参微调 7B 需要 7B × 12 字节 ≈ 84GB 优化器状态——单卡无法承担；而 LoRA 只对 A/B 维护状态：可训练参数 0.2% 时约 0.17GB。梯度方面同理：全参微调梯度 14GB，LoRA 只需反向传播到 A/B（底座权重冻结后不计算梯度），显存大头只剩下激活值。训练峰值 ≈ 权重 + 激活 + 优化器状态，LoRA 把后两项压到百分之一量级——这就是 8GB 显卡能训 7B 的结构性原因。

## 参数量：省在哪里

以 7B 模型、r=16、对注意力与 FFN 全部线性层挂载为例：单层可训练参数约 7×2×16×4096 ≈ 92 万（7 个投影层 × 两个矩阵），总计约 1000-2000 万，占全模型 0.1%~0.2%。与全参微调相比，省下的不只是存储：优化器状态（Adam 每个参数 12 字节）按可训练参数而非全模型计算，r=16 的 8B 模型约 0.21% 可训练比例（2026 Unsloth 实测），显存占用随秩大致线性增长——r 翻倍，显存与训练时间约翻倍，这就是"秩也要省着花"的工程原因。

## 与参数高效微调家族的关系

LoRA 不是第一个 PEFT 方法，但它解决了前人的结构性缺陷：

| 方法 | 改动位置 | 推理延迟 | 主要缺陷 |
|---|---|---|---|
| Adapter | 层间插入 MLP | 有（序列变深） | 每层串行额外计算 |
| Prefix/Prompt | 输入序列前拼接向量 | 有（序列变长） | 可学习 token 数受窗口限制 |
| BitFit | 只训 bias | 无 | 容量小，复杂任务不足 |
| LoRA | 权重矩阵旁路 | 无（可合并） | 低秩假设在高秩任务上有容量上限 |

Adapter 与 Prefix 把"参数"放进推理路径，代价是延迟或窗口占用；LoRA 的旁路结构允许训练完成后把 ΔW 直接加回 W₀（merge），推理时零额外开销——这个特性是它成为工业事实标准的最重要推手。2026 年的实证（ICML 2026 RLVR 12 方法对比）也确认：在 RL 训练中结构化变体（DoRA 46.6%、MiSS 等）稳定胜过 vanilla LoRA（42.5%），但全参微调（44.9%）与强变体差距已很小，说明"低秩逼近全参"在现代模型上基本成立。

## 最小代码形态

```python
from peft import LoraConfig, get_peft_model

config = LoraConfig(
    r=16, lora_alpha=16, lora_dropout=0.0, bias="none",
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj",
                    "gate_proj", "up_proj", "down_proj"],
)
model = get_peft_model(model, config)   # 内部完成 A/B 初始化与冻结
```

PEFT 的 get_peft_model 返回一个 PeftModel 包装器：原权重被冻结并替换为 lora 模块，训练时只有 A/B 得到梯度。导出适配器只存 A/B 与配置，safetensors 格式约 100-150MB（7B、r=16，2026 实测），而全量权重 14GB——这就是 LoRA 能"一个底座挂几百个任务适配器"的数学基础。

## 缩放因子的数学等价视角

α/r 的缩放还有一个值得记住的等价解释：设 λ = α/r，则 ΔW = λ·BA。把 λ 吸进 A（定义 A' = λA），等价于"保持 BA 结构不变、只放大 A 的初始化与更新"。这意味着**调节 α 与调节学习率在数学上部分等价**——α 调大 = 隐式放大 A 的梯度步长。这个等价关系解释了三个工程经验：α/r 比例不变时改 r 不改变有效步长（只改变容量）；α 与 LR 之间存在补偿关系（α 翻倍 + LR 减半 ≈ 等效果，实测近似成立）；以及"α 过大训练发散"与"LR 过大训练发散"是同一现象。理解这个视角后，调参时可以只保留一个旋钮的心理模型：比例控制容量语义，LR 控制收敛动力学，两者分开调、分别观察——比混合调节更容易定位问题。

## 训练中 BA 的实际行为

理解 B、A 的职责分工能解释许多工程现象：A 是"压缩器"（把输入投影到 r 维子空间），B 是"展开器"（把子空间结果映射回输出空间）。B 初始为零意味着第一轮梯度全部流经 A（B=0 时 A 的梯度非零），A 先"选择方向"，随后 B 才逐步"塑造幅度"——这就是 LoRA+ 给 B 更高学习率的动力学依据。实测观察（2026 社区共识）：训练早期 loss 下降主要由 A 的更新贡献，后期主要由 B 的更新贡献；如果训练 1 个 epoch 后 A 的范数远大于 B，说明学习率对 A 过高，反之亦然。这个"A 选方向、B 定幅度"的分工也解释了为什么 LoRA 适配器能被线性组合——不同任务的适配器共享底座后的组合近似于在低秩子空间内做方向叠加，冲突小于全参微调之间的组合。

## 局限与边界

低秩假设的边界在三类场景暴露：**任务内在维度超过秩**（复杂推理、多技能叠加）——此时 LoRA 收敛到次优解，提秩到 64-128 或直接全参；**分布外知识**——预训练没见过的知识（新语言、新领域协议）不在可复用的低秩流形内，LoRA 只是"硬拟合"训练集；**对抗性/安全敏感场景**——低秩小参数训练出的安全行为容易被少量恶意数据击穿（见 09 篇）。判断口诀：LoRA 是"让模型用已会的技能做好事"，不是"让模型学会不会的技能"——需求落在前者用 LoRA，落在后者请先考虑数据注入或全参。

> 🎯 **核心要点**：LoRA 的全部设计决策（低秩、B 零初始化、α/r 缩放、旁路可合并）都服务于同一目标——在最小参数量下不破坏预训练表示，且推理零开销。理解公式的三个符号 W₀、B、A 与两个常数 r、α 的关系，就理解了 LoRA 的一切变体。
