# 08-多模态与扩散模型应用

> 定位：LoRA 不只属于纯文本 LLM——视觉语言模型（VLM）的语言侧适配、扩散模型的风格注入，是两个规模同样巨大的战场。本文覆盖 LLaVA 家族与 DreamBooth+LoRA 两条主流实践线。

## 视觉语言模型：LoRA 挂在语言侧

VLM 的标准结构是"冻结视觉编码器 + 投影层 + LLM"（LLaVA 系）。微调的目标是让 LLM 学会解读投影进来的视觉 token，因此 LoRA 的挂载位置与文本模型完全一致——LLM 的注意力与 FFN 线性层；视觉塔（ViT/CLIP）与投影层通常冻结。PEFT 对多模态栈的支持成熟：`AutoPeftModelForCausalLM` 等 Auto 类可直接加载带 LoRA 的 VLM 适配器，LLaVA-NeXT 等架构的 target_modules 命名规范（`q_proj` 等）与文本模型同构，训练代码几乎零改动。

两个值得注意的 2026 实证：**MTLoRA**（BTA 中间变换）在 LLaVA-1.5-7B 上取得结构变体中最佳多模态效果，说明低秩子空间内的旋转变换对跨模态对齐有帮助；**Rank-1 Expert Pool**（AAAI 2026）把单个 LoRA 拆成可组合的 rank-1 专家池做视觉-语言持续学习，用 [CLS] token 语义动态组合稀疏更新，可训练参数降 96.7% 且无推理延迟——多模态持续学习场景 LoRA 已能"不断学新任务不遗忘旧任务"。

## VLM 微调的实际流程

LLaVA 家族的微调管线是两阶段的：预训练阶段（对齐投影层，LoRA 可选）、微调阶段（指令数据，LoRA 挂 LLM 语言侧）。工程上常见的简化是跳过预训练、直接用现成 VLM 检查点（如 LLaVA-1.5 系列）做单阶段 LoRA 微调——大多数业务场景（让 VLM 学会识别特定领域物体、输出固定格式）单阶段足够。数据格式与文本 SFT 同构：image + 多轮对话 messages，唯一区别是图像需要过视觉塔得到 embedding 再注入。target_modules 探测要小心：VLM 的 LLM 部分沿用 q_proj 等命名，但图像 token 来自视觉塔的嵌入，若视觉塔也有同名模块需要区分（peft 的 target_modules 匹配会同时命中两者，必要时用正则排除视觉塔）。评估比文本模型多一个维度：图文一致性（生成的描述是否真的对应输入图像），常用 CLIP 分数与人工抽检双通道。

## 扩散模型：DreamBooth + LoRA 的事实标准

文生图微调的主流形态是"DreamBooth 少样本学习 + LoRA 参数高效训练"：10-30 张目标图像（人物/物体/画风），教模型一个稀有 token 与视觉概念的绑定。与 LLM 的关键差异在结构：扩散模型的可训练组件是 **UNet 去噪网络 + 文本编码器（CLIP/T5）**，LoRA 挂在 UNet 的交叉注意力层（文本条件注入处）的 in/out 投影与自注意力的 QKV 上，文本编码器通常只训 LoRA 或不训（避免风格漂移）。

超参惯例与 LLM 明显不同（2026 实测）：秩 r=4（扩散模型的适配往往只需要极低秩）、α=8（比例 2.0）、AdamW LR 4e-5、cosine 调度——扩散 LoRA 训练步数短（几百到几千步）、数据小，秩需求远低于语言任务。训练目标是 UNet 前向过程（加噪图像 + 条件）的去噪损失，无需 chat template 等语言处理。

## DreamBooth 训练的三件关键设计

**概念绑定**：给目标概念分配一个稀有 token（如 "sks cat"），训练时把它与概念图像配对，生成时用该 token 触发——token 选词要避开高频词（用罕见字符串），否则学习被已有语义稀释。**class 图像**：原始 DreamBooth 需要同类的先验图像（如"普通猫"的样本）防止概念漂移，LoRA 版可以省略或少量保留（2026 的 few-shot 研究已证明 class 集可去除，代价是轻微过拟合风格）；**正则化与步数**：扩散 LoRA 训练步数短（500-3000 步），过量训练会过拟合到训练图像（生成图开始复刻训练图的构图与背景），行业惯例是"肉眼盯生成图"而非只看 loss——扩散模型没有可靠的验证损失，人工抽检是质量门的唯一手段。训练后的验证三件套：FID（分布距离）、CLIP score（文本-图像一致性）、人工比较（风格是否"像"而不只是"复刻"）。

## 扩散模型结构与 LoRA 挂载点

理解扩散 LoRA 的挂载选择需要先看 UNet 的结构：UNet 的每层有自注意力（图像内部关系）与交叉注意力（图像-文本条件关系），文本条件通过交叉注意力的 K/V 注入（文本 token 作 key/value，图像 token 作 query）。LoRA 挂载的收益排序（社区实测）：**交叉注意力的 in/out 投影与 QKV > 自注意力的 QKV > FFN**——因为风格与概念的绑定本质发生在"文本条件如何影响图像生成"的交叉注意力处，训练量不足时优先保这里。文本编码器（CLIP/T5）的 LoRA 争议更大：训它能让 prompt 理解更准（风格关键词生效），但显著增加过拟合风险（风格与特定词绑定过死）；2026 惯例是"主体（概念）训练训文本编码器、纯风格训练冻结文本编码器"。扩散 LoRA 的另一个结构特点：适配器文件兼容性好（UNet 层命名跨 SD 1.5/SDXL 基本一致），这也是 Civitai 生态能跨底座共用适配器的技术基础。

## 2026 扩散 LoRA 研究趋势

- **多 token 策略**：为风格与角色分别分配独立 token（Pascual et al.，ESWA 2026），用聚类把"集体风格"与"单角色"解耦，替代传统 class 正则化集，实现无限角色生成，并配套 CLIP-I 风格一致性新指标。
- **合成数据公平性**（AAAI 2026）：按组聚类训练多个 DreamBooth+LoRA 生成平衡合成数据，在强偏置数据集上媲美 SOTA 去偏方法——LoRA 微调成为数据增强管线的一部分。
- **工具链**：lorakit（2026）把 SDXL DreamBooth/LoRA 训练收敛为单 YAML 配置驱动，集成 latent caching、torch.compile、bf16（RTX 4090 上比朴素 4-bit 方案快约 5.9 倍）、4-bit QLoRA 支持 16GB 卡、10-30 张图推荐、面部背景保持（19 类 face parser）。

```yaml
# lorakit 风格配置（节选）
model: SDXL
rank: 4
alpha: 8
targets: [unet.cross_attn, unet.self_attn]   # UNet 交叉注意力为主
text_encoder: false                          # 冻结文本编码器防漂移
quant: qlora-4bit                            # 16GB 卡可用
```

## 生态与分发：Civitai 模式

扩散 LoRA 拥有业界最成熟的分发生态：Civitai 等平台以 .safetensors 单文件分发适配器（几十到几百 MB），附带触发词与示例图，用户下载后在 WebUI/ComfyUI 中挂载即用，同一底座可叠加多个风格/角色 LoRA 自由组合。这套生态反过来定义了扩散 LoRA 的工程约定：适配器文件内嵌 metadata（底座版本、训练参数、触发词）；模型名规范（如 "add_detail"、"flat2" 等语义名）；训练方需在 model card 标注底座兼容范围。相比之下 LLM LoRA 的生态以 Hugging Face Hub 为中心（PEFT 目录结构 + adapter 配置），风格更"版本化"而更不"集市化"。两条生态线共同说明一件事：LoRA 的分发能力（小文件、即插即用、可组合）本身就是它成为微调事实标准的产品化红利。

## 多模态 LoRA 的扩展边界

LoRA 的多模态应用不止"LLM + 扩散"两类，2026 年的扩展谱系值得标记：**视频生成**——视频扩散模型的 LoRA（SVD/视频生成模型做风格化与角色一致），挂载点与图像 UNet 同构，但训练数据量级与时长成本高一到两个数量级，社区实践以"图像预训练 LoRA + 视频微调"两段式为主；**音频/语音**——TTS 音色 LoRA（vLLM 生态 2026 年出现 LoRA 适配 TTS 模型的 RFC，说明多 LoRA 服务正在扩展语言模型之外的模型族）；**检索与 embedding**——低秩适配 embedding 模型做领域向量空间（与 RAG 体系相关）；**具身/视觉-语言行动模型**——VLA 的策略头微调（如 RT-2 类，LoRA 适配视觉-动作映射层）。共同的工程规律不变：冻结大网络、低秩适配轻量部分、适配器可插拔可组合。这条扩展路径与 `03-AI大模型应用开发` 的 RAG/Agent 体系形成对照——LoRA 解决"模型能力适配"，RAG 解决"知识接入"，两者互补而非竞争。

## 语言 LoRA 与扩散 LoRA 差异速查

| 维度 | LLM LoRA | 扩散 LoRA |
|---|---|---|
| 目标网络 | 解码器/编码器 | UNet + 可选文本编码器 |
| 挂载层 | QKV/FFN 全线性层 | 交叉注意力为主，r 可更小 |
| 典型秩 | 16-64 | 4-16 |
| 数据规模 | 千-万级样本 | 10-30 张图（DreamBooth） |
| 典型 LR | 2e-4 | 4e-5 量级 |
| 损失 | 语言建模/偏好/奖励 | 去噪 MSE |
| 交付形态 | merge 或多适配器服务 | .safetensors 适配器（Civitai 生态分发） |

> 🎯 **核心要点**：多模态的 LoRA 应用遵循同一原则——**冻结重网络、低秩微调轻量部分**：VLM 只调语言侧，扩散模型只调 UNet 注意力。扩散侧因任务本质（风格/概念注入）秩需求更低，超参惯例（r=4、LR 4e-5）与 LLM 不可互抄。
