## 4. 核心概念速查

| 概念 | 一句话本质 |
|---|---|
| LoRA | 冻结预训练权重 W，学习低秩增量 ΔW=BA（秩 r 远小于原矩阵维数） |
| 内在低秩 | 微调产生的权重变化近似落在低秩子空间中，故 r 足够小也能逼近全参微调 |
| 缩放因子 | 实际更新 = α/r × BA；α 与 r 的比例先钉住（1.0 或 2.0），再调 r |
| QLoRA | 在 4-bit NF4 量化底座上训练 LoRA，双重量化 + 分页优化器再省显存 |
| DoRA | 权重分解为幅度+方向，只对方向做低秩适配（RLVR 实证强于 vanilla） |
| PiSSA | 用 SVD 主奇异分量初始化适配器，收敛快但 RL 场景会谱坍缩 |
| merge | 把 ΔW 加回 W 得到等价全量权重，推理零额外开销 |
| 多 LoRA 服务 | 单底座动态挂载多适配器（vLLM/Punica），无需复制模型 |
| loftq | 用预训练权重奇异向量初始化 LoRA 矩阵，避免随机初始化的冷启动损失 |
| CSULoRA | 后验安全校正：把 LoRA 更新投影到对齐子空间做收缩 |

> 🎯 **核心要点**：LoRA 的价值 = 以千分之一的可训练参数量，逼近全参微调的效果，并天然获得"适配器可插拔、可组合、可多实例共享底座"的工程收益。2026 年的研究重心已从"发明新结构"转向"训练前免费分配秩（RSLoRA/κ-LoRA）与后验安全校正（CSULoRA）"。

## 5. 常见误区速查

- **误区一："LoRA 是低精度训练"**。LoRA 的全精度版本（fp16/bf16）不是低精度方法，量化只是 QLoRA 的附加选择；LoRA 省的是"参数数量"，不是"数值精度"。
- **误区二："秩越大越好"**。r 超过任务内在维度后收益趋零，代价（显存、时间）却线性上涨；r=16 与 r=128 的差距远小于数据质量与学习率的差距。
- **误区三："变体一定比 vanilla 强"**。2026 年 LR 扫描实证显示大部分变体增益可被调好的学习率抹平；变体价值高度任务相关（DoRA 在 RL、PiSSA 在 SFT 快速收敛）。
- **误区四："LoRA 适合所有微调"**。全新知识注入、超高维推理需求场景下低秩容量不足，全参 SFT 仍是正确选择。
- **误区五："合并后与带 LoRA 推理完全一致"**。数学等价，数值上因精度累积存在微小差异；DoRA 等变体合并有版本要求（PEFT ≥ 0.10）。
- **误区六："加载第三方适配器很安全"**。适配器是代码级别的权重投毒入口（后门、对齐破坏），信任边界要画在加载之前。
- **误区七："LoRA 与模型量化是互斥技术"**。二者正交：QLoRA 正是"量化底座 + LoRA 适配器"的组合；训练产物还可以跨精度部署（QLoRA 训练、fp16 底座上线）。

## 6. 2026 版本基线速查

正文所有数字与断言均以本表为基准（2026-08 检索校准，详细出处见各篇末尾）：

| 组件 | 版本 | 关键约束 |
|---|---|---|
| peft | 0.19.1（2026-04-16） | Python 3.10+；transformers 5.12.1+ 要求 ≥0.19.0 |
| bitsandbytes | 0.49.2（2026-02-16） | QLoRA 4-bit 训练；0.46.1 为最低要求 |
| transformers | 5.x（5.13 验证） | v5 起 PEFT 依赖下限上调 |
| trl | 0.15.2+ | quantization_config 直传（PR #6157，2026-06） |
| torch | 2.6+ | FSDP/bf16 支持 |
| vLLM | 0.14/0.15 | punica_wrapper 多 LoRA 服务（GPU/CPU/NPU） |
| Unsloth | 2026 文档基准 | 默认 r=16/α=16/dropout=0/random_state=3407 |
