## 1. 章节定位

章节二解决对比总结的进阶与工程落地的入口两个问题：**"多个方案怎么组合成最优架构"**（组合层）与**"选定方案怎么部署成推理服务"**（服务层）——**先组合后部署**（架构定了再谈服务——`00-模块4课程总览.md` 的层顺序）——本章节的过渡本质：**"从'选一个方案'升级为'组合多个方案'，从'模型'升级为'服务'"**。

## 2. 第 3 层：混合策略与组合架构（组合层）

**子体系**：`../大模型微调知识体系/边界判断（非常关键，面试必问）/`（09 篇）+ `../多模态/多模态 RAG/`（05/08 篇）+ `../多模态/推理部署工程/`（07 篇）——**核心问题："RAG + 微调 + Prompt + 工具怎么组合成完整架构"**。

**逐篇学习清单**（组合 4 篇 + 对照）：

| 篇 | 主题 | 组合视角的一句话 | 优先级 |
|:---:|------|------|:---:|
| 边界/09 | 成本收益量化与混合策略 | ROI、form/facts/orchestrate——组合的原则 | 必读（精读） |
| RAG/05 | 多模态 RAG 架构设计 | 双路由、证据图——组合的骨架 | 必读（精读） |
| RAG/08 | 多模态 RAG 工程实现 | 成本账、选择性视觉化——组合的成本边界 | 必读（精读） |
| 推理/07 | 多模态 Agent 部署 | 截图感知、多智能体——组合的编排层 | 选读（精读） |

**本层学习要点**：**三个必须组合的架构框架**——混合策略三原则（**form（行为/格式）归微调、facts（知识）归 RAG、orchestrate（编排）归 Agent/工具**——`边界判断（非常关键，面试必问）/09-成本收益量化与混合策略.md`——组合不是堆方案，是按性质分工）；双路由架构（摄入路由按内容分流——文本页 OCR/图表页 ColPali——查询路由按问题分流——`多模态/多模态 RAG/05-多模态RAG架构设计.md`——RAG + 微调的组合模板）；成本边界（选择性视觉化——**不是所有输入都要视觉处理**——`多模态/多模态 RAG/08-多模态RAG工程实现.md`——组合时先算账）——**"组合层学完 = 能设计一个多方案组合的完整架构"**（性质分工 + 路由骨架 + 成本边界三件事）。

## 3. 第 4 层：推理服务与性能（服务层）

**子体系**：`../多模态/推理部署工程/`（本层精读 01-06）+ 对照 `../../07-模型部署与工程化/模型推理与部署/`（11 篇，精读 02-07）——**核心问题："模型怎么部署成高性能推理服务、性能账怎么算"**。

**逐篇学习清单**（多模态服务 6 篇 + 文本服务对照）：

| 篇 | 主题 | 服务视角的一句话 | 优先级 |
|:---:|------|------|:---:|
| 推理/01 | 多模态推理全景与定位 | 四阶段链路、与文本推理三差异 | 必读（精读） |
| 推理/02 | 多模态推理性能分析 | token 膨胀第一问题、瓶颈四步法 | 必读（精读） |
| 推理/03 | 多模态推理优化 | token 压缩第一杠杆、编码器优化 | 必读（精读） |
| 推理/04 | 多模态服务架构 | 合设 vs E-P-D 分离、模态感知调度 | 必读（精读） |
| 推理/05 | 多模态量化与压缩 | FP8 默认、视觉塔量化谨慎 | 必读（精读） |
| 推理/06 | 多模态缓存策略 | 三重复用、前缀缓存路由 | 必读（精读） |

**对照篇（模型推理与部署——相同处回跳）**：02 KV-Cache 管理与优化（**相同**：PagedAttention/前缀复用——多模态加视觉 KV 剪枝）；03 投机采样与推测解码（**相同**：草稿模型——多模态用 mmproj）；04 批处理与动态 Batching（**相同**：continuous batching——多模态按 token 预算分组）；05 模型量化推理实战（**相同**：AWQ/GPTQ/FP8——多模态加混合精度视觉塔）；07 推理引擎选型对比（**相同**：vLLM 默认——多模态检查引擎就绪）；08 服务架构与弹性伸缩（**相同**：副本/伸缩——多模态加图像显存预算）。

**本层学习要点**：**四个必须结合的服务框架**——token 膨胀是第一问题（**图像 token 是文本的 100 倍级——文档负载的大头**——优化先压缩 token 再量化——`多模态/推理部署工程/02-多模态推理性能分析.md`）；服务架构决策（**先合设优化、后分离扩展**——64 并发/96 GPU 才是 E-P-D 分离盈亏点——`多模态/推理部署工程/04-多模态服务架构.md`）；量化纪律（**FP8 默认、视觉塔量化 = 感知缺陷放大器**——混合精度——`多模态/推理部署工程/05-多模态量化与压缩.md`）；缓存策略（**多模态重复率高——缓存省最贵的部分**——三重复用/前缀缓存路由——`多模态/推理部署工程/06-多模态缓存策略.md`）——**"服务层学完 = 能设计一个多模态推理服务"**（架构/优化/量化/缓存四件事 + 性能账本）。

**层内顺序**：组合层 边界 09 → RAG 05/08 → 推理 07；服务层 推理 01 → 06 + 对照 02-08。**层间顺序**：组合 → 服务（先架构后服务——`00-模块4课程总览.md` 的层顺序）。

**跨模块跳读建议**：本层与模块 2 章节三/四（检索排障/推理部署）联动——RAG 与推理部署的逐篇清单在模块 2 已列，本层做"组合与落地视角"精读；服务层对照篇（模型推理与部署）是新引入体系——按本层清单精读 02-07，其余篇回跳 `../../07-模型部署与工程化/模型推理与部署/00-模型推理与部署体系总览.md`；与章节三联动——服务是工程化的对象（第 5 层）。

## 5. 章节验收

章节二的验收（两子体系各 10 题自测 + 每层一实践）：

**自测**：`多模态/多模态微调（PEFT）/00-多模态微调（PEFT）总览.md` 的快速自测 10 题（决策边界部分——组合层）+ `多模态/推理部署工程/00-多模态推理部署工程总览.md` 的快速自测 10 题（服务层）。

**实践三（组合）**：为"文档问答"设计混合方案——内容分流（文本页 OCR/图表页 ColPali）+ 查询路由 + 微调兜底场景 + Agent 编排（需要工具调用时）——产出"架构图 + 成本估算"（`多模态/多模态 RAG/05-多模态RAG架构设计.md` 与 `多模态/多模态 RAG/08-多模态RAG工程实现.md` 的对照）。

**实践四（服务）**：把微调后的 VLM 设计成推理服务——服务形态（合设起步）+ 量化选型（FP8/混合精度）+ 缓存策略（三重复用）+ token 预算（单会话图像 token 账本）——产出"服务设计 + 性能预算"（`多模态/推理部署工程/04-多模态服务架构.md` 与 `05-多模态量化与压缩.md` 的对照）。

> 🎯 **核心要点**：章节二 = 组合层（form/facts/orchestrate 三原则 + 双路由骨架 + 成本边界）+ 服务层（token 膨胀第一问题/先合设后分离/量化纪律/缓存策略四框架）；过渡本质 = "从选一个方案到组合多个方案、从模型到服务"；验收 = 20 题自测 + 混合方案 + 服务设计——"方案能组合、模型能上线 = 章节二通过"。
