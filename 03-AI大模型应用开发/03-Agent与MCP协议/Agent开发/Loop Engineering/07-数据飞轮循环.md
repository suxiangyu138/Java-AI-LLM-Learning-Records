## 1. 数据飞轮模型

```text
数据飞轮 = 使用 → 数据 → 改进 → 更好的体验 → 更多使用

        ┌──────────────────────────┐
        │      更多用户使用          │
        └──────────┬───────────────┘
                   │
    ┌──────────────┼──────────────┐
    ▼              ▼              ▼
用户反馈数据   行为埋点数据    对话交互数据
    │              │              │
    └──────────────┼──────────────┘
                   ▼
        ┌──────────────────────┐
        │    数据清洗 + 标注    │
        └──────────┬───────────┘
                   ▼
        ┌──────────────────────┐
        │  模型迭代 (微调/RLHF) │
        └──────────┬───────────┘
                   ▼
        ┌──────────────────────┐
        │    AI 能力明显提升    │
        └──────────┬───────────┘
                   │
                   └────→ 回到"更多用户使用"
```

### 1.1 三个反馈速度层

| 层级 | 反馈周期 | 数据来源 | 改进方式 |
|------|:---:|------|------|
| **快速** | 实时-小时 | 用户点赞/踩 | Prompt 调整 |
| **中速** | 天-周 | 复杂对话日志 | 微调模型 |
| **慢速** | 月-季度 | 大规模标注数据 | 预训练改进 |

## 2. 飞轮启动策略

### 2.1 冷启动问题

```text
鸡生蛋还是蛋生鸡？
  → 没有用户 → 没有数据 → 模型不够好 → 用户不来

冷启动三条路：

1. 用通用模型起步（最实际）
   GPT-4 / Claude 做推理 → 积累数据 → 微调小模型替代
   → 先用"别人家的飞轮"，造"自己家的飞轮"

2. 专家标注冷启动（最可控）
   请领域专家标注 500-2000 条高质量数据
   → 微调出初步可用模型
   → 上线后用户反馈补充

3. 合成数据冷启动（最快）
   LLM 生成模拟对话 → 用少量人工标注做质量过滤
   → 微调 → 上线
```

### 2.2 飞轮启动的 MVP 数据量

| 任务类型 | 最少启动数据 | 达到 80% 效果 |
|------|:---:|:---:|
| 意图分类 | 200-500 条 | 标注 + 模板增强 |
| 客服问答 | 500-1000 条 | 专业标注 |
| 代码审查 | 300-500 条 | 专家标注 |
| 内容摘要 | 200-400 条 | LLM 合成 + 人工审核 |

## 3. 飞轮中的隐性数据采集

### 3.1 显性 vs 隐性反馈

```text
显性反馈（用户主动给的）：
  ✅ 点赞/点踩
  ✅ 评分 (1-5星)
  ✅ "这条回答有用吗？"

隐性反馈（用户无意中留下的）：
  ✅ 用户采纳了 AI 建议的代码（复制了）= 正面
  ✅ 用户重新提问了一遍 = 上次回答不好
  ✅ 用户在对话中途关掉了 = 不满意
  ✅ AI 回答后用户很久没回复 = 满意（不需要追问）
  ✅ 用户修改了 AI 生成的内容 = 参考但不完全可用
```

### 3.2 反馈采集代码

```python
class ImplicitFeedbackCollector:
    """隐性反馈采集器"""

    def collect(self, conversation: list[dict]) -> dict:
        signals = {}

        # 1. 采纳率 = AI 生成内容是否被使用
        if self._was_code_copied(conversation):
            signals["code_accepted"] = True

        # 2. 追问 = 上次回答不够好
        if self._was_follow_up(conversation):
            signals["needs_improvement"] = True

        # 3. 对话中断 = 不满意 / 任务完成
        if self._was_abandoned(conversation):
            signals["abandoned"] = True

        # 4. 用户修改率
        signals["edit_ratio"] = self._calc_edit_ratio(conversation)

        return signals
```

## 4. 飞轮断裂与修复

### 4.1 飞轮断裂的四种模式

| 断裂模式 | 症状 | 根因 | 修复 |
|------|------|------|------|
| **数据污染** | 模型越训越差 | 低质量反馈被当做正面样本 | 引入人工抽检 + 反馈权重 |
| **分布漂移** | 准确率逐渐下降 | 用户行为变了但训练数据没更新 | 持续监控 + 定期重训 |
| **反馈稀疏** | 飞轮转不动 | 用户不给反馈 | 用隐性反馈补充 |
| **偏见放大** | 模型倾向某些回答 | 反馈循环自强化偏见 | 多样性采样 + 对抗样本 |

### 4.2 飞轮健康监控

```python
class FlywheelMonitor:
    def health_check(self) -> dict:
        return {
            # 飞轮在转吗？
            "weekly_active_users": self.get_wau(),

            # 数据质量好吗？

            "positive_feedback_ratio": self.get_positive_ratio(),

            # 模型在变好吗？

            # 飞轮在加速吗？
            "organic_growth_rate": self.get_organic_rate(),    # > 30% = 强力飞轮
        }
```

## 核心要点回顾

- 数据飞轮 = 使用 → 数据 → 模型 → 更好体验 → 更多使用
- 飞轮三速：快速(Prompt)、中速(微调)、慢速(预训练)
- 冷启动：GPT-4 代跑(最快) / 专家标注(最稳) / 合成数据(最便宜)
- 隐性反馈 > 显性反馈：用户不说但行为会暴露真实评价
- 飞轮断裂四大模式：数据污染、分布漂移、反馈稀疏、偏见放大
- 健康标准：有机增长 > 30%、准确率月增 > 2%
