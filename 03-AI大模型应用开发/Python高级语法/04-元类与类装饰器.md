## 1. type：类的类

```python
# 类也是对象——type 是创建类的类
class Dog:
    bark = "汪汪"

# Dog 的本质 = type() 动态创建
Dog = type('Dog', (object,), {'bark': '汪汪'})
#        (类名,  父类元组,   类属性字典)

d = Dog()
print(d.bark)  # 汪汪

# type 的三个参数：
# param1: 类名字符串
# param2: 父类元组（支持多继承）
# param3: 类属性和方法的字典
```

## 2. 自定义元类

```python
# 元类 = 控制类的创建过程
# metaclass 必须继承 type
class SingletonMeta(type):
    _instances = {}

    def __call__(cls, *args, **kwargs):
        if cls not in cls._instances:
            cls._instances[cls] = super().__call__(*args, **kwargs)
        return cls._instances[cls]

class Database(metaclass=SingletonMeta):
    def __init__(self, url):
        self.url = url

db1 = Database("postgresql://...")
db2 = Database("mysql://...")
print(db1 is db2)  # True — 单例！

# 元类 __call__ 的调用时机：
# Database("url") → SingletonMeta.__call__() → type.__call__()
```

### 自动注册子类

```python
class PluginRegistry(type):
    registry = {}

    def __new__(cls, name, bases, attrs):
        new_class = super().__new__(cls, name, bases, attrs)
        if name != "BasePlugin":
            cls.registry[name] = new_class
        return new_class

class BasePlugin(metaclass=PluginRegistry):
    pass

class WeatherPlugin(BasePlugin):
    pass

class StockPlugin(BasePlugin):
    pass

print(PluginRegistry.registry)
# {'WeatherPlugin': <class WeatherPlugin>, 'StockPlugin': <class StockPlugin>}
```

## 3. 类装饰器 vs 元类

```python
# 类装饰器：更简单，大多数场景够了
def add_repr(cls):
    """自动生成 __repr__"""
    def __repr__(self):
        attrs = ', '.join(f'{k}={v!r}' for k, v in self.__dict__.items())
        return f'{cls.__name__}({attrs})'
    cls.__repr__ = __repr__
    return cls

@add_repr
class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y

p = Point(1, 2)
print(p)  # Point(x=1, y=2)
```

| 维度 | 类装饰器 | 元类 |
|------|:---:|:---:|
| 影响力 | 只影响装饰的类 | 影响所有使用该元类的类 |
| 可继承 | 子类不受影响 | **子类自动继承** |
| 复杂度 | 低 | 高 |
| 使用建议 | 能装饰器解决的不用元类 | 需要跨类继承行为时用 |

## 核心要点回顾

- `type` 是 Python 的默认元类——一切类都是 type 的实例
- 元类的 `__new__` 控制类的创建，`__call__` 控制实例的创建
- 元类最经典应用：ORM（Django/SQLAlchemy）、单例、自动注册、Pydantic 的 BaseModel
- 90% 场景用类装饰器就够了，元类是最后手段
