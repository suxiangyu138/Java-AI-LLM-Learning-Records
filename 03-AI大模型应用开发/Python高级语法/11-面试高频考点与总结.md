## 1. 高频面试题

### Q1（⭐⭐⭐⭐⭐）: 装饰器的原理是什么？

> 装饰器 = 接受函数 → 返回新函数的高阶函数
> `@decorator` = `func = decorator(func)`
> 闭包是装饰器的前置知识——内部函数捕获外部变量
> `@functools.wraps` 保留原函数的元信息（`__name__`、`__doc__`）

### Q2: `yield` 和 `return` 的区别？

> `return` 返回一次，函数结束
> `yield` 返回一次，函数暂停，下次从暂停处继续
> 生成器 = 用 `yield` 的函数 → 惰性求值，节省内存

### Q3: GIL 是什么？怎么绕过？

> GIL = 全局解释器锁，同一时刻只有一个线程执行 Python 代码
> 绕过：I/O 密集 → `asyncio`（协程），CPU 密集 → `ProcessPoolExecutor`（多进程）

### Q4: `with` 语句的原理？

> `with obj as var:` =
> 1. `var = obj.__enter__()`
> 2. 执行 with 块代码
> 3. `obj.__exit__(type, value, tb)` ← 即使异常也执行
> `@contextmanager` + `yield` = 最简单的实现方式

### Q5: `__new__` 和 `__init__` 的区别？

> `__new__`：创建对象（分配内存）→ 返回实例
> `__init__`：初始化对象（设置属性）→ 返回 None
> 调用顺序：`__new__` 先 → `__init__` 后

### Q6: 类型提示对运行时有什么影响？

> **零影响**——类型提示在运行时被忽略（只是注解）
> 需要运行时校验 → Pydantic
> 需要静态检查 → mypy / pyright

### Q7: Python 协程和 Java 虚拟线程的对比？

| 维度 | Python asyncio | Java Virtual Threads |
|------|:---:|:---:|
| 调度 | 协作式 (await 释放) | 抢占式 (JVM 调度) |
| 语法 | `async/await` (显式) | 普通同步代码 (透明) |
| 最大并发 | 10,000+ | 1,000,000+ |
| CPU 密集 | 需要线程池 | 自动切换载体线程 |

## 核心要点回顾

- 装饰器 = Python 的头号面试题，闭包是前置知识
- 生成器 + 上下文管理器 = 资源管理两大神器
- GIL 是 Python 并发绕不开的话题
- 协程 > 线程 > 进程（I/O 密集场景优先级）
- 类型提示 + Pydantic = 用类型系统消灭运行时 bug
