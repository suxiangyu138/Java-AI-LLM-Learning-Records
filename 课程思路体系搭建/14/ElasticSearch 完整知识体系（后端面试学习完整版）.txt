ElasticSearch 完整知识体系（后端面试/学习完整版）
一、基础核心概念
1. 定位与底层
1. ES：基于Lucene的分布式全文检索引擎，Java开发，RESTful API
2. 适用场景：全文搜索、日志存储（ELK）、商品检索、指标分析、多维筛选
3. 不适合：海量事务、强一致性数据库、高频更新小文档
2. 核心名词
- 集群 Cluster：多节点组成，统一对外提供服务，集群名区分环境
- 节点 Node
- Master节点：管理分片、集群元数据（选举、扩容、分片分配）
- Data节点：存储分片数据，执行查询/写入
- Coordinating节点：接收请求、路由分发、结果聚合（所有节点默认兼任）
- Ingest节点：数据预处理（管道pipeline）
- 索引 Index：逻辑库，类比MySQL库，存放一类文档
- 类型 Type：ES7+彻底废弃，仅单类型  _doc 
- 文档 Document：单条数据，JSON格式，类比行记录，唯一标识 _id 
- 字段 Field：文档属性，类比字段，有类型映射mapping
- 分片 Shard
- 主分片 Primary Shard：写入主副本，数据唯一，创建索引后数量不可修改
- 副本分片 Replica Shard：主分片备份，提升容灾、读负载，可动态调整
- 规则：副本不能和对应主分片放同一节点；分片数 = 主分片*(副本+1)
3. 倒排索引（底层核心）
1. 正排索引：文档→字段（MySQL存储方式）
2. 倒排索引：词条Term→文档ID列表
3. 组成：
- Term词典：所有分词后的词条
- 倒排表：每个term对应的文档、词频、位置、偏移
4. 优化结构：FST（有限状态转换）压缩词典、DocValues（聚合排序专用）、FieldData
二、Mapping 字段映射
1. 核心字段类型
1. 字符串
-  text ：分词、支持检索，不支持聚合排序（分词存储倒排）
-  keyword ：不分词，精确匹配、聚合、分组、排序
2. 数值：long/integer/short/double/float
3. 日期：date，支持格式化  yyyy-MM-dd HH:mm:ss 
4. 布尔：boolean
5. 复合类型
- object：嵌套对象（扁平化存储，关联查询有缺陷）
- nested：嵌套数组对象，独立倒排，适合数组对象联合筛选
6. 特殊：geo地理、ip、range范围类型
2. 核心参数
-  analyzer ：分词器（standard/ik_smart/ik_max_word）
-  index: true/false ：是否构建倒排索引，false不可检索
-  doc_values: true ：开启聚合排序
-  store ：是否单独存储字段原始值
-  dynamic ：动态映射策略（true自动识别、strict严格报错、false忽略）
3. 动态映射 vs 手动Mapping
- 动态：新增字段自动推断类型，线上易出现类型错乱（数字识别为text）
- 生产规范：创建索引时手动定义Mapping，禁止自动动态映射
三、分词器 Analyzer
1. 分词器三组件
1. Character Filter：字符替换（去除html、特殊符号）
2. Tokenizer：切词（标准、空格、ik中文分词）
3. Token Filter：归一化（小写、去停用词、同义词）
2. 常用分词器
1. standard：默认，英文分词，中文单字拆分（不适合中文业务）
2. ik分词（必备）
- ik_max_word：细粒度拆分（查询用）
- ik_smart：粗粒度合并（索引存储用）
3. whitespace：按空格切分
4. pattern：正则分词
四、文档CRUD（REST API）
1. 写入
1. 单条PUT/POST
2. 批量 Bulk API（create/index/update/delete），性能核心
3. 写入流程：内存缓冲区→refresh生成segment→translog持久化→flush落盘segment→merge合并小segment
2. 读取
- GET /index/_doc/id 精准查询
- _search 检索
3. 更新&删除
- 更新：不会原地修改，标记旧文档删除，写入新文档
- 删除：仅标记墓碑，segment合并时才物理清除
五、检索 Query DSL（面试重点）
1. 两大查询分类
1. 查询上下文 query：算相关性打分_score，用于全文检索（match/match_all）
2. 过滤上下文 filter：不打分，缓存，精准筛选（term/range/exists）
2. 基础查询
1. match：分词模糊检索（text字段专用）
2. match_phrase：短语匹配，连续词条
3. term：精确匹配（keyword字段，不分词）
4. terms：多值精确匹配 in 查询
5. range：数值/日期范围筛选
6. exists：字段非空
7. bool 复合查询（核心）
- must：同时满足，算分
- filter：同时满足，无分，可缓存
- should：或条件，满足加分（minimum_should_match控制匹配数）
- must_not：排除条件，无分
3. 聚合 Aggs（统计分析）
1. 桶聚合 Bucket（分组）
- terms：按字段分组
- date_histogram：日期直方图（日志统计）
- range：区间分组
2. 指标聚合 Metric（计算）
- avg/sum/max/min/cardinality(去重计数)
3. 管道聚合：聚合结果二次计算
4. 排序、分页、高亮
- sort：支持多字段排序，text字段不可直接排序
- 分页：from+size（深度分页性能差）；深分页用 search_after / scroll
- highlight：关键词检索高亮返回
六、写入底层原理（面试高频）
1. 写入流程
1. 路由计算： shard = hash(_id) % 主分片数 ，定位主分片节点
2. 主分片执行写入，写内存缓冲区+translog事务日志
3. 同步副本分片，全部成功返回客户端ack
4. refresh（默认1s）：缓冲区数据生成segment，写入内存倒排索引，可检索
5. flush：translog清空，segment持久化磁盘
6. merge：后台合并大量小segment，删除标记文档物理清理
2. 关键机制
1. translog：宕机恢复数据，保证写入不丢失
2. refresh_interval：近实时搜索NRT，调大可提升写入性能
3. segment：不可变，只能新增、合并，不修改旧文件
七、集群分布式机制
1. 分片路由
路由公式固定，主分片创建后不能修改，否则数据无法查找
2. Master选举
基于Zen Discovery，节点配置 node.master:true 参与选举，过半节点投票当选
3. 分片分配策略
集群扩容/缩容自动迁移分片；可手动设置分配过滤、水位控制
4. 脑裂问题
旧版本隐患：集群网络断开，多节点各自选主
解决方案： discovery.zen.minimum_master_nodes = (总主节点数/2)+1 ，ES7自动优化
八、性能优化（生产核心）
写入优化
1. 批量bulk提交，单批500~1000条，控制单批大小<10MB
2. 增大refresh_interval（30s/60s），减少segment生成频率
3. 副本数调整：大批量导入时临时设0，导入完成恢复
4. 禁用动态mapping，提前建好索引mapping
5. 使用numeric类型，减少keyword存储开销
6. 服务器内存：堆内存-Xmx/-Xms统一设置，不超过物理内存50%，最大31G
查询优化
1. 精准filter过滤前置，减少打分计算
2. 避免深分页from过大，使用search_after
3. 聚合尽量使用keyword，禁用text聚合
4. 合理设置分片数：单分片数据控制10~30G
5. 开启doc_values，聚合提速
6. 不返回无用字段：_source过滤
集群优化
1. 节点角色分离：独立master、data、ingest节点
2. 磁盘水位：低水位停止分片分配，高水位只读保护
3. 定期清理无用索引，冷数据归档
九、高可用与容灾
1. 副本分片：节点宕机自动提升副本为主分片
2. translog持久化：断电丢失最多一个refresh周期数据
3. 快照snapshot：全量备份索引至对象存储/磁盘，用于灾难恢复
4. 跨机房集群：CCR跨集群复制，异地容灾
十、ELK技术栈配套
1. ElasticSearch：存储检索
2. Logstash：数据清洗、管道转换（资源消耗大）
3. Filebeat：轻量采集日志，替代logstash输入
4. Kibana：可视化、查询控制台、监控面板
5. Ingest Pipeline：ES内置预处理，替代轻量Logstash任务
十一、常见问题&面试考点
1. ES为什么近实时而非实时？refresh机制延迟
2. 为什么text不能排序聚合？无doc_values
3. 副本作用：容灾、分担读压力
4. 深度分页问题：from+size累加查询所有分片，海量数据OOM
5. scroll与search_after区别：scroll适合全量导出；search_after适合分页查询
6. 倒排索引优缺点：检索快，写入慢
7. nested和object区别：object数组会扁平化，关联查询错乱
8. 索引删除数据不会立即消失：segment不可变，仅墓碑标记，merge清理
9. ES事务支持：单文档原子性，多文档无分布式事务，靠业务补偿
