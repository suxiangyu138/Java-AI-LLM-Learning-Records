## 1. Embedding 的本质定义

**Embedding（嵌入）** 是将文字、图片、音频等非结构化数据转换为一串固定长度的数字向量。

| 维度 | 人类视角 | 机器视角 |
|------|----------|----------|
| 示例 | RabbitMQ 是消息队列 | [0.12, 0.35, -0.21, ...] |

> **重点**：语义越相似的内容，其向量距离越近。"猫"和"猫咪"的向量距离很近，而"猫"和"汽车"的向量距离很远。

---

## 2. 为什么需要 Embedding

大模型本身无法直接计算文本间的语义相似度。传统方法依赖关键词匹配（如 MySQL、Elasticsearch 的全文搜索），只能做到字面匹配，无法理解语义。

Embedding 的三大核心用途：

1. **RAG 必备**：文档切片后向量化，存入向量数据库用于检索增强生成
2. **语义检索**：支持同义词、近义词、相关内容的模糊匹配
3. **内容分类、聚类与推荐**：基于文本相似度进行分组和排序

---

## 3. 底层原理

Embedding 的生成过程可概括为四个步骤：

1. **预训练 Embedding 模型**：在海量文本上学习语义映射关系
2. **输入编码**：将输入文本通过模型进行压缩和映射
3. **向量输出**：生成高密度浮点向量（如 768 维、1024 维）
4. **距离计算**：使用数学公式度量向量间相似度

常用的相似度度量方法：

- **余弦相似度**：最常用，计算向量夹角的余弦值
- **欧氏距离**：计算向量在空间中的直线距离
- **内积**：向量点积，值越大表示越相似

> **重点**：距离越小（余弦相似度越大）表示语义越相似。

## 4. 主流 Embedding 模型分类

### 4.1 开源本地模型（免费、离线）

| 模型 | 特点 | 部署方式 |
|------|------|----------|
| **Qwen-Embedding** | 阿里通义出品，中文优化 | Ollama / 本地 Python |
| **BGE-M3** | 国内最强开源全能嵌入模型，多语言支持 | Ollama / 本地 Python |
| **Sentence-BERT** | 经典老牌模型，社区生态成熟 | 本地 Python |

### 4.2 云端 API 模型（付费、精度高）

- **OpenAI text-embedding-3**：商业模型，效果好，1536 维
- **阿里云百炼 Embedding**：中文场景优化
- **智谱 GLM Embedding**：中文场景优化

### 4.3 多模态 Embedding

将文字和图片同时转换为向量，支持图文交叉检索场景。

## 5. 关键参数

| 参数 | 说明 | 注意事项 |
|------|------|----------|
| **向量维度 (dim)** | 768、1024、2048 等 | 维度越高语义表达能力越强，但存储和计算开销也越大 |
| **归一化 (Normalize)** | 将向量压缩到固定范围 | RAG 场景必须开启，可提升检索精度 |
| **批次嵌入 (Batch)** | 一次性批量处理多个文本切片 | 可大幅提升处理速度 |

---

## 6. Embedding 与 RAG 完整链路

```
原始文档
→ 文本切块 (Chunk)
→ Embedding 模型生成向量
→ 向量存入 Milvus / Chroma
————————————
用户问题
→ 问题同样进行 Embedding
→ 向量库相似度检索
→ 取出相似原文
→ 拼接上下文给大模型
→ 输出答案
```

> **重点**：没有 Embedding，就没有 RAG。

## 7. 三种调用方式

### 7.1 本地 Ollama 一键调用

最简单的方式，一条命令拉取嵌入模型：

```bash
ollama pull bge-m3
```

无需复杂配置，完全离线运行。

### 7.2 LangChain 一行接入

```python
from langchain_community.embeddings import OllamaEmbeddings

embeddings = OllamaEmbeddings(model="bge-m3")
vec = embeddings.embed_query("解释 Docker")
```

### 7.3 云端 API 调用

```python
from openai import OpenAI

client = OpenAI(api_key="sk-xxx")

def get_embedding(text, model="text-embedding-3-small"):
    text = text.replace("\n", " ")
    return client.embeddings.create(
        input=[text], model=model
    ).data[0].embedding
```

## 8. 易混概念区分

| 对比维度 | LLM 大模型 | Embedding 模型 |
|----------|-----------|----------------|
| 职责 | 聊天、推理、写代码、生成文字 | 只负责转向量，不聊天、不生成内容 |
| 输出 | 自然语言文本 | 浮点数向量 |

| 对比维度 | 关键词检索 | 向量检索 |
|----------|-----------|----------|
| 匹配方式 | 字面必须对上 | 语义对上即可 |
| 灵活性 | 死板，无法处理同义词 | 智能，可理解近义表达 |

## 9. 生产级最佳实践

1. **国内项目优先选择 BGE-M3 或 Qwen-Embedding**
2. **向量必须归一化**，否则相似度计算结果不准确
3. **长文档先切片，再 Embedding**，切片长度需匹配模型上下文窗口
4. **混合检索**：关键词检索 + 向量检索一起使用，效果最佳
5. **向量库与 Embedding 模型必须配套**，不同模型的向量分布不一致，不能跨模型混用

---

## 10. 核心要点回顾

- Embedding 的本质是将文字转换为数值向量，使机器能够理解语义相似度
- 核心逻辑：语义越相似的内容，向量距离越近
- LLM 负责生成内容，Embedding 负责语义检索
- RAG 四件套：文本切块 + Embedding 模型 + 向量数据库 + 大模型
- 本地场景推荐 BGE-M3，云端场景推荐厂商官方接口
