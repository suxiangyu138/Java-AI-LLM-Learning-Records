## 1. 核心基础

### 1.1 定义

**Prompt Engineering（提示工程）** 是系统性设计、优化、迭代提示词（Prompt）的方法论与实操技术，核心是通过结构化的自然语言输入，引导生成式 AI（GenAI）模型产出符合预期的输出。本质是弥合人类自然语言表达与 AI 模型认知逻辑之间的差异，让模型从"随机生成"转变为"精准执行"。

> **重点**：牛津英语词典将 Prompt Engineering 定义为"为人工智能程序、算法等制定和优化提示，以优化其输出或实现预期结果的行为或过程"。

### 1.2 核心价值

| 价值 | 说明 |
|------|------|
| **提升模型效能** | 优质提示让 AI 输出更准确、专业，甚至接近人类专家水平 |
| **增强输出可控性** | 规范输出的风格、结构和边界，适合标准化结果场景 |
| **降低使用门槛** | 无需编程基础，非技术人员也能发挥模型价值 |
| **规避模型缺陷** | 减少 AI"幻觉"和逻辑混乱，在敏感领域降低风险 |

### 1.3 Prompt Engineering 与相关领域的区别

| 领域 | 聚焦 | 关系 |
|------|------|------|
| **Prompt Engineering** | 输入指令的优化 | 核心方法论 |
| **Context Engineering** | 非提示类上下文的组织 | 与 Prompt Engineering 互补 |
| **模型微调** | 修改模型参数 | 比 Prompt Engineering 更重、成本更高 |

## 2. Prompt 的核心构成要素

### 2.1 必备核心要素

| 要素 | 说明 | 示例 |
|------|------|------|
| **角色指令（Role）** | 设定身份，锚定思考视角和专业调性 | "资深数据分析师""专业翻译官" |
| **核心任务（Task）** | 具体、无歧义的动作描述 | "总结文章核心观点""用 Java 写登录功能" |
| **上下文背景（Context）** | 任务相关的背景信息和参考资料 | 受众、场景、参考文本、数据范围 |

### 2.2 优化进阶要素

| 要素 | 说明 | 示例 |
|------|------|------|
| **输出约束（Constraints）** | 限定边界条件 | 字数限制、语言风格、禁忌内容 |
| **输出格式（Format）** | 指定排版方式 | 分点、表格、Markdown、JSON |
| **示例参考（Example）** | 1-3 个标准答案样本 | Few-Shot 学习的核心 |
| **思考引导（Think）** | 引导分步拆解问题 | "请分步思考""列出推理过程" |

### 2.3 标准 Prompt 结构化模板

> 【角色设定】请你扮演 XX 专业角色，具备 XX 资质/经验，擅长 XX 风格，遵循 XX 规则；
> 【背景信息】本次任务的场景、目的、参考资料：XX；
> 【核心任务】请完成 XX 具体任务，核心目标是 XX；
> 【约束条件】字数、风格、禁忌、专业度等要求：XX；
> 【输出格式】请按照 XX 结构/排版输出；
> 【示例/思考】参考示例：XX；请分步思考/先分析后结论。

## 3. Prompt Engineering 核心原则

| 原则 | 说明 | 核心要求 |
|------|------|----------|
| **清晰性原则** | 拒绝抽象歧义表述 | 用具体词汇替代模糊词汇 |
| **完整性原则** | 补齐所有必要信息 | 角色、任务、背景、约束形成闭环 |
| **简洁性原则** | 剔除无关冗余信息 | Prompt 并非越长越好 |
| **针对性原则** | 根据模型特性和任务类型调整 | 创作类重风格，推理类重步骤 |
| **可迭代原则** | 通过输出反向优化指令 | 形成"初版生成->复盘->优化->验证"闭环 |
| **工具辅助原则** | 善用外部工具增强模型能力 | RAG、计算器、分隔符辅助 |

## 4. 核心提示技巧

### 4.1 基础实用技巧（入门必学）

| 技巧 | 说明 | 示例 |
|------|------|------|
| **角色扮演设定** | 细化角色身份、资质和风格 | "10 年临床经验的内科医生" |
| **结构化输入分隔** | 用分隔符区分指令和输入 | 三引号、XML 标签、章节标题 |
| **任务步骤拆解** | 复杂任务分解为多步子任务 | 1.识别问题 2.检索信息 3.构建答案 |
| **输出格式控制** | 明确指定结构和长度 | "用两个段落总结，第一段..."
| **温度参数调控** | 控制随机性 | 低温(0-0.3)严谨，高温(0.8-1)创意 |

### 4.2 进阶推理技巧

| 技巧 | 说明 | 适用场景 |
|------|------|----------|
| **零样本提示（Zero-Shot）** | 无需示例，直接凭模型训练经验完成任务 | 翻译、基础总结、简单问答 |
| **少样本提示（Few-Shot）** | 提供 1-3 个输入输出示例 | 文本分类、信息提取、话术撰写 |
| **链式思考（CoT）** | 引导分步展示推理过程 | 数学计算、逻辑分析、方案策划 |
| **查漏补缺机制** | 多轮查询确保信息完整性 | 长文档处理、复杂信息提取 |

### 4.3 高阶拓展技巧

| 技巧 | 说明 | 适用场景 |
|------|------|----------|
| **树状思维（Tree-of-Thought）** | 从多个角度探索解决方案 | 创意生成、多维度分析 |
| **提示链（Prompt Chaining）** | 前后提示串联形成工作流 | 长流程任务（总结->提取->分析） |
| **反向约束技巧** | 明确"不要做什么" | 精准规避无效内容 |
| **自一致性提示** | 多次生成择优选择 | 科研数据整理、法律文书 |
| **多模态提示技巧** | 针对文本-图像、文本-音频优化 | 图像生成、音频生成 |

## 5. 常见应用场景

### 5.1 语言与文本生成

| 场景 | 技巧 | 示例 |
|------|------|------|
| 创意写作 | 明确题材和风格 | "写一篇科幻短篇，围绕'记忆与科技'" |
| 摘要提取 | 指定长度和重点 | "用 300 字总结，重点突出方法和结论" |
| 语言翻译 | 标注语境和风格 | "翻译成日语，保持正式礼貌的语气" |
| 对话模拟 | 设定角色和场景 | "你是宠物医生，解答猫咪呕吐原因" |
| 文案润色 | 明确修改方向 | "修改得更口语化，适合短视频旁白" |

### 5.2 代码生成与优化

| 场景 | 说明 |
|------|------|
| 代码补全 | 提供部分代码，说明功能需求 |
| 跨语言转换 | 保持逻辑的跨语言迁移 |
| 代码优化 | 明确改进目标（性能、可读性） |
| 查错调试 | 附上问题代码，让 AI 分析并修改 |

### 5.3 多模态生成

- **文本-图像**：详细描述主题、风格、布局和灯光
- **文本-音频**：明确曲风、节奏、采样类型

## 6. 常见误区与避坑指南

| 误区 | 说明 | 正确做法 |
|------|------|----------|
| **Prompt 越长越好** | 冗余信息干扰判断 | 精准传递核心需求 |
| **忽略角色设定** | 无身份的输出泛泛而谈 | 设定基础角色提升贴合度 |
| **依赖零样本处理复杂任务** | 逻辑混乱、格式不符 | 搭配少样本或思维链 |
| **不做格式约束** | 输出杂乱无章 | 明确格式要求 |
| **一套 Prompt 适配所有模型** | 模型认知逻辑不同 | 根据模型特性微调 |
| **忽视 Prompt 注入风险** | 恶意输入操控模型行为 | 过滤可疑输入 |

## 7. 学习与实践方法

### 7.1 学习路径

| 阶段 | 目标 | 核心内容 |
|------|------|----------|
| **基础阶段** | 写出清晰完整的基础 Prompt | 核心要素和六大原则 |
| **进阶阶段** | 针对不同任务设计专属 Prompt | Zero-Shot、Few-Shot、CoT 等技巧 |
| **高阶阶段** | 应对复杂场景，规避安全风险 | 模板库搭建、迭代优化 |

### 7.2 实践技巧

1. 从小任务入手，逐步过渡到复杂推理
2. 建立模板库，将常用场景的优质 Prompt 整理归档
3. 注重迭代复盘，标注缺陷并针对性优化
4. 关注行业动态，适配新模型特性

## 9. 核心要点回顾

- Prompt Engineering 是系统性设计提示词的方法论，无需修改模型参数即可提升输出质量
- 标准 Prompt 由角色、任务、背景、约束、格式和示例六大要素组成
- 六大核心原则：清晰、完整、简洁、针对、可迭代、工具辅助
- 基础技巧包括角色设定和输出格式控制，高阶技巧包括 Tree-of-Thought 和 Prompt Chaining
- CoT 是提升复杂推理任务准确率的关键技术
- 避免常见误区：Prompt 越长越好、忽略角色设定、依赖零样本处理复杂任务
