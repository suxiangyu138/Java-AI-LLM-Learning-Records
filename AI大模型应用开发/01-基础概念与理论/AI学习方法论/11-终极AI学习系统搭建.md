## 1. 系统设计目标

构建一个无缝嵌入编码流程的 AI 辅助系统，遵循以下设计原则：

- **低侵入性**：AI 在需要时自然出现，不需要时安静退场，不打断思维流
- **全流程覆盖**：覆盖编码、调试、重构、测试生成、知识沉淀等完整开发周期
- **跨设备协同**：主力编码设备与移动设备数据统一，碎片时间也可学习
- **自动化沉淀**：学习记录通过 Git 自动提交，确保知识积累不丢失

## 2. 开发环境配置

### 2.1 插件安装

**方案 A（推荐）：使用 Cursor IDE**

**Cursor** 基于 VSCode 内核构建，从官网下载安装后即可使用全部 AI 功能。

**方案 B：VSCode + GitHub Copilot**

```bash
# 安装 GitHub Copilot 代码补全插件
code --install-extension GitHub.copilot

# 安装 GitHub Copilot Chat 对话插件
code --install-extension GitHub.copilot-chat
```

**GitHub Copilot** 提供行内代码补全，**GitHub Copilot Chat** 提供侧边栏对话交互，二者配合覆盖大部分 AI 辅助场景。

### 2.2 快捷键绑定

**Cursor 核心快捷键**

| 快捷键 | 功能 | 适用场景 |
|--------|------|----------|
| `Ctrl+K` | AI 编辑 | 选中代码后输入需求，AI 直接生成修改 |
| `Ctrl+L` | AI 对话 | 侧边栏聊天，适合追问、解释、调试 |
| `Ctrl+I` | Composer（多文件编辑） | 跨文件重构、批量生成 |
| `Ctrl+Shift+I` | AI 解释代码 | 快速理解选中代码片段 |
| `Ctrl+K Ctrl+S` | 查看所有快捷键 | 快捷键管理 |

**建议自定义快捷键**

| 自定义绑定 | 功能 | 说明 |
|-----------|------|------|
| `Alt+Shift+R` | 重构选中代码 | 一键触发 AI 重构 |
| `Alt+Shift+E` | 解释选中代码 | 快速获取代码说明 |
| `Alt+Shift+T` | 生成单元测试 | 为选中方法生成测试用例 |

> **注意**：VSCode 用户需在 `keybindings.json` 中手动添加上述自定义绑定。

## 3. Cursor 工作流详解

### 3.1 编码流程

采用"注释驱动开发"模式，通过自然语言描述需求，让 AI 快速生成代码骨架：

1. **新建文件，写入功能描述注释**
   ```java
   // 实现用户登录接口：
   // - POST /api/login 接收 username + password
   // - 验证通过返回 JWT token
   // - 验证失败返回 401
   ```

2. **选中注释，触发 AI 生成**
   - 按 `Ctrl+K` 选中注释，输入"实现这个登录接口"
   - AI 生成完整代码，包含 Controller、Service、异常处理等

3. **审查并修正生成代码**
   - 移除不必要的 `try-catch` 包装
   - 替换密码加密方式为项目实际使用的算法
   - 补充业务日志记录

4. **进一步优化**
   - 选中方法体，按 `Ctrl+K` 输入"优化这段代码的可读性"
   - AI 建议变量重命名、提取方法、添加注释等改进

### 3.2 调试流程

采用 **ADR 循环（AI -> Debug -> Redo）** 模式快速解决异常：

1. **粘贴错误信息**
   - 按 `Ctrl+L` 打开 AI 对话
   - 粘贴报错堆栈，输入"这个错误是什么原因？怎么修复？"

2. **应用 AI 建议**
   - AI 分析根因并提供修复方案
   - 点击 **Apply** 按钮，AI 自动修改代码

3. **迭代验证**
   - 若修复未生效，粘贴新的错误信息
   - 补充说明："上次的修改没有解决，新的错误是...请重新诊断"

> **重点**：调试时提供完整的错误上下文（堆栈 + 相关代码片段），AI 的诊断准确率将大幅提升。

### 3.3 重构流程

利用 **Composer（Ctrl+I）** 进行跨文件、大规模重构：

1. **选中目标文件或代码段**
2. **按 `Ctrl+I` 打开 Composer，输入重构需求**
   ```text
   重构这个类：
   - 提取公共逻辑到 private 方法
   - 将 if-else 改为策略模式
   - 给所有 public 方法添加参数校验
   ```

3. **对比并审阅改动**
   - Composer 在侧边栏生成新版本代码
   - 逐块对比原文件与 AI 修改
   - 逐个接受或拒绝每个改动

> **注意**：对于**策略模式**等结构性重构，建议先在注释中画好类关系草图，再输入 Composer，生成质量更高。

### 3.4 单元测试生成

1. **打开目标 Service 类**
2. **按 `Ctrl+I` 输入测试生成指令**
   ```text
   为 UserService 的所有 public 方法生成单元测试：
   - 使用 JUnit 5 + Mockito
   - 覆盖正常路径 + 异常路径 + 边界条件
   - Mock 所有外部依赖（Repository / RedisTemplate）
   ```

3. **审查并补充**
   - AI 自动生成测试代码，包含 Mock 初始化、测试方法、断言
   - 开发者需补充业务特有的边界条件（如特定枚举值、时间边界）

> **重点**：AI 生成的测试覆盖常规路径质量较高，但业务特有的边界条件和异常组合仍需人工补充。建议将覆盖率工具（如 **JaCoCo**）集成到 CI 流程中量化测试质量。

## 4. 终端 AI 快捷命令

在 shell 配置文件中添加以下快捷命令，将 AI 能力延伸到终端：

### Bash / Zsh（~/.bashrc 或 ~/.zshrc）

```bash
# 快速在 Cursor 中打开当前项目
alias ai="cursor"

# 用 AI 解释代码文件
alias explain="cursor --explain"

# 用 AI 重构代码文件
alias refactor="cursor --refactor"

# 解释上一个终端命令的错误输出
function explain-error() {
    local last_error=$(fc -ln -1 2>&1)
    echo "解释以下命令的错误：" > /tmp/ai-query.txt
    echo "$last_error" >> /tmp/ai-query.txt
    cat /tmp/ai-query.txt | pbcopy  # macOS: 复制到剪贴板
    echo "错误已复制，粘贴到 Cursor Chat (Ctrl+L)"
}
```

### PowerShell（$PROFILE）

```powershell
function Invoke-AI { cursor @args }
Set-Alias -Name ai -Value Invoke-AI

function Explain-Error {
    $lastError = $error[0] | Out-String
    $lastError | Set-Clipboard
    Write-Host "错误已复制到剪贴板，粘贴到 Cursor Chat (Ctrl+L)"
}
```

> **重点**：将 `explain-error` 绑定到常用快捷键（如 `Ctrl+Alt+E`），可在终端报错后一键复制错误信息并切换至 AI 对话，大幅缩短调试循环。

## 5. 多设备协同方案

### 5.1 设备分工

| 设备 | 用途 | 核心工具 | AI 集成 |
|------|------|----------|---------|
| 笔记本 / 台式机 | 主力编码 + 深度学习 | VSCode / Cursor + ChatGPT | 全流程 |
| 手机 | 碎片时间学习 + 紧急查资料 | **Perplexity** + ChatGPT App | 快速问答 |
| 平板 | 笔记整理 + 算法手绘 | Notability + AI 思维导图 | 知识整理 |

### 5.2 笔记同步方案

采用 **Obsidian + Git + GitHub** 三件套实现笔记跨设备无缝同步。

**架构说明**

```text
本地 (Obsidian)  -->  Git 仓库  -->  GitHub 远程  -->  拉取到其他设备
```

**操作流程**

1. 本地使用 **Obsidian** 管理所有 Markdown 格式的学习笔记
2. 笔记库即当前 Git 仓库（`D:/本地学习项目/Java-AI-LLM-Learning-Records`）
3. AI 生成的回答内容直接保存为 `.md` 文件到对应目录
4. 执行 `git commit + push` 推送至 GitHub
5. 其他设备通过 `git pull` 拉取同步

> **重点**：纯文本 Markdown + Git 版本控制 = 最可靠的个人知识管理体系。优势包括跨平台兼容、历史版本可追溯、AI 可直接读写笔记库文件。

## 6. Git 自动化：学习记录沉淀

### 6.1 每日自动提交脚本

在项目根目录创建自动提交脚本，结合操作系统计划任务实现每日定时同步。

```bash
#!/bin/bash
# auto_commit.sh —— 每日学习记录自动提交脚本
# 用途：定时扫描笔记变更，自动 commit 并 push

cd D:/本地学习项目/Java-AI-LLM-Learning-Records

# 拉取远程最新更改，避免冲突
git pull --rebase

# 暂存所有学习笔记目录
git add "06-AI与大模型/" "01-JavaSE/" "03-Spring生态/" "leetcode/"

# 如有变更则提交并推送
if ! git diff --cached --quiet; then
    git commit -m "daily learning update: $(date +%Y-%m-%d)"
    git push
else
    echo "今日无新增变更，跳过提交。"
fi
```

### 6.2 定时任务配置

| 操作系统 | 工具 | 配置方式 |
|----------|------|----------|
| Windows | 任务计划程序（Task Scheduler） | 创建每日 23:00 触发的任务，执行 `auto_commit.sh` |
| macOS / Linux | crontab | `0 23 * * * /path/to/auto_commit.sh` |

> **注意**：首次运行前请确保 SSH Key 已配置且 GitHub 远程仓库可正常访问。建议先手动执行一次脚本验证流程完整性。

## 7. 终端推荐

### Windows 环境

推荐组合：**Windows Terminal** + **Oh My Posh** + **JetBrains Mono**

```text
Windows Terminal 配置要点：
- Oh My Posh：PowerShell 主题引擎，自定义提示符样式
- JetBrains Mono 字体：等宽字体，支持编程连字（Ligatures）
- 半透明背景：减少视觉疲劳，便于叠加参考文档
- 分屏布局：左侧代码编辑，右侧终端运行测试
- AI 配合：在终端旁常驻 Cursor Chat 窗格
```

**推荐窗口布局**

```text
┌──────────────────┬──────────────────┐
│  代码编辑区域     │  终端窗口        │
│  (VSCode/Cursor)  │  - 运行测试       │
│                   │  - Git 操作       │
│                   │  - 构建部署       │
├──────────────────┼──────────────────┤
│  Cursor Chat      │  文档 / 预览     │
│  (AI 对话)        │  (参考资源)       │
└──────────────────┴──────────────────┘
```

### macOS 环境

推荐使用 **Warp** 终端，其原生支持 AI 功能（AI Command Search、自然语言转命令），可与 Cursor 配合形成全 AI 工作流。

## 8. 核心要点回顾

- 使用 **Cursor IDE** 可获得开箱即用的 AI 编码体验，无需额外插件配置
- 掌握 **Ctrl+K（编辑）、Ctrl+L（对话）、Ctrl+I（Composer）** 三大核心快捷键，覆盖编码、调试、重构全流程
- AI 调试遵循 **ADR 循环（AI -> Debug -> Redo）**：粘贴错误、应用修复、迭代验证
- 单元测试生成后务必补充业务特有的边界条件，不可完全信赖 AI 输出
- 使用 **Obsidian + Git + GitHub** 构建纯文本笔记管理体系，支持跨设备同步与版本回溯
- 配置 **每日自动提交脚本** + 操作系统计划任务，确保学习记录持久化不丢失
