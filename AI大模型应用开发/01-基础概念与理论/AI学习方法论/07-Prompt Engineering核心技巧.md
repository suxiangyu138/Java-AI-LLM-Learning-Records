# Prompt Engineering 核心技巧 —— 提问质量决定学习效率

## 提问效率公式

```
AI 输出质量 = 角色设定 × 结构化约束 × 示例引导 × 迭代深度
```

四个因子缺一不可。差提问得到的是百度百科级别答案，好提问得到的是架构师级别指导。

---

## 技巧 1：角色扮演 + 结构化输出

### 原理

AI 的输出质量取决于它"以为"自己的身份。不给角色 = 默认"普通聊天机器人"，给角色 = 模拟该角色的知识结构和表达方式。

### 差 vs 好

```
❌ 差提问："怎么学 Redis？"
→ 得到：Redis 是 key-value 数据库...（百度百科级别）

✅ 好提问：
"你是阿里 P8 架构师，我是 Java 初学者。请用以下结构教我 Redis：
1. 核心价值：为什么用 Redis 而不是 MySQL（50 字）
2. 5 大数据结构使用场景（表格，含时间复杂度）
3. 持久化方案对比：RDB vs AOF（表格，≥8 行）
4. 缓存三大问题：穿透/击穿/雪崩（各附解决方案）
5. 实战项目：用 Redis 实现分布式锁（完整可运行代码）
输出格式：Markdown，代码无注释"
```

### 角色库

| 场景 | 推荐角色 | 为什么 |
|------|---------|--------|
| 学框架原理 | 核心贡献者 / 资深架构师 | 了解设计意图 |
| 面试准备 | 大厂面试官 | 知道考点和追问方向 |
| 代码审查 | 安全专家 + 性能专家 | 多维度发现问题 |
| 技术选型 | CTO / 技术负责人 | 考虑维护成本和团队能力 |
| 写简历 | HR 总监 + 技术面试官 | 兼顾过筛和面试两关 |

## 技巧 2：提供示例引导输出格式

### 原理

AI 是模式匹配器。你给它一个示例，它就理解了你想要的输出结构、语气、深度。

### 实战：生成简历项目描述

```
我的简历需要项目描述，参考以下格式：

【示例】
"采用 Redis 缓存热点数据，接口响应时间从 800ms 降至 120ms，QPS 提升 300%"

我的项目：苍穹外卖系统
技术栈：Spring Boot + MyBatis + Redis + JWT
请生成 3 条类似格式的项目亮点：
- 数据量化（从 X 到 Y）
- 明确技术栈
- 一条不超过 40 字
```

### 为什么有效

- 示例 = 输出格式的精确约束
- AI 不需要猜测你要什么风格
- 减少无效往返，一次性得到想要的结果

## 技巧 3：迭代追问法 —— 拒绝浅层答案

### 原理

AI 默认输出"够用"级别的答案（相当于百度百科前 3 条的综合）。每次追问强迫它深入一层，相当于把回答从 L1 提升到 L4。

### 4 层追问实战

```
第 1 轮（L1 概念层）：
"解释 JVM 垃圾回收机制"
→ AI：标记-清除、复制、标记-整理三种算法

第 2 轮（L2 对比层）：
"CMS 和 G1 收集器的核心区别是什么？用表格对比"
→ AI：表格列出 10+ 项区别

第 3 轮（L3 原理层）：
"为什么 G1 适合大堆内存？从底层 Region 设计和 
 Remembered Set 机制解释"
→ AI：解释 Region 划分、RSet 维护、SATB 算法

第 4 轮（L4 实战层）：
"给我一个真实生产环境 G1 调优案例：
 场景、问题现象、排查过程、参数调优、验证方法"
→ AI：结合真实场景的完整调优方案
```

### 追问信号词

| 信号词 | 效果 |
|--------|------|
| "为什么这样设计？" | 触及架构权衡 |
| "有什么例外情况？" | 发现边界条件 |
| "如果 X 条件改变会怎样？" | 理解前提假设 |
| "这是最优解吗？" | 触发 AI 重新评估 |
| "给我一个反例" | 理解什么情况下不适用 |

## 技巧 4：多 AI 对抗验证法（黄仁勋秘诀）

### 流程

```
第 1 轮：AI-A 生成方案
→ ChatGPT："用 Redis 实现分布式锁应该用 SETNX + Expire"

第 2 轮：AI-B 审查漏洞  
→ Claude："上述方案有什么致命漏洞？"
→ Claude："SETNX 和 Expire 非原子操作，中间崩溃会死锁"

第 3 轮：AI-A 修复
→ ChatGPT："如何解决非原子操作问题？"
→ ChatGPT："用 Lua 脚本保证原子性，或使用 SET NX EX 原子命令"

第 4 轮：交叉验证
→ Perplexity："Redis 分布式锁 2026 最新最佳实践"
→ 确认方案是否与社区最新实践一致
```

### 价值

- 避免单一 AI 幻觉——一个 AI 出错时另一个可能发现
- 获得经过批判验证的方案——不是"AI 说的"，而是"经过审查的"
- 训练自己的批判性思维——看两个 AI 互审的过程，自己也会学会质疑

## 五大常见 Prompt 错误

| 错误 | 为什么错 | 正确做法 |
|------|---------|---------|
| "解释一下 Spring" | 范围太宽，AI 瞎猜 | 指定角色 + 结构 + 深度 |
| "给我最好的方案" | 没有"最好"，只有"最适合" | 说明约束条件（性能/复杂度/时间） |
| 只问一轮就结束 | 停留在浅层 | 追问 3 轮以上 |
| 只用 1 个 AI | 幻觉风险 | 至少 2 个 AI 交叉验证 |
| 不提背景直接问 | AI 不知道你的水平 | 说明自己的技术栈和水平 |
