## 2. Prometheus + Grafana 监控

### 2.1 核心指标定义

```java
@Component
public class AiMetrics {

    private final MeterRegistry registry;

    // 请求计数器
    private final Counter requestCounter;
    private final Counter errorCounter;
    private final Counter tokenCounter;

    // 延迟计时器
    private final Timer requestLatency;
    private final Timer ttftLatency;        // Time to First Token
    private final Timer retrievalLatency;  // RAG 检索延迟

    // 分布摘要
    private final DistributionSummary tokensPerRequest;

    public AiMetrics(MeterRegistry registry) {
        this.registry = registry;

        this.requestCounter = Counter.builder("ai.requests.total")
            .description("AI 请求总数")
            .tag("app", "ai-platform")
            .register(registry);

        this.errorCounter = Counter.builder("ai.errors.total")
            .description("AI 请求错误数")
            .register(registry);

        this.tokenCounter = Counter.builder("ai.tokens.total")
            .description("Token 消耗总数")
            .register(registry);

        this.requestLatency = Timer.builder("ai.request.latency")
            .description("AI 请求端到端延迟")
            .publishPercentiles(0.5, 0.95, 0.99)
            .register(registry);

        this.ttftLatency = Timer.builder("ai.ttft.latency")
            .description("首 Token 延迟")
            .publishPercentiles(0.5, 0.95, 0.99)
            .register(registry);

        this.retrievalLatency = Timer.builder("ai.retrieval.latency")
            .description("RAG 检索延迟")
            .register(registry);

        this.tokensPerRequest = DistributionSummary.builder("ai.tokens.per_request")
            .description("每次请求的 Token 数")
            .publishPercentiles(0.5, 0.95, 0.99)
            .register(registry);
    }

    // 使用示例
    public <T> T recordRequest(String model, String endpoint, Supplier<T> call) {
        requestCounter.increment();
        Timer.Sample sample = Timer.start(registry);

        try {
            T result = call.get();
            return result;
        } catch (Exception e) {
            errorCounter.increment();
            throw e;
        } finally {
            sample.stop(requestLatency);
        }
    }
}
```

## 3. 告警规则

### 3.1 Prometheus 告警规则

```yaml
# ai-alerts.yml
groups:
  - name: ai_application
    rules:
      # 错误率告警
      - alert: HighErrorRate
        expr: rate(ai_errors_total[5m]) / rate(ai_requests_total[5m]) > 0.05
        for: 5m
        labels:
          severity: critical
        annotations:
          summary: "AI 请求错误率超过 5%"
          description: "当前错误率 {{ $value | humanizePercentage }}"

      # P95 延迟告警
      - alert: HighLatency
        expr: histogram_quantile(0.95, rate(ai_request_latency_bucket[5m])) > 10
        for: 10m
        labels:
          severity: warning
        annotations:
          summary: "AI 请求 P95 延迟超过 10 秒"

      # Token 用量异常
      - alert: TokenSpike
        expr: rate(ai_tokens_total[15m]) > 100000
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "Token 消耗异常增长"

      # 模型不可用
      - alert: ModelDown
        expr: ai_model_health == 0
        for: 2m
        labels:
          severity: critical
        annotations:
          summary: "模型 {{ $labels.model }} 不可用"

      # 成本超预算
      - alert: BudgetExceeded
        expr: ai_daily_cost > 100
        for: 1m
        labels:
          severity: critical
        annotations:
          summary: "日 AI 成本超过 $100 预算"
```

## 4. SLO / SLA 定义

### 4.1 AI 应用 SLO

```yaml
# AI 应用服务水平目标 (SLO)

可用性:
  目标: 99.9% (每月 downtime < 43min)
  口径: 成功请求数 / 总请求数
  排除: 用户主动取消、超配额拒绝

延迟:
  目标: P95 < 3s (端到端，含 LLM 推理)
  口径: 从请求到完整回复的时间
  TTFT: P95 < 500ms (首 Token 时间)

准确性:
  目标: 事实准确率 > 90% (对于 RAG 场景)
  口径: 人工标注抽样评估

安全性:
  目标: 有害内容拦截率 > 99.5%
  口径: 内容审核发现的有害内容比例

成本:
  目标: 月成本偏差 < 预算的 10%
```

### 4.2 SLO 监控实现

```java
@Component
public class SloMonitor {

    private final MeterRegistry registry;
    private final Counter sloViolations;

    public boolean checkAvailabilitySLO() {
        // SLO: 99.9% 可用性
        double errorRate = getErrorRate5Min();
        if (errorRate > 0.001) {  // 超过 0.1%
            sloViolations.increment();
            return false;
        }
        return true;
    }

    public boolean checkLatencySLO() {
        // SLO: P95 < 3s
        double p95 = getP95Latency5Min();
        if (p95 > 3000) {
            sloViolations.increment();
            return false;
        }
        return true;
    }

    /**
     * 计算 Error Budget 剩余
     */
    public double getErrorBudgetRemaining() {
        // 月度 SLO: 99.9%
        // Error Budget = 总请求 × (1 - 0.999)
        long totalRequests = getMonthlyRequestCount();
        long allowedErrors = (long) (totalRequests * 0.001);
        long actualErrors = getMonthlyErrorCount();
        return Math.max(0, 1.0 - (double) actualErrors / allowedErrors);
    }
}
```

## 5. 成本分析面板

### 5.1 成本统计 SQL

```sql
-- 按模型统计日成本
SELECT
    model,
    DATE(created_at) as date,
    SUM(input_tokens) as total_input_tokens,
    SUM(output_tokens) as total_output_tokens,
    SUM(input_tokens * 0.0000025 + output_tokens * 0.00001) as estimated_cost_usd
FROM ai_usage_logs
WHERE created_at >= DATE_SUB(NOW(), INTERVAL 30 DAY)
GROUP BY model, DATE(created_at)
ORDER BY date DESC, estimated_cost_usd DESC;

-- 按用户统计月成本
SELECT
    u.username,
    u.department,
    SUM(l.input_tokens) as tokens,
    SUM(l.input_tokens * 0.0000025 + l.output_tokens * 0.00001) as cost
FROM ai_usage_logs l
JOIN users u ON l.user_id = u.id
WHERE l.created_at >= DATE_FORMAT(NOW(), '%Y-%m-01')
GROUP BY u.id
ORDER BY cost DESC;

-- 缓存节省统计
SELECT
    DATE(created_at) as date,
    SUM(CASE WHEN cache_hit THEN output_tokens ELSE 0 END) as cached_tokens,
    COUNT(CASE WHEN cache_hit THEN 1 END) as cache_hits,
    COUNT(*) as total,
    ROUND(COUNT(CASE WHEN cache_hit THEN 1 END) * 100.0 / COUNT(*), 1) as hit_rate
FROM ai_usage_logs
WHERE created_at >= DATE_SUB(NOW(), INTERVAL 7 DAY)
GROUP BY DATE(created_at);
```

## 6. 日志与审计

### 6.1 结构化日志

```java
@Slf4j
@Component
public class AiAuditLogger {

    public void logRequest(String requestId, String userId, String model,
                            String prompt, String response,
                            int inputTokens, int outputTokens, long latencyMs) {
        // 结构化 JSON 日志
        log.info("{}", toJson(Map.of(
            "type", "ai_request",
            "request_id", requestId,
            "user_id", userId,
            "model", model,
            "prompt", truncate(prompt, 500),
            "response", truncate(response, 500),
            "input_tokens", inputTokens,
            "output_tokens", outputTokens,
            "latency_ms", latencyMs,
            "timestamp", Instant.now().toString()
        )));
    }

    public void logToolCall(String requestId, String toolName,
                             String params, String result) {
        log.info("{}", toJson(Map.of(
            "type", "tool_call",
            "request_id", requestId,
            "tool", toolName,
            "params", params,
            "result", truncate(result, 500)
        )));
    }

    public void logSecurity(String requestId, String event, String detail) {
        log.warn("{}", toJson(Map.of(
            "type", "security",
            "request_id", requestId,
            "event", event,
            "detail", detail
        )));
    }
}
```

## 8. 快速复习

```
□ 可观测三支柱：Metrics (指标) + Traces (追踪) + Logs (日志)
□ 核心指标：QPS / 错误率 / P95延迟 / TTFT / Token用量 / 成本
□ Prometheus 埋点：Counter (计数) / Timer (延迟) / Gauge (瞬时值)
□ 告警规则：错误率 > 5% / P95 > 3s / 成本超预算
□ SLO：可用 99.9% / P95 < 3s / TTFT < 500ms / 准确率 > 90%
□ Error Budget：衡量可以承受多少错误，指导发布节奏
□ 日志：结构化 JSON 日志，便于 ELK 检索
□ 优化闭环：监控 → 分析 → 优化 → A/B → 灰度 → 循环
```
