# 01 — AI 与大模型基础概念

> **目标**：建立 AI 大模型领域的基础认知，理清所有核心名词和概念之间的层次关系。

---

## 1. 概念层次全景图

```
人工智能 (AI)
  └── 机器学习 (ML)                    ← 从数据中学习规律
        ├── 监督学习 (Supervised)
        ├── 无监督学习 (Unsupervised)
        ├── 强化学习 (Reinforcement)
        └── 深度学习 (DL)              ← 使用深层神经网络
              ├── CNN  (卷积神经网络)  → 图像
              ├── RNN/LSTM/GRU        → 序列（已逐渐被 Transformer 替代）
              ├── Transformer         → 当前主流架构
              │     ├── Encoder-Only  → BERT 系 (理解)
              │     ├── Decoder-Only  → GPT 系 (生成) ← 当前最主流
              │     └── Encoder-Decoder → T5/BART (翻译)
              ├── GAN  (生成对抗)      → 图像生成
              ├── Diffusion           → 图像/视频生成
              ├── VAE                 → 变分自编码
              └── SSM/Mamba           → 新范式（线性复杂度）
```

## 2. 核心名词详解

### 2.1 模型层级

| 名词 | 全称 | 详解 |
|------|------|------|
| **LLM** | Large Language Model（大语言模型） | 参数量通常在 10B（100 亿）以上的语言模型。能够在海量文本上进行预训练，并表现出**涌现能力**。代表：GPT-4、Claude、Llama、通义千问 |
| **SLM** | Small Language Model（小语言模型） | 参数量较小（1B-14B），可在消费级设备运行。代表：Phi-4、Llama-3.2-3B、Qwen2.5-7B、Gemma-3 |
| **VLM** | Vision-Language Model（视觉语言模型） | 能同时理解图像和文本的模型。代表：GPT-4V、Claude 3.5 Vision、Gemini Pro Vision、Qwen-VL |
| **LMM** | Large Multimodal Model（大模态模型） | 支持文本+图片+音频+视频多种模态。代表：Gemini 2.5 Pro、GPT-4o |
| **FM** | Foundation Model（基础模型） | 在广泛数据上预训练、可适配多种下游任务的通用模型。是"基座"而非"产品" |

### 2.2 模型参数量级对照

```
模型参数量级直觉：
1B   (10 亿)   ≈ 一部智能手机可运行
7B   (70 亿)   ≈ 一台 RTX 4090 (24GB) 可运行 (INT4 量化)
14B  (140 亿)  ≈ 一台 RTX 4090 勉强运行
70B  (700 亿)  ≈ 需要 A100×2 或 H100×1
405B (4050 亿) ≈ 需要 H100×8 或更多 (Llama 4)
1T+  (万亿)   ≈ 数据中心级别 (传言 GPT-4 约 1.8T MoE)
```

### 2.3 推理 vs 训练

| 维度 | 训练 (Training) | 推理 (Inference) |
|------|----------------|-----------------|
| **目的** | 学习知识、调整参数 | 根据输入生成输出 |
| **方向** | 前向 + 反向传播 | 仅前向传播 |
| **计算量** | 极大（需要存储梯度、优化器状态） | 较小（仅计算激活值） |
| **内存** | 参数量 × 4 (Adam) + 梯度 + 激活 | 参数量 × 2 (FP16) + KV Cache |
| **硬件** | 数据中心 GPU 集群 | 可单卡甚至 CPU |
| **时间** | 数天 ~ 数月 | 毫秒 ~ 秒 |
| **产出** | Checkpoint / Model Weights | Token / Text / Image |
| **成本** | 极高（数百万美元） | 相对低（按 Token 计费） |

## 3. Token 基础

### 3.1 什么是 Token

> **Token** 是大模型处理文本的最小单元。它不是"字"或"词"，而是一种介于两者之间的子词单元。

```
中文示例：
"人工智能大模型" → 人工 / 智能 / 大 / 模型 → 4 tokens
"你好世界"       → 你好 / 世界          → 2-3 tokens

英文示例：
"Hello, world!"  → Hello / , /  world / !   → 4 tokens
"unbelievable"   → un / belie / vable       → 3 tokens

粗略估算：
- 英文：1 token ≈ 0.75 个单词 ≈ 4 个字符
- 中文：1 token ≈ 1.5 ~ 2 个汉字
- 代码：1 token ≈ 0.8 个有效字符（空格计数少）
```

### 3.2 上下文窗口 (Context Window)

> 模型一次能处理的最大 token 数量（input + output）

| 模型 | 上下文窗口 | 说明 |
|------|-----------|------|
| GPT-4o | 128K | ~ 240 页英文 |
| GPT-4 Turbo | 128K | ~ 240 页英文 |
| Claude Opus 4 | 200K | ~ 375 页英文 |
| Claude Sonnet 4 | 200K | ~ 375 页英文 |
| Gemini 2.5 Pro | 1M | ~ 1500 页英文，当前最大 |
| Gemini 2.5 Flash | 1M | ~ 1500 页英文 |
| DeepSeek-V3 | 128K | ~ 240 页英文 |
| Qwen2.5 | 128K | ~ 240 页英文 |
| Llama 4 Scout | 10M | 千万级（Meta 宣称） |

### 3.3 Token 计算工具

```java
// Java 中估算 Token 数量（粗略法）
public class TokenEstimator {
    // 中文：约每 1.5 字符 1 token
    public static int estimateChinese(String text) {
        return (int) (text.length() / 1.5);
    }
    // 英文：约每 4 字符 1 token
    public static int estimateEnglish(String text) {
        return (int) (text.length() / 4.0);
    }
}

// 精确计算需要使用对应模型的 Tokenizer
// OpenAI: 使用 tiktoken 库（仅 Python）或 HTTP API
// 国内厂商：通常提供在线 Token 计算工具
```

## 4. 大模型的核心能力与局限

### 4.1 核心能力

| 能力 | 说明 | 企业应用 |
|------|------|---------|
| **文本生成** | 流畅、连贯地生成人类语言 | 营销文案、报告撰写、邮件回复 |
| **理解与分析** | 提取语义、分析情感、判断意图 | 客服意图识别、合同审查、舆情分析 |
| **摘要** | 从长文本提取核心信息 | 会议纪要、文档总结、新闻摘要 |
| **翻译** | 多语种互译 | 国际化产品、跨国协作 |
| **代码生成** | 根据自然语言描述生成代码 | 辅助编程、自动化脚本、SQL 生成 |
| **推理** | 逻辑推理、数学计算、因果推断 | 数据分析、风险评估、故障诊断 |
| **分类** | 文本分类、情感分类、意图分类 | 工单路由、垃圾过滤、内容审核 |
| **对话** | 多轮对话、上下文理解 | 智能客服、虚拟助手、教育培训 |
| **信息抽取** | NER（命名实体识别）、关系抽取 | 简历解析、发票识别、知识图谱构建 |

### 4.2 核心局限（企业开发必须了解）

| 局限 | 说明 | 缓解手段 |
|------|------|---------|
| **幻觉 (Hallucination)** | 生成看似合理但事实错误的内容 | RAG、事实核查、置信度阈值 |
| **知识截止** | 训练数据有时间截止日期 | RAG、Web Search Tool |
| **上下文限制** | 超出窗口的内容会被截断 | 长文本分块、摘要压缩 |
| **缺乏实时信息** | 无法访问互联网/实时数据 | Function Calling、MCP |
| **数学能力不稳定** | 复杂计算可能出错 | Tool Use（调用计算器/代码执行器）|
| **指令敏感** | 对 Prompt 措辞敏感,结果不稳定 | Prompt 工程、评估体系 |
| **偏见与安全问题** | 训练数据可能包含偏见 | 安全审核、Human-in-the-loop |
| **成本** | API 调用成本不低 | 缓存、模型路由、SLM 分流 |

## 5. 涌现能力 (Emergent Abilities)

> 当模型规模超过某个阈值时,突然出现的新能力——这些能力在小模型上完全不存在。

### 5.1 典型涌现能力

```
涌现曲线示意：

能力 ──────────────────────────────────────
  │
  │                                      ★ 涌现阈值
  │                                   ／
  │                                ／
  │                             ／
  │                          ／
  │                       ／
  │   ──────────────────
  │   (小模型完全没有此能力)
  │
  └──────────────────────────────────────→ 参数量
      1B    7B    14B    70B    100B    1T
```

| 涌现能力 | 说明 | 典型阈值 |
|----------|------|---------|
| **Few-Shot Learning** | 给几个示例就能学会新任务 | ~10B |
| **Chain-of-Thought** | 能逐步推理复杂问题 | ~60B |
| **代码生成** | 从自然语言生成可运行代码 | ~10B |
| **翻译** | 多语言互译能力 | ~7B |
| **世界知识** | 百科全书式的知识储备 | ~30B |
| **指令遵循** | 理解和遵循复杂指令 | ~7B |
| **Tool Use** | 自主判断何时调用工具 | ~60B |

### 5.2 对企业的意义

- **不要用小模型做复杂推理任务** —— 7B 模型的数学/逻辑能力远不如 70B+
- **可以多模型分级路由** —— 简单任务用 SLM（降低成本），复杂任务用 LLM
- **涌现不可预测** —— 需要实际测试而非看 benchmark 数字
