# 10 — 向量数据库深度解析

> **目标**：深入理解向量数据库的索引算法、对比主流产品、掌握企业选型和生产实践。

---

## 1. 向量数据库基础

### 1.1 为什么需要向量数据库

```
传统数据库：精确匹配
  SELECT * FROM docs WHERE title = 'AI入门'
  → 只能找到 title 精确等于 'AI入门' 的文档

向量数据库：语义搜索
  搜索 "如何入门人工智能"
  → 能匹配到 "AI入门指南"、"机器学习新手教程" 等语义相似的文档
  → 即使关键词完全不同
```

### 1.2 核心概念

| 概念 | 解释 |
|------|------|
| **Vector / Embedding** | 文本/图片的数学表示，例如 `[0.23, -0.15, 0.78, ...]` × 1024 |
| **Vector Dimension** | 向量维度，如 1024、1536 |
| **Vector Index** | 加速相似搜索的数据结构（ANN 算法） |
| **Similarity Metric** | 相似度度量：余弦/Cosine、欧几里得/L2、内积/IP |
| **Collection / Table** | 向量集合，对应关系数据库的"表" |
| **Metadata** | 除向量外的其他属性（标题、分类、时间等） |

## 2. 索引算法详解

### 2.1 ANN vs KNN

```
KNN (精确最近邻搜索)：
  → 遍历所有向量，计算每个的距离，排序
  → 复杂度 O(n × d)，百万级已经慢到不可用

ANN (近似最近邻搜索)：
  → 牺牲一点精度，换取数量级加速
  → 复杂度 O(log n) ~ O(n)
  → 实际场景下 99.9% 召回率就够了
```

### 2.2 主流索引算法对比

| 算法 | 原理 | 查准率 | 速度 | 内存 | 构建 |
|------|------|:---:|:---:|:---:|:---:|
| **Flat** | 暴力搜索 | 100% | 最慢 | 低 | 即时 |
| **IVF (Inverted File)** | 聚类+只在最近几个簇搜索 | 95-99% | 快 | 中 | 需要训练 |
| **HNSW (Hierarchical NSW)** | 多层图，贪婪搜索 | 98-99.9% | 最快 | 高 | 需要构建 |
| **PQ (Product Quantization)** | 压缩向量，近似距离 | 90-95% | 快 | 低 | 需要训练 |
| **IVF+PQ** | IVF + PQ 组合 | 90-97% | 快 | 低 | 需要训练 |
| **DiskANN** | 磁盘级索引 | 95-98% | 中 | 超低 | 需要构建 |

### 2.3 HNSW 详解（最常用）

```
HNSW (Hierarchical Navigable Small World)：

原理：构建一个多层图结构
  Layer 2: ●─────●          (稀疏，跳远)
  Layer 1: ●───●───●───●    (中等)
  Layer 0: ●─●─●─●─●─●─●   (密集，精确)

搜索过程：
  1. 从最高层开始，贪婪搜索到最近的节点
  2. 下降一层，从上一层最近节点继续搜索
  3. 重复直到第 0 层
  4. 返回 Top-K 结果

参数：
  M:    每个节点最大连接数（通常 16-64）
  efConstruction: 构建时的搜索宽度（通常 200-500）
  efSearch:       查询时的搜索宽度（通常 50-200）
```

### 2.4 相似度度量

```java
public class SimilarityMetrics {

    // 1. 余弦相似度（最常用）
    //   值域 [-1, 1]，越接近 1 越相似
    public static double cosine(float[] a, float[] b) {
        double dot = 0, normA = 0, normB = 0;
        for (int i = 0; i < a.length; i++) {
            dot += a[i] * b[i];
            normA += a[i] * a[i];
            normB += b[i] * b[i];
        }
        return dot / (Math.sqrt(normA) * Math.sqrt(normB));
    }

    // 2. 欧几里得距离
    //   值域 [0, +∞)，越小越相似
    public static double euclidean(float[] a, float[] b) {
        double sum = 0;
        for (int i = 0; i < a.length; i++) {
            double diff = a[i] - b[i];
            sum += diff * diff;
        }
        return Math.sqrt(sum);
    }

    // 3. 内积（点积）
    //   值域 (-∞, +∞)，越大越相似
    public static double dotProduct(float[] a, float[] b) {
        double sum = 0;
        for (int i = 0; i < a.length; i++) {
            sum += a[i] * b[i];
        }
        return sum;
    }
}
```

### 3.2 各产品一句话总结

```
Milvus     → 功能最全面的专用向量数据库，分布式首选，但复杂度高
Qdrant     → Rust 实现，性能极好，API 优雅，中型项目首选
Weaviate   → GraphQL API + 内置 Embedding 模块，但内存消耗大
Pinecone   → 全托管，零运维，贵但省心
Chroma     → 嵌入 Python 进程，最简单的原型开发
PGVector   → 基于 PostgreSQL，SQL 友好，小项目零额外运维成本
Redis Stack → 超低延迟，适合实时场景，但数据量不宜过大
ES         → 全文+向量双搜索，适合已有 ES 的团队
FAISS      → Meta 的索引库，非"数据库"（无 CRUD/持久化/分布式）
```

## 4. 企业选型决策树

### 4.1 决策流程

```
你的团队情况？
│
├── 团队 < 5 人，快速原型？
│   └── PGVector (已有 PG) 或 Chroma
│
├── 已有 PostgreSQL？
│   ├── 数据量 < 500 万？→ PGVector（零额外运维）
│   └── 数据量 > 500 万？→ Milvus / Qdrant（独立扩展）
│
├── 已有 Redis？
│   ├── 需要超低延迟 (< 5ms)？→ Redis Stack
│   └── 否则 → PGVector / Milvus
│
├── 已有 Elasticsearch？
│   └── ES + 向量插件（统一技术栈）
│
├── 需全托管，不想运维？
│   └── Pinecone / Zilliz Cloud
│
├── 需要分布式 + 水平扩展？
│   └── Milvus / Qdrant
│
└── 预算有限？
    └── PGVector / Qdrant / Chroma (都是开源免费)
```

### 4.2 规模与选型

```
数据量级选型：

< 10 万条：
  任何方案都行（Chroma / PGVector / Redis）

10 万 ~ 100 万条：
  PGVector / Qdrant / Redis Stack
  需要合理配置索引参数

100 万 ~ 1000 万条：
  Qdrant / Milvus / Weaviate
  需要专用向量数据库

> 1000 万条：
  Milvus (分布式) / Pinecone (云)
  需要水平扩展
```

## 5. PGVector 实战

### 5.1 初始化

```sql
-- 安装扩展
CREATE EXTENSION vector;

-- 创建表
CREATE TABLE documents (
    id BIGSERIAL PRIMARY KEY,
    content TEXT,
    embedding VECTOR(1024),          -- 1024 维向量
    metadata JSONB,
    created_at TIMESTAMP DEFAULT NOW()
);

-- 创建 HNSW 索引（PGVector 支持 IVFFlat 和 HNSW）
CREATE INDEX ON documents
  USING hnsw (embedding vector_cosine_ops)
  WITH (m = 16, ef_construction = 200);
```

### 5.2 Java 操作

```java
@Repository
public class PgVectorRepository {

    private final JdbcTemplate jdbc;

    // 插入
    public void insert(String content, float[] embedding, Map<String, Object> metadata) {
        String vectorStr = Arrays.toString(embedding)
            .replace("[", "[").replace("]", "]"); // PGVector expects [...]

        jdbc.update(
            "INSERT INTO documents (content, embedding, metadata) VALUES (?, ?::vector, ?::jsonb)",
            content, vectorStr, toJson(metadata)
        );
    }

    // 相似度搜索（余弦相似度）
    public List<SearchResult> search(float[] queryEmbedding, int topK) {
        String vectorStr = Arrays.toString(queryEmbedding)
            .replace("[", "[").replace("]", "]");

        return jdbc.query("""
            SELECT id, content, metadata,
                   1 - (embedding <=> ?::vector) AS similarity
            FROM documents
            ORDER BY embedding <=> ?::vector
            LIMIT ?
            """,
            (rs, rowNum) -> new SearchResult(
                rs.getLong("id"),
                rs.getString("content"),
                rs.getDouble("similarity")
            ),
            vectorStr, vectorStr, topK
        );
    }
    // 运算符：
    // <=>  余弦距离    (1 - cosine_similarity)
    // <->  欧几里得距离
    // <#>  内积的负值
}
```

## 7. 性能优化

### 7.1 索引参数调优

```
HNSW 参数调优：

m (每个节点最大连接数)：
  增大 → 查准率更高，但内存更大、构建更慢
  16 → 通用场景
  32 → 高精度场景
  64 → 极致精度

efConstruction (构建时的搜索宽度)：
  增大 → 索引质量更高，但构建更慢
  200 → 通用
  500 → 高质量

efSearch / ef (查询时的搜索宽度)：
  增大 → 查准率更高，但查询更慢
  50 → 快速
  100 → 平衡
  200 → 高精度

调优流程：
  默认参数 → 测查准率
  → 不满意的查准率 → 提高 ef/m
  → 延迟过高 → 降低 ef/m
```

### 7.2 通用优化清单

```
向量数据库优化清单：

□ 索引选型
  - HNSW: 查准率优先
  - IVF+PQ: 内存优先
  - Flat: 百万以下数据量

□ 向量维度
  - 1024 → 512：存储减半，速度提升 30-50%
  - 对准确率影响 < 2%

□ 批量写入
  - 单条插入慢 → 批量插入（100-1000/批）
  - 先写后建索引

□ 元数据过滤
  - 先过滤再向量搜索 (Pre-filter)
  - 还是先向量搜索再过滤 (Post-filter) → 取决于数据分布

□ 连接池
  - Milvus / Qdrant 客户端连接池配置
  - PGVector HikariCP 连接池

□ 监控指标
  - 查询延迟 (P50 / P99)
  - 索引大小
  - 内存使用量
  - 查准率 (定期抽样评估)
```

## 8. 数据迁移

```java
@Service
public class VectorDataMigration {

    /**
     * 从 PGVector 迁移到 Milvus
     */
    public void migrate(JdbcTemplate jdbc, MilvusVectorStore milvus) {
        // 1. 分批从源库读取
        int offset = 0;
        int batchSize = 1000;

        while (true) {
            List<Document> batch = jdbc.query("""
                SELECT content, embedding::text, metadata::text
                FROM documents
                ORDER BY id
                LIMIT ? OFFSET ?
                """,
                (rs, rowNum) -> {
                    float[] emb = parseVector(rs.getString("embedding"));
                    Map<String, Object> meta = parseMeta(rs.getString("metadata"));
                    Document doc = new Document(rs.getString("content"), meta);
                    doc.setEmbedding(emb);
                    return doc;
                },
                batchSize, offset
            );

            if (batch.isEmpty()) break;

            // 2. 批量写入目标库
            milvus.add(batch);
            offset += batchSize;

            log.info("Migrated {} documents", offset);
        }
    }
}
```
