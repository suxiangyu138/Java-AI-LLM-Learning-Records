## 1. 量化原理与分类

### 1.1 什么是量化

量化是将模型参数的数值精度从高比特位降低到低比特位：

```
原始模型（FP32）：
权重值：0.1234567890123456 → 32位存储

半精度（FP16）：
权重值：0.12346 → 16位存储（体积减半，精度基本无损）

INT8 量化：
权重值：0.123 → 8位存储（体积为1/4，精度轻微损失）

INT4 量化：
权重值：0.1 → 4位存储（体积为1/8，需要校正技术）
```

### 1.2 量化的两种范式

| 范式 | 时间 | 方法 | 精度 | 适用场景 |
|------|------|------|------|---------|
| **训练后量化（PTQ）** | 训练完成后 | GPTQ、AWQ、GGUF | 轻微损失 | 推理部署（主流） |
| **量化感知训练（QAT）** | 训练过程中 | 模拟量化 + 训练 | 几乎无损 | 追求极致精度 |

> **重点**：对于大多数应用开发场景，**PTQ（训练后量化）完全够用**。QAT 需要重新训练，成本高，只在极端精度要求下使用。

### 1.3 量化精度损失来源

```
量化误差 = 原始值 - 量化值

例如：FP16 值 0.375 → INT4 只有16个离散值可选
      0.375 可能被映射到 0.4 或 0.3
      这个误差在单层传播中很小，但经过几十层会累积

解决方案：
  - GPTQ：用校准数据逐层补偿量化误差
  - AWQ：保护"重要"通道不被过度量化
  - GGUF：使用非均匀量化（Q4_K_M 等混合精度方案）
```

### 2.3 量化级别与质量参考

| 量化级别 | 体积（相对FP16） | 质量保持 | 推荐度 |
|----------|----------------|---------|--------|
| FP16 | 100% | 100% | 基准 |
| INT8 | 50% | 99.5% | ⭐⭐⭐⭐ |
| Q8_0 (GGUF) | 50% | 99.5% | ⭐⭐⭐⭐ |
| INT4 (GPTQ/AWQ) | 25% | 97-99% | ⭐⭐⭐⭐⭐ |
| Q4_K_M (GGUF) | 25% | 96-98% | ⭐⭐⭐⭐⭐ |
| Q3_K_M (GGUF) | 18% | 93-96% | ⭐⭐⭐ |
| Q2_K (GGUF) | 12% | 85-90% | ⭐⭐ |

> **注意**：Q2 级别的量化虽然体积最小，但质量下降明显。**Q4_K_M 是性价比最优解**，在大部分场景下与 FP16 差异不可感知。

## 3. GGUF：CPU 推理的终极方案

### 3.1 GGUF 的设计理念

GGUF（GPT-Generated Unified Format）是 llama.cpp 项目的模型格式，专门为 CPU 推理优化。它的核心优势是**不需要 GPU 就能运行大模型**。

```bash
# 使用 Ollama（底层是 llama.cpp）运行量化模型
ollama run qwen2.5:7b-q4_K_M

# 显存需求：0（纯 CPU 推理）
# 内存需求：~5GB
# 推理速度：10-20 tokens/s（M2 Mac）或 5-10 tokens/s（现代 x86 CPU）
```

### 3.2 GGUF 量化类型详解

```
Q4_K_M 的含义：
  Q4 = 基础精度 4-bit
  K = "K-quant" 算法（不同层使用不同精度）
  M = Medium（中等大小，还有 S 小型和 L 大型）

精度分配策略（以 Q4_K_M 为例）：
  - 注意力层的权重：4.5 bit（略高精度）
  - FFN 层的权重：4.0 bit
  - 输出嵌入：6.0 bit（保留最高精度以保证输出质量）
```

## 4. 知识蒸馏：大模型教小模型

### 4.1 什么是知识蒸馏

**知识蒸馏**不是压缩模型，而是**用大模型（教师）的输出训练小模型（学生）**，让小模型学会大模型的"思考方式"。

```
传统训练：小模型 ← 训练数据（hard labels）
知识蒸馏：小模型 ← 大模型的输出分布（soft labels, 包含更多信息）

例如：
  Hard label: 猫（只有正确类别）
  Soft label: 猫 0.85, 虎 0.10, 豹 0.03, 狗 0.02
                          ↑
              这些"错误"概率包含了类别间的相似关系
              这是大模型学到的"知识"，蒸馏给小模型
```

### 4.2 蒸馏 vs 微调 vs 量化

| 方法 | 最终模型大小 | 训练成本 | 效果 |
|------|------------|---------|------|
| **知识蒸馏** | 任意（取决于学生模型大小） | 中（需要教师模型推理） | 好 |
| **LoRA 微调** | 几乎不变（+<1%） | 低 | 很好 |
| **量化** | 原来的 1/4-1/8 | 极低 | 较好 |
| **剪枝** | 原来的 1/2-1/3 | 低 | 一般 |

### 4.3 蒸馏实战框架

```python
# 使用 Teacher 模型的输出分布训练 Student 模型
import torch.nn.functional as F

def distillation_loss(student_logits, teacher_logits, labels, temperature=4.0, alpha=0.7):
    """
    知识蒸馏损失函数

    Args:
        student_logits: 学生模型的输出 logits
        teacher_logits: 教师模型的输出 logits（冻结）
        labels: 真实标签
        temperature: 软化温度（越高越soft）
        alpha: 蒸馏损失的权重
    """
    # 软标签损失（KL散度）：让学生模仿教师的输出分布
    soft_loss = F.kl_div(
        F.log_softmax(student_logits / temperature, dim=-1),
        F.softmax(teacher_logits / temperature, dim=-1),
        reduction='batchmean'
    ) * (temperature ** 2)

    # 硬标签损失（交叉熵）：让学生不要偏离正确答案太远
    hard_loss = F.cross_entropy(student_logits, labels)

    # 总损失 = 软标签损失（权重α） + 硬标签损失（权重1-α）
    return alpha * soft_loss + (1 - alpha) * hard_loss
```

## 5. 推理加速综合方案

### 5.1 加速技术全景

```
推理加速 = 量化 + KV Cache + Flash Attention + 批处理 + 投机采样

量化（Quantization）       → 降低计算精度（INT4/INT8）
KV Cache 优化             → 避免重复计算历史 token
Flash Attention            → 减少显存访问，加速注意力计算
Continuous Batching        → 合并多个请求一起推理
Speculative Decoding       → 用小模型"猜"token，大模型验证
Tensor Parallelism         → 多 GPU 并行推理
```

### 5.2 实际部署的推荐组合

```python
# vLLM：生产环境推理引擎（集成了以上所有优化）
from vllm import LLM, SamplingParams

# 自动应用：Flash Attention + Continuous Batching + PagedAttention
llm = LLM(
    model="Qwen/Qwen2.5-7B-Instruct-AWQ",  # INT4 量化版本
    tensor_parallel_size=1,                 # 单卡推理
    gpu_memory_utilization=0.90,           # GPU 显存利用率
    max_num_seqs=32,                       # 最大并发请求数
)

sampling_params = SamplingParams(
    temperature=0.7,
    top_p=0.95,
    max_tokens=512
)

# 批量推理
prompts = ["解释什么是微服务", "如何实现分布式锁", "Spring Cloud 的核心组件"]
outputs = llm.generate(prompts, sampling_params)

for output in outputs:
    print(output.outputs[0].text)
```

## 核心要点回顾

- **量化**是将模型从 FP16 压缩到 INT4/INT8，体积缩至 1/4-1/8，质量损失不到 3%
- **Q4_K_M** 是当前性价比最优的量化级别（GGUF 格式）
- **GPTQ/AWQ** 适合 GPU 推理，**GGUF** 适合 CPU 推理（Ollama/llama.cpp）
- **知识蒸馏**让小模型学习大模型的"思考方式"，而非简单复制标签
- 生产环境推荐 **vLLM + INT4量化模型**，一站式获得 Flash Attention、Continuous Batching 等优化
- 综合应用所有优化技术，延迟可降低 80%+，吞吐提升 10-30×
