# 如何快速看懂日志（通用方法论 + 实战拆解）

> **核心摘要**：日志是程序运行的黑匣子。本文提供通用的日志分析方法论：先筛时间 → 再搜 ERROR → 看错误类型 → 看自己项目代码行号 → 核对入参和 SQL → 微服务用 traceId 串联全链路。

---

## 一、日志核心作用

日志记录以下三类关键信息：
1. **行为记录**：程序启动、接口调用、定时任务、数据库操作
2. **上下文信息**：关键变量、入参/出参、耗时、调用链路
3. **异常信息**：报错堆栈、异常原因、崩溃现场

## 二、日志级别（优先看级别筛重点）

| 级别 | 说明 | 排查优先级 |
|------|------|-----------|
| TRACE | 详细流程，调试用 | 忽略 |
| DEBUG | 开发调试信息 | 本地环境用 |
| INFO | 正常业务流程 | 参考 |
| WARN | 不影响运行的异常 | 可选检查 |
| **ERROR** | 业务报错、接口失败 | **最高优先** |
| FATAL | 致命错误，服务崩溃 | 立即处理 |

## 三、标准日志格式

```
2026-04-26 15:30:22 [ERROR] [http-nio-8080-exec-5] com.demo.UserController.login : 用户名密码错误
java.sql.SQLException: 数据库连接超时
```

| 字段 | 分析要点 |
|------|---------|
| 时间 | 定位报错发生时间，结合业务时间复盘 |
| 级别 | 快速判断严重程度 |
| 线程 | 区分并发请求，排查多线程冲突 |
| 类+方法名 | **直接定位出错代码位置（最关键）** |
| 业务内容 | 入参、返回值、自定义打印 |
| 异常堆栈 | 报错根源、调用链 |

## 四、看日志核心步骤

1. **锁定时间范围**：根据问题发生时间筛选对应时间段日志
2. **过滤错误关键字**：搜索 ERROR、Exception、NullPointerException、SQL、Timeout、OOM
3. **先看报错摘要，再看堆栈**：
   - 第一行错误信息直接告诉问题类型
   - 堆栈只看自己项目的包路径，忽略框架底层源码
4. **结合入参 + 上下文**：查看接口请求参数、数据库查询条件
5. **看链路日志（微服务）**：用 traceId/requestId 全局搜索，完整还原请求全流程

## 五、常见日志报错快速识别

| 错误类型 | 可能原因 |
|---------|---------|
| NullPointerException | 变量未初始化、对象为 null 直接调用方法 |
| SQLSyntaxError | 字段不存在、语法错误 |
| 参数绑定异常 | 前端传参名不对、格式不匹配 |
| 超时异常 | 接口响应慢、数据库慢查询 |
| OOM 内存溢出 | 内存泄漏、大对象未释放 |

## 六、实用技巧

| 技巧 | 说明 |
|------|------|
| 检索过滤 | 本地用 Notepad++/VS Code，线上用 ELK/Graylog/grep |
| 忽略无关日志 | 框架启动日志、第三方依赖 INFO 直接跳过 |
| 保留现场 | 报错后不要立刻重启，先导出日志再处理 |
| 自定义日志规范 | 关键节点打印：入参、出参、耗时、业务 ID |

## 核心要点回顾

1. 先筛时间 → 再搜 ERROR
2. 看错误类型 → 看自己项目代码行号
3. 核对入参、SQL、第三方调用
4. 微服务用 traceId 串联全链路
