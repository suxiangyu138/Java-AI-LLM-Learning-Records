## 一、RAG 核心基础认知

### 1.1 什么是 RAG

**RAG**（检索增强生成）是将"检索外部知识库"与"大模型生成"结合的技术，核心解决大模型"知识滞后、事实性错误、幻觉"三大痛点。

### 1.2 RAG 与纯大模型、微调的区别

| 维度 | 纯大模型 | RAG | 微调 |
|------|----------|-----|------|
| 知识更新 | 固定，无法更新私有数据 | 实时更新知识库即可 | 需重新微调 |
| 开发成本 | 低 | 中 | 高 |
| 可解释性 | 无 | 可追溯来源 | 无 |
| 适用场景 | 通用场景 | 企业级应用首选 | 知识固定、高频复用 |

### 1.3 企业级核心价值

- **知识可控**：私有数据独立管理，避免泄露
- **成本可控**：无需微调高额算力，仅维护知识库
- **合规可控**：回答可追溯，满足审计要求
- **体验可控**：贴合企业业务场景

## 二、RAG 应用核心架构

### 2.1 输入层（用户交互层）

- 输入类型：文本、语音转文字、图片 OCR
- 预处理：去除无效字符、问题归一化、意图识别

### 2.2 检索层（RAG 核心）

| 检索方式 | 说明 |
|----------|------|
| **向量检索**（主流） | 文本转向量，计算相似度 |
| **关键词检索**（辅助） | 关键词匹配 |
| **混合检索**（首选） | 向量 + 关键词 |

**Embedding 模型选型**：

| 类型 | 代表模型 | 适用场景 |
|------|----------|----------|
| 开源 | BERT、Sentence-BERT、M3E、BGE | 私有化部署、数据安全 |
| 闭源 API | OpenAI、通义千问、文心一言 | 快速原型开发 |

### 2.3 知识库层

**构建流程**：数据采集 → 清洗 → 文档分割 → 向量编码 → 存储

**文档分割技巧**：
- 长度控制在 512-1024 tokens
- 工具：RecursiveCharacterTextSplitter、SentenceSplitter
- 保留上下文信息（标题、来源）

**向量数据库选型**：

| 数据库 | 类型 | 适用场景 |
|--------|------|----------|
| Milvus | 开源 | 企业级大规模部署 |
| Chroma | 开源轻量 | 原型开发 |
| FAISS | 开源 | 小规模本地实验 |
| Pinecone | 云服务 | 快速上线 |

### 2.4 生成层

**大模型选型**：

| 类型 | 代表模型 | 优势 |
|------|----------|------|
| 闭源 | GPT-4、通义千问、文心一言 | 生成能力强、快速落地 |
| 开源 | Llama 2、Qwen、ChatGLM | 私有化部署、数据安全 |

**Prompt 模板**：

```
你是企业 XX 领域的顾问，仅基于以下提供的上下文信息回答用户问题，
不要添加外部知识。如果上下文没有相关信息，直接回答"暂无相关信息"。

上下文：{检索到的内容}
用户问题：{用户输入}
```

### 2.5 输出层

- 格式多样化：文本、分点、表格、链接
- 上下文溯源：可查看对应的知识库片段
- 多终端适配：PC、移动端、企业系统嵌入

## 三、开发环境搭建

### 3.1 通用基础环境

```bash
# Python 3.8-3.11
python -m venv rag-env
rag-env\Scripts\activate  # Windows

# 核心库安装
pip install langchain llama-index sentence-transformers openai \
            pypdf python-docx chromadb streamlit
```

### 3.2 快速原型环境（10 分钟上手）

| 组件 | 选型 |
|------|------|
| Embedding | OpenAI Embeddings（API 调用） |
| 向量数据库 | Chroma（内存运行，无需部署） |
| 大模型 | GPT-3.5-turbo（API） |
| Web 界面 | Streamlit |

### 3.3 企业级私有化部署

**硬件要求**：
- CPU：≥ 8 核（推荐 16 核）
- GPU：NVIDIA RTX 3090/4090，显存 ≥ 16GB
- 内存：≥ 16GB（推荐 32GB）
- 存储：SSD

**软件架构**：

```
应用层（管理后台 + 用户界面）
核心服务层（RAG 服务 + Embedding 服务 + 大模型服务）
数据层（Milvus + MinIO + MySQL）
基础层（Linux + Docker）
```

## 四、开发核心注意事项

- **数据安全**：加密存储，私有化部署避免公网
- **检索精度**：合理文档分割，选择适配的 Embedding 模型
- **成本控制**：原型用免费 API 额度，生产用开源模型
- **可扩展性**：预留接口，支持知识库扩容和多模型适配
- **合规性**：回答可追溯，保留日志
- **用户体验**：响应时间 ≤ 3 秒，提供溯源信息

## 核心要点回顾

- RAG 五层架构：输入层 → 检索层 → 知识库层 → 生成层 → 输出层
- 原型开发：OpenAI + Chroma + Streamlit（10 分钟上手）
- 生产部署：Milvus + 开源大模型 + Docker（私有化可控）
- 企业级重点：数据安全、性能优化、合规性、可扩展性
