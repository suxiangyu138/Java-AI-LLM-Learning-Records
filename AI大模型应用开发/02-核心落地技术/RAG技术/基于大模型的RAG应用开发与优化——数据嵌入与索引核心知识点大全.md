## 一、数据嵌入（Data Embedding）

### 1.1 定义与核心作用

**数据嵌入**是将非结构化数据转换为高维稠密向量的过程，核心是将"语义信息"转化为"机器可计算的数值信息"。语义越相似的文本，其向量在空间中的距离越近。

### 1.2 嵌入模型选型

| 模型类型 | 代表模型 | 优势 | 企业级场景 |
|----------|----------|------|------------|
| 开源轻量级 | BGE-base、Sentence-BERT、E5-small | 部署成本低、延迟低 | 中小规模、敏感数据场景 |
| 开源重量级 | BGE-large、all-mpnet-base-v2 | 语义精度高、可微调 | 大型企业、核心业务 |
| 闭源 API | OpenAI text-embedding-3、阿里云 PAI-Core | 无需部署、迭代快 | 快速验证、非敏感数据 |

### 1.3 嵌入过程关键操作

**文本预处理**：
- 去噪：去除页眉页脚、水印、特殊符号
- 分块：512-1024 tokens
- 标准化：大小写统一、术语统一
- 增强：短文本补充上下文

**分块策略**：

| 策略 | 说明 | 适用场景 |
|------|------|----------|
| 固定长度分块 | 简单易实现 | 结构规整文档 |
| 语义分块 | 基于段落、章节 | 非结构化文档 |
| 重叠分块 | 保留 10%-20% 重叠 | 避免关键信息丢失 |
| 动态分块 | 根据文档类型自动调整 | 复杂文档场景 |

**嵌入参数优化**：
- **向量维度**：768 维（平衡精度与性能），轻量可选 384 维
- **批量处理**：batch size 32-128
- **领域微调**：用企业内部数据微调 BGE-base

### 1.4 嵌入质量评估

- **离线评估**：计算相似文本的余弦相似度（≥ 0.7）
- **在线评估**：结合 RAG 召回率、精确率间接评估
- **人工评估**：抽样检查 query 检索结果匹配度

## 二、索引（Index）

### 2.1 定义与核心作用

**索引**是将高维向量进行组织和存储的结构，核心作用是实现"快速检索"，避免遍历所有向量。

### 2.2 索引类型

| 索引类型 | 原理 | 代表工具 | 适用场景 |
|----------|------|----------|----------|
| **ANN 索引**（近似最近邻） | 牺牲少量精度换极快检索 | FAISS、Milvus、Pinecone | ≥ 10 万文本块 |
| **KNN 索引**（精确最近邻） | 遍历所有向量 | Sklearn KNN | ≤ 1 万、精度极高场景 |
| **HNSW 图索引** | 多层图结构，兼顾速度与精度 | Milvus、FAISS HNSW | 10 万-1000 万条 |

### 2.3 混合索引

| 组合 | 适用场景 |
|------|----------|
| 向量 + 关键词索引（ES/BM25） | 语义 + 精确匹配（合同编号） |
| 向量 + 结构化索引 | 按文档类型/时间过滤 |

### 2.4 索引参数调优（HNSW 示例）

| 参数 | 说明 | 常见取值 |
|------|------|----------|
| **efConstruction** | 构建时候选节点数 | 100-200 |
| **efSearch** | 检索时候选节点数 | 50-100 |

### 2.5 索引更新

- **增量更新**：新增文档直接插入索引
- **删除更新**：根据文档 ID 删除对应向量
- **全量重建**：嵌入模型大改时重建，安排在业务低峰期

### 2.6 检索优化

- **Top-K 值**：企业常用 K=5-10
- **相似度阈值**：0.7-0.8 过滤低相似度结果
- **索引分区**：按文档类型/时间/业务线分区
- **缓存优化**：高频查询结果存 Redis
- **向量压缩**：PCA 降维或量化

### 2.7 索引性能评估

| 指标 | 目标 |
|------|------|
| 检索延迟 | 100-500ms |
| 召回率 | ≥ 80% |
| 精确率 | ≥ 70% |
| 吞吐量（QPS） | ≥ 100（客服场景） |

## 三、企业级优化实践

### 端到端优化流程

```
文本预处理 → 分块优化 → 嵌入模型微调 → 索引构建 → 检索参数调优 → 评估 → 迭代
```

| 痛点 | 优化方向 |
|------|----------|
| 嵌入精度低 | 语义+重叠分块、领域微调、提升向量维度 |
| 检索延迟高 | HNSW 索引、索引分区、缓存、向量压缩 |
| 索引更新慢 | 增量更新、批量导入 |
| 存储成本高 | 向量量化、维度优化、分库分表 |
| 数据隐私泄露 | 开源嵌入模型 + 私有化向量数据库 |

---

## 核心要点回顾

- 嵌入决定精度：选型平衡成本与精度，768 维是常用平衡点
- 索引决定效率：HNSW 是当前最主流的企业级索引方案
- 混合索引：向量 + 关键词/结构化，提升综合检索精度
- 企业级要求：低延迟（<500ms）、高召回（>80%）、高可用
