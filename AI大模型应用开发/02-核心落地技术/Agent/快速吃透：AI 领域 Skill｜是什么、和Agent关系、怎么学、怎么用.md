## 一、Skill 的定义

在 AI 领域中，**Skill** 是大模型/Agent 可调用的具体能力工具，中文常称为技能、工具或能力插件。

- 中文别称：技能、工具、能力插件
- 英文对应：Skill / Tool / Function

> **大白话**：LLM 本身只会打字和推理，Skill 就是给大模型装的"一个个专属手脚"，让它能干具体的事。

---

## 二、常见 AI Skill 清单

| Skill 类型 | 功能说明 |
|---|---|
| **联网搜索 Skill** | 实时查新闻、查资料、查最新技术 |
| **文档检索 Skill** | 对接 RAG / 向量库，查询私有笔记和课程资料 |
| **数据库 Skill** | 查询 MySQL、Redis、业务数据 |
| **代码执行 Skill** | 运行 Python、数学计算、写脚本、排错 |
| **接口调用 Skill** | 调用第三方 API（天气、时间、爬虫等） |
| **系统操作 Skill** | 读写本地文件、整理笔记、批量处理 |

## 三、Skill / LLM / Agent 三者关系

```
LLM（思考决策）
    ↓
Agent（任务拆解 + 调度）
    ↓
Skill 1 / Skill 2 / Skill 3（具体干活）
```

| 组件 | 核心职责 | 特点 |
|---|---|---|
| **LLM 大模型** | 思考、理解、推理、写文案 | 无行动能力，不能联网 |
| **Skill 技能** | 纯执行、纯工具 | 不会思考，只负责固定的单一功能 |
| **Agent 智能体** | 调度者、指挥官 | 思考需要哪个 Skill，自动调用并整合结果 |

> **一句话总结**：LLM 动脑，Skill 动手，Agent 管调度。

---

## 四、AI Skill 的核心特性

| 特性 | 说明 |
|---|---|
| **单一职责** | 一个 Skill 只做一件事（如"只查向量库""只联网搜索"） |
| **标准化入参出参** | 统一入参和返回格式，便于 Agent 调用 |
| **可插拔** | 想用就加载、不用就关闭，随时新增自定义技能 |
| **结构化描述** | 必须写清楚技能用途、参数和使用场景，LLM 靠此判断何时调用 |

## 五、主流框架中 Skill 的实现

LangChain、LlamaIndex 等主流框架的 Skill 写法统一：

1. 定义函数（具体功能）
2. 添加描述注释（给大模型看）
3. 注册到技能列表
4. Agent 自动识别并调用

```python
from langchain_core.tools import tool

# 自定义一个 AI Skill
@tool
def search_tech_knowledge(keyword: str) -> str:
    """
    技能用途：查询计算机后端、AI 相关技术知识点
    参数：
        keyword: 要查询的技术名词
    """
    return f"【技能检索】{keyword} 核心原理、用法已查询完成"

# 把技能交给 Agent
skills = [search_tech_knowledge]
```

> **注意**：`@tool` 装饰器标记这是一个 AI Skill；注释即大模型识别该技能的说明书。

## 六、RAG / Skill / Agent 区别

| 组件 | 本质 | 说明 |
|---|---|---|
| **RAG** | 一种专属 Skill | 知识检索技能，只负责查文档 |
| **Skill** | 泛指所有工具能力 | 检索、搜索、数据库、代码等 |
| **Agent** | 调度中心 | 按需选择不同 Skill 组合完成复杂任务 |

## 七、快速学习路径（三步速成）

### 步骤一：分清边界

- LLM：负责想
- Skill：负责做
- Agent：负责派活

### 步骤二：掌握固定结构

每个 Skill 包含：

1. 名称
2. 功能描述
3. 入参
4. 执行逻辑
5. 返回结果

### 步骤三：动手实践

建议亲手编写以下两个最小 Skill：

- **文档检索 Skill**（对接 RAG）
- **简单自定义工具 Skill**

## 核心要点回顾

- AI 领域的 Skill = 可调用工具 / 技能插件
- LLM 无行动能力，靠 Skill 落地执行
- Agent 负责判断并调用各类 Skill
- RAG 本质上是一种"知识库检索 Skill"
- 大模型 + 多 Skill + Agent 编排是未来的标准架构
