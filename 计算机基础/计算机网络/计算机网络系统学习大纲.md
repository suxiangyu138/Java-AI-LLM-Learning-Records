## 学习目标

完成本大纲后，应当能够达到以下目标：

- 理解计算机网络的分层思想，能说清每一层解决什么问题、常见协议有哪些
- 掌握 IP、ARP、ICMP、路由、NAT、DNS、TCP、UDP、HTTP、HTTPS 等高频协议的核心机制
- 能独立分析"三次握手、四次挥手、TIME_WAIT、滑动窗口、拥塞控制、HTTP 缓存、HTTPS 握手"等经典问题
- 能结合抓包工具或日志，定位常见网络问题，如连接超时、重传、DNS 解析慢、请求被限流、跨机房延迟高等

---

## 阶段一：建立整体框架

### 1.1 分层模型

建议先掌握 OSI 七层模型与 TCP/IP 五层模型，重点不是死记名称，而是理解"每层向上一层提供什么能力"。

**这一阶段需要达到的要求：**

- 能说出每层的典型协议与设备（交换机对应数据链路层，路由器对应网络层）
- 能区分数据单位：比特、帧、IP数据报、报文段、报文
- 能解释"封装"和"解封装"的过程

### 1.2 网络通信全流程

把"浏览器输入一个 URL 后发生了什么"作为总线索：DNS 解析、建立 TCP 连接、发送 HTTP 请求、服务器处理、返回响应、浏览器渲染页面，这条链路几乎会覆盖所有重要知识点。

> 建议在这一阶段画出一张总流程图，后续每学完一个协议，就补充到图里。

---

## 阶段二：网络层基础

### 2.1 IP 地址与子网划分

需要掌握 IPv4 的基本结构、网络号和主机号、子网掩码、CIDR 表示法，以及私有 IP 与公网 IP 的区别。

**本部分重点：**

- IPv4 地址分类与 CIDR 的关系
- 子网掩码如何判断两个主机是否处于同一网段
- 默认网关的作用，以及跨网段通信为什么需要网关

### 2.2 ARP、ICMP、NAT、路由

| 协议 | 作用 |
|------|------|
| **ARP** | 在局域网中根据IP地址获取目标主机的MAC地址 |
| **ICMP** | 网络诊断（ping依赖ICMP） |
| **NAT** | 让多个内网设备复用较少的公网地址 |

**本阶段要能回答：**

- 同一局域网中两台主机如何通信
- 跨网段访问时数据包为什么要先发给网关
- NAT 为什么能缓解 IPv4 地址不足问题

## 阶段三：传输层重点突破

### 3.1 UDP

UDP 是无连接、尽最大努力交付、面向报文的传输协议，协议开销小、时延低，但不保证可靠性、顺序和去重。更适合实时音视频、语音通话、DNS 等对时延更敏感的场景。

### 3.2 TCP 基础机制

TCP 是面向连接、可靠传输、面向字节流的协议，其可靠性通常通过序列号、确认应答、超时重传、滑动窗口、流量控制和拥塞控制来实现。

**建议拆成以下小节：**

- 序列号与确认号
- 重传机制与累计确认
- 滑动窗口与流量控制
- 拥塞控制：慢启动、拥塞避免、快重传、快恢复
- TCP 为什么会粘包/拆包，以及应用层如何解决消息边界问题

### 3.3 三次握手与四次挥手

| 问题 | 核心要点 |
|------|----------|
| 为什么不是两次握手 | 防止已失效的连接请求报文段传到服务端 |
| 为什么挥手通常是四次 | TCP是全双工协议，每个方向需独立关闭 |
| 为什么客户端进入 TIME_WAIT | 确保最后一个ACK能到达服务端 |
| TIME_WAIT过多如何缓解 | 开启`tcp_tw_reuse`，使用连接池 |

## 阶段四：应用层核心协议

### 4.1 DNS

DNS 的本质是把域名解析成 IP 地址，常见查询路径包括浏览器缓存、本机缓存、hosts 文件、本地 DNS 服务器，再到递归或迭代查询。

**学习重点：**

- 递归查询与迭代查询的区别
- DNS 缓存为什么能提升性能
- DNS 故障会如何影响应用访问

### 4.2 HTTP

HTTP 是应用层协议，基于请求-响应模型，本身是无状态的。

**建议按以下顺序学习：**

1. 请求报文与响应报文结构，常见请求方法与状态码
2. GET 和 POST 的常见区别，以及幂等性、安全性的概念
3. Cookie、Session、Token 的基本作用
4. HTTP 缓存机制（强缓存和协商缓存）
5. 长连接、短连接、Connection: keep-alive 的意义

### 4.3 HTTP/1.1、HTTP/2、HTTP/3

| 版本 | 特点 | 问题 |
|------|------|------|
| HTTP/1.1 | 持久连接 + 管线化 | 队头阻塞 |
| HTTP/2 | 多路复用 + 头部压缩 + 服务器推送 | TCP层队头阻塞 |
| HTTP/3 | 基于QUIC（UDP） | 部署复杂 |

### 4.4 HTTPS 与 TLS

HTTPS 是在 HTTP 与 TCP 之间加入了 TLS/SSL 安全层，提供加密、身份认证与完整性保护。

**重点掌握：**

- 对称加密与非对称加密分别解决什么问题
- 数字证书、CA、证书链的作用
- HTTPS 握手的大致过程，以及为什么它能防止中间人攻击

## 阶段五：局域网与设备认知

掌握集线器、交换机、路由器分别工作在哪一层、如何转发数据、对广播域和冲突域有什么影响。

> 建议顺带理解 MAC 地址、以太网帧、ARP 广播、交换机 MAC 地址表等基础概念。

---

## 阶段六：网络安全与工程实践

了解工程上常见的安全与稳定性话题，例如常见端口、常见攻击面、限流、重试、超时、幂等、防重放等。

**建议至少建立如下意识：**

- 为什么服务调用一定要配置连接超时和读超时
- 为什么重试策略必须考虑幂等性
- 为什么跨服务调用要关注连接池、队列堆积和雪崩效应

---

## 阶段七：抓包与排障

**建议实践内容：**

- 使用 Wireshark 观察 TCP 三次握手和四次挥手
- 使用浏览器开发者工具观察 HTTP 请求头、响应头、缓存命中情况
- 使用 ping、traceroute、nslookup 或 dig 排查连通性和 DNS 问题
- 尝试复现一次连接超时、一次读超时、一次 DNS 解析异常

---

## 阶段八：面试复习路线

当基础章节学完后，复习应从"章节式"转向"问题式"。最值得反复训练的问题包括：

- TCP 和 UDP 区别
- 三次握手、四次挥手、TIME_WAIT
- HTTP 与 HTTPS 区别、HTTP 各版本差异
- DNS 解析流程
- 输入 URL 后发生了什么

> 建议每个问题都按照"定义 → 核心机制 → 为什么这样设计 → 工程意义 → 常见追问"的结构来整理答案。

## 四周学习安排

### 第1周：整体框架 + 网络层

- 分层模型、封装/解封装、网络通信全流程
- IP 地址、子网掩码、局域网通信、网关、ARP、ICMP
- 每天尝试口述一次"同网段通信"和"跨网段通信"流程

### 第2周：TCP/UDP

- UDP 特性与适用场景
- TCP 可靠传输机制、三次握手、四次挥手、TIME_WAIT
- 使用抓包工具验证 TCP 报文中的 SYN、ACK、FIN 标志位

### 第3周：HTTP/HTTPS/DNS

- HTTP 报文结构、状态码、请求方法、缓存、Cookie/Session
- HTTPS、TLS、证书、HTTP/2、HTTP/3
- DNS 解析流程与常见故障定位

### 第4周：串讲与面试表达

- 按高频面试题进行口述训练
- 将各协议串成"输入 URL 后发生了什么"的完整链路
- 查缺补漏，并通过抓包和日志练习提升排障能力
