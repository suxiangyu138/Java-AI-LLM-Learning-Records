## 一、基础必考题

### 题目 1：什么是进程和线程？Java 中的线程与操作系统线程是什么关系？（高频 ★★★★★）

**理论核心**：

| 维度 | 进程 | 线程 |
|------|------|------|
| 定义 | 资源分配和调度的基本单位 | 进程内的执行单元，调度最小单位 |
| 内存 | 独立内存空间 | 共享进程内存空间 |
| 切换开销 | 大 | 小 |

**Java 关联**：JDK 1.2 后采用"一对一映射"——一个 Java 线程对应一个操作系统线程，JVM 调用 OS API 创建线程（Linux 下 `pthread_create()`）。

**面试标准回答**：

> "进程是 OS 资源分配的基本单位，有独立内存空间，切换开销大；线程是进程内的执行单元，共享进程资源，切换开销小。Java 线程底层依赖 OS 线程，采用一对一映射。JVM 通过 new Thread() 创建线程时，会调用 OS API 创建对应的 OS 线程，调度由 OS 完成（抢占式调度）。"

**避坑**：

- ❌ 不要混淆"进程与线程的区别"：核心是"资源分配单位"vs"调度单位"
- ❌ 不要认为"Java 线程与 OS 无关"

### 题目 2：死锁是什么？产生死锁的四个必要条件是什么？Java 中如何避免死锁？（高频 ★★★★★）

**死锁的四个必要条件**：

| 条件 | 说明 |
|------|------|
| 互斥 | 资源只能被一个线程占用 |
| 请求与保持 | 持有部分资源，同时请求其他资源 |
| 不可剥夺 | 已分配资源无法被强制剥夺 |
| 循环等待 | 形成循环等待链 |

**Java 中避免死锁的方案**：

1. **破坏循环等待**：给资源排序，所有线程按统一顺序获取锁
2. **破坏请求与保持**：一次性获取所有资源（如 tryLock 获取所有锁）
3. **破坏不可剥夺**：使用可中断锁（如 `lockInterruptibly()`）

### 题目 3：什么是虚拟内存？虚拟内存的作用是什么？对 Java 后端开发有什么影响？（高频 ★★★★）

**核心作用**：

1. **扩大内存空间**：可用内存超过物理内存
2. **实现内存隔离**：每个进程虚拟地址空间独立
3. **优化内存使用**：页面置换算法将不常用页面置换到磁盘

**对 Java 的影响**：

| 影响 | 说明 |
|------|------|
| **正面** | JVM 堆内存可超过物理内存，支持内存密集型应用 |
| **负面** | 堆内存过大导致页面置换频繁，性能下降 |

> **JVM 配置建议**：堆内存大小需结合物理内存，避免过大或过小。

## 二、进阶高频题

### 题目 4：操作系统的 I/O 模型有哪些？Java 的 BIO、NIO、AIO 分别对应哪种 OS I/O 模型？（高频 ★★★★★）

| OS I/O 模型 | 说明 | Java 对应 |
|-------------|------|-----------|
| 阻塞 I/O | 进程阻塞直到 I/O 完成 | **BIO**（InputStream/OutputStream） |
| 非阻塞 I/O | 不阻塞，需轮询 | — |
| I/O 多路复用 | select/poll/epoll 监听多路 I/O | **NIO**（Selector，Linux 下 epoll） |
| 信号驱动 I/O | 信号通知 | — |
| 异步 I/O | 内核完成后回调 | **AIO**（实际使用较少） |

> **易错点**：Java NIO 底层依赖操作系统的 I/O 多路复用（epoll），而非操作系统的非阻塞 I/O。

### 题目 5：什么是 inode？inode 包含哪些信息？Java 中 File 类的哪些方法与 inode 相关？（高频 ★★★★）

**inode（索引节点）**：描述文件属性和存储位置的核心数据结构。

**关键信息**：文件权限、大小、数据块指针、所有者、时间戳（**文件名不存储在 inode 中**）。

**Java 关联**：

| 方法 | 对应 inode 字段 |
|------|----------------|
| `file.length()` | 文件大小 |
| `file.lastModified()` | 修改时间 |
| `file.canRead()/canWrite()` | 文件权限 |
| `file.delete()` | 删除目录项映射 |

> **坑点**：不要说"inode 存储文件名"。文件名存储在目录项中。

### 题目 6：操作系统的进程调度算法有哪些？Java 线程调度与 OS 有什么关系？（高频 ★★★★）

**核心调度算法**：FCFS、SJF、高响应比优先（HRRN）、时间片轮转（RR）、优先级调度。

**Java 关联**：

- Java 线程优先级（1-10）本质是给 OS 优先级"打标签"，供参考
- Java 采用抢占式调度，与 OS 一致
- 实战中不依赖线程优先级保证执行顺序

### 题目 7：什么是内存分页和分段？分页与分段的区别是什么？对 JVM 内存管理有什么影响？（高频 ★★★★）

| 维度 | 分页 | 分段 |
|------|------|------|
| 划分依据 | 按固定大小划分 | 按程序逻辑划分 |
| 大小 | 固定（通常 4KB） | 不固定 |
| 目的 | 提高内存利用率 | 满足程序逻辑需求 |
| JVM 关联 | 内存分配依赖 OS 分页 | 内存分区（堆、栈、方法区）体现分段 |

## 三、高阶难点题

### 题目 8：信号量是什么？如何用信号量实现同步？Java 中如何实现信号量？（高频 ★★★★）

**信号量**：Dijkstra 提出的同步机制，本质是一个计数器。

**核心操作**：P 操作（申请资源，减 1）→ V 操作（释放资源，加 1）

**Java Semaphore 示例**：

```java
import java.util.concurrent.Semaphore;

public class SemaphoreDemo {
    private static final Semaphore semaphore = new Semaphore(5); // 允许5个线程并发

    public static void main(String[] args) {
        for (int i = 0; i < 10; i++) {
            new Thread(() -> {
                try {
                    semaphore.acquire();  // P 操作
                    System.out.println(Thread.currentThread().getName() + " 访问共享资源");
                    Thread.sleep(1000);
                } catch (InterruptedException e) {
                    e.printStackTrace();
                } finally {
                    semaphore.release();  // V 操作
                }
            }, "线程" + i).start();
        }
    }
}
```

### 题目 9：什么是死锁检测？操作系统如何检测死锁？Java 中如何检测和排查死锁？（高频 ★★★★）

**OS 检测方法**：资源分配图算法——构建进程和资源的关系图，简化后判断是否存在无法释放的节点。

**Java 排查方法**：

| 方法 | 命令/工具 | 说明 |
|------|-----------|------|
| **jps + jstack** | `jps -l` → `jstack <PID>` | 最常用，输出包含 "Found one Java-level deadlock" |
| **VisualVM** | jvisualvm.exe | 可视化，自动检测死锁 |
| **Arthas** | `thread -d` | 线上场景，功能强大 |

### 题目 10：操作系统的缓存机制有哪些？对 Java 后端 I/O 性能有什么影响？如何优化？（高频 ★★★★★）

**核心缓存**：

| 缓存 | 说明 |
|------|------|
| **页缓存（Page Cache）** | 缓存磁盘文件内容，减少磁盘 I/O |
| **缓冲区（Buffer）** | 缓解 CPU 与 I/O 设备的速度差异 |

**优化方案**：

- 利用页缓存：使用 NIO 的 MappedByteBuffer 实现零拷贝
- 批量 I/O：在 Java 内存中缓冲，批量写入
- 合理设置刷盘策略：核心业务用 `fsync()` 强制刷盘
