# 计算机操作系统核心知识点

> **核心定位**：操作系统（OS）是计算机系统的核心系统软件，本质是"硬件与软件的桥梁"，负责管理计算机的硬件资源（CPU、内存、存储、外设），调度软件运行，为用户和应用程序提供便捷、高效、安全的运行环境。

## 一、操作系统核心概念

### 1.1 定义与核心作用

**定义**：操作系统是管理和控制计算机硬件与软件资源的系统软件，是计算机系统中所有软硬件资源的管理者和协调者。

**核心作用**：

| 作用 | 说明 |
|------|------|
| **资源管理** | 统一管理 CPU、内存、存储、外设 |
| **提供接口** | 用户接口（GUI/CLI）+ 程序接口（系统调用） |
| **调度与协调** | 调度应用程序运行，协调多程序并发 |

### 1.2 四大基本特征

| 特征 | 说明 |
|------|------|
| **并发** | 多个程序在同一时间段内交替执行（≠ 并行） |
| **共享** | 资源可被多个并发程序共同使用（互斥共享 / 同时共享） |
| **虚拟** | 将物理资源抽象为逻辑资源（虚拟内存、虚拟 CPU） |
| **异步** | 程序执行"走走停停"，OS 保障最终完成 |

### 1.3 核心术语

| 术语 | 定义 |
|------|------|
| **进程** | OS 资源分配和调度的基本单位，程序的一次执行过程 |
| **线程** | 进程内的执行单元，CPU 调度的最小单位 |
| **程序** | 静态指令集合（如 .exe 文件），不占用系统资源 |
| **系统调用** | 应用程序请求 OS 服务的唯一接口 |
| **中断** | CPU 遇到外部事件时暂停当前程序，处理完后再返回 |

## 二、操作系统核心功能（五大核心）

### 2.1 处理机管理（CPU 管理）

**核心任务**：合理调度 CPU 资源，提高 CPU 利用率。

| 调度层次 | 说明 |
|----------|------|
| **高级调度**（作业调度） | 外存作业调入内存，创建进程 |
| **中级调度**（内存调度） | 挂起/激活进程，释放内存 |
| **低级调度**（进程调度） | 就绪队列选择进程分配 CPU（最频繁） |

### 2.2 内存管理

**核心任务**：管理内存资源，提高利用率，保障内存安全。

| 分配方式 | 优点 | 缺点 |
|----------|------|------|
| **连续分配** | 简单 | 内存碎片 |
| **非连续分配**（分页/分段/段页式） | 碎片少，利用率高 | 现代 OS 主流 |

### 2.3 设备管理

**核心任务**：管理外部设备，解决 CPU 速度快、外设速度慢的矛盾。

**核心技术**：

| 技术 | 说明 |
|------|------|
| **中断技术** | 外设完成操作后发中断，CPU 响应处理 |
| **DMA 技术** | 外设直接与内存传输数据，无需 CPU 干预 |

### 2.4 文件管理

**核心任务**：管理外存文件，保障文件安全性和可访问性。

| 核心概念 | 说明 |
|----------|------|
| 文件目录 | 记录文件名、路径、大小、权限等信息 |
| 文件路径 | 绝对路径 / 相对路径 |
| 文件系统 | NTFS、ext4、FAT32 |

### 2.5 用户接口管理

| 接口类型 | 说明 |
|----------|------|
| **图形用户接口（GUI）** | 可视化界面（Windows 桌面） |
| **命令行接口（CLI）** | 通过命令操作（Linux 终端） |
| **系统调用** | 应用程序请求 OS 服务的接口 |
| **库函数** | 对系统调用的封装（如 printf） |

## 三、操作系统关键机制

### 3.1 进程同步机制

**核心问题**：避免多个并发进程访问共享资源时的"竞态条件"。

| 同步工具 | 说明 |
|----------|------|
| **信号量** | P/V 操作，控制并发访问，分互斥信号量和同步信号量 |
| **互斥锁** | 简化的信号量，仅用于互斥 |
| **管程** | 封装共享数据和操作，简化开发 |

### 3.2 死锁机制

**死锁的四个必要条件**（缺一不可）：

| 条件 | 说明 |
|------|------|
| 互斥 | 资源只能被一个进程占用 |
| 请求与保持 | 持有资源同时请求其他资源 |
| 不可剥夺 | 持有资源不能被强制剥夺 |
| 循环等待 | 多个进程形成循环等待链 |

**解决方法**：

| 策略 | 说明 |
|------|------|
| **预防** | 破坏四个必要条件之一 |
| **避免** | 银行家算法 |
| **检测与解除** | 检测死锁后终止进程或剥夺资源 |

### 3.3 中断与异常机制

| 类型 | 来源 | 示例 |
|------|------|------|
| **中断** | 外部设备触发 | 键盘输入、网卡接收数据 |
| **异常** | CPU 内部触发 | 除零、内存访问越界 |

**中断处理流程**：

```
中断请求 → 中断响应 → 保存现场 → 处理中断 → 恢复现场 → 返回原程序
```

## 四、操作系统经典调度算法

### 4.1 先来先服务（FCFS）

- **原理**：按进程到达顺序依次分配 CPU
- **优点**：简单、公平、无饥饿
- **缺点**：短进程等待长进程，效率低

### 4.2 短作业优先（SJF）

- **原理**：优先选择估计运行时间最短的进程
- **优点**：缩短平均响应时间，提高吞吐量
- **缺点**：长进程饥饿，无法准确估计运行时间

### 4.3 时间片轮转（RR）

- **原理**：固定时间片轮流分配 CPU
- **优点**：响应快，适合分时系统
- **缺点**：时间片大小影响效率（过大→FCFS，过小→切换频繁）

### 4.4 优先级调度

- **原理**：优先选择优先级高的进程
- **分类**：抢占式 / 非抢占式
- **缺点**：低优先级可能饥饿

### 4.5 高响应比优先（HRRN）

- **原理**：计算响应比 =（等待时间 + 运行时间）/ 运行时间
- **优点**：兼顾短进程和长进程，无饥饿

### 4.6 多级反馈队列调度

- **原理**：多个就绪队列，不同优先级和时间片
- **优点**：兼顾短进程和长进程，现代 OS 主流

## 五、常见操作系统架构与分类

### 5.1 按架构分类

| 架构 | 特点 | 示例 |
|------|------|------|
| **单内核** | 所有模块运行在核心态，简单高效，稳定性差 | 早期 Linux |
| **微内核** | 核心模块在核心态，其他在用户态，稳定性高 | Mach、QNX |
| **混合内核** | 结合两者优点，兼顾效率和稳定性 | 现代 Linux、macOS、Windows 10+ |

### 5.2 按使用场景分类

| 类型 | 特点 | 示例 |
|------|------|------|
| 桌面操作系统 | 图形化界面、易用性 | Windows、macOS |
| 服务器操作系统 | 稳定性、安全性、并发能力 | CentOS、Ubuntu Server |
| 嵌入式操作系统 | 轻量化、低功耗 | Android、iOS、QNX |
| 实时操作系统（RTOS） | 响应时间确定性 | FreeRTOS、QNX |

## 六、核心总结

操作系统的核心是**资源管理**和**程序调度**，围绕 CPU、内存、外设、文件四大资源，通过进程/线程调度、内存分配、设备控制、文件管理四大功能，实现多程序并发、高效、稳定运行。

| 维度 | 核心内容 |
|------|----------|
| **四大资源** | CPU、内存、外设、文件 |
| **四大功能** | 进程/线程调度、内存分配、设备控制、文件管理 |
| **关键机制** | 进程同步、死锁、中断与异常 |
| **调度算法** | FCFS、SJF、RR、优先级、HRRN、多级反馈队列 |
| **架构分类** | 单内核、微内核、混合内核 |
