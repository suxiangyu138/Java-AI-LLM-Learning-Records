## 1. 进程管理

### 1.1 进程 vs 线程 vs 协程

| 维度 | 进程 | 线程 | 协程 |
|------|------|------|------|
| 定义 | 资源分配的基本单位 | CPU 调度的基本单位 | 用户态的轻量级线程 |
| 资源 | 独立地址空间、文件描述符 | 共享进程地址空间 | 共享线程资源 |
| 切换开销 | 大（切换页表、刷新 TLB） | 中（内核态切换） | 小（用户态切换） |
| 通信方式 | IPC（管道、消息队列、共享内存） | 共享变量（需同步） | Channel / 共享变量 |
| Java 对应 | JVM 进程 | `java.lang.Thread` | 虚拟线程（Project Loom） |

**Java 线程 vs 操作系统线程：**
- Java 线程（传统 `Thread`）与 OS 线程是 1:1 映射
- HotSpot JVM 将 Java 线程映射到内核线程（KLT）
- Java 21 虚拟线程（Virtual Thread）是 M:N 映射，类似协程

### 1.2 进程状态转换

```
         ┌──────────┐
         │   创建    │
         └─────┬────┘
               │ 就绪
         ┌─────▼────┐
    ┌───►│   就绪    │◄──────────┐
    │    └──┬───┬───┘           │
    │调度  │   │ 时间片用完     │
    │    ┌─▼──┐│               │
    │    │运行├┘               │
    │    └─┬──┘                │
    │      │ 等待事件           │
    │   ┌──▼────┐    事件发生   │
    │   │  等待  ├──────────────┘
    │   └──┬────┘
    │      │ 终止
    │   ┌──▼────┐
    └───┤  终止  │
        └───────┘
```

**Java 线程状态对应（Thread.State）：**
| OS 状态 | Java 线程状态 |
|---------|--------------|
| 就绪 + 运行 | `RUNNABLE` |
| 等待 | `WAITING` / `TIMED_WAITING` |
| 阻塞（I/O） | `BLOCKED`（等待锁）/ `RUNNABLE`（I/O 阻塞） |
| 终止 | `TERMINATED` |

### 1.3 进程调度算法

| 调度算法 | 核心思想 | 优缺点 |
|----------|----------|--------|
| FCFS（先来先服务） | 按到达顺序 | 简单但效率低，护航效应 |
| SJF（最短作业优先） | 优先短作业 | 平均等待最小，但需预知运行时长 |
| RR（时间片轮转） | 固定时间片轮流 | 公平性好，时间片太小切换开销大 |
| 优先级调度 | 按优先级排序 | 低优先级可能饥饿（aging 解决） |
| 多级反馈队列 | 多队列 + 动态调整 | **现代 OS 实际使用**（如 Linux CFS） |

### 1.4 进程间通信（IPC）

| 方式 | 特点 | Java 对应 |
|------|------|-----------|
| 管道（Pipe） | 半双工，父子进程 | — |
| 命名管道（FIFO） | 无亲缘关系也可用 | — |
| 消息队列 | 消息的链表，异步 | JMS、RabbitMQ（应用层） |
| 共享内存 | 最快 IPC，需同步 | `MappedByteBuffer` |
| 信号量（Semaphore） | 计数器，控制多资源访问 | `java.util.concurrent.Semaphore` |
| Socket | 跨网络通信 | `java.net.Socket` |
| 信号（Signal） | 异步通知 | — |

## 2. 内存管理

### 2.1 虚拟内存核心概念

```
  虚拟地址                   物理地址
  ┌──────────┐    MMU      ┌──────────┐
  │ 页号 │偏移│ ───────►   │ 帧号 │偏移│
  │    │    │  页表转换    │    │    │
  └──────────┘             └──────────┘
```

**为什么要虚拟内存？**
1. **隔离性**：每个进程有自己的地址空间，互不干扰
2. **扩展性**：程序可使用比物理内存更大的地址空间
3. **安全性**：进程无法直接访问物理内存，防止越界

### 2.2 分页与分段

| 特性 | 分页 | 分段 |
|------|------|------|
| 划分方式 | 固定大小（通常 4KB） | 不等长（代码段/数据段堆栈） |
| 地址结构 | 页号 + 页内偏移 | 段号 + 段内偏移 |
| 碎片 | 内部碎片 | 外部碎片 |
| 可见性 | 对程序员透明 | 对程序员可见 |
| 现代使用 | 主流（多级页表 + TLB） | Intel 兼容模式保留 |

### 2.3 页面置换算法

| 算法 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| OPT（最优） | 淘汰最远将来才使用的页 | 理论最优 | 不可实现（需预知未来） |
| FIFO | 淘汰最早进入的页 | 简单 | Belady 异常 |
| LRU | 淘汰最近最少使用的页 | 接近最优 | 硬件支持成本高 |
| Clock（NRU） | 环形链表 + 访问位 | LRU 的近似，实现简单 | 近似而非精确 |
| LFU | 淘汰使用频率最低的页 | 适合热点数据 | 历史数据影响判断 |

**LinkedHashMap 实现 LRU 缓存：**
```java
// Java 中 LinkedHashMap 天然适合实现 LRU
new LinkedHashMap<K, V>(capacity, 0.75f, true) {
    @Override
    protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
        return size() > capacity;
    }
};
// accessOrder=true 使 get 操作将元素移到链表尾部
```

### 2.4 TLB（Translation Lookaside Buffer）

**核心概念：**
- 页表缓存，位于 CPU 内部，加速虚拟地址→物理地址转换
- 命中率极高（>99%），因程序具有空间局部性和时间局部性
- TLB 缺失代价大（需多次访存查多级页表）

**对后端开发的启示：**
- 数组遍历按行优先（非列优先），利用 TLB 和 Cache 局部性
- Java 二维数组按行优先存储，遍历时外层循环放行，内层放列

## 3. 文件系统

### 3.1 inode 结构

```
inode 包含：
├── 文件类型和权限
├── 所有者信息（UID、GID）
├── 文件大小
├── 时间戳（atime, mtime, ctime）
├── 链接计数
└── 数据块指针
    ├── 直接指针（12 个，指向数据块）
    ├── 一级间接指针
    ├── 二级间接指针
    └── 三级间接指针
```

**关键面试题：为什么删除文件需要目录写权限，而不是文件写权限？**
→ 删除操作修改的是目录文件（删除 dentry 记录），而非文件本身。

### 3.2 硬链接 vs 软链接

| | 硬链接 | 软链接（符号链接） |
|------|--------|-------------------|
| 本质 | 同一个 inode 的多个目录项 | 独立的特殊文件，存目标路径 |
| 跨文件系统 | 不可以 | 可以 |
| 目录 | 不可以（通常） | 可以 |
| 源文件删除后 | 仍可访问（引用计数 > 0） | 失效（断链） |
| 命令 | `ln src dst` | `ln -s src dst` |

### 3.3 文件 IO 缓冲

```
用户空间                内核空间                磁盘
┌─────────┐    write()  ┌──────────┐   pdflush  ┌──────┐
│ 应用程序  │ ─────────► │ 页缓存     │ ────────► │ 磁盘   │
│ Buffer  │ ◄───────── │ Page Cache│ ◄──────── │      │
└─────────┘   read()   └──────────┘           └──────┘
```

**关键点：**
- 写操作通常先写页缓存（write-back），由内核异步刷盘
- `fsync` / `fdatasync` 强制刷盘
- `O_DIRECT` 绕过页缓存直接 I/O

## 4. I/O 模型

### 4.1 五种 I/O 模型

| 模型 | 描述 | Linux 实现 |
|------|------|------------|
| 阻塞 I/O | 进程阻塞直到数据就绪且拷贝完成 | 默认 socket |
| 非阻塞 I/O | 立即返回，需轮询检查 | `O_NONBLOCK` |
| I/O 多路复用 | 阻塞于 select/poll/epoll，事件就绪时通知 | select / poll / epoll |
| 信号驱动 I/O | 数据就绪时内核发 SIGIO 信号 | `fcntl + F_SETOWN` |
| 异步 I/O | 内核完成全部操作后通知进程 | `aio_read`（Linux AIO） |

### 4.2 epoll 原理（高频面试题）

**select vs poll vs epoll：**

| | select | poll | epoll |
|------|--------|------|-------|
| 数据结构 | 位图（fd_set） | 链表（pollfd） | 红黑树 + 就绪链表 |
| FD 上限 | 1024（可重编译） | 无上限 | 无上限 |
| 遍历方式 | 每次轮询所有 FD | 每次轮询所有 FD | **只返回就绪 FD** |
| 内核态拷贝 | 每次调用拷贝全量 FD | 每次调用拷贝全量 FD | 一次注册，持续使用 |
| 复杂度 | O(n) | O(n) | **O(1)**（就绪事件数） |

**epoll 为什么快？**
1. epoll_ctl 注册时使用红黑树管理 FD，增删改 O(log n)
2. 事件发生时，回调将 FD 加入就绪链表
3. epoll_wait 直接从就绪链表取事件，O(1)
4. 无需每次调用都拷贝全量 FD

### 4.3 Java NIO 与 I/O 模型的对应

```java
// Java NIO Selector 底层在 Linux 使用 epoll
Selector selector = Selector.open();           // epoll_create
serverSocketChannel.register(selector, OP_ACCEPT); // epoll_ctl
selector.select();                              // epoll_wait
Set<SelectionKey> keys = selector.selectedKeys(); // 就绪链表
```

**Redis 高性能原理关联：**
- Redis 是单线程 Reactor 模型 + epoll
- 单线程避免锁竞争和上下文切换
- epoll 实现高效事件处理

## 5. 死锁

### 5.1 死锁四个必要条件

1. **互斥**：资源不能共享，一次只能一个进程使用
2. **持有并等待**：进程持有资源的同时等待其他资源
3. **不可抢占**：已分配的资源不能被强制夺走
4. **环路等待**：存在进程-资源的循环等待链

**四个条件必须同时满足才会死锁。破坏任一条件即可预防。**

### 5.2 Java 中模拟死锁

```java
public class DeadLockDemo {
    private static final Object lockA = new Object();
    private static final Object lockB = new Object();

    public static void main(String[] args) {
        new Thread(() -> {
            synchronized (lockA) {
                sleep(100);
                synchronized (lockB) { /* 永远到不了 */ }
            }
        }).start();

        new Thread(() -> {
            synchronized (lockB) {
                sleep(100);
                synchronized (lockA) { /* 永远到不了 */ }
            }
        }).start();
    }
}
```

### 5.3 死锁排查

**jstack 检测死锁：**
```bash
jps -l           # 获取 Java 进程 PID
jstack <PID>     # 输出末尾包含 "Found 1 deadlock"
```

### 5.4 银行家算法

**核心数据结构：**
- `Available`：可用资源向量
- `Max`：每个进程的最大需求矩阵
- `Allocation`：已分配矩阵
- `Need = Max - Allocation`：剩余需求矩阵

**安全性检查：** 是否存在一个安全序列，使得所有进程都能顺利执行完毕。

## 6. Linux 常用命令

### 6.1 系统监控

```bash
# 进程监控
top          # 实时 CPU/内存，交互式
htop         # top 增强版（需安装）
ps aux       # 列出所有进程
pidstat 1    # 每秒输出进程 CPU、内存统计

# 内存监控
free -h      # 内存使用总览
vmstat 1     # 虚拟内存统计（每秒）

# CPU 监控
mpstat -P ALL 1  # 每个 CPU 核心使用率
uptime            # 系统负载（1min, 5min, 15min）

# 磁盘 I/O
iostat -x 1       # 磁盘读写详细统计
iotop             # 按进程排名
```

### 6.2 网络排查

```bash
netstat -tlnp      # 查看监听端口
ss -tlnp           # 替代 netstat（更快）
lsof -i :8080      # 查看占用 8080 端口的进程
tcpdump -i eth0 port 80  # 抓包分析
```

### 6.3 文本处理

```bash
# grep — 文本过滤
grep -r "ERROR" /var/log/       # 递归搜索
grep -c "keyword" file.log      # 计数

# awk — 列处理
awk '{print $1, $3}' file       # 打印第1、3列
awk '$3 > 100' file             # 过滤第3列大于100的行

# sed — 流编辑
sed 's/old/new/g' file          # 替换
sed -n '10,20p' file            # 打印10-20行

# 组合使用
cat access.log | grep 500 | awk '{print $1}' | sort | uniq -c | sort -rn
```

### 6.4 文件与权限

```bash
chmod 755 file    # rwxr-xr-x
chown user:group file
find / -name "*.log" -mtime +7 -delete  # 删除7天前的日志
```

## 7. 后端开发关联

### 7.1 Java 多线程与 OS 线程

| Java 概念 | OS 对应 |
|-----------|---------|
| `synchronized` | Monitor（管程）→ 依赖 OS mutex |
| `Thread.sleep()` | 系统调用让出 CPU |
| `volatile` | 内存屏障 + 缓存一致性协议（MESI） |
| `LockSupport.park()` | `futex` 系统调用（Linux） |
| 虚拟线程（Java 21） | 用户态调度，类似协程 |

### 7.2 JVM 内存与 OS 虚拟内存

| JVM 概念 | OS 对应 |
|----------|---------|
| GC 分代 | 利用分页局部性 |
| 堆外内存（DirectByteBuffer） | `malloc` / `mmap` |
| 内存映射文件 | `mmap` 系统调用 |
| 页大小 | OS 页 4KB，JVM 对象对齐 8 字节 |

### 7.3 线上问题排查思路

```
CPU 飙升 100%：
  top 找高 CPU 进程 PID → top -H -p PID 找线程 → printf '%x' TID 转十六进制
  → jstack PID | grep 十六进制 定位代码行

内存 OOM：
  jmap -heap PID 查看堆信息
  jmap -dump:format=b,file=heap.hprof PID 导出堆转储
  → MAT / JProfiler 分析

磁盘 I/O 高：
  iostat -x 1 → 找到高 util 磁盘
  iotop → 找到高 I/O 进程 → lsof -p PID 查看文件句柄

网络连接异常：
  ss -s 查看 socket 连接数统计
  ss -antp | grep ESTAB 查看所有 TCP 连接
  tcpdump -i eth0 host <IP> 抓包分析
```

## 8. 面试高频题

1. **进程和线程的区别是什么？** → 对照表（资源分配 vs CPU 调度）
2. **Linux 中进程间通信的方式有哪些？** → 管道/消息队列/共享内存/信号量/Socket/信号
3. **虚拟内存是什么？为什么要引入？** → 隔离 + 扩展 + 安全
4. **什么是死锁？如何预防？** → 四个必要条件 + 破坏任一条件
5. **页面置换算法：LRU 怎么实现？** → HashMap + 双向链表（Java LinkedHashMap 天然实现）
6. **epoll 的原理？和 select/poll 的区别？** → 红黑树 + 就绪链表 + O(1)
7. **用户态和内核态的区别？** → 访问权限不同，系统调用切换
8. **零拷贝（Zero-Copy）是什么？** → `sendFile` / `mmap`，数据不经过用户态
9. **什么是上下文切换？如何减少？** → CPU 寄存器和 PC 切换，减少线程数、使用无锁并发
10. **Linux 如何查看某个端口被哪个进程占用？** → `lsof -i :端口` / `ss -tlnp | grep 端口`
