## 一、核心基础：安全原则与威胁模型

### 1.1 四大核心安全原则

> 贯穿开发、测试、部署全生命周期。

| 原则 | 核心思想 | 实践要点 |
|------|----------|----------|
| **最小权限原则** | 应用、用户、进程仅拥有完成任务必需的最小权限 | 数据库账号仅授予业务必需权限；Java 程序使用非 root 用户运行 |
| **纵深防御原则** | 构建多层防护体系，某一层失效时其他层仍能阻挡攻击 | 防御 SQL 注入：输入验证 + 参数绑定 + ORM 框架三重防护 |
| **数据最小化原则** | 仅收集和存储业务必需的数据 | 敏感数据无需完整存储的坚决不存，减少数据泄露风险面 |
| **可审计原则** | 记录关键操作日志，便于安全事件追溯和漏洞排查 | 记录操作人、操作时间、IP 地址、操作内容 |

### 1.2 Java 后端核心安全威胁模型

| 威胁类型 | 典型场景 | 后端危害 |
|----------|----------|----------|
| **SQL 注入** | 用户输入拼接 SQL 语句 | 数据库数据泄露、篡改、删除，甚至获取服务器权限 |
| **跨站脚本（XSS）** | 评论区、表单输入恶意 JS 脚本，后端未过滤直接存储并返回前端 | 窃取 Cookie、会话劫持 |
| **跨站请求伪造（CSRF）** | 伪造用户已登录身份发起恶意请求 | 越权操作，造成财产损失或数据泄露 |
| **权限越界** | 低权限用户访问高权限资源 | 敏感信息泄露、越权操作 |
| **敏感数据泄露** | 密码明文存储、接口明文传输敏感数据 | 用户隐私泄露、账号被盗 |
| **依赖包漏洞** | 使用存在漏洞的第三方依赖（如 Log4j2、FastJSON） | 远程代码执行、服务器被入侵 |
| **配置不当** | 数据库弱密码、Redis 未授权访问、生产环境开启调试模式 | 服务器被入侵、数据泄露 |

## 二、输入验证与注入防御

> Java 后端所有外部输入都可能携带恶意 payload，核心防御思路是**不信任任何外部输入**。

### 2.1 SQL 注入防御

#### 核心防御方案

| 防御方式 | 说明 | 优先级 |
|----------|------|--------|
| **参数化查询（PreparedStatement）** | 将用户输入作为参数传入 SQL，驱动自动转义 | 首选 |
| **ORM 框架** | MyBatis、Hibernate 默认支持参数化查询；注意避免 `${}` 拼接 | 推荐 |
| **输入校验与过滤** | 类型校验、长度限制、特殊字符过滤 | 辅助 |

#### 代码示例

**危险示例（字符串拼接，存在注入风险）：**

```java
// 危险：直接拼接用户输入，攻击者可输入 "1' OR '1'='1" 绕过验证
String sql = "SELECT * FROM user WHERE id = '" + userId + "' AND username = '" + username + "'";
Statement stmt = connection.createStatement();
ResultSet rs = stmt.executeQuery(sql);
```

**安全示例（PreparedStatement 参数化查询）：**

```java
// 安全：使用 PreparedStatement，用户输入作为参数，自动转义特殊字符
String sql = "SELECT * FROM user WHERE id = ? AND username = ?";
PreparedStatement pstmt = connection.prepareStatement(sql);
pstmt.setLong(1, userId);    // 强制类型为 Long，过滤非法字符
pstmt.setString(2, username);
ResultSet rs = pstmt.executeQuery();
```

**MyBatis 安全用法：**

```xml
<!-- 安全：使用 #{} 占位符（参数化查询） -->
<select id="findUser" parameterType="Long" resultType="User">
    SELECT * FROM user WHERE id = #{id}
</select>
```

### 2.2 XSS（跨站脚本）防御

| 防御维度 | 实现方式 |
|----------|----------|
| **输入过滤** | Spring 内置 HtmlUtils 转义 HTML 特殊字符；OWASP AntiSamy 过滤富文本中的恶意脚本标签 |
| **输出转义** | 后端返回前端的用户输入数据必须进行 HTML 转义；JSON 格式确保特殊字符正确转义 |
| **Cookie 安全配置** | 设置 `HttpOnly` 属性禁止 JS 读取 Cookie；设置 `Secure` 属性仅允许 HTTPS 传输 |

### 2.3 其他注入类漏洞防御

| 漏洞类型 | 防御措施 |
|----------|----------|
| **命令注入** | 避免使用 `Runtime.getRuntime().exec()` 执行系统命令；必须使用时严格校验输入参数 |
| **XXE（XML外部实体）** | 禁用外部实体解析；优先使用 JSON 格式传输数据替代 XML |

## 三、认证授权与会话管理

> 认证（验证用户身份）与授权（控制用户访问权限）直接决定"谁能访问系统、能访问哪些资源"。

### 3.1 认证机制

#### 核心安全要点

| 要点 | 最佳实践 |
|------|----------|
| **密码安全存储** | 使用不可逆哈希算法（BCrypt、SHA-256）加盐存储；Spring Security 提供的 `BCryptPasswordEncoder` |
| **弱密码防护** | 密码复杂度要求（长度 >= 8、大小写字母+数字+特殊字符）；错误次数限制（如 5 次锁定） |
| **JWT 安全** | 设置合理过期时间（1-2 小时）；签名密钥保密；禁止在 Token 中存储敏感信息 |

#### 代码示例（JWT 安全配置）

```java
// JWT 工具类核心方法（安全实现）
public class JwtUtils {
    // 签名密钥（需配置在配置文件，禁止硬编码）
    @Value("${jwt.secret}")
    private String secret;

    // 过期时间（1小时，单位：毫秒）
    @Value("${jwt.expiration}")
    private long expiration;

    // 生成 JWT Token
    public String generateToken(String username) {
        Date now = new Date();
        Date expireDate = new Date(now.getTime() + expiration);
        return Jwts.builder()
                .setSubject(username)               // 存储非敏感信息（用户名）
                .setIssuedAt(now)
                .setExpiration(expireDate)
                .signWith(SignatureAlgorithm.HS256, secret)  // 签名加密
                .compact();
    }

    // 解析 JWT Token，验证有效性
    public Claims parseToken(String token) {
        try {
            return Jwts.parser()
                    .setSigningKey(secret)
                    .parseClaimsJws(token)
                    .getBody();
        } catch (Exception e) {
            // Token 过期、篡改时抛出异常，拒绝认证
            throw new UnauthorizedException("Token无效或已过期");
        }
    }
}
```

### 3.2 授权机制

| 方案 | 说明 |
|------|------|
| **RBAC 模型** | 用户-角色-权限关联关系 |
| **Spring Security** | `@PreAuthorize`、`@PostAuthorize` 注解实现方法级/接口级权限控制 |
| **权限校验全覆盖** | 接口层面 + 数据层面全流程校验 |
| **避免前端依赖** | 后端必须独立实现权限校验，不能依赖前端的权限控制 |

#### 代码示例（Spring Security 权限配置）

```java
@Configuration
@EnableWebSecurity
public class SecurityConfig {
    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            // 关闭 CSRF（前后端分离场景通常禁用）
            .csrf(AbstractHttpConfigurer::disable)
            // 会话管理设置为无状态（适配 JWT）
            .sessionManagement(session -> session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            // 接口权限控制
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/auth/**").permitAll()      // 放行登录注册接口
                .requestMatchers("/api/admin/**").hasRole("ADMIN") // 仅管理员可访问
                .requestMatchers("/api/user/**").hasRole("USER")  // 仅普通用户可访问
                .anyRequest().authenticated()                     // 其他接口需认证
            )
            // 添加 JWT 认证过滤器（校验 Token）
            .addFilterBefore(new JwtAuthenticationTokenFilter(), UsernamePasswordAuthenticationFilter.class);
        return http.build();
    }
}
```

### 3.3 会话管理安全

| 要点 | 最佳实践 |
|------|----------|
| **会话 ID 安全** | 随机生成，避免可预测 |
| **会话超时** | 设置合理超时时间（如 30 分钟无操作自动失效） |
| **无状态认证** | 前后端分离场景优先使用 JWT 无状态认证 |
| **会话固定攻击防护** | 登录成功后重新生成会话 ID（或 JWT Token） |

## 四、敏感数据保护

> 敏感数据保护不仅是安全需求，也是合规需求（如《网络安全法》《个人信息保护法》）。

### 4.1 敏感数据加密

#### 加密算法选型

| 加密类型 | 代表算法 | 适用场景 | Java 实现方式 |
|----------|----------|----------|---------------|
| **对称加密** | AES（推荐） | 大数据量加密（文件、流、接口传输） | `javax.crypto.Cipher` + AES/CBC/PKCS5Padding |
| **非对称加密** | RSA、ECC | 小数据加密（密钥传输、数字签名） | `java.security.KeyPairGenerator` |
| **单向哈希** | BCrypt、SHA-256 | 密码存储、数据完整性校验 | `BCryptPasswordEncoder`、`MessageDigest` |

#### 核心加密场景

- **传输加密**：所有接口使用 HTTPS 协议；Tomcat、Nginx 等中间件开启 HTTPS
- **存储加密**：敏感数据存储时加密处理（手机号、身份证号用 AES 加密，密码用 BCrypt 哈希）；密钥存储在配置中心，定期更换

#### 代码示例（AES 加密工具类）

```java
import javax.crypto.Cipher;
import javax.crypto.KeyGenerator;
import javax.crypto.SecretKey;
import javax.crypto.spec.IvParameterSpec;
import javax.crypto.spec.SecretKeySpec;
import java.util.Base64;

/**
 * AES加密工具类（CBC模式+PKCS5Padding填充，企业级常用）
 */
public class AesUtils {

    private static final String ALGORITHM = "AES";
    private static final String TRANSFORMATION = "AES/CBC/PKCS5Padding";
    private static final int KEY_SIZE = 128;

    /**
     * 生成AES密钥（Base64编码）
     */
    public static String generateKey() throws Exception {
        KeyGenerator keyGenerator = KeyGenerator.getInstance(ALGORITHM);
        keyGenerator.init(KEY_SIZE);
        SecretKey secretKey = keyGenerator.generateKey();
        return Base64.getEncoder().encodeToString(secretKey.getEncoded());
    }

    /**
     * AES加密（返回Base64编码的密文）
     */
    public static String encrypt(String plainText, String keyStr, String ivStr) throws Exception {
        byte[] keyBytes = Base64.getDecoder().decode(keyStr);
        SecretKeySpec secretKey = new SecretKeySpec(keyBytes, ALGORITHM);
        byte[] ivBytes = Base64.getDecoder().decode(ivStr);
        IvParameterSpec iv = new IvParameterSpec(ivBytes);
        Cipher cipher = Cipher.getInstance(TRANSFORMATION);
        cipher.init(Cipher.ENCRYPT_MODE, secretKey, iv);
        byte[] cipherBytes = cipher.doFinal(plainText.getBytes("UTF-8"));
        return Base64.getEncoder().encodeToString(cipherBytes);
    }

    /**
     * AES解密
     */
    public static String decrypt(String cipherText, String keyStr, String ivStr) throws Exception {
        byte[] keyBytes = Base64.getDecoder().decode(keyStr);
        SecretKeySpec secretKey = new SecretKeySpec(keyBytes, ALGORITHM);
        byte[] ivBytes = Base64.getDecoder().decode(ivStr);
        IvParameterSpec iv = new IvParameterSpec(ivBytes);
        Cipher cipher = Cipher.getInstance(TRANSFORMATION);
        cipher.init(Cipher.DECRYPT_MODE, secretKey, iv);
        byte[] plainBytes = cipher.doFinal(Base64.getDecoder().decode(cipherText));
        return new String(plainBytes, "UTF-8");
    }
}
```

### 4.2 敏感数据脱敏

#### 常见脱敏场景

| 场景 | 实现方式 | 示例 |
|------|----------|------|
| **接口返回脱敏** | Jackson 注解自定义脱敏序列化器、Hutool 的 `DesensitizedUtil` | 手机号：138\*\*\*\*1234 |
| **日志脱敏** | 日志框架（Logback、Log4j2）过滤器实现，禁止打印敏感信息 | 身份证号：110101\*\*\*\*1234 |

#### 代码示例（Jackson 自定义脱敏）

```java
// 手机号脱敏序列化器
public class PhoneDesensitizer extends StdScalarSerializer<String> {
    public PhoneDesensitizer() {
        super(String.class);
    }

    @Override
    public void serialize(String phone, JsonGenerator gen, SerializerProvider provider) throws IOException {
        if (phone != null && phone.length() == 11) {
            // 脱敏规则：保留前3位和后4位，中间用****代替
            String desensitizedPhone = phone.substring(0, 3) + "****" + phone.substring(7);
            gen.writeString(desensitizedPhone);
        } else {
            gen.writeString(phone);
        }
    }
}

// 实体类中使用
public class User {
    private Long id;
    private String username;

    @JsonSerialize(using = PhoneDesensitizer.class)
    private String phone; // 接口返回时自动脱敏

    // 其他字段...
}
```

## 五、漏洞防护与工程化安全

> Java 后端安全不能仅依赖编码层面的防御，还需结合工程化手段覆盖"开发、测试、部署、运维"全流程。

### 5.1 常见高危漏洞防护

| 漏洞类型 | 风险 | 防御措施 |
|----------|------|----------|
| **文件上传漏洞** | 恶意文件被执行 | 校验文件类型（后缀+文件头双重校验）、限制文件大小、存储在非 Web 访问目录 |
| **反序列化漏洞** | 远程代码执行 | 避免反序列化不可信数据；使用安全序列化框架并及时升级 |
| **依赖包漏洞** | 供应链攻击 | 定期检查依赖包漏洞（Maven Dependency Check、SonarQube） |
| **配置不当漏洞** | 信息泄露、服务器被入侵 | 禁用调试模式、修改默认密码、禁止暴露不必要接口 |

### 5.2 工程化安全实践

#### 安全开发生命周期（SDL）

| 阶段 | 安全实践 |
|------|----------|
| **需求设计** | 识别安全需求，进行威胁建模（如 STRIDE 模型） |
| **编码阶段** | 遵循安全编码规范，使用安全框架 |
| **测试阶段** | 安全测试（静态扫描、动态渗透测试、漏洞扫描） |
| **部署阶段** | 安全配置服务器、中间件、数据库 |
| **运维阶段** | 持续监控安全事件，及时修复漏洞，定期安全审计 |

#### 安全工具应用

| 工具类型 | 工具 | 作用 |
|----------|------|------|
| **静态代码扫描** | SonarQube、FindBugs | 编码阶段扫描安全漏洞（SQL注入、XSS、硬编码密钥） |
| **漏洞扫描** | OWASP ZAP、Nessus | 部署后扫描应用漏洞 |
| **日志审计** | ELK、Graylog | 监控关键操作日志，发现异常行为 |

### 5.3 Java 后端安全编码规范

> 核心要点清单。

- 禁止硬编码敏感信息（密钥、密码、数据库地址等），统一存储在配置中心
- 避免使用 `System.out.println()` 打印日志，统一使用日志框架，且禁止打印敏感信息
- 接口参数必须进行校验（JSR-380 注解：`@NotNull`、`@NotBlank`、`@Pattern`）
- 禁止使用过期、不安全的 API（如 Vector、Hashtable；MD5、DES 加密算法）
- 异常处理需统一，避免抛出详细异常堆栈给前端，仅返回通用错误提示

## 六、总结

> Java 后端安全的核心不是"堆砌安全技术"，而是**将安全融入日常开发的每一个环节**。

| 层次 | 核心要点 |
|------|----------|
| **输入验证** | 第一道防线：不信任任何外部输入 |
| **认证授权** | 身份管控：确保谁可以访问什么 |
| **敏感数据保护** | 全流程加密脱敏，满足合规要求 |
| **工程化防护** | 开发到运维的闭环防护体系 |

对于 Java 后端开发者而言，掌握安全知识点的关键是**理解漏洞原理、掌握防御方法、养成安全编码习惯**，既要抵御外部攻击，也要规避自身开发中的安全隐患，最终实现"数据机密、系统可用、操作合规"的安全目标。
