## 一、TLS/SSL 协议

> TLS（Transport Layer Security）在 TCP 之上提供加密通信。SSL 是其前身（已废弃）。

### 1.1 TLS 在协议栈中的位置

```
应用层  HTTP | SMTP | FTP  ...
       ────────────────────
       TLS（安全层）          ← 这里！
       ────────────────────
传输层  TCP
网络层  IP
```

### 1.2 TLS 1.3 握手（1-RTT）

```
Client                                    Server
  │                                          │
  │  1. ClientHello                          │
  │     支持的密码套件、密钥共享(Key Share)     │
  │     ──────────────────────────────────→   │
  │                                          │
  │  2. ServerHello + 加密扩展                │  (1-RTT)
  │     选定密码套件、密钥共享                 │  ↓
  │     服务器证书 + 证书验证 + Finished       │  此时服务器已可发送加密数据
  │     ←──────────────────────────────────   │
  │                                          │
  │  3. Finished（加密的）                    │
  │     ──────────────────────────────────→   │  此时客户端已可发送加密数据
  │                                          │
  │  ✅ 加密通道建立（0-RTT 模式还可更快）      │
```

### 1.3 TLS 1.2 vs TLS 1.3

| 对比 | TLS 1.2 | TLS 1.3 |
|------|---------|---------|
| 握手 RTT | 2-RTT | 1-RTT（0-RTT 可选） |
| 密钥交换 | RSA / DHE / ECDHE | 仅 ECDHE（前向安全） |
| 密码套件 | 37 种 | 5 种（删掉不安全算法） |
| 对称加密 | CBC / GCM | 仅 AEAD（GCM / ChaCha20-Poly1305） |
| 部署 | 广泛 | 快速普及（2018 RFC） |

### 1.4 密码套件（Cipher Suite）

```
TLS_AES_256_GCM_SHA384
  ├─ TLS：协议版本
  ├─ AES_256_GCM：对称加密算法（AEAD）
  └─ SHA384：哈希/伪随机函数
```

## 二、HTTPS 深入

### 2.1 HTTPS 解决的问题

| 问题 | HTTP（明文） | HTTPS（加密） |
|------|-------------|-------------|
| 窃听 | ✅ 中间人可读所有内容 | ❌ 加密内容不可读 |
| 篡改 | ✅ 中间人可修改内容（运营商插广告） | ❌ MAC 校验防篡改 |
| 冒充 | ✅ DNS 劫持到钓鱼站 | ❌ 证书验证身份 |
| 重放 | ✅ 抓包重放请求 | ❌ 时间戳 + Nonce 防重放 |

### 2.2 证书验证链

```
浏览器验证流程：
1. 收到服务器证书
2. 检查证书是否在有效期内
3. 检查证书是否被吊销（CRL / OCSP）
4. 用中间 CA 公钥验证服务器证书签名
5. 用根 CA 公钥验证中间 CA 证书签名
6. 根 CA 在信任列表中？✅
7. 验证域名是否匹配（SAN / CN）
8. 全部通过 → 信任
```

### 2.3 HSTS（HTTP Strict Transport Security）

```
Strict-Transport-Security: max-age=31536000; includeSubDomains; preload

作用：
1. 浏览器强制 HTTPS，拒绝 HTTP 连接
2. 证书错误 → 用户无法跳过（真正的安全）
3. includeSubDomains → 所有子域名强制
4. preload → 加入浏览器预加载列表（chrome://net-internals/#hsts）
```

### 2.4 HTTPS 优化

| 优化点 | 做法 |
|--------|------|
| **Session 复用** | 首次握手后缓存 Session ID/Ticket，后续 0-RTT |
| **OCSP Stapling** | 服务器主动获取证书状态并随握手发送，省去客户端查询 |
| **证书链优化** | 证书链尽量短（根→中间→服务器，3 级为佳） |
| **证书类型** | ECC 证书（256-bit）比 RSA（2048-bit）快 |

## 三、DDoS 攻击与防护

### 3.1 常见 DDoS 攻击类型

| 类型 | 原理 | OSI 层 | 典型 |
|------|------|--------|------|
| **SYN Flood** | 大量 SYN 包，不完成三次握手，耗尽连接队列 | L4 | `hping3 -S --flood` |
| **UDP Flood** | 大量 UDP 包，占满带宽 | L4 | DNS/NTP 放大 |
| **HTTP Flood** | 大量 HTTP 请求，消耗应用层资源 | L7 | CC 攻击 |
| **DNS 放大** | 伪造源 IP 发小请求给 DNS，DNS 返回大响应给受害者 | L4 | 放大倍数 50x+ |
| **Slowloris** | 慢速发送 HTTP Header，占满连接池 | L7 | 连接不释放 |

### 3.2 防护层次

```
L3/L4 DDoS → 黑洞路由 / IP 清洗 / 云防护（Cloudflare、阿里云高防）
L7 DDoS   → CDN + WAF + 限流 + 验证码 + 源站隐藏
DNS 放大  → 关闭递归查询 / 限制响应速率
```

### 3.3 后端开发能做的基础防护

```java
// ① 接口限流
@RateLimiter(permitsPerSecond = 100)

// ② 请求大小限制
spring.servlet.multipart.max-file-size=10MB

// ③ 连接超时
server.tomcat.connection-timeout=5000

// ④ 并发连接数限制
// Nginx: limit_conn_zone $binary_remote_addr zone=addr:10m;
//        limit_conn addr 10;
```

## 四、防火墙与IDS/IPS

### 4.1 防火墙类型

| 类型 | 工作层 | 能力 | 代表 |
|------|--------|------|------|
| **包过滤** | L3/L4 | 按 IP/端口/协议放行 | iptables、ACL |
| **状态检测** | L3/L4 | 跟踪连接状态（SYN/ESTABLISHED） | iptables + conntrack |
| **应用层代理** | L7 | 代理应用协议，内容过滤 | Nginx 反向代理、WAF |
| **WAF** | L7 | 识别 Web 攻击（SQL 注入/XSS/CSRF） | ModSecurity、阿里云 WAF |

### 4.2 IDS vs IPS

| 对比 | IDS（检测） | IPS（防御） |
|------|------------|------------|
| 部署方式 | 旁路（镜像流量） | 串联（inline） |
| 作用 | 发现攻击 → 告警 | 阻断攻击 |
| 对性能影响 | 无（不经过） | 有（所有流量经过） |
| 代表性工具 | Snort、Suricata | Suricata（IPS 模式） |

## 五、中间人攻击（MITM）

### 5.1 常见 MITM 攻击

| 攻击 | 手法 | 防御 |
|------|------|------|
| **ARP 欺骗** | 伪造 ARP 响应，将流量导向攻击者 | 静态 ARP 绑定、交换机端口安全 |
| **DNS 劫持** | 篡改 DNS 响应，指向钓鱼站 | DNSSEC、DoH（DNS over HTTPS） |
| **SSL 剥离** | 将 HTTPS 降级为 HTTP | HSTS |
| **伪造证书** | 自签证书冒充服务器 | 证书钉扎（Certificate Pinning） |
| **WiFi 钓鱼** | 伪造同名 WiFi，截获流量 | VPN、HSTS |

### 5.2 TLS MITM 的局限性

TLS 通过证书验证基本杜绝了 MITM——除非：
- 攻击者控制了受信任的 CA（极少见）
- 用户在浏览器中点了"继续访问（不安全）"
- 企业内部安装了自定义根证书做 TLS 检查（合法的 MITM）

## 六、DNS 安全

### 6.1 DNS 安全威胁

| 威胁 | 说明 |
|------|------|
| **DNS 劫持** | 篡改 DNS 响应，引导到钓鱼站 |
| **DNS 缓存投毒** | 伪造 DNS 响应注入递归 DNS 缓存 |
| **DNS 隧道** | 利用 DNS 协议传输非 DNS 数据（数据外泄） |
| **DDoS 放大** | 伪造源 IP 发起 DNS 查询，响应放大到受害者 |

### 6.2 防护方案

| 方案 | 作用 |
|------|------|
| **DNSSEC** | 对 DNS 数据进行数字签名，防篡改 |
| **DoH（DNS over HTTPS）** | DNS 查询走 HTTPS，防窃听/劫持 |
| **DoT（DNS over TLS）** | DNS 查询走 TLS |
| **DNS 防火墙** | 过滤恶意域名请求 |

## 七、面试高频问题

**Q1：HTTPS 的握手过程是怎样的？**
> TLS 1.3 简化版：ClientHello（支持的密码套件 + 密钥共享）→ ServerHello（选定密码 + 密钥共享 + 证书）→ 双方各自计算出共享密钥 → Finished → 加密通信。1-RTT。

**Q2：TLS 1.2 和 1.3 有什么区别？**
> 1.3 更快（1-RTT）、更安全（删了 RSA 密钥交换、CBC 等不安全算法）、更简洁（5 种密码套件），强制前向安全。

**Q3：怎么防范 DDoS？**
> 分层防护：CDN/云清洗（L3/L4）+ WAF + 限流（L7）+ 验证码 + IP 黑白名单。后端做好接口限流、连接超时、请求大小限制。

**Q4：DNS 劫持怎么解决？**
> 用 DNSSEC（防篡改）、DoH/DoT（防窃听/劫持），客户端可选信誉好的 DNS（Cloudflare 1.1.1.1、Google 8.8.8.8）。

## 📖 核心要点速记

1. **TLS 1.3**：1-RTT + ECDHE（前向安全）+ AEAD 加密
2. **HTTPS**：加密 + 认证 + 完整性，证书链 + HSTS
3. **DDoS 防护**：云清洗（L4） + WAF+限流（L7），后端做好基础限制
4. **MITM**：TLS 最有效防线，HSTS 防降级
5. **DNS 安全**：DNSSEC（签名）+ DoH/DoT（加密传输）
6. **WAF**：Web 应用防火墙，SQL 注入/XSS/CSRF 第一道防线
