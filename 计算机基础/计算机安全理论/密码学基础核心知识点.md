## 一、密码学核心目标

| 目标 | 含义 | 实现手段 |
|------|------|---------|
| **机密性（Confidentiality）** | 数据不可被未授权者读取 | 对称/非对称加密 |
| **完整性（Integrity）** | 数据不被篡改 | 哈希函数、MAC |
| **认证（Authentication）** | 确认通信双方身份 | 数字签名、证书 |
| **不可否认性（Non-repudiation）** | 发送方不能否认发送过 | 数字签名 |

## 二、对称加密

> 加密和解密使用**同一把密钥**。速度快，适合大量数据加密。

### 2.1 主流算法对比

| 算法 | 密钥长度 | 分组大小 | 安全性 | 性能 | 推荐度 |
|------|---------|---------|--------|------|--------|
| **AES** | 128/192/256 | 128 bit | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ✅ 首选 |
| DES | 56 bit | 64 bit | ⭐（已破解） | ⭐⭐ | ❌ 废弃 |
| 3DES | 168 bit | 64 bit | ⭐⭐⭐ | ⭐ | ❌ 太慢 |
| ChaCha20 | 256 bit | 流加密 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ✅ 移动端 |
| SM4 | 128 bit | 128 bit | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ✅ 国密 |

### 2.2 AES 工作模式

| 模式 | 特点 | 并行 | 需要 IV | 推荐度 |
|------|------|------|---------|--------|
| **ECB** | 每块独立加密，相同明文→相同密文 | ✅ | ❌ | ❌ 不安全 |
| **CBC** | 每块与前一块密文 XOR 再加密 | ❌（解密可并行） | ✅ | ⭐⭐⭐ |
| **CTR** | 计数器模式，转为流加密 | ✅ | ✅ | ⭐⭐⭐⭐ |
| **GCM** | CTR + GMAC 认证，加密+完整性校验 | ✅ | ✅ | ⭐⭐⭐⭐⭐ |

> **生产推荐**：AES-256-GCM，同时提供加密和完整性校验（AEAD）。

### 2.3 对称加密的核心问题：密钥分发

对称加密的前提是双方都有同一把密钥——如何安全地将密钥发给对方？→ 需要非对称加密配合。

## 三、非对称加密

> 加密和解密使用**不同密钥**：公钥加密，私钥解密。速度慢，适合加密少量数据（密钥、签名）。

### 3.1 主流算法对比

| 算法 | 原理 | 密钥长度 | 安全级别 | 用途 |
|------|------|---------|---------|------|
| **RSA** | 大整数分解 | 2048/3072/4096 | ⭐⭐⭐⭐ | 加密、签名 |
| **ECC** | 椭圆曲线离散对数 | 256（等同 RSA 3072） | ⭐⭐⭐⭐⭐ | 加密（ECIES）、签名（ECDSA） |
| **SM2** | 椭圆曲线（国密） | 256 | ⭐⭐⭐⭐⭐ | 国密加密/签名 |
| DH/DHE | 离散对数 | 2048+ | ⭐⭐⭐⭐ | 密钥交换 |
| ECDHE | 椭圆曲线 DH | 256 | ⭐⭐⭐⭐⭐ | TLS 密钥交换首选 |

### 3.2 RSA vs ECC

| 对比 | RSA | ECC |
|------|-----|-----|
| 相同安全级别的密钥长度 | 2048 bit（112 bit 安全） | 256 bit（128 bit 安全） |
| 性能 | 慢（大数运算） | 快（曲线运算） |
| 密钥大小 | 大 | 小（适合移动端） |
| 成熟度 | 极高 | 高 |
| 抗量子计算 | ❌ | ❌ |

### 3.3 非对称加密的缺点

- **速度慢**：比对称加密慢 100~1000 倍
- **不支持大文件**：RSA-2048 最多加密 245 字节

> **实际用法**：非对称加密传输**对称密钥**，对称密钥加密**数据** → TLS 就是这么做的。

## 四、哈希函数

> 任意长度输入 → 固定长度输出。单向不可逆。核心特性：**雪崩效应**（改 1 位输入 → 一半输出位变化）。

### 4.1 主流算法

| 算法 | 输出长度 | 安全性 | 推荐度 |
|------|---------|--------|--------|
| **MD5** | 128 bit | ❌ 已被碰撞攻击 | ❌ 废弃 |
| **SHA-1** | 160 bit | ❌ 已被碰撞攻击 | ❌ 废弃 |
| **SHA-256** | 256 bit | ⭐⭐⭐⭐⭐ | ✅ 推荐 |
| **SHA-512** | 512 bit | ⭐⭐⭐⭐⭐ | ✅ 需要更长输出时 |
| **SHA-3** | 可变 | ⭐⭐⭐⭐⭐ | ✅ 新项目 |
| **BLAKE3** | 可变 | ⭐⭐⭐⭐⭐ | ✅ 性能极高 |
| **SM3** | 256 bit | ⭐⭐⭐⭐⭐ | ✅ 国密 |

### 4.2 哈希的常见用途

| 用途 | 说明 | 示例 |
|------|------|------|
| **密码存储** | 加盐哈希后存储 | `bcrypt(password + salt)` |
| **文件完整性** | 下载文件后对比哈希值 | SHA-256 校验 |
| **数字签名** | 对哈希值签名（不对原文） | RSA-SHA256 |
| **区块链** | 区块链接、Merkle Tree | Bitcoin（SHA-256） |
| **数据去重** | 哈希值相同的文件视为重复 | 云存储去重 |

### 4.3 密码哈希（慢哈希）

> 密码哈希要**慢**——增加暴力破解成本。

| 算法 | 特点 | 推荐度 |
|------|------|--------|
| **bcrypt** | 自带 salt + 可调节迭代次数 | ⭐⭐⭐⭐⭐ |
| **scrypt** | 内存密集，抵抗 GPU/ASIC 攻击 | ⭐⭐⭐⭐⭐ |
| **Argon2** | 2015 年密码哈希竞赛冠军 | ⭐⭐⭐⭐⭐ |
| **PBKDF2** | 基于 HMAC，NIST 推荐 | ⭐⭐⭐⭐ |

> **生产推荐**：bcrypt（兼容性好）或 Argon2id（最新最安全）。

## 五、数字签名与证书

### 5.1 数字签名流程

```
签名：
  原文 → SHA-256 → 哈希值 → 私钥加密 → 数字签名

验证：
  原文 → SHA-256 → 哈希值 A
  数字签名 → 公钥解密 → 哈希值 B
  比较 A == B？ → 相等则验证通过
```

> 数字签名 = 反过来的非对称加密：**私钥签名，公钥验证**。

### 5.2 PKI（公钥基础设施）

```
CA（证书颁发机构）
  │
  ├─ 根证书（自签名，预装在操作系统/浏览器中）
  │   └─ 中间 CA 证书
  │       └─ 服务器证书（域名）
  │
  └─ 证书链验证：
      服务器证书 ← 中间 CA ← 根 CA（信任锚点）
```

### 5.3 X.509 证书内容

| 字段 | 说明 |
|------|------|
| Subject | 证书持有者（域名） |
| Issuer | 颁发者（CA） |
| Validity | 有效期（Not Before / Not After） |
| Public Key | 公钥 |
| Signature | CA 对证书的签名 |
| SAN | Subject Alternative Name（多域名支持） |

## 六、密钥交换协议

> 如何在不安全的信道上**安全地协商出共享密钥**？

### 6.1 DH（Diffie-Hellman）密钥交换

```
Alice                              Bob
  │                                  │
  │  1. 公开参数 g, p（大素数）       │
  │                                  │
  │  2. Alice 生成私钥 a，计算 A=g^a mod p
  │     发送 A →                     │
  │                                  │
  │  3. Bob 生成私钥 b，计算 B=g^b mod p
  │                      ← 发送 B    │
  │                                  │
  │  4. 共享密钥 K = B^a mod p        │
  │                     K = A^b mod p│
  │                                  │
  │  g^ab mod p 双方都知道，窃听者不知道（离散对数难解）
```

### 6.2 ECDHE（TLS 1.3 默认）

> 椭圆曲线 + 临时（Ephemeral）密钥 = 前向安全性（Forward Secrecy）。

即使服务器私钥泄露，历史会话也无法解密——因为每次会话用的密钥是临时的，用完即销毁。

## 七、Java 密码学实践

### 7.1 AES-GCM 加密

```java
// Java 加密示例
import javax.crypto.Cipher;
import javax.crypto.spec.GCMParameterSpec;
import javax.crypto.spec.SecretKeySpec;

// 加密
Cipher cipher = Cipher.getInstance("AES/GCM/NoPadding");
GCMParameterSpec gcmSpec = new GCMParameterSpec(128, iv); // 96-bit IV 推荐
cipher.init(Cipher.ENCRYPT_MODE, new SecretKeySpec(key, "AES"), gcmSpec);
byte[] ciphertext = cipher.doFinal(plaintext);
// ciphertext 自带 GMAC 认证标签（最后 16 字节）
```

### 7.2 密码哈希（bcrypt）

```java
// Spring Security 自带 BCryptPasswordEncoder
BCryptPasswordEncoder encoder = new BCryptPasswordEncoder();
String hash = encoder.encode("mypassword");
// $2a$10$N9qo8uLOickgx2ZMRZoMyeIjZAgcfl7p92ldGxad68LJZdL17lhWy
//  $2a$ → bcrypt, 10 → cost factor (2^10 次迭代)

boolean matches = encoder.matches("mypassword", hash); // true
```

### 7.3 安全随机数

```java
// ❌ 错误：伪随机，可预测
Random random = new Random();

// ✅ 正确：加密安全随机数
SecureRandom secureRandom = SecureRandom.getInstanceStrong();
byte[] randomBytes = new byte[32];
secureRandom.nextBytes(randomBytes);
```

## 八、面试高频问题

**Q1：对称加密和非对称加密的区别？应用场景？**
> 对称：同密钥加解密，快，适合大数据 → AES。非对称：公私钥对，慢，适合密钥交换和签名 → RSA/ECC。TLS 用非对称交换对称密钥，再用对称加密传输数据。

**Q2：HTTPS 中用了哪些密码学技术？**
> ① 非对称加密（ECDHE）交换对称密钥 ② 对称加密（AES-GCM）加密数据 ③ 哈希（SHA-256）做完整性校验 ④ 数字签名（ECDSA/RSA）验证证书 ⑤ PKI 证书链做身份认证。

**Q3：为什么要加盐（salt）存储密码？**
> ① 防止彩虹表攻击（预计算哈希→密码）② 相同密码不同用户哈希值不同（防止一次泄露全暴露）③ bcrypt/scrypt/Argon2 自带 salt。

**Q4：什么是前向安全性（Forward Secrecy）？**
> 服务器私钥泄露后，历史会话仍然无法解密。实现方式：每次会话用临时密钥（DHE/ECDHE），用完即销毁。TLS 1.3 强制要求。

## 📖 核心要点速记

1. **对称加密**：AES-256-GCM（首选），加密+认证一体化
2. **非对称加密**：RSA（老牌）/ ECC（新锐），用于密钥交换和签名
3. **哈希**：SHA-256（通用）/ bcrypt（密码）/ Argon2（最安全）
4. **签名**：私钥签名 + 公钥验证 = 防篡改 + 防否认
5. **密钥交换**：ECDHE（前向安全）→ TLS 1.3 默认
6. **证书**：CA 背书绑定域名与公钥，基于信任链验证
7. **不要自己造轮子**：用成熟的库（JCA/Bouncy Castle/Spring Security）
