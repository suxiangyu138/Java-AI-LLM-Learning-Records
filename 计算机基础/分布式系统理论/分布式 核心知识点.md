## 一、分布式基础概念

### 1. 定义与核心特征

- **分布式系统**：由多个**独立自治节点**通过网络互联，协同完成统一任务的系统，节点无集中强管控。
- **四大核心特征**：异构、异地、异步、并发
- **核心痛点**：网络不可靠、时钟不一致、节点故障、数据一致性、网络分区

### 2. 分布式三大问题

#### CAP 定理

| 维度 | 说明 |
|------|------|
| **C 一致性** | 所有节点同一时刻数据完全相同 |
| **A 可用性** | 任意请求都能正常响应 |
| **P 分区容错** | 网络分区发生时系统仍可运行 |
| **结论** | **三者不可同时满足**，分布式系统必须保证 P，只能在 C 和 A 之间取舍 |

#### BASE 理论（互联网分布式主流）

> 弱一致性理论，牺牲强 C 换高 A。

| 维度 | 说明 |
|------|------|
| **BA 基本可用** | 故障时保证核心功能可用，允许降级 |
| **S 软状态** | 副本数据允许短暂不一致 |
| **E 最终一致性** | 一段时间后，所有副本数据自动达成一致 |

#### ACID vs CAP / BASE

| 对比维度 | ACID | BASE |
|----------|------|------|
| 适用场景 | 单机事务 | 分布式事务 |
| 一致性 | 强一致、强隔离 | 高可用、最终一致 |
| 典型应用 | 传统数据库 | 微服务、大数据 |

## 二、分布式通信

### 1. 通信模型

| 模型 | 特点 |
|------|------|
| **同步通信** | 调用阻塞等待响应（RPC） |
| **异步通信** | 发送后立即返回，通过回调/消息通知结果（MQ） |

### 2. 主流通信方案

| 方案 | 说明 | 代表技术 |
|------|------|----------|
| **RPC** | 跨服务进程调用，屏蔽网络细节 | Dubbo、gRPC、Spring Cloud OpenFeign |
| **消息队列 MQ** | 异步解耦、削峰填谷、流量消峰 | RabbitMQ、RocketMQ、Kafka |
| **HTTP / REST** | 跨语言、简单通用，性能低于 RPC | RestTemplate、WebClient |

## 三、分布式一致性

### 1. 一致性分级

| 级别 | 说明 |
|------|------|
| **强一致性** | 写完成后，所有读请求立刻看到最新数据 |
| **弱一致性** | 短暂数据不一致 |
| **最终一致性** | 短暂延迟后数据自动一致 |

### 2. 经典一致性算法

| 算法 | 特点 | 核心机制 |
|------|------|----------|
| **Raft** | 主流选主+同步算法，易于落地 | Leader（写）、Follower（读）、Candidate（竞选）；任期、心跳、日志复制、过半投票 |
| **Paxos** | 理论性强，分布式一致性基础算法，实现复杂 | 提议者、接受者、学习者角色 |
| **ZAB 协议** | Zookeeper 专用，基于 Paxos 改进，保证顺序一致性 | 原子广播、崩溃恢复 |

## 四、分布式事务

### 1. 问题本质

跨多个服务/数据库的操作，无法单机本地事务保证原子性。

### 2. 主流解决方案

| 方案 | 原理 | 优缺点 |
|------|------|--------|
| **2PC 两阶段提交** | 阶段1：准备阶段（预提交）；阶段2：提交/回滚 | 同步阻塞、协调者单点故障、数据锁定时间长 |
| **3PC 三阶段提交** | 增加预提交阶段，降低超时风险 | 优化 2PC 阻塞问题 |
| **TCC 补偿事务** | Try（资源校验+锁定）→ Confirm → Cancel | 业务侵入高，适合核心金融场景 |
| **本地消息表** | 本地事务+消息落库，定时任务轮询投递 | 最终一致，实现简单 |
| **可靠消息 MQ** | 半消息、投递确认、死信重试 | 解耦分布式事务 |
| **SAGA 模式** | 长事务拆分，分段执行，失败逆向补偿 | 适合长流程业务 |

## 五、分布式锁

### 1. 作用

解决多节点并发竞争共享资源，替代单机锁（`synchronized`、`Lock`）。

### 2. 实现方案

| 方案 | 核心原理 | 优缺点 |
|------|----------|--------|
| **Redis 分布式锁** | `SET NX EX` 原子加锁，Lua 脚本保证解锁原子性 | 性能高；问题：锁超时、主从延迟、锁续期（看门狗） |
| **Zookeeper 分布式锁** | 临时有序节点 + 监听机制 | 可靠性高，性能略低 |
| **数据库分布式锁** | 悲观锁（行级锁）、乐观锁（版本号、时间戳） | 实现简单，性能一般 |

## 六、分布式协调与治理

### 1. 服务注册与发现

- **原理**：服务启动注册 → 注册中心维护列表 → 消费者拉取/订阅
- **组件**：Nacos、Eureka、Consul、Zookeeper

### 2. 负载均衡

| 分类 | 实现 | 算法 |
|------|------|------|
| **客户端负载** | Nacos、Dubbo 内置 | 轮询、随机、加权、一致性哈希、最小连接数 |
| **服务端负载** | Nginx、网关 | |

### 3. 限流、熔断、降级

| 机制 | 说明 |
|------|------|
| **限流** | 限制 QPS/并发，防止流量打垮系统（令牌桶、漏桶） |
| **熔断** | 依赖服务故障时快速断开，避免级联雪崩 |
| **降级** | 非核心功能关闭，保障核心业务 |

### 4. 分布式配置中心

统一管理多环境配置，动态刷新：Nacos、Apollo、Spring Cloud Config

## 七、分布式数据存储

### 1. 分库分表

| 拆分方式 | 说明 |
|----------|------|
| **垂直拆分** | 按业务模块拆分库/表 |
| **水平拆分** | 按用户 ID、时间等字段分片 |
| **分片算法** | 哈希分片、范围分片 |

### 2. 数据副本

多节点存储同一份数据，提升可用性与容灾。

### 3. 读写分离

| 角色 | 职责 | 注意事项 |
|------|------|----------|
| 主库 | 写操作 | 主从延迟需关注 |
| 从库 | 读操作 | 缓解数据库压力 |

## 八、分布式经典理论补充

| 概念 | 说明 | 解决方案 |
|------|------|----------|
| **脑裂** | 集群网络分裂，出现多个主节点，数据混乱 | 过半选举、心跳检测 |
| **幂等性** | 重复请求结果一致，防止重试、消息重复消费 | 唯一 ID、全局序列号、状态机、防重表 |
| **数据分片与路由** | 解决单机存储上限 | 大数据、分布式数据库核心基础 |
