《深入理解计算机系统》（CSAPP）**附录A 错误处理**，核心是补充计算机系统中"异常控制流"的延伸知识，聚焦系统级错误与应用级错误的处理机制。

> **核心目标**：将"不可预测的错误"转化为"可控制的执行流程"，避免程序因错误直接崩溃，为问题排查提供可追溯的信息。

## 一、错误处理的核心定位与本质

### 错误与异常的核心区别

| 对比维度 | 错误（Error） | 异常（Exception） |
|----------|---------------|-------------------|
| **触发来源** | 软件层面（系统调用失败、输入非法） | 硬件/内核层面（中断、陷阱、故障） |
| **处理主体** | 应用程序（程序员主动编写处理逻辑） | 内核/硬件（预设的异常处理程序） |
| **可处理性** | 大部分可处理（重试、降级、提示） | 部分可处理，部分不可处理 |
| **核心场景** | 文件操作、网络通信、内存分配 | 硬件中断、指令错误、内核态异常 |

### 错误处理的核心价值

1. **避免程序崩溃**：将错误拦截在可控范围内
2. **简化问题排查**：通过错误码和日志定位问题
3. **保障系统健壮性**：应对资源不足、输入非法等场景
4. **规范程序行为**：统一处理逻辑，提升代码可读性

## 二、Unix-Linux系统级错误处理

### （一）核心机制：错误码（errno）

`errno` 是 Unix/Linux 系统中用于标识"错误类型"的全局整数变量，定义在 `<errno.h>` 中。

**核心规则：**

- 只有当系统调用/库函数执行**失败**时，`errno` 才会被设置
- `errno` 的值非 0 即表示错误
- `errno` 是线程局部变量（现代系统中），避免多线程环境下的混淆

**常用错误码：**

| 错误码 | 含义 | 典型场景 |
|--------|------|----------|
| `ENOENT` | No such file or directory | 打开不存在的文件 |
| `EACCES` | Permission denied | 读取没有权限的文件 |
| `ENOMEM` | Cannot allocate memory | `malloc()` 分配失败 |
| `EBADF` | Bad file descriptor | 使用已关闭的文件描述符 |
| `EINTR` | Interrupted system call | 系统调用被信号中断 |
| `EIO` | I/O error | 磁盘读写失败 |

### （二）错误信息的获取

**strerror 函数：**

```c
char *strerror(int errnum);
// 返回对应的错误描述字符串
```

**perror 函数：**

```c
void perror(const char *msg);
// 自动获取当前 errno，输出 "msg: 错误描述" 到标准错误流
```

**示例：**

```c
#include <stdio.h>
#include <errno.h>
#include <string.h>

int main() {
    FILE *fp = fopen("nonexistent.txt", "r");
    if (fp == NULL) {
        // 方式1：使用strerror
        printf("fopen failed: %s\n", strerror(errno));
        // 方式2：使用perror
        perror("fopen failed");
        return 1;
    }
    fclose(fp);
    return 0;
}
```

### （三）系统调用的错误处理范式

```c
// 统一范式：检查返回值 -> 获取errno -> 处理错误
ssize_t n = read(STDIN_FILENO, buf, sizeof(buf));
if (n == -1) {
    if (errno == EINTR) {
        // 系统调用被中断，重试
        n = read(STDIN_FILENO, buf, sizeof(buf));
    } else {
        perror("read failed");
        return 1;
    }
}
```

### （四）错误处理包装函数

由于系统调用的错误处理逻辑高度重复，可以封装一层"包装函数"：

```c
#include <fcntl.h>
#include <errno.h>
#include <stdio.h>
#include <stdlib.h>

// open()的包装函数，失败时自动输出信息并终止程序
int Open(const char *pathname, int flags, mode_t mode) {
    int fd = open(pathname, flags, mode);
    if (fd == -1) {
        perror("open failed");
        exit(EXIT_FAILURE);
    }
    return fd;
}

// 上层代码直接使用包装函数
int main() {
    int fd = Open("test.txt", O_RDONLY, 0);
    // 后续操作...
    close(fd);
    return 0;
}
```

## 三、编程语言层面的错误处理

### C 语言错误处理核心原则

| 原则 | 说明 |
|------|------|
| 明确返回值语义 | 函数需明确"成功返回什么、失败返回什么" |
| 及时检查错误 | 每次系统调用后都需检查返回值 |
| 提供错误上下文 | 错误信息需包含"哪里出错、为什么出错" |
| 避免忽略错误 | 即使是"看似无关"的错误也需处理 |

### 与C++/Java异常机制的对比

| 语言 | 错误处理方式 | 特点 |
|------|-------------|------|
| **C** | 返回值 + errno | 手动、显式，完全由程序员控制 |
| **C++** | try-catch-throw | 将错误处理与业务逻辑分离，底层仍依赖 errno |
| **Java** | Checked/Unchecked 异常 | 通过 JVM 异常表实现，与系统级错误隔离 |

## 四、常见错误类型及处理策略

| 错误类型 | 常见场景 | 处理策略 |
|----------|----------|----------|
| **资源类错误** | 内存分配失败、文件打开失败 | 检查返回值，尝试重试或优雅退出 |
| **系统调用中断（EINTR）** | 系统调用被信号中断 | 重新执行系统调用（可恢复） |
| **输入/输出错误** | 硬件故障、无效 fd、磁盘满 | 检查 fd 有效性，输出错误信息 |
| **权限错误** | 访问权限不足 | 提示用户提升权限 |

### 系统调用中断错误（EINTR）的标准处理

```c
ssize_t Read(int fd, void *buf, size_t count) {
    ssize_t n;
    while (1) {
        n = read(fd, buf, count);
        if (n == -1) {
            if (errno == EINTR) {
                continue;  // 被中断，重试
            } else {
                perror("read failed");
                return -1;
            }
        }
        return n;
    }
}
```

## 五、错误处理的最佳实践

1. **最小化侵入性**：错误处理逻辑应与业务逻辑分离
2. **信息精准完整**：包含"错误位置、错误类型、错误原因"
3. **区分可恢复与不可恢复错误**：
   - 可恢复错误（如 `EINTR`）：尝试重试
   - 不可恢复错误（如 `ENOMEM`）：优雅退出
4. **避免忽略错误**：即使是 `close()` 失败也可能导致资源泄漏
5. **适配多线程环境**：使用线程局部的 `errno`
6. **结合断言与错误处理**：断言用于开发阶段逻辑检查，错误处理用于运行时
