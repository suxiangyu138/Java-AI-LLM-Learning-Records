# 计算机存储与外设：输入输出

> **计算机存储与外设的输入输出（I/O）是 Java 后端开发的核心底层支撑。后端系统的所有数据交互——数据库读写、文件上传下载、网络通信、日志输出——本质上都是与存储设备、外部外设的 I/O 操作。**

## 一、核心理论基础

### 1.1 存储体系分类

| 类型 | 特点 | Java 后端关联 |
|------|------|--------------|
| **主存（内存）** | 速度快、易失性 | JVM 堆、栈、方法区 |
| **辅助存储（磁盘/SSD）** | 速度慢、非易失性 | 文件 IO、数据库 IO |
| **外部存储（U 盘/NAS/云存储）** | 可扩展、非易失性 | OSS SDK、网络 IO |

### 1.2 外设分类

| 外设类型 | 常见设备 | 后端开发 IO 场景 |
|---------|---------|----------------|
| **存储类外设** | 磁盘、SSD、NAS、云存储 | 数据持久化、文件读写、备份 |
| **网络类外设** | 网卡、路由器 | 接口通信、跨服务调用 |
| **输入输出类外设** | 键盘、打印机 | 控制台输入、日志输出 |

### 1.3 I/O 核心原理

I/O 的本质是"数据在主机与外设之间的传输"，核心瓶颈在于"主机速度与外设速度不匹配"。

#### 1.3.1 程序控制 I/O（PIO）

CPU 全程参与数据传输，效率极低。

> **Java 关联**：早期 BIO（`InputStream`、`OutputStream`）本质上是 PIO 模式的封装。

#### 1.3.2 直接内存访问（DMA）

DMA 控制器负责数据传输，CPU 无需等待。

> **Java 关联**：NIO、AIO 底层依赖 DMA 机制，通过 Buffer 实现内存与外设的直接数据传输。

## 二、Java 后端核心 I/O 技术

### 2.1 文件 I/O

#### 2.1.1 传统 I/O（BIO）：简单场景首选

```java
// 读取配置文件
try (InputStream is = new FileInputStream("src/main/resources/application.properties")) {
    Properties props = new Properties();
    props.load(is);
    String url = props.getProperty("spring.datasource.url");
} catch (IOException e) {
    e.printStackTrace();
}
```

**实战注意点**：
- 使用 `try-with-resources` 自动关闭流资源，避免资源泄露
- 传统 IO 每次读写触发 CPU 干预，大文件时效率低

#### 2.1.2 NIO（非阻塞 I/O）：高并发首选

```java
// 使用 NIO 写入大文件
try (FileChannel channel = new FileOutputStream("largeFile.txt").getChannel()) {
    ByteBuffer buffer = ByteBuffer.allocate(1024);
    // ... 写入数据
    buffer.flip();
    channel.write(buffer);
    buffer.clear();
}
```

**优化技巧**：
- 缓冲区大小建议设为 2 的幂次方（如 1024、4096）
- 使用 `FileChannel.transferTo/transferFrom` 实现零拷贝

### 2.2 网络 I/O

#### 2.2.1 BIO 服务器

```java
// BIO 服务器
ServerSocket serverSocket = new ServerSocket(8080);
Socket clientSocket = serverSocket.accept(); // 阻塞等待
InputStream is = clientSocket.getInputStream();
byte[] buffer = new byte[1024];
int len = is.read(buffer);
```

#### 2.2.2 NIO 服务器（多路复用）

```java
// NIO 服务器核心
Selector selector = Selector.open();
ServerSocketChannel serverChannel = ServerSocketChannel.open();
serverChannel.bind(new InetSocketAddress(8080));
serverChannel.configureBlocking(false);
serverChannel.register(selector, SelectionKey.OP_ACCEPT);

while (true) {
    selector.select(); // 阻塞等待事件
    Iterator<SelectionKey> iterator = selector.selectedKeys().iterator();
    while (iterator.hasNext()) {
        SelectionKey key = iterator.next();
        iterator.remove();
        // 处理事件...
    }
}
```

> **实战核心**：后端开发通常使用 Netty 框架（基于 NIO 封装）来实现高并发网络 I/O。

#### 2.2.3 AIO（异步 I/O）

AIO 底层基于 DMA 机制，CPU 发起请求后直接返回，传输完成后系统通知 CPU。适合高吞吐量、低延迟场景。

### 2.3 数据库 I/O

```java
// MyBatis 数据库 IO 操作
try (SqlSession session = sqlSessionFactory.openSession()) {
    UserMapper userMapper = session.getMapper(UserMapper.class);
    User user = userMapper.selectById(1);
}
```

**数据库 IO 优化技巧**：

| 技巧 | 说明 |
|------|------|
| **使用连接池** | HikariCP、Druid 复用连接 |
| **开启缓存** | MyBatis 一级/二级缓存减少磁盘 IO |
| **优化 SQL** | 避免全表扫描，使用索引 |
| **分库分表** | Sharding-JDBC 减少单磁盘 IO 压力 |

## 三、Java 后端 I/O 实战痛点与解决方案

### 3.1 痛点 1：I/O 阻塞导致接口响应缓慢

**解决方案**：
- 替换 I/O 模型：BIO → NIO/Netty
- 使用异步 I/O：`CompletableFuture`、Spring Async
- 优化缓冲区大小，减少数据拷贝次数

### 3.2 痛点 2：I/O 资源泄露导致系统崩溃

**解决方案**：
- 使用 `try-with-resources` 自动关闭资源
- 使用连接池管理数据库、网络连接
- 代码审计重点检查资源关闭逻辑

### 3.3 痛点 3：海量数据 I/O 导致内存溢出

**解决方案**：
- 分批次处理（NIO 缓冲区、分页查询）
- 流式处理（Java 8 Stream API、MyBatis Cursor）
- 调整 JVM 堆内存参数

### 3.4 痛点 4：网络 I/O 异常导致服务不稳定

**解决方案**：
- 设置超时时间（连接超时、读取超时）
- 实现重试机制（Spring Retry、Resilience4j）
- 使用 Netty 的异常处理、断线重连、心跳检测
