《深入理解计算机系统》（CSAPP）中 **"信息的表示和处理"** 是整个计算机系统的底层基石——所有程序的运行、数据的存储与传输，本质都是对"信息"的二进制表示与操作。

> **核心价值**：打破"高级语言抽象"，让开发者理解数据在计算机底层如何存储、运算、转换，以及这些底层机制如何影响程序的正确性、性能与安全性。

---

## 一、核心前提：信息的二进制本质与计算机硬件基础

CSAPP 开篇即强调：计算机中所有信息（数值、字符、图像、指令等）最终都以二进制（0 和 1）形式存储和传输。

### 1.1 比特、字节与字长

| 概念 | 定义 | 说明 |
|------|------|------|
| **比特（bit）** | 最小的信息单位，0 或 1 | 对应电路的高电平和低电平 |
| **字节（Byte）** | 最小可寻址存储单位，8 比特 | 可表示 0~255（无符号）或 -128~127（有符号） |
| **字长（Word Size）** | CPU 一次能处理的二进制数据位数 | 决定寻址能力和数据处理效率 |

> 现代计算机多为 64 位字长，但仍兼容 32 位程序，其核心差异在于"可处理的数据范围"和"寻址能力"。

### 1.2 大端与小端存储（字节序）

当信息占用多个字节时，字节在内存中的存储顺序有两种方式：

| 字节序 | 存储方式 | 示例（0x12345678） |
|--------|----------|-------------------|
| **大端（Big-Endian）** | 高位字节存低地址，低位字节存高地址 | `0x12`（高位）在低地址，`0x78`（低位）在高地址 |
| **小端（Little-Endian）** | 低位字节存低地址，高位字节存高地址 | `0x78`（低位）在低地址，`0x12`（高位）在高地址 |

> **核心结论**：x86 架构采用小端存储，ARM 架构可切换，网络传输默认采用大端字节序。跨平台传输多字节数据时，必须进行字节序转换（如 `htonl`、`htons` 等函数）。

## 二、数值的表示：无符号数与有符号数

### 2.1 无符号数的表示

无符号数（unsigned）仅表示非负整数：

- **取值范围**：n 比特无符号数范围为 0 ~ 2ⁿ - 1
- **表示方法**：直接将十进制数转换为二进制，高位补 0

> CSAPP 提醒：C 语言中 `unsigned` 类型的变量，即使赋值为负数，也会被自动转换为对应的无符号数。

### 2.2 有符号数的表示：补码（Two's Complement）

现代计算机统一采用 **补码表示法**。

**补码的定义（n 比特）：**

- **符号位**：最高位为符号位，0 表示正数，1 表示负数
- **正数的补码**：与原码一致
- **负数的补码**：先取原码的反码（符号位不变，其余位取反），再加 1

**补码的核心优势：**

| 优势 | 说明 |
|------|------|
| **消除 0 的二义性** | 补码中 0 只有一种表示（00000000） |
| **减法统一为加法** | `5 - 3 = 5 + (-3)`，无需单独设计减法电路 |
| **取值范围更合理** | n 比特补码范围为 -2ⁿ⁻¹ ~ 2ⁿ⁻¹ - 1 |

### 2.3 无符号数与有符号数的转换（CSAPP易错点）

```c
// 32位系统中，unsigned int 和 int 混合运算
unsigned int u = 10;
int i = -20;
if (u + i > 0) {
    printf("正\n");  // 实际输出：正
} else {
    printf("负\n");
}
```

> **原因解析**：`-20` 的补码为 `0xFFFFFFEC`，转换为无符号数后为 4294967276，`u + i = 10 + 4294967276 = 4294967286`，因此输出"正"。

## 三、数值运算：溢出、截断与舍入

### 3.1 溢出（Overflow）

| 溢出类型 | 处理方式 | 示例 |
|----------|----------|------|
| **无符号数溢出** | 采用"模运算"，结果对 2ⁿ 取模 | 8 比特无符号数 300 -> 300 - 256 = 44 |
| **有符号数溢出** | 结果"失真"，计算机不会主动提示 | 127 + 1 = -128（正溢出） |

> CSAPP 提醒：有符号数溢出是 **未定义行为**（C 语言标准），开发中需避免溢出。

### 3.2 截断（Truncation）

截断是指"将高位比特丢弃，保留低位比特"，发生在将高位数据类型转换为低位数据类型时。

```c
// 示例：int 型 0x12345678 转换为 char 型
// 丢弃高24位，保留低8位 0x78，对应十进制120
```

### 3.3 舍入（Rounding）

计算机中常用的 **"向偶数舍入"（Round to Even）**，也叫"银行家舍入"：

| 条件 | 处理 |
|------|------|
| 舍弃的比特最高位为 0 | 直接舍去 |
| 舍弃的比特最高位为 1，且保留部分最低位为 1 | 向前进 1 |
| 舍弃的比特最高位为 1，且保留部分最低位为 0 | 舍弃（避免积累误差） |

## 四、浮点数的表示与处理

### 4.1 IEEE 754 标准

IEEE 754 标准将浮点数表示为 **"符号位 + 阶码 + 尾码"** 三部分：

| 类型 | 符号位（S） | 阶码（E） | 尾码（M） | 总比特数 |
|------|-------------|-----------|-----------|----------|
| **单精度（float）** | 1 位 | 8 位（偏移量 127） | 23 位 | 32 位 |
| **双精度（double）** | 1 位 | 11 位（偏移量 1023） | 52 位 | 64 位 |

**真值计算公式：**

```
V = (-1)^S × (1 + M) × 2^(E - Bias)
```

**浮点数的分类：**

| 类别 | 阶码 E | 说明 |
|------|--------|------|
| **规格化浮点数** | 1 ~ 2ⁿ⁻² | 最常用，尾码隐含整数部分 1 |
| **非规格化浮点数** | 0 | 用于表示接近 0 的小数 |
| **特殊值** | 全为 1 | 无穷大或 NaN（非数字） |

### 4.2 精度损失

> 浮点数无法精确表示所有实数，尤其是十进制小数。根源是"二进制无法精确表示某些十进制分数"（如 0.1）。

```c
// 错误写法：直接判断浮点数相等
if (0.1 + 0.2 == 0.3) { ... }  // 实际结果为 false

// 正确写法：判断差值小于极小值
if (fabs(0.1 + 0.2 - 0.3) < 1e-6) { ... }  // 结果为 true
```

## 五、字符与字符串的表示

### 5.1 ASCII 编码

ASCII 编码是最早的字符编码，采用 7 比特表示，共 128 个字符（0~127）：

- **0~31**：控制字符（如换行、回车）
- **32~126**：可打印字符（`'A'` 对应 65，`'a'` 对应 97，`'0'` 对应 48）

### 5.2 Unicode 编码

Unicode 为每个字符分配唯一的数值（码点，Code Point），范围为 0~0x10FFFF。

### 5.3 UTF-8 编码

UTF-8 是 Unicode 的可变长度编码，兼容 ASCII 编码：

| 字节数 | 格式 | 码点范围 |
|--------|------|----------|
| 1 字节 | `0xxxxxxx` | 0~127（ASCII） |
| 2 字节 | `110xxxxx 10xxxxxx` | 128~2047 |
| 3 字节 | `1110xxxx 10xxxxxx 10xxxxxx` | 2048~65535 |
| 4 字节 | `11110xxx 10xxxxxx 10xxxxxx 10xxxxxx` | 65536~0x10FFFF |

> **核心优势**：UTF-8 按需分配字节，英文字母占用 1 字节，中文占用 3 字节，兼容 ASCII，跨语言、跨平台兼容性好。

## 六、CSAPP核心考点与实践启示

### 6.1 核心考点

- 补码的计算、取值范围及运算规则
- 无符号数与有符号数的转换及混合运算陷阱
- 大端/小端存储的判断与字节序转换
- IEEE 754 浮点数的表示、精度损失及舍入规则
- UTF-8 编码规则与字符串字节数计算

### 6.2 实践启示

| 原则 | 说明 |
|------|------|
| 避免混合运算 | 无符号数与有符号数混合运算时，需手动进行类型转换 |
| 警惕溢出 | 使用合适的数据类型，或添加溢出判断 |
| 浮点数比较 | 避免直接使用 `==`，改用差值判断 |
| 统一字节序 | 跨平台传输数据时，统一使用网络字节序（大端） |
| 明确编码 | 程序中统一使用 UTF-8 编码，避免乱码问题 |

## 七、总结

> 《深入理解计算机系统》中 **"信息的表示和处理"**，核心是揭示"高级语言中的数据，在计算机底层如何以二进制形式存在、运算和转换"。

其本质是 **"抽象与实现的桥梁"**——高级语言中的整数、浮点数、字符串，底层都是二进制比特的组合，而补码、IEEE 754、UTF-8 等标准，是实现"统一、高效、兼容"的核心保障。
