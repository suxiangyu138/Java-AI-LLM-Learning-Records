非关系型数据库 核心知识点
一、非关系型数据库的核心定义
1. 又称NoSQL（Not Only SQL），不遵循关系模型，无需固定表结构，数据存储形式灵活。
2. 核心特征：
   - 无需预定义表结构，支持动态扩展字段；
   - 不依赖SQL，有专属的数据操作方式；
   - 弱化事务（部分支持弱事务，不严格遵循ACID），优先保证高性能和高可用；
   - 数据存储形式多样（键值对、文档、列族、图形等）；
   - 易于水平扩展，适配高并发、大数据量场景。
3. 主流产品：Redis（键值型，Bookstore核心应用）、MongoDB（文档型）、Elasticsearch（搜索引擎型）、HBase（列族型）。

---------------------------------------------------------------------------------------------------------------------------------------
二、核心类型及Bookstore场景适配
1. 键值型数据库（Redis）
   - 存储形式：key-value键值对，value支持字符串、哈希、列表、集合、有序集合等类型；
   - Bookstore应用场景：用户登录令牌、购物车数据、热门书籍缓存、库存计数、接口限流。
2. 文档型数据库（MongoDB）
   - 存储形式：JSON格式的文档，支持嵌套字段，无需固定结构；
   - Bookstore应用场景：书籍评论（字段不固定，可包含图片、点赞数、回复）、用户行为日志（字段动态扩展）。
3. 搜索引擎型数据库（Elasticsearch）
   - 存储形式：倒排索引结构，专为全文检索优化；
   - Bookstore应用场景：书籍全文搜索（按书名、作者、简介模糊检索，支持分词）。
4. 列族型数据库（HBase）
   - 存储形式：按列族存储，适配海量结构化数据；
   - Bookstore应用场景：大规模订单历史数据归档（百万/千万级订单存储）。

三、Redis核心应用
1. 核心数据类型及使用场景
   - 字符串（String）：存储用户登录token、书籍库存、订单编号生成；
     示例：SET user:token:1 "abc123"（用户ID=1的登录令牌）、SET book:stock:1 100（书籍ID=1的库存）。
   - 哈希（Hash）：存储用户购物车（key=cart:user:1，value={bookId:数量, ...}）；
     示例：HSET cart:user:1 1 2（用户1的购物车中，书籍1数量为2）、HGET cart:user:1 1（获取数量）。
   - 列表（List）：存储热门书籍ID（按访问量排序）、订单消息队列；
     示例：LPUSH hot:books 1 3 5（添加热门书籍ID）、LRANGE hot:books 0 9（获取前10本热门书籍）。
   - 有序集合（ZSet）：存储书籍销量排名、用户积分排名；
     示例：ZADD book:sales 100 1 80 2（书籍1销量100，书籍2销量80）、ZREVRANGE book:sales 0 9（销量前10）。
2. Bookstore核心应用场景
   - 缓存热门数据：将首页热门书籍、分类书籍列表缓存到Redis，减少MySQL查询压力；
     流程：请求→Redis查询→有数据直接返回→无数据查MySQL→写入Redis→返回。
   - 购物车存储：用户未登录时购物车存Cookie，登录后同步到Redis，比数据库读写更快；
   - 登录状态保持：用户登录后生成token存入Redis，设置过期时间，替代Session共享（集群场景）；
   - 库存限流：秒杀/热销书籍时，用Redis原子操作（INCR/DECR）控制库存，防止超卖；
   - 接口限流：限制单用户/IP访问频率（如登录接口1分钟最多5次）。
3. 核心操作命令
   - 新增/修改：SET key value EX 3600（设置值并指定过期时间1小时）、HSET hashKey field value；
   - 查询：GET key、HGET hashKey field、LRANGE listKey start end；
   - 删除：DEL key、HDEL hashKey field；
   - 过期设置：EXPIRE key 3600（设置过期时间）、TTL key（查看剩余过期时间）；
   - 原子操作：INCR key（数值+1）、DECR key（数值-1）、HINCRBY hashKey field num（哈希字段数值增减）。

四、MongoDB核心应用
1. 核心存储形式：BSON（JSON扩展格式）文档，示例（书籍评论）：
   {
     "_id": "comment123",
     "bookId": 1,
     "userId": 2,
     "content": "这本书讲解JavaWeb很详细",
     "createTime": "2026-03-16",
     "likeNum": 5,
     "reply": [{"userId": 3, "content": "同意，我也觉得不错"}]
   }
2. Bookstore应用场景
   - 书籍评论存储：评论的回复、点赞数等字段动态变化，无需固定表结构；
   - 用户行为日志：记录用户浏览、搜索、加购行为，字段可灵活扩展；
   - 非核心业务数据：如用户收藏夹（字段简单，无需关联查询）。
3. 核心操作
   - 新增文档：db.comments.insertOne({bookId:1, userId:2, content:"好评"});
   - 查询文档：db.comments.find({bookId:1}).sort({createTime:-1});（查询书籍1的评论，按时间倒序）；
   - 修改文档：db.comments.updateOne({_id:"comment123"}, {$set:{likeNum:6}});（更新点赞数）。

五、关系型数据库 vs 非关系型数据库
维度
关系型数据库（MySQL）
非关系型数据库（Redis/MongoDB）
数据结构
固定二维表，需预定义结构
灵活，无固定结构
事务支持
强事务（ACID）
弱事务（Redis 仅部分支持）
查询能力
复杂关联查询（JOIN）强
简单查询快，复杂关联弱
性能
中低并发，适合复杂查询
高并发，读写速度极快
扩展方式
垂直扩展（升级硬件）为主
水平扩展（增加节点）为主
Bookstore 用途
核心业务数据（用户、订单、书籍）
缓存、购物车、评论、日志
--------------------------------------------------------------------------------------------------------------------------------------- 六、Bookstore项目中混合使用策略
1. 核心原则：核心业务用MySQL，非核心/高并发场景用NoSQL。 
2. 具体策略： - MySQL存储：用户信息、书籍基础信息、订单、订单项（需事务和关联查询）；
     - Redis存储：登录token、购物车、热门书籍缓存、库存计数、接口限流（高并发、快读写）； 
    - MongoDB存储：书籍评论、用户行为日志（结构灵活，无需关联）； - Elasticsearch存储：书籍全文检索数据（优化搜索体验）。
3. 数据一致性保证： 
    - 写操作：先写MySQL，再更新Redis（或设置Redis过期时间，失效后自动从MySQL加载）；
     - 读操作：优先读Redis，缺失则读MySQL并回写Redis；
     - 避免直接修改Redis核心数据，以MySQL为数据最终来源。

 --------------------------------------------------------------------------------------------------------------------------------------- 
七、核心总结 
1. 非关系型数据库（NoSQL）结构灵活、高性能、易扩展，弥补关系型数据库在高并发、灵活结构场景的不足；
 2. Bookstore项目中，Redis是核心非关系型数据库，用于缓存、购物车、登录状态、限流等高频场景； 
3. 企业开发中采用“关系型+非关系型”混合架构：MySQL存储核心业务数据，Redis提升性能，MongoDB适配灵活结构数据； 
4. 核心选型原则：需事务/关联查询用MySQL，高并发/灵活结构用NoSQL，保证数据最终一致性。
