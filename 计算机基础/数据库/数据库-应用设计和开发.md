## 二、Java 后端开发视角深度剖析

### （一）应用架构与 Java 后端分层设计

#### 1. 三层架构对应 Java 后端标准分层

| 架构层 | Java 对应 | 框架 |
|-------|----------|------|
| 表示层 | Controller 层 | Spring MVC、Spring Boot |
| 业务逻辑层 | Service 层 | Spring |
| 数据访问层 | DAO / Mapper 层 | MyBatis、JPA |

#### 2. 架构优势

- **职责分离：** 便于维护、测试、扩展
- **数据库变更：** 仅影响 DAO 层，不污染业务逻辑

#### 3. Web 应用架构适配

| 架构模式 | 说明 |
|---------|------|
| B/S 架构 | 浏览器 → Nginx → 应用服务 → 数据库 |
| 微服务架构 | 服务拆分、API 网关、注册中心、分布式数据库 |

### （二）数据库交互：Java 后端连接与操作

#### 1. JDBC 核心（底层基础）

```java
// JDBC 标准流程：加载驱动 → 获取连接 → 创建 Statement → 执行 SQL → 处理 ResultSet
```

> **Java 后端所有 ORM 框架底层均基于 JDBC。**

#### 2. 连接池（性能关键）

| 连接池 | 说明 |
|--------|------|
| HikariCP | Spring Boot 默认，性能最优 |
| Druid | 阿里巴巴开源，带监控功能 |
| C3P0 | 老牌连接池，已逐步淘汰 |

**配置关注点：** 最大连接数、最小空闲数、超时时间

#### 3. ORM 框架（开发效率）

| 框架 | 特点 | 适用场景 |
|------|------|---------|
| MyBatis | 半自动化，灵活控制 SQL | 复杂查询、SQL 优化 |
| JPA / Hibernate | 全自动化，简化 CRUD | 快速开发、标准 CRUD |
| MyBatis-Plus | 增强 MyBatis | 通用 CRUD、分页、逻辑删除 |

### （三）事务管理：Java 后端一致性保障

#### 1. 声明式事务（主流）

```java
@Transactional(rollbackFor = Exception.class)
public void businessMethod() {
    // 业务逻辑
}
```

**传播机制：**

| 传播行为 | 说明 |
|---------|------|
| REQUIRED | 支持当前事务，不存在则新建（默认） |
| REQUIRES_NEW | 新建事务，暂停当前事务 |
| NESTED | 嵌套事务（基于保存点） |
| SUPPORTS | 支持当前事务，不存在则以非事务方式执行 |

**隔离级别：** 读未提交、读已提交、可重复读、串行化

#### 2. 编程式事务

```java
@Autowired
private TransactionTemplate transactionTemplate;

public void businessMethod() {
    transactionTemplate.execute(status -> {
        // 手动控制提交/回滚
        return result;
    });
}
```

> 适用于复杂事务场景，灵活度高。

#### 3. 分布式事务（微服务必备）

| 场景 | 说明 |
|------|------|
| 跨服务、跨库操作 | 下单 + 扣库存 + 积分 |
| 方案 | Seata（AT/TCC/SAGA）、可靠消息最终一致性 |

#### 4. 事务陷阱

| 陷阱 | 说明 |
|------|------|
| 大事务 | 长时间占用连接，导致连接耗尽 |
| 事务不生效 | 私有方法、非 public 方法、try-catch 吞异常 |

### （四）安全设计：Java 后端防护体系

#### 1. SQL 注入防护

```java
// ✅ 预编译 SQL（PreparedStatement）
String sql = "SELECT * FROM users WHERE id = ?";
PreparedStatement ps = connection.prepareStatement(sql);
ps.setInt(1, id);

// ❌ 禁止字符串拼接 SQL
String sql = "SELECT * FROM users WHERE id = " + id;
```

> ORM 框架默认防注入，禁止字符串拼接 SQL。

#### 2. 身份认证与授权

| 框架 | 说明 |
|------|------|
| Spring Security | 全面的认证授权框架 |
| Shiro | 轻量级安全框架 |
| RBAC 模型 | 用户表、角色表、权限表 |

#### 3. 数据脱敏

| 场景 | 措施 |
|------|------|
| 敏感字段 | 手机号、身份证号、密码加密存储 |
| 密码加密 | BCrypt、MD5 + 盐 |
| 传输加密 | HTTPS、JWT 令牌 |

#### 4. 访问控制

- 数据库最小权限原则，应用账号仅赋必要权限
- 行级权限：数据隔离（如用户仅查看自己订单）

### （五）性能优化：Java 后端数据库调优

#### 1. 查询优化

| 优化项 | 说明 |
|--------|------|
| 避免 SELECT * | 按需查询字段 |
| 合理创建索引 | 主键、唯一、复合索引 |
| 分页查询 | LIMIT 分页，避免全表扫描 |
| 慢查询监控 | MySQL 开启慢查询日志，Druid 监控 |

#### 2. 批量操作

```xml
<!-- MyBatis 批量插入 -->
<insert id="batchInsert" parameterType="list">
    INSERT INTO users (username, email) VALUES
    <foreach collection="list" item="item" separator=",">
        (#{item.username}, #{item.email})
    </foreach>
</insert>
```

> 批量操作减少网络交互，提升吞吐量。

#### 3. 缓存机制

| 缓存类型 | 技术 | 适用场景 |
|---------|------|---------|
| 本地缓存 | Caffeine、Guava | 低频变化数据 |
| 分布式缓存 | Redis | 热点数据（商品信息、配置） |

**缓存策略：** Cache Aside、Read/Write Through

#### 4. 数据库优化

| 优化方式 | 技术 | 说明 |
|---------|------|------|
| 分库分表 | Sharding-JDBC | 解决单表数据量过大 |
| 读写分离 | 主从复制 | 读请求分摊到从库 |

### （六）应用开发实践：Java 后端工程化

#### 1. 版本控制

| 类型 | 工具 | 说明 |

#### 2. 单元测试

| 测试层级 | 注解 / 框架 |

| 工具 | 用途 |

#### 4. 异常处理

```java
@RestControllerAdvice
public class GlobalExceptionHandler {
    @ExceptionHandler(DataAccessException.class)
    public Result handleDataException(DataAccessException e) {
        // 事务回滚，返回友好提示
        return Result.error("数据库操作异常");
    }
}
```

## 四、Java 后端应用开发常见误区

| 误区 | 问题 | 正确做法 |
|------|------|---------|
| 事务滥用 | 大事务、嵌套事务导致性能问题 | 事务尽量短小，合理设置传播行为 |
| 忽视 SQL 注入 | 字符串拼接 SQL，安全漏洞 | 使用参数化查询或 ORM 框架 |
| 连接池配置不当 | 连接数过大/过小，影响并发能力 | 根据压测结果合理配置 |
| 缓存雪崩/击穿 | 缓存设计不合理，导致数据库压力过大 | 合理设置过期时间、使用熔断降级 |
| 不分层设计 | Controller 直接写 SQL，代码耦合严重 | 严格遵循三层架构 |
