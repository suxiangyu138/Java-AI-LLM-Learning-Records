## 1. 数据库系统概述

### 1.1 数据管理技术的发展阶段

| 阶段 | 特点 | 局限性 |
|------|------|--------|
| **人工管理** | 数据不保存、无专门软件、不共享 | 仅适用于科学计算 |
| **文件系统** | 数据可长期保存、由文件系统管理 | 共享性差、冗余度高、独立性低 |
| **数据库系统** | DBMS 统一管理、高共享、低冗余 | 目前主流方案 |

### 1.2 数据库核心概念

| 概念 | 定义 |
|------|------|
| **数据 (Data)** | 描述事物的符号记录（数字、文字、图像、音视频等） |
| **数据库 (DB)** | 长期存储、有组织、可共享的大量数据集合 |
| **数据库管理系统 (DBMS)** | 位于用户与 OS 之间的数据管理软件 |
| **数据库系统 (DBS)** | DB + DBMS + 应用程序 + DBA + 用户 |

### 1.3 数据库系统的特点

| 特点 | 说明 |
|------|------|
| **数据结构化** | 按数据模型组织，面向整个系统 |
| **共享性高、冗余度低** | 多用户共享，减少数据不一致 |
| **数据独立性高** | 物理独立性 + 逻辑独立性 |
| **DBMS 统一管控** | 安全性保护、完整性检查、并发控制、数据库恢复 |

### 1.4 数据模型分类

```
数据模型
├── 概念模型：E-R 模型（信息世界建模）
├── 逻辑模型：层次 / 网状 / 关系 / 面向对象
└── 物理模型：存储结构和存取方法
```

**关系模型基本概念：**

| 术语 | 对应关系 |
|------|----------|
| 关系 (Relation) | 数据库中的表 |
| 元组 (Tuple) | 表中的行 |
| 属性 (Attribute) | 表中的列 |
| 码 (Key) | 唯一标识元组（如主键） |
| 域 (Domain) | 属性的取值范围 |
| 关系模式 | `关系名(属性1, 属性2, ..., 属性n)` |

## 2. 关系数据库

### 2.1 关系的数学定义

- 关系是**笛卡尔积的有限子集**
- 关系必须满足**第一范式（1NF）**：每个属性都是不可再分的原子值

### 2.2 完整性约束

| 约束类型 | 规则 | 说明 |
|----------|------|------|
| **实体完整性** | 主键属性值不为 NULL，且唯一 | 保证实体唯一性 |
| **参照完整性** | 外键值 = 引用表主键值 或 NULL | 保证引用一致性 |
| **用户定义完整性** | 自定义约束（取值范围、格式等） | 业务规则保障 |

### 2.3 关系代数

#### 传统集合运算

| 运算 | 说明 |
|------|------|
| **并 (Union)** | 两个关系所有元组的集合（去重） |
| **差 (Difference)** | 属于 R 但不属于 S 的元组 |
| **交 (Intersection)** | 同时属于 R 和 S 的元组 |
| **笛卡尔积 (Cartesian Product)** | 两关系元组的所有可能组合 |

#### 专门的关系运算

| 运算 | 说明 | SQL 对应 |
|------|------|----------|
| **选择 (σ)** | 选取满足条件的元组（行操作） | `WHERE` |
| **投影 (π)** | 选取指定属性列（列操作） | `SELECT 列名` |
| **连接 (⋈)** | 从笛卡尔积中选取满足条件的元组 | `JOIN` |
| **除 (÷)** | 求解"查询…全部的…"类问题 | 复杂子查询 |

**连接类型：**

| 类型 | 说明 |
|------|------|
| **等值连接** | 连接条件为属性值相等 |
| **自然连接** | 等值连接 + 去掉重复属性列 |
| **左外连接** | 保留左表全部元组，无匹配填 NULL |
| **右外连接** | 保留右表全部元组，无匹配填 NULL |
| **全外连接** | 保留两表全部元组，无匹配填 NULL |

## 3. 结构化查询语言 SQL

### 3.1 SQL 特点

| 特点 | 说明 |
|------|------|
| **综合统一** | 集 DDL、DML、DCL 于一体 |
| **高度非过程化** | 只需说明"做什么"，无需"怎么做" |
| **面向集合** | 操作对象和结果都是集合 |
| **语言简洁** | 核心功能仅需少量关键词 |

### 3.2 DDL —— 数据定义语言

```sql
-- 创建数据库
CREATE DATABASE db_name;

-- 创建表
CREATE TABLE table_name (
    col1 INT PRIMARY KEY,
    col2 VARCHAR(50) NOT NULL,
    col3 INT,
    FOREIGN KEY (col3) REFERENCES other_table(id)
);

-- 修改表
ALTER TABLE table_name ADD col_new INT;
ALTER TABLE table_name MODIFY col_name VARCHAR(100);
ALTER TABLE table_name DROP COLUMN col_name;

-- 删除
DROP TABLE table_name;
DROP DATABASE db_name;
```

### 3.3 DML —— 数据操纵语言

```sql
-- 查询
SELECT [DISTINCT] col1, col2, ...
FROM table_name
[WHERE conditions]
[GROUP BY col [HAVING conditions]]
[ORDER BY col [ASC|DESC]];

-- 聚合函数
SELECT COUNT(*), SUM(amount), AVG(price), MAX(score), MIN(score)
FROM orders;

-- 插入
INSERT INTO table_name (col1, col2) VALUES (val1, val2);
INSERT INTO table_name SELECT ...;  -- 插入查询结果

-- 更新
UPDATE table_name SET col1 = val1 WHERE conditions;

-- 删除
DELETE FROM table_name WHERE conditions;
TRUNCATE TABLE table_name;  -- DDL，不可回滚，速度更快
```

### 3.4 DCL —— 数据控制语言

```sql
-- 授予权限
GRANT SELECT, INSERT ON table_name TO user_name;

-- 回收权限
REVOKE DELETE ON table_name FROM user_name;
```

## 4. 数据库设计

### 4.1 数据库设计步骤

```
需求分析 → 概念结构设计 → 逻辑结构设计 → 物理结构设计 → 实施 → 运行维护
```

| 步骤 | 工作内容 | 产出物 |
|------|----------|--------|
| **需求分析** | 调查业务需求和数据需求 | 需求分析报告 |
| **概念结构设计** | E-R 模型设计 | E-R 图 |
| **逻辑结构设计** | E-R 图 → 关系模式 | 关系模式集合 |
| **物理结构设计** | 存储结构、索引设计 | 物理设计文档 |
| **实施** | 建库建表、编写应用、测试 | 可运行系统 |
| **运行维护** | 备份恢复、性能监控 | 运维记录 |

### 4.2 E-R 模型转换规则

| E-R 元素 | 转换规则 |
|----------|----------|
| **实体** | → 独立的关系模式 |
| **属性** | → 关系的属性 |
| **码** | → 关系的主键 |
| **1:1 联系** | → 独立关系模式，或与任一端合并 |
| **1:N 联系** | → 独立关系模式，或与 N 端合并 |
| **M:N 联系** | → 必须转换为独立的关系模式 |

### 4.3 数据库规范化（范式）

| 范式 | 要求 | 消除的问题 |
|------|------|-----------|
| **1NF** | 属性原子性，不可再分 | 基本结构规范 |
| **2NF** | 满足 1NF，非主属性完全函数依赖于主键 | 部分函数依赖 |
| **3NF** | 满足 2NF，非主属性不传递依赖于主键 | 传递函数依赖 |
| **BCNF** | 满足 3NF，主属性不部分/传递依赖于码 | 主属性部分依赖 |
| **4NF** | 满足 BCNF，消除非平凡多值依赖 | 多值依赖 |

> **实践建议：** 通常达到 3NF 即可，范式级别越高，数据冗余度越低，但查询效率可能越低。

### 4.4 函数依赖类型

| 类型 | 定义 | 示例 |
|------|------|------|
| **完全函数依赖** | X → Y，且 X 的任意真子集不能 → Y | (学号, 课程号) → 成绩 |
| **部分函数依赖** | X → Y，存在 X 的真子集能 → Y | (学号, 课程号) → 学生姓名（仅学号即可） |
| **传递函数依赖** | X → Y, Y → Z，则 X → Z | 学号 → 系编号 → 系主任 |

## 5. 数据库恢复技术

### 5.1 故障分类

| 故障类型 | 描述 | 严重程度 |
|----------|------|:--------:|
| **事务内部故障** | 逻辑错误或系统错误导致事务无法完成 | 低 |
| **系统故障** | 硬件故障、OS 崩溃导致事务中断 | 中 |
| **介质故障** | 磁盘损坏，数据部分或全部丢失 | 高 |
| **计算机病毒** | 恶意程序破坏数据 | 高 |

### 5.2 恢复实现技术

| 技术 | 说明 |
|------|------|
| **数据转储** | DBA 定期将数据库复制备份（静态/动态，海量/增量） |
| **日志文件** | 记录事务更新操作（操作类型、旧值、新值），**先写日志后写数据库** |

### 5.3 恢复策略

| 故障类型 | 恢复策略 |
|----------|----------|
| **事务故障** | 自动反向扫描日志，撤销未提交的修改 |
| **系统故障** | 撤销未提交事务 + 重做已提交未写入磁盘的事务 |
| **介质故障** | 装入最新备份 + 装入日志文件 + 重做已提交事务 |

## 6. 并发控制

### 6.1 并发问题

| 问题 | 说明 |
|------|------|
| **丢失修改** | 两个事务同时修改，一个覆盖另一个 |
| **不可重复读** | 同一事务内两次读取结果不同 |
| **幻读** | 同一查询范围出现新增/删除记录 |

### 6.2 封锁技术

| 锁类型 | 说明 |
|--------|------|
| **共享锁 (S 锁)** | 多个事务可同时持有，只能读 |
| **排他锁 (X 锁)** | 一个事务独占，可读写，其他事务不能加任何锁 |

### 6.3 封锁协议

| 协议级别 | 规则 | 防什么问题 |
|----------|------|-----------|
| **一级** | 修改前加 X 锁，事务结束释放 | 丢失修改 |
| **二级** | 一级 + 读前加 S 锁，读完立即释放 | 丢失修改 + 不可重复读 |
| **三级** | 一级 + 读前加 S 锁，事务结束释放 | 丢失修改 + 不可重复读 + 幻读 |

### 6.4 死锁处理

| 方法 | 说明 |
|------|------|
| **预防** | 一次封锁法（一次性申请所有锁）、顺序封锁法 |
| **诊断** | 超时法、等待图法 |
| **解除** | 选择代价最小的事务撤销，释放其持有的锁 |

## 7. 数据库新技术

### 7.1 分布式数据库

| 特性 | 说明 |
|------|------|
| **数据分布性** | 数据分布在网络不同节点上 |
| **逻辑整体性** | 对用户呈现为统一的逻辑整体 |
| **节点自治性** | 每个节点具有独立处理能力 |
| **优点** | 高可靠性、负载均衡、低通信成本 |
| **缺点** | 复杂度高、数据一致性维护困难 |

### 7.2 NoSQL 数据库

| 类型 | 代表产品 | 特点 |
|------|----------|------|
| **键值型** | Redis | 高性能、简单 KV 操作 |
| **文档型** | MongoDB | JSON/BSON 文档存储 |
| **列族型** | HBase | 稀疏宽表、高可扩展 |
| **图形型** | Neo4j | 节点-关系模型 |

### 7.3 云数据库

| 特点 | 说明 |
|------|------|
| **按需付费** | 无需一次性大额硬件投入 |
| **弹性扩展** | 根据负载自动伸缩 |
| **高可用** | 内置主从复制、自动故障转移 |

## 8. 数据库安全

### 8.1 安全威胁

| 威胁类型 | 说明 |
|----------|------|
| **非授权访问** | 未授权用户访问数据 |
| **数据泄露** | 敏感数据被非法获取 |
| **数据篡改** | 非法修改数据 |
| **拒绝服务攻击** | 导致数据库无法正常服务 |

### 8.2 防护措施

| 措施 | 说明 |
|------|------|
| **用户身份认证** | 用户名密码、指纹、数字证书 |
| **存取控制** | 不同用户分配不同权限（DBA 最高） |
| **数据加密** | 对称加密 / 非对称加密 |
| **审计跟踪** | 记录用户所有操作，便于追查 |
| **防火墙** | 过滤非法访问请求 |
