## 一、并发控制核心内容（原书框架）

### 1. 并发控制的目的

> 保证事务隔离性，解决并发操作导致的数据不一致问题。

### 2. 并发带来的问题

| 问题 | 描述 |
|------|------|
| 脏读 | 读取到未提交的数据 |
| 不可重复读 | 同一事务中多次读取结果不一致 |
| 幻读 | 范围查询时出现新增记录 |
| 丢失更新 | 多事务同时修改同一数据导致覆盖 |

### 3. 封锁机制

- 共享锁（S）
- 排他锁（X）
- 意向锁
- 封锁协议

### 4. 死锁与活锁

- 死锁产生条件、检测、预防、解除

### 5. 多版本并发控制（MVCC）

- 版本链、ReadView、快照读、当前读

### 6. 时间戳协议与乐观锁

- 基于时间戳排序、无锁并发控制

## 二、Java 后端开发视角深度剖析

### （一）并发问题与 Java 高并发痛点

#### 1. 丢失更新

多事务同时修改同一数据导致覆盖。

> **Java 场景**：并发扣减库存导致超卖。

#### 2. 脏读

读取未提交数据。

> **Java 场景**：读取临时订单状态导致业务错误。

#### 3. 不可重复读

同一事务多次读取结果不同。

> **Java 场景**：查询余额两次不一致。

#### 4. 幻读

范围查询出现新增记录。

> **Java 场景**：统计订单数两次结果不同。

### （二）封锁机制：Java 后端并发控制基础

#### 1. 锁类型与 Java 场景

| 锁类型 | 说明 | Java 场景 |
|--------|------|-----------|
| 共享锁（S 锁） | 查询加锁，多事务可共存 | 只读事务适用 |
| 排他锁（X 锁） | 修改加锁，独占资源 | 库存扣减、支付场景 |
| 意向锁 | 提升表级锁效率 | MySQL InnoDB 自动维护 |

#### 2. 封锁协议

> 三级封锁协议保证一致性，Java 事务隔离级别基于此实现。

#### 3. 行锁与表锁

| 类型 | 特点 | Java 使用建议 |
|------|------|---------------|
| 行锁 | InnoDB 默认，粒度小并发高 | 高频使用 |
| 表锁 | 粒度大并发低 | 避免全表更新导致锁表 |

### （三）MVCC：Java 高并发核心优化

#### 1. MVCC 原理

- **版本链**：存储历史数据
- **ReadView**：控制可见性
- **快照读**：普通 `SELECT` 不加锁，适用于 Java 高并发查询场景
- **当前读**：`SELECT ... FOR UPDATE` 加锁，适用于 Java 修改数据场景

#### 2. 对 Java 价值

> 读写不阻塞，大幅提升并发性能，支撑电商、社交等高并发场景。

### （四）死锁问题与 Java 解决方案

#### 1. 死锁产生条件

- 互斥
- 请求与保持
- 不可剥夺
- 循环等待

#### 2. Java 实践

| 策略 | 做法 |
|------|------|
| 预防 | 统一资源获取顺序，避免循环等待 |
| 检测 | 数据库死锁检测自动回滚，Java 日志监控 |
| 解除 | 超时回滚，避免死锁持续阻塞 |

### （五）乐观锁与悲观锁：Java 选型策略

#### 1. 悲观锁

- **假设**：冲突必发生，先加锁再操作
- **实现**：`SELECT ... FOR UPDATE`、`Synchronized`
- **适用**：写多读少、高冲突场景（如库存扣减）

#### 2. 乐观锁

- **假设**：冲突少，版本号/时间戳控制
- **实现**：`version` 字段、CAS 机制
- **适用**：读多写少、低冲突场景（如商品浏览）

### （六）并发控制与 Spring 事务结合

#### 1. 隔离级别映射

| 隔离级别 | 解决的问题 |
|----------|------------|
| 读未提交 | ——（允许脏读） |
| 读已提交 | 解决脏读 |
| 可重复读 | 解决不可重复读 |
| 串行化 | 完全串行执行 |

#### 2. Java 实践

> - 核心业务（订单、支付）用 **可重复读**
> - 普通查询用 **读已提交**
> - 金融强一致用 **串行化**

## 三、并发控制对 Java 后端核心价值

1. **保障数据一致性**：解决并发冲突，避免超卖、数据错乱
2. **提升系统并发能力**：MVCC、行锁优化，支撑高并发请求
3. **指导锁选型策略**：乐观/悲观锁适配不同业务场景
4. **避免死锁等故障**：规范加锁顺序，保证系统稳定

---

## 四、Java 后端并发控制常见误区

| 误区 | 后果 |
|------|------|
| 滥用悲观锁 | 并发性能低下，锁等待严重 |
| 忽视 MVCC 机制 | 重复加锁，浪费资源 |
| 加锁顺序不一致 | 死锁频繁发生 |
| 长事务持有锁 | 阻塞其他事务，并发能力下降 |
| 乐观锁版本冲突未处理 | 更新失败，业务异常 |

## 五、总结（Java 后端视角）

> 并发控制是数据库高并发的核心技术，对 Java 后端开发而言，是系统性能与一致性的平衡关键。

从封锁机制到 MVCC，从死锁处理到锁选型，并发控制决定高并发场景下的数据安全与系统吞吐量。掌握并发控制原理，能合理设计锁策略、解决并发冲突，构建高可用、高性能的 Java 后端系统，是成为高级工程师的必备核心能力。
