## 一、散列表核心定义（后端视角）

**散列表（Hash Table）** 是基于散列函数实现的键值存储结构，通过哈希映射将键转为数组索引，实现平均 O(1) 的查找、插入、删除。

> **后端意义**：在 Java 后端开发中，散列表是 HashMap、ConcurrentHashMap、Redis 等核心组件的底层原理，支撑高并发、大数据场景下的高效数据访问。

---

## 二、散列表核心原理（算法导论）

### 1. 核心组成

- **散列函数**：将键 key 映射为数组下标 index
- **冲突解决**：处理不同 key 映射到同一 index 的情况
- **负载因子**：`α = 元素数 / 数组长度`，控制冲突概率

### 2. 散列函数（后端常用）

| 方法 | 公式 | 说明 |
|------|------|------|
| **除留余数法** | `index = key % m` | m 为数组长度，推荐质数 |
| **乘法散列法** | `index = floor(m * (key * A mod 1))` | A ≈ 0.618（黄金分割） |
| **混合散列** | `key.hashCode() + 扰动函数` | Java HashMap 使用的方案 |

### 3. 冲突解决策略

#### 链地址法（Java HashMap 底层）

| 特性 | 说明 |
|------|------|
| **原理** | 每个数组位置维护链表/红黑树，冲突元素追加到链表 |
| **优势** | 实现简单、负载因子高、删除方便 |
| **劣势** | 链表过长退化为 O(n) |

#### 开放寻址法（Redis Dict 底层）

| 探测方式 | 说明 |
|---------|------|
| **线性探测** | 冲突时依次查找下一个位置 |
| **二次探测** | 冲突时按 i^2 步长查找 |
| **双重散列** | 使用第二个散列函数计算步长 |

| 特性 | 说明 |
|------|------|
| **优势** | 无额外空间、缓存友好 |
| **劣势** | 删除复杂、负载因子低（α <= 0.7） |

## 三、Java 散列表完整实现（链地址法）

```java
/**
 * 散列表（链地址法，简化HashMap）
 * 时间复杂度：平均O(1)，最坏O(n)
 * 空间复杂度：O(n)
 */
public class MyHashMap<K, V> {
    // 哈希节点
    static class Node<K, V> {
        K key;
        V value;
        Node<K, V> next;
        public Node(K key, V value) {
            this.key = key;
            this.value = value;
        }
    }

    private Node<K, V>[] table;
    private int size;
    private static final int DEFAULT_CAPACITY = 16;
    private static final float LOAD_FACTOR = 0.75f;

    @SuppressWarnings("unchecked")
    public MyHashMap() {
        table = new Node[DEFAULT_CAPACITY];
        size = 0;
    }

    /**
     * 散列函数：获取索引
     */
    private int hash(K key) {
        int h = key.hashCode();
        // 扰动函数：减少哈希冲突
        h ^= (h >>> 16);
        return h & (table.length - 1);
    }

    /**
     * 插入元素
     */
    public void put(K key, V value) {
        int index = hash(key);
        Node<K, V> node = table[index];
        // 遍历链表，更新已有key
        while (node != null) {
            if (node.key.equals(key)) {
                node.value = value;
                return;
            }
            node = node.next;
        }
        // 头插法添加新节点
        Node<K, V> newNode = new Node<>(key, value);
        newNode.next = table[index];
        table[index] = newNode;
        size++;
        // 扩容
        if (size >= table.length * LOAD_FACTOR) {
            resize();
        }
    }

    /**
     * 获取元素
     */
    public V get(K key) {
        int index = hash(key);
        Node<K, V> node = table[index];
        while (node != null) {
            if (node.key.equals(key)) {
                return node.value;
            }
            node = node.next;
        }
        return null;
    }

    /**
     * 扩容：2倍扩容，重新哈希
     */
    @SuppressWarnings("unchecked")
    private void resize() {
        int newCapacity = table.length * 2;
        Node<K, V>[] newTable = new Node[newCapacity];
        for (Node<K, V> node : table) {
            while (node != null) {
                Node<K, V> next = node.next;
                int index = hash(node.key);
                node.next = newTable[index];
                newTable[index] = node;
                node = next;
            }
        }
        table = newTable;
    }

    /**
     * 删除元素
     */
    public void remove(K key) {
        int index = hash(key);
        Node<K, V> node = table[index];
        Node<K, V> prev = null;
        while (node != null) {
            if (node.key.equals(key)) {
                if (prev == null) {
                    table[index] = node.next;
                } else {
                    prev.next = node.next;
                }
                size--;
                return;
            }
            prev = node;
            node = node.next;
        }
    }
}
```

## 四、Java 后端核心散列表实现

| 实现 | 底层结构 | 核心特性 | 适用场景 |
|------|---------|---------|---------|
| **HashMap（JDK 1.8+）** | 数组 + 链表 + 红黑树 | 链表 >= 8 转红黑树，2 倍扩容 | 单线程高效场景 |
| **ConcurrentHashMap（JDK 1.8+）** | CAS + synchronized | 线程安全，并发性能优异 | 高并发场景 |
| **LinkedHashMap** | 哈希表 + 双向链表 | 保持插入/访问顺序，可实现 LRU 缓存 | 需要有序遍历 |
| **Hashtable** | 数组 + 链表 | 线程安全（全局锁） | 已淘汰，不推荐使用 |

## 五、Java 后端核心应用场景

| 应用场景 | 技术实现 | 核心优势 |
|---------|---------|---------|
| **本地缓存** | LinkedHashMap 实现 LRU 缓存 | O(1) 访问 |
| **会话管理** | HashMap 存储用户登录态 | 快速查询 |
| **分布式缓存** | Redis 基于散列表（Dict） | 分布式高可用 |
| **分布式锁** | Redisson 基于哈希结构 | 高并发安全 |
| **计数器、限流** | ConcurrentHashMap / Redis | O(1) 操作 |
| **数据库哈希索引** | MySQL Memory 引擎 | 等值查询 O(1) |
| **一致性哈希** | 分布式分片 | 避免缓存雪崩、数据倾斜 |
| **布隆过滤器** | 哈希 + 位图 | 海量数据去重，空间效率高 |

## 六、散列表性能优化（后端必备）

| 优化方向 | 具体策略 |
|---------|---------|
| **哈希函数优化** | 减少冲突，使用高质量哈希函数，重写 hashCode() + equals() |
| **负载因子控制** | 默认 0.75 平衡空间与时间；内存充足调小，内存紧张调大 |
| **冲突优化** | JDK 1.8+ 链表转红黑树，避免哈希攻击（随机哈希种子） |
| **扩容优化** | 预扩容避免频繁扩容，ConcurrentHashMap 懒扩容优化 |

## 七、散列表与其他数据结构对比（后端选型）

| 对比 | 数据结构 | 时间复杂度 | 特点 |
|------|---------|-----------|------|
| **HashMap vs TreeMap** | HashMap | O(1) | 无序，高效 |
| | TreeMap | O(logn) | 有序，范围查询 |
| **HashMap vs ArrayList** | HashMap | O(1) 查找 | 键值对存储 |
| | ArrayList | O(1) 随机访问 | 顺序存储 |

### 后端选型建议

| 业务需求 | 推荐选型 |
|---------|---------|
| 键值存储、快速查找 | HashMap |
| 有序存储、范围查询 | TreeMap |
| 高并发场景 | ConcurrentHashMap |
| 分布式存储 | Redis 哈希 |

## 八、总结（后端散列表核心要点）

1. 散列表是平均 O(1) 的高效键值存储，是后端核心数据结构
2. 核心组成：散列函数 + 冲突解决 + 负载因子
3. Java 实现：HashMap（链地址 + 红黑树）、ConcurrentHashMap（并发安全）
4. 应用场景：缓存、分布式、索引、负载均衡、去重
5. 优化方向：哈希函数、负载因子、冲突处理、扩容策略
6. 是 Java 后端开发者必须掌握的底层原理
