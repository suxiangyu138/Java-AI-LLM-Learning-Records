## 1. 编译概览

### 1.1 编译阶段全景

```
  source.c        ┌──────────────┐
     │            │  词法分析器    │ ← 正则表达式、有限自动机
     ▼            │  (Lexer)     │
 字符流 ────────► └──────┬───────┘
                         │ Token 流
                    ┌────▼───────┐
                    │  语法分析器    │ ← 上下文无关文法、BNF
                    │  (Parser)   │
                    └──────┬───────┘
                           │ AST（抽象语法树）
                    ┌──────▼───────┐
                    │  语义分析器    │ ← 类型检查、符号表
                    │  (Semantic) │
                    └──────┬───────┘
                           │ 带注解的 AST
                    ┌──────▼───────┐
                    │ 中间代码生成   │ ← IR：三地址码、LLVM IR、Java 字节码
                    └──────┬───────┘
                           │ IR（中间表示）
                    ┌──────▼───────┐
                    │   优化器      │ ← 常量折叠、死代码消除、内联
                    │ (Optimizer) │
                    └──────┬───────┘
                           │ 优化后的 IR
                    ┌──────▼───────┐
                    │ 目标代码生成   │ ← 寄存器分配、指令选择
                    │ (Code Gen)  │
                    └──────┬───────┘
                           │
                         a.out
```

### 1.2 编译器 vs 解释器

| | 编译器（Compiler） | 解释器（Interpreter） |
|------|-------------------|----------------------|
| 执行方式 | 一次性翻译为机器码后执行 | 逐行解释执行 |
| 输出 | 独立的可执行文件 | 不产生独立输出 |
| 执行速度 | 快（预编译） | 慢 |
| 调试 | 较复杂 | 简单 |
| 典型 | C/C++（GCC/Clang） | Python（CPython） |

**Java 的特殊位置：** 编译为字节码（javac）+ 解释执行/即时编译（JVM JIT）——混合模式。

## 2. 词法分析

### 2.1 核心任务

将字符流转换为有意义的 **Token**（标记/词法单元）序列。

**Token 示例：**
```
输入:  int sum = a + 10;

输出 Token 流:
  KEYWORD("int")  IDENTIFIER("sum")  OPERATOR("=")
  IDENTIFIER("a")  OPERATOR("+")  NUMBER(10)  SEPARATOR(";")
```

### 2.2 正则表达式与有限自动机

**核心关系：**
```
正则表达式 ◄──等价──► NFA（非确定有限自动机）◄──子集构造──► DFA（确定有限自动机）
```

**常用 Token 的正则表达式：**
```
数字：      [0-9]+
标识符：    [a-zA-Z_][a-zA-Z0-9_]*
关键字：    if | else | while | for | int | return | ...
运算符：    + | - | * | / | = | == | != | < | > | ...
```

### 2.3 Java 中的词法分析示例

```java
// 使用 ANTLR 定义词法规则（.g4 文件）
lexer grammar SimpleLexer;

IF      : 'if';
ELSE    : 'else';
WHILE   : 'while';
INT     : 'int';
ID      : [a-zA-Z_][a-zA-Z0-9_]*;
NUMBER  : [0-9]+;
PLUS    : '+';
MINUS   : '-';
ASSIGN  : '=';
SEMI    : ';';
WS      : [ \t\r\n]+ -> skip;  // 跳过空白字符
```

## 3. 语法分析

### 3.1 核心任务

检查 Token 序列是否符合语言的语法规则，生成 **抽象语法树（AST）**。

**示例：** `a + b * c`
```
      +
     / \
    a   *
       / \
      b   c
```

### 3.2 语法描述工具

**BNF（巴科斯-诺尔范式）：**
```
<expr>    ::= <term> ('+' <term> | '-' <term>)*
<term>    ::= <factor> ('*' <factor> | '/' <factor>)*
<factor>  ::= NUMBER | IDENTIFIER | '(' <expr> ')'
```

**EBNF（扩展 BNF）：** 引入 `[]`（可选）、`{}`（重复 0 次或多次）等语法糖。

### 3.3 自顶向下 vs 自底向上

| | 自顶向下 | 自底向上 |
|------|---------|---------|
| 策略 | 从根开始推导 | 从叶子开始归约 |
| 代表算法 | LL(k)，递归下降 | LR(k)，LALR |
| 工具 | ANTLR（LL(*）） | Yacc / Bison（LALR） |
| 需要处理 | 左递归消除 | 移进-归约冲突 |
| 手写友好度 | ★★★★★（最常用） | ★★☆☆☆ |

### 3.4 递归下降解析器示例

```java
// 手写递归下降解析器解析简单表达式
class Parser {
    List<Token> tokens;
    int pos = 0;

    // expr → term (('+' | '-') term)*
    ASTNode parseExpr() {
        ASTNode left = parseTerm();
        while (match(TokenType.PLUS) || match(TokenType.MINUS)) {
            Token op = previous();
            ASTNode right = parseTerm();
            left = new BinaryOpNode(op, left, right);
        }
        return left;
    }

    // term → factor (('*' | '/') factor)*
    ASTNode parseTerm() {
        ASTNode left = parseFactor();
        while (match(TokenType.MULTIPLY) || match(TokenType.DIVIDE)) {
            Token op = previous();
            ASTNode right = parseFactor();
            left = new BinaryOpNode(op, left, right);
        }
        return left;
    }

    // factor → NUMBER | IDENTIFIER | '(' expr ')'
    ASTNode parseFactor() {
        if (match(TokenType.NUMBER)) return new NumberNode(previous());
        if (match(TokenType.LPAREN)) {
            ASTNode expr = parseExpr();
            expect(TokenType.RPAREN);
            return expr;
        }
        throw new ParseException("Unexpected token");
    }
}
```

### 3.5 AST 的应用

- **编译/转译：** Java → 字节码、TypeScript → JavaScript
- **代码格式化：** Prettier（解析→格式化→重新输出）
- **静态分析：** ESLint、Checkstyle、SpotBugs
- **IDE 功能：** 语法高亮、自动补全、跳转定义

## 4. 语义分析

### 4.1 核心任务

- **类型检查：** 操作数类型与操作符兼容
- **符号表管理：** 作用域规则（变量声明、可见性）
- **类型推断：** `var x = 10` → `int x = 10`（Java 10+）
- **类型转换插入：** `int + double` → `double + double`

### 4.2 符号表

```
┌─────────────┬───────┬──────────┐
│  变量名      │  类型  │  作用域    │
├─────────────┼───────┼──────────┤
│  sum        │  int  │  global   │
│  i          │  int  │  for-loop │
│  temp       │ float │  function │
└─────────────┴───────┴──────────┘
```

**Java 编译器中的符号表：** `javac` 使用 `com.sun.tools.javac.comp.Enter` 和 `MemberEnter` 两个阶段构建符号表。

### 4.3 类型检查示例

```java
// 类型规则：运算符 '+' 接受 int × int → int
// 若操作数类型不匹配，编译器报错
int a = 10;
String b = "hello";
int c = a + b;  // 编译错误：二元运算符'+'的操作数类型错误
```

## 5. 中间代码生成

### 5.1 为什么要中间表示（IR）？

```
前后端解耦：
  M 种源语言 × N 种目标架构
  → 只需写 M 个前端 + N 个后端（而非 M×N 个编译器）
```

### 5.2 常见 IR 形式

| IR 形式 | 特点 | 代表 |
|---------|------|------|
| 三地址码（TAC） | `x = y op z` 形式，每条最多一个运算符 | GCC 早期 |
| 静态单赋值（SSA） | 每个变量恰好赋值一次 | LLVM IR |
| 字节码 | 平台无关的指令序列 | Java 字节码 |
| 图 IR | 基于数据流图 | TensorFlow XLA |

### 5.3 三地址码示例

```
源代码:  a = b * c + d * e

三地址码:
  t1 = b * c
  t2 = d * e
  t3 = t1 + t2
  a  = t3
```

### 5.4 Java 字节码

```java
// Java 源码
public int add(int a, int b) {
    return a + b;
}

// javap -c 反编译后的字节码
public int add(int, int);
  Code:
     0: iload_1        // 将局部变量 a 压入操作数栈
     1: iload_2        // 将局部变量 b 压入操作数栈
     2: iadd           // 弹出栈顶两个 int，相加后压入结果
     3: ireturn        // 返回栈顶 int
```

## 6. 代码优化

### 6.1 优化分类

| 优化层级 | 作用范围 | 示例 |
|----------|----------|------|
| 局部优化 | 基本块内 | 常量折叠、死代码消除 |
| 全局优化 | 函数内 | 公共子表达式消除 |
| 过程间优化 | 跨函数 | 函数内联、死函数消除 |
| 机器相关优化 | 目标代码 | 寄存器分配、指令调度 |

### 6.2 常见优化技术

**常量折叠：**
```
int x = 3 + 4 * 5;  →  int x = 23;
```

**死代码消除：**
```java
if (false) {
    doSomething();  // 永远不会执行 → 移除
}
```

**公共子表达式消除：**
```
a = b + c;      →  a = b + c;
d = b + c + e;  →  d = a + e;
```

**函数内联：**
```java
// 调用处直接展开函数体 → 消除调用开销
int add(int a, int b) { return a + b; }
int x = add(1, 2);   →   int x = 3;   // 直接内联+常量折叠
```

### 6.3 JIT 编译器优化

- **HotSpot C1（Client Compiler）：** 快速编译，较少优化（适合 GUI 应用）
- **HotSpot C2（Server Compiler）：** 深度优化，编译慢但运行快（适合服务端）
- **分层编译（Tiered Compilation）：** 先 C1 → 热点代码升级 C2

**C2 关键优化：**
- **逃逸分析：** 对象未逃逸线程 → 栈上分配 / 标量替换
- **锁消除：** 同步块只被单线程访问 → 去除锁
- **偏向锁 / 轻量级锁：** 减少重量级锁开销

## 7. 目标代码生成

### 7.1 核心任务

1. **指令选择：** IR 操作 → 目标机器指令序列
2. **寄存器分配：** 尽量将变量放在寄存器（图着色算法）
3. **指令调度：** 重排指令顺序，充分利用流水线

### 7.2 寄存器分配（图着色）

```
构建冲突图：
  两个变量同时活跃 → 它们之间有一条边 → 不能分配同一寄存器
  k 个寄存器可用 → 能否用 k 种颜色着色？

若不可着色 → 将某些变量溢出（Spill）到栈内存
```

## 8. Java 编译体系

### 8.1 Java 编译全过程

```
.java 源文件
    │
    ▼ javac（前端编译器）
.class 字节码文件
    │
    ▼ JVM 加载 → 解释执行 / JIT 编译
    │
    ├── 解释执行（启动快，运行慢）
    │
    └── JIT 编译（C1/C2，热点检测后编译为机器码）
           │
           ▼
        机器码（缓存于 Code Cache）
```

### 8.2 javac 编译阶段

```
1. Parse（词法分析 + 语法分析） → CompilationUnit（AST）
2. Enter（符号填充） → 构建符号表
3. Process（注解处理） → Annotation Processing（如 Lombok）
4. Attr（语义分析） → 类型检查、常量折叠
5. Flow（控制流分析） → 变量赋值检查、异常检查
6. Desugar（语法糖脱糖） → 拆解增强 for、lambda、泛型等
7. Generate（代码生成） → 写入 .class 字节码
```

### 8.3 注解处理器（APT）

**Lombok 原理：** 通过 `@Getter`、`@Setter` 等注解，在编译期修改 AST，插入 getter/setter 方法。

```java
// 编译前
@Getter
public class User {
    private String name;
}

// 编译后 AST 等价于
public class User {
    private String name;
    public String getName() { return this.name; }
}
```

## 9. 后端开发关联

### 9.1 领域特定语言（DSL）

**场景：** 业务规则引擎、工作流定义、查询语言定制

```java
// 使用 ANTLR 构建内部 DSL
// 语法: SELECT name, age FROM users WHERE age > 20
// ANTLR 自动生成 Lexer 和 Parser，你只需定义文法规则

grammar Query;
query   : 'SELECT' columns 'FROM' table 'WHERE' condition;
columns : '*' | ID (',' ID)* ;
table   : ID ;
condition : ID op value ;
op      : '>' | '<' | '=' | '!=' | '>=' | '<=';
value   : NUMBER | STRING ;
ID      : [a-zA-Z_][a-zA-Z0-9_]* ;
NUMBER  : [0-9]+ ;
STRING  : '\'' .*? '\'' ;
```

### 9.2 字节码增强

**场景：** AOP 实现、链路追踪、热部署

```java
// Java Agent + 字节码增强（ASM / ByteBuddy）
// 在不修改源码的情况下为方法添加日志/监控

// ByteBuddy 示例：拦截所有 @Timed 注解的方法
new AgentBuilder.Default()
    .type(declaresMethod(isAnnotatedWith(Timed.class)))
    .transform((builder, type, classLoader, module) ->
        builder.method(isAnnotatedWith(Timed.class))
               .intercept(MethodDelegation.to(TimingInterceptor.class))
    ).installOn(inst);
```

### 9.3 理解 JVM 字节码对调优的帮助

```bash
# 查看字节码（分析 JIT 编译行为）
javap -c -v MyClass.class            # 详细字节码
javap -p MyClass.class               # 显示所有成员

# 查看 JIT 编译日志
java -XX:+PrintCompilation MyApp     # 实时打印编译事件
java -XX:+PrintInlining MyApp        # 查看内联决策

# 查看 Code Cache
java -XX:+PrintCodeCache MyApp
```

### 9.4 编译原理知识在日常开发中的应用

| 场景 | 编译原理知识点 |
|------|---------------|
| 正则表达式（日志解析、输入验证） | 有限自动机 |
| JSON/XML 解析 | 上下文无关文法、递归下降 |
| SQL 解析（MyBatis 动态 SQL） | 词法 + 语法分析 |
| Java 注解处理器（APT） | AST 操作 |
| 反射 + 动态代理 | 元编程、字节码 |
| IDE 快捷键（跳转/重构） | AST 导航 |
