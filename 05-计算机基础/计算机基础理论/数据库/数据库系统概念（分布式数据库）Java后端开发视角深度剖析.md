数据库系统概念（分布式数据库）Java后端开发视角深度剖析
一、分布式数据库核心内容（原书框架）
1. 分布式数据库目标与挑战
    透明性、可用性、可扩展性、一致性、容错性
2. 数据分布策略
    水平分片、垂直分片、混合分片、复制
3. 分布式查询处理
    查询分解、数据本地化、优化、结果合并
4. 分布式事务
    两阶段提交(2PC)、三阶段提交(3PC)、一致性协议
5. 分布式并发控制
    分布式锁、时间戳、多版本并发控制
6. 分布式恢复
    故障检测、日志复制、数据恢复
    二、Java后端开发视角深度剖析
    （一）分布式数据库与Java微服务架构
    1. 架构匹配
    微服务按领域拆分，分布式数据库按领域分片
    服务自治、数据自治，降低耦合
2. Java适配
    服务与分片库一一对应，本地事务优先
    跨服务调用通过接口，避免分布式事务
    （二）数据分布策略与Java分库分表实践
    1. 水平分片
    按ID/时间/哈希拆分，单表数据量可控
    Java实现：Sharding-JDBC、ShardingSphere
2. 垂直分片
    按业务模块拆分，冷热字段分离
    Java场景：用户基础信息+用户详情分离
3. 数据复制
    主从复制、多副本，提升可用性
    Java适配：读写分离、故障转移
    （三）分布式查询处理与Java优化
    1. 查询分解
    拆分为子查询，路由到对应分片
    Java实践：携带分片键，避免广播查询
2. 结果合并
    多节点结果聚合、排序、分页
    Java实现：MyBatis拦截器、内存聚合
3. 优化原则
    减少跨节点交互、小表广播、大表分片
    （四）分布式事务与Java解决方案
    1. 两阶段提交(2PC)
    强一致性，性能低
    Java场景：金融核心支付
2. TCC模式
    侵入性强，高性能
    Java实现：Seata TCC、自定义事务
3. 最终一致性
    高性能，最终一致
    Java场景：可靠消息、Saga模式
    （五）分布式并发控制与Java锁机制
    1. 分布式锁
    Redis、ZooKeeper实现
    Java场景：库存扣减、订单创建
2. MVCC扩展
    多版本控制，读写不阻塞
    Java适配：InnoDB集群、TiDB
3. 乐观锁
    版本号控制，低冲突场景
    Java实现：version字段、CAS
    （六）分布式恢复与Java高可用设计
    1. 故障检测
    心跳机制、健康检查
    Java适配：Nacos、Eureka服务发现
2. 数据恢复
    日志复制、备份恢复
    Java实践：binlog同步、定时备份
3. 熔断降级
    避免故障扩散
    Java实现：Sentinel、Resilience4j
    三、分布式数据库对Java后端核心价值
    1. 支撑海量数据与高并发
    水平扩展，突破单机瓶颈
2. 提升系统可用性
    多副本、故障转移，无单点故障
3. 适配微服务架构
    数据自治，服务解耦
4. 平衡一致性与性能
    多种事务方案，适配业务场景
    四、Java后端分布式数据库常见误区
    1. 过度分片
    小数据量分库，增加复杂度
2. 滥用分布式事务
    本地事务用分布式方案
3. 无分片键查询
    广播查询性能差
4. 数据倾斜
    热点分片压力过大
5. 忽视数据一致性
    跨库操作无事务保障
    五、总结（Java后端视角）
    分布式数据库是微服务架构的核心支撑，对Java后端开发而言，是高并发、大数据系统的基石。
    从数据分片到事务一致性，分布式数据库贯穿微服务设计全流程。
    掌握分布式数据库原理，能合理设计分片策略、选择事务方案、构建高可用、可扩展的Java微服务系统，是高级工程师必备能力。
