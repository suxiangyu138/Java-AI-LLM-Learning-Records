# AI 工具组合拳 —— 不同场景专用工具矩阵

## 为什么需要工具组合？

每个 AI 工具的设计目标和能力边界不同：

| 工具 | 核心优势 | 核心劣势 |
|------|---------|---------|
| ChatGPT | 通用性强，代码生成优秀 | 长上下文能力弱，知识有 cutoff |
| Claude | 长文档分析，深度推理 | 无实时搜索，代码补全体验不如 Copilot |
| Perplexity | 实时搜索 + 引用来源 | 代码能力弱于 ChatGPT/Claude |
| GitHub Copilot | IDE 内代码补全流畅 | 不会解释原理，不会架构设计 |
| Cursor | AI 结对编程，理解项目上下文 | 需要项目加载，不适合临时问答 |

## 场景 × 工具决策矩阵

### 学习知识场景

| 场景 | 首选工具 | 为什么 |
|------|---------|--------|
| Java SE 基础概念 | ChatGPT | 回答结构化，代码示例丰富 |
| 算法题讲解 | ChatGPT | 思路讲解清晰，多解法对比 |
| Spring 原理深入 | Claude | 能处理长调用链，深度追问不崩 |
| 阅读论文/技术规范 | Claude | 长文本分析强，能提取关键信息 |
| 查最新技术趋势 | Perplexity | 实时搜索，带引用来源 |
| 技术选型调研 | Perplexity | 能对比不同框架的最新版本特性 |
| 找开源项目/替代方案 | Perplexity | 实时搜索 GitHub/技术社区 |

### 编码场景

| 场景 | 首选工具 | 为什么 |
|------|---------|--------|
| 写 CRUD 模板代码 | GitHub Copilot | Tab 补全，不打断心流 |
| 写 SQL / 配置文件 | GitHub Copilot | 上下文感知，补全准确 |
| 重构复杂代码 | Cursor | 理解整个项目，重命名/提取方法 |
| 调试 Bug | Cursor + ChatGPT | Cursor 看项目 → ChatGPT 诊断 |
| 生成单元测试 | Cursor | 一键生成覆盖所有分支 |
| 写复杂业务逻辑 | 自己写，AI 只 review | 核心逻辑不能外包 |

## 三大组合拳流程

### 组合拳 1：学新技术

```
Step 1: Perplexity → "2026 年 Spring AI 最新教程推荐"
         → 找到最新、最权威的学习资源

Step 2: ChatGPT → 用结构化模板生成学习路线
         → "我是 Java 后端，用以下结构输出 Spring AI 学习路线..."

Step 3: Cursor → 新建 Demo 项目，跟着学习路线写代码
         → 边学边写，遇到问题直接 @Cursor 问
```

### 组合拳 2：调试复杂 Bug

```
Step 1: Cursor → 定位 Bug 相关代码，选中 → Explain Code
         → 确保自己理解了代码意图

Step 2: ChatGPT → 贴上错误栈 + 环境信息 + 相关代码
         → 生成初步诊断和修复方案

Step 3: Claude → "请审查 ChatGPT 的方案，找出潜在漏洞"
         → 深度分析，发现边界条件问题

Step 4: ChatGPT → "Claude 发现了 X 问题，请重新生成方案"
         → 修复漏洞后的完整方案
```

### 组合拳 3：刷算法题

```
Step 1: 自己写 10-15 分钟，产出暴力解法或伪代码

Step 2: ChatGPT → "我的思路是 X，哪里错了？怎么优化？"
         → 在现有思维上修正，给多种解法

Step 3: → "请出 2 道同类型变种题，不给答案"
         → 检验是否真正理解算法思想

Step 4: 3 天后 → ChatGPT → "上次做的 #42 接雨水，请再出 1 道题"
         → 间隔重复，巩固长期记忆
```
