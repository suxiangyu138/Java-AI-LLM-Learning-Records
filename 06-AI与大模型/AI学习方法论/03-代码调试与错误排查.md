# 代码调试与错误排查 —— 终结无效 Google 搜索

## 传统调试的困境

Redis 连接超时报错，StackOverflow 翻 10 页没找到解决方案，因为：
- 搜索结果泛化，不匹配你的具体环境
- 答案碎片化，缺少系统诊断链路
- 版本差异导致方案失效

---

## AI 诊断流程（4 步法）

### 步骤 1：精准提问 —— 提供完整上下文

```
我遇到以下错误，请帮我诊断：

【错误栈】
java.net.SocketTimeoutException: connect timed out
    at redis.clients.jedis.Connection.connect(Connection.java:184)
    at redis.clients.jedis.BinaryJedis.connect(BinaryJedis.java:1600)
    ...

【环境信息】
- Spring Boot 版本：2.7.14
- Jedis 版本：4.3.1
- Redis 版本：7.0.5（Docker 部署）
- 配置文件：
  spring.redis.host=192.168.1.100
  spring.redis.port=6379
  spring.redis.timeout=2000ms
  spring.redis.jedis.pool.max-active=8
```

**关键**：错误栈 + 版本号 + 配置 = AI 精准定位的前提。缺少任何一项，AI 只能泛泛而谈。

### 步骤 2：要求穷举可能原因

```
请列出导致此错误的 5 种可能原因（按概率从高到低），
每种原因给出：
- 根因解释
- 验证方法（具体命令）
- 解决方案
```

### 步骤 3：逐步验证，不是全部照做

AI 给出 5 种原因后，你需要**逐个验证**：
1. 先验证概率最高的原因
2. 用 AI 给的验证命令执行
3. 排除后进入下一个
4. 过程中把新发现反馈给 AI，让它修正诊断方向

### 步骤 4：交叉验证 —— 多 AI 互审

```
# 第 1 轮
ChatGPT："问题应该是 Redis 绑定了 127.0.0.1 而非 0.0.0.0"

# 第 2 轮
Claude："ChatGPT 的上述诊断有什么遗漏？请审查"
Claude："还可能是 Docker 端口映射未配置、防火墙规则阻拦、或 Jedis 连接池耗尽"

# 第 3 轮
回到 ChatGPT："Claude 提出了 3 个补充原因，请逐一验证方法"
```

## 进阶技巧

### 技巧 1：追问"这是最优解吗？"

```
我："这个问题用 Redis Lua 脚本解决对吗？"
AI："对，这样可以保证原子性。"

我："你确定这是最优解吗？"
AI（被追问后）："实际上，如果 Redis 版本 >= 2.6，可以用
SET key value NX EX seconds 一条命令替代，不需要 Lua 脚本。"
```

**原理**：AI 倾向给"够用"的答案。追问迫使它重新评估，深度搜索更优方案。

### 技巧 2：要求给代码级别的修复

```
不要问："怎么修复这个 Bug？"
要问："给出完整的修复代码 diff，包括改动前后的对比"
```

### 技巧 3：要求解释"为什么这样修"

```
给出修复方案后追问：
"请用因果链解释：这个修复为什么能解决问题？
 从根因 → 异常链路 → 修复点，逐一说明。"
```

## 反模式警告

```
❌ 不做的事：
1. 贴一半错误栈（缺少关键异常类型）
2. 不提供版本号和环境信息
3. AI 给方案后不验证直接上线
4. 只用 1 个 AI 工具
5. AI 说"应该是 X 原因"就停止追问

✅ 必做的事：
1. 完整错误栈 + 环境信息 + 已尝试的方法
2. 要求列出多种可能原因
3. 逐个验证并反馈结果
4. 至少 2 个 AI 交叉审查方案
5. 追问 3 层直到触及根因
```
