# 数据库核心知识点

## 一、数据库基础概念
1. **DB、DBMS、DBS**
    - DB：数据库，长期存储、结构化数据集合
    - DBMS：数据库管理系统，管理数据库的软件（MySQL、Oracle）
    - DBS：数据库系统，由DB+DBMS+硬件+用户组成
2. **三大特性**：数据结构化、数据共享、数据独立性
3. **数据独立性**
    - 物理独立性：存储结构变，应用程序不变
    - 逻辑独立性：逻辑结构变，应用程序不变

## 二、数据库三大范式

### 1NF 第一范式
列不可再分，原子性，字段不可拆分。

### 2NF 第二范式
满足1NF，**消除部分函数依赖**，非主键字段完全依赖主键。

### 3NF 第三范式
满足2NF，**消除传递函数依赖**，非主键字段不依赖其他非主键。
> 反范式：高并发场景适当冗余字段，减少联表查询，提升性能。

## 三、关系模型与完整性约束
1. **三大完整性**
    - 实体完整性：主键非空、唯一
    - 参照完整性：外键约束，引用主键合法值或为空
    - 用户自定义完整性：字段长度、范围、唯一等限制
2. **键分类**
    - 超键、候选键、主键、外键、联合主键

## 四、SQL 核心
1. **DQL 查询**：`select`、`from`、`where`、`group by`、`having`、`order by`、`limit`
2. **DML 操作**：`insert`、`update`、`delete`
3. **DDL 定义**：`create`、`alter`、`drop`
4. **DCL 权限**：`grant`、`revoke`
5. **多表查询**
    内连接、左连接、右连接、全连接、子查询、联合查询`union`

## 五、索引（高频）
1. **索引作用**：加速查询、约束唯一；降低写入效率、占用磁盘空间
2. **索引分类**
    - 主键索引、唯一索引、普通索引、联合索引、全文索引
3. **底层结构**
    - InnoDB：**B+树**，聚簇索引，叶子节点存整行数据
    - MyISAM：B+树，非聚簇索引，叶子存数据地址
4. **最左匹配原则**：联合索引遵循最左前缀匹配
5. **索引失效场景**
    like %xx、函数运算、类型隐式转换、or、not in、字段Null

## 六、事务 ACID
1. **ACID 四大特性**
    - **A 原子性**：事务要么全成功，要么全回滚
    - **C 一致性**：事务前后数据完整性约束不变
    - **I 隔离性**：多事务互不干扰
    - **D 持久性**：提交后数据永久落地，崩溃不丢失
2. **事务隔离级别**（由低到高）
    1. 读未提交：脏读、不可重复读、幻读都存在
    2. 读已提交：解决脏读，存在不可重复读、幻读
    3. 可重复读（MySQL默认）：解决脏读、不可重复读，存在幻读
    4. 串行化：全部问题解决，性能最低
3. **并发问题**
    - 脏读：读到未提交数据
    - 不可重复读：同一事务多次读取结果不同（update）
    - 幻读：同一事务范围查询数量不一致（insert/delete）

## 七、锁机制
1. **按粒度**
    - 表锁：开销小、并发低、整表锁定
    - 行锁：开销大、并发高、锁定单行
2. **按类型**
    - 共享锁S：读锁，共享不互斥
    - 排他锁X：写锁，互斥独占
3. InnoDB 关键：**行锁基于索引**，无索引降级为表锁

## 八、MySQL 存储引擎
1. **InnoDB**
    支持事务、行锁、外键、MVCC、崩溃恢复，默认引擎
2. **MyISAM**
    不支持事务、表锁、查询快，适合静态只读业务

## 九、MVCC 多版本并发控制
1. 作用：实现**可重复读、读不加锁**，提升并发
2. 核心：undo log 版本链 + read view 快照读
3. 当前读：select for update、update、delete（加锁）
4. 快照读：普通 select（无锁，走MVCC）

## 十、日志机制
1. **redo log 重做日志**：保证事务持久性，崩溃恢复
2. **undo log 回滚日志**：保证原子性、MVCC版本
3. **binlog 二进制日志**：主从复制、数据恢复，记录SQL逻辑

## 十一、数据库优化
1. SQL优化：避免全表扫描、合理索引、少用联表、避免大事务
2. 架构优化：读写分离、分库分表、缓存（Redis）
3. 配置优化：连接池、缓冲池、超时参数调整

## 十二、主从复制
1. 原理：主库binlog日志同步至从库，从库重放SQL
2. 作用：读写分离、数据备份、容灾

## 十三、数据库设计
E-R模型：实体、属性、联系（一对一、一对多、多对多）
多对多解决方案：引入中间关联表
