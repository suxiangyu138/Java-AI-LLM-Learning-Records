# Java 设计模式概述

> **文档定位**：Java 后端企业级技术文档 | 设计模式概述  
> **核心定义**：针对特定场景的通用解决方案模板，非固定代码  
> **前置基础**：面向对象三大特性（封装、继承、多态）

---

## 一、核心概念

### 1.1 什么是设计模式

设计模式（Design Pattern）是 GoF（四人组）系统化总结的 **23 种经典通用解决方案模板**，本质是一套解决特定问题的思路、流程与结构规范。核心目标：提高代码的 **可复用性、可扩展性、可维护性**，降低模块间的耦合度。

> 设计模式不是"银弹"，必须结合业务场景合理选用，避免过度设计。

### 1.2 三大分类（GoF 23 种）

| 分类 | 核心关注 | 包含模式 |
|------|----------|----------|
| **创建型**（5 种） | 对象创建与初始化 | 单例、工厂方法、抽象工厂、建造者、原型 |
| **结构型**（7 种） | 类与对象的组合结构 | 适配器、装饰器、代理、外观、桥接、组合、享元 |
| **行为型**（11 种） | 对象间通信与职责分配 | 策略、模板方法、观察者、迭代器、责任链、命令、备忘录、状态、访问者、中介者、解释器 |

## 二、底层原理

### 2.1 SOLID 五大核心原则

| 原则 | 核心思想 | 一句话总结 |
|------|----------|------------|
| **S** - 单一职责 | 一个类只做一件事 | 职责分离、粒度细化 |
| **O** - 开放封闭 | 对扩展开放，对修改关闭 | 新增功能通过扩展而非修改现有代码 |
| **L** - 里氏替换 | 子类可替换父类而不破坏逻辑 | 继承时子类不破坏父类规范 |
| **I** - 接口隔离 | 不依赖不需要的接口 | 大接口拆分为多个专用小接口 |
| **D** - 依赖倒置 | 依赖抽象而非具体实现 | 面向接口编程 |

### 2.2 两大补充原则

| 原则 | 核心思想 |
|------|----------|
| **迪米特法则** | 最少知道原则——只与直接朋友通信 |
| **合成复用原则** | 优先组合/聚合，而非继承 |

## 三、代码实现（实战关联）

### 3.1 Java 框架中的设计模式应用

| 模式 | 框架应用 |
|------|----------|
| **单例模式** | Spring Bean 默认单例、Redis 连接池 |
| **工厂模式** | Spring `BeanFactory`、MyBatis `SqlSessionFactory` |
| **代理模式** | Spring AOP 动态代理、MyBatis Mapper 代理 |
| **模板方法** | Spring `JdbcTemplate`、`RestTemplate` |
| **观察者模式** | Spring Event 机制、ZooKeeper Watcher |
| **责任链模式** | Netty `ChannelPipeline`、Servlet Filter Chain |
| **策略模式** | Spring 资源加载策略、消息路由 |

## 四、实战要点

| 要点 | 说明 |
|------|------|
| **切勿死记硬背** | 重在理解场景 —— "为什么用、什么时候用、怎么用" |
| **拒绝盲目滥用** | 简单场景无需强行套用模式，避免过度设计 |
| **遵循原则优先** | 先掌握 SOLID，再灵活选用模式 |
| **结合框架源码** | 读 Spring/Netty/MyBatis 源码理解模式落地 |

---

## 五、避坑总结

| 坑点 | 正确做法 |
|------|----------|
| **盲目套用模式** | 简单业务无需工厂/建造者等复杂模式 |
| **过度设计** | 3 个 if-else 不需要策略模式，KISS 原则优先 |
| **模式本身成为负担** | 新增成员不熟悉模式反而降低效率 |

---

## 六、企业级最佳实践

- **Spring 源码是最好的设计模式教材**：IOC（工厂+单例）、AOP（代理）、事件（观察者）
- **设计模式服务于业务**：先识别痛点，再选用合适的模式
- **代码审查关注 SOLID**：用五大原则检验代码质量
