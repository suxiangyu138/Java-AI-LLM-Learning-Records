Java后端开发：中介者模式核心知识点全解
一、模式基础理论
1.1 模式定义
中介者模式（Mediator Pattern）是行为型设计模式，核心设计目标为：引入独立的中介者对象，统一封装并调度多个交互对象间的通信与协作逻辑，将对象间原本高度耦合的多对多网状依赖，转化为对象与中介者之间的一对多星形依赖，从而降低系统耦合度，实现交互逻辑的集中管控与独立维护，严格契合迪米特法则与开闭原则。
该模式的核心逻辑是剥离对象间的直接交互，所有业务请求、指令传递均通过中介者中转，各业务对象仅聚焦自身核心业务，无需感知其他对象的存在，彻底解决多模块、多对象协同场景下的耦合混乱、维护困难问题，是企业级后端复杂业务协同的核心设计方案。
1.2 核心设计思想
集中调度、解耦网状依赖、职责分离。将分散在各个对象中的交互协作逻辑收拢至中介者统一管理，对象间无直接依赖，中介者承担全部协调职责，各对象保持单一职责，系统扩展与迭代仅需调整中介者逻辑，不影响现有业务模块。
1.3 适用场景
系统中多个对象相互关联、双向交互，形成复杂网状耦合，模块间依赖混乱；
对象间协作逻辑分散且复杂，单一逻辑变更需修改多个关联对象，维护成本过高；
需对多模块协作流程进行统一管控，实现交互逻辑复用、标准化调度；
需降低模块间耦合度，提升系统可扩展性、可测试性与可维护性；
Java后端典型场景：电商订单全流程协同、工作流节点调度、表单组件联动、API网关服务调度、MVC框架层交互、即时通信消息转发。
1.4 四大核心角色及职责
抽象中介者（Mediator）：顶层接口或抽象类，定义同事对象注册、消息转发、业务协调的统一方法，规范中介者核心行为，是衔接各同事对象的抽象纽带。
具体中介者（ConcreteMediator）：实现抽象中介者，为模式核心。内部持有所有同事对象引用，实现具体的协调调度逻辑，处理对象间的通信与业务流转，屏蔽复杂交互细节。
抽象同事类（Colleague）：顶层抽象类或接口，定义所有交互对象的公共方法，持有中介者引用，规范对象发送请求、接收指令的标准流程，所有业务对象均需继承或实现该类。
具体同事类（ConcreteColleague）：实现抽象同事类，是实际执行业务的实体对象。仅处理自身核心业务，禁止与其他同事对象直接交互，所有请求通过中介者发送，接收中介者指令并执行。
1.5 优缺点分析
核心优势
彻底拆解网状耦合，将多对多依赖转为一对多，系统结构清晰可控；
交互逻辑集中管理，避免代码散落，便于维护与迭代；
同事类职责单一，符合高内聚低耦合准则，便于独立测试与复用；
扩展性优异，新增协作对象仅需修改中介者，不影响现有模块，遵循开闭原则；
简化对象调用逻辑，客户端无需关注复杂协作流程。
核心局限性
随着协作对象增多，中介者逻辑易过度膨胀，成为复杂庞类，维护难度上升；
存在单点故障风险，中介者异常会导致全系统交互失效，需配套容错机制；
简单交互场景使用会造成过度设计，增加不必要的代码层级。
1.6 与观察者模式核心区别（高频易混）
对比维度
中介者模式
观察者模式
核心目的
消除多对象网状耦合，集中协调双向交互
实现一对多事件通知，被动触发状态更新
通信方式
对象-中介者-对象，主动调度、双向协作
主题-观察者，单向推送、被动响应
依赖结构
星形结构，所有对象仅依赖中介者
一对多结构，主题持有观察者集合
适用场景
多对象双向协作、复杂流程调度
状态变更单向通知、事件触发
二、Java后端实战实现
2.1 实战场景
模拟电商订单创建全流程，涉及订单模块、库存模块、支付模块、日志模块四大核心模块，传统模式下模块两两耦合，采用中介者模式实现统一调度，模块间无直接依赖，流程可灵活调整。
2.2 代码实现
步骤1：定义抽象中介者接口
/**
 * 抽象中介者：定义同事注册与业务协调方法
     */
    public interface OrderMediator {
    /**
     * 注册同事对象到中介者
     * @param colleague 业务模块对象
     */
    void registerColleague(Colleague colleague);
    /**
     * 协调调度各模块执行业务
     * @param sender 发送请求的模块
     * @param operate 执行操作
     */
    void coordinate(Colleague sender, String operate);
    }
    步骤2：定义抽象同事类
    /**
 * 抽象同事类：所有业务模块父类，绑定中介者
     */
    public abstract class Colleague {
    protected OrderMediator mediator;
    protected String moduleName;
    public Colleague(String moduleName, OrderMediator mediator) {
        this.moduleName = moduleName;
        this.mediator = mediator;
        // 自动注册到中介者
        mediator.registerColleague(this);
    }
    /**
     * 发送请求，交由中介者调度
     * @param operate 操作指令
     */
    public void sendRequest(String operate) {
        mediator.coordinate(this, operate);
    }
    /**
     * 接收中介者指令，执行业务
     * @param operate 操作指令
     */
    public abstract void execute(String operate);
    }
    步骤3：定义具体同事类（业务模块）

    步骤4：定义具体中介者（核心调度器）
    import java.util.ArrayList;
    import java.util.List;
    /**
 * 具体中介者：订单流程统一调度器
     */
    public class OrderMediatorImpl implements OrderMediator {
    // 持有所有业务模块
    private final List<Colleague> colleagueList = new ArrayList<>();
    @Override
    public void registerColleague(Colleague colleague) {
        colleagueList.add(colleague);
    }
    @Override
    public void coordinate(Colleague sender, String operate) {
        // 订单模块发起创建请求，中介者统一调度全流程
        if (sender instanceof OrderColleague && "create".equals(operate)) {
            // 调度各模块执行对应操作
            colleagueList.forEach(colleague -> {
                if (colleague instanceof StockColleague) {
                    colleague.execute("deduct");
                } else if (colleague instanceof PayColleague) {
                    colleague.execute("prePay");
                } else if (colleague instanceof LogColleague) {
                    colleague.execute("订单创建");
                } else if (colleague instanceof OrderColleague) {
                    colleague.execute("create");
                }
            });
        }
    }
    }
    步骤5：客户端测试
    public class Client {
    public static void main(String[] args) {
        // 创建中介者
        OrderMediator mediator = new OrderMediatorImpl();
        // 创建各业务模块，自动注册至中介者
        Colleague order = new OrderColleague(mediator);
        new StockColleague(mediator);
        new PayColleague(mediator);
        new LogColleague(mediator);
        // 客户端仅触发订单创建，中介者完成全流程调度
        System.out.println("===== 开始执行订单创建流程 =====");
        order.sendRequest("create");
    }
    }

    三、开发注意事项与落地建议
    严禁同事类直接交互：同事对象之间禁止直接引用、调用方法，所有通信必须通过中介者中转，否则会破坏解耦效果，重回网状耦合；
    控制中介者复杂度：当中介者逻辑过于庞大时，按业务域拆分多个子中介者，避免单类代码冗余、逻辑混乱；
    合理设计同事类粒度：同事类保持单一职责，一个模块仅负责一类业务，避免职责交叉，降低调度难度；
    规避单点故障：核心业务场景为中介者增加异常捕获、重试与降级机制，防止中介者异常导致流程中断；
    避免过度设计：仅3个以内对象的简单协作，无需使用中介者模式，直接调用更高效；
    结合Spring优化落地：实际项目中，将中介者与同事类交由Spring容器管理，通过依赖注入实现自动注册，简化手动绑定逻辑；
    区分适用场景：多对象双向协作选用中介者模式，单向事件通知选用观察者模式，切勿混用。
    核心总结：中介者模式是解决Java后端多模块复杂协作的关键设计模式，核心价值在于解耦网状依赖、集中管控交互逻辑。落地时需严格把控交互规范，合理控制中介者复杂度，在复杂业务协同场景下，可大幅提升系统的可维护性与扩展性，是企业级后端开发的常用方案。
