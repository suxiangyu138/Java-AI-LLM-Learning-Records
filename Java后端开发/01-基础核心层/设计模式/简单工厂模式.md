简单工厂模式
在面向对象编程体系中，对象创建与业务逻辑分离是降低耦合、提升代码可维护性的核心诉求，前文所述的依赖倒置原则、开放封闭原则，均要求上层模块面向抽象编程，规避直接依赖具体实现类所带来的耦合问题。
在实际业务开发中，大量重复的对象实例化操作，不仅会造成代码冗余，还会导致业务层与对象创建层强绑定，需求迭代时改造范围不可控。
针对这类标准化对象创建场景，简单工厂模式（Simple Factory Pattern）作为最基础、最易用的创建型设计模式，能够高效实现对象创建与业务使用的解耦，它虽不属于GoF 23种经典设计模式，却是工厂方法模式、抽象工厂模式的入门基础，也是日常业务开发中高频使用的简易工厂化解决方案，本章将围绕其定义、结构、实现、场景及工程实践展开深度讲解。
一、模式核心定义
简单工厂模式又称静态工厂模式（Static Factory Pattern），属于创建型设计模式的范畴，其核心定义为：定义一个专门的工厂类，对外提供统一的对象创建接口，根据传入的参数或标识，动态实例化对应的具体产品类，客户端无需关注产品类的实例化细节，仅需依赖工厂类与抽象产品层即可完成对象调用。
该模式的核心价值在于封装对象创建的复杂逻辑，将对象实例化过程集中管理，屏蔽底层实现细节，使客户端专注于业务逻辑开发，严格遵循单一职责原则，同时初步践行依赖倒置原则，实现客户端与具体产品类的解耦。
二、模式结构与角色拆解
简单工厂模式包含三大核心角色，各角色职责边界清晰，符合高内聚、低耦合的设计准则：
抽象产品（Abstract Product）：定义产品类的统一规范与核心行为接口，声明所有具体产品共有的方法，是所有具体产品类的父类或接口，也是客户端直接依赖的抽象层，践行依赖倒置原则的核心载体。
具体产品（Concrete Product）：实现或继承抽象产品角色，完成具体业务逻辑的实现，是工厂类实际创建的目标对象，每个具体产品对应独立的业务场景。
工厂（Factory）：简单工厂模式的核心角色，对外提供统一的静态创建方法，内部封装对象实例化逻辑，根据传入的参数判断并实例化对应的具体产品类，承担全部对象创建职责，遵循单一职责原则。
三、标准代码实现
结合分布式IM系统中消息处理器创建场景，演示简单工厂模式的标准落地实现，贴合前序实战场景，强化知识连贯性：
1. 抽象产品层：消息处理器接口
    /**
     * 抽象产品：定义消息处理规范
     */
    public interface MessageHandler {
    /**
     * 消息处理核心方法
     * @param message 待处理消息
     */
    void handleMessage(String message);
    }
2. 具体产品层：各类消息处理器实现
    /**
     * 具体产品：文本消息处理器
     */
    public class TextMessageHandler implements MessageHandler {
    @Override
    public void handleMessage(String message) {
        System.out.println("文本消息处理：" + message);
    }
    }
    /**
     * 具体产品：图片消息处理器
     */
    public class ImageMessageHandler implements MessageHandler {
    @Override
    public void handleMessage(String message) {
        System.out.println("图片消息处理：" + message);
    }
    }
    /**
     * 具体产品：语音消息处理器
     */
    public class VoiceMessageHandler implements MessageHandler {
    @Override
    public void handleMessage(String message) {
        System.out.println("语音消息处理：" + message);
    }
    }
3. 工厂角色：消息处理器工厂
    /**
     * 工厂类：统一封装消息处理器创建逻辑
     */
    public class MessageHandlerFactory {
    // 私有化构造方法，禁止外部实例化工厂类
    private MessageHandlerFactory() {}
    /**
     * 静态工厂方法：根据消息类型创建对应处理器
     * @param type 消息类型标识
     * @return 对应消息处理器实例
     */
    public static MessageHandler createHandler(String type) {
        if ("text".equals(type)) {
            return new TextMessageHandler();
        } else if ("image".equals(type)) {
            return new ImageMessageHandler();
        } else if ("voice".equals(type)) {
            return new VoiceMessageHandler();
        } else {
            throw new IllegalArgumentException("不支持的消息类型：" + type);
        }
    }
    }
4. 客户端调用
    /**
     * 客户端：仅依赖工厂与抽象产品，无具体产品耦合
     */
    public class Client {
    public static void main(String[] args) {
        // 创建文本消息处理器
        MessageHandler textHandler = MessageHandlerFactory.createHandler("text");
        textHandler.handleMessage("Hello, Simple Factory");
        // 创建图片消息处理器
        MessageHandler imageHandler = MessageHandlerFactory.createHandler("image");
        imageHandler.handleMessage("img_001.png");
    }
    }
    四、模式执行流程
    客户端通过工厂类的静态创建方法，传入产品标识参数，发起对象创建请求；
    工厂类接收参数，内部判断参数对应的具体产品类，完成实例化操作；
    工厂类将实例化后的具体产品对象，以抽象产品类型的形式返回给客户端；
    客户端面向抽象产品调用业务方法，无需关注具体产品的实现细节。
    五、核心优缺点分析
    1. 优点
    职责清晰，解耦彻底：严格遵循单一职责原则，工厂类专注对象创建，业务层专注逻辑实现，客户端与具体产品类完全解耦，符合依赖倒置原则；
    代码复用，减少冗余：集中管理对象创建逻辑，避免客户端重复编写实例化代码，降低代码冗余度；
    实现简易，上手快速：结构简单、逻辑清晰，无需复杂架构设计，适合中小型项目快速落地，是工厂模式体系的入门首选；
    统一管控，便于维护：对象创建规则集中管理，后续修改创建逻辑仅需改造工厂类，不影响客户端业务代码。
2. 缺点
    违背开放封闭原则：新增具体产品类时，必须修改工厂类的创建逻辑，添加新的分支判断，无法做到对修改关闭，产品类型过多时易导致工厂类代码臃肿；
    工厂职责过重：所有产品创建逻辑集中于一个工厂类，一旦工厂类异常，整个对象创建链路失效，系统容错性降低；
    静态方法限制扩展：通常采用静态方法实现，无法形成基于继承的工厂体系，难以扩展为更复杂的工厂模式。
    六、适用场景
    产品类数量较少，且产品类型相对固定，后续新增、修改频率较低的场景；
    客户端仅需使用对象，无需关注对象创建细节，追求快速实现、简化调用的业务场景；
    对象创建逻辑简单，无复杂依赖、初始化流程，无需分层工厂设计的中小型模块；
    前序实战中的工具类对象创建（如Redis客户端、协议编解码器、消息处理器）等标准化实例化场景。
    七、工程实践注意事项
    规避滥用场景：产品类型频繁变动、逻辑复杂的场景，禁止使用简单工厂模式，避免频繁修改工厂类引发故障，建议改用工厂方法模式；
    参数规范化：工厂方法的入参建议使用枚举类替代字符串常量，避免硬编码错误，提升代码可读性与健壮性；
    异常处理完善：针对不支持的参数类型，必须抛出明确的业务异常，便于问题排查与定位；
    结合单例优化：无状态产品对象可在工厂内部实现单例化，避免频繁创建销毁对象，提升系统性能；
    明确模式定位：简单工厂模式是简易解决方案，而非复杂架构设计方案，大型分布式系统、微服务架构中，优先选用工厂方法或抽象工厂模式。
    八、模式对比与进阶
    简单工厂模式是工厂模式体系的基础形态，与工厂方法模式、抽象工厂模式形成递进关系：
    简单工厂集中创建所有产品，耦合度较高；
    工厂方法模式将工厂抽象化，每个产品对应独立工厂，完全遵循开放封闭原则；
    抽象工厂模式则面向产品族设计，支持多系列产品创建。
    实际开发中，可根据业务复杂度，从简单工厂模式逐步演进为更高级的工厂模式，兼顾开发效率与系统扩展性。
    九、本章总结
    简单工厂模式作为最基础的创建型设计模式，以极简的结构实现了对象创建与业务逻辑的解耦，高效落地单一职责、依赖倒置两大核心设计原则，是面向对象设计思想在对象创建场景的典型实践。
    其优势在于简易易用、集中管控，适合轻量级业务场景，但受限于开放封闭原则，无法适配复杂多变的产品体系。
    在实际工程开发中，需结合业务迭代频率、产品数量合理选用，既要发挥其解耦复用的价值，也要规避过度使用导致的架构僵化，为后续学习工厂方法模式、抽象工厂模式奠定扎实的设计基础。
