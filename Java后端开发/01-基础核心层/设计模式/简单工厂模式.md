# 简单工厂模式
面向对象开发中，将**对象创建逻辑与业务逻辑分离**是降低代码耦合、提升可维护性的核心手段。依赖倒置、开闭原则均要求上层模块面向抽象编程，杜绝直接依赖具体实现类带来的强耦合问题。

日常业务里大量重复的`new`实例化代码会造成严重冗余，业务层与对象构造逻辑深度绑定，后续需求迭代改动范围不可控。针对标准化对象创建场景，**简单工厂模式（静态工厂模式）** 是最轻量、最易落地的创建型模式。它不属于GoF 23种标准设计模式，却是工厂方法、抽象工厂模式的底层基础，也是业务开发高频使用的轻量化创建方案。本章从定义、结构、代码实现、执行流程、优劣、落地规范完整拆解。

## 一、模式核心定义
简单工厂模式又称静态工厂模式，归属创建型模式。核心定义：
单独提供一个统一工厂类，对外暴露静态创建方法；外部传入类型标识，工厂内部根据参数动态判断并实例化对应产品，客户端只依赖工厂与抽象产品，完全屏蔽对象实例化细节。

核心价值：
统一封装所有产品的构造逻辑，集中管控实例创建流程，让业务代码只专注业务功能；初步落地单一职责与依赖倒置原则，实现客户端与具体产品解耦。

## 二、三大核心角色
整体分为产品抽象、产品实现、统一工厂三层，职责边界清晰，满足高内聚低耦合：
1. **抽象产品 Abstract Product**
    顶层接口/抽象类，定义全部产品统一的业务行为规范，是所有具体产品的父类型，客户端直接依赖该抽象层，是依赖倒置原则的载体。
2. **具体产品 Concrete Product**
    实现抽象产品接口，承载专属业务逻辑，是工厂最终生成的实例对象，一类产品对应一个独立实现类。
3. **工厂 Factory（核心角色）**
    唯一集中创建类，构造方法私有化防止外部实例化；对外提供静态创建方法，内部通过分支判断匹配参数，生成对应产品实例，包揽全部对象创建工作。

## 三、标准代码实现
沿用IM即时通讯消息处理器业务场景，和前文工厂方法模式场景保持统一，方便对比学习：
### 1. 抽象产品：消息处理顶层接口
```java
public interface MessageHandler {
    void handleMessage(String message);
}
```

### 2. 具体产品：多类型消息处理器
```java
public class TextMessageHandler implements MessageHandler {
    @Override
    public void handleMessage(String message) {
        System.out.println("文本消息处理：" + message);
    }
}

public class ImageMessageHandler implements MessageHandler {
    @Override
    public void handleMessage(String message) {
        System.out.println("图片消息处理：" + message);
    }
}

public class VoiceMessageHandler implements MessageHandler {
    @Override
    public void handleMessage(String message) {
        System.out.println("语音消息处理：" + message);
    }
}
```

### 3. 统一工厂类（静态工厂）
```java
public class MessageHandlerFactory {
    private MessageHandlerFactory() {}

    public static MessageHandler createHandler(String type) {
        if ("text".equals(type)) {
            return new TextMessageHandler();
        } else if ("image".equals(type)) {
            return new ImageMessageHandler();
        } else if ("voice".equals(type)) {
            return new VoiceMessageHandler();
        } else {
            throw new IllegalArgumentException("不支持的消息类型：" + type);
        }
    }
}
```

### 4. 客户端调用代码
客户端仅依赖工厂与抽象接口，无任何具体产品硬编码依赖：
```java
public class Client {
    public static void main(String[] args) {
        MessageHandler textHandler = MessageHandlerFactory.createHandler("text");
        textHandler.handleMessage("Hello, Simple Factory");

        MessageHandler imageHandler = MessageHandlerFactory.createHandler("image");
        imageHandler.handleMessage("img_001.png");
    }
}
```

## 四、模式执行流程
1. 客户端调用工厂静态方法，传入产品类型标识；
2. 工厂接收参数，通过分支条件匹配对应具体产品，完成实例化；
3. 工厂向上返回抽象产品类型对象，屏蔽底层具体实现；
4. 客户端调用抽象产品的业务方法，全程无需感知对象创建细节；
5. 新增产品时，必须修改工厂内部`if-else`分支，新增判断逻辑。

## 五、优缺点分析
### 优点
1. **职责分离，基础解耦**
    工厂只负责创建，业务层只负责逻辑，符合单一职责；客户端不直接`new`具体产品，初步实现依赖倒置。
2. **消除重复实例化代码**
    创建逻辑集中一处，全项目复用，大幅减少冗余代码。
3. **实现简单，上手成本极低**
    仅三层结构，无多层抽象，中小型模块可快速落地，是工厂体系入门方案。
4. **创建逻辑统一维护**
    产品初始化规则、参数校验仅需修改工厂，不改动所有业务调用方。

### 缺点
1. **严重违背开闭原则**
    每新增一款产品，都要修改工厂的分支判断代码，对修改开放，产品变多后工厂代码极度臃肿。
2. **单一工厂职责过载**
    所有产品创建逻辑全部耦合在一个类中，工厂一旦故障，全局对象创建功能瘫痪，容错性差。
3. **静态方法无法扩展**
    静态工厂方法不支持重写、继承扩展，无法基于工厂体系做分层拓展，很难平滑迭代为复杂工厂架构。

## 六、适用场景
1. 产品品类少、类型固定，长期新增、修改频次极低的小型模块；
2. 业务层只需使用对象，不需要关心复杂初始化流程，追求快速开发；
3. 对象创建逻辑简单，无复杂依赖、多步骤初始化，无需分层工厂；
4. 工具类、轻量处理器、简易客户端等标准化实例化场景。

## 七、工程落地规范
1. **控制使用边界**
    产品频繁迭代、创建逻辑复杂的场景禁止使用，优先升级工厂方法模式，避免频繁修改工厂引发线上bug。
2. **入参使用枚举替代字符串**
    用枚举定义产品类型，杜绝字符串硬编码带来的参数写错、类型不统一问题，提升代码健壮性。
3. **完善异常分支**
    不匹配的类型必须抛出明确非法参数异常，方便日志排查、异常拦截。
4. **无状态产品单例优化**
    对于无状态处理器、工具类，在工厂内部缓存单例，减少对象频繁创建销毁开销。
5. **清晰定位模式层级**
    简单工厂仅作为轻量化临时方案，微服务、大型分布式系统不推荐作为标准创建方案，优先选用工厂方法/抽象工厂。

## 八、与进阶工厂模式递进关系
简单工厂是工厂体系最基础形态，三者形成递进升级链路：
1. 简单工厂：单一工厂承载全部产品创建，扩展需修改代码，耦合高；
2. 工厂方法：拆分抽象工厂+独立具体工厂，一类产品对应一个工厂，完全遵循开闭原则；
3. 抽象工厂：面向产品族设计，一套工厂可创建多系列关联产品。

业务迭代过程中可按需平滑升级，兼顾短期开发效率与长期系统扩展性。

## 九、章节总结
简单工厂是最轻量的创建型方案，依靠极简三层结构完成创建与业务逻辑解耦，落地单一职责、依赖倒置两大核心设计原则，是面向对象抽象思想在对象创建场景的基础实践。

它的核心优势是结构简单、开发高效，适配轻量稳定业务；但受开闭原则限制，无法支撑大规模、高频迭代的产品体系。开发时需要结合产品数量、迭代频率合理选型，发挥其轻量化优势，同时规避架构僵化问题，为后续学习工厂方法、抽象工厂模式打好底层设计基础。
