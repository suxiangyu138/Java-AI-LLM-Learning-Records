# Java 多线程核心知识点讲义（大学计算机专业授课版）

## 前言

本讲义针对 Java 多线程核心知识体系，按照"基础认知→核心原理→实现方式→同步控制→高级特性→实战避坑"的模块化逻辑梳理，兼顾理论深度与工程实用性，适合课堂学习、期末复习及后端开发进阶。多线程是 Java 核心重难点，也是面试与生产环境的高频考点，核心目标是实现并发执行提升效率，同时解决线程安全、死锁、资源竞争等核心问题，全文条理清晰、通俗易懂，贴合计算机专业教学规范。

## 模块一：基础概念铺垫（先搞懂底层逻辑）

### 1. 线程与进程核心区别

- **进程**：操作系统分配资源的基本单位，是独立运行的程序实例，拥有独立内存空间（堆、栈、方法区），进程间相互隔离，通信成本高，一个进程崩溃不影响其他进程。
- **线程**：进程内的执行单元，是 CPU 调度的基本单位，依附于进程存在，同一进程内的多线程共享进程内存空间（堆、方法区），仅栈内存独立，线程间通信便捷、切换成本低，但一个线程异常可能导致整个进程崩溃。

核心总结：进程是资源容器，线程是执行路径；进程间隔离，线程间共享资源，这也是线程安全问题的根源。

### 2. 并发与并行核心差异

- **并发（Concurrency）**：单个 CPU 核心通过时间片轮转，交替执行多个线程，宏观上同时运行，微观上串行执行，解决 CPU 空闲等待问题（比如 IO 阻塞时切换线程）。
- **并行（Parallelism）**：多个 CPU 核心同时执行不同线程，微观和宏观均为同时运行，真正实现多核算力利用，效率远高于并发。

### 3. 多线程核心作用

- 提高 CPU 利用率，避免 IO 操作（网络、文件、数据库）阻塞导致 CPU 空闲；
- 提升程序响应速度，比如 GUI 界面不卡顿、后端接口异步处理；
- 实现任务拆分与并行计算，缩短大批量任务执行耗时；
- 注意：线程不是越多越好，线程切换会消耗系统资源，过多线程反而降低效率。

### 4. 线程的生命周期（6 大状态，必考）

Java 线程通过 Thread.State 枚举定义 6 种状态，状态切换遵循固定流程，是多线程核心基础：

- **新建（New）**：创建 Thread 对象，未调用 start() 方法，仅初始化，未进入调度队列；
- **就绪（Runnable）**：调用 start() 后，线程进入就绪队列，等待 CPU 分配时间片，具备执行条件；
- **运行（Running）**：CPU 分配时间片，线程执行 run() 方法内的业务逻辑；
- **阻塞（Blocked）**：线程等待锁资源，无法进入同步代码块/方法，直到获取锁；
- **等待（Waiting）**：线程主动等待，需其他线程唤醒（调用 wait()、join()、LockSupport.park()），无超时时间；
- **超时等待（Timed_Waiting）**：带超时时间的等待，超时后自动唤醒（sleep(long)、wait(long)、join(long)）；
- **终止（Terminated）**：run() 方法执行完毕、线程正常退出，或抛出未捕获异常，线程生命周期结束。

关键提示：阻塞、等待、超时等待状态下，线程不占用 CPU 时间片，只有就绪和运行状态参与 CPU 调度。

## 模块二：Java 线程的 3 种核心实现方式

Java 中创建线程并非直接新建线程实例，而是定义线程执行任务，再交由线程调度执行，共 3 种标准方式，适配不同业务场景。

### 1. 继承 Thread 类（基础方式）

自定义类继承 Thread 类，重写 run() 方法，创建对象后调用 start() 启动线程。

```java
class MyThread extends Thread {
    @Override
    public void run() {
        // 线程执行的业务逻辑
        System.out.println(Thread.currentThread().getName() + " 执行中");
    }
}

new MyThread().start();
```

优点：写法简单，直接使用 Thread 类方法；缺点：Java 单继承，无法再继承其他类，扩展性差。

### 2. 实现 Runnable 接口（推荐）

自定义类实现 Runnable 接口，重写 run() 方法，将实例传入 Thread 构造器，调用 start() 启动。

```java
class MyRunnable implements Runnable {
    @Override
    public void run() {
        System.out.println(Thread.currentThread().getName() + " 执行中");
    }
}

new Thread(new MyRunnable()).start();
```

优点：避免单继承局限，支持多个线程共享同一个 Runnable 实例，适合多线程处理同一任务；缺点：run() 方法无返回值，无法抛出异常，只能内部捕获。

### 3. 实现 Callable 接口 + FutureTask（高级方式）

自定义类实现 Callable 接口，重写 call() 方法，将实例封装为 FutureTask，再传入 Thread 构造器启动，通过 Future.get() 获取返回值。

```java
class MyCallable implements Callable<String> {
    @Override
    public String call() throws Exception {
        return Thread.currentThread().getName() + " 执行完成";
    }
}

FutureTask<String> futureTask = new FutureTask<>(new MyCallable());
new Thread(futureTask).start();
String result = futureTask.get();
```

优点：有返回值，支持抛出异常，支持异步任务结果获取；缺点：写法稍复杂，get() 方法会阻塞主线程直到任务完成。

核心易错点：必须调用 start() 方法启动线程，而非直接调用 run()！直接调用 run() 属于普通方法调用，在主线程串行执行，不会开启新线程。

## 模块三：线程常用核心方法（必考 + 常用）

| 方法 | 作用 | 核心特性 |
| --- | --- | --- |
| start() | 启动线程，进入就绪状态 | 一个线程只能调用一次，重复调用抛异常 |
| run() | 线程业务逻辑载体 | 直接调用为普通方法，不开启线程 |
| sleep(long) | 线程休眠指定毫秒数 | 进入 Timed_Waiting，不释放锁，休眠结束自动就绪 |
| wait()/wait(long) | 线程等待，释放锁 | 必须在同步代码块内使用，需 notify()/notifyAll() 唤醒 |
| notify()/notifyAll() | 唤醒等待队列中的线程 | notify() 唤醒单个，notifyAll() 唤醒全部，不释放锁 |
| join()/join(long) | 线程插队，等待目标线程执行完毕 | 主线程调用后，会阻塞主线程，直到子线程结束 |
| yield() | 线程让步，释放 CPU 时间片 | 重回就绪状态，可能立即再次获取 CPU 时间片 |
| interrupt() | 中断线程 | 仅设置中断标志位，不强制终止线程，需配合逻辑处理 |

关键区分：sleep() 不释放锁，wait() 释放锁，这是二者最核心区别，也是高频面试考点。

## 模块四：线程安全与同步控制（核心重难点）

### 1. 线程安全问题根源

同一进程内多线程共享资源（全局变量、静态变量、共享对象），同时进行读写操作，且操作不具备原子性，导致数据错乱、结果不一致，这就是线程安全问题。

典型场景：多窗口售票、多线程修改同一集合、并发下单扣库存等。

### 2. synchronized 同步锁（基础解决方案）

JVM 内置的隐式锁，属于互斥锁、可重入锁、非公平锁，通过锁定共享资源，保证同一时间只有一个线程执行同步代码，解决线程安全问题。

三种使用方式：

- **同步代码块**：锁定指定对象（锁对象），粒度小，灵活度高，`synchronized(锁对象){ 同步代码 }`
- **同步实例方法**：锁定当前对象 this，整个方法执行完毕才释放锁
- **同步静态方法**：锁定当前类的 Class 对象，作用于所有类实例

可重入性：同一线程可多次获取同一把锁，避免自己锁死自己。

### 3. Lock 锁（JUC 显式锁，进阶方案）

java.util.concurrent.locks 包下的显式锁，核心实现类 ReentrantLock，功能比 synchronized 更强大，支持手动加锁、解锁、公平锁/非公平锁切换、超时获取锁、中断锁。

```java
Lock lock = new ReentrantLock();
lock.lock();
try {
    // 同步业务逻辑
} finally {
    lock.unlock();
}
```

标准用法：lock() 加锁，finally 块中 unlock() 解锁，保证锁一定释放，避免死锁。

### 4. volatile 关键字（轻量级同步）

轻量级线程同步机制，保证变量的可见性和禁止指令重排序，但不保证原子性。

适用场景：状态标记量（如线程启停标志），不适合读写复合操作（如 i++）。

### 5. 原子类（JUC 原子包，无锁同步）

java.util.concurrent.atomic 包下的类，基于 CAS（Compare And Swap，比较并交换）无锁算法实现原子操作，无需加锁即可保证线程安全，性能优于锁机制，适合简单的数值操作（AtomicInteger、AtomicLong、AtomicBoolean）。

## 模块五：线程通信与线程池（高级应用）

### 1. 线程间通信

多线程协同完成任务时，需通过通信实现等待-唤醒机制，避免线程盲目执行，核心方式：

- Object 类的 wait() + notify()/notifyAll()：配合 synchronized 使用；
- Condition 接口的 await() + signal()/signalAll()：配合 Lock 锁使用，更灵活，支持多个等待队列；
- CountDownLatch、CyclicBarrier、Semaphore（JUC 工具类）：解决复杂线程协同问题。

### 2. 线程池（生产环境必用，禁止手动创建线程）

**线程池核心作用**

- 复用线程，避免频繁创建/销毁线程的资源消耗；
- 控制线程数量，防止线程过多导致系统崩溃；
- 统一管理线程，提升任务调度效率。

**核心参数（ThreadPoolExecutor，必考）**

- **corePoolSize**：核心线程数，线程池常驻线程；
- **maximumPoolSize**：最大线程数，线程池允许创建的最大线程数量；
- **keepAliveTime**：非核心线程空闲超时时间，超时自动销毁；
- **workQueue**：任务队列，存储待执行的任务；
- **threadFactory**：线程工厂，自定义线程创建；
- **handler**：拒绝策略，任务超出线程池承载能力时的处理策略。

**常用线程池（Executors 工具类，生产慎用，推荐手动创建）**

- **FixedThreadPool**：固定线程数线程池，适合稳定任务；
- **CachedThreadPool**：缓存线程池，线程数动态调整，适合大量短任务；
- **ScheduledThreadPool**：定时任务线程池，替代 Timer；
- **SingleThreadExecutor**：单线程线程池，保证任务串行执行。

## 模块六：高频问题与避坑指南（实战 + 面试必备）

### 1. 死锁问题

- **死锁产生条件**：互斥条件、请求与保持条件、不可剥夺条件、循环等待条件，四个条件同时满足才会发生死锁。
- **死锁解决办法**：避免嵌套锁、统一锁获取顺序、设置锁超时时间、避免线程长时间持有锁。

### 2. 线程池使用禁忌

禁止使用 Executors 创建线程池（易导致 OOM），推荐手动创建 ThreadPoolExecutor；合理设置核心线程数，CPU 密集型任务设为 CPU 核心数 + 1，IO 密集型任务设为 2 * CPU 核心数。

### 3. 锁使用避坑

- 锁粒度尽量小，只锁定共享资源操作代码，不锁定无关逻辑；
- Lock 锁必须在 finally 中解锁，避免异常导致锁泄漏；
- 区分锁对象，避免锁无效对象。

### 4. 线程终止规范

禁止使用 stop()、destroy() 等废弃方法强制终止线程，通过 volatile 标志位或 interrupt() 中断标志位，配合业务逻辑优雅退出线程。

## 模块七：核心总结

Java 多线程核心围绕线程创建、状态切换、同步安全、线程池、线程协同五大核心展开，基础阶段重点掌握线程实现方式、生命周期、常用方法；进阶阶段攻克线程安全、锁机制、线程池；实战阶段规避死锁、锁泄漏、线程池滥用等问题。

生产环境优先使用线程池 + Lock 锁 + JUC 工具类，兼顾效率与安全；面试重点关注线程状态、锁机制、线程池参数、死锁、sleep 与 wait 区别等核心考点，吃透这些知识点，即可应对绝大多数多线程场景。
