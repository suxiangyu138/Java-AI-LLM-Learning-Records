# 第二章 使用Redis构建Web应用

## 2.1 Web 项目引入 Redis 的核心价值
传统 Web 应用完全依赖 MySQL 存储与查询，存在明显瓶颈：
1. 高并发场景下数据库连接压力大、查询延迟高；
2. 高频重复查询（用户信息、首页数据、配置信息）浪费数据库资源；
3. 缺少高效的临时数据、限时数据、计数、排队、分布式控制能力。

Redis 作为**内存高速中间件**，接入 Web 项目后可实现：
- 读写性能大幅提升，降低接口响应时间；
- 削峰填谷，分担关系型数据库压力；
- 快速实现 Web 通用业务能力，减少重复开发。

---

## 2.2 Web 应用经典分层架构（MySQL + Redis）

### 2.2.1 读写缓存架构流程
1. **查询流程**
   客户端请求 → 先查询 Redis 缓存 → 缓存命中直接返回数据
   → 缓存未命中 → 查询 MySQL 数据库 → 写入 Redis 缓存 → 返回结果

2. **更新流程**
   执行新增/修改/删除业务 → 优先更新 MySQL 持久化数据
   → 删除或更新对应 Redis 缓存 → 保证缓存与数据库最终一致

### 2.2.2 架构优势
- **查询加速**：内存读取毫秒级响应，适配高并发 Web 接口；
- **数据库保护**：拦截 70% 以上热点查询请求；
- **业务解耦**：缓存层独立，不侵入原有数据库业务代码。

## 2.3 Redis 支撑的 Web 核心业务场景

### 2.3.1 会话与登录状态管理
Web 项目中用户登录 Token、Session 共享：
- 替代传统服务器 Session 绑定，实现**分布式会话**；
- 设置 key 过期时间，自动控制登录有效期、自动下线；
- 适合集群、微服务架构下多节点登录状态同步。

### 2.3.2 验证码与临时凭证存储
短信验证码、图片验证码、临时授权码：
- 短时间限时存储，利用 Redis 过期特性自动失效；
- 防暴力刷码、限制单用户发送频率。

### 2.3.3 热点页面与静态数据缓存
首页导航、商品列表、公告、系统配置等低频变动数据：
- 全页缓存、接口结果缓存；
- 定时刷新缓存，平衡实时性与性能。

### 2.3.4 点赞、收藏、浏览量计数器
文章、评论、作品互动数据：
- 利用 String 原子自增命令，高性能计数；
- 定时异步落地到数据库，避免频繁写库。

### 2.3.5 接口限流与防刷
Web 接口防爬虫、恶意请求、高频访问：
- 限制单 IP、单账号单位时间访问次数；
- 避免接口被恶意攻击导致服务雪崩。

### 2.3.6 简单延时队列与异步任务
基于 List / Stream 实现轻量异步处理：
- 订单超时关闭、消息推送、日志异步上报；
- 无需额外部署 MQ，适合中小型 Web 项目。

## 2.4 Web 项目缓存常见问题

### 2.4.1 缓存穿透
**问题**：查询不存在的数据，直接穿透到数据库，压垮库。
**解决方案**：空值缓存、布隆过滤器、接口参数校验。

### 2.4.2 缓存击穿
**问题**：热点 Key 过期瞬间，大量请求同时打向数据库。
**解决方案**：互斥锁、热点 Key 永不过期、定时预热缓存。

### 2.4.3 缓存雪崩
**问题**：大量缓存 Key 同时过期 / Redis 宕机，数据库瞬间承压。
**解决方案**：过期时间加随机偏移、Redis 高可用、服务降级熔断。

### 2.4.4 缓存与数据库一致性
**问题**：缓存更新不及时，出现脏数据。
**解决方案**：删除缓存策略、延迟双删、最终一致性方案。

## 2.5 Java Web 整合 Redis 基础方案

### 2.5.1 主流客户端
- **Jedis**：原生客户端，轻量，适合简单项目；
- **Lettuce**：Spring 生态默认，支持异步、连接池；
- **Spring Data Redis**：框架整合方案，开发效率最高。

### 2.5.2 整合核心步骤
1. 引入 Redis 依赖；
2. 配置 Redis 服务地址、端口、密码、连接池；
3. 注入 `RedisTemplate` 工具类；
4. 封装通用缓存工具方法（存、取、删、设置过期）；
5. 在业务接口中加入缓存逻辑。

---

## 2.6 本章小结
1. Redis 是现代 Web 应用**标配中间件**，核心作用是缓存加速与业务能力扩展；
2. 「MySQL 持久化 + Redis 缓存」是互联网 Web 项目标准架构；
3. 覆盖登录、限流、计数、缓存、消息等高频 Web 场景；
4. 开发中必须解决穿透、击穿、雪崩、数据一致性四大缓存问题；
5. Java 技术栈通过 Spring Data Redis 快速完成整合开发。
