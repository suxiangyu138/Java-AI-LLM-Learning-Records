# 「环境变量」同类核心概念
与环境变量类似的核心概念

## 一、系统/进程级同类概念
1. 注册表（Windows Registry）
    - 本质：Windows系统的分层键值数据库，比环境变量更底层、存储更复杂的系统/软件配置
    - 和环境变量的关系：环境变量本质就是存在注册表中的一组特殊键值对
    - 用途：系统启动项、软件安装信息、权限配置、系统深层设置
2. 配置文件（.env / .properties / .yaml / .json）
    - 本质：文件形式的静态键值对配置
    - 和环境变量的关系：环境变量是「内存级全局配置」，配置文件是「磁盘级持久化配置」
    - 用途：项目参数、数据库地址、接口密钥、环境区分
3. 命令行参数（CLI Args）
    - 本质：启动程序时临时传入的参数
    - 和环境变量的关系：都是给程序传配置，优先级：命令行参数 > 环境变量
    - 用途：临时指定端口、环境、日志级别、启动模式
4. 系统属性（JVM System Property）
    - 本质：Java虚拟机内部的键值对配置
    - 和环境变量的关系：JVM 独有，比系统环境变量更精准控制Java程序
    - 用途：编码设置、系统信息、自定义程序参数
 
## 二、开发架构层面同类概念
5. 上下文（Context）
    - 本质：程序运行时的全局状态容器
    - 和环境变量的关系：环境变量是「系统级上下文」，Context 是「代码级上下文」
    - 用途：Spring上下文、HTTP请求上下文、进程运行时状态传递
6. 依赖注入（DI）
    - 本质：外部给程序注入配置/对象，而非程序自己硬编码
    - 和环境变量的关系：环境变量是最简单的「外部注入方式」
    - 用途：Spring Boot 自动配置、解耦代码与配置
7. 启动参数 / 运行参数
    - 本质：容器、应用启动时的动态配置项
    - 和环境变量的关系：Docker/K8s 中环境变量是标准注入方式
    - 用途：容器环境配置、云原生动态扩容配置
 
## 三、网络/服务层面同类概念
8. 请求头（HTTP Header）
    - 本质：HTTP请求中的键值对元数据
    - 和环境变量的关系：环境变量是「进程全局」，Header 是「单次请求全局」
    - 用途：Token、认证信息、客户端信息、跨域配置
9. Cookie / Session
    - 本质：浏览器/服务端存储的用户级键值对
    - 和环境变量的关系：环境变量是「机器级全局」，Cookie 是「用户会话级全局」
    - 用途：登录状态、用户偏好、会话跟踪
10. 全局变量
    - 本质：代码内整个程序都能访问的变量
    - 和环境变量的关系：环境变量是操作系统级的全局变量
    - 用途：代码内全局状态、常量配置
 
## 四、容器/云原生同类概念
11. Docker 环境变量 / K8s ConfigMap & Secret
    - 本质：容器编排系统中标准化的配置注入方案
    - 和环境变量的关系：是环境变量在云原生时代的标准化形态
    - 用途：微服务配置、敏感信息加密、动态环境切换
12. 变量替换 / 占位符
    - 本质：配置中用  ${key}  动态取值
    - 和环境变量的关系：Spring、Maven、Shell 都支持读取环境变量做占位符替换
    - 用途：配置文件动态化、多环境适配
 
核心共性总结
所有这些概念，底层逻辑完全一致：
都是「键值对」形式，用来做：配置与代码解耦、外部注入、全局共享、环境隔离
区别只在：
- 作用范围：系统级 / 用户级 / 进程级 / 请求级 / 会话级
- 存储位置：内存 / 磁盘 / 网络 / 注册表
- 生命周期：永久 / 会话 / 临时
 
优先级排序（开发必记）
命令行参数 > 运行时参数 > 环境变量 > 配置文件 > 硬编码
