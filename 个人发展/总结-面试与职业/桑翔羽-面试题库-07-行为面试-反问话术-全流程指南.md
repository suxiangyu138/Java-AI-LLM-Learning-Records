## 二、项目与能力类

### 4. 你最自豪的一个项目/一个难题？

**推荐选 SuGuangMall 的 Multi-Agent 或灵枢的安全设计**。

**例子（SuGuangMall Multi-Agent）**：
> "最自豪的是在 SuGuangMall 中实现了 Multi-Agent 购物管家。这不是简单的调 API，而是设计了一整套 Agent 系统：
>
> - 6 个专业 Agent，按不同购物场景分工
> - AgentRouter 做意图路由，自动选择最合适的 Agent
> - YAML 技能热加载，新增 Agent 能力不用重启
> - 双层会话存储，支持多轮对话
>
> **遇到的难题**：Agent 有时候会陷入死循环——模型反复调用同一个工具但结果没变化。我的解决方式是加了最大步骤限制 + 工具调用去重检测，同一工具同一参数连续调用 2 次就强制模型结束循环。"

### 5. 你做过的最失败的决定/最大的教训？

**真实案例（体现成长）**：
> "在 Flavor Dash 项目初期，我试图一次把所有 AI 功能都做出来——AI 客服、智能推荐、NL2SQL 运营看板、AI 调度、AI 菜单优化——结果摊子铺太大，各个功能都做不精。
>
> **教训**：后来我改成 MVP 策略：先做一个最好做的（AI 客服），把它做到能用、稳定，再用同样的架构范式复制到其他模块。这让我学会了'先窄后宽，先深后广'。"

### 6. 怎么平衡技术追求和业务交付？

> "我的原则是：技术选型服从业务需求，但不放过用技术手段提升业务价值的机会。
>
> 比如在医疗项目中，如果只是为了'能用'，一个简单的 LLM 调用就能回答问题。但医疗场景要求高安全性和可信度，所以我设计了 14 步 RAG 管线 + 多层护栏。这不是过度设计，而是业务必要性驱动。
>
> 反过来，如果只是一个内部管理后台，我不会上微服务和 K8s，单体 + Docker Compose 足够了。"

### 7. 你如何学习新技术？（展示学习能力）

> "我的学习方法论是四步走：
>
> **1. 建立认知框架（30 分钟）**
> 先用中文技术博客/视频快速了解：这个技术解决什么问题？核心概念是什么？
>
> **2. 看官方文档 + 源码关键部分（2~4 小时）**
> 不看二手解读，直接看官方 Quick Start 和核心类源码
>
> **3. 动手写 Demo（1~2 小时）**
> 一定要亲手敲代码，很多坑只看文档看不出来
>
> **4. 在真实项目中应用 + 输出总结**
> 落地过程中遇到问题 → 搜索/看 Issue/读源码 → 解决后写博客/笔记
>
> **例子**：学 LangChain4j 时，我先花 30 分钟看官网介绍，然后跑通了 Quick Start，接着去看 AiServices、ToolSpecification 的源码理解它怎么和 LLM 交互的，最后在 SuGuangMall 中落地了 Multi-Agent 系统。"

### 8. 你觉得一个好的程序员需要具备什么？

> "四个关键词：**责任心、学习力、工程思维、沟通能力**。
>
> 责任心：对自己写的代码负责——不只是功能正确，还要考虑边界条件、异常处理、可读性、可维护性。
>
> 学习力：技术迭代太快，不学习就会被淘汰。关键不是知道多少，而是多快能学会新东西。
>
> 工程思维：能区分'能用'和'好用'。写代码之前先想清楚架构、扩展性、监控怎么做，而不是边写边改。
>
> 沟通能力：技术最终是为人服务的。能把复杂的技术方案讲清楚、和产品/业务方对齐需求，这和写代码一样重要。"

## 三、团队协作类

### 9. 和团队成员意见不一致怎么办？

> "首先，我会先理解对方的出发点和依据——他是基于什么数据、经验或业务需求提出这个方案的？
>
> 然后，用数据和 Demo 说话。比如如果我们在争论用 Redis Cluster 还是哨兵模式，我会做简单的压测对比——Redis Cluster 在 10W QPS 下表现如何？哨兵模式下主从切换的延迟是多少？
>
> 如果分歧在实现细节上，可以两方快速写个 PoC（概念验证代码）对比。
>
> 最终决策：以团队和项目的目标为导向。如果对方方案确实更好，我完全接受。如果各有优劣，列出 trade-off 让 lead 决策。"

### 10. 如果 deadline 临近但任务做不完怎么办？

> "**提前沟通，不要硬撑。**
>
> 1. **尽早暴露风险**：发现可能做不完时，第一时间和 leader 同步，不要拖到最后一天才说
> 2. **提供方案选项**：带着方案去沟通，不是只报告问题：
>    - 方案 A：砍掉不重要的功能，先保证核心链路
>    - 方案 B：找同事帮忙分担
>    - 方案 C：延期，但给出明确的新时间线
> 3. **事后复盘**：为什么预估不准？下次如何改进？
>
> 关键心态：deadline 不是用来崩溃的，是用来排序的。"

### 11. 你是怎么推进一个项目的？

> "以 SuGuangMall 为例，我的项目推进方式：
>
> **Phase 1：需求拆解 + 方案设计（1~2 天）**
> 先把大目标拆成可执行的小模块（用户服务、商品服务、订单服务、AI 服务...），明确每个模块的输入输出、技术选型、依赖关系。
>
> **Phase 2：MVP 先行（1 周）**
> 先跑通核心链路——用户注册登录 + 商品展示 + 下单，能跑就行。有了骨架再填肉。
>
> **Phase 3：逐步迭代**
> - Round 1：加微服务能力（Nacos、Gateway、Sentinel）
> - Round 2：加高并发能力（秒杀、分库分表）
> - Round 3：加 AI 能力（Multi-Agent、以图搜图、RAG）
>
> **Phase 4：收尾 + 文档**
> 测试 → 部署 → 写 README → 总结复盘。"

## 四、适配性类

### 12. 为什么想来我们公司/团队？

**公式**：公司吸引你的点 + 你能力匹配的点 + 你想学到的东西。

**示例（面 AI 应用方向的团队）**：
> "两个原因。
> 一是我看到贵团队在做 [具体业务]，这个方向我非常有兴趣而且有一定经验——我在项目中落地过 [相关经验]。
> 二是贵团队的技术氛围——[举一个公司的技术输出：博客/开源项目/技术分享]，这对我的成长非常重要。
> 我希望找到一个能把 Java 后端工程能力和 AI 应用开发结合起来的岗位，贵团队恰好是这样。"

### 13. 你对加班怎么看？

> "为了项目目标必要的加班，我完全可以接受。特别是上线、紧急问题修复这样的关键节点。
>
> 但我认为长期、频繁的加班通常意味着流程或项目管理出了问题——需求不明确、排期不合理、技术债太多。健康的团队应该追求效率而不是拼时长。
>
> 我个人更关注的是：在这个岗位上，我能不能快速成长。只要能学到东西、做出成绩，加班不是问题。"

### 14. 你的期望薪资是多少？

**回答原则**：
- 提前查好行情（Boss 直聘、牛客 offer 小程序、脉脉）
- 给出一个区间而不是一个数字
- 可以表达灵活性

> "我了解过目前合肥 Java 后端实习生的市场薪资。我的期望是 X~Y/天，不过我也很看重成长机会和团队氛围，薪资可以根据具体情况商量。"

**市场参考**（2025~2026 合肥/南京/杭州）：
- Java 后端实习生：150~300/天
- AI 应用开发方向实习生：200~400/天
- 大厂实习（杭州/上海）：300~500/天

### 15. 你还有其他 Offer 吗？

> （如实回答，但不要给面试官"我是海王"的感觉）
>
> 如果没 Offer： "目前刚开始投，贵公司是我优先考虑的。"
> 如果有一两个： "手上有 X 家在面，但我更倾向贵公司，因为 [说原因]。"
> 如果有竞争性 Offer： 说明你有竞争力，但不要摆出"你爱要不要"的姿态。

## 五、反问面试官（必问！展示你的深度）

### 技术面试官

| 推荐反问 | 为什么要这么问 |
|---------|-------------|
| "团队目前的技术栈是什么样的？在用什么版本的 Spring Boot / JDK？" | 展示你关心实际技术，同时也帮你判断团队水平 |
| "团队目前有在落地 AI 相关的功能吗？是在用大模型做哪些场景？" | 对你的 AI 方向有加分，也帮你判断岗位匹配度 |
| "团队的代码规范和 Code Review 流程是怎样的？" | 展示你的工程化意识 |
| "团队现在的技术挑战是什么？有什么难点是一直想解决但没来得及解决的？" | 很好的问题，展示你愿意啃硬骨头 |
| "从您的角度看，这个岗位最关键的技能和素质是什么？" | 帮你了解面试官的期望，也方便后面补答 |
| "团队的部署和运维方式是什么样的？用 K8s 还是 Docker Compose？" | 展示你的 DevOps 意识 |

### HR 面试官

| 推荐反问 | 说明 |
|---------|------|
| "实习生的培养计划是什么样的？有没有 mentor 带？" | 必问，了解你能学到什么 |
| "转正的比例和条件大概是什么？" | 了解转正机会 |
| "团队的工作节奏大概是怎样的？" | 委婉了解加班情况 |
| "如果我拿到 offer，入职前有什么可以提前准备的？" | 加分，展示主动性 |

### 避免问的问题
- ❌ "公司是做啥的？"（面试前就应该查清楚）
- ❌ "几点下班？加班多吗？"（太直接，用其他方式了解）
- ❌ "薪资能再高点吗？"（等 offer 阶段再谈）
- ❌ "我这个岗位到底做什么？"（JD 上应该写了）

## 六、面试全流程指南

### 面试前 24 小时 Checklist

```
技术准备：
☐ 复习自己最亮眼的 2 个项目（架构、难点、量化数据）
☐ 过一遍 Java 基础高频考点（HashMap、线程池、JVM）
☐ 准备 1 个技术难题的完整叙述（STAR 原则）
☐ 如果面 AI 方向：深度复习 RAG、Agent、模型网关

公司调研：
☐ 公司官网：产品/业务、技术栈、团队规模
☐ 面试官背景（如果能查到 LinkedIn/脉脉）：技术方向、文章
☐ 牛客/脉脉面经：这个公司面试风格、常问问题
☐ 准备 3 个针对性的反问

环境准备（视频面试）：
☐ 安静、光线充足的房间
☐ 测试摄像头、麦克风、网络
☐ 如果是共享屏幕：关掉聊天软件、清理桌面
☐ 准备纸笔（有时需要画架构图、推导算法）

心态准备：
☐ 面试是把你的能力展示出来，不是考试
☐ 不会的问题 ≠ 面试失败（思考过程也是分）
☐ 把每次面试当作"和同行交流学习的机会"
```

### 面试中

```
开场（前 30 秒）：
  ✓ 微笑 + 自信打招呼
  ✓ "面试官您好，我是桑翔羽"

自我介绍（1~2 分钟）：
  ✓ 教育背景（1 句）
  ✓ 技术栈（2~3 句）
  ✓ 项目亮点（选 1~2 个带量化数据的）
  ✓ 求职意向（1 句）

回答问题（STAR 原则）：
  S - Situation（情境）
  T - Task（任务）
  A - Action（行动）← 最重点
  R - Result（结果，带数据）

遇到不会的题：
  ✓ "这个问题我了解不深，但我可以尝试分析一下..."（展示思考过程）
  ✓ "这部分我确实没接触过，但我理解核心可能是..."（关联已有知识）
  ✗ 不要硬编答案

技术题写代码：
  ✓ 先讲思路，再写代码
  ✓ 边写边讲（让面试官跟着你的思路）
  ✓ 写完后主动跑一个测试用例
  ✓ 考虑边界情况（null、空输入、极端值）

反问环节（2~3 个问题）：
  ✓ 展示你对技术/业务的思考深度
  ✓ 打听团队氛围和发展空间
```

### 面试后

```
立即：
☐ 记录面试中被问到的问题（不管会不会）
☐ 标记答得不好的部分 → 面试后补充学习

当天：
☐ 如果拿到了面试官邮箱，发感谢信（简短即可）
   "感谢您今天的时间，关于 [某个问题] 我后来想了一下 [补充内容]..."
   
☐ 复盘：哪几个问题答得不好？为什么？下次怎么说？

☐ 更新自己的面试题库
```

### 面试中常见的"坑"

| 坑 | 怎么避开 |
|----|---------|
| "你还有什么问题吗？" → 说没有 | 至少准备 2~3 个有深度的问题！ |
| 自我介绍照着简历念 | 简历面试官手里有，自我介绍要说简历上不写的：为什么选这个方向？最大的成就感？ |
| 被连续追问答不上来 → 慌了 | 深呼吸，说"让我想想"。面试官想看你的思维过程，不是标准答案 |
| 说前公司的坏话（你没有，但注意不要说学校/老师的） | 任何评价保持客观，聚焦自己能学到什么 |
| "我精通 xxx" | 说"熟练掌握"或"在项目中实践过"，留有余地。精通是面试官判断的 |
| 回答太简短（1~2 句） | 每个问题至少展开 3~5 句：概念 → 原理 → 项目中的应用 → 遇到的坑 |

## 七、不同公司面试风格差异

### 大厂（阿里/腾讯/字节/美团）

**特点**：
- 算法题必考（LeetCode 中等难度，注重思路和分析复杂度）
- 项目深挖（追问到你不会为止，看你的上限）
- 基础知识面广（网络、OS、数据库原理）
- 系统设计（有一定工作经验的，实习生较少）

**准备策略**：
- 算法：刷高频 50 题，每道题能讲清楚复杂度分析
- 基础知识：计算机网络/操作系统补充（题库 02）
- 项目：准备被连续追问 5 层的深度

### 中厂（小红书/B站/得物/各类独角兽）

**特点**：
- 偏重实际工程能力（更关心你能不能干活）
- 场景题多（"这个功能你怎么实现？"）
- 算法难度相对低
- AI 应用方向的可能会重点问你的 AI 经验

**准备策略**：
- 项目经验是核心：能展示出独立搭建项目的能力
- 场景题（题库 05 的系统设计和场景题）
- 你的 AI 经验是中厂的差异化加分项

### 创业公司

**特点**：
- 广度比深度重要（一个人可能负责多个模块）
- 自驱力和学习能力很重要
- 技术栈可能比较前沿
- 可能直接让你现场写一个小功能

**准备策略**：
- 展示学习能力（自学的 AI 方向就是最好的证明）
- 展示全栈能力（从后端到部署到 AI 都能做）
- 准备好解决模糊问题的能力（创业公司需求变化快）

### 外企

**特点**：
- 行为面试占比高（STAR 重度使用）
- 代码质量 > 速度（命名、注释、测试）
- 英语交流能力（可能部分英文面试）
- 系统设计更偏实际

**准备策略**：
- 准备好行为面试故事（英文版也要准备）
- 英文自我介绍 + 英文技术讨论
- 代码写干净的、有注释的、有测试意识的
