## 二、数据结构（第一优先级）

> 一切算法面试的根基，先啃透再往下走。

### 2.1 知识分层

```
Level 1：基础结构（必掌握）
   数组、链表、栈、队列、哈希表、字符串

Level 2：树与图（核心）
   二叉树、二叉搜索树、堆、AVL/红黑树概念
   图的遍历（DFS/BFS）、最短路径

Level 3：算法思想（升华）
   递归、分治、贪心、动规、回溯、双指针、滑动窗口

Level 4：进阶（加分项）
   并查集、Trie 树、线段树、拓扑排序、位运算
```

### 2.2 必须能口述的 10 个核心知识点

| # | 知识点 | 口述要点 |
|---|--------|----------|
| 1 | 数组 vs 链表 | 内存连续/非连续，随机访问 O(1)/O(n)，插入删除 O(n)/O(1) |
| 2 | 栈与队列 | LIFO vs FIFO，各自应用场景（括号匹配、BFS）|
| 3 | 哈希表原理 | 哈希函数 → 冲突解决（链地址法/开放定址法）→ 扩容 rehash |
| 4 | 二叉树遍历 | 前序(根左右)、中序(左根右)、后序(左右根)、层序（BFS） |
| 5 | 堆（优先队列） | 完全二叉树，大顶堆/小顶堆，插入上浮、删除下沉 |
| 6 | 快排原理 | 选 pivot → partition → 递归左右，平均 O(nlogn)，最坏 O(n²) |
| 7 | 二分查找 | 有序数组，每次折半，O(log n)，注意 mid 防溢出 |
| 8 | 动态规划 | 最优子结构 + 重叠子问题，自底向上填表 vs 记忆化递归 |
| 9 | DFS vs BFS | 走迷宫(栈/回溯) vs 最短路径(队列/层序)，图/树的搜索基础 |
| 10 | 链表反转 | 双指针 prev/curr，逐个改指针方向，O(n) |

### 2.3 刷题路线

```
入门（30 题）：数组、链表、栈、队列、哈希表 → 熟悉基本操作
基础（40 题）：树、DFS/BFS、二分查找、双指针、滑动窗口
进阶（50 题）：动态规划、回溯、图、并查集、单调栈、前缀和
高频（30 题）：LeetCode Hot 100、剑指 Offer → 反复刷 3 遍
```

## 三、计算机组成原理（硬件的视角）

> 理解"程序如何在硬件上跑起来"，建立从晶体管到程序的完整链路。

### 3.1 核心逻辑链

```
高级语言 → 编译 → 汇编 → 机器指令 → CPU 执行 → 内存读写 → I/O 交互
          │                │           │           │           │
     编译器原理       指令系统    数据通路     存储层次     外设管理
```

### 3.2 必须能口述的 10 个核心知识点

| # | 知识点 | 口述要点 |
|---|--------|----------|
| 1 | 冯诺依曼体系 | 五大部件：运算器 + 控制器 + 存储器 + 输入 + 输出，存储程序原理 |
| 2 | 补码为什么存在 | 统一加减法（减法变补码加法），0 的表示唯一 |
| 3 | IEEE 754 浮点数 | 符号位 + 阶码(移码表示) + 尾数(1.xxx 隐含第一位)，精度损失原因 |
| 4 | Cache 为什么快 | 局部性原理（时间/空间局部性），SRAM vs DRAM 速度差异 |
| 5 | Cache 映射方式 | 全相联（灵活但慢）、直接映射（快但冲突多）、组相联（折中主流）|
| 6 | 虚拟内存 | 逻辑地址 → 页表 → 物理地址，TLB 加速，缺页中断换入磁盘 |
| 7 | 指令流水线 | 五级流水：IF→ID→EX→MEM→WB，流水线冲突及解决 |
| 8 | 中断全过程 | 中断请求 → 响应（关中断、保护现场）→ 服务程序 → 恢复现场 → 返回 |
| 9 | DMA 为什么快 | 数据传送不经过 CPU，总线直接由 DMA 控制器接管 |
| 10 | 主存与 Cache 地址映射 | 主存地址 = 标记(主存字块标记) + 行号(Cache行号) + 块内地址 |

### 3.3 知识框架速记

```
计算机系统 = CPU + 主存 + I/O

CPU 内部：
├── 运算器（ALU + 累加器 + 寄存器）：做计算
├── 控制器（PC + IR + CU）：指挥各部件工作
└── 寄存器组（通用 + 专用）

存储层次（速度越快越贵越少）：
寄存器 (1ns) → Cache (L1/L2/L3, 5-20ns) → 主存 DRAM (50-100ns) → 磁盘 SSD (μs) → 机械盘 (ms)

程序执行流程：
取指令(PC→MAR→主存) → 指令放入 IR → 译码 → 执行 → 写回 → PC+1 → 循环
```

## 四、操作系统（软硬件之间的桥梁）

> 理解"多个程序如何共享一台计算机的资源"。

### 4.1 四大管理职能

```
操作系统
├── 进程管理：CPU 给谁用、什么时候用
├── 内存管理：内存怎么分配、怎么回收
├── 文件管理：数据如何组织在磁盘上
└── I/O 管理：怎么跟外设交互
```

### 4.2 必须能口述的 10 个核心知识点

| # | 知识点 | 口述要点 |
|---|--------|----------|
| 1 | 进程 vs 线程 | 进程是资源分配的基本单位（独立地址空间），线程是 CPU 调度的基本单位（共享地址空间） |
| 2 | 进程状态转换 | 就绪 ↔ 运行 ↔ 阻塞，以及创建/终止状态 |
| 3 | 调度算法对比 | FCFS（不公平）、SJF（最优但不可实现）、RR（公平响应快）、多级反馈队列（实际 OS 用） |
| 4 | 信号量（PV 操作） | P(加锁/等待)、V(解锁/唤醒)，解决互斥与同步 |
| 5 | 死锁四个条件 + 处理 | 互斥/请求保持/不可剥夺/循环等待；鸵鸟/预防/避免/检测解除 |
| 6 | 分页 vs 分段 | 分页（固定大小，对外透明）；分段（逻辑单位，用户可见）；段页式（两者结合） |
| 7 | 页面置换算法 | OPT(理论最优)、FIFO(Belady 异常)、LRU(最近最久未用)、CLOCK(近似 LRU、OS 实践) |
| 8 | 虚拟内存 = 请求分页 + 页面置换 | 程序不用全部加载到内存，按需调入，换出暂时不用的 |
| 9 | 文件物理结构 | 连续分配(便于顺序存取)、链接分配(无外部碎片)、索引分配(inode，综合最优) |
| 10 | 磁盘访问时间 | 寻道时间(最主要) + 旋转延迟 + 传输时间 |

### 4.3 一条线索串联

```
写了一段代码 .cpp
  ↓ 编译
可执行文件 .exe（存储在磁盘）
  ↓ 双击运行
创建进程（PCB + 分配内存）→ 就绪态
  ↓ 调度器选中
CPU 上运行（用户态）
  ↓ 调用 printf
系统调用（切换到内核态）→ 内核处理 I/O → 结果输出 → 返回用户态
  ↓ 程序结束
进程终止 → 资源回收
```

## 五、计算机网络（多机通信的艺术）

> 理解"两台计算机如何跨越千里进行可靠通信"。

### 5.1 TCP/IP 协议栈

```
应用层（应用进程间通信）   HTTP / DNS / FTP / SMTP
        │
传输层（端到端）           TCP (可靠) / UDP (快速)
        │
网络层（主机到主机）        IP / ICMP / ARP / 路由协议
        │
链路层（相邻节点间）        以太网 / MAC / 交换机
        │
物理层（物理介质）          网线 / 光纤 / 无线
```

### 5.2 必须能口述的 10 个核心知识点

| # | 知识点 | 口述要点 |
|---|--------|----------|
| 1 | 输入 URL 到显示页面的全过程 | DNS 解析 → TCP 三次握手 → HTTP 请求 → 服务器处理 → HTTP 响应 → 浏览器渲染 → 四次挥手 |
| 2 | TCP 三次握手 | SYN → SYN+ACK → ACK；为什么三次？（防止过期连接请求，同步双方初始序列号）|
| 3 | TCP 四次挥手 | FIN→ACK→FIN→ACK；为什么四次？（TCP 全双工，每方向独立关闭）；TIME_WAIT 等 2MSL |
| 4 | TCP 如何保证可靠 | 确认应答 + 超时重传 + 序号/确认号 + 流量控制（滑动窗口）+ 拥塞控制 |
| 5 | TCP 拥塞控制 | 慢开始(指数增长)→拥塞避免(线性增长)→快重传(3个冗余ACK)→快恢复(降ssthresh而非降到1) |
| 6 | TCP vs UDP | TCP 可靠面向连接/开销大/有序；UDP 不可靠无连接/开销小/实时性好（视频/语音/DNS）|
| 7 | HTTP 1.1 vs 2.0 vs 3.0 | 1.1(串行/Keep-Alive)→2.0(二进制/多路复用/头部压缩)→3.0(QUIC/UDP/0-RTT) |
| 8 | HTTPS = HTTP + TLS | 非对称加密交换会话密钥 → 对称加密通信；中间人攻击原理与证书体系 |
| 9 | DNS 解析过程 | 浏览器缓存→OS hosts→本地 DNS 服务器→根域名服务器→顶级域→权威 DNS→逐级返回 |
| 10 | 路由协议对比 | RIP(距离向量/跳数15限制/简单) vs OSPF(链路状态/Dijkstra/收敛快) vs BGP(路径向量/跨自治域) |

### 5.3 TCP 状态机（面试最爱）

```
CLOSED → LISTEN → SYN_RCVD → ESTABLISHED
                     ↑
CLOSED ← TIME_WAIT ← FIN_WAIT_2 ← FIN_WAIT_1
```

## 六、数据库（数据可靠性守护者）

> 理解"如何保证数据不丢不错、查询又快又准"。

### 6.1 核心三件事

```
数据库核心能力：
├── 存得对（完整性、范式设计）
├── 查得快（索引优化、SQL 调优）
└── 不出错（事务 ACID、并发控制）
```

### 6.2 必须能口述的 10 个核心知识点

| # | 知识点 | 口述要点 |
|---|--------|----------|
| 1 | 事务 ACID | 原子性(Undo Log)/一致性(约束保证)/隔离性(MVCC+锁)/持久性(Redo Log) |
| 2 | 四种隔离级别 | RU(脏读)→RC(不可重复读)→RR(幻读)→Serializable(全串行)；MySQL InnoDB 默认 RR |
| 3 | MVCC 原理 | ReadView + Undo Log 版本链，每个事务看到自己的快照，读不阻塞写 |
| 4 | B+ 树索引 | 所有数据在叶子节点，叶子用双向链表连接（范围查询友好）；千万级数据 3-4 层 |
| 5 | 聚簇索引 vs 非聚簇索引 | 聚簇索引叶子存完整行数据（有且仅有一个）；非聚簇索引叶子存主键值（需回表） |
| 6 | 最左前缀原则 | 联合索引 (a,b,c) 中：WHERE a=1 ✅ / WHERE b=1 ❌ / WHERE a=1 AND c=1 只能用 a |
| 7 | 索引失效场景 | 函数操作/隐式转换/OR/LIKE '%xxx'/不等于(is not/!=)/最左前缀缺失 |
| 8 | EXPLAIN 使用 | type (const>ref>range>ALL)、key (用到哪个索引)、rows (扫描行数)、Extra (Using index/filesort) |
| 9 | SQL 执行顺序 | FROM→ON→JOIN→WHERE→GROUP BY→HAVING→SELECT→ORDER BY→LIMIT |
| 10 | 三范式 | 1NF(列不可分)、2NF(消除部分依赖)、3NF(消除传递依赖)；大多数场景到 3NF 就够 |

### 6.3 一条 SQL 的执行路径

```
SELECT * FROM user WHERE age > 18 ORDER BY id LIMIT 10;

客户端 → 连接器（认证）→ 分析器（语法解析）→ 优化器（选索引/Join 顺序）
→ 执行器（调用存储引擎接口）→ InnoDB 引擎（B+ 树索引查找）→ 返回数据

REDO LOG（崩溃恢复，物理日志）：先写日志再写磁盘（WAL 预写日志）
UNDO LOG（事务回滚，逻辑日志）：记录修改前的值
BINLOG（主从复制，逻辑日志）：Server 层记录所有修改
```

## 七、五大件交叉复习法

### 7.1 跨课程串联问题

| 串联问题 | 涉及课程 |
|----------|----------|
| 编译后的程序从磁盘加载到 CPU 执行，全过程涉及哪些组件？| 组成原理 + 操作系统 |
| 访问一个网址，从输入 URL 到页面渲染，数据经过了哪些环节？| 计网 + 操作系统 + 数据库 |
| 大量用户同时访问数据库，如何保证数据正确性和响应速度？| 数据库 + 操作系统（并发）|
| 内存不够用时系统怎么做？| 操作系统（虚拟内存）+ 组成原理（Cache）|
| 线程切换和进程切换的区别？为什么线程切换更快？| 操作系统 |
| B+ 树和红黑树各适合什么场景？为什么数据库用 B+ 树？| 数据结构 + 数据库 |
| TCP 的滑动窗口和操作系统的滑动窗口在信号量里有什么联系？| 计网 + 操作系统 |
| 一次 HTTP 请求在 MySQL 中被执行，经历了哪些缓存？| 计网 + 操作系统（文件系统/Cache）+ 数据库 |

### 7.2 口述练习方法

```
费曼学习法（最高效的复习方式）：

1. 拿一张白纸
2. 主题写在最上面（如"TCP 三次握手"）
3. 假装给一个完全不懂的人讲清楚：
   - 为什么需要它？
   - 发生了什么？（分步骤）
   - 能不能比个生活中的例子？
4. 卡壳的地方 → 翻书看 → 继续讲
5. 简化：去专业术语 → 转换成自己能脱口而出的话

每天一个主题，坚持 1 个月就能覆盖五大件各 6 个核心问题。
```
