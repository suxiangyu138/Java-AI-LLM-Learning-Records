# 计算机专业英语

## 一、学科特性认知

### 1.1 计算机英语的三层结构
计算机英语不是一门独立的语言，而是叠在通用英语之上的术语系统：

```
第三层 | 行业黑话/缩写（k8s, LGTM, bike-shedding）
第二层 | 专业术语（middleware, runtime, dependency injection）
第一层 | 通用学术英语（implement, configure, deploy）
地基层 | 基础英语（语法、常用词汇、阅读能力）
```

**学习路径**：地基不牢先补基础，否则直接逐层向上攻克。

### 1.2 核心能力需求排序
1. **阅读英文文档**（最核心，日常最高频）
2. **阅读英文论文/技术博客**（进阶）
3. **英文技术写作**（写 README、注释、API 文档）
4. **英文技术听说**（英文会议、技术演讲）

### 2.3 高频后缀（词性/语义标记）

| 后缀 | 含义 | 示例 |
|------|------|------|
| -ware | ...件 | hardware, software, firmware, middleware |
| -gram | ...程序/图 | program, diagram, histogram |
| -tion/-sion | 动作/过程 | compilation, execution, serialization |
| -er/-or | 执行者/器 | compiler, processor, scheduler, connector |
| -able/-ible | 可...的 | serializable, iterable, callable, readable |
| -ity | 性质/状态 | scalability, availability, compatibility |
| -ize/-ise | 使...化 | initialize, serialize, optimize, synchronize |
| -al | ...的 | computational, algorithmical, procedural |
| -less | 无...的 | serverless, stateless, lossless |

### 2.4 术语拆解实操
遇到陌生术语的标准流程：
1. 识别前缀（定位场景）
2. 识别词根（定位核心概念）
3. 识别后缀（确定词性）
4. 组合推理

示例：
- **deserialization** = de（反向）+ serial（序列）+ ization（过程）→ 反序列化
- **multithreading** = multi（多）+ thread（线程）+ ing（进行中）→ 多线程
- **immutability** = im（否定）+ mut（变化）+ ability（能力）→ 不可变性
- **asynchronous** = a（否定）+ syn（同步）+ chron（时间）+ ous（形容词）→ 异步的

## 三、阅读英文技术文档

### 3.1 文档的结构化阅读法
技术文档有固定结构，不需要从头读到尾：

| 你的需求 | 直接读 | 跳过 |
|---------|--------|------|
| 快速上手 | Quick Start / Getting Started | API Reference |
| 解决具体问题 | API Reference / 对应章节 | Overview |
| 理解概念 | Overview / Concepts / Guide | 代码示例 |
| 排查报错 | Troubleshooting / FAQ / Issues | 其余一切 |
| 评估选型 | Introduction + Features + Limitations | 配置细节 |

### 3.2 英文文档高频句型
| 句型 | 含义 | 注意 |
|------|------|------|
| Note that ... | 请注意... | 后面通常是重要限制条件 |
| It is recommended that ... | 建议... | 不是必须，但是最佳实践 |
| Be aware that ... | 请务必注意... | 后面常有陷阱说明 |
| This is beyond the scope of ... | 超出本文范围 | 不要再找了，文档不打算讲这个 |
| Refer to ... for more details | 详见... | 指路牌，去那边找 |
| As of version X.X | 从 X.X 版本开始 | 注意你的版本是否满足 |
| This has been deprecated since ... | 已废弃 | 不要再用这个 API |
| Under the hood, ... | 底层实现上... | 深入原理的入口 |
| For the sake of simplicity | 为简化起见 | 后面给的不是完整实现 |
| In a nutshell | 简而言之 | 后面是一句话总结 |

### 3.3 提高文档阅读速度的技巧
1. **先看代码块，再看解释文字**：代码能表达的逻辑不需要花时间读英文描述
2. **只看你不懂的**：找 unfamiliar 的关键词和概念，已有知识跳过
3. **利用浏览器翻译插件辅助**：遇到整段看不懂时快速翻译，但专业术语强迫自己记英文原文
4. **建立个人术语索引**：每次遇到新术语，记录英文原文+中文理解+出处链接

## 四、技术英语写作

### 4.1 四大原则
1. **Plain English**：能用简单词不用复杂词
2. **主动语态**："Click the button"（不是 "The button should be clicked"）
3. **一句一事**：每句话只表达一个技术操作或概念
4. **先结论后解释**：同样适用金字塔原理

### 4.2 高频写作场景模板

**README.md 结构模板：**
```markdown
# Project Name
Brief description (one sentence).

## Installation
```bash
npm install xxx
```

## Quick Start
```javascript
const lib = require('xxx')
lib.doThing()
```

## API
### `methodName(param, options)`
Description of what it does.

## License
MIT
```

**Git Commit Message 规范：**
```
<type>: <subject>

<body>
```

常用 type：
- `feat`: 新功能
- `fix`: 修 bug
- `docs`: 文档变更
- `refactor`: 重构
- `perf`: 性能优化
- `test`: 测试
- `chore`: 构建/工具变更

**代码注释要点：**
- 注释解释 WHY（为什么这样做），不是 WHAT（做了什么）
- WHAT 应该通过变量名和函数名自解释
- 不要写 "// increment i by 1"

### 4.3 常见错误
| 错误 | 正确 | 原因 |
|------|------|------|
| The data **is** correct? | The data **are** correct | data 是复数（datum 的复数） |
| Install the **dependant** | Install the **dependency** | dependant = 人（依赖者），dependency = 物 |
| It **effects** performance | It **affects** performance | effect 是名词（效果），affect 是动词（影响） |
| **less** bugs | **fewer** bugs | less 修饰不可数，fewer 修饰可数 |
| it's features | its features | it's = it is，its = 它的 |

## 五、英文技术听说

### 5.1 听懂技术演讲/会议的要点
1. **提前了解议程和关键术语**：会议/演讲的英文关键词提前查好，降低听力认知负荷
2. **关注演示者的幻灯片**：幻灯片上出现的术语和关键句就是你最需要听懂的
3. **抓住"信号词"**：
   - 转折：However / That said / On the other hand
   - 强调：The key point is / What really matters / The main takeaway
   - 结论：In summary / To wrap up / The bottom line is
4. **听不懂时的话术**：
   - "Could you elaborate on that?"
   - "Just to confirm, did you mean ...?"
   - "Could you give a concrete example?"

### 5.2 发音注意事项
技术词汇常被读错，因为它们是"造出来的词"：

| 术语 | 正确发音要点 |
|------|------------|
| cache | /kæʃ/（"凯许"），不是 "凯吃" |
| regex | /ˈrɛdʒɛks/（"瑞杰克丝"） |
| SQL | /ˈsiːkwəl/ 或 /ˌɛs kjuː ˈɛl/ 都可以 |
| JSON | /ˈdʒeɪsən/（"杰森"），不是 "J-S-O-N" |
| async | /eɪˈsɪŋk/（"A-辛克"），不是 "阿辛克" |
| integer | /ˈɪntɪdʒər/（"因替哲"） |
| char | /kɑːr/ 或 /tʃɑːr/ 都通用 |
| lib | /laɪb/（"莱布"） |
| GUI | /ˈɡuːi/（"古伊"） |
| CLI | /ˌsiː ˌɛl ˈaɪ/（逐字母念） |

## 六、学习资源与路径

### 6.1 分级阅读材料
| 级别 | 材料 | 说明 |
|------|------|------|
| 入门 | MDN Web Docs | 写得极好，适合学英文文档阅读 |
| 入门 | freeCodeCamp 文章 | 面向初学者的英文教程 |
| 中级 | 官方文档（React, Vue, Spring） | 每个框架的文档都是好教材 |
| 中级 | Stack Overflow | 学 Q&A 式技术英语表达 |
| 进阶 | 技术白皮书（AWS, Google Cloud） | 正式技术写作风格 |
| 进阶 | 学术论文（arXiv） | 学术英语 + 技术英语 |
| 实战 | GitHub Issues/PR 讨论 | 真实的、非正式的沟通英语 |

### 6.2 每日 25 分钟训练方案
- **前 10 分钟**：读一篇官方文档的某一章节（刻意不查字典，先猜含义）
- **中间 10 分钟**：查刚才遇到的生词，整理到术语本
- **最后 5 分钟**：用英文写 2-3 句话总结今天读了什么

### 6.3 避坑指南
1. 不要死记硬背术语表——在阅读中遇到再记
2. 不要用中文材料学英文术语——用英文文档学英文术语，形成直接映射
3. 不要追求完美理解——技术文档的理解目标不是 100%，而是能正确使用 API
4. 不要忽略缩写——同一缩写在不同语境含义完全不同（如 GC = Garbage Collection / Git Commit / General Catalog）
