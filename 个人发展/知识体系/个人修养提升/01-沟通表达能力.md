# 沟通表达能力

## 一、沟通的本质认知

### 1.1 沟通 ≠ 说话
沟通的第一性原理：**沟通的效果取决于对方接收到的信息，而不是你发出的信息。** 不是你说了什么，而是对方听到了什么、理解了什么、记住了什么。

市面上大部分"沟通技巧"课程都在教你"怎么说"，但真正有效的沟通首先思考"对方怎么听"。

### 1.2 沟通的四种目的
每次开口之前，先问自己：这次沟通的目的是什么？

| 目的 | 场景 | 成功标准 |
|------|------|---------|
| **告知** | 同步进度、汇报工作、传递信息 | 对方能复述核心信息 |
| **说服** | 提案、争取资源、推销观点 | 对方改变了认知或采取了行动 |
| **建立关系** | 破冰、团建、1-1对话 | 对方愿意和你继续聊 |
| **解决问题** | 冲突化解、方案讨论、决策会 | 产出可执行的共识方案 |

**最常见的沟通失败原因**：你以为你在"告知"，但对方以为你在"说服"；或者你以为你在"说服"，但对方以为你在"命令"。

## 二、金字塔原理：一切沟通的结构基础

### 2.1 核心规则：结论先行
任何沟通，先说结论，再说过程，最后补细节。

**不要这样汇报**：
> "老板，我们上周启动了用户调研，发了 1000 份问卷，回了 300 份，数据还在清洗中。不过从初步结果来看，用户对我们新产品满意度大概是 3.8 分。另外我们的竞品分析也快做完了...所以我在想要不要调整一下产品定位？"

**而要这样**：
> "老板，我建议把产品定位从'极致性能'调整为'易用性优先'。原因有三：用户调研显示满意度只有 3.8，低于预期；竞品分析表明市场空白在简易性；我们团队的设计能力也偏向这个方向。具体数据在 slides 2-4。"

### 2.2 金字塔搭建法
```
                    核心结论
                   /    |    \
              论点 1   论点 2   论点 3
              /  \     /  \     /  \
           事实  数据  案例  事实  数据  事实
```

**MECE 原则**（Mutually Exclusive, Collectively Exhaustive）：
- 论据之间**互不重叠**（Mutually Exclusive）
- 论据加起来**穷尽所有可能**（Collectively Exhaustive）

例如分析"为什么这个季度销量下降"：
- 不好的分法：原因 1：产品问题 / 原因 2：价格过高 / 原因 3：竞品太强（三个原因可能重叠）
- 好的分法：内部因素（产品、价格、渠道）+ 外部因素（竞品、市场、政策）

### 2.3 日常工作沟通中的金字塔

**写邮件**：
```
主题行 = 结论（"请求批准：Q3 市场活动预算追加 20 万"）

正文第一段 = 核心信息 3 句话（为什么、多少、什么时候）
正文第二段 = 展开的论据（数据支撑、风险分析）
正文第三段 = 明确的行动请求（"请在下周五前批准"）
```

**发消息**（微信/飞书/Slack）：
一条消息只讲一件事。如果需要讲多件事，用序号分行。
```
关于 XX 项目，3 件事同步：
1. 设计稿明天下午 3 点前出来
2. 后端接口这周五联调，需要你在场
3. 客户想加一个新功能，我整理了需求在附件
```

## 三、非暴力沟通（NVC）

### 3.1 NVC 四步法
Marshall Rosenberg 的非暴力沟通框架，是化解冲突、表达需求的最有效工具。

```
观察 → 感受 → 需要 → 请求
(Observation) (Feeling) (Need) (Request)
```

**错误示范**（通常的说法）：
> "你这人怎么总是不守时？跟你合作太累了！"

**NVC 正确示范**：
> **观察**：我们最近三次会议你都迟到了 15 分钟以上。
> **感受**：我感到有些着急和沮丧。
> **需要**：因为我需要我们的会议能够高效地按时开始。
> **请求**：下次会议你可以提前 5 分钟到吗？如果有特殊情况可以提前跟我说。

### 3.2 NVC 的关键技巧

**区分"观察"和"评判"**：
| 评判（对方会防御） | 观察（对方会听） |
|------------------|----------------|
| 你总是迟到 | 你这周有 3 天在 9:15 以后到 |
| 你工作不认真 | 这份报告有 5 处数据错误 |
| 你根本不关心这个项目 | 这个月你没有参加过项目周会 |
| 你太情绪化了 | 刚才讨论这个话题时你声音变大了 |

**区分"感受"和"想法"**：
| 想法（暗含指责） | 感受（只是描述自己的状态） |
|-----------------|------------------------|
| 我觉得你不尊重我 | 我感到了委屈和不被重视 |
| 我觉得你在针对我 | 我感到困惑和不安 |
| 你让我很生气 | 我感到生气 |
| 我觉得这个安排有问题 | 我对这个安排有顾虑 |

**不要这样提"请求"**：
- "你能不能靠谱一点？" → 这不是请求，这是批评
- "我希望你多考虑考虑" → 太模糊，对方不知道具体要做什么
- "你要是有空就看看吧" → 不是真的请求，是在甩锅

**要这样提"请求"**：
- 具体可操作："请在周三前回复我是否同意这个方案"
- 有时限："这周五 5 点前能把初稿发给我吗？"
- 可验证："如果可以的话，请回复'确认'"

### 3.3 在冲突场景中使用 NVC

**场景：同事推过来的需求总是变来变去**

差的做法：
> "你需求能不能定下来再给我？每次都改来改去我真的没法做！"

NVC 做法：
> "这周的需求文档已经更新了三次（观察）。我跟起来确实有点吃力（感受），因为我需要稳定的基准来做开发和测试（需要）。以后需求确认后如果有重大变更，我们用邮件正式确认一下可以吗？（请求）"

## 四、场景实战

### 4.1 如何向上沟通（汇报工作）

**给上级的三"要"三"不要"**：

三"要"：
1. **要结论先行**：领导没时间听你推导过程
2. **要给选择而非给问题**：不是"老板这里有个问题你看怎么办"，而是"这里有 X 问题，我想到 A/B 两个方案，A 是...B 是...，我倾向 A 因为...，你觉得呢？"
3. **要有时间预期**："这件事我预计周三前能给你第一版"

三"不要"：
1. **不要只带坏消息**：有坏消息也带上你的补救方案
2. **不要绕过上级做决定**：尤其是涉及跨部门协调或资源使用
3. **不要在公开场合挑战上级**：分歧在 1-1 中私下沟通

**进度汇报的 SCQA 公式**：
```
S (Situation): 当前状态是什么
C (Complication): 遇到了什么情况/变化
Q (Question): 需要解决什么问题
A (Answer): 你的解决方案是什么

示例：
S: 开发按计划进行，目前完成了 70%
C: 但设计那边比原计划晚了 3 天，我们的联调时间被压缩了
Q: 如果等设计完全完成再联调，会延期上线。怎么办？
A: 我建议分批联调——设计先交付核心页面，我们边联调边等剩余的
```

### 4.2 如何平行沟通（跨部门协作）

**跨部门沟通最常犯的错**：把"你需要配合我"说成"你应该配合我"。

**利益交换思维**：
不是"设计部为什么不配合我们的进度？"而是"这个项目做成了对设计部有什么好处？我怎么把这个好处说明白？"

**跨部门请求的 SOP**：
1. 先建立关系（日常维护关系，不要只在需要帮忙时才找人）
2. 说明背景（为什么做这件事，让对方理解而不是服从）
3. 明确诉求（具体的交付物 + 截止时间 + 格式要求）
4. 提供支持（"你需要什么信息/资源我可以提供？"）
5. 感谢反馈（事情做完后同步结果，让对方知道他的付出是有用的）

### 4.3 如何向下沟通（带团队/带新人）

**反馈的四象限**：
```
              正 向
               |
    ┌──────────┼──────────┐
    │ 具体表扬  │ 具体建设  │
    │ "你上次  │ 性批评   │
    │  用 X 方 │ "这个模块│
    │  法解决了│ 的出错了，│
    │  Y 问题  │ 我们看下 │
    │  很有效" │ 怎么改善"│
过  ─┼──────────┼──────────┼─ 未
去    │          │          │  来
    │ 模糊夸奖  │ 模糊攻击  │
    │ "做得不错"│ "你不行"  │
    │          │ "怎么搞的"│
    └──────────┼──────────┘
               │
              负 向
```

**好反馈三要素**：
1. **具体**：不是"你的代码写得不错"，而是"你用 async/await 替代了回调，逻辑清楚很多"
2. **及时**：事情发生后 48 小时内给反馈，越拖越没意义
3. **面向未来**：不只说哪里不好，还要说"怎么改进"和"改进后的标准是什么"

### 4.4 如何做公开表达 / 演讲

**克服紧张的最有效方法**：
- 不是告诉自己"别紧张"（越说越紧张）
- 而是把"紧张"重新定义为"兴奋"——"我现在心跳加速是因为我很兴奋要分享这个内容"
- 生理上紧张和兴奋是一样的（心跳快、手心出汗），区别只在大脑的标签

**演讲开头的三个最佳方式**：
1. **数据/事实冲击**："每 60 秒就有 500 小时的视频被上传到 YouTube"
2. **提问**："在座有多少人曾经...？"（让观众参与进来）
3. **故事**："3 年前我还是一个..."

**演讲中必须避免的**：
- 念 PPT（观众可以自己看，不用你念）
- 为内容多而道歉（"不好意思今天内容有点多..." → 既然多你为什么要讲？）
- 说我有点紧张（观众本来没注意，你一说大家都开始注意了）

## 五、沟通中的"元技能"

### 5.1 倾听——最被低估的沟通技能

**三层次倾听**：
| 层次 | 你在听什么 | 效果 |
|------|-----------|------|
| Level 1：内在倾听 | 听的时候脑子里在想"我接下来要说什么" | 没在听，你在准备回答 |
| Level 2：聚焦倾听 | 专注在对方说的话上 | 听到了内容，但可能没听到情绪 |
| Level 3：全局倾听 | 听内容 + 听情绪 + 听意图 + 听没说出来的 | 真正的理解 |

**积极倾听的四个动作**：
1. **复述（Paraphrasing）**：用你自己的话复述对方说的核心意思（"所以你的意思是...？"）
2. **澄清（Clarifying）**：针对模糊的地方提问（"你说'进度还可以'，具体是指完成了哪些模块？"）
3. **共情（Empathizing）**：说出对方的感受（"听起来你对这个结果挺失望的"）
4. **总结（Summarizing）**：阶段性总结，确认理解无误（"那我来确认一下，你刚才主要说了三点：..."）

### 5.2 提问——引导对话方向的工具

**开放式 vs 封闭式问题**：
| 封闭式（回答是/否） | 开放式（回答需要展开） |
|-------------------|---------------------|
| 你喜欢这份工作吗？ | 这份工作让你最有成就感的是什么？ |
| 项目有问题吗？ | 项目进展中最大的挑战是什么？ |
| 你听懂了吗？ | 你可以复述一下你的理解吗？ |

**黄金法则**：想要信息 → 问开放式；想要确认 → 问封闭式。

**追问（Follow-up Questions）**：
- "你能举个具体的例子吗？"
- "然后发生了什么？"
- "这个问题的根本原因你觉得是什么？"
- "如果这个问题解决了，会带来什么不同的结果？"

### 5.3 说"不"的能力

**为什么说不难**：害怕伤害关系、害怕被认为不合作、害怕错过机会。

**说不的四种方式（从弱到强）**：

1. **延迟回应**："让我先确认一下我手头的事情，明天给你答复"（给自己思考空间）
2. **给出替代方案**："这个我暂时做不了，但我可以帮你找 XX 同学，他在这方面更擅长"
3. **条件同意**："我可以做，但如果要做这个，A 项目就得往后排，你觉得能接受吗？"
4. **清晰拒绝 + 理由**："这个我没办法参与，因为我目前全力在 XX 项目上，分不出精力来保证质量"

**说不的要点**：
- 快的拒绝比慢的答应更尊重对方（不要拖 3 天再说不行）
- 拒绝的是事情，不是人（"这件事情我做不了" ≠ "我不愿意帮你"）
- 不给假希望（"下次有机会一定..."如果你根本不想，不要说）

## 六、沟通能力的持续提升

### 6.1 每周自我复盘
每次重要沟通（汇报、会议发言、1-1、冲突化解）后，花 2 分钟回顾：
- 我说的最终目的是什么？达成了吗？
- 如果重来一次，我会在哪一句换一种说法？
- 对方当时是什么反应？我有没有注意到并作出调整？

### 6.2 刻意练习的场景
| 技能 | 日常练习机会 |
|------|------------|
| 结论先行 | 把每条发给同事的消息压缩到 3 句话以内 |
| 提问 | 每次会议至少问一个问题 |
| 反馈 | 每周至少给一位同事一个具体的正面反馈 |
| 说不 | 对本周内 1-2 个不重要的请求练习温和拒绝 |
| 倾听 | 下次 1-1 中，让对方说 70% 的时间 |

### 6.3 推荐学习资源
- **书籍**：《金字塔原理》（Barbara Minto）、《非暴力沟通》（Marshall Rosenberg）、《关键对话》
- **TED 演讲**：Julian Treasure "How to speak so that people want to listen"
- **日常观察**：找一个你认为沟通能力很强的人，每次跟他交流后记录一条他做得好而你没想到的技巧
