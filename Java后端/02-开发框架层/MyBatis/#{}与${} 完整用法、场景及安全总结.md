# }与${} 完整用法、场景及安全总结

# }与${}均为MyBatis核心参数占位符，二者用法、底层实现、适用场景差异显著，结合各自核心用法、必用场景、安全注意事项及对比，完整总结如下，方便精准区分、正确使用：
一、核心占位符基础认知
两者均用于MyBatis中SQL语句的参数传递，核心区别在于“是否预编译”“是否处理参数”，底层实现不同，适用场景完全不同，避免混淆使用。
二、#{}核心用法（重点：防注入，优先使用）

# }是MyBatis中的预编译占位符，底层通过PreparedStatement实现，**先预编译SQL语句，再将参数值传入**，自带防SQL注入功能，自动识别参数类型、转义特殊字符（如字符串自动加引号）。

### 基础用法示例
单个参数传递：直接使用#{参数名}，无需额外配置（无@Param注解时，默认用#{param1}）。 <!-- Mapper接口：User selectById(Integer id); --> <select id="selectById" resultType="User"> SELECT * FROM user WHERE id = #{id} </select> 说明：传入id=1时，SQL自动转为SELECT * FROM user WHERE id = 1（数值类型无引号）；传入字符串name=张三，自动转为SELECT * FROM user WHERE name = '张三'（自动加引号）。
多个参数传递：需用@Param注解指定参数名，通过#{注解名}传递。 <!-- Mapper接口：User selectByNameAndAge(@Param("name") String name, @Param("age") Integer age); --> <select id="selectByNameAndAge" resultType="User"> SELECT * FROM user WHERE name = #{name} AND age = #{age} </select>

### #{适用场景（所有传递“字段值”的场景）
WHERE条件中的字段值（如id、name、age等具体值）；
INSERT语句中的插入值（如INSERT INTO user(name, age) VALUES(#{name}, #{age})）；
UPDATE语句中的更新值（如UPDATE user SET name = #{name} WHERE id = #{id}）；
所有无需修改SQL结构，仅传递具体参数值的场景（核心：安全、通用）。
三、${}核心用法（谨慎使用：仅动态拼接SQL结构）
${}是MyBatis中的字符串拼接占位符，底层通过Statement实现，**直接将参数原样拼接到SQL语句中**，不进行预编译、不自动转义参数，也不处理参数类型（如字符串不会自动加引号）。

### 基础用法示例
单个参数拼接：直接使用${参数名}，无需额外配置（无@Param注解时，默认用${param1}）。 <!-- Mapper接口：List<User> selectByTable(String tableName); --> <select id="selectByTable" resultType="User"> SELECT * FROM ${tableName} WHERE status = 1 </select>
多个参数拼接：需用@Param注解指定参数名，直接通过${注解名}拼接。 <!-- Mapper接口：List<User> selectOrderBy(@Param("sortCol") String sortCol, @Param("dir") String dir); --> <select id="selectOrderBy" resultType="User"> SELECT * FROM user ORDER BY ${sortCol} ${dir} </select>

### ${必用场景（仅${}可实现，#{}失效）
所有场景的核心共性：需动态修改SQL结构（关键字、标识符），#{}因会自动加引号、仅支持参数值替换而失效。
动态表名：分表场景（如按年/按ID分表），需拼接动态表名（例：user_${year}），#{}会导致表名带引号报错。
动态列名：动态指定查询字段（如导出Excel时用户选择的列），需拼接列名（例：SELECT ${columns} FROM user）。
动态排序：ORDER BY后的排序字段、排序方向（ASC/DESC），#{}会将其转为字符串常量，导致排序失效。
其他动态SQL结构：如动态LIMIT分页参数（部分场景/老版本数据库）、IN条件动态拼接（需拼接多个值而非单个字符串）。

五、安全注意事项（重点关注${}）
针对${}：因存在SQL注入风险，需做好3点防护
参数可控：${}的参数需由后端逻辑生成（如分表年份、预设排序字段），禁止直接使用用户原始输入；
白名单过滤：对动态参数（如排序字段、表名）设置允许值白名单，非白名单参数用默认值替代；
特殊字符转义：若必须接收用户输入，需手动转义`'`、`;`、`OR`等特殊字符，防止注入攻击。
针对#{}：无需额外防护，其自带预编译、自动转义功能，可直接使用（注意参数名与Mapper接口对应即可）。
六、核心使用原则（必记）
1. 优先使用#{}：所有传递“具体字段值”的场景，一律用#{}，兼顾安全与便捷；
2. 谨慎使用${}：仅在需动态修改SQL结构（表名、列名等）时使用，且必须做好安全防护；
3. 禁止滥用${}：避免用${}传递字段值，防止SQL注入；禁止用#{}拼接SQL结构，避免报错或功能失效。
