微服务常用技术栈
微服务架构的核心是将单体应用拆分为多个独立部署、可独立扩展、职责单一的服务，各服务通过标准化接口通信，不同模块可选用适配自身需求的技术，以下是各核心环节最常用、最成熟的技术栈梳理，兼顾主流性和实用性。
一、服务开发框架（核心基础）
负责微服务的核心开发，提供服务治理、依赖注入、接口开发等基础能力，适配不同编程语言，是微服务落地的核心载体。
Java 生态（主流首选）：Spring Cloud + Spring Boot，最成熟、应用最广泛的微服务开发框架。Spring Boot 简化单体服务开发，快速搭建独立服务；Spring Cloud 提供服务注册发现、配置中心、负载均衡等全套微服务治理能力，配套组件完善，社区支持强大，适合中大型企业级应用。核心组件包括 Spring Cloud Eureka/Consul（注册发现）、Spring Cloud Config（配置中心）、Spring Cloud Gateway（网关）等。
Go 生态（轻量高效）：Gin + Kitex/Go-Micro，Go 语言的高并发、轻量特性适配微服务的高可用需求。Gin 是高性能的 Web 框架，用于快速开发服务接口；Kitex（字节跳动开源）、Go-Micro 是专为 Go 设计的微服务框架，提供服务注册发现、负载均衡、熔断降级等能力，适合对性能要求高、轻量级的微服务场景（如互联网、高并发接口）。
Python 生态（快速迭代）：FastAPI + Sanic，适合快速开发、迭代的微服务场景（如数据分析、轻量接口）。FastAPI 支持异步、自动生成接口文档，性能接近 Go 框架；Sanic 是高性能异步 Web 框架，适配高并发场景，搭配 Consul 等组件实现微服务治理。
Node.js 生态（前端联动）：Express + NestJS，适合前后端联动紧密、需要快速开发的微服务（如 BFF 层、轻量接口）。NestJS 基于 Express 封装，支持依赖注入、模块化开发，贴合微服务架构设计，可快速对接前端需求。
二、服务注册与发现（服务协同核心）
微服务拆分后，服务数量多、地址动态变化，需通过注册发现组件管理服务地址，实现服务间的动态调用，避免硬编码地址导致的维护成本。
Eureka：Spring Cloud 生态原生组件，AP 架构（高可用、最终一致性），支持服务注册、心跳检测、故障剔除，部署简单，适合 Java 生态为主的微服务架构，缺点是社区已停止维护，适合中小型应用。
Consul：HashiCorp 开源，CP 架构（强一致性、分区容错），除注册发现外，还支持配置中心、服务网格功能，跨语言支持性好（Java、Go、Python 等均适配），适合对数据一致性要求高的场景（如金融、电商核心服务）。
Nacos：阿里开源，支持 AP/CP 双模切换，兼顾高可用和一致性，同时集成注册发现和配置中心功能，部署简单、控制台友好，支持动态配置更新，是目前国内应用最广泛的注册发现组件之一，适配多语言生态。
ZooKeeper：CP 架构，强一致性，原本用于分布式协调，可作为注册发现组件，适合对一致性要求极高的场景，但部署复杂、性能一般，目前更多用于大数据生态，微服务场景中逐渐被 Nacos、Consul 替代。
三、API 网关（服务入口）
作为微服务的统一入口，负责请求路由、负载均衡、权限校验、限流熔断、日志监控等，隔离外部请求与内部服务，简化客户端调用逻辑。
Spring Cloud Gateway：Spring Cloud 生态官方网关，基于 Spring Boot 2.x，支持异步非阻塞，性能优于传统网关，集成 Spring Cloud 各类组件（如 Nacos、Sentinel），支持路由动态配置、限流、熔断，适合 Java 生态微服务。
Zuul：Spring Cloud 早期网关，基于 Servlet 同步阻塞，性能一般，社区已停止维护，目前多被 Spring Cloud Gateway 替代，仅老项目仍在使用。
Kong：基于 Nginx + Lua 开发，高性能、高可用，跨语言支持，支持插件扩展（如权限校验、限流、监控），适合高并发场景，部署简单，可独立于开发语言使用，适合多语言混合的微服务架构。
APISIX：云原生网关，基于 Nginx + Lua（OpenResty），阿里开源，性能优于 Kong，支持动态配置、插件化扩展，适配 Kubernetes 云原生环境，适合容器化部署的微服务。
四、配置中心（配置管理）
微服务数量多，配置分散（如数据库地址、接口地址、业务参数），配置中心用于集中管理配置，支持动态更新配置，无需重启服务，降低维护成本。
Nacos：前文提及，集成注册发现和配置中心，支持多环境（开发、测试、生产）配置隔离，动态更新配置，支持配置加密，适配多语言，部署简单，是目前国内主流选择。
Spring Cloud Config：Spring Cloud 原生组件，基于 Git 存储配置，支持配置版本控制，适合 Java 生态，但不支持动态更新（需配合 Spring Cloud Bus 实现），功能相对简单，适合中小型 Java 微服务。
Apollo：携程开源，专业的配置中心，支持多环境、多集群配置管理，动态更新、灰度发布、配置回滚，控制台功能强大，适合中大型企业级微服务，跨语言支持。
Consul：前文提及，配置中心功能与注册发现集成，支持 KV 存储，强一致性，适合对配置一致性要求高的场景，无需额外部署组件。
五、服务治理（高可用保障）
微服务间调用频繁，需通过服务治理组件解决分布式场景下的容错、限流、熔断、链路追踪等问题，保障系统高可用。
1. 熔断与降级
    Sentinel：阿里开源，轻量级、高性能，支持熔断、降级、限流、热点防护，集成 Spring Cloud、Dubbo 等框架，控制台友好，可动态配置规则，适合 Java 生态，是国内主流选择。
    Hystrix：Netflix 开源，Spring Cloud 早期熔断组件，支持熔断、降级、线程隔离，功能成熟，但社区已停止维护，目前多被 Sentinel 替代。
    Resilience4j：轻量级、无依赖，支持熔断、降级、限流，适配 Java 8+，适合对依赖简洁性要求高的场景，可替代 Hystrix。
2. 链路追踪
    用于追踪微服务间的调用链路，定位跨服务调用的异常、性能瓶颈，便于问题排查。
    SkyWalking：国产开源，性能优异，支持分布式链路追踪、服务监控、日志分析，跨语言支持（Java、Go、Python 等），适配云原生环境，是目前国内微服务链路追踪的主流选择。
    Zipkin：Netflix 开源，轻量级，易于部署，支持链路追踪、依赖分析，但功能相对简单，适合中小型微服务。
    Jaeger：Uber 开源，兼容 OpenTelemetry 标准，支持分布式链路追踪、性能监控，适配 Kubernetes 云原生环境，适合容器化部署的微服务。
3. 服务监控
    监控微服务的运行状态（CPU、内存、接口响应时间、错误率），及时发现异常并告警。
    Prometheus + Grafana：目前最主流的监控组合。Prometheus 负责采集 metrics 数据（如接口响应时间、服务存活状态），支持时序数据存储；Grafana 负责可视化展示，可自定义监控面板，支持告警配置，适配所有主流微服务技术栈。
    ELK Stack：Elasticsearch + Logstash + Kibana，用于日志收集、分析、可视化，可监控服务日志，定位异常日志，搭配 Prometheus 可实现全方位监控。
    六、数据存储（持久化）
    微服务架构中，数据存储采用“去中心化”原则，不同服务根据业务需求选择适配的数据库，避免单一数据库瓶颈。
    1. 关系型数据库（结构化数据）
    MySQL：最主流的关系型数据库，开源、稳定、性能优异，支持主从复制、分库分表，适配大多数业务场景（如用户、订单、商品等核心数据），搭配 MyBatis、JPA 等 ORM 框架使用。
    PostgreSQL：开源，支持复杂查询、JSON 数据类型，扩展性强，适合需要复杂业务逻辑、多数据类型的场景（如数据分析、地理信息）。
    Oracle：商业数据库，稳定、安全，支持高并发、大数据量，适合金融、政务等对数据安全性、稳定性要求极高的场景，但成本较高。
2. 非关系型数据库（非结构化/半结构化数据）
    Redis：高性能缓存数据库，支持字符串、哈希、列表等多种数据结构，用于缓存热点数据、分布式锁、消息队列，是微服务架构中不可或缺的组件，提升系统性能。
    MongoDB：文档型数据库，适合存储非结构化/半结构化数据（如用户行为日志、商品详情、评论），支持灵活的查询，扩展性强，适合大数据量、高并发的读写场景。
    Elasticsearch：全文检索数据库，用于实现全文搜索功能（如商品搜索、日志检索），支持分词、模糊查询，性能优异，常与 Kibana 搭配使用。
3. 分库分表（大数据量场景）
    当单库单表数据量过大（如千万级以上），需通过分库分表拆分数据，提升查询性能。
    Sharding-JDBC：轻量级分库分表框架，集成于应用层，无需额外部署中间件，支持水平分表、垂直分表、分库，适配 Java 生态，适合中小型应用。
    MyCat：中间件级分库分表，独立部署，支持多语言，功能强大（如读写分离、分库分表、数据迁移），适合中大型企业级应用。
    七、消息队列（异步通信）
    用于解耦微服务间的同步调用，实现异步通信，削峰填谷，避免因服务依赖导致的级联故障，提升系统吞吐量。
    RabbitMQ：开源，基于 AMQP 协议，支持多种交换机类型（direct、topic、fanout），消息可靠性高，支持死信队列、延迟队列，部署简单，适合中小型微服务，适配多语言。
    RocketMQ：阿里开源，基于 JMS 协议，支持高并发、大数据量，消息可靠性高，支持事务消息、延迟队列，适合中大型企业级应用（如电商订单、支付场景），适配 Java 生态。
    Kafka：开源，基于发布/订阅模式，高吞吐量、高可用，适合大数据量、高并发的日志收集、消息传输场景（如用户行为日志、实时数据同步），但消息可靠性略低于 RabbitMQ、RocketMQ。
    ActiveMQ：老牌消息队列，支持多种协议，功能成熟，但性能一般，目前逐渐被 RabbitMQ、RocketMQ 替代，仅老项目使用。
    八、容器化与部署（运维支撑）
    微服务数量多，部署、扩展、运维难度大，容器化与编排工具可实现微服务的自动化部署、弹性扩展、故障自愈，降低运维成本。
    Docker：容器化技术，将微服务及其依赖打包为容器，实现“一次构建、到处运行”，隔离服务环境，避免环境不一致导致的问题，是微服务容器化的基础。
    Kubernetes（K8s）：容器编排工具，负责容器的部署、扩展、负载均衡、故障自愈，支持自动扩缩容、滚动更新，是目前微服务容器化部署的主流选择，适配云原生环境。
    Jenkins/GitLab CI：持续集成/持续部署（CI/CD）工具，实现微服务的自动化构建、测试、部署，搭配 Docker、K8s，可实现全流程自动化运维，提升部署效率。
    Helm：K8s 的包管理工具，将微服务的部署配置（如 Deployment、Service）打包为 Chart，简化 K8s 应用的部署、升级、回滚，提升运维效率。
    九、常用技术栈组合推荐（实战参考）
    中小型 Java 微服务（最常用）：Spring Boot + Spring Cloud + Nacos（注册+配置） + Spring Cloud Gateway + Sentinel + MySQL + Redis + RabbitMQ + Docker + Jenkins
    中大型 Java 微服务（企业级）：Spring Boot + Spring Cloud Alibaba + Nacos/Apollo + APISIX/Kong + Sentinel + MySQL（分库分表 Sharding-JDBC） + Redis + RocketMQ + Kafka + K8s + Prometheus + Grafana + SkyWalking
    Go 语言微服务（高并发）：Gin + Kitex + Consul/Nacos + APISIX + Resilience4j + MySQL/MongoDB + Redis + Kafka + Docker + K8s
    轻量级微服务（快速迭代）：FastAPI（Python）/NestJS（Node.js） + Nacos + Spring Cloud Gateway（或 Kong） + MySQL + Redis + RabbitMQ + Docker
    总结：微服务技术栈的选择需结合业务场景、团队技术栈、系统规模，优先选择成熟、社区支持强的组件，避免过度追求“新技术”，核心是实现服务的高可用、可扩展、易维护。
