# 多线程与高并发

---

## 一、多线程与高并发基础概念

### 1. 核心定义

| 概念 | 定义 |
|------|------|
| **进程** | 操作系统资源分配的基本单位，有独立的内存空间，一个进程可包含多个线程 |
| **线程** | CPU调度和执行的基本单位，共享进程的内存空间（堆、方法区），拥有私有栈、程序计数器 |
| **并发** | 同一时间段内多个任务交替执行（单核CPU实现），看似同时进行 |
| **并行** | 同一时刻多个任务同时执行（多核CPU实现） |
| **高并发** | 系统在单位时间内处理大量请求/任务的能力，核心是提升资源利用率和响应效率 |

### 2. 多线程的意义

- **提升CPU利用率**：避免单线程因IO/等待导致CPU空闲
- **提高程序响应性**：如UI程序后台处理任务，前端仍可交互
- **充分利用多核硬件资源**：现代CPU均为多核，多线程可并行执行

### 3. 多线程的问题

| 问题 | 说明 |
|------|------|
| **线程安全** | 多个线程操作共享资源导致数据不一致（如并发修改同一变量） |
| **死锁** | 多个线程互相持有对方需要的资源，导致永久阻塞 |
| **上下文切换** | 线程切换消耗CPU资源，过度切换反而降低性能 |
| **资源竞争** | 线程争抢锁、CPU时间片等资源，导致执行效率下降 |

## 二、Java多线程实现方式

### 1. 继承 Thread 类

**步骤**：继承 `Thread` 类 → 重写 `run()` 方法 → 创建实例调用 `start()` 启动

```java
class MyThread extends Thread {
    @Override
    public void run() {
        for (int i = 0; i < 10; i++) {
            System.out.println(Thread.currentThread().getName() + ": " + i);
        }
    }
}

// 使用
public class Test {
    public static void main(String[] args) {
        MyThread thread1 = new MyThread();
        MyThread thread2 = new MyThread();
        thread1.start();
        thread2.start();
    }
}
```

> **缺点**：Java单继承限制，无法继承其他类；线程与任务耦合。

### 2. 实现 Runnable 接口

**步骤**：实现 `Runnable` 接口 → 重写 `run()` 方法 → 创建 `Thread` 实例传入 `Runnable` → 调用 `start()`

```java
class MyRunnable implements Runnable {
    @Override
    public void run() {
        for (int i = 0; i < 10; i++) {
            System.out.println(Thread.currentThread().getName() + ": " + i);
        }
    }
}

// 使用
public class Test {
    public static void main(String[] args) {
        MyRunnable runnable = new MyRunnable();
        Thread thread1 = new Thread(runnable);
        Thread thread2 = new Thread(runnable);
        thread1.start();
        thread2.start();
    }
}
```

> **优点**：避免单继承限制；线程与任务解耦，可复用任务。

### 3. 实现 Callable 接口（带返回值 + 可抛异常）

**步骤**：实现 `Callable` 接口 → 重写 `call()` 方法 → 封装为 `FutureTask` → 传入 `Thread` 启动

```java
import java.util.concurrent.Callable;
import java.util.concurrent.FutureTask;

class MyCallable implements Callable<Integer> {
    @Override
    public Integer call() throws Exception {
        int sum = 0;
        for (int i = 1; i <= 100; i++) {
            sum += i;
        }
        return sum;
    }
}

// 使用
public class Test {
    public static void main(String[] args) throws Exception {
        MyCallable callable = new MyCallable();
        FutureTask<Integer> futureTask = new FutureTask<>(callable);
        Thread thread = new Thread(futureTask);
        thread.start();
        // 获取返回值（阻塞直到任务完成）
        Integer result = futureTask.get();
        System.out.println("计算结果：" + result);
    }
}
```

> **优点**：有返回值；可抛出受检异常；支持取消任务。

### 4. 线程池（推荐，高并发核心）

手动创建线程成本高（创建/销毁耗时），线程池可**复用线程、控制并发数**。

**核心接口层级**：`Executor` → `ExecutorService` → `ThreadPoolExecutor`（核心实现）

#### 常用线程池（Executors 工具类创建）

| 线程池 | 特点 | 适用场景 |
|--------|------|---------|
| `FixedThreadPool` | 固定核心线程数 | 任务量稳定的场景 |
| `CachedThreadPool` | 核心线程数0，最大线程数无限 | 短期轻量任务 |
| `SingleThreadExecutor` | 单线程池，任务串行执行 | 需顺序执行的任务 |
| `ScheduledThreadPool` | 定时/周期性任务 | 定时调度 |

#### ThreadPoolExecutor 自定义线程池（推荐生产使用）

```java
import java.util.concurrent.ArrayBlockingQueue;
import java.util.concurrent.ThreadPoolExecutor;
import java.util.concurrent.TimeUnit;

public class Test {
    public static void main(String[] args) {
        ThreadPoolExecutor executor = new ThreadPoolExecutor(
            5,                              // 核心线程数
            10,                             // 最大线程数
            60,                             // 空闲线程存活时间（秒）
            TimeUnit.SECONDS,
            new ArrayBlockingQueue<>(100),  // 任务队列（有界）
            new ThreadPoolExecutor.AbortPolicy()  // 拒绝策略
        );

        for (int i = 0; i < 20; i++) {
            int taskNum = i;
            executor.execute(() -> {
                System.out.println(Thread.currentThread().getName() + "执行任务" + taskNum);
                try {
                    Thread.sleep(100);
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }
            });
        }

        executor.shutdown();  // 关闭线程池
    }
}
```

#### 核心参数说明

| 参数 | 说明 |
|------|------|
| **核心线程数** | 常驻线程数，即使空闲也不会销毁 |
| **最大线程数** | 线程池允许的最大线程数量 |
| **任务队列** | 存放等待执行的任务，分为有界/无界队列 |
| **拒绝策略** | `AbortPolicy`（抛异常）、`CallerRunsPolicy`（调用者执行）、`DiscardPolicy`（丢弃）、`DiscardOldestPolicy`（丢弃最老任务） |

## 三、线程生命周期（Java）

| 状态 | 说明 |
|------|------|
| **新建（New）** | 创建 Thread 实例但未调用 `start()` |
| **就绪（Runnable）** | 调用 `start()` 后，等待CPU调度 |
| **运行（Running）** | CPU调度后执行 `run()` 方法 |
| **阻塞（Blocked）** | 同步阻塞（等待 `synchronized` 锁）、等待阻塞（`wait()`/`join()`）、超时阻塞（`sleep(long)`/`wait(long)`） |
| **终止（Terminated）** | `run()` 执行完毕或异常终止 |

## 四、线程安全与同步机制

### 1. 线程安全问题根源

- **共享资源**：多个线程访问同一可变资源（如成员变量、静态变量）
- **非原子操作**：多个步骤的操作被线程切换打断（如 `i++`，分为读取、加1、写入三步）
- **指令重排序**：JVM优化导致代码执行顺序与预期不一致

### 2. 同步机制

#### ① synchronized 关键字（内置锁）

保证方法/代码块同一时刻只有一个线程执行，**可重入、非公平**。

| 用法 | 锁的对象 |
|------|---------|
| 修饰实例方法 | 锁当前对象实例 |
| 修饰静态方法 | 锁类对象（Class） |
| 修饰代码块 | 锁指定对象（如 `synchronized (this) {}`） |

```java
class Counter {
    private int count = 0;

    // 同步实例方法
    public synchronized void increment() {
        count++;
    }

    // 同步代码块
    public void decrement() {
        synchronized (this) {
            count--;
        }
    }
}
```

#### ② Lock 接口（显式锁，JUC包）

| 实现类 | 特点 |
|--------|------|
| `ReentrantLock` | 可重入锁，支持公平/非公平、可中断、可超时 |
| `ReentrantReadWriteLock` | 读写锁，读锁共享、写锁排他，适合读多写少 |

**ReentrantLock 示例**：

```java
import java.util.concurrent.locks.ReentrantLock;

class Counter {
    private int count = 0;
    private ReentrantLock lock = new ReentrantLock(true); // 公平锁

    public void increment() {
        lock.lock();
        try {
            count++;
        } finally {
            lock.unlock();  // 必须放finally，避免异常导致锁不释放
        }
    }
}
```

> **synchronized vs Lock**：Lock 可手动加锁/释放、支持公平锁、可中断获取、可超时获取，更灵活；synchronized 语法简洁，自动释放。

#### ③ 原子类（`java.util.concurrent.atomic` 包）

基于 **CAS（Compare And Swap）** 实现无锁并发，避免锁竞争。

| 常用类 | 用途 |
|--------|------|
| `AtomicInteger` / `AtomicLong` | 原子整数 |
| `AtomicReference` | 原子引用 |
| `AtomicBoolean` | 原子布尔 |

```java
import java.util.concurrent.atomic.AtomicInteger;

class AtomicCounter {
    private AtomicInteger count = new AtomicInteger(0);

    public void increment() {
        count.incrementAndGet();  // 原子自增
    }

    public int getCount() {
        return count.get();
    }
}
```

#### ④ volatile 关键字

| 作用 | 局限 |
|------|------|
| 保证变量的**可见性**（一个线程修改后，其他线程立即可见） | **不保证原子性**（如 `volatile int i; i++` 仍非线程安全） |
| **禁止指令重排序** | — |

**适用场景**：状态标记（如 `boolean flag`）、双重检查锁（单例模式）。

```java
class Singleton {
    private volatile static Singleton instance;  // 必须加volatile

    private Singleton() {}

    public static Singleton getInstance() {
        if (instance == null) {                  // 第一次检查
            synchronized (Singleton.class) {
                if (instance == null) {          // 第二次检查
                    instance = new Singleton();  // volatile禁止指令重排序
                }
            }
        }
        return instance;
    }
}
```

## 五、高并发核心工具类（JUC）

### 1. CountDownLatch（倒计时门闩）

让一组线程等待另一组线程执行完毕后再继续执行。

```java
import java.util.concurrent.CountDownLatch;

public class Test {
    public static void main(String[] args) throws InterruptedException {
        CountDownLatch latch = new CountDownLatch(3);  // 计数3

        for (int i = 0; i < 3; i++) {
            new Thread(() -> {
                System.out.println(Thread.currentThread().getName() + "执行任务");
                latch.countDown();  // 计数减1
            }).start();
        }

        latch.await();  // 主线程等待计数为0
        System.out.println("所有子线程执行完毕，主线程继续");
    }
}
```

### 2. CyclicBarrier（循环栅栏）

让一组线程到达屏障点后才继续执行，**可重复使用**。

```java
import java.util.concurrent.CyclicBarrier;

public class Test {
    public static void main(String[] args) {
        CyclicBarrier barrier = new CyclicBarrier(3, () -> {
            System.out.println("所有线程到达屏障，执行统一逻辑");
        });

        for (int i = 0; i < 3; i++) {
            new Thread(() -> {
                System.out.println(Thread.currentThread().getName() + "到达屏障");
                try {
                    barrier.await();  // 等待其他线程
                } catch (Exception e) {
                    e.printStackTrace();
                }
                System.out.println(Thread.currentThread().getName() + "继续执行");
            }).start();
        }
    }
}
```

### 3. Semaphore（信号量）

控制同时访问特定资源的线程数量，实现**限流**。

```java
import java.util.concurrent.Semaphore;

public class Test {
    public static void main(String[] args) {
        Semaphore semaphore = new Semaphore(2);  // 允许2个线程同时访问

        for (int i = 0; i < 5; i++) {
            new Thread(() -> {
                try {
                    semaphore.acquire();  // 获取许可
                    System.out.println(Thread.currentThread().getName() + "获取资源，开始执行");
                    Thread.sleep(1000);
                    System.out.println(Thread.currentThread().getName() + "释放资源");
                } catch (InterruptedException e) {
                    e.printStackTrace();
                } finally {
                    semaphore.release();  // 释放许可
                }
            }).start();
        }
    }
}
```

### 4. ConcurrentHashMap（并发集合）

线程安全的 HashMap，替代 `Hashtable` 和 `Collections.synchronizedMap`。

| 版本 | 实现原理 |
|------|---------|
| JDK 7 | 分段锁（Segment） |
| JDK 8 | CAS + synchronized（粒度更小） |

**优点**：并发度高，读操作无锁（volatile），写操作只锁当前桶。

```java
import java.util.concurrent.ConcurrentHashMap;

public class Test {
    public static void main(String[] args) {
        ConcurrentHashMap<String, Integer> map = new ConcurrentHashMap<>();

        for (int i = 0; i < 10; i++) {
            int num = i;
            new Thread(() -> {
                map.put("key" + num, num);
                System.out.println(Thread.currentThread().getName() + ": " + map.get("key" + num));
            }).start();
        }
    }
}
```

## 六、高并发调优思路

### 1. 线程池调优

| 调优点 | 建议 |
|--------|------|
| 核心线程数 | CPU密集型：`CPU核心数 + 1`；IO密集型：`CPU核心数 * 2` |
| 任务队列 | 使用**有界队列**，避免无界队列导致OOM |
| 拒绝策略 | 根据业务选择（如 `CallerRunsPolicy` 降级处理） |
| 监控 | 记录活跃线程数、队列长度、完成任务数 |

### 2. 锁优化

- **减少锁粒度**：如 `ConcurrentHashMap` 的分段锁/桶锁
- **锁消除**：JVM自动消除无竞争的锁
- **锁粗化**：将多次加锁/释放锁合并为一次
- **替换锁**：用原子类、CAS替代 synchronized/Lock（无锁编程）

### 3. 减少上下文切换

- 避免创建过多线程（超过 `CPU核心数 + 1` 会导致频繁切换）
- 使用协程（如 Project Loom），轻量级线程减少切换成本
- 无锁编程：CAS、原子类替代锁

### 4. 资源隔离

- **线程池隔离**：不同业务使用不同线程池，避免相互影响
- **信号量隔离**：控制单个资源的访问数

### 5. 缓存优化

| 层级 | 方案 |
|------|------|
| 本地缓存 | Caffeine 等，减少远程调用 |
| 分布式缓存 | Redis 等，共享缓存，减轻数据库压力 |
| 防护措施 | 缓存击穿/穿透/雪崩防护：布隆过滤器、过期时间随机化、熔断降级 |

## 七、常见问题与解决方案

| 问题 | 原因 | 排查/解决 |
|------|------|----------|
| **死锁** | 互斥、持有并等待、不可剥夺、循环等待 | `jstack` 查看线程状态；破坏死锁条件（定时释放锁、按顺序获取锁） |
| **线程泄漏** | 核心线程数过多、任务阻塞导致线程无法回收 | 设置合理的核心线程数和超时时间，监控线程池状态 |
| **竞态条件** | 多个线程同时修改共享资源 | 使用 synchronized/Lock、原子类 |
| **吞吐量低** | 锁竞争激烈、上下文切换频繁、IO阻塞 | 减少锁粒度、无锁编程、异步处理IO |

---

## 总结

| 层面 | 核心要点 |
|------|---------|
| **多线程** | 核心是利用多核资源提升效率 |
| **高并发** | 核心是保证系统在高负载下的稳定性和响应性 |
| **线程安全** | 通过 synchronized/Lock、原子类、并发集合实现，优先使用无锁方案减少竞争 |
| **调优** | 从线程池、锁、缓存、资源隔离多维度入手，结合监控工具定位瓶颈 |
