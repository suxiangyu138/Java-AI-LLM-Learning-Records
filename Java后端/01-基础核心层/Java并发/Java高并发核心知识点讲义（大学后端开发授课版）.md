Java高并发核心知识点讲义（大学后端开发授课版）
前言
高并发是后端开发的核心能力，也是Java后端面试、企业级项目研发的重中之重。本讲义围绕“理论打底、实战落地、避坑提效”三大核心，按照“基础认知→核心工具→同步控制→线程池→高级并发组件→安全方案→线上实战”的模块化逻辑梳理，摒弃纯理论晦涩讲解，每一个知识点都配套企业级使用场景，既符合计算机专业教学规范，又贴合互联网、分布式项目的高并发开发需求，适合课堂学习、期末复习及后端工程师进阶。
高并发核心目标：在多线程并发访问场景下，保证系统吞吐量、响应速度、线程安全三者平衡，避免出现数据错乱、死锁、OOM、服务宕机等问题，支撑高流量、高请求的业务场景。
模块一：高并发核心基础概念（先理清底层逻辑）
本模块是高并发学习的前提，搞懂基础概念才能理解后续并发问题根源与解决方案，避免死记硬背。
1. 高并发核心定义
    高并发指系统在短时间内处理大量并发请求的能力，核心衡量指标：QPS（每秒查询数）、TPS（每秒事务数）、响应时间、并发线程数、吞吐量。企业级场景：电商秒杀、订单支付、流量峰值、大数据批量处理等均属于典型高并发场景。
2. 并发编程三大核心问题（必考）
    原子性：一个或多个操作要么全部执行成功，要么全部不执行，执行过程中不会被CPU调度打断；未保证原子性会导致数据计算错误、状态错乱。
    可见性：一个线程修改了共享变量的值，其他线程能立即感知到修改结果；JVM内存模型中线程私有工作内存与主内存同步延迟，会导致可见性问题。
    有序性：程序执行顺序按照代码编写顺序执行；JVM和CPU为优化性能会进行指令重排序，多线程下会破坏有序性，引发逻辑错误。
3. Java内存模型（JMM）与并发关联
    JMM是Java定义的内存规范，用来屏蔽底层硬件和操作系统的内存差异，保证并发编程下的原子性、可见性、有序性：
    主内存：存储共享变量（实例对象、静态变量），所有线程共享；
    工作内存：线程私有内存，存储线程用到的共享变量副本，线程无法直接操作主内存，只能操作副本；
    核心规范：通过volatile、synchronized、Lock等机制，保证工作内存与主内存的数据同步，解决三大核心问题。
4. 线程状态与并发调度回顾
    沿用Java多线程6大状态（新建、就绪、运行、阻塞、等待、超时等待、终止），高并发场景下核心关注阻塞状态：锁竞争、IO等待、线程调度延迟都会导致线程阻塞，直接影响系统并发性能，也是性能调优的核心切入点。
    模块二：高并发基础同步机制（企业级基础方案）
    本模块讲解Java原生并发同步工具，是解决线程安全的基础，也是高并发编程的入门必备，区分不同方案的适用场景与优劣。
    1. volatile关键字（轻量级并发工具）
    核心作用：保证共享变量的可见性、禁止指令重排序，不保证原子性，是最轻量的并发同步机制，无锁开销。
    底层原理：内存屏障指令，强制刷新工作内存到主内存，禁止CPU指令重排序，保证变量修改对所有线程立即可见。
    企业适用场景：线程启停标志位、状态标记量、双重校验锁单例模式，不适用：i++、count++等复合操作场景。
    高频易错点：volatile不能替代锁，仅解决可见性和有序性，原子性需靠锁或原子类保证。
2. synchronized隐式锁（JVM内置锁）
    核心特性：JVM层面实现的互斥锁、可重入锁、非公平锁，自动加锁与释放锁，无需手动管理，解决并发三大核心问题。
    三种使用粒度（企业实战优先级）
    同步代码块：锁定指定对象，锁粒度最小，灵活度高，高并发首选；
    同步实例方法：锁定当前this对象，粒度适中，适合单实例并发操作；
    同步静态方法：锁定类Class对象，全局锁，粒度最大，慎用避免性能瓶颈。
    锁升级机制（JDK1.6+优化，必考）
    为提升高并发性能，synchronized锁会逐步升级：无锁→偏向锁→轻量级锁→重量级锁，锁只能升级不能降级，减少重量级锁的性能开销，适配不同并发竞争程度。
    适用场景：低并发、代码逻辑简单、快速执行的同步场景，开发成本低，稳定性高。
3. Lock显式锁（JUC核心，高并发进阶）
    java.util.concurrent.locks包下的显式锁，核心实现类ReentrantLock，手动加锁解锁，功能远超synchronized，是高并发场景的主流锁方案。
    核心优势
    支持公平锁与非公平锁灵活切换；
    支持超时获取锁，避免线程无限等待；
    支持中断获取锁，解决线程死等问题；
    支持多个Condition等待队列，精细化线程通信。
    企业实战规范
    lock()加锁必须放在try外，unlock()解锁放在finally块中，保证锁一定释放，避免锁泄漏导致线程阻塞堆积。
    模块三：JUC原子类（无锁并发，高性能方案）
    JUC（java.util.concurrent）并发工具包是Java高并发的核心，原子类基于CAS无锁算法实现，无锁竞争开销，性能远高于传统锁机制，企业高并发项目必用。
    1. CAS核心原理（Compare And Swap，比较并交换）
    无锁并发核心算法，包含三个核心参数：内存值V、预期值A、更新值B；当且仅当V=A时，将V更新为B，否则重试，整个操作是原子性的，由CPU底层指令保证，无锁阻塞。
    优缺点：优点是无锁、高性能、线程无阻塞；缺点是高并发下自旋重试次数过多，消耗CPU，存在ABA问题。
2. 常用原子类分类（企业实战）
    基本数据类型原子类：AtomicInteger、AtomicLong、AtomicBoolean，适合数值计数、状态标记；
    引用类型原子类：AtomicReference，存储对象引用，保证对象操作原子性；
    原子数组类：AtomicIntegerArray、AtomicLongArray，数组元素原子操作；
    原子更新字段类：AtomicIntegerFieldUpdater，更新对象字段，需volatile修饰字段；
    ABA问题解决类：AtomicStampedReference（带版本号引用），彻底解决CAS的ABA问题。
3. 适用场景
    高并发下的计数、ID生成、状态切换、限流统计等简单原子操作，替代锁机制，大幅提升并发性能。
    模块四：线程池（高并发核心，企业级禁用手动创建线程）
    高并发场景下，频繁创建销毁线程会极大消耗系统资源，导致线程栈溢出、CPU飙升，线程池是高并发编程的核心基石，企业级项目强制要求使用线程池管理线程，禁止手动new Thread。
    1. 线程池核心作用
    线程复用：避免频繁创建销毁线程，降低资源开销；
    流量控制：限制最大并发线程数，防止线程过多导致系统崩溃；
    统一管理：统一调度、监控、调优线程，提升系统稳定性；
    提升响应：线程提前创建，任务到达立即执行，无需等待线程创建。
2. ThreadPoolExecutor核心参数（必考+实战）
    参数
    含义
    企业实战配置
    corePoolSize
    核心线程数，线程池常驻线程
    CPU密集型：CPU核心数+1；IO密集型：2*CPU核心数
    maximumPoolSize
    最大线程数，允许创建的最大线程数量
    根据服务器配置、业务峰值调整，不建议过大
    keepAliveTime
    非核心线程空闲超时时间
    短任务设60s，长任务适当延长，超时自动销毁
    workQueue
    任务阻塞队列，存储待执行任务
    LinkedBlockingQueue（常用）、ArrayBlockingQueue
    threadFactory
    线程工厂，自定义线程创建
    自定义线程名，方便线上问题排查
    handler
    拒绝策略，任务过载时处理
    CallerRunsPolicy（生产常用），避免任务丢失
3. 线程池执行流程（必懂）
    任务提交，线程数小于corePoolSize，创建核心线程执行任务；
    核心线程满，任务加入阻塞队列等待；
    队列满，线程数小于maximumPoolSize，创建非核心线程执行任务；
    最大线程数+队列均满，执行拒绝策略。
4. 企业实战禁忌
    禁止使用Executors工具类创建线程池（FixedThreadPool、CachedThreadPool易导致OOM），必须手动创建ThreadPoolExecutor；线程池不用不关闭，核心线程长期驻留，避免频繁重启线程池。
5. 定时任务线程池ScheduledThreadPoolExecutor
    替代原生Timer，基于线程池的定时任务工具，支持定时执行、周期性执行，多线程调度，单个任务异常不影响其他任务，适合高并发定时任务场景。
    模块五：JUC高级并发工具类（企业级复杂并发场景）
    针对复杂高并发协同场景，JUC提供专用工具类，解决线程等待、协同、限流、屏障等问题，替代原生wait/notify，代码更优雅、性能更稳定。
    1. CountDownLatch（倒计时门栓）
    作用：让一个或多个线程等待，直到其他线程全部执行完毕再执行，基于计数器实现，计数器减为0时唤醒等待线程。
    企业场景：主线程等待多个子线程加载数据完毕、多接口并发调用汇总结果。
2. CyclicBarrier（循环屏障）
    作用：让一组线程相互等待，所有线程都到达屏障点后，再同时执行后续逻辑，可重复使用。
    企业场景：多线程并行计算，最后汇总结果、并发初始化资源。
3. Semaphore（信号量）
    作用：控制并发线程数量，实现限流，限制同时访问共享资源的线程数。
    企业场景：接口限流、数据库连接池限流、稀缺资源访问控制。
4. Exchanger（线程交换器）
    作用：两个线程之间交换数据，线程到达交换点后互相传递数据，适合线程间数据传输。
5. LockSupport（线程阻塞工具）
    作用：线程阻塞与唤醒工具，替代wait/notify，无需依赖同步代码块，无锁要求，灵活度高，是JUC内部实现的基础工具。
    模块六：高并发线程安全与容器（企业级数据安全方案）
    普通集合类（ArrayList、HashMap、HashSet）均非线程安全，高并发下会出现数据丢失、死循环、ConcurrentModificationException异常，必须使用线程安全容器。
    1. 传统线程安全容器（淘汰，性能差）
    Vector、Hashtable、Collections工具类包装的同步集合，底层基于synchronized锁，全方法加锁，并发竞争激烈，性能极差，高并发场景禁用。
2. JUC高并发容器（生产首选）
    List：CopyOnWriteArrayList，写时复制容器，写操作加锁复制数组，读操作无锁，适合读多写少场景；
    Set：CopyOnWriteArraySet、ConcurrentSkipListSet，前者读多写少，后者支持排序；
    Map：ConcurrentHashMap（重点），JDK1.8+基于数组+链表+红黑树，分段锁+CAS，并发性能极高，是高并发Map首选；
    队列：ArrayBlockingQueue、LinkedBlockingQueue、PriorityBlockingQueue，阻塞队列，线程池核心配套工具，实现任务异步缓冲。
3. 单例模式的并发安全
    高并发下普通单例会出现多实例问题，推荐使用双重校验锁（DCL）+volatile或枚举单例，保证线程安全且高性能。
    模块七：高并发高频问题与线上实战避坑（核心）
    1. 死锁问题（高并发致命问题）
    产生四大条件（必须同时满足）
    互斥条件、请求与保持条件、不可剥夺条件、循环等待条件。
    企业排查与解决
    排查：jstack命令查看线程堆栈，定位死锁线程；解决：避免嵌套锁、统一锁获取顺序、设置锁超时时间、使用定时锁，破坏任意一个条件即可避免死锁。
2. 并发性能调优要点
    锁优化：减小锁粒度、使用读写锁（ReentrantReadWriteLock）、读多写少用写时复制容器、避免长时间持有锁；
    线程优化：合理配置线程池参数，避免线程过多或过少，减少线程上下文切换；
    无锁优化：优先使用CAS原子类、volatile，减少锁竞争；
    避免阻塞：减少线程内IO操作、同步调用，改用异步、异步回调。
3. 高频线上坑点
    线程池参数配置不合理，导致任务堆积、OOM、CPU飙升；
    锁粒度太大，并发性能极差，系统吞吐量上不去；
    使用非线程安全容器，导致数据错乱、线上bug；
    volatile误用，试图保证原子性，引发数据计算错误；
    线程泄漏：线程执行完毕未释放，线程池无限创建线程。
4. 高并发服务稳定性保障
    限流：Semaphore、Guava RateLimiter、网关限流，控制请求流量；
    降级：高并发下关闭非核心接口，保证核心接口可用；
    熔断：依赖服务异常时熔断，避免级联故障；
    异步：核心流程同步，非核心流程异步处理，提升响应速度。
    模块八：核心总结与学习路径
    Java高并发核心围绕JMM内存模型、锁机制、CAS无锁、线程池、JUC工具、并发安全容器、线上调优七大核心展开，学习路径遵循：基础概念→同步机制→无锁并发→线程池→高级工具→实战避坑。
    企业级开发原则：优先无锁，少用锁，减小锁粒度；强制使用线程池，杜绝手动创建线程；优先JUC并发工具，摒弃传统低效同步方案；线上环境做好监控、限流、降级，保障高并发下系统稳定。
    面试核心考点：JMM、volatile与synchronized原理、CAS与ABA问题、线程池参数、ConcurrentHashMap原理、死锁、JUC工具类使用场景，吃透这些即可应对绝大多数高并发面试与实战场景。
