多线程与高并发

--------------------------------------------------------------------------------------------------------------------------------------
一、多线程与高并发基础概念
1. 核心定义
    - 进程：操作系统资源分配的基本单位，有独立的内存空间，一个进程可包含多个线程
    - 线程：CPU调度和执行的基本单位，共享进程的内存空间（堆、方法区），拥有私有栈、程序计数器
    - 并发：同一时间段内多个任务交替执行（单核CPU实现），看似同时进行
    - 并行：同一时刻多个任务同时执行（多核CPU实现）
    - 高并发：系统在单位时间内处理大量请求/任务的能力，核心是提升资源利用率和响应效率
2. 多线程的意义
    - 提升CPU利用率：避免单线程因IO/等待导致CPU空闲
    - 提高程序响应性：如UI程序后台处理任务，前端仍可交互
    - 充分利用多核硬件资源：现代CPU均为多核，多线程可并行执行
3. 多线程的问题
    - 线程安全：多个线程操作共享资源导致数据不一致（如并发修改同一变量）
    - 死锁：多个线程互相持有对方需要的资源，导致永久阻塞
    - 上下文切换：线程切换消耗CPU资源，过度切换反而降低性能
    - 资源竞争：线程争抢锁、CPU时间片等资源，导致执行效率下降

二、Java多线程实现方式
1. 继承Thread类
    - 步骤：继承Thread类 → 重写run()方法 → 创建实例调用start()启动
    - 代码示例：
    class MyThread extends Thread {
    @Override
    public void run() {
        for (int i = 0; i < 10; i++) {
            System.out.println(Thread.currentThread().getName() + ": " + i);
        }
    }
    }
    // 使用
    public class Test {
    public static void main(String[] args) {
        MyThread thread1 = new MyThread();
        MyThread thread2 = new MyThread();
        thread1.start();
        thread2.start();
    }
    }
    - 缺点：Java单继承限制，无法继承其他类；线程与任务耦合
2. 实现Runnable接口
    - 步骤：实现Runnable接口 → 重写run()方法 → 创建Thread实例传入Runnable → 调用start()
    - 代码示例：
    class MyRunnable implements Runnable {
    @Override
    public void run() {
        for (int i = 0; i < 10; i++) {
            System.out.println(Thread.currentThread().getName() + ": " + i);
        }
    }
    }
    // 使用
    public class Test {
    public static void main(String[] args) {
        MyRunnable runnable = new MyRunnable();
        Thread thread1 = new Thread(runnable);
        Thread thread2 = new Thread(runnable);
        thread1.start();
        thread2.start();
    }
    }
    - 优点：避免单继承限制；线程与任务解耦，可复用任务
3. 实现Callable接口（带返回值+可抛异常）
    - 步骤：实现Callable接口 → 重写call()方法 → 封装为FutureTask → 传入Thread启动
    - 代码示例：
    import java.util.concurrent.Callable;
    import java.util.concurrent.FutureTask;
    class MyCallable implements Callable<Integer> {
    @Override
    public Integer call() throws Exception {
        int sum = 0;
        for (int i = 1; i <= 100; i++) {
            sum += i;
        }
        return sum;
    }
    }
    // 使用
    public class Test {
    public static void main(String[] args) throws Exception {
        MyCallable callable = new MyCallable();
        FutureTask<Integer> futureTask = new FutureTask<>(callable);
        Thread thread = new Thread(futureTask);
        thread.start();
        // 获取返回值（阻塞直到任务完成）
        Integer result = futureTask.get();
        System.out.println("计算结果：" + result);
    }
    }
    - 优点：有返回值；可抛出受检异常；支持取消任务
4. 线程池（推荐，高并发核心）
    - 原因：手动创建线程成本高（创建/销毁耗时），线程池可复用线程、控制并发数
    - 核心接口：Executor → ExecutorService → ThreadPoolExecutor（核心实现）
    - 常用线程池（Executors工具类创建）：
  ① FixedThreadPool：固定核心线程数，适用于任务量稳定的场景
  ② CachedThreadPool：可缓存线程池，核心线程数0，最大线程数无限，适用于短期轻量任务
  ③ SingleThreadExecutor：单线程池，任务串行执行，适用于需顺序执行的任务
  ④ ScheduledThreadPool：定时/周期性任务线程池
    - 代码示例（ThreadPoolExecutor自定义线程池，推荐生产使用）：
    import java.util.concurrent.ArrayBlockingQueue;
    import java.util.concurrent.ThreadPoolExecutor;
    import java.util.concurrent.TimeUnit;
    public class Test {
    public static void main(String[] args) {
        // 核心参数：核心线程数、最大线程数、空闲线程存活时间、时间单位、任务队列、线程工厂、拒绝策略
        ThreadPoolExecutor executor = new ThreadPoolExecutor(
            5,  // 核心线程数
            10, // 最大线程数
            60, // 空闲线程存活时间（秒）
            TimeUnit.SECONDS,
            new ArrayBlockingQueue<>(100), // 任务队列（有界）
            new ThreadPoolExecutor.AbortPolicy() // 拒绝策略（默认，满了抛异常）
        );
        // 提交任务
        for (int i = 0; i < 20; i++) {
            int taskNum = i;
            executor.execute(() -> {
                System.out.println(Thread.currentThread().getName() + "执行任务" + taskNum);
                try {
                    Thread.sleep(100);
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }
            });
        }
        // 关闭线程池
        executor.shutdown();
    }
    }
    - 核心参数说明：
  - 核心线程数：常驻线程数，即使空闲也不会销毁
  - 最大线程数：线程池允许的最大线程数量
  - 任务队列：存放等待执行的任务，分为有界/无界队列
  - 拒绝策略：任务队列满且达到最大线程数时的处理方式（AbortPolicy抛异常、CallerRunsPolicy调用者执行、DiscardPolicy丢弃、DiscardOldestPolicy丢弃最老任务）

三、线程生命周期（Java）
1. 新建状态（New）：创建Thread实例但未调用start()
2. 就绪状态（Runnable）：调用start()后，等待CPU调度
3. 运行状态（Running）：CPU调度后执行run()方法
4. 阻塞状态（Blocked）：
   - 同步阻塞：等待获取synchronized锁
   - 等待阻塞：调用wait()、join()等方法
   - 超时阻塞：调用sleep(long)、wait(long)等方法
5. 终止状态（Terminated）：run()执行完毕或异常终止

四、线程安全与同步机制
1. 线程安全问题根源
    - 共享资源：多个线程访问同一可变资源（如成员变量、静态变量）
    - 非原子操作：多个步骤的操作被线程切换打断（如i++，分为读取、加1、写入三步）
    - 指令重排序：JVM优化导致代码执行顺序与预期不一致
2. 同步机制
    ① synchronized关键字（内置锁）
    - 作用：保证方法/代码块同一时刻只有一个线程执行，可重入、非公平
    - 使用场景：
  - 修饰实例方法：锁当前对象实例
  - 修饰静态方法：锁类对象（Class）
  - 修饰代码块：锁指定对象（如synchronized (this) {}）
    - 代码示例：
    class Counter {
    private int count = 0;
    // 同步实例方法
    public synchronized void increment() {
        count++;
    }
    // 同步代码块
    public void decrement() {
        synchronized (this) {
            count--;
        }
    }
    }
    ② Lock接口（显式锁，JUC包）
    - 常用实现：ReentrantLock（可重入锁）、ReentrantReadWriteLock（读写锁）
    - 优点：可手动加锁/释放锁、支持公平锁/非公平锁、可中断、可超时获取锁
    - 代码示例（ReentrantLock）：
    import java.util.concurrent.locks.ReentrantLock;
    class Counter {
    private int count = 0;
    private ReentrantLock lock = new ReentrantLock(true); // 公平锁
    public void increment() {
        lock.lock(); // 加锁
        try {
            count++;
        } finally {
            lock.unlock(); // 释放锁（必须放finally，避免异常导致锁不释放）
        }
    }
    }
    - 读写锁（ReentrantReadWriteLock）：
  - 读锁：多个线程可同时获取，适用于读多写少场景
  - 写锁：排他锁，同一时刻只能一个线程获取
  - 优点：提升读操作并发度
    ③ 原子类（java.util.concurrent.atomic包）
    - 原理：基于CAS（Compare And Swap，比较并交换）实现无锁并发，避免锁竞争
    - 常用类：AtomicInteger、AtomicLong、AtomicReference、AtomicBoolean
    - 代码示例：
    import java.util.concurrent.atomic.AtomicInteger;
    class AtomicCounter {
    private AtomicInteger count = new AtomicInteger(0);
    public void increment() {
        count.incrementAndGet(); // 原子自增
    }
    public int getCount() {
        return count.get();
    }
    }
    ④ volatile关键字
    - 作用：保证变量的可见性（一个线程修改后，其他线程立即可见）、禁止指令重排序
    - 局限：不保证原子性（如volatile int i; i++仍非线程安全）
    - 适用场景：状态标记（如boolean flag;）、双重检查锁（单例模式）
    - 代码示例（单例模式双重检查锁）：
    class Singleton {
    private volatile static Singleton instance; // 必须加volatile
    private Singleton() {}
    public static Singleton getInstance() {
        if (instance == null) { // 第一次检查
            synchronized (Singleton.class) {
                if (instance == null) { // 第二次检查
                    instance = new Singleton(); // 禁止指令重排序
                }
            }
        }
        return instance;
    }
    }

五、高并发核心工具类（JUC）
1. CountDownLatch（倒计时门闩）
    - 作用：让一组线程等待另一组线程执行完毕后再继续执行
    - 场景：主线程等待多个子线程完成初始化任务
    - 代码示例：
    import java.util.concurrent.CountDownLatch;
    public class Test {
    public static void main(String[] args) throws InterruptedException {
        CountDownLatch latch = new CountDownLatch(3); // 计数3
        for (int i = 0; i < 3; i++) {
            new Thread(() -> {
                System.out.println(Thread.currentThread().getName() + "执行任务");
                latch.countDown(); // 计数减1
            }).start();
        }
        latch.await(); // 主线程等待计数为0
        System.out.println("所有子线程执行完毕，主线程继续");
    }
    }
2. CyclicBarrier（循环栅栏）
    - 作用：让一组线程到达屏障点后才继续执行，可重复使用
    - 场景：多个线程协同完成一个任务，需全部准备好后再执行
    - 代码示例：
    import java.util.concurrent.CyclicBarrier;
    public class Test {
    public static void main(String[] args) {
        CyclicBarrier barrier = new CyclicBarrier(3, () -> {
            System.out.println("所有线程到达屏障，执行统一逻辑");
        }); // 3个线程到达后执行回调
        for (int i = 0; i < 3; i++) {
            new Thread(() -> {
                System.out.println(Thread.currentThread().getName() + "到达屏障");
                try {
                    barrier.await(); // 等待其他线程
                } catch (Exception e) {
                    e.printStackTrace();
                }
                System.out.println(Thread.currentThread().getName() + "继续执行");
            }).start();
        }
    }
    }
3. Semaphore（信号量）
    - 作用：控制同时访问特定资源的线程数量，实现限流
    - 场景：接口限流、连接池（如数据库连接池）
    - 代码示例：
    import java.util.concurrent.Semaphore;
    public class Test {
    public static void main(String[] args) {
        Semaphore semaphore = new Semaphore(2); // 允许2个线程同时访问
        for (int i = 0; i < 5; i++) {
            new Thread(() -> {
                try {
                    semaphore.acquire(); // 获取许可
                    System.out.println(Thread.currentThread().getName() + "获取资源，开始执行");
                    Thread.sleep(1000);
                    System.out.println(Thread.currentThread().getName() + "释放资源");
                } catch (InterruptedException e) {
                    e.printStackTrace();
                } finally {
                    semaphore.release(); // 释放许可
                }
            }).start();
        }
    }
    }
4. ConcurrentHashMap（并发集合）
    - 作用：线程安全的HashMap，替代Hashtable和Collections.synchronizedMap
    - 原理：JDK7分段锁（Segment），JDK8 CAS + synchronized（粒度更小）
    - 优点：并发度高，读操作无锁（volatile），写操作只锁当前桶
    - 代码示例：
    import java.util.concurrent.ConcurrentHashMap;
    public class Test {
    public static void main(String[] args) {
        ConcurrentHashMap<String, Integer> map = new ConcurrentHashMap<>();
        // 并发插入
        for (int i = 0; i < 10; i++) {
            int num = i;
            new Thread(() -> {
                map.put("key" + num, num);
                System.out.println(Thread.currentThread().getName() + ": " + map.get("key" + num));
            }).start();
        }
    }
    }

六、高并发调优思路
1. 线程池调优
    - 核心线程数：CPU密集型（CPU核心数+1），IO密集型（CPU核心数*2）
    - 任务队列：使用有界队列（避免无界队列导致OOM）
    - 拒绝策略：根据业务选择（如CallerRunsPolicy降级处理）
    - 监控：记录线程池状态（活跃线程数、队列长度、完成任务数）
2. 锁优化
    - 减少锁粒度：如ConcurrentHashMap的分段锁/桶锁
    - 锁消除：JVM自动消除无竞争的锁
    - 锁粗化：将多次加锁/释放锁合并为一次
    - 替换锁：用原子类、CAS替代synchronized/Lock（无锁编程）
3. 减少上下文切换
    - 避免创建过多线程：线程数超过CPU核心数+1会导致频繁切换
    - 使用协程（如Project Loom）：轻量级线程，减少切换成本
    - 无锁编程：CAS、原子类替代锁
4. 资源隔离
    - 线程池隔离：不同业务使用不同线程池，避免一个业务耗尽所有线程
    - 信号量隔离：控制单个资源的访问数
5. 缓存优化
    - 本地缓存（如Caffeine）：减少远程调用
    - 分布式缓存（如Redis）：共享缓存，减轻数据库压力
    - 缓存击穿/穿透/雪崩防护：布隆过滤器、缓存过期时间随机化、熔断降级

七、常见问题与解决方案
1. 死锁
    - 产生条件：互斥、持有并等待、不可剥夺、循环等待
    - 排查：jstack命令查看线程状态
    - 解决：破坏死锁条件（如定时释放锁、按顺序获取锁）
2. 线程泄漏
    - 原因：线程池核心线程数过多、任务阻塞导致线程无法回收
    - 解决：设置合理的核心线程数、超时时间，监控线程池状态
3. 竞态条件
    - 原因：多个线程同时修改共享资源
    - 解决：使用同步机制（synchronized/Lock）、原子类
4. 吞吐量低
    - 原因：锁竞争激烈、上下文切换频繁、IO阻塞
    - 解决：减少锁粒度、使用无锁编程、异步处理IO

--------------------------------------------------------------------------------------------------------------------------------------
总结
1. 多线程核心是利用多核资源提升效率，高并发核心是保证系统在高负载下的稳定性和响应性
2. 线程安全需通过同步机制（synchronized/Lock）、原子类、并发集合实现，优先使用无锁方案减少竞争
3. 高并发调优需从线程池、锁、缓存、资源隔离多维度入手，结合监控工具定位瓶颈
