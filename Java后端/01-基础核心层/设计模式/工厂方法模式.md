工厂方法模式
通过前序简单工厂模式的学习，已实现对象创建逻辑与业务逻辑的基础解耦，依托统一工厂类封装实例化细节，可有效简化客户端调用流程。
但该模式存在根本性设计缺陷：新增产品类型时，必须修改工厂类内部的条件判断逻辑，直接违背开放封闭原则；
同时单一工厂类承担全品类产品的实例化职责，存在职责过载、代码冗余臃肿等问题，难以适配产品类型动态迭代的复杂业务场景。
针对上述架构痛点，工厂方法模式（Factory Method Pattern）作为GoF 23种经典创建型设计模式，对简单工厂模式进行规范化重构与升级，可彻底解决开闭原则违背问题，进一步细化职责边界、降低模块耦合度，是工业级软件开发中对象创建场景的主流设计方案。
本章将围绕该模式的核心定义、架构角色、标准实现、实战落地及工程规范展开系统性阐述。
一、模式核心定义
工厂方法模式亦称工厂模式，属于典型的创建型设计模式，其核心定义为：定义用于创建对象的抽象工厂接口，声明标准化工厂方法，将具体产品类的实例化逻辑延迟至具体工厂实现类完成，由具体工厂决定目标产品的实例化规则；客户端仅依赖抽象层完成调用，实现系统对扩展开放、对修改关闭的设计目标。
该模式的核心设计思路，是将简单工厂模式的集中式工厂拆分为抽象工厂与具体工厂两层架构，每类具体工厂对应单一具体产品的实例化逻辑，严格遵循单一职责原则与开放封闭原则，实现产品创建逻辑与业务执行逻辑的彻底剥离，达成更高层级的模块解耦，适配复杂业务体系下产品类型动态扩展的架构需求。
该模式的核心设计思想，是将简单工厂的单一工厂拆分为抽象工厂与具体工厂两层，每个具体工厂对应创建一种具体产品，严格遵循单一职责原则与开放封闭原则，彻底剥离产品创建与业务逻辑，实现更高程度的解耦，适配复杂业务下的产品类型动态扩展需求。
二、模式结构与角色拆解
工厂方法模式包含四大核心角色，相较简单工厂模式新增抽象工厂层级，各角色职责边界清晰、分工明确，完全契合高内聚、低耦合的面向对象设计准则，各角色定义如下：
抽象产品（Abstract Product）：定义产品模块的核心业务契约，声明所有具体产品需实现的公共接口方法，为所有具体产品类的父级接口或抽象类，是客户端直接依赖的抽象层，也是落实依赖倒置原则的核心载体。
具体产品（Concrete Product）：实现抽象产品接口或继承抽象产品类，完成具体业务逻辑的落地实现，是工厂类最终实例化的目标对象，每一类具体产品对应独立的业务实现类。
抽象工厂（Abstract Factory）：工厂方法模式的核心抽象层，定义工厂方法的标准规范，仅声明产品创建接口，不包含任何具体产品的实例化逻辑，所有具体工厂必须强制实现该抽象工厂契约。
具体工厂（Concrete Factory）：实现抽象工厂接口，重写标准化工厂方法，完成对应单一具体产品的实例化逻辑，每类具体工厂仅承担一类产品的创建职责，严格遵循单一职责原则。
抽象产品（Abstract Product）：定义产品的核心业务规范，声明所有具体产品共有的接口方法，是所有具体产品的父类或接口，也是客户端直接依赖的抽象层，践行依赖倒置原则。
具体产品（Concrete Product）：实现抽象产品接口，完成具体业务逻辑的落地，是最终实例化的目标对象，每种产品对应一个独立的具体产品类。
抽象工厂（Abstract Factory）：工厂方法模式的核心抽象层，定义工厂方法接口，声明产品创建规范，不涉及具体产品的实例化逻辑，所有具体工厂必须实现该接口。
具体工厂（Concrete Factory）：实现抽象工厂接口，重写工厂方法，完成对应具体产品的实例化，每个具体工厂仅负责创建一种具体产品，严格遵循单一职责原则。
三、标准代码实现
本章沿用分布式即时通讯（IM）系统消息处理器的实战场景，基于简单工厂模式进行架构重构，改造为工厂方法模式，从根本上解决开闭原则违背问题，同时保持技术场景的连贯性与一致性，标准实现如下：
1. 抽象产品：消息处理接口
    /**
     * 抽象产品：定义消息处理统一规范
     */
    public interface MessageHandler {
    /**
     * 消息处理核心方法
     * @param content 消息内容
     */
    void handleMessage(String content);
    }
2. 具体产品：各类消息处理器实现
    /**
     * 具体产品：文本消息处理器
     */
    public class TextMessageHandler implements MessageHandler {
    @Override
    public void handleMessage(String content) {
        System.out.println("文本消息处理：" + content);
    }
    }
    /**
     * 具体产品：图片消息处理器
     */
    public class ImageMessageHandler implements MessageHandler {
    @Override
    public void handleMessage(String content) {
        System.out.println("图片消息处理：" + content);
    }
    }
    /**
     * 具体产品：语音消息处理器
     */
    public class VoiceMessageHandler implements MessageHandler {
    @Override
    public void handleMessage(String content) {
        System.out.println("语音消息处理：" + content);
    }
    }
3. 抽象工厂：工厂方法接口
    /**
     * 抽象工厂：定义消息处理器创建规范
     */
    public interface MessageHandlerFactory {
    /**
     * 抽象工厂方法：延迟到具体工厂实现
     * @return 具体消息处理器实例
     */
    MessageHandler createHandler();
    }
4. 具体工厂：对应产品创建实现
    /**
     * 具体工厂：文本消息处理器工厂
     */
    public class TextMessageHandlerFactory implements MessageHandlerFactory {
    @Override
    public MessageHandler createHandler() {
        // 仅创建文本消息处理器，单一职责
        return new TextMessageHandler();
    }
    }
    /**
     * 具体工厂：图片消息处理器工厂
     */
    public class ImageMessageHandlerFactory implements MessageHandlerFactory {
    @Override
    public MessageHandler createHandler() {
        // 仅创建图片消息处理器，单一职责
        return new ImageMessageHandler();
    }
    }
    /**
     * 具体工厂：语音消息处理器工厂
     */
    public class VoiceMessageHandlerFactory implements MessageHandlerFactory {
    @Override
    public MessageHandler createHandler() {
        // 仅创建语音消息处理器，单一职责
        return new VoiceMessageHandler();
    }
    }
5. 客户端调用
    /**
     * 客户端：仅依赖抽象层，无具体产品与工厂耦合
     */
    public class ImClient {
    public static void main(String[] args) {
        // 创建文本消息处理器，面向抽象工厂与产品调用
        MessageHandlerFactory textFactory = new TextMessageHandlerFactory();
        MessageHandler textHandler = textFactory.createHandler();
        textHandler.handleMessage("工厂方法模式实战");
        // 创建图片消息处理器
        MessageHandlerFactory imageFactory = new ImageMessageHandlerFactory();
        MessageHandler imageHandler = imageFactory.createHandler();
        imageHandler.handleMessage("im_img_001.jpg");
    }
    }
    四、模式执行流程
    客户端指定具体工厂实现类，完成具体工厂对象实例化，全程仅依赖抽象工厂接口，不与具体实现产生硬编码耦合。
    调用抽象工厂定义的标准工厂方法，由具体工厂封装对应具体产品的实例化全流程。
    工厂方法返回抽象产品类型的实例对象，客户端面向抽象产品接口完成业务方法调用，无需感知具体产品的实现细节。
    新增产品类型时，仅需新增对应具体产品类与具体工厂类，无需修改既有代码逻辑，即可完成功能扩展。
    五、核心优缺点分析
    1. 核心优点
    严格遵循开放封闭原则：新增产品类型时，仅需扩展具体产品类与对应具体工厂类，无需修改既有工厂及业务代码，彻底规避简单工厂模式的核心设计缺陷，适配业务需求高频迭代场景。
    单一职责原则落地充分：每类具体工厂仅承担单一产品的实例化职责，职责边界清晰、代码精简，避免集中式工厂职责过载、逻辑冗余臃肿等问题。
    模块解耦程度显著提升：客户端完全依赖抽象层完成交互，与具体产品、具体工厂实现彻底解耦，契合依赖倒置原则，系统灵活性与可维护性大幅优化。
    横向扩展能力优异：产品类型扩展对现有系统无侵入性，不影响既有业务逻辑稳定性，适配中大型项目及分布式系统的架构演进需求。
    代码规范性与可读性强：采用标准化分层架构，团队协作开发过程中，代码风格统一，便于调试、维护与迭代升级。
2. 核心缺点
    类文件数量呈线性增长：每类产品对应独立的具体工厂类，产品类型较多时，会产生大量工厂实现类，增加系统类文件管理与维护成本。
    架构复杂度高于简单工厂模式：引入抽象工厂层级，相较于简单工厂模式，初学者的理解与落地实现难度略有提升。
    客户端需感知具体工厂实现：客户端需指定具体工厂实现类完成对象创建，无法通过统一参数完成实例化调用，实际工程中需结合配置文件或IOC容器进一步优化。
    六、适用场景
    产品品类较多、需动态新增产品类型，且系统需严格遵循开放封闭原则、具备强扩展性的业务场景。
    需屏蔽产品实例化细节，客户端仅面向抽象接口编程，实现业务层与对象创建层彻底解耦的中大型项目。
    单一产品实例化逻辑复杂，需独立封装、单独维护，避免复杂创建逻辑侵入业务代码的场景。
    分布式系统、微服务架构中，各类标准化组件、工具类、业务Bean的规范化创建与管理场景。
    现有系统基于简单工厂模式实现，需进行架构重构，解决开闭原则违背问题的技术改造场景。
    七、工程实践注意事项
    合理管控产品品类数量：产品类型过多时，可结合抽象工厂模式对产品进行分组管理，避免工厂类过度膨胀，优化系统架构复杂度。
    结合IOC容器实现架构优化：企业级项目中，通过Spring等IOC容器统一管理具体工厂Bean，客户端无需硬编码指定具体工厂，进一步降低模块耦合度。
    封装公共实例化逻辑：可将抽象工厂由接口改造为抽象类，封装通用创建逻辑，具体工厂仅实现差异化实例化代码，减少代码冗余。
    规范异常处理机制：产品实例化异常时，需在具体工厂内部抛出标准化业务异常，便于问题定位与故障排查。
    无状态产品单例化优化：针对无状态产品对象，可在具体工厂内部实现单例模式，避免频繁创建与销毁对象，提升系统运行性能。
    精准区分场景选型：小型项目、产品类型固定且迭代频率低的场景，优先选用简单工厂模式；中大型项目、需求迭代频繁的场景，推荐采用工厂方法模式。

    九、本章总结
    工厂方法模式作为经典创建型设计模式，是简单工厂模式的规范化升级方案，通过抽象工厂层级的设计，彻底解决了简单工厂模式违背开放封闭原则的核心缺陷，将单一职责、依赖倒置、开放封闭三大核心设计原则贯穿对象创建全流程。
    其核心架构价值在于实现极致模块解耦与动态横向扩展，完美适配复杂业务体系的动态迭代需求，是工业级项目中对象创建场景的标准设计方案。
    实际工程应用中，需结合项目规模、产品迭代频率完成合理选型，既要规避简单工厂模式的架构短板，也要避免工厂方法模式过度设计导致的类膨胀问题。
    熟练掌握工厂方法模式，不仅能够优化对象创建逻辑，更能深入理解面向对象抽象设计的核心思想，为后续学习抽象工厂模式、分布式架构设计及源码研读奠定坚实的设计基础。
    在实际工程应用中，需根据项目规模、产品迭代频率合理选型，既要规避简单工厂的架构短板，也要避免工厂方法模式过度设计导致的类膨胀问题。
    掌握工厂方法模式，不仅能优化对象创建逻辑，更能深入理解面向对象抽象设计的核心思想，为后续学习抽象工厂模式、架构设计与源码研读奠定坚实基础。
