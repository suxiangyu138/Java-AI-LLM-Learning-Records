# 基于 Redis 构建轻量社交网络 + **极致降内存方案**
核心思路：
1. 精简 Key、压缩存储、弱化大对象
2. 合理过期、冷热分离、禁用大数据持久化
3. 改用**纯字符串/整型编码**、减少序列化开销
4. 时间线采用「拉模式+裁剪」，杜绝数据膨胀
5. 集合压缩、限制列表上限、自动淘汰旧数据

---

## 一、先改底层：从根源砍内存
### 1. 更换序列化（最关键）
丢掉 Jackson JSON 序列化，**改用 String 原生存储**
JSON 序列化体积大、字段冗余、占用内存极高。

```java
@Configuration
public class RedisConfig {
    @Bean
    public RedisTemplate<String, String> redisTemplate(RedisConnectionFactory factory) {
        RedisTemplate<String, String> template = new RedisTemplate<>();
        template.setConnectionFactory(factory);
        StringRedisSerializer serializer = new StringRedisSerializer();
        // 全部统一 String 序列化，零额外内存开销
        template.setKeySerializer(serializer);
        template.setHashKeySerializer(serializer);
        template.setValueSerializer(serializer);
        template.setHashValueSerializer(serializer);
        return template;
    }
}
```
- 所有 value 存 **纯字符串/数字**
- 不再存 JSON 对象，内存直接降 50%+

### 2. Redis 全局内存配置（redis.conf）
```conf
# 最大内存限制
maxmemory 512mb
# 内存满了优先淘汰最久未使用的动态/内容
maxmemory-policy allkeys-lru
# 缩减闲置释放
hz 10
# 关闭不必要持久化（纯缓存社交场景）
save ""
appendonly no
```

## 二、Key 设计压缩（减少 Key 冗余）
### 旧版（耗内存）
```
user:userId
follow:me:userId
fans:me:userId
feed:content:feedId
timeline:userId
```

### 新版（极简短 Key，内存更低）
```
u:{uid}       // 用户Hash
fw:{uid}      // 我的关注 Set
fs:{uid}      // 我的粉丝 Set
fd:{fid}      // 动态内容 String
tl:{uid}      // 时间线 ZSet
```
Key 越短，全局内存占用越低，大规模数据差距极大。

## 三、各模块降内存重构（可直接替换）
### 1. 用户模块：Hash 精简字段，不存冗余
只存必要字段，不存冗余扩展字段
```java
@Component
public class UserService {
    @Resource
    private RedisTemplate<String, String> rt;

    public void saveUser(Long uid, String name) {
        String key = "u:" + uid;
        rt.opsForHash().put(key, "n", name);
        // 不存头像、简介等非强必要字段
    }

    public String getUserName(Long uid) {
        return (String) rt.opsForHash().get("u:" + uid, "n");
    }
}
```

### 2. 关注/粉丝：Set 只存数字ID，极致紧凑
Set 存 Long 字符串，Redis 对**整型字符串会自动压缩编码**
```java
@Component
public class FollowService {
    @Resource
    private RedisTemplate<String, String> rt;

    // 关注
    public void follow(Long uid, Long targetUid) {
        rt.opsForSet().add("fw:" + uid, targetUid.toString());
        rt.opsForSet().add("fs:" + targetUid, uid.toString());
    }

    // 取关
    public void unFollow(Long uid, Long targetUid) {
        rt.opsForSet().remove("fw:" + uid, targetUid.toString());
        rt.opsForSet().remove("fs:" + targetUid, uid.toString());
    }
}
```
Redis 特性：
> 纯数字字符串集合 → 底层 `intset` 紧凑编码，内存极小
> 含字母/特殊字符 → 升级 `hashtable` 内存翻倍

## 四、动态&时间线：社交最吃内存，重点优化
### 1. 动态内容：短内容+自动过期
```java
@Component
public class FeedService {
    @Resource
    private RedisTemplate<String, String> rt;

    // 发布动态：内容精简 + 7天自动过期
    public void publish(Long fid, Long uid, String content) {
        String key = "fd:" + fid;
        // 拼接极简字符串：uid|time|content
        long now = System.currentTimeMillis();
        String val = uid + "|" + now + "|" + content;
        rt.opsForValue().set(key, val, 7, TimeUnit.DAYS);

        // 时间线写入
        rt.opsForZSet().add("tl:" + uid, fid.toString(), now);
        // 时间线也设置过期
        rt.expire("tl:" + uid, 30, TimeUnit.DAYS);
    }
}
```

### 2. 时间线：**拉模式+数量裁剪**（核心降内存）
放弃「推模式」（关注人发动态全推给粉丝，内存爆炸）
采用工业级低成本方案：
- **推模式**：粉丝多 → 一条动态复制几万份，内存爆炸
- **拉模式**：只存自己时间线，查看时实时合并关注列表动态，零冗余

```java
// 裁剪单个人时间线，只保留最近200条，防止无限膨胀
public void trimTimeline(Long uid) {
    String key = "tl:" + uid;
    // 移除score最小的旧数据
    rt.opsForZSet().removeRange(key, 0, -201);
}
```
每条动态只存**1份原版**，所有人共用，内存直接砍 80%。

## 五、通用全局降内存规则
1. **所有大体积数据必须加过期**
   动态、临时关系、浏览记录、临时缓存 全部 TTL

2. **禁止存储长文本、富文本**
   长内容存 MySQL，Redis 只存摘要+ID

3. **集合/有序集合强制限制容量**
   关注列表、粉丝、时间线 上限封顶，避免恶意刷数据

4. **利用 Redis 底层编码优化**
   - Key/Value 尽量纯数字
   - 避免特殊符号、长字符串
   - 利用 intset、ziplist 压缩编码

5. **冷热数据分离**
   - 热点社交数据：常驻 Redis
   - 历史旧动态、冷门关系：自动 LRU 淘汰

## 六、优化前后内存对比
| 优化项 | 优化前 | 优化后 | 降幅 |
|--------|--------|--------|------|
| 序列化 | JSON 对象 | 纯字符串/数字 | 50% |
| Key 长度 | 长前缀Key | 极简短Key | 15% |
| 时间线 | 推模式多份冗余 | 拉模式单份存储 | 80% |
| 动态数据 | 永久存储 | 7天过期 | 60% |
| 集合编码 | 哈希表 | 整型压缩集合 | 40% |

## 七、最简落地清单（你直接照着改）
1. 替换为 **StringRedisTemplate** 纯字符串存储
2. 全线改用短 Key：`u:、fw:、fs:、fd:、tl:`
3. 动态、时间线全部配置 TTL 过期
4. 时间线改为**拉模式**，关闭推模式冗余
5. 每个 ZSet 时间线增加 `trim` 裁剪上限
6. redis 配置内存上限 + LRU 淘汰策略
