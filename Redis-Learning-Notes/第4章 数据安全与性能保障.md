# 第四章 数据安全与性能保障
## 4.1 本章概述
Redis 是**内存数据库**，断电、进程崩溃、机器宕机都会导致内存数据丢失；同时高并发下会存在性能瓶颈、内存溢出、命令滥用等问题。
本章核心讲解：**持久化、内存淘汰、安全配置、高可用、性能优化**，兼顾数据不丢失与服务高性能稳定运行。

---

## 4.2 Redis 数据持久化（核心数据安全）
持久化作用：将内存数据定期写入磁盘，重启后加载恢复数据，解决断电丢数问题。

### 4.2.1 RDB 持久化（快照模式）
1. 原理
   周期性将**全量内存数据**生成二进制快照文件 `dump.rdb` 保存到磁盘。
2. 触发方式
- 自动触发：配置规则，如多少秒内修改多少 key 自动快照
- 手动触发：`save`、`bgsave`
3. 特点
- 优点：文件体积小、恢复速度快、适合冷备份、对主线程压力小
- 缺点：存在**时间窗口丢数**，两次快照之间的数据宕机丢失

### 4.2.2 AOF 持久化（日志模式）
1. 原理
   以**日志形式**记录每一条写命令，追加到 `appendonly.aof` 文件，重启重放命令恢复数据。
2. 刷盘策略
- `always`：每条写命令立即落盘，数据最安全，性能最差
- `everysec`：每秒批量落盘，折中方案（生产常用）
- `no`：由操作系统控制刷盘，性能高、安全性低
3. 特点
- 优点：几乎不丢数据、实时性强
- 缺点：日志文件大、恢复速度慢、长期运行文件臃肿

### 4.2.3 生产持久化组合方案
- 默认推荐：**RDB + AOF 同时开启**
- 宕机恢复：优先加载 AOF 保证数据完整，RDB 做定时全量备份

## 4.3 内存淘汰策略（内存溢出保障）
Redis 内存有限，大量缓存数据会占满内存，需配置**最大内存 + 淘汰规则**。

### 4.3.1 核心配置
- `maxmemory`：限制 Redis 最大使用内存
- `maxmemory-policy`：内存满时淘汰规则

### 4.3.2 六大淘汰策略
1. **volatile-lru**：只淘汰设置过期键，优先淘汰最少使用
2. **allkeys-lru**：全体 key 范围内，淘汰最少使用（业务常用）
3. **volatile-ttl**：只淘汰过期键，优先淘汰剩余时间最短
4. **volatile-random**：过期键随机删除
5. **allkeys-random**：所有 key 随机删除
6. **noeviction**：不删除任何数据，内存满直接报错（默认）

## 4.4 Redis 基础安全配置
### 4.4.1 密码认证
开启密码，禁止匿名访问，防止外网恶意连接。
```bash
# 临时设置密码
config set requirepass 123456
# 连接后认证
auth 123456
```

### 4.4.2 绑定 IP 与端口防护
- 禁止 `0.0.0.0` 全网监听，仅绑定内网/指定业务 IP
- 修改默认 6379 端口
- 防火墙放行白名单 IP，屏蔽公网直接访问

### 4.4.3 危险命令禁用
生产禁用高危命令，防止误操作删库：
- 禁用：`flushdb`、`flushall`、`keys *`、`config` 等
  通过配置文件重命名或直接禁用。

### 4.4.4 防止大数据泄露
- 禁止开启外网 AOF/RDB 文件下载
- 定期备份 RDB 快照，异地备份留存

## 4.5 高可用基础方案（服务高可用）
### 4.5.1 主从复制
- 一主多从，主节点负责写，从节点负责读
- 数据自动同步，读写分离，分担读压力
- 缺陷：主节点宕机后无法自动切换，存在单点故障

### 4.5.2 哨兵模式（Sentinel）
在主从基础上增加哨兵集群：
- 自动监控主从节点健康状态
- 主节点宕机自动**故障转移**，选举新主节点
- 实现半自动高可用，适合中小型项目

### 4.5.3 集群模式（Redis Cluster）
- 分片存储，数据分散到多个节点
- 横向扩容，突破单节点内存与并发上限
- 自带高可用，分片节点互相备份，适合大规模分布式项目

## 4.6 性能优化保障
### 4.6.1 基础使用优化
1. 避免使用 `keys *`、`hgetall` 等全量遍历命令
2. 批量操作使用 `mset/mget` 代替多次单条命令
3. 合理设置 key 过期时间，避免大量 key 集中过期

### 4.6.2 内存优化
1. 合理设计 key 命名，缩短 key 长度
2. 热点小对象优先使用 Hash 压缩存储
3. 定时清理过期无效缓存，减少内存碎片

### 4.6.3 并发性能优化
1. 合理配置连接池参数，避免频繁创建销毁连接
2. 利用单线程多路复用特性，避免大耗时命令
3. 读写分离：主写从读，分摊高并发读请求

### 4.6.4 慢查询日志
开启慢日志监控，记录执行耗时过长的命令，定位性能瓶颈。

---

## 4.7 缓存三大问题解决方案（业务层安全）
1. **缓存穿透**
   空值缓存、布隆过滤器、接口参数校验、黑名单拦截
2. **缓存击穿**
   热点 key 永不过期、分布式锁、缓存预热
3. **缓存雪崩**
   过期时间加随机值、集群高可用、服务降级、限流熔断

---

## 4.8 本章小结
1. 数据安全核心依靠 **RDB+AOF 持久化**，解决宕机数据丢失；
2. **内存淘汰策略** 避免内存溢出，保证服务不崩溃；
3. 密码、IP 白名单、禁用高危命令，加固 Redis 访问安全；
4. 主从、哨兵、集群 三层架构，逐级提升高可用能力；
5. 合理命令使用、内存管控、读写分离，全方位保障高性能；
6. 必须处理穿透、击穿、雪崩三大经典缓存问题，保证业务稳定。
