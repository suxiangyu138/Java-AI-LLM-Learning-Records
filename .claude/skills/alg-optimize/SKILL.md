# Alg Optimize：TLE 定位与优化

算法题超时（TLE）的系统化诊断与优化——**先定位根源，再给方案**。

## 核心流程

```text
1. 复现并确认：真的是 TLE？（还是死循环/输入读取问题）
2. 复杂度分析：当前实现的时间/空间复杂度，对照数据范围算理论上限
   ── 数据范围 n 决定可接受复杂度：
       n ≤ 10^4   → O(n²) 勉强，优先 O(n log n)
       n ≤ 10^5   → O(n log n) 标准
       n ≤ 10^6   → O(n) 或 O(n log n)
       n ≤ 10^9   → O(log n) 或 O(1)
3. 定位热点：哪一步是瓶颈（循环嵌套？集合操作？递归？）
4. 给出优化方案 + 复杂度对比表
5. 提供优化后代码（简洁、可直接提交）
```

## 优化手段速查表

| 瓶颈模式 | 优化手段 | 复杂度变化 |
|---------|---------|-----------|
| 双重循环查找 | HashMap 空间换时间 | O(n²) → O(n) |
| 有序数组查找 | 二分查找 | O(n) → O(log n) |
| 区间和查询 | 前缀和/差分数组 | O(n) → O(1) 查询 |
| 滑动窗口类 | 双指针（左右指针） | O(n²) → O(n) |
| 排序后操作 | 先排序（Arrays.sort） | 为 O(n log n) 打底 |
| 重复子问题 | 记忆化/DP（自底向上） | 指数 → 多项式 |
| 大数运算 | 预处理/取模技巧 | 防溢出 + 省时间 |
| 图遍历 | BFS 分层/visited 剪枝 | 防重复访问 |
| 递归爆栈 | 迭代化/尾递归 | 防栈溢出 TLE |

## 输出格式

```markdown
## TLE 诊断：{题目}

### 根源分析
- 数据范围：n = {范围}
- 当前复杂度：O({...})，理论上限 O({...})
- 瓶颈：{定位}

### 优化方案
| 步骤 | 做法 | 效果 |
|------|------|------|
| 1 | ... | O(n²) → O(n) |

### 优化后代码
（简洁实现，可直接提交）

### 避坑提醒
- 输入用 BufferedReader/Scanner 差异（Java）
- 频繁打印用 StringBuilder 合并输出
```

## Java 特定优化（用户是 Java 选手）

```text
- 输入：BufferedReader + StringTokenizer（Scanner 慢 5-10 倍）
- 输出：StringBuilder 一次性打印（System.out.println 每条都慢）
- 集合：int[] 优先于 List<Integer>（自动装箱开销大）
- 排序：Arrays.sort 原生类型（快于对象排序）
- 位运算：x & 1 判奇偶、x << 1 乘 2（微优化，最后考虑）
```

## 禁忌

- 禁止不分析复杂度直接改代码
- 禁止"加个缓存试试"式乱试——必须说明为什么能优化
- 禁止用大常数换时间（如过度预分配）——要真正降低复杂度
