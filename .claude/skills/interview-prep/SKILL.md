# Interview Prep：大厂面试题生成

把用户指定的知识点/主题，转化为**对标大厂面试标准**的问答清单。

## 触发场景

- 用户说"给我出面试题"、"这个知识点面试怎么问"、"整理面试笔记"
- 用户学习完一个主题后要求输出面试弹药
- 秋招冲刺阶段的任何知识点复习

## 输出规范

1. **四档分类**（严格按此分档）：
   - 基础概念档：定义/原理类，30-60 秒回答
   - 工程实践档：做过没，回答要求"我遇到过 → 怎么定位 → 怎么修 → 怎么防"
   - 架构设计档：设计权衡，面试官会追问"为什么不用另一个方案"
   - 算法档（仅算法主题）：复杂度分析 + 优化路径

2. **每题结构**：题目 + 答题要点（表格列要点，不是长篇答案）+ 追问提示

3. **格式**：Markdown 表格优先；要点 ≤5 条/题；可背诵、可复用

4. **深度要求**：
   - 覆盖边界与异常（面试官必问"如果…会怎样"）
   - 写清权衡取舍（为什么这么设计）
   - 2026 现状优先（版本、新特性——写前先 WebSearch 验证时效）

## 流程

```text
1. 明确知识点范围（用户指定或从仓库知识体系抽取）
2. WebSearch 校验最新版本/事实（绝不凭记忆输出版本号）
3. 按四档生成题目（每档至少 3 题，共 12-15 题）
4. 每题附答题要点表 + 追问方向
5. 输出前自检：每题能否 60 秒答完要点？不能 → 精简
```

## 输出模板

```markdown
## 面试题：{主题}

### 基础概念档
| # | 题目 | 答题要点（30-60s） |
|---|------|------------------|

### 工程实践档
| # | 题目 | 答题要点（遇到过→定位→修→防） |
|---|------|----------------------------|

### 架构设计档
| # | 题目 | 答题要点 + 面试官追问点 |
|---|------|----------------------|

### 追问速查
面试官最可能的追问与应答（3-5 条）
```

## 禁忌

- 禁止空洞概念题（"讲一下 X"）——必须带场景或对比
- 禁止过时版本信息——先搜索再写
- 禁止长篇大论——每条要点 ≤20 字，可直接背诵
