# Doc Quality：文档质量校验

对 Markdown 文档/知识体系做全面质量校验（格式层 + 内容层 + 用户风格），输出问题清单。

## 一、格式层校验项（脚本可查）

| 项 | 检查内容 | 失败示例 |
|----|---------|---------|
| 代码围栏 | ` ``` ` 数量成对、语言标注齐全 | 围栏余数 1 |
| 内部链接 | 相对路径链接目标存在（含 `%20` 解码）；跨目录层级正确 | 少一级 `../` |
| TOC 锚点 | 目录锚点与标题匹配（小写、空格→`-`、去标点） | `#5-xxx` 对不上标题 |
| 表格 | 无孤立分隔行；表头下紧跟 `|---|`；列数一致 | 分隔行无表头 |
| 导航 | 非首篇有「返回总览」，非末篇有「下一模块」 | 缺导航 |
| 链接编码 | 含空格的文件名链接用 `%20` 编码 | `01-xxx 篇.md` 未编码 |
| 参考来源 | 每条带 URL 超链接 + **每条独立一行**（2026-08-10 用户要求） | 顿号堆叠 / 纯文本 |
| 标题空格 | `#`/`-`/`1.` 后必须有空格 | `#标题` / `-条目` |
| 标题跳级 | `#` → `###` 跳级；标题重名（锚点冲突） | 跳过二级 |
| 成对符号 | `**`/反引号成对闭合 | `**内容*` 大片变粗 |
| 大小写路径 | 链接目标文件名大小写与磁盘一致（**GitHub Linux 区分大小写**） | `./jvm.md` vs `JVM.md` |
| 块元素空行 | 标题/表格/列表前后必须空行（GitHub 渲染） | VSCode 正常 GitHub 合并 |
| 章节编号 | `## N.` 编号唯一、连续顺延 | 编号重复/跳号 |
| 孤立短段 | 正文段 <45 字且语义断裂（拆分脚本副作用） | 孤句段 |
| 句尾标点 | 正文段以句号结尾；代码块/ASCII/目录/标题行不加 | 判断句缺句号 |

## 校验脚本

对单个文件或整个目录运行：

```bash
# 单文件围栏检查
grep -c '^```' "文件.md"   # 结果应为偶数

# 目录全量校验（链接/锚点/导航）
python -c "
import re, urllib.parse
from pathlib import Path
base = Path('.')
for f in sorted(base.glob('*.md')):
    text = f.read_text(encoding='utf-8')
    # 围栏
    fences = len(re.findall(r'^\`\`\`', text, re.M))
    if fences % 2: print(f'{f.name}: 围栏不成对 ({fences})')
    # 内部链接存在性
    for m in re.finditer(r'\]\(([^)]+)\)', text):
        link = m.group(1)
        if link.startswith(('http','#','mcp')) or '://' in link: continue
        path_part = urllib.parse.unquote(link.split('#')[0])
        if path_part and not (f.parent / path_part).resolve().exists() and not (base / path_part).resolve().exists():
            print(f'{f.name}: 链接缺失 -> {link}')
    # 锚点
    if '## 📚 目录' in text:
        toc = text.split('## 📚 目录')[1].split('## 1.')[0]
        headers = re.findall(r'^#{1,3} (.+)$', text, re.M)
        for a in re.findall(r'\]\(#([^)]+)\)', toc):
            if not any(a == re.sub(r'[^\w一-鿿 -]','',h).lower().replace(' ','-') for h in headers):
                print(f'{f.name}: 锚点缺失 #{a}')
print('校验完成')
"
```

## 二、内容层校验项（人工过清单，2026-08-10 用户方案）

| 维度 | 检查内容 |
|------|---------|
| 事实 | API/参数/概念与官方一致？版本限制标注（哪些版本生效）？张冠李戴？ |
| 逻辑 | 前后矛盾？缺前提条件（结论写清适用范围）？边界/不支持场景写明？ |
| 术语 | 同一概念全文同一名词？无口语化模糊（量化 TP99/QPS 替代"很快"）？拼写正确？ |
| 示例 | 代码可复制运行？无隐藏 bug？输入输出对得上？ |
| 陈旧 | 过时方案标【废弃】？链接有效？ |
| 体验 | 长段拆分有小标题？重点提炼？跨章节无重复？ |
| 受众 | 面向读者的术语解释到位？不堆砌基础科普/黑话？ |

## 三、用户风格要求（2026-08-10 汇总）

- 知识体系统一 **10 篇正文 + 00 总览 = 11 篇**（见 memory `documentation-structure-standard`）
- 单篇约 **2000 中文字符**（1600-2500 通过线）
- **长段落必须换行分句**（单段 >150-200 字按逻辑断点拆分，多要点用分段而非长句堆叠）
- 参考来源**每条独立一行**（论文参考文献风格）
- 排版六要素（标题层级/间距/强调/表格/代码/列表）见 memory `enterprise-doc-quality-standard`
- 读者视角：无需找作者即可看懂/决策/复现/排错（memory `high-quality-doc-standard`）

## 修复规则

- 链接缺失 → 先 `ls` 确认真实文件名/层级，再修正（不猜）
- 锚点不匹配 → 以标题实际生成规则为准修正 TOC
- 围栏不成对 → 定位缺失的 ``` 行
- 大小写路径 → 以磁盘实际文件名修正（`ls` 确认，不猜）
- 孤句段/断段 → 读上下文判断合并（语义断裂才合并，引导句不动）
- 缺句号/多句号 → 正文段补、代码块/ASCII/目录/标题行不加

## 禁忌

- 禁止"看起来没问题"就跳过——必须跑脚本
- 禁止凭印象修链接——先确认目标文件真实存在
- 禁止只查格式不查内容——内容层清单（事实/逻辑/术语/示例）必须人工过一遍
- 禁止只看源码——**必须看渲染效果**（GitHub 渲染与本地预览有差异：大小写路径、块元素空行）
