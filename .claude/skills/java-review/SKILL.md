# Java Review：P3C 规范代码审查

对 Java 代码做规范 + 性能 + 安全的综合审查，输出问题清单。

## 审查维度

| 维度 | 检查项 | 典型问题 |
|------|--------|---------|
| 规范（P3C） | 命名/常量/集合/异常/并发规范 | 魔法值、`new HashMap()` 无容量、catch 吞异常 |
| 性能 | 复杂度/循环/IO/集合选型 | 循环内查询 DB、`String +` 拼接、`contains` 用 List |
| 冗余 | 重复代码/无效代码/过度设计 | 复制粘贴逻辑、未使用变量、多层无用封装 |
| 并发 | 线程安全/锁粒度/并发集合 | HashMap 并发写、synchronized 过大、线程池不当 |
| 边界 | 空指针/越界/资源泄漏 | 未判空、流未关闭、数组越界 |

## 输出格式

```markdown
## 审查结果：{文件/模块}

| # | 位置(行号) | 严重级 | 问题 | 规范依据 | 修复方案 |
|---|-----------|:---:|------|---------|---------|
| 1 | OrderService.java:42 | P0 | ... | P3C [强制] ... | ... |

### 修复建议优先级
P0（必修）→ P1（建议）→ P2（可选）
```

## 审查流程

```text
1. 读代码，先建立数据流与调用链
2. 逐维度检查（规范→性能→冗余→并发→边界）
3. 性能问题先算复杂度（用户强调规避 TLE——循环嵌套/集合操作必须算）
4. 输出问题清单，按严重级排序
5. 每个问题给出可复制的修复代码（简洁少注释，符合用户偏好）
```

## 重点检查清单（P3C 高频）

```text
□ 魔法值：常量类/枚举替代
□ 集合：指定初始容量；遍历删除用 Iterator.remove()
□ 异常：不 catch Exception 后吞掉；finally 释放资源/TWR
□ 并发：HashMap→ConcurrentHashMap；线程池不用 Executors 快捷方法
□ 字符串：循环拼接用 StringBuilder
□ 判空：Objects.requireNonNull / 防御式编程
□ 日期：java.time 替代 Date/SimpleDateFormat
```

## 禁忌

- 禁止只报问题不给修复方案
- 禁止误报——不确定的标注"待确认"
- 禁止改用户代码——只输出审查报告与建议
