### 1.2 视图容器组件完全指南

| 组件 | 功能 | 核心属性 | 注意点 |
|------|------|---------|--------|
| `view` | 基本容器 | hover-class、hover-start-time | 替代 div，默认 flex |

### 1.10 数据缓存详解

| API | 特征 | 建议场景 |
|-----|------|---------|
| `wx.setStorageSync(key, data)` | 同步、阻塞 | 写入小数据量、初始化配置 |
| `wx.setStorage(key, data)` | 异步、非阻塞 | 写入大量数据 |
| `wx.getStorageSync(key)` | 同步读取 | token、用户信息等频繁读取 |
| `wx.getStorageInfoSync()` | 获取缓存占用 | 检查存储空间 |

```javascript
// 缓存策略示例
function saveWithExpiry(key, data, ttlMinutes = 30) {
  const payload = {
    data,
    expiry: Date.now() + ttlMinutes * 60 * 1000
  };
  wx.setStorageSync(key, payload);
}

function getWithExpiry(key) {
  const payload = wx.getStorageSync(key);
  if (!payload) return null;
  if (Date.now() > payload.expiry) {
    wx.removeStorageSync(key);
    return null;
  }
  return payload.data;
}
```

### 1.14 wxs 过滤器与增强

```xml
<wxs module="helper">
  // 1. 日期格式化
  function dateFormat(ts, fmt) {
    var date = getDate(ts * 1000);
    var o = {
      'Y+': date.getFullYear(),
      'M+': date.getMonth() + 1,
      'D+': date.getDate(),
      'h+': date.getHours(),
      'm+': date.getMinutes(),
      's+': date.getSeconds()
    };
    for (var key in o) {
      if (new RegExp('(' + key + ')').test(fmt)) {
        fmt = fmt.replace(RegExp.$1, o[key].toString().padStart(2, '0'));
      }
    }
    return fmt;
  }

  // 2. 金额格式化
  function currency(num) {
    return '¥' + num.toFixed(2);
  }

  // 3. 字符串截断
  function truncate(str, len) {
    if (str.length <= len) return str;
    return str.substring(0, len) + '...';
  }

  module.exports = { dateFormat: dateFormat, currency: currency, truncate: truncate };
</wxs>

<view>创建时间：{{ helper.dateFormat(item.createdAt, 'YYYY-MM-DD hh:mm') }}</view>
<view>金额：{{ helper.currency(item.price) }}</view>
```

## 二、深度原理剖析

### 2.1 小程序组件系统（Exparser）

小程序使用自研 **Exparser** 组件系统，基于 Shadow DOM 概念但经过简化：

**组件树的构建过程**：
```
WXML 编译 → 解析为 JSON 节点树 → 创建组件实例 → 建立父子关系树
                                                      ↓
                                              注入数据 → 渲染
```

**Exparser 特点**：
- 每个组件独立作用域（样式隔离 + 数据隔离）
- 使用 `relations` 实现组件间嵌套关系管理
- 组件节点不暴露真实 DOM，通过组件实例 API 访问

```javascript
// relations 组件关系
Component({
  relations: {
    '../parent/parent': {
      type: 'parent',
      linked(target) { console.log('子组件找到父组件', target); },
      unlinked(target) { console.log('子组件移除父组件关联'); }
    }
  }
});
```

### 2.2 setData 的虚拟节点对比机制

小程序渲染层内部维护一棵 **虚拟节点树（Virtual Node Tree）**，setData 更新过程：

```
逻辑层：
  setData({ name: '张三' })
  → JSON 序列化（约 0.1-2ms）
  → 通过 JSBridge 发送到渲染层（约 0.5-5ms）

渲染层：
  → JSON 反序列化
  → 对比新旧虚拟节点树（diff 算法）
  → 生成 patch 更新包
  → 应用到真实节点树
  → 重排 (reflow) + 重绘 (repaint)
```

**性能关键数据**：
- 单次 setData 数据量：建议 < 64KB，上限 1MB
- 高频阈值：> 60 次/秒 明显卡顿
- 传输路径：逻辑层内存 → JSON字符串 → 微信客户端 Native → WebView 内存

### 2.3 WXS 与 JavaScript 的本质区别

| 维度 | WXS | JavaScript |
|------|-----|-----------|
| 运行环境 | 渲染层（WebView） | 逻辑层（JSCore/V8） |
| ES6+ | 不支持（仅 ES5） | 支持 |
| DOM API | 无 | 无（小程序环境） |
| Web API | 无 | 无 |
| 与 WXML 交互 | 可直接参与模板计算 | 只能通过 setData |
| 模块化 | `module.exports` | CommonJS / ES Module |
| 定时器 | `setTimeout` 不准确 | 准确 |
| 异常捕获 | 不支持 try-catch | 支持 |
| 作用域 | 函数级 var | let/const 块级 |

**适用场景**：
- 价格格式化、时间格式化、文本截断、列表过滤
- 高频滚动事件处理（通过 WXS 响应事件代替 setData）
- 复杂模板表达式中不适合放在 JS 层处理的计算

```javascript
// WXS 中不支持的写法
// ❌ let a = 1
// ❌ const fn = () => {}
// ❌ try { ... } catch(e) { ... }
// ❌ new Map(), new Set()
// ❌ Array.prototype.includes
// ❌ Object.entries

// ✅ 支持的写法
// var a = 1
// function fn() {}
// Array.prototype.forEach / map / filter / indexOf
// Object.keys / stringify / parse
```

### 2.4 事件传递与 currentTarget vs target

```xml
<view bindtap="onTap" data-parent="outer">
  <button data-child="inner">点击</button>
</view>
```

```javascript
Page({
  onTap(e) {
    // target: 触发事件的原始组件（button）
    console.log(e.target.dataset);      // { child: 'inner' }
    // currentTarget: 绑定事件处理函数的组件（view）
    console.log(e.currentTarget.dataset); // { parent: 'outer' }
  }
});
```

**两者关键区别**：

| 属性 | target | currentTarget |
|------|--------|---------------|
| 指向 | 用户触摸的原始节点 | 绑定事件处理函数的节点 |
| 冒泡时 | 不变（始终原始节点） | 变化（当前冒泡到的节点） |
| 数据来源 | e.target.dataset | e.currentTarget.dataset |

### 4.1 封装 Http 请求类（含拦截器）

```javascript
// utils/http.js
class HttpClient {
  constructor(baseURL) {
    this.baseURL = baseURL;
    this._interceptors = {
      request: [],
      response: []
    };
  }

  // 注册拦截器
  use(type, handler) {
    if (this._interceptors[type]) {
      this._interceptors[type].push(handler);
    }
  }

  request(method, url, data = {}) {
    // 请求前拦截器链
    let config = { method, url: this.baseURL + url, data, header: this._defaultHeader() };
    for (const interceptor of this._interceptors.request) {
      config = interceptor(config) || config;
    }

    return new Promise((resolve, reject) => {
      wx.request({
        ...config,
        success: (res) => {
          let result = res.data;
          // 响应后拦截器链
          for (const interceptor of this._interceptors.response) {
            result = interceptor(result) || result;
          }
          resolve(result);
        },
        fail: (err) => reject(err)
      });
    });
  }

  _defaultHeader() {
    const token = wx.getStorageSync('token');
    const header = { 'Content-Type': 'application/json' };
    if (token) header['Authorization'] = `Bearer ${token}`;
    return header;
  }

  get(url, data) { return this.request('GET', url, data); }
  post(url, data) { return this.request('POST', url, data); }
}

// 导出单例
const http = new HttpClient('https://api.example.com');

// 使用拦截器处理 token 过期
http.use('response', (res) => {
  if (res.code === 401) {
    wx.removeStorageSync('token');
    wx.navigateTo({ url: '/pages/login/login' });
    return null;
  }
  return res;
});

module.exports = http;
```

```javascript
// utils/tools.js
function deepClone(obj) {
  if (typeof obj !== 'object' || obj === null) return obj;
  if (Array.isArray(obj)) return obj.map(deepClone);
  const result = {};
  for (const key in obj) {
    if (Object.prototype.hasOwnProperty.call(obj, key)) {
      result[key] = deepClone(obj[key]);
    }
  }
  return result;
}

// 找出两个对象的差异路径（用于 setData 增量更新）
function diff(oldObj, newObj, path = '') {
  let changes = {};
  for (const key in newObj) {
    if (!Object.prototype.hasOwnProperty.call(oldObj, key)) {
      changes[path + key] = newObj[key];
    } else if (JSON.stringify(oldObj[key]) !== JSON.stringify(newObj[key])) {
      if (typeof newObj[key] === 'object' && newObj[key] !== null
          && typeof oldObj[key] === 'object' && oldObj[key] !== null) {
        const nested = diff(oldObj[key], newObj[key], path + key + '.');
        changes = { ...changes, ...nested };
      } else {
        changes[path + key] = newObj[key];
      }
    }
  }
  return changes;
}

module.exports = { deepClone, diff };
```

### 5.2 设计小程序的离线缓存策略

**目标**：在无网络或弱网络下提供基本可用体验。

```
首次访问 → 下载数据 → 写入本地缓存（含过期时间）
   ↓
再次访问 → 读取缓存 → 立即展示（秒开）
   ↓
请求网络 → 新数据 → 更新缓存 + 更新视图
   ↓
请求失败 → 展示缓存数据 + 提示"网络异常"
```

```javascript
// 缓存管理器
class CacheManager {
  constructor() {
    this.namespace = 'cache_v1';
  }

  get(key) {
    const raw = wx.getStorageSync(`${this.namespace}_${key}`);
    if (!raw) return null;
    try {
      const parsed = JSON.parse(raw);
      if (parsed.expiry && Date.now() > parsed.expiry) {
        wx.removeStorageSync(`${this.namespace}_${key}`);
        return null;
      }
      return parsed.data;
    } catch { return null; }
  }

  set(key, data, ttl = 30 * 60 * 1000) {
    wx.setStorageSync(`${this.namespace}_${key}`, JSON.stringify({
      data,
      expiry: Date.now() + ttl
    }));
  }

  // 网络请求 + 缓存策略
  async fetchWithCache(url, data, ttl = 30 * 60 * 1000) {
    const cacheKey = url + JSON.stringify(data);
    const cached = this.get(cacheKey);
    if (cached) return cached;  // 先返回缓存

    try {
      const freshData = await http.get(url, data);
      this.set(cacheKey, freshData, ttl);
      return freshData;
    } catch (err) {
      if (cached) return cached; // 网络失败且有缓存时返回缓存
      throw err;
    }
  }
}
module.exports = new CacheManager();
```

| setData 数据量过大 | 页面卡顿或白屏 | 单次传输超过 1MB | 分批传输，用路径表达式只更新变化部分 |
| setData 在 onLoad 中多次调用 | 页面初始化慢 | 多次跨线程通信 | 合并为一次 setData |
| image src 为空或 404 | 显示默认裂图 | 图片地址异常 | 使用 binderror 事件设置 fallback 图 |
| navigatorTo 超过 10 层 | 跳转无响应 | 页面栈最大 10 层 | 超 8 层改用 redirectTo 或 reLaunch |
| 组件样式被污染 | 全局样式影响组件 | 未启用样式隔离 | 设置 styleIsolation: 'isolated' |
| canvas 内容模糊 | 绘制内容不清晰 | 物理像素与逻辑像素不匹配 | 使用 dpr 缩放 canvas |
| wx.getStorage 在低版本闪退 | 存储满时崩溃 | 低版本 IOS 存储容量小 | 使用 try-catch 包裹 |
| wx.request 在真机不生效 | 接口请求失败 | 域名未配置白名单 | 微信公众平台配置合法域名 |
| IOS 底部内容被手势条遮挡 | 底部按钮看不到 | 未适配安全区域 | 使用 `safe-area-inset-bottom` |
| this 指向错误 | 回调中 this 变成 undefined | 作用域丢失 | 使用箭头函数或 `that = this` |
| async/await 语法报错 | 低版本基础库不支持 | ES6 语法兼容性问题 | 使用 Generator 或降低基础库版本 |

## 七、面试回答模板

### Q1: 小程序的 setData 和 Vue/React 的数据驱动有什么区别？

> Vue 和 React 都是在同一个线程中进行虚拟 DOM diff 和 DOM 更新，setData 则需要跨线程通信（逻辑层→Native→渲染层），而且传递的数据需要 JSON 序列化，性能和频率都受限。所以小程序有更严格的性能约束：单次 setData 不超过 1MB，避免高频调用。而 Vue/React 没有这种跨线程限制，更新频率和数据量可以更大。这也是为什么小程序需要 WXS 来处理高频更新的原因——WXS 运行在渲染层，不需要跨线程通信。
>
> 相同点是都是数据驱动视图变化，都支持 diff 机制避免全量渲染。

### Q2: 小程序的自定义组件和页面的区别？

> 小程序中页面可以理解为特殊的组件，但有几点关键区别：
>
> 第一，**路由能力**不同：页面可以通过 wx.navigateTo 等路由 API 跳转，组件不能。
>
> 第二，**生命周期**不同：页面有 onLoad/onShow/onHide/onPullDownRefresh 等页面级生命周期，组件有 created/attached/ready/detached 等组件级生命周期。
>
> 第三，**配置方式**不同：页面的 .json 配置可以设置导航栏、下拉刷新等页面行为，组件的 .json 需要声明 `"component": true` 并支持 styleIsolation 和 multipleSlots。
>
> 第四，**复用范围**不同：页面只能作为入口被路由调用，组件可以在其他页面和组件中多次复用。

### Q3: 小程序的渲染流程是怎样的？

> 小程序的渲染分为初始渲染和更新渲染。初始渲染时，逻辑层将页面数据和模板路径传递给渲染层，渲染层解析 WXML 和 WXSS 生成节点树，然后渲染页面。更新渲染时，逻辑层调用 setData 传递变化的数据，渲染层接收到数据后进行 diff 对比，只更新变化的节点。整个过程是异步的，逻辑层不会等待渲染层完成。
>
> 正因如此，在 setData 后立即获取节点位置是不准确的，需要在 nextTick 或 setTimeout 中执行。

### Q4: wx:if 和 hidden 如何选择？

> 这要看具体的需求场景。
>
> wx:if 是条件渲染，条件为假时不创建节点。它的初始化成本低（不渲染），但切换成本高（创建/销毁节点）。适合初始时条件确定的场景，比如用户身份不同展示不同页面。
>
> hidden 始终渲染节点，通过 display:none 控制显示。它的初始化成本高（始终渲染），但切换成本低（仅修改 display 属性）。适合需要频繁切换显示隐藏的场景，比如 Tab 切换。
>
> 简单来说：初始化时条件明确、不频繁切换的用 wx:if；需要频繁切换显示的用 hidden。

### Q5: 小程序分包加载有什么好处？怎么用？

> 分包加载的好处有三点：
>
> 第一，**缩小主包体积**，主包控制在 2MB 以内，冷启动更快。第二，**按需加载**，用户访问分包页面时才下载对应代码，节省流量。第三，**总包可达 20MB**，突破了主包 2MB 的限制。
>
> 用法是在 app.json 中配置 subpackages 字段，将非核心功能页面放入分包。还可以用 preloadRule 配置预加载策略，比如在首页时提前预下载订单分包，提升用户访问订单页时的打开速度。主包最好只包含首页、TabBar 页面和公共组件/工具库。
