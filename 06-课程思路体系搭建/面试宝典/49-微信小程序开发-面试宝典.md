## 一、基础概念速答

### 1.1 小程序文件结构与配置

四个同名文件组成一个页面：`.wxml`（模板）、`.wxss`（样式）、`.js`（逻辑）、`.json`（配置）。全局配置在 `app.json` 中声明页面路径、窗口样式、tabBar 等。

```json
{
  "pages": ["pages/index/index", "pages/category/category"],
  "window": {
    "navigationBarBackgroundColor": "#07c160",
    "navigationBarTitleText": "商城",
    "enablePullDownRefresh": true
  },
  "tabBar": {
    "color": "#999",
    "selectedColor": "#07c160",
    "list": [
      { "pagePath": "pages/index/index", "text": "首页", "iconPath": "images/home.png" },
      { "pagePath": "pages/cart/cart", "text": "购物车", "iconPath": "images/cart.png" }
    ]
  },
  "subpackages": [
    { "root": "packageA", "pages": ["pages/order/order"] }
  ]
}
```

> 💡 `project.config.json` 是开发者工具配置，`sitemap.json` 控制搜索索引规则。

### 1.2 应用/页面/组件生命周期

| 层级 | 函数 | 触发时机 | 高频用途 |
|------|------|---------|---------|
| App | `onLaunch` | 小程序初始化完成（全局一次） | 获取设备信息、登录检查 |
| App | `onShow` | 从后台切到前台 | 检查更新、恢复状态 |
| App | `onHide` | 从前台切到后台 | 保存草稿、暂停播放 |
| Page | `onLoad(query)` | 页面加载 | 接收路由参数、发起首页请求 |
| Page | `onShow` | 页面显示（含返回） | 刷新数据（如购物车角标） |
| Page | `onReady` | 首次渲染完成 | 创建 canvas、SelectorQuery |
| Page | `onHide` | 页面隐藏 | 暂停动画、释放资源 |
| Page | `onUnload` | 页面卸载 | 清理定时器、EventBus 解绑 |
| Page | `onReachBottom` | 上拉触底 | 加载下一页数据 |
| Page | `onPullDownRefresh` | 下拉刷新 | 刷新当前页数据 |
| Component | `created` | 组件实例创建 | 初始化内部数据 |
| Component | `attached` | 挂载到页面树 | 发起数据请求 |
| Component | `ready` | 组件渲染完成 | 操作子组件 |
| Component | `detached` | 从页面树移除 | 清理资源 |

```javascript
Page({
  onLoad(query) {
    console.log('路由参数:', query.id); // 从 navigateTo url 获取
  },
  onShow() {
    this.refreshCartBadge(); // 每次页面显示刷新购物车角标
  }
});
```

### 1.3 WXML 数据绑定与指令系统

```xml
<!-- 数据绑定 -->
<view>{{ message }}</view>
<view id="item-{{id}}"></view>
<image src="{{imageUrl}}?x-oss-process=style/thumb" />

<!-- 条件渲染 -->
<view wx:if="{{type === 'A'}}">类型A</view>
<view wx:elif="{{type === 'B'}}">类型B</view>
<view wx:else>其他</view>

<!-- ⚠️ wx:if 惰性渲染（false 时不创建节点），适合低频率切换 -->
<!-- 💡 hidden 始终渲染（display:none），适合高频切换 -->

<!-- 列表渲染 -->
<view wx:for="{{list}}" wx:for-item="item" wx:for-index="idx" wx:key="id">
  {{idx + 1}}. {{item.name}}
</view>
```

> 🎯 `wx:key` 必须绑定，原因类似 React 的 key，用于帮助框架识别节点复用，提升 diff 性能。可使用数组项的 `id` 或 `*this`（当数组为基本类型时）。

### 1.4 事件系统：bind vs catch

| 绑定方式 | 冒泡行为 | 典型场景 |
|---------|---------|---------|
| `bind:tap` | 允许冒泡 | 普通点击事件 |
| `catch:tap` | 阻止冒泡 | 阻止事件穿透（如弹窗内点击不触发背景） |
| `capture-bind:tap` | 捕获阶段监听 | 全局手势拦截 |
| `capture-catch:tap` | 捕获阶段并阻止 | 完全阻止事件向子节点传递 |

```xml
<view bindtap="outer">
  外层
  <view catchtap="inner">内层（点击不会触发 outer）</view>
</view>

<!-- 事件传参通过 data-* 属性 -->
<button data-id="{{item.id}}" data-index="{{index}}" bindtap="onItemClick">点击</button>
```

```javascript
Page({
  onItemClick(e) {
    const { id, index } = e.currentTarget.dataset; // 注意是 currentTarget
    console.log('参数:', id, index);
  }
});
```

### 1.5 路由跳转方式

| API | 页面栈行为 | 关闭当前页 | 动画 |
|-----|-----------|-----------|------|
| `wx.navigateTo` | 推入新页面 | 否（保留） | 从右滑入 |
| `wx.redirectTo` | 替换当前页 | 是 | 从右滑入 |
| `wx.switchTab` | 切换到 tab 页 | 关闭所有非 tab 页 | 无动画 |
| `wx.navigateBack` | 返回上一页 | 是（可指定 delta） | 从左滑出 |
| `wx.reLaunch` | 重新启动 | 关闭所有页面 | 无动画 |

**页面栈限制：最大 10 层。** 超过时 navigateTo 静默失败。

```javascript
// 获取当前页面栈
const pages = getCurrentPages();
if (pages.length >= 8) {
  wx.redirectTo({ url: '/pages/order/order' }); // 超过 8 层改用替换
} else {
  wx.navigateTo({ url: '/pages/order/order' });
}
```

### 1.6 `wx.request` 网络请求

```javascript
wx.request({
  url: 'https://api.example.com/goods/list',
  method: 'POST',
  data: { page: 1, size: 20 },
  header: {
    'Content-Type': 'application/json',
    'Authorization': `Bearer ${wx.getStorageSync('token')}`
  },
  timeout: 5000,
  success: (res) => { console.log('成功:', res.data); },
  fail: (err) => { wx.showToast({ title: '网络异常', icon: 'none' }); }
});
```

> ⚠️ **域名白名单**：request、uploadFile、downloadFile 等域名必须在小程序后台配置，否则开发工具可忽略校验，但真机环境会拦截。2023 年起新创建的小程序默认开启 HTTPS。

### 1.7 `wx.login` 与登录流程

```javascript
wx.login({
  success: (res) => {
    if (res.code) {
      wx.request({
        url: 'https://api.example.com/wx/login',
        method: 'POST',
        data: { code: res.code },
        success: (resp) => {
          const { token } = resp.data;
          wx.setStorageSync('token', token);
        }
      });
    }
  }
});
```

**完整流程**：`wx.login()` 获取临时 code（5分钟有效）→ 传给后端 → 后端调 `auth.code2Session` 获取 `openid + session_key` → 后端生成自定义 token → 前端存储 token 并在后续请求中携带。

```xml

```


### 1.9 `wx.requestPayment` 微信支付

```javascript
wx.requestPayment({
  timeStamp: '1711123456',          // 时间戳（字符串）
  nonceStr: 'random123',            // 随机字符串
  package: 'prepay_id=wx...',       // 统一下单返回的 prepay_id
  signType: 'RSA',                  // 签名类型
  paySign: 'signature...',          // 签名
  success: () => { wx.showToast({ title: '支付成功' }); },
  fail: (err) => {
    if (err.errMsg.includes('cancel')) {
      wx.showToast({ title: '用户取消支付', icon: 'none' });
    }
  }
});
```

> 🎯 **支付流程**：前端创建订单 → 后端调微信统一下单 API 获取 prepay_id → 后端生成签名参数返回前端 → 前端调 requestPayment 发起支付。

### 1.10 组件通信方式

| 方式 | 方向 | 使用方法 |
|------|------|---------|
| `properties` | 父→子 | 父组件传递属性，子组件通过 `properties` 接收 |
| `triggerEvent` | 子→父 | 子组件触发自定义事件，父组件监听 |
| `selectComponent` | 父→子（方法调用） | `this.selectComponent('#child')` 获取子组件实例 |
| `app.globalData` | 全局 | 任意页面/组件通过 `getApp().globalData` 访问 |
| MobX store | 全局响应式 | `mobx-miniprogram-bindings` 自动绑定 |
| EventBus | 跨页面/组件 | 自定义事件发布订阅模式 |

```javascript

// <child name="{{name}}" bind:myevent="onChildEvent" />

// 子组件定义

  properties: { name: String },
  methods: {
    emitEvent() {
      this.triggerEvent('myevent', { result: '数据' });
    }
  }
});
```

### 1.13 WXS 脚本

```xml

    return '¥' + price.toFixed(2);
  }
  function formatDate(ts) {
    var date = getDate(ts * 1000);
```

## 二、深度原理剖析

### 2.1 双线程架构详解

小程序采用 **逻辑层（AppService）** + **渲染层（WebView）** 分离的双线程模型：

```
逻辑层（JSCore/V8 独立线程）        渲染层（多个 WebView 实例）
     ↓                                      ↑
     └─────── Native Bridge（JSBridge）───────┘
                   ↓        ↑
              Native 系统能力
         （网络/存储/定位/支付/蓝牙/...）
```

**为什么设计双线程？**
1. **性能隔离**：逻辑层 JS 执行不阻塞 UI 渲染线程
2. **安全隔离**：逻辑层无法直接操作 DOM，避免 XSS 注入
3. **页面独立**：每个页面独享 WebView，切换时保留状态
4. **能力统一**：通过 Native 桥提供一致的硬件能力调用

> 🎯 面试重点：setData 是跨线程通信，需要 JSON 序列化，成本和传输数据量成正比。

### 2.2 小程序启动流程（冷启动 vs 热启动）

**冷启动**（用户首次打开 / 微信杀死后打开）：
```
下载代码包 → 解压 → 初始化 JS 引擎
→ 读取 app.json 注册页面 → 执行 App.onLaunch
→ 根据启动路径打开页面 → Page.onLoad → onShow → onReady
```
**热启动**（从后台切回）：
```
恢复页面栈状态 → 执行 App.onShow → 各页面 onShow
```

> 💡 冷启动优化方向：分包加载、代码压缩、减少首屏请求数、使用骨架屏。

### 2.3 setData 的 diff 与批量更新机制

```javascript
// 小程序内部（概念性伪代码）
function setData(data) {
  const prevData = this._data;
  const diff = computeDiff(prevData, data);    // 1. diff 计算变化路径
  const serialized = JSON.stringify(diff);     // 2. JSON 序列化
  jsBridge.postMessage('updateView', serialized); // 3. JSBridge 传输
  // 渲染层收到后：
  // 4. JSON.parse 反序列化
  // 5. 根据变化路径更新对应节点
}
```

**性能优化原则**：
- 合并多次 setData 为一次（减少 JSBridge 调用次数）
- 只传输变化的属性（使用路径表达式 `'list[0].name'`）
- 单次数据量不超过 1MB
- 高频更新用 WXS 替代 setData

### 2.4 事件捕获与冒泡的完整流程

```
触摸事件传递分为三个阶段：
1. 捕获阶段（capture phase）    ← capture-bind / capture-catch
2. 目标阶段（target phase）
3. 冒泡阶段（bubble phase）     ← bind / catch
```

```xml
<view capture-bind:tap="onCapture1">
  <view capture-catch:tap="onCapture2">
    <button bindtap="onBubble">点击</button>
  </view>
</view>
<!-- 点击按钮：onCapture1 → onCapture2（capture-catch 阻止后续传递）→ 不会触发 onBubble -->
```

### 2.6 小程序更新机制

```javascript
const updateManager = wx.getUpdateManager();
updateManager.onCheckForUpdate((res) => {
  console.log('是否有新版本:', res.hasUpdate);
});
updateManager.onUpdateReady(() => {
  wx.showModal({
    title: '更新提示',
    content: '新版本已就绪，是否重启应用？',

      if (res.confirm) updateManager.applyUpdate();
```

> 💡 小程序更新是 **静默下载 + 下次冷启动生效** 机制。如需强制更新，使用 UpdateManager 弹窗提示用户重启。

### 2.8 自定义组件 observers 监听器

```javascript
Component({
  properties: {
    value: String
  },
  observers: {
    'value': function(newVal, oldVal) {
      console.log(`value 从 ${oldVal} 变为 ${newVal}`);
    },
    'a.b.c': function(newVal) {
      // 支持路径监听
    },

      // 通配符：任意数据变化都会触发
    }
  }

```

> 💡 `observers` 类似 Vue 的 watch，在数据变化时自动执行。但注意 observer 中不要修改自身的值，会导致死循环。

### 2.10 Uni-app / Taro 跨平台原理

| 框架 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| Uni-app | Vue 语法 + 编译时转换 | 生态丰富、HBuilder 工具链 | 性能不如原生 |
| Taro | React 语法 + 编译时+运行时适配 | 可复用 Web 组件 | 调试困难、包体积大 |

核心思路：**编译时转换**，将开发者写的 Vue/React 代码转换成小程序可识别的 WXML/WXSS/JS。

```javascript
  toggleItem(e) {
    const id = e.currentTarget.dataset.id;
    const cartList = this.data.cartList.map(item =>
      item.id === id ? { ...item, checked: !item.checked } : item
    );
    const allChecked = cartList.length > 0 && cartList.every(i => i.checked);
    this.setData({ cartList, allChecked });
    this.calcSummary();
  },

  changeCount(e) {
    const { id, delta } = e.currentTarget.dataset; // delta: +1 或 -1
    const cartList = this.data.cartList.map(item => {
      if (item.id === id) {
        const newCount = Math.max(1, Math.min(item.count + delta, item.stock));
        return { ...item, count: newCount };
      }
      return item;
    });
    this.setData({ cartList });
    this.calcSummary();
  },

  calcSummary() {
    const checkedItems = this.data.cartList.filter(i => i.checked);
    const totalCount = checkedItems.reduce((s, i) => s + i.count, 0);
    const totalPrice = checkedItems.reduce((s, i) => s + i.price * i.count, 0);
    this.setData({ totalCount, totalPrice: Math.round(totalPrice * 100) / 100 });
  },

  deleteItem(e) {

    wx.showModal({
      title: '提示',

      success: (res) => {
        if (res.confirm) {
          const cartList = this.data.cartList.filter(i => i.id !== id);
          this.setData({ cartList });
          this.calcSummary();
```

### 3.5 网络请求封装（含 token 刷新与错误处理）

```javascript
// utils/http.js
const BASE_URL = 'https://api.example.com';

function request(url, method, data) {
  return new Promise((resolve, reject) => {
    const token = wx.getStorageSync('token');
    wx.request({
      url: BASE_URL + url,
      method,
      data,
      header: {
        'Content-Type': 'application/json',
        'Authorization': token ? `Bearer ${token}` : ''
      },
      success: (res) => {
        if (res.statusCode === 200) {
          if (res.data.code === 0) {
            resolve(res.data.data);
          } else if (res.data.code === 401) {
            // token 过期，尝试刷新
            refreshTokenAndRetry(url, method, data).then(resolve).catch(reject);
          } else {
            wx.showToast({ title: res.data.msg || '请求失败', icon: 'none' });
            reject(res.data);
          }
        } else {
          wx.showToast({ title: '服务器异常', icon: 'none' });
          reject(res);
        }
      },
      fail: () => {
        wx.showToast({ title: '网络异常，请检查网络', icon: 'none' });
        reject(new Error('network error'));
      }
    });
  });
}

function refreshTokenAndRetry(url, method, data) {
  return new Promise((resolve, reject) => {
    wx.login({
      success: (res) => {
        wx.request({
          url: BASE_URL + '/auth/refresh',
          method: 'POST',
          data: { code: res.code },
          success: (r) => {
            wx.setStorageSync('token', r.data.token);
            // 重试原请求
            request(url, method, data).then(resolve).catch(reject);
          },
          fail: () => {
            wx.removeStorageSync('token');
            wx.navigateTo({ url: '/pages/login/login' });
            reject(new Error('refresh failed'));
          }
        });
      }
    });
  });
}

module.exports = {
  get: (url, data) => request(url, 'GET', data),
  post: (url, data) => request(url, 'POST', data),
  put: (url, data) => request(url, 'PUT', data),
  del: (url) => request(url, 'DELETE')
};
```

```javascript
// utils/util.js
function debounce(fn, delay = 300) {
  let timer = null;
  return function(...args) {
    if (timer) clearTimeout(timer);
    timer = setTimeout(() => {
      fn.apply(this, args);
      timer = null;
    }, delay);
  };
}

function throttle(fn, interval = 300) {
  let lastTime = 0;
  return function(...args) {
    const now = Date.now();
    if (now - lastTime >= interval) {
      lastTime = now;
      fn.apply(this, args);
    }
  };
}

module.exports = { debounce, throttle };
```

```javascript
// utils/eventbus.js
class EventBus {
  constructor() {
    this._events = {};
  }

  on(event, callback) {
    if (!this._events[event]) this._events[event] = [];
    this._events[event].push(callback);
    return this;
  }

  off(event, callback) {
    if (!this._events[event]) return;
    this._events[event] = this._events[event].filter(cb => cb !== callback);
  }

  emit(event, ...args) {
    if (!this._events[event]) return;
    this._events[event].forEach(cb => cb(...args));
  }

  once(event, callback) {
    const wrapper = (...args) => {
      callback(...args);
      this.off(event, wrapper);
    };
    this.on(event, wrapper);
  }
}

module.exports = new EventBus();
```

```javascript
const rules = {
  required: (val, msg) => (!val || val.trim() === '') ? msg : '',
  phone: (val) => /^1[3-9]\d{9}$/.test(val) ? '' : '手机号格式不正确',
  email: (val) => /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(val) ? '' : '邮箱格式不正确',
  minLength: (val, min) => (val && val.length >= min) ? '' : `最少输入${min}个字符`,
  maxLength: (val, max) => (val && val.length <= max) ? '' : `最多输入${max}个字符`
};

function validate(formData, fieldRules) {
  const errors = {};
  for (const [field, validators] of Object.entries(fieldRules)) {
    const value = formData[field];
    for (const validator of validators) {
      const [rule, param] = validator.split(':');
      const error = rules[rule](value, param);
      if (error) { errors[field] = error; break; }
    }
  }
  return Object.keys(errors).length > 0 ? errors : null;
}
```

```javascript
// utils/tracker.js
class Tracker {
  constructor() {
    this.points = {};
  }

  // 打点开始
  mark(name) {
    this.points[name] = Date.now();
  }

  // 测量耗时
  measure(from, to, action) {
    const start = this.points[from];
    const end = this.points[to];
    if (start && end) {
      this.report({
        type: 'performance',
        action,
        duration: end - start,
        timestamp: Date.now()
      });
    }
  }

  // 页面曝光（PV）
  pageView(pagePath) {
    this.report({ type: 'pv', page: pagePath, timestamp: Date.now() });
  }

  // 用户行为
  event(action, params = {}) {
    this.report({ type: 'event', action, params, timestamp: Date.now() });
  }

  report(data) {
    // 批量上报（缓存后批量发送）
    if (!this._buffer) this._buffer = [];
    this._buffer.push(data);
    if (this._buffer.length >= 10) this.flush();
  }

  flush() {
    if (this._buffer.length === 0) return;
    const data = this._buffer.slice();
    this._buffer = [];
    wx.request({
      url: 'https://track.example.com/report',
      method: 'POST',
```

## 六、常见坑点与最佳实践

| 坑点 | 具体表现 | 根本原因 | 解决方案 |
|------|---------|---------|---------|
| setData 数据超过 1MB | 页面卡顿甚至白屏 | JSBridge 传输阻塞 | 单次不超过 1MB，按路径更新 |
| 多次连续 setData | 页面响应延迟 | 频繁跨线程通信 | 合并为一次 setData |
| navigateTo 超过 10 层 | 跳转无反应 | 页面栈限制 | 超 8 层改用 redirectTo/reLaunch |
| 图片加载过多导致 OOM | 低端机闪退 | WebView 内存溢出 | 使用 lazy-load + 分页加载 + 尺寸裁剪 |
| IOS 底部固定元素遮挡 | 元素被 Home Indicator 覆盖 | 未适配安全区域 | 使用 `safe-area-inset-bottom` |
| wx.request 被拦截 | 请求失败（真机） | 域名未配置白名单 | 后台配置 request 白名单 |
| 登录态过期 | 接口报 401 且未处理 | 未统一处理 token 过期 | 请求层统一刷新 token 并重试 |
| onPageScroll 中 setData | 滑动卡顿 | 高频跨线程通信 | 使用节流 + WXS 处理 |
| 自定义组件样式失效 | 组件样式不生效 | 样式隔离导致 | 配置 styleIsolation 或全局引入 |
| Android 字体过小 | 部分机型字体异常 | 系统字体缩放影响 | 使用 rpx 单位 + 禁止系统字体缩放 |
| 回调中 this 指向错误 | this 为 undefined | 作用域丢失 | 使用箭头函数或全局保存 that |

## 七、面试回答模板

### Q1: 小程序双线程架构的原理和优缺点？

> 小程序采用逻辑层（AppService）和渲染层（WebView）分离的双线程架构，两层通过 Native JSBridge 通信。逻辑层运行在独立的 JS 线程中，负责业务逻辑和 API 调用；渲染层由多个 WebView 实例组成，负责 WXML 渲染和事件收集。**优点**：逻辑不阻塞 UI 渲染，页面切换流畅；数据隔离更安全；页面独立运行互不干扰。**缺点**：setData 跨线程通信有性能开销，不能频繁传输大数据。

### Q2: setData 的性能瓶颈在哪？怎么优化？

> setData 的瓶颈在于每次调用都是跨线程通信：逻辑层将数据 JSON 序列化后通过 JSBridge 发送给渲染层，渲染层反序列化后执行 diff 更新节点。**优化方案**：第一，合并多次 setData 为一次，减少通信次数。第二，单次数据控制在 1MB 以内，用路径表达式更新局部数据。第三，高频更新（如手势拖动）用 WXS 在渲染层直接处理。第四，长列表用 recycle-view 虚拟列表只渲染可见区域。

### Q3: 小程序的登录流程？

> 第一步，前端调用 `wx.login()` 获取临时 code（5 分钟有效期）。第二步，前端将 code 传给后端，后端使用 appid + appsecret + code 调用微信接口 `auth.code2Session`，获取 openid 和 session_key。第三步，后端生成自定义 token 返回前端，前端存入 `wx.setStorageSync`。后续请求携带 token 作为身份凭证。如果需要跨小程序识别用户，需绑定微信开放平台获取 unionid。

### Q4: 小程序如何实现支付？

> 小程序支付分三步：第一步，前端提交订单信息到后端，后端调用微信支付统一下单 API 获取 prepay_id。第二步，后端根据 prepay_id 生成签名参数（timeStamp、nonceStr、package、signType、paySign）返回前端。第三步，前端调用 `wx.requestPayment` 传入上述参数，调起微信支付弹窗。支付成功后在前端 success 回调和后端 notify_url 中分别处理成功逻辑。注意支付参数中的 timeStamp 必须是字符串类型。

### Q5: 分包加载的意义和实现？

> 小程序主包限制 2MB，总包 20MB。分包将代码按功能拆分为主包和分包，用户首次只下载主包，进入分包页面时才按需下载对应分包代码。**实现**：在 `app.json` 中用 `subpackages` 字段声明分包根目录和页面路径。**预加载**：用 `preloadRule` 配置在某个主包页面时提前下载分包。**意义**：缩短冷启动时间、突破 2MB 限制、节省用户流量。适用于电商订单、个人中心等非核心模块。
