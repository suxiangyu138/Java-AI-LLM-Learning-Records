# 计算机网络系统学习大纲

适用对象：后端开发、Java 开发、校招/社招面试准备。学习主线建议按照“分层模型 → IP 与路由 → 传输层 → 应用层 → 网络安全 → 抓包排障 → 面试串联”推进，这样更容易把协议之间的关系串起来。 [javabetter](https://javabetter.cn/cs/wangluo.html)

## 学习目标

完成本大纲后，应当能够达到以下目标：

- 理解计算机网络的分层思想，能说清每一层解决什么问题、常见协议有哪些。 [runoob](https://www.runoob.com/w3cnote/summary-of-network.html)
- 掌握 IP、ARP、ICMP、路由、NAT、DNS、TCP、UDP、HTTP、HTTPS 等高频协议的核心机制。 [openeuler.csdn](https://openeuler.csdn.net/69f315cd54b52172bc70f8df.html)
- 能独立分析“三次握手、四次挥手、TIME_WAIT、滑动窗口、拥塞控制、HTTP 缓存、HTTPS 握手”等经典问题。 [cloud.tencent](https://cloud.tencent.com/developer/article/1950799)
- 能结合抓包工具或日志，定位常见网络问题，如连接超时、重传、DNS 解析慢、请求被限流、跨机房延迟高等。 [javabetter](https://javabetter.cn/cs/wangluo.html)

## 阶段一：建立整体框架

### 1.1 分层模型

建议先掌握 OSI 七层模型与 TCP/IP 五层模型，重点不是死记名称，而是理解“每层向上一层提供什么能力”。常见划分包括物理层、数据链路层、网络层、传输层、应用层；OSI 模型还包含会话层和表示层。 [cnblogs](https://www.cnblogs.com/tangjielin/p/17114410.html)

这一阶段需要达到的要求：

- 能说出每层的典型协议与设备，例如交换机常对应数据链路层，路由器常对应网络层。 [runoob](https://www.runoob.com/w3cnote/summary-of-network.html)
- 能区分数据单位：比特、帧、IP 数据报、报文段、报文。 [cloud.tencent](https://cloud.tencent.com/developer/article/1950799)
- 能解释“封装”和“解封装”的过程。 [javabetter](https://javabetter.cn/cs/wangluo.html)

### 1.2 网络通信全流程

把“浏览器输入一个 URL 后发生了什么”作为总线索：DNS 解析、建立 TCP 连接、发送 HTTP 请求、服务器处理、返回响应、浏览器渲染页面，这条链路几乎会覆盖所有重要知识点。 [openeuler.csdn](https://openeuler.csdn.net/69f315cd54b52172bc70f8df.html)

建议在这一阶段画出一张总流程图，后续每学完一个协议，就补充到图里。

## 阶段二：网络层基础

### 2.1 IP 地址与子网划分

需要掌握 IPv4 的基本结构、网络号和主机号、子网掩码、CIDR 表示法，以及私有 IP 与公网 IP 的区别。 [runoob](https://www.runoob.com/w3cnote/summary-of-network.html)

这一部分建议重点学习：

- IPv4 地址分类与 CIDR 的关系。 [runoob](https://www.runoob.com/w3cnote/summary-of-network.html)
- 子网掩码如何判断两个主机是否处于同一网段。 [cloud.tencent](https://cloud.tencent.com/developer/article/1950799)
- 默认网关的作用，以及跨网段通信为什么需要网关。 [javabetter](https://javabetter.cn/cs/wangluo.html)

### 2.2 ARP、ICMP、NAT、路由

ARP 用于在局域网中根据 IP 地址获取目标主机的 MAC 地址，ICMP 常用于网络诊断，例如 ping 就依赖 ICMP。 [openeuler.csdn](https://openeuler.csdn.net/69f315cd54b52172bc70f8df.html)

路由器工作在网络层，负责分组转发与路由选择；NAT 则让多个内网设备复用较少的公网地址，是家庭网络和公司内网中非常常见的机制。 [cloud.tencent](https://cloud.tencent.com/developer/article/1950799)

本阶段要能回答：

- 同一局域网中两台主机如何通信。 [openeuler.csdn](https://openeuler.csdn.net/69f315cd54b52172bc70f8df.html)
- 跨网段访问时数据包为什么要先发给网关。 [javabetter](https://javabetter.cn/cs/wangluo.html)
- NAT 为什么能缓解 IPv4 地址不足问题。 [runoob](https://www.runoob.com/w3cnote/summary-of-network.html)

## 阶段三：传输层重点突破

### 3.1 UDP

UDP 是无连接、尽最大努力交付、面向报文的传输协议，协议开销小、时延低，但不保证可靠性、顺序和去重。 [javabetter](https://javabetter.cn/cs/wangluo.html)

要理解 UDP 更适合实时音视频、语音通话、DNS 等对时延更敏感的场景。 [openeuler.csdn](https://openeuler.csdn.net/69f315cd54b52172bc70f8df.html)

### 3.2 TCP 基础机制

TCP 是面向连接、可靠传输、面向字节流的协议，其可靠性通常通过序列号、确认应答、超时重传、滑动窗口、流量控制和拥塞控制来实现。 [cloud.tencent](https://cloud.tencent.com/developer/article/1950799)

这部分是整个计算机网络学习的核心，建议拆成以下小节：

- 序列号与确认号。 [cloud.tencent](https://cloud.tencent.com/developer/article/1950799)
- 重传机制与累计确认。 [javabetter](https://javabetter.cn/cs/wangluo.html)
- 滑动窗口与流量控制。 [cloud.tencent](https://cloud.tencent.com/developer/article/1950799)
- 拥塞控制：慢启动、拥塞避免、快重传、快恢复。 [cloud.tencent](https://cloud.tencent.com/developer/article/1950799)
- TCP 为什么会粘包/拆包，以及应用层如何解决消息边界问题。 [javabetter](https://javabetter.cn/cs/wangluo.html)

### 3.3 三次握手与四次挥手

三次握手是面试最高频问题之一，重点要理解其目的不是“建立连接”这句表面描述，而是让通信双方确认彼此的发送和接收能力处于正常状态。 [javabetter](https://javabetter.cn/cs/wangluo.html)

四次挥手则要重点理解：TCP 是全双工协议，因此连接关闭时双方都需要分别关闭自己的发送方向；TIME_WAIT 的存在与 2MSL 的意义也必须掌握。 [runoob](https://www.runoob.com/w3cnote/summary-of-network.html)

这一阶段建议自己写出以下问答：

- 为什么不是两次握手。 [cloud.tencent](https://cloud.tencent.com/developer/article/1950799)
- 为什么挥手通常是四次而不是三次。 [runoob](https://www.runoob.com/w3cnote/summary-of-network.html)
- 为什么客户端常常进入 TIME_WAIT。 [cloud.tencent](https://cloud.tencent.com/developer/article/1950799)
- TIME_WAIT 过多会带来什么影响，工程上如何缓解。 [cloud.tencent](https://cloud.tencent.com/developer/article/1950799)

## 阶段四：应用层核心协议

### 4.1 DNS

DNS 的本质是把域名解析成 IP 地址，常见查询路径包括浏览器缓存、本机缓存、hosts 文件、本地 DNS 服务器，再到递归或迭代查询。 [openeuler.csdn](https://openeuler.csdn.net/69f315cd54b52172bc70f8df.html)

学习重点：

- 递归查询与迭代查询的区别。 [openeuler.csdn](https://openeuler.csdn.net/69f315cd54b52172bc70f8df.html)
- DNS 缓存为什么能提升性能。 [runoob](https://www.runoob.com/w3cnote/summary-of-network.html)
- DNS 故障会如何影响应用访问。 [openeuler.csdn](https://openeuler.csdn.net/69f315cd54b52172bc70f8df.html)

### 4.2 HTTP

HTTP 是应用层协议，基于请求-响应模型，本身是无状态的。 [runoob](https://www.runoob.com/w3cnote/summary-of-network.html)

建议按以下顺序学习：

1. 请求报文与响应报文结构，常见请求方法与状态码。 [runoob](https://www.runoob.com/w3cnote/summary-of-network.html)
2. GET 和 POST 的常见区别，以及幂等性、安全性的概念。 [openeuler.csdn](https://openeuler.csdn.net/69f315cd54b52172bc70f8df.html)
3. Cookie、Session、Token 的基本作用。 [javabetter](https://javabetter.cn/cs/wangluo.html)
4. HTTP 缓存机制，如强缓存和协商缓存。 [openeuler.csdn](https://openeuler.csdn.net/69f315cd54b52172bc70f8df.html)
5. 长连接、短连接、Connection: keep-alive 的意义。 [runoob](https://www.runoob.com/w3cnote/summary-of-network.html)

### 4.3 HTTP/1.1、HTTP/2、HTTP/3

HTTP/1.1 解决了部分连接复用问题，但仍然存在明显的队头阻塞问题；HTTP/2 通过二进制分帧、头部压缩和多路复用提升了传输效率；HTTP/3 基于 QUIC 和 UDP，进一步优化了握手与丢包场景下的性能表现。 [openeuler.csdn](https://openeuler.csdn.net/69f315cd54b52172bc70f8df.html)

这一部分不一定要求掌握特别底层的实现，但至少要能说清每个版本解决了上一代的哪些痛点。 [openeuler.csdn](https://openeuler.csdn.net/69f315cd54b52172bc70f8df.html)

### 4.4 HTTPS 与 TLS

HTTPS 并不是新的应用层协议，而是在 HTTP 与 TCP 之间加入了 TLS/SSL 安全层，用来提供加密、身份认证与完整性保护。 [runoob](https://www.runoob.com/w3cnote/summary-of-network.html)

建议重点掌握：

- 对称加密与非对称加密分别解决什么问题。 [openeuler.csdn](https://openeuler.csdn.net/69f315cd54b52172bc70f8df.html)
- 数字证书、CA、证书链的作用。 [openeuler.csdn](https://openeuler.csdn.net/69f315cd54b52172bc70f8df.html)
- HTTPS 握手的大致过程，以及为什么它能防止中间人攻击。 [runoob](https://www.runoob.com/w3cnote/summary-of-network.html)

## 阶段五：局域网与设备认知

需要掌握集线器、交换机、路由器分别工作在哪一层、如何转发数据、对广播域和冲突域有什么影响。 [cloud.tencent](https://cloud.tencent.com/developer/article/1950799)

建议顺带理解 MAC 地址、以太网帧、ARP 广播、交换机 MAC 地址表等基础概念，这些内容能帮助建立“局域网里数据到底怎么走”的直觉。 [cloud.tencent](https://cloud.tencent.com/developer/article/1950799)

## 阶段六：网络安全与工程实践

除了 HTTPS，还需要了解一些工程上常见的安全与稳定性话题，例如常见端口、常见攻击面、限流、重试、超时、幂等、防重放等。 [cloud.tencent](https://cloud.tencent.com/developer/article/1950799)

建议至少建立如下意识：

- 为什么服务调用一定要配置连接超时和读超时。
- 为什么重试策略必须考虑幂等性。
- 为什么跨服务调用要关注连接池、队列堆积和雪崩效应。

这些工程实践概念虽然不全是单纯的协议知识，但它们是网络基础在后端系统中的直接落地。

## 阶段七：抓包与排障

系统学习不能只停留在背概念，建议尽早接触抓包和排障。很多协议问题在纸面上不难，但只有看到真实报文后，才能真正理解握手、重传、窗口变化和连接关闭的细节。 [javabetter](https://javabetter.cn/cs/wangluo.html)

建议实践内容：

- 使用 Wireshark 观察 TCP 三次握手和四次挥手。
- 使用浏览器开发者工具观察 HTTP 请求头、响应头、缓存命中情况。
- 使用 ping、traceroute、nslookup 或 dig 排查连通性和 DNS 问题。
- 尝试复现一次连接超时、一次读超时、一次 DNS 解析异常，并记录现象与定位思路。

## 阶段八：面试复习路线

当基础章节学完后，复习应从“章节式”转向“问题式”。最值得反复训练的问题包括 TCP 和 UDP 区别、三次握手、四次挥手、TIME_WAIT、HTTP 与 HTTPS 区别、HTTP 各版本差异、DNS 解析流程、输入 URL 后发生了什么。 [javabetter](https://javabetter.cn/cs/wangluo.html)

建议每个问题都按照“定义 → 核心机制 → 为什么这样设计 → 工程意义 → 常见追问”的结构来整理答案，这样更适合面试表达。

## 复习顺序建议

如果目标是后端面试，优先级建议如下：TCP > HTTP/HTTPS > DNS > IP/ARP/路由 > 局域网设备与交换基础 > 扩展内容。 [javabetter](https://javabetter.cn/cs/wangluo.html)

原因在于，TCP、HTTP、HTTPS、DNS 几乎是服务端开发岗位面试中的最高频考点，而它们也最直接对应线上系统的真实问题。 [runoob](https://www.runoob.com/w3cnote/summary-of-network.html)
