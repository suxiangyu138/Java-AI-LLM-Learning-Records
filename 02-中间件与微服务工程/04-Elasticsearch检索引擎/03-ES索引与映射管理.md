## 1. 索引核心概念

### 1.1 什么是 Index

Index 是 ES 中存储数据的逻辑命名空间，类比 MySQL 的 Database 或 Table。

```text
MySQL： Database > Table > Row > Column
ES：     Index > Type(7.x废弃) > Document > Field

Index 包含：
  ├── Settings:  分片数、副本数、分词器配置
  ├── Mapping:   字段类型定义（Schema）
  └── Documents: JSON 格式的数据
```

### 1.2 Type 的废弃

| ES 版本 | Type 状态 |
|:-------:|:---------:|
| 5.x | 可用，Index 下可有多个 Type |
| 6.x | 兼容模式，只允许一个 Type |
| 7.x | 废弃，`_doc` 作为默认 Type |
| 8.x | 移除，直接使用 `/_doc` |

建议：每个实体一个独立索引，而非用 Type 区分。

### 1.3 文档元数据

```json
{
  "_index": "user_index",      // 所属索引
  "_type": "_doc",             // 固定为 _doc
  "_id": "1",                  // 文档 ID（GUID 或自定义）
  "_version": 2,               // 版本号（乐观锁）
  "_score": 1.0,               // 相关性评分
  "_source": { "name": "张三" } // 原始 JSON 数据
}
```

## 2. 文档基础操作

### 2.1 新增

```json
// 自动生成 ID
POST /user_index/_doc
{ "name": "张三", "age": 25, "desc": "计算机专业学生" }

// 指定 ID
PUT /user_index/_doc/1
{ "name": "张三", "age": 25 }
```

### 2.2 查询

```json
// 按 ID 查
GET /user_index/_doc/1
// 查是否存在
HEAD /user_index/_doc/1    // 200 存在 / 404 不存在
```

### 2.3 更新与删除

```json
// 部分更新（推荐，不覆盖其他字段）
POST /user_index/_update/1
{ "doc": { "age": 26 } }

// upsert（存在更新，不存在创建）
POST /user_index/_update/1
{ "doc": { "age": 27 }, "doc_as_upsert": true }

// 按条件删除
POST /user_index/_delete_by_query
{ "query": { "match": { "status": "deleted" } } }
```

### 2.4 批量操作 _bulk

```json
POST /user_index/_bulk
{ "index":  { "_id": "1" } }
{ "name": "张三", "age": 25 }
{ "index":  { "_id": "2" } }
{ "name": "李四", "age": 30 }
{ "update": { "_id": "1" } }
{ "doc": { "age": 26 } }
{ "delete": { "_id": "2" } }
```

> 💡 `_bulk` 比逐条写入快 10-100 倍，批量导入数据时务必使用。

## 3. 创建索引与 Mapping

### 3.1 基础创建

```json
PUT /goods
{
  "settings": {
    "number_of_shards": 3,
    "number_of_replicas": 1,
    "refresh_interval": "1s"
  },
  "mappings": {
    "properties": {
      "id":          { "type": "long" },
      "title": {
        "type": "text",
        "analyzer": "ik_max_word",
        "search_analyzer": "ik_smart"
      },
      "price":       { "type": "double" },
      "category":    { "type": "keyword" },
      "brand":       { "type": "keyword" },
      "stock":       { "type": "integer" },
      "description": { "type": "text", "analyzer": "ik_max_word" },
      "create_time": { "type": "date", "format": "yyyy-MM-dd HH:mm:ss" },
      "is_on_sale":  { "type": "boolean" },
      "tags":        { "type": "keyword" },
      "location":    { "type": "geo_point" }
    }
  }
}
```

### 3.2 Settings 核心参数

| 参数 | 默认值 | 说明 | 可动态修改 |
|------|:------:|------|:---------:|
| `number_of_shards` | 1 | 主分片数 | 否 |
| `number_of_replicas` | 1 | 副本数 | 是 |
| `refresh_interval` | 1s | 数据可搜索间隔 | 是 |
| `max_result_window` | 10000 | from+size 最大深度 | 是 |
| `translog.durability` | `request` | translog 刷盘策略 | 是 |

### 3.3 写入优化 Settings

```json
// 批量导入时
PUT /goods_batch
{
  "settings": {
    "number_of_shards": 3,
    "number_of_replicas": 0,           // 写入时副本设为 0
    "refresh_interval": "-1",           // 关闭 refresh
    "translog.durability": "async"
  }
}

// 写入完成后恢复
PUT /goods_batch/_settings
{
  "number_of_replicas": 1,
  "refresh_interval": "1s",
  "translog.durability": "request"
}
```

## 4. 字段类型详解

### 4.1 核心类型总览

| 类别 | 类型 | 用途 |
|------|------|------|
| 文本 | `text` | 全文搜索（分词）|
| 关键字 | `keyword` | 精确匹配/排序/聚合（不分词）|
| 整数 | `long` / `integer` / `short` / `byte` | 整数数值 |
| 浮点 | `float` / `double` / `half_float` / `scaled_float` | 浮点数值 |
| 布尔 | `boolean` | true / false |
| 日期 | `date` | 日期时间 |
| 范围 | `integer_range` / `float_range` / `date_range` | 范围类型 |
| 地理位置 | `geo_point` / `geo_shape` | 地理位置 |
| 结构化 | `object` / `nested` / `flattened` | JSON 对象 |
| 向量 | `dense_vector` / `sparse_vector` | 语义搜索（8.x）|

### 4.2 text vs keyword 详细对比

| 维度 | `text` | `keyword` |
|------|--------|-----------|
| 分词 | 是 | 否 |
| 全文搜索 | 支持（match） | 不支持 |
| 精确查询 | 不支持 | 支持（term）|
| 排序 | 需 multi-field | 支持 |
| 聚合 | 不支持 | 支持 |

```json
// 测试 text vs keyword 的不同表现
PUT /test_types
{ "mappings": { "properties": {
  "description": { "type": "text" },
  "category":    { "type": "keyword" }
}}}

POST /test_types/_doc/1
{ "description": "华为手机P40", "category": "手机" }

// text 字段：match 可以查，term 查不到（因为被分词了）
GET /test_types/_search
{ "query": { "match": { "description": "华为" } } }     // 找到！
{ "query": { "term":  { "description": "华为手机" } } } // 找不到！

// keyword 字段：term/match 都能查
GET /test_types/_search
{ "query": { "term":  { "category": "手机" } } }        // 找到！
{ "query": { "match": { "category": "手机" } } }        // 也找到
```

### 4.3 日期类型

```json
PUT /order_index
{ "mappings": { "properties": {
  "order_time": {
    "type": "date",
    "format": "yyyy-MM-dd HH:mm:ss||yyyy-MM-dd||epoch_millis"
  }
}}}
```

### 4.4 地理位置

```json
PUT /shop_index
{ "mappings": { "properties": {
  "name":     { "type": "text" },
  "location": { "type": "geo_point" }
}}}

POST /shop_index/_doc/1
{ "name": "北京天安门", "location": { "lat": 39.90, "lon": 116.39 } }
```

### 4.5 dense_vector（8.x RAG）

```json
PUT /ai_docs
{ "mappings": { "properties": {
  "content": { "type": "text" },
  "content_vector": {
    "type": "dense_vector",
    "dims": 768,
    "index": true,
    "similarity": "cosine"
  }
}}}

```

## 5. Mapping 高级配置

### 5.1 Multi-fields（多字段）

同一字段多种索引方式，适用不同查询场景。

```json
PUT /goods
{ "mappings": { "properties": {
  "title": {
    "type": "text",
    "analyzer": "ik_max_word",
    "fields": {
      "keyword": { "type": "keyword" },                // 精确过滤和排序
      "pinyin":  { "type": "text", "analyzer": "pinyin_analyzer" }  // 拼音搜索
    }
  }
}}}

// 使用
GET /goods/_search
{ "query": { "match": { "title": "华为" } } }               // 全文
{ "query": { "term":  { "title.keyword": "华为手机P40" } } } // 精确
{ "query": { "match": { "title.pinyin": "huawei" } } }      // 拼音
```

### 5.2 copy_to 聚合字段

```json
PUT /goods
{ "mappings": { "properties": {
  "title":       { "type": "text", "copy_to": "full_text" },
  "description": { "type": "text", "copy_to": "full_text" },
  "brand":       { "type": "keyword", "copy_to": "full_text" },
  "full_text":   { "type": "text", "analyzer": "ik_max_word" }
}}}

// 搜索 full_text 同时匹配 title + description + brand
GET /goods/_search
{ "query": { "match": { "full_text": "华为手机" } } }
```

### 5.3 index 与 store 控制

| 参数 | 默认 | 说明 |
|------|:----:|------|
| `index` | true | false 表示不被索引（不可搜索）|
| `store` | false | true 表示独立存储（加快大字段读取）|
| `doc_values` | true | false 禁用列式存储（不用排序/聚合的字段可关闭）|

### 5.4 null_value

```json
PUT /goods
{ "mappings": { "properties": {
  "price":    { "type": "integer", "null_value": 0 },
  "category": { "type": "keyword", "null_value": "UNKNOWN" }
}}}
```

### 5.5 字段限制

```json
PUT /goods
{
  "settings": {
    "index.mapping.total_fields.limit": 200,
    "index.mapping.depth.limit": 10,
    "index.mapping.ignore_malformed": true
  }
}
```

## 6. 动态 Mapping

### 6.1 三种模式

| dynamic 值 | 行为 | 适用场景 |
|:----------:|------|---------|
| `true`（默认）| 新字段自动加入 Mapping | 开发调试 |
| `runtime` | 新字段作为运行时字段 | Schema on Read |
| `false` | 忽略新字段（_source 中保留）| 半结构化数据 |
| `strict` | 新字段报错 | 生产严格模式 |

```json
PUT /my_index
{ "mappings": { "dynamic": "strict", "properties": {
  "name": { "type": "text" },
  "age":  { "type": "integer" }
}}}

POST /my_index/_doc/1
{ "name": "张三", "age": 25, "city": "北京" }
// 报错：strict 模式不允许引入新字段 [city]
```

### 6.2 Dynamic Templates

```json
PUT /my_index
{ "mappings": {
  "dynamic_templates": [
    {
      "strings_as_keyword": {
        "match_mapping_type": "string",
        "mapping": { "type": "keyword" }
      }
    },
    {
      "longs_as_integer": {
        "match_mapping_type": "long",
        "mapping": { "type": "integer" }
      }
    }
  ]
}}
```

## 8. Reindex 数据迁移

### 8.1 基本 Reindex

```json
// 索引间复制数据（修改分词器时必备）
POST _reindex
{
  "source": { "index": "goods_v1" },
  "dest":   { "index": "goods_v2" }
}

// 带查询条件（只迁移部分数据）
POST _reindex
{
  "source": {
    "index": "goods_v1",
    "query": { "range": { "create_time": { "gte": "2026-01-01" } } }
  },
  "dest": { "index": "goods_v2" }
}
```

### 8.2 Reindex 修改分词器

```json
// 1. 创建新索引（新 Mapping）
PUT /goods_v2
{ "settings": { "number_of_shards": 3 },
  "mappings": { "properties": {
    "title": { "type": "text", "analyzer": "ik_max_word" }
  }}
}

// 2. 数据迁移
POST _reindex
{ "source": { "index": "goods_v1" }, "dest": { "index": "goods_v2" } }

// 3. 删除旧索引 + 创建别名
DELETE /goods_v1
PUT /goods_v2/_alias/goods
```

### 8.3 Update By Query / Delete By Query

```json
// 批量修改
POST /goods/_update_by_query
{
  "script": { "source": "ctx._source.price *= 1.1", "lang": "painless" },
  "query": { "match_all": {} }
}

// 批量删除
POST /goods/_delete_by_query
{ "query": { "range": { "create_time": { "lt": "2025-01-01" } } } }
```

## 9. 索引别名

### 9.1 别名的作用

别名是索引的"软链接"，应用层使用别名访问，底层索引可透明切换。

```text
应用层 → 别名 goods → goods_v1（当前）
                      goods_v2（新版本→切换）

切换后：
应用层 → 别名 goods → goods_v2（当前）
                      goods_v1（废弃）
```

### 9.2 别名操作

```json
// 创建别名
PUT /goods_v1/_alias/goods

// 或使用 _aliases API
POST /_aliases
{
  "actions": [
    { "add": { "index": "goods_v1", "alias": "goods" } }
  ]
}

// 查看
GET /_alias/goods

// 零停机切换（原子操作）
POST /_aliases
{
  "actions": [
    { "remove": { "index": "goods_v1", "alias": "goods" } },
    { "add":    { "index": "goods_v2", "alias": "goods" } }
  ]
}
```

### 9.3 带过滤条件的别名

```json
POST /_aliases
{
  "actions": [
    {
      "add": {
        "index": "goods",
        "alias": "goods_expensive",
        "filter": { "range": { "price": { "gte": 5000 } } }
      }
    }
  ]
}
```

## 10. 索引模板

### 10.1 Index Template

自动应用于匹配模式的索引。

```json
PUT _index_template/logs_template
{
  "index_patterns": ["logs-*"],
  "template": {
    "settings": {
      "number_of_shards": 3,
      "number_of_replicas": 1
    },
    "mappings": {
      "properties": {
        "@timestamp": { "type": "date" },
        "level":      { "type": "keyword" },
        "message":    { "type": "text", "analyzer": "ik_max_word" }
      }
    }
  },
  "priority": 100
}

// 创建 logs-2026-01-15 时自动应用模板配置
PUT /logs-2026-01-15
```

## 11. 索引生命周期管理（ILM）

### 11.1 ILM 策略

自动管理索引从创建到删除的全过程。

```json
PUT _ilm/policy/logs_policy
{
  "policy": {
    "phases": {
      "hot": {
        "min_age": "0ms",
        "actions": {
          "rollover": { "max_primary_shard_size": "50gb", "max_age": "1d" }
        }
      },
      "warm": {
        "min_age": "30d",
        "actions": {
          "forcemerge": { "max_num_segments": 1 }
        }
      },
      "cold": {
        "min_age": "90d",
        "actions": {
          "searchable_snapshot": { "snapshot_repository": "my_backup" }
        }
      },
      "delete": {
        "min_age": "180d",
        "actions": { "delete": {} }
      }
    }
  }
}

// 索引关联 ILM
PUT _index_template/logs_template
{
  "index_patterns": ["logs-*"],
  "template": {
    "settings": {
      "index.lifecycle.name": "logs_policy",
      "index.lifecycle.rollover_alias": "logs"
    }
  }
}
```

### 11.2 ILM 阶段

| 阶段 | 作用 | 常用操作 |
|:----:|------|---------|
| Hot | 正在写入的活跃索引 | Rollover, Set Priority |
| Warm | 不再写入但需查询 | Force Merge, Shrink |
| Cold | 极少查询，只读 | Searchable Snapshot |
| Delete | 删除索引 | Delete |

## 12. 索引优化设计

### 12.1 设计原则

| 原则 | 说明 |
|------|------|
| 主分片数不可修改 | 创建时根据数据量估算（单分片 20-50GB）|
| 别名代替索引名 | 应用层使用别名，底层索引可透明切换 |
| 关闭 dynamic Mapping | 生产用 `strict`，避免字段类型错误 |
| 避免过多字段 | 单索引不超过 200 个字段 |
| 合理使用 keyword | text 不需要排序/聚合就设 `index: false` |
| 拒绝 fielddata | 用 multi-field keyword 替代 |
| 按时间分索引 | 日志类按天/月分索引，配合 ILM |

### 12.2 分片估算

```text
总数据量 = 文档数 × 平均文档大小
目标分片大小 = 20-50GB（建议 30GB）
主分片数 = 总数据量 / 目标分片大小

示例：200GB / 30GB ≈ 7（取整为 8）
```

### 12.3 常见场景建议

| 场景 | 主分片数 | 副本数 | 建议 |
|------|:-------:|:------:|------|
| 日志小数据（< 10GB） | 1 | 1 | 单分片足够 |
| 日志大数据（100GB+） | 3-6 | 1 | 按天分索引 |
| 电商商品（50GB） | 3 | 1 | 别名切换 |
| 全量文本搜索 | 5-10 | 1 | IK 分词 |

## 面试核心要点

| 问题 | 答案 |
|------|------|
| **为什么主分片数不可修改？** | 路由公式 `hash(_id) % num_primary_shards`，修改会导致数据错位。需 Reindex |
| **text 和 keyword 怎么选？** | text 分词用于全文搜索；keyword 不分词用于精确匹配/排序/聚合 |
| **multi-field 有什么用？** | 同一字段多种索引方式（如 title:text + title.keyword）|
| **copy_to 和 multi-field 区别？** | copy_to 多字段合并为搜索字段；multi-field 同一字段多种索引方式 |
| **Reindex 适用场景？** | 修改分词器、分片数、Mapping、跨集群迁移 |
| **别名为什么重要？** | 实现零停机索引切换 |
| **索引模板有什么用？** | 自动为新索引应用 settings 和 mappings |
| **ILM 分哪几个阶段？** | Hot → Warm → Cold → Delete |
| **dynamic: strict 好处？** | 字段写错时报错而非静默忽略，保证数据质量 |

> 🎯 **极简总结**：Index = Settings（分片/副本） + Mapping（字段类型/分词器） + Documents（数据）。创建时定分片数，运行时用别名，修改时用 Reindex，分层用 ILM。
