# 高并发与性能调优

## 📌 定位
**课外自学 | 第二梯队 | 大厂面试高阶考点**

系统能扛多少QPS、接口响应多少ms——这是衡量后端工程师水平的核心指标。从JVM到数据库到系统架构，调优是全链路的。

## 🎯 核心章节

### 1. JVM 调优
- **监控工具**：`jps`(进程)、`jstat -gc`(GC统计)、`jmap -heap`(堆信息)、`jstack`(线程栈)、`jconsole/jvisualvm`(图形化)
- **GC 日志分析**：`-Xlog:gc*`(JDK9+)+GCViewer/GCeasy——关注Young GC频率、Full GC持续时间、内存Promotion
- **调优目标**：减少Full GC次数→保证低延迟(SLA<100ms)→吞吐量优先(批处理)
- **内存配置**：`-Xms -Xmx`(堆大小，同值防扩容震荡)、`-Xmn`(新生代大小)、`-XX:MetaspaceSize`
- **GC选择**：响应优先→G1/ZGC，吞吐优先→Parallel GC

### 2. 线程池调优
- **参数计算**（经验公式，非绝对）：
  - CPU密集型：corePoolSize = CPU核数+1
  - IO密集型：corePoolSize = CPU核数×(1+平均等待时间/平均计算时间)
- **队列选择**：SynchronousQueue(无容量直接交接，CachedThreadPool) vs LinkedBlockingQueue(有界防OOM) vs ArrayBlockingQueue
- **监控指标**：activeCount、queueSize、completedTaskCount、rejectedCount——空闲告警+积压告警
- **拒绝策略**：DISCARD_OLDEST(适合允许丢老任务的场景)、ABORT(默认)、CALLER_RUNS(天然的限流)

### 3. 数据库调优（MySQL）
- **索引优化**：最左前缀、覆盖索引、避免索引失效
- **SQL 优化**：小表驱动大表、避免SELECT *、JOIN替代子查询(部分场景)、LIMIT大偏移量→基于主键的延迟关联
- **连接池配置**：HikariCP(默认)的maximumPoolSize = (CPU核数×2+1)为起点，connectionTimeout防雪崩
- **读写分离**：主写从读——ShardingSphere-jdbc(客户端)或Proxy(代理端)
- **慢查询**：开启log→pt-query-digest分析→针对优化

### 4. 系统层调优
- **文件描述符**：`ulimit -n` 提高——高并发服务必须
- **内核参数**：`net.core.somaxconn`(TCP半连接/全连接队列)、`tcp_tw_reuse`(TIME_WAIT复用)
- **内存**：关闭swap(或降低swappiness)——尽量避免JVM堆被换出

### 5. 架构层高并发
- **缓存层**：多级缓存(本地Caffeine+分布式Redis)→缓存预热+降级
- **异步化**：能异步的不同步——MQ削峰(秒杀场景)
- **读写分离**：读多写少→一主多从
- **分库分表**：单表超过500万行→考虑分表；单库扛不住→分库
- **CDN + 静态化**：静态资源/热点页面前置到CDN，源站只处理动态请求
- **限流**：令牌桶(Guava RateLimiter/Sentinel)→漏桶→滑动窗口——网关层统一限流

### 6. 压测与监控
- **压测工具**：JMeter(HTTP+DB)、wrk/ab(HTTP轻量)、Locust(Python脚本灵活)
- **压测流程**：摸底→加压→瓶颈定位→优化→验证→容量规划
- **关注指标**：QPS、RT(平均/P99/P999)、错误率、CPU%/内存%/磁盘IO/网络

## ✅ 学习建议
- 先学会用工具（jstat/top/jstack/arthas），再学怎么调
- 压测从单接口→单服务→全链路，逐步加压
- 阿里Arthas(JVM在线诊断工具)是调优神器——`watch/trace/thread/vmstat`
