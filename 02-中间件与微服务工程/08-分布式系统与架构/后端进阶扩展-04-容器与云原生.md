# 容器与云原生

## 📌 定位
**课外自学 | 第二梯队 | 现代后端运维标配**

云原生改变了软件交付和运维方式——容器化、编排、服务网格、CI/CD已成为后端基础设施标准。

## 🎯 核心章节

### 1. Docker
- **三大核心概念**：镜像(Image,分层构建)→容器(Container,运行实例)→仓库(Registry,镜像存储)
- **镜像分层与写时复制**：UnionFS(Overlay2)——每层只读，容器层可写
- **Dockerfile 最佳实践**：多阶段构建(减小镜像)、`COPY` vs `ADD`、命令合并减少层数
- **网络模式**：bridge(默认, NAT)、host(共享宿主机网络)、none、container(共享另一个容器网络栈)
- **数据卷**：volume(managed by Docker)、bind mount(宿主机目录映射)

### 2. Kubernetes（K8s，⭐ 核心）
- **架构**：Master(API Server+etcd+Scheduler+Controller Manager) + Node(kubelet+kube-proxy+Container Runtime)
- **核心资源对象（⭐ 必掌握）**：
  - Pod：最小调度单元，共享网络+存储+IPC命名空间（Sidecar模式）
  - Deployment：无状态应用的声明式管理——滚动更新、版本回滚
  - Service：Pod的负载均衡入口——ClusterIP/NodePort/LoadBalancer
  - Ingress：七层HTTP路由——基于域名/路径分发
  - ConfigMap/Secret：配置与敏感信息分离
  - StatefulSet：有状态应用——稳定网络标识+持久存储
- **调度流程**：Pod创建→Scheduler打分→绑定Node→kubelet创建容器
- **网络方案**：CNI插件(Calico/Flannel/Cilium)——Pod-to-Pod通信

### 3. 服务网格（Service Mesh）
- **Sidecar模式**：每个Pod旁注入一个代理(Envoy)，接管所有流量
- **Istio**：控制面(Istiod)+数据面(Envoy)——流量管理+安全+可观测性
- **解决了什么**：将服务治理逻辑从业务代码中剥离到基础设施层

### 4. CI/CD 流水线
```
代码提交 → 自动构建 → 单元测试 → 代码扫描 → 构建镜像 → 推送仓库 → 部署测试环境 → 集成/E2E测试 → 部署生产
```
- **Jenkins**：老牌CI工具——Pipeline as Code(Jenkinsfile)
- **GitHub Actions**：GitHub原生CI——yaml配置简单
- **GitLab CI**：GitLab集成——`.gitlab-ci.yml`
- **ArgoCD**：GitOps部署工具——Git仓库作为部署的唯一真相源

### 5. 可观测性
- **三大支柱**：日志(ELK/Loki)+指标(Prometheus+Grafana)+链路追踪(Jaeger/Zipkin/SkyWalking)
- **Prometheus**：Pull模型采集指标+PromQL查询+AlertManager告警
- **OpenTelemetry**：统一的可观测性标准——一次埋点，多后端兼容

## ✅ 学习建议
- Docker必学——本地开发环境标配，一小时内上手
- K8s先理解核心资源对象(Deployment/Service/Pod)，再学网络和调度
- 推荐实践：把自己项目Docker化→Compose编排→K8s部署的完整链路走一遍
