# 第一章：TCP 深度剖析

### 1.1 TCP 状态机完整分析
- **11 种状态**：LISTEN → SYN-RCVD → ESTABLISHED → FIN-WAIT-1 → FIN-WAIT-2 → TIME-WAIT → CLOSED 等
- **状态转换触发条件**：三次握手中状态变化（CLOSED→SYN-SENT→ESTABLISHED，LISTEN→SYN-RCVD→ESTABLISHED）
- **TIME_WAIT（2MSL ≈ 60秒）**：为什么存在？①确保最后的ACK被对方收到 ②让旧连接的报文在网络中消失
  - 问题：高并发短连接导致端口耗尽 → `tcp_tw_reuse` / 连接池 / 长连接
- **CLOSE_WAIT 过多排查**：服务端没调用 close()——应用层 Bug（忘记关闭连接/线程池没释放）

### 1.2 TCP 流量控制（滑动窗口深入）
- **接收窗口（rwnd）**：接收方缓冲区剩余空间——防止发送方"淹没"接收方
- **零窗口探测**：接收方窗口=0时，发送方启动持续计时器，周期性发探测包
- **糊涂窗口综合征（Silly Window Syndrome）**：接收方每次只释放少量空间——Nagle 算法 + Clark 方案

### 1.3 TCP 拥塞控制（⭐ 核心算法演进）
- **为什么要拥塞控制**：流量控制管接收方，拥塞控制管网络——防止过多数据注入网络
- **经典算法（Reno/NewReno）**：
  - 慢启动（Slow Start）：cwnd 从 1 MSS 开始指数增长（每 RTT ×2）直到 ssthresh
  - 拥塞避免（Congestion Avoidance）：cwnd 线性增长（每 RTT +1）
  - 快速重传：收到 3 个重复 ACK 立即重传丢失报文
  - 快速恢复：快速重传后 cwnd = cwnd/2 + 3*MSS，进入拥塞避免——不重走慢启动
  - 超时重传：RTO 超时 → cwnd=1，重走慢启动
- **BBR（Google, 2016）**：基于瓶颈带宽 + RTT 建模，不依赖丢包信号——适合高延迟高带宽（如跨国专线）
- **CUBIC**：Linux 默认（2.6.19+）——三次函数曲线优化高速网络

### 1.4 TCP 定时器
- **重传定时器**：RTO 动态估算（Jacobson 算法/Karn 算法）
- **持续定时器**：零窗口探测
- **保活定时器**：2小时空闲→发探测包→无响应则关闭
- **TIME_WAIT 定时器**：2MSL

### 1.5 TCP 选项字段
- **MSS（最大报文段长度）**：SYN 中协商——通常为 MTU - 40（IP头20+TCP头20）
- **SACK（选择性确认）**：告诉发送方哪些段收到了——只需重传真正丢失的段
- **窗口缩放（Window Scale）**：窗口字段只有16位（最大64KB）→ 缩放因子扩展至 1GB
- **时间戳（Timestamp）**：精确计算 RTT + 防回绕（PAWS）

# 第二章：Socket 网络编程

### 2.1 Socket API 编程模型
- **TCP 服务端**：`socket()` → `bind()` → `listen()` → `accept()` → `read()/write()` → `close()`
- **TCP 客户端**：`socket()` → `connect()` → `write()/read()` → `close()`
- **UDP**：`socket()` → `bind()` → `sendto()/recvfrom()` → `close()`（无连接，不需 listen/accept）

### 2.2 Socket 选项深入
- **SO_REUSEADDR**：允许重用 TIME_WAIT 状态的端口——服务端重启必备
- **SO_KEEPALIVE**：TCP 保活——检测死连接
- **SO_LINGER**：控制 close() 行为——优雅关闭 vs 直接 RST
- **SO_RCVBUF / SO_SNDBUF**：收发缓冲区大小——影响 TCP 窗口
- **TCP_NODELAY**：禁用 Nagle 算法——低延迟场景必开（游戏、实时通信）
- **SO_BACKLOG**：已完成连接队列（ESTABLISHED）的最大长度

### 2.3 I/O 模型深入分析
- **阻塞 I/O**：进程阻塞直到数据就绪并拷贝完成——简单但并发差
- **非阻塞 I/O + 轮询**：立即返回，没数据返回 EAGAIN/EWOULDBLOCK——CPU 忙等
- **I/O 多路复用**：
  - **select**：fd_set 位图，1024限制，O(n)轮询，每次调用需重新传入 fd 集
  - **poll**：pollfd 数组，无数量限制，O(n)轮询，需在用户态和内核态间拷贝
  - **epoll**（Linux 专属）：红黑树管理所有 fd + 就绪链表直接返回——O(1)获取就绪事件
    - epoll_create → epoll_ctl(EPOLL_CTL_ADD/MOD/DEL) → epoll_wait
    - LT（水平触发）：状态就绪就一直通知
    - ET（边缘触发）：状态变化时才通知一次——必须配合非阻塞 I/O，效率更高
  - **kqueue**（BSD/Mac）——类似 epoll
  - **IOCP**（Windows）——纯异步 I/O
- **异步 I/O（AIO）**：内核完成数据拷贝后通知——真正的异步（Linux io_uring 是未来）

### 2.4 高性能网络服务设计模式
- **Reactor 模式**：主线程 epoll_wait 监听事件 → 分发给工作线程处理——Netty、Nginx
  - 单 Reactor（Redis 6.0 前）、多 Reactor（Netty 主从 Reactor）
- **Proactor 模式**：异步 I/O + 回调——IOCP
- **协程模型**：Go goroutine + 网络 I/O 自动挂起/恢复

# 第三章：应用层协议设计

### 3.1 协议设计原则
- **无状态 vs 有状态**：简单可扩展 vs 需要维持会话上下文
- **二进制 vs 文本**：Protobuf 二进制高效 vs JSON 文本可读
- **定长 vs 变长**：TLV（Type-Length-Value）变长编码
- **向后兼容性**：新增字段不可改已有字段的含义

### 3.2 HTTP 深度解析
- **HTTP/1.1**：持久连接（Keep-Alive）、管道化（Pipelining，队头阻塞严重）、分块传输（Transfer-Encoding: chunked）
- **HTTP/2**：二进制分帧层、多路复用（同一连接多个 Stream 并发，无队头阻塞...但 TCP 层面仍有）、头部压缩（HPACK，静态表+动态表+哈夫曼编码）、服务器推送（Server Push，已被 Chrome 移除）
- **HTTP/3 / QUIC**：基于 UDP，0-RTT 建立连接、无 TCP 队头阻塞（每个 Stream 独立）、连接迁移（切换 WIFI/4G 不断连）
- **HTTP 缓存**：强缓存（Cache-Control: max-age / Expires）+ 协商缓存（ETag / Last-Modified → 304 Not Modified）

### 3.3 自定义协议设计
- **魔数（Magic Number）**：协议头固定字节——快速识别你的协议
- **版本号**：协议演进的基础
- **序列化方式**：JSON / Protobuf / MessagePack / Hessian
- **分包策略**：固定长度头（含 Body 长度）+ Body——解决 TCP 粘包/拆包

# 第四章：负载均衡与反向代理

### 4.1 负载均衡层次
- **DNS 负载均衡**：域名解析返回不同 IP——简单但无健康检查
- **L4（传输层）负载均衡**：基于 IP+端口转发——F5、LVS（DR/TUN/NAT 模式）
- **L7（应用层）负载均衡**：基于 HTTP 内容路由——Nginx、HAProxy

### 4.2 负载均衡算法
- **静态算法**：轮询（Round-Robin）、加权轮询、IP Hash（会话保持）
- **动态算法**：最少连接、最短响应时间——Nginx 的 least_conn
- **一致性哈希**：节点增减时最少数据迁移——缓存层常用

### 4.3 Nginx 进阶
- **反向代理配置**：`proxy_pass`、超时设置、缓冲、header 传递
- **动静分离**：静态资源直接返回（try_files），动态请求代理到后端
- **限流**：`limit_req_zone`（请求频率限制）+ `limit_conn_zone`（并发连接限制）
- **健康检查**：主动（nginx_upstream_check_module）+ 被动（proxy_next_upstream）

# 第五章：网络性能调优与排障

### 5.1 网络性能指标
- **带宽、吞吐量、延迟（RTT）、抖动、丢包率**
- **TCP 吞吐量理论极限**：吞吐量 ≤ window_size / RTT

### 5.2 常见网络问题与排查
- **TCP 连接无法建立**：`telnet/nc` 测试端口可达性 → `tcpdump` 抓包看 SYN 有无回复
- **延迟高**：`ping`（RTT）、`traceroute/mtr`（逐跳分析）、`ss -ti`（TCP 信息，含 RTT/cwnd）
- **丢包**：`netstat -s`（TCP 统计）、网卡 error/drop 计数
- **连接数问题**：`ulimit -n`、`net.core.somaxconn`、`net.ipv4.tcp_max_syn_backlog`

### 5.3 内核参数调优
- `net.core.somaxconn`：全连接队列大小
- `net.ipv4.tcp_max_syn_backlog`：半连接队列大小
- `net.ipv4.tcp_tw_reuse`：TIME_WAIT 复用
- `net.ipv4.tcp_fin_timeout`：FIN_WAIT_2 超时时间
- `net.core.rmem_max / wmem_max`：最大接收/发送缓冲区
