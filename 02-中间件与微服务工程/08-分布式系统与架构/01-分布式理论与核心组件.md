# 分布式理论与核心组件

## 📌 课程定位
分布式系统是现代后端的基础设施。微服务、消息队列、缓存、注册中心——这些中间件是大厂后端的日常。理解CAP理论、一致性协议、RPC原理是进阶必备。

## 🎯 核心章节

### 1. 分布式理论基石（⭐ 面试必问）
- **CAP定理**：C(一致性) + A(可用性) + P(分区容错) 三者最多同时满足两个
  - P必须保证（网络分区不可避免），实际是CP还是AP的选择
  - CP：ZooKeeper/etcd（强一致性，牺牲部分可用性）
  - AP：Eureka/Nacos（高可用，允许短暂不一致）
- **BASE理论**：Basically Available(基本可用) + Soft State(软状态) + Eventually Consistent(最终一致性)
- **一致性模型**：强一致性→顺序一致性→因果一致性→最终一致性（从强到弱）

### 2. 分布式一致性协议
- **2PC/3PC（两阶段/三阶段提交）**：协调者+参与者——同步阻塞、单点故障问题
- **Paxos**：多数派协议——Basic Paxos(难理解)、Multi-Paxos
- **Raft（⭐ 易理解的主流）**：Leader选举+日志复制+安全性——etcd/Consul/TiKV采用
  - 三个角色：Leader(处理所有请求)→Follower(被动响应)→Candidate(候选)
  - Leader 选举：term+随机超时——先超时的成为Candidate

### 3. 消息队列（MQ, ⭐ 核心中间件）
- **为什么需要MQ**：削峰填谷、异步解耦、系统解耦
- **Kafka**（高吞吐）：
  - Topic→Partition(有序、可并行)→Segment文件，顺序写磁盘=极快
  - Consumer Group：同组内partition独占，不同组独立消费
  - 高水位(HW)+ISR保障一致性
- **RocketMQ**：事务消息、延迟消息——阿里系
- **RabbitMQ**：基于AMQP，Exchange→Queue→Consumer——灵活路由
- **MQ常见问题**：消息丢失(生产→MQ→消费三段都要确认)、重复消费(幂等设计)、消息积压

### 4. 缓存
- **Redis（⭐ 后端必会）**：
  - 5种基本类型：String(SDS/embstr)、List(双向链表/quicklist)、Hash(dict+zipList)、Set、ZSet(跳表+dict)
  - 持久化：RDB(快照)、AOF(命令日志)、混合持久化
  - 淘汰策略：LRU、LFU、TTL、随机——`maxmemory-policy`
  - 缓存三大问题：
    - 穿透：查不存在的数据→布隆过滤器/缓存空值
    - 击穿：热点key过期→互斥锁/永不过期
    - 雪崩：大量key同时过期→过期时间加随机值/多级缓存
  - 分布式锁：`SET key value NX EX 30` + Lua脚本安全释放(Redlock争议)

### 5. RPC（远程过程调用）
- **核心目标**：像调用本地方法一样调用远程服务
- **调用链路**：Client Stub(序列化)→网络→Server Stub(反序列化)→执行→返回
- **序列化**：JSON(可读但慢)/Protobuf(二进制，快)/Hessian/Thrift
- **gRPC**：基于HTTP/2+Protobuf——微服务主流选择
- **Dubbo**：Java生态的RPC框架——服务治理(注册/发现/负载均衡/容错)

### 6. 服务治理
- **注册中心**：Nacos(阿里，AP+CP可切换)、Consul、ZooKeeper(CP)
- **网关**：Spring Cloud Gateway、Kong、Nginx——统一入口+鉴权+限流
- **限流算法**：计数器、滑动窗口、令牌桶、漏桶
- **熔断降级**：Hystrix→Sentinel(阿里)——快速失败防止雪崩

## ✅ 学习建议
- CAP定理是分布式系统的"第一原理"——拿到任何系统先分析CP还是AP
- Kafka和Redis是最重要的两个中间件——深入理解其设计哲学
- 分布式系统《数据密集型应用系统设计》(DDIA)——必读神书
