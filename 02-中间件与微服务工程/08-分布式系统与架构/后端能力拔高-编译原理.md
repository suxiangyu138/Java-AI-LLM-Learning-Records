# 第一章：编译概述

### 1.1 编译器 vs 解释器
- **编译器**：源码 → 目标代码（一次性翻译，独立运行）—— C/C++/Rust/Go
- **解释器**：源码 → 逐行解释执行（不生成独立目标代码）—— Python/JavaScript/Ruby
- **JIT（即时编译）**：运行时间歇编译热点代码—— JVM HotSpot、V8 TurboFan
- **AOT（预编译）**：安装时/构建时编译—— Android ART

### 1.2 编译的五个阶段
```
源程序 → 词法分析 → 语法分析 → 语义分析 → 中间代码生成 → 代码优化 → 目标代码生成
```
- **前端**（语言相关）：词法分析 + 语法分析 + 语义分析 → 中间表示（IR）
- **中端**（IR相关）：中间代码优化——与语言和目标平台无关
- **后端**（目标平台相关）：目标代码生成 + 目标相关优化

### 1.3 编译的辅助组件
- **符号表（Symbol Table）**：记录标识符的类型、作用域、存储位置——贯穿所有阶段
- **错误处理器**：定位错误位置、错误类型、尝试恢复并继续编译

# 第二章：词法分析

### 2.1 词法分析器的作用
- 从左到右扫描源程序字符流 → 识别出有意义的词法单元（Token）
- Token 格式：<种别码（token type），属性值（token value）>
- 剔除空白、注释

### 2.2 正则表达式与正规文法
- **正规式 → 正规集**：描述 Token 的模式
- **正规文法（3型）↔ 正规式 ↔ 有限自动机**：三者等价，可互相转换

### 2.3 有限自动机
- **NFA（非确定有限自动机）**：同一输入可转移到多个状态，可有 ε 转移
- **DFA（确定有限自动机）**：每个状态 + 每个输入符号有唯一后继
- **NFA → DFA（子集构造法/确定化）**：
  1. ε-closure(s)：从状态 s 出发不消耗任何符号能到达的所有状态
  2. Move(T, a)：从集合 T 中的状态出发经过 a 能到达的状态
  3. 计算 ε-closure(Move(T, a)) 得到新的 DFA 状态
- **DFA 最小化**：划分法——初始分为接受状态组和非接受状态组 → 迭代划分直到不再细分

### 2.4 词法分析器的自动生成
- **Lex / Flex**：输入正则表达式 + 动作 → 生成 C 语言词法分析器

# 第三章：语法分析

### 3.1 上下文无关文法（CFG）
- **四元组 G = (Vn, Vt, P, S)**：非终结符集、终结符集、产生式集、开始符号
- **推导**：最左推导（每次替换最左非终结符）、最右推导（归约的逆过程）
- **语法分析树**：推导的树状表示——内结点=非终结符，叶结点=终结符
- **二义性**：一个句子有两棵及以上语法分析树——需要消除或通过规则解决（如 else 匹配最近 if）

### 3.2 自上而下分析（LL 分析法）
- **LL(1) 文法的条件**：无左递归 + 每个非终结符的各产生式的 SELECT 集两两不相交
- **FIRST(α)**：可以从 α 推导得到的串的首终结符集合
- **FOLLOW(A)**：可能紧跟在 A 后面的终结符集合
- **SELECT(A→α)** = FIRST(α) 若 α 不可推出 ε；= FIRST(α) ∪ FOLLOW(A) 若 α 可推出 ε
- **预测分析表**：M[A, a] = 当面临输入 a 时非终结符 A 应该选哪个产生式
- **递归下降分析法**：每个非终结符写一个函数——手写 Parser 的基础
- **LL(1) 的局限性**：不能处理左递归，需要提取左公因子

### 3.3 自下而上分析（LR 分析法）
- **核心思想**：移进-归约——从左到右扫描，识别出句柄（可归约的串）就归约
- **活前缀**：右句型的前缀，不超过句柄的右端
- **LR(0) → SLR(1) → LR(1) → LALR(1)**：分析能力递增，状态数不同
- **LR 项目**：[A→α·β, a]——圆点的位置表示已识别的进度
- **SLR(1)**：利用 FOLLOW 集解决移进-归约冲突
- **LR(1)**：在每个项目中附带前瞻符号——状态数膨胀
- **LALR(1)**：合并 LR(1) 中同心集（核心相同，前瞻不同）——Yacc/Bison 使用，折中方案

### 3.4 语法分析器的自动生成
- **Yacc / Bison**：输入 CFG 规则 + 语义动作 → 生成 C 语言 LALR(1) 分析器
- **ANTLR**：Java 生态的 LL(*) 分析器生成器——更现代、更友好

# 第四章：语法制导翻译与语义分析

### 4.1 语法制导定义（SDD）
- **综合属性**：结点属性值由子结点计算（自底向上）
- **继承属性**：结点属性值由父结点/兄弟结点计算（自顶向下）
- **S-属性定义**：只含综合属性——适合自底向上（LR 分析时边归约边计算）
- **L-属性定义**：继承属性只依赖父结点或左边兄弟——适合自上而下（LL 分析/递归下降）

### 4.2 语法制导翻译（SDT）
- **SDT 是在产生式体中嵌入了语义动作的上下文无关文法**
- 语义动作的执行时机取决于分析方式（LL/LR）

### 4.3 语义分析
- **类型检查**：类型表达式、类型等价（名字等价 vs 结构等价）、类型转换（隐式/显式）
- **作用域分析**：静态作用域（词法作用域，大多数语言）vs 动态作用域
- **类型系统**：强类型/弱类型、静态类型/动态类型

# 第五章：中间代码生成

### 5.1 中间表示（IR）的作用
- 解耦前端和后端——N 种语言 × M 种平台 → N 个前端 + M 个后端（vs N×M 个编译器）
- 便于进行机器无关的优化

### 5.2 三地址码（TAC）
- 每条指令最多一个操作符 + 最多三个地址
- 形式：`x = y op z`、`x = op y`、`x = y`、`goto L`、`if x goto L`、`if x relop y goto L`
- **生成方法**：对 AST 递归生成或对 SDT 归约时生成

### 5.3 中间表示的其他形式
- **语法树（AST/DAG）**：DAG（有向无环图）可共享公共子表达式
- **静态单赋值（SSA）**：每个变量只被赋值一次——所有现代优化编译器的基础
  - φ 函数：在控制流汇合点合并不同来源的值
- **LLVM IR**：最著名的现代编译器 IR——类 SSA、类型化、低层但独立于目标

# 第六章：代码优化

### 6.1 优化的层次
- **局部优化**：基本块内——常量折叠、代数简化、死代码消除
- **全局优化**：跨基本块——全局公共子表达式消除、代码外提（循环不变量）
- **过程间优化**：跨函数——内联（inline）、过程间常量传播

### 6.2 常见优化技术
- **常量折叠（Constant Folding）**：`2+3*4` 编译期算成 `14`
- **常量传播（Constant Propagation）**：`x=3; y=x*2` → `y=6`
- **死代码消除（Dead Code Elimination）**：删掉不会被执行/结果不用的代码
- **公共子表达式消除（CSE）**：`a=b*c; d=b*c` → `a=b*c; d=a`
- **循环优化**：
  - 代码外提（Loop-Invariant Code Motion）：循环中不变的计算移到循环外
  - 强度削弱（Strength Reduction）：乘法变加法
  - 循环展开（Loop Unrolling）：复制循环体减少迭代次数
- **函数内联（Inlining）**：将函数调用替换为函数体——消除调用开销，但增大代码体积

### 6.3 数据流分析
- **到达定值分析**：某个定值（定义）能到达程序的哪些点
- **活跃变量分析**：哪些变量在离开某个点后还会被使用——用于寄存器分配
- **可用表达式分析**：哪些表达式已经计算过且结果尚未失效

# 第七章：目标代码生成

### 7.1 目标代码生成的输入与输出
- 输入：优化后的 IR + 符号表
- 输出：汇编代码 / 机器代码 / 目标文件

### 7.2 指令选择
- 将 IR 操作映射为具体目标机器的指令——树覆盖（Tree Covering）/ 贪心 / 动态规划

### 7.3 寄存器分配（⭐ 核心难点）
- **目标**：将尽量多的变量放入寄存器（而非内存），因为寄存器比内存快 100+ 倍
- **图着色算法（Chaitin/Briggs）**：
  1. 构建冲突图：两个变量同时活跃 → 它们之间有边
  2. 用 K（可用寄存器数）种颜色着色 → 相邻结点不同色
  3. 若无法着色，选一个变量溢出（Spill）到内存
- **线性扫描分配**：更简单、更快——JIT 编译器常用（HotSpot C1）

### 7.4 指令调度
- 重新排列指令顺序以充分利用流水线——避免数据冒险导致的流水线停顿

# 第八章：运行时环境

### 8.1 存储组织
- **栈（Stack）**：局部变量、函数返回地址、参数传递——LIFO
- **堆（Heap）**：动态分配——malloc/free 或 new/delete 或 GC 管理
- **静态区**：全局变量、静态变量、常量

### 8.2 调用约定（Calling Convention）
- **cdecl**：调用者清理栈——C 默认
- **stdcall**：被调用者清理栈——Win32 API
- **fastcall**：前几个参数通过寄存器传递

### 8.3 垃圾回收（GC）
- **标记-清除（Mark-Sweep）**：标记可达对象 → 清除不可达——碎片化
- **标记-复制（Mark-Copy）**：可达对象复制到新空间——无碎片
- **分代收集（Generational GC）**：弱分代假说——大多数对象朝生夕死，分成年轻代和老年代
