## 1. 负载均衡策略

### 1.1 七种策略对比

| 策略 | 别名 | 原理 | 适用场景 |
|------|------|------|----------|
| **Random** | 随机 + 权重 | 按权重随机选择 | ⭐ 默认，通用 |
| **RoundRobin** | 轮询 + 权重 | 按权重轮询分配 | 请求均匀 |
| **LeastActive** | 最小活跃数 | 选当前处理请求最少的 | 长连接/耗时不均 |
| **ShortestResponse** | 最短响应时间 | 选历史响应最快的（滑动窗口） | 异构机器 |
| **ConsistentHash** | 一致性哈希 | 同参数请求路由到同一 Provider | 有状态服务 |
| **Sticky** | 粘滞连接 | 同一 Consumer 始终连同 Provider | — |
| **Custom** | 自定义 | 实现 `LoadBalance` SPI | 特殊需求 |

### 1.2 配置方式

```yaml
# 全局配置（Consumer 端）
dubbo:
  consumer:
    loadbalance: roundrobin
```

```java
// 接口级配置（优先级更高）
@DubboReference(loadbalance = "leastactive")
private UserService userService;
```

### 1.3 权重调节

```text
权重适用场景：
  机器配置不同：高性能机器 weight=200，普通 weight=100
  无损上下线：重启前先设 weight=0 → 等待流量排干 → 下线上线后逐步恢复权重
  灰度验证：新版本先 weight=10，验证通过后调到 100
```

```yaml
# 静态权重
dubbo:
  provider:
    weight: 200
```

```java
// 动态权重（通过 Dubbo Admin 调整，无需重启）
// Dubbo Admin → 服务治理 → 权重调节
```

## 2. 集群容错策略

### 2.1 六种策略对比

| 策略 | 行为 | 适用场景 |
|------|------|----------|
| **Failover** | 失败后切换另一个 Provider 重试（默认） | ⭐ 幂等读操作 |
| **Failfast** | 失败立即报错，不重试 | 非幂等写操作 |
| **Failsafe** | 失败后吞掉异常、记录日志 | 旁路逻辑（日志/审计） |
| **Failback** | 失败后后台定时重试 | 消息通知 |
| **Forking** | 并行调用多个 Provider，取最快返回 | 实时性要求高 |
| **Broadcast** | 逐个调用所有 Provider，任一失败即报错 | 通知所有 Provider |

### 2.2 配置

```java
// Failover + 重试 2 次
@DubboReference(cluster = "failover", retries = 2)
private UserService userService;
```

```yaml
dubbo:
  consumer:
    cluster: failover
    retries: 0    # ⚠️ 非幂等接口设为 0！
```

### 2.3 Failover 重试机制

```text
调用 userService.getUser(1)：
  1 → Provider A(超时) → 重试 Provider B → 成功
  ↑ 总共一次原始调用 + 一次重试

⚠️ 风险：非幂等操作（如扣款）重试可能造成重复操作！
  → 非幂等接口：cluster=failfast, retries=0
  → 幂等接口：cluster=failover, retries=2
```

## 3. 服务降级与 Mock

### 3.1 强制降级

```java
// Mock 类：与服务接口同包
public class UserServiceMock implements UserService {
    @Override
    public User getUser(Long id) {
        return new User(0L, "降级用户", 0);  // 返回兜底数据
    }
}
```

```java
@DubboReference(mock = "com.example.UserServiceMock")
private UserService userService;
```

### 3.2 动态降级（Dubbo Admin 控制）

```
Dubbo Admin → 服务治理 → 降级
  ├── 屏蔽：直接返回 null / 空对象（不发起远程调用）
  └── 容错：远程调用失败后返回 Mock
```

## 4. 限流配置

### 4.1 Provider 端限流

```yaml
dubbo:
  provider:
    executes: 100         # 每接口最大并发执行数
    actives: 50           # 每客户端最大并发数
```

```java
// 注解级
@DubboService(executes = 100)
public class UserServiceImpl implements UserService { }
```

### 4.2 Sentinel 集成限流

```xml
<dependency>
    <groupId>org.apache.dubbo</groupId>
    <artifactId>dubbo-sentinel-spring-boot-starter</artifactId>
</dependency>
```

```java
@DubboService
@SentinelResource(value = "getUser", blockHandler = "getUserBlock")
public class UserServiceImpl implements UserService {
    // 被限流后走 getUserBlock
}
```

## 5. 最佳实践组合

| 场景 | 负载均衡 | 容错 | 重试 | 说明 |
|------|:---:|:---:|:---:|------|
| 查询类接口 | Random | Failover | 2 | 幂等，可重试 |
| 写入类接口 | Random | Failfast | 0 | 非幂等，不可重试 |
| 耗时不均 | LeastActive | Failover | 1 | 自动选最快 |
| 有状态路由 | ConsistentHash | Failfast | 0 | 同参数同 Provider |
| 异步事件 | RoundRobin | Failback | — | 失败后台补发 |
| 实时要求高 | Random | Forking | — | 并发调用取最快 |

> 🎯 **口诀**：默认 Random+Failover 够用；写操作 Failfast+retries=0；异构机器用 LeastActive；有状态用 ConsistentHash。
