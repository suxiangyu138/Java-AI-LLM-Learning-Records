## 1. 协议概述

Dubbo 支持多种通信协议，核心区别在于传输层和序列化方式：

| 协议 | 传输层 | 序列化(默认) | 特点 |
|------|:---:|------|------|
| **dubbo** (dubbo2) | TCP (Netty) | Hessian2 | ⭐ 经典高性能、长连接、NIO |
| **tri** (triple) | HTTP/2 (Netty) | Protobuf | ⭐ Dubbo 3.x 主推、兼容 gRPC |
| **rest** | HTTP | JSON | RESTful 风格 |
| **grpc** | HTTP/2 | Protobuf | 官方 gRPC 实现 |
| **hessian** | HTTP | Hessian | 兼容旧系统 |

## 2. Dubbo2 协议（经典 TCP 协议）

### 2.1 协议头（16 字节固定头）

```text
 0-1 字节：Magic Number (0xdabb)
 2   字节：序列化 ID + 事件标志
 3   字节：状态码
 4-11 字节：Request ID (8 字节，唯一标识一次调用)
 12-15 字节：Body 长度

特点：
  - 固定头设计，解析速度快
  - 单一长连接（连接复用，减少握手开销）
  - 默认 Netty NIO 实现
```

### 2.2 配置

```yaml
dubbo:
  protocol:
    name: dubbo
    port: 20880
    serialization: hessian2       # 序列化方式
    threadpool: fixed             # 线程池类型
    threads: 200                  # 业务线程数
    payload: 8388608              # 最大请求大小 (8MB)
```

### 2.3 线程模型

```
Netty IO 线程 → 处理网络读写（不阻塞）
    ↓
Dubbo 业务线程池 → 处理业务逻辑（隔离网络与业务）
    ↓
Provider 实现

三种线程池类型：
├── fixed (固定大小) — 默认，适合稳定流量
├── cached (可伸缩) — 适合流量波动大
└── limited (有限制) — 防止线程无限增长
```

## 3. Triple 协议（新一代 HTTP/2 协议）

> 🎯 Triple 是 Dubbo 3.x 定义的新协议，基于 HTTP/2 + Protobuf，完全兼容 gRPC。

### 3.1 核心特性

| 特性 | 说明 |
|------|------|
| **HTTP/2** | 多路复用、头部压缩、Server Push |
| **Protobuf** | 高性能二进制序列化 |
| **兼容 gRPC** | gRPC 客户端可直接调用 Triple 服务 |
| **跨语言** | Go/Node.js/Python 客户端可调用 Java Dubbo |
| **流式调用** | Client Stream / Server Stream / Bidirectional Stream |
| **穿透网关** | HTTP/2 天然支持网关/负载均衡 |

### 3.2 配置

```yaml
dubbo:
  protocol:
    name: tri
    port: 50051
```

```java
// 流式调用 — Server Stream
public interface UserService {
    // 返回 Stream：服务端推送多条数据
    @DubboService
    StreamObserver<User> listUsers(StreamObserver<User> response);
}

// 使用
userService.listUsers(new StreamObserver<User>() {
    @Override public void onNext(User user) { /* 收到一条 */ }
    @Override public void onError(Throwable t) { /* 错误 */ }
    @Override public void onCompleted() { /* 完成 */ }
});
```

### 3.3 Triple vs Dubbo2

| 维度 | Triple | Dubbo2 |
|------|--------|--------|
| 传输层 | HTTP/2 | TCP 自定义 |
| 序列化 | Protobuf（默认） | Hessian2 |
| 跨语言 | ✅ 原生支持 | ❌ |
| 流式调用 | ✅ Client/Server/Bi Stream | ❌ (仅 req-res) |
| 网关穿透 | ✅ HTTP/2 天然 | ❌ 需协议转换 |
| 性能 | ⭐⭐⭐ 略低于 dubbo2 | ⭐⭐⭐ 最高 |
| **推荐** | Dubbo 3.x 新项目 | 纯 Java 高性能场景 |

## 4. 序列化方案对比

| 序列化 | 类型 | 大小 | 速度 | 可读性 | 跨语言 | 推荐度 |
|--------|:---:|:---:|:---:|:---:|:---:|:---:|
| **Hessian2** | 二进制 | 小 | ⭐⭐⭐ 快 | ❌ | ❌ | Dubbo2 默认 |
| **Protobuf** | 二进制 | ⭐ 最小 | ⭐⭐⭐ 最快 | ❌ | ✅ | Triple 推荐 |
| **JSON** | 文本 | 大 | ⭐⭐ 慢 | ✅ | ✅ | REST/调试 |
| **Kryo** | 二进制 | 很小 | ⭐⭐⭐ 快 | ❌ | ❌ | 高性能场景 |
| **FST** | 二进制 | 很小 | ⭐⭐⭐ 快 | ❌ | ❌ | 高性能替代 |
| **Java Serializable** | 二进制 | 大 | ⭐ 最慢 | ❌ | ❌ | ❌ 不推荐 |

### 序列化切换

```yaml
dubbo:
  protocol:
    serialization: kryo    # 切换为 Kryo
```

```xml
<!-- Kryo 依赖 -->
<dependency>
    <groupId>org.apache.dubbo</groupId>
    <artifactId>dubbo-serialization-kryo</artifactId>
</dependency>
```

> ⚠️ **不要用 Java Serializable！** 体积大、速度慢、安全性差。Hessian2/Protobuf/Kryo 三选一。

## 5. 协议选型指南

| 场景 | 推荐协议 | 序列化 | 理由 |
|------|:---:|------|------|
| 纯 Java 微服务 | dubbo2 | Hessian2 | 性能最优、成熟稳定 |
| 需要跨语言调用 | triple | Protobuf | 兼容 gRPC、跨语言 |
| Dubbo 3.x 新项目 | triple | Protobuf | 未来方向、流式调用 |
| 对外开放 API | rest | JSON | RESTful、易调试 |
| 高性能内部调用 | dubbo2 | Kryo | 极致性能 |
| 网关/服务网格 | triple | Protobuf | 网关友好、统一协议 |

> 🎯 **选型口诀**：纯 Java 内部用 Dubbo2+Hessian2；需要跨语言/流式/上云用 Triple+Protobuf；对外 API 用 REST+JSON。Dubbo 3.x 推荐新系统优先 Triple。
