# 开发流程与项目管理

## 📌 课程定位
软件工程不是"学管理"，而是"学如何不把项目做崩"。从个人编码到团队协作，从需求分析到上线维护，软件工程提供了一套可复用的方法论。

## 🎯 核心章节

### 1. 软件生命周期
```
需求分析 → 系统设计 → 编码实现 → 测试 → 部署 → 运维
```
- **瀑布模型**：阶段严格顺序——需求明确时高效，变更成本高
- **敏捷开发（⭐ 主流）**：迭代+增量+快速反馈——Scrum、Kanban
  - Scrum三角色：Product Owner(定需求)、Scrum Master(保流程)、Dev Team
  - Sprint：固定时间盒(通常2周)→Sprint Plan→Daily Standup→Sprint Review→Retro
- **DevOps**：开发+运维一体化——CI/CD自动化流水线

### 2. 需求分析
- **功能性需求**：系统"做什么"——用户故事(As a...I want...So that...)
- **非功能性需求**：性能、安全、可用性、可扩展性
- **需求优先级**：MoSCoW(Must/Should/Could/Won't have)

### 3. 系统设计
- **概要设计**：模块划分、架构选型、技术栈
- **详细设计**：类设计、接口定义、数据库设计(ER图→表结构)
- **设计文档**：架构图(C4模型)、时序图、接口文档(Swagger/OpenAPI)

### 4. 版本管理（Git工作流）
- **Git Flow**：main/release/develop/feature/hotfix——适合有版本发布的传统软件
- **GitHub Flow**：main + feature分支——简单，适合持续部署的Web应用
- **Trunk-Based**：所有人往main提交，极短的特性分支——高级团队的选择
- **Code Review**：每个PR至少一人Review——知识共享+质量保证

### 5. 测试策略
- **测试金字塔**：单元测试(底层)→集成测试→端到端测试(顶层)——底层多、顶层少
- **TDD（测试驱动开发）**：红(写失败的测试)→绿(写最少代码通过)→重构
- **测试覆盖率**：行覆盖/分支覆盖——80%+即可，100%不现实

### 6. 项目管理基础
- **估算**：故事点(相对大小)、计划扑克
- **燃尽图**：剩余工作量随时间递减
- **技术债**：为了快速交付牺牲代码质量——需要有计划地偿还
- **事后复盘(Postmortem)**：故障/项目结束后的无责分析

## ✅ 学习建议
- 理论结合实践——在课程设计/竞赛项目中用Git+敏捷方式协作
- Git工作流是团队协作的基础——GitHub上找开源项目参与，感受PR流程
- 软件工程不只是"写文档"，核心是管理复杂度和应对变化
