# 软件测试核心

## 📌 课程定位
测试不是"测试工程师的事"——每个开发者都要为自己的代码质量负责。单元测试、集成测试、自动化测试是现代软件工程的基础实践，TDD更是极限编程的核心。

## 🎯 核心章节

### 1. 测试基础概念
- **测试目的**：发现错误，证明软件满足需求——不是为了证明"软件是对的"
- **测试原则**：
  1. 穷举测试不可能——用等价类/边界值选代表性用例
  2. 测试有"集群性"——80%的错误集中在20%的模块
  3. 杀虫剂悖论：同一组用例重复会使测试失效——需要不断更新
  4. 尽早测试：缺陷发现越晚修复成本越高（需求阶段vs生产环境，差100倍+）

### 2. 测试分类
- **按阶段**：
  - 单元测试：单个函数/方法——开发者自己写，最底层
  - 集成测试：模块间接口——联调验证
  - 系统测试：完整系统——功能+性能+安全
  - 验收测试：用户角度验证——UAT(User Acceptance Test)
- **按是否看代码**：
  - 黑盒测试：不看代码，关注输入输出——等价类、边界值、因果图
  - 白盒测试：看代码，关注逻辑覆盖——语句覆盖→分支覆盖→路径覆盖
  - 灰盒测试：两者结合

### 3. 测试用例设计方法
- **等价类划分**：把输入分为有效等价类和无效等价类——每类至少一个用例
- **边界值分析**：边界上、边界内、边界外——bug常出现在边界(如数组越界、溢出)
- **判定表/因果图**：多条件组合场景 → 用表格枚举
- **场景法**：模拟用户实际使用流程——主流程+分支流程

### 4. 单元测试实践（⭐ 开发者核心）
- **JUnit（Java）**：`@Test`、`assertEquals`、`assertThrows`
  ```java
  @Test
  void shouldReturnSum() {
      assertEquals(5, calculator.add(2, 3));
  }
  ```
- **pytest（Python）**：`assert`、`@pytest.mark.parametrize`、`conftest.py`(fixture)
  ```python
  def test_add():
      assert add(2, 3) == 5
  ```
- **Mock/Stub**：模拟外部依赖——数据库、网络请求、文件系统
  - Mockito(Java)、unittest.mock(Python)
- **好的单元测试特征**：独立(不依赖其他测试)、可重复、快速、自验证

### 5. 自动化测试
- **CI/CD 集成测试**：每次push自动运行测试套件——GitHub Actions/Jenkins
- **端到端测试(E2E)**：Selenium/Playwright/Cypress 模拟浏览器操作
- **接口测试**：Postman/JMeter——测试REST API
- **性能测试**：JMeter/Gatling——并发用户、响应时间、吞吐量

### 6. TDD（测试驱动开发）
- **红→绿→重构**循环：
  1. 红：写一个失败的测试
  2. 绿：写最少代码让测试通过
  3. 重构：优化代码设计，保持测试通过
- **优点**：测试先行→代码天然可测试→减少Bug→重构有底气
- **适用场景**：核心业务逻辑、工具库、算法实现
- **不适用**：UI频繁变化、原型探索、一次性脚本

## ✅ 学习建议
- 从单元测试开始——给自己的项目加上测试覆盖
- 重点理解等价类+边界值——最常用最有效的测试设计方法
- Mock是写单元测试的核心技能——学会隔离外部依赖
- 测试不是"附加项"，而是"质量内嵌"——养成边开发边写测试的习惯
