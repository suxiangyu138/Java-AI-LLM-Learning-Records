## 1. 为什么设计模式在 Java 企业级开发中重要

### 1.1 设计模式的价值

设计模式不是教条，而是**经过验证的、可复用的解决方案**，用于解决特定场景下的通用设计问题。

| 维度 | 没有设计模式 | 使用设计模式 |
|------|------------|-------------|
| 可读性 | 新成员需要阅读全部代码才能理解架构 | 模式名传递设计意图 |
| 可维护性 | 修改一个功能可能影响多处 | 职责分离，变更局部化 |
| 可扩展性 | 新增功能需要大量改动 | 开闭原则，新增不修改 |
| 可测试性 | 代码耦合度高，难以 mock | 依赖倒置，易于测试 |
| 团队协作 | 每个人按自己的方式实现 | 统一的设计语言 |

### 1.2 模式在 Spring 中的体现

```text
Singleton        → Spring Bean (默认 scope)
Factory Method   → BeanFactory, getBean()
Abstract Factory → @Bean 方法, FactoryBean
Builder          → UriComponentsBuilder, MockMvc
Prototype        → @Scope("prototype")
Adapter          → HandlerAdapter, JdbcTemplate
Decorator        → HttpServletRequestWrapper
Proxy            → AOP (JDK Proxy / CGLIB)
Facade           → JdbcTemplate (封装 JDBC 细节)
Observer         → ApplicationEvent / ApplicationListener
Strategy         → ResourceLoader, AuthenticationProvider
Template Method  → JdbcTemplate, RestTemplate
Chain of Resp.   → FilterChain, HandlerInterceptor
Command          → JdbcTemplate callback
Iterator         → Collections framework
State            → OAuth2, 订单状态机
```

## 2. 创建型模式

### 2.1 Singleton (单例)

**意图：** 确保一个类只有一个实例，并提供一个全局访问点。

```java
// 1. 饿汉式 (类加载时创建)
public class SingletonEager {
    private static final SingletonEager INSTANCE = new SingletonEager();
    private SingletonEager() {}
    public static SingletonEager getInstance() {
        return INSTANCE;
    }
}

// 2. 懒汉式 (双重检查锁定 DCL)
public class SingletonLazy {
    private static volatile SingletonLazy instance;
    private SingletonLazy() {}

    public static SingletonLazy getInstance() {
        if (instance == null) {
            synchronized (SingletonLazy.class) {
                if (instance == null) {
                    instance = new SingletonLazy();
                }
            }
        }
        return instance;
    }
}

// 3. 枚举方式 (最佳实践 — 线程安全、防反序列化)
public enum SingletonEnum {
    INSTANCE;

    public void doSomething() {
        // ...
    }
}

// 使用: SingletonEnum.INSTANCE.doSomething();

// 4. 静态内部类 (延迟加载，线程安全)
public class SingletonHolder {
    private SingletonHolder() {}

    private static class Holder {
        private static final SingletonHolder INSTANCE = new SingletonHolder();
    }

    public static SingletonHolder getInstance() {
        return Holder.INSTANCE;
    }
}
```

```java
// 基于 Redis 的分布式锁实现
@Component
public class DistributedLock {
    @Autowired
    private StringRedisTemplate redisTemplate;

    public boolean tryLock(String key, String value, long timeoutMs) {
        return Boolean.TRUE.equals(
            redisTemplate.opsForValue()
                .setIfAbsent(key, value, Duration.ofMillis(timeoutMs))
        );
    }

    public void unlock(String key, String value) {
        // 使用 Lua 脚本确保原子性
        String script = "if redis.call('get', KEYS[1]) == ARGV[1] " +
            "then return redis.call('del', KEYS[1]) else return 0 end";
        redisTemplate.execute(
            new DefaultRedisScript<>(script, Long.class),
            List.of(key), value
        );
    }
}
```

```java
public class Order {
    private final String orderNumber;
    private final BigDecimal amount;
    private final String currency;
    private final String description;

    private Order(Builder builder) {
        this.orderNumber = builder.orderNumber;
        this.amount = builder.amount;
        this.currency = builder.currency;
        this.description = builder.description;
    }

    public static Builder builder() {
        return new Builder();
    }

    public static class Builder {
        private String orderNumber;
        private BigDecimal amount;
        private String currency = "CNY";  // 默认值
        private String description;

        public Builder orderNumber(String orderNumber) {
            if (orderNumber == null || orderNumber.length() < 8) {
                throw new IllegalArgumentException("Order number must be at least 8 chars");
            }
            this.orderNumber = orderNumber;
            return this;
        }

        public Builder amount(BigDecimal amount) {
            if (amount == null || amount.compareTo(BigDecimal.ZERO) <= 0) {
                throw new IllegalArgumentException("Amount must be positive");
            }
            this.amount = amount;
            return this;
        }

        public Builder description(String description) {
            this.description = description;
            return this;
        }

        public Order build() {
            Objects.requireNonNull(orderNumber, "orderNumber must not be null");
            Objects.requireNonNull(amount, "amount must not be null");
            return new Order(this);
        }
    }
}
```

### 3.2 Decorator (装饰器)

```java
// 基础接口
public interface DataSource {
    void writeData(String data);
    String readData();
}

// 基础实现
public class FileDataSource implements DataSource {
    private final String filename;

    public FileDataSource(String filename) {
        this.filename = filename;
    }

    @Override
    public void writeData(String data) {
        System.out.println("Write to file: " + data);
    }

    @Override
    public String readData() {
        return "data from file";
    }
}

// 装饰器基类
public abstract class DataSourceDecorator implements DataSource {
    protected DataSource wrappee;

    public DataSourceDecorator(DataSource wrappee) {
        this.wrappee = wrappee;
    }

    @Override
    public void writeData(String data) {
        wrappee.writeData(data);
    }

    @Override
    public String readData() {
        return wrappee.readData();
    }
}

// 具体装饰器
public class EncryptionDecorator extends DataSourceDecorator {
    public EncryptionDecorator(DataSource wrappee) {
        super(wrappee);
    }

    @Override
    public void writeData(String data) {
        super.writeData(encrypt(data));
    }

    @Override
    public String readData() {
        return decrypt(super.readData());
    }

    private String encrypt(String data) {
        return "encrypted(" + data + ")";
    }

    private String decrypt(String data) {
        return data.replace("encrypted(", "").replace(")", "");
    }
}

public class CompressionDecorator extends DataSourceDecorator {
    public CompressionDecorator(DataSource wrappee) {
        super(wrappee);
    }

    @Override
    public void writeData(String data) {
        super.writeData(compress(data));
    }

    @Override
    public String readData() {
        return decompress(super.readData());
    }

    private String compress(String data) {
        return "compressed(" + data + ")";
    }

    private String decompress(String data) {
        return data.replace("compressed(", "").replace(")", "");
    }
}

// 使用
DataSource source = new CompressionDecorator(
    new EncryptionDecorator(
        new FileDataSource("test.txt")
    )
);
source.writeData("Hello World");
// 输出: Write to file: compressed(encrypted(Hello World))

// JDK 中的例子:
// - BufferedInputStream(FileInputStream) — 经典装饰器
// - Collections.synchronizedList(list) — 线程安全装饰
// - HttpServletRequestWrapper — Servlet 请求包装
```

```java
// 性能监控代理
public class PerformanceProxy implements InvocationHandler {
    private final Object target;

    public PerformanceProxy(Object target) {
        this.target = target;
    }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        long start = System.currentTimeMillis();
        Object result = method.invoke(target, args);
        long elapsed = System.currentTimeMillis() - start;
        System.out.println(method.getName() + " took " + elapsed + "ms");
        return result;
    }

    @SuppressWarnings("unchecked")
    public static <T> T createProxy(T target) {
        return (T) Proxy.newProxyInstance(
            target.getClass().getClassLoader(),
            target.getClass().getInterfaces(),
            new PerformanceProxy(target)
        );
    }
}

// 2. CGLIB 代理 (基于类，不需要接口)
// Spring AOP 默认选择:
//   - 目标类实现了接口 → JDK 动态代理
//   - 目标类没有实现接口 → CGLIB

// 3. Spring AOP 声明式代理
@Aspect
@Component
public class LoggingAspect {
    @Around("execution(* com.company.service.*.*(..))")
    public Object logAround(ProceedingJoinPoint joinPoint) throws Throwable {
        Logger log = LoggerFactory.getLogger(joinPoint.getTarget().getClass());
        log.info("Entering: {}", joinPoint.getSignature());
        try {
            Object result = joinPoint.proceed();
            log.info("Exiting: {}", joinPoint.getSignature());
            return result;
        } catch (Exception e) {
            log.error("Error in: {}", joinPoint.getSignature(), e);
            throw e;
        }
    }
}
```

```java
// 复杂子系统
class InventoryService {
    public boolean checkStock(String sku, int quantity) {
        return true;  // 检查库存
    }

class PaymentService {
    public String processPayment(BigDecimal amount) {
        return "txn_123";  // 处理支付

    public String createShipment(String address) {
        return "SF1234567890";  // 创建物流
    }
}

class NotificationService {
    public void sendEmail(String email, String content) {
        // 发送邮件
    }
}

// Facade: 简化对外接口
@Component
public class OrderFacade {
    private final InventoryService inventoryService;
    private final PaymentService paymentService;
    private final ShippingService shippingService;
    private final NotificationService notificationService;

    public OrderFacade(InventoryService inventoryService,
                       PaymentService paymentService,
                       ShippingService shippingService,
                       NotificationService notificationService) {
        this.inventoryService = inventoryService;
        this.paymentService = paymentService;
        this.shippingService = shippingService;
        this.notificationService = notificationService;
    }

    public OrderResult placeOrder(OrderRequest request) {
        // 1. 检查库存
        if (!inventoryService.checkStock(request.getSku(), request.getQuantity())) {
            throw new BusinessException("Insufficient stock");
        }

        // 2. 处理支付
        String txnId = paymentService.processPayment(request.getAmount());

        // 3. 创建物流
        String trackingNumber = shippingService.createShipment(request.getAddress());

        // 4. 发送通知
        notificationService.sendEmail(request.getEmail(), "Order placed: " + txnId);

        return new OrderResult(txnId, trackingNumber);
    }
}

// 客户端只需调用一个方法
@RestController
public class OrderController {
    @Autowired
    private OrderFacade orderFacade;

    @PostMapping("/orders")
    public OrderResult createOrder(@RequestBody OrderRequest request) {
        return orderFacade.placeOrder(request);
    }
}
```

### 3.5 Composite (组合)

```java
// 组件接口
public interface FileSystemNode {
    String getName();
    long getSize();
    void display(String indent);
}

// 叶子节点: 文件
public class File implements FileSystemNode {
    private String name;
    private long size;

    public File(String name, long size) {
        this.name = name;
        this.size = size;
    }

    @Override
    public String getName() { return name; }

    @Override
    public long getSize() { return size; }

    @Override
    public void display(String indent) {
        System.out.println(indent + "📄 " + name + " (" + size + " bytes)");
    }
}

// 容器节点: 目录
public class Directory implements FileSystemNode {
    private String name;
    private List<FileSystemNode> children = new ArrayList<>();

    public Directory(String name) {
        this.name = name;
    }

    public void add(FileSystemNode node) {
        children.add(node);
    }

    public void remove(FileSystemNode node) {
        children.remove(node);
    }

    @Override
    public String getName() { return name; }

    @Override
    public long getSize() {
        return children.stream()
            .mapToLong(FileSystemNode::getSize)
            .sum();
    }

    @Override
    public void display(String indent) {
        System.out.println(indent + "📁 " + name + "/");
        for (FileSystemNode child : children) {
            child.display(indent + "  ");
        }
    }
}

// 使用
Directory root = new Directory("root");
Directory docs = new Directory("docs");
docs.add(new File("readme.md", 1024));
docs.add(new File("guide.md", 2048));
root.add(docs);
root.add(new File("pom.xml", 512));
root.display("");
```

### 4.3 Template Method (模板方法)

```java
// 模板: 定义流程骨架，子类实现具体步骤
public abstract class PaymentHandler {

    // 模板方法 — 定义支付流程
    public final PaymentResult handlePayment(PaymentRequest request) {
        // 1. 校验参数 (子类可覆盖)
        validate(request);

        // 2. 创建支付订单 (子类可覆盖)
        PaymentOrder order = createPaymentOrder(request);

        // 3. 调用支付网关 (子类必须实现)
        PaymentResult result = callGateway(order);

        // 4. 处理支付结果 (子类可覆盖)
        if (result.isSuccess()) {
            onSuccess(order, result);
        } else {
            onFailure(order, result);
        }

        // 5. 发送通知 (钩子方法)
        if (shouldNotify(result)) {
            sendNotification(order);
        }

        return result;
    }

    // 具体步骤 — 子类必须实现
    protected abstract PaymentResult callGateway(PaymentOrder order);

    // 可选覆盖 — 默认实现
    protected void validate(PaymentRequest request) {
        Objects.requireNonNull(request, "Payment request must not be null");
    }

    protected PaymentOrder createPaymentOrder(PaymentRequest request) {
        return new PaymentOrder(request);
    }

    protected void onSuccess(PaymentOrder order, PaymentResult result) {
        log.info("Payment success: {}", order.getId());
    }

    protected void onFailure(PaymentOrder order, PaymentResult result) {
```

### 4.4 Chain of Responsibility (责任链)

```java
// 抽象处理者
public abstract class OrderHandler {
    protected OrderHandler next;

    public OrderHandler setNext(OrderHandler next) {
        this.next = next;
        return next;
    }

    public abstract Order handle(Order order);

    protected Order handleNext(Order order) {
        if (next != null) {
            return next.handle(order);
        }
        return order;
    }
}

// 具体处理器
@Component
@Order(1)
public class ValidateHandler extends OrderHandler {
    @Override
    public Order handle(Order order) {
        if (order.getAmount() == null || order.getAmount().compareTo(BigDecimal.ZERO) <= 0) {
            throw new BusinessException("Invalid amount");
        }
        System.out.println("Validation passed");
        return handleNext(order);
    }
}

@Component
@Order(2)
public class InventoryCheckHandler extends OrderHandler {
    @Override
    public Order handle(Order order) {
        System.out.println("Inventory check passed");
        return handleNext(order);
    }
}

@Component
@Order(3)
public class FraudDetectionHandler extends OrderHandler {
    @Override
    public Order handle(Order order) {
        System.out.println("Fraud check passed");
        return handleNext(order);
    }
}

@Component
@Order(4)
public class OrderPersistenceHandler extends OrderHandler {
    @Override
    public Order handle(Order order) {
        System.out.println("Order saved: " + order.getId());
        return order;  // 最后一个处理器，不调用 next
    }
}

// 链的组装
@Configuration
public class OrderHandlerChainConfig {

    @Bean
    public OrderHandler orderHandlerChain(List<OrderHandler> handlers) {
        if (handlers.isEmpty()) return null;

        // 按 @Order 排序
        handlers.sort(Comparator.comparingInt(
            h -> h.getClass().getAnnotation(Order.class).value()
        ));

        // 组装链
        for (int i = 0; i < handlers.size() - 1; i++) {
            handlers.get(i).setNext(handlers.get(i + 1));
        }

        return handlers.get(0);
    }
}
```

### 4.5 State (状态)

```java
// 状态模式: 用枚举+策略实现状态机
public enum OrderState {
    PENDING {
        @Override
        public OrderState next(OrderEvent event) {
            switch (event) {
                case PAY: return PAID;
                case CANCEL: return CANCELLED;
                default: throw new IllegalStateException("Cannot " + event + " from PENDING");
            }
        }
    },
    PAID {
        @Override
        public OrderState next(OrderEvent event) {
            switch (event) {
                case SHIP: return SHIPPED;
                case REFUND: return REFUNDED;
                default: throw new IllegalStateException("Cannot " + event + " from PAID");
            }
        }
    },
    SHIPPED {
        @Override
        public OrderState next(OrderEvent event) {
            switch (event) {
                case DELIVER: return DELIVERED;
                default: throw new IllegalStateException("Cannot " + event + " from SHIPPED");
            }
        }
    },
    DELIVERED, CANCELLED, REFUNDED {
        @Override
        public OrderState next(OrderEvent event) {
            throw new IllegalStateException("Terminal state, no transitions allowed");
        }
    };

    public abstract OrderState next(OrderEvent event);
}

public enum OrderEvent {
    PAY, CANCEL, SHIP, DELIVER, REFUND
}

// 使用
@Service
public class OrderStateMachine {
    public OrderState transition(OrderState current, OrderEvent event) {
        OrderState next = current.next(event);
        System.out.println(current + " --[" + event + "]--> " + next);
        return next;
    }
}
```

## 7. DDD 领域驱动设计

### 7.1 战术模式

| 模式 | 描述 | 示例 |
|------|------|------|
| **Entity** | 有唯一标识、生命周期、可变状态 | `User(id, name, email)` |
| **Value Object** | 无标识、不可变、通过属性相等判断 | `Address(city, street, zip)` |
| **Aggregate** | 实体和 VO 的集群，一致性边界 | `Order + OrderItem` |
| **Repository** | 领域对象的集合式存储 | `UserRepository` |
| **Domain Service** | 无状态，处理不适合放在 Entity/VO 的业务 | `TransferService` |
| **Domain Event** | 领域中的关键事件 | `OrderCreatedEvent` |

### 7.2 Entity vs Value Object

```java
// Entity: 有 ID，可变，通过 ID 区分
@Entity
@Table(name = "users")
public class User {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String name;
    private String email;

    // Entity 可以有修改行为
    public void changeEmail(String newEmail) {
        this.email = newEmail;
    }

    // Entity 通过 ID 判等
    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof User)) return false;
        return id != null && id.equals(((User) o).id);
    }

    @Override
    public int hashCode() {
        return getClass().hashCode();
    }
}

// Value Object: 无 ID，不可变，通过属性判等
@Value
public class Money {
    BigDecimal amount;
    String currency;

    // 不可变 — 操作返回新对象
    public Money add(Money other) {
        if (!this.currency.equals(other.currency)) {
            throw new IllegalArgumentException("Currency mismatch");
        }
        return new Money(this.amount.add(other.amount), this.currency);
    }

    // 通过所有属性判等 (Lombok @Value 自动生成)
}
```

### 7.3 Aggregate (聚合)

```java
// Aggregate Root: Order
@Entity
@Table(name = "orders")
public class Order {
    @Id
    private Long id;

    @Enumerated(EnumType.STRING)
    private OrderStatus status;

    @Embedded
    private Money totalAmount;

    @OneToMany(cascade = CascadeType.ALL, orphanRemoval = true)
    @JoinColumn(name = "order_id")
    private List<OrderItem> items = new ArrayList<>();

    // Aggregate Root 约束一致性
    public void addItem(Product product, int quantity) {
        if (this.status != OrderStatus.PENDING) {
            throw new BusinessException("Can only add items to pending orders");
        }

        OrderItem item = new OrderItem(product, quantity);
        items.add(item);

        // 重新计算总额
        this.totalAmount = calculateTotal();
    }

    public void pay() {
        if (this.status != OrderStatus.PENDING) {
            throw new BusinessException("Order is not pending");
        }
        this.status = OrderStatus.PAID;
    }

    public void ship() {
        if (this.status != OrderStatus.PAID) {
            throw new BusinessException("Order is not paid");
        }
        this.status = OrderStatus.SHIPPED;
    }

    private Money calculateTotal() {
        BigDecimal total = items.stream()
            .map(OrderItem::getSubtotal)
            .reduce(BigDecimal.ZERO, BigDecimal::add);
        return new Money(total, "CNY");
    }
}

// Repository 只操作 Aggregate Root
public interface OrderRepository {
    Order save(Order order);
    Optional<Order> findById(Long id);
    // 不直接提供 OrderItem 的查询
}
```

## 8. 反模式

### 8.1 常见 Java 反模式

| 反模式 | 描述 | 解决方案 |
|--------|------|---------|
| 上帝类 (God Class) | 一个类几千行，什么功能都有 | 拆分遵循 SRP |

## 9. 架构决策记录 (ADR)

### 9.1 什么是 ADR

ADR (Architecture Decision Record) 是记录架构决策的轻量级文档。帮助团队理解"为什么这样做"。

### 9.2 ADR 模板

```markdown
# ADR-001: 选择 PostgreSQL 作为主数据库

## 状态
✅ 已接受 (2024-01-15)

## 背景
我们需要为新的订单系统选择主数据库。系统需要处理每天约 100 万笔订单，
需要支持复杂的事务和聚合查询。

## 决策
选择 PostgreSQL 15 作为主数据库。

## 原因
1. 需要强一致性事务支持 (ACID)
2. 订单查询复杂度高，需要 CTE、窗口函数等高级 SQL 特性
3. 团队熟悉 PostgreSQL
4. 开源，无需授权费用
5. 对比 MySQL 8.0，PostgreSQL 在复杂查询上性能更好

## 备选方案
- MySQL 8.0: 复制更成熟，但复杂查询性能不如 PostgreSQL
- Oracle: 功能最强，但授权费用高
- MongoDB: Schema-less 不适合订单系统的强一致性需求

## 影响
- 正面: 团队已有经验，开发效率高
- 正面: 丰富的数据类型支持 (JSONB, 数组)
- 负面: 主从复制工具不如 MySQL 成熟
- 风险: 需要在业务增长时前置分片方案

## 相关 ADR
- ADR-002: 读写分离方案
- ADR-005: 分片策略
```

### 10.1 演化式架构

### 10.2 Fitness Function (适应度函数)

## 11. 面试高频题

### 基础概念类

**Q: 单例模式有哪几种实现方式？推荐哪一种？**
A: 饿汉式、懒汉式(DCL)、静态内部类、枚举。推荐枚举方式，它线程安全、防反序列化、防反射攻击。Spring 默认的单例是通过容器管理的，不是通过枚举。

**Q: 代理模式在 Spring 中有哪些应用？**
A:
1. Spring AOP (JDK 动态代理 / CGLIB)
2. 声明式事务 @Transactional
3. 懒加载 @Lazy
4. Spring Security 的 @PreAuthorize
5. 缓存 @Cacheable

**Q: SOLID 原则中哪个最容易被违反？**
A: 单一职责 (SRP) 和开闭原则 (OCP) 最常被违反。SRP 因为"职责"的界限不清晰，OCP 因为开发时倾向于直接修改已有代码。

### 实战类

**Q: 策略模式和状态模式有什么区别？**
A:
- 策略模式：客户端主动选择策略，策略之间是平级的（如支付方式选择）
- 状态模式：状态自动转换，不同状态决定行为（如订单状态机）
- 本质区别：策略的切换由调用方控制，状态的切换由对象内部控制

**Q: Spring 观察者模式和消息队列 (MQ) 的区别？**
A:
- Spring Event (ApplicationEvent): 进程内同步/异步，简单轻量，适合单体应用
- MQ (RocketMQ/Kafka): 跨进程异步，持久化，适合分布式系统
- 选择：单体用 Spring Event，微服务用 MQ

**Q: 你如何在团队中推广设计模式？**
A:
1. 先从代码评审中识别可改进的设计
2. 不要引入所有模式，从最常用的几个开始（Strategy, Template Method, Observer）
3. 在 ADR 中记录设计决策
4. 写代码示例，展示 before/after 对比
5. 让团队成员参与讨论，理解"为什么"而非"是什么"

### 场景类

**Q: 面对一个遗留系统的"上帝类"，怎么重构？**
A:
1. 先写 Characterization Test (锁定当前行为)
2. 用 Extract Class 拆分类 (按 SRP)
3. 用 Extract Interface 提取抽象
4. 逐步迁移调用方
5. 每次只改动一小部分，确保测试通过
6. 最终删除原类

**Q: 设计一个订单系统需要考虑哪些模式？**
A:
1. Builder: 创建复杂订单对象
2. State: 订单状态流转 (PENDING → PAID → SHIPPED → DELIVERED)
3. Strategy: 不同支付方式
4. Observer: 订单创建后的处理 (通知、库存、优惠券)
5. Chain of Resp: 订单处理流水线 (验证 → 库存 → 风控 → 保存)
6. Template Method: 不同支付渠道的处理流程模板

**Q: 什么时候不应该使用设计模式？**
A:
1. 问题很简单，使用模式反而增加复杂度
2. 团队不熟悉模式，强行使用导致维护困难
3. 性能敏感场景 (如代理模式增加调用链路)
4. 可能只需要一个简单的 if-else 或 switch
