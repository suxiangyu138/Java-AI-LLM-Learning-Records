# 01 - Docker 概述与核心概念

## 1.1 什么是 Docker？

Docker 是一个开源的**容器化平台**，用于开发、分发和运行应用程序。它将应用程序及其依赖打包到一个轻量级、可移植的容器中，确保应用在任何环境中都能一致地运行。

### 为什么需要 Docker？

| 传统部署痛点 | Docker 解决方案 |
|---|---|
| "在我电脑上能跑啊" | 容器镜像统一环境，消除环境差异 |
| 依赖冲突（A 要 Python 2，B 要 Python 3） | 每个容器有独立的运行环境 |
| 部署步骤繁琐（装依赖、配环境） | 一条 `docker run` 即可启动 |
| 资源利用率低（多个 VM 各占一份 OS） | 容器共享宿主机内核，秒级启动 |

## 1.2 容器 vs 虚拟机

```
传统虚拟机架构                      容器架构
┌─────────────────┐            ┌─────────────────┐
│   App A │ App B  │            │   App A │ App B  │
├─────────┴────────┤            ├─────────┴────────┤
│  Guest OS │Guest OS│          │   Docker Engine   │
├─────────┴────────┤            ├───────────────────┤
│   Hypervisor     │            │   Host OS (Linux) │
├──────────────────┤            ├───────────────────┤
│   Host OS        │            │   Infrastructure  │
├──────────────────┤            └───────────────────┘
│  Infrastructure  │
└──────────────────┘

虚拟机：每个 VM 包含完整 OS，GB 级别，分钟级启动
容器：共享宿主机内核，MB 级别，秒级启动
```

| 特性 | 容器 | 虚拟机 |
|---|---|---|
| 启动速度 | 秒级 | 分钟级 |
| 镜像大小 | 几十 MB | 几 GB |
| 资源隔离 | 进程级隔离 | 完全隔离 |
| OS 依赖 | 共享宿主机内核 | 每个 VM 有独立 OS |
| 可移植性 | 极高 | 中等 |

## 1.3 Docker 核心三要素

### 镜像 (Image)
- 容器的**只读模板**，类似于虚拟机的快照
- 采用分层存储（Union FS），每一层都是只读的
- 通过 Dockerfile 构建，或从 Registry 拉取

### 容器 (Container)
- 镜像的**运行实例**
- 在镜像的只读层之上添加一个**可写层**
- 可以启动、停止、删除、暂停

### 仓库 (Registry)
- 存储和分发镜像的地方
- **Docker Hub** 是默认的公共仓库（类似 GitHub）
- 可以搭建私有仓库（Harbor、Nexus）

```
Dockerfile ──build──▶ Image ──run──▶ Container
                          │
                          ▼
                      Registry (Docker Hub / 私有仓库)
                          │
                     pull │ push
                          │
                      Image ◀──
```

## 1.4 Docker 架构

```
┌─────────────────────────────────────────────────────┐
│                   Docker Client                      │
│              (docker CLI / docker compose)           │
└────────────────────┬────────────────────────────────┘
                     │ REST API (Unix Socket / TCP)
┌────────────────────▼────────────────────────────────┐
│                  Docker Daemon (dockerd)              │
│  ┌──────────┐ ┌────────────┐ ┌───────────────────┐  │
│  │ 镜像管理  │ │ 容器运行时   │ │ 网络/存储插件      │  │
│  └──────────┘ └────────────┘ └───────────────────┘  │
│  ┌──────────────────────────────────────────────┐    │
│  │           containerd / runc                   │   │
│  └──────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────┘
```

- **Docker Client**：用户交互的命令行工具
- **Docker Daemon**：后台进程，管理镜像、容器、网络、存储
- **containerd**：管理容器生命周期的工业级运行时
- **runc**：OCI 标准的容器运行时，真正创建和运行容器

## 1.5 Docker 能做什么？

1. **环境标准化**：开发、测试、生产环境完全一致
2. **微服务架构**：每个服务独立容器化，独立部署和扩缩容
3. **CI/CD 流水线**：构建→测试→部署全流程在容器中完成
4. **快速部署**：一条命令启动完整应用栈
5. **资源隔离**：在同一台机器上安全运行多个应用

## 1.6 关键术语速查

| 术语 | 说明 |
|---|---|
| Dockerfile | 构建镜像的脚本文件 |
| Image | 容器的只读模板 |
| Container | 镜像的运行实例 |
| Registry | 镜像存储仓库 |
| Volume | 持久化数据存储 |
| Network | 容器间网络通信 |
| Compose | 多容器应用编排工具 |
| Tag | 镜像标签（版本号） |
