# 31-GitHub高频核心词汇
> 🎯 GitHub英文界面无障碍阅读 — 按场景分类的100个高频核心词，后端开发者必懂

## 一、仓库基础

| 英文 | 中文 | 说明 |
|------|------|------|
| Repository (repo) | 仓库 | 代码存放的地方 |
| Star | 星标 | 点赞/收藏 |
| Fork | 复刻 | 复制别人的仓库到自己账号 |
| Clone | 克隆 | 下载到本地 |
| Branch | 分支 | 独立的开发线 |
| Tag | 标签 | 版本标记，如v1.0.0 |
| Main / Master | 主分支 | 默认分支 |
| Public / Private | 公开/私有 | 仓库可见性 |
| Owner | 所有者 | 仓库拥有者 |
| Organization | 组织 | 团队账号 |
| Contributor | 贡献者 | 提交过代码的人 |
| .gitignore | 忽略文件 | 指定不跟踪的文件 |

## 二、Pull Request

| 英文 | 中文 | 说明 |
|------|------|------|
| Pull Request (PR) | 合并请求 | 请求把代码合并到目标分支 |
| Draft PR | 草稿PR | 还在开发中的PR |
| Review | 审查 | 代码审查 |
| Approve | 批准 | 审查通过 |
| Request Changes | 请求修改 | 审查不通过，要求修改 |
| Comment | 评论 | 讨论/建议 |
| Resolve Conversation | 解决讨论 | 标记讨论已完成 |
| Merge | 合并 | 将PR合入目标分支 |
| Squash and Merge | 压缩合并 | 所有commit压为1个后合并 |
| Rebase and Merge | 变基合并 | 线性合并 |
| Close | 关闭 | 关闭PR（不合并） |

## 三、Issue

| 英文 | 中文 | 说明 |
|------|------|------|
| Issue | 议题 | Bug报告/功能请求 |
| Label | 标签 | 分类标记（bug/enhancement等） |
| Milestone | 里程碑 | 按版本/目标分组 |
| Assignee | 负责人 | 指派给谁处理 |
| Open / Closed | 打开/已关闭 | Issue状态 |
| Duplicate | 重复 | 标记为已有相同Issue |
| Won't Fix | 不修复 | 决定不处理 |

## 四、Git操作

| 英文 | 中文 | 说明 |
|------|------|------|
| Commit | 提交 | 保存修改到本地仓库 |
| Push | 推送 | 上传到远程仓库 |
| Pull | 拉取 | 下载远程更新 |
| Fetch | 获取 | 下载但不合并 |
| Merge | 合并 | 合并分支 |
| Rebase | 变基 | 重新设置commit基础 |
| Cherry-pick | 摘取 | 选择特定commit移植 |
| Stash | 暂存 | 临时保存工作区修改 |
| Reset | 重置 | 回退到指定状态 |
| Revert | 撤销 | 创建反向commit来撤销 |
| Force Push | 强制推送 | 覆盖远程历史 |
| Conflict | 冲突 | 合并冲突 |

| 英文 | 中文 | 说明 |
|------|------|------|
| Workflow | 工作流 | CI/CD流水线定义 |
| Job | 作业 | Workflow中的一个任务 |
| Step | 步骤 | Job中的一个步骤 |
| Runner | 运行器 | 执行Job的机器 |
| Trigger | 触发器 | 什么事件触发Workflow |
| Artifact | 制品 | 构建产物 |
| Secret | 密钥 | 加密的环境变量 |
| Matrix | 矩阵 | 多版本/多环境并行测试 |

## 七、安全
