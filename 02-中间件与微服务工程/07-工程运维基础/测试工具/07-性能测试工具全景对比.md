## 1. 性能测试工具分类

### 1.1 按架构分类

| 类型 | 代表工具 | 特点 |
|------|----------|------|
| **GUI桌面工具** | JMeter, LoadRunner | 图形化操作，适合复杂场景编排 |
| **CLI命令行工具** | wrk, ab, vegeta, hey | 轻量快速，适合CI/CD和快速验证 |
| **代码/DSL工具** | Gatling(Scala), k6(JS), Locust(Python) | 代码定义场景，版本可控，CI友好 |
| **云压测平台** | JMeter Cloud, LoadRunner Cloud, 阿里云PTS | 分布式大规模压测，免运维 |

### 1.2 按协议支持分类

| 协议 | 支持的测试工具 |
|------|--------------|
| **HTTP/HTTPS** | JMeter, Gatling, wrk, ab, vegeta, hey, k6, Locust, LoadRunner |
| **WebSocket** | JMeter, k6, Gatling, Locust |
| **gRPC** | k6(xk6-grpc), Gatling(gRPC plugin), JMeter(plugin) |
| **TCP/UDP** | JMeter(TCP Sampler), Gatling, Locust |
| **JDBC/数据库** | JMeter(JDBC Request), Gatling(jdbc) |
| **MQ消息队列** | JMeter(JMS Sampler), Gatling(JMS) |
| **Redis** | JMeter(Redis Data Set/Plugin) |

## 3. 各工具快速上手

### 3.1 wrk — 最简压测

```bash
# 安装
# macOS: brew install wrk
# Ubuntu: apt install wrk
# Windows: WSL中使用

# 基本用法
wrk -t4 -c100 -d30s --latency http://localhost:8080/api/users

# 参数说明：
# -t4    : 4个线程
# -c100  : 100个并发连接
# -d30s  : 持续30秒
# --latency : 显示延迟分布

# POST + Body
wrk -t2 -c50 -d20s -s post.lua http://localhost:8080/api/users

# post.lua:
wrk.method = "POST"
wrk.body   = '{"name":"test"}'
wrk.headers["Content-Type"] = "application/json"
```

### 3.2 vegeta — 恒定速率攻击

```bash
# 安装: go install github.com/tsenart/vegeta@latest

# 恒定速率 100 req/s，持续30秒
echo "GET http://localhost:8080/api/users" | \
  vegeta attack -rate=100 -duration=30s | \
  vegeta report

# POST with body
echo "POST http://localhost:8080/api/users" | \
  vegeta attack -rate=50 -duration=20s -body user.json \
  -header "Content-Type: application/json" | \
  vegeta report -type=text

# 输出示例：
# Requests      [total, rate, throughput]  3000, 100.02, 99.98
# Duration      [total, attack, wait]      30.001s, 30s, 999.85µs
# Latencies     [min, mean, 50, 90, 95, 99, max]
#               180µs, 2.5ms, 2.1ms, 4.3ms, 5.1ms, 8.2ms, 45ms
# Status Codes  [code:count]              200:2998  500:2
```

### 3.3 hey — Go单文件压测

```bash
# 安装: go install github.com/rakyll/hey@latest

# 200并发、10000总请求
hey -n 10000 -c 200 http://localhost:8080/api/users

# POST + Header
hey -n 5000 -c 100 -m POST \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer xxx" \
  -d '{"name":"test"}' \
  http://localhost:8080/api/users
```

### 3.4 k6 — 现代JS压测

```javascript
// k6 测试脚本 test.js
import http from 'k6/http';
import { check, sleep } from 'k6';
import { Rate, Trend } from 'k6/metrics';

export const options = {
    stages: [
        { duration: '30s', target: 50 },   // 30秒内爬升到50并发
        { duration: '1m',  target: 100 },  // 1分钟内爬升到100并发
        { duration: '30s', target: 0 },    // 30秒内降到0
    ],
    thresholds: {
        http_req_duration: ['p(95)<500'],  // 95%请求 < 500ms
        http_req_failed: ['rate<0.01'],    // 失败率 < 1%
    },
};

export default function () {
    const res = http.get('http://localhost:8080/api/users/1');
    check(res, { 'status is 200': (r) => r.status === 200 });
    sleep(1);
}
```

```bash
# 运行
k6 run test.js                # 本地运行
k6 run --out json=result.json test.js  # 输出JSON结果
k6 cloud test.js              # 云端分布式运行
```

### 3.5 Gatling — Scala DSL高性能

```scala
// UserSimulation.scala
import io.gatling.core.Predef._
import io.gatling.http.Predef._
import scala.concurrent.duration._

class UserSimulation extends Simulation {

  val httpProtocol = http
    .baseUrl("http://localhost:8080")
    .acceptHeader("application/json")

  val scn = scenario("Get Users")
    .exec(http("GetUser")
      .get("/api/users/1")
      .check(status.is(200)))
    .pause(1)

  setUp(
    scn.inject(
      rampUsers(100).during(30.seconds),   // 30秒内爬升到100用户
      constantUsersPerSec(20).during(60)   // 保持20 req/s持续60秒
    )
  ).protocols(httpProtocol)
}
```

### 3.6 ab — Apache Bench 快速冒烟

```bash
ab -n 500 -c 20 -p user.json -T application/json \
  http://localhost:8080/api/users
```

## 4. 场景化选型指南

### 4.1 按场景推荐

| 场景 | 推荐工具 | 理由 |
|------|----------|------|
| **日常API压测（Java团队）** | JMeter | GUI可视化、Java生态、功能最全 |
| **CI/CD流水线集成** | Gatling 或 k6 | 代码定义场景、Git版本管理 |
| **快速冒烟测试** | ab 或 hey | 一行命令、秒级启动 |
| **高精度恒定速率压测** | wrk2 或 vegeta | 精确控制QPS、延迟分布 |
| **单机极限QPS测试** | wrk | C语言极致性能、百万QPS |
| **多协议（DB/MQ/TCP）** | JMeter | 插件生态丰富、协议覆盖最广 |
| **云原生/K8s环境** | k6 | 原生K8s Operator、Prometheus集成 |
| **Python技术栈** | Locust | Python编写场景、灵活 |
| **大型企业/金融** | LoadRunner | 商业支持、合规、多协议 |

### 4.2 Java后端团队推荐组合

```
JMeter          → 主力压测工具（GUI编排场景 + CLI集成CI）
wrk             → 快速性能基准测试
Gatling 或 k6   → CI/CD流水线持续性能回归
```

## 5. 性能测试指标解读

| 指标 | 含义 | 如何评估 |
|------|------|----------|
| **QPS/TPS** | 每秒处理请求数/事务数 | 越高越好，关注瓶颈点 |
| **Avg Latency** | 平均响应时间 | 可能存在被长尾拉高的情况 |
| **P50/P95/P99** | 中位数/95%/99%百分位延迟 | **P99是最重要指标**，代表绝大多数用户体验 |
| **Max Latency** | 最大响应时间 | 关注是否有异常长尾 |
| **Error Rate** | 错误率 | 目标 < 0.1%（99.9%成功率）|
| **Throughput** | 吞吐量（KB/s） | 网络带宽是否成为瓶颈 |

## 6. 性能测试流程规范

```
1. 需求分析
   ├── 明确测试目标（QPS目标、RT目标）
   ├── 确定测试场景（核心接口、混合场景）
   └── 准备测试数据（脱敏的生产级数据量）

2. 环境准备
   ├── 独立的压测环境（不要用生产！）
   ├── 环境配置与生产保持一致
   └── 监控搭建（应用+JVM+DB+OS）

3. 基准测试
   ├── 单接口单用户基准 → 记录RT基线
   ├── 逐步加压10→50→100→200→500并发
   └── 找到拐点（QPS不再增长/RT陡增/错误率上升）

4. 稳定性测试
   ├── 用拐点的80%负载持续压测 ≥ 30分钟
   ├── 观察是否有内存泄漏、GC异常
   └── 检查RT是否随时间增长

5. 容量评估
   ├── 根据拐点QPS推算单机容量
   ├── 根据预估峰值QPS计算所需实例数
   └── 预留20-30%冗余

6. 报告输出
   ├── QPS vs RT 曲线图
   ├── 各并发量下的P99延迟
   ├── 瓶颈分析和优化建议
   └── 容量规划建议
```

> 🎯 **黄金法则**：每次上线前必须跑性能基准测试；每次架构变更必须做性能回归；性能数据要入库趋势化监控。
