# 开源项目协作

## 📌 定位
**课外自学 | 第三梯队 | 简历亮点·工程素养提升**

参与开源项目是提升工程能力的"捷径"——看优秀代码怎么写的、学规范的协作流程、丰富简历上的真实贡献。

## 🎯 核心章节

### 1. 协作流程（GitHub 标准）
1. **Fork**：把别人的仓库复制到自己的账号下
2. **Clone**：`git clone` 到本地
3. **新建分支**：`git checkout -b fix/typo-in-readme`
4. **修改 + Commit**：遵循项目的commit规范（通常是Conventional Commits）
5. **Push**：推送到自己的Fork
6. **发起 Pull Request（PR）**：从Fork分支 → 原始仓库的main分支
7. **Code Review**：维护者审查→修改→再次Push（自动更新PR）→LGTM(Looks Good To Me)→Merge

### 2. 贡献类型（从易到难）
1. **Good First Issue**：修typo、补充文档——熟悉流程的最佳入口
2. **Bug Fix**：复现Bug→定位原因→提交修复——含金量上升
3. **Feature**：新功能——需要前期Issue讨论，不能自己写了就PR
4. **性能优化/重构**：需要深度理解项目
5. **成为Maintainer**：长期高质量贡献+社区信任

### 3. 常规规范
- **Conventional Commits（约定式提交）**：
  ```
  feat: add user login API
  fix: resolve NPE in UserService
  docs: update README with setup guide
  refactor: extract validation logic
  ```
- **Issue 模板**：Bug Report(复现步骤+期望vs实际)+ Feature Request(动机+方案)
- **Code Review 礼仪**：对事不对人、具体建议而非笼统否定、PR小一点(200行以内)

### 4. 找项目参与
- **你正在用的工具**：发现Bug→修了→PR——最自然的方式
- **Awesome Lists**：`awesome-java`、`awesome-llm`——找相关领域的热门项目
- **Good First Issue 标签**：GitHub搜索 `label:good-first-issue language:java`
- **推荐方向**：Spring生态/中间件(RocketMQ)/AI Agent框架——匹配你的技术栈

### 5. 读源码的能力
- **从哪里开始**：README→核心模块→关键接口→关键数据结构→启动流程
- **工具辅助**：Sourcegraph(代码搜索)、Git blame(看谁写的什么原因)
- **目的不是"读完"**：而是理解设计决策——为什么这样设计？解决了什么问题？

## ✅ 学习建议
- 不用等"学好了再参与"——修复typo和补充文档就是最好的入门
- 先成为优秀项目的"深度用户"→自然发现可改进的地方→贡献
- 一个良好的开源贡献记录对校招简历加成很大——比"XX系统课设"有说服力得多
