## 1. 容量规划

### 1.1 存储估算公式

```
存储需求 ≈ 每个样本的字节数 × 每秒样本数 × 保留时间

每个样本：~1.5 bytes（压缩后）
每秒样本数 = Targets 数量 × 每个 Target 的 Series 数 / scrape_interval

示例：
  - 100 个 Target
  - 每个 Target 1000 条 Series
  - scrape_interval = 30s
  - 保留 30 天

每秒样本数 = 100 × 1000 / 30 ≈ 3333 samples/s
存储 = 1.5 × 3333 × 30 × 86400 ≈ 13 GB
```

### 1.2 内存估算

```
内存 ≈ Series 数量 × 每条 Series 的开销

每条 Series：~3-5 KB（含索引 + 最近数据块）

示例：10 万 Series × 4 KB ≈ 400 MB 基础内存
    + Head Block 缓存 ~200 MB
    ≈ 600 MB 起步，建议 2-4 GB
```

| 规模 | Targets | Series | 存储(15d) | 推荐内存 |
|------|:---:|:---:|------|:---:|
| 小 | <50 | <5 万 | <3 GB | 2 GB |
| 中 | 50-200 | 5-30 万 | 3-15 GB | 4-8 GB |
| 大 | 200-1000 | 30-100 万 | 15-50 GB | 8-16 GB |
| 超大 | 1000+ | 100 万+ | 50 GB+ | 使用 Thanos/Cortex |

## 2. 存储优化与 Retention

### 2.1 启动参数

```bash
prometheus \
  --storage.tsdb.path=/var/lib/prometheus \
  --storage.tsdb.retention.time=15d \          # 数据保留时间
  --storage.tsdb.retention.size=50GB \         # 最大存储大小（与 time OR 关系）
  --storage.tsdb.max-block-duration=2h \       # Block 最大时长
  --storage.tsdb.min-block-duration=2h
```

### 2.2 减少 Series 基数

```promql
# ❌ 高基数 — 用户 ID 作为 Label（10 万用户 = 10 万 Series）
orders_total{user_id="12345"} 100

# ✅ 低基数 — 聚合统计
orders_total{status="completed"} 50000

# ❌ 不要将 URI 保留所有路径参数
http_requests_total{uri="/api/users/12345/orders/67890"} 1

# ✅ 在应用中规范化 URI
http_requests_total{uri="/api/users/{id}/orders/{id}"} 1
```

### 2.3 Remote Write 长期存储

```yaml
# prometheus.yml — 写入远程存储（VictoriaMetrics/Thanos/Mimir）
remote_write:
  - url: "http://victoriametrics:8428/api/v1/write"
    queue_config:
      max_samples_per_send: 5000
      max_shards: 30
      capacity: 10000

remote_read:
  - url: "http://victoriametrics:8428/api/v1/read"
```

## 4. 性能调优

### 4.1 抓取调优

```yaml
global:
  scrape_interval: 30s          # 不建议 < 15s（增加 TSDB 压力）
  evaluation_interval: 30s

scrape_configs:
  - job_name: 'high-cardinality'
    scrape_interval: 60s        # 高基数 Target 降低频率
    sample_limit: 10000         # 丢弃超过 1 万样本的 Target
    label_limit: 30             # 限制 Label 数量
    label_name_length_limit: 50
    label_value_length_limit: 200
```

### 4.2 TSDB 调优

```bash
prometheus \
  --storage.tsdb.wal-compression \                # WAL 压缩（节省磁盘）
  --storage.tsdb.max-block-chunk-segment-size=32MB \ # Block chunk 大小
  --query.max-concurrency=20 \                   # 查询并发数
  --query.max-samples=50000000                    # 单次查询最大样本数（防 OOM）
```

### 4.3 AlertManager 性能

```yaml
# alertmanager.yml
global:
  resolve_timeout: 5m

route:
  group_wait: 30s               # 适当延长等待窗口
  group_interval: 5m            # 不要设太短
  repeat_interval: 4h           # ⚠️ 不要设 < 1h（避免轰炸）
```

## 5. 安全加固

```nginx
# Nginx Basic Auth 反向代理
server {
    listen 80;
    server_name prometheus.example.com;

    auth_basic "Prometheus";
    auth_basic_user_file /etc/nginx/.htpasswd;

    location / {
        proxy_pass http://localhost:9090;
    }
}
```

```yaml
# Prometheus 自身安全配置
# 启动参数
prometheus \
  --web.enable-admin-api \         # 谨慎开启（含 TSDB 管理）
  --web.enable-lifecycle \         # /-/reload 等接口
  --web.external-url=https://prometheus.example.com
```

> ⚠️ **安全建议**：Prometheus 自带无认证，必须用 Nginx Basic Auth 或 OAuth2 Proxy 保护。`/api/v1/admin/tsdb/*` 接口可删除数据，严格限制访问。

## 6. 常见故障排查

### 6.1 Target 全部 Down

```bash
# 排查顺序
# 1. Prometheus 自身存活
curl http://localhost:9090/-/healthy

# 2. 网络可达性
telnet 10.0.1.10 8080

# 3. Target 的 /metrics 是否正常
curl http://10.0.1.10:8080/actuator/prometheus

# 4. Prometheus 日志
journalctl -u prometheus -f

# 5. 配置语法
promtool check config /etc/prometheus/prometheus.yml
```

### 6.2 Prometheus OOM

| 原因 | 排查 | 解决 |
|------|------|------|
| Series 太多 | `count({__name__=~".+"})` 查看总 Series | 减少 Label 基数 |
| 查询太复杂 | `topk(10, count by (__name__)({__name__=~".+"}))` | 限制查询时间范围 |
| TSDB 内存 | 查看 `prometheus_tsdb_head_series` | 缩短 retention |

### 6.3 磁盘写满

```bash
# 1. 检查数据目录
du -sh /var/lib/prometheus/

# 2. 缩短保留时间
prometheus --storage.tsdb.retention.time=7d

# 3. 删除旧数据（谨慎！）
promtool tsdb clean -t 2024-01-01 /var/lib/prometheus/

# 4. 启用 Remote Write 将数据迁出
```

## 7. 生产部署 Checklist

| 分类 | 检查项 | 说明 |
|------|--------|------|
| **部署** | systemd 管理 | 确保 Prometheus 作为系统服务运行 |
| **部署** | 持久化存储 | `/var/lib/prometheus` 独立分区 |
| **配置** | `promtool check` | 每次修改配置前先检查 |
| **配置** | 告警规则覆盖 | Node/JVM/HTTP/中间件 |
| **容量** | 磁盘使用率监控 | 监控 TSDB 数据目录增长 |
| **安全** | Nginx 反向代理 + Auth | 禁止公网裸奔 |
| **安全** | 禁用 admin API | `--web.enable-admin-api` 默认关闭 |
| **高可用** | 双实例或 Thanos | 根据规模选择 |
| **备份** | 告警规则 + Dashboard | Git 管理 Infrastructure as Code |
| **恢复** | TSDB 快照 | `promtool tsdb snapshot` |

```bash
# 配置语法检查（CI 中集成）
promtool check config /etc/prometheus/prometheus.yml
promtool check rules /etc/prometheus/rules/*.yml

# TSDB 快照备份
promtool tsdb snapshot /var/lib/prometheus /backup/prometheus-snapshot
```

> 🎯 **监控系统的自我监控**：Prometheus 自身暴露 `prometheus_*` 指标 — 用 Prometheus 监控 Prometheus（元监控）。重点指标：`prometheus_tsdb_head_series`、`prometheus_engine_query_duration_seconds`、`up`。
