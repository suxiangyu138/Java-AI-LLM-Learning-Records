## 1. 配置中心实现

### 1.1 基本模式

```text
/config
  ├── /config/db-url     = "jdbc:mysql://..."
  ├── /config/redis      = "10.0.1.10:6379"
  └── /config/app-params = "maxPool=50;timeout=3000"

变更流程：
  管理员 → 更新 /config/db-url 的值
  → ZK 推送 Watch 通知给所有监听该节点的应用
  → 应用收到通知 → 重新读取配置 → 动态生效（如重建连接池）
```

### 1.2 动态刷新实现

```java
public class ConfigCenter {
    private final CuratorFramework client;
    private String dbUrl;
    private volatile DataSource dataSource;

    public void init() {
        // 启动时读取配置
        loadConfig();
        // 监听配置变更
        watchConfig();
    }

    private void loadConfig() {
        byte[] data = client.getData().forPath("/config/db-url");
        dbUrl = new String(data);
        refreshDataSource();
    }

    private void watchConfig() {
        // Curator NodeCache：自动反复注册 Watch
        NodeCache nodeCache = new NodeCache(client, "/config/db-url");
        nodeCache.getListenable().addListener(() -> {
            String newUrl = new String(nodeCache.getCurrentData().getData());
            if (!newUrl.equals(dbUrl)) {
                dbUrl = newUrl;
                refreshDataSource();   // 热更新数据源
                log.info("配置已更新: db-url={}", dbUrl);
            }
        });
        nodeCache.start();
    }
}
```

### 1.3 TreeCache 监听整个配置树

```java
// 监听 /config 下所有节点的增删改
TreeCache treeCache = new TreeCache(client, "/config");
treeCache.getListenable().addListener((c, event) -> {
    if (event.getData() != null) {
        String path = event.getData().getPath();
        String value = new String(event.getData().getData());
        System.out.println(path + " → " + value);
    }
});
treeCache.start();
```

## 2. 服务发现实现

### 2.1 注册模式

```text
服务提供者启动 → 在 ZK 创建临时节点：
  /services/user-service/192.168.1.10:8080  (EPHEMERAL)
  /services/user-service/192.168.1.11:8080  (EPHEMERAL)
  /services/order-service/192.168.1.20:8080 (EPHEMERAL)

消费者启动 → Watch /services/user-service/
  → 获取所有子节点（Provider 列表）
  → 负载均衡选一个调用

Provider 宕机 → Session 断开 → ZK 自动删除临时节点
  → 消费者收到变更通知 → 更新本地 Provider 列表
```

### 2.2 注册方代码

```java
public class ServiceRegistry {
    private final CuratorFramework client;
    private final String basePath = "/services";

    public void register(String serviceName, String address) throws Exception {
        String path = basePath + "/" + serviceName + "/" + address;
        client.create()
            .creatingParentsIfNeeded()
            .withMode(CreateMode.EPHEMERAL)   // ⭐ 临时节点 — 宕机自动删除
            .forPath(path, address.getBytes());
        log.info("服务注册成功: {}", path);
    }
}
```

### 2.3 发现方代码

```java
public class ServiceDiscovery {
    private final CuratorFramework client;
    private volatile List<String> providers = new ArrayList<>();

    public void discover(String serviceName) {
        String path = "/services/" + serviceName;
        // 获取当前 Provider 列表
        updateProviders(path);
        // 监听 Provider 变更
        watchProviders(path);
    }

    private void updateProviders(String path) {
        try {
            providers = client.getChildren().forPath(path);
        } catch (Exception e) {
            log.error("获取 Provider 列表失败", e);
        }
    }

    private void watchProviders(String path) {
        PathChildrenCache cache = new PathChildrenCache(client, path, true);
        cache.getListenable().addListener((c, event) -> {
            log.info("Provider 变更: type={}", event.getType());
            updateProviders(path);   // 更新本地缓存
        });
        cache.start();
    }

    public String getProvider() {
        return providers.get(ThreadLocalRandom.current().nextInt(providers.size()));
    }
}
```

## 3. ZooKeeper vs Nacos 对比

| 维度 | ZooKeeper 方案 | Nacos 方案 |
|------|---------------|-----------|
| 注册中心 | 临时节点 + PathChildrenCache | 内置注册中心，HTTP API |
| 配置中心 | NodeCache/TreeCache | 内置配置中心，Web 控制台 |
| 动态刷新 | 需手动实现回调 | `@RefreshScope` 注解自动 |
| 健康检查 | Session 心跳 + 被动 | 主动 TCP/HTTP 探测 |
| Web 控制台 | ❌ 需要第三方 | ✅ 内置完美控制台 |
| 推荐度 | 存量系统，学习理解 | ⭐ 新项目首选 |

> 🎯 **结论**：新项目注册/配置用 Nacos（开箱即用+控制台），理解分布式协调原理学 ZK（Watch + Session + 临时顺序节点）。两者思想相通，掌握一个上手另一个很快。
