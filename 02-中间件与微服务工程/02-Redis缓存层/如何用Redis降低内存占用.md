# 如何用 Redis 降低内存占用

> **核心思路**：减少无效开销 + 优化存储效率 + 合理回收内存。可直接降低 50% 以上内存占用。

## 1. 优化数据结构与编码

### 1.1 紧凑编码

| Redis 版本 | 配置项 | 推荐值 |
|-----------|--------|:------:|
| ≤ 6.2 | `hash-max-ziplist-entries` | 512 |
| ≤ 6.2 | `zset-max-ziplist-entries` | 128 |
| ≥ 7.0 | `hash-max-listpack-entries` | 512 |

### 1.2 结构选型优化

| 场景 | ❌ 不推荐 | ✅ 推荐 | 节省 |
|------|----------|--------|------|
| 存储对象 | 多个 String key | Hash 一个 key | 减少元数据开销 |
| 布尔状态集合 | Set | Bitmap | 1000 万用户仅 1.2MB |
| 基数统计 | Set | HyperLogLog | 单个仅 12KB |
| 大 Key | 单键 >100MB | 分片拆分 | 减少碎片 |

## 2. 优化键设计

| 原则 | 示例 |
|------|------|
| 简洁命名 | `user:1001` 替代 `redis_user_id_1001_2026` |
| 过期时间 | 缓存数据必须设 TTL |
| 随机偏移 | 避免集中过期（`EX 3600 + rand(0,60)`） |

---

## 3. 配置调优

| 配置 | 推荐值 | 说明 |
|------|:------:|------|
| `maxmemory` | 物理内存 70-80% | 内存上限 |
| `maxmemory-policy` | `allkeys-lru` | 通用缓存首选 |
| `activedefrag` | `yes` | 主动碎片整理 |
| `maxclients` | 10000 | 限制空闲连接 |
| `timeout` | 60 | TCP 超时释放 |

---

## 4. 运维层面优化

| 措施 | 说明 |
|------|------|
| **实例拆分** | 按业务拆 Redis 实例或集群分片 |
| **清理无效键** | `SCAN` 遍历清理 |
| **监控指标** | `used_memory` / `mem_fragmentation_ratio` / 缓存命中率 |
| **压缩存储** | 大 value 用 gzip/snappy 压缩后存储 |
