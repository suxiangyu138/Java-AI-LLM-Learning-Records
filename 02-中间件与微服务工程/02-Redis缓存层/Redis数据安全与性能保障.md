## 1. 数据安全

### 1.1 持久化对比

| 维度 | RDB | AOF |
|------|-----|-----|
| 原理 | 定时全量快照 | 每条写命令追加日志 |
| 优点 | 文件小、恢复快 | 数据安全性高 |
| 缺点 | 可能丢失快照后数据 | 文件大、恢复慢 |
| 配置 | `save 900 1` | `appendfsync everysec`（推荐） |

> 生产环境：**RDB + AOF 组合**——AOF 保安全，RDB 保恢复。

### 1.2 访问控制

| 措施 | 配置 |
|------|------|
| 密码 | `requirepass redis@123456` |
| 监听限制 | `bind 127.0.0.1`（单机）/ `bind 192.168.1.100`（内网） |
| 禁用危险命令 | `rename-command FLUSHALL ""`、`KEYS ""` |
| 防火墙 | `iptables` 限制 6379 端口访问 |

### 1.3 备份策略

```bash
# 每日凌晨自动备份
0 2 * * * cp /usr/local/redis/dump.rdb /backup/redis/dump_$(date +%Y%m%d).rdb
```

> 本地 + 异地备份，保留多个版本。

## 2. 性能保障

### 2.1 内存管理

| 配置 | 推荐值 | 说明 |
|------|:------:|------|
| `maxmemory` | 物理内存 70-80% | 内存上限 |
| `maxmemory-policy` | `allkeys-lru` | 淘汰策略 |

### 2.2 慢命令替代

| ❌ 慢命令 | ✅ 替代方案 |
|----------|------------|
| `KEYS *` | `SCAN cursor MATCH pattern` |
| `HGETALL`（大 Hash） | `HSCAN` |
| `SMEMBERS`（大 Set） | `SSCAN` |
| `FLUSHALL/FLUSHDB` | `SCAN + DEL` 逐步删除 |

### 2.3 部署架构

| 架构 | 场景 | 能力 |
|------|------|------|
| 主从 + 哨兵 | 中小规模 | 1-10 万 QPS |
| Redis Cluster | 大规模 | 10 万+ QPS |

### 2.4 并发控制

| 场景 | 方案 |
|------|------|
| 简单并发 | 原子命令（`INCR`/`DECR`/`ZINCRBY`） |
| 复杂并发 | 分布式锁（`SET NX EX` + Lua 释放） |

## 3. 常见问题

| 问题 | 方案 |
|------|------|
| **内存溢出** | `maxmemory` + `allkeys-lru` + 清理无效键 |
| **响应延迟** | 禁用慢命令 + 读写分离 + 优化服务器负载 |
| **数据丢失** | RDB+AOF + 定期备份 + 主从 |
| **并发冲突** | 原子命令 + 分布式锁 + 批量操作 |
| **非法访问** | 密码 + `bind` + 防火墙 + 日志检查 |
