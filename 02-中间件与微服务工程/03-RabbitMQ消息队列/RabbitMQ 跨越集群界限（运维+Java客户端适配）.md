## 1. 三大核心场景

| 场景 | 问题 | 方案 |
|------|------|------|
| **跨地域协同** | 华东应用访问华北集群延迟高 | 就近连接 + 联邦链路同步 |
| **容量扩容** | 单集群连接数/消息量达上限 | 多集群分片负载 |
| **容灾备份** | 单集群宕机全业务中断 | 主备实时镜像 + 自动切换 |

## 2. 实现方案

### 方案 1：联邦集群（Federation）⭐ 推荐

```bash
# 开启插件
rabbitmq-plugins enable rabbitmq_federation rabbitmq_federation_management

# 下游集群配置上游
rabbitmqctl set_parameter federation-upstream upstream_cluster1 \
  '{"uri":"amqp://user:pass@上游IP:5672/vhost","exchange":"test_exchange"}'
```

| 优势 | 说明 |
|------|------|
| 对 Java 透明 | 无需改代码，仅调整连接地址 |
| 跨地域 | 适合跨地域消息同步 |

### 方案 2：镜像集群扩展（容灾优先）

> 主集群队列实时镜像到备用集群，主宕机后备自动接管。

```bash
rabbitmqctl set_policy ha-all "^" \
  '{"ha-mode":"exactly","ha-params":2,"ha-sync-mode":"automatic"}' --apply-to queues
```

### 方案对比

| 维度 | 联邦集群 | 镜像集群 | 第三方中间件 |
|------|:------:|:------:|:----------:|
| 适用 | 跨地域同步 | 容灾备份 | 超高并发 |
| 性能 | 中 | 中 | 高 |
| 复杂度 | 低 | 中 | 高 |

## 3. Java 客户端适配

```yaml
# 多集群地址
spring:
  rabbitmq:
    addresses: 192.168.1.100:5672,192.168.2.100:5672
    connection-retry:
      enabled: true
      max-attempts: 5
```

| 策略 | 做法 |
|------|------|
| **就近连接** | 跨地域客户端连本地集群 |
| **故障切换** | `RetryTemplate` + 多地址自动切换 |
| **幂等校验** | 防止跨集群重复投递 |

## 4. 运维注意事项

| 原则 | 说明 |
|------|------|
| **配置一致** | 所有集群账号/密码/vhost/交换机/队列完全一致 |
| **网络延迟 < 50ms** | 跨地域需专线 |
| **避免循环同步** | 明确主从，不双向互相同步 |
| **定期容灾测试** | 每月 1 次主备切换演练 |
| **版本一致** | 所有节点 + 客户端依赖版本统一 |
