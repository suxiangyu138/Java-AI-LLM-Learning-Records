# RabbitMQ 网络分区图谱（生产级）

> **定位**：网络分区全流程可视化——成因→检测→应急处理→自动恢复→长效预防，可直接用于运维排查和团队培训。

---

## 全流程图谱

```text
成因（A）→ 发生分区（B）→ 检测（C）→ 应急处理（D/E）→ 恢复（F）→ 长效预防（G）
```

### A. 成因（4 类）

| 成因 | 说明 |
|------|------|
| A1 网络硬件故障 | 交换机/路由器宕机、网线断裂 |
| A2 网络配置异常 | 防火墙拦截 5672/25672、IP 变更 |
| A3 节点负载过高 | CPU/内存/磁盘耗尽 → 无响应 |
| A4 部署不合理 | 跨公网、不同网段，延迟 >100ms |

### B. 分区发生

```text
正常：rabbit@node1 ←→ rabbit@node2 ←→ rabbit@node3
分区：rabbit@node1 ✗ ↔ [rabbit@node2, rabbit@node3]
```

### C. 检测（3 种方式）

| 方式 | 操作 | 正常/异常 |
|------|------|-----------|
| C1 接口检测 | `/api/nodes` → `partitions` 字段 | 空 = 正常 / 非空 = 分区 |
| C2 命令检测 | `rabbitmqctl cluster_status` | partitions 空 = 正常 |
| C3 Web 界面 | Overview → Cluster Partitions | 0 = 正常 / >0 = 分区 |

### D/E. 应急处理

```text
D. 紧急止损
  ├── D1 通知 Java 开发 + 运维
  ├── D2 暂停消息收发（可选）
  └── D3 备份各分区数据

E. 恢复网络
  ├── E1 排查硬件（交换机/网线）
  ├── E2 检查防火墙规则（5672/25672）
  ├── E3 ping + telnet 验证连通
  └── E4 确认所有节点互通
```

### F. 合并分区

| 方式 | 条件 | 操作 |
|------|------|------|
| F1 自动合并 | `auto_heal=true` | 等待 1-5 分钟自动恢复 |
| F2 手动合并 | 自动失败 | `stop_app → reset → join_cluster → start_app` |
| F3 校验 | 合并后 | `rabbitmqctl cluster_status` + 接口验证 |
| F4 数据校验 | — | 队列消息数、交换机绑定、元数据一致性 |

### G. 长效预防

| 层面 | 措施 |
|------|------|
| G1 部署 | 奇数节点(3-5)、同局域网、跨地域用专线、双交换机 |
| G2 配置 | `heartbeat=30`、`auto_heal=true`、`connection_timeout=10000` |
| G3 网络 | 冗余网络、仅开必要端口、监控延迟/丢包 |
| G4 Java | 重连机制、幂等校验、持久化、多地址连接 |

## 核心关联点

| 图谱节点 | 关联前文 |
|----------|----------|
| C1 | `/api/nodes` 接口 `partitions` 字段 |
| F1/F2 | 网络分区处理命令 |
| G2 | `rabbitmq.conf` 预防配置 |
| G4 | Java 客户端重连+幂等配置 |

---

## 使用指南

| 场景 | 做法 |
|------|------|
| **故障排查** | C→定位→A→成因→D/E→处理 |
| **日常运维** | 关注 G1-G4 长效预防 |
| **团队培训** | 按图谱串联全流程 |
| **多集群** | 每集群单独绘制，区分联邦链路异常 vs 内部分区 |
