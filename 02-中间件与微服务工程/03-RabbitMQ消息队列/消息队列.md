## 1. 消息队列是什么

> 异步通信中间件——A 发消息到 MQ，B 从 MQ 取消息处理，A 和 B 不直接调用。

| 作用 | 说明 |
|------|------|
| **解耦** | 系统之间不直接依赖 |
| **异步** | 不用同步等待，提高响应速度 |
| **削峰** | 高并发请求暂存，慢慢消费 |
| **缓冲** | 流量突增不压垮下游 |

## 2. 主流 MQ 产品对比

| 产品 | 特点 | 适用场景 |
|------|------|----------|
| **RabbitMQ** | 轻量、易用、稳定 | 中小公司主流 |
| **RocketMQ** | 阿里开源，高吞吐、高可靠 | 电商、金融 |
| **Kafka** | 超高吞吐、日志、流处理 | 大数据场景 |
| ActiveMQ | 老牌 | 用得少 |

### 选型指南

| 场景 | 推荐 |
|------|------|
| 中小项目、易用 | RabbitMQ |
| 高并发、电商、金融 | RocketMQ |
| 日志、大数据、流处理 | Kafka |

## 3. 工作模式

| 模式 | 说明 |
|------|------|
| **点对点（P2P）** | 一生产者→一队列→一消费者，消息只消费一次 |
| **发布订阅（Pub/Sub）** | 多消费者订阅同一主题，都能收到 |
| 广播 | 所有消费者都收到 |
| 延迟队列 | 延迟一定时间后消费（订单超时取消） |

## 4. 核心问题与方案

| 问题 | 原因 | 方案 |
|------|------|------|
| **消息丢失** | 发失败/MQ 宕机/消费未处理完 | Confirm + 持久化 + 手动 ACK |
| **重复消费** | 网络重试/ACK 失败 | 业务幂等（唯一 ID + 状态机 + 锁） |
| **消息堆积** | 消费者慢/宕机/消息突增 | 加消费者 + 优化逻辑 + 分队列 |
| **消息乱序** | 多线程/多队列/重试 | 同业务同队列 + 单线程消费 |

---

## 5. 可靠机制

| 层级 | 机制 |
|------|------|
| **生产者** | 发送确认（Confirm）+ 事务消息 + 失败重试 |
| **Broker** | 持久化 + 集群/主从 + 刷盘策略 |
| **消费者** | 手动 ACK + 重试 + 死信队列 |

## 6. MQ 产品速查

### RabbitMQ

```text
模型：生产者 → 交换机 → 队列 → 消费者
交换机：direct / topic / fanout / headers
特性：持久化、手动ACK、死信Exchange、延迟队列（插件）
```

### RocketMQ

```text
特性：事务消息、延迟消息（18个等级）、主从架构、重试队列
适用：金融、电商高并发
```

### Kafka

```text
特性：分区（partition）、消费者组、offset消费
适用：日志、流处理、大数据
```
