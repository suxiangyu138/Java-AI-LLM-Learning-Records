## 一、数据库核心概念

### 1.1 什么是数据库（DB）

#### 理论核心

数据库（Database，简称 DB）是长期存储在计算机内、有组织、可共享的大量数据的集合，它采用特定的数据结构组织数据，能实现数据的高效存储、查询、修改和删除，且保证数据的完整性、安全性和一致性。

#### Java 后端视角

作为后端开发，我们写的接口（如用户登录、订单查询），本质都是通过 Java 代码操作数据库，获取或修改数据：

- **用户登录**：后端代码查询数据库中"用户表"的账号密码，判断是否匹配
- **下单操作**：向"订单表"插入新数据，同时修改"商品表"的库存

数据库就是后端的数据"仓库"，所有业务数据都依赖它存储。

> **企业级注意**：生产环境中数据库不会单机运行（避免单点故障），入门阶段先掌握单机基础，后续再讲解集群、主从复制等企业级部署方案。

### 1.2 数据库管理系统（DBMS）与 MySQL

#### 理论核心

数据库管理系统（Database Management System，简称 DBMS）是管理数据库的软件，负责统一管理和控制数据库。类比关系：

```
DBMS（仓库管理员） → 数据库（仓库） → 数据（仓库里的货物）
```

#### 主流 DBMS 对比

| DBMS | 类型 | 特点 | Java 后端适用度 |
|------|------|------|----------------|
| **MySQL** | 开源免费 | 轻量、高效、高并发 | ⭐⭐⭐⭐⭐ 首选（互联网项目） |
| **Oracle** | 收费 | 功能强大、稳定性高 | ⭐⭐⭐ 大型企业级 |
| **SQL Server** | 收费 | 微软出品，.NET 技术栈 | ⭐ Java 后端极少用 |

> **实战要点**：Java 后端通过 JDBC、MyBatis、Spring Data JPA 等框架操作 MySQL，无需直接操作 DBMS 软件，但必须理解 DBMS 的工作逻辑，才能排查数据操作问题（如连接超时、查询缓慢）。

### 1.3 数据库分类（关系型 vs 非关系型）

Java 后端开发中通常是"**关系型数据库为主，非关系型数据库为辅**"，二者搭配使用。

#### 关系型数据库（RDBMS）

以"关系模型"（表格形式）组织数据，表格之间有明确的关联关系，支持 SQL 操作，强调数据一致性和完整性。

| 代表 | 适用场景 |
|------|----------|
| MySQL | 电商、社交、后台管理系统 |
| Oracle | 银行、政务系统 |
| PostgreSQL | 复杂查询、GIS 地理数据 |

#### 非关系型数据库（NoSQL）

不采用表格结构，以键值对、文档、图形等形式存储数据，追求高并发、高可用、可扩展。

| 代表 | 类型 | 适用场景 |
|------|------|----------|
| **Redis** | 键值对 | 缓存热点数据、用户登录状态 |
| **MongoDB** | 文档型 | 非结构化数据（文章内容、用户日志） |
| **ElasticSearch** | 搜索引擎 | 全文检索 |

#### 企业级实战搭配

```
MySQL（核心业务数据） + Redis（缓存） + MongoDB（非结构化数据）
```

> 这是 Java 后端最常见的"关系型 + 非关系型"组合，后续会专门讲解实战场景。

## 二、MySQL 安装与环境配置

### 理论基础

- 企业级开发常用 **MySQL 8.0**（稳定、支持新特性：窗口函数、JSON 类型）
- 避免使用 5.6 及以下版本（语法不兼容、安全性不足）
- 版本分为：社区版（Community，免费）和企业版（Enterprise，收费）

### 安装步骤（简化版）

| 步骤 | 操作 | 注意事项 |
|------|------|----------|
| **下载** | 官网下载 [MySQL 8.0 社区版](https://dev.mysql.com/downloads/mysql/) | 选择对应系统（Windows/Linux） |
| **安装** | Windows 一路下一步，Linux 通过 yum/源码安装 | 设置 root 用户密码，避免简单密码（如 root123） |
| **测试连接** | `mysql -u root -p` 输入密码进入控制台 | 可搭配 Navicat、DBeaver 可视化工具 |

### 企业级核心配置

| 配置项 | 推荐值 | 说明 |
|--------|--------|------|
| 端口 | `3306` | 企业级可能修改端口，避免被攻击 |
| 字符集 | `utf8mb4` | 支持所有中文和 emoji，避免乱码 |
| 数据存储路径 | 自定义 | 避免系统盘满导致数据库崩溃 |
| 连接超时 | `wait_timeout = 86400` | 避免连接闲置过久被断开，适配 Java 连接池 |

> **企业级安全注意**：生产环境中 MySQL 不直接暴露公网，通过防火墙限制访问；root 用户仅允许本地登录，业务操作使用普通用户（最小权限原则）。

## 三、核心概念：数据库、表、字段、记录

### 层级关系

```
数据库（DB） > 表（Table） > 记录（Row）/ 字段（Column）
     ↓              ↓                   ↓
 Java 项目 >  Java 实体类 >  实体对象 / 属性
```

### Java 后端对应关系

| MySQL 概念 | 定义 | Java 后端对应物 | 企业级实例 |
|-----------|------|----------------|-----------|
| **数据库（DB）** | 独立的数据仓库 | 一个 Java 项目 | `db_ecommerce`（电商项目） |
| **表（Table）** | 基本存储单元 | Java 实体类 | `t_user`（用户表）、`t_order`（订单表） |
| **字段（Column）** | 数据的一个属性 | 实体类属性 | `id`、`username`、`password` |
| **记录（Row）** | 具体的数据对象 | 实体类对象 | `new User(1, "zhangsan", "123456")` |

### Java 类型映射

| MySQL 类型 | Java 类型 |
|-----------|----------|
| `BIGINT` | `Long` |
| `VARCHAR` | `String` |
| `INT` | `Integer` |
| `DECIMAL` | `BigDecimal` |
| `DATETIME` | `LocalDateTime` |

> **实战要点**：创建实体类时，属性名、数据类型要和 MySQL 表的字段一一对应，否则会出现数据映射异常（后续 MyBatis 实战章节详细讲解）。

## 四、入门实战：创建第一个数据库和表

### 目标

模拟 Java 后端项目，创建一个"用户管理"相关的数据库和用户表，练习基础 SQL 操作。

### 步骤 1：创建数据库

```sql
-- 企业级命名规范：db_项目名，小写，下划线分隔
CREATE DATABASE IF NOT EXISTS db_user_manage
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_general_ci;

-- 切换到该数据库（后续操作都针对这个数据库）
USE db_user_manage;
```

### 步骤 2：创建用户表

```sql
-- 企业级命名规范：t_表名，小写，下划线分隔
CREATE TABLE IF NOT EXISTS t_user (
    id          BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
    username    VARCHAR(50) NOT NULL UNIQUE COMMENT '用户名',
    password    VARCHAR(100) NOT NULL COMMENT '密码（加密存储）',
    phone       VARCHAR(20) COMMENT '手机号',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 步骤 3：插入测试数据

```sql
-- 模拟用户注册
INSERT INTO t_user (username, password, phone)
VALUES ('zhangsan', '123456', '13800138000');

-- 验证插入成功
SELECT * FROM t_user;
```

### 企业级注意事项

| 规范 | 说明 |
|------|------|
| **表引擎** | `InnoDB` 是企业级首选，支持事务和外键；`MyISAM` 已基本淘汰 |
| **密码存储** | 绝对不能存储明文密码，企业级中用 MD5、SHA256 等加密方式 |
| **字段约束** | `NOT NULL`、`UNIQUE` 是表设计基础，避免无效数据 |
