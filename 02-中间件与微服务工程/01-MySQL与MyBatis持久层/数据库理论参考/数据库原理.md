# 数据库原理

## 课程概述
- **课程性质**：专业核心必修课
- **适用专业**：计算机类各专业
- **开课学期**：大三学年
- **考核方式**：考试（闭卷）+ 实验 + 课程设计

## 课程目标
1. 掌握关系数据库的基本理论和设计方法
2. 熟练使用SQL语言进行数据定义、查询、更新
3. 理解数据库系统的内部实现机制（存储、索引、查询优化、事务）
4. 能够进行规范的数据库设计

## 核心知识点

### 第一章：数据库系统概论
- 数据管理技术的发展（人工管理→文件系统→数据库系统）
- 数据库系统的体系结构：外模式/模式/内模式（三级模式两级映像）
- 数据独立性：逻辑独立性与物理独立性
- 数据模型：层次模型、网状模型、关系模型

### 第二章：关系数据库
- 关系数据结构：域、笛卡尔积、关系、元组、属性
- 码：候选码、主码、外码
- 关系完整性约束：
  - 实体完整性（主码非空且唯一）
  - 参照完整性（外码要么为NULL，要么等于被参照表主码值）
  - 用户定义完整性
- 关系代数：
  - 集合运算：∪、∩、−、×
  - 专门关系运算：选择σ、投影π、连接⋈（等值连接、自然连接）、除÷
- 关系演算简介

### 第三章：SQL语言
- 数据定义(DDL)：CREATE TABLE、ALTER TABLE、DROP TABLE
- 数据查询(DQL)：
  - SELECT、FROM、WHERE、GROUP BY、HAVING、ORDER BY
  - 连接查询：内连接(INNER JOIN)、外连接(LEFT/RIGHT/FULL OUTER JOIN)
  - 嵌套查询（子查询）：IN、EXISTS、比较运算符
  - 聚合函数：COUNT、SUM、AVG、MAX、MIN
  - 集合查询：UNION、INTERSECT、EXCEPT
- 数据更新(DML)：INSERT、UPDATE、DELETE
- 视图(View)：虚拟表，简化复杂查询、保护数据安全
- 索引的创建与使用

### 第四章：数据库安全性
- 安全性控制机制：用户标识与鉴别、存取控制（GRANT/REVOKE）
- 自主存取控制(DAC)与强制存取控制(MAC)
- 视图机制
- 审计

### 第五章：数据库完整性
- 完整性约束的类别
- CHECK约束
- 断言(ASSERTION)
- 触发器(TRIGGER)：ECA规则（事件-条件-动作）

### 第六章：关系数据理论（规范化理论）
- 函数依赖：完全函数依赖、部分函数依赖、传递函数依赖
- 范式：
  - 1NF：属性不可再分
  - 2NF：消除非主属性对码的部分函数依赖
  - 3NF：消除非主属性对码的传递函数依赖
  - BCNF：消除主属性对码的部分和传递函数依赖
- Armstrong公理系统（推导函数依赖）
- 模式分解：无损连接分解、保持函数依赖分解

### 第七章：数据库设计
- 需求分析
- 概念结构设计：E-R模型（实体、属性、联系）
  - 1:1、1:N、M:N联系的转换方法
- 逻辑结构设计：E-R图→关系模式
- 物理结构设计：存储结构、索引选择
- 数据库实施与维护

### 第八章：事务管理与并发控制
- 事务的ACID特性：
  - 原子性(Atomicity)、一致性(Consistency)、隔离性(Isolation)、持久性(Durability)
- 并发操作带来的问题：丢失修改、读"脏"数据、不可重复读、幻读
- 封锁机制：
  - 共享锁(S锁/读锁)与排他锁(X锁/写锁)
  - 两段锁协议(2PL)
- 封锁粒度：多粒度封锁（意向锁）
- 事务隔离级别：READ UNCOMMITTED→READ COMMITTED→REPEATABLE READ→SERIALIZABLE

### 第九章：数据库恢复
- 故障分类：事务故障、系统故障、介质故障
- 冗余技术：数据转储、登记日志文件
- 恢复策略：
  - 事务故障：UNDO（反向扫描日志，撤销未完成事务）
  - 系统故障：UNDO + REDO
  - 介质故障：转储备份 + REDO日志

### 第十章：查询处理与优化
- 查询处理的步骤：语法分析→查询检查→查询优化→查询执行
- 代数优化（规则优化）
- 物理优化（基于代价的优化）
- SQL语句的等价转换规则

## 重点难点
- **重点**：SQL查询、关系代数、规范化设计（范式）、事务与封锁、E-R模型
- **难点**：范式判断与模式分解、两段锁协议、查询优化

## 学习方法与建议
1. 大量练习SQL查询语句，在MySQL/PostgreSQL上实际操作
2. 规范化理论需多做范式判定和模式分解的习题
3. 事务与并发的理论比较抽象，思考实际场景（如银行转账）
4. 动手设计一个小型数据库系统（需求→E-R→模式→SQL→应用）
