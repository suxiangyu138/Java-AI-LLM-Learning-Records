# 事务与锁

## 📌 课程定位
事务是数据库一致性的保障。理解ACID、隔离级别、MVCC是处理高并发业务的基础，也是面试"数据库"部分最难的一关。

## 🎯 核心章节

### 1. 事务 ACID 特性
- **原子性（Atomicity）**：要么全做、要么全不做——Undo Log回滚
- **一致性（Consistency）**：事务前后数据库都满足完整性约束——AID共同保证
- **隔离性（Isolation）**：并发事务互不干扰——锁+MVCC实现
- **持久性（Durability）**：提交的事务数据不丢失——Redo Log保证

### 2. 并发问题（无隔离级别的后果）
- **脏读**：读到其他事务未提交的数据——最严重
- **不可重复读**：同一事务内两次读同一行，结果不同（被其他事务UPDATE了）
- **幻读**：同一事务内两次查同一范围，行数不同（被其他事务INSERT了）

### 3. 四大隔离级别（⭐ 必背）
| 隔离级别 | 脏读 | 不可重复读 | 幻读 | 实现方式 |
|----------|------|----------|------|----------|
| READ UNCOMMITTED | ✗ | ✗ | ✗ | 不加锁 |
| READ COMMITTED | ✓ | ✗ | ✗ | 每次读生成ReadView |
| REPEATABLE READ | ✓ | ✓ | ✓(部分) | 事务开始生成ReadView |
| SERIALIZABLE | ✓ | ✓ | ✓ | 读加共享锁 |
- **MySQL默认REPEATABLE READ**（InnoDB通过临键锁解决大部分幻读）
- **Oracle/PostgreSQL默认READ COMMITTED**

### 4. MVCC（多版本并发控制，⭐ 核心机制）
- **思想**：写不阻塞读，读不阻塞写——通过保存数据的多个版本实现
- **三个隐藏列**：DB_TRX_ID(最近修改的事务ID)、DB_ROLL_PTR(回滚指针)、DB_ROW_ID(隐含主键)
- **Undo Log链**：每次修改前将旧版本写入Undo Log，通过回滚指针串联形成版本链
- **ReadView**：读操作时生成一个"快照"
  - 判断规则：trx_id < min_trx_id → 可见(已提交)；trx_id > max_trx_id → 不可见(未开始)；介于之间→看是否在当前活跃事务列表中
- **RC vs RR 的ReadView差异**：RC每次SELECT都生成新的ReadView，RR整个事务用同一个ReadView

### 5. 锁机制
- **按粒度**：表锁、行锁(通过索引实现——没索引就锁全表！)、页锁
- **按模式**：
  - 共享锁(S锁/读锁)：`SELECT ... LOCK IN SHARE MODE`——互不阻塞
  - 排他锁(X锁/写锁)：`SELECT ... FOR UPDATE`/UPDATE/DELETE——阻塞一切
- **意向锁**：IS/IX——表级意向锁，快速判断表中是否有行锁
- **临键锁（Next-Key Lock）**：行锁+间隙锁 —— 解决RR下的幻读
  - 间隙锁(Gap Lock)：锁住索引记录间的间隙，阻止INSERT
  - 唯一索引等值查询降级为行锁，非唯一索引或范围查询使用临键锁
- **死锁**：两个事务互相等待对方的锁→MySQL自动检测(超时/等待图)并回滚一个

### 6. Redo Log 与 Undo Log
- **Redo Log（重做日志）**：物理日志，记录"数据页做了什么修改"——崩溃恢复(Crash Safe)
  - WAL(Write-Ahead Log)：先写Redo Log再写数据——保证持久性
  - 固定大小、循环写——`innodb_log_file_size`
- **Undo Log（回滚日志）**：逻辑日志，记录"修改前的数据"——回滚+MVCC版本链
- **Binlog（归档日志）**：Server层日志，主从复制+数据恢复

- 临键锁的理解：`WHERE id>10 AND id<20 FOR UPDATE` 会锁哪些范围？
- 推荐阅读MySQL官方文档的InnoDB Locking章节
