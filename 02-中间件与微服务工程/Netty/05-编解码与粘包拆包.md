## 1. 粘包拆包问题

```text
TCP 是流式协议 — 无消息边界！

发送方发送：
  Packet A: "HELLO"    Packet B: "WORLD"

接收方可能收到：
  ① "HELLOWORLD"           ← 粘包（两个包粘在一起）
  ② "HELLO" + "WORLD"      ← 正常
  ③ "HEL" + "LOWORLD"      ← 拆包（一个包被拆成多块）
  ④ "HELLO" + "WOR" + "LD" ← 粘包+拆包混合

根本原因：
  → TCP 面向字节流，不保留消息边界
  → 发送方的 write() 次数 ≠ 接收方的 read() 次数
  → Nagle 算法合并小包、MSS 限制分包
```

## 2. Netty 内置拆包器

### 2.1 方案对比

| 拆包器 | 原理 | 适用场景 |
|--------|------|----------|
| **FixedLengthFrameDecoder** | 固定长度 | 定长协议 |
| **LineBasedFrameDecoder** | 换行符 `\n` / `\r\n` | 文本协议（Telnet） |
| **DelimiterBasedFrameDecoder** | 自定义分隔符 | 自定义分隔符协议 |
| **LengthFieldBasedFrameDecoder** | 长度域 | ⭐ 最通用，自定义二进制协议 |
| **HttpObjectAggregator** | HTTP 消息聚合 | HTTP 协议 |

### 2.2 FixedLengthFrameDecoder

```java
// 每 8 字节一个完整帧
pipeline.addLast(new FixedLengthFrameDecoder(8));
```

### 2.3 DelimiterBasedFrameDecoder

```java
// 以 _END_ 为分隔符
ByteBuf delimiter = Unpooled.copiedBuffer("_END_".getBytes());
pipeline.addLast(new DelimiterBasedFrameDecoder(1024, delimiter));
```

### 2.4 LengthFieldBasedFrameDecoder（⭐ 最常用）

```text
自定义协议格式：
┌──────────┬──────────────┬──────────┐
│  Length  │    Header    │   Body   │
│  (4字节)  │   (12字节)    │  (变长)   │
└──────────┴──────────────┴──────────┘
```

```java
//                                   最大长度 长度偏移 长度字节 长度调整 跳过字节
//                                      |      |      |       |       |
pipeline.addLast(new LengthFieldBasedFrameDecoder(
    65535,   // maxFrameLength: 最大帧长度
    0,       // lengthFieldOffset: 长度字段偏移（0=从头开始）
    4,       // lengthFieldLength: 长度字段占 4 字节
    0,       // lengthAdjustment: 长度调整值（长度域值+调整=Body长度）
    4        // initialBytesToStrip: 跳过前 4 字节（去掉 Length 域）
));

// 解码后 Handler 收到的就是 Body 部分
```

| 参数 | 说明 |
|------|------|
| `maxFrameLength` | 最大帧长，超限抛异常（防内存溢出） |
| `lengthFieldOffset` | 长度字段在帧中的偏移量 |
| `lengthFieldLength` | 长度字段占几个字节（1/2/4/8） |
| `lengthAdjustment` | 长度调整值（`lengthFieldValue + lengthAdjustment = Body长度`） |
| `initialBytesToStrip` | 跳过前 N 个字节（如跳过 Length 域本身） |

## 3. 自定义编解码器

### 3.1 Decoder（字节 → 对象）

```java
public class MessageDecoder extends ByteToMessageDecoder {
    @Override
    protected void decode(ChannelHandlerContext ctx, ByteBuf in, List<Object> out) {
        // ⚠️ 可读字节不足时直接 return，Netty 会累积数据后重试
        if (in.readableBytes() < 8) return;

        int type = in.readInt();
        int length = in.readInt();

        if (in.readableBytes() < length) {
            in.resetReaderIndex();   // 回退读指针，等数据完整
            return;
        }

        byte[] body = new byte[length];
        in.readBytes(body);
        out.add(new Message(type, body));   // 添加到输出列表
    }
}
```

### 3.2 Encoder（对象 → 字节）

```java
public class MessageEncoder extends MessageToByteEncoder<Message> {
    @Override
    protected void encode(ChannelHandlerContext ctx, Message msg, ByteBuf out) {
        out.writeInt(msg.getType());
        out.writeInt(msg.getBody().length);
        out.writeBytes(msg.getBody());
    }
}
```

### 3.3 MessageToMessage Codec

```java
// 对象 → 对象（非字节）的编解码
public class MessageCodec extends MessageToMessageCodec<ByteBuf, Message> {
    @Override protected void decode(ChannelHandlerContext ctx, ByteBuf in, List<Object> out) { }
    @Override protected void encode(ChannelHandlerContext ctx, Message msg, List<Object> out) { }
}

// 或分开写
pipeline.addLast(new MessageToMessageDecoder<ByteBuf>() { ... });
pipeline.addLast(new MessageToMessageEncoder<Message>() { ... });
```

## 4. 常见编解码方案

### 4.1 Protobuf（⭐ 推荐高性能场景）

```java
// Protobuf 自带 LengthFieldBasedFrameDecoder + ProtobufDecoder
pipeline
    .addLast(new ProtobufVarint32FrameDecoder())                 // 基于 Varint 长度
    .addLast(new ProtobufDecoder(MessageProto.Message.getDefaultInstance()))
    .addLast(new ProtobufVarint32LengthFieldPrepender())         // 编码：加长度
    .addLast(new ProtobufEncoder())
    .addLast(new BizHandler());
```

### 4.2 JSON（适合调试/API）

```java
pipeline
    .addLast(new StringDecoder(CharsetUtil.UTF_8))
    .addLast(new StringEncoder(CharsetUtil.UTF_8))
    .addLast(new JsonDecoder())
    .addLast(new BizHandler());
```

### 4.3 完整 Pipeline 配置套路

```java
// ⭐ 通用二进制协议的黄金 Pipeline
pipeline
    // ← 入站（Head → Tail）←
    .addLast(new LengthFieldBasedFrameDecoder(65535, 0, 4, 0, 4))  // ① 粘包处理
    .addLast(new MessageDecoder())                                   // ② 字节 → Message

    // ← 出站（Tail → Head）←
    .addLast(new MessageEncoder())                                   // ③ Message → 字节
    .addLast(new LengthFieldPrepender(4))                            // ④ 添加 4 字节长度头

    .addLast(new BizHandler());                                      // ⑤ 业务处理
```

> 🎯 **编解码核心**：LengthFieldBasedFrameDecoder 解决粘包 → 自定义 Decoder 转对象 → 业务 Handler 处理 → 自定义 Encoder 转字节 → LengthFieldPrepender 加长度头。管道顺序就是协议定义。
