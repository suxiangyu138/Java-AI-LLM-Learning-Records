## 一、前端基础核心（必掌握）

### 1. HTML 基础

> **核心目标**：看懂结构、能简单编写

| 知识点 | 要求 | 说明 |
|--------|------|------|
| **核心标签** | 掌握 | `<div>`、`<span>`、`<ul>`、`<li>`、`<table>`、`<form>`、`<input>`、`<button>` |
| **表单相关** | 重点掌握 | `form` 提交方式（`GET`/`POST`）、`input` 的 `type` 属性（`text`/`password`/`radio`/`checkbox`/`file`） |
| **基础属性** | 了解 | `id`（唯一标识）、`class`（样式控制）、`name`（表单提交键名） |

> **关键要求**：能看懂前端 HTML 结构，知道前端提交的数据对应哪个表单元素，能简单修改表单属性来匹配后端接口参数名。

### 2. CSS 基础

> **核心目标**：看懂样式、能简单调试

| 知识点 | 要求 | 说明 |
|--------|------|------|
| **基础选择器** | 掌握 | `#id`、`.class`、`div`（标签选择器） |
| **核心样式属性** | 了解 | `display`、`margin`/`padding`、`width`/`height`、`color`、`background` |
| **布局基础** | 了解 | Flex 布局（弹性布局），理解元素排列方式 |

> **关键要求**：能通过浏览器 F12 调试工具查看和修改 CSS，排查"元素不显示""布局错乱"等简单问题。

### 3. JavaScript 基础

> **核心目标**：理解逻辑、能配合联调

#### 3.1 基础语法（看懂即可）

| 知识点 | 说明 |
|--------|------|
| **变量与数据类型** | `var`/`let`/`const`、String、Number、Object、Array |
| **基础逻辑** | `if-else`、`for` 循环、`function` 函数 |

#### 3.2 核心重点（后端必掌握）

**DOM 操作基础**：

```javascript
// 获取页面元素
document.getElementById('id')
document.querySelector('.class')

// 修改元素内容
element.innerText = '文本'
element.innerHTML = '<p>HTML</p>'
```

**事件绑定**：

```javascript
// 常见事件：click、input、submit
element.onclick = function() {}
element.addEventListener('click', function() {})
```

**异步请求（重中之重）**：

| 方式 | 说明 | 核心参数 |
|------|------|----------|
| **AJAX** | 传统方式 | `url`、`method`、`data` |
| **Fetch** | 原生 API | `url`、`method`、`body`、`headers` |
| **Axios** | 最常用（推荐） | `url`、`method`、`params`（GET）、`data`（POST） |

> **GET vs POST 区别**：GET 参数拼接在 URL 上（查询数据），POST 参数放在请求体中（提交数据）。

**JSON 数据处理**：

```javascript
// JSON 字符串 → JavaScript 对象（解析）
JSON.parse(jsonStr)

// JavaScript 对象 → JSON 字符串（序列化）
JSON.stringify(obj)
```

> 与后端接口的请求体、响应体格式完全对应：后端返回 JSON → 前端解析 JSON；前端提交 JSON → 后端接收解析。

## 二、前后端协作核心（必掌握）

### 1. 接口联调基础

#### 请求方式

| 方法 | 用途 | Spring Boot 注解 |
|------|------|-----------------|
| `GET` | 查询数据 | `@GetMapping` |
| `POST` | 新增数据 | `@PostMapping` |
| `PUT` | 修改数据 | `@PutMapping` |
| `DELETE` | 删除数据 | `@DeleteMapping` |

#### 参数传递

| 类型 | 格式 | 前端传递 | 后端接收 |
|------|------|----------|----------|
| **路径参数** | `/api/user/{id}` | URL 路径 | `@PathVariable` |
| **Query 参数** | `/api/user?name=zhangsan` | URL 拼接 | `@RequestParam` |
| **Body 参数** | JSON 格式请求体 | POST/PUT body | `@RequestBody` |

#### 跨域问题

- **概念**：浏览器的同源策略阻止不同源的请求
- **解决**：Spring Boot 添加 `@CrossOrigin` 注解
- **排查**：查看响应头是否缺少 `Access-Control-Allow-Origin`

### 2. 浏览器调试工具

| 面板 | 用途 | 常见排查 |
|------|------|----------|
| **Elements** | 查看 HTML 结构、CSS 样式 | 页面结构错误、样式问题 |
| **Network** | 查看所有请求（URL、参数、响应、状态码） | 接口 404/400/500 排查 |
| **Console** | 查看 JS 错误信息 | 语法错误、请求错误 |

| 状态码 | 含义 | 排查方向 |
|--------|------|----------|
| `404` | URL 错误 | 检查接口路径 |
| `400` | 参数格式错误 | 检查请求参数 |
| `500` | 后端接口错误 | 检查后端日志 |

## 四、避坑要点

| 常见问题 | 原因 | 解决方案 |
|----------|------|----------|
| **参数格式不一致** | 前端传 `userName`，后端收 `username` | 统一命名规范，前后端对齐 |
| **跨域问题** | 后端未处理跨域 | 添加 `@CrossOrigin` 或全局跨域配置 |
| **响应格式不规范** | 后端返回格式与前端预期不一致 | 统一使用 `{code, message, data}` 格式 |
| **忽略前端请求头** | 前端携带 Token 但后端未接收 | 使用 `@RequestHeader` 正确接收 |

## 五、总结

> **核心原则**：后端掌握前端知识，核心目的是"高效协作、独立排查问题"，无需成为前端开发。

| 必须做到 | 无需做到 |
|----------|----------|
| 能看懂前端代码（HTML/CSS/JS） | 独立开发复杂前端页面 |
| 能配合前端联调接口 | 深入掌握前端框架开发 |
| 能使用调试工具排查问题 | 编写复杂 CSS 样式 |
| 能独立测试后端接口 | 掌握前端构建配置 |

**核心聚焦**：接口联调、异步请求、JSON 处理、跨域问题 — 这些是后端与前端协作的核心，也是提升开发效率的关键。
