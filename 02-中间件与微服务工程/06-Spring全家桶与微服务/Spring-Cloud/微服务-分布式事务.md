# 微服务 - 分布式事务

> **定位**：跨多个服务、多个数据库的事务协同——要么全成功，要么全回滚。CAP 定理约束下，优先选 AP + 最终一致性。

---

## 1. 核心理论

### CAP 定理

| 选择 | 场景 |
|:----:|------|
| **CP**（一致性优先） | 金融、支付 |
| **AP**（可用性优先）⭐ | 大多数业务（电商、社交） |

### BASE 理论

| 概念 | 说明 |
|------|------|
| **基本可用** | 故障时允许降级 |
| **软状态** | 允许短暂不一致 |
| **最终一致性** | 补偿机制兜底 |

---

## 2. 四大解决方案

| 方案 | 一致性 | 性能 | 开发成本 | 适用场景 |
|------|:------:|:----:|:------:|----------|
| **Seata AT** | 强 | 中 | 低 | 金融、支付 |
| **TCC** | 最终 | 高 | 中 | 高并发下单、秒杀 |
| **本地消息表** | 最终 | 中 | 低 | 中小规模 |
| **RocketMQ 事务** | 最终 | 高 | 中 | 大流量、解耦 |

### 2.1 Seata AT 模式

```java
@GlobalTransactional(rollbackFor = Exception.class)
public void createOrder(OrderDTO dto) {
    orderMapper.insert(dto);                     // ① 创建订单
    stockFeignClient.deductStock(dto.getProductId(), dto.getNum());  // ② 扣库存
    payFeignClient.deductBalance(dto.getUserId(), dto.getAmount());  // ③ 扣余额
    // 任一步骤失败 → Seata 自动回滚全部
}
```

### 2.2 TCC（Try-Confirm-Cancel）

```text
Try：锁定资源（冻结库存/余额）
Confirm：所有 Try 成功 → 执行确认
Cancel：任一 Try 失败 → 全部回滚
```

### 2.3 本地消息表

```text
① 业务操作 + 写入消息表（同一本地事务）
② 定时任务扫描 → 调用下游服务
③ 成功 → 标记已发送 / 失败 → 重试（最多 3 次）
```

### 2.4 RocketMQ 事务消息

```java
// 半事务消息
rocketMQTemplate.sendMessageInTransaction("topic", message, bizArg);
// 事务回调：校验本地事务 → COMMIT / ROLLBACK
```

---

## 3. 避坑要点

| 问题 | 方案 |
|------|------|
| 数据不一致 | 最终一致性 + 补偿机制 |
| 重复消费 | 幂等校验（订单 ID + Redis/DB 去重） |
| 性能下降 | 减少事务范围 + 优先 TCC/MQ |
| Seata 不生效 | 版本匹配 + `@GlobalTransactional` + 事务组一致 |
