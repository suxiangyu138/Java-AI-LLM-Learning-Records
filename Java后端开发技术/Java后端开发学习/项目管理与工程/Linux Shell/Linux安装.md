Linux安装
一、前言：Java后端开发为何要重视Linux安装？
Java后端开发的核心部署环境几乎都是Linux系统（CentOS、Ubuntu、Rocky Linux等），无论是生产环境的服务器、测试环境的虚拟机，还是本地开发的Docker容器，Linux的安装质量直接影响后续JDK部署、Tomcat/Nginx配置、数据库搭建（MySQL、Redis）及项目部署的稳定性。不同于普通桌面端Linux使用，后端开发视角下的Linux安装，核心诉求是“轻量化、可配置、易部署、高兼容”——无需多余桌面组件，重点保障命令行操作、网络连通性、权限管理及软件依赖兼容性，为后续Java项目运行奠定基础。
本文将从后端开发实际场景出发，跳过冗余的桌面版安装，聚焦服务器版Linux（以主流的CentOS 8 Stream、Ubuntu Server 22.04 LTS为例），深度剖析安装的核心步骤、关键配置及后端开发专属优化，解决“安装后无法联网”“权限不足”“依赖缺失导致JDK无法安装”等常见问题。
二、安装前准备：后端开发视角的环境规划
安装前的规划直接决定后续开发、部署效率，核心围绕“硬件适配、系统选型、网络规划、分区设计”四大维度，贴合Java后端开发的实际需求（如内存分配、存储分区适配数据库和项目文件）。

Java后端开发中，Linux版本的选择需兼顾“稳定性、兼容性、社区支持”，避免选择过于小众或版本过新/过旧的系统，以下是主流版本对比及选型建议：

2.2 硬件配置：贴合Java项目运行需求
Java项目（尤其是Spring Boot、微服务项目）对内存、CPU有一定要求，安装前需根据场景配置硬件，避免因资源不足导致项目启动失败或运行卡顿：
本地开发虚拟机：CPU ≥ 2核，内存 ≥ 4G（建议8G，满足JDK、MySQL、Tomcat同时运行），硬盘 ≥ 50G（建议100G，预留项目文件、日志、依赖包存储）。
测试环境服务器：CPU ≥ 4核，内存 ≥ 8G，硬盘 ≥ 100G（建议分区分盘，分离系统和数据）。
生产环境服务器：根据项目并发量调整，CPU ≥ 8核，内存 ≥ 16G，硬盘 ≥ 200G（建议使用SSD，提升数据库读写速度），支持扩展。
2.3 其他准备工作
下载系统镜像：从官方网站下载对应版本的服务器版镜像（ISO文件），避免第三方镜像（可能包含恶意软件），推荐阿里云镜像源（速度快，适配国内网络）。
准备安装介质：虚拟机（VMware、VirtualBox）或物理服务器，虚拟机需提前创建虚拟机，配置硬件参数（对应上述硬件要求）。
网络规划：提前确定Linux系统的IP地址（建议静态IP，避免后续IP变动导致项目访问失败）、子网掩码、网关、DNS（推荐8.8.8.8或国内DNS如223.5.5.5）。
三、核心安装步骤：后端开发专属配置（以CentOS 8 Stream为例）
后端开发视角下的Linux安装，核心是“精简、高效、可配置”，跳过桌面组件安装，重点配置网络、分区、权限，确保安装完成后可直接进行JDK、数据库等软件部署。
3.1 虚拟机创建与镜像挂载（本地开发场景）
打开VMware，创建新虚拟机，选择“自定义（高级）”，兼容模式选择最新版本，点击下一步。
选择“安装程序光盘映像文件（ISO）”，浏览并选择下载好的CentOS 8 Stream ISO文件，点击下一步。
配置虚拟机名称（如“Java-Backend-CentOS8”），选择安装路径（建议非系统盘，避免占用C盘空间），点击下一步。
配置硬件参数：CPU设置为2核及以上，内存设置为4G及以上，硬盘设置为100G，网络适配器选择“桥接模式”（方便本地开发机与虚拟机互通，后续部署项目可直接访问），点击完成。
启动虚拟机，开始Linux安装流程，选择“Install CentOS Stream 8”，进入安装界面。
3.2 安装界面核心配置（关键步骤，影响后续开发）
3.2.1 语言选择
建议选择“English”，避免中文环境下的命令行乱码问题（后续可通过配置locale解决，但英文环境更适配后端开发的命令行操作）。
3.2.2 时间与时区配置
选择“Time & Date”，时区设置为“Asia/Shanghai”（上海时区），开启网络时间同步（NTP），确保Linux系统时间与本地开发机一致——避免因时间偏差导致数据库日志、项目日志混乱，以及接口调用时的时间戳异常。
3.2.3 网络配置（后端开发重中之重）
网络配置直接决定后续JDK下载、Maven依赖拉取、项目部署后的访问，核心是配置静态IP，步骤如下：
选择“Network & Host Name”，开启网络连接（开关拨至“ON”）。
点击“Configure”，进入网络配置界面，选择“IPv4 Settings”，方法选择“Manual”（手动配置静态IP）。
添加静态IP：填写IP地址（如192.168.1.100，需与本地开发机在同一网段）、子网掩码（255.255.255.0）、网关（如192.168.1.1，与本地路由器网关一致）、DNS（8.8.8.8和223.5.5.5）。
勾选“Automatically connect”（开机自动联网），点击“Save”保存配置，返回安装界面，此时网络已连通。
设置主机名（如“java-server”），点击“Apply”，方便后续通过主机名访问虚拟机。
注意：静态IP的网段必须与本地开发机一致，否则无法互通。可通过本地开发机“cmd”输入“ipconfig”查看本机IP和网关，确保Linux的IP在同一网段（如本机IP为192.168.1.50，Linux可设置为192.168.1.100）。
3.2.4 分区配置（适配Java项目与数据库存储）
后端开发中，Linux分区需兼顾“系统稳定性、数据安全性”，避免所有文件都放在根分区（导致根分区满，项目崩溃），推荐分区方案如下（以100G硬盘为例）：
/boot：引导分区，建议2G，存储系统引导文件，避免引导失败。
swap：交换分区，当内存不足时，系统会使用swap分区临时存储数据，建议设置为内存的1.5倍（如内存8G，swap设置为12G），避免Java项目内存溢出时系统崩溃。
/：根分区，建议30G，存储系统文件和常用软件（JDK、Tomcat等）。
/data：数据分区，剩余空间（约56G），用于存储Java项目文件、数据库数据（MySQL、Redis）、日志文件——将数据与系统分离，方便后续备份和迁移，避免系统重装导致数据丢失。
操作步骤：选择“Installation Destination”，勾选需要分区的硬盘，选择“Custom”（自定义分区），按照上述方案创建分区，点击“Done”保存配置。
3.2.5 软件包选择（精简为主，避免冗余）
后端开发无需安装桌面组件，选择“Software Selection”，默认是“Minimal Install”（最小化安装），此版本仅包含核心命令行工具，无多余桌面组件，占用资源少，适合服务器环境。
补充选择：可勾选“Development Tools”（开发工具集），包含gcc、make等编译工具，后续安装JDK、MySQL时可能需要（避免手动安装依赖，节省时间）。
3.2.6 用户名与密码配置（权限管理基础）
设置root密码：root用户是Linux最高权限用户，后端开发中很多操作（如安装软件、修改配置文件）需要root权限，设置一个复杂度高的密码（字母+数字+特殊符号），避免密码泄露导致安全风险。
创建普通用户：建议创建一个普通用户（如“java”），用于日常开发操作（如部署项目、查看日志），避免直接使用root用户操作（防止误操作删除系统文件）。勾选“Make this user an administrator”（赋予管理员权限，可通过sudo命令执行root操作），设置用户名和密码。
3.2.7 开始安装与重启
所有配置完成后，点击“Begin Installation”，开始安装系统（约10-15分钟，取决于硬件配置）。安装完成后，点击“Reboot”重启系统，重启后输入用户名和密码，即可进入Linux命令行界面。
四、安装后验证：后端开发必备检查
安装完成后，需进行一系列验证，确保系统符合Java后端开发要求，避免后续部署软件时出现问题。
4.1 网络连通性验证
核心验证“Linux能访问外网”“本地开发机能访问Linux”，命令如下：
检查Linux外网连通性：在命令行输入ping www.baidu.com，若能正常接收数据包，说明外网连通（可正常下载JDK、Maven依赖）；若无法连通，检查网络配置（静态IP、网关、DNS）。
检查本地开发机与Linux连通性：在本地开发机cmd输入 ping 192.168.1.100（Linux的静态IP），若能正常接收数据包，说明连通（后续可通过Xshell、SecureCRT等工具远程连接Linux）。
4.2 系统基础环境验证
查看系统版本：输入 cat /etc/centos-release，确认系统版本为CentOS 8 Stream，避免安装错误。
查看IP配置：输入 ip addr，确认静态IP配置正确（与安装时设置的一致）。
查看分区情况：输入 df -h，确认分区配置正确（/boot、swap、/、/data分区正常挂载）。
4.3 必备工具安装（后端开发前置依赖）
最小化安装的Linux缺少部分后端开发必备工具，需手动安装，命令如下（root用户或sudo权限）：
安装wget（用于下载文件，如JDK安装包）：yum install -y wget（CentOS）或 apt install -y wget（Ubuntu）。
安装vim（用于编辑配置文件，如JDK环境变量、Tomcat配置）：yum install -y vim 或 apt install -y vim。
关闭防火墙（开发/测试环境，方便项目访问；生产环境需配置防火墙规则，而非直接关闭）：systemctl stop firewalld（停止防火墙）、systemctl disable firewalld（禁止开机自启）。
关闭SELinux（避免权限限制，导致JDK、Tomcat无法正常运行）：输入 vim /etc/selinux/config，将SELINUX=enforcing 改为 SELINUX=disabled，保存退出后，重启系统生效（reboot）。
五、Ubuntu Server 22.04 LTS安装差异（本地开发优选）
Ubuntu Server与CentOS的安装流程大致相同，核心差异在于“包管理器（apt vs yum）”“网络配置方式”，以下是后端开发视角的关键差异点：
软件包选择：安装时选择“Minimal Ubuntu Server”，无需勾选多余组件，安装完成后默认已开启SSH（可直接远程连接）。
网络配置：Ubuntu Server安装时会自动询问是否配置静态IP，按照提示输入IP、网关、DNS即可，无需手动进入配置界面。
包管理器：后续安装软件使用apt命令，而非yum，例如安装wget：apt update && apt install -y wget（update用于更新软件源，避免安装失败）。
防火墙：Ubuntu默认使用ufw防火墙，关闭命令：ufw disable，查看状态：ufw status。
六、常见问题排查（后端开发高频场景）
6.1 安装后无法联网
排查1：检查网络配置是否正确（IP、网关、DNS），输入 ip addr 确认IP是否生效，输入cat /etc/sysconfig/network-scripts/ifcfg-ens33（CentOS）查看网卡配置文件（ens33为网卡名称，可能不同），确保BOOTPROTO=static、ONBOOT=yes。
排查2：检查网关是否可达，输入 ping 192.168.1.1（网关IP），若无法ping通，检查虚拟机网络适配器是否为桥接模式，或本地路由器是否限制连接。
排查3：检查DNS配置，输入 cat /etc/resolv.conf，确认DNS为8.8.8.8或223.5.5.5，若未配置，手动添加：echo "nameserver 8.8.8.8" >> /etc/resolv.conf。
6.2 远程连接失败（Xshell/SecureCRT）
排查1：检查Linux是否安装SSH服务，CentOS最小化安装默认未安装，输入 yum install -y openssh-server 安装，启动SSH服务：systemctl start sshd，设置开机自启：systemctl enable sshd。
排查2：检查防火墙是否关闭（开发/测试环境），或防火墙是否开放22端口（SSH默认端口），CentOS开放端口命令：firewall-cmd --add-port=22/tcp --permanent，重启防火墙：firewall-cmd --reload。
排查3：确认本地开发机与Linux在同一网段，且ping能通，远程连接时输入Linux的静态IP、用户名和密码，避免输入错误。
6.3 安装软件时依赖缺失
后端开发安装JDK、MySQL时，可能出现“依赖缺失”报错，解决方法：
CentOS：输入 yum install -y epel-release 安装额外软件源，再执行安装命令；或使用 yum install -y 缺失的依赖包名称 手动安装依赖。
Ubuntu：输入 apt update 更新软件源，再执行安装命令；或使用 apt install -y 缺失的依赖包名称 手动安装依赖。
七、总结：后端开发视角的Linux安装核心要点
Java后端开发的Linux安装，核心不是“完成安装”，而是“安装后能直接用于开发、部署”，关键要点总结如下：
选型优先：生产/测试用CentOS 8 Stream/Rocky Linux 9，本地开发用Ubuntu Server 22.04 LTS，避免版本兼容问题。
网络优先：配置静态IP，确保外网连通、本地互通，为后续软件下载和项目访问奠定基础。
分区合理：分离系统与数据（/data分区），避免数据丢失，适配数据库和项目文件存储。
精简高效：最小化安装，关闭不必要的服务（防火墙、SELinux，开发/测试环境），安装必备工具（wget、vim、SSH）。
权限安全：创建普通用户，避免直接使用root操作，降低误操作风险。
Linux安装是Java后端开发的基础，后续JDK部署、Tomcat配置、数据库搭建、项目部署，都依赖于一个稳定、配置合理的Linux环境。掌握上述安装要点和问题排查方法，能有效提升开发、部署效率，避免因环境问题影响项目进度。
