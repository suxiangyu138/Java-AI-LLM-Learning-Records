消息队列
-------------------------------------------------------------------
一、消息队列是什么
消息队列是一种**异步通信**中间件。
应用A把消息发给MQ，应用B从MQ取消息处理，A和B不直接调用，解耦、异步、削峰。
核心作用：
1. 解耦：系统之间不直接依赖
2. 异步：不用同步等待，提高响应速度
3. 削峰：高并发时把请求暂存，慢慢消费
4. 缓冲：流量突增不压垮下游
-------------------------------------------------------------------
二、常见MQ产品（企业主流）
1. RabbitMQ
   轻量、易用、稳定，中小公司主流
2. RocketMQ
   阿里开源，高吞吐、高可靠，适合电商、金融
3. Kafka
   超高吞吐、日志、流处理、大数据场景
4. ActiveMQ
   老牌，现在用得少
-------------------------------------------------------------------
三、核心概念
1. 生产者：发消息的一方
2. 消费者：收消息、处理消息的一方
3. 队列/主题：消息存放的地方
   - 队列：点对点，一条消息只被消费一次
   - 主题：发布订阅，一条消息可被多个消费者消费
4. Broker：MQ服务端
5. 消息：要传递的数据
6. 偏移量（offset）：消费位置标记
7. 确认机制（ACK）：告诉MQ消息已处理
-------------------------------------------------------------------
四、消息队列工作模式
1. 点对点（P2P）
   一个生产者 → 一个队列 → 一个消费者
   消息只消费一次
2. 发布/订阅（Pub/Sub）
   生产者发主题
   多个消费者订阅同一个主题，都能收到消息
3. 广播模式
   所有消费者都收到消息
4. 延迟队列
   消息延迟一定时间后才被消费
   订单超时未支付自动取消、验证码过期等场景
-------------------------------------------------------------------
五、消息队列核心问题（面试必考）
1. 消息丢失
   原因：
   - 生产者发失败
   - MQ宕机
   - 消费者没处理完就宕机
   解决：
   - 生产者确认机制
   - MQ持久化
   - 消费者手动ACK
2. 消息重复消费（幂等性问题）
   原因：网络重试、ACK失败
   解决：
   - 业务幂等（唯一ID、状态机）
   - 数据库唯一约束
   - 分布式锁
   - 记录已消费ID
3. 消息堆积
   原因：
   - 消费者处理慢
   - 消费者宕机
   - 消息量突增
   解决：
   - 增加消费者
   - 优化消费逻辑
   - 分队列、分主题
   - 批量消费
4. 消息乱序
   原因：多线程、多队列、重试
   解决：
   - 同一业务用同一个队列
   - 单线程消费
   - 带顺序标识，业务层排序
5. 死信队列（DLQ）
   消息无法被消费，进入死信队列
   场景：
   - 过期
   - 被拒绝
   - 达到最大重试次数
   作用：统一处理失败消息
-------------------------------------------------------------------
六、消息可靠性机制（企业必开）
1. 生产者可靠性
   - 同步/异步发送
   - 事务消息
   - 发送确认（Confirm）
   - 失败重试
2. MQ可靠性
   - 消息持久化（磁盘）
   - 集群、主从
   - 刷盘策略
3. 消费者可靠性
   - 手动ACK（不要自动ACK）
   - 重试机制
   - 失败进入死信
-------------------------------------------------------------------
七、高级特性
1. 延迟消息
   订单超时、支付超时、验证码过期
2. 事务消息
   保证本地事务和发消息**原子性**
   电商下单+扣库存+发通知常用
3. 批量发送/批量消费
   提高吞吐量
4. 消息回溯
   重新消费某段消息
5. 限流、流量控制
   保护下游系统
6. 消息追踪
   查看消息从生产到消费全链路
-------------------------------------------------------------------
八、使用场景（企业最常用）
1. 异步通知
   注册成功发短信、发邮件
2. 系统解耦
   订单系统 ↔ 库存系统 ↔ 物流系统 ↔ 积分系统
3. 削峰填谷
   秒杀、下单、高并发接口
4. 最终一致性
   分布式事务（柔性事务）
5. 延迟任务
   订单超时关闭
   未支付自动取消
6. 日志收集、流数据处理
   Kafka 常用
-------------------------------------------------------------------
九、RabbitMQ 核心知识点
1. 模型：生产者 → 交换机 → 队列 → 消费者
2. 交换机类型：
   - direct 直连
   - topic 主题（通配符）
   - fanout 广播
   - headers 头匹配
3. 持久化：队列、消息都要持久化
4. 手动ACK：确保消息不丢
5. 死信Exchange：处理失败消息
6. 延迟队列：用插件或死信实现
-------------------------------------------------------------------
十、RocketMQ 核心知识点
1. 高性能、高可靠、阿里出品
2. 支持事务消息
3. 支持延迟消息（18个固定等级）
4. 主从架构
5. 重试队列、死信队列
6. 适合金融、电商高并发
-------------------------------------------------------------------
十一、Kafka 核心知识点
1. 超高吞吐
2. 分区（partition）提高并发
3. 消费者组
4. 按offset消费
5. 日志、流处理、大数据场景
6. 不适合严格消息有序
-------------------------------------------------------------------
十二、如何选择MQ
1. 中小项目、易用：RabbitMQ
2. 高并发、电商、金融：RocketMQ
3. 日志、大数据、流处理：Kafka
-------------------------------------------------------------------
十三、消息队列架构设计（面试常问）
1. 高可用：集群、主从、多机房
2. 高可靠：持久化、确认机制、死信
3. 高吞吐：分区、批量、异步
4. 可监控：消息堆积、丢失、重复、耗时
5. 可运维：动态扩容、消息回溯、异常处理
-------------------------------------------------------------------
十四、总结一句话
消息队列 = 异步 + 解耦 + 削峰 + 缓冲
核心要解决：不丢、不重、不乱、不堆积。
