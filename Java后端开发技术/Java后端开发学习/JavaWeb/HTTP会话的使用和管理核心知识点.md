HTTP会话的使用和管理核心知识点
---------------------------------------------------------------------------------------------------------------------------------------
一、会话机制的由来
1. HTTP是无状态协议，服务器无法识别多次请求是否来自同一个用户。
2. 会话（Session）用于在服务器端保存用户状态，实现多次请求之间的数据共享。
3. 典型场景：用户登录状态、购物车、验证码、个人信息。
---------------------------------------------------------------------------------------------------------------------------------------
二、会话核心概念
1. Session
服务器为每个用户单独开辟的存储空间，用于保存该用户的数据。
2. SessionID
服务器为每个会话生成的唯一标识，用于区分不同用户。
3. 传递方式
默认通过Cookie传递SessionID，浏览器每次请求自动携带。
4. 生命周期
第一次请求时创建，超时或主动注销时销毁。
---------------------------------------------------------------------------------------------------------------------------------------
三、JavaWeb中会话常用操作
1. 获取会话
HttpSession session = request.getSession();
获取当前会话，没有则自动创建。
HttpSession session = request.getSession(false);
只获取，不创建新会话。
2. 存储数据
session.setAttribute("key", value);
3. 获取数据
Object obj = session.getAttribute("key");
4. 删除数据
session.removeAttribute("key");
5. 销毁会话（退出登录）
session.invalidate();
6. 设置会话超时时间
session.setMaxInactiveInterval(秒数);
---------------------------------------------------------------------------------------------------------------------------------------
四、会话超时配置
1. 代码配置
session.setMaxInactiveInterval(1800);
2. web.xml全局配置
<session-config>
    <session-timeout>30</session-timeout>
</session-config>
3. Tomcat全局默认配置
在conf/web.xml中设置session-timeout。
---------------------------------------------------------------------------------------------------------------------------------------
五、SessionID传递方式
1. Cookie传递（默认）
服务器通过Set-Cookie响应头返回JSESSIONID。
浏览器自动在请求头中携带Cookie。
2. URL重写（禁用Cookie时）
将SessionID拼接在URL后面。
String url = response.encodeURL("cart.jsp");
---------------------------------------------------------------------------------------------------------------------------------------
六、四大作用域（从小到大）
1. pageContext：当前页面有效
2. request：一次请求有效
3. session：一次会话有效（多次请求）
4. application：整个应用运行期间有效
---------------------------------------------------------------------------------------------------------------------------------------
七、会话安全要点
1. 设置Cookie为HttpOnly
防止JS读取，防范XSS攻击。
2. 登录成功后重置SessionID
避免会话固定攻击。
3. 敏感操作必须校验登录状态
如支付、修改密码、注销。
4. 用户退出必须销毁会话
调用session.invalidate()。
---------------------------------------------------------------------------------------------------------------------------------------
八、集群环境会话共享
1. 单机Tomcat：Session保存在内存。
2. 多台Tomcat集群：Session不互通，用户会反复登录。
3. 解决方案：
使用Redis统一存储Session。
Spring Session + Redis是企业常用方案。
---------------------------------------------------------------------------------------------------------------------------------------
九、Session与Cookie区别
1. Session
存储在服务器，安全，可存对象，大小无限制。
2. Cookie
存储在浏览器，不安全，只能存字符串，大小有限制。
3. 关系
Cookie保存SessionID，Session保存真实业务数据。
---------------------------------------------------------------------------------------------------------------------------------------
十、企业开发常用总结
1. 登录信息、购物车、验证码存入Session。
2. 登录创建会话，退出销毁会话。
3. 使用Filter统一拦截未登录请求。
4. 集群项目必须使用Redis实现Session共享。
5. 必须做安全控制：HttpOnly、重置SessionID、超时控制。
