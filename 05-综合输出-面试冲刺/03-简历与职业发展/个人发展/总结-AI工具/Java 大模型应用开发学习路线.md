# Java 大模型应用开发学习路线

## 概述

> **核心理念**：以 Java + Spring Boot 工程能力为主，把大模型当成外部服务/组件来用。先会"用"，再会"组合"，最后会"工程化上线"。不急着学算法，先做出可运行的 AI 功能。

## 阶段一：打基础（1~2 周）

> **目标**：能写 Java 程序，能调通大模型 API，跑出第一个 AI 功能。

| 模块 | 核心内容 | 技术点 |
|------|---------|--------|
| **Java & Spring Boot 复习** | 集合、IO、异常处理；Spring Boot 项目创建、REST API 编写 | — |
| **大模型基础概念** | LLM、Token、上下文长度、温度（Temperature）等基本概念 | 了解 GPT、通义千问、文心一言、DeepSeek 等主流模型 |
| **调用大模型 API** | 用 HttpClient / OkHttp 发 POST 请求；Spring Boot 封装 `/chat` 接口 | HTTP 通信、JSON 序列化、流式输出（SSE） |
| **小项目** | 做一个"智能聊天接口"或"代码生成小助手"，前端用 Postman 测试 | 端到端联调 |

> ✅ **产出**：能调通 API 的 Spring Boot 服务，可返回模型回答。

---

## 阶段二：RAG 检索增强生成（2~4 周）

> **目标**：让模型能基于你自己的数据回答问题，解决"知识过期"和"幻觉"问题。

| 步骤 | 内容 | 工具/技术 |
|:--:|------|---------|
| 1 | **文档处理**：读取 PDF/Word/Markdown 等文档 | Apache PDFBox、Apache POI |
| 2 | **文本分块**：按长度/句子切分，保证每块能放进模型上下文 | 自定义 Chunk 策略（固定长度/语义分割） |
| 3 | **向量化（Embedding）**：调用 Embedding API 将文本转为向量 | OpenAI Embedding / 通义千问 Embedding API |
| 4 | **向量存储**：存储向量并建立索引 | FAISS / Milvus / pgvector |
| 5 | **检索 + 生成**：用户提问 → 向量检索 → 拼接 Prompt → 调模型生成 | Prompt Template + LLM API |

### RAG 完整链路

```
用户提问 → Embedding 向量化 → 向量检索（Top-K）→ 拼接上下文
                                                    ↓
                                              组装 Prompt
                                                    ↓
                                              调用 LLM 生成
                                                    ↓
                                              返回答案
```

> ✅ **产出**：能根据本地文档回答问题的 RAG 系统（如公司制度问答机器人、产品文档智能助手）。

---

## 阶段三：Function / Tool Calling（2~4 周）

> **目标**：让模型能调用你写的 Java 方法，完成实际业务动作。

| 步骤 | 内容 | 实现方式 |
|:--:|------|---------|
| 1 | **理解 Tool Calling 机制** | 在 Prompt 中定义工具（函数描述）；模型决定调用哪个工具，返回调用信息 |
| 2 | **Java 实现工具方法** | 查天气、查航班、查数据库、发邮件——每个工具封装为独立方法 |
| 3 | **解析模型返回的工具调用请求** | 提取函数名 + 参数 → 用反射或 Map 找到对应方法执行 |
| 4 | **结果回传给模型** | 执行结果返回模型 → 模型综合生成最终回答 |

### Tool Calling 循环

```
用户输入 → LLM 判断需要调用工具 → 返回函数名 + 参数
                                        ↓
                                   Java 执行业务方法
                                        ↓
                                   结果回传 LLM
                                        ↓
                                   LLM 生成最终回答
```

> ✅ **产出**：能自动调用外部工具的 Agent 型应用（如旅行规划助手：查天气+酒店+航班 → 综合方案）。

## 阶段四：工程化与系统整合（持续）

> **目标**：让 AI 服务稳定、可扩展、可上线。

| 维度 | 内容 | 技术手段 |
|------|------|---------|
| **容器化** | Docker 打包 Spring Boot + 向量库 | Dockerfile + Docker Compose |
| **编排与服务发现** | Kubernetes 基础 | Deployment、Service、ConfigMap |
| **性能优化** | 缓存 Embedding 结果、批量请求模型 API、异步处理耗时任务 | Redis 缓存、CompletableFuture、消息队列 |
| **高可用** | 多模型路由（主模型挂了切备用）、限流/熔断/重试 | Sentinel、Resilience4j |
| **接入现有系统** | 把 AI 问答嵌入 OA、CRM、客服系统 | REST API / SDK 封装 |

> ✅ **产出**：可在生产环境运行的 AI 微服务。
