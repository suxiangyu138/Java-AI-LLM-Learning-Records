# Java 后端开发常用技术栈

## 概述

Java 后端开发核心技术围绕 **基础 + 框架 + 中间件 + 工程化** 四层展开。Spring 生态是核心骨架，数据库和中间件是关键支撑，工程化和监控保障系统稳定运行。

## 一、基础核心技术

### 1.1 Java 基础

| 维度 | 内容 |
|------|------|
| **核心内容** | Java SE：面向对象、集合、泛型、异常、多线程、IO/NIO、反射、注解；JDK 新特性：Stream 流、Lambda 表达式、Optional 类 |
| **应用场景** | 所有 Java 后端开发的基础，决定代码编写规范和效率 |
| **核心价值** | 构建稳定、高效的 Java 程序底层逻辑 |

### 1.2 数据库

| 数据库 | 类型 | 核心内容 | 应用场景 | 核心价值 |
|--------|:---:|---------|---------|---------|
| **MySQL / Oracle** | 关系型 | SQL（DQL/DML/DDL）、索引、事务（ACID）、存储过程、分库分表、读写分离 | 存储结构化业务数据（用户/订单/商品） | 保证数据一致性和可靠性 |
| **Redis** | 内存 KV | String/Hash/List/Set/ZSet、分布式锁、限流、排行榜、缓存 | 高性能缓存、实时计数 | 弥补关系型数据库性能短板 |
| **MongoDB** | 文档型 | BSON 文档模型、聚合管道 | 非结构化数据（日志/用户画像） | 灵活的数据模型 |

## 二、框架类技术

### 2.1 Spring 生态

| 框架 | 核心内容 | 应用场景 |
|------|---------|---------|
| **Spring Framework** | IoC（依赖注入）、AOP（面向切面）、事务管理、资源管理 | 所有 Spring 体系应用的基础，解耦代码 |
| **Spring Boot** | 自动配置、Starter、内嵌服务器、Actuator 监控 | 快速搭建单体应用或微服务基础服务 |
| **Spring Cloud** | Nacos/Eureka（注册发现）、OpenFeign（远程调用）、Gateway（网关）、Nacos Config（配置中心）、Sentinel/Resilience4j（熔断限流） | 构建分布式微服务架构，解决服务治理 |
| **Spring Security** | 认证（登录）+ 授权（权限控制），支持 JWT/OAuth2 | 安全框架 |
| **Spring Data** | 统一各类数据源访问（JPA/Redis/MongoDB） | 简化数据层代码 |

### 2.2 持久层框架

| 框架 | 核心内容 | 适用场景 |
|------|---------|---------|
| **MyBatis / MyBatis-Plus** | SQL 与 Java 解耦、动态 SQL、结果映射、通用 CRUD（MP） | 复杂 SQL 场景，简化单表 CRUD |
| **JPA / Hibernate** | ORM 映射、自动生成 SQL、面向对象操作数据库 | 快速开发，简单业务场景 |

### 2.3 其他常用工具

| 工具 | 用途 |
|------|------|
| **Lombok** | 简化实体类代码（自动生成 get/set/toString） |
| **Hutool** | Java 工具类库（字符串/日期/加密等常用功能） |
| **Druid** | 数据库连接池，提供监控、防 SQL 注入功能 |

## 三、中间件技术

### 3.1 消息队列

| 维度 | 说明 |
|------|------|
| **核心内容** | 异步通信、消息持久化、消息重试、死信队列 |
| **应用场景** | 系统解耦（订单→通知库存）、削峰填谷（秒杀）、日志采集 |
| **核心价值** | 提升系统吞吐量，降低模块耦合 |
| **主流选择** | RabbitMQ（可靠性高）/ Kafka（高吞吐）/ RocketMQ（事务消息） |

### 3.2 分布式中间件

| 技术 | 功能 | 典型方案 |
|------|------|---------|
| **分布式锁** | 解决多服务并发操作数据 | Redis（SET NX + Redisson）/ ZooKeeper |
| **分布式事务** | 保证分布式系统数据一致性 | Seata（AT/TCC/SAGA） |
| **注册中心** | 管理微服务地址，服务发现 | Nacos / Eureka |
| **配置中心** | 统一管理多环境配置 | Nacos Config / Apollo |

### 3.3 搜索引擎

| 维度 | 说明 |
|------|------|
| **核心内容** | 全文检索、分词、聚合分析、高亮显示 |
| **应用场景** | 商品搜索、日志检索、站内搜索 |
| **核心价值** | 替代数据库模糊查询，大幅提升检索效率 |
| **主流工具** | Elasticsearch（倒排索引 + Query DSL） |

## 四、工程化与运维

| 领域 | 技术 | 核心内容 | 应用场景 |
|------|------|---------|---------|
| **构建工具** | Maven / Gradle | 依赖管理、项目构建、打包发布、多环境配置 | 统一构建规范 |
| **版本控制** | Git | 分支管理（master/develop/feature）、提交、合并、冲突解决 | 团队协作，代码追溯 |
| **容器化** | Docker + K8s | Docker 打包镜像保证环境一致性；K8s 自动部署、扩缩容、故障恢复 | 简化部署，云原生架构 |
| **监控日志** | ELK / Prometheus + Grafana | ELK（收集/存储/分析日志）；Prometheus+Grafana（监控 CPU/内存/QPS 指标） | 排查线上问题，监控运行状态 |

## 五、性能优化

| 优化层面 | 核心内容 | 解决的问题 |
|---------|---------|-----------|
| **JVM 调优** | GC 回收机制、内存模型、参数配置（堆内存/回收器） | 内存溢出、GC 频繁、应用卡顿 |
| **数据库优化** | 索引优化、慢 SQL 优化、分库分表、读写分离 | 数据库查询效率低 |
| **接口优化** | 缓存（Redis）、异步处理、批量操作、熔断限流 | 接口响应慢、高并发不稳定 |

## 六、设计模式与编程思想

| 领域 | 核心内容 | 应用场景 |
|------|---------|---------|
| **设计模式** | 单例、工厂、代理、观察者、策略等 | 解决特定业务场景的代码设计问题，提升可维护性 |
| **面向接口编程** | 定义接口规范，实现类灵活替换 | 微服务开发、框架扩展 |
| **微服务设计思想** | 服务拆分、高内聚低耦合、服务容错、数据一致性 | 分布式系统设计 |

## 七、技术栈掌握优先级

| 优先级 | 技术 | 理由 |
|:---:|------|------|
| 🔴 第一优先 | Java SE + Spring Boot + MySQL + Redis + MyBatis + Git + Maven | 面试必问、工作必用、决定能否胜任日常开发 |
| 🟡 第二优先 | Spring Cloud + RabbitMQ/Kafka + Docker + Linux + Nginx | 提升架构能力，中高级必备 |
| ⚪ 第三优先 | K8s + ELK + Prometheus + 性能调优 + 设计模式 | 高级工程师与架构师方向 |
