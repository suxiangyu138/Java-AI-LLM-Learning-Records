# IntelliJ IDEA 新建项目技术栈全面解析

## 概述

本文对 IntelliJ IDEA 新建项目界面中的可选技术栈按分类进行系统剖析，覆盖 **编程语言、Java 生态框架、其他语言/框架、前端/全栈** 四大类别，每项技术涵盖定位、适用场景、核心特点、底层原理与选型建议，帮助开发者精准选型。

## 一、编程语言类

### 1.1 JVM 语言对比

| 维度 | Java | Kotlin | Groovy | Scala |
|------|------|--------|--------|-------|
| **发布年份** | 1995 | 2011 | 2003 | 2004 |
| **类型系统** | 强类型 | 强类型+空安全 | 动态+静态混合 | 强类型+类型推断 |
| **代码量** | 多 | 比 Java 少 30%~50% | 少 | 最少（表达力最强） |
| **学习曲线** | 中等 | 中等 | 低 | 陡峭 |
| **编译产物** | JVM 字节码 | JVM 字节码 | JVM 字节码 | JVM 字节码 |
| **生态完善度** | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐ |

### 1.2 各语言详解

#### Java

| 维度 | 说明 |
|------|------|
| **定位** | 企业级后端开发基石，基于 JVM 跨平台运行 |
| **核心适用场景** | 后端服务、微服务（Spring Cloud）、大数据（Hadoop/Flink）、Android 原生、中间件开发 |
| **核心优势** | 生态极完善（Spring 全家桶/MyBatis）、语法严谨（编译期发现错误）、跨平台、社区庞大、GC 自动内存管理 |
| **核心劣势** | 语法繁琐、启动慢、内存占用高 |
| **最新版本** | 稳定版 Java 21，LTS 版 Java 17 |
| **底层原理** | javac 编译 → .class 字节码 → JVM 解释/JIT 编译执行 |
| **实操要点** | 优先选 LTS 版本；合理配置 JVM 参数（堆内存/GC 器）；注意多线程安全 |

#### Kotlin

| 维度 | 说明 |
|------|------|
| **定位** | JetBrains 推出的现代 JVM 语言，100% 兼容 Java |
| **核心适用场景** | Android 开发（官方首选）、Spring Boot 后端、KMM 跨平台、Compose Multiplatform |
| **核心优势** | 语法简洁（代码量减 30%~50%）、空安全（编译期避免 NPE）、协程（简化异步）、扩展函数 |
| **核心劣势** | 学习曲线略高于 Java（函数式特性需适应）、部分场景性能略低 |
| **底层原理** | 编译为 JVM 字节码，与 Java 共同运行；KMM 场景编译为对应平台机器码 |
| **实操要点** | 注意空安全兼容（Java 的 null → Kotlin 用 `?.` 或 `!!`）；合理管理协程生命周期；版本与 Spring Boot 适配 |

#### Groovy

| 维度 | 说明 |
|------|------|
| **定位** | JVM 动态脚本语言，简化 Java 开发 |
| **核心适用场景** | Gradle 构建脚本、自动化测试/运维脚本、Jenkins Pipeline、快速原型 |
| **核心优势** | 语法灵活（动态类型/闭包/DSL）、与 Java 无缝集成、支持脚本化运行 |
| **核心劣势** | 运行时类型风险、性能低、不适合大型项目 |
| **底层原理** | 编译为 JVM 字节码，动态特性通过反射实现 |
| **实操要点** | 注意类型校验避免运行时异常；Gradle 版本与 Groovy 版本适配；避免过度元编程 |

#### Scala

| 维度 | 说明 |
|------|------|
| **定位** | 融合 OOP + FP 的多范式 JVM 语言，大数据核心语言 |
| **核心适用场景** | 大数据（Apache Spark/Flink）、高并发系统、函数式编程实践 |
| **核心优势** | 表达力极强（一行顶 Java 多行）、并发处理优秀（Actor 模型）、类型系统严谨 |
| **核心劣势** | 学习曲线陡峭、编译慢、生态小众（仅大数据领域主流） |
| **底层原理** | 编译为 JVM 字节码；Actor 模型基于消息传递，避免共享状态并发问题 |
| **实操要点** | 避免过度隐式转换；适配 Spark/Flink 版本；符合尾递归规范以利用自动优化 |

## 二、Java 生态框架

### 2.1 框架全景对比

| 维度 | Spring Boot | Quarkus | Micronaut | Jakarta EE |
|------|:---:|:---:|:---:|:---:|
| **发布年份** | 2014 | 2019 | 2018 | 2017（改名） |
| **启动速度** | 中等 | 快（Spring Boot 的 50%+） | 极快（毫秒级） | 慢 |
| **内存占用** | 中高 | 低 | 极低 | 高 |
| **原生编译** | 支持（GraalVM） | 原生支持 | 原生支持 | 不支持 |
| **生态完善度** | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐ | ⭐⭐⭐⭐ |
| **学习曲线** | 低 | 中 | 中高 | 高 |
| **最佳场景** | 通用后端/微服务 | Serverless/云原生 | 资源受限/CLI | 传统企业级 |

### 2.2 各框架详解

#### Spring Boot

| 维度 | 说明 |
|------|------|
| **核心机制** | 自动配置（`@EnableAutoConfiguration`）+ 内嵌容器 + Starter 生态 |
| **核心优势** | 开发效率极高（约定大于配置）、生态最完善、生产级特性完备、社区最活跃 |
| **核心劣势** | 启动速度相对较慢、内存占用较高 |
| **底层原理** | 扫描 classpath 下的自动配置导入文件 → 条件注解判断 → 动态创建 Bean → 完成配置 |
| **实操要点** | 优先选 LTS 版（3.1.x）；按需引入 Starter 避免冗余；配置文件优先级：命令行 > 环境变量 > yml > properties |

#### Quarkus

| 维度 | 说明 |
|------|------|
| **核心机制** | 编译时依赖注入（CDI）+ GraalVM 原生编译 + 分层构建优化镜像 |
| **核心优势** | 启动极快（毫秒级）、内存极低、云原生优化、兼容 Spring 注解 |
| **核心劣势** | 生态不及 Spring Boot、原生编译配置复杂、部分 Spring 特性不支持 |
| **实操要点** | 与 GraalVM 版本适配；原生编译避免反射/动态代理；迁移时参考官方文档调整注解 |

#### Micronaut

| 维度 | 说明 |
|------|------|
| **核心机制** | 编译时依赖注入（注解处理器）+ Netty 异步通信 + AOT 编译 |
| **核心优势** | 极轻量（核心包极小）、启动毫秒级、无反射开销、支持多 JVM 语言 |
| **核心劣势** | 生态最小、社区活跃度一般、学习资料较少 |

#### Jakarta EE

| 维度 | 说明 |
|------|------|
| **核心机制** | 标准化规范集（Servlet/JPA/CDI/EJB/JMS）→ 应用服务器实现（TomEE/WildFly） |
| **核心优势** | 标准化、企业级特性完善、稳定性极高（向后兼容）、兼容 Spring 生态 |
| **核心劣势** | 配置复杂、启动慢、不适合微服务和云原生 |
| **实操要点** | 区分 javax.* → jakarta.* 包名迁移；避免过度使用 EJB（用 Spring Bean 替代）；应用服务器版本适配 |

### 2.3 其他工具与框架

#### Maven Archetype

| 维度 | 说明 |
|------|------|
| **定位** | Maven 项目模板生成工具，快速创建标准化项目骨架 |
| **核心价值** | 统一团队项目结构、支持自定义模板（含依赖/配置/基础代码）、参数化配置 |
| **常用模板** | `maven-archetype-quickstart`（简单 Java 项目）、`maven-archetype-webapp`（Web 项目） |

#### JavaFX

| 维度 | 说明 |
|------|------|
| **定位** | Java 官方桌面 GUI 框架，替代 Swing/AWT |
| **核心特性** | FXML 布局分离、CSS 美化、跨平台、支持 GraalVM 原生打包 |
| **当前状态** | Oracle 停止官方维护，由 OpenJFX 社区维护——社区活跃度下降 |

## 三、其他语言/框架

### 3.1 Ktor

| 维度 | 说明 |
|------|------|
| **定位** | JetBrains 推出的 Kotlin 异步 Web 框架，基于协程 |
| **核心适用场景** | Kotlin 后端 API、微服务、WebSocket 实时通信 |
| **核心优势** | Kotlin 原生协程支持、轻量模块化、DSL 路由定义灵活 |
| **核心劣势** | 生态不如 Spring Boot、企业级特性需手动集成 |

### 3.2 Compose Multiplatform

| 维度 | 说明 |
|------|------|
| **定位** | JetBrains 推出的跨平台声明式 UI 框架 |
| **支持平台** | Android / Desktop / Web（JS） / iOS |
| **核心优势** | 一套代码多端运行、声明式 UI（状态驱动）、Kotlin 原生 |
| **核心劣势** | iOS 支持不够成熟、Web 性能略低、生态不如 Flutter |

### 3.3 Play

| 维度 | 说明 |
|------|------|
| **定位** | Lightbend 推出的 Java/Scala 异步 Web 框架 |
| **核心优势** | 基于 Netty 异步非阻塞、支持热重载、无 Servlet 容器依赖 |
| **核心劣势** | 国内社区活跃度低、文档不够完善 |

## 四、前端/全栈类

### 4.1 HTML

| 维度 | 说明 |
|------|------|
| **定位** | Web 页面结构基石，与 CSS/JS 并称前端三大基石 |
| **核心机制** | HTML 标签 → 浏览器解析引擎 → DOM 树 → 浏览器渲染页面 |
| **核心价值** | 简单易学、跨平台（所有浏览器支持）、语义化标签利于 SEO |

### 4.2 React

| 维度 | 说明 |
|------|------|
| **定位** | Meta 推出的声明式 UI 库，SPA（单页应用）开发主流 |
| **核心机制** | 虚拟 DOM + Diffing 算法（只更新差异部分）+ 单向数据流 |
| **核心优势** | 组件化、声明式 UI、生态庞大（Next.js/Redux/React Router） |
| **核心劣势** | 学习曲线略陡（JSX/Hooks/状态管理）、需搭配构建工具 |
| **实操要点** | 合理使用 Hooks（useState/useEffect）；用 React.memo/useMemo 优化渲染；复杂场景搭配 Redux/Zustand |

### 4.3 Express

| 维度 | 说明 |
|------|------|
| **定位** | Node.js 最流行的轻量级 Web 框架，极简灵活 |
| **核心适用场景** | RESTful API、中间件架构、快速原型 |
| **核心优势** | 极简（最小核心）、灵活（无预设约束）、中间件生态丰富 |
| **核心劣势** | 不预设项目结构（大型项目需自行组织）、性能不如 Fastify |

## 五、快速选型指南

### 按项目类型选技术栈

| 项目类型 | 推荐技术栈 |
|---------|-----------|
| 企业级后端服务 | Java + Spring Boot + Maven/Gradle |
| 微服务架构 | Java/Kotlin + Spring Boot + Spring Cloud Alibaba |
| Serverless 函数 | Java + Quarkus / Micronaut（原生编译） |
| Android 开发 | Kotlin + Compose Multiplatform |
| 大数据处理 | Scala/Java + Spark/Flink |
| 跨平台桌面应用 | Kotlin + Compose Multiplatform Desktop |
| 快速原型/脚本 | Groovy（Gradle 脚本）/ Python |
| SPA 前端 | React + TypeScript |
| 轻量级 API 服务 | Ktor / Express |

### 按开发者经验选语言

| 经验水平 | 推荐语言 | 原因 |
|:---:|------|------|
| 新手 | Java | 语法严谨、生态完善、资料最多 |
| 有基础 | Kotlin | 更现代、更简洁，与 Java 互操作 |
| 函数式爱好者 | Scala | 表达力强，大数据场景必备 |
| 脚本/自动化 | Groovy | 灵活快速，Gradle 必备 |
