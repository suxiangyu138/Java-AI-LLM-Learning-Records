# 分布式、高并发、云原生

---

## 一、分布式是什么

### 简单理解

把一个大系统，拆成很多个小系统，跑在多台服务器上，一起对外服务。

### 举个生活例子

- 传统项目：一个饭店，从点菜、做饭、收银、打扫全是一个人干。
- 分布式：点菜员、厨师、收银员、保洁分开干，各自负责一块，效率更高。

### 企业里的真实做法

把系统拆成多个服务：
- 用户服务、订单服务、商品服务、支付服务、库存服务
- 每个服务独立部署、独立运行、独立数据库

### 分布式要解决的问题

- 服务之间怎么调用
- 服务挂了怎么办
- 数据怎么保持一致
- 请求怎么路由
- 高并发下怎么扛住

### 企业级应用场景

电商、外卖、支付、政务系统、直播、金融系统。只要用户量一大，一定用分布式。

### 你未来必会的技术

Spring Cloud、Nacos、OpenFeign、Gateway、Dubbo、分布式锁、分布式事务、分布式缓存

## 二、高并发是什么

### 简单理解

同一时间，有大量用户同时访问系统。

### 比如

秒杀、双十一购物、抢票、热搜爆发、直播间带货

### 高并发要解决的核心问题

- 服务器不崩溃
- 接口响应快
- 数据库不卡死
- 数据不出错

### 企业真实做法

- 加缓存，减少数据库压力
- 异步处理，不阻塞主线程
- 限流，超过一定量直接拒绝
- 熔断，防止一个服务挂掉拖垮全部
- 读写分离，分库分表
- 扩容服务器，加机器

### 高并发真正考验的能力

接口性能优化、数据库优化、缓存设计、消息队列使用、服务扩容与缩容

### 企业级技术

Redis、RabbitMQ、Sentinel、分库分表、索引优化、多级缓存

## 三、云原生是什么

### 简单理解

把程序跑在云上，用云的能力自动扩容、自动恢复、自动部署。

### 传统部署

买服务器 → 装系统 → 装环境 → 上传jar → 手动启动。挂了要人工重启。

### 云原生部署

- 把程序打包成镜像
- 交给平台自动运行
- 挂了自动重启
- 流量大自动加机器
- 流量小自动减机器

### 核心思想

容器化、服务网格、自动扩缩容、声明式部署、不可变基础设施

### 企业真实技术

Docker 容器、K8s 容器编排、Jenkins 自动化部署、云服务器、弹性伸缩

### 云原生的价值

运维成本极低、上线速度极快、稳定性极高、适合大规模分布式系统。现在所有大厂、中厂都在全面云原生化，不会云原生，未来很难进好公司。

---

## 四、三个概念之间的关系

- 高并发是目标：用户多、流量大，必须扛住
- 分布式是架构：把系统拆小，才能扛高并发
- 云原生是落地方式：让分布式系统更容易部署、更稳定、更便宜

### 一句话总结

高并发是需求，分布式是架构，云原生是现代企业的实施标准。
