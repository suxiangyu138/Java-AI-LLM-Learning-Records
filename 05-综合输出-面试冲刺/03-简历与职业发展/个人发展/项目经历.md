## 项目一：餐饮外卖服务平台

### 1.1 项目概述

企业级本地化外卖服务平台，打通 **用户端、餐饮商家端、配送骑手端** 三方业务链路，实现从线上下单到履约配送的全流程闭环。支撑区域化餐饮商家线上化运营，满足规模化、稳定化的外卖服务实战需求。

### 1.2 技术栈

| 层级 | 技术选型 |
|------|---------|
| 后端框架 | Spring Boot + Spring MVC + MyBatis-Plus |
| 数据库 | MySQL + Redis |
| 消息中间件 | RabbitMQ |
| 服务治理 | Spring Cloud Gateway + Nacos（注册中心/配置中心） |
| 容器化 | Docker + Docker Compose |
| 前端 | Vue.js + Element UI（管理后台） |

### 1.3 核心功能模块

| 模块 | 功能描述 |
|------|---------|
| **用户端** | 商品浏览与搜索、购物车、在线下单、订单追踪、评价体系 |
| **商家端** | 菜品管理、订单接单与处理、营业数据统计、营销活动配置 |
| **骑手端** | 订单接单、路径导航、配送状态上报、收入结算 |
| **平台管理后台** | 商家入驻审核、用户管理、订单调度监控、数据大盘、运营配置 |

### 1.4 技术亮点

- **订单调度系统**：基于地理位置与骑手状态，实现订单的智能分配与手动抢单双模式
- **缓存策略**：使用 Redis 缓存热门菜品与商家信息，降低数据库读压力；通过缓存预热 + 过期时间随机化防止缓存雪崩
- **异步处理**：订单状态变更通过 RabbitMQ 异步通知各端，解耦下单与推送，提升接口响应速度
- **幂等设计**：订单支付回调接口使用唯一订单号 + 状态机保证幂等，防止重复扣款

### 1.5 个人职责与产出

- 独立负责用户端核心下单流程的后端开发（商品浏览 → 购物车 → 下单 → 支付回调）
- 设计并实现订单状态机（待支付 → 已支付 → 商家接单 → 配送中 → 已完成/已取消）
- 编写接口文档与单元测试，核心接口覆盖率 > 80%

## 项目二：高可用电商购物平台

### 2.1 项目概述

基于微服务分布式架构打造的企业级电商平台，完成 **用户、商品、订单、支付、物流** 五大核心微服务的设计开发与独立部署。具备服务弹性伸缩、高并发承载、故障隔离降级能力，满足生产环境高可用与易扩展要求。

### 2.2 技术栈

| 层级 | 技术选型 |
|------|---------|
| 后端框架 | Spring Boot + Spring Cloud Alibaba |
| 数据库 | MySQL（主从 + 读写分离）+ Redis Cluster |
| 消息中间件 | RocketMQ |
| 服务治理 | Nacos + Sentinel（限流熔断）+ Seata（分布式事务） |
| 搜索 | Elasticsearch |
| 容器编排 | Kubernetes |
| 监控 | Prometheus + Grafana |

### 2.3 核心功能模块

| 模块 | 功能描述 |
|------|---------|
| **用户服务** | 注册登录（JWT 认证）、用户信息管理、收货地址管理 |
| **商品服务** | 商品发布与管理、SKU 库存管理、分类检索（ES 全文搜索） |
| **订单服务** | 购物车、订单创建、订单状态流转、退款/退货处理 |
| **支付服务** | 对接第三方支付、支付回调处理、对账系统 |
| **物流服务** | 物流信息追踪、快递公司对接、发货/签收状态同步 |

### 2.4 技术亮点

- **分布式事务**：订单创建涉及库存扣减与积分扣减跨服务操作，使用 Seata AT 模式保证数据最终一致性
- **高并发优化**：商品详情页多级缓存（CDN → Nginx 本地缓存 → Redis → 数据库），库存扣减使用 Redis + Lua 脚本保证原子性
- **限流熔断**：基于 Sentinel 对网关层做 QPS 限流，核心服务配置熔断降级策略，兜底返回降级页面
- **读写分离**：MySQL 主从架构，ShardingSphere 实现读写分离路由，读多写少场景性能显著提升
- **秒杀场景**：Redis 预扣库存 + RocketMQ 异步下单 + 定时任务补偿，解决超卖与流量冲击问题

### 2.5 个人职责与产出

- 主导订单服务与支付服务的详细设计与开发
- 实现订单创建链路中的分布式事务方案选型与落地
- 参与秒杀模块的架构设计与 Redis + MQ 方案实现
- 编写核心接口的压力测试脚本（JMeter），QPS 达到目标要求

## 项目三：AI 医疗智能问答平台

### 3.1 项目概述

依托大模型（LLM）+ 专业医疗知识图谱构建的企业级医疗 AI 平台，支持私有化部署与多渠道接入。实现 **症状问诊、用药指导、健康科普、体检报告解读** 等核心服务，满足医疗数据合规、高可用、运维管控等企业级要求。

### 3.2 技术栈

| 层级 | 技术选型 |
|------|---------|
| 后端框架 | Spring Boot + Spring Cloud |
| 大模型接入 | OpenAI API 兼容接口 + 本地部署模型（Qwen / ChatGLM） |
| 知识图谱 | Neo4j + 医疗专业知识库 |
| 向量检索 | Milvus / FAISS + Embedding 模型 |
| 数据库 | MySQL + Redis |
| 消息中间件 | RabbitMQ |
| 前端 | Vue.js + WebSocket（流式对话） |

### 3.3 核心功能模块

| 模块 | 功能描述 |
|------|---------|
| **症状问诊** | 用户描述症状 → RAG 检索医疗知识 → LLM 生成问诊建议（含免责声明） |
| **用药指导** | 药品信息查询、用法用量说明、药物相互作用提醒 |
| **健康科普** | 基于知识图谱的疾病科普、预防建议、健康管理方案生成 |
| **体检报告解读** | OCR 识别报告内容 → LLM 解读指标异常项 → 生成健康建议 |
| **多轮对话管理** | 对话历史管理、上下文窗口控制、意图识别与澄清 |

### 3.4 技术亮点

- **RAG 架构**：用户问题 → Embedding 向量化 → 向量库检索相关知识片段 → 拼接 Prompt → LLM 生成回答，有效缓解大模型幻觉问题
- **知识图谱增强**：医疗专业知识图谱（症状-疾病-药品-科室关系）作为约束层，对 LLM 输出做合规校验与危险内容拦截
- **私有化部署**：支持基于 Qwen / ChatGLM 等开源模型的本地化部署，满足医疗数据不出域的安全合规要求
- **流式对话**：基于 WebSocket + SSE 实现 LLM 回答的流式输出，提升用户体验
- **敏感信息脱敏**：用户输入与病历数据自动识别并脱敏处理（姓名、身份证号、手机号等）

### 3.5 个人职责与产出

- 负责 RAG 检索链路的设计与实现（Embedding 选型对比 + 向量库搭建 + 检索策略优化）
- 实现知识图谱约束层：编写 Cypher 查询语句，对 LLM 输出做规则校验与危险内容拦截
- 参与流式对话接口的开发与调试
- 编写技术方案文档与 API 接口文档
