## 1. 学生简历的黄金结构

学生简历的信息优先级和社招不同。HR在看到"学生"身份时，最关心的是：

1. 你是什么学校的、什么专业的（快速判断学历匹配度）
2. 你有什么实习经历（证明你上过班能干活）
3. 你做了什么项目（没有实习就看项目）
4. 你的技术栈是什么（关键字匹配）

基于这个逻辑，学生简历的推荐结构：

```
1. 个人信息      姓名 | 电话 | 邮箱 | 意向岗位 | 到岗时间
2. 教育背景      学校 · 专业 · 学历 · 毕业时间 · GPA(如果高) · 相关课程
3. 实习经历      公司 · 岗位 · 时间 · 工作内容（STAR法则）
4. 项目经验      项目名 · 技术栈 · 你的角色 · 项目描述（STAR法则）
5. 专业技能      按掌握程度分层：精通/熟练/了解
6. 竞赛/开源/其他  有就写，没有不写，别编
```

> ⚠️ 教育背景放在前面！社招把工作经历放前面，校招把教育背景放前面。HR要快速知道你是什么学校的。

## 2. 每一部分怎么写

### 个人信息

```text
✅ 好例子：
张三 | 138xxxx1234 | zhangsan@email.com | Java后端开发工程师 | 可实习3个月/可尽快到岗

❌ 坏例子：
- 写性别、年龄、民族、籍贯、身高体重（不相关，占空间）
- 放自拍/生活照（除了部分国企要求，互联网公司不需要）
- 写"求职意向：Java/前端/测试/产品"（方向太多=你不确定要做什么）
```

### 教育背景

```text
✅ 好例子：
北京大学 | 计算机科学与技术 | 本科 | 2026年6月毕业
GPA: 3.6/4.0（专业前20%）  |  主修课程：数据结构、操作系统、计算机网络、数据库原理

❌ 坏例子：
- GPA低于3.0还非要写上去
- 列十几门课程（HR不关心你上过什么课）
- 学校一般但排版得很小想藏起来（藏不住的，不如坦诚）
```

> 💡 **GPA写在什么情况下写：** 3.5以上必写，3.0-3.5可写，低于3.0不写。如果你的专业排名比GPA好看（比如3.2但排名前15%），写排名。

### 实习经历

如果有实习经历，这是简历最大的加分项。写法在后面STAR法则详细讲。这里强调一个点：

> ⚠️ **实习生最大的简历错误：** 只写"做了什么"，不写"取得了什么效果"。HR想看的是你做的事情的影响，而不只是任务的罗列。

### 竞赛/开源/其他

加分但不是必选项。写的时候注意：

| 值得写的 | 不值得写的 |
|---------|-----------|
| ACM/蓝桥杯省奖以上 | "蓝桥杯省三"（除非其他完全没有） |
| GitHub >100 star的项目 | "熟练使用Git" |
| 技术博客持续更新 | "热爱编程，喜欢钻研"（空洞） |
| 数学建模国奖 | 普通校园活动 |
| 开源贡献（PR被merge） | "自学过Python" |

## 3. STAR法则写项目

### STAR是什么

| 字母 | 含义 | 你要回答的问题 |
|:---:|------|---------------|
| **S**ituation | 背景/情境 | 这个项目在什么背景下产生的？解决什么问题？ |
| **T**ask | 任务 | 你在这个项目中的具体任务和角色是什么？ |
| **A**ction | 行动 | 你具体做了什么？用了什么技术？怎么做决策的？ |
| **R**esult | 结果 | 你的行动带来了什么可量化的成果？ |

### 对比：不用STAR vs 用STAR

```text
❌ 不用STAR：
「电商后台管理系统」
负责开发商品管理模块，使用Spring Boot + MyBatis，实现了商品增删改查。

✅ 用STAR：
「电商后台管理系统」Java · Spring Boot · MySQL · Redis · RocketMQ
背景：为某电商平台搭建商家后台管理系统，日均处理订单量约5000单。
任务：独立负责商品管理模块的设计与开发，包括商品创建、上下架、库存同步。
行动：
  - 设计了商品SPU/SKU两级数据模型，支持多规格商品灵活配置
  - 使用Redis缓存热点商品信息，将查询响应时间从200ms降至30ms
  - 通过RocketMQ异步更新搜索索引，解耦商品变更与搜索服务
结果：模块上线后支撑日均5000+商品操作，缓存命中率95%+，上线至今无P0故障
```

看出区别了吗？

| 维度 | 不用STAR | 用STAR |
|------|---------|--------|
| 技术细节 | 模糊（"用了Spring Boot"） | 具体（"SPU/SKU数据模型、Redis缓存、RocketMQ异步"） |
| 个人角色 | 不清楚 | 明确（"独立负责"） |
| 量化结果 | 没有 | 有（"200ms降到30ms""命中率95%"） |
| 思考深度 | 看不出 | 能看出（为什么用Redis、为什么用MQ） |

### STAR法则的实战技巧

**S（背景）怎么写：**
- 一句话说清项目是干什么的、给谁用的
- 给出一个能体现规模的数据（用户量、QPS、数据量级）

**T（任务）怎么写：**
- 明确你在团队中的角色：独立负责 / 核心开发 / 参与
- 如果是一个大项目，说明你负责的那部分

**A（行动）怎么写：** 这是最核心的部分——
- 写技术决策和原因（"因为...所以选择了..."）
- 写技术细节（用了什么设计模式、什么数据结构）
- 写遇到的难点和解决方案

**R（结果）怎么写：**
- **必须有数字！** 没有数字的结果不是结果
- 性能提升：从X ms降到Y ms、QPS提升了Z%
- 业务指标：日活、订单量、用户增长
- 质量指标：故障率、bug数、测试覆盖率
- 如果没有精确数字，用保守估计+~号

## 4. 没有实习/项目怎么办

大三没有实习经历是正常的。你需要用其他东西来证明你的技术能力。

### 优先级排序

```
有实习 > 有比赛获奖项目 > 有自己做的完整项目 > 有课程设计改进版 > 有DEMO
```

### 方案一：把课程设计升级为项目

大部分CS学生的课设是"学生管理系统""图书管理系统"。HR看了没有1000份也有500份。你需要做的是给它加点"工业感"：

| 普通课设 | 升级后的项目表述 |
|---------|----------------|
| SpringBoot + MySQL CRUD | 加上Redis缓存、MQ异步处理 |
| 单机部署 | 加上Docker部署 |
| 没有测试 | 加上单元测试和接口文档(Swagger) |
| 没有并发 | 用JMeter压测，分析瓶颈 |
| 功能堆砌 | 聚焦1-2个难点深入（比如权限设计、秒杀） |

> 💡 **一个可行的操作：** 找一个开源的商城/博客/论坛项目，从头到尾理解它的设计，然后加一个你自己的改进（比如加一个推荐系统、加一个实时通知）。在简历上写"基于XX开源项目的二次开发，新增了XX功能，解决了XX问题"——这比纯课设好得多。

### 方案二：参与开源项目

| 方式 | 难度 | 价值 |
|------|:--:|:--:|
| 给知名项目修Bug/改进文档 | 中 | 高（证明你能读源码） |
| 翻译技术文档 | 低 | 中（至少证明英语+积极性） |
| 提Issue帮助项目改进 | 低 | 低（但有总比没有好） |
| 自己写工具库 | 中高 | 高（如果有用户那就更好了） |

### 方案三：做一个"面试导向"的项目

所谓"面试导向"，就是做这个项目的目的就是为了面试有东西讲。推荐方向：

| 项目方向 | 能体现的能力 | 推荐指数 |
|---------|------------|:------:|
| 秒杀系统 | 高并发、缓存、消息队列、分布式锁 | ⭐⭐⭐⭐⭐ |
| RAG知识库/智能客服 | AI集成、向量检索、Prompt工程 | ⭐⭐⭐⭐⭐ |
| 短链系统 | 系统设计、哈希算法、高可用 | ⭐⭐⭐⭐ |
| 即时通讯(IM) | WebSocket、消息可靠性、在线状态 | ⭐⭐⭐⭐ |
| 博客/论坛 | 基础扎实度、权限设计、数据库设计 | ⭐⭐⭐ |

## 5. 技术栈怎么写才不会给自己挖坑

### 大忌：堆砌关键词

```text
❌ 坏例子：
熟悉Java, Python, C++, Go, JavaScript, TypeScript, Kotlin, Scala
熟悉Spring, SpringMVC, MyBatis, Hibernate, Struts2, SpringCloud, Dubbo
熟悉MySQL, Oracle, PostgreSQL, MongoDB, Redis, Elasticsearch, Neo4j
...（以下省略20行）

——面试官一看：这个学生要么在吹牛，要么每样都只会Hello World
```

### 正确写法：分层级 + 突出核心

```text
✅ 好例子：
专业技能
  - 精通：Java（熟悉JUC并发编程、JVM调优基础）、Spring Boot、MySQL
  - 熟练：Redis（缓存策略、分布式锁）、RabbitMQ、MyBatis-Plus、Linux基础
  - 了解：Docker、Spring Cloud、LangChain4j、Prompt Engineering
```

> 🎯 **原则：** 只写你经得起面试官追问的技术。写在"精通"里的，要做好被问到源码级问题的准备。写在"了解"里的，至少要能说出是什么、用来解决什么问题。

### 怎样算"精通"、"熟练"、"了解"

| 级别 | 标准 | 面试官会问什么 |
|------|------|-------------|
| 精通 | 读过核心源码，理解设计思想，能独立解决复杂问题 | 源码级别的实现细节、设计模式、为什么这样设计 |
| 熟练 | 有项目实战经验，能独立使用，了解常用配置和优化 | 常见使用场景、核心概念、遇到过什么坑 |
| 了解 | 知道是什么、用来做什么、在哪学过/用过 | 基本概念、和同类技术的对比 |

> ⚠️ **如果你无法回答"你是怎么学的""你在哪用过"，就不要写。** 面试官最喜欢做的一件事就是：看到你简历上写了某个技术，然后深挖到你回答不上来为止。

## 6. 简历格式与排版规范

### 硬性要求

| 项目 | 要求 |
|------|------|
| 页数 | **一页！** 学生简历绝对不要超过一页 |
| 格式 | PDF ！不要发 Word |
| 文件命名 | `姓名-学校-岗位-简历.pdf`，不要叫`简历最终版3.pdf` |
| 字体 | 中文用微软雅黑/宋体，英文用Consolas/等宽字体 |
| 字号 | 正文10-11pt，标题12-14pt |
| 照片 | 不放（除非特别说明需要） |

### 排版原则

- **倒叙时间：** 经历和项目都从最近的开始写
- **一列布局：** 不要双栏，HR是快速扫描的
- **留白充足：** 不要密密麻麻，HR看花了直接跳过
- **重点加粗：** 关键技术名词、数字结果可以加粗，但别超过5处
- **颜色克制：** 黑色为主，最多一种强调色

## 7. 投递渠道与时间节奏

### 投递渠道对比

| 渠道 | 效率 | 说明 |
|------|:--:|------|
| **内推** | ⭐⭐⭐⭐⭐ | 最好的渠道，简历直达HR/面试官，有些公司内推免笔试 |
| 官网投递 | ⭐⭐⭐⭐ | 正式渠道，流程正规，最稳妥 |
| 牛客网 | ⭐⭐⭐⭐ | 大量的校招信息、内推码、面经 |
| Boss直聘 | ⭐⭐⭐ | 中小厂效果好，大厂一般走官网 |
| 校园招聘会 | ⭐⭐⭐ | 现场投递+沟通，但公司质量参差不齐 |
| 拉勾/猎聘 | ⭐⭐ | 偏社招，对校招帮助有限 |
| 脉脉 | ⭐ | 主要用来找内推人，直接在上面投效果差 |

### 找内推的正确姿势

```text
❌ 错误姿势：
"学长您好，能帮我内推吗？"然后甩一份简历过去

✅ 正确姿势：
"学长您好，我是XX大学XX专业大三的XXX。看到您在XX公司做后端开发，
我目前也在准备Java后端的校招，想投贵公司的暑期实习。这是我的简历，
如果您方便的话可以帮忙内推吗？不方便也没关系，谢谢学长！"
```

> 💡 **找内推的渠道：** 牛客网内推板块 > 脉脉搜公司名 > 学校校友群 > GitHub上搜`公司名+内推`

### 大三学生投递时间线

```
3月-4月（大三下学期）
└── 暑期实习集中投递期
    ├── 提前批：2月底-3月初（大厂，免笔试）
    ├── 正式批：3月中-4月（所有公司）
    └── 补录：5月（少部分岗位）

9月-10月（大四上学期）
└── 秋招集中投递期
    ├── 提前批：7月底-8月初
    ├── 正式批：8月中-10月
    └── 补录：11月-12月

随时
└── 日常实习：全年都有，时间灵活
```

> ⚠️ **关键提醒：** 不要等到简历"完美"了再投！早投的人面试机会多，越到后面HC越少。你的简历可以持续迭代到v2、v3，但第一版一定要在投递窗口打开的第一周就投出去。

## 8. 投递管理系统

投了十几家公司之后你会搞不清谁是谁。从第一份投递开始就建一个表格：

| 公司 | 岗位 | 投递日期 | 进度 | 笔记 |
|------|------|---------|------|------|
| 字节 | 后端实习 | 3.5 | 笔试已过→一面3.12 | 内推，问了很多Redis |
| 美团 | 后端实习 | 3.5 | 待笔试 | 官网投递 |
| XX科技 | Java开发 | 3.6 | 简历已读/无回复 | Boss直聘，可能凉了 |
| ... | ... | ... | ... | ... |

> 💡 这样做的三个好处：①不会搞混公司和进度 ②事后可以分析自己的通过率 ③知道哪些公司效率高/低

## 9. 常见简历问题和修改对照

| 常见问题 | 为什么是问题 | 怎么改 |
|---------|------------|--------|
| "熟练使用Java" | 信息量为零，什么都不会写才写这个 | 具体写：集合源码、JUC、JVM调优 |
| "熟悉Linux常用命令" | 太基础，占空间 | 不写，除非你有Linux运维/调优经验 |
| 项目只写了功能描述 | 看不出技术深度 | STAR法则重写，强调技术决策和量化结果 |
| 技术栈列了15+项 | 一看就是堆砌 | 精简到8-10项核心的，分层次 |
| 用"参与""协助"开头 | 显得你只是打杂的 | 写你具体做了什么，"独立负责XX模块" |
| 没有数字 | 没有说服力 | 每个项目至少1-2个量化的结果 |
| 超过一页 | 学生简历不需要 | 删掉不重要的内容 |
| 花里胡哨的模板 | 干扰阅读 | 用简洁模板 |
| GitHub链接放上去没有内容 | 面试官看了更减分 | 要么把GitHub内容充实了，要么不放 |

> 🎯 **检验标准：** 把你的简历给一个不懂技术的朋友看30秒，然后问他记住了什么。如果他记住了你的学校和项目，说明简历结构是对的。如果他什么都记不住——回去重写。

---

> 🎯 **最后的话：** 简历不是你的自传，是你的广告。广告的目的不是让你看起来很厉害，而是让HR想约你面试。所以检查每一行——如果去掉它，HR仍然会约你面试，那就去掉。简历上的每个字都应该为你争取面试机会服务。
