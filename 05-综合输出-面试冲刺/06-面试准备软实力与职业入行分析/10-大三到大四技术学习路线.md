## 1. 关键时间线全景

### 阶段一：大三上学期（9月-1月）— 打基础 + 做项目

| 时间 | 学习内容 | 具体动作 |
|------|---------|---------|
| 9月-10月 | **Java基础强化** | 集合源码、多线程(JUC)、JVM内存与GC、IO/NIO |
| 10月-11月 | **Web框架** | Spring Boot、MyBatis、Spring MVC、RESTful API设计 |
| 11月-12月 | **中间件入门** | MySQL进阶（索引+事务+锁）、Redis（数据结构+缓存策略）、消息队列基础 |
| 12月-1月 | **项目实战** | 完成第一个完整后端项目，至少涉及MySQL+Redis |

> 🏁 **阶段里程碑：** 一个能跑的后端项目（代码量2000+行）+ 基础体系建立

---

### 阶段二：大三寒假（1月-2月）— 算法 + 简历

| 时间 | 学习内容 | 具体动作 |
|------|---------|---------|
| 1月 | **算法刷题启动** | 每天2-3题，按类型刷：数组→链表→树→DP。目标50题+ |
| 2月 | **简历+继续刷题** | 写出简历v1.0，用STAR法则包装项目。算法补弱项模块 |

> 🏁 **阶段里程碑：** 算法50题+ + 简历v1.0可投递 + 明确目标公司和方向

---

### 阶段三：大三下学期（3月-6月）— 面试 + 实习

| 时间 | 学习内容 | 具体动作 |
|------|---------|---------|
| 3月-4月 | **暑期实习投递+面试** | 大量投递、面试、复盘迭代。每天保持2题保持手感 |
| 5月-6月 | **两条路径** | ✅ 有Offer → 预习公司技术栈，准备入职<br>❌ 没Offer → 转投日常实习，加大面试量，重点补面试中暴露的短板 |

> 🏁 **阶段里程碑：** 至少一个实习Offer，或者面试能力稳定在能过二面的水平

---

### 阶段四：大三暑假（7月-8月）— 实习实战

| 时间 | 学习内容 | 具体动作 |
|------|---------|---------|
| 7月-8月 | **全力实习** | 快速上手、积累项目经验、争取转正。关注秋招提前批（7月底开始） |
| 备选路线 | **如果没有实习** | 暑假是补项目+刷题的最后完整时间窗口，同时准备秋招简历 |

> 🏁 **阶段里程碑：** 实习转正意向明确 / 或秋招简历v2.0用项目经验更新完成

---

### 阶段五：大四上学期（9月-11月）— 秋招冲刺

| 时间 | 学习内容 | 具体动作 |
|------|---------|---------|
| 9月-10月 | **秋招主战场** | 大量投递（梯度布局）+ 面试 + 复盘。延续刷题保持手感 |
| 11月-12月 | **收割与备选** | 收割Offer、比较选择。没满意的则准备补录和春招 |

> 🏁 **阶段里程碑：** 至少一个满意的校招Offer

## 2. Java后端学习路线详解

### 阶段一：Java基础（3-4周）

| 模块 | 必须掌握 | 面试重点 | 学习资源 |
|------|---------|---------|---------|
| **Java语法** | 面向对象、接口抽象类、异常、泛型、注解、反射 | 多态的实现、泛型擦除、动态代理 | 《Java核心技术》卷Ⅰ |
| **集合框架** | ArrayList/LinkedList、HashMap/ConcurrentHashMap、TreeMap | HashMap扩容、ConcurrentHashMap的segment/lock | 看源码 |
| **多线程** | 线程创建、synchronized、volatile、线程池、ThreadLocal | 锁升级过程、AQS原理、线程池参数 | 《Java并发编程的艺术》 |
| **JVM** | 内存模型、类加载、垃圾回收、常见JVM参数 | GC算法对比、类加载的双亲委派、OOM排查 | 《深入理解Java虚拟机》 |
| **Java 8+** | Lambda、Stream、Optional、新日期API | Stream的惰性求值 | 官方教程 |

> 💡 **判断标准：** 能自己手写一个线程安全的LRU缓存 + 能说清楚HashMap的put过程——Java基础过关。

### 阶段二：Web框架（3-4周）

| 模块 | 必须掌握 | 深入方向 |
|------|---------|---------|
| **Spring** | IoC/DI、AOP、Bean生命周期、事务管理 | 循环依赖解决、三级缓存、事务传播机制 |
| **Spring Boot** | 自动配置、起步依赖、配置管理、Actuator | 自动配置原理、@Conditional机制 |
| **Spring MVC** | DispatcherServlet、拦截器、统一异常处理 | 请求处理流程 |
| **MyBatis/MyBatis-Plus** | XML映射、动态SQL、分页、关联查询 | MyBatis缓存机制、插件机制 |

### 阶段三：中间件（4-6周）

| 中间件 | 必须掌握 | 面试深度 |
|--------|---------|---------|
| **MySQL** | SQL编写、索引优化、事务、锁机制、MVCC | Explain分析、慢查询优化、分库分表思路 |
| **Redis** | 5种数据结构、缓存策略、持久化(RDB/AOF)、分布式锁 | 缓存穿透/击穿/雪崩、RedLock、集群模式 |
| **消息队列** | RabbitMQ或RocketMQ基础：生产者/消费者、消息可靠性 | 消息重复消费、顺序消息、事务消息 |
| **Linux** | 常用命令、文件操作、查看日志、权限管理 | top/ps/netstat/tcpdump等排错命令 |

### 阶段四：面试备战（持续进行）

```
刷题：LeetCode 150-200题（中等为主）
八股：系统整理Java+框架+中间件+计算机基础的问答
项目：准备好2-3个能深入讲的项目
面经：看目标公司最近的面经，了解出题风格
```

## 3. AI/LLM方向叠加学习路线

如果你在Java后端的基础上想做AI应用层，这是一个**叠加**的学习路径（不是替代）：

### AI叠加学习路线（总计额外6-8周）

```text
第1-2周：LLM基础认知
  - 了解GPT/Claude等主流模型的能力和局限
  - 理解Token、Context Window、Temperature等核心概念
  - 掌握Prompt Engineering基础（Few-shot、Chain-of-Thought、结构化输出）

第3-4周：RAG原理与实践
  - 理解RAG流程：文档加载 → 切分 → Embedding → 向量检索 → 生成
  - 学习文本切分策略（固定长度、语义切分、递归切分）
  - 了解主流向量数据库（Milvus/Pinecone/Chroma/Elasticsearch向量检索）
  - 用Spring AI或LangChain4j实现一个简单的RAG问答系统

第5-6周：Agent概念与进阶
  - 理解Agent的核心：规划(Planning) + 工具调用(Tool Use) + 记忆(Memory)
  - 了解ReAct模式、Function Calling
  - 用Spring AI实现一个可调用工具的Agent Demo
  - 了解模型评测的基本思路（RAGAS等）

第7-8周（可选）：进阶主题
  - 模型服务化与部署（OpenAI API / 本地模型Ollama）
  - 多模态基础概念（文本+图片）
  - AI工程化：Prompt版本管理、A/B测试、监控
```

### Java后端 + AI应用层组合的优势

| 纯Java后端 | Java + AI应用层 |
|-----------|---------------|
| 竞争者多 | 竞争者少（大部分人不会AI） |
| 定位模糊 | 定位清晰："懂AI的后端工程师" |
| 只能做传统业务 | 能做AI驱动的业务（知识库、智能客服、代码助手） |
| 面试亮点普通 | 简历上有RAG/Agent项目，面试官眼前一亮 |

## 4. 校招的技术深度标准：学多深才算够

### 各知识模块的"够了"标准

| 模块 | 不算够 | 够了 | 超出预期 |
|------|--------|------|---------|
| **HashMap** | 知道数组+链表 | 能说清楚put流程、扩容机制、红黑树退化条件 | 能讲为什么用红黑树不用AVL树 |
| **ConcurrentHashMap** | 知道它是线程安全的HashMap | 能讲1.7分段锁 vs 1.8 CAS+synchronized | 能讲size()的计数方式 |
| **线程池** | 知道7个参数 | 能解释核心线程→队列→最大线程→拒绝的流程 | 能讲线程池动态调整、如何监控 |
| **JVM GC** | 知道有新生代老年代 | 能讲清楚GC算法和触发条件 | 能讲ZGC/Shenandoah的设计思路 |
| **MySQL索引** | 知道B+Tree | 能分析Explain结果，会索引优化 | 能讲索引下推、MRR、自适应哈希 |
| **Redis缓存** | 知道缓存雪崩等概念 | 能讲解决方案的具体实现 | 能讲多级缓存、热点发现、缓存预热 |
| **Spring IoC** | 知道控制反转 | 能讲Bean的完整生命周期 | 能讲循环依赖的三级缓存解决 |
| **MQ** | 知道异步解耦 | 能讲消息可靠性的具体保证 | 能讲消息堆积的处理方案 |

> 💡 **对大多数大三学生来说，达到"够了"这一列就是可以过面试的水平。** 不要一开始就追求"超出预期"——那是拿到Offer之后的事。

### 判断深度的自检方法

每学完一个知识点，做这个测试：

```
问自己：
1. 这个东西解决什么问题？（Why）
2. 它怎么解决？（How）
3. 有没有其他方案？（Alternative）
4. 为什么选这个方案？（Trade-off）

如果四个问题都能回答 → 够了
如果只能回答1和2 → 还不够，需要深入
```

## 5. 项目经验怎么快速积累

### 路线A：改造开源项目（推荐，最快见效）

```
1. GitHub找一个"外卖/商城/博客"的Spring Boot开源项目
2. 跑起来，理解它的结构和设计
3. 加至少3个你自己的改进：
   - 加一个缓存层（Redis）
   - 加一个消息队列异步处理（如订单超时取消）
   - 加一个技术亮点（如接口限流、分布式锁、Elasticsearch搜索）
4. 写一个READ ME文档说明你的改进
5. 这就可以写在简历上了——你不只是"用了开源项目"，你做了改进
```

### 路线B：从头搭一个项目

```
如果时间充足（有2-3个月），从头做一个项目是最好的。

推荐方向（选一个）：
  1. 电商秒杀系统 → 练高并发、缓存、分布式锁
  2. RAG智能客服/知识库 → 练AI集成、向量检索、Prompt
  3. 简易IM系统 → 练WebSocket、消息可靠性、在线状态
  4. 短链系统 → 练系统设计、哈希算法、高可用

最低要求：
  - 至少2000行代码
  - 至少涉及3个中间件（MySQL + Redis + MQ/ES）
  - 有完整的接口文档和基本测试
```

### 路线C：比赛项目/课程设计深化

```
如果你参加过比赛（大创、服创、数学建模等）或有课程设计：
  - 不要只写"参加了XX比赛"
  - 把比赛项目转化为技术项目来表述
  - 强调你用了什么技术、解决了什么问题、取得了什么效果
```

## 6. 时间不够时的优先级排序

大三的你大概率时间不够。以下是精简后的优先级：

### 必做项（没有这些不要投简历）

```
1. Java基础：集合 + 多线程 + JVM（2-3周）
2. Spring Boot + MyBatis + MySQL + Redis（4-5周）
3. 一个完整的项目（2-3周）
4. LeetCode 100题以上（每天2-3题，1-2个月）
5. 一份能投出去的简历
```

### 锦上添花项（有时间就做，加分明显）

```
6. 计算机基础（OS/网络）的系统复习
7. 消息队列的学习和使用
8. AI应用层（RAG/Agent）的入门
9. GitHub仓库有代码有star
10. 技术博客5篇以上
```

### 可以舍弃的（校招阶段性价比低的）

```
- 学第二门语言（Go/Python）——专心把Java学好
- 研究各种新框架——面试不考
- 看大部头技术书从头看到尾——时间不够，按面试考点学
- 做太多DEMO级小项目——不如一个项目做深
```

## 7. GitHub与技术博客的建设

### GitHub：不要是空白的

面试官真的会点开你的GitHub链接。如果打开是一片空白或者只有fork的仓库，不如不放链接。

```text
最低要求：
  - 至少1个你自己写的完整项目（不是fork）
  - READ ME清楚（项目介绍、技术栈、如何运行）
  - 代码有基本的注释
  - 提交记录能看出开发过程（不是一次提交全部代码）

加分项：
  - 项目有star（哪怕是同学互点几个也行）
  - 有issue和pull request（说明你在维护）
  - 写了单元测试
  - 有CI/CD配置
```

### 技术博客：证明你在思考

| 博客内容方向 | 价值 |
|------------|:--:|
| 踩坑记录（"Spring Boot 整合 XX 时遇到的 N 个坑"） | ⭐⭐⭐⭐ 最真实、最容易写 |
| 学习笔记（"XX 技术核心原理总结"） | ⭐⭐⭐ 展示知识体系 |
| 项目复盘（"XX 项目技术选型和架构设计"） | ⭐⭐⭐⭐⭐ 面试价值最高 |
| 源码阅读（"XX 中间件核心源码解析"） | ⭐⭐⭐⭐ 展示技术深度 |

> 💡 **不用写很多篇。** 5-10篇认真写的技术博客，远胜于50篇拼凑的文章。博客平台推荐：掘金、CSDN、或自己搭一个GitHub Pages博客（本身也是一个项目）。
