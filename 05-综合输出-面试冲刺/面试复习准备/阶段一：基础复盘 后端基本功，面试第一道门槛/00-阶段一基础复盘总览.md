🟢 保命路线（3天，每天2小时）：01语法 → 02集合 → 03并发 → 04JVM

三条路线对应三个处境：时间只够保底就死磕 Java 四件套（命中率最高、性价比最大）；时间充足就补齐中间件与框架；临考前只看 09-10 两篇做最后冲刺。**每一篇都按"先记住答题要点 → 再理解为什么 → 最后过一遍追问"的顺序消化**，不要反着来——面试是口头输出，背诵优先于深究。

每篇的消化节奏建议 60 分钟："**15 分钟通读 → 15 分钟背诵要点区 → 20 分钟理解原理与权衡 → 10 分钟口述复现**"。口述复现是最关键的一步——对着目录结构把全文要点讲一遍，讲不出的段落标红回炉。仓库里每个主题（如 HashMap、MySQL 索引、Redis 缓存）都有对应的深度知识体系（见 CLAUDE.md 的知识系统索引），复盘时如果某篇讲不透，跳转对应深体系补课后再回来——本系列是"面试视角的精装版"，深体系是"学习视角的全量版"，两者配合使用效果最佳。

## 6. 面试官视角：第一道门槛怎么打分

理解评分逻辑才能答在点上，面试官对基础题的打分基本是"减法"：**先说结论 → 再说原理 → 能带权衡 → 覆盖边界**，每缺一层扣一档。基础题的满分答案结构是"结论 + 一句话原理 + 一个反例"——比如"String 不可变（结论），因为安全与性能（原理），如果可变 HashMap 的 key 就坏了（反例）"，三个元素齐全即 A 档。

候选人最常见的三种死法：**只背结论不背原理**（"HashMap 是数组加链表"，问为什么 2 的幂答不出）；**只背原理不背边界**（"volatile 保证可见性"，不知道它不保证原子性）；**不背版本**（2026 年还在说偏向锁是标配、MySQL 8.0 最新——版本意识是面试官判断你"持续学习"的硬信号）。本系列的每篇末尾都按这三种死法埋了"追问预案"，自测时专挑追问答。

另一个评分细节：**基础题的表现会决定后面所有题的提问深度**——基础答得干脆，面试官默认你水平高，问得更深；基础支支吾吾，面试官提前收工。所以阶段一的策略是"保下限"：不求每个细节惊艳，但所有基础题必须答得又快又稳。

## 7. 与阶段二三四的衔接

本系列是四阶段复习的第一步，衔接逻辑一句话："**基础是门槛，AI 是差异，项目是底气，模拟是检验**"。阶段一过关后带着两个产出进入下一阶段：**一份薄弱点清单**（从 10 篇自测的 C 档题统计，进阶段二时同步回炉）与**一套答题模板**（四档模板在项目与 AI 题目中同样适用）。阶段二（AI 大模型专项攻坚）考察的是差异化能力——RAG、Agent、Function Calling、大模型 API 工程化；阶段三（项目与简历打磨）把技术与项目串起来讲成故事；阶段四（模拟面试）做最终检验。基础不牢时强行进阶段二，AI 题里一旦追问到底层（比如向量检索为什么快、Agent 循环的内存模型），就会暴露地基空洞——**按顺序复习，别跳级**。

> 💡 **一句话总结**：第一道门槛的本质是"基础知识的肌肉记忆"——不是会不会，而是 30 秒内能不能把要点说清楚。本系列每篇都按 **考点 → 答题要点 → 追问预案 → 自测** 四段式编排，10 篇过完，基本功这道门槛稳稳迈过，再进入阶段二（AI 大模型专项攻坚）。
