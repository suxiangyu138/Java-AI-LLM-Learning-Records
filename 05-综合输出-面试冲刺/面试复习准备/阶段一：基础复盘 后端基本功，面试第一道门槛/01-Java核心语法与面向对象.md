## 1. 基础语法高频考点

基础语法题很少单独出现，而是藏在代码阅读题里。三个必考点：**基本类型与引用类型的本质区别**（值拷贝 vs 引用拷贝、栈上存储 vs 堆上对象）、**== 与 equals 的判等差异**（== 比较栈上的值：基本类型比数值、引用类型比地址；equals 默认也是比地址，String 等类重写后才比内容）、**自动类型转换的规则**（小转大自动、大转小需强转且可能丢失精度，`int → long` 自动，`long → int` 强转截断）。

`float f = 3.14;` 为什么编译不过？因为字面量 3.14 默认是 double 类型，大转小必须强转——这是面试官最爱埋的坑之一。同理 `byte b = 127;` 能过（编译期常量在范围内自动收缩），`byte b = 128;` 报错（超出范围）。区分"编译期常量折叠"和"运行期强转"，是答对这类题的关键。

## 2. 装箱拆箱与缓存陷阱

自动装箱本质是编译期调用 `Integer.valueOf()`，拆箱调用 `intValue()`。**缓存陷阱**：`Integer` 在 -128~127 范围内有缓存池，`Integer a = 100; Integer b = 100; a == b` 为 true；超过 127 则 false，因为每次 new 新对象。`Integer.valueOf()` 会先查缓存，而 `new Integer()` 永远新建——所以面试题里"两个 128 比较"必是坑。

```java
Integer a = 128, b = 128;
System.out.println(a == b);        // false，超出缓存范围
Integer c = 100, d = 100;
System.out.println(c == d);        // true，缓存池命中
System.out.println(c.equals(d));   // true，比较数值
```

由此引出两条工程铁律：**包装类型比较一律用 equals**；**循环中反复装箱会创建大量对象，用基本类型**。追问方向通常是"缓存范围为什么是 -128~127"——答：高频小整数复用收益高，`-XX:AutoBoxCacheMax` 可调整上限（仅上限，下限固定 -128）。

## 3. String 专题：不可变与常量池

String 不可变有三个层面的答案：**安全**（不可变对象可被多个线程共享、可作为 HashMap 的 key 和缓存 key 而不会被修改导致哈希错乱）、**性能**（常量池复用、hashCode 可缓存——String 的 hashCode 字段惰性计算一次存下）、**设计**（Java 之父在《Effective Java》之外的经典设计决策）。注意子类安全问题也是原因之一：String 被 final 修饰，不可被继承覆写。

字符串拼接的演进是高频追问：JDK 8 用 StringBuilder 优化 `+` 号；JDK 9 之后改成 `invokedynamic` + `StringConcatFactory` 动态拼接，不再无条件 new StringBuilder。循环内拼接仍应手写 StringBuilder——编译器优化不覆盖循环体内多次拼接。`intern()` 手动入池、`==` 比较字符串常量池对象，都是延伸考点。

## 4. 面向对象三大特性辨析

三大特性必须用"能说出一个真实场景"的方式回答，而不是背定义：

**封装**：隐藏内部状态，通过方法暴露操作——JavaBean 的 private 字段 + getter/setter、DTO 对外只读、状态变更统一走业务方法，都是封装。追问"封装和把字段设 private 是一回事吗"——不是，封装是设计原则，private 是实现手段之一，包级可见 + 文档约束同样可以是封装。

**继承**：is-a 关系复用代码与抽象——但面试官更想听到"继承的代价"：强耦合（父类一改子类全动）、破坏了封装（子类可见父类实现细节）、菱形问题（Java 用单继承规避，接口多实现）。现代工程实践倾向**组合优于继承**——用 `has-a` 关系 + 委托替代深继承链。

**多态**：运行时行为绑定——父类引用指向子类对象，调用被子类覆写的方法时动态分派。三个前提：继承或实现、方法覆写、父类引用指向子类对象。追问"多态与方法重载的区别"——重载是编译期静态绑定（看引用类型决定调哪个），覆写是运行期动态绑定（看实际对象类型决定调哪个）。

## 5. 接口 vs 抽象类：选型决策

选型看语义关系：**抽象类是"是什么"（is-a），接口是"能做什么"（can-do）**。抽象类允许有实例字段、构造器、具体方法，适合模板方法模式——父类定义骨架，子类填充差异；接口侧重行为契约，Java 8 后可以有 default/static 方法，Java 9 有私有方法，支持多实现，天然解耦"类型定义"与"实现来源"。

2026 年的视角要补充：接口 default 方法承担了部分"抽象类式"的代码复用职责，但 default 方法没有状态（不能定义实例字段），所以**需要共享状态用抽象类，只需要行为契约用接口**。经典例证：`AbstractList` 为 `ArrayList`/`LinkedList` 提供公共骨架，`List` 接口只声明行为。

## 6. 异常体系与受检之争

异常体系一句话背熟：**Throwable 分 Error（不可控，OOM/StackOverflow）与 Exception；Exception 分受检异常（编译期强制处理，IOException）与运行时异常（RuntimeException，可不受检，NPE/ClassCast）**。受检异常的争议是高频追问：受检异常强制调用方处理，提高健壮性，但也导致大量空 catch 和 throws 泛滥；现代工程（Spring 等框架）倾向**继承 RuntimeException 的自定义业务异常**——错误码 + 异常类型 + 全局处理器，把"该不该抛、谁来处理"从编译期约束转为架构约定。

工程铁律：**异常只用不做控制流**（不要用异常做正常分支判断，性能差且可读性差）；**catch 后必须处理或上抛，禁止吞异常**；**finally 里不要 return**（会覆盖 try 中的返回值）；**try-with-resources 优先于 finally 手动关闭**（JDK 7+，自动调用 close 且保留主异常）。

## 7. 泛型与类型擦除

泛型是编译期类型检查 + 运行期擦除：`List<String>` 编译后变成 `List`，类型参数在字节码层面消失（Method 参数保留 Signature 属性用于反射）。三个经典考点：**泛型不能是基本类型**（`List<int>` 非法，用 `List<Integer>`）；**不能 new T[]**（数组的运行时类型检查与擦除冲突，用 `(T[]) new Object[n]` 强转）；**泛型与重载的冲突**（`void f(List<String>)` 与 `void f(List<Integer>)` 擦除后签名相同，编译不过）。

逆变协变的通配符：`? extends T` 只能读（上界通配符，读出来的是 T 类型），`? super T` 只能写（下界通配符，可存 T 及其子类）——这就是著名的 PECS 原则（Producer Extends, Consumer Super）。TypeToken 方案（`new TypeToken<List<String>>(){}` 通过匿名子类保留类型信息）是 Gson 等库解决擦除的经典做法，深挖可加分。

### 追问速查

面试官最可能的追问与应答（挑 3 条背熟即可）：`Integer` 缓存能调吗（`-XX:AutoBoxCacheMax`，仅上限）；String 拼接 JDK 9 后怎么优化（`invokedynamic` + StringConcatFactory）；泛型擦除后反射能看到类型吗（能，Signature 属性保留，Gson TypeToken 依赖它）。

> 🎯 **核心要点**：语法题的满分答案 = 结论 + 一句话原理 + 一个反例。比如 String 不可变：不可变（结论）→ 安全/性能/设计三层面（原理）→ "若可变，HashMap 的 key 会坏"（反例）。背熟这个结构，语法关必过。
