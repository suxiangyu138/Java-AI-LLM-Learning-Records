## 1. 运行时内存区域

六区一线背熟：**程序计数器**（线程私有，记录字节码行号，唯一不 OOM 的区域）、**虚拟机栈**（线程私有，栈帧存局部变量表/操作数栈/动态链接/返回地址，StackOverflowError）、**本地方法栈**（native 方法）、**堆**（线程共享，对象与数组，GC 主战场，Java 8 之后字符串常量池也在堆）、**方法区**（JDK 8 改为元空间 Metaspace，存类元数据，用本地内存——最大好处是不受堆上限约束，OOM 类型从 PermGen 变 Metaspace）、**直接内存**（NIO 的 DirectByteBuffer，不受堆管理，容易漏回收）。

内存模型 vs 内存区域的辨析是高频坑：**JMM（Java 内存模型）是抽象规范**（主内存+工作内存，解决可见性问题），**运行时数据区是 JVM 实际划分**——两者不是一个东西，答错即减分。Java 8 的永久代 → 元空间变化要会答：为什么改（永久代大小难调、字符串常量池放永久代易 OOM、HotSpot 与 JRockit 合并的推动）。

## 2. 对象创建与内存布局

对象创建四步：**类加载检查 → 分配内存（指针碰撞或空闲列表，取决于堆是否规整）→ 初始化零值（保证字段有默认值）→ 设置对象头 + 执行构造方法**。并发分配的安全手段：CAS + 失败重试，或 TLAB（线程本地分配缓冲，每个线程在 Eden 划一块，避免竞争）——**对象分配首选 TLAB，大对象直接进老年代**。

对象内存布局三部分：**对象头**（Mark Word 存锁状态/GC 年龄/hashCode + 类型指针）、**实例数据**（字段值，对齐填充）、**对齐填充**（8 字节倍数）。对象头 Mark Word 复用锁状态位是 synchronized 实现的基础——与并发篇的锁升级呼应，面试官常把两题串起来问。

## 3. GC 判定与三大算法

判定存活两方法：**引用计数**（循环引用缺陷，主流不用）与**可达性分析**（GC Roots 出发，不可达即垃圾）。GC Roots 四类必背：**虚拟机栈中的局部变量、静态变量、常量引用、native 方法引用的对象**。延伸考点：四种引用强度（强引用永不回收、软引用内存不足回收——缓存、弱引用下次 GC 即回收——ThreadLocal key、虚引用跟踪回收——DirectByteBuffer 清理）。

三大算法取舍：**标记-清除**（基础但产生碎片）、**复制**（新生代用，空间换时间，存活率低时高效）、**标记-整理**（老年代用，移动对象消碎片，但停顿长）。核心认知：**没有完美的 GC 算法，只有适配分代特征的组合**——新生代对象 98% 朝生夕死，用复制；老年代对象存活久，用标记-整理。

## 4. 分代假设与收集器选型

分代划分必背：**新生代（Eden:S0:S1 = 8:1:1）+ 老年代（默认比例 1:2）**。对象晋升老年代四条件：**年龄阈值 15（CMS 6）、大对象直入、动态年龄判定、S 区放不下**。Minor GC 触发：Eden 满；Full GC：老年代满、元空间满、System.gc()（Stop-The-World 全暂停）。

收集器演进是 2026 面试必考主线：

**CMS**（JDK 9 弃用、JDK 14 移除）：并发标记清除——四阶段（初始标记/并发标记/重新标记/并发清除），目标最短停顿，但**碎片化 + 并发失败退化为 Serial Old 全停顿**——答出这两个致命伤即到位。

**G1**（JDK 9 起默认）：**堆分为约 2048 个 Region，不再物理分代，逻辑分代**；可预测停顿模型（-XX:MaxGCPauseMillis 默认 200ms），按回收收益排序回收 Region（Garbage First）；跨 Region 引用用 Remembered Set 追踪；三色标记 + SATB 快照解决并发标记漏标。G1 是生产主力，面试必须能讲清"Region 化 + 收益优先"两个核心。

**ZGC**（JDK 21 起默认，JDK 24 支持分代）：**着色指针 + 读屏障，停顿目标 < 1ms 且与堆大小无关**——百万级 TLAB、TB 级堆场景。面试口径："G1 停顿随堆增长，ZGC 停顿恒定毫秒级，代价是吞吐略降与内存占用略高（着色指针）。

JDK 25 LTS（2025-09 发布）维持 G1/ZGC 双默认格局——**生产选型：追求吞吐与成熟稳定用 G1，超大堆 + 低延迟刚需用 ZGC**。

## 5. 类加载机制与双亲委派

类生命周期七阶段：**加载 → 验证 → 准备 → 解析 → 初始化 → 使用 → 卸载**（前五阶段是"加载时机"考点）。初始化时机六条（new/反射/调用静态成员/初始化子类先父类/主类/动态代理）挑三条背即可。

**双亲委派**：类加载请求先委派父加载器，逐级向上，父加载不了才自己加载。目的：**避免核心类被重复加载与篡改**（java.lang.String 必须由 Bootstrap 加载器加载，保证核心 API 一致性）。三级加载器：Bootstrap（JDK 核心）、Platform（JDK 9+，取代 Extension）、Application（classpath）。**打破双亲委派的两个经典场景**：SPI（JDBC DriverManager 用线程上下文类加载器加载实现类）与 Tomcat 的 WebApp 类加载器（优先加载应用自己的类实现热部署、隔离应用依赖）。答出"为什么打破 + 怎么打破"，本题满分。

## 6. OOM 全景与排查实战

四种 OOM 必背：**Java heap space**（堆满——内存泄漏或堆太小）、**Metaspace**（类太多——反射/动态代理/热部署加载器泄漏）、**GC overhead limit exceeded**（GC 回收率低且回收量小，98% 时间在 GC）、**Unable to create native thread**（线程数超 OS 限制——ulimit/线程池滥用）。StackOverflowError 是递归过深，不是 OOM。

排查方法论一条线：**jps 找进程 → jmap -heap 看堆 → jmap -dump 堆 dump → MAT 分析大对象/泄漏路径 → jstack 看线程状态**。生产实践：OOM 前自动 dump（`-XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath`）、用 Arthas 在线定位（dashboard 看内存、heapdump 命令、sc 查类）、GC 日志分析（-Xlog:gc*）——答排查题用"遇到过 → 定位 → 修复 → 防再犯"四段式，比背命令加分得多。
