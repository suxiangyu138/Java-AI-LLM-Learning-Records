## 1. 盲区清单的使用方法

本清单的定位：**不是复习教材，是自测索引**——每条给"自测题"（30 秒内能口述答案吗？）与"回炉源"（答不上回哪补）。使用方法三步骤：**① 速查自测**——每周过一遍清单，30 秒一题，答不上的打标（这三步与阶段一/二的速查表同用法）；**② 深度回炉**——打标的条目跳转回炉源（仓库对应知识体系 + 阶段一/二对应篇目）补课，补完回来重新自测；**③ 项目对照**（第 8 节）——把盲区与自己的项目挂钩："这个盲区在我的项目里对应哪个点？如果面试官从项目追问到这个盲区，我怎么答？"——**盲区只有挂到自己的项目上才算真解决**。使用频率建议：**面试前 1 天 + 每周一次例行自测**；配合 08 篇的错题本——错题本里反复出现的条目就是你的"个人盲区"，优先于通用清单。

## 2. MySQL 高频盲区

**① 索引失效场景**——自测：列运算（`WHERE id+1=2`）、隐式类型转换（字符串列与数字比较）、LIKE 前置 %、最左前缀破坏（跳过首列）、范围查询后失效、OR 未全索引——**一句话：让索引列"独立出现在比较表达式左侧"才不失效**；回炉源：阶段一 05 篇 + `02-.../MySQL 体系`。**② 事务隔离级别与 MVCC**——自测：四个级别分别解决什么问题？MVCC 的版本链（隐藏字段 + undo log + Read View）怎么实现快照读？——**一句话：MVCC 让读不加锁，Read View 决定可见版本**；回炉源：阶段一 05 篇。**③ 幻读怎么解决**——自测：RC 下有幻读吗？RR 下 MVCC 能防快照读幻读，当前读靠什么？（间隙锁/临键锁）——**一句话：快照读靠 MVCC、当前读靠锁**；回炉源：阶段一 05 篇。**④ 慢查询排查**——自测：慢日志 → EXPLAIN 看哪三列？（type/key/rows）→ 加索引或改写——**一句话：先看全表扫描标志，再优化索引**；回炉源：阶段一 05 篇 + `中间件运维故障排查`。**⑤ 分库分表策略**——自测：什么规模要分？（单表千万级/单库连接瓶颈）水平 vs 垂直？分片键怎么选？（按业务访问模式）——**一句话：分片键选"查询最频繁的等值条件"，范围查询用分片键前缀**；回炉源：`MySQL 体系` 分库分表篇。

## 3. Redis 高频盲区

**① 缓存三问防线**——自测：穿透/击穿/雪崩的定义与防线（布隆过滤器/互斥锁+逻辑过期/随机过期+多级+降级）——**一句话：穿透查不存在、击穿热 key 过期、雪崩大量同时过期**；回炉源：阶段一 06 篇 + 阶段三 06 篇。**② 持久化选型**——自测：RDB（快照、恢复快、丢数据窗口大）vs AOF（日志、fsync 策略、恢复慢）——**一句话：数据安全优先 AOF、恢复速度优先 RDB、生产常用混合**；回炉源：阶段一 06 篇。**③ 分布式锁**——自测：SET NX EX 原子性、value 唯一值防误删、看门狗续期、RedLock 争议——**一句话：锁是加速器不是安全网，靠幂等兜底**；回炉源：阶段一 06 篇 + 阶段三 06 篇。**④ ZSet 底层**——自测：跳表 + 哈希表，为什么跳表不是红黑树？（实现简单、区间遍历好）——**一句话：跳表保序 + 哈希表 O(1) 查分值**；回炉源：`Redis 体系` 数据结构篇。**⑤ 大 key 与热 key**——自测：大 key 的危害（阻塞/内存倾斜）、热 key 的应对（多级缓存/热点探测/副本）——**一句话：大 key 治本靠拆分，热 key 靠多副本分摊**；回炉源：`中间件运维故障排查`。

## 4. 并发与 JVM 高频盲区

**① volatile 语义边界**——自测：可见性 + 禁重排，**不保证原子性**（i++ 是三条指令）——**一句话：volatile 是轻量同步，复合操作必须加锁或 CAS**；回炉源：阶段一 03 篇 + JMM 体系。**② 线程池七参数与拒绝**——自测：core/max/队列/存活/工厂/拒绝四策略（Abort/CallerRuns/Discard/DiscardOldest）——**一句话：队列满再扩到 max，max 满走拒绝策略**；回炉源：阶段一 03 篇。**③ ThreadLocal 泄漏**——自测：ThreadLocalMap 的 key 是弱引用，value 强引用——线程池复用线程时 value 不释放 → 必须 remove——**一句话：用完 remove 是铁律**；回炉源：阶段一 03 篇。**④ CAS 的 ABA 问题**——自测：版本号解决；**一句话：加版本戳或 AtomicStampedReference**；回炉源：阶段一 03 篇。**⑤ 虚拟线程（2026 高频）**——自测：平台线程 vs 虚拟线程、适用场景（IO 密集）、pinning 陷阱（synchronized 阻塞内核线程）——**一句话：IO 密集用虚拟线程、CPU 密集用平台线程**；回炉源：`虚拟线程` 体系。**⑥ GC 选型**——自测：CMS vs G1 vs ZGC 的适用（延迟敏感 vs 吞吐 vs 超大堆）——**一句话：JDK 17+ 默认 G1，超低延迟用 ZGC**；回炉源：阶段一 04 篇 + JVM 体系。

## 5. 消息队列与分布式高频盲区

**① 消息可靠性三环节**——自测：生产（发送确认+重试）、存储（持久化）、消费（手动 ack+幂等）——**一句话：生产重试、消费幂等、存储持久化**；回炉源：阶段一 09 篇。**② 消费积压**——自测：积压怎么查（lag）、怎么处理（扩容分区/消费提速/降级）——**一句话：分区数=并行度上限，扩容要新分区+重分配**；回炉源：`消息队列理论与实战` + `中间件运维故障排查`。**③ 分布式事务四方案**——自测：XA/TCC/SAGA/消息事务的适用场景——**一句话：资金强一致 TCC、业务最终一致消息事务**；回炉源：阶段三 07 篇 + Seata 体系。**④ 分布式 ID**——自测：雪花算法结构与时钟回拨、号段模式——**一句话：雪花靠时间戳有序，回拨要兜底**；回炉源：`雪花算法` 体系。**⑤ CAP 与 BASE**——自测：为什么不能三选二（网络分区必选）、最终一致怎么做——**一句话：分区是常态，一致与可用只能二选一，生产走 BASE**；回炉源：阶段一 09 篇。

## 6. Spring 高频盲区

**① Bean 生命周期与循环依赖**——自测：实例化-属性填充-初始化三段关键回调？三级缓存为什么三级？——**一句话：第三级是工厂函数，只有循环依赖才用到**；回炉源：阶段一 07 篇 + `Spring框架核心`。**② 事务失效场景**——自测：自调用（this 调用不走代理）、非 public、异常被 catch、类未被代理——**一句话：事务靠代理，绕过代理就失效**；回炉源：阶段一 07 篇。**③ @Autowired vs @Resource**——自测：按类型 vs 按名称——**一句话：Autowired 按类型 + 可配合 Qualifier**；回炉源：`Spring框架核心`。**④ Spring Boot 自动装配原理**——自测：@EnableAutoConfiguration + 条件注解 + META-INF/spring.factories（Boot 4 是 AutoConfiguration.imports）——**一句话：starter 带配置类 + 条件注解按需装配**；回炉源：阶段一 07 篇。**⑤ 拦截器 vs 过滤器 vs AOP**——自测：三层职责与顺序（Filter 容器层 → Interceptor MVC 层 → AOP Bean 层）——**一句话：越内层越接近业务**；回炉源：`Filter 过滤器` + `SpringBoot Web` 体系。

## 7. AI 应用高频盲区

**① RAG 为什么不直接问模型**——自测：时效/隐私/成本/溯源 + 长上下文之辩——**一句话：窗口解决装得下，不解决找得准与付得起**；回炉源：阶段二 05 篇。**② 分块与检索参数**——自测：chunk size 为什么 256-512、重叠、TopK/重排、混合检索——**一句话：分块是精度第一关口，重排用数量换质量**；回炉源：阶段二 05/06 篇。**③ 幻觉防线**——自测：RAG 接地/拒答机制/评估门禁——**一句话：约束治标、接地治本、门禁兜底**；回炉源：阶段二 02/09 篇。**④ Prompt Caching**——自测：稳定前缀/工具排序/命中率监控——**一句话：前缀字节级不变才命中，排序一变全 miss**；回炉源：阶段二 03 篇。**⑤ Agent 可控性**——自测：工具权限最小化/二次确认/轮数上限/审计——**一句话：模型只输出意图，执行权与校验全在后端**；回炉源：阶段二 04/07 篇。**⑥ LLM-as-Judge 偏见**——自测：位置/自我偏好/冗长三偏见——**一句话：跨家族评判 + 交换顺序检测**；回炉源：阶段二 09 篇。

## 8. 项目对照法：从盲区到项目

清单扫盲的最后一公里：**把每个盲区挂到自己的项目上**。对照方法：**① 找对应点**——"缓存三问"在你的项目里对应什么？（商品详情缓存？库存查询？）——没有对应点的盲区说明项目没覆盖该场景，面试时不会被从项目追问到；**② 造场景问法**——"如果面试官从我的项目问缓存穿透：我的缓存 key 是什么？如果用户查不存在的商品会发生什么？我当时怎么防的？"——**把通用题改造成"我的项目版"再答一遍**；**③ 查简历声明**——简历上写了"熟悉 Redis"就至少覆盖 Redis 盲区全表（写了的就要能扛追问，阶段三 03 篇纪律）；**④ 形成项目盲区清单**——每个项目一张"项目盲区对照表"（盲区 / 项目对应点 / 我的答案 / 回炉状态）——面试前只过这张表，比过通用清单高效十倍。**注意**：盲区不是"全要补"——**与项目无关的盲区（如项目没有 Kafka 就不用精通积压处理）降级为"了解即可"**；与项目强相关的盲区（如 AI 项目的幻觉防线）必须补到"能口述 60 秒"——**精力花在"会被问到的盲区"上，这是查漏补缺的效率法则**。
