## 1. 高并发项目的考察定位

面试官考高并发项目的三层意图：**第一层**：验证你理解"高并发不是调参数，是架构"——并发上不去不是加机器就完事，是读写分离、缓存、异步、限流的系统设计（90% 候选人死在这一层：只会说"用了 Redis"）；**第二层**：验证"每个组件为什么存在"——缓存放什么、MQ 削什么峰、锁锁什么资源，每个组件都要能讲清职责与权衡；**第三层**：验证"数字与演进"——压测数据、瓶颈分析、流量 10 倍的演进路径。经典场景（秒杀/抢购/热点）之所以是面试官最爱：链路完整（接入-校验-库存-订单）、矛盾集中（读写冲突、超卖、流量尖峰）、追问可预期（缓存三问、锁、幂等）。备考动作：**把仓库的电商类项目（SuGuangMall 等）或自己的商城项目，按本模块的问题链完整复盘一遍**——大厂问的高并发 90% 都在这个框架内。

## 2. 四件套架构：缓存-限流-异步-锁

高并发系统的架构讲法四件套：**缓存**（读多写少的流量先扛在缓存层——商品详情、库存余量、热榜都进缓存，把数据库流量降两个数量级）；**限流**（入口层挡住超预期的流量——Sentinel/网关限流，保护后端不被尖峰打爆）；**异步**（写路径削峰——订单创建、扣减的耗时操作异步化，MQ 削峰填谷，响应先回成功再慢慢落库）；**锁**（并发下的资源保护——库存扣减用 Redis 分布式锁或原子操作，防超卖）。四件套的讲解顺序即系统的数据流顺序：**请求进来 → 限流过滤 → 缓存承接读 → 写走异步 → 关键资源加锁**——把这个流程讲顺，架构层面的分数就到手了。加分细节：**每件套都要讲"为什么在这一层"**（限流在网关层要挡在最前面；缓存放应用层要离用户近）与**代价**（缓存一致性、异步的最终一致、锁的性能损失）。

## 3. 缓存三问：穿透-击穿-雪崩

高并发面试的必考三连，每个都要"定义 + 场景 + 防线"讲透：**缓存穿透**（查询不存在的数据，缓存永远不命中，请求全部打到数据库——防线：布隆过滤器拦截不存在 key + 空值缓存 + 参数校验）；**缓存击穿**（热 key 过期瞬间，大量并发同时打数据库——防线：互斥锁重建缓存 + 逻辑过期；注意区分"穿透"是查不存在、"击穿"是热 key 过期）；**缓存雪崩**（大量 key 同时过期，或缓存节点宕机，流量全压数据库——防线：过期时间加随机值 + 多级缓存 + 限流降级 + 集群高可用）。讲法要点：**每个防线要讲"为什么有效"**（布隆过滤器为什么能拦截：位数组 + 多次哈希，存在性判定有假阳性无假阴性）；**要讲选择**（"空值缓存适合不存在量大的场景，布隆过滤器适合不存在量少但查询频率极高的场景"）；**2026 加分视角**：AI 项目里的缓存同样适用（"LLM 结果缓存：幂等的检索结果按参数缓存，非幂等的生成不缓存"——把三问迁移到 AI 场景是差异化表达）。

## 4. 缓存一致性：双写与锁

"缓存与数据库怎么保持一致"是必追问，讲法分两层：**第一层：方案谱系**——Cache-Aside（旁路缓存，读未命中回源+写库后删缓存——最常用）、Write-Through/Write-Back（写穿/写回）、延迟双删（写库后先删缓存、延迟再删一次，防并发读写竞态）；**第二层：为什么难**——缓存与数据库是两个存储，双写天然存在时间窗口，强一致需要引入事务或锁（代价巨大），所以生产默认"最终一致 + 业务可接受窗口"。表达公式："**我用了 Cache-Aside + 延迟双删 + 对账任务兜底**（方案）→ 因为强一致要分布式事务太重、业务允许秒级最终一致（权衡）→ 对账任务每小时扫不一致数据修复（兜底）"。加分点：**能讲出双删为什么"延迟"**（先删缓存后写库，写库期间有读会把旧数据回填缓存——延迟再删一次覆盖这个窗口）；**能讲出缓存更新的顺序选择**（先更新数据库再删缓存 vs 先删缓存再更新数据库——后者在写失败时缓存被删导致雪崩，所以主流是"先写库后删缓存"）。

## 5. 限流削峰：从网关到库存

限流的讲法三层：**限流算法**（固定窗口/滑动窗口/漏桶/令牌桶——令牌桶最常用：允许突发且匀速；滑动窗口解决固定窗口的临界突变问题——仓库的 Sentinel 体系有完整原理）；**限流位置**（网关层限整体流量 → 应用层限接口/用户维度 → 库存层做最终校验——多层限流的职责分工）；**削峰手段**（MQ 异步化——"下单请求先进 MQ，消费者按最大处理能力消费落库，削峰填谷；前端再配答题/排队/按钮置灰"）。秒杀场景的完整链路示范："**入口限流（Sentinel 按用户维度限流 + 网关总闸）→ 缓存承接（商品详情与库存余量走 Redis）→ 库存预扣（Redis 原子扣减，成功才发 MQ）→ 异步落库（消费者创建订单，数据库做最终校验）→ 超卖防线（数据库库存字段 CAS 更新 + 唯一订单号防重）**"——这条链讲顺 + 每个环节能答追问，秒杀题就稳了。注意：**限流不只是拒绝**——"拒绝后返回什么（排队页/稍后再试）+ 怎么放量（动态调整阈值）"是 2026 年面试官爱追问的体验细节。

## 6. 分布式锁：Redis 锁的正确姿势

"分布式锁怎么做"的完整答案链：**简单版**（SET key value NX EX 10——原子设置 + 过期时间，注意必须原子，分开 setnx 和 expire 是经典错误）；**防误删**（value 存唯一标识，删除前 Lua 校验再删——防"锁超时后误删别人的锁"）；**可重入**（Redisson 的看门狗自动续期——锁快过期但业务没做完，看门狗续期防锁失效；注意续期是把双刃剑：业务卡死锁永不释放，要有兜底）；**RedLock 与争议**（多节点加锁防单点——但要讲清 RedLock 的争议：可用性 vs 一致性的取舍，生产常用"单节点 Redis + 看门狗 + 业务兜底"或 ETCD 实现）；**业务兜底**（分布式锁防的是并发不防故障——锁丢了还有数据库唯一约束/幂等键兜底，"锁是加速器不是安全网"是 2026 年高频加分句）。追问链预备：锁的粒度（"锁订单 ID 而不是锁全局——粒度越大并发越低"）；锁与幂等的配合（"锁 + 幂等表双保险，锁失效时幂等兜底"）；AI 项目里的锁（"Agent 工具调用的并发控制：同一用户的工具调用串行化，用 Redis 锁按用户 ID 加锁"）。

## 7. 压测与数据：高并发故事的灵魂

高并发项目没有压测数据等于白做——数据是故事的灵魂，讲法三件套：**压测环境**（"JMeter 1000 并发、3 台 4C8G 服务、压测 5 分钟"——环境必须可复述，这是真实性的锚点）；**关键指标**（QPS、P99/P95、错误率、成功率——"峰值 QPS 3000，P99 120ms，0 错误"）；**瓶颈分析**（压测结论——"瓶颈在数据库连接池，优化后连接池从 20 到 50 + 加了查询缓存，QPS 从 1200 到 3000"——瓶颈分析展示的是"看懂系统"的能力）。追问链预备：**流量 10 倍怎么演进**（"缓存命中率 95% → 先加缓存分片与多级缓存 → 再分库分表 → 最后异地多活"——按"软件优化 → 资源 → 架构"顺序答）；**降级与限流的阈值怎么定**（"按数据库安全水位反推：DB 能扛 500 QPS，限流就设在其 70%"）。2026 年 AI 项目的数据补充：**token 成本与推理延迟**（"RAG 检索 P99 50ms、生成首字 800ms、单次问答 token 成本 0.02 元"——AI 项目的"并发"是成本与延迟，不是纯吞吐）。

### 追问速查

挑 3 条背熟：穿透-击穿-雪崩的区分（不存在/热key过期/大量同时过期）；双删为什么延迟（防写库期间旧值回填）；"锁是加速器不是安全网"（锁失效靠幂等兜底）。
