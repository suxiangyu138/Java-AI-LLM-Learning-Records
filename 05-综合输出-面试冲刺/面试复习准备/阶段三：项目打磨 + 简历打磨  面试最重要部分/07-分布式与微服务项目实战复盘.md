## 1. 微服务项目的考察定位

面试官考微服务项目的三层意图：**第一层**：验证"为什么拆"——微服务是手段不是目的，讲不清拆分动机（业务边界/独立部署/团队协作）就只是"用了个框架"；**第二层**：验证分布式基础——拆完的代价（网络、一致性、治理）用什么方案补，这是深度所在；**第三层**：验证工程能力——注册中心、网关、配置、监控、容灾的完整工程闭环。必背的底层认知：**微服务没有消灭复杂度，是把单机复杂度变成了分布式复杂度**——CAP 权衡、网络不可靠、一致性更难，面试官考的就是你对"分布式复杂度"的理解程度。答题姿势：**先讲拆分动机与边界（为什么这样拆）→ 再讲每个服务的关键设计 → 最后讲治理体系（注册/配置/网关/监控）**——"拆-建-治"三段式是微服务项目的通用叙事骨架。

## 2. 服务拆分：边界与演进

拆分题的核心考点是"边界意识"：**按业务域拆（DDD 限界上下文）而不是按技术层拆**——"订单服务、库存服务、支付服务"（业务边界）优于"Controller 服务、Service 服务"（技术边界，拆分后互相调用没有意义）。讲法三件套：**拆分原则**（高内聚低耦合——"订单与库存强关联但变更频率不同，拆开让库存独立扩容"）；**拆分粒度的权衡**（拆太细：链路长、运维重、一致性难；拆太粗：等于没拆——"按变更频率与团队边界决定粒度"）；**演进路径**（"先从单体模块化开始，业务大了再拆出高频变更的服务"——展示"先单体后微服务"的务实路线是 2026 年加分观点，阿里等大厂也在回归"适度微服务"）。追问预备："服务间调用怎么做"（OpenFeign + 注册中心 + 负载均衡）；"服务间共享数据怎么办"（**禁止共享数据库——库是服务的私有边界，数据共享走 API 或事件**——这是微服务数据隔离的经典考点）。

## 3. 注册中心与配置中心

注册中心的讲法：**为什么需要**（服务地址动态变化，不能写死 IP——注册中心提供服务发现）；**工作机制**（服务启动注册、心跳续约、消费者订阅/拉取、摘除下线——"Nacos 客户端每 5s 发送心跳，15s 未续约标记不健康"这类具体数字是加分细节）；**选型对比**（Nacos vs Eureka vs Consul：Nacos 支持 AP/CP 切换、自带配置中心；Eureka 只有 AP 且已停维护；Consul 强一致——"注册中心选型看可用性诉求：注册发现优先 AP，配置变更优先 CP"——结合仓库 Nacos 体系复盘）。配置中心的讲法：**为什么需要**（配置变更不能重启服务——动态刷新）；**实现机制**（配置推送：Nacos 长轮询/发布订阅 vs Spring Cloud Bus 消息广播——"长轮询 30s 级别延迟、Bus 秒级但引入消息依赖"）；**配置管理的工程细节**（环境隔离 dev/test/prod、敏感配置加密、灰度发布配置——2026 年加分：AI 项目的 Prompt 也是配置，"Prompt 版本化走配置中心 + 灰度"是前沿表达）。注意：**注册中心是分布式系统的事实依赖——它的高可用就是系统的高可用**，"Nacos 集群部署 + 多机房容灾"要能讲。

## 4. 分布式事务：四方案选型

分布式事务是微服务面试的最高频深度题，讲法分两层：**第一层：为什么难**——本地事务只能保证单库，跨服务跨库的事务没有单点协调者，网络不可靠 + 事务无法原子提交，所以必须选型；**第二层：四方案谱系与选型**——**XA 两阶段提交**（强一致但性能差、协调者单点——"2PC 的 prepare 阶段锁资源，高并发下不可用"）；**TCC**（Try-Confirm-Cancel 三阶段，业务侵入大但灵活——"预留-确认-取消，适合跨服务资金类强一致"）；**SAGA**（长事务补偿编排——"正向执行 + 反向补偿，适合订单流程类最终一致"）；**消息事务/本地消息表**（"本地消息表 + MQ：本地写业务与消息同事务，MQ 保证消息可达，消费者幂等——最常用、成本最低"）。选型结论：**资金强一致用 TCC/Seata AT，业务最终一致用消息事务**——"Seata AT 模式基于 undo_log 自动补偿，对业务侵入小（结合仓库 Seata 体系复盘）"。追问链预备："Seata AT 的全局锁怎么实现"、"消息丢了怎么办"（生产者重试 + 消费者幂等 + 对账）、"为什么不用 2PC"（阻塞与单点）。

## 5. 分布式 ID 与幂等

**分布式 ID** 讲法：**要求四性**（全局唯一、趋势递增、高性能、高可用）；**方案谱系**（数据库自增/号段、Redis INCR、UUID、雪花算法——雪花 64 位：时间戳 + 机器 ID + 序列号）；**权衡**（UUID 无序伤索引、雪花依赖时钟"时钟回拨会重复"——"我用号段模式或雪花 + 时钟回拨兜底（如回拨后等位或借用序列）"——结合仓库雪花算法体系复盘）；**2026 加分**：UUIDv7 是时间有序的新标准、"短 ID（Snowflake 变体/自研）用于链接场景"。**幂等** 讲法：**为什么需要**（网络重试、MQ 重投、用户双击——幂等是分布式系统的底线）；**方案三件套**（唯一键/幂等表（"订单号唯一索引，重复插入被拒"）、状态机（"订单状态流转只能前进"）、去重表（"支付回调用订单号做去重"））；**与锁的关系**（"幂等是终局兜底，锁是并发控制——锁失效时幂等兜住"）。追问链预备："MQ 消费者幂等怎么做"（消息 ID 去重表 + 业务唯一键）；"接口重试与幂等怎么配合"（请求方带幂等键，服务方查重）。

## 6. 链路追踪与可观测

分布式系统排查问题靠日志不够——**一个请求跨 5 个服务，没有 traceId 连不成一条线**。讲法三件套：**原理**（traceId 入口生成、span 记录每段调用、traceId 在 HTTP 头/日志中透传——"MDC 放 traceId，日志自动带上"）；**工具**（SkyWalking/Arthas/OTel + 监控大盘——"SkyWalking 无侵入探针 + 服务拓扑图，一眼看请求走哪条链路哪段慢"）；**三支柱**（日志/指标/链路——"线上问题排查三步：看链路找到慢的服务 → 看该服务指标（CPU/GC/连接池）→ 看慢服务日志"——结合仓库日志监控指标体系复盘）。2026 年 AI 项目的新可观测（加分表达）：**AI 应用要记录 token 成本、模型版本、检索命中情况**（"每次问答打点：模型、token 数、缓存命中、检索来源——成本与质量问题都能归因"）；**Agent 轨迹日志**（"Agent 每轮的工具调用序列写 JSONL，评估与排障全靠它"——见阶段二 07/09 篇）。

## 7. 容灾与治理：限流-熔断-降级

服务治理三件套的讲法（结合仓库 Sentinel 体系）：**限流**（保护自己——按 QPS/线程数限流，超出拒绝或排队）；**熔断**（保护调用方——下游故障时快速失败，"熔断 10s 内 50% 请求失败即打开熔断器，后续请求直接降级，半开试探恢复"——熔断状态机与滑动窗口能讲就讲）；**降级**（保核心——"大促时非核心功能（评论、推荐）降级，保证下单主链路"——降级策略要在压测时演练过）。三者关系一句话："**限流防自己被打爆，熔断防被下游拖死，降级保核心链路**"——这句口诀背熟，治理题必过。配套讲法：**线程池隔离 vs 信号量隔离**（线程池防下游慢拖垮、信号量轻量防并发超限）；**网关的角色**（统一限流入口 + 路由 + 鉴权——"网关是治理的第一道闸"）。追问链预备："熔断和限流有什么区别"（对象不同：保护对象 vs 保护自己）；"降级怎么设计"（降级点提前识别 + 降级开关配置化 + 降级演练常态化——"没有演练过的降级等于没有降级"）。

| 1 | 为什么拆微服务？ | 业务边界/独立部署/团队协作 / 拆的代价（一致性-链路-运维）要能讲 |
| 2 | 分布式事务怎么选？ | XA 强一致但阻塞 / TCC 资金强一致 / 消息事务最常用最终一致 |
| 3 | 分布式 ID 方案？ | 号段-雪花-UUID / 四性要求 / 时钟回拨兜底 |
| 4 | 熔断-限流-降级区别？ | 保护对象不同 / 口诀：防打爆-防拖死-保核心 |

| 6 | MQ 消息丢了怎么办？ | 生产者重试 / 消费者幂等 / 对账兜底 |

| # | 题目 | 答题要点 + 追问点 |
|---|------|------------------|

### 追问速查

挑 3 条背熟：微服务共享数据库为什么禁止（库是服务私有边界，耦合数据 = 耦合生命周期）；幂等三件套（唯一键-状态机-去重表）；"没有演练过的降级等于没有降级"。

> 🎯 **核心要点**：分布式题满分答案 = 一段式叙事 + 一个选型 + 一个兜底。如"按业务域拆（拆）→ 资金用 Seata AT、订单流程用消息事务（选型）→ 最终一致靠消费者幂等 + 对账兜底（兜底）"。四方案选型谱系与治理三件套口诀是本模块背诵重点。
