## 1. 深度的定义：不是会用，是讲清三层

面试官判断"深不深"不看你会不会用（会用是 2026 年的门槛），看你能讲清几层：**第一层：是什么**（"Redis 是键值缓存"——谁都会）；**第二层：为什么/怎么工作**（"单线程事件循环 + IO 多路复用，所以单线程下无锁且高效；持久化 RDB 快照与 AOF 日志的取舍"——有深度的起点）；**第三层：权衡与边界**（"单线程在高并发下计算密集命令会阻塞所有请求，所以大 key、慢命令要治理；为什么缓存一致性难，因为缓存与数据库是两个存储，双写必然有窗口"——区分"懂"与"真懂"的分界线）。练习方法：对项目里每个技术点问自己"三层答得了吗"——答不了第三层的点，要么补课要么删掉（见第 7 节）。2026 年的加分表达是"**推演过程**"——不只是背结论，而是讲"我自己设计会考虑什么"（"如果让我设计 ConcurrentHashMap，我会先想怎么减少锁粒度……"），面试官明确表示这是区分"背出来的"与"理解出来的"的信号。

## 2. 技术选型必答追问：为什么不用别的

选型追问是项目面试的最高频问题，也是拉开差距最快的一类题。三连句式背熟：**为什么选 A？为什么不用 B？什么场景该用 B？**——"为什么用 Redis 不用 Memcached"（Redis 支持持久化与丰富数据结构，Memcached 纯缓存、多线程）；"为什么用 Kafka 不用 RabbitMQ"（吞吐量优先 + 日志回放场景 vs 灵活路由 + 低延迟）；"为什么用 MySQL 不用 MongoDB"（强事务与关系查询 vs 灵活文档模型）。答题结构："**场景 + 对比 + 结论**"——"我们的场景是商品详情高并发读（场景），Redis 有持久化与过期策略而 Memcached 纯内存会丢数据（对比），所以选 Redis（结论）"；加分动作是**补一句边界**——"如果只做临时会话缓存、对数据丢失无感，Memcached 的多线程反而更省 CPU"。注意：**"网上说它好""大家都用"是零分答案**；选型题答好了，等于主动展示"做过决策的人"而非"用过工具的人"。

## 3. 深度四件套：原理-对比-权衡-演进

任何一个技术点的深度表达，用四件套组织：**原理**（底层机制一句话——"ZSet 是跳表 + 哈希表，跳表保证有序性，哈希表保证 O(1) 查分值"）；**对比**（与替代方案的差异——"ZSet vs 普通 List + 排序"）；**权衡**（这个方案放弃了什么——"跳表 vs 红黑树：跳表实现简单、区间遍历友好，但内存占用更高"）；**演进**（换场景/换规模会怎么变——"数据量到千万级，单机跳表变瓶颈，要分片 + 多级缓存"）。套用示范（Redis 缓存）：原理（单线程事件循环 + IO 多路复用）→ 对比（vs 本地缓存：跨服务共享但多一次网络）→ 权衡（一致性难保——缓存与 DB 双写窗口）→ 演进（流量 10 倍：多级缓存 + 热 key 探测 + 缓存分层）。练习动作：对项目的 5 个核心技术点（缓存、锁、MQ、分库分表、向量检索）各写一套四件套脚本——这就是"一个点挖到底"的具体落地。

## 4. 源码级理解：读源码读什么

"读过源码"是 2026 年的高频标签，但面试官追问的是"读到什么程度"。三个层次：**接口层**（会用 API——人人都会）；**流程层**（核心流程的源码走读——"Spring 的 refresh() 十二步里 Bean 创建发生在第几步、循环依赖怎么用三级缓存解"）；**设计层**（为什么这么设计——"三级缓存为什么是三级不是两级：一级是成品，二级是半成品，三级是工厂函数；只有循环依赖才需要第三级"）。读源码的性价比排序（时间有限时）：**你最常用的框架源码 > 你项目里的中间件源码 > 冷门源码**——Spring 容器/MyBatis 代理/Redis 客户端是 Java 后端的高频考点，仓库的"高级进阶与源码学习"体系有完整地图。注意：**源码细节答错了比不答更糟**——只读核心流程（创建、扩容、加锁路径）并记准版本（"JDK 17 的 HashMap 扩容逻辑"），记不准的细节主动说"这个我记不清，但流程上……"。

## 5. 性能数字纪律：数据怎么给才可信

项目里带性能数字是高分的必要条件，但**数字必须可信、可自证**——编数字被拆穿 = 全盘信用崩塌。三条纪律：**数字要有测量方式**（"QPS 3000"要能接"JMeter 1000 并发压测 3 台 4C8G 服务，持续 5 分钟，P99 120ms"——面试官一追问测量方式，编的数字就露馅）；**给对比不给绝对值**（"P99 从 2.1s 优化到 0.4s"比"P99 0.4s"可信且更有故事性——对比本身说明了你的优化动作）；**给量级不给精确**（没测过的指标说"数量级上大概……，我们没有精确测量"，比编一个"98.7%"安全得多——诚实 + 量级判断同样是能力的体现）。数字的来源要真实：压测报告、监控截图、日志统计都可以作为"证据"——把这些证据留存在项目文件夹里，面试前翻一遍就是最好的准备。

## 6. 深度准备的优先序：从高频到低频

时间有限时，深度准备按"面试命中率"排序：**第一梯队（必问）**：MySQL（索引/事务/MVCC/锁/SQL 优化）、Redis（缓存三问/持久化/分布式锁）、并发（线程池/锁/并发容器）——这是大厂项目面试的"三连杀"，参考阶段一 05/06/03 篇与仓库对应体系；**第二梯队（高频）**：MQ（选型/可靠性/幂等/积压）、Spring（IOC/AOP/事务/循环依赖）、分布式（分布式事务/ID/CAP）；**第三梯队（加分）**：AI 工程（RAG 链路/评估/降本）、JVM（GC/调优/排查）、云原生（Docker/K8s/CI-CD）。每个梯队只需把"项目里用到的点"挖到四件套深度，**不用的点不挖**——面试官只追问你简历上写的；简历是深度的地图，写得越聚焦越容易准备充分。

## 7. 讲不深的技术点：删掉或降级

简历与项目讲解的原则：**写上去的每个点都必须能扛三层追问**。处理讲不深的点的两个动作：**删掉**（"了解 Docker"如果不准备 Docker 的追问链，就删掉或降级为"使用过 Docker Compose 部署"）；**降级**（"熟悉 Kafka"降级为"用过 Kafka 做订单异步，消息可靠性由生产者重试 + 消费者幂等保证"——降级后的描述精确对应你真实的深度，追问链自然成立）。自检方法：把简历的"技能"与"项目技术点"两栏拉一个清单，每个点用第 1 节的"三层自测"过一遍——**过不了的要么补课（回到仓库对应知识体系）要么降级/删除**。这个动作的收益双份：简历更可信（每句话可自证），面试更轻松（问的都是有准备的）。

## 8. 高频面试题与追问预案

### 基础概念档（30-60 秒作答）

| # | 题目 | 答题要点 |
|---|------|----------|
| 1 | 怎么判断一个技术点懂多深？ | 三层：是什么-怎么工作-权衡边界 / 答不到第三层就是不懂 |
| 2 | 选型问题怎么答？ | 场景 + 对比 + 结论 + 边界（为什么用 A、为什么不用 B、什么场景用 B） |
| 3 | 深度四件套是什么？ | 原理-对比-权衡-演进 / 每个核心点写一套脚本 |
| 4 | 性能数字怎么给才可信？ | 带测量方式 / 给对比不给绝对值 / 没测过给量级不编数字 |

### 工程实践档（"我遇到过 → 怎么定位 → 怎么修"）

| # | 题目 | 答题要点 |
|---|------|----------|
| 5 | 面试官追问到源码层？ | 背熟核心流程 + 记准版本 / 记不准说"记不清但流程上" |
| 6 | 简历技术点太多准备不过来？ | 聚焦项目用到的点 / 用不上的删掉或降级 / 深度优先于广度 |
| 7 | 被问"你自己会怎么设计"？ | 推演过程：先想需求与边界 → 再给方案 → 最后说取舍（这是 2026 高分信号） |

### 架构设计档

| # | 题目 | 答题要点 + 追问点 |
|---|------|------------------|
| 8 | 项目里最体现深度的设计是哪个？ | 选一个能讲 5 分钟的点：背景-方案-权衡-演进；追问"换一种方案行不行" |
| 9 | 深挖时暴露了知识盲区怎么办？ | 诚实 + 原理兜底 + 补一句"我之后会去补"；追问"哪些盲区可以现场推演" |

### 追问速查

挑 3 条背熟：三级缓存为什么是三级（一级成品/二级半成品/三级工厂，只有循环依赖用到第三级）；"背结论"与"理解"的区分信号（能否讲推演过程与边界）；数字自证的三要素（测量工具-环境-时长）。

> 🎯 **核心要点**：深度题满分答案 = 三层定位 + 四件套脚本 + 一个自证数字。如"Redis 缓存能讲三层（定位）→ 原理-对比-权衡-演进四件套（脚本）→ 'P99 从 2.1s 到 0.4s，JMeter 1000 并发压测 3 台 4C8G'（自证）"。四件套与"删不掉就补课"的自检纪律是本模块背诵重点。
