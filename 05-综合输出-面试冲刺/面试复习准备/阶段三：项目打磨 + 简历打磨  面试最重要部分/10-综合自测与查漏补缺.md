## 1. 限时自测：项目面试 30 题通关卷

自测方法：每题 60 秒内口述要点，**项目题的标准是"必须回到自己的项目作答"**——答不出就回炉对应模块。**通用档（1-8 题，任何项目必问）**：

1. 先介绍一下你的项目？（开场 60 秒：痛点 → 架构 → 成果）
2. 项目里最体现你能力的点是哪个？（深度四件套展开 5 分钟）
3. 为什么选这个技术栈？为什么不用别的？（选型三连）
4. 项目遇到的最大难点？怎么定位怎么解决？（四段式）
5. 项目的量化结果是什么？指标怎么测出来的？（数据自证）
6. 如果流量涨十倍/数据量涨百倍怎么演进？（系统设计迁移）
7. 如果重做这个项目，你会改哪里？（反思信号）
8. 这个项目你个人负责的部分是什么？（ownership 边界）

**高并发档（9-18 题，有交易/并发场景必问）**：

9. 缓存穿透、击穿、雪崩各自怎么防？（三问防线）
10. 缓存和数据库一致性怎么保证？（双写 + 对账）
11. 分布式锁怎么做？锁过期怎么办？（SET NX EX + 看门狗）
12. 限流算法有哪些？你用的哪个？（令牌桶等）
13. 怎么防超卖？（Redis 预扣 + DB 兜底 + 幂等）
14. 接口幂等怎么设计？（唯一键/状态机/去重表）
15. 压测怎么做的？瓶颈在哪？（环境 + 指标 + 归因）
16. 消息积压了怎么办？（扩容分区/消费提速/降级）
17. 大促降级策略怎么设计？（保核心 + 演练）
18. 数据库慢查询怎么排查？（慢日志 + EXPLAIN + 索引）

**AI 档（19-26 题，有 AI 项目必问）**：

19. 为什么用 RAG 不用直接问模型？（时效/隐私/成本/溯源）
20. 数据流转完整链路讲一遍？（解析→分块→向量→检索→生成）
21. 分块大小怎么定的？检索不准怎么排查？（512 token / 两类归因）
22. 知识库权限隔离怎么做？（namespace + RBAC + 检索层过滤）
23. 幻觉怎么防？（RAG 接地 + 拒答 + faithfulness 门禁）
24. 怎么评估 AI 应用？（Golden Set + RAGAS + CI 门禁）
25. Agent 工具调用怎么保证可控？（权限最小化 + 二次确认 + 审计）
26. token 成本怎么降？（Prompt Caching/模型分层/缓存）

**简历档（27-30 题，对照自己的简历）**：

27. 简历上有没有毒药词？（熟练掌握/负责/全栈）
28. 每条经历是否有量化结果且可自证？（测量方式）
29. 技术栈与项目经历是否一致？（叙事一致性）
30. 简历每个技术点能扛三层追问吗？（追问链自测）

评分标准：通用档 ≥2 题说不出 → 回炉 01-05 篇；高并发档 ≥2 题 → 回炉 06-07 篇；AI 档 ≥2 题 → 回炉 08 篇 + 阶段二 04-07 篇；简历档任何一题不过 → 先改简历再投递。

## 2. 项目讲解脚本模板：10 分钟故事线

每个项目写一张"讲解脚本卡"，10 分钟时间轴：**0-1 分钟：开场定位**（一句话痛点 + 一句话方案 + 一句成果——"人工客服 60% 精力在重复咨询，我基于大模型做了 RAG 智能客服，把自动解决率从 30% 提到 55%"）；**1-3 分钟：架构总览**（数据流/系统拓扑一句话讲清——"文档 → 分块向量 → 检索重排 → 生成"或"限流 → 缓存 → 异步 → 锁"，画不出来就是没想清）；**3-7 分钟：两个技术决策深潜**（选最有故事的两个点，各 2 分钟：背景 → 方案 → 权衡 → 数据——"混合检索：向量 + BM25 + RRF，Recall@5 0.42→0.68"）；**7-9 分钟：一个难点故事**（四段式，定位过程讲 40%）；**9-10 分钟：数据与收尾**（北极星指标 + 复盘沉淀 + 下一步规划）。**每个项目准备三版**：15 秒版（面试开场与电梯介绍）、3 分钟版（HR 面/主管面）、10 分钟版（技术面主体）——三版共用同一套骨架，只是裁剪深度。演练方法：对着录音讲三遍，听回放改掉"嗯啊"与超时；再让朋友扮演面试官按第 1 节的 30 题追问——**"被追着问还能答顺"才是真过关**。

## 3. 简历自检清单：逐句过审

投递前逐句自检，八项全过才提交：**① 毒药词清零**（熟练掌握/负责/全栈——换强动词 + 结果）；**② 每句有量化**（有基线有结果有对比，没有可靠数字写范围不编造）；**③ 每句可自证**（数字能说测量方式、方案能说选型理由）；**④ 技术点扛三层追问**（答不出第三层的删或降级）；**⑤ 叙事一致**（技术栈与项目经历互相印证、时间线连续）；**⑥ 个人边界清晰**（团队项目写清"主导 XX 模块/独立实现"）；**⑦ ATS 友好**（标准标题、无表格色块、文字层 PDF、1 页）；**⑧ 一岗一版**（按目标 JD 做关键词替换与经历重排）。自检三问（第 9 篇已给，投递前重过一遍）：去掉这句话 HR 的判断会变吗？20 秒能读懂做了什么与结果吗？数字经得起追问吗？**投递节奏建议**：母版简历 → 按岗位出第一版 → 投 3-5 家试水 → 根据面试反馈（"面试官问了简历哪一块"）迭代第二版——**简历是活的，跟着面试反馈每轮优化**。

## 4. 高频错误说法 vs 正确说法

| # | 错误说法（扣分） | 正确说法（加分） |
|---|-----------------|------------------|
| 1 | "项目用了 Redis、Kafka、Seata……" | "高并发链路：限流 → 缓存 → 异步 → 锁，每个组件职责讲清" |
| 2 | "老板让我做的" | "我发现 XX 痛点，提议用 XX 解决，目标是 XX 指标" |
| 3 | "项目比较顺利没遇到难点" | 讲定位过程（监控-复现-二分），"一开始怀疑 X 后来发现是 Y" |
| 4 | "实现了文档上传、向量检索、对话生成" | "混合检索 Recall@5 0.42→0.68，为什么：语义+精确互补" |
| 5 | "熟练掌握 Java" | "熟悉 Java（能讲 JVM 内存模型与 GC 调优）" |
| 6 | "QPS 3000"（说不出怎么测的） | "JMeter 1000 并发压测 3 台 4C8G，峰值 QPS 3000" |
| 7 | "我有 50 万用户"（来源说不清） | 真实规模 + 问题密度代替规模虚报 |
| 8 | "这个 bug 不怪我" | 复盘学到什么（根因挖到规范层 + 沉淀） |
| 9 | "RAG 检索不到就调大 TopK" | 两类归因：分块/向量问题 vs 重排问题，分开优化 |
| 10 | "全栈开发"（应届） | 写清前后端各自的深度边界，主次分明 |

## 5. 薄弱点清单与回炉路线

自测后的回炉按"命中率 × 当前项目匹配度"排序：**第一优先**：通用档四题（自我介绍/最体现能力的点/最大难点/量化结果）——这四题是**每次面试必问**，必须练到脱稿流畅；**第二优先**：项目匹配的专项档（高并发项目补缓存三问与压测、AI 项目补数据链路与三件套）；**第三优先**：简历档——简历是自测的入口，简历上任何答不出的点 = 简历改完再投。回炉方法：**通用档用"讲解脚本卡"练口述**（三版各讲三遍）；**专项档回仓库深体系补课**（MySQL/Redis/MQ 体系、阶段二 AI 体系）再回来自测；**简历档直接改简历**——改完再自测一遍（简历改一次 = 复习一次）。注意：**阶段三的回炉不是"再背一遍"，是"把知识焊进自己的项目"**——每个薄弱点都要问一句"我的项目里对应的点怎么答"。

## 6. 带进阶段四：模拟面试的剧本

阶段三的产出即阶段四的剧本，三份文件随身带：**① 讲解脚本卡**（每个项目的 15 秒/3 分钟/10 分钟三版故事线）；**② 追问链答案卡**（30 题通关卷里每个项目对应的追问链答案——按四段式写全，模拟面试直接抽查）；**③ 一版简历**（已过八项自检 + 按目标岗位微调）。阶段四（模拟面试）的用法：**模拟面试 = 剧本演练 + 剧本迭代**——每次模拟后把"没答好的问题"补进追问链答案卡，把"面试官追问的点"反映进简历微调；三轮模拟后，剧本会变成"几乎无死角"的版本。冲刺纪律：**宁可少一个项目的花哨亮点，也要把主项目的 10 分钟故事线练到倒背如流**——面试官 80% 的时间花在第一个项目上，主项目的流畅度决定 80% 的分数。

> 🎯 **核心要点**：阶段三的检验标准是"项目能讲 + 简历能过"——30 题通关卷过一遍找出薄弱模块，讲解脚本卡把故事练到脱稿，简历八项自检逐句过审。带着"主项目 10 分钟倒背如流 + 一版可自证简历"进入阶段四，模拟面试就是验收而不是备考。
