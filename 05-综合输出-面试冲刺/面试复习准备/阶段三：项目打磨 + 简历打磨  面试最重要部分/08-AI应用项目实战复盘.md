## 1. AI 项目的考察定位：双线覆盖

AI 应用项目在 2026 年的价值：**一条项目同时覆盖两条考察线**——后端工程线（文档解析、分块、向量库、检索接口、鉴权、审计、性能）与 AI 能力线（RAG、Agent、评估、降本、安全），面试官"问什么都有的接"。考察的三个重点视角（都是后端视角不是算法视角）：**可控**（模型只负责生成，所有真实操作由后端接管校验——工具注册、参数校验、调用失败处理、多步骤编排）；**可拦截**（幻觉、越权、注入的防线——拒答机制、权限隔离、内容过滤）；**可溯源**（每次回答的检索来源、工具调用序列、token 成本都可追溯）。面试官的经典开场问："讲一下你的 AI 项目"，你的应答骨架：**一句话业务定位（痛点）→ 系统架构（数据流）→ 2-3 个技术决策（选型权衡）→ 评估数据（指标）→ 迭代规划（闭环）**——这个骨架本模块逐段展开。

## 2. 项目四要素：描述-个人工作-难点-收获

AI 项目（以及所有项目）的经历写法四要素，每条都要能展开讲 20 分钟：**项目描述**——一句话 + 业务场景 + 核心能力："基于 RAG 架构的企业知识库问答系统，面向 10 万+ 内部员工的知识检索场景，实现文档自动解析、语义检索与智能生成"——**常见坑：只写技术不写场景、把功能列表当描述**；**个人工作**——每条都是"技术决策 + 量化结果"而不是操作步骤："选用 Milvus 做向量存储，HNSW 索引检索延迟 <50ms"、"设计向量 + BM25 混合检索策略，准确率从 72% 提升至 91%"——**坑：写"使用 Milvus 存储向量"（无决策无结果）**；**难点**——检索不准、幻觉、权限隔离、成本失控四选一，按阶段三 05 篇的四段式讲；**收获**——方法论沉淀："沉淀了 200 条 Golden Set 与评估流程"、"把 Prompt 变成可版本化的配置"。自检标准：**每一句都能展开 20 分钟，能才留下，不能就删**。

## 3. RAG 数据流转：一条链路讲到底

讲 RAG 项目最值钱的是一条完整的数据流转链（面试官听的就是你懂不懂全链路）：**文档上传 → 解析（Apache Tika/MinerU 多格式解析 PDF/Word/Excel 10+ 种）→ 分块（语义分块，512 tokens/块、50 tokens 重叠——为什么：太长噪声大、太短语义断，重叠防边界截断）→ 向量化（BGE-M3，1024 维，入库查询同模型——不同模型向量空间不同）→ 存储（Milvus，HNSW 索引 + 元数据）→ 检索（用户问题向量化 → 混合检索：稠密向量 + BM25 + 元数据过滤 → RRF 融合 → Cross-Encoder 重排，TopK 5-8 进上下文）→ 生成（Prompt 拼装：系统提示词 + 检索片段 + 引用溯源 → 大模型生成 → 输出护栏与脱敏）**。每条都要能接追问："分块大小为什么 512"（甜点区权衡）、"检索为什么用混合检索"（稠密懂语义、BM25 精确匹配、RRF 无参融合）、"重排为什么单独做"（双塔快而粗、Cross-Encoder 准而慢，两级配合）。这条链讲顺 + 每个环节两个追问能接 = RAG 项目的深度分到手（细节对应阶段二 05/06 篇，讲不透先回去补）。

## 4. 为什么选 RAG 而不是直接问模型

AI 项目的第一个必问："为什么不用直接把文档喂给大模型/为什么不用长上下文"，答案三层：**为什么 RAG**——知识时效（业务文档每周更新，RAG 改索引即可）、隐私与合规（私有知识不出内网）、成本（每次请求只送 TopK 片段 vs 全量文档）、可溯源（答案有引用来源，可验证）；**长上下文为什么不够**——"1M 上下文解决装得下，不解决找得准与付得起"——文档库 10 亿 token 放不下、放得下也贵、百万 token 里找一条关键信息正是向量检索的活（对应阶段二 05 篇的长上下文之辩）；**边界也讲清楚**——"单文档超长场景（一份完整年报的问答）确实直接长上下文更简单，RAG 与长上下文是互补"——**讲出边界是加分动作**。追问链预备："RAG 也会答错怎么办"（答错的两类：检索没召回对的 → 优化检索；召回了但模型没引用 → 提示词约束 + faithfulness 评估门禁拦截——**分两类归因是 AI 项目最加分的表达之一**）。

## 5. 企业级三件套：隔离-权限-脱敏

"企业内部知识库怎么做权限隔离"是 2026 年 AI 面试官最爱深挖的题，三件套背熟：**多租户隔离**——方案谱系与选型："数据库 schema 隔离（中等规模）、向量 namespace/分区隔离（大多数场景，Milvus 原生支持）、独立部署（高安全大客户）——我选了 namespace 隔离，成本与隔离度平衡"；**权限模型**——"RBAC + ABAC 组合：RBAC 控角色、ABAC 控资源（密级、部门）——检索前先做文档级权限过滤，用户只能检索到有权限的文档，**权限过滤在检索层做，不在生成层做**（生成层过滤是事后补救，检索层过滤是从源头）"；**PII 脱敏**——"上传时扫描、脱敏、存储三步走；输出与日志双层脱敏（模型可能把敏感信息复述出来）"；**审计**——"全量操作日志：谁在什么时间问了什么、检索了什么、模型答了什么——合规要求与问题排查都需要"。这三件套讲全，等于向面试官证明"我做过企业级 AI，不是 demo 玩家"——2026 年面试官明确说"能说清 namespace 隔离 + RBAC + 脱敏三件套，说明有实战理解"。

## 6. 评估闭环：从指标到门禁

AI 项目讲评估是 2026 年的高分段（对应阶段二 09 篇）：**为什么必须评估**——"大模型是概率生成器，同一问题两次答案不同，传统断言测试失效，必须语义评估"；**评估体系**——Golden Set（"200 条分层：正常/边界/对抗样本，季度刷新 15%"）+ 指标（"RAGAS 四指标：faithfulness 忠实度 ≥0.9、answer relevancy ≥0.85；检索段 Recall@5、Hit@5；Agent 段工具调用成功率、任务完成率"）+ LLM-as-Judge（"注意位置/自我偏好/冗长三偏见，跨家族评判"）；**CI 门禁**——"评估进 CI：改 Prompt、检索配置、模型版本时自动跑，指标回归就阻止合并——没有门禁只有仪表盘没有流水线"；**线上闭环**——"生产 trace 喂评估集、评估集卡下一次发布，5% 流量抽样异步 judge 打分"。讲评估闭环的姿势：**先讲为什么（概率生成器）→ 再讲体系（Golden Set + 指标）→ 最后讲闭环（CI + 线上）**——三步走完，AI 项目的工程深度与阶段二知识完美咬合。

## 7. 智能客服：工作流与 Agent 的落地

如果项目是智能客服（或给知识库问答加 Agent 能力），追加讲法：**为什么工作流 + Agent 混合**——"意图识别走固定路由（确定性用工作流），复杂工单进 Agent 多轮工具调用（开放性用 Agent）——确定性与开放性分开治理"（对应阶段二 07 篇）；**工具调用闭环**——"客服要查订单、查物流、创建工单：工具列表声明 → 模型输出调用意图 → 后端校验执行 → 结果回传 → 模型续答；工具报错转结构化错误回传，模型自己调整策略；轮数上限 8-12 防死循环"；**可控性设计**——"退款类工具要二次确认 + 权限最小化（普通用户 Agent 看不到退款工具）——模型只输出意图，执行权在后端，这就是可控"；**数据**——"日均处理咨询 2000+ 次、自动解决率 55%、人工客服工作量降 60%、工具调用成功率 92%"（对应阶段二 04 篇）。追问链预备："Agent 跑偏怎么办"（轮数上限 + 关键动作确认 + 降级人工兜底）；"多轮会话的上下文怎么管"（窗口裁剪 + 摘要压缩 + 关键信息外置）。

| # | 题目 | 答题要点 + 追问点 |
|---|------|------------------|

### 追问速查

挑 3 条背熟：RAG 答错的两类归因（检索没召回 vs 模型没引用，分开优化）；权限过滤为什么在检索层（源头拦截 vs 事后补救）；AI 项目"每句能展开 20 分钟"的自检标准。

> 🎯 **核心要点**：AI 项目满分答案 = 数据流转链 + 三件套 + 评估闭环。如"文档→分块→向量→混合检索→重排→生成（链路）→ namespace 隔离 + RBAC + 脱敏（三件套）→ Golden Set + faithfulness 门禁 + 线上闭环（评估）"。数据流转链与企业级三件套是本模块背诵重点——这也是阶段二知识在项目上的完整落点。
