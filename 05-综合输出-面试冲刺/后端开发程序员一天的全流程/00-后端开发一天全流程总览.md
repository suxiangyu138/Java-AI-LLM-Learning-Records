## 3. 为什么面试要问"日常工作"？

### 3.1 面试官心理分析

很多候选人以为面试只问八股文和算法，忽略了"日常工作"类问题。实际上，几乎所有面试官都会绕开简历上的项目名称，问一些看似"软性"的问题：

> "那你平时一天都做什么？"
> "你在项目中主要负责什么？"
> "你们团队怎么协作的？"
> "遇到线上问题怎么办？"

这些问题背后，面试官真正考察的是以下三个维度：

### 3.2 三个核心考察点

**维度的"真实性验证"（60%）**

| 候选人类型 | 典型回答 | 面试官判断 |
|-----------|---------|-----------|
| 包装简历 | "我负责核心交易系统，用微服务架构……（开始背项目）" | 背书痕迹明显，缺乏细节 |
| 有真实经验 | "我们上午10点站会，我一般9点到先看邮件和线上监控，然后排今天的事……" | 有画面感，可信度高 |
| 优秀候选人 | "我觉得站会最重要的是说阻塞，我上周遇到一个XX问题……" | 有思考深度，有场景细节 |

**关键点**：面试官见过的简历比你看过的还多。**真实的细节**（几点做什么、用什么工具、怎么处理冲突）比"高大上的术语"更有说服力。

**维度二："工程化思维"（30%）**

| 观察维度 | 差的信号 | 好的信号 |
|---------|---------|---------|
| 时间管理 | "就正常上班，写代码" | 有优先级排序，有专注时段规划 |
| 工具使用 | 说不出工具名 | 能说出具体工具 + 为什么用它 |
| 协作意识 | "我就做我自己的事" | 主动举例团队协作场景 |
| 应急处理 | "没遇到过" | 有具体的事故处理经历和反思 |

**维度三："文化匹配度"（10%）**

- 你是否适应公司的开发节奏？
- 你对加班的看法？
- 你倾向于独立完成还是团队协作？

> 💡 **面试官的真实心声**：技术可以学，经验可以积累，但如果候选人没有工程化的工作习惯，或者对团队协作没有正确认知，那会是团队的风险点。所以我一定会问日常工作相关的问题来验证。

## 4. 一日时间线全景图

以下是一个**中高级后端开发**在**中型互联网公司**的标准一天。这不是一成不变的，但代表了最典型的节奏。

```text
后端开发标准一整天 · ASCII甘特图
======================================================================
时间         活动                       专注度  可被打断?  重要度
----------------------------------------------------------------------
09:00-09:30  晨间准备                   中      是          中
             · 打开IDE/终端/数据库客户端
             · 检查消息和邮件
             · 看监控大盘/Prometheus/Grafana
             · 梳理想办清单（紧急-重要矩阵）
             · 如果值班日：先过一遍线上告警

09:30-09:50  每日站会                   低      是          高
             · 昨天做了什么
             · 今天计划做什么
             · 有什么阻塞需要帮助
             · 分布式团队用飞书/Teams

09:50-10:30  需求拆解与任务评估          高      否          高
             · 读PRD → 画流程图 → 拆任务 → 估工时
             · 识别边界条件和隐含需求
             · 和产品确认疑问点
             · 分配Jira/TAPD任务

10:30-12:00  核心开发时段 ███████████   极高    否          极高
             · 拉最新代码 → 切分支 → 开始写
             · 从Controller到Service到DAO
             · 写单元测试
             · 番茄钟工作法：25+5循环
             · 中间被打断？记下来，开发完再说

12:00-13:30  午休                       低      是          低
             · 吃饭 + 散步/午休
             · 完全不看代码（让大脑重置）

13:30-15:00  编码 + 联调 ███████        高      部分        高
             · 继续上午的开发
             · 接口写好了，和前端联调
             · 用Postman/ApiFox调试
             · 查日志看报错（Kibana）
             · 遇到问题：15分钟自查 → 问AI → 问同事

15:00-16:00  Code Review + 自测        中      部分        高
             · 提交MR/PR，请同事Review
             · Review别人的代码
             · 跑SonarQube检查代码质量
             · 自测：冒烟测试 + 边界测试
             · 修复Bug → 修改 → 重新提交

16:00-17:00  会议与沟通                 低      是          中
             · 需求评审会：和产品/测试对齐
             · 技术方案评审：设计文档过会
             · 如果今天没会：继续开发

17:00-18:00  收尾与总结                 中      是          中
             · 写日报：今天做了什么、进度如何
             · 知识沉淀：把踩的坑记到Wiki或笔记
             · Git提交代码，清理本地分支
             · 看明天的任务，提前准备
             · 关IDE，下班！
======================================================================
```

> 💡 **关键洞察**：上图最值得注意的点是——**10:30-12:00 和 13:30-15:00 是两个深度专注时段**。有经验的后端开发会把"写代码"这种高认知负荷的任务安排在这两个时段，而把会议、沟通等低认知负荷任务安排在碎片时间。

## 5. 不同职级的一天差异

### 5.1 对比总览

| 维度 | 实习生 | 初级(1-3年) | 中级(3-5年) | 高级(5-8年) | 技术负责人(8年+) |
|------|--------|------------|------------|------------|----------------|
| **核心职责** | 在指导下完成开发 | 独立完成任务 | 独立完成模块 | 架构设计 + 攻坚 | 技术规划 + 团队管理 |
| **写代码占比** | 70% | 60% | 50% | 30% | 10-20% |
| **会议占比** | 5% | 10% | 20% | 35% | 50%+ |
| **Code Review** | 被Review | 被Review为主 | 互相Review | 主力Reviewer | 把控整体质量 |
| **需求来源** | 分到的Task | 小需求独立承接 | 中型需求 | 跨模块/系统需求 | 部门级技术规划 |
| **遇难题处理** | 问师兄/组长 | 先查再问 | 独立解决 | 指导他人 | 一锤定音 |
| **日常产出** | 跑通一个功能 | 完成一个接口 | 完成一个模块 | 设计一套方案 | 落地一个技术方向 |

### 5.2 具体的一天描述

**实习生的一天**

```text
09:00  到工位，打开电脑，看导师有没有留言
09:30  站会：听为主，"我跟着XX做XX模块，目前在学习XX技术"
09:50  看导师分配的任务：改一个Bug / 写一个简单接口
10:30  写代码，遇到不懂的翻项目代码 / 查Google / 问ChatGPT
12:00  吃饭
13:30  继续写，写完找导师Review
15:00  被导师指出问题，修改
16:00  改完，跑通了！成就感满满
17:00  看文档，学习项目用的技术栈（公司用的和学校学的很不一样）
18:00  下班
```

> ⚠️ **实习生存指南**：不要被动等待分配任务。主动问"有什么我可以帮忙的"，主动汇报进度，主动在Wiki上记录踩坑经验——这些都会让你的转正面评里出现"积极主动"这个词。

**中级开发的一天**

```text
09:00  到工位，开IDE+DBeaver+Terminal，看监控大盘
09:30  站会："昨天完成了订单列表接口开发，今天开始做退款流程，有一个退款幂等的问题需要和产品确认"
10:00  画退款流程时序图，琢磨幂等方案
10:30  开始写退款接口代码
12:00  吃饭前：代码写了一小半，留了个注释 `// TODO: 并发控制`
13:30  继续写，把 Redis 分布式锁加上了
15:00  提MR，同事Review发现一个边界情况没处理，改之
16:00  参加产品评审会，提了一个技术风险点（第三方支付接口有金额限制）
17:00  写日报 + 把今天踩的坑（分布式锁的key设计）记到个人笔记
17:30  看看明天要做的事
18:00  下班
```

**技术负责人的一天**

```text
09:00  到工位，先看线上大盘和告警，看有没有P0/P1事故
09:30  站会：听团队成员汇报，记录阻塞项，会后帮协调
10:00  A同事的性能优化方案评审
11:00  写技术设计文档——团队下个季度的技术规划PPT
12:00  和架构组同事吃饭，聊团队间的技术对齐
13:30  B同事遇到一个死锁问题，一起排查（DBA + 代码分析）
15:00  C同事的MR Review，重点关注架构合理性
16:00  跨部门会议：和新业务团队讨论技术对接方案
17:00  面试候选人
18:00  回复邮件，看明天日程
18:30  下班（但回家后可能还要Review紧急PR）
```

## 6. 不同公司规模的一天差异

### 6.1 初创公司（0-50人）

| 特点 | 具体表现 |
|------|---------|
| **身兼多职** | 后端也要写前端、运维、甚至测试 |
| **流程灵活** | 没有固定站会，有事在群里喊一声 |
| **决策快** | 改需求直接找创始人，拍了就改 |
| **技术栈** | SpringBoot + MySQL + Redis 三件套打天下 |
| **发布随意** | 可能没有灰度，没有回滚脚本，全靠胆大 |
| **沟通方式** | 微信群/飞书群，消息轰炸 |
| **典型一天** | 上午写接口，下午搭服务器，晚上修Bug |

### 6.2 中型互联网公司（50-500人）

| 特点 | 具体表现 |
|------|---------|
| **有流程** | 每日站会、每周迭代、双周复盘 |
| **分工明确** | 前后端分离，有测试团队 |
| **持续集成** | Jenkins/GitLab CI自动化构建部署 |
| **技术栈** | Spring Cloud微服务 + Redis + MQ + ES |
| **发布规范** | 灰度发布 + 回滚机制 + 发布Checklist |
| **沟通方式** | 企业微信 + Jira + Wiki文档驱动 |
| **典型一天** | 上午写代码，下午开会Review，节奏稳定 |

### 6.3 大厂/一线互联网（5000+人）

| 特点 | 具体表现 |
|------|---------|
| **流程严谨** | 每日站会 + 周会 + 双周迭代会 + 季度OKR review |
| **螺丝钉化** | 每个领域都有专门团队（中间件、DBA、SRE、安全） |
| **工具完善** | 自研IDE插件、发布系统、监控平台、效能平台 |
| **技术栈** | 自研或深度定制框架，K8s容器化部署 |
| **发布约束** | 固定发布窗口，变更审批，变更委员会 |
| **沟通方式** | 飞书/钉钉 + 文档(语雀/Confluence) + 邮件 |
| **典型一天** | 大量时间在沟通对齐，写代码反而变成奢侈的事 |

> 💡 **面试tips**：如果你在小公司，面试大厂时不要觉得"我们公司没什么流程"。可以说"我经历过从0到1的搭建过程，对流程的必要性有深刻理解"——这就是你的优势。

## 7. 学习路线

### 路线一：面试前1天速通版

> 适合：明天就面试了，想快速了解后端日常工作的面试回答思路

```text
第1步 (15min)：快速浏览本总览文件的【3-为什么面试要问日常工作】
      → 理解面试官的考察心理
第2步 (20min)：阅读【4-一日时间线全景图】
      → 在脑海里形成一个完整的时间画面
第3步 (15min)：看【6-面试篇】的回答模板
      → 准备自己的回答话术
第4步 (10min)：回想自己的项目经历
      → 套用叙事框架，准备一个"日常工作"的1分钟回答
```

### 路线二：实习/入职前1周准备版

> 适合：拿到offer还没入职，或者正在找实习，想提前适应职场节奏

```text
第1步：系统读完本系列全部6个模块（1小时）
第2步：重点看【01-上午篇】的编码实战案例
      → 学习真实项目中的开发流程
第3步：重点看【04-工具链篇】的IDE和Git操作
      → 提前安装配置，练熟快捷键
第4步：模拟站会汇报（对着镜子说一遍）
      → "昨天我完成了XX，今天计划做XX，有一个问题需要请教"
第5步：准备几个技术场景的回答
      → "遇到线上Bug怎么处理"、"需求不清晰怎么办"
```

### 路线三：深度了解版（覆盖全部6模块）

> 适合：想要全面了解后端开发日常，为未来做准备

```text
阶段一：上午篇 + 下午篇（先了解一天的全貌）
阶段二：特殊场景篇（了解事故处理和发布的完整流程）
阶段三：工具链篇（逐个工具上手实操）
阶段四：协作篇（理解团队协作的沟通方式和原则）
阶段五：面试篇（整理自己的故事，形成回答体系）
```
