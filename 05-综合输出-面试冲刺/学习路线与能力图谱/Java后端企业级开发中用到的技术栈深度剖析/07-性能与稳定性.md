## 1. 性能指标体系

```
核心指标四件套：
  QPS/TPS：吞吐量
  P95/P99：分位延迟（长尾）
  CPU/内存/IO：资源
  错误率：5xx 占比

SLO 目标示例：
  可用性 99.9%（月故障 < 43 分钟）
  P99 < 200ms
  错误率 < 0.1%

⚠️ 面试必答：
"性能四指标——吞吐/延迟/资源/错误；
 P99 比平均值有意义（长尾即体验）。"
```

## 2. 性能优化路线

```
优化五层（由外到内）：
  ① 前端：CDN/压缩/懒加载
  ② 网络：HTTP2/Gzip/连接复用
  ③ 应用：缓存/异步/并行/线程池
  ④ 数据：索引/SQL/连接池/读写分离
  ⑤ 架构：集群/分库分表/消息削峰

⚠️ 面试必答：
"优化五层——前端/网络/应用/数据/架构；
 先监控定位瓶颈，再针对性优化
 （不要盲调参数）。"
```

## 3. JVM 与缓存调优

### 3.1 JVM 调优要点

```
JVM 调优三板斧：
  ① 堆大小：-Xms = -Xmx（物理内存 60-70%）
  ② GC 选择：G1（默认）或 ZGC（低延迟）
  ③ 参数：停顿目标 + HeapDump + GC 日志

⚠️ 面试必答：
"JVM 调优 = 监控 → 定位 → 调参；
 80% 的 JVM 问题是代码问题
 （泄漏/大对象），先查代码。"
```

### 3.2 缓存优化

```
缓存优化路径：
  单机 → Caffeine（本地）
  共享 → Redis（分布式）
  两级 → Caffeine + Redis（热点 + 共享）

⚠️ 三难防护：
  穿透（布隆过滤器/空值缓存）
  击穿（互斥锁/逻辑过期）
  雪崩（随机过期/集群）

⚠️ 面试必答：
"缓存三难三解——穿透布隆、击穿互斥、
 雪崩随机；三连问必背。"
```

## 4. 压测方法论

### 4.1 压测流程

```
压测五步：
  ① 定目标（预期 QPS/P99）
  ② 选工具（JMeter/wrk/ab）
  ③ 单接口 → 全链路
  ④ 逐步加压找拐点（吞吐不再增长 = 瓶颈）
  ⑤ 优化 → 回归

⚠️ 面试必答：
"压测核心 = 找拐点——
 吞吐不再随并发增长即瓶颈；
 瓶颈分层定位（CPU/锁/DB/GC）。"
```

### 4.2 瓶颈定位

```
瓶颈四类：
  CPU 型：计算密集 → 优化算法/并行
  锁型：竞争激烈 → 锁粒度/无锁化
  DB 型：慢 SQL/连接耗尽 → 索引/缓存
  GC 型：Full GC 频繁 → 堆/对象

⚠️ 面试必答：
"瓶颈定位 = 看四类指标——
 CPU 高查代码、锁等查线程、DB 慢查 SQL、
 GC 频查堆。"
```

## 5. 稳定性三板斧

### 5.1 限流熔断降级

```
① 限流：防超载（令牌桶/滑动窗口）
② 熔断：故障快速失败（关闭→打开→半开）
③ 降级：非核心让路（缓存/默认值）

⚠️ 面试必答：
"三板斧——限流防超载、熔断防雪崩、
 降级保核心；
 高可用系统的自我保护机制。"
```

### 5.2 防雪崩

```
雪崩链路：
  A 慢 → 线程池满 → 请求堆积 → 下游全挂

防护四件套：
  ① 超时控制（必须设）
  ② 线程池隔离（Bulkhead）
  ③ 熔断器（错误率阈值）
  ④ 队列削峰（MQ 缓冲）

⚠️ 面试必答：
"防雪崩四件套——超时/隔离/熔断/削峰；
 '慢请求占用资源'是雪崩本质。"
```

## 6. 故障排查流程

### 6.1 排查四步

```
线上故障排查流程：
  ① 告警定位（哪个服务/指标异常）
  ② 指标看全局（CPU/内存/连接/QPS）
  ③ 日志/链路定位（traceId 查详情）
  ④ 处置（回滚/扩容/限流）

⚠️ 面试必答：
"排查四步——告警 → 指标 → 日志链路 → 处置；
 处置优先控制影响（回滚/限流）。"
```

### 6.2 高频故障场景

| 场景 | 现象 | 排查 |
|------|------|------|
| 接口变慢 | P99 上升 | 慢 SQL/外部调用/GC |
| 内存飙升 | 堆占用高 | HeapDump + MAT |
| CPU 100% | 计算/死循环 | 线程 dump + jstack |
| 连接耗尽 | 连接失败 | 连接池/慢请求 |

```
⚠️ 面试必答：
"四类高频故障——慢（SQL/GC）、
 内存（泄漏）、CPU（死循环）、
 连接（池耗尽）——每类有固定排查工具。"
```

---

> 🎯 **核心要点**：性能稳定性 = **四指标**（吞吐/延迟/资源/错误）+ **五层优化**（前端到架构）+ **JVM/缓存调优**（堆/GC + 三难防护）+ **压测**（拐点定位）+ **三板斧**（限流/熔断/降级）+ **排查四步**（告警→指标→链路→处置）。"先监控后优化、先处置后定位"是性能稳定的方法论。
