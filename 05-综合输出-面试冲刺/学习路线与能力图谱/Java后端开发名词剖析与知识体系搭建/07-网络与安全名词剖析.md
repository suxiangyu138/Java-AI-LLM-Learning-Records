## 1. 网络协议栈

### 1.1 TCP/IP 四层模型

```text
┌──────────────┬──────────────────────────────┐
│   应用层      │ HTTP, HTTPS, DNS, FTP, SMTP  │
├──────────────┼──────────────────────────────┤
│   传输层      │ TCP, UDP                    │
├──────────────┼──────────────────────────────┤
│   网络层      │ IP, ICMP, ARP, OSPF         │
├──────────────┼──────────────────────────────┤
│ 网络接口层    │ Ethernet, WiFi              │
└──────────────┴──────────────────────────────┘
```

### 1.2 TCP vs UDP

| 维度 | TCP | UDP |
|------|:---:|:---:|
| **连接** | 面向连接（三次握手） | 无连接 |
| **可靠性** | 可靠交付（确认+重传） | 不保证交付 |
| **顺序** | 保证有序 | 不保证 |
| **速度** | 慢（流量控制+拥塞控制） | 快 |
| **头部开销** | 20-60 字节 | 8 字节 |
| **适用** | HTTP、文件传输、数据库 | 视频流、DNS、游戏 |

### 1.3 TCP 三次握手与四次挥手

```text
三次握手（建立连接）：
  Client → SYN=1, seq=x                        → Server
  Client ← SYN=1, ACK=1, seq=y, ack=x+1       ← Server
  Client → ACK=1, seq=x+1, ack=y+1            → Server

  为什么三次？
    → 防止已失效的连接请求到达 Server
    → 确认双方收发能力正常

四次挥手（断开连接）：
  Client → FIN=1, seq=u                        → Server
  Client ← ACK=1, seq=v, ack=u+1              ← Server (Server 可能还有数据要发)
  Client ← FIN=1, ACK=1, seq=w, ack=u+1       ← Server
  Client → ACK=1, seq=u+1, ack=w+1            → Server → TIME_WAIT(2MSL)
```

## 2. HTTP 协议

### 2.1 HTTP 版本演进

| 版本 | 连接 | 多路复用 | 头部压缩 | 服务端推送 | 现状 |
|:----:|------|:------:|:------:|:------:|:---:|
| **1.0** | 短连接（每次请求新建） | ❌ | ❌ | ❌ | 极少 |
| **1.1** | 长连接（Keep-Alive） | ❌ | ❌ | ❌ | 主流 |
| **2.0** | 单连接 | ✅ 多 Stream | ✅ HPACK | ✅ | 增长中 |
| **3.0** | QUIC(UDP) | ✅ | ✅ QPACK | ✅ | 前沿 |

### 2.2 HTTP 状态码

| 范围 | 类别 | 常见码 |
|:---:|------|--------|
| **1xx** | 信息响应 | 101 Switching Protocols (WebSocket 升级) |
| **2xx** | 成功 | 200 OK, 201 Created, 204 No Content |
| **3xx** | 重定向 | 301 永久, 302 临时, 304 Not Modified |
| **4xx** | 客户端错误 | 400 参数错误, 401 未认证, 403 无权限, 404 未找到, 429 限流 |
| **5xx** | 服务端错误 | 500 内部错误, 502 网关错误, 503 服务不可用, 504 超时 |

### 2.3 GET vs POST

| 维度 | GET | POST |
|------|:---:|:----:|
| **参数位置** | URL 查询字符串 | 请求体 |
| **长度限制** | 浏览器/服务器限制（~2KB-8KB） | 理论上无限制 |
| **安全性** | 参数暴露在 URL | 参数在请求体 |
| **缓存** | 可缓存 | 不可缓存（默认） |
| **幂等性** | 幂等 | 非幂等 |
| **书签** | 可收藏 | 不可收藏 |

## 3. HTTPS 与 TLS

### 3.1 HTTPS = HTTP + TLS

```text
TLS 握手（简化版 1.2）：

  Client → ClientHello（支持的加密套件 + 随机数1）    → Server
  Client ← ServerHello（选定的加密套件 + 随机数2+证书） ← Server
  Client → 验证证书 → 生成 Pre-Master + 公钥加密     → Server
  Client → ChangeCipherSpec（开始加密通信）           → Server

  双方各自用 随机数1+随机数2+Pre-Master → 生成会话密钥
  → 后续对称加密通信

TLS 1.3 握手：1-RTT（比 1.2 少一轮往返）
```

### 3.2 数字证书与 CA

```text
证书链验证：

  Root CA（根证书）→ 预置在操作系统/浏览器
      │ 签名
      ▼
  Intermediate CA（中间证书）
      │ 签名
      ▼
  服务器证书（如 *.example.com）

验证过程：逐级验证签名，直到信任的 Root CA
```

## 4. 认证与授权

### 4.1 Session vs Token vs JWT

| 维度 | Session + Cookie | Token (随机字符串) | JWT |
|------|:--------------:|:----------------:|:---:|
| **存储位置** | 服务端 Session | 服务端 Redis | 客户端（无状态） |
| **扩展性** | 差（共享 Session） | 好（共享 Redis） | 优（完全无状态） |
| **安全性** | 高（服务端控制） | 高 | 中（无法服务端撤销） |
| **性能** | 每次查 Session | 每次查 Redis | 本地验证（快） |
| **适合** | 单体应用 | 分布式应用 | 微服务/跨域 |

### 4.2 JWT 结构

```text
JWT = Header.Payload.Signature

  Header:   { "alg": "RS256", "typ": "JWT" }
  Payload:  { "sub": "123", "name": "John", "exp": 1700000000 }
  Signature: HMACSHA256(base64(header) + "." + base64(payload), secret)

  验证流程：
    客户端：Authorization: Bearer <JWT>
    服务端：读取 Header → 用公钥/密钥验签 → 检查 exp（过期）

  ⚠️ JWT 注意：
    → Payload 仅 Base64 编码，非加密！敏感信息不要放 Payload
    → 无法服务端主动失效（需配合黑名单 Redis）
    → Access Token 短过期（15min）+ Refresh Token 长过期（7天）
```

### 4.3 OAuth2 授权码流程

```text
OAuth2 授权码模式（PKCE 增强）：

  1. 客户端重定向 → 授权服务器
     GET /authorize?response_type=code&client_id=xxx&redirect_uri=yyy&code_challenge=zzz

  2. 用户登录 + 授权

  3. 授权服务器返回授权码
     redirect_uri?code=abc123

  4. 客户端用授权码换 Token
     POST /token { code, client_id, client_secret, code_verifier }

  5. 返回 Access Token + Refresh Token
     { "access_token": "...", "refresh_token": "...", "expires_in": 3600 }

  6. 使用 Access Token 访问资源
     GET /api/user Authorization: Bearer <access_token>
```

## 5. Web 安全攻防

### 5.1 常见攻击与防御

| 攻击 | 说明 | 防御 |
|------|------|------|
| **XSS** | 注入恶意脚本 | 输出编码、CSP、HttpOnly Cookie |
| **CSRF** | 跨站请求伪造 | CSRF Token、SameSite Cookie、Referer 校验 |
| **SQL 注入** | 拼接恶意 SQL | 参数化查询（PreparedStatement）、ORM |
| **SSRF** | 服务端请求伪造 | URL 白名单、禁止内网 IP |
| **DDoS** | 分布式拒绝服务 | CDN、WAF、限流、黑洞 |
| **点击劫持** | 透明 iframe | X-Frame-Options: DENY |
| **文件上传** | 上传恶意文件 | 类型校验、大小限制、病毒扫描、隔离存储 |

```java
// SQL 注入防御：参数化查询
String sql = "SELECT * FROM users WHERE name = ?";  // ✅ 预编译
PreparedStatement ps = conn.prepareStatement(sql);
ps.setString(1, userName);  // 参数绑定，自动转义

// ❌ 永远不要字符串拼接 SQL！
// String sql = "SELECT * FROM users WHERE name = '" + userName + "'";
```

### 5.2 CORS 跨域

```text
CORS = Cross-Origin Resource Sharing（跨域资源共享）

简单请求条件（同时满足）：
  1. 方法：GET / HEAD / POST
  2. Content-Type 仅限于：
     text/plain, multipart/form-data, application/x-www-form-urlencoded
  3. 无自定义 Header

非简单请求 → 先发 OPTIONS 预检请求（Preflight）

响应头：
  Access-Control-Allow-Origin: https://example.com (或 *)
  Access-Control-Allow-Methods: GET, POST, PUT, DELETE
  Access-Control-Allow-Headers: Content-Type, Authorization
  Access-Control-Allow-Credentials: true  (允许携带 Cookie)
  Access-Control-Max-Age: 3600  (预检缓存时间)
```

## 6. 加密算法

### 6.1 对称加密 vs 非对称加密

| 维度 | 对称加密 | 非对称加密 |
|------|---------|-----------|
| **密钥** | 1 个（共享密钥） | 2 个（公钥 + 私钥） |
| **速度** | 快（1000x+） | 慢 |
| **用途** | 数据加密 | 密钥交换、数字签名 |
| **代表算法** | AES, DES, ChaCha20 | RSA, ECC, Ed25519 |
| **密钥长度** | AES-128/256 | RSA-2048/4096, ECC-256 |

### 6.2 哈希算法

| 算法 | 输出 | 安全性 | 用途 |
|------|:--:|:----:|------|
| **MD5** | 128 bit | ❌ 已被破解 | 仅用于非安全校验 |
| **SHA-1** | 160 bit | ❌ 已被破解 | 废弃 |
| **SHA-256** | 256 bit | ✅ | 数字签名、区块链 |
| **SHA-512** | 512 bit | ✅ | 高安全场景 |
| **bcrypt** | 可调 | ✅ | 密码存储（加盐+慢哈希） |
| **Argon2** | 可调 | ✅ 最佳 | 密码存储（推荐） |

```java
// 密码存储最佳实践
// ❌ MD5("password") → 不安全！彩虹表秒破
// ❌ SHA256("password") → 不安全！可以 GPU 暴力破解

// ✅ bcrypt（Spring Security 默认）
BCryptPasswordEncoder encoder = new BCryptPasswordEncoder();
String hash = encoder.encode("password");
// $2a$10$...  → 自动包含随机盐 + 10 轮 hash 迭代
```
