## 一、Java 基础与 JVM

### Q1：HashMap 底层实现原理？JDK 1.7 和 1.8 区别？

| 版本 | 结构 | 哈希冲突 | 插入方式 | 扩容风险 |
|------|------|----------|----------|----------|
| JDK 1.7 | 数组+链表 | 链地址法 | 头插法 | 链表循环（线程不安全） |
| JDK 1.8 | 数组+链表+红黑树（链表>8 且数组≥64） | 链地址法 | 尾插法 | 优化扩容机制 |

> 初始容量 16，负载因子 0.75，扩容翻倍。HashMap 线程不安全，多线程用 ConcurrentHashMap。

### Q2：JVM 内存模型？

| 区域 | 存储 | 线程 | 异常 |
|------|------|:--:|------|
| **堆** | 对象实例、数组 | 共享 | OOM |
| **虚拟机栈** | 栈帧（局部变量表/操作数栈） | 私有 | StackOverflow/OOM |
| **方法区** | 类信息、常量、静态变量（JDK 8+ 元空间） | 共享 | OOM |
| 程序计数器 | 字节码行号 | 私有 | ❌ |

### Q3：GC 算法？CMS 和 G1 区别？

| 收集器 | 目标 | 优点 | 缺点 |
|--------|------|------|------|
| **CMS** | 低延迟 | 并发执行、响应快 | 内存碎片、CPU 高、浮动垃圾 |
| **G1** | 兼顾吞吐+延迟 | 无碎片、可预测延迟 | 复杂度高、适合大堆（8G+） |

### Q4：volatile 能保证原子性吗？

- ✅ 保证**可见性**（修改立即刷新主内存）+ **禁止指令重排**（内存屏障）
- ❌ 不保证原子性（如 `i++` 分三步：读→算→写），需用 `synchronized` 或 `AtomicInteger`

### Q5：线程池核心参数？

```text
corePoolSize → 队列 → maximumPoolSize → 拒绝策略
```

| 任务类型 | 线程数公式 |
|----------|-----------|
| CPU 密集型 | CPU 核数 + 1 |
| IO 密集型 | CPU 核数 × 2 |

## 二、后端框架

### Q1：Spring IOC 原理？Bean 生命周期？

```text
实例化 → 依赖注入 → BeanPostProcessor#before → @PostConstruct → InitializingBean
→ BeanPostProcessor#after → 使用 → @PreDestroy → DisposableBean → 销毁
```

### Q2：AOP 动态代理两种方式？

| 方式 | 前提 | 原理 | 限制 |
|------|------|------|------|
| JDK 动态代理 | 实现接口 | 生成接口代理对象 | 不能增强非接口方法 |
| CGLIB | 无要求 | 生成目标类子类 | 不能增强 final 方法 |

### Q3：Spring Boot 自动配置原理？

```text
@EnableAutoConfiguration → @Import(AutoConfigurationImportSelector)
→ 读取 META-INF/spring/...AutoConfiguration.imports
→ @ConditionalOnClass / @ConditionalOnMissingBean 判断 → 自动注册 Bean
```

### Q4：MyBatis 一级/二级缓存？

| 缓存 | 作用域 | 默认 | 失效条件 |
|------|--------|:--:|----------|
| 一级 | SqlSession | ✅ | 关闭 Session / 执行增删改 / clearCache |
| 二级 | Mapper | ❌ | 执行增删改 / 对象未序列化 |

### Q5：Spring Cloud 核心组件？

| 组件 | 作用 |
|------|------|
| Nacos | 注册中心 + 配置中心 |
| Feign | 声明式远程调用（集成 Ribbon 负载均衡） |
| Sentinel | 限流、熔断、降级 |
| Gateway | 统一入口、路由转发 |
| Seata | 分布式事务 |

## 三、中间件

### Q1：Redis 持久化 RDB vs AOF？

| 维度 | RDB | AOF |
|------|-----|-----|
| 原理 | 定时全量快照 | 每条写命令追加日志 |
| 优点 | 体积小、恢复快 | 数据安全性高 |
| 缺点 | 可能丢失快照后数据 | 文件大、恢复慢 |

### Q2：缓存穿透/击穿/雪崩？

| 问题 | 定义 | 解决方案 |
|------|------|----------|
| **穿透** | 查不存在的数据 | 缓存空值 + 布隆过滤器 |
| **击穿** | 热点 key 过期 | 永不过期 / 互斥锁 / 预热 |
| **雪崩** | 大量 key 同时过期 | 随机过期时间 + 集群 + 降级 |

### Q3：MQ 消息可靠性？

| 环节 | 保障 |
|------|------|
| **生产者** | 确认机制（Confirm）+ 失败重试 |
| **Broker** | 持久化 + 集群副本 |
| **消费者** | 手动 ACK + 幂等（唯一 ID 去重） |

## 四、数据库

### Q1：聚簇索引 vs 非聚簇索引？

| 维度 | 聚簇索引 | 非聚簇索引 |
|------|----------|-----------|
| 叶子节点 | 数据本身 | 主键值（需回表） |
| 数量 | 1 个 | 多个 |
| 查询 | 一次到位 | 两次（索引→主键→数据） |

### Q2：事务隔离级别？

| 级别 | 脏读 | 不可重复读 | 幻读 |
|:--|:--:|:-----:|:--:|
| Read Uncommitted | ✅ | ✅ | ✅ |
| Read Committed | ❌ | ✅ | ✅ |
| **Repeatable Read**（MySQL 默认） | ❌ | ❌ | ✅（MVCC 解决） |
| Serializable | ❌ | ❌ | ❌ |

### Q3：SQL 优化常用方法？

| 维度 | 方法 |
|------|------|
| **索引** | WHERE/JOIN/ORDER BY 列建索引，避免函数/!=/NOT IN 致失效 |
| **语句** | JOIN 替代子查询，避免 SELECT *，批量操作，EXPLAIN 分析 |
| **表结构** | 合适数据类型，分库分表，读写分离 |

## 五、工程化与 DevOps

### Q1：CI/CD 核心概念？

| 概念 | 说明 |
|------|------|
| **CI**（持续集成） | 代码提交→自动编译+测试+代码扫描 |
| **CD**（持续交付） | CI 通过→自动部署到测试/预发，手动发布生产 |
| **CD**（持续部署） | 全自动发布到生产 |

### Q2：Docker vs 虚拟机？

| 维度 | Docker | 虚拟机 |
|------|--------|--------|
| 架构 | 共享宿主机内核，进程级隔离 | 独立 OS 内核，系统级隔离 |
| 资源 | 轻量，秒级启动 | 重量，分钟级启动 |
| 部署 | 一次构建到处运行 | 环境迁移成本高 |
| 适用 | 微服务、高频迭代 | 强隔离、不同 OS |
