### Q1：Vue3 的 Composition API 和 Options API 有什么区别？你在项目中为什么选 Composition API？

**面试官意图：** 考察对 Vue3 核心特性的理解和实战选型经验。

**完美解答：**

| 维度 | Options API | Composition API |
|------|-------------|-----------------|
| 代码组织 | 按选项类型（data/methods/computed） | 按功能逻辑（自定义组合函数） |
| 逻辑复用 | mixins（有命名冲突风险） | composables（无冲突，显式导入） |
| TypeScript 支持 | 有限 | 原生支持，类型推导友好 |
| Tree-shaking | 不好（未使用的选项难移除） | 好（按需导入） |
| 学习曲线 | 平缓 | 稍陡峭 |
| 大型项目维护 | 逻辑分散在各选项中，难维护 | 相关逻辑集中，高内聚 |

**实战对比：**

```vue
<!-- Options API 写法：相关逻辑被拆散 -->
<script>
export default {
  data() {
    return {
      userList: [],
      loading: false,
      searchForm: { name: '', status: '' }
    }
  },
  methods: {
    async fetchUsers() { /* ... */ },
    handleSearch() { /* ... */ },
    handleReset() { /* ... */ }
  },
  computed: {
    filteredUsers() { /* ... */ }
  },
  watch: {
    searchForm: { /* ... */ }
  }
}
</script>

<!-- Composition API 写法：相关逻辑在一起，可提取复用 -->
<script setup>
import { useUserList } from '@/composables/useUserList'
import { useSearch } from '@/composables/useSearch'

const { userList, loading, fetchUsers } = useUserList()
const { searchForm, filteredUsers, handleSearch, handleReset } = useSearch()
// 逻辑按功能组织，而不是按选项类型
</script>
```

**延伸追问应对：** 如果面试官问"Composition API 有什么缺点"，回答（1）学习曲线更陡，新手容易把 `ref`/`reactive`/`computed` 搞混；（2）如果组织不好，反而比 Options API 更混乱，所以需要 `composables` 的良好设计。

### Q2：Vue3 的响应式原理是什么？和 Vue2 相比有什么改进？

**面试官意图：** 考察框架原理深度，而不只是会用。

**完美解答：**

**Vue2 响应式（Object.defineProperty）：**
```javascript
// Vue2 通过 Object.defineProperty 拦截属性的 get/set
Object.defineProperty(data, 'key', {
  get() { /* 收集依赖 */ },
  set(newVal) { /* 触发更新 */ }
})

// 缺陷：
// 1. 无法检测新增属性（需要 Vue.set）
// 2. 无法检测数组索引/长度变化（需要重写数组方法）
// 3. 递归遍历所有属性，性能开销大
```

**Vue3 响应式（Proxy）：**
```javascript
// Vue3 使用 Proxy 代理整个对象
const proxy = new Proxy(data, {
  get(target, key) {
    track(target, key)  // 依赖收集
    return Reflect.get(target, key)
  },
  set(target, key, value) {
    const result = Reflect.set(target, key, value)
    trigger(target, key)  // 触发更新
    return result
  },
  deleteProperty(target, key) {
    const result = Reflect.deleteProperty(target, key)
    trigger(target, key)
    return result
  }
})

// 优势：
// 1. 可以检测新增/删除属性
// 2. 可以检测数组索引/长度变化
// 3. 惰性代理——只有访问到深层属性时才代理，性能更好
// 4. 拦截操作更多（deleteProperty、has 等 13 种）
```

**ref 和 reactive 的区别：**
```javascript
// ref：用于基本类型，底层还是用对象包裹
const count = ref(0)
// 编译后：const count = { value: 0 }

// reactive：用于对象类型，直接用 Proxy
const user = reactive({ name: '张三', age: 25 })

// 注意：reactive 不能直接替换整个对象
// ❌ user = reactive({ name: '李四' })  // 丢失响应式
// ✅ Object.assign(user, { name: '李四' })
```

> 🎯 **面试关键**：能讲出 Proxy 和 Object.defineProperty 的 3 个以上区别，说明真的读懂了 Vue3 源码级别的原理。

### Q3：什么是 SSE（Server-Sent Events）？它在 AI 对话场景中怎么用？

**面试官意图：** 考察对 AI 应用前端交互核心技术的理解。

**完美解答：**

**SSE 核心概念：**
SSE（Server-Sent Events）是一种服务端向客户端单向推送数据的技术。与 WebSocket 不同，它是**基于 HTTP 的、服务端到客户端的单向通道**。

**为什么 AI 对话要用 SSE 而不是普通 HTTP 请求？**

| 方案 | AI 对话场景的问题 | 结论 |
|------|------------------|------|
| 普通 POST | 等 LLM 生成完整响应才返回（10-30 秒），用户干等 | 体验差 |
| WebSocket | 全双工通道，功能过剩；需要额外协议升级 | 大材小用 |
| SSE | 天然支持流式文本、浏览器原生 `EventSource` 支持 | **最佳选择** |

**前端实现：**
```vue
<script setup>
import { ref } from 'vue'

const messages = ref([])
const inputText = ref('')
const isLoading = ref(false)

async function sendMessage() {
  const question = inputText.value
  messages.value.push({ role: 'user', content: question })
  inputText.value = ''
  isLoading.value = true
  
  // 方法 1：使用 Fetch API 读取流（推荐，兼容性更好）
  const response = await fetch('http://localhost:8080/api/chat/stream', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ question })
  })
  
  const reader = response.body.getReader()
  const decoder = new TextDecoder()
  let aiMessage = { role: 'assistant', content: '' }
  messages.value.push(aiMessage)
  
  while (true) {
    const { done, value } = await reader.read()
    if (done) break
    
    const text = decoder.decode(value)
    // 解析 SSE 格式：data: {...}\n\n
    const lines = text.split('\n').filter(line => line.startsWith('data: '))
    for (const line of lines) {
      const data = line.slice(6)
      if (data === '[DONE]') break
      const parsed = JSON.parse(data)
      aiMessage.content += parsed.content
    }
  }
  
  isLoading.value = false
}

// 方法 2：使用 EventSource（只能 GET，不能自定义 Header）
// function useEventSource() {

//   source.onmessage = (event) => {
//     if (event.data === '[DONE]') {
//       source.close()
//       return
//     }
//     aiMessage.content += JSON.parse(event.data).content
//   }
// }
</script>
```

```javascript
// 登录后从后端获取用户权限，动态添加路由
function filterRoutes(routes, permissions) {

      return route.meta.permissions.some(p => permissions.includes(p))

    return true
```

```vue
<script setup>
import { ref, watch } from 'vue'

const displayContent = ref('')
const isTyping = ref(false)
let typeTimer = null

// 流式输出过程中，每隔 30ms 显示一个字
function startTyping(fullContent) {
  isTyping.value = true
  displayContent.value = ''
  let index = 0
  
  typeTimer = setInterval(() => {
    if (index < fullContent.length) {
      displayContent.value += fullContent[index]
      index++
      // 滚动到底部
      scrollToBottom()
    } else {
      clearInterval(typeTimer)
      isTyping.value = false
    }
  }, 30)
}

// 如果用户点击"跳过动画"，直接显示全部内容
function skipTyping() {
  clearInterval(typeTimer)
  displayContent.value = fullContent.value
  isTyping.value = false
}

// 组件卸载时清理定时器
onUnmounted(() => {
  clearInterval(typeTimer)
})
</script>
```

### Q7：如果让你从零搭建一个企业级前端项目，你会选哪些技术栈？为什么？

**面试官意图：** 考察技术选型的判断力和架构能力。

**完美解答：**

**我的选型策略：** 不是"用最新的"，而是"选最合适的"。

```yaml
# 企业级前端项目技术栈

构建工具:
  选择: Vite
  原因: 
    - 开发服务器启动 < 1s（Webpack 需要 10-30s）
    - HMR 热更新毫秒级
    - 生态成熟，Vue 官方推荐
  不选 Webpack: 开发体验太差，新项目没必要

框架:
  选择: Vue 3 + Composition API
  原因:
    - 我的后端主力，全栈统一
    - 学习曲线比 React 平缓
    - 中文生态好，Element Plus 成熟
  不选 React: 如果是纯前端团队我可能选 React，但全栈角度 Vue 更适合

语言:
  选择: TypeScript (严格模式)
  原因:
    - 类型安全，减少 40% 运行时错误
    - 代码可读性/可维护性提升
    - 大型项目重构有保障
  不选 JS: 项目 > 50 个组件时，没有类型系统就是灾难

状态管理:
  选择: Pinia
  原因:
    - 比 Vuex 更简洁（去掉 mutations）
    - 完整 TypeScript 支持
    - 模块化设计，按需加载

UI 库:
  选择: Element Plus + Tailwind CSS
  原因:
    - Element Plus：后台管理标配，表格/表单/弹窗开箱即用
    - Tailwind CSS：原子化样式，定制灵活，避免 CSS 命名冲突

请求库:
```

### Q8：前后端分离项目中，前端怎么处理跨域问题？你有几种方案？

**面试官意图：** 考察全栈开发中的网络工程经验和问题解决能力。

**完美解答：**

跨域问题有 4 种主流方案，我按推荐度排序：

**方案 1：Nginx 反向代理（生产环境推荐）**
```nginx
# nginx.conf — 最佳方案，前端后端都在同一域名下
server {
    listen 80;
    server_name www.example.com;
    
    # 前端静态资源
    location / {
        root /opt/app/web;
        index index.html;
        try_files $uri $uri/ /index.html;
    }
    
    # 后端 API 代理
    location /api/ {
        proxy_pass http://localhost:8080/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
    
    # WebSocket / SSE 支持
    location /ws/ {
        proxy_pass http://localhost:8080/ws/;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```
**优点**：真正的跨域解决——变成同域访问，没有跨域问题

**方案 2：CORS 后端配置（开发环境 + 简单场景）**
```java
// Spring Boot CORS 配置
@Configuration
public class CorsConfig {
    
    @Bean
    public WebMvcConfigurer corsConfigurer() {
        return new WebMvcConfigurer() {
            @Override
            public void addCorsMappings(CorsRegistry registry) {
                registry.addMapping("/api/**")
                    .allowedOriginPatterns("*")  // 生产环境要限定域名
                    .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
                    .allowedHeaders("*")
                    .allowCredentials(true)
                    .maxAge(3600);  // 预检请求缓存 1 小时
            }
        };
    }
}
```

**方案 3：Vite 开发代理（开发环境）**
```javascript
// vite.config.js
export default defineConfig({
  server: {
    proxy: {
      '/api': {
        target: 'http://localhost:8080',
        changeOrigin: true,
        // WebSocket 代理
        ws: true
      }
    }
  }
})
```

**方案对比：**
| 方案 | 场景 | 优点 | 缺点 |
|------|------|------|------|
| Nginx 代理 | 生产 | 最彻底，同域访问 | 需要 Nginx 配置 |
| CORS | 开发/简单应用 | 后端配置一次即可 | 携带 Cookie 复杂 |
| Vite Proxy | 本地开发 | 零配置 | 仅开发环境 |
| JSONP | 兼容旧浏览器 | 支持跨域 | 只支持 GET，已过时 |

> 💡 **最佳实践**：开发环境用 Vite Proxy，生产环境用 Nginx 反向代理。后端始终开启 CORS 配置作为兜底。

### Q9：前端页面加载很慢，你怎么定位和优化？

**面试官意图：** 考察前端性能问题的系统化排查能力。

**完美解答：**

**排查流程（从外到内，层层深入）：**

**第一层：网络层面（Chrome DevTools → Network）**
```text
1. 看瀑布图：哪些请求耗时最长？
   - 接口响应慢 → 后端优化
   - 静态资源加载慢 → CDN/压缩
   - 请求排队 → 域名分片/HTTP/2

2. 检查资源体积：
   - JS 包 > 500KB → 代码分割
   - 图片 > 200KB → 压缩/WebP
   - 字体文件大 → 字体子集化
```

**第二层：渲染层面（Chrome DevTools → Performance）**
```text
1. 录制加载过程，看：
   - FCP (First Contentful Paint) > 2s
   - LCP (Largest Contentful Paint) > 2.5s
   - TTI (Time to Interactive) > 3s

2. 观察火焰图：
   - 长任务（>50ms）阻塞了主线程 → 拆分为异步任务
   - 强制回流/重排 → 批量 DOM 操作
   - 组件过度渲染 → 加 v-if/v-show/computed 缓存
```

**第三层：打包分析（vite-plugin-inspect）**
```javascript
// 运行后可视化看到：
// 1. 某个依赖占了 300KB（太大，找替代）
// 2. 某个页面组件的依赖被重复打包（优化 shared chunk）
// 3. 没用到的图标库全量引入了（改按需引入）
```

**典型优化案例：**
```javascript
// 优化前：所有图标全量引入  →  300KB
import { allIcons } from 'element-plus/icons-vue'

// 优化后：按需引入  →  30KB
import { Edit, Delete, Search } from '@element-plus/icons-vue'

// 优化前：组件全部打包到主 bundle  →  2MB
// 优化后：路由懒加载 + 异步组件  →  首屏 300KB
```

> 🎯 **面试关键**：用 DevTools 的 Network 和 Performance 面板定位问题，这是"会做"和"会用工具做"的区别。

### Q10：用户在 AI 对话页发现"页面卡死了"，你怎么排查和修复？

**面试官意图：** 考察前端运行时问题的定位和修复能力。

**完美解答：**

**真实案例：AI 对话页面在长对话后卡死**

**排查过程：**

**第一步：确认问题现象**
```
打开 Chrome DevTools → Performance 录制 → 复现卡顿
发现：主线程几乎被占满，每 3-5 秒出现一个 300ms+ 的长任务
```

**第二步：定位问题来源**
```javascript
// 问题 1：消息列表渲染 500 条对话，没有虚拟滚动
// 当消息超过 200 条时，渲染性能严重下降

// 问题 2：每条消息的 Markdown 渲染每次都重新解析
// marked() 是同步操作，消息多时阻塞主线程

// 问题 3：缺少防抖的滚动事件
// scroll 事件频繁触发，导致 layout thrashing
```

**第三步：解决方案**

```vue
<!-- 修复 1：虚拟滚动 + 窗口化渲染 -->
<template>
  <RecycleScroller
    class="message-list"
    :items="messages"
    :item-size="80"
    key-field="id"
    v-slot="{ item }"
  >
    <MessageBubble :message="item" />
  </RecycleScroller>
</template>

<!-- 修复 2：消息缓存和惰性渲染 -->
<script setup>
import { computed } from 'vue'
import { marked } from 'marked'

// 缓存已渲染的内容，避免重复解析
const renderedCache = new Map()

function renderContent(message) {
  if (!renderedCache.has(message.id)) {
    // 使用 setTimeout 分片渲染，避免阻塞主线程
    const timer = setTimeout(() => {
      renderedCache.set(message.id, marked(message.content))
      clearTimeout(timer)
    }, 0)
  }
  return renderedCache.get(message.content)
}

// 只渲染最近的 50 条消息
const visibleMessages = computed(() => {
  if (messages.value.length > 50) {
    return messages.value.slice(-50)
  }
  return messages.value
})
</script>

<!-- 修复 3：滚动事件防抖 -->
<script setup>
import { throttle } from 'lodash-es'

const handleScroll = throttle(() => {
  // 只在用户停止滚动 100ms 后执行
  const container = messageContainer.value
  const isNearBottom = container.scrollHeight - container.scrollTop - container.clientHeight < 100
  if (isNearBottom) {
    scrollToBottom()
  }
}, 100)
</script>
```

**优化效果：**
- 500 条对话场景下，FPS 从 12 提升到 58
- 页面响应从"卡死"变为"流畅滚动"
- 内存占用减少 60%（只渲染可视区域）

### Q12：你们的项目是怎么做前端错误监控和日志上报的？

**面试官意图：** 考察前端工程的运维能力，不只是"开发"还有"运营"。

**完美解答：**

前端错误监控是从"能用"到"稳定"的关键环节。我设计了一套三级错误监控体系：

**第一级：全局异常捕获**
```javascript
// main.js — 应用入口捕获所有未处理异常

// 1. 同步错误
window.onerror = function(message, source, lineno, colno, error) {
  console.error('全局异常:', { message, source, lineno, colno, error })
  reportError({
    type: 'RUNTIME_ERROR',
    message: message,
    stack: error?.stack,
    url: window.location.href,
    timestamp: Date.now()
  })
  return true  // 阻止默认错误处理
}

// 2. 异步 Promise 错误
window.addEventListener('unhandledrejection', (event) => {
  console.error('未处理的 Promise 拒绝:', event.reason)
  reportError({
    type: 'UNHANDLED_REJECTION',
    message: event.reason?.message || String(event.reason),
    stack: event.reason?.stack,
    url: window.location.href,
    timestamp: Date.now()
  })
})

// 3. Vue 组件内错误
app.config.errorHandler = (err, instance, info) => {
  console.error('Vue 组件错误:', err, info)
  reportError({
    type: 'VUE_ERROR',
    message: err.message,
    stack: err.stack,
    component: instance?.type?.__name || 'unknown',
    hook: info,  // 哪个生命周期钩子
    url: window.location.href
  })
}
```

**第二级：接口请求监控**
```javascript
// axios 拦截器 — 监控所有 API 请求的状态和延迟
axios.interceptors.response.use(
  response => {
    // 上报成功请求的性能指标
    reportApiMetric({
      url: response.config.url,
      method: response.config.method,
      status: response.status,
      duration: Date.now() - response.config._startTime,
      timestamp: Date.now()
    })
    return response
  },
  error => {
    // 上报失败请求
    reportApiMetric({
      url: error.config?.url,
      method: error.config?.method,
      status: error.response?.status || 'NETWORK_ERROR',
      duration: Date.now() - (error.config?._startTime || Date.now()),
      message: error.message,
      timestamp: Date.now()
    })
    
    // HTTP 状态码统一处理
    const status = error.response?.status
    if (status === 401) {
      // Token 过期，跳转登录
      userStore.logout()
      router.push('/login')
    } else if (status === 403) {
      ElMessage.warning('没有操作权限')
    } else if (status >= 500) {
      ElMessage.error('服务器繁忙，请稍后重试')
    }
    
    return Promise.reject(error)
  }
)

// 请求拦截器记录开始时间
axios.interceptors.request.use(config => {
  config._startTime = Date.now()
  return config
})
```

**第三级：用户行为采集**
```javascript
// 用户操作埋点 — 用于复现问题路径
function trackUserAction(action, detail) {
  const events = JSON.parse(sessionStorage.getItem('user_events') || '[]')
  
  events.push({
    action,           // 'click' | 'route_change' | 'form_submit'
    detail,           // 具体操作描述
    url: window.location.href,
    timestamp: Date.now(),
    userAgent: navigator.userAgent
  })
  
  // 只保留最近 50 条
  if (events.length > 50) events.shift()
  sessionStorage.setItem('user_events', JSON.stringify(events))
}

// 当错误上报时，携带用户操作轨迹
function reportError(errorInfo) {
  const events = JSON.parse(sessionStorage.getItem('user_events') || '[]')
  
  fetch('/api/monitor/error', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      ...errorInfo,
      userId: userStore.userInfo?.id,
      userEvents: events.slice(-10),  // 发送最近 10 步操作
      systemInfo: {
        browser: navigator.userAgent,
        screen: `${window.screen.width}x${window.screen.height}`,
        language: navigator.language
      }
    })
  }).catch(() => {
    // 上报失败不阻塞用户操作
    console.warn('错误上报失败')
  })
}
```
