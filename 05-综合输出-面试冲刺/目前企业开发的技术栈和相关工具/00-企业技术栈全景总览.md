## 5. 面试中如何回答"你用过哪些技术栈"

### 三层回答法：列举 -> 关系 -> 场景

面试官问这个问题，真正的考察点包括：
- 你用过的东西是停留在"会用API"层面，还是理解其**原理和选型依据**
- 你能不能说清楚技术之间**如何协作**
- 你有没有在实际项目中**踩过坑、做过取舍**

#### 第一层：列举 (List) — 10秒

简明扼要地列出你主要使用的技术栈，按层次组织：

> "我在上一家公司主要负责后端开发，技术栈主要是 **Spring Cloud Alibaba** 这一套，包括 Nacos 做注册中心和配置中心、Sentinel 做限流熔断、Gateway 做API网关。数据层用的是 **MySQL + MyBatis-Plus**，缓存是 **Redis**，消息队列用的 **RocketMQ**。部署在 **K8s** 上，用 **Jenkins** 做CI/CD，监控用的是 **Prometheus + Grafana + SkyWalking**。"

#### 第二层：关系 (Relation) — 30秒

讲清楚这些技术之间如何协作，用一条请求链路串起来：

> "举个例子，一条用户下单的请求链路是这样的：
> 1. 请求先经过 **Nginx** 到达 **Spring Cloud Gateway**，Gateway做鉴权（解析JWT Token）和限流（集成Sentinel）
> 2. 网关转发到 **订单服务**，它用 **OpenFeign** 调用库存服务和用户服务
> 3. 服务间用 **Seata AT模式** 保证分布式事务一致性
> 4. 缓存用了 **Redis**，配合 **Canal** 做MySQL的缓存最终一致性，先删缓存再更新DB
> 5. 订单创建后发 **RocketMQ** 消息，通知服务异步处理短信通知
> 6. 整个链路的耗时通过 **SkyWalking** APM追踪，关键指标上报到 **Prometheus**，**Grafana** 展示"

#### 第三层：场景 (Scenario) — 60秒

挑1-2个你最有心得的场景，讲讲踩过的坑、做过的选型，这是真正拉开差距的部分：

> "举个例子，我们之前在 **技术选型** 上做过一次迁移决策。最早用的是 **Spring Cloud Netflix** 那一套（Eureka + Hystrix + Zuul），迁移到 **Spring Cloud Alibaba** 主要是三个原因：
> 1. **Netflix组件进入维护期**，不再有大的功能迭代
> 2. **Nacos比Eureka功能更丰富**，注册中心和配置中心二合一，减少了运维组件
> 3. **Sentinel比Hystrix更强大**，支持实时监控、热点参数限流、规则持久化到Nacos
>
> 迁移过程中遇到的挑战主要是 **配置兼容性**，从Zuul迁移到Gateway时路由规则需要重写，我们通过灰度发布逐步切换，先切20%流量到新网关，观察SkyWalking上的error rate和响应时间，确认没问题再全量切。"

### 回答示例总结

```
❌ 差："我用过Spring Boot、Spring Cloud、MySQL、Redis、MQ、Docker、K8s..."
    (听起来像是在背单词，没有深度)
✅ 中："我主要用Spring Cloud Alibaba这套，外加MySQL、Redis、RocketMQ..."
    (有层次感，有主线)
✅ ✅ 好："我这边用Spring Cloud Alibaba全家桶...以一次下单请求为例，完整链路是..."
    (用请求串联技术栈，展示对协作关系的理解)
✅ ✅ ✅ 优秀：在好的基础上，再加上具体的踩坑和选型理由
    (展示深度思考和工程判断力)
```

> ⚠️ **面试警告**：不要张口就是"我全部用过"——面试官会挑一个你最不熟的追着问，露馅了反而扣分。建议**主攻3-5个核心技术**，保证每个都能讲30分钟以上。

## 6. 不同公司规模技术栈差异速览

### 6.1 初创公司 (0-50人)

**核心诉求**：快速验证、低成本、一人多能

| 维度 | 典型方案 | 说明 |
|------|---------|------|
| 架构 | 单体应用 / 简单微服务 | Spring Boot单一应用，最多拆3-5个服务 |
| 注册中心 | Nacos / 甚至不用 | 服务不多时，配置写死也行 |
| 网关 | Nginx + 网关层简化 | 甚至不需要Gateway，Nginx直接反向代理到服务 |
| 部署 | 阿里云ECS / Docker Compose | 一般不碰K8s，成本高、维护重 |
| 数据库 | 单库MySQL + Redis | 不需要分库分表，RDS托管 |
| MQ | 不需要 / RocketMQ轻量版 | 业务简单时异步用线程池就够了 |
| 监控 | 阿里云CloudMonitor | 不需要Prometheus，云厂商自带的够用 |
| CI/CD | Jenkins简单流水线 / 手动部署 | 快速迭代优先 |
| 团队分工 | 全栈开发为主 | 后端也得写前端、运维 |

### 6.2 中型公司 (50-500人)

**核心诉求**：规范化、可扩展、团队协作

| 维度 | 典型方案 | 说明 |
|------|---------|------|
| 架构 | 微服务 (10-30个服务) | 按业务域拆分，有明确的服务边界 |
| 注册中心 | Nacos (集群, 3节点) | AP/CP模式根据场景选择 |
| 网关 | Spring Cloud Gateway + 灰度发布 | 路由规则存Nacos，动态刷新 |
| 部署 | K8s + Jenkins Pipeline | 容器化基本成熟，DevOps团队已建立 |
| 数据库 | MySQL主从 + ShardingSphere分库 | 已有分库分表需求，读写分离 |
| MQ | RocketMQ (集群) | 事务消息、顺序消息都在用 |
| 监控 | Prometheus + Grafana + SkyWalking | 可观测性三件套基本到位 |
| CI/CD | GitLab CI / Jenkins | 自动化测试+自动部署到K8s |
| 团队分工 | 后端/前端/测试/运维明确分工 | 有专门的架构师或技术Lead |

### 6.3 大厂 / 头部企业 (500人+)

**核心诉求**：高可用、极致性能、深度定制

| 维度 | 典型方案 | 说明 |
|------|---------|------|
| 架构 | 微服务 + 中台 + 多活 | 上百个服务，多机房/多区域部署 |
| 注册中心 | 自研 / 深度定制Nacos | 基于开源二次开发，支持百万级实例 |
| 网关 | 自研网关 / 多级网关架构 | 接入层+业务层+内部网关分层 |
| 部署 | Service Mesh (Istio) + K8s | Proxy注入、流量控制、安全策略 |
| 数据库 | 自研分布式数据库 / TiDB / OceanBase | 告别单机MySQL，原生分布式 |
| MQ | 自研MQ / 深度定制Kafka | 百万级QPS，高可用强一致性 |
| 监控 | 全链路可观测 + 根因分析 | OpenTelemetry统一标准，AI辅助定位 |
| CI/CD | 自研平台 / 发布系统 | 灰度发布+自动回滚+变更评审 |
| 团队分工 | 细分领域专家 | 有人专门负责JVM优化、数据库DBA、SRE |

> 💡 **面试策略**：如果在小公司，可以结合"在小公司虽然规模不大，但因此我**接触了从开发到部署的全流程**"来展现广度。如果面大厂，强调"我用的是开源方案，但我**研究了源码和原理**"，也能弥补与自研框架的差距。

## 7. 学习路线推荐

### 路线A：面试突击路线 (1-2个月)

适合**准备面试**的同学，优先攻面试最高频的模块：

```
第1-2周：Spring Boot 原理 + MyBatis-Plus 企业用法
  └─ 重点：自动配置原理、条件构造器、分页
第3-4周：Spring Cloud Alibaba 四大组件
  └─ 重点：Nacos AP/CP、Sentinel流控、Gateway路由、Seata AT
第5-6周：Redis + MySQL 深度
  └─ 重点：缓存三大问题、分布式锁、索引、MVCC
第7-8周：MQ + 项目串讲 + 模拟面试
  └─ 重点：消息可靠性、顺序消息 + 用项目经验串联
```

### 路线B：系统提升路线 (3-6个月)

适合**想全面提升**的同学，从底层到上层：

```
阶段1 (1个月)：Java核心 + Spring Boot 源码
  └─ 读Spring Boot自动配置源码 → 理解@Conditional机制
阶段2 (1个月)：微服务全栈 + 数据库深度
  └─ 搭建完整微服务Demo + MySQL优化实战
阶段3 (1个月)：中间件 + 容器化
  └─ Redis集群方案 + RocketMQ整合 + Docker+K8s入门
阶段4 (1个月)：可观测性 + DevOps + 项目整合
  └─ 搭建Prometheus+Grafana + Jenkins流水线
阶段5 (1个月)：新趋势 + 面试冲刺
  └─ AI+Java (LangChain4j) + Virtual Threads + 模拟面试
```

### 路线C：高阶深化路线 (6-12个月)

适合**架构师方向**的同学：

```
┌─ 源码级深入：Spring Cloud Alibaba 源码 + 自定义Starter
├─ 云原生转型：Service Mesh (Istio) + Serverless
├─ AI融合：Spring AI + RAG + AI原生应用架构
├─ 性能优化：JVM调优 + 全链路压测 + 性能建模
└─ 架构设计：领域驱动设计 + 事件驱动架构 + 多活架构
```

> 🎯 **核心要点**：面试准备的重点不是"学过多少技术"，而是"能用技术解决什么问题"。把力气花在**选型思考**和**踩坑经验**上，比多背10个框架名更有价值。
