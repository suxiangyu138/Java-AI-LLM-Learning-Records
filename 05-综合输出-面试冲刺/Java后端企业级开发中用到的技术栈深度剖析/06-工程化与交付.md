## 1. 工程化全景

```
工程化链路：代码 → 构建 → 测试 → 交付 → 部署 → 运维

六大环节：
  ① 构建：Maven/Gradle
  ② 版本：Git + 分支策略
  ③ 质量：静态检查 + 测试
  ④ 交付：CI/CD 流水线
  ⑤ 部署：Docker/K8s
  ⑥ 运维：监控/告警（见 08 篇）

⚠️ 面试必答：
"工程化 = 从代码到上线的自动化链路——
 构建/版本/测试/交付/部署/运维六环，
 目标是'可复现、可追溯、可回滚'。"
```

## 2. 构建工具 Maven

### 2.1 Maven 核心

```
Maven 三概念：
  坐标：groupId + artifactId + version（唯一定位）
  生命周期：clean → compile → test → package → install
  仓库：本地（~/.m2）→ 中央/私服（Nexus）

常用命令：
  mvn compile / test / package / install
  mvn clean package -DskipTests

⚠️ 面试必答：
"Maven 三概念——坐标、生命周期、仓库；
 多模块 + 依赖版本集中管理（BOM）。"
```

### 2.2 Gradle vs Maven

| 维度 | Maven | Gradle |
|------|:---:|:---:|
| 配置 | XML（啰嗦） | Groovy/Kotlin DSL |
| 性能 | 慢 | ✅ 快（增量/并行） |
| 生态 | 默认标准 | 新项目偏好 |
| 复杂度 | 简单 | 灵活 |

```
⚠️ 面试必答：
"Maven 稳定默认、Gradle 快而灵活；
 Spring 官方项目已转向 Gradle，
 企业存量 Maven 居多。"
```

## 3. 版本控制与分支

### 3.1 Git 核心操作

```
Git 工作流：
  工作区 → 暂存区（add）→ 本地仓库（commit）→ 远程（push）

高频命令：
  git status / log / diff
  git add . / commit -m / push
  git pull --rebase（线性历史）
  git cherry-pick / stash / reset --soft

⚠️ 面试必答：
"Git 三区模型 + 高频命令；
 合并策略：rebase（线性）vs merge（保留分支）。"
```

### 3.2 分支策略

```
主流分支策略（2026）：
  Trunk-Based：短分支快速合并（CI/CD 配套）✅ 主流
  Git Flow：master/develop/feature/release（低频发版）

提交规范（Conventional Commits）：
  feat/fix/refactor/docs/test

⚠️ 面试必答：
"高频部署用 Trunk-Based、低频发版 Git Flow；
 语义化提交（feat/fix）自动生成 changelog。"
```

## 4. 测试体系

### 4.1 测试分层

```
测试金字塔（70/20/10）：
  单元测试 70%：JUnit + Mockito（快）
  集成测试 20%：Testcontainers（真环境）
  E2E 10%：核心链路（慢）

⚠️ 面试必答：
"测试金字塔——单元多快、E2E 少慢；
 覆盖率目标 80%（有意义覆盖）。"
```

### 4.2 Boot 测试要点

```
@SpringBootTest：集成测试（全量）
@WebMvcTest：切片（快）
@MockBean：隔离依赖
Testcontainers：真实 DB/MQ

⚠️ 面试必答：
"Boot 测试 = 切片优先（快）+ 集成验证 +
 Testcontainers 真实环境。"
```

## 5. CI/CD 流水线

### 5.1 流水线设计

```
CI 阶段（提交触发）：
  编译 → 静态检查 → 单元测试 → 安全扫描（5 分钟内反馈）

CD 阶段（合并后）：
  集成测试 → 构建镜像 → 部署 staging → 灰度 → 生产

⚠️ 面试必答：
"CI = 自动构建测试（质量门禁）、
 CD = 自动部署（发布策略）；
 每次提交触发、快反馈、可回滚。"
```

### 5.2 发布策略

```
三种发布：
  滚动：逐台替换（无状态）
  蓝绿：双环境切换（秒级回滚）
  金丝雀：5%→100% 渐进（高风险变更）

自动回滚：错误率超阈值自动回滚

⚠️ 面试必答：
"发布三策略——滚动/蓝绿/金丝雀；
 回滚速度蓝绿最快；
 自动回滚 = 指标驱动（错误率/延迟）。"
```

## 6. 容器化部署

### 6.1 Docker 核心

```
Docker 三概念：
  镜像（Image）：只读模板
  容器（Container）：运行实例
  Dockerfile：镜像构建脚本

多阶段构建（生产实践）：
  构建阶段（Maven + JDK）→ 运行阶段（JRE 瘦镜像）

⚠️ 面试必答：
"Docker = 环境一致 + 快速部署；
 多阶段构建瘦镜像（几百 MB → 几十 MB）。"
```

### 6.2 K8s 核心

```
K8s 核心概念：
  Pod（最小部署单元）
  Deployment（无状态应用 + 滚动更新）
  Service（服务发现 + 负载均衡）
  HPA（自动扩缩容）
  ConfigMap/Secret（配置/密钥）

⚠️ 面试必答：
"K8s = 容器编排——Pod/Deployment/Service
 三概念 + 探针（存活/就绪）+ 弹性伸缩。"
```
