## 1. VPN 是什么

### 1.1 一句话定义

> **VPN (Virtual Private Network)** = 在不可信的公共网络（互联网）之上，建立一条**加密的、经过认证的**虚拟专用通信隧道。

### 1.2 三个关键词

| 关键词 | 含义 | 实现手段 |
|--------|------|---------|
| **Virtual（虚拟）** | 不是物理专线，而是在共享网络上逻辑隔离 | 隧道协议封装 |
| **Private（私有）** | 通信内容不可被第三方读取或篡改 | 加密（Encryption） |
| **Network（网络）** | 提供完整的网络层连接，不只是单个应用代理 | 路由 + IP 分配 |

### 1.3 VPN 解决的核心问题

```
没有 VPN 时：
你 ─── [明文数据] ─── 互联网（任何人都能看到）─── 目标服务器
                          ↑
                     ISP、黑客、GFW 都能看到你的流量

有 VPN 时：
你 ─── [🔒 加密隧道] ─── 互联网（只能看到加密乱码）─── VPN 服务器 ─── 目标服务器
                              ↑
                         只能看到你在和 VPN 通信，不知道内容
```

### 1.4 VPN vs 代理 (Proxy)

> ⚠️ **常见误区**：很多人把 VPN 和代理混为一谈，它们有本质区别。

| 维度 | VPN | HTTP 代理 | SOCKS5 代理 |
|------|-----|----------|------------|
| **工作层级** | OSI L2/L3（数据链路/网络层） | L7（应用层） | L5（会话层） |
| **流量范围** | 整个设备的全部流量 | 仅浏览器/配置了代理的应用 | 支持 TCP/UDP 的应用 |
| **加密** | ✅ 端到端加密 | ❌ 通常不加密（除非 HTTPS） | ❌ 不加密 |
| **DNS** | VPN 服务器解析 | 可能泄露 DNS | 可能泄露 DNS |
| **系统集成** | 创建虚拟网卡，系统级路由 | 应用级配置 | 应用级配置 |
| **性能开销** | 加密/解密有开销 | 较低 | 较低 |

> 🎯 **核心要点**：VPN 是**网络层**方案，接管整个设备的流量；代理是**应用层**方案，只代理特定应用。

## 2. 隧道技术

### 2.1 什么是隧道

隧道 (Tunneling) 是将一个网络协议的数据包**封装**在另一个协议的数据包中传输。

```
原始数据包：
┌──────────────────────────────┐
│ 原始 IP 头 │ TCP/UDP 头 │ 数据  │     ← 目标地址：真实目标服务器
└──────────────────────────────┘
              ↓ 隧道封装
┌──────────────────────────────────────────────┐
│ 外层 IP 头 │ 隧道协议头 │ 加密的原始数据包      │   ← 目标地址：VPN 服务器
└──────────────────────────────────────────────┘
```

### 2.2 隧道的两种实现模式

| 模式 | 描述 | 代表协议 | 特点 |
|------|------|---------|------|
| **传输模式 (Transport Mode)** | 只加密载荷，保留原始 IP 头 | IPsec Transport | 端到端通信，无法隐藏通信双方 IP |
| **隧道模式 (Tunnel Mode)** | 加密整个原始包，添加新 IP 头 | IPsec Tunnel, WireGuard, OpenVPN | 完全隐藏内部网络结构 |

### 2.3 隧道 = 封装 + 加密 + 路由

```
1. 封装 (Encapsulation)
   将原始 IP 包作为新 IP 包的 payload
   
2. 加密 (Encryption)
   对封装后的 payload 进行加密
   
3. 路由 (Routing)
   修改系统路由表，将目标流量导向虚拟网卡
```

> 💡 **类比理解**：隧道就像把一封信（原始数据包）放进另一个信封（隧道包），写上 VPN 服务器的地址，然后交给邮局（互联网）。邮局只能看到外层信封，不知道里面装的是什么。

## 3. 加密体系

### 3.1 VPN 中的两种加密

| 加密类型 | 用途 | 算法示例 | 特点 |
|---------|------|---------|------|
| **对称加密** | 加密实际传输的数据 | AES-256, ChaCha20 | 快，适合大量数据 |
| **非对称加密** | 安全交换对称密钥 | RSA, ECDH, Curve25519 | 慢，但无需预共享密钥 |

### 3.2 密钥交换过程

```
Client                                     Server
  │                                           │
  │ ──── 1. Client Hello (支持的算法列表) ────→ │
  │                                           │
  │ ←─── 2. Server Hello (选择的算法) ─────── │
  │                                           │
  │ ──── 3. 密钥交换 (DH/ECDH) ────────────→ │
  │                                           │
  │    双方独立计算出相同的对称密钥              │
  │    (中间人即使截获交换过程也无法算出)       │
  │                                           │
  │ ←──→ 4. 使用对称密钥加密通信 ←──→         │
```

### 3.3 主流 VPN 的加密方案

| VPN 协议 | 加密算法 | 密钥交换 | 认证 | 前向安全性 |
|---------|---------|---------|------|:--------:|
| **WireGuard** | ChaCha20 + Poly1305 | Curve25519 (Noise IK) | BLAKE2s | ✅ |
| **OpenVPN** | AES-256-GCM (默认) | RSA/ECDH + TLS | SHA-256/SHA-512 | ✅ (ECDH) |
| **IPsec/IKEv2** | AES-256-GCM | DH Group 14-20 | SHA-256/384 | ✅ |
| **L2TP/IPsec** | IPsec AES + L2TP 无加密 | IKE | 证书/预共享密钥 | ⚠️ 有限 |
| **PPTP** | MPPE-128 (弱) | MS-CHAPv2 | MS-CHAPv2 | ❌ |

> 🎯 **核心要点**：WireGuard 的加密栈极简但安全 —— 没有算法协商，没有降级攻击的可能。ChaCha20-Poly1305 是 AEAD（认证加密）模式，同时提供机密性和完整性。

## 4. 认证机制

### 4.1 认证的两层含义

```
第一层：设备/用户认证
    ↓ 确认"你是谁"
    → 预共享密钥 (PSK)
    → 证书 (X.509)
    → 用户名/密码
    → SSH 密钥对 (WireGuard)

第二层：数据完整性认证
    ↓ 确认"数据在传输中未被篡改"
    → HMAC (Hash-based Message Authentication Code)
    → AEAD (如 AES-256-GCM, ChaCha20-Poly1305 自带)
```

### 4.2 认证方式对比

| 方式 | 安全性 | 部署复杂度 | 适用场景 |
|------|:-----:|:--------:|---------|
| **预共享密钥 (PSK)** | ⭐⭐ | 低 | 小团队、家庭网络 |
| **证书 (PKI)** | ⭐⭐⭐⭐⭐ | 高 | 企业环境、大规模部署 |
| **用户名/密码** | ⭐⭐ | 低 | 临时访问 |
| **SSH 密钥对** | ⭐⭐⭐⭐ | 中 | WireGuard 默认 |
| **OAuth/SAML** | ⭐⭐⭐⭐ | 中 | 企业 SSO 集成 |

### 4.3 WireGuard 的密钥模型

```
┌─────────────────────────────────────────┐
│          WireGuard 密钥模型               │
│                                          │
│  每个 peer 有一对密钥：                   │
│  ┌──────────────┐  ┌──────────────┐      │
│  │  Private Key  │  │  Public Key   │      │
│  │  (绝不出站)    │  │  (在配置中交换) │      │
│  └──────────────┘  └──────────────┘      │
│                                          │
│  认证方式：                               │
│  当双方配置了对方的 Public Key，           │
│  连接自动认证 —— 像 SSH 的 authorized_keys│
└─────────────────────────────────────────┘
```

> 💡 WireGuard 的哲学：密钥即身份。没有用户名/密码，没有证书链 —— 公钥对了，你就对了。

## 5. VPN 的四种类型

```
VPN 分类
│
├── 按部署场景
│   ├── Remote Access VPN（远程访问） → 个人连公司内网
│   └── Site-to-Site VPN（站点到站点）  → 两个局域网互联
│
└── 按实现层级
    ├── Network-based VPN（网络层）     → IPsec, WireGuard
    ├── SSL/TLS VPN（传输层）           → OpenVPN (TLS mode)
    └── MPLS VPN（链路层）             → 运营商提供
```

### 5.1 Remote Access VPN

```
出差员工 ─── 互联网 ─── [VPN Gateway] ─── 公司内网
                                       ├── 数据库 10.0.1.100
                                       ├── 文件服务器 10.0.2.50
                                       └── GitLab 10.0.3.10
```

### 5.2 Site-to-Site VPN

```
北京办公室 (192.168.1.0/24)              上海办公室 (192.168.2.0/24)
         │                                        │
    [VPN Gateway] ──── 加密隧道 ──── [VPN Gateway]
         │                                        │
    两台网关之间建立永久隧道，两端局域网互通
```

### 5.3 类型对比

| 类型 | 连接方式 | 典型协议 | 使用场景 |
|------|---------|---------|---------|
| **Remote Access** | 客户端 → 服务器 | WireGuard, OpenVPN, IKEv2 | 远程办公、个人隐私 |
| **Site-to-Site** | 网关 → 网关 | IPsec, WireGuard | 多云互联、分支互联 |
| **SSL VPN** | 浏览器 → 服务器 | TLS/DTLS | 无客户端访问、BYOD |
| **Cloud VPN** | 云环境 → 本地 | IPsec, WireGuard (云厂商提供) | 混合云互联 |

## 6. VPN 与 OSI 模型

```
OSI 层级          VPN 方案              工作方式
─────────        ─────────             ──────────
L7 应用层         SSL VPN (部分)        应用代理，如 Web VPN
L6 表示层         ——                    TLS 加密在此层
L5 会话层         SOCKS5                会话代理，不分协议
L4 传输层         SSL/TLS VPN           TLS 封装 TCP/UDP
L3 网络层      ┌─ IPsec (Tunnel)       直接封装 IP 包
              ├─ WireGuard             虚拟网卡 + IP 路由
              ├─ OpenVPN (tun)         创建 tun 设备
              └─ OpenVPN (tap)         创建 tap 设备
L2 数据链路层     L2TP, PPTP           PPP 封装 + 链路层加密
L1 物理层         ——                    物理专线
```

> 🎯 **核心要点**：VPN 可以工作在不同层级。L3 层的 VPN（WireGuard, IPsec）是最灵活的选择 —— 透明传输任何 IP 协议（TCP/UDP/ICMP），对应用程序完全无感。

### 6.1 tun vs tap

| 设备 | OSI 层 | 工作方式 | 适用场景 |
|------|:-----:|---------|---------|
| **tun** | L3（网络层） | 处理 IP 包 | 路由模式，最常用 |
| **tap** | L2（数据链路层） | 处理以太网帧 | 桥接模式，需要二层广播 |

```bash
# WireGuard 创建的是 tun 设备（wg0）
# OpenVPN 可以选择 tun 或 tap
# tun 更高效，tap 更灵活（但更复杂）
```

## 7. VPN 的数据包之旅

### 7.1 一个完整的 VPN 通信流程

以访问 `api.github.com` 为例：

```
步骤 1: 应用层
  浏览器/curl 发起 HTTP 请求 → GET /repos/xxx

步骤 2: DNS 解析（通过 VPN 隧道）
  DNS 查询  →  [🔒 WireGuard 加密]  →  VPN 服务器 DNS (8.8.8.8) → 返回 IP

步骤 3: 网络层（核心：路由决策）
  系统路由表：
  ┌─────────────────────────────────────────┐
  │ 0.0.0.0/0      → wg0 (所有流量走 VPN)    │  ← 默认路由指向虚拟网卡
  │ 10.0.0.0/24    → eth0 (本地网络保留)     │
  │ <VPN Server IP> → eth0 (VPN 服务器直连)  │
  └─────────────────────────────────────────┘
  
  api.github.com 的 IP (140.82.121.3):
  → 匹配 0.0.0.0/0 → 路由到 wg0 虚拟网卡

步骤 4: 数据链路层
  wg0 是虚拟设备，实际数据需要从物理网卡 eth0 发送

步骤 5: WireGuard 加密
  ┌─────────────────────────────────────────┐
  │ 原始包: [src:192.168.1.100:54321]→[dst:140.82.121.3:443] │
  │ + TCP payload: "GET /repos/xxx"          │
  └─────────────────────────────────────────┘
         ↓ 加密 (ChaCha20 + Noise IK)
  ┌─────────────────────────────────────────┐
  │ 加密包: [src:<真实IP>:51820]→[dst:<VPN服务端IP>:51820] │
  │ + UDP payload: [加密的原始IP包]           │
  └─────────────────────────────────────────┘
         ↓ 通过 eth0 发送

步骤 6: 互联网传输
  中间路由器和 ISP → 只能看到 UDP 包 → 不知所云

步骤 7: VPN 服务器解密
  WireGuard 解密 → 还原原始 IP 包 → NAT 后转发

步骤 8: 响应原路返回
  api.github.com → VPN 服务器 → 加密 → eth0 → wg0 解密 → 应用
```

### 7.2 时序图

```text
App         wg0(TUN)    路由表    WireGuard   eth0      互联网    VPN Server  目标
 │             │          │          │         │          │          │         │
 │─GET /repos─→│          │          │         │          │          │         │
 │             │─匹配路由?→│          │         │          │          │         │
 │             │←0.0.0.0/0│          │         │          │          │         │
 │             │─原始包──→│          │         │          │          │         │
 │             │          │          │─加密───→│          │          │         │
 │             │          │          │         │──UDP包──→│          │         │
 │             │          │          │         │          │──解密───→│         │
 │             │          │          │         │          │          │──请求──→│
 │             │          │          │         │          │          │←──响应──│
 │             │          │          │         │          │←──加密──│         │
 │             │          │          │         │←──UDP包──│          │         │
 │             │          │          │←──解密──│          │          │         │
 │             │←──原始包──│          │         │          │          │         │
 │←─响应数据──│          │          │         │          │          │         │
```

---

> 🎯 **核心要点**：VPN 的精髓在于**路由 + 加密**。路由表决定哪些流量进入隧道，加密保证隧道内数据不可读。两者配合，实现了"在公共网络上安全私密通信"的目标。
