## 1. JVM 对后端开发的核心价值

| 能力 | 说明 |
|------|------|
| **异常排查** | `ClassNotFoundException`、`OOM`、`NoClassDefFoundError` 根源都在 JVM |
| **性能优化** | 接口延迟、GC 卡顿本质是内存分配不合理、回收策略不当 |
| **理解框架** | Spring IOC/动态代理依赖类加载、反射机制 |

> JVM 本质是一台"虚拟计算机"，屏蔽底层 OS 和硬件差异，实现"一次编写，到处运行"。

---

## 2. 核心架构

```text
JVM
├── 类加载子系统 ──→ 加载 .class → 生成 Class 对象
├── 运行时数据区 ──→ 存储程序运行中的所有数据
├── 执行引擎 ────→ 解释器 + JIT 编译器（混合模式）
└── 垃圾回收机制 ──→ 自动回收无用对象
```

## 3. 类加载子系统

### 3.1 加载流程（5 阶段）

```text
加载 → 验证 → 准备 → 解析 → 初始化
  │      │      │      │       └── 执行静态代码块 + 显式赋值（唯一执行 Java 代码的阶段）
  │      │      │      └── 符号引用 → 直接引用（内存地址）
  │      │      └── 静态变量分配内存 + 设默认值（非最终值）
  │      └── 安全校验，防恶意字节码
  └── 读取 .class 二进制 → 生成 Class 对象
```

### 3.2 类加载器层次

| 加载器 | 实现 | 加载范围 | 后端关联 |
|--------|------|----------|----------|
| **启动类**（Bootstrap） | C++ | `<JAVA_HOME>/lib` 核心类（`rt.jar`） | `String`、`HashMap` 等基础类 |
| **扩展类**（Extension） | Java | `<JAVA_HOME>/lib/ext` | 较少接触 |
| **应用类**（Application） | Java | `classpath` 上的类 | ✅ Controller/Service/Dao + 第三方依赖 |

### 3.3 双亲委派模型

```text
加载请求
    │
    ▼
应用类加载器 → 先问扩展类 → 再问启动类
    │              │              │
    └── 父类能加载？── 父类能加载？── 自行加载
         │ 不能           │ 不能
         ▼                ▼
      自行加载          自行加载
```

**核心价值**：① 避免类重复加载 ② 保障核心类安全（自定义 `java.lang.Object` 无法加载）

**打破双亲委派的场景**：Tomcat（隔离不同 Web 应用）、OSGi（模块热部署）、JNDI（SPI 加载）。

### 3.4 常见异常

| 异常 | 原因 | 排查 |
|------|------|------|
| `ClassNotFoundException` | 类路径配置错误/依赖缺失 | `-verbose:class` 查看加载详情 |
| `NoClassDefFoundError` | 编译时存在，运行时找不到（静态初始化失败） | 查 `Caused by` 定位静态代码块异常 |

## 4. 运行时数据区

### 4.1 区域概览

| 区域 | 线程 | 存储内容 | 异常风险 |
|------|:----:|----------|----------|
| **堆（Heap）** | 共享 | 对象实例、数组 | ⚠️ OOM 主战场 |
| **方法区（元空间）** | 共享 | 类元数据、常量池、静态变量 | ⚠️ 动态类过多 → OOM |
| 程序计数器 | 私有 | 字节码行号 | ✅ 唯一不 OOM |
| 虚拟机栈 | 私有 | 栈帧（局部变量表/操作数栈） | StackOverflowError |
| 本地方法栈 | 私有 | Native 方法 | 同虚拟机栈 |

### 4.2 堆内存结构

```text
堆（Heap）
├── 新生代（Young）
│   ├── Eden 区（80%）        ← 新对象优先分配
│   ├── Survivor 0 / From（10%）
│   └── Survivor 1 / To（10%）
└── 老年代（Old）              ← 多次 GC 存活对象晋升
```

### 4.3 后端场景关联

| 场景 | 机制 | 后果 |
|------|------|------|
| 高并发创建临时对象 | Eden 满 → Minor GC | 频繁 Minor GC → 响应延迟 |
| 缓存对象长期驻留 | 晋升老年代 → 老年代满 | Full GC → 服务卡顿 STW |
| 大量动态代理/反射 | 元空间膨胀 | Metaspace OOM |

## 5. 执行引擎

### 5.1 混合执行模式

| 组件 | 机制 | 特点 |
|------|------|------|
| **解释器** | 逐行解析字节码 → 机器指令 | 启动快，执行慢 |
| **JIT 编译器** | 识别热点代码 → 一次性编译为机器码 | 启动后逐渐提速 |

### 5.2 后端关联

> 服务刚启动时接口慢（解释器为主）→ 运行一段时间后变快（JIT 编译热点代码）。**接口预热**的底层原理就是提前触发 JIT 编译。

## 6. 垃圾回收机制

### 6.1 GC 流程

```text
标记（识别无用对象）→ 清除（回收内存）→ 整理（消除碎片）
```

### 6.2 Minor GC vs Full GC

| 维度 | Minor GC | Full GC |
|------|----------|---------|
| 触发时机 | Eden 区满 | 老年代满 / 元空间满 / `System.gc()` |
| 回收区域 | 新生代 | 整个堆 + 方法区 |
| 算法 | 复制算法 | 标记-清除-整理 |
| 耗时 | 短（10-50ms） | ⚠️ 长（1s+），STW |
| 优化目标 | 减少频率 | **重点规避** |

### 6.3 后端常见 GC 问题

| 问题 | 原因 | 优化 |
|------|------|------|
| **Minor GC 频繁** | 频繁创建临时对象（循环拼接字符串/POJO） | `StringBuilder` + 对象池 + 增大新生代 |
| **Full GC 频繁** | 静态缓存未清理、长期存活对象堆积 | 清理缓存 + 弱引用 `WeakHashMap` + 调整老年代 |

## 7. 实战排查与调优

### 7.1 OOM 排查

| 类型 | 表现 | 排查方案 |
|------|------|----------|
| 堆 OOM | `Java heap space` | `-XX:+HeapDumpOnOutOfMemoryError` → MAT 分析堆转储 |
| 元空间 OOM | `Metaspace` | 增大 `MaxMetaspaceSize` + 减少动态代理使用 |

### 7.2 Web 应用调优模板

> 场景：高并发、低延迟（4 核 8G 服务器）

```text
-Xms4g -Xmx4g                      # 初始=最大，避免堆震荡
-XX:+UseG1GC                       # G1 平衡延迟+吞吐
-XX:MaxGCPauseMillis=100           # 目标停顿 ≤100ms
-XX:InitiatingHeapOccupancyPercent=35  # 提前触发混合回收
-XX:+HeapDumpOnOutOfMemoryError
-Xloggc:/var/log/app/gc.log
-XX:MaxMetaspaceSize=512m
```

### 7.3 批处理任务调优模板

> 场景：高吞吐量（8 核 16G 服务器）

```text
-Xms8g -Xmx8g
-Xmn5g                              # 增大新生代
-XX:+UseParallelGC                  # 吞吐量优先
-XX:+UseParallelOldGC
-XX:ParallelGCThreads=8             # = CPU 核心数
-XX:GCTimeRatio=19                  # GC 时间占比 ≤5%
```

### 7.4 调优核心原则

| 原则 | 说明 |
|------|------|
| **先调代码，再调 JVM** | 代码层内存泄漏无法通过参数弥补 |
| **不要过早优化** | 性能满足需求即可 |
| **基于数据** | GC 日志 + 堆快照 + 监控 → 定位瓶颈 |
| **适配场景** | Web（低延迟 G1/ZGC）vs 批处理（高吞吐 Parallel） |
| **充分测试** | 生产调优前必须压测验证 |
