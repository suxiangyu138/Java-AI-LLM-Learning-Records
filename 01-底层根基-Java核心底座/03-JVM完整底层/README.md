## 为什么要学习核心机制？

大部分 Java 开发者停留在 Stage 1（语法 + 基础 API）的层面——能写业务代码，能完成 CRUD。但一旦涉及 **性能优化、线上故障排查、高并发架构选型、框架定制** 等场景，仅仅"会用"是远远不够的。

Stage 2 的学习目标是将你的知识体系从"表面"推向"深层"：

```
Stage 1 (会用)         Stage 2 (懂原理)         Stage 3+ (能设计)
  ├── 语法                   ├── JVM 内存模型           ├── 架构设计
  ├── API 调用               ├── GC 调优                ├── 框架定制
  ├── 简单的并发             ├── 并发编程深入           ├── 性能优化
  └── 基础框架使用           ├── 反射/泛型/集合源码     └── 中间件开发
                              └── NIO 网络模型
```

**对于职业发展：**

| 面试级别 | 常见问题 | 依赖的知识 |
|---------|---------|-----------|
| 初级 (1-3年) | HashMap 原理、线程池参数 | 基础 API |
| 中级 (3-5年) | JMM、GC 调优、并发容器源码 | **本阶段内容** |
| 高级 (5-8年) | 框架设计、性能优化、架构选型 | 本阶段 + Stage 3/4 |
| 专家/架构 (8年+) | 定制 JVM、中间件开发 | 全阶段 |

> **核心机制是区分"CRUD Boy"和"真正的 Java 工程师"的分水岭。**

## 学习建议

### 正确姿势

1. **动手写代码**：每个文档都包含可运行的代码示例，请务必亲自运行和修改
2. **画图理解**：JVM 内存结构、并发模型、IO 模型——画出来比读十遍更有效
3. **对比思考**：为什么 JDK 7 的 HashMap 有死循环？为什么 JDK 8 改用了红黑树？每个设计决策背后都有 trade-off
4. **关联现实**：学习 ConcurrentHashMap 时想想 Spring 框架、学习 NIO 时想想 Netty 和 Tomcat
5. **做笔记**：用自己的话总结每个机制的核心要点

### 常见误区

| 误区 | 纠正 |
|------|------|
| "面试前背一背就行" | 核心机制的理解需要在实战中验证，背出来的答案在深度追问下会露馅 |
| "我要把所有收集器参数都背下来" | 理解设计思想和适用场景比背参数更重要 |
| "并发编程就是加 synchronized" | 现代 Java 并发工具远不止 synchronized，了解各种工具的适用场景 |
| "源码太难看不懂" | 从关键方法的入口开始，先看主干再深入细节 |

## 与"培训速成"的区别

很多培训班出来的人也能说出"HashMap 是数组+链表+红黑树"，但只有真正深入原理的人才能回答：

- HashMap 的 hash 函数为什么是 `(h = key.hashCode()) ^ (h >>> 16)`？
- 为什么链表转红黑树的阈值是 8？为什么树转回链表的阈值是 6？
- CMS 收集器的并发预处理失败怎么办？G1 的 Remembered Set 如何维护跨 Region 引用？
- JMM 的 happens-before 规则如何保证可见性？volatile 的内存屏障具体插在哪？
- Spring AOP 在什么情况下用 JDK 动态代理，什么情况下用 CGLIB？

本阶段的每个文档都旨在回答这类"为什么"的问题，而不是停留在"是什么"的层面。
