## 1. Class文件结构全景（魔数CAFEBABE→属性表）

Class文件是javac编译源码产出的标准二进制文件，是JVM唯一识别的执行载体，具备**顺序固定、无分隔符、紧凑二进制流**特性，任意一段损坏直接报类加载异常。

### 1.1 整体结构

```
┌──────────────────────────────────────┐
│ magic u4 0xCAFEBABE                  │ ← 魔数
├──────────────────────────────────────┤
│ minor_version u2 | major_version u2  │ ← 版本号
├──────────────────────────────────────┤
│ constant_pool_count u2               │
│ constant_pool[] cp_info              │ ← 常量池
├──────────────────────────────────────┤
│ access_flags u2                      │ ← 访问标识
├──────────────────────────────────────┤
│ this_class u2 | super_class u2       │
│ interfaces_count u2 | interfaces[]   │ ← 继承关系
├──────────────────────────────────────┤
│ fields_count u2 | field_info[]       │ ← 字段表（仅本类）
├──────────────────────────────────────┤
│ methods_count u2 | method_info[]     │ ← 方法表（含字节码）
├──────────────────────────────────────┤
│ attributes_count u2 | attribute_info[]│ ← 属性表（扩展元数据）
└──────────────────────────────────────┘
```

### 1.2 基础数据单元

| 类型 | 说明 | 示例 |
|------|------|------|
| u1 | 1字节无符号数 | tag标识、字节码指令 |
| u2 | 2字节无符号数 | 索引、计数、版本号 |
| u4 | 4字节无符号数 | 魔数、行号 |
| u8 | 8字节无符号数 | 时间戳、长整型 |
| `_info` | 复合表结构 | cp_info、field_info、method_info |

### 1.3 magic 魔数与版本号

**魔数**：固定4字节 `0xCAFEBABE`（咖啡宝贝），JVM加载类第一步校验前4字节，不匹配抛出 `ClassFormatError`。

> 💡 场景：文件传输损坏、手动篡改二进制、非法文件改名.class都会报错。

**主版本号 major_version** 决定JVM兼容范围（高频面试背诵）：

| JDK版本 | major十进制 | 说明 |
|---------|------------|------|
| JDK6 | 50 | 老旧存量项目 |
| JDK7 | 51 | 遗留系统 |
| **JDK8** | **52** | 存量老项目通用，行业主流 |
| JDK11 | 55 | SpringBoot 3最低要求 |
| **JDK17** | **61** | 新版LTS，低版本JVM无法加载 |
| JDK21 | 65 | 最新LTS，虚拟线程原生支持 |

> ⚠️ JDK17编译class部署JDK8 → `UnsupportedClassVersionError`。解决：`javac -target 1.8 -source 1.8` 降级版本。

## 2. 常量池详解：字面量与符号引用

常量池 = Class文件的**全局字符串、符号引用、字面量仓库**，所有类/方法/字段名、字符串、数字存在这里。

### 2.1 基础规则

- `constant_pool_count`：常量池总个数，**索引从1开始，0号预留空索引**
  - 例：count=20 → 有效索引1~19，共19个常量
- `cp_info` 靠 `tag` 区分常量类型

### 2.2 后端高频常量类型

| tag | 常量类型 | 作用 |
|-----|---------|------|
| 1 | CONSTANT_Utf8_info | 存储所有字符串：类名、方法名、描述符、注解值 |
| 7 | CONSTANT_Class_info | 类/接口符号引用，指向Utf8全限定名 |
| 8 | CONSTANT_String_info | 代码中字面字符串常量 |
| 9 | CONSTANT_Fieldref_info | 字段符号引用（类+字段名+类型） |
| 10 | CONSTANT_Methodref_info | 普通方法符号引用，AOP增强核心操作对象 |
| 3 | CONSTANT_Integer_info | 整型字面量 |

### 2.3 access_flags 访问标志

2字节比特位标识类的修饰符、类型：

| 十六进制 | 标识 | 含义 |
|---------|------|------|
| 0x0001 | ACC_PUBLIC | public类 |
| 0x0010 | ACC_FINAL | 不可继承final |
| 0x0020 | ACC_SUPER | 允许invokespecial增强（JDK8默认） |
| 0x0200 | ACC_INTERFACE | 接口，不能实例化 |
| 0x0400 | ACC_ABSTRACT | 抽象类/接口 |
| 0x2000 | ACC_ENUM | 枚举类型 |

> ⚠️ 接口必须同时带ACC_ABSTRACT，不能加ACC_FINAL；非法组合直接报格式错误。

## 3. 字段表与方法表

### 3.1 字段表 field_info

存储当前类**自身定义的成员变量**，不含父类继承字段。

```java
field_info {
    u2 access_flags;        // private/static/final/volatile等
    u2 name_index;          // 字段名Utf8索引 → 常量池
    u2 descriptor_index;    // 字段类型描述符索引
    u2 attributes_count;
    attribute_info attributes[];  // 可携带ConstantValue等属性
}
```

**类型描述符规则（必背）**：

| 标识 | 类型 | 示例 |
|------|------|------|
| Z/B/C/S/I/J/F/D | 基本类型 | I → int, J → long |
| L`全限定名`; | 引用类型 | Ljava/lang/String; |
| `[` + 类型 | 数组 | [I → int[], [[Ljava/lang/Object; → Object[][] |

### 3.2 方法表 method_info（字节码核心）

存储本类所有方法：构造器`<init>`、静态块`<clinit>`、普通方法，不含父类方法。

```java
method_info {
    u2 access_flags;        // public/static/synchronized等
    u2 name_index;          // 方法名索引 → 常量池
    u2 descriptor_index;    // 方法签名描述符（参数+返回值）
    u2 attributes_count;
    attribute_info attributes[];  // 核心包含Code属性
}
```

**方法描述符格式**：`(参数描述符)返回值`

| 方法签名 | 描述符 |
|---------|--------|
| `void test()` | `()V` |
| `int add(String s, int i)` | `(Ljava/lang/String;I)I` |
| `User find(Long id)` | `(Ljava/lang/Long;)Lcom/example/User;` |

**关键内置隐藏方法**：

| 方法名 | 触发时机 | 说明 |
|--------|---------|------|
| `<init>` | `new` 对象时 | 实例构造方法，先调用父类`<init>`再执行成员变量赋值和构造块 |
| `<clinit>` | 类加载初始化阶段 | 静态代码块 + static变量赋值合并生成，线程安全同步执行 |

> 💡 AOP字节码增强本质：修改method_info的Code属性内字节码指令。`NoSuchMethodError`根源：调用方法name/descriptor与方法表不匹配。

## 4. 属性表：Code/Exceptions/LineNumberTable等

类/字段/方法都可携带属性表，存储扩展元数据，JVM忽略不识别的自定义属性。

### 4.1 高频内置属性

| 属性名 | 所属元素 | 作用 |
|--------|---------|------|
| **Code** | 方法 | **字节码指令主体**，含操作数栈深度、局部变量表容量、字节码流、异常表 |
| SourceFile | 类 | 源码文件名，缺失时堆栈打印`Unknown Source` |
| LineNumberTable | Code内部 | 字节码偏移 ↔ 源码行号映射，用于异常堆栈和断点调试 |
| LocalVariableTable | Code内部 | 局部变量作用域与名称映射，用于debug |
| **Signature** | 类/字段/方法 | 保存泛型原始类型，解决泛型擦除后反射拿不到泛型 |
| InnerClasses | 类 | 记录内部类关联信息 |
| Deprecated | 类/字段/方法 | 标记@Deprecated过期元素 |
| **Exceptions** | 方法 | 记录方法throws声明的受检异常 |
| ConstantValue | 字段 | static final字段的编译期常量值 |

### 4.2 Code属性内部结构

```java
Code_attribute {
    u2 attribute_name_index;    // 指向"Code"字符串
    u4 attribute_length;
    u2 max_stack;               // 操作数栈最大深度（编译期确定）
    u2 max_locals;              // 局部变量表容量（Slot数）
    u4 code_length;
    u1 code[code_length];       // 字节码指令流（核心）
    u2 exception_table_length;
    {   u2 start_pc;
        u2 end_pc;
        u2 handler_pc;
        u2 catch_type;          // 0 = finally（任何异常都捕获）
    } exception_table[exception_table_length];
    u2 attributes_count;
    attribute_info attributes[]; // LineNumberTable、LocalVariableTable等
}
```

> 🎯 AOP字节码增强的原理：读取目标Class完整二进制流 → 解析常量池和方法表 → 新增常量池项（新增字符串、方法引用） → 找到目标method_info → 修改内部Code属性字节码 → 重新组装完整Class二进制，内存生成新类交给类加载器加载。

## 5. 字节码指令分类速查

字节码为单字节指令（0x00~0xFF），部分携带1/2字节操作数；基于栈式虚拟机，所有计算依赖**局部变量表**和**操作数栈**完成。

### 5.1 加载存储指令（局部变量 ↔ 操作数栈）

| 指令码 | 指令 | 功能说明 |
|--------|------|----------|
| 0x2A | aload_0 | 局部变量0（this）引用入栈 |
| 0x1A~0x1D | iload_0/1/2/3 | 局部变量0~3 int入栈 |
| 0x3C~0x3F | istore_0/1/2/3 | 栈顶int存入对应局部变量 |
| 0x12 | ldc | 常量池单字节索引，加载int/String/Class |
| 0x13 | ldc_w | 常量池双字节索引，适配索引>255场景 |

### 5.2 算术运算指令

int系列高频：
- `iadd` 加法、`isub` 减法、`imul` 乘法、`idiv` 整除
- `iinc` 局部变量自增，**for循环底层核心指令**

long/float/double：`ladd`、`fadd`、`dadd`等，规则统一。

### 5.3 类型转换指令

| 类型 | 方向 | 指令示例 |
|------|------|---------|
| 宽化（无精度丢失） | i→l/i→f/i→d/l→f/l→d/f→d | i2l, i2f, i2d |
| 窄化（丢失精度） | l→i/f→i/d→i/d→l/f→l/d→f | l2i, f2i, d2i |

### 5.4 对象创建与字段访问

**创建指令**：

| 指令 | 作用 | 示例 |
|------|------|------|
| `new` | 实例化对象，仅分配内存，不执行构造器 | `new User` |
| `newarray` | 基本类型数组 | `new int[10]` |
| `anewarray` | 引用类型数组 | `new String[10]` |

**字段读写**：

| 指令 | 作用 |
|------|------|
| `getfield` / `putfield` | 实例成员变量读写 |
| `getstatic` / `putstatic` | static静态变量读写 |

### 5.5 控制转移指令

| 指令 | 作用 |
|------|------|
| `goto` | 无条件跳转 |
| `if_icmpeq/if_icmpne/if_icmplt/if_icmpgt` | int数值比较跳转 |
| `ifnull` / `ifnonnull` | 空/非空跳转 |
| `tableswitch` | case值连续，性能高 |
| `lookupswitch` | case离散，二分查找匹配 |

> 💡 `tableswitch` vs `lookupswitch`：switch-case底层根据case值的连续性选择，连续用查表法O(1)，离散用二分查找O(log n)。

### 5.6 异常处理指令

| 指令 | 作用 |
|------|------|
| `athrow` | 抛出异常对象，对应`throw`关键字 |
| `jsr` / `ret` | JDK7前finally块跳转指令，新版已废弃 |

## 6. 运行时栈帧结构

栈帧是执行引擎执行方法时的基本单元，每个方法调用都会创建一个栈帧压入Java虚拟机栈，方法执行完毕后弹出释放。

### 6.1 栈帧核心结构

```
┌────────────────────────────────────┐
│  Stack Frame（栈帧）               │
│ ┌──────────────────────────────┐   │
│ │ 局部变量表                    │   │  ← 参数+局部变量
│ │ Slot[0]=this Slot[1]=arg1 .. │   │     容量编译期确定
│ ├──────────────────────────────┤   │
│ │ 操作数栈                      │   │  ← 全部计算在此完成
│ │ [top][ ][ ]                   │   │
│ ├──────────────────────────────┤   │
│ │ 动态链接                      │   │  ← 符号→直接引用
│ │ 指向运行时常量池               │   │
│ ├──────────────────────────────┤   │
│ │ 方法返回地址 / 异常表           │   │  ← 恢复调用者
│ └──────────────────────────────┘   │
└────────────────────────────────────┘
```

### 6.2 局部变量表

- 存储方法参数和局部变量（基本数据类型、对象引用）
- 容量固定，编译期确定（`max_locals`）
- Slot复用：超出作用域的变量占用的Slot可被后续变量复用

> ⚠️ 方法参数过多、局部变量过多，会导致局部变量表容量不足，间接影响栈帧大小，增加栈溢出风险。

### 6.3 操作数栈

- 用于存储字节码指令执行过程中的操作数和中间结果
- 深度固定（`max_stack`），编译期确定
- 例：`a + b` → 先压入a、b，再`iadd`弹出计算，结果压回

### 6.4 动态链接

- 将符号引用（方法名、类名）转化为直接引用（内存实际地址）
- 类加载**解析阶段**完成部分转化，运行时动态分派完成另一部分

> 🎯 动态链接失败的两个高频场景：1）Spring AOP代理类生成失败 → `NoSuchMethodError`；2）依赖冲突导致同名类方法签名不匹配。

### 6.5 方法返回地址

| 返回方式 | 操作 |
|---------|------|
| 正常返回 | 执行引擎遇到`return`/`ireturn`/`areturn`等返回指令，恢复调用者栈帧 |
| 异常返回 | 方法抛出未捕获异常，通过异常表寻找匹配处理器，找不到则逐层上抛 |

> 💡 StackOverflowError 高发场景：无限递归、拦截器嵌套超过10层、-Xss过小（JDK8默认1MB）。

## 7. 方法调用：解析调用与分派调用

所有方法调用在Class文件中存储的都是**符号引用**，而非直接引用，这给Java带来了强大的动态扩展能力。

### 7.1 方法调用字节码指令

| 指令 | 调用目标 | 分派方式 | 典型场景 |
|------|---------|---------|---------|
| `invokevirtual` | 实例方法 | **动态分派**（运行时确定） | 调用Service/Dao方法，多态重写 |
| `invokestatic` | 静态方法 | 解析调用（编译期确定） | 工具类方法、Math函数 |
| `invokespecial` | 构造器/私有/super | 解析调用（编译期确定） | `<init>`、private方法、super.method() |
| `invokeinterface` | 接口方法 | **动态分派**（运行时确定） | 面向接口编程的方法调用 |
| `invokedynamic` | 动态语言/Lambda | 动态调用（JDK7+） | Lambda表达式、动态语言 |

### 7.2 解析调用（编译期可知，运行期不变）

适用于以下**非虚方法**（编译期确定唯一版本）：

| 方法类型 | 调用指令 | 特点 |
|---------|---------|------|
| 静态方法 | invokestatic | 类名直接确定 |
| 私有方法 | invokespecial | 类外不可见，唯一版本 |
| 构造器 | invokespecial | `<init>`无多态含义 |
| 父类方法 | invokespecial | super.method()确定版本 |
| final方法 | invokevirtual（特殊） | 虽用invokevirtual但不可重写 |

> 💡 final方法虽然使用invokevirtual指令调用，但JVM会特殊处理，将其视为非虚方法（不可重写，不会有其他版本），本质也是解析调用。

## 8. 静态分派（重载）与动态分派（重写）原理

### 8.1 静态分派 —— 重载（Overload）

发生在**编译阶段**，根据参数的**静态类型**（声明类型）决定调用哪个重载版本。

```java
public class OverloadDispatch {
    static abstract class Human {}
    static class Man extends Human {}
    static class Woman extends Human {}

    public void sayHello(Human guy) { System.out.println("hello,guy!"); }
    public void sayHello(Man guy)   { System.out.println("hello,man!"); }
    public void sayHello(Woman guy) { System.out.println("hello,woman!"); }

    public static void main(String[] args) {
        Human man = new Man();
        Human woman = new Woman();
        OverloadDispatch od = new OverloadDispatch();
        od.sayHello(man);   // hello,guy!
        od.sayHello(woman); // hello,guy!
    }
}
```

> 🎯 编译时参数声明类型都是`Human`，都匹配`sayHello(Human)`——重载版本选择在编译期已完成。

静态类型 = 声明类型（`Human man`中的`Human`）；实际类型 = 运行时真实类型（`new Man()`中的`Man`）。

### 8.2 动态分派 —— 重写（Override）

发生在**运行阶段**，根据参数的**实际类型**决定调用哪个重写版本。

```java
public class DynamicDispatch {
    static abstract class Human {
        protected abstract void sayHello();
    }
    static class Man extends Human {
        @Override
        protected void sayHello() { System.out.println("hello,man!"); }
    }
    static class Woman extends Human {
        @Override
        protected void sayHello() { System.out.println("hello,woman!"); }
    }

    public static void main(String[] args) {
        Human man = new Man();
        Human woman = new Woman();
        man.sayHello();   // hello,man!
        woman.sayHello(); // hello,woman!
    }
}
```

> 🎯 静态类型相同（`Human`），但实际类型不同，动态分派根据实际类型找到正确版本。

### 8.3 两种分派对比

| 对比维度 | 静态分派（重载） | 动态分派（重写） |
|---------|----------------|----------------|
| 发生阶段 | 编译期 | 运行期 |
| 依据 | 参数的**静态类型** | 接收者的**实际类型** |
| 指令 | invokestatic / invokespecial | invokevirtual / invokeinterface |
| 性能 | 无需运行时查找，速度快 | 需在方法表查找，有微小开销 |
| 典型场景 | 方法重载 | 方法重写、多态 |
| 改变条件 | 重载多个版本的参数类型不同 | 子类重写父类方法 |

### 8.4 动态分派底层机制：虚方法表

JVM在方法区建立**虚方法表（vtable）** 加速动态分派：每个类维护一个方法表，包含所有虚方法的实际入口地址；子类重写后直接指向子类实现，避免遍历父类链。

```
Object 虚方法表: [hashCode → Object, equals → Object, ...]
Human 虚方法表:   [hashCode → Human, equals → Object, sayHello → Human, ...]
Man 虚方法表:     [hashCode → Man, equals → Object, sayHello → Man, ...]
Woman 虚方法表:   [hashCode → Woman, equals → Object, sayHello → Woman, ...]
```

## 9. invokedynamic与Lambda实现

### 9.1 背景与定位

JDK7引入，最初为动态语言（Scala/Groovy/JRuby）高效运行而设计，JDK8通过Lambda被Java开发者广泛接触。

### 9.2 与传统调用指令的核心区别

| 对比维度 | invokevirtual等传统指令 | invokedynamic |
|---------|----------------------|--------------|
| 分派逻辑 | 固化在JVM内部（虚方法表等） | 由**用户自定义的引导方法（BSM）** 决定 |
| 灵活性 | 方法版本的选择逻辑固定 | 可在运行时动态改变调用目标 |
| 方法引用 | 编译时确定符号引用 | 运行时通过BSM解析出目标方法句柄 |
| 性能开销 | 少量（虚方法表直接定位） | 首次调用BSM有开销，后续缓存优化 |

### 9.3 Lambda底层实现原理

```java
// 源代码
List<User> list = ...;
list.forEach(user -> System.out.println(user.getName()));
```

Lambda不是匿名内部类的语法糖！底层由`invokedynamic` + `LambdaMetafactory`实现：

1. 编译器将Lambda体提取为**私有静态方法**（如`lambda$main$0`）
2. 使用`invokedynamic`指令指向`LambdaMetafactory`作为引导方法（BSM）
3. 首次调用时BSM生成函数式接口（如`Consumer`）的适配器实现
4. 后续调用直接使用缓存的方法句柄，无额外开销

```java
// 编译后近似实现
private static void lambda$main$0(User user) {
    System.out.println(user.getName());
}
// BSM: LambdaMetafactory.metafactory(caller, "accept", MethodType, ...)
```

> 🎯 Lambda相比匿名内部类的优势：1）不产生额外的.class文件；2）不创建匿名内部类实例（避免多一层`this`引用）；3）变量捕获无需复制`final`变量（实际是effectively final）。

## 10. 基于栈的字节码解释执行

### 10.1 栈式执行模型

JVM执行引擎采用**基于栈的计算模型**（而非基于寄存器），所有操作数通过操作数栈传递：

```
指令序列举例：i = add(a, b)

编译后字节码：
iload_1       // 将局部变量1（a）压入操作数栈
iload_2       // 将局部变量2（b）压入操作数栈
iadd          // 弹出栈顶两值相加，结果压回栈顶
istore_3      // 将栈顶结果存入局部变量3（i）

操作数栈变化：
步骤1: [a]           ← iload_1
步骤2: [a, b]        ← iload_2
步骤3: [a+b]         ← iadd（弹出a、b，压入结果）
步骤4: []            ← istore_3（弹出结果存入i）
```

### 10.2 javap反汇编实战

对 `calc(3, 5)` 执行 `javap -verbose Sample` 得到：

```java
// calc(int, int) 的字节码
public int calc(int, int);
  descriptor: (II)I
  Code:
    stack=2, locals=3, args_size=3
       0: iload_1                    // 加载 x
       1: iload_2                    // 加载 y
       2: iadd                       // x + y
       3: iconst_2                   // 常量2
       4: imul                       // (x + y) * 2
       5: ireturn                    // 返回

// main 的字节码
  public static void main(java.lang.String[]);
    Code:
      stack=3, locals=3, args_size=1
         0: new           #2           // class Sample
         3: dup                        // 复制引用
         4: invokespecial #3           // Method "<init>":()V
         7: astore_1                   // 存入局部变量1 (s)
         8: aload_1                    // 加载 s
         9: iconst_3                   // 常量3
        10: iconst_5                   // 常量5
        11: invokevirtual #4           // Method calc:(II)I
        14: istore_2                   // 存入局部变量2 (r)
        15: getstatic     #5           // Field System.out
        18: iload_2                    // 加载 r
        19: invokevirtual #6           // Method PrintStream.println
        22: return
```

> 💡 关键观察：1）`new` + `dup` + `invokespecial <init>` 三段式是对象创建的标准字节码模式；2）所有方法参数和返回值通过操作数栈传递；3）`iconst_3`/`iconst_5` 是常量入栈指令，对应源码中的字面量3和5。

### 10.3 解释执行完整流程（Spring Boot接口调用场景）

以 `UserController.getUserById(Long id)` 调用 `userService.getUserById(id)` 为例：

```
1. 类加载 → 加载UserController.class到方法区
2. 栈帧创建 → 为getUserById创建栈帧，压入虚拟机栈
3. aload_0 → 将this压入操作数栈
4. aload_1 → 将方法参数id压入操作数栈
5. invokevirtual → 动态链接找到UserService.getUserById实际地址
   → 创建其栈帧并执行（数据库查询等）
6. 结果返回 → 被调用方法栈帧弹出，结果压入调用者操作数栈
7. return → 当前栈帧弹出，返回结果给前端
```

> 💡 JIT优化：若该接口被高频调用（如每秒1000次），JVM将getUserById标记为热点代码，触发JIT编译为机器指令，后续调用直接执行机器指令，无需再次解析字节码，大幅提升接口响应速度。

## 11. 面试高频考点

### 11.1 Class结构+执行引擎

| 考点 | 答案要点 |
|------|---------|
| 魔数是什么？ | 0xCAFEBABE，u4类型，JVM校验文件身份 |
| 版本号兼容性？ | major_version决定，JDK8=52，JDK17=61，高版本class无法在低版本JVM运行 |
| 常量池索引从几开始？ | 从1开始，0号预留 |
| 字段表存哪些字段？ | 仅存当前类定义字段，不含父类继承字段 |
| 方法表存哪些方法？ | 当前类所有方法（含`<init>`和`<clinit>`），不含父类继承方法 |
| Code属性的作用？ | 存储字节码指令+操作数栈深度+局部变量表容量+异常表 |
| 栈帧包含哪几部分？ | 局部变量表、操作数栈、动态链接、方法返回地址 |
| 操作数栈最大深度谁决定？ | 编译期由javac计算写入Code属性的`max_stack` |
| invokevirtual与invokespecial区别？ | virtual动态分派（多态），special静态分派（构造器/私有/super） |
| 重载（Overload）分派类型？ | 静态分派，编译期根据参数静态类型确定 |
| 重写（Override）分派类型？ | 动态分派，运行期根据接收者实际类型确定 |
| invokedynamic引导方法？ | 用户自定义BSM（Lambda场景为LambdaMetafactory） |
| Lambda底层实现？ | invokedynamic + LambdaMetafactory |
| StackOverflowError原因？ | 无限递归、方法嵌套过深、-Xss过小 |
| JIT编译触发条件？ | 热点代码计数达CompileThreshold（JDK8默认10000次） |

### 11.2 常见异常排查速查

| 异常类型 | 根源定位 | 解决方向 |
|---------|---------|---------|
| `ClassFormatError` | 魔数错误/访问标志非法组合/文件损坏 | 重新编译或替换class |
| `UnsupportedClassVersionError` | 编译JDK版本 > 运行JDK版本 | 统一编译和运行JDK版本 |
| `NoSuchMethodError` | 方法名/描述符不匹配 | 检查依赖版本冲突 |
| `NoSuchFieldError` | 字段名/描述符不匹配 | 检查实体类与字节码一致性 |
| `StackOverflowError` | 栈帧数量超限 | 修复递归、优化嵌套层次、增大-Xss |
| `Unknown Source` | 缺少SourceFile属性 | 编译时添加-g参数保留调试信息 |

> 🎯 核心总结：Class文件是Java跨平台的基石，字节码执行引擎是JVM的核心动力。读懂Class结构能快速定位版本冲突和类加载异常，理解栈帧机制能有效预防StackOverflowError，掌握方法分派原理看透多态和Lambda的本质，而JIT编译优化是后端高并发应用性能提升的关键底层支撑。
