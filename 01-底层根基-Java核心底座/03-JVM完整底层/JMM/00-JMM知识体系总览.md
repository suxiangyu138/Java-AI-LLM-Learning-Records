## 3. 学习路线推荐

**路线 A：并发面试必读（1 天，推荐）**
01 → 03 → 04 → 05。覆盖面试 90% 的 JMM 问题：happens-before 七规则、volatile 语义、为什么要有内存模型。

**路线 B：并发原理深潜（2-3 天）**
路线 A + 02 + 06。补上硬件层（缓存一致性、内存屏障）与原子层（CAS、锁升级）——理解"为什么 volatile 是那个成本"。

**路线 C：并发专家（面向高阶）**
路线 B + 07 + 08。工具类源码级的 HB 边分析、JEP 491 等 2024-2026 演进、性能验证方法论。

## 4. 核心概念速查

| 概念 | 一句话定义 | 关键事实 |
|------|-----------|---------|
| JMM | JLS 第 17 章定义的并发语义契约 | 自 2004（Java 5）起稳定 |
| 可见性 | 一个线程的写何时对另一线程可见 | 缺 HB 边 → 允许读到旧值 |
| 有序性 | 允许/禁止哪些重排序 | 单线程内 as-if-serial |
| 原子性 | 哪些操作不可分割 | 引用与 int 天然原子 |
| 重排序 | 编译器/处理器/内存系统调整顺序 | 三类来源 |
| Happens-Before | 可见性保证的偏序关系 | 7 条规则 + 传递性 |
| volatile | 可见性 + 有序性（无原子性） | 读写带全屏障（x86） |
| synchronized | 互斥 + 可见性 + 原子性 | monitorenter/exit |
| CAS | 比较并交换（原子指令） | ABA 问题的来源 |
| 内存屏障 | 处理器级指令（lfence/sfence/mfence） | x86 语义比 ARM 强 |
| 锁升级 | 偏向→轻量→重量级 | 偏向锁 JDK 18 移除 |
| JEP 491 | JDK 24：虚拟线程不再被 synchronized pinning | 2025-03 发布 |

> 🎯 **核心要点**：JMM 是 Java 并发正确性的"宪法"——它不规定实现（不指定屏障指令），只规定**语义契约**：满足 happens-before 的两个操作之间，读写必然有序可见；不满足时，一切"奇怪"（重排序、旧值）都是合法的。理解"契约而非实现"是 JMM 学习的第一性原理。
