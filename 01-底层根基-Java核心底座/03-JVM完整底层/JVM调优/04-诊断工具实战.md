## 1. 工具全景：六把手术刀

| 工具 | 用途 | 场景 | 开销 |
|------|------|------|:----:|
| **jstat** | GC/类加载统计 | 快速看堆与 GC 趋势 | 极低 |
| **jmap / jcmd** | 堆转储/直方图 | 泄漏分析素材 | 高（转储暂停） |
| **jstack** | 线程栈 | 死锁/阻塞/热点 | 低 |
| **jcmd** | 综合诊断 | 诊断首选（替代多数 jmap/jstack） | 低-中 |
| **JFR** | 飞行记录 | **现代首选**（全量事件） | 低（<2%） |
| **Arthas** | 在线诊断 | 免重启排查（线上利器） | 低-中 |

**现代工具观（2026）**：

```text
① jcmd 是"综合瑞士军刀"（JDK 8+ 推荐替代 jmap/jstack 的命令）
② JFR 是"黑匣子"（启动即记录，事故后分析）——首选
③ Arthas 是"线上手术台"（不重启改代码/看变量/热更新）
④ 老工具（jmap/jstack）依然有效，但 jcmd/JFR 更安全现代
```

> 🎯 **核心要点**：工具观 = "**jcmd 综合、JFR 首选、Arthas 线上**"——**JFR 常开（低开销）**是现代诊断的第一习惯；工具选择按"要不要停服务"划分。

## 2. jstat：GC 统计速查

```bash
# GC 统计（间隔 1000ms，输出 10 次）
jstat -gcutil <pid> 1000 10
# 输出列：
#   S0/S1（幸存区使用%）、E（Eden%）、O（老年代%）
#   M（元空间%）、CCS（压缩类%）、YGC/YGCT（Young GC 次数/耗时）
#   FGC/FGCT（Full GC 次数/耗时）、GCT（总耗时）

# 类加载统计
jstat -class <pid>
# 内存布局
jstat -gccapacity <pid>
```

**jstat 判读要点**：

```text
① O（老年代%）持续高位（>90%）→ Full GC 风险 → 查 IHOP/泄漏
② FGC 频率高 → 标记跟不上/存活集大
③ YGC 极频繁 → 分配速率高（优化代码而非调参）
④ M（元空间）持续增长 → 类加载器泄漏风险

示例判读：
  O: 95% 且 FGC 每 5 分钟一次 → 老年代压力 → 降 IHOP/查大对象
  O: 60% 稳定但 YGC 每秒 10 次 → 分配太快 → 优化对象创建
```

> 🎯 **核心要点**：jstat = "**GC 仪表盘（快速健康检查）**"——**`-gcutil` 五列（O/E/M/FGC/GCT）**是最高频用法；"O 高位 + FGC 频繁"与"YGC 频繁但 O 平稳"是两种完全不同的病。

## 3. jmap / jcmd：堆信息与转储

```bash
# jmap（传统）：
jmap -heap <pid>            # 堆配置与使用概况
jmap -histo <pid> | head    # 对象直方图（类 → 实例数/大小）
jmap -histo:live <pid>      # 只统计存活对象（触发 Full GC！慎用）

# jcmd（现代推荐）：
jcmd <pid> GC.heap_info     # 堆信息（替代 jmap -heap）
jcmd <pid> GC.class_histogram   # 类直方图（替代 jmap -histo）
jcmd <pid> GC.heap_dump heap.hprof   # 堆转储（生产安全）

# 老命令保留：jmap -dump:format=b,file=heap.hprof <pid>
```

**堆转储的注意事项**：

```text
① 转储会暂停 JVM（大堆可能秒级-分钟级）——生产谨慎/低峰
② 转储前确认大小：jcmd GC.heap_info → 评估磁盘空间
③ 分析工具：MAT（Eclipse）/ JProfiler / VisualVM
④ MAT 分析流程：Histogram → Dominator Tree → Leak Suspects
   → 找大对象 + GC Roots 引用链
```

**对象直方图的快速判读**：

```text
大数组/大集合/大量同类型对象 = 嫌疑
byte[] 巨大 → 大 JSON/IO 缓冲
自定义业务对象大量 → 缓存未清理/集合泄漏
String 大量 → 字符串去重（UseStringDeduplication）
```

> 🎯 **核心要点**：堆诊断 = "**jcmd 三件（heap_info/class_histogram/heap_dump）**"——**生产转储用 jcmd 更安全**；直方图找嫌疑、MAT 找引用链，两步完成泄漏定位。

## 4. jstack：线程栈与死锁

```bash
# 线程栈（死锁/阻塞/热点定位）
jstack <pid> > thread.dump
# 或：jcmd <pid> Thread.print

# 多次抓取对比（确认线程是否卡住）
jstack <pid> >> dump1.txt; sleep 5; jstack <pid> >> dump2.txt
```

**jstack 判读要点**：

| 状态 | 含义 | 排查方向 |
|------|------|---------|
| RUNNABLE | 运行中 | 可能 CPU 热点（结合 top） |
| BLOCKED | 等锁 | 锁竞争（谁持有） |
| WAITING | 无限等待 | 池耗尽/join/等待 |
| TIMED_WAITING | 限时等待 | sleep/限时锁（大量=异常） |

```text
死锁定位：jstack 输出末尾的 "Found one Java-level deadlock"
   → 直接给出死锁线程对与锁链（JVM 自动检测）
线程池耗尽：大量 WAITING（等待任务队列）
   → 见 Java多线程/06 与 Java异常体系/07
```

> 🎯 **核心要点**：jstack = "**线程问题定位器**"——**死锁（自动检测）+ 阻塞（BLOCKED 找锁持有者）+ 池耗尽（WAITING 大量）**三场景；多次抓取对比确认"真卡住"。

## 5. JFR：现代诊断首选

**JFR（Java Flight Recorder，JDK 11 内置）**：低开销（<2%）的全量事件记录——**"黑匣子"式诊断**：

```bash
# 启动时记录（推荐：事故后分析）
-XX:StartFlightRecording=filename=app.jfr,duration=1h
# 运行时开启
jcmd <pid> JFR.start filename=app.jfr duration=1h
jcmd <pid> JFR.dump filename=app.jfr     # 导出
jcmd <pid> JFR.stop

# 分析：JMC（JDK Mission Control）打开 .jfr
```

**JFR 的核心事件（调优视角）**：

| 事件 | 回答的问题 |
|------|-----------|
| GC 暂停（G1 等） | 停顿分布（P95/P99） |
| 分配速率（Allocation） | 对象创建速度（代码优化依据） |
| 晋升速率（Promotion） | 老年代压力来源 |
| Live Set | 真实存活集（堆规划依据） |
| GC CPU | 吞吐损耗 |
| 锁竞争（Monitor） | 锁热点（与多线程联动） |
| IO | 阻塞来源 |

```text
JFR 的优势：
  ① 常开低开销（<2%）→ 事故后"黑匣子"可查
  ② 事件丰富（GC/锁/IO/CPU 全覆盖）
  ③ 现代生产标配（许多公司默认开启）
```

> 🎯 **核心要点**：JFR = "**现代诊断首选（黑匣子）**"——**启动即开（<2% 开销）**，事故后分析全量事件；与 GC 日志互补（日志看 GC、JFR 看全貌）；面试谈"线上怎么排查"先答 JFR = 加分。

## 6. Arthas：在线诊断神器

**Arthas（阿里开源）**：免重启的在线诊断——线上问题的"手术台"：

```bash
# 启动（attach 到目标进程）
curl -O https://arthas.aliyun.com/arthas-boot.jar
java -jar arthas-boot.jar          # 选择目标进程

# 核心命令：
dashboard                  # 全局看板（CPU/内存/线程/GC）
thread -n 3                # 最忙的 3 个线程（CPU 热点）
thread -b                  # 阻塞线程（死锁）
jad com.example.OrderService   # 反编译线上代码
watch com.example.OrderService getOrder '{params, returnObj}'   # 方法入参出参
trace com.example.OrderService getOrder    # 方法耗时（定位慢调用）
sc / sm                     # 类/方法搜索
ognl -x 3 '@xxx@yyy'        # 在线执行表达式（看变量）
```

**Arthas 的核心场景**：

| 场景 | 命令 | 价值 |
|------|------|------|
| CPU 高 | thread -n 3 / dashboard | 秒级定位热点线程 |
| 方法慢 | trace | 定位耗时瓶颈（不用加日志重启） |
| 参数异常 | watch | 看线上真实入参/出参 |
| 死锁 | thread -b | 阻塞线程 |
| 类版本疑问 | jad | 确认线上跑的代码 |

> 🎯 **核心要点**：Arthas = "**线上免重启诊断**"——**thread（热点）+ trace（耗时）+ watch（参数）+ jad（代码）**四命令覆盖 80% 线上排查；生产利器但需权限管控（可执行 ognl）。

## 7. 工具选择速查

**场景 → 工具速查**（面试/生产快查）：

| 场景 | 首选工具 | 备选 |
|------|---------|------|
| GC 健康检查 | jstat -gcutil | JFR GC 事件 |
| 堆使用概况 | jcmd GC.heap_info | jmap -heap |
| 对象嫌疑 | jcmd GC.class_histogram | jmap -histo |
| 泄漏分析 | jcmd heap_dump + MAT | JFR 分配事件 |
| 死锁/阻塞 | jstack / jcmd Thread.print | Arthas thread -b |
| CPU 热点 | Arthas thread -n | top + jstack |
| 全量事故分析 | **JFR** | — |
| 线上免重启 | Arthas | jcmd（有限） |
| 原生内存 | jcmd VM.native_memory | — |

**工具链总口诀**：

```text
"jstat 快看、jcmd 综合、JFR 黑匣、
 Arthas 线上、MAT 分析堆、jstack 找线程"
```

> 🎯 **核心要点**：工具选择 = "**场景定工具**"——**九场景一表**覆盖调优与排查全链路；**JFR 常开 + Arthas 线上 + jcmd 综合**是现代三件套（老工具 jstat/jmap/jstack 作为快速补充）。
