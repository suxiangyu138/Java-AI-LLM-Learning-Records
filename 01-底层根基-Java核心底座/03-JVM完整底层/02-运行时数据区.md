## 1. 运行时数据区全景图

JVM在执行Java程序过程中会将其管理的内存划分为若干不同的数据区域，统称为运行时数据区。理解这些区域的划分是掌握JVM的基石。

```ascii
┌───────────────────────────────────────────────────────────────────────┐
│                       JVM Runtime Data Areas                          │
│                                                                       │
│  ┌──────────────────────────────┐  ┌──────────────────────────────┐  │
│  │      Thread Shared           │  │       Thread Private          │  │
│  │                              │  │                              │  │
│  │  ┌────────────────────────┐  │  │  ┌────────────────────────┐  │  │
│  │  │   Java Heap (堆)       │  │  │  │  Program Counter      │  │  │
│  │  │  ┌─────┬────┬────┐    │  │  │  │  (无OOM风险)           │  │  │
│  │  │  │Eden │ S0 │ S1 │    │  │  │  └────────────────────────┘  │  │
│  │  │  ├─────┴────┴────┤    │  │  │  ┌────────────────────────┐  │  │
│  │  │  │   Old Gen     │    │  │  │  │  JVM Stack (虚拟机栈)   │  │  │
│  │  │  └────────────────┘    │  │  │  │  StackOverflow/OOM    │  │  │
│  │  │  String Pool (JDK7+)   │  │  │  └────────────────────────┘  │  │
│  │  └────────────────────────┘  │  │  ┌────────────────────────┐  │  │
│  │  ┌────────────────────────┐  │  │  │  Native Method Stack   │  │  │
│  │  │  Metaspace (方法区)    │  │  │  │  (HotSpot合并实现)      │  │  │
│  │  │  类元数据/常量池/JIT   │  │  │  └────────────────────────┘  │  │
│  │  └────────────────────────┘  │  │                              │  │
│  └──────────────────────────────┘  └──────────────────────────────┘  │
│  ┌────────────────────────────────────────────────────────────────┐  │
│  │         Direct Memory (直接内存, 堆外NIO Buffer)                │  │
│  └────────────────────────────────────────────────────────────────┘  │
└───────────────────────────────────────────────────────────────────────┘
```

### 1.1 线程私有 vs 线程共享

| 区域 | 线程归属 | 存储内容 | OOM风险 | JVM参数 |
|------|---------|---------|---------|---------|
| **程序计数器** | 私有 | 字节码指令地址（Native→Undefined） | **无** | 无 |
| **虚拟机栈** | 私有 | 栈帧（局部变量表/操作数栈/动态链接/返回地址） | `StackOverflowError` / `OOM` | `-Xss` |
| **本地方法栈** | 私有 | Native方法栈帧 | `StackOverflowError` / `OOM` | `-Xss`（HotSpot合并） |
| **Java堆** | **共享** | 对象实例、数组、字符串常量池（JDK7+） | `Java heap space` | `-Xms` / `-Xmx` |
| **方法区/元空间** | **共享** | 类元数据、常量池、静态变量、JIT代码缓存 | `Metaspace` | `-XX:MetaspaceSize` / `-XX:MaxMetaspaceSize` |
| **直接内存** | 共享（非JVM规范） | NIO DirectByteBuffer | `Direct buffer memory` | `-XX:MaxDirectMemorySize` |

### 1.2 栈帧结构

```ascii
       ┌──────────────────────────────────────────────┐
       │              Stack Frame                     │
       │  ┌────────────────────────────────────────┐  │
       │  │  Local Variable Table                  │  │
       │  │  Slot 0: this (实例方法)                │  │
       │  │  Slot 1..N: 参数和局部变量              │  │
       │  │  long/double 占 2 Slot                 │  │
       │  └────────────────────────────────────────┘  │
       │  ┌────────────────────────────────────────┐  │
       │  │  Operand Stack (LIFO)                   │  │
       │  │  字节码指令的工作空间                    │  │
       │  └────────────────────────────────────────┘  │
       │  ┌────────────────────────────────────────┐  │
       │  │  Dynamic Linking → 运行时常量池引用     │  │
       │  └────────────────────────────────────────┘  │
       │  ┌────────────────────────────────────────┐  │
       │  │  Return Address (调用者的PC值)          │  │
       │  └────────────────────────────────────────┘  │
       └──────────────────────────────────────────────┘
```

> 💡 **栈帧大小在编译期确定**：局部变量表大小和操作数栈深度在编译时写入Code属性，JVM运行时不改变。

## 2. 程序计数器（PC Register）

| 特性 | 说明 |
|------|------|
| 线程归属 | **私有**，每个线程独立拥有 |
| Java方法 | 记录当前执行的字节码指令地址 |
| Native方法 | 值为 **Undefined**（空） |
| OOM风险 | **唯一没有OOM的区域** |

> 🎯 多线程并发执行的基石——线程切换后通过PC恢复执行位置。

```java
public class PCRegisterDemo {
    public static void main(String[] args) {
        new Thread(() -> {
            int sum = 0;
            for (int i = 0; i < 100; i++) sum += i;
        }, "线程A").start();
        new Thread(() -> {
            int product = 1;
            for (int i = 1; i <= 10; i++) product *= i;
        }, "线程B").start();
        // 两个线程的PC互不影响
    }
}
```

## 3. Java虚拟机栈（JVM Stack）

每个方法调用创建一个栈帧（入栈），方法返回时栈帧出栈。

| 特性 | 说明 |
|------|------|
| 线程归属 | **私有**，生命周期与线程相同 |
| 默认大小 | ~1024KB（平台相关） |
| 参数 | `-Xss256k` ~ `-Xss2m` |
| 异常1 | `StackOverflowError`：递归过深，栈深度超限 |
| 异常2 | `OOM`：栈动态扩展时无法申请足够内存（或线程过多） |

### 3.1 操作数栈字节码示例

```java
public class OperandStackDemo {
    public int sum() {
        int a = 1;      // iconst_1 → istore_1
        int b = 2;      // iconst_2 → istore_2
        return a + b;   // iload_1 → iload_2 → iadd → ireturn
    }
}
```

### 3.2 栈溢出演示

```java
public class StackOverflowDemo {
    private static int depth = 0;
    public static void recursiveCall() { depth++; recursiveCall(); }
    public static void main(String[] args) {
        try { recursiveCall(); } catch (StackOverflowError e) {
            System.out.println("递归深度 = " + depth);
            // -Xss256k → ~800  |  -Xss512k → ~2500  |  -Xss1m → ~10000+
        }
    }
}
```

### 3.3 线程过多OOM

```java
public class StackOOMDemo {
    public static void main(String[] args) {
        while (true) new Thread(() -> {
            try { Thread.sleep(Long.MAX_VALUE); }
            catch (InterruptedException e) { Thread.currentThread().interrupt(); }
        }).start();
    }
    // java.lang.OutOfMemoryError: unable to create new native thread
}
```

| `-Xss` | 递归深度（约） | 适用场景 |
|--------|--------------|---------|
| 128k | 400~500 | 极度受限 |
| 256k | 800~1000 | 大量线程场景 |
| 512k | 2000~3000 | 通用 |
| 1m | 10000~20000 | 默认值 |
| 2m | 20000+ | 深度递归 |

> ⚠️ 减小栈大小可创建更多线程：`-Xss256k` 使每线程栈从1MB降到256KB，相同物理内存下可创建更多线程。

## 4. 本地方法栈（Native Method Stack）

与虚拟机栈作用相似，区别在于为**Native方法**（JNI调用C/C++实现）服务。

| 特性 | 说明 |
|------|------|
| 服务对象 | JNI调用的Native方法 |
| HotSpot实现 | **与虚拟机栈合并** |
| 异常 | `StackOverflowError` / `OOM`（同虚拟机栈） |

```java
public class NativeMethodDemo {
    public native void nativePrint(String message);    // JNI声明
    static { System.loadLibrary("native-lib"); }       // 加载本地库
    public static void main(String[] args) {
        new NativeMethodDemo().nativePrint("Hello JNI");
    }
}
```

> 💡 Java标准库大量使用native方法：`Object.hashCode()`、`System.currentTimeMillis()`、`Thread.start()` 等均通过JNI调用。

## 5. Java堆（Heap）

**最大**的一块内存，所有线程共享，存放对象实例。

| 特性 | 说明 |
|------|------|
| 线程归属 | **所有线程共享** |
| 存储内容 | 对象实例、数组、字符串常量池（JDK7+） |
| GC主战场 | 新生代 + 老年代 |
| 参数 | `-Xms`（初始堆）、`-Xmx`（最大堆） |

### 5.1 堆内存布局

```ascii
                          Java Heap
┌────────────────────────────────────────────────────────────────────────┐
│  ┌──────────────────────────────────┬──────────────────────────────┐   │
│  │      Young Gen (默认1/3堆)       │       Old Gen (默认2/3堆)     │   │
│  │  ┌────────┬────────┬────────┐   │                              │   │
│  │  │ Eden   │  S0    │  S1    │   │  大对象/长期存活对象          │   │
│  │  │ (80%)  │ (10%)  │ (10%)  │   │                              │   │
│  │  └────────┴────────┴────────┘   │                              │   │
│  │  TLAB 分配热点                   │                              │   │
│  └──────────────────────────────────┴──────────────────────────────┘   │
│  ┌──────────────────────────────────────────────────────────────────┐  │
│  │  String Pool (JDK7+移入堆) / 静态变量 (JDK7+移入堆)              │  │
│  └──────────────────────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────────────────────┘
```

### 5.2 对象分配与晋升

```ascii
新对象 → 逃逸分析
  ├── 未逃逸 → 栈上分配 (标量替换, 无GC)
  └── 已逃逸 → TLAB分配 (线程私有, 无锁)
                 ├── TLAB不足 → Eden加锁分配
                 └── >PretenureSizeThreshold → 直接在老年代分配
Minor GC: Eden存活对象→S0/S1, age++
  age ≥ MaxTenuringThreshold(默认15) → 晋升老年代
```

### 5.3 TLAB机制

```java
public class TLABDemo {
    public static void main(String[] args) {
        byte[] small = new byte[1024];              // TLAB 分配
        byte[] big = new byte[1024 * 1024];         // 可能直接在老年代
    }
}
```

### 5.4 大对象直接进老年代

```java
/**
 * JVM: -Xms20m -Xmx20m -Xmn10m -XX:SurvivorRatio=8
 *      -XX:PretenureSizeThreshold=3m -XX:+UseSerialGC
 */
public class PretenureDemo {
    private static final int _1MB = 1024 * 1024;
    public static void main(String[] args) {
        byte[] allocation = new byte[4 * _1MB];  // 4MB > 3MB, 直接老年代
    }
}
```

### 5.5 堆参数速查

```bash
-Xms4g -Xmx4g                          # 初始=最大（避免动态扩容）
-Xmn1024m                              # 新生代大小
-XX:NewRatio=2                         # 老年代/新生代=2
-XX:SurvivorRatio=8                    # Eden:S0:S1 = 8:1:1
-XX:MaxTenuringThreshold=15            # 晋升年龄阈值
-XX:PretenureSizeThreshold=3m          # 大对象直接进老年代
-XX:+UseTLAB                           # 开启TLAB(默认)
```

> ⚠️ 生产环境建议 `-Xms = -Xmx`，配合 `-XX:+AlwaysPreTouch` 使JVM启动时即向OS申请物理内存，避免运行时扩容抖动。

## 6. 方法区与元空间（Method Area & Metaspace）

存储已加载的**类型信息、常量、静态变量、JIT编译代码**。

| Java版本 | 实现 | 位置 | 参数 |
|----------|------|------|------|
| JDK 6- | 永久代（PermGen） | JVM堆内 | `-XX:PermSize` / `-XX:MaxPermSize` |
| JDK 7 | 永久代（逐步移除） | JVM堆内 | String池/静态变量移入堆 |
| JDK 8+ | **元空间（Metaspace）** | **本地内存** | `-XX:MetaspaceSize` / `-XX:MaxMetaspaceSize` |

### 6.1 永久代 vs 元空间

| 永久代痛点 | 元空间优势 |
|-----------|-----------|
| 固定大小上限，容易OOM | 使用本地内存，理论上限受物理内存限制 |
| 与堆耦合，Full GC才回收 | 独立管理，类卸载更灵活 |
| GC效率低下 | 减少FGC触发频率 |

### 6.2 元空间存储内容

| 类别 | 内容 |
|------|------|
| **类型信息** | 类名、修饰符、父类/接口、字段描述、方法描述、字节码 |
| **运行时常量池** | 符号引用（类/字段/方法）+ 字面量（字符串、final常量值）|
| **静态变量** | 引用在元空间，对象实例在堆（JDK7+静态变量整体移至堆）|
| **JIT代码缓存** | 热点方法编译后的机器码 |

### 6.3 元空间参数

```bash
-XX:MetaspaceSize=256m         # 触发FGC的阈值（非初始分配大小）
-XX:MaxMetaspaceSize=512m      # 最大大小（建议设置，防止无限膨胀）
-XX:+UseCompressedClassPointers # 类指针压缩（默认开启）
-XX:CompressedClassSpaceSize=1g # 压缩类空间大小
```

> 💡 `-XX:MetaspaceSize` 不是初始分配量，而是**触发FGC的阈值**——元空间使用量达到此值时JVM触发Full GC卸载无用类。

## 7. 运行时常量池

方法区的一部分，对应Class文件中常量池的运行时表示。

| 类别 | 内容 | 来源 |
|------|------|------|
| **字面量** | 文本字符串、final常量值、基本类型值 | Class文件常量池 |
| **符号引用** | 类/接口/字段/方法的全限定名和描述符 | Class文件常量池 |
| **动态性** | `String.intern()` 可在运行时新增常量 | 运行时 |

```java
public class StringPoolDemo {
    public static void main(String[] args) {
        String s1 = "hello";                 // 常量池创建
        String s2 = "hello";                 // 复用常量池
        System.out.println(s1 == s2);        // true
        String s3 = new String("hello");     // 堆中新对象
        System.out.println(s1 == s3);        // false
        String s4 = s3.intern();             // 返回常量池引用
        System.out.println(s1 == s4);        // true (JDK7+)
        String s5 = "he" + "llo";            // 编译期常量折叠
        System.out.println(s1 == s5);        // true
    }
}
```

| JDK版本 | String常量池位置 | 说明 |
|---------|----------------|------|
| JDK 6 | **永久代** | 大量intern()易PermGen OOM |
| JDK 7 | **堆** | 移入堆，减少PermGen OOM |
| JDK 8+ | **堆** | 元空间取代永久代，常量池仍在堆 |

## 8. 直接内存（Direct Memory）

**非JVM规范定义**的内存区域，通过`ByteBuffer.allocateDirect()`分配堆外内存。

| 特性 | 说明 |
|------|------|
| 归属 | 堆外本地内存（Native Memory）|
| 核心优势 | **零拷贝**，避免Java堆与Native堆间数据复制 |
| 默认上限 | 等于 `-Xmx` |
| 参数 | `-XX:MaxDirectMemorySize` |
| 常见应用 | NIO、Netty、gRPC、大文件传输 |

### 8.1 直接内存 vs 堆内存

| 对比项 | 堆内存 | 直接内存 |
|-------|--------|---------|
| 分配速度 | **快** | 慢（慢10倍+） |
| IO效率 | 需一次中间复制 | **零拷贝** |
| 内存管理 | GC自动管理 | GC回收DirectByteBuffer时释放 |
| OOM类型 | `Java heap space` | `Direct buffer memory` |

```java
public class DirectMemoryDemo {
    private static final int _1MB = 1024 * 1024;
    public static void main(String[] args) {
        ByteBuffer buffer = ByteBuffer.allocateDirect(_1MB);
        buffer.putInt(42); buffer.flip();
        System.out.println(buffer.getInt()); // 42
        buffer = null; // GC时释放直接内存

        // OOM模拟: -XX:MaxDirectMemorySize=32m
        java.util.List<ByteBuffer> list = new java.util.ArrayList<>();
        try { while (true) list.add(ByteBuffer.allocateDirect(_1MB)); }
        catch (OutOfMemoryError e) { System.out.println("Direct buffer OOM"); }
    }
}
```

> ⚠️ 直接内存回收依赖于DirectByteBuffer的GC。Netty等框架使用池化技术管理直接内存，避免频繁分配和泄漏。

## 9. JDK 7 vs JDK 8+ 内存结构变化

### 9.1 各区域位置变化

| 数据 | JDK 6 | JDK 7 | JDK 8+ |
|------|-------|-------|--------|
| 对象实例 | 堆 | 堆 | 堆 |
| 字符串常量池 | 永久代 | **堆** | **堆** |
| 静态变量 | 永久代 | **堆** | **堆** |
| 类元数据 | 永久代 | 永久代 | **元空间（本地内存）** |
| 运行时常量池 | 永久代 | 永久代 | **元空间** |
| JIT代码缓存 | 永久代 | 永久代 | **元空间** |
| 方法区实现 | 永久代 | 永久代 | **元空间** |
| 直接内存 | 堆外 | 堆外 | 堆外 |

```ascii
JDK 7:                              JDK 8+:
┌──────────────────┐               ┌──────────────────┐
│      Heap        │               │      Heap        │
│  ┌─────────────┐ │               │  Young + Old     │
│  │ Young + Old  │ │               │  + String Pool   │
│  │ + String Pool│ │               │  + 静态变量       │
│  │ + 静态变量    │ │               └──────────────────┘
│  └─────────────┘ │               ┌──────────────────┐
│  ┌─────────────┐ │               │ 本地内存(Native)  │
│  │  PermGen    │ │               │  ┌─────────────┐ │
│  │类元数据/常量 │ │               │  │  Metaspace  │ │
│  │JIT代码/池   │ │               │  │类元数据/常量 │ │
│  └─────────────┘ │               │  │JIT代码/池   │ │
└──────────────────┘               │  └─────────────┘ │
                                   └──────────────────┘
```

### 9.2 参数变化

| 含义 | JDK 7 (PermGen) | JDK 8+ (Metaspace) |
|------|-----------------|-------------------|
| 初始大小 | `-XX:PermSize` | `-XX:MetaspaceSize` |
| 最大大小 | `-XX:MaxPermSize` | `-XX:MaxMetaspaceSize` |
| 默认最大值 | 64~82MB | 无上限（受物理内存限制） |
| 动态调整 | 不支持 | 支持 |

> 🎯 **一句话总结**：JDK 8将方法区从堆内永久代迁移到本地内存元空间，字符串常量池和静态变量提前在JDK 7移入堆，永久代完全退出历史舞台。

## 10. 各区OOM场景与代码演示

### 10.1 OOM类型速查

| OOM错误 | 区域 | 常见原因 | 排查方向 |
|---------|------|---------|---------|
| `Java heap space` | 堆 | 内存泄漏/数据量过大 | MAT分析dump |
| `Metaspace` | 元空间 | CGLIB过多/类加载泄漏 | `jmap -clstats` |
| `Direct buffer memory` | 直接内存 | NIO未释放Buffer | NMT追踪 |
| `StackOverflowError` | 栈 | 无限递归 | 检查递归条件 |
| `unable to create new native thread` | 栈+OS | 线程过多 | 改用线程池 |
| `GC overhead limit exceeded` | 堆 | 98%时间GC回收<2% | 排查泄漏 |
| `Requested array size exceeds VM limit` | 堆 | 数组超Integer.MAX_VALUE | 检查长度 |

### 10.2 堆OOM

```java
/** -Xms32m -Xmx32m -XX:+HeapDumpOnOutOfMemoryError */
public class HeapOOMDemo {
    public static void main(String[] args) {
        java.util.List<Object> list = new java.util.ArrayList<>();
```

## 11. 面试高频考点

### Q1: 运行时数据区有哪些？哪些线程私有？

**答：** 6大区域。**线程私有**（3个）：程序计数器、虚拟机栈、本地方法栈。**共享**（3个）：堆、方法区（元空间）、直接内存。程序计数器是**唯一不OOM**的区域。

### Q2: 栈帧包含哪几部分？

**答：** 4部分：
1. **局部变量表**：参数和局部变量，Slot单位，long/double占2Slot，实例方法Slot0=this。
2. **操作数栈**：字节码LIFO工作空间。
3. **动态链接**：指向运行时常量池的符号引用，支持多态。
4. **返回地址**：方法退出后恢复调用者位置。

### Q3: JDK 7 → JDK 8+ 内存结构的核心变化？

**答：** 两点：(1) **永久代→元空间**：方法区从堆内PermGen迁移到本地内存Metaspace，避免PermGen OOM。(2) String常量池和静态变量在JDK 7已提前移入堆。

### Q4: 对象在堆中的分配过程？

**答：** 逃逸分析（栈上分配）→ TLAB分配（无锁）→ Eden分配 → 大对象直接进老年代。Minor GC后存活对象复制到Survivor，age≥阈值(默认15)晋升老年代。

### Q5: 各区域OOM参数配置？

```bash
java -Xms4g -Xmx4g                          # 堆
     -XX:MetaspaceSize=256m                 # 元空间阈值
     -XX:MaxMetaspaceSize=512m              # 元空间上限
     -Xss512k                               # 栈大小
     -XX:MaxDirectMemorySize=256m           # 直接内存
     -XX:+HeapDumpOnOutOfMemoryError        # OOM自动dump
     -XX:HeapDumpPath=/data/dump.hprof      # dump路径
```

| 异常 | 触发场景 | 解决 |
|------|---------|------|
| `StackOverflowError` | 递归过深 | 检查递归条件 / 增大`-Xss` |
| `OOM: unable to create new native thread` | 线程过多 | 线程池 / 减小`-Xss` / 调整`ulimit` |

---

> 🎯 **总结**：运行时数据区是JVM的"地基"。掌握各区域的**线程归属、存储内容、OOM风险及参数调优**，是JVM调优和问题排查的第一步。实践中**堆**和**元空间**是OOM重灾区，合理设置 `-Xms`、`-Xmx`、`-XX:MetaspaceSize`、`-XX:MaxMetaspaceSize` 是生产环境的基本要求。
