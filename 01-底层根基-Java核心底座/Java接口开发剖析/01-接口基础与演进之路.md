## 1. 接口的本质：契约 {#1}

### 1.1 接口是什么？

```text
接口 = 一份行为契约

它定义 "能做什么" (What)，不定义 "怎么做" (How)
实现类负责 "怎么做"

            ┌──────────────┐
            │  <<interface>> │
            │   Payment      │  ← 契约：支付
            │──────────────│
            │ + pay(amount) │
            └──────┬───────┘
                   │
      ┌────────────┼────────────┐
      │            │            │
      ▼            ▼            ▼
┌──────────┐ ┌──────────┐ ┌──────────┐
│  WeChat   │ │   Alipay  │ │   Card   │
│   Pay     │ │   Pay     │ │   Pay    │
└──────────┘ └──────────┘ └──────────┘
```

```java
// 契约：支付能力
public interface Payment {
    PayResult pay(BigDecimal amount);  // 抽象方法——每个实现类必须提供
}

// 实现：微信支付
public class WeChatPay implements Payment {
    @Override
    public PayResult pay(BigDecimal amount) {
        // 调用微信支付 API
    }
}
```

### 1.2 接口的三大价值

| 价值 | 说明 | 体现 |
|------|------|------|
| **多态** | 同一接口，不同实现 | `Payment p = new WeChatPay();` |
| **解耦** | 调用方只依赖接口，不依赖实现 | `service.setPayment(payment);` |
| **契约** | 编译期保证方法存在 | `implements Payment` → 必须实现 `pay()` |

## 2. 接口基础语法 {#2}

### 2.1 接口定义

```java
// ── 基础语法 ──
public interface Comparable<T> {
    int compareTo(T o);                  // public abstract（隐式）
}

// ── 接口可以包含 ──
public interface Example {

    // 1. 常量字段（public static final，隐式）
    int MAX_SIZE = 100;
    String DEFAULT_NAME = "unknown";

    // 2. 抽象方法（public abstract，隐式）
    void execute();

    // 3. 默认方法 (JDK 8+)
    default void log(String msg) {
        System.out.println("[LOG] " + msg);
    }

    // 4. 静态方法 (JDK 8+)
    static Example createDefault() {
        return new DefaultExample();
    }

    // 5. 私有方法 (JDK 9+)
    private void commonLogic() {
        // default 方法间共享的代码
    }
}
```

### 2.2 接口的多继承

```java
// ── 接口可以继承多个接口 ──
public interface A {
    void doA();
}
public interface B {
    void doB();
}
public interface C extends A, B {   // 多继承接口
    void doC();
}

// C 的实现必须同时实现 A、B、C 的所有抽象方法
class Impl implements C {
    public void doA() { }
    public void doB() { }
    public void doC() { }
}

// ── 实现多接口 ──
// 一个类可以实现多个接口（突破单继承限制）
public class SmartPhone implements Camera, Phone, MusicPlayer {
    // 必须实现所有接口的抽象方法
}
```

### 2.3 接口 vs 类的关键限制

```java
// ❌ 接口不能做
public interface CannotDo {
    // ❌ 不能有实例字段（只能有 public static final 常量）
    // private String name;

    // ❌ 不能有构造器（接口不能被实例化）
    // public CannotDo() {}

    // ❌ 不能有 protected/包级私有的方法
    // protected void helper();
}

// ✅ 接口能做
public interface CanDo {
    // ✅ 静态常量
    int TIMEOUT = 5000;

    // ✅ private 方法 (JDK 9+)
    private void sharedLogic() { }

    // ✅ static 方法 (JDK 8+)
    static CanDo of(String type) { return ...; }

    // ✅ default 方法 (JDK 8+)
    default void doWithDefault() { }
}
```

## 3. JDK 8：默认方法与静态方法 {#3}

### 3.1 为什么需要默认方法？

JDK 8 引入 Stream API，需要在 `Collection` 接口中添加 `stream()` 方法。但 `Collection` 有无数实现类——如果添加抽象方法，所有实现都会编译失败。

```java
// JDK 8 之前的噩梦：
// Collection 接口想加 stream() 方法
// → 所有自定义 Collection 实现全部报错！

// JDK 8 解决方案：默认方法
public interface Collection<E> {
    // 新增的默认方法——现有实现类无需修改
    default Stream<E> stream() {
        return StreamSupport.stream(spliterator(), false);
    }
    default Stream<E> parallelStream() {
        return StreamSupport.stream(spliterator(), true);
    }
}
```

### 3.2 默认方法的使用场景

| 场景 | 示例 |
|------|------|
| **接口演化** | 给已有接口添加新方法，不破坏现有实现 |
| **可选方法** | `Iterator.remove()` —— 默认抛 `UnsupportedOperationException` |
| **便利方法** | `Comparator.reversed()` —— 基于 `compare()` 提供额外功能 |
| **逐步增强** | 先定义核心抽象方法，再通过默认方法添加衍生功能 |

```java
// ── 默认方法模式：核心抽象 + 衍生默认 ──
public interface Calculator {
    // 核心抽象方法：必须实现
    int compute(int a, int b);

    // 衍生默认方法：基于核心方法提供便利
    default int add(int a, int b) { return compute(a, b); }
    default int subtract(int a, int b) { return compute(a, -b); }
    default int multiply(int a, int b) {
        int result = 0;
        for (int i = 0; i < b; i++) result = add(result, a);
        return result;
    }
}
```

### 3.3 菱形继承问题

```java
// 两个接口提供同名默认方法 → 冲突！
public interface A {
    default void hello() { System.out.println("A"); }
}
public interface B {
    default void hello() { System.out.println("B"); }
}

// 规则1: 类优先于接口
class Parent {
    public void hello() { System.out.println("Parent"); }
}
class Child extends Parent implements A {
    // hello() 使用 Parent 的版本（类优先）
}

// 规则2: 子接口优先于父接口
interface C extends A {
    default void hello() { System.out.println("C"); }  // 覆盖 A
}

// 规则3: 冲突时必须显式覆盖
class Conflict implements A, B {
    @Override
    public void hello() {
        A.super.hello();  // 显式选择 A 的版本
        // 或 B.super.hello();
        // 或提供全新实现
    }
}
```

### 3.4 静态方法

```java
public interface Parser {
    Document parse(String input);

    // 静态工厂方法（替代工具类）
    static Parser json() { return new JsonParser(); }
    static Parser xml() { return new XmlParser(); }

    // 静态工具方法
    static boolean isValidFormat(String input, String format) {
        return input != null && input.startsWith("{") == "json".equals(format);
    }
}

// 使用
Parser parser = Parser.json();    // 不用 new ParserFactory().create()
Document doc = parser.parse("{}");
```

## 4. JDK 9：私有方法 {#4}

### 4.1 为什么需要私有方法？

多个默认方法可能有共享逻辑。JDK 8 的解决办法是写一个辅助静态方法或辅助接口，不够优雅。

```java
// ❌ JDK 8：默认方法间代码重复
public interface ReportGenerator {
    default String generatePdf(Report r) {
        validate(r);       // 重复调用
        // ... PDF 生成逻辑
        return format(r);  // 重复调用
    }
    default String generateHtml(Report r) {
        validate(r);       // 重复调用
        // ... HTML 生成逻辑
        return format(r);  // 重复调用
    }
    // validate 和 format 被迫写成 static 或提到外部
}

// ✅ JDK 9：私有方法共享代码
public interface ReportGenerator {
    default String generatePdf(Report r) {
        validate(r);
        return format(r, "pdf");
    }
    default String generateHtml(Report r) {
        validate(r);
        return format(r, "html");
    }

    // 私有实例方法
    private void validate(Report r) {
        Objects.requireNonNull(r);
        if (r.isEmpty()) throw new IllegalArgumentException();
    }

    // 私有静态方法
    private static String format(Report r, String type) {
        return "[" + type + "] " + r.getTitle();
    }
}
```

## 5. JDK 17：密封接口 {#5}

### 5.1 传统接口的问题

```java
// 传统接口：谁都可以实现 → 无法穷尽枚举所有可能情况
public interface Shape { double area(); }
// 任何人都可以写 class MyWeirdShape implements Shape {}

// instanceof 检查永远需要 default 兜底
if (shape instanceof Circle c) { ... }
else if (shape instanceof Rectangle r) { ... }
else { /* 永远不知道还有什么！ */ }
```

### 5.2 sealed 接口语法

```java
// ── sealed interface ──
public sealed interface Shape
    permits Circle, Rectangle, Triangle {

    double area();
}

// 允许的子类型必须是 final、sealed 或 non-sealed
public record Circle(double radius) implements Shape {
    public double area() { return Math.PI * radius * radius; }
}

public record Rectangle(double width, double height) implements Shape {
    public double area() { return width * height; }
}

public non-sealed interface Triangle extends Shape {
    // non-sealed → 其他人可以继续实现 Triangle
}
```

### 5.3 编译期穷尽性

```java
// ── 编译器知道 Shape 只有 3 种子类型 ──
public double getArea(Shape shape) {
    return switch (shape) {
        case Circle c    -> c.area();
        case Rectangle r -> r.area();
        case Triangle t  -> t.area();
        // 无需 default！编译器验证了穷尽性
    };
}

// 以后如果给 Shape 添加新子类型 → 所有 switch 自动报编译错误
// → 你不会忘记处理新情况！
```

### 5.4 sealed interface + record = 代数数据类型 (ADT)

```java
// ── 模式：用 sealed interface + record 建模"一个或另一个"──
public sealed interface Result<T> permits Success, Failure {

    record Success<T>(T value) implements Result<T> {}
    record Failure<T>(String error) implements Result<T> {}
}

// 使用
public Result<User> createUser(String name) {
    if (name == null || name.isBlank()) {
        return new Result.Failure<>("用户名不能为空");
    }
    return new Result.Success<>(new User(name));
}

// 调用方
String message = switch (result) {
    case Result.Success<User> s -> "欢迎, " + s.value().getName();
    case Result.Failure<User> f -> "错误: " + f.error();
};
```

## 6. JDK 21：模式匹配 switch {#6}

### 6.1 完整的模式匹配

```java
// ── JDK 17: instanceof 模式匹配 ──
if (obj instanceof String s && s.length() > 5) {
    System.out.println(s.toUpperCase());
}

// ── JDK 21: switch 模式匹配 ──
// 支持 when 子句（守卫）和 record 解构
public String describeShape(Shape shape) {
    return switch (shape) {
        case Circle(var r) when r > 100  -> "巨大的圆 (r=" + r + ")";
        case Circle(var r)                -> "圆 (r=" + r + ")";
        case Rectangle(var w, var h)
            when w == h                   -> "正方形 (边长=" + w + ")";
        case Rectangle(var w, var h)      -> "矩形 (" + w + "x" + h + ")";
        case Triangle t                   -> "三角形";
    };
}
```

### 6.2 密封接口 + 模式匹配的协同效应

```java
// ── AST 节点建模 ──
public sealed interface Expr
    permits Expr.Constant, Expr.Add, Expr.Multiply {

    record Constant(int value) implements Expr {}
    record Add(Expr left, Expr right) implements Expr {}
    record Multiply(Expr left, Expr right) implements Expr {}
}

// 求值 —— 编译器确保覆盖所有情况
public int eval(Expr e) {
    return switch (e) {
        case Expr.Constant(var v)    -> v;
        case Expr.Add(var l, var r)  -> eval(l) + eval(r);
        case Expr.Multiply(var l, var r) -> eval(l) * eval(r);
    };
    // 无 default！添加新 Expr 类型 → 编译报错 → 不会遗漏
}
```

> 🎯 **核心要点**：sealed interface + record + 模式匹配 = Java 的代数数据类型 (ADT)。这是 JDK 17-21 最重要的类型系统进化——让你能用编译器保证代码完整性，而不是靠程序员记住所有情况。
