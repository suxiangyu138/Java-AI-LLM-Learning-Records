## 1. 语法差异全景表 {#1}

| 特性 | 接口 (interface) | 抽象类 (abstract class) |
|------|:---:|:---:|
| **实例字段** | ❌ 只有 `public static final` 常量 | ✅ 任意字段 |
| **构造器** | ❌ | ✅ |
| **抽象方法** | ✅ (public abstract 隐式) | ✅ |
| **具体方法** | ✅ default (JDK 8+) | ✅ |
| **私有方法** | ✅ private (JDK 9+) | ✅ |
| **静态方法** | ✅ (JDK 8+) | ✅ |
| **多继承** | ✅ 可继承多个接口 | ❌ 只能继承一个类 |
| **实现限制** | sealed (JDK 17+) | sealed (JDK 17+) |
| **访问修饰符** | public / private (方法) | public / protected / private |
| **初始化块** | ❌ | ✅ |
| **成员类型** | 隐式 public | 任意 |

```java
// ── 语法差异一目了然 ──

public interface MyInterface {
    // 字段：自动 public static final
    int MAX = 100;          // 等价于 public static final int MAX = 100;

    // 方法：自动 public
    void doAbstract();      // 等价于 public abstract void doAbstract();
    default void doDefault() { }   // 必须有方法体
    static void doStatic() { }     // 必须有方法体
    private void helper() { }      // JDK 9+，必须有方法体
}

public abstract class MyAbstractClass {
    // 字段：可以有任何修饰符
    private String name;
    protected int count;
    public static final int MAX = 100;

    // 构造器
    public MyAbstractClass(String name) {
        this.name = name;
    }

    // 方法
    public abstract void doAbstract();
    public void doConcrete() { }
    protected void doProtected() { }
    private void doPrivate() { }
    public static void doStatic() { }
}
```

## 2. 语义差异：是什么 vs 能做什么 {#2}

### 2.1 核心语义区别

```text
抽象类：定义 "是什么" (IS-A)
├── 描述对象的本质、类别
├── 共享状态和行为
└── 例：Animal (有 name, age), HttpServlet (有 service 方法)

接口：定义 "能做什么" (CAN-DO)
├── 描述对象的能力、行为
├── 跨类型层次共享契约
└── 例：Comparable (能比较), Serializable (能序列化), AutoCloseable (能关闭)
```

### 2.2 经典案例对比

```java
// ── 抽象类：共享状态 ──
public abstract class AbstractVehicle {
    protected String brand;              // ← 共享状态
    protected int speed;

    public AbstractVehicle(String brand) {
        this.brand = brand;              // ← 构造器初始化状态
    }

    public abstract void move();         // ← 抽象行为

    public final void stop() {           // ← final 锁定算法步骤
        decelerate();
        this.speed = 0;
    }
    protected abstract void decelerate();
}

// ── 接口：共享能力 ──
public interface Flyable {
    void fly();                          // ← 纯行为契约
}
public interface Chargeable {
    void charge();
}

// ── 组合使用 ──
public class ElectricCar extends AbstractVehicle
    implements Flyable, Chargeable {     // ← 多重能力

    public ElectricCar(String brand) {
        super(brand);
    }
    public void move() { /* 电动驱动 */ }
    protected void decelerate() { /* 能量回收 */ }
    public void fly() { /* 飞行模式 */ }
    public void charge() { /* 充电 */ }
}
```

### 2.3 何时用抽象类 —— 三个必要条件

```text
同时满足以下条件 → 用抽象类：

1. ✅ 需要共享状态（字段）
   例：所有子类都需要 brand、speed

2. ✅ 需要构造器初始化
   例：构造时必须传入 brand

3. ✅ 需要 protected 方法（子类可访问、外部不可）
   例：decelerate() 只让子类实现

如果只满足 1-2 个 → 考虑接口 + 组合
```

## 3. JDK 演进如何改变选型 {#3}

### 3.1 default 方法是否模糊了界限？

```text
"接口现在也有方法体了，是不是和抽象类一样了？"

回答：不一样。

关键区别：
├── 接口仍不能有状态（实例字段）
├── 接口仍不能有构造器
├── 接口的 default 方法是"可选便利"，不是"共享算法骨架"
└── 抽象类的具体方法通常是"模板方法"——定义算法骨架

结论：default 方法让接口更像"混入 (Mixin)"，但不等同于抽象类
```

```java
// ── default 的正确用法：提供便利 ──
// 不是替代抽象类，而是减少样板代码
public interface Iterator<E> {
    boolean hasNext();        // 核心抽象
    E next();                 // 核心抽象

    // 便捷默认实现（你可能不需要覆盖）
    default void remove() {
        throw new UnsupportedOperationException("remove");
    }

    default void forEachRemaining(Consumer<? super E> action) {
        Objects.requireNonNull(action);
        while (hasNext()) action.accept(next());
    }
}
```

### 3.2 sealed interface + record：抽象类的新替代者

```java
// ── 传统方式：抽象类定义封闭类型体系 ──
public abstract class PaymentResult {
    private PaymentResult() {}  // 私有构造器模拟封闭

    public static final class Success extends PaymentResult {
        private final String transactionId;
        // ... getter
    }
    public static final class Failure extends PaymentResult {
        private final String errorMessage;
        // ... getter
    }
}

// ── 现代方式：sealed interface + record ──
public sealed interface PaymentResult
    permits PaymentResult.Success, PaymentResult.Failure {

    record Success(String transactionId) implements PaymentResult {}
    record Failure(String errorMessage) implements PaymentResult {}
}

// 现代方式优势：
// ✅ 更简洁 (record 自动生成 getter/equals/hashCode/toString)
// ✅ 编译器穷尽性检查
// ✅ 模式匹配 switch 友好
// ✅ 不可变保证 (record)
```

### 3.3 2026 年选型倾向

```text
倾向变化：

2015:  抽象类 40% ─── 接口 60%
2025:  抽象类 15% ─── 接口 85%

原因：
├── sealed interface + record 取代了"封闭类型体系"场景
├── default 方法提供了便利方法的承载
├── 接口支持 private 方法做代码复用
├── 组合优于继承的观念深入人心
└── 多实现能力在微服务/SPI 场景更灵活

抽象类仅剩的核心优势：
└── 共享可变状态 + 模板方法 (真正的"骨架")
```

## 4. 场景选型决策树 {#4}

```text
需要定义一个抽象类型 → 接口 or 抽象类？

├── Q1: 需要共享状态（实例字段）？
│   ├── YES → Q2
│   └── NO  → 接口 ✅
│
├── Q2: 需要保护子类的内部方法 (protected)？
│   ├── YES → 抽象类 ✅
│   └── NO  → Q3
│
├── Q3: 子类是否需要继承其他类？
│   ├── YES → 接口 ✅（只能继承一个类，但可实现多接口）
│   └── NO  → Q4
│
├── Q4: 类型层次是否封闭（已知所有子类型）？
│   ├── YES → sealed interface + record ✅（更强编译检查）
│   └── NO  → Q5
│
└── Q5: 实现类是否共享大量代码（模板方法）？
    ├── YES → 接口 + 骨架抽象类 ✅（组合优于单继承）
    └── NO  → 接口 ✅
```

### 实际场景速查

| 你要做什么 | 用什么 | 为什么 |
|-----------|:---:|------|
| 定义"能排序"的能力 | 接口 `Comparable<T>` | 纯能力，无状态 |
| 定义支付流程（鉴权→风控→扣款→通知） | 抽象类 `AbstractPayment` | 模板方法，固定算法骨架 |
| 定义 REST API 接口 | 接口 `@FeignClient` | 多实现 + 代理 |
| 定义数据库实体基类（id/createdAt/updatedAt） | 抽象类 `BaseEntity` | 共享状态 |
| 定义事件监听器 | 接口 `@EventListener` | 多实现，无状态 |
| 定义消息转换器链 | 接口 `HttpMessageConverter` | 多实现链式组合 |
| 定义命令模式 (Command) | 接口 / sealed interface | 接口简单，sealed 更安全 |

## 5. 混合模式：接口 + 骨架实现类 {#5}

### 5.1 什么是骨架实现？

```text
接口：定义契约
骨架抽象类：提供大部分方法的默认实现，减少实现者工作量

JDK 中的经典案例：
├── Collection → AbstractCollection
├── List → AbstractList
├── Map → AbstractMap
├── Set → AbstractSet
└── Queue → AbstractQueue
```

### 5.2 实战示例

```java
// ── 步骤1: 定义接口（最小化抽象方法）──
public interface DataProcessor<T> {
    T process(T input);
    default T processWithLogging(T input) {
        logBefore(input);
        T result = process(input);
        logAfter(result);
        return result;
    }
    default void logBefore(T input) {
        System.out.println("Processing: " + input);
    }
    default void logAfter(T result) {
        System.out.println("Result: " + result);
    }
}

// ── 步骤2: 提供骨架实现（简化子类工作）──
public abstract class AbstractDataProcessor<T> implements DataProcessor<T> {

    // 提供校验和异常处理的骨架
    @Override
    public T process(T input) {
        validate(input);
        try {
            T result = doProcess(input);
            postProcess(result);
            return result;
        } catch (Exception e) {
            throw new ProcessingException("处理失败: " + input, e);
        }
    }

    // 子类只需实现这个方法！
    protected abstract T doProcess(T input);

    // 可选的钩子方法
    protected void validate(T input) {
        if (input == null) throw new IllegalArgumentException("input is null");
    }
    protected void postProcess(T result) {
        // 默认空实现
    }
}

// ── 步骤3: 实现者非常轻松 ──
public class UppercaseProcessor extends AbstractDataProcessor<String> {
    @Override
    protected String doProcess(String input) {
        return input.toUpperCase();  // 只需写核心逻辑！
    }
}
```

> 🎯 **核心要点**：2026 年的答案——**优先用接口**。抽象类仅在"需要共享状态 + 模板方法骨架"时使用。sealed interface + record 组合正在大量取代传统抽象类的封闭类型体系场景。
