## 1. 三种脚本对比

> **背景**：自动化脚本按平台分三派——Linux 的 Bash、Windows 的 PowerShell/Batch。
> **目的**：掌握三者的语法差异，按平台/场景选对脚本。
> **适用范围**：部署、构建、备份、批量处理等重复操作。
> **不适用场景**：复杂业务逻辑（用真正的编程语言）；跨平台逻辑（优先 Java/Python/Go）。

| 维度 | Bash（.sh） | PowerShell（.ps1） | Batch（.bat） |
|------|:---:|:---:|:---:|
| 平台 | Linux/macOS | Windows（跨平台新版本） | Windows（遗留） |
| 语法 | Unix 风格 | 对象管道 | 老式命令 |
| 变量 | `$x` | `$x` | `%x%` |
| 条件 | `if [ ... ]` | `if (...) {...}` | `if %x%==...` |
| 循环 | `for x in ...` | `foreach ($x in ...)` | `for %%x in (...)` |
| 函数 | `func() {}` | `function f {}` | `:label` + goto |
| 2026 定位 | **服务器标准** | **Windows 标准** | 仅兼容遗留 |
| 适用 | 部署/运维脚本 | Windows 自动化 | 老系统 |

> 🎯 **2026 建议**：**跨平台自动化优先「真正的语言」**（Python/Go/Java）——脚本只用于「平台本地、快速、简单」的场景；Bash 管 Linux 服务器、PowerShell 管 Windows。

## 2. Bash Shell 脚本

### 2.1 脚本基础结构

```bash
#!/bin/bash
# ① shebang：解释器声明（必须第一行！）

# ② 严格模式（2026 推荐——防静默错误）
set -e          # 出错即退出（防止错误继续执行）
set -u          # 未定义变量报错
set -o pipefail # 管道中任一命令失败即失败

# ③ 变量
APP_NAME="order-service"
VERSION=${1:-latest}        # 第一个参数，默认 latest

# ④ 函数
log() {
    echo "[$(date '+%F %T')] $1"
}

# ⑤ 主流程
log "开始部署 $APP_NAME:$VERSION"
```

### 2.2 实战：Java 服务部署脚本

```bash
#!/bin/bash
set -euo pipefail

APP_NAME="order-service"
JAR_PATH="/opt/${APP_NAME}/app.jar"
PID_FILE="/var/run/${APP_NAME}.pid"
LOG_DIR="/var/log/${APP_NAME}"

log() { echo "[$(date '+%F %T')] $*"; }

start() {
    if [ -f "$PID_FILE" ] && kill -0 "$(cat $PID_FILE)" 2>/dev/null; then
        log "服务已在运行 (PID: $(cat $PID_FILE))"
        return 1
    fi
    nohup java -jar "$JAR_PATH" \
        --spring.profiles.active=prod \
        > "${LOG_DIR}/app.log" 2>&1 &
    echo $! > "$PID_FILE"
    log "启动完成 (PID: $!)"
}

stop() {
    if [ ! -f "$PID_FILE" ]; then
        log "服务未运行"
        return 1
    fi
    kill "$(cat $PID_FILE)" && log "已停止" || log "停止失败"
    rm -f "$PID_FILE"
}

restart() { stop; sleep 2; start; }

case "${1:-}" in
    start)   start ;;
    stop)    stop ;;
    restart) restart ;;
    status)  [ -f "$PID_FILE" ] && kill -0 "$(cat $PID_FILE)" 2>/dev/null \
                && echo "运行中" || echo "已停止" ;;
    *) echo "用法: $0 {start|stop|restart|status}"; exit 1 ;;
esac
```

### 2.3 Bash 易错点

```text
Bash 脚本高频坑
├── ⚠️ 空格敏感：[ "$x" = "y" ]（括号内必须有空格！）
├── ⚠️ 未加 set -e：命令失败继续执行（静默错误）
├── ⚠️ 变量未加引号：含空格的文件名被拆分
├── ⚠️ 换行符：Windows 编辑的脚本报 $'\r'（dos2unix）
├── ⚠️ 权限：chmod +x script.sh（否则 Permission denied）
└── ✅ 调试：bash -x script.sh（逐步打印执行）
```

## 3. PowerShell 脚本

### 3.1 基础结构

```powershell
# app.ps1
# ① 执行策略（首次运行需要）
# 以管理员运行：Set-ExecutionPolicy RemoteSigned

# ② 参数
param(
    [string]$AppName = "order-service",
    [string]$Version = "latest"
)

# ③ 函数
function Log($msg) {
    Write-Host "[$(Get-Date -Format 'yyyy-MM-dd HH:mm:ss')] $msg"
}

# ④ 主流程
Log "开始部署 $AppName:$Version"
```

### 3.2 实战：Windows 服务管理

```powershell
# java-service.ps1 —— Windows 上管理 Java 服务
param([ValidateSet("start","stop","restart","status")]$Action)

$AppName = "order-service"
$JarPath = "D:\apps\$AppName\app.jar"
$LogPath = "D:\logs\$AppName\app.log"

function Start-App {
    if (Get-Process -Name "java" -ErrorAction SilentlyContinue) {
        Write-Host "已有 java 进程"
        return
    }
    Start-Process java -ArgumentList "-jar", $JarPath, "--spring.profiles.active=prod" `
        -RedirectStandardOutput $LogPath -WindowStyle Hidden
    Write-Host "已启动"
}

function Stop-App {
    Get-Process -Name "java" -ErrorAction SilentlyContinue | Stop-Process -Force
    Write-Host "已停止"
}

function Get-Status {
    $p = Get-Process -Name "java" -ErrorAction SilentlyContinue
    if ($p) { Write-Host "运行中 (PID: $($p.Id))" } else { Write-Host "已停止" }
}

switch ($Action) {
    "start"   { Start-App }
    "stop"    { Stop-App }
    "restart" { Stop-App; Start-Sleep 2; Start-App }
    "status"  { Get-Status }
}
```

### 3.3 PowerShell 特色

```text
PowerShell 的独特能力（对象管道）
├── ① 对象管道：Get-Process | Where-Object CPU -gt 10（精准过滤）
├── ② 模块化：Import-Module（复用）
├── ③ 远程管理：Invoke-Command -ComputerName（多机执行）
├── ④ 与 .NET 集成：完整 CLR 能力
└── ⑤ 跨平台：PowerShell Core（Linux/macOS 可用）
```

## 4. Batch 批处理

### 4.1 基础结构（遗留但常见）

```bat
@echo off
REM 批处理脚本（cmd 遗留格式）
REM ① @echo off：关闭命令回显

REM ② 变量
set APP_NAME=order-service
set JAR_PATH=D:\apps\%APP_NAME%\app.jar

REM ③ 判断
if exist "%JAR_PATH%" (
    echo 找到 jar 文件
) else (
    echo 未找到 jar 文件
    exit /b 1
)

REM ④ 循环
for %%f in (D:\logs\*.log) do echo 日志: %%f

REM ⑤ 调用
call :func1
goto :eof

:func1
echo 函数 1
goto :eof
```

### 4.2 Batch 的边界

```text
Batch 的局限性（2026 建议）
├── ① 语法古老（goto 代替函数）
├── ② 无对象/模块化
├── ③ 错误处理脆弱
├── ④ 编码问题（中文乱码常见）
└── 建议：新脚本一律 PowerShell；Batch 仅维护遗留
```

## 5. 跨平台定时任务

### 5.1 Linux cron（服务器定时）

```bash
# crontab -e 编辑
# 格式：分 时 日 月 周  命令
#       *  *  *  *  *  command

# 示例
*/5 * * * * /opt/scripts/health-check.sh      # 每 5 分钟健康检查
0 2 * * * /opt/scripts/backup-db.sh           # 每天 2 点备份数据库
30 9 * * 1 /opt/scripts/weekly-report.sh     # 周一 9:30 周报
0 0 1 * * /opt/scripts/cleanup-logs.sh        # 每月 1 号清理日志

# 查看/管理
crontab -l          # 列出
crontab -e          # 编辑
systemctl status cron   # 服务状态

# ⚠️ cron 环境注意：
# ① PATH 与登录 Shell 不同（脚本内写绝对路径！）
# ② 输出默认邮件——重定向：* * * * * cmd >> /var/log/x.log 2>&1
```

### 5.2 Windows 计划任务（schtasks）

```bat
:: 创建计划任务（管理员 cmd）
schtasks /create /tn "HealthCheck" /tr "powershell -File D:\scripts\health.ps1" /sc minute /mo 5
:: /sc 频率：minute/hourly/daily/weekly/monthly/onstart

:: 每天 2 点
schtasks /create /tn "DBBackup" /tr "powershell -File D:\scripts\backup.ps1" /sc daily /st 02:00

:: 管理
schtasks /query /tn "HealthCheck"       :: 查询
schtasks /run /tn "HealthCheck"         :: 手动运行
schtasks /delete /tn "HealthCheck" /f   :: 删除
```

### 5.3 定时任务最佳实践

```text
定时任务规范
├── ① 脚本输出重定向到日志（cron 邮件噪音）
├── ② 脚本内用绝对路径（cron PATH 有限）
├── ③ 先手动跑通再挂定时（防定时才发现错误）
├── ④ 加锁防重叠（长任务重入）：
│   flock -n /tmp/backup.lock /opt/scripts/backup.sh
├── ⑤ 失败告警：脚本失败时发通知
└── ⑥ 日志轮转：日志目录定期清理
```

## 6. Java 开发常用模板

### 6.1 构建与部署脚本

```bash
#!/bin/bash
# build.sh —— Maven 构建 + 测试 + 打包
set -euo pipefail

echo "=== 1/4 编译 ==="
mvn clean compile

echo "=== 2/4 测试 ==="
mvn test

echo "=== 3/4 打包 ==="
mvn package -DskipTests

echo "=== 4/4 产物 ==="
ls -lh target/*.jar
```

```bash
#!/bin/bash
# backup-db.sh —— 数据库备份（定时任务模板）
set -euo pipefail

BACKUP_DIR="/backup/mysql"
DB_NAME="order_db"
DATE=$(date +%Y%m%d_%H%M%S)

mkdir -p "$BACKUP_DIR"

# 备份 + 压缩
mysqldump -u backup "$DB_NAME" | gzip > "$BACKUP_DIR/${DB_NAME}_${DATE}.sql.gz"

# 清理 30 天前的备份
find "$BACKUP_DIR" -name "*.sql.gz" -mtime +30 -delete

echo "备份完成: ${BACKUP_DIR}/${DB_NAME}_${DATE}.sql.gz"
```

### 6.2 环境检查脚本

```bash
#!/bin/bash
# env-check.sh —— 部署前环境检查
set -euo pipefail

check() {
    local name=$1 cmd=$2
    if command -v "$cmd" >/dev/null 2>&1; then
        echo "✅ $name: $($cmd --version 2>&1 | head -1)"
    else
        echo "❌ $name: 未安装"
        return 1
    fi
}

check "Java" java
check "Maven" mvn
check "Git" git
check "Docker" docker

# 检查端口占用
PORT=${1:-8080}
if ss -tlnp | grep -q ":$PORT "; then
    echo "❌ 端口 $PORT 已被占用"
    exit 1
else
    echo "✅ 端口 $PORT 可用"
fi
```

## 7. 脚本安全实践

### 7.1 安全清单

```text
脚本安全七条
├── ① 密钥不进脚本：密码/密钥用环境变量或 Secret 文件
├── ② set -euo pipefail（Bash 防静默错误）
├── ③ 输入校验：参数校验（$1 缺失/非法）
├── ④ 路径安全：脚本内不拼接用户输入路径
├── ⑤ 权限最小：脚本文件 700；不需要 root 就不 sudo
├── ⑥ 日志脱敏：不打印密码/敏感参数
└── ⑦ 代码评审：脚本也走 Review（尤其部署/删除类）
```

### 7.2 密钥处理示例

```bash
#!/bin/bash
# ❌ 错误：密钥写死在脚本
DB_PASSWORD="SuperSecret123"
mysqldump -u root -p"$DB_PASSWORD" ...

# ✅ 正确：环境变量注入
# 部署时：DB_PASSWORD=xxx ./backup.sh
# 或从 Secret 文件读取（权限 600）
DB_PASSWORD="${DB_PASSWORD:-}"    # 必填检查
if [ -z "$DB_PASSWORD" ]; then
    echo "❌ 缺少 DB_PASSWORD 环境变量" >&2
    exit 1
fi
mysqldump -u root -p"$DB_PASSWORD" ...
```

## 8. 核心要点

> 🎯 **核心要点**：
> 1. 三脚本定位：Bash 管 Linux 服务器、PowerShell 管 Windows、Batch 仅遗留——跨平台复杂逻辑用真正的语言
> 2. Bash 必加 `set -euo pipefail`（防静默错误）；调试用 `bash -x`
> 3. PowerShell 对象管道是杀手锏；新脚本一律 PowerShell 而非 Batch
> 4. 定时任务：cron（Linux）/schtasks（Windows）——**绝对路径 + 日志重定向 + 先手动跑通 + flock 防重入**
> 5. 脚本安全：密钥环境变量注入、输入校验、权限最小、脚本也走评审
