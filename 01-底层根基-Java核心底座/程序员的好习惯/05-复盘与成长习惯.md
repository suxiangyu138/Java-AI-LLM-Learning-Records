## 1. 复盘的本质

> 🎯 **核心认知**：工作 1 年 ≠ 1 年经验——可能是同一年的经验重复了 12 次。**经验不会自动变成能力，复盘是转化的唯一通道**：经历（发生了什么）→ 复盘（为什么发生）→ 能力（下次怎么办）。

```text
复盘公式
├── 经历：项目上线遇到性能问题
├── 复盘：根因是查询未加索引 + 未做缓存（三层分析）
├── 能力：下次设计阶段先做容量评估 + 索引规划
└── 闭环：复盘结论 → 写入知识库 → 变成下次的检查清单
→ 不复盘的人：同一个坑踩三次；复盘的人：坑变资产
```

| ❌ 不复盘 | ✅ 复盘 |
|---------|--------|
| 项目结束就翻篇 | 项目结束花 30 分钟复盘 |
| 同一个错反复犯 | 错一次沉淀一条规则 |
| 说不出自己哪强哪弱 | 技能矩阵一目了然 |
| 经验随项目流失 | 经验进知识库沉淀 |

## 2. 个人周复盘

### 2.1 周复盘流程（30 分钟）

> 🎯 **每周复盘**：花半小时过一遍任务看板，问自己四个问题：

```text
周复盘四问（30 分钟）
├── ① 哪些做法有效可复用？
│   └── 记入「有效做法清单」（下周继续用）
├── ② 哪些事超时了？原因是什么？
│   └── 估算偏差？被打断？范围蔓延？→ 调整下周估算
├── ③ 哪些卡片卡在「待反馈」？
│   └── 该主动追一下了（评审/依赖/回复）
└── ④ 下周 TOP3 是什么？
    └── 对齐优先级，避免低价值空转
```

### 2.2 晚间复盘（3 分钟）

```text
晚间复盘（下班前 3 分钟）
├── ① 今天完成了什么（看板勾选）
├── ② 还有什么未完成
├── ③ 写下明日第一件事：「明天继续 API 测试、检查空购物车
│     边界情况、然后提 PR」
└── 价值：减少下班后的心理负担（大脑清空）+
    明天开工即进入状态（无启动成本）
```

> 💡 **Git 思维管理时间**：每天写下「commit message」，晚上检查今天的「代码」是否跑通——用工程思维管理人生，有趣且有效。

## 3. 技术复盘（Retrospective）

### 3.1 技术复盘四维度

| 维度 | 复盘内容 |
|------|---------|
| **技术决策回顾** | 为什么选这个方案？现在看是否仍合理？ |
| **代码质量分析** | 哪些模块 bug 率最高？为什么？ |
| **工具链效率** | 哪些工具/流程拖慢了交付？ |
| **知识沉淀** | 方案文档化，形成团队知识库 |

### 3.2 项目复盘清单

```text
项目结束后 30 分钟技术复盘
├── ① 目标回顾：达成了吗？（数据说话）
├── ② 过程拆解：哪一步最耗时？哪一步最顺利？
├── ③ 问题剖析：最大的 3 个问题？根因？预防措施？
├── ④ 经验提炼：哪些做法值得固化到流程？
├── ⑤ 行动落地：3 条可执行改进 + 负责人 + 截止时间
└── 沉淀：复盘结论写入团队知识库/流程规范
```

### 3.3 错误管理流程

```text
错误管理五步（把错误变成资产）
├── ① 快速识别隔离（止损）
├── ② 记录详细日志 + 复现步骤（保留证据）
├── ③ 根因分析（为什么发生，不只看表象）
├── ④ 制定预防措施（测试/门禁/规范）
└── ⑤ 事后复盘总结经验（写入知识库）
→ 每次事故都是一次免费的评估集扩充
```

## 4. 技能矩阵

### 4.1 什么是技能矩阵

> 🎯 **技能矩阵**：技术领域 / 当前水平 / 目标水平 / 达成路径 四维表格——**让成长可视化、可量化、有路径**，避免无效努力。

```text
技能矩阵示例（个人版）
┌──────────┬──────┬──────┬────────────────────┐
│ 技术领域   │ 当前  │ 目标  │ 达成路径            │
├──────────┼──────┼──────┼────────────────────┤
│ Java 基础 │ 4/5  │ 5/5  │ 源码精读+输出文章     │
│ JVM      │ 3/5  │ 4/5  │ 调优实战+GC笔记       │
│ Redis    │ 3/5  │ 4/5  │ 生产故障复盘 3 例      │
│ Agent 开发│ 2/5  │ 4/5  │ 完成 2 个项目+评估体系 │
│ AI 架构   │ 1/5  │ 3/5  │ 系统学习+架构方案输出   │
└──────────┴──────┴──────┴────────────────────┘
→ 使用：每季度更新一次；选择 1-2 项重点突破（不撒网）
```

### 4.2 技能复盘的节奏

```text
技能复盘节奏
├── 每周：技术成长日志（见下节）
├── 每月：技能矩阵微调（进度更新）
├── 每季：矩阵大复盘（重新选重点突破项）
└── 每年：战略复盘（方向是否要调整）
→ 原则：每年选择 1 个技术领域深度学习——
   形成「入门→实践→精通→输出」完整闭环
```

## 5. 技术成长日志

### 5.1 日志内容

> 🎯 **技术成长日志**：记录本周的四个高价值瞬间——**复杂问题解决、新技术学习、审查最佳反馈、下次优化方案**：

```text
技术成长日志模板（每周 15 分钟）
├── ① 本周解决的最复杂问题：
│   └── 并发退款 bug → 幂等键方案（根因+解法+测试）
├── ② 本周学习的新技术：
│   └── MCP v2.0 多 Agent 协作能力（应用场景笔记）
├── ③ 本周代码审查获得的最佳反馈：
│   └── 「错误信息要带上下文」→ 已应用到全局异常
└── ④ 下次的优化方案：
    └── 订单查询加 Redis 缓存（预计 P95 -50%）
```

### 5.2 日志的价值

```text
技术成长日志的三重价值
├── ① 成长可见：3 个月后回看，能看见自己怎么长大
├── ② 复盘有据：周报/绩效/述职的素材库
├── ③ 沉淀资产：直接转知识库条目（与 04 篇知识管理联动）
└── 金句：日志写的是「过程」，未来看见的是「成长轨迹」
```

## 6. 学习闭环

### 6.1 学习闭环四步

```text
学习闭环：入门 → 实践 → 精通 → 输出
├── ① 入门：系统学习（课程/文档/书籍）
├── ② 实践：真实项目落地（学以致用，只学不用 = 白学）
├── ③ 精通：解决复杂问题 + 源码精读
└── ④ 输出：分享/写作/开源（费曼学习法）
→ 输出是学习的最强引擎：
   讲不清楚 = 没真懂；写不出来 = 没消化
```

### 6.2 费曼学习法落地

```text
费曼学习法（程序员版）
├── ① 选主题：本周学的技术
├── ② 讲出来：给团队做 15 分钟技术分享
├── ③ 找漏洞：分享中讲不清楚的地方 = 没学透的地方
├── ④ 补漏洞：回去补学 → 重讲
└── ⑤ 沉淀：分享稿 = 知识库文章
→ 定期技术分享：用费曼学习法加深理解 + 建立个人影响力
```

### 6.3 成长支持系统

| 支持 | 做法 | 价值 |
|------|------|------|
| **导师制** | 找到比自己强的 mentor 定期获取反馈 | 少走弯路 |
| **开源社区** | 参与开源项目/技术社区 | 实战 + 人脉 |
| **关键任务** | 主动承担关键任务、深度参与技术决策 | 能力跃迁 |
| **精力投入** | 每天留 2-3 分精力提升自己（02 篇） | 复利成长 |

> 🎯 **成长的本质**：程序员的成长 = 输入（学习）× 加工（实践）× 转化（复盘）× 输出（分享）——四者循环，缺一环成长就停。**每天留出精力池的 2-3 分提升自己，不要把 10 分精力全砸进工作**。

## 7. 核心要点

> 🎯 **核心要点**：
> 1. 复盘是把经历转化为能力的唯一通道——不复盘 = 同一个坑踩三次
> 2. 周复盘四问（有效做法/超时原因/卡住事项/下周 TOP3）+ 晚间复盘 3 分钟清空大脑
> 3. 技能矩阵（领域/当前/目标/路径）季度更新、重点突破 1-2 项
> 4. 学习闭环（入门→实践→精通→输出）：费曼分享验证真懂 + 导师制 + 每天 2-3 分精力投入
