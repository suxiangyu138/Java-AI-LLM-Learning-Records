## 1. 模型总览：K 路归并与外部排序

| 模板 | 一句话记忆 | 核心公式 |
|------|------|------|
| K 路归并 | 入堆 → 弹最小 → 补位 | O(n log K) |
| 外部排序 | 分块生成段 → 多路归并 | 趟数 = ⌈log_K m⌉ |
| 替换-选择 | 边输出边补入 | 段长平均 2w |

```text
⚠️ 定位: 面试以"概念 + 公式"为主——
  23 合并 K 链表（堆版）必手撕；
  外部排序讲清两阶段与轮数公式即可
```

> 🎯 **核心认知**："**多路归并 = '从 K 个头里反复选最小'——堆让它 O(log K) 选一次**；外部排序 = '多路归并的磁盘版'——趟数 = I/O 次数，全部优化指向减 I/O。"

## 2. K 路归并（最小堆模板）

### 2.1 5 分钟模板（数组版 + 链表版）

```java
/**
 * K 路归并（最小堆）——数组版
 * 时间 O(n·log K)，空间 O(K)
 */
int[] mergeKSortedArrays(int[][] arrays) {
    PriorityQueue<int[]> heap = new PriorityQueue<>((x, y) -> x[0] - y[0]);
    for (int i = 0; i < arrays.length; i++)          // ① K 个头入堆
        if (arrays[i].length > 0)
            heap.offer(new int[]{arrays[i][0], i, 0});   // [值, 路, 列]

    List<Integer> result = new ArrayList<>();
    while (!heap.isEmpty()) {
        int[] top = heap.poll();                     // ② 弹全局最小
        result.add(top[0]);
        int row = top[1], col = top[2];
        if (col + 1 < arrays[row].length)            // ③ 同路补位
            heap.offer(new int[]{arrays[row][col + 1], row, col + 1});
    }
    return result.stream().mapToInt(Integer::intValue).toArray();
}

// 链表版（23 题）: 堆存 ListNode，补位 = node.next
//   → 无需三元组（链表自带 next）
```

### 2.2 模板要点

```text
三步: "K 个头入堆 → 弹最小 → 同路补位"
复杂度: O(n·log K)（每元素入出堆各一次）/ O(K) 空间
稳定性: ✔（平局取路号小的）

⚠️ 变体: 败者树（大 K 常数减半——每层 1 比较 vs 堆 2）
  23 合并 K 链表 = 本模板的链表载体
```

## 3. 多路归并推演

**三路归并：[1,4,7] [2,5] [3,6,9]**

| 步 | 堆内容（值,路,列） | 弹出 | 补位 | 结果 |
|:---:|------|:---:|:---:|------|
| 初始 | (1,0,0)(2,1,0)(3,2,0) | — | — | [] |
| 1 | (2,1,0)(3,2,0)(4,0,1) | 1 | 4 | [1] |
| 2 | (3,2,0)(4,0,1)(5,1,1) | 2 | 5 | [1,2] |
| 3 | (4,0,1)(5,1,1)(6,2,1) | 3 | 6 | [1,2,3] |
| 4 | (5,1,1)(6,2,1)(7,0,2) | 4 | 7 | [1,2,3,4] |
| 5 | (6,2,1)(7,0,2) | 5 | 路 1 耗尽 | [1,2,3,4,5] |
| 6 | (7,0,2)(9,2,2) | 6 | 9 | [1,2,3,4,5,6] |
| 7 | (9,2,2) | 7 | 路 0 耗尽 | [1,2,3,4,5,6,7] |
| 8 | — | 9 | 路 2 耗尽 | [1,2,3,4,5,6,7,9] ✓ |

**轮数公式**：m 个段 K 路归并 → 趟数 = ⌈log_K m⌉（100 段：二路 7 趟、十路 2 趟）。

## 4. 外部排序两阶段

### 4.1 阶段一：生成归并段

```text
分块读入（块大小 = 可用内存）→ 内存排序 → 写回磁盘
  例: 100GB 数据 / 1GB 内存 → 100 个有序段（run）
优化: 替换-选择 → 段长平均 2× 内存 → 段数减半
```

### 4.2 阶段二：多路归并

```text
K 路同时归并所有段（K 个输入缓冲 + 最小堆/败者树选最小）
趟数 = ⌈log_K m⌉ → I/O ≈ 2 × 数据量 × 趟数

⚠️ K 权衡: K 大 → 趟数少但缓冲内存大（K+1~2K 个缓冲）
  实践值: K ≈ 10~50（按内存预算）
```

### 4.3 最佳归并树（软考考点）

```text
段长不一时 → K 叉哈夫曼树（短段先并）→ WPL 最小
虚段数 = (K−1) − (N−1)%(K−1)（不足时补 0 长段）

⚠️ 例: N=6 段、K=3 → (6−1)%2=1 → 补 1 个虚段
```

## 5. 替换-选择与败者树

### 5.1 替换-选择（生成更长段）

```java
// 概念模板: 内存维护候选堆，边输出边补入
// 输出后: 新元素 >= 当前段最后 → 入当前段；否则留到下一段
// 效果: 段平均长度 ≈ 2w（w = 内存工作区）
// 例: 1GB 内存 → 平均 2GB 段 → 段数减半 → 趟数减一
```

### 5.2 败者树（大 K 选最小）

```text
vs 堆: 每层 1 比较 + 1 访存（堆 2+2）→ 大 K 常数减半
内部节点存"败者"（= 另一侧冠军）→ 沿路径 1 比较/层
初始化 K−1 次比较，之后每轮 ⌈log₂K⌉

⚠️ 面试定位: 讲清"败者 = 另一侧冠军"的不变式即可
  手撕优先级低于堆版（工程默认堆，Spark 4.0 才加败者树）
```

## 6. 模板对照与选型

| 场景 | 模板 | 复杂度 |
|------|------|:---:|
| 内存内 K 路合并（23 题） | 最小堆 | O(n log K) |
| 大 K + 内存敏感 | 败者树 | O(n log K) 常数小 |
| 数据超内存 | 外部排序（分块 + K 路） | I/O = 2n·⌈log_K m⌉ |
| 生成更长段 | 替换-选择 | 段长 2w |
| 段长不一 | 最佳归并树 | WPL 最小 |

```text
⚠️ 一句话: "内存内用堆、超内存用外部排序、
   段长用替换-选择、顺序用哈夫曼树"
```

## 7. 易错点总表

| # | 模板 | 易错点 | 正确写法 |
|:---:|:---:|------|------|
| 1 | K 路 | 忘补位 | 弹出后同路 next 入堆 |
| 2 | K 路 | 空路入堆 | `length > 0` 过滤 |
| 3 | K 路 | 堆只存值 | 存三元组（值/路/列） |
| 4 | 外部 | 趟数公式错 | ⌈log_K m⌉（K 为底） |
| 5 | 外部 | K 越大越好 | 缓冲内存权衡（K≈10~50） |
| 6 | 替换-选择 | 段长 = w | 平均 2w |
| 7 | 最佳归并树 | 忘虚段 | (K−1)−(N−1)%(K−1) |

> 🎯 **核心要点**：多路归并通关——**堆版模板（入堆弹补位）+ 轮数公式（⌈log_K m⌉）+ 两阶段（分块生成段/多路归并）+ 三个优化（替换-选择 2w、败者树常数、哈夫曼树顺序）**。它是外部排序的引擎——"趟数 = I/O 次数"一句，就是大数据排序的全部哲学。
