## 1. 哈希查找模型：边遍历边记录

```text
核心模式: 遍历一遍，把"见过的"存进哈希——
  后续元素直接查"历史" → O(n) 而非 O(n²)

三步:
  ① 查: 当前元素需要的"补差/历史"是否在哈希里？
  ② 算: 命中 → 记录/返回
  ③ 记: 当前元素入哈希（边遍历边记录）

识别信号:
  "找两数/补差/配对" → 值 → 下标 / 值 → 计数
  "判重/判循环" → 值 → 布尔 / 状态 → 是否见过

⚠️ 与双指针的分工:
  有序数组找两数 → 对撞（O(1) 空间，专题 1）
  无序数组找两数 → 哈希（O(n) 空间换时间）
```

> 🎯 **核心认知**："**哈希查找 = '查历史 + 记当下'两个 O(1) 动作**——把 O(n²) 的暴力配对变成 O(n)。'空间换时间'在这类题里是唯一解：无序数据没有有序性可用，哈希是唯一 O(1) 查找。"

## 2. 1 两数之和（母题）

### 2.1 题目与思路

**题**：无序数组找两数和 = target 的下标（O(n)）。

**边遍历边记录**：查补差 → 命中返回 → 未命中记录：

```java
/**
 * LeetCode 1. 两数之和
 * 时间 O(n)，空间 O(n)
 * ⚠️ 核心: 边遍历边记录——保证"只用当前元素之前的"（不重复配对）
 */
public int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> index = new HashMap<>();
    for (int i = 0; i < nums.length; i++) {
        int complement = target - nums[i];       // ① 计算补差
        if (index.containsKey(complement)) {     // ② 查历史
            return new int[]{index.get(complement), i};
        }
        index.put(nums[i], i);                   // ③ 记当下（先查后记！）
    }
    return new int[]{-1, -1};
}
// 推演 [2,7,11,15]，target=9：
//   i=0: 查 7 无 → 记 {2:0}；i=1: 查 7 命中 → [0,1] ✓
// ⚠️ 为什么先查后记: 先记会把"自己"算进去（i=0 时 complement=7 不是自己，
//   但 target 为偶数且 nums[i]*2==target 时先记会误配自己）
//   例: [3,3], target=6 —— 先记后查: i=0 记 {3:0}，i=1 查 3 命中 → 仍正确
//   但 [3], target=6 —— 先记后查: i=0 记 {3:0} 后查 3 命中自己 → 错误！
```

> 🎯 **先查后记的边界**："**'先查后记'防止同一元素与自己配对**——[3] target=6 的场景，先记再查会返回 [0,0] 错误。这是 1 题最隐蔽的边界，主动说出 = 加分。"

## 3. 202 快乐数（哈希检测循环）

### 3.1 题目与思路

**题**：数字各位平方和反复计算，最终 = 1 是快乐数，否则进入循环。

**哈希检测循环**：用 HashSet 记录出现过的数——重复出现 = 循环 = 非快乐数：

```java
/**
 * LeetCode 202. 快乐数
 * 时间 O(log n)（数位平方和快速收敛），空间 O(log n)
 */
public boolean isHappy(int n) {
    Set<Integer> seen = new HashSet<>();
    while (n != 1 && seen.add(n)) {              // ① add 返回 false = 已见过
        n = sumOfSquares(n);                     // ② 计算数位平方和
    }
    return n == 1;                               // ③ 到 1 快乐；重复非快乐
}

private int sumOfSquares(int n) {
    int sum = 0;
    while (n > 0) {
        int d = n % 10;
        sum += d * d;
        n /= 10;
    }
    return sum;
}
// 推演 19：19→82→68→100→1 → true ✓
//   2：2→4→16→37→58→89→145→42→20→4（重复）→ false ✓
// ⚠️ 进阶（O(1) 空间）: 快慢指针检测循环（Floyd，链表专题同款）
```

> 💡 **哈希判循环的通用性**："**'出现过的状态集合'是循环检测的哈希版**——快乐数、LRU 判环（可哈希版）、单词接龙都是同款。O(1) 空间版用快慢指针（Floyd），与链表 141 完全同构。"

## 4. 383 赎金信（计数查找）

### 4.1 题目与思路

**题**：magazine 的字符能否拼出 ransomNote（每个字符只能用一次）。

**计数表**：magazine 计数，ransomNote 消耗——不够即失败：

```java
/**
 * LeetCode 383. 赎金信
 * 时间 O(m+n)，空间 O(26)
 * ⚠️ 字符集小 → 数组计数（比 HashMap 更优）
 */
public boolean canConstruct(String ransomNote, String magazine) {
    int[] count = new int[26];
    for (char c : magazine.toCharArray()) {
        count[c - 'a']++;                        // ① magazine 计数
    }
    for (char c : ransomNote.toCharArray()) {
        if (count[c - 'a'] == 0) return false;   // ② 不够用 → 失败
        count[c - 'a']--;                        // ③ 消耗一个
    }
    return true;
}
// 推演 ransomNote="aa", magazine="aab"：
//   magazine: a:2, b:1；消耗 a,a → 够 → true ✓
// ⚠️ 选型: 26 字符 → 数组 O(1) 空间、缓存友好；
//   HashMap 在这里是"杀鸡用牛刀"（面试主动指出 = 加分）
```

## 5. 705 设计哈希集合（手写底层）

### 5.1 题目与思路

**题**：实现 add/remove/contains 的 HashSet（不用内置集合）。

**链地址法**：数组 + 链表（01 文件手写版的无值版）：

```java
/**
 * LeetCode 705. 设计哈希集合（链地址法）
 * 时间 O(1) 平均，空间 O(n)
 */
class MyHashSet {
    private static final int SIZE = 1009;        // ① 素数容量（降冲突）
    private final List<Integer>[] buckets;

    public MyHashSet() {
        buckets = new List[SIZE];
    }

    public void add(int key) {
        int idx = key % SIZE;                    // ② 哈希函数（取模）
        if (buckets[idx] == null) buckets[idx] = new ArrayList<>();
        if (!buckets[idx].contains(key)) {       // ③ 已存在不重复加
            buckets[idx].add(key);
        }
    }

    public void remove(int key) {
        int idx = key % SIZE;
        if (buckets[idx] != null) {
            buckets[idx].remove(Integer.valueOf(key));
        }
    }

    public boolean contains(int key) {
        int idx = key % SIZE;
        return buckets[idx] != null && buckets[idx].contains(key);
    }
}
// ⚠️ 为什么容量取素数: 取模哈希下素数容量降低公因数冲突
//   （工程 HashMap 用 2 的幂 + 扰动是另一套方案——位运算优先）
```

> 💡 **与 HashMap 的对比**："**705 是'哈希表思想'的最小实现**——'数组 + 桶内集合 + 取模'三步。用素数容量展示'均匀性'考量，与 HashMap 的'2 的幂 + 扰动'形成对比（面试两个都能讲 = 深度）。"

## 6. 706 设计哈希映射（链地址 + 扩容）

### 6.1 题目与思路

**题**：实现 key→value 的 HashMap（不用内置）。

**完整版**（01 文件手写版，数组 + 链表 + 负载因子扩容）：

```java
/**
 * LeetCode 706. 设计哈希映射（链地址 + 扩容）
 * 与 01 文件手写版相同: 定位 → 冲突链查找 → 超阈值扩容
 */
class MyHashMap {
    private static class Node {
        int key, value;
        Node next;
        Node(int key, int value) { this.key = key; this.value = value; }
    }

    private Node[] buckets = new Node[16];
    private int size = 0;
    private static final double LOAD = 0.75;

    public void put(int key, int value) {
        int idx = hash(key);
        for (Node cur = buckets[idx]; cur != null; cur = cur.next) {
            if (cur.key == key) { cur.value = value; return; }   // ① 更新
        }
        Node node = new Node(key, value);        // ② 头插
        node.next = buckets[idx];
        buckets[idx] = node;
        if (++size > buckets.length * LOAD) resize();            // ③ 扩容
    }

    public int get(int key) {
        int idx = hash(key);
        for (Node cur = buckets[idx]; cur != null; cur = cur.next) {
            if (cur.key == key) return cur.value;
        }
        return -1;
    }

    public void remove(int key) {
        int idx = hash(key);
        Node dummy = new Node(0, 0);             // ④ 哑结点删头（链表技巧）
        dummy.next = buckets[idx];
        Node prev = dummy;
        while (prev.next != null && prev.next.key != key) prev = prev.next;
        if (prev.next != null) { prev.next = prev.next.next; size--; }
        buckets[idx] = dummy.next;
    }

    private int hash(int key) { return (key ^ (key >>> 16)) & (buckets.length - 1); }

    private void resize() {
        Node[] old = buckets;
        buckets = new Node[old.length * 2];
        size = 0;
        for (Node head : old) {
            for (Node cur = head; cur != null; ) {
                Node next = cur.next;
                put(cur.key, cur.value);
                cur = next;
            }
        }
    }
}
// ⚠️ remove 的哑结点: 复用链表专题的"哑结点统一删头"心法
```

> 🎯 **706 的考点**："**手写哈希映射 = 705 集合 + 键值对 + 扩容**——'定位 → 冲突链 → 扩容'三步走。能完整手撕 706 并讲清负载因子与扩容触发，HashMap 八股就落到实处了。"

## 7. 查找用法易错点

| # | 易错点 | 正确写法 | 后果 |
|:---:|------|------|------|
| 1 | 1 题先记后查 | 先查后记 | 自己与自己配对 |
| 2 | 202 用 `while (n != 1)` 无 seen | 加 HashSet 判循环 | 死循环 |
| 3 | 383 用 HashMap | 26 数组计数 | 常数大/面试减分 |
| 4 | 705 重复 add | `contains` 判重 | 桶内重复元素 |
| 5 | 706 删除头节点特判 | 哑结点统一 | 头删漏判 |
| 6 | 哈希函数取模负 key | `key % SIZE` 可为负 | 负数下标越界 |
| 7 | 705 用固定数组当桶 | 桶内是集合（冲突处理） | 容量不足即满 |

> 🎯 **核心要点**：哈希查找通关四件事——**① '先查后记'的边界意识**（1 题自配对）；**② 哈希判循环模板**（202 的 seen 集合）；**③ 数组 vs HashMap 选型**（26 字符用数组）；**④ 705/706 手写**（链地址 + 扩容三步）。**查找是哈希四用法的地基——'查历史 + 记当下'这一对 O(1) 动作，衍生出计数、去重、索引全部用法**。
