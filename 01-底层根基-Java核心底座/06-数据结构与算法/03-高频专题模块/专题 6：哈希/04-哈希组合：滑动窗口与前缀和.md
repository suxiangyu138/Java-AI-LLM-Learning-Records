## 1. 哈希 × 滑动窗口：状态容器

```text
滑动窗口需要"窗口状态"的 O(1) 增删查:
  计数 → 哈希表 / 计数数组（字符集小）
  位置 → 哈希表（值 → 最后出现位置）

窗口题中哈希的角色:
  ① 状态容器: 记录窗口内字符计数（3/76/438）
  ② 跳跃指针: 记录"最后出现位置"，left 直接跳跃（3 的进阶）
  ③ 匹配判定: valid 计数（76 的达标种类）

⚠️ 组合要点: 哈希的"增删"必须与窗口的"进出"严格同步——
  左出窗口时忘删哈希 = 状态失真 = 答案错误
```

> 🎯 **核心认知**："**哈希是窗口题的'状态大脑'**——窗口的合法性判断（无重复？覆盖？）全部依赖哈希的 O(1) 读写。'进窗加、出窗减'的同步纪律是组合题的命门。"

## 2. 3 无重复字符的最长子串（哈希 + 窗口）

### 2.1 题目与思路

**题**：无重复字符的最长子串（O(n)）。

**窗口 + 计数**（基础版）与 **窗口 + 位置跳跃**（进阶版）：

```java
/**
 * LeetCode 3. 无重复字符的最长子串（进阶版: 位置跳跃）
 * 哈希记录"最后出现位置" → left 直接跳到重复位置之后
 * 时间 O(n)，空间 O(字符集)
 */
public int lengthOfLongestSubstring(String s) {
    Map<Character, Integer> lastIndex = new HashMap<>();   // ① 最后出现位置
    int left = 0, best = 0;

    for (int right = 0; right < s.length(); right++) {
        char c = s.charAt(right);
        if (lastIndex.containsKey(c)) {
            // ② 重复 → left 直接跳跃（取 max 防回退）
            left = Math.max(left, lastIndex.get(c) + 1);
        }
        lastIndex.put(c, right);                 // ③ 更新位置
        best = Math.max(best, right - left + 1); // ④ 最长题: 收缩后更新
    }
    return best;
}
// 推演 "abcabcbb"：
//   right=3(第二个 a): left 跳 1 → 窗口 "bca"（3）
//   right=4(第二个 b): left 跳 2 → 窗口 "cab"（3）
//   right=6(第二个 b): left 跳 5 → 窗口 "cb"（2）
//   答案 3 ✓
// ⚠️ 基础版（计数数组 + while 收缩）见专题 1——
//   进阶版省掉 while，left 一次跳到位
```

> 💡 **两版对比**："**计数版 O(1) 空间但 while 收缩，位置版省 while 但 O(字符集) 空间**——'取 max 防回退'是位置版的关键细节（重复字符可能让 left 后退）。"

## 3. 76 最小覆盖子串（need/window/valid 三变量）

### 3.1 题目与思路

**题**：包含 t 所有字符的最短子串（O(n)）。

**三变量**：`need`（需求表）、`window`（窗口计数）、`valid`（达标种类数）：

```java
/**
 * LeetCode 76. 最小覆盖子串
 * 时间 O(n)，空间 O(字符集)
 * ⚠️ 最短题: 先记录答案再收缩！
 */
public String minWindow(String s, String t) {
    int[] need = new int[128], window = new int[128];
    for (char c : t.toCharArray()) need[c]++;

    int left = 0, valid = 0;                   // valid: 已达标字符种类
    int minLen = Integer.MAX_VALUE, start = 0;

    for (int right = 0; right < s.length(); right++) {
        char c = s.charAt(right);
        if (need[c] > 0) {                     // ① 只关心 t 中的字符
            window[c]++;
            if (window[c] == need[c]) valid++; // ② 该字符达标
        }
        while (valid == t.length() 的达标判定) { ... }   // 见下
    }
    return minLen == Integer.MAX_VALUE ? "" : s.substring(start, start + minLen);
}
// ⚠️ 完整代码见专题 1 文件 02（76 的完整实现与推演）——
//   达标判定: valid == t 的字符种类数（不是 t 的长度！）
//   例: t="AABC" → 种类 3（A/B/C），A 需 2 个，window['A']==2 才算达标
```

> 🎯 **三变量的要点**："**`valid` 计的是'达标种类'而非'达标个数'**——每种字符达到需求才 +1。这是 76 与 3 的本质区别（3 只要求无重复，76 要求覆盖）。完整实现与推演见专题 1 的 02 文件，此处只讲哈希角色。"

## 4. 哈希 × 前缀和：历史账本

```text
前缀和 + 哈希 = 区间问题的"历史账本":
  sum(l, r) = K ⇔ prefix[r+1] − prefix[l] = K
  ⇔ prefix[l] = prefix[r+1] − K

哈希角色: 记录"每种历史前缀和出现几次/最早位置"
  → 遍历时查"当前 − K"在历史中出现几次 → O(n) 而非 O(n²)

为什么窗口不行: 前缀和可增可减（含负数时窗口失效）
  → 哈希 + 前缀和是"区间和 = K"的唯一 O(n) 解

⚠️ 关键边界: 先查后加！
  先记录当前前缀和再查，会把"当前自己"配进去
  （k=0 时当前前缀和 == 当前−K → 自配对 → 答案偏大）
```

> 🎯 **历史账本思维**："**'查历史 + 记当下'从两数之和（1 题）延伸到前缀和（560）**——同一个模式，容器从'值→下标'变成'前缀和→计数'。这就是哈希组合的威力：模式不变，载体换。"

## 5. 560 和为 K 的子数组（先查后加）

### 5.1 完整实现

```java
/**
 * LeetCode 560. 和为 K 的子数组
 * 时间 O(n)，空间 O(n)
 */
public int subarraySum(int[] nums, int k) {
    Map<Integer, Integer> seen = new HashMap<>();
    seen.put(0, 1);                            // ① 哨兵: 空前缀和出现 1 次
    int sum = 0, count = 0;

    for (int x : nums) {
        sum += x;                              // ② 当前前缀和
        count += seen.getOrDefault(sum - k, 0);   // ③ 先查补差（历史出现次数）
        seen.merge(sum, 1, Integer::sum);      // ④ 后记当前（先查后加！）
    }
    return count;
}
// 推演 [1,1,1]，k=2：
//   sum=1: 查 −1 → 0；记 {0:1, 1:1}
//   sum=2: 查 0 → 1 ✓；记 2
//   sum=3: 查 1 → 1 ✓ → 总数 2 ✓
// ⚠️ k=0 陷阱: [1,-1,0], k=0 →
//   若先记后查: sum=0 时查 0 命中自己 → 多计 1 个 → 错！
```

> 🎯 **560 的三步转化**："**'区间和 = K' → '前缀差 = K' → '查历史前缀和'**——第一步是数学转化、第二步是公式变形、第三步是哈希落地。这个三步框架是前缀和家族（525/974/523）的通用模板。"

## 6. 525/974 前缀和家族变体

### 6.1 家族一览

| 题 | 变形 | 哈希键 | 记录内容 |
|:---:|------|:---:|------|
| 560 和为 K | 前缀和 = K | sum | 出现次数 |
| 525 连续数组 | 0/1 数组，和 = 0 最长 | sum（0 记 −1） | **最早出现位置** |
| 974 和可被 K 整除 | 前缀和 mod K = 0 | sum % K | 出现次数 |
| 523 连续子数组和 | 倍数 K 且长度 ≥2 | sum % K | 最早位置 + 长度差 |
| 437 路径总和 III | 树上前缀和 | sum（DFS 回溯） | 出现次数 |

### 6.2 525 连续数组（记录最早位置）

```java
/**
 * LeetCode 525. 连续数组（0/1 数组，最长和 = 0 的子数组）
 * 0 记 −1、1 记 +1 → 前缀和相等 ⇔ 区间和为 0
 * 哈希记录"最早出现位置"→ 最长区间 = 当前 − 最早
 * 时间 O(n)，空间 O(n)
 */
public int findMaxLength(int[] nums) {
    Map<Integer, Integer> firstIndex = new HashMap<>();
    firstIndex.put(0, -1);                     // ① 哨兵: 前缀和 0 最早在 −1
    int sum = 0, best = 0;

    for (int i = 0; i < nums.length; i++) {
        sum += (nums[i] == 1) ? 1 : -1;        // ② 0 记 −1、1 记 +1
        if (firstIndex.containsKey(sum)) {
            best = Math.max(best, i - firstIndex.get(sum));  // ③ 区间长 = 位置差
        } else {
            firstIndex.put(sum, i);            // ④ 只记最早位置
        }
    }
    return best;
}
// 推演 [0,1,0,1]：sum: −1,0,−1,0 →
//   sum=0 最早在 −1: i=1 → 2；sum=−1 最早 0: i=2 → 2；i=3 → 4
//   答案 4 ✓
```

> 💡 **记录内容的选择**："**'计数还是位置'取决于问题问'多少个'还是'多长'**——560 问个数（记次数）、525 问长度（记最早位置）。同一个哈希模式，记录内容由问题语义决定。"

## 7. 组合模式易错点

| # | 易错点 | 正确写法 | 后果 |
|:---:|------|------|------|
| 1 | 560 先记后查 | 先查后加 | k=0 自配对，答案偏大 |
| 2 | 560 忘 `put(0, 1)` | 哨兵初始化 | 漏掉从头开始的子数组 |
| 3 | 76 valid 用 t 长度 | 用 t 的**字符种类数** | 覆盖判定错误 |
| 4 | 3 进阶版忘 `Math.max` | left 跳跃取 max | 左指针回退 |
| 5 | 窗口左出忘同步哈希 | 出窗必须删/减 | 状态失真 |
| 6 | 525 更新最早位置 | 只记第一次（更早） | 最长区间漏算 |
| 7 | 974 负数取模 | `(sum % k + k) % k` | 负数键错乱 |

> 🎯 **核心要点**：组合模式通关四件事——**① 哈希 × 窗口的同步纪律**（进窗加/出窗减）；**② 三变量判定**（76 的 valid 种类计数）；**③ 560 先查后加 + 哨兵**；**④ 家族变形**（560 记次数 / 525 记位置 / 974 取模键）。**哈希从'查找工具'升级为'状态容器'与'历史账本'——组合题的哈希不再是被动查表，而是主动维护的窗口状态与历史索引**。
