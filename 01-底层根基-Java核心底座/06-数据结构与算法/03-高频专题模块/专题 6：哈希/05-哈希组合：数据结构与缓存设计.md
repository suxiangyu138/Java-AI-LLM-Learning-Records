## 1. 组合设计模型：哈希当索引

```text
组合设计的总纲: "哈希当索引，其他结构管顺序/频率"

  需求 O(1) 查找 → 哈希（值 → 位置/节点）
  需求 O(1) 顺序操作 → 链表（LRU 的淘汰顺序）
  需求 O(1) 随机访问 → 数组（380 的随机取值）
  需求 O(1) 频率操作 → 频率桶（LFU）

经典组合:
  146 LRU  = 哈希（查找）+ 双向链表（淘汰顺序）
  380 随机 = 哈希（定位）+ 数组（随机）+ 末尾交换（删除）
  138 复制 = 哈希（old → new 映射）
  460 LFU  = 哈希（key → 节点）+ 频率桶（频次 → 链表）

⚠️ 面试主线: 每个组合题的"为什么选这个结构"就是设计题的全部
```

> 🎯 **核心认知**："**组合设计的本质是'各取所长'——哈希提供 O(1) 查找，另一个结构提供 O(1) 的某种操作**。146 的'为什么双向链表'、380 的'为什么末尾交换'，每个'为什么'都是一次结构选型考试。"

## 2. 146 LRU 缓存（哈希 + 双向链表）

### 2.1 设计思路与完整实现

**需求**：O(1) get/put + 最近最少使用淘汰。

**选型**：哈希（key → 节点）+ 双向链表（按使用时间排序）+ 哨兵（免边界）：

```java
/**
 * LeetCode 146. LRU 缓存
 * 哈希（O(1) 查找）+ 双向链表（O(1) 删除/移动）+ 哨兵
 */
class LRUCache {
    private static class Node {
        int key, value;
        Node prev, next;
        Node(int key, int value) { this.key = key; this.value = value; }
    }

    private final Map<Integer, Node> map = new HashMap<>();
    private final int capacity;
    private final Node head = new Node(0, 0);    // ① 头哨兵
    private final Node tail = new Node(0, 0);    // ② 尾哨兵

    public LRUCache(int capacity) {
        this.capacity = capacity;
        head.next = tail;
        tail.prev = head;
    }

    public int get(int key) {
        Node node = map.get(key);
        if (node == null) return -1;
        moveToHead(node);                        // ③ 使用 → 移到头部
        return node.value;
    }

    public void put(int key, int value) {
        Node node = map.get(key);
        if (node != null) {
            node.value = value;                  // ④ 更新值
            moveToHead(node);
            return;
        }
        Node newNode = new Node(key, value);
        map.put(key, newNode);
        addToHead(newNode);                      // ⑤ 头插（最新使用）
        if (map.size() > capacity) {             // ⑥ 超容 → 删尾部（最久未用）
            Node last = tail.prev;
            removeNode(last);
            map.remove(last.key);
        }
    }

    private void addToHead(Node node) {
        node.next = head.next;
        node.prev = head;
        head.next.prev = node;
        head.next = node;
    }

    private void removeNode(Node node) {
        node.prev.next = node.next;
        node.next.prev = node.prev;
    }

    private void moveToHead(Node node) {
        removeNode(node);
        addToHead(node);
    }
}
// 推演 cap=2: put(1,1) put(2,2) → [1,2]；get(1) → [2,1]（1 最新）
//   put(3,3) → 超容删尾 2 → [1,3] ✓
```

> 🎯 **146 的选型论述**："**查找 O(1) → 哈希；删除任意节点 O(1) → 双向链表（单向删中间要 O(n) 找前驱）；淘汰最旧 → 链表尾部；哨兵免边界**——四句话是 146 的完整选型答案（详细版见链表专题 05 文件）。"

## 3. 380 O(1) 插入删除随机（哈希 + 数组）

### 3.1 题目与思路

**题**：O(1) 插入/删除/随机获取（元素不重复）。

**哈希（值 → 下标）+ 数组（随机访问）+ 末尾交换删除**：

```java
/**
 * LeetCode 380. O(1) 时间插入、删除和获取随机元素
 * 数组（随机 O(1)）+ 哈希（值 → 下标）+ 末尾交换删除
 */
class RandomizedSet {
    private final List<Integer> list = new ArrayList<>();
    private final Map<Integer, Integer> index = new HashMap<>();
    private final Random random = new Random();

    public boolean insert(int val) {
        if (index.containsKey(val)) return false;
        index.put(val, list.size());             // ① 哈希记下标
        list.add(val);                           // ② 数组尾插
        return true;
    }

    public boolean remove(int val) {
        Integer pos = index.remove(val);
        if (pos == null) return false;
        int last = list.get(list.size() - 1);    // ③ 末尾交换法
        list.set(pos, last);                     //    被删位置 ← 末尾元素
        index.put(last, pos);                    //    ④ 更新其哈希
        list.remove(list.size() - 1);            //    ⑤ 弹出末尾
        return true;
    }

    public int getRandom() {
        return list.get(random.nextInt(list.size()));   // ⑥ 数组随机 O(1)
    }
}
// 推演: 插 1,2,3 → list [1,2,3]、map {1:0,2:1,3:2}
//   remove(2): pos=1 → list[1]=3 → map{3:1} → list [1,3] ✓ O(1)！
// ⚠️ 为什么末尾交换: 数组中间删除 = O(n) 搬移；
//   换到末尾再弹 = O(1)（与哈希下标更新配套）
```

> 💡 **380 的工程意义**："**'数组 + 哈希 + 末尾交换'是 O(1) 容器的经典配方**——随机要数组、查找要哈希、删除要交换。这个组合在 Redis 的集合实现、线程池任务队列设计中反复出现。"

## 4. 138 复制带随机指针的链表（哈希映射）

### 4.1 题目与思路

**题**：深拷贝带 random 指针的链表。

**哈希映射**：old → new 的映射让 random 的"指回去"变成 O(1) 查表：

```java
/**
 * LeetCode 138. 复制带随机指针的链表
 * 两遍法: 先建映射，再接指针
 * 时间 O(n)，空间 O(n)
 */
public Node copyRandomList(Node head) {
    Map<Node, Node> map = new HashMap<>();
    // ① 第一遍: 只建新节点 + 映射
    for (Node cur = head; cur != null; cur = cur.next) {
        map.put(cur, new Node(cur.val));
    }
    // ② 第二遍: 接 next 与 random（全部通过映射）
    for (Node cur = head; cur != null; cur = cur.next) {
        map.get(cur).next = map.get(cur.next);
        map.get(cur).random = map.get(cur.random);   // ③ random 也查映射
    }
    return map.get(head);
}
// ⚠️ 这里的哈希是"映射"而非"查找"——old → new 的对应关系
// 进阶（O(1) 空间）: 交错复制法（老→新→老→新穿插）——面试提一句即可
```

> 🎯 **两遍法套路**："**'先建映射、再接指针'是复制类题的通用两遍法**——random 指向任意节点，映射让'指回去' O(1)。138 的哈希角色与 1/560 不同：这里是'对象映射'而非'值查找'。"

## 5. 460 LFU 缓存（哈希 + 频率桶）

### 5.1 题目与思路

**题**：LFU（最不经常使用）淘汰——频率最低的先淘汰，同频按 LRU。

**哈希（key → 节点）+ 频率桶（freq → 双向链表）+ 最小频率指针**：

```java
/**
 * LeetCode 460. LFU 缓存（设计思路版）
 * 三级结构:
 *   哈希1: key → 节点（O(1) 定位）
 *   哈希2: freq → 双向链表（O(1) 按频率分组操作）
 *   minFreq: 当前最小频率（淘汰起点）
 * 时间 O(1) 全操作，空间 O(n)
 */
class LFUCache {
    // 节点: key, value, freq, prev, next
    // freqMap: Map<Integer, Deque<Node>>（频率 → 该频率的 LRU 链）
    // keyMap: Map<Integer, Node>
    // minFreq: 最小频率（get/put 时更新）

    // get(key): 节点 freq+1 → 移入更高频桶 → 更新 minFreq
    // put(key): 存在 → 更新值 + freq+1；不存在 → 新节点 freq=1
    //   超容 → 从 minFreq 桶的尾部淘汰
}
// ⚠️ 手撕量大（~80 行）——面试重点是讲清三级结构选型，
//   手写优先级低于 146（146 必须手撕，460 讲清即可）
```

> 💡 **460 的面试定位**："**460 = 146 + 频率维度**——把'单一 LRU 链'换成'按频率分组的多个 LRU 链'。面试被问 460 时讲清三级结构（keyMap + freqMap + minFreq）比硬写代码更划算。"

## 6. LinkedHashMap：146 的工程形态

### 6.1 一行实现 LRU

```java
/**
 * LinkedHashMap 实现 LRU（工程形态）
 * accessOrder=true: 按访问顺序排列（get 也会移动到末尾）
 * removeEldestEntry: 超容时淘汰最老（头部）
 */
class LRUCacheLinked {
    private final LinkedHashMap<Integer, Integer> map;

    public LRUCacheLinked(int capacity) {
        map = new LinkedHashMap<>(capacity, 0.75f, true) {   // ① accessOrder=true
            @Override
            protected boolean removeEldestEntry(Map.Entry<Integer, Integer> eldest) {
                return size() > capacity;        // ② 超容淘汰最老
            }
        };
    }

    public int get(int key) {
        return map.getOrDefault(key, -1);
    }

    public void put(int key, int value) {
        map.put(key, value);
    }
}
// ⚠️ 面试顺序: 先手写双向链表版（考察底层理解），
//   再提 LinkedHashMap 版（展示工程知识）——两个都能给 = 满分
```

> 🎯 **手写 vs 内置**："**手写 146 考'为什么双向链表'，LinkedHashMap 版考'会用工程封装'**——面试先手写再提内置，顺序不能反（先给内置会显得不会底层）。"

## 7. 组合设计易错点

| # | 易错点 | 正确写法 | 后果 |
|:---:|------|------|------|
| 1 | LRU 忘删哈希 | `map.remove(last.key)` | 哈希残留脏数据 |
| 2 | LRU 双向指针只接一半 | prev/next 四条线全接 | 链表断裂 |
| 3 | 380 删除忘更新 last 的哈希 | `index.put(last, pos)` | 哈希指向失效位置 |
| 4 | 380 用 `remove(Integer)` 中间删 | 末尾交换法 | O(n) 退化 |
| 5 | 138 忘处理 random=null | `map.get(null)` 安全（返回 null） | 空指针（哈希 get 允许 null） |
| 6 | LFU 忘维护 minFreq | get/put 后更新 | 淘汰错对象 |
| 7 | LinkedHashMap 忘 accessOrder=true | 构造器第三参 | 变成插入序（非 LRU） |

> 🎯 **核心要点**：组合设计通关四件事——**① 总纲一句话**（哈希当索引，其他结构管顺序/频率）；**② 146 手撕 + 选型论述**（四句话：查找哈希/删除双向/淘汰尾部/哨兵边界）；**③ 380 末尾交换**（删 O(1) 的配方）；**④ 138 映射与 LFU 三级结构**（讲清选型即可）。**组合设计是'各取所长'的艺术——每个 O(1) 需求对应一个结构，哈希永远负责'找得到'，剩下的交给'排得动'**。
