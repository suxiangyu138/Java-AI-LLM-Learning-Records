## 1. 计数与去重模型

```text
计数模型: 值 → 出现次数（频率表）
  用途: 频率排序、异位词判定、出现次数统计
  选型: 字符/小整数 → 数组（26/128）；任意值 → HashMap

去重模型: 值 → 是否出现过（集合）
  用途: 判重、连续序列、循环检测
  技巧: 起点剪枝（只从"序列起点"开始扩展）→ O(n)

识别信号:
  "频率/出现次数" → 计数表
  "去重/唯一/连续" → 集合 + 剪枝
```

> 🎯 **核心认知**："**计数表是'值 → 频次'的映射，去重集合是'值 → 存在'的映射**——两者共享'哈希 O(1) 读写'的底座。字符集有限时数组计数完胜 HashMap（O(1) 空间 + 缓存友好），这是面试选型的第一判断。"

## 2. 242 有效的字母异位词（计数数组对拍）

### 2.1 题目与思路

**题**：两字符串字符组成是否相同（异位词）。

**一加一减**：同一个计数数组，s 加 t 减，最终全零：

```java
/**
 * LeetCode 242. 有效的字母异位词
 * 时间 O(n)，空间 O(26)（数组计数）
 */
public boolean isAnagram(String s, String t) {
    if (s.length() != t.length()) return false;    // ① 长度不等直接 false
    int[] count = new int[26];
    for (int i = 0; i < s.length(); i++) {
        count[s.charAt(i) - 'a']++;                // ② s 加
        count[t.charAt(i) - 'a']--;                // ③ t 减
    }
    for (int c : count) if (c != 0) return false;  // ④ 全零 = 异位词
    return true;
}
// 推演 s="anagram", t="nagaram"：加减后全零 → true ✓
// ⚠️ 数组 vs HashMap: 26 槽数组 O(1) 空间、缓存友好——
//   HashMap 在这里性能与代码都吃亏（面试主动选型）
```

## 3. 49 字母异位词分组（归一化键）

### 3.1 题目与思路

**题**：字符串分组，异位词同组。

**归一化键**：异位词 → 相同键（计数归一化 / 排序归一化）：

```java
/**
 * LeetCode 49. 字母异位词分组
 * 归一化键: 计数数组转字符串作键 → 异位词必然同键
 * 时间 O(n·L)（计数键），空间 O(n·L)
 */
public List<List<String>> groupAnagrams(String[] strs) {
    Map<String, List<String>> groups = new HashMap<>();
    for (String s : strs) {
        char[] count = new char[26];               // ① 计数归一化
        for (char c : s.toCharArray()) count[c - 'a']++;
        String key = new String(count);            // ② 异位词同键
        groups.computeIfAbsent(key, k -> new ArrayList<>()).add(s);
    }
    return new ArrayList<>(groups.values());
}
// 推演 ["eat","tea","tan","ate","nat","bat"]：
//   eat/tea/ate → 计数键相同 → 同组；tan/nat 同组；bat 独立 ✓
// ⚠️ 两种键: 计数键（O(L)）/ 排序键（O(L log L)）——
//   计数键更快，排序键更直观；面试给计数键是加分
```

> 🎯 **归一化键的通用性**："**'把'等价类'映射到'同一个键''是分组的万能思路**——异位词（计数键）、变位词、同字母异序词全部适用。`computeIfAbsent` 是分组题的标准 API（比 containsKey 分支简洁）。"

## 4. 347 前 K 个高频元素（计数 + 堆/频次桶）

### 4.1 题目与思路

**题**：返回频率前 K 高的元素。

**两步**：哈希计数（O(n)）→ 选 TopK（堆 O(n log k) / 频次桶 O(n)）：

```java
/**
 * LeetCode 347. 前 K 个高频元素
 * 时间 O(n·log k)（堆版），空间 O(n)
 */
public int[] topKFrequent(int[] nums, int k) {
    // ① 哈希计数
    Map<Integer, Integer> freq = new HashMap<>();
    for (int x : nums) freq.merge(x, 1, Integer::sum);

    // ② 最小堆（按频率比较，堆顶 = 第 K 高频门槛）
    PriorityQueue<Integer> heap = new PriorityQueue<>(
        (a, b) -> freq.get(a) - freq.get(b));
    for (int key : freq.keySet()) {
        heap.offer(key);
        if (heap.size() > k) heap.poll();          // ③ 超容弹最低频
    }

    int[] result = new int[k];
    for (int i = 0; i < k; i++) result[i] = heap.poll();
    return result;
}
// 推演 [1,1,1,2,2,3], k=2：freq {1:3, 2:2, 3:1}
//   堆 [3,2,1] → 弹 3 → [1,2] ✓
// ⚠️ 进阶: 频次桶 O(n)——桶下标 = 频次（451 题的思路，见专题 1）
```

> 💡 **两步法套路**："**'计数 + TopK'是频率类题的固定两步**——347 用堆（O(n log k)）、451 用频次桶（O(n)）。哈希计数永远是第一步，第二步选 TopK 容器。"

## 5. 128 最长连续序列（起点剪枝）

### 5.1 题目与思路

**题**：无序数组最长连续序列长度（O(n) 要求，如 [100,4,200,1,3,2] → 4）。

**HashSet + 起点剪枝**：只从"没有前驱"的元素开始扩展：

```java
/**
 * LeetCode 128. 最长连续序列
 * 时间 O(n)（每元素进出集合各一次），空间 O(n)
 * ⚠️ O(n) 的魔法: 非起点直接跳过——总扩展次数 = 总序列长度
 */
public int longestConsecutive(int[] nums) {
    Set<Integer> set = new HashSet<>();
    for (int x : nums) set.add(x);                 // ① 去重

    int best = 0;
    for (int x : set) {
        if (set.contains(x - 1)) continue;         // ② 有前驱 → 非起点 → 跳过！
        int len = 1;
        while (set.contains(x + len)) len++;       // ③ 只从起点扩展
        best = Math.max(best, len);
    }
    return best;
}
// 推演 [100,4,200,1,3,2]：
//   起点 1 → 1,2,3,4 → 4；100/200 孤立 → 1
//   答案 4 ✓（100,4,200 非起点被跳过 → 总扩展 = 4 次）
// ⚠️ 复杂度论证: 每个元素只被"起点扩展"访问一次 →
//   总 while 迭代 = Σ序列长度 ≤ n → O(n)
```

> 🎯 **起点剪枝的复杂度论证**："**'非起点跳过'让总扩展次数 = 总序列长度 ≤ n**——这是 128 从 O(n²) 到 O(n) 的全部秘密。能现场论证这个复杂度，就是 O(n) 要求的完整答案。"

## 6. 169 多数元素（计数 vs 摩尔投票）

### 6.1 题目与思路

**题**：出现次数 > n/2 的元素（O(1) 空间要求）。

**三种解法递进**：排序取中位（O(n log n)）→ 哈希计数（O(n)/O(n)）→ **摩尔投票（O(n)/O(1)）**：

```java
/**
 * LeetCode 169. 多数元素（摩尔投票，最优解）
 * 核心: 多数元素与其他元素两两抵消后必然剩下
 * 时间 O(n)，空间 O(1)
 */
public int majorityElement(int[] nums) {
    int candidate = nums[0], count = 1;
    for (int i = 1; i < nums.length; i++) {
        if (count == 0) {                        // ① 计数归零 → 换候选
            candidate = nums[i];
            count = 1;
        } else if (nums[i] == candidate) {
            count++;                             // ② 相同累加
        } else {
            count--;                             // ③ 不同抵消
        }
    }
    return candidate;
}
// 推演 [2,2,1,1,1,2,2]：候选 2，计数 1→2→1→0(换 1)→1→0(换 2)→1 → 2 ✓
// ⚠️ 正确性: 多数元素 > n/2 → 抵消后计数必为正 → 必剩多数
// 变体: 出现 > n/3 的元素（两候选版）——最多 2 个
```

> 💡 **哈希版 vs 投票版**："**哈希计数 O(n) 空间是直观解，摩尔投票 O(1) 空间是要求解**——'抵消'思想是多数元素的唯一 O(1) 解法。面试给三解法递进（排序 → 哈希 → 投票），深度立现。"

## 7. 计数去重易错点

| # | 易错点 | 正确写法 | 后果 |
|:---:|------|------|------|
| 1 | 242 忘先判长度 | `s.length() != t.length()` | 越界/错判 |
| 2 | 347 堆比较器写反 | 按频率升序（最小堆） | TopK 变 BottomK |
| 3 | 128 遍历原数组 | 遍历 set（去重后） | 重复元素重复扩展 |
| 4 | 128 从非起点扩展 | `contains(x−1)` 跳过 | O(n²) 退化 |
| 5 | 169 候选初始化错 | `nums[0]` + count=1 | 空数组越界 |
| 6 | 49 用排序键 | 计数键（O(L)） | 常数更大 |
| 7 | 计数用 `getOrDefault` 手动 | `merge(key, 1, sum)` | 代码冗余易错 |

> 🎯 **核心要点**：计数去重通关四件事——**① 数组 vs HashMap 选型**（字符集小用数组）；**② 归一化键分组**（49 的计数键）；**③ 起点剪枝 + 复杂度论证**（128 的 O(n) 魔法）；**④ 三解法递进**（169 排序 → 哈希 → 投票）。**计数的本质是'值 → 频次'的 O(1) 映射，去重的本质是'值 → 存在'的 O(1) 查询——四题四个技巧，全部建立在哈希的 O(1) 读写之上**。
