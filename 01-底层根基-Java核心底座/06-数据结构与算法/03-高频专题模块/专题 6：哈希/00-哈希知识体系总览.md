## 4. 核心概念速查

| 概念 | 一句话解释 | 说明 |
|------|-----------|------|
| **哈希函数** | key → 数组下标的映射 | 均匀分布是核心要求 |
| **冲突** | 不同 key 映射到同一下标 | 拉链/开放寻址/再哈希 |
| **拉链法** | 冲突元素挂链表/红黑树 | Java HashMap 的方案 |
| **开放寻址** | 冲突后找下一个空位 | ThreadLocalMap 线性探测 |
| **负载因子** | size/容量，0.75 最优 | 时间与空间的平衡点 |
| **扰动函数** | `h ^ (h >>> 16)` 高低位混合 | 降冲突概率 |
| **2 的幂容量** | `(n−1) & hash` 替代取模 | 位运算 + 均匀分布 + 扩容高效 |
| **树化阈值** | 链表 ≥8 且容量 ≥64 转红黑树 | 防哈希洪水（泊松 0.00000006） |
| **扩容** | 超阈值翻倍 + 高低链拆分 | `hash & oldCap` 免全量重算 |
| **先查后加** | 560 的查历史前缀和顺序 | k=0 防自配对 |

## 5. 解题模式速查

### 5.1 哈希四用法 → 题 → 技巧

| 用法 | 识别信号 | 核心技巧 | 代表题 |
|------|------|------|------|
| 查找 | "找两数/补差" | 边遍历边记录（值→下标） | 1/15 |
| 计数 | "频率/出现次数" | 计数表（字符集小用数组） | 242/347/169 |
| 去重 | "去重/连续序列" | HashSet + 起点剪枝 | 128 |
| 索引 | "O(1) 定位/缓存" | 值→节点映射（哈希+链表） | 146/380/138 |

### 5.2 哈希 vs 数组计数

```text
数组计数（字符集小: 26/128/256）:
  O(1) 空间、缓存友好、无装箱 → 首选
哈希表（值域大/任意对象）:
  通用、动态 → 数组装不下时用

⚠️ 选型: "字符/小整数 → 数组；任意值/对象 → HashMap"
```

> 🎯 **一句话定位**："**哈希是'空间换时间'的核心武器——查找 O(1)、计数 O(1)、去重 O(1)、索引 O(1)**，四大用法覆盖算法题 30%+ 的场景；而 Java HashMap 的底层（扰动/树化/扩容）是 Java 后端面试必考八股。"

## 6. 常见误区速查

| 误区 | 正解 |
|------|------|
| "链表长度到 8 就树化" | ❌ 必须同时满足容量 ≥ 64——否则只扩容不树化 |
| "new HashMap(10) 容量是 10" | ❌ 自动转为 ≥ 10 的最小 2 的幂（16） |
| "JDK8 的 HashMap 线程安全" | ❌ 只修复了扩容死循环，仍会数据覆盖 |
| "HashMap 有序" | ❌ 无序；有序 LinkedHashMap、排序 TreeMap |
| "哈希 O(1) 是绝对保证" | ❌ 平均/期望 O(1)，最坏 O(n)（树化后 O(log n)） |
| "560 先加后查也行" | ❌ k=0 时当前前缀和自己配对 → 答案偏大 |
| "哈希表一定比数组计数好" | ❌ 字符集小（26）时数组更省更快 |
| "自定义 key 只重写 hashCode" | ❌ equals + hashCode 必须一起重写且一致 |
| "负载因子越小越好" | ❌ 过小频繁扩容浪费内存，0.75 是平衡点 |
| "HashMap 不能处理冲突" | ❌ 拉链 + 树化 + 扩容是完整组合拳 |
