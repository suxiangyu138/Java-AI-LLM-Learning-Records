## 1. 分配与构造模型

```text
分配类（数值分配/选择，20%+）:
  资源匹配问题 → "排序 + 双指针"或"双向遍历"
  例: 455 饼干喂孩子、135 糖果、860 找零

构造类（序列构造/优化，15%+）:
  构造满足条件的序列 → "单调性"或"趋势计数"
  例: 402 移 K 位（单调栈）、738 单调递增、376 摆动

⚠️ 共同点: 都需要"排序或单调性"作为贪心的结构基础——
  无结构 → 贪心无从下手（先问自己：能排序吗？）
```

> 🎯 **核心认知**："**分配贪心 = '资源匹配的优先级'（最小满足最不贪婪/大面额优先找零）；构造贪心 = '单调性维护'（高位尽可能小/趋势变化才计数）**。两类题的贪心点都藏在'排序规则'或'单调结构'里。"

## 2. 455 分发饼干（排序 + 双指针）

### 2.1 完整实现（01 文件回顾）

```java
/**
 * LeetCode 455. 分发饼干
 * 排序 + 双指针: 最小的合适饼干满足最不贪婪的孩子
 * 时间 O(n log n)，空间 O(1)
 */
public int findContentChildren(int[] g, int[] s) {
    Arrays.sort(g);                            // ① 胃口升序
    Arrays.sort(s);                            // ② 饼干升序
    int i = 0;
    for (int cookie : s) {                     // ③ 每个饼干找能喂的孩子
        if (i < g.length && cookie >= g[i]) {
            i++;                               // ④ 最小满足最不贪婪
        }
    }
    return i;
}
// 推演 g=[1,2,3], s=[1,1] → 1 ✓；g=[1,2], s=[1,2,3] → 2 ✓
// ⚠️ 贪心论证: 大饼干留给大胃口——小饼干喂不了大胃口，
//   但大饼干能喂小胃口（浪费）→ "最小合适"不浪费任何资源
```

## 3. 135 分发糖果（双向贪心）

### 3.1 题目与思路

**题**：相邻孩子评分高者糖果更多，每人至少 1 颗，求最少糖果。

**双向贪心**：**每次只贪一个方向，两次遍历取 max**（贪心两头兼顾会顾此失彼）：

```java
/**
 * LeetCode 135. 分发糖果
 * 双向贪心: 左→右（右比左高 +1），右→左（左比右高取 max）
 * 时间 O(n)，空间 O(n)
 */
public int candy(int[] ratings) {
    int n = ratings.length;
    int[] candies = new int[n];
    Arrays.fill(candies, 1);                    // ① 每人至少 1 颗

    // ② 左 → 右: 只满足"右边比左边高"
    for (int i = 1; i < n; i++) {
        if (ratings[i] > ratings[i - 1]) {
            candies[i] = candies[i - 1] + 1;
        }
    }
    // ③ 右 → 左: 只满足"左边比右边高"（取 max 兼顾两侧约束）
    for (int i = n - 2; i >= 0; i--) {
        if (ratings[i] > ratings[i + 1]) {
            candies[i] = Math.max(candies[i], candies[i + 1] + 1);
        }
    }
    int total = 0;
    for (int c : candies) total += c;
    return total;
}
// 推演 [1,0,2]：左→右 [1,1,2]；右→左 [2,1,2] → 5 ✓
//   [1,2,2]：左→右 [1,2,1]；右→左 不变 → 4 ✓（相等不需多给）
// ⚠️ 为什么取 max: 位置 i 同时受左右约束——
//   第二次遍历时"左约束"可能已给更多，取 max 不破坏第一次结果
```

> 🎯 **135 的教训**："**'每次只贪一个方向'是双向贪心的铁律——同时兼顾两侧会顾此失彼**。左→右处理'右高'、右→左处理'左高'，取 max 合流。这个'分方向处理'的思路在 406 身高重建中再次出现。"

## 4. 860 柠檬水找零（面额策略）

### 4.1 题目与思路

**题**：卖 5 元柠檬水，收 5/10/20，能否正确找零。

**贪心面额策略**：找 20 时优先用 10+5（10 的通用性更差，先用掉）：

```java
/**
 * LeetCode 860. 柠檬水找零
 * 贪心: 找 20 优先 10+5（10 更不通用，先用掉）
 * 时间 O(n)，空间 O(1)
 */
public boolean lemonadeChange(int[] bills) {
    int five = 0, ten = 0;                      // ① 只关心 5 和 10 的数量
    for (int bill : bills) {
        if (bill == 5) {
            five++;                             // ② 收 5 直接收
        } else if (bill == 10) {
            if (five == 0) return false;        // ③ 找 5：没有 → 失败
            five--;
            ten++;
        } else {                                // ④ 收 20
            if (ten > 0 && five > 0) {          //    优先 10+5（贪心！）
                ten--; five--;
            } else if (five >= 3) {             //    退而求其次 5+5+5
                five -= 3;
            } else {
                return false;
            }
        }
    }
    return true;
}
// 推演 [5,5,5,10,20] → true ✓（20 用 10+5 找零）
//   [5,5,10,10,20] → false ✓（第二个 20 时只剩 10+10 找不开）
// ⚠️ 贪心点: 10 只能找 20、5 什么都能找——
//   "越不通用越先用"，与 455 的"最小合适"同一哲学
```

> 💡 **贪心的面额直觉**："**'通用性差的面额优先使用'是找零贪心的核心**——5 元通用性最强（能找 10 和 20）、10 元只能找 20。先用 10 保住 5，是'为后续留余地'的经典体现。"

## 5. 376 摆动序列（趋势计数）

### 5.1 题目与思路

**题**：最长摆动子序列（相邻差一正一负交替）。

**趋势计数**：只统计"趋势改变"的点（相同趋势的点只保留一个）：

```java
/**
 * LeetCode 376. 摆动序列
 * 贪心: 只统计趋势变化（同趋势的中间点无意义）
 * 时间 O(n)，空间 O(1)
 */
public int wiggleMaxLength(int[] nums) {
    if (nums.length < 2) return nums.length;
    int prevDiff = 0;                            // ① 上一次趋势
    int count = 1;                               // ② 至少第一个元素

    for (int i = 1; i < nums.length; i++) {
        int diff = nums[i] - nums[i - 1];
        // ③ 趋势变化（正→负 或 负→正）→ 计数
        if ((diff > 0 && prevDiff <= 0) || (diff < 0 && prevDiff >= 0)) {
            count++;
            prevDiff = diff;                     // ④ 更新趋势
        }
        // ⑤ 同趋势/相等 → 跳过（中间点不影响摆动长度）
    }
    return count;
}
// 推演 [1,7,4,9,2,5] → 6（全摆动）✓
//   [1,17,5,10,13,15,10,5,16,8] → 7 ✓
// ⚠️ 贪心点: 上升段只需保留"最高点"、下降段只需"最低点"——
//   中间点对摆动长度无贡献，全部舍弃
```

> 🎯 **376 的构造贪心**："**'趋势改变才计数'——同趋势的中间点全部舍弃，只留拐点**。这与 402/738 的'单调性维护'是同一族：构造类贪心 = 在序列上维护单调结构。"

## 6. 402 移掉 K 位数字与 738 单调递增数字（单调构造）

### 6.1 402 移掉 K 位数字（单调栈）

```java
/**
 * LeetCode 402. 移掉 K 位数字
 * 单调栈: 遇到"栈顶 > 当前"就弹出（移除高位大数 = 数更小）
 * 时间 O(n)，空间 O(n)
 */
public String removeKdigits(String num, int k) {
    Deque<Character> stack = new ArrayDeque<>();
    for (char c : num.toCharArray()) {
        // ① 栈顶 > 当前 → 移除栈顶（高位大数让数变大）
        while (k > 0 && !stack.isEmpty() && stack.peek() > c) {
            stack.pop();
            k--;
        }
        stack.push(c);                           // ② 当前入栈
    }
    while (k > 0) { stack.pop(); k--; }          // ③ 剩余移除次数删尾部

    // ④ 组装（去前导零）
    StringBuilder sb = new StringBuilder();
    boolean leading = true;
    for (char c : stack) {                       // 迭代顺序 = 栈底到栈顶
        if (leading && c == '0') continue;
        leading = false;
        sb.append(c);
    }
    return sb.isEmpty() ? "0" : sb.toString();
}
// 推演 "1432219", k=3 → "1219" ✓（移除 4,3,2 留最小）
// ⚠️ 贪心点: 高位数字越大数越大——"高位降序对"中移除高位
//   是让数字变小的唯一手段（单调栈天然维护"升序栈底"）
```

### 6.2 738 单调递增的数字

```java
/**
 * LeetCode 738. 单调递增的数字
 * 找到第一个"降序对"，前面减一、后面全变 9
 * 时间 O(n)，空间 O(n)
 */
public int monotoneIncreasingDigits(int n) {
    char[] digits = String.valueOf(n).toCharArray();
    int mark = digits.length;                    // ① 需要变 9 的起点

    for (int i = digits.length - 1; i > 0; i--) {
        if (digits[i] < digits[i - 1]) {         // ② 降序对（从右往左找）
            digits[i - 1]--;                     //    高位减一
            mark = i;                            //    记下变 9 起点
        }
    }
    for (int i = mark; i < digits.length; i++) {
        digits[i] = '9';                         // ③ 起点之后全变 9
    }
    return Integer.parseInt(new String(digits));
}
// 推演 332 → 299 ✓（3-1=2，后面全 9）
//   1234 → 1234 ✓（无降序对）；10 → 9 ✓
// ⚠️ 贪心点: "降序对高位减一"是让数变小的最小代价——
//   后面全 9 是"该位置能取的最大合法值"
```

> 🎯 **单调构造的共性**："**402 与 738 都是'单调性维护'——402 用单调栈删高位大数、738 找降序对减一补 9**。'构造最小/最大数'类题的贪心点永远是'高位优先'（高位权重最大）。"

## 7. 分配与构造易错点

| # | 易错点 | 正确写法 | 后果 |
|:---:|------|------|------|
| 1 | 135 只遍历一次 | 双向遍历（左右各一次） | 顾此失彼 |
| 2 | 135 第二次不用 max | `Math.max(现有, 另一侧+1)` | 破坏第一次结果 |
| 3 | 860 找 20 先用 5×3 | 优先 10+5 | 后续 10 找不开 |
| 4 | 402 忘去前导零 | leading 标记 | "0200" 非法输出 |
| 5 | 402 剩余 k 忘删 | 尾部补删 | 数字过长 |
| 6 | 738 从前往后找降序 | 从右往左找 | 进位处理错 |
| 7 | 376 相等差值处理错 | `prevDiff <= 0` 边界含等号 | 摆动计数错 |

> 🎯 **核心要点**：分配与构造通关四件事——**① 双向贪心**（135 每次只贪一个方向）；**② 面额策略**（860 越不通用越先用）；**③ 趋势计数**（376 只留拐点）；**④ 单调构造**（402 单调栈/738 降序对）。**分配贪心管'资源优先级'、构造贪心管'单调结构'——两类题都藏在'排序规则'与'高位优先'里**。
