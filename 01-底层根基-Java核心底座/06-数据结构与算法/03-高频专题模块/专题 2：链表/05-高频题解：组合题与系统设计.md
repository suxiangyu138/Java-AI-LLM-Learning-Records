## 2. 146 LRU 缓存（哈希 + 双向链表，必会）

### 2.1 设计思路

```text
需求: O(1) 的 get 与 put（最近最少使用淘汰）

结构选型:
  哈希表: key → 节点（O(1) 查找）
  双向链表: 按"使用时间"排序（O(1) 删除/插入头部）
  ⚠️ 为什么双向不是单向: 删除任意节点需要 O(1) 找到前驱
     ——单向链表删中间节点必须从头找（O(n)）

操作:
  get(key): 哈希命中 → 移到链表头部（最新使用）
  put(key): 存在 → 更新值移头部；不存在 → 头插 + 超容删尾部
```

### 2.2 完整实现（手撕标准答案）

```java
/**
 * LeetCode 146. LRU 缓存
 * 哈希表（O(1) 查找）+ 双向链表（O(1) 删除/移动）
 */
class LRUCache {
    // ① 双向链表节点（带头尾哨兵，免边界判断）
    private static class Node {
        int key, value;
        Node prev, next;
        Node(int key, int value) { this.key = key; this.value = value; }
    }

    private final Map<Integer, Node> map = new HashMap<>();
    private final int capacity;
    private final Node head = new Node(0, 0);   // ② 头哨兵
    private final Node tail = new Node(0, 0);   // ③ 尾哨兵

    public LRUCache(int capacity) {
        this.capacity = capacity;
        head.next = tail;
        tail.prev = head;
    }

    public int get(int key) {
        Node node = map.get(key);
        if (node == null) return -1;
        moveToHead(node);                        // ④ 使用 → 移到头部
        return node.value;
    }

    public void put(int key, int value) {
        Node node = map.get(key);
        if (node != null) {
            node.value = value;                  // ⑤ 更新值
            moveToHead(node);
            return;
        }
        Node newNode = new Node(key, value);
        map.put(key, newNode);
        addToHead(newNode);                      // ⑥ 头插
        if (map.size() > capacity) {             // ⑦ 超容 → 删尾
            Node last = tail.prev;
            removeNode(last);
            map.remove(last.key);
        }
    }

    private void addToHead(Node node) {
        node.next = head.next;
        node.prev = head;
        head.next.prev = node;
        head.next = node;
    }

    private void removeNode(Node node) {
        node.prev.next = node.next;
        node.next.prev = node.prev;
    }

    private void moveToHead(Node node) {
        removeNode(node);                        // ⑧ 摘除 + 头插
        addToHead(node);
    }
}
```

> 🎯 **146 的面试价值**："**LRU = 哈希（O(1) 查找）+ 双向链表（O(1) 删除）+ 哨兵（免边界）**三件套——是算法题与系统设计（Redis 内存淘汰、操作系统页面置换）的桥梁。**'为什么双向'的答案是面试必问**：删除任意节点需要 O(1) 找到前驱。"

## 3. 138 复制带随机指针的链表

### 3.1 题目与思路

**题**：深拷贝带 random 指针的链表。

**哈希版**：老节点 → 新节点映射（random 指回老节点时查表）；**交错版**：O(1) 空间（老→新→老→新穿插再拆开）：

```java
/**
 * LeetCode 138. 复制带随机指针的链表（哈希版）
 * 时间 O(n)，空间 O(n)
 * ⚠️ 核心: 映射表 old → new，random 的指向在映射中解析
 */
public Node copyRandomList(Node head) {
    Map<Node, Node> map = new HashMap<>();
    // ① 第一遍: 只建新节点 + 映射
    for (Node cur = head; cur != null; cur = cur.next) {
        map.put(cur, new Node(cur.val));
    }
    // ② 第二遍: 接 next 与 random（通过映射）
    for (Node cur = head; cur != null; cur = cur.next) {
        map.get(cur).next = map.get(cur.next);
        map.get(cur).random = map.get(cur.random);
    }
    return map.get(head);
}
// ⚠️ 进阶（O(1) 空间）: 交错复制法——
//   老节点后插新节点（老→新→老→新…）→ 设 random → 拆开两条链
```

> 💡 **两遍法的套路**："**'先建映射、再接指针'是复制类题的通用两遍法**——随机指针指向任意节点，映射让'指回去'变成 O(1) 查表。会哈希版后提一句'交错法 O(1) 空间'，就是进阶加分。"

## 4. 2 两数相加（链表加法）

### 4.1 题目与思路

**题**：两个逆序存储的链表相加（个位在头）。

**模拟加法**：逐位相加 + 进位，新链表尾插：

```java
/**
 * LeetCode 2. 两数相加
 * 模拟: 逐位相加 + 进位（carry），21 的"带进位版"
 * 时间 O(max(m,n))，空间 O(1) 额外
 */
public ListNode addTwoNumbers(ListNode l1, ListNode l2) {
    ListNode dummy = new ListNode(0), tail = dummy;
    int carry = 0;                              // ① 进位

    while (l1 != null || l2 != null || carry > 0) {   // ② 三条件（含进位残留）
        int sum = carry;
        if (l1 != null) { sum += l1.val; l1 = l1.next; }
        if (l2 != null) { sum += l2.val; l2 = l2.next; }

        tail.next = new ListNode(sum % 10);     // ③ 当前位
        tail = tail.next;
        carry = sum / 10;                       // ④ 进位
    }
    return dummy.next;
}
// 推演 [2,4,3] + [5,6,4]：342 + 465 = 807 → [7,0,8] ✓
// ⚠️ 边界: 两链表不等长 / 最后有进位（9+9+1 → 19 残留 carry）——
//   while 条件含 carry > 0 一网打尽
// 变体: 445 两数相加 II（正序存储 → 先反转再算）
```

> 🎯 **链表加法的边界意识**："**'循环条件三合一'（l1 或 l2 或 carry）是加法的边界法宝**——不等长、进位残留全部覆盖。会 2 后，445（反转后加）只是加一个 206 组件。"

## 5. 430 扁平化多级双向链表

### 5.1 题目与思路

**题**：多级双向链表（child 指针）扁平化为单层。

**迭代 + 栈**：遇到 child 时保存 next 入栈，处理完子链后弹栈续接：

```java
/**
 * LeetCode 430. 扁平化多级双向链表
 * 思路: 遇到 child → 当前 next 入栈 → 接 child 链 →
 *       子链走完 → 弹栈续接
 * 时间 O(n)，空间 O(d)（d = 最深嵌套）
 */
public Node flatten(Node head) {
    if (head == null) return head;
    Deque<Node> stack = new ArrayDeque<>();
    Node cur = head;

    while (cur != null) {
        if (cur.child != null) {               // ① 有子链
            if (cur.next != null) {
                stack.push(cur.next);          // ② 保存下一段（回头续接）
            }
            cur.next = cur.child;              // ③ 接子链
            cur.next.prev = cur;
            cur.child = null;                  // ④ 清 child
        }
        if (cur.next == null && !stack.isEmpty()) {
            Node next = stack.pop();           // ⑤ 子链走完 → 弹栈续接
            cur.next = next;
            next.prev = cur;
        }
        cur = cur.next;
    }
    return head;
}
```

> 💡 **栈的作用**："**栈保存'回来继续走的路'**——遇 child 先记路（next 入栈），走完子链再返回。这是树的 DFS 前序遍历在链表上的变体，与 114 二叉树展开为链表的思路同源。"

## 6. 系统设计视角：为什么是双向链表

### 6.1 双向链表的三重身份

```text
① 算法题: 146 LRU 的核心结构（O(1) 删除任意节点）
② 数据结构: Deque/LinkedList 的底层（双向 = 双端操作）
③ 系统设计: Redis 内存淘汰（LRU/LFU）、缓存设计、数据库页置换

为什么"双向"是刚需:
  删除"任意节点" → 需要 O(1) 找前驱 → 单向链表做不到
  ⚠️ 数组删除中间 = O(n) 搬移；单向链表删中间 = O(n) 找前驱
  → 只有双向链表 + 哈希能做到 O(1) 全操作

工程事实:
  Redis 的 LRU 近似实现、Java LinkedHashMap（accessOrder=true）
  都是"哈希 + 双向链表"——146 就是它们的算法抽象
```

### 6.2 面试表达（系统设计角度）

```text
"146 的选型逻辑:
  查找要 O(1) → 哈希表；
  删除任意节点要 O(1) → 双向链表（有前驱指针）；
  淘汰要'最久未使用' → 链表按使用时间排序，尾部即最旧；
  哨兵节点免去头尾边界判断。
  这个组合也是 Redis 内存淘汰与 LinkedHashMap 的底层。"
```

> 🎯 **146 的分量**："**LRU 是算法题与系统设计的唯一'双向桥梁'**——Amazon/Meta/Microsoft/Google 的 senior 面试常客，Redis/LinkedHashMap 的工程原型。能把'为什么双向'讲成一段设计权衡，就是算法题答出系统设计深度。"

## 7. 组合题识别与易错点

### 7.1 组合题识别表

| 题 | 组合 | 核心选型 |
|:---:|------|------|
| 146 LRU | 链表 × 哈希 | 双向链表（O(1) 删任意） |
| 138 复制 | 链表 × 哈希 | 映射表（old → new） |
| 2 两数相加 | 链表 × 数学 | 进位模拟 |
| 430 扁平化 | 链表 × 树/栈 | 栈保存回溯路径 |
| 445 两数相加 II | 链表 × 数学 × 反转 | 206 + 2 |

### 7.2 易错点

| # | 易错点 | 正确写法 | 后果 |
|:---:|------|------|------|
| 1 | LRU 忘删哈希 | `map.remove(last.key)` | 哈希残留脏数据 |
| 2 | LRU 哨兵接错 | head.next.prev 双向维护 | 链表断裂 |
| 3 | 138 忘处理 random=null | `map.get(cur.random)` 允许 null | 空指针（哈希 get 返回 null） |
| 4 | 2 的 while 条件漏 carry | `|| carry > 0` | 进位丢失 |
| 5 | 430 忘清 child | `cur.child = null` | 循环遍历死循环 |
| 6 | 146 单链表实现 | 双向（删任意 O(1)） | 复杂度退化 O(n) |
| 7 | 138 交错法忘拆链 | 双链交替 | 新旧节点混杂 |

> 🎯 **核心要点**：组合题通关四件事——**① 146 LRU 手撕 + 选型论述**（哈希查找 + 双向删除 + 哨兵边界，'为什么双向'必答）；**② 138 两遍法**（先映射后接指针）；**③ 2 的进位边界**（循环条件三合一）；**④ 430 栈回溯**（先记路再走子链）。**组合题是 senior 分水岭——'会操作'与'会选型'的差距就在这四题里**。
