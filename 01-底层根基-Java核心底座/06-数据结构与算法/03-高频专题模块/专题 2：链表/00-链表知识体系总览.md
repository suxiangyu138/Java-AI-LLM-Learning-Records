## 4. 核心概念速查

| 概念 | 一句话解释 | 说明 |
|------|-----------|------|
| **链表** | 节点 + next 指针的线性结构 | 无随机访问，只能顺序遍历 |
| **哑结点（dummy）** | 虚拟头节点，统一边界 | 删除/插入头节点的必需技巧 |
| **反转** | 把 next 指向前驱 | 三指针迭代（O(1) 空间） |
| **快慢指针** | 速度不同的双指针 | 环/中点/倒数第 K 的统一武器 |
| **Floyd 判圈** | 慢 1 快 2，必相遇 | 速度差 1 保证必然追上 |
| **入环点** | 环的起点 | 相遇后重置 head 同速再遇 |
| **递归反转** | head.next.next = head | 简洁但 O(n) 栈空间 |
| **归并排序链表** | 中点拆分 + 有序合并 | 链表排序唯一自然解 |
| **LRU** | 哈希 + 双向链表 | O(1) 读写的缓存设计 |

## 5. 解题模式速查

### 5.1 五大模式 → 题 → 技巧

| 模式 | 识别信号 | 核心技巧 | 代表题 |
|------|------|------|------|
| 反转 | "反转/翻转" | 三指针 + 哑结点 | 206/92/25 |
| 环检测 | "环/循环" | 快慢指针（慢 1 快 2） | 141/142 |
| 合并 | "合并/拼接" | 哑结点 + 谁小接谁 | 21/23 |
| 快慢 | "中点/倒数/回文/重排" | 速度差 / 步差 | 876/19/234/143 |
| 组合 | "缓存/复制/加法" | 哈希 + 链表 / 交错 | 146/138/2 |

### 5.2 心法两则

```text
心法一（哑结点）: 让所有真实节点都有"前驱"——
  删除/插入头节点时不用特判
  → 19 删倒数 N 必需、203 删值推荐、206 反转可用可不用
  → 环检测不需要（只移动指针，无前驱操作）

心法二（三指针口诀）: "保存 next → 翻转 next → 前进"——
  反转类题的通用节奏，防止"断链丢节点"

⚠️ 链表面试特点: "非常死板"——来来回回就这几类套路，
   掌握模式比刷题数量重要（2025 年面试趋势确认）
```

> 🎯 **一句话定位**："**链表 = 指针操作 + 边界处理 + 思维转化（递归 vs 迭代）**——掌握五大模式 + 两大心法，链表面试就稳了。大多数题 O(n)/O(1) 空间（迭代），面试官默认期望这个效率。"

## 6. 常见误区速查

| 误区 | 正解 |
|------|------|
| "递归反转空间 O(1)" | ❌ 最差 O(n) 栈空间——大链表有栈溢出风险，面试追问点 |
| "141 快指针走 3 步也行" | ❌ 速度差必须 1（慢 1 快 2）——差 >1 时相遇取决于距离与环长整除关系 |
| "dummy 只用于删除头" | ❌ 一切"头节点可能被改/被删"的场景都可用，统一所有节点的前驱 |
| "链表题用哈希表判环" | ❌ 141 要求 O(1) 空间 → 快慢指针是标准解 |
| "23 合并 K 用两两合并就行" | ❌ 朴素两两 O(N·K)；堆 O(N log K)、分治 O(N log K) |
| "148 排序链表用快排" | ❌ 无随机访问，快排 partition 低效——归并是唯一自然解 |
| "操作指针不用先保存" | ❌ 先保存可能丢失的引用（next 被改写前）——断链 bug 之源 |
| "链表题不用画图" | ❌ 不画图必错——面试官也期待你先画图再写码 |
| "146 LRU 用普通链表就行" | ❌ O(1) 查找需要哈希，O(1) 删除需要双向链表——两者缺一不可 |
| "回文链表用栈" | ❌ O(n) 空间；中点 + 反转后半 O(1) 空间是标准解 |
