## 1. 合并模型：哑结点 + 谁小接谁

```java
// 合并两有序链表统一模板
ListNode dummy = new ListNode(0), tail = dummy;
while (l1 != null && l2 != null) {
    if (l1.val <= l2.val) { tail.next = l1; l1 = l1.next; }   // 谁小接谁
    else                  { tail.next = l2; l2 = l2.next; }
    tail = tail.next;
}
tail.next = (l1 != null) ? l1 : l2;      // 接上剩余（天然有序）
return dummy.next;
```

**为什么这是"第二母题"**：

```text
① 21 合并两链表 → 23 合并 K 链表（堆/分治的组件）
② 21 合并两链表 → 148 排序链表（归并的 merge 步骤）
③ 21 合并两链表 → 143 重排链表（交替合并的后半步）
④ 21 合并两链表 → 2 两数相加（带进位版）

⚠️ 21 是所有"合并族"的原子操作——与数组的 merge 同构
   （归并排序的 merge 是数组版，21 是链表版）
```

> 🎯 **核心认知**："**哑结点 + 谁小接谁**是合并族的统一骨架——21/23/148/143 的合并步骤全部复用这一个模板。合并与反转并列链表两大母题，其他题都是组合变形。"

## 2. 21 合并两个有序链表（递归 + 迭代双解）

### 2.1 迭代版（O(1) 空间，面试首选）

```java
/**
 * LeetCode 21. 合并两个有序链表（迭代版）
 * 时间 O(m+n)，空间 O(1)
 */
public ListNode mergeTwoLists(ListNode l1, ListNode l2) {
    ListNode dummy = new ListNode(0), tail = dummy;
    while (l1 != null && l2 != null) {
        if (l1.val <= l2.val) { tail.next = l1; l1 = l1.next; }
        else                  { tail.next = l2; l2 = l2.next; }
        tail = tail.next;
    }
    tail.next = (l1 != null) ? l1 : l2;     // ① 接剩余（不用逐个拷）
    return dummy.next;
}
```

### 2.2 递归版（简洁优雅）

```java
/**
 * 合并两有序链表（递归版）
 * 时间 O(m+n)，空间 O(m+n)（递归栈）⚠️
 */
public ListNode mergeTwoListsRecursive(ListNode l1, ListNode l2) {
    if (l1 == null) return l2;              // ① 基线: 一空接另一
    if (l2 == null) return l1;
    if (l1.val <= l2.val) {                 // ② 谁小谁当头，递归接剩余
        l1.next = mergeTwoListsRecursive(l1.next, l2);
        return l1;
    } else {
        l2.next = mergeTwoListsRecursive(l1, l2.next);
        return l2;
    }
}
```

> 💡 **双解对比**："**迭代 O(1) 空间首选，递归简洁但 O(m+n) 栈**——与 206 反转的双解对比同款。面试先写迭代，追问时补递归展示第二种思路。"

## 3. 23 合并 K 个升序链表（堆 / 分治）

### 3.1 堆版（K 路归并，O(N log K)）

```java
/**
 * LeetCode 23. 合并 K 个升序链表（最小堆 = K 路归并）
 * 时间 O(N log K)，空间 O(K)
 */
public ListNode mergeKLists(ListNode[] lists) {
    PriorityQueue<ListNode> heap = new PriorityQueue<>((a, b) -> a.val - b.val);
    for (ListNode h : lists)                // ① K 个头入堆（空链跳过）
        if (h != null) heap.offer(h);

    ListNode dummy = new ListNode(0), tail = dummy;
    while (!heap.isEmpty()) {
        ListNode node = heap.poll();        // ② 弹全局最小
        tail.next = node;
        tail = node;
        if (node.next != null) heap.offer(node.next);   // ③ 同路补位
    }
    return dummy.next;
}
```

### 3.2 分治版（两两合并，O(N log K) 空间 O(log K)）

```java
/**
 * 23. 合并 K 个升序链表（分治两两合并）
 * 空间 O(log K)（递归栈）—— K 大时比堆省空间
 */
public ListNode mergeKListsDivide(ListNode[] lists) {
    if (lists == null || lists.length == 0) return null;
    return mergeRange(lists, 0, lists.length - 1);
}

private ListNode mergeRange(ListNode[] lists, int lo, int hi) {
    if (lo == hi) return lists[lo];
    int mid = lo + (hi - lo) / 2;
    ListNode left = mergeRange(lists, lo, mid);      // ① 左半合并
    ListNode right = mergeRange(lists, mid + 1, hi); // ② 右半合并
    return mergeTwoLists(left, right);               // ③ 21 模板合二
}
// 推演 4 个链表：合并 (0,1) 和 (2,3) → 再合并两结果 → 2 层
//   ⚠️ 每层总 O(N)，共 log K 层 → O(N log K)
```

> 🎯 **23 的选型论述**："**堆 O(K) 空间、分治 O(log K) 空间，时间同为 O(N log K)**——K 大时堆空间可能超限，分治更省；K 小两者无差。'两版都能给 + 讲清空间差异'是 23 题的完整答案（与多路归并专题联动）。"

## 4. 148 排序链表（归并排序）

### 4.1 题目与思路

**题**：链表 O(n log n) 排序（不能用数组辅助）。

**为什么是归并**：快排 partition 需随机访问、堆排需数组下标——**归并只需 next 指针，链表天然适配**：

```java
/**
 * LeetCode 148. 排序链表（链表归并排序）
 * 三步: 快慢找中点 → 断开 → 递归排序 + 21 合并
 * 时间 O(n log n)，空间 O(log n)（递归栈）
 */
public ListNode sortList(ListNode head) {
    if (head == null || head.next == null) return head;   // ① 基线

    // ② 快慢找中点（fast 从 head.next 起步 → slow 停在左半尾）
    ListNode slow = head, fast = head.next;
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
    }
    ListNode right = slow.next;
    slow.next = null;                            // ③ 断开两半！

    // ④ 递归排序两半
    ListNode left = sortList(head);
    right = sortList(right);

    // ⑤ 21 模板合并
    return mergeTwoLists(left, right);
}
// 推演 [4→2→1→3]：拆 [4,2] | [1,3] → 排 [2,4] | [1,3] → 合并 [1,2,3,4] ✓
// ⚠️ 关键细节: fast 从 head.next 起步（不是 head）
//   → 偶数长度时 slow 停在"左半尾"而非右半头 → 断开后两侧均衡
```

### 4.2 与数组归并的对比

| 维度 | 数组归并 | 链表归并 |
|------|:---:|:---:|
| 空间 | O(n) 辅助数组 | **O(log n)**（仅递归栈） |
| 合并 | 双指针 + 辅助数组回填 | 改指针（21 模板） |
| 拆分 | 下标对半 | 快慢指针 + 断开 |
| 稳定性 | ✔ | ✔（21 用 <=） |
| 复杂度 | O(n log n) | O(n log n) |

> 🎯 **148 的考点**："**链表归并 = 876 找中点 + 21 合并 + 正确断开**——三个已学组件拼装。`fast = head.next` 让 slow 停在左半尾是唯一新细节，讲清'为什么不是 head 起步'（偶数长度断开位置）就是深度。"

## 5. 复杂度对比与选型

| 题 | 方法 | 时间 | 空间 | 选型依据 |
|:---:|------|:---:|:---:|------|
| 21 | 迭代/递归 | O(m+n) | O(1)/O(m+n) | 迭代首选 |
| 23 | 最小堆 | O(N log K) | O(K) | K 小时默认 |
| 23 | 分治两两 | O(N log K) | O(log K) | K 大、空间受限 |
| 148 | 链表归并 | O(n log n) | O(log n) | 唯一自然解 |

```text
⚠️ 常见误答:
  "23 用两两顺序合并" → O(N·K) 不可接受（每轮全量扫描 K−1 次）
  "148 用快排" → partition 需要双向遍历/随机访问，链表低效
  "148 转数组排再转回" → 面试可提（O(n) 空间），但不是链表题的正解
```

## 6. 合并思想迁移与易错点

### 6.1 合并思想迁移表

| 题 | 合并的应用 | 组件 |
|:---:|------|------|
| 21 | 两链表合并 | 原子操作 |
| 23 | K 链表合并 | 21 + 堆/分治 |
| 148 | 排序链表 | 876 + 21 + 断开 |
| 143 | 重排链表 | 876 + 206 + 交替合并 |
| 2 | 两数相加 | 21 + 进位 |
| 1669 | 合并两个链表 | 21 + 区间拼接 |

### 6.2 易错点

| # | 易错点 | 正确写法 | 后果 |
|:---:|------|------|------|
| 1 | 合并忘接剩余 | `tail.next = l1 != null ? l1 : l2` | 丢后半段 |
| 2 | 148 忘断开 | `slow.next = null` | 递归死循环 |
| 3 | 148 fast 从 head 起步 | `fast = head.next` | 偶数长度断开偏右 |
| 4 | 23 空链表入堆 | `if (h != null)` 过滤 | 堆污染/空指针 |
| 5 | 23 补位忘判 null | `if (node.next != null)` | 空指针 |
| 6 | 21 递归忘基线 | `l1 == null` 返回 l2 | 无限递归 |
| 7 | 稳定性用 `<` | 用 `<=`（相等取左） | 失去稳定性 |

> 🎯 **核心要点**：合并与排序通关四件事——**① 21 模板烂熟**（哑结点 + 谁小接谁 + 接剩余）；**② 23 双解**（堆 O(K) / 分治 O(log K) 空间，选型讲清）；**③ 148 三组件拼装**（876 + 21 + 断开，fast=head.next 细节）；**④ 迁移意识**（合并是 143/2/1669 的公共组件）。**合并是链表"第二母题"——排序链表、重排链表、K 链表全部建立在 21 之上**。
