## 1. 状态设计的三个维度

### 1.1 状态 = 递归参数的最小完备集

```
状态设计三问：
  ① 需要知道什么才能决定下一步？（参数）
  ② 历史信息是否可合并？（同状态同未来 → 可合并）
  ③ 参数组合是否稀疏？（决定缓存结构）

⚠️ 完备性：状态必须覆盖"所有影响未来的信息"
  例：青蛙过河（403）——只知道位置不够！
    下一步能跳多远取决于"上一次跳了多远"
    → 状态 = (位置, 上一次跳跃长度)

⚠️ 合并性：不同历史到达同状态 → 未来相同 → 可缓存
  例：掷骰子（1155）——到达 (剩余和=5, 剩余骰子=2)
    的路径有千万条，但未来相同 → 缓存 (5,2) 即可
```

### 1.2 状态维度速查

| 题目 | 状态 | 维度 | 为什么 |
|------|------|:---:|--------|
| 62 不同路径 | (i, j) | 2 | 位置即全部信息 |
| 329 最长递增路径 | (i, j) | 2 | 位置 + 记忆化防环 |
| 403 青蛙过河 | (pos, jump) | 2 | 下一步依赖上一步 |
| 576 出界路径数 | (i, j, steps) | 3 | 剩余步数影响后续 |
| 140 单词拆分 | (index) | 1 | 后缀下标即状态 |
| 464 我能赢吗 | (mask, total) | 2 | 已选数字集合 |
| 808 分汤 | (a, b) | 2 | 剩余量 |

```
⚠️ 面试表达：
"状态是'影响未来的最小信息集'——参数多余会
 浪费缓存空间，参数不足会算错。403 必须带
 跳跃长度、464 必须带已选集合（掩码）。"
```

### 1.3 状态设计的验证方法

```
① 写出朴素递归（不缓存）→ 明确参数
② 问自己："下一步需要知道什么？"→ 核对参数完备
③ 找"同一参数的重复计算"→ 确认有重叠（值得记忆化）
④ 画状态转移图 → 检查是否有环（有环需要 visited/博弈）

⚠️ 无重叠 → 记忆化无意义（退化为普通递归）
  有环 → 记忆化防死循环（329 最长路径需 visited 或排序）
```

## 2. 缓存数据结构的选型

### 2.1 四类缓存结构

| 结构 | 适用 | 优点 | 缺点 |
|------|------|------|------|
| 一维数组 | 单参数（下标） | 最快 | 只限整数参数 |
| 二维数组 | 双参数（整数） | 快、直观 | 需预知边界 |
| HashMap | 稀疏状态/大范围 | 只存实际状态 | 哈希开销 |
| Map<Long, V> | 多参数编码 | 灵活 | 编码易错 |

```
⚠️ 选型口诀：
  参数范围已知且紧凑 → 数组（int[][]）
  参数范围大/稀疏 → Map（key = 参数拼接）
  参数多（>3）→ 编码成 long 或 String key

⚠️ 编码技巧：
  (i, j, k) → i * 1000_000 + j * 1000 + k（十进制拼接）
  位掩码状态 → 直接用 mask 作下标（2^m 数组）
```

### 2.2 哨兵值的坑（经典陷阱）

```java
// ⚠️ 记忆化缓存用"默认值判断是否算过"——默认值必须是"不可能结果"！
// 0 作哨兵的问题：如果答案是 0，会反复重算！
double[][] memo = new double[m + 1][m + 1];
// 分汤的答案是 0~1 的 double → 0 可能恰好是答案？
// → 用 -1 哨兵或 boolean visited 数组

// ✅ 正确姿势：
double[][] memo = new double[m + 1][m + 1];
Arrays.fill 每行 with -1.0;        // ⚠️ 答案非负 → -1 安全
if (memo[a][b] >= 0) return memo[a][b];

// 或双数组：
boolean[][] visited = new boolean[m + 1][m + 1];
if (visited[a][b]) return memo[a][b];
visited[a][b] = true;
```

> 🎯 **面试必答**："缓存判重不能靠'默认值 0'——0 可能是合法答案导致反复重算。用 -1 哨兵或 visited 数组。"

### 2.3 缓存与返回值类型

```
整数 → int[][] + 哨兵 -1
double → double[][] + 哨兵 -1.0 或 visited
boolean（博弈题）→ Boolean[][]（null = 未算）⚠️ 三态！
List（构造类）→ Map<key, List>（null 判重）

⚠️ Boolean 缓存的三态：null（未算）/ true / false
  ——不能用默认 false 判重（false 是合法结果）
```

## 3. 记忆化 ↔ 表格 DP 双向转换

### 3.1 两种形态的同一性

```
记忆化（自顶向下）= 递归 + 缓存
表格 DP（自底向上）= 循环 + 数组

同一问题两种写法：
  递归视角：dfs(状态) = f(子状态)（直观）
  表格视角：dp[i] = f(dp[i-1])（高效）

⚠️ 转换三步骤：
  ① 确定状态维度 → 数组形状
  ② 确定转移方向 → 循环顺序（依赖先算）
  ③ 确定边界 → 初始化

例：62 不同路径
  记忆化：dfs(i,j) = dfs(i-1,j) + dfs(i,j-1)
  表格：dp[i][j] = dp[i-1][j] + dp[i][j-1]（第 0 行/列 = 1）
```

### 3.2 各自的适用场景

| 维度 | 记忆化 | 表格 DP |
|------|:---:|:---:|
| 状态稀疏 | ✅ 只算可达 | ❌ 全表填 |
| 转移方向复杂 | ✅ 递归天然处理 | ⚠️ 循环顺序难定 |
| 博弈/带环 | ✅ 递归 + 状态判断 | ⚠️ 需拓扑 |
| 性能极致 | ⚠️ 递归调用开销 | ✅ 循环最快 |
| 直觉 | ✅ 直接 | ⚠️ 需想转移序 |

```
⚠️ 面试表达：
"记忆化与表格 DP 等价——记忆化只算可达状态
 且思路直观；表格 DP 全量填表但无递归开销。
 稀疏状态用记忆化，稠密状态用表格。"
```

### 3.3 记忆化特有的优势场景

```
① 状态空间巨大但实际可达少（搜索树剪枝）
② 转移带"跳过/不规则"（表格循环顺序难定）
③ 博弈类（需要"当前玩家视角"，递归自然表达）
④ 字符串处理（后缀下标递归切分自然）

⚠️ 典型：140 单词拆分 II、464 我能赢吗、403 青蛙过河
  都是"记忆化明显优于表格"的题目
```

## 4. 位掩码状态：子集型记忆化

### 4.1 子集状态的特征

```
问题："从集合中选/访问" → 状态 = 已选集合
集合用位掩码表示：mask 的第 i 位 = 元素 i 是否已选
  状态数 = 2^m（m = 元素数，一般 m ≤ 20）

⚠️ 识别信号：
  "每个元素用一次/访问一次" → 掩码
  "顺序无关的集合状态" → 掩码

常见形态：
  464 我能赢吗：mask = 已选的数
  旅行商（TSP）：mask = 已访问城市
  状态压缩 DP：掩码是标准状态
```

### 4.2 掩码状态的操作速查

```java
// mask 常用操作（必背）：
int mask = 0;
mask |= 1 << i;              // ① 选第 i 个（置位）
boolean has = (mask >> i & 1) == 1;   // ② 检查第 i 个
mask & ~(1 << i);            // ③ 移除第 i 个（清位）
Integer.bitCount(mask);      // ④ 已选个数
int full = (1 << m) - 1;     // ⑤ 全集
// 遍历子集：for (int sub = mask; sub > 0; sub = (sub - 1) & mask)
```

```java
/** 464 状态缓存：int[]（mask 直接作下标） */
int[] memo = new int[1 << m];          // ⚠️ 掩码作下标
// 0 = 未算，1 = 必胜，-1 = 必败（三态）
```

> 🎯 **要点**：掩码状态用数组（2^m 大小）直接索引——比 Map 快且简单。m ≤ 20 时 2^m ≤ 10⁶ 可接受。

## 5. 记忆化的树形与图场景

### 5.1 树形记忆化

```
树 DP = 记忆化在树上的应用：
  后序递归 + 状态（节点, 选择/不选）
  ⚠️ 记忆化价值取决于"同状态是否重复出现"
  普通树每个节点只访问一次 → 无需缓存
  但"多个子树结构相同"（如 894 满二叉树）→ 需要

⚠️ 面试表达：
"树形记忆化要判断必要性——普通树上每个
 节点状态唯一（无需缓存）；结构复用的
 构造题（894）才值得缓存。"
```

### 5.2 图上的记忆化（防环）

```
图 DFS + 记忆化的问题：环 → 无限递归
  329 最长递增路径：沿递增方向 → 天然无环（严格递增）
  一般图：需要 visited 或拓扑序

⚠️ 两类处理：
  ① 天然无环（递增/递减方向）→ 直接记忆化
  ② 有环 → 三色标记（白灰黑）或拓扑排序后 DP

面试表达：
"图上记忆化的前提是无环——329 利用严格递增
 天然无环；一般图要先用拓扑排序或三色标记防环。"
```

## 6. 空间优化与缓存陷阱

### 6.1 空间优化思路

```
① 维度压缩：只依赖前一行 → 滚动数组（表格 DP 专属）
② 稀疏 Map：大范围参数只存实际到达的
③ 剪枝后缓存：先剪枝再查缓存（减少缓存写入）

⚠️ 记忆化的空间 = 状态数 × 每状态大小
  状态数由参数范围决定——参数范围大是空间杀手
```

### 6.2 缓存陷阱清单

| 陷阱 | 后果 | 修正 |
|------|------|------|
| 0 作哨兵 | 答案 0 反复重算 | -1 / visited |
| Boolean 默认 false 判重 | 必败状态重算 | null 判重 |
| 参数范围估计错 | 数组越界 | 先分析边界 |
| 掩码状态忘重置 | 串状态 | 每测试用例新 memo |
| 缓存不完整（漏参数） | 状态污染 | 参数完备性检查 |
| 大状态 Map key 编码冲突 | 结果错 | 分隔符/位编码 |

### 6.3 调试记忆化

```
① 小规模手推状态转移
② 打印"首次计算 vs 命中缓存"（验证重叠存在）
③ 检查返回值语义（返回给谁：子问题/全局）
④ 边界：memo 初始化与哨兵一致性

⚠️ 面试表达：
"调试记忆化先验证两件事——状态完备（不会漏算）
 与缓存命中（确实有重叠）。两者缺一，结果错或缓存无用。"
```

## 7. 面试要点与追问

### 7.1 面试话术模板

```
"记忆化 = 递归 + 缓存。状态设计是核心：
 影响未来的最小参数集（403 要带跳跃长度）。
 缓存选型：参数紧凑用数组、稀疏用 Map、
 掩码状态直接作下标。缓存判重用 -1 哨兵
 或 visited（0 可能是合法答案）。
 与表格 DP 等价，稀疏状态记忆化更优。"
```

### 7.2 高频追问 TOP 8

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | 状态怎么设计？ | 影响未来的最小参数完备集 |
| 2 | 缓存用数组还是 Map？ | 范围紧凑数组；稀疏 Map |
| 3 | 哨兵选什么？ | -1 / visited（0 可能是答案） |
| 4 | 与表格 DP 区别？ | 等价；稀疏用记忆化、稠密用表格 |
| 5 | 掩码状态？ | 2^m 数组直接索引（m ≤ 20） |
| 6 | 图上有环？ | 递增方向天然无环；否则拓扑/三色 |
| 7 | 什么时候记忆化没用？ | 子问题无重叠（普通递归即可） |
| 8 | 树形需要缓存吗？ | 普通树不需要；结构复用才需要 |

### 7.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| 0 哨兵 | 答案 0 重算 | -1/visited |
| 状态缺参数 | 结果错 | 完备性验证 |
| 掩码编码错 | 越界/冲突 | 1<<i 位运算 |
| 有环直接记忆化 | 栈溢出 | 无环前提/防环 |
| 缓存全局复用 | 串测试 | 每用例重建 |

---

> 🎯 **核心要点**：记忆化 = **状态完备**（最小参数集）+ **缓存选型**（数组/Map/掩码）+ **哨兵安全**（-1/visited）+ **无环前提**（递增方向/拓扑）。它是 DP 的递归形态——状态设计能力直接迁移到表格 DP。
