## 1. 核心概念

### 1.1 什么是记忆化

> 记忆化（Memoization）= **递归（DFS）+ 缓存**。把已计算的子问题结果存起来，重复遇到直接返回，避免指数级重复计算。

```
fib(5) 的朴素递归：
  大量重复计算（fib(3) 算两次、fib(2) 算三次）

记忆化后：
  fib(3) 第一次算完存入 memo[3]
  之后 O(1) 直接取 → O(n) 而非 O(2ⁿ)

本质：动态规划的自顶向下实现
  递归（分解） + 缓存（去重）
```

### 1.2 识别信号

```
"递归会超时 + 存在重叠子问题" → 记忆化
"状态可哈希/可索引（坐标/参数）" → 记忆化

⚠️ 无重叠子问题 → 记忆化无意义（白加缓存）
  判断：递归树中相同状态出现多次？

经典识别：
  Fibonacci：重叠明显 → 记忆化
  归并排序：子问题不重叠 → 不需要
```

### 1.3 记忆化的价值

```
① 把指数级降到多项式级
   fib：O(2ⁿ) → O(n)
   网格路径：O(2^(m+n)) → O(mn)
② 只计算用到的状态（稀疏场景省计算）
③ 自顶向下直观（递归思路直接加缓存）

⚠️ 本质认知：
  "记忆化 = DP 的递归写法"
  与表格 DP 数学等价，实现视角不同
```

## 2. 完整代码模板

### 2.1 记忆化通用模板

```java
/**
 * 记忆化通用模板（三步：查缓存 → 计算 → 存缓存）
 */
public int solve(参数) {
    int[][] memo = new int[m][n];        // ① 缓存（-1 = 未算）
    for (int[] row : memo) Arrays.fill(row, -1);
    return dfs(参数, memo);
}

private int dfs(状态参数, int[][] memo) {
    if (基础情况) return 基础值;          // ② base case

    if (memo[i][j] != -1) return memo[i][j];   // ③ ⚠️ 查缓存！

    int result = 计算(递归调用);          // ④ 递归计算
    return memo[i][j] = result;          // ⑤ ⚠️ 存缓存
}
// ⚠️ 查缓存和存缓存缺一不可：
//   只查不存 → 每次重算（无意义）
//   只存不查 → 永远不命中（白存）
```

### 2.2 62. 不同路径（记忆化）

```java
/**
 * LeetCode 62. 不同路径
 * 朴素 DFS：O(2^(m+n)) 超时 → 记忆化 O(mn)
 */
public int uniquePaths(int m, int n) {
    int[][] memo = new int[m][n];
    for (int[] row : memo) Arrays.fill(row, -1);
    return dfs(m, n, 0, 0, memo);
}

private int dfs(int m, int n, int i, int j, int[][] memo) {
    if (i == m - 1 && j == n - 1) return 1;   // 到达终点
    if (i >= m || j >= n) return 0;           // 越界

    if (memo[i][j] != -1) return memo[i][j];  // 查缓存

    memo[i][j] = dfs(m, n, i + 1, j, memo)    // 右
               + dfs(m, n, i, j + 1, memo);   // 下
    return memo[i][j];                        // 存缓存
}
// 每个格子算一次 → O(mn)
// 推演 3×3：从 (2,2) 出发 = 1（终点）
//   (2,1) = 1；(1,2) = 1；(1,1) = 2 ...
//   memo 填充后直接复用 ✓
```

### 2.3 329. 矩阵最长递增路径（经典）

```java
/**
 * LeetCode 329. 矩阵中的最长递增路径（Hard）
 * memo[i][j] = 从 (i,j) 出发的最长递增路径
 * ⚠️ 递增 → 无环 → 不需要 visited！
 */
public int longestIncreasingPath(int[][] matrix) {
    int m = matrix.length, n = matrix[0].length;
    int[][] memo = new int[m][n];       // 0 = 未计算

    int maxLen = 0;
    for (int i = 0; i < m; i++) {
        for (int j = 0; j < n; j++) {
            maxLen = Math.max(maxLen, dfs(matrix, i, j, memo));
        }
    }
    return maxLen;
}

private int dfs(int[][] matrix, int i, int j, int[][] memo) {
    if (memo[i][j] != 0) return memo[i][j];     // 查缓存

    int[][] dirs = {{0,1},{0,-1},{1,0},{-1,0}};
    int best = 1;                               // 自己至少 1

    for (int[] d : dirs) {
        int ni = i + d[0], nj = j + d[1];
        if (越界 || matrix[ni][nj] <= matrix[i][j]) continue;  // 非递增跳过

        best = Math.max(best, 1 + dfs(matrix, ni, nj, memo));
    }
    return memo[i][j] = best;                   // 存缓存
}
// 每个格子算一次 → O(mn)
// ⚠️ 为什么不需要 visited？
//   路径严格递增 → 不可能走回已访问格子 → 天然无环
//   （面试必讲点！）
```

## 3. 记忆化 vs 表格 DP

### 3.1 对比表

| 维度 | 记忆化 | 表格 DP |
|------|:---:|:---:|
| 方向 | 自顶向下 | 自底向上 |
| 实现 | 递归 + 缓存 | 循环 + 数组 |
| 计算范围 | 只算用到的状态 | 通常算全部 |
| 遍历顺序 | 无需显式 | 必须确定 |
| 栈溢出 | 深度大时可能 | 无风险 |
| 状态稀疏 | ✅ 高效 | 浪费 |
| 滚动数组 | 不适用 | ✅ |

### 3.2 选型决策

```
✅ 记忆化更合适：
  状态空间稀疏（只算用到的）
  遍历顺序难确定（329 递增路径）
  树形/递归结构天然（树 DP）

✅ 表格 DP 更合适：
  所有状态都需要（二维表格）
  需要滚动数组优化空间
  状态转移顺序明确

⚠️ 面试表达：
"这题我写记忆化搜索——DFS + memo 缓存，
 和 DP 本质等价，只是自顶向下实现。
 状态稀疏时只算用到的，更高效。"
```

### 3.3 面试手写建议

```
先写记忆化（思路直观、快速验证）
再转表格（面试官要求优化空间时）
⚠️ 记忆化 → 表格的转换：
  ① 识别状态与依赖方向
  ② 确定遍历顺序（保证依赖先算）
  ③ 循环实现 + 可选滚动数组

面试加分："我可以用滚动数组把空间
 从 O(mn) 优化到 O(n)"（表格版）
```

## 4. 记忆化的设计要点

### 4.1 缓存结构选择

```
一维状态 → int[] memo（-1 标记）
二维状态 → int[][] memo
复杂状态 → HashMap<参数组合, 结果>
  例：403 青蛙过河 → Map<位置, Set<跳跃>>
       464 我能赢吗 → Boolean[] memo（掩码）

⚠️ 缓存键必须包含全部状态参数
  少一个参数 → 状态不完整 → 结果错误
```

### 4.2 记忆化与 visited 的关系

```
需要 visited 吗？
  ① 状态转移"单调"（递增/减少）→ 无环 → 不需要
     例：329 递增路径（只走向更大的值）
  ② 状态可能回访（无单调性）→ 需要 visited
     例：79 单词搜索（可走回）
  ③ 记忆化本身可代替 visited？
     ⚠️ 不行！记忆化缓存"结果"，visited 防"回访"
     有环时递归根本不会结束 → 无法缓存

⚠️ 面试必答：
"记忆化防重复计算；visited 防重复访问。
 递增场景天然无环 → 只需记忆化。"
```

### 4.3 常见陷阱

```
① 缓存初值用 0 但结果可能为 0
   → 用 -1 标记"未计算"（329 用 0 因为路径 ≥ 1）
② 忘查缓存（等于没记忆化）
③ 忘存缓存（白算）
④ 递归深度过大（栈溢出）→ 转表格

⚠️ 结果可能为 0 的场景：
  "计数"类（路径数可能是 0）
  → 必须用 -1 或 boolean 标记
```

## 6. 面试要点与追问

### 6.1 面试话术模板

```
"朴素 DFS 有大量重叠子问题（指数级），
 我用记忆化：memo 缓存每个状态的结果，
 递归开头查缓存、算完存缓存。
 本质是 DP 的自顶向下实现——
 每个状态只算一次 → O(状态数 × 转移代价)。
 这题状态是【(i,j)】，状态数 mn，O(mn)。"
```

### 6.2 高频追问 TOP 8

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | 记忆化 vs 表格 DP？ | 自顶向下 vs 自底向上；数学等价，实现视角不同 |
| 2 | 什么时候选记忆化？ | 状态稀疏/顺序难定/递归自然 |
| 3 | 查缓存为什么必须？ | 不查 = 每次重算（记忆化失去意义） |
| 4 | 缓存初值？ | 结果可能为 0 → 用 -1 标记 |
| 5 | 什么时候不需要 visited？ | 转移单调（递增）→ 天然无环 |
| 6 | 递归深度？ | 状态链深度；过大转表格 |
| 7 | 复杂状态缓存？ | HashMap<参数组合, 结果> |
| 8 | 与回溯区别？ | 记忆化缓存结果；回溯撤销选择 |

### 6.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| 忘查缓存 | 重复计算 | 递归开头查 |
| 忘存缓存 | 白算 | 算完存 |
| 初值 0 混淆 | 未计算误判 | -1 标记 |
| 状态参数不全 | 结果错误 | 缓存键含全部参数 |
| 有环用记忆化 | 无限递归 | 先分析单调性 |

> 🎯 **核心要点**：记忆化 = **递归 + 查缓存 + 存缓存**三步模板。识别信号："重叠子问题、DFS 会超时、状态稀疏"。与表格 DP 的等价关系、单调转移免 visited、-1 标记初值是三大必答细节。
