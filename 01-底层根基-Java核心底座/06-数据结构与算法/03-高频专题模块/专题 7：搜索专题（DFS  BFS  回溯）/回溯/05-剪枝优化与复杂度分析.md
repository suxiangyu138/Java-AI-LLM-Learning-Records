## 1. 剪枝的本质：不减复杂度，减搜索树

```text
剪枝 = 提前终止"不可能产生解"的分支

核心认知:
  理论复杂度不变（O(2ⁿ)/O(n!) 是最坏上界）
  实际搜索树大幅收缩（平均情况远小于最坏）

三种剪枝:
  ① 和约束: sum + nums[i] > target → break（02 文件）
  ② 剩余数量: 剩余可选数 < 还需数 → 终止（组合定长）
  ③ 约束前置: 合法性检查放在"选"之前（N皇后/数独）

⚠️ 面试表达:
  "剪枝不减最坏复杂度——O(2ⁿ) 还是 O(2ⁿ)；
   但它砍掉大量无效分支，让实际运行时间可接受。
   剪枝的本质是'提前知道这条路走不通'。"
```

> 🎯 **核心认知**："**剪枝是回溯的'路标系统'——在进入死胡同前就掉头**。判断剪枝是否正确的标准：被剪的分支**必然无解**（而不是"可能无解"）。正确剪枝绝不丢解。"

## 2. 剪枝一：和约束（排序 + break）

### 2.1 原理与代码

```java
// 组合总和类题的标准剪枝（39/40/216）
for (int i = start; i < nums.length; i++) {
    if (sum + nums[i] > target) break;   // ① 排序后: 后续更大必超 → 整层终止
    path.add(nums[i]);
    backtrack(nums, target, i, sum + nums[i], path, result);
    path.remove(path.size() - 1);
}
// ⚠️ 为什么 break 而不是 continue:
//   排序后 nums[i] 递增 → nums[i+1] > nums[i] → 后续必然也超
//   break 直接终止整层循环（continue 还要白扫）
```

### 2.2 为什么必须排序

```text
不排序: sum + nums[i] > target 时无法判断后续——
  后面的元素可能更小（可能不超）→ 只能 continue 不能 break
排序后: 递增序列中"当前超了，后面全超"→ break 安全

⚠️ 排序的额外收益:
  剪枝更狠（break）+ 去重可行（重复相邻）
  一箭双雕——组合总和类题排序是标配
```

> 💡 **面试表达**："**和剪枝 = 排序 + break——'当前超了后面全超'的单调性论证**。能讲清'为什么 break 安全'（排序保证单调），剪枝就答到了原理层。"

## 3. 剪枝二：剩余数量（组合定长）

### 3.1 原理与代码

```java
// 77 组合 / 216 组合总和 III 的定长剪枝
for (int i = start; i <= n; i++) {
    // ① 剩余可选数 (n - i + 1) < 还需数 (k - path.size()) → 后面全不够 → 终止
    if (n - i + 1 < k - path.size()) break;
    path.add(i);
    backtrack(n, k, i + 1, path, result);
    path.remove(path.size() - 1);
}
// 推演 n=4, k=3, path=[1]（还需 2 个）:
//   i=4 时剩余 1 个 < 2 → break（[1,4] 不可能凑满 3 个）
//   节省约一半的分支
```

### 3.2 剪枝条件推导

```text
还需选择数 = k − path.size()
当前位置 i 开始剩余可选数 = n − i + 1
若剩余 < 还需 → 无论怎么选都凑不满 → 终止

⚠️ 这个剪枝只对"定长组合"有效（77/216）——
  不定长的子集/总和题不适用
```

## 4. 剪枝三：约束前置（N皇后/数独）

### 4.1 原理

```text
N皇后: 放置前检查 列/正对角/反对角 三数组——
  冲突 → continue（不进入该分支）
数独: 填数前检查 行/列/宫 三组——
  冲突 → 跳过该数字

约束前置的本质:
  把"合法性检查"从"递归深处"提到"选择之前"
  → 无效分支根本不生成（而非生成了再剪）

对比组合去重（也是剪枝）:
  去重剪枝: 跳过"会产生重复结果"的分支
  约束剪枝: 跳过"会产生非法结果"的分支
  → 两者都是"提前掉头"，只是判据不同
```

> 🎯 **约束前置的意义**："**'选之前检查'比'选之后检查'省掉一整层递归**——N皇后把冲突检查放循环开头，每行最多尝试 n 次而非递归后再验。**检查越早，搜索树越瘦**。"

## 5. N 皇后搜索空间分析（6 个数量级）

### 5.1 从 C(64,8) 到 2000

```text
朴素枚举（8 皇后）:
  从 64 格选 8 格: C(64,8) ≈ 4.4×10⁹ 种组合
  每组合再验证合法性 → 不可行

回溯 + 剪枝的递进收缩:
  ① 行递归: 每行必放 1 个 → 8^8 ≈ 1.7×10⁷（去掉同行）
  ② 列剪枝: 每列至多 1 个 → 8! = 40320（去掉同列）
  ③ 对角线剪枝: 实时检查 → 实际只探索约 2000 个节点

效果: 4.4×10⁹ → 2000 ≈ 缩小 6 个数量级
```

### 5.2 复杂度与规模对照

| n | 解的数量（N皇后） | 搜索节点（剪枝后） |
|:---:|:---:|:---:|
| 4 | 2 | ~15 |
| 8 | 92 | ~2000 |
| 12 | 14200 | ~10⁶ |
| 16 | 14772512 | ~10⁹（接近极限） |

```text
⚠️ 结论: N皇后是"剪枝让不可行变可行"的教科书——
  n=8 朴素不可行、剪枝后毫秒级；n=16 剪枝后仍要秒级
```

> 🎯 **N皇后剪枝的面试价值**："**'行递归 + 列 + 对角线'三连剪枝把 C(64,8)≈4.4×10⁹ 缩到约 2000 节点——6 个数量级**。这个数字对比是回溯剪枝最有力的实证，背下来面试直接引用。"

## 6. 复杂度推导：组合/排列/棋盘

### 6.1 三大类复杂度

| 题型 | 节点数 | 每节点代价 | 总复杂度 | 代表 |
|------|:---:|:---:|:---:|:---:|
| 组合 | C(n,k) | O(k)（拷贝） | O(C(n,k)·k) ≤ O(n·2ⁿ) | 77 |
| 子集 | 2ⁿ | O(n)（拷贝） | O(n·2ⁿ) | 78 |
| 排列 | n! | O(n)（拷贝） | O(n·n!) | 46 |
| N皇后 | n!（剪枝后远小） | O(n)（构造棋盘） | O(n!) 最坏 | 51 |
| 数独 | 9^81 最坏 | O(1)（数组检查） | 剪枝后实际可解 | 37 |

### 6.2 推导要点（面试必答）

```text
组合/子集: 每个元素"选/不选"两种 → 决策树 2ⁿ 节点
排列: 第 1 位 n 选、第 2 位 n−1 选… → n! 叶子
空间: O(n)——递归深度 + path（不含结果集）

⚠️ 结果集空间另算:
  结果数量 × 每个结果长度（如组合 C(n,k)×k）
  面试要说清"结果集空间 vs 递归空间"两个口径
```

> 💡 **复杂度表达模板**："**时间 = 节点数 × 每节点代价——组合/子集 O(2ⁿ)、排列 O(n!)；空间 = 递归深度 O(n) + 结果集 O(结果数×长度)**。剪枝让实际远小于最坏，但理论最坏不变。"

## 7. 剪枝策略总表

### 7.1 六大剪枝

| 剪枝 | 适用 | 条件 | 效果 |
|------|------|------|------|
| 和约束 | 组合总和类 | 排序 + `sum+nums[i]>target` → break | 整层终止 |
| 剩余数量 | 定长组合 | `n−i+1 < k−path.size()` → break | 提前终止 |
| 同层去重 | 含重复元素 | `i>start && nums[i]==nums[i-1]` | 去重 |
| 排列去重 | 含重复排列 | `!used[i-1]` | 去重 |
| 约束前置 | 棋盘/数独 | 放置前查冲突数组 | 分支不生成 |
| 段合法 | 切割 | 回文/IP 校验 | 无效段跳过 |

### 7.2 剪枝正确性三问（面试自查）

```text
① 被剪的分支必然无解吗？ —— 是 → 安全剪枝
② 剪枝会丢解吗？ —— 任何有效解都不在被剪分支 → 正确
③ 剪枝位置够早吗？ —— 检查越靠前，搜索树越瘦

⚠️ 常见错误: 用"可能无解"的判据剪枝 → 丢解
  例: 组合总和"未排序就 break" → 后续可能有更小的数 → 丢解！
```

> 🎯 **核心要点**：剪枝通关四件事——**① 本质认知**（不减复杂度，减搜索树）；**② 三大剪枝**（和约束 break、剩余数量、约束前置）；**③ N皇后数字**（4.4×10⁹ → 2000，6 个数量级）；**④ 正确性三问**（必然无解/不丢解/位置够早）。**剪枝是回溯从'能跑'到'跑得动'的分水岭——'提前知道走不通'这八个字，就是全部剪枝哲学**。
