## 1. 设计题方法论：选型 + 边界

```text
数据结构设计题的三步框架:
  ① 需求拆解: 列出所有操作与复杂度要求（O(1)？）
  ② 结构选型: 数组（随机访问/环形）vs 链表（动态/指针）
     vs 双结构组合（哈希+链表、双栈）
  ③ 边界处理: 空/满/单元素/容量 1——设计题的失分重灾区

栈队列家族的设计题:
  155 最小栈（辅助栈）    → O(1) 取最小值
  232/225 互相实现        → 语义转换（LIFO ↔ FIFO）
  622 循环队列（k+1 槽）  → O(1) 环形数组
  641 循环双端队列        → 622 + 头尾双操作
  146 LRU（哈希+双向链表）→ O(1) 全操作（链表专题）

⚠️ 设计题面试要点:
  先讲选型理由（为什么这个结构），再写代码——
  "选型论述"比代码本身更值钱（senior 面试必考）
```

> 🎯 **核心认知**："**设计题 = 需求 → 选型 → 边界三步，选型论述占一半分**——155 为什么辅助栈？622 为什么 k+1 槽？146 为什么双向链表？每个'为什么'都是考点。"

## 2. 622 设计循环队列（k+1 槽，回顾与深潜）

### 2.1 完整实现（03 文件模板）

```java
/**
 * LeetCode 622. 设计循环队列
 * k+1 槽: 数组长度 k+1，head==tail 空，(tail+1)%len==head 满
 * 时间 O(1) 全操作，空间 O(k)
 */
class MyCircularQueue {
    private final int[] data;
    private final int capacity;
    private int head = 0, tail = 0;          // tail = 下一个写入位置

    public MyCircularQueue(int k) {
        data = new int[k + 1];               // ① k+1 槽
        capacity = k;
    }

    public boolean enQueue(int value) {
        if (isFull()) return false;
        data[tail] = value;
        tail = (tail + 1) % data.length;     // ② 环形
        return true;
    }

    public boolean deQueue() {
        if (isEmpty()) return false;
        head = (head + 1) % data.length;
        return true;
    }

    public int Front() { return isEmpty() ? -1 : data[head]; }
    public int Rear()  { return isEmpty() ? -1 : data[(tail - 1 + data.length) % data.length]; }
    public boolean isEmpty() { return head == tail; }
    public boolean isFull()  { return (tail + 1) % data.length == head; }
}
```

### 2.2 为什么 k+1 槽（选型论述）

```text
朴素方案: 数组 k 槽 + 额外标志位（size 或 isFull 布尔）
  → 每个操作多一次标志维护，边界易错

k+1 槽: 牺牲 1 格，让"空/满"从"状态"变成"指针关系":
  空: head == tail（指针相遇）
  满: (tail+1) % len == head（指针相邻）
  → 无标志位、无特判，环形逻辑自洽

⚠️ 面试表达: "k+1 槽用空间换掉了 isFull 的标志位分支——
   循环队列的经典实现，牺牲一格换简单与可靠。"
```

> 💡 **环形数组心法**："**环形 = 指针 + 取模**——所有下标运算 `% data.length`，头尾指针永不越界。Rear 的 `(tail−1+len) % len` 防负数是必背细节。"

## 3. 641 设计循环双端队列（头尾双操作）

### 3.1 题目与思路

**题**：622 升级——头尾都能插入/删除（deque 语义）。

**622 模板 + 头插尾删对称操作**：

```java
/**
 * LeetCode 641. 设计循环双端队列
 * 622 + 头尾双操作（insertFront/insertLast/deleteFront/deleteLast）
 * 时间 O(1) 全操作，空间 O(k)
 */
class MyCircularDeque {
    private final int[] data;
    private int head = 0, tail = 0;

    public MyCircularDeque(int k) {
        data = new int[k + 1];               // 同样 k+1 槽
    }

    public boolean insertFront(int value) {
        if (isFull()) return false;
        head = (head - 1 + data.length) % data.length;   // ① 头指针后退
        data[head] = value;
        return true;
    }

    public boolean insertLast(int value) {
        if (isFull()) return false;
        data[tail] = value;                  // ② 尾写入（同 622）
        tail = (tail + 1) % data.length;
        return true;
    }

    public boolean deleteFront() {
        if (isEmpty()) return false;
        head = (head + 1) % data.length;
        return true;
    }

    public boolean deleteLast() {
        if (isEmpty()) return false;
        tail = (tail - 1 + data.length) % data.length;   // ③ 尾指针后退
        return true;
    }

    public int getFront() { return isEmpty() ? -1 : data[head]; }
    public int getRear()  { return isEmpty() ? -1 : data[(tail - 1 + data.length) % data.length]; }
    public boolean isEmpty() { return head == tail; }
    public boolean isFull()  { return (tail + 1) % data.length == head; }
}
// ⚠️ 头插 = 头指针后退再写；尾删 = 尾指针后退——
//   环形数组的"对称性"让四个操作各两行
```

> 💡 **641 与 622 的关系**："**641 = 622 + 头插/尾删两个对称操作**——会 622 就能 5 分钟改出 641。'环形数组 + 取模'的思想在这里完整成型。"

## 4. 155 最小栈变体：双栈 vs 差值法

### 4.1 双栈版（01 文件回顾）

```java
/** 双栈: 辅助栈同步存当前最小值（push 用 <= 防重复值错位） */
class MinStack {
    private final Deque<Integer> stack = new ArrayDeque<>();
    private final Deque<Integer> minStack = new ArrayDeque<>();

    public void push(int val) {
        stack.push(val);
        int min = minStack.isEmpty() ? val : Math.min(val, minStack.peek());
        minStack.push(min);                // ⚠️ <= 或 Math.min 都保证同步
    }
    public void pop() { stack.pop(); minStack.pop(); }
    public int top() { return stack.peek(); }
    public int getMin() { return minStack.peek(); }
}
```

### 4.2 差值法（O(1) 空间进阶）

```java
/**
 * 最小栈（差值法，O(1) 额外空间）
 * 栈内存"当前值 − 当前最小值"——无需辅助栈
 * ⚠️ 面试进阶方案: 能讲清原理即可，手撕优先双栈
 */
class MinStackDiff {
    private final Deque<Long> diff = new ArrayDeque<>();   // 存差值（防溢出用 long）
    private long min;

    public void push(int val) {
        if (diff.isEmpty()) {
            diff.push(0L);
            min = val;
        } else {
            diff.push((long) val - min);   // ① 存差值
            if (val < min) min = val;      // ② 更新最小值
        }
    }
    public void pop() {
        long d = diff.pop();
        if (d < 0) min = min - d;          // ③ 弹出的是最小值 → 还原旧 min
    }
    public int top() {
        long d = diff.peek();
        return (int) (d < 0 ? min : min + d);   // ④ 由差值还原原值
    }
    public int getMin() { return (int) min; }
}
// ⚠️ 原理: 差值 d = val − min。若 d < 0 → val 就是新的 min
//   还原: val = d ≥ 0 ? min + d : min
```

> 🎯 **双方案对比**："**双栈简单可靠（工程首选）、差值法 O(1) 空间（面试谈资）**——'两个方案都能给 + 讲清取舍'是 155 的完整答案。"

## 5. 232/225 互相实现（回顾与摊还论证）

### 5.1 摊还论证（232 双栈队列）

```text
为什么"stOut 空才倒"是摊还 O(1):
  每个元素的生命周期: 入 stIn 1 次（O(1)）→ 倒 stOut 1 次（O(1)）
  → 总操作 2 次摊到它的 1 次 pop = O(1) 摊还

对比错误写法（每次 pop 都倒）:
  最坏 O(n) 每次 → 队列操作全退化

⚠️ 面试表达: "摊还 O(1)——每个元素恰好被倒一次，
   就像银行每次取款平摊的固定成本。"
```

### 5.2 四种"互相实现"复杂度对照

| 实现 | push | pop/peek | 核心思路 |
|------|:---:|:---:|------|
| 232 双栈队列 | O(1) | 摊还 O(1) | 入出分离 + 空才倒 |
| 225 单队列栈 | O(n) | O(1) | 旋转（前 n−1 重排） |
| 225 双队列栈 | O(1) | O(n) | 主从队列切换 |
| 用栈实现 min | O(1) | O(1) | 辅助栈同步 |

> 💡 **设计取舍**："**'互相实现'的核心是选'哪个操作 O(1)'**——232 让出队摊还 O(1)（更常用），225 单队列让出栈 O(1) 入栈 O(n)。没有免费午餐，只有权衡。"

## 6. 与 146 LRU 联动：栈队列在系统设计中的位置

### 6.1 栈队列是系统设计的"原语"

```text
栈（LIFO）: 函数调用栈、Undo/Redo、浏览器后退、括号校验器
队列（FIFO）: 消息队列、任务调度、BFS、数据缓冲
双端队列: 滑动窗口、双端任务（641/239）
循环队列: 环形缓冲区（生产者-消费者、日志缓冲）

与 146 LRU 的关系:
  LRU = 哈希（查找）+ 双向链表（淘汰）——队列的"变体"
  → 栈队列专题是"受限数据结构"，LRU 是"组合结构"
  → 面试路线: 622 循环队列 → 641 双端 → 146 LRU
```

### 6.2 设计题面试路线图

```text
入门: 155 最小栈（辅助栈思想）
基础: 622 循环队列（环形数组 + k+1 槽）
进阶: 641 双端队列（头尾对称）
组合: 232/225 互相实现（语义转换 + 摊还）
系统: 146 LRU（哈希 + 双向链表，链表专题 05 文件）
     232 → 实现"线程安全队列"（加锁版本——并发专题）

⚠️ 面试表达: "设计题考的是结构选型与边界意识——
   622 的 k+1 槽、155 的辅助栈、146 的双向链表，

```

## 7. 设计题易错点

| # | 易错点 | 正确写法 | 后果 |
|:---:|------|------|------|
| 1 | 622 忘取模 | 所有指针 `% len` | 越界 |
| 2 | Rear 负下标 | `(tail−1+len) % len` | 负数下标 |
| 3 | 641 头插顺序反 | 先退指针再写值 | 覆盖/错位 |
| 4 | 155 差值法溢出 | 用 long 存差值 | int 溢出 |
| 5 | 232 每次 pop 倒数据 | stOut 空才倒 | 摊还失效 |
| 6 | 225 旋转次数错 | `size()−1` 次 | 栈序错 |
| 7 | 设计题先写码后讲选型 | 先选型论述再写码 | 面试印象分流失 |

> 🎯 **核心要点**：设计题通关四件事——**① 三步框架**（需求 → 选型 → 边界）；**② 622/641 环形模板烂熟**（k+1 槽 + 取模 + 对称操作）；**③ 155 双方案**（双栈工程版 + 差值法谈资）；**④ 摊还论证**（232 的"每个元素倒一次"）。**设计题是'选型 + 边界'的考试——把'为什么'讲成一段论述，就是 senior 级的表现**。
