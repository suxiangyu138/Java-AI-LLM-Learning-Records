## 1. 什么是动态规划

动态规划（Dynamic Programming, DP）是一种通过将复杂问题**分解为重叠的子问题**，并**缓存子问题的解**来避免重复计算的算法思想。它最初由 Richard Bellman 在 1950 年代提出，名字中的"Dynamic Programming"更多是出于当时的政治考量（Bellman 在 RAND 公司工作，当时国防部长不喜欢"研究"这个词），而非算法本身的特点。

> 💡 **一句话核心**：DP = 记忆化搜索 → 表格递推，用空间换时间，将指数级复杂度降至多项式级。

### DP 不是什么

| 容易混淆 | 区别 |
|------|------|
| **分治法** | 分治法子问题不重叠（归并排序），DP 子问题重叠 |
| **贪心法** | 贪心每步选局部最优 → 全局最优，DP 通过状态转移保证全局最优 |
| **回溯法** | 回溯穷举所有可能，DP 利用重叠子问题剪枝避免重复计算 |

## 2. DP 三大核心性质

### 2.1 最优子结构（Optimal Substructure）

> 一个问题的最优解包含其子问题的最优解。

**判定标准**：能否通过子问题的最优解推导出原问题的最优解？

```
反例（无最优子结构）：
图中最长简单路径（不重复节点）没有最优子结构。
从 A 到 D 的最长路径 ≠ 从 A 到 C 的最长路径 + C 到 D 的边。
因为从 A 到 C 的最长路径可能用到了 D 路径需要的节点。

正例（有最优子结构）：
最短路径有最优子结构：
从 A 到 D 的最短路径 = 从 A 到 C 的最短路径 + C 到 D。
```

### 2.2 重叠子问题（Overlapping Subproblems）

> 递归树中存在大量相同子问题，DP 通过缓存避免重复计算。

```java
// Fibonacci 递归树（大量重叠）
// fib(5)
// ├── fib(4)
// │   ├── fib(3)           <── 第 1 次
// │   │   ├── fib(2)       <── 第 1 次
// │   │   └── fib(1)
// │   └── fib(2)           <── 第 2 次！重复计算
// └── fib(3)               <── 第 2 次！重复计算

// 指数爆炸：fib(n) 不含记忆化需要 O(2ⁿ)
// DP 优化后：O(n)
```

### 2.3 无后效性（No Aftereffect）

> 状态一旦确定，后续决策只依赖当前状态值，不依赖到达该状态的具体路径。

```
正例：在背包问题中，dp[i][w] 只记录"前 i 个物品、容量 w"的最优值，
      不管这些物品是按什么顺序放进去的。

反例：带时间窗的路径规划中，当前车站的状态还需要考虑"几点到的"，
      因为影响后续能否赶上下一班车 → 需要增加时间维度。
```

> ⚠️ **关键**：无后效性是设计 DP 状态的约束条件。如果发现状态转移需要考虑"历史路径"，说明维度不够，需要扩展状态。

## 3. 两种实现方式：记忆化搜索 vs 表格递推

### 3.1 自顶向下：记忆化搜索（Memoization）

**本质**：在 DFS/递归的基础上加缓存，先查缓存，没有再计算并存入。

```java
// 爬楼梯：记忆化搜索
public int climbStairs(int n) {
    int[] memo = new int[n + 1];          // 备忘录
    Arrays.fill(memo, -1);
    return dfs(n, memo);
}

private int dfs(int n, int[] memo) {
    if (n <= 2) return n;                 // Base Case
    if (memo[n] != -1) return memo[n];    // 查缓存
    memo[n] = dfs(n - 1, memo) + dfs(n - 2, memo); // 计算并存储
    return memo[n];
}
```

**特点**：
- ✅ 思维直观，直接翻译递归思路
- ✅ 只计算需要的状态（按需计算，非所有子问题都要）
- ❌ 递归栈溢出风险（n 很大时）
- ❌ 函数调用开销

### 3.2 自底向上：表格递推（Tabulation）

**本质**：从小到大，循环填表。先算 base case，再逐步推导到最终答案。

```java
// 爬楼梯：表格递推
public int climbStairs(int n) {
    if (n <= 2) return n;
    int[] dp = new int[n + 1];
    dp[1] = 1;                             // Base Case
    dp[2] = 2;
    for (int i = 3; i <= n; i++) {
        dp[i] = dp[i - 1] + dp[i - 2];     // 状态转移
    }
    return dp[n];
}
```

**特点**：
- ✅ 无递归开销，性能更优
- ✅ 容易做空间优化（滚动数组）
- ❌ 需要确定遍历顺序
- ❌ 可能计算了不需要的状态

### 3.3 选择策略

| 场景 | 推荐方式 |
|------|------|
| 初学者、快速验证思路 | 记忆化搜索（写出递归 + 加缓存） |
| 面试、生产代码 | 表格递推（性能更好，展示优化能力） |
| 状态空间稀疏、维度高 | 记忆化搜索（只算需要的状态） |
| 需要依赖多维历史状态 | 表格递推（递归栈不好控） |
| 树形 DP（自底向上聚合） | DFS 后序遍历（天然递归） |

## 4. 五步解题法（通用框架）

> 🎯 **这是本知识体系最核心的解题方法论，每道 DP 题都用这五步。**

```
Step 1: 识别状态 —— 什么在子问题间变化？
Step 2: 定义 dp —— 用一句话描述 dp[...] 的含义
Step 3: 写转移方程 —— dp[当前] = f(dp[历史])
Step 4: 确定 Base Case —— 最小子问题的答案
Step 5: 确定计算顺序与输出 —— 遍历方向 + 最终答案在哪里
```

### 示例：用五步法解「最大子序和」(LeetCode 53)

```
Step 1: 识别状态
    → 变化的是「以哪个位置结尾」→ 一维状态 i

Step 2: 定义 dp
    → dp[i] 表示「以 nums[i] 结尾的最大子序和」

Step 3: 转移方程
    → dp[i] = max(nums[i], dp[i-1] + nums[i])
    → 要么另起炉灶(只取自己)，要么接入前面的子数组

Step 4: Base Case
    → dp[0] = nums[0]

Step 5: 计算顺序与输出
    → i = 1 → n-1 正序遍历
    → 答案 = max(dp[0], dp[1], ..., dp[n-1])
```

```java
public int maxSubArray(int[] nums) {
    int[] dp = new int[nums.length];
    dp[0] = nums[0];
    int max = dp[0];
    for (int i = 1; i < nums.length; i++) {
        dp[i] = Math.max(nums[i], dp[i - 1] + nums[i]);
        max = Math.max(max, dp[i]);
    }
    return max;
}

// 空间优化：只保留 dp[i-1]
public int maxSubArray_Optimized(int[] nums) {
    int dp = nums[0], max = dp;
    for (int i = 1; i < nums.length; i++) {
        dp = Math.max(nums[i], dp + nums[i]);
        max = Math.max(max, dp);
    }
    return max;
}
```

## 5. 状态定义方法论

### 5.1 维度选择指南

| 问题特征 | 推荐维度 | 例子 |
|------|:---:|------|
| 单序列，决策只依赖前 1-2 位置 | 1D `dp[i]` | 爬楼梯、打家劫舍 |
| 单序列，子问题依赖任意前驱 | 1D `dp[i]`（内层遍历 j） | LIS |
| 两个序列的对应关系 | 2D `dp[i][j]` | LCS、编辑距离 |
| 序列 + 约束条件（容量、次数）| 2D `dp[i][w]` | 背包问题 |
| 区间 `[i,j]` | 2D `dp[i][j]` | 回文子串、石子合并 |
| 树节点 + 选/不选 | 2D `dp[node][0/1]` | 打家劫舍 III |
| 集合的子集 | 1D `dp[mask]`（位掩码）| TSP 旅行商 |

### 5.2 常见状态定义模式

```java
// 模式 A：以 i 结尾（最常见的 1D 模式）
dp[i] = 以 arr[i] 结尾的某个最优值  // LIS, 最大子序和

// 模式 B：考虑前 i 个元素
dp[i] = 考虑 arr[0..i-1] 的某个最优值  // 背包, 打家劫舍

// 模式 C：双序列对应
dp[i][j] = s1[0..i-1] 与 s2[0..j-1] 的关系  // LCS, 编辑距离

// 模式 D：区间
dp[i][j] = arr[i..j] 上的最优值  // 区间 DP

// 模式 E：选/不选（状态机）
dp[i][0/1] = 第 i 个位置选/不选的某个值  // 打家劫舍, 股票
```

## 6. 空间优化：滚动数组原理

### 6.1 为什么能降维？

当 `dp[i]` **只依赖** `dp[i-1]` 和 `dp[i-2]` 时，更早的状态（`dp[i-3]`...）就是垃圾——只需要维护一个滑动窗口。

```java
// 通用滚动数组模板：2D → 1D（背包问题）
// 原始 2D: dp[i][j] = max(dp[i-1][j], dp[i-1][j-w] + v)
// 优化 1D: dp[j] = max(dp[j], dp[j-w] + v)  逆序遍历 j ！
for (int i = 0; i < n; i++) {
    for (int j = target; j >= weight[i]; j--) {  // ⚠️ 逆序！
        dp[j] = Math.max(dp[j], dp[j - weight[i]] + value[i]);
    }
}
```

### 6.2 逆序 vs 正序的本质

```
逆序遍历保证：dp[j - weight[i]] 来自「上一轮」i-1 的状态
正序遍历导致：dp[j - weight[i]] 可能来自「本轮」i 的状态 → 物品被重复使用

记忆口诀：
  0/1 背包 → 逆序（每个物品只能选一次）
  完全背包 → 正序（每个物品可以无限选）
```

### 6.3 滚动数组的三种写法

```java
// 写法 1：交替行（二维用两行）
int[][] dp = new int[2][n+1];
dp[0][...] = base;
for (int i = 1; i <= m; i++) {
    for (int j = 0; j <= n; j++) {
        dp[i%2][j] = f(dp[(i-1)%2][j], ...);
    }
}

// 写法 2：双变量（一维转两个变量）
int prev = 0, curr = 1;
for (...) {
    int next = f(prev, curr);
    prev = curr;
    curr = next;
}

// 写法 3：逆序覆盖（二维转一维，最常用）
int[] dp = new int[target+1];
for (int item : items) {
    for (int j = target; j >= weight; j--) {
        dp[j] = max(dp[j], dp[j-weight] + value);
    }
}
```

## 7. 入门实战：从 Fibonacci 到打家劫舍

### 7.1 斐波那契数列 (509)

```java
// 四种实现方式对比
public class Fibonacci {
    // ① 朴素递归 O(2ⁿ)
    public int fib_recursive(int n) {
        if (n <= 1) return n;
        return fib_recursive(n - 1) + fib_recursive(n - 2);
    }

    // ② 记忆化搜索 O(n) / O(n)
    public int fib_memo(int n) {
        int[] memo = new int[n + 1];
        return dfs(n, memo);
    }
    private int dfs(int n, int[] memo) {
        if (n <= 1) return n;
        if (memo[n] != 0) return memo[n];
        return memo[n] = dfs(n - 1, memo) + dfs(n - 2, memo);
    }

    // ③ 表格递推 O(n) / O(n)
    public int fib_dp(int n) {
        if (n <= 1) return n;
        int[] dp = new int[n + 1];
        dp[0] = 0; dp[1] = 1;
        for (int i = 2; i <= n; i++)
            dp[i] = dp[i - 1] + dp[i - 2];
        return dp[n];
    }

    // ④ 空间优化 O(n) / O(1) ★ 面试最优
    public int fib_optimized(int n) {
        if (n <= 1) return n;
        int prev = 0, curr = 1;
        for (int i = 2; i <= n; i++) {
            int next = prev + curr;
            prev = curr;
            curr = next;
        }
        return curr;
    }
}
```

### 7.2 打家劫舍 (198) — 五步法完整演示

```
Step 1: 识别状态 → 遍历到第 i 个房子
Step 2: 定义 dp → dp[i] = 偷前 i 个房子的最高金额
Step 3: 转移方程 → dp[i] = max(dp[i-1], dp[i-2] + nums[i])
         解释：第 i 个房子：不偷 → dp[i-1]；偷 → dp[i-2] + nums[i]
Step 4: Base Case → dp[0] = nums[0]; dp[1] = max(nums[0], nums[1])
Step 5: 计算顺序 → i = 2 → n-1，答案 = dp[n-1]
```

```java
// 空间优化版（面试推荐）
public int rob(int[] nums) {
    if (nums.length == 1) return nums[0];
    int prev2 = nums[0];
    int prev1 = Math.max(nums[0], nums[1]);
    for (int i = 2; i < nums.length; i++) {
        int curr = Math.max(prev1, prev2 + nums[i]);
        prev2 = prev1;
        prev1 = curr;
    }
    return prev1;
}
```

### 7.3 DP 新手常见错误

| 错误类型 | 表现 | 修正 |
|------|------|------|
| **状态定义不清晰** | dp[i][j] 含义模糊，转移方程写不出 | 用一句话精确描述 dp 含义，写在代码注释里 |
| **数组越界** | `dp[i-2]` 当 i=1 时越界 | 提前处理 n=0,1 的边界情况 |
| **Base Case 遗漏** | 忘记初始化某些基础状态 | 手动模拟 n=1,2,3 验证 |
| **遍历方向错误** | 背包问题正序遍历导致错误 | 画表模拟一轮，确认依赖关系 |
| **空间优化过早** | 一开始就想用 O(1) 空间 | 建议先写 2D 版本确保障正确，再逐步压缩 |
| **把贪心当 DP** | 每步选最大，发现不一定全局最优 | 反证法：举反例打破贪心策略 |

> 🎯 **核心要点**：DP 的本质是用**有组织的填表**替代**无脑的穷举**。五步解题法是我们的导航——拿到题先写五步（纸上或脑内），再写代码。坚持 10 题后，你会发现自己已经内化了这套方法论。
