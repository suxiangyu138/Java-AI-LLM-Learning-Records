## 1. 核心概念

### 1.1 递归的三要素

> 递归：函数调用自身。正确递归需要三要素——**基线条件、递推关系、收敛性**。

```
① 基线条件（Base Case）：最小规模直接返回
   ⚠️ 缺失 → 无限递归 → 栈溢出

② 递推关系：把问题规模缩小后调用自身

③ 收敛性：每次调用规模必然减小 → 最终到达基线

例（阶乘）：
  factorial(n) = 1                    （n=0 基线）
  factorial(n) = n × factorial(n-1)   （递推，规模减 1）

⚠️ 面试第一句："递归三要素：基线、递推、收敛"
```

### 1.2 识别信号

```
"结构自相似（树/链表）" → 递归
"问题可缩小为同类子问题" → 递归

⚠️ 树/链表天然适合递归（子树/子链也是同类结构）
   数组问题通常迭代更自然（但也可递归）
```

### 1.3 递归与相关概念

```
递归：机制（函数调用自身）
回溯：递归 + 撤销（枚举方案）
DFS：递归遍历策略（深度优先）
分治：递归 + 拆分 + 合并（思想）
记忆化：递归 + 缓存（去重）

关系："回溯/DFS/分治/记忆化都建立在递归之上"
  理解递归 = 理解这些算法的一半
```

## 2. 完整代码模板

### 2.1 递归通用模板

```java
/**
 * 递归通用模板
 */
public ReturnType recurse(参数) {
    // ① 基线条件（先写！）
    if (最小规模) {
        return 直接结果;
    }

    // ② 递推（缩小规模调用）
    ReturnType sub = recurse(更小的参数);

    // ③ 合并/处理
    return 处理(sub, 当前);
}
// ⚠️ 写法顺序：基线最先（先判退出）
//   返回值语义要明确（返回什么给上一层）
```

### 2.2 206. 反转链表（递归版）

```java
/**
 * LeetCode 206. 反转链表（递归版）
 * 基线：空/单节点直接返回
 * 递推：反转剩余部分，回溯时反转指针
 */
public ListNode reverseList(ListNode head) {
    if (head == null || head.next == null) {
        return head;                    // 基线：空/单节点
    }

    ListNode newHead = reverseList(head.next);  // 递归反转剩余

    head.next.next = head;              // ⚠️ 后继指向自己（反转）
    head.next = null;                   // 断开原前向
    return newHead;                     // 返回新头
}
// 推演 1→2→3：
//   reverse(3) → 返回 3（基线）
//   reverse(2)：3.next=2, 2.next=null → 3→2
//   reverse(1)：2.next=1, 1.next=null → 3→2→1 ✓
// 面试对比：迭代三指针 O(1) 空间更优；递归展示思维
```

### 2.3 树遍历（递归三模板）

```java
/**
 * 树遍历三模板（前/中/后序）
 * ⚠️ 只移动"处理"位置
 */
void preorder(TreeNode node) {          // 前序：根左右
    if (node == null) return;
    处理(node);
    preorder(node.left);
    preorder(node.right);
}

void inorder(TreeNode node) {           // 中序：左根右
    if (node == null) return;
    inorder(node.left);
    处理(node);
    inorder(node.right);
}

void postorder(TreeNode node) {         // 后序：左右根
    if (node == null) return;
    postorder(node.left);
    postorder(node.right);
    处理(node);
}
// 记忆："前中后指根的位置"
// 应用：前序传参（路径）、后序聚合（高度）
```

## 3. 递归的执行模型

### 3.1 函数调用栈

```
递归 = 函数调用栈：
  调用 → 压栈（保存现场）
  返回 → 弹栈（恢复现场）

fib(4) 的调用栈：
  fib(4) → fib(3) → fib(2) → fib(1)（触底）
  → 返回 1 → fib(0) → 返回 1 → 返回 2 ...

⚠️ 递归深度 = 栈深度
  深度 10⁵ 可能 StackOverflow
  树退化为链表时递归深度 = n（危险！）
```

### 3.2 栈溢出与应对

```
递归深度分析：
  树高 h → 递归深度 h
  链表长度 n → 深度 n（危险）
  网格路径 m×n → 最坏深度 m×n

应对方案：
  ① 转迭代（显式栈用堆内存）
  ② 尾递归优化（Java 不支持自动优化）
  ③ 增大栈空间（-Xss，工程手段）

⚠️ 面试表达：
"递归深度 O(n) 可能栈溢出，
 我可以转迭代实现（显式栈）。
 树场景深度 O(h) 通常安全。"
```

### 3.3 三种递归形态

```
① 直接递归：函数调自己（阶乘/斐波那契）
② 尾递归：递归调用是最后一步（可优化为迭代）
   例：factorial(n, acc) → factorial(n-1, n*acc)
   ⚠️ Java 不会自动优化尾递归（函数式语言会）
③ 间接递归：A 调 B，B 调 A（少用）

⚠️ 尾递归的面试价值：
  "这题可以写成尾递归（递归在最后一步），
   函数式语言会优化为迭代；Java 需要手动转。"
```

## 4. 递归转迭代

### 4.1 两种转换方法

```
方法一：显式栈模拟（通用）
  Deque 存"待处理状态"
  循环替代递归调用

方法二：尾递归直接变循环（简单）
  递归在最后一步 → 参数更新 + 循环

⚠️ 显式栈的难点：
  状态管理（压栈什么、弹栈恢复什么）
  前序/后序的处理时机不同
```

### 4.2 树中序遍历迭代（经典）

```java
/**
 * 中序迭代：左探-回溯-右转
 * ⚠️ 面试最高频的递归转迭代考点
 */
public List<Integer> inorderIterative(TreeNode root) {
    List<Integer> result = new ArrayList<>();
    Deque<TreeNode> stack = new ArrayDeque<>();
    TreeNode cur = root;

    while (cur != null || !stack.isEmpty()) {
        while (cur != null) {           // ① 左探：一路向左压栈
            stack.push(cur);
            cur = cur.left;
        }
        cur = stack.pop();              // ② 回溯：弹出
        result.add(cur.val);            //     中序处理
        cur = cur.right;                // ③ 右转
    }
    return result;
}
// 递归版 3 行 → 迭代版 12 行
// 记忆："左探-回溯-右转"三步骤
```

### 4.3 递归 vs 迭代选型

```
递归：简洁直观、天然匹配树/链表
迭代：无栈溢出、性能略优（无调用开销）

面试策略：
  先写递归（快速、清晰）
  被追问"栈溢出怎么办" → 转迭代
  ⚠️ 中序迭代是必背（高频考点）

⚠️ 迭代的性能优势通常可忽略
  面试主要考察"能否转换"的能力
```

## 6. 面试要点与追问

### 6.1 面试话术模板

```
"递归三要素：基线条件（空/单节点直接返回）、
 递推关系（缩小规模）、收敛性（规模必减）。
 这题基线是【...】，递推是【...】，
 递归深度 O(h)（h 为树高/链长）。
 如果深度过大，我可以转显式栈迭代。"
```

### 6.2 高频追问 TOP 8

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | 递归三要素？ | 基线、递推、收敛（缺一不可） |
| 2 | 栈溢出怎么处理？ | 分析深度 → 显式栈迭代/尾递归 |
| 3 | 递归 vs 迭代？ | 递归简洁但 O(n) 栈；迭代 O(1) 无风险 |
| 4 | 尾递归是什么？ | 递归在最后一步；Java 不自动优化 |
| 5 | 与回溯/DFS 关系？ | 递归是机制，回溯/DFS 是建立其上的思想 |
| 6 | 中序迭代怎么做？ | 左探-回溯-右转（显式栈） |
| 7 | 什么时候用递归？ | 树/链表等自相似结构 |
| 8 | 调试递归？ | 小规模手推调用栈 + 明确返回值语义 |

### 6.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| 忘基线条件 | 栈溢出 | 基线最先写 |
| 规模不收敛 | 无限递归 | 参数必减 |
| 返回值语义不清 | 结果错 | 明确返回给谁 |
| 基线条件错 | 边界错误 | 空/单元素验证 |
| 深度过大硬递归 | 栈溢出 | 主动转迭代 |

> 🎯 **核心要点**：递归 = **基线 + 递推 + 收敛**三要素。识别信号："结构自相似（树/链表）、问题可缩小"。先写基线的习惯、栈溢出的应对（转迭代）、与回溯/DFS 的关系是面试三大必答点。中序迭代（左探-回溯-右转）是递归转迭代的必背考点。
