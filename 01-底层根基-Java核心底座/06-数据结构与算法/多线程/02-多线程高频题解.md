## 1. 1114. 按序打印（三解法对比）

### 1.1 题目与思路

```
三个方法分别被不同线程调用，保证执行顺序 first → second → third
（synchronized 标志位版见 00 模板，此处给另外两种解法）

解法对比：
  ① synchronized + volatile 标志位：最基础（00 已写）
  ② CountDownLatch：语义直观（放行式）
  ③ Semaphore：交接式（线程间传递许可）
```

### 1.2 CountDownLatch 版

```java
/**
 * LeetCode 1114. 按序打印 —— CountDownLatch 版
 * ⚠️ 语义：second 等 first 放行，third 等 first+second 放行
 */
class Foo2 {
    private final CountDownLatch latch12 = new CountDownLatch(1);  // first→second
    private final CountDownLatch latch23 = new CountDownLatch(1);  // second→third

    public void first(Runnable printFirst) {
        printFirst.run();
        latch12.countDown();              // ⚠️ first 完成 → 放行 second
    }

    public void second(Runnable printSecond) {
        try {
            latch12.await();              // 等 first（无竞态，不用 while）
            printSecond.run();
            latch23.countDown();
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }

    public void third(Runnable printThird) {
        try {
            latch23.await();              // 等 second
            printThird.run();
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }
}
// ⚠️ 为什么这里不用 while？—— CountDownLatch 是一次性倒数，
//   不存在"虚假唤醒后条件仍不满足"（放行即终态）
```

### 1.3 Semaphore 版 + 无锁自旋版

```java
/** Semaphore 版：交接语义 */
class Foo3 {
    private final Semaphore s12 = new Semaphore(0);
    private final Semaphore s23 = new Semaphore(0);

    public void first(Runnable printFirst) {
        printFirst.run();
        s12.release();                    // 给 second 许可
    }
    public void second(Runnable printSecond) {
        try { s12.acquire(); printSecond.run(); s23.release(); }
        catch (InterruptedException e) { Thread.currentThread().interrupt(); }
    }
    public void third(Runnable printThird) {
        try { s23.acquire(); printThird.run(); }
        catch (InterruptedException e) { Thread.currentThread().interrupt(); }
    }
}

/** 无锁自旋版：volatile + 忙等（展示极端写法，不推荐生产） */
class Foo4 {
    private volatile int stage = 1;
    public void first(Runnable p) { p.run(); stage = 2; }
    public void second(Runnable p) {
        while (stage != 2) { Thread.onSpinWait(); }   // ⚠️ 忙等烧 CPU
        p.run(); stage = 3;
    }
    public void third(Runnable p) {
        while (stage != 3) { Thread.onSpinWait(); }
        p.run();
    }
}
```

| 解法 | 优点 | 缺点 | 推荐 |
|------|------|------|:---:|
| synchronized 标志位 | 最基础、通用 | 代码略长 | ✅ 首选 |
| CountDownLatch | 语义直观、无虚假唤醒问题 | 只能放行一次 | ✅ |
| Semaphore | 交接式、可循环 | 需注意初始许可 | ✅ |
| volatile 自旋 | 代码最短 | 忙等烧 CPU | ❌ 面试可提 |

## 2. 1115. 交替打印 FooBar（双解法）

### 2.1 题目与思路

```
foo 与 bar 线程交替打印 n 轮：foo bar foo bar ...
Semaphore 版见 00 模板（两信号量互相交接）
此处补充 Lock + Condition 版（多条件精确唤醒）
⚠️ 面试对比价值：同一题展示"信号量 vs 条件变量"两种思想
```

### 2.2 Lock + Condition 版

```java
/**
 * LeetCode 1115. 交替打印 FooBar —— Lock + Condition 版
 * ⚠️ 两个 Condition 分别等待"foo 轮次"与"bar 轮次"
 */
class FooBar2 {
    private final int n;
    private final Lock lock = new ReentrantLock();
    private final Condition fooCond = lock.newCondition();
    private final Condition barCond = lock.newCondition();
    private boolean fooTurn = true;               // 状态标志

    public FooBar2(int n) { this.n = n; }

    public void foo(Runnable printFoo) throws InterruptedException {
        for (int i = 0; i < n; i++) {
            lock.lock();
            try {
                while (!fooTurn) fooCond.await(); // 等 foo 轮次（⚠️ while）
                printFoo.run();
                fooTurn = false;                  // 先改状态
                barCond.signal();                 // 再精确唤醒 bar
            } finally {
                lock.unlock();                    // ⚠️ finally 释放
            }
        }
    }

    public void bar(Runnable printBar) throws InterruptedException {
        for (int i = 0; i < n; i++) {
            lock.lock();
            try {
                while (fooTurn) barCond.await();  // 等 bar 轮次
                printBar.run();
                fooTurn = true;
                fooCond.signal();
            } finally {
                lock.unlock();
            }
        }
    }
}
// ⚠️ 三要点：while 等待（防虚假唤醒）、先改状态后 signal（防丢失唤醒）、
//           finally 释放（防异常死锁）
```

> 🎯 **两种思路对比**：Semaphore 是"许可交接"（谁来谁拿许可）；Condition 是"条件等待"（等轮次 + 精确唤醒）。**交替打印用 Semaphore 更简洁，多角色编排用 Condition 更灵活**。

## 3. 1116. 打印零与奇偶数

### 3.1 题目与思路

```
三个线程：zero 打印 0，even 打印偶数，odd 打印奇数
输出：0102030405...（0 与每个数交替，数按奇偶分发）

设计：3 个信号量
  zero 每轮给"奇"或"偶"一个许可
  odd/even 打印完还给 zero 许可（循环交接）
```

### 3.2 完整代码

```java
/**
 * LeetCode 1116. 打印零与奇偶数
 * ⚠️ 核心：zero 决定下一个交给奇还是偶（按 i 的奇偶）
 */
class ZeroEvenOdd {
    private final int n;
    private final Semaphore zeroSem = new Semaphore(1);   // zero 先开始
    private final Semaphore evenSem = new Semaphore(0);
    private final Semaphore oddSem  = new Semaphore(0);

    public ZeroEvenOdd(int n) { this.n = n; }

    public void zero(IntConsumer printNumber) throws InterruptedException {
        for (int i = 1; i <= n; i++) {
            zeroSem.acquire();                // 拿 zero 许可
            printNumber.accept(0);            // 打印 0
            if ((i & 1) == 1) oddSem.release();     // 奇数轮 → 放行 odd
            else              evenSem.release();    // 偶数轮 → 放行 even
        }
    }

    public void even(IntConsumer printNumber) throws InterruptedException {
        for (int i = 2; i <= n; i += 2) {
            evenSem.acquire();                // 等 zero 放行
            printNumber.accept(i);
            zeroSem.release();                // 还给 zero（下一轮）
        }
    }

    public void odd(IntConsumer printNumber) throws InterruptedException {
        for (int i = 1; i <= n; i += 2) {
            oddSem.acquire();
            printNumber.accept(i);
            zeroSem.release();
        }
    }
}
// 推演 n=3：0→1(odd)→0→3(odd)→0→2(even) ✓ 输出 010203
// ⚠️ 模式：一个"分发者"（zero）+ 两个"消费者"（奇/偶），
//   分发者按规则把许可发给对应消费者 —— 多信号量交接的通用模式
```

## 4. 1117. H2O 生成

### 4.1 题目与思路

```
两种线程：hydrogen（H）与 oxygen（O），组合出 H2O 分子
  2 个 H + 1 个 O = 1 个 H2O
约束：每来 1 个 O 要等 2 个 H 到齐（反之每 2 个 H 要等 1 个 O）

设计：
  ① 信号量：氢/氧许可（2 个 H 许可 + 1 个 O 许可交替发放）
  ② 加锁计数：H 计数到 2 才放行 O
⚠️ 关键：输出顺序不要求（只要原子 H2O 内成分正确）
```

### 4.2 完整代码（信号量版）

```java
/**
 * LeetCode 1117. H2O 生成 —— 信号量版
 */
class H2O {
    private final Semaphore hSem = new Semaphore(2);   // 最多 2 个 H 同时
    private final Semaphore oSem = new Semaphore(1);   // 最多 1 个 O 同时
    private final Semaphore lock = new Semaphore(1);   // 互斥：组合计数
    private int hCount = 0;                            // 已到 H 数

    public H2O() {}

    public void hydrogen(Runnable releaseHydrogen) throws InterruptedException {
        hSem.acquire();                    // 拿 H 许可（最多 2 并发）
        lock.acquire();                    // 互斥修改计数
        hCount++;
        if (hCount == 2) {                 // ⚠️ H 凑齐 2 个 → 放行 1 个 O
            oSem.release();
            hCount = 0;                    // 重置计数
        }
        lock.release();
        releaseHydrogen.run();
    }

    public void oxygen(Runnable releaseOxygen) throws InterruptedException {
        oSem.acquire();                    // 等 H 凑齐 2 个放行
        releaseOxygen.run();
        hSem.release(2);                   // ⚠️ 一个 O 消耗 2 个 H 许可
    }
}
// ⚠️ 思路拆解：
//   H 线程：互斥计数，满 2 个就"解锁"一个 O（许可+1）
//   O 线程：等许可 → 打印 → 归还 2 个 H 许可（下个分子）
// 变形（锁 + Condition 版）：同样计数逻辑，用 lock + notifyAll
```

> 🎯 **H2O 模式**：**"计数凑组 + 凑满放行"**——多个生产者按比例凑成一个"组"，凑满后统一放行消费方。生产环境映射：批量提交、按比例配额。

## 5. 1195. 交替打印字符串

### 5.1 题目与思路

```
4 个线程：fizz（3 倍数）、buzz（5 倍数）、fizzbuzz（15 倍数）、number（其他）
按 1..n 顺序输出，每个数只由一个线程处理
⚠️ 难点：4 个消费者如何"按序领号"（互斥 + 按号分发）
（信号量骨架见 00，此处给"原子计数器 + 锁"的完整实现）
```

### 5.2 完整代码（原子计数 + 信号量分发）

```java
/**
 * LeetCode 1195. 交替打印字符串
 * ⚠️ 核心：一个原子计数器"发号"，每个线程按规则领号；
 *   主发放者（number 线程）把号交给对应线程
 */
class FizzBuzz {
    private final int n;
    private final Semaphore numSem = new Semaphore(1);    // 发号者
    private final Semaphore fizzSem = new Semaphore(0);
    private final Semaphore buzzSem = new Semaphore(0);
    private final Semaphore fbSem = new Semaphore(0);

    public FizzBuzz(int n) { this.n = n; }

    public void fizz(Runnable printFizz) throws InterruptedException {  // 3 倍数
        for (int i = 3; i <= n; i += 3) {
            if (i % 15 != 0) {                  // 排除 15 倍数
                fizzSem.acquire();
                printFizz.run();
            }
        }
    }

    public void buzz(Runnable printBuzz) throws InterruptedException {  // 5 倍数
        for (int i = 5; i <= n; i += 5) {
            if (i % 15 != 0) {
                buzzSem.acquire();
                printBuzz.run();
            }
        }
    }

    public void fizzbuzz(Runnable printFizzBuzz) throws InterruptedException { // 15 倍数
        for (int i = 15; i <= n; i += 15) {
            fbSem.acquire();
            printFizzBuzz.run();
        }
    }

    public void number(IntConsumer printNumber) throws InterruptedException {  // 发号者
        for (int i = 1; i <= n; i++) {
            numSem.acquire();                   // ⚠️ 每轮只放一个号
            if (i % 15 == 0)      fbSem.release();
            else if (i % 3 == 0)  fizzSem.release();
            else if (i % 5 == 0)  buzzSem.release();
            else { printNumber.accept(i); numSem.release(); }  // 自己消费
        }
    }
}
// 流程：number 领号 → 按规则分发许可 → 对应线程打印 → 下一轮 number 再领
// ⚠️ 注意：fizz/buzz 循环跳过 15 倍数（避免重复领取），
//   fizzbuzz 只领 15 倍数 —— 每个数恰好一个线程处理
```

## 6. 1226. 哲学家进餐（死锁避免）

### 6.1 题目与思路

```
5 个哲学家围桌，5 把叉子，每人需要左右两把才能吃
不加约束 → 5 人同时拿左叉 → 循环等待 → 死锁！

两种经典解法：
  方案 A：最多 4 人同时上桌（破坏循环等待）
  方案 B：奇数号先拿左叉，偶数号先拿右叉（破坏循环等待）
⚠️ 面试必问："为什么这么设计？"——破坏死锁四条件中的循环等待
```

### 6.2 完整代码（方案 A：限流 + 方案 B：编号取叉）

```java
/**
 * LeetCode 1226. 哲学家进餐
 * 方案 A：Semaphore(4) 限流 —— 最多 4 人同时尝试拿叉
 *   → 永远至少 1 人能拿到两把叉 → 无循环等待
 */
class DiningPhilosophersA {
    private final Semaphore table = new Semaphore(4);      // ⚠️ 限 4 人
    private final ReentrantLock[] forks = new ReentrantLock[5];
    { for (int i = 0; i < 5; i++) forks[i] = new ReentrantLock(); }

    public void wantsToEat(int philosopher,
                           Runnable pickLeftFork, Runnable pickRightFork,
                           Runnable eat, Runnable putLeftFork, Runnable putRightFork) {
        try {
            table.acquire();                              // 上桌名额
            int left = philosopher, right = (philosopher + 1) % 5;
            forks[left].lock();                           // 拿左叉
            forks[right].lock();                          // 拿右叉
            pickLeftFork.run(); pickRightFork.run();
            eat.run();
            putLeftFork.run(); putRightFork.run();
            forks[left].unlock(); forks[right].unlock();
            table.release();                              // 下桌
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }
}

/**
 * 方案 B：奇数先左后右、偶数先右后左
 *   → 不可能所有哲学家都先拿同一把叉 → 无环
 */
class DiningPhilosophersB {
    private final ReentrantLock[] forks = new ReentrantLock[5];
    { for (int i = 0; i < 5; i++) forks[i] = new ReentrantLock(); }

    public void wantsToEat(int philosopher,
                           Runnable pickLeftFork, Runnable pickRightFork,
                           Runnable eat, Runnable putLeftFork, Runnable putRightFork) {
        int left = philosopher, right = (philosopher + 1) % 5;
        if ((philosopher & 1) == 1) {                     // 奇数：左→右
            forks[left].lock(); forks[right].lock();
        } else {                                          // 偶数：右→左
            forks[right].lock(); forks[left].lock();
        }
        pickLeftFork.run(); pickRightFork.run();
        eat.run();
        putLeftFork.run(); putRightFork.run();
        forks[left].unlock(); forks[right].unlock();
    }
}
// 验证方案 B 无死锁：
//   奇数号先拿"左"，偶数号先拿"右" → 最多 4 人各拿一把 → 总有空叉可让
// ⚠️ 面试表达："死锁四条件之一循环等待被破坏——加锁顺序按编号交错"
```

## 7. 实战一：手写有界阻塞队列

### 7.1 题目与思路

```
实现 ArrayBlockingQueue 的核心语义：
  put(e)：满则阻塞等待；take()：空则阻塞等待
三版演进（面试常见"一步步升级"）：
  版一 wait/notify（基础）→ 版二 Lock/Condition（生产/消费分条件）→ 对照
⚠️ 版一的坑：notify 可能唤醒"同类线程"（生产者唤醒生产者）→ 假死
```

### 7.2 完整代码（Lock + Condition 版，正确实现）

```java
/**
 * 手写有界阻塞队列 —— Lock + 双 Condition 版
 * ⚠️ 生产/消费两个条件队列：生产者只唤醒消费者（反之亦然）→ 无"假死"
 */
class MyBoundedQueue<T> {
    private final Object[] items;
    private final ReentrantLock lock = new ReentrantLock();
    private final Condition notFull = lock.newCondition();   // 不满 → 可放
    private final Condition notEmpty = lock.newCondition();  // 不空 → 可取
    private int head, tail, count;

    public MyBoundedQueue(int capacity) { items = new Object[capacity]; }

    public void put(T v) throws InterruptedException {
        lock.lock();
        try {
            while (count == items.length) notFull.await();   // ⚠️ 满 → 等
            items[tail] = v;
            tail = (tail + 1) % items.length;                // 环形数组
            count++;
            notEmpty.signal();                               // ⚠️ 精确唤醒消费者
        } finally {
            lock.unlock();
        }
    }

    @SuppressWarnings("unchecked")
    public T take() throws InterruptedException {
        lock.lock();
        try {
            while (count == 0) notEmpty.await();             // 空 → 等
            T v = (T) items[head];
            items[head] = null;
            head = (head + 1) % items.length;
            count--;
            notFull.signal();                                // ⚠️ 精确唤醒生产者
            return v;
        } finally {
            lock.unlock();
        }
    }
}
// ⚠️ 与 wait/notify 版对比：
//   版一：一个条件队列，notifyAll 唤醒所有 → 可能唤醒同类（低效甚至假死）
//   版二：双 Condition → 生产只唤醒消费、消费只唤醒生产 → 精确高效
// ⚠️ 要点回顾：while 防虚假唤醒、finally 释放锁、环形数组复用空间
```

## 8. 实战二：生产者-消费者（线程池版）

### 8.1 题目与思路

```
生产者线程池 + 消费者线程池 + 有界队列（BlockingQueue）
工程版生产者-消费者：解耦 + 削峰填谷
⚠️ 与算法题的区别：线程池管理线程生命周期；队列负责缓冲
```

### 8.2 完整代码

```java
/**
 * 生产者-消费者（线程池 + BlockingQueue 版）
 * ⚠️ 工程标准写法：队列天然线程安全，无需手写锁
 */
class ProducerConsumer {
    private final BlockingQueue<Integer> queue = new ArrayBlockingQueue<>(100);

    public void run(int producers, int consumers) throws InterruptedException {
        CountDownLatch latch = new CountDownLatch(producers + consumers);

        ExecutorService prodPool = Executors.newFixedThreadPool(producers);
        ExecutorService consPool = Executors.newFixedThreadPool(consumers);

        // 生产者
        for (int p = 0; p < producers; p++) {
            prodPool.submit(() -> {
                try {
                    for (int i = 0; i < 100; i++)
                        queue.put((int) (Math.random() * 1000));   // 满则阻塞
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                } finally {
                    latch.countDown();
                }
            });
        }
        // 消费者
        for (int c = 0; c < consumers; c++) {
            consPool.submit(() -> {
                try {
                    while (!queue.isEmpty() || queue.take() != null) { }  // 简化消费
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                } finally {
                    latch.countDown();
                }
            });
        }
        latch.await();                                   // ⚠️ 等全部结束
        prodPool.shutdown(); consPool.shutdown();        // ⚠️ 优雅关闭
    }
}
// ⚠️ 工程要点：
//   ① BlockingQueue 替代手写锁（put/take 原子阻塞）
//   ② 线程池控制并发度（生产者/消费者数量独立调优）
//   ③ shutdown 后 awaitTermination 等收尾（防任务丢失）
//   ④ 终止信号：生产结束 → 发"毒丸"（特殊对象）通知消费者退出
```

---

## 9. 并发题方法论总结

### 9.1 六步框架

```
① 明确角色：几个线程？谁是"分发者"谁是"消费者"？
   ⚠️ 交替类题总有"交接双方"；多角色题总有一个"发号者"
② 明确顺序：打印序列是什么？（画出期望输出）
③ 选工具：见下表（先画状态再写代码）
④ 写模板：等待（while）→ 执行 → 更新状态 + 通知（先改后通知）
⑤ 锁纪律：finally 释放、volatile 可见性、中断恢复
⑥ 验证：n=1 手推 + 多轮循环推演 + 并发竞态检查
```

### 9.2 选型速查表

| 题目特征 | 首选工具 | 备选 |
|---------|---------|------|
| 按序打印（链式） | CountDownLatch / Semaphore | synchronized 标志位 |
| 两线程交替 | Semaphore（交接） | Condition |
| 多角色分发 | 多信号量（分发者模式） | Lock + 计数 |
| 凑组（H2O） | Semaphore + 互斥计数 | Lock + Condition |
| 死锁风险（哲学家） | Semaphore 限流 / 编号加锁 | 一次拿全部 |
| 生产消费 | BlockingQueue | wait/notify、Condition |

### 9.3 自测清单

```
□ 等待用 while 了吗？（防虚假唤醒）
□ volatile 标志可见性？（或锁内共享）
□ Lock 在 finally 释放了吗？
□ 状态更新在 notify 之前吗？（防丢失唤醒）
□ 信号量初始许可正确吗？（谁先开始 = 许可 1）
□ 中断异常恢复标志了吗？
□ 每个数/每个输出恰好被一个线程处理？（无重复无遗漏）
```

---

> 🎯 **核心要点**：并发题 = **角色划分 + 工具选型 + 等待-执行-通知模板**。三大模式——**交接**（Semaphore 交替）、**分发**（发号者 + 多信号量）、**凑组**（计数 + 放行）；两大铁律——while 等待、先改状态再通知；一个加分点——主动对比多种解法（锁/CAS/信号量/Condition）。
