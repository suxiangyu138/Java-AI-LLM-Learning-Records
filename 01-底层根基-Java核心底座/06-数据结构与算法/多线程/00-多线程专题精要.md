## 1. 核心概念

### 1.1 多线程题考什么

```
多线程标签题 = LeetCode 上的并发题
  核心：控制多个线程的执行顺序

三大手段：
  ① synchronized + 标志位（最简单）
  ② Lock + Condition（灵活）
  ③ Semaphore / CyclicBarrier（语义化）

面试定位：Java 岗必考（并发基础）；算法岗较少
```

### 1.2 识别信号

```
"按序打印/交替打印" → 并发控制
"线程安全/并发" → 多线程

⚠️ 并发题的通用框架：
  "等待条件 → 执行 → 通知下一个"
  每个线程一个"轮到我的"条件
```

### 1.3 并发三要素

```
① 互斥：同一时刻只有一个线程访问共享资源
   → synchronized / Lock
② 可见性：一个线程的修改对其他线程可见
   → volatile / 锁
③ 有序性：指令重排的约束
   → volatile（happens-before）

⚠️ 面试必答：
"并发三要素：互斥（锁）、可见性（volatile）、
 有序性（happens-before 规则）。"
```

## 2. 完整代码模板

### 2.1 1114. 按序打印（标志位 + synchronized）

```java
/**
 * LeetCode 1114. 按序打印（最基础的并发控制）
 */
class Foo {
    private volatile int stage = 1;      // ⚠️ volatile 可见性
    private final Object lock = new Object();

    public void first(Runnable printFirst) {
        synchronized (lock) {
            printFirst.run();
            stage = 2;                   // 先改标志
            lock.notifyAll();            // 再唤醒
        }
    }

    public void second(Runnable printSecond) {
        synchronized (lock) {
            while (stage != 2) {         // ⚠️ while 不是 if！
                try {
                    lock.wait();         // 条件不满足 → 等待
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                }
            }
            printSecond.run();
            stage = 3;
            lock.notifyAll();
        }
    }

    public void third(Runnable printThird) {
        synchronized (lock) {
            while (stage != 3) {
                try { lock.wait(); } catch (InterruptedException e) {}
            }
            printThird.run();
        }
    }
}
// 模板三步：等待条件 → 执行 → 更新标志 + 唤醒
```

### 2.2 1115. 交替打印（Semaphore 版）

```java
/**
 * LeetCode 1115. 交替打印 FooBar
 * 两个信号量互相"交接"（语义最清晰）
 */
class FooBar {
    private int n;
    private Semaphore fooSem = new Semaphore(1);  // foo 先开始
    private Semaphore barSem = new Semaphore(0);

    public FooBar(int n) { this.n = n; }

    public void foo(Runnable printFoo) {
        for (int i = 0; i < n; i++) {
            try {
                fooSem.acquire();        // 拿许可（没有则等）
                printFoo.run();
                barSem.release();        // 给 bar 许可
            } catch (InterruptedException e) {}
        }
    }

    public void bar(Runnable printBar) {
        for (int i = 0; i < n; i++) {
            try {
                barSem.acquire();        // 等 foo 给许可
                printBar.run();
                fooSem.release();        // 还给 foo
            } catch (InterruptedException e) {}
        }
    }
}
// foo → bar → foo → bar ...（信号量交接）
// ⚠️ Semaphore(0) 初始化：先 acquire 会阻塞（等待 release）
```

### 2.3 1195. 交替打印字符串（多信号量）

```java
/**
 * LeetCode 1195. 交替打印字符串
 * FizzBuzz 并发版：4 个线程按规则打印
 * 多信号量交接（n+1 个状态）
 */
class FizzBuzz {
    private int n;
    private Semaphore fizz = new Semaphore(0);
    private Semaphore buzz = new Semaphore(0);
    private Semaphore fizzbuzz = new Semaphore(0);
    private Semaphore num = new Semaphore(1);   // 数字线程先开始

    public FizzBuzz(int n) { this.n = n; }

    public void fizz(Runnable printFizz) {      // 3 的倍数
        for (int i = 3; i <= n; i += 3) {
            if (i % 15 != 0) {                  // 排除 15 的倍数
                fizz.acquire();
                printFizz.run();
                releaseNext(i + 1);
            }
        }
    }
    // buzz（5 的倍数）、fizzbuzz（15 的倍数）同构
    // number（其他）：循环 acquire num + 判断 + 释放对应信号量
    // ⚠️ 核心：每个数只由一个线程处理（互斥 + 交接）
}
```

## 3. 并发控制工具详解

### 3.1 工具对比表

| 工具 | 场景 | 特点 |
|------|------|------|
| **synchronized** | 互斥锁 | 简单，但无法"指定唤醒" |
| **Lock/Condition** | 精确唤醒 | 多个条件队列 |
| **Semaphore** | 信号量 | 许可控制（n 个） |
| **CountDownLatch** | 等待 N 个完成 | 一次性 |
| **CyclicBarrier** | N 个线程会合 | 可循环 |
| **volatile** | 可见性 | 不能保证原子性 |

```
选型：
  简单互斥 → synchronized
  精确条件 → Lock + Condition
  顺序交接 → Semaphore（语义清晰）
  ⚠️ 交替打印题 → Semaphore 最推荐
```

### 3.2 Semaphore 详解

```
Semaphore（信号量）：
  acquire()：拿一个许可（没有则阻塞）
  release()：释放一个许可

初始化：
  Semaphore(1)：互斥（类似锁）
  Semaphore(0)：初始不可用（等别人 release）
  Semaphore(n)：n 个资源（池）

⚠️ 面试表达：
"信号量管理许可数量——acquire 消费、
 release 生产。交替打印用两个信号量
 互相交接（一个执行完给另一个许可）。"
```

### 3.3 Lock + Condition（进阶）

```java
/**
 * Lock + Condition：多条件精确唤醒
 * （synchronized 只能 notifyAll 全部唤醒）
 */
class Printer {
    private final Lock lock = new ReentrantLock();
    private final Condition condA = lock.newCondition();
    private final Condition condB = lock.newCondition();
    private boolean turnA = true;

    public void printA() {
        lock.lock();
        try {
            while (!turnA) condA.await();   // 等 A 轮次
            System.out.println("A");
            turnA = false;
            condB.signal();                 // ⚠️ 精确唤醒 B
        } catch (InterruptedException e) {} finally {
            lock.unlock();                  // ⚠️ finally 释放！
        }
    }
    // printB 同构（等 B 轮次 → 打印 → 唤醒 A）
}
// ⚠️ 对比 synchronized：Condition 可指定唤醒谁
```

## 4. 多线程的核心易错点

### 4.1 为什么等待必须用 while？

```
虚假唤醒（spurious wakeup）：
  wait() 返回不代表条件满足！
  JVM 规范允许虚假唤醒（不满足条件也返回）

→ 必须 while 重新检查条件
  if 只检查一次 → 条件不满足也继续 → 顺序错乱

⚠️ 面试必答：
"等待用 while 不用 if——防止虚假唤醒：
 wait 返回后条件可能仍不满足，
 while 保证重新检查。"
```

### 4.2 volatile 的作用与局限

```
volatile 保证：
  ① 可见性（写后其他线程立即可见）
  ② 有序性（禁止指令重排）
不保证：
  原子性（i++ 不是原子的！）

→ 标志位用 volatile；计数用锁/原子类

⚠️ 面试必答：
"volatile 管可见性不管原子性——
 i++ 需要锁或 AtomicInteger。"
```

### 4.3 锁的正确使用

```
① synchronized 块要小（只锁必要部分）
② Lock 必须在 finally 中 unlock（防异常死锁）
③ wait/notify 必须在 synchronized 内
④ 先改共享状态再 notify（防丢失唤醒）

⚠️ 经典错误：
  Lock 忘 unlock → 死锁
  notify 在状态更新前 → 唤醒后条件仍不满足
```

## 6. 面试要点与追问

### 6.1 面试话术模板

```
"按序打印用 synchronized + 标志位：
 每个方法 while 等待自己的阶段号，
 满足执行并更新标志 + notifyAll。
 关键点：等待必须 while（防虚假唤醒）、
 标志加 volatile（保证可见性）。
 交替打印更推荐 Semaphore——两个信号量
 互相交接（一个执行完给另一个许可）。"
```

### 6.2 高频追问 TOP 8

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | 等待为什么用 while？ | 虚假唤醒：wait 返回条件可能仍不满足 |
| 2 | volatile 作用？ | 可见性 + 有序性；不保证原子性 |
| 3 | 信号量 vs 锁？ | 许可数量（可多个）vs 互斥；交替用信号量 |
| 4 | 死锁怎么避免？ | 加锁顺序一致 / 超时 / 一次拿全部（哲学家） |
| 5 | Condition 优势？ | 精确唤醒指定线程（synchronized 只能全部） |
| 6 | notify vs notifyAll？ | 单等待者 notify；多等待者 notifyAll（防丢失） |
| 7 | InterruptedException？ | 中断响应；恢复中断标志（重设 interrupt） |
| 8 | 三要素？ | 互斥、可见性、有序性 |

### 6.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| 等待用 if | 虚假唤醒错乱 | 用 while |
| 标志不加 volatile | 可见性缺失 | 加 volatile |
| Lock 忘 unlock | 死锁 | finally 释放 |
| notify 在改状态前 | 丢失唤醒 | 先改后通知 |
| Semaphore 初始化错 | 顺序错乱 | 正确的初始许可 |

> 🎯 **核心要点**：多线程 = **等待-执行-通知**三步骤 + 工具选型（synchronized/信号量/Condition）。识别信号："按序打印、交替执行、线程同步"。while 等待、volatile 可见性、先改状态再通知是三大铁律；交替打印首选 Semaphore（语义清晰）。
