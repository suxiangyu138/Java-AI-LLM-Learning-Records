## 1. 回溯的本质：DFS + 状态回退

### 1.1 一句话定义

> **回溯 = 深度优先搜索（DFS）+ 状态回退**。它通过递归遍历所有可能的解空间，当某条路径走不通（或不满足条件）时，**撤销上一步的选择**，换一个方向继续尝试，直到穷举完所有可能。

### 1.2 核心套路：选择 → 递归 → 撤销

```java
// 回溯代码的三部曲（所有回溯题的骨架）
void backtrack(状态参数) {
    if (结束条件) {              // ① 收集结果
        收集解;
        return;
    }
    for (选择 : 选择列表) {       // ② 遍历决策树宽度
        做选择;                   // 记录进 path
        backtrack(新状态);        // ③ 递归进入决策树深度
        撤销选择;                 // ④ 撤销，恢复现场 ← 回溯的灵魂！
    }
}
```

### 1.3 为什么需要"撤销"？

```
没有撤销会发生什么？
以全排列 [1,2,3] 为例：
  第一层选 1 → path=[1]
  第二层选 2 → path=[1,2]
  第三层选 3 → path=[1,2,3] → 收集 {1,2,3}
  回到第三层，如果不撤销 3 → path=[1,2]
  第二层想选 3 → path=[1,2,3] → 重复！且永远选不了其他组合

撤销选择 = 恢复现场，让同层兄弟分支可以复用同一份 path
这是回溯与普通递归最大的区别！
```

> 💡 **类比**：回溯就像走迷宫——走到死路时退回到上一个岔路口（撤销选择），换一条没走过的路（选择列表中的下一个选项），直到找到所有出口（所有可行解）。

## 2. 回溯三要素

### 2.1 三要素详解

| 要素 | 含义 | 代码形态 | 常见实现 |
|------|------|------|------|
| **路径 path** | 已做的选择序列 | `List<Integer> path` | `path.add(x)` / `path.removeLast()` |
| **选择列表** | 当前还能选什么 | for 循环的遍历范围 | `for (i = start...)` 或 `for (i = 0...)` + used |
| **结束条件** | 何时收集结果 | if 判断 | 长度达标 / 总和达标 / 到达边界 |

### 2.2 三要素在五类题中的形态

| 题型 | path 的含义 | 选择列表怎么定 | 结束条件 |
|------|------|------|------|
| 组合 | 已选元素 | `[start, n)` 防回头 | path 长度 = k |
| 排列 | 已排序列 | 全数组，跳过 used | path 长度 = n |
| 子集 | 已选元素 | `[start, n)` | 每层都收集 |
| 切割 | 已切割的段 | `[start, n)` 切点位置 | start = n |
| 棋盘 | 已放置的位置 | 下一行所有合法列 | 摆满/找到解 |

## 3. 决策树模型

### 3.1 全排列的决策树

```
输入 [1, 2, 3] 的全排列决策树：

                根 (path=[])
      ┌──────────┼──────────┐
     1           2           3
   ┌─┼─┐      ┌─┼─┐      ┌─┼─┐
   2   3      1   3      1   2
   │   │      │   │      │   │
   3   2      3   1      2   1
   
树的性质：
  - 树的宽度 = 每层可选择元素数（决策点）
  - 树的深度 = 递归层数（= 元素个数）
  - 根到叶的一条路径 = 一个完整解
  - 叶子节点总数 = 解的数量 = n!
```

### 3.2 用决策树理解"剪枝"

```
剪枝 = 在遍历决策树时提前砍掉不可能产生可行解的子树

例：组合总和 [2,3,6,7], target=7（排序后）
  根
 ├── 选2 ── 选2 ── ... → 总和 6，还能继续（≤7）
 ├── 选3 ── 选6 → 总和 9 > 7 → 剪掉！(break，因为 6 之后更大)
 └── 选7 → 总和 7 ✓ 收集

排序 + 单调剪枝：一旦 sum > target，后面的元素更大，全部不用试
```

## 4. 核心模板框架

### 4.1 通用回溯模板（Java）

```java
/**
 * 回溯算法通用模板
 * 组合/子集：用 start 控制起始下标
 * 排列：用 used 控制已选元素
 */
class BacktrackingTemplate {
    List<List<Integer>> res = new ArrayList<>();
    List<Integer> path = new ArrayList<>();

    public List<List<Integer>> solve(int[] nums) {
        backtrack(nums, 0, 参数...);
        return res;
    }

    private void backtrack(int[] nums, int start, 参数...) {
        // ① 收集结果（子集类：进入即收集；组合/排列类：满足条件才收集）
        if (满足条件) {
            res.add(new ArrayList<>(path));   // ⚠️ 必须拷贝！
            return;
        }

        // ② 遍历选择列表
        for (int i = start; i < nums.length; i++) {
            if (剪枝条件) continue;           // 可选：剪枝

            path.add(nums[i]);                // ③ 做选择
            backtrack(nums, i + 1, 参数...);  // ④ 递归（可重复选则传 i）
            path.remove(path.size() - 1);     // ⑤ 撤销选择 ← 灵魂
        }
    }
}
```

### 4.2 三类题型模板速查

```java
// ─── 组合模板：start 控顺序 ─────────────────────────
void dfs(int start) {
    if (path.size() == k) { res.add(new ArrayList<>(path)); return; }
    // 范围剪枝：i 最多到 n-(k-path.size())，保证能凑满 k 个
    for (int i = start; i <= n - (k - path.size()) + 1; i++) {
        path.add(i);
        dfs(i + 1);      // 不可重复选 → i+1
        path.removeLast();
    }
}

// ─── 排列模板：used 控重复 ──────────────────────────
void dfs() {
    if (path.size() == nums.length) { res.add(new ArrayList<>(path)); return; }
    for (int i = 0; i < nums.length; i++) {
        if (used[i]) continue;
        used[i] = true;
        path.add(nums[i]);
        dfs();
        path.removeLast();
        used[i] = false;
    }
}

// ─── 子集模板：进入即收集 ───────────────────────────
void dfs(int start) {
    res.add(new ArrayList<>(path));   // 每个节点都是答案！
    for (int i = start; i < nums.length; i++) {
        path.add(nums[i]);
        dfs(i + 1);
        path.removeLast();
    }
}
```

## 5. path 拷贝：最常见的坑

### 5.1 错误演示

```java
// ❌ 错误：直接收集 path 引用
if (path.size() == k) {
    res.add(path);   // 存的是同一个对象引用！
    return;
}

// 后果：path 后续被撤销修改 → res 里所有结果最后都变成同一个最终状态
// 例：res 会变成 [[], [], ...] 或全部相同
```

### 5.2 正确写法

```java
// ✅ 正确：拷贝一份快照
if (path.size() == k) {
    res.add(new ArrayList<>(path));  // 深拷贝当前路径
    return;
}
```

> 🎯 **面试必讲**：面试官看到你写 `res.add(new ArrayList<>(path))` 会点头，看到 `res.add(path)` 直接扣分——这是回溯最容易踩的坑，也是面试必问点："为什么收集结果时要拷贝？"

## 6. 复杂度分析：由输出规模决定

### 6.1 核心认知

> 回溯本质是穷举，其时间复杂度**主要由输出结果的数量（解的数量）决定**。剪枝可以减少实际搜索时间，但**不改变理论复杂度**。

```java
// 复杂度分析公式
时间复杂度 = 解的数量 × 每构造一个解的开销
空间复杂度 = path 最大深度（递归栈 + path 长度）

例：全排列
  解的数量 = n!
  每解开销 = O(n)（拷贝 path 是 O(n)）
  → 总时间 O(n × n!)
  → 空间 O(n)（递归深度 n + path 长度 n）
```

### 6.2 各题型复杂度

| 题型 | 解数量 | 总复杂度 | 空间 |
|------|:---:|:---:|:---:|
| 子集 | 2ⁿ | O(2ⁿ) | O(n) |
| 组合 | C(n,k) | O(C(n,k)×k) | O(k) |
| 全排列 | n! | O(n×n!) | O(n) |
| 组合总和 | 指数 | O(指数级) | O(target/最小元素) |
| 切割回文 | 2^(n-1) | O(n×2ⁿ) | O(n) |
| N 皇后 | 上界 n! | O(n×n!) | O(n²) |

### 6.3 面试话术

```
"回溯本质是穷举，所以复杂度由输出规模决定：
 全排列有 n! 个解，每个解构造 O(n)，总 O(n×n!)；
 子集有 2ⁿ 个解，总 O(2ⁿ)。
 我做的剪枝（排序+早停、同层去重）能显著减少实际搜索
 的分支，但不改变最坏情况下的理论复杂度。"
```

## 7. 回溯 vs 其他算法

| 对比算法 | 区别 | 一句话总结 |
|------|------|------|
| **DFS** | 回溯是带"撤销"的 DFS，DFS 只求遍历/到达 | 回溯 = DFS + 状态回退 |
| **动态规划** | DP 求最优解/计数（重叠子问题），回溯求所有解 | DP 剪枝重叠，回溯枚举全部 |
| **贪心** | 贪心每步选最优不回退，回溯会回退重试 | 贪心局部最优，回溯全局穷举 |
| **BFS** | BFS 按层扩散，回溯是深度优先 | 找最短用 BFS，枚举方案用回溯 |
| **递归** | 递归是执行机制，回溯是算法思想 | 回溯靠递归实现 |

> 🎯 **核心要点**：回溯的本质是**穷举 + 恢复现场**。理解"选择→递归→撤销"三步曲和决策树模型后，组合/排列/子集/切割/棋盘五类题只是模板的三个参数不同（start vs used vs 其他约束）。**path 必须拷贝、撤销必须在递归后**——记住这两条铁律，回溯题就是套模板的重复劳动。
