## 1. 递归 vs 迭代：两种实现形态

### 1.1 对比

| 维度 | 递归（自顶向下） | 迭代（自底向上） |
|------|:---:|:---:|
| 拆分方式 | 递归对半拆到单元素 | 从单元素块逐轮翻倍 |
| 递归栈 | O(log n) | 无（省栈空间） |
| 代码 | 直观（面试首选） | 稍绕（边界多） |
| 应用 | 教学/面试 | 工程（避免深递归） |
| 结果 | 完全相同 | 完全相同 |

```
⚠️ 面试表达：
"递归版拆到单元素再合并，直观好写；
 迭代版从长度 1 的块开始两两合并，块长翻倍，
 无递归栈，适合深数据。两者合并逻辑完全一样。"
```

### 1.2 两者的同一性

```
递归版：mergeSort(0,7) → mergeSort(0,3) | mergeSort(4,7) → ... → 合并
迭代版：len=1 两两合并 → len=2 两两合并 → len=4 → len=8

递归树的层序 = 迭代的轮次：
  递归第 k 层处理的大小 = 迭代第 k 轮
  → 本质是同一过程的不同执行顺序
```

## 2. 自底向上迭代版详解

### 2.1 完整实现（含边界防护）

```java
/**
 * 归并排序（自底向上迭代版）
 * ⚠️ 三处边界防护：mid 与 hi 都要 min 夹紧
 */
void mergeSortIterative(int[] nums) {
    int n = nums.length;
    int[] tmp = new int[n];                     // 全程复用辅助数组
    for (int len = 1; len < n; len <<= 1) {     // 块长 1,2,4,8...
        for (int lo = 0; lo < n; lo += len * 2) {
            int mid = Math.min(lo + len - 1, n - 1);     // ⚠️ 左块右界
            int hi = Math.min(lo + len * 2 - 1, n - 1);  // ⚠️ 右块右界
            if (mid < hi) {                     // ⚠️ 左块非空且右块存在
                merge(nums, lo, mid, hi, tmp);
            }
        }
    }
}

private void merge(int[] nums, int lo, int mid, int hi, int[] tmp) {
    int i = lo, j = mid + 1, k = lo;
    while (i <= mid && j <= hi) {
        if (nums[i] <= nums[j]) tmp[k++] = nums[i++];
        else                    tmp[k++] = nums[j++];
    }
    while (i <= mid) tmp[k++] = nums[i++];
    while (j <= hi)  tmp[k++] = nums[j++];
    System.arraycopy(tmp, lo, nums, lo, hi - lo + 1);
}
// 推演 [3,1,4,2]：
//   len=1：merge(0,0,1) → [1,3]；merge(2,2,3) → [2,4]
//   len=2：merge(0,1,3) → [1,2,3,4] ✓
// ⚠️ 三个 min 是迭代版最易错的点（递归版天然规避）
```

### 2.2 迭代版为什么适合"链表"

```
链表归并（148）用递归版需要快慢指针找中点（每层 O(n) 扫描）
迭代版直接按"块长"操作——但链表定位块边界同样需要移动指针

⚠️ 工程现实：链表归并通常用递归+快慢指针
  （简单直观），迭代版优化留给需要极致性能的场景
```

## 3. 归并的工程优化细节

### 3.1 四类优化

| 优化 | 做法 | 收益 |
|------|------|------|
| 小规模转插入 | 长度 < 16 用 InsertionSort | 减少递归调用开销 |
| 有序检测 | 两半已有序则跳过 merge | 近似有序输入加速 |
| 共享辅助数组 | 全程复用 tmp | 空间 O(n) 非 O(n log n) |
| 交替写回 | 双缓冲交替（tmp↔nums） | 省一次拷贝 |

```java
/** 有序检测优化：左块最大值 ≤ 右块最小值 → 已有序，跳过合并 */
void mergeWithCheck(int[] nums, int lo, int mid, int hi, int[] tmp) {
    if (nums[mid] <= nums[mid + 1]) return;      // ⚠️ 已有序
    merge(nums, lo, mid, hi, tmp);
}
// 适用：接近有序的真实数据（如增量排序后的再排序）
```

### 3.2 归并排序的缓存与内存访问

```
归并排序访问模式：顺序扫描（缓存友好）
快排访问模式：随机跳转（缓存较差，但交换更少）
→ 大数据下归并的"顺序性"部分抵消了辅助空间的劣势

⚠️ 面试表达：
"归并顺序读写，对 CPU 缓存友好；
 快排随机访问。n 很大（超出缓存）时
 归并的缓存行为反而更有优势。"
```

## 4. TimSort：归并与插入的合体

### 4.1 设计思想

```
TimSort（2002，Tim Peters 为 Python 设计）：
  ① 识别天然有序的"run"（升序段/严格降序反转）
  ② run 长度不足 minRun → 用二分插入补齐
  ③ 用"栈 + 合并策略"合并相邻 run（保证平衡）

⚠️ 为什么快？
  真实数据往往包含大量有序片段
  → 直接利用，避免无谓拆分
  最坏仍是 O(n log n)，但常数远小于纯归并
```

### 4.2 Java 中的 TimSort

```java
// ⚠️ 工程事实：Arrays.sort(Object[]) 内部就是 TimSort
//   （对象排序要求稳定 → 归并家族）
//   Arrays.sort(int[]) 用 DualPivotQuickSort
//     （原始类型不要求稳定 → 快排家族更快）

String[] names = {"bob", "alice", "carol"};
Arrays.sort(names);          // TimSort（稳定）
int[] nums = {3, 1, 2};
Arrays.sort(nums);           // 双轴快排（不稳定）

// ⚠️ 面试表达：
//   "Java 对象排序用 TimSort（稳定 + 利用天然有序段）；
//    原始类型排序用双轴快排（不稳定但常数小）。
//    排序稳定性是选择的核心依据。"
```

## 5. 外部排序：磁盘级归并

### 5.1 为什么需要外部排序

```
数据超出内存（如 100GB 文件，内存 8GB）：
  无法一次加载 → 排序必须在磁盘与内存之间进行
  磁盘 I/O 是瓶颈 → 策略核心是"减少磁盘读写"

外部归并排序两阶段：
  阶段一（生成归并段）：分块读入 → 内存排序 → 写回磁盘
    每块生成一个"有序归并段"（run）
  阶段二（归并段合并）：多路归并所有 run → 全局有序
```

```
文件 100GB / 内存 1GB：
  阶段一：分 100 块 → 每块 1GB 排序 → 100 个有序 run
  阶段二：多路归并 100 个 run → 一次读出 100 个文件的头部
          每次取最小写回 → 生成全序文件
  读写量：约 2×文件大小（读一遍写一遍 + 归并一遍）
```

### 5.2 归并轮数与 I/O 次数

```
K 路归并 vs 2 路归并：
  2 路：每轮合并 2 个 run → 100 个 run 需 log₂100 ≈ 7 轮
  K 路：每轮合并 K 个 → 轮数 = log_K(100)
  轮数越少 → 磁盘读写次数越少 → 越快

⚠️ 但 K 不能无限大：内存中要同时持有 K 个缓冲块
  权衡：缓冲块大小 × K ≤ 可用内存
```

## 6. 多路归并与败者树

### 6.1 简单实现：堆

```java
/** K 路归并：堆实现（每轮取最小） */
PriorityQueue<int[]> heap = new PriorityQueue<>((a, b) -> a[0] - b[0]);
// 每个 run 维护：(当前值, 所在 run, 当前下标)
// 弹出最小 → 从对应 run 补下一个 → 直到全部耗尽
// 复杂度：O(n log K)
```

### 6.2 败者树（工程优化）

```
堆的缺点：每次弹出后需要 O(log K) 调整
败者树：叶子是 K 个候选，内部节点记录"败者"（较大者）
  每次比较只沿"胜者路径"向上——比较次数更少（约 log K 但常数小）

⚠️ 面试定位：
  "多路归并用堆 O(n log K) 足够；
   败者树把常数做小（比较次数约 log K，且减少缓存失效），
   是数据库/外部排序的工程细节。"
```

### 6.3 归并排序在数据库/大数据的存在

| 系统 | 归并的应用 |
|------|-----------|
| MySQL | 排序算法（filesort 用归并）、临时表排序 |
| 外部排序 | 数据库 order by 超内存时 |
| Hadoop | 外部排序是 Shuffle 阶段核心 |
| 日志系统 | 多文件日志按时间归并 |

## 7. 稳定性的工程价值

### 7.1 稳定性定义与场景

```
稳定：相等元素的相对顺序不变
  例：先按时间排序，再按用户排序
    → 稳定排序保证"同一用户的记录仍按时间有序"

⚠️ 场景：
  ① 多关键字排序（先次关键字后主关键字）
  ② 保留输入顺序的辅助排序
  ③ 数据库 order by a, b（实现就是两次稳定排序）
```

### 7.2 稳定性的实现代价

```
归并：稳定（合并时取左块 → O(n) 空间代价）
快排：不稳定（交换破坏相对顺序）
插入/冒泡：稳定
堆排：不稳定

⚠️ 面试必答：
"归并用 <= 比较保证稳定（相等取左侧元素）；
 代价是 O(n) 辅助空间。需要稳定排序且内存够 → 归并；
 内存敏感且不要求稳定 → 原地快排/堆排。"
```

## 8. 归并 vs 全排序家族

| 排序 | 时间 | 空间 | 稳定 | 特点 |
|------|:---:|:---:|:---:|------|
| 归并 | O(n log n) | O(n) | ✅ | 稳定、顺序访问、外部排序 |
| 快排 | O(n log n) 期望 | O(log n) | ❌ | 原地、常数小、缓存较差 |
| 堆排 | O(n log n) | O(1) | ❌ | 原地但缓存跳跃严重 |
| 插入 | O(n²) | O(1) | ✅ | 小数组/近似有序最优 |
| 基数 | O(d·n) | O(n) | ✅ | 整数/定长字符串 |
| TimSort | O(n log n) | O(n) | ✅ | 真实数据最快（run 利用） |

```
选型口诀：
  要稳定 → 归并/TimSort/插入
  要原地 → 快排/堆排
  近似有序 → 插入/TimSort
  外部数据 → 归并
  Java 对象 → TimSort；原始类型 → 双轴快排
```

## 9. 面试要点与追问

### 9.1 面试话术模板

```
"归并排序：拆两半 → 递归排 → 合并有序。
 时间 O(n log n)（每层合并 O(n)，log n 层），
 空间 O(n)（辅助数组），稳定（相等取左）。
 工程变体：迭代版无递归栈、TimSort 利用有序段、
 外部排序用于磁盘数据。逆序对等统计问题
 在合并时顺手计数（O(n log n)）。"
```

### 9.2 高频追问 TOP 8

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | 归并为什么稳定？ | 合并时相等取左块元素 |
| 2 | 迭代版边界？ | mid/hi 用 min 夹紧，避免越界 |
| 3 | TimSort 是什么？ | 归并+插入：识别 run、小段插入、栈式合并 |
| 4 | Java 用什么排序？ | 对象 TimSort；原始类型双轴快排 |
| 5 | 外部排序？ | 分块排序生成 run → 多路归并 |
| 6 | 多路归并怎么实现？ | 堆 O(n log K)；败者树优化常数 |
| 7 | 归并缓存优势？ | 顺序读写，大数据下比快排更友好 |
| 8 | 什么时候用归并？ | 要稳定/链表/外部数据/多关键字排序 |

### 9.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| 迭代版忘了 min 夹紧 | 越界/漏数据 | 三个 min 检查 |
| 相等时取右块 | 失去稳定性 | 用 <= |
| 每层新建辅助数组 | O(n log n) 空间 | 全程复用 |
| 归并段数不均衡 | 归并轮次多 | 段大小尽量均匀 |
| 忘有序检测 | 近似有序白跑 | nums[mid] <= nums[mid+1] 跳过 |
