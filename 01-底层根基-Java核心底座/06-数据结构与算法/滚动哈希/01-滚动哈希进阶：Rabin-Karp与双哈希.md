## 1. 滚动哈希的数学本质

### 1.1 定义

```
滚动哈希 = 用"多项式哈希"表示字符串，并支持 O(1) 滑动更新

字符串 s[0..n-1] 的哈希：
  H = (s[0]·B^(n-1) + s[1]·B^(n-2) + ... + s[n-1]) mod M
  其中 B 是基数（base），M 是模数（mod）

⚠️ 三个 O(1) 操作：
  ① 窗口右滑：H' = (H - s[i]·B^(len-1))·B + s[i+len]
  ② 取子串哈希：sub = (H[j] - H[i]·B^(j-i)) mod M（前缀哈希差分）
  ③ 拼接：H(a+b) = H(a)·B^len(b) + H(b)
```

### 1.2 为什么叫"滚动"

```
朴素思路：每个子串重新算哈希 → O(len) 每个
滚动思路：窗口右移一位 → 减去左边、乘 B、加右边 → O(1)

对比：
  朴素匹配（暴力）：O(n·m)
  滚动哈希：O(n + m)（一次滑动 + 一次比较）
⚠️ 本质：把"比较两个字符串"O(m) 降为"比较两个数"O(1)
```

### 1.3 前缀哈希（核心工具）

```java
// 前缀哈希：pre[i] = 字符串 [0, i) 的哈希
// 任意子串 [i, j) 哈希 = pre[j] - pre[i]·B^(j-i)（O(1) 取子串！）

long[] pre = new long[n + 1];
long[] pow = new long[n + 1];          // pow[i] = B^i mod M
pow[0] = 1;
for (int i = 0; i < n; i++) {
    pre[i + 1] = (pre[i] * B + s.charAt(i)) % M;
    pow[i + 1] = pow[i] * B % M;
}

// 子串 [l, r)（含 l 不含 r）的哈希：
long hashOf(int l, int r) {
    return ((pre[r] - pre[l] * pow[r - l]) % M + M) % M;   // ⚠️ +M 防负
}
// 应用：任意子串比较 O(1) —— 回文判断、最长重复子串的基础
```

## 2. Rabin-Karp：字符串匹配 O(n+m)

### 2.1 算法流程

```
在文本 text（长 n）中找模式 pattern（长 m）：
  ① 计算 pattern 的哈希 Hp（O(m)）
  ② 计算 text 前 m 个字符的哈希 Ht（O(m)）
  ③ 窗口滑动（n-m+1 次，每次 O(1) 更新）
     Ht 与 Hp 相等 → 逐字符验证（防哈希碰撞）→ 找到
  复杂度：O(n+m) 期望，最坏 O(n·m)（全碰撞时）

⚠️ 与 KMP 对比：
  KMP：O(n+m) 确定性，无需碰撞验证，但有 next 数组
  Rabin-Karp：实现简单（尤其多模式匹配），有碰撞风险
```

### 2.2 完整实现

```java
/**
 * Rabin-Karp 字符串匹配：text 中找 pattern，返回首次出现下标
 * ⚠️ 大素数模数（如 1_000_000_007）降低碰撞
 */
int rabinKarp(String text, String pattern) {
    int n = text.length(), m = pattern.length();
    if (m > n) return -1;
    long B = 131, M = 1_000_000_007L;

    long hp = 0;
    for (char c : pattern.toCharArray())
        hp = (hp * B + c) % M;                    // ① pattern 哈希

    long h = 0, powB = 1;
    for (int i = 0; i < m - 1; i++) powB = powB * B % M;   // B^(m-1)

    for (int i = 0; i < n; i++) {
        if (i < m) {
            h = (h * B + text.charAt(i)) % M;     // ② 初始窗口哈希
        } else {
            // ③ 窗口右滑：减左边，乘 B，加右边
            h = ((h - text.charAt(i - m) * powB % M + M) % M * B
                 + text.charAt(i)) % M;
        }
        if (i >= m - 1 && h == hp) {
            // ⚠️ 哈希相等 → 逐字符验证（防碰撞）
            if (text.substring(i - m + 1, i + 1).equals(pattern))
                return i - m + 1;
        }
    }
    return -1;
}
// ⚠️ 滑动公式推导：
//   H_old = a·B^(m-1) + b·B^(m-2) + ... + x   （m 个字符）
//   H_new = b·B^(m-1) + ... + x·B + y
//   H_new = (H_old - a·B^(m-1))·B + y ✓
```

### 2.3 多模式匹配（Rabin-Karp 的独特优势）

```
KMP 一次只能匹配一个模式；多模式要 Aho-Corasick
Rabin-Karp：模式集合的哈希放进 Set → 一次扫描全部匹配
  ⚠️ 场景：敏感词过滤、字典匹配（模式数多、文本长）
```

## 3. 哈希冲突与概率分析

### 3.1 碰撞的来源

```
两个不同字符串哈希相同 → 碰撞
  数学上无法避免（值域 M 有限，字符串无限）
  但概率可以控制到极小

生日悖论警示：
  哈希值域 M，比较 k 个哈希时碰撞概率 ≈ k²/(2M)
  M = 10⁹ 时，k = 10⁵ 个哈希 → 碰撞概率 ≈ 0.5%？（k²/(2M) = 10¹⁰/2e9 = 5）
  ⚠️ 注意：海量子串比较时碰撞概率会上升！
```

### 3.2 单哈希的风险场景

```
1044 最长重复子串（二分 + 哈希）：
  每轮检查 n 个子串哈希 → 需要比较 O(n) 次
  单哈希 + 小模数（如 1e9+7）：
    理论碰撞概率低，但 LeetCode 曾有构造用例碰撞
  工程结论：关键场景必须双哈希或大模数

⚠️ 面试表达：
"单哈希有理论碰撞风险（生日悖论下概率可控但非零）；
 双哈希（两个基/模）把碰撞概率降到平方级别；
 更保守的做法是碰撞后回退到直接比较（Rabin-Karp 的验证步骤）。"
```

### 3.3 碰撞概率量化

| 策略 | 值域 | 碰撞概率（10⁶ 个哈希比较） | 结论 |
|------|:---:|:---:|------|
| 单哈希 int（2³²） | 2³² | ~1.2×10⁻⁴ | 可能碰撞 |
| 单哈希 long（2⁶⁴） | 2⁶⁴ | ~2.7×10⁻¹⁴ | 实际安全 |
| 双哈希 2×10⁹ | ~10¹⁸ | ~10⁻⁹ | 理论安全 |
| 双哈希 + 验证 | - | 0（验证兜底） | 绝对正确 |

## 4. 双哈希与防碰撞策略

### 4.1 双哈希实现

```java
/** 双哈希：两个独立 (基, 模) 组合，同时相等才判定相同 */
class DoubleHash {
    static final long B1 = 131, M1 = 1_000_000_007L;
    static final long B2 = 137, M2 = 1_000_000_009L;
    long[] pre1, pre2, pow1, pow2;

    DoubleHash(String s) {
        int n = s.length();
        pre1 = new long[n + 1]; pre2 = new long[n + 1];
        pow1 = new long[n + 1]; pow2 = new long[n + 1];
        pow1[0] = 1; pow2[0] = 1;
        for (int i = 0; i < n; i++) {
            pre1[i + 1] = (pre1[i] * B1 + s.charAt(i)) % M1;
            pre2[i + 1] = (pre2[i] * B2 + s.charAt(i)) % M2;
            pow1[i + 1] = pow1[i] * B1 % M1;
            pow2[i + 1] = pow2[i] * B2 % M2;
        }
    }
    // ⚠️ 子串比较：两个哈希都相等 → 判定相等
    boolean equal(int l1, int r1, int l2, int r2) {
        if (r1 - l1 != r2 - l2) return false;
        return hash(l1, r1, pre1, pow1, M1) == hash(l2, r2, pre1, pow1, M1)
            && hash(l1, r1, pre2, pow2, M2) == hash(l2, r2, pre2, pow2, M2);
    }
}
// ⚠️ 注意事项：
//   两个模数必须互质（选两个大素数）
//   两个基不要相同（131/137）
//   复杂度不变（常数 ×2）
```

### 4.2 防碰撞的四种层次

| 层次 | 手段 | 代价 | 适用 |
|------|------|:---:|------|
| 1 | 大模数 long 单哈希 | 无 | 一般题目 |
| 2 | 双哈希 | 2 倍常数 | 竞赛/关键 |
| 3 | 碰撞验证（equals 回退） | 碰撞时才付 | Rabin-Karp 匹配 |
| 4 | 换成确定性算法（KMP/后缀数组） | 实现复杂度 | 绝对正确性要求 |

> 🎯 **工程结论**：LeetCode 场景"long 单哈希 + 大基"足够；**碰撞验证**（第 3 层）是不增加复杂度又能保证正确的关键——Rabin-Karp 本来就是"哈希预筛选 + 精确验证"。

## 5. 基与模数的选择

### 5.1 基（base）的选择

```
① 大于字符集大小：B = 131/13331（ASCII 场景）
   ⚠️ B 太小（如 26）→ 不同字符串容易碰撞
② 最好选质数（如 131、137、31）
③ 避免 B 与 M 有公因子（保证多项式哈希的"随机性"）

⚠️ 字符映射：直接用 char 值（ASCII）即可
  若用 char-'a'（0-25），B 必须 > 25（否则前缀可能重复）
```

### 5.2 模数（mod）的选择

```
推荐：
  1_000_000_007（1e9+7，素数，竞赛标配）
  1_000_000_009（1e9+9，素数，双哈希第二模）
  Long.MAX_VALUE？——不推荐，乘法溢出会破坏模运算

⚠️ 模数的作用：
  ① 防溢出（乘法结果超 long）
  ② 制造"伪随机"——不同字符串的哈希均匀分布在 [0, M)
  M 越大 → 碰撞越少 → 优先大素数
```

### 5.3 Java 溢出的坑

```java
// ❌ 危险写法：中间乘法可能溢出
long h = (h * B + c) % M;                    // h*B 可能超 long？
// ✅ 如果 B ≤ 10⁵、h < M ≈ 10⁹ → h*B ≈ 10¹⁴ < 9.2×10¹⁸ 安全
//   但 B 大（如 13331）且 M 大（1e18）时可能溢出！

// 安全策略：保持 M ≈ 1e9，B ≈ 1e5 → 乘法 < 1e14 安全
// 或使用 Math.multiplyHigh / 高精度库（工程场景）
```

## 6. 二维滚动哈希：矩阵场景

### 6.1 一维 → 二维

```
矩阵（m×n）中快速比较任意子矩阵：
  先在行方向滚动（每行前缀哈希）
  再在列方向滚动（列组合）

公式（k 行 × k 列子矩阵哈希）：
  H = Σ Σ a[i][j] · B1^i · B2^j（二维多项式哈希）

⚠️ 应用：
  718 最长重复子数组（一维特例）
  矩阵查重、图像匹配、生物序列二维比对
```

### 6.2 二维实现的要点

```java
/** 二维滚动哈希：双重基 B1（行）与 B2（列） */
// 预处理：
//   pre[i][j] = 左上角 (0,0) 到 (i,j) 的二维前缀哈希
//   pre[i][j] = pre[i-1][j]·B1 + pre[i][j-1]·B2
//              - pre[i-1][j-1]·B1·B2 + a[i][j]

// 查询任意 (r1,c1)-(r2,c2) 子矩阵（容斥原理）：
//   hash = pre[r2][c2]
//         - pre[r1-1][c2]·B1^(r2-r1+1)
//         - pre[r2][c1-1]·B2^(c2-c1+1)
//         + pre[r1-1][c1-1]·B1^(...)·B2^(...)
// ⚠️ 与一维前缀和同理：二维哈希 = 二维前缀和 + 幂次修正
```

> 🎯 **面试表达**："二维滚动哈希 = 二维前缀和思想 + 双基多项式——子矩阵哈希 O(1) 查询，用于矩阵查重/图像匹配。实现要点是容斥公式中的幂次修正。"

## 7. 滚动哈希 vs KMP/后缀数组

### 7.1 三种字符串技术对比

| 技术 | 复杂度 | 确定性 | 难度 | 适用 |
|------|:---:|:---:|:---:|------|
| 滚动哈希 | O(n) 期望 | ⚠️ 概率 | 低 | 子串比较/匹配/回文/重复 |
| KMP | O(n+m) | ✅ 确定 | 中 | 单模式匹配 |
| 后缀数组 | O(n log n) | ✅ 确定 | 高 | 全子串排序/LCP 家族 |

### 7.2 选型决策

```
单模式匹配 → KMP（确定）或 Rabin-Karp（简单）
多模式匹配 → Rabin-Karp + 哈希集合 / AC 自动机
大量子串比较 → 滚动哈希（O(1) 比较是杀手锏）
字符串全信息（LCP/排名）→ 后缀数组
⚠️ 面试表达：
"哈希的优势是'任意子串 O(1) 比较'——这是 KMP
 给不了的（KMP 只能匹配模式）；
 代价是概率性，用双哈希 + 验证兜底。"
```

## 8. 面试要点与追问

### 8.1 面试话术模板

```
"滚动哈希用多项式哈希：pre[i+1] = pre[i]·B + s[i]，
 任意子串哈希 = pre[r] - pre[l]·B^(r-l)（O(1)）。
 窗口滑动 O(1) 更新（减左乘 B 加右）。
 碰撞风险用【大模数/双哈希/验证】控制。
 复杂度 O(n)（比暴力 O(n·m) 优）。"
```

### 8.2 高频追问 TOP 8

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | 子串哈希怎么 O(1) 取？ | pre[r] - pre[l]·B^(r-l)（前缀哈希差分） |
| 2 | 窗口滑动公式？ | H' = (H - a·B^(m-1))·B + y |
| 3 | 碰撞怎么防？ | 大素数模 + 双哈希 + 碰撞回退验证 |
| 4 | 基怎么选？ | 大于字符集、质数（131/13331） |
| 5 | 生日悖论影响？ | 哈希比较数 k 时碰撞 ≈ k²/(2M)，海量比较需双哈希 |
| 6 | 与 KMP 区别？ | KMP 确定性单模式；哈希支持 O(1) 子串比较/多模式 |
| 7 | 二维怎么做？ | 双基多项式 + 二维前缀容斥 |
| 8 | 为什么 +M 再模？ | pre[r] - pre[l]·pow 可能为负（Java % 负数） |

### 8.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| 减法后直接取模 | 负哈希 | +M 再 %M |
| 基 ≤ 字符集大小 | 碰撞剧增 | 基 > 字符集（131） |
| pow 数组忘预处理 | 重复计算 | 预计算 B^k |
| 单哈希硬刚海量比较 | 碰撞 | 双哈希 |
| 乘法溢出 | 哈希错乱 | 控制模数/基的量级 |

---

> 🎯 **核心要点**：滚动哈希 = **前缀哈希 + O(1) 滑动**。三大武器：子串 O(1) 比较、窗口 O(1) 滚动、Rabin-Karp 匹配。防碰撞四层（大模数→双哈希→验证→确定性算法）；基选质数大于字符集、模选大素数、减法防负是三大细节。
