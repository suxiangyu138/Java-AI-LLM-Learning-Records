## 1. 核心概念

### 1.1 什么是最小生成树

> 最小生成树（MST）：无向连通图中，**连接所有节点**且**总边权最小**的树（n 个节点 n-1 条边）。

```
        1
    A-----B
    | \   |
  3 |  \4 | 2
    |   \ |
    C-----D
       5

MST：A-B(1) + B-D(2) + A-C(3) = 6（选 3 条边连 4 个节点）

应用：修路成本最小、网络布线、集群连接
⚠️ 前提：无向连通图；不连通 → 无 MST（有最小生成森林）
```

### 1.2 两种算法对比

| 算法 | 思路 | 数据结构 | 复杂度 | 适用 |
|------|------|:---:|:---:|------|
| **Kruskal** | 边排序 + 贪心选边 | 并查集 | O(E log E) | **稀疏图（推荐）** |
| Prim | 节点扩展 + 取最小边 | 堆/visited | O((V+E) log V) | 稠密图 |

```
Kruskal 核心：边按权重排序，从小到大加边
  ⚠️ 两端已连通 → 成环 → 跳过（并查集判环！）
  加到 n-1 条边 → 完成

Prim 核心：从一个节点出发，每次取"连接已选集合
  与未选集合"的最小边（类似 Dijkstra）
```

### 1.3 为什么"最小生成"而不是"最短路径"？

```
MST：连接**所有节点**的最小总代价（全局）
最短路：**两点之间**的最小代价（局部）
  → 算法完全不同：
    MST 用 Kruskal/Prim（贪心选边）
    最短路用 Dijkstra（贪心选点）

⚠️ 常见混淆：MST 不是所有节点两两最短
  （MST 保证总代价最小，不保证任意两点最短）
```

## 2. Kruskal 完整模板

### 2.1 标准实现（并查集判环）

```java
/**
 * Kruskal 模板（推荐）——并查集判环
 * 输入：n 节点，edges = [u, v, weight]
 */
public int kruskal(int n, int[][] edges) {
    // ① 按权重排序（贪心：先选最小边）
    Arrays.sort(edges, (a, b) -> a[2] - b[2]);

    UnionFind uf = new UnionFind(n);      // 并查集（见并查集专题）
    int totalWeight = 0, edgeCount = 0;

    // ② 依次取边
    for (int[] e : edges) {
        if (uf.connected(e[0], e[1])) {
            continue;                     // ⚠️ 已连通 → 成环 → 跳过
        }
        uf.union(e[0], e[1]);             // 合并两端
        totalWeight += e[2];
        if (++edgeCount == n - 1) break;  // n-1 条边完成
    }

    return edgeCount == n - 1 ? totalWeight : -1;   // -1 = 不连通
}
// 复杂度：O(E log E)（排序主导）+ 并查集 O(E α)
// 空间：O(V)（并查集）
```

### 2.2 推演：4 节点 5 条边

```
边（排序后）：A-B(1), B-D(2), A-C(3), A-D(4), C-D(5)

选 A-B(1)：两端不连通 → 合并，total=1
选 B-D(2)：不连通 → 合并，total=3
选 A-C(3)：不连通 → 合并，total=6（3 条边 = n-1 ✓）
选 A-D(4)：A、D 已连通 → ⚠️ 跳过（成环）
选 C-D(5)：C、D 已连通 → 跳过
MST = 6 ✓（与图中标注一致）
```

### 2.3 为什么"跳过已连通"就是贪心？

```
Kruskal 的贪心选择：每次取"不成环的最小边"
  为什么最小边安全？（切割性质，见第 4 节）
  为什么成环要跳过？
    n 个节点的树恰好 n-1 条边
    已成环 → 该边两端已有路径 → 加了破坏树的定义
    → 跳过不影响"连通所有节点"的目标

⚠️ 面试必答："并查集在这里的作用是 O(1) 判环"
```

## 3. Prim 完整模板

### 3.1 标准实现（堆优化，类似 Dijkstra）

```java
/**
 * Prim 模板（堆优化）——从节点扩展
 * 输入：graph 邻接表（List<List<int[]>>）
 */
public int prim(List<List<int[]>> graph, int n) {
    boolean[] inTree = new boolean[n];       // 已在生成树中
    // 最小堆：(节点, 到树的距离)
    PriorityQueue<int[]> pq =
        new PriorityQueue<>((a, b) -> a[1] - b[1]);
    pq.offer(new int[]{0, 0});               // 从节点 0 开始

    int total = 0, count = 0;
    while (!pq.isEmpty() && count < n) {
        int[] cur = pq.poll();
        int u = cur[0], w = cur[1];
        if (inTree[u]) continue;             // ⚠️ 已在树中 → 跳过

        inTree[u] = true;                    // 加入生成树
        total += w;
        count++;

        for (int[] e : graph.get(u)) {       // 松弛邻居
            if (!inTree[e[0]]) {
                pq.offer(new int[]{e[0], e[1]});   // 到树的距离
            }
        }
    }
    return count == n ? total : -1;
}
// 复杂度：O((V+E) log V)
// ⚠️ 与 Dijkstra 的区别：
//   Dijkstra：dist = 到起点的距离
//   Prim：dist = 到生成树（已选集合）的距离
```

### 3.2 Prim vs Dijkstra 对比

| 维度 | Prim | Dijkstra |
|------|:---:|:---:|
| 目标 | 最小生成树 | 最短路径 |
| dist 含义 | 到树的距离 | 到起点的距离 |
| 更新 | 只关心未入树节点 | 所有节点 |
| 结果 | n-1 条边 | dist 数组 |
| 代码 | 几乎相同 | 几乎相同 |

```
⚠️ 面试易混点：
  两者代码 90% 相同，区别只在
  "dist 更新时是否需要累加历史"
  Prim 直接记录边权；Dijkstra 累加 dist[u]+w
  讲清这个差异 = 展示理解深度
```

### 3.3 Kruskal vs Prim 选型

```
Kruskal 优势：
  稀疏图（E 小）→ 排序主导 O(E log E)
  实现直观（排序 + 并查集）
  适合"边集已给出"的输入

Prim 优势：
  稠密图（E≈n²）→ 节点主导
  适合"邻接矩阵/图已建好"的输入

面试默认 Kruskal（代码直白、并查集复用）
```

## 4. 贪心正确性证明

### 4.1 切割性质（Cut Property）

```
定理：任意切割（把节点分成两组），
  横跨切割的最小权重边必属于某个 MST。

证明（反证法）：
  假设 MST 不含最小横跨边 e
  沿 e 加回 MST → 形成环（e 两端已有路径）
  环上必有另一条横跨边 f（权 ≥ e）
  用 e 替换 f → 仍连通 + 总权不增
  → 存在含 e 的 MST ✓

Kruskal 的每次选择都是"某切割的最小横跨边"
  → 每次选择都安全 → 最终得到 MST
```

### 4.2 归纳证明（Kruskal 完整）

```
归纳假设：前 k 步选出的边集是"某个 MST 的子集"
基础：k=0 空集显然成立
递推：第 k+1 步选边 e（最小不成环边）
  e 连接的两个连通分量构成一个切割
  且 e 是横跨该切割的最小边（排序保证）
  → 由切割性质，e 属于某个含当前边集的 MST
  → 归纳成立

面试话术（简化版）：
"每次选最小且不成环的边——它是某个
 切割的最小横跨边，切割性质保证它在
 某个 MST 中，所以贪心选择安全。"
```

### 4.3 为什么总权最小？

```
Kruskal 与 Prim 都基于切割性质
  → 每一步的选择都在"某个 MST 中"
  → 最终边集 = 一个 MST → 总权最小

⚠️ 唯一性问题：
  边权全不同 → MST 唯一
  有权重相同的边 → MST 可能不唯一
  （但总权一定相同）
```

### 1584 建边技巧

```java
// 点坐标 → 两两建边（曼哈顿距离）
// ⚠️ 需要全部两两建边：O(n²) 条边
public int minCostConnectPoints(int[][] points) {
    int n = points.length;
    List<int[]> edges = new ArrayList<>();
    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n; j++) {
            int dist = Math.abs(points[i][0] - points[j][0])
                     + Math.abs(points[i][1] - points[j][1]);
            edges.add(new int[]{i, j, dist});
        }
    }
    // 然后标准 Kruskal
}
```

## 6. 面试要点与追问

### 6.1 面试话术模板

```
"最小生成树用 Kruskal：
 ① 边按权重排序（贪心先选小边）；
 ② 并查集判环——两端已连通说明成环，跳过；
 ③ 加到 n-1 条边完成。
 贪心正确性由切割性质保证：
 每次选的都是某切割的最小横跨边。
 O(E log E)（排序主导）。
 稠密图可以改用 Prim（O((V+E) log V)）。"
```

### 6.2 高频追问 TOP 8

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | 为什么并查集判环？ | 树 n-1 条边；已连通说明两端已有路径 → 成环 |
| 2 | 切割性质是什么？ | 任何切割的最小横跨边必在某个 MST 中（反证法证明） |
| 3 | Kruskal vs Prim？ | 稀疏 Kruskal（排序主导）；稠密 Prim（节点主导） |
| 4 | Prim 与 Dijkstra 区别？ | dist 含义不同：到树 vs 到起点；更新方式不同 |
| 5 | 不连通怎么办？ | 无 MST → 返回 -1（或最小生成森林） |
| 6 | MST 唯一吗？ | 边权全不同才唯一；有相同权重可能多解（总权相同） |
| 7 | 最大生成树？ | 排序倒序即可（同样并查集） |
| 8 | 虚拟节点技巧？ | 1168 水井：加 0 节点连所有点（成本=挖井费） |

### 6.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| 忘判断已连通 | 成环边加入 | union 前 connected 检查 |
| 边界写错 | 少算/多算 | n-1 条边即停 |
| 比较器溢出 | 排序错误 | Integer.compare |
| 无向忘双向 | 图不完整 | addEdge 两条 |
| 与最短路混淆 | 算法选错 | MST 选边，最短路选点 |

> 🎯 **核心要点**：Kruskal = **边排序 + 并查集判环 + n-1 条边**；Prim = **堆 + 类 Dijkstra 扩展**。识别信号："连接所有节点的最小代价、铺设/布线成本"。切割性质（贪心正确性）与虚拟节点建边（1168）是两大加分点。
