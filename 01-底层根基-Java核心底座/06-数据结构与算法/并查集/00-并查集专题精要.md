## 1. 核心概念

### 1.1 什么是并查集

> 并查集（Union-Find / Disjoint Set）：维护**元素分属哪些集合**的数据结构，支持两种操作——**合并**两个集合、**查询**两个元素是否同集合。时间复杂度近似 O(1)（反阿克曼函数）。

```
场景：判断两点是否连通、统计连通分量数、动态加边
类比：朋友圈——"A 和 B 是朋友、B 和 C 是朋友" → A、C 同圈

核心操作：
  find(x)：找到 x 所在集合的代表（根节点）
  union(x, y)：合并 x、y 所在集合
  connected(x, y)：find(x) == find(y)
```

### 1.2 核心原理

```
树形结构：每个集合是一棵树，根节点代表集合

  集合 {1,2,3}：  parent[2]=1, parent[3]=1, parent[1]=1
                 1（根）
                / \
               2   3

  合并：把一棵树的根挂到另一棵树根下
  union(2, 5) → parent[find(2)] = find(5)
              → parent[1] = 5 → 1 的根变成 5

  查询：向上找根，比较根是否相同
  find(2)：2 → 1 → 5（根）

两大优化（缺一不可）：
  ① 路径压缩：find 时把路径上所有节点直接挂到根
     → 后续 find O(1)（树高压成 1-2）
  ② 按秩合并：矮树挂到高树下（避免树退化）
     → 合并 O(log n)（无压缩时）
  两者结合 → 操作近似 O(1)
```

### 1.3 何时用并查集

```
① 动态连通性：边不断加入，随时查询连通
   （305 岛屿数量 II：只有并查集能在线处理）
② 连通分量计数：合并后统计根的数量
   （547 省份数量）
③ Kruskal 最小生成树：判环（两端已连通 → 成环）
④ 等价关系分组：同组元素等价传递（721 账户合并）

⚠️ 静态连通（已知全部边）→ DFS/BFS 更简单
   动态连通（边增量加入）→ 并查集
```

## 2. 完整代码模板

### 2.1 标准模板（路径压缩 + 按秩合并）

```java
/**
 * 并查集标准模板（面试主推）
 * 复杂度：近似 O(1) 每次操作
 */
class UnionFind {
    private int[] parent;
    private int[] rank;          // 树的高度（按秩合并）
    private int count;           // 连通分量数

    public UnionFind(int n) {
        parent = new int[n];
        rank = new int[n];
        count = n;               // 初始每个元素独立
        for (int i = 0; i < n; i++) parent[i] = i;
    }

    // 查询根 + 路径压缩（递归版，简洁）
    public int find(int x) {
        if (parent[x] != x) {
            parent[x] = find(parent[x]);     // 沿途直接挂根
        }
        return parent[x];
    }

    // 合并（按秩：矮树挂高树）
    public void union(int x, int y) {
        int rx = find(x), ry = find(y);
        if (rx == ry) return;                // 已同集合
        if (rank[rx] < rank[ry]) {
            parent[rx] = ry;
        } else if (rank[rx] > rank[ry]) {
            parent[ry] = rx;
        } else {
            parent[ry] = rx;                 // 同高：任选，高度+1
            rank[rx]++;
        }
        count--;                             // 分量数-1
    }

    public boolean connected(int x, int y) {
        return find(x) == find(y);
    }

    public int count() { return count; }
}
```

### 2.2 迭代版 find（防栈溢出）

```java
/**
 * 迭代版 find：两遍（找根 + 压缩）
 * 适用于数据量极大/递归深度可能超限的场景
 */
public int find_Iterative(int x) {
    // ① 第一遍：向上找根
    int root = x;
    while (parent[root] != root) {
        root = parent[root];
    }

    // ② 第二遍：路径压缩（沿途节点直接挂根）
    while (parent[x] != x) {
        int next = parent[x];
        parent[x] = root;
        x = next;
    }
    return root;
}
// 面试表达："递归版简洁；迭代版两遍处理，
// 数据量极大时更安全（无栈溢出）"
```

## 3. 复杂度严格分析

### 3.1 各阶段复杂度

```
无优化：find O(n)（最坏链状）、union O(n)
按秩合并：树高 ≤ log n → find O(log n)
路径压缩：均摊 O(α(n)) ≈ O(1)
两者结合：均摊 O(α(n))（反阿克曼函数）

α(n) 的实际值：
  n = 2^65536 时 α(n) 才达到 5
  → 实际可视为常数 O(1)

均摊论证（为什么压缩后快）：
  每个节点最多被压缩一次（挂到根后不再移动）
  总压缩代价 O(n log n) → 均摊 O(log n)
  加强论证 → O(α(n))
```

### 3.2 空间复杂度

```
O(n)：parent 数组 + rank 数组
优化：rank 可用"集合大小"代替（按大小合并）
  或省略 rank（仅路径压缩，仍接近 O(log n)）
```

### 3.3 复杂度面试话术

```
"并查集两个优化：路径压缩（find 时把路径上
 节点直接挂根）和按秩合并（矮树挂高树）。
 两者结合后每次操作均摊 O(α(n))——
 α 是反阿克曼函数，增长极慢，
 实际可视为常数 O(1)。
 空间 O(n)。"
```

### 4.2 场景二：等价分组（721 账户合并）

```
建模：邮箱 = 节点？账户 = 节点？
  正确：账户 = 节点（union 的是账户）
  邮箱 = 建立关系的"桥"（同邮箱 → 账户 union）

关键：先想清楚"什么作为节点"
  "实体之间需要'等价' → 实体是节点"
```

### 4.3 场景三：Kruskal 判环

```
Kruskal 最小生成树：
  边按权重排序 → 依次取边
  ⚠️ 两端已连通 → 成环 → 跳过
  并查集 connected 恰好 O(1) 判环

（详见最小生成树专题）
```

### 4.4 场景四：等式验证（990）

```
"先等后不等"两遍处理：
  ① 所有等式 union（建立等价关系）
  ② 验证不等式（两端已连通 → 矛盾）
  ⚠️ 必须"先全部合并再验证"
    （关系有传递性：a==b, b==c → a==c）
```

## 6. 面试要点与追问

### 6.1 面试话术模板

```
"这题是动态连通性问题，用并查集：
 ① 建模：节点是【...】，合并条件是【...】；
 ② find：路径压缩（沿途挂根）；
 ③ union：按秩合并（矮挂高）+ count 维护；
 ④ 复杂度：近似 O(1) 每次（反阿克曼函数）。
 为什么不用 DFS？因为【动态加边/在线查询】，
 DFS 每次要全图扫描。"
```

### 6.2 高频追问 TOP 8

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | 为什么近似 O(1)？ | 路径压缩把树高压成 1-2，find 常数级；严格均摊 O(α(n))，α 增长极慢 |
| 2 | 路径压缩 vs 按秩合并？ | 压缩管查询（压树高），按秩管合并（防退化）；两者结合最优 |
| 3 | 递归 find 的栈溢出？ | 压缩后树高很小，实际无风险；极端场景用迭代两遍版 |
| 4 | 什么时候比 DFS 好？ | 动态加边（在线处理）；静态图 DFS 更简单 |
| 5 | 怎么统计分量数？ | union 成功 count--（O(1)）；或数 find(i)==i 的个数 |
| 6 | 二维网格怎么用？ | 映射一维：id = i*n + j |
| 7 | 带权并查集是什么？ | 额外维护"节点到根的倍率/差值"，find 时累乘/累加（399） |
| 8 | 并查集能删除吗？ | 不能直接删 → 倒序技巧（删除反转成添加） |

### 6.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| find 忘路径压缩 | 树退化 O(n) | parent[x] = find(parent[x]) |
| union 忘判同根 | 误减 count | if (rx == ry) return |
| 二维忘映射 | 下标越界 | id = i * n + j |
| 静态图也用并查集 | 代码冗长 | 静态 → DFS/BFS |
| 990 边处理边验证 | 传递关系漏判 | 先全部合并再验证 |

> 🎯 **核心要点**：并查集 = **find（路径压缩）+ union（按秩合并）+ count（分量维护）**。识别信号："动态连通/分量计数/等价分组"。复杂度论证（α(n)≈O(1)）与建模（节点=什么）是面试两大得分点。
