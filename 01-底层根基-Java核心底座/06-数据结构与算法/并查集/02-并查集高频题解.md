## 1. 684. 冗余连接（加边判环）

### 1.1 完整实现

```java
/**
 * LeetCode 684. 冗余连接
 * 无向图有 n 条边（树只有 n-1 条）→ 恰好一条多余边
 * 删除它使图成为树。返回该边。
 *
 * 并查集判环：加边前检查两端是否已连通
 *   已连通 → 这条边形成环 → 是冗余边
 */
public int[] findRedundantConnection(int[][] edges) {
    int n = edges.length;
    UnionFind uf = new UnionFind(n + 1);   // 1-indexed

    for (int[] edge : edges) {
        int u = edge[0], v = edge[1];
        if (uf.connected(u, v)) {
            return edge;                   // ⚠️ 已连通 → 成环 → 冗余
        }
        uf.union(u, v);
    }
    return new int[0];
}
// 例：[[1,2],[1,3],[2,3]]
// 加 [1,2]、[1,3] 都正常；加 [2,3] 时 2、3 已连通 → 返回 [2,3] ✓
```

### 1.2 为什么"已连通"就是冗余？

```
树的性质：n 个节点 n-1 条边且连通
  已有 n-1 条边连通了所有节点
  第 n 条边的两端必然已连通（否则节点数不对）
  → "已连通" ⇔ 形成环 ⇔ 冗余

⚠️ 变体：685. 冗余连接 II（有向图）
  需要先处理"入度为 2"的情况，更复杂
```

## 2. 721. 账户合并（等价分组）

### 2.1 完整实现

```java
/**
 * LeetCode 721. 账户合并
 * 每个账户有姓名和邮箱列表，相同邮箱属于同一人
 * 合并所有属于同一人的账户
 *
 * 建模：邮箱 = 节点，同账户邮箱 union
 *   ① 邮箱 → 所属账户索引（map）
 *   ② 同账户邮箱全部 union（合并到第一个邮箱）
 *   ③ 按根分组收集邮箱
 */
public List<List<String>> accountsMerge(List<List<String>> accounts) {
    // ① 邮箱 → 账户索引（首次出现）
    Map<String, Integer> emailToId = new HashMap<>();
    UnionFind uf = new UnionFind(accounts.size());

    for (int i = 0; i < accounts.size(); i++) {
        for (int j = 1; j < accounts.get(i).size(); j++) {
            String email = accounts.get(i).get(j);
            if (emailToId.containsKey(email)) {
                // ⚠️ 邮箱已属于其他账户 → 合并两个账户
                uf.union(i, emailToId.get(email));
            } else {
                emailToId.put(email, i);
            }
        }
    }

    // ② 按根分组邮箱
    Map<Integer, TreeSet<String>> groups = new HashMap<>();
    for (var e : emailToId.entrySet()) {
        int root = uf.find(e.getValue());
        groups.computeIfAbsent(root, k -> new TreeSet<>()).add(e.getKey());
    }

    // ③ 组装结果（姓名 + 排序后的邮箱）
    List<List<String>> result = new ArrayList<>();
    for (var g : groups.entrySet()) {
        List<String> account = new ArrayList<>();
        account.add(accounts.get(g.getKey()).get(0));  // 姓名
        account.addAll(g.getValue());                  // 邮箱（TreeSet 有序）
        result.add(account);
    }
    return result;
}
// 关键：union 的是"账户索引"，邮箱只是建立关系的桥梁
```

### 2.2 建模思维

```
核心洞察：把"实体"换成"等价关系的载体"
  邮箱相同 → 账户等价 → 账户 union
  （不像普通并查集 union 元素本身）

⚠️ 用 TreeSet 收集邮箱 → 自动排序（题目要求）
```

## 3. 990. 等式方程的可满足性

### 3.1 完整实现

```java
/**
 * LeetCode 990. 等式方程的可满足性
 * 等式 "a==b" 和不等式 "a!=b"，判断是否可同时满足
 *
 * 两遍处理：
 *   ① 先处理所有等式 → union（合并等价变量）
 *   ② 再验证不等式 → 两端已连通 → 矛盾
 */
public boolean equationsPossible(String[] equations) {
    UnionFind uf = new UnionFind(26);       // 26 个字母

    // ① 等式先合并
    for (String eq : equations) {
        if (eq.charAt(1) == '=') {          // "a==b"
            uf.union(eq.charAt(0) - 'a', eq.charAt(3) - 'a');
        }
    }

    // ② 不等式验证
    for (String eq : equations) {
        if (eq.charAt(1) == '!') {          // "a!=b"
            if (uf.connected(eq.charAt(0) - 'a', eq.charAt(3) - 'a')) {
                return false;               // ⚠️ 相等关系要求不等 → 矛盾
            }
        }
    }
    return true;
}
// ["a==b","b!=a"] → a、b 已 union，但 b!=a 要求不连通 → false ✓
```

### 3.2 两遍处理的顺序

```
为什么等式必须"先全部处理"再验证不等式？
  关系传递：a==b, b==c → a==c
  若边处理边验证：验证 a!=c 时 a、c 还未合并
  → 误判为可满足
  → 先建立全部等价关系，再统一验证

记忆："先等后不等"（先 union 再检查）
```

## 4. 128. 最长连续序列（Set 并查集）

### 4.1 并查集版实现

```java
/**
 * LeetCode 128. 最长连续序列
 * 两种解法：Set 起点剪枝（标准）或并查集
 * 并查集版：相邻元素 union，统计最大集合大小
 */
public int longestConsecutive(int[] nums) {
    Map<Integer, Integer> parent = new HashMap<>();   // 值 → 父
    Map<Integer, Integer> size = new HashMap<>();     // 根 → 集合大小
    Set<Integer> set = new HashSet<>();
    for (int x : nums) {
        parent.put(x, x);
        size.put(x, 1);
        set.add(x);
    }

    int maxSize = 0;
    for (int x : set) {
        // 与相邻元素合并（x-1 和 x+1 都存在时）
        if (set.contains(x - 1)) union(parent, size, x, x - 1);
        if (set.contains(x + 1)) union(parent, size, x, x + 1);
    }

    for (int s : size.values()) maxSize = Math.max(maxSize, s);
    return maxSize;
}
// ⚠️ 并查集需要"离散化"：值域大 → 用 HashMap 而非数组
// 标准解法仍是 Set 起点剪枝（更简洁），并查集展示替代方案
```

### 4.2 两种解法对比

| 维度 | Set 起点剪枝 | 并查集 |
|------|:---:|:---:|
| 思路 | 只从序列起点统计 | 相邻合并计大小 |
| 代码 | 更简洁（推荐） | 需要离散化 |
| 复杂度 | O(n) | O(n×α) |
| 面试选 | **标准答案** | 展示知识广度 |

## 5. 547. 省份数量（分量计数）

### 5.1 完整实现

```java
/**
 * LeetCode 547. 省份数量（连通分量计数）
 * isConnected[i][j]=1 表示 i、j 直接相连
 * 求连通分量数（省份数）
 *
 * 并查集：所有相连的城市 union → count
 */
public int findCircleNum(int[][] isConnected) {
    int n = isConnected.length;
    UnionFind uf = new UnionFind(n);

    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n; j++) {     // ⚠️ 只扫上三角
            if (isConnected[i][j] == 1) {
                uf.union(i, j);
            }
        }
    }
    return uf.count();                        // 剩余分量数
}
// 并查集 count 初始 n，每次 union 成功减 1

// DFS 版（面试备用）：visited 数组 + 遍历每行
// public int findCircleNum_DFS(int[][] isConnected) { ... }
// 每发现未访问城市 → count++ → DFS 标记整省
```

### 5.2 分量计数的两种方式

```
方式一：uf.count()（union 成功减 1）
方式二：遍历所有 find(i) == i 的数量（根的数量）
两者等价，方式一更高效（O(α) 维护）
```

## 6. 题解方法论总结

### 6.1 五题模式总结

| 题号 | 模式 | 关键洞察 |
|:---:|------|------|
| 684 | 加边判环 | 已连通 → 成环 → 冗余 |
| 721 | 等价分组 | 邮箱为桥，union 账户 |
| 990 | 先等后不等 | 先建关系再验证 |
| 128 | 离散化并查集 | 值域大用 HashMap |
| 547 | 分量计数 | union 成功 count-- |

### 6.2 并查集题识别清单

```
① 动态加边/在线连通 → 并查集（305/684）
② 等价关系传递 → 并查集（721/990）
③ 连通分量统计 → 并查集/DFS（547）
④ 比值/差值关系 → 带权并查集（399）
⑤ 删除操作统计 → 倒序并查集（1970）

⚠️ 静态全量图 → DFS/BFS 更简单
   动态/增量 → 并查集
```

### 6.3 面试话术

```
"这题是动态连通性问题：
 ① 识别：边/关系不断加入，随时查询连通或分量
 ② 建模：什么作为节点？什么触发 union？
 ③ 模板：find（路径压缩）+ union（按秩合并）
 ④ 复杂度：近似 O(1) 每次操作（反阿克曼函数）
 ⑤ 变体：带权（比值）/倒序（删除反转）"
```
