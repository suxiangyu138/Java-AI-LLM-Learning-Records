## 1. 排序算法大对比

| 算法 | 平均 | 最坏 | 空间 | 稳定 | 特点 |
|------|:---:|:---:|:---:|:---:|------|
| 快速排序 | O(n log n) | O(n²) | O(log n) | ❌ | 原地、缓存友好 |
| 归并排序 | O(n log n) | O(n log n) | O(n) | ✅ | 稳定、外部排序 |
| 堆排序 | O(n log n) | O(n log n) | O(1) | ❌ | 原地但缓存差 |
| 插入排序 | O(n²) | O(n²) | O(1) | ✅ | **小数组最优** |
| 桶/计数排序 | O(n+k) | O(n+k) | O(k) | 可 | 值域小才用 |
| 基数排序 | O(d(n+k)) | 同 | O(n+k) | ✅ | 定长键 |

### 1.1 工程真相（JDK 视角）

```text
Arrays.sort(基本类型) → 双轴快排（DualPivotQuickSort）
Arrays.sort(对象)    → TimSort（归并 + 插入混合，稳定）
Arrays.sort(小数组)  → 插入排序（≤ 47 时，常数最优）
⚠️ 面试答「快排最好」要补一句：工程里小数组用插入、对象用归并系
```

> 🎯 一句话分法：**要稳定 → 归并/TimSort；要原地省空间 → 快排/堆排；小数组 → 插入**。快排最坏 O(n²) 而平均快，就是它「不稳定」的真相。

### 1.2 快排 vs 归并 vs 堆排（面试三问）

| 问题 | 答案 |
|------|------|
| 为什么快排平均最快？ | 缓存局部性 + 常数小（原地交换） |
| 为什么归并稳定？ | 合并时左先右后，相等元素不动 |
| 为什么堆排常数大？ | 跳跃式访问内存，缓存命中差 |

### 1.3 排序稳定性的意义（追问）

```text
稳定性 = 相等元素排序后相对顺序不变
意义：多关键字排序需要稳定——先按次关键字排，再按主关键字排
示例：先按分数排序，再按学号排序 → 学号相同段内仍按分数有序
不稳定排序（快排）第二次排序会破坏第一次的结果
```

## 2. HashMap 家族版本对比

| 维度 | JDK 7 | JDK 8+ |
|------|------|------|
| 结构 | 数组 + 链表 | 数组 + 链表 + **红黑树** |
| 链表转树阈值 | — | ≥ 8 且容量 ≥ 64 |
| 树退链表 | — | 树节点 ≤ 6 |
| 头插/尾插 | 头插（并发死链） | **尾插** |
| 扩容 | 全部 rehash | 高低位拆分（高效） |
| 初始化容量 | 需 2 的幂 | 同（tabSizeFor） |
| 懒加载 | — | **首次 put 才建表** |

### 2.1 高频追问答案

| 追问 | 标准答案 |
|------|------|
| 为什么阈值是 8？ | 泊松分布：负载 0.75 下链表长 8 概率 < 千万分之一 |
| 为什么容量是 2 的幂？ | `(n-1) & hash` 代替取模，且扩容时高低位直接拆分 |
| 为什么树化要容量 ≥ 64？ | 避免哈希整体失效时大链表反复树化/退化 |
| null 键去哪？ | putForNullKey → 下标 0 |
| 线程安全吗？ | 否——并发用 ConcurrentHashMap |

> ⚠️ 面试陷阱：**JDK 8 的 HashMap 仍有线程安全问题**（只是没死链了），不是「并发安全」；并发必须 ConcurrentHashMap。

### 2.2 为什么 8 是阈值：泊松分布的简化推导

```text
假设负载因子 0.75、哈希均匀分布：
桶内元素个数 ~ Poisson(0.5)（期望 = 0.75 × 桶平均装载）
P(链长 ≥ 8) ≈ 千万分之一量级 → 若真到 8，说明哈希严重劣化
→ 用红黑树 O(log n) 兜底，代价是树节点内存更大（约 2 倍）
阈值 6 退链表：留 2 的差值防止「频繁插入删除」在 7/8 间抖动
```

## 3. O(log n) 四兄弟

| 结构 | 操作 | 底层 | 场景 |
|------|------|------|------|
| 二分查找 | 查询 O(log n) | 有序数组 | 静态数据 |
| 平衡树 | 查插删 O(log n) | 二叉搜索 | 动态有序 |
| 二叉堆 | 查极值 O(1)、插删 O(log n) | 完全二叉树数组 | TopK |
| 倍增/稀疏表 | 区间最值 O(1) | 预处理表 | 静态区间 |

### 3.1 为什么都是 O(log n) 但常数不同

| 结构 | 每次操作代价 | 常数因子 |
|------|------|:---:|
| 二分 | 数组访问 | 极小 |
| 平衡树 | 指针跳转 + 旋转 | 中 |
| 堆 | 数组上下浮 | 中 |
| 稀疏表 | 数组访问（预计算） | 极小但预处理 O(n log n) |

> 🎯 记忆锚点：**O(log n) 只是「层级数」，常数看「每层做什么」**——面试说「都是 O(log n)」后补一句常数差异，立刻显深度。

### 3.2 堆 vs 平衡树的选择（追问）

```text
只要极值：堆（O(1) 取顶，插入 O(log n)）
还要第 k 大 / 范围查询：平衡树（O(log n) 任意值）
还要删任意元素：平衡树（堆删任意元素 O(n) 定位）
结论：堆是「极值专用」，平衡树是「全能有序」
```

## 4. 空间换时间家族对比

| 技巧 | 空间 | 换到 | 场景 |
|------|:---:|------|------|
| 哈希表 | O(n) | 查询 O(1) | 两数之和、判重 |
| 计数数组/桶 | O(值域) | 排序 O(n+k) | 值域小排序、频次 |
| 前缀和 | O(n) | 区间和 O(1) | 多次区间查询 |
| 稀疏表 | O(n log n) | 区间最值 O(1) | 静态 RMQ |
| 记忆化 | O(状态数) | 重复子问题 O(1) | DP、搜索 |
| 位图/BitSet | O(值域/64) | 判重/计数压缩 | 海量去重 |

### 4.1 空间开销的「反直觉」案例

| 案例 | 直觉 | 实际 |
|------|------|------|
| 哈希表内存 | 只存数据 | 负载因子 0.75 → 实际约 1.33 倍 + 节点对象头 |
| 稀疏表 | 比数组大 | 2 倍 n 的表 × log n 层 → O(n log n) |
| 位图 | 每个元素 1 位 | 10⁹ 范围 = 125 MB → 比 HashSet 省 40 倍 |
| 递归栈 | 忽略 | 深度 10⁵ 即爆默认栈（约 1MB） |

## 5. 复杂度分析高频误判

| 误判 | 真相 |
|------|------|
| 嵌套循环必是 O(n²) | 内层 if 提前 break / 均摊（单调栈每个元素进出一次） |
| 递归必指数级 | 记忆化后变多项式（DP） |
| 排序必 O(n log n) | 值域小 → 计数 O(n+k)；已近有序 → 插入 O(n) |
| 图算法看 V 不看 E | 稀疏图 O(E) ≈ O(V)，稠密图 O(E) ≈ O(V²) |
| 二分前提是有序数组 | 答案本身单调也可以二分答案（检查函数） |
| HashSet 查询 O(1) | 最坏冲突 O(n)；Java 8 后链表长 8 转树 O(log n) |
| 常数可以忽略 | 10⁷ 的 O(n) 配大常数（对象装箱）可能 TLE |

### 5.1 误判修正示例

| 场景 | 常见误判 | 正确 |
|------|------|------|
| 双指针两层循环 | O(n²) | O(n)——指针单调移动 |
| 记忆化斐波那契 | O(2ⁿ) | O(n) |
| 邻接矩阵遍历图 | O(V²) 恒成立 | 是的（矩阵本身就是 V²） |
| 每次查 HashMap | O(n log n) | O(n) 均摊 |
| 字符串循环 + | O(n) | O(n²)（每次拼接复制） |

## 6. 均摊分析速记（最容易被问）

| 场景 | 均摊复杂度 | 原理 |
|------|:---:|------|
| ArrayList add | O(1) | 扩容倍增，搬移代价摊薄 |
| StringBuilder append | O(1) | 同扩容倍增 |
| HashMap put | O(1) | 扩容偶尔发生 |
| 单调栈整体 | O(n) | 每元素入栈出栈各一次 |
| splay 树操作 | O(log n) | 摊还分析经典 |

### 6.1 均摊 vs 平均 vs 最坏的区分（面试基础题）

```text
平均：对随机输入取期望（如快排平均 O(n log n)）
最坏：对最差输入（如快排 O(n²)）
均摊：对【一个数据结构上连续操作序列】的总代价取平均
      （如 ArrayList 连续 n 次 add 总 O(n) → 单次均摊 O(1)）
⚠️ 三者独立：均摊 O(1) 不代表单次没有 O(n) 的时刻（扩容那次）
```

> 🎯 **核心要点**：实现对比的规律——**同一个复杂度，工程实现永远优先「常数小 + 内存少 + 并发安全」**（TimSort、尾插、懒加载都是这个逻辑）。复杂度误判的共同根源是**只看最内层循环、忽略均摊与前置条件**。记住「误判表」七行 + 均摊/平均/最坏三语义，复杂度分析题基本不失分。
