## 1. 线性表对比

### 1.1 ArrayList vs LinkedList

| 维度 | ArrayList | LinkedList |
|------|------|------|
| 底层 | 动态数组 | 双向链表 |
| 随机访问 | **O(1)** | O(n) |
| 头部插入/删除 | O(n)（搬移） | **O(1)** |
| 尾部插入 | **O(1) 摊还** | O(1) |
| 内存 | 连续（缓存友好） | 离散 + 指针开销 |
| 中间插入 | O(n) | O(n)（查找 O(n) + 插入 O(1)） |

> 🎯 一句话分法：**随机访问选 ArrayList，大量头部操作选 LinkedList**——注意「中间插入」两者都是 O(n)，LinkedList 的优势只在头部/尾部明确位置。

### 1.2 数组 vs 链表（算法视角）

| 维度 | 数组 | 链表 |
|------|------|------|
| 缓存局部性 | 高（连续） | 低（离散） |
| 扩容 | 搬移 O(n) | 无 |
| 反向遍历 | 容易 | 双向链才能 |
| 删除已知节点 | O(n)（搬移） | O(1)（改指针） |
| 适用 | 下标运算、前缀和、二分 | 频繁删插、环检测 |

### 1.3 面试追问：LinkedList 真的适合「频繁中间插入」吗

```text
追问：LinkedList 中间插入 O(1)？
答案：不是！插入本身 O(1)，但【找到插入位置】是 O(n)。
      LinkedList 的 O(1) 优势只在「持有前驱节点指针」时成立
      （如迭代器插入）。
结论：工程上绝大多数「插入多」场景其实用 ArrayList 或
      双端 Deque，LinkedList 是 JDK 中最常被误用的结构之一。
```

## 2. 哈希家族对比

### 2.1 HashMap vs HashSet vs Hashtable

| 维度 | HashMap | HashSet | Hashtable |
|------|------|------|------|
| 存储 | 键值对 | 键集合（内部用 HashMap） | 键值对（线程安全） |
| null | 键值都允许（各 1 个） | 允许 1 个 null | 不允许 |
| 线程安全 | 否 | 否 | 是（synchronized） |
| 复杂度 | O(1) 均摊 | O(1) 均摊 | O(1) 均摊（有锁开销） |

### 2.2 HashMap vs TreeMap vs LinkedHashMap

| 维度 | HashMap | TreeMap | LinkedHashMap |
|------|------|------|------|
| 顺序 | 无序 | **按键排序**（红黑树） | 插入序 / 访问序 |
| 复杂度 | O(1) 均摊 | O(log n) | O(1) 均摊 |
| 适用 | 通用查询 | 需要有序遍历、范围查询 | LRU 缓存（accessOrder） |
| 底层 | 哈希表 | 红黑树 | 哈希表 + 双向链表 |

> 🎯 选型三问：**需要有序吗？** 要 → TreeMap（排序）或 LinkedHashMap（插入序）；**要最值吗？** 要 → 优先队列；否则 HashMap。

### 2.3 哈希 vs 树形集合（HashSet vs TreeSet 同理）

| 维度 | 哈希 | 平衡树 |
|------|------|------|
| 查询 | O(1) 均摊 | O(log n) |
| 有序性 | 无 | 有 |
| 范围查询 | 不支持 | `subSet/headSet` 支持 |
| 工程例子 | HashSet/HashMap | TreeSet/TreeMap |

### 2.4 面试追问：为什么 HashMap 不保证顺序

```text
哈希表基于「桶数组 + 哈希散列」，桶下标由 hash 决定，
扩容（resize）后桶下标全部变化 → 顺序不可预期。
LinkedHashMap 额外用双向链表记录插入/访问序解决此问题。
JDK 21 起：LinkedHashMap 实现 SequencedMap，有 firstEntry() 等统一 API。
```

## 3. 栈、队列与双端队列对比

| 维度 | 栈 Stack | 队列 Queue | Deque 双端 |
|------|------|------|------|
| 原则 | LIFO | FIFO | 双端可入可出 |
| 核心操作 | push/pop/peek | offer/poll/peek | addFirst/addLast |
| O(1) | 顶进出 | 头出尾进 | 两端进出 |
| 典型场景 | 括号、递归、单调栈 | BFS、任务队列 | 滑动窗口单调队列 |

### 3.1 三问区分（面试标准答法）

| # | 问题 | 答案 |
|:---:|------|------|
| 1 | 处理顺序是什么？ | 后进先出 = 栈；先进先出 = 队列 |
| 2 | 需要两端操作吗？ | 需要 → Deque（滑动窗口） |
| 3 | 有单调性维护吗？ | 单调栈/单调队列 = 各自 + 有序性维护 |

### 3.2 单调栈 vs 单调队列

| 维度 | 单调栈 | 单调队列 |
|------|------|------|
| 结构 | 单端 | 双端 |
| 维护 | 栈内单调（增/减） | 队内单调 + **过期淘汰** |
| 场景 | 下一个更大/更小元素 | 滑动窗口最值、DP 优化 |
| 复杂度 | 每个元素入栈出栈各一次 O(n) | 同 O(n) |

### 3.3 工程选型注意

| 需求 | 正确选择 | 常见错误 |
|------|------|------|
| Java 里用栈 | `ArrayDeque` | `Stack`（Vector 遗留，方法同步） |
| Java 里用队列 | `ArrayDeque` / `LinkedList` | 直接用 `Stack` |
| 需要双端 | `ArrayDeque` | `LinkedList`（慢） |

## 4. 树形结构对比

### 4.1 BST vs 堆 vs 优先队列

| 维度 | BST（平衡） | 堆 | PriorityQueue |
|------|------|------|------|
| 有序性 | **全序**（中序有序） | 部分序（父子） | 同堆 |
| 查询任意值 | O(log n) | O(n) | O(n) |
| 极值 | 最左/最右 O(log n) | 堆顶 **O(1)** | 队首 O(1) |
| 唯一场景 | 第 k 小、范围查询 | 动态 TopK、堆排序 | 合并有序流 |

> 🎯 一句话分法：**要「搜索」用 BST，要「极值」用堆**。堆永远只关心最大/最小，BST 关心「任意值在哪」。

### 4.2 AVL vs 红黑树

| 维度 | AVL | 红黑树 |
|------|------|------|
| 平衡度 | 严格（高度差 ≤ 1） | 松弛（最长 2 倍最短） |
| 查询 | 更快（更矮） | 略慢 |
| 插入删除 | 旋转更多 | 旋转更少（O(1) 摊销） |
| 工程使用 | 只读多/查多 | **插入删除频繁**（JDK TreeMap、STL map） |

### 4.3 满二叉树 / 完全二叉树 / 平衡二叉树

| 类型 | 定义 | 性质 |
|------|------|------|
| 满二叉树 | 所有层满 | 节点数 2ʰ-1 |
| 完全二叉树 | 除末层外全满，末层靠左 | **堆的实现基础**（数组下标定位） |
| 平衡二叉树 | 任一节点左右高度差 ≤ 1 | AVL、红黑树统称 |

### 4.4 面试追问：为什么堆用数组而 BST 用指针

```text
完全二叉树性质：第 i 个节点的孩子是 2i+1 与 2i+2（0 基）
→ 数组天然定位父子，无需指针 → 省内存、缓存友好
BST 不一定是完全二叉树 → 必须指针/节点表示
结论：堆的「宽松有序」换来了「紧凑存储」
```

## 5. String 家族对比

| 维度 | String | StringBuilder | StringBuffer |
|------|------|------|------|
| 可变 | 不可变 | 可变 | 可变 |
| 线程安全 | 是（不可变即安全） | 否 | 是（synchronized） |
| 性能 | 拼接 O(n²) | **最快** | 有锁略慢 |
| 适用 | 常量、key | 单线程拼接 | 多线程拼接（极少） |

> 🎯 面试必答：**循环拼接用 StringBuilder；String 的 `+` 在循环里每次 new 对象**——这是字符串题 TLE 的常见原因。

## 6. 选型决策流程

```text
要存什么？
 ├─ 键值对 → 需要顺序？
 │    ├─ 是：按键排序 → TreeMap；插入序 → LinkedHashMap
 │    └─ 否 → HashMap
 ├─ 元素集合 → 需要去重？
 │    ├─ 是：有序 → TreeSet；无序 → HashSet
 │    └─ 否：需要下标 → ArrayList；频繁头插 → LinkedList
 ├─ 需要极值 → 优先队列（PriorityQueue）
 └─ 需要双端/单调 → Deque / 单调栈 / 单调队列
```

## 7. 深拷贝 vs 浅拷贝 vs 引用传递（工程高频混淆）

| 维度 | 浅拷贝 | 深拷贝 | 引用传递 |
|------|------|------|------|
| 对象 | 新建外壳，内部引用共享 | 全部新建 | 不新建 |
| 修改内部 | 影响原对象 | 不影响 | 影响原对象 |
| 实现 | `clone()` 默认 / 拷贝构造 | 序列化 / 手动递归拷贝 | 直接赋值 |
| 数组 | `Arrays.copyOf`（一维深、二维浅） | 逐行 new | `int[] b = a` |

```text
⚠️ 工程高频坑：
  ① 二维数组 clone 是浅拷贝——第二层还是同一引用
  ② 集合 copyOf/构造函数拷贝的是引用（元素对象共享）
  ③ 深拷贝常用：序列化（慢）、手动 new（快）
```

> 🎯 **核心要点**：数据结构对比的规律——**「有序性、极值、去重、双端」四个需求词**直接对应四类结构（树形有序 / 堆极值 / 哈希去重 / 队列双端）。面试选型题先听清需求词，再对号入座。三个高频加分点：LinkedList 中间插入的 O(n) 真相、堆用数组 BST 用指针的原因、深拷贝/浅拷贝/引用传递的三层区别（第 7 节）。
