## 1. 二分查找坑

| 坑 | 症状 | 正确写法 |
|------|------|------|
| 死循环 | `l = mid` 且 `mid = (l+r)/2` | `l = mid + 1` / `mid = l + (r-l)/2` |
| 求上界下界混 | 首个 ≥ x vs 首个 > x | 统一：`while (l < r)` + `r = mid`（左闭右开） |
| mid 溢出 | `(l + r) / 2` | `l + (r - l) / 2`（r 超 2e9 时） |
| 单调性误判 | 对非单调数组二分 | 先证明单调性 |
| 二分答案 | 检查函数忘写或 O(n) 整体超时 | check 复杂度 × log 域 达标 |
| 浮点二分 | 判 `r - l < 1e-9` 可能死循环 | 固定迭代次数（如 100 次） |

### 1.1 二分模板三件套（记死）

```java
/** ① 查下界：首个 >= target（左闭右开） */
int lowerBound(int[] a, int t) {
    int l = 0, r = a.length;              // ⚠️ r 开区间
    while (l < r) {
        int mid = l + (r - l) / 2;
        if (a[mid] < t) l = mid + 1;
        else r = mid;                     // 收缩右界保留 mid
    }
    return l;                             // 若都 < t，返回 a.length
}

/** ② 查上界：最后一个 <= target */
int upperBound(int[] a, int t) { /* lowerBound(a, t+1) - 1 */ }

/** ③ 二分答案：最大化最小值 */
// while (l < r) { mid; if (check(mid)) l = mid+1; else r = mid; }
// ⚠️ check 内部独立成函数，保持主循环干净
```

> 🎯 二分三问：**① 单调吗？② 求下界还是上界？③ 死循环吗？** 用「左闭右开 + r=mid / l=mid+1」模板可从根上规避死循环。

### 1.2 死循环的机械检查

```text
检查：l 与 r 相邻（r = l+1）时，mid = l，
     若分支走 l = mid → l 不变 → 死循环 ✗
     若分支保证 l = mid+1 或 r = mid → 区间必收缩 ✓
```

## 2. 双指针与滑动窗口坑

| 坑 | 症状 | 修复 |
|------|------|------|
| 指针越界 | `l < r` 写成 `l != r` | 明确相遇处理 |
| 窗口顺序 | 先更新答案再缩窗 | 先保证窗口合法再统计 |
| 窗口收缩幅度 | l 一次只移一位（O(n²)） | 条件满足时 while 收缩 |
| 快慢指针顺序 | 快指针越界 | 先移快指针判 null 再动慢 |
| 三数之和去重 | 结果重复 | 排序 + 相同值跳过 |
| 子数组计数 | 忘用「以 r 结尾」视角 | `ans += r - l + 1` |

### 2.1 滑动窗口固定套路

```text
for r in 0..n-1:
    加入 a[r]（更新状态）
    while 窗口不满足条件:
        移除 a[l]; l++
    统计以 r 结尾的合法窗口
⚠️ 坑：状态更新（加入/移除）必须与 while 条件严格一致，否则漏窗/重窗
```

### 2.2 窗口顺序的三种问法

| 问法 | 顺序 |
|------|------|
| 求最短合法窗口 | 每次先尝试收缩到合法，再统计 |
| 求最长合法窗口 | 先扩到不合法，收缩后统计 |
| 求恰好 k 个 | 前缀和/窗口计数变体，注意负数场景 |

## 3. 动态规划坑

| 坑 | 症状 | 修复 |
|------|------|------|
| 初始化漏状态 | dp[0] 语义错 | 明确「边界状态」含义再赋值 |
| 状态缺维度 | 信息不足导致转移错 | 加维度（是否持有/上次取没取） |
| 无后效性破坏 | 转移依赖未来 | 调整状态定义或拓扑序 |
| 循环顺序错 | 一维背包正序（重复取） | **0-1 背包倒序**，完全背包正序 |
| 忘了取 max/min | 转移比较错 | 明确「继承 vs 转移」两分支 |
| 大数取模 | 计数 DP 忘模 | 每步取模 |
| 滚动数组覆盖 | 二维压缩后状态丢失 | 需要旧状态的用临时变量 |
| 树形 DP 递归 | 子树间顺序 | 后序遍历自底向上 |

### 3.1 背包四问（经典坑源）

| 问题 | 答案 |
|------|------|
| 0-1 背包循环方向？ | 容量**倒序**（防止重复取） |
| 完全背包循环方向？ | 容量**正序**（允许重复取） |
| 恰好装满怎么初始化？ | `dp[0]=0, 其余 -INF`（不可达） |
| 求方案数怎么转移？ | `dp[j] += dp[j-w]`（累加取模） |

```java
/** 0-1 背包：⚠️ 容量倒序 */
for (int i = 0; i < n; i++)
    for (int j = cap; j >= w[i]; j--)       // 倒序：每个物品最多取一次
        dp[j] = Math.max(dp[j], dp[j - w[i]] + v[i]);

/** 完全背包：⚠️ 容量正序 */
for (int i = 0; i < n; i++)
    for (int j = w[i]; j <= cap; j++)       // 正序：允许重复取
        dp[j] = Math.max(dp[j], dp[j - w[i]] + v[i]);
```

## 4. 回溯与搜索坑

| 坑 | 症状 | 修复 |
|------|------|------|
| 递归无返回 | 结果被覆盖 | 传副本 / 加入结果时 new 一份 |
| 撤销漏做 | 状态累积污染 | 递归后**撤销**（回溯标志位） |
| 去重漏做 | 重复排列 | 排序 + `i > start && a[i]==a[i-1]` 剪枝 |
| BFS 判重晚 | 同一节点多次入队 | 入队即标记 visited |
| 迷宫方向 | 四个方向写错 | 方向数组 `dx/dy` 统一 |
| 剪枝过度 | 合法分支被剪 | 剪枝条件加注释说明充分性 |
| 记忆化冲突 | memo 值被污染 | 独立 memo 数组，与 visited 区分 |
| 递归深度 | 组合爆炸 | 先估剪枝后分支数 |

```java
/** 回溯标准骨架：选 → 递归 → 撤销 */
void dfs(路径, 选择列表) {
    if (满足结束) { 记录路径副本; return; }
    for (选择 : 选择列表) {
        if (不可选) continue;
        做选择;
        dfs(...);
        撤销选择;                       // ⚠️ 忘了这行 = 状态污染
    }
}
```

### 4.1 BFS 判重时机的代价对比

```text
入队时标记：每个节点最多入队 1 次 → O(V+E)
出队时标记：同一节点可能入队多次 → 最坏指数级
例：网格最短路，出队判重 → 四方向反复入队 → TLE
```

## 5. 贪心坑

| 坑 | 症状 | 修复 |
|------|------|------|
| 未证明直接贪 | 反例击穿 | 反例三问（局部最优会锁死全局吗） |
| 排序依据错 | 比较器写反 | 先小样例验证排序方向 |
| 区间调度 | 按开始时间排序 | **按结束时间排序** |
| 找零问题 | 局部贪心全局错 | 先证贪心选择性质 |
| 双向贪心 | 先处理 A 影响 B | 固定一个维度再贪另一个 |

### 5.1 区间类贪心两条铁律

```text
最大不重叠区间数：按【结束时间】升序排序，贪心取最早结束的
区间覆盖最少点：按【结束时间】排序，点在最早结束区间右端点
⚠️ 换排序依据 = 换题，别凭感觉
```

### 5.2 贪心的证法（面试要求）

| 证法 | 思路 |
|------|------|
| 贪心选择性质 | 证明存在一个最优解包含第一次贪心选择 |
| 交换论证 | 交换最优解中相邻的「非贪心对」不劣化 |
| 反证法 | 假设贪心解非最优，推出矛盾 |

## 6. 排序坑

| 坑 | 症状 | 修复 |
|------|------|------|
| 比较器溢出 | `return a - b` | `Integer.compare(a, b)` |
| 稳定性需求 | 快排不稳定 | 归并 / 稳定排序 |
| 原地修改 | 排序后还要原序 | 存 `(值, 原下标)` 对 |
| 大 O 误估 | 以为快排最坏 O(n log n) | 最坏 O(n²)，工程随机化 pivot |
| 逆序对 | 用 O(n²) | 归并 / 树状数组 O(n log n) |
| 自定义对象 | 没实现 Comparable | 用 Lambda 比较器 |

> 🎯 **核心要点**：思想类坑的共同本质是**「忘了证明/忘了状态语义」**——二分的单调性、DP 的状态含义、贪心的选择性质、回溯的撤销，都是「思路对但实现错」。修复方法统一：**回到伪代码层验证语义，再改代码层细节**。每类思想的模板代码（二分三件套、背包循环方向、回溯骨架）是坑的「正解面」，背模板 + 查坑表双保险。
