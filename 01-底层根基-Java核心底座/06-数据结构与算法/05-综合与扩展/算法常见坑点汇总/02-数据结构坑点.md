## 1. 数组与字符串坑

| 坑 | 错误 | 正确 | 为什么 |
|------|------|------|------|
| 越界 | `a[i+1]` 在 i=n-1 时 | 循环条件 `i+1 < n` | 数组下标最大 n-1 |
| 返回长度 | `a.length` 与需要的 n 混 | 分清「数组长度」与「有效长度」 | 预留数组长度 ≠ 数据量 |
| 原地修改 | 滚动数组正序覆盖 | **倒序**更新（杨辉单行） | 正序用新值污染同行后续 |
| 前缀和边界 | `pre[0]` 语义 | 前缀和长度 n+1，pre[0]=0 | 查询 [l,r] 需 pre[r+1]-pre[l] |
| 二维开反 | `new int[m][n]` 与 `new int[n][m]` | 与访问顺序一致 | 行列维度错位即越界 |
| 字符串不可变 | 循环 `+` 拼接 | `StringBuilder` | 每次 + 新建对象 O(n²) |
| 字符计数 | `char - 'a'` 数组 | 注意大小写混合题 | 范围估计错越界 |

### 1.1 前缀和经典坑

```text
pre[i] = a[0..i-1] 的和（pre 长 n+1）
查询 [l, r] 和 = pre[r+1] - pre[l]
⚠️ 忘开 n+1、查询时下标错位是区间和题 WA 第一原因
例：a = [1,2,3]，pre = [0,1,3,6]
查询 [0,2] 和 = pre[3] - pre[0] = 6 ✓（不是 pre[2]！）
```

## 2. 链表坑

| 坑 | 错误 | 正确 | 为什么 |
|------|------|------|------|
| 空指针 | `cur.next.next` 未判 | 先判 `cur.next != null` | 尾节点 next 为 null |
| 头节点删除 | 头节点特判漏 | 用**哑节点** `dummy` 统一 | 头删与中间删逻辑统一 |
| 环检测 | 快指针先取 next | 每步判 `fast != null && fast.next != null` | 快指针两步一跳先触 null |
| 反转链表 | 断链丢后继 | 三指针：`prev/cur/next` 顺序保存 | 改指向前必须先存 next |
| 快慢中点 | 奇偶长度差异 | 定好「偶数取左中还是右中」 | 题面约定不同答案不同 |
| 合并 | 一链耗尽后忘接剩余 | 收尾 `cur.next = (l1 != null ? l1 : l2)` | 剩余链整体挂接 O(1) |
| 删除节点 | 只传目标节点没法删前驱 | 传前驱 / 值覆盖法 | 单向链表无前驱指针 |

```java
/** 哑节点统一头处理（删除/合并类题标配） */
ListNode dummy = new ListNode(0);
dummy.next = head;
// 操作到 dummy.next 结束，最后返回 dummy.next
// 例：LC 19 删倒数第 n 个——dummy 让「删头节点」与「删中间」同一条代码
```

### 2.1 链表题三查

```text
① 改 next 前存好 next 了吗？
② 访问 next.next 前判空了吗？
③ 返回的是 dummy.next 还是 head？（头可能被删）
```

## 3. 栈与队列坑

| 坑 | 错误 | 正确 | 为什么 |
|------|------|------|------|
| 单调栈方向 | 求「下一个更大」用递增栈 | 栈内**递减**（从栈顶到栈底递减） | 新元素大 → 弹栈结算 |
| 出栈时机 | 新元素到来前出栈 | 先处理栈顶出栈，再入栈 | 出栈时结算「下一个更大」 |
| 单调队列 | 维护窗口大小忘出队 | 先「过期出队」再「单调性出队」 | 过期元素仍在队首会污染 |
| BFS 层序 | 忘记记录当前层大小 | `int size = queue.size()` 快照 | 循环中 size 变化 |
| 双端队列 | Deque 的 add/remove 混 | `addFirst/addLast` 语义明确 | 默认方法语义混乱 |
| 括号匹配 | 出栈后不判空 | 栈空时右括号直接不匹配 | 空栈 pop 抛异常 |

```text
单调栈口诀：求「更大」栈内递减；求「更小」栈内递增。
           出栈时结算，新元素入栈后结算它自己。
```

### 3.1 BFS 层序的正确骨架

```java
// ⚠️ size 必须在循环前快照，因为循环中队列会变化
while (!queue.isEmpty()) {
    int size = queue.size();              // 本层节点数
    for (int i = 0; i < size; i++) {
        // 弹出本层节点，子节点入队（属于下一层）
    }
}
```

## 4. 哈希与集合坑

| 坑 | 错误 | 正确 | 为什么 |
|------|------|------|------|
| 可变键 | 用 StringBuilder/数组做 key | 转字符串或不可变包装 | 键 hash 变化后查不到 |
| 空值 | `map.get(key)` 直接判空 | 与 `containsKey` 区分「不存在 vs 值 null」 | get 返回 null 两义 |
| 默认值 | `getOrDefault` 忘更新 | 更新后要 put 回去 | getOrDefault 不写回 |
| 迭代删除 | 边遍历边删 | 收集后统一删 / `iterator.remove()` | ConcurrentModification |
| 冲突性能 | 大输入用 HashSet 大量操作 | 可预分配容量 / 数组代替 | 扩容 + 哈希开销 |
| TreeMap 语义 | 误当 HashMap 用 | 需要有序才用 TreeMap（log n） | O(1) 需求用了 O(log n) |
| 计数自增 | `map.put(k, map.get(k)+1)` 繁琐 | `merge(k, 1, Integer::sum)` | 简写且防 NPE |
| 数组做下标 | 值域大用数组 | 值域 ≤ 10⁶ 数组，否则哈希 | 值域 1e9 开数组爆内存 |

## 5. 树与堆坑

| 坑 | 错误 | 正确 | 为什么 |
|------|------|------|------|
| 递归爆栈 | 链状树递归 | 深树转迭代栈 | 100k 层递归爆 JVM 栈 |
| 空树 | 忘记判 root == null | 所有递归入口判空 | NPE 或错答案 |
| 中序性质 | 假设 BST 中序有序 | 验证（中序必升序） | 验证 BST 的标准手法 |
| 层序空节点 | 层序遍历漏掉 null 子节点 | 按需入队并标记 | 空节点影响结构判断 |
| 堆的初始化 | 想取大值用小顶堆 | 大顶堆 `(a,b) -> b - a`（小心溢出用 compare） | 堆顶 = 你关心的极值 |
| TopK 维护 | 维护了堆忘了剪枝 | 超过 K 就弹出，保持 O(n log k) | 不剪枝退化为全排序 |
| 并查集 | 忘路径压缩/按秩合并 | 压缩必做，否则最坏 O(n) 每次 | 压缩后近 O(1) |
| 并查集初始化 | `parent[i] = i` 漏 | 每个节点自指 | 不自指 = 找不到根 |
| 二叉堆数组 | 下标从 0 起 parent 公式 | `(i-1)/2` 而非 `i/2` | 0 基与 1 基公式不同 |

```java
/** 大顶堆：用 compare 防溢出（a-b 会溢出） */
PriorityQueue<Integer> maxHeap = new PriorityQueue<>((a, b) -> Integer.compare(b, a));
```

## 6. 图结构坑

| 坑 | 错误 | 正确 | 为什么 |
|------|------|------|------|
| 无向图加边 | 只加一条 | `add(u,v); add(v,u)` | 无向边双向可达 |
| 邻接表初始化 | 忘了 new 每个桶 | `List<Integer>[] g = new List[n]; 逐个 new` | 默认 null，add 即 NPE |
| 重边自环 | 不处理 | 按题意决定去重 | 最短路可能被污染 |
| BFS 判重时机 | 出队时判 visited | **入队时**标记防重复入队 | 出队时判会重复入队 |
| DFS 递归深度 | 大图递归 | 转迭代 / 限制深度 | 10⁵ 节点爆栈 |
| 二分图染色 | 忘判「已染且冲突」 | 染色冲突即非二分图 | 冲突 = 奇数环 |
| Dijkstra 负权 | 负权用 Dijkstra | Bellman-Ford/SPFA（或转思路） | 贪心假设被负权破坏 |
| 拓扑排序 | 忘算入度/忘初始化队列 | 入度为 0 的全部入队 | 漏节点导致顺序不完整 |
| 环检测 | DFS 只记 visited 不记在栈 | 区分「访问过」与「在当前路径」 | 访问过 ≠ 有环 |

> 🎯 **核心要点**：数据结构坑两大规律——**① 指针/索引类坑（链表、树）核心是「先判空再取 next」**；**② 状态类坑（BFS、并查集、拓扑）核心是「标记时机与初始化完整」**。每种结构记住 2-3 个专属坑（表格加粗处），结构类题 WA 率减半。
