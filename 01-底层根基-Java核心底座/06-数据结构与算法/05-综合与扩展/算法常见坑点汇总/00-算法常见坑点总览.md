## 2. Top 10 致命坑点（必背）

| # | 坑点 | 错误写法 | 正确写法 | 为什么错 |
|:---:|------|------|------|------|
| 1 | int 溢出 | `int sum = a + b` | 求和/乘法一律 `long` | 1e9 + 1e9 超 int 上限 2.1e9 |
| 2 | 负数取模 | `a % m`（负得负） | `(a % m + m) % m` | Java 取模符号跟随被除数 |
| 3 | 二分死循环 | `mid = (l+r)/2` + `l = mid` | `mid = l + (r-l)/2` 且 `l = mid+1` | l=mid 时区间不收缩 |
| 4 | 数组越界 ±1 | `for (i = 0; i <= n; i++)` 访问 a[i] | 明确 a.length 与索引上界 | 索引从 0 起，最后一个下标是 n-1 |
| 5 | 链表空指针 | `cur.next.next` 未判空 | 先判 `cur.next != null` | 尾部节点 next 为 null |
| 6 | 递归爆栈 | 树深 n 用递归 | 深递归转栈迭代 | JVM 默认栈深约 1 万层 |
| 7 | 忘取模 | 组合/DP 计数忘 `% p` | 每步运算后取模 | 中间值先溢出，最后取模已错 |
| 8 | 贪心反例 | 不证直接贪心 | 反例三问（02 篇 4.1） | 局部最优 ≠ 全局最优 |
| 9 | 快慢指针越界 | 快指针先移动后判空 | 循环内先判 `fast != null` | 快指针每步走 2，先越界 |
| 10 | 输出超时 | 循环 `System.out.println` | 攒 `StringBuilder` 一次输出 | 每次 println 同步刷盘 |

### 2.1 Top 10 的记忆口诀

```text
一 long 二取模，三二分四越界；
五链表六递归，七取模八贪心；
九快慢十输出——十个坑位背下来，70% 的低级错误消失
```

## 3. 提交前 60 秒自检清单

```text
□ 1. 所有求和/乘法用 long？（含下标运算）
□ 2. 取模做了吗？负数处理了吗？
□ 3. 空输入、n=1、首尾元素测过吗？
□ 4. 循环边界 ±1 核对过吗？
□ 5. 链表/树的 next/null 判空了吗？
□ 6. 递归最大深度估算过吗？
□ 7. 复杂度对上数据范围了吗（01 篇定档表）？
□ 8. 多组数据时状态/数组重置了吗？
□ 9. 输出格式与样例完全一致吗（空格/换行）？
□ 10. 用到的结构（TreeSet/优先队列）import 了吗？
```

### 3.1 清单的使用时机

| 时机 | 用法 |
|------|------|
| 提交前 | 逐项勾选，任何一项「没把握」就停下来验证 |
| WA 后 | 重跑清单，前 6 项是 WA 高发区 |
| 面试手写后 | 口头报「我检查了空输入、单元素、溢出」——面试官印象分 |

> 💡 打印贴屏幕上：前 6 条能挡住 70% 的 WA/TLE/RE。

## 4. 坑点统计规律：错因分布

| 错因 | 占比 | 高频场景 | 对策 |
|------|:---:|------|------|
| 边界遗漏 | ~40% | 空/单元素/首尾 | 边界清单（做题流程 03 篇） |
| 思路缺陷 | ~25% | 贪心错证、状态漏维度 | 反例三问 + DP 状态检查 |
| 溢出取模 | ~15% | 大数、负数模 | 全 long + 防负取模 |
| 审题偏差 | ~20% | 漏约束、误读 | 八问清单（做题流程 01 篇） |

### 4.1 错因统计的用法：发现自己（个人化）

```text
步骤：错题本每道 WA 记错因 → 每 50 题统计一次占比
用途：占比最高的错因 = 你的第一改进项
示例：若你 60% 错在边界 → 写代码时把边界处理「提到最前面」写
      若你 40% 错在思路 → 加强「反例三问」而不是刷更多题
```

## 5. 坑点系统的使用姿势

### 5.1 三种使用场景

| 场景 | 动作 |
|------|------|
| 编码中 | 写完一个函数，对照「数据结构坑点」对应结构节 |
| 提交前 | 60 秒清单全过一遍 |
| WA 后 | 归因 → 进对应篇目定位 → 修正 → 记入错题本 |

### 5.2 与相邻系统的配合

```text
坑点汇总（是什么错了）  ← 现象层
做题分析流程（怎么避免） ← 流程层
易混淆对比（为什么像但不同） ← 概念层
三套配合：先查坑 → 再走流程 → 概念不清回对比表
```

## 6. 个人坑点画像：从统计到改进

### 6.1 建立自己的坑点画像（50 题一更新）

| 维度 | 记录方式 | 用途 |
|------|------|------|
| 错因占比 | 错题本按四类打标 | 找「我的第一错因」 |
| 踩坑位置 | 记录 WA 在哪个环节（读题/思路/编码/验证） | 定位流程短板 |
| 高频题坑 | 记录哪些题型的坑反复出现 | 定向补该专题 |
| 复发率 | 二刷时同一题是否还错 | 验证修复是否有效 |

### 6.2 画像驱动的改进动作

| 画像结果 | 改进动作 |
|------|------|
| 边界错 60%+ | 编码前先写边界三行（空/单/首尾），再写主体 |
| 思路错 40%+ | 每题强制「反例三问」后再编码 |
| 审题错 30%+ | 读题后先口头复述题意再动手 |
| 溢出错集中 | 编码时全部量默认 long，写完检查乘法处 |

> 🎯 **核心要点**：坑点系统的价值 = **把「踩坑」变成「查表」**。Top 10 必背 + 60 秒清单 + 四类归因，三者配合能拦截绝大多数低级错误。深层坑点（各结构/思想的特殊坑）进入对应篇目细查。别试图背完所有坑——**用清单挡住高频坑，用归因捕捉自己的个性坑**，两条腿走路；第 6 节的「画像 → 改进」闭环让坑点系统随刷题量自我优化。
