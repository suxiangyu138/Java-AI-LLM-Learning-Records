## 一、动态数组与链表

### 1.1 ArrayList 底层实现

ArrayList 基于**动态数组**实现，核心字段为 `Object[] elementData` 和 `int size`。

#### 1.1.1 扩容机制

当元素个数超过当前容量时触发 **grow()**，扩容 1.5 倍：

```java
private void grow(int minCapacity) {
    int oldCapacity = elementData.length;
    int newCapacity = oldCapacity + (oldCapacity >> 1); // 1.5 倍
    elementData = Arrays.copyOf(elementData, newCapacity);
}
```

| 版本 | 扩容倍数 | 初始容量 | 备注 |
|------|----------|----------|------|
| JDK 6 | 1.5 倍 | 10 | 预先分配 |
| JDK 7+ | 1.5 倍 | 10（懒加载） | 首次 add 初始化 |
| JDK 8+ | 1.5 倍 | 10（懒加载） | 引入 `DEFAULTCAPACITY_EMPTY_ELEMENTDATA` |

> 💡 能预估数据量时使用 `new ArrayList<>(initialCapacity)`，避免频繁扩容。

#### 1.1.2 System.arraycopy

所有插入和删除操作依赖 `System.arraycopy`（JVM native 方法，内存块拷贝）：

```java
// 中间插入：index 之后元素整体后移
public void add(int index, E element) {
    rangeCheckForAdd(index);
    ensureCapacityInternal(size + 1);
    System.arraycopy(elementData, index, elementData, index + 1, size - index);
    elementData[index] = element;
    size++;
}

// 删除：index 之后元素整体前移，末位置 null 帮助 GC
public E remove(int index) {
    E oldValue = elementData(index);
    int numMoved = size - index - 1;
    if (numMoved > 0)
        System.arraycopy(elementData, index + 1, elementData, index, numMoved);
    elementData[--size] = null;
    return oldValue;
}
```

### 1.2 LinkedList 底层实现

基于**双向链表**，内部类 `Node<E>` 持有 prev/next 指针：

```java
private static class Node<E> {
    E item;
    Node<E> next;
    Node<E> prev;
    Node(Node<E> prev, E element, Node<E> next) {
        this.item = element; this.next = next; this.prev = prev;
    }
}
```

头尾操作均为 O(1)：

```java
// 头插
private void linkFirst(E e) {
    final Node<E> f = first;
    final Node<E> newNode = new Node<>(null, e, f);
    first = newNode;
    if (f == null) last = newNode;
    else f.prev = newNode;
    size++;
}

// 按索引访问时折半搜索
Node<E> node(int index) {
    if (index < (size >> 1)) {  // 前半段：从 first 向后
        Node<E> x = first;
        for (int i = 0; i < index; i++) x = x.next;
        return x;
    } else {                    // 后半段：从 last 向前
        Node<E> x = last;
        for (int i = size - 1; i > index; i--) x = x.prev;
        return x;
    }
}
```

### 1.3 性能对比

| 操作 | ArrayList | LinkedList |
|------|-----------|------------|
| get(i) 随机访问 | O(1) | O(n) |
| add(E) 尾部插入 | O(1) 均摊 | O(1) |
| add(i,E) 中间插入 | O(n) | O(n) |
| remove(i) | O(n) | O(n) |
| 内存占用 | 连续数组（缓存友好） | 离散 Node 对象 |
| 局部性 | 好 | 差 |

### 1.4 后端落地要点

- **遍历删除**：用 `Iterator.remove()` 或 `removeIf()` 避免 `ConcurrentModificationException`。
- **大列表释放**：处理完批量数据后调用 `trimToSize()` 收缩容量。
- **空值校验**：ArrayList 和 LinkedList 允许 null，建议统一用 `Objects.requireNonNull()` 拦截。

## 二、栈与队列

### 2.1 Stack（LIFO）

Java 的 `Stack` 继承自 `Vector`，已过时，推荐用 `ArrayDeque`：

```java
Deque<String> stack = new ArrayDeque<>();
stack.push("a"); stack.push("b"); stack.push("c");
String top = stack.pop(); // c
```

#### 括号匹配示例

```java
public boolean isValid(String s) {
    Deque<Character> stack = new ArrayDeque<>();
    for (char c : s.toCharArray()) {
        if (c == '(' || c == '[' || c == '{') {
            stack.push(c);
        } else {
            if (stack.isEmpty()) return false;
            char top = stack.pop();
            if ((c == ')' && top != '(') || (c == ']' && top != '[') || (c == '}' && top != '{'))
                return false;
        }
    }
    return stack.isEmpty();
}
```

### 2.2 Queue（FIFO）

| 操作 | 抛异常 | 返回特殊值 |
|------|--------|------------|
| 插入 | add(e) | offer(e) |
| 移除 | remove() | poll() |
| 检查 | element() | peek() |

#### 阻塞队列

```java
BlockingQueue<Task> queue = new ArrayBlockingQueue<>(1000);
queue.put(task);     // 满时阻塞
Task t = queue.take(); // 空时阻塞
```

| 实现类 | 特性 | 适用场景 |
|--------|------|----------|
| ArrayBlockingQueue | 有界数组，公平锁可选 | 线程池工作队列 |
| LinkedBlockingQueue | 有界/无界链表 | 消息队列 |
| SynchronousQueue | 零容量，直接传递 | 高吞吐直传 |
| DelayQueue | 延迟出队 | 定时任务 |

### 2.3 PriorityQueue

基于**最小堆**，poll() 返回堆顶元素：

```java
PriorityQueue<Integer> pq = new PriorityQueue<>();
pq.offer(3); pq.offer(1); pq.offer(2);
Integer top = pq.poll(); // 1

// 任务调度示例
class Task implements Comparable<Task> {
    int priority; String name;
    Task(int p, String n) { priority = p; name = n; }
    public int compareTo(Task o) { return Integer.compare(this.priority, o.priority); }
}
PriorityQueue<Task> scheduler = new PriorityQueue<>();
scheduler.offer(new Task(3, "低优先级"));
scheduler.offer(new Task(1, "高优先级"));
scheduler.poll(); // 高优先级任务
```

> 💡 PriorityQueue 迭代器不保证遍历有序，只有 poll() 序列保证。需遍历全部有序元素时用 `while (!pq.isEmpty()) pq.poll()`。

### 2.4 后端应用场景

| 结构 | 场景 | 说明 |
|------|------|------|
| Stack | 方法调用栈、表达式求值、撤销、DFS | LIFO |
| Queue | 消息队列、任务缓冲、BFS | FIFO |
| PriorityQueue | 定时调度、Dijkstra、Top K | 按优先级 |
| BlockingQueue | 线程池队列、生产者-消费者 | 线程安全 + 阻塞 |

## 三、散列表

### 3.1 哈希函数设计

#### 除留余数法

```java
hash(key) = key mod P   // P 选质数，远离 2 的幂
```

若 P 为 2 的幂，`key mod 2^n` 等价于取低 n 位，散列效果差。

#### 乘法散列法

```java
hash(key) = floor(M * (key * A mod 1))
// A = (√5 - 1) / 2 ≈ 0.618（黄金分割比例）
```

#### Java 扰动函数

```java
static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}
```

将高 16 位与低 16 位异或，使高位信息参与低位寻址。HashMap 取模使用 `(n - 1) & hash`，若高位不参与，散列度会不足：

```
原始 hashCode:  1101 0110 1011 0011  1110 0001 0101 1010
h >>> 16:       0000 0000 0000 0000  1101 0110 1011 0011
异或结果:       1101 0110 1011 0011  0011 0111 1110 1001  ← 高位信息混入低位
```

### 3.2 冲突解决

#### 链地址法

每个槽位维护链表（JDK 8+ 过长时转红黑树），冲突元素追加到链中。插入 O(1)，查找 O(α)（α = 负载因子）。

#### 开放寻址法

```java
slot = (hash(key) + f(i)) mod M
```

| 探测方式 | f(i) | 特点 |
|----------|------|------|
| 线性探测 | f(i) = i | 简单，易生群集 |
| 二次探测 | f(i) = i² | 缓解群集 |
| 双重散列 | f(i) = i * h₂(key) | 最均匀 |

#### 对比

| 特性 | 链地址法 | 开放寻址法 |
|------|----------|------------|
| 负载因子容忍度 | 可超 1 | 必须 < 1 |
| 缓存友好 | 差 | 好 |
| 删除 | 直接删除 | 惰性标记 |
| 适用场景 | 数据量不可预测 | 内存敏感 |

### 3.3 Java HashMap 简化实现

```java
public class SimpleHashMap<K, V> {
    static class Node<K, V> {
        final int hash; final K key; V value; Node<K, V> next;
        Node(int hash, K key, V value, Node<K, V> next) {
            this.hash = hash; this.key = key; this.value = value; this.next = next;
        }
    }

    private static final int DEFAULT_CAPACITY = 16;
    private static final float DEFAULT_LOAD_FACTOR = 0.75f;
    private Node<K, V>[] table;
    private int size;

    @SuppressWarnings("unchecked")
    public SimpleHashMap() { table = new Node[DEFAULT_CAPACITY]; }

    private int hash(Object key) {
        int h;
        return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
    }

    public void put(K key, V value) {
        int hash = hash(key);
        int index = (table.length - 1) & hash;
        for (Node<K, V> p = table[index]; p != null; p = p.next) {
            if (p.hash == hash && Objects.equals(p.key, key)) {
                p.value = value;
                return;
            }
        }
        table[index] = new Node<>(hash, key, value, table[index]);
        size++;
    }

    public V get(Object key) {
        int hash = hash(key);
        int index = (table.length - 1) & hash;
        for (Node<K, V> p = table[index]; p != null; p = p.next) {
            if (p.hash == hash && Objects.equals(p.key, key)) return p.value;
        }
        return null;
    }
}
```

### 3.4 负载因子与扩容

```
threshold = capacity * loadFactor
size > threshold → resize()
新容量 = 旧容量 × 2
```

| 负载因子 | 优点 | 缺点 |
|----------|------|------|
| 0.75（默认） | 时间/空间均衡 | — |
| 0.5 | 冲突少，查找快 | 内存浪费 |
| 1.0 | 内存利用率高 | 冲突多 |

JDK 8+ 扩容优化：元素在新数组的位置要么是原索引，要么是 `原索引 + 旧容量`，判断依据为 `(e.hash & oldCap) == 0`，避免重新计算 hash：

```java
Node<K,V> loHead = null, loTail = null; // 留在原位的链
Node<K,V> hiHead = null, hiTail = null; // 要移动的链
do {
    if ((e.hash & oldCap) == 0) {
        if (loTail == null) loHead = e; else loTail.next = e;
        loTail = e;
    } else {
        if (hiTail == null) hiHead = e; else hiTail.next = e;
        hiTail = e;
    }
    e = next;
} while (e != null);
if (loTail != null) { loTail.next = null; newTab[j] = loHead; }
if (hiTail != null) { hiTail.next = null; newTab[j + oldCap] = hiHead; }
```

### 3.5 ConcurrentHashMap（JDK 8+）

| 版本 | 实现 | 并发粒度 |
|------|------|----------|
| JDK 5-6 | Segment 分段锁（ReentrantLock） | 16 个 Segment |
| JDK 7 | Segment 分段锁 | 可配 |
| JDK 8+ | CAS + synchronized + 红黑树 | 每个桶 |

核心流程：

```java
final V putVal(K key, V value, boolean onlyIfAbsent) {
    int hash = spread(key.hashCode());
    for (Node<K,V>[] tab = table;;) {
        Node<K,V> f;
        // 1. 懒加载初始化
        if (tab == null) tab = initTable();
        // 2. 桶为空 → CAS 无锁插入
        else if (tabAt(tab, i) == null) {
            if (casTabAt(tab, i, null, new Node<>(hash, key, value, null))) break;
        }
        // 3. 正在扩容 → 协助迁移
        else if (f.hash == MOVED) tab = helpTransfer(tab, f);
        // 4. 桶非空 → synchronized 锁桶头
        else { synchronized (f) { /* 遍历链表/树插入 */ } }
    }
    addCount(1L, binCount);
}
```

- 无竞争：CAS 原子插入
- 有竞争：synchronized 锁桶头
- 扩容：多线程协助迁移

### 3.6 自定义 Key 规范

```java
public class UserKey {
    private final Long id;
    private final String type;

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof UserKey)) return false;
        UserKey that = (UserKey) o;
        return Objects.equals(id, that.id) && Objects.equals(type, that.type);
    }

    @Override
    public int hashCode() {
        return Objects.hash(id, type);
    }
}
```

> 💡 `a.equals(b) == true` 必须保证 `a.hashCode() == b.hashCode()`，反之不成立。Key 应声明为不可变（final 字段）。

### 3.7 后端业务场景

**用户缓存**：`ConcurrentHashMap.computeIfAbsent` 实现原子加载。**多级缓存**：L1 本地 ConcurrentHashMap + L2 Redis + L3 DB。**分布式计数**：`LongAdder` 配合分段计数取代 HashMap 自增。

```java
// computeIfAbsent 原子语义：key 不存在时才执行函数，避免缓存击穿
public User getUser(Long id) {
    return cache.computeIfAbsent(id, k -> userDao.findById(k));
}
```

## 四、数据结构的扩张

### 4.1 三大扩张准则

| 步骤 | 描述 | 举例 |
|------|------|------|
| 1. 选择基础结构 | 确定底层数据结构 | 红黑树、数组、链表 |
| 2. 确定附加信息 | 需维护的额外字段 | size、sum、min/max |
| 3. 维护操作约束 | 增删改查后如何更新附加信息 | O(1) 或 O(log n) 更新 |

### 4.2 HashMap 的扩张：链表 → 红黑树

JDK 8+ 引入红黑树优化（链表长度 ≥ 8 时树化，≤ 6 时退化）：

| 底层结构 | 查找 | 插入 | 删除 |
|----------|------|------|------|
| 链表 | O(n) | O(1) | O(1) |
| 红黑树 | O(log n) | O(log n) | O(log n) |

**扩容机制的扩张**：JDK 7 全量 rehash，JDK 8+ 用 `(e.hash & oldCap) == 0` 判断元素是否移动，无需重算 hash。

### 4.3 TreeMap 的扩张：顺序统计操作

红黑树节点维护 `size` 字段（子树节点数），支持 kth 查询：

```java
// 查找第 k 小的 key
public K selectKth(int k) {
    Entry<K,V> node = root;
    while (node != null) {
        int leftSize = (node.left == null) ? 0 : node.left.size;
        if (k == leftSize + 1) return node.key;
        else if (k <= leftSize) node = node.left;
        else { k -= leftSize + 1; node = node.right; }
    }
    return null;
}
```

插入/删除时沿路径向上更新 size，旋转时调整涉及节点的 size，每次操作额外 O(log n) 开销。

### 4.4 ArrayList 的扩张：动态扩容

| 维度 | 实现 |
|------|------|
| 基础结构 | Object[] 定长数组 |
| 附加信息 | size（已用数）、modCount（修改计数） |
| 维护约束 | 插入时检查并触发 grow() |

**均摊分析**：扩容总拷贝次数 ≤ 3n，均摊到 n 次 add 约为 O(1)。

### 4.5 自定义数据结构扩张：商品热度排行榜

```java
/**
 * 需求：商品热度实时排行、ID 查排名、Top N 查询
 * 基础：ArrayList + HashMap
 * 扩张字段：rankIndex（元素在列表中的排名索引）
 */
public class ProductRanking {
    private final ArrayList<Product> list = new ArrayList<>();
    private final HashMap<Long, Product> index = new HashMap<>();

    static class Product {
        Long id; int heatScore; int rankIndex; // 扩张字段
        Product(Long id, int heat) { this.id = id; this.heatScore = heat; }
    }

    public void updateHeat(Long productId, int delta) {
        Product p = index.get(productId);
        if (p == null) {
            p = new Product(productId, delta);
            p.rankIndex = list.size();
            list.add(p); index.put(productId, p);
            return;
        }
        p.heatScore += delta;
        // 冒泡上浮
        int i = p.rankIndex;
        while (i > 0 && list.get(i - 1).heatScore < p.heatScore) {
            swap(i, i - 1);
            i--;
        }
        p.rankIndex = i;
    }

    public List<Product> getTopN(int n) {
        return list.subList(0, Math.min(n, list.size()));
    }
}
```

> 💡 生产环境的排行榜通常用 **Redis ZSET**（跳表 + 哈希表），O(log n) 支持排名和范围查询。

## 五、数据结构选型与总结

### 5.1 选型原则

| 需求 | 推荐 | 理由 |
|------|------|------|
| 快速随机访问 | ArrayList | O(1) 索引 |
| 频繁头尾操作 | LinkedList / ArrayDeque | O(1) 头尾 |
| 元素唯一 + 快速查找 | HashSet / HashMap | O(1) 均摊 |
| 有序 + 范围查询 | TreeSet / TreeMap | O(log n) |
| 线程安全 | ConcurrentHashMap / CopyOnWriteArrayList | CAS + 分段 |
| 优先级处理 | PriorityQueue | O(log n) 堆 |
| LRU 缓存 | LinkedHashMap | accessOrder=true |
| Top K | HashMap + PriorityQueue | 最小堆 |
| 数据流中位数 | 两个 PriorityQueue | 最大堆 + 最小堆 |

### 5.2 后端避坑指南

| 陷阱 | 错误做法 | 正确做法 |
|------|----------|----------|
| 并发 HashMap | 多线程读写 HashMap | `ConcurrentHashMap` |
| 初始容量 | 已知 1000 元素却用默认容量 | `ArrayList(1000)` 或 `HashMap((int)(1000/0.75)+1)` |
| 迭代中修改 | for-each 中 remove | `removeIf()` 或 `Iterator.remove()` |
| TreeMap Comparator | Comparator 违反传递性 | 确保 compare 与 equals 一致 |
| PQ 迭代 | 直接 for-each 遍历 | `while (!pq.isEmpty()) pq.poll()` |
| 链表过长的 HashMap | 忽略 hashCode 质量 | 保证散列均匀 + 扰动函数 |

### 5.3 核心速查表

| 结构 | 底层 | 查询 | 插入 | 删除 | 有序 | 线程安全 |
|------|------|------|------|------|------|----------|
| ArrayList | 动态数组 | O(1) | O(n) | O(n) | 插入序 | 否 |
| LinkedList | 双向链表 | O(n) | O(1)* | O(1)* | 插入序 | 否 |
| ArrayDeque | 循环数组 | O(1) | O(1)** | O(1)** | 否 | 否 |
| HashMap | 数组+链表+红黑树 | O(1) | O(1) | O(1) | 否 | 否 |
| LinkedHashMap | HashMap+双向链表 | O(1) | O(1) | O(1) | 插入/访问序 | 否 |
| TreeMap | 红黑树 | O(log n) | O(log n) | O(log n) | 自然序 | 否 |
| ConcurrentHashMap | 数组+链表+红黑树+CAS+sync | O(1) | O(1) | O(1) | 否 | 是 |
| PriorityQueue | 二叉堆 | O(1)*** | O(log n) | O(log n) | 堆序 | 否 |

> * 已知节点引用；** 仅头尾；*** 仅 peek()

---

> 🎯 **核心总结**：基本数据结构是算法的基石。动态数组与链表代表"连续内存 vs 离散内存"两种思路；栈与队列规定处理顺序（LIFO vs FIFO）；散列表以 O(1) 均摊时间实现键值映射——工程中最常用的操作；数据结构扩张思想指导我们在已有结构上"搭积木"实现更丰富的功能。理解每种结构的底层实现、性能边界和适用场景，是写出高性能代码的前提。在后端开发中，选择合适的数据结构往往比优化算法本身更具性价比——选对结构，事半功倍。
