## 3. 刷题路线

根据你的时间预算选择对应路线。三条路线**共享同一套题目库**，区别在深度和题量。

### 🟢 速通版（15 天）

> 💡 目标：快速覆盖面试最高频题型，适合时间紧迫、已有一定算法基础的同学

```text
Day 1-2   → 01-刷题方法论与Java模板库（掌握模板）
Day 3-5   → 02-哈希与双指针 + 03-链表与栈（Easy/Medium 各 5 题）
Day 6-8   → 04-二叉树与图（二叉树的遍历与常见题型）
Day 9-11  → 05-动态规划（背包/线性DP 最基础 5 题）
Day 12-13 → 07-面试手写代码30题（前 15 题）
Day 14-15 → 复盘 + 模考（随机抽 3 题限时 45 分钟）
```

> 💡 目标：系统掌握 Hot100 + 高频面试题，适合大多数准备秋招/春招的同学


## 4. 核心概念速查

### 4.1 时间复杂度速查表

| 复杂度 | 典型场景 | 数据量容忍度 |
|:------:|---------|:----------:|
| O(1) | HashMap 查找、数组随机访问 | 任意 |
| O(log n) | 二分查找、平衡树操作 | 任意 |
| O(n) | 线性遍历、单调栈 | 10^7 ~ 10^8 |
| O(n log n) | 排序、分治、堆操作 | 10^5 ~ 10^6 |
| O(n²) | 双层循环、简单 DP | 10^3 ~ 10^4 |
| O(n³) | Floyd、三重循环 | ~500 |
| O(2ⁿ) | 回溯、子集枚举 | ~20 |
| O(n!) | 全排列 | ~10 |

> 🎯 **面试技巧**：口算复杂度时，找到循环层数 × 每层操作数。递归看递推公式，T(n) = aT(n/b) + O(n^d) 用 Master Theorem。

### 4.2 常用 Java API 速查

| 数据结构 | 核心 API | 时间复杂度 |
|---------|---------|:---------:|
| `ArrayList` | `add()`, `get()`, `set()`, `remove()`, `size()` | get/set O(1), add/remove O(n) |
| `LinkedList` | `addFirst()`, `addLast()`, `removeFirst()`, `removeLast()` | 头尾 O(1), 中间 O(n) |
| `HashMap<K,V>` | `put()`, `get()`, `containsKey()`, `getOrDefault()` | 平均 O(1) |
| `HashSet<E>` | `add()`, `contains()`, `remove()` | 平均 O(1) |
| `TreeMap<K,V>` | `put()`, `get()`, `ceilingKey()`, `floorKey()`, `firstKey()` | O(log n) |
| `TreeSet<E>` | `add()`, `contains()`, `ceiling()`, `floor()`, `first()` | O(log n) |
| `PriorityQueue<E>` | `offer()`, `poll()`, `peek()`, `size()` | offer/poll O(log n) |
| `ArrayDeque<E>` | `push()`, `pop()`, `offer()`, `poll()` | O(1) |
| `StringBuilder` | `append()`, `insert()`, `reverse()`, `toString()` | append O(1) 均摊 |
| `Arrays` | `sort()`, `binarySearch()`, `fill()`, `copyOf()` | sort O(n log n) |
| `Collections` | `sort()`, `reverse()`, `max()`, `min()`, `frequency()` | sort O(n log n) |

### 4.3 算法模式速查

| 模式 | 一句话识别 | 时间复杂度 |
|:----:|-----------|:---------:|
| 二分查找 | 有序数组 + 查找 / 最小值最大化 | O(log n) |
| 滑动窗口 | 连续子数组/子串 + 最大/最小/包含 | O(n) |
| 双指针 | 有序 + 两数关系 / 链表环 / 原地去重 | O(n) |
| 单调栈 | 下一个更大/更小元素 | O(n) |
| BFS | 最短路径 / 层序遍历 / 拓扑排序 | O(V + E) |
| DFS | 所有路径 / 岛屿问题 / 回溯穷举 | O(分支^深度) |
| 动态规划 | 最优子结构 + 重叠子问题 | O(n²) ~ O(n) |
| 贪心 | 局部最优 = 全局最优（需证明） | O(n log n) |
| 并查集 | 连通性 / 冗余连接 | O(α(n)) 近似 O(1) |

## 5. 刷题五步法详解

> 刷题不在多，在于**每道题都吃透**。以下五步法源自对多数大厂面试者经验总结，每一步都不可跳过。

### 第 1 步：读题与复述（2 分钟）

拿到题目先**不要看题解**。逐字读题，用自己的话复述一遍：

- 输入是什么？输出是什么？
- 数据范围有多大？（这决定了能接受什么复杂度）
- 有没有特殊要求（原地、稳定、O(1) 额外空间）？

**示例**：LeetCode 1 两数之和

```text
输入：int[] nums, int target
输出：两个下标 int[]，顺序无关
数据范围：10^4，O(n²) 勉强可过，但 O(n) 更优
特殊要求：无
复述：给定数组中找到两个数之和等于 target，返回下标。
```

### 第 2 步：思考解法（5-8 分钟）

先想**暴力解**，再逐步优化：

1. 暴力解是什么？复杂度多少？
2. 能不能用 HashMap 优化查找？
3. 数据是否有序？能用双指针/二分吗？
4. 是否可以排序？排序后有什么好处？
5. 能不能用滑动窗口/前缀和/单调栈等模式？

> 💡 **原则**：5 分钟没思路很正常，标记后直接看题解，不要死磕。

### 第 3 步：看题解与理解（10 分钟）

看题解时**不要抄代码**，要理解**解题思路**：

- 核心思路是什么？（一句话概括）
- 为什么这样能降低复杂度？
- 边界条件怎么处理的？

**三遍阅读法**（详见 01 模块）：

| 遍数 | 目标 | 做法 |
|:---:|------|------|
| 第一遍 | 理思路 | 看文字解析 + 图解，不看代码 |
| 第二遍 | 看代码 | 逐行理解，问自己"这行为什么这么写" |
| 第三遍 | 关书复述 | 关闭题解，口述完整解法 |

### 第 4 步：手写实现（10-15 分钟）

关掉所有参考，自己写代码：

1. 先在注释里写框架（方法签名 + 核心逻辑）
2. 写代码，一步到位
3. 写完**自己在脑中跑测试用例**

```text
✅ 正常用例 → 通过
✅ 边界用例 → 空数组/单个元素/重复元素/最大值
✅ 特殊用例 → 无解/全相同/负数
```

### 第 5 步：复盘与模板化（5 分钟）

> 🎯 这是最重要的一步，决定了这道题是"做过"还是"会了"。

每道题回答以下四个问题：

| 问题 | 示例回答 |
|:----|---------|
| 一句话核心思路 | 用 HashMap 存遍历过的值，实现 O(n) 查找 |
| 属于什么模式 | 哈希表优化查找 |
| 复杂度 | 时间 O(n)，空间 O(n) |
| 容易错在哪 | 忘记处理无解情况、下标索引搞反 |

## 6. 不同公司算法面试特点

| 公司 | 难度 | 特点 | 高频方向 |
|:---:|:---:|------|---------|
| **字节跳动** | ⭐⭐⭐⭐⭐ | 题量大（2-3 轮），代码量要求高，注重细节、边界条件 | 数组/字符串操作、DFS/BFS、DP、LRU 设计 |
| **阿里巴巴** | ⭐⭐⭐⭐ | 偏难但不偏怪，注重思路推导过程，会引导你优化 | 二叉树、链表、DP、系统设计结合算法 |
| **腾讯** | ⭐⭐⭐⭐ | 贴近业务，会有实际场景改编题 | 字符串、动态规划、栈/队列、回文系列 |
| **美团** | ⭐⭐⭐⭐ | 中等偏上，有时考 Java 特定 API | 哈希表、排序、链表、模拟题 |
| **快手/拼多多** | ⭐⭐⭐⭐ | 类似字节风格 | DP、字符串、TopK |
| **百度/华为** | ⭐⭐⭐ | 相对传统，更考察基础 | 排序、搜索、基础数据结构 |

### 面试官追问常见方向

```
基础解法 → 优化解法 → 能否改成递归/迭代 → 
空间能否优化到 O(1) → 如果数据量扩大 10 倍怎么办 →
如果输入是流式的怎么办 → 能否用多线程加速
```

> ⚠️ **重要**：不要背题。面试官更看重你"能不能把思路说清楚"和"能不能在提示下自己想到优化方向"。

## 7. Java 刷题 vs C++/Python 刷题差异

| 方面 | Java | C++ | Python |
|:----|:----:|:---:|:-----:|
| **代码量** | 中等（需显式声明类型） | 中等（STL 较短） | 最短（脚本语言） |
| **输入输出** | `Scanner` / `System.out` | `cin`/`cout` | `input()`/`print()` |
| **字符串操作** | `String` 不可变，用 `StringBuilder` | `string` 可变 | `str` 不可变，但切片方便 |
| **排序** | `Arrays.sort()` / `Collections.sort()` | `std::sort()` | `list.sort()` / `sorted()` |
| **堆** | `PriorityQueue` | `std::priority_queue` | `heapq` |
| **哈希表** | `HashMap<K,V>` | `std::unordered_map` | `dict`（内置） |
| **大整数** | `BigInteger`（较麻烦） | 需手写或第三方库 | 原生支持大整数 |
| **Lambda 排序** | `(a,b) -> a - b` | `[](int a,int b){...}` | `lambda x: x[0]` |
| **调试体验** | IDE 强（IDEA 顶级） | IDE 不错 | 轻量但够用 |
| **面试手写** | 代码较长，需注意语法 | 指针操作易出错 | 代码简短，但不贴近 Java 后端 |

### Java 刷题优劣势

**优势**：
- 与后端面试语言一致，面试中写 Java = 展示语言功底
- 类型安全，调试时少出现类型错误
- 丰富的集合框架（HashMap/PriorityQueue/TreeMap 等）
- 社区最活跃，Java 题解最多

**劣势**：
- 代码量大，手写容易漏分号/类型声明
- 没有 C++ 的 `std::pair`，需要自己定义 Pair 或使用 `int[]`
- 基本类型与包装类型自动装箱有性能损耗
- 没有 Python 的列表切片 `[l:r]` 和 `a, b = b, a` 这类语法糖

> 💡 **建议**：刷题时用 Java，面试时也用 Java。不要用 Python 刷题再转 Java 面试——语法细节会暴露。

## 8. 使用建议

### 本系列适合谁

- ✅ 正在准备 Java 后端校招/社招面试的同学
- ✅ 已完成基础算法学习（至少看过《算法（第4版）》或类似课程）
- ✅ 需要系统化刷题规划而非零散刷题的同学
- ✅ 希望每一道题都有完整 Java 代码参考的同学

### 本系列不适合谁

- ❌ 算法零基础（建议先学完数据结构与算法基础课程再来）
- ❌ 只想看题解不想动手（看再多不如自己写一遍）
- ❌ 追求刷题数量而不是质量（本系列更重精讲和模板化）

### 学习建议

1. **按顺序学习**：建议从 01 开始，掌握了模板后再进入分类精讲
2. **每道题手写 3 遍**：
   - 第一遍：看完题解后默写
   - 第二遍：第二天不看题解写（检验短期记忆）
   - 第三遍：一周后限时 15 分钟写（检验是否真的会了）
3. **建立错题本**：记录每道题错的点和启发（参考 01 模块的刷题记录模板）
4. **限时训练**：面试前两周，每天随机 3 题限时 45 分钟
5. **组队监督**：找同学组队，每天互相抽查一道题，讲给对方听

> 🎯 **记住**：刷 300 道题但每道只过一遍，不如刷 100 道题每道过三遍。重复是记忆之母。
