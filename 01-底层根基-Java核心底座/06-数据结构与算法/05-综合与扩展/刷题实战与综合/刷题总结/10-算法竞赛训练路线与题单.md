# 10 算法竞赛训练路线与题单

> 竞赛训练的价值不在奖牌，而在"限时把陌生问题拆成已知模型"的能力。对求职者，它是算法能力的上限训练；对面试，它提供的是"看到题就知道用什么"的条件反射。这篇给出从零到高阶的阶段路线、题单与 Java 竞赛工程细节。

## 1. 先明确目标

竞赛训练有三条不同的目标线，投入方式完全不同：

| 目标 | 需要的深度 | 时间投入 | 产出 |
|------|-----------|---------|------|
| 面试算法 | LeetCode 中等 + 高频困难 | 3-6 个月，每天 1-2 小时 | 笔试通过、面试手撕 |
| 竞赛入门（ICPC 区域赛/省赛） | 铜牌到银牌 | 1-2 年，系统训练 | 奖项、保研加分 |
| 竞赛进阶（金牌/CF 高分） | 高阶算法 + 数学 | 2-3 年，高强度 | 顶级奖项 |

```text
对 2028 秋招 Java 后端 + AI 应用方向：
  目标线一足够
  竞赛是加分项，不是必需项
  先把 LeetCode 主线刷稳，再考虑补高阶
```

## 2. 阶段路线

### 2.1 阶段一：语言与基础（2-4 周）

```text
目标：
  能用 Java 快速实现任何模拟题
  能准确分析时间复杂度

内容：
  输入输出（BufferedReader、StringTokenizer）
  数组、字符串、集合（List/Map/Set/Deque）
  排序、二分查找
  递归与迭代
  复杂度分析（时间、空间、常数）
```

验收：

```text
能在 20 分钟内写完一道纯模拟题
能说出每道题的复杂度，并判断是否会超时
```

### 2.2 阶段二：基础算法（4-6 周）

```text
内容：
  枚举与剪枝
  前缀和、差分
  双指针、滑动窗口
  贪心（区间调度、排序不等式）
  二分答案
  归并排序与逆序对
  快速幂
```

验收：

```text
看到"最大/最小化某个值，且可行性单调" → 想到二分答案
看到"区间和/区间修改" → 想到前缀和/差分
```

### 2.3 阶段三：数据结构（4-6 周）

```text
内容：
  栈、队列、单调栈、单调队列
  堆（优先队列）
  哈希表
  并查集（路径压缩 + 按秩合并）
  树状数组
  线段树（区间和、区间最值、懒标记）
  平衡树（了解即可，Java 用 TreeMap）
```

验收：

```text
能手写并查集、树状数组、线段树模板
能判断"这题该用堆还是单调队列"
```

### 2.4 阶段四：图论（4-6 周）

```text
内容：
  图的存储（邻接表、链式前向星）
  DFS/BFS、连通分量
  拓扑排序
  最短路（Dijkstra、Bellman-Ford、Floyd）
  最小生成树（Kruskal、Prim）
  二分图判定与匹配（匈牙利）
  强连通分量（Tarjan）
  欧拉路径
```

验收：

```text
看到"最短路"能根据边权正负与数据范围选算法
能手写 Dijkstra + 优先队列
```

### 2.5 阶段五：动态规划（6-8 周）

```text
内容：
  线性 DP
  背包（01、完全、多重、分组）
  区间 DP
  树形 DP
  状压 DP
  数位 DP
  概率 DP
  单调队列/斜率优化（进阶）
```

验收：

```text
能把一个问题拆成"状态 + 转移 + 边界"
能判断状态是否可压缩
```

### 2.6 阶段六：字符串与数学（4-6 周）

```text
字符串：
  KMP、Z 函数
  字符串哈希
  Trie
  AC 自动机（进阶）
  后缀数组（竞赛）

数学：
  数论（gcd、exgcd、逆元、CRT）
  组合计数（组合数、容斥、卡特兰数）
  概率与期望
  博弈论（Nim、SG 函数）
  矩阵快速幂
  计算几何（凸包、叉积）
```

### 2.7 阶段七：高阶专题（长期）

```text
数据结构高阶：
  树链剖分
  虚树
  Link-Cut Tree
  莫队（普通/带修/树上/回滚）
  CDQ 分治
  整体二分
  可持久化数据结构

图论高阶：
  网络流（Dinic、费用流）
  2-SAT
  仙人掌
  支配树

字符串高阶：
  后缀自动机（SAM）
  后缀数组 + height

数学高阶：
  多项式（NTT）
  生成函数
  线性代数（矩阵树定理、高斯消元）
```

## 4. 训练方法

### 4.1 每日节奏

```text
工作日：
  1 道 LeetCode 中等（30-40 分钟）
  1 道竞赛题（40-60 分钟）

周末：
  1 场 Codeforces/AtCoder（2 小时）
  补题（2-3 小时）
```

### 4.2 补题法

```text
做完一场比赛后：
  ① 把没做出来的题重新独立思考 30 分钟
  ② 看题解，理解核心转化
  ③ 不看题解重写一遍
  ④ 总结"这题属于哪个模型、关键一步是什么"
  ⑤ 一周后重做

重点不是"看懂题解"，而是"下次能自己想到"
```

### 4.3 模板库

```text
维护自己的模板库：
  并查集、树状数组、线段树
  最短路、MST、拓扑
  KMP、Trie、字符串哈希
  DP 常见转移

要求：
  每个模板能在 5 分钟内默写
  模板必须经过至少 3 道题验证
```

### 4.4 对拍

```text
对拍 = 用暴力程序验证优化程序的正确性

步骤：
  ① 写暴力（保证正确，允许慢）
  ② 写优化（待验证）
  ③ 写随机数据生成器
  ④ 循环运行，比较输出
  ⑤ 发现不同 → 缩小数据 → 定位 bug

工具：
  Windows 批处理 / Shell 脚本
  竞赛环境可用 C++ 对拍，Java 也可以
```

### 4.5 复盘

```text
每道错题记录三件事：
  ① 错在哪：思路、边界、实现、读题
  ② 正确模型是什么
  ③ 下次遇到什么信号应该想到它

复盘笔记比刷题数量更重要
```

## 5. Java 竞赛工程细节

### 5.1 快速输入

```java
import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStreamReader;
import java.util.StringTokenizer;

public class FastInput {

    private static final BufferedReader READER =
            new BufferedReader(new InputStreamReader(System.in));
    private static StringTokenizer tokenizer;

    public static String next() throws IOException {
        while (tokenizer == null || !tokenizer.hasMoreTokens()) {
            tokenizer = new StringTokenizer(READER.readLine());
        }
        return tokenizer.nextToken();
    }

    public static int nextInt() throws IOException {
        return Integer.parseInt(next());
    }

    public static long nextLong() throws IOException {
        return Long.parseLong(next());
    }
}
```

`Scanner` 在 $10^5$ 级输入下可能慢 5-10 倍，竞赛一律用 `BufferedReader`。

### 5.2 快速输出

```java
StringBuilder output = new StringBuilder();
for (int value : result) {
    output.append(value).append('\n');
}
System.out.print(output);
```

避免在循环里 `System.out.println`。

### 5.3 递归深度

```text
Java 默认栈深度约 1 万层
树/图的 DFS 在 n=10^5 时会 StackOverflowError

方案：
  ① 改迭代（显式栈）
  ② 启动参数 -Xss64m（竞赛环境可能不允许）
  ③ 增大线程栈：new Thread(null, task, "main", 1 << 26).start()

推荐：能改迭代就改迭代
```

### 5.4 集合性能

```text
HashMap/HashSet 的常数远大于数组
  能用数组代替就用数组
  值域大时先离散化

TreeMap 的红黑树常数也大
  能用排序 + 二分就用排序
```

### 5.5 内存

```text
Java 对象开销大：
  int[] 比 ArrayList<Integer> 省 5-10 倍
  二维数组用一维展开
  避免在循环中创建对象

内存限制通常 256MB
  大数组预估：int[10^7] ≈ 40MB
```

### 5.6 常见超时原因

| 原因 | 处理 |
|------|------|
| `Scanner` 输入 | 换 `BufferedReader` |
| `System.out.println` 循环输出 | 换 `StringBuilder` |
| `ArrayList<Integer>` 存百万数据 | 换 `int[]` |
| 递归深度过大 | 改迭代 |
| `HashMap` 高频操作 | 换数组或离散化 |
| 字符串拼接 | 换 `StringBuilder` |

## 6. 比赛策略

```text
① 先读全部题目（5-10 分钟）
   按难度排序，不要按顺序做

② 先拿稳分
   简单题快速写完，确保不因低级错误丢分

③ 暴力打底
   想不出正解时，先写暴力拿部分分
   再想办法优化

④ 对拍
   正解写完后，用暴力对拍验证

⑤ 时间分配
   一道题卡 30 分钟没思路 → 跳过
   最后 30 分钟检查边界与多组数据

⑥ 读题
   注意数据范围、取模、多组数据、输出格式
   竞赛 50% 的罚时来自读题与边界
```

## 7. 与面试的关系

| 竞赛能力 | 面试收益 |
|---------|---------|
| 复杂度分析 | 快速判断解法是否可行 |
| 模板熟练 | 手撕代码不卡壳 |
| 模型识别 | 看到题就知道用 DP/图/二分 |
| 边界处理 | 减少 off-by-one 与空输入错误 |
| 限时编码 | 45 分钟手撕两道中等题 |

但竞赛与面试有明确差异：

```text
竞赛：
  追求最优解、卡常数、复杂模型
  代码可以很长

面试：
  追求可读、可解释、边界清晰
  更看重沟通与 trade-off 分析
  不会考 LCT/后缀自动机

结论：
  竞赛训练提升上限，但不要把竞赛代码风格带进面试
```

## 8. 常见误区

```text
① 只刷题不总结
   做了 500 道，遇到新题还是不会

② 只看题解不重写
   看懂了 ≠ 能写出来

③ 追求数量
   同一模型刷 50 道，不如精做 10 道 + 复盘

④ 跳过基础直接学高阶
   树链剖分会写，但并查集不熟

⑤ 不做对拍
   正解有 bug 却不知道

⑥ 用 Java 硬刚需要卡常数的题
   语言劣势存在，选适合的题

⑦ 把竞赛当求职唯一路径
   面试算法与工程能力才是主线
```

## 9. 小结

| 问题 | 答案 |
|------|------|
| 训练目标 | 面试主线优先，竞赛作为上限训练 |
| 阶段路线 | 语言 → 基础算法 → 数据结构 → 图论 → DP → 字符串数学 → 高阶 |
| 题单 | Hot 100 → 洛谷题单 → CF/AtCoder |
| 训练方法 | 每日一题、补题、模板库、对拍、复盘 |
| Java 要点 | 快读、快输、迭代 DFS、数组替代集合 |
| 比赛策略 | 先易后难、暴力打底、对拍、控时间 |
| 与面试 | 提升上限，但代码风格要切换 |
