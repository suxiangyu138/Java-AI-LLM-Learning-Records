## 1. 验证四件套

| 验证 | 做什么 | 抓什么错 |
|:---:|------|------|
| ① 样例走查 | 用题目样例手跑一遍代码 | 流程性错误、笔误 |
| ② 极端数据 | n=0/1、全同、逆序、最大 n | 边界错误、溢出 |
| ③ 随机对拍 | 暴力版 vs 优化版，随机输入跑 10⁴ 组 | 逻辑错误 |
| ④ 复杂度实测 | 用最大数据构造测运行时间 | TLE、常数过大 |

> 💡 顺序固定：先样例（快），再极端（准），最后对拍（全）。前三步都在本地，提交前完成。

### 1.1 极端数据构造表（按题型）

| 题型 | 必测极端数据 |
|------|------|
| 数组题 | 空数组、单元素、全同值、严格逆序、最大长度 |
| 字符串题 | 空串、单字符、全同字符、超长串、含特殊字符 |
| 图题 | 单点、双点、完全图、稀疏图、有环、无环 |
| 树题 | 空树、单节点、链状（最坏深度）、满二叉树 |
| DP 题 | 边界状态（0 与 1）、不可达状态、最大 n |
| 数学题 | 0、1、负数、int 边界、模数边界 |

## 2. 调试：WA/TLE/RE 的归因诊断

### 2.1 错误类型速查

| 提交结果 | 大概率病因 | 排查顺序 |
|:---:|------|------|
| WA（答案错） | 边界、取模、思路缺陷 | 极端数据 → 对拍 |
| TLE（超时） | 复杂度超标、常数大、死循环 | 复杂度重估 → 找最坏输入测时 |
| RE/MLE（越界/超内存） | 数组越界、递归爆栈、开太多 | 检查索引 → 估算内存 |
| 编译错误 | 语法、import | 本地先编译 |

### 2.2 WA 排查路线图

```text
WA
 ├─ 极端数据测试
 │    ├─ n=0/1 挂 → 边界漏判
 │    ├─ 全同/逆序 挂 → 逻辑错误（排序、贪心假设）
 │    └─ 最大 n 挂 → 溢出（int→long）
 ├─ 随机对拍
 │    └─ 有差异 → 输出中间状态定位（print 关键变量）
 └─ 思路重审
      └─ 样例都过但 WA → 审题偏差（漏约束、误解题意）
```

### 2.3 定位技巧

| 技巧 | 做法 |
|------|------|
| 二分定位 | 注释掉后半段逻辑，看前半段输出是否正常 |
| 最小反例 | 对拍差异出现后，不断缩小输入直到最小可复现 |
| 中间态打印 | 循环内打印关键变量（l/r/ans/窗口内容） |
| 对照暴力 | 暴力版 + 优化版输出同输入逐行对比 |

## 3. WA 的四种病因

| 病因 | 典型表现 | 修复 | 占比 |
|------|------|------|:---:|
| 审题偏差 | 代码「对」但题意理解错 | 重读题面，逐条对照约束 | ~20% |
| 边界遗漏 | 空/单元素/首尾处理缺 | 边界清单过一遍（03 篇第 2 节） | ~40% |
| 溢出取模 | 大数错、负数模错 | 全部 long + 防负取模 | ~15% |
| 思路缺陷 | 反例能击穿 | 换模型或补状态（02 篇第 4 节） | ~25% |

> 🎯 关键结论：**边界遗漏是 WA 第一病因（约 40%）**——这就是为什么第③步强调「边界先行」。每次 WA 先归类再改，而不是随机改。

### 3.1 归因模板（每次 WA 填一次）

```text
题目：______  提交结果：WA（第 3 次）
归因：□审题 □边界 □溢出取模 □思路
具体位置：______
修正动作：______
下次同类预防：______
```

## 4. 对拍：验证的正确姿势

对拍 = 暴力版（保证正确，慢）+ 优化版（被测）+ 随机数据生成器，三件套循环比对：

```text
随机生成器 → 输入
    ├→ 暴力版 → 答案 A
    └→ 优化版 → 答案 B
A ≠ B 时输出输入 + 两个答案 → 定位最小反例
```

### 4.1 随机生成器要点

| 要点 | 说明 |
|------|------|
| 覆盖边界 | 随机大小：n 在 1..max 间随机，含极小值 |
| 覆盖特征 | 随机生成 50% 常规 + 25% 极值 + 25% 重复值 |
| 图/树题 | 保证生成的是合法的图/树（连通、无重边） |
| 跑量 | 常规 10³-10⁴ 组；发现差异后用二分法缩小 n 定位最小反例 |

### 4.2 对拍的适用场景

| 场景 | 是否适合对拍 | 说明 |
|------|:---:|------|
| 逻辑型算法（DP/贪心/搜索/模拟） | ✅ | 暴力好写，价值最高 |
| 性能型算法 | ❌ | 对拍只验证正确性，TLE 用最大数据实测 |
| 数学公式题 | ✅ | 小 n 暴力枚举验证公式 |
| 交互题 | ❌ | 对拍不适用，构造特殊输入 |

## 5. 调试实战案例：一次完整的 WA 排查

以「LC 322 零钱兑换」为例，模拟一次典型调试：

| 步骤 | 动作 | 发现 |
|------|------|------|
| 1 样例 | `[1,2,5], 11` → 3 ✓；`[2], 3` → -1？ | 输出 0，**WA** |
| 2 归因 | 不是边界（判空了），怀疑初始化 | 定位：dp 数组默认 0，未用 INF 标记不可达 |
| 3 修复 | `Arrays.fill(dp, INF); dp[0]=0` | 转移时 `dp[i-c]` 为 INF 的情况也要跳过 |
| 4 重测 | `[2], 3` → -1 ✓；`[1], 0` → 0 ✓ | 全过 |
| 5 归纳 | 「恰好装满 + 求最小」必须 INF 初始化 | 沉淀为背包模板的固定第一步 |

> 💡 本例的教训：**「0」与「不可达」在计数类 DP 里是两个不同的语义**——求方案数时 0 = 不可达，求最小时 INF = 不可达，混用必错。

## 6. 复盘归档：让错题增值

### 6.1 错题本字段（每题 10 分钟）

| 字段 | 内容 | 示例 |
|------|------|------|
| 题目 | 题号 + 一句话题意 | LC 300 最长递增子序列 |
| 专题 | 归入哪个专题 | 专题 8 动态规划 |
| 方法 | 核心思路一句话 | 二分优化 LIS O(n log n) |
| 错因 | 四类之一 + 细节 | 边界：dp 初始化漏 -1 |
| 模板 | 沉淀的代码骨架 | 二分 LIS 模板 |
| 同类 | 同方法的其他题 | LC 354 俄罗斯套娃 |

### 6.2 复盘的三个层次

| 层次 | 动作 | 产出 |
|:---:|------|------|
| 一 归因 | 这次 WA 是什么类型？ | 一张错因统计表（发现自己 60% 错在边界 → 加强 03 篇清单） |
| 二 归类 | 这题属于哪个专题、用了什么模型？ | 专题熟练度雷达图 |
| 三 归纳 | 这类题的通法是什么？ | 自己的模板库（而不是抄网上的） |

### 6.3 刷题复利曲线

| 阶段 | 刷题方式 | 效果 |
|:---:|------|------|
| 前 50 题 | 按专题刷，每题复盘 | 建立每个专题的母题感 |
| 50-150 题 | 混刷，定时（30 分钟无思路看答案） | 训练审题定档与专题切换 |
| 150 题+ | 二刷错题本 + 限时模拟 | 巩固弱项，形成肌肉记忆 |

> 🎯 **核心要点**：验证 = 提交前四件套（样例/极端/对拍/测时）；调试 = 先归因再动手（WA 四类：审题 20% / 边界 40% / 溢出 15% / 思路 25%）；复盘 = 错题四字段归档（专题/方法/错因/模板）。**做题不复盘等于白做——复盘是把一道题的解法变成一类题的钥匙。** 第 5 节的调试案例值得亲手重现：从「输出 0」到「INF 初始化」的 5 步，就是一次标准的归因式调试。
