## 1. 定档的本质：约束 → 复杂度 → 算法

```text
题面给出：n ≤ 10³ 或 n ≤ 10⁵ 或 n ≤ 10⁹
    │
    ▼（1 秒 ≈ 10⁷-10⁸ 次基础操作；Java 通常按 10⁷ 保守估）
能承受的复杂度：O(n²) / O(n log n) / O(n) / O(log n) / O(1)
    │
    ▼
候选算法被过滤到 1-2 个 → 再结合「操作类型」做最终选型
```

三组数据范围的「标准答案」（务必背熟）：

| n 的范围 | 能用的复杂度 | 典型算法 |
|:---:|:---:|------|
| n ≤ 20 | O(2ⁿ)、O(n!) | 暴力枚举、状态压缩 DP |
| n ≤ 100 | O(n³) | Floyd、区间 DP、三重循环 |
| n ≤ 10³ | O(n²) | 杨辉三角、朴素 DP、双重循环 |
| n ≤ 10⁵ | O(n log n) | 排序、二分、线段树、Dijkstra+堆、KMP |
| n ≤ 10⁶ | O(n) / O(n log n) 常数小 | 线性筛、前缀和、双指针、滑动窗口 |
| n ≤ 10⁹ | O(log n)、O(√n) | 二分答案、快速幂、欧拉函数、试除 |
| n ≤ 10¹⁸ | O(log n) | 矩阵快速幂、Lucas、exgcd、快速乘 |

### 1.1 为什么这是「免费提示」

| 出题人意图 | 数据范围设计 | 期望解法 |
|------|------|------|
| 考朴素模拟 | n ≤ 10³ | O(n²) 即可 |
| 考排序/二分 | n ≤ 10⁵ | O(n log n) 是目标 |
| 考贪心/双指针 | n ≤ 10⁶ | O(n) 是目标 |
| 考数学/倍增 | n ≤ 10¹⁸ | O(log n)，暗示矩阵/快速幂 |
| 考状态压缩 | n ≤ 20 | O(2ⁿ·n)，n 就是状态位数 |

> 💡 反过来说：如果 n ≤ 20 你却想 O(n³) DP——大概率读错了题（出题人通常把「需要位运算/枚举」的信号藏在 20 这个数字里）。

## 2. 复杂度定档对照表

### 2.1 执行次数速查（Java，1 秒）

| 复杂度 | 1 秒内能跑的规模 | 说明 |
|:---:|:---:|------|
| O(n) | 10⁷-10⁸ | 常数为 2-3 倍时降到 5×10⁶ 也要小心 |
| O(n log n) | 10⁶-10⁷ | 排序类最稳 |
| O(n²) | 10⁴ | 5×10³ × 5×10³ = 2.5×10⁷ 勉强 |
| O(n³) | 10²-10³ | n=500 时 1.25×10⁸ 危险 |
| O(2ⁿ) | ≤ 20-22 | 剪枝好的回溯可放宽到 25-30 |
| O(n!) | ≤ 10 | 只有全排列类 |

### 2.2 常数因子的影响（易被忽略）

| 操作 | 相对代价 | 说明 |
|------|:---:|------|
| 数组访问 | 1 | 基准 |
| HashMap 操作 | 5-10 | 哈希计算 + 冲突处理 |
| 对象创建 | 10-20 | GC 压力 |
| 递归调用 | 20-50 | 栈帧开销 |
| 字符串拼接（+） | 100+ | 每次都 new 对象 |

> ⚠️ 同一 O(n log n)：`Arrays.sort` 比「TreeSet 逐个插入」快一个量级——**大 O 只承诺趋势，常数决定生死**。

### 2.3 隐藏定档信号（易错）

| 信号 | 真实含义 | 常见误判 |
|------|------|------|
| 「求方案数 / 最大值」 | 可能 DP，也可能贪心 | 直接套 DP 忽略贪心可能 |
| 「n 次查询，每次 O(n)」 | 总 O(n·q)，注意 q 也计入 | 只算单次 O(n)，忘乘 q |
| 「值域 ≤ 10⁶」 | 可能用计数/值域数组换时间 | 只盯着 n 忘了值域也决定复杂度 |
| 「多组数据 T」 | 总复杂度要乘 T | 每组 O(n log n) 而 T=10⁵ → 爆 |
| 「答案取模 1e9+7」 | 结果巨大，暗示组合/DP 计数 | 忘了取模/用错模数 |
| 「无自环、无重边」 | 图算法的边界前提 | 忽略后 Dijkstra 等出错 |
| 「保证连通」 | 可省并查集判连通 | 多写判连通反而超时 |

## 3. 读题清单：信息提取八问

每题读题时过一遍这八问，能覆盖 95% 的审题遗漏：

| # | 问题 | 例子 |
|:---:|------|------|
| 1 | 输入规模多大？几个变量？ | n 和 m 是两个独立范围 |
| 2 | 数值范围？是否可能溢出 / 负数？ | 求和用 long？负 index？ |
| 3 | 结果要什么形态？个数 / 方案 / 路径 / 序列？ | 求方案数 vs 求最优值不同路 |
| 4 | 是否取模？模数什么性质（质数/合数）？ | 合数模不能费马逆元 |
| 5 | 有无重复 / 无序 / 可重用限制？ | 「每个元素只能用一次」→ 背包类型 |
| 6 | 图还是树？有向无环？连通保证？ | 「保证连通」省略并查集判连通 |
| 7 | 特殊输入：空、全同、单元素？ | 空数组、n=1、全 0 |
| 8 | 时间限制与内存限制？ | 2 秒 vs 1 秒；数组能开多大 |

### 3.1 八问的输出格式（30 秒内完成）

```text
输入：n ≤ 10⁵, 值域 ≤ 10⁹      → 复杂度目标 O(n log n)
操作：区间最值 + 单点修改        → 线段树
模数：1e9+7（质数）             → 费马逆元可用
输出：方案数                    → 计数类，注意取模
特殊：元素可重复使用             → 完全背包
```

## 4. 从复杂度到算法选型

定档出复杂度后，用「操作类型」二次过滤：

| 操作类型信号 | 候选算法 | 复杂度档 |
|------|------|:---:|
| 查询区间最值/和，可离线 | 前缀和、差分、ST 表、线段树 | O(n log n) 建 |
| 查询区间最值，需在线修改 | 线段树、树状数组、分块 | O(log n) 次 |
| 求第 k 大 / TopK | 堆、快选（partition）、平衡树 | O(n log k) / O(n) |
| 匹配 / 最长回文 / 模式串 | KMP、Manacher、哈希 | O(n) |
| 图上最短路 | BFS（无权）/ Dijkstra（非负权）/ SPFA（负权） | O(n+m)~O(mlog n) |
| 有向无环依赖处理 | 拓扑排序（+ DP） | O(n+m) |
| 计数类（方案数、取模） | 组合数、DP、容斥 | 视 n 定 |
| 大数幂 / 递推加速 | 快速幂、矩阵快速幂 | O(log n) |
| 判断素数 / 质因数分解 | 试除 √n、线性筛、Miller-Rabin | O(√n) / O(n) |

> 💡 选型口诀：**「值域换时间」优先**（桶/计数数组），**「排序降维」其次**（先排序再扫描），**「二分换对数」兜底**（答案单调时二分）。三个思路能解决一半的「没思路」题。

## 5. 完整推演：一道题的三次定档

以「求数组第 k 大元素」为例，展示定档 → 选型的完整链路：

| 轮次 | 约束 | 定档 | 选型 | 结论 |
|:---:|------|------|------|------|
| 1 | n ≤ 10⁴ | O(n²) 可用 | 排序后取下标 O(n log n) | 最稳妥 |
| 2 | n ≤ 10⁷（流式） | O(n log n) 危险 | 维护 k 大小堆 O(n log k) | 内存 k，可流式 |
| 3 | n ≤ 10⁹ 但值域 ≤ 10⁶ | O(n) 目标 | 值域计数 + 前缀和找第 k | 桶计数，免排序 |

再以「子数组和等于 k 的个数」定档：

| 约束 | 定档 | 选型 |
|------|------|------|
| n ≤ 10³ | O(n²) | 双层枚举前缀和差 |
| n ≤ 10⁶ | O(n) | 哈希表存前缀和出现次数（边算边查） |
| n ≤ 10⁶ 且值域小 | O(n) | 计数数组替代哈希（常数更小） |

> 🎯 规律：**同一个题，约束不同答案的「正解」就不同**——这就是定档的价值。能根据数据范围说出「这题 O(n log n) 是目标复杂度」，面试已经过了一半。

## 6. 定档错误的自救

| 情况 | 症状 | 自救策略 |
|------|------|------|
| 复杂度估高了 | 提交 TLE，本地小数据过 | 检查是否有 O(n) 的计数/哈希/双指针替代 O(n log n) |
| 复杂度估低了 | 思路对但 WA，边界没覆盖 | 回读约束，补上大数据的复杂度论证 |
| 隐含维度忘了 | 数组题没看到「值域 ≤ 10⁵」 | 重读题面数值，值域也是输入维度 |
| 常数过大 | 同为 O(n log n) 也 TLE | 用快读（BufferedReader 手写）、减少取模、数组代替集合 |
| 溢出 | 大数求和用 int | 全部涉及求和/乘法的量默认 long，必要时快速乘 |

### 6.1 TLE 的二次诊断

```text
TLE
 ├─ 复杂度超标？→ 重新定档（回第 1-2 节），换低一档算法
 ├─ 常数太大？→ 快读 / 数组替代集合 / 减少取模 / 避免装箱
 └─ 死循环？→ 二分模板检查（l=mid 陷阱）、while 终止条件
```

> 🎯 **核心要点**：审题定档 = 三行推导——**约束大小 → 复杂度上限 → 候选算法**。数据范围是题目给的「免费提示」，它直接告诉你出题人期望的复杂度。读题花 5 分钟完成定档，比提交后看 TLE 再回头改省 10 倍时间。第 5 节的两次推演值得各手推一遍，把「定档思维」变成条件反射。
