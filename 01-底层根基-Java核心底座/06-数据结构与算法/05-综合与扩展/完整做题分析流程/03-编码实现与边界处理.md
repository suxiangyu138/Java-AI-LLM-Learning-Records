## 1. 编码的节奏：骨架 → 边界 → 细节

```text
① 骨架：函数签名 → 空方法体 → 主流程（注释写清每一步对应伪代码哪行）
② 边界：n=0/1、空输入、极端值的处理先写在最前面（early return）
③ 细节：循环边界、取模、溢出、索引变换
```

| 层次 | 时间占比 | 常见错误 |
|:---:|:---:|------|
| 骨架 | 20% | 直接写细节，主流程混乱 |
| 边界 | 30% | 忘判空、忘判单元素 |
| 细节 | 50% | 边界写错 ±1、忘取模 |

> 🎯 关键认知：**边界不是「细节」，是「第一公民」**——先写 early return 的空/单元素处理，再写主体，错误率下降一半。

### 1.1 为什么骨架先行能防错

| 做法 | 效果 |
|------|------|
| 先写签名与注释 | 强迫自己说清「输入是什么、输出是什么」 |
| 主流程留桩 | 每个子功能单独填，不会「一锅烩」 |
| 注释对应伪代码行号 | 编码 ↔ 思路可对照检查 |

## 2. 边界条件全清单

### 2.1 通用边界（每道题都要过）

| 边界 | 检查点 | 示例代码 |
|------|------|------|
| 空输入 | 数组长度 0、字符串空 | `if (arr == null \|\| arr.length == 0)` |
| 单元素 | n=1 是否进循环 | 循环 `i < n` 而非 `i <= n` |
| 首尾 | 第一个和最后一个元素 | 双指针 l/r 相遇条件 |
| 越界 | `i+1`、`i-1`、`i+k` 是否越界 | 循环终止条件严格 `i + k < n` |
| 溢出 | 求和、乘法、绝对值 | 用 long；`-Integer.MIN_VALUE` 仍溢出 |
| 取模 | 负数取模在 Java 得负 | `((x % p) + p) % p` |
| 整除 | 除法是否整除 | 逐项乘除保证每步整除 |

### 2.2 分场景边界

| 场景 | 必查项 |
|------|------|
| 二分查找 | `l <= r` vs `l < r`；死循环（mid 永不变）；`l + (r-l)/2` 防溢出 |
| 双指针 | 相遇时是否处理；快慢指针越界顺序（先动快的，检查 null） |
| 链表 | 头节点删除；`cur.next.next` 空指针；环检测快慢指针 |
| 树 | 空树；单节点；深度可能达 n（递归爆栈 → 转迭代） |
| DP | dp 数组初始化；`dp[0]` 语义；状态转移的下标范围 |
| 图 | 孤立节点；自环；重边；无向图两次加边 |
| 滑动窗口 | 窗口收缩时机；右移与左移的顺序 |
| 字符串 | 空串；全空格；大小写；Unicode 代理对 |

### 2.3 边界写错的典型 WA 形态

| 边界 | 错误代码 | 正确代码 |
|------|------|------|
| 空数组 | `int m = arr.length; ...` 直接用 | 先判 `arr == null \|\| len == 0` |
| 单元素 | `for (i = 0; i <= n; i++)` 越界 | `i < n`，或单独处理 n=1 |
| 二分下界 | `mid = (l + r) / 2` l=r 时死循环 | 模板三件套（坑点 03 篇 §1） |
| 滑动窗口 | 先更新答案再收缩（统计到非法窗） | 先收缩到合法再统计 |
| 取模负数 | `(a - b) % p` 得负 | `((a - b) % p + p) % p` |

## 3. Java 编码高频细节

| # | 细节 | 正确写法 | 错误写法 |
|:---:|------|------|------|
| 1 | 读入 | `BufferedReader + StringTokenizer` | `Scanner`（慢 10 倍） |
| 2 | 输出 | 攒 `StringBuilder` 一次性输出 | 每行 `System.out.println` |
| 3 | 排序 | `Arrays.sort(long[])` | 用 `Collections` 装箱浪费 |
| 4 | 取模 | `((a % m) + m) % m` 防负 | `a % m` 负数得负 |
| 5 | 乘法溢出 | `long` 承载；超 1e18 用快速乘 | int × int 直接溢出 |
| 6 | 幂运算 | 快速幂 | `Math.pow` 丢精度 |
| 7 | 二维数组 | 先行后列访问（缓存友好） | 列优先导致缓存抖动 |
| 8 | 比较器 | `Integer.compare(a, b)` | `a - b` 溢出 |
| 9 | 字符串拼接 | `StringBuilder.append` | `+` 循环拼接 |
| 10 | 递归深度 | 深递归转栈/迭代 | 100k 层递归 StackOverflow |

### 3.1 快速乘模板（模数超 1e18 时）

```java
/** 快速乘：a*b mod p，防止 long 溢出（加法二分） */
long mulMod(long a, long b, long p) {
    long res = 0;
    while (b > 0) {
        if ((b & 1) == 1) res = (res + a) % p;
        a = (a << 1) % p;
        b >>= 1;
    }
    return res;
}
```

### 3.2 快读模板（竞赛标配）

```java
/** 快读：整数流，10⁶ 级输入必备 */
static java.io.BufferedReader br = new java.io.BufferedReader(new java.io.InputStreamReader(System.in));
static java.util.StringTokenizer st;

static long nextLong() throws Exception {
    while (st == null || !st.hasMoreTokens()) st = new java.util.StringTokenizer(br.readLine());
    return Long.parseLong(st.nextToken());
}
```

## 4. 面试手写代码的加分写法

| 加分项 | 做法 | 效果 |
|------|------|------|
| 先说后写 | 报出复杂度 + 思路再动手 | 让面试官跟上 |
| 骨架先行 | 先写函数签名和注释 | 展示结构化思维 |
| 命名清晰 | `left/right`、`maxWindow` | 可读性即正确性 |
| 防御式判空 | early return 边界 | 减少追问 |
| 注释关键行 | 只在**易错点**注释 | 展示「我知道坑在哪」 |
| 主动走查 | 写完用 n=3 的样例手动跑一遍 | 面试官最看重 |
| 复杂度收尾 | 最后报时间/空间复杂度 | 完整闭环 |

> ⚠️ 面试手写与竞赛写作的区别：面试**可读性优先**（命名、注释、分层），竞赛**常数优先**（位运算、快读）。两者不要混用。

### 4.1 面试走查示范（LC 206 反转链表）

```text
面试官：讲一下思路
答：三指针 prev/cur/next，cur 指向头，每步先存 next，再改 cur.next 指向 prev，
    三者各前进一位，最后 prev 即新头。O(n) 时间 O(1) 空间。
（写完代码后）
面试官：怎么验证？
答：用 1→2→3 走查：第一步 cur=1 存 next=2，1.next→null；第二步 cur=2，next=3，
    2.next→1；第三步 cur=3，next=null，3.next→2；循环结束 prev=3 即新头 ✓
```

## 5. 写完即自查：五分钟清单

| # | 自查项 | 确认方式 |
|:---:|------|------|
| 1 | 空输入、单元素过吗？ | 加 n=0/1 手动走查 |
| 2 | 循环边界 ±1 对吗？ | 检查 `<=` vs `<`，`i+1` 越界 |
| 3 | 所有 int 换成 long 了吗？ | 求和/乘法/下标计算处 |
| 4 | 取模统一了吗？负数处理了吗？ | `(x%m+m)%m` |
| 5 | 用到的集合 import 齐了吗？ | 编译一次 |
| 6 | 返回值语义对吗？ | 与题目输出格式一致 |
| 7 | 有重复计算吗？ | 循环内不变的量提出来 |
| 8 | 递归深度安全吗？ | 估算最大栈深 |

> 🎯 **核心要点**：编码不是「把想法打出来」，而是**三遍工程**——骨架（结构对）、边界（首尾对）、细节（±1 对）。写完不要急着交，五分钟自查清单走一遍：空输入、单元素、越界、溢出、取模、递归深度——六项全过再提交，WA 率大幅下降。面试加分的关键不是「写得快」而是「说得出为什么这么写」。
