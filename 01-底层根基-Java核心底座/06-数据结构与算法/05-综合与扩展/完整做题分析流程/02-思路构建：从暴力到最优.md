## 1. 思路构建的三条路

| 路 | 思路 | 适用 |
|:---:|------|------|
| A 暴力出发 | 先写朴素解（保证正确），逐步优化 | 一切题型的起点 |
| B 换模型 | 把问题翻译成已知模型（图/区间/序列/计数） | 题干包装陌生的题 |
| C 逆向思考 | 从答案出发反推条件（二分答案、贪心反证） | 「最大化最小」「最少操作」 |

> 💡 三条路不是三选一，而是**依次尝试**：先 A 保证理解，A 卡住用 B 换视角，B 没思路用 C 反推。

### 1.1 换模型的常见翻译表

| 题面包装 | 真实模型 |
|------|------|
| 「课程依赖关系」 | 拓扑排序 / 环检测 |
| 「最少传递次数」 | BFS 最短路 |
| 「分成若干组，组内互不冲突」 | 二分图 / 图着色 |
| 「选几个使总价值最大且不超容量」 | 背包（0-1/完全/分组） |
| 「任意前缀不越界」 | 卡特兰数 |
| 「两两配对的最小总代价」 | 排序 + 相邻配对（贪心） |
| 「区间上多次询问」 | 前缀和 / 线段树 / 离线排序 |

## 2. 暴力到最优的七级阶梯

以「求最长无重复子串长度」为例展示完整阶梯：

| 级 | 思路 | 复杂度 | 关键动作 |
|:---:|------|:---:|------|
| 1 暴力枚举 | 枚举所有子串 + 检查是否重复 | O(n³) | 保证题意理解 |
| 2 去掉无效检查 | 检查用哈希集 | O(n²) | 常数优化 |
| 3 剪枝 | 长度上界 = n - 起点 | O(n²) | 提前结束 |
| 4 双指针 | 窗口 [l, r] 维护，重复时右移 l | O(n) | **滑动窗口** |
| 5 哈希表定位 | 记录字符最后位置，l 直接跳 | O(n) | 值域换时间 |
| 6 位图/数组 | 字符集有限时用 int[128] | O(n) | 空间换常数 |
| 7 工程化 | 处理 Unicode 代理对等细节 | O(n) | 正确性完善 |

> 🎯 阶梯的规律：**1→4 是质的飞跃**（枚举→维护），4→7 是常数优化。面试时说到「4 双指针」已达标，能讲出 5 的哈希优化是加分项。

### 2.1 各级的适用判断

| 问题 | 判断 |
|------|------|
| 什么时候停在 3（剪枝）？ | n ≤ 10⁴ 且面试时间紧——O(n²) 剪枝可过小数据 |
| 什么时候必须到 4（滑动窗口）？ | n ≤ 10⁵+，或面试官提示「一次遍历」 |
| 什么时候用 5（哈希定位）？ | 窗口收缩不是「逐格」而是「跳跃」时 |
| 什么时候用 6（数组）？ | 字符集已知（如 ASCII 128 / 小写 26） |

## 3. 代码演化实录：最长无重复子串

### 3.1 暴力版（级 1-2）：理解题意的基准

```java
/** 级 2：枚举子串 + HashSet 查重，O(n²) */
public int lengthOfLongestSubstring(String s) {
    int n = s.length(), ans = 0;
    for (int i = 0; i < n; i++) {
        Set<Character> seen = new HashSet<>();
        for (int j = i; j < n; j++) {
            if (seen.contains(s.charAt(j))) break;   // 重复 → 换起点
            seen.add(s.charAt(j));
            ans = Math.max(ans, j - i + 1);
        }
    }
    return ans;
}
```

### 3.2 滑动窗口版（级 4）：质的飞跃

```java
/** 级 4：窗口 [l, r]，重复时右移 l，O(n) */
public int lengthOfLongestSubstring(String s) {
    Set<Character> window = new HashSet<>();
    int l = 0, ans = 0;
    for (int r = 0; r < s.length(); r++) {
        char c = s.charAt(r);
        while (window.contains(c)) {        // ⚠️ 收缩：先移出再右移
            window.remove(s.charAt(l));
            l++;
        }
        window.add(c);
        ans = Math.max(ans, r - l + 1);
    }
    return ans;
}
```

### 3.3 哈希定位版（级 5）：l 直接跳跃

```java
/** 级 5：记录每个字符最近位置，l 直接跳到重复位 +1，O(n) */
public int lengthOfLongestSubstring(String s) {
    int[] last = new int[128];              // 字符 → 最近位置（0 基）
    Arrays.fill(last, -1);
    int l = 0, ans = 0;
    for (int r = 0; r < s.length(); r++) {
        int c = s.charAt(r);
        if (last[c] >= l) l = last[c] + 1;  // 重复：跳过（不是逐格收缩）
        last[c] = r;
        ans = Math.max(ans, r - l + 1);
    }
    return ans;
}
```

> 💡 三版代码的对照价值：面试官追问「能不能再优化」时，从 3.2 到 3.3 的跳跃就是标准答案；3.1 到 3.2 的 while 收缩逻辑是滑动窗口模板。

## 4. 常见优化手段一览与适用边界

| 手段 | 原理 | 典型场景 | 效果 | **不适用场景** |
|------|------|------|:---:|------|
| 前缀和/差分 | 区间和转两点差 | 子数组和、二维区域和 | O(n²)→O(n) | 需要区间最值（非可减运算） |
| 哈希/计数数组 | 查找 O(1) | 两数之和、判重、频次 | O(n log n)→O(n) | 需要有序遍历（用 TreeMap） |
| 双指针/滑动窗口 | 单调区间维护 | 子数组、链表环 | O(n²)→O(n) | 窗口约束不可单调收缩（含负权） |
| 排序预处理 | 有序化降低判断成本 | 区间合并、贪心题 | O(n²)→O(n log n) | 需要保留原顺序（存 index 对） |
| 二分 | 单调性换对数 | 有序查找、答案二分 | O(n)→O(log n) | 检查函数不单调 |
| 记忆化 | 重叠子问题复用 | 递归 DP、DFS 剪枝 | 指数→多项式 | 子问题独立（用分治） |
| 单调栈/队列 | 维护候选集 | 下一个更大元素、窗口最值 | O(n) | 需要全区间有序性（用线段树） |
| 值域数组/位图 | 压缩空间 | TopK 频次、去重 | 空间换时间 | 值域超大（1e9）时用哈希 |
| 快速幂/倍增 | 幂与跳跃对数化 | 大幂、LCA、稀疏表 | O(n)→O(log n) | 递推必须 O(n) 建表 |

### 4.1 优化路线图（决策顺序）

```text
第一问：能先排序吗？          → 排序 + 扫描（贪心/双指针/二分）
第二问：能预处理吗？          → 前缀和 / 哈希表 / 计数数组
第三问：有单调性吗？          → 二分答案 / 双指针
第四问：有重叠子问题吗？      → DP（记忆化）
第五问：是序列+最值类吗？     → 单调栈 / 单调队列
```

> ⚠️ 「不适用场景」列是本表的精华——面试答「为什么不用前缀和」时，说出「区间最值不可减」就是区分度答案。

## 5. 反例检验：思路的最后一关

思路成型后**先找反例，再写代码**——反例 3 分钟，改代码 30 分钟：

| 反例类型 | 测试思路的方法 |
|------|------|
| 最小输入 | n=0、n=1、空数组/空串 |
| 全同输入 | 全 0、全相等字符 |
| 逆序/有序 | 单调递减、单调递增 |
| 极值 | 最大 n、int 边界、负数 |
| 边界条件 | 「恰好」成立与「恰好」不成立之间 |
| 贪心/DP 反例 | 刻意构造「局部最优 ≠ 全局最优」的输入 |

### 5.1 贪心思路的必答三问

| # | 问题 | 反例模板 |
|:---:|------|------|
| 1 | 局部最优会锁死全局吗？ | 「选最大起步」导致后续全废 |
| 2 | 决策顺序影响结果吗？ | 先处理 A 与先处理 B 结果不同 |
| 3 | 有没有「先吃亏后占便宜」？ | 牺牲眼前换未来更大收益 |

> 💡 能对贪心思路说出反例 → 这题大概率不是贪心，转 DP；DP 思路的反例比较少见，重点查「状态定义是否漏信息」。

### 5.2 DP 状态的反例检查清单

| 检查 | 说明 |
|------|------|
| 状态是否覆盖所有决策信息？ | 「第 i 天是否持有」漏掉就错 |
| 转移是否漏分支？ | 「继承 vs 转移」两分支都写了吗 |
| 边界初始化语义？ | dp[0] 代表「空」还是「第一个」 |
| 有后效性吗？ | 转移依赖未来 → 调整状态或顺序 |

## 6. 常见卡壳场景与破局

| 卡壳场景 | 破局动作 |
|------|------|
| 完全没思路 | 回到暴力级，先写出「枚举所有可能」的朴素解，再问优化三问 |
| 思路 O(n²) 超时 | 检查四个优化开关：排序、前缀和、哈希、单调栈 |
| 思路正确但实现复杂 | 拆分：先写主流程 + 桩函数，逐步填 |
| DP 状态不会定义 | 从「答案需要什么」倒推：最终状态 = 目标，往前补子状态 |
| 题目包装陌生 | 提取数据形态：是序列？树？图？集合？套对应模型 |
| 答案巨大/取模 | 立即想到计数类（组合/DP），检查是否要逆元 |
| 思路被反例击穿 | 不是失败：说明问题需要更强模型（贪心→DP→状态压缩） |

### 6.1 伪代码的规范（思路阶段的产出）

```text
输入：n, arr[]
输出：最长无重复子串长度
1. l = 0, ans = 0, last[128] = -1      # 哈希定位（级 5）
2. for r in 0..n-1:
3.     if last[arr[r]] >= l:            # 重复：收缩左界
4.         l = last[arr[r]] + 1
5.     last[arr[r]] = r                 # 更新最近位置
6.     ans = max(ans, r - l + 1)
7. return ans
复杂度：O(n) 时间 O(1) 空间（字符集固定）
```

> 🎯 **核心要点**：思路阶段的三条纪律——**① 暴力先行**（正确性参照系）、**② 优化走决策顺序**（排序→预处理→单调性→DP）、**③ 写完找反例**（贪心重点）。第 3 节的代码演化实录建议亲手打一遍三版代码，体会「同一道题三种复杂度」的转化手感。伪代码留在草稿上，正文代码是第③步的事。
