## 3. 工程算法 vs 竞赛算法

| 维度 | 竞赛算法 | 工程算法 |
|------|------|------|
| 目标 | 正确 + 复杂度最优 | 正确 + **可维护 + 内存可控 + 并发安全** |
| 数据 | 一次性、已知范围 | 海量、持续增长、不确定分布 |
| 环境 | 单线程理想化 | 多线程、磁盘/网络/GC 现实约束 |
| 复杂度 | 大 O 是硬指标 | 常数因子、缓存、IO 次数同样关键 |
| 经典差异 | 快排随手写 | JDK 用双轴快排 + TimSort + 插入兜底 |

> 💡 例证：竞赛里 O(n log n) 就够了；工程里 MySQL 索引选 B+树而非哈希——因为范围查询 + 磁盘 IO 次数（树高=IO 次数）才是真实瓶颈。**工程选型看的是「真实成本」，不只是大 O。**

### 3.1 三个「竞赛正确但工程不行」的例子

| 例子 | 竞赛思路 | 工程问题 |
|------|------|------|
| 快排写最简版 | 取首元素做 pivot | 有序输入退化 O(n²) → 工程用三数取中/随机化 |
| HashMap 自实现 | 简单链地址 | 不考虑负载因子/扩容/并发 → JDK 精细调参 |
| 递归处理大数组 | 深递归 | 10⁵ 层爆 JVM 栈 → 工程必须转迭代/分治阈值 |

## 5. 面试中的应用场景

| 面试环节 | 工程算法怎么加分 |
|------|------|
| 手写算法题 | 写完后补一句「工程里 JDK 会怎么做」（TimSort、懒加载） |
| 八股追问 | HashMap/Redis/MySQL 原理 = 数据结构实现题 |
| 系统设计 | LRU、一致性哈希、布隆过滤器是设计题的必答组件 |
| 深挖项目 | 自研缓存/分库分表/搜索方案都有算法内核 |

### 5.1 系统设计题的算法四件套（背熟）

```text
缓存：LRU/LFU（LinkedHashMap 实现 or 手写）
分片：一致性哈希 + 虚拟节点
去重/穿透：布隆过滤器
限流：令牌桶（允许突发）/ 漏桶（严格匀速）
```

### 5.2 工程视角的学习闭环（怎么用本系统）

```text
学习时：01 篇（JDK）→ 02 篇（中间件）→ 03 篇（数据库）→ 04 篇（搜索/AI）
对照时：学到 03 层专题（如堆）→ 回本系统 04 篇看「TopK 在推荐里怎么用」
复习时：每篇末尾的「面试问题清单」当口试抽题卡
项目时：写代码遇到性能问题 → 回本系统对「算法 = 组件」映射表
```

| 阶段 | 动作 | 产出 |
|:---:|------|------|
| 学专题时 | 专题学完 → 看映射表对应行 | 建立「算法 → 工程」第一连接 |
| 面试前 | 背四篇的问题清单（共 20 问） | 工程八股全覆盖 |
| 做项目 | 写缓存/分表/检索代码时对照实现 | 工程能力落地 |

> 🎯 **核心要点**：本系统把「数据结构与算法」和「后端技术栈」接上线——01 篇接 Java 集合、02 篇接分布式中间件、03 篇接数据库、04 篇接检索与 AI。**面试中「数据结构会背不会用」的断层，由本系统补齐**：每篇都是「算法原理 → 工程实现 → 选型决策」三段式。第 4 节的映射表是「算法 = 工程组件」的索引，面试前背熟一行对应关系，系统设计题就有话可说；第 5.2 节的学习闭环把它变成日常学习的一部分，而不是考前突击材料。
