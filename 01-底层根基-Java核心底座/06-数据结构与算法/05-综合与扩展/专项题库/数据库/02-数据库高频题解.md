## 1. 175. 组合两个表（LEFT JOIN）

### 1.1 题目与思路

```
Person + Address（有的 Person 无地址）→ 所有人 + 地址
LEFT JOIN（保留 Person 全部）
⚠️ 无地址时 Address 列为 NULL（符合题意）
```

### 1.2 完整 SQL

```sql
-- LeetCode 175. 组合两个表
SELECT p.firstName, p.lastName, a.city, a.state
FROM Person p
LEFT JOIN Address a ON p.personId = a.personId;
-- ⚠️ LEFT JOIN 而非 INNER：无地址的人也要出现（city/state 为 NULL）
-- ⚠️ 面试必答："175 是 LEFT JOIN 的最小样板——
--   主表全保留，匹配不到补 NULL。"
```

## 2. 176. 第二高的薪水

### 2.1 题目与思路

```
第二高薪水（不存在则 NULL）
排序 + OFFSET + 子查询（NULL 包装）
⚠️ 三个坑：重复值去重、第二不存在返回 NULL、排序方向
```

### 2.2 完整 SQL

```sql
-- LeetCode 176. 第二高的薪水
SELECT (
    SELECT DISTINCT salary
    FROM Employee
    ORDER BY salary DESC
    LIMIT 1 OFFSET 1        -- ⚠️ 跳过第 1 名
) AS SecondHighestSalary;
-- ⚠️ 关键：外层 SELECT 包装 →
--   子查询无结果时返回 NULL（而非空集）
-- ⚠️ DISTINCT：相同薪水只算一个名次

-- 窗口函数版（更通用）：
SELECT MAX(salary) AS SecondHighestSalary
FROM Employee
WHERE salary < (SELECT MAX(salary) FROM Employee);
-- ⚠️ 面试必答："176 三要素：DISTINCT 去重、
--   OFFSET 1 取第二、外层包装防 NULL。"
```

## 3. 177. 第 N 高的薪水

### 3.1 题目与思路

```
第 N 高（N 是参数）→ 存储函数封装
⚠️ OFFSET 不能直接用参数 → 函数内 N-1
```

### 3.2 完整 SQL

```sql
-- LeetCode 177. 第 N 高的薪水（存储函数）
CREATE FUNCTION getNthHighestSalary(N INT) RETURNS INT
BEGIN
    SET N = N - 1;               -- ⚠️ OFFSET 从 0 开始
    RETURN (
        SELECT DISTINCT salary
        FROM Employee
        ORDER BY salary DESC
        LIMIT 1 OFFSET N
    );
END;
-- ⚠️ 面试必答："177 = 176 的参数化——
--   LIMIT 1 OFFSET (N-1) 是核心；
--   函数封装解决'参数化 OFFSET'。"
```

## 4. 180. 连续出现的数字

### 4.1 题目与思路

```
出现至少连续 3 次的数字
三表自连接：id 连续 + num 相同
⚠️ 自连接模拟"滑动窗口"（id 相邻三行）
```

### 4.2 完整 SQL

```sql
-- LeetCode 180. 连续出现的数字
SELECT DISTINCT l1.num AS ConsecutiveNums
FROM Logs l1, Logs l2, Logs l3
WHERE l1.id = l2.id - 1        -- ⚠️ 三行 id 连续
  AND l2.id = l3.id - 1
  AND l1.num = l2.num
  AND l2.num = l3.num;         -- num 相同

-- 窗口函数版（更优雅，可扩展到任意 k）：
SELECT DISTINCT num AS ConsecutiveNums
FROM (
    SELECT num,
           id - ROW_NUMBER() OVER (PARTITION BY num ORDER BY id) AS grp
    FROM Logs
) t
GROUP BY num, grp
HAVING COUNT(*) >= 3;
-- ⚠️ 面试必答："连续检测两种写法——
--   自连接（k 固定时直观）与窗口函数
--   （id - 行号 = 连续段分组，可扩展 k）。"
```

## 5. 181. 超过经理收入的员工

### 5.1 题目与思路

```
员工收入 > 经理（同一表：managerId 指向经理）
自连接（员工表 × 经理表）
⚠️ 自连接的经典：一张表扮演两个角色
```

### 5.2 完整 SQL

```sql
-- LeetCode 181. 超过经理收入的员工
SELECT e.name AS Employee
FROM Employee e
JOIN Employee m ON e.managerId = m.id    -- ⚠️ 员工 JOIN 经理
WHERE e.salary > m.salary;
-- ⚠️ 面试必答："自连接 = 一张表两次出现——
--   e 是员工视角、m 是经理视角，
--   managerId 作为连接键。"
```

## 6. 184. 部门工资最高的员工

### 6.1 题目与思路

```
每个部门工资最高的人（可能有多个并列）
窗口函数：ROW_NUMBER 或 RANK（并列都要 → RANK/DENSE_RANK）
⚠️ 并列最高都要输出 → 用 RANK 或 IN 子查询
```

### 6.2 完整 SQL

```sql
-- LeetCode 184. 部门工资最高的员工
SELECT d.name AS Department, e.name AS Employee, e.salary
FROM Employee e
JOIN Department d ON e.departmentId = d.id
JOIN (
    -- ⚠️ 每个部门最高薪水（去重）
    SELECT departmentId, MAX(salary) AS max_salary
    FROM Employee
    GROUP BY departmentId
) t ON e.departmentId = t.departmentId
   AND e.salary = t.max_salary;           -- ⚠️ 并列最高都匹配

-- 窗口函数版：
SELECT Department, Employee, salary FROM (
    SELECT d.name AS Department, e.name AS Employee, e.salary,
           RANK() OVER (PARTITION BY e.departmentId ORDER BY e.salary DESC) AS rk
    FROM Employee e JOIN Department d ON e.departmentId = d.id
) t
WHERE rk = 1;                              -- ⚠️ RANK 保留并列
-- ⚠️ 面试必答："184 并列都要 → RANK 而非 ROW_NUMBER；
--   '每组最高' = PARTITION BY 部门 + ORDER BY 薪水 DESC。"
```

## 7. 185. 部门工资前三高的所有员工

### 7.1 题目与思路

```
每个部门工资前三（并列都算，如 1,1,2,3 前三是 4 人）
DENSE_RANK：并列不跳号（前三 = rk ≤ 3）
⚠️ RANK 会跳号（1,1,3 → 前三只有 2 人）→ 必须 DENSE_RANK
```

### 7.2 完整 SQL

```sql
-- LeetCode 185. 部门工资前三高的所有员工
SELECT Department, Employee, salary FROM (
    SELECT d.name AS Department, e.name AS Employee, e.salary,
           DENSE_RANK() OVER (
               PARTITION BY e.departmentId
               ORDER BY e.salary DESC) AS rk
    FROM Employee e
    JOIN Department d ON e.departmentId = d.id
) t
WHERE rk <= 3;                        -- ⚠️ DENSE_RANK 并列不跳号
-- 对比：若用 RANK，工资 1,1,3 时 rk=3 的第三名被跳过
-- ⚠️ 面试必答："185 的关键是 DENSE_RANK——
--   '前三'含并列必须不跳号；ROW_NUMBER 会漏并列、
--   RANK 会跳名次。"
```

## 8. 196. 删除重复的电子邮箱

### 8.1 题目与思路

```
删除重复邮箱（保留 id 最小者）
自连接 DELETE：保留最小 id
⚠️ MySQL 同表 DELETE 需包一层（子查询不能直接同表）
```

### 8.2 完整 SQL

```sql
-- LeetCode 196. 删除重复的电子邮箱
DELETE p1
FROM Person p1
JOIN Person p2 ON p1.email = p2.email AND p1.id > p2.id;
-- ⚠️ 保留 id 最小：删掉"id 大于别人同邮箱"的行

-- 窗口函数版：
DELETE FROM Person
WHERE id IN (
    SELECT id FROM (
        SELECT id,
               ROW_NUMBER() OVER (PARTITION BY email ORDER BY id) AS rn
        FROM Person
    ) t
    WHERE rn > 1            -- ⚠️ 非每组第一条 → 删除
);
-- ⚠️ 面试必答："196 自连接删除：email 相同且
--   id 更大 → 删除。窗口函数版更易扩展到
--   '保留每组前 k 条'。"
```

## 9. SQL 方法论总结

### 9.1 解题框架

```
① 需求拆解：要什么（行/聚合/排名）？
② 数据关系：单表/自连接/多表 JOIN？
③ 工具选型：
   排名 → 窗口函数（RANK 家族）
   分组统计 → GROUP BY + HAVING
   连续检测 → 自连接/窗口 grp
   保留主表 → LEFT JOIN（条件放 ON）
④ NULL/去重处理：IS NULL、DISTINCT
⑤ 性能：索引列裸用、避免 SELECT *

⚠️ 识别信号：
  "第 N/前三/最高" → 窗口函数
  "连续/经理/重复" → 自连接
  "所有 + 可能没有" → LEFT JOIN
```

### 9.2 模板速查表

| 题型 | 模板 | 代表题 |
|------|------|--------|
| JOIN 组合 | LEFT JOIN | 175 |
| 第 N 大 | DISTINCT + ORDER + OFFSET | 176、177 |
| 自连接 | 双别名同表 | 181、180、196 |
| 组内最高 | RANK + PARTITION | 184 |
| 组内前 K | DENSE_RANK ≤ K | 185 |
| 删除重复 | 自连接 DELETE / 窗口 | 196 |

### 9.3 自测清单

```
□ 执行顺序核对（WHERE 不能用别名）？
□ LEFT JOIN 条件放 ON（防退化）？
□ NULL 用 IS NULL？
□ 并列排名选对函数（RANK/DENSE_RANK）？
□ 连续检测扩展性（k 可变）？
□ 同表 DELETE 包一层？
□ 索引裸用（无函数包裹）？
```

> 🎯 **核心要点**：SQL 题 = **关系建模**（单表/自连接/JOIN）+ **工具选型**（窗口函数/分组/去重）+ **边界处理**（NULL/并列/重复）。八题覆盖全部考点：LEFT JOIN（175）、排序取位（176/177）、自连接（180/181）、窗口排名（184/185）、删除去重（196）——"先画执行顺序，再选函数"是标准解法。
