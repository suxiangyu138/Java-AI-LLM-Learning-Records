## 1. sa / rank / height 三角关系

### 1.1 三个数组的定义与互推

```
sa[i]     = 第 i 名后缀的起始下标（后缀排序的"名次 → 下标"）
rank[i]   = 起始下标 i 的后缀的排名（"下标 → 名次"）
height[i] = sa[i] 与 sa[i-1] 的最长公共前缀（相邻排名后缀的 LCP）

互推：
  rank[sa[i]] = i        （sa 与 rank 互为逆）
  height[0] = 0（无前驱）
  LCP(sa[i], sa[j]) = min(height[i+1..j])    （★ 关键性质）

s = "banana"，后缀排序：
  排名   下标   后缀        height
  0      5     "a"         0
  1      3     "ana"       1    （"a" 与 "ana" 的 LCP = 1）
  2      1     "anana"     3    （"ana" 与 "anana" 的 LCP = 3）
  3      0     "banana"    0
  4      4     "na"        0
  5      2     "nana"      2    （"na" 与 "nana" 的 LCP = 2）
```

### 1.2 为什么相邻后缀的 LCP 最重要

```
性质：两个后缀的 LCP = 它们之间所有相邻 height 的最小值
  LCP(sa[i], sa[j]) = min(height[i+1], ..., height[j])

推论 1：最长重复子串 = max(height)（相邻后缀 LCP 最大）
推论 2：不同子串数 = Σ(n - sa[i] - height[i])
  （每个后缀贡献"自己独有的前缀数" = 全长 - 与上一个共享的前缀数）

⚠️ 直觉：后缀排序把"相似的字符串"排在一起
  → 公共前缀只在相邻后缀之间"传递"
```

## 2. height 数组的 O(n) 构建原理

### 2.1 朴素构建为什么慢

```
朴素：对每个后缀，与前一名的后缀逐字符比较 → O(n²)
  （n 个后缀 × 每次比较 O(n)）

优化关键（h 不减引理）：
  按"原字符串下标"顺序计算（而非排名顺序）：
  若 height[rank[i]] = h，则 height[rank[i+1]] ≥ h-1
  → 每次比较从 h 开始，h 只减 1 → 总比较次数 O(n)
```

### 2.2 引理证明（直觉）

```
suffix(i) 与 suffix(sa[rank[i]-1]) 的 LCP = h
（sa 中排在 suffix(i) 前面的那个后缀）

→ suffix(i+1) 与前一名后缀的 LCP ≥ h-1：
  因为 suffix(i) 与它的前驱去掉第一个字符后，
  它们的公共前缀去掉首字符 = h-1 个字符仍相同
  → 下次比较直接从 h-1 开始，跳过重复比较

⚠️ 代码模式：
  while (i+h<n && j+h<n && s.charAt(i+h)==s.charAt(j+h)) h++;
  height[rank[i]] = h;
  if (h > 0) h--;          // ⚠️ 核心：只减 1 不归零
```

### 2.3 复杂度论证

```
每个位置 i：h 最多从 0 增到 n，总增量 ≤ n
               h 每轮最多减 1，总减量 ≤ n
  → 总比较次数 O(n) ✓（这就是"h 不减"的威力）

⚠️ 面试表达：
"height 构建 O(n) 的关键是 h 不减引理——
 相邻下标的后缀 LCP 至少比前一对少 1，
 因此比较起点不归零，总比较 O(n)。"
```

## 3. LCP 查询与 RMQ

### 3.1 任意两个后缀的 LCP

```
LCP(sa[i], sa[j]) = min(height[i+1..j])     （区间最小值）
→ 任意两后缀的 LCP = RMQ（区间最值查询）

实现：Sparse Table（ST 表）
  预处理 O(n log n)，查询 O(1)
  ⚠️ height 区间取 min（与最大值 RMQ 方向相反，但结构相同）
```

```java
/** ST 表实现任意两后缀 LCP 查询 */
int[][] st;   // st[i][k] = height[i..i+2^k-1] 的最小值

int lcp(int rankI, int rankJ) {      // 两个排名
    if (rankI == rankJ) return n - sa[rankI];   // 同一后缀：全长
    int l = Math.min(rankI, rankJ) + 1;
    int r = Math.max(rankI, rankJ);
    int k = (int) (Math.log(r - l + 1) / Math.log(2));
    return Math.min(st[l][k], st[r - (1 << k) + 1][k]);
}
// 应用：任意子串比较 O(1)、回文判断、子串出现次数统计
```

### 3.2 子串出现次数（二分定位）

```
给定模式串 P（长度 m），求它在 s 中出现的次数：
  后缀数组按字典序 → 以 P 为前缀的后缀是"连续区间"
  二分两次：
    第一个 ≥ P 的排名（lower_bound）
    第一个 > P 的排名（upper_bound）
  区间长度 = 出现次数
复杂度：O(m log n)（比较 O(m) × 二分 O(log n)）

⚠️ 面试表达：
"后缀数组把'模式匹配'变成'区间定位'——
 以 P 为前缀的后缀在 sa 中连续，二分两次即得出现次数。"
```

## 4. 核心公式推导

### 4.1 最长重复子串 = max(height)

```
重复子串 = 某两个后缀的公共前缀（LCP）
两个后缀的 LCP = 它们之间相邻 height 的最小值
→ 任意两后缀 LCP ≤ max(height)（区间最小值不超过全局最大）
→ 而 max(height) 本身由"相邻后缀"取得 → 可达
∴ 最长重复子串长度 = max(height) ✓

⚠️ 等价说法：字典序相邻的后缀共享的前缀最长
  （相似字符串在排序后相邻）
```

### 4.2 不同子串数 = Σ(n - sa[i] - height[i])

```
每个后缀 sa[i] 贡献"新子串"数：
  该后缀有 n - sa[i] 个前缀（子串）
  其中 height[i] 个与"前一名后缀"共享（重复）
  → 新贡献 = n - sa[i] - height[i]

Σ 后互不重叠、不遗漏（字典序枚举天然去重）：
  不同子串数 = Σ(n - sa[i] - height[i]) ✓

验证 s="banana"（n=6）：
  各后缀贡献：6-5-0=1, 6-3-1=2, 6-1-3=2, 6-0-0=6, 6-4-0=2, 6-2-2=2
  总和 = 1+2+2+6+2+2 = 15 ✓（"banana" 共有 15 个不同子串）
```

### 4.3 公式记忆口诀

```
max(height)          → 最长重复子串
Σ(n - sa[i] - h[i])  → 不同子串数
min(height[i+1..j])  → 任意两后缀 LCP
height ≥ m 的连续段  → 出现次数 ≥ 2 的长子串候选
```

## 5. 多字符串：最长公共子串

### 5.1 拼接技巧

```
两个字符串 s1、s2 的最长公共子串：
  拼接 s1 + '#' + s2（分隔符小于所有字符）→ 构建后缀数组
  ⚠️ 分隔符保证：跨串后缀的 LCP 不会"穿过"分隔符
  在 height 中找最大且"两端后缀属于不同字符串"的相邻对

⚠️ 为什么需要分隔符：
  不加分隔符时，"ab" 与 "abc" 的边界模糊（a 的后缀可能跨串）
  分隔符 < 所有字符 → 排序隔离，LCP 不会跨串
```

### 5.2 完整算法

```java
/** 两字符串最长公共子串（拼接 + height + 归属判断） */
int longestCommonSubstring(String s1, String s2) {
    String s = s1 + "#" + s2;
    int n1 = s1.length();
    int[] sa = buildSuffixArray(s);          // 00 模块模板
    int[] height = buildHeight(s, sa);

    int best = 0;
    for (int i = 1; i < s.length(); i++) {
        // ⚠️ 相邻两个后缀必须来自不同字符串
        boolean cross = (sa[i] < n1) != (sa[i - 1] < n1);
        if (cross) best = Math.max(best, height[i]);
    }
    return best;
}
// 推演 s1="ABAB", s2="BABA" → 最长公共子串 "ABA"（长度 3）
// ⚠️ 扩展：k 个字符串的公共子串 → 归属做"位掩码"（第 i 串 → 第 i 位）
//   连续段中掩码全 1 → 该段最小 height 即候选
```

## 6. 最长回文子串的后缀数组视角

### 6.1 转换思路

```
回文 = 正序与逆序的公共部分：
  s + '#' + reverse(s) 构建后缀数组
  对每个位置 i，找 s[i..] 与 reverse(s)[?..] 的 LCP
  → 奇数回文：以 i 为中心，比较 s[i..] 与 rev[n-1-i..]
  → 偶数回文：比较 s[i..] 与 rev[n-i..]

⚠️ 复杂度：O(n log n)（LCP 查询 O(1) 后每位置 O(1)）
  对比：Manacher O(n) 更优；后缀数组版展示通用性
  （与滚动哈希版同思路，但后缀数组一次构建支持多查询）
```

### 6.2 与其他方案对比

| 方案 | 复杂度 | 特点 |
|------|:---:|------|
| 中心扩展 | O(n²) | 暴力 |
| Manacher | O(n) | 最优（专用算法） |
| 滚动哈希 + 二分 | O(n log n) | 简单通用 |
| 后缀数组 | O(n log n) | 构建复杂，但可复用 |

> 🎯 **面试结论**："回文题优先 Manacher（O(n)）；后缀数组是'一鱼多吃'——构建一次后，重复子串/公共子串/回文/子串计数全部 O(1) 查询。"

## 7. 后缀三兄弟：数组 / 树 / 自动机

### 7.1 对比

| 结构 | 本质 | 构建 | 特点 |
|------|------|:---:|------|
| 后缀数组 | 后缀排序 + height | O(n log n) | 实现最简单，空间紧凑 |
| 后缀树 | 所有后缀的压缩 Trie | O(n)（算法复杂） | 结构直观，节点多 |
| 后缀自动机（SAM） | 最小 DFA 接受所有子串 | O(n) | 最强大，最难懂 |

```
三者的关系：
  后缀数组 ≈ 后缀树的"紧凑线性化"（DFS 序）
  后缀自动机 ≈ 最简表示（等价但更抽象）
  功能等价：最长重复子串/不同子串数/公共子串都能解

⚠️ 面试定位：
  "后缀数组是三者中最适合面试的——概念清晰、
   倍增实现 O(n log n)。后缀树/SAM 竞赛级，
   知道存在与定位即可。"
```

## 8. 面试要点与追问

### 8.1 面试话术模板

```
"后缀数组 = sa（后缀排序）+ rank（逆）+ height（相邻 LCP）。
 最长重复子串 = max(height)；不同子串数 = Σ(n-sa[i]-height[i])；
 任意两后缀 LCP = height 区间最小值（RMQ）。
 构建 O(n log n)（倍增双关键字排序），height O(n)（h 不减引理）。
 面试实现我更倾向滚动哈希 + 二分（同样 O(n log n) 且简单），
 后缀数组作为'一次构建、多类查询'的最优方案提及。"
```

### 8.2 高频追问 TOP 8

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | sa 和 rank 关系？ | 互为逆：rank[sa[i]] = i |
| 2 | 任意两后缀 LCP？ | min(height[i+1..j])（RMQ 查询） |
| 3 | height 为什么 O(n)？ | h 不减引理：比较起点只减 1，总 O(n) |
| 4 | 不同子串数公式？ | Σ(n - sa[i] - height[i])（字典序去重） |
| 5 | 最长公共子串？ | 拼接 + 分隔符 + 归属判断 |
| 6 | 子串出现次数？ | 二分定位 sa 连续区间 |
| 7 | 与滚动哈希选型？ | 哈希简单；后缀数组复用性强 |
| 8 | 后缀三兄弟？ | 数组/树/SAM：功能等价、复杂度递增 |

### 8.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| height[0] 忘初始化 | 越界 | height[0] = 0 |
| 拼接忘分隔符 | LCP 跨串 | '#' 隔离 |
| 归属判断错 | 公共子串漏算 | 掩码/分段判断 |
| 倍增比较器忘 -1 处理 | 排序错 | 越界第二关键字 = -1 |
| RMQ 取 max | LCP 错 | height 区间取 min |

> 🎯 **核心要点**：后缀数组进阶 = **height 的 O(n) 原理**（h 不减引理）+ **三大公式**（max height / Σ贡献 / RMQ 区间 min）+ **多串扩展**（拼接 + 分隔符 + 归属）。面试定位清晰：概念必讲、实现用哈希替代、后缀数组是"最优方案"的答案。
