## 1. 链表节点与类型

### 1.1 节点定义（Java）

```java
// 单链表节点（LeetCode 标准定义）
public class ListNode {
    int val;
    ListNode next;
    ListNode() {}
    ListNode(int val) { this.val = val; }
    ListNode(int val, ListNode next) { this.val = val; this.next = next; }
}

// 双向链表节点（LRU 缓存等设计题用）
public class DoublyListNode {
    int val;
    DoublyListNode prev;   // 前驱
    DoublyListNode next;   // 后继
}
```

### 1.2 链表三大类型

```
单链表（Singly Linked List）：
  head → [1] → [2] → [3] → null

双向链表（Doubly Linked List）：
  null ← [1] ⇄ [2] ⇄ [3] → null
          (prev 指向也保留)

循环链表（Circular Linked List）：
  head → [1] → [2] → [3] → 回到 [1]（尾节点的 next 指向 head）
```

> 💡 面试默认单链表，除非题目明确说双向。**画图永远是链表题的第一动作。**

## 2. 链表 vs 数组

| 维度 | 数组 | 链表 |
|------|:---:|:---:|
| 内存 | 连续内存 | 分散节点 + 指针 |
| 随机访问 | O(1) `arr[i]` | **O(n)** 必须从头遍历 |
| 头部插入/删除 | O(n) 需移动 | **O(1)** 改指针即可 |
| 中间插入/删除 | O(n) | O(n)（需先找到位置，插入本身 O(1)） |
| 空间 | 容量固定/自动扩容 | 每个节点额外存指针（8 字节） |
| 缓存友好度 | 高（连续） | 低（离散） |

```
经验法则：
  需要频繁随机访问 → 数组
  需要频繁头部插入删除 → 链表
  数据量巨大且插入删除多 → 链表
```

## 3. 基础操作：遍历、插入、删除

### 3.1 遍历

```java
// 遍历模板
ListNode cur = head;
while (cur != null) {
    // 处理 cur.val
    cur = cur.next;          // 前进
}

// 递归遍历
void traverse(ListNode node) {
    if (node == null) return;
    traverse(node.next);
}
```

### 3.2 插入（在节点 prev 之后）

```java
// 在 prev 后面插入 newNode
ListNode newNode = new ListNode(val);
newNode.next = prev.next;    // ① 新节点指向 prev 的后继
prev.next = newNode;         // ② prev 指向新节点
// ⚠️ 顺序不能反！先 ① 后 ②，否则丢失原后继
```

### 3.3 删除（删除 prev 的下一个）

```java
// 删除 prev 的后继节点
ListNode target = prev.next;
prev.next = target.next;     // 跳过 target
target.next = null;          // 可选：断开（帮助 GC）

// ⚠️ 链表的删除，核心是"修改前驱的 next"
// 删除头节点特殊：需要 head = head.next
```

### 3.4 三种常见错误

| 错误 | 原因 | 修正 |
|------|------|------|
| 断链 | 插入时先改 prev.next | 先连新节点，再接 prev |
| 空指针 | 未判断 `cur == null` 就访问 cur.next | 循环条件/判空前置 |
| 头节点丢失 | 删除头节点后未更新 head | 用 dummy 或返回新 head |

## 4. 核心技巧一：虚拟头结点 Dummy

### 4.1 为什么需要 dummy？

```
问题场景：删除头节点
  普通做法：需要特判 head == null 或删除 head 时 head = head.next
  大量分支判断 → 代码丑、易错

Dummy 方案：
  dummy → [原链表]
  所有操作（插入/删除）都从 dummy.next 开始统一处理
  删除任何节点（含原头节点）都变成"删除某个节点的后继"
  → 代码统一、无特判
```

### 4.2 Dummy 使用模板

```java
// 需要修改链表的题目，先建 dummy
ListNode dummy = new ListNode(-1);   // 值随意
dummy.next = head;
ListNode prev = dummy;               // prev 从 dummy 开始操作

// ... 操作完成后
return dummy.next;                   // 返回新头（可能是原 head 或新节点）
```

### 4.3 Dummy 适用场景

| 场景 | 例题 | 为什么用 |
|------|:---:|------|
| 删除节点（可能删头） | 19. 删除倒数第N | 可能删除 head，dummy 统一 |
| 合并链表 | 21. 合并有序链 | 结果头未定，dummy 先占位 |
| 分隔链表 | 86. 分隔链表 | 头可能变化 |
| 删除重复 | 82. 删除排序重复 II | 头可能被删光 |

> 🎯 **口诀**：**修改链表先建 dummy，操作从 dummy 开始，返回 dummy.next**——这条铁律能消灭一半链表 bug。

## 5. 核心技巧二：快慢指针

### 5.1 经典形态

```java
// 快慢指针：fast 走 2 步，slow 走 1 步
ListNode slow = head, fast = head;
while (fast != null && fast.next != null) {
    slow = slow.next;        // 慢指针走 1 步
    fast = fast.next.next;   // 快指针走 2 步
}
```

### 5.2 三大应用

| 应用 | 原理 | 结果 |
|------|------|------|
| **找中点** (876) | fast 到头时 slow 恰好在中点 | slow 即中点 |
| **判环** (141) | 有环时 fast 会在环内追上 slow | 相遇即判环 |
| **找倒数第 N 个** (19) | fast 先走 N 步，再同步走 | fast 到尾时 slow 指向倒数第 N 个的前驱 |

### 5.3 为什么 fast 每次走 2 步？

```
如果 fast 每次走 3 步会怎样？
  环长 k 不是 2 的倍数时，fast 可能永远跳不到 slow 的下一格
  → 1 和 2 步差 = 1，fast 相对 slow 每轮逼近 1 步，必然相遇

数学证明（141）：
  假设环长 L，slow 进环后 fast 已领先 d 步
  每轮 slow+1，fast+2 → 距离差减 1 → 最多 L 轮追上
```

## 6. 核心技巧三：三指针

### 6.1 反转链表的三指针模型

```java
// 反转链表：prev / curr / next 三指针
public ListNode reverseList(ListNode head) {
    ListNode prev = null;       // 前驱（初始为空）
    ListNode curr = head;       // 当前节点
    while (curr != null) {
        ListNode next = curr.next;   // ① 暂存后继（防断链）
        curr.next = prev;            // ② 反转指针
        prev = curr;                 // ③ 前驱前进
        curr = next;                 // ④ 当前前进
    }
    return prev;                // 新头 = 原尾节点
}
```

### 6.2 为什么必须暂存 next？

```
[1] → [2] → [3] → null，反转第一个节点时：
  curr = 1
  curr.next = prev → 1.next = null  ← 此时 [2] 的引用丢了！
  → 必须先 next = curr.next 暂存，否则断链

三指针本质：用三个引用分别追踪"前驱-当前-后继"，
反转当前指针的同时保住链表完整性
```

## 7. 核心技巧四：递归思维

### 7.1 递归模型

```
链表递归 = 处理当前节点 + 递归处理剩余部分

递归反转链表：
  函数返回：反转后链表的头
  递归到：最后一个节点（newHead）
  回溯时：head.next.next = head 实现反转

适用于：反转、合并、两两交换等"从局部到整体"的问题
注意：递归深度 = 链表长度，大链表有栈溢出风险
```

### 7.2 迭代 vs 递归对比

| 维度 | 迭代 | 递归 |
|------|:---:|:---:|
| 空间 | O(1) | O(n)（递归栈） |
| 可读性 | 指针操作繁琐 | 更直观简洁 |
| 栈溢出风险 | 无 | 链表很长时可能 |
| 面试偏好 | **推荐**（空间优） | 考察递归思维时用 |

> 💡 面试策略：**先写迭代版本**（空间 O(1) 更稳），面试官追问"能用递归吗"再展示递归版本。

### 7.3 四大技巧组合拳

```
实际面试题往往是技巧组合：
  19. 删除倒数第N → Dummy + 快慢指针
  148. 排序链表 → 快慢指针（找中点）+ 递归（归并）+ 合并（21）
  234. 回文链表 → 快慢指针（中点）+ 三指针（反转后半）+ 双指针比较

拿到题先识别用哪几个技巧，再逐个实现——链表题就变成了
"核心技巧的排列组合"
```

> 🎯 **核心要点**：链表的全部套路浓缩为四大技巧——**Dummy 统一头操作、快慢指针定位、三指针反转、递归分解**。基础操作记住"先连后继再接前驱""删除靠改前驱 next"。每做一道链表题先画图，把指针变化画清楚再写代码，正确率直接翻倍。
