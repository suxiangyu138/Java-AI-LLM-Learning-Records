## 1. 核心概念

### 1.1 回溯的本质

> 回溯 = **DFS + 状态回退**。穷举所有可行解，走不通撤销选择换路。核心套路：**选择 → 递归 → 撤销**。

```
适用判断："找出所有可行方案" → 99% 是回溯

回溯三要素：
  路径 path（已做的选择）
  选择列表（当前可选）
  结束条件（何时收集）

复杂度：由输出规模决定（子集 2ⁿ、排列 n!）
  ⚠️ 剪枝只减常数，不改变理论复杂度
```

### 1.2 识别信号

```
"所有组合/排列/子集" → 回溯
"所有分割方案" → 回溯（131/93）
"N 皇后/数独" → 回溯（51/37）
"路径枚举" → 回溯（79 单词搜索）

⚠️ 与 DP 的区别：
  "多少种方案"（计数）→ DP
  "所有方案"（枚举）→ 回溯
  "最优方案" → DP/贪心
```

### 1.3 五类题型

```
① 组合（startIndex 控顺序）：77/39/40
② 排列（used 数组）：46/47
③ 子集（进入即收集）：78/90
④ 切割（start 为切点）：131/93
⑤ 棋盘（多维约束）：51/37/79

⚠️ 模板差异只在"三要素"的形态
```

## 2. 完整代码模板

### 2.1 组合模板（startIndex 版）

```java
/**
 * LeetCode 77. 组合（组合模板）
 * start 控制"不回头"（防 [2,1] 与 [1,2] 重复）
 */
public List<List<Integer>> combine(int n, int k) {
    List<List<Integer>> res = new ArrayList<>();
    backtrack(n, k, 1, new ArrayList<>(), res);
    return res;
}

private void backtrack(int n, int k, int start,
                       List<Integer> path, List<List<Integer>> res) {
    if (path.size() == k) {                        // ① 收集
        res.add(new ArrayList<>(path));            // ⚠️ 必须拷贝！
        return;
    }

    // ② 范围剪枝：i ≤ n-(k-size)+1（保证能凑满）
    for (int i = start; i <= n - (k - path.size()) + 1; i++) {
        path.add(i);                               // ③ 选择
        backtrack(n, k, i + 1, path, res);         // ④ 递归（不回头）
        path.remove(path.size() - 1);              // ⑤ 撤销（灵魂！）
    }
}
// ⚠️ 可重复选（39 组合总和）：递归传 i（而非 i+1）
```

### 2.2 排列模板（used 版）

```java
/**
 * LeetCode 46. 全排列（排列模板）
 * 每层从 0 开始 + used 防重复选
 */
public List<List<Integer>> permute(int[] nums) {
    List<List<Integer>> res = new ArrayList<>();
    backtrack(nums, new boolean[nums.length],
              new ArrayList<>(), res);
    return res;
}

private void backtrack(int[] nums, boolean[] used,
                       List<Integer> path, List<List<Integer>> res) {
    if (path.size() == nums.length) {
        res.add(new ArrayList<>(path));
        return;
    }
    for (int i = 0; i < nums.length; i++) {        // ⚠️ 从 0 开始！
        if (used[i]) continue;

        used[i] = true;                            // 标记
        path.add(nums[i]);
        backtrack(nums, used, path, res);
        path.remove(path.size() - 1);
        used[i] = false;                           // ⚠️ 标记也要撤销！
    }
}
// 组合 vs 排列：
//   组合：startIndex（不回头，顺序无关）
//   排列：used 数组（从 0 遍历，顺序相关）
```

### 2.3 子集模板（进入即收集）

```java
/**
 * LeetCode 78. 子集（子集模板）
 * ⚠️ 与组合的唯一区别：每个节点都是答案
 */
public List<List<Integer>> subsets(int[] nums) {
    List<List<Integer>> res = new ArrayList<>();
    backtrack(nums, 0, new ArrayList<>(), res);
    return res;
}

private void backtrack(int[] nums, int start,
                       List<Integer> path, List<List<Integer>> res) {
    res.add(new ArrayList<>(path));                // ⚠️ 进入即收集！

    for (int i = start; i < nums.length; i++) {
        path.add(nums[i]);
        backtrack(nums, i + 1, path, res);
        path.remove(path.size() - 1);
    }
}
// 决策树节点数 = 2ⁿ = 子集数 ✓
// 记忆："子集进入即收集，组合满足才收集"
```

## 3. 去重技巧详解

### 3.1 去重的三种场景

```
① 组合/子集去重（40/90）：
   排序 + if (i > start && nums[i] == nums[i-1]) continue

② 排列去重（47）：
   排序 + if (i > 0 && nums[i] == nums[i-1] && !used[i-1]) continue

③ 子序列去重（491）：
   每层新建 Set 记录本层已用数字

⚠️ 共同前提：必须先排序（相同值相邻才能判重）
```

### 3.2 同层 vs 同路径去重

```
nums = [1, 1, 2]：

同层去重（i > start）：
  第一层 i=0 选 1 → 展开所有含"第一个 1"的组合
  第一层 i=1（nums[1]==nums[0]）→ 跳过！
  （与 i=0 展开完全重复）

为什么不用 i > 0？
  同路径内 [1,1,...] 是合法的（两个位置用两个 1）
  → 必须区分"同层"（跳过）与"同路径"（保留）

⚠️ 记忆："i > start 同层去重；i > 0 会误删合法路径"
```

### 3.3 排列去重的 !used[i-1]

```
if (i > 0 && nums[i] == nums[i-1] && !used[i-1]) continue;

!used[i-1] 的含义：
  used[i-1] = false → 相同值在前面的同层已展开过 → 跳过
  used[i-1] = true → 相同值在同路径上（如 [1,1,...]）→ 保留

例 nums=[1,1,2]：
  第一层：i=1 且 !used[0] → 跳过（同层重复）
  路径 [1,1,...]：i=1 且 used[0]=true → 不跳过（合法！）

⚠️ 47 全排列 II 是 26 届秋招手撕重点
```

## 4. 剪枝策略

### 4.1 四大剪枝

```
① 边界剪枝：remain < 0 / 越界 / 超限
   例：39 组合总和（剩余 < 0 终止）

② 范围剪枝：剩余数量凑不齐
   例：77 组合（i ≤ n-(k-size)+1）
   例：93 IP 地址（剩余字符与段数匹配）

③ 单调剪枝：排序后提前 break
   例：39 组合总和（nums[i] > remain → break）
   ⚠️ 排序后 break 而非 continue（后面更大）

④ 对称性剪枝：等价状态只试一次
   例：同层去重（本质是剪枝）
```

### 4.2 剪枝的时机

```
✅ 推荐：写在"做选择前"（for 循环内、path.add 之前）
  → 省掉递归调用开销

❌ 不推荐：进入递归后再判断
  → 白白消耗栈帧

⚠️ 面试表达：
"我做了【范围剪枝】——保证当前分支
 还有足够的数可选，从源头排除
 不可能的分支。"
```

### 4.3 剪枝 vs 复杂度

```
剪枝不改变最坏复杂度（子集仍 2ⁿ）
但显著减少实际搜索时间

⚠️ 面试必答：
"回溯本质是穷举，复杂度由输出规模决定
 （子集 2ⁿ、排列 n!、组合 C(n,k)），
 剪枝只减少实际分支，不改变理论复杂度。"
```

## 6. 面试要点与追问

### 6.1 面试话术模板

```
"这题要枚举所有方案 → 回溯：
 三要素：path（已选）、选择列表（start/used）、
 结束条件（长度/总和）。
 组合用 startIndex（不回头），排列用 used（防重复选）。
 收集时拷贝 path（防共享引用被撤销污染）。
 复杂度由输出规模决定：子集 2ⁿ、排列 n!。"
```

### 6.2 高频追问 TOP 8

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | 为什么收集必须拷贝？ | path 是共享引用，撤销会修改 → 快照 |
| 2 | 组合 vs 排列模板？ | startIndex（顺序无关）vs used（顺序相关） |
| 3 | 去重为什么先排序？ | 相同值相邻才能判重 |
| 4 | 同层 vs 同路径去重？ | i>start 同层；i>0 误删合法路径 |
| 5 | 39 为什么传 i？ | 可重复选当前元素 |
| 6 | 剪枝时机？ | 选择前（省递归调用） |
| 7 | 复杂度？ | 输出规模决定；剪枝不减理论复杂度 |
| 8 | 回溯 vs DFS？ | 回溯 = DFS + 撤销 |

### 6.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| 收集不拷贝 | 结果全空/相同 | new ArrayList<>(path) |
| 忘撤销 | 路径污染 | 成对 add/remove |
| used 忘恢复 | 重复/缺失 | used[i]=false |
| 去重忘排序 | 去重失效 | 先排序 |
| 同路径误去重 | 合法解丢失 | i > start 而非 i > 0 |

> 🎯 **核心要点**：三模板（组合 start/排列 used/子集即收集）+ 两条铁律（path 拷贝、撤销成对）。去重（同层 vs 同路径）是最高频考点；47/77/216/93 是 26 届秋招手撕重点。
