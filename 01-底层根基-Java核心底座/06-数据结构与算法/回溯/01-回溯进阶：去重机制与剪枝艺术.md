## 1. 去重问题的完整体系

### 1.1 为什么会重复

```
输入含重复元素 → 相同值在不同位置被展开
  例：nums=[1,1,2] 的组合
  选第一个 1 与选第二个 1 产生的组合完全相同

⚠️ 去重三原则：
  ① 必须先排序（相同值相邻才能判重）
  ② 区分"同层"与"同路径"
  ③ 不同题型用不同机制
```

### 1.2 三种去重机制

| 题型 | 机制 | 代码 |
|------|------|------|
| 组合/子集 | 排序 + 同层去重 | `i > start && nums[i]==nums[i-1]` |
| 排列 | 排序 + used 判断 | `i > 0 && nums[i]==nums[i-1] && !used[i-1]` |
| 子序列 | 每层 Set | `set.contains(nums[i]) → continue` |

```
⚠️ 为什么题型不同机制不同？
  组合/子集：startIndex 已控顺序 → 只需同层去重
  排列：从 0 遍历 → 需要 used 区分"同层"与"同路径"
  子序列：不能排序（破坏相对顺序）→ Set 替代
```

### 1.3 去重的本质

```
去重 = 等价状态的剪枝：
  相同值在同一层展开 → 产生的子树完全相同
  → 只保留第一个展开 → 其余跳过

⚠️ 面试表达：
"去重本质是剪枝——相同值在同一层
 的展开是等价的，只保留第一个。
 关键是区分同层（跳过）与同路径（保留）。"
```

## 2. 同层去重详解

### 2.1 组合去重（40. 组合总和 II）

```java
/**
 * LeetCode 40. 组合总和 II
 * candidates 含重复，每个数只能用一次
 *
 * 同层去重：if (i > start && nums[i] == nums[i-1]) continue;
 * ⚠️ i > start（同层）而非 i > 0（同路径）！
 */
public List<List<Integer>> combinationSum2(int[] candidates, int target) {
    List<List<Integer>> res = new ArrayList<>();
    Arrays.sort(candidates);                    // ⚠️ 去重前提：排序

    backtrack(candidates, target, 0, new ArrayList<>(), res);
    return res;
}

private void backtrack(int[] nums, int remain, int start,
                       List<Integer> path, List<List<Integer>> res) {
    if (remain == 0) {
        res.add(new ArrayList<>(path));
        return;
    }

    for (int i = start; i < nums.length; i++) {
        if (nums[i] > remain) break;            // 单调剪枝

        // ⚠️ 同层去重：跳过本层用过的相同值
        if (i > start && nums[i] == nums[i - 1]) continue;

        path.add(nums[i]);
        backtrack(nums, remain - nums[i], i + 1, path, res);
        path.remove(path.size() - 1);
    }
}
// 推演 candidates=[1,1,2,5,6,7,10], target=8：
//   第一层 i=0 选 1 → 展开所有含"第一个 1"的组合
//   第一层 i=1（nums[1]==nums[0]）→ 跳过！
//   ⚠️ 但同路径内 [1,1,...] 合法（两个位置用两个 1）
```

### 2.2 为什么 i > start 而非 i > 0

```
nums = [1, 1, 2]：

i > start（同层去重）：
  第一层：i=0 选 1 → 递归；i=1 跳过（同层重复）
  第二层（path=[1]）：i=1 选 1（1 > start=1）→ 合法！
  → [1,1,2] 被保留 ✓

i > 0（无脑去重）：
  第二层 i=1：1 > 0 且 nums[1]==nums[0] → 跳过！
  → [1,1,...] 全部丢失 ✗ 错误！

⚠️ 记忆："i > start 是'同层'，i > 0 会误删合法路径"
```

### 2.3 子集去重（90. 子集 II）

```java
/**
 * LeetCode 90. 子集 II
 * 与 40 同机制：排序 + 同层去重
 */
public List<List<Integer>> subsetsWithDup(int[] nums) {
    List<List<Integer>> res = new ArrayList<>();
    Arrays.sort(nums);
    backtrack(nums, 0, new ArrayList<>(), res);
    return res;
}

private void backtrack(int[] nums, int start,
                       List<Integer> path, List<List<Integer>> res) {
    res.add(new ArrayList<>(path));             // 进入即收集

    for (int i = start; i < nums.length; i++) {
        if (i > start && nums[i] == nums[i - 1]) continue;  // 同层去重

        path.add(nums[i]);
        backtrack(nums, i + 1, path, res);
        path.remove(path.size() - 1);
    }
}
// nums=[1,2,2] → [[],[1],[1,2],[1,2,2],[2],[2,2]]
// ⚠️ 记忆："组合/子集的去重 = 排序 + i>start"
```

## 3. 排列去重详解

### 3.1 47. 全排列 II

```java
/**
 * LeetCode 47. 全排列 II（26 届秋招手撕重点）
 *
 * 排列去重：if (i > 0 && nums[i] == nums[i-1] && !used[i-1]) continue;
 * ⚠️ !used[i-1] 是灵魂——区分同层与同路径
 */
public List<List<Integer>> permuteUnique(int[] nums) {
    List<List<Integer>> res = new ArrayList<>();
    Arrays.sort(nums);                          // 排序
    boolean[] used = new boolean[nums.length];

    backtrack(nums, used, new ArrayList<>(), res);
    return res;
}

private void backtrack(int[] nums, boolean[] used,
                       List<Integer> path, List<List<Integer>> res) {
    if (path.size() == nums.length) {
        res.add(new ArrayList<>(path));
        return;
    }

    for (int i = 0; i < nums.length; i++) {
        if (used[i]) continue;

        // ⚠️ 排列去重：前一个相同值未被使用 → 本层已展开过 → 跳过
        if (i > 0 && nums[i] == nums[i - 1] && !used[i - 1]) continue;

        used[i] = true;
        path.add(nums[i]);
        backtrack(nums, used, path, res);
        path.remove(path.size() - 1);
        used[i] = false;
    }
}
```

### 3.2 !used[i-1] 的含义

```
!used[i-1] 区分两种场景：

场景 A（同层重复 → 跳过）：
  第一层：i=0 选 nums[0]=1 → 展开后回到第一层
  i=1：nums[1]==nums[0] 且 !used[0]（已撤销）
  → 说明第一层已经用 1 展开过 → 跳过 ✓

场景 B（同路径重复 → 保留）：
  path=[1] 的第二层：i=1 选 nums[1]=1
  used[0]=true（路径上正在用第一个 1）
  → 不满足 !used[i-1] → 不跳过 → [1,1,...] 合法 ✓

⚠️ 记忆：
  "!used[i-1] = true → 前一个相同值不在路径上
   → 本层重复展开 → 跳过"
```

### 3.3 两种等价写法

```java
// 写法 A（推荐）：跳过"前一个未被使用"的
if (i > 0 && nums[i] == nums[i - 1] && !used[i - 1]) continue;

// 写法 B（等价）：只保留"前一个已使用"的
// if (i > 0 && nums[i] == nums[i - 1] && used[i - 1]) continue;
// ⚠️ 注意：B 保留的是"最后一个相同值"的展开
//   两者结果相同（都只展开一次），A 更常见

// ⚠️ 千万别写：i > 0 && nums[i] == nums[i-1]（无条件）
//   会误删同路径合法的 [1,1,...]
```

### 3.4 491. 非递减子序列（Set 去重）

```java
/**
 * LeetCode 491. 非递减子序列
 * ⚠️ 不能排序！（要求保持原数组相对顺序）
 * → 用每层 Set 记录本层已用数字
 */
public List<List<Integer>> findSubsequences(int[] nums) {
    List<List<Integer>> res = new ArrayList<>();
    backtrack(nums, 0, new ArrayList<>(), res);
    return res;
}

private void backtrack(int[] nums, int start,
                       List<Integer> path, List<List<Integer>> res) {
    if (path.size() >= 2) {
        res.add(new ArrayList<>(path));
    }

    Set<Integer> usedThisLevel = new HashSet<>();   // ⚠️ 本层去重 Set
    for (int i = start; i < nums.length; i++) {
        // 剪枝：保持非递减
        if (!path.isEmpty() && nums[i] < path.get(path.size() - 1)) continue;
        // ⚠️ 本层已用过相同值 → 跳过
        if (usedThisLevel.contains(nums[i])) continue;

        usedThisLevel.add(nums[i]);
        path.add(nums[i]);
        backtrack(nums, i + 1, path, res);
        path.remove(path.size() - 1);
    }
}
// ⚠️ 为什么 Set 放循环外、递归前？
//   记录的是"本层 for 循环"用过的值（同层去重）
```

## 4. 剪枝的四大类

### 4.1 边界剪枝

```
条件：remain < 0 / 越界 / 超限 / 候选为空
位置：递归入口（兜底）

例：39 组合总和 remain < 0 → return
⚠️ 边界剪枝是最基础的兜底
```

### 4.2 范围剪枝

```
条件：剩余数量/长度凑不齐
位置：for 循环上界（源头排除）

例：77 组合：i ≤ n - (k - path.size()) + 1
   93 IP：剩余字符需填满剩余段数
   （remaining < need 或 > need*3 → return）

⚠️ 效果：从源头砍掉不可能的分支（不进入递归）
```

### 4.3 单调剪枝

```
条件：排序后 nums[i] > remain
位置：for 循环内（break 而非 continue！）

例：39 组合总和：nums[i] > remain → break
⚠️ 为什么 break？排序后后面的更大，必然也 > remain
   continue 会浪费剩余循环

⚠️ 面试必答：
"单调剪枝用 break——排序后当前值已超限，
 后面的更大，必然也超限，直接终止循环。"
```

### 4.4 对称性剪枝

```
条件：等价状态只试一次
位置：选择前

例：同层去重（40/90/47 的本质是剪枝）
   698 装桶：等价桶状态跳过
   51 N 皇后：行/列/对角线冲突提前排除

⚠️ 去重与剪枝的关系：
  去重 = 对称性剪枝的特例
  （等价状态的展开是重复的 → 剪掉）
```

### 4.5 剪枝位置总结

```
✅ 推荐：写在"做选择前"（for 循环内、path.add 之前）
  → 省掉递归调用开销

❌ 不推荐：进入递归后再判断
  → 白白消耗栈帧

⚠️ 剪枝效果对比：
  边界剪枝（递归入口）：兜底，省少量
  范围剪枝（循环上界）：省大量（源头排除）
  单调剪枝（break）：省大量（排序后终止）
```

## 5. 回溯与记忆化/DP 的关系

### 5.1 回溯 vs 记忆化搜索

```
回溯：枚举所有方案（无缓存，指数级）
记忆化：缓存子问题结果（有重叠子问题才有效）

⚠️ 关键判断：
  子问题是否重叠？
  重叠 → 记忆化/DP（缓存）
  不重叠（每个方案独立）→ 回溯（枚举）

例：组合总和 vs 硬币找零
  组合总和：枚举所有方案 → 回溯
  硬币找零：求最少硬币（重叠）→ DP
```

### 5.2 什么时候回溯可以转 DP

```
① 问题问"多少种方案"（计数）
   → 子问题重叠 → 记忆化/DP 更快
② 问题问"最优方案"（最值）
   → 子问题最优 → DP
③ 问题问"所有方案"（枚举）
   → 必须回溯（DP 不输出方案）

⚠️ 面试表达：
"计数/最优 → DP（重叠子问题缓存）；
 枚举所有方案 → 回溯（必须展开全部）。"
```

### 5.3 回溯 vs DFS

```
DFS：遍历所有节点（无撤销概念）
回溯：DFS + 撤销（枚举方案的实现）

⚠️ 关系：
  回溯是 DFS 的特化（加撤销）
  DFS 是回溯的基础（先遍历再撤销）

⚠️ 面试必答：
"回溯 = DFS + 状态回退。
 普通 DFS 访问完就结束；
 回溯需要在递归返回后撤销选择，
 让兄弟分支复用同一份 path。"
```

## 6. 进阶总结

### 6.1 进阶要点速查

```
① 去重三机制：
   组合/子集 → 排序 + i>start
   排列 → 排序 + !used[i-1]
   子序列 → 每层 Set
② 剪枝四类：
   边界（兜底）/ 范围（源头）/ 单调（break）/ 对称（去重）
③ 回溯 vs DP：
   枚举方案 → 回溯；计数/最优 → DP
④ 回溯 = DFS + 撤销
```

### 6.2 面试话术模板

```
"去重问题是回溯的难点。我的方案：
 ① 先排序（相同值相邻）；
 ② 区分同层与同路径——
   组合用 i>start，排列用 !used[i-1]；
 ③ 剪枝写在选择前：
   范围剪枝（循环上界）、单调剪枝（break）。
 去重本质是等价状态的剪枝。"
```

### 6.3 易错点清单

| 错误 | 后果 | 修正 |
|------|------|------|
| 去重忘排序 | 去重失效 | 先排序 |
| i>0 代替 i>start | 合法路径丢失 | 同层才去重 |
| 排列忘 !used[i-1] | 去重失效 | 三条件齐 |
| 单调剪枝用 continue | 浪费循环 | 用 break |
| 剪枝放递归后 | 白耗栈帧 | 选择前剪 |

> 🎯 **核心要点**：回溯进阶 = **去重三机制**（组合 i>start / 排列 !used / 子序列 Set）+ **剪枝四类**（边界/范围/单调/对称）。"同层 vs 同路径"是去重核心；"剪枝写在选择前"是效率关键；与 DP 的选型（枚举 vs 计数/最优）是面试必答。
