# 查找算法

## 📌 课程定位
查找是计算机最基本的操作——数据库索引、缓存系统、搜索引擎都建立在高效的查找数据结构之上。面试必考哈希表、二分查找。

## 🎯 核心章节

### 1. 顺序查找
- 无序表遍历，O(n)，适用于小数据量或链表
- **哨兵优化**：在0号位置放哨兵值，省去循环中判尾条件

### 2. 二分查找（⭐ 必肌肉记忆）
- **前提**：有序表 + 顺序存储（随机访问）
- **标准实现**（注意 mid 防溢出）：
  ```java
  int lo = 0, hi = n-1;
  while (lo <= hi) {
      int mid = lo + (hi - lo) / 2;  // 防溢出
      if (arr[mid] == target) return mid;
      else if (arr[mid] < target) lo = mid + 1;
      else hi = mid - 1;
  }
  ```
- **变体（高频面试）**：
  - 查找第一个等于 target 的位置（左边界）
  - 查找最后一个等于 target 的位置（右边界）
  - 查找第一个 ≥ target 的位置（lower_bound）
  - 查找第一个 > target 的位置（upper_bound）
- **时间复杂度**：O(log n)

### 3. 二叉搜索树（BST）查找
- 类似二分查找，O(h)，h最坏为n
- 插入、查找都在O(h)内完成

### 4. 平衡二叉树（AVL）
- 严格平衡（|BF|≤1），查找O(log n)保证
- 插入/删除可能触发旋转（LL/RR/LR/RL），适合查找多修改少的场景

### 5. 红黑树（了解原理）
- 弱平衡（最长路径 ≤ 2×最短路径），插入删除比AVL快
- Java HashMap（链表长度≥8转红黑树）、TreeMap、C++ std::map 的底层
- 五大性质：①红/黑 ②根黑 ③叶(空)黑 ④红结点子必黑 ⑤任意路径黑结点数同

### 6. B树与B+树（⭐ 数据库索引核心）
- **B树**：m阶B树每个结点最多m个孩子、至少⌈m/2⌉个——多路平衡搜索树
  - 数据分布在各层结点中
- **B+树**：MySQL InnoDB 默认索引结构
  - 所有数据在叶子层，非叶层只存索引
  - 叶子层用双向链表串联——支持范围查询、排序查询
  - 每个结点大小≈一个磁盘页（16KB），大幅减少磁盘IO

### 7. 哈希表（⭐ 面试最高频）
- **核心思想**：通过哈希函数将 key 映射到数组索引，期望O(1)
- **哈希函数设计要求**：计算快、分布均匀、相同key相同hash
- **冲突解决**：
  - **拉链法**：每个槽是链表/红黑树——Java HashMap 采用
  - **开放地址法**：冲突时探测下一个位置
    - 线性探测：index+1, +2, +3... （一次聚集问题）
    - 平方探测：index+1², +2², +3²...
    - 双重哈希：index + i×hash2(key)
- **负载因子（Load Factor）**：α = 元素数/表长，α过大影响效率→rehash扩容
- **一致性哈希**：分布式缓存中节点增减时最小化数据迁移

### 8. 跳表（Skip List）
- 多层有序链表，每层按概率向上"晋升"，期望O(log n)
- Redis 有序集合（ZSet）底层数据结构之一
- 实现比平衡树简单，性能相近

## ✅ 学习建议
- 二分查找的4个变体必须能手写（闭区间/左边界/右边界/lower_bound）
- B+树要理解为什么适合磁盘——每个结点刚好一页，减少IO次数
- 哈希表是面试最高频数据结构，冲突解决方式+扩容机制都要能说清
