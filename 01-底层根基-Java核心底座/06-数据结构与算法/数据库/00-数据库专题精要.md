## 1. 核心概念

### 1.1 SQL 题的考察结构

```
数据库标签题 = LeetCode 上的 SQL 题
  题型：查询/统计/排名/去重/连表

三大核心能力：
  ① JOIN 连表（表关系建模）
  ② 聚合分组（GROUP BY + HAVING）
  ③ 窗口函数（排名/累计）

面试定位：后端/数据岗必考；算法岗偶尔
```

### 1.2 识别信号

```
"SQL 查询/统计/排名" → 数据库标签
"部门/薪水/订单" 场景 → SQL 题
"第 N 高/连续出现" → SQL 模板题

⚠️ 面试准备：
  高频 10 题覆盖全部考点（见第 5 节）
  窗口函数是近年的加分重点
```

### 1.3 核心能力一：JOIN

```
四种 JOIN：
  INNER：只留匹配（默认）
  LEFT：左表全部保留
  RIGHT：右表全部保留
  FULL OUTER：两边全部保留（MySQL 不支持 → UNION）

选型："要保留谁的全部 → 谁是主表"
  例：所有人（含无地址）→ LEFT JOIN

⚠️ 常见错误：
  JOIN 条件方向反（ON 写错列）
  多表 JOIN 漏条件 → 笛卡尔积
```

## 2. 完整代码模板

### 2.1 175. 组合两个表（LEFT JOIN 基础）

```sql
-- 所有人（含无地址者）→ LEFT JOIN
SELECT p.firstName, p.lastName, a.city, a.state
FROM Person p
LEFT JOIN Address a ON p.personId = a.personId;
-- ⚠️ 无地址的人 city/state 为 NULL（LEFT JOIN 保留）
```

### 2.2 176. 第二高薪水（排序 + NULL 处理）

```sql
-- 第二高：降序去重 → OFFSET 1 跳过最高
SELECT (
    SELECT DISTINCT salary
    FROM Employee
    ORDER BY salary DESC
    LIMIT 1 OFFSET 1        -- ⚠️ 跳过第一名
) AS SecondHighestSalary;
-- ⚠️ 子查询返回 NULL → 无第二高时输出 NULL ✓
-- 例：[100, 200, 300] → 200；[100, 100] → NULL（去重后只有 1 个）

-- 第 N 高（177 题）：函数封装
CREATE FUNCTION getNthHighestSalary(N INT) RETURNS INT
BEGIN
  SET N = N - 1;            -- ⚠️ OFFSET 从 0 开始
  RETURN (
    SELECT DISTINCT salary FROM Employee
    ORDER BY salary DESC LIMIT 1 OFFSET N
  );
END
```

### 2.3 184. 部门最高工资（窗口函数）

```sql
-- 窗口函数：分组排名 → 取每组第一名
SELECT Department, Employee, Salary FROM (
    SELECT
        d.name AS Department,
        e.name AS Employee,
        e.salary AS Salary,
        DENSE_RANK() OVER (          -- ⚠️ 并列不跳号
            PARTITION BY d.id        -- 按部门分组
            ORDER BY e.salary DESC   -- 组内工资降序
        ) AS rk
    FROM Employee e
    JOIN Department d ON e.departmentId = d.id
) t WHERE rk = 1;                  -- 每组第一名

-- 185. 部门前三高：WHERE rk <= 3（一行改动）
-- ⚠️ DENSE_RANK vs RANK：
--   并列时 DENSE_RANK：1,1,2；RANK：1,1,3
--   题目要"前 3 高"含并列 → DENSE_RANK
```

### 2.4 180. 连续出现三次（自连接）

```sql
-- 同一数字连续出现 ≥ 3 次
SELECT DISTINCT l1.num AS ConsecutiveNums
FROM Logs l1
JOIN Logs l2 ON l1.id = l2.id - 1 AND l1.num = l2.num
JOIN Logs l3 ON l1.id = l3.id - 2 AND l1.num = l3.num;
-- ⚠️ 自连接 + 相邻 id 匹配（连续 3 个相同）
-- 进阶（任意连续 N 次）：窗口函数 LEAD/LAG
```

## 3. SQL 执行顺序详解

### 3.1 执行顺序（必背）

```
SQL 执行顺序：
  FROM → WHERE → GROUP BY → HAVING
  → SELECT → DISTINCT → ORDER BY → LIMIT

记忆："先取表，再过滤，再分组，再筛选组，
       再选列，再去重，再排序，再限量"

⚠️ 易错点：
  ① WHERE 过滤行（分组前），HAVING 过滤组（分组后）
  ② SELECT 别名不能用于 WHERE（执行顺序）
  ③ GROUP BY 后 SELECT 只能选分组列 + 聚合
```

### 3.2 WHERE vs HAVING

```
WHERE：分组前过滤行（原始数据）
HAVING：分组后过滤组（聚合结果）

例：SELECT dept, COUNT(*) FROM emp
    WHERE salary > 5000          -- 先过滤行
    GROUP BY dept
    HAVING COUNT(*) >= 3;        -- 再过滤组

⚠️ 聚合函数（COUNT/SUM）只能出现在 HAVING
  写在 WHERE 里 → 语法错误
```

### 3.3 去重的两种方式

```
DISTINCT：SELECT 层面去重
  SELECT DISTINCT salary FROM emp;

GROUP BY：分组去重（可配合聚合）
  SELECT salary FROM emp GROUP BY salary;

⚠️ 选型：
  只要去重 → DISTINCT
  需要计数/其他聚合 → GROUP BY
```

## 4. 窗口函数详解

### 4.1 窗口函数 vs GROUP BY

```
GROUP BY：合并成一行（丢失明细）
窗口函数：每行保留 + 附加计算列

例：每人工资 + 部门平均
  GROUP BY：只有部门行
  窗口函数：每人行都有部门平均值

⚠️ 面试表达：
"需要明细 + 组内统计 → 窗口函数
（GROUP BY 会合并行丢失明细）"
```

### 4.2 三大窗口函数

```sql
-- ① 排名函数
ROW_NUMBER()：行号（1,2,3...无并列）
RANK()：排名（1,1,3...并列跳号）
DENSE_RANK()：排名（1,1,2...并列不跳）

-- ② 聚合窗口（累计/移动）
SUM(salary) OVER (ORDER BY id)         -- 累计和
SUM(salary) OVER (PARTITION BY dept)   -- 组内总和

-- ③ 取值窗口
LEAD(salary, 1) OVER (ORDER BY id)     -- 下一行
LAG(salary, 1) OVER (ORDER BY id)      -- 上一行
FIRST_VALUE(salary) OVER (...)         -- 组内第一个

-- 语法：函数() OVER (PARTITION BY 分组 ORDER BY 排序)
```

### 4.3 窗口函数高频应用

```
① 分组 TopK（184/185）：DENSE_RANK + WHERE rk <= K
② 连续问题（180 进阶）：LAG 比较上一行
③ 累计/同比：SUM OVER + LAG
④ 去重保留最新：ROW_NUMBER + 取 rk=1

⚠️ 面试加分：
"窗口函数在 MySQL 8.0+ 支持，
 老版本用变量模拟（GROUP_CONCAT 等）"
```

## 6. 面试要点与追问

### 6.1 面试话术模板

```
"第二高薪水：先按工资降序去重排序，
 OFFSET 1 跳过最高，LIMIT 1 取第二。
 用子查询包裹——没有第二高时返回 NULL
 而不是报错。或者用窗口函数
 DENSE_RANK + 取 rk=2（更通用）。"
```

### 6.2 高频追问 TOP 8

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | JOIN 四种怎么选？ | 要保留谁的全部 → 谁是主表 |
| 2 | WHERE vs HAVING？ | WHERE 过滤行（分组前）；HAVING 过滤组（分组后） |
| 3 | 窗口函数 vs GROUP BY？ | 窗口保留明细；GROUP BY 合并行 |
| 4 | RANK vs DENSE_RANK？ | 并列跳号 vs 不跳号 |
| 5 | 执行顺序？ | FROM→WHERE→GROUP→HAVING→SELECT→ORDER→LIMIT |
| 6 | 第 N 高的 NULL 处理？ | 子查询包裹（无结果返回 NULL） |
| 7 | 连续出现怎么做？ | 自连接相邻 id / LAG 窗口函数 |
| 8 | MySQL 老版本窗口函数？ | 变量模拟（了解） |

### 6.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| OFFSET 从 1 开始 | 少一行 | OFFSET N-1 |
| 忘 DISTINCT | 重复计数 | 排序前去重 |
| WHERE 用聚合 | 语法错误 | 改 HAVING |
| JOIN 条件漏 | 笛卡尔积 | ON 条件完整 |
| GROUP BY 选非分组列 | 报错/随机值 | 只选分组列+聚合 |

> 🎯 **核心要点**：SQL 三件套 = **JOIN（表关系）+ GROUP BY/HAVING（聚合）+ 窗口函数（排名）**。识别信号："SQL 查询、排名、部门/薪水"。执行顺序（FROM→WHERE→GROUP→HAVING→SELECT）与窗口函数模板是必背；OFFSET N-1 与 NULL 处理是两个易错细节。
