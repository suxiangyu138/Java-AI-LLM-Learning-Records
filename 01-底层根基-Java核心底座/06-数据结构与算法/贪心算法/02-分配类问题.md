## 1. 455. 分发饼干：最小满足最小

### 1.1 完整实现

```java
/**
 * LeetCode 455. 分发饼干（贪心入门第一题）
 * 每个孩子最多给一块饼干，饼干尺寸 ≥ 孩子胃口才满足
 * 求最多满足的孩子数
 *
 * 贪心策略：最小饼干满足最小胃口（不浪费大饼干）
 *   ① 排序孩子胃口和饼干尺寸
 *   ② 双指针：能喂就喂，不能喂就换下一块饼干
 *
 * 证明（归纳）：
 *   最小饼干 ≥ 最小胃口 → 给它（最优，大饼干留给大胃口）
 *   最小饼干 < 最小胃口 → 这块饼干满足不了任何人（丢弃）
 */
public int findContentChildren(int[] g, int[] s) {
    Arrays.sort(g);               // 胃口排序
    Arrays.sort(s);               // 饼干排序

    int child = 0, cookie = 0;
    while (child < g.length && cookie < s.length) {
        if (s[cookie] >= g[child]) {
            child++;              // 满足一个孩子
        }
        cookie++;                 // 饼干消耗或丢弃
    }
    return child;
}
```

### 1.2 推演：g = [1, 2, 3], s = [1, 1]

```
排序后 g=[1,2,3], s=[1,1]
cookie=0(1) ≥ child=0(1) → child=1
cookie=1(1) < child=1(2) → 丢弃（饼干太小）
cookie 耗尽 → 返回 1 ✓（只满足 1 个孩子）

关键：如果贪心给大饼干（3）给第一个孩子（1）
→ 第二个孩子（2）无法满足 → 只能 1 个
贪心策略同样 1 个，但大饼干优先的贪心在
g=[1,2], s=[1,2] 时会少满足 → 最小满足最小才是最优
```

## 2. 135. 分发糖果：两趟遍历

### 2.1 完整实现（经典升级题）

```java
/**
 * LeetCode 135. 分发糖果（每个孩子至少 1 颗）
 * 相邻孩子中评分高的必须获得更多糖果
 *
 * 约束是双向的（左邻 + 右邻）→ 两趟遍历：
 *   ① 左到右：右边评分高 → 左边+1
 *   ② 右到左：左边评分高 → 右边+1（取 max 兼顾左规则）
 *
 * 为什么两趟？
 *   只一趟无法同时满足左右两个方向的约束
 *   两趟分别处理一个方向，最后取 max 兼顾
 */
public int candy(int[] ratings) {
    int n = ratings.length;
    int[] candies = new int[n];
    Arrays.fill(candies, 1);        // 每人至少 1 颗

    // ① 左到右：处理"右边评分高"
    for (int i = 1; i < n; i++) {
        if (ratings[i] > ratings[i - 1]) {
            candies[i] = candies[i - 1] + 1;
        }
    }

    // ② 右到左：处理"左边评分高"
    for (int i = n - 2; i >= 0; i--) {
        if (ratings[i] > ratings[i + 1]) {
            candies[i] = Math.max(candies[i], candies[i + 1] + 1);
        }
    }

    int sum = 0;
    for (int c : candies) sum += c;
    return sum;
}
```

### 2.2 为什么第二趟要取 max？

```
ratings = [1, 3, 2, 2, 1]

① 左到右后：candies = [1, 2, 1, 1, 1]
   位置 2（值 2）：右边（值 2）不高 → 保持 1

② 右到左：
   i=3（值 2）> i=4（值 1）→ candies[3] = max(1, 1+1) = 2
   i=2（值 2）> i=3（值 2）？否 → 保持 1
   i=1（值 3）> i=2（值 2）→ candies[1] = max(2, 1+1) = 2
   i=0（值 1）> i=1（值 3）？否

取 max 的意义：位置 1 已经被左规则给了 2，
右规则要求至少 2 → max(2, 2) = 2 不减少已有分配

⚠️ 如果第二趟直接赋值（不取 max）：
  可能覆盖左规则的结果 → 违反"右边评分高"约束
```

## 3. 1005. K 次取反：贪心排序

### 3.1 完整实现

```java
/**
 * LeetCode 1005. K 次取反后最大化的数组和
 * 恰好 k 次取反（一个数可以多次取反），最大化数组和
 *
 * 贪心策略：
 *   ① 优先把负数翻正（绝对值大的负数收益最大）
 *   ② 负数翻完后：
 *      剩偶数次 → 翻来翻去等于没翻 → 直接返回
 *      剩奇数次 → 把绝对值最小的数翻负（损失最小）
 */
public int largestSumAfterKNegations(int[] nums, int k) {
    // 按绝对值从大到小排序（优先翻大负数）
    nums = Arrays.stream(nums)
                 .boxed()
                 .sorted((a, b) -> Math.abs(b) - Math.abs(a))
                 .mapToInt(Integer::intValue)
                 .toArray();

    for (int i = 0; i < nums.length && k > 0; i++) {
        if (nums[i] < 0) {        // 负数翻正
            nums[i] = -nums[i];
            k--;
        }
    }

    // 剩余 k 次：奇数 → 翻最小绝对值；偶数 → 不变
    if (k % 2 == 1) {
        nums[nums.length - 1] = -nums[nums.length - 1];
    }

    int sum = 0;
    for (int x : nums) sum += x;
    return sum;
}
```

### 3.2 关键决策点

```
① 为什么按绝对值排序？
   翻负数时绝对值大的收益大（-5→5 收益 10）
   → 优先翻绝对值大的负数

② 为什么最后翻最小绝对值？
   奇数剩余 1 次必须翻一个数
   → 翻绝对值最小的数损失最小

③ 负数翻完 k 还有剩：
   偶数次 → 一正一负抵消
   奇数次 → 必须牺牲一个（最小绝对值）
```

## 4. 860. 柠檬水找零

### 4.1 完整实现（模拟贪心）

```java
/**
 * LeetCode 860. 柠檬水找零
 * 柠檬水 5 美元，顾客用 5/10/20 支付，依次找零
 * 判断能否给所有顾客正确找零
 *
 * 贪心策略：找零时优先用大面额（10 优先于 5）
 *   （因为 5 元更灵活——能应付 5 和 10 的找零）
 */
public boolean lemonadeChange(int[] bills) {
    int five = 0, ten = 0;

    for (int bill : bills) {
        if (bill == 5) {
            five++;                    // 收 5 元
        } else if (bill == 10) {
            if (five == 0) return false;   // 需要 5 元找零
            five--;
            ten++;
        } else {                       // 20 元
            if (ten > 0 && five > 0) {
                ten--;                 // 优先 10+5 组合
                five--;
            } else if (five >= 3) {
                five -= 3;             // 或者 3 张 5 元
            } else {
                return false;
            }
        }
    }
    return true;
}
```

### 4.2 为什么优先用 10 元找零？

```
5 元是最灵活的（5/10/20 找零都需要）
10 元只能用于 20 的找零

找 20 元时：
  方案 A：10 + 5（消耗一张 10）
  方案 B：5 + 5 + 5（消耗三张 5）
  → 优先 A：保留 5 元灵活性

这是贪心："优先消耗最不灵活的钞票"
```

## 5. 分配类问题总结

### 5.1 题型对比

| 题号 | 题目 | 贪心策略 | 排序？ | 复杂度 |
|:---:|------|------|:---:|:---:|
| 455 | 分发饼干 | 最小满足最小 | ✅ | O(n log n) |
| 135 | 分发糖果 | 两趟遍历 | ❌ | O(n) |
| 1005 | K 次取反 | 绝对值排序 | ✅ | O(n log n) |
| 860 | 柠檬水找零 | 优先大面额 | ❌ | O(n) |
| 409 | 最长回文串 | 偶数计数 | ❌ | O(n) |

### 5.2 分配类贪心共性

```
共性："需求 → 资源"的匹配问题
  孩子的胃口 → 饼干尺寸
  评分比较 → 糖果分配
  负数翻正 → 取反次数

解题四问：
  ① 谁是最小/最急迫的需求？
  ② 哪个资源成本最低？
  ③ 排序后从哪端开始匹配？
  ④ 剩余资源如何处理？

面试话术：
"贪心策略是【最小成本满足最小需求】——
 排序后从最小的开始匹配，
 证明：交换论证——用最小资源满足最小需求
 不会比任何其他匹配更差。"
```

> 🎯 **核心要点**：分配类贪心的共同模式是**"排序 + 从最优端开始匹配"**——455 最小满足最小、1005 绝对值排序优先翻大负、860 优先消耗不灵活面额。135 是升级题：**双向约束用两趟遍历**，第二趟取 max 防止覆盖。四道题 + 证明话术掌握后，分配类贪心就是送分题。
