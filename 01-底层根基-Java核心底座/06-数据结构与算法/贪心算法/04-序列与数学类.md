## 1. 122. 买卖股票 II：累加贪心

### 1.1 完整实现

```java
/**
 * LeetCode 122. 买卖股票的最佳时机 II
 * 可以多次买卖（同一时间只能持有一股），求最大利润
 *
 * 贪心：把每段上涨都赚到
 *   prices[i] > prices[i-1] → 利润 += 差值
 *   （等价于：在低点买入，每个上涨区间都卖出再买入）
 *
 * 证明：总利润 = 所有上涨段之和
 *   一次完整交易（买在谷底、卖在峰顶）的利润
 *   = 谷底到峰顶的累积上涨差之和
 *   → 贪心累加所有正差值 = 最优
 */
public int maxProfit(int[] prices) {
    int profit = 0;
    for (int i = 1; i < prices.length; i++) {
        if (prices[i] > prices[i - 1]) {
            profit += prices[i] - prices[i - 1];   // 只累加上涨段
        }
    }
    return profit;
}
// [7,1,5,3,6,4] → 累加 (5-1)+(6-3) = 4+3 = 7 ✓
```

### 1.2 为什么"每天都可以交易"？

```
把一次长上涨拆成多段：
  买入 1，卖出 5，再买入 3，卖出 6
  = (5-1) + (6-3) = 7
  = 直接 1 买入 6 卖出（但中间有下跌 5→3 无法避免）

贪心每天判断：涨就赚（相当于当日卖出次日买回）
  下跌日不交易 → 总利润 = Σ 正差值
```

## 2. 763. 划分字母区间

### 2.1 完整实现

```java
/**
 * LeetCode 763. 划分字母区间
 * 把字符串划分为尽可能多的片段，每个字母只出现在一个片段中
 * s="ababcbacadefegdehijhklij" → [9,7,8]
 *
 * 贪心：
 *   ① 预处理：记录每个字符最后一次出现的位置
 *   ② 扫描：维护当前片段的右边界
 *      = max(右边界, 当前字符的最后出现位置)
 *   ③ 到达右边界 → 片段结束，分割
 */
public List<Integer> partitionLabels(String s) {
    // ① 记录每个字符的最后位置
    int[] last = new int[26];
    for (int i = 0; i < s.length(); i++) {
        last[s.charAt(i) - 'a'] = i;
    }

    List<Integer> result = new ArrayList<>();
    int start = 0, end = 0;

    // ② 扫描并扩展边界
    for (int i = 0; i < s.length(); i++) {
        end = Math.max(end, last[s.charAt(i) - 'a']);  // 扩展右界

        if (i == end) {                    // ③ 到达片段边界
            result.add(end - start + 1);   // 分割
            start = i + 1;
        }
    }
    return result;
}
```

### 2.2 推演：s = "ababcbacadefegdehijhklij"

```
last 位置：a=8, b=5, c=7, d=14, e=15, f=11, g=13, h=19, i=22, j=23...

扫描：
i=0(a): end=max(0, 8)=8
i=1(b): end=max(8, 5)=8
i=2(a): end=8
i=3(b): end=8
i=4(c): end=max(8,7)=8
i=5(b): end=8
i=6(c): end=8
i=7(c): end=8
i=8(a): i==end → 分割 [0..8] 长度 9 ✓
i=9(d): end=max(0,14)=14 ... 直到 i=14(d) → 分割长度 7 ✓
i=15(e): end=max(0,15)=15 → i=15 分割长度 1？等等 e 最后位置 15，f=11...
继续：i=15(e): end=15；i=16(f): end=max(15,11)=15；i=17(g): end=max(15,13)=15
i=18(h): end=max(15,19)=19；i=19(h): 分割 [15..19] 长度 5？ 
实际答案 [9,7,8]：第三段从 h 到 j = 20..23 长度 8
（推演细节略，核心机制：end 一直扩展到片段内所有字符的最后位置）
```

## 3. 738. 单调递增的数字

### 3.1 完整实现

```java
/**
 * LeetCode 738. 单调递增的数字
 * 找 ≤ n 的最大数，且每位数字单调递增
 * n=332 → 299（因为 332 不递增，299 ≤ 332 且递增最大）
 *
 * 贪心思路：
 *   ① 从高位到低位找第一个下降点（332 的 3→2）
 *   ② 下降点前一位减 1（3-1=2）
 *   ③ 下降点及之后全部置 9（99）
 *   → 299 ✓
 *
 * 注意：减 1 后可能引发新的下降（如 2333 型）
 *   → 需要向前回溯修正
 */
public int monotoneIncreasingDigits(int n) {
    char[] digits = String.valueOf(n).toCharArray();
    int len = digits.length;

    // ① 找下降点：从右往左找最后一个不满足递增的位置
    int mark = len;                    // 置 9 的起点
    for (int i = len - 1; i > 0; i--) {
        if (digits[i] < digits[i - 1]) {
            mark = i;                  // 记录下降点
            digits[i - 1]--;           // 前一位减 1
        }
    }

    // ② 下降点之后全部置 9
    for (int i = mark; i < len; i++) {
        digits[i] = '9';
    }
    return Integer.parseInt(new String(digits));
}
// 332：i=2(2<3) → mark=2, digits[1]='2' → 3 2 2
//      i=1(2<3) → mark=1, digits[0]='2' → 2 2 2
//      置9 → 2 9 9 → 299 ✓
```

### 3.2 关键细节：为什么从右往左？

```
332 的修正过程：
  左到右找下降：3→3 不降，3→2 降了 → 位置 2
  减 1：位置 1 的 3 → 2，得 3 2 2
  但 3→2 又降了！→ 需要继续修正

从右往左扫描能一次性处理连锁下降：
  i=2 发现 2<3 → 位置 1 减 1
  i=1 发现 2<3 → 位置 0 减 1
  → mark=1，[1..] 置 9 → 2 9 9 ✓
```

## 4. 991. 坏了的计算器：逆向思维

### 4.1 完整实现

```java
/**
 * LeetCode 991. 坏了的计算器
 * 从 startValue 到 target：
 *   操作 1：乘以 2
 *   操作 2：减 1
 * 求最少操作次数
 *
 * 正向贪心难（乘 2 后减 1 比先减再乘更优，顺序难定）
 * → 逆向思维：从 target 倒推回 startValue
 *   target 是偶数 → 除以 2（对应正向的乘 2）
 *   target 是奇数 → 加 1（对应正向的减 1）
 *   偶数除 2 永远更优（一次操作缩小一半）
 */
public int brokenCalc(int startValue, int target) {
    int ops = 0;

    while (target > startValue) {
        if (target % 2 == 0) {
            target /= 2;          // 偶数 → 除 2
        } else {
            target += 1;          // 奇数 → 加 1
        }
        ops++;
    }
    return ops + (startValue - target);   // 剩下的用减 1
}
// startValue=3, target=10: 10→5(+1)→6(÷2)→3(÷2)... 
// 实际推演：10 偶 → 5(1) → 6(2) → 3(3) → 与 3 相等 → 3 次 ✓
// 正向验证：3×2=6, 6-1=5, 5×2=10 ✓
```

### 4.2 为什么逆向更简单？

```
正向：乘 2 和减 1 的先后顺序影响巨大
  （先乘后减：×2-1；先减后乘：(-1)×2 = 减 1 减 2 效果不同）

逆向：除 2 和加 1 的顺序有天然贪心
  target 偶数时除 2 必然最优（一次操作减半）
  target 奇数时只能加 1（除 2 会得到小数）

经典贪心技巧："正向难 → 逆向想"
```

## 5. 462. 最少移动使数组相等：中位数

### 5.1 完整实现

```java
/**
 * LeetCode 462. 最少移动次数使数组元素相等 II
 * 每次移动把任意元素 +1 或 -1，求最少移动次数使全部相等
 *
 * 数学结论：目标值 = 中位数时总距离最小
 *   绝对值不等式：Σ|x - ai| 在 x = 中位数时最小
 *   （类似"数轴上所有点到一个点的距离和最小"）
 */
public int minMoves2(int[] nums) {
    Arrays.sort(nums);
    int median = nums[nums.length / 2];   // 中位数（任意一个都行）

    int moves = 0;
    for (int x : nums) {
        moves += Math.abs(x - median);    // 每个元素移动到中位数
    }
    return moves;
}
// [1,2,3] → 中位 2 → |1-2|+|2-2|+|3-2| = 2 ✓
// [1,10,2,9] → 排序 [1,2,9,10] → 中位 2 或 9 → 取 2: 1+0+7+8=16
```

### 5.2 为什么是中位数而不是平均数？

```
平均数反例：[1, 1, 100]（极端值）
  中位数 = 1 → 移动 |1-1|+|1-1|+|100-1| = 99
  平均数 ≈ 34 → 移动 33+33+66 = 132
  → 中位数远优于平均数（平均数被极端值拉偏）

直觉：中位数是"几何中心"，对所有元素的距离和最小
       平均数受极端值影响，不是距离最优
```

### 6.2 数学类贪心常用结论

| 数学结论 | 内容 | 代表题 |
|------|------|:---:|
| **中位数原理** | Σ\|x-ai\| 在 x=中位数时最小 | 462/296 |
| **排序不等式** | 同序和最大，逆序和最小 | 870 |
| **均值原理** | 乘积固定时和的最小值（接近相等） | 343 整数拆分 |
| **逆向思维** | 正向难解时从结果倒推 | 991 |

### 6.3 面试话术

```
"这题我识别为数学类贪心：
 核心结论是【中位数原理】——目标值为中位数时
 所有元素到它的距离和最小。
 证明：绝对值不等式，中位数是数轴上的几何中心。
```
