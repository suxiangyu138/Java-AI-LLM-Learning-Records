## 1. 区间调度的核心模型

### 1.1 问题原型

```
经典区间调度：
  给定若干区间 [start, end]，选择最多的互不重叠区间

贪心策略：按结束时间排序，优先选择结束最早的区间
  然后跳过所有与它重叠的，继续选下一个结束最早的

为什么按结束时间排序？
  结束早 → 留出的空间多 → 能容纳更多区间
  交换论证：最优解中第一个区间可以用
  "结束最早"的区间替换而不影响后续选择
```

### 1.2 两种排序视角

| 排序方式 | 用途 | 代表题 |
|------|------|:---:|
| **按结束时间升序** | 选最多互不重叠区间 | 435/452 |
| **按开始时间升序** | 合并区间/统计重叠 | 56/253 |

```
记忆：要"最多不重叠"→ 按结束排序（尽快让出空间）
     要"覆盖所有"→ 按开始排序（从早到晚扫描）
```

## 2. 435. 无重叠区间

### 2.1 完整实现

```java
/**
 * LeetCode 435. 无重叠区间（区间贪心教科书题）
 * 移除最少的区间，使剩余区间互不重叠
 * [[1,2],[2,3],[3,4],[1,3]] → 移除 [1,3] → 1
 *
 * 等价转化：移除最少 = 保留最多不重叠
 * 贪心：按结束时间排序，保留结束最早的
 *   当前区间与保留的最后一个重叠 → 丢弃当前
 *   不重叠 → 保留
 */
public int eraseOverlapIntervals(int[][] intervals) {
    // 按结束时间升序排序
    Arrays.sort(intervals, (a, b) -> a[1] - b[1]);

    int count = 0;              // 移除的区间数
    int lastEnd = Integer.MIN_VALUE;   // 最后保留区间的结束

    for (int[] interval : intervals) {
        if (interval[0] >= lastEnd) {
            lastEnd = interval[1];     // 不重叠 → 保留，更新边界
        } else {
            count++;                   // 重叠 → 丢弃
        }
    }
    return count;
}
```

### 2.2 交换论证（面试必讲）

```
证明：按结束时间排序的贪心是最优的

假设最优解第一个区间是 X，贪心选的是 G（结束最早）
  G.end ≤ X.end
  用 G 替换 X：
    - G 结束不晚于 X → 与后续区间的冲突不更多
    - 保留的区间数不变
  → 替换后解不更差
  → 贪心选择可以出现在最优解中
  → 归纳推进：每步贪心 → 全局最优 ✓
```

### 2.3 推演：[[1,2],[2,3],[3,4],[1,3]]

```
按结束排序：[[1,2],[2,3],[1,3],[3,4]]
lastEnd = -∞
[1,2]：1 ≥ -∞ → 保留，lastEnd=2
[2,3]：2 ≥ 2 → 保留，lastEnd=3
[1,3]：1 < 3 → 重叠，丢弃 count=1
[3,4]：3 ≥ 3 → 保留，lastEnd=4
返回 1 ✓
```

## 3. 452. 用最少数量的箭引爆气球

### 3.1 完整实现（435 的孪生题）

```java
/**
 * LeetCode 452. 用最少数量的箭引爆气球
 * 气球是 [xstart, xend] 区间，一支箭射中 x 坐标
 * 可引爆所有覆盖 x 的气球。求最少箭数。
 *
 * 与 435 的关系：
 *   435：移除最少使不重叠（保留结束最早）
 *   452：一支箭 = 一组重叠气球（同样按结束排序）
 *   —— 本质相同！唯一区别：端点相撞算重叠
 */
public int findMinArrowShots(int[][] points) {
    // ⚠️ 用 Integer.compare 防 int 溢出（区间可为极大负数）
    Arrays.sort(points, (a, b) -> Integer.compare(a[1], b[1]));

    int arrows = 1;                        // 至少一支箭
    int lastEnd = points[0][1];            // 当前箭的覆盖右界

    for (int i = 1; i < points.length; i++) {
        // 端点相撞算重叠 → 用 > 而不是 >=
        if (points[i][0] > lastEnd) {
            arrows++;                      // 需要新箭
            lastEnd = points[i][1];        // 更新覆盖范围
        }
    }
    return arrows;
}
```

### 3.2 435 vs 452 一字之差

```
435 无重叠区间：interval[0] >= lastEnd → 不重叠（保留）
452 引爆气球：  points[i][0] > lastEnd → 不重叠（新箭）

区别：452 端点相撞（10 和 10）算同一支箭
  → 435 用 >=（相撞算不重叠）
  → 452 用 >（相撞算重叠）

面试必讲："这两题是同一个模型，
 唯一的区别是端点是否算重叠——一字之差！"
```

## 4. 56. 合并区间

### 4.1 完整实现（按开始排序）

```java
/**
 * LeetCode 56. 合并区间
 * 合并所有重叠区间
 * [[1,3],[2,6],[8,10],[15,18]] → [[1,6],[8,10],[15,18]]
 *
 * 贪心（按开始排序）：覆盖式扫描
 *   当前区间与上一个合并结果重叠 → 扩展右边界
 *   不重叠 → 输出上一个，开始新的
 */
public int[][] merge(int[][] intervals) {
    Arrays.sort(intervals, (a, b) -> a[0] - b[0]);   // 按开始排序

    List<int[]> result = new ArrayList<>();
    int[] current = intervals[0];        // 当前合并区间

    for (int i = 1; i < intervals.length; i++) {
        if (intervals[i][0] <= current[1]) {
            // 重叠 → 扩展右边界（取较大的结束）
            current[1] = Math.max(current[1], intervals[i][1]);
        } else {
            result.add(current);         // 不重叠 → 输出
            current = intervals[i];      // 开始新区间
        }
    }
    result.add(current);                 // 最后一个
    return result.toArray(new int[0][]);
}
```

### 4.2 推演：[[1,3],[2,6],[8,10],[15,18]]

```
排序（已有序）后：
current = [1,3]
[2,6]：2 ≤ 3 → 重叠 → current=[1,6]
[8,10]：8 > 6 → 输出 [1,6]，current=[8,10]
[15,18]：15 > 10 → 输出 [8,10]，current=[15,18]
最后输出 [15,18]
结果 [[1,6],[8,10],[15,18]] ✓
```

## 5. 253. 会议室 II

### 5.1 完整实现（排序+最小堆）

```java
/**
 * LeetCode 253. 会议室 II（付费题，面试高频）
 * 求最少需要的会议室数
 * [[0,30],[5,10],[15,20]] → 2
 *
 * 方法一（推荐）：按开始排序 + 最小堆存结束时间
 *   堆顶 = 最早结束的会议
 *   新会议开始 ≥ 堆顶结束 → 复用会议室（弹出堆顶）
 *   否则 → 新开会议室（入堆）
 *   堆大小 = 同时进行的会议数 = 最少会议室
 */
public int minMeetingRooms(int[][] intervals) {
    Arrays.sort(intervals, (a, b) -> a[0] - b[0]);   // 按开始排序

    // 最小堆：存会议结束时间
    PriorityQueue<Integer> heap = new PriorityQueue<>();

    for (int[] meeting : intervals) {
        if (!heap.isEmpty() && meeting[0] >= heap.peek()) {
            heap.poll();            // 复用：最早结束的会议已结束
        }
        heap.offer(meeting[1]);     // 分配会议室
    }
    return heap.size();             // 同时进行的最多会议数
}

// 方法二：差分数组（扫描线思想）
//   开始 +1，结束 -1，最大前缀和 = 最少会议室
```

### 5.2 区间四大题模型对比

| 题号 | 题目 | 排序键 | 处理方式 | 答案 |
|:---:|------|:---:|------|------|
| 435 | 无重叠区间 | 结束 | 保留最早结束 | 移除数 |
| 452 | 引爆气球 | 结束 | 重叠合并 | 箭数 |
| 56 | 合并区间 | **开始** | 扩展右界 | 合并结果 |
| 253 | 会议室 II | **开始** | 堆管理 | 最大并发数 |

```
记忆：
  求"最多/最少"（选区间）→ 按结束排序（让出空间）
  求"覆盖/合并"（扫区间）→ 按开始排序（从早到晚）
```

## 6. 区间类问题总结

### 6.1 解题框架

```
区间题五步：
① 排序：按开始 or 结束（看目标）
② 边界：lastEnd / current 初始化
③ 扫描：逐区间处理（重叠判断）
④ 更新：扩展边界 or 输出
⑤ 收尾：最后一个区间处理

重叠判断公式：
  区间 i 与已保留区间重叠 ⇔ interval[i].start < lastEnd
  （是否包含端点决定 < 还是 <=）
```

### 6.2 高频追问

| 追问 | 标准回答 |
|------|------|
| 为什么按结束时间排序？ | 结束早留出的空间多，交换论证证明贪心最优 |
| 435 和 452 什么关系？ | 同一模型——"选择互不重叠区间"，仅端点处理不同 |
| 合并区间为什么按开始排序？ | 从早到晚扫描才能顺序合并，按结束排序会漏合并 |
| 会议室为什么用堆？ | 需要快速获取"最早结束"的会议 → 最小堆 O(log n) |
| 区间题时间复杂度？ | 排序 O(n log n) + 扫描 O(n) = O(n log n) |

> 🎯 **核心要点**：区间贪心是面试必考模型——**"选最多"按结束排序（435/452），"扫覆盖"按开始排序（56/253）**。435 的交换论证是证明模板，452 的"一字之差"（>= vs >）是细节考点，253 的堆管理是进阶。四个模型吃透 + 一句话论证，区间题全部拿下。
