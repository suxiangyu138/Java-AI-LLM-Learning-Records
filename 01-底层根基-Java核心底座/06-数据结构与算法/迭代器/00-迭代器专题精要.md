## 1. 核心概念

### 1.1 什么是迭代器

> 迭代器（Iterator）：提供**逐个访问元素**的接口，隐藏底层结构。核心契约——**hasNext()**（还有吗）+ **next()**（取下一个）。

```
设计意图：
  惰性：按需生成/遍历，不一次性加载全部
  解耦：调用者无需知道底层结构
  统一：不同结构相同遍历接口

Java 接口：
  Iterator<E>：hasNext() / next() / remove()
  Iterable<E>：iterator()（for-each 支持）
```

### 1.2 识别信号

```
"设计迭代器/遍历器" → 迭代器题
"扁平化嵌套结构" → 栈存子迭代器
"惰性/按需遍历" → 迭代器思想

⚠️ 迭代器题 = 状态管理题
  核心难点：hasNext/next 的状态一致性
```

### 1.3 迭代器 vs 递归遍历

```
迭代器：惰性（需要才算）、有状态、可暂停
递归：一次性算完、无状态、不可暂停

→ 数据流/超大结构用迭代器
  （无法一次加载全部 → 按需生成）
```

## 2. 完整代码模板

### 2.1 284. 顶端迭代器（预取模式）

```java
/**
 * LeetCode 284. 顶端迭代器
 * 在普通迭代器上加 peek()（预取下一个）
 * ⚠️ 核心：预取缓存（cached）保证 peek/next 一致
 */
class PeekingIterator implements Iterator<Integer> {
    private Iterator<Integer> iterator;
    private Integer cached;          // ⚠️ 预取缓存

    public PeekingIterator(Iterator<Integer> iterator) {
        this.iterator = iterator;
        cached = iterator.hasNext() ? iterator.next() : null;
    }

    public Integer peek() {
        return cached;               // 看而不取
    }

    @Override
    public Integer next() {
        Integer result = cached;     // 返回缓存
        cached = iterator.hasNext() ? iterator.next() : null;  // 预取下一个
        return result;
    }

    @Override
    public boolean hasNext() {
        return cached != null;       // 缓存即状态
    }
}
// ⚠️ 为什么预取？
//   普通迭代器 peek 需要"取回来"（做不到）
//   预取缓存让 peek/next 共用同一状态 → 一致
```

### 2.2 341. 扁平化嵌套列表（栈存迭代器）

```java
/**
 * LeetCode 341. 扁平化嵌套列表迭代器
 * [[1,1],2,[1,1]] → [1,1,2,1,1]
 * ⚠️ 惰性展开：只展开到下一个整数（不全量展开）
 */
public class NestedIterator implements Iterator<Integer> {
    Deque<Iterator<NestedInteger>> stack = new ArrayDeque<>();
    Integer nextVal;                 // 预取的下一个值

    public NestedIterator(List<NestedInteger> nestedList) {
        stack.push(nestedList.iterator());
    }

    @Override
    public Integer next() {
        if (nextVal == null) advance();
        Integer result = nextVal;
        nextVal = null;              // ⚠️ 取走（防重复）
        return result;
    }

    @Override
    public boolean hasNext() {
        if (nextVal == null) advance();
        return nextVal != null;
    }

    // ⚠️ 核心：推进到下一个整数（惰性展开）
    private void advance() {
        nextVal = null;
        while (!stack.isEmpty()) {
            Iterator<NestedInteger> it = stack.peek();
            if (!it.hasNext()) {
                stack.pop();         // 当前迭代器耗尽 → 弹栈
                continue;
            }
            NestedInteger next = it.next();
            if (next.isInteger()) {
                nextVal = next.getInteger();   // 找到整数
                break;
            }
            stack.push(next.getList().iterator());  // 嵌套 → 压栈
        }
    }
}
// 空间 O(深度)（只存路径上的迭代器，不存全部）
// ⚠️ 惰性：每次只展开一层（next 需要时才深入）
```

### 2.3 173. 二叉搜索树迭代器（树迭代）

```java
/**
 * LeetCode 173. 二叉搜索树迭代器
 * 中序迭代遍历（左探-回溯-右转）
 * next/hasNext 均摊 O(1)，空间 O(h)
 */
class BSTIterator {
    private Deque<TreeNode> stack = new ArrayDeque<>();
    private TreeNode cur;

    public BSTIterator(TreeNode root) {
        cur = root;
        // 初始左探（压入左路径）
        while (cur != null) {
            stack.push(cur);
            cur = cur.left;
        }
    }

    public int next() {
        // 回溯 + 右转
        TreeNode node = stack.pop();
        int val = node.val;
        cur = node.right;
        while (cur != null) {        // 右子树左探
            stack.push(cur);
            cur = cur.left;
        }
        return val;
    }

    public boolean hasNext() {
        return !stack.isEmpty();
    }
}
// 与中序迭代遍历同构（树的迭代器 = 按需遍历）
```

## 3. 迭代器的设计要点

### 3.1 hasNext/next 一致性

```
⚠️ 核心契约：
  next() 前必须先 hasNext()（调用者约定）
  hasNext() 不应改变状态（可多次调用）

实现模式：
  ① 预取模式：hasNext 时已看过下一个
     nextVal 缓存 → 两方法共用状态 → 天然一致
  ② 状态推进：hasNext 不推进，next 才推进
     ⚠️ 需要维护"当前指针"精确语义

面试推荐预取模式（一致性好实现）
```

### 3.2 惰性 vs 急切

```
惰性（推荐）：
  只计算/展开"下一个"需要的
  空间 O(深度) 而非 O(总量)

急切（简单）：
  构造时全部展开（存列表）
  空间 O(n)

⚠️ 面试表达：
"我用惰性实现——栈保存遍历路径，
 只展开到下一个元素，空间 O(深度)。
 急切版简单但空间 O(n)，大数据不适用。"
```

### 3.3 状态管理

```
迭代器本质 = 遍历状态的封装：
  数组：next 下标
  链表：当前节点
  树：栈（左路径）
  嵌套：栈（子迭代器）

⚠️ 设计题通用思路：
  ① 确定"遍历到哪了"（状态变量）
  ② 确定"下一步怎么走"（推进逻辑）
  ③ 保证两方法共享同一状态
```

## 4. 迭代器的应用场景

### 4.1 场景一：扁平化（341）

```
嵌套列表/树形数据 → 迭代器展开
  栈存子迭代器 → 惰性深入
  找到整数 → 返回

⚠️ 变体：251 展开二维向量（行/列迭代器）
  281 锯齿迭代器（交替取用）
```

### 4.2 场景二：树的按需遍历（173）

```
BST 中序迭代器：
  栈存左路径 → next 弹栈 → 右转左探
  均摊 O(1)（每个节点进出栈一次）

应用：合并两个 BST（两迭代器归并）
```

### 4.3 场景三：数据流（惰性加载）

```
超大文件/无限流：
  迭代器按需读取 → 不占内存
  生产-消费模式（iterator + hasNext 控制）

⚠️ 与数据流标签的关系：
  数据流：在线统计（堆/双堆）
  迭代器：按需遍历（惰性）
  → 两者常结合（数据流题用迭代器读入）
```

## 6. 面试要点与追问

### 6.1 面试话术模板

```
"迭代器用预取模式：hasNext 时提前看下一个
 并缓存（nextVal），next 返回缓存并预取下一个。
 这样 hasNext/next 状态一致。
 嵌套结构用栈存子迭代器实现惰性展开，
 空间 O(深度) 而非 O(总量)。"
```

### 6.2 高频追问 TOP 8

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | hasNext/next 一致性？ | 预取模式：共用 nextVal 缓存 |
| 2 | 惰性 vs 急切？ | 惰性空间 O(深度)；急切 O(n) |
| 3 | next 忘置 null？ | 返回重复 | 取走缓存 |
| 4 | 嵌套怎么展开？ | 栈存子迭代器（深度路径） |
| 5 | 树的迭代器？ | 栈模拟中序（左探-回溯-右转） |
| 6 | 均摊 O(1)？ | 每个节点进出栈一次 |
| 7 | remove() 实现？ | 记录最后返回的元素（可选实现） |
| 8 | 与递归区别？ | 迭代器惰性可暂停；递归一次算完 |

### 6.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| next 忘置 null | 重复返回 | 取走缓存 |
| hasNext 推进状态 | 语义错误 | 预取模式共享 |
| 急切展开全部 | 空间爆炸 | 惰性栈 |
| 栈顺序错 | 展开顺序乱 | 嵌套先压栈 |
| 忘判空栈 | 空指针 | advance 先检查 |

> 🎯 **核心要点**：迭代器 = **预取缓存（peek 模式）+ 状态一致性**。识别信号："设计迭代器、扁平化、惰性遍历"。栈存子迭代器（341）与树的迭代遍历（173）是两大经典实现；惰性空间 O(深度) 是加分表达。
