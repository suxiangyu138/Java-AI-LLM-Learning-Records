## 1. 队列实现的完整体系

### 1.1 三种实现

| 实现 | 操作 | 特点 |
|------|:---:|------|
| 数组（循环） | O(1) | 固定容量，需取模 |
| 链表 | O(1) | 动态容量，节点开销 |
| 动态数组（ArrayList） | O(1) 均摊 | 队尾高效，队首 O(n) |

```
⚠️ Java 实现：
  Queue<Integer> = LinkedList（链表）
  Deque<Integer> = ArrayDeque（循环数组）

⚠️ 面试表达：
"LinkedList 实现队列（FIFO 天然）；
 ArrayDeque 实现双端队列（循环数组更快）。"
```

### 1.2 队列 vs 栈

| 维度 | 队列 | 栈 |
|------|:---:|:---:|
| 顺序 | FIFO | LIFO |
| 操作端 | 尾进头出 | 栈顶 |
| 典型 | BFS/调度 | 括号/DFS |

```
⚠️ 识别："顺序相关" → 队列；"最近相关" → 栈
```

### 1.3 识别信号

```
"先进先出/顺序处理" → 队列
"BFS/层序扩散" → 队列（102/994）
"窗口过期移除" → 队列（933）
"公平调度" → 队列

⚠️ 队列是 BFS 的唯一正确结构
```

## 2. 循环队列详解

### 2.1 622. 设计循环队列（数组实现）

```java
/**
 * LeetCode 622. 设计循环队列
 * 数组 + 取模循环
 */
class MyCircularQueue {
    private int[] data;
    private int head = 0, tail = 0;      // 队首/队尾下标
    private int size = 0;                // 当前元素数

    public MyCircularQueue(int k) {
        data = new int[k];
    }

    public boolean enQueue(int value) {
        if (isFull()) return false;
        data[tail] = value;
        tail = (tail + 1) % data.length; // ⚠️ 取模循环！
        size++;
        return true;
    }

    public boolean deQueue() {
        if (isEmpty()) return false;
        head = (head + 1) % data.length; // ⚠️ 取模循环！
        size--;
        return true;
    }

    public int Front() {
        return isEmpty() ? -1 : data[head];
    }

    public int Rear() {
        return isEmpty() ? -1
            : data[(tail - 1 + data.length) % data.length];  // ⚠️ 防负
    }

    public boolean isEmpty() { return size == 0; }
    public boolean isFull() { return size == data.length; }
}
// ⚠️ 循环队列两个细节：
//   ① 取模循环：(tail+1) % len
//   ② 队尾取值：(tail-1+len) % len（防负数下标！）
// ⚠️ 为什么要 size？
//   head == tail 可能"空"也可能"满" → 需要 size 区分
//   或用"浪费一个槽位"的方案
```

### 2.2 641. 设计循环双端队列

```java
/**
 * LeetCode 641. 设计循环双端队列
 * = 622 + 两端操作
 * 前插/后插/前删/后删均 O(1)
 */
class MyCircularDeque {
    private int[] data;
    private int head = 0, tail = 0;
    private int size = 0;
    private int capacity;

    public MyCircularDeque(int k) {
        data = new int[k];
        capacity = k;
    }

    // 前插：head 前移（取模）+ 赋值
    public boolean insertFront(int value) {
        if (isFull()) return false;
        head = (head - 1 + capacity) % capacity;   // ⚠️ 前移（防负）
        data[head] = value;
        size++;
        return true;
    }

    // 后插：赋值 + tail 后移（与 622 相同）
    public boolean insertLast(int value) {
        if (isFull()) return false;
        data[tail] = value;
        tail = (tail + 1) % capacity;
        size++;
        return true;
    }

    // 前删：head 后移
    public boolean deleteFront() {
        if (isEmpty()) return false;
        head = (head + 1) % capacity;
        size--;
        return true;
    }

    // 后删：tail 前移（防负）
    public boolean deleteLast() {
        if (isEmpty()) return false;
        tail = (tail - 1 + capacity) % capacity;
        size--;
        return true;
    }
    // getFront/getRear/isEmpty/isFull 同 622
}
// ⚠️ 双端操作的四个方向（取模方向）：
//   前插/后删：前移（-1+len）% len
//   后插/前删：后移（+1）% len
```

### 2.3 循环队列的工程价值

```
① 固定容量 + O(1) 全部操作
② 不扩容（避免 GC/拷贝）
③ 适合"环形缓冲"（生产者-消费者）

⚠️ 工程类比：
  Kafka/环形缓冲/滑动日志
  ArrayDeque 底层就是循环数组

⚠️ 面试表达：
"循环队列 = 数组 + 取模——
 固定容量 O(1) 操作，工程上用于
 环形缓冲（Kafka/日志）。"
```

## 3. 双端队列的应用

### 3.1 单调队列（窗口最值）

```
Deque 维护窗口单调性：
  入队淘汰（晚到且大淘汰早到且小）
  过期弹出（队头滑出窗口）
  队头 = 窗口最值

⚠️ 239 滑动窗口最大值（详见单调队列专题）
  每个元素进出队各一次 → O(n)
```

### 3.2 双端队列 vs 双栈

```
双端队列：两端操作（Deque）
双栈：两个栈配合（倒腾）

选型：
  需要"两端同时操作" → Deque（天然）
  需要"逆序还原" → 双栈（倒腾）

⚠️ 232 栈实现队列 vs 直接 Deque：
  面试考察"结构转换"能力（双栈倒腾）
  工程直接用 LinkedList/ArrayDeque
```

### 3.3 双端队列的应用场景

```
① 滑动窗口最值（239）：Deque 单调
② 双端操作（641）：插入/删除两端
③ 任务调度（Deque 任务池）：双端窃取
   （Work-Stealing：空闲线程从另一端取任务）

⚠️ 面试加分：
"Java 的 ArrayDeque 底层是循环数组——
 双端队列是单调队列与循环队列的基础。"
```

## 4. 队列在算法中的角色

### 4.1 BFS 的载体

```
BFS = 队列驱动的逐层扩散：
  size 固定本层 → 层数与步数

⚠️ 队列为什么是 BFS 的唯一选择？
  FIFO 保证"先到先处理"（层序）

⚠️ 面试必答：
"BFS 用队列——FIFO 保证先进入的节点
 先处理，恰好是层序扩散的顺序。"
```

### 4.2 Kahn 拓扑的载体

```
Kahn 拓扑 = BFS + 入度：
  入度 0 入队 → 出队减入度 → 减到 0 再入队
  处理数 == n → 无环

⚠️ 队列在拓扑中的角色：
  "可处理集合"的维护（入度 0 的节点）
```

### 4.3 滑动窗口的载体

```
队列维护窗口：
  新元素入队（右扩）
  过期元素出队（左缩）
  队内 = 当前窗口

⚠️ 933 最近请求（窗口过期出队）
  346 滑动窗口平均值（队内元素和）
```

## 5. 阻塞队列与并发

### 5.1 Java 阻塞队列

```
BlockingQueue（线程安全队列）：
  ArrayBlockingQueue：数组有界
  LinkedBlockingQueue：链表可选有界
  SynchronousQueue：无缓冲（直接交接）

关键操作（阻塞版）：
  put()：满时阻塞等待
  take()：空时阻塞等待
  offer(e, time)：带超时

⚠️ 面试必答：
"阻塞队列的 put/take 会阻塞——
 生产者满时等待，消费者空时等待。
 这是生产-消费模式的标准组件。"
```

### 5.2 生产-消费者模式

```
生产者 → 阻塞队列 → 消费者
  put 满则等（背压）
  take 空则等（无空转）

⚠️ 与算法题的类比：
  933 最近请求 = 消费者（队列读）
  239 窗口最值 = 队列维护（生产+消费）

⚠️ 面试表达：
"阻塞队列实现生产-消费：
 put 满时阻塞（背压保护），
 take 空时等待（无忙轮询）。"
```

### 5.3 并发队列的选型

```
单线程 → LinkedList/ArrayDeque（无锁）
多线程 → BlockingQueue（并发安全）
高吞吐 → ConcurrentLinkedQueue（CAS）

⚠️ 面试必答：
"单线程 LinkedList；多线程生产-消费
 BlockingQueue；高并发无界 CAS 队列。"
```

## 6. 进阶总结

### 6.1 进阶要点速查

```
① 三种实现：数组（循环）/链表/动态数组
② 循环队列：取模循环 + size 区分空满
   "前移防负：(idx-1+len)%len"
③ 双端队列：单调队列（窗口最值）+ 双端操作
④ 队列角色：BFS/拓扑/滑窗
⑤ 阻塞队列：put/take 阻塞（生产-消费）
```

### 6.2 面试话术模板

```
"队列的实现与工程应用：
 ① 循环队列【数组+取模】，细节【防负/空满区分】；
 ② 双端队列【单调队列窗口最值】；
 ③ 算法角色【BFS/拓扑/滑窗】；
 ④ 并发【BlockingQueue put/take 阻塞】。
 复杂度 O(1) 全部操作。"
```

### 6.3 易错点清单

| 错误 | 后果 | 修正 |
|------|------|------|
| 队尾取值负数 | 越界 | (tail-1+len)%len |
| 忘取模 | 越界 | (tail+1)%len |
| 空满混淆 | 逻辑错 | 用 size 区分 |
| 并发用 LinkedList | 数据竞争 | BlockingQueue |
| offer/add 混用 | 异常 | 统一 offer/poll |

> 🎯 **核心要点**：队列进阶 = **循环队列实现**（取模 + size）+ **双端应用**（单调队列）+ **算法角色**（BFS/拓扑/滑窗）+ **并发**（BlockingQueue）。"前移防负、后移取模"是两个细节；"队列是 BFS 唯一结构"与"put/take 阻塞"是两个必答点。
