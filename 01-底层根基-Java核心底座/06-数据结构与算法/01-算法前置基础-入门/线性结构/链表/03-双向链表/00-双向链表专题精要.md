## 1. 核心概念

### 1.1 什么是双向链表

> 双向链表：每个节点有 **prev（前驱）+ next（后继）** 两个指针。相比单链表，**删除任意节点 O(1)**（无需找前驱）。

```
单链表删除 node：需遍历找前驱 → O(n)
双向链表删除 node：node.prev.next = node.next → O(1)

代价：每个节点多一个指针（8 字节）
适用：需要"已知节点后 O(1) 删除"的场景

节点定义：
class Node {
    int key, value;
    Node prev, next;          // ⚠️ 双向指针
    Node(int k, int v) { key = k; value = v; }
}
```

### 1.2 核心操作四件套

```
① addToHead(node)：头插（最近使用）
② removeNode(node)：摘除（O(1)!）
③ moveToHead(node)：移到头部（remove + add）
④ removeTail()：删除尾部（最久未使用）

虚拟头尾（哨兵）：
  head.next = tail; tail.prev = head;
  → 空链表/边界操作统一（无需判空）

⚠️ 四件套是 LRU 的全部核心
  手写顺序：Node 类 → 四件套 → get/put
```

### 1.3 何时用双向链表

```
① LRU 缓存（146）：需要任意节点 O(1) 删除
② 浏览器历史（1472）：前进/后退双向导航
③ LFU 缓存（460）：频次桶内双向链表
④ 循环双端队列（641）

⚠️ 判断标准："删除任意节点必须 O(1)"
  只需要"删头/删尾" → 单链表够用
  需要"删中间" → 双向链表
```

## 2. 完整代码模板

### 2.1 LRU 缓存完整实现（146）

```java
/**
 * LeetCode 146. LRU 缓存（面试最高频设计题）
 * 哈希表定位 + 双向链表排序
 * get/put 均 O(1)
 */
class LRUCache {
    class Node {
        int key, value;
        Node prev, next;
        Node(int k, int v) { key = k; value = v; }
    }

    private final int capacity;
    private final Map<Integer, Node> map = new HashMap<>();
    private final Node head = new Node(-1, -1);   // 虚拟头
    private final Node tail = new Node(-1, -1);   // 虚拟尾

    public LRUCache(int capacity) {
        this.capacity = capacity;
        head.next = tail;
        tail.prev = head;
    }

    public int get(int key) {
        Node node = map.get(key);
        if (node == null) return -1;
        moveToHead(node);              // ⚠️ 使用过 → 移到头部
        return node.value;
    }

    public void put(int key, int value) {
        Node node = map.get(key);
        if (node != null) {
            node.value = value;        // 更新值
            moveToHead(node);
        } else {
            node = new Node(key, value);
            map.put(key, node);
            addToHead(node);
            if (map.size() > capacity) {
                Node removed = removeTail();   // 淘汰最久未用
                map.remove(removed.key);       // ⚠️ 同步删哈希
            }
        }
    }

    // ── 双向链表四件套 ──────────────────────────
    private void addToHead(Node node) {      // 头插
        node.next = head.next;
        node.prev = head;
        head.next.prev = node;
        head.next = node;
    }

    private void removeNode(Node node) {     // 摘除（O(1)!）
        node.prev.next = node.next;
        node.next.prev = node.prev;
    }

    private void moveToHead(Node node) {     // 移到头部
        removeNode(node);
        addToHead(node);
    }

    private Node removeTail() {              // 删除尾部
        Node node = tail.prev;
        removeNode(node);
        return node;
    }
}
```

### 2.2 为什么必须双向链表？

```
LRU 删除任意节点（含中间）必须 O(1)：
  单链表删除 node 需要前驱 → O(n) ❌
  双向链表 node.prev 直接给 → O(1) ✅

⚠️ 面试必答：
  "单链表删节点要遍历找前驱 O(n)，
   不满足 LRU 的 O(1) 要求，
   所以必须双向链表。"
```

### 2.3 为什么节点必须存 key？

```
删除尾部后要同步删哈希：
  map.remove(removed.key)
  → 节点不存 key 就无法定位哈希表项

⚠️ 面试细节：
  Node 存 key + value 两个字段
  （不存 key 是设计题的常见错误）
```

## 3. LRU 缓存详解

### 3.1 设计思路拆解

```
需求分析：
  get O(1) → 哈希表定位（key → Node）
  有序性（最近使用在前）→ 链表
  删除任意节点 O(1) → 双向链表

结构：HashMap<key, Node> + 双向链表
  头部 = 最近使用，尾部 = 最久未使用

操作：
  get：命中 → moveToHead（O(1)）
  put：存在 → 更新 + moveToHead
       不存在 → 头插；超容量 → 删尾部

⚠️ 为什么哈希 + 链表组合？
  哈希管"定位"（O(1)），链表管"顺序"（O(1)）
  → 两个维度的需求各用一个结构
```

### 3.2 推演：cap=2, put(1,1), put(2,2), get(1), put(3,3)

```
put(1,1)：链表 [1]，map{1}
put(2,2)：链表 [2,1]，map{1,2}（2 最近）
get(1)：命中 → 移到头部 → 链表 [1,2]
put(3,3)：超容量 → 删尾部 2 → 链表 [3,1]
  map：删 2，加 3
最终：链表 [3,1]，map{1:1, 3:3} ✓
```

### 3.3 变体：LFU（460）

```
LFU（最少使用频率淘汰）比 LRU 复杂：
  双哈希：Map<key, 节点> + Map<频次, 双向链表>
  更新：使用 → 频次+1 → 移入新频次链表

⚠️ 面试定位：
  LRU 必考（手写流畅）
  LFU 了解思路（双哈希 + 频次链表）
  "先手写 LRU，追问 LFU 讲思路"
```

## 4. 双向链表的应用场景

### 4.1 场景一：浏览器历史（1472）

```
前进/后退导航：
  当前页 = 链表指针位置
  访问新页 → 清空前进部分
  后退 → 前驱；前进 → 后继
  → 双向链表天然支持双向导航

⚠️ 也可用双栈（后退栈 + 前进栈）
  面试两种方案都能讲
```

### 4.2 场景二：LFU 缓存（460）

```
频次 → 双向链表（同频次内按时间排序）
  Map<key, Node> 定位
  Map<freq, 链表> 分组

删除：从最小频次的链表中删尾部
  （minFreq 维护全局最小频次）

⚠️ 复杂度 O(1) 全部操作（双哈希 + 双向链表）
```

### 4.3 场景三：双端队列实现（641）

```
循环双端队列（数组实现更常见）：
  双向链表实现：头尾指针 + 哨兵
  前插/后插/前删/后删均 O(1)

⚠️ 面试选择：
  数组实现（循环取模）代码更短
  链表实现讲"双向 O(1)"原理
```

## 6. 面试要点与追问

### 6.1 面试话术模板

```
"LRU 用哈希表 + 双向链表：
 哈希 O(1) 定位节点，链表维护使用顺序
 （头部最近、尾部最久）。
 双向链表保证删除任意节点 O(1)——
 单链表删节点要找前驱，不满足要求。
 用虚拟头尾简化边界。get/put 均 O(1)。"
```

### 6.2 高频追问 TOP 8

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | 为什么必须双向？ | 删除任意节点 O(1)（单链表删节点要找前驱 O(n)） |
| 2 | 虚拟头尾作用？ | 空链表/边界统一（head.next 恒存在） |
| 3 | 节点为什么存 key？ | 删尾部后 map.remove(removed.key) 同步 |
| 4 | 为什么不用 LinkedHashMap？ | 可以（removeEldestEntry），但手写展示底层能力 |
| 5 | 线程安全？ | 不加锁不安全；加锁或 ConcurrentHashMap |
| 6 | 单链表什么时候够？ | 只删头尾（队列/栈）；删中间必须双向 |
| 7 | LFU 怎么做？ | 双哈希：key→节点 + 频次→链表 |
| 8 | 头插顺序？ | 先连新节点（next/prev），再接 head（防断链） |

### 6.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| 节点不存 key | 无法删哈希 | Node 存 key+value |
| 头插顺序反 | 断链 | 先连新节点再接 head |
| 忘删哈希 | 内存泄漏/错误 | 删尾同步 map.remove |
| 用单链表 | 删除 O(n) | 双向 |
| 忘虚拟头尾 | 空链表特判 | head/tail 哨兵 |

> 🎯 **核心要点**：双向链表 = **prev/next 双指针 + O(1) 任意节点删除**。最大价值是 LRU（146）——"哈希定位 + 链表排序"组合。四件套（addToHead/removeNode/moveToHead/removeTail）+ 节点存 key + 虚拟头尾是三大细节。
