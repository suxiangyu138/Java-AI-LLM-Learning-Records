## 1. 工程树的版图

```text
工程中的普通树（多叉）
├── 📁 文件系统: 目录树（根 / → 子目录 → 文件）
├── 🏢 组织架构: 公司树（CEO → 部门 → 员工）
├── 🌐 前端: DOM 树（document → 元素 → 文本）
├── 🗂️ 分类体系: 商品分类、知识分类（无限级菜单）

└── 📊 报表: 汇总树（销售 → 区域 → 门店）
```

> 💡 认知升级：算法题考二叉树，**工程全是多叉树**——文件系统/DOM/组织架构的每个节点孩子数都不固定，孩子表示法（List<Node>）是工程树的默认实现。

## 2. 文件系统与目录树

**目录树**：文件系统的标准模型——根 `/` 出发的多叉树，目录是内部节点、文件是叶子。

```text
/ (root)
├── etc/
│   ├── nginx/nginx.conf
│   └── hosts
├── opt/
│   └── app/app.jar
└── home/
    └── user/
        └── document.txt
```

```java
// 文件系统树的 Java 建模
class FileNode {
    String name;
    boolean isDirectory;
    List<FileNode> children;      // 目录的孩子（文件无孩子）
}

// 经典操作：目录大小 = Σ 子树大小（树形 DP）
long sizeOf(FileNode node) {
    if (!node.isDirectory) return node.fileSize;
    long total = 0;
    for (FileNode child : node.children) {
        total += sizeOf(child);   // 递归累加 = du 命令的实现
    }
    return total;
}
```

> 💡 `du -sh`、`find`、`rm -rf` 全是目录树的 DFS——**文件系统的每个命令都是树的遍历**。

## 3. 组织架构与分类体系

**组织树**：CEO → CTO/CFO/CMO → 各级部门 → 员工——典型的「无限层级」结构。

```java
// 组织树通用模型（无限级分类的数据库标准设计）
// 数据库表: id, name, parent_id（父指针表示法！）
// 内存模型: Node { id, name, List<Node> children }

// 核心操作 1：找所有下属（DFS 收集）
List<Node> collectSubordinates(Node manager) {
    List<Node> res = new ArrayList<>();
    dfs(manager, res);
    return res;
}

// 核心操作 2：找上级链（父指针上溯）
List<String> orgChain(Node node) {
    List<String> chain = new ArrayList<>();
    while (node != null) {
        chain.add(0, node.name);   // 从根到自身
        node = node.parent;
    }
    return chain;
}
```

**无限级分类的工程场景**：商品分类、菜单权限、知识库分类、评论嵌套——数据库用 `parent_id`（父指针），应用层转成孩子表示法树再操作。

## 4. DOM 与前端树

**DOM 树**：HTML 文档的树形模型——`document` 根节点，元素节点/文本节点/注释节点的多叉树。

```text
document
└── html
    ├── head
    │   └── title
    └── body
        ├── div
        │   ├── p
        │   └── span
        └── script
```

**前端树操作（面试跨界考点）**：

| 操作 | 树算法 |
|------|--------|
| 遍历 DOM | DFS（document.querySelectorAll 内部） |
| 找父元素 | parent 链上溯 |
| 事件冒泡 | 叶子 → 根（后序思想） |
| 事件捕获 | 根 → 叶子（前序思想） |
| 虚拟 DOM diff | 树比较（双指针 + 递归） |

> 💡 React 的虚拟 DOM 就是一棵 JS 对象树——**树比较算法（diff）是前端性能的核心**；事件捕获（前序）与冒泡（后序）直接对应树遍历的两种顺序。

## 5. 路由与决策树

**路由表树**：URL 路径 → 处理函数的树形匹配（框架路由的通用实现）：

```text
/ (根路由)
├── api
│   ├── users → UserController
│   └── orders → OrderController
└── static
    └── assets → 静态文件
```

**决策树**（机器学习）：特征划分的多叉树——每个内部节点按特征分叉、叶子是决策结果（详见 AI 体系）。

```text
是否购买？
├── 收入 > 10k?
│   ├── 是 → 购买
│   └── 否 → 需求强度?
│       ├── 高 → 购买
│       └── 低 → 不购买
└── ...
```

> 💡 决策树 = 树的「分类」应用——训练 = 建树（信息增益选特征），预测 = 遍历树到叶子（[计算机中的各种树](../计算机中的各种树/05-工程场景中的树.md)有对比）。

## 6. 工程树面试问答

| 问题 | 答题要点 |
|------|---------|
| 工程树为什么多叉？ | 真实结构孩子数不定（文件/组织/DOM） |
| 数据库怎么存树？ | `parent_id`（父指针）或邻接表；复杂查询用闭包表 |
| du 命令的实现？ | 目录树 DFS 累加 |
| DOM 事件冒泡/捕获？ | 后序（子→父）/前序（父→子） |
| 无限级分类怎么查？ | 内存建树 DFS 收集 or SQL 递归 CTE |
| 树形结构 JSON 怎么设计？ | `{ id, name, children: [] }`（孩子表示法） |

> 🎯 **核心要点**：工程树验收——能说出 5 个工程树场景（文件/组织/DOM/分类/路由）；理解「数据库存树用父指针、应用层建树用孩子法」的双表示法；du/find/事件冒泡/路由匹配全是树遍历；「普通树 = 工程默认树」的认知是本节最大的收获。
