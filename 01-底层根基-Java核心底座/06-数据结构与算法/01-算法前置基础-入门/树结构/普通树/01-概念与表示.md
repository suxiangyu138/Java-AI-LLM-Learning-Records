## 1. 普通树的定义

**普通树（General Tree / N-ary Tree）**：每个节点可以有**任意数量**子节点的树。

```text
        CEO
       / | \
    CTO  CFO  CMO          ← 每个节点子节点数不限（度不限）
    / \       |
 后端 前端    市场部
```

| 对比 | 二叉树 | 普通树 |
|------|--------|--------|
| 子节点数 | ≤ 2（且区分左右） | 不限（0..n） |
| 子节点有序性 | 左右有序 | 通常有序（从左到右） |
| 高度 | log n ~ n | log n ~ n（同） |
| 存储 | left/right 指针 | List<Node> children |
| 典型场景 | 算法题主力 | 工程结构（文件系统/DOM） |

**关键术语**：度（子节点数）、叶子（度 0）、内部节点（度 > 0）、森林（多棵树）。

> 💡 二叉树是普通树的特例（度 ≤ 2）；普通树是工程中最常见的「树」形态——**算法题多考二叉树，工程全是多叉树**。

## 2. 孩子表示法（工程默认）

```java
// LeetCode N 叉树标准定义
class Node {
    public int val;
    public List<Node> children;    // 子节点列表（空列表 = 叶子）

    public Node() {}
    public Node(int val) { this.val = val; }
    public Node(int val, List<Node> children) {
        this.val = val;
        this.children = children;
    }
}
```

```text
        A
      / | \
     B  C  D
    / \    |
   E   F   G

孩子表示:
  A.children = [B, C, D]
  B.children = [E, F]
  C.children = []
  D.children = [G]
```

| 优点 | 缺点 |
|------|------|
| 直观、工程通用 | 每个节点有 List 开销 |
| 遍历简单（for child） | 找父节点需遍历 |

> 💡 LeetCode 的 N 叉树题（589/590/429 等）全部用孩子表示法——`children` 为 `List<Node>`，空列表即叶子。

## 3. 孩子兄弟表示法（二叉树化钥匙）

**核心思想**：用两个指针表示任意多叉——**左指针存第一个孩子，右指针存下一个兄弟**。

```java
// 孩子兄弟表示法（二叉链表）
class TreeNode {           // 与二叉树节点同构！
    int val;
    TreeNode firstChild;   // 左：第一个孩子
    TreeNode nextSibling;  // 右：下一个兄弟
}
```

```text
        A                A(左=B, 右=null)
      / | \             /
     B  C  D           B(左=E, 右=C)
    / \               /       \
   E   F             E(右=F)   C(右=D)
```

**为什么重要**：普通树用两个指针就能表示 → **任何普通树都能转成二叉树** → 二叉树的全部算法（遍历/深度/LCA）直接复用（04 模块详解）。

> ⚠️ 转换后「右子树」语义变了：不再是「右孩子」，而是「兄弟」——遍历二叉树时要注意语义（中序遍历 = 先孩子后兄弟）。

## 4. 父指针表示法

```java
// 父指针表示：每个节点只存父节点（并查集的表示法）
class Node {
    int val;
    Node parent;           // 指向父节点
}
// 根节点的 parent = null
```

| 适用场景 | 说明 |
|---------|------|
| 并查集 | 森林 + 父指针（[图论基础](../../../03-高频专题模块/专题 7：搜索专题（DFS  BFS  回溯）/..)并查集） |
| 找祖先/根 | 沿 parent 上溯 O(深度) |
| 节省空间 | 每节点 1 个指针（vs 孩子法 List） |

> 💡 父指针表示法的代价：找子节点需要全局扫描——所以它只适合「向上查询」为主的场景（并查集、进程树）。

## 5. 三种表示法对比

| 表示法 | 指针数/节点 | 找孩子 | 找父 | 典型场景 |
|--------|:---:|:---:|:---:|---------|
| 孩子表示法 | 1 List | O(孩子数) | ❌ O(n) | LeetCode/文件系统 |
| 孩子兄弟 | 2 指针 | O(孩子数) | ❌ | 树↔二叉树转换 |
| 父指针 | 1 指针 | ❌ O(n) | **O(深度)** | 并查集、进程树 |

**选型口诀**：**向下操作用孩子法、向上操作用父指针、要复用二叉树算法用孩子兄弟法**。
