# 04 - 删除与平衡修复

> 删除是 AVL 最复杂的操作：BST 删除三态 + **回溯到根**逐层修复——与插入的关键差异：删除后旋转可能不恢复高度，需继续向上回溯，最多 O(log n) 次旋转。

## 1. 删除的三步

```text
第一步：BST 删除（450 题三态：叶子/单子/双子）
第二步：从替代节点回溯到根，逐层：
   ① 更新高度
   ② 检查平衡因子
   ③ 失衡 → balance 旋转
第三步：若旋转后高度仍少 1 → 继续回溯（与插入不同！）
```

| 步骤 | 操作 | 复杂度 |
|------|------|--------|
| BST 删除 | 三态 + 双子替代 | O(log n) |
| 回溯修复 | 每层更新高度 + 检查 | O(log n) |
| 旋转次数 | **最多 O(log n) 次** | 每层可能一次 |
| 总计 | — | **O(log n)** |

> ⚠️ **删除 vs 插入的本质差异**：插入旋转后高度复原（一次即止）；删除旋转后**高度可能仍比原来少 1**（节点真的少了）→ 上层平衡因子继续变化 → **必须回溯到根**。

## 2. 与插入修复的差异

| 维度 | 插入 | 删除 |
|------|------|------|
| 回溯范围 | 到最小失衡子树即止 | **一直回溯到根** |
| 旋转次数 | 最多 1 次 | **最多 O(log n) 次** |
| 高度变化 | 旋转后复原 | 旋转后可能仍少 1 |
| 实现 | balance 一次即可 | 每层都要 balance |

**为什么删除要回溯到根**：

```text
删除叶子 X 后:
        A(0)              A(-1)            祖先的平衡因子
       / \               / \              都可能变化
      B   C(删除)        B
     ...
   （高度少 1 传递到根）
→ 每一层的 BF 都可能变 ±2 → 每层都可能旋转
```

> 💡 面试高频追问：「为什么 AVL 删除比插入复杂？」——**节点真的减少了**，旋转无法弥补「少了一个节点」的高度损失，失衡可能逐层向上传递。

## 3. 删除完整实现

```java
class AVLTree {
    private AVLNode root;

    public void delete(int val) {
        root = delete(root, val);
    }

    private AVLNode delete(AVLNode node, int val) {
        if (node == null) return null;
        if (val < node.val) {
            node.left = delete(node.left, val);
        } else if (val > node.val) {
            node.right = delete(node.right, val);
        } else {
            // ① BST 删除三态
            if (node.left == null) return node.right;      // 叶子/单右
            if (node.right == null) return node.left;      // 单左
            // 双子：右子树最小节点替代
            AVLNode min = findMin(node.right);
            node.val = min.val;
            node.right = delete(node.right, min.val);      // 删除替代者
        }

        // ② 回溯修复（与插入同款，但每层都执行）
        if (node == null) return null;
        updateHeight(node);
        return balance(node);                              // 每层都可能旋转
    }

    private AVLNode findMin(AVLNode node) {
        while (node.left != null) node = node.left;
        return node;
    }
    // balance / rotate / height 与 03 模块相同
}
```

**与插入实现的差异只有两处**：
1. 删除逻辑（三态 + 双子替代）；
2. **balance 在每层递归返回时都执行**（插入也是每层执行 balance——其实相同！插入的「一次旋转」是旋转后高度复原的自然结果，代码结构一样，只是旋转发生的频率不同）。

> 💡 洞察：插入和删除的代码**结构完全相同**（递归 + 回溯 balance）——差异是数学性质（旋转后高度是否复原）而非代码！这个理解能消解「删除更复杂」的恐惧。

## 4. 删除示例推演

**示例**：删除叶子 2（触发一次 LL 旋转后继续回溯）。

```text
原树:           删除 2:
       5              5
      / \            / \
     3   7          3   7
    /              /
   2              空
   （BF 全平衡）  3 的 BF = +2？ 左空右空 → 实际：
                  5 的左子树高度 2→1，右子树 2
                  → 5 的 BF = -1 仍平衡 ✓
```

**示例**：删除触发旋转且高度未复原（多层回溯场景）：

```text
           10
          /  \
         5    15
        / \   / \
       2   7 12  20
删除 20 后: 15 的 BF=+1 平衡，10 的 BF=0 平衡 → 无需旋转

删除 2 后:  10 的 BF? 左高 2（5-7）右高 2（15-12）→ 0 平衡
           5 的 BF = +1 平衡 → 无旋转
```

> ⚠️ 实际多层旋转场景：删除左子树深处节点后，右子树失衡——`balance(右子树)` 可能 RR 或 RL；若旋转后右子树高度仍比删除前少 1，则继续检查 10 的平衡……**每层一个 balance 调用，最坏 O(log n) 次**。

## 5. 删除速查表

| 场景 | 处理 |
|------|------|
| 删除叶子/单子 | 直接顶替（BST 三态） |
| 删除双子 | 右最小替代 + 递归删除替代者 |
| 回溯修复 | 每层 updateHeight + balance |
| LL/RR/LR/RL | 与插入同款旋转（02 模块） |
| 回溯终止 | 到达根（没有「旋转即止」） |

**面试对比（AVL 删除 vs 红黑树删除）**：

| 维度 | AVL | 红黑树 |
|------|-----|--------|
| 删除旋转次数 | 最多 O(log n) | **最多 3 次** |
| 修复思想 | 高度平衡逐层回溯 | 双黑借键/上移 |
| 实现难度 | ★★★ | ★★★★★ |
| 场景 | 读多写少 | 写多读少 |

> 🎯 **核心要点**：删除验收——删除方法默写（BST 三态 + 递归回溯 balance）；讲清「删除 vs 插入」的本质差异（高度不复原 → 回溯到根）；理解「代码结构相同、数学性质不同」的洞察；与红黑树删除（≤3 次旋转）的对比是选型面试的必答点（05 模块）。
