## 1. 压缩 Trie / Radix Tree

**问题**：标准 Trie 单子链浪费空间（"abc" 每条边一个节点）。

**压缩**：**合并单子链**——每条边存字符串而非单字符。

```text
标准 Trie:                   压缩 Trie（Radix）:
    root                          root
     |                             |
     a                             ab
     |                              |
     b                             cd
     |
     c
   （"abc" 用 3 个节点）       （"abcd" 用 2 个节点）

插入 "abcd", "abef":
    root
     |
    ab ──┬── cd   （ab 合并）
         └── ef
```

| 对比 | 标准 Trie | 压缩 Trie |
|------|:---:|:---:|
| 边内容 | 单字符 | 字符串段 |
| 空间 | O(总字符数) | O(节点数)（大幅减少） |
| 实现复杂度 | ★ | ★★★★ |
| 工程应用 | LeetCode | **Redis/Routing（IP 匹配）/PostgreSQL** |

> 💡 工程上最常见的压缩 Trie 是 **Radix Tree（基数树）**：Linux 路由表、Redis 集群槽位、PostgreSQL 稀疏索引都在用——按位/按前缀合并路径。

## 2. 子节点存储优化

标准 Trie 每个节点固定 26 指针，大部分为 null——优化思路：

| 方案 | 原理 | 适用 |
|------|------|------|
| 哈希 Map | 按需存储子节点 | 通用字符集 |
| 动态数组 | 只存存在的孩子 | 稀疏场景 |
| **排序数组 + 二分** | 子节点有序、二分查 | 查询多插入少 |
| 跳表/红黑树 | 有序子节点 | 需要有序遍历 |

```java
// 子节点二分优化（子节点有序时）
class TrieSorted {
    char[] chars;                  // 有序子节点字符
    TrieSorted[] children;         // 平行数组
    boolean isEnd;

    // 二分查找子节点 O(log 度)
    int find(char c) {
        int lo = 0, hi = chars.length - 1;
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;
            if (chars[mid] == c) return mid;
            if (chars[mid] < c) lo = mid + 1;
            else hi = mid - 1;
        }
        return -1;
    }
}
```

> 💡 工程权衡：哈希 Map 实现最简单（01 模块已给）；有序数组 + 二分适合「构建后只读」的字典场景（编译期常量词典）。

## 3. 01-Trie：位运算专用

**01-Trie**：二叉树，按**二进制位**分叉（0 走左、1 走右）——求「最大异或对」的利器（05 模块详解）。

```text
插入 5(101), 3(011), 6(110):

          root
         /    \
        0      1
       / \    /
      0   1  1
      |   |  |
      1   1  0
    (3) (5) (6)

查询与 5(101) 异或最大: 贪心走相反位 → 6(110): 101^110 = 011 = 3
```

| 维度 | 普通 Trie | 01-Trie |
|------|-----------|---------|
| 分叉依据 | 字符 | 二进制位（0/1） |
| 度数 | 字母表大小 | 固定 2 |
| 查询 | 前缀匹配 | **异或最值（贪心相反位）** |
| 典型题 | 208/212 | 421/1707 |

> ⚠️ 01-Trie 的插入位数：通常按 31 位（int 符号位起）或 30 位固定深度——**深度固定**使复杂度与数据值域相关而非字符串长度。

## 4. 其他变体一览

| 变体 | 定义 | 应用 |
|------|------|------|
| 后缀 Trie | 所有后缀的 Trie | 子串查询（后缀树前身） |
| 双数组 Trie | 两个数组紧凑存储 | 中文分词（结巴分词） |
| Patricia Trie | 路径压缩的 Radix | 路由/文件系统 |
| C-Trie | 压缩字典树 | 学术优化 |
| Trie + AC 自动机 | Trie + fail 指针 | 多模式匹配（[字符串树家族](../计算机中的各种树/03-字符串树家族对比.md)） |

**双数组 Trie（工程重点）**：用 `base[]` + `check[]` 两个数组代替指针——内存只有标准 Trie 的 1/5~1/10，是**中文分词器（jieba、HanLP）的默认实现**。

## 5. 变体选型速查

```text
需要 Trie？
├── LeetCode 题 → 标准数组实现（够用）
├── 任意字符集 → 哈希实现
├── 内存敏感/海量词典 → 压缩 Trie（Radix）
├── 构建后只读 → 有序数组 + 二分
├── 异或最值/位运算 → 01-Trie
├── 中文分词 → 双数组 Trie
└── 多模式匹配 → AC 自动机
```

### 5.1 变体面试对比

| 问题 | 答案 |
|------|------|
| Radix Tree 和 Trie 区别？ | Radix 合并单子链，空间省、实现复杂 |
| 双数组 Trie 为什么省内存？ | base/check 两数组替代指针（1/5~1/10 空间） |
| 01-Trie 与普通 Trie 关系？ | 01-Trie 是字母表 = {0,1} 的特例 |
| 什么时候用压缩？ | 词典海量且单链多（英文单词） |
| AC 自动机是 Trie 变体吗？ | 是——Trie + fail 指针（多模式） |

### 5.2 变体选择速记

```text
空间敏感 → 压缩 Trie / 双数组
字符集大 → 哈希子节点
位运算  → 01-Trie
多模式  → AC 自动机
只读词典 → 有序数组 + 二分
```

> 🎯 **核心要点**：变体验收——理解「压缩 = 合并单子链」（Radix Tree）；哈希/有序数组两种子节点优化的取舍；01-Trie 的「按位分叉 + 贪心相反位」思想（05 模块展开）；双数组 Trie 是中文分词的工程主力；面试通常考标准实现，变体是深度加分项。
