## 1. 双堆思想

**双堆**：一个大顶堆 + 一个小顶堆，把数据流对半切——左半装大顶堆（最大的在顶），右半装小顶堆（最小的在顶）。

```text
数据流 [5, 2, 7, 4, 9, 1]
左半（大顶堆）     右半（小顶堆）
     5                   7
    / \                 / \
   2   4               9   9?  ← 示意，见下方平衡逻辑
中位数 = (左顶 + 右顶) / 2 或左顶（奇数个）
```

### 1.1 维护规则（295 数据流中位数）

| 规则 | 目的 |
|------|------|
| 新数 ≤ 左顶 → 进左堆；否则进右堆 | 大小分段 |
| 左堆比右堆多 >1 → 左顶移右 | 保持左 ≥ 右 |
| 右堆比左堆多 → 右顶移左 | 左堆永远 ≥ 右堆大小 |

```java
class MedianFinder {
    PriorityQueue<Integer> left  = new PriorityQueue<>(Comparator.reverseOrder());
    PriorityQueue<Integer> right = new PriorityQueue<>();

    public void addNum(int num) {
        if (left.isEmpty() || num <= left.peek()) left.offer(num);
        else right.offer(num);
        if (left.size() > right.size() + 1) right.offer(left.poll());
        if (right.size() > left.size()) left.offer(right.poll());
    }

    public double findMedian() {
        if (left.size() > right.size()) return left.peek();
        return (left.peek() + right.peek()) / 2.0;
    }
}
```

> 💡 双堆的通用性：不止中位数——**任何「把数据按大小分成两半，随时取边界」的问题**（如 480 滑动窗口中位数）都是双堆舞台。

## 2. 延迟删除技巧

**问题**：PriorityQueue 删除任意元素是 O(n)（线性查找）——滑动窗口/过期元素场景不可接受。

**延迟删除**：不真删，标记「已过期」，取顶时惰性清理：

```java
// 480 滑动窗口中位数：双堆 + 延迟删除
class Solution {
    PriorityQueue<Integer> left  = new PriorityQueue<>(Comparator.reverseOrder());
    PriorityQueue<Integer> right = new PriorityQueue<>();
    Map<Integer, Integer> delayed = new HashMap<>();   // 延迟删除计数

    private void prune() {
        while (!left.isEmpty() && delayed.getOrDefault(left.peek(), 0) > 0) {
            int x = left.poll();
            delayed.merge(x, -1, Integer::sum);
        }
        while (!right.isEmpty() && delayed.getOrDefault(right.peek(), 0) > 0) {
            int x = right.poll();
            delayed.merge(x, -1, Integer::sum);
        }
    }
    // 删除：标记延迟；取顶前先 prune() 清理堆顶垃圾
    private void remove(int num) { delayed.merge(num, 1, Integer::sum); }
}
```

**延迟删除三步曲**：
1. 删除时：`delayed.put(x, count+1)`（O(1) 标记）；
2. 取顶前：while 堆顶在 delayed 中 → poll 并减计数；
3. 平衡后：再 prune 一次（堆顶变化可能暴露新垃圾）。

> ⚠️ 延迟删除的坑：垃圾元素可能堆在**堆顶之下**（不挡路），不影响正确性——只有堆顶的垃圾才需要清理；计数归零要从 Map 移除，否则 `getOrDefault` 永远命中。

```java
// 23 合并 K 个有序链表：堆存「(节点值, 链表)」——小顶堆按值
public ListNode mergeKLists(ListNode[] lists) {
    PriorityQueue<ListNode> heap = new PriorityQueue<>((a, b) -> a.val - b.val);
    for (ListNode head : lists) if (head != null) heap.offer(head);
    ListNode dummy = new ListNode(0), cur = dummy;
    while (!heap.isEmpty()) {
        cur.next = heap.poll();
        cur = cur.next;
        if (cur.next != null) heap.offer(cur.next);   // 弹出后推后继
    }
    return dummy.next;
}
```

## 4. 面试追问与答题话术

| 追问 | 答题要点 |
|------|---------|
| 中位数为什么用双堆？ | 插入 O(log n)、查询 O(1)，比排序/二分查找更适应数据流 |
| 双堆平衡规则？ | 左堆 ≤ 右堆+1，且左堆 ≥ 右堆；奇数个时左堆多 1 |
| 堆删任意元素为什么 O(n)？ | 堆只保证根有序，任意元素要线性扫描；用延迟删除优化 |
| TopK 堆选什么类型？ | 前 K 大用小顶堆（装 K 个最大的，顶是门槛） |
| 堆 vs 有序数组？ | 堆插入 O(log n) vs 数组 O(n)；堆是动态场景最优 |
| 堆 vs 红黑树（TreeMap）？ | 堆只取最值 O(1)/O(log n)；红黑树查任意值 O(log n)——需要查任意元素用红黑树 |

| # | 易错点 | 后果 | 对策 |
