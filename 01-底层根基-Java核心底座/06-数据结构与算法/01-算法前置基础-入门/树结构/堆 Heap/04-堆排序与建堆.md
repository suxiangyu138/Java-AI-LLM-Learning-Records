## 1. 堆排序原理

**三句话**：
1. 无序数组**建堆** → O(n)；
2. **交换堆顶（最值）到末尾**，缩小堆范围；
3. 新堆顶**下沉**恢复堆序 → O(log n)，重复 n 次。

```text
大顶堆排序过程：
[5, 3, 8, 1, 9]
→ 建大顶堆 [9, 5, 8, 1, 3]
→ 9↔3，堆缩小 [3, 5, 8, 1 | 9]，下沉 → [8, 5, 3, 1 | 9]
→ 8↔1，堆缩小 [1, 5, 3 | 8, 9]，下沉 → [5, 1, 3 | 8, 9]
→ ... → [1, 3, 5, 8, 9] ✓
```

| 维度 | 值 |
|------|-----|
| 时间复杂度 | O(n log n)（最坏/平均/最好相同） |
| 空间复杂度 | O(1)（原地） |
| 稳定性 | **不稳定**（父子交换破坏相对顺序） |
| 适用 | 需要原地排序且数据动态变化的场景 |

## 2. 堆排序 Java 实现

```java
// 原地大顶堆排序（依赖 02 模块的 siftDown 思想）
void heapSort(int[] nums) {
    int n = nums.length;
    // 1. 建大顶堆
    for (int i = n / 2 - 1; i >= 0; i--) {
        siftDown(nums, n, i);
    }
    // 2. 反复取顶
    for (int i = n - 1; i > 0; i--) {
        swap(nums, 0, i);              // 堆顶 → 末尾
        siftDown(nums, i, 0);          // 新堆顶下沉（堆大小 = i）
    }
}

void siftDown(int[] a, int n, int i) {   // 大顶堆版本：选较大的子
    while (true) {
        int l = 2 * i + 1, r = 2 * i + 2, largest = i;
        if (l < n && a[l] > a[largest]) largest = l;
        if (r < n && a[r] > a[largest]) largest = r;
        if (largest == i) break;
        swap(a, i, largest);
        i = largest;
    }
}
```

> 💡 堆排序只需 **siftDown**（建堆 + 反复取顶都是下沉）——所以 02 模块说「siftDown 是灵魂」。

## 3. 建堆 O(n) 的证明

**弗洛伊德方法**：从最后一个非叶子 `n/2 - 1` 向前逐个 siftDown。

**代价分析**（关键：按「高度」而非「节点数」求和）：

| 高度 h | 节点数（约） | 每个下沉代价 | 该层总代价 |
|:---:|:---:|:---:|:---:|
| 0（叶子） | n/2 | 0 | 0 |
| 1 | n/4 | 1 | n/4 |
| 2 | n/8 | 2 | n/4 |
| … | … | … | … |
| log n | 1 | log n | log n / 2^log n |

总代价 T(n) = Σ (n/2^(h+1)) · h = n · Σ h/2^(h+1) = **O(n)**（几何级数收敛到常数）。

> 🎯 **面试标准答案**：不是 n 次 O(log n) 下沉（那是 n log n 的错觉），而是**「越底层的节点越多、下沉越少」**——按高度求和，绝大多数节点的代价是常数级，只有根节点是 log n，总和收敛于 O(n)。

## 4. 排序算法横向对比

| 算法 | 平均 | 最坏 | 空间 | 稳定 | 特点 |
|------|:---:|:---:|:---:|:---:|------|
| 快速排序 | O(n log n) | O(n²) | O(log n) | 否 | **工程默认**（Arrays.sort 原始类型） |
| 归并排序 | O(n log n) | O(n log n) | O(n) | **是** | 稳定、外部排序（Arrays.sort 对象类型） |
| 堆排序 | O(n log n) | **O(n log n)** | **O(1)** | 否 | 原地、最坏有保证、无缓存友好性 |
| 计数/基数 | O(n+k) | O(n+k) | O(k) | 可 | 值域受限场景 |

**堆排序的工程地位**：
- **优点**：最坏 O(n log n) 保证 + O(1) 空间——理论完美；
- **缺点**：访问模式跳变（下标 i、2i、2i+1 不连续），**缓存不友好**，常数比快排大——实际运行常慢于快排；
- 因此 JDK 排序不选堆排序；堆排序的价值在**概念与 TopK**（堆 + 部分排序）。

## 5. 堆排序的定位与考题

| 考题 | 答案 |
|------|------|
| 堆排序稳定吗？ | 不稳定（堆顶与末尾交换会跨过相等元素） |
| 最好/最坏复杂度 | 都是 O(n log n)（建堆 O(n) 被取顶的 n log n 主导） |
| 为什么工程不用堆排序？ | 缓存不友好（跳跃访问），常数大；快排/归并更优 |
| 堆排序 vs 快速选择？ | TopK 高频用堆（动态数据）；静态数组第 K 大用快速选择更快（期望 O(n)） |
| 部分排序（前 K 个有序）？ | 堆排序天然支持：取 K 次顶即前 K 有序，O(n + K log n) |

> 🎯 **核心要点**：堆排序验收——能 5 分钟默写原地大顶堆排序；能背出建堆 O(n) 的「高度求和」证明；能说清工程弃用堆排序的「缓存不友好」理由；记住 TopK 场景下堆排序的兄弟「堆选择」才是主力（05 模块）。排序全景见[排序算法体系](../../../02-基础算法思想-核心/排序算法/00-排序知识体系总览.md)。
