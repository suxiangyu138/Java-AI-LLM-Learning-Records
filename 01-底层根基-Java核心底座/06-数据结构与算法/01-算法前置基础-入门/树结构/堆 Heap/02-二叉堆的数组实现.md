## 1. 两个核心动作：siftUp 与 siftDown

堆的全部操作都由**一个上浮、一个下沉**驱动。

### 1.1 siftUp（上浮）：插入时用

```java
// 小顶堆上浮：新元素在 index i，与父比较，小则交换
void siftUp(int[] heap, int i) {
    while (i > 0 && heap[i] < heap[(i - 1) / 2]) {
        swap(heap, i, (i - 1) / 2);
        i = (i - 1) / 2;          // 上移一层
    }
}
```

**触发时机**：offer 新元素 → 先放数组尾部，再上浮到正确位置。

### 1.2 siftDown（下沉）：删除时用

```java
// 小顶堆下沉：节点在 index i，与较小的子交换
void siftDown(int[] heap, int n, int i) {
    while (true) {
        int left = 2 * i + 1, right = 2 * i + 2;
        int smallest = i;
        if (left < n && heap[left] < heap[smallest]) smallest = left;
        if (right < n && heap[right] < heap[smallest]) smallest = right;
        if (smallest == i) break;          // 已满足堆序
        swap(heap, i, smallest);
        i = smallest;
    }
}
```

> 💡 **下沉选「较小的子」**（小顶堆）：与大的子交换会破坏堆序（大的子 > 当前时仍比父大，但另一个子可能更小）。这是新手最常写错的地方。

| 动作 | 时间复杂度 | 适用 |
|------|-----------|------|
| siftUp | O(log n) | 插入元素 |
| siftDown | O(log n) | 删除根、建堆、替换 |

## 2. 三大操作：插入/删除/替换

### 2.1 插入 offer

```java
// 1. 放数组末尾
heap[size] = val;
size++;
// 2. 上浮
siftUp(heap, size - 1);
```

### 2.2 删除堆顶 poll

```java
// 1. 用最后一个元素覆盖堆顶
int top = heap[0];
heap[0] = heap[size - 1];
size--;
// 2. 下沉
siftDown(heap, size, 0);
return top;
```

### 2.3 替换堆顶 replace（TopK 的核心操作）

```java
// 替换堆顶并保持堆序：先下沉再返回旧顶
int replace(int val) {
    int old = heap[0];
    heap[0] = val;
    siftDown(heap, size, 0);
    return old;
}
```

> 💡 **TopK 的高频操作就是 replace**：`if (val > heap.peek()) heap.replace(val)`——比 poll+offer 少一次上浮，且语义清晰。

## 3. 建堆：O(n) 的弗洛伊德方法

**从最后一个非叶子节点开始，自底向上逐个 siftDown**：

```java
void buildHeap(int[] heap, int n) {
    for (int i = n / 2 - 1; i >= 0; i--) {   // 最后一个非叶子 = n/2 - 1
        siftDown(heap, n, i);
    }
}
```

### 3.1 为什么是 O(n) 而不是 O(n log n)

每个节点下沉的代价与其**高度**成正比，而大多数节点在底层（高度小）：

| 层 | 节点数 | 高度 | 总代价 |
|----|--------|------|--------|
| 底层 | n/2 | 0 | 0 |
| 上一层 | n/4 | 1 | n/4 |
| … | … | … | … |
| 根 | 1 | log n | log n |

总代价 = Σ n/2^k · k = **O(n)**（等比收敛）。

> ⚠️ 面试追问「建堆为什么 O(n)」——不要说「n 次下沉 × log n」；正确答法：**高度求和**（只有根是 log n，绝大多数节点下沉很少）。

## 4. 完整手写小顶堆模板

```java
class MinHeap {
    private final int[] heap;
    private int size;

    public MinHeap(int capacity) { heap = new int[capacity]; }

    public void offer(int val) {
        heap[size] = val;
        siftUp(size++);
    }

    public int poll() {
        int top = heap[0];
        heap[0] = heap[--size];
        siftDown(0);
        return top;
    }

    public int peek() { return heap[0]; }
    public int size() { return size; }
    public boolean isEmpty() { return size == 0; }

    private void siftUp(int i) {
        while (i > 0 && heap[i] < heap[(i - 1) / 2]) {
            swap(i, (i - 1) / 2);
            i = (i - 1) / 2;
        }
    }

    private void siftDown(int i) {
        while (true) {
            int l = 2 * i + 1, r = 2 * i + 2, smallest = i;
            if (l < size && heap[l] < heap[smallest]) smallest = l;
            if (r < size && heap[r] < heap[smallest]) smallest = r;
            if (smallest == i) return;
            swap(i, smallest);
            i = smallest;
        }
    }

    private void swap(int a, int b) {
        int t = heap[a]; heap[a] = heap[b]; heap[b] = t;
    }
}
```

> 🎯 **面试手写堆的验收**：5 分钟内写出这个模板（含 siftUp/siftDown/offer/poll），并能在 215 题上替换 PriorityQueue 通过——堆的知识就彻底是自己的了。

## 5. 常见实现陷阱

| # | 陷阱 | 后果 | 对策 |
|---|------|------|------|
| 1 | siftDown 选「较大的子」 | 堆序破坏 | 小顶堆必须选较小的子 |
| 2 | 数组越界（left/right 超 size） | 异常 | 下沉前检查 `left < size` |
| 3 | 建堆从上往下 siftUp | O(n log n) 慢 | 弗洛伊德：从 n/2-1 向下 siftDown |
| 4 | poll 后 size 减错 | 漏元素/越界 | `--size` 再下沉，范围是 size |
| 5 | 用 `(i-1)/2` 时 i=0 | 死循环 | while 条件加 `i > 0` |
| 6 | 堆数组扩容忘记 | 溢出 | 动态扩容或预分配足够容量 |

> 🎯 **核心要点**：手写堆的八字真言——**「插上浮、删下沉、建堆下沉」**；siftDown 是灵魂（插入只发生一次上浮，删除/建堆/替换全靠下沉）；建堆 O(n) 的「高度求和」证明是面试高频追问；模板写到肌肉记忆后，工程场景仍用 PriorityQueue（03 模块），手写堆只是面试武器。
