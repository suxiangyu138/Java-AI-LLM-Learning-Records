# 03 - B 树的删除

> B 树最复杂的操作：删除可能发生在内部节点（用前驱/后继替代），下溢时「借键」或「合并」——与插入分裂对称，删除的合并会让树变矮。

## 1. 删除的三种情况

```text
情况 A: 删除的键在叶子 → 直接删（检查下溢）
情况 B: 删除的键在内部节点 → 用前驱/后继替代（类似 BST 双子）
情况 C: 递归删除导致下溢 → 借键或合并
```

| 情况 | 处理 | 类比 |
|------|------|------|
| 叶子删除 | 直接删 + 下溢检查 | BST 叶子删除 |
| 内部删除 | 前驱/后继替代（值替换） | BST 双子删除 |
| 下溢修复 | 借键 / 合并 | 红黑树删除的双黑修复 |

> ⚠️ **内部节点删除的关键**：与 BST 一样「值替代」——实际删除的是**叶子里的前驱/后继**，所以**真正的物理删除永远发生在叶子**。

## 2. 下溢与修复策略

**下溢（Underflow）**：删除后节点键数 < ⌈m/2⌉-1（少于下限）。

```text
下溢判定: 非根节点键数 < ⌈m/2⌉ - 1

修复策略（按兄弟情况）:
  策略 1: 兄弟「富余」（键数 > 下限）→ 借键（旋转）
  策略 2: 兄弟也「贫穷」→ 合并（两节点 + 父中键合成一个）
```

**两个方向**（与 AVL/红黑树的「借/并」思想同构）：

| 策略 | 条件 | 操作 |
|------|------|------|
| 借键 | 左/右兄弟键数 > ⌈m/2⌉-1 | 父键下移 + 兄弟键上移（旋转） |
| 合并 | 兄弟键数 = ⌈m/2⌉-1 | 两节点 + 父中键合并，父键数 -1（递归检查父） |

> 💡 **合并会减少父节点键数** → 父可能继续下溢 → **递归向上**（最坏到根）；根下溢到 0 键时树高减 1——**合并是树变矮的唯一方式**（与插入的「根分裂长高」对称）。

## 3. 借键与合并

### 3.1 借键（从右兄弟借，左移）

```text
m=5（下限 2 键），左节点下溢（1 键），右兄弟富余（3 键）:

删除前:                    借键后:
        [30 | 50]                [30 | 40 | 50]
       /    |    \              /    |    |    \
  [10|20] [40] [60|70|80]  [10|20|30] [40] [60|70|80]
   ↓下溢    ↑父键      借 40 上提，30 下移:
  借 40 → 左节点变 [10|20|30] ✓
```

```java
// 借键：右兄弟 → 父 → 下溢节点（顺时针旋转）
void borrowFromRight(BTreeNode node, BTreeNode parent, int idx) {
    BTreeNode right = parent.children[idx + 1];
    // ① 父键下移给下溢节点
    node.keys[node.keyCount] = parent.keys[idx];
    // ② 兄弟最左键上提给父
    parent.keys[idx] = right.keys[0];
    // ③ 兄弟孩子过继
    if (!right.isLeaf) {
        node.children[node.keyCount + 1] = right.children[0];
        for (int i = 0; i < right.keyCount - 1; i++) {
            right.children[i] = right.children[i + 1];
        }
    }
    node.keyCount++;
    right.keyCount--;
}
```

### 3.2 合并（左兄弟 + 下溢节点）

```text
m=5，左兄弟贫穷（2 键）、下溢节点（1 键）:

合并前:                    合并后:
        [30 | 50]                [50]
       /    |    \              /    \
  [10|20] [25] [60|70]    [10|20|25|30] [60|70]
   ↓贫穷   ↓下溢        父键 30 下移参与合并

合并: 左节点 + 父键 30 + 右节点 → [10|20|25|30]（4 键 = 上限，合法）
```

```java
// 合并：左兄弟 + 父中键 + 当前节点 → 一个节点
void mergeNodes(BTreeNode parent, int idx) {
    BTreeNode left = parent.children[idx];
    BTreeNode right = parent.children[idx + 1];
    // ① 父键下移
    left.keys[left.keyCount] = parent.keys[idx];
    left.keyCount++;
    // ② 右节点内容并入左
    for (int i = 0; i < right.keyCount; i++) {
        left.keys[left.keyCount + i] = right.keys[i];
        left.children[left.keyCount + i] = right.children[i];
    }
    left.keyCount += right.keyCount;
    // ③ 父节点删除该键和孩子
    for (int i = idx; i < parent.keyCount - 1; i++) {
        parent.keys[i] = parent.keys[i + 1];
        parent.children[i + 1] = parent.children[i + 2];
    }
    parent.keyCount--;
}
```

> 💡 合并后节点键数 = (⌈m/2⌉-1) + 1 + (⌈m/2⌉-1) ≤ m-1 ✓ 合法——**合并不溢出**（两半 + 父键恰好 ≤ 上限）。

## 4. 删除完整流程

```java
// B 树删除（CLRS 风格：下降时预合并保证路径节点富余）
void delete(BTreeNode node, int key) {
    int idx = findKey(node, key);              // 节点内找键位置

    if (idx < node.keyCount && node.keys[idx] == key) {
        if (node.isLeaf) {
            removeKey(node, idx);              // 情况 A：叶子直接删
        } else {
            deleteInternal(node, idx);         // 情况 B：内部节点
        }
    } else {
        if (node.isLeaf) return;               // 不存在
        boolean lastChild = (idx == node.keyCount);
        // 下降前预修复：保证孩子有富余键
        if (node.children[idx].keyCount < MIN_KEYS) {
            fixChild(node, idx);               // 借键或合并
            if (lastChild && idx > node.keyCount) idx--;
        }
        delete(node.children[idx], key);       // 递归下降
    }
}

// 内部节点删除：前驱替代（实际删除在叶子）
void deleteInternal(BTreeNode node, int idx) {
    int key = node.keys[idx];
    if (node.children[idx].keyCount > MIN_KEYS) {
        // 左孩子富余 → 前驱替代
        int pred = getPredecessor(node.children[idx]);
        node.keys[idx] = pred;
        delete(node.children[idx], pred);
    } else if (node.children[idx + 1].keyCount > MIN_KEYS) {
        // 右孩子富余 → 后继替代
        int succ = getSuccessor(node.children[idx + 1]);
        node.keys[idx] = succ;
        delete(node.children[idx + 1], succ);
    } else {
        mergeNodes(node, idx);                 // 都贫穷 → 合并再删
        delete(node.children[idx], key);
    }
}
```

**CLRS 预修复技巧**：下降时若孩子将下溢（键数 = 下限），先借/合并——**保证路径上节点始终富余**，删除单趟完成（与插入的「先分裂」对称）。

## 5. 删除示例推演

**示例**：m=3（2-3 树），依次删除 1, 2, 3。

```text
初始:          [2|4]
             /  |  \
          [1] [3] [5]

删除 1（叶子）:
          [2|4]          ← [1] 变空 → 下溢！
         /  |  \
       [空] [3] [5]
       借右兄弟 3: 父键 2 下移、3 上提
          [3|4]
         /  |  \
       [2] [空] [5]       ← 又下溢？继续借/合并
       合并: [2] + 3 + [空] → [2|3]
          [4]
         /   \
      [2|3]  [5]          ✓ 平衡

删除 2（内部节点键）:
          [4]
         /   \
      [2|3]  [5]
      前驱 3 替代 4? 不——删除 2 在叶子 [2|3] 内，直接删
          [4]
         /   \
       [3]   [5]          ✓

删除 3:
          [4]
         /   \
       [空]  [5]          ← 下溢，借右兄弟
       父键 4 下移、5 上提 → [4|5]
       根变空 → 树高减 1
          [4|5]           ✓ 树变矮（合并导致的）
```

**观察**：删除可能让**树高减 1**（根下溢到空）——与插入的「根分裂长高」完全对称。

## 6. 删除速查表

| 场景 | 处理 | 复杂度 |
|------|------|--------|
| 叶子删除（不触发下溢） | 直接删 | O(log_B n) I/O |
| 叶子删除（下溢） | 借键或合并 | O(log_B n) I/O |
| 内部键删除 | 前驱/后继替代 | O(log_B n) I/O |
| 合并传播 | 递归到根（可能减高） | O(log_B n) I/O |

**面试追问**：

| 追问 | 答题要点 |
|------|---------|
| 删除和插入的对称性？ | 插入分裂长高、删除合并变矮 |
| 为什么实际删除总在叶子？ | 内部键用前驱/后继值替代 |
| 借键和合并怎么选？ | 兄弟富余借、兄弟贫穷合并 |
| 合并为什么合法（不溢出）？ | 两半 + 父键 = (下限×2+1) ≤ 上限 |
| 树什么时候变矮？ | 根下溢到 0 键时（合并传播到根） |
| 预修复技巧是什么？ | 下降时保证路径节点富余（单趟） |

> 🎯 **核心要点**：删除验收——三种情况（叶子/内部/下溢）的处理；借键（旋转）与合并（父键下移）两个策略的触发条件；「合并让树变矮」与插入对称；CLRS 预修复的单趟技巧；m=3 推演能手算（删除导致借键→合并→减高完整链）。B+ 树的工程变体见 04 模块。
