# 02 - B 树的查找与插入

> B 树的两大基础操作：查找 = 逐层二分（每节点一次 I/O）；插入 = 先找叶子 + 满则分裂（中键上提）——分裂是 B 树长高的唯一方式。

## 1. 查找操作

**查找 = 逐层下钻 + 节点内二分**——每访问一个节点 = 一次磁盘 I/O。

```java
// B 树查找（概念实现）
boolean search(BTreeNode node, int key) {
    int i = 0;
    while (i < node.keyCount && key > node.keys[i]) {
        i++;                                 // 节点内顺序/二分找位置
    }
    if (i < node.keyCount && key == node.keys[i]) {
        return true;                         // 命中
    }
    if (node.isLeaf) return false;           // 叶子未命中 = 不存在
    return search(node.children[i], key);    // 进入对应孩子（一次 I/O）
}
```

```text
查找 45（m=5 示例树）:
        [20 | 40 | 60 | 80]           ← 第 1 次 I/O（根常驻内存）
       /    |     |     |    \
  [10|15] [25|30] [45|50] ...
                    ↑ 40 < 45 < 60 → 第 2 个孩子
                    → 第 2 次 I/O，命中 45 ✓

总 I/O: 2 次（树高 3 的查找路径）
```

| 复杂度 | 值 |
|--------|-----|
| 节点访问 | O(log_B n)（树高） |
| 节点内比较 | O(log m)（二分） |
| 磁盘 I/O | **O(log_B n) 次（关键！）** |

> 💡 与 BST 查找的区别：BST 每层 O(1) 指针跳转（内存）；B 树每层一次**整页加载**（磁盘）——所以 B 树把「比较次数」让位给「节点加载次数」：一次加载 1000 键，比较随便做，I/O 才是成本。

## 2. 插入的两步

```text
第一步: 查找定位 → 找到应插入的叶子节点
第二步: 插入键 → 若节点未满，直接插入（有序）
        → 若节点已满（m-1 个键），分裂！

关键: 插入永远发生在叶子（与 BST 不同——BST 可能插内部）
```

| 步骤 | 操作 | 复杂度 |
|------|------|--------|
| 定位 | 从根到叶子 | O(log_B n) 次 I/O |
| 插入 | 叶子内有序插入 | O(m)（页内） |
| 分裂 | 满节点拆两半 | O(m)（页内） |
| 上提 | 中键插入父节点 | 递归（最多到根） |

> ⚠️ **B 树插入只在叶子**——这是「先查后插」的天然流程；分裂产生的「中键上提」是唯一向上传播的操作。

## 3. 分裂：中键上提

**分裂（Split）**：节点满（m-1 键）时，把中间键上提给父节点，左右各半成两个新节点。

```text
m=5（节点最多 4 键），插入导致 5 键:

分裂前（满）:       分裂后:
  [1|2|3|4|5]        [1|2]   [3]→上提   [4|5]
  中键 3 上提给父:
       [3]
      /   \
  [1|2]  [4|5]
```

```java
// 分裂核心逻辑（概念）
void splitChild(BTreeNode parent, int childIndex) {
    BTreeNode child = parent.children[childIndex];   // 满节点
    BTreeNode right = new BTreeNode();               // 新右节点
    int mid = child.keyCount / 2;                    // 中键位置

    // ① 中键右侧移到新节点
    right.keyCount = child.keyCount - mid - 1;
    for (int i = 0; i < right.keyCount; i++) {
        right.keys[i] = child.keys[mid + 1 + i];
        if (!child.isLeaf) {
            right.children[i] = child.children[mid + 1 + i];
        }
    }
    // ② 中键上提给父
    for (int i = parent.keyCount; i > childIndex; i--) {
        parent.keys[i] = parent.keys[i - 1];         // 父节点后移腾位
    }
    parent.keys[childIndex] = child.keys[mid];       // 中键上提
    parent.keyCount++;
    // ③ 右节点挂接到父
    parent.children[childIndex + 1] = right;
    // ④ 原节点保留左半
    child.keyCount = mid;
}
```

> 💡 分裂的「一半」：左半 ⌈m/2⌉-1 键、右半 ⌈m/2⌉-1 键、中键上提——**正好满足键数下限 ⌈m/2⌉-1**，这就是下限公式的来源。

## 4. 插入完整流程

```java
// B 树插入（CLRS 风格：先分裂后下降，避免回溯）
class BTree {
    private BTreeNode root;
    private int m;                       // 阶

    public void insert(int key) {
        if (root == null) {
            root = new BTreeNode(true);
            root.keys[0] = key;
            root.keyCount = 1;
            return;
        }
        if (root.keyCount == m - 1) {    // 根满：先分裂根
            BTreeNode newRoot = new BTreeNode(false);
            newRoot.children[0] = root;
            splitChild(newRoot, 0);
            root = newRoot;
        }
        insertNonFull(root, key);        // 递归插入（保证路径上无满节点）
    }

    // 插入到非满节点（递归下降）
    void insertNonFull(BTreeNode node, int key) {
        int i = node.keyCount - 1;
        if (node.isLeaf) {
            // 叶子：直接有序插入
            while (i >= 0 && key < node.keys[i]) {
                node.keys[i + 1] = node.keys[i];
                i--;
            }
            node.keys[i + 1] = key;
            node.keyCount++;
        } else {
            // 内部：找到孩子，若满则先分裂
            while (i >= 0 && key < node.keys[i]) i--;
            i++;
            if (node.children[i].keyCount == m - 1) {
                splitChild(node, i);     // 孩子满：先分裂
                if (key > node.keys[i]) i++;
            }
            insertNonFull(node.children[i], key);
        }
    }
}
```

**两种插入策略对比**：

| 策略 | 方式 | 特点 |
|------|------|------|
| 先分裂后下降 | 下降时遇到满节点就分裂 | 一次遍历、无回溯（CLRS 经典） |
| 插入后回溯 | 叶子分裂后向上传播 | 直观但需维护父链 |

> 💡 CLRS 的「先分裂」技巧：保证下降路径上没有满节点 → 叶子插入永远不会因父满而回溯——**单趟完成插入**。

## 5. 插入示例推演

**示例**：m=3（2-3 树），依次插入 1, 2, 3, 4, 5。

```text
插入 1, 2:   [1|2]            ← 未满（m=3 最多 2 键）

插入 3:      [1|2|3] 满       ← 分裂
              [2]              ← 中键 2 上提成根
             /   \
          [1]   [3]

插入 4:      [2]              ← 落到右叶子
            /   \
         [1]   [3|4]

插入 5:      [2]              ← 右叶子 [3|4|5] 满 → 分裂
            /   \              中键 4 上提
         [1]   [3|4|5] 满
              ↓
              [2|4]            ← 4 上提到根
             /  |  \
          [1] [3] [5]
```

**观察**：树高只在「根分裂」时增加 1 层——**分裂从叶子向上传播，根分裂是树长高的唯一方式**（与红黑树的「变色上提」对应）。

## 6. 查找与插入速查表

| 操作 | 流程 | I/O 次数 | 页内成本 |
|------|------|:---:|:---:|
| 查找 | 逐层二分 | O(log_B n) | O(log m) |
| 插入（未满） | 定位叶子 + 有序插入 | O(log_B n) | O(m) |
| 插入（满） | 分裂 + 中键上提 | O(log_B n) | O(m) × 分裂数 |
| 根满 | 先分裂根 | 1 | O(m) |

**面试追问**：

| 追问 | 答题要点 |
|------|---------|
| 为什么插入只发生在叶子？ | 查找定位天然到叶子；内部键变化会破坏区间 |
| 分裂为什么把中键上提？ | 保持键数范围 + 区间语义不变 |
| 树什么时候长高？ | 根分裂时（唯一途径） |
| 为什么先分裂后下降？ | 保证路径无满节点 → 单趟无回溯 |
| 插入的最坏 I/O？ | 每层一次（含分裂上提），O(log_B n) |

> 🎯 **核心要点**：查找验收——能说「每层一次 I/O、页内二分」；插入验收——「先分裂后下降」单趟策略 + 分裂的中键上提 + 根分裂是树长高唯一方式；m=3 的推演能手算（5 个键完整过程）；「分裂保证两半各 ⌈m/2⌉-1 键」解释了键数下限的来源。删除（下溢处理）见 03 模块。
