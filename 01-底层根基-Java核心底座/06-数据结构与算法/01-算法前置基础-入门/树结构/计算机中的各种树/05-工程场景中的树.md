## 2. 数据库与存储

### 2.1 B+ 树（InnoDB 主索引）

| 特性 | 说明 |
|------|------|
| 为什么 B+ 不是红黑树 | 树高 = 磁盘 I/O 次数；页装千键 → 树高 3-4 |
| 为什么 B+ 不是 B | 数据只在叶子（页利用率高）+ 叶子链表（范围查询） |
| 聚簇索引 | InnoDB 主键索引的叶子存整行数据 |
| 二级索引 | 叶子存主键 → 回表 |

### 2.2 LSM 树（NoSQL 的写优化树）

**Log-Structured Merge Tree**：写内存表（MemTable）+ 批量刷盘（SSTable）+ 后台合并（Compaction）。

```text
写入: 内存 MemTable（跳表/树）→ 写满刷为 SSTable（有序不可变）
读取: MemTable → 新 SSTable → 旧 SSTable（逐层查 + 布隆过滤）
合并: 后台定时合并 SSTable（与 B+ 树在线更新的思路相反）

B+ 树: 读快写慢（就地更新有随机 I/O）
LSM:  写快读慢（顺序写 + 后台合并）→ 写多读少的日志/监控场景
```

| 数据库 | 索引结构 |
|--------|---------|
| MySQL InnoDB | B+ 树 |
| PostgreSQL | B+ 树 + Radix Tree（稀疏索引） |
| MongoDB | B 树（WiredTiger） |
| LevelDB / RocksDB | LSM 树 |
| Cassandra / HBase | LSM 树 |

> 💡 「B+ 树 vs LSM」是数据库面试的终极对比题：**读多选 B+、写多选 LSM**（详见 MySQL/NoSQL 体系）。

## 3. 操作系统与系统软件

### 3.1 Linux 内核的红黑树

| 场景 | 用途 |
|------|------|
| CFS 调度器 | 进程按 vruntime 排序，O(log n) 取最小 |
| epoll | 监听 fd 的红黑树组织，O(log n) 增删查 |
| 定时器（Nginx/内核） | 按超时时间排序 |
| 内存管理（vma） | 虚拟内存区间的红黑树 |

### 3.2 文件系统与目录树

- **目录树**：文件系统的层次结构（从根 / 出发的树）；
- **inode 与目录项**：目录是「文件名 → inode」的映射，目录树遍历是文件操作的基础；
- **设备树（Device Tree）**：Linux 对嵌入式硬件的树形描述（CPU/内存/外设）；
- **进程树**：fork 产生的父子进程树，`pstree` 查看。

### 3.3 压缩与编码

**哈夫曼树**：频率高的字符编码短——最优前缀编码。

```text
字符: A(45) B(13) C(12) D(16) E(9) F(5)
哈夫曼树构建: 每次取频率最小的两棵合并
→ 编码: A=0, B=101, C=100, D=111, E=1101, F=1100
→ 总长最短（信息论最优，无损压缩基础）
```

> 💡 哈夫曼编码是「贪心算法」的经典应用——与贪心体系呼应；ZLIB/PNG/JPEG 都含哈夫曼思想。

## 4. 编译器与语言

| 树 | 定义 | 应用 |
|----|------|------|
| 语法树 | 语法分析产物（CFG 推导树） | 编译器前端 |
| AST | 抽象语法树（去掉非本质语法） | 代码分析/转换/格式化 |
| 表达式树 | AST 子集（运算符为内部节点） | 表达式求值/求导 |
| DOM 树 | HTML 文档结构树 | 浏览器渲染/JS 操作 |
| 调用树 | 函数调用关系 | 性能分析（profiler） |

```java
// 表达式树示例：((3 + 4) × 5)
//        ×
//       / \
//      +   5
//     / \
//    3   4
// 后序遍历 = 后缀表达式：3 4 + 5 ×
```

**AST 的工程价值**：IDE 重构/格式化、代码检查（ESLint）、编译器插件——「程序 = 一棵树」的思想让代码可分析可转换。

## 5. 机器学习与数据

| 树模型 | 核心思想 | 场景 |
|--------|---------|------|
| 决策树 | 特征划分（信息增益/基尼系数） | 分类/回归，可解释 |
| 随机森林 | 多棵决策树投票（Bagging） | 高维/抗过拟合 |
| GBDT/XGBoost | 梯度提升树（Boosting） | **表格数据默认王者** |
| 层次聚类树 | 簇的合并/分裂树状图 | 无监督聚类 |

**树模型与深度学习的选型**（面试常问）：

```text
表格数据（结构化） → 树模型（XGBoost/LightGBM）更强
图像/文本/语音 → 深度学习（CNN/Transformer）
数据量小 → 树模型（可解释、不过拟合）
```

> 💡 树模型是 AI 时代的「经典武器」——详见[机器学习/AI 体系](../../../03-AI大模型应用开发/)（如适用路径）。

## 6. 工程树面试问答速查

| 问题 | 答案要点 |
|------|---------|
| 为什么数据库用 B+ 树？ | 树高 = I/O 次数；页装千键树高 3-4；叶子链表范围查询 |
| B+ vs LSM？ | 读多 B+、写多 LSM；B+ 就地更新、LSM 顺序写后台合并 |
| Linux 为什么用红黑树？ | 增删频繁（进程/定时器）→ 写操作旋转少的平衡树 |
| epoll 为什么红黑树？ | 大量 fd 的 O(log n) 增删查 |
| AST 有什么用？ | 代码可分析可转换（重构/检查/编译） |
| 哈夫曼树为什么最优？ | 频率高编码短 + 前缀码无歧义（信息论） |
| 决策树 vs 深度学习？ | 表格数据树模型、非结构化深度学习 |

> 🎯 **核心要点**：工程树验收——「B+ 树 = 磁盘 I/O 次数」「LSM = 写优化」「红黑树 = Linux 增删频繁场景」「AST = 程序即树」四个工程认知；哈夫曼树（贪心+压缩）、决策树（AI 基础）是跨界考点；本目录 5 篇横向对比全部完成——各树深度体系见[总览](00-各种树全景总览.md)的体系入口表。
