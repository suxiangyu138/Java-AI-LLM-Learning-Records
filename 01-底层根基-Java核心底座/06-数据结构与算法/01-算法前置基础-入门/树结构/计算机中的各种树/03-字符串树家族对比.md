> 字符串问题的树形解法：Trie（前缀匹配）、后缀树（子串之王）、后缀数组（后缀树的实用替代）、AC 自动机（多模式匹配）——四者的能力边界与选型。

## 1. 家族谱系

```text
字符串树家族
├── 字典树 Trie ──────── 按字符分叉，前缀共享
├── 后缀树 ───────────── Trie 的压缩版（所有后缀）
├── 后缀数组 ─────────── 后缀树的空间优化替代
└── AC 自动机 ────────── Trie + KMP 失配指针（多模式）
```

| 结构 | 一句话定位 | 状态 |
|------|-----------|------|
| Trie | 前缀匹配之王 | ✅ 面试高频 |
| 后缀树 | 子串问题全解（理论） | 空间大，工程少见 |
| 后缀数组 | 后缀树的实用版 | 竞赛/工程主力 |
| AC 自动机 | 多模式串匹配 | 敏感词过滤 |

> 💡 深度内容：Trie 见[字典树 Trie（前缀树）](../字典树 Trie（前缀树）/)体系；后缀数组见[字符串高级](../../../04-中高级算法专题/专题 3：字符串高级算法/字符串高级/后缀数组/)。

## 2. 四种结构对比

| 维度 | Trie | 后缀树 | 后缀数组 | AC 自动机 |
|------|:---:|:---:|:---:|:---:|
| 构建 | O(Σ·n) | O(n)（Ukkanen） | O(n log n) 排序 | O(Σ·n) |
| 空间 | O(Σ·n) | **O(n) 但常数大** | **O(n) 紧凑** | O(Σ·n) |
| 查询单个模式 | O(len) | O(len) | O(len·log n) | O(len) |
| 多模式匹配 | 需遍历子树 | 需遍历 | 需遍历 | **O(len + 匹配数)** |
| 前缀查询 | ✅ 天生 | ✅ | 需 LCP 辅助 | ✅ |
| 最长重复子串 | ❌ | ✅ | ✅（LCP 数组） | ❌ |
| 工程实现难度 | ★ | ★★★★★ | ★★★★ | ★★★ |

## 3. 能力边界对照表

| 问题类型 | Trie | 后缀树/后缀数组 | 说明 |
|---------|:---:|:---:|------|
| 单词是否存在 | ✅ | ✅ | Trie 最直接 |
| 前缀计数/提示 | ✅ | ❌ | Trie 天生支持 |
| 单词排序 | ✅ 字典序输出 | ✅ 后缀数组 | 均可 |
| 最长公共前缀 LCP | ❌ | ✅ | 后缀数组 LCP 数组 |
| 最长重复子串 | ❌ | ✅ | 后缀数组经典应用 |
| 不同子串个数 | ❌ | ✅ | 后缀数组/后缀树 |
| 子串出现次数 | ❌ | ✅ | 后缀数组二分 |
| 多模式同时匹配 | ⚠️ 慢 | ⚠️ | **AC 自动机** |
| 敏感词过滤 | ⚠️ 单模式 | — | AC 自动机 |

**记忆锚点**：
- **前缀问题 → Trie**（存在/计数/提示/敏感词单模式）；
- **子串问题 → 后缀数组**（重复子串/不同子串/LCP）；
- **多模式同时匹配 → AC 自动机**（Trie + 失配指针）。

## 4. 选型建议

```text
字符串匹配问题？
├── 单模式串匹配 → KMP（字符串高级体系）
├── 多模式串（敏感词/词典） → AC 自动机
├── 前缀/单词查询 → Trie（面试最高频）
├── 子串统计类（重复/不同子串/LCP） → 后缀数组
└── 模式串很长且构建一次多次查询 → 后缀树（理论最优）
```

**Trie 的工程应用**（面试加分）：

| 场景 | Trie 的角色 |
|------|-----------|
| 输入法/搜索引擎 | 前缀提示 |
| 手机通讯录 | 号码前缀匹配 |
| 路由器 | IP 最长前缀匹配（Radix Tree） |
| LeetCode 单词搜索 II | 多单词 DFS 剪枝 |
| 数据库 | 稀疏索引的 Radix Tree（PostgreSQL） |

### 4.1 AC 自动机：多模式匹配的核心思想

**AC 自动机 = Trie + KMP 失配指针**：

```text
构建三步：
① 建 Trie（所有模式串插入）
② BFS 建立 fail 指针（失配时跳转的最长后缀节点）
③ 匹配时沿 fail 链收集所有命中

示例: 模式串 [he, she, his, hers]
文本: "ushers" → 匹配 she + hers（fail 链跳转命中）
```

| 场景 | 为什么用 AC 自动机 |
|------|-------------------|
| 敏感词过滤 | 一次扫描命中所有模式 |
| 词典匹配 | 多模式同时匹配 |
| 入侵检测 | 特征库模式匹配 |

### 4.2 面试问答

| 问题 | 答案 |
|------|------|
| Trie 的空间优化？ | 压缩 Trie（Radix Tree）、哈希子节点 |
| 后缀树 vs 后缀数组？ | 后缀数组空间 O(n) 紧凑，配合 LCP 数组 |
| 什么时候用后缀树？ | 模式串超长/一次性构建多次查询 |
| AC 自动机复杂度？ | 构建 O(Σ·n)，匹配 O(len + 命中数) |
| 前缀查询 vs 子串查询？ | 前缀用 Trie（共享前缀）；子串用后缀结构 |

### 4.3 实战选择卡

```text
单词/前缀 → Trie（面试最高频）
敏感词多模式 → AC 自动机
最长重复子串/不同子串 → 后缀数组
单模式 KMP → 字符串高级体系
```

### 4.4 后缀数组构建示例

```text
文本 "banana" 的后缀与排序:
  后缀: banana, anana, nana, ana, na, a
  排序: a(5), ana(3), anana(1), banana(0), na(4), nana(2)
  后缀数组 SA = [5, 3, 1, 0, 4, 2]

LCP 数组（相邻后缀的最长公共前缀）:
  LCP = [-, 1, 3, 0, 0, 2]
  最长重复子串 = max(LCP) = 3 → "ana"
```

> 🎯 **核心要点**：字符串树家族验收——「前缀 Trie、子串后缀数组、多模式 AC 自动机」三句选型；Trie 的工程版图（输入法/路由/数据库）能举例；后缀数组 = 后缀树的实用替代（空间）是竞赛与工程共识；Trie 深度内容见[字典树 Trie](../字典树 Trie（前缀树）/)体系。

> 💡 字符串树一句话回顾：前缀 Trie、子串后缀数组、多模式 AC 自动机——三种需求三种树，后缀树是理论最优但空间大。

| 需求 | 首选 | 备选 |
|------|------|------|
| 单词存在/前缀 | Trie | 哈希集合（无前缀） |
| 敏感词过滤 | AC 自动机 | Trie 单模式 |
| 最长重复子串 | 后缀数组 | 后缀树 |
| 不同子串计数 | 后缀数组 | 后缀树（O(n) 构建） |
