## 1. 堆家族谱系

```text
二叉堆（完全二叉树 + 数组）
    ├── 泛化 d 叉堆（d 个子，树更矮）
    ├── 理论优化 → 斐波那契堆（摊还 O(1) 减键）
    └── 实用替代 → 配对堆（实现简单的自调整堆）
```

| 堆 | 一句话定位 | 状态 |
|----|-----------|------|
| 二叉堆 | 数组实现，工程绝对默认 | ✅ 生产主力 |
| d 叉堆 | 树更矮，缓存更友好 | 特定场景 |
| 斐波那契堆 | 减键/合并摊还 O(1) | 理论最优，常数大 |
| 配对堆 | 简单实现的摊还堆 | 实用替代 |

> 💡 深度内容见[堆 Heap](../堆 Heap/00-堆 Heap 知识体系总览.md)体系（二叉堆完整 7 篇）；本节做横向对比。

## 2. 四种堆对比

| 操作 | 二叉堆 | d 叉堆（d=4） | 斐波那契堆 | 配对堆 |
|------|:---:|:---:|:---:|:---:|
| 插入 | O(log n) | O(log_d n) | **O(1)** 摊还 | **O(1)** 摊还 |
| 取最小 | O(1) | O(1) | O(1) | O(1) |
| 删除最小 | O(log n) | O(d·log_d n) | O(log n) 摊还 | O(log n) 摊还 |
| 合并两堆 | O(n) | O(n) | **O(1)** 摊还 | **O(1)** 摊还 |
| 减键 | O(log n) | O(log_d n) | **O(1)** 摊还 | O(log n) 摊还 |
| 空间 | O(n) 数组连续 | O(n) | O(n) + 指针多 | O(n) |
| 实现难度 | ★（最简单） | ★★ | ★★★★★ | ★★★ |

**为什么斐波那契堆理论最优却没统治世界**：
- 摊还分析假设大量操作摊平，实际场景插入/删除混合时**常数项巨大**；
- 每个节点 5 个指针 + 双向链表结构，内存开销与缓存不友好；
- **Dijkstra/Prim 的减键场景**（节点少、减键多）才真正受益——图算法教材里它的舞台。

**d 叉堆的工程亮点**：d=4 时树高减半（log₄n ≈ log n / 2），且子节点在数组中**连续**——缓存命中率高于二叉堆的跳跃访问；`std::priority_queue` 的底层就是二叉堆，d 叉堆需自实现。

## 3. 堆 vs 平衡树

**堆与红黑树都能取最值，怎么选？**（面试高频对比）

| 维度 | 二叉堆 | 红黑树 |
|------|:---:|:---:|
| 取最值 | **O(1)** | O(log n) |
| 插入 | O(log n) | O(log n) |
| 删除任意元素 | **O(n)** | **O(log n)** |
| 查任意元素 | O(n) | O(log n) |
| 有序遍历 | ❌ | ✅ 中序升序 |
| floor/ceiling | ❌ | ✅ |
| 工程实现 | PriorityQueue | TreeMap/TreeSet |

**选型规则**：
- 只要**最值 + 增删** → 堆（PriorityQueue，TopK/中位数）；
- 要**任意元素操作/有序性/区间** → 红黑树（TreeMap）。

> ⚠️ 记忆锚点：**堆只管「根」、树管「所有」**——堆删任意元素 O(n) 的短板是「延迟删除」技巧的用武之地（堆体系 06 模块）。

## 4. 选型建议

```text
需要优先级/最值？
├── 标准场景（TopK/任务调度） → 二叉堆（PriorityQueue）✅ 默认
├── 海量减键（Dijkstra 优化） → 斐波那契堆（理论）/配对堆（实用）
├── 缓存敏感/树高敏感 → d 叉堆（d=4）
├── 需要删除/查询任意元素 → 红黑树（TreeMap）
└── 需要中位数/双堆 → 二叉堆双堆组合（堆体系 06 模块）
```

**工程速查**：

| 语言/框架 | 堆实现 | 说明 |
|-----------|--------|------|
| Java | PriorityQueue | 二叉堆，默认小顶堆 |
| C++ | std::priority_queue | 二叉堆，默认大顶堆 |
| Python | heapq | 二叉堆（列表） |
| Go | container/heap | 二叉堆接口 |
| Rust | BinaryHeap | 二叉堆 |

### 4.1 堆的工程应用全景

| 系统 | 堆的用途 |
|------|---------|
| Java PriorityQueue | TopK/任务调度 |
| Python heapq | 合并有序流 |
| Go 调度器 | 定时器堆 |
| Redis | 延迟队列（有序集合，堆思想） |
| Kafka | 时间轮（变体，非堆但同思想） |
| 操作系统 | 就绪队列（优先级） |

### 4.2 面试问答

| 问题 | 答案 |
|------|------|
| 堆排序为什么不常用？ | 缓存不友好（跳跃访问），常数大 |
| 斐波那契堆什么时候用？ | Dijkstra 减键密集场景（理论） |
| d 叉堆比二叉堆好在哪？ | 树矮 + 子节点连续（缓存友好） |
| 堆和跳表都能取最值？ | 跳表支持有序遍历；堆只最值 |
| 「第 K 大」用堆还是快速选择？ | 动态/流式用堆；静态数组快速选择期望 O(n) |

### 4.3 决策速记卡

```text
取最值 → 堆（O(1) peek）
取最值 + 删任意 → 红黑树（O(log n) 双向）
取最值 + 有序遍历 → 跳表/红黑树
多路归并 → 堆（每路指针入堆）
```

### 4.4 二叉堆的实现细节速查

```text
二叉堆三要点（深度见堆 Heap 体系）:
  存储: 数组（完全二叉树，无空位）
  上浮: 插入时 siftUp（与父比较交换）
  下沉: 删除时 siftDown（与较小的子交换）
  TopK: 前 K 大装小顶堆（K 大小，门槛替换）
  双堆: 大顶+小顶对半分 → 中位数 O(1) 查询
```

> 🎯 **核心要点**：堆家族验收——「工程默认二叉堆」是铁律，其他堆是特定场景武器；堆 vs 红黑树的选型一句话（只管根用堆、要全序用树）；「取最值 O(1) 但删任意 O(n)」的堆短板要能答；二叉堆深度内容（siftUp/siftDown/TopK/双堆）见[堆 Heap](../堆 Heap/00-堆 Heap 知识体系总览.md)体系。
