## 1. 家族谱系

```text
二叉搜索树 BST（有序性基础）
    ├── 加「高度平衡」 → AVL 树（左右高差 ≤ 1）
    ├── 加「黑色平衡」 → 红黑树（最长 ≤ 2×最短）
    └── 加「多路 + 磁盘」 → B 树 / B+ 树（每节点多键）
```

| 树 | 解决的痛点 | 引入的代价 |
|----|-----------|-----------|
| BST | 有序查找 | 不平衡退化 O(n) |
| AVL | 严格平衡 | 旋转频繁，写慢 |
| 红黑树 | 写操作旋转少 | 树略高，读略慢 |
| B 树 | 磁盘 I/O 次数 | 节点实现复杂 |

> 💡 演进主线：**BST（有序）→ 平衡（保 O(log n)）→ 工程折中（红黑）→ 介质适配（B 树）**——每一步都是解决上一步的短板。

## 2. 平衡标准对比

| 树 | 平衡标准 | 树高上界 | 最坏查找 |
|----|---------|---------|---------|
| BST | 无（可能退化为链） | O(n) | O(n) |
| AVL | 任意节点 |左高-右高| ≤ 1 | 1.44·log₂(n+1) | O(log n) |
| 红黑树 | 最长路径 ≤ 2×最短（黑色平衡） | 2·log₂(n+1) | O(log n) |
| B 树 | 所有叶子同层（多路完美平衡） | log_B(n+1) | O(log_B n) |

**直观对比**（n = 100 万）：

| 树 | 树高 ≈ | 查询路径长度 |
|----|:---:|:---:|
| AVL | 20 层 | 20 次比较 |
| 红黑树 | 40 层 | 40 次比较（上限） |
| B 树（页 1000 键） | 2 层 | 2 次磁盘 I/O |

> 🎯 关键认知：**树高 = 查询代价**——内存中 AVL 比红黑树快一点（层数少），磁盘上 B 树把「层数」变成「I/O 次数」后优势碾压。

## 3. 操作复杂度对比

| 操作 | BST（最坏） | AVL | 红黑树 | B 树 |
|------|:---:|:---:|:---:|:---:|
| 查找 | O(n) | O(log n) | O(log n) | O(log_B n) |
| 插入 | O(n) | O(log n) + ≤1 旋转 | O(log n) + ≤2 旋转 | O(log_B n) |
| 删除 | O(n) | O(log n) + O(log n) 旋转 | O(log n) + ≤3 旋转 | O(log_B n) |
| 空间 | O(n) | O(n) | O(n) | O(n) 但页内连续 |

**写操作的旋转代价**（红黑树 vs AVL 的本质差异）：

```text
插入: 红黑树 ≤ 2 次旋转        AVL ≤ 1 次旋转（但可能回溯 O(log n) 层更新平衡因子）
删除: 红黑树 ≤ 3 次旋转        AVL 可能 O(log n) 次旋转（回溯到根）

→ 频繁增删：红黑树旋转总数更少 → 常数更小
→ 只读不改：AVL 树更矮 → 查找更快
```

## 4. 应用场景对比

| 树 | 经典应用 | 为什么选它 |
|----|---------|-----------|
| BST | 算法题、概念教学 | 简单；非生产（退化风险） |
| AVL | 静态索引、只读缓存 | 查询最速 |
| 红黑树 | TreeMap/TreeSet、HashMap 树化、Linux CFS 调度、Nginx 定时器 | 写多读少工程默认 |
| B 树 | 文件系统（ext4）、NoSQL（MongoDB） | 磁盘顺序读 |
| B+ 树 | MySQL InnoDB、PostgreSQL、SQLite | 范围查询 + 页利用率 |

**红黑树的工程版图**（远超想象）：

| 场景 | 红黑树用途 |
|------|-----------|
| Java TreeMap/TreeSet | 有序 Map/Set |
| Java HashMap（≥8 桶） | 链表退化兜底 |
| Linux CFS 调度器 | 进程按 vruntime 排序 |
| Nginx 定时器 | 超时事件按时间排序 |
| C++ std::map | 红黑树实现 |
| epoll | 监听事件的红黑树组织 |

## 5. 演进逻辑总结

```text
问题 1：BST 会退化 → 平衡树（AVL/红黑）解决
问题 2：AVL 写太贵 → 红黑树折中（旋转少）
问题 3：内存不够放/磁盘慢 → B 树多路（页适配）
问题 4：B 树范围查询差 → B+ 树（叶子链表）
```

### 5.1 平衡树的「平衡因子」实现差异

| 树 | 平衡信息 | 维护成本 | 失衡修复 |
|----|---------|---------|---------|
| AVL | 节点高度/平衡因子 | 每次更新沿路径回溯 | 单旋/双旋 |
| 红黑树 | 颜色 + 黑高 | 局部变色/旋转 | 插入 ≤2 旋、删除 ≤3 旋 |
| B 树 | 键数（度约束） | 分裂/合并 | 中键上移 |

> 💡 AVL 的平衡因子是「数值」（-1/0/1），红黑树是「颜色布尔」——颜色的修复更局部，这就是红黑树旋转更少的底层原因。

### 5.2 面试对比问答

| 问题 | 答案 |
|------|------|
| 为什么 B 树不叫平衡二叉树？ | 它是多路平衡搜索树（每节点多键） |
| 红黑树 vs AVL 的查找差异？ | AVL 树更矮，查找快 ~20-30%（常数级） |
| 数据库为什么不用红黑树？ | 树高 60 层 = 60 次磁盘 I/O vs B+ 树 3-4 次 |
| 文件系统为什么 B 树？ | 磁盘块大小固定（页），多键一页少 I/O |
| 什么时候用 BST 而不是平衡树？ | 数据量小/无退化风险/教学演示 |

### 5.3 学习顺序建议

```text
BST（有序基础）→ AVL（严格平衡）→ 红黑树（工程折中）
→ B 树（磁盘）→ B+ 树（数据库）
每步新增的知识点：旋转 / 染色 / 分裂合并
```

### 5.4 数据规模直觉表

```text
n = 100 万节点的查询路径长度:
  BST（退化）   1,000,000 层  ← 灾难
  AVL           20 层
  红黑树        40 层（上限）
  B+ 树（页千键） 2 层

面试直觉: 内存树「层数 = 比较次数」，磁盘树「层数 = I/O 次数」
```

> 🎯 **核心要点**：搜索树家族验收——能画出演进主线（BST→AVL→红黑→B/B+）；说出「AVL 树矮读快、红黑树旋转少写快、B 树磁盘 I/O 少」三句选型；红黑树工程版图（TreeMap/HashMap/Linux/Nginx/epoll）是面试加分项；各树深度内容见[红黑树](../红黑树 Red‑Black Tree/00-红黑树知识体系总览.md)、[AVL 树](../AVL 树（平衡二叉搜索树）/)、[B 树 B + 树](../B 树 B + 树/)体系。
