# 02 - 与 2-3-4 树的等价关系

> 理解红黑树的钥匙：红黑树 = 2-3-4 树的二叉树编码——红节点表示「与父同键」。插入/删除的修复逻辑从「背情形」变成「推导」，本节建立这个等价桥。

## 1. 2-3-4 树回顾

**2-3-4 树**：多路搜索树，每个节点可有 2/3/4 个孩子，键有序排列。

```text
2-节点:  [5]                1 个键 2 个孩子
3-节点:  [5 | 9]            2 个键 3 个孩子
4-节点:  [5 | 9 | 12]       3 个键 4 个孩子

            [5 | 9]
           /   |    \
        [2]  [6|7]  [12]
```

**平衡性质**：所有叶子同深度——**完美平衡**（比红黑树的「黑色平衡」更强）。

> 💡 2-3-4 树的插入/删除靠「节点分裂/合并」保持完美平衡——红黑树把「多键节点」拆成「二叉树 + 红链接」表达，两者完全等价。

## 2. 等价编码规则

**红黑树 ↔ 2-3-4 树的对应**：

| 2-3-4 树 | 红黑树编码 | 规则 |
|---------|-----------|------|
| 2-节点 | 黑色节点 | 单键节点原样 |
| 3-节点 | 黑节点 + 1 个红孩子 | 两键拆成父子（红连） |
| 4-节点 | 黑节点 + 2 个红孩子 | 三键拆成父+两红子 |

**核心规则一句话**：**红节点 = 「与黑父同属于一个多键节点」**——红节点不是独立的树节点，而是父节点的「附加键」。

```text
4-节点 [5 | 9 | 12] 的两种编码：

      9(黑)                    9(黑)
     /    \                  /    \
  5(红)  12(红)           5(红)  12(红)

红节点 5 和 12 表示「与 9 同键组」
```

> ⚠️ 红色 = 「附加」而非「独立」——所以**红节点必有一个黑父**（性质 4 的另一种解释：红节点不能有两个红兄弟？不——性质 4 说红的孩子必黑，从编码看红孩子本身就是多键节点的一部分，不能再挂红）。

## 3. 三类节点的映射

**3-节点两种形态**（左倾/右倾）等价：

```text
3-节点 [5 | 9]:          9(黑)              5(黑)
                         /                  \
                      5(红)                9(红)
```

**4-节点唯一形态**：

```text
4-节点 [5 | 9 | 12]:      9(黑)
                         /    \
                      5(红)  12(红)
```

**红黑树 → 2-3-4 树（合并回推）**：把每个黑节点与它的红孩子合并成一个多键节点：

```text
        13(黑)                    →        [8 | 13]
       /      \                          /   |    \
   8(红)     17(红)                [1|6] [11] [15|17|25]
   /    \    /    \                    ↓ 全黑路径同高 → 2-3-4 树完美平衡 ✓
1(黑) 11(黑)15(黑) 25(黑)
```

**为什么这个等价重要**：
- 黑高相等（性质 5） ⟺ 2-3-4 树所有叶子同深度（完美平衡）——同一件事的两种表达；
- 插入/删除的「修复」 ⟺ 2-3-4 树的「分裂/合并」——逻辑等价，红黑树只是把多键操作拆成旋转+变色。

## 4. 用 2-3-4 树理解修复

**插入（预告 03 模块）**：

| 2-3-4 树操作 | 红黑树对应 |
|-------------|-----------|
| 向 2-节点插入键 → 变 3-节点 | 插红节点，无需修复 |
| 向 3-节点插入键 → 变 4-节点 | 插红节点，可能需变色/旋转 |
| 向 4-节点插入键 → 先分裂成 2+2，中键上移 | **叔叔是红 → 变色**（父、叔变黑，祖父变红，问题向上传递） |

**插入的三种情形（叔叔颜色驱动）**：
```text
情形 1：叔叔红 → 变色（等价 4-节点分裂，问题上升）
情形 2：叔叔黑 + 之字形 → 先旋转成直线
情形 3：叔叔黑 + 直线 → 旋转 + 变色（等价 3-节点吸收新键）
```

> 💡 **背情形的痛苦 → 推逻辑的轻松**：叔叔红 = 4-节点分裂（变色上提）；叔叔黑 = 3-节点吸收（旋转收编）。等价关系把「6 种情形」压缩成「2 种思想」。

## 5. 等价关系速查表

| 红黑树概念 | 2-3-4 树概念 |
|-----------|-------------|
| 红节点 | 与黑父同键（附加键） |
| 黑节点 | 多键节点的主键 |
| 红+黑父子 | 一个多键节点 |
| 黑高相等 | 叶子同深度 |
| 红色不相邻 | 多键节点键有序连续 |
| 插入叔叔红 → 变色 | 4-节点分裂，中键上移 |
| 插入叔叔黑 → 旋转 | 3-节点吸收新键 |
| 删除双黑 | 下溢合并/借键（04 模块） |

### 4.1 删除的 2-3-4 树视角（预告 04 模块）

| 2-3-4 树删除 | 红黑树对应 |
|-------------|-----------|
| 从 2-节点删除 → **下溢** | 双黑（欠一个黑色） |
| 兄弟有富余键 → 借键 | 情形 3/4：旋转借黑色 |
| 兄弟也下溢 → 合并 | 情形 2：兄弟变红，上移 |

```text
删除思想速览（详见 04 模块）:
  删红节点 → 无事发生
  删黑节点 → 欠黑 → 双黑
    兄弟富余 → 借（旋转）
    兄弟贫穷 → 合并（变色上移，问题交给父）
```

### 4.2 左倾红黑树（LLRB，面试拓展）

**左倾红黑树**（Sedgewick）：3-节点统一为「左红」形态——插入修复只剩 3 种情形，代码更短。

| 对比 | 标准红黑树 | 左倾红黑树 |
|------|-----------|-----------|
| 3-节点形态 | 左倾/右倾皆可 | 仅左倾 |
| 插入修复情形 | 3 种（含对称） | 3 种（无对称） |
| 代码量 | TreeMap 实现 ~700 行 | ~200 行 |
| 工程使用 | JDK/Linux | 教学/教学库 |

> 💡 面试提「左倾红黑树」是加分项——说明你理解红黑树 = 2-3-4 树编码，左倾只是**统一编码规范**。

### 4.3 等价关系的面试用法

| 面试场景 | 用等价关系回答 |
|---------|---------------|
| 「为什么叔叔红就变色？」 | 叔叔+父+祖父是 4-节点，插入溢出 → 分裂变色 |
| 「为什么叔叔黑就旋转？」 | 3-节点吸收新键 → 旋转收编 |
| 「黑高为什么必须相等？」 | 等价 2-3-4 树的完美平衡（叶子同层） |
| 「红节点为什么不能相邻？」 | 相邻红 = 一个 5-键节点（2-3-4 树不允许） |

> 🎯 **核心要点**：等价关系验收——能把任意红黑树「合并红孩子」还原成 2-3-4 树（验证黑高）；能解释「性质 5 ⟺ 叶子同深度」；能用 2-3-4 树推导插入修复（4-节点分裂 = 变色上提）；这个视角让 03/04 模块的修复情形从「背诵」变「推导」。
