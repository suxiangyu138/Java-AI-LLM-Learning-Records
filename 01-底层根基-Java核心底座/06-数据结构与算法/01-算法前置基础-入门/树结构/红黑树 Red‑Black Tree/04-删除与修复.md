# 04 - 删除与修复

> 删除是红黑树最复杂操作：BST 删除三态 + 双黑传播——「借兄弟」与「上移问题」两种策略应对四种情形。本节目标是**看懂修复逻辑**（面试不考手写，但要能讲清双黑思想）。

## 1. 删除的两步

```text
第一步：BST 删除（450 题三态：叶子/单子/双子）
  - 双子用后继替代值，实际删除的是后继（叶子或单子）
  - 关键简化：真正被删的节点至多有一个非空孩子

第二步：若删的是黑节点 → 修复黑高（双黑）
  - 删红节点：无需修复（黑高不变）
  - 删黑节点：该路径黑高 -1 → 引入「双黑」概念
```

**删红不修、删黑必修**——这是删除与插入的对称性：插入染红只破坏性质 4；删除黑节点破坏性质 5（黑高）。

## 2. 双黑的概念

**双黑（double black）**：删除黑节点后，用其孩子顶替位置——若孩子也是黑，则该位置「欠一个黑色」，标记为双黑（等效一个节点承担两倍黑色）。

```java
// 概念示意：x 位置承担双重黑色
// 修复目标：把双黑变成普通黑（借黑或上移）
```

**修复的两个方向**：

| 方向 | 操作 | 适用 |
|------|------|------|
| 借兄弟 | 兄弟有红孩子 → 旋转借一个黑色 | 兄弟「富有」 |
| 上移 | 兄弟全黑 → 兄弟变红，双黑上移给父 | 兄弟「贫穷」 |

> 💡 双黑思想与 2-3-4 树删除的「下溢合并/借键」完全对应（02 模块的等价关系在这里发挥最大价值）——兄弟借键 = 旋转，兄弟也下溢 = 合并（变红上移）。

## 3. 四种修复情形

设双黑节点 x、兄弟 s（s 必存在，因为黑高平衡）。

**情形 1：兄弟 s 是红色**

```java
// 兄弟红 → 旋转父，使兄弟变黑（转化为情形 2/3/4）
rotateLeft(parent);         // 父在左时；对称则右旋
parent.color = RED;
s.color = BLACK;
s = x.parent.right;         // 更新兄弟
```

**情形 2：兄弟 s 黑 + s 的两个孩子都黑**

```java
// 兄弟全黑 → 兄弟变红，双黑上移给父（2-3-4 树合并）
s.color = RED;
x = parent;                 // 双黑上移
parent = x.parent;
// 循环继续；若 x 到根，直接染黑收尾
```

**情形 3：兄弟 s 黑 + s 的远孩子黑、近孩子红**

```java
// 近红远黑 → 旋兄弟成直线（转化为情形 4）
rotateRight(s);             // 近孩子方向旋转
s.color = RED;
s.parent.color = BLACK;
s = x.parent.right;         // 更新兄弟
```

**情形 4：兄弟 s 黑 + s 的远孩子红**

```java
// 远孩子红 → 旋父 + 变色（借黑色，修复完成）
rotateLeft(parent);         // 父在左时；对称则右旋
s.color = parent.color;     // 兄弟继承父色
parent.color = BLACK;
s.right.color = BLACK;      // 远孩子变黑
x = root;                   // 修复完成
```

## 4. 删除完整实现

```java
// 红黑树删除修复（JDK TreeMap 风格，完整版）
void fixAfterDeletion(Node x) {
    while (x != root && x.color == BLACK) {
        if (x == x.parent.left) {                     // x 在左
            Node s = x.parent.right;                  // 兄弟
            if (s.color == RED) {                     // 情形 1：兄弟红
                s.color = BLACK;
                x.parent.color = RED;
                rotateLeft(x.parent);
                s = x.parent.right;
            }
            if ((s.left == null || s.left.color == BLACK)
             && (s.right == null || s.right.color == BLACK)) {  // 情形 2
                s.color = RED;
                x = x.parent;
            } else {
                if (s.right == null || s.right.color == BLACK) {  // 情形 3
                    if (s.left != null) s.left.color = BLACK;
                    s.color = RED;
                    rotateRight(s);
                    s = x.parent.right;
                }
                s.color = x.parent.color;             // 情形 4
                x.parent.color = BLACK;
                if (s.right != null) s.right.color = BLACK;
                rotateLeft(x.parent);
                x = root;
            }
        } else {                                      // x 在右（对称）
            // ... 镜像逻辑 ...
        }
    }
    x.color = BLACK;
}
```

**删除主流程**：

```java
void deleteNode(Node z) {
    Node y = z;                    // 实际删除的节点（双子时用后继）
    boolean yWasRed = y.color == RED;
    Node x;                        // y 的替代者

    if (z.left == null) {          // 无左子（叶子/单右）
        x = z.right;
        replace(z, x);
    } else if (z.right == null) {  // 单左
        x = z.left;
        replace(z, x);
    } else {                       // 双子：用后继替代
        y = minNode(z.right);
        yWasRed = y.color == RED;
        x = y.right;
        // ... 标准 BST 双子删除（值替代/节点替换）...
    }
    if (yWasRed) return;           // 删红：无需修复
    fixAfterDeletion(x);           // 删黑：双黑修复
}
```

## 5. 删除修复速查表

| 情形 | 条件（x 在左） | 操作 | 2-3-4 树视角 |
|------|---------------|------|-------------|
| 1 | 兄弟红 | 旋父，兄弟变黑 | 转为 2/3/4 |
| 2 | 兄弟黑 + 双黑侄 | 兄弟变红，双黑上移 | 兄弟合并下溢 |
| 3 | 兄弟黑 + 近红远黑 | 旋兄弟成直线 | 调整形态 |
| 4 | 兄弟黑 + 远红 | 旋父 + 变色 | **借键，修复完成** |

| 对比 | 插入 | 删除 |
|------|------|------|
| 破坏性质 | 4（红相邻） | 5（黑高） |
| 新节点颜色 | 红 | — |
| 修复终止 | 情形 3（旋转收编） | 情形 4（借键）或上移到根 |
| 最大旋转 | 2 次 | 3 次 |
| 复杂度 | O(log n) | O(log n) |

> 🎯 **核心要点**：删除验收——能讲「删红不修、删黑必修」；双黑概念（欠一个黑色）与两个方向（借兄弟/上移）；四种情形的触发条件（兄弟颜色 → 侄颜色）；与 2-3-4 树删除的等价（借键/合并）；面试通常只考**思想**（双黑、借键、上移）不考手写——重点在 05 模块的 TreeMap 源码与 06 模块的选型对比。
