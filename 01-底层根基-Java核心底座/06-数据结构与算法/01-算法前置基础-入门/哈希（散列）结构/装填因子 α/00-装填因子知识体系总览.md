## 6. 常见问题 FAQ

| 问题 | 一句话答案 |
|------|-----------|
| 为什么默认 0.75？ | 时空均衡 + 泊松论证（P(≥8) 千万分之六） |
| α 大说明什么？ | 键多桶少 → 冲突多 → 查找慢 |
| α 小说明什么？ | 键少桶多 → 空间浪费 |
| 扩容时机？ | size > capacity × α |
| 扩容代价？ | O(n) 重哈希（摊还 O(1)） |
| 预分配有用吗？ | 避免频繁扩容（大集合收益明显） |
| 开放定址的 α 限制？ | 必须 < 1（满则死循环） |
| α 能手动调吗？ | 能——HashMap 构造器指定 |

## 12. 一句话速记卡

```text
α = n/m（键/桶）
0.75: 时空均衡 + 泊松（树化 8 的前提）
扩容: size > cap × α → ×2 + 重哈希（摊还 O(1)）
拆链: hash & oldCap 决定去留（JDK8）
预分配: N/α + 1 → 扩容归零
```

## 15. 一句话总结

| 核心认知 | 一句话 |
|---------|--------|
| α 的本质 | 空间与时间的交换旋钮 |
| 0.75 的意义 | 均衡点 + 泊松论证 |
| 扩容的本质 | 性能重置（摊还 O(1)） |
| 预分配的价值 | 大集合零扩容 |
| 结构约束 | 链地址可 >1、定址必须 <1 |

> 🎯 **核心要点**：装填因子验收——「**α = n/m 是哈希性能的调音旋钮**」：α 大省空间费时间（冲突多）、α 小费空间省时间；0.75 是时空均衡 + 泊松论证的工程默认；扩容（×2 + 重哈希）摊还 O(1)；预分配（已知规模）避免扩容抖动；开放定址（必须 <1）与链地址（可 >1）的 α 约束差异。
