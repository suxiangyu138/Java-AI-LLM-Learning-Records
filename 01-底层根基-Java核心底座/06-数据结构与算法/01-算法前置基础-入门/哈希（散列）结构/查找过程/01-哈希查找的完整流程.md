## 1. 查找三步链路

**哈希查找 = 三步**：

```text
① hash(key):  计算键的哈希值（O(1)）
② 定位桶:     index = hash % m（O(1)）
③ 链查:       桶内顺序/树查找（平均 O(1)）
```

```java
// 三步链路（概念实现）
int find(String key) {
    // ① 哈希
    int hash = key.hashCode();
    // ② 定位桶
    int index = hash % bucketCount;
    // ③ 链查（桶内链表）
    Node node = buckets[index];
    while (node != null) {
        if (node.key.equals(key)) return node.value;   // 命中
        node = node.next;
    }
    return NOT_FOUND;                                   // 未命中
}
```

```text
查找示例: find("banana")
  ① hash("banana") = 0xc3f1...（31 倍计算）
  ② index = 0xc3f1 % 16 = 5（桶 5）
  ③ 桶 5 链表: "apple" → "banana" ✓ 命中（2 次比较）

未命中示例: find("grape")
  ③ 桶 5 链表走到尾 null → 未命中（比较整个链）
```

| 步骤 | 复杂度 | 说明 |
|------|:---:|------|
| 哈希计算 | O(1) | 与键长度相关（字符串 O(L)） |
| 桶定位 | O(1) | 取模/位与 |
| 链查 | O(1) 平均 | 均匀时桶长 ~ α |

> 💡 注意：字符串键的哈希计算是 O(L)（遍历字符）——但 L 通常很小（键长度常数），工程上视为 O(1)；**长键攻击**正是利用这一点（02 模块防御）。

## 2. 复杂度分析

### 2.1 平均 vs 最坏

| 场景 | 桶长 | 查找复杂度 |
|------|:---:|:---:|
| 均匀哈希 + 合理 α | ~α | **O(1) 平均** |
| 最坏（全同桶） | n | **O(n)** |
| 树化桶 | ≤ 8+ | O(log n) |

```text
平均查找长度（ASL）:
  链地址: ASL ≈ 1 + α/2（α = 装填因子）
  例: α = 0.75 → ASL ≈ 1.375（几乎一次比较）

最坏场景的两个触发:
  ① 恶意: 攻击者构造同哈希键（HashDoS）
  ② 失效: 哈希函数设计缺陷（模式聚集）
```

### 2.2 为什么 O(1) 是「平均」而非「保证」

```text
哈希查找的 O(1) 依赖两个假设:
  ① 哈希函数均匀（01 模块四性质）
  ② 装填因子合理（α 不过大）

两者任一失效 → 退化 O(n)
（与红黑树的「最坏 O(log n) 保证」对比鲜明）
```

> 🎯 **面试对比**：哈希查找 O(1) 平均但无最坏保证；红黑树 O(log n) 最坏保证但常数大——「要最坏保证选树、要平均速度选哈希」是选型第一句（[和其他结构对比](../和其他结构对比/)专题）。

## 3. HashMap 查找源码

### 3.1 get 的完整链路（JDK 8+）

```java
// HashMap.get 核心链路（概念还原）
public V get(Object key) {
    Node<K, V> e = getNode(hash(key), key);      // ① 扰动后哈希
    return e == null ? null : e.value;
}

static final int hash(Object key) {
    int h;
    // ② 扰动函数: 高低位混合
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}

final Node<K, V> getNode(int hash, Object key) {
    Node<K, V>[] tab;
    // ③ 定位桶: (n-1) & hash（n 为 2 的幂）
    Node<K, V> first = tab[(n - 1) & hash];
    if (first != null) {
        if (first.hash == hash && key.equals(first.key)) {
            return first;                          // ④ 首节点命中
        }
        Node<K, V> e = first.next;
        if (first instanceof TreeNode) {
            return ((TreeNode) first).getTreeNode(hash, key);  // ⑤ 树查找
        }
        do {
            if (e.hash == hash && key.equals(e.key)) {
                return e;                          // ⑥ 链表查找
            }
        } while ((e = e.next) != null);
    }
    return null;                                   // ⑦ 未命中
}
```

| 细节 | 说明 |
|------|------|
| 扰动函数 | `h ^ (h >>> 16)` 高低位混合（防低位聚集） |
| 桶定位 | `(n-1) & hash`（n 为 2 的幂 → 位与 = 取模） |
| 首节点优先 | 命中率最高（链头） |
| 树查找 | 桶为红黑树时 O(log n) |
| 双条件 | `hash 相等 && equals 相等`（hash 预筛 + equals 确认） |

### 3.2 为什么双条件比较

```text
if (e.hash == hash && key.equals(e.key))
       ↑ 预筛（快）          ↑ 确认（慢但必对）

原因: hashCode 相等不能保证键相等（碰撞）
      → 先比 hash（O(1) 快筛），再比 equals（正确性）
```

> 💡 双条件设计的工程智慧：**快筛 + 确认**——99% 的情况 hash 不同直接跳过 equals；equals 只在 hash 相同时调用（大部分是碰撞的少数键）。

## 4. 扩容与查找

### 4.1 扩容对查找的影响

```text
扩容触发: size > capacity × 0.75（装填因子）

扩容过程:
  ① 新数组 2 倍容量
  ② 每个键重新 hash 定位（rehash）
  ③ 链表拆分到两个新桶（低/高位）

对查找的影响:
  扩容后 α 回到 0.375 → 桶长减半 → 查找更快
  扩容本身 O(n) → 摊还到每次插入 O(1)
```

```java
// 扩容后的重定位（2 的幂特性: 只分高低两个桶）
// 键 hash 的第 (oldCapacity 位) 决定去留:
//   bit = (hash & oldCap) == 0 → 留在低位桶
//   bit = 1 → 移到高位桶（index + oldCap）

// JDK 8 优化: 链表拆分不用重哈希（位运算判断）
Node<K,V> loHead, hiHead;        // 低/高两个新链表
do {
    if ((e.hash & oldCap) == 0) { lo 链表 }
    else { hi 链表 }
} while ((e = e.next) != null);
```

### 4.2 扩容后的查找链路

```text
扩容前: hash % 16 = 5（桶 5）
扩容后: 容量 32，hash % 32 = 21（桶 21）
  → 查找必须用「新容量」定位（rehash 后）
  → HashMap 内部自动处理（用户无感）
```

> ⚠️ 面试常问：扩容后查找怎么定位？——**用新容量重新计算桶位**；JDK 8 的链表拆分利用「hash 的扩容位」判断去留，O(1) 拆链（无需重算 hash）。

## 5. 查找优化技巧

| 技巧 | 原理 | 适用 |
|------|------|------|
| 预分配容量 | 避免频繁扩容 | 已知规模 |
| 自定义哈希 | 均衡分布 | 对象键 |
| 布隆前置 | 快速拒绝不存在 | 大量 miss 查询 |
| 缓存键哈希 | 避免重复计算 | 字符串长键 |
| 负载均衡 | 多表分片 | 超大集合 |

```java
// 预分配容量（避免扩容 rehash）
Map<String, Integer> map = new HashMap<>(expectedSize);

// 缓存哈希（String 内部已做: 惰性缓存）
// 自定义长键可缓存 hash 字段
class LongKey {
    String data;
    int cachedHash;                     // 缓存
    @Override public int hashCode() {
        if (cachedHash == 0) cachedHash = data.hashCode();
        return cachedHash;
    }
}
```

**面试追问**：

| 追问 | 答题要点 |
|------|---------|
| 哈希查找为什么平均 O(1)？ | 均匀哈希 + 合理 α → 桶长常数 |
| 什么时候退化 O(n)？ | 恶意/失效哈希（全同桶） |
| 为什么 (n-1)&hash 不是 %？ | n 为 2 的幂时位与更快等价 |
| 扰动函数有必要吗？ | 防低位聚集（如低 4 位相同的键） |
| 扩容后查找怎么办？ | 新容量重定位（JDK8 位运算拆链） |
| 双条件比较为什么？ | hash 快筛 + equals 确认 |

> 🎯 **核心要点**：查找验收——三步链路（hash→定位→链查）默写；平均 O(1) 的两前提（均匀 + α）；HashMap get 源码细节（扰动/位与/双条件/树查）；扩容对查找的影响（α 回落 + JDK8 位运算拆链）；「要平均速度选哈希、要最坏保证选树」的选型认知。
