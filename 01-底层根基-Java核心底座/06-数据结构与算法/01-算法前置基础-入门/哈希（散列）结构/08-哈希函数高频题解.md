## 1. 705. 设计哈希集合

### 1.1 题目与思路

```
实现 add/remove/contains（O(1)），不使用内置哈希集合
经典实现：链地址法（数组 + 链表/Set）+ 取模哈希
⚠️ 面试两个层次：
  简单版：桶数组 + 每个桶用 HashSet（能用但绕）
  完整版：自己实现哈希函数 + 链地址（展示功底）
```

### 1.2 完整代码（自实现哈希 + 链地址）

```java
/**
 * LeetCode 705. 设计哈希集合
 * 链地址法：hash(key) % 桶数 + 桶内链表
 */
class MyHashSet {
    private static final int BUCKETS = 769;      // ⚠️ 素数桶数（分布更好）
    private final List<List<Integer>> buckets;

    public MyHashSet() {
        buckets = new ArrayList<>(BUCKETS);
        for (int i = 0; i < BUCKETS; i++) buckets.add(new ArrayList<>());
    }

    private int hash(int key) {
        return key % BUCKETS;                    // ⚠️ 哈希函数
    }

    public void add(int key) {
        List<Integer> bucket = buckets.get(hash(key));
        if (!bucket.contains(key)) bucket.add(key);   // 已存在则忽略
    }

    public void remove(int key) {
        List<Integer> bucket = buckets.get(hash(key));
        // ⚠️ 用 Integer 对象调用 remove → 删除值而非下标
        bucket.remove((Integer) key);
    }

    public boolean contains(int key) {
        return buckets.get(hash(key)).contains(key);
    }
}
// 复杂度：均摊 O(桶内元素数) ≈ O(1)（负载因子 < 1 时）
// ⚠️ 面试升级点：
//   "如果 key 大量集中怎么办？→ 桶内转红黑树（JDK 8 HashMap 同款思路）
//    或者换更好的哈希函数（如乘以黄金比例后取位）"
// ⚠️ 完整 HashMap 版见 706（加 value 即可）
```

## 2. 706. 设计哈希映射

### 2.1 题目与思路

```
同 705 但存 key-value（put/get/remove）
升级点：
  ① 链地址 + key 匹配（不只是 contains）
  ② 可扩展：负载因子 + 扩容
⚠️ 面试加分版：实现"扩容"（超过阈值容量 ×2 重哈希）
```

### 2.2 完整代码（含扩容）

```java
/**
 * LeetCode 706. 设计哈希映射（含扩容）
 */
class MyHashMap {
    private static final int INIT_CAP = 16;      // 初始 2 的幂（方便取模优化）
    private static final float LOAD_FACTOR = 0.75f;
    private Node[] table;
    private int size;

    static class Node {
        int key, val;
        Node next;
        Node(int k, int v) { key = k; val = v; }
    }

    public MyHashMap() {
        table = new Node[INIT_CAP];
    }

    private int hash(int key) {
        return key & (table.length - 1);         // ⚠️ 2 的幂 → 位运算取模
    }

    public void put(int key, int value) {
        int idx = hash(key);
        Node head = table[idx];
        if (head == null) {
            table[idx] = new Node(key, value);
            size++;
        } else {
            // 找 key：存在则更新，否则尾插
            Node cur = head, prev = null;
            while (cur != null) {
                if (cur.key == key) { cur.val = value; return; }
                prev = cur;
                cur = cur.next;
            }
            prev.next = new Node(key, value);
            size++;
        }
        if (size > table.length * LOAD_FACTOR) resize();   // ⚠️ 扩容检查
    }

    public int get(int key) {
        Node cur = table[hash(key)];
        while (cur != null) {
            if (cur.key == key) return cur.val;
            cur = cur.next;
        }
        return -1;
    }

    public void remove(int key) {
        int idx = hash(key);
        Node cur = table[idx], prev = null;
        while (cur != null) {
            if (cur.key == key) {
                if (prev == null) table[idx] = cur.next;
                else prev.next = cur.next;       // ⚠️ 链表删除
                size--;
                return;
            }
            prev = cur;
            cur = cur.next;
        }
    }

    /** ⭐ 扩容：容量 ×2 + 全量重哈希 */
    private void resize() {
        Node[] old = table;
        table = new Node[old.length * 2];
        size = 0;                                // ⚠️ 重插时重新计数
        for (Node head : old) {
            Node cur = head;
            while (cur != null) {
                put(cur.key, cur.val);           // 复用 put（自动重哈希）
                cur = cur.next;
            }
        }
    }
}
// ⚠️ 面试表达："这是 HashMap 的教学复刻——取模哈希、
//   链地址、负载因子 0.75、2 的幂容量 + 位运算取模、
//   扩容重哈希。JDK 还加了树化（链表≥8）与扰动函数。"
```

## 3. 535. TinyURL 的加密与解密

### 3.1 题目与思路

```
长 URL → 短码（如 6 位），可逆还原
两种经典方案：
  ① 自增 ID + 62 进制编码：id → 短码（可逆、有顺序、可预测）
  ② 哈希取前 6 位 + 碰撞解决：随机性更好但需处理碰撞
⚠️ 62 进制 = 数字 10 + 小写 26 + 大写 26
  6 位可表示 62⁶ ≈ 568 亿个 URL
```

### 3.2 完整代码（自增 ID + 62 进制）

```java
/**
 * LeetCode 535. TinyURL 编码与解码
 * 自增 ID + 62 进制双向转换
 */
public class Codec {
    private static final String CHARS =
            "0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ";
    private final Map<String, String> shortToLong = new HashMap<>();
    private final Map<String, String> longToShort = new HashMap<>();
    private long id = 0;

    /** 编码：longUrl → shortUrl */
    public String encode(String longUrl) {
        if (longToShort.containsKey(longUrl)) return longToShort.get(longUrl);
        String code = toBase62(++id);                  // id → 62 进制
        String shortUrl = "http://tinyurl.com/" + code;
        shortToLong.put(shortUrl, longUrl);
        longToShort.put(longUrl, shortUrl);
        return shortUrl;
    }

    /** 解码：shortUrl → longUrl */
    public String decode(String shortUrl) {
        return shortToLong.get(shortUrl);
    }

    /** ⚠️ 62 进制转换：id → 字符串 */
    private String toBase62(long n) {
        StringBuilder sb = new StringBuilder();
        while (n > 0) {
            sb.append(CHARS.charAt((int) (n % 62)));
            n /= 62;
        }
        return sb.toString();
    }
}
// 推演 encode("https://example.com/a") → id=1 → "1" → tinyurl.com/1
//   第 62 个 URL → "10"（62 进制）；第 3844 个 → "100"
// ⚠️ 面试追问：
//   ① "自增 ID 可预测 → 泄露 URL 数量/被遍历？" → 方案二（哈希/随机）
//   ② "多机部署 ID 怎么生成？" → 分布式 ID（雪花算法/Redis incr）
//   ③ "并发安全？" → id 用 AtomicLong 或 Redis 原子自增
```

> 🎯 **要点**：编码类题 = **进制转换**（62 进制是 URL 场景标配）。可逆性是硬要求 → 自增 ID 方案天然可逆；随机方案需存映射表。

## 4. 380. O(1) 时间插入、删除和获取随机元素

### 4.1 题目与思路

```
insert/remove/getRandom 全部 O(1)（元素不重复）
结构：哈希（值 → 下标）+ 数组（存值）
  ⚠️ 哈希给出 O(1) 定位，数组给出 O(1) 随机与尾部删除
  删除技巧：与末尾元素交换后删除（避免数组中间删除 O(n)）
```

### 4.2 完整代码

```java
/**
 * LeetCode 380. O(1) 时间插入、删除和获取随机元素
 * ⚠️ 哈希 + 数组的经典复合结构（哈希设计题代表作）
 */
class RandomizedSet {
    private final List<Integer> values = new ArrayList<>();   // 数组存值
    private final Map<Integer, Integer> pos = new HashMap<>(); // 值 → 下标
    private final Random rand = new Random();

    public boolean insert(int val) {
        if (pos.containsKey(val)) return false;
        pos.put(val, values.size());
        values.add(val);                     // ⚠️ 尾插 O(1)
        return true;
    }

    public boolean remove(int val) {
        if (!pos.containsKey(val)) return false;
        int idx = pos.get(val);
        int last = values.get(values.size() - 1);

        // ⚠️ 核心技巧：被删元素与末尾交换 → 再删尾
        values.set(idx, last);               // ① 末尾值覆盖到 idx
        pos.put(last, idx);                  // ② 更新末尾值的下标
        values.remove(values.size() - 1);    // ③ 删除尾部
        pos.remove(val);                     // ④ 删除被删值的映射
        return true;
    }

    public int getRandom() {
        return values.get(rand.nextInt(values.size()));   // 数组随机 O(1)
    }
}
// 推演：insert(1) insert(2) insert(3) → values=[1,2,3], pos={1:0,2:1,3:2}
//   remove(1)：idx=0, last=3 → values=[3,2], pos={3:0,2:1} ✓
// ⚠️ 要点记忆："删中间 = 尾部交换 + 尾删"（O(1) 的关键）
//   与 146 LRU（哈希+双向链表）同构：哈希做定位，另一结构做特性
```

## 5. 49. 字母异位词分组

### 5.1 题目与思路

```
把异位词（相同字母不同顺序）分到一组
两种哈希键设计：
  ① 排序后字符串作 key：sorted(s)（"ate"→"aet"）
  ② 计数数组转字符串作 key：count 数组 26 位
⚠️ 哈希键设计是这题的核心考点——"同义词如何归一"
```

### 5.2 完整代码

```java
/**
 * LeetCode 49. 字母异位词分组
 * 方案一：排序 key（简单直观）
 */
public List<List<String>> groupAnagrams(String[] strs) {
    Map<String, List<String>> map = new HashMap<>();
    for (String s : strs) {
        char[] ca = s.toCharArray();
        Arrays.sort(ca);                        // ⚠️ 异位词排序后相同
        String key = new String(ca);
        map.computeIfAbsent(key, k -> new ArrayList<>()).add(s);
    }
    return new ArrayList<>(map.values());
}
// 复杂度：O(n·k log k)（k 为字符串平均长度）

/** 方案二：计数数组 key（更快，O(n·k)） */
public List<List<String>> groupAnagramsCount(String[] strs) {
    Map<String, List<String>> map = new HashMap<>();
    for (String s : strs) {
        int[] count = new int[26];
        for (char c : s.toCharArray()) count[c - 'a']++;
        String key = Arrays.toString(count);    // ⚠️ "[1,0,2,...]" 作 key
        map.computeIfAbsent(key, k -> new ArrayList<>()).add(s);
    }
    return new ArrayList<>(map.values());
}
// 推演 ["eat","tea","tan"]：
//   排序 key："eat"→"aet"，"tea"→"aet"，"tan"→"ant"
//   分组：{"aet": [eat, tea], "ant": [tan]} ✓
// ⚠️ 面试表达："异位词归一化：排序 key 简单，计数 key 更快
//   ——哈希键的设计要保证'同义必同键、异义尽量异键'。"
```

## 6. 128. 最长连续序列

### 6.1 题目与思路

```
无序数组中最长连续数字序列长度（O(n)！不能排序）
关键技巧：哈希集合 + "只从序列起点开始"
  ⚠️ 起点判定：x-1 不在集合中 → x 是起点 → 向后数
  每个元素最多被访问 2 次 → 总 O(n)
```

### 6.2 完整代码

```java
/**
 * LeetCode 128. 最长连续序列
 * ⚠️ 核心：只有起点（x-1 不存在）才向后扩展 —— 保证 O(n)
 */
public int longestConsecutive(int[] nums) {
    Set<Integer> set = new HashSet<>();
    for (int x : nums) set.add(x);

    int best = 0;
    for (int x : set) {
        if (!set.contains(x - 1)) {            // ⚠️ 起点判定（去重 O(n²) 的关键）
            int len = 1;
            while (set.contains(x + len)) len++;   // 向后数
            best = Math.max(best, len);
        }
    }
    return best;
}
// 推演 [100,4,200,1,3,2]：
//   100：起点（99 不在）→ 长度 1
//   4：起点 → 4,5? 没有 → 1
//   200：起点 → 1
//   1：起点（0 不在）→ 1,2,3,4 → 长度 4 ✓
//   3：不是起点（2 在）→ 跳过
//   → 答案 4 ✓
// ⚠️ 复杂度论证：外层每个元素一次；内层只有"起点"会扩展，
//   总扩展次数 = 最长连续段的总长 ≤ n → O(n)
```

## 7. 1. 两数之和：哈希应用的元问题

### 7.1 题目与思路

```
找两个数之和为 target（返回下标）
哈希解法：边遍历边查"补数"（target - x）
⚠️ 这是哈希"查找历史"思想的元问题——衍生出 15/18/454/1 家族
```

### 7.2 完整代码

```java
/**
 * LeetCode 1. 两数之和
 * ⚠️ 一边插入一边查询：每个元素只需查一次历史
 */
public int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> seen = new HashMap<>();   // 值 → 下标
    for (int i = 0; i < nums.length; i++) {
        int need = target - nums[i];
        if (seen.containsKey(need)) {
            return new int[]{seen.get(need), i};    // ⚠️ 先查后插
        }
        seen.put(nums[i], i);                       // 记录历史
    }
    return new int[]{-1, -1};
}
// 推演 [2,7,11,15], target=9：
//   i=0：need=7 无 → 记 {2:0}
//   i=1：need=7 有 → 返回 [0,1] ✓
// ⚠️ 为什么"先查后插"：防止同一元素用两次
//   （target=4 且 nums=[2,2]：先插后查会返回 [0,0] ✗）
// ⚠️ 衍生：3Sum（排序+双指针）、4Sum、454 四数相加（哈希分组）
```

> 🎯 **元问题价值**："查历史"模式（哈希存已见元素）是哈希应用的第一范式——两数之和、最长连续序列、前缀和（560 子数组和）、可见性栈题都源于此。

## 8. 哈希设计方法论总结

### 8.1 哈希设计四步框架

```
① 定哈希函数：均匀（质数取模/位运算）+ 避免退化
② 定冲突方案：链地址（增删频繁）vs 开放寻址（内存紧凑）
③ 定负载控制：初始容量 n/0.75、负载因子 0.75、扩容策略
④ 定键设计：同义归一（排序/计数 key）、值→下标映射

⚠️ 设计题（705/706/380/146）共同套路：
  哈希定位 + 另一结构做特性（链表保序、数组随机、堆取最值）
```

### 8.2 题型模板速查

| 题型 | 核心手法 | 代表题 |
|------|---------|--------|
| 手写哈希结构 | 链地址 + 取模 + 扩容 | 705、706 |
| 编码与映射 | 62 进制 / 双向映射 | 535 |
| 复合结构 | 哈希 + 数组（尾部交换） | 380 |
| 键设计 | 归一化 key | 49 |
| 集合应用 | 起点判定 O(n) | 128 |
| 查历史 | 补数查找 | 1、560 |

### 8.3 自测清单

```
□ 哈希函数均匀（避免固定值/小值域）？
□ 扩容触发与重哈希正确（size 重置）？
□ 删除时指针维护正确（头删/尾删/中间删）？
□ 键设计"同义必同键"（49 排序/计数）？
□ 先查后插（防重复使用）？
□ 起点判定（128 防 O(n²)）？
□ 复杂度说清均摊 O(1) 与最坏 O(n)？
```

---

> 🎯 **核心要点**：哈希设计题 = **哈希函数**（均匀）+ **冲突处理**（链地址/开放寻址）+ **复合结构**（哈希定位、别管特性）。705/706 是手工复刻 HashMap；380/146 是"哈希+数组/链表"的复合结构；49/128/1 是哈希键设计与集合应用的三种范式。
