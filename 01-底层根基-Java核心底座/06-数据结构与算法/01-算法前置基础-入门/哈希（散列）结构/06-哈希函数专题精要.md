## 1. 核心概念

### 1.1 哈希函数的目标

> 哈希函数：把任意键映射到固定范围下标。三个要求——**确定性**（同键同值）、**均匀性**（分布均匀）、**高效性**（O(1) 计算）。

```text
好的哈希 vs 差的哈希：
  均匀 → 冲突少 → 查找 O(1)
  聚集（不均匀）→ 冲突多 → 退化 O(n)

常见哈希方法：
  质数取模：hash = key % p（p 质数）
  乘法散列：floor((key×φ % 1) × m)（φ≈0.618）
  字符串哈希：Σ s[i] × base^i（base=31/131）
```

### 1.2 冲突解决（核心考点）

```text
① 链地址法（拉链）：冲突挂链表
   Java HashMap 采用；链表 >8 转红黑树

② 开放定址：冲突找下一个空位
   线性探测 i+1、i+2...（易聚集）
   二次探测 i+1²、i+2²...（ThreadLocal 用）

③ 再哈希：换哈希函数重算

负载因子：元素数/容量，Java 默认 0.75
  超阈值 → 扩容 + 全部 rehash
```

### 1.3 哈希 vs 平衡树

```text
哈希：O(1) 查找，无序，不支持范围
红黑树：O(log n) 查找，有序，支持范围

选型：只要精确查找 → 哈希
     需要有序/范围 → TreeMap
     ⚠️ 哈希的局限（面试必答）：
       无序、空间大、范围查询差
```

## 2. 完整代码模板

### 2.1 705. 设计哈希集合（链地址法）

```java
/**
 * LeetCode 705. 设计哈希集合（链地址法实现）
 */
class MyHashSet {
    private static final int SIZE = 1000;      // 桶数
    private List<Integer>[] buckets;

    public MyHashSet() {
        buckets = new List[SIZE];
    }

    private int hash(int key) {
        return key % SIZE;                     // 质数取模
    }

    public void add(int key) {
        int idx = hash(key);
        if (buckets[idx] == null) {
            buckets[idx] = new ArrayList<>();
        }
        if (!buckets[idx].contains(key)) {     // 冲突 → 链上追加
            buckets[idx].add(key);
        }
    }

    public void remove(int key) {
        int idx = hash(key);
        if (buckets[idx] != null) {
            buckets[idx].remove(Integer.valueOf(key));
        }
    }

    public boolean contains(int key) {
        int idx = hash(key);
        return buckets[idx] != null
            && buckets[idx].contains(key);
    }
}
// 平均 O(1)；最坏 O(n)（全部冲突到一个桶）
// ⚠️ 桶用链表（LinkedList）更标准，ArrayList 可读性更好
```

### 2.2 535. TinyURL 编码

```java
/**
 * LeetCode 535. TinyURL 的加密与解密
 * 短链：id → 62 进制编码（数字 + 大小写字母）
 */
public class Codec {
    private static final String BASE62 =
        "0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ";
    private Map<String, String> shortToLong = new HashMap<>();
    private Map<String, String> longToShort = new HashMap<>();
    private int id = 0;
    private static final String PREFIX = "http://tinyurl.com/";

    public String encode(String longUrl) {
        if (longToShort.containsKey(longUrl)) {
            return PREFIX + longToShort.get(longUrl);
        }
        String shortUrl = toBase62(id++);      // 自增 id → 62 进制
        shortToLong.put(shortUrl, longUrl);
        longToShort.put(longUrl, shortUrl);
        return PREFIX + shortUrl;
    }

    public String decode(String shortUrl) {
        return shortToLong.get(shortUrl.substring(PREFIX.length()));
    }

    // 十进制 → 62 进制
    private String toBase62(int num) {
        StringBuilder sb = new StringBuilder();
        while (num > 0) {
            sb.append(BASE62.charAt(num % 62));
            num /= 62;
        }
        return sb.reverse().toString();
    }
}
// 10 亿个 URL 只需 6 位 62 进制（62⁶ ≈ 5.6×10¹⁰）
```

### 2.3 自定义哈希（工程思维）

```java
/**
 * 自定义对象哈希设计：
 * 必须同时重写 hashCode + equals！
 */
class Point {
    int x, y;

    @Override
    public int hashCode() {
        // ⚠️ 用质数参与运算减少冲突
        return 31 * x + y;
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Point)) return false;
        Point p = (Point) o;
        return x == p.x && y == p.y;
    }
}
// ⚠️ 经典错误：只重写 equals（哈希不同桶 → 判重失效）
//   equals 相等 → hashCode 必须相等（反向不成立）
```

## 3. HashMap 底层详解

### 3.1 JDK 8 数据结构

```text
HashMap = 数组 + 链表 + 红黑树

  数组（Node<K,V>[] table）
  ┌──┬──┬──┬──┬──┬──┐
  │  │N1│  │  │N2│  │    链表 → 红黑树（>8 时）
  └──┴─┬┴──┴──┴─┬┴──┘
       N1.next  N2.next
        ↓        ↓
       N3       N4

关键参数：
  容量 16（2 的幂 → 位运算取模）
  负载因子 0.75（扩容阈值）
  树化阈值 8（链表过长转红黑树）
  反树化 6（红黑树节点少转回链表）
```

### 3.2 put 流程（面试必背）

```text
put(key, value) 流程：
  ① 计算哈希：hash = key.hashCode() ^ (hash >>> 16)
     （高位异或低位 → 分布更均匀）
  ② 定位槽位：index = hash & (cap - 1)
     （容量 2 的幂 → 位运算替代取模）
  ③ 槽位为空 → 直接插入
  ④ 槽位有链表 → 遍历：
       键相同 → 覆盖旧值返回旧值
       键不同 → 尾插；链表 > 8 且容量 ≥ 64 → 转红黑树
  ⑤ 插入后 size > 容量×0.75 → resize()（扩容 + rehash）

⚠️ 扩容为什么 rehash？
  容量变化 → 取模除数变化 → 旧位置失效
  全部重新计算位置（O(n) 一次，均摊 O(1)）
```

### 3.3 为什么树化阈值是 8？

```text
泊松分布：负载因子 0.75 时
  链表长度达到 8 的概率 ≈ 0.00000006（六千万分之一）
  → 正常情况链表不会很长
  → 8 是"极低概率才会触发"的兜底阈值
  → 防御哈希攻击（恶意构造同哈希键）

⚠️ 面试必答：
  "树化是防攻击的兜底——正常负载下
   链表到 8 的概率约六千万分之一。"
```

## 4. 哈希函数的设计

### 4.1 好哈希的标准

```text
① 确定性：同键必同值（必须）
② 均匀性：键均匀分布（减少冲突）
③ 高效性：计算 O(1)
④ 雪崩性：输入小变化 → 输出大变化（进阶）

⚠️ 常见设计：
  质数取模（简单有效）
  乘法散列（黄金分割 0.618）
  字符串多项式（base 幂次）
```

### 4.2 Java 的哈希设计

```text
String.hashCode()：
  s[0]*31^(n-1) + s[1]*31^(n-2) + ... + s[n-1]
  为什么 31？奇素数 + 乘法可优化为移位减
  （31*x = (x<<5) - x）

HashMap 的扰动函数：
  hash = h ^ (h >>> 16)
  目的：高位参与低位（容量小时高位被丢弃）
  → 分布更均匀

⚠️ 面试加分：
  "31 是奇素数，乘法可被 JVM 优化为
   移位减，且素数减少碰撞。"
```

### 4.3 哈希攻击与防御

```text
攻击方式：构造大量同哈希的键 → 全部冲突
  → 链表退化 O(n) → 服务变慢

防御：
  ① 红黑树化（Java：>8 转树 O(log n)）
  ② 随机种子（字符串哈希随机化）
  ③ 加盐（分布式场景）

⚠️ 面试表达：
  "Java 用红黑树兜底 + 字符串随机种子
   双重防御哈希攻击。"
```

## 6. 面试要点与追问

### 6.1 面试话术模板

```text
"哈希冲突用链地址法：每个桶挂链表，
 查找时先哈希定位桶再遍历链表。
 Java HashMap 在链表超过 8 且容量 ≥64 时
 转红黑树，最坏 O(log n)。
 负载因子 0.75 触发扩容并重新哈希。
 扩容必须 rehash——容量变了取模除数变了。"
```

### 6.2 高频追问 TOP 8

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | 冲突三种解决？ | 链地址（HashMap）、开放定址（ThreadLocal）、再哈希 |
| 2 | 为什么负载因子 0.75？ | 空间时间平衡；泊松分布验证冲突可控 |
| 3 | 扩容为什么 rehash？ | 容量变 → 取模除数变 → 旧位置失效 |
| 4 | 为什么 2 的幂容量？ | hash & (cap-1) 位运算替代取模（更快） |
| 5 | 为什么树化 8？ | 概率六千万分之一；防哈希攻击兜底 |
| 6 | hashCode/equals 关系？ | equals 相等 → hashCode 必等；反向不成立 |
| 7 | 扰动函数？ | h ^ (h>>>16) 高位参与低位（分布均匀） |
| 8 | 哈希攻击防御？ | 红黑树兜底 + 随机种子 |

### 6.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| 只重写 equals | 判重失效 | hashCode+equals 都重写 |
| 桶忘初始化 | 空指针 | add 时 new |
| 移除用 int | 按下标删 | Integer.valueOf(key) |
| 可变对象做 key | 查找失败 | 不可变键 |
| 容量非 2 幂 | 位运算失效 | 取模或保证 2 幂 |

> 🎯 **核心要点**：哈希函数 = **映射 + 冲突解决 + 扩容**三件事。识别信号："设计哈希表、短链编码、键值映射"。HashMap 底层（链地址/0.75/树化 8/rehash/扰动函数）是 Java 面试必背源码知识；自定义 key 必须同时重写 hashCode+equals。
