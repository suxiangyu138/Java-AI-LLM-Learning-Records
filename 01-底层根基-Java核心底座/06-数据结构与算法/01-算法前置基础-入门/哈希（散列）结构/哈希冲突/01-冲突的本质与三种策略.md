## 1. 冲突的本质：鸽笼原理

**鸽笼原理（Pigeonhole Principle）**：n+1 只鸽子放进 n 个笼子，至少一笼有 ≥2 只。

```text
哈希语境:
  键域（无限/巨大）→ 桶域（有限）
  → 必然有多个键映射到同一桶
  → 冲突不可避免！

例: 10001 个键进 10000 个桶
  → 至少一桶 ≥ 2 个键（鸽笼）
```

| 冲突影响 | 桶长 | 查找 |
|---------|:---:|:---:|
| 无冲突 | 1 | O(1) 完美 |
| 少量冲突 | 2-3 | O(1) 平均 |
| 严重冲突 | n | O(n) 退化 |

> 💡 冲突不可消除只能控制——**「好的函数（01 模块）+ 好的策略（本节）+ 合理的 α」**三管齐下。

## 2. 链地址法

### 2.1 原理与实现

**链地址（Chaining）**：同桶元素用链表串联——Java HashMap 默认方案。

```java
// 链地址法核心（数组 + 链表）
class ChainingHash {
    private static final int M = 16;
    private Node[] buckets = new Node[M];

    static class Node {
        int key;
        String value;
        Node next;
        Node(int key, String value) { this.key = key; this.value = value; }
    }

    void put(int key, String value) {
        int index = key % M;              // ① 定位桶
        Node node = buckets[index];
        while (node != null) {            // ② 链上查重
            if (node.key == key) { node.value = value; return; }
            node = node.next;
        }
        Node first = new Node(key, value);  // ③ 头插
        first.next = buckets[index];
        buckets[index] = first;
    }

    String get(int key) {
        Node node = buckets[key % M];     // 定位 + 链查
        while (node != null) {
            if (node.key == key) return node.value;
            node = node.next;
        }
        return null;
    }
}
```

### 2.2 Java HashMap 的进化（链 → 树）

```text
JDK 7:   纯链表（最坏 O(n)）
JDK 8+:  链表 → 红黑树（桶长 ≥ 8 且容量 ≥ 64）
         红黑树 → 链表（节点 ≤ 6）

树化的双重条件:
  ① 桶长 ≥ 8（泊松概率千万分之六）
  ② 容量 ≥ 64（否则先扩容）
```

| 特性 | 说明 |
|------|------|
| 结构 | 桶数组 + 链表/红黑树 |
| 删除 | 容易（链表删除） |
| 装填因子 | 可 > 1（无死锁风险） |
| 最坏 | 树化后 O(log n) |
| 缓存 | 不友好（指针跳跃） |

## 3. 开放定址法

### 3.1 原理与三种探测

**开放定址（Open Addressing）**：冲突时探测下一个空位——所有元素都在数组内。

```java
// 三种探测序列
// 线性探测:  index = (h(k) + i) % M
// 二次探测:  index = (h(k) + i²) % M
// 双重哈希:  index = (h1(k) + i·h2(k)) % M

// 线性探测插入（概念）
void insert(int key, int value) {
    int i = 0;
    int index;
    do {
        index = (hash(key) + i) % M;      // 探测序列
        if (table[index] == EMPTY) {      // 找到空位
            table[index] = new Entry(key, value);
            return;
        }
        i++;
    } while (i < M);                      // 满则失败
}
```

| 探测方式 | 序列 | 优点 | 缺点 |
|---------|------|------|------|
| 线性 | h+i | 简单、缓存好 | **聚集**（连续占位） |
| 二次 | h+i² | 减少聚集 | 删除难（同线性） |
| 双重 | h1+i·h2 | 最均匀 | 计算两次哈希 |

### 3.2 开放定址的删除问题：墓碑

```text
删除 10 后:
  [3]=10 → [3]=TOMESTONE（墓碑）

为什么不能直接置空？
  探测序列可能被「空位」截断:
  插入 17 探测: 桶3（墓碑）→ 桶4（空）→ 放桶4
  查找 24 探测: 桶3（墓碑）→ 桶4（24）✓
  若桶3直接置空: 查找 24 在桶3 见空 → 提前结束 ✗ 漏找！

→ 删除必须留墓碑，查找跳过墓碑继续
```

| 特性 | 说明 |
|------|------|
| 空间 | 纯数组（无指针） |
| 缓存 | 好（连续） |
| 删除 | 需墓碑（复杂） |
| 装填因子 | **必须 < 1**（满则死循环） |
| 工程 | Redis dict 变体、Python dict 混合 |

> ⚠️ 开放定址的硬约束：**装填因子必须 < 1**（如 0.7）——满了探测会死循环；这是它「更省内存但更早扩容」的权衡。

## 4. 再哈希

**再哈希（Rehashing）**：第一个哈希函数冲突时，用第二个函数计算。

```java
// 再哈希：多级哈希函数
int rehash(int key, int attempt) {
    switch (attempt) {
        case 0: return hash1(key);   // 第一选择
        case 1: return hash2(key);   // 冲突 → 换函数
        default: return hash3(key);
    }
}
```

| 特性 | 说明 |
|------|------|
| 优点 | 不同函数分布互补 |
| 缺点 | 多次哈希计算（变慢） |
| 适用 | 双重哈希是开放定址的推荐实现 |
| 工程 | 很少单独使用（常作探测策略） |

> 💡 再哈希与「扩容重哈希（rehash）」是两回事——前者是冲突策略（换函数），后者是扩容时全部键重新定位（[查找过程](../查找过程/01-哈希查找的完整流程.md) 4 节）。

## 5. 三策略对比与选型

| 维度 | 链地址 | 开放定址 | 再哈希 |
|------|:---:|:---:|:---:|
| 结构 | 桶 + 链表/树 | 纯数组 | 多函数 |
| 删除 | ✅ 容易 | ⚠️ 墓碑 | — |
| 装填因子 | 可 > 1 | **必须 < 1** | — |
| 缓存 | ❌ | ✅ | — |
| 最坏 | O(n)/O(log n) 树化 | O(n) | O(n) |
| 工程 | Java HashMap | Redis/Python | 探测策略 |

**工程选型**：

```text
Java HashMap     → 链地址 + 树化（写多场景）
Redis dict       → 链地址 + 渐进式 rehash
Python dict      → 开放定址（读多缓存友好）
C++ unordered_map → 链地址（桶 + 链表）
Go map           → 桶内 8 槽（开放定址变体）
```

**面试追问**：

| 追问 | 答题要点 |
|------|---------|
| 为什么 Java 用链地址？ | 实现简单、删除容易、α 可 >1 |
| 为什么 Redis 用链地址？ | 渐进式 rehash 不阻塞 |
| 开放定址为什么删不掉？ | 探测链会被空位截断（墓碑） |
| 什么时候开放定址更好？ | 读多写少、α 低、缓存敏感 |
| 树化的两个条件？ | 桶长 ≥ 8 且容量 ≥ 64 |
| 再哈希和扩容 rehash 区别？ | 换函数 vs 全部重定位 |

> 🎯 **核心要点**：本节验收——鸽笼原理解释冲突必然；链地址（Java）与开放定址（Redis/Python）的实现与权衡；线性/二次/双重探测的差异；墓碑机制（开放定址删除）；装填因子约束（链地址可 >1、定址必须 <1）；「写多链地址、读多定址」的选型认知。
