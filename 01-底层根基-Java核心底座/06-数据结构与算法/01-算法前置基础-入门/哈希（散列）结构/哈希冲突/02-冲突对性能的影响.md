## 1. 平均查找长度 ASL

**平均查找长度（Average Search Length）**：查找一个键的平均比较次数。

```text
链地址法的 ASL:
  成功: ASL ≈ 1 + α/2
  失败: ASL ≈ 1 + α

α = 装填因子 = n/m（键数/桶数）

例: α = 0.75（HashMap 默认）:
  成功 ≈ 1.375 次（几乎一次命中）
  失败 ≈ 1.75 次

α = 1.0:  成功 ≈ 1.5，失败 ≈ 2.0
α = 2.0:  成功 ≈ 2.0，失败 ≈ 3.0（仍可接受）
```

| α | 成功 ASL | 失败 ASL | 状态 |
|:---:|:---:|:---:|:---:|
| 0.5 | 1.25 | 1.5 | 宽松 |
| 0.75 | 1.375 | 1.75 | **工程默认** |
| 1.0 | 1.5 | 2.0 | 临界 |
| 2.0 | 2.0 | 3.0 | 偏高（应扩容） |

> 🎯 **性能直觉**：α 在 0.5-1 之间，哈希查找「几乎一次比较」——这就是 O(1) 的工程含义；α 翻倍 ASL 线性增长（不是爆炸），但 α 失控（恶意冲突）才是指数级退化。

## 2. 冲突的三种程度

### 2.1 程度对比

| 程度 | 桶长分布 | 查找 | 原因 |
|------|---------|:---:|------|
| 正常 | 泊松（桶长 0-3） | O(1) | 均匀哈希 |
| 偏斜 | 少数长链 | O(1) 平均 | 键模式聚集 |
| 恶意 | 全同桶 | **O(n)** | HashDoS |

### 2.2 泊松分布的意义

```text
均匀哈希下桶长服从泊松分布:
  P(桶长 = k) = (α^k · e^(-α)) / k!

α = 0.75 时:
  P(0) ≈ 0.47
  P(1) ≈ 0.35
  P(2) ≈ 0.13
  P(3) ≈ 0.03
  P(≥8) ≈ 0.00000006（千万分之六）

→ 正常数据几乎不可能出现长链
→ 出现长链 = 哈希失效/恶意 → 树化兜底
```

> 💡 泊松论证是「树化阈值 8」的数学依据——正常哈希下长链是「不可能事件」，出现即异常，用红黑树把最坏从 O(n) 拉回 O(log n)。

## 3. 树化的性能兜底

```java
// HashMap 树化（JDK 8+ 概念）
// 触发: 桶长 ≥ 8 且容量 ≥ 64
// 效果: 最坏 O(n) → O(log n)

// 树化后的查找（红黑树）
// 对比:
//   链表 10000 节点: 最坏 10000 次比较（O(n)）
//   红黑树 10000 节点: 最坏 14 次比较（O(log n)）
//   → 树化把恶意冲突的伤害降了 700 倍！
```

| 桶长 | 链表查找 | 树查找 | 树化收益 |
|:---:|:---:|:---:|:---:|
| 8 | 8 次 | 3 次 | ~2.7× |
| 64 | 64 次 | 6 次 | ~10× |
| 1000 | 1000 次 | 10 次 | ~100× |
| 10000 | 10000 次 | 14 次 | **~700×** |

> ⚠️ 树化不是常态优化而是**最坏兜底**——正常数据链表 ≤ 3，树化几乎不触发；触发了说明哈希失效，红黑树把攻击伤害从「灾难」降为「可容忍」。

## 4. 冲突 → 退化的完整链路

```text
完整链路:

哈希函数失效/恶意
    ↓
大量键映射同桶
    ↓
桶长爆炸（n 个）
    ↓
查找 O(n)（链表遍历）
    ↓
CPU 耗尽（HashDoS 攻击）

防御节点:
  ① 随机种子（破坏攻击者预判）
  ② 树化（O(n) → O(log n)）
  ③ 扩容（α 回落）
  ④ 布隆前置（快速拒绝）
  ⑤ 限流（频率控制）
```

```text
数值演示（10 万键恶意冲突）:
  无防御:   100000 次比较/查询 → 服务器瞬间打满
  树化:    17 次比较/查询（log2 100000）→ 攻击失效
  布隆:    先布隆拒绝 99.9% 恶意键 → 树内几乎无压力
```

> 🎯 **攻击防御的层次**：树化是「被动兜底」（最坏有界），布隆+限流是「主动拦截」（把恶意键挡在哈希表外）——生产环境两者都要。

## 5. 冲突管理实践

| 实践 | 做法 | 效果 |
|------|------|------|
| 合理 α | 默认 0.75（可调） | ASL 保持 ~1.4 |
| 预分配容量 | 避免扩容抖动 | 稳定桶长 |
| 自定义哈希 | 对象键均衡分布 | 防聚集 |
| 输入校验 | 长度/频率限制 | 防长键攻击 |
| 监控桶长 | 定期统计 | 早期发现异常 |
| 树化参数 | 8/64 默认（可调） | 最坏兜底 |

```java
// 自定义哈希优化（防聚集示例）
class UserKey {
    String name;
    int age;

    @Override
    public int hashCode() {
        // 31 倍组合（避免只依赖一个字段）
        return 31 * name.hashCode() + age;
        // 反例: 只用 name.hashCode() → 同姓名聚集
    }
}
```

**面试追问**：

| 追问 | 答题要点 |
|------|---------|
| ASL 公式？ | 链地址成功 ≈ 1 + α/2 |
| α 影响冲突吗？ | 正比——α 大冲突多 |
| 树化是优化还是兜底？ | **兜底**（恶意哈希防御） |
| 树化收益量级？ | 最坏 O(n) → O(log n)（万级 700×） |
| 防御层次？ | 树化被动兜底 + 布隆/限流主动拦截 |
| 什么时候手动调 α？ | 读多调低（省内存换速度）、写多可高 |

### 5.1 冲突监控与调优

```text
监控指标:
  桶长分布（最大桶长 / 平均桶长）
  装填因子实时值
  树化次数（异常信号！）

调优动作:
  最大桶长 > 8 且非恶意 → 检查哈希函数（可能聚集）
  树化频繁 → 大概率 HashDoS，立即布隆+限流
  α > 0.75 持续 → 预分配更大容量
```

### 5.2 冲突管理速查卡

| 场景 | 动作 |
|------|------|
| 正常冲突（桶长 ≤ 3） | 无需处理 |
| 桶长偏高（4-8） | 检查哈希函数 |
| 树化触发（≥8 且 ≥64） | 警惕攻击 |
| 频繁扩容 | 预分配容量 |
| 恶意冲突 | 布隆 + 限流 |

| 一句话总结 | 冲突决定哈希性能：均匀时 O(1)（ASL≈1.4）、恶意时 O(n)——树化兜底 + 主动防御双保险 |

> 🎯 **核心要点**：本节验收——ASL ≈ 1+α/2 的推导与直觉；泊松分布论证（P(≥8) = 千万分之六）；树化的「最坏兜底」定位（O(n)→O(log n)，万级 700× 收益）；冲突→退化的完整链路与五层防御；「正常哈希下长链是不可能事件，出现即异常」的工程判断。
