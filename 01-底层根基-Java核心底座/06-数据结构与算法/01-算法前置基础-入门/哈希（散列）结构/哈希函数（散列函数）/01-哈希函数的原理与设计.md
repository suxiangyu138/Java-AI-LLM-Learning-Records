## 1. 哈希函数的定义

**哈希函数（Hash Function）**：把任意长度的输入映射为固定长度输出（散列值）的函数。

```text
h: key → 固定长度散列值

h("apple")  = 0x4a7b...
h("banana") = 0xc3f1...
h(42)       = 42（直接定址）

哈希表用途: h(key) → 桶下标（index = h(key) % m）
```

| 维度 | 说明 |
|------|------|
| 输入域 | 任意（字符串/数字/对象） |
| 输出域 | 固定（如 32 位 int） |
| 时间复杂度 | O(1)（常数次运算） |
| 作用 | 空间换时间（O(1) 查找） |

> 💡 哈希函数是哈希表 O(1) 的**数学前提**——查找只需算一次哈希 + 一次定位；若哈希慢（如加密哈希），O(1) 就名存实亡。

## 2. 四大性质

| 性质 | 含义 | 违反后果 |
|------|------|---------|
| **确定性** | 相同输入必得相同输出 | 查找失效（同键不同桶） |
| **均匀性** | 输出均匀分布 | 聚集 → 桶长失衡 → 退化 O(n) |
| **高效性** | O(1) 计算 | 查找变慢 |
| **单向性** | 由输出难推输入 | （加密哈希要求；工程哈希可弱） |

**均匀性的量化**：

```text
n 个键分布到 m 个桶:
  完全均匀: 每桶 n/m 个
  随机哈希: 桶长服从泊松分布
    P(桶长 ≥ k) ≈ (n/(m·k))^k

例: n/m = 0.75（装填因子 α）时
    P(桶长 ≥ 8) ≈ 0.00000006（千万分之六）
    → 这就是 HashMap 树化阈值 8 的数学来源！
```

> 🎯 **面试杀手锏**：HashMap 树化阈值 8 的泊松分布论证——正常哈希下链表 ≥ 8 的概率是千万分之六，达到 8 说明哈希失效（恶意/设计缺陷），此时树化兜底。

## 3. 质数取模

**除法散列（Division Method）**：`h(k) = k mod m`——最简单、最常用。

```java
// 质数取模
int hash(int key, int m) {
    return key % m;              // m 选质数
}
```

**为什么 m 选质数**：

```text
反例: m = 100，键 k = 100, 200, 300...
  → 全部映射到桶 0（k % 100 = 0）
  → 灾难性聚集！

选 m = 97（质数）:
  → 100%97=3, 200%97=6, 300%97=9
  → 均匀分散 ✓

原理: 质数不与常见步长（10 的幂）共享因子
  → 减少「模式化输入」的聚集
```

| 要点 | 说明 |
|------|------|
| 适用 | 整数键、直接定址 |
| m 选择 | 质数（远离 2 的幂） |
| 缺点 | 键的分布模式可能影响均匀性 |
| 工程 | HashMap 扩容后 `(n-1) & hash`（2 的幂优化） |

> ⚠️ 注意：Java HashMap 用 `(n-1) & hash`（位与代替取模）——因为 n 是 2 的幂；**取模与位与等价性依赖 n 为 2 的幂**，这是「2 的幂容量」设计的原因（配合扰动函数补足低位随机性）。

## 4. 乘法散列

**乘法散列（Multiplication Method）**：用黄金比例分数乘键取小数部分——不依赖 m 的取值。

```text
公式: h(k) = ⌊m · (k·φ mod 1)⌋

φ = (√5 - 1) / 2 ≈ 0.618（黄金比例倒数）

例: k=61, m=100
  k·φ = 37.698
  k·φ mod 1 = 0.698
  h = ⌊100 × 0.698⌋ = 69

性质: 对连续整数键，输出分布极其均匀
```

```java
// 乘法散列实现
int multiplicationHash(int key, int m) {
    double goldenRatio = (Math.sqrt(5) - 1) / 2;   // ≈ 0.618
    double frac = (key * goldenRatio) % 1.0;       // 小数部分
    return (int) (m * frac);
}
```

| 对比 | 质数取模 | 乘法散列 |
|------|:---:|:---:|
| 公式 | k mod m | ⌊m(kφ mod 1)⌋ |
| m 依赖 | 需质数 | **任意 m 都好** |
| 均匀性 | 依赖键模式 | 对连续键极好 |
| 适用 | 整数键 | 通用/竞赛 |

> 💡 乘法散列的优雅之处：**不依赖 m 的选择**——m 取任意值都能保持良好分布；Splay/字符串哈希的经典选择。

## 5. 一致性哈希

**一致性哈希（Consistent Hashing）**：分布式缓存节点分配——节点增减时**最小化键迁移**。

```text
环形哈希空间 [0, 2^32):
  节点（服务器）哈希后放在环上
  键哈希后顺时针找第一个节点

  3 台服务器 (S1, S2, S3):
        S1
      /    \
   键k2   键k1
    |      |
    S3 ---- S2

节点 S2 宕机:
  只迁移 S2 环段内的键（约 1/3）
  其他键不受影响 ✓
```

| 特性 | 说明 |
|------|------|
| 核心 | 哈希环 + 顺时针寻节点 |
| 增减节点 | **只迁移 1/n 的键** |
| 虚拟节点 | 每物理节点多个虚拟点（平衡负载） |
| 应用 | Redis 集群、负载均衡、CDN |

```java
// 一致性哈希骨架（TreeMap 实现）
class ConsistentHash {
    private final TreeMap<Integer, String> ring = new TreeMap<>();  // hash → 节点

    void addNode(String node) {
        for (int i = 0; i < 160; i++) {            // 160 个虚拟节点
            int hash = (node + "#" + i).hashCode();
            ring.put(hash, node);
        }
    }

    String getNode(String key) {
        int hash = key.hashCode();
        Integer ceiling = ring.ceilingKey(hash);   // 顺时针第一个
        if (ceiling == null) ceiling = ring.firstKey();  // 环回绕
        return ring.get(ceiling);
    }
}
```

> 🎯 **面试必答**：一致性哈希解决「节点增减时的雪崩迁移」——普通取模（hash % n）在 n 变化时几乎全部键迁移；一致性哈希只迁移 1/n；虚拟节点解决「节点分布不均」。

## 6. Java hashCode 设计

### 6.1 String 的 31 倍

```java
// String.hashCode 源码逻辑
int hash = 0;
for (char c : value) {
    hash = 31 * hash + c;          // 31 倍累加
}
```

**为什么 31**：

```text
① 31 是质数 → 减少碰撞
② 31 = 32 - 1 → JVM 优化为移位:
    31 * hash = (hash << 5) - hash   ← 一次移位 + 一次减法
  → 乘法便宜（现代 CPU 也快）
③ 奇质数避免「哈希值被 2 整除」的模式

经验值: 31、33、37 等奇质数是经典选择
```

### 6.2 自定义对象 hashCode

```java
// 自定义 hashCode 规范（31 倍 + equals 配套）
class User {
    String name;
    int age;

    @Override
    public int hashCode() {
        int result = 17;                       // 初始非零值
        result = 31 * result + name.hashCode();
        result = 31 * result + age;
        return result;
    }

    @Override
    public boolean equals(Object o) {
        // 约定: equals 相等 → hashCode 必相等
        // 重写 equals 必须重写 hashCode（契约红线）
    }
}
```

| 契约 | 说明 |
|------|------|
| equals 相等 | → hashCode 必相等（必须） |
| hashCode 相等 | → equals 不一定相等（允许碰撞） |
| 违反后果 | HashMap 查找失效（同键不同桶） |
| 字段选择 | 参与 equals 的字段都要参与 hashCode |

> ⚠️ **工程红线**：重写 equals 必须重写 hashCode——否则 HashMap/HashSet 中「相等的对象」落到不同桶，contains 失效（经典面试陷阱）。

> 🎯 **核心要点**：本节验收——四性质默写（确定性/均匀性/高效性/单向性）；质数取模（m 选质数防聚集）与乘法散列（黄金比例）两公式；一致性哈希（环 + 虚拟节点 + 最小迁移）；String 31 倍（质数 + 移位优化）；自定义 hashCode 的 31 倍模板与 equals 契约；HashMap 树化 8 的泊松论证（n/m=0.75 时千万分之六）。冲突与防御见 02 模块。
