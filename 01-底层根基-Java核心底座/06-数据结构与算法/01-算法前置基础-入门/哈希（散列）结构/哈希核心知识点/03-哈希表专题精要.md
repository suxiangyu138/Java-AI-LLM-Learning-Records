## 1. 核心概念

### 1.1 哈希表元模式

> 哈希表：键 → 位置的 O(1) 映射。核心价值：**用哈希查找替换内层循环**，把 O(n²) 暴力降到 O(n)。

```text
元模式（面试必须脱口而出）：
  "每当需要'检查某元素是否存在/计数/找补数'时，
   用哈希表查找替换内层循环"

五大题型：
  找补数（1/167）｜判重（217）
  分组映射（49）｜连续查询（128）
  前缀和统计（560）

⚠️ 面试第一句：
"暴力是 O(n²) 的双重循环，内层在做查找，
 用哈希表 O(1) 替代 → 总 O(n)。"
```

### 1.2 识别信号

```text
"找两数/补数" → 哈希（1）
"是否存在/判重" → Set（217）
"分组/映射" → 哈希键（49）
"计数/频次" → 哈希（347）
"连续序列" → Set + 剪枝（128）

⚠️ 以空间换时间的代表：
  牺牲 O(n) 空间 → 换取 O(n²)→O(n) 时间
```

### 1.3 为什么是面试之王

```text
① 元模式适用面广（查找/计数/分组）
② 以空间换时间（最常用优化手段）
③ Hot 100 覆盖率高（数组/字符串题大量使用）

⚠️ 局限性（面试必答）：
  无序（无法有序遍历）
  空间开销大
  不支持范围查询（用 TreeMap）
```

## 2. 完整代码模板

### 2.1 1. 两数之和（母题）

```java
/**
 * LeetCode 1. 两数之和（面试第一题）
 * 关键细节：先检查再插入（防自匹配）
 */
public int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> map = new HashMap<>();   // 值 → 下标

    for (int i = 0; i < nums.length; i++) {
        int complement = target - nums[i];          // 补数
        if (map.containsKey(complement)) {
            return new int[]{map.get(complement), i};
        }
        map.put(nums[i], i);                        // ⚠️ 先查后插！
    }
    return new int[0];
}
// 推演 nums=[3,3], target=6：
//   i=0：补数 3 不在 map（还没存自己）→ 存 {3:0}
//   i=1：补数 3 在 map → 返回 [0,1] ✓
// ⚠️ 先插后查会返回 [0,0]（自匹配）→ 必须先查后插
```

### 2.2 49. 字母异位词分组（规范键）

```java
/**
 * LeetCode 49. 字母异位词分组
 * 核心：找"规范键"（异位词共享的标识）
 */
public List<List<String>> groupAnagrams(String[] strs) {
    Map<String, List<String>> map = new HashMap<>();

    for (String s : strs) {
        // 计数键：26 位字符计数转字符串
        int[] count = new int[26];
        for (char c : s.toCharArray()) count[c - 'a']++;

        StringBuilder key = new StringBuilder();
        for (int x : count) key.append('#').append(x);
        // "eat" → "#1#0#0...#1#1"；"tea" 同键 → 同组

        map.computeIfAbsent(key.toString(),
            k -> new ArrayList<>()).add(s);
    }
    return new ArrayList<>(map.values());
}
// 两种键：排序键（O(k log k)）/ 计数键（O(k)）★ 更优
// ⚠️ 面试讲两种方案并说明计数键更优 = 加分
```

### 2.3 128. 最长连续序列（起点剪枝）

```java
/**
 * LeetCode 128. 最长连续序列（O(n)！）
 * 核心优化：起点剪枝——只有"没有前驱"的数才作为起点
 */
public int longestConsecutive(int[] nums) {
    Set<Integer> set = new HashSet<>();
    for (int x : nums) set.add(x);

    int maxLen = 0;
    for (int x : set) {                       // ⚠️ 遍历 set（去重后）
        if (!set.contains(x - 1)) {           // 剪枝：不是起点就跳过
            int cur = x, len = 1;
            while (set.contains(cur + 1)) {   // 向后扩展
                cur++;
                len++;
            }
            maxLen = Math.max(maxLen, len);
        }
    }
    return maxLen;
}
// 为什么 O(n)？
//   每个数最多被统计一次（只有起点开始统计）
//   朴素做法：对每个数都 while → O(n²)
// ⚠️ 面试必答："起点剪枝保证每个数只统计一次"
```

## 3. HashMap 底层详解

### 3.1 JDK 8 数据结构

```text
HashMap = 数组 + 链表 + 红黑树

关键参数：
  容量 16（2 的幂 → 位运算取模）
  负载因子 0.75（扩容阈值）
  树化阈值 8（链表过长转红黑树）
  反树化 6（红黑树少转回链表）
  最小树化容量 64

⚠️ 为什么 2 的幂？
  hash & (cap-1) 位运算替代取模（更快）
```

### 3.2 put 流程（面试必背）

```text
put(key, value) 流程：
  ① 计算哈希：hash = key.hashCode() ^ (hash >>> 16)
     （高位异或低位 → 分布更均匀）
  ② 定位槽位：index = hash & (cap - 1)
  ③ 槽位为空 → 直接插入
  ④ 槽位有链表 → 遍历：
       键相同 → 覆盖旧值返回旧值
       键不同 → 尾插；链表 > 8 且容量 ≥ 64 → 转红黑树
  ⑤ 插入后 size > 容量×0.75 → resize()（扩容 + rehash）

⚠️ 扩容为什么 rehash？
  容量变化 → 取模除数变化 → 旧位置失效
  全部重新计算位置（O(n) 一次，均摊 O(1)）
```

### 3.3 关键参数速记

| 参数 | 值 | 追问场景 |
|------|:---:|------|
| 初始容量 | 16 | "为什么 2 的幂？"→ 位运算取模 |
| 负载因子 | 0.75 | "为什么 0.75？"→ 泊松分布最优 |
| 树化阈值 | 8 | "为什么 8？"→ 概率六千万分之一 |
| 反树化 | 6 | "为什么 6？"→ 留缓冲防抖动 |
| 最小树化容量 | 64 | "容量不够？"→ 先扩容不树化 |

### 4.2 560. 和为 K 的子数组

```java
/**
 * LeetCode 560. 和为 K 的子数组（前缀和+哈希）
 * ⚠️ 为什么不用滑动窗口？
 *   含负数 → 扩窗不单调 → 滑窗失效
 */
public int subarraySum(int[] nums, int k) {
    Map<Integer, Integer> prefixCount = new HashMap<>();
    prefixCount.put(0, 1);        // ⚠️ 空前缀和为 0

    int sum = 0, count = 0;
    for (int x : nums) {
        sum += x;
        count += prefixCount.getOrDefault(sum - k, 0);
        prefixCount.put(sum, prefixCount.getOrDefault(sum, 0) + 1);
    }
    return count;
}
// 数学：sum(l,r)=k ⇔ pre[r]-pre[l-1]=k ⇔ 找 pre[l-1]=pre[r]-k
// ⚠️ {0:1} 处理"从开头开始的和为 K 的子数组"
```

### 4.3 哈希表的工程注意

```text
① 自定义 key：hashCode + equals 都重写
② 遍历时修改：用 entrySet 或先收集
③ HashMap vs ConcurrentHashMap：单线程/并发
④ LinkedHashMap：保持插入序（LRU 简易版）

⚠️ 面试表达：
"自定义对象做 key 必须同时重写 hashCode
 和 equals——hashCode 定位桶，equals 桶内比较。"
```

## 6. 面试要点与追问

### 6.1 面试话术模板

```text
"这题暴力是 O(n²) 内层查找，
 用哈希表：Map<值, 下标> 存已遍历元素，
 每步 O(1) 查补数。
 关键细节：先查后插（防自匹配）。
 时间 O(n) 空间 O(n)。
 追问 HashMap 原理：数组+链表+红黑树、
 负载因子 0.75、扩容 rehash。"
```

### 6.2 高频追问 TOP 8

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | 哈希为什么 O(1)？ | 哈希函数映射到数组下标；冲突链均摊 |
| 2 | 冲突怎么解决？ | 链地址（HashMap）/开放定址（ThreadLocal）/再哈希 |
| 3 | 为什么树化 8？ | 泊松分布概率六千万分之一（防攻击兜底） |
| 4 | 扩容为什么 rehash？ | 容量变 → 取模除数变 → 旧位置失效 |
| 5 | 扰动函数？ | h ^ (h>>>16) 高位参与低位（分布均匀） |
| 6 | 自定义 key？ | hashCode+equals 都重写（缺一不可） |
| 7 | 与 TreeMap 区别？ | 哈希无序 O(1)；TreeMap 有序 O(log n) |
| 8 | 哈希局限？ | 无序/空间大/范围查询差 |

### 6.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| 先插后查 | 自匹配 [0,0] | 先查后插 |
| getOrDefault 忘 +1 | 计数覆盖 | +1 或 merge |
| 起点剪枝遗漏 | O(n²) | !contains(x-1) |
| 忘 {0:1} | 漏子数组 | 初始化空前缀 |
| 只重写 equals | 判重失效 | hashCode+equals |

> 🎯 **核心要点**：哈希表 = **元模式**（替换内层循环）+ **HashMap 原理**（16/0.75/8/红黑树/rehash）。两数之和（先查后插）、异位词（规范键）、连续序列（起点剪枝）、前缀和（{0:1}）四个细节是面试必考点。
