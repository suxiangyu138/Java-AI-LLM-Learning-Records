## 1. HashMap 源码深度剖析

### 1.1 JDK 8 的数据结构

```text
HashMap = 数组 + 链表 + 红黑树

  数组（Node<K,V>[] table）
  ┌──┬──┬──┬──┬──┬──┐
  │  │N1│  │  │N2│  │    链表 → 红黑树（>8 时）
  └──┴─┬┴──┴──┴─┬┴──┘
       N1.next  N2.next
        ↓        ↓
       N3       N4

节点：
  Node：hash, key, value, next（链表）
  TreeNode：红黑树节点（继承 Node）

⚠️ 关键参数：
  容量 16（2 的幂）
  负载因子 0.75
  树化阈值 8 / 反树化 6 / 最小树化容量 64
```

### 1.2 put 流程（面试必背）

```text
put(key, value) 流程：
  ① 计算哈希：hash = key.hashCode() ^ (hash >>> 16)
     （扰动函数：高位异或低位 → 分布更均匀）
  ② 定位槽位：index = hash & (cap - 1)
     （容量 2 的幂 → 位运算替代取模，更快）
  ③ 槽位为空 → 直接插入
  ④ 槽位有链表 → 遍历：
       键相同 → 覆盖旧值返回旧值
       键不同 → 尾插；链表 > 8 且容量 ≥ 64 → 转红黑树
  ⑤ 插入后 size > 容量×0.75 → resize()（扩容 + rehash）

⚠️ 面试表达：
"put 五步：扰动哈希 → 位运算定位 →
 空位直插 / 链表遍历（同键覆盖、异键尾插、
 超 8 转树）→ 超阈值扩容 rehash。"
```

### 1.3 扰动函数的原理

```text
hash = h ^ (h >>> 16)

为什么需要扰动？
  容量较小时（如 16），取模只用低 4 位
  高位信息被丢弃 → 分布可能不均匀
  右移 16 位异或 → 高位参与低位 → 更均匀

⚠️ 面试必答：
"扰动函数让高位参与低位运算——
 容量小时分布更均匀，减少冲突。"
```

## 2. 哈希冲突与扩容机制

### 2.1 冲突的三种解决方案

```text
① 链地址法（拉链）：冲突挂链表
   Java HashMap 采用
   查找：哈希定位 → 链表遍历 O(k)

② 开放定址：冲突找下一个空位
   线性探测：i+1, i+2...（易聚集）
   二次探测：i+1², i+2²...
   应用：ThreadLocal 的 ThreadLocalMap

③ 再哈希：换哈希函数重算

⚠️ 面试必答：
"链地址（HashMap）/开放定址（ThreadLocal）
 /再哈希三种方案；Java 用链地址 + 红黑树兜底。"
```

### 2.2 为什么树化阈值是 8

```text
泊松分布：负载因子 0.75 时
  链表长度达到 8 的概率 ≈ 0.00000006（六千万分之一）

→ 正常情况链表不会很长
→ 8 是"极低概率才会触发"的兜底阈值
→ 防御哈希攻击（恶意构造同哈希键）

⚠️ 面试必答：
"树化 8 是泊松分布计算的阈值——
 0.75 负载下链表到 8 的概率约六千万分之一，
 树化是防哈希攻击的兜底。"
```

### 2.3 扩容为什么必须 rehash

```text
扩容：容量翻倍（16→32→64...）

⚠️ 必须 rehash 的原因：
  定位公式：index = hash & (cap - 1)
  容量变化 → 掩码变化 → 旧位置失效！
  例：hash=17，cap=16 → 17&15=1
      cap=32 → 17&31=17（位置变了！）

→ 全部元素重新计算位置（O(n) 一次，均摊 O(1)）

⚠️ 面试必答：
"扩容必须 rehash——容量变了取模除数变了，
 旧位置全部失效，需要重新计算。"
```

### 2.4 为什么容量是 2 的幂

```text
① 位运算替代取模：hash & (cap-1)（更快）
② 扩容翻倍：16→32→64（简单）
③ rehash 后元素只可能"原地或 +旧容量"（JDK8 优化）

⚠️ 面试必答：
"2 的幂让取模变成位运算（& 替代 %），
 且扩容翻倍后 rehash 可以优化。"
```

## 3. 规范键的设计艺术

### 3.1 什么是规范键

```text
规范键（Canonical Key）：等价对象共享的标识
  用途：分组/去重/映射

⚠️ 设计三要求：
  ① 等价对象 → 相同键（充分）
  ② 不等价对象 → 不同键（必要，尽量）
  ③ 键可哈希/可比较（用作 map 键）
```

### 3.2 三种键设计模式

```java
// ═══════════ 模式一：排序键 ═══════════════════════
// 适用：字符重排等价（异位词）
// "eat" 排序 → "aet"；"tea" 排序 → "aet" → 同键
String key = new String(chars);   // Arrays.sort(chars) 后

// ═══════════ 模式二：计数键 ═══════════════════════
// 适用：字母/数字频次等价（异位词更优）
// 26 位计数转字符串 → "#1#0#0#...#1#1"
StringBuilder key = new StringBuilder();
for (int x : count) key.append('#').append(x);

// ═══════════ 模式三：数学键 ═══════════════════════
// 适用：坐标/向量等价（斜率）
// 斜率 → 最简分数对 "dx/gcd,dy/gcd"
// 例：(1,2) 与 (2,4) → gcd=2 → 同键 "1,2"
```

### 3.3 键设计示例：49. 异位词分组

```java
/**
 * LeetCode 49. 字母异位词分组
 * 计数键（免排序，O(k) 而非 O(k log k)）
 */
public List<List<String>> groupAnagrams(String[] strs) {
    Map<String, List<String>> map = new HashMap<>();

    for (String s : strs) {
        int[] count = new int[26];
        for (char c : s.toCharArray()) count[c - 'a']++;

        // ⚠️ 计数键："#1#1#1#0..."
        StringBuilder key = new StringBuilder();
        for (int x : count) key.append('#').append(x);

        map.computeIfAbsent(key.toString(),
            k -> new ArrayList<>()).add(s);
    }
    return new ArrayList<>(map.values());
}
// "eat" 与 "tea" 计数相同 → 同键 → 同组 ✓
// ⚠️ 面试讲两种方案（排序键/计数键）并说明计数键更优
```

## 4. 哈希表的工程实践

### 4.1 自定义对象做 key

```java
/**
 * ⚠️ 自定义 key 必须同时重写 hashCode + equals！
 */
class Point {
    int x, y;

    @Override
    public int hashCode() {
        // ⚠️ 用质数参与运算减少冲突
        return 31 * x + y;
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Point)) return false;
        Point p = (Point) o;
        return x == p.x && y == p.y;
    }
}
// 经典错误：只重写 equals
//   → 相同对象 hashCode 不同 → 不同桶 → 判重失效
// ⚠️ 规则：equals 相等 → hashCode 必须相等（反向不成立）
// ⚠️ key 应不可变（可变 key 的 hashCode 变化后找不到）
```

### 4.2 遍历时修改的坑

```java
// ⚠️ for-each 遍历中修改 → ConcurrentModificationException
Map<Integer, Integer> map = new HashMap<>();

// ❌ 错误：
for (int key : map.keySet()) {
    if (条件) map.remove(key);    // 并发修改异常！
}

// ✅ 正确一：迭代器 + remove
Iterator<Integer> it = map.keySet().iterator();
while (it.hasNext()) {
    int key = it.next();
    if (条件) it.remove();        // 迭代器安全删除
}

// ✅ 正确二：先收集再删除
List<Integer> toRemove = new ArrayList<>();
for (int key : map.keySet()) {
    if (条件) toRemove.add(key);
}
for (int key : toRemove) map.remove(key);
```

### 4.3 哈希表的线程安全

```text
HashMap：单线程（非线程安全）
Hashtable：全方法加锁（性能差，遗留）
ConcurrentHashMap：分段锁/CAS（并发首选）

⚠️ 面试必答：
"单线程 HashMap；并发用 ConcurrentHashMap
 （JDK8 用 CAS + synchronized 锁桶）。"
```

## 5. 哈希表 vs 其他结构

### 5.1 对比表

| 结构 | 查找 | 插入 | 有序 | 范围 |
|------|:---:|:---:|:---:|:---:|
| HashMap | O(1) | O(1) | ❌ | ❌ |
| TreeMap | O(log n) | O(log n) | ✅ | ✅ |
| LinkedHashMap | O(1) | O(1) | 插入序 | ❌ |
| 数组 | O(1) 下标 | O(1) 尾 | 天然 | 天然 |

```text
选型：
  精确查找 → HashMap（O(1)）
  需要有序/范围 → TreeMap
  需要插入序 → LinkedHashMap（LRU 简易版）
  ⚠️ 哈希局限：无序、空间大、范围查询差
```

### 5.2 哈希 vs 数组

```text
值域小且已知 → 数组（int[26] 计数）
值域大/未知 → HashMap

⚠️ 面试表达：
"字符频次用 26 数组（下标=字符，O(1) 访问）；
 数值频次用 HashMap（值域大）。"
```

### 5.3 哈希在算法中的角色

```text
① 查找优化：O(n²) → O(n)（元模式）
② 分组映射：规范键（异位词）
③ 计数统计：频次
④ 去重判重：Set
⑤ 记忆化：缓存状态

⚠️ 元模式（面试必答）：
"每当需要'检查元素是否存在/计数/找补数'，
 用哈希表替换内层循环。"
```

## 6. 进阶总结

### 6.1 进阶要点速查

```text
① HashMap 源码：扰动哈希/位运算定位/链转树
② 冲突三方案：链地址/开放定址/再哈希
③ 扩容 rehash：容量变 → 掩码变 → 全重算
④ 规范键：排序键/计数键/数学键
⑤ 自定义 key：hashCode + equals 都重写
⑥ 线程安全：HashMap vs ConcurrentHashMap
```

### 6.2 面试话术模板

```text
"HashMap 原理：
 数组 + 链表 + 红黑树，负载因子 0.75。
 put 五步：扰动哈希 → 位运算定位 →
 空位直插/链表处理（同键覆盖、超 8 转树）
 → 超阈值扩容 rehash。
 树化 8 是泊松分布阈值（防哈希攻击）。
 自定义 key 必须 hashCode + equals 都重写。"
```

### 6.3 易错点清单

| 错误 | 后果 | 修正 |
|------|------|------|
| 只重写 equals | 判重失效 | 都重写 |
| 可变对象做 key | 查找失败 | 不可变键 |
| 遍历中修改 | 并发异常 | 迭代器/收集 |
| 单线程用 Concurrent | 性能浪费 | 按场景选 |
| 键设计冲突多 | 性能退化 | 规范键设计 |

> 🎯 **核心要点**：哈希表进阶 = **HashMap 源码**（扰动/位运算/树化/扩容）+ **规范键设计**（排序/计数/数学键）+ **工程实践**（hashCode+equals/线程安全）。"扰动函数"、"树化 8 泊松分布"、"扩容 rehash"是三大必答点；键设计三模式是分组题的灵魂。
