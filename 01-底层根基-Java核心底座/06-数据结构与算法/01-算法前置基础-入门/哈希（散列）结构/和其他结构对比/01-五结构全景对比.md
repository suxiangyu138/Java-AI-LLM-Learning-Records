## 1. 复杂度总表

| 结构 | 查找 | 插入 | 删除 | 有序 | 最坏保证 |
|------|:---:|:---:|:---:|:---:|:---:|
| 哈希表 | **O(1) 平均** | O(1) 摊还 | O(1) 平均 | ❌ | ❌ O(n) |
| 数组 | O(1) 下标 | O(n) 搬移 | O(n) | ✅ 排序后 | ✅ |
| 链表 | O(n) | O(1) 已知位置 | O(1) 已知位置 | ❌ | ✅ |
| 红黑树 | O(log n) | O(log n) | O(log n) | ✅ 中序 | **✅ O(log n)** |
| 跳表 | O(log n) 平均 | O(log n) | O(log n) | ✅ | ⚠️ 概率 |

```text
核心结论:
  平均最快: 哈希表（O(1)）
  最坏最好: 红黑树（O(log n) 保证）
  有序能力: 树/跳表（哈希永远缺）
  空间效率: 数组最优（无指针）
```

> 🎯 **一句话定位**：哈希 = 速度王者（无保证）、红黑树 = 保证王者（有序）、数组 = 缓存王者、链表 = 插入王者、跳表 = 工程均衡。

## 2. 哈希 vs 数组

| 维度 | 哈希表 | 数组 |
|------|:---:|:---:|
| 访问 | 按键 O(1) 平均 | 按下标 O(1) |
| 插入 | O(1) 摊还 | O(n) 搬移 |
| 删除 | O(1) 平均 | O(n) |
| 有序 | ❌ | ✅ 排序后 |
| 缓存 | 一般（跳跃） | **最优（连续）** |
| 键类型 | 任意（可哈希） | 整数下标 |
| 应用 | Map/Set | 数组题/缓存 |

```text
本质区别:
  数组: 值 = 下标 → 连续内存 → 缓存极优
  哈希: 值 = hash(key) → 桶数组 → 跳跃访问

工程: 能用数组（键是连续整数）就不用哈希
  → 如 ID 连续的用户表: 数组直接按下标
  → 哈希反而慢（计算 + 冲突）
```

> 💡 **面试技巧**：当键是「连续整数」时数组是更优选择（O(1) 且缓存友好）——「能数组则数组」是性能优化的第一原则。

## 3. 哈希 vs 链表

| 维度 | 哈希表 | 链表 |
|------|:---:|:---:|
| 查找 | O(1) 平均 | O(n) |
| 插入（已知位置） | O(1) | **O(1)** |
| 头部插入 | O(1) | O(1) |
| 有序 | ❌ | ❌ |
| 缓存 | 一般 | 差（指针跳跃） |
| 最坏 | O(n) | O(n) |

```text
链表的核心价值:
  ① 已知位置插入/删除 O(1)（如 LRU 的移动）
  ② 无需预分配容量（动态增长）
  ③ 队列/栈的实现基础

组合用法: 哈希 + 链表 = LRU 缓存
  → 哈希 O(1) 查找 + 链表 O(1) 移动
  → 146 LRU 缓存（LeetCode 经典）
```

> 💡 哈希与链表是**搭档**而非对手：LRU 缓存（146 题）正是「哈希定位 + 链表排序」的组合——哈希表与链表的配合是工程标配。

## 4. 哈希 vs 红黑树

| 维度 | 哈希表 | 红黑树 |
|------|:---:|:---:|
| 查找 | **O(1) 平均** | O(log n) |
| 插入 | O(1) 摊还 | O(log n) |
| 最坏 | O(n) | **O(log n) 保证** |
| 有序 | ❌ | ✅ 中序升序 |
| 区间查询 | ❌ | ✅（TreeMap subMap） |
| floor/ceiling | ❌ | ✅ |
| 内存 | 桶数组 | 节点+指针 |
| Java | HashMap | TreeMap |

```text
选型场景:
  纯按键取值 → 哈希（O(1) 平均）
  需要有序遍历 → 红黑树（中序）
  需要区间查询 → 红黑树（subMap）
  需要最坏保证 → 红黑树（防攻击）
  混合（Map + 有序） → 红黑树

面试对比题:
  「为什么 TreeMap 比 HashMap 慢但更稳？」
  → 哈希 O(1) 平均无保证 + 无序
  → 红黑树 O(log n) 保证 + 有序 + 区间
```

> 🎯 **面试必答**：哈希 vs 红黑树的三个差异——**复杂度（O(1) 平均 vs O(log n) 保证）、有序性（无 vs 中序）、区间能力（无 vs subMap）**；「要速度哈希、要有序树」是选型第一句。

## 5. 哈希 vs 跳表

| 维度 | 哈希表 | 跳表 |
|------|:---:|:---:|
| 查找 | O(1) 平均 | O(log n) 平均 |
| 插入 | O(1) 摊还 | O(log n) |
| 有序 | ❌ | ✅ |
| 区间 | ❌ | **✅ 天然友好** |
| 实现 | 数组+链/树 | 多层链表 |
| 最坏 | O(n) | O(n) 概率（极低） |
| 工程 | HashMap | Redis ZSet、LevelDB |

```text
跳表的优势:
  ① 区间查询天然支持（链表顺滑）
  ② 实现简单（vs 红黑树旋转）
  ③ 并发友好（无全局重平衡）

工程案例:
  Redis ZSet（有序集合）: 跳表实现
  LevelDB 内存表: 跳表
  并发场景: ConcurrentSkipListMap
```

> 💡 跳表是红黑树的「工程替代」——实现简单 + 区间友好 + 并发友好；Redis ZSet 选择跳表而非红黑树正是这个原因（面试高频案例）。

## 6. 全景对比总结

### 6.1 五结构定位卡

```text
哈希表:   O(1) 平均 · 无序 · 无保证 · Map/Set
数组:     O(1) 下标 · 有序可选 · 缓存王 · 连续键
链表:     O(1) 已知位置插删 · 无查找优势 · LRU
红黑树:   O(log n) 保证 · 有序 · 区间 · TreeMap
跳表:     O(log n) 平均 · 有序 · 区间 · Redis ZSet
```

### 6.2 Java 容器映射

| 需求 | Java 容器 | 底层 |
|------|----------|------|
| 按键取值（无序） | HashMap | 哈希表 |
| 有序遍历 | TreeMap | 红黑树 |
| 按下标 | ArrayList | 数组 |
| 头尾操作 | ArrayDeque | 数组双端 |
| 任意位置插入 | LinkedList | 链表 |
| 并发有序 | ConcurrentSkipListMap | 跳表 |
| 缓存淘汰 | LinkedHashMap | 哈希+链表 |

### 6.3 面试一句话

```text
「数据结构的本质是交换:
  哈希用空间换时间（O(1) 平均）
  红黑树用旋转换保证（O(log n) 最坏）
  数组用连续换缓存（访问最快）
  跳表用概率换简单（实现最易）」
```

**面试追问**：

| 追问 | 答题要点 |
|------|---------|
| 哈希为什么不是万能？ | 无序 + 无最坏保证 + 空间开销 |
| 什么时候数组优于哈希？ | 键连续整数、缓存敏感 |
| 哈希和链表怎么配合？ | LRU 缓存（146 题） |
| TreeMap 比 HashMap 贵在哪？ | O(log n) vs O(1) 平均 |
| Redis ZSet 为什么跳表？ | 区间 + 简单 + 并发 |
| 选型总口诀？ | 速度哈希、有序树、保证红黑、区间跳表 |

### 6.4 实践检查清单

| 场景 | 检查问题 |
|------|---------|
| 新建 Map | 需要有序/区间吗？→ TreeMap 而非 HashMap |
| 排行榜 | lastKey/descendingMap 可用？→ 红黑树 |
| 缓存 | 淘汰策略需要？→ LinkedHashMap |
| 区间统计 | subMap 可用？→ TreeMap |
| 连续键 | 能数组吗？→ 数组优先 |

> 🎯 **核心要点**：对比验收——五结构复杂度总表默写；哈希 vs 红黑树三差异（复杂度/有序/区间）；「能数组则数组」的缓存原则；哈希+链表 = LRU 的组合智慧；Redis ZSet 跳表案例；「结构本质是交换」的全局视角。
