## 1. 四大子模型的完整识别体系

### 1.1 子模型总览

| 子模型 | 缩窗触发 | 答案更新 | 代表题 | 识别信号 |
|------|------|------|:---:|------|
| **定长** | 长度恰为 K | 恰 K 时 | 438/567/643 | "固定长度" |
| **不定长最长** | while 不合法 | **while 外**取 max | 3/1004/424 | "最长/最多" |
| **不定长最短** | while 合法 | **while 内**取 min | 76/209 | "最短/最小" |
| **恰好型** | while 超限 | while 外累加 | 992/930 | "恰好 K" |

```
⚠️ 30 秒识别：
  ① "固定窗口大小" → 定长
  ② "最长/最多" → 不定长最长
  ③ "最短/最小" → 不定长最短
  ④ "恰好 K" → 容斥（atMost）
```

### 1.2 最长 vs 最短的黄金法则

```
求最长（3 题）：
  扩窗 → while 缩到合法 → 更新（while 外）
  原因：缩完的窗口才是"以 right 结尾的最长合法窗口"

求最短（76 题）：
  扩窗 → while 一合法就更新（while 内）→ 继续缩
  原因：刚合法的窗口就是"以 right 结尾的最短合法窗口"

⚠️ 记忆："最长在外更新，最短在内更新"
  （面试必答！）
```

### 1.3 判定口诀

```
"连续看单调，单调看维护，维护看结构"

① 连续子数组/子串？→ 检查单调性
② 条件单调？→ 滑动窗口
③ 维护什么？→ 计数/哈希/单调队列

⚠️ 不单调（含负数）→ 前缀和（560）
```

## 2. 定长窗口的工程细节

### 2.1 定长模板（先建首窗）

```java
/**
 * 定长窗口模板（窗口大小恒为 k）
 * ⚠️ 常见错误：忘记处理第一个窗口！
 */
public int fixedWindow(int[] nums, int k) {
    // ① 先建第一个窗口 [0, k-1]
    int sum = 0;
    for (int i = 0; i < k; i++) sum += nums[i];
    int answer = sum;                     // ⚠️ 首窗也要判断！

    // ② 滑动：加新尾，去旧头
    for (int i = k; i < nums.length; i++) {
        sum += nums[i];                   // 加新尾
        sum -= nums[i - k];               // ⚠️ 去旧头（i-k 不是 k-i）
        answer = Math.max(answer, sum);
    }
    return answer;
}
// 推演 nums=[1,12,-5,-6,50,3], k=4：
//   首窗 [1,12,-5,-6] = 2
//   i=4: 2+50-1=51（[12,-5,-6,50]）
//   i=5: 51+3-12=42 → 最大 51 ✓
// ⚠️ 三个易错点：
//   ① 首窗遗漏
//   ② i-k 写反（应为 nums[i-k]）
//   ③ 先加后减顺序（无关紧要但保持习惯）
```

### 2.2 定长 + 频次比较（438/567）

```java
/**
 * LeetCode 438. 找到字符串中所有字母异位词
 * 定长窗口 + 频次数组比较
 */
public List<Integer> findAnagrams(String s, String p) {
    List<Integer> res = new ArrayList<>();
    if (s.length() < p.length()) return res;

    int[] pCount = new int[26];
    int[] windowCount = new int[26];

    for (char c : p.toCharArray()) pCount[c - 'a']++;

    for (int i = 0; i < s.length(); i++) {
        windowCount[s.charAt(i) - 'a']++;          // 加新尾

        if (i >= p.length()) {                     // 窗口超过
            windowCount[s.charAt(i - p.length()) - 'a']--;   // 去旧头
        }

        // 长度达标后比较频次
        if (i >= p.length() - 1
            && Arrays.equals(pCount, windowCount)) {
            res.add(i - p.length() + 1);           // 窗口起始下标
        }
    }
    return res;
}
// 推演 s="cbaebabacd", p="abc"：
//   窗口 [cba]：频次匹配 → 起始 0
//   窗口 [bac]：频次匹配 → 起始 6
//   → [0,6] ✓
// ⚠️ 567 字符串排列 = 438 的 boolean 版（代码几乎相同）
```

## 3. 恰好型的容斥原理

### 3.1 为什么"恰好"不能用滑窗

```
"恰好 K 个不同整数"不满足单调性：
  扩窗 → 可能变 K+1（超过）
  缩窗 → 可能变 K-1（不足）
  → 指针移动无法保证条件朝向可预测

"至多 K 个不同整数"满足单调性：
  扩窗 → 更难满足（种类增加）
  缩窗 → 更易满足（种类减少）
  → 滑窗可用！
```

### 3.2 容斥公式

```
恰好 K = 至多 K - 至多 (K-1)

exactlyK = atMost(K) - atMost(K-1)

原理：集合论容斥（差集）
  {≤K} 包含 {≤K-1} → 差集恰好是 {=K}

⚠️ 记忆："恰好等于至多减至多"
  （面试必答公式）
```

### 3.3 992. K 个不同整数的子数组

```java
/**
 * LeetCode 992. K 个不同整数的子数组（Hard）
 * exactlyK = atMost(K) - atMost(K-1)
 */
public int subarraysWithKDistinct(int[] nums, int k) {
    return atMostK(nums, k) - atMostK(nums, k - 1);
}

private int atMostK(int[] nums, int k) {
    Map<Integer, Integer> count = new HashMap<>();
    int left = 0, total = 0;

    for (int right = 0; right < nums.length; right++) {
        count.merge(nums[right], 1, Integer::sum);

        while (count.size() > k) {          // 种类太多 → 缩
            int leftVal = nums[left];
            count.merge(leftVal, -1, Integer::sum);
            if (count.get(leftVal) == 0) count.remove(leftVal);
            left++;
        }
        total += right - left + 1;          // ⚠️ 以 right 结尾的合法数
    }
    return total;
}
// 推演 nums=[1,2,1,2,3], k=2：
//   atMost(2) = 12；atMost(1) = 5 → 答案 7 ✓
// ⚠️ 为什么累加 right-left+1？
//   窗口 [left, right] 合法 → 以 right 结尾的
//   合法子数组 = 从 left 到 right 的每个位置做起点
//   = right - left + 1 个
```

### 3.4 恰好型家族

| 题号 | 题目 | 窗口条件 |
|:---:|------|------|
| 992 | K 个不同整数 | 种类 ≤ K |
| 930 | 和相同的二元子数组 | 和 ≤ K（非负） |
| 1248 | K 个奇数的子数组 | 奇数 ≤ K |

## 4. 窗口状态的维护结构

### 4.1 三种结构选型

| 结构 | 适用 | 复杂度 |
|------|------|:---:|
| 计数数组 | 值域小（字符/0-100） | O(1) 更新 |
| HashMap | 值域大/未知 | O(1) 更新 |
| 单调队列 | 窗口最值 | O(1) 均摊 |

```
⚠️ 选型：
  字符频次 → int[26]（最快）
  数值频次 → HashMap
  窗口最值 → 单调队列（Deque）
```

### 4.2 计数数组的窗口维护

```java
/**
 * 3. 无重复字符的最长子串（计数数组做窗口状态）
 */
public int lengthOfLongestSubstring(String s) {
    int[] count = new int[128];         // ASCII 频次
    int left = 0;
    int maxLen = 0;

    for (int right = 0; right < s.length(); right++) {
        char c = s.charAt(right);
        count[c]++;                     // ① 扩窗

        while (count[c] > 1) {          // ② 缩窗（有重复）
            count[s.charAt(left)]--;
            left++;
        }

        maxLen = Math.max(maxLen, right - left + 1);   // ③ while 外
    }
    return maxLen;
}
// ⚠️ 增量维护的本质：
//   扩窗 O(1)：count[c]++
//   缩窗 O(1)：count[left]--
//   → 不重新计算窗口 → O(n)
```

### 4.3 76. 最小覆盖子串（valid 变量）

```java
/**
 * LeetCode 76. 最小覆盖子串
 * valid = 已满足的字符种类数（不是数量！）
 * valid == required → 窗口合法
 */
public String minWindow(String s, String t) {
    int[] need = new int[128];
    for (char c : t.toCharArray()) need[c]++;

    int required = 0;
    for (int x : need) if (x > 0) required++;   // t 的种类数

    int left = 0, valid = 0, minLen = Integer.MAX_VALUE, start = 0;

    for (int right = 0; right < s.length(); right++) {
        char c = s.charAt(right);
        if (need[c] > 0) {
            need[c]--;
            if (need[c] == 0) valid++;          // 该类满足
        }

        while (valid == required) {             // ⚠️ 合法就缩（最短型）
            if (right - left + 1 < minLen) {
                minLen = right - left + 1;
                start = left;
            }
            char out = s.charAt(left);
            if (need[out] > 0) {
                if (need[out] == 0) valid--;    // 满足被破坏
                need[out]++;
            }
            left++;
        }
    }
    return minLen == Integer.MAX_VALUE ? ""
        : s.substring(start, start + minLen);
}
// ⚠️ 为什么用"种类数"而非"数量"？
//   种类满足 O(1) 判断（valid == required）
//   数量判断需逐个字符检查（128 次）
// ⚠️ 面试必答："valid 追踪种类满足状态——
//   从缺到满 valid++，从满到缺 valid--"
```

## 5. 滑窗与单调队列/前缀和的协作

### 5.1 滑窗 + 单调队列（窗口最值）

```
普通滑窗维护"计数/和"
窗口最值 → 单调队列（239）

⚠️ 识别：
  "窗口内最大值/最小值" → Deque
  "窗口内频次/和" → 计数/哈希

⚠️ 关系：
  单调队列 = 滑窗 + 单调性维护
  （详见单调队列专题）
```

### 5.2 滑窗 vs 前缀和

```
滑窗：条件单调（扩窗更难/更易满足）→ O(1) 空间
前缀和：含负数/统计个数 → O(n) 空间

⚠️ 识别：
  "连续子数组 + 单调条件" → 滑窗
  "连续子数组 + 含负数/计数" → 前缀和+哈希

⚠️ 面试必答：
"滑窗要求条件单调——含负数时窗口和
 不单调，用前缀和+哈希替代。"
```

### 5.3 滑窗 + 二分（答案二分变体）

```
窗口约束 + 答案二分：
  例：1102 最高得分路径（BFS + 二分）
  ⚠️ 少见于纯滑窗题，了解即可
```

## 6. 进阶总结

### 6.1 进阶要点速查

```
① 四大子模型：定长/最长/最短/恰好
   识别信号：固定长度/最长最短/恰好 K
② 黄金法则：最长外更新、最短内更新
③ 容斥：恰好 K = atMost(K) - atMost(K-1)
④ 维护结构：计数数组/HashMap/单调队列
⑤ 协作：单调队列（最值）、前缀和（含负数）
```

### 6.2 面试话术模板

```
"这是【子模型】滑窗：
 ① 识别信号【最长/最短/恰好 K】；
 ② 模板要点【while 缩窗/更新位置/容斥】；
 ③ 维护结构【计数数组/HashMap/单调队列】；
 ④ 复杂度 O(n)（每元素进出各一次）。
 追问失效：【含负数 → 前缀和】。"
```

### 6.3 易错点清单

| 错误 | 后果 | 修正 |
|------|------|------|
| 缩窗用 if | 仍不合法 | 用 while |
| 更新位置反 | 答案错 | 最长外最短内 |
| 恰好型直接滑 | 答案错 | atMost 容斥 |
| 忘处理首窗 | 漏窗口 | 先建首窗 |
| 计数归零忘删键 | 种类判断错 | count==0 remove |

> 🎯 **核心要点**：滑窗进阶 = **模型识别**（四大子模型 30 秒判定）+ **容斥技巧**（恰好=至多减至多）+ **维护结构选型**（计数/哈希/单调队列）。"最长外最短内"黄金法则与"恰好等于至多减至多"公式是两大必答点。
