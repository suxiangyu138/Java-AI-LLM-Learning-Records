## 1. 界函数：决定算法生死的函数

### 1.1 界函数是什么

对搜索树上的每个结点 v（对应一个**部分解**），界函数给出一个值 bound(v)：

| 问题类型 | 界函数 | 含义 |
|---------|-------|------|
| 最大化 | ub(v)（上界） | v 的子树中**任何可行解**的目标值 ≤ ub(v) |
| 最小化 | lb(v)（下界） | v 的子树中**任何可行解**的目标值 ≥ lb(v) |

### 1.2 为什么它是灵魂

回顾 02 文件：界函数同时承担**剪枝、排序、提前终止**三大职责。这意味着：

```text
界越紧（越接近真实最优值）
  → 剪掉越多无望子树
  → 最优解越早出现（Best-First 排序）
  → 提前终止越早触发
  → 算法越快
```

反之，界太松（极端情况 ub ≡ +∞ / lb ≡ -∞）时**剪枝完全失效，算法退化为纯枚举**——复杂度回到最坏指数级。

> 🎯 **一句话定理**：分支限界的效率 = 界函数的质量。**界设计没有通用公式，每个问题都需要单独推导**——这正是它比回溯/DP"难"的地方，也是面试里值得展开讲的地方。

## 2. 松弛思想：界函数的万能设计法

### 2.1 核心原理

松弛（Relaxation）是设计界函数的**第一性原理**：

```text
原问题很难解 → 去掉/放宽某些约束 → 得到"松弛问题"（好解）
松弛问题的最优值 → 天然的界（合法性的证明依据）
```

为什么松弛问题的最优值是合法界？因为**松弛问题的可行域 ⊇ 原问题的可行域**：

- 最大化：松弛问题在更大可行域上取最大 → 松弛最优值 ≥ 原问题最优值 → 是**上界** ✔
- 最小化：松弛问题在更大可行域上取最小 → 松弛最优值 ≤ 原问题最优值 → 是**下界** ✔

### 2.2 三种常用松弛手法

| 松弛手法 | 做法 | 例子 |
|---------|------|------|
| **连续化松弛** | 把整数变量放宽为连续变量 | 0-1 背包 → 分数背包 |
| **删除约束松弛** | 去掉一部分约束 | TSP → 最小生成树（MST） |
| **分解松弛** | 拆成多个独立子问题分别求解再合并 | 调度问题按机器/任务分解 |

### 2.3 松弛的双重角色

松弛不仅给界，还给**解**：松弛问题的解（如分数背包的最优装载方案）可以作为**初始可行解**（first incumbent），同时它的"取整"版本是搜索树的**初始 best**。工程上这一步叫 **初始解/热启动（warm start）**，能让剪枝从第一轮就开始生效。

## 3. 最大化问题上界设计

### 3.1 0-1 背包：分数背包松弛（教科书级）

**问题**：容量 C，物品 i 重量 wᵢ、价值 vᵢ，每个最多选一次，求最大价值。

**松弛**：允许物品按任意比例切割（分数背包），用单位价值 vᵢ/wᵢ 降序贪心装填。

设当前结点已选总价值 cv、总重量 cw，剩余容量 C − cw，从下一个物品 j 开始按单位价值顺序：

```text
ub(v) = cv + 分数背包(剩余物品, 剩余容量)
      = cv + Σ(能全装的物品价值) + 最后一个物品按比例装入的部分价值
```

**合法性**：分数背包可行域 ⊇ 0-1 背包可行域，其最优值 ≥ 0-1 背包最优值 ✔

**紧度评估**：这是"紧且便宜"的界——只需一次排序（预处理）+ 一次线性扫描。

> ⚠️ 三个常见误区：
> - 用"剩余物品价值总和"当上界：太松，几乎不剪枝（除非容量极大）
> - 用"剩余容量 × 最大单位价值"：可能**高估真实上界之外的部分**，注意它依然是合法上界，但比分数背包松（信息量少）
> - 忘记排序：分数背包贪心必须按单位价值降序，否则不是最优松弛解

### 3.2 通用线性松弛

整数规划（如 MILP）中，把 xᵢ ∈ {0,1} 放宽为 0 ≤ xᵢ ≤ 1 连续，用 **LP（线性规划）求解**，LP 最优值就是上界（这是 09 文件 Branch and Cut 的基石）。

### 3.3 贪心估算上界

有时松弛问题也难解，就用**贪心构造一个可行解，再加一个乐观修正项**：

```text
ub(v) = 贪心可行解价值 + 乐观增量（如忽略剩余约束的额外收益）
```

注意：贪心可行解本身是**下界**（它确实可行，真实最优 ≥ 它）；要构造**上界**必须在贪心解上再叠加一个乐观项。**混淆两者是新手最常犯的错误**。

## 4. 最小化问题下界设计

### 4.1 TSP：MST 下界（经典中的经典）

**问题**：访问所有城市恰好一次并回到起点，求最短回路。

**松弛**：去掉"必须成环"约束，得到**最小生成树（MST）**。

**下界推导**：TSP 最优回路删去任意一条边后是一棵生成树（连通、n−1 条边），故：

```text
lb(v) = 已走路程 + (剩余城市 + 起点/终点)子图上的 MST 权值
```

MST 权值 ≤ 回路删除边后的边集权值 ≤ 回路总长 → 合法下界 ✔

**改进版 1-树（1-tree）**：固定一个城市（如城市 1），从它引出两条边连到 MST 剩余部分。1-树权值 ≥ MST 权值（更紧），且对对称 TSP 是最经典的紧下界之一：

```text
lb = 已走路程 + 1-tree 权值（含城市1的两条最短邻边 + 其余城市的 MST）
```

> 💡 一个巧妙的紧化：**MST + 最小两条关联边 = 1-tree**，它更接近"回路"结构（每个点度数至少 2），所以更紧。Holdbrook-Held-Karp 还提出了"加势值"进一步紧化，是 TSP 下界的里程碑（1970），有兴趣可查。

### 4.2 作业调度：贪心下界

**问题**：n 个作业在 m 台机器上处理，求最小化完工时间（makespan）。

**下界设计**（常用两层）：

```text
lb(v) = max( 已分配机器上的最大负载,
             剩余作业总处理时间 / m,     // 平均分摊的乐观估计
             单个剩余作业的最大处理时间 )
```

三层取 max 是三个独立松弛（删除约束）的交集，**同时满足多个下界 → 取最大者最紧**。

### 4.3 单源最短路径：0 下界与 A* 启发式

- 朴素 Dijkstra：lb(v) = 已走路程 + 0（非负边权保证 0 是下界）——合法但松
- A*：lb(v) = 已走路程 + h(v)，h(v) 是可采纳启发式（≤ 真实剩余路程，如欧氏距离/曼哈顿距离）——**更紧，这就是 A* 比 Dijkstra 快的数学原因**

> 🎯 **这里揭示了本模块最深刻的洞察**：Dijkstra 和 A* 就是分支限界——活结点表 = 优先队列，界函数 = g + h，提前终止 = 队头出队即最优。**学完分支限界再回头看最短路，整个图论搜索瞬间打通**（07 文件再系统对比）。

## 5. 单调性：正确性的隐形保险丝

### 5.1 定义回顾

| 问题类型 | 单调性要求 | 违反后果 |
|---------|-----------|---------|
| 最大化 | ub(父) ≥ ub(子) | 父被剪但子含最优 → 丢解 |
| 最小化 | lb(父) ≤ lb(子) | 同上 |

### 5.2 为什么"看起来合理"的界可能违反单调性

**例**：0-1 背包上界若定义为"当前价值 + 剩余物品价值总和"（忽略容量）：

- 父结点（剩余容量大）：ub 高
- 子结点（选了重物，剩余容量小）：ub = 当前价值 + 剩余价值总和，可能**比父更高**？

不会——因为子结点当前价值更高但剩余物品更少。但换个设计就会翻车：若界函数包含"乐观容量"项（如容量 × 单位价值），选重物导致剩余容量骤降，子界可能低于父界 → 违反单调性。**设计界函数后必须验证单调性**，这是正确性三前提里最容易在实现时悄悄被破坏的一条。

### 5.3 快速验证手段

1. **手工小样例**：n = 3 的全树上打印每个结点的界值，检查父子关系
2. **暴力对照**：与枚举最优解对比，结果一致才说明剪枝没错（见第 7 节）

## 6. 松紧权衡：紧度与计算成本的博弈

界函数存在"更紧但更贵"的谱系。以 TSP 下界为例：

| 下界 | 计算成本 | 紧度 | 适用场景 |
|------|:---:|:---:|------|
| 0 下界（纯 BFS） | O(1) | 极松 | 教学 |
| 最小生成树 MST | O(n²)（Prim） | 中 | 通用 |
| 1-树（1-tree） | O(n²) | 较紧 | 对称 TSP 标配 |
| 带势值的 HK 下界 | O(n³) 起 | 很紧 | 高性能 TSP 求解器 |
| LP 松弛下界 | 多项式（单纯形/内点） | 很紧 | 整数规划通用 |

### 6.1 权衡法则

```text
剪枝收益 × 剪掉的结点数  >  界函数计算成本 × 计算次数   →  用更紧的界
```

- 搜索树小（n 小）→ 松界够用，别过度设计
- 搜索树大（n 大）→ 紧界收益显著，值得重计算
- **性价比之王**：能在 O(n²) 内算出的紧界（MST、1-tree 级别）

### 6.2 增量计算技巧

界值不必每次从头算。子结点相对父结点只多走了一步：

- TSP：新结点加入后，MST 只需局部更新（动态 MST）
- 背包：从父结点界值出发，减去被排除物品的贡献
- 调度：只重算受影响机器的负载

> 💡 缓存父结点的界值并做**增量修正**，能把界函数成本再降一个量级——这是工程级优化，面试提出来是明显加分项。

## 7. 常见错误与调试方法

### 7.1 五大经典错误

| 错误 | 后果 | 自查方法 |
|------|------|---------|
| 界非法（高估 ub / 低估 lb） | **静默丢最优解**，结果看似正确实则错误 | 与暴力枚举对照 |
| 违反单调性 | 丢解，且难以复现 | 打印全树界值检查父子 |
| 贪心解当上界 | 剪掉最优解 | 明确"可行解 = 下界，乐观估计 = 上界" |
| 界函数没包含已选部分 | 界与路径无关，剪枝失效 | 检查界是否随深度收紧 |
| 提前终止条件写成"严格劣" | 多搜（变慢，但正确） | 按需求选择 ≤ 还是 < |

### 7.2 调试三件套

```text
① 小样例验证正确性：n ≤ 4 全树打印，与暴力枚举对比最优值
② 中等样例验证效率：n = 15~20，统计扩展结点数、剪枝率
③ 极端样例验证边界：空输入、全不可行、界值全相等、最优解唯一性
```

**剪枝率**是衡量界函数质量的唯一硬指标：

```text
剪枝率 = 1 − (实际扩展结点数 / 理论结点数)
```

界函数改版前后对比剪枝率，一眼看出设计好坏。

> 🎯 **核心要点**：界函数设计 = 松弛思想（放宽约束得到易解问题）+ 合法性证明（可行域包含关系）+ 单调性验证（父不劣于子）+ 松紧权衡（紧度 × 剪枝收益 vs 计算成本）。记住三个黄金案例：**分数背包松弛（0-1 背包上界）、MST/1-tree 松弛（TSP 下界）、可采纳启发式（A* 下界）**——它们覆盖了"连续化、删约束、加启发"三种设计范式。
