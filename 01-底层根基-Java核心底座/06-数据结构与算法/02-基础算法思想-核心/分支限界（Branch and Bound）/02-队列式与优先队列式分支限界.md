## 1. 活结点表：分支限界的心脏

分支限界的搜索过程围绕一张表展开：

```text
while (活结点表非空) {
    从表中取出一个活结点作为扩展结点;
    扩展该结点 → 生成全部子结点;
    对每个子结点:
        if (不满足约束) 丢弃;              // 约束剪枝
        if (界函数值不优于 best) 丢弃;      // 限界剪枝
        else 子结点进入活结点表;           // 等待扩展
}
```

**活结点表用什么数据结构，决定了结点被扩展的先后顺序**，进而决定：

- 最优解多快被找到（越快 → 越早剪枝 → 总搜索量越小）
- 是否可以提前终止
- 内存占用形态

三种主流实现：队列（FIFO）、栈（LIFO）、优先队列（堆，Best-First）。

## 2. 队列式（FIFO）分支限界

### 2.1 算法流程

活结点表用普通队列，先进先出，本质是 **BFS 的剪枝增强版**：

```text
算法 FIFO-分支限界
输入: 问题实例
1. 初始化队列 Q 为空，根结点入队
2. while Q 非空:
3.     结点 v = Q.dequeue()          // 先来先扩展
4.     生成 v 的全部子结点
5.     for 每个子结点 c:
6.         if c 可行 且 界值优于 best:
7.             if c 是叶子: 更新 best
8.             else: Q.enqueue(c)
9. 输出 best
```

### 2.2 行为特征

| 特征 | 说明 |
|------|------|
| 扩展顺序 | 严格按层（深度）扩展，同层结点按生成顺序 |
| 界函数角色 | 只用于剪枝，**不参与排序**（没有优先级） |
| 最优解出现时机 | 通常较晚（可能要搜完大部分树） |
| 提前终止 | **不支持**——队列式无法保证"剩下的结点都不比 best 好" |
| 空间 | 最坏 O(2ⁿ)（整层结点同时驻留） |

### 2.3 典型用途

- **教学演示**：流程直观，易于理解"分支 + 限界"两个操作
- **布线问题 / 迷宫最短路径**：BFS 天然最短步数，曼哈顿距离剪枝
- 与 **Dijkstra（朴素版）** 结构对应：队列式 + 下界剪枝

> 💡 队列式的剪枝收益有限：它"按层推进"意味着**所有深度 < 解深度的结点都可能被生成**，界函数只能砍掉边界上的残枝。它的优势是**实现简单、顺序可预测**（可稳定输出按层的信息）。

## 3. 栈式（LIFO）分支限界

活结点表用栈，后进先出。它与回溯法的关系：

| | 回溯法 | 栈式分支限界 |
|--|-------|-------------|
| 骨架 | DFS + 状态回退（路径复用） | 栈 + 结点拷贝（每次扩展生成全部子结点） |
| 剪枝 | 约束剪枝（限界可选，通常没有） | 约束 + 限界双剪枝 |
| 结点复用 | 通过撤销操作复用父结点状态 | 结点独立携带状态 |

栈式分支限界相当于"**把回溯的递归栈显式化 + 加上限界函数**"。它比队列式空间小（沿一条路径展开，栈深 O(n) 量级），但"后进先出"没有任何启发意义，**策略上并不优于队列式**，实际使用最少。

> 🎯 结论：栈式在理论教材中常被一笔带过，**面试记住"有 LIFO 变体、但工程不用"即可**。真正的主角是优先队列式。

## 4. 优先队列式（Best-First）分支限界

### 4.1 核心思想

活结点表用**优先队列（堆）**，每次取出"界值最优"的结点扩展：

| 问题类型 | 界函数 | 堆类型 | 优先级 |
|---------|-------|-------|--------|
| 最大化（背包、装载、最大团） | 上界 ub | 最大堆 | ub 越大越先扩展 |
| 最小化（TSP、调度、最短路） | 下界 lb | 最小堆 | lb 越小越先扩展 |

"界值最优 = 最有希望 = 大概率藏着最优解"。这就是 **Best-First（最佳优先）搜索**，也叫 **LC-搜索**（Least Cost，代价最小者优先）。

### 4.2 算法流程（以最小化问题为例）

```text
算法 Best-First-分支限界（最小化）
输入: 问题实例
1. 初始化最小堆 H，根结点入堆（lb 已计算）
2. while H 非空:
3.     if H 堆顶 lb >= best: break        // 提前终止（见第 5 节）
4.     v = H.pop()                        // lb 最小者 = 最有希望
5.     生成 v 的全部子结点
6.     for 每个子结点 c:
7.         if c 可行:
8.             if c 是叶子:
9.                 best = min(best, c 的目标值)
10.            else if c 的 lb < best:
11.                H.push(c)              // 仍有希望，入堆
12. 输出 best
```

### 4.3 为什么它通常最快

用一个比喻：搜索树是一座矿山，每个结点是一块矿区，界函数是地质勘探报告。

- **队列式**：按编号顺序依次开采，可能先挖几个月矿渣区
- **优先队列式**：每次总是开采"报告说储量最高"的矿区 → 最优解（富矿）最早挖到 → 一旦挖到富矿，所有"报告储量低于它"的矿区（占绝大多数）直接放弃，**后面几乎不用挖**

数学直觉：**最优解越早出现，best 越紧，界函数能剪掉的子树越多**，形成正反馈。这是 Best-First 的核心价值。

## 5. 优先队列式的提前终止机制

### 5.1 终止条件

```text
if (堆顶结点的界值不优于当前最优解 best) 终止
```

### 5.2 正确性证明（为什么可以安全终止）

堆的性质保证：**堆顶的界值是整个活结点表中的最优界值**。

- 最大化问题：堆顶 ub 最大，故所有活结点的 ub ≤ 堆顶 ub ≤ best
- 最小化问题：堆顶 lb 最小，故所有活结点的 lb ≥ 堆顶 lb ≥ best

而每个活结点的子树最优值不会优于它的界值（界函数的合法性，见 01 文件）。所以：

```text
剩余所有子树的最优值 ≤ best（最大化） / ≥ best（最小化）
→ 没有任何剩余子树能产生更优解
→ 搜索可以安全终止
```

> 🎯 这个"提前终止"是优先队列式相对队列式**最实质的优势**：队列式必须搜到队列空才停（最坏指数级），优先队列式往往在只探索了很小一部分结点时就能"证明"最优解已经到手。**注意：终止是基于"界"的证明，不是碰运气**。

### 5.3 一个边界细节

提前终止时堆顶条件写"不优于"（≤ / ≥）而不是"严格劣于"——因为界值相等时，剩余子树最多与 best 打平，不可能产生**严格更优**的解，不需要再搜。但对"求方案"问题，若题目要求输出**所有**最优方案，则需把条件放宽为严格劣（< / >），继续搜完所有并列最优。

## 6. 三种策略横向对比

| 维度 | 队列式 FIFO | 栈式 LIFO | 优先队列式 Best-First |
|------|:---:|:---:|:---:|
| 数据结构 | 队列 | 栈 | 优先队列（堆） |
| 对应搜索 | BFS | 类 DFS | Best-First / LC |
| 界函数用途 | 仅剪枝 | 仅剪枝 | 剪枝 + 排序 + 提前终止 |
| 最优解找到速度 | 慢 | 慢 | 快（界越紧越快） |
| 提前终止 | 不支持 | 不支持 | 支持（可证明） |
| 实现复杂度 | 低 | 低 | 中（比较器/堆） |
| 最坏空间 | O(2ⁿ) | O(n·m)（沿路径） | O(活结点数) |
| 实际用途 | 教学、布线 | 理论存在 | **工程与竞赛首选** |

> 💡 面试一句话总结：**"队列式是 BFS 剪枝版，优先队列式是 Best-First，后者的界函数同时承担剪枝、排序、提前终止三个职责，所以工程上几乎总是用它。"**

## 7. 空间复杂度与内存权衡

### 7.1 空间形态差异

| 策略 | 空间形态 | 最坏量级 |
|------|---------|:---:|
| 队列式 | 整层结点同时驻留 | O(2ⁿ) |
| 栈式 | 单路径 + 兄弟结点 | O(n) 量级 |
| 优先队列式 | 所有"有希望"的活结点 | O(2ⁿ)（最坏） |

### 7.2 优先队列式的空间悖论

优先队列式**时间上通常最快，空间上可能最胖**：Best-First 倾向于"广撒网"，深度浅的结点不轻易丢弃（它们界值可能不错），堆里可能堆着大量结点。

工程上的缓解手段：

| 手段 | 做法 | 代价 |
|------|------|------|
| 界函数做紧 | 界紧 → 剪枝多 → 堆小 | 界计算更贵（时间换空间） |
| 深度限制 | 超过最大深度直接丢弃 | 可能丢最优解（需谨慎） |
| 宽容剪枝 | 界值 ≥ best + ε 才入堆 | 近似解（不再精确） |
| 迭代深化 IDA* | 内存 O(d)，用重复搜索换空间 | 时间翻倍（见 07 文件） |

> ⚠️ **记忆点**：分支限界的时间-空间特性是"**最坏都指数，但界函数决定实际表现**"。写论文/面试谈复杂度时，先说最坏 O(2ⁿ)、再强调实际由剪枝强度决定——这是标准答案结构。

## 8. 工程实现注意点

### 8.1 堆的选择与比较器

```java
// 最小化问题（如 TSP）：lb 小的优先 → 最小堆
PriorityQueue<Node> heap = new PriorityQueue<>(
    (a, b) -> Double.compare(a.lb, b.lb));

// 最大化问题（如 0-1 背包）：ub 大的优先 → 最大堆
PriorityQueue<Node> heap = new PriorityQueue<>(
    (a, b) -> Double.compare(b.ub, a.ub));
```

> ⚠️ 三个经典坑：
> 1. **不要直接相减**（a.lb - b.lb）——double 精度 / int 溢出会导致比较器反序，堆失效
> 2. 界值相等时比较器返回 0，两个结点可以按任意顺序扩展，**不影响正确性**（只影响速度）
> 3. Java 的 `PriorityQueue` 是**最小堆**，做最大堆靠比较器反转，别搞反

### 8.2 结点设计

每个结点通常携带：深度/路径信息、部分解、目标函数部分值、界值、父指针（回溯方案）。**结点对象必须携带完整状态**——因为 B&B 不做"撤销"，出堆的结点状态靠自身携带（与回溯的区别，再次强调）。

### 8.3 界值用 double 还是 long

- 问题规模小、界值全整数 → 用 long，快且无精度问题
- 涉及平均/开方（如欧氏距离下界）→ double，比较时注意误差容忍

> 🎯 **核心要点**：活结点表选什么 = 选搜索性格。FIFO 按层推进、简单可预测但效率平庸；Best-First 按"希望值"择优，配合界函数实现**可证明的提前终止**——这是工程与竞赛的标配。记住终止条件的证明思路（堆顶界最优 ⇒ 剩余全部无望），面试被追问"为什么能提前停"时直接推导。
