## 1. 五大算法全景对比

| 维度 | 回溯 | 分支限界 | 动态规划 | 贪心 | A* |
|------|------|---------|---------|------|-----|
| 搜索骨架 | DFS | BFS / Best-First | 子问题递推（拓扑序） | 单路径局部最优 | Best-First |
| 目标 | 求所有解 | 求一个最优解 | 求最优解 | 近似最优 | 最优（可采纳时） |
| 剪枝依据 | 约束函数 | 约束 + 限界函数 | 无剪枝（重叠去重） | 无（一次走完） | 界函数 |
| 最优性保证 | ✔（穷举） | ✔（界合法时） | ✔ | ✘ | ✔（h 可采纳） |
| 核心数据结构 | 递归栈 | 队列/优先队列 | 状态表（DP 数组） | 无 | 优先队列 |
| 空间复杂度 | O(n) | O(2ⁿ)/O(n!) | O(状态数) | O(1) | O(展开结点) |
| 典型失败场景 | 最优解出现晚 | 界太松退化穷举 | 状态数爆炸 | 局部最优陷阱 | 启发式不可采纳 |

> 🎯 一句话记住五者关系：**贪心是"永远只看一步"的近视眼，回溯是"把所有路都走完"的笨办法，DP 是"把走过的路记下来"的聪明人，分支限界是"带勘探报告采矿"的工程师，A* 是给采矿工程师装上 GPS 的最短路特例。**

## 2. 分支限界 vs 回溯：最常被问的对比

这是软考、考研、面试**三料必考**对比，逐项背熟：

| 对比项 | 回溯法 | 分支限界法 |
|-------|-------|-----------|
| 搜索方式 | **深度优先（DFS）**，一条路走到底再回头 | **广度优先（BFS）或最佳优先（Best-First）** |
| 求解目标 | 找出**所有**可行解（或某个可行解） | 找出**一个最优解**（值 + 方案） |
| 活结点表 | 递归栈（隐式） | 队列 / 优先队列（显式） |
| 剪枝手段 | 仅约束函数（可行性） | **约束函数 + 限界函数（最优性）** |
| 结点的界值 | 无 | 每个结点计算上界/下界 |
| 最优解证明 | 搜完全部才知道 | **界值推理可提前证明** |
| 空间复杂度 | O(n)（路径长） | O(2ⁿ) / O(n!)（活结点表最坏） |
| 典型用途 | 排列组合穷举（N 皇后、全排列、子集） | 最优化（背包、TSP、调度、装载） |

**记忆锚点**：

```text
回溯   = "走到底，不行回头"           → 适合"找所有方案"
分支限界 = "带勘探报告，按希望采矿"      → 适合"找最优方案"
```

**同题对比（0-1 背包 n=30）**：回溯必须枚举完所有可行子集才能确定最优（剪枝只剪超重）；分支限界用分数背包上界剪掉绝大多数子树，毫秒级证明最优。

> ⚠️ 常见口误纠正：**"分支限界 = 回溯 + 剪枝"是错的**。回溯的剪枝是约束剪枝（可行性），分支限界多出的限界剪枝（最优性）是质变——它让算法能在**没有搜完**的情况下证明最优。正确的表述是"分支限界 = 系统枚举 + 限界剪枝，搜索骨架是 BFS/Best-First 而非 DFS"。

## 3. 分支限界 vs 动态规划：结构与依赖

### 3.1 本质差异

| | 动态规划 | 分支限界 |
|--|---------|---------|
| 依赖结构 | **子问题重叠**（同一子问题被反复遇到）→ 记忆化合并 | **无重叠依赖**（每个结点状态独立） |
| 状态定义 | 状态 = 子问题的参数（如剩余容量、子集掩码） | 结点 = 部分解 + 界值 |
| 空间 | 所有状态都要存（可能巨大） | 只存活结点（剪枝越多越小） |
| 最优性 | 递推保证 | 界函数合法保证 |
| 典型规模 | 依赖状态空间 | 依赖剪枝效果 |

### 3.2 什么时候哪个更强

| 场景 | 结论 | 原因 |
|------|------|------|
| 有重叠子问题 + 状态可压缩 | DP 碾压 | 指数级压缩（如 0-1 背包 O(nC)） |
| 状态空间巨大（如 TSP 的 O(n2ⁿ)） | 分支限界 | 空间不失控，剪枝动态 |
| n 大 + 容量小 | DP | 状态数 = n×C 可控 |
| n 大 + 容量大 + 需证明最优 | 分支限界 | DP 状态爆炸 |
| 只要最优值不要方案 | 两者皆可 | DP 更稳、B&B 更快（通常） |

> 💡 融合是高级玩法：**DP 先跑出 best（边界情况最优解），再喂给分支限界做初始解**——"DP 冷启动 + B&B 热搜索"。工业求解器就是这么干的（启发式求初始解 + B&B 证明最优）。

## 4. 分支限界 vs 贪心：精确与近似的分界

| | 贪心 | 分支限界 |
|--|------|---------|
| 决策 | 每步选局部最优，**不回头** | 每步选界值最优，**随时可放弃** |
| 最优性 | 无保证（除非满足贪心选择性质） | 保证（界合法时） |
| 复杂度 | 极快（O(n log n) 级） | 最坏指数 |
| 关系 | **贪心解 = 分支限界的初始 best / 界函数估算器** | 利用贪心加速 |

**两者不是竞争而是配合**：

```text
1. 贪心构造初始可行解 → best 起点高 → 剪枝提前生效
2. 贪心估算界值（分数背包上界就是贪心！）→ 界函数本体
3. B&B 找到最优后，贪心解可作"近似解对照"
```

> 🎯 **洞察**：分支限界（包括大多数精确算法）与近似算法是**生态关系**——近似负责"快速给出可用解"，精确负责"证明还能不能更好"。工业界标准流程：启发式找好解 → B&B 证明最优 → 超时则输出目前最好（这就是求解器的 gap 机制，09 文件展开）。

## 5. 与 Dijkstra / A* / IDA* 的亲缘关系

### 5.1 一个算法家族

| 算法 | 活结点表 | 界函数 | 特化之处 |
|------|:---:|------|------|
| Dijkstra | 最小堆 | g(v) + 0 | 界 = 已确认距离 |
| A* | 最小堆 | g(v) + h(v) | h 可采纳且一致 |
| 分支限界 | 队列/堆 | 任意合法 lb/ub | 通用框架 |
| IDA* | 无（递归 + 阈值） | 同 A* | 用深度阈值换空间 |

### 5.2 一致性（单调性）的意义

A* 的 h 需要满足**一致性**：h(u) ≤ d(u,v) + h(v)。这正是 01/03 文件里界函数单调性的图论版本——不满足时，出堆的结点可能被"更短路径"再次发现，需要重复扩展，A* 退化为 D* 式重复处理。

### 5.3 IDA*：分支限界的空间救赎

优先队列式 B&B 的空间最坏 O(2ⁿ)，IDA*（Iterative Deepening A*）用**迭代加深阈值**：

```text
for threshold = h(起点) 逐步增加:
    DFS 搜索，只扩展 f = g + h ≤ threshold 的结点
    本轮无解 → threshold 提高为"上轮最小的 f 超出值"
```

- 空间：O(路径深度)（递归栈）——彻底摆脱堆
- 时间：每轮重复搜索，但代价因子有界（≈ b/(b−1)），通常可接受
- **它证明了"空间与时间可以互换"**——面试谈 B&B 内存瓶颈时引出 IDA* 是深度体现

## 6. 选型决策树：拿到题目先问三件事

```text
拿到最优化题目
│
├─ Q1: 要求"所有可行解"吗？
│     ├─ 是 → 回溯 / DFS
│     └─ 否（只要最优）→ Q2
│
├─ Q2: 有重叠子问题吗（状态可压缩）？
│     ├─ 是 → 动态规划（背包、路径计数、序列类）
│     └─ 否 / 状态爆炸 → Q3
│
├─ Q3: 需要证明最优吗？
│     ├─ 否（可接受近似）→ 贪心 / 元启发式（模拟退火、遗传）
│     └─ 是 → Q4
│
└─ Q4: 能设计合法且够紧的界函数吗？
      ├─ 是 → ✔ 分支限界（子集树/排列树 + 松弛界）
      └─ 否 → 回溯 + 强约束剪枝，或直接上求解器
```

**实战对照**：

| 题目类型 | 推荐算法 | 理由 |
|---------|---------|------|
| 找所有组合/排列/子集 | 回溯 | 目标 = 枚举 |
| 0-1 背包（容量小） | DP O(nC) | 状态可压缩 |
| 0-1 背包（容量大、n ≤ 50） | 分支限界 | 分数背包界极强 |
| TSP（n ≤ 20） | 分支限界 | 1-树界 + 对称剪枝 |
| TSP（n 大） | 2-opt + 模拟退火 | 精确不可行 |
| 最短路径 | Dijkstra / A* | 本身就是特例 |
| 整数规划（规模大） | OR-Tools / Gurobi | B&B 工业实现 |

**决策提示**：面试中给出选型时要**说出理由链**（目标 → 结构 → 界函数），而不是只报算法名——"这题是求最优值、子问题状态可压缩，所以用 DP"比"用 DP"得分高一个档次；同理，"TSP 求最优、没有重叠子问题、1-树下界够紧，用分支限界"才是完整答案。

## 7. 面试追问标准答案库

**Q1：分支限界一定能找到最优解吗？**
> 是，前提是界函数合法（上界确实是上界）、满足单调性、根结点界包含最优解。满足三前提时，限界只剪"不可能产生更优解"的子树，枚举的完备性不受影响。

**Q2：界函数越紧越好吗？**
> 不一定。紧界剪枝多，但计算更贵。最优选择是"性价比最高"的界：剪掉的结点数 × 每结点节省时间 > 界函数额外成本。工程上通常选 O(n²) 内可算的紧界（MST/1-tree 级别），并用增量计算摊薄成本。

**Q3：为什么优先队列式能提前终止？**
> 堆顶的界值是所有活结点中最优的；若堆顶界都不优于 best，则所有活结点的界都不优于 best，而每个结点的子树最优值不会优于它的界值（合法性），所以剩余子树全部无望——可以安全终止。

**Q4：分支限界和回溯的本质区别？**
> 骨架不同：回溯是 DFS 一路走到底再回头（空间 O(n)）；分支限界是 BFS/Best-First 广度铺开（空间 O(2ⁿ)）。剪枝不同：回溯只有约束剪枝，分支限界还有限界剪枝，后者使得"未搜完也能证明最优"。

**Q5：什么时候回溯比分支限界好？**
> 求所有解时（回溯天然支持）；空间受限时（回溯 O(n) vs B&B O(2ⁿ)）；界函数设计不出来时（此时 B&B 退化为穷举，不如回溯省空间）。

**Q6：求解器（Gurobi/OR-Tools）底层是什么？**
> 核心是 Branch and Bound + 割平面（Branch and Cut）：LP 松弛给出界，割平面收紧，启发式给初始解，B&B 树证明最优。现代求解器还在用 ML 学习分支策略（09 文件）。

**Q7：分支限界能求"所有最优解"吗？**
> 能。把提前终止条件从"界不优于 best"放宽为"界严格劣于 best"（< / >），并允许与 best 打平的叶子继续结算，就能枚举全部并列最优方案。代价是搜索量增大，需评估是否必要。

**Q8：界函数设计不出来怎么办？**
> 三个退路：① 退回回溯 + 强约束剪枝（空间 O(n) 更省）；② 如果问题有重叠子问题，改用 DP；③ 规模大且允许近似，用贪心/元启发式。面试中"如实分析界函数难度 + 给出备选路线"比硬套 B&B 更得分。

**Q9：分支限界与遗传算法/模拟退火是什么关系？**
> 精确与近似的分工：B&B 保证最优、最坏指数；元启发式不保证最优、能解大规模。工业实践是配合使用——元启发式快速给出高质量初始解（best），B&B/求解器接管并证明最优（gap 归零）。**"近似找解、精确证明"是组合优化的标准工作流**。

**Q10：B&B 的提前终止会不会因为界函数紧度不同而失效？**
> 不会失效，只影响生效时机。无论界松紧，只要界合法，堆顶界不优于 best 时剩余子树必然无望——终止条件本身与界紧度无关。界松只会让"堆顶界值变差得慢"，推迟终止，但绝不错误终止。

> 🎯 **核心要点**：选型四问（所有解？重叠子问题？要证明最优？界函数可行？）把五大算法放进一张决策树。与回溯比记住"骨架 + 剪枝"两个差异；与 DP 比记住"重叠依赖 vs 动态剪枝"；与贪心比记住"生态配合"；与 A*/Dijkstra 比记住"同一个框架的实例化"。**这份"算法宇宙地图"是面试综合题的通关密钥**。
