## 1. 问题定义与建模

### 1.1 问题定义

```text
有 n 件物品，第 i 件重量 wᵢ、价值 vᵢ，背包容量 C。
每件物品最多选一次，求装入物品的总价值最大。
```

目标：max Σ vᵢ·xᵢ，约束 Σ wᵢ·xᵢ ≤ C，xᵢ ∈ {0,1}。

### 1.2 解空间树：子集树

每个结点对应"前 k 件物品的决策已完成"，左右两支分别是**不选 / 选第 k+1 件**：

```text
                [空]
           不选 /    \ 选
          [1号不选]  [1号选中]
           /    \      /    \
     [2号不选] [2号选中] ...
```

- 树高 n，叶子 2ⁿ 个，每片叶子对应一个完整的 0-1 选择向量
- 结点携带状态：`level`（已决策到第几件）、`curWeight`（已选总重）、`curValue`（已选总价）、`ub`（上界）

### 1.3 预处理：按单位价值降序

上界函数要求物品按单位价值 vᵢ/wᵢ 降序排列（理由见 2.1），**必须先排序**：

```java
Arrays.sort(items, (a, b) -> Double.compare(
    (double) b.value / b.weight, (double) a.value / a.weight));
```

## 2. 上界函数：分数背包松弛的完整推导

### 2.1 松弛构造

**原问题**：xᵢ ∈ {0,1}（整件选择）——NP-hard。
**松弛问题（分数背包）**：允许 0 ≤ xᵢ ≤ 1 连续，即物品可以切割。

**关键观察**：分数背包可行域 ⊃ 0-1 背包可行域 → 分数背包最优值 ≥ 0-1 背包最优值 → **合法上界**。

### 2.2 分数背包的最优解结构

分数背包的贪心最优性：**单位价值高的物品优先装**（交换论证可证：若装了单位价值低的而没装高的，交换后不劣）。

因此给定当前结点（已选 cv、cw，已决策到物品 k），上界为：

```text
ub = cv + Σ(物品 k+1..n 中能全装的价值) + 最后一件按比例的价值

例：剩余容量 10，剩余物品按单位价值排序后依次为
    (w=4, v=6), (w=5, v=7), (w=6, v=8), ...
    → 装 4(6) + 5(7) = 9 容量，剩 1 容量
    → 第三件只装 1/6，得 8 × (1/6) ≈ 1.33
    → ub = cv + 6 + 7 + 1.33 = cv + 14.33
```

### 2.3 实现代码

```java
/** 计算结点上界：当前价值 + 剩余容量做分数背包 */
static double upperBound(int level, int curWeight, int curValue,
                         int capacity, int[] weights, int[] values, int n) {
    double bound = curValue;
    int remain = capacity - curWeight;          // 剩余容量
    for (int i = level; i < n; i++) {           // 从 level 开始（该件尚未决策）
        if (weights[i] <= remain) {             // 能全装
            bound += values[i];
            remain -= weights[i];
        } else {                                // 只能装一部分（分数背包允许）
            bound += (double) values[i] / weights[i] * remain;
            break;
        }
    }
    return bound;
}
```

> 🎯 **合法性双检查**：① 分数背包可行域包含原问题 → 松弛值 ≥ 真实最优 ✔；② 从 level 件开始按单位价值降序贪心 → 松弛问题被精确求解 ✔。两者都满足，ub 才是合法上界。

## 3. 优先队列式完整 Java 实现

### 3.1 结点类

```java
class Node {
    int level;        // 已决策物品数（下一个待决策的是 level 号）
    int weight;       // 已选总重量
    int value;        // 已选总价值
    double ub;        // 上界 = value + 分数背包剩余容量
    boolean[] taken;  // 决策记录（恢复方案用）
}
```

### 3.2 主算法

```java
import java.util.*;

public class KnapsackBranchAndBound {

    static class Node {
        int level, weight, value;
        double ub;
        Node(int level, int weight, int value, double ub) {
            this.level = level; this.weight = weight;
            this.value = value; this.ub = ub;
        }
    }

    static int knapsack(int[] weights, int[] values, int capacity) {
        int n = weights.length;
        Integer[] idx = new Integer[n];
        for (int i = 0; i < n; i++) idx[i] = i;
        // 按单位价值降序
        Arrays.sort(idx, (a, b) -> Double.compare(
                (double) values[b] / weights[b], (double) values[a] / weights[a]));
        int[] w = new int[n], v = new int[n];
        for (int i = 0; i < n; i++) { w[i] = weights[idx[i]]; v[i] = values[idx[i]]; }

        // 最大堆：ub 大者优先
        PriorityQueue<Node> heap = new PriorityQueue<>(
                (a, b) -> Double.compare(b.ub, a.ub));

        int best = 0;                                  // 当前最优价值（初始 0）
        Node root = new Node(0, 0, 0,
                upperBound(0, 0, 0, capacity, w, v));
        heap.offer(root);

        while (!heap.isEmpty()) {
            Node cur = heap.poll();
            if (cur.ub <= best) break;                 // 提前终止：堆顶都不行了
            if (cur.level == n) {                      // 完整方案
                best = Math.max(best, cur.value);
                continue;
            }
            // 分支 1：不选 level 号物品
            Node skip = new Node(cur.level + 1, cur.weight, cur.value,
                    upperBound(cur.level + 1, cur.weight, cur.value, capacity, w, v));
            if (skip.ub > best) heap.offer(skip);
            // 分支 2：选 level 号物品
            if (cur.weight + w[cur.level] <= capacity) {   // 约束检查
                Node take = new Node(cur.level + 1,
                        cur.weight + w[cur.level],
                        cur.value + v[cur.level],
                        upperBound(cur.level + 1,
                                cur.weight + w[cur.level],
                                cur.value + v[cur.level], capacity, w, v));
                if (take.ub > best) heap.offer(take);
            }
        }
        return best;
    }

    static double upperBound(int level, int weight, int value,
                             int capacity, int[] w, int[] v) {
        double bound = value;
        int remain = capacity - weight;
        for (int i = level; i < w.length && remain > 0; i++) {
            if (w[i] <= remain) { bound += v[i]; remain -= w[i]; }
            else { bound += (double) v[i] / w[i] * remain; break; }
        }
        return bound;
    }

    public static void main(String[] args) {
        int[] weights = {10, 20, 30, 40, 50};
        int[] values  = {20, 30, 66, 40, 60};
        System.out.println(knapsack(weights, values, 100));  // 输出 156
    }
}
```

### 3.3 恢复最优方案

需要输出"选了哪些物品"时，结点携带 `boolean[] taken` 或 `List<Integer> chosen`，在更新 best 时**同步拷贝**当前方案（与回溯收集结果的时机完全一致）。

## 4. 手动走查：n=3 全流程

**数据**：容量 C = 10；物品（按单位价值降序后）：A(w=4, v=12, 单位3.0)、B(w=6, v=12, 单位2.0)、C(w=5, v=8, 单位1.6)。

| 步骤 | 操作 | 堆状态 (ub, 描述) | best |
|:---:|------|-------------------|:---:|
| 1 | 根结点入堆：ub = 24（分数背包：A 全装 4 + B 全装 6 = 满 10，价值 24） | {根: 24} | 0 |
| 2 | 扩展根：不选 A → ub = 18.4（B 全装 12，剩 4，C 装 4/5×8=6.4）；选 A → ub = 24（剩 6，B 全装 12，满） | {不选A: 18.4, 选A: 24} | 0 |
| 3 | 扩展"选A"（ub 24 最大）：不选 B → ub = 20（剩 6，C 全装 8）；选 B → 重量 4+6=10 可行，ub = 24 入堆 | {不选A:18.4, 不选B:20, 选B:24} | 0 |
| 4 | 扩展"选B"（ub 24 最大）：不选 C → ub = 24，叶子结点入堆；选 C → 重量 15 > 10 超重丢弃 | {不选A:18.4, 不选B:20, 不选C:24} | 0 |
| 5 | 扩展"不选C"（ub 24 最大）：level = n = 3，是叶子 → best = max(0, 24) = **24** | {不选A:18.4, 不选B:20} | 24 |
| 6 | 堆顶"不选B" ub = 20 ≤ best = 24 → **提前终止**（剩余结点均不可能超过 24） | — | **24** |

> 🎯 **走查要点**：第 4 步演示了提前终止——堆顶 ub = 24 与 best 相等，剩余所有结点（不选A、不选B）都不可能超过 24，直接停机。整个搜索只扩展了 3 个结点，而穷举需要 2³ = 8 个叶子。**界函数的威力一目了然**。

## 5. 队列式实现与两者对比

队列式只需把 `PriorityQueue` 换成 `ArrayDeque`，去掉比较器与提前终止，其余完全一样。对比（同一份数据 n=30、容量 300 随机数据）：

| 维度 | 队列式 FIFO | 优先队列式 Best-First |
|------|:---:|:---:|
| 扩展结点数 | 约 2³⁰ 的很大一部分 | 通常几千~几万 |
| 提前终止 | 不支持 | 支持（本例题第 4 步就停） |
| 时间 | 慢（几乎退化为枚举） | 快（若干数量级） |
| 适用 | 教学、小 n | 工程、竞赛、面试 |

> 💡 面试常问："为什么优先队列式快？" 标准答案链：**界最优者先扩展 → 最优解更早出现 → best 更早收紧 → 更多子树被剪 → 搜索量骤减 → 提前终止更早触发**。

## 6. 与回溯法求解同题的对比

同题回溯（DFS + 约束剪枝，无界函数）：

| 维度 | 回溯法 | 分支限界（优先队列式） |
|------|-------|----------------------|
| 搜索骨架 | DFS，沿路径深入到底 | Best-First，按上界择优 |
| 剪枝依据 | 仅约束（超重） | 约束 + 上界 |
| 最优解确认时机 | 必须走完所有可行路径 | 可证明的提前终止 |
| 空间 | O(n)（递归栈） | O(活结点数)（堆） |
| 时间（n=30 随机） | 秒级~分钟级 | 毫秒~秒级 |
| 求所有最优方案 | 天然支持 | 需放宽终止条件 |

**两者互补**：回溯强在"枚举所有方案 + 低内存"，分支限界强在"快速证明最优 + 大问题"。

## 7. 变体与扩展

| 变体 | 变化 | 界函数调整 |
|------|------|-----------|
| 完全背包 | 每件可取无限次 | 分数背包上界仍适用（连续化思想天然兼容） |
| 多重背包 | 每件有数量上限 | 先做二进制拆分/单调队列，再套 B&B |
| 二维背包 | 重量 + 体积两个约束 | 分数背包需按两个维度扫描，界变松 |
| 带偏序约束 | 选 B 必须选 A（依赖） | 界函数需额外考虑依赖关系 |
| 价值 = 物品组合收益 | 子集间有协同 | 需子集级贪心上界，复杂度上升 |

> 💡 实际工程中，**n ≤ 50 的 0-1 背包用分支限界可轻松求解**；n 上万时用 DP（若容量小）或贪心近似；工业级用求解器（09 文件）。这也是回答"背包用什么算法"的完整答案。

## 8. 复杂度与适用边界

- **最坏复杂度**：O(2ⁿ) 时间、O(2ⁿ) 空间（堆中活结点数）——与穷举同阶
- **实际复杂度**：由上界紧度决定，n ≤ 30 随机数据通常毫秒级
- **上界计算**：每次 O(n)，全算法 O(n·结点数)；可用增量优化到 O(1) 均摊
- **适用边界**：n 小（≤ 50）且需要**证明最优**；n 大 → DP（容量小）或启发式/求解器

> 🎯 **核心要点**：0-1 背包是理解分支限界的唯一最佳例题——**子集树建模（简单）+ 分数背包上界（教科书级松弛）+ 优先队列 + 提前终止（可证明）**四件套一次集齐。把它彻底吃透，分支限界的原理、实现、调试、面试表述就全部过关了。
