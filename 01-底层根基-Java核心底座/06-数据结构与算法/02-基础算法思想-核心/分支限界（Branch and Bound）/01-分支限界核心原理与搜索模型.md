## 1. 问题定位：分支限界解决什么问题

分支限界（Branch and Bound，B&B）是一类**精确求解组合优化问题**的算法框架。组合优化问题的标准形态是：

- **决策变量**：一组可枚举的离散选择（选/不选、排列、组合）
- **约束条件**：可行解必须满足的限制（容量、资源、冲突）
- **目标函数**：最大化或最小化某个值（总价值、总距离、总成本）

> 💡 典型的"求最优解 + 解空间可枚举"问题：0-1 背包、旅行商（TSP）、装载、作业调度、整数规划。**凡是能用回溯枚举出所有可行解的问题，理论上都能用分支限界求最优解**——区别只在于搜索策略与剪枝依据不同。

分支限界的策略本质可以用一句话概括：

```text
暴力枚举（保证找到最优） + 界函数剪枝（避免枚举无望子树） = 精确且尽量快
```

它不放弃"最优性保证"（这是它区别于贪心、启发式的根本），也不像动态规划那样依赖子问题重叠结构（这是它区别于 DP 的根本）。

## 2. 解空间树：三种基本形态

解空间树是分支限界工作的舞台。不同的问题类型对应不同的树形态：

### 2.1 子集树（Subset Tree）

每个结点分两支：**选 / 不选**。树高 n，叶子数 2ⁿ。

```text
            []
         /      \
       [x1]    [~x1]
       /  \     /  \
    [x2][~x2][x2][~x2]
    ...          ...
```

| 适用问题 | 特点 |
|---------|------|
| 0-1 背包 | 每个物品 选/不选，容量约束 |
| 装载问题 | 集装箱 装/不装，重量约束 |
| 最大团 / 独立集 | 顶点 加入/不加入，冲突约束 |

> 🎯 判断口诀：**"每项一个二选一"→ 子集树**，规模 O(2ⁿ)。

### 2.2 排列树（Permutation Tree）

每个结点对应"确定第 i 个位置的元素"，剩余元素全排列。叶子数 n!。

```text
            []
      /   |    \   ...
   [a]  [b]  [c]
   /|\   ...  ...
[b][c] ...
```

| 适用问题 | 特点 |
|---------|------|
| 旅行商 TSP | 确定访问顺序，首尾闭环 |
| 作业调度 / 分配 | 确定处理顺序或任务分配 |
| 八皇后（变体） | 每行放哪一列（其实是 nⁿ 到 n! 的剪枝后） |

> 🎯 判断口诀：**"顺序决定答案"→ 排列树**，规模 O(n!)。

### 2.3 满 m 叉树（m-ary Tree）

每个结点有 m 个选择（m > 2）。例如把 n 个作业分给 m 台机器，或数独、图着色。

```text
            []
      /   |   |   \
   [1]  [2]  [3]  [4]    ← m = 4
    ...
```

规模 O(mⁿ)。满 m 叉树本质上是"更宽的决策"，剪枝空间往往更大，**界函数的意义也更大**。

## 3. 结点的三态与状态转移

分支限界在搜索过程中维护三种状态的结点：

| 状态 | 定义 | 生命周期 |
|------|------|---------|
| **活结点（Live Node）** | 已生成、尚未被完全扩展的结点 | 进入活结点表（队列/堆）等待扩展 |
| **扩展结点（E-Node）** | 正在被扩展的活结点（生成其全部子结点） | 从活结点表弹出后、扩展中 |
| **死结点（Dead Node）** | 全部子结点已生成，或已被限界剪枝的结点 | 出表后不再回来 |

状态转移图：

```text
生成子结点
   ┌────────────────────────┐
   ▼                        │
活结点 ──弹出/选取──▶ 扩展结点 ──扩展完/被剪──▶ 死结点
   ▲                        │
   └───────── 未剪的子结点入表 ┘
```

> 💡 关键理解：**结点一旦成为死结点就再也不会被访问**——这正是分支限界与回溯的本质差异：回溯可以"撤销选择、回到父结点再次搜索"（同一路径反复经过），分支限界每个结点只被扩展一次。

## 4. 分支与限界：两个核心操作

### 4.1 分支（Branch）

扩展当前结点时，**一次性生成它的全部子结点**（而不是像 DFS 那样只沿一条路深入），然后：

1. 对每个子结点计算约束可行性（**约束函数**检查）
2. 计算界函数值（**限界函数**估算）
3. 不可行或界值不优于当前最优解的 → 直接丢弃
4. 幸存者 → 进入活结点表

"分支"保证了**完备性**：所有可能解都被系统地枚举到。

### 4.2 限界（Bound）

限界是整个算法的灵魂，包含两层含义：

**① 剪枝**：设当前已找到的最优解为 best（当前最优目标值）。则：

| 优化方向 | 剪枝条件 | 剪枝含义 |
|---------|---------|---------|
| 最大化 | ub(结点) ≤ best | 该子树最优值不可能超过 best，剪掉 |
| 最小化 | lb(结点) ≥ best | 该子树最优值不可能低于 best，剪掉 |

**② 排序**：优先队列式用界值决定扩展顺序，界值最好的结点先扩展（Best-First），让最优解更早出现、剪枝更早生效。

> 🎯 把"限界"理解为双刃：**对每个结点，界值既是"值不值得继续挖"的判决书，也是"先挖哪个"的优先级**。

### 4.3 约束函数 vs 限界函数

| | 约束函数（可行性剪枝） | 限界函数（最优性剪枝） |
|--|---------------------|---------------------|
| 检查内容 | 部分解是否仍可能完整可行 | 子树最优值是否可能优于 best |
| 剪枝依据 | 违反约束（如超容量） | 界值不优于 best |
| 类比回溯 | 回溯只有这一种剪枝 | 分支限界独有 |

回溯法只有约束剪枝（还能剪"不可能完整可行"的结点吗？——回溯没有界函数，它会走到底才知道结果）。分支限界**两者都有**，这就是它通常比回溯快的原因。

## 5. 搜索策略概览：FIFO / LIFO / Best-First

活结点表的数据结构决定了搜索顺序。三种主流策略（02 文件详解）：

| 策略 | 活结点表 | 扩展顺序 | 特点 |
|------|---------|---------|------|
| 队列式（FIFO） | 队列 Queue | 先来先扩展（BFS） | 简单、直观、空间大、不剪最优 |
| 栈式（LIFO） | 栈 Stack | 后进先扩展（类 DFS） | 空间小、策略不优、较少用 |
| 优先队列式（Best-First / LC） | 堆 Heap | 界值最优者先扩展 | 最快找到最优解、支持提前终止 |

> 💡 优先队列式也叫 **LC-搜索（Least Cost 或 Best First）**：每个结点按"代价/效益估计"排队，界值最优（最小化问题中 lb 最小 = 最有希望）的结点最先扩展。

## 6. 算法正确性的三个前提

分支限界要保证**一定找到全局最优解**，必须同时满足：

### 前提 1：界函数合法（界必须真是界）

- 最大化问题：ub(结点) 必须是该子树内**所有可行解目标值的上界**（即 ≥ 子树内任何可行解的值）
- 最小化问题：lb(结点) 必须是子树内所有可行解目标值的**下界**（≤ 任何可行解的值）

> ⚠️ 若 ub 低估了子树最大值（非法上界），可能把含最优解的子树剪掉 → 结果错误。**界函数可以松（剪枝少、慢），但绝不能错（会丢最优解）**。

### 前提 2：单调性（父与子的界不能倒挂）

- 最大化：ub(父) ≥ ub(子)
- 最小化：lb(父) ≤ lb(子)

违反单调性会导致**包含最优解的子树被错误剪掉**——父结点因为界值不好被剪，但它的某个子结点（界值更好）却含最优解。

### 前提 3：根结点的界包含最优解

根结点（空解）的界必须覆盖全局最优值，即 ub(根) ≥ 最优解。这是递归的起点，由前提 1 在根处自然保证。

> 🎯 **自检三连**：界合法吗？单调吗？根覆盖最优吗？三个问题都答"是"，算法就保证正确。**再强调一次：界松不致命，界错才致命。**

## 7. 适用条件判断：什么时候用分支限界

实际做题/面试时用这个决策链：

```text
问题要求"最优值/最优方案"？
├─ 是 → 解空间能否显式枚举（树/图）？
│      ├─ 否 → 数值优化 / 线性规划，考虑求解器
│      └─ 是 → 能否设计合法且较紧的界函数？
│             ├─ 否 → 回溯 + 剪枝 / DP（若有重叠子问题）
│             └─ 是 → ✔ 分支限界适用
└─ 否（只求一个可行解/所有解）→ 回溯 / BFS / DFS
```

| 判断维度 | 适合分支限界 | 不适合 |
|---------|-------------|--------|
| 目标 | 求最优解（值或方案） | 只求可行解、求所有解 |
| 结构 | 有天然的解空间树 | 无显式枚举结构 |
| 界函数 | 能设计合法且够紧的界 | 界只能设计成 ±∞（退化为穷举） |
| 规模 | n 适中（背包 n≤50、TSP n≤20 量级） | 极大规模 → 用近似/元启发式或求解器 |

> ⚠️ 经验之谈：**n 很大（比如 TSP n > 40）时，精确分支限界仍然跑不动**，业界会转向启发式（模拟退火、遗传算法）或带时间限制的求解器（Gurobi 的 MIP 也靠 B&B + 割平面 + 启发式混合，但那是工业级工程）。面试答"适用边界"是加分点。

## 8. 与暴力枚举 / BFS 的关系

### 8.1 分支限界 ⊇ BFS

队列式分支限界 = BFS + 约束剪枝 + 限界剪枝。把限界函数去掉、只保留约束剪枝，FIFO 分支限界退化为带剪枝的 BFS；再去掉约束剪枝就退化为纯 BFS。**BFS 是分支限界的最朴素形态**。

### 8.2 分支限界 ⊇ Dijkstra / A*

- **Dijkstra**：本质是优先队列式分支限界——lb(结点) = 已确认路径长度，是严格合法的下界（因为边权非负）
- **A***：B&B + 可采纳启发式（h(n) ≤ 真实代价），即 lb = g(n) + h(n)，正是"界函数紧化"的思想

这个视角在 07 文件详细展开。先记住：**分支限界不是孤立算法，而是一个"界函数 + 搜索策略"的框架，套上不同的界就得到 Dijkstra、A*、求解器核心**。

> 🎯 **核心要点**：分支限界 = 解空间树（舞台） + 分支（完备性保障） + 限界（效率来源） + 活结点表策略（搜索顺序）。正确性的全部秘密在界函数：**合法、单调、根覆盖最优**。它和回溯的差异不是"剪枝力度"而是"搜索骨架"：回溯是 DFS 一路到底再回头，分支限界是广度铺开、按界择优。
