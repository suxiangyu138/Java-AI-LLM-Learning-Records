## 2. 五步法实战演练

### 2.1 演练题：322 零钱兑换（完整五步）

```java
// 322 零钱兑换（最少的硬币数）
public int coinChange(int[] coins, int amount) {
    // ① 状态: dp[j] = 凑出金额 j 的最少硬币数
    int[] dp = new int[amount + 1];
    // ③ 初始化: dp[0]=0（0 元 0 枚），其余 INF（不可达）
    Arrays.fill(dp, amount + 1);
    dp[0] = 0;

    // ④ 遍历: 完全背包正序（每枚可重复用）
    for (int coin : coins) {
        for (int j = coin; j <= amount; j++) {
            // ② 转移: 用 coin 或不用的最小值
            dp[j] = Math.min(dp[j], dp[j - coin] + 1);
        }
    }
    // ⑤ 优化: 一维滚动已是最优
    return dp[amount] > amount ? -1 : dp[amount];
}
```

**五步复盘**：

```text
① 状态: dp[j] = 金额 j 的最少硬币（容量维度）
② 转移: dp[j] = min(dp[j], dp[j-coin]+1)（最后一枚硬币）
③ 初始化: dp[0]=0、其余 INF（区分不可达）
④ 遍历: 正序（完全背包可重复取）
⑤ 优化: 一维已最优（无多余维度）

识别: 「最少数量 + 可重复选」→ 完全背包最值
```

### 2.2 建模练习（看题 → 五步 → 模型）

```text
题 1: 不同路径（62）
  → 状态: dp[i][j] 到 (i,j) 路径数
  → 转移: dp[i][j] = dp[i-1][j] + dp[i][j-1]
  → 模型: 网格计数（线性二维）

题 2: 单词拆分（139）
  → 状态: dp[i] 前 i 个字符可拆
  → 转移: dp[i] = OR(dp[j]) 对 j..i 是单词
  → 模型: 线性 + 集合查

题 3: 编辑距离（72）
  → 状态: dp[i][j] 前 i 转前 j 最小编辑
  → 转移: 相等 dp[i-1][j-1] / 替换/插入/删除
  → 模型: 二维线性（双序列）
```

> 💡 **建模训练法**：每天 5 题「只建模不写码」（口述状态/转移/模型）——比盲目刷题高效 10 倍；建模 = 状态 + 转移，实现是体力活。

## 3. DP 面试话术

### 3.1 解题流程话术

```text
「我按五步来分析:
  ① 状态: dp[i] 表示...
  ② 转移: 最后一个选择是...所以 dp[i] = ...
  ③ 初始化: dp[0] = ...
  ④ 遍历: 因为依赖...所以正/逆序
  ⑤ 优化: 只依赖前两个，可以滚动数组 O(1)
  （顺便说复杂度: 时间 O(n)、空间 O(1)）」
```

### 3.2 高频追问与标准答案

| 追问 | 标准答案 |
|------|---------|
| 为什么能用 DP？ | 最优子结构 + 重叠子问题（举例） |
| 状态为什么这么定义？ | 「以 i 结尾/前 i 个」使转移可表达 |
| 转移怎么想到的？ | 问「最后一个选择」枚举所有可能 |
| 为什么背包逆序？ | 防同一物品重复取 |
| 怎么优化空间？ | 滚动数组（只留依赖行） |
| 复杂度？ | 时间 O(n²)/O(n³)、空间可滚 |
| 与贪心区别？ | 贪心局部最优需证明、DP 枚举子问题保证 |
| 写记忆化可以吗？ | 可以——自顶向下与自底向上等价 |

### 3.3 面试表现要点

```text
✅ 加分表现:
  ① 先说出五步法框架（显示方法论）
  ② 讲清「最后一个选择」（显示建模能力）
  ③ 主动分析复杂度与优化（显示工程意识）
  ④ 讨论边界（空数组/单元素/溢出）

❌ 减分表现:
  ① 闷头写码不讲思路
  ② 状态定义含糊
  ③ 不分析复杂度
  ④ 初始化边界遗漏
```

> 🎯 **面试心法**：DP 题面试官考的是**建模过程**而非代码——「状态为什么这么定义」比「代码对不对」重要；把五步法说出口 = 把思考过程可视化。

## 4. 易错点清单

| # | 易错点 | 后果 | 对策 |
|---|--------|------|------|
| 1 | 状态定义含糊 | 转移写不出 | 先大声说状态 |
| 2 | 初始化漏边界 | 结果错 | dp[0]/空态先验证 |
| 3 | 背包遍历顺序错 | 重复取/漏取 | 0-1 逆序、完全正序 |
| 4 | 区间先起点后长度 | 依赖缺失 | **先长度后起点** |
| 5 | 树形用前序 | 子树未算 | 必须后序 |
| 6 | 53 题取 dp[n-1] | 子数组结尾错 | max 所有 dp |
| 7 | 计数背包初始化 0 | 方案数全 0 | dp[0]=1 |
| 8 | 滚动数组更新顺序 | 覆盖未用值 | 先算后用（逆序） |
| 9 | 状态压缩忘位运算 | mask 错 | 1<<i / mask\|bit |
| 10 | 数位 DP 缓存贴上限 | 缓存污染 | 只缓存 tight=0 |

**三问排查法**：

```text
DP 结果不对时:
  ① 状态对吗？   → 重述状态定义（是否缺维度）
  ② 转移全吗？   → 枚举最后一步所有可能
  ③ 顺序对吗？   → 依赖方向（背包逆序/区间长度）
```

> ⚠️ **十个易错点的共性**：全部来自「状态/转移/顺序」三要素的理解偏差——**排查从三要素入手**，比盲改代码高效。
