## 1. 单调性论证的完整体系

### 1.1 为什么需要论证

```
双指针的每一步"排除一批解"
  被排除的解中可能有最优解吗？
  → 需要数学论证（单调性）

⚠️ 面试必答：
"双指针的正确性不是直觉，是单调性——
 指针移动方向与结果变化方向单调对应，
 被排除的组合不可能包含最优解。"
```

### 1.2 三种论证模式

```
① 有序单调性（167 两数之和）：
   有序数组 → sum 与指针移动方向单调对应

② 短板效应（11 盛水）：
   容量由矮边决定 → 移高边容量必变小

③ 速度差（141 判环）：
   相对速度 1 → 必然相遇

⚠️ 识别：
  "有序数组" → 单调性论证
  "面积/容量" → 短板论证
  "链表环" → 速度差论证
```

### 1.3 面试表达框架

```
"为什么双指针是对的？
 ① 每轮移动【指针】时，
 ② 被排除的组合是【哪些】，
 ③ 由【单调性/短板/速度差】保证它们不可能含最优解，
 ④ 所以贪心地移动是安全的。"
```

## 2. 对撞指针的正确性证明

### 2.1 167. 两数之和（有序单调性）

```java
/**
 * 证明框架：
 * 当前和 sum = nums[left] + nums[right]
 *
 * ① sum < target → 移动 left
 *    需要更大的和 → 只有左指针右移（值变大）
 *    → 排除"所有以 nums[left] 为左端点的组合"
 *    ⚠️ 这些组合的和 ≤ 当前 sum < target → 不可能有答案
 *
 * ② sum > target → 移动 right
 *    同理排除"所有以 nums[right] 为右端点的组合"
 *
 * 数学依据：有序性 → 指针移动方向与和的变化单调对应
 */
public int[] twoSum(int[] numbers, int target) {
    int left = 0, right = numbers.length - 1;
    while (left < right) {
        int sum = numbers[left] + numbers[right];
        if (sum == target) return new int[]{left + 1, right + 1};
        else if (sum < target) left++;
        else right--;
    }
    return new int[0];
}
// 推演 [2,7,11,15], target=9：
//   sum=17>9 → right--（排除 15 的组合）
//   sum=13>9 → right--（排除 11 的组合）
//   sum=9 ✓ → [1,2]
// ⚠️ 每步安全排除一批 → O(n) 而非 O(n²)
```

### 2.2 11. 盛水容器（短板效应）

```java
/**
 * 证明框架：
 * 容量 = min(左高, 右高) × 宽度
 *
 * ① 移动高边：
 *    宽度变小，高度不变（还是矮边）→ 容量必变小
 *    → 移动高边永远不可能找到更优解 → 安全排除
 *
 * ② 移动矮边：
 *    宽度变小，但高度可能变大 → 有希望
 *    → 只有移动矮边才可能找到更优解
 *
 * → 每次移动"矮边"是正确的
 */
public int maxArea(int[] height) {
    int left = 0, right = height.length - 1;
    int maxWater = 0;

    while (left < right) {
        int width = right - left;
        int h = Math.min(height[left], height[right]);
        maxWater = Math.max(maxWater, width * h);

        if (height[left] < height[right]) left++;   // ⚠️ 移动矮边
        else right--;
    }
    return maxWater;
}
// ⚠️ 面试必答："短板效应——容量由矮边决定，
//   移高边必变小（无希望），移矮边才有希望"
```

### 2.3 42. 接雨水（矮边确定）

```java
/**
 * 证明框架：
 * 位置 left 的接水量 = min(左最高, 右边最高) - height[left]
 *
 * 当 leftMax < rightMax 时：
 *   右边最高 ≥ rightMax > leftMax
 *   → min(左最高, 右边最高) = leftMax（可确定！）
 *   → water += leftMax - height[left]
 *
 * 同理 rightMax < leftMax 时右边可确定
 * → 每次移动"最高值较小"的一侧
 */
public int trap(int[] height) {
    int left = 0, right = height.length - 1;
    int leftMax = 0, rightMax = 0;
    int water = 0;

    while (left < right) {
        leftMax = Math.max(leftMax, height[left]);
        rightMax = Math.max(rightMax, height[right]);

        if (leftMax < rightMax) {
            water += leftMax - height[left];   // 矮边确定
            left++;
        } else {
            water += rightMax - height[right];
            right--;
        }
    }
    return water;
}
// ⚠️ 三解法对比：
//   暴力 O(n²)；DP O(n)/O(n)；双指针 O(n)/O(1) ★
```

## 3. 快慢指针的数学原理

### 3.1 为什么走 2 步

```
判环场景（141）：
  slow 走 1 步，fast 走 2 步
  相对速度 = 2 - 1 = 1（每轮差距减 1）
  环长 L → 最多 L 轮追上 → 必然相遇

⚠️ 如果走 3 步？
  相对速度 = 2（每轮差距减 2）
  环长不是 2 的倍数时可能永远跳过
  例：环长 3，fast 每次跳 2 → 可能错过

⚠️ 面试必答：
"走 2 步保证相对速度 1——
 任何环长下必然相遇。"
```

### 3.2 142. 找环入口的数学推导

```
设：
  a = 链表头到环入口的距离
  b = 环入口到相遇点的距离
  c = 相遇点到环入口的剩余距离
  环长 L = b + c

slow 走 = a + b
fast 走 = a + b + kL（k 圈）
且 fast = 2 × slow

⇒ 2(a+b) = a+b+kL
⇒ a + b = kL
⇒ a = kL - b = (k-1)L + (L-b) = (k-1)L + c

结论：从 head 走 a 步 与 从相遇点走 a 步
     都会到达环入口！

阶段 2 实现：
  slow 重置 head，fast 留在相遇点
  同速走 1 步 → 再次相遇 = 环入口 ✓
```

### 3.3 快慢指针应用汇总

```
① 判环（141）：相遇即有环
② 找入口（142）：相遇后重置同速走
③ 找中点（876）：fast 到头 slow 在中点
④ 倒数第 N（19）：fast 先走 N+1
⑤ 快乐数（202）：数字版判环
⑥ 找重复数（287）：数组下标跳跃判环

⚠️ 统一模型：
  "快慢指针 = 相对速度 1 的追击问题"
```

## 4. 双指针的组合应用

### 4.1 三指针（固定 + 对撞）

```
15 三数之和：排序 → 固定一个 → 双指针
  复杂度：O(n²)（固定 O(n) × 双指针 O(n)）
  去重三处（固定数/左指针/右指针）

⚠️ 双指针 + 排序的组合：
  排序让双指针可用（单调性）
  排序让去重可行（相邻相同）
```

### 4.2 双指针 + 贪心

```
881 救生艇：最重配最轻（对撞 + 贪心）
  最重的人：
    能配最轻 → 一起走（双指针都动）
    配不了 → 单独走（只动右指针）

⚠️ 识别：
  "最大配最小/最重配最轻" → 排序 + 对撞
```

### 4.3 双指针 + 哈希

```
双指针找两数（有序版 167）→ 双指针
无序版（1 两数之和）→ 哈希
15 三数之和：排序 + 双指针（不重复）

⚠️ 选型：
  有序数组 → 双指针（O(1) 空间）
  无序数组 → 哈希（O(n) 空间）
```

### 4.4 多指针（数组版）

```
75 颜色分类：三指针（p0/p2/curr）
  ⚠️ 2 交换后 curr 不前进（可能还是 2）

⚠️ 三指针 vs 双指针：
  双指针：两端信息
  三指针：三段分区（荷兰国旗）
```

## 5. 双指针的失效场景

### 5.1 无序数组找两数

```
无法判断移动方向：
  无序数组 sum < target → 移动 left 还是 right？
  两者都可能（值分布未知）→ 双指针失效

✅ 解法：哈希（1 两数之和）
  或排序后双指针（167）

⚠️ 面试必答：
"双指针需要单调性——无序数组无法
 判断移动方向，用哈希或先排序。"
```

### 5.2 含负数的滑窗

```
含负数 → 窗口和不单调：
  扩窗可能减小和 → 无法判断缩窗还是扩窗

✅ 解法：前缀和 + 哈希（560）

⚠️ 识别：
  "连续子数组 + 含负数" → 前缀和而非滑窗
```

### 5.3 失效场景总结

| 场景 | 失效原因 | 替代 |
|------|------|------|
| 无序找两数 | 无法判断方向 | 哈希/排序 |
| 含负数子数组 | 不单调 | 前缀和+哈希 |
| 非单调面积 | 短板失效 | 枚举/DP |
| 带权最短路 | 需要全局 | Dijkstra |

```
⚠️ 判断标准：
  "指针移动时能否安全排除一批解？"
  能 → 双指针；不能 → 换思路
```

## 6. 进阶总结

### 6.1 进阶要点速查

```
① 单调性论证：有序单调/短板效应/速度差
② 对撞证明：排除"以端点为界的组合"
③ 快慢数学：相对速度 1 + 142 推导
④ 组合应用：三指针/贪心/哈希/多指针
⑤ 失效场景：无序/含负数 → 换思路
```

### 6.2 面试话术模板

```
"这题用【对撞/快慢】双指针：
 ① 指针语义【left 最左，right 最右】；
 ② 移动规则【条件 → 移动哪个】；
 ③ 正确性论证【单调性/短板/速度差】——
   被排除的组合不可能含最优解；
 ④ 复杂度 O(n) 时间 O(1) 空间。
 追问失效场景：【无序/含负数】时...。"
```

### 6.3 易错点清单

| 错误 | 后果 | 修正 |
|------|------|------|
| 无序用双指针 | 结果错 | 先排序/哈希 |
| 移动方向反 | 排除错误 | 单调性确认 |
| 忘排除论证 | 面试减分 | 讲"为什么安全" |
| 循环条件 <= | 重复处理 | 用 < |
| 三数忘去重 | 重复结果 | 三处去重 |

> 🎯 **核心要点**：双指针进阶 = **单调性论证**（有序/短板/速度差）+ **组合应用**（三指针/贪心/哈希）+ **失效识别**（无序/含负数）。"被排除的组合不可能含最优解"是统一证明框架；142 数学推导与矮边确定是两个必答细节。
