## 4. 核心概念速查

| 概念 | 一句话解释 | 典型例题 |
|------|-----------|------|
| **递归** | 函数调用自身，问题规模逐层缩小 | 阶乘、斐波那契 |
| **三要素** | 基线条件、递推关系、收敛性 | 所有递归题 |
| **调用栈** | 每次调用压入栈帧，深度 = 递归深度 | 栈溢出分析 |
| **递归树** | 递归调用关系画成树，分析复杂度 | 斐波那契 O(2ⁿ) |
| **递与归** | 递 = 向下调用，归 = 向上返回（两个阶段） | 206 反转链表 |
| **记忆化** | 缓存中间结果去重 | 509 斐波那契 |
| **尾递归** | 递归是最后一步，可被编译器优化 | 斐波那契累加器版 |
| **主定理** | 分治递推式 T(n)=aT(n/b)+f(n) 的复杂度公式 | 归并排序 O(n log n) |
| **分治** | 递归 + 拆分 + 合并 | 归并排序 |
| **显式栈** | 用栈模拟递归，避免爆栈 | 递归转迭代 |
| **基线条件** | 最小规模直接返回（递归的出口） | 缺失 → 栈溢出 |

## 5. 复杂度速查表

| 递推式 / 递归 | 复杂度 | 说明 |
|------|:---:|------|
| 单路递归（阶乘） | O(n) 时间 / O(n) 栈空间 | 深度 = n |
| 朴素斐波那契 | O(2ⁿ) | 大量重复计算（灾难） |
| 记忆化斐波那契 | O(n) | 每个状态算一次 |
| 归并排序 | O(n log n) / O(n) | 主定理情况 2 |
| 快排（平均） | O(n log n) | 最坏 O(n²) |
| 二叉树遍历 | O(n) / O(log n)~O(n) | 每个结点访问一次 |
| 二叉树高度 | O(n) | 递归深度 = 树高 |
| 排列递归 | O(n!) | 回溯家族 |
| 子集递归 | O(2ⁿ) | 回溯家族 |

> 🎯 **递归复杂度的两个维度**：**时间**（总调用次数 × 每次成本）与**空间**（最大递归深度，即栈大小）。面试答复杂度必须同时说两个维度——"时间 O(n)、空间 O(n) 栈"才算完整。

## 6. 常见误区速查

| 误区 | 正解 |
|------|------|
| "递归效率总是低" | ❌ 取决于写法：朴素斐波那契 O(2ⁿ) 低，记忆化 O(n) 不输迭代 |
| "递归深度 = 调用次数" | ❌ 归并排序调用 O(n) 次但深度只有 O(log n) |
| "递归一定能转迭代" | ❌ 带状态保存的复杂递归转迭代需要显式栈，不一定更简洁 |
| "基线条件随便写" | ❌ 基线是正确性根基——缺失必爆栈，写错必出错 |
| "尾递归在 Java 中自动优化" | ❌ Java 不支持尾调用消除（TCO），需手动转循环/累加器 |
| "树问题只能用递归" | ❌ 迭代（显式栈）也可，但递归最简洁自然 |
| "递归和分治是同一概念" | ❌ 递归是机制，分治是思想（递归 + 拆分 + 合并） |
| "记忆化 = 缓存所有参数" | ❌ 只缓存"可复现"的状态参数，且要控制缓存维度 |

## 10. 一句话速记卡

```text
递归三要素: 基线 / 递推 / 收敛 —— 缺一不可
递与归:     调用前是"去时任务"，调用后是"回来任务"
树递归选序: 要子树答案→后序；传父层信息→前序；有序输出→中序
两大杀手:   重复计算（→记忆化）/ 栈溢出（→迭代/尾递归）
复杂度双维: 时间=调用次数×成本；空间=最大递归深度
分治判据:   子问题独立 + 需要组合 → 分治；重叠 → DP
递归是底盘: 回溯/DFS/分治/DP 全部建立在递归之上
```

> 🎯 **核心要点**：递归验收三件事——**① 三要素脱口而出**（基线/递推/收敛，缺失必爆栈）；**② 能画出调用栈与递归树**（解释"递与归"两个阶段、先序/后序动作）；**③ 掌握两大优化**（记忆化治重复计算、尾递归/显式栈治栈溢出）。**递归是算法大厦的底盘**——回溯、DFS、分治、DP 全部建立其上，理解递归 = 理解这些算法的一半。
