## 1. 递归题的标准答题流程

面试拿到递归题，按五步走（这是把"会做"变成"讲得清楚"的关键）：

```text
① 三问框架（30 秒）: 终止条件？返回值？本层做什么？
   → 先说这三点，展示结构化思维（03/04 文件的三问）

② 递/归推演（1 分钟）: 小样例（n=3 或 3 节点树）口推一遍
   → "先走到基线，返回路上做 XXX"——展示理解而非背诵

③ 写码（3-5 分钟）: 基线最先写 → 递归调用 → 返回处理

④ 复杂度（30 秒）: 时间 = 调用次数 × 每次成本
                  空间 = 最大递归深度（两个维度都要说！）

⑤ 预案（30 秒）: "深度 O(n) 有栈溢出风险，我可以转显式栈迭代"
   → 主动暴露风险 + 给出方案 = 工程素养
```

> 🎯 **面试官心理**：递归题不只看代码对不对，更看**"能否解释为什么这样递归"**——三问框架 + 递/归推演是区分"背题"与"懂题"的分水岭。

## 3. 必背话术：三要素与复杂度

### 3.1 三要素话术（任何递归题开场）

> "递归三要素：**基线条件**（最小规模直接返回）、**递推关系**（把问题规模缩小）、**收敛性**（每次调用规模必减）。这道题基线是【……】，递推是【……】，所以每次调用规模从【n】降到【n−1 / n/2】，保证收敛。"

### 3.2 复杂度双维度话术

> "时间上，总调用次数 × 每次成本，这题是【O(n)】；空间上，递归深度是【树高 h / 链长 n】，所以空间是【O(h) / O(n)】。如果深度可能很大，我会转显式栈迭代来规避栈溢出。"

> ⚠️ **只说一个维度 = 扣分**——时间 + 空间必须成套说出，且空间要说"递归栈"而非"额外数组"。

### 3.3 面试收尾话术

> "这题我还可以用迭代实现（显式栈/循环），空间能降到 O(1)【如适用】；递归版的好处是和问题结构一致、可读性好，工程上深度可控时我会优先递归。"

## 4. 高频追问与标准回答

| # | 追问 | 标准回答 |
|:---:|------|---------|
| 1 | 递归 vs 迭代怎么选？ | 结构自相似（树/链表）用递归更自然；深度不可控或追求 O(1) 空间用迭代 |
| 2 | 栈溢出怎么办？ | ① 分析深度（O(h) 安全，O(n) 危险）② 转显式栈迭代 ③ 尾递归（Java 不自动优化） |
| 3 | 尾递归是什么？ | 递归是函数最后一步、结果直接返回；函数式语言可优化为循环复用栈帧；Java 需手动转 |
| 4 | 这题能尾递归化吗？ | 能被"累加器"改写才行（如阶乘）；树递归需要后序聚合，不能尾递归化 |
| 5 | 递归和 DP 的关系？ | 记忆化递归 = 自顶向下 DP；迭代 DP = 自底向上；两者等价，都是"去重叠" |
| 6 | 为什么斐波那契朴素递归是 O(2ⁿ)？ | 递归树满二叉：f(n) 调 f(n−1) 和 f(n−2)，节点数 2ⁿ；且有大量重复子树（f(3) 出现 2 次） |
| 7 | 归并为什么稳定 O(n log n)？ | 严格对半拆分 → 递归树永远平衡；merge 用 `<=` 保持相等元素相对顺序 |
| 8 | 递归能解决哪些"非递归"问题？ | 分治（归并/快排）、回溯（DFS）、记忆化（DP）、树/链表结构处理——递归是"思想载体" |

## 5. 易错点复盘清单

| 易错点 | 症状 | 根因 | 防线 |
|--------|------|------|------|
| 漏基线 | StackOverflowError | 最小规模没覆盖 | 基线最先写 + 空/单元素测试 |
| 参数不收敛 | 无限递归/死循环 | 递归参数没有严格减小 | 检查"每次调用规模必减" |
| 返回值语义错 | 答案错但代码"合理" | 没说清返回什么 | 写前用一句话定义返回值 |
| 共享容器未拷贝 | 结果全部相同 | Java 引用传递 | new ArrayList<>(path) |
| 忘撤销 | 结果多了/乱了 | 递阶段改状态、归阶段没恢复 | 对称性原则（03 文件 6.2） |
| 深链硬递归 | 运行超时/溢出 | n 大 + 深度 O(n) | 预判深度 → 主动转迭代 |
| 只报时间不报空间 | 复杂度答案不完整 | 忘了递归栈 | "时间 X 空间 Y"成套说 |
| 边界区间错 | 分治结果错 | 区间开闭不一致 | 统一 [l, r] 闭区间 + mid 防溢出 |

## 6. AI 时代的递归观

2026 年的视角：AI 编程助手（Cursor、Copilot 等）能瞬间生成递归代码，但**判断力仍是人类的**：

```text
AI 能写:  标准递归题（模板类）——但可能:
          ① 基线条件不完整（边界漏一种）
          ② 复杂度爆炸（朴素递归直接给）
          ③ 深链不转迭代（栈溢出隐患）

你需要会: ① 审查 AI 代码的三要素是否完备
          ② 评估复杂度是否满足数据范围
          ③ 指出栈溢出风险并要求转迭代

面试表达: "AI 能生成递归模板，但判断基线完备性、
          复杂度可行性和栈风险，需要真正理解递归的人"
```

> 🎯 面试官其实在考察"**你会不会验证递归的正确性**"——三问框架、递归树数节点、边界测试，这三件事就是 AI 时代递归能力的核心增量。**"懂递归的人用 AI 如虎添翼，不懂的人被 AI 带进坑里"**——这句可以作为收尾金句。

## 7. 模拟面试实录（一问一答）

**场景**：面试官出题 104 二叉树最大深度。完整实录：

```text
👨💻 我（三问框架）:
  "我先定义递归三要素。终止条件：空节点返回 0；
   返回值：子树的高度；本层逻辑：左右子树高度取最大再加 1。
   这是后序聚合——先问子树，再算自己。"

👨💻 我（写码）:
  public int maxDepth(TreeNode root) {
      if (root == null) return 0;
      int l = maxDepth(root.left);
      int r = maxDepth(root.right);
      return Math.max(l, r) + 1;
  }

👨💻 我（复杂度双维度）:
  "时间 O(n)——每个节点访问一次；
   空间 O(h)——递归栈深度等于树高，h 是树高不是 n；
   最坏情况树退化成链时 h = n，有栈溢出风险。"

👨💻 我（主动补充）:
  "如果需要，我可以转显式栈迭代版本，空间不变（也要 O(h) 栈），
   但规避了默认栈限制。"
```

> 🎯 **实录要点**：全程 5 个节点（三问 → 码 → 双维复杂度 → 最坏分析 → 迭代预案），**没有一句"我不会"、没有一处停顿**——这就是"会讲"的标准形态。

## 8. 考前 30 分钟冲刺清单

```text
默写四件套（各 3 分钟）:
  □ 斐波那契三版（朴素/记忆化/迭代）
  □ 反转链表（递归 + 迭代）
  □ 前中后序遍历模板
  □ 归并排序（含 merge）

背诵三话术（各 1 分钟）:
  □ 三要素话术（基线/递推/收敛）
  □ 复杂度双维度话术（时间 × 空间，空间说递归栈）
  □ 栈溢出预案话术（分析深度 → 显式栈/尾递归）

过一遍易错点（3 分钟）:
  □ 深拷贝   □ 同层去重   □ 基线全覆盖   □ 归阶段对称撤销
```

### 8.1 十分钟自测（模拟开考）

```text
题目: 反转链表（递归版）
① 30 秒: 说出三问（基线: 空/单节点返回自身；
            返回值: 反转后的新头；本层: 后继指向自己 + 断旧链）
② 90 秒: 默写代码（5 行）
③ 30 秒: 复杂度（O(n) 时间 / O(n) 栈空间）
④ 30 秒: 预案（"长链场景转三指针迭代，O(1) 空间"）
⑤ 60 秒: 推演 1→2→3（归阶段逐环反转的过程）
自评: ⑤ 分钟内完成 ①②③④，⑤ 能讲清楚 → 过关
```

> 🎯 **核心要点**：递归面试通关 = **五步流程**（三问 → 推演 → 写码 → 双维度复杂度 → 栈溢出预案）+ **三档题单**（5 道必背 + 5 道高频 + 5 道进阶）+ **8 条追问库**。最容易被忽视的是"讲"——**每道题都能 1 分钟讲清"递/归"两个阶段发生了什么**，这是区分背题与懂题的试金石。考前按冲刺清单过一遍，稳进面试状态。
