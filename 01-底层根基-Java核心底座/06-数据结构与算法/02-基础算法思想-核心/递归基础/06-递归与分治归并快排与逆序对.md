## 1. 分治三步骤：拆、解、合

**分治（Divide and Conquer）**不是新的机制，而是递归的一种**应用模式**（01 文件 4.2 已给三步曲，此处展开成可操作的框架）：

```text
① 分解（Divide）  : 把问题拆成若干独立子问题（通常两半）
② 解决（Conquer） : 递归求解子问题
③ 合并（Combine） : 把子结果组合成原问题的答案

分治的基线: 问题小到可以直接解（如只剩一个元素）
```

| 分治三问 | 归并排序的答案 |
|---------|---------------|
| 拆什么？ | 数组从中间切成两半 |
| 解什么？ | 两半各自递归排序 |
| 合什么？ | 两个有序数组合并（merge） |
| 基线？ | 长度为 0/1 已经有序 |

> 🎯 **分治 vs 普通递归的分水岭**：普通递归"缩小规模后直接利用结果"（阶乘 n×(n−1)!）；分治"**拆成多个独立子问题，答案必须由子答案组合而来**"（归并 n = 左有序 + 右有序 合并）。**子问题相互独立、组合出答案**是分治的判据。

## 2. 归并排序：分治的教科书实现

### 2.1 完整实现

```java
// 归并排序: 分治三步 + 归并（核心是 merge 的稳定性）
public void mergeSort(int[] arr, int l, int r) {
    if (l >= r) return;                        // 基线：单元素已有序
    int mid = l + (r - l) / 2;                 // ① 分解：取中点
    mergeSort(arr, l, mid);                    // ② 解决：左半排序
    mergeSort(arr, mid + 1, r);                // ② 解决：右半排序
    merge(arr, l, mid, r);                     // ③ 合并：两个有序段
}

void merge(int[] arr, int l, int mid, int r) {
    int[] tmp = new int[r - l + 1];            // 临时数组
    int i = l, j = mid + 1, k = 0;
    while (i <= mid && j <= r) {               // 双指针归并（有序 → 单调）
        if (arr[i] <= arr[j]) tmp[k++] = arr[i++];   // <= 保证稳定性
        else tmp[k++] = arr[j++];
    }
    while (i <= mid) tmp[k++] = arr[i++];      // 剩余左半
    while (j <= r) tmp[k++] = arr[j++];        // 剩余右半
    System.arraycopy(tmp, 0, arr, l, tmp.length);    // 写回原数组
}
```

### 2.2 递归树推演（arr = [5, 2, 4, 6, 1, 3]）

```text
                    [5,2,4,6,1,3]
                 /              \
          [5,2,4]              [6,1,3]
          /     \              /     \
       [5,2]   [4]          [6,1]   [3]
       /   \                /   \
     [5]  [2]             [6]  [1]
        ↓ 归并（从叶子向上）↓
       [2,5]  [4]         [1,6]  [3]
          \   /               \   /
        [2,4,5]             [1,3,6]
              \               /
                [1,2,3,4,5,6]
```

> 🎯 **推演要点**：**归并排序的"处理"全在归阶段（合并）**——递阶段只负责切分（O(1)），真正的工作（merge O(n)）发生在返回路上。这是"后序聚合"思想在数组上的体现。

## 3. 归并排序的复杂度推导

### 3.1 递推方程与主定理（呼应 01 文件 4.1）

```text
T(n) = 2T(n/2) + O(n)      ← 两个规模减半的子问题 + 每次合并 O(n)

主定理: 比较 n^log₂2 = n 与 f(n) = n → 同阶
→ T(n) = O(n log n)

空间: O(n)（临时数组）+ O(log n)（递归栈）→ 合计 O(n)
```

### 3.2 为什么归并排序不受最坏输入影响

```text
快排: 划分可能不平衡 → 最坏 O(n²)（已排序数组 + 固定选轴）
归并: 每次严格对半切 → 递归树永远平衡 → 稳定 O(n log n)
代价: 需要 O(n) 额外空间（快排 O(log n) 栈）

面试对比答案: "归并稳定、最坏 O(n log n)，但空间 O(n)；
             快排原地、平均 O(n log n)，但最坏 O(n²) 且不稳定"
```

## 4. 快速排序：分治的另一种拆分

### 4.1 完整实现（原地分区）

```java
// 快速排序: 分治——拆法是"分区"，合是隐式的（原地）
public void quickSort(int[] arr, int l, int r) {
    if (l >= r) return;                        // 基线
    int p = partition(arr, l, r);              // ① 分区：pivot 归位
    quickSort(arr, l, p - 1);                  // ② 解决：左区间
    quickSort(arr, p + 1, r);                  // ② 解决：右区间
    // ③ 合并不需要！——原地分区后左右区间天然有序衔接
}

int partition(int[] arr, int l, int r) {
    int pivot = arr[r];                        // 选尾元素为轴
    int i = l - 1;                             // 慢指针：小于 pivot 的边界
    for (int j = l; j < r; j++) {
        if (arr[j] < pivot) {                  // 小于轴 → 换到左边
            swap(arr, ++i, j);
        }
    }
    swap(arr, i + 1, r);                       // 轴归位
    return i + 1;                              // 返回轴位置
}
```

### 4.2 快排与归并的对比（分治的两种拆分哲学）

| 维度 | 归并排序 | 快速排序 |
|------|---------|---------|
| 拆分依据 | 位置（中点）——确定平衡 | 值（pivot）——可能失衡 |
| 合并 | 需要 merge O(n) | 不需要（原地） |
| 最坏 | O(n log n)（稳定） | O(n²)（已排序） |
| 稳定性 | 稳定 | 不稳定 |
| 空间 | O(n) | O(log n) 栈 |
| 分治侧重 | "合"是主角 | "拆"是主角 |

> 🎯 **一句话分治哲学**：**归并排序是"拆得均匀、合得辛苦"；快速排序是"拆得关键、合得免费"**——两者交换了工作重心，这就是同一思想下的两种设计。

## 5. 逆序对计数：归并思想的进阶应用

### 5.1 问题定义

```text
逆序对: i < j 且 nums[i] > nums[j] 的数对
例: [3, 1, 2] → 逆序对 (3,1), (3,2) → 共 2 个
暴力: O(n²) 双重循环（n ≤ 5000 可用）
进阶: 归并过程中计数 O(n log n)（剑指 Offer 51 / LeetCode 493 变体）
```

### 5.2 归并计数的关键洞察

```text
归并时，左半段 [l..mid] 与右半段 [mid+1..r] 各自有序。
当 arr[i] > arr[j]（i 在左半，j 在右半）时:
  → 左半段从 i 到 mid 的所有元素都 > arr[j]（有序保证！）
  → 一次性贡献 (mid - i + 1) 个逆序对
这就是"一次合并数出一大片"——O(n) 合并内完成 O(n) 对数
```

### 5.3 完整实现

```java
// 51 逆序对（归并计数）: 在 merge 里顺手统计
long count = 0;

void mergeSort(int[] arr, int l, int r) {
    if (l >= r) return;
    int mid = l + (r - l) / 2;
    mergeSort(arr, l, mid);
    mergeSort(arr, mid + 1, r);
    countMerge(arr, l, mid, r);
}

void countMerge(int[] arr, int l, int mid, int r) {
    int[] tmp = new int[r - l + 1];
    int i = l, j = mid + 1, k = 0;
    while (i <= mid && j <= r) {
        if (arr[i] <= arr[j]) {
            tmp[k++] = arr[i++];
        } else {
            count += (mid - i + 1);      // ★ 核心：arr[j] 小于左半 i..mid 全部
            tmp[k++] = arr[j++];
        }
    }
    while (i <= mid) tmp[k++] = arr[i++];
    while (j <= r) tmp[k++] = arr[j++];
    System.arraycopy(tmp, 0, arr, l, tmp.length);
}
```

> 🎯 **逆序对 = "分治 + 有序性"的经典组合**：暴力的 O(n²) 无法通过时，想到"**归并过程中左右段有序 → 一次比较解决一段计数**"——这正是分治把"枚举"变成"批量结算"的威力（与暴力枚举 07 文件"少枚举"思想同源）。

## 6. 分治 vs 普通递归 vs 动态规划

| | 普通递归 | 分治 | 动态规划 |
|--|---------|------|---------|
| 子问题关系 | 单个或少量 | **相互独立** | **相互重叠** |
| 组合答案 | 直接利用 | 必须合并 | 递推组合 |
| 代表 | 阶乘、链表递归 | 归并、快排、快速幂 | 背包、LCS |
| 记忆化 | 不需要 | 不需要（无重叠） | 必须 |
| 典型复杂度 | O(n)~O(2ⁿ) | O(n log n) 类 | 多项式（状态数） |

```text
判别口诀:
  子问题重叠 → DP（记忆化）
  子问题独立 + 需要组合 → 分治
  只有一条路 → 普通递归
```

> 💡 快速幂（50 题，02 文件有题解）是**"独立但可共享"的分治特例**：`pow(x, n/2)` 算一次，结果平方——既是分治（指数减半）又避免重复（只递归一次），复杂度 O(log n)。**面试讲 50 题时点出"只递归一次而非两次"是得分细节**。

## 7. 分治递归的调试与注意事项

| 注意事项 | 说明 |
|---------|------|
| 区间边界 | 统一用闭区间 [l, r] 或左闭右开 [l, r)，混用必错；mid 用 `l + (r-l)/2` 防溢出 |
| 基线条件 | 归并/快排基线是 `l >= r`（空/单元素）——漏了会死循环 |
| merge 的稳定性 | `<=` 而非 `<`，否则相同元素乱序（不稳定） |
| 递归深度 | 归并 log n 安全；快排最坏 n（已排序）→ 工程用随机化 pivot |
| 全局计数 | 逆序对等用全局变量时注意多线程/重复调用问题（工程上应传对象或返回值） |
| 空间估算 | 归并 O(n) 临时数组必须说明——面试复杂度要报时间 + 空间两个 |

**调试手段**（呼应 03 文件 7.1）：

```text
① 小数组全打印: 每次 merge 前后打印数组 → 观察"部分有序 → 整体有序"
② 递归树对照: 手动画 n=4 的递归树，对比代码实际行为
③ 边界样例: 空数组、单元素、两个元素、全相等、逆序数组
```

> 🎯 **核心要点**：分治 = "拆得合理、解得独立、合得正确"三件事。归并（拆中点 + 合 merge）与快排（拆 pivot + 合免费）是同一思想的两极；**逆序对计数是"分治思想升维"的证明——把 O(n²) 枚举变成 O(n log n) 批量结算**。背下递推式 `T(n) = 2T(n/2) + O(n) → O(n log n)` 的主定理推导，分治复杂度就全通了。
