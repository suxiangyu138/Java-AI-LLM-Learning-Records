## 1. 链表为什么能递归：递归定义的线性结构

链表与二叉树一样是"递归定义"的数据结构：

```text
一个链表 = 头节点 + 剩余链表（链表）
空（null）是基线条件
```

```java
class ListNode {
    int val;
    ListNode next;   // 剩余部分：还是一个链表
}
```

| 递归三要素 | 链表的对应 |
|-----------|-----------|
| 基线条件 | `head == null` 或 `head.next == null` |
| 递推关系 | 问题分解为"头节点 + 子链表问题" |
| 收敛性 | 子链表严格更短 |

> 🎯 与树的对比：**树递归有两个分支（左/右），链表递归只有一个分支（next）**——所以链表递归是"单链递归树"（一条线），深度 = 链表长度 n。**n 大时栈溢出风险比树更高**（树深 h ≤ n，链表深恒为 n）。

## 2. 206 反转链表：归来时反转指针

### 2.1 代码与推演

```java
// 206 反转链表（递归版）
public ListNode reverseList(ListNode head) {
    if (head == null || head.next == null) return head;   // 基线：空或单节点
    ListNode newHead = reverseList(head.next);            // ① 递：先反转剩余链表
    head.next.next = head;                                // ② 归：后继指回自己
    head.next = null;                                     // ③ 归：断开原前向
    return newHead;                                       // ④ 归：新头向上传
}
```

```text
推演 1 → 2 → 3 → 4：

递阶段（一路深入）:
  reverse(1): 调 reverse(2)
    reverse(2): 调 reverse(3)
      reverse(3): 调 reverse(4)
        reverse(4): 4.next==null → 基线 → 返回 4
归阶段（一路返回，逐层改指针）:
  reverse(3) 拿到 newHead=4:  3.next.next=3 → 4.next=3;  3.next=null
  reverse(2) 拿到 newHead=4:  2.next.next=2 → 3.next=2;  2.next=null
  reverse(1) 拿到 newHead=4:  1.next.next=1 → 2.next=1;  1.next=null
结果: 4 → 3 → 2 → 1 ✓（newHead 始终是 4）
```

### 2.2 为什么"归来时"才改指针

```text
递阶段: 只知道"我面前的头"，不知道"链表尽头"——不能动手
归阶段: 每个节点都知道"我的后继是谁"（head.next 还在）
        → 让后继指向自己，就完成了"这一环"的反转

关键洞察: 反转需要"从后往前"逐环进行 —— 恰好是归阶段的顺序
        先到尽头（递） → 尽头返回时逐环反转（归）
```

> 🎯 **206 是"归来时动作"的最纯粹示例**：整个函数体在递归调用**之后**执行——所有代码都属于归阶段。面试讲 206 时说出"**递归先走到链表末尾，然后在返回路上逐环反转指针**"，比直接背代码高一档。

### 2.3 返回值的语义

```text
reverseList 返回什么？→ "反转后的新链表头"
每个递归层都返回同一个新头（原链表的尾节点）
"返回值是接口契约"（03 文件）——这里契约 = 子链反转后的头
```

## 3. 归来时处理 vs 去程时处理

以链表为例对比两种时机（呼应 03 文件 4.1）：

| 时机 | 代码位置 | 行为 | 典型题 |
|------|---------|------|--------|
| 去程（递阶段） | 递归调用前 | "先处理当前节点，再深入" | 打印链表、累加前缀 |
| 归来（归阶段） | 递归调用后 | "先深入到底，返回时处理" | 反转、从尾部数第 k 个 |

```java
// 去程: 正序打印
void printForward(ListNode head) {
    if (head == null) return;
    System.out.println(head.val);       // 去程打印 → 1, 2, 3
    printForward(head.next);
}

// 归来: 倒序打印（不建栈不反转就拿到倒序！）
void printBackward(ListNode head) {
    if (head == null) return;
    printBackward(head.next);
    System.out.println(head.val);       // 归程打印 → 3, 2, 1
}
```

> 💡 **倒序打印是"归来时处理"的最小演示**——递归天然携带"后进先出"语义，**需要倒序而题目不让你开额外空间时，递归栈就是免费的栈**（如 面试题 06 从尾到头打印链表）。

## 4. 链表递归三模式：头/尾/中

链表递归题基本是三种"动作位置"的组合：

| 模式 | 处理位置 | 代表题 | 直觉 |
|------|---------|--------|------|
| 处理头部 | 去程 | 移除链表元素 203 | "先处理头，再递归剩余" |
| 处理尾部 | 归来 | 反转 206、倒序输出 | "先递归到底，返回时处理" |
| 处理中部 | 归来 + 指针 | 回文链表 234、重排 143 | "双指针夹逼 + 归来同步" |

### 4.1 234 回文链表（归来时 + 全局指针）

```java
// 234 回文链表: 递归归来时与全局前指针比对（空间 O(n) 版）
ListNode front;
public boolean isPalindrome(ListNode head) {
    front = head;
    return check(head);
}
boolean check(ListNode node) {
    if (node == null) return true;
    if (!check(node.next)) return false;      // 先走到尾部（递）
    if (front.val != node.val) return false;  // 归来时: 尾部与头部比对
    front = front.next;                       // 头部前进
    return true;
}
```

> 💡 工程最优解是快慢指针 + 反转后半（O(1) 空间）；**递归版的价值在展示"归来时携带外部状态"**——面试先讲递归版理解原理，再提 O(1) 优化版，是完整的技术展示链。

## 5. 递归合并：21/23 的模式

### 5.1 21 合并两个有序链表（02 文件有完整题解，此处提炼模式）

```java
public ListNode mergeTwoLists(ListNode l1, ListNode l2) {
    if (l1 == null) return l2;                    // 基线：一方空 → 另一方
    if (l2 == null) return l1;
    if (l1.val <= l2.val) {
        l1.next = mergeTwoLists(l1.next, l2);     // 选 l1，递归合并剩余
        return l1;
    } else {
        l2.next = mergeTwoLists(l1, l2.next);     // 选 l2
        return l2;
    }
}
```

**模式提炼**：

```text
"比较选头，递归合余部，返回新头"
① 选当前更小的节点作为结果头
② 它的 next = 递归合并（剩余 l1 与另一个链表）
③ 返回值语义 = "合并后的链表头"
```

### 5.2 23 合并 K 个有序链表（分治递归）

```java
// 23: 分治——两两归并，O(k·n log k)
public ListNode mergeKLists(ListNode[] lists) {
    return merge(lists, 0, lists.length - 1);
}
ListNode merge(ListNode[] lists, int l, int r) {
    if (l > r) return null;                       // 基线 1: 空区间
    if (l == r) return lists[l];                  // 基线 2: 单链表
    int mid = l + (r - l) / 2;
    ListNode left = merge(lists, l, mid);         // 分治：左半合并
    ListNode right = merge(lists, mid + 1, r);    // 分治：右半合并
    return mergeTwoLists(left, right);            // 合并：两两归并
}
```

> 🎯 **23 是"链表 + 分治"的桥**：递归树深度 log k，总复杂度 O(k·n log k)。它把 21（递归合两个）与分治（06 文件）串成一条线——**链表递归不只有"单链深入"，还有"分治合并"**。

## 6. 链表递归 vs 迭代三指针

| 维度 | 递归版 | 迭代版（三指针） |
|------|:---:|:---:|
| 代码 | 5 行（清晰） | 8 行（机械） |
| 空间 | O(n) 栈（危险） | **O(1)（最优）** |
| 风险 | 长链栈溢出 | 无 |
| 面试定位 | 展示递归思维 | 工程最优解 |

```java
// 206 迭代版: prev/cur/next 三指针
public ListNode reverseListIter(ListNode head) {
    ListNode prev = null, cur = head;
    while (cur != null) {
        ListNode next = cur.next;   // ① 记住后继
        cur.next = prev;            // ② 反转指向前
        prev = cur;                 // ③ 前进
        cur = next;
    }
    return prev;                    // 新头 = 原尾
}
```

> 💡 **面试标准流程**："反转链表我两种都会——递归版 5 行展示结构，但空间 O(n)；迭代三指针 O(1) 空间，工程上更优。我先写迭代版，再补充递归版讲思路。"**两个版本都能默写**是链表递归的基本功。

## 7. 链表递归的易错点清单

| 易错点 | 错误 | 正确 | 后果 |
|--------|------|------|------|
| 基线漏空指针 | `if (head == null)` 只判一种 | 同时判 `head == null || head.next == null` | 单节点/空链表空指针异常 |
| 丢失新头 | `return head` | `return newHead`（原尾） | 返回错误结果 |
| 忘断旧链 | 只改 `next.next` 不断 `head.next` | `head.next = null` | 链表成环 |
| 顺序颠倒 | 先断 `head.next` 再改 `next.next` | 先 `head.next.next = head` 再断 | 丢失后继引用 |
| 修改入参 | 递归中改原链表未恢复 | 明确是否允许原地改 | 结果错乱 |
| 深链硬递归 | 10⁶ 长链直接递归 | 转迭代（O(1) 空间） | 栈溢出 |

> 🎯 **核心要点**：链表递归 = "递归定义的线性结构 + 归来时处理"的组合。三件事通关：**① 206 反转的"归来时逐环反转"推演能讲 30 秒；② 返回值语义"子链反转后的头"脱口而出；③ 递归与迭代（三指针）双版本都能默写**。链表递归与树递归共用同一套"递/归"心法，但深度恒为 n——**面试记得主动说"长链场景我会转迭代"**，这是工程素养的体现。
