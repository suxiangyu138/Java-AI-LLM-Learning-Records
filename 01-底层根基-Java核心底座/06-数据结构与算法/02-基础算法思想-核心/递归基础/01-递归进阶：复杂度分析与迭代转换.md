## 1. 递归的时间复杂度分析

### 1.1 递推方程法（核心方法）

递归的时间复杂度分析 = 写出**递推方程**并求解：

| 递归形态 | 递推方程 | 复杂度 | 典型 |
|---------|---------|--------|------|
| 单路线性 | `T(n) = T(n-1) + c` | O(n) | 阶乘、反转链表 |
| 二分单路 | `T(n) = T(n/2) + c` | O(log n) | 二分查找 |
| 二分双路 | `T(n) = 2T(n/2) + n` | O(n log n) | 归并排序 |
| 二叉分裂 | `T(n) = 2T(n/2) + c` | O(n) | 树遍历 |
| 多路爆炸 | `T(n) = T(n-1) + T(n-2)` | O(2^n) | 朴素斐波那契 |
| 多路爆炸 | `T(n) = T(n/2) + T(n/2)` | O(n) | 无意义重复 |

```java
// 例：maxDepth 后序递归
int maxDepth(TreeNode root) {
    if (root == null) return 0;                          // 基线 c
    return Math.max(maxDepth(root.left), maxDepth(root.right)) + 1;
}
// 方程：T(n) = 2T(n/2) + c → O(n)（每个节点恰好访问一次）
// 空间：O(h)，h 为树高（递归栈深度 = 调用链长度）
```

### 1.2 空间复杂度 = 最大调用深度

```
递归空间 = 调用栈深度 × 每帧占用
树递归：深度 O(h)（h 为树高）
链式递归：深度 O(n)（链长）← 栈溢出高危
网格 DFS：最坏深度 O(m×n)

⚠️ 空间复杂度容易答错：
  "每层函数都还没返回，栈帧全部占用"
  递归的空间是"最深调用链"，不是"总调用次数"
```

### 1.3 复杂度速查表（背）

| 递归 | 时间 | 空间 |
|------|:---:|:---:|
| 阶乘（线性） | O(n) | O(n) |
| 反转链表（线性） | O(n) | O(n) |
| 树遍历（访问全部节点） | O(n) | O(h) |
| 归并排序（分治） | O(n log n) | O(log n) |
| 朴素斐波那契（双路） | O(2^n) | O(n) |
| 快速幂（二分） | O(log n) | O(log n) |

## 2. 多路递归与指数爆炸

### 2.1 斐波那契：为什么朴素递归是灾难

```java
// ❌ 朴素递归：T(n) = T(n-1) + T(n-2) + c → O(2^n)
int fib(int n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);   // 两个子问题，且大量重复
}

// fib(5) 的调用树（重复计算可见）：
//                     fib(5)
//              fib(4)         fib(3)
//         fib(3)   fib(2)  fib(2)  fib(1)
//     fib(2) fib(1) ...
// fib(3) 被算了 2 次，fib(2) 被算 3 次 → 指数爆炸
```

```
数据：n=45 时朴素递归约 18 亿次调用，单线程跑几十秒
     n=100 直接 2^100 次 → 宇宙毁灭都算不完

本质：子问题重叠（overlapping subproblems）
诊断信号："同一状态被多次计算" → 上记忆化/DP
```

### 2.2 多路递归的正确打开方式

| 方案 | 复杂度 | 本质 |
|------|:---:|------|
| 朴素递归 | O(2^n) | 重复计算 |
| 记忆化递归 | O(n) | 缓存已算结果，每个状态只算一次 |
| 迭代 DP | O(n) | 自底向上，天然无栈 |

> 🎯 **诊断口诀**："递归数叶子个数 = 时间复杂度"——多路递归的调用树有多少节点就有多少次调用。斐波那契调用树是满二叉树 → 2^n。

## 3. 记忆化：递归 + 缓存

### 3.1 模板与实战

```java
/**
 * 记忆化递归通用模板
 * ① 递归定义不变（清晰） ② 加缓存去重（快）
 */
int memo(int n) {
    int[] cache = new int[n + 1];
    Arrays.fill(cache, -1);              // 哨兵：未计算
    return dfs(n, cache);
}

int dfs(int n, int[] cache) {
    if (n <= 1) return n;                // ① 基线
    if (cache[n] != -1) return cache[n]; // ② 查缓存（记忆化核心）
    return cache[n] = dfs(n - 1, cache) + dfs(n - 2, cache);  // ③ 存缓存
}
// fib(100)：O(n)，缓存数组 size 100
```

### 3.2 什么时候该上记忆化

```
适用信号：
  ① 递归中有重复子问题（调用树含重复子树）
  ② 状态可以用简单键表示（int / 参数元组）
  ③ 题目要求指数 → 多项式

⚠️ 注意：
  - 记忆化的状态数 = 缓存大小 = 复杂度
  - 一维缓存 O(n)；二维（两个参数）O(n×m)
  - 记忆化是"自顶向下 DP"——和迭代 DP 殊途同归
```

## 4. 分治递归：主定理应用

### 4.1 主定理（Master Theorem）速用

```
形如 T(n) = a·T(n/b) + f(n) 的递归：
比较 n^log_b(a) 与 f(n) 的"大小关系"：

① f(n) 更小   → T(n) = O(n^log_b(a))
② 同阶        → T(n) = O(n^log_b(a) · log n)
③ f(n) 更大   → T(n) = O(f(n))

三个经典例：
归并排序  T(n) = 2T(n/2) + n     → log₂2=1, f=n 同阶 → O(n log n)
二叉树遍历 T(n) = 2T(n/2) + c    → n¹ > c → O(n)
二分查找  T(n) = T(n/2) + c      → n⁰ = c 同阶 → O(log n)
```

### 4.2 分治三步曲（以归并排序为例）

```
① 分解（Divide）    ：拆成两半            → mergeSort(left), mergeSort(right)
② 解决（Conquer）   ：递归解决子问题       → 两半各自有序
③ 合并（Combine）   ：合并有序子结果       → merge O(n)

⚠️ 分治 = 递归 + 拆分 + 合并
   与"普通递归"的区别：每层都把问题拆成多个独立子问题，然后合并
   与"动态规划"的区别：子问题互不重叠（分治），重叠了就要记忆化
```

```java
// 快速幂：分治递归的代表（自顶向下 + 奇偶合并）
public double myPow(double x, int n) {
    long N = n;                        // 防 -2^31 溢出
    return N < 0 ? 1 / pow(x, -N) : pow(x, N);
}
private double pow(double x, long n) {
    if (n == 0) return 1;              // 基线：x⁰ = 1
    double half = pow(x, n / 2);       // 二分：只算一半
    return (n & 1) == 1 ? half * half * x : half * half;
}   // T(n) = T(n/2) + c → O(log n)  ← 主定理用例 ③
```

## 5. 栈溢出四道防线

### 5.1 深度预判

```
递归深度可预判的场景：
  树高度 h → 深度 h（链表型树 = n，危险）
  链表长 n → 深度 n（⚠️ 反转链表/合并链表类要留意）
  网格 m×n → 最坏 m×n
  数字折半 → log n（安全）

⚠️ 工程经验：深度 > 10⁴ 就有溢出风险
  （默认栈约 512KB-1MB，每帧约 100-500 字节）
```

### 5.2 四道防线总览

| 防线 | 手段 | 适用 |
|------|------|------|
| ① 分析深度 | 确认 O(h) 而非 O(n) | 所有递归 |
| ② 转迭代 | 显式栈（堆内存，无栈限制） | 深度不可控 |
| ③ 尾递归改造 | 递归放最后 + 累加器 | 可尾递归化的场景 |
| ④ 调大栈 | JVM 参数 `-Xss` | 工程临时手段 |

```bash
# 工程手段：JVM 调大线程栈（治标）
java -Xss1m -jar app.jar        # 默认约 1MB → 调到 2-4MB 可撑更深
# ⚠️ 治本仍是转迭代：栈大小是有限的，深度可以无限
```

### 5.3 显式栈转换的状态机框架

```
递归 → 迭代的本质：把"隐式调用栈"换成"显式状态栈"
每帧记录：当前节点 + 处理阶段（进/出）

通用框架（树遍历类）：
  压栈 (node, 0)                        // 0=进入，1=返回
  while (栈非空):
    弹 (cur, phase)
    phase=0 → 处理节点，压 (cur,1)，压子节点 (子,0)
    phase=1 → 出栈后处理（后序聚合在此）

⚠️ 面试表达："递归隐式用调用栈，迭代显式用 Deque，
   手动管理'进/出'两个阶段即可完整模拟。"
```

## 6. 尾递归与手动优化

### 6.1 什么是尾递归

```
尾递归 = 递归调用是函数体的最后一步（返回值直接作为本函数返回值）

// 非尾递归：返回后还有 * 运算
int fact(int n)      { return n == 0 ? 1 : n * fact(n - 1); }

// 尾递归：递归结果直接返回（用累加器 acc 携带中间结果）
int factTail(int n, int acc) { return n == 0 ? acc : factTail(n - 1, n * acc); }

⚠️ 尾递归的好处：函数式语言（Scala/Kotlin 等）可优化为循环，
   复用当前栈帧 → 不加深栈 → 不溢出
   Java：❌ 不做尾递归优化（JVM 规范层面），需手动转循环
```

### 6.2 Java 手动优化（累加器模式）

```java
// 尾递归 → 迭代：参数变循环变量
int factorial(int n) {
    return factTail(n, 1);
}
int factTail(int n, int acc) {
    // 优化前（尾递归，Java 不会自动优化）：
    //   return n == 0 ? acc : factTail(n - 1, n * acc);
    // 优化后（手动转循环，等价）：
    while (n > 0) {
        acc *= n;
        n--;
    }
    return acc;
}
```

> 🎯 **面试必答句**："尾递归指递归在最后一步、结果直接返回；函数式语言会优化成迭代复用栈帧，**Java 不自动优化**，需要手动转循环或用显式栈。"

## 7. 间接递归与递归展开

### 7.1 间接递归（互相调用）

```java
// 经典：奇偶判断互相调用（教学范例）
boolean isEven(int n) { return n == 0 ? true : isOdd(n - 1); }
boolean isOdd(int n)  { return n == 0 ? false : isEven(n - 1); }
// A → B → A → ... 调用链，同样需要基线（n==0）收敛

// 工程里的间接递归：解释器（表达式求值）、
//   语法分析（表达式 → 项 → 因子 → 表达式）
```

### 7.2 递归展开技巧（组合/子集类）

```
展开 = 用"生产-消费"式循环替代隐式调用栈：

// 例：打印 1..n 的所有子集（递归版）
void subsets(int[] a, int i, List<Integer> path) {
    if (i == a.length) { 输出(path); return; }
    subsets(a, i + 1, path);            // 不选
    path.add(a[i]);
    subsets(a, i + 1, path);            // 选
    path.remove(path.size() - 1);
}

// 展开要点：状态 = (i, path) 元组，压栈的正是这个元组
// 深度 = 数组长度 n；展开后栈中最多 n 帧 → 与递归深度相同
// ⚠️ 注意：展开只解决"栈溢出"，不改变时间复杂度
```

## 8. 工程实战中的递归

### 8.1 真实应用场景

| 场景 | 递归形态 | 注意事项 |
|------|---------|---------|
| 文件系统遍历 | 目录树 DFS | 深度 = 目录嵌套层数；符号链接环要防（visited） |
| JSON/XML 解析 | 嵌套结构递归下降 | 深度 = 嵌套层数；恶意深层嵌套是攻击面 |
| 树形菜单/组织架构 | 子节点递归构建 | 需防环（parentId 回环） |
| 表达式求值 | 间接递归 | 递归下降解析器 |
| 模板引擎/规则引擎 | 嵌套表达式递归求值 | 深度限制 + 超时保护 |

```java
// 工程例：递归统计目录大小（带深度限制，防异常嵌套）
long dirSize(Path dir, int depth) {
    if (depth > 32) return 0;                    // ⚠️ 工程防线：深度上限
    try (var stream = Files.list(dir)) {
        long total = 0;
        for (Path p : stream.toList()) {
            if (Files.isDirectory(p)) total += dirSize(p, depth + 1);
            else total += Files.size(p);
        }
        return total;
    } catch (IOException e) { return 0; }
}
```

### 8.2 工程铁律

```
① 深度防护：解析/遍历类递归必须设深度上限
   （攻击者用 10⁵ 层嵌套 JSON 即可触发 StackOverflow → DoS）
② 环防护：树结构要检查 visited / 深度
③ 性能防护：重叠子问题必上记忆化（不要递归裸奔）
④ 资源防护：递归内打开的文件/连接要确保关闭（finally）
```

## 9. 面试要点与追问

### 9.1 面试话术模板

```
"这题我用递归：基线是【...】，递推是【...】，
 时间 O(n)，空间 O(h)。
 如果用朴素递归会有重复计算（指数级），
 我会加记忆化降到 O(n)；
 如果深度可能超限，我会转显式栈迭代。"
```

### 9.2 进阶追问 TOP 6

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | 递归时间复杂度怎么算？ | 递推方程：T(n) = aT(n/b) + f(n)，主定理三情形 |
| 2 | 斐波那契朴素递归为什么慢？ | 重叠子问题，调用树 2^n 个节点，同状态重复计算 |
| 3 | 记忆化和 DP 什么关系？ | 记忆化 = 自顶向下 DP（递归+缓存）；迭代 DP = 自底向上，等价 |
| 4 | 为什么 Java 不做尾递归优化？ | JVM 规范未要求；栈帧含丰富上下文（异常表等），复用难度大 |
| 5 | 递归空间复杂度怎么算？ | 最深调用链 × 每帧大小，不是总调用数 |
| 6 | 深递归会栈溢出怎么办？ | 四道防线：预判深度 → 显式栈 → 尾递归改造 → -Xss |

### 9.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| 重复计算不上记忆化 | 指数爆炸 | 先诊断重叠子问题 |
| 误判深度安全 | 线上 StackOverflow | 按最坏深度（链表型树）预判 |
| 忘了递归后的清理 | 状态残留 | 回溯类记得还原 path/used |
| 解析类递归无深度上限 | 恶意输入 DoS | 深度 > 32 直接拒绝 |
| 尾递归当"Java 会优化" | 误判复杂度 | 记住：Java 不优化，手动转循环 |
