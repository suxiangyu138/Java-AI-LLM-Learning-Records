## 1. 调用栈：递归的物理载体

### 1.1 栈帧里有什么

每次函数调用，JVM 在调用栈（Call Stack）上压入一个**栈帧（Stack Frame）**：

```text
┌───────────────────────────┐
│ 返回地址（调用后跳回哪）      │
│ 局部变量（本层的中间结果）     │
│ 参数（本层的入参副本）        │
│ 上一帧指针（链回调用者）       │
└───────────────────────────┘
          ↓ 压栈（调用）
        [frame of f(4)]
        [frame of f(3)]
        [frame of f(2)]
        [frame of f(1)]  ← 栈顶（正在执行）
```

**关键认知**：

```text
① 每层递归 = 一个独立栈帧 = 一份独立的局部变量（互不干扰）
② 递归深度 = 栈帧个数 = 栈内存占用
③ 栈空间有限（默认约 512KB~1MB）→ 深度过大 → StackOverflowError
④ 返回时弹栈 = 自动"撤销"该层的一切局部状态
```

> 🎯 **为什么递归能"记住"路径**：路径保存在**栈帧链**里——递归调用返回后，上一层帧的变量原封不动。这解释了回溯算法的"撤销选择"为何可行：**栈帧自动保存现场**。

### 1.2 一个简单的栈帧推演

```java
int f(int n) {              // f(3) 的完整推演
    if (n <= 1) return 1;
    return f(n - 1) * n;
}
```

```text
f(3) 调用 → 压帧 f(3)
  → f(2) 调用 → 压帧 f(2)
    → f(1) 调用 → 压帧 f(1)
      → f(1) 基线命中 → 返回 1 → 弹帧 f(1)
    → f(2) 继续: 1 * 2 = 2 → 返回 2 → 弹帧 f(2)
  → f(3) 继续: 2 * 3 = 6 → 返回 6 → 弹帧 f(3)
结果: 6
```

⚠️ 注意 `return f(n-1) * n` 中 **`* n` 必须等 f(n-1) 返回后才能执行**——这迫使 f(n) 的帧一直活着，直到子调用返回。**"返回后还有计算"是栈帧无法提前释放的原因**（也是尾递归优化的动机，见 01 文件）。

## 2. 递归树：递归的完整调用图

### 2.1 什么是递归树

把每次调用画成树的节点，父子即调用关系——**递归树是理解"递归在干什么"的最佳可视化**。

```text
                 f(5)
              /        \
          f(4)          f(3)
         /    \        /    \
      f(3)    f(2)   f(2)   f(1)
     /   \   /  \   /  \
  f(2) f(1) f(1)f(0)...
   ...
```

**递归树的两大用途**：

```text
① 数叶子/节点个数 → 时间复杂度（每个节点 = 一次调用）
   斐波那契递归树是满二叉树 → O(2ⁿ) 次调用
② 看重复子树 → 发现"重叠子问题" → 该上记忆化
   f(3) 出现两次、f(2) 出现三次 → 重复计算（01 文件详述）
```

> 🎯 **面试诊断口诀**："**递归树叶子个数 = 调用次数 = 时间复杂度的直觉来源**"——先画树再谈复杂度，是分析递归的标准动作。归并排序的递归树每层都是 n 个节点的合并，层数 log n → O(n log n)。

### 2.2 单路递归树 vs 多路递归树

| 形态 | 树形 | 叶子数 | 例 |
|------|------|:---:|------|
| 单路线性 | 一条链 | 1 | 阶乘、反转链表 |
| 单路折半 | 链但每层减半 | 1 | 二分查找、快速幂 |
| 双路分治 | 每层翻倍 | n | 归并排序（平衡树） |
| 双路爆炸 | 满二叉树 | 2ⁿ | 朴素斐波那契 |
| 多路枚举 | 每层 m 个孩子 | mⁿ | 排列、组合、DFS |

## 3. 递与归：两个截然不同的阶段

### 3.1 一个递归调用 = 递 + 归

```java
void traverse(TreeNode node, List<Integer> out) {
    if (node == null) return;
    out.add(node.val);          // ← 递阶段（向深层走之前）
    traverse(node.left);        // 向下深入
    traverse(node.right);       // 向下深入
    // ← 归阶段（从深层返回之后）【此处无事发生】
}
```

```text
"递"（Descending）: 调用不断深入，每层压栈 —— 处理"下去之前"的事
"归"（Ascending） : 子调用返回后逐层弹栈 —— 处理"回来之后"的事

同一段代码中：
  · 递归调用之前的语句 → 递阶段执行（先序）
  · 递归调用之后的语句 → 归阶段执行（后序）
  · 多个递归调用之间 → 夹在中间的执行（中序）
```

> 🎯 **这是整个递归专题最重要的一个认知**：**"在递归调用前后写代码"意味着完全不同的语义**——前面是"去时的任务"，后面是"回来时的任务"。反转链表（05 文件）就是在"回来时"反转指针，N 皇后（暴力枚举 06 文件）的撤销选择也发生在"回来时"。

### 3.2 用打印验证两个阶段

```java
void trace(int n) {
    if (n == 0) return;
    System.out.println("进入 n=" + n);   // 递阶段打印
    trace(n - 1);
    System.out.println("离开 n=" + n);   // 归阶段打印
}
// 输出:
// 进入 n=3
//   进入 n=2
//     进入 n=1
//     离开 n=1
//   离开 n=2
// 离开 n=3
```

观察输出呈**对称的括号结构**——递是"开括号"，归是"闭括号"。任何递归代码都可以用这个心法推演："**先开的最后合**"。

## 4. 先序动作与后序动作：处理时机决定行为

### 4.1 三种处理时机

以树的递归为例，同一个"处理"放在不同位置产生三种遍历：

| 时机 | 位置 | 名字 | 行为特征 |
|------|------|------|---------|
| 递阶段（调用前） | 先递归左再右 | 前序 | "根左右"——先做再走 |
| 夹中间（调用间） | 左调用与右调用之间 | 中序 | "左根右"——排序序 |
| 归阶段（调用后） | 全部调用之后 | 后序 | "左右根"——先走再做 |

```text
应用直觉（背）：
  前序 → "自上而下传参数"（路径、前缀和、构建树）
  中序 → "有序输出"（二叉搜索树中序 = 升序）
  后序 → "自下而上聚合"（高度、和、最大路径、返回值依赖子树）
```

> 💡 **选序口诀**：**"要子树的答案 → 后序；要把自己的信息传下去 → 前序；要排序 → 中序"**。80% 的树递归题用这三句就能定出处理位置。

### 4.2 同题两种写法的对比（翻转二叉树 226）

```java
// 前序版（递阶段交换）
TreeNode invert(TreeNode root) {
    if (root == null) return null;
    TreeNode t = root.left; root.left = root.right; root.right = t;  // 先换
    invert(root.left);
    invert(root.right);
    return root;
}

// 后序版（归阶段交换）
TreeNode invert2(TreeNode root) {
    if (root == null) return null;
    TreeNode l = invert2(root.left);
    TreeNode r = invert2(root.right);
    root.left = r; root.right = l;                                     // 后换
    return root;
}
```

两个版本都对——交换操作**与递归时机无关**（每个节点换一次即可）。**但大多数"依赖子树结果"的题，时机选错就错**（如最大路径和必须在归阶段聚合）。

## 5. 返回值语义设计：递归的"接口契约"

### 5.1 三问确定返回值

写任何递归函数前，先回答三个问题（这是 leetcode-master 与社区公认的递归三问框架，也是面试话术骨架）：

```text
① 终止条件是什么？（空节点？n==0？越界？）
② 本层递归要返回什么？（"子树高度"？"合并后的链表头"？"是否平衡"？）
③ 本层递归要做什么？（返回值如何与子树返回值组合？）
```

### 5.2 返回值的四种常见语义

| 语义 | 例子 | 代码形态 |
|------|------|---------|
| 聚合值 | 104 最大深度 | `return max(l, r) + 1` |
| 结构指针 | 21 合并链表、206 反转 | `return 新头` |
| 布尔/哨兵 | 110 平衡二叉树 | `return -1` 表示不平衡 |
| 无返回值（副作用） | 遍历、路径收集 | `void + 外部容器` |

```java
// 110 平衡二叉树：-1 哨兵语义（返回值携带"高度 + 是否平衡"两个信息）
int height(TreeNode root) {
    if (root == null) return 0;
    int l = height(root.left), r = height(root.right);
    if (l == -1 || r == -1 || Math.abs(l - r) > 1) return -1;  // 失衡信号
    return Math.max(l, r) + 1;
}
```

> ⚠️ **返回值语义不清是递归 bug 的第一来源**：写之前先在心里说一遍"这层函数返回的是 ______"，说不清楚就动手写，十有八九会错。面试中主动说出返回值语义（"我返回子树的高度"）是规范的表现。

## 6. 参数设计：状态如何穿越调用链

### 6.1 两类参数

| 类型 | 作用 | 例子 |
|------|------|------|
| **缩小参数** | 决定子问题规模（必须收敛！） | n-1、start+1、node.left |
| **携带参数** | 把父层信息带给子层（前序传递） | 路径 list、前缀和、深度、visited |

```java
// 携带参数示例：路径收集（113 路径总和 II 的骨架）
void dfs(TreeNode node, int target, List<Integer> path, List<List<Integer>> res) {
    if (node == null) return;
    path.add(node.val);                     // 携带：路径
    if (node.left == null && node.right == null && node.val == target) {
        res.add(new ArrayList<>(path));     // 叶子收集（深拷贝！）
    }
    dfs(node.left, target - node.val, path, res);
    dfs(node.right, target - node.val, path, res);
    path.remove(path.size() - 1);           // 归阶段撤销（对称性！）
}
```

### 6.2 可变参数与不可变参数

```text
携带 list/set 等可变对象时（如 path）:
  · 递阶段 add，归阶段必须 remove —— 保持"栈帧链"与"路径"同步
  · 收集答案必须深拷贝 new ArrayList<>(path)（Java 引用陷阱）
不可变参数（int 深度、boolean）:
  · 值传递天然安全，无需撤销
```

> 🎯 **对称性原则**：**递归调用前对共享可变状态做了什么，返回后就必须反向恢复**——这是回溯算法的基石（撤销选择），也是"递归树"与"状态"同步的保证。忘记撤销 = 状态泄漏 = 结果错乱。

## 7. 调试递归：栈帧可视化的三件套

### 7.1 三件套调试法

```text
① 打印法: 进出打印（深度缩进），观察"递/归"两个阶段
② 小样例: n=3 / 高度 3 的树，手推或单步跟踪
③ 断言法: 基线处断言、返回前断言不变量

调试工具:
  - IDEA 断点看 Call Stack 面板（当前调用链一目了然）
  - 打印缩进: System.out.println("  ".repeat(depth) + ...)
```

```java
// 打印法模板（带深度缩进）
void dfs(int n, int depth) {
    String pad = "  ".repeat(depth);
    System.out.println(pad + "进入 dfs(" + n + ")");
    if (n <= 1) { System.out.println(pad + "基线命中 → 返回"); return; }
    dfs(n - 1, depth + 1);
    System.out.println(pad + "离开 dfs(" + n + ")");
}
```

### 7.2 常见 bug 定位速查

| Bug 现象 | 大概率原因 | 检查点 |
|---------|-----------|--------|
| StackOverflowError | 基线缺失 / 参数不收敛 | ① 基线是否覆盖最小规模 ② 参数是否必减 |
| 结果全部相同 | 共享容器未深拷贝 | res.add(new ArrayList<>(path)) |
| 结果重复 | 忘撤销 / 忘去重 | 归阶段是否对称恢复 |
| 结果偏大/偏小 | 返回值语义错 | 用 110 哨兵法重述返回值 |
| 只对部分输入对 | 基线边界少一种情况 | 空输入、单元素、全相等测试 |

> 🎯 **核心要点**：递归的执行机制一句话——**"每层调用一个栈帧，递阶段压栈、归阶段弹栈，递归调用前后的代码分别属于两个阶段"**。由此推出三把钥匙：**① 画递归树数调用次数（复杂度直觉）；② 用"递/归"判断处理时机（前序传参、后序聚合）；③ 返回值与参数先设计后编码（接口契约 + 对称撤销）**。想清楚这四点，任何递归题都不是"背模板"而是"推演得出"。
