## 1. 复杂度视角：循环嵌套的降维

```
循环复杂度 = 嵌套层数的乘积
  单层循环        → O(n)
  双层循环        → O(n²)（暴力枚举）
  三层循环        → O(n³)

优化本质：减少"每轮循环内的工作量"或"循环层数"
```

| 降维手段 | 做法 | 例子 |
|---------|------|------|
| 双指针 | 有序性砍掉一层 | 167 两数之和 O(n²)→O(n) |
| 哈希表 | 查找 O(1) 替代内层扫描 | 1 两数之和 |
| 预排序 | 排序后单调性剪枝 | 15 三数之和 O(n³)→O(n²) |
| 滑动窗口 | 区间不变量去重计算 | 209 长度最小子数组 |
| 前缀和 | 区间和 O(1) | 560 和为 K 的子数组 |
| 动态规划 | 重叠子问题复用 | 最大子数组和 |

> 💡 面试话术："暴力是 O(n²) 双层循环，但数组有序 → 内层指针单向移动不回退 → 双指针降到 O(n)，因为每轮至少一个指针前进，总移动次数 O(n)。"

## 2. 循环不变量外提

> 循环不变量外提（Loop Invariant Hoisting）：**把每轮结果不变的计算移到循环外，只算一次**。

```java
// ❌ 差：computeFactor 每轮重算（假设内部代价不低）
for (int i = 0; i < n; i++) {
    result += list.get(i) * computeFactor(config);
}

// ✅ 好：不变量外提，只算一次
double factor = computeFactor(config);     // 与 i 无关 → 移出
for (int i = 0; i < n; i++) {
    result += list.get(i) * factor;
}
```

```java
// ❌ O(n²)：String 不可变，每轮拼接都新建对象复制
String s = "";
for (int i = 0; i < n; i++) {
    s += i;                    // 每次都是新字符串 + 全量复制
}

// ✅ O(n)：StringBuilder 原地追加
StringBuilder sb = new StringBuilder();
for (int i = 0; i < n; i++) {
    sb.append(i);              // 扩容摊销 O(1)/次
}
// ⚠️ 循环内 String 拼接是新手最常见的 O(n²) 陷阱
```

| 外提对象 | 好处 |
|---------|------|
| 与 i 无关的计算 | 少 n-1 次执行 |
| 常量对象/数组长度 | 少 n 次字段访问 |
| 循环外已知的结果 | 语义清晰 |
| 资源（连接/流） | 少 n 次创建销毁 |

## 3. 减少循环内开销

```java
// ❌ 每轮重复调 size()/length()（虽然后者已被 JIT 优化，风格仍差）
for (int i = 0; i < list.size(); i++) { ... }

// ✅ 循环外缓存长度（容器结构性变化时还更安全）
int size = list.size();
for (int i = 0; i < size; i++) { ... }

// ❌ 循环内重复创建对象/自动装箱
for (Integer x : bigIntList) {          // int → Integer 装箱
    sum += x * 2;                       // 拆箱 + 运算
}
```

| 循环内开销 | 优化 |
|-----------|------|
| 重复方法调用 | 结果缓存到局部变量 |
| 重复对象创建 | 移到循环外 / 复用 |
| 自动装箱 | 用 int[] / IntStream 避免装箱 |
| 字符串拼接 | StringBuilder（§2） |
| 重复容器查找 | 索引/指针推进替代 |
| 日志/校验 | 循环外做，循环内只留热路径 |

> 💡 JIT 的"循环优化"（逃逸分析、栈上分配）会自动做一部分，但**逻辑层面的冗余计算永远靠人肉外提**。

## 4. 缓存友好：顺序访问

```
CPU 缓存行（Cache Line，通常 64 字节）：
  一次内存读取会带入整行数据
  顺序访问 → 每行数据全部用上（缓存命中率高）
  跳跃访问 → 每行只用一小块（缓存命中率低，反复等内存）

二维数组遍历顺序决定性能（可能差 10 倍）：
```

```java
// ✅ 快：按行遍历（a[i][j] 在内存中连续 → 命中缓存行）
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) sum += a[i][j];
}

// ❌ 慢：按列遍历（每次跳一个整行 → 缓存行反复失效）
for (int j = 0; j < n; j++) {
    for (int i = 0; i < n; i++) sum += a[i][j];
}
```

| 数据结构 | 缓存友好 | 说明 |
|---------|:---:|------|
| 数组/ArrayList | ✅ | 连续内存 |
| LinkedList | ❌ | 节点散落，每次跳指针 |
| HashMap | 中 | 桶内链表/红黑树节点散落 |
| 二维数组按行 | ✅ | 行优先连续 |

## 5. 空间换时间

```java
// 前缀和：把"区间和"从 O(n) 查询降到 O(1)
int[] prefix = new int[n + 1];
for (int i = 0; i < n; i++) {
    prefix[i + 1] = prefix[i] + nums[i];    // 一遍迭代构建
}
// 查询 sum(i, j) = prefix[j + 1] - prefix[i]   ← O(1)
```

```java
// 哈希表去重：O(n²) 内层扫描 → O(n) 查表
// ❌ 双层循环找两数之和 = target
// ✅ Map<Integer, Integer> 记录「值 → 下标」，单层循环查补数
Map<Integer, Integer> map = new HashMap<>();
for (int i = 0; i < nums.length; i++) {
    int complement = target - nums[i];
    if (map.containsKey(complement)) return new int[]{map.get(complement), i};
    map.put(nums[i], i);
}
```

| 手段 | 空间 | 时间收益 | 典型场景 |
|------|:---:|------|------|
| 滚动数组 | O(1) | 空间优化 | DP（爬楼梯） |
| 前缀和 | O(n) | 区间查询 O(1) | 子数组和 |
| 哈希表 | O(n) | 查找 O(1) | 两数之和 |
| 计数数组 | O(V) | 排序/频次 O(n) | 计数排序 |
| 记忆化缓存 | O(n) | 避免重复子问题 | DP/递归 |

> ⚠️ 空间换时间的边界：空间大到无法接受时（如亿级数据），回到时间换空间（流式处理、外排序）。

## 6. 微优化：展开与 JIT

```
循环展开（Loop Unrolling）：每轮多处理几个元素，减少循环控制开销
  例：每轮处理 4 个元素，循环次数从 n 降到 n/4
  ⚠️ 现代 JVM 的 JIT 会自动展开热循环
  ⚠️ 手动展开代码可读性差、收益微乎其微 → 不要做！

JIT 已自动做好的事：
  ① 循环展开与向量化（HotSpot 对简单循环）
  ② 逃逸分析（循环内对象栈上分配）
  ③ 边界检查消除（数组访问）
  ④ 循环不变量外提（部分场景编译器可自动做）

结论：先做逻辑级优化（§1-§5），微优化交给 JVM
```

```java
// ❌ 手动展开：可读性差，JIT 已能自动做
// ✅ 正确姿势：写清晰代码，用 JMH 基准测试验证热点后再说
```

## 7. 性能分析清单

```
优化前先测量（profile 优先于猜测）：
  ① 哪里最热？→ JProfiler / JFR / arthas 采样
  ② 是算法层（复杂度）还是常数层？
  ③ 数据规模多大？n=100 的 O(n²) 不必优化

自检清单：
  □ 复杂度能否降阶？（双指针/哈希/排序）
  □ 循环内有没有与 i 无关的计算？
  □ 循环内有没有拼接/装箱/建对象？
  □ 遍历顺序缓存友好吗？（数组按行）
  □ 需要 O(1) 查询吗？（前缀和/哈希）
  □ 迭代器用对了吗？（LinkedList 禁索引）
  □ 递归深度会栈溢出吗？（该转迭代？）
```

> 🎯 **核心要点**：迭代优化的三板斧——**降阶**（双指针/哈希把 O(n²) 变 O(n)）、**外提**（不变量与对象创建移出循环、StringBuilder 拼接）、**空间换时间**（滚动数组/前缀和/哈希表）。缓存友好靠顺序访问；微优化（循环展开）交给 JIT。原则：**先测热点，再做逻辑级优化，最后才考虑常数**。
