## 1. 迭代的本质

> 迭代（Iteration）：**重复执行同一段逻辑，每次基于当前状态更新进展，直到终止条件成立**。

```
迭代 = 重复执行 + 状态更新 + 终止判定
  · 重复执行：同一段逻辑（循环体）被反复运行
  · 状态更新：用变量记录"进行到哪了"（progress）
  · 终止判定：条件不再满足 → 退出循环
```

```java
// 最朴素的迭代：求 0..n-1 的和
// 状态：sum（累计结果）、i（当前进度）
int sum = 0;
for (int i = 0; i < n; i++) {
    sum += i;              // 循环体：基于当前状态推进
}
System.out.println(sum);   // 终止后，状态即答案
```

⚠️ 与"枚举"的区别：枚举是**逐个列出所有可能**（暴力尝试），迭代是**按规则推进状态**。与"递归"的区别：递归靠自我调用缩小问题，迭代靠循环原地推进——两者可互相转换（见模块 03）。

> 💡 识别信号："从初始状态出发，反复执行同一规则直到满足条件" → 迭代

## 2. 迭代三要素

> 任何正确迭代都包含三要素——**初始化、循环条件、更新步进**。缺一不可。

```
① 初始化（Initialization）：循环开始前的状态设定
   ⚠️ 遗漏 → 初始状态错误 → 结果全错

② 循环条件（Condition）：决定"是否继续执行"
   ⚠️ 恒真 → 死循环；恒假 → 循环体一次不执行

③ 更新步进（Update）：每轮结束后推进状态
   ⚠️ 遗漏 → 状态不变化 → 死循环（最隐蔽的错误）
```

```java
// 三要素对照
int sum = 0;                    // ① 初始化：sum=0, i=0
for (int i = 0; i < n; i++) {   // ② 条件：i < n
    sum += i;                   // 循环体
}                               // ③ 步进：i++（for 第三段）
```

| 要素 | 缺失后果 | 自查问题 |
|------|---------|---------|
| 初始化 | 状态错、越界 | 循环开始前状态对吗？ |
| 循环条件 | 死循环 / 一次不执行 | 条件可能恒真或恒假吗？ |
| 更新步进 | **死循环（最常见）** | 每轮状态必然变化吗？ |
| 收敛性 | 无限循环 | 状态单调推进到条件不满足吗？ |

> 🎯 面试第一句："迭代三要素：初始化、循环条件、更新步进；其中更新步进决定收敛性，漏掉它是死循环最常见的根源。"

## 3. 循环不变量

> 循环不变量（Loop Invariant）：**在每次迭代开始前（及结束后）都成立的性质**。它是证明循环正确性的核心工具（源自《算法导论》）。

```
循环不变量的三性质：
  ① 初始化：循环开始前，不变量成立
  ② 保持：若某次迭代前成立，迭代后仍然成立
  ③ 终止：循环终止时，不变量 + 条件不成立 → 推出正确结论

（类比数学归纳法：①=归纳基，②=归纳步，③=结论）
```

```java
/**
 * 二分查找：循环不变量 = "目标只可能存在于 [lo, hi] 区间"
 */
public int binarySearch(int[] nums, int target) {
    int lo = 0, hi = nums.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;       // ⚠️ 防溢出写法
        if (nums[mid] == target) return mid;
        if (nums[mid] < target) lo = mid + 1;   // 排除左半，不变量保持
        else hi = mid - 1;                      // 排除右半，不变量保持
    }
    return -1;      // 终止：lo > hi → 区间为空 → 目标不存在 ✓
}
// ① 初始化：[0, n-1] 覆盖全部元素，目标若存在必在其中 ✓
// ② 保持：每轮按有序性排除一半，目标不会落在排除区 ✓
// ③ 终止：区间为空 → 目标不存在 ✓ 算法正确
```

| 场景 | 常用不变量 | 终止后结论 |
|------|-----------|-----------|
| 二分查找 | 目标 ∈ [lo, hi] | 区间空 → 不存在 |
| 快速排序分区 | [lo, i) 全 ≤ 基准 | i 即基准最终位置 |
| 快慢指针移除 | [0, slow) 全为保留值 | slow = 新长度 |
| 前缀和 | prefix[i] = sum[0..i) | 区间和 O(1) 查询 |

> 💡 面试价值："为什么这个循环是对的？"——用循环不变量三性质回答，直接拉开档次。刷题时把不变量写成注释，边界错误会大幅减少。

## 4. 三种循环结构与选型

| 结构 | 语义 | 典型场景 | 特点 |
|------|------|---------|------|
| `for` | 次数已知 | 数组/列表遍历、计数 | 三要素集中在头部，最不易漏 |
| `while` | 条件驱动 | 读输入、二分、快慢指针 | 灵活，但步进易漏（死循环源） |
| `do-while` | 至少执行一次 | 输入校验、菜单循环 | 先执行后判断，边界易忘 |

```java
// for：遍历次数确定
for (int i = 0; i < nums.length; i++) { ... }

// while：条件驱动（双指针/二分/输入流）
int i = 0;
while (i < nums.length && nums[i] < 0) i++;

// do-while：至少执行一次（输入校验）
int n;
do {
    n = scanner.nextInt();
} while (n < 0);
```

```
选型口诀：
  "数得清次数" → for
  "条件说了算" → while
  "必须先干一次" → do-while
⚠️ 面试常问："while 和 for 有什么区别？"
   → 本质等价；for 把三要素集中，更不易漏步进
```

## 5. 边界与死循环

### 5.1 半开区间约定

```
统一用 [0, n)（左闭右开）：
  · 循环变量取值 0..n-1，共 n 次
  · 条件写作 i < n，而不是 i <= n-1
  · 越界风险最小化，与集合 size()/subList 语义一致

⚠️ 混用 [0, n] 与 [0, n) 是 off-by-one 错误的根源
```

### 5.2 三类典型边界错误

| 错误 | 表现 | 修正 |
|------|------|------|
| 越界（i <= n 遍历数组） | ArrayIndexOutOfBounds | `i < nums.length` |
| 漏处理最后一个元素 | 结果少一项 | 用 [0, n) 并验证 n=0/1 边界 |
| 空集合/单元素特殊分支 | 误入循环或跳过 | 先手推 n=0、n=1 两种情况 |

### 5.3 死循环四问

```
① 更新步进真的执行了吗？（continue 跳过了？）
② 条件可能恒真吗？（边界变量被修改了？）
③ 步进方向对吗？（i-- 写成 i++？）
④ 浮点相等判断？（== 改为误差比较 |a-b| < eps）

⚠️ 浮点循环是经典坑：while (x != 1.0) 可能永远不成立
```

## 6. 迭代的执行模型

```
迭代的执行模型：
  单帧执行：循环体始终复用同一份栈帧/寄存器
  无栈增长：占用空间与迭代次数无关 → 天然无栈溢出
  硬件友好：规律性循环命中 I-Cache
             分支预测对"每轮同方向"的循环命中率高
```

| 维度 | 迭代 | 递归 |
|------|------|------|
| 执行帧 | 复用一个 | 每层新建 |
| 空间 | O(1)（无显式栈） | O(深度) |
| 栈溢出 | 不会 | 深度大时会发生 |
| 指令局部性 | 好（循环体连续执行） | 差（反复跳转调用） |
| 调试 | 状态可随时打印 | 需要跟踪调用栈 |

> 💡 所以"递归转迭代"不仅是面试考点，也是真实工程里防止 `StackOverflowError` 的硬需求——详见模块 03。

## 7. 迭代 vs 递归

| 维度 | 迭代 | 递归 |
|------|------|------|
| 状态存储 | 显式变量 | 调用栈帧 |
| 空间复杂度 | O(1)（无显式栈） | O(深度) |
| 栈溢出风险 | 无 | 深度 > 10⁴~10⁵ 可能溢出 |
| 表达力 | 线性推进自然 | 树/分治/回溯自然 |
| 性能 | 无调用开销 | 压栈/弹栈开销 |
| 何时优先 | 数组、数值、状态机、大深度 | 树、链表自相似结构、回溯 |

```
记忆：递归把状态藏进调用栈（隐式），
     迭代把状态摆在变量里（显式）。
     能用迭代就用迭代；树/回溯写递归，被追问再转迭代。
```

> 🎯 **核心要点**：迭代 = **重复执行 + 状态更新 + 终止判定**。三要素（初始化/条件/步进）缺一不可，**漏更新步进是死循环头号根源**；循环不变量（初始化/保持/终止）是证明正确性的武器；`[0, n)` 半开区间统一边界；迭代无栈增长、硬件友好，是与递归（状态在调用栈）的本质区别。
