## 1. 知识体系导图

```text
暴力枚举（Brute Force）
│
├── 核心本质 ──────────────────────────────────────────────
│   ├── = 无遗漏遍历解空间（生成 + 验证）
│   ├── 三要素：枚举对象、枚举范围、验证条件
│   ├── 复杂度 = 解空间大小 × 单解验证成本
│   └── 方法论：「先暴力后优化」——暴力保正确，优化提性能
│
├── 四大模型 ──────────────────────────────────────────────
│   ├── 🟢 顺序枚举（for 循环）   → 复杂度 O(n)/O(n²)
│   ├── 🟡 子集枚举（位掩码 2ⁿ） → O(2ⁿ·n)，n ≤ 20
│   ├── 🔴 排列枚举（n!）        → O(n!·n)，n ≤ 10
│   └── 🟡 组合枚举（C(n,k)）    → O(C·k)，剪枝空间最大
│
├── 优化加速六法（先暴力后优化）────────────────────────────
│   ├── 剪枝：提前排除无效分支（不影响正确性）
│   ├── 哈希：内层查找 O(n) → O(1)（空间换时间）
│   ├── 二分：有序查找 O(log n)
│   ├── 双指针：二维枚举降一维（需单调性）
│   ├── 前缀和：区间求和免重复计算
│   └── 预处理：排序/统计先做一遍
│
├── 五大经典题型 ──────────────────────────────────────────
│   ├── 🟡 查找与统计（两数之和、和为 K 子数组、回文枚举）
│   ├── 🟡 子集与组合（78/77/39/40/216，衔接回溯）
│   ├── 🟡 排列（46/47/31，used 数组与 nextPermutation）
│   ├── 🔴 棋盘与网格（N 皇后、数独、单词搜索的暴力版）
│   └── 🟡 区间与子数组（滑动窗口、前缀和计数）
│
├── 与兄弟算法关系 ────────────────────────────────────────
│   ├── 回溯 = 枚举 + 剪枝（DFS 骨架）
│   ├── 分支限界 = 枚举 + 界函数（求最优解）
│   ├── 动态规划 = 枚举 + 记忆化（去重叠）
│   ├── 贪心 = 枚举的"一步到位"替代（需证明）
│   └── 递归 = 枚举的代码载体（排列/组合递归实现）
│
└── Java 实战 ─────────────────────────────────────────────
    ├── 四模型模板默写（顺序/位掩码/交换递归/start 递归）
    ├── 去重三原则（排序 + 同层去重 + 深拷贝）
    └── 复杂度话术：解空间 × 验证成本，先说最坏再谈剪枝
```

## 3. 学习路线推荐

### 🟢 路线 A：零基础入门（1 周）
```text
00 总览 → 01 四模型（模板默写）→ 07 复杂度分析
→ 练习：1 两数之和 → 78 子集 → 46 全排列 → 77 组合
```
- **目标**：能独立写出四种枚举模型，并说出各自的复杂度与规模上限
- **题量**：约 8-10 题

### 🟡 路线 B：刷题进阶（2 周）
```text
01-02 快速过 → 04 查找统计（1/15/560/5）
→ 05 子集组合（78/77/39/40）→ 06 排列（46/47/31）
→ 03 加速技术（双指针/前缀和/滑动窗口）
```
- **目标**：掌握"暴力 → 优化"的完整升级链，能在面试中展示优化思路
- **题量**：约 20-25 题

### 🔴 路线 C：体系贯通（3 周）
```text
01→08 全模块 + 每类 5-8 题
→ 同题多解对比：78（位掩码/迭代/回溯）、46（交换/used）
→ 衔接专项：暴力 → 回溯（剪枝）→ DP（记忆化）的演化路径
→ 复杂度估算专项（07）——判断何时该优化
```
- **目标**：任何题目先写暴力验证思路，再定向优化；复杂度估算 10 秒内完成
- **题量**：约 35-40 题

## 8. 常见误区速查

| 误区 | 正解 |
|------|------|
| "暴力枚举是笨办法，面试不能提" | ❌ 「先暴力后优化」是标准方法论——先保证正确性，再谈优化 |
| "枚举和回溯是两种算法" | ❌ 回溯 = 枚举 + 剪枝（DFS 骨架），是同族 |
| "位掩码能枚举 n=30 的子集" | ❌ 2³⁰ ≈ 10 亿，必超时；n ≤ 20~22 才可行 |
| "排列枚举的复杂度是 O(n!)" | ❌ 生成 n! 个排列每个成本 O(n)，总 O(n!·n) |
| "组合用 used 数组去重" | ❌ 组合用 startIndex 不回头；used 是排列的 |
| "结果集直接 add(path)" | ❌ 必须深拷贝 new ArrayList<>(path)，否则全共享同一引用 |
| "有重复元素不用处理" | ❌ 必须先排序，再用同层去重（i > start && nums[i]==nums[i-1]） |
| "枚举复杂度只说最坏" | ❌ 要说「解空间 × 验证成本」，再补剪枝后的实际表现 |

## 9. 术语表

| 术语 | 英文 | 定义 |
|------|------|------|
| 暴力枚举 | Brute Force | 无优化地遍历全部解空间 |
| 解空间 | Solution Space | 所有可能解的集合 |
| 枚举 | Enumeration | 系统化遍历解空间的过程 |
| 子集 | Subset | 集合的任一子集（2ⁿ 个） |
| 排列 | Permutation | 有序的全排列（n! 个） |
| 组合 | Combination | 无序的 k-选取（C(n,k) 个） |
| 位掩码 | Bitmask | 用二进制位表示元素选/不选 |
| 剪枝 | Pruning | 提前排除不可能的分支 |
| 记忆化 | Memoization | 缓存递归结果去重（衔接 DP） |
| 前缀和 | Prefix Sum | 区间和 O(1) 查询的预处理 |
| 滑动窗口 | Sliding Window | 连续子数组的线性枚举 |
