## 1. 优化的本质：把"内层查找"变快

回顾 02 文件的核心公式：

```text
枚举复杂度 = 解空间大小 × 单解验证成本
```

优化的两条路：

| 优化方向 | 手段 | 本质 |
|---------|------|------|
| **少枚举**（缩小解空间） | 剪枝、双指针跳过、滑动窗口 | 减少要验证的解的个数 |
| **快验证**（降低单解成本） | 哈希 O(1)、二分 O(log n)、前缀和 O(1) | 让每个解的验证更快 |

> 🎯 **本文件的四大武器分工**：双指针与滑动窗口属于"少枚举"（把 O(n²) 对枚举压缩为 O(n) 趟）；前缀和与排序预处理属于"快验证"（把重复计算缓存起来）。**面试讲优化，先分类再动手**——"这题瓶颈在内层查找，我可以用哈希换 O(1)"比直接改代码更像工程师。

## 2. 双指针：二维枚举降一维

### 2.1 原理

双指针把"枚举所有 (i, j) 对"的 O(n²) 压缩为"两个指针相向/同向移动"的 O(n)——前提是**数组有序且答案具有单调性**：

```text
暴力: for i in [0,n): for j in [i+1,n): check(i,j)     O(n²)
双指针: l=0, r=n-1; while(l<r){ sum 偏大 → r--; 偏小 → l++ }  O(n)
```

为什么可以跳过大量对？因为有序保证：`nums[l] + nums[r] > target` 时，**任何 j > r 的组合只会更大**——l 与 [r+1, n) 的所有配对都无望，整段跳过。这就是"少枚举"。

### 2.2 模板：两数之和（有序版）

```java
// 两数之和（有序数组，167 题）：暴力 O(n²) → 双指针 O(n)
public int[] twoSumSorted(int[] nums, int target) {
    int l = 0, r = nums.length - 1;
    while (l < r) {
        int sum = nums[l] + nums[r];
        if (sum == target) return new int[]{l + 1, r + 1};
        else if (sum < target) l++;   // 和太小，左指针右移增大
        else r--;                      // 和太大，右指针左移减小
    }
    return new int[0];
}
```

### 2.3 三数之和：双指针套内层（15 题）

```java
// 15 三数之和：排序 + 固定 i + 双指针(l, r)
public List<List<Integer>> threeSum(int[] nums) {
    List<List<Integer>> res = new ArrayList<>();
    Arrays.sort(nums);
    int n = nums.length;
    for (int i = 0; i < n - 2; i++) {
        if (nums[i] > 0) break;              // 剪枝：最小都大于 0
        if (i > 0 && nums[i] == nums[i - 1]) continue;   // 去重：同值跳过
        int l = i + 1, r = n - 1;
        while (l < r) {
            int sum = nums[i] + nums[l] + nums[r];
            if (sum == 0) {
                res.add(Arrays.asList(nums[i], nums[l], nums[r]));
                while (l < r && nums[l] == nums[l + 1]) l++;   // 去重
                while (l < r && nums[r] == nums[r - 1]) r--;
                l++; r--;
            } else if (sum < 0) l++;
            else r--;
        }
    }
    return res;
}
```

复杂度对比：暴力三重循环 O(n³) → 排序 O(n log n) + 每 i 一趟双指针 O(n) = **O(n²)**。

> 💡 四数之和（18 题）同理：固定 i、j 两层，内层双指针，O(n³)。**双指针消灭的是最内层的枚举**——"少枚举一层"是它的核心价值。

### 2.4 双指针的适用条件

| 条件 | 说明 | 违反时 |
|------|------|--------|
| 有序（或可排序） | 单调性由有序保证 | 不能直接排序的题（需保下标） |
| 目标单调 | 和大了要减小、小了要增大 | 无单调关系时双指针失效 |
| 无重复对 | 有序后 l/r 相遇即遍历完 | 需要全部对的题不适合 |

## 3. 滑动窗口：连续子数组的线性枚举

### 3.1 原理

暴力枚举所有连续子数组是 O(n²)（起点 × 终点）；滑动窗口让左右指针**只前进不后退**，每个元素至多进出窗口一次 → **O(n)**。

```text
暴力: for i in [0,n): for j in [i,n): 检查子数组[i..j]    O(n²)
滑动窗口: l=0; for r in [0,n): 扩右 → 不满足时缩左 → 记录   O(n)
```

### 3.2 模板：无重复最长子串（3 题）

```java
// 3 无重复字符的最长子串：O(n²) 暴力 → O(n) 滑动窗口
public int lengthOfLongestSubstring(String s) {
    Set<Character> window = new HashSet<>();
    int l = 0, maxLen = 0;
    for (int r = 0; r < s.length(); r++) {
        while (window.contains(s.charAt(r))) {   // 有重复 → 缩左
            window.remove(s.charAt(l));
            l++;
        }
        window.add(s.charAt(r));                  // 扩右
        maxLen = Math.max(maxLen, r - l + 1);
    }
    return maxLen;
}
```

### 3.3 滑动窗口 vs 双指针 vs 前缀和

| 技术 | 场景 | 复杂度 |
|------|------|:---:|
| 相向双指针 | 找两数/三数和（有序） | O(n) |
| 同向双指针（滑动窗口） | 连续子数组满足条件 | O(n) |
| 前缀和 + 哈希 | 子数组和 == K（无序可） | O(n) |

> ⚠️ 滑动窗口的前提是**窗口收缩单调**（左指针右移必然让"不满足"趋于"满足"）。若窗口内"加元素"和"减元素"对目标的影响不单调（如求乘积含 0），滑动窗口失效。

## 4. 前缀和与差分：区间操作 O(1)

### 4.1 前缀和模板

```java
// 前缀和：预处理 O(n)，区间和查询 O(1)
long[] pre = new long[n + 1];
for (int i = 0; i < n; i++) pre[i + 1] = pre[i] + nums[i];

// 区间 [l, r] 的和（含两端）
long sum = pre[r + 1] - pre[l];
```

**暴力 vs 前缀和**：枚举所有区间的和从 O(n³)（枚举起点×终点×求和）降到 O(n²)（枚举起点×终点，O(1) 求区间和）；再配哈希可降到 O(n)（见 04 文件 560 题）。

### 4.2 二维前缀和（304 题）

```java
// 二维前缀和：预处理 O(nm)，任意子矩阵和 O(1)
int[][] pre = new int[m + 1][n + 1];
for (int i = 1; i <= m; i++)
    for (int j = 1; j <= n; j++)
        pre[i][j] = pre[i-1][j] + pre[i][j-1] - pre[i-1][j-1] + matrix[i-1][j-1];

// 子矩阵 (r1,c1)-(r2,c2) 的和
int sum = pre[r2+1][c2+1] - pre[r1][c2+1] - pre[r2+1][c1] + pre[r1][c1];
```

> 🎯 **记忆点**：二维前缀和公式 = "大矩形 − 左 − 上 + 左上"——容斥原理。暴力枚举子矩阵是 O(n⁴)，前缀和后 O(n²) 枚举 + O(1) 查询。

### 4.3 差分数组：区间修改 O(1)

```text
差分数组 diff[i] = nums[i] - nums[i-1]
区间 [l, r] 全体 +v  →  diff[l] += v; diff[r+1] -= v;    // O(1)
最后前缀和还原 → 得到修改后的数组
```

典型应用：1109 航班预订统计（批量区间加）。**差分是前缀和的逆运算**——前缀和用于查询，差分用于修改。

## 5. 排序预处理：让枚举有序化

### 5.1 为什么先排序

很多"查找/配对"类暴力题，排序后可以获得**单调性**，从而解锁双指针、二分、去重三大能力：

| 排序带来的能力 | 例子 |
|---------------|------|
| 双指针（单调性） | 15 三数之和、11 盛最多水 |
| 二分查找 | 34 在排序数组中查找 |
| 相邻去重 | 90 子集 II、40 组合总和 II |
| 贪心优先（排序后按序处理） | 406 按身高重建队列 |

### 5.2 排序 + 去重的组合模板

```java
// 排序是去重的前提：让相同元素相邻
Arrays.sort(nums);
// 去重（组合/子集类）：同层跳过相同值
for (int i = start; i < n; i++) {
    if (i > start && nums[i] == nums[i - 1]) continue;   // 同层去重
    ...
}
```

> ⚠️ **排序会破坏原顺序**——需要保下标的题（如 1 两数之和、315 逆序对）不能用原数组排序，可用"下标数组 + 自定义比较"或改用哈希。

## 6. 枚举 + 二分：有序空间里的快速验证

### 6.1 模式

```text
外层枚举一个量（起点/中点/数值），内层在有序结构上二分查找验证
例: 枚举 i，二分找 j 使 nums[i] + nums[j] == target（有序时）
复杂度: O(n log n)，比 O(n²) 快一档
```

### 6.2 实战：长度最小的子数组（209 题）

```java
// 209: 和 ≥ target 的最短连续子数组
// 暴力: O(n²) 枚举起点 × 终点
// 枚举+二分: 前缀和有序 → 枚举起点 i，二分找终点 j
public int minSubArrayLen(int target, int[] nums) {
    int n = nums.length, ans = n + 1;
    long[] pre = new long[n + 1];
    for (int i = 0; i < n; i++) pre[i + 1] = pre[i] + nums[i];
    for (int i = 0; i < n; i++) {
        // 找最小的 j 使 pre[j+1] - pre[i] >= target
        int j = lowerBound(pre, pre[i] + target);
        if (j <= n) ans = Math.min(ans, j - i);
    }
    return ans == n + 1 ? 0 : ans;
}
// 复杂度: O(n log n)；滑动窗口可进一步 O(n)
```

> 💡 **三层递进是面试展示**：暴力 O(n²) → 枚举+二分/前缀和 O(n log n) → 滑动窗口 O(n)。**能把一道题讲出三层优化，比直接给最优解更显功力**。

## 7. 综合案例：一道题的暴力到最优全过程

**题**：和为 K 的子数组（560 题）——求数组中和为 K 的连续子数组个数。

```text
① 暴力三重循环（枚举起点×终点×求和）:  O(n³)    ← 先暴力验证思路
② 前缀和优化求和（枚举起点×终点）:      O(n²)    ← 快验证：区间和 O(1)
③ 前缀和 + 哈希（遍历一遍）:            O(n)     ← 快验证：查"补"O(1)
```

```java
// ③ 前缀和 + 哈希: O(n)
public int subarraySum(int[] nums, int k) {
    Map<Integer, Integer> count = new HashMap<>();   // 前缀和 → 出现次数
    count.put(0, 1);                                 // 空前缀
    int pre = 0, ans = 0;
    for (int x : nums) {
        pre += x;
        ans += count.getOrDefault(pre - k, 0);       // 找补 = pre - k 的个数
        count.put(pre, count.getOrDefault(pre, 0) + 1);
    }
    return ans;
}
```

**完整优化链**：O(n³) → O(n²) → O(n)。每一步改动的理由都对应 02 文件的两条主线（少枚举/快验证）——**这就是「先暴力后优化」方法论的标准演示**。

## 8. 加速技术选型总表

| 问题特征 | 首选加速 | 复杂度 | 典型题 |
|---------|---------|:---:|--------|
| 有序数组找两数和 | 相向双指针 | O(n) | 167 |
| 三个/四个数和 | 排序 + 固定外层 + 双指针 | O(n²)/O(n³) | 15/18 |
| 连续子数组满足条件 | 滑动窗口 | O(n) | 3/209/76 |
| 子数组和 == K | 前缀和 + 哈希 | O(n) | 560 |
| 子矩阵和 | 二维前缀和 | O(n²) 枚举 | 304 |
| 区间批量修改 | 差分数组 | O(1) 修改 | 1109 |
| 枚举 i 找 j（有序） | 二分 | O(n log n) | 209 变体 |
| 有重复需去重 | 排序 + 同层去重 | 预处理 O(n log n) | 90/40/15 |

> 🎯 **核心要点**：加速技术本质 = 02 文件"少枚举 + 快验证"的两条主线。**双指针/滑动窗口消灭内层枚举（少枚举），前缀和/哈希/二分让验证 O(1)/O(log n)（快验证），排序是解锁双指针与去重的前提**。面试展示模板：暴力 O(n³) → 前缀和 O(n²) → 哈希 O(n)，每一层都有明确理由——这就是"先暴力后优化"的标准答案结构。
