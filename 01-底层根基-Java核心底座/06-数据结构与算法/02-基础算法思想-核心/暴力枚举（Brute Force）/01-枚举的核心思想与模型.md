## 1. 枚举的本质

**暴力枚举（Brute Force）**：遍历全部可能的解，逐一验证——「无遗漏」是正确性的保证，「穷举」是性能的天花板。

```text
枚举三要素:
  ① 解空间: 所有可能解（明确范围）
  ② 生成:   按某种顺序无遗漏生成
  ③ 验证:   判断是否满足条件

枚举的复杂度 = 解空间大小 × 单解验证成本

例: 找数组中两数之和为 target
  解空间: C(n,2) 对组合
  单解验证: O(1)
  总复杂度: O(n²)
```

| 要素 | 说明 | 反例 |
|------|------|------|
| 无遗漏 | 所有解都覆盖 | 漏一种情况 → 答案错 |
| 无重复 | 每个解验证一次 | 重复 → 浪费时间 |
| 可验证 | 每个解可判定 | 无法判定 → 无法枚举 |

> 🎯 **枚举的正确性 = 无遗漏**——「暴力错」通常不是暴力本身错，而是漏枚举了边界情况；「先暴力」的最大价值是保证思路正确。

## 2. 顺序枚举

**顺序枚举**：for 循环按序遍历——一维（n）、二维（n²）、多维（nᵏ）。

```java
// 一维顺序枚举: O(n)
for (int i = 0; i < n; i++) {
    check(nums[i]);
}

// 二维顺序枚举: O(n²)
for (int i = 0; i < n; i++) {
    for (int j = i + 1; j < n; j++) {       // 避免重复对 (i,j) 与 (j,i)
        if (nums[i] + nums[j] == target) return true;
    }
}

// 例题 1. 两数之和（暴力版）
public int[] twoSum(int[] nums, int target) {
    for (int i = 0; i < nums.length; i++) {
        for (int j = i + 1; j < nums.length; j++) {
            if (nums[i] + nums[j] == target) {
                return new int[]{i, j};
            }
        }
    }
    return new int[0];                       // O(n²) 暴力 ✓（可哈希优化 O(n)）
}
```

| 技巧 | 说明 |
|------|------|
| `j = i + 1` | 避免对称重复（组合语义） |
| 边界检查 | 枚举范围先验证 |
| 提前返回 | 找到即退出（最优剪枝） |
| 哈希加速 | 两数之和 → O(n)（02 模块） |

> 💡 二维枚举的 `j = i+1` 是「组合 vs 排列」的分水岭——**对枚举 `(i,j)` 与 `(j,i)` 等价时，用 i<j 减半解空间**。

## 3. 子集枚举（位掩码）

**子集枚举**：n 个元素的全部子集 = 2ⁿ 个——用二进制位表示「选/不选」。

```java
// 子集枚举（位掩码）: O(2ⁿ × n)
int[] nums = {1, 2, 3};
int n = nums.length;

for (int mask = 0; mask < (1 << n); mask++) {      // ① 枚举所有掩码 0..2ⁿ-1
    List<Integer> subset = new ArrayList<>();
    for (int i = 0; i < n; i++) {
        if ((mask & (1 << i)) != 0) {              // ② 第 i 位为 1 → 选第 i 个
            subset.add(nums[i]);
        }
    }
    // ③ 处理子集
    System.out.println(subset);
}
// 输出: [] [1] [2] [1,2] [3] [1,3] [2,3] [1,2,3]
```

```text
mask 语义:
  0b000 = {}        （空集）
  0b001 = {1}       （选第 0 个）
  0b101 = {1, 3}    （选第 0、2 个）
  0b111 = {1, 2, 3} （全集）

复杂度: 2ⁿ 个子集 × n 位检查 = O(2ⁿ·n)
适用: n ≤ 20（2²⁰ ≈ 100 万）
```

> ⚠️ **位掩码上限**：n = 20 → 2²⁰ ≈ 100 万（可行）；n = 30 → 10 亿（超时）——**n > 22 时位掩码枚举必须优化**。

**子集枚举的经典题**：

| 题号 | 题目 | 枚举用法 |
|------|------|---------|
| 78 | 子集 | 位掩码模板 |
| 90 | 子集 II | 位掩码 + 去重 |
| 1863 | 子集异或和 | 位掩码 + 异或 |
| 1286 | 组合迭代器 | 组合枚举 |

```java
// 78 子集（位掩码完整版）
public List<List<Integer>> subsets(int[] nums) {
    List<List<Integer>> res = new ArrayList<>();
    int n = nums.length;
    for (int mask = 0; mask < (1 << n); mask++) {
        List<Integer> subset = new ArrayList<>();
        for (int i = 0; i < n; i++) {
            if ((mask & (1 << i)) != 0) subset.add(nums[i]);
        }
        res.add(subset);
    }
    return res;
}
```

> 💡 位掩码的优雅：**一个 int 就是整个子集状态**——传递/比较/记忆化全部 O(1)（这是状态压缩 DP 的根基，衔接[动态规划](../../03-高频专题模块/动态规划 DP（Dynamic Programming）/)）。

## 4. 排列枚举

**排列枚举**：n 个元素的全排列 = n! 个——递归交换法 / nextPermutation。

```java
// 排列枚举（递归交换法）: O(n! × n)
void permute(int[] nums, int start, List<List<Integer>> res) {
    if (start == nums.length) {                    // ① 完整排列
        List<Integer> list = new ArrayList<>();
        for (int x : nums) list.add(x);
        res.add(list);
        return;
    }
    for (int i = start; i < nums.length; i++) {    // ② 当前位置逐个尝试
        swap(nums, start, i);                      // ③ 交换到 start
        permute(nums, start + 1, res);             // ④ 递归下一位置
        swap(nums, start, i);                      // ⑤ 回溯还原
    }
}
// 输入 [1,2,3] → 6 个排列
```

```java
// 字典序排列: nextPermutation（31 题模板）
boolean nextPermutation(int[] nums) {
    int i = nums.length - 2;
    while (i >= 0 && nums[i] >= nums[i + 1]) i--;  // ① 找第一个降序点
    if (i < 0) { reverse(nums, 0); return false; } // 已是最后一个
    int j = nums.length - 1;
    while (nums[j] <= nums[i]) j--;                // ② 找第一个更大
    swap(nums, i, j);                              // ③ 交换
    reverse(nums, i + 1);                          // ④ 反转后缀
    return true;
}
```

| 方式 | 特点 |
|------|------|
| 递归交换 | 生成全部排列（回溯） |
| nextPermutation | 字典序逐个生成（去重天然） |
| 复杂度 | O(n! × n)（生成 n! 个 × 每份 n 成本） |

> ⚠️ **排列的上限**：10! = 362 万（可行）、11! = 4000 万（危险）、12! = 4.8 亿（超时）——**n > 10 的全排列必须剪枝**。

## 5. 组合枚举

**组合枚举**：从 n 个选 k 个 = C(n,k) 个——递归「选/不选」或「从 start 开始选」。

```java
// 组合枚举 C(n, k): 递归（回溯模板）
void combine(int n, int k, int start, List<Integer> path, List<List<Integer>> res) {
    if (path.size() == k) {                        // ① 选够 k 个
        res.add(new ArrayList<>(path));
        return;
    }
    for (int i = start; i <= n; i++) {             // ② 从 start 开始（组合无序）
        path.add(i);                               // ③ 选
        combine(n, k, i + 1, path, res);           // ④ 下一个从 i+1（不回头）
        path.remove(path.size() - 1);              // ⑤ 回溯
    }
}
// C(4,2) → 6 个组合: [1,2] [1,3] [1,4] [2,3] [2,4] [3,4]
```

```text
组合 vs 排列的区别:
  组合: [1,2] == [2,1]（无序）→ 从 start 开始，不回头
  排列: [1,2] != [2,1]（有序）→ 全排列，交换法

组合的剪枝优化:
  for (int i = start; i <= n - (k - path.size()) + 1; i++)
  → 剩余数量不足直接跳过（经典剪枝）
```

| 经典组合题 | 枚举方式 |
|-----------|---------|
| 77 组合 | 递归模板（剪枝） |
| 39 组合总和 | 组合 + 可重复 |
| 40 组合总和 II | 组合 + 去重 |
| 216 组合总和 III | 组合 + 固定和 |

> 💡 组合枚举是[回溯算法（Backtracking）](../回溯算法（Backtracking）/)的第一模板——「从 start 开始 + 不回头」是组合去重的本质；剪枝优化（剩余不足）是回溯的入门技巧。

## 6. 四模型复杂度总表

| 模型 | 解空间大小 | 复杂度 | 上限（约） | 典型题 |
|------|:---:|:---:|:---:|--------|
| 顺序枚举 | n 或 n² | O(n) / O(n²) | n ≤ 10⁵ / n ≤ 10⁴ | 1 两数之和 |
| 子集枚举 | 2ⁿ | O(2ⁿ·n) | n ≤ 20 | 78 子集 |
| 排列枚举 | n! | O(n!·n) | n ≤ 10 | 46 全排列 |
| 组合枚举 | C(n,k) | O(C(n,k)·k) | 依 k 而定 | 77 组合 |

```text
选型速记:
  顺序 → 数据规模主导（数组题）
  子集 → 2ⁿ（状态压缩的入口）
  排列 → n!（最快爆炸，必剪枝）
  组合 → 中间态（剪枝空间最大）
```

**面试追问**：

| 追问 | 答题要点 |
|------|---------|
| 枚举的复杂度怎么算？ | 解空间 × 单解验证 |
| 什么时候枚举？ | 解空间 ≤ 10⁶ / 验证正确性 |
| 位掩码为什么只能 n ≤ 20？ | 2²⁰ ≈ 100 万、2³⁰ 超时 |
| 组合为什么从 start 开始？ | 无序（i<j 防重复） |
| 排列为什么交换法？ | 全排列有序（递归交换） |
| 枚举和回溯的关系？ | 回溯 = 枚举 + 剪枝 |

> 🎯 **核心要点**：本节验收——四模型模板默写（顺序 for、子集位掩码、排列交换、组合 start）；四复杂度（n/2ⁿ/n!/C(n,k)）与上限（10⁵/20/10/剪枝）；「j=i+1 组合语义」「位掩码 1<<i」「组合不回头」三个关键细节；「先暴力后优化」的方法论。优化技巧见 02 模块。
