## 1. 复杂度公式：解空间 × 验证成本

枚举复杂度的唯一公式：

```text
T(枚举) = 解空间大小（要枚举的解的个数） × 单解验证成本（检查一个解花多少时间）
```

### 1.1 公式的分解

| 组成部分 | 含义 | 例子（两数之和） |
|---------|------|----------------|
| 解空间大小 | 枚举对象的数量 | C(n,2) ≈ n²/2 |
| 单解验证成本 | 检查一个解是否满足条件 | 两数相加比较 O(1) |
| 总复杂度 | 两者相乘 | O(n²) |

### 1.2 公式的两种优化方向（呼应 02/03 文件）

```text
少枚举: 缩小解空间大小（剪枝、双指针、滑动窗口）
快验证: 降低单解验证成本（哈希 O(1)、二分 O(log n)、前缀和 O(1)）
```

> 🎯 **面试被问"枚举的复杂度怎么分析"——答出公式 + 两个优化方向 + 一个具体例子（两数之和 O(n²) → O(n)），三句话构成完整答案**。

## 2. 1 秒规则：规模与复杂度的对应表

**1 秒规则**：现代 CPU 每秒约执行 10⁸~10⁹ 条基础指令。按保守估计（常数因子 ~10），**1 秒能跑完的操作数约 10⁷~10⁸**，据此反推各复杂度允许的输入规模：

| 复杂度 | 允许规模（约） | 例子 | 决策 |
|:---:|:---:|------|------|
| O(n) | 10⁷ ~ 10⁸ | 线性扫描 | ✔ 放心枚举 |
| O(n log n) | 10⁶ ~ 10⁷ | 排序 | ✔ 放心枚举 |
| O(n²) | 10⁴ ~ 10⁵ | 两数之和暴力 | ⚠️ 注意上限 |
| O(n³) | ~500 | 三重循环 | ⚠️ 小数据可用 |
| O(2ⁿ) | n ≤ 20~22 | 子集枚举 | 🔴 必须控制 n |
| O(n!) | n ≤ 10 | 排列枚举 | 🔴 必须剪枝 |
| O(n·2ⁿ) | n ≤ 15~18 | 状压 DP 枚举 | 🔴 必须优化 |

> ⚠️ **经验区间而非铁律**：Java 常数因子比 C++ 大（约 3-5 倍），LeetCode 时限通常 1-2 秒（宽松到 10⁸）。实际做题按**保守档**（10⁷）估算，超了就想优化。

## 3. 四种模型的上限速算

```text
顺序枚举:    n ≤ 10⁷（O(n)）/ n ≤ 10⁴（O(n²)）
子集枚举:    n ≤ 20（2²⁰ ≈ 100 万，×n 位检查 ≈ 2000 万 → 可过）
              n ≤ 22（2²² ≈ 400 万，需注意常数）
排列枚举:    n ≤ 10（10! = 362 万，×n 成本 ≈ 3600 万 → 勉强）
              n ≤ 9（9! = 36 万 → 轻松）
组合枚举:    C(n,k) 依 k 而定——n=30, k=10 → 3 亿（不可行，必须剪枝）
```

**速算技巧**：

```text
2¹⁰ ≈ 10³（千）     2²⁰ ≈ 10⁶（百万）     2³⁰ ≈ 10⁹（十亿）
10! = 3.6×10⁶        11! = 4×10⁷            12! = 4.8×10⁸
C(20,10) ≈ 1.8×10⁵   C(30,15) ≈ 1.6×10⁸
```

> 🎯 **必背三组数**：2²⁰ ≈ 100 万、10! ≈ 360 万、2³⁰ ≈ 10 亿——它们分别决定了子集、排列、超大规模的上限直觉。

## 4. 指数爆炸的直觉：2ⁿ 与 n! 的临界点

### 4.1 增长对比表

| n | 2ⁿ | n! | 直觉 |
|:---:|:---:|:---:|------|
| 10 | 1024 | 3.6×10⁶ | 都可行 |
| 15 | 3.3×10⁴ | 1.3×10¹² | 排列已死 |
| 20 | 1.0×10⁶ | 2.4×10¹⁸ | 子集还可，排列绝望 |
| 25 | 3.4×10⁷ | — | 子集接近极限 |
| 30 | 1.1×10⁹ | — | 子集超时（≈ 10 亿） |

### 4.2 三个临界点（背下来）

```text
n = 10:  n! 可行上限（排列枚举）
n = 20:  2ⁿ 可行上限（子集/位掩码）
n = 22:  位掩码纯枚举极限（2²² ≈ 420 万，勉强）
```

> ⚠️ 面试高频追问："n=25 的数组枚举所有子集可行吗？" 答案：**2²⁵ ≈ 3300 万掩码 × 25 位检查 ≈ 8 亿操作——超时，必须用回溯 + 剪枝（提前排除）或换 DP**。能当场速算出 8 亿，说明规模直觉到位。

## 5. 优化决策树：什么时候该优化

```text
拿到暴力枚举方案
│
├─ 估算解空间大小 S（用 1 秒规则）
│
├─ S ≤ 10⁷ → 直接暴力 ✔（提交即可）
│
├─ 10⁷ < S ≤ 10⁸ → 轻微优化：剪枝 + 提前返回
│
├─ 10⁸ < S ≤ 10¹⁰ → 必须换思路：
│   ├─ 能"少枚举"？→ 双指针 / 滑动窗口 / 剪枝
│   ├─ 能"快验证"？→ 哈希 / 二分 / 前缀和
│   ├─ 有重叠子问题？→ 动态规划（枚举 + 记忆化）
│   └─ 是求最优解 + 可设计界函数？→ 分支限界
│
└─ S > 10¹⁰ → 基本告别精确枚举：
    ├─ 贪心 / 近似（可接受近似解）
    ├─ 求解器 / 专用算法（工业级）
    └─ 数学构造（找到闭式解）
```

### 决策示例

| 题目 | 暴力规模 | 决策 |
|------|:---:|------|
| 1 两数之和（n=10⁵） | C(10⁵,2) ≈ 5×10⁹ | 🔴 必须优化 → 哈希 O(n) |
| 78 子集（n=15） | 2¹⁵ = 3.3×10⁴ | ✔ 直接暴力 |
| 78 子集（n=25） | 2²⁵ ≈ 3.3×10⁷ | ⚠️ 边缘 → 剪枝/换写法 |
| 51 N 皇后（n=8） | C(64,8) ≈ 4.4×10⁹ | 🔴 必须递进剪枝（06 文件） |
| 46 全排列（n=10） | 10!×10 ≈ 3.6×10⁷ | ✔ 可行但紧 → 用剪枝更稳 |

## 6. 复杂度分析的标准答案结构

面试/笔试分析枚举复杂度的四步模板：

```text
① 解空间: "解空间是 X 个（C(n,2) / 2ⁿ / n! / C(n,k)）"
② 验证成本: "每个解验证需要 O(Y)"
③ 总复杂度: "所以是 O(X × Y)"
④ 规模判断: "按 1 秒规则，n ≤ 阈值时可行；本数据规模 …，需要/不需要优化"
```

**完整示例**（三数之和）：

> "暴力三重循环枚举所有三元组，解空间 C(n,3) ≈ n³/6，每次验证三个数和是否为 0 是 O(1)，总 O(n³)。n = 3000 时约 4.5×10⁹ 操作，超时——所以排序后用固定一位 + 双指针，内层从 O(n²) 降到 O(n)，总 O(n²)，n = 3000 时约 900 万，可行。"

> 🎯 **这就是"复杂度分析 = 公式 + 估算 + 决策"的三段式**——面试官听到的不是"O(n²)"这个结论，而是"你怎么得出这个结论、数据规模下意味着什么"的完整推理。

## 7. 规模估算实战演练

### 演练 1：子集异或和（1863）

```text
题: n ≤ 12，求所有子集的异或和之和
解空间: 2¹² = 4096 个子集，每个子集求异或 O(n) = 12
总复杂度: 4096 × 12 ≈ 5 万 → 直接暴力 ✔
```

### 演练 2：组合总和（39）

```text
题: candidates 长度 n ≤ 30，target ≤ 500
解空间: 最坏 2³⁰（每个元素可选可不选）
但 target 限制下实际组合数远小 → 剪枝（和超 target 即停）后可行
复杂度: 理论 O(2ⁿ)，实际由剪枝决定 → 面试答"最坏指数，实际剪枝后远小"
```

### 演练 3：全排列（46）

```text
题: n ≤ 8
解空间: 8! = 40320 个排列 × 8 复制成本 ≈ 32 万 → 直接暴力 ✔
题: n ≤ 12（LeetCode 扩展场景）
12! = 4.8 亿 × 12 ≈ 57 亿 → 超时 → 必须剪枝 / 换思路（如 DP/数学）
```

### 演练 4：暴力回文（5）

```text
题: 字符串长 n ≤ 1000
暴力三重: n³ = 10⁹ → 超时
中心扩展: 2n−1 个中心 × 平均扩展 O(n) → n² = 10⁶ → 可行 ✔
```

### 演练 5：规模决策的完整闭环（N 皇后）

```text
题: 8×8 棋盘放 8 个皇后，枚举所有摆法
① 最朴素的"任选 8 格":  C(64, 8) ≈ 4.4×10⁹ → 估算出不可行
② 决策: 必须优化 → 约束递进（每行一个 → 列不重复 → 对角线）
③ 剪枝后实际: ~2000 个结点 → 秒出
④ 验证: 结果与已知解数（8 皇后 = 92 种）对照
结论: "估算 → 决策 → 剪枝 → 验证"是规模分析的标准闭环
```

### 7.1 自查清单（每次写完暴力后过一遍）

```text
□ 解空间算对了吗？（组合/排列/子集别混）
□ 验证成本是 O(1) 吗？（不是则考虑哈希/二分/前缀和）
□ 数据规模下 1 秒能跑完吗？（保守按 10⁷）
□ 超时的话，是"少枚举"还是"快验证"？（说出优化方向）
□ 优化后与暴力对拍过了吗？（正确性兜底）
```

> 🎯 **核心要点**：规模估算 = 枚举决策的第一道闸门。背三组数（2²⁰/10!/2³⁰）、记三临界点（10/20/22）、用四步模板（解空间→验证→总复杂度→规模判断）。**"先估算后动手"是把暴力枚举用好、避免白写超时代码的必修课**——估算能力也是面试官判断工程素养的隐形考点。
