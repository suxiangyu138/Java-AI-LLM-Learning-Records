## 1. 适用边界：什么时候计数排序赢

### 1.1 复杂度对比的真相

```
计数排序：O(n + k)（k = 值域大小）
快排：O(n log n)（常数小）

⚠️ 关键比值：k 与 n 的关系
  k ≈ n    → 计数 O(2n) vs 快排 O(n log n) → 计数赢
  k ≈ n²   → 计数 O(n²) vs 快排 O(n log n) → 快排赢
  k 巨大   → 计数空间爆炸 → 不可能

经验法则：
  k ≤ 10·n → 计数排序有竞争力
  k ≤ n    → 计数排序显著更快
  否则      → 快排/基数
```

### 1.2 判断决策树

```
① 值域 k 有多大？
   小（≤ 10⁶ 且 ≈ n）→ 计数排序 ✅
   中（可分位）      → 基数排序
   大（任意）        → 快排
② 需要稳定吗？
   需要 → 计数（稳定版）/ 归并
   不需要 → 计数（非稳定版更省）/ 快排
③ 数据分布？
   均匀 → 桶排序也可
   
⚠️ 面试表达：
"计数排序 O(n+k)，赢不赢取决于 k 与 n 的关系——
 k 与 n 同量级时线性优势明显；
 k 远大于 n 时空间与时间双重劣化。"
```

### 1.3 计数排序的隐藏开销

```
① 值域扫描：统计后要遍历 count 数组展开（O(k)）
   k 大时即使 n 小也要 O(k)
② 缓存行为：count 数组随机访问（值域大时缓存差）
③ 空间：O(k) 可能触发 GC 压力

⚠️ 工程结论：
  计数排序在"值域小 + 数据多"的场景是杀手锏
  例：成绩排序（0-100）、年龄统计（0-150）、
      状态码统计、像素直方图
```

## 2. 稳定实现的完整推导

### 2.1 位置语义（前缀和的含义）

```
count[v] = 值 v 的出现次数
前缀和后：count[v] = 值 ≤ v 的元素个数
  → 值 v 的元素在输出数组中的位置区间为：
     [count[v-1], count[v])    （左闭右开）

⚠️ 为什么从后往前放置：
  从后往前遍历原数组 → 相同值 v 的元素
  依次放入位置区间的最右端 → 先放的后放？
  不——倒序遍历保证：原数组靠后的元素先放置到
  区间右端，靠前的元素随后放在它左边
  → 原顺序保持 ✓（稳定）

推演 [2,1,2]：
  count = [1, 0, 2] → 前缀和 [1, 1, 3]
  倒序遍历原数组：
    nums[2]=2 → output[--count[2]]=output[2] → 放 2
    nums[1]=1 → output[--count[1]]=output[0] → 放 1
    nums[0]=2 → output[--count[2]]=output[1] → 放 2
  output = [1, 2, 2] —— 两个 2 原顺序（先出现的在左）✓
```

### 2.2 稳定性验证的通用方法

```
验证：构造"相同 key 不同原顺序"的输入
  [2a, 1, 2b] → 排序后必须 [1, 2a, 2b]
  （a、b 只是标记，key 相同）

⚠️ 面试表达：
"稳定版的关键是'前缀和定位 + 倒序放置'——
 倒序保证相同值的元素按原相对顺序落位。
 若正序放置，相同值的顺序会反转。"
```

### 2.3 不稳定版何时可接受

```
非稳定版（直接展开）：
  优点：省 output 数组（O(1) 额外空间）
  缺点：无法排序"对象/结构体"

✅ 适用：纯值排序（整数/字符，值即信息）
❌ 不适用：对象按字段排序、需要保留原序

⚠️ 判断："排序对象是值本身还是值的载体？"
  值本身 → 非稳定版够用
  值的载体（对象）→ 必须稳定版
```

## 3. 对象与结构体的计数排序

### 3.1 对象排序的完整实现

```java
/** 对象按 key 字段计数排序（必须稳定版） */
void countingSortObjects(Pair[] arr) {
    int k = 值域大小(arr);
    int[] count = new int[k];

    for (Pair p : arr) count[p.key]++;          // ① 频次
    for (int i = 1; i < k; i++) count[i] += count[i - 1];  // ② 位置

    Pair[] output = new Pair[arr.length];
    for (int i = arr.length - 1; i >= 0; i--) { // ③ ⚠️ 倒序 → 稳定
        Pair p = arr[i];
        output[--count[p.key]] = p;             // 对象整体搬移
    }
    System.arraycopy(output, 0, arr, 0, arr.length);
}
// ⚠️ 稳定性语义：key 相同的对象保持原相对顺序
//   应用：按分数排序学生（同分保留原顺序）
```

### 3.2 多关键字排序（二次计数）

```
先按次关键字稳定计数排序 → 再按主关键字稳定计数排序
结果：主关键字有序，相同主关键字内按次关键字有序

⚠️ 例子：按（年级, 成绩）排序
  第一轮：按成绩稳定排
  第二轮：按年级稳定排
  → 同年级内成绩有序 ✓（数据库 ORDER BY 同原理）
```

## 4. 值域工程：负数与离散化

### 4.1 负数偏移

```java
/** 负数处理：整体偏移（00 模板的基础工程化） */
void countingSortSigned(int[] nums) {
    int min = Integer.MAX_VALUE, max = Integer.MIN_VALUE;
    for (int x : nums) { min = Math.min(min, x); max = Math.max(max, x); }

    int[] count = new int[max - min + 1];      // ⚠️ 值域含偏移
    for (int x : nums) count[x - min]++;

    int idx = 0;
    for (int i = 0; i < count.length; i++)
        while (count[i]-- > 0) nums[idx++] = i + min;   // 还原偏移
}
// 例 [-3, 5, -1] → 偏移 [0, 8, 2] → 排序 → 还原 [-3, -1, 5] ✓
// ⚠️ 溢出风险：min 极负时 max - min 可能溢出 int → 用 long 判值域
```

### 4.2 稀疏值域：离散化（压缩）

```
问题：值域 10⁹ 但只有 10⁵ 个不同值 → 计数数组爆炸
离散化：把不同值映射到 0..m-1（m = 不同值个数）
  ① 收集所有不同值 → 排序
  ② 二分映射：值 → 排序后的下标
  ③ 对映射后的下标计数排序

⚠️ 离散化本质："压缩值域"——保持值的相对序
  应用：树状数组/线段树的值域索引、TopK 统计
```

```java
/** 离散化：值 → 排名（0 基） */
Map<Integer, Integer> discretize(int[] nums) {
    int[] sorted = nums.clone();
    Arrays.sort(sorted);                        // ① 排序
    Map<Integer, Integer> rank = new HashMap<>();
    int r = 0;
    for (int x : sorted)                        // ② 去重编号
        if (!rank.containsKey(x)) rank.put(x, r++);
    return rank;                                // ③ 值 → 0..m-1
}
// 例 [1000, 5, 999999999] → {5:0, 1000:1, 999999999:2}
//   值域从 10⁹ 压缩到 3 ✓
// ⚠️ 复杂度：O(n log n)（排序主导），换来 O(m) 计数数组
```

### 4.3 值域分析三步

```
① 计算实际值域（min/max）
② 与 n 比较（k ≤ 10n 才有竞争力）
③ 稀疏 → 离散化；连续大 → 换基数/快排

⚠️ 面试表达：
"值域压缩（离散化）是'伪计数排序'——
 保持相对序、压缩索引空间；
 真正的计数排序要求 k 与 n 同量级。"
```

## 5. 计数 vs 基数 vs 桶 vs 快排

### 5.1 精确对比表

| 排序 | 时间 | 空间 | 稳定 | 键要求 | 适用 |
|------|:---:|:---:|:---:|------|------|
| 计数 | O(n+k) | O(k) | ✅ | 值域小 | 小值域批量 |
| 基数 | O(d·(n+r)) | O(n+r) | ✅ | 可分位 | 定长整数 |
| 桶 | O(n) 期望 | O(n) | 视桶内 | 均匀分布 | 均匀数据 |
| 快排 | O(n log n) | O(log n) | ❌ | 无 | 通用默认 |

```
⚠️ 关系定位：
  计数排序 = 基数排序的"单轮"
  桶排序 = 计数排序的"分块版"（桶内再排）
  快排 = 无法利用值域信息的通用兜底

面试表达：
"四者选型：值域小 → 计数；可分位 → 基数；
 均匀分布 → 桶；否则快排。计数是'最简线性排序'，
 其他线性排序都是它的扩展。"
```

### 5.2 常数与缓存的实际对比

```
n = 10⁶，k = 10⁶：
  计数：统计 10⁶ 次读写 + 展开 10⁶ → ~3×10⁶ 操作，顺序访问
  快排：~2×10⁷ 比较 + 交换，随机访问
  → 计数约快 5-10 倍（数据量越大越明显）

n = 10⁴，k = 10⁶：
  计数：统计 10⁴ + 展开 10⁶（值域主导！）→ 10⁶ 操作
  快排：~2×10⁵ → 快排赢
  → 值域主导时计数反而更慢（O(k) 的 k 惩罚）
```

## 6. 工程应用：直方图与数据库

### 6.1 真实场景

| 场景 | 计数排序的角色 |
|------|---------------|
| 成绩/年龄/状态码排序 | 值域小（0-100/0-150/几十种） |
| 像素直方图（图像处理） | 灰度 0-255 统计 |
| 数据库直方图 | 列值分布统计（查询优化器） |
| 基数排序的底层 | 每轮就是一次计数排序 |
| 流式频次 TopK | 频次桶（计数 + 桶） |

```
⚠️ 工程启示：
  计数排序极少"独立出场"，更多是"内嵌组件"：
  基数排序的每轮、频次桶的构建、直方图统计
  ——理解计数 = 理解这些结构的基础
```

### 6.2 与频次桶的关系

```
计数排序 = 频次 + 前缀和 + 展开
频次桶 = 频次 + 桶组织（不排序，按频次取）

⚠️ 区别：
  计数排序：输出"有序序列"
  频次桶：输出"按频次组织的结构"（用于 TopK/频率重排）

同一份频次数据，两种消费方式：
  展开 → 排序结果（912 计数版）
  桶化 → 频次排序（347/451，见计数专题）
```

## 7. 面试要点与追问

### 7.1 面试话术模板

```
"计数排序 O(n+k)：值域 k 可控时线性。
 稳定版：频次 + 前缀和（位置区间）+ 倒序遍历放置。
 适用边界：k 与 n 同量级（k ≤ 10n）才值得用；
 值域大用基数/快排，稀疏值域先离散化。
 工程上是基数排序的轮内组件 + 频次桶的基础。"
```

### 7.2 高频追问 TOP 8

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | 什么时候用计数排序？ | k 与 n 同量级（≤ 10n） |
| 2 | 稳定版关键？ | 前缀和定位 + 倒序放置 |
| 3 | 负数？ | 偏移（x - min） |
| 4 | 值域巨大？ | 基数/快排；稀疏先离散化 |
| 5 | 与基数关系？ | 基数的每一轮就是计数排序 |
| 6 | 与频次桶？ | 同一频次：展开=排序，桶化=TopK |
| 7 | 对象排序？ | 必须稳定版（整体搬移对象） |
| 8 | 多关键字？ | 两次稳定排序（先次后主） |

### 7.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| 正序放置 | 不稳定 | 倒序遍历 |
| 忘记偏移 | 负数越界 | x - min |
| 值域溢出（max-min） | 数组负长度 | long 检查 |
| 稀疏值域硬计数 | OOM | 离散化 |
| 展开时还原偏移错 | 值错误 | i + min |

---

> 🎯 **核心要点**：计数排序 = **值域索引**（O(n+k)）+ **前缀和**（位置语义）+ **倒序放置**（稳定性）。适用边界一句话：**k 与 n 同量级**。它是基数排序的轮内组件、频次桶的基础、直方图的本质——"线性排序家族的地基"。
