## 1. 退化场景分析：为什么有序数据会 O(n²)

### 1.1 退化机制

```text
固定基准（取首/尾元素）+ 有序/逆序输入:
  第 1 趟划分 → pivot 在一端 → 一侧空、一侧 n−1
  第 2 趟 → 又 n−2 ……
  递归树退化为"斜树"（每层只固化 1 个元素）

T(n) = T(n−1) + O(n) = ΣO(k) = O(n²)
  等价于: 每次划分只把数组"切开 1 个"——
  退化的快排 ≈ 每趟扫描全数组的选择排序

⚠️ 经典攻击输入:
  有序数组 [1,2,3,…,n] + 取末尾基准 → 稳定退化
  逆序数组 + 取首元素基准 → 同样退化
  （拒绝服务攻击常利用这点打排序接口——见 3 节防御）
```

### 1.2 退化检测的量化

```text
划分平衡度 = 两侧大小的比值:
  平衡: 每侧 ≥ n/3 → 层数 ≤ log_{3/2}n ≈ 1.7·log₂n → O(n log n)
  极端: 每侧 ≤ 1 → 层数 n → O(n²)

结论: 只要划分"不太偏"，快排就是 O(n log n)——
  随机数据下退化的概率指数级趋零
  → 防御重点不是"消除退化"，而是"让退化不可被构造"
```

> 🎯 **核心认知**："快排的最坏 O(n²) 不是数学命运，而是**输入可构造性**问题——固定基准时，攻击者或巧合数据就能触发；随机化基准后，任何输入的最坏期望都回到 O(n log n)。"

## 2. 基准选择三策略：固定/随机/三数取中

### 2.1 策略对比

| 策略 | 实现 | 退化风险 | 代价 |
|------|------|:---:|------|
| 固定（首/尾/中） | 零成本 | 高（可被构造） | 无 |
| 随机 | `random(lo, hi)` 交换到末尾 | 趋零（不可构造） | 随机数开销 |
| 三数取中 | 首/中/尾取中值 | 低（防有序，可被构造） | 3 次比较 |

### 2.2 随机基准（推荐首选）

```java
/** 随机基准：先随机选一个与末尾交换，再走 Lomuto */
private int partitionRandom(int[] arr, int lo, int hi) {
    int r = lo + new Random().nextInt(hi - lo + 1);   // ① 随机下标
    int tmp = arr[r]; arr[r] = arr[hi]; arr[hi] = tmp; // ② 换到末尾
    return partition(arr, lo, hi);                    // ③ 标准 Lomuto
}
// ⚠️ 效果: 任何输入都"平均"——最坏概率指数级趋零
//   代价: 每次划分一次随机数（可忽略）
```

### 2.3 三数取中（防"有序输入"特化攻击）

```java
/** 三数取中：首/中/尾取中值作基准 */
private int medianOfThree(int[] arr, int lo, int hi) {
    int mid = lo + (hi - lo) / 2;
    // 排序三个位置，中值放 hi（pivot 位置）
    if (arr[lo] > arr[mid]) swap(arr, lo, mid);
    if (arr[lo] > arr[hi]) swap(arr, lo, hi);
    if (arr[mid] > arr[hi]) swap(arr, mid, hi);
    swap(arr, mid, hi - 1);                            // 中值放 hi−1（典型实现）
    return hi - 1;
}
// ⚠️ 效果: 有序输入直接取到中值 → 划分完美
//   局限: 对手可构造"首中尾三处都大于中值"的输入 → 仍退化
```

> 💡 选型建议：**面试讲"随机基准"（简单 + 不可构造）**；**工程讲"三数取中 + introsort"**（无随机数依赖、可结合深度检测）。两者可以叠加。

## 3. introsort：递归深度检测兜底

### 3.1 原理

```text
introsort（introspective sort，Musser 1997）:
  跟踪递归深度，超过阈值（≈ 2·log₂n）→ 划分疑似退化
  → 该区间改用堆排序（严格 O(n log n)）→ 整体最坏 O(n log n)

组合策略:
  快排（平均最快） + 深度检测（检测退化） + 堆排（兜底）
  = 平均 O(n log n) 常数小 + 最坏 O(n log n) 有界
```

### 3.2 核心实现（结合三数取中）

```java
/**
 * introsort 核心：深度超限转堆排（最坏有界）
 * maxDepth ≈ 2·log₂n（C++ std::sort / JDK 的实现思想）
 */
void introsort(int[] arr, int lo, int hi, int depth) {
    if (hi - lo <= 16) { insertionSort(arr, lo, hi); return; }  // 小区间
    if (depth == 0) { heapSort(arr, lo, hi); return; }          // 深度超限 → 堆排
    int p = partitionMedianOfThree(arr, lo, hi);                // 三数取中划分
    introsort(arr, lo, p - 1, depth - 1);
    introsort(arr, p + 1, hi, depth - 1);
}
// 调用: introsort(arr, 0, n-1, (int)(2 * Math.log(n) / Math.log(2)))
```

> ⚠️ **面试谈资**："C++ `std::sort` 与 JDK `DualPivotQuicksort` 都内置 introsort 思想——JDK 的 `MAX_RECURSION_DEPTH = 64`，递归超深即转堆排，从机制上消灭最坏 O(n²)。"

## 4. 三路划分：重复元素的荷兰国旗

### 4.1 问题：大量重复元素时经典划分失效

```text
数据全是重复值（如 [5,5,5,…,5]）:
  Lomuto: 每次划分 5 全在右区 → 一侧 n−1 → 退化 O(n²)！
  （划分"平衡"是陷阱——pivot 重复时左区可能空）

三路划分（Dutch National Flag，Dijkstra）:
  一趟划分成三区: <p | =p | >p
  → 中间区（=p）直接跳过，不再递归
  → 重复元素越多收益越大（全重复 → O(n)）
```

### 4.2 三路快速排序

```java
/**
 * 三路快速排序（荷兰国旗划分）
 * 分三区: <pivot | =pivot | >pivot，中间区不递归
 * 全重复数据: O(n)；随机数据: 略慢于两路（多一路判断）
 */
void quickSort3Way(int[] arr, int lo, int hi) {
    if (hi <= lo) return;
    int pivot = arr[lo];
    int lt = lo, i = lo + 1, gt = hi;    // lt: <区边界, gt: >区边界
    while (i <= gt) {
        if (arr[i] < pivot) {
            swap(arr, lt++, i++);        // 换到 < 区
        } else if (arr[i] > pivot) {
            swap(arr, i, gt--);          // 换到 > 区（i 不动，再查一次）
        } else {
            i++;                         // = pivot → 留在中间
        }
    }
    quickSort3Way(arr, lo, lt - 1);      // 递归 < 区
    quickSort3Way(arr, gt + 1, hi);      // 递归 > 区
}
// 75 颜色分类就是三路划分的裸题（03 文件实战）
```

> 🎯 **选型判断**："**重复多 → 三路（O(n) 收益）；重复少 → 两路（常数小）**。JDK 双轴快排正是三路的工程化——两个基准把数组切成三区，天然处理重复元素。"

## 5. 小区间插入与尾递归优化

### 5.1 小区间切插入排序

```text
为什么: 递归到小片段时，函数调用开销 > 插入排序的 O(k²)
  （k < 阈值时，插入的常数优势压制阶数）

阈值: 7~16（教材）→ 47（JDK 快排）→ 51（JDK-8266431 新值）
效果: 减少约 30-40% 的递归调用（工程实测显著）

代码: if (hi - lo <= THRESHOLD) { insertionSort(arr, lo, hi); return; }
```

### 5.2 尾递归优化（栈空间 O(n) → O(log n)）

```java
/** 尾递归优化：只递归小区间，大区间迭代处理 */
void quickSortTail(int[] arr, int lo, int hi) {
    while (lo < hi) {
        int p = partition(arr, lo, hi);
        if (p - lo < hi - p) {           // ① 小区间递归
            quickSortTail(arr, lo, p - 1);
            lo = p + 1;                  // ② 大区间迭代（栈帧复用）
        } else {
            quickSortTail(arr, p + 1, hi);
            hi = p - 1;
        }
    }
}
// ⚠️ 效果: 递归深度始终 ≤ log₂n（栈空间最坏 O(log n)）
```

> 💡 面试表达："工程快排是组合拳——**小片段插入（阈值 47）+ 深度检测堆排（64）+ 双轴/三路划分（重复元素）+ 尾递归（栈 O(log n)）**。能背出这四个阈值与机制，JDK 源码级的深度就有了。"

## 6. JDK 双轴快排深潜：源码级解剖

### 6.1 双轴原理（JDK 7+，Vladimir Yaroslavskiy）

```text
采样: 从数组取 5 个元素 e1..e5，排序后:
  e2 = pivot1（左基准），e4 = pivot2（右基准）
  → 一次划分切三区: <p1 | p1~p2 | >p2
  → 两个基准同时就位，递归三区（中间区小）

优势 vs 单轴:
  ① 每次递归固化 2 个基准 → 递归深度减约 1 层
  ② 三区划分天然处理重复元素（p1~p2 区间跳过）
  ③ 采样 5 元素 ≈ 三数取中的增强版（抗退化）

回退策略:
  重复元素过多 → 回退单轴快排（双轴在重复数据上交换变多）
  递归深度 > 64 → 堆排（introsort 兜底）
```

### 6.2 JDK 的混合决策树（Arrays.sort 基本类型）

```text
n < 47:           插入排序（混合插入排序）
n ≥ 286 且检测到大量有序段: 归并排序（近有序数据归并更快）
递归深度 > 64:    堆排序
默认:             双轴快排（随机分布数据）/ 单轴（重复多）
byte/char/short:  计数排序（值域 ≤ 2^16，线性更快）
并行版本:         Fork-Join 分块排序后合并

⚠️ JDK 8 演化: 5 元素采样、三路划分、深度回退、run 检测
   JDK-8266431（2026）: 阈值调整为 <51 混合插入、近有序 >512 归并
```

> 🎯 **一句话总结 JDK 快排**："JDK 的 Arrays.sort(基本类型) 不是纯双轴快排，而是一棵**按数据特征切换算法的决策树**——小数组插入、近有序归并、深度超限堆排、重复多单轴、值域小计数、默认双轴。这就是'工程排序 = 组合拳'的最好教材。"

## 7. 2025-2026 工程前沿

### 7.1 JDK-8266431（2026.08）：Dual-Pivot Quicksort 重大改进

```text
Vladimir Yaroslavskiy 本人提交的改进 PR（v10）:
  ① 并行排序引入基数排序 —— 线性复杂度（取代 n·ln n 级别），快数倍
  ② 混合插入排序改进（阈值 51）
  ③ 近有序大数组（>512）改用归并排序
  ④ 优化 pivot 划分逻辑（双轴/单轴按数据分布选择）
  ⑤ 缓冲分配失败 → 原地排序兜底（不再抛 OutOfMemoryError）

实测提速（报告数据）:
  顺序: byte 最高 50%、char 4-7×、short 2-6×、int/long/float/double 1.2-5×
  并行: int/long 1.2-9×、float/double 1.2-4×
```

### 7.2 AVX512 SIMD 排序（JDK-8309130，已并入 8266431）

```text
x86_64 AVX512 指令集内建排序例程:
  单轴快排 + SIMD 位排（bitonic sort）处理 ≤128 元素的分区
  实测: int/float 最高 ~13×、long/double ~8×（大数组）
  意义: 排序进入"向量化时代"——SIMD 排序不再是论文而是 JDK 标配
```

### 7.3 IPS4o 与形式化验证

```text
IPS4o（In-Place Parallel Super Scalar Sample Sort）:
  现代最先进的原地并行排序: 采样分桶 + 并行划分 + 向量化
  已被 KeY 定理证明器形式化验证（直接对未修改的高效实现验证）
  与 JDK 双轴快排同样被 KeY 验证过 → "工业排序的正确性可证明"

⚠️ 谈资: "快排家族 60 多年后仍在演进——
  2026 年 JDK 引入并行基数排序与 AVX512 SIMD，
  学术界用定理证明器验证工业实现。排序没有终点。"
```

## 8. 面试要点与追问

### 8.1 话术模板

```
"快排 = 选基准 + 划分 + 递归。平均 O(n log n) 常数最小，
最坏 O(n²) 来自固定基准 + 有序输入——随机基准/三数取中防退化，
introsort 深度检测转堆排彻底兜底；三路划分治重复元素，
小区间切插入减递归。JDK 双轴快排采样 5 元素切三区，
配合 47/286/64 阈值决策树——工程快排是组合拳。"
```

### 8.2 高频追问 TOP 10

| # | 追问 | 标准回答 |
|:---:|------|---------|
| 1 | 什么时候退化 O(n²)？ | 固定基准 + 有序/逆序输入，每次划分只切 1 个 |
| 2 | 怎么防退化？ | 随机基准（不可构造）/ 三数取中（防有序）+ introsort 兜底 |
| 3 | Lomuto vs Hoare？ | Lomuto 简单但交换多；Hoare 双向常数小、返回 j 易错 |
| 4 | 重复元素多怎么办？ | 三路划分（荷兰国旗）→ 中间区跳过 → 全重复 O(n) |
| 5 | 快排空间复杂度？ | 平均 O(log n) 递归栈；最坏 O(n)；尾递归优化保 O(log n) |
| 6 | 为什么 JDK 用双轴？ | 双基准一次固化 2 个 + 三区天然处理重复 |
| 7 | 三个阈值？ | <47 插入、深度 >64 堆排、>286 近有序转归并（2026: 51/512） |
| 8 | quickselect 复杂度？ | 每次只递归一侧 → 平均 O(n)（几何级数） |
| 9 | 为什么对象排序不用快排？ | 快排不稳定；对象排序要求稳定 → TimSort |
| 10 | 2025-2026 进展？ | JDK-8266431 并行基数排序、AVX512 SIMD ~13×、IPS4o 形式化验证 |

### 8.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| 固定基准处理有序数据 | O(n²) 退化 | 随机/三数取中 |
| Hoare 返回 i | 区间重叠死循环 | 返回 j |
| 小区间无插入兜底 | 递归开销大 | 阈值 16~47 切插入 |
| 三路划分 i 不后移 | 死循环（>pivot 交换后 i 停） | `arr[i] > pivot` 分支 i 不动 |
| 深度检测缺失 | 恶意输入打挂排序 | introsort 兜底 |

> 🎯 **核心要点**：进阶专题验收 = **一个退化机制（固定基准 + 有序输入）+ 三层防御（随机/三数取中 → introsort → 三路划分）+ 一套阈值（47/64/286）+ 一段前沿（JDK-8266431/AVX512/IPS4o）**。快排从 1962 年教科书算法到 2026 年工业标配的演化主线是"**不断消除'可构造的退化'"**——这条主线能讲清楚，就是源码级的深度。
