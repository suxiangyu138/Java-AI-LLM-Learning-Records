## 1. 划分模型：选基准、分两边、各自递归

### 1.1 算法就是"选队长分两队"

快排（1962 年 C. A. R. Hoare 提出）的直觉：**选一个基准（pivot），把比它小的放左边、比它大的放右边——基准永久就位，然后两边各自重复**：

```text
① 选基准: 通常取末尾元素（Lomuto）或首元素（Hoare）
② 划分: 一趟扫描把数组分成 左区(<p) | pivot | 右区(≥p)
③ 递归: 对左右两区分别快排（pivot 已就位，不再参与）

关键性质: 划分完成后 pivot 的位置就是最终位置——
  它左边都比它小、右边都比它大，无论两侧内部怎么排
  → 每次递归都"固化"一个元素（好的划分 ≈ 一半元素）
```

### 1.2 与归并排序的本质对比

```text
归并排序: 先递归（拆到单元素）→ 再合并（后处理）
  → 拆分不看数值，合并时排序 → 无退化但需要辅助数组

快速排序: 先划分（定位 pivot）→ 再递归（后处理）
  → 划分时排序，递归时"不用管" → 原地但划分质量决定复杂度

一句话: "归并是'先拆后合'，快排是'先定后分'"——
  划分 = 快排的 partition 做的排序工作；
  递归 = 两侧各自再来一遍
```

> 🎯 **核心动作三连**：**选基准（pivot）→ 划分（partition 使左 < p ≤ 右）→ 递归（两侧各自快排）**。快排的全部性能命门在划分——**划分越平衡，递归树越矮，越接近 O(n log n)**。

## 2. 基本实现：Lomuto 版（2 分钟默写）

### 2.1 完整代码（面试标准答案）

```java
/**
 * 快速排序（Lomuto 划分版）
 * 平均 O(n log n)，最坏 O(n²)，空间 O(log n) 栈，不稳定
 */
public void quickSort(int[] arr) {
    sort(arr, 0, arr.length - 1);
}

private void sort(int[] arr, int lo, int hi) {
    if (lo >= hi) return;                    // ① 基线：单元素/空区间
    int p = partition(arr, lo, hi);          // ② 划分：pivot 就位
    sort(arr, lo, p - 1);                    // ③ 递归左区（<pivot）
    sort(arr, p + 1, hi);                    // ④ 递归右区（≥pivot）
}

/** Lomuto 划分：单向扫描，pivot 取末尾 */
private int partition(int[] arr, int lo, int hi) {
    int pivot = arr[hi];                     // ① 基准 = 末尾元素
    int i = lo;                              // ② i = 已确定 < pivot 的边界
    for (int j = lo; j < hi; j++) {
        if (arr[j] < pivot) {                // ③ 小于基准 → 换到左区
            int tmp = arr[i]; arr[i] = arr[j]; arr[j] = tmp;
            i++;
        }
    }
    // ④ pivot 归位（放到 i 处）
    int tmp = arr[i]; arr[i] = arr[hi]; arr[hi] = tmp;
    return i;                                // 返回 pivot 最终位置
}
```

### 2.2 三个关键细节

```text
① i 的语义: 左区（< pivot）的右边界——
   扫描中所有 < pivot 的元素都被换到 [lo, i-1]
② 循环范围 j ∈ [lo, hi-1]: 不含 pivot 本身（最后再归位）
③ 稳定性: 用 < 而非 <= → 相等元素留在右区 → 全局不稳定
   （交换跨越了相等元素，见第 6 节反例）
```

> 💡 **记忆技巧**：Lomuto 划分 = "**双指针同向扫描：j 找小的、i 圈地**"——j 扫到小于 pivot 的就与 i 处交换、i 前进。**与 283 移动零的双指针同构**（快慢指针交换），会写移动零就会写 partition。

## 3. 进阶实现：Hoare 版（双向扫描）

### 3.1 完整代码（常数更小，工程变体基础）

```java
/**
 * 快速排序（Hoare 划分版）
 * 双向相向扫描，交换次数更少；注意返回 j 而非 i
 */
private int hoarePartition(int[] arr, int lo, int hi) {
    int pivot = arr[lo];                     // ① 基准 = 首元素
    int i = lo - 1, j = hi + 1;
    while (true) {
        do { i++; } while (arr[i] < pivot);  // ② 左指针找 ≥ pivot
        do { j--; } while (arr[j] > pivot);  // ③ 右指针找 ≤ pivot
        if (i >= j) return j;                // ④ 相遇 → 划分完成
        int tmp = arr[i]; arr[i] = arr[j]; arr[j] = tmp;
    }
}
// ⚠️ 递归调用: sort(arr, lo, j) 与 sort(arr, j+1, hi)（注意边界！）
```

### 3.2 Lomuto vs Hoare 对比

| 维度 | Lomuto | Hoare |
|------|:---:|:---:|
| 扫描方式 | 单向（i, j 同向） | 双向（i, j 相向） |
| pivot 位置 | 末尾（最后归位） | 首元素（不显式归位） |
| 交换次数 | 多（约 3 倍） | 少（交换即消除逆序对） |
| 代码复杂度 | 简单（面试首选） | 边界易错（返回 j） |
| 递归边界 | (lo, p-1) (p+1, hi) | (lo, j) (j+1, hi) |
| 工程地位 | 教学/面试 | 工程变体（JDK 划分的思想基础） |

> ⚠️ **面试提示**：手写先用 Lomuto（数组边界直观），被追问"怎么优化"再讲 Hoare 与第 02 文件的工程优化——**主动升级 = 加分**。Hoare 的 `do-while` 双循环与返回 j 是必背易错点。

## 4. 逐步推演：n=8 全流程

**数据**：[9, 3, 7, 1, 8, 2, 6, 5]（升序排序，Lomuto）

| 递归层 | 区间 | pivot | 划分结果（pivot 位置） |
|:---:|:---:|:---:|------|
| 1 | [0..7] | 5 | [3,1,2,**5**,8,7,6,9]（位置 3） |
| 2 | [0..2] | 2 | [1,**2**,3]（位置 1） |
| 2 | [4..7] | 9 | [8,7,6,**9**]（位置 7） |
| 3 | [4..6] | 6 | [**6**,7,8]（位置 4） |
| 3 | [5..6] | 8 | [7,**8**]（位置 6） |

**最终结果**：[1, 2, 3, 5, 6, 7, 8, 9] ✓

**第 1 层划分推演（pivot=5）**：

```text
i=0, j 从 0 到 6:
  j=0: 9>5 跳过； j=1: 3<5 → 换 arr[0]↔arr[1] → [3,9,7,1,8,2,6,5], i=1
  j=2: 7 跳过；  j=3: 1<5 → 换 arr[1]↔arr[3] → [3,1,7,9,8,2,6,5], i=2
  j=4: 8 跳过；  j=5: 2<5 → 换 arr[2]↔arr[5] → [3,1,2,9,8,7,6,5], i=3
  j=6: 6 跳过
最后: pivot 归位 → 换 arr[3]↔arr[7] → [3,1,2,5,8,7,6,9], 返回 3
左区 [3,1,2] 全 < 5，右区 [8,7,6,9] 全 ≥ 5 ✓
```

> 🎯 **从推演看性能**：第 1 层划分把 5 个比较 + 3 次交换换成"**5 永久就位 + 两侧缩小**"。划分平衡时每层 O(n)、层数 log n → O(n log n)；**划分偏斜时层数变多，最坏每层只固化 1 个元素 → O(n²)**——这个直觉比背公式重要。

## 5. 复杂度推导：最好/平均/最坏

### 5.1 递推方程与三情形

| 情形 | 划分质量 | 递推方程 | 复杂度 |
|------|:---:|------|:---:|
| 最好 | 每次对半 | T(n) = 2T(n/2) + O(n) | **O(n log n)** |
| 平均 | 随机分布 | T(n) = T(n/3) + T(2n/3) + O(n)（期望） | **O(n log n)** |
| 最坏 | 每次 1/n−1 | T(n) = T(n−1) + O(n) | **O(n²)** |

```text
最坏推导（有序数据 + 固定基准）:
  第 1 趟划分后: pivot 在一端 → 一侧空、一侧 n−1
  T(n) = T(n−1) + O(n) → ΣO(k) = O(n²)（等差数列求和）

平均推导（常数分析）:
  每个元素平均参与约 1.39 次比较/层 × log n 层
  → 平均比较次数 ≈ 1.39n·log n（比归并的 n·log n 多约 39%，
    但原地无拷贝 → 实际更快——常数优势在"少搬移"而非"少比较"）

空间（递归栈）:
  平均 O(log n)（平衡树高）；最坏 O(n)（退化为线性递归）
```

### 5.2 为什么"平均快但最坏慢"

```text
① 平均快: 随机数据下划分"大致平衡"的概率极高——
   即使每次 1/3-2/3 的偏斜，层数也只是 log_{3/2}n ≈ 1.7log n
   → 常数稍大但仍 O(n log n)
② 最坏慢: 有序/逆序数据 + 固定基准 → 每次都取到极值
   → 退化 O(n²)（第 02 文件的随机/三数取中就是治这个）
③ 结论: "快排的最坏 O(n²) 是'可选'的——
   随机化基准后期望最坏仍是 O(n log n)；introsort 彻底兜底"
```

> 🎯 **面试必答句**："快排最好与平均 O(n log n)（平均常数约 1.39n log n 次比较，但原地无拷贝所以实际最快）、最坏 O(n²)（固定基准 + 有序数据）；空间 O(log n) 递归栈；不稳定。**平均性能是排序家族第一，最坏退化可用随机基准与 introsort 防御**——这就是 JDK 为什么选它。"

## 6. 稳定性分析：为什么不稳定（含反例）

### 6.1 反例演示（Lomuto，pivot=末尾）

**数据**：[5a, 3, 5b, 1]（5a 在 5b 前，相等）

| 步骤 | 操作 | 数组状态 |
|:---:|------|------|
| 初始 | — | [5a, 3, 5b, 1] |
| 扫描 | 3 < 1? 否；5b < 1? 否；5a < 1? 否（无人进左区） | [5a, 3, 5b, 1] |
| pivot 归位 | 换 arr[0] ↔ arr[3] | [**1**, 3, **5b**, 5a] |

**结果**：5b 跳到了 5a 前面——**相等元素相对顺序被逆转**。

```text
逆转机制: pivot 归位时把 arr[hi] 与 arr[lo] 交换，
          5b 从位置 2 "跨过" 5a（位置 0）落到前面
          → 跨距离交换天然破坏相等元素的相对顺序
          → 任何"交换式划分"都无法稳定（Hoare 同样如此）
```

> ⚠️ **稳定性考点**：稳定排序口诀"冒插归基"里没有快排——**快排的不稳定是"跨距离交换"的结构性缺陷**，换基准策略也改变不了。面试被问"为什么快排不稳定"——答"pivot 归位与交换跨越了相等元素"，比背结论高级。

## 7. 与归并排序对比与手写易错点

### 7.1 分治双雄对比

| 维度 | 快速排序 | 归并排序 |
|------|:---:|:---:|
| 分治顺序 | 先划分（定位）后递归 | 先递归后合并 |
| 平均复杂度 | O(n log n) 常数最小 | O(n log n) 常数中 |
| 最坏复杂度 | O(n²)（可防） | **O(n log n)（无退化）** |
| 空间 | O(log n) 栈 | O(n) 辅助数组 |
| 稳定性 | ✘ | ✔ |
| 缓存友好 | ✔（原地） | 中（顺序 + 拷贝） |
| 链表 | ✘（需随机访问） | ✔（天然适配） |
| 应用 | 通用数组（JDK 基本类型） | 稳定需求/链表/外部排序 |

> 💡 面试表达："**快排赢在平均与常数，归并赢在最坏与稳定**——JDK 的答案是基本类型用双轴快排（不需要稳定）、对象用 TimSort（必须稳定），两条线各取所长。"

### 7.2 手写易错点速查

| # | 易错点 | 正确写法 | 后果 |
|:---:|------|------|------|
| 1 | 递归基线漏 `lo >= hi` | `if (lo >= hi) return;` | 无限递归/栈溢出 |
| 2 | Lomuto 循环含 pivot 位置 | `j < hi`（不含末尾） | pivot 被提前交换 |
| 3 | 忘记 pivot 归位 | 最后 swap(arr[i], arr[hi]) | pivot 未就位 |
| 4 | Hoare 返回 i | 返回 `j` | 递归区间重叠/死循环 |
| 5 | Hoare 递归边界错 | `(lo, j)` 与 `(j+1, hi)` | 区间重叠 |
| 6 | 用 `<=` 比较 | `arr[j] < pivot` | 相等元素全进左区（性能差） |
| 7 | mid 计算 `(lo+hi)/2` | 大数组无 mid（partition 不需要） | —（仅三数取中用 `lo+(hi-lo)/2`） |

> 🎯 **核心要点**：快速排序通关四件事——**① 2 分钟默写 Lomuto 版**（选末尾基准 → 双指针扫描 → pivot 归位）；**② 三情形复杂度与退化条件脱口而出**（最好/平均 O(n log n)、最坏 O(n²) 需固定基准 + 有序数据）；**③ 稳定性反例张嘴就来**（pivot 归位跨距离交换）；**④ 与归并对比讲清分工**（快排平均与常数、归并最坏与稳定）。**它是"面试手撕概率最高"的排序，也是"JDK 工程选型的第一答案"**——这两点就足以让它成为排序专题的必修主课。
