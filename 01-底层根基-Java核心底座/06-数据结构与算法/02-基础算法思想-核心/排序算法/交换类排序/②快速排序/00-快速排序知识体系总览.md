## 1. 知识体系导图

```text
快速排序（Quick Sort，1962 Hoare）
│
├── 核心本质 ──────────────────────────────────────────────
│   ├── = 选基准（pivot）→ 划分（partition）→ 递归两侧
│   ├── 划分后: 左 < pivot ≤ 右 → pivot 永久就位
│   ├── Lomuto（简单）/ Hoare（更快）两种划分
│   └── 与归并对比: 先"定位"后递归（归并先递归后合并）
│
├── 关键特性 ──────────────────────────────────────────────
│   ├── 时间复杂度：最好 O(n log n) / 平均 ≈1.39n log n / 最坏 O(n²)
│   ├── 空间复杂度：平均 O(log n) 递归栈 / 最坏 O(n)
│   ├── 稳定性：✘ 不稳定（交换跨越相等元素）
│   └── 常数因子：最小（原地 + 缓存友好）→ 工程默认
│
├── 退化与三大优化 ────────────────────────────────────────
│   ├── 退化场景：有序数据 + 固定基准 → O(n²)
│   ├── 基准选择：随机 / 三数取中 → 退化概率归零
│   ├── introsort：递归深度检测 → 切堆排（最坏有界）
│   └── 三路划分：重复元素集中处理（荷兰国旗）
│
├── 工程优化 ──────────────────────────────────────────────
│   ├── 小区间切插入排序（阈值 47 左右，常数压制阶数）
│   ├── 尾递归优化（只递归小区间，栈 O(log n)）
│   └── JDK 双轴快排（采样 5 元素双基准、三区划分）
│
├── 工程前沿（2025-2026）──────────────────────────────────
│   ├── JDK-8266431（2026）：并行基数排序、深度>64 转堆排、计数排序分支
│   ├── AVX512 SIMD 排序（JDK-8309130）：分区 ≤128 位排，int 快 13×
│   └── IPS4o：原地并行采样排序（KeY 定理证明器验证）
│
└── 实战与面试 ────────────────────────────────────────────
    ├── 手写：Lomuto 版（2 分钟）+ Hoare 版（进阶）
    ├── 考题：215 第 K 大（quickselect）、75 颜色分类、912
    ├── 对比：快排 vs 归并 vs 堆排（常数/稳定/退化）
    └── 话术：平均最优 + 退化防护 + 工程混合策略
```

## 4. 核心概念速查

| 概念 | 一句话解释 | 说明 |
|------|-----------|------|
| **快速排序** | 选基准划分 + 递归两侧 | 1962 年 Hoare 提出 |
| **基准（pivot）** | 划分的参照元素 | 选择策略决定退化风险 |
| **划分（partition）** | 把数组分成 <p 与 ≥p 两区 | 划分后 pivot 永久就位 |
| **Lomuto 划分** | 单向扫描，pivot 取末尾 | 实现简单，面试首选 |
| **Hoare 划分** | 双向相向扫描 | 交换更少，常数更小 |
| **三数取中** | 首/中/尾取中值作基准 | 防御有序数据退化 |
| **introsort** | 递归深度超限转堆排 | 保证最坏 O(n log n) |
| **三路划分** | 分 <p / =p / >p 三区 | 重复元素多的场景 |
| **双轴快排** | 双基准分三区 | JDK 基本类型排序底层 |
| **quickselect** | 划分后只递归一侧 | 平均 O(n) 求第 K 大 |
| **退化** | 划分严重不平衡 → O(n²) | 有序 + 固定基准的经典陷阱 |

## 5. 复杂度与特性速查表

| 维度 | 最好 | 平均 | 最坏 | 说明 |
|------|:---:|:---:|:---:|------|
| 时间复杂度 | O(n log n) | ≈1.39n log n | O(n²) | 最坏 = 固定基准 + 有序数据 |
| 空间复杂度 | O(log n) | O(log n) | O(n) | 递归栈（尾递归可降） |
| 稳定性 | ✘ 不稳定 | — | — | 交换跨越相等元素 |
| 常数因子 | 最小 | 最小 | — | 原地 + 缓存友好 |

**快排 vs 归并 vs 堆排**：

| 维度 | 快排 | 归并 | 堆排 |
|------|:---:|:---:|:---:|
| 平均 | O(n log n) 常数最小 | O(n log n) 常数中 | O(n log n) 常数大 |
| 最坏 | O(n²)（可防：introsort） | **O(n log n)** | **O(n log n)** |
| 空间 | O(log n) 栈 | O(n) 辅助 | O(1) |
| 稳定 | ✘ | ✔ | ✘ |
| 缓存 | 好（原地） | 中（顺序但拷贝多） | 差（跳跃访问） |
| 适用 | 通用数组（工程默认） | 稳定/链表/外部排序 | 最坏有界 + 内存受限 |

> 🎯 **一句话选型**：**通用数组排序选快排**（平均最快、原地、缓存友好）；**要稳定/链表/外部数据选归并**；**要最坏有界且内存受限选堆排**。JDK 的答案：基本类型双轴快排（可切归并/堆排兜底）、对象 TimSort——工程选型的完整答案就在这。

## 6. 常见误区速查

| 误区 | 正解 |
|------|------|
| "快排最坏 O(n²) 所以不如归并" | ❌ 平均 O(n log n) 常数最小；随机基准/三数取中后退化概率趋零；introsort 彻底兜底 |
| "快排不稳定，所以工程不用" | ❌ 基本类型排序不需要稳定 → JDK 用双轴快排；对象排序才要稳定（TimSort） |
| "三数取中是唯一基准优化" | ❌ 还有随机基准、introsort 深度检测、双轴/多轴采样 |
| "快排空间 O(1)" | ❌ 递归栈平均 O(log n)、最坏 O(n)；尾递归优化可保证 O(log n) |
| "划分必须用 Lomuto" | ❌ Lomuto 简单但交换多；Hoare 双向扫描常数更小（工程用 Hoare 变体） |
| "快排对有序数组一定退化" | ❌ 只有固定基准（如取首元素）才退化；随机/三数取中后有序数组表现正常 |
| "quickselect 是 O(n log n)" | ❌ 每次只递归一侧 → 平均 O(n)（几何级数收敛） |
| "快排适合链表" | ❌ 链表无随机访问，划分低效——链表排序用归并 |
| "JDK 快排是纯双轴" | ❌ 是混合策略：小数组插入、近有序归并、深度超限堆排、双轴/单轴按数据选择 |
| "2026 年快排已无研究" | ❌ JDK-8266431 引入并行基数排序与 AVX512 SIMD 排序——工业优化仍在推进 |
