## 1. 优化全景：两大核心优化

冒泡排序的瓶颈：**每趟都从 0 扫描到 n−1−i，即使数据已经局部有序**。所有优化都围绕"少扫、少换"：

| 优化/变体 | 手段 | 收益 |
|------|------|------|
| 提前终止（swapped） | 无交换即停 | 有序输入 O(n) |
| 最后交换位置（lastSwap） | 有序尾部动态缩短 | 部分有序数据更快 |
| 鸡尾酒排序 | 左右交替扫描 | 常数因子更小（快 20-40%） |
| 梳排序 | 间隔 n/1.3 递减 | 平均接近 O(n log n) |
| 奇偶排序 | 奇偶位置交替比较 | 易并行（无数据依赖） |

> 🎯 **关键认知**："**比较 vs 交换是两个独立成本**"——提前终止砍比较次数，lastSwap 砍扫描区间，鸡尾酒砍"气泡漂移距离"，梳排序砍逆序对消除路径。**冒泡优化的主线是"让扫描区间收缩得比 i 更快"**。

## 2. 优化一：提前终止（swapped 标记）

### 2.1 原理与代码

某趟没有发生任何交换 → 相邻元素全部有序 → 全局有序 → 提前结束：

```java
public static void bubbleSortOptimized(int[] arr) {
    int n = arr.length;
    for (int i = 0; i < n - 1; i++) {
        boolean swapped = false;
        for (int j = 0; j < n - 1 - i; j++) {
            if (arr[j] > arr[j + 1]) {
                int tmp = arr[j]; arr[j] = arr[j + 1]; arr[j + 1] = tmp;
                swapped = true;
            }
        }
        if (!swapped) return;          // 无交换 ⇔ 已有序
    }
}
```

### 2.2 正确性论证（软考判断题考点）

```text
"一趟无交换 ⇔ 数组已有序"为什么成立:
  一趟扫描检查了所有相邻对 (j, j+1)
  全部无逆序 ⇔ 任意相邻对有序 ⇔ 全数组有序（传递性）
  → 提前终止不会漏排序 ✓

收益: 有序输入只扫 1 趟（n−1 次比较）→ 最好 O(n)
  逆序输入仍 n²/2 → 最坏不变
```

## 3. 优化二：记录最后交换位置（lastSwap）

### 3.1 原理与代码

```text
观察: 一趟中最后发生交换的位置 lastSwap 之后 → 已全部有序
下一趟只需扫描到 lastSwap 即可（末尾有序区动态缩短）

例: 第 1 趟最后交换在位置 4 → 下一趟扫描 [0..4] 而非 [0..n-2]
```

```java
public static void bubbleSortLastSwap(int[] arr) {
    int n = arr.length;
    int lastSwap = n - 1;                // 扫描上界（初始 n-1）
    while (lastSwap > 0) {
        int newLast = 0;                 // 本趟最后交换位置
        for (int j = 0; j < lastSwap; j++) {
            if (arr[j] > arr[j + 1]) {
                int tmp = arr[j]; arr[j] = arr[j + 1]; arr[j + 1] = tmp;
                newLast = j;             // 更新最后交换位置
            }
        }
        if (newLast == 0) return;        // 无交换 → 已有序（含提前终止）
        lastSwap = newLast;              // 下趟只扫到 newLast
    }
}
```

> 💡 **收益对比**：提前终止是"整趟跳过"，lastSwap 是"**部分扫描跳过**"——数据"前乱后有序"时（如大部分元素已就位），扫描区间逐趟快速收缩，实际时间接近 O(n)。两者可叠加（lastSwap 版天然包含提前终止）。

## 4. 变体一：鸡尾酒排序（双向冒泡）

### 4.1 原理

```text
问题: 基础冒泡只往右"冒"最大者——最小值若在最右端，
      要 n−1 趟才能"漂"到最左（每趟只左移 1 位）
鸡尾酒排序: 每轮从左到右冒最大、再从右到左冒最小
  → 两端同时收缩，气泡漂移距离减半
```

### 4.2 完整实现

```java
/**
 * 鸡尾酒排序（双向冒泡 / 搅拌排序）
 * 每轮: 正向冒最大到右端 + 反向冒最小到左端
 * 复杂度仍 O(n²)，但常数更小；稳定；O(1) 空间
 */
public static void cocktailSort(int[] arr) {
    int left = 0, right = arr.length - 1;
    boolean swapped = true;

    while (swapped) {
        swapped = false;
        // ① 正向: 最大者冒到右端
        for (int j = left; j < right; j++) {
            if (arr[j] > arr[j + 1]) {
                int tmp = arr[j]; arr[j] = arr[j + 1]; arr[j + 1] = tmp;
                swapped = true;
            }
        }
        right--;                              // 右端收缩
        if (!swapped) break;                  // 已有序
        swapped = false;
        // ② 反向: 最小者冒到左端
        for (int j = right; j > left; j--) {
            if (arr[j] < arr[j - 1]) {
                int tmp = arr[j]; arr[j] = arr[j - 1]; arr[j - 1] = tmp;
                swapped = true;
            }
        }
        left++;                               // 左端收缩
    }
}
```

### 4.3 实测收益（2025 年数据）

| 输入类型 | 相对基础冒泡 | 说明 |
|------|:---:|------|
| 随机数组 | 快 20-40% | 双向冒泡减少漂移 |
| 已排序数组 | 快 90%+ | 一趟双向扫描即确认 |
| 逆序数组 | 快 10-20% | 双向同时收尾 |
| 两端有序中间乱 | 最快 | 鸡尾酒的专属场景 |

## 5. 变体二：梳排序（间隔递减）

### 5.1 原理

```text
问题: 冒泡只比较相邻元素——小元素要从尾部漂到头部要 O(n) 趟
梳排序: 借鉴希尔排序的"间隔"思想——
  先以较大间隔 gap 比较交换（远距离元素快速就位），
  每轮 gap 缩小（÷1.3，经验最优值），直到 gap=1（普通冒泡）

效果: 远距离逆序对快速消除 → 平均复杂度接近 O(n log n)
  （不严格证明，工程经验值；最坏仍 O(n²) 量级）
```

### 5.2 核心实现

```java
/**
 * 梳排序（Comb Sort）——冒泡的"间隔版"
 * gap 从 n 以 /1.3 递减到 1（1.3 为经验最优收缩因子）
 */
public static void combSort(int[] arr) {
    int n = arr.length;
    int gap = n;
    boolean swapped = true;

    while (gap > 1 || swapped) {
        gap = (gap > 1) ? (int) (gap / 1.3) : 1;   // ① 间隔递减
        swapped = false;
        for (int j = 0; j + gap < n; j++) {         // ② 间隔 gap 比较
            if (arr[j] > arr[j + gap]) {
                int tmp = arr[j]; arr[j] = arr[j + gap]; arr[j + gap] = tmp;
                swapped = true;
            }
        }
    }
}
```

> 💡 **演化视角**：梳排序 = 冒泡的"希尔化"——**希尔排序是插入排序 + 间隔，梳排序是冒泡 + 间隔**，两者共享"大步先就位、小步再精修"的思想（见希尔排序专题）。面试被问"冒泡怎么救"，答"梳排序"比"鸡尾酒"更有深度。

## 6. 变体三：奇偶排序（并行友好）

### 6.1 原理

```text
奇偶排序（Odd-Even Sort / 砖墙排序）:
  反复交替执行两阶段:
    奇相位: 比较 (1,2) (3,4) (5,6)…（奇偶对）
    偶相位: 比较 (0,1) (2,3) (4,5)…（偶奇对）
  直到某轮两阶段都无交换 → 有序

复杂度: 仍 O(n²)，但每阶段内所有对互不依赖 → 可并行
  （GPU/多核场景: 每对并行交换）
```

### 6.2 与鸡尾酒排序的关系

```text
鸡尾酒排序: 同轮内从左扫到右、从右扫到左（顺序依赖）
奇偶排序:   奇/偶两阶段交替（阶段内完全并行）
  → 串行环境两者差不多；并行环境奇偶排序是唯一选择
  （排序网络（Sorting Network）的经典案例）
```

## 7. 优化收益矩阵与工程边界

### 7.1 收益矩阵

| 优化 | 代码成本 | 时间收益 | 工程价值 |
|------|:---:|------|:---:|
| 提前终止 | +3 行 | 有序输入 O(n) | ★★★★（必加） |
| lastSwap | +4 行 | 部分有序再提速 | ★★★★（推荐） |
| 鸡尾酒 | +10 行 | 常数 20-40% | ★★★（实现简单） |
| 梳排序 | +10 行 | 平均接近 O(n log n) | ★★★（质变但无保证） |
| 奇偶排序 | +15 行 | 并行潜力 | ★★（并行场景才值） |

### 7.2 工程边界（什么时候真的用它）

```text
可以用:
  ① 教学/演示（第一个排序算法）
  ② n < 100 且不想引入库函数（鸡尾酒版）
  ③ 检测数组是否已有序（一趟冒泡思想，O(n)）
  ④ 并行环境的小规模排序（奇偶排序）

不要用:
  ① n > 1000 —— O(n²) 不可接受（用快排/归并）
  ② n 小但追求速度 —— 插入排序常数更小
  ③ 大规模工程 —— JDK 双轴快排/TimSort 全面碾压

⚠️ 结论: 冒泡是"教学工具"而非"工程工具"——
  它的价值在让你理解"交换类排序"与"提前终止"思想，
  工程上让位给插入（小）与快排（大）
```

> 🎯 **核心要点**：进阶专题验收 = **两个优化（提前终止 → O(n)、lastSwap → 扫描收缩）+ 三个变体（鸡尾酒常数、梳排序质变、奇偶并行）+ 一个边界（教学用、工程不用）**。冒泡家族演化的主线是"**让扫描区间收缩得更快、让比较对象间隔更大**"——这条主线与希尔排序的"间隔思想"殊途同归，能讲出来就是深度。
