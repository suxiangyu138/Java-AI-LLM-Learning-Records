## 1. 选择模型：从排队到算法

### 1.1 算法就像"选最矮的排最前"

排队整理（按身高从矮到高）：

```text
① 在未排序的队伍中扫一遍，找到最矮的
② 让最矮的与队首交换（或出列排好）
③ 队伍缩小一位，重复直到全部排好

每趟效果:
  第 1 趟 → 全局最小到位
  第 2 趟 → 次小到位
  …
  第 n−1 趟 → 全部有序（最后一个自然就位）
```

### 1.2 算法要素

```text
未排序区: arr[i .. n-1]（第 i 趟，i 从 0 开始）
每趟: 线性扫描找最小 → 与 arr[i] 交换
总趟数: n−1 趟（最后一趟只剩一个元素）
交换次数: 恒 n−1 次（每趟 1 次，与数据无关！）

与冒泡的本质区别:
  冒泡: 边扫边换（每趟可能多次交换）
  选择: 先找最小再换（每趟恰好 1 次交换）
```

> 🎯 **核心动作三连**：**找最小（线性扫描记录 minIndex）→ 交换（arr[i] ↔ arr[minIndex]）→ 区间收缩**。"先找后换"让交换次数与数据分布无关——这是它 vs 冒泡/插入最本质的差异，也是"写操作最省"的来源。

## 2. 基本实现：30 秒默写

### 2.1 完整代码

```java
/**
 * 简单选择排序
 * 时间 O(n²)（三情形相同），空间 O(1)，不稳定
 * 交换次数恒 n−1（写操作最省）
 */
public static void selectionSort(int[] arr) {
    int n = arr.length;
    for (int i = 0; i < n - 1; i++) {        // ① 共 n−1 趟
        int minIndex = i;                    // ② 假设当前位最小
        for (int j = i + 1; j < n; j++) {    // ③ 线性扫描找最小
            if (arr[j] < arr[minIndex]) {
                minIndex = j;
            }
        }
        if (minIndex != i) {                 // ④ 交换到区间首位
            int tmp = arr[i];
            arr[i] = arr[minIndex];
            arr[minIndex] = tmp;
        }
    }
}
```

### 2.2 两个关键细节

```text
① minIndex 初始 = i: 若扫描后没找到更小的 → 不交换
   （数据已有序时第 4 步零交换 → 但比较次数不变！）
② 严格小于才更新: arr[j] < arr[minIndex] ——
   注意这只是"找最小"的判据，与稳定性无关
   （不稳定来自交换，不是比较——见第 5 节）
```

> 💡 **记忆技巧**：选择排序 = "**双循环：外圈定位（i）、内圈找最小（j）、找到就换**"。与 283 移动零的双指针不同——**选择是"找极值再换"，冒泡是"边扫边换"**，写代码时先想清楚用哪种哲学。

## 3. 逐步推演：n=8 全流程

**数据**：[8, 3, 5, 1, 9, 2, 6, 4]（升序排序）

| 趟 | 扫描区间 | 找到的最小 | 交换 | 数组状态 |
|:---:|:---:|:---:|:---:|------|
| 初始 | — | — | — | [8,3,5,1,9,2,6,4] |
| 1 | [0..7] | 1（下标 3） | 8↔1 | [1,3,5,8,9,2,6,4] |
| 2 | [1..7] | 2（下标 5） | 3↔2 | [1,2,5,8,9,3,6,4] |
| 3 | [2..7] | 3（下标 5） | 5↔3 | [1,2,3,8,9,5,6,4] |
| 4 | [3..7] | 4（下标 7） | 8↔4 | [1,2,3,4,9,5,6,8] |
| 5 | [4..7] | 5（下标 5） | 9↔5 | [1,2,3,4,5,9,6,8] |
| 6 | [5..7] | 6（下标 6） | 9↔6 | [1,2,3,4,5,6,9,8] |
| 7 | [6..7] | 8（下标 7） | 9↔8 | [1,2,3,4,5,6,8,9] ✓ |

**工作量统计**：

```text
比较次数: 7+6+5+4+3+2+1 = 28 = n(n−1)/2（恒定！）
交换次数: 7 = n−1（恒定！）
→ 与数据是否有序完全无关 —— 这就是"不适应性"的实证
```

> 🎯 **从推演看特性**：数据明明是"乱序 → 有序"的改善过程，但**比较次数一像素都不减**——每趟必须扫完整个未排序区才能确认"最小"。这与插入排序（有序时 O(n)）形成鲜明对比，是选择排序最容易被低估的特性（也是它面试必被问的点）。

## 4. 复杂度推导：三情形相同的原因

### 4.1 精确计数

```text
第 i 趟: 扫描 [i+1 .. n-1]，比较 n−1−i 次

总比较次数:
  Σ(n−1−i) = (n−1) + (n−2) + … + 1 = n(n−1)/2 ≈ n²/2
  → 与数据分布无关（必须全扫才能确认最小）

总交换次数:
  每趟至多 1 次 → 恒 ≤ n−1 次
  → 写操作 O(n)，读操作 O(n²)
```

### 4.2 三情形汇总

| 情形 | 比较次数 | 交换次数 | 复杂度 |
|------|:---:|:---:|:---:|
| 最好（有序） | n²/2 | 0（minIndex==i） | **O(n²)** |
| 平均（随机） | n²/2 | ~n/2 | **O(n²)** |
| 最坏（逆序） | n²/2 | n−1 | **O(n²)** |

```text
面试推导句:
"选择排序每趟必须扫描完整个未排序区才能确定最小，
所以比较次数恒为 n(n−1)/2——最好、平均、最坏完全相同。
交换次数恒 ≤ n−1，这是 O(n²) 家族唯一'写操作 O(n)'的算法。"
```

> 🎯 **面试必答句**："选择排序最好/平均/最坏都是 O(n²)——**不适应性**：每趟必须全扫找最小，有序输入也省不了比较；交换恒 n−1 次是它唯一的亮点（写操作最省）；空间 O(1)；**不稳定**（跨距离交换）。"

## 5. 稳定性分析：反例与稳定版

### 5.1 交换版为什么不稳定（反例）

**数据**：[5a, 3, 5b, 1]（5a 在 5b 前，相等）

| 步骤 | 操作 | 数组状态 |
|:---:|------|------|
| 初始 | — | [5a, 3, 5b, 1] |
| 第 1 趟 | 找最小 = 1（下标 3）→ 交换 arr[0] ↔ arr[3] | [1, 3, **5b**, **5a**] |

**结果**：5b 跳到了 5a 前面——**跨距离交换把相等元素的相对顺序破坏了**。

```text
逆转机制: 交换 arr[i] ↔ arr[minIndex] 时，
          minIndex 可能跨越多个位置（含相等元素）
          → 与快排的"pivot 归位交换"是同一个结构性缺陷
          → 任何"交换式选择"都无法稳定
```

### 5.2 稳定版实现（前移插入替代交换）

```java
/**
 * 稳定版选择排序：找到最小后"前移插入"而非交换
 * 把 [i, minIndex-1] 整体右移 1 位，minIndex 的元素插入 i
 * → 相等元素不会被越过 → 稳定（但移动代价从 O(n) 变 O(n²)）
 */
public static void selectionSortStable(int[] arr) {
    int n = arr.length;
    for (int i = 0; i < n - 1; i++) {
        int minIndex = i;
        for (int j = i + 1; j < n; j++) {
            if (arr[j] < arr[minIndex]) minIndex = j;
        }
        if (minIndex != i) {
            int min = arr[minIndex];               // ① 保存最小
            System.arraycopy(arr, i, arr, i + 1, minIndex - i);  // ② 整体右移
            arr[i] = min;                          // ③ 最小插入前位
        }
    }
}
// ⚠️ 代价: 移动从 O(n)（交换）变 O(n²)（整体右移）
//   → 稳定版失去"写操作最省"的优势 → 工程上很少用
//   → 面试被问"选择排序能稳定吗"：能，但代价是写操作变 O(n²)，
//     通常直接推荐归并排序（稳定 + O(n log n)）
```

> ⚠️ **稳定性考点**：稳定口诀"冒插归基"里没有选择——**选择排序的不稳定是"跨距离交换"的结构性缺陷**（与快排同源）。面试被追问"怎么变稳定"——答"交换改前移插入，但写操作优势消失，工程上直接选归并"。

## 6. 与冒泡/插入排序对比

| 维度 | 选择排序 | 冒泡排序 | 插入排序 |
|------|:---:|:---:|:---:|
| 最好复杂度 | **O(n²)**（不适应性） | O(n) | O(n) |
| 平均/最坏 | O(n²) | O(n²) | O(n²) |
| 稳定性 | ✘ 不稳定 | ✔ 稳定 | ✔ 稳定 |
| 适应性 | ✘ 与数据无关 | ✔ 有序最快 | ✔ 有序最快 |
| 交换/移动次数 | **O(n)**（最少） | O(n²)（交换） | O(n²)（移动） |
| 常数因子 | 中 | 最大 | 最小 |
| 实际速度（n 小） | 居中 | 最慢 | 最快 |

**各自的独特价值**：

```text
选择排序: 交换次数 O(n)——写操作贵的场景（大对象数组、闪存写入）
冒泡排序: 教学直观（可加提前终止检测有序）
插入排序: 综合最优——稳定 + 适应 + 常数最小（小数组王者）

面试选型标准答案:
  "n 小或近乎有序 → 插入排序；
   写操作昂贵（大对象/持久化介质）→ 选择排序；
   其余情况三个都不选，直接 O(n log n) 的归并/快排/堆排。"
```

> 🎯 **核心要点**：选择排序通关四件事——**① 30 秒默写基础版**（双循环找最小 + 交换）；**② 三情形复杂度与交换次数脱口而出**（恒 O(n²)、恒 n−1 次交换）；**③ 稳定性反例张嘴就来**（跨距离交换，5b 越过 5a）；**④ 定位清晰**（写操作最省 vs 不适应性最典型）。**它是"交换次数最少的 O(n²) 排序"和"唯一完全不适应的排序"**——这两个"之最"就是它面试存在的全部意义。
