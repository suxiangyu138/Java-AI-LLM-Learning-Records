## 1. 变体全景：三个改进方向

简单选择排序的瓶颈有两个：**每趟 O(n) 找最小（比较次数恒定 n²/2）**与**交换破坏稳定**。变体围绕这三点：

| 变体 | 优化对象 | 手段 | 效果 |
|------|:---:|------|------|
| 双向选择排序 | 趟数 | 每轮同时找 min + max | 趟数减半 |
| 稳定版选择 | 稳定性 | 前移插入替代交换 | 稳定但写操作变 O(n²) |
| 锦标赛排序 | 找最小 | 树形组织比较 | O(n log n) 但空间 O(n) |
| 堆排序 | 找最小 + 空间 | 完全二叉树 + 堆 | **O(n log n) + O(1)** |

> 🎯 **关键认知**："选择排序的核心瓶颈是'每趟从头找最小'——**所有真正的改进都在'找最小'上做文章**（树形化 → 堆），变体只是在边角（趟数/稳定性）修修补补。这也解释了为什么家族顶点是堆排序而非任何选择变体。"

## 2. 变体一：双向选择排序（min + max 同时找）

### 2.1 原理

```text
每轮同时扫描未排序区:
  找最小 → 交换到左端（begin）
  找最大 → 交换到右端（end）
  begin++、end-- → 区间从两端同时收缩
  → 趟数从 n−1 减半为 ≈ n/2

⚠️ 边界陷阱: 最大元素恰好在 begin 位置时——
  先换最小会把最大换走 → 需先记录/后修正（见代码注释）
```

### 2.2 完整实现

```java
/**
 * 双向选择排序：每轮同时确定最小和最大
 * 趟数减半，复杂度仍 O(n²)，不稳定
 */
public static void selectionSortBidirectional(int[] arr) {
    int begin = 0, end = arr.length - 1;
    while (begin < end) {
        int minIdx = begin, maxIdx = begin;
        // ① 一趟扫描同时找 min 与 max
        for (int i = begin; i <= end; i++) {
            if (arr[i] < arr[minIdx]) minIdx = i;
            if (arr[i] > arr[maxIdx]) maxIdx = i;
        }
        // ② 最小交换到左端
        swap(arr, begin, minIdx);
        // ⚠️ 边界: max 原本在 begin 位置 → 已被换走 → 修正到 minIdx
        if (maxIdx == begin) maxIdx = minIdx;
        // ③ 最大交换到右端
        swap(arr, end, maxIdx);
        begin++;
        end--;
    }
}
// 推演 [5,1,4,2]：找 min=1(max 原本在 begin=0)
//   换 min → [1,5,4,2]；修正 maxIdx=0→1；换 max → [1,2,4,5] ✓ 一轮完成
```

> 💡 **收益评估**：比较次数不变（每轮仍扫全区间，总比较 ≈ n²/2），**省的是交换的趟数开销与循环开销**——实测快约 20-30%，但复杂度不变。面试讲"双向选择"是变体常识，讲"复杂度不变只是常数"是判断力。

## 3. 变体二：稳定版选择排序（前移插入）

### 3.1 原理与实现

```java
/**
 * 稳定版选择排序：交换 → 前移插入
 * 找到最小后把 [i, minIndex-1] 整体右移 1 位，最小插入 i
 * → 相等元素不被越过 → 稳定；但移动从 O(n) 变 O(n²)
 */
public static void selectionSortStable(int[] arr) {
    int n = arr.length;
    for (int i = 0; i < n - 1; i++) {
        int minIndex = i;
        for (int j = i + 1; j < n; j++) {
            if (arr[j] < arr[minIndex]) minIndex = j;
        }
        if (minIndex != i) {
            int min = arr[minIndex];
            System.arraycopy(arr, i, arr, i + 1, minIndex - i);
            arr[i] = min;
        }
    }
}
// 稳定性验证: [5a, 3, 5b, 1]
//   找 min=1 → [i..minIdx-1] 即 [5a,3,5b] 右移 → [1,5a,3,5b]
//   5a 仍在 5b 前 → 稳定 ✓（最小元素"插队"到最前，不越过相等元素）
```

### 3.2 代价与判断

| 维度 | 交换版 | 稳定版 |
|------|:---:|:---:|
| 稳定性 | ✘ | ✔ |
| 移动次数 | O(n)（交换 3 赋值） | O(n²)（整体右移） |
| 唯一卖点 | 写操作最省 | 稳定性 |
| 工程价值 | 大对象/闪存场景 | 极低（归并排序全面替代） |

> ⚠️ **面试判断**："稳定版选择排序存在，但**它把'写操作最省'的卖点换成了稳定性，而稳定 + O(n log n) 有归并排序——所以稳定版选择没有任何工程场景**。被追问时给出这个'用稳定性换卖点'的分析，比背代码高级。"

## 4. 家族演化：锦标赛排序（树形选择）

### 4.1 思想：把比较结果"记住"

```text
问题: 简单选择每趟都从头比较——上一趟的比较结果全丢弃了
锦标赛排序（树形选择，1950s）:
  ① 模拟单败淘汰赛: 两两比较 → 胜者（小者）再两两比较 → 冠军 = 全局最小
  ② 输出冠军后改为 ∞，沿冠军路径重新比较（只需更新路径上的节点）
  ③ 每次选最小从 O(n) 降到 O(log n)

结构: 完全二叉树，n 个叶子 + n−1 个内部节点 → 空间 2n−1
复杂度: 初始化 O(n) + 每次选择 O(log n) → 总 O(n log n)
  空间 O(n)（2n−1 节点，常数约 5）→ 堆排序的"前身"
```

### 4.2 关系公式

```text
锦标赛排序 = (选择排序 + 堆排序) / 2
  选择排序: 每次 O(n) 找最小（比较结果不保存）
  锦标赛排序: 树形保存比较结果 → 每次 O(log n) 更新
  堆排序: 完全二叉树 + 堆性质 → O(log n) 更新 + O(1) 空间

缺陷（堆排序诞生的原因，1964 J. Williams）:
  锦标赛排序需要 2n−1 个节点（空间 O(n)）且要与 ∞ 比较
  堆排序用"数组即树"消灭辅助空间 → O(1)
```

> 🎯 **一句话家族史**："选择排序的演化 = **把'找最小'从线性变成树形**——锦标赛排序用 2n−1 节点换 O(log n)，堆排序用'数组即堆'再省掉空间，最终形态 O(n log n) + O(1)。**这条链是面试讲'选择家族'的最佳主线**。"

## 5. 家族顶点：堆排序衔接

### 5.1 为什么堆排序是"选择排序"的顶点

```text
堆排序 = 用堆做"找最小/最大"的选择排序:
  简单选择: 线性扫描找最小 → O(n) × n 趟 = O(n²)
  堆排序:   堆顶即最值 → O(log n) × n 次 = O(n log n)
  核心: 完全二叉树下标映射 (2i+1, 2i+2, (i−1)/2) 让"数组即树"

三阶段复杂度:
  建堆: O(n)（自底向上筛选，数学证明见堆排序 01 文件）
  排序: n 次取顶 × O(log n) 堆化 = O(n log n)
  空间: O(1)（原地，无辅助数组）

⚠️ 两者共同点: 均不稳定、均 O(1) 空间、均与初始状态无关
  区别只在"找最值"的复杂度: 线性 vs 树形
```

### 5.2 选型决策（数据规模是第一依据）

| 数据规模 | 选型 | 原因 |
|------|------|------|
| n ≤ 1000 | 简单选择排序 | 实现最简单、不易出错、常数开销小 |
| n > 1000 | 堆排序 | O(n log n) 稳定有界 |
| 要稳定 | 归并/TimSort | 选择家族均不稳定 |
| 链式存储 | 都不推荐 | 堆排/选择需随机访问，效率下降 |

> 💡 面试表达："堆排序就是'用堆优化找最值的选择排序'——**选择家族的演化是一条连续曲线：线性找最小 O(n²) → 树形找最小 O(n log n) + O(n) 空间 → 堆找最小 O(n log n) + O(1) 空间**。能画出这条曲线，选择家族就通了。"

## 6. 工程价值：写操作最省的场景

### 6.1 交换次数 O(n) 的实际意义

```text
写操作（赋值/交换）成本:
  基本类型数组: 交换 3 赋值 ≈ 比较成本 → 无差别
  大对象数组:   交换 = 3 次引用赋值，代价小但……
  持久化介质:   每次写入的代价是内存的 100-1000 倍
    （闪存写入寿命限制、HDD 随机写、分布式存储的序列化成本）

选择排序的价值场景:
  ① 大对象数组 + 交换比比较贵（引用交换便宜？——实际引用交换恒 3 赋值，优势有限）
  ② 写入受限介质: 每趟只写 2 个位置（最小 + 首元素）→ 写次数 O(n)
  ③ 需要"部分排序"（只排前 K 个最小）→ 前 K 趟即停

⚠️ 诚实评估: 交换 O(n) 的卖点在现代 CPU/内存架构下被削弱
  （引用交换 3 赋值与比较同阶），真正硬场景是"写入代价极高"的介质
  → 面试说"写操作贵时用选择"即可，别过度吹捧
```

### 6.2 部分选择（Partial Selection）

```java
/** 只求前 K 个最小：前 K 趟即停，O(n·K) */
public static int[] partialSelectMin(int[] arr, int k) {
    for (int i = 0; i < k; i++) {          // 只做前 K 趟
        int minIndex = i;
        for (int j = i + 1; j < arr.length; j++) {
            if (arr[j] < arr[minIndex]) minIndex = j;
        }
        swap(arr, i, minIndex);
    }
    return Arrays.copyOf(arr, k);          // 前 K 个即最小的 K 个
}
// ⚠️ K 很小（如 K=5）时比全排序划算；K 大时被 quickselect（平均 O(n)）取代
```

## 7. 优化收益矩阵与决策规则

### 7.1 收益矩阵

| 优化/变体 | 代码成本 | 时间收益 | 代价 | 工程价值 |
|------|:---:|------|------|:---:|
| 基础版 | 0 | — | — | ★★（小规模） |
| 双向选择 | +8 行 | 常数 20-30% | 边界处理 | ★★ |
| 稳定版 | +5 行 | 稳定性 | **写操作变 O(n²)** | ★（被归并取代） |
| 部分选择 | +3 行 | TopK 场景 O(nK) | K 大时无效 | ★★★ |
| 锦标赛排序 | +30 行 | 质变 O(n log n) | 空间 O(n) | ★★（教学/过渡） |
| 堆排序 | +20 行 | O(n log n) + O(1) | 常数较大 | ★★★★★（见 ②堆排序） |

### 7.2 决策规则

```text
n ≤ 1000 且写操作不敏感 → 基础版 / 双向版（简单优先）
写入代价极高（持久化介质）→ 基础版（交换 O(n)）
求前 K 小且 K 很小 → 部分选择
要稳定性 → 直接归并排序（别用稳定版选择）
n > 1000 → 堆排序 / 快排 / 归并（选择家族退出）

⚠️ 一句话: "选择排序的工程答案不在选择排序内部，
   而在家族顶点堆排序——但'交换 O(n)'与'部分选择'
   这两个独有能力让它在特定场景仍有存在价值。"
```

> 🎯 **核心要点**：进阶专题验收 = **两个变体（双向趟数减半、稳定版前移插入）+ 一条演化链（选择 → 锦标赛 → 堆）+ 两个独有能力（交换 O(n)、部分选择）**。选择家族的演化本质是"**把找最小从线性变成树形**"——从 O(n²) 到 O(n log n)，空间从 O(1) 到 O(n) 再到 O(1)，这条曲线就是堆排序专题的入口。
