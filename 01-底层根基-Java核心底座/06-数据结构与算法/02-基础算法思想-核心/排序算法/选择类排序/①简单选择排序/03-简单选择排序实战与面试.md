## 1. 实战题：前 K 个最小元素（部分选择）

### 1.1 题目与思路

**题**：求数组前 K 个最小元素（K 很小，如 K ≤ 10）。

**部分选择**：选择排序前 K 趟即停——**每趟确定一个最小，前 K 趟就确定了最小的 K 个**：

```java
/**
 * 前 K 个最小元素（部分选择）
 * 时间 O(n·K)，空间 O(1) 额外
 * ⚠️ 适用: K 很小时（K=5 远好于全排序）；K 大时用 quickselect（平均 O(n)）
 */
public int[] smallestK(int[] arr, int k) {
    for (int i = 0; i < k; i++) {
        int minIndex = i;
        for (int j = i + 1; j < arr.length; j++) {
            if (arr[j] < arr[minIndex]) minIndex = j;
        }
        int tmp = arr[i]; arr[i] = arr[minIndex]; arr[minIndex] = tmp;
    }
    return Arrays.copyOf(arr, k);
}
// 推演 [5,2,8,1,9,3]，k=3：
//   趟1: min=1 → [1,2,8,5,9,3]
//   趟2: min=2 → [1,2,8,5,9,3]
//   趟3: min=3 → [1,2,3,5,9,8] → 返回 [1,2,3] ✓
```

> 🎯 **这题的选型价值**："部分选择 O(n·K) 在 K 小（≤10）时是最简单的 TopK 解法；K 大到 n/2 时与全排序等价，被 quickselect（平均 O(n)）取代。**'按 K 选型'是 TopK 问题的方法论起点**——堆版 O(n log k)、快速选择 O(n) 都在 04-排序算法应用 有完整对比。"

## 2. 实战题：最小交换次数类问题

### 2.1 题目与思路

**题**：只允许交换相邻元素，求把数组排好序的最小交换次数 → **等于逆序对数量**（归并计数，见归并专题）。若允许任意交换 → 贪心 + 选择排序思想。

```text
"任意交换"变体（求最少任意交换次数）:
  每趟把正确元素换到正确位置（类似选择排序的交换模式）
  计数 = 已就位元素不换 → 交换次数 = n − 环的数量
  （每个置换环只需 n−1 次交换）

与选择排序的关系:
  选择排序每趟交换后"当前位置元素就位" → 它天然逼近最少任意交换次数
  → "最少任意交换"的贪心实现可以看作选择排序的计数版
```

### 2.2 完整实现

```java
/**
 * 求最少"任意交换"次数使数组有序（元素互不相同）
 * 思路: 置换环分解——每个长度为 c 的环需要 c−1 次交换
 *       total = Σ(c−1) = n − 环数
 */
public int minSwaps(int[] arr) {
    int n = arr.length;
    int[] sorted = arr.clone();
    Arrays.sort(sorted);                          // ① 目标位置映射
    Map<Integer, Integer> pos = new HashMap<>();
    for (int i = 0; i < n; i++) pos.put(sorted[i], i);

    boolean[] visited = new boolean[n];
    int swaps = 0;
    for (int i = 0; i < n; i++) {                 // ② 找置换环
        if (visited[i]) continue;
        int j = i, cycleLen = 0;
        while (!visited[j]) {                     // 沿环走一遍
            visited[j] = true;
            j = pos.get(arr[j]);                  // 元素应去的位置
            cycleLen++;
        }
        swaps += cycleLen - 1;                    // ③ 每环 c−1 次
    }
    return swaps;
}
// 推演 [4,3,2,1]：sorted=[1,2,3,4] → 环 (0→3→0)(1→2→1) 两个
//   swaps = (2−1)+(2−1) = 2 次：4↔1、3↔2 ✓
```

> 💡 **讲解亮点**："选择排序每趟'固定一个元素'，与'任意交换的最少次数'共享同一个环分解模型——**这题的贪心解法就是选择排序的计数版本**。讲这题时把选择排序的'每趟就位一个'特性串进去，就是算法题与排序思想的连线。"

## 3. 实战题：912 排序数组（选择排序的边界）

### 3.1 题目与思路

**题**：排序数组（912），n ≤ 5×10⁴。

```text
选择排序在此题:
  比较 n²/2 ≈ 1.25×10⁹ 次 → 必然超时 ❌
  双向选择也一样（比较次数不变）
  交换少救不了"比较恒定 O(n²)"的命

结论: 912 正解是快排/归并/堆排——
  选择排序的 O(n²) 比较是硬伤，交换 O(n) 的优势在 5×10⁴ 规模无意义
```

### 3.2 选择排序在题目中的真正位置

| 场景 | 选择排序可用？ | 说明 |
|------|:---:|------|
| 前 K 小（K ≤ 10） | ✔ 推荐 | 部分选择 O(nK)，实现最简单 |
| 求最少任意交换次数 | ✔ 思想复用 | 环分解与选择排序同源 |
| n ≤ 1000 手写排序 | ✔ 勉强 | 实现简单不易错 |
| n ≥ 10⁴ 的排序题 | ✘ 超时 | 快排/归并/堆排 |
| 要求稳定 | ✘ | 选择家族不稳定（归并上） |

> 🎯 **实战判断**："选择排序在算法题里**从不当排序正解，但'部分选择'与'环分解'两个思想是题目的解法来源**。它的存在意义是 TopK 小 K 场景的最简实现，其余交给家族顶点堆排序。"

## 4. 面试话术三连

### 4.1 三连话术（背下来）

```text
Q1: "选择排序的复杂度？"
A: "最好/平均/最坏都是 O(n²)——每趟必须扫描完整
   未排序区才能确定最小，比较次数恒 n(n−1)/2。
   空间 O(1)；交换次数恒 n−1，是 O(n²) 家族写操作最省的。
   不稳定——跨距离交换会越过相等元素。"

Q2: "选择排序 vs 冒泡 vs 插入？"
A: "都是 O(n²)。插入综合最优（稳定 + 适应 + 常数最小）；
   选择唯一优势是交换 O(n)（写操作贵的场景）；
   冒泡教学直观但常数最大。选择排序的不适应性
   （三情形相同）是它最大的短板。"

Q3: "选择排序家族怎么演化？"
A: "选择 → 锦标赛 → 堆：找最小从线性 O(n) 变成树形 O(log n)。
   锦标赛排序 O(n log n) 但空间 O(n)（2n−1 节点）；
   堆排序用'数组即树'省到 O(1)——1964 年 Williams
   为弥补锦标赛排序缺陷而提出。家族顶点就是堆排序。"
```

### 4.2 30 秒手写版本

```java
// 面试手写最简版（30 秒内）
void selectionSort(int[] a) {
    for (int i = 0; i < a.length - 1; i++) {
        int m = i;
        for (int j = i + 1; j < a.length; j++)
            if (a[j] < a[m]) m = j;
        if (m != i) { int t = a[i]; a[i] = a[m]; a[m] = t; }
    }
}
```

## 5. 手撕清单与复杂度速答

### 5.1 手撕清单

```text
必默写（30 秒）:
  □ 基础版（双循环找最小 + 交换）
  □ 前 K 小部分选择（K 趟即停）

进阶（3 分钟）:
  □ 双向选择（min + max 同时找，含 begin 边界修正）
  □ 稳定版选择（前移插入，能讲清代价）

概念必答:
  □ 三情形复杂度 + 交换次数恒 n−1
  □ 不稳定反例（5b 越过 5a）
  □ 家族演化链（选择 → 锦标赛 → 堆）
```

### 5.2 复杂度速答表

| 问题 | 标准答案 |
|------|---------|
| 最好/平均/最坏 | O(n²) / O(n²) / O(n²)（不适应性） |
| 空间 | O(1) |
| 稳定性 | 不稳定（跨距离交换）；稳定版前移插入可行但写操作变 O(n²) |
| 比较次数 | 恒 n(n−1)/2 |
| 交换次数 | 恒 ≤ n−1 |
| 部分选择 | 前 K 趟即停 → O(n·K) |
| 家族演化 | 锦标赛 O(n log n) + O(n) 空间 → 堆 O(n log n) + O(1) |

## 6. 软考与笔试考点：过程模拟

### 6.1 过程模拟题（必考大题）

**真题样式**：对序列 [8, 3, 5, 1, 9, 2, 6, 4] 做简单选择排序，写出每趟结果并计算比较/交换次数。

| 趟 | 扫描区间 | 选出的最小 | 交换 | 结果 |
|:---:|:---:|:---:|:---:|------|
| 初始 | — | — | — | [8,3,5,1,9,2,6,4] |
| 1 | [0..7] | 1 | 8↔1 | [1,3,5,8,9,2,6,4] |
| 2 | [1..7] | 2 | 3↔2 | [1,2,5,8,9,3,6,4] |
| 3 | [2..7] | 3 | 5↔3 | [1,2,3,8,9,5,6,4] |
| 4 | [3..7] | 4 | 8↔4 | [1,2,3,4,9,5,6,8] |
| 5 | [4..7] | 5 | 9↔5 | [1,2,3,4,5,9,6,8] |
| 6 | [5..7] | 6 | 9↔6 | [1,2,3,4,5,6,9,8] |
| 7 | [6..7] | 8 | 9↔8 | [1,2,3,4,5,6,8,9] ✓ |

**答案**：比较 28 次（n(n−1)/2）、交换 7 次（n−1）。

**答题技巧**：

```text
① 每趟先写"扫描找最小"，再写"交换结果"——中间状态是评分点
② 交换次数恒 n−1：即使有序也每趟至多 1 次（软考常考"有序输入交换几次"）
③ 判断题陷阱: "选择排序对有序输入比较次数减少？" ❌ 不减少！
```

### 6.2 其他题型

| 考点 | 题型 | 要点 |
|------|------|------|
| 稳定性判断 | 概念题 | 口诀"冒插归基"不含选择——交换版不稳定 |
| 交换次数 | 计算题 | 恒 n−1 次（每趟至多 1 次） |
| 比较次数 | 计算题 | 恒 n(n−1)/2（与有序度无关） |
| 不适应性 | 判断题 | 最好 = 最坏 = O(n²)——有序输入也全扫 |
| 家族演化 | 概念题 | 选择 → 锦标赛（O(n) 空间）→ 堆（O(1)） |

## 7. 高频追问与标准回答

| # | 追问 | 标准回答 |
|:---:|------|---------|
| 1 | 为什么选择排序不稳定？ | 跨距离交换会把相等元素越过（5b 越过 5a 反例）——与快排同源 |
| 2 | 能变稳定吗？ | 能——前移插入替代交换，但写操作从 O(n) 变 O(n²)，工程上直接选归并 |
| 3 | 为什么最好情况也是 O(n²)？ | 每趟必须扫描完整未排序区才能"确认"最小——比较恒 n²/2 |
| 4 | 什么时候用选择排序？ | 写操作贵的介质（交换 O(n)）+ 前 K 小（部分选择 K 趟即停） |
| 5 | 选择 vs 冒泡交换次数？ | 选择恒 n−1；冒泡最坏 n²/2（边扫边换） |
| 6 | 锦标赛排序为什么被堆取代？ | 需要 2n−1 个节点（空间 O(n)）；堆用"数组即树"省到 O(1) |
| 7 | TopK 选哪种？ | K 小用部分选择（O(nK)）；K 大用堆（O(n log k)）或 quickselect（O(n)） |
| 8 | 选择排序适合链表吗？ | 不适合——找最小需随机访问；链式存储下效率下降（堆排同理） |

> 🎯 **核心要点**：实战面试通关 = **两个思想（部分选择、环分解）+ 一道边界题（912 超时实证）+ 话术三连 + 一道模拟（软考过程模拟，交换次数恒 n−1）**。选择排序在面试中的正确姿势是"**承认 O(n²) 比较是硬伤，讲清交换 O(n) 的独有能力与家族演化链**"——把"从选择到堆"的曲线画出来，比硬吹选择排序高级得多。
