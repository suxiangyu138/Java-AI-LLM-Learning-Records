## 1. TopK 问题：堆的五种解法全景

### 1.1 问题定义

```text
从 n 个元素中找最大的 k 个（n 巨大，如 10⁹；k 相对小，如 1000）

五种思路:
  ① 重复找最大（选择排序思想）: k 轮线性扫描
  ② QuickSelect: 划分后只递归一侧（平均 O(n)）
  ③ 最小堆 TopK: 维护大小为 k 的最小堆
  ④ 最大堆全建: 建最大堆 → 取顶 k 次
  ⑤ 锦标赛树: 树形选择（k 次 O(log n) 更新）
```

### 1.2 最小堆 TopK（工程默认，必会）

```java
/**
 * TopK（前 K 大）：维护大小为 K 的最小堆
 * 时间 O(n·log k)，空间 O(k)
 * 核心: 堆顶是"当前第 K 大"——新元素比堆顶大才入堆
 */
public int[] topK(int[] nums, int k) {
    PriorityQueue<Integer> heap = new PriorityQueue<>();   // 最小堆
    for (int x : nums) {
        if (heap.size() < k) {
            heap.offer(x);                                 // ① 堆未满 → 直接入
        } else if (x > heap.peek()) {                      // ② 比堆顶大 → 替换
            heap.poll();
            heap.offer(x);
        }
    }
    int[] result = new int[k];
    for (int i = 0; i < k; i++) result[i] = heap.poll();
    return result;
}
// ⚠️ 语义: 堆顶 = 前 K 大的"门槛"（第 K 大的值）
//   空间 O(k) 是它在 n=10⁹ 场景的制胜点（无法 O(n) 建堆）
```

> 🎯 **TopK 的核心认知**："**最小堆 TopK 是'只关心门槛'的算法**——堆里只保留最大的 k 个，堆顶就是第 k 大的门槛，新元素与门槛比较决定去留。空间 O(k) 让它在 n=10⁹（无法全量入内存）时是唯一现实方案。"

## 2. TopK 五方法对比（n=10⁹，k=1000）

### 2.1 对比表（实测比较次数级）

| 方法 | 比较次数级 | 时间 | 空间 | 适用 |
|------|:---:|:---:|:---:|------|
| 重复找最大 | ~1000·n | O(k·n) | O(1) | k 极小（k ≤ 10） |
| QuickSelect | ~60·n | O(n) 期望 | O(1) | 内存够、要精确 TopK |
| 最小堆 TopK | ~20·n | O(n·log k) | **O(k)** | 空间受限（工程默认） |
| 最大堆全建 | ~2·n | O(n + k·log n) | O(n) | 时间优先、内存够 |
| 锦标赛树 | ~n | O(n) | 2n−1 | 比较极贵、时间最优先 |

### 2.2 选型决策（面试方法论）

```text
n = 10⁹（放不进内存）→ 最小堆 TopK（唯一空间可行）
n = 10⁶~10⁷（可入内存）:
  k 小（≤100）→ 最小堆 TopK（实现简单、常数小）
  k 大（≥n/2 或要精确第 K 大）→ QuickSelect（O(n)）
比较极昂贵（对象键）→ 锦标赛树（比较次数最少，~n）
要"动态 TopK"（数据流式到达）→ 最小堆（唯一支持增量）

⚠️ 一句话: "静态一次性 TopK 用 QuickSelect（O(n) 最优），
   流式/空间受限用最小堆（O(n log k) + O(k)）——
   大数据场景 90% 选最小堆，因为它能处理放不进内存的数据。"
```

> 🎯 **2026 谈资版**："TopK 的方法论在 2026 年依旧成立——**最小堆 O(n log k) + O(k) 空间是流式与大数据场景的唯一现实解；QuickSelect O(n) 是内存内场景的理论最优；锦标赛树比较次数最少但空间 2n−1 不划算**。五方法对比表是面试 TopK 题的标准答题框架。"

## 3. 优先队列：堆的工程形态

### 3.1 PriorityQueue 与堆排序的关系

```text
Java PriorityQueue = 最小堆（数组实现的完全二叉树）
  offer（入堆）: 尾插 + 上浮（siftUp）→ O(log n)
  poll（出堆）: 取根 + 尾补根 + 下沉（siftDown）→ O(log n)
  peek: O(1)

与堆排序的分工:
  堆排序 = 用堆对数组原地排序（siftDown 为核心）
  优先队列 = 堆的"动态容器"（siftUp + siftDown 并用）
  → 两者共享完全相同的堆结构与核心操作
```

### 3.2 工程应用矩阵

| 场景 | 用法 | 复杂度 |
|------|------|:---:|
| TopK（流式） | 最小堆容量 k | O(n log k) |
| 合并 K 有序序列（23/多路归并） | 最小堆存 K 个候选 | O(n log k) |
| 任务调度（时间片） | 最小堆按时间/优先级 | O(log n)/操作 |
| Dijkstra / Prim | 最小堆存待选节点 | O((V+E) log V) |
| 中位数维护 | 最大堆 + 最小堆双堆 | O(log n)/操作 |

> 💡 面试表达："**优先队列就是堆的工程形态**——PriorityQueue 的实现与堆排序共享'完全二叉树 + 数组映射'，区别只是堆排序用 siftDown 原地排序、优先队列用 siftUp+siftDown 做动态容器。TopK/多路归并/图算法里的'堆'全是它。"

## 4. 学术变体：bottom-up / weak heap / smoothsort

### 4.1 bottom-up heapsort（下沉比较减半）

```text
经典堆化: 每层 2 次比较（两孩子比大小 + 与父比）
bottom-up 优化:
  ① 先沿"较大孩子路径"一路下沉（每层 1 次比较，只比孩子）
  ② 到叶子后再向上找到正确位置插入（借插入排序的"找到位置再移"思想）
  → 平均比较次数从 2n log n 降到 ~n log n（减半）
  → 实际常数提升约 25-30%（工程上值得用的优化）
```

### 4.2 weak heap / smoothsort

```text
Weak heap（弱堆，Dujmović 1996）:
  放宽堆性质（弱堆约束）→ 比较次数降到理论下界 n log n − 1.9n
  → 学术界最接近最优的原地比较排序

Smoothsort（Dijkstra 1981）:
  用"光滑排序树"替代完全二叉树 → 自适应
  → 有序数据 O(n)、随机数据 O(n log n)、空间 O(1)
  → 罕见的同时具备"自适应 + 最坏有界 + 原地"的排序
  → 但常数很大 + 实现复杂 → 工程上基本不用（教学价值为主）

⚠️ 面试定位: 知道存在即可——
  "bottom-up 是工程优化（比较减半）；
   weak heap/smoothsort 是学术前沿（理论最优/自适应），
   工程主流仍是经典堆排序 + 优先队列。"
```

## 5. 缓存与常数：堆排序的真实性能画像

### 5.1 为什么堆排序缓存不友好

```text
堆化路径: 下标 i → 2i+1 → 4i+3 → …（每次 ×2 跳跃）
  大数组时父子相距甚远 → 每次访问都可能缓存未命中
  对比快排: 顺序扫描分区 → 缓存友好

实测画像（O(n log n) 家族）:
  快排: 比较最多（1.39n log n）但缓存最优 → 实际最快
  堆排: 比较次多（2n log n）且缓存最差 → 实际最慢
  归并: 比较最少（n log n）但拷贝多 → 居中

结论: 堆排的"最坏有界 + O(1) 空间"是用速度换来的——
  它的工程定位是"保障者"而非"速度王"
```

### 5.2 什么时候堆排序真正占优

| 场景 | 为什么是堆排 |
|------|------|
| 内存严格受限（嵌入式/固件） | O(1) 空间 + 无递归栈 |
| 最坏必须 O(n log n) | 快排退化不可接受 |
| introsort 兜底 | 深度超限转堆排（C++ std::sort / JDK） |
| TopK / 优先队列语义 | 不需要全排序，只要堆结构 |
| 实时系统（可预测性） | 复杂度与数据分布完全无关 |

## 6. introsort 兜底：堆在工业排序中的角色

### 6.1 堆排的"工业退休"与"工业返聘"

```text
退休: 通用排序不用堆排（常数大、缓存差）→ 快排/归并/TimSort
返聘: 快排深度超限时转堆排 —— introsort 的标准设计:
  ① 递归深度 ≤ 2·log₂n → 快排（平均最快）
  ② 深度超限 → 判定划分退化 → 该区间转堆排序（最坏有界）
  → 组合结果: 平均快排的常数 + 最坏堆排的保证

工业事实:
  C++ std::sort = introsort（快排 + 插入 + 堆排兜底）
  JDK DualPivotQuicksort = 双轴快排 + 深度 64 超限转堆排
  → 堆排序是工业排序的"保险丝"——平时不工作，关键时兜底
```

> 🎯 **一句话定位**："堆排序是工业排序的'保险丝'——**通用场景被快排取代（常数大），但最坏保障与 O(1) 空间让它在 introsort 里成为必选兜底**。讲清楚'退休与返聘'，堆排的工程价值就立体了。"

## 7. 2025-2026 基准与面试要点

### 7.1 2025-2026 基准研究

```text
① Discover Computing（2025）系统性综述（12 种算法）:
   归并与堆排在大数据量下提供"稳定可扩展"性能（O(n log n) 恒定）
   选择/冒泡在大数据集显著低效
② 跨语言研究（2026，C/C++/Go/Java/PHP/Python，10⁵ 元素）:
   堆排与归并在各输入模式下表现最一致
   选择排序在所有环境中均低效
③ 结论: 堆排的"与数据无关"特性在大数据 + 未知分布场景
   是被反复验证的核心优势

⚠️ 面试谈资: "2025-2026 的跨语言基准显示堆排在
   未知数据分布下是最一致的 O(n log n) 排序——
   '无适应性'从缺点变成了'可预测性'的优点（实时系统视角）。"
```

### 7.2 面试要点清单

```text
必会:
  □ siftDown 手写（循环版）
  □ 建堆起点 (n−2)/2 + 建堆 O(n) 证明
  □ 升序用大顶堆（软考判定）
  □ 最小堆 TopK（O(n log k) + O(k) 空间）

进阶:
  □ TopK 五方法对比与选型
  □ 优先队列工程（PriorityQueue 的 offer/poll 内部）
  □ bottom-up 比较减半 / smoothsort 自适应
  □ introsort 兜底（C++ std::sort / JDK 深度 64）

概念必答:
  □ 三情形 O(n log n) + O(1) 空间 + 不稳定
  □ 缓存不友好（下标 ×2 跳跃）
  □ 家族定位（选择家族的顶点）
```

> 🎯 **核心要点**：进阶专题验收 = **一个方法论（TopK 五方法对比 + 选型）+ 一个工程形态（PriorityQueue）+ 三个变体（bottom-up/weak heap/smoothsort）+ 一个角色（introsort 保险丝）**。堆的舞台远不止排序——**TopK、多路归并、图算法、任务调度全是它的地盘，而排序只是它最朴素的应用**。能把"堆 = 优先队列的底层 = TopK 的引擎 = 工业排序的保险丝"讲成一条线，就是堆专题的深度。
