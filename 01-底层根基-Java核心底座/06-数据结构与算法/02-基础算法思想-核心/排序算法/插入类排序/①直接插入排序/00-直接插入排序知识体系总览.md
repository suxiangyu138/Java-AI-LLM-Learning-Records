## 1. 知识体系导图

```text
直接插入排序（Straight Insertion Sort）
│
├── 核心本质 ──────────────────────────────────────────────
│   ├── = 把无序区的每个元素插入到已排序区的正确位置
│   ├── 扑克牌模型：摸一张牌 → 找到位置 → 插入
│   ├── 就地排序：边比较边移动（前驱后移腾位）
│   └── 共 n−1 趟，每趟插入一个元素
│
├── 关键特性 ──────────────────────────────────────────────
│   ├── 时间复杂度：最好 O(n) / 平均 O(n²) / 最坏 O(n²)
│   ├── 空间复杂度：O(1)（原地）
│   ├── 稳定性：✔ 稳定（相等元素不交换）
│   └── 适应性：✔ 数据越有序越快（最佳 O(n)）
│
├── 三大优化与变体 ────────────────────────────────────────
│   ├── 哨兵优化：R[0] 作哨兵，省去边界判断（速度提升明显）
│   ├── 折半插入：二分查找定位插入点（比较数降到 O(n log n)）
│   └── 希尔排序：分组插入 → 大步长后小步长（02 衔接）
│
├── 工程价值 ──────────────────────────────────────────────
│   ├── 小数组杀手：n < 64 时快过快排（常数极小）
│   ├── TimSort 的基石：Python/Java 内置排序的片段插入
│   ├── 近乎有序数据：实际 O(n)（运维/日志场景）
│   └── 链表适用：链式存储也能插入排序（147 题）
│
└── 实战与面试 ────────────────────────────────────────────
    ├── 手写：基础版 + 哨兵版（2 分钟默写）
    ├── 考题：147 链表插入排序、912 数组排序片段
    ├── 对比：插入 vs 冒泡 vs 选择（三个 O(n²) 谁最好）
    └── 话术：稳定性 + 适应性 + 常数因子 + 适用场景
```

## 4. 核心概念速查

| 概念 | 一句话解释 | 说明 |
|------|-----------|------|
| **直接插入排序** | 把无序元素逐个插入已排序区 | 最简单稳定的排序之一 |
| **已排序区/未排序区** | 数组逻辑分成两段 | 前半有序，后半待插入 |
| **边比较边移动** | 从后向前比较，前驱后移腾位 | 就地排序的核心手法 |
| **哨兵（Sentinel）** | R[0] 保存副本 + 监视越界 | 省去 j>=0 判断，提速 |
| **稳定性** | 相等元素相对顺序不变 | 插入时严格小于才移动 |
| **适应性（Adaptive）** | 数据有序程度影响性能 | 基本有序 → O(n) |
| **折半插入** | 二分定位插入点 | 比较降到 O(n log n) |
| **希尔排序** | 分组插入，大步长到小步长 | 插入排序的规模化改进 |
| **TimSort** | 归并 + 插入的混合排序 | Python/Java 内置排序底层 |
| **常数因子** | 同阶算法间的实际速度差异 | 插入排序常数最小 |

## 5. 复杂度与特性速查表

| 维度 | 最好 | 平均 | 最坏 | 说明 |
|------|:---:|:---:|:---:|------|
| 时间复杂度 | O(n) | O(n²) | O(n²) | 最好 = 数据已有序 |
| 空间复杂度 | O(1) | O(1) | O(1) | 原地排序 |
| 比较次数 | n−1 | n²/4 | n²/2 | 最坏逆序 |
| 移动次数 | 0 | n²/4 | n²/2 | 与比较同阶 |
| 稳定性 | ✔ 稳定 | — | — | 相等不交换 |
| 适应性 | ✔ 数据越有序越快 | — | — | 关键特性 |

**与其他 O(n²) 排序对比**：

| 算法 | 最好 | 最坏 | 稳定 | 适应 | 常数因子 |
|------|:---:|:---:|:---:|:---:|:---:|
| 插入排序 | O(n) | O(n²) | ✔ | ✔ | 最小 |
| 冒泡排序 | O(n) | O(n²) | ✔ | ✔ | 大 |
| 选择排序 | O(n²) | O(n²) | ✘ | ✘ | 中 |

> 🎯 **一句话选型**：三个 O(n²) 里，**插入排序综合最优**——稳定、自适应、常数最小；选择排序唯一优势是"交换次数最少"（O(n) 次交换，写操作少的场景）；冒泡唯一优势是教学直观。

### 5.1 与高级排序的分工

| 场景 | 推荐 | 原因 |
|------|------|------|
| n < 64 的任意数组 | **插入排序** | 常数最小，实际快过 O(n log n) 家族 |
| 近乎有序的大数组 | **插入排序 / TimSort** | 适应性 → 实际 O(n) |
| 大数组、不要求稳定 | 快速排序 | O(n log n) 平均 + 原地 |
| 大数组、要求稳定 | 归并排序 / TimSort | O(n log n) + 稳定 |
| 大数组、要求最坏有界 | 堆排序 | 严格 O(n log n) |
| 混合排序的短片段 | **插入排序** | JDK/Python 标准做法（阈值 16~64） |

> 💡 **决策口诀**："**小和有序用插入，大且乱用快排，要稳定用归并，要界限用堆排**"——插入排序在大规模场景的角色是"辅助者"（混合排序片段），而不是主角。

## 6. 常见误区速查

| 误区 | 正解 |
|------|------|
| "插入排序时间复杂度是 O(n²)，一无是处" | ❌ 最好 O(n)、常数最小、稳定自适应——小数组和近乎有序数据它是王者 |
| "插入排序和选择排序一样" | ❌ 插入是"边比较边移动"（前驱后移）；选择是"找最小然后交换"（交换次数 O(n)） |
| "哨兵只是优化，可有可无" | ❌ 哨兵省去循环内边界判断，比较时间减少约一半（教材经典优化） |
| "插入排序不稳定" | ❌ 稳定！内层仅当严格小于时才移动，相等元素保持相对顺序 |
| "n 小就直接用冒泡" | ❌ n < 64 时插入排序最快（常数最小），Java 排序就是这么设计的 |
| "希尔排序是另一种算法" | ❌ 希尔 = 分组的直接插入排序（大步长 → 小步长） |
| "折半插入让总复杂度变 O(n log n)" | ❌ 只降低**比较**次数，**移动**次数不变，总复杂度仍 O(n²) |
| "基本有序用快排最快" | ❌ 快排基本有序时退化 O(n²)；插入排序这时是 O(n)——TimSort 正是利用这点 |
