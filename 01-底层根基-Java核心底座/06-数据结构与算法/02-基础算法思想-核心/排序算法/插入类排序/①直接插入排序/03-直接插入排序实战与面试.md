## 1. 实战题：147 对链表进行插入排序

### 1.1 题目与思路

**题**：对单链表进行插入排序（不能改节点值，必须改指针）。

**与数组版的关键差异**：

```text
数组插入: 找到位置后要"搬移"元素（O(n)）——前驱后移
链表插入: 找到位置后只改指针（O(1)）——插入本身免费
两者共同的成本: 找位置 = 顺序扫描（O(n)）→ 总 O(n²)
```

### 1.2 完整代码（哨兵头结点技巧）

```java
/**
 * LeetCode 147. 对链表进行插入排序
 * 时间 O(n²)，空间 O(1)
 * 技巧: 哑结点 dummy 作哨兵，简化头插入的边界处理
 */
public ListNode insertionSortList(ListNode head) {
    if (head == null) return null;
    ListNode dummy = new ListNode(0);     // ① 哑结点（哨兵思想：省去头插特判）
    ListNode cur = head;                  // ② cur = 当前待插入节点
    while (cur != null) {
        ListNode next = cur.next;         // ③ 先保存后继（cur 会被摘除）
        ListNode pos = dummy;             // ④ 从哑结点开始找插入位置
        while (pos.next != null && pos.next.val < cur.val) {
            pos = pos.next;               // ⑤ 找到第一个 >= cur 的位置之前
        }
        cur.next = pos.next;              // ⑥ 摘除 cur 并插入（只改指针！）
        pos.next = cur;
        cur = next;                       // ⑦ 继续下一个
    }
    return dummy.next;
}
```

### 1.3 推演与易错点

```text
推演 [4, 2, 1, 3]:
  插入 4: dummy → 4
  插入 2: dummy → 2 → 4（4.next=2 位置找对，2 插到头）
  插入 1: dummy → 1 → 2 → 4
  插入 3: dummy → 1 → 2 → 3 → 4 ✓

易错点:
  ① 必须先存 next（cur.next = pos.next 会断开原链）
  ② 插入后 cur 要指向保存的 next，不是 cur.next（已被改写）
  ③ 哑结点必须每次从头扫描（不能复用上次位置，因为插入位置不单调）
```

> 🎯 **147 是"哨兵思想"的链表版实践**：哑结点 = 哨兵（省去"插到头部"的特判分支）。与数组版哨兵（省去 j>=0 判断）是同一个思想——**用一个额外的哑位置统一边界**。

## 2. 实战题：912 排序数组中的插入应用

### 2.1 题目与思路

**题**：排序数组（912），数据范围随机。**直接插入排序 O(n²) 会超时**——但它不是主角，主角是"**插入排序作为混合排序的片段**"：

```java
// 工程混合排序模式: 大数组快排/归并，小片段切插入
// （以下为 TimSort / 双轴快排的标准手法）
public void hybridSort(int[] arr, int lo, int hi) {
    if (hi - lo <= 16) {                        // ① 片段足够小
        insertionSort(arr, lo, hi);             // ② 插入排序收尾（常数最小）
        return;
    }
    // ③ 大片段继续递归/归并（此处以快排为例）
    int p = partition(arr, lo, hi);
    hybridSort(arr, lo, p - 1);
    hybridSort(arr, p + 1, hi);
}
```

### 2.2 为什么"小片段切插入"是工程标准

```text
① 常数因子: O(n²) 的插入排序常数远小于 O(n log n) 的快排
   → n < 阈值时，插入排序的实际时间反而更短（常数压制阶数）
② 缓存友好: 插入排序只访问相邻元素，局部性优于快排的分区
③ 递归开销: 深递归的调用栈开销 > 小片段插入的收益
阈值经验值: 快排系 7~16、TimSort 32~64、Android 双轴快排 47

工程证据:
  Java Arrays.sort(基本类型) = 双轴快排 + 小片段插入
  Java Arrays.sort(对象) = TimSort（32 阈值 + 插入排序）
  Python sorted = TimSort
```

> 💡 面试谈资："**JDK 的快排不是纯快排——片段小于阈值时切到插入排序**，因为小数组上插入排序的常数优势超过阶数优势。阈值一般 16 到 64，取决于语言和硬件。" 能说出阈值区间与理由，工程深度立现。

## 3. 工程应用：TimSort 与 JDK 源码

### 3.1 TimSort 是什么

```text
TimSort（2002 年 Tim Peters 为 Python 设计）:
  ① 扫描检测"天然有序段"（run）——升序段直接复用
  ② 短 run（< 32/64）用直接插入排序扩张
  ③ 相邻 run 用归并合并（栈 + 平衡策略）
  ④ 结果: 最坏 O(n log n)、近乎有序 O(n)、稳定、O(n) 空间

关键: 插入排序的"适应性" + 归并的"稳定性与最坏保证"
```

> 🎯 **一句话总结 TimSort 与插入排序的姻缘**："TimSort = 用插入排序的**适应性和小数组速度**处理短片段，用归并的**稳定性和最坏保证**合并长片段——这是插入排序在工业界的最高地位。"（参考来源见 00 文件）

## 4. 面试话术三连

### 4.1 三连话术（背下来）

```text
Q1: "插入排序的复杂度？"
A: "最好 O(n)——数据已有序；平均和最坏 O(n²)——逆序时每趟都要移动到底；
   空间 O(1) 原地，稳定。"

Q2: "什么时候用插入排序？"
A: "三个场景：小数组（n < 64，常数最小，快过快排）；
   近乎有序的数据（自适应 O(n)）；
   作为混合排序的片段（TimSort 短 run 的处理）。"

Q3: "插入排序 vs 冒泡 vs 选择？"
A: "三者都是 O(n²)。插入综合最优——稳定、自适应、常数最小；
   选择唯一优势是交换次数 O(n)（写操作贵时用）；
   冒泡教学直观但常数最大，工程上基本不用。"
```

### 4.2 30 秒手写版本

```java
// 面试手写标准版（2 分钟内）
void insertionSort(int[] a) {
    for (int i = 1; i < a.length; i++) {
        int key = a[i], j = i - 1;
        while (j >= 0 && a[j] > key) { a[j + 1] = a[j]; j--; }
        a[j + 1] = key;
    }
}
```

### 5.2 复杂度速答表

| 问题 | 标准答案 |
|------|---------|
| 最好/平均/最坏 | O(n) / O(n²) / O(n²) |
| 空间 | O(1) |
| 稳定性 | 稳定（严格大于才移动） |

## 7. 高频追问与标准回答

| # | 追问 | 标准回答 |
|:---:|------|---------|
| 1 | 为什么小数组插入排序比快排快？ | 常数因子压制阶数：快排的递归/分区开销在小数组上大于插入的 O(n²) 实际成本 |
| 2 | 插入排序能提前终止吗？ | 不能严格证明有序（除非检测到整趟无移动的启发）；TimSort 用 run 检测实现等效效果 |
| 3 | 折半插入为什么总复杂度还是 O(n²)？ | 移动次数不变（最坏仍 n²/2），移动是 O(n²) 的主导项 |
| 4 | 希尔排序为什么不稳定？ | 跨组（相隔 gap）移动可能让相等元素越过彼此，破坏相对顺序 |
| 5 | 147 为什么不能用值交换？ | 链表节点物理位置由指针决定——"值交换"会违反"改指针"的语义且可能产生环 |
| 6 | JDK 排序底层是什么？ | 基本类型双轴快排（DualPivotQuicksort，片段 < 47 切插入）；对象 TimSort（折半插入 + 归并） |
| 7 | 插入排序的空间为什么是 O(1)？ | 只需要一个 key 变量保存待插入元素，完全原地 |
