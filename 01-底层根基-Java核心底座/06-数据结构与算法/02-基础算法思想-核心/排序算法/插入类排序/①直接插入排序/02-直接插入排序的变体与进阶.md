## 1. 变体全景：三个优化方向

直接插入排序的瓶颈有两个：**定位慢**（顺序查找）与**移动多**（前驱逐个后移）。所有变体都是针对这两点：

| 变体 | 优化对象 | 手段 | 效果 |
|------|:---:|------|------|
| 折半插入排序 | 定位（比较） | 二分查找插入点 | 比较 O(n²) → O(n log n) |
| 2-路插入排序 | 移动 | 环形数组两端插入 | 移动约减半 |
| 表插入排序 | 移动 | 链表存储（无需物理移动） | 移动 O(n) |
| 希尔排序 | 全局 | 分组大步长预排序 | 总复杂度降至 O(n^1.3) 量级 |

> 🎯 **关键认知**：**"比较"和"移动"是两个独立的成本**——折半插入只降比较、移动不变，所以总复杂度仍是 O(n²)。真正突破 O(n²) 的是希尔排序（减少远距离移动）。

## 2. 折半插入排序：二分定位

### 2.1 原理

已排序区 `arr[0..i-1]` 是有序的 → 用**二分查找**定位插入点（第一个大于 key 的位置），再统一后移。

```java
/**
 * 折半插入排序
 * 比较: O(n log n)；移动: O(n²)（不变）→ 总 O(n²) 但常数更小
 */
public static void binaryInsertionSort(int[] arr) {
    int n = arr.length;
    for (int i = 1; i < n; i++) {
        int key = arr[i];
        // ① 二分定位：在 [0, i-1] 中找第一个 > key 的位置（插入点）
        int lo = 0, hi = i - 1;
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;
            if (arr[mid] <= key) lo = mid + 1;   // 相等也往右 → 稳定
            else hi = mid - 1;
        }
        // ② 统一后移 [lo, i-1] → [lo+1, i]
        for (int j = i - 1; j >= lo; j--) {
            arr[j + 1] = arr[j];
        }
        // ③ 插入
        arr[lo] = key;
    }
}
```

### 2.2 关键细节

```text
① 查找条件: arr[mid] <= key 时往右 —— 保证插入点在所有相等元素【之后】→ 稳定
② 移动不变: 后移次数与直接插入完全相同（最坏仍 n²/2 次）
③ 收益: 比较次数从 n²/4 降到 n log n → 总时间约减半（比较贵时收益明显）
④ 局限: key 为对象、比较函数昂贵（如字符串）时收益最大；基本类型比较便宜时收益有限
```

> 💡 面试表达："**折半插入把比较次数从 O(n²) 降到 O(n log n)，但移动次数不变，所以总复杂度仍 O(n²)**"——这句"既看到优化又看到局限"的回答是加分项。

## 3. 2-路插入排序：环形数组

### 3.1 原理

额外开一个**环形数组**（大小 2n），最小元素放中间，之后的元素插入时选择**左端或右端**（离哪端近插哪端），减少整体移动：

```text
环形数组语义:
  头指针 first、尾指针 final 指向已排元素的两端
  新元素若 < arr[first] → 插到左端（前移 first）
  新元素若 > arr[final] → 插到右端（后移 final）
  否则 → 在中间二分定位后局部移动
```

### 3.2 特点

| 维度 | 说明 |
|------|------|
| 空间 | O(n) 额外数组（从 O(1) 升级为 O(n)） |
| 移动 | 最好接近 0（数据两极端插入）、最坏 n²/2（仍不变） |
| 复杂度 | 仍 O(n²)，但平均移动约减半 |
| 应用 | 教材级优化，工程中很少用（空间代价换移动减半不划算） |

> ⚠️ **工程判断**：2-路插入是"空间换时间"的经典教学案例，但 O(n) 额外空间让它在实践中被归并排序（同样 O(n) 空间但 O(n log n) 时间）完全取代——**面试提及即可，强调"被归并取代"是成熟判断**。

## 4. 表插入排序：链式存储

### 4.1 原理

用静态链表（数组 + next 指针）存储，插入时**只改指针不改物理位置**：

```text
移动成本: 物理移动 O(n²) → 指针修改 O(1) × n 次 = O(n) 次修改
比较成本: 仍 O(n²)（顺序查找插入点）
总复杂度: 仍 O(n²)，但"移动"的定义从物理移动变为指针修改
```

### 4.2 工程对应

```text
表插入排序 = 链表的直接插入排序
→ 工程即 LeetCode 147 对链表进行插入排序（03 文件详讲）
→ 链式存储天然支持"插入"（无需搬移元素）
```

> 🎯 **洞察**：表插入排序揭示了插入排序的"存储无关性"——**只要支持 O(1) 的"插入"操作，插入排序框架就能用**。数组的插入要搬移元素（O(n)），链表的插入只改指针（O(1)）——这是 147 题链表插入排序比数组版快的结构性原因（比较仍 O(n²) 不变）。

## 5. 希尔排序：插入排序的规模化

### 5.1 核心思想

**远距离元素先排好（大步长分组插入），再逐步缩小步长到 1**：

```text
为什么能突破 O(n²):
  ① 大步长阶段: 元素跨越远距离快速到位 → 减少后续的远距离移动
  ② 小步长阶段: 数据已"基本有序" → 插入排序发挥 O(n) 适应性
  ③ 最后一趟步长 1 = 普通插入排序，但此时数据接近有序 → 总时间大幅下降

直观例子:
  [9, 8, 7, 6, 5, 4, 3, 2, 1]  （逆序）
  步长 4: 分组 (9,5,1)(8,4,2)... 各自插入 → 远距离元素先就位
  步长 1: 此时数组接近有序 → 插入排序 O(n) 完成
```

### 5.2 与直接插入排序的关系

| | 直接插入排序 | 希尔排序 |
|--|:---:|:---:|
| 步长 | 恒为 1 | 从大递减到 1 |
| 比较对象 | 相邻前驱 | 相隔 gap 的前驱 |
| 本质 | 一次插入排序 | **多次不同步长的插入排序** |
| 复杂度 | O(n²) | O(n^1.3) 量级（依步长序列） |
| 稳定性 | ✔ 稳定 | ✘ **不稳定**（跨组移动破坏稳定） |

> 💡 **希尔 = 插入排序的"分而治之"**：直接插入排序的问题在于"一次只能挪一步"，希尔用大步长让元素"跳"到大致位置，再用小步长微调。**理解希尔的关键是先吃透直接插入排序**——这也是本专题先建"①直接插入排序"再建"②希尔排序"的原因（兄弟目录已建，见 `插入类排序/②希尔排序（缩小增量排序）/`）。

## 6. 优化边界分析：哪些值得哪些不值得

### 6.1 优化收益矩阵

| 优化 | 空间代价 | 时间收益 | 工程价值 |
|------|:---:|------|:---:|
| 哨兵 | 0 | 比较时间减半 | ★★★★（零成本） |
| 提前终止检查 | 0 | 检测有序（收益不稳定） | ★★ |
| 折半插入 | 0 | 比较减半（比较贵时） | ★★★ |
| 2-路插入 | O(n) | 移动减半 | ★（被归并取代） |
| 希尔化 | 0 | 复杂度质变 O(n^1.3) | ★★★★★（但要稳定性时慎用） |

### 6.2 决策规则

```text
想要更快且保持稳定 → 折半插入（零空间代价）
想要质变提速、可接受不稳定 → 希尔排序
追求 O(n log n) 级稳定性 → 归并排序（不是插入变体）
小片段（n < 64）→ 直接插入就够（常数最小）
```

> ⚠️ **面试陷阱题**："插入排序有哪些优化？" 标准回答顺序：**哨兵（零成本）→ 折半插入（降比较）→ 希尔（质变）**，并主动指出"折半插入总复杂度仍 O(n²)（移动不变）"——全面且诚实。

## 7. 演化主线：从插入排序到 TimSort

### 7.1 完整演化链

```text
直接插入排序（O(n²)，稳定，适应）
   │
   ├─ 定位优化 → 折半插入（比较 O(n log n)）
   ├─ 移动优化 → 2-路插入 / 表插入（移动减半/指针化）
   └─ 规模化 → 希尔排序（O(n^1.3)，不稳定）
                  │
                  └─ 混合思维 → TimSort = 归并 + 插入
                      ├─ 短片段（< 64）用直接插入排序
                      ├─ 检测"天然有序段"（run）直接复用
                      └─ run 之间用归并合并 → O(n log n) + 适应性
```

### 7.2 TimSort 为什么选插入排序

```text
① 小片段用插入: 常数最小，n < 64 时比快排/归并都快
② 天然有序段: 插入排序的适应性 → 近乎有序数据 O(n)
③ 稳定性: 插入排序稳定 → 整个 TimSort 稳定（Python/Java 内置排序都要求稳定）

工程事实:
  Python 的 sorted / list.sort = TimSort
  Java 的 Arrays.sort(对象数组) / Collections.sort = TimSort（改进版）
  → "插入排序没用"的论点在 TimSort 面前不攻自破
```

> 🎯 **核心要点**：变体专题的验收 = **一条主线 + 三个判断**。主线：**"定位更快的折半插入、移动更少的 2-路/表插入、规模化的希尔、混合化的 TimSort"**——一条从 O(n²) 到 O(n log n) 的演化链。判断：① 折半插入总复杂度不变（移动是瓶颈）；② 2-路插入被归并取代（空间不划算）；③ 希尔失去稳定性（跨组移动）。**能把这条演化链讲清楚，排序专题的深度就有了**——尤其是 TimSort 选择插入排序的三大理由（常数小、适应性、稳定）是工程面试的高分故事。
