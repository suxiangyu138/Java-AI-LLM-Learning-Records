## 1. 扑克牌模型：从生活直觉到算法

### 1.1 算法就是打扑克

整理手中扑克牌的过程就是直接插入排序：

```text
① 手里已经整理好的牌 = 已排序区（初始 = 第一张）
② 摸起一张新牌 = 待插入元素
③ 从右往左与手中的牌比较 → 找到合适位置
④ 比新牌大的牌依次后移 → 腾出位置
⑤ 插入新牌 → 已排序区长度 +1
⑥ 重复直到所有牌整理完
```

### 1.2 算法要素

```text
已排序区: arr[0 .. i-1]（初始只有 arr[0]）
未排序区: arr[i .. n-1]
每趟: 取 arr[i]，在已排序区中找到位置并插入
共 n−1 趟（第 2 个元素到第 n 个元素各插入一次）
```

> 🎯 **核心动作三连**：**取出（key = arr[i]）→ 前驱后移（arr[j+1] = arr[j]）→ 插入（arr[j+1] = key）**。"边比较边移动"意味着比较和移动在同一趟内完成，这正是它与选择排序（先找后换）的本质区别。

## 2. 基本实现：两个版本

### 2.1 标准版（教材版，最常手写）

```java
/**
 * 直接插入排序（标准版）
 * 时间 O(n²)，空间 O(1)，稳定
 */
public static void insertionSort(int[] arr) {
    int n = arr.length;
    for (int i = 1; i < n; i++) {          // ① 从第 2 个元素开始
        int key = arr[i];                  // ② 取出待插入元素（备份！）
        int j = i - 1;
        while (j >= 0 && arr[j] > key) {   // ③ 从后往前找位置（严格大于才移动）
            arr[j + 1] = arr[j];           // ④ 前驱后移腾位
            j--;
        }
        arr[j + 1] = key;                  // ⑤ 插入正确位置
    }
}
```

### 2.2 哨兵版（数组下标从 1 开始）

```java
/**
 * 直接插入排序（哨兵版）
 * 哨兵 arr[0]：保存副本 + 监视越界，省去 j>=0 判断
 */
public static void insertionSortSentinel(int[] arr, int n) {
    // 约定: arr[1..n] 是待排序数据，arr[0] 留作哨兵
    for (int i = 2; i <= n; i++) {
        arr[0] = arr[i];                   // ① 哨兵 = 待插入元素（副本）
        int j = i - 1;
        while (arr[j] > arr[0]) {          // ② 无需 j>=0：j=0 时 arr[0]==arr[0] 恒不成立，自动停
            arr[j + 1] = arr[j];           // ③ 前驱后移
            j--;
        }
        arr[j + 1] = arr[0];               // ④ 插入
    }
}
```

> 💡 **为什么哨兵能省判断**：当 j 减到 0 时，`arr[0]` 与自己比较 `arr[0] > arr[0]` 恒为假，循环自然终止——**用一次必然失败的比较替代了边界判断**。每趟省 1 次判断 × n 趟，对大规模数据节约可观（教材称比较时间减少约一半）。

## 3. 逐步推演：n=5 全流程

**数据**：[5, 2, 4, 6, 1]（升序排序）

| 趟 | 待插入 | 已排序区（变化） | 移动次数 | 说明 |
|:---:|:---:|------|:---:|------|
| 初始 | — | [5] \| [2,4,6,1] | 0 | 第 1 个元素自成一区 |
| 1 | 2 | [2,5] \| [4,6,1] | 1 | 2 < 5 → 5 后移，2 插到最前 |
| 2 | 4 | [2,4,5] \| [6,1] | 1 | 5 > 4 后移，2 < 4 停 → 插入 |
| 3 | 6 | [2,4,5,6] \| [1] | 0 | 6 > 5 不动，原地插入 |
| 4 | 1 | [1,2,4,5,6] | 4 | 全部后移，1 插到最前 |

```text
推演关键:
  第 3 趟（6）→ 移动 0 次 —— 数据有序时每趟只比较 1 次，这就是 O(n) 的来源
  第 4 趟（1）→ 移动 4 次 —— 逆序时每趟移动到底，这就是 O(n²) 的来源
```

> 🎯 **从推演看复杂度直觉**：插入排序的工作量 = 每个元素"越过多少个比自己大的前驱"。**数据有序 → 没人要越过 → O(n)；数据逆序 → 都要越过到底 → O(n²)**。这个直觉比背公式重要。

## 4. 哨兵优化：省去边界判断

### 4.1 哨兵的两个作用

```text
作用一（保存副本）: 后移过程中 arr[i] 会被覆盖，哨兵先备份
作用二（监视越界）: j 减到 0 时用"自己和自己比较"自然终止
                  → 循环内不再需要 j >= 0 判断
```

### 4.2 性能对比

| 版本 | 内层循环条件 | 每趟判断次数 | 适用 |
|------|------------|:---:|------|
| 标准版 | `j >= 0 && arr[j] > key` | 2 次（边界 + 比较） | 数组从 0 开始（Java 默认） |
| 哨兵版 | `arr[j] > arr[0]` | 1 次（仅比较） | 数组从 1 开始（教材/考试） |

> ⚠️ **面试提示**：手写时先用标准版（数组天然从 0 开始），被追问"怎么优化"再讲哨兵版——**主动引出哨兵并说清"省去边界判断"是加分项**。注意 Java 手写哨兵版需要把数组整体右移一位（arr[0] 留空），实际工程中少用，但软考/考研必考。

### 4.3 其他微优化

```text
① 提前终止: 某趟比较 0 次（key >= 已排序区末尾）→ 后面元素也可能已有序？
   ❌ 不能提前终止——但可检测：若连续若干趟都无需移动，说明接近有序（工程启发）
② 局部性: 数据在内存中连续访问 → 缓存友好（插入排序被低估的原因之一）
③ 批量移动: 找位置与移动分离（折半插入）→ 02 文件
```

## 5. 复杂度推导：最好/平均/最坏

### 5.1 精确计数（第 i 趟）

```text
设第 i 趟插入时，前 i-1 个元素已有序，
dj = 已排序区中比 key 大的元素个数（即需要移动的个数）

比较次数 = dj + 1（多比一次发现位置）
移动次数 = dj + 2（后移 dj 次 + 取出 1 次 + 插入 1 次）
```

### 5.2 三情形汇总

| 情形 | 每趟 dj | 总比较 | 总移动 | 总复杂度 |
|------|:---:|:---:|:---:|:---:|
| 最好（已有序） | 0 | n−1 | 2(n−1) | **O(n)** |
| 平均（随机） | (i−1)/2 | n²/4 | n²/4 | **O(n²)** |
| 最坏（逆序） | i−1 | n²/2 | n²/2 | **O(n²)** |

```text
最坏推导（逆序）:
  第 i 趟比较 i 次、移动 i+1 次
  Σ(i) = n(n-1)/2 ≈ n²/2 次比较
  → O(n²)

最好推导（有序）:
  每趟只比较 1 次（arr[i-1] > key 不成立）、移动 2 次
  → n−1 次比较 → O(n)
```

> 🎯 **面试必答句**："插入排序最好 O(n)（数据有序）、最坏 O(n²)（逆序）、空间 O(1)、稳定。**它是 O(n²) 家族中唯一具有适应性的算法**——数据越有序越快，这是它被 TimSort 选作子算法的原因。"

## 6. 稳定性证明

### 6.1 证明

```text
内层循环条件: arr[j] > key（严格大于才移动）

当遇到与 key 相等的元素时:
  arr[j] == key → 不满足 > 条件 → 循环停止
  → key 被插入到相等元素的【后面】

相等元素的相对顺序在排序前后保持不变 → 稳定 ✔
```

### 6.2 如果不带等号会怎样

```java
// ❌ 错误：arr[j] >= key 会把相等元素换到前面 → 不稳定
while (j >= 0 && arr[j] >= key) { ... }
```

> ⚠️ **稳定性考点**：稳定排序的通用判据 = "**内层循环用严格大于/严格小于，相等时停止**"。插入排序、冒泡、归并都是这个模式；快排、堆排、选择排序做不到。面试被问"哪些排序稳定"——答"冒泡、插入、归并、基数"并解释插入的机制。

## 7. 与冒泡/选择排序对比

### 7.1 三表对比

| 维度 | 插入排序 | 冒泡排序 | 选择排序 |
|------|:---:|:---:|:---:|
| 最好复杂度 | O(n) | O(n) | **O(n²)**（不适应性！） |
| 平均/最坏 | O(n²) | O(n²) | O(n²) |
| 稳定性 | ✔ 稳定 | ✔ 稳定 | ✘ 不稳定 |
| 适应性 | ✔ 越有序越快 | ✔ 越有序越快 | ✘ 与数据无关 |
| 交换次数 | O(n²)（移动） | O(n²)（交换） | **O(n)**（最少） |
| 常数因子 | 最小 | 最大（交换 3 次赋值） | 中 |
| 实际速度（n 小） | 最快 | 最慢 | 居中 |

### 7.2 各自的独特价值

```text
插入排序: 综合最优——稳定 + 适应 + 常数小（小数组与近乎有序的王者）
冒泡排序: 唯一优势是教学直观（可加"提前终止"优化，检测有序）
选择排序: 唯一优势是交换次数 O(n)（写操作少的场景：大对象数组、闪存写入）

面试选型题标准答案:
  "n 小或近乎有序 → 插入排序；
   写操作昂贵（大对象）→ 选择排序；
   其余情况两个都不选，直接 O(n log n) 的归并/快排/堆排。"
```

> 🎯 **核心要点**：直接插入排序通关四件事——**① 扑克牌模型讲清"取出→后移→插入"三连**；**② 标准版 + 哨兵版都能默写**（哨兵省边界判断，比较时间减半）；**③ 复杂度从"每趟越过多少前驱"推导**（有序 O(n)、逆序 O(n²)）；**④ 稳定性靠"严格大于才移动"保证**。它是最简单却最有工程价值的 O(n²) 排序——**小数组最快、近乎有序最快、TimSort 的基石**，这三点是面试故事的灵魂。
