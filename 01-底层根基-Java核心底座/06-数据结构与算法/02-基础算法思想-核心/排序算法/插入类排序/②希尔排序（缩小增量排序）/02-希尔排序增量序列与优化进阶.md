## 1. 增量序列全景：六大经典序列

### 1.1 序列总表

| 序列 | 构造公式 | 示例 | 提出 |
|------|------|------|:---:|
| Shell 原始 | n/2^k 递减 | 8, 4, 2, 1 | 1959 |
| Knuth | (3^k − 1)/2（h = 3h + 1） | 1, 4, 13, 40, 121, 364 | 1973 |
| Hibbard | 2^k − 1 | 1, 3, 7, 15, 31, 63 | 1963 |
| Sedgewick | 双公式交错（见下） | 1, 5, 19, 41, 109, 209, 505, 929, 2161… | 1986 |
| Ciura | 实验搜索 + 表内递推 | 1, 4, 10, 23, 57, 132, 301, 701, 1750 | 2001 |
| Tokuda | ⌈(9·(9/4)^(k−1) − 4)/5⌉ | 1, 4, 9, 20, 46, 103, 233, 525, 1182… | 1992 |

### 1.2 关键序列详解

```text
① Shell 原始（n/2, n/4, …, 1）: 1959 年论文原版
   → 全偶增量 + 等比 2 倍陡降 → 最坏 Θ(n²)，只作教学演示

② Knuth（(3^k−1)/2）: h = 3h + 1 递推，教学/竞赛首选
   → 相邻增量接近 3 倍，下降平缓且互质 → 最坏 O(n^3/2)

③ Hibbard（2^k−1）: 最坏 O(n^3/2)（有理论证明）
   → 与 Knuth 同阶，实现稍麻烦，教学一般用 Knuth 替代

④ Sedgewick（1986，最坏 O(n^4/3)）: 由两个公式交错生成
   公式 A: 9·4^k − 9·2^k + 1  → 1, 19, 109, 505, 2161…
   公式 B: 4^k − 3·2^k + 1    → 5, 41, 209, 929, 3905…
   交错合并 → 1, 5, 19, 41, 109, 209, 505, 929, 2161, 3905, 8929…
   → 理论最坏 O(n^4/3) ≈ O(n^1.33)，平均实证 ≈ O(n^7/6) ≈ O(n^1.16)
   → 大数据、通用算法库首选（理论保障 + 实践高效）

⑤ Ciura（2001，实验搜索）: 1, 4, 10, 23, 57, 132, 301, 701, 1750
   → 对中小规模（n ≤ 10⁴）实测最快，无理论证明
   → 表内项用尽后按 ×2.25 递推估算后续项

⑥ Tokuda（1992）: 公式简洁、生成容易，实测接近 Ciura
   → 2026 年首次获得非平凡最坏下界证明（见第 4 节）→ 理论补全
```

> 🎯 **一句话记忆**："**教学用 Knuth，小数据用 Ciura，大数据用 Sedgewick，永远别用 n/2**"——四句话覆盖全部选型场景。

## 2. 复杂度对比与选型

### 2.1 复杂度对比表

| 序列 | 最坏 | 平均（实证） | 理论证明 | 实用评价 |
|------|:---:|:---:|:---:|------|
| Shell 原始 | Θ(n²) | — | ✔ 有 | 避免（奇偶隔离） |
| Knuth | O(n^3/2) | ≈O(n^1.5) | ✔ 有 | 教学首选 |
| Hibbard | O(n^3/2) | — | ✔ 有 | 理论课代表 |
| Sedgewick | O(n^4/3) | ≈O(n^7/6) | ✔ 有 | 大数据通用库 |
| Ciura | 未证明 | 实测最快 | ✘ 无 | n ≤ 10⁴ 首选 |
| Tokuda | ≥ Ω(n^1.2695)（2026） | 接近 Ciura | ✔ 2026 补齐 | 有下界保证 |
| Pratt（2^p·3^q） | O(n log²n) | — | ✔ 有 | 理论最优之一，但增量个数 O(log²n) 太多，n 大时不实用 |

### 2.2 选型建议（n=5000 随机数组相对耗时参考）

| 场景 | 推荐 | 说明 |
|------|------|------|
| 教学/竞赛手写 | Knuth | 公式简单、代码好写、最坏有界 O(n^3/2) |
| 中等规模（n ≤ 10⁴） | Ciura | 实测最快（相对耗时约 15% 基准） |
| 大数据/通用库 | Sedgewick | 理论保障 + 实践高效（相对耗时约 20% 基准） |
| 任何场景 | ❌ Shell 原始 | 全偶增量退化（相对耗时 100% 基准） |

> 💡 相对耗时数据为经验对比（基准 = Shell 原始序列）：Ciura 约 15%、Sedgewick 约 20%、Hibbard 约 35%、Knuth 约 40%——**增量序列的选择可以带来数倍差距，这就是"序列决定命运"的实证**。

## 3. 好增量序列的黄金标准

| # | 标准 | 原因 | 反例 |
|:---:|------|------|------|
| 1 | **最后一增量必须为 1** | 只有 gap=1 才是完整插入排序，保证正确性 | 序列不含 1 → 结果可能未排序 |
| 2 | **增量间尽量互质（避免整除）** | 可整除的增量（如 8,4,2,1）会形成"组合盲区"——某些位置的元素对在所有轮次中都不被比较 | 8,4,2,1 奇偶隔离 |
| 3 | **下降不要过快** | n/2 等比陡降 → 每轮几乎"白跑"（无远距离收益）或组内过小 | n/2^k（2 倍陡降） |
| 4 | **下降也不宜过慢** | 轮次太多 → 常数开销大 | 每次只减 1（退化为插入排序） |
| 5 | **有理论或实验支撑** | Sedgewick 有理论最坏界、Ciura 有大量实验验证 | 随意自造序列 |
| 6 | **序列长度适中** | Pratt（2^p·3^q）理论最优但需 O(log²n) 个增量，实际轮次太多 | 2^p·3^q 全列 |

> 🎯 **判断口诀**："**递减到 1、尽量互质、下降平缓、有据可依**"——十六条准则里前两条是正确性的底线（保证完成与防盲区），后两条是性能的保证。

## 4. 2025-2026 最新进展：下界证明与序列改进

### 4.1 2025：TCS 论文——期望复杂度 O(n log²n) 的尝试（有争议）

2025 年 4 月发表于 *Theoretical Computer Science*（Shengrong Hu）：

```text
贡献: 提出改进增量序列 h₁ = 1，hᵢ₊₁ = αhᵢ + β（0 ≤ β ≤ 1）
方法: 对关键比较/移动次数做"稳定性拟合"（stability fitting），
      结果形如 cn·ln(n) + d·n^λ·ln(n)，λ < 1 → 期望 O(n log²n)
注意: 作者本人也承认结论"likely controversial"——
      此前从未有报告过 O(n log²n) 的希尔排序，需同行验证
```

> ⚠️ 面试提及分寸："2025 年有论文声称特定增量序列可达期望 O(n log²n)，但作者自述有争议、未获公认——**希尔排序复杂度能否做到 O(n log n) 仍是开放问题**。" 这个"既知道新进展、又知道不靠谱"的表述最加分。

### 4.2 2026：Tokuda 序列的非平凡下界证明（arXiv:2607.08997）

2026 年预印本（Zhenghan Zang）提出了参数化映射/势函数分析框架，绕开传统 Frobenius 硬币问题方法在计算上的瓶颈：

```text
① 主要结果: Tokuda 序列最坏复杂度 ≥ Ω(N^1.2695…)
   → 首次为"实用且经验调优"的增量序列单独证明非平凡下界
② 一般化: 任何严格递减、各项位于有理几何比 a/b（互质，a > b > 1）
   固定距离内的增量序列，最坏 ≥ Ω(N^(1 + (log_b a − 1)/(2 log_b a − 1)))
③ 整数比情形: 各项在整数公比等比序列有界距离内的序列 → 最坏 ≥ Ω(N^3/2)
   （推广了 Pratt 的经典结果）
④ 最优序列的结构: 达到 Ω(N^1.26) 最坏界的序列，其项必须达到
   Ω(N/(log log N)^c) 量级，且满足涉及 log N / log log N 的密度约束
```

### 4.3 2026：Ciura 序列 25 年来首次被超越

2026 年 1 月，Bryan Banner 用进化算法搜索出首个平均表现超过 Ciura（2001）的增量序列：

```text
新序列: [1, 4, 10, 23, 57, 132, 301, 701, 1577, 3524, 7705, 17961,
        40056, 94681, 199137, 460316, 1035711, 3236462]
成绩: 平均减少 0.52% 比较次数；规模越大优势越明显——
      1M 元素 +0.37%、8M 元素 +0.57%（对 Ciura/Tokuda/Sedgewick 等基线）
```

### 4.4 意义：复杂度仍是开放问题

```text
① 下界与上界仍有鸿沟: 已知最好最坏上界 O(n^4/3)（Sedgewick 类），
   而一般序列下界研究（2026）刚到 Ω(n^1.2695) 量级
② 最优增量序列（同时最优最坏与平均）不存在已知构造
③ 2025-2026 的活跃论文证明这个 1959 年的算法仍在被研究——
   "一个 67 岁算法的复杂度问题还没解决"本身就是最好的面试谈资
```

> 🎯 **2026 谈资版**："希尔排序的复杂度是最古老的开放问题之一——2025 年 TCS 有人声称期望 O(n log²n)（有争议），2026 年 arXiv 首次证明了 Tokuda 序列的最坏下界 Ω(n^1.2695)，同月进化算法搜索出了 25 年来第一个超越 Ciura 的序列。**下界和上界之间的鸿沟依旧巨大。**"

## 5. 实现优化：移动替代交换与细节

### 5.1 用"移动"代替"交换"（最重要的实现优化）

```text
错误写法（交换版）: 组内每步做 swap(a[j], a[j-gap]) —— 每次 3 次赋值
正确写法（移动版）: key 备份后，逐位"后移覆盖"，最后一次性插入 —— 平均 1.5 次赋值/步
差距: 交换版比移动版慢约 3 倍（01 文件的实现即移动版）
```

### 5.2 增量序列的生成方式

| 方式 | 优点 | 缺点 | 适用 |
|------|------|------|------|
| 运行时递推（Knuth 式） | 不占内存、任意 n 自适应 | 序列质量固定 | 教学/竞赛 |
| 预置表 + 递减取用（Ciura 式） | 直接用最优已知序列 | 超表范围需估算递推 | 工程（n ≤ 10⁴） |
| 运行时计算 Sedgewick 双公式 | 理论有界 + 自适应 | 代码略长 | 大数据 |

### 5.3 其他实现细节

```text
① 组内提前终止: 某组某趟无移动 → 该组可提前结束（收益小，代码复杂度上升，一般不做）
② 逆序比较方向: 升序排序时组内从后往前比较（j -= gap），与插入排序一致
③ 缓存局部性: 组内访问地址相隔 gap，gap 大时缓存命中率低于直接插入排序
   （这是希尔常数因子稍大的原因之一，但 gap 变小时局部性恢复）
```

> ⚠️ 面试陷阱题："希尔排序有什么优化？" 标准回答顺序：**① 换更好的增量序列（收益最大）→ ② 移动替代交换（~3 倍）→ ③ 组内提前终止（收益小）**。与插入排序的优化清单（哨兵/折半）形成对比——**希尔的优化重心在序列，不在循环细节**。

## 6. 工程价值与局限

### 6.1 为什么 JDK 不用希尔排序

| 原因 | 说明 |
|------|------|
| 无严格 O(n log n) 保证 | 库排序必须最坏有界（快排退化的补救在 JDK 中也存在，但希尔连平均都不能保证） |
| 不稳定 | Java 对象排序要求稳定（TimSort 的硬约束） |
| 常数因子不占优 | 多轮循环开销 + 大 gap 时缓存不友好 |
| 替代品更强 | TimSort（稳定 + 自适应 + O(n log n)）/ 双轴快排（原地 + 常数小） |

### 6.2 希尔排序仍然有用的场景

| 场景 | 为什么是希尔 |
|------|------|
| 嵌入式/内存受限设备 | O(1) 空间、无递归栈、代码极简（几十行 C） |
| 中等规模数据（n ≤ 10⁴） | Ciura 序列实测效率高，常数优势明显 |
| 教学 | "增量序列如何影响复杂度"的最佳教材案例 |
| 硬件/特殊环境 | 无动态内存、无栈的约束环境（部分 GPU/固件场景） |

> 💡 定位总结："**库排序追求最坏有界 + 稳定 → 希尔出局；受限环境追求极简 + 原地 + 够快 → 希尔入选**。" 工程上它不是主角，但从来不是废物——这是面试需要传递的分寸感。

## 7. 演化主线：插入 → 希尔 → 混合排序

### 7.1 完整演化链

```text
直接插入排序（O(n²)，稳定，适应性）
   │
   ├─ 规模化（1959）→ 希尔排序（分组插入，亚二次，不稳定）
   │                    │
   │                    ├─ 增量序列研究至今活跃（2025-2026 论文不断）
   │                    └─ 嵌入式/受限环境仍在使用
   │
   └─ 混合化（2002）→ TimSort = 归并 + 插入
        ├─ 短片段用直接插入（常数最小）
        ├─ 检测天然有序段（run）复用
        └─ run 之间归并 → O(n log n) + 稳定 + 自适应
```

### 7.2 希尔排序的历史地位

```text
① 1959 年: 第一个让插入排序"规模化"的算法——O(n²) 时代的重要突破
② 思想遗产: "大步先到位、小步再精修"的渐进思想，
   与归并排序的"先分割后合并"并列成为排序设计的两种基本模式
③ 学术遗产: 复杂度随增量序列变化 → 引出一整类组合数学问题
   （硬币问题、势函数分析），至今是算法理论的研究样本
④ 工程遗产: 在主流库排序中被取代，但在受限环境中继续服役
```

> 🎯 **核心要点**：进阶专题的验收 = **一条主线 + 两个判断 + 一段谈资**。主线："**Knuth 教学 → Sedgewick 有界 → Ciura 实测最快 → 2026 新序列**"的序列演化。判断：① 希尔的优化重心在**增量序列**而非循环细节；② 工程上"无严格 O(n log n) + 不稳定"让它退出主流库，但"O(1) 空间 + 极简"让它在受限环境保留。谈资：**2025 TCS 的 O(n log²n) 声称（有争议）、2026 Tokuda 下界 Ω(n^1.2695) 证明、2026 首个超越 Ciura 的进化序列**——一个 67 岁算法仍然活跃，这就是深度。
