## 1. 分组插入模型：从"一步一挪"到"跳跃就位"

### 1.1 问题：直接插入排序"一次只能挪一步"

逆序数组中，最右端的最小元素要一格一格挪到最前面——每趟移动 1 位，**远距离逆序对的消除成本极高**，这正是直接插入排序 O(n²) 的根源。

### 1.2 解法：间隔 gap 的元素为一组

```text
gap = 4 时分组（n = 8）:
  组 1: 下标 0, 4       组 2: 下标 1, 5
  组 3: 下标 2, 6       组 4: 下标 3, 7
  → 每组内做插入排序（组内元素间隔 4，一步移动 4 位）

gap 递减: 4 → 2 → 1
  每轮分组不同 → 前一轮就位的元素在下一轮重新参与比较
  gap = 1 时 = 普通直接插入排序（但此时数组已基本有序）
```

### 1.3 算法要素

```text
增量序列: gap = n/2, n/4, …, 1（递减到 1 保证最终正确）
每趟: 对 gap 个子序列各做一次插入排序（组间交叉完成）
共: log₂n 趟（n/2 序列）或按增量序列长度而定
核心收益: 元素每步可移动 gap 个位置 → 远距离逆序对快速消除
```

> 🎯 **核心动作**：**"分组（间隔 gap）→ 组内插入排序 → gap 减半"** 循环。与直接插入排序的唯一区别是：比较/移动的"邻居"从相隔 1 变成相隔 gap。**理解这点，希尔排序的代码就是插入排序换个步长。**

## 2. 基本实现：n/2 递减版（30 秒默写）

### 2.1 完整代码

```java
/**
 * 希尔排序（Shell Sort / 缩小增量排序）基础版
 * 增量序列: n/2, n/4, …, 1
 * 时间: 最好 O(n log n) / 最坏 O(n²)  空间: O(1)  稳定性: 不稳定
 */
public static void shellSort(int[] arr) {
    int n = arr.length;
    for (int gap = n / 2; gap > 0; gap /= 2) {      // ① 增量递减: n/2 → n/4 → … → 1
        for (int i = gap; i < n; i++) {             // ② 从 gap 开始逐元素处理（组间交叉）
            int key = arr[i];                       // ③ 取出待插入元素（组内: i, i-gap, i-2gap…）
            int j = i;
            while (j >= gap && arr[j - gap] > key) {// ④ 组内从后往前找位置（严格大于才移动）
                arr[j] = arr[j - gap];              // ⑤ 组内前驱后移（每次移动 gap 格）
                j -= gap;
            }
            arr[j] = key;                           // ⑥ 插入
        }
    }
}
```

### 2.2 为什么是三层循环

```text
外层: gap 递减（增量序列）
中层: i 从 gap 到 n−1 —— 看似"全体元素"，实为"各组交叉插入":
      当 i = gap   时处理组 1 的第 2 个元素
      当 i = gap+1 时处理组 2 的第 2 个元素
      当 i = 2gap  时处理组 1 的第 3 个元素 …
      → 各组插入排序在同一次扫描中交叉完成，无需按组分别扫描
内层: 组内插入（j 每次减 gap，相当于插入排序中的 j--）
```

> 💡 **记忆技巧**：希尔排序 = 直接插入排序的"三处改动"——① 外层加 gap 循环；② `i = 1` 改 `i = gap`；③ `j >= 0` 改 `j >= gap`、`j--` 改 `j -= gap`。**会写直接插入排序就能 30 秒改出希尔排序。**

## 3. 逐步推演：n=8 全流程

**数据**：[9, 8, 7, 6, 5, 4, 3, 2]（升序排序），增量序列 4 → 2 → 1

| 轮 | gap | 分组 | 组内排序结果 | 数组状态 |
|:---:|:---:|------|------|------|
| 初始 | — | — | — | [9,8,7,6,5,4,3,2] |
| 1 | 4 | (0,4)(1,5)(2,6)(3,7) | (9,5)→(5,9)；(8,4)→(4,8)；(7,3)→(3,7)；(6,2)→(2,6) | [5,4,3,2,9,8,7,6] |
| 2 | 2 | 偶(0,2,4,6)、奇(1,3,5,7) | 偶组 [5,3,9,7]→[3,5,7,9]；奇组 [4,2,8,6]→[2,4,6,8] | [3,2,5,4,7,6,9,8] |
| 3 | 1 | 全体 | 整体插入排序（已接近有序，移动很少） | [2,3,4,5,6,7,8,9] |

**单组推演示例（第 1 轮组 1，gap=4）**：

```text
组内元素: 下标 0 = 9，下标 4 = 5
① 取 key = 5（arr[4]）
② j = 4：arr[0] = 9 > 5 → 9 后移到下标 4（arr[4] = 9）
③ j = 0 < gap(4) → 停
④ 插入: arr[0] = 5 → 组内变为 [5, 9]

效果: 5 从下标 4 一步跳到下标 0 —— 直接插入排序需要 4 步，希尔只需 1 步
```

> 🎯 **从推演看收益**：第 1 轮后所有"大数"（9,8,7,6）集中到右半区、小数到左半区——**大跨步移动让每个元素以几何级数速度接近最终位置**。第 3 轮（gap=1）时数组已基本有序，插入排序发挥 O(n) 适应性收尾。逆序数组 [9..2] 直接插入需约 n²/2 次移动，希尔只需少量。

## 4. 复杂度推导：最好/平均/最坏

### 4.1 最好情形 O(n log n)

```text
数据已有序时: 每轮每组只需比较 1 次（key 与组内最后一个元素比较后即停）
每轮比较次数 ≈ n − gap；总比较 ≈ Σ(n − gap) ≈ n·log₂n（n/2 序列共 log₂n 轮）
→ 最好 O(n log n)
```

### 4.2 平均与最坏：取决于增量序列

```text
平均: 依增量序列的"组合覆盖能力"——不同轮次的分组形成不同的元素对
      已被证明（Sedgewick 1986）: Sedgewick 序列平均 O(n^7/6)、最坏 O(n^4/3)
      经验常记: ≈ O(n^1.3)

最坏: Shell 原始序列（n/2 递减）最坏 Θ(n²)——全偶增量 → 奇偶下标的元素
      直到 gap=1 才相互比较，对特定构造数组前几轮几乎无效果，最后一轮接近
      完整插入排序（最坏构造例较精巧，见 Sedgewick《算法》，不必背诵）
```

### 4.3 逆序数视角：为什么能突破 O(n²)

```text
直接插入排序的工作量 = 数组逆序对数量 I（最坏 ~n²/4）
希尔排序的核心贡献: 每轮大幅消灭"远距离逆序对"——
  ① gap 大时: 一步移动 gap 格，一次插入消除多个逆序对
  ② 下一轮 gap 减半: 远距离逆序已消除，剩余逆序对距离减半 → 工作量大减
  ③ 最后一轮: 数组接近有序 → 逆序对已降到 O(n) → 插入排序 O(n)

为什么不是简单的"跑 log₂n 遍插入排序":
  每轮都在"缩小逆序对距离"，工作量逐轮几何级数下降，
  而不是每轮都满负荷 O(n²)
```

> 🎯 **面试必答句**："希尔排序最好 O(n log n)（数据有序），最坏依增量序列 O(n^3/2)~O(n²)，平均约 O(n^1.3)（Sedgewick 序列实证）；空间 O(1)；**不稳定**。本质是多次不同步长的插入排序——用大跨步移动消除远距离逆序，复杂度由增量序列决定。"

## 5. 与直接插入排序对比

| 维度 | 直接插入排序 | 希尔排序 |
|------|:---:|:---:|
| 步长 | 恒为 1 | 从大递减到 1 |
| 比较对象 | 相邻前驱 | 相隔 gap 的前驱 |
| 一趟移动距离 | 1 格 | gap 格 |
| 时间复杂度 | 最坏 O(n²)（无逃生口） | 最坏 O(n^3/2)~O(n²)（依序列） |
| 空间复杂度 | O(1) | O(1) |
| 稳定性 | ✔ 稳定 | ✘ 不稳定 |
| 常数因子 | 最小 | 稍大（多轮开销） |
| 适用 | 小数组/近乎有序 | 中等规模（n ≤ 10⁴）通用 |

**本质关系**：希尔排序 = 直接插入排序的"分治版"——**直接插入排序一次只能挪一步，希尔排序用大步长让元素先"跳"到大致位置，再用小步长微调**。gap=1 时两者完全等价。

> 💡 面试表达："**希尔排序不是与插入排序并列的另一种算法，而是插入排序的规模化版本**——gap 从大到小多次分组插入，最后一趟就是普通插入排序。它的复杂度突破来自大跨步消除远距离逆序对。"

## 6. 稳定性分析：为什么不稳定（含反例）

### 6.1 组内稳定，全局不稳定

```text
组内: 插入排序用"严格大于才移动"→ 组内相等元素保持相对顺序（组内稳定）
跨组: 元素可能"跳过"其他组的相等元素而不比较 → 全局不稳定
```

### 6.2 反例演示（gap=2 → gap=1）

**数据**：[2, 1, 4, 7, 5a, 5b]（5a 在 5b 之前，两者相等）

| 轮 | gap | 操作 | 数组状态 |
|:---:|:---:|------|------|
| 初始 | — | — | [2, 1, 4, 7, 5a, 5b] |
| 1 | 2 | 奇数组(1,3,5)：[1,7,5b] → [1,5b,7] | [2, 1, 4, 5b, 5a, 7] |
| 2 | 1 | 整体插入排序（严格大于才移动） | [1, 2, 4, 5b, 5a, 7] |

**结果**：5b 跳到了 5a 前面——**两个相等元素的相对顺序被逆转**。

```text
逆转机制: 第 1 轮中 5b 从下标 5 一步跳到下标 3，
          跳过了下标 4 的 5a（不同组、不比较）
          → 相对顺序在"跳跃"中翻转
          gap=1 轮本身是稳定的，但它只是"固化"了已被打乱的顺序
```

> ⚠️ **稳定性考点**：稳定排序口诀"冒插归基"里没有希尔——**希尔的稳定性反例是面试常考题**。表述要点：组内稳定但"跨组跳跃"会跳过相等元素，一旦顺序被翻转，后面的轮次（包括最后的 gap=1）都不会再恢复它。

## 7. 手写易错点与调试技巧

| # | 易错点 | 正确写法 | 后果 |
|:---:|------|------|------|
| 1 | 内层条件写成 `j >= 0` | `j >= gap` | 数组越界（j 会减到负数） |
| 2 | 步长写成 `j--` | `j -= gap` | 变成普通插入排序，失去分组意义 |
| 3 | 忘记 `key = arr[i]` 备份 | 先备份再移动 | 移动时覆盖待插入值 |
| 4 | 外层从 `gap = n` 起 | `gap = n / 2` | 第一轮 i=gap=n 空转或越界 |
| 5 | 用 `arr[j-gap] >= key` | `arr[j-gap] > key` | 组内不稳定（全局本就不稳定） |
| 6 | 增量序列不含 1 | 最后必须 gap=1 | 无法保证排序完成 |

**调试技巧**：

```text
① 小样本验证: n=8 随机数组 + 打印每轮后的数组状态（对照本文件推演表）
② 断言验证: 排序完成后 assert 数组升序（增量序列含 1 时必有序）
③ 计数验证: 统计比较/移动次数，观察"远距离移动"的分布——
   gap 大时单次移动距离长，这是希尔收益的来源
```

> 🎯 **核心要点**：希尔排序通关四件事——**① 理解"分组插入"模型**（间隔 gap 一组，大跨步就位）；**② 30 秒默写 n/2 基础版**（就是插入排序改三处：加 gap 循环、i=gap、j-=gap）；**③ 复杂度讲清"依增量序列而定"**（最好 O(n log n)、最坏 O(n²)~O(n^3/2)）；**④ 稳定性反例张嘴就来**（5b 跳过 5a）。**"会写插入排序就会写希尔排序"是它最大的优点——这也是它作为插入类排序压轴的原因。**
