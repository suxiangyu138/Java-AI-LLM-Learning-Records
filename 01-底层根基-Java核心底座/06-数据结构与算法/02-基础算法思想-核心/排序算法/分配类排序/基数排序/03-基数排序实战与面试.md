## 1. 164. 最大间距（桶排序版）

### 1.1 题目与思路

```
无序数组排序后相邻元素最大差值（要求 O(n)）
⚠️ 排序被禁（O(n log n)）→ 桶排序/基数排序

桶排序版关键定理：
  答案 ≥ gap = ceil((max-min)/(n-1))
  用 gap 分桶 → 桶内元素差 ≤ gap < 答案
  → 答案只可能出现在"相邻非空桶之间"！
  → 只需记录每桶 min/max，O(n) 完成
```

### 1.2 完整代码

```java
/**
 * LeetCode 164. 最大间距（桶排序版，O(n)）
 * ⚠️ 核心：答案只出现在相邻非空桶之间（桶内必不构成答案）
 */
public int maximumGap(int[] nums) {
    int n = nums.length;
    if (n < 2) return 0;

    int min = Integer.MAX_VALUE, max = Integer.MIN_VALUE;
    for (int x : nums) { min = Math.min(min, x); max = Math.max(max, x); }
    if (max == min) return 0;

    int gap = (int) Math.ceil((double) (max - min) / (n - 1));  // ⚠️ 理论下界
    int bucketCount = (max - min) / gap + 1;
    int[] bucketMin = new int[bucketCount];
    int[] bucketMax = new int[bucketCount];
    boolean[] used = new boolean[bucketCount];
    Arrays.fill(bucketMin, Integer.MAX_VALUE);

    for (int x : nums) {                     // ① 分桶（只记 min/max）
        int idx = (x - min) / gap;
        used[idx] = true;
        bucketMin[idx] = Math.min(bucketMin[idx], x);
        bucketMax[idx] = Math.max(bucketMax[idx], x);
    }

    int best = 0, prevMax = min;
    for (int i = 0; i < bucketCount; i++) {  // ② 相邻非空桶差
        if (!used[i]) continue;
        best = Math.max(best, bucketMin[i] - prevMax);   // ⚠️ 桶间差
        prevMax = bucketMax[i];
    }
    return best;
}
// 推演 [3,6,9,1]：gap=ceil(8/3)=3 → 桶 [0,3),[3,6),[6,9)
//   桶内最多差 2 < 3 ≤ 答案 → 只查桶间 → 3-1=2? 1-6? 桶0:1, 桶2:3? 
//   实际：1 在桶0，3 在桶1，6 在桶2，9 在桶3
//   桶间差：3-1=2, 6-3=3, 9-6=3 → 答案 3 ✓
// ⚠️ 定理证明：n 个元素 n-1 个间隔，平均差 ≥ gap；
//   若桶内构成答案则矛盾（桶宽 < gap）
```

## 2. 164. 最大间距（基数排序版）

### 2.1 思路

```
同一题的基数版：O(n) 基数排序后扫相邻差
⚠️ 与桶版的区别：
  桶版：不排序，只求"桶间差"（更快，O(n) 且常数小）
  基数版：完整排序（可复用，但常数大）
→ 面试两版都能给 = 展示线性排序家族功底
```

### 2.2 完整代码

```java
/** 164 基数版：基数排序 + 扫描相邻差 */
public int maximumGapRadix(int[] nums) {
    int n = nums.length;
    if (n < 2) return 0;
    radixSort(nums);                       // 02 模块字节基数排序
    int best = 0;
    for (int i = 1; i < n; i++)
        best = Math.max(best, nums[i] - nums[i - 1]);
    return best;
}
// ⚠️ 面试表达："164 两种 O(n) 解法——桶版只算桶间差
//   （利用答案 ≥ 桶宽下界）；基数版完整排序再扫描。
//   桶版更贴合'最大间距'语义，常数更小。"
```

## 3. 912. 排序数组（基数版实现）

### 3.1 题目与思路

```
数组排序（基数版）——展示线性排序的完整实现
⚠️ 912 的数值范围 [-50000, 50000] → 偏移后值域 100001
  计数排序也是 O(n+k) 可行！两个版本都展示
```

### 3.2 双版本代码

```java
/** 版本一：计数排序（值域已知且小）O(n+k) */
public int[] sortArrayCount(int[] nums) {
    int min = Integer.MAX_VALUE, max = Integer.MIN_VALUE;
    for (int x : nums) { min = Math.min(min, x); max = Math.max(max, x); }

    int[] count = new int[max - min + 1];
    for (int x : nums) count[x - min]++;

    int idx = 0;
    for (int i = 0; i < count.length; i++)
        while (count[i]-- > 0) nums[idx++] = i + min;   // 展开
    return nums;
}
// 复杂度：O(n + k)，k = 值域 100001
// ⚠️ 稳定性：非稳定版（直接展开）；稳定版用前缀和+倒放

/** 版本二：字节基数排序（值域大也可用）O(4·(n+256)) */
public int[] sortArrayRadix(int[] nums) {
    // ① 偏移处理负数
    int min = Integer.MAX_VALUE;
    for (int x : nums) min = Math.min(min, x);
    for (int i = 0; i < nums.length; i++) nums[i] -= min;   // ⚠️ 平移
    // ② 字节基数排序（02 模块模板）
    radixSortBytes(nums);
    // ③ 还原
    for (int i = 0; i < nums.length; i++) nums[i] += min;
    return nums;
}
// ⚠️ 面试表达："912 线性排序版适合'值域有限'——
//   计数排序 O(n+k) 值域 10⁵ 时约 2n 常数；
//   基数排序不受值域影响但多轮搬运。
//   实际工程双轴快排常数更小。"
```

## 4. 451. 根据字符出现频率排序

### 4.1 题目与思路

```
按字符频率降序重排字符串（同频率任意顺序）
三解法：
  ① 哈希计数 + 排序（O(n log n)）
  ② 频次桶 + 降序展开（O(n)，频次范围 ≤ n）⭐
  ③ 哈希 + 堆
⚠️ 这题是"频次桶"（计数排序思想）的经典应用
```

### 4.2 完整代码（频次桶）

```java
/**
 * LeetCode 451. 根据字符出现频率排序
 * 频次桶：下标 = 频次，桶内 = 该频次字符
 */
public String frequencySort(String s) {
    int[] freq = new int[128];
    for (char c : s.toCharArray()) freq[c]++;

    // 桶：freq[i] 为 i 的字符列表（频次范围 1..n）
    List<Character>[] buckets = new List[s.length() + 1];
    for (int i = 0; i < 128; i++) {
        if (freq[i] > 0) {
            if (buckets[freq[i]] == null) buckets[freq[i]] = new ArrayList<>();
            buckets[freq[i]].add((char) i);
        }
    }

    StringBuilder sb = new StringBuilder();
    for (int f = s.length(); f >= 1; f--) {        // ⚠️ 高频桶 → 低频桶
        if (buckets[f] != null) {
            for (char c : buckets[f])
                for (int i = 0; i < f; i++) sb.append(c);   // 展开 f 次
        }
    }
    return sb.toString();
}
// 推演 s="tree"：freq{t:1,r:1,e:2}
//   桶[2]=[e]，桶[1]=[t,r] → "eetr"/"eert"（同频任意）✓
// ⚠️ 复杂度：O(n)（频次桶免排序）+ O(n) 空间
// ⚠️ 与 347 前 K 高频同构（347 取前 K，451 全量重排）
```

## 5. 179. 最大数（排序规则设计）

### 5.1 题目与思路

```
非负整数数组 → 拼接成最大数（如 [3,30,34,5,9] → "9534330"）
⚠️ 不是基数排序，但考"比较器设计"（排序的边界情况）：
  规则：x+y > y+x 则 x 在前（拼接比较）
  反例警示：直接按数值/字典序排是错的
  （"30" > "3" 字典序？但 330 > 303 需要 3 在前）
```

### 5.2 完整代码

```java
/**
 * LeetCode 179. 最大数
 * ⚠️ 比较器：拼接比较 x+y vs y+x
 */
public String largestNumber(int[] nums) {
    String[] strs = new String[nums.length];
    for (int i = 0; i < nums.length; i++) strs[i] = String.valueOf(nums[i]);

    Arrays.sort(strs, (a, b) -> (b + a).compareTo(a + b));  // ⚠️ 降序拼接
    if (strs[0].equals("0")) return "0";      // ⚠️ 全零特判

    StringBuilder sb = new StringBuilder();
    for (String s : strs) sb.append(s);
    return sb.toString();
}
// 推演 [3,30,34,5,9]：
//   比较 "3" vs "30"："330" > "303" → 3 在前
//   排序后 [9,5,34,3,30] → "9534330" ✓
// ⚠️ 正确性说明：拼接比较满足传递性（需要证明，工程上
//   直觉理解即可——"谁放前面拼出来大"）
// ⚠️ 注意：这不是基数排序题，但排序规则的"边界设计"
//   是线性排序/自定义排序的共同考点
```

## 6. 正负数混合基数排序实战

### 6.1 场景与思路

```
含负数的数组做基数排序——工程最常见变体
三种方案：
  ① 偏移法：整体平移（值域可控时）
  ② 符号位法：最高位变换（无符号视角排序）
  ③ 分治：负数正数分开排再拼接
⚠️ 面试给出 ①② 双方案 = 加分
```

### 6.2 完整实现（偏移 + 符号位）

```java
/** 方案一：偏移法（简单直观） */
void radixSortSigned(int[] nums) {
    int min = Integer.MAX_VALUE;
    for (int x : nums) min = Math.min(min, x);
    if (min < 0) {
        for (int i = 0; i < nums.length; i++) nums[i] -= min;
        radixSortBytes(nums);
        for (int i = 0; i < nums.length; i++) nums[i] += min;
    } else {
        radixSortBytes(nums);
    }
}

/** 方案二：符号位变换（无溢出风险，字节排序直接可用） */
void radixSortSignedKey(int[] nums) {
    // 变换：负数（最高位 1）→ 全位翻转（变小值靠前）
    //      正数（最高位 0）→ 符号位取反
    int[] keys = new int[nums.length];
    for (int i = 0; i < nums.length; i++) {
        keys[i] = nums[i] ^ Integer.MIN_VALUE;   // ⚠️ 翻转符号位
        // 变换后：负数 < 正数（无符号序正确）
    }
    // 对 keys 做字节基数排序（无符号移位），再把 nums 按序重排
}
// ⚠️ 原理：补码表示下，无符号整数序 = 有符号序 + 偏移
//   翻转符号位后，负数（原最高位 1）变 0x0xxx 排前 ✓
```

## 7. 912 家族：三版线性排序对比

### 7.1 三版代码对照

| 版本 | 复杂度 | 空间 | 稳定性 | 适用 |
|------|:---:|:---:|:---:|------|
| 计数排序 | O(n+k) | O(k) | 可稳定 | 值域小 |
| 基数排序 | O(4n) | O(n+256) | ✅ | 定长整数 |
| 桶排序 | O(n) 期望 | O(n) | 视桶内 | 均匀分布 |

```
⚠️ 同一题 912 三版都能过——面试的价值在"选型论述"：
  "值域 [−50000, 50000] → 计数排序最贴切（k=10⁵ 可控）；
   值域未知但定长整数 → 基数排序（分位不依赖值域）；
   数据均匀分布 → 桶排序。"
```

### 7.2 线性排序的边界

```
何时"线性"不成立：
  ① 值域巨大（k >> n）→ 计数排序空间爆炸
  ② 键不可分位（对象/浮点）→ 基数排序失效
  ③ 分布极不均匀 → 桶排序退化为 O(n log n)

⚠️ 面试表达：
"线性排序是'用空间/键特性换时间'——
 前提是键可索引或可分位。
 通用场景快排仍是默认（比较器灵活 + 常数小）。"
```

## 8. 方法论总结

### 8.1 线性排序四步框架

```
① 键分析：值域大小 / 可分位 / 分布形态
② 选型：
   值域小 → 计数排序（O(n+k)）
   定长键 → 基数排序（O(d·n)）
   均匀分布 → 桶排序（期望 O(n)）
③ 稳定性：需要稳定 → 计数"倒放"、基数逐轮稳定
④ 边界：负数偏移/符号位、全零特判、值域溢出

⚠️ 识别信号：
  "O(n) 排序、最大间距、频率排序、值域有限"
```

### 8.2 自测清单

```
□ 计数排序值域 k 是否可控（k ≤ 10⁶ 量级）？
□ 基数每轮稳定放置（从后往前）？
□ 负数用偏移/符号位处理？
□ 桶排序桶宽计算正确（gap 下界）？
□ 全零/单元素/相等元素特判？
□ 溢出检查（偏移法 min 很负时）？
```

### 8.3 复杂度速查

```
计数排序：O(n + k)，空间 O(k)
基数排序：O(d·(n + r))，32 位 r=256 → O(4n)
桶排序：O(n) 期望（桶数 ~ n），最坏 O(n log n)
稳定性：计数/基数可稳定；桶视桶内排序
```

## 9. 面试话术与手撕清单

### 9.1 识别信号

```text
"定长数值（ID/时间戳/固定位数）+ 要求 O(n)" → 基数排序
"O(n) 排序、最大间距、频率排序、值域有限"   → 线性排序家族
⚠️ 面试定位：了解原理 + 能手写按位计数排序；
   手撕优先级低于快排/归并（面试很少要求），
   但"三种线性排序对比"与"稳定性"是高频追问
```

### 9.2 话术三连（背下来）

| # | 问题 | 标准回答 |
|:---:|------|---------|
| 1 | 基数排序的原理？ | "按位多次稳定排序——每轮对某一位做稳定计数排序（桶数 = 基数），LSD 从低位到高位累积，高位相同时低位顺序不乱。d 轮后完全有序。" |
| 2 | 复杂度与稳定性？ | "O(d·(n+r))，d 是位数、r 是基数；定长键（32 位整数 r=256 → d=4）即 O(n) 线性；空间 O(n+r)；稳定。非比较排序，不受数据有序度影响。" |
| 3 | 什么时候赢快排？ | "n 大 + 定长键 + 稳定需求。n 小或键可变长/不可分位时快排更好（常数小、比较器灵活）。工程上 CPU 场景库排序默认快排/TimSort，GPU 大规模排序基数才是王者。" |

### 9.3 高频追问 TOP 10

| # | 追问 | 标准回答 |
|:---:|------|---------|
| 1 | 为什么每轮必须稳定？ | 高位排序后要保持低位顺序，否则结果错误（归纳定理：轮 k 后按后 k 位有序） |
| 2 | 稳定性怎么实现？ | 倒序回填：`result[--count[digit]] = arr[i]`（从后往前扫、先减再用） |
| 3 | LSD vs MSD？ | LSD 简单稳定（数值主流）；MSD 递归分桶（字符串字典序、可早停） |
| 4 | 复杂度？ | O(d·(n+r))；定长键即 O(n)；空间 O(n+r) |
| 5 | 与计数/桶排序？ | 计数是单轮索引、基数多轮分位、桶是分布分区（三兄弟同属值域索引） |
| 6 | 基数选多少？ | r=256（字节）工程标准：4 轮完成 32 位整数、计数数组进缓存 |
| 7 | 负数怎么办？ | 偏移法（简单，防溢出）或符号位变换（无溢出）——绝不直接取绝对值 |
| 8 | 字符串可以吗？ | 可以：LSD 补位（定长）或 MSD 递归（字典序、变长天然适配） |
| 9 | 为什么 Java 不用？ | Arrays.sort 双轴快排/TimSort 常数更小、更通用；基数的舞台是 GPU 与大数据框架 |
| 10 | 2025-2026 有新进展？ | Onesweep 进 CUB（单趟前缀和）、AMD 循环缓冲版、libcusort 快 33.6% |

## 10. 软考与笔试考点

### 10.1 过程模拟题（必考大题）

**真题样式**：对序列 [329, 457, 657, 839, 436, 720, 355] 用十进制 LSD 基数排序，写出每趟结果。

| 趟 | 位 | 分桶与收集 | 结果 |
|:---:|:---:|------|------|
| 初始 | — | — | [329, 457, 657, 839, 436, 720, 355] |
| 1 | 个位 | 0:{720} 5:{355} 6:{436} 7:{457,657} 9:{329,839} | [720, 355, 436, 457, 657, 329, 839] |
| 2 | 十位 | 2:{720,329} 3:{436,839} 5:{355,457,657} | [720, 329, 436, 839, 355, 457, 657] |
| 3 | 百位 | 3:{329,355} 4:{436,457} 6:{657} 7:{720} 8:{839} | [329, 355, 436, 457, 657, 720, 839] ✓ |

**答题技巧**：

```text
① 每趟写"分桶分布 + 收集结果"两步，中间状态是评分点
② 同桶元素保持上一趟顺序（稳定性）——写错即扣分
③ 先找最大值确定轮数，别漏最高位轮
```

### 10.2 其他题型

| 考点 | 题型 | 要点 |
|------|------|------|
| 稳定性判断 | 概念题 | 稳定口诀"冒插归基"含基数；**基数必须稳定**（高位不破坏低位） |
| 复杂度辨析 | 选择题 | O(d·(n+r))，定长键视为 O(n)；**与数据有序度无关**（非比较） |
| 与计数/桶区别 | 选择题 | 计数按值域、基数按位数、桶按分布 |
| 负数处理 | 概念题 | 偏移/符号位，**不可直接绝对值** |
| 基数选择 | 概念题 | r=256 字节工程标准（4 轮 32 位） |

> 🎯 **核心要点**：实战面试通关 = **三兄弟题解（164 桶版/基数版双解 + 912 三版 + 451 频次桶）+ 一个比较器题（179）+ 话术三连 + 一道模拟（软考过程模拟，分桶/收集分步写）**。基数排序在面试中的定位是"**知道原理、会写十进制 LSD、讲清稳定与线性条件**"——把"何时赢快排"讲出边界感（n 大 + 定长键 + 稳定需求），再补一句 GPU 前沿（Onesweep），就是完整的高分故事。
