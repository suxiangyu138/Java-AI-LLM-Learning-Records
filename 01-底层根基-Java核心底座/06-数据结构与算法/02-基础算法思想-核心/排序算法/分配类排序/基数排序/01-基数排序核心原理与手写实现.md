## 1. 桶模型：从卡片机到数组

### 1.1 算法就是整理卡片

基数排序的思想可以追溯到 1887 年 Hollerith 的穿孔卡片分卡器——按卡片上某一位打孔位置分堆，再按堆序收集。整理扑克牌也是同样的流程：

```text
① 每轮按"某一位数字"分桶（十进制 0-9 号桶）
② 按桶号 0→9 顺序收集（同桶内保持原顺序 = 稳定）
③ 换更高一位重复（个位 → 十位 → 百位…）
④ d 轮后完全有序
```

### 1.2 算法要素

```text
基数 r: 每轮分桶数（十进制 r=10、字节 r=256、二进制 r=2）
位数 d: 轮数 = 最大值的位数（十进制 ⌊log₁₀(max)⌋ + 1）
每轮: 对某一位做"稳定的计数排序"
关键: 每轮必须稳定 → 高位相同时低位顺序不乱（正确性的全部秘密）
```

> 🎯 **核心动作三连**：**分桶（统计该位数字频次）→ 前缀和（确定落位区间）→ 倒序回填（保证稳定）**。"按位多次 + 稳定累积"是基数排序的灵魂——它把一个大值域问题拆成 d 个小值域问题，每个小值域用计数排序 O(n) 解决。

## 2. 基本实现：十进制 LSD（2 分钟默写）

### 2.1 完整代码（面试标准答案）

```java
/**
 * 基数排序（LSD，十进制）——面试标准答案
 * 时间 O(d·(n+10))，空间 O(n+10)，稳定
 */
public void radixSort(int[] arr) {
    if (arr.length == 0) return;

    // ① 找最大值确定位数
    int max = 0;
    for (int x : arr) max = Math.max(max, x);

    // ② 按位排序：exp = 1, 10, 100…（个位 → 十位 → 百位）
    for (int exp = 1; max / exp > 0; exp *= 10) {
        countingSortByDigit(arr, exp);
    }
}

/** 按某一位稳定排序（计数排序核心） */
private void countingSortByDigit(int[] arr, int exp) {
    int n = arr.length;
    int[] count = new int[10];         // 十进制 0-9
    int[] result = new int[n];

    // ① 该位的数字计数
    for (int x : arr) {
        count[(x / exp) % 10]++;
    }

    // ② 前缀和（把计数转成"落位区间"）
    for (int i = 1; i < 10; i++) {
        count[i] += count[i - 1];
    }

    // ③ 倒序回填（稳定性关键！）
    for (int i = n - 1; i >= 0; i--) {
        int digit = (arr[i] / exp) % 10;
        result[--count[digit]] = arr[i];
    }
    System.arraycopy(result, 0, arr, 0, n);
}
```

### 2.2 为什么倒序回填是稳定性的关键

```text
正序回填（❌ 错误）:
  从前往后扫描，每个元素放到该数字桶的"当前末尾位置"
  → 位置由前缀和递减得到，但正序扫描时同桶元素的相对顺序会被反转
  （先扫到的元素先占高位位置，后扫到的反而落前 → 顺序翻转）

倒序回填（✔ 正确）:
  从后往前扫描，--count 先减后用 → 后扫到的元素落在更高位置
  → 同桶元素保持原始相对顺序 → 稳定

一句话: 倒序扫描 + 前缀和递减 = 同桶内"后来的元素靠后放" → 相对顺序不变
```

> 💡 **记忆技巧**：`result[--count[digit]] = arr[i]` 是计数排序稳定版的标准写法——**"从后往前扫、先减再用"** 八字诀。软考/考研问"计数排序如何保证稳定"，答案就是这一行。

## 3. 逐步推演：n=8 全流程

**数据**：[170, 45, 75, 90, 802, 24, 2, 66]（升序排序），十进制，3 轮

| 轮 | exp | 各数字分布 | 排序结果 |
|:---:|:---:|------|------|
| 初始 | — | — | [170, 45, 75, 90, 802, 24, 2, 66] |
| 1 | 1 | 0:{170,90} 2:{802,2} 4:{24} 5:{45,75} 6:{66} | [170, 90, 802, 2, 24, 45, 75, 66] |
| 2 | 10 | 0:{802,2} 2:{24} 4:{45} 6:{66} 7:{170,75} 9:{90} | [802, 2, 24, 45, 66, 170, 75, 90] |
| 3 | 100 | 0:{2,24,45,66,75,90} 1:{170} 8:{802} | [2, 24, 45, 66, 75, 90, 170, 802] ✓ |

**推演关键观察**：

```text
第 2 轮: 170 和 75 的十位都是 7 → 保持第 1 轮的个位顺序（170 在 75 前）→ 稳定！
第 3 轮: 百位为 0 的 6 个元素保持第 2 轮的十位顺序 → 完全有序 ✓
验证: 每轮结束，序列按"已处理的后 k 位"有序（见第 5 节归纳定理）
```

> 🎯 **从推演看正确性**：第 2 轮中"十位相同 → 个位顺序保留"，第 3 轮中"百位相同 → 十位顺序保留"——**每一轮都在利用前一轮的成果，稳定性是这条"成果传递链"的粘合剂**。任何一轮不稳定，链条断裂，最终结果错误。

## 4. 复杂度推导：线性时间的来源

### 4.1 精确计数

```text
轮数 d = ⌊log_r(max)⌋ + 1（最大值的位数）
  十进制: d = ⌊log₁₀(max)⌋ + 1
  字节:   d = 32 / 8 = 4（32 位整数，恒定！）

每轮成本（稳定计数排序）:
  计数: O(n)
  前缀和: O(r)
  回填 + 拷贝: O(n)
  → 每轮 O(n + r)

总复杂度: O(d·(n + r))
```

### 4.2 定长键 → 真正的线性

```text
32 位整数 + r=256（字节基数排序）:
  d = 4 恒定 → O(4·(n + 256)) = O(n) 线性！

对比快排（n = 10⁶，32 位整数）:
  快排:  ~n·log n ≈ 2×10⁷ 次比较
  基数:  4 轮 × 10⁶ 搬运 = 4×10⁶ 次操作 + 计数开销
  → 基数更快（顺序访问 + 无比较），但 n 小时快排赢（常数更小）
```

### 4.3 与数据有序度无关

```text
比较排序（快排/归并）: 复杂度受数据分布影响（有序/逆序/随机）
基数排序: 每轮无脑分桶 + 收集，与有序度完全无关
  → 最好 = 平均 = 最坏 = O(d·(n+r))

这是"非比较排序"的共同特性，也是面试常考的一个点:
"基数排序没有最好/最坏之分——它不看比较结果，只看位值。"
```

> 🎯 **面试必答句**："基数排序 O(d·(n+r))——d 是位数、r 是基数。定长键（如 32 位整数、r=256）时 d 是常数，所以实际是 O(n) 线性；空间 O(n+r)；稳定。它是非比较排序，不受数据有序度影响，也不受比较下界 Ω(n log n) 约束。"

## 5. 稳定性证明：LSD 正确性的核心

### 5.1 正确性定理（归纳法）

```text
命题: 第 k 轮结束后，序列按"后 k 位"有序（k = 1..d）

归纳基础: k=0 平凡成立（任何序列对"后 0 位"有序）

归纳步骤: 假设第 k 轮后按后 k 位有序，看第 k+1 轮（按第 k+1 位稳定排序）:
  ① 第 k+1 位不同 → 本轮直接按第 k+1 位排好 ✓
  ② 第 k+1 位相同 → 稳定排序保留前 k 轮的相对顺序
     → 后 k 位仍然有序 ✓（这正是稳定性的用武之地）
  两情形都成立 → 命题对 k+1 成立

结论: d 轮后按全部 d 位有序 → 排序完成 ✓
```

### 5.2 稳定性在哪里丢失（不稳定排序的后果）

```text
若某轮用不稳定排序（如正序回填的计数排序）:
  第 k+1 位相同的元素，其"后 k 位"相对顺序可能被打乱
  → 归纳步骤中的情形 ② 失效 → 最终结果错误

示例: 170 与 75（十位都是 7）
  个位轮后: 170（个位 0）在 75（个位 5）之前
  十位轮若不稳定 → 同桶（7 号桶）内顺序反转 → 170 跑到 75 后面
  百位轮后: 170 在 75 后 → 错误（170 < 75 的十位相等时比个位）

一句话: "稳定性不是优化，是正确性"——这是基数排序区别于其他排序的最大考点
```

> 🎯 **面试必答**："基数排序每轮必须稳定——高位相同时要保留低位顺序，这是通过倒序回填的计数排序实现的。正确性由归纳定理保证：第 k 轮后序列按后 k 位有序。" 能把归纳定理讲出来，深度立现。

## 6. 与计数排序的关系：单轮与多轮

### 6.1 组件关系

```text
计数排序: 值域小（k 个可能值）→ 一次统计 + 定位完成
基数排序: 值域大但可分位 → 把大值域拆成 d 个"每位的小值域"（r 个可能值）
  → 每轮 = 一个"小值域计数排序"
  → 基数排序 = 按位复用的计数排序

关系表:
  计数排序 = 基数排序的"单轮"
  基数排序 = d 轮计数排序（每轮基数 r）
  计数排序的稳定性写法（倒序回填）= 基数排序正确性的基石
```

### 6.2 选型分界线

| 情形 | 选型 | 原因 |
|------|------|------|
| 值域小（0-100） | 计数排序 | 一轮 O(n+k)，无多轮搬运 |
| 值域大但位数少（32 位整数） | 基数排序 | d 恒定 → O(n)，计数排序空间爆炸 |
| 键不可分位（对象/浮点） | 快排等比较排序 | 基数要求可分位 |

> 💡 面试表达："**计数排序受值域限制，基数排序受位数的分位能力限制**——一个适合小值域，一个适合大值域定长键。两者共享'值域索引'思想与稳定性写法，面试时把这条线讲清比背代码值钱。"

## 7. 负数处理与手写易错点

### 7.1 负数处理：偏移法与符号位法

```java
/** 方案一：偏移法（简单直观，值域可控时用） */
public void radixSortWithNegatives(int[] arr) {
    int min = Integer.MAX_VALUE;
    for (int x : arr) min = Math.min(min, x);
    if (min < 0) {
        for (int i = 0; i < arr.length; i++) arr[i] -= min;  // 整体平移为非负
    }
    radixSort(arr);                                          // 正常排序
    if (min < 0) {
        for (int i = 0; i < arr.length; i++) arr[i] += min;  // 还原
    }
}
// ⚠️ 风险: min 很负时 arr[i] - min 可能溢出 int → 大值域改用符号位法

/** 方案二：符号位变换（无溢出风险，面试进阶方案） */
// 原理: 补码表示下，翻转符号位后按无符号序排序，
//       负数（原最高位 1）自然排在正数前面
// 实现: key = x ^ Integer.MIN_VALUE → 对 key 做字节基数排序 → 按序重排
```

> ⚠️ **常见错误**：负数**不能直接取绝对值排序**——`-3` 与 `-1` 取绝对值后是 3 与 1，排出来是 `-1, -3`，顺序错误。必须整体偏移（保持相对大小）或用符号位变换。

### 7.2 手写易错点速查

| # | 易错点 | 正确写法 | 后果 |
|:---:|------|------|------|
| 1 | 忘记稳定回填（正序） | 倒序回填 `result[--count[d]]` | 稳定性破坏 → 结果错误 |
| 2 | 漏掉 `System.arraycopy` | 每轮结束拷回原数组 | 原数组未更新 |
| 3 | exp 循环边界错 | `max / exp > 0` | 漏掉最高位轮 |
| 4 | 取位公式错 | `(x / exp) % 10` | 该位数字算错 |
| 5 | 负数直接排序 | 先偏移或符号位变换 | 排序结果错误 |
| 6 | 计数数组大小错 | 十进制 `new int[10]` | 越界或桶数不足 |
| 7 | 忘记 `max` 找最大值 | 先扫描最大值定轮数 | 轮数不足/无限循环 |

> 🎯 **核心要点**：基数排序通关四件事——**① 2 分钟默写十进制 LSD**（分桶 → 前缀和 → 倒序回填，八字诀"从后往前扫、先减再用"）；**② 说清线性条件**（O(d·(n+r))，定长键 d 恒定 → O(n)）；**③ 讲透稳定性**（归纳定理：第 k 轮后按后 k 位有序，不稳定 = 结果错误）；**④ 负数偏移或符号位**（绝不直接取绝对值）。**它是"唯一能排大值域定长键的线性算法"，而这一切只靠一个三件套：分桶、前缀和、倒序回填。**
