## 1. 知识体系导图

```text
归并排序（Merge Sort，1945 冯·诺依曼，二路归并）
│
├── 核心本质 ──────────────────────────────────────────────
│   ├── = 拆（对半分）→ 排（递归排）→ 合（合并有序）
│   ├── 二路归并：两个有序序列合并为一个（双指针 + 辅助数组）
│   ├── 拆分与数据无关 → 递归树恒 log n 层 × 每层 O(n)
│   └── 分治典范：T(n) = 2T(n/2) + O(n) → 主定理情形二
│
├── 关键特性 ──────────────────────────────────────────────
│   ├── 时间复杂度：最好 = 平均 = 最坏 O(n log n)（无退化）
│   ├── 空间复杂度：数组 O(n) 辅助 / 链表 O(log n) 递归栈
│   ├── 稳定性：✔ 稳定（merge 用 <=，相等取左块）
│   └── 顺序访问：缓存友好，大数据下反而有优势
│
├── 两大形态 ──────────────────────────────────────────────
│   ├── 递归版（自顶向下）：直观好写，面试首选
│   ├── 迭代版（自底向上）：无递归栈，min 边界三处防护
│   └── 工程优化：小段插排 / 有序检测跳过 / 共享辅助数组 / 交替写回
│
├── 变体与家族 ────────────────────────────────────────────
│   ├── 链表归并（148）：无随机访问 → 归并天然适配，O(1) 额外空间
│   ├── 逆序对统计（剑指 51）：合并时批量计数（mid-i+1）
│   ├── TimSort：归并 + 插入 + run 识别（Java 对象排序默认）
│   ├── Powersort（2022）：TimSort 合并策略的继任者（CPython 3.11+ 默认）
│   └── 外部排序：分块内排生成 run → 多路归并（数据库/大数据地基）
│
├── 工程前沿（2025-2026）──────────────────────────────────
│   ├── Java：对象 TimSort / 基本类型双轴快排 / parallelSort Fork-Join
│   ├── Powersort：修复 TimSort 两个盲点，长 run 输入快 30%
│   └── Multiway Powersort（2023）：多路归并扩展
│
└── 实战与面试 ────────────────────────────────────────────
    ├── 手写：递归版（2 分钟）+ 迭代版（5 分钟）
    ├── 考题：912/148/88/21/23 + 剑指 51 逆序对家族（493/315/327）
    ├── 对比：归并 vs 快排 vs 堆排（稳定 / 空间 / 退化）
    └── 话术：无退化 + 稳定 + 链表 + 外部排序四张牌
```

## 4. 核心概念速查

| 概念 | 一句话解释 | 说明 |
|------|-----------|------|
| **归并排序** | 拆 → 排 → 合的分治排序 | 1945 年冯·诺依曼提出 |
| **二路归并** | 两个有序序列合并为一个 | 归并排序的基本原子操作 |
| **合并（merge）** | 双指针比较 + 辅助数组回填 | 每次取较小的头元素 |
| **递归树** | 拆分产生的二叉树 | 恒 log n 层（与数据无关） |
| **辅助数组** | 合并时暂存数据的 O(n) 空间 | 全程复用避免反复分配 |
| **无退化** | 最好 = 最坏 = O(n log n) | 拆分不依赖数据分布 |
| **稳定性** | 相等元素相对顺序不变 | merge 用 <=（相等取左块） |
| **自底向上** | 迭代版：块长 1→2→4 翻倍合并 | 无递归栈 |
| **run** | 天然有序片段 | TimSort 识别的可复用段 |
| **TimSort** | 归并 + 插入 + run 识别 | Java 对象排序默认算法 |
| **Powersort** | TimSort 合并策略的继任者 | CPython 3.11+ 默认（2022） |
| **外部排序** | 分块内排 + 多路归并 | 数据超内存时的排序方案 |
| **多路归并** | K 个有序段同时合并 | 堆 O(n log K) 或败者树 |
| **逆序对** | i < j 且 a[i] > a[j] | 合并时批量计数（mid-i+1） |
| **主定理** | T(n) = aT(n/b) + f(n) 的解法 | 归并是情形二的经典例 |

## 5. 复杂度与特性速查表

| 维度 | 最好 | 平均 | 最坏 | 说明 |
|------|:---:|:---:|:---:|------|
| 时间复杂度 | O(n log n) | O(n log n) | O(n log n) | 拆分与数据无关 → 无退化 |
| 空间复杂度（数组） | O(n) | O(n) | O(n) | 辅助数组（全程复用） |
| 空间复杂度（链表） | O(log n) | O(log n) | O(log n) | 仅递归栈，合并改指针 |
| 稳定性 | ✔ 稳定 | — | — | merge 用 <= 相等取左块 |
| 适应性 | ✘ 无 | — | — | 有序数据也不加速（TimSort 才有） |

**归并 vs 快排 vs 堆排**：

| 维度 | 归并 | 快排 | 堆排 |
|------|:---:|:---:|:---:|
| 最坏 | O(n log n) | O(n²) | O(n log n) |
| 空间 | O(n) 辅助数组 | O(log n) 栈 | O(1) |
| 稳定 | ✔ | ✘ | ✘ |
| 链表 | ✔ 最优 | ✘ 需随机访问 | ✘ 需下标 |
| 缓存 | 顺序访问友好 | 随机访问较差 | 跳跃最差 |
| 实际速度 | 中（拷贝多） | 最快（常数小） | 中 |

> 🎯 **一句话选型**：**要稳定 → 归并/TimSort；要原地 → 快排/堆排；链表/外部数据/逆序对 → 归并；内存受限 → 堆排**。Java 里对象排序用 TimSort（稳定归并家族）、基本类型用双轴快排（快但不稳）——工程选型的"稳定 vs 快"分界线在归并这里看得最清楚。

## 6. 常见误区速查

| 误区 | 正解 |
|------|------|
| "归并排序空间 O(1)" | ❌ 数组版 O(n) 辅助数组；只有链表版才 O(log n)（递归栈） |
| "归并排序最坏退化成 O(n²)" | ❌ 拆分与数据无关，恒 O(n log n)——这是它 vs 快排的核心优势 |
| "归并排序不稳定" | ❌ 稳定！merge 用 <=（相等取左块）；用 < 才会不稳定 |
| "归并排序平均比快排快" | ❌ 快排常数更小（无拷贝）；归并赢在稳定/无退化/链表/顺序访问 |
| "归并排序只能排数组" | ❌ 链表、外部数据（磁盘）、数据库 order by 都是它的主场 |
| "迭代版与递归版结果不同" | ❌ 合并逻辑完全一致，只是执行顺序不同（层序 vs 前序） |
| "TimSort 与归并无关" | ❌ TimSort = 归并 + 插入 + run 识别，是归并家族的工程巅峰 |
| "外部排序不需要归并" | ❌ 外部排序的核心阶段就是多路归并 |
| "逆序对统计要另写算法" | ❌ 合并时顺手计数（右块取走 +mid-i+1），O(n log n) 一举两得 |
| "Java 所有排序都用 TimSort" | ❌ 对象数组 TimSort；基本类型数组双轴快排 |
