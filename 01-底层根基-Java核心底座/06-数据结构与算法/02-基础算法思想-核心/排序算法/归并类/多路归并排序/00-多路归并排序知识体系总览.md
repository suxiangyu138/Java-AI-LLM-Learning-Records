## 1. 知识体系导图

```text
多路归并排序（K-Way Merge Sort）
│
├── 核心本质 ──────────────────────────────────────────────
│   ├── = 一次合并 K 个有序段（run）为一个有序序列
│   ├── K 路"选最小"三实现：循环 O(K) / 堆 O(log K) / 败者树 O(log K)
│   ├── 归并趟数：S = ⌈log_K m⌉（m = 初始归并段数）
│   └── 外部排序第二阶段的核心引擎
│
├── 关键特性 ──────────────────────────────────────────────
│   ├── 时间复杂度：O(n·log K)（堆 / 败者树）
│   ├── 空间复杂度：O(K)（堆 / 树）+ O(K) 输入缓冲
│   ├── 稳定性：✔ 稳定（K 路平局取段号小的）
│   └── 核心权衡：K 增大 → 趟数减少 / 缓冲内存与缓存压力增大
│
├── 三种"选最小"实现 ──────────────────────────────────────
│   ├── 循环遍历：每元素 K−1 次比较 → 总 O(nK)，K 大不可用
│   ├── 最小堆：每元素 O(log K) → 总 O(n log K)，工程默认
│   └── 败者树：每层 1 比较 + 1 访存（vs 堆 2+2）→ 大 K 首选
│
├── 外部排序两阶段 ────────────────────────────────────────
│   ├── 阶段一：分块内排生成归并段（替换-选择 → 平均 2w 段长）
│   ├── 阶段二：多路归并所有段（堆 / 败者树，I/O 主导）
│   └── 最佳归并树：K 叉哈夫曼树优化归并顺序（短段先并 + 虚段补齐）
│
├── 工程前沿（2025-2026）──────────────────────────────────
│   ├── Apache Spark SPARK-57714：败者树 K 路合并器（Spark 4.0，opt-in）
│   ├── MySQL filesort 外部排序：多路归并 + 败者树的工程代表
│   └── SSD/NVM 感知、预取、自适应 K（2026 综述方向）
│
└── 实战与面试 ────────────────────────────────────────────
    ├── 手写：堆版 K 路归并（2 分钟）+ 败者树（进阶）
    ├── 考题：23 合并 K 链表（堆 / 分治）、K 路有序数组、K 路文件归并
    ├── 对比：二路 vs 多路、堆 vs 败者树 vs 循环
    └── 话术：轮数公式 + K 权衡 + 败者树优势 + 数据库故事
```

## 4. 核心概念速查

| 概念 | 一句话解释 | 说明 |
|------|-----------|------|
| **多路归并** | 一次合并 K 个有序段 | 外部排序第二阶段的核心 |
| **归并段（run）** | 内存排序后写回磁盘的有序块 | 阶段一的产物 |
| **归并趟数** | 需要几轮归并：⌈log_K m⌉ | 趟数越少 I/O 越少 |
| **K 路选择** | 从 K 个当前元素中选最小 | 循环 / 堆 / 败者树三种实现 |
| **最小堆** | K 个候选建堆，弹出补位 | 每元素 O(log K)，工程默认 |
| **败者树** | 锦标赛变体，内部节点存败者 | 每层 1 比较 + 1 访存，大 K 首选 |
| **胜者树** | 内部节点存胜者的锦标赛树 | 调整路径复杂，教材对照物 |
| **替换-选择** | 边输出边补入的段生成法 | 平均段长 ≈ 2× 内存工作区 |
| **最佳归并树** | K 叉哈夫曼树 | 短段先并，I/O 总代价最小 |
| **虚段** | 长度 0 的补位段 | (N−1) % (K−1) ≠ 0 时补齐 |
| **输入缓冲区** | 每路在内存中的暂存区 | 至少 K+1 个，2K 个更充分 |
| **MAXKEY 哨兵** | 段尾的最大关键字 | 败者树/归并的结束标记 |

## 5. 复杂度与特性速查表

| 实现 | 每次选最小 | 总时间 | 额外空间 | 适用 |
|------|:---:|:---:|:---:|------|
| 循环遍历 | O(K) 次比较 | O(n·K) | O(K) | 仅 K 很小的教学 |
| 最小堆 | O(log K) | O(n·log K) | O(K) | 工程默认（简单可靠） |
| 败者树 | O(log K)，每层 1 比较 + 1 访存 | O(n·log K)，常数更小 | O(K) | 大 K、内存敏感场景 |

| 维度 | 值 | 说明 |
|------|:---:|------|
| 归并趟数 | ⌈log_K m⌉ | m = 归并段数；K 越大趟数越少 |
| 稳定性 | ✔ 稳定 | K 路平局取段号小的（同二路归并） |
| 缓冲需求 | ≥ K+1 个输入缓冲 | 内存固定时 K 增 → 每缓冲变小 |

> 🎯 **一句话选型**：**K 小用循环法（教学），K 中等用堆（工程默认），K 很大且内存敏感用败者树**。多路归并的收益公式就一条——**归并趟数从 log₂m 降到 log_K m，磁盘 I/O 按趟数比例减少**，这是外部排序提速的第一杠杆。

## 6. 常见误区速查

| 误区 | 正解 |
|------|------|
| "K 越大越好" | ❌ K 增大 → 输入缓冲内存翻倍、缓存 miss 增多、每缓冲变小 I/O 变差——K 需按内存权衡 |
| "败者树和堆复杂度相同，没差别" | ❌ 堆 sift-down 每层 2 比较 + 2 子读；败者树每层 1 比较 + 1 访存——大 K 时差距显著 |
| "败者树内部节点存胜者" | ❌ 存**败者**（较大者），胜者继续向上——这是它与胜者树的唯一结构区别 |
| "多路归并只用于外部排序" | ❌ 23 合并 K 链表、K 路有序数组、数据库 filesort 都是多路归并 |
| "归并段只能靠分块生成" | ❌ 替换-选择排序可生成平均 2w 长的段（w = 内存工作区） |
| "归并顺序随便安排就行" | ❌ 段长不一时用最佳归并树（K 叉哈夫曼树）才最优，还需虚段补齐 |
| "多路归并不稳定" | ❌ 稳定——K 路平局取段号小的路 |
| "败者树初始化也要 O(K log K)" | ❌ 初始化只需 K−1 次比较，之后每轮 ⌈log₂K⌉ 次 |
| "二路归并趟数公式直接套多路" | ❌ 趟数 = ⌈log_K m⌉（K 为底），K=2 时才等于 ⌈log₂m⌉ |
| "外部排序瓶颈在 CPU 比较" | ❌ 瓶颈在磁盘 I/O——多路归并/替换-选择/最佳归并树都是为了减 I/O |
