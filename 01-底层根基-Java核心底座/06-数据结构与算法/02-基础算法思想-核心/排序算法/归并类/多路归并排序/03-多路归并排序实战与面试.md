## 1. 实战题：23 合并 K 个升序链表（多路归并视角）

### 1.1 题目与思路

**题**：K 个升序链表 → 一个升序链表（O(N log K)）。

**多路归并视角**：K 个链表的头节点 = K 路候选 → 最小堆选最小 → 同路补位。**这就是 K 路归并的链表载体**（数组版载体见第 2 节，文件版见第 3 节）。

```text
两种实现:
  ① 堆（多路归并）: K 个头入堆 → 弹最小 → 补位 → O(N log K)，空间 O(K)
  ② 分治两两合并: 复用 21 题，对半递归合并 → O(N log K)，空间 O(log K)
  → K 大时堆空间 O(K) 可能超限，分治栈更省（详见归并排序 03 文件 4 节）
```

### 1.2 堆版完整代码（多路归并模板）

```java
/**
 * LeetCode 23. 合并 K 个升序链表（堆版 = K 路归并）
 * 时间 O(N log K)，空间 O(K)
 */
public ListNode mergeKLists(ListNode[] lists) {
    PriorityQueue<ListNode> heap = new PriorityQueue<>((a, b) -> a.val - b.val);

    for (ListNode h : lists)                  // ① K 个头入堆（空链跳过）
        if (h != null) heap.offer(h);

    ListNode dummy = new ListNode(0), tail = dummy;
    while (!heap.isEmpty()) {
        ListNode node = heap.poll();          // ② 弹全局最小
        tail.next = node;
        tail = node;
        if (node.next != null) heap.offer(node.next);   // ③ 同路补位
    }
    return dummy.next;
}
```

> 🎯 **23 题 = 多路归并的面试名片**：堆元素不需要"三元组"——**链表节点的 next 天然携带补位信息**（数组版要存 [值, 路, 列]，链表版直接补 node.next）。讲题时点出"这就是 K 路归并"，把算法题和系统设计串起来是加分项。

## 2. 实战：K 路有序数组合并（堆版模板复用）

### 2.1 完整代码（与 01 文件模板一致）

```java
/**
 * K 路有序数组合并（堆版，01 文件模板）
 * 时间 O(n·log K)，空间 O(K) + O(n)
 */
public int[] mergeKSortedArrays(int[][] arrays) {
    int k = arrays.length, total = 0;
    for (int[] a : arrays) total += a.length;

    PriorityQueue<int[]> heap = new PriorityQueue<>((x, y) -> x[0] - y[0]);
    for (int i = 0; i < k; i++)
        if (arrays[i].length > 0)
            heap.offer(new int[]{arrays[i][0], i, 0});   // [值, 路, 列]

    int[] result = new int[total];
    int idx = 0;
    while (!heap.isEmpty()) {
        int[] top = heap.poll();
        result[idx++] = top[0];
        if (top[2] + 1 < arrays[top[1]].length)
            heap.offer(new int[]{arrays[top[1]][top[2] + 1], top[1], top[2] + 1});
    }
    return result;
}
// ⚠️ 与 23 题的差异: 数组版必须记录"来源路与列"才能补位；
//   链表版节点自带 next → 结构更简洁
```

### 2.2 变形题一览

| 题 | 变形 | 要点 |
|:---:|------|------|
| 373 查找和最小的 K 对数字 | 两个有序数组 → K 路归并（每行 = 一个数组对） | 堆元素: (sum, i, j)，补位 (i+1, j) / (i, j+1) |
| 378 有序矩阵第 K 小 | 每行有序 → K 路归并取第 K 个 | 归并到第 K 个即停 |
| 632 最小区间 | K 个有序列表 → 覆盖区间的滑动 | 堆 + 每路当前最大 |

## 3. 实战：K 路文件归并（外部排序核心）

### 3.1 场景与思路

```text
场景: 100GB 日志按时间排序，内存 1GB
阶段一: 分 100 块 → 每块内存排序 → 写 100 个有序文件（归并段）
阶段二（本实战）: 100 路文件归并 → 全局有序

与数组版的差异:
  ① 数据在磁盘 —— 每路维护输入缓冲（读一段到内存）
  ② 每路耗尽 = 文件读完（而非下标越界）
  ③ 输出写文件（而非内存数组）
```

### 3.2 核心代码（伪代码级，体现工程要点）

```java
/**
 * K 路文件归并（外部排序阶段二核心）
 * 输入: K 个已排序的临时文件；输出: 全局有序文件
 */
void kWayFileMerge(String[] sortedFiles, String outputFile) {
    // ① 每路打开一个 BufferedReader（内部带输入缓冲）
    // ② 每路读入首行 → 入堆（元素: [值, 路号]）
    PriorityQueue<int[]> heap = new PriorityQueue<>((a, b) -> a[0] - b[0]);
    BufferedReader[] readers = new BufferedReader[sortedFiles.length];
    // ... 打开文件、读首行、非空入堆 ...

    BufferedWriter out = new BufferedWriter(new FileWriter(outputFile));
    while (!heap.isEmpty()) {
        int[] top = heap.poll();                  // 弹全局最小
        out.write(top[0] + "\n");
        String next = readers[top[1]].readLine(); // 同路补位（读下一行）
        if (next != null)
            heap.offer(new int[]{Integer.parseInt(next), top[1]});
    }
    // ... 关闭所有流 ...
}
// ⚠️ 工程要点:
//   ① 缓冲大小 = 可用内存 / K —— K 增则每缓冲变小（K 权衡的现场）
//   ② 平局稳定性: 堆比较器加"路号"次键 → 段号小的先出
//   ③ 错误处理: 文件损坏/读取失败要留日志
//   ④ 进阶: 败者树替换堆（02 文件）→ 大 K 常数减半
```

> 🎯 **实战判断**："K 路文件归并 = 01 堆版模板 + 磁盘 I/O 三件套（缓冲、流管理、平局路号）**——模板不变，变的只是数据载体**。能把这个场景讲清楚，说明你理解的是多路归并的本质而非背题。"

## 4. 面试话术三连

### 4.1 三连话术（背下来）

| # | 问题 | 标准回答 |
|:---:|------|---------|
| 1 | 多路归并的原理？ | "一次合并 K 个有序段：K 个头入最小堆，弹最小输出，同路补位，直到全部耗尽。趟数 ⌈log_K m⌉，比二路的 ⌈log₂m⌉ 大幅减少磁盘 I/O。" |
| 2 | 复杂度与权衡？ | "O(n log K) 时间、O(K) 空间、稳定（平局取段号小）。K 不是越大越好——缓冲内存线性增长、每缓冲变小导致 I/O 反弹，实践中按内存预算取 K ≈ 10~50。" |
| 3 | 堆 vs 败者树？ | "堆是工程默认（标准库现成、O(log K)）；败者树每层 1 比较 1 访存（vs 堆 2+2），大 K 时常数减半——Spark 4.0 正在给 spill 归并加败者树选项（SPARK-57714）。" |

### 4.2 30 秒手写版本（堆版核心）

```java
// 面试手写最简版（23 题链表版，30 秒内）
ListNode mergeKLists(ListNode[] lists) {
    PriorityQueue<ListNode> pq = new PriorityQueue<>((a, b) -> a.val - b.val);
    for (ListNode h : lists) if (h != null) pq.offer(h);
    ListNode dummy = new ListNode(0), tail = dummy;
    while (!pq.isEmpty()) {
        ListNode n = pq.poll();
        tail.next = n; tail = n;
        if (n.next != null) pq.offer(n.next);
    }
    return dummy.next;
}
```

## 6. 软考与笔试考点：轮数计算与虚段

### 6.1 轮数计算题（必考大题）

**题型**：m 个归并段做 K 路归并，需要几趟？

| 例 | 计算 | 答案 |
|------|------|:---:|
| 100 段，二路 | ⌈log₂100⌉ = ⌈6.64⌉ | 7 趟 |
| 100 段，十路 | ⌈log₁₀100⌉ | 2 趟 |
| 16 段，四路 | ⌈log₄16⌉ | 2 趟 |
| 8 段，四路 | ⌈log₄8⌉ = ⌈1.5⌉ | 2 趟 |

**答题技巧**：

```text
① 公式: 趟数 = ⌈log_K m⌉（向上取整！）
② I/O 次数 = 趟数 × 2 × 数据量（每趟读一遍写一遍）
③ 题设若给"内部排序时间 + 归并时间" → 总时间 = 两者之和
```

### 6.2 虚段与最佳归并树题

**题型**：N 个长度不等的归并段做 K 路归并，如何组织归并顺序？补几个虚段？

```text
虚段数: (N − 1) % (K − 1) == 0 → 0 个；否则补 (K−1) − (N−1)%(K−1) 个

例: N = 6 段，K = 3:
  (6−1) % 2 = 1 → 补 1 个虚段（长度 0）→ 共 7 个叶子
  构建 3 叉哈夫曼树（每轮选最短的 3 段合并）→ WPL 最小

WPL 意义: 总读次数 = WPL，总读写 ≈ 2 × WPL（软考计算题）
```

### 6.3 其他题型

| 考点 | 题型 | 要点 |
|------|------|------|
| 败者树概念 | 概念题 | 内部节点存败者（=另一侧冠军），每层 1 比较 |
| 替换-选择 | 概念题 | 段平均长 ≈ 2w（w = 内存工作区） |
| K 权衡 | 辨析题 | K 增大趟数减但缓冲内存增——非越大越好 |
| 稳定性 | 判断题 | 多路归并稳定（平局取段号小） |
| 23 题复杂度 | 计算题 | O(N log K)（堆版）/ O(N log K) 空间 O(log K)（分治版） |

## 7. 高频追问与标准回答

| # | 追问 | 标准回答 |
|:---:|------|---------|
| 1 | 为什么外部排序必须多路？ | 二路 7 趟 vs 十路 2 趟（100 段）——趟数即 I/O 次数 |
| 2 | K 值怎么定？ | 内存预算：缓冲 ≥ K+1 个，K ≈ 10~50 实践值 |
| 3 | 败者树为什么省？ | 存败者 = 另一侧冠军 → 每层 1 比较 1 访存 vs 堆 2+2 |
| 4 | 替换-选择原理？ | 输出后补入 ≥ 前值的元素留在当前段 → 平均段长 2w |
| 5 | 虚段是什么？ | 长度 0 的占位段，保证 K 叉哈夫曼树每轮恰好 K 个 |
| 6 | 23 题两种解法？ | 堆 O(K) 空间 / 分治 O(log K) 空间，都是 O(N log K) |
| 7 | 多路归并稳定吗？ | 稳定——堆比较器加路号次键，平局段号小先出 |
| 8 | 数据库怎么落地？ | MySQL filesort / PostgreSQL 外部排序 = 多路归并 + 败者树 |
| 9 | 2025-2026 有什么新进展？ | Spark SPARK-57714 败者树合并器进 4.0；SSD/NVM 感知与自适应 K |
| 10 | 和归并排序什么关系？ | 二路归并 = K=2 特例；多路是外部排序阶段的"引擎升级" |
