## 1. K 路归并模型：从二路到多路

### 1.1 二路归并的局限

二路归并每次只合并 2 个有序段。外部排序中若有 m 个归并段，需要 **⌈log₂m⌉ 趟**——每趟都要把全部数据读一遍写一遍，磁盘 I/O 随趟数线性增长：

```text
m = 100 个归并段，二路归并:
  趟数 = ⌈log₂100⌉ = 7 趟
  I/O ≈ 每趟读 100 段 + 写 100 段 → 7 趟 × 200 次读写

若一次合并 10 段（十路归并）:
  趟数 = ⌈log₁₀100⌉ = 2 趟
  I/O 减少约 70%！
```

### 1.2 K 路归并模型

```text
输入: K 个有序段（每个内部已升序）
输出: 一个完整有序序列

核心循环（K 路"选最小"）:
  ① 从 K 个段的当前头元素中选出全局最小
  ② 输出它
  ③ 从它所在的段补入下一个元素（段耗尽则退出该路）
  ④ 重复直到所有段耗尽

选最小的三种实现:
  循环遍历: 每步比较 K−1 次 → 总 O(n·K)，K 大不可用
  最小堆:   每步 O(log K) → 总 O(n·log K)，工程默认
  败者树:   O(log K) 但常数减半 → 大 K 首选（02 文件详讲）
```

> 🎯 **核心动作三连**：**入堆（K 个头）→ 弹最小（输出）→ 同路补位（保持堆 K 元素）**。与二路归并的唯一区别是"从两个头选小"变成"从 K 个头选小"——**把 merge 的双指针换成最小堆，就是多路归并的全部**。

## 2. 基本实现：堆版 K 路归并（2 分钟默写）

### 2.1 完整代码（K 路有序数组合并）

```java
/**
 * K 路归并（最小堆版）——合并 K 个升序数组
 * 时间 O(n·log K)，空间 O(K)（堆）+ O(n)（结果）
 */
public int[] mergeKSortedArrays(int[][] arrays) {
    int k = arrays.length, total = 0;
    for (int[] a : arrays) total += a.length;

    // ① 堆元素: [值, 所在路, 列下标]（按值升序）
    PriorityQueue<int[]> heap = new PriorityQueue<>((x, y) -> x[0] - y[0]);

    // ② K 个头入堆
    for (int i = 0; i < k; i++) {
        if (arrays[i].length > 0) {
            heap.offer(new int[]{arrays[i][0], i, 0});
        }
    }

    // ③ 弹最小 → 输出 → 同路补位
    int[] result = new int[total];
    int idx = 0;
    while (!heap.isEmpty()) {
        int[] top = heap.poll();                      // 弹全局最小
        result[idx++] = top[0];
        int row = top[1], col = top[2];
        if (col + 1 < arrays[row].length) {           // 同路补位（未耗尽）
            heap.offer(new int[]{arrays[row][col + 1], row, col + 1});
        }
    }
    return result;
}
```

### 2.2 三个关键实现细节

```text
① 堆元素三元组: [值, 路号, 列号] ——
   只存值无法知道"从哪路补位"（23 题链表版则存 ListNode）
② 空路不入堆: 长度为 0 的段跳过，
   否则 null/哨兵处理会污染堆
③ 补位时机: 弹出后立刻补 ——
   堆始终保持"当前 K' 路的头元素"（K' ≤ K 为未耗尽路数）
```

> 💡 **记忆技巧**：K 路归并堆版 = "**K 个头入堆 → 弹最小 → 同路补位**" 三步循环。与 23 题合并 K 个链表、多路文件归并是同一个模板的三种载体（数组/链表/文件）——**会写数组版，链表和文件版只差数据结构**。

## 3. 逐步推演：三路归并全流程

**数据**：路 0 = [1, 4, 7]，路 1 = [2, 5]，路 2 = [3, 6, 9]

| 步 | 堆内容（值,路,列） | 弹出 | 补位 | 结果 |
|:---:|------|:---:|------|------|
| 初始 | (1,0,0) (2,1,0) (3,2,0) | — | — | [] |
| 1 | (2,1,0) (3,2,0) (4,0,1) | 1 | 4 | [1] |
| 2 | (3,2,0) (4,0,1) (5,1,1) | 2 | 5 | [1,2] |
| 3 | (4,0,1) (5,1,1) (6,2,1) | 3 | 6 | [1,2,3] |
| 4 | (5,1,1) (6,2,1) (7,0,2) | 4 | 7 | [1,2,3,4] |
| 5 | (6,2,1) (7,0,2) | 5 | 路 1 耗尽 | [1,2,3,4,5] |
| 6 | (7,0,2) (9,2,2) | 6 | 9 | [1,2,3,4,5,6] |
| 7 | (9,2,2) | 7 | 路 0 耗尽 | [1,2,3,4,5,6,7] |
| 8 | — | 9 | 路 2 耗尽 | [1,2,3,4,5,6,7,9] ✓ |

> 🎯 **从推演看结构**：每个元素"入堆 1 次 + 出堆 1 次"，堆操作 O(log K)——**n 个元素 × O(log K) = O(n log K)，与段内数据无关**。路的耗尽不会影响正确性：K' 路时堆里剩 K' 个元素，继续同样的循环。

## 4. 复杂度推导：O(n·log K) 与轮数公式

### 4.1 单次归并的复杂度

```text
循环遍历法: 每输出 1 个元素比较 K−1 次 → n 个元素 O(n·K)
最小堆法:   每输出 1 个元素弹 1 次 + 补 1 次，各 O(log K)
            → n 个元素 O(n·log K)
败者树法:   O(n·log K) 但常数更小（02 文件）

内存: 堆/树 O(K) + 输入缓冲 O(K) → 总共 O(K) 级别
```

### 4.2 外部排序的总 I/O 与趟数公式

```text
趟数: 每趟把 m 个段合并为 ⌈m/K⌉ 个段 → 到 1 个段需要
      S = ⌈log_K m⌉ 趟

I/O 总量: 每趟读全部数据一遍 + 写一遍
      → 总 I/O ≈ 2 × 数据量 × S = 2·n·⌈log_K m⌉

对比:
  二路: 2·n·⌈log₂m⌉（m=100 → 14n 次读写）
  十路: 2·n·⌈log₁₀m⌉（m=100 → 4n 次读写）
  → K 从 2 到 10，I/O 减少约 71%

⚠️ 为什么外部排序拼的是 I/O 不是 CPU:
  磁盘读写比内存比较慢 5-6 个数量级，
  一趟全量读写的时间 ≈ 上百万次比较的时间
```

> 🎯 **面试必答句**："多路归并 K 路同时合并，归并趟数从二路的 ⌈log₂m⌉ 降到 ⌈log_K m⌉——**趟数决定磁盘 I/O 次数，I/O 是外部排序的瓶颈**。单次归并用最小堆 O(n log K)，败者树再优化常数。"

## 5. K 值权衡：趟数 vs 内存

### 5.1 K 增大带来的两面性

| K | 趟数（m=100） | 输入缓冲 | 单缓冲大小（内存固定） | 净效果 |
|:---:|:---:|:---:|:---:|------|
| 2 | 7 | 2 个 | 大 | 趟数多、I/O 大 |
| 10 | 2 | 10~20 个 | 中 | 趟数大幅减少 ✔ 甜点区 |
| 100 | 1 | 100+ 个 | 很小 | 一趟完成但缓冲太小 I/O 反而差 |

### 5.2 权衡的三条约束

```text
① 内存约束: 输入缓冲至少 K+1 个（2K 个更充分）
   → 内存固定时 K 增 → 每缓冲变小 → 每次读写的数据块变小 → I/O 次数变多
② 缓存约束: 堆/败者树大小 O(K) 超出 CPU 缓存 → 访存变慢
   → 败者树的"1 访存/层"优势在 K 大时更明显
③ 实践经验: 磁盘时代 K ≈ 10~50 常见；
   现代 SSD/内存数据库可以更大（2026 综述: SSD/NVM 感知的自适应 K）

⚠️ 面试表达:
"K 不是越大越好——趟数按 log_K m 减少，
但缓冲内存线性增长、每缓冲变小导致 I/O 反弹，
实践中按内存预算取 K ≈ 10~50 并配合败者树。"
```

## 6. 与二路归并对比

| 维度 | 二路归并 | 多路归并（K 路） |
|------|:---:|:---:|
| 每次合并段数 | 2 | K |
| 选最小实现 | 双指针（O(1) 比较/元素） | 堆 / 败者树（O(log K)/元素） |
| 趟数（m 段） | ⌈log₂m⌉ | ⌈log_K m⌉ |
| I/O 总量 | 2n·⌈log₂m⌉ | 2n·⌈log_K m⌉ |
| 输入缓冲 | 2 个 | K+1 ~ 2K 个 |
| 复杂度（单次） | O(n) | O(n log K) |
| 稳定性 | ✔ | ✔（平局取段号小） |
| 适用 | 内存内排序、小数据 | 外部排序、大 K 场景 |

**本质关系**：多路归并 = 二路归并的"泛化"——**K=2 时两者完全等价**（堆退化为两元素比较）。二路赢在简单（双指针零额外结构），多路赢在趟数（I/O 是外部排序的第一瓶颈）。

> 💡 面试表达："二路归并适合内存内排序（双指针、O(1) 额外比较结构）；数据超出内存时必须多路归并——**趟数从 log₂m 降到 log_K m，I/O 减少 70%+**。二路是 K=2 的多路，多路是加了'选最小数据结构'的二路。"

## 7. 手写易错点与调试技巧

| # | 易错点 | 正确写法 | 后果 |
|:---:|------|------|------|
| 1 | 堆比较器写反 | `(x, y) -> x[0] - y[0]` 升序 | 输出从大到小 |
| 2 | 忘记补位 | 弹出后同路 next 入堆 | 漏数据/堆提前空 |
| 3 | 空路入堆 | `length > 0` 才 offer | 越界或哨兵污染堆 |
| 4 | 补位越界 | `col + 1 < len` 判断 | 数组越界 |
| 5 | 堆里只存值 | 存三元组（值/路/列） | 无法确定补位来源 |
| 6 | 平局处理随意 | 相等时取段号小的 | 失去稳定性 |
| 7 | K 取太大 | 按内存预算取 K | 缓冲爆/缓存 miss/I/O 反弹 |

**调试技巧**：

```text
① 小样本验证: 三路各 2-3 个元素的数组，对照本文件推演表逐步核对
② 断言验证: 结果数组升序 + 长度 = 各路长度之和
③ 稳定性验证: 构造两路含相等元素的输入，检查相等元素按路号顺序
④ 边界验证: 空数组、单路、某路耗尽后继续归并
```

> 🎯 **核心要点**：多路归并通关四件事——**① 2 分钟默写堆版**（K 个头入堆 → 弹最小 → 同路补位，三元组记录来源）；**② 轮数公式脱口而出**（S = ⌈log_K m⌉，趟数 = I/O 次数）；**③ 说清 K 权衡**（趟数 log_K 减少 vs 缓冲线性增长，K ≈ 10~50 实践值）；**④ 会推导复杂度**（每元素堆操作 O(log K) → O(n log K)）。**它是"用一次选最小从 O(K) 变 O(log K)、用路数从 log₂m 变 log_K m"的双重优化**——外部排序提速的两大杠杆它占了一个半。
