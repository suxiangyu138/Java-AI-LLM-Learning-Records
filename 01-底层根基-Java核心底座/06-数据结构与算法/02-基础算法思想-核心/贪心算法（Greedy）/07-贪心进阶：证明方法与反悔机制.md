## 1. 贪心证明的完整方法体系

### 1.1 为什么需要证明

```
贪心的每一步"局部最优"：
  凭什么保证累积成"全局最优"？
  → 需要数学证明！

⚠️ 面试必答：
"贪心不是直觉——是证明。
 交换论证/归纳法确认贪心选择
 必然在某个最优解中。"
```

### 1.2 两种证明方法

| 方法 | 适用 | 思路 |
|------|------|------|
| 交换论证 | 有"选择序列"的问题 | 替换后不更差 |
| 数学归纳 | 分步决策问题 | 每步贪心正确 |

```
⚠️ 识别：
  "选区间/选物品" → 交换论证
  "逐步决策" → 归纳法
  ⚠️ 两种方法面试常用交换论证（更通用）
```

### 1.3 证明的通用框架

```
① 假设存在一个最优解 O
② 用贪心选择 g 替换 O 中的某个选择 → 得到 O'
③ 证明 O' 不比 O 差
④ 归纳推进：贪心解 = 最优解

⚠️ 面试表达：
"我证明贪心正确性用的是交换论证：
 假设最优解不以我的贪心选择开头，
 用贪心选择替换后结果不会更差，
 所以贪心选择可以出现在最优解中，
 反复替换得到贪心解 = 最优解。"
```

## 2. 交换论证法详解

### 2.1 435. 无重叠区间（完整证明）

```java
/**
 * LeetCode 435. 无重叠区间
 * 贪心策略：按结束时间排序，优先保留结束最早的
 *
 * 交换论证：
 * 假设最优解 O 的第一个区间是 X（非结束最早）
 * 贪心选的是 G（结束最早，G.end ≤ X.end）
 * 用 G 替换 O 中的 X：
 *   - G 结束不晚于 X → 与后续区间的冲突不更多
 *   - 保留的区间数不变
 * → 替换后解不更差 ✓
 * → 贪心选择可以出现在最优解中
 * → 归纳推进：贪心解 = 最优解 ✓
 */
public int eraseOverlapIntervals(int[][] intervals) {
    Arrays.sort(intervals, (a, b) -> a[1] - b[1]);   // 按结束排序

    int count = 0;
    int lastEnd = Integer.MIN_VALUE;

    for (int[] interval : intervals) {
        if (interval[0] >= lastEnd) {
            lastEnd = interval[1];     // 不重叠 → 保留
        } else {
            count++;                   // 重叠 → 丢弃
        }
    }
    return count;
}
// ⚠️ 面试必答：
//   "结束最早 → 让出最多空间 → 替换任何
//    最优解的第一个区间都不更差"
```

### 2.2 交换论证的变体

```
452 引爆气球：同一模型（端点相撞算重叠 → >）
56 合并区间：按开始排序（覆盖式扫描）
763 划分字母：last 扩展边界（贪心切分）

⚠️ 共性：
  "选最多/覆盖全部" 类区间问题
  → 排序键 + 交换论证
```

### 2.3 交换论证的边界

```
⚠️ 什么时候交换论证不适用？
  ① 局部最优可能危害全局（0-1 背包）
  ② 选择有"不可逆"代价（硬币找零奇葩面额）
  → 换 DP/其他

⚠️ 判断：
  "贪心选择替换后是否必然不更差？"
  是 → 贪心可行；不确定 → 保守用 DP
```

## 3. 数学归纳法详解

### 3.1 455. 分发饼干（归纳证明）

```java
/**
 * LeetCode 455. 分发饼干
 * 贪心：最小饼干满足最小胃口
 *
 * 归纳证明：
 * 基础：最小饼干 ≥ 最小胃口 → 给它
 *   （贪心最优：大饼干留给大胃口）
 *       最小饼干 < 最小胃口 → 这块饼干满足不了任何人
 *   （丢弃：它连最小胃口都满足不了）
 * 归纳：每步处理最小的饼干/胃口对，问题规模减一
 *   → 每步正确，归纳成立 ✓
 */
public int findContentChildren(int[] g, int[] s) {
    Arrays.sort(g);                    // 胃口排序
    Arrays.sort(s);                    // 饼干排序

    int child = 0, cookie = 0;
    while (child < g.length && cookie < s.length) {
        if (s[cookie] >= g[child]) {
            child++;                   // 满足一个孩子
        }
        cookie++;                      // 饼干消耗或丢弃
    }
    return child;
}
// ⚠️ 面试表达：
//   "归纳法：最小饼干要么满足最小胃口（最优），
//    要么满足不了任何人（丢弃）——每步正确"
```

### 3.2 135. 分发糖果（两趟遍历）

```java
/**
 * LeetCode 135. 分发糖果（Hard）
 * 双向约束 → 两趟遍历（每趟只处理一个方向）
 * 第二趟取 max 兼顾两个方向
 */
public int candy(int[] ratings) {
    int n = ratings.length;
    int[] candies = new int[n];
    Arrays.fill(candies, 1);        // 每人至少 1 颗

    // ① 左到右：处理"右边评分高"
    for (int i = 1; i < n; i++) {
        if (ratings[i] > ratings[i - 1]) {
            candies[i] = candies[i - 1] + 1;
        }
    }

    // ② 右到左：处理"左边评分高"（⚠️ 取 max 兼顾）
    for (int i = n - 2; i >= 0; i--) {
        if (ratings[i] > ratings[i + 1]) {
            candies[i] = Math.max(candies[i], candies[i + 1] + 1);
        }
    }

    int sum = 0;
    for (int c : candies) sum += c;
    return sum;
}
// 推演 [1,3,2,2,1]：
//   ① → [1,2,1,1,1]
//   ② → 位置 3: max(1,2)=2 → [1,2,1,2,1] → 和 7 ✓
// ⚠️ 面试必答：
//   "第二趟取 max——直接赋值会覆盖第一趟结果，
//    违反'右边评分高'的约束"
```

## 4. 反悔贪心机制

### 4.1 什么是反悔贪心

```
反悔贪心 = 贪心选择 + 堆记录历史 + 超限时替换

特点：
  每步看似贪心（选当前最优）
  但允许"撤销历史选择"（牺牲局部换全局）
  → 比纯贪心强，比 DP 简单

⚠️ 识别信号：
  "资源有限 + 每个候选有成本/收益"
  "超限时需要放弃某个已选" → 反悔贪心
```

### 4.2 630. 课程表 III（反悔贪心代表）

```java
/**
 * LeetCode 630. 课程表 III（Hard 进阶）
 * 每门课有持续时间 duration 和截止时间 lastDay
 * 求最多能修完的课程数
 *
 * 贪心 + 反悔：
 *   ① 按截止时间排序（越早截止越先安排）
 *   ② 能按时修 → 加入（贪心选择）
 *   ③ 不能按时修 → 堆里找"已修中最长的"
 *      放弃最长课程 → 总数不变但总时间更短
 *      → 为未来留空间（反悔！）
 */
public int scheduleCourse(int[][] courses) {
    Arrays.sort(courses, (a, b) -> a[1] - b[1]);   // 按截止排序

    PriorityQueue<Integer> heap = new PriorityQueue<>(
        (a, b) -> b - a);               // ⚠️ 大根堆：存已修课程时长
    int time = 0;

    for (int[] course : courses) {
        int duration = course[0], lastDay = course[1];
        time += duration;
        heap.offer(duration);           // 先加入（贪心）

        if (time > lastDay) {           // ⚠️ 超时 → 反悔
            time -= heap.poll();        // 放弃最长的课程
        }
    }
    return heap.size();                 // 堆中就是最终选的课程
}
// 推演 [[100,200],[200,1300],[1000,1250],[2000,3200]]：
//   按截止排序后逐个安排
//   超时 → 放弃已修中最长的 → 总数不变时间更短
//   结果 3 ✓
// ⚠️ 面试必答：
//   "超限时放弃最长的——总数不变但总时间
//    更短，为未来的课程留空间。堆保存
//    历史选择实现反悔。"
```

### 4.3 反悔贪心的通用模板

```java
/**
 * 反悔贪心通用模板
 * ① 排序（按截止/优先级）
 * ② 贪心选择 + 入堆
 * ③ 超限时弹出"代价最大"的（反悔）
 * ④ 堆大小 = 最优选择数
 */
public int template(int[][] items) {
    Arrays.sort(items, (a, b) -> a[1] - b[1]);   // ① 按截止排序

    PriorityQueue<Integer> heap = new PriorityQueue<>(
        (a, b) -> b - a);               // ② 大根堆（代价最大优先弹出）
    int cost = 0;

    for (int[] item : items) {
        cost += item[0];
        heap.offer(item[0]);

        if (cost > item[1]) {           // ③ 超限 → 反悔
            cost -= heap.poll();        //    放弃代价最大的
        }
    }
    return heap.size();                 // ④ 最优数量
}
// 应用：630 课程表 III、517 超级洗衣机（变体）
// ⚠️ 对比纯贪心：
//   纯贪心：选完不能改（可能错过更优组合）
//   反悔贪心：堆保存历史 → 超限时替换
```

## 5. 贪心 vs 其他算法

### 5.1 贪心 vs DP

| 维度 | 贪心 | DP |
|------|:---:|:---:|
| 决策 | 每步局部最优 | 比较所有子问题 |
| 回退 | 不可反悔（反悔贪心除外） | 可回退 |
| 复杂度 | 通常更低 | 需要状态枚举 |
| 正确性 | 需要证明 | 转移方程保证 |

```
⚠️ 面试必答：
"贪心 = DP 的特例——当局部最优选择
 必然在全局最优解中时，无需枚举所有
 子问题，贪心更高效。"
```

### 5.2 贪心 vs 排序/双指针

```
贪心常与排序/双指针结合：
  455 饼干：排序 + 双指针（贪心匹配）
  881 救生艇：排序 + 对撞（最大配最小）
  435 区间：排序（按结束）

⚠️ 90% 贪心题需要排序！
  找不到排序角度的策略往往有问题
```

### 5.3 反例识别清单

| 场景 | 能否贪心 | 原因 |
|------|:---:|------|
| 0-1 背包 | ❌ | 选物品影响后续容量 |
| 部分背包（可切分） | ✅ | 单位价值贪心正确 |
| 普通硬币找零 | ✅ | 标准面额性质 |
| 奇葩面额找零 | ❌ | 组合不灵活 |
| 区间调度 | ✅ | 结束时间排序 |
| 负权最短路 | ❌ | 需 Bellman-Ford |

## 6. 进阶总结

### 6.1 进阶要点速查

```
① 证明方法：交换论证（替换不更差）/ 归纳法（每步正确）
② 反悔贪心：贪心 + 堆 + 超限替换（630）
③ 与 DP 关系：贪心是特例（无需枚举）
④ 90% 要排序 + 反例识别

⚠️ 面试必答三句：
  "为什么贪心是对的？" → 交换论证/归纳
  "什么时候不能贪心？" → 0-1 背包反例
  "怎么进阶？" → 反悔贪心（堆）
```

### 6.2 面试话术模板

```
"这题用贪心：局部最优 =【度量标准】。
 证明：【交换论证/归纳法】——
 假设最优解不以我的选择开头，
 替换后不更差（论证过程），
 因此贪心解 = 最优解。
 进阶：反悔贪心——超限时用堆放弃
 代价最大的历史选择（630）。"
```

### 6.3 易错点清单

| 错误 | 后果 | 修正 |
|------|------|------|
| 凭直觉不证明 | 面试减分 | 交换论证 |
| 忘排序 | 策略失效 | 90% 先排序 |
| 反悔堆方向反 | 放弃错误 | 大根堆（最大代价） |
| 两趟直接赋值 | 覆盖第一趟 | 取 max |
| 反例未识别 | 答案错 | 先试 0-1 背包式反例 |

> 🎯 **核心要点**：贪心进阶 = **证明体系**（交换论证/归纳法）+ **反悔机制**（贪心+堆+超限替换）+ **边界意识**（反例识别）。"替换后不更差"是交换论证核心；630 课程表 III 是反悔贪心代表作；0-1 背包是必答反例。
