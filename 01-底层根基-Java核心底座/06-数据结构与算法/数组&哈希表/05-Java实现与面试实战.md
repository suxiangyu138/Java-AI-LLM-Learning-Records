## 2. 面试解题话术：暴力→优化模板

### 2.1 通用表达框架（两数之和演示）

```
📣 第 1 步：暴力思路 (30秒)
"最直观的做法是双重循环枚举所有数对，O(n²) 时间 O(1) 空间。
 但这在数据量大时不可行。"

📣 第 2 步：识别优化点 (30秒)
"暴力中的内层循环在做'查找补数'的工作。
 查找 → 可以用哈希表 O(1) 完成，这就是优化点。"

📣 第 3 步：哈希优化方案 (60秒)
"我维护一个哈希表 Map<值, 下标>，遍历数组时：
 ① 检查补数 target - nums[i] 是否在哈希表中；
 ② 在 → 返回配对下标；
 ③ 不在 → 把当前元素存入哈希表。
 关键细节：先查后插，防止元素匹配自身。
 时间 O(n)，空间 O(n)。"

📣 第 4 步：边界与验证 (30秒)
"边界：空数组、无解（题目保证有解）、重复元素。
 用 [3,3], target=6 验证先查后插的正确性。"
```

### 2.2 为什么"暴力→优化"是面试得分关键

```
面试官考察的不是"会不会这道题"，而是：
  ① 有没有优化意识（暴力→O(n²)→O(n)）
  ② 能不能讲清 trade-off（时间换空间）
  ③ 边界细节是否敏感（先查后插等）

话术模板："暴力 O(n²) → 内层是查找 → 哈希表 O(1) → 总 O(n)"
这个思路适用于 90% 的哈希表题
```

## 3. 高频追问与标准回答

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | 哈希表查找为什么是 O(1)？ | 哈希函数把键映射到数组下标，直接定位；冲突时链表/红黑树，均摊 O(1) |
| 2 | 哈希冲突怎么解决？ | 链地址法（Java HashMap）、开放定址（线性/二次探测）、再哈希 |
| 3 | HashMap 为什么用红黑树？ | 恶意哈希攻击/极端冲突时链表退化 O(n)，红黑树 O(log n) 兜底 |
| 4 | 负载因子 0.75 为什么？ | 泊松分布下链表长度 >8 概率约六千万分之一；0.75 是空间与时间的最优平衡 |
| 5 | 扩容为什么重新哈希？ | 数组容量变了，取模运算的除数变了，所有元素必须重新计算槽位 |
| 6 | HashMap 和 Hashtable 区别？ | HashMap 线程不安全/允许 null/性能好；Hashtable 全方法加锁/不允许 null |
| 7 | HashSet 怎么判重？ | 底层 HashMap，依赖元素的 hashCode() + equals()，两者必须同时重写 |
| 8 | 为什么 hash 要右移 16 位异或？ | 让高位参与低位运算，分布更均匀，减少冲突 |
| 9 | 哈希表能替代所有查找吗？ | 不能——无序、空间大、不支持范围查询；有序/范围场景用 TreeMap |
| 10 | 键能用可变对象吗？ | 不建议——hashCode 变化后无法定位到原槽位，HashMap 中不可变键（String/Integer） |

## 4. HashMap 源码级追问

### 4.1 put 流程口述版

```
"put(key, value) 的流程：
 ① 计算哈希：key.hashCode() 异或右移 16 位（让高位参与）；
 ② 定位槽位：hash & (capacity-1)（位运算代替取模）；
 ③ 槽位为空 → 直接插入；
 ④ 槽位有链表 → 遍历：
     键相同 → 覆盖旧值返回旧值；
     键不同 → 尾插；链表长度 > 8 且容量 ≥ 64 → 转红黑树；
 ⑤ 插入后 size > 容量 × 0.75 → resize() 扩容（容量翻倍 + rehash）"
```

### 4.2 get 流程口述版

```
"get(key) 的流程：
 ① 计算哈希定位槽位；
 ② 槽位为空 → null；
 ③ 槽位是链表 → 遍历找 equals 相等的键；
 ④ 槽位是红黑树 → 红黑树查找；
 ⑤ 找到返回 value，找不到返回 null"
```

### 4.3 常见源码参数速记

| 参数 | 值 | 追问场景 |
|------|:---:|------|
| 初始容量 | 16 | "为什么 2 的幂？"→ 位运算代替取模 |
| 负载因子 | 0.75 | "为什么 0.75？"→ 泊松分布最优 |
| 树化阈值 | 8 | "为什么 8？"→ 概率六千万分之一 |

## 5. 高频题深度复盘

### 5.1 380. O(1) 时间插入、删除和获取随机元素

```java
/**
 * LeetCode 380. O(1) 插入/删除/随机获取（设计题）
 * 哈希表 + 动态数组联动：
 *   Map<值, 数组下标> + List<值>
 *
 * 插入：list 尾部 add，map 记录下标 → O(1)
 * 随机：list.get(random) → O(1)
 * 删除：⚠️ 用"尾删换顶"技巧
 *   ① 把待删元素与末尾元素交换
 *   ② 更新末尾元素的新下标
 *   ③ 删除末尾 → O(1)（避免 list.remove(中间) 的 O(n)）
 */
class RandomizedSet {
    Map<Integer, Integer> indexMap = new HashMap<>();
    List<Integer> values = new ArrayList<>();
    Random random = new Random();

    public boolean insert(int val) {
        if (indexMap.containsKey(val)) return false;
        indexMap.put(val, values.size());   // 记录下标
        values.add(val);
        return true;
    }

    public boolean remove(int val) {
        if (!indexMap.containsKey(val)) return false;

        int idx = indexMap.get(val);             // 待删下标
        int last = values.get(values.size() - 1); // 末尾元素

        values.set(idx, last);                   // ① 末尾换到待删位置
        indexMap.put(last, idx);                 // ② 更新末尾元素下标
        values.remove(values.size() - 1);        // ③ 删除末尾
        indexMap.remove(val);                    // ④ 删除映射
        return true;
    }

    public int getRandom() {
        return values.get(random.nextInt(values.size()));
    }
}
```

**复盘要点**：**尾删换顶**是设计题的核心技巧——把 O(n) 的中间删除变成 O(1) 的末尾删除，代价是更新被换元素的下标。

### 5.2 128. 最长连续序列（复盘）

```java
public int longestConsecutive(int[] nums) {
    Set<Integer> set = new HashSet<>();
    for (int x : nums) set.add(x);
    int maxLen = 0;
    for (int x : set) {                      // 遍历 set（去重后）
        if (!set.contains(x - 1)) {          // 起点剪枝：核心
            int len = 1;
            while (set.contains(++x)) len++; // 向后扩展
            maxLen = Math.max(maxLen, len);
        }
    }
    return maxLen;
}
```

**复盘要点**：O(n) 的关键是**起点剪枝**——只有没有前驱的数才作为起点统计，每个数只统计一次。面试官追问"为什么不是 O(n²)？"时用 [1,2,3,...,n] 举例说明。

## 6. 调试技巧与自检清单

### 6.1 哈希表题自检三步法

```
第 1 步：检查键与值
  □ Map<值, 下标> 还是 Map<值, 次数>？语义对吗？
  □ 自定义对象做键时重写 hashCode + equals 了吗？

第 2 步：检查顺序
  □ 两数之和：先查后插了吗？
  □ 560 前缀和：初始化 prefixCount.put(0,1) 了吗？
  □ 128 连续序列：遍历 set 而不是数组吗？

第 3 步：检查边界
  □ 空数组 / 空字符串
  □ 全相同元素
  □ 负数 / 最大值溢出（用 long 的场景）
```

### 6.2 高频 Bug 速查表

| Bug | 原因 | 修复 |
|------|------|------|
| 两数之和返回 [0,0] | 先插后查自匹配 | 先查补数再插入 |
| 计数统计错 | getOrDefault 忘了加初始值 | `map.put(k, map.getOrDefault(k,0)+1)` |
| 连续序列 O(n²) | 没做起点剪枝 | `!set.contains(x-1)` 才统计 |
| 前缀和结果漏 | 忘初始化 {0:1} | 空前缀和为 0 |
| 旋转图像错 | 转置时 j 从 0 开始 | `j = i+1`（对角线不动） |
| 螺旋矩阵重复 | 单行/列未 break | 收缩后检查边界交叉 |
