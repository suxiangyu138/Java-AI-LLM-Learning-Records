## 1. 哈希表是什么

### 1.1 定义

> 哈希表（Hash Table）：通过**哈希函数**将键（Key）映射到存储位置（下标），实现平均 **O(1)** 的查找、插入、删除。

```
数组的进化：数组按下标 O(1) 访问
哈希表：把"任意键"通过哈希函数变成"下标"

键 "apple" ──哈希函数──→ 下标 3
键 "banana" ──哈希函数──→ 下标 7
```

### 1.2 为什么是面试之王

```
核心价值：以空间换时间
  暴力解法：内层循环扫描找元素 → O(n²)
  哈希解法：O(1) 查找补数/计数/去重 → O(n)

元模式（面试必须脱口而出）：
  "每当需要'在数组其余部分检查某元素是否存在/计数/找补数'
   时，用哈希表查找替换内层循环"
```

## 2. 哈希函数设计

### 2.1 好哈希函数的三个要求

| 要求 | 含义 |
|------|------|
| **确定性** | 相同输入必须相同输出 |
| **均匀性** | 输入均匀分布到所有槽位（减少冲突） |
| **高效性** | 计算快（O(1)） |

### 2.2 常见哈希方法

```
① 质数取模法（最常用）
   hash(key) = key % p （p 为质数，减少冲突）
   例：Java HashMap 扩容后取模

② 乘法散列（黄金分割）
   hash(key) = floor((key × φ % 1) × m)
   φ ≈ 0.618（黄金分割比），效果更好

③ 字符串哈希（多项式）
   hash(s) = Σ s[i] × base^i （base 常用 131/31）
   例：Java String.hashCode() 用 31

Java String.hashCode()：
  s[0]*31^(n-1) + s[1]*31^(n-2) + ... + s[n-1]
  为什么选 31？奇素数 + 乘法可被 JVM 优化为移位减法
```

## 3. 哈希冲突与解决方案

### 3.1 冲突必然存在

```
鸽笼原理：槽位 m < 键的数量 n 时，必然有多个键映射到同一槽位
→ 冲突（Collision）不可避免，关键是解决方案

扩展：即便 m ≥ n，哈希函数也做不到完美无冲突（如连续整数取模）
```

### 3.2 三种解决方案

```java
// ① 链地址法（拉链法）—— Java HashMap 采用
//    每个槽位是一个链表，冲突的键挂到链上
//    Java：table[i] → Node(key, value, next)
//    查找：哈希定位 → 链表遍历 O(k)（k 为链表长度）

// ② 开放定址法
//    冲突时找下一个空槽位
//    线性探测：i+1, i+2, i+3...
//    二次探测：i+1², i+2², i+3²...
//    缺点：容易聚集，删除复杂（需标记）
//    应用：ThreadLocal 的 ThreadLocalMap

// ③ 再哈希法
//    冲突时换一个哈希函数再算
//    应用：多种哈希函数备选，减少冲突
```

| 方法 | 优点 | 缺点 | 应用 |
|------|------|------|------|
| 链地址法 | 实现简单、删除容易 | 链表长时退化 | Java HashMap |
| 线性探测 | 空间利用高 | 聚集、删除复杂 | ThreadLocalMap |
| 再哈希 | 冲突率低 | 计算开销 | Redis 部分场景 |

### 3.3 链地址法的退化与升级

```
链表长度 ≤ 8 → 链表（遍历 O(k)）
链表长度 > 8 且数组容量 ≥ 64 → 红黑树（O(log k)）
  （红黑树平衡 → 最坏 O(log n)）

扩展：为什么是 8？
  泊松分布计算：负载因子 0.75 时，链表长度达到 8 的概率
  约 0.00000006（六千万分之一）→ 极低概率才转树
```

## 4. 负载因子与扩容

### 4.1 负载因子定义

```
负载因子 α = 元素数 / 数组容量

α 小 → 冲突少但空间浪费
α 大 → 空间省但冲突多
最优平衡点：0.75（Java HashMap 默认）

扩容阈值 = 容量 × 负载因子
  容量 16，α=0.75 → 元素到 12 个时触发扩容
```

### 4.2 扩容机制

```
扩容：数组容量翻倍（16→32→64...）+ 全部元素重新哈希（rehash）
  ⚠️ 必须重新哈希！因为取模运算的除数变了

扩容代价：O(n) 时间、O(n) 空间
平均摊还：每次插入摊还 O(1)（均摊分析）

面试话术：
"扩容会触发 rehash，把旧数组所有元素重新计算哈希
 放到新数组。均摊后插入仍是 O(1)。"
```

## 5. Java HashMap 底层（JDK 8）

### 5.1 数据结构

```
JDK 8 HashMap = 数组 + 链表 + 红黑树

  数组（Node<K,V>[] table）
  ┌──┬──┬──┬──┬──┬──┐
  │  │N1│  │  │N2│  │    链表 → 红黑树（>8 时）
  └──┴─┬┴──┴──┴─┬┴──┘
       N1.next  N2.next
        ↓        ↓
       N3       N4
```

### 5.2 put(key, value) 流程

```java
// ① 计算哈希：hash = (h = key.hashCode()) ^ (h >>> 16)
//    高位异或低位，让高位也参与取模（分布更均匀）

// ② 定位槽位：index = hash & (table.length - 1)
//    用 & 代替 %（容量是 2 的幂时两者等价，& 更快）

// ③ 冲突处理：
//    槽位空 → 直接放
//    槽位有值 → 遍历链表
//      键相同 → 覆盖旧值
//      键不同 → 追加到链表尾；链表 > 8 且容量 ≥ 64 → 转红黑树

// ④ 扩容检查：size > 容量 × 0.75 → resize()
```

### 5.3 关键参数速查

| 参数 | 值 | 含义 |
|------|:---:|------|
| 默认容量 | 16 | 数组初始大小 |
| 负载因子 | 0.75 | 扩容阈值系数 |
| 树化阈值 | 8 | 链表长度超 8 转红黑树 |
| 反树化阈值 | 6 | 红黑树节点少到 6 转回链表 |
| 最小树化容量 | 64 | 数组容量不足 64 先扩容不树化 |

## 6. HashMap / HashSet / Hashtable 选型

### 6.1 Java 三大哈希容器

| 容器 | 线程安全 | 允许 null | 底层 | 适用 |
|------|:---:|:---:|------|------|
| **HashMap** | ❌ | ✅ key/value | 数组+链表+红黑树 | 单线程首选 |
| **Hashtable** | ✅ 全方法加锁 | ❌ | 数组+链表 | 老代码/遗留 |
| **ConcurrentHashMap** | ✅ 分段锁/CAS | ❌ | 数组+链表+红黑树 | 并发首选 |
| **LinkedHashMap** | ❌ | ✅ | HashMap+双向链表 | 保持插入序（LRU） |
| **TreeMap** | ❌ | ✅（key 不可 null） | 红黑树 | 有序需求 |

### 6.2 HashSet 的实现

```java
// HashSet 内部就是一个 HashMap（value 用固定对象占位）
// 只用到 key，value 恒为 PRESENT
public boolean add(E e) {
    return map.put(e, PRESENT) == null;   // 返回 null = 新加入
}

// 面试常问：HashSet 判重原理
// 答：底层 HashMap 的 key 判重，依赖 hashCode() + equals()
```

### 6.3 自定义对象入 HashMap 的注意点

```
必须同时重写 hashCode() 和 equals()！
  仅重写 equals：相同对象 hashCode 不同 → 定位到不同槽位 → 判重失效
  仅重写 hashCode：不同对象可能哈希碰撞 → equals 才能区分

equals 相等 → hashCode 必须相等（反向不成立）
```

## 7. 哈希表的局限与替代

| 局限 | 说明 | 替代方案 |
|------|------|------|
| **无序** | 不保证遍历顺序 | TreeMap（红黑树） |
| **空间开销** | 数组+节点+负载因子冗余 | 数组（紧凑） |
| **范围查询** | 不支持 [a,b] 范围扫描 | 平衡 BST/数据库索引 |
| **扩容抖动** | rehash 有停顿 | ConcurrentHashMap 分段 |
| **哈希攻击** | 恶意键全冲突退化 | 随机种子/红黑树（Java 已防） |

> 🎯 **核心要点**：哈希表是面试最高频数据结构——**元模式**（哈希替换内层循环）是解题核心，**哈希函数/冲突/负载因子/扩容/红黑树化**是原理追问必背点。记住：HashMap 单线程、ConcurrentHashMap 并发、TreeMap 有序、LinkedHashMap 保序；自定义 key 必须同时重写 hashCode + equals。
