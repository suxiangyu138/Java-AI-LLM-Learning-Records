## 1. 稳定性的完整剖析

### 1.1 什么是稳定性

```
稳定：相等元素排序后相对顺序保持不变

例：[a(3), b(3), c(1)] 按值排序：
  稳定：c, a, b（a 仍在 b 前）
  不稳定：c, b, a（a、b 顺序可能颠倒）

⚠️ 为什么重要？
  二次排序：先按学号排，再按分数排
  分数相同的 → 保持学号顺序
  → 必须稳定排序！
```

### 1.2 各排序的稳定性

| 算法 | 稳定 | 原因 |
|------|:---:|------|
| 冒泡 | ✅ | 相等不交换 |
| 插入 | ✅ | 相等不越过 |
| 归并 | ✅ | merge 用 <= |
| 计数/基数/桶 | ✅ | 倒序回填 |
| 选择 | ❌ | 远距离交换 |
| 快排 | ❌ | partition 交换 |
| 堆排 | ❌ | 堆顶与末尾交换 |
| 希尔 | ❌ | 分组打乱 |

```
⚠️ 记忆："冒插归 + 三个线性 = 稳定"
   "选快希堆 = 不稳定"
```

### 1.3 为什么"不稳定"的算法不稳定

```
选择排序反例：
  [(a,5), (b,3), (c,5)]
  第一轮选最小 (b,3) 与 (a,5) 交换 → [(b,3), (a,5), (c,5)]
  第二轮选 (a,5) 与 (c,5) 交换 → [(b,3), (c,5), (a,5)]
  → a、c 顺序颠倒（远距离交换跨越相等元素）

快排反例：
  partition 时小于基准的元素与左边界交换
  → 相等元素可能被交换到不同侧

堆排反例：
  堆顶（最大）与末尾交换 → 跨越大量元素
```

## 2. 快速排序的三大优化

### 2.1 优化一：三数取中（防退化）

```java
/**
 * 问题：有序数组 + 固定基准（首/尾）→ 每次只排除一个 → O(n²)
 * 解决：取 lo、mid、hi 的中位数做基准
 */
private int medianOfThree(int[] arr, int lo, int hi) {
    int mid = lo + (hi - lo) / 2;
    // 把三个位置的中位数交换到 hi（作为 pivot）
    if (arr[lo] > arr[mid]) swap(arr, lo, mid);
    if (arr[lo] > arr[hi]) swap(arr, lo, hi);
    if (arr[mid] > arr[hi]) swap(arr, mid, hi);
    return arr[hi];       // 现在 arr[hi] 是中位数
}
// 效果：即使数组有序，基准也接近中值 → 划分均衡
// ⚠️ 面试必答："三数取中防有序数组退化成 O(n²)"
```

### 2.2 优化二：小区间插入排序

```java
/**
 * 问题：递归到小区间时，函数调用开销占比大
 * 解决：区间长度 < 阈值（10~20）改用插入排序
 */
private static final int THRESHOLD = 16;

public void quickSortOptimized(int[] arr, int lo, int hi) {
    if (hi - lo + 1 < THRESHOLD) {
        insertionSort(arr, lo, hi);   // 小区间插入
        return;
    }
    int pivotIdx = partition(arr, lo, hi);
    quickSortOptimized(arr, lo, pivotIdx - 1);
    quickSortOptimized(arr, pivotIdx + 1, hi);
}
// 效果：减少 ~20% 递归调用（实际常数优化）
// ⚠️ 这也是 TimSort 用插入的原因（小片段）
```

### 2.3 优化三：三路快排（大量重复）

```java
/**
 * 问题：大量重复元素（如全 1）时经典分区严重失衡
 * 解决：分成 < pivot / == pivot / > pivot 三部分
 */
public void quickSort3Way(int[] arr, int lo, int hi) {
    if (lo >= hi) return;
    int pivot = arr[lo];
    int lt = lo;        // < pivot 的右边界
    int gt = hi;        // > pivot 的左边界
    int i = lo + 1;

    while (i <= gt) {
        if (arr[i] < pivot) {
            swap(arr, i++, lt++);      // 小值入左
        } else if (arr[i] > pivot) {
            swap(arr, i, gt--);        // 大值入右（i 不动！）
        } else {
            i++;                       // 等于 → 留中间
        }
    }
    quickSort3Way(arr, lo, lt - 1);    // 递归 < 部分
    quickSort3Way(arr, gt + 1, hi);    // 递归 > 部分
    // == 部分不递归！
}
// 效果：重复元素多时接近线性
// ⚠️ 变体应用：75 颜色分类（荷兰国旗 = 三路思想的数组版）
```

### 2.4 优化总结

| 优化 | 解决的问题 | 效果 |
|------|------|------|
| 三数取中 | 有序数组退化 O(n²) | 划分均衡 |
| 小区间插入 | 递归调用开销 | 常数降低 |
| 三路快排 | 大量重复失衡 | 重复场景线性 |
| 随机基准 | 恶意输入攻击 | 平均保证 |

```
⚠️ 面试表达：
"快排我做了两个优化：三数取中选基准
 （防有序退化）、小区间插入排序
 （减递归开销）。三路快排处理大量
 重复元素是进阶方案。"
```

## 3. 归并排序的工程细节

### 3.1 辅助数组的复用

```java
/**
 * ⚠️ 工程优化：全局辅助数组（避免反复分配）
 * 每次 merge 都 new 一个数组 → 大量 GC
 * 全局 temp → 只分配一次
 */
public void mergeSort(int[] arr) {
    int[] temp = new int[arr.length];      // ① 全局分配一次
    sort(arr, 0, arr.length - 1, temp);
}

private void merge(int[] arr, int lo, int mid, int hi, int[] temp) {
    System.arraycopy(arr, lo, temp, lo, hi - lo + 1);   // 拷贝
    int i = lo, j = mid + 1, k = lo;
    while (i <= mid && j <= hi) {
        if (temp[i] <= temp[j]) arr[k++] = temp[i++];   // ⚠️ <= 稳定
        else arr[k++] = temp[j++];
    }
    while (i <= mid) arr[k++] = temp[i++];
    while (j <= hi)  arr[k++] = temp[j++];
}
// 面试加分："用全局辅助数组避免反复分配"
```

### 3.2 稳定性为什么是 <=

```
merge 时相等元素：
  temp[i] == temp[j] → 取左半（i++）
  → 左半元素永远先于右半相等元素
  → 相对顺序保持 ✓

如果用 <（相等取右半）→ 不稳定！

⚠️ 记忆："merge 用 <= 才稳定"
```

### 3.3 逆序对统计（归并专属应用）

```java
/**
 * 归并的隐藏能力：统计逆序对（剑指 51）
 * 合并时右半先入结果 → 与左半剩余都构成逆序对
 */
private int merge(int[] arr, int lo, int mid, int hi, int[] temp) {
    System.arraycopy(arr, lo, temp, lo, hi - lo + 1);
    int i = lo, j = mid + 1, k = lo;
    int count = 0;

    while (i <= mid && j <= hi) {
        if (temp[i] <= temp[j]) {
            arr[k++] = temp[i++];
        } else {
            count += mid - i + 1;      // ⚠️ 右半先入 → 逆序对！
            arr[k++] = temp[j++];
        }
    }
    while (i <= mid) arr[k++] = temp[i++];
    while (j <= hi)  arr[k++] = temp[j++];
    return count;
}
// 为什么"右半先入 = 逆序对"？
//   temp[j] < temp[i] → temp[j] 小于左半剩余 (mid-i+1) 个
//   → 构成 (mid-i+1) 个逆序对
```

## 4. 堆排序的原理剖析

### 4.1 建堆为什么是 O(n)

```
直觉：多数节点在底层附近 → 下沉次数少

严格推导：
  深度 d 的节点最多下沉 h-d 次
  第 d 层有 n/2^(d+1) 个节点
  总下沉 = Σ(d=0..h) n/2^(d+1) × (h-d)
          ≈ n（等比数列求和）
  → 建堆 O(n) 而非 O(n log n)

对比：n 次插入（每次上浮 O(log n)）= O(n log n)

⚠️ 面试必答：
"建堆从 n/2-1 开始下沉，总代价 O(n)——
 底层节点下沉少。插入是上浮，每次 O(log n)。"
```

### 4.2 堆排 vs 快排 vs 归并

| 维度 | 快排 | 归并 | 堆排 |
|------|:---:|:---:|:---:|
| 平均 | O(n log n) | O(n log n) | O(n log n) |
| 最坏 | O(n²) | O(n log n) | O(n log n) |
| 空间 | O(log n) | O(n) | **O(1)** |
| 稳定 | ❌ | ✅ | ❌ |
| 常数 | **最小** | 中 | 较大 |

```
为什么快排实际最快？
  ① 局部性好（顺序访问 → 缓存命中高）
  ② 无辅助数组（归并要拷贝）
  ③ 平均比较少（1.39n log n）

为什么堆排实际较慢？
  跳跃访问（父子下标跳变 → 缓存不友好）

⚠️ 面试必答：
"快排常数最小（缓存友好 + 无拷贝）；
 堆排空间最优（O(1) 原地）；
 归并稳定无退化。"
```

### 4.3 堆排的工程局限

```
① 缓存不友好（跳跃访问）
② 不稳定（堆顶远距离交换）
③ 常数大（比较次数约 2n log n）

应用场景：
  内存受限（O(1) 空间）
  优先级队列（TopK）

⚠️ Java 的 PriorityQueue 用堆
  （工程用堆做"优先队列"而非"排序"）
```

## 5. 工程实现：TimSort 与外部排序

### 5.1 Arrays.sort 的双轨设计

```
基本类型（int[]/long[]/...）→ DualPivotQuickSort（双轴快排）
  - 两个基准 → 三段划分 → 缓存友好
  - 性能极致，但不稳定

对象类型（Integer[]/String[]/...）→ TimSort（归并+插入混合）
  - 稳定！（对象的稳定性有意义）
  - 小片段（<32）用插入排序
  - 检测有序段（run）直接复用 → 近乎有序 O(n)

⚠️ 面试必答：
"为什么基本类型用快排、对象用归并？
 基本类型纯数值，稳定性无所谓 → 追求速度；
 对象排序后相对顺序有意义（二次排序）→ 必须稳定。"
```

### 5.2 TimSort 要点

```
TimSort = 归并 + 插入混合：
  ① 扫描天然有序段（run）
  ② 短 run 用插入排序补齐（最小 32）
  ③ 相邻 run 栈式归并
  ④ 近乎有序数据 → O(n)，最坏 O(n log n)
  ⑤ 稳定 → 对象排序首选

⚠️ 面试表达：
"TimSort 是归并与插入的混合——
 检测天然有序段直接复用，近乎有序时 O(n)。"
```

### 5.3 外部排序（大数据面试题）

```
问题：1TB 数据，内存 2GB，怎么排序？

步骤：
  ① 分批排序（生成顺段 Run）：
     读入内存能装的（如 1GB）→ 内存排序 → 写盘
     → 得到若干有序段
  ② 多路归并（K 路归并）：
     每段取一个元素入堆（大小 K）
     每次弹最小写结果，对应段补下一个
     → 类似 23. 合并 K 个有序链表！
  ③ 重复归并：顺段多 → 多轮归并

⚠️ 面试必答：
"外部排序 = 分批排序 + K 路归并。
 堆取最小 O(log K)；
 工业级用败者树（复用比较结果，访存更少）。"
```

```java
// K 路归并核心（与 23 题同构！）
PriorityQueue<int[]> heap = new PriorityQueue<>((a, b) -> a[0] - b[0]);
// int[] = {值, 来自哪个顺段}
// 弹最小 → 写结果 → 该段补下一个 → 重复
```

## 6. 进阶总结

### 6.1 进阶要点速查

```
① 稳定性：冒插归+线性稳定；选快希堆不稳定
   "二次排序必须稳定"
② 快排优化：三数取中/小区间插入/三路快排
③ 归并细节：全局辅助数组 + <= 稳定 + 逆序对
④ 堆排原理：建堆 O(n) 推导 + 缓存不友好
⑤ 工程：Arrays.sort 双轨 + TimSort + 外部排序
```

### 6.2 面试话术模板

```
"排序的稳定性：冒插归稳定（merge 用 <=），
 选快希堆不稳定（远距离交换）。
 手撕快排带三数取中优化；
 归并用全局辅助数组 + <= 保证稳定；
 堆排建堆 O(n)（底层下沉少）。
 工程上 Arrays.sort：基本类型双轴快排、
 对象 TimSort（稳定）。
 大数据用外部排序（分批 + 多路归并）。"
```

### 6.3 易错点清单

| 错误 | 后果 | 修正 |
|------|------|------|
| 归并用 < | 不稳定 | 用 <= |
| 快排边界错 | 死循环 | [lo,i] 与 [i+2,hi] |
| 堆排建堆起点错 | 结果错 | n/2-1 |
| 辅助数组反复 new | GC 压力 | 全局分配 |
| 外部排序用全内存 | 内存溢出 | 分批处理 |

> 🎯 **核心要点**：排序进阶 = **稳定性原理**（二次排序场景）+ **快排三优化**（取中/插入/三路）+ **工程实现**（TimSort/外部排序）。"merge 用 <= 稳定"、"建堆 O(n)"、"Arrays.sort 双轨"是三大必答点；外部排序的"分批 + 多路归并"是大数据压轴题标准答案。
