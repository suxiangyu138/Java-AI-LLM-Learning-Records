## 一、B树

### 1.1 核心特性与磁盘I/O优化

B树是一种平衡多路搜索树，专为减少磁盘I/O而设计。磁盘I/O比内存慢10万倍以上：

| 存储层级 | 访问延迟 | 对比 |
|---------|---------|------|
| L1缓存 | ~1ns | 最快 |
| 主存 | ~100ns | |
| SSD | ~100μs | 比主存慢1000倍 |
| HDD | ~10ms | 比主存慢10万倍 |

传统二叉搜索树100万数据约20层，B树通过多路分支降低树高，最小度数 $t=100$ 时仅需2~3层。节点大小与磁盘块对齐（4KB/8KB），利用磁盘预读提升吞吐。

### 1.2 节点定义

一棵B树最小度数 $t \geq 2$，核心属性如下：

| 属性 | 含义 | Java类型 |
|------|------|---------|
| $n(x)$ | 当前节点键值对数量 | `int` |
| $keys[x]$ | 长度为 $2t-1$ 的有序键数组 | `K[]` |
| $values[x]$ | 与键对应的值数组 | `V[]` |
| $children[x]$ | 长度为 $2t$ 的子节点指针数组 | `Node[]` |
| $leaf[x]$ | 是否为叶节点 | `boolean` |

| 节点类型 | 最少键数 | 最多键数 |
|---------|---------|---------|
| 根节点 | 1 | $2t-1$ |
| 非根节点 | $t-1$ | $2t-1$ |

### 1.3 查找操作

```java
class BTreeNode<K extends Comparable<K>, V> {
    private int t;
    private K[] keys;
    private V[] values;
    private BTreeNode<K, V>[] children;
    private boolean isLeaf;
    private int keyCount;

    @SuppressWarnings("unchecked")
    public BTreeNode(int t, boolean isLeaf) {
        this.t = t;
        this.isLeaf = isLeaf;
        this.keys = (K[]) new Comparable[2 * t - 1];
        this.values = (V[]) new Object[2 * t - 1];
        this.children = new BTreeNode[2 * t];
        this.keyCount = 0;
    }

    // 查找方法（线性遍历，优先用二分查找优化）
    public V search(K key) {
        int i = 0;
        while (i < keyCount && key.compareTo(keys[i]) > 0) i++;
        if (i < keyCount && key.compareTo(keys[i]) == 0) return values[i];
        if (isLeaf) return null;
        return children[i].search(key);
    }
}

class BTree<K extends Comparable<K>, V> {
    private BTreeNode<K, V> root;
    private int t;

    public BTree(int t) { this.t = t; this.root = new BTreeNode<>(t, true); }
    public V search(K key) { return root.search(key); }
}
```

### 1.4 插入操作（分裂）

插入需保证节点不溢出（键数不超过 $2t-1$）。路径上遇满节点先分裂，再递归向下。

```java
private void splitChild(BTreeNode<K, V> parent, int childIndex) {
    BTreeNode<K, V> full = parent.children[childIndex];
    BTreeNode<K, V> child = new BTreeNode<>(t, full.isLeaf);
    child.keyCount = t - 1;
    for (int i = 0; i < t - 1; i++) {
        child.keys[i] = full.keys[i + t];
        child.values[i] = full.values[i + t];
    }
    if (!full.isLeaf) {
        for (int i = 0; i < t; i++) child.children[i] = full.children[i + t];
    }
    for (int i = parent.keyCount; i > childIndex; i--) {
        parent.children[i + 1] = parent.children[i];
        parent.keys[i] = parent.keys[i - 1];
        parent.values[i] = parent.values[i - 1];
    }
    parent.keys[childIndex] = full.keys[t - 1];
    parent.values[childIndex] = full.values[t - 1];
    parent.children[childIndex + 1] = child;
    parent.keyCount++;
    full.keyCount = t - 1;
}

public void insert(K key, V value) {
    BTreeNode<K, V> r = root;
    if (r.keyCount == 2 * t - 1) {
        BTreeNode<K, V> newRoot = new BTreeNode<>(t, false);
        root = newRoot;
        newRoot.children[0] = r;
        splitChild(newRoot, 0);
        insertNonFull(newRoot, key, value);
    } else {
        insertNonFull(r, key, value);
    }
}

private void insertNonFull(BTreeNode<K, V> node, K key, V value) {
    int i = node.keyCount - 1;
    if (node.isLeaf) {
        while (i >= 0 && key.compareTo(node.keys[i]) < 0) {
            node.keys[i + 1] = node.keys[i];
            node.values[i + 1] = node.values[i];
            i--;
        }
        node.keys[i + 1] = key;
        node.values[i + 1] = value;
        node.keyCount++;
    } else {
        while (i >= 0 && key.compareTo(node.keys[i]) < 0) i--;
        i++;
        if (node.children[i].keyCount == 2 * t - 1) {
            splitChild(node, i);
            if (key.compareTo(node.keys[i]) > 0) i++;
        }
        insertNonFull(node.children[i], key, value);
    }
}
```

### 1.5 删除操作

需保证节点不欠载（键数不小于 $t-1$）：

| 情况 | 处理方式 |
|------|---------|
| 叶节点且键数 $\geq t$ | 直接删除 |
| 叶节点且键数 $= t-1$（欠载） | 向兄弟借键或合并节点 |
| 非叶节点 | 用前驱/后继替换后再删除 |

### 1.6 B+树对比与后端应用

| 对比维度 | B树 | B+树（MySQL InnoDB） |
|---------|-----|-------------------|
| 数据存储 | 所有节点均可存数据 | 仅叶节点存数据 |
| 内部节点 | 存数据+索引 | 仅存索引键 |
| 叶节点链接 | 无 | 双向链表链接 |
| 范围查询 | 需中序遍历 | 链表直接遍历 |

**后端应用**：MySQL InnoDB B+树索引（主键优先自增Long）；HBase Region索引（B+树）；RocksDB LSM-Tree；自定义缓存（节点与磁盘块对齐、LRU淘汰、分段锁）。

**性能优化**：$t$ 设为100~1000；使用自增ID避免频繁分裂；热点节点缓存到内存。

## 二、van Emde Boas树

### 2.1 适用场景

vEB树针对**有界整数集合**高效操作，key为 $0 \sim U-1$ 的整数（$U$ 为2的幂）。

| 应用场景 | 说明 |
|---------|------|
| 分布式ID生成 | 雪花算法workerId/sequenceId快速分配 |
| IP路由表 | IPv4地址转为 $0 \sim 2^{32}-1$ 整数 |
| 图算法优化 | Dijkstra节点权重快速更新 |
| 高频整数去重 | 用户/订单ID快速校验与范围查询 |

> 若key非整数或 $U$ 极大而元素极少，vEB树空间开销成为瓶颈，适用HashMap/TreeMap。

### 2.2 核心结构（递归分割）

```java
public class VEBNode {
    private int u;                    // 全域大小（2的幂）
    private Integer min;              // 最小值
    private Integer max;              // 最大值
    private VEBNode summary;          // 摘要树：记录子簇是否非空
    private VEBNode[] clusters;       // 子簇：拆分为 √u 个小全域

    public VEBNode(int u) {
        this.u = u;
        if (u > 2) {
            int cs = (int) Math.sqrt(u);
            this.summary = new VEBNode(cs);
            this.clusters = new VEBNode[cs];
            for (int i = 0; i < cs; i++) clusters[i] = new VEBNode(cs);
        }
    }
    private int high(int key) { return key / (int) Math.sqrt(u); }
    private int low(int key)  { return key % (int) Math.sqrt(u); }
    private int index(int h, int l) { return h * (int) Math.sqrt(u) + l; }
}
```

### 2.3 核心操作

```java
// 插入：O(log log U)
public void insert(int key) {
    if (min == null) { min = key; max = key; return; }
    if (key < min) { int t = key; key = min; min = t; }
    if (u > 2) {
        int h = high(key), l = low(key);
        if (clusters[h].min == null) summary.insert(h);
        clusters[h].insert(l);
    }
    if (key > max) max = key;
}

// 查找：O(log log U)
public boolean contains(int key) {
    if (min == null) return false;
    if (key == min || key == max) return true;
    if (u <= 2) return false;
    return clusters[high(key)].contains(low(key));
}

// 后继查找：高频需求——下一可用ID
public Integer successor(int key) {
    if (min == null || key >= max) return null;
    if (key < min) return min;
    if (u == 2) return max;
    int h = high(key), l = low(key);
    Integer sub = clusters[h].successor(l);
    if (sub != null) return index(h, sub);
    Integer next = summary.successor(h);
    if (next == null) return null;
    return index(next, clusters[next].min);
}
```

### 2.4 复杂度本质

| 原理 | 说明 | 举例（$U=2^{32}$） |
|------|------|------------------|
| 递归分割 | 全域拆分为 $\sqrt{U}$ 个子全域 | 递归深度 $\log_2 32 = 5$ |
| 摘要树优化 | 记录子簇非空状态 | 查找非空子簇 $O(\log \log U)$ |
| 与红黑树对比 | $n$ 接近 $U$ 时优势显著 | $\log n \approx 30$ vs $5$ |

| 对比维度 | vEB树 | TreeMap（红黑树） |
|---------|-------|-----------------|
| 插入 | $O(\log \log U)$ | $O(\log n)$ |
| 查找后继 | $O(\log \log U)$ | $O(\log n)$ |
| 递归深度（$U=2^{32}$） | 5层 | ~30层 |

### 2.5 空间优化（懒加载子簇+哈希表）

原始vEB树空间 $O(U)$，$U=2^{32}$ 时开销极大。优化后降至 $O(n \log \log U)$。

```java
public class OptimizedVEBNode {
    private int u;
    private Integer min, max;
    private OptimizedVEBNode summary;
    private Map<Integer, OptimizedVEBNode> clusters;  // 仅非空子簇

    public OptimizedVEBNode(int u) {
        this.u = u;
        this.clusters = new HashMap<>();
        if (u > 2) this.summary = new OptimizedVEBNode((int) Math.sqrt(u));
    }

    public void insert(int key) {
        if (min == null) { min = key; max = key; return; }
        if (key < min) { int t = key; key = min; min = t; }
        if (u > 2) {
            int h = high(key), l = low(key);
            if (!clusters.containsKey(h)) {
                clusters.put(h, new OptimizedVEBNode((int) Math.sqrt(u)));
                summary.insert(h);
            }
            clusters.get(h).insert(l);
        }
        if (key > max) max = key;
    }
}
```

> 效果：$U=2^{32}$、$n=10^6$ 时空间仅几MB。

### 2.6 后端应用场景

| 场景 | 方案 | 优势 |
|------|------|------|
| 分布式ID生成 | vEB树存已用ID，后继操作找下一可用ID | $O(\log \log U)$ 分配时间 |
| IP路由查找 | IP转整数key，路由规则value | 查找 $O(5)$，千万级QPS |
| Dijkstra优化 | 权重为key，节点ID为value | 提取最小元素 $O(1)$ |

## 三、高级数据结构总览

### 3.1 红黑树（TreeMap/TreeSet）

5条着色规则维持平衡：节点非红即黑；根节点黑色；叶节点黑色；红节点子节点必为黑；任意节点到叶子的黑节点数相同。

| TreeMap方法 | 时间复杂度 | 后端场景 |
|-------------|-----------|---------|
| `put(K, V)` | $O(\log n)$ | 新增/更新有序数据 |
| `get(Object)` | $O(\log n)$ | 有序数据查询 |
| `subMap(K, K)` | $O(\log n)$ | 时间范围筛选 |
| `lastKey()` / `firstKey()` | $O(\log n)$ | 获取极值 |

**避坑**：Key必须可比较（优先String/Long）；Key不可为null；多线程用ConcurrentSkipListMap替代；无需有序用HashMap。

### 3.2 B+树（MySQL InnoDB索引）

B+树是B树变种，核心优化是减少磁盘IO：

| 特性 | 后端价值 |
|------|---------|
| 多路分支 | 树高极低，亿级数据仅3~4层 |
| 叶节点有序连续、链表连接 | 极大提升范围查询效率 |
| 非叶节点仅存索引 | 减少磁盘IO数据量 |

```sql
CREATE TABLE `user` (
  `id` bigint NOT NULL,
  `username` varchar(50) NOT NULL,
  `age` int DEFAULT NULL,
  `create_time` datetime NOT NULL,
  PRIMARY KEY (`id`) USING BTREE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 覆盖索引避免回表
ALTER TABLE `user` ADD KEY `idx_username_age` (`username`, `age`) USING BTREE;
SELECT username, age FROM `user` WHERE username = 'Java后端';  -- 无需回表
```

### 3.3 散列表进阶（ConcurrentHashMap）

| 要素 | Java实现 | 优化方向 |
|------|---------|---------|
| 哈希函数 | hashCode() | 自定义Key重写 hashCode()+equals() |
| 冲突解决 | 链表法+红黑树（JDK1.8） | 链表 $\to$ 红黑树（$\geq 8$时） |
| 负载因子 | 默认0.75 | 根据业务调整 |

**核心优化**：CAS + synchronized对桶头节点加锁；容量为2的幂，高位哈希值减少元素移动。

**避坑**：自定义Key必须同时重写hashCode/equals；不可用可变对象作为Key；大数据量提前设初始容量。

### 3.4 跳表（ConcurrentSkipListMap / Redis Sorted Set）

有序概率性数据结构，优势：有序 + 高并发 + 高效操作。

| 特性 | 后端价值 |
|------|---------|
| 有序性 | 支持有序遍历和范围查询 |
| 分层索引 | 平均 $O(\log n)$ |
| 并发友好（无旋转操作） | 适合高并发场景 |

**Redis Sorted Set应用（排行榜）**：
```java
@Component
public class UserScoreRank {
    @Resource
    private RedisTemplate<String, Object> redisTemplate;
    private static final String KEY = "user:score:rank";

    public void updateScore(String userId, double score) {
        redisTemplate.opsForZSet().add(KEY, userId, score);
    }
    public Set<Object> getTopN(int n) {
        return redisTemplate.opsForZSet().reverseRange(KEY, 0, n - 1);
    }
    public Long getRank(String userId) {
        return redisTemplate.opsForZSet().reverseRank(KEY, userId);
    }
}
```

## 四、不相交集合（并查集）

### 4.1 核心操作

不相交集合（Disjoint-Set / Union-Find）维护互不重叠的动态集合：

| 操作 | 定义 | 后端含义 |
|------|------|---------|
| `MAKE-SET(x)` | 创建仅含 $x$ 的新集合 | 初始化独立元素 |
| `FIND-SET(x)` | 查询 $x$ 所属集合的代表元素 | 判断元素归属 |
| `UNION(x, y)` | 合并 $x$ 和 $y$ 所在集合 | 建立元素关联 |

### 4.2 森林表示法（路径压缩 + 按秩合并）

均摊复杂度 $O(\alpha(n))$（反阿克曼函数，$\alpha(n) \leq 5$，接近常数时间）。

```java
public class DisjointSetForest<T> {
    private final Map<T, T> parent = new HashMap<>();
    private final Map<T, Integer> rank = new HashMap<>();
    private int setCount = 0;

    public void makeSet(T x) {
        if (x == null) throw new NullPointerException();
        if (!parent.containsKey(x)) {
            parent.put(x, x);
            rank.put(x, 0);
            setCount++;
        }
    }

    // FIND-SET + 路径压缩（递归版）
    public T findSet(T x) {
        if (x == null) throw new NullPointerException();
        if (!parent.containsKey(x))
            throw new NoSuchElementException("元素" + x + "未创建集合");
        if (!parent.get(x).equals(x))
            parent.put(x, findSet(parent.get(x)));
        return parent.get(x);
    }

    // UNION + 按秩合并
    public void union(T x, T y) {
        T rootX = findSet(x), rootY = findSet(y);
        if (rootX.equals(rootY)) return;
        int rX = rank.get(rootX), rY = rank.get(rootY);
        if (rX < rY)      parent.put(rootX, rootY);
        else if (rX > rY) parent.put(rootY, rootX);
        else              { parent.put(rootY, rootX); rank.put(rootX, rX + 1); }
        setCount--;
    }

    public boolean isConnected(T x, T y) { return findSet(x).equals(findSet(y)); }
    public int getSetCount() { return setCount; }
}
```

### 4.3 迭代版FIND（避免栈溢出）

百万级以上元素时，递归版可能栈溢出。使用两趟法：第一趟找根，第二趟压缩路径。

```java
public T findSet(T x) {
    if (x == null) throw new NullPointerException();
    if (!parent.containsKey(x))
        throw new NoSuchElementException();
    // 第一趟：找根节点
    T root = x;
    while (!parent.get(root).equals(root)) root = parent.get(root);
    // 第二趟：路径上所有节点指向根
    while (!parent.get(x).equals(root)) {
        T next = parent.get(x);
        parent.put(x, root);
        x = next;
    }
    return root;
}
```

### 4.4 数组优化版（连续整数场景）

元素为连续整数（如用户ID 0..n-1）时，用数组替代HashMap消除额外开销：

```java
public class OptimizedDSU {
    private int[] parent, rank;

    public OptimizedDSU(int n) {
        parent = new int[n];
        rank = new int[n];
        for (int i = 0; i < n; i++) { parent[i] = i; rank[i] = 1; }
    }

    public int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]);
        return parent[x];
    }

    public void union(int x, int y) {
        int rx = find(x), ry = find(y);
        if (rx == ry) return;
        if (rank[rx] > rank[ry])      parent[ry] = rx;
        else if (rank[rx] < rank[ry]) parent[rx] = ry;
        else                          { parent[ry] = rx; rank[rx]++; }
    }

    public boolean isConnected(int x, int y) { return find(x) == find(y); }
}
```

### 4.5 后端应用场景

**用户关系合并（权限系统）**：
```java
public class PermissionService {
    private final DisjointSetForest<Long> dsu = new DisjointSetForest<>();
    public void assignRole(Long userId, Long roleId) { dsu.union(userId, roleId); }
    public void assignPermission(Long roleId, Long permId) { dsu.union(roleId, permId); }
    public boolean hasPermission(Long userId, Long permId) { return dsu.isConnected(userId, permId); }
}
```

**分布式节点连通性检测**：`DisjointSetForest<String>`，建链时 `union`，检测时 `isConnected`。

**数据去重**：每条数据唯一标识作为元素，相同主体执行 `union`，最终 `setCount` 为不重复数据集个数。

**Kruskal最小生成树**：
```pseudocode
for each edge (u, v) in sorted edges:
    if findSet(u) != findSet(v):
        union(u, v)
        add edge to MST
```

**朋友圈问题（连通分量统计）**：
```java
public class FriendCircle {
    public int findCircleNum(int[][] isConnected) {
        int n = isConnected.length;
        OptimizedDSU dsu = new OptimizedDSU(n);
        for (int i = 0; i < n; i++)
            for (int j = i + 1; j < n; j++)
                if (isConnected[i][j] == 1) dsu.union(i, j);
        int count = 0;
        for (int i = 0; i < n; i++) if (dsu.find(i) == i) count++;
        return count;
    }
}
```

### 4.6 避坑指南

| 问题 | 现象 | 方案 |
|------|------|------|
| 元素未初始化 | NoSuchElementException | 操作前先 makeSet |
| 线程安全 | 高并发结果错误 | ConcurrentHashMap + synchronized |
| 栈溢出 | StackOverflowError | 统一使用迭代版 findSet |
| 空间占用过大 | JVM内存溢出 | 连续整数用数组替代HashMap |

| 跳表 | 分布式有序场景 | ConcurrentSkipListMap / Redis ZSet | 并发友好，实现简单 |
| B树 | 文件系统/大块读写 | RocksDB、WiredTiger | 多路分支降低树高 |
| vEB树 | 有界整数集合 | 需自定义实现 | $O(\log \log U)$ 极致性能 |
| 并查集 | 动态连通性判定 | DisjointSetForest（自定义） | 均摊 $O(\alpha(n))$，极简 |
| 树状数组/线段树 | 区间统计 | Fenwick / Segment Tree | 高频区间查询与修改 |
| 字典树 | 字符串前缀匹配 | 自定义实现 | 按字符逐层存储 |
| 布隆过滤器 | 缓存穿透防护 | Guava BloomFilter | 空间极省 |
| 一致性哈希 | 分布式缓存路由 | TreeMap模拟 | 增减节点最少迁移 |

### 5.3 核心总结

| 数据结构 | 一句话定位 | 时间复杂度 | 空间复杂度 |
|---------|-----------|:---------:|:---------:|
| B树 | 多路平衡搜索树，降低磁盘I/O | $O(\log_t n)$ | $O(n)$ |
| B+树 | 仅叶节点存数据，范围查询极优 | $O(\log_t n)$ | $O(n)$ |
| vEB树 | 有界整数集合，递归分割+摘要树 | $O(\log \log U)$ | $O(U)$ / 优化后 $O(n \log \log U)$ |
| 红黑树 | 着色规则弱平衡，综合效率最高 | $O(\log n)$ | $O(n)$ |
| 跳表 | 有序概率结构，并发友好 | $O(\log n)$ | $O(n \log n)$ |
| 散列表 | 哈希+冲突解决，均摊常数访问 | $O(1)$ 均摊 | $O(n)$ |
| 并查集 | 动态连通性判定，路径压缩+按秩合并 | $O(\alpha(n))$ | $O(n)$ |

> **总结**：高级数据结构各有适用场景。B树/B+树解决磁盘I/O瓶颈；vEB树在有界整数场景提供极致性能；红黑树与跳表应对有序与并发需求；散列表满足高频缓存；并查集以极简实现处理连通性问题。后端开发应"理论服务于工程"——聚焦场景、精准选型、熟练使用成熟实现。
