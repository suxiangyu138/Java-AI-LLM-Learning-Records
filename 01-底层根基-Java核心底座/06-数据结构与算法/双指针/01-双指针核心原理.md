## 1. 双指针的本质

### 1.1 定义

> 双指针：使用**两个下标（或节点引用）**协同遍历，通过指针的移动策略消除冗余计算，将时间复杂度从 O(n²) 降到 O(n)。

```
暴力解法：枚举所有 (i, j) 对 → O(n²) 种组合
双指针：两个指针各自单调移动 → 总共 O(n) 次移动
       （每个指针最多移动 n 次 → 2n → O(n)）
```

### 1.2 核心思想：信息复用

```
暴力为什么浪费？
  枚举 (1,2), (1,3), (1,4)... 每次都重新计算
  前一轮的判断结果没有传递给下一轮

双指针为什么高效？
  指针移动时"继承"前一轮的信息
  每次移动排除一批不可能的解（剪枝）
  → 每个指针最多移动 n 次 → O(n)
```

## 2. 三大模式总览

### 2.1 模式一：对撞指针（相向而行）

```java
// 适用：有序数组、回文、面积/容量问题
int left = 0, right = arr.length - 1;
while (left < right) {
    // 处理 arr[left] 和 arr[right]
    if (满足条件A) left++;
    else right--;
}
```

| 特征 | 说明 |
|------|------|
| 指针方向 | 两端向中间 |
| 适用场景 | 有序数组找两数、回文验证、最大面积 |
| 典型题 | 167/11/15/125/344 |

### 2.2 模式二：快慢指针（同向而行）

```java
// 适用：原地修改、链表问题
int slow = 0;
for (int fast = 0; fast < n; fast++) {
    if (保留条件(arr[fast])) {
        arr[slow++] = arr[fast];   // slow 慢写，fast 快读
    }
}
```

| 特征 | 说明 |
|------|------|
| 指针方向 | 同向前进 |
| 适用场景 | 原地去重/移动、链表环/中点 |
| 典型题 | 27/283/141/876/19 |

### 2.3 模式三：滑动窗口（同向+区间）

```java
// 适用：连续子数组/子串问题（详见滑动窗口子体系）
int left = 0;
for (int right = 0; right < n; right++) {
    // 扩窗：加入 arr[right]
    while (窗口不合法) {
        // 缩窗：移除 arr[left]
        left++;
    }
    // 更新答案
}
```

| 特征 | 说明 |
|------|------|
| 指针方向 | 同向 + 维护区间 |
| 适用场景 | 连续子数组/子串、单调性问题 |
| 典型题 | 3/76/209 |

## 3. 为什么是 O(n)：信息复用

### 3.1 对撞指针的移动次数

```
对撞指针：left 和 right 总共移动多少次？
  left 从 0 → n（最多 n 次）
  right 从 n → 0（最多 n 次）
  两者加起来 2n 次 → O(n)

对比暴力：枚举 (i,j) 对 → n² 次 → O(n²)

关键：每一轮 left 或 right 必有一个移动，
      每次移动排除掉一批不可能的解
```

### 3.2 快慢指针的移动次数

```
快慢指针：fast 遍历一次 n 次，slow 最多写 n 次
  总共 O(n) 操作 → O(n)

对比暴力：每插入一个元素都整体移动 → O(n²)
```

### 3.3 直觉理解

```
对撞指针像"会师"：两个人从两端相向走，每一步排除
  "不可能包含答案"的一侧区间 → 必然相遇

快慢指针像"过滤"：一个负责扫描（fast），一个负责
  记录（slow），扫描一遍完成原地变换
```

## 4. 对撞指针的正确性：单调性

### 4.1 面试必答："为什么双指针是对的？"

```
以 167 两数之和 II（有序数组）为例：

状态：left 指向最小值方向，right 指向最大值方向
  当前和 sum = nums[left] + nums[right]

① sum < target → 需要更大的和
   只有移动 left（向右，值变大）才能增大和
   → 排除所有以 nums[left] 为左端点的组合！✓

② sum > target → 需要更小的和
   只有移动 right（向左，值变小）才能减小和
   → 排除所有以 nums[right] 为右端点的组合！✓

③ sum == target → 找到答案

数学依据：有序性 → 指针移动方向与和的变化方向单调对应
这就是"单调性"——双指针正确性的根源
```

### 4.2 盛水容器的单调性（11 题）

```
容量 = min(左高, 右高) × 宽度

为什么移动矮边？
  当前容量由矮边决定（短板效应）
  移动高边 → 宽度变小，高度不变（还是矮边）→ 容量必变小
  移动矮边 → 宽度变小，但高度可能变大 → 容量可能变大
  → 只有移动矮边才有希望找到更优解
  → 排除所有以矮边为边界、另一侧更高的组合 ✓

这是"排除不可能解"的典型论证：数学上证明被排除的
组合中不可能存在最优解 → 指针可以安全移动
```

### 4.3 单调性失效的场景

```
⚠️ 双指针不是万能的：
  无序数组找两数之和 → 无法判断移动方向 → 需哈希表/排序
  含负数的子数组和 → 滑窗不单调 → 前缀和+哈希
  （详见滑动窗口体系的"失效场景"）

判断标准：指针移动时能否"安全排除"一批解？
  能 → 双指针；不能 → 换思路
```

## 5. 模式判定指南

### 5.1 30 秒判定

```
拿到题 → 按顺序问：

① 链表题？
   判环/中点/倒数第N → 快慢指针

② 连续子数组/子串？
   + 单调性 → 滑动窗口

③ 数组且有序？
   找两数/三数 → 对撞指针

④ 原地修改数组？
   去重/移动零/移除元素 → 快慢指针

⑤ 面积/容量最大化？
   对撞（短板效应）
```

## 6. 常见错误与调试

### 6.1 高频 Bug

| 错误 | 后果 | 修正 |
|------|------|------|
| 对撞循环用 `<=` | 单元素重复处理 | 用 `left < right` |
| 忘记 left++/right-- | 死循环 | 每轮必有指针移动 |
| 快慢循环条件漏判 | 越界 | `while (fast != null && fast.next != null)` |
| slow 位置语义混淆 | 结果错 | 明确 slow 是"下一个写入位置" |
| 三数之和忘记去重 | 重复结果 | 固定数和双指针都去重 |

### 6.2 调试三步法

```
第 1 步：小数组手推
  [1,2,3,4,5] 推演指针移动轨迹

第 2 步：边界验证
  空数组 / 单元素 / 全相同 / 全逆序

第 3 步：不变量检查
  每一轮循环后，指针的语义是否保持？
  （对撞：排除区间是否正确？快慢：slow 前是否满足条件？）
```

> 🎯 **核心要点**：双指针的本质是**信息复用 + 安全排除**——每轮移动排除一批不可能的解，每个指针最多移动 n 次，所以 O(n)。面试被问"为什么正确"时，用单调性论证（移动方向与解的变化方向对应）。判定口诀：**有序找两数→对撞，原地修改→快慢，连续子串→滑窗，链表→快慢**。
