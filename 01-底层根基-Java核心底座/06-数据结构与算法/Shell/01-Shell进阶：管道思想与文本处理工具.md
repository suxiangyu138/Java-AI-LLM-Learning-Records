## 1. 管道与过滤器思想

### 1.1 管道哲学

```
Unix 哲学：一个工具做一件事，管道串联
  cmd1 | cmd2 | cmd3
  （cmd1 输出 → cmd2 输入 → cmd3 输出）

⚠️ 面试必答：
"Shell 编程 = 管道串联过滤器——
 每个命令是'过滤器'（输入 → 处理 → 输出），
 管道把它们串成流水线。"
```

### 1.2 管道 vs 重定向

```
管道 |：前命令输出 → 后命令输入（内存传递）
重定向 > / <：输出/输入 → 文件（磁盘）

⚠️ 面试必答：
"管道是'进程间流'、重定向是'文件'——
 统计词频的经典管道：
 cat file | tr -s ' ' '\n' | sort | uniq -c | sort -rn
（192 题的核心骨架）。"
```

## 2. 核心工具速查

### 2.1 文本处理五兄弟

| 工具 | 作用 | 常用 |
|------|------|------|
| grep | 行匹配 | grep 'pattern' file |
| sed | 流编辑 | sed -n '10p' |
| awk | 列处理 | awk '{print $2}' |
| tr | 字符转换 | tr 'a-z' 'A-Z' |
| sort/uniq | 排序去重 | sort -rn \| uniq -c |

```
⚠️ 面试必答：
"文本五工具——grep 找行、sed 改流、
 awk 拆列、tr 转字符、sort/uniq 排序统计。
 LeetCode Shell 四题全是它们的组合。"
```

### 2.2 sort 与 uniq 的配合

```bash
# uniq 只去"相邻重复" → 必须先 sort！
cat words.txt | sort | uniq -c        # 统计词频（含计数）
cat words.txt | sort | uniq -c | sort -rn   # 按频次降序

# ⚠️ uniq 选项：
uniq -c        # 加计数
uniq -d        # 只显重复
uniq -u        # 只显唯一
# ⚠️ 面试必答："uniq 的前提是排序——
#   只合并相邻行；统计频次 = sort | uniq -c。"
```

## 3. 正则表达式体系

### 3.1 基础语法

```
字符类：[abc] / [a-z] / [^0-9]
量词：*（0+）、+（1+）、?（0/1）、{n,m}
锚点：^ 开头、$ 结尾
分组：() 与 |
转义：\.

⚠️ 常用模式：
  ^[0-9]+$     全数字
  ^[a-zA-Z]+$  全字母
  \(...\)      转义括号（grep 基础版）
```

### 3.2 grep 的正则模式

```
⚠️ grep 两种模式：
  grep 'pattern' file     基础正则（BRE）
  grep -E 'pattern' file  扩展正则（ERE，推荐）

⚠️ 面试必答：
"grep -E 用扩展正则（+、|、? 直接可用）；
 基础正则要转义（\+、\|）。193 电话号码
 就是 grep -E 的匹配题。"
```

## 4. awk：文本处理的瑞士军刀

### 4.1 awk 编程模型

```
awk 'pattern { action }' file
  逐行处理：
    读一行 → 按分隔符拆字段（$1, $2, ...）
    匹配 pattern → 执行 action

⚠️ 内置变量：
  $0 整行、$1..$n 字段
  NR 行号、NF 字段数
  FS 输入分隔符（默认空格）、OFS 输出分隔符

⚠️ 面试必答：
"awk = 逐行 + 按列处理——
 $1 第一列、NR 行号、FS 自定义分隔符；
 '模式-动作'模型是 awk 的灵魂。"
```

### 4.2 awk 的进阶用法

```bash
# 自定义分隔符
awk -F',' '{print $2}' file        # 逗号分隔取第 2 列

# 二维数组（194 转置文件的核心）
awk '{ for (i=1; i<=NF; i++) a[NR, i] = $i } END { ... }'

# 条件处理
awk '$1 > 100 {print}' file        # 第一列 > 100 的行

# ⚠️ 面试必答："awk 二维数组 = 转置文件
#   （194）的标准解法——a[行,列] 存储
#   后按列输出。"
```

## 5. sed：流编辑器

### 5.1 sed 基础

```
sed 's/旧/新/g' file      替换（g = 全局）
sed -n '10p' file         打印第 10 行（195 题）
sed -n '2,5p' file        打印 2-5 行
sed '/pattern/d' file     删除匹配行

⚠️ -n：静默模式（不自动打印）→ 配合 p 精确输出

⚠️ 面试必答：
"sed 三常用——替换 s///g、定位打印
 -n 'Np'、删除 /d；
 195 第十行 = sed -n '10p'。"
```

### 5.2 边界处理

```
# 195 第十行（文件可能不足 10 行 → 无输出）
sed -n '10p' file.txt

# ⚠️ 替代方案：
awk 'NR==10' file.txt          # awk 版
head -10 file | tail -1        # 组合版（空文件无输出）

# ⚠️ 面试必答："第十行四写法——sed/awk/
#   head+tail/while read；
#   空文件行为要一致（无输出）。"
```

## 6. Shell 题的解题框架

### 6.1 四题方法论

| 题号 | 题目 | 核心工具 |
|------|------|---------|
| 192 | 统计词频 | tr + sort + uniq -c |
| 193 | 有效电话号码 | grep -E 正则 |
| 194 | 转置文件 | awk 二维数组 |
| 195 | 第十行 | sed -n '10p' |

```
⚠️ 面试必答：
"LeetCode Shell 四题 = 文本工具四件套——
 词频（管道统计）、电话（正则）、
 转置（awk 数组）、第十行（sed 定位）。"
```

### 6.2 通用步骤

```
① 明确输出格式（行/列/排序？）
② 选工具：找行 grep、改行 sed、拆列 awk、转字符 tr
③ 管道串联（一个工具的输入 = 上个的输出）
④ 边界验证（空文件/不足行数）

⚠️ 面试表达：
"'输出格式决定工具组合'——Shell 题
 先想清'要什么形状的输出'再选管道。"
```

## 7. 面试要点与追问

### 7.1 面试话术模板

```
"Shell 题 = 管道串联过滤器。
 词频：cat | tr -s | sort | uniq -c | sort -rn；
 电话：grep -E 正则；
 转置：awk 二维数组按列输出；
 第十行：sed -n '10p'。
 记住 uniq 必须先 sort、awk 按列、sed 定位。"
```

### 7.2 高频追问 TOP 8

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | uniq 前提？ | 先 sort（相邻去重） |
| 2 | 词频统计？ | sort | uniq -c |
| 3 | awk 模型？ | 逐行 + 列（$1..） |
| 4 | sed 第十行？ | sed -n '10p' |
| 5 | 正则模式？ | grep -E（ERE） |
| 6 | 转置？ | awk 二维数组 |
| 7 | 管道 vs 重定向？ | 流 vs 文件 |
| 8 | 空文件边界？ | 无输出 |

### 7.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| uniq 忘 sort | 统计错 | 先排序 |
| grep 忘 -E | 正则失效 | -E 扩展 |
| awk 忘分隔符 | 列拆错 | -F',' |
| sed 忘 -n | 重复输出 | -n 静默 |
| 转置列数不齐 | 错乱 | 动态行数 |
