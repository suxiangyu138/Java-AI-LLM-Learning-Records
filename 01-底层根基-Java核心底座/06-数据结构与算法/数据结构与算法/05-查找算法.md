## 1. 顺序查找

### 1.1 基本实现

```java
public int sequentialSearch(int[] arr, int target) {
    for (int i = 0; i < arr.length; i++) {
        if (arr[i] == target) return i;
    }
    return -1;
}
```

**时间复杂度**：O(n)，适用于小数据量或链表等不支持随机访问的结构。

### 1.2 哨兵优化

在 0 号位置放置目标值，省去循环中的边界判断，常数优化。

```java
public int sentinelSearch(int[] arr, int target) {
    int n = arr.length;
    if (n == 0) return -1;
    int last = arr[n - 1];
    arr[n - 1] = target; // 将最后一个元素替换为哨兵
    int i = 0;
    while (arr[i] != target) i++;
    arr[n - 1] = last; // 恢复
    if (i < n - 1) return i;
    return last == target ? n - 1 : -1;
}
```

> 💡 **哨兵优化的收益**：少一次 `i < n` 的比较，数据量大时有一定效果。

## 2. 二分查找（⭐ 必肌肉记忆）

### 2.1 前提条件

- 有序表 + 顺序存储（随机访问）
- 时间复杂度 O(log n)

### 2.2 标准实现

```java
public int binarySearch(int[] arr, int target) {
    int lo = 0, hi = arr.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2; // 防溢出：不直接写 (lo+hi)/2
        if (arr[mid] == target) return mid;
        else if (arr[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}
```

> ⚠️ **防溢出**：`mid = lo + (hi - lo) / 2` 而非 `(lo + hi) / 2`，防止 lo + hi 超过 int 最大值。

### 2.3 四种高频变体

```java
// 1. 查找第一个等于 target 的位置（左边界）
public int findFirst(int[] arr, int target) {
    int lo = 0, hi = arr.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (arr[mid] >= target) hi = mid - 1;
        else lo = mid + 1;
    }
    return lo < arr.length && arr[lo] == target ? lo : -1;
}

// 2. 查找最后一个等于 target 的位置（右边界）
public int findLast(int[] arr, int target) {
    int lo = 0, hi = arr.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (arr[mid] <= target) lo = mid + 1;
        else hi = mid - 1;
    }
    return hi >= 0 && arr[hi] == target ? hi : -1;
}

// 3. 查找第一个 ≥ target 的位置（lower_bound）
public int lowerBound(int[] arr, int target) {
    int lo = 0, hi = arr.length;
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (arr[mid] < target) lo = mid + 1;
        else hi = mid;
    }
    return lo;
}

// 4. 查找第一个 > target 的位置（upper_bound）
public int upperBound(int[] arr, int target) {
    int lo = 0, hi = arr.length;
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (arr[mid] <= target) lo = mid + 1;
        else hi = mid;
    }
    return lo;
}
```

> 🎯 **面试高频**：二分查找的边界变体直接考察对二分查找的深入理解。核心在于理解 `lo`、`hi` 的初始化和收缩条件。

### 2.4 二分查找的应用

| 问题类型 | 举例 |
|---------|------|
| 在有序数组中查找 | #704 二分查找 |
| 搜索旋转排序数组 | #33 旋转数组查找 |

## 3. 二叉搜索树（BST）查找

### 3.1 查找操作

```java
public TreeNode searchBST(TreeNode root, int val) {
    if (root == null || root.val == val) return root;
    return val < root.val ? searchBST(root.left, val) : searchBST(root.right, val);
}
```

### 3.2 时间复杂度

| 树形态 | 查找时间复杂度 |
|--------|--------------|
| 平衡 BST | O(log n) |
| 退化为单链表（斜树） | O(n) |

> 💡 普通 BST 的查找效率不稳定，因此需要 AVL 或红黑树保证 O(log n)。

## 4. 平衡二叉树（AVL）

### 4.1 定义

- 平衡因子 BF = 左子树高 - 右子树高，|BF| ≤ 1
- 严格平衡，保证查找 O(log n)

### 4.2 性能

| 操作 | 时间复杂度 |
|------|-----------|
| 查找 | O(log n) |
| 插入 | O(log n) + 最多两次旋转 |
| 删除 | O(log n) + 最多 O(log n) 次旋转 |

> ⚠️ AVL 适合**查找多、修改少**的场景，因为插入/删除后的旋转比红黑树更频繁。

## 5. 红黑树

### 5.1 五大性质

| 性质 | 说明 |
|------|------|
| 1 | 每个结点是红色或黑色 |
| 2 | 根结点是黑色 |
| 3 | 叶结点（NIL）是黑色 |
| 4 | 红色结点的子结点必须是黑色（不能有连续红色结点） |
| 5 | 从任意结点到叶子的所有路径，黑色结点数相同 |

### 5.2 关键特性

- 弱平衡：最长路径 ≤ 2 × 最短路径
- 插入/删除比 AVL 快（只需染色+最多 3 次旋转）

### 5.3 应用

| 组件 | 用途 |
|------|------|
| Java HashMap | 链表 ≥ 8 时转红黑树（JDK 8+） |
| Java TreeMap / TreeSet | 有序 Map/Set 底层实现 |
| C++ std::map / std::set | 标准库有序容器 |

## 6. B 树与 B+ 树

### 6.1 B 树

m 阶 B 树的特点：

| 特性 | 说明 |
|------|------|
| 每个结点最多 | m 个孩子 |
| 每个结点至少（除根外） | ⌈m/2⌉ 个孩子 |
| 数据分布 | 分布在各层结点中 |

### 6.2 B+ 树（⭐ 数据库索引核心）

MySQL InnoDB 默认索引结构。

| 特性 | 说明 |
|------|------|
| 非叶结点 | 只存索引（键值），不存数据 |
| 叶结点 | 存储完整数据记录 |
| 叶结点连接 | 双向链表串联——支持范围查询 |
| 结点大小 | 约一个磁盘页（16KB），减少磁盘 IO |

> 🎯 **B+ 树相比 B 树的优势**：非叶结点可以存更多索引，树更矮；范围查询通过叶结点链表高效实现。

| 对比项 | B 树 | B+ 树 |
|--------|------|-------|
| 数据存储 | 所有结点存数据 | 仅叶结点存数据 |
| 范围查询 | 需要中序遍历（跨层） | 叶链表直接遍历 |
| 磁盘 IO | 可能更多（非叶结点大） | 更少（非叶结点只存索引） |

## 7. 哈希表

### 7.1 核心思想

通过**哈希函数**将 key 映射到数组索引，期望 O(1) 时间完成查找、插入、删除。

### 7.2 哈希函数设计要求

- 计算速度快
- 分布均匀（减少冲突）
- 相同 key 得到相同 hash

```java
// 简单的哈希函数（Java String 的哈希）
int hash(String key) {
    int h = 0;
    for (char c : key.toCharArray()) {
        h = 31 * h + c; // 31 是质数，减少碰撞
    }
    return h;
}
```

### 7.3 冲突解决方法

| 方法 | 原理 | 优缺点 |
|------|------|--------|
| **拉链法** | 每个槽是链表/红黑树 | 实现简单，适合元素较多；Java HashMap 采用 |
| **线性探测** | 冲突时 h+1, h+2, h+3... | 一次聚集问题；删除麻烦 |
| **平方探测** | 冲突时 h+1², h+2², h+3²... | 缓解一次聚集 |
| **双重哈希** | 冲突时 h + i × hash2(key) | 分布更均匀，计算成本略高 |

### 7.4 扩容与负载因子

```java
// 负载因子 α = 元素数 / 表长
// α 过大 → 冲突增加，效率下降 → 触发 rehash 扩容
// Java HashMap 默认负载因子 0.75
```

| 负载因子 | 空间利用率 | 查找效率 |
|---------|-----------|---------|
| 小（如 0.5） | 低（空间浪费） | 高 |
| 大（如 0.9） | 高 | 低（冲突多） |

### 7.5 一致性哈希

分布式缓存中节点增减时最小化数据迁移的方案。

> 💡 一致性哈希将哈希值空间组织成环，每个节点负责环上的一段区间。节点增减只需迁移相邻节点的数据。

### 7.6 Java HashMap 核心参数

| 参数 | 默认值 | 说明 |
|------|-------|------|
| 初始容量 | 16 | 2 的幂次 |
| 负载因子 | 0.75 | 扩容阈值 = 容量 × 负载因子 |
| 树化阈值 | 8 | 链表长度 ≥ 8 且容量 ≥ 64 转红黑树 |
| 退化阈值 | 6 | 红黑树结点 ≤ 6 退化为链表 |

## 8. 跳表（Skip List）

### 8.1 结构

多层有序链表，每层按概率向上"晋升"。

```
Level 3: 1 ---------------------------→ 9
Level 2: 1 -----→ 5 -----→ 7 -----→ 9
Level 1: 1 → 3 → 5 → 6 → 7 → 8 → 9
```

### 8.2 性能

| 操作 | 平均时间复杂度 | 最坏时间复杂度 |
|------|--------------|--------------|
| 查找 | O(log n) | O(n) |
| 插入 | O(log n) | O(n) |
| 删除 | O(log n) | O(n) |

> 💡 **Redis 有序集合（ZSet）** 的底层数据结构之一就是跳表。跳表实现比平衡树简单，但性能相近。

## 9. KMP 字符串匹配算法

### 9.1 核心思想

KMP 是高效的字符串匹配算法，核心解决暴力匹配的重复回溯问题。

- **时间复杂度**：O(n + m)，n 为主串长度，m 为模式串长度
- **核心优势**：主串指针**永不回溯**，模式串按 next 数组智能回退

> ⚠️ 暴力匹配的时间复杂度为 O(n × m)，KMP 稳定 O(n + m)，长文本场景优势明显。

### 9.2 关键概念：最长相等前后缀

对模式串子串 `s[0...i]`：

- **前缀**：不含最后一个字符的所有头部子串
- **后缀**：不含第一个字符的所有尾部子串
- **最长相等前后缀**：两者中长度最大的相同子串

示例：模式串 `ababc`，子串 `abab` 的前缀 `[a, ab, aba]`、后缀 `[b, ab, bab]`，最长相等前后缀为 `ab`，长度 2。

### 9.3 next 数组的构建

```java
// 构建基础版 next 数组（部分匹配表）
public static int[] buildNext(String pattern) {
    int m = pattern.length();
    int[] next = new int[m];
    int j = 0; // 前缀指针，也记录最长相等前后缀长度
    next[0] = 0; // 第一个字符的 next 值为 0
    for (int i = 1; i < m; i++) { // i 为后缀指针
        // 匹配失败，回退 j
        while (j > 0 && pattern.charAt(i) != pattern.charAt(j)) {
            j = next[j - 1];
        }
        // 匹配成功，j 后移
        if (pattern.charAt(i) == pattern.charAt(j)) {
            j++;
        }
        next[i] = j;
    }
    return next;
}

// 构建优化版 nextVal 数组（解决重复字符的无效回退）
public static int[] buildNextVal(String pattern) {
    int m = pattern.length();
    int[] nextVal = new int[m];
    int j = 0;
    nextVal[0] = 0;
    for (int i = 1; i < m; i++) {
        while (j > 0 && pattern.charAt(i) != pattern.charAt(j)) {
            j = nextVal[j - 1];
        }
        if (pattern.charAt(i) == pattern.charAt(j)) {
            j++;
        }
        // 优化点：当前字符与回退位置字符相同，直接继承
        if (j > 0 && pattern.charAt(i) == pattern.charAt(j - 1)) {
            nextVal[i] = nextVal[j - 1];
        } else {
            nextVal[i] = j;
        }
    }
    return nextVal;
}
```

### 9.4 KMP 匹配过程

```java
/**
 * KMP 匹配：查找模式串在主串中首次出现的起始索引
 */
public static int kmpFindFirst(String text, String pattern, int[] next) {
    int n = text.length();
    int m = pattern.length();
    if (m > n) return -1;
    int j = 0; // 模式串指针
    for (int i = 0; i < n; i++) { // 主串指针，全程不回溯
        // 匹配失败，根据 next 数组回退模式串指针
        while (j > 0 && text.charAt(i) != pattern.charAt(j)) {
            j = next[j - 1];
        }
        // 匹配成功，模式串指针后移
        if (text.charAt(i) == pattern.charAt(j)) {
            j++;
        }
        // 模式串完全匹配
        if (j == m) {
            return i - m + 1; // 返回起始索引
        }
    }
    return -1;
}

/**
 * KMP 匹配：查找所有出现位置
 */
public static List<Integer> kmpFindAll(String text, String pattern, int[] next) {
    List<Integer> indices = new ArrayList<>();
    int n = text.length();
    int m = pattern.length();
    if (m > n) return indices;
    int j = 0;
    for (int i = 0; i < n; i++) {
        while (j > 0 && text.charAt(i) != pattern.charAt(j)) {
            j = next[j - 1];
        }
        if (text.charAt(i) == pattern.charAt(j)) {
            j++;
        }
        if (j == m) {
            indices.add(i - m + 1);
            j = next[j - 1]; // 关键：回退查找重叠匹配
        }
    }
    return indices;
}
```

> 💡 **重叠匹配**：`kmpFindAll` 中匹配成功后执行 `j = next[j - 1]`，支持重叠匹配（如主串 `aaaaa`，模式串 `aa`，匹配位置为 0, 1, 2, 3）。若需非重叠匹配，将 `j = 0` 即可。

### 9.5 暴力匹配 vs KMP 对比

| 特性 | 暴力匹配 | KMP 算法 |
|:--- |:--- |:--- |
| **时间复杂度** | O(n × m)（最坏情况） | O(n + m)（稳定高效） |
| **核心问题** | 主串、模式串双回溯，重复比较 | 主串不回溯，模式串按 next 数组智能回退 |
| **预处理** | 无 | 预处理模式串生成 next 数组 O(m) |
| **适用场景** | 短字符串匹配 | 长文本匹配（日志、DNA 序列、编辑器查找） |

### 9.6 KMP 经典应用

| 应用场景 | 说明 |
|---------|------|
| 编辑器查找替换 | Ctrl+F 的核心算法 |
| 生物信息学 | DNA/蛋白质序列匹配 |
| 日志分析 | 大规模日志关键词匹配 |
| 编译器语法分析 | 词法分析阶段的字符串匹配 |

## 10. 查找算法复杂度对比

| 算法 | 平均时间复杂度 | 最坏时间复杂度 | 空间复杂度 | 数据结构要求 |
|------|--------------|--------------|-----------|-------------|
| 顺序查找 | O(n) | O(n) | O(1) | 无 |
| 二分查找 | O(log n) | O(log n) | O(1) | 有序 + 随机访问 |
| BST 查找 | O(log n) | O(n) | O(1) | 二叉搜索树 |

| 跳表查找 | O(log n) | O(n) | O(n log n) | 多层有序链表 |
| KMP 匹配 | O(n + m) | O(n + m) | O(m) | 字符串 |

## 11. 学习建议

1. **二分查找的 4 个变体**必须能手写（标准/左边界/右边界/lower_bound/upper_bound）
2. **B+ 树**要理解为什么适合磁盘——每个结点刚好一页，减少 IO 次数
3. **哈希表**是面试最高频数据结构，冲突解决方式 + 扩容机制都要能说清
4. **KMP 算法**的核心是 next 数组的理解与构建，掌握最长相等前后缀的计算即可理解匹配过程

> 🎯 查找是算法的核心能力——从 O(n) 的顺序查找到 O(1) 的哈希查找，体现了算法设计的核心思想：**用空间换时间**。
