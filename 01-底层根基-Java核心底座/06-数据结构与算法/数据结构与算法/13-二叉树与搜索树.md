## 一、二叉搜索树

### 1.1 BST性质

**二叉搜索树（Binary Search Tree, BST）** 是一棵二叉树，其中每个节点包含一个关键字（Key），且满足以下BST性质：

| 性质 | 说明 |
|------|------|
| 左小右大 | 左子树所有节点值 < 根节点值 < 右子树所有节点值 |
| 递归定义 | 左右子树均为二叉搜索树 |
| 中序递增 | 中序遍历结果严格递增 |

> **后端意义**：BST是TreeMap/TreeSet的底层结构基础，用于有序存储、范围查询、动态排序。

### 1.2 基本操作（Java实现）

```java
class TreeNode {
    int val;
    TreeNode left, right;
    TreeNode(int val) { this.val = val; }
}

public class BST {
    private TreeNode root;

    // 插入
    public void insert(int val) {
        root = insert(root, val);
    }
    private TreeNode insert(TreeNode node, int val) {
        if (node == null) return new TreeNode(val);
        if (val < node.val) node.left = insert(node.left, val);
        else node.right = insert(node.right, val);
        return node;
    }

    // 查找
    public boolean search(int val) {
        return search(root, val);
    }
    private boolean search(TreeNode node, int val) {
        if (node == null) return false;
        if (val == node.val) return true;
        return val < node.val ? search(node.left, val) : search(node.right, val);
    }

    // 删除（分三种情况）
    public void delete(int val) {
        root = delete(root, val);
    }
    private TreeNode delete(TreeNode node, int val) {
        if (node == null) return null;
        if (val < node.val) node.left = delete(node.left, val);
        else if (val > node.val) node.right = delete(node.right, val);
        else {
            if (node.left == null) return node.right;       // 无左子树
            if (node.right == null) return node.left;       // 无右子树
            TreeNode min = findMin(node.right);             // 双子树：找后继
            node.val = min.val;
            node.right = delete(node.right, min.val);
        }
        return node;
    }
    private TreeNode findMin(TreeNode node) {
        while (node.left != null) node = node.left;
        return node;
    }
}
```

#### 删除操作三种情况

| 被删节点情况 | 操作 | 复杂度 |
|-------------|------|--------|
| 叶子节点（无子树） | 直接删除 | O(logn) |
| 单子树 | 子树替换当前节点 | O(logn) |
| 双子树 | 找后继/前驱节点替换后删除 | O(logn) |

### 1.3 性能分析

| 操作 | 平均时间复杂度 | 最坏时间复杂度 |
|------|--------------|--------------|
| 插入 | O(logn) | O(n) |
| 查找 | O(logn) | O(n) |
| 删除 | O(logn) | O(n) |
| 空间 | O(n) | O(n) |

### 1.4 性能瓶颈（有序数据退化）

> **关键问题**：普通BST的性能高度依赖数据分布。理想情况下树高logn，平均O(logn)；最坏情况下（插入有序数据如递增用户ID）树退化为单链表，高度n，复杂度降为O(n)。

**后端避坑**：若直接使用普通BST存储按时间递增的订单数据，会导致查询效率大幅降低。因此Java内置有序集合（TreeMap、TreeSet）均采用**红黑树**（平衡BST）实现。

### 1.5 Java工程：TreeMap / TreeSet 底层

| 特性 | TreeMap | TreeSet |
|------|---------|---------|
| 底层结构 | 红黑树 | 底层为TreeMap（只存Key） |
| 有序性 | 默认Key升序，支持Comparator定制 | 元素有序去重 |
| 核心方法 | put/get/remove/subMap/headMap/tailMap | add/remove/first/last/headSet/subSet |
| 时间复杂度 | O(logn) | O(logn) |
| 线程安全 | 非线程安全 | 非线程安全 |
| Key要求 | 必须可比较（Comparable或Comparator） | 同左 |

## 二、红黑树

### 2.1 定义与五大性质

**红黑树（Red-Black Tree）** 是一种自平衡二叉搜索树，通过颜色规则与旋转操作维持黑色高度平衡，保证最坏情况下时间复杂度为O(logn)。

| 指标 | 值 |
|------|----|
| 最坏情况时间复杂度 | O(logn) |
| 空间复杂度 | O(n) |
| 插入最多旋转次数 | 2次 |
| 删除最多旋转次数 | 3次 |
| 树高上限 | 2 * log(n+1) |

红黑树在满足BST性质的基础上，增加5个着色规则：

| 编号 | 性质 | 说明 |
|------|------|------|
| 性质1 | 每个节点非红即黑 | 节点只有两种颜色状态 |
| 性质2 | 根节点为黑色 | 树根始终为黑色 |
| 性质3 | 所有叶子节点（NIL空节点）为黑色 | 空节点视为黑色 |
| 性质4 | 红色节点的两个子节点均为黑色 | 不允许连续红色节点 |
| 性质5 | 任意节点到所有后代叶子节点的路径包含相同数量的黑色节点 | 黑色高度平衡 |

> **核心目的**：五大性质将红黑树的高度限制在`2 * log(n+1)`以内，确保所有操作稳定在O(logn)，无论输入数据如何分布。

### 2.2 旋转操作（Java实现）

```java
class RBNode {
    int val;
    RBNode left, right, parent;
    boolean color;  // true=红, false=黑
    RBNode(int val) {
        this.val = val;
        this.color = true;  // 新节点默认红色
    }
}

public class RedBlackTree {
    private static final boolean RED = true;
    private static final boolean BLACK = false;
    private RBNode root;

    // 左旋：将当前节点x的右子y提升为父节点
    private void leftRotate(RBNode x) {
        RBNode y = x.right;
        x.right = y.left;
        if (y.left != null) y.left.parent = x;
        y.parent = x.parent;
        if (x.parent == null) root = y;
        else if (x == x.parent.left) x.parent.left = y;
        else x.parent.right = y;
        y.left = x;
        x.parent = y;
    }

    // 右旋：将当前节点y的左子x提升为父节点
    private void rightRotate(RBNode y) {
        RBNode x = y.left;
        y.left = x.right;
        if (x.right != null) x.right.parent = y;
        x.parent = y.parent;
        if (y.parent == null) root = x;
        else if (y == y.parent.right) y.parent.right = x;
        else y.parent.left = x;
        x.right = y;
        y.parent = x;
    }

    // 插入后修复
    private void insertFixup(RBNode z) {
        while (z.parent != null && z.parent.color == RED) {
            if (z.parent == z.parent.parent.left) {
                RBNode y = z.parent.parent.right; // 叔节点
                if (y != null && y.color == RED) {
                    // 情况1：叔节点为红色 → 变色处理
                    z.parent.color = BLACK;
                    y.color = BLACK;
                    z.parent.parent.color = RED;
                    z = z.parent.parent;
                } else {
                    // 情况2：叔节点为黑色 → 旋转+变色
                    if (z == z.parent.right) {
                        z = z.parent;
                        leftRotate(z);
                    }
                    z.parent.color = BLACK;
                    z.parent.parent.color = RED;
                    rightRotate(z.parent.parent);
                }
            } else {
                // 对称处理（父节点为右子）
                RBNode y = z.parent.parent.left;
                if (y != null && y.color == RED) {
                    z.parent.color = BLACK;
                    y.color = BLACK;
                    z.parent.parent.color = RED;
                    z = z.parent.parent;
                } else {
                    if (z == z.parent.left) {
                        z = z.parent;
                        rightRotate(z);
                    }
                    z.parent.color = BLACK;
                    z.parent.parent.color = RED;
                    leftRotate(z.parent.parent);
                }
            }
        }
        root.color = BLACK;
    }

    // 插入
    public void insert(int val) {
        RBNode z = new RBNode(val);
        RBNode y = null;
        RBNode x = root;
        while (x != null) {
            y = x;
            if (z.val < x.val) x = x.left;
            else x = x.right;
        }
        z.parent = y;
        if (y == null) root = z;
        else if (z.val < y.val) y.left = z;
        else y.right = z;
        insertFixup(z);
    }
}
```

### 2.3 复杂度分析

| 操作 | 最坏时间复杂度 | 平均时间复杂度 |
|------|--------------|--------------|
| 插入 | O(logn) | O(logn) |
| 删除 | O(logn) | O(logn) |
| 查找 | O(logn) | O(logn) |
| 旋转次数 | 插入最多2次，删除最多3次 | — |

### 2.4 红黑树 vs AVL树

| 对比维度 | AVL树 | 红黑树 |
|---------|-------|--------|
| 平衡标准 | 高度差 <= 1（严格平衡） | 黑色高度平衡（宽松平衡） |
| 旋转频率 | 更频繁 | 较少 |
| 查询性能 | 略快（更矮） | 略慢（稍高） |
| 插入/删除性能 | 较差（旋转多） | 更好（旋转少） |
| 树高上限 | 1.44 * logn | 2 * log(n+1) |
| 后端工程选型 | 不常用 | TreeMap、HashMap树化均采用 |

> **后端选型**：后端工程优先选择红黑树（TreeMap），因为插入/删除更高效，旋转次数少，且查询性能差距在常数因子内，通常可接受。

### 2.5 红黑树 vs 跳表（SkipList）

| 对比维度 | 红黑树 | 跳表 |
|---------|--------|------|
| 内存占用 | 更紧凑（仅2个子指针+颜色位） | 指针多（多层索引），内存略大 |
| 范围查询 | 高效（中序遍历） | 高效（链表层级推进） |
| 实现复杂度 | 复杂（旋转+着色+6种插入情况） | 简单（随机层高） |
| 并发友好度 | 较差（结构调整粒度细） | 好（CAS操作链表节点） |
| 后端选型 | 单机有序场景 | 高并发有序场景 |

> **后端选型**：高并发选跳表（ConcurrentSkipListMap、Redis ZSet），单机有序选红黑树（TreeMap）。

### 2.6 Java后端核心应用

#### 2.6.1 TreeMap / TreeSet

| 应用场景 | 技术实现 | 核心价值 |
|---------|---------|---------|
| 有序键值对 | TreeMap（红黑树） | 有序存储，范围查询O(logn) |
| 有序去重集合 | TreeSet（底层TreeMap） | 元素有序且唯一 |
| 时间序列数据 | TreeMap按时间戳排序 | 按时间范围快速检索 |
| 区间统计 | subMap/headMap/tailMap | 范围查询、最值查询 |

#### 2.6.2 HashMap树化（JDK 1.8+）

| 特性 | 说明 |
|------|------|
| 触发条件 | 链表长度 >= 8 且数组容量 >= 64 |
| 回退条件 | 节点数 <= 6 时转回链表 |
| 核心目的 | 避免哈希冲突严重时退化为O(n) |
| 保证 | 最坏情况查找为O(logn) |

> 使用红黑树而非AVL树的原因是：HashMap的写入/删除远多于查询，红黑树旋转更少、写入性能更优。

#### 2.6.3 后端实操示例：订单按时间排序

```java
import java.util.TreeMap;

public class OrderManager {
    static class Order {
        String orderId;
        long timestamp;
        double amount;
        String status;
        Order(String orderId, long timestamp, double amount, String status) {
            this.orderId = orderId;
            this.timestamp = timestamp;
            this.amount = amount;
            this.status = status;
        }
    }

    private final TreeMap<Long, Order> orderMap = new TreeMap<>();

    public void addOrder(Order order) {
        orderMap.put(order.timestamp, order);
    }

    // 范围查询
    public TreeMap<Long, Order> getOrdersByTimeRange(long start, long end) {
        return (TreeMap<Long, Order>) orderMap.subMap(start, true, end, true);
    }

    // 最新/最旧订单
    public Order getLatest() { return orderMap.get(orderMap.lastKey()); }
    public Order getEarliest() { return orderMap.get(orderMap.firstKey()); }

    public static void main(String[] args) {
        OrderManager mgr = new OrderManager();
        mgr.addOrder(new Order("O001", 1690000100000L, 199.9, "已支付"));
        mgr.addOrder(new Order("O002", 1690000000000L, 299.9, "待支付"));
        mgr.addOrder(new Order("O003", 1690000200000L, 399.9, "已完成"));

        System.out.println("最新订单：" + mgr.getLatest().orderId);

        TreeMap<Long, Order> range = mgr.getOrdersByTimeRange(
                1690000050000L, 1690000150000L);
        range.forEach((t, o) ->
                System.out.println("范围订单：" + o.orderId));
    }
}
```

#### 2.6.4 后端实操示例：积分排行榜

```java
import java.util.*;

public class ScoreRank {
    // 积分降序排列，同积分用户放入列表
    private final TreeMap<Long, ArrayList<String>> rank =
            new TreeMap<>(Comparator.reverseOrder());

    public void updateScore(String userId, long score) {
        // 先删除旧积分记录
        rank.forEach((oldScore, users) -> {
            users.remove(userId);
            if (users.isEmpty()) rank.remove(oldScore);
        });
        // 插入新积分
        rank.computeIfAbsent(score, k -> new ArrayList<>()).add(userId);
    }

    public void showTopN(int n) {
        int count = 0;
        for (Long score : rank.keySet()) {
            for (String user : rank.get(score)) {
                if (count >= n) break;
                System.out.println("第" + (++count) + "名：" + user + " 积分=" + score);
            }
        }
    }
}
```

### 2.7 避坑指南

| 坑点 | 问题 | 解决方案 |
|------|------|---------|
| Key未实现Comparable | ClassCastException | 使用String、Long等自带实现，或指定Comparator |
| Key为null | NullPointerException | TreeMap不支持null Key，与HashMap不同 |
| 多线程使用TreeMap | 红黑树结构破坏，数据错乱 | 高并发用ConcurrentSkipListMap |
| 频繁增删未批量优化 | 大量旋转/着色开销 | 优先使用putAll()批量操作 |
| 混淆TreeMap与HashMap | 选型错误导致性能浪费 | 无需有序时始终用HashMap（O(1)） |
| 混淆B+树与红黑树 | 场景错配 | 磁盘存储用B+树，内存缓存用红黑树 |

## 三、斐波那契堆

### 3.1 结构特点

斐波那契堆（Fibonacci Heap）是一组满足**最小堆序**的树的集合，采用**懒操作**策略延迟结构调整：

| 组成部分 | 说明 | 设计意图 |
|---------|------|---------|
| **根链表（Root List）** | 所有树的根节点组成的双向环形链表 | 合并操作仅需拼接链表 |
| **最小节点（Min Node）** | 指向根链表中关键字最小的节点 | O(1)获取最小元素 |
| **节点结构** | 含关键字、父指针、子指针、度数、标记位 | 标记位用于级联剪枝 |
| **度（Degree）** | 节点的子节点数量 | 控制树的大小分布 |
| **懒操作机制** | 延迟结构调整到extract-min时统一执行 | 减少频繁调整开销 |

### 3.2 核心操作复杂度

| 操作 | 二叉堆 | 斐波那契堆（摊还） | 后端场景价值 |
|------|-------|------------------|-------------|
| 插入 | O(logn) | **O(1)** | 高频任务提交场景 |
| 合并（Merge） | O(n) | **O(1)** | 多队列合并场景 |
| 提取最小（Extract-Min） | O(logn) | O(logn) | 低频任务提取场景 |
| 关键字减值（Decrease-Key） | O(logn) | **O(1)** | 动态优先级调整 |
| 删除 | O(logn) | O(logn) | — |

> **摊还分析**：单次操作可能较慢（如Extract-Min需合并同度数树），但连续m次操作的总时间上界优于二叉堆。

### 3.3 核心操作逻辑

#### 插入（摊还O(1)）

将新节点直接加入根链表，若关键字小于当前最小节点则更新最小指针。与二叉堆的O(logn)上浮相比，仅需常数次指针修改。

```java
class FibNode {
    int key;
    FibNode left, right, parent, child;
    int degree;
    boolean mark;
    FibNode(int key) {
        this.key = key;
        this.left = this.right = this;  // 自环双向链表
    }
}
```

#### 合并（摊还O(1)）

拼接两个堆的根链表（双向链表节点重连），更新最小节点指针。二叉堆合并需要O(n)——将一个堆的元素逐个插入另一个堆。

#### 提取最小（摊还O(logn)）

唯一需要立即调整结构的操作：
1. 将最小节点的所有子节点加入根链表
2. 从根链表中删除最小节点
3. 执行**合并同度数树**（Consolidate）：遍历根链表，将度数相同的树的根节点合并，直到所有根节点度数唯一
4. 遍历根链表更新最小节点指针

#### 关键字减值（摊还O(1)）

适用于后端"动态更新优先级"场景：
1. 降低目标节点关键字
2. 若违反最小堆序，将该节点从父节点子链表中剪除，加入根链表
3. 若父节点已标记为失去过子节点（mark=true），递归向上执行**级联剪枝**
4. 若新节点关键字小于当前最小节点，更新最小节点指针

### 3.4 与二叉堆对比

| 对比维度 | 二叉堆 | 斐波那契堆 |
|---------|-------|-----------|
| 结构 | 完全二叉树 | 最小堆序树集合 |
| 合并复杂度 | O(n) | O(1) 摊还 |
| 插入复杂度 | O(logn) | O(1) 摊还 |
| 实现复杂度 | 简单（数组+上浮/下沉） | 极复杂（多指针+级联剪枝） |
| 实际常数因子 | 小 | 大 |
| 是否被JDK采用 | PriorityQueue（二叉堆） | 未直接采用 |

> **工程现实**：虽然理论复杂度更优，但斐波那契堆的实现极其复杂、常数因子大，Java标准库未直接采用。但它的**懒操作思想**和**级联剪枝机制**被多个中间件借鉴。

### 3.5 后端应用场景

| 场景 | 应用说明 | 借鉴思想 |
|------|---------|---------|
| **分布式任务调度** | Elastic-Job、XXL-Job的队列分段存储，分段间采用根链表式合并 | 懒操作、高效合并 |
| **图算法引擎** | Neo4j、Apache Giraph中大规模图计算的Dijkstra/Prim算法 | Decrease-Key优化，O(E + VlogV) |
| **消息队列优先级** | 大量消息入队、少量消息出队的场景 | 高频插入优化 |
| **Redis ZSet演化** | 早期版本借鉴Decrease-Key思想优化权重更新 | 关键字减值 |

## 四、树形结构选型与总结

### 4.1 全面对比表

| 对比维度 | BST（普通） | 红黑树 | 斐波那契堆 | B+树 | 跳表 |
|---------|-----------|-------|-----------|------|------|
| **平衡机制** | 无 | 颜色+旋转 | 懒操作+合并 | 多路分裂 | 随机层高 |
| **插入** | O(logn)~O(n) | O(logn) | O(1) 摊还 | O(logn) | O(logn) |
| **查找** | O(logn)~O(n) | O(logn) | O(logn) | O(logmn) | O(logn) |
| **删除** | O(logn)~O(n) | O(logn) | O(logn) | O(logn) | O(logn) |
| **合并** | O(m+n) | O(m+n) | O(1) 摊还 | O(m+n) | O(m+n) |
| **范围查询** | 支持 | 高效 | 不适用 | 极高效（叶子链表） | 高效 |
| **内存占用** | 低 | 低 | 较高（多指针） | 高（多路） | 中（索引冗余） |
| **实现复杂度** | 低 | 高 | 极高 | 高 | 中 |
| **并发友好度** | 差 | 差 | 差 | 一般 | 好 |

### 4.2 后端选型指南

| 业务场景 | 推荐方案 | 核心原因 |
|---------|---------|---------|
| **单线程有序映射** | TreeMap（红黑树） | O(logn)稳定，功能完备 |
| **单线程有序集合** | TreeSet（红黑树） | 底层TreeMap，有序去重 |
| **高并发有序缓存** | ConcurrentSkipListMap | 线程安全，范围查询高效 |
| **分布式有序集合** | Redis ZSet（跳表） | 有序集合，权重排序 |
| **数据库索引** | MySQL B+树索引 | 减少磁盘IO，多路分支 |
| **优先级队列** | PriorityQueue（二叉堆） | 简单高效，足够满足多数场景 |
| **图算法/高频插入队列** | 借鉴斐波那契堆思想 | 高频插入+低频提取的最优理论解 |

### 4.3 核心选型原则

1. **先定有序性**：无需有序 → HashMap（O(1)）；需要有序 → 进入下一步
2. **再定并发性**：单线程 → TreeMap/红黑树；高并发 → ConcurrentSkipListMap/跳表
3. **再定数据规模**：内存数据 → 树/跳表；磁盘/海量数据 → B+树
4. **最后看操作特征**：插入远多于提取 → 借鉴斐波那契堆懒操作思想；读写均衡 → 红黑树

### 4.4 后端避坑核心清单

| 场景 | 正确做法 | 错误做法 |
|------|---------|---------|
| 有序存储 | TreeMap | 用HashMap手动排序 |
| 高并发有序 | ConcurrentSkipListMap | TreeMap + 外部锁 |
| 大量数据有序 | MySQL B+树索引 | TreeMap内存全量缓存 |
| 优先级队列 | PriorityQueue（二叉堆） | 自己实现堆 |
| Key类型 | String/Long等不可变类型 | 可变对象作为Key |

> 🎯 **总结**：二叉搜索树是树形数据结构的理论基础，红黑树是Java工程中最广泛应用的平衡树实现，斐波那契堆提供理论最优的摊还复杂度。后端开发的核心在于根据有序性需求、并发场景、数据规模三大维度正确选型——对于80%的应用场景，TreeMap和ConcurrentSkipListMap即可覆盖。
