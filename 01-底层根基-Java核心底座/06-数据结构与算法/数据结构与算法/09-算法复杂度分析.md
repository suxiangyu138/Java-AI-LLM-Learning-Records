## 1. 算法分析的核心目的

1. **评估算法效率，选择最优实现** — 面对多种实现方案，通过复杂度对比选择最适合的算法
2. **预测程序在大数据量下的性能表现** — 提前预判代码在海量数据场景下的执行效率
3. **指导 Java 后端系统设计与性能优化** — 在系统设计阶段就规避性能风险
4. **作为技术选型与架构决策的依据** — 为缓存策略、数据分片、并发模型提供量化参考

> 后端开发中，算法分析的核心不是复杂的数学推导，而是结合业务场景量化算法的时间/空间复杂度，为算法选型、性能优化提供客观依据。

## 2. 时间复杂度

### 2.1 定义

时间复杂度描述算法执行时间随数据规模增长的变化趋势，表示为 `T(n) = O(f(n))`，`n` 为数据规模。

后端开发中采用**大O记法**，核心是保留影响时间增长的"主导项"，忽略常数项、低次项。例如，执行步骤为 `3n² + 2n + 5`，时间复杂度为 `O(n²)`。

### 2.2 常见复杂度等级（从优到劣）

| 复杂度 | 名称 | 说明 | 后端案例 |
|--------|------|------|---------|
| **O(1)** | 常数阶 | 执行时间不随 `n` 变化 | `HashMap.get()`、`ArrayList.get()` |
| **O(log n)** | 对数阶 | 增长速度极慢，n 越大优势越明显 | 二分查找、红黑树操作 |
| **O(n)** | 线性阶 | 与 `n` 成正比，最常见 | 数组遍历、批量订单处理 |
| **O(n log n)** | 线性对数阶 | 高效排序的主流复杂度 | 快速排序、`Arrays.sort()` |
| **O(n²)** | 平方阶 | 双重循环，效率较低 | 冒泡排序（限 n ≤ 1000） |
| **O(2ⁿ)** | 指数阶 | 效率极低，需避免 | 无实际后端应用场景 |

> 核心记忆公式：O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)

### 2.3 后端视角的分析技巧

1. **忽略常数项和低次项**：关注与 `n` 相关的主导项。n² 循环 + n 循环 = O(n²)
2. **循环嵌套看"乘积"**：外层 n 次 × 内层 n 次 = O(n²)；内层固定次数 = O(n)
3. **递归看"调用次数"**：递归次数 × 每次递归执行步骤。二分查找递归 log n 次，每次 O(1)，总 O(log n)

### 2.4 摊还分析（Amortized Analysis）

摊还分析用于评估数据结构一系列操作的平均复杂度，不依赖概率分布，保证最坏情况下的平均性能。

#### 三种方法

| 方法 | 核心原理 | 示例 |
|------|----------|------|
| **聚合分析** | 计算 n 次操作总代价，除以 n | ArrayList 扩容：n 次 add 总代价 O(n)，摊还 O(1) |
| **记账法** | 低代价操作存"信用"，高代价操作消耗信用 | push 预存 2 单位信用，扩容时用信用抵消复制代价 |
| **势能法** | 定义势能函数 Φ，摊还 = 实际 + ΔΦ | HashMap 重哈希：Φ = 2 × size − capacity |

#### Java 后端经典摊还场景

| 数据结构 | 操作 | 均摊复杂度 | 分析 |
|----------|------|-----------|------|
| `ArrayList` | add（扩容） | O(1) | 扩容为 2 倍，总复制代价 1+2+4+...+2^k ≈ 2n |
| `HashMap` | put（重哈希） | O(1) | 扩容翻倍，势能法证明摊还 O(1) |
| `ArrayDeque` | addLast（扩容） | O(1) | 循环数组扩容 2 倍 |
| 并查集 | find/union | O(α(n)) ≈ O(1) | 路径压缩 + 按秩合并 |

```java
/**
 * ArrayList 扩容的摊还分析示例
 * 扩容触发点：size = 1, 2, 4, 8, ..., 2^k
 * 总复制代价：1 + 2 + 4 + ... + 2^k = 2^(k+1) - 1 ≈ 2n
 * n 次 add 总代价 O(n)，摊还 O(1)
 */
public class MyArrayList {
    private int[] arr;
    private int size;
    private int capacity;

    public MyArrayList() {
        capacity = 1;
        arr = new int[capacity];
        size = 0;
    }

    public void add(int val) {
        if (size == capacity) {
            capacity *= 2;
            int[] newArr = new int[capacity];
            System.arraycopy(arr, 0, newArr, 0, size);
            arr = newArr;
        }
        arr[size++] = val;
    }
}
```

```java
/**
 * 并查集（路径压缩 + 按秩合并）
 * 均摊复杂度：O(α(n))，α(n) 是阿克曼函数反函数，n < 10^6 时 α(n) ≤ 5
 */
public class DSU {
    private int[] parent;
    private int[] rank;

    public DSU(int n) {
        parent = new int[n];
        rank = new int[n];
        for (int i = 0; i < n; i++) {
            parent[i] = i;
            rank[i] = 1;
        }
    }

    public int find(int x) {
        if (parent[x] != x) {
            parent[x] = find(parent[x]); // 路径压缩
        }
        return parent[x];
    }

    public void union(int x, int y) {
        int fx = find(x);
        int fy = find(y);
        if (fx == fy) return;
        if (rank[fx] > rank[fy]) {
            parent[fy] = fx;
        } else {
            parent[fx] = fy;
            if (rank[fx] == rank[fy]) rank[fy]++;
        }
    }
}
```

## 3. 空间复杂度

### 3.1 定义

空间复杂度描述算法执行过程中所需额外内存随数据规模 `n` 增长的变化趋势，**不包括输入数据本身**。

### 3.2 常见空间复杂度

| 复杂度 | 说明 | 后端案例 |
|--------|------|---------|
| **O(1)** | 额外内存固定，不随 n 变化 | 原地排序（冒泡）、`HashMap.get()` |
| **O(n)** | 额外内存与 n 成正比 | ArrayList 初始化、归并排序临时数组 |
| **O(log n)** | 对数增长，主要用于递归 | 二分查找递归栈、平衡树遍历 |
| **O(n²)** | 极少使用，仅极小数据量 | n×n 矩阵、双重循环二维数组 |

### 3.3 后端优化重点

1. **优先使用原地操作**：避免额外占用内存。排序选快速排序（原地）而非归并排序（需 O(n) 辅助空间）
2. **控制递归深度**：递归深度过大（n > 1000）会导致栈溢出。不可控时将递归转换为迭代，空间复杂度从 O(n) 优化为 O(1)
3. **复用内存资源**：高并发场景避免频繁创建临时对象，使用对象池、`ThreadLocal` 复用内存，减少 GC 压力

## 4. 渐进符号

| 记号 | 名称 | 含义 | 说明 |
|:----:|------|------|------|
| **O** | 大O | 上界（最坏情况） | 算法执行时间的上限，最常用 |
| **Ω** | 大Ω | 下界（最好情况） | 算法执行时间的下限 |
| **Θ** | 大Θ | 紧确界 | O 和 Ω 一致时，精确复杂度 |

### 4.1 主定理

解决形如 `T(n) = aT(n/b) + f(n)` 的递推式：

| 条件 | 结论 |
|------|------|
| `f(n) < n^(log_b a)`（多项式小于） | `T(n) = Θ(n^(log_b a))` |
| `f(n) = n^(log_b a)` | `T(n) = Θ(n^(log_b a) log n)` |
| `f(n) > n^(log_b a)`（多项式大于） | `T(n) = Θ(f(n))` |

**经典应用**：

| 算法 | 递推式 | 复杂度 |
|------|--------|:------:|
| 归并排序 | T(n) = 2T(n/2) + O(n) | O(n log n) |
| 二分查找 | T(n) = T(n/2) + O(1) | O(log n) |
| Strassen 矩阵乘 | T(n) = 7T(n/2) + O(n²) | O(n^2.807) |

## 5. 最好、最坏、平均复杂度

| 类型 | 定义 | 说明 |
|------|------|------|
| **最好情况** | 最优输入下的复杂度 | 理想状态，参考价值有限 |
| **最坏情况** | 最差输入下的复杂度 | **重点关注**，保证系统稳定性 |
| **平均情况** | 随机输入下的期望复杂度 | 反映一般场景下的性能 |

> **典型案例：HashMap 查找**
> - 最好 O(1) — 无哈希冲突
> - 最坏 O(n) — 所有元素冲突形成链表（JDK 8+ 退化为红黑树则为 O(log n)）
> - 平均 O(1) — 哈希函数设计合理

> **重点分析最坏情况** —— 这是系统稳定性的保障。

## 6. 均摊复杂度

### 6.1 定义

连续多次操作后，单次操作的平均复杂度。与平均情况分析的区别在于：**摊还分析不依赖概率分布**，保证最坏情况输入下的平均性能。

### 6.2 典型应用

| 数据结构 | 操作 | 均摊复杂度 | 分析 |
|----------|------|-----------|------|
| `ArrayList` | add（扩容） | O(1) | 扩容为 2 倍，总复制代价 ≈ 2n |
| `HashMap` | put（重哈希） | O(1) | 扩容翻倍 + 重新散列 |
| `ArrayDeque` | addLast | O(1) | 循环数组扩容 2 倍 |
| 并查集 | find/union | O(α(n)) ≈ O(1) | 路径压缩 + 按秩合并 |

### 6.3 LRU 缓存摊还分析

```java
import java.util.LinkedHashMap;
import java.util.Map;

/**
 * LRU 缓存（LinkedHashMap 实现）
 * 访问/插入：O(1)（摊还）
 * 淘汰：链表删除头部 O(1)
 */
public class LRUCache {
    private final int capacity;
    private final Map<Integer, Integer> cache;

    public LRUCache(int capacity) {
        this.capacity = capacity;
        this.cache = new LinkedHashMap<Integer, Integer>(capacity, 0.75f, true) {
            @Override
            protected boolean removeEldestEntry(Map.Entry<Integer, Integer> eldest) {
                return size() > capacity;
            }
        };
    }

    public int get(int key) {
        return cache.getOrDefault(key, -1);
    }

    public void put(int key, int value) {
        cache.put(key, value);
    }
}
```

## 7. 递推方程求解方法

| 方法 | 适用场景 | 做法 |
|------|----------|------|
| **代入法** | 已知或可猜测解的形式 | 猜测解 → 数学归纳法证明 |
| **递归树法** | 直观分析递归过程 | 画树展开，逐层求和 |
| **主定理** | T(n) = aT(n/b) + f(n) 型 | 套用主定理公式 |

### 7.1 递归树示例：归并排序

```
T(n) = 2T(n/2) + O(n)

            n                ← 代价 n
          /   \
       n/2     n/2           ← 代价 n
      /  \    /   \
    n/4  n/4 n/4  n/4        ← 代价 n
   ...  ... ...  ...
   log n 层，每层代价 n → 总代价 O(n log n)
```

## 8. Java 后端实战分析案例

### 案例 1：ArrayList vs LinkedList

| 操作 | ArrayList | LinkedList |
|------|-----------|------------|
| 随机访问 | O(1) | O(n) |
| 头部插入 | O(n) | O(1) |
| 尾部插入 | O(1) 均摊 | O(1) |
| 遍历 | O(n) | O(n) |

### 案例 2：HashMap vs TreeMap

| 指标 | HashMap | TreeMap |
|------|---------|---------|
| 查找 | O(1) 均摊 | O(log n) |
| 有序遍历 | 不支持 | O(n) |
| 内存 | 更低 | 更高（额外指针） |

### 案例 3：排序算法选择

| 数据量 | 推荐算法 | 原因 |
|--------|----------|------|
| n ≤ 1000 | 插入排序 | 常数小，接近有序时 O(n) |
| n ≤ 10⁶ | 快速排序（双轴快排） | O(n log n)，原地排序 |
| n > 10⁶ 需稳定 | TimSort（归并变体） | 稳定，对象排序默认 |
| Top K | 堆排序 | O(n log k)，无需全排序 |

### 案例 4：递归 vs 迭代

```java
/**
 * 递归实现（简洁但深度大时栈溢出）
 * 空间复杂度：O(n)（递归栈）
 */
public int factorialRecursive(int n) {
    if (n <= 1) return 1;
    return n * factorialRecursive(n - 1);
}

/**
 * 迭代实现（无栈溢出风险）
 * 空间复杂度：O(1)
 */
public int factorialIterative(int n) {
    int result = 1;
    for (int i = 2; i <= n; i++) {
        result *= i;
    }
    return result;
}
```

> 分析结论：若树形结构层级可控（层级 ≤ 10），可用递归兼顾可读性；若层级不可控（如用户关系树，可能 1000+），必须使用迭代避免栈溢出。

## 9. 算法优化原则

### 9.1 空间换时间

缓存数据、预计算结果，以额外内存换取更快的执行。

| 场景 | 做法 |
|------|------|
| 接口查询 | Redis 缓存热点数据 |
| 递归计算 | 记忆化搜索（DP） |
| 哈希查找 | HashMap 存储键值对 |

### 9.2 时间换空间

减少内存占用，适用于内存受限场景。

| 场景 | 做法 |
|------|------|
| 大文件处理 | 流式读取，分批加载 |
| 排序 | 原地排序（快排）替代非原地排序（归并） |

### 9.3 避免重复计算

缓存中间结果，使用记忆化技术。

```java
// 未优化：O(2ⁿ)
int fib(int n) {
    if (n <= 1) return n;
    return fib(n-1) + fib(n-2);
}

// 优化后（DP）：O(n)
int fibDP(int n) {
    if (n <= 1) return n;
    int[] dp = new int[n + 1];
    dp[0] = 0; dp[1] = 1;
    for (int i = 2; i <= n; i++) {
        dp[i] = dp[i-1] + dp[i-2];
    }
    return dp[n];
}
```

## 10. 常见误区与避坑指南

| 误区 | 正确做法 |
|------|---------|
| **过度追求"最优复杂度"，忽略业务场景** | 小数据量（n ≤ 100）优先考虑代码简洁性 |
| **只关注时间复杂度，忽略空间复杂度** | 高并发、内存有限场景优先控制空间复杂度 |
| **忽略 Java API 的底层复杂度** | 使用 API 前理解其底层复杂度，如 `ArrayList.add()` 扩容时退化为 O(n) |
| **将"理论复杂度"等同于"实际效率"** | 最终需通过 JMH 压测验证，| 尤其是高并发场景 |
| **认为 O(n²) 永远不可用** | 当 n ≤ 1000 且操作不频繁时，O(n²) 可能比 O(n log n) 更快（常数小） |

> 核心原则：算法分析需结合业务场景，"合适"比"最优"更重要。

## 11. 算法设计核心技巧

### 11.1 六大核心技巧速览

| 技巧 | 核心思想 | 时间复杂度 | 适用场景 |
|------|----------|-----------|----------|
| **分治法** | 分解-解决-合并 | O(n log n) | 大规模数据处理、排序 |
| **动态规划** | 重叠子问题+记忆化 | O(n²) 常见 | 最优解、路径规划 |
| **贪心** | 局部最优推全局最优 | O(n log n) | 资源分配、任务调度 |
| **回溯** | 试探+回退+剪枝 | O(n!)~O(2ⁿ) | 排列组合、约束满足 |
| **分支限界** | BFS+剪枝 | O(2ⁿ) | 最优解搜索 |
| **随机化** | 引入随机因素降低最坏复杂度 | O(n log n) 期望 | 快排、负载均衡 |

### 11.2 分治法详解

```
分解（Divide）→ 求解（Conquer）→ 合并（Combine）
```

| 算法 | 递推式 | 复杂度 |
|------|--------|:------:|
| 归并排序 | T(n) = 2T(n/2) + O(n) | O(n log n) |
| 快速排序 | T(n) = 2T(n/2) + O(n) | O(n log n) 平均 |
| 二分查找 | T(n) = T(n/2) + O(1) | O(log n) |
| Karatsuba 乘法 | T(n) = 3T(n/2) + O(n) | O(n^1.585) |

### 11.3 动态规划核心要素

| 要素 | 说明 |
|------|------|
| **最优子结构** | 问题最优解包含子问题最优解 |
| **重叠子问题** | 子问题被重复求解（区别于分治） |
| **无后效性** | 某一步的决策不影响后续子问题的求解 |

### 11.4 贪心算法基本要素

| 要素 | 说明 |
|------|------|
| **贪心选择性质** | 局部最优可推出全局最优 |
| **最优子结构** | 贪心选择后的子问题最优解 = 原问题最优解 |

## 12. NP 完全性理论简介

### 12.1 问题分类

| 类别 | 含义 | 示例 |
|------|------|------|
| **P** | 多项式时间可解 | 排序、最短路径 |
| **NP** | 多项式时间可验证 | TSP 的验证、数独 |
| **NPC** | NP 中最难的问题，任意 NP 问题可归约到它 | SAT、TSP、哈密顿回路 |
| **NP-Hard** | 至少和 NPC 一样难 | 停机问题 |

### 12.2 常见 NPC 问题

| 问题 | 说明 |
|------|------|
| SAT | Cook 定理证明 SAT 是第一个 NPC |
| TSP（判定版） | 是否存在长度 ≤ k 的回路 |
| 顶点覆盖 | 是否存在大小 ≤ k 的顶点覆盖 |
| 哈密顿回路 | 是否存在经过每个点一次的回路 |
| 子集和 | 是否存在子集和为指定值 |

> **后端启示**：遇到 NP 完全问题时，不追求精确最优解，转而使用近似算法或启发式算法（如遗传算法、模拟退火）。
