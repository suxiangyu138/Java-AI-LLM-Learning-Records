## 1. 核心概念

### 1.1 什么是计数排序

> 计数排序：**值域小**时，用计数数组统计每个值的个数，再按顺序输出。复杂度 **O(n+k)**（k = 值域大小），突破比较排序 O(n log n) 下界。

```
适用条件：值域 k 小且已知（如 0-100 的分数）
  例：分数排序（0-100）→ 101 个桶计数

与比较排序的本质区别：
  比较排序：通过比较确定顺序 → 下界 Ω(n log n)
  计数排序：值直接作为下标 → 无需比较 → 线性

⚠️ 局限：值域大（10⁹）→ 数组爆炸 → 不可用
  值域大 + 数值固定 → 基数排序（按位计数）
```

### 1.2 识别信号

```
"值域小且已知（0-100/0-255）" → 计数排序
"要求 O(n) 排序" → 计数/基数/桶
"频次统计" → 计数思想

⚠️ 面试定位：
  了解原理 + 能手写稳定版
  比快排/归并优先级低（面试少要求手撕）
  但"三种线性排序对比"是高频追问
```

### 1.3 计数排序的本质

```
三个步骤的本质：
  计数：统计每个值的个数（O(n)）
  前缀和：确定每个值的最终位置范围（O(k)）
  回填：按位置放回（O(n)）

⚠️ 关键理解：
  前缀和 count[i] = ≤ i 的元素个数
  → count[i] 恰好是值 i 的"结束位置 + 1"
  → 回填时 --count[val] 得到正确位置
```

## 2. 完整代码模板

### 2.1 稳定版（面试标准答案）

```java
/**
 * 计数排序（稳定版）——面试标准答案
 * 值域 [0, maxVal]
 */
public void countingSort(int[] arr, int maxVal) {
    int n = arr.length;

    // ① 计数：统计每个值的个数
    int[] count = new int[maxVal + 1];
    for (int x : arr) {
        count[x]++;
    }

    // ② 前缀和：count[i] = ≤ i 的元素个数
    for (int i = 1; i <= maxVal; i++) {
        count[i] += count[i - 1];
    }

    // ③ ⚠️ 倒序回填（保证稳定）
    int[] result = new int[n];
    for (int i = n - 1; i >= 0; i--) {
        result[--count[arr[i]]] = arr[i];
    }
    System.arraycopy(result, 0, arr, 0, n);
}
// 例：[4, 2, 2, 8, 3, 3, 1] maxVal=8
// 计数：[0,1,2,2,1,0,0,0,1]
// 前缀：[0,1,3,5,6,6,6,6,7]
// 倒序回填 → [1,2,2,3,3,4,8] ✓
```

### 2.2 推演：为什么倒序回填稳定？

```
arr = [4, 2, 2]，count 前缀 = [0,0,2,2,3]（到 4）

正序回填（i=0,1,2）：
  i=0(4)：count[4]--=2 → result[2]=4
  i=1(2)：count[2]--=1 → result[1]=2
  i=2(2)：count[2]--=0 → result[0]=2
  → 两个 2 的顺序反转了！不稳定 ❌

倒序回填（i=2,1,0）：
  i=2(2)：count[2]--=1 → result[1]=2（后出现的先放）
  i=1(2)：count[2]--=0 → result[0]=2（先出现的后放）
  i=0(4)：count[4]--=2 → result[2]=4
  → 两个 2 保持原顺序 ✓ 稳定！

⚠️ 记忆："倒序回填 = 稳定性的关键"
```

### 2.3 优化版（负值/偏移）

```java
/**
 * 计数排序（支持负值）：偏移映射
 * 值域 [min, max] → 偏移 -min → [0, max-min]
 */
public void countingSortWithOffset(int[] arr, int min, int max) {
    int offset = -min;
    int[] count = new int[max - min + 1];

    for (int x : arr) {
        count[x + offset]++;            // ⚠️ 偏移映射
    }
    // 前缀和 + 倒序回填（同标准版）
    // 回填时记得 -offset 还原
}
// 例：值域 [-5, 10] → 偏移 5 → [0, 15]
```

## 3. 稳定性的实现

### 3.1 为什么稳定性重要

```
稳定排序：相等元素保持原相对顺序
  应用：二次排序（先按分数再按学号）
        基数排序的基础（按位多次计数）

⚠️ 计数排序稳定版是基数排序的组件：
  基数排序按位计数 → 必须稳定
  → 倒序回填是基数排序正确性的前提！
```

### 3.2 不稳定版本的陷阱

```
朴素版（直接输出）：
  遍历计数数组 → 按个数输出
  → 相同值顺序乱（不稳定）

何时可以接受不稳定？
  排序"纯数值"（无附加信息）→ 不影响结果
  排序"带记录"（对象）→ 必须稳定

⚠️ 面试表达：
"倒序回填保证稳定——相同值的相对顺序
 保持不变。基数排序按位多次计数依赖这一点。"
```

### 3.3 稳定性验证方法

```
测试用例：[a1, a2]（值相同但可区分）
  排序后 a1 仍在 a2 前 → 稳定

⚠️ 通用验证：
  给元素附加原始下标 → 排序后检查下标顺序
  （面试口头验证即可）
```

## 4. 计数排序 vs 其他线性排序

### 4.1 三种线性排序对比

| 排序 | 思想 | 复杂度 | 适用 |
|------|------|:---:|------|
| 计数 | 值 → 下标计数 | O(n+k) | 值域小 |
| 桶 | 均匀分桶 + 桶内排序 | O(n+k) | 均匀分布 |
| 基数 | 按位多次计数 | O(kn) | 定长数值 |

```
关系：
  基数排序 = 多次计数排序（按位）
  桶排序 = 广义的计数（桶内可任意排序）
  计数排序 = 每个值一个桶（桶排序特例）
```

### 4.2 复杂度细节

```
时间 O(n+k)：
  计数 O(n) + 前缀 O(k) + 回填 O(n)
  → k 远大于 n 时不如比较排序！

空间 O(k)：
  计数数组（值域大小）

⚠️ 选型判断：
  k ≤ n 或固定小范围 → 计数排序
  k 巨大（10⁹）→ 快排/基数
```

### 4.3 频次桶（面试高频变形）

```
计数排序思想的最常见应用：
  347 前 K 高频元素：频次作桶下标
  451 按频率排序：频次桶拼接

⚠️ 面试考察重点：
  不是"手撕计数排序"而是"计数思想的应用"
  （频次桶 = 计数 + 桶的变形）
```

## 6. 面试要点与追问

### 6.1 面试话术模板

```
"值域小用计数排序：计数数组统计频次 → 前缀和
 确定位置 → 倒序回填保证稳定。
 O(n+k) 时间 O(k) 空间，突破比较排序下界。
 值域大时不适用（数组爆炸）。
 基数排序的按位计数也依赖它（必须稳定）。"
```

### 6.2 高频追问 TOP 8

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | 为什么必须倒序回填？ | 稳定：相同值后出现的先占靠后位置 |
| 2 | 什么时候用计数排序？ | 值域小且已知（k ≤ n 或固定） |
| 3 | 复杂度？ | O(n+k) 时间 O(k) 空间 |
| 4 | 负值怎么处理？ | 偏移映射（+offset） |
| 5 | 与桶/基数关系？ | 计数是特例；基数 = 多次计数 |
| 6 | 为什么突破下界？ | 值当下标（不比较）→ 绕过 Ω(n log n) |
| 7 | 稳定性重要吗？ | 二次排序/基数排序依赖 |
| 8 | 面试考什么？ | 原理 + 稳定版手写 + 频次桶应用 |

### 6.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| 正序回填 | 不稳定 | 倒序回填 |
| 前缀和忘做 | 位置错 | count[i] += count[i-1] |
| 偏移忘还原 | 值错 | 回填 -offset |
| 值域大硬用 | 内存爆炸 | 换比较排序 |
| 拷贝漏 | 原数组未变 | System.arraycopy |

> 🎯 **核心要点**：计数排序 = **计数 → 前缀和 → 倒序回填**三步（倒序是稳定关键）。识别信号："值域小、O(n) 排序、频次统计"。高频变形是"频次作桶"（347 前 K 高频）；与基数排序的依赖关系（稳定性）是进阶必答。
