## 1. 枚举空间的复杂度评估

### 1.1 三种枚举形态

| 形态 | 空间 | 复杂度 | 代表 |
|------|------|:---:|------|
| 组合枚举 | C(n, k) | O(n^k) | 两数/三数之和 |
| 子集枚举 | 2^n | O(2^n) | 子集/位掩码 |
| 排列枚举 | n! | O(n!) | 全排列/旅行商 |
| 参数枚举 | 值域 | O(值域×判定) | 二分答案/暴力尝试 |

```
⚠️ 枚举的复杂度评估三步：
  ① 确定枚举对象（组合/子集/参数）
  ② 计算空间大小（C(n,k) / 2^n / n! / 值域）
  ③ 乘判定代价（每候选验证 O(1)/O(n)）

⚠️ 面试必答：
"先评估枚举空间再动手——C(10,3)=120 可暴力；
 C(10⁴,2)=5×10⁷ 需要优化；2^30 直接不可行。"
```

### 1.2 数据规模速查表

| 数据量 | 可行枚举 | 需要优化 |
|--------|---------|---------|
| n ≤ 10 | 全排列/子集（10!=3.6M） | 否 |
| n ≤ 20 | 子集（2^20≈10⁶） | 否 |
| n ≤ 10⁴ | 两两组合（10⁸ 边缘） | 哈希/双指针 |
| n ≤ 10⁵ | 一层枚举 | 必须 O(n) 或 O(n log n) |
| n ≤ 10⁹ | 不可枚举 | 数学/二分 |

```
⚠️ 经验阈值：
  10⁶-10⁷ 操作 = 1 秒（Java）
  组合枚举 C(n,2) 在 n=10⁴ 时 = 5×10⁷ 次（边缘可行）
  n=10⁵ 的 C(n,2) = 5×10⁹ → 必须降维

⚠️ 面试表达：
"n=10⁴ 的两两枚举约 5×10⁷ 勉强可行；
 n=10⁵ 就到 10⁹ 必须换思想——
 这是'该不该优化'的量化判断。"
```

### 1.3 枚举与暴力的关系

```
枚举 = 暴力的系统化：
  暴力：无差别尝试（可能重复）
  枚举：有组织地遍历解空间（不重不漏）

⚠️ 区别要点：
  枚举强调"完备性"（不遗漏任何可能）
  优化强调"减少空间"（等价类合并/剪枝）

面试表达：
"枚举是'解空间的系统遍历'——完备性是第一要求，
 优化是在完备的前提下减少无效尝试。"
```

## 2. 优化三板斧之一：排序去重

### 2.1 排序的价值

```
排序后的枚举收益：
  ① 去重：相同值相邻 → 跳过重复（15/18 三数/四数）
  ② 单调性：双指针代替内层枚举（O(n²) → O(n)）
  ③ 剪枝：边界判断（最小/最大组合）

⚠️ 排序的代价：O(n log n)（一次付出，多次受益）
```

### 2.2 排序 + 双指针（三数之和核心）

```java
/** 15 题骨架：排序 + 固定一个 + 双指针扫剩余 */
void threeSum(int[] nums) {
    Arrays.sort(nums);                       // ⚠️ ① 排序（去重 + 双指针前提）
    int n = nums.length;
    for (int i = 0; i < n - 2; i++) {
        if (i > 0 && nums[i] == nums[i - 1]) continue;   // ⚠️ ② 外层去重
        int lo = i + 1, hi = n - 1;
        while (lo < hi) {
            int sum = nums[i] + nums[lo] + nums[hi];
            if (sum == 0) {
                // 记录 + 内层去重（跳过相同 lo/hi）
                while (lo < hi && nums[lo] == nums[lo + 1]) lo++;
                while (lo < hi && nums[hi] == nums[hi - 1]) hi--;
                lo++; hi--;
            } else if (sum < 0) lo++;
            else hi--;
        }
    }
}
// ⚠️ 复杂度：排序 O(n log n) + 枚举 O(n²) = O(n²)
//   对比纯三重枚举 O(n³) → 双指针降一维
// ⚠️ 面试表达："排序 + 双指针把'两个自由变量'压缩成
//   '单调移动'——这是组合枚举降维的标准手段。"
```

### 2.3 去重技巧总结

```
去重的三个层次：
  ① 排序后跳过相同值（nums[i] == nums[i-1]）
  ② Set 记录已用组合（简单但费空间）
  ③ 枚举方向的等价类（子集用 start 下标防重复）

⚠️ 面试表达：
"去重本质是'等价类合并'——排序让相同值相邻，
 枚举时只取第一个。子集/组合的 start 下标
 也是等价类思想（顺序无关的组合只枚举一次）。"
```

## 3. 优化三板斧之二：哈希加速

### 3.1 用哈希"记住历史"

```
两数之和的 O(n) 优化：
  暴力：每对 (i,j) 检查 O(n²)
  哈希：遍历时把"已见值"存入 Map → 补数 O(1) 查找

⚠️ 通用模式：'边遍历边查历史'
  ① 需要找"与当前配对的过去元素" → 哈希记历史
  ② 历史可以是值/前缀和/频率

⚠️ 面试表达：
"哈希优化的本质是'空间换时间'——把 O(n) 的
 查找降为 O(1)。枚举类题目中，内层循环
 能被'查表'替代时，复杂度降一维。"
```

### 3.2 两数之和的哈希模板

```java
/** 1. 两数之和：边遍历边查补数 */
public int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> seen = new HashMap<>();
    for (int i = 0; i < nums.length; i++) {
        int need = target - nums[i];
        if (seen.containsKey(need)) return new int[]{seen.get(need), i};
        seen.put(nums[i], i);                // ⚠️ 先查后插（防重复使用）
    }
    return new int[]{-1, -1};
}
// ⚠️ 复杂度：O(n)（两两枚举 O(n²) → 哈希 O(n)）
// ⚠️ 衍生：454 四数相加（两两分组哈希）、560 前缀和+哈希
```

### 3.3 哈希 vs 排序双指针的选型

| 场景 | 选型 |
|------|------|
| 需要返回下标 | 哈希（保下标） |
| 需要去重 | 排序 + 双指针 |
| 需要有序结果 | 排序 + 双指针 |
| 值域大但稀疏 | 哈希 |
| 内存敏感 | 排序（O(1) 空间） |

## 4. 优化三板斧之三：剪枝与二分

### 4.1 剪枝的四种类型

| 剪枝 | 原理 | 例子 |
|------|------|------|
| 边界剪枝 | 当前组合不可能最优 | 四数之和跳过 |sum| 超界 |
| 可行性剪枝 | 剩余选择无法满足 | 组合总和剩余值不够 |
| 单调剪枝 | 有序后提前终止 | 双指针的 lo/hi 收敛 |
| 对称剪枝 | 等价情况只算一次 | 子集 start 下标 |

```java
/** 18 题剪枝示例（四数之和） */
void fourSum(int[] nums, int target) {
    Arrays.sort(nums);
    int n = nums.length;
    for (int i = 0; i < n - 3; i++) {
        // ⚠️ 剪枝 1：当前最小组合已超 → 后续全超
        if ((long) nums[i] + nums[i+1] + nums[i+2] + nums[i+3] > target) break;
        // ⚠️ 剪枝 2：当前最大组合不够 → 跳过 i（继续找更大的）
        if ((long) nums[i] + nums[n-1] + nums[n-2] + nums[n-3] < target) continue;
        for (int j = i + 1; j < n - 2; j++) { /* 双指针 + 同款剪枝 */ }
    }
}
// ⚠️ 剪枝的正确性：基于排序后的单调性（最值边界）
// ⚠️ 面试表达："剪枝 = 用'不可能区域'的快速判断
//   跳过整个枚举子树——边界判断 O(1)，省掉 O(n²)。"
```

### 4.2 参数枚举与二分替代

```
参数枚举：直接枚举"答案"（值域）
  例：69 平方根 → 枚举 0..x 找平方 ≤ x 的最大值 → O(√x) 太慢
  二分替代：mid² 与 x 比较 → O(log x)

⚠️ 二分答案 = 参数枚举的加速版（单调判定）
  判定单调 → 二分；判定不单调 → 只能枚举

⚠️ 面试表达：
"'答案值域可枚举'但空间大时，先问'判定是否单调'——
 单调 → 二分 O(log 值域)；不单调 → 枚举/数学。
 这是参数枚举的优化决策。"
```

## 5. 位掩码枚举

### 5.1 子集枚举的两种写法

```java
/** 78. 子集：位掩码枚举（每个元素选/不选） */
public List<List<Integer>> subsets(int[] nums) {
    int n = nums.length;
    List<List<Integer>> res = new ArrayList<>();
    for (int mask = 0; mask < (1 << n); mask++) {    // ⚠️ 2^n 个掩码
        List<Integer> sub = new ArrayList<>();
        for (int i = 0; i < n; i++)
            if ((mask & (1 << i)) != 0) sub.add(nums[i]);   // 第 i 位 = 1 → 选
        res.add(sub);
    }
    return res;
}
// 复杂度：O(2^n × n)（每掩码检查 n 位）
// ⚠️ 或回溯写法（start 下标递归）——两者结果相同

/** 子集枚举的子集遍历（进阶技巧） */
void enumerateSubsets(int mask) {
    // 遍历 mask 的所有子集（含空集）
    for (int sub = mask; sub > 0; sub = (sub - 1) & mask) {
        // 处理 sub
    }
}
// ⚠️ 复杂度：2^|mask|（子集数）
// ⚠️ 应用：状态压缩 DP 的枚举转移
```

### 5.2 位掩码枚举的边界

```
⚠️ 适用范围：n ≤ 20（2^20 ≈ 10⁶）
  n = 30 → 2^30 ≈ 10⁹（Java 1 秒上限边缘）
  n > 30 → 位掩码不可行（需数学/折半枚举）

折半枚举（Meet in the Middle）：
  30 个元素 → 拆两半各 15 → 各枚举 2^15
  → 组合两半结果（排序 + 双指针）→ 总 2^15×2 + 排序

⚠️ 面试表达：
"位掩码枚举 n≤20 直接做；n=30 用折半枚举
 （2^15+2^15 代替 2^30）——'指数减半'
 是处理大枚举空间的经典技巧。"
```

## 6. 枚举与相邻思想的边界

### 6.1 枚举 vs 回溯 vs 双指针

| 思想 | 枚举对象 | 特点 |
|------|---------|------|
| 枚举 | 全部可能（系统遍历） | 完备优先 |
| 回溯 | 解空间树（带剪枝） | 需要"方案"时 |
| 双指针 | 单调扫描 | 有序前提 |
| 贪心 | 局部最优 | 有最优子结构 |
| DP | 状态转移 | 重叠子问题 |

```
⚠️ 边界判断：
  需要"所有方案" → 枚举/回溯
  只要"一个最优" → 贪心/DP/双指针
  方案有顺序 → 排列枚举/回溯
  组合不重不漏 → 组合枚举

⚠️ 面试表达：
"枚举是'遍历解空间'的统称——回溯是带剪枝的
 深度枚举，双指针是单调空间的枚举加速，
 DP 是重叠枚举的记忆化。理解枚举 = 理解
 其他思想的底层。"
```

### 7.1 面试话术模板

```
"枚举先评估空间：C(n,k)/2^n/值域 × 判定代价。
 优化三板斧：排序去重（等价类合并）、
 哈希加速（边遍历边查历史）、剪枝二分（单调判定）。
 子集枚举用位掩码（n≤20）；n=30 折半枚举。
 评估结论：空间【X】→ 可行/需要优化/换思想。"
```
