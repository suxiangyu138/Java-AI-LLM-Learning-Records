## 2. 面试手写二分话术模板

> 面试官最看重的不是你能不能 AC，而是**能不能把边界讲清楚**。

### 2.1 五步话术框架

```
📣 第 1 步：识别二段性 (15秒)
"这道题我判断可以用二分：因为搜索空间（下标/值域）满足单调性——
满足条件的部分和不满足的部分有清晰分界。时间复杂度 O(log n)。"

📣 第 2 步：明确搜索空间与区间含义 (30秒) ⭐ 防错关键
"我使用左闭右闭区间 [left, right]。
 left 的含义是：已知左侧所有元素都 < target
 right 的含义是：已知右侧所有元素都 > target"

📣 第 3 步：写 mid 与更新规则 (30秒)
"mid = left + (right - left)/2 防溢出。
 如果 nums[mid] < target → 更新 left = mid + 1（mid 已排除）
 如果 nums[mid] > target → 更新 right = mid - 1"

📣 第 4 步：确认边界情况 (15秒)
"循环条件用 left <= right，这样 left == right 时元素也会被判断。
 空数组/单元素数组已提前处理。"

📣 第 5 步：复杂度与测试 (15秒)
"时间 O(log n)，空间 O(1)。我跑一下 [1,3,5,7] 找 5 验证。"
```

### 2.2 边界题附加话术（34 题场景）

```
"这道题要求两个边界，我的思路是拆成两次二分：
 第一次找第一个 ≥ target 的位置（lowerBound），
 第二次找第一个 > target 的位置（upperBound），
 左边界 = lowerBound，右边界 = upperBound - 1。
 两次都是 O(log n)，总计 O(log n)。

 关键点：找到 target 后不能直接返回，要继续逼近边界——
 找左边界时命中后收缩 right，找右边界时命中后收缩 left。
 右边界需要注意 mid 向上取整避免死循环。"
```

## 3. 高频追问 TOP 10 与标准回答

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | `left < right` 和 `left <= right` 的区别？ | 前者区间只剩一个元素时退出，适合边界/不变量写法；后者单个元素也会判断，适合精确查找。核心是**区间为空的定义不同**：`left>right` vs `left==right` |
| 2 | 二分一定要求数组有序吗？ | 不是。二分的本质是**二段性**——只要能把区间划分为"满足/不满足"两部分且可判定即可。旋转数组、峰值问题、答案二分都不要求整体有序 |
| 3 | 为什么 mid 要写成 `left+(right-left)/2`？ | 防止 `left+right` 溢出 int 上限。数学上等价，但避免了大数相加越界 |
| 4 | 找左边界时命中 target 为什么不返回？ | 命中的可能是中间重复元素，左边可能还有 target。需要继续收缩右边界逼近第一个位置 |
| 5 | 右边界为什么要 mid 向上取整？ | 当 `left = mid` 时，若 mid 向下取整可能等于 left，left 不再前进 → 死循环。向上取整保证 left 每次至少前进 1 |
| 6 | 什么是答案二分？ | 直接在答案值域上二分，用 check(mid) 判断可行性。适用"求最小X使条件成立"且 check 单调的问题，如 875 |
| 7 | 二分为什么是 O(log n)？ | 每轮区间减半，n→n/2→n/4→...→1，共 log₂n 轮，每轮 O(1) |
| 8 | 旋转数组最小值为什么以 nums[right] 为基准？ | 用 nums[left] 在"未旋转"场景会误判（递增时 mid 总大于 left）。nums[right] 在所有场景都能正确判断 mid 所在段 |
| 9 | 含重复的旋转数组复杂度？ | 大量重复时无法判断段归属，只能 left++/right-- 逐步收缩，最坏 O(n)。需要向面试官主动说明这个退化 |
| 10 | 浮点数二分怎么写？ | 循环条件改为 `right - left > 1e-7` 精度控制，收缩不需要 ±1。或固定迭代 100 次更稳定 |

## 4. 高频题深度复盘（含手写演练）

### 4.1 35. 搜索插入位置 — lowerBound 直接应用

```java
/**
 * 给定排序数组和目标值，如果找到返回下标，否则返回按序插入的位置。
 * 本质：lowerBound(nums, target) —— 第一个 ≥ target 的位置
 */
public int searchInsert(int[] nums, int target) {
    int left = 0, right = nums.length;
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] < target) {
            left = mid + 1;
        } else {
            right = mid;
        }
    }
    return left;   // 无需验证！插入位置一定存在
}
// [1,3,5,6], target=5 → 2; target=2 → 1; target=7 → 4; target=0 → 0
```

### 4.2 153. 旋转数组最小值 — 手写演练

```java
public int findMin(int[] nums) {
    int left = 0, right = nums.length - 1;
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] > nums[right]) {
            left = mid + 1;    // mid 在左段（较大段）→ 最小值在右
        } else {
            right = mid;       // mid 在右段（较小段）→ 最小值在左或等于 mid
        }
    }
    return nums[left];
}
// 手写自检：mid 与 nums[right] 比较——为什么？因为右端点是"分界线"的锚点
```

### 4.3 875. 吃香蕉 — 答案二分手写演练

```java
public int minEatingSpeed(int[] piles, int h) {
    int max = 0;
    for (int p : piles) max = Math.max(max, p);

    int left = 1, right = max;
    while (left < right) {
        int mid = left + (right - left) / 2;
        long hours = 0;
        for (int p : piles) {
            hours += (p + mid - 1) / mid;
            if (hours > h) break;
        }
        if (hours <= h) right = mid;
        else left = mid + 1;
    }
    return left;
}
// 关键自检：
// ① 值域是否覆盖答案？ [1, max] ✓（速度至少 1，最大堆可一次吃完）
// ② check 单调吗？ 速度越大时间越少 ✓
// ③ hours 会溢出吗？ 用 long ✓
```

## 5. 调试技巧与自检清单

### 5.1 二分 Bug 自检三步法

```
第 1 步：模拟 2-3 个用例（空数组、单元素、target 在两端、target 不存在）
第 2 步：检查死循环风险——
        如果区间收缩时 left 或 right 有可能不变化 → 死循环
        （左边界用 right=mid 必须配向下取整；
          右边界用 left=mid 必须配向上取整）
第 3 步：检查最终返回值——
        精确查找：返回 -1 还是下标？
        边界查找：返回 left 还是需要验证 nums[left] == target？
```

### 5.2 二分高频 Bug 速查表

| Bug | 原因 | 修复 |
|------|------|------|
| 死循环 | `left=mid` 配向下取整 | 右边界改成向上取整 |
| 漏掉最后一个元素 | 左闭右闭用了 `left<right` | 改成 `left<=right` |
| 返回错误下标 | 混淆了 lowerBound 与左边界 | 边界题最后验证 `nums[left]==target` |
| 越界异常 | 未处理空数组 | `if (nums.length == 0)` 前置 |
| 结果溢出 | `mid*mid`、`left+right`、hours 求和 | 全部用 `long` |
| 旋转数组误判 | 用固定 `nums[0]` 判段 | 用动态 `nums[left]` 或 `nums[right]` |
| 答案二分越界 | 值域上下界取错 | 下界取最大约束，上界取总和 |

### 5.3 面试手写自检 Checklist

```
□ 说出二段性在哪里（一句话）
□ 说清区间是左闭右闭还是左闭右开
□ mid 防溢出写法
□ 循环条件与区间写法匹配
□ 收缩时 mid 是否已被正确排除
□ 边界题：命中后是否继续逼近（不是立即返回）
□ 边界题：最后是否验证 nums[left] 的值
□ 数值题：是否用 long 防溢出
□ 答案二分：check 函数是否单调
□ 手动跑 1 个用例验证
```
