## 1. 旋转数组的本质

### 1.1 什么是旋转数组

```
原数组：[0, 1, 2, 4, 5, 6, 7]
旋转 k=3 次 → [4, 5, 6, 7, 0, 1, 2]
                     ↑     ↑
                递增段A  递增段B（更小）

关键性质：旋转数组 = 两段各自递增的数组，且 B 段所有元素 < A 段所有元素
         （无重复时：B段最大值 < A段最小值）
```

### 1.2 二分在旋转数组上为什么可行？

```
二段性在哪？
以 nums[right]（或 nums[0]）为基准，把数组分成两段：
  [4, 5, 6, 7, 0, 1, 2]
   └────> right ────┘
  nums[mid] > nums[right] → mid 在 A 段（左段）
  nums[mid] ≤ nums[right] → mid 在 B 段（右段）

这就是旋转数组的二段性！不是有序，但可以判断 mid 落在哪一段，
进而收缩搜索区间。
```

## 2. 153. 寻找旋转数组最小值

### 2.1 问题与分析

```java
/**
 * LeetCode 153. 寻找旋转排序数组中的最小值
 * 数组 [0,1,2,4,5,6,7] 旋转后如 [4,5,6,7,0,1,2]，找最小值 0。
 * 所有元素互不相同，O(log n)。
 *
 * 关键观察：
 *   以 nums[right] 为基准——
 *   若 nums[mid] > nums[right] → mid 在左段（较大的递增段）
 *      → 最小值在 mid 右边 → left = mid + 1
 *   若 nums[mid] < nums[right] → mid 在右段（较小的递增段）
 *      → 最小值在 mid 左侧或就是 mid → right = mid
 */
public int findMin(int[] nums) {
    int left = 0, right = nums.length - 1;
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] > nums[right]) {
            left = mid + 1;    // mid 在左段，最小值在右边
        } else {
            right = mid;       // mid 在右段，最小值在 mid 或其左边
        }
    }
    return nums[left];
}
```

### 2.2 推演：nums = [4, 5, 6, 7, 0, 1, 2]

```
初始: left=0, right=6
mid=3 → nums[3]=7 > nums[6]=2 → left=4        (最小值在 [4,6])
mid=5 → nums[5]=1 < nums[6]=2 → right=5       (最小值在 [4,5])
mid=4 → nums[4]=0 < nums[5]=1 → right=4       (最小值在 [4,4])
left=4 == right=4 → 返回 nums[4]=0 ✓

// 未旋转情况 nums=[0,1,2,3,4]：
mid=2 → nums[2]=2 < nums[4]=4 → right=2
mid=1 → nums[1]=1 < nums[2]=2 → right=1
mid=0 → nums[0]=0 < nums[1]=1 → right=0
返回 nums[0]=0 ✓ (未旋转时最小值就是第一个元素)
```

### 2.3 为什么基准选 nums[right] 而不是 nums[left]？

```
以 nums[left] 为基准的坑：
  [4,5,6,7,0,1,2] 中 mid=3 → nums[3]=7 > nums[0]=4 → 判定 mid 在左段 ✓
  但未旋转的 [0,1,2,3,4] 中 mid=2 → nums[2]=2 > nums[0]=0 → 误判为左段！
  → 未旋转的情况会出错

以 nums[right] 为基准完美覆盖未旋转场景（最小值始终在 [left, right] 的右段边界）
```

## 3. 33. 搜索旋转排序数组

### 3.1 问题与分析

```java
/**
 * LeetCode 33. 搜索旋转排序数组
 * 旋转数组 [4,5,6,7,0,1,2] 中搜索 target=0，返回下标 4，不存在返回 -1。
 * 元素互不相同，O(log n)。
 *
 * 两步走：
 *   第一步：判断 mid 落在哪一段（比较 nums[mid] 与 nums[0]）
 *   第二步：根据 target 与段边界的关系，确定去哪一段收缩
 */
public int search(int[] nums, int target) {
    int left = 0, right = nums.length - 1;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] == target) return mid;

        // 判断 mid 落在左段还是右段（以 nums[left] 为基准判断哪段有序）
        if (nums[mid] >= nums[left]) {
            // mid 在左段（较大的递增段，该段有序）
            if (target >= nums[left] && target < nums[mid]) {
                right = mid - 1;          // target 在左段的前半部分
            } else {
                left = mid + 1;           // target 在别处
            }
        } else {
            // mid 在右段（较小的递增段，该段有序）
            if (target > nums[mid] && target <= nums[right]) {
                left = mid + 1;           // target 在右段的后半部分
            } else {
                right = mid - 1;
            }
        }
    }
    return -1;
}
```

### 3.2 推演：nums = [4, 5, 6, 7, 0, 1, 2], target = 0

```
初始: left=0, right=6
mid=3 → nums[3]=7 ≠ 0, 7 ≥ 4 → 左段
      target=0 < 4 → 不在左段前半 → left=4
mid=5 → nums[5]=1 ≠ 0, 1 < 4 → 右段
      target=0 < 1 且 0 ≤ nums[6]=2 → 右段后半 → left=6
mid=6 → nums[6]=2 ≠ 0, 2 < 4 → 右段
      target=0 < 2 且 0 ≤ 2 → left=7 > right → 返回 -1 ❌

等等！target=0 明明在 nums[4]！重新推演：
mid=3 → nums[3]=7 ≥ nums[0]=4 → mid 在左段
      判断 target=0：0 ≥ 4? 否 → 走 else → left=4 ✓ 进入 [4,6]
mid=5 → nums[5]=1 ≥ nums[4]=0 → mid 在左段！
      （注意：此时 left=4，以 nums[left] 判断，[4,5,6] 中 1≥0 成立 → 左段）
      target=0 ≥ 0 且 0 < 1 → 左段前半 → right=4 ✓
mid=4 → nums[4]=0 == 0 → 返回 4 ✓
```

> ⚠️ **注意**：33 题中"左段/右段"的判断基准是**动态的 nums[left]**（随 left 变化），每次循环重新判断，不要用固定的 nums[0]。

## 4. 81. 含重复元素的旋转搜索

### 4.1 问题与分析

```java
/**
 * LeetCode 81. 搜索旋转排序数组 II
 * 与 33 题相同，但允许数组含重复元素。
 *
 * 退化场景：nums = [1, 0, 1, 1, 1], target = 0
 *   mid=2 → nums[2]=1，nums[left]=1 → 相等！
 *   无法判断 mid 在左段还是右段 → 唯一的处理办法：
 *   left++（或 right--），把相同的端点移掉，逐步恢复二段性
 *   最坏情况（大量重复）→ O(n)
 */
public boolean search(int[] nums, int target) {
    int left = 0, right = nums.length - 1;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] == target) return true;

        // 处理重复：无法判断段归属时，收缩端点
        if (nums[left] == nums[mid] && nums[mid] == nums[right]) {
            left++;
            right--;
        } else if (nums[mid] >= nums[left]) {
            // mid 在左段
            if (target >= nums[left] && target < nums[mid]) {
                right = mid - 1;
            } else {
                left = mid + 1;
            }
        } else {
            // mid 在右段
            if (target > nums[mid] && target <= nums[right]) {
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }
    }
    return false;
}
```

### 4.2 复杂度分析

| 情况 | 复杂度 | 原因 |
|------|:---:|------|
| 大部分元素不重复 | O(log n) | 正常二分收缩 |
| 大量重复（如全 1） | **O(n)** | 每次只能 left++/right-- 各移一位 |

> 💡 **面试加分**：主动指出"含重复时最坏会退化到 O(n)"——展示你对算法边界的深刻理解。

## 5. 162. 寻找峰值

### 5.1 问题与分析

```java
/**
 * LeetCode 162. 寻找峰值
 * 峰值元素：严格大于左右相邻值的元素。数组两端视为 -∞。
 * nums = [1, 2, 3, 1] → 峰值是 3（下标 2）
 * 要求 O(log n)，可能有多个峰值，返回任意一个。
 *
 * 二段性在哪？
 *   比较 nums[mid] 与 nums[mid+1]：
 *     nums[mid] < nums[mid+1] → 右侧必然存在峰值（上坡必有顶）
 *     nums[mid] > nums[mid+1] → 左侧必然存在峰值（下坡起始必有顶）
 *
 * 极值边界：端点视为 -∞ 保证单调数组也有峰值
 *   [1,2,3,4,5] → 5 是峰值（右边 -∞）→ 返回 4
 *   [5,4,3,2,1] → 5 是峰值（左边 -∞）→ 返回 0
 */
public int findPeakElement(int[] nums) {
    int left = 0, right = nums.length - 1;
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] < nums[mid + 1]) {
            left = mid + 1;      // 上坡 → 峰值在右侧
        } else {
            right = mid;         // 下坡或平顶 → 峰值在左侧或就是 mid
        }
    }
    return left;
}
```

### 5.2 为什么"上坡必有顶"？

```
nums = [1, 3, 5, 4, 2]

mid=2 → nums[2]=5 > nums[3]=4 → 下坡 → 峰值在 [0,2] 内
  （因为 nums[2]=5 要么是峰值，要么左边还有更高点，总之左侧必有峰）
mid=1 → nums[1]=3 < nums[2]=5 → 上坡 → 峰值在 [2,2]
  返回 2 → nums[2]=5 ✓

逻辑保证：每次收缩后，新区间内部**必然**存在至少一个峰值
（这就是"二段性"——左右方向的选择不是靠直觉，而是有数学保证）
```

## 6. 852. 山脉数组的峰顶索引

### 6.1 问题与分析

```java
/**
 * LeetCode 852. 山脉数组的峰顶索引
 * 山脉数组：先严格递增后严格递减，无重复。如 [0, 1, 2, 3, 2, 1]。
 * 返回峰顶下标（最大值位置）。
 *
 * 本质：162 寻找峰值的特例（保证存在唯一山峰）
 */
public int peakIndexInMountainArray(int[] arr) {
    int left = 0, right = arr.length - 1;
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (arr[mid] < arr[mid + 1]) {
            left = mid + 1;   // 仍在上升段 → 峰顶在右侧
        } else {
            right = mid;      // 已过峰顶 → 峰顶在左侧或就是 mid
        }
    }
    return left;
}
```

### 6.2 旋转数组 + 峰值专题总结

| 题目 | 二段性基准 | 判断逻辑 | 复杂度 |
|:---:|------|------|:---:|
| 153 最小值 | `nums[right]` | mid > right → 左段(右移)；否则右段(保留) | O(log n) |
| 33 搜索 | `nums[left]` 动态 | 先判段归属，再按 target 与段边界收缩 | O(log n) |
| 81 搜索 II | `nums[left]` | 三端相等 → left++/right-- | O(log n)~O(n) |
| 162 峰值 | `nums[mid+1]` | 上坡 → 右移；下坡 → 保留 | O(log n) |
| 852 峰顶 | `nums[mid+1]` | 同 162，特例版 | O(log n) |

> 🎯 **核心要点**：旋转数组和峰值问题共同演示了二分的本质——**不要求整体有序，只要求存在可判定的二段性**。旋转数组以端点值判断段归属，峰值问题以上坡/下坡判断方向。记住各自的"基准"（`nums[right]`、动态 `nums[left]`、`nums[mid+1]`），就能在 30 秒内识别并套用。
