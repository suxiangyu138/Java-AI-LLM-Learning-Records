## 1. 二段性：二分的本质

### 1.1 破除迷思

> ⚠️ **最常见的误解**："二分查找要求数组必须有序。"

**真相**：二分查找的根本前提不是"有序"，而是**二段性（单调性）**——能够把搜索区间明确划分成"满足条件"和"不满足条件"两个部分，且两部分之间存在清晰的分界点。

```
二段性的两种表现形式：

① 数组单调（下标上的二段性）
   有序数组中找 target：
   [1, 3, 5, 7, 9, 11]
   └────< 7────┘ └──> 7──┘
   前半段全 < target，后半段全 > target → 可二分

② 答案单调（值域上的二段性）
   求"最小速度"问题：速度越快，需要的天数越少（单调递减）
   速度 v → check(v) 天数 ≤ D ? 满足 : 不满足
   | 不满足 | 满足 |   ← 临界点就是答案
   v=1     v=k   v=∞
   → 在值域 [1, 最大速度] 上二分
```

### 1.2 如何判断能否用二分

```
问自己三个问题：
1. 我的搜索空间是什么？（数组下标 or 答案值域）
2. 搜索空间是否有单调性（二段性）？
3. 能否写一个 check(mid) 函数判断 mid 处于哪一段？

三个问题都回答"是" → 二分可行
```

| 反例 | 为什么不能二分 |
|------|------|
| 无序数组找 target | 没有二段性，无法判断目标在哪一侧 |
| 求数组中第二大的值 | 值域上没有单调的判定函数 |
| 图的最短路 | 边权非负时其实可以（Dijkstra 是贪心+优先队列，不是二分） |

## 2. 二分查找的工作流程

```
初始化：left = 0, right = n - 1（左闭右闭）
循环：while (left <= right)
  mid = left + (right - left) / 2
  |--- nums[mid] == target → 命中，返回 mid
  |--- nums[mid] < target  → target 在右半 → left = mid + 1
  |--- nums[mid] > target  → target 在左半 → right = mid - 1
未命中 → 返回 -1
```

### 模拟演示：nums = [1, 3, 5, 7, 9], target = 5

```
初始:  left=0, right=4
第1轮: mid=(0+4)/2=2, nums[2]=5 == target ✓ 返回 2

// 更完整的追踪（target=3）：
初始:  left=0, right=4, mid=2 → nums[2]=5 > 3 → right=1
第2轮: left=0, right=1, mid=0 → nums[0]=1 < 3 → left=1
第3轮: left=1, right=1, mid=1 → nums[1]=3 == 3 ✓ 返回 1

// 未命中追踪（target=4）：
初始:  left=0, right=4, mid=2 → nums[2]=5 > 4 → right=1
第2轮: left=0, right=1, mid=0 → nums[0]=1 < 4 → left=1
第3轮: left=1, right=1, mid=1 → nums[1]=3 < 4 → left=2
循环结束: left=2 > right=1 → 返回 -1 ✓
```

## 3. 两种区间写法：左闭右闭 vs 左闭右开

### 3.1 左闭右闭 [left, right] ⭐ 面试推荐

```java
// 核心要点：
// - right 初始为 n-1（最后一个元素在区间内）
// - 循环条件 left <= right（left==right 时元素仍需判断）
// - left = mid+1, right = mid-1（mid 已排除）
public int search(int[] nums, int target) {
    int left = 0, right = nums.length - 1;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] == target) return mid;
        else if (nums[mid] < target) left = mid + 1;
        else right = mid - 1;
    }
    return -1;
}
```

### 3.2 左闭右开 [left, right)

```java
// 核心要点：
// - right 初始为 n（最后一个元素不在区间内）
// - 循环条件 left < right（left==right 时区间为空）
// - left = mid+1, right = mid（mid 本身不在右开区间内，保留无妨）
public int search(int[] nums, int target) {
    int left = 0, right = nums.length;
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] == target) return mid;
        else if (nums[mid] < target) left = mid + 1;
        else right = mid;
    }
    return -1;
}
```

### 3.3 两种写法对照

| 维度 | 左闭右闭 [L, R] | 左闭右开 [L, R) |
|------|:---:|:---:|
| right 初始值 | `n - 1` | `n` |
| 循环条件 | `left <= right` | `left < right` |
| 区间为空判定 | `left > right` | `left == right` |
| 左收缩 | `left = mid + 1` | `left = mid + 1` |
| 右收缩 | `right = mid - 1` | `right = mid` |
| mid 是答案时 | 已排除，±1 | 右开不包含，保留 |
| 适用场景 | 精确查找 | 边界查找（lowerBound 等） |

> ⚠️ **最重要的教训**：两种写法不要混用！混用是最常见的死循环来源。选定一种并始终如一——**面试中推荐左闭右闭，因为最直觉**；**边界题中左闭右开配合 `right=mid` 是 STL 的标准做法**。

## 4. 基础模板题：704 二分查找

### 4.1 完整实现（左闭右闭 + 递归版）

```java
/**
 * LeetCode 704. 二分查找
 * 给定 n 个升序排列的整数数组 nums 和目标值 target，
 * 返回 target 在 nums 中的下标，不存在返回 -1。
 * 时间复杂度 O(log n)，空间 O(1)
 */
public class Solution704 {

    // 迭代版（面试首选）
    public int search(int[] nums, int target) {
        int left = 0, right = nums.length - 1;
        while (left <= right) {
            int mid = left + (right - left) / 2;   // 防溢出写法
            if (nums[mid] == target) {
                return mid;
            } else if (nums[mid] < target) {
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }
        return -1;
    }

    // 递归版（考察递归思维时展示）
    public int searchRecursive(int[] nums, int target) {
        return binarySearch(nums, 0, nums.length - 1, target);
    }

    private int binarySearch(int[] nums, int left, int right, int target) {
        if (left > right) return -1;                    // 区间为空
        int mid = left + (right - left) / 2;
        if (nums[mid] == target) return mid;
        if (nums[mid] < target) return binarySearch(nums, mid + 1, right, target);
        return binarySearch(nums, left, mid - 1, target);
    }
}
```

### 4.2 为什么用 `left + (right - left) / 2`？

```
错误写法：(left + right) / 2
  当 left 和 right 都接近 Integer.MAX_VALUE 时，
  left + right 溢出为负数 → mid 变负 → 越界

正确写法：left + (right - left) / 2
  数学上等价于 (left+right)/2，但不会溢出
  例：left=2_000_000_000, right=2_000_000_000
    (left+right)/2 → 溢出 ❌
    left+(right-left)/2 → 2_000_000_000 + 0 ✓
```

## 5. 为什么二分查找是 O(log n)

```
每次循环区间长度减半：
  n → n/2 → n/4 → n/8 → ... → 1

设循环次数为 k，则 n / 2^k = 1 → k = log₂(n)

例：n = 2^30 ≈ 10亿，只需 30 次比较
  对比线性查找：最坏 10 亿次
  二分快了 3300 万倍
```

| 数据规模 | 线性查找 | 二分查找 |
|:---:|:---:|:---:|
| 1,000 | 1,000 次 | **10 次** |
| 1,000,000 | 1,000,000 次 | **20 次** |
| 10 亿 | 10 亿次 | **30 次** |
| 10 万亿 | 10 万亿次 | **44 次** |

## 6. 常见错误与避坑指南

| 错误 | 错误写法 | 正确写法 | 后果 |
|------|------|------|------|
| **mid 溢出** | `(left + right) / 2` | `left + (right - left) / 2` | 大数越界崩溃 |
| **循环条件错** | 左闭右闭用 `left < right` | `left <= right` | 最后一个元素漏检 |
| **区间收缩错** | 命中后 `left = mid` | `left = mid + 1` | 死循环（mid 永远不变） |
| **混用两种写法** | 左闭右开但 `right = mid - 1` | 保持一种风格 | 漏检/死循环 |
| **未处理空数组** | 直接 `nums[mid]` | `if (n == 0) return -1` | 越界异常 |
| **返回错误值** | 找不到返回 `left` | 返回 -1（边界题返回 left 另有含义） | 语义错误 |

### 死循环自检法

```
出现死循环 → 检查区间收缩：
  如果 left 和 mid 相等且 left 没有前进 → 死循环

自检用例（心里模拟 1-2 轮）：
  nums = [1], target = 0
  左闭右闭: left=0, right=0, mid=0, 0<1 → left=1 > right → 退出 ✓
  nums = [1], target = 1
  左闭右闭: left=0, right=0, mid=0, 相等 → 返回 0 ✓
```

> 🎯 **核心要点**：二分的本质是**二段性**而非有序。基础模板记住三个固定动作——`mid 防溢出`、`left<=right 循环`、`mid 排除后 ±1`。写完后用 2-3 个边界用例（空数组、单元素、未命中）在心里跑一遍，这是面试不丢分的保障。
