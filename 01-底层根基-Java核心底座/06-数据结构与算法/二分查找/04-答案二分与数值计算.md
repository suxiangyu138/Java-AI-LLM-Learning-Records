## 1. 什么是答案二分

### 1.1 核心思想

> 当问题直接求解困难，但**判断某个候选答案是否可行**容易时，在**答案的值域**上二分，不断逼近最优答案。

```
经典场景："求最小 X，使得 check(X) 成立"

例子：吃完所有香蕉所需的最小速度 v
  v 越大 → 需要天数越少（单调递减）
  | 不满足(check(v) > D) | 满足(check(v) ≤ D) |
  v = 1        v = k ← 答案      v = ∞
  
在值域 [1, maxPile] 上二分查找这个临界点
```

### 1.2 答案二分的识别特征

```
出现这些关键词 → 考虑答案二分：
  "最小化最大值" / "最大化最小值"
  "在 D 天内" / "至少 k 次" / "不超过 X 的"
  "求最小速度 / 最小运力 / 最少天数 / 最小容量"

判断标准：
  1. 答案落在某个整数区间 [lo, hi]（值域清晰）
  2. 存在单调的 check(mid)：mid 满足 → 更大的 mid 也满足
  3. 直接求答案难，验证答案易
```

| 直接求解（难） | check 验证（易） |
|------|------|
| 最少需要多快的速度？ | 给定速度 v，模拟算几天？ |
| 最少多少天？ | 给定天数 D，模拟能否装完？ |
| 最小容量？ | 给定容量 c，模拟能否装下？ |

## 2. 875. 爱吃香蕉的珂珂（最小化答案）

### 2.1 问题分析

```java
/**
 * LeetCode 875. 爱吃香蕉的珂珂
 * 珂珂喜欢一根一根地吃香蕉。piles[i] 表示第 i 堆香蕉的根数。
 * 如果她决定用速度 h 根/小时吃，那么每堆香蕉她都会以该速度吃完该堆，
 * 然后花 1 小时吃下一堆。返回她可以在 h 小时内吃完所有香蕉的最小速度 k。
 *
 * 值域：[1, max(piles)]   （每小时至少 1 根，最多一次吃完最大堆）
 * check(mid)：以速度 mid 吃，总耗时 ≤ h 吗？
 *
 * 吃一堆的时间 = ceil(pile / speed) = (pile + speed - 1) / speed
 * ⚠️ 注意 sum 可能溢出 int → 用 long
 */
public int minEatingSpeed(int[] piles, int h) {
    int maxPile = 0;
    for (int p : piles) maxPile = Math.max(maxPile, p);

    int left = 1, right = maxPile;       // 答案值域
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (canFinish(piles, h, mid)) {
            right = mid;                 // mid 可行 → 尝试更小速度
        } else {
            left = mid + 1;              // mid 不可行 → 必须更快
        }
    }
    return left;                         // 最小可行速度
}

// check 函数：以 speed 速度能否在 h 小时内吃完
private boolean canFinish(int[] piles, int h, int speed) {
    long hours = 0;
    for (int p : piles) {
        hours += (p + speed - 1) / speed;   // 向上取整
        if (hours > h) return false;        // 提前剪枝
    }
    return hours <= h;
}
```

### 2.2 推演：piles = [3, 6, 7, 11], h = 8

```
值域 [1, 11]
mid=6 → canFinish(6): 3/6=1 + 6/6=1 + 7/6=2 + 11/6=2 = 6 ≤ 8 ✓ → right=6
mid=3 → canFinish(3): 1+2+3+4 = 10 > 8 ✗ → left=4
mid=5 → canFinish(5): 1+2+2+3 = 8 ≤ 8 ✓ → right=5
mid=4 → canFinish(4): 1+2+2+3 = 8 ≤ 8 ✓ → right=4
left=4 == right=4 → 返回 4 ✓
验证：速度 3 需要 10 小时不行，速度 4 恰好 8 小时 → 答案 4
```

## 3. 1011. 在 D 天内送达包裹（最大化最小值思想）

### 3.1 问题分析

```java
/**
 * LeetCode 1011. 在 D 天内送达包裹的能力
 * 传送带上的包裹按顺序装载，重量数组 weights。
 * 船每天最多装连续的一批包裹（不能打乱顺序），求在 D 天内
 * 运完所有包裹的最小运载能力。
 *
 * 值域：[max(weights), sum(weights)]
 *   - 下限：至少能装下最重的单个包裹
 *   - 上限：一天全装完
 * check(mid)：运力 capacity 能否 D 天内运完？
 */
public int shipWithinDays(int[] weights, int days) {
    int left = 0, right = 0;
    for (int w : weights) {
        left = Math.max(left, w);   // 下界：最重包裹
        right += w;                 // 上界：总重量
    }

    while (left < right) {
        int mid = left + (right - left) / 2;
        if (canShip(weights, days, mid)) {
            right = mid;            // 能运完 → 尝试更小运力
        } else {
            left = mid + 1;
        }
    }
    return left;
}

// check 函数：模拟按顺序装载，统计需要几天
private boolean canShip(int[] weights, int days, int capacity) {
    int dayCount = 1;
    int currentLoad = 0;
    for (int w : weights) {
        if (currentLoad + w > capacity) {
            dayCount++;             // 装不下 → 新开一天
            currentLoad = 0;
            if (dayCount > days) return false;
        }
        currentLoad += w;
    }
    return true;
}
```

### 3.2 为什么上下界这样取？

| 边界 | 取值 | 原因 |
|:---:|------|------|
| 下界 left | `max(weights)` | 运力小于最重包裹 → 永远装不完它 |
| 上界 right | `sum(weights)` | 一天全装完必可行（保证二分有解） |
| check 模拟 | 顺序累积 | 包裹必须按序运输，不能跳过 |

## 4. 410. 分割数组的最大值

### 4.1 问题分析

```java
/**
 * LeetCode 410. 分割数组的最大值
 * 给定非负整数数组 nums 和一个整数 k，将数组分成 k 个非空子数组，
 * 使得这 k 个子数组各自和的最大值最小。返回这个最小化的最大值。
 *
 * "最小化最大值" → 经典答案二分
 * 值域：[max(nums), sum(nums)]
 * check(mid)：能否分成 ≤ k 段，每段和 ≤ mid？
 *
 * 注意：1011 的 check 是"天数 ≤ D"，410 的 check 是"段数 ≤ k"
 * —— 两个问题本质相同（都是按容量切分），只是场景不同
 */
public int splitArray(int[] nums, int k) {
    int left = 0, right = 0;
    for (int x : nums) {
        left = Math.max(left, x);
        right += x;
    }

    while (left < right) {
        int mid = left + (right - left) / 2;
        if (canSplit(nums, k, mid)) {
            right = mid;
        } else {
            left = mid + 1;
        }
    }
    return left;
}

private boolean canSplit(int[] nums, int k, int maxSum) {
    int parts = 1, curSum = 0;
    for (int x : nums) {
        if (curSum + x > maxSum) {
            parts++;                  // 新开一段
            curSum = 0;
            if (parts > k) return false;
        }
        curSum += x;
    }
    return parts <= k;
}
```

### 4.2 "切分型"答案二分三兄弟

| 题目 | 场景 | check 逻辑 |
|:---:|------|------|
| 875 吃香蕉 | 时间约束 | 总小时数 ≤ h |
| 1011 运包裹 | 天数约束 | 天数 ≤ D |
| 410 分割数组 | 段数约束 | 段数 ≤ k |
| 1283 最小除数 | 商和约束 | 商之和 ≤ threshold |
| 1482 制作 m 束花 | 天数约束 | 可采花数 ≥ m |

## 5. 69. x 的平方根（整数数值二分）

### 5.1 问题分析

```java
/**
 * LeetCode 69. x 的平方根
 * 返回 x 的平方根的整数部分（向下取整），不使用内置库函数。
 *
 * 值域：[1, x]
 * 单调性：mid² 随 mid 单调递增
 * 要找的是：最后一个满足 mid² ≤ x 的 mid（右边界变形！）
 *
 * ⚠️ mid * mid 可能溢出 int → 用 long
 */
public int mySqrt(int x) {
    if (x < 2) return x;                    // 0 和 1 的平方根就是自身

    int left = 1, right = x;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        long square = (long) mid * mid;     // ⚠️ long 防溢出
        if (square == x) {
            return mid;
        } else if (square < x) {
            left = mid + 1;                 // 还不够大 → 向右
        } else {
            right = mid - 1;                // 太大了 → 向左
        }
    }
    return right;                           // 最后一个 mid² ≤ x 的位置
}
```

### 5.2 变形题：367. 有效的完全平方数

```java
public boolean isPerfectSquare(int num) {
    long left = 1, right = num;
    while (left <= right) {
        long mid = left + (right - left) / 2;
        long square = mid * mid;
        if (square == num) return true;
        else if (square < num) left = mid + 1;
        else right = mid - 1;
    }
    return false;   // 找不到精确等于 → 不是完全平方数
}
```

### 5.3 数值二分注意事项

| 陷阱 | 解决方案 |
|------|------|
| `mid * mid` int 溢出 | 用 `long` 类型计算 |
| 左闭右闭时找不到精确值 | 返回 `right`（最后一个满足条件的位置） |
| x=0 或 1 | 提前特判返回 |
| 二分只找整数 | 浮点结果需另行处理（见下节） |

## 6. 浮点数二分

### 6.1 通用模板

```java
/**
 * 浮点数二分：找满足条件的实数答案
 * 与整数二分不同：
 *   1. 循环条件用精度控制：right - left > 1e-7
 *   2. 区间收缩不需要 ±1（没有下标概念）
 *   3. 最终答案取 left 或 (left+right)/2
 */
public double sqrtDouble(double x) {
    double left = 0, right = Math.max(1, x);
    // 若 x < 1，例如 0.25，right 取 1（平方根 0.5 在 [0,1] 内）
    while (right - left > 1e-7) {           // 精度控制
        double mid = left + (right - left) / 2;
        if (mid * mid < x) {
            left = mid;                     // 无 ±1！
        } else {
            right = mid;
        }
    }
    return (left + right) / 2;              // 或直接返回 left
}
```

### 6.2 精度选择的权衡

| 精度 | 迭代次数 | 适用场景 |
|:---:|:---:|------|
| 1e-3 | ~30 次 | 题目要求 3 位小数 |
| 1e-6 | ~40 次 | 题目要求 6 位小数（大多数） |
| 1e-9 | ~50 次 | 高精度需求 |

> 💡 **面试小技巧**：数值二分一般固定迭代 100 次更稳定（不依赖精度判断），`for (int i = 0; i < 100; i++)` 每次区间减半，任何精度都足够。

## 7. 答案二分的万能模板

```java
/**
 * 答案二分万能模板（整数版）
 * 使用场景：最小化/最大化某个单调可行性的答案
 *
 * @param lo 答案下界（通常取 1 或 max 约束）
 * @param hi 答案上界（通常取 sum 或最大可能值）
 */
public int binarySearchAnswer(int lo, int hi) {
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (check(mid)) {
            hi = mid;          // mid 可行 → 尝试更小（最小化问题）

    return lo;
}
```

### 答案二分解题流程

```
1. 识别：题目问"最小X使..."/"最大X使..." → 答案二分
2. 定值域：[lo, hi] —— 下界最大约束，上界总和/最大可能
3. 写 check(mid)：模拟验证可行性（这是核心工作！）
4. 套模板：最小化 → 可行收 hi；最大化 → 可行放 lo
5. 验证：手动跑 2-3 个边界用例
```

> 🎯 **核心要点**：答案二分把"难解的原问题"转化为"简单的 check 判断"。判断标准是：**check(mid) 是否随 mid 单调变化**。一旦确认单调，值域+check+模板三步即可解题。875（最小速度）、1011（最小运力）、410（最小化最大值）三题同源，练熟一道就通了这一整类。
