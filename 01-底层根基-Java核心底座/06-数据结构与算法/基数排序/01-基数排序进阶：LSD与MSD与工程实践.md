## 1. LSD 与 MSD：两种遍历方向

### 1.1 两种策略

```
LSD（Least Significant Digit，最低位优先）：
  从个位 → 十位 → 百位逐轮稳定排序
  例：[170, 45, 75, 90, 802, 24, 2, 66]
    轮 1（个位）：170 90 802 2 24 45 75 66
    轮 2（十位）：802 2 24 45 66 170 75 90
    轮 3（百位）：2 24 45 66 75 90 170 802 ✓

MSD（Most Significant Digit，最高位优先）：
  从最高位开始排序 → 分桶 → 递归处理各桶
  （每桶内用下一高位继续排序）

⚠️ LSD 用"稳定排序"保证整体有序（简单）
  MSD 需要"递归分桶"（复杂但可早停）
  → 数值排序主流用 LSD
```

### 1.2 LSD 为什么稳定就够

```
核心定理：每一轮稳定排序后，序列按"已处理位"有序
  轮 k 后：按"后 k 位"有序
  证明：若后 k 位相同 → 稳定排序保留前 k 轮顺序
        若后 k 位不同 → 本轮按第 k 位排好
  → 归纳成立

⚠️ 面试表达：
"LSD 每轮是稳定排序（计数排序），
 稳定性保证'高位相同时低位顺序不乱'——
 这就是基数排序正确性的全部秘密。"
```

### 1.3 MSD 的适用场景

```
字符串字典序排序：
  先按首字符分桶 → 递归各桶按次字符
  ⚠️ 可提前终止：桶内只有一个元素 → 不用继续
  （LSD 必须处理完全部位）

⚠️ 选型：定长数值 → LSD；变长字符串字典序 → MSD 或 LSD 补位
```

## 2. 基数的选择：时间与空间的权衡

### 2.1 基数的含义

```
基数 r = 每轮处理"多少个可能取值"
  r = 10：十进制位（教学）
  r = 256：字节（8 位一组，工程主流）
  r = 2^k：按位分组

复杂度与基数的关系：
  轮数 d = 位数 / log₂r（每轮处理 log₂r 位）
  每轮代价 O(n + r)（计数排序）
  总代价 O(d·(n + r))

⚠️ 权衡：
  r 增大 → 轮数减少，但每轮计数数组变大（内存 O(r)）
  r 翻倍 → 轮数减半，内存翻倍
```

### 2.2 最优基数的直觉

```
32 位整数：
  r = 256（1 字节）：d = 4 轮，内存 4×256 计数
  r = 65536（2 字节）：d = 2 轮，内存 4×65536 大
  r = 2^16 空间翻 256 倍但只省 2 轮

工程结论：
  r = 256 是经典选择（字节基数排序）：
  4 轮、计数数组 256 个 int、缓存友好

⚠️ 面试表达：
"基数选 256（字节）是工程标准——
 4 轮完成 32 位整数，计数数组 256 个元素
 完全进缓存，每轮 O(n+256) ≈ O(n)。"
```

### 2.3 内存与稳定性

```
每轮需要：
  计数数组 O(r) + 输出数组 O(n)
  → 总 O(n + r) 空间

⚠️ 稳定性与实现：
  计数排序的"累计后缀和 + 从后往前放置"保证稳定
  例：count[i] 前缀和 → 位置区间 → 倒序遍历放置
```

## 3. 复杂度的精确分析

### 3.1 渐进与实际的差别

```
O(d·(n + r))：
  定长整数（d 常数，如 32 位 r=256 → d=4）：
    → O(4·(n+256)) = O(n) 线性！
  变长字符串（d = 最长长度）：
    → O(L·(n + r))

对比其他排序：
  快排：O(n log n) 期望，常数小
  基数：O(n) 渐进更优，但常数（4 轮 × 搬运）不小

⚠️ 实际对比（n = 10⁶，32 位整数）：
  快排：~n log n = 2×10⁷ 次比较
  基数：4 轮 × 10⁶ 搬运 = 4×10⁶ 次操作 + 计数开销
  → 基数更快（顺序访问 + 无比较），但 n 小时快排赢
```

### 3.2 什么时候基数排序占优

| 场景 | 选型 | 原因 |
|------|------|------|
| n 巨大 + 定长键 | 基数排序 | 线性时间，缓存友好 |
| n 中等 + 键可变长 | 快排 | 常数小 |
| 键是字符串/整数 | 基数排序 | 无比较优势 |
| 键是浮点/复杂对象 | 快排 | 基数难处理 |
| 需要稳定 | 基数排序（天然稳定） | 快排不稳定 |

```
⚠️ 面试表达：
"基数排序 O(n) 渐进最优，但要求键'可分位'。
 整数/字符串完美适用；浮点需要位变换。
 实际工程：数据量足够大 + 定长整数键 → 基数赢。"
```

## 4. 负数与浮点的处理

### 4.1 负整数：偏移法

```java
/** 处理负数：先整体偏移为非负，排序后还原 */
void radixSortWithNegatives(int[] nums) {
    int min = Integer.MAX_VALUE;
    for (int x : nums) min = Math.min(min, x);
    if (min < 0) {
        for (int i = 0; i < nums.length; i++) nums[i] -= min;  // ⚠️ 整体平移
    }
    radixSort(nums);                             // 正常基数排序
    if (min < 0) {
        for (int i = 0; i < nums.length; i++) nums[i] += min;  // 还原
    }
}
// ⚠️ 注意：平移后值域变大（n 个元素的跨度），
//   溢出风险：min 很负时 nums[i] - min 可能溢出 int
//   → 大值域用 long 或符号位处理（见下）

/** 符号位方案：把符号位纳入排序键 */
// 思路：最高位 1 表示负数 → 用补码的"无符号序"：
//   负数比正数大（无符号视角）→ 排序后翻转即可
// 具体：key = (unsigned) x ^ (1 << 31) 使负数排在前面
```

### 4.2 浮点数：位变换技巧

```
IEEE 754 浮点数的"排序等价"变换：
  正数：按位序递增（符号位 0，指数/尾数即字典序）
  负数：按位序递减（反转）
  经典技巧（Radix Sort 浮点）：
    key = Float.floatToIntBits(x)
    key ^= (key >> 31) | 0x80000000   （负数全位翻转）
    → 排序后转回 Float

⚠️ 工程现实：浮点基数排序是"黑魔法"——
  面试只需知道存在，不要求手写
  实际场景用快排即可（浮点比较开销小）
```

### 4.3 通用做法总结

| 键类型 | 处理 | 复杂度 |
|--------|------|:---:|
| 非负整数 | 直接按位 | O(n) |
| 负整数 | 偏移 / 符号位变换 | O(n) |
| 浮点 | 位变换（IEEE 754 技巧） | O(n) |
| 字符串 | 补位 / MSD | O(L·n) |

## 5. 字符串与对象的基数排序

### 5.1 定长字符串

```
固定长度（如电话号码、学号）：
  直接 LSD：从最后一位到第一位稳定排序
  与整数完全同构（每位是 0-9 或字符集）

变长字符串的处理：
  方案一：补位（最短的补最小字符）
  方案二：LSD 从尾部 → 短的先耗尽 → 视为"小于"
  方案三：MSD 递归（天然适配变长）
```

### 5.2 对象数组的基数排序

```java
/** 对象（如 Pair）按 key 字段基数排序：稳定是关键 */
void radixSortObjects(Pair[] arr) {
    // 每轮对"某一位"做稳定计数排序
    // ⚠️ 稳定性保证：同 key 的对象保持原有相对顺序
    // 应用：多关键字排序（先按次关键字排，再按主关键字排）
}
// ⚠️ 多关键字排序 = 两次稳定排序：
//   先按次关键字稳定排 → 再按主关键字稳定排
//   结果：主关键字有序，且主关键字相同时按次关键字有序
//   （这就是数据库 ORDER BY a, b 的实现原理）
```

## 6. 线性排序三兄弟：计数 / 基数 / 桶

### 6.1 关系与区别

| 排序 | 原理 | 复杂度 | 键要求 | 空间 |
|------|------|:---:|------|:---:|
| 计数排序 | 统计频次 + 前缀和定位 | O(n+k) | 值域小（整数） | O(k) |
| 基数排序 | 多位逐轮计数排序 | O(d·(n+r)) | 可分位 | O(n+r) |
| 桶排序 | 分桶 + 桶内排序 | O(n) 平均 | 均匀分布 | O(n) |

```
关系：
  计数排序 = 基数排序的"单轮"（一个位）
  基数排序 = 多轮计数排序（分位复用计数思想）
  桶排序 = 分桶 + 桶内任意排序（可再套基数/快排）

⚠️ 面试表达：
"三者同族——都用'值域索引'而非'比较'。
 计数是单轮索引；基数是分位多轮；
 桶是分布分区。共同前提：键的分布可利用。"
```

### 6.2 适用性对比

```
计数排序：值域 k 不大（如成绩 0-100）→ O(n+k)
基数排序：值域大但可分位（32 位整数）→ O(d·n)
桶排序：数据均匀分布（如随机数）→ 期望 O(n)
⚠️ 非均匀数据桶排序退化为 O(n log n)（全进一桶）
```

## 7. 工程优化：字节基数排序与并行

### 7.1 字节基数排序（经典实现）

```java
/** 32 位整数 × 4 轮字节基数排序（r=256） */
void radixSortBytes(int[] nums) {
    int n = nums.length;
    int[] output = new int[n];
    int[] count = new int[256];

    for (int shift = 0; shift < 32; shift += 8) {   // ⚠️ 4 轮，每轮 8 位
        Arrays.fill(count, 0);
        for (int x : nums)
            count[(x >>> shift) & 0xFF]++;          // ① 取当前 8 位

        // ② 前缀和（转成"位置区间"）
        for (int i = 1; i < 256; i++)
            count[i] += count[i - 1];

        // ③ 从后往前放置（保证稳定）
        for (int i = n - 1; i >= 0; i--) {
            int digit = (nums[i] >>> shift) & 0xFF;
            output[--count[digit]] = nums[i];       // ⚠️ 倒序放置
        }
        System.arraycopy(output, 0, nums, 0, n);
    }
}
// ⚠️ 正确性依赖：无符号移位（>>>）+ 稳定放置
// 优化点：
//   ① count 数组 256 完全进缓存
//   ② 顺序读写（缓存友好）
//   ③ 可用 16 位（r=65536）减少到 2 轮（内存换时间）
```

### 7.2 并行化思路

```
基数排序天然可并行：
  ① 分块排序：数据分块各自基数排序 → 归并（需知道块间键序）
  ② 轮内并行：统计频次并行（各段独立计数 → 合并）
  ③ GPU 实现：每轮 256 线程处理计数（经典并行基数）

⚠️ 工程现实：单机 Java 场景基数排序并不常用
  （Arrays.sort 双轴快排常数更小）
  基数排序价值主要在：
    大数据框架的排序原语、GPU 排序、特定键型（定长字节键）
```

## 8. 面试要点与追问

### 8.1 面试话术模板

```
"基数排序用稳定排序逐位处理：LSD 从低位到高位，
 每轮计数排序 O(n+r)。稳定性是正确性核心——
 高位相同时低位顺序不乱。复杂度 O(d·(n+r))，
 32 位整数 r=256 → 4 轮 → 实际线性。
 与计数/桶排序同族（值域索引而非比较）。
 负数用偏移或符号位处理，浮点用位变换。"
```

### 8.2 高频追问 TOP 8

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | 为什么每轮必须稳定？ | 高位相同时保留低位顺序 |
| 2 | LSD vs MSD？ | LSD 简单稳定；MSD 适合变长字符串 |
| 3 | 复杂度？ | O(d·(n+r))；定长键即 O(n) |
| 4 | 基数选多少？ | r=256（字节）工程标准，缓存友好 |
| 5 | 负数怎么办？ | 偏移 / 符号位变换 |
| 6 | 与计数/桶排序？ | 计数是单轮，基数多轮，桶是分区 |
| 7 | 什么时候赢快排？ | n 大 + 定长键 + 稳定需求 |
| 8 | 为什么 Java 不用？ | Arrays.sort 双轴快排常数更小 |

### 8.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| 忘记稳定放置（倒序） | 排序错误 | 从后往前放 |
| 用有符号移位 >> | 负数错乱 | 无符号 >>> |
| 偏移法溢出 | 结果错 | long 或符号位方案 |
| 基数过大 | 内存爆 | r=256 起步 |
| 忘前缀和 | 位置定位错 | count[i] += count[i-1] |

---

> 🎯 **核心要点**：基数排序 = **稳定多轮计数**。LSD 正确性靠"稳定性"；复杂度靠"分位"（定长键 → 线性）；工程选 r=256（缓存友好）；负数/浮点靠变换。三兄弟（计数/基数/桶）同属"值域索引"家族，面试一条线讲清。
