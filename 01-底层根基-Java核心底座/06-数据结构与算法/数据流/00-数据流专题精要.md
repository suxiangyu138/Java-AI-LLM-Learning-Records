## 1. 核心概念

### 1.1 什么是数据流问题

> 数据流问题：数据**逐个到达**（无法预知总量、无法回头），需要**在线维护**统计结果。

```
与静态数组问题的区别：
  静态：先拿到全部数据 → 排序/预处理
  数据流：数据不断到来 → 每次操作后立即返回结果

经典场景：股票价格、日志流、传感器数据

核心数据结构：
  堆（TopK/中位数）、计数数组、单调队列
```

### 1.2 两大经典模型

```
① 数据流第 K 大（703）
   定长小根堆：堆里永远维护最大的 k 个
   新元素 > 堆顶 → 替换（弹出堆顶）
   堆顶 = 第 K 大 → O(log k) 每次

② 数据流中位数（295）
   双堆：大根堆（左半）+ 小根堆（右半）
   保持两堆大小差 ≤ 1
   中位数 = 两堆顶 / 较大堆顶 → O(log n) 插入 O(1) 查询
```

### 1.3 数据流的其他场景

```
③ 滑动窗口统计：单调队列（239 窗口最大）
④ 流式采样：水塘抽样（382 等概率采样）
⑤ 流式计数：计数数组/HashMap

统一特征：无法用"排序 + 二分"（数据没到齐）
→ 用堆/单调结构做在线维护

⚠️ 面试第一问："这题数据是静态数组还是流式？
  静态 → 可能有更快的非在线解法"
```

## 2. 完整代码模板

### 2.1 703. 数据流第 K 大

```java
/**
 * LeetCode 703. 数据流中的第 K 大元素
 * 定长小根堆：堆里永远保留最大的 k 个
 */
class KthLargest {
    private PriorityQueue<Integer> minHeap;
    private int k;

    public KthLargest(int k, int[] nums) {
        this.k = k;
        minHeap = new PriorityQueue<>();
        for (int x : nums) add(x);         // 逐个添加
    }

    public int add(int val) {
        minHeap.offer(val);
        if (minHeap.size() > k) {
            minHeap.poll();                // ⚠️ 超 k 弹最小
        }
        return minHeap.peek();             // 堆顶 = 第 K 大
    }
}
// 每次 add O(log k)，堆大小恒 ≤ k
// 推演：k=3, [4,5,8,2]
//   add 4 → [4]；add 5 → [4,5]；add 8 → [4,5,8]
//   add 2 → [4,5,8]（2 < 4 被淘汰... 实际入堆后弹 2）
//   add 3 → [4,5,8]；peek=4 ✓
```

### 2.2 295. 数据流中位数（双堆）

```java
/**
 * LeetCode 295. 数据流的中位数（双堆经典）
 */
class MedianFinder {
    // 左半（较小的一半）用大根堆 → 堆顶是左半最大
    PriorityQueue<Integer> left  = new PriorityQueue<>((a, b) -> b - a);
    // 右半（较大的一半）用小根堆 → 堆顶是右半最小
    PriorityQueue<Integer> right = new PriorityQueue<>();

    public void addNum(int num) {
        left.offer(num);                 // ① 先入左半
        right.offer(left.poll());        // ② 左半最大给右半
        if (left.size() < right.size()) {
            left.offer(right.poll());    // ③ 保持左 ≥ 右
        }
    }

    public double findMedian() {
        if (left.size() > right.size()) {
            return left.peek();          // 奇数个：左半堆顶
        }
        return (left.peek() + right.peek()) / 2.0;   // 偶数：平均
    }
}
// 插入 O(log n)，查询 O(1)
// 空间 O(n)（两堆共存所有数据）
```

### 2.3 933. 最近请求次数（队列）

```java
/**
 * LeetCode 933. 最近的请求次数
 * 队列维护时间窗口：过期请求出队
 */
class RecentCounter {
    private Queue<Integer> queue;

    public RecentCounter() {
        queue = new LinkedList<>();
    }

    public int ping(int t) {
        queue.offer(t);
        // ⚠️ 移除窗口外（超过 3000ms）的请求
        while (queue.peek() < t - 3000) {
            queue.poll();
        }
        return queue.size();             // 窗口内请求数
    }
}
// 每个请求入队出队各一次 → 均摊 O(1)
```

## 3. 双堆详解

### 3.1 双堆不变量

```
不变量：
  left（大根堆）存较小一半
  right（小根堆）存较大一半
  left.size() ∈ {right.size(), right.size()+1}

推论：
  奇数个 → left 多 1 个 → 中位数 = left.peek()
  偶数个 → 两堆相等 → 中位数 = 两堆顶平均

⚠️ 为什么左半用大根堆？
  中位数是"左右分界处"：
  左半最大（大根堆顶）+ 右半最小（小根堆顶）
  → 两个堆顶恰好夹住中位数
```

### 3.2 插入三步的推导

```
addNum(num) 三步：
  ① num 入 left：假设先入左半
  ② left 最大给 right：保证"左小右大"分界正确
     （num 若很大，经此步进入右半）
  ③ right 比 left 多 → 还一个：恢复大小平衡

为什么能保证有序分界？
  ② 把 left 最大值（可能含新 num）移到 right
  → right 中所有元素 ≥ left 中所有元素 ✓
  ③ 保证 left ≥ right 的大小关系

⚠️ 三步顺序不能乱（面试手写易错点）
```

### 3.3 双堆的变体

```
① 480 滑动窗口中位数：
   双堆 + 延迟删除（窗口滑出元素标记删除）
   弹出时惰性验证 → 均摊 O(log n)

② 数据流 TopK：
   定长堆（小根堆存最大 K 个）

③ 数据流中位数 + 删除：
   删除时从对应堆"标记删除"（延迟）

⚠️ 延迟删除模板：
  Map<值, 待删次数> + 弹出时检查
  （堆不支持 O(1) 删任意元素）
```

## 4. 数据流的进阶技巧

### 4.1 延迟删除（480 滑动窗口中位数）

```java
/**
 * 延迟删除核心思路：
 * ① 记录"待删除"：map.merge(val, 1, +1)
 * ② 弹出时检查：堆顶在待删表中 → 弹出并减计数
 * ③ 重复直到堆顶是"有效"元素
 */
// 伪代码：
void lazyRemove(PriorityQueue<Integer> heap, Map<Integer, Integer> lazy) {
    while (!heap.isEmpty() && lazy.getOrDefault(heap.peek(), 0) > 0) {
        int val = heap.poll();
        lazy.merge(val, -1, Integer::sum);    // 真正删除
    }
}
// 每个元素"假删"一次 + "真删"一次 → 均摊 O(log n)
```

### 4.2 水塘抽样（流式采样）

```java
/**
 * 382. 链表随机节点（流式等概率采样）
 * 第 i 个元素以 1/i 概率替换候选
 */
public int getRandom() {
    ListNode cur = head;
    int result = 0, count = 0;
    while (cur != null) {
        count++;
        if (random.nextInt(count) == 0) {    // 1/count 概率
            result = cur.val;
        }
        cur = cur.next;
    }
    return result;
}
// 数学归纳保证每个节点概率 1/n
// （详见水塘抽样专题）
```

### 4.3 数据流 vs 静态问题的判断

```
⚠️ 关键判断（面试第一问）：
  题目给"全部数组" → 静态 → 可能有非在线最优解
  题目给"流式/不断 add" → 数据流 → 在线结构

例：
  215 数组第 K 大（静态）→ 快速选择 O(n) 更快
  703 数据流第 K 大（流式）→ 只能堆 O(log k)
  295 数据流中位数（流式）→ 双堆
  静态找中位数 → 排序/快选 O(n)

面试话术："这题是数据流（在线处理），
 所以不能用排序/快选（需要全量数据），
 必须用堆维护在线统计。"
```

## 6. 面试要点与追问

### 6.1 面试话术模板

```
"数据流中位数用双堆：
 大根堆存较小的一半，小根堆存较大的一半，
 保持大小差不超过 1。
 插入三步：入左 → 左顶给右 → 右多还左。
 中位数：奇数取左顶，偶数取两顶平均。
 插入 O(log n)，查询 O(1)。
 关键：数据流无法排序，堆是唯一在线方案。"
```

### 6.2 高频追问 TOP 8

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | 双堆怎么保持平衡？ | 三步：入左 → 左顶给右 → 右多还左；差 ≤ 1 |
| 2 | 为什么用堆不用数组？ | 数组插入 O(n)；堆 O(log n)；流式需在线 |
| 3 | 延迟删除是什么？ | 标记待删 + 弹出时惰性验证（堆无法 O(1) 删任意） |
| 4 | 数据流 vs 静态？ | 流式在线用堆；静态可能有更快（快选/排序） |
| 5 | 第 K 大为什么小根堆？ | 堆顶是 k 个候选中的最小 = 第 k 大 |
| 6 | 中位数奇数/偶数？ | 奇数左堆顶；偶数两顶平均 |
| 7 | 双堆空间？ | O(n)（全部数据都在堆中） |
| 8 | 流式采样？ | 水塘抽样（1/i 替换，等概率） |

### 6.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| 双堆三步顺序乱 | 分界错误 | 入左→给右→还左 |
| 比较器写反 | 大小根颠倒 | b-a 大根堆 |
| 延迟删除忘验证 | 返回已删值 | 弹出时检查 lazy |
| 静态当流式 | 解法不够优 | 先判断数据形态 |
| 703 忘弹超 k | 堆无限增长 | size > k → poll |

> 🎯 **核心要点**：数据流 = **在线维护**思维——定长堆（TopK）、双堆（中位数三步平衡）、队列（窗口）。识别信号："流、不断到来、实时查询"。先判断静态/流式（决定算法），延迟删除是进阶加分。
