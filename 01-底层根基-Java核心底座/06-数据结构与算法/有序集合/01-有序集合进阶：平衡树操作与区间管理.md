## 1. 有序集合的本质

### 1.1 定义与定位

```
有序集合：插入/删除/查找都 O(log n) 的有序结构
  Java：TreeSet（有序集）/ TreeMap（有序映射）
  底层：红黑树（自平衡 BST）

⚠️ 与哈希的区别：
  哈希：O(1) 但无序（不能 floor/ceiling）
  有序集合：O(log n) 但有序（支持范围查询）

⚠️ 面试必答：
"有序集合 = 平衡树——
 哈希给不了'有序操作'（floor/ceiling/范围），
 有序集合 O(log n) 补上这个能力。"
```

### 1.2 核心能力矩阵

| 操作 | 哈希 | 有序集合 | 堆 |
|------|:---:|:---:|:---:|
| 查找 | O(1) | O(log n) | ❌ |
| 删除任意值 | O(1) | O(log n) | ❌（懒删除） |
| floor/ceiling | ❌ | ✅ | ❌ |
| 前 K 有序 | 需排序 | ✅ | ✅ 弹出 |
| 最值 | 需扫描 | ✅ 首尾 | ✅ 堆顶 |

```
⚠️ 面试必答：
"有序集合的独门：任意值的 floor/ceiling
 与任意删除——堆做不到、哈希给不了。"
```

## 2. TreeSet/TreeMap API 体系

### 2.1 TreeSet 操作速查

```java
TreeSet<Integer> set = new TreeSet<>();

set.add(x);                    // 插入 O(log n)
set.remove(x);                 // 任意删除 O(log n)（⭐ 堆做不到）
set.contains(x);               // 查找

set.first();                   // 最小
set.last();                    // 最大
set.floor(x);                  // ⚠️ ≤ x 的最大
set.ceiling(x);                // ⚠️ ≥ x 的最小
set.lower(x);                  // < x 的最大
set.higher(x);                 // > x 的最小

set.subSet(l, true, r, true);  // 范围视图
// ⚠️ 面试必答："TreeSet 四件套——
//   floor（≤）、ceiling（≥）、lower（<）、higher（>）
//   是滑动窗口/日程表的常用 API。"
```

### 2.2 TreeMap 操作速查

```java
TreeMap<Integer, Integer> map = new TreeMap<>();   // key → 计数/值

map.floorKey(x);               // ≤ x 的最大 key
map.ceilingKey(x);             // ≥ x 的最小 key
map.firstKey();                // 最小 key
map.lastKey();                 // 最大 key
map.pollFirstEntry();          // 取出最小项（贪心常用）
// ⚠️ 面试必答："TreeMap 的 Key 版四件套
//   与 TreeSet 同构——floorKey/ceilingKey
//   是日程表题的标准 API。"
```

## 3. 有序操作四件套

### 3.1 floor/ceiling 的语义与陷阱

```
floor(x) = 最大的 ≤ x     （"正好或更小"）
ceiling(x) = 最小的 ≥ x   （"正好或更大"）
lower(x) = 最大的 < x     （"严格更小"）
higher(x) = 最小的 > x    （"严格更大"）

⚠️ 陷阱：
  floor/ceiling 含等号、lower/higher 不含
  空集返回 null → 判空

⚠️ 面试必答：
"'含等号'是四件套的第一区分——
 floor/ceiling 允许等于、lower/higher 严格。"
```

### 3.2 常见应用模式

```java
/** 模式一：找"最近的合法值"（220 滑动窗口） */
Integer candidate = set.ceiling(nums[i] - t);   // ⚠️ ≥ nums[i]-t
if (candidate != null && candidate <= nums[i] + t) return true;

/** 模式二：找"前驱后继"（855 考场） */
Integer prev = seats.floor(pos);
Integer next = seats.ceiling(pos);

/** 模式三：贪心取最小（846 顺子） */
Integer first = map.firstKey();                // 每次取最小
// ⚠️ 面试必答："四件套三大模式——
//   范围窗口（220）、前驱后继（855）、
//   贪心最小（846）——识别模式直接套。"
```

## 4. 区间管理：日程表模式

### 4.1 729 日程表（冲突检测）

```
插入区间 [start, end)，冲突则拒绝
TreeMap 前驱检查：
  ⚠️ 前驱的 end > start → 冲突
  ⚠️ 后继的 start < end → 冲突
```

```java
/** 729. 我的日程安排表 I */
class MyCalendar {
    private final TreeMap<Integer, Integer> calendar = new TreeMap<>();  // start → end

    public boolean book(int start, int end) {
        // ⚠️ 前驱：≤ start 的最近区间
        Integer prev = calendar.floorKey(start);
        if (prev != null && calendar.get(prev) > start) return false;

        // ⚠️ 后继：≥ start 的最近区间
        Integer next = calendar.ceilingKey(start);
        if (next != null && next < end) return false;

        calendar.put(start, end);
        return true;
    }
}
// 推演 book(10,20) book(15,25)：
//   (10,20)：无冲突 → 存入
//   (15,25)：floorKey(15)=10，get(10)=20 > 15 → 冲突 ✗ ✓
// ⚠️ 复杂度：O(log n)/次
// ⚠️ 面试必答："729 = TreeMap 前驱后继检查——
//   floorKey 查前驱（end > start 冲突）、
//   ceilingKey 查后继（start < end 冲突）。"
```

### 4.2 区间合并模式（715 区间模块）

```
区间插入/删除/查询（维护不重叠区间集合）
TreeMap 的区间合并：
  找重叠区间 → 删除 → 合并插入

⚠️ 面试必答：
"区间模块 = TreeMap + 区间合并——
 插入时找重叠区间（floor/ceiling），
 删除后合并，O(k log n)（k 为重叠数）。"
```

## 5. 滑动窗口 + 有序集合

### 5.1 220 的滑动窗口有序集合

```
|nums[i]-nums[j]| ≤ t 且 |i-j| ≤ k
滑动窗口（维护 k 个元素）+ TreeSet：
  ceiling(nums[i] - t) 是否存在 ≤ nums[i] + t
⚠️ 与桶版对比：桶 O(1)/元素、TreeSet O(log k)/元素
  （TreeSet 实现更简单，桶更快）

⚠️ 面试必答：
"220 两种解——桶（O(1)）与 TreeSet
 （O(log k)）。TreeSet 版：窗口内找
 ceiling(nums[i]-t) 检查上界。"
```

### 5.2 滑动窗口有序集合的删除

```
⚠️ 滑动窗口滑出元素 → 有序集合任意删除
  这正是 TreeSet 相对堆的优势（堆需懒删除）

⚠️ 面试必答：
"滑动窗口 + 有序集合的关键是'任意删除'——
 TreeSet remove O(log n) 直接删；
 堆做不到（要懒删除）。"
```

## 6. 有序集合 vs 堆 vs 线段树

### 6.1 三结构选型

| 需求 | 结构 |
|------|------|
| 取最值（TopK/中位） | 堆（O(1) 取顶） |
| 任意删除 + 有序操作 | 有序集合 |
| 区间更新/查询 | 线段树 |
| 窗口最值 | 单调队列 |

```
⚠️ 面试必答：
"三结构分工——堆管'最值'（弹出）、
 有序集合管'任意操作'（floor/删除）、
 线段树管'区间'（更新/查询）。"
```

### 6.2 决策框架

```
需要任意删除？
  ├─ 是 → 需要有序（floor）？→ 有序集合
  └─ 否 → 只需最值？→ 堆
需要区间操作？
  ├─ 是 → 线段树
  └─ 否 → 有序集合/堆

⚠️ 面试必答：
"'任意删除 + 有序' = 有序集合、
 '只取最值' = 堆、
 '区间批量' = 线段树——
 三个特征决定三个结构。"
```

## 7. 面试要点与追问

### 7.1 面试话术模板

```
"有序集合 = 平衡树（TreeSet/TreeMap）。
 独门能力：任意删除 + floor/ceiling（O(log n)）。
 四件套含等号区分：floor ≤ / ceiling ≥ /
 lower < / higher >。
 应用：日程表（前驱后继检查）、滑动窗口
 （任意删除）、贪心最小（firstKey）。
 选型：任意删除用有序集合、取最值用堆。"
```

### 7.2 高频追问 TOP 8

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | 与哈希区别？ | 哈希无序、有序集合支持范围 |
| 2 | 四件套？ | floor/ceiling/lower/higher |
| 3 | 含等号？ | floor/ceiling 含、lower/higher 不含 |
| 4 | 与堆区别？ | 堆不能任意删除 |
| 5 | 日程表？ | floorKey + ceilingKey 检查 |
| 6 | 滑动窗口？ | 任意删除 + ceiling 窗口 |
| 7 | 空集？ | 返回 null 判空 |
| 8 | 底层？ | 红黑树 |

### 7.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| 忘判 null | NPE | floor/ceiling 判空 |
| 四件套混用 | 边界错 | 含等号区分 |
| 堆当有序集合 | 删除 O(n) | TreeSet |
| 区间冲突判断方向反 | 误判 | 前驱 end / 后继 start |
| 窗口忘删除 | 窗口超尺寸 | 滑出即删 |

---

> 🎯 **核心要点**：有序集合 = **红黑树**（O(log n) 一切操作）+ **四件套**（floor/ceiling 含等号）+ **三大模式**（前驱后继/滑动窗口/贪心最小）。选型一句话：任意删除 + 有序 → TreeSet；只取最值 → 堆。
