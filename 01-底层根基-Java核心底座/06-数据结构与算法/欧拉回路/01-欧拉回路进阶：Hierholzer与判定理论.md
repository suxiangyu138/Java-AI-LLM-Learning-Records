## 1. 欧拉路径/回路的判定定理

### 1.1 定义与定理

```
欧拉路径：经过每条边恰好一次
欧拉回路：欧拉路径 + 起点终点相同

判定定理（图连通的前提下）：
  ① 欧拉回路存在 ⟺ 所有节点度数为偶数
  ② 欧拉路径存在 ⟺ 恰有 0 或 2 个奇数度节点
     （2 个时：起点 = 一个奇度节点，终点 = 另一个）

⚠️ 面试必答：
"欧拉判定两句话：全偶有回路、
 恰两个奇度有路径（奇度 0 个时路径即回路）。"
```

### 1.2 定理的直觉

```
为什么全偶才有回路：
  进入一个节点必须能离开（出边配对）
  奇度节点会"困住"（进入后无路可走）

为什么恰好 2 个奇度有路径：
  起点的出边比入边多 1、终点入边比出边多 1
  其余节点进出配对
  >2 个奇度 → 必然有边无法经过

⚠️ 边数统计佐证：
  所有节点度数之和 = 2×边数（偶数）
  → 奇度节点数必为偶数（0、2、4...）
```

### 1.3 判定代码

```java
/** 欧拉路径存在性判定（有向图版本） */
boolean hasEulerPath(int n, int[][] edges) {
    // ① 连通性检查（忽略孤立点）
    // ② 入度/出度差
    int[] in = new int[n], out = new int[n];
    for (int[] e : edges) { out[e[0]]++; in[e[1]]++; }

    int startCnt = 0, endCnt = 0;
    for (int i = 0; i < n; i++) {
        int diff = out[i] - in[i];
        if (diff == 1) startCnt++;        // ⚠️ 出比入多 1 → 起点候选
        else if (diff == -1) endCnt++;    // 入比出多 1 → 终点候选
        else if (diff != 0) return false; // 差 >1 → 不可能
    }
    // ⚠️ 回路：全 0；路径：恰好 1 个起点 + 1 个终点
    return (startCnt == 0 && endCnt == 0) ||
           (startCnt == 1 && endCnt == 1);
}
// 有向图版本（332 重新安排行程用）
// 无向图版本：数奇度节点（0 或 2 个）
```

## 2. Hierholzer 算法推导

### 2.1 算法思想

```
Hierholzer（1873）：找欧拉回路/路径的线性算法

核心思想：走一步删一步，遇到死路回溯
  ① 从起点出发，贪心走边（边走边删）
  ② 走到无路可走 → 当前点必是终点 → 回溯入栈
  ③ 回溯到有分叉的点 → 继续走
  ④ 栈弹出顺序即欧拉路径（逆序）

⚠️ 为什么有效：
  贪心走会形成"子环"，回溯时把子环
  插入主路径 → 所有边恰好一次

⚠️ 面试表达：
"Hierholzer = 贪心走边 + 回溯拼接——
 走一步删一条边，死路时把路径入栈；
 分叉点回来继续。复杂度 O(E) 线性。"
```

### 2.2 递归实现（332 模板）

```java
/** Hierholzer 递归版（有向图，字典序变体见 02 模块） */
List<String> result = new ArrayList<>();

void hierholzer(String node, Map<String, List<String>> graph) {
    List<String> neighbors = graph.get(node);
    while (neighbors != null && !neighbors.isEmpty()) {
        String next = neighbors.remove(0);     // ⚠️ 走边即删（贪心）
        hierholzer(next, graph);               // 递归走
    }
    result.add(node);                          // ⚠️ 死路回溯时入栈
}
// 调用后 result 反转 = 欧拉路径
// ⚠️ 为什么"入栈"而非"直接加入"：
//   后加入的是主路径，先加入的是子环
//   反转后才是正确的访问顺序

// 迭代版（防栈溢出）：
void hierholzerIter(String start, Map<String, List<String>> graph) {
    Deque<String> stack = new ArrayDeque<>();
    stack.push(start);
    while (!stack.isEmpty()) {
        String node = stack.peek();
        List<String> neighbors = graph.get(node);
        if (neighbors != null && !neighbors.isEmpty()) {
            stack.push(neighbors.remove(0));   // 贪心走边
        } else {
            result.add(stack.pop());           // 死路 → 记录
        }
    }
}
```

### 2.3 复杂度分析

```
每条边恰好被访问一次（删除）→ O(E)
每个节点进栈出栈一次 → O(V)
总复杂度 O(V + E)（线性！）

⚠️ 对比：暴力找路径 O(E!)（排列所有边序）
  Hierholzer 从指数降到线性 —— 贪心 + 回溯的威力

⚠️ 面试表达：
"Hierholzer 线性 O(V+E)——每条边走一次删一次。
 关键设计：'边删除'保证不重不漏。"
```

## 3. 算法正确性的直觉证明

### 3.1 为什么"删边贪心 + 回溯"正确

```
性质 1：死路时所在节点必是终点
  证明：其他节点删除的入边 = 出边（偶数度）
  只有起点（路径版）或起点=终点（回路版）
  会"有出无入" → 无路可走时只剩终点

性质 2：回溯后能继续走完剩余边
  回路的子结构：当前路径是"链 + 环"的组合
  回溯到环的入口 → 剩余边构成新环 → 继续贪心

性质 3：最终所有边都被访问
  每条边被删除恰好一次（贪心走时删）
  递归/栈保证删除的边都进入结果

⚠️ 面试表达：
"正确性三性质：死路必是终点、
 回溯能续走子环、删边保证不重不漏——
 三个性质合起来证明算法完备。"
```

### 3.2 手推示例

```
图：A→B, B→C, C→A（三角形）+ A→D, D→E, E→A

从 A 出发：
  A→B→C→A（回到 A 但还有边）
  A→D→E→A（死路？A 无边了 → 入栈 A）
  → 回溯 E（无边 → 入栈）→ D → A...
  栈：[A, E, D, A, C, B, A] → 反转 [A,B,C,A,D,E,A] ✓
```

## 4. 与哈密顿路径的对比

### 4.1 两类路径的根本区别

| 维度 | 欧拉路径 | 哈密顿路径 |
|------|:---:|:---:|
| 经过对象 | **每条边**恰好一次 | **每个节点**恰好一次 |
| 判定 | 度数条件（简单） | NP 完全（无多项式判定） |
| 求解 | Hierholzer O(E) | 回溯 O(n!)（指数） |
| 例子 | 一笔画 | 旅行商（TSP） |

```
⚠️ 常见混淆：
  欧拉 = 边不重复（笔画问题）
  哈密顿 = 点不重复（旅行问题）
  判定难度天差地别：欧拉多项式、哈密顿 NP 完全

⚠️ 面试必答：
"欧拉路径管'边'（一笔画），O(E) 可解；
 哈密顿路径管'点'（TSP），NP 完全——
 这是两类问题最根本的区别。"
```

### 4.2 现实映射

```
欧拉路径的应用：
  邮递员路线（中国邮路问题变体）
  电路板布线（一笔画）
  街道清扫路线

哈密顿路径的应用：
  旅行商（TSP）
  调度问题
  （NP 完全 → 近似算法/启发式）
```

## 5. 一笔画问题

### 5.1 一笔画判定

```
一笔画（无向图）：
  能一笔画完（欧拉路径）⟺ 奇度节点 0 或 2 个
  0 个奇度：任意起点 → 一笔画回路
  2 个奇度：必须从奇度节点开始 → 在另一个奇度结束

⚠️ 面试必答：
"一笔画判定 = 数奇度节点：0 个（回路）或
 2 个（从奇度起笔）——这就是欧拉定理的
 通俗版。"
```

### 5.2 一笔画的起笔策略

```
2 个奇度节点：从任一奇度开始（必然结束于另一个）
0 个奇度：可从任意点开始（回到自身）

⚠️ 面试表达：
"奇度节点是'有进无出/有出无进'的节点——
 路径必须从'出多'开始、在'入多'结束。
 这就是起笔选择的数学依据。"
```

## 6. 构造类欧拉问题

### 6.1 构造路径 vs 判定存在

```
判定：只需存在性（度数条件）
构造：需要输出路径（Hierholzer）

⚠️ 构造题的两种形态：
  ① 给定图 → 输出欧拉路径（332 重新安排行程）
  ② 设计图使欧拉路径存在（753 保险箱）
  ③ 合法重排（2097）：给边集 → 找路径

⚠️ 面试表达：
"'存在性'用度数判定 O(V)；
 '构造'用 Hierholzer O(E)。
 构造题先证存在（度数条件），再构造。"
```

### 6.2 753 保险箱的欧拉视角

```
753 破解保险箱：
  所有 k 位密码（k 位数）出现一次的序列
  → 构造 de Bruijn 序列 = 欧拉回路问题：
  节点 = k-1 位，边 = k 位（每边对应一个密码）
  图全偶度 → 欧拉回路存在 → Hierholzer 构造

⚠️ 面试表达：
"753 的本质是 de Bruijn 序列——
 把'密码'建模成图的边、'前缀'建模成节点，
 一条欧拉回路恰好覆盖所有密码一次。"
```
