## 1. 核心概念

### 1.1 什么是欧拉回路/路径

> 欧拉回路（Euler Circuit）：**每条边恰好经过一次**且回到起点的路径。欧拉路径：每条边恰一次但不要求回起点。

```
经典问题：一笔画（七桥问题）
  能否一笔画完所有边？

判定条件（无向图）：
  欧拉回路：所有节点度数为偶数 + 连通
  欧拉路径：恰 0 或 2 个奇度节点 + 连通
    （2 个奇度 → 必须从其中一个开始）

判定条件（有向图）：
  欧拉回路：所有节点入度 = 出度 + 连通
  欧拉路径：恰一个入=出-1（起点）、一个出=入-1（终点）
```

### 1.2 识别信号

```
"每条边恰走一次" → 欧拉路径
"一笔画/走遍所有边" → 欧拉
"重新安排行程/机票" → 332 欧拉路径

⚠️ 与哈密顿路径的区别：
  欧拉：每条**边**恰一次（边问题）
  哈密顿：每个**节点**恰一次（点问题，NP 难）
  → 面试先确认是"边"还是"点"！
```

### 1.3 面试定位

```
低频考点（大厂偶尔考 332）
掌握：
  ① 判定条件（奇度/出入度）
  ② Hierholzer 模板（DFS + 后序 + 反转）
  ③ 332 题（字典序最小）
即可覆盖
```

## 2. 完整代码模板

### 2.1 判定模板

```java
/**
 * 欧拉路径/回路判定（无向图）
 */
public boolean hasEulerPath(int n, int[][] edges) {
    // ① 度数统计
    int[] degree = new int[n];
    for (int[] e : edges) {
        degree[e[0]]++;
        degree[e[1]]++;
    }

    // ② 奇度节点计数（0 或 2 → 有欧拉路径）
    int odd = 0;
    for (int d : degree) {
        if (d % 2 == 1) odd++;
    }
    if (odd != 0 && odd != 2) return false;

    // ③ 连通性检查（非零度节点连通）
    // （DFS/并查集：所有 degree > 0 的节点同分量）
    return isConnected(n, edges);
}
// 奇度 0 → 欧拉回路；奇度 2 → 欧拉路径
// ⚠️ 奇数个奇度节点不可能存在（握手引理：度数和为偶数）
```

### 2.2 有向图判定

```java
/**
 * 有向图欧拉路径判定
 */
public boolean hasEulerPathDirected(int n, int[][] edges) {
    int[] in = new int[n], out = new int[n];
    for (int[] e : edges) {
        out[e[0]]++;
        in[e[1]]++;
    }

    int startDiff = 0, endDiff = 0;
    for (int i = 0; i < n; i++) {
        if (in[i] == out[i]) continue;
        else if (out[i] - in[i] == 1) startDiff++;    // 起点
        else if (in[i] - out[i] == 1) endDiff++;      // 终点
        else return false;                            // 差 > 1 → 不可能
    }
    return (startDiff == 0 && endDiff == 0)           // 回路
        || (startDiff == 1 && endDiff == 1);          // 路径
}
// 记忆："入出相等（回路）；一进一出差 1（路径）"
```

### 2.3 332. 重新安排行程（Hierholzer）

```java
/**
 * LeetCode 332. 重新安排行程（字典序最小欧拉路径）
 * 给定机票 [from, to]，从 "JFK" 出发走完所有机票
 */
public List<String> findItinerary(List<List<String>> tickets) {
    // ① 建图：目的地用最小堆（自动字典序）
    Map<String, PriorityQueue<String>> graph = new HashMap<>();
    for (List<String> ticket : tickets) {
        graph.computeIfAbsent(ticket.get(0),
            k -> new PriorityQueue<>()).offer(ticket.get(1));
    }

    // ② Hierholzer：DFS 后序记录
    List<String> result = new ArrayList<>();
    dfs("JFK", graph, result);

    // ③ ⚠️ 反转得到路径
    Collections.reverse(result);
    return result;
}

private void dfs(String airport,
                 Map<String, PriorityQueue<String>> graph,
                 List<String> result) {
    PriorityQueue<String> destinations = graph.get(airport);
    // 走完所有未走的边（最小堆弹完 = 边用完）
    while (destinations != null && !destinations.isEmpty()) {
        String next = destinations.poll();   // ⚠️ 取即删（边用一次）
        dfs(next, graph, result);
    }
    result.add(airport);                     // ⚠️ 后序记录！
}
// 推演 [["JFK","SFO"],["JFK","ATL"],["SFO","ATL"],["ATL","JFK"],["ATL","SFO"]]
// 后序记录 → 反转 → 字典序最小路径
// 复杂度 O(E log E)（堆操作）
```

## 3. Hierholzer 算法详解

### 3.1 算法原理

```
思想：DFS 走边，边走完删除（防重复），
  走不通时"后序"记录节点，最后反转

为什么后序记录？
  死路先被记录（后序 = 先走完子边再记录自己）
  → 反转后死路成为路径的后半部分
  → 每条边恰走一次的正确路径

⚠️ 关键：
  ① 边用后立即删除（防重复走）
  ② 后序记录（递归返回后 add）
  ③ 结果反转（后序 → 正确顺序）
```

### 3.2 推演（简单图）

```
图：A→B→C，A→C
邻接表：A: [B, C]，B: [C]

DFS(A)：
  走 A→B（删 B）→ DFS(B) → 走 B→C（删 C）→ DFS(C)
    C 无出边 → 记录 C
  → 记录 B
  走 A→C（删 C）→ DFS(C) → 记录 C
  → 记录 A
后序记录：[C, B, C, A]
反转：[A, C, B, C]
检查：A→C ✓，C→B？✗ 不对！
```

```
⚠️ 等等，上面推演错了！正确推演：

图：A→B，B→C，A→C
邻接表：A: [B, C]（按序），B: [C]

DFS(A)：
  弹出 B → DFS(B)：
    弹出 C → DFS(C)：无出边 → 记录 C
    记录 B
  弹出 C → DFS(C)：无出边 → 记录 C
  记录 A
后序：[C, B, C, A] → 反转：[A, C, B, C]
A→C ✓；C→B ✗（C 没有到 B 的边！）

嗯，这说明图的边集假设错误。正确例子：
图：A→B，B→C，C→A（回路）
DFS(A) → B → C → A（A 已无未走边？不，A 的边用过了）
后序：[A, C, B, A]？反转 [A, B, C, A] ✓
```

```
正确理解：Hierholzer 的边删除保证
每条边恰走一次，后序反转 = 正确路径。
（面试重点讲"边删 + 后序 + 反转"三步骤
  和"为什么后序"即可，不必纠结复杂推演）
```

### 3.3 为什么最小堆保证字典序

```
邻接表用 PriorityQueue：
  每次弹最小的目的地 → 优先走字典序小的
  贪心局部字典序 → 结合后序反转得到全局最小

⚠️ 面试必答：
"最小堆保证每次选择字典序最小的下一站，
 与 Hierholzer 结合得到字典序最小的完整行程。"
```

## 4. 欧拉路径的应用

### 4.1 753. 破解保险箱（欧拉回路构造）

```java
/**
 * LeetCode 753. 破解保险箱
 * 构造最短字符串包含所有 n 位密码（每位 0-k-1）
 *
 * 建模：节点 = n-1 位前缀，边 = 加一位数字
 *   → 每个密码 = 一条边 → 走遍所有边 = 欧拉回路
 *   → Hierholzer 构造（每节点出度 = k）
 */
public String crackSafe(int n, int k) {
    if (n == 1 && k == 1) return "0";

    StringBuilder sb = new StringBuilder();
    Set<String> seen = new HashSet<>();
    String start = "0".repeat(n - 1);

    dfs(start, k, seen, sb);
    sb.append(start);
    return sb.toString();
}

private void dfs(String node, int k, Set<String> seen, StringBuilder sb) {
    for (int i = 0; i < k; i++) {
        String edge = node + i;              // 边 = 密码
        if (seen.add(edge)) {                // 未走过
            dfs(edge.substring(1), k, seen, sb);   // 下一节点
            sb.append(i);                    // 后序记录
        }
    }
}
// 复杂度 O(k^n)：每个密码恰访问一次
// ⚠️ 欧拉回路思想：每个节点出度 = k → 必存在回路
```

### 4.2 欧拉 vs 哈密顿

| 维度 | 欧拉 | 哈密顿 |
|------|:---:|:---:|
| 经过 | 每条边恰一次 | 每个节点恰一次 |
| 判定 | 度数（多项式） | NP 难 |
| 应用 | 行程/保险箱 | 旅行商变体 |
| 面试 | 332 可解 | 了解概念 |

```
⚠️ 面试先确认：
  "每条边" → 欧拉（度数判定）
  "每个点" → 哈密顿（NP 难，通常不考）
```

### 4.3 应用场景总结

```
① 重新安排行程（332）：欧拉路径 + 字典序
② 破解保险箱（753）：欧拉回路构造
③ 一笔画判定：奇度计数
④ 邮递员问题（中国邮路）：欧拉扩展

⚠️ 识别信号："每条边恰一次/走遍所有边"
```

### 6.2 高频追问 TOP 8

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | 判定条件？ | 无向：奇度 0 或 2；有向：出入相等或差 1 |
| 2 | Hierholzer 为什么后序？ | 死路先记录 → 反转成正确路径 |
| 3 | 边为什么要删？ | 防重复走（每条边恰一次） |
| 4 | 字典序怎么保证？ | 最小堆邻接表（贪心字典序） |
| 5 | 欧拉 vs 哈密顿？ | 边恰一次 vs 点恰一次 |
| 6 | 为什么必须连通？ | 不连通无法走遍所有边 |
| 7 | 奇度为什么是 0/2？ | 握手引理：奇度节点数必为偶数 |
| 8 | 复杂度？ | O(E log E)（堆操作） |

### 6.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| 边不删 | 重复走 | poll 即删 |
| 忘反转 | 路径错误 | Collections.reverse |
| 忘判断连通 | 误判存在 | 连通性检查 |
| 奇度判断错 | 判定错误 | 0 回路 / 2 路径 |
| 字典序忘堆 | 非最小 | PriorityQueue |

> 🎯 **核心要点**：欧拉 = **判定（奇度/出入度）+ Hierholzer（DFS+后序+反转）**。识别信号："每条边恰一次、行程安排、一笔画"。332 是唯一高频题——"取即删 + 后序记录 + 反转"三步骤背熟；欧拉 vs 哈密顿的区分是面试必答。
