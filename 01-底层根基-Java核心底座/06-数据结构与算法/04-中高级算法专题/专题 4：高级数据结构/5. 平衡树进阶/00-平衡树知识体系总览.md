## 1. 知识体系导图

```text
平衡树（Balanced BST）
│
├── 为什么需要 ────────────────────────────────────────────
│   ├── BST 退化: 有序插入 → 单链表 → O(n)
│   ├── 平衡目标: 树高 O(log n) → 操作 O(log n)
│   └── 手段: 旋转/变色/随机化
│
├── AVL（严格平衡）──────────────────────────────────────
│   ├── 平衡因子: 左右高度差 ∈ {−1, 0, 1}
│   ├── 失衡四型: LL/RR/LR/RL → 单旋/双旋
│   ├── 优点: 查询最快（树高最低）
│   └── 缺点: 增删旋转多、维护贵 → 工程少用
│
├── 红黑树（弱平衡）────────────────────────────────────
│   ├── 五条性质: 红黑/根黑/叶黑/不连红/黑高同
│   ├── 最长 ≤ 2× 最短 → 近似平衡
│   ├── 增删最多 2 次旋转 → 维护便宜
│   └── 工程之王: TreeMap/TreeSet、C++ map、Linux 内核
│
├── Treap（随机化）──────────────────────────────────────
│   ├── BST 键值 + 堆优先级（随机）→ 期望平衡
│   ├── 实现最简（旋转版 ~30 行 / 分裂合并版）
│   └── 竞赛首选: 第 K 大、区间操作
│
├── 选型与对比 ──────────────────────────────────────────
│   ├── AVL: 读多写少（查询快）
│   ├── 红黑树: 增删频繁（旋转少）→ 工程默认
│   ├── Treap: 竞赛/手写（简单 + 期望 O(log n)）
│   └── B 树: 磁盘场景（数据库索引——多路矮树）
│
└── 实战与面试 ────────────────────────────────────────────
    ├── 手写: Treap 旋转版（5 分钟）；红黑树讲性质
    ├── 考点: 红黑树五性质、AVL 四旋转、与 B 树对比
    ├── 工程: TreeMap 底层、HashMap 树化 8/6
    └── 话术: "退化 → 平衡手段 → 家族选型"三段式
```

## 4. 核心概念速查

| 概念 | 一句话解释 | 说明 |
|------|-----------|------|
| **BST** | 左 < 根 < 右的二叉搜索树 | 有序插入退化为链表 |
| **平衡因子** | 左右子树高度差 | AVL 的平衡判据（|h|≤1） |
| **旋转** | 改变树形态保持 BST 性质 | LL/RR 单旋、LR/RL 双旋 |
| **红黑树** | 五条颜色规则的弱平衡树 | 工程默认（TreeMap） |
| **黑高** | 到叶子的黑节点数 | 五性质保证黑高相同 |
| **Treap** | BST + 随机堆优先级 | 期望 O(log n)、实现最简 |
| **Splay** | 访问即旋转到根 | 区间操作（竞赛） |
| **B 树** | 多路平衡树 | 磁盘场景（数据库） |

## 5. 家族对比速查表

| 维度 | AVL | 红黑树 | Treap | B 树 |
|------|:---:|:---:|:---:|:---:|
| 平衡方式 | 高度差 ≤ 1 | 颜色五规则 | 随机优先级 | 多路分支 |
| 树高 | ≤ 1.44·log n | ≤ 2·log n | 期望 log n | log_m n（极矮） |
| 查询 | 最快 | 快 | 期望快 | 磁盘友好 |
| 增删维护 | 旋转多 | 最多 2 旋转 | 期望少 | 分裂/合并 |
| 代码量 | 中 | 复杂 | **最简单** | 复杂 |
| 工程地位 | 少用 | **默认（TreeMap）** | 竞赛 | 数据库索引 |
| 场景 | 读多写少 | 增删频繁 | 手写/竞赛 | 磁盘 I/O |

> 🎯 **一句话选型**："**查询多 AVL、增删多红黑树、手写/竞赛 Treap、磁盘 B 树——'读多写少 AVL、工程默认红黑、手写最简 Treap'**。面试的完整答案 = 退化原因 + 家族对比 + 场景选型。"

## 6. 常见误区速查

| 误区 | 正解 |
|------|------|
| "红黑树比 AVL 快" | ❌ 查询 AVL 更快（树高低）；红黑树赢在**增删**（旋转少） |
| "红黑树严格平衡" | ❌ 弱平衡（最长 ≤ 2× 最短）；AVL 才是严格（高度差 ≤ 1） |
| "红黑树插入最坏 O(n)" | ❌ O(log n)——变色 + 最多 2 次旋转 |
| "Treap 一定能平衡" | ❌ 期望平衡——随机优先级下最坏仍可能退化（概率极低） |
| "TreeMap 底层是 AVL" | ❌ 红黑树（与 C++ map 相同） |
| "HashMap 树化是常态" | ❌ 泊松概率极低——防御哈希洪水（8/64 阈值） |
| "数据库用红黑树做索引" | ❌ B+ 树——磁盘页对齐、树高 3-4 层 |
| "旋转改变 BST 性质" | ❌ 旋转保持中序遍历不变——只改形态不改顺序 |
| "平衡树只能存数字" | ❌ 一切可比对象（Comparable）都能存 |
| "面试要手写红黑树" | ❌ 讲性质 + 插入变色流程即可；手写是竞赛 Treap/Splay |
