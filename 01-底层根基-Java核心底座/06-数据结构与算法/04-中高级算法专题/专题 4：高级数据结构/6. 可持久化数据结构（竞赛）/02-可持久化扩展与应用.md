## 1. 标记永久化：可持久化区间更新

### 1.1 为什么不能懒标记

```text
懒标记（pushdown）问题: 下放会修改孩子的值——
  修改的是"当前版本"的孩子 →
  但孩子可能被其他版本共享 → 污染历史版本！

例: 版本 0 区间加 5（标记在根）→ 查询版本 0 前访问孩子
  pushdown 把 5 下放到孩子 → 共享这些孩子的其他版本也被改了 ✗

标记永久化: 不下放——
  修改: 完全覆盖时打标记（不 pushdown）
  查询: 沿路径累加标记贡献
  效果: 每个版本的值 = 树上值 + 路径标记和（互不干扰）

⚠️ 代价: 查询多一层标记累加（仍 O(log n)）
```

### 1.2 实现骨架

```java
/**
 * 标记永久化（可持久化区间更新）
 * ⚠️ 查询时累加路径标记——不下放、不污染
 */
int query(int u, int v, int l, int r, int k, int lazySum) {
    // lazySum: 沿路径累积的标记贡献
    // 区间和查询: 结果 = 树上值 + lazySum × 区间长
    // ⚠️ 与普通查询的差异: 多一个 lazySum 参数
    //   部分覆盖递归时: lazySum += 当前节点标记
}
// 推演: 版本 0 区间 [1,4] 加 5（根标记 5）
//   查版本 0 的 [1,2]: 路径累加 5 → 结果含 5 ✓
//   查版本 1（[1,4] 加 3 后）: 标记 8 → 结果含 8 ✓
// ⚠️ 定位: "可持久化的区间更新 = 标记永久化"
```

> 🎯 **标记永久化的本质**："**'不下放、查询时累加路径标记'——每个版本的值自洽、互不污染**。它是可持久化区间更新的唯一正解（懒标记的 pushdown 会穿越版本）。"

## 2. 树上第 K 小：P2633 树上差分

### 2.1 题目与思路

**题**：树上路径 [u, v] 上第 K 小（点权）。

**树上差分 + 主席树**：

```text
核心: 每个节点从父节点继承建版本——
  root[u] = root[parent[u]] + u 的点权（版本继承 = 树上前缀）

查询路径 u→v 的权值树:
  root[u] + root[v] − root[lca] − root[parent[lca]]
  （树上差分公式——四条版本链作差）

作差后树上二分 → 路径第 K 小

⚠️ 与静态区间的对应:
  静态: root[r] − root[l−1]（线性前缀）
  树上: root[u] + root[v] − root[lca] − root[fa[lca]]（树上前缀）
  → "版本继承的方向从线性变树形"

⚠️ 需要 LCA: 倍增/树剖预处理（O(log n) 求 LCA）
```

> 🎯 **树上差分的对应**："**'root[u] + root[v] − root[lca] − root[fa[lca]]'——静态区间的作差公式推广到树**。会 P3834 就会 P2633：换继承方向 + 加 LCA 预处理。"

## 3. 动态第 K 小：树套树

### 3.1 为什么主席树不能动态

```text
静态主席树: 版本前缀不可修改——
  单点更新 a[pos] 会波及 root[pos..n] 所有版本 ✗

动态第 K 小: 支持"修改 + 查询区间第 K 小"

树套树（BIT 套主席树）:
  外层: BIT（维护下标区间的管辖）
  内层: 动态开点权值线段树（频次）
  修改: BIT 上 O(log n) 个节点各更新一次（O(log²n)）
  查询: 收集 BIT 路径节点 + 主席树作差（O(log²n)）

⚠️ 复杂度: O(log²n)/操作——"两维操作，两层结构"
```

### 3.2 结构示意

```text
BIT（下标维度）
  ├── tree[1] → 权值线段树（管辖部分下标）
  ├── tree[2] → 权值线段树
  └── …（每个 BIT 节点一棵动态开点权值树）

修改 a[pos] += delta:
  for (i = pos; i <= n; i += lowbit(i))
      update(tree[i], rank, delta)            // O(log²n)

查询 [l, r] 第 K 小:
  收集 BIT 前缀路径（l−1 与 r 两组）
  两组作差 + 树上二分                         // O(log²n)

⚠️ 竞赛定位: 树套树是动态第 K 小的标准解——
  代码 ~100 行，进阶考点
```

> 💡 **树套树的直觉**："**'BIT 管下标、权值树管值域'——两维查询拆两层结构**。O(log²n) 是'两维 × 每维 log'的代价；会 BIT + 会主席树，树套树就是组合。"

## 4. 可持久化 Trie 与并查集

### 4.1 可持久化 Trie

```java
/**
 * 可持久化 Trie: 前缀版本的二进制 Trie——
 * 查询区间 [l, r] 内与 x 异或的最大值
 */
// 结构: 每个前缀建 Trie 版本（同主席树：复制路径 + 共享兄弟）
// root[i] = root[i−1] + a[i] 的二进制路径
// 查询 [l, r]: 用 root[r] 与 root[l−1] 作差（同主席树）
//   沿"相反位"贪心走（同 421 位 Trie）

// 应用: 区间最大异或、最大异或对（静态区间版）
// ⚠️ 与主席树同构: "版本复用 + 作差"的通用框架
//   只是树的形状从"值域"变"二进制位"
```

### 4.2 可持久化并查集

```java
/**
 * 可持久化并查集: 支持回退到历史版本
 * = 可持久化数组（主席树）+ 按大小合并
 */
// ① parent/size 用可持久化数组存（每次修改建新版本）
// ② find 无路径压缩（结构信息需保留——同可撤销 DSU）
// ③ 版本 = 每次 union 后的 parent/size 快照

// 查询历史版本: 从对应版本根读 parent/size
// 时间 O(log n)/操作（可持久化数组的读写）

// ⚠️ 与可撤销 DSU 的差异:
//   可撤销: 只能"时间倒序回滚"（栈）
//   可持久化: 任意版本查询（版本树）
//   → 可持久化更强，代价 O(log n) 常数
```

> 🎯 **持久化的通用框架**："**'版本复用 + 作差'不限于线段树——Trie/并查集/数组都套同一框架**。理解'复制路径、共享版本'，可持久化家族就是模板的换皮。"

## 5. 二维数点与区间颜色

### 5.1 二维数点

```text
问题: 平面点集，查询矩形 [x1,x2]×[y1,y2] 内点数（强制在线）
主席树解法:
  ① x 作版本（按 x 排序插入）
  ② y 作值域（权值线段树）
  ③ 矩形点数 = 两版本作差（x 维度）的 y 区间查询

⚠️ 本质: "可持久化 = 把一维排序做成版本、另一维做值域"——
  二维数点 = 主席树的经典应用（竞赛高频）
```

### 5.2 区间颜色

```text
问题: 区间 [l, r] 内不同颜色的个数（强制在线）
主席树解法:
  ① 预处理 last[i] = i 前面最近同色位置
  ② 建版本: root[i] = root[i−1] + (last[i] 处 −1、i 处 +1)
  ③ 查询 [l, r]: root[r] 版本中 l..n 的区间和
     = "最后一次出现 ≥ l 的颜色数" ✓

⚠️ 思路: "区间颜色 → 只记最后一次出现位置"——
  主席树的版本前缀让它天然支持这种"历史状态"
```

> 💡 **竞赛应用的共同模式**："**二维数点（x 版本 + y 值域）、区间颜色（last 预处理 + 版本前缀）——主席树的竞赛应用都是'版本表达历史状态'**。理解'版本 = 前缀状态'，应用就是建模问题。"

## 6. 识别信号与易错点

### 6.1 识别信号

```text
"静态区间第 K 小（多次查询）" → 主席树（P3834）
"树上路径第 K 小" → 主席树 + LCA（P2633）
"动态区间第 K 小" → 树套树
"区间最大异或" → 可持久化 Trie
"版本回退查询" → 可持久化并查集/数组
"强制在线 + 区间统计" → 主席树家族

⚠️ 定位: 全为竞赛（NOI 级）——
  面试提及"可持久化线段树解决静态区间第 K 小"即可
```

### 6.2 易错点

| # | 易错点 | 正确写法 | 后果 |
|:---:|------|------|------|
| 1 | 可持久化区间更新用懒标记 | 标记永久化 | 污染版本 |
| 2 | 树上差分公式错 | `u+v−lca−fa[lca]` | 路径权值错 |
| 3 | 忘 LCA 预处理 | 倍增/树剖 | 查询错 |
| 4 | 动态第 K 小用静态主席树 | 树套树 | 修改波及版本 |
| 5 | 持久化 Trie 忘作差 | root[r]−root[l−1] | 区间混入历史 |
| 6 | 持久化并查集用路径压缩 | 只按大小合并 | 版本无法回退 |
| 7 | 二维数点维度搞反 | x 版本、y 值域 | 查询错 |
| 8 | 空间吝啬 | n<<5 起步 | 越界 |

> 🎯 **核心要点**：可持久化扩展通关四件事——**① 标记永久化**（区间更新不污染）；**② 树上差分**（root 继承方向树形化）；**③ 树套树**（动态第 K 小两层结构）；**④ 通用框架**（Trie/并查集同一套路）。**可持久化家族 = '版本复用 + 作差'的模板化——'复制路径、共享版本、作差查询'三句口诀，全家桶通吃**。
