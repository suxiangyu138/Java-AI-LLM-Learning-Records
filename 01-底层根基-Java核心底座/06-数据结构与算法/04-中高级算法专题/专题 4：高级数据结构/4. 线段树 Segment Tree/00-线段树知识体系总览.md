## 1. 知识体系导图

```text
线段树（Segment Tree）
│
├── 核心本质 ──────────────────────────────────────────────
│   ├── = 维护区间信息的二叉树（每个节点 = 一个区间）
│   ├── 支持: 单点/区间更新 + 区间查询，均 O(log n)
│   ├── 前提: 区间信息可"合并"（满足结合律）
│   └── 空间: 4n（堆式存储）
│
├── 三大操作 ──────────────────────────────────────────────
│   ├── build: 自底向上建树 O(n)
│   ├── query: 区间查询（分治合并）
│   └── update: 单点/区间更新（递归定位）
│
├── 懒标记（区间更新核心）─────────────────────────────────
│   ├── "延迟更新、按需下发"——整段覆盖只打标记
│   ├── pushdown（下放）/ pushup（上收）
│   ├── 前提: 修改可批量执行（区间加可、区间平方不可）
│   └── 多标记: 加乘/赋值+加（顺序是坑）
│
├── 进阶形态 ──────────────────────────────────────────────
│   ├── 动态开点: 大值域（1e9）按需建节点 O(q log m)
│   ├── 权值线段树: 值域频次 + 离散化（逆序对/第 K 大）
│   ├── 扫描线: 面积/周长并
│   └── 主席树: 可持久化（竞赛）
│
├── 能力对比 ──────────────────────────────────────────────
│   ├── vs 树状数组: 线段树全能（最值/懒标记）、代码更长
│   ├── vs 分块: 线段树 O(log n) 更优、分块常数小
│   └── vs 平衡树: 线段树静态、平衡树动态（插入删除）
│
└── 实战与面试 ────────────────────────────────────────────
    ├── 手写: 307 区域检索（单点版 5 分钟）
    ├── 进阶: 懒标记区间加（洛谷 P3372 模板）
    ├── 复杂度: O(log n)/操作、O(4n) 空间
    └── 话术: "区间树 + 分治合并"双段式
```

## 4. 核心概念速查

| 概念 | 一句话解释 | 说明 |
|------|-----------|------|
| **线段树** | 区间信息的二叉树 | 每节点 = 一个区间 |
| **build** | 自底向上建树 | O(n) |
| **query** | 区间查询（分治合并） | O(log n) |
| **update** | 区间/单点更新 | O(log n) |
| **懒标记** | 整段覆盖只打标记 | 区间更新核心 |
| **pushdown** | 标记下放给孩子 | 按需下发 |
| **pushup** | 孩子信息上收 | 合并 |
| **动态开点** | 按需建节点 | 大值域（1e9） |
| **权值线段树** | 值域频次 + 离散化 | 逆序对/第 K 大 |
| **扫描线** | 面积/周长并 | 竞赛经典 |

## 5. 复杂度速查表

| 操作 | 线段树 | 树状数组 | 分块 |
|------|:---:|:---:|:---:|
| 单点更新 | O(log n) | O(log n) | O(1) |
| 区间查询 | O(log n) | O(log n)×2 | O(√n) |
| 区间更新 | O(log n)（懒标记） | O(log n)×2（差分） | O(√n) |
| 区间最值 | ✔ | ✘ | ✔ |
| 代码量 | ~80 行 | ~20 行 | ~50 行 |
| 空间 | O(4n) | O(n) | O(√n) |

> 🎯 **一句话定位**："**线段树 = '区间信息的全能树'——能合并的信息都能维护，O(log n) 覆盖单点/区间操作**。代码是 BIT 的 4 倍，但换来了最值与懒标记的全能——'能合并就能建树'是它的万能公式。"

## 6. 常见误区速查

| 误区 | 正解 |
|------|------|
| "线段树只能维护区间和" | ❌ 一切满足结合律的信息（最值/和/积/gcd）都能维护 |
| "懒标记是优化" | ❌ 是正确性关键——区间更新不用懒标记会 O(n log n) 超时 |
| "懒标记万能" | ❌ 修改必须"可批量执行"（区间加可、区间平方不可） |
| "空间 O(n) 够" | ❌ 堆式存储需要 O(4n)（防越界） |
| "动态开点用堆式下标" | ❌ 必须记录左右儿子编号/指针 |
| "线段树比 BIT 永远好" | ❌ 前缀/计数题 BIT 更短更快——按需求选 |
| "递归一定栈溢出" | ❌ 树高 O(log n)——递归深度安全（动态开点注意） |
| "多懒标记顺序无所谓" | ❌ 加乘/赋值+加有严格顺序（先乘后加等） |
| "权值线段树不用离散化" | ❌ 大值域必须离散化或动态开点 |
| "查询/更新复杂度 O(n)" | ❌ O(log n)——分治只走 O(log n) 条路径 |
