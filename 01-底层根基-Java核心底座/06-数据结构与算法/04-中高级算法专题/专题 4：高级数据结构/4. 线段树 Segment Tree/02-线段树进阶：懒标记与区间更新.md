## 1. 为什么需要懒标记

```text
问题: 区间 [l, r] 统一加 k（区间更新）
朴素做法: 区间内每个位置单点更新 → O(n log n)——
  n 与操作数 10⁵ 时必然超时

核心痛点: 无法对"整段区间的统一修改"批量处理

懒标记（Lazy Tag）: 整段覆盖时——
  ① 立即更新当前节点的信息（O(1)）
  ② 打上标记（"这段要加 k，先欠着"）
  ③ 不递归到叶子（标记暂存）
  ④ 后续访问孩子时才下放（pushdown）

⚠️ 适用前提: 修改必须"可批量执行"——
  区间加 k: 区间和 = 原和 + 长度×k ✓（O(1) 可算）
  区间平方: 无法 O(1) 由原和算 → 不能用懒标记
```

> 🎯 **懒标记的本质**："**'整段覆盖 = 打标记 + 记值，不逐点更新'——修改被'记账'到节点，访问孩子时才结算（pushdown）**。'延迟更新、按需下发'八个字，就是懒标记的全部哲学。"

## 2. 懒标记模型：延迟更新按需下发

### 2.1 三个核心操作

```text
pushup（上收）: 孩子信息合并到父
  tree[p] = tree[2p] + tree[2p+1]（01 文件已有）

pushdown（下放）: 把懒标记传给孩子——
  ① 若 lazy[p] ≠ 0:
  ② 左孩子: tree[2p] += lazy[p] × len(左)
  ③ 右孩子: tree[2p+1] += lazy[p] × len(右)
  ④ 孩子各自打上 lazy 标记
  ⑤ 清空自己的 lazy[p] = 0

lazy 更新（区间加）: 整段覆盖时——
  tree[p] += k × len(区间)
  lazy[p] += k（记账）

⚠️ pushdown 的时机: 任何需要"深入孩子"的操作前——
  query 部分覆盖前、update 递归前
```

### 2.2 为什么不 pushdown 会错

```text
例: 区间 [0..3] 加 5（打了标记）后查询 [0..1]
  不 pushdown: 查 [0..1] 时 tree[2] 还是旧值 → 结果漏了 5 ✗
  pushdown 后: [0..1] 先收到 5 的标记 → 结果正确 ✓

⚠️ 铁律: "进入孩子前必须 pushdown——
   孩子的值必须包含祖先欠它的所有更新"
```

> 🎯 **pushdown 的定位**："**'深入孩子前结算欠账'——pushdown 把祖先的标记传给需要访问的孩子**。漏了它 = 孩子值过期 = 查询错，它是懒标记正确性的生命线。"

## 3. pushdown 与区间更新实现

### 3.1 完整实现

```java
/** 懒标记三件套: pushup / pushdown / 区间 update */
void pushup(int p) {                             // ① 上收
    tree[p] = tree[p * 2] + tree[p * 2 + 1];
}

void pushdown(int p, int l, int r) {             // ② ⚠️ 下放（核心）
    if (lazy[p] != 0) {
        int mid = (l + r) / 2;
        // 左孩子: 区间长 (mid−l+1)
        tree[p * 2] += lazy[p] * (mid - l + 1);
        lazy[p * 2] += lazy[p];
        // 右孩子: 区间长 (r−mid)
        tree[p * 2 + 1] += lazy[p] * (r - mid);
        lazy[p * 2 + 1] += lazy[p];
        lazy[p] = 0;                             // ③ 清空自己
    }
}

void updateRange(int p, int l, int r, int ql, int qr, int k) {
    if (ql <= l && r <= qr) {                    // ④ 完全覆盖
        tree[p] += k * (r - l + 1);              //    批量更新（O(1)）
        lazy[p] += k;                            //    打标记
        return;
    }
    pushdown(p, l, r);                           // ⑤ ⚠️ 深入前先下放
    int mid = (l + r) / 2;
    if (ql <= mid) updateRange(p * 2, l, mid, ql, qr, k);
    if (qr > mid) updateRange(p * 2 + 1, mid + 1, r, ql, qr, k);
    pushup(p);                                   // ⑥ 返回后上收
}
// ⚠️ query 也要 pushdown（部分覆盖时）——否则孩子值过期
```

> 💡 **updateRange 的流程**："**'完全覆盖 → 批量 + 打标；部分覆盖 → 下放 → 递归 → 上收'**。与单点 update 的差异就在'批量打标 + pushdown'两处——骨架完全一致。"

## 4. 完整模板（P3372 区间加）

### 4.1 面试/竞赛标准模板

```java
/**
 * 线段树 + 懒标记完整模板（洛谷 P3372 区间加、区间求和）
 * 时间 O(log n)/操作，空间 O(4n)
 */
class SegmentTreeLazy {
    private final long[] tree;                   // ① 区间和
    private final long[] lazy;                   // ② 懒标记（欠账）
    private final int n;

    public SegmentTreeLazy(int[] nums) {
        n = nums.length;
        tree = new long[4 * n];
        lazy = new long[4 * n];
        build(nums, 1, 0, n - 1);
    }

    private void build(int[] nums, int p, int l, int r) { ... }  // 同 01

    private void pushup(int p) {
        tree[p] = tree[p * 2] + tree[p * 2 + 1];
    }

    private void pushdown(int p, int l, int r) { ... }           // 3.1 节

    public void rangeAdd(int ql, int qr, int k) {
        updateRange(1, 0, n - 1, ql, qr, k);
    }

    public long rangeSum(int ql, int qr) {
        return query(1, 0, n - 1, ql, qr);
    }

    private long query(int p, int l, int r, int ql, int qr) {
        if (ql <= l && r <= qr) return tree[p];  // ③ 完全覆盖直接返
        pushdown(p, l, r);                       // ④ ⚠️ 部分覆盖先下放
        int mid = (l + r) / 2;
        long sum = 0;
        if (ql <= mid) sum += query(p * 2, l, mid, ql, qr);
        if (qr > mid) sum += query(p * 2 + 1, mid + 1, r, ql, qr);
        return sum;
    }
}
// 推演 [1,3,5]，rangeAdd(0,2,2)：根打标记 tree[1]=11, lazy[1]=2
//   rangeSum(1,1)：根 pushdown → 孩子收到 +2 → query(1,1) = 5 ✓
// 记忆: "pushdown 在下、pushup 在上——双向流动"
```

### 4.2 模板要点

```text
四件套: build + pushup + pushdown + 区间 update/query
新增: lazy[] 数组 + pushdown（唯一新代码）

⚠️ 记忆: "01 模板 + lazy 数组 + pushdown = 懒标记版"
```

> 🎯 **懒标记模板的地位**："**'01 模板 + lazy + pushdown'——懒标记版线段树是竞赛与面试的进阶必背**。P3372 是它的标准验收题（区间加 + 区间求和）。"

## 5. 多懒标记与标记顺序

### 5.1 区间加 + 区间乘

```java
/**
 * 区间加 + 区间乘（双懒标记）
 * ⚠️ 顺序: 先乘后加（乘法要影响已有加法标记）
 */
long[] tree, add, mul;                            // ① mul 初始 1

void applyMul(int p, int l, int r, long k) {      // ② 区间乘
    tree[p] *= k;
    mul[p] *= k;
    add[p] *= k;                                  // ⚠️ 已有加法标记也要乘！
}

void applyAdd(int p, int l, int r, long k) {      // ③ 区间加
    tree[p] += k * (r - l + 1);
    add[p] += k;
}

void pushdown(int p, int l, int r) {              // ④ 下放: 先乘后加
    int mid = (l + r) / 2;
    applyMul(p * 2, l, mid, mul[p]);
    applyMul(p * 2 + 1, mid + 1, r, mul[p]);
    applyAdd(p * 2, l, mid, add[p]);
    applyAdd(p * 2 + 1, mid + 1, r, add[p]);
    mul[p] = 1;
    add[p] = 0;
}
// ⚠️ 顺序陷阱: 先加后乘时，乘法必须"作用到已有加法"——
//   (a + x) × k = a×k + x×k → add 也要乘 k
// 区间赋值 + 加: 赋值优先级更高（赋值标记清空加标记）
```

> 💡 **多标记的顺序**："**'先乘后加 + 乘法作用于加法标记'——多懒标记的顺序是进阶第一大坑**。记住'乘法是缩放、会改变加法欠账'，顺序就对了。"

### 5.2 标记永久化

```text
标记永久化: 不 pushdown，标记留在节点上——
  查询时沿路径累加标记贡献
适用: pushdown 不可用的场景——
  可持久化、高维结构、李超线段树
效果: 时间不变、代码更简（竞赛技巧）

⚠️ 面试定位: 提存在即可——常规场景用 pushdown
```

## 6. 识别信号与易错点

### 6.1 识别信号

```text
"区间统一修改 + 区间查询" → 懒标记线段树
"区间加/乘/赋值 + 求和/最值" → 懒标记（P3372）
"区间开方/取模" → 势能线段树（特殊处理）
"10⁵ 操作量级" → 必须 O(log n)（懒标记）

⚠️ 判断: "修改可批量执行吗？" → 是 → 懒标记
```

### 6.2 易错点

| # | 易错点 | 正确写法 | 后果 |
|:---:|------|------|------|
| 1 | query 忘 pushdown | 部分覆盖先下放 | 查询漏更新 |
| 2 | pushdown 忘清 lazy | `lazy[p] = 0` | 重复下放 |
| 3 | 区间长度算错 | `r−l+1` / `mid−l+1` | 批量更新错 |
| 4 | 乘标记忘作用于 add | `add[p] *= k` | 先加后乘错 |
| 5 | 懒标记初始值错 | mul=1、add=0 | 乘法失效 |
| 6 | 不可批量硬用 | 验证可批量 | 结果错 |
| 7 | pushup/pushdown 混淆 | 上收 vs 下放方向 | 信息错乱 |

> 🎯 **核心要点**：懒标记通关四件事——**① 本质**（延迟更新按需下发）；**② 三操作**（pushup/pushdown/lazy 更新）；**③ 铁律**（深入孩子前必须 pushdown）；**④ 多标记顺序**（先乘后加）。**'整段打标、访问下放'——懒标记是区间更新的 O(log n) 魔法，也是线段树从入门到进阶的门槛**。
