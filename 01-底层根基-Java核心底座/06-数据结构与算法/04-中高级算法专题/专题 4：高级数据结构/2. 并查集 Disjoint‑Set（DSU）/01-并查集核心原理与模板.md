## 1. 并查集模型：集合的树表示

```text
并查集（DSU）: 维护不相交集合的"合并"与"同组查询"

树表示:
  每个集合一棵树，根 = 集合代表（代表元）
  parent[i] = i 的父节点；parent[根] = 根（自环）

操作:
  find(x): 沿 parent 向上找根（集合代表）
  union(x, y): 把 x 的树挂到 y 的树上（或反之）
  isSame(x, y): find(x) == find(y)

⚠️ 语义: 并查集只回答"A 和 B 是否在同一集合"——
  不维护路径信息（那是带权 DSU 的事）

例: 合并 {1,2} 与 {3,4} → 树:
  1 → 2（根），3 → 4（根）→ union(2, 4) → 2 → 4
  find(1) == find(3) → true（同组）
```

> 🎯 **核心认知**："**并查集 = '集合的树表示'——find 找根、union 挂树，isSame 比根**。它只回答'是否同组'，但 O(α(n)) 的代价让它在连通性/等价关系问题上近乎免费。"

## 2. 基础实现（朴素版）

### 2.1 朴素代码与退化问题

```java
/** 朴素并查集（无优化）——会退化！ */
class DSU {
    int[] parent;

    DSU(int n) {
        parent = new int[n];
        for (int i = 0; i < n; i++) parent[i] = i;   // ① 初始化: 自成一集合
    }

    int find(int x) {
        while (parent[x] != x) x = parent[x];        // ② 沿父向上找根
        return x;
    }

    void union(int x, int y) {
        int rx = find(x), ry = find(y);
        if (rx != ry) parent[rx] = ry;               // ③ 直接挂（可能退化）
    }

    boolean isSame(int x, int y) { return find(x) == find(y); }
}
// ⚠️ 退化场景: 依次 union(0,1), union(1,2), union(2,3)…
//   → 链表形态: 0→1→2→3→…→n → find(0) 是 O(n)！
//   例: union 顺序 "0-1, 1-2, 2-3" → find(0) 走 n 步
```

> 💡 **为什么必须优化**："**朴素版最坏 O(n)（退化成链表）——'0→1→2→3…'的合并顺序是经典反例**。两大优化（路径压缩/按秩合并）就是治这个：压缩扁平化、按秩防长链。"

## 3. 路径压缩：find 的扁平化

### 3.1 原理与代码

```java
/**
 * 路径压缩: find(x) 时把路径上所有节点直接挂根
 * 效果: 树扁平化——后续 find O(1) 级别
 */
int find(int x) {
    if (parent[x] != x) {
        parent[x] = find(parent[x]);             // ① 递归: 先找根再挂根
    }
    return parent[x];
}
// 推演: 链 0→1→2→3（根 3）
//   find(0): 递归到 3 → 回溯时挂根 → 0→3, 1→3, 2→3
//   之后 find(0) 一步直达 ✓
// ⚠️ 递归版简洁但深树可能栈溢出——
//   迭代版（先找根再遍历挂根）是工程选择
```

### 3.2 为什么路径压缩不影响语义

```text
路径压缩只改变"内部结构"不改"集合成员"——
  挂根前后，find(x) 返回的根相同（集合代表不变）
  → 压缩是纯优化，语义零影响

⚠️ 与可撤销 DSU 的冲突（02 文件）:
  路径压缩破坏树结构信息 → 无法撤销
  → 可撤销版本必须禁用路径压缩
```

> 🎯 **路径压缩的本质**："**'find 时顺手把路径挂根'——扁平化树、后续查询加速**。压缩是纯优化（语义不变），但它是可撤销 DSU 的禁区（结构信息被毁）。"

## 4. 按秩合并：union 的防退化

### 4.1 原理与代码

```java
/**
 * 按秩合并: 矮树挂高树（秩 = 高度上界）
 * 效果: 树高 ≤ log n（防退化）
 */
int[] rank;                                      // 秩（高度上界）

void union(int x, int y) {
    int rx = find(x), ry = find(y);
    if (rx == ry) return;                        // ① 已同组

    if (rank[rx] < rank[ry]) {
        parent[rx] = ry;                         // ② 矮挂高
    } else if (rank[rx] > rank[ry]) {
        parent[ry] = rx;
    } else {
        parent[ry] = rx;                         // ③ 等高 → 任一为根
        rank[rx]++;                              //    高度 +1
    }
}
// ⚠️ 效果: 只有"等高合并"才 +1 → 树高 ≤ log n
//   例: 依次合并 0-1, 2-3, 0-2… 树高保持 log 级别 ✓
// 按大小合并变体: size[] 记元素数，小树挂大树——语义更直观
```

### 4.2 按秩 vs 按大小

| 维度 | 按秩 | 按大小 |
|------|:---:|:---:|
| 记录 | 高度上界 | 元素个数 |
| 合并 | 矮挂高 | 小挂大 |
| 高度保证 | ≤ log n | ≤ log n |
| 语义 | 结构优化 | 更直观（size） |

```text
⚠️ 两者都防退化（树高 O(log n)）——
  选其一即可；可撤销 DSU 必须按大小（size 可恢复）
```

> 🎯 **按秩合并的定位**："**'矮挂高、等高 +1'——树高 ≤ log n 的保证**。与路径压缩配合后达到 O(α(n))，单独使用时 O(log n)。可撤销场景必须按大小（02 文件）。"

## 5. 完整模板（双优化）与复杂度证明

### 5.1 面试标准模板

```java
/**
 * 并查集完整模板（路径压缩 + 按秩合并）——面试标准答案
 * find O(α(n))、union O(α(n))——近似 O(1)
 */
class DSU {
    private final int[] parent;
    private final int[] rank;

    public DSU(int n) {
        parent = new int[n];
        rank = new int[n];
        for (int i = 0; i < n; i++) parent[i] = i;
    }

    public int find(int x) {                     // ① 路径压缩
        if (parent[x] != x) parent[x] = find(parent[x]);
        return parent[x];
    }

    public void union(int x, int y) {            // ② 按秩合并
        int rx = find(x), ry = find(y);
        if (rx == ry) return;
        if (rank[rx] < rank[ry]) parent[rx] = ry;
        else if (rank[rx] > rank[ry]) parent[ry] = rx;
        else { parent[ry] = rx; rank[rx]++; }
    }

    public boolean isSame(int x, int y) { return find(x) == find(y); }
}
// 记忆: "find 压缩 + union 按秩 + isSame 比根"
```

### 5.2 O(α(n)) 复杂度论证（面试必答）

```text
为什么双优化后是 O(α(n)):
  ① 路径压缩: 每次 find 把路径挂根 → 后续查询变快
  ② 按秩合并: 树高 ≤ log n → 找根路径短
  ③ 两者叠加: 摊还分析得 O(α(n))
     α(n) = 反阿克曼函数——
     任何实际 n（≤ 10^80）都满足 α(n) ≤ 5
  → 视为"近似 O(1)"

单独使用:
  只路径压缩: O(log n) 摊还
  只按秩合并: O(log n)
  双优化: O(α(n)) ✓

⚠️ 面试表达:
  "双优化后摊还 O(α(n))——反阿克曼函数，
   实际任何 n 都 ≤ 5，视为常数时间。"
```

> 🎯 **复杂度的面试价值**："**'双优化 → O(α(n))，α(n) ≤ 5'是并查集的复杂度标答**——能讲出反阿克曼 + 单独 vs 双用的差异，比背'近似 O(1)'有深度。"

## 6. 识别信号与易错点

### 6.1 识别信号

```text
"是否连通/同组 + 合并" → 并查集
"动态加边 + 查询连通" → 并查集（在线）
"冗余连接/判环（树 + 一条边）" → 并查集
"Kruskal/最小生成树" → 并查集判环
"等价关系分组" → 并查集

⚠️ 面试定位: 并查集是高频基础数据结构——
  547/684/990 是常见手撕；模板 2 分钟必会
```

### 6.2 易错点

| # | 易错点 | 正确写法 | 后果 |
|:---:|------|------|------|
| 1 | 忘初始化 parent[i] = i | 构造器初始化 | find 死循环 |
| 2 | union 忘判 rx == ry | 已同组直接返回 | 环误判 |
| 3 | find 忘路径压缩 | 挂根操作 | O(log n)→O(n) |
| 4 | 按秩合并忘 +1 | 等高时 rank++ | 高度失控 |
| 5 | 深树用递归 find | 迭代版 | 栈溢出 |
| 6 | union 顺序随意 | 按秩/按大小 | 退化 |
| 7 | 可撤销用路径压缩 | 只按大小（02 文件） | 无法撤销 |

> 🎯 **核心要点**：并查集基础通关四件事——**① 模型**（parent 树 + find/union）；**② 两大优化**（路径压缩/按秩合并）；**③ 复杂度论证**（双用 O(α(n))）；**④ 模板 2 分钟默写**。**'find 压缩、union 按秩、isSame 比根'——九个字就是并查集基础的全部**。
