## 1. 复合结构：哈希 + X 家族

### 1.1 核心模式

```
设计题第一套路："哈希定位 + 另一结构做特性"

哈希：O(1) 查找（键 → 节点/下标）
另一结构：
  链表 → 顺序/LRU（146）
  数组 → 随机访问（380）
  堆 → 最值（TopK）
  栈 → 单调/最近（155 辅助栈）

⚠️ 面试必答：
"设计题的通用骨架：哈希负责 O(1) 定位，
 另一结构负责题目要求的特性（顺序/随机/最值），
 两者指针互指、同步更新。"
```

### 1.2 家族对照表

| 题号 | 题目 | 复合结构 | 哈希的作用 |
|------|------|---------|-----------|
| 146 | LRU 缓存 | 哈希 + 双向链表 | key → 节点（O(1) 定位） |
| 380 | 随机获取 | 哈希 + 数组 | 值 → 下标（O(1) 定位） |
| 460 | LFU 缓存 | 哈希 + 频次桶 + 双向链表 | key → 节点 |
| 155 | 最小栈 | 栈 + 辅助栈 | 无（栈内配对） |
| 895 | 最大频率栈 | 哈希 + 频次桶 + 栈 | key → 计数 |
| 432 | 全 O(1) 结构 | 双向链表 + 双哈希 | key → 节点 |

```
⚠️ 规律：
  需要"淘汰/频次"→ 双向链表（节点摘除 O(1)）
  需要"随机"→ 数组（下标访问）
  需要"频次桶"→ 桶 + 链表（460/895）

⚠️ 面试表达：
"看到'O(1) + 特性'就想到复合结构——
 哈希定位是常量，特性由附属结构保证。"
```

### 1.3 复合结构的三原则

```
① 双向链表而非单向：删除需要前驱（O(1) 摘除）
② 同步更新：哈希与链表的修改必须原子（一个操作内完成）
③ 哨兵节点：dummy head/tail 免空判（代码简洁 + 防错）

⚠️ 面试必答：
"复合结构实现三原则——双向链表（O(1) 摘除）、
 同步更新（一个方法内改两结构）、哨兵节点
 （省空指针判断）。这是 146/460/432 的共同点。"
```

## 2. 设计题的方法论框架

### 2.1 五步设计法

```
① 需求拆解：每个操作的要求（O(1)？有序？随机？）
② 结构选型：哈希 + 什么？（见家族表）
③ 状态定义：节点存什么？下标指什么？
④ 同步更新：所有操作中两结构如何联动？
⑤ 边界验证：空结构、单元素、重复操作

⚠️ 面试表达：
"设计题五步：拆需求 → 选结构 → 定状态 →
 同步更新 → 边界验证。第 ④ 步是设计题的
 核心——'哈希改了链表也要改'。"
```

### 2.2 操作语义核对

```
每个方法都要回答：
  ① 复杂度是多少？（O(1)/O(log n)？）
  ② 边界行为？（空/不存在/重复）
  ③ 副作用？（缓存淘汰/计数变化）

⚠️ 常见遗漏：
  LRU 的 get 也要移动节点（访问刷新！）
  LFU 的频次 +1 后要跨桶移动
  随机结构的删除要更新"被换元素的映射"

⚠️ 面试必答：
"设计题写完先自查每个方法的'副作用'——
 get 刷新 LRU、删除更新映射、频次跨桶——
 这些是最容易漏的 O(1) 细节。"
```

### 2.3 设计题的验证方式

```
① 手推操作序列（put/get 交替）
② 边界序列（空/满/重复 key）
③ 复杂度逐方法核对
④ 结构一致性（哈希与链表指向是否同步）

⚠️ 面试表达：
"设计题验证 = 操作序列手推 + 边界序列 +
 复杂度逐方法 + 结构一致性检查。"
```

## 3. 复杂度论证的艺术

### 3.1 均摊 vs 最坏

```
⚠️ 关键区分：
  均摊 O(1)：大部分 O(1)，偶尔 O(n)（如扩容）
  最坏 O(1)：每次都是 O(1)（哈希不冲突时）

⚠️ 面试表达：
"'均摊 O(1)'与'最坏 O(1)'要分开说——
 哈希结构冲突时最坏 O(n)，均摊 O(1)；
 链表结构才是严格 O(1)。"
```

### 3.2 复杂度论证模板

```
每个操作论证三行：
  ① 哈希定位：O(1)（键 → 节点/下标）
  ② 结构操作：O(1)（链表摘除/数组交换）
  ③ 合计：O(1)（两个 O(1) 串联）

⚠️ 反例：数组中间删除是 O(n) → 所以 380
  用"尾部交换"把删除变 O(1)（哈希存下标）

⚠️ 面试必答：
"复杂度论证要'逐操作'——每个方法独立说
 复杂度，并解释为什么（哪个结构提供）。"
```

## 4. 线程安全设计

### 4.1 并发设计的三层

```
设计题 + 并发 = 三层递进：
  ① 基础版：单线程（面试默认）
  ② 加锁版：synchronized 全方法（简单正确）
  ③ 精细版：分段锁/读多写少优化（加分）

⚠️ 面试表达：
"并发设计先说三层：单线程 → 全锁 → 精细锁。
 面试先给单线程正确实现，被追问并发时
 再逐层加。'先正确后并发'是设计铁律。"
```

### 4.2 加锁策略

| 策略 | 做法 | 适用 |
|------|------|------|
| 全方法锁 | synchronized 所有公开方法 | 简单正确 |
| 细粒度锁 | 分段锁（哈希分桶） | 高并发读 |
| 读写锁 | ReentrantReadWriteLock | 读多写少 |
| 原子操作 | ConcurrentHashMap 等 | 键级并发 |

```
⚠️ 并发下的常见坑：
  ① 复合结构两结构更新不一致（需要同一把锁内完成）
  ② 检查-更新竞态（containsKey + put 非原子）
  ③ 迭代器并发修改

⚠️ 面试必答：
"复合结构的并发 = 一次操作内两结构同步更新
 必须在同一把锁内——'get-改-put'不能拆开。"
```

### 4.3 并发 LRU 的设计要点

```
并发 LRU 缓存：
  ① synchronized 方法版：简单（锁粒度大）
  ② ConcurrentHashMap + 手动同步链表：难（链表是全局状态）
  ③ 分段锁：按 key 哈希分桶，桶内独立 LRU
  ④ 工程实践：Caffeine（淘汰策略 + 并发优化）

⚠️ 面试表达：
"工程上并发缓存用 Caffeine/Guava Cache——
 内置淘汰策略与并发控制。手写题给
 synchronized 版即可，讲清升级路径。"
```

## 5. 设计题的扩展性思考

### 5.1 参数化与泛化

```
设计题的"加分扩展"：
  ① LRU → LFU（淘汰策略参数化：最近 vs 最不常）
  ② 容量可配置（构造参数）
  ③ 泛型支持（K/V 类型）
  ④ 统计接口（命中率、大小）

⚠️ 面试表达：
"设计题答完基础版，主动提扩展——
 '如果淘汰策略要可配置，我可以抽象
  EvictionPolicy 接口'——扩展性思考是加分项。"
```

### 5.2 边界与防御

```
防御性设计：
  ① 非法参数（负容量、null key）
  ② 幂等操作（重复 put 同 key）
  ③ 容量边界（0 容量 / 满容量）
  ④ 类型安全（泛型而非 Object）

⚠️ 面试必答：
"防御性设计 = 参数校验 + 幂等 + 边界处理。
 设计题的'工程感'来自这些细节，
 而不是主流程本身。"
```

## 6. 设计题 → 系统设计

### 6.1 从数据结构到系统

```
设计题（数据结构级）→ 系统设计（架构级）：
  LRU 缓存 → 分布式缓存（Redis 的淘汰策略）
  Trie → 搜索引擎的词典索引
  LFU → CDN 热点淘汰
  前缀树 → 自动补全系统

⚠️ 面试表达：
"设计题是系统设计的'零件'——
 146 是 Redis 内存淘汰的实现细节；
 208 是搜索引擎索引的基础。"
```

### 6.2 两者的共同方法论

```
数据结构设计与系统设计共用：
  ① 需求拆解（读多写少？容量？）
  ② 结构选型（哈希/树/队列？）
  ③ 复杂度/吞吐论证
  ④ 扩展性（容量增长？）
  ⑤ 边界与容错

⚠️ 面试结论：
"设计题答得好 = 系统设计答得好——
 同一套方法论，只是粒度不同：
 内存结构 vs 分布式组件。"
```

## 7. 面试要点与追问

### 7.1 面试话术模板

```
"设计题五步：拆需求（【O(1)/特性】）→
 选结构（哈希 + 【链表/数组/堆】）→
 定状态（【节点/下标含义】）→
 同步更新（【两结构联动】）→ 边界验证。
 复杂度逐方法：哈希 O(1) + 结构 O(1) = O(1)。
 并发：先单线程正确，再谈加锁分层。"
```

### 7.2 高频追问 TOP 8

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | 为什么哈希+链表？ | 哈希定位 O(1) + 链表保序 |
| 2 | 为什么双向链表？ | 删除需前驱（O(1) 摘除） |
| 3 | 均摊 vs 最坏？ | 哈希最坏 O(n)，均摊 O(1) |
| 4 | 并发怎么处理？ | 单线程 → 全锁 → 精细锁 |
| 5 | 为什么数组随机 O(1)？ | 下标访问 + 尾部交换删除 |
| 6 | 扩展性？ | 淘汰策略抽象接口 |
| 7 | 与系统设计关系？ | 同一方法论，粒度不同 |
| 8 | 最易漏的细节？ | get 刷新、删除更新映射 |

### 7.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| 单向链表 | 删除 O(n) | 双向 |
| 两结构不同步 | 数据不一致 | 一锁内更新 |
| get 忘刷新 | LRU 语义错 | 访问即移动 |
| 数组删除直接删 | O(n) | 尾部交换 |
| 忘哨兵节点 | 空判繁琐易错 | dummy head/tail |

---

> 🎯 **核心要点**：设计题 = **复合结构**（哈希定位 + 特性结构）+ **五步法**（需求→选型→状态→同步→边界）+ **复杂度逐方法论证** + **并发分层**（单线程→全锁→精细）。设计题是系统设计的零件——同一方法论，粒度不同。
