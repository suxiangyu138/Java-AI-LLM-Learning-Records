## 1. 数据流问题的本质

### 1.1 与静态问题的区别

```
静态数组：可重排/可全量排序 → 快选/排序
数据流：元素逐个到达，不可重排历史 → 在线结构

⚠️ 数据流三约束：
  ① 只进不出（或窗口进出）
  ② 每次到达都要"立即可答"
  ③ 历史不可重排（快选失效）

⚠️ 面试必答：
"数据流与静态问题的分界：能否'重排历史'。
 不能 → 在线结构（堆/队列/平衡树）；
 能 → 快选/排序。"
```

### 1.2 数据流问题的分类

| 类型 | 查询 | 结构 |
|------|------|------|
| 流式 TopK | 第 K 大/前 K | 定长堆 |
| 流式中位数 | 中位数 | 双堆 |
| 滑动窗口 | 窗口内统计 | 队列/双堆/单调结构 |
| 流式频率 | 频次统计 | 哈希/Count-Min |
| 流式唯一 | 去重 | Set/布隆 |

```
⚠️ 面试表达：
"数据流题先答'什么结构能在线维护答案'——
 TopK 用堆、中位数用双堆、窗口用队列、
 频率用哈希——结构选择决定一切。"
```

## 2. 双堆：中位数与分位数

### 2.1 双堆原理

```
双堆 = 大顶堆（左半）+ 小顶堆（右半）
不变量：
  ① 左顶 ≤ 右顶（左半所有 ≤ 右半所有）
  ② |左| - |右| ≤ 1（平衡）

中位数：
  奇数 → 左顶（左比右多 1）
  偶数 → (左顶 + 右顶) / 2

⚠️ 插入流程（三步）：
  ① 入左堆
  ② 平衡值序（左顶 > 右顶 → 交换堆顶）
  ③ 平衡大小（|左| - |右| ≤ 1）

⚠️ 面试必答：
"双堆 = 两个堆夹出'分界线'——
 大顶堆堆顶是左半最大、小顶堆堆顶是右半最小，
 分界线附近即中位数。插入 O(log n)、查询 O(1)。"
```

### 2.2 分位数扩展

```
任意分位数（如 90% 分位）：
  左堆大小 : 右堆大小 = p : (1-p)
  → 平衡条件改为比例而非 1:1

⚠️ 面试表达：
"双堆可以扩展为任意分位数——
 平衡条件从'差 ≤ 1'改为'按比例'。"
```

### 2.3 双堆的删除问题

```
⚠️ 堆不支持"任意值删除"（只能删堆顶）
  需要删除任意元素 → 延迟删除（第 3 节）
  或平衡树（TreeSet 支持任意删除）

⚠️ 面试必答：
"双堆的软肋是'任意删除'——堆只能删顶。
 滑动窗口场景（480）必须删除窗口滑出的元素
 → 用延迟删除解决。"
```

## 3. 延迟删除：删除的 O(log n) 化

### 3.1 核心思想

```
延迟删除（Lazy Deletion）：
  删除元素时不在堆里"物理删除"
  而是记录到"待删除表"（HashMap 计数）
  取堆顶时检查：若在待删除表 → 弹出丢弃

⚠️ 优点：删除 O(1)（记表）+ 取顶 O(log n) 均摊
  （物理删除需要 O(n) 查找或平衡树）

⚠️ 面试必答：
"延迟删除 = 删除'记账'、取顶'对账'——
 删除 O(1) 记入待删表，pop 时循环清理
 脏堆顶。均摊 O(log n) 且实现简单。"
```

### 3.2 完整实现（双堆 + 延迟删除）

```java
/** 双堆 + 延迟删除（480 的基础） */
class DualHeap {
    private final PriorityQueue<Integer> left = new PriorityQueue<>((a, b) -> b - a);
    private final PriorityQueue<Integer> right = new PriorityQueue<>();
    private final Map<Integer, Integer> pending = new HashMap<>();  // ⚠️ 待删表
    private int leftSize, rightSize;          // ⚠️ 逻辑大小（不含脏元素）

    void insert(int x) {
        if (left.isEmpty() || x <= left.peek()) {
            left.offer(x);
            leftSize++;
        } else {
            right.offer(x);
            rightSize++;
        }
        balance();
    }

    void remove(int x) {
        pending.merge(x, 1, Integer::sum);    // ⚠️ 删除 = 记账
        if (x <= left.peek()) leftSize--;
        else rightSize--;
        prune(left);                          // ⚠️ 清理两堆堆顶脏元素
        prune(right);
        balance();
    }

    private void prune(PriorityQueue<Integer> heap) {
        while (!heap.isEmpty() && pending.getOrDefault(heap.peek(), 0) > 0) {
            int x = heap.poll();              // 脏堆顶 → 弹出丢弃
            pending.merge(x, -1, Integer::sum);
        }
    }

    private void balance() {
        // ⚠️ 调整到 leftSize == rightSize 或 leftSize == rightSize + 1
        if (leftSize > rightSize + 1) {
            right.offer(left.poll());
            leftSize--; rightSize++;
        } else if (leftSize < rightSize) {
            left.offer(right.poll());
            leftSize++; rightSize--;
        }
        prune(left); prune(right);
    }
}
// ⚠️ 面试必答："延迟删除三件套：删除记账、
//   取顶清脏、逻辑大小维护（size 与堆实际大小分离）。"
```

## 4. 滑动窗口双堆：480 的核心

### 4.1 问题结构

```
滑动窗口（固定大小 k）+ 中位数：
  每个位置：加一个（插入）+ 减一个（删除）→ 双堆 + 延迟删除
⚠️ 复杂度：O(n log k)（每个元素插删一次）

⚠️ 与纯数据流的区别：
  数据流：只进不出
  滑动窗口：进出并存（删除 = 延迟删除登场）

⚠️ 面试必答：
"480 = 数据流双堆 + 窗口删除——
 窗口滑出元素用延迟删除处理，
 窗口滑入元素正常插入。"
```

### 4.2 滑动窗口模板

```java
/** 滑动窗口双堆骨架（480） */
double[] slidingWindowMedian(int[] nums, int k) {
    DualHeap dh = new DualHeap();
    double[] result = new double[nums.length - k + 1];

    for (int i = 0; i < nums.length; i++) {
        dh.insert(nums[i]);                  // ① 滑入
        if (i >= k) dh.remove(nums[i - k]);  // ② 滑出（延迟删除）

        if (i >= k - 1) {
            // ③ 取中位数（左右堆顶）
            result[i - k + 1] = dh.median();
        }
    }
    return result;
}
// ⚠️ 面试表达："滑动窗口 + 双堆 = 480 的完整骨架——
//   insert/remove/median 三操作，remove 走延迟删除。"
```

## 5. 数据流结构家族

### 5.1 家族总览

| 结构 | 维护什么 | 复杂度 | 代表 |
|------|---------|:---:|------|
| 定长堆 | 前 K 大/小 | O(log k)/次 | 703 |
| 双堆 | 中位数/分位 | O(log n)/次 | 295、480 |
| 队列 | 窗口元素（FIFO） | O(1)/次 | 346、933 |
| 单调队列 | 窗口最值 | 均摊 O(1) | 239 |
| 哈希计数 | 频率 | O(1) 期望 | 流式频次 |
| 平衡树 | 有序集合 | O(log n) | 流式第 K |

```
⚠️ 选型口诀：
  TopK → 定长堆
  中位数 → 双堆
  窗口最值 → 单调队列
  窗口均值/计数 → 队列 + 累加
  任意删除 + 有序 → 平衡树

⚠️ 面试必答：
"数据流结构家族——堆管'前 K/中位'、
 队列管'窗口'、单调队列管'窗口最值'。
 特征决定结构，结构决定复杂度。"
```

### 5.2 单调队列 vs 双堆（窗口最值 vs 中位数）

```
窗口最大值：单调递减队列（队首即最大）均摊 O(1)
窗口中位数：双堆 + 延迟删除 O(log k)

⚠️ 区别：
  最值有单调性（可淘汰劣者）→ 单调队列
  中位数无单调性（不能淘汰）→ 必须全保留 → 双堆

⚠️ 面试必答：
"'窗口最值'能淘汰（单调队列）、
 '窗口中位数'不能淘汰（双堆）——
 能不能'丢弃无用元素'决定结构。"
```

## 6. 在线 vs 离线：选型决策

### 6.1 判定框架

```
能否重排/离线预处理？
  ├─ 能（静态数组）→ 快选/排序（一次 O(n)）
  └─ 不能（流式/在线）→ 在线结构（每次 O(log n)）

⚠️ 面试必答：
"在线与离线的分界 = '能否等待全部数据'。
 数据流必须在线（元素到达即答）→
 每次 O(log n) 的堆/树结构；
 静态数组可离线 → 快选一次 O(n)。"
```

### 6.2 复杂度对比（同一问题）

| 场景 | 离线 | 在线 |
|------|:---:|:---:|
| 第 K 大 | 快选 O(n) | 堆 O(n log k) |
| 中位数 | 排序 O(n log n) | 双堆 O(n log n) |
| 窗口均值 | 前缀和 O(n) | 队列 O(n) |
| 频率 TopK | 频次桶 O(n) | 堆 O(n log k) |

```
⚠️ 面试表达：
"同一问题在线比离线常数大（log 因子）——
 在线结构的代价是'每次都要维护答案'。
 面试先问：数据是静态还是流式？"
```

## 7. 面试要点与追问

### 7.1 面试话术模板

```
"数据流题先判在线/离线：流式 → 在线结构。
 TopK → 定长堆；中位数 → 双堆（平衡 + 堆顶）；
 窗口 → 队列/双堆（删除用延迟删除：
 记账 O(1) + 取顶清脏）。
 复杂度：每次 O(log n)，总 O(n log n)。"
```

### 7.2 高频追问 TOP 8

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | 数据流为什么不能快选？ | 历史不可重排 |
| 2 | 双堆不变量？ | 左≤右 + 大小差 ≤ 1 |
| 3 | 延迟删除？ | 记账 + 取顶清脏 |
| 4 | 窗口删除怎么办？ | 延迟删除（480） |
| 5 | 单调队列 vs 双堆？ | 最值可淘汰、中位不可 |
| 6 | 任意分位数？ | 双堆按比例平衡 |
| 7 | 在线复杂度？ | 每次 O(log n) |
| 8 | 数据流 TopK？ | 定长堆 |

### 7.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| 堆直接删除任意值 | 不支持 | 延迟删除 |
| 忘逻辑大小 | 平衡错乱 | size 与堆分离 |
| 脏堆顶不清 | 答案错 | prune 循环 |
| 窗口忘滑出删除 | 窗口超尺寸 | remove 旧元素 |
| 静态当流式 | 常数浪费 | 先判在线/离线 |
