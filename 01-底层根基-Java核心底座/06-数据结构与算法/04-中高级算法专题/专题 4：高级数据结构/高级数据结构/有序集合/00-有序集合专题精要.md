## 1. 核心概念

### 1.1 什么是有序集合

> 有序集合：基于**平衡搜索树**（红黑树）的集合，元素保持有序，支持 O(log n) 的查找/插入/删除及**范围查询**。

```
Java 实现：
  TreeSet<T>：有序集合（无重复）
  TreeMap<K,V>：有序映射（键有序）

核心方法（红黑树支撑）：
  add/remove/contains：O(log n)
  first()/last()：最小/最大
  floor(x)/ceiling(x)：≤x 最大 / ≥x 最小 ★ 核心
  lower(x)/higher(x)：<x 最大 / >x 最小
  subSet(from, to)：范围子集

⚠️ 底层：红黑树（自平衡 BST）
  插入/删除后自动平衡 → 高度 O(log n)
```

### 1.2 核心操作的意义

```
floor/ceiling 的价值（面试核心）：
  floor(x)：小于等于 x 的最大元素（"地板"）
  ceiling(x)：大于等于 x 的最小元素（"天花板"）

应用场景：
  ① 找最接近的值（差 ≤ t 配对）
  ② 日程冲突检查（前驱/后继）
  ③ 有序窗口维护

记忆：floor = 向下找，ceiling = 向上找
```

### 1.3 适用场景

```
① 需要"前驱/后继"：找比 x 大的最小元素
   （220 存在重复 III：|nums[i]-nums[j]| ≤ t）
② 需要"范围查询"：区间内的元素
   （729 日程表：找与 [start,end] 冲突的日程）
③ 需要"有序性"：第 K 小/字典序
   （数据流有序统计）

⚠️ Java 无内置"有序多重集"（可重复）
   → TreeMap<值, 计数> 模拟
```

## 2. 完整代码模板

### 2.1 220. 存在重复元素 III（经典应用）

```java
/**
 * LeetCode 220. 存在重复元素 III
 * |nums[i]-nums[j]| ≤ t 且 |i-j| ≤ k
 *
 * 滑动窗口 + TreeSet 有序查找：
 *   窗口内元素有序 → ceiling 找最接近的配对
 */
public boolean containsNearbyAlmostDuplicate(int[] nums, int k, int t) {
    TreeSet<Long> set = new TreeSet<>();     // ⚠️ long：差值可能超 int

    for (int i = 0; i < nums.length; i++) {
        // 找 ≥ nums[i]-t 的最小元素（最接近的候选）
        Long candidate = set.ceiling((long) nums[i] - t);

        if (candidate != null && candidate <= (long) nums[i] + t) {
            return true;                     // |差| ≤ t ✓
        }

        set.add((long) nums[i]);             // 加入窗口
        if (set.size() > k) {                // ⚠️ 窗口大小限制
            set.remove((long) nums[i - k]);  // 移除窗口外
        }
    }
    return false;
}
// 暴力 O(nk) → TreeSet O(n log k)
// ⚠️ long 的必要性：nums[i]+t 可能溢出 int
```

### 2.2 729. 日程表（前驱后继判断冲突）

```java
/**
 * LeetCode 729. 我的日程安排表 I
 * book(start, end)：与已有日程冲突返回 false
 *
 * TreeMap<start, end> + floorKey/ceilingKey 判断
 */
class MyCalendar {
    TreeMap<Integer, Integer> calendar = new TreeMap<>();  // start → end

    public boolean book(int start, int end) {
        // 前一个日程（start 最大且 < 当前 start）
        Integer prev = calendar.floorKey(start);
        if (prev != null && calendar.get(prev) > start) {
            return false;                    // ⚠️ 前一个还没结束
        }

        // 后一个日程（start 最小且 ≥ 当前 end）
        Integer next = calendar.ceilingKey(start);
        if (next != null && next < end) {
            return false;                    // ⚠️ 后一个已开始
        }

        calendar.put(start, end);
        return true;
    }
}
// O(log n) 每次 book（floorKey/ceilingKey 各 O(log n)）
// ⚠️ 判断逻辑：prev.end > start（重叠）或 next.start < end（重叠）
```

### 2.3 855. 考场就座（距离计算）

```java
/**
 * LeetCode 855. 考场就座
 * seat()：选离最近的人最远的位置
 * leave(p)：p 离开
 *
 * TreeSet 存已占座位 → 有序 → 计算最大间隔
 */
class ExamRoom {
    private TreeSet<Integer> seats;
    private int n;

    public ExamRoom(int n) {
        this.n = n;
        seats = new TreeSet<>();
    }

    public int seat() {
        if (seats.isEmpty()) {
            seats.add(0);                    // 空考场坐 0
            return 0;
        }

        // 找最大间隔（考虑两端）
        int best = -1, bestPos = 0;
        int prev = -1;                       // 虚拟左端

        for (int s : seats) {
            if (prev == -1) {
                // 左端位置：0 到第一个座位
                if (s > best) { best = s; bestPos = 0; }
            } else {
                // 中间：两座位之间的中点
                int dist = (s - prev) / 2;
                if (dist > best) {
                    best = dist;
                    bestPos = prev + dist;
                }
            }
            prev = s;
        }
        // 右端：最后一个座位到 n-1
        if (n - 1 - prev > best) bestPos = n - 1;

        seats.add(bestPos);
        return bestPos;
    }

    public void leave(int p) {
        seats.remove(p);                     // O(log n)
    }
}
// 有序集合让"找最大间隔"变成线性扫描 O(n)
```

## 3. 有序集合的应用模式

### 3.1 三大应用模式

```
模式一：前驱/后继查询（220/729）
  floorKey/ceilingKey 找最接近 → 判断条件

模式二：有序维护（855 座位）
  插入/删除保持有序 → 线性扫描取最优

模式三：范围查询（363 矩阵）
  subSet 或 ceiling 定位 → 统计区间

⚠️ 统一识别："需要有序 + 动态增删 + log 级查找"
```

### 3.2 有序多重集模拟

```java
/**
 * Java 无内置 multiset → TreeMap<值, 计数> 模拟
 */
class MultiSet {
    TreeMap<Integer, Integer> map = new TreeMap<>();
    int size = 0;

    public void add(int x) {
        map.merge(x, 1, Integer::sum);
        size++;
    }

    public void remove(int x) {
        if (map.merge(x, -1, Integer::sum) == 0) {
            map.remove(x);                   // 计数归零 → 删键
        }
        size--;
    }

    public int min() { return map.firstKey(); }
    public int max() { return map.lastKey(); }
    // ⚠️ 中位数：需要维护双指针/双堆（单独实现）
}
// 应用：动态有序数据的中位数/分位数统计
```

### 3.3 有序集合在滑窗中的应用

```
滑动窗口 + 有序集合：
  窗口内元素有序 → 可查询窗口内"第 K 小/最接近"
  例：480 滑动窗口中位数（双堆替代）
      363 矩形区域不超过 K（TreeSet 前缀和）

⚠️ 选型：窗口只需最值 → 单调队列（O(1) 均摊）
       窗口需要有序统计 → TreeSet（O(log k)）
```

## 4. 有序集合 vs 其他结构

### 4.1 结构对比

| 结构 | 查找 | 插入 | 有序 | 范围查询 |
|------|:---:|:---:|:---:|:---:|
| HashMap | O(1) | O(1) | ❌ | ❌ |
| **TreeSet/Map** | O(log n) | O(log n) | ✅ | ✅ |
| 堆 | O(1) 最值 | O(log n) | ❌ | ❌ |
| 排序数组 | O(log n) | O(n) | ✅ | ✅ |

```
选型口诀：
  只查不排序 → HashMap
  需要有序/前驱后继 → TreeSet/TreeMap
  只取最值 → 堆
  静态有序 → 排序数组（二分）
```

### 4.2 Java 实现细节

```
TreeSet vs TreeMap：
  同底层（红黑树）
  Set 无键值；Map 带值

⚠️ 自定义对象比较：
  实现 Comparable 或传入 Comparator
  否则 ClassCastException

⚠️ 复杂度保证：
  红黑树自平衡 → 插入/删除/查找恒 O(log n)
  （对比 BST 可能退化 O(n)）
```

## 6. 面试要点与追问

### 6.1 面试话术模板

```
"滑窗内需要找与当前值差 ≤ t 的元素——
 用 TreeSet 维护窗口：ceiling(nums[i]-t)
 找可能配对的最小元素，O(log k) 一次查询。
 暴力需要 O(k) 扫描，TreeSet 优化为 O(log k)。
 底层是红黑树，插入删除自动平衡。"
```

### 6.2 高频追问 TOP 8

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | TreeSet vs TreeMap？ | 同底层（红黑树）；Set 无值、Map 带值 |
| 2 | floorKey vs ceilingKey？ | floor 向下（≤x 最大）；ceiling 向上（≥x 最小） |
| 3 | 为什么用 long（220）？ | nums[i]+t 可能溢出 int |
| 4 | 有序多重集？ | TreeMap<值,计数> 模拟（Java 无内置 multiset） |
| 5 | 与堆的区别？ | 堆只给最值 O(1)；TreeSet 有序+前驱后继 O(log n) |
| 6 | 底层为什么红黑树？ | 自平衡保证 O(log n)（BST 会退化） |
| 7 | 自定义对象？ | Comparable/Comparator，否则 ClassCastException |
| 8 | 什么时候用？ | 需要"有序 + 动态 + 前驱后继" |

### 6.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| 忘 long 转换 | 溢出误判 | (long) 转换 |
| 窗口忘移除 | 窗口无限大 | size > k → remove |
| floor/ceiling 混淆 | 判断错 | 向下 floor/向上 ceiling |
| 729 判断方向错 | 冲突漏判 | prev.end > start |
| 忘比较器 | 自定义对象异常 | Comparable/Comparator |

> 🎯 **核心要点**：有序集合 = **红黑树 + floor/ceiling 前驱后继查询**。识别信号："差 ≤ t 配对、日程冲突、范围查询、有序维护"。记忆 floor=向下、ceiling=向上；220/729/855 三道题覆盖三大应用模式。
