## 1. 计数排序：完整实现与稳定性

### 1.1 原理

```
计数排序（Counting Sort）：值域 k 已知 → 频次数组 + 前缀和 → 定位放置
  ① 统计每个值的出现次数（count[v]++）
  ② 前缀和：count[i] 变成"≤ i 的元素个数"（= 位置区间右端）
  ③ 从后往前放置：保证稳定（同值元素保持原相对顺序）

⚠️ 适用条件：值域 k 可控（k ≤ 10⁶ 量级）
  复杂度 O(n + k)，空间 O(k)
```

### 1.2 稳定版完整实现

```java
/**
 * 计数排序（稳定版）——从后往前放置是关键
 */
void countingSort(int[] nums) {
    int n = nums.length;
    if (n == 0) return;

    // ① 值域分析（支持负数：偏移）
    int min = Integer.MAX_VALUE, max = Integer.MIN_VALUE;
    for (int x : nums) { min = Math.min(min, x); max = Math.max(max, x); }
    int k = max - min + 1;

    int[] count = new int[k];
    for (int x : nums) count[x - min]++;         // ② 频次

    for (int i = 1; i < k; i++) count[i] += count[i - 1];   // ③ 前缀和（位置）

    int[] output = new int[n];
    for (int i = n - 1; i >= 0; i--) {           // ④ ⚠️ 从后往前 → 稳定
        int v = nums[i] - min;
        output[--count[v]] = nums[i];            // 放置并前移位置指针
    }
    System.arraycopy(output, 0, nums, 0, n);
}
// 稳定性验证 [2,1,2]：
//   count = [1, 0, 2] → 前缀和 [1, 1, 3]
//   从后往前：2（最后一个）→ output[2]；1 → output[0]；2（第一个）→ output[1]
//   output = [1, 2, 2] —— 两个 2 的相对顺序保持 ✓
// ⚠️ 如果从前向后放置 → 两个 2 顺序反转（不稳定）
```

### 1.3 非稳定版（空间更省）

```java
/** 非稳定版：直接按值展开（不需要 output 数组） */
void countingSortUnstable(int[] nums, int min, int max) {
    int[] count = new int[max - min + 1];
    for (int x : nums) count[x - min]++;
    int idx = 0;
    for (int i = 0; i < count.length; i++)
        while (count[i]-- > 0) nums[idx++] = i + min;   // 展开
}
// ⚠️ 适用：只关心"排序结果"不关心稳定性（整数去重排序）
//   稳定性只有"对象排序"才需要
```

## 2. 频次统计的四类模式

### 2.1 模式总览

| 模式 | 结构 | 用途 | 代表题 |
|------|------|------|--------|
| 计数数组 | int[k]（k=值域） | 小值域频次 | 242、383、387 |
| 哈希计数 | Map<Key, Int> | 大值域/任意键 | 347、451 |
| 频次桶 | List[]（下标=频次） | 按频次排序/取 TopK | 347、451 |
| 位计数 | int（二进制位） | 位运算统计 | 136、137 |

### 2.2 计数数组 vs 哈希计数的选型

```
计数数组（int[]）：
  ✅ 快（数组索引）、省内存（int vs 装箱）
  ✅ 字符（26/128）、小整数
  ❌ 值域大（1e9）→ 空间爆炸

哈希计数（Map）：
  ✅ 任意键（字符串/对象）、稀疏值域
  ❌ 慢一点（哈希 + 装箱）、内存大

⚠️ 面试表达：
"字符计数用 int[26]（值域 26 固定）；
 大值域/对象用 HashMap——'值域大小'决定选型。"
```

### 2.3 频次桶的核心价值

```
频次桶 = 按频次"免排序"组织数据：
  下标 = 频次（1..n），桶内 = 该频次的元素
  从高频桶到低频桶遍历 = 频次降序（O(n) 免排序！）

⚠️ 应用：
  347 前 K 高频：取高频桶的前 K 个 → O(n)
  451 频率排序：全桶降序展开 → O(n)
  （对比排序解法 O(n log n)——频次桶是线性优化）

⚠️ 前提：频次上界 = n（元素总数）→ 桶数组大小 n+1 可控
```

## 3. 前缀计数：出现次数的区间查询

### 3.1 定义

```
前缀计数数组：pre[i] = 前 i 个位置中某值出现的次数
  区间 [l, r] 出现次数 = pre[r] - pre[l-1]（O(1) 查询）

与"前缀和"的区别：
  前缀和：数值累加（区间和）
  前缀计数：某值的频次累加（区间出现次数）

⚠️ 应用场景：
  多次查询"字符/数字在某区间出现次数" → 预计算 O(n)，查询 O(1)
```

```java
/** 字符区间出现次数查询（预计算 26 个前缀计数） */
int[][] buildCharPrefix(String s) {
    int n = s.length();
    int[][] pre = new int[26][n + 1];          // 每字符一个前缀计数
    for (int i = 0; i < n; i++) {
        for (int c = 0; c < 26; c++)
            pre[c][i + 1] = pre[c][i];         // 继承
        pre[s.charAt(i) - 'a'][i + 1]++;       // 当前字符 +1
    }
    return pre;
}
// 查询 [l, r] 内字符 c 出现次数：pre[c][r+1] - pre[c][l]
// 复杂度：预计算 O(26n)，查询 O(1)
// ⚠️ 工程映射：数据库的"频率直方图"、日志统计的时间窗计数
```

### 3.2 前缀计数的进阶

```
① 二维前缀计数：矩阵子区域中某值出现次数
   （二维前缀和思想，见前缀和专题）
② 动态前缀计数：支持单点更新 → 树状数组（BIT）
   （频率 → 值域 BIT：查询"小于 x 的个数"）
③ 滑动窗口计数：窗口内频次维护
   （加减法更新，见滑动窗口专题）
```

## 4. 计数 vs 哈希 vs 桶 vs 基数

### 4.1 四兄弟对比

| 结构 | 本质 | 复杂度 | 适用 |
|------|------|:---:|------|
| 计数数组 | 值 → 频次 | O(1) 读写 | 值域小 |
| 哈希表 | 键 → 值（哈希定位） | O(1) 期望 | 任意键 |
| 频次桶 | 频次 → 元素列表 | O(n) 构建 | 按频次处理 |
| 计数排序 | 频次 + 前缀和 | O(n+k) | 值域小排序 |

```
⚠️ 关系：
  计数数组 = "值域即下标"的哈希（无哈希函数）
  频次桶 = 计数的"转置"（频次做下标）
  计数排序 = 计数数组 + 前缀和的排序应用

面试表达：
"计数的本质是'值域索引'——用值直接做下标，
 免去哈希计算。值域大就退化用哈希；
 需要按频次排序就转置成频次桶。"
```

### 4.2 选型决策树

```
值域小（字符/小整数）？→ 计数数组（最快）
值域大但稀疏？      → 哈希表
需要按频次组织？    → 频次桶
需要排序？          → 计数排序 / 频次桶展开
只需判重？          → Set（哈希/位图）
```

## 5. 计数的工程应用

### 5.1 真实场景

| 场景 | 计数应用 |
|------|---------|
| 日志统计 | 错误码频次、接口 QPS 计数 |
| 数据库 | 索引选择性（列值分布直方图） |
| 推荐系统 | 物品共现计数（协同过滤） |
| 限流 | 时间窗计数器（固定窗口/滑动窗口） |
| 监控 | 分位数估算（HdrHistogram） |
| 大数据 | WordCount（MapReduce 的经典） |

```
⚠️ 工程启示：
  计数是"统计型问题"的基础原语
  高频 + 小值域 → 数组计数（性能第一）
  高频 + 大值域 → 分片计数（LongAdder）
  分布式 → 计数器合并（MapReduce 思想）
```

### 5.2 计数与去重的结合

```
判重本质也是计数：
  Set = 计数 > 0 的集合
  位图 = 布尔计数（每值 1 位）
  布隆过滤器 = 概率计数（见哈希专题）

⚠️ 面试表达：
"去重/判重是计数的退化形态——只关心'是否出现'。
 精确用 Set/位图，海量数据用布隆过滤器
 （允许误判但空间省 90%+）。"
```

## 6. 计数与流式统计

### 6.1 流式频次的三种方案

```
① 哈希计数：Map 累加（精确，内存随种类增长）
② 分片计数：LongAdder/CounterCell（高频单键，减少竞争）
③ 近似计数：Count-Min Sketch（流式、哈希+位图、可调误差）
   ⚠️ 原理：k 个哈希 → k 个位图 → 取 min（低估保证）
```

```
⚠️ 面试表达：
"流式频次：精确用哈希计数；单键高频用分片
 （LongAdder 减少 CAS 竞争）；海量流数据用
 Count-Min Sketch——哈希位图 + 取 min，误差有界。"
```

### 6.2 数据流的中位数/众数

```
流式众数：摩尔投票（O(1) 空间，见分治/07 169 题）
流式中位数：双堆（大顶 + 小顶）
流式 TopK：堆（见分治/03）

⚠️ 共同点：流式场景禁止"全量计数排序" → 用近似/在线结构
```

## 7. 计数题的边界与精度

### 7.1 边界清单

| 边界 | 处理 |
|------|------|
| 值域含负数 | 偏移（x - min） |
| 值域巨大 | 换哈希计数 |
| 计数溢出（int） | long / 取模 |
| 空数组 | 提前返回 |
| 频次桶下标越界 | 桶大小 n+1 |

### 7.2 精度与内存

```
内存公式：
  计数数组：4 × k 字节（int）
  10⁶ 值域 = 4MB（可接受）
  10⁹ 值域 = 4GB（不可接受 → 哈希）

⚠️ 面试表达：
"计数数组内存 O(k)——值域 10⁶ 时 4MB 可控，
 值域 10⁹ 时必须哈希。'值域是否可控'是
 计数 vs 哈希的第一判据。"
```

## 8. 面试要点与追问

### 8.1 面试话术模板

```
"计数用数组（值域小）或哈希（值域大）。
 需要按频次组织 → 频次桶（下标=频次，免排序）。
 计数排序 O(n+k)：频次 + 前缀和 + 从后往前放置（稳定）。
 前缀计数支持 O(1) 区间出现次数查询。
 流式场景用分片/Count-Min Sketch。"
```

### 8.2 高频追问 TOP 8

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | 计数数组 vs 哈希？ | 值域小用数组（快）；大用哈希 |
| 2 | 计数排序为什么稳定？ | 前缀和 + 从后往前放置 |
| 3 | 频次桶的作用？ | 免排序按频次组织（O(n)） |
| 4 | 前缀计数？ | pre[r] - pre[l-1] O(1) 查询 |
| 5 | 流式频次？ | 哈希 / 分片 / Count-Min Sketch |
| 6 | 计数的内存？ | O(k)；值域 10⁶ ≈ 4MB |
| 7 | 判重是计数吗？ | 是退化形态（是否出现） |
| 8 | 负数值域？ | 偏移处理（x - min） |

### 8.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| 负数直接当下标 | 越界 | 偏移 |
| 计数排序从前放 | 不稳定 | 从后往前 |
| 频次桶大小 = 最大频次 | 越界 | n + 1 |
| 值域 1e9 用数组 | OOM | 换哈希 |
| 忘继承前缀（二维） | 计数错 | pre[c][i+1] = pre[c][i] |

---

> 🎯 **核心要点**：计数体系 = **计数数组/哈希**（频次采集）+ **频次桶**（按频次免排序）+ **计数排序**（前缀和 + 稳定放置）+ **前缀计数**（区间查询）。判据一句话："值域小 → 数组，值域大 → 哈希，按频次 → 桶，流式 → 分片/近似。"
