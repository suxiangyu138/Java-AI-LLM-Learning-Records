## 1. 必胜态与必败态的递归定义

### 1.1 核心定义

```
必败态（P 态）：无论怎么走，下一步都到必胜态
必胜态（N 态）：存在一步走到必败态

递归定义（从终局倒推）：
  终局（无法操作）→ 必败态（轮到的人输）
  某状态存在一步到必败态 → 必胜态
  某状态所有步都到必胜态 → 必败态

例（取 1-3 个石子，取完者胜）：
  n=0：无法操作 → 必败
  n=1,2,3：可取完 → 一步到 n=0（必败）→ 必胜
  n=4：只能到 1/2/3（都必胜）→ 必败
  n=5,6,7：可取到 4（必败）→ 必胜
  模式：4 的倍数必败 ✓（与 292 的数学结论一致）
```

### 1.2 三种博弈形态

```
① 数学博弈：可推导公式（292 Nim、1025 奇偶）
   → O(1) 直接判断

② 区间博弈：两端取数（486、877）
   → 区间 DP（dp[i][j] = 净胜分）

③ 状态博弈：状态空间大（464、913）
   → 记忆化搜索 + 位掩码（状态压缩）

识别信号：
  状态少可枚举 → 记忆化 DFS
  状态有数学规律 → 找公式
```

### 1.3 状态博弈的模板

```
状态 = 当前局面（已选集合/位置组合）
dp[状态] = 当前玩家是否必胜

转移：存在一步到"对方必败" → 必胜
      所有步都到"对方必胜" → 必败

⚠️ 与普通 DP 区别：
  普通 DP：dp[状态] = 最优值
  博弈 DP：dp[状态] = 当前玩家视角的胜负
  转移时"对方视角"要取反
```

## 2. 464. 我能赢吗：状态压缩博弈

### 2.1 完整实现

```java
/**
 * LeetCode 464. 我能赢吗
 * 1..maxChoosableInteger 的数，双方轮流取（不重复）
 * 谁先使累计和 ≥ desiredTotal 谁赢。问先手能否必胜。
 *
 * 状态：已取的数（位掩码）+ 当前累计和
 * ⚠️ 累计和可用"剩余和"推导（和 = desiredTotal - 剩余）
 *   → 状态只需掩码！
 */
public boolean canIWin(int maxChoosableInteger, int desiredTotal) {
    // ① 剪枝：所有数之和都不够 → 必输
    int sum = maxChoosableInteger * (maxChoosableInteger + 1) / 2;
    if (sum < desiredTotal) return false;
    if (desiredTotal <= 0) return true;   // 先手直接赢

    // ② 记忆化：mask → 当前玩家是否必胜
    Boolean[] memo = new Boolean[1 << maxChoosableInteger];
    return dfs(0, desiredTotal, maxChoosableInteger, memo);
}

private boolean dfs(int mask, int remain,
                    int max, Boolean[] memo) {
    if (memo[mask] != null) return memo[mask];

    for (int i = 0; i < max; i++) {
        int bit = 1 << i;
        if ((mask & bit) != 0) continue;      // 已取过

        int nextRemain = remain - (i + 1);
        boolean opponentLose;
        if (nextRemain <= 0) {
            opponentLose = true;              // 我取完就赢
        } else {
            opponentLose = !dfs(mask | bit, nextRemain, max, memo);
            // ⚠️ 对方视角取反：对方必败 → 我必胜
        }

        if (opponentLose) {
            return memo[mask] = true;         // 存在一步必胜
        }
    }
    return memo[mask] = false;                // 所有步都输
}
// 状态数 2^max（max ≤ 20 可行）
// 复杂度 O(2^max × max)
```

### 2.2 关键细节

```
① 为什么状态只要 mask？
   剩余和 = desiredTotal - 已取和
   已取和可由 mask 计算（bitCount）
   → 状态压缩到一维（不用 (mask, remain) 二维）

② 为什么 max ≤ 20？
   2^20 ≈ 10⁶ 状态可行
   max > 20 → 状态爆炸 → 需数学剪枝

③ 记忆化为什么用 Boolean[]？
   Boolean 可表示 null（未计算）/true/false
   普通 boolean[] 无法区分"未计算"和"false"
```

## 3. 913. 猫和老鼠：复杂状态博弈

### 3.1 问题与状态设计

```java
/**
 * LeetCode 913. 猫和老鼠（Hard 博弈压轴题）
 * 老鼠从 1 出发，猫从 2 出发，猫鼠轮流移动
 * 老鼠到 0（洞）赢；猫抓到老鼠赢
 *
 * 状态：(猫位置, 鼠位置, 轮到谁)
 *   → 三维状态 (cat, mouse, turn)
 *
 * ⚠️ 难点：
 *  ① 图可能有环 → 不是所有状态都能确定胜负
 *  ② 平局判定：无法确定胜负的状态
 *  ③ 需要"染色法"或"BFS 逆推"（从确定状态反向传播）
 */
// 状态 (c, m, t)：t=0 鼠走 / t=1 猫走
// 返回值：0 平局 / 1 鼠赢 / 2 猫赢
// 实现：博弈 BFS 逆推（从"确定结局"状态反向）
// 面试定位：极难（压轴题），掌握思路即可
```

### 3.2 复杂博弈的分析框架

```
① 枚举所有状态（位置组合 × 轮次）
② 标记"确定结局"的状态（鼠到洞/猫抓鼠）
③ 从确定状态逆推（BFS）：
    轮到 X 且存在一步到"X 赢" → X 赢（确定）
    轮到 X 且所有步都到"Y 赢" → Y 赢（确定）
    无法确定 → 平局
④ 复杂度 O(状态数)

面试话术：
"图上有环导致部分状态无法直接判定，
 我用逆推 BFS：先标记确定结局的状态，
 从它们反向传播胜负，传播不到的
 就是平局。"
```

## 4. Sprague-Grundy 定理（SG）

### 4.1 SG 值定义

```
SG 值（博弈状态的 Grundy 数）：
  SG(终局) = 0
  SG(状态) = mex{ SG(所有可达状态) }
  （mex = 最小未出现的非负整数）

胜负判定：
  SG(状态) == 0 → 必败
  SG(状态) != 0 → 必胜

与 Nim 的关系：
  单个 Nim 堆 n → SG(n) = n
  多个独立子游戏 → SG 异或和（Nim 和）
  （Nim 是 SG 定理的特例！）
```

### 4.2 SG 定理

```
多个独立子游戏的组合博弈：
  总局面 SG = 各子游戏 SG 的异或和
  异或和 == 0 → 必败；≠ 0 → 必胜

应用：取石子变体（每堆可取 1-3 个）
  每堆独立 → 各自 SG → 异或判胜负

⚠️ 前提：子游戏独立（不相互影响）
  互相影响 → 不能直接异或（需整体博弈 DP）

面试定位：竞赛级理论，面试很少要求
  能讲"SG = mex 递归 + 异或组合"概念即可
```

## 5. 博弈策略总结

### 5.1 三种形态的选型

| 形态 | 特征 | 解法 | 代表题 |
|------|------|------|:---:|
| 数学博弈 | 有公式规律 | 数学推导 | 292/1025 |
| 区间博弈 | 两端取数 | 区间 DP | 486/877 |
| 状态博弈 | 状态可枚举 | 记忆化+掩码 | 464/913 |

### 5.2 解题四步

```
① 识别形态：数学？区间？状态？
② 定义状态：什么决定局面？（掩码/区间/位置）
③ 写转移：当前玩家视角 → 对方取反
④ 确定终局：无法操作的必败 / 达成条件者胜

⚠️ 状态可枚举性检查（面试第一句）：
  "状态数 = 2^20 ≈ 10⁶，记忆化可行"
```

### 5.3 面试话术

```
"博弈题从终局倒推：必败态是'怎么走都到必胜'，
 必胜态是'存在一步到必败'。
 这题状态是【掩码/区间】，用记忆化 DFS，
 转移时切换玩家视角（对手必败我必胜）。
 状态数【2^n】，复杂度【O(2^n × n)】可行。
 剪枝：总和不够直接返回。"
```

> 🎯 **核心要点**：博弈进阶 = **必胜/必败态倒推**（递归定义）+ **状态设计**（掩码/区间/位置）+ **玩家视角切换**（取反）。464（掩码状态）、913（逆推平局）是进阶代表；SG 定理（mex + 异或）是理论储备。识别信号："轮流取数、先手必胜、局面可枚举"。
