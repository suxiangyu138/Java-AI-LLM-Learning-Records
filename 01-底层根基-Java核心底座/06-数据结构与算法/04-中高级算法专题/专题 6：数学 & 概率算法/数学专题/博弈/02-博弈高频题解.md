## 1. 292. Nim 游戏（数学公式）

### 1.1 完整实现

```java
/**
 * LeetCode 292. Nim 游戏
 * 一堆 n 个石子，每次取 1-3 个，取完者胜
 *
 * 数学规律：4 的倍数必败
 *   n=4：无论取 1/2/3，对方都能取完剩下的 → 必败
 *   n=5,6,7：取到 4 给对手 → 必胜
 *   n=8：对手取到 4 → 必败
 *   → 归纳：n % 4 == 0 必败
 */
public boolean canWinNim(int n) {
    return n % 4 != 0;
}
```

### 1.2 规律推导（面试必讲）

```
必胜策略：让对手永远面对 4 的倍数
  我取 x（1-3），对手取 4-x → 总量减 4
  循环到 n=4 → 对手面对 4 → 必败

推演验证：
  n=5：我取 1 → 剩 4 → 对手必败 ✓
  n=8：无论取什么 → 对手取 4-x → 剩 4 → 我必败 ✓
```

### 1.3 变体：Nim 异或和（多堆）

```java
// 多堆 Nim：每堆任意取（不只 1-3）
// 先手必胜 ⇔ 所有堆异或和 ≠ 0
public boolean nimGame(int[] piles) {
    int xor = 0;
    for (int p : piles) xor ^= p;
    return xor != 0;
}
// xor=0 是"平衡态"：任何操作破坏平衡，对手总能恢复
// 面试话术："异或和为 0 是必败态——这是 Nim 的数学本质"
```

## 2. 486. 预测赢家（区间博弈 DP）

### 2.1 完整实现

```java
/**
 * LeetCode 486. 预测赢家
 * 双方轮流从数组两端取数，总分高者胜
 * 问先手能否获胜（或平局）
 *
 * 博弈 DP：dp[i][j] = 先手玩家在区间 [i,j] 的净胜分
 *   dp[i][j] = max(nums[i] - dp[i+1][j],   // 取左端
 *                  nums[j] - dp[i][j-1])    // 取右端
 *
 * 理解：取 nums[i] 后，对手在 [i+1,j] 是先手
 *       其净胜分 dp[i+1][j] 从我收益中扣除（零和）
 */
public boolean PredictTheWinner(int[] nums) {
    int n = nums.length;
    int[][] dp = new int[n][n];

    for (int i = 0; i < n; i++) {
        dp[i][i] = nums[i];              // 单元素区间
    }

    for (int len = 2; len <= n; len++) {           // 区间长度递增
        for (int i = 0; i + len - 1 < n; i++) {
            int j = i + len - 1;
            dp[i][j] = Math.max(
                nums[i] - dp[i + 1][j],            // 取左
                nums[j] - dp[i][j - 1]);           // 取右
        }
    }
    return dp[0][n - 1] >= 0;            // 先手净胜分 ≥ 0
}
// 推演 [1,5,2]：
// dp[0][2] = max(1 - dp[1][2], 2 - dp[0][1])
//          = max(1 - 3, 2 - 4) = -2 < 0 → 先手输 ✓
// （最优：对手拿 5，先手拿 1+2=3）
```

### 2.2 为什么用"净胜分"而非"最大得分"？

```
零和博弈：我拿的 = 对手没拿的
  双方总分固定（数组总和）
  → 只需比较净胜分（先手 - 后手）
  → 转移用减法（对方净胜分从我的收益扣除）

对比普通区间 DP（最大得分）：
  博弈 DP 需要"对手视角" → 减法
  普通 DP 只需要"自己最优" → 加法
```

## 3. 877. 石子游戏（先手必胜证明）

### 3.1 完整实现

```java
/**
 * LeetCode 877. 石子游戏（486 的特例）
 * 石子堆数为偶数，且总数为奇数 → 先手必胜！
 *
 * 证明（奇偶下标分组）：
 *   偶数堆 → 下标奇偶各占一半
 *   先手第一手必取某一端 → 之后可"锁死"同奇偶性下标
 *   例：先手取下标 0（偶），对手只能取 1 或 n-1
 *       （奇或偶... 实际上先手可保证全取同奇偶性）
 *   两组的和不同（总数为奇数）→ 先手选大的一组 → 必胜
 */
public boolean stoneGame(int[] piles) {
    return true;                     // ⚠️ 数学结论：先手必胜
}
// 486 的通用版（任意长度）需要 DP
// 877 的偶数+奇数总和 → O(1) 直接 true

// 通用 DP 版（486 相同）：
public boolean stoneGame_DP(int[] piles) {
    int n = piles.length;
    int[][] dp = new int[n][n];
    for (int i = 0; i < n; i++) dp[i][i] = piles[i];
    for (int len = 2; len <= n; len++) {
        for (int i = 0; i + len - 1 < n; i++) {
            int j = i + len - 1;
            dp[i][j] = Math.max(
                piles[i] - dp[i + 1][j],
                piles[j] - dp[i][j - 1]);
        }
    }
    return dp[0][n - 1] > 0;
}
```

### 3.2 奇偶下标锁死论证（面试加分）

```
偶数堆 [1, 5, 2, 4]（下标 0,1,2,3）：
  奇数组：下标 1,3 → 5+4 = 9
  偶数组：下标 0,2 → 1+2 = 3

先手策略：
  第一手只能取两端（0 或 3）
  若取 0（偶组）→ 对手只能取 1 或 3（奇组）
  之后先手永远能取到偶数组的下一枚（同奇偶性）
  → 先手必取完偶数组（或奇数组，取决于第一手）

先手选择较大组 → 必胜 ✓
```

## 4. 1025. 除数博弈（奇偶规律）

### 4.1 完整实现

```java
/**
 * LeetCode 1025. 除数博弈
 * 轮到 x：选 x 的因子 d（d < x），替换 x = x - d
 * 谁无法操作（x=1）谁输。问先手（n）能否赢。
 *
 * 数学规律：偶数先手必胜，奇数先手必败
 *   奇数 n：所有因子都是奇数 → 减后必为偶数 → 对手拿到偶数
 *   偶数 n：取 1 → 变奇数给对手
 *   → 保持"奇数给对手" → 对手最终面对 1 → 必败
 */
public boolean divisorGame(int n) {
    return n % 2 == 0;               // 偶数必胜
}

// DP 版（验证规律用）：
public boolean divisorGame_DP(int n) {
    boolean[] dp = new boolean[n + 1];   // dp[i] = 轮到 i 是否必胜
    for (int i = 2; i <= n; i++) {
        for (int d = 1; d < i; d++) {
            if (i % d == 0 && !dp[i - d]) {   // 存在一步到必败
                dp[i] = true;
                break;
            }
        }
    }
    return dp[n];
}
// dp 结果与奇偶规律一致 → 验证数学结论
```

### 4.2 数学 vs DP 的选择

```
面试策略：
  先讲数学观察（奇偶规律 + 论证）→ O(1) 答案
  再补充 DP 验证（展示严谨）
  数学题"先规律后代码"是标准表达

⚠️ 规律要先验证：
  小规模手算 n=1..6 确认规律
  再给出数学证明（奇偶论证）
```

## 5. 1140. 石子游戏 II（DP 优化）

### 5.1 完整实现

```java
/**
 * LeetCode 1140. 石子游戏 II
 * 每次可拿 1 到 2M 堆（M 随上轮拿的堆数更新）
 * 求先手最大得分
 *
 * 状态：(当前下标 i, 当前 M)
 * dp[i][M] = 从 i 开始、M 限制下先手最大得分
 * 转移：枚举拿 k 堆（1 ≤ k ≤ 2M）
 *   得分 = 拿的 k 堆和 + (剩余总和 - 对手从 i+k 的最大得分)
 *   = 前缀和技巧：拿 k 堆和 = pre[i+k] - pre[i]
 *   剩余总和 = total - pre[i+k]
 */
public int stoneGameII(int[] piles) {
    int n = piles.length;
    int[] pre = new int[n + 1];          // 前缀和
    for (int i = 0; i < n; i++) pre[i + 1] = pre[i] + piles[i];

    int[][] memo = new int[n][n + 1];    // dp[i][M]
    return dfs(piles, pre, 0, 1, memo);
}

private int dfs(int[] piles, int[] pre, int i, int M, int[][] memo) {
    if (i >= piles.length) return 0;
    if (memo[i][M] != 0) return memo[i][M];

    int total = pre[piles.length] - pre[i];   // 剩余总和
    int maxScore = 0;

    // 枚举拿 k 堆
    for (int k = 1; k <= 2 * M && i + k <= piles.length; k++) {
        int take = pre[i + k] - pre[i];       // 本轮拿的
        int opponent = dfs(piles, pre, i + k, Math.max(M, k), memo);
        // ⚠️ M 更新为 max(M, k)
        maxScore = Math.max(maxScore, total - opponent);
        // 简化：本轮得分 = total - 对手从 i+k 的得分
        // （对手得分最大 = 我得分最小 → 取 total - 对手最大）
    }
    return memo[i][M] = maxScore;
}
// 复杂度 O(n² × M)（M ≤ n）
// 面试话术："状态 (i, M)，转移枚举 k 堆，
//   用前缀和 O(1) 算区间和，对手视角取反"
```

### 5.2 进阶博弈的通用模式

```
多参数状态博弈：
  状态 = 位置 + 限制参数（i, M）
  转移 = 枚举操作量（k 堆）
  优化 = 前缀和（区间和 O(1)）

⚠️ M 的更新是本题关键：
  本轮拿 k 堆 → 下轮 M' = max(M, k)
  （不是固定 M！状态必须包含 M）
```

## 6. 题解方法论总结

### 6.1 五题模式总结

| 题号 | 形态 | 关键洞察 |
|:---:|------|------|
| 292 | 数学 | 4 的倍数必败（异或和=0） |
| 486 | 区间 DP | 净胜分 = 取数 - 对手净胜分 |
| 877 | 数学+DP | 偶数堆 → 奇偶分组锁死 |
| 1025 | 数学 | 奇数因子全奇 → 奇偶转换 |
| 1140 | 状态 DP | (i, M) 状态 + 前缀和优化 |

### 6.2 博弈题识别清单

```
① "轮流取数/取石子" → 数学（找规律）或 DP
② "从两端取" → 区间博弈 DP（486/877）
③ "状态可枚举（≤2²⁰）" → 记忆化+掩码（464）
④ "先手能否必胜" → 必胜/必败态倒推
⑤ 多堆/多子游戏 → Nim 异或和 / SG 定理

第一反应："先小规模手算找规律，再选数学/DP"
```

### 6.3 面试话术

```
"博弈题从终局倒推：dp 表示当前玩家的净胜分/
 必胜性。转移的关键是零和——我取 x 后，
 对手在剩余局面的收益要从我的收益中扣除。
 这题状态是【区间/掩码/(i,M)】，
 复杂度【O(n²)/O(2^n)/O(n²M)】。
 先手胜 ⇔ dp 初始状态 ≥ 0 或为 true。"
```

> 🎯 **核心要点**：五道母题覆盖博弈三大形态——**数学**（292/1025：找规律+证明）、**区间 DP**（486/877：净胜分减法）、**状态 DP**（1140：多参数+前缀和）。识别信号："轮流取数、两端取、先手必胜"。方法论：**小规模找规律 → 选形态 → 零和视角转移**。
