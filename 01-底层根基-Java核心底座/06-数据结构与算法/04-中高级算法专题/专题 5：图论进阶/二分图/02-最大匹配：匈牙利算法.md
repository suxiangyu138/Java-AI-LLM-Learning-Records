## 1. 匹配与增广路

```text
匹配: 一组没有公共端点的边
  例: 左点 {A,B,C} 右点 {1,2,3}——
    边 A-1、B-1、C-2: {A-1, C-2} 是匹配（无公共端点）

最大匹配: 边数最多的匹配
  例: 上述最大匹配 = 2（A-1 与 C-2，或 B-1 与 C-2）

增广路: 一条"首尾都是未匹配点"的交错路——
  未匹配边 → 匹配边 → 未匹配边 → … → 未匹配边
  例: 未匹配点 A —(未匹配)1 —(匹配)B —(未匹配)2

⚠️ 核心性质: 增广路翻转（匹配边 ↔ 非匹配边）→ 匹配数 +1
  例: A-1、B-2 变匹配 → 匹配从 {B-1} 变成 {A-1, B-2}（+1）

⚠️ Berge 定理: 匹配是最大匹配 ⇔ 不存在增广路
  → 反复找增广路直到没有 = 最大匹配
```

> 🎯 **核心认知**："**增广路 = '翻转后匹配 +1'的路径——Berge 定理说'无增广路即最大匹配'**。匈牙利算法就是反复找增广路，找到就翻转。"

## 2. 匈牙利算法思想

### 2.1 "夺妻式"增广

```text
匈牙利算法（Kuhn，1955）: 从每个左点出发找增广路——
  ① 遍历左点（依次尝试匹配）
  ② 对每个左点 DFS 找增广路
  ③ 找到 → 翻转 → 匹配数 +1

DFS 的"夺妻"逻辑:
  当前左点想匹配右点 v——
  v 未匹配 → 直接匹配 ✓
  v 已匹配（给了别的左点 u）→ 尝试让 u 重新找（夺妻）
    u 能找到新的 → 让出 v 给当前点（匹配数 +1）
    u 找不到 → 当前点换别的右点

⚠️ 递归的语义:
  tryMatch(left, visited) →
    "尝试给 left 找匹配；visited 防本轮重复尝试"

⚠️ 复杂度: 每个左点 O(E) DFS → 总 O(VE)
```

> 🎯 **"夺妻式"的直觉**："**'让已匹配的对手重新找'——递归转移矛盾，最后总匹配数 +1**。这个递归是匈牙利算法的灵魂，也是它难写的原因（visited 防死循环）。"

## 3. 匈牙利完整实现（DFS 版）

### 3.1 核心代码

```java
/**
 * 匈牙利算法（最大匹配）——DFS 版
 * 时间 O(VE)，空间 O(V)
 */
class Hungarian {
    private final List<Integer>[] graph;           // ① 邻接表（左 → 右）
    private final int[] matchRight;                // ② 右点的匹配左点（-1 未匹配）
    private boolean[] visited;                     // ③ 本轮访问标记

    public Hungarian(int leftSize, int rightSize) {
        graph = new List[leftSize];
        for (int i = 0; i < leftSize; i++) graph[i] = new ArrayList<>();
        matchRight = new int[rightSize];
        Arrays.fill(matchRight, -1);
    }

    public int maxMatching() {
        int count = 0;
        for (int left = 0; left < graph.length; left++) {
            visited = new boolean[matchRight.length];  // ④ 每左点重置
            if (tryMatch(left)) count++;               // ⑤ 找到增广路 → +1
        }
        return count;
    }

    private boolean tryMatch(int left) {
        for (int right : graph[left]) {
            if (visited[right]) continue;          // ⑥ 本轮已尝试
            visited[right] = true;
            // ⑦ ⚠️ 夺妻: 右点未匹配 或 让它的当前匹配点重新找
            if (matchRight[right] == -1
                || tryMatch(matchRight[right])) {
                matchRight[right] = left;          // ⑧ 匹配成功
                return true;
            }
        }
        return false;                              // ⑨ 找不到增广路
    }
}
// ⚠️ 记忆: "遍历左点 → visited 重置 → 递归夺妻"
```

### 3.2 关键细节

```text
① visited: 每左点重置——防"本轮"重复尝试（死循环）
② 夺妻递归: tryMatch(已匹配该右点的左点)
③ 翻转隐式: 递归返回时 matchRight 已更新

⚠️ 面试表达:
  "对每个左点 DFS：右点空闲直接占；
   被占则让原主递归重找（夺妻）；
   visited 防本轮绕圈——O(VE)。"
```

> 🎯 **模板的灵魂**："**'空闲直接占、被占夺妻、visited 防圈'——三行核心逻辑就是匈牙利**。会背这个递归，最大匹配就过了。"

## 4. 逐步推演：增广路翻转

**左点 {A,B,C}、右点 {1,2,3}，边：A-1、B-1、B-2、C-2、C-3**

| 步骤 | 尝试 | 过程 | 匹配 |
|:---:|:---:|------|:---:|
| 1 | A | A-1 空闲 → 直接占 | {A-1} |
| 2 | B | B-1 被 A 占 → 夺妻：A 试 2（A 无边）→ 失败 | {A-1} |
| 3 | B | B-2 空闲 → 占 | {A-1, B-2} |
| 4 | C | C-2 被 B 占 → 夺妻：B 试 1（被 A 占）→ 夺妻 A 试 2（无）→ 失败 | {A-1, B-2} |
| 5 | C | C-3 空闲 → 占 | {A-1, B-2, C-3} |

**结果**：最大匹配 3 ✓（完美匹配）

```text
观察: 第 4 步的"双层夺妻"（C 抢 2 → B 抢 1 → A 换 2）失败——
  增广路不存在（C-2 是匹配边，B-1 是匹配边，A 无替代）
  第 5 步 C-3 直接成功 → 匹配满
⚠️ 递归深度 = 夺妻链长度——visited 保证不绕圈
```

## 5. HK 优化与复杂度

### 5.1 Hopcroft-Karp（竞赛优化）

```text
匈牙利: O(VE)——每个左点独立找增广路（可能重复）
HK（Hopcroft-Karp）: 分层 BFS + 多路增广——
  ① BFS 建立分层图（找最短增广路集）
  ② DFS 一次匹配多条增广路
  ③ 复杂度: O(√V·E)——竞赛大数据首选

⚠️ 选型:
  面试/小数据 → 匈牙利（好写）
  竞赛/大数据 → HK（O(√V·E)）
```

### 5.2 复杂度对比

| 算法 | 时间 | 适用 |
|------|:---:|:---:|
| 匈牙利（DFS） | O(VE) | 面试/小图 |
| Hopcroft-Karp | O(√V·E) | 竞赛/大图 |
| 网络流（Dinic） | O(E√V) | 与 HK 同阶 |

```text
⚠️ 面试表达:
  "匈牙利 O(VE) 面试够用；
   大图用 HK（O(√V·E)）或 Dinic（最大流）"
```

## 6. 识别信号与易错点

### 6.1 识别信号

```text
"配对/分配/任务 + 最大数量" → 最大匹配
"行列配对（POJ 3041 小行星）" → 行列建模 + 匈牙利
"互不冲突的最大组合" → 匹配
"棋盘覆盖/骨牌" → 网格染色 → 匹配

⚠️ 建模识别: "左组与右组的配对" →
  把配对关系建边 → 最大匹配（O(VE)）
```

### 6.2 易错点

| # | 易错点 | 正确写法 | 后果 |
|:---:|------|------|------|
| 1 | visited 忘重置 | 每左点 new 数组 | 死循环/漏匹配 |
| 2 | 夺妻递归条件错 | `matchRight[r]==-1 \|\| tryMatch(matchRight[r])` | 匹配错误 |
| 3 | visited 位置错 | 进入右点先标记 | 重复尝试 |
| 4 | matchRight 初始化 -1 | Arrays.fill | 空指针语义错 |
| 5 | 建图方向反 | 左 → 右邻接表 | 匹配错 |
| 6 | 计数时机错 | 每左点成功才 +1 | 匹配数错 |
| 7 | 大图用匈牙利 | HK/Dinic | 超时 |

> 🎯 **核心要点**：匈牙利通关四件事——**① 增广路性质**（翻转 +1、Berge 定理）；**② "夺妻式"递归**（空闲占/被占夺/visited 防圈）；**③ 完整模板**（O(VE)）；**④ 建模识别**（配对 → 匹配）。**'空闲直接占、被占夺妻、visited 防圈'——匈牙利算法的三行灵魂，就是最大匹配的全部**。
