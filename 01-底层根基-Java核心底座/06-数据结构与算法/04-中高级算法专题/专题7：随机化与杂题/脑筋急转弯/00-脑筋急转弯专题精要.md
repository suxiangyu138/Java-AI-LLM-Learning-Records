## 1. 核心概念

### 1.1 什么是脑筋急转弯题

> 脑筋急转弯（Brain Teaser）：**看似需要复杂算法，实则一句数学洞察**就能 O(1) 解决的题。考察"看穿本质"的能力。

```
特征：
  题干复杂（大数/大操作）
  解法极简（公式/规律）
  暴力可行但毫无意义

破局三问：
  ① 有周期/对称性吗？
  ② 能化简成简单计数吗？
  ③ 极端情况有什么规律？
```

### 1.2 经典规律速查

```
① 灯泡开关（319）：第 k 个灯泡亮 ⇔ k 是完全平方数
   （翻转次数 = 因子个数，完全平方数因子为奇数个）
② 除数博弈（1025）：偶数先手必胜（奇数必败）
③ 阶乘后零（172）：因子 5 的个数
④ 找不同（389）：异或/差值
⑤ 多数元素（169）：摩尔投票（计数抵消）
⑥ Nim 游戏（292）：4 的倍数必败
⑦ 快乐数（202）：快慢指针判环

共同点：先小规模手算 → 找规律 → 验证
```

### 1.3 识别信号

```
"n 巨大但操作简单" → 必然有规律（模拟会超时）
"看似复杂/反直觉" → 数学洞察题
"第 K 个 X / 多少个 X" → 计数规律

⚠️ 与模拟/数学的区别：
  模拟：规则明确按步骤（O(n)）
  数学：公式推导（O(1)）
  急转弯：洞察隐藏规律（代码 ≤ 5 行）
```

## 2. 完整代码模板

### 2.1 319. 灯泡开关（完全平方数）

```java
/**
 * LeetCode 319. 灯泡开关
 * n 轮翻转（第 k 轮翻转 k 的倍数），最后亮的灯泡数
 *
 * 推导：
 *   第 k 个灯泡被翻转的次数 = k 的因子个数
 *   亮 ⇔ 翻转奇数次 ⇔ 因子数为奇数 ⇔ 完全平方数
 *   （因子成对出现 a×b=k，完全平方数有 √k 自配对）
 *   → 答案 = 1..n 中完全平方数个数 = ⌊√n⌋
 */
public int bulbSwitch(int n) {
    return (int) Math.sqrt(n);
}
// 推演 n=3：1 翻 1 次亮；2 翻 2 次灭；3 翻 2 次灭 → 1 = ⌊√3⌋ ✓
// 推演 n=4：1 亮；2 灭；3 灭；4 翻 3 次亮 → 2 = ⌊√4⌋ ✓
```

### 2.2 1025. 除数博弈（奇偶规律）

```java
/**
 * LeetCode 1025. 除数博弈
 * 轮到 x：选 x 的因子 d（d<x），替换 x = x-d
 * 无法操作（x=1）者输。先手（n）能否赢？
 *
 * 推导：
 *   奇数 n：所有因子都是奇数 → 减后必为偶数
 *     → 对手拿到偶数
 *   偶数 n：取 1 → 变奇数给对手
 *   → 保持"奇数给对手"，对手最终面对 1 → 必败
 *   → 偶数先手必胜！
 */
public boolean divisorGame(int n) {
    return n % 2 == 0;
}
// 验证 n=1：奇数 → false（先手无法操作输）✓
// 验证 n=2：偶数 → true（取 1 给对手 1）✓
// 验证 n=3：奇数 → false（只能取 1 → 对手拿 2 必胜）✓
```

### 2.3 169. 多数元素（摩尔投票）

```java
/**
 * LeetCode 169. 多数元素（出现 > n/2）
 * 摩尔投票：候选 + 计数抵消
 * 多数元素与其他元素两两抵消后仍剩
 */
public int majorityElement(int[] nums) {
    int candidate = nums[0], count = 1;

    for (int i = 1; i < nums.length; i++) {
        if (count == 0) {
            candidate = nums[i];     // 换候选人
            count = 1;
        } else if (nums[i] == candidate) {
            count++;                 // 同票加
        } else {
            count--;                 // 异票抵消
        }
    }
    return candidate;                // 剩余候选 = 多数元素
}
// [2,2,1,1,1,2,2]：candidate=2, count=1
//   2→2(2)；1→1(1)；1→0；1→换1(1)；2→0；2→换2(1) → 2 ✓
// 为什么正确？多数元素数量 > 其他总和 → 抵消后必然存活
```

## 3. 经典规律推导

### 3.1 灯泡开关的完整推导

```
第 k 个灯泡被翻转的次数 = k 的正因子个数
  第 1 轮翻 1 的倍数 → 第 1 次
  第 2 轮翻 2 的倍数 → 若 k%2==0 → 第 2 次
  ...
  总共 = k 的因子个数

因子成对：k = a×b（a ≠ b 时成对出现）
  翻转次数 = 偶数（成对）→ 灭
  完全平方数：√k × √k（自配对）→ 奇数 → 亮

答案：1..n 中完全平方数 = ⌊√n⌋
```

### 3.2 除数博弈的证明

```
奇数 n 的性质：
  奇数因子只有奇数（奇×奇=奇）
  n - 奇数因子 = 偶数 → 对手拿到偶数
偶数 n 的策略：
  取因子 1 → n-1 = 奇数给对手
  → 始终保持"奇数给对手"
  → 对手最终面对 1（奇数）→ 无法操作 → 输

归纳：偶数必胜、奇数必败
```

### 3.3 摩尔投票的正确性

```
核心：多数元素数量 > 其他元素数量之和
  抵消过程：每对"异票"互相抵消
  多数元素最多被抵消到 0 后再被换掉？
  ⚠️ 不会！多数元素数量 > 总和的一半
  → 抵消后必然存活为最终候选

⚠️ 前提：题目保证存在多数元素（> n/2）
  不保证时需二次验证 count > n/2
```

## 4. 找规律的方法论

### 4.1 五步法

```
① 小规模枚举：手算 n=1,2,3,4 的结果
② 观察序列：1,1,2,3,5 → 斐波那契？
             1,1,2,5,14 → 卡特兰？
             1,0,1,0... → 奇偶？
③ 猜测公式/规律
④ 验证：n=5,6 是否符合
⑤ 证明（归纳/构造）：面试可简化

⚠️ 关键：先动手算，不要急着写代码
  急转弯题的代码通常 ≤ 5 行
  洞察力才是得分点
```

### 4.2 常见序列对照

```
① 1,1,2,3,5,8... → 斐波那契
② 1,1,2,5,14,42... → 卡特兰数
③ 1,2,4,8,16... → 2 的幂
④ 1,1,2,2,2... → 完全平方数计数（⌊√n⌋）
⑤ 1,0,1,0... → 奇偶交替

⚠️ 验证技巧：
  序列前几项与已知模式对照
  模式匹配后找"为什么"（证明）
```

### 4.3 反直觉陷阱

```
① 规律要先验证再使用（猜测可能错误）
② 大 n 与小 n 可能不同（边界）
③ "看起来像"不等于"就是"（需证明）

⚠️ 面试表达：
"我先手算了前几个值【1,1,2,2】，观察到
 与完全平方数相关——第 k 个灯亮当且仅当
 k 是平方数（因子成对 + √k 自配对），
 所以答案是 ⌊√n⌋。"
```

| 错误 | 后果 | 修正 |

| 没验证就写代码 | 规律错误 | 手算 3-5 例 |
