## 1. 核心概念

### 1.1 什么是交互题

> 交互题：无法直接看到全部输入，只能通过**提问 API** 获取信息，逐步缩小答案范围。每个提问有代价，需要**最少提问次数**。

```
与普通题的区别：
  普通题：给定全部输入 → 直接计算
  交互题：通过接口探测 → 逐步逼近

例（猜数字）：
  普通版：直接给数组 → 二分查找
  交互版：只能问 guess(n) 返回 -1/0/1 → 需要自己二分

核心思想：信息论——每次提问获得最大信息量
  （二分每次排除一半 → O(log n) 次提问）
```

### 1.2 识别信号

```
"猜数字/猜大小" → 比较型交互
"isBadVersion/API 查询" → 布尔型交互
"系统提供接口" → 交互题

⚠️ 交互题 = 二分查找的外包装
  答案空间有序/单调 → 二分
```

### 1.3 交互题的分类

```
① 比较型：guess() 返回 -1/0/1（374 猜数字）
② 布尔型：isBadVersion() 返回布尔（278）
③ 结构型：自定义 API 探测结构（链表/数组）
④ 在线型：边输入边决策（设计题）

共同点：问题可"二分"（答案空间有序/单调）
```

## 2. 完整代码模板

### 2.1 374. 猜数字大小（比较型）

```java
/**
 * LeetCode 374. 猜数字大小
 * 系统提供 guess(int n) → -1（大了）/0（对了）/1（小了）
 */
public class GuessGame {
    // 假设 guess(int n) 已提供

    public int guessNumber(int n) {
        int lo = 1, hi = n;
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;    // 防溢出
            int result = guess(mid);         // ⚠️ 提问（交互点）

            if (result == 0) return mid;     // 猜中
            else if (result == -1) {
                hi = mid - 1;                // 猜大了 → 左半
            } else {
                lo = mid + 1;                // 猜小了 → 右半
            }
        }
        return -1;
    }
}
// 复杂度：O(log n) 次提问（信息论下界）
// 推演 n=10，答案 6：
//   mid=5 → 1（小了）→ lo=6
//   mid=8 → -1（大了）→ hi=7
//   mid=6 → 0 → 返回 6 ✓（3 次提问 ≤ log₂10≈4）
```

### 2.2 278. 第一个错误版本（布尔型）

```java
/**
 * LeetCode 278. 第一个错误的版本
 * 系统提供 isBadVersion(int v) → boolean
 * 版本序列：[good, good, bad, bad...]（单调）
 */
public class VersionControl {
    // 假设 isBadVersion() 已提供

    public int firstBadVersion(int n) {
        int lo = 1, hi = n;
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (isBadVersion(mid)) {
                hi = mid;                // 坏的 → 第一个在左（含 mid）
            } else {
                lo = mid + 1;            // 好的 → 在右
            }
        }
        return lo;
    }
}
// ⚠️ 边界二分模板（right = mid 保留候选）
// 二段性：坏的序列单调（true 之后全 true）
// 这就是"第一个满足条件的位置"（lowerBound）
```

### 2.3 1095. 山脉数组查找目标（双 API）

```java
/**
 * LeetCode 1095. 山脉数组中查找目标值
 * 山脉数组（先升后降）→ 三次二分：
 *   ① 找峰顶（852 题）
 *   ② 左半升序二分找 target
 *   ③ 右半降序二分找 target（取最小下标）
 */
public int findInMountainArray(int target, MountainArray mountainArr) {
    int n = mountainArr.length();

    // ① 二分找峰顶
    int lo = 0, hi = n - 1;
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (mountainArr.get(mid) < mountainArr.get(mid + 1)) {
            lo = mid + 1;                // 上坡 → 峰在右
        } else {
            hi = mid;                    // 下坡 → 峰在左
        }
    }
    int peak = lo;

    // ② 左半升序二分
    int idx = binarySearch(0, peak, target, mountainArr, true);
    if (idx != -1) return idx;

    // ③ 右半降序二分
    return binarySearch(peak + 1, n - 1, target, mountainArr, false);
}

private int binarySearch(int lo, int hi, int target,
                         MountainArray arr, boolean ascending) {
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        int val = arr.get(mid);
        if (val == target) return mid;
        if (ascending) {                 // 升序：正常方向
            if (val < target) lo = mid + 1;
            else hi = mid - 1;
        } else {                         // 降序：方向反转
            if (val > target) lo = mid + 1;
            else hi = mid - 1;
        }
    }
    return -1;
}
// ⚠️ 注意 API 调用次数限制（题目要求 ≤ 100 次）
```

## 3. 信息论与提问次数

### 3.1 提问次数的下界

```
每次提问至少获得 1 bit 信息（二分）
n 个可能答案 → 至少 log₂n 次提问

例：猜 1-1000 的数字 → 10 次提问足够（2¹⁰=1024）

二分达到下界 → 最优
⚠️ 其他策略：
  三等分每次 log₃n < log₂n（更少！）
  但实现复杂 → 面试默认二分

⚠️ 面试必答：
"每次提问获得 1 bit 信息，
 n 个答案至少 log₂n 次，二分恰好达到。"
```

### 3.2 期望提问次数

```
二分最坏：log₂n 次
期望：≈ log₂n - 1 次（均匀分布）

⚠️ 面试表达：
"最坏 log₂n 次——每次提问排除一半，
 信息论下界恰好达到，是最优的。"
```

### 3.3 提问设计的原则

```
① 每次提问最大化信息（二分）
② 提问必须单调（答案空间可收缩）
③ 提问次数受限时 → 信息论估算可行性

⚠️ 交互题的第一步：
  "状态空间多大？提问多少次可行？"
  （与状态压缩 DP 的状态数评估同理）
```

## 4. 交互题 vs 普通题

### 4.1 对比表

| 维度 | 交互题 | 普通题 |
|------|:---:|:---:|
| 输入 | API 提问获得 | 全部给定 |
| 思路 | 逐步逼近 | 直接计算 |
| 复杂度 | 提问次数 | 计算时间 |
| 典型 | 猜数字 | 二分查找 |

```
关系：交互题 = 二分思想的"封装外壳"
  数组访问 arr[mid] → 替换为 API 调用
  其余模板完全相同
```

### 4.2 交互题与二分的对应

```
普通二分：arr[mid]（O(1) 访问）
交互题：guess(mid) / isBadVersion(mid)（一次提问）

边界二分：34 找边界 ↔ 278 找第一个坏版本
旋转数组：33 ↔ 1095 山脉（需先找峰顶）

⚠️ 面试表达：
"这题本质是二分——把数组访问换成
 API 调用即可。答案空间有序（单调），
 每次提问排除一半 → O(log n) 次。"
```

### 4.3 交互题的边界注意

```
① 返回值语义：-1/0/1 或 true/false 的方向
   （"大了"是左移还是右移——写反全错！）
② 提问次数限制：超过 = 错
③ 边界值：1 和 n、空输入

⚠️ 手写后自检：
  用 1-2 个例子推演提问序列
  确认方向正确（大了往左/小了往右）
```

## 6. 面试要点与追问

### 6.1 面试话术模板

```
"这是交互题，本质是二分：答案空间 1..n 有序，
 每次调用 guess(mid) 获得三分信息，排除
 一半范围 → O(log n) 次提问。
 每次提问 1 bit 信息，log₂n 是理论下界，
 二分恰好达到——最优。"
```

### 6.2 高频追问 TOP 8

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | 交互题第一反应？ | 二分！答案空间有序 + 提问单调 |
| 2 | 提问次数论证？ | 每次 1 bit → log₂n 下界 → 二分达到 |
| 3 | 返回值方向？ | -1/0/1 或 true/false 的移动方向（易错） |
| 4 | 与普通二分的差异？ | 数组访问换成 API 调用（模板相同） |
| 5 | 提问次数限制？ | 超出 = 错；二分 O(log n) 通常够 |
| 6 | 边界二分适用？ | 找第一个/最后一个（278 lowerBound） |
| 7 | 多段单调？ | 1095：找峰顶 + 两段二分 |
| 8 | 期望次数？ | 最坏 log₂n（信息论最优） |

### 6.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| 方向写反 | 永远找不到 | 验证 -1/0/1 语义 |
| 循环条件错 | 死循环/漏 | 按模板（<= 或 <） |
| 忘次数限制 | 超时 | 先估算 log₂n |
| mid 溢出 | 越界 | left + (right-left)/2 |
| 边界值漏 | 边界错误 | 1/n 特例 |

> 🎯 **核心要点**：交互题 = **二分模板 + API 调用替换数组访问**。识别信号："猜数字、只能提问、系统 API"。信息论论证（log₂n 次提问最优）+ 返回值方向是两大关键；278（布尔 lowerBound）与 374（比较型）是两个模板题。
