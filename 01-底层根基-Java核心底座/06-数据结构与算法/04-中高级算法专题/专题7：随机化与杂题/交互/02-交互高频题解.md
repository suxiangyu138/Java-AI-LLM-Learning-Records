## 1. 374. 猜数字大小

### 1.1 题目与思路

```
猜 1..n 的数字，guess(x) 返回 -1（大了）/0（对了）/1（小了）
⚠️ 语义：guess(x) 的返回值是"我的猜测 vs 目标"：
  -1 → 猜大了 → hi = mid - 1
   1 → 猜小了 → lo = mid + 1
⚠️ 每次提问 1 位信息 → log₂n 次（信息论最优，见 01 模块）
```

### 1.2 完整代码

```java
/**
 * LeetCode 374. 猜数字大小
 * ⚠️ 注意返回值语义（-1 是大了不是小了！）
 */
public int guessNumber(int n) {
    int lo = 1, hi = n;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;      // ⚠️ 防溢出
        int res = guess(mid);
        if (res == 0) return mid;
        if (res == -1) hi = mid - 1;       // 猜大了 → 上界收紧
        else           lo = mid + 1;       // 猜小了 → 下界抬高
    }
    return -1;
}
// 推演 n=10, 目标 6：
//   mid=5 → guess=1（小了）→ lo=6
//   mid=8 → guess=-1（大了）→ hi=7
//   mid=6 → 0 ✓（3 次 = ⌈log₂10⌉ = 4 以内 ✓）
// ⚠️ 面试表达："374 是'查值型'二分——lo<=hi 模板，
//   命中即返回。与 278 的'找边界型'（lo<hi）对比记忆。"
```

## 2. 278. 第一个错误的版本

### 2.1 题目与思路

```
isBadVersion(i) 布尔：从某版本起全是坏版本（布尔单调）
找第一个坏版本 → lower_bound 二分（找边界型）
⚠️ 单调性：isBadVersion 序列 false...false true...true
```

### 2.2 完整代码

```java
/**
 * LeetCode 278. 第一个错误的版本
 * ⚠️ 找边界模板：while (lo < hi) + hi = mid（含 mid）
 */
public int firstBadVersion(int n) {
    int lo = 1, hi = n;
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (isBadVersion(mid)) {
            hi = mid;                     // ⚠️ mid 可能是答案 → 保留
        } else {
            lo = mid + 1;                 // mid 是好的 → 排除
        }
    }
    return lo;                            // 收敛到第一个坏版本
}
// 推演 n=5, 坏版本从 4 开始：T T T F F
//   mid=3 → true → hi=3
//   mid=2 → true → hi=2
//   mid=1 → true → hi=1 → 返回 1? 不——假设坏从 4 开始：
//   mid=3 → false → lo=4；mid=4 → true → hi=4 → 返回 4 ✓
// ⚠️ 与 374 的区别：374 是"值存在"（lo<=hi）；278 是"边界"（lo<hi）
// ⚠️ 面试表达："布尔单调 → lower_bound 模板；
//   关键是 hi=mid（含 mid）——mid 可能就是第一个坏版本。"
```

## 3. 852. 山脉数组的峰顶索引

### 3.1 题目与思路

```
山脉数组：严格升后严格降（单峰，长度 ≥ 3）
峰值二分：比较相邻两点判定所在段
⚠️ 非交互题（数组直接访问），但"峰值二分"是 1095 的前置
```

### 3.2 完整代码

```java
/**
 * LeetCode 852. 山脉数组的峰顶索引
 */
public int peakIndexInMountainArray(int[] arr) {
    int lo = 0, hi = arr.length - 1;
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (arr[mid] < arr[mid + 1]) {
            lo = mid + 1;                 // ⚠️ 上升段 → 峰在右
        } else {
            hi = mid;                     // 下降段 → 峰在左（含 mid）
        }
    }
    return lo;
}
// 推演 [0,2,1,0]：
//   mid=1(2)：2 > 1 → hi=1 → 返回 1 ✓
// 推演 [0,1,2,3,1]：
//   mid=2(2)：2 < 3 → lo=3；mid=3(3)：3 > 1 → hi=3 → 返回 3 ✓
// ⚠️ 复杂度：O(log n)
// ⚠️ 为什么不用"三分"：两个相邻点的比较已经给出
//   方向信息（升/降）——每步 O(1) 判定，无需三态
```

## 4. 1095. 山脉数组中查找目标值

### 4.1 题目与思路

```
MountainArray.get(i) 访问（≤ 100 次预算），找 target 的任意下标
三段式：
  ① 峰值二分找峰顶（~log n 次 get）
  ② 左半（升序）二分 target（~log n 次）
  ③ 右半（降序）二分 target（~log n 次）
预算：3·log n ≤ 100 ✓（n ≤ 10⁴）
⚠️ 这是"峰值二分 + 双段二分"的组合题
```

### 4.2 完整代码

```java
/**
 * LeetCode 1095. 山脉数组中查找目标值
 * ⚠️ 访问预算 100 次：三段二分 3·⌈log₂n⌉ ≤ 60 次足够
 */
public int findInMountainArray(int target, MountainArray mountainArr) {
    int n = mountainArr.length();

    // ① 找峰顶
    int lo = 0, hi = n - 1;
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (mountainArr.get(mid) < mountainArr.get(mid + 1))
            lo = mid + 1;
        else
            hi = mid;
    }
    int peak = lo;

    // ② 左半升序二分
    int left = binarySearch(mountainArr, target, 0, peak, true);
    if (left != -1) return left;

    // ③ 右半降序二分
    return binarySearch(mountainArr, target, peak + 1, n - 1, false);
}

/** 通用二分（ascending 控制比较方向） */
private int binarySearch(MountainArray arr, int target,
                         int lo, int hi, boolean ascending) {
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        int v = arr.get(mid);                  // ⚠️ 每次 get 都花预算
        if (v == target) return mid;
        if (ascending == (v < target)) lo = mid + 1;   // ⚠️ 降序时比较反转
        else hi = mid - 1;
    }
    return -1;
}
// 推演 arr=[1,2,3,4,5,3,1], target=3：
//   峰顶 = 4（值 5）；左半 [0..4] 升序找 3 → 下标 2 ✓
//   若 target=1：左半 [0..4] 无 → 右半 [5..6] 降序找 1 → 下标 6 ✓
// ⚠️ 面试表达："1095 = 峰值二分 + 两段二分三段拼接；
//   降序段比较方向反转是关键；预算 3log n 恒够。"
```

## 5. 1533. 找到最大整数的索引

### 5.1 题目与思路

```
数组分成等大组（groupSize ≥ 2），
compare(a,b,c,d) 返回：a..b 段与 c..d 段谁更大（含相等）
找最大元素的下标（数组本身不可直接访问值！）
⚠️ 每次提问淘汰一半 → ⌈log₂n⌉ 次（信息论最优）
⚠️ 边界：余数段（不能等分时）单独处理
```

### 5.2 完整代码

```java
/**
 * LeetCode 1533. 找到最大整数的索引
 * ⚠️ compare 返回 0（相等）时 → 中间元素就是最大值
 */
public int getIndex(ArrayReader reader) {
    int lo = 0, hi = reader.length() - 1;

    while (lo < hi) {
        int len = hi - lo + 1;
        int half = len / 2;

        if (len % 2 == 1) {
            // ⚠️ 奇数长度：比较左半与右半，相等则中间是最大
            int cmp = reader.compare(lo, lo + half - 1,
                                     lo + half + 1, hi);
            if (cmp == 0) return lo + half;        // 中点是最大
            if (cmp < 0) lo = lo + half + 1;       // 右半更大
            else hi = lo + half - 1;               // 左半更大
        } else {
            // 偶数长度：直接对半比较
            int cmp = reader.compare(lo, lo + half - 1,
                                     lo + half, hi);
            if (cmp == 0) return lo + half;        // ⚠️ 理论不会发生
            if (cmp < 0) lo = lo + half;
            else hi = lo + half - 1;
        }
    }
    return lo;
}
// ⚠️ 推演 [3,1,2]（groupSize=2 时）：
//   len=3, half=1：compare(0,0 vs 2,2) → 3 vs 2 → cmp>0 → hi=0 → 返回 0 ✓
// ⚠️ 面试表达："1533 每次 compare 淘汰一半 →
//   log₂n 次提问。奇数长度的中点特殊处理
//   （相等即答案）是边界关键。"
```

## 6. 173. 二叉搜索树迭代器（交互式遍历）

### 6.1 题目与思路

```
next()/hasNext() 按中序返回 BST 元素——"惰性交互遍历"
⚠️ 交互本质：每次 next() 是一次"提问"（返回下一个元素）
  均摊 O(1)（每个节点进出栈一次）
⚠️ 与 01 模块的"迭代器设计"衔接（迭代器专题有完整版）
```

### 6.2 完整代码

```java
/**
 * LeetCode 173. 二叉搜索树迭代器
 * ⚠️ 中序惰性遍历：栈存左路径，next 弹栈 + 右转左探
 */
class BSTIterator {
    private final Deque<TreeNode> stack = new ArrayDeque<>();

    public BSTIterator(TreeNode root) {
        pushLeft(root);                    // 初始：左路径全部入栈
    }

    public int next() {
        TreeNode node = stack.pop();       // 弹栈 = 当前最小
        pushLeft(node.right);              // ⚠️ 右转左探
        return node.val;
    }

    public boolean hasNext() {
        return !stack.isEmpty();
    }

    private void pushLeft(TreeNode node) {
        while (node != null) {
            stack.push(node);
            node = node.left;
        }
    }
}
// 推演 [7,3,15,null,null,9,20]：
//   初始化栈 [7,3]；next → 3；next → 7（右转压 15,9）...
//   输出 3,7,9,15,20 ✓ 中序
// ⚠️ 均摊 O(1) 论证：每个节点入栈一次、出栈一次
// ⚠️ 面试表达："173 是'按需遍历'的交互——
//   调用者控制遍历节奏（惰性）；栈深度 = 树高 O(h)。"
```

## 7. 交互题方法论总结

### 7.1 解题五步框架

```
① 信息审计：有哪些 API？每个返回什么？语义是什么？
② 单调性：API 的信息能否形成"方向判定"？
   布尔单调 → lower_bound（278）
   三态有序 → 查值二分（374）
   相邻比较 → 峰值二分（852/1095）
   区间比较 → 淘汰一半（1533）
③ 预算：总不确定性 log₂N / 每次信息量 → 提问次数上界
   与题目限制对比（1095：3log n ≤ 100）
④ 边界：奇偶长度、空输入、越界、取整方向
⑤ 验证：小样例手推提问序列

⚠️ 识别信号："调用 API 获取信息 + 次数限制" → 交互题
  本质 = 普通算法的"信息获取被 API 封装"
```

### 7.2 题型模板速查

| 交互模式 | 算法 | 次数 | 代表题 |
|---------|------|:---:|--------|
| 三态反馈 | 查值二分 | log₂n | 374 |
| 布尔单调 | lower_bound | log₂n | 278 |
| 峰值 | 相邻判定二分 | log₂n | 852 |
| 峰值+双段 | 三段二分 | 3log n | 1095 |
| 区间比较 | 淘汰二分 | log₂n | 1533 |
| 按需遍历 | 迭代器 | O(1)/次 | 173 |

### 7.3 自测清单

```
□ API 返回语义核对（-1/0/1 方向）？
□ 模板选对（查值 lo<=hi vs 边界 lo<hi）？
□ 预算估算（log₂n vs 题目上限）？
□ 奇偶长度与取整方向一致（防死循环）？
□ 降序段比较反转？
□ 越界访问防护？
```

> 🎯 **核心要点**：交互题 = **API 信息审计** → **方向判定**（单调性）→ **二分提问**（信息论最优）→ **预算验证**。六题覆盖全部交互模式：三态（374）、布尔（278）、峰值（852/1095）、区间（1533）、按需（173）。信息论下界（log₂N）是判断"能否更少提问"的标尺。
