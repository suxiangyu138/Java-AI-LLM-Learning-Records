## 1. 搜索视角的记忆化：重复剪枝

```text
搜索本质: 遍历状态空间（状态 → 图节点）
记忆化 = "重复剪枝"——同一状态只探索一次

树搜索 vs 图搜索:
  树搜索: 同一状态可能从多条路径到达 → 重复计算
  图搜索: visited/memo 标记 → 每个状态只算一次

例（62 不同路径）:
  朴素 DFS: (2,2) 从多条路径到达 → 指数级重复
  记忆化: memo[2][2] 算一次 → O(mn)

⚠️ 与基础 visited 的区别:
  visited: 防"回访"（防环/死循环）
  memo: 防"重复计算"（缓存结果）
  记忆化 = visited + 结果缓存（两步合一）

识别信号: "DFS 会超时 + 重叠子问题"
```

> 🎯 **核心认知**："**记忆化在搜索中的本质 = '重复剪枝'——同一状态只探索一次**。与基础 visited 的差异：visited 防回访、memo 防重算；记忆化是'visited + 结果缓存'的合体。"

## 2. 三步模板（搜索版）

### 2.1 模板

```java
/**
 * 记忆化搜索模板（搜索视角）
 * 三步: 基线 → 查缓存 → 算 + 存
 */
int dfs(状态, memo) {
    if (基线条件) return 基线值;              // ① 终止（叶节点）

    if (memo[状态] != 未计算标记) return memo[状态];  // ② 查缓存（剪重复）

    int result = 计算(所有后继状态);          // ③ 遍历子节点
    return memo[状态] = result;              // ④ 存缓存（标记已访问）
}
```

### 2.2 与普通 DFS 的差异

```text
普通 DFS: 遍历 + 收集（void）——每个节点访问一次
记忆化: 遍历 + 计算 + 缓存（返回值）——每个状态算一次

⚠️ 三步对应搜索术语:
  ① 基线 = 叶节点判定
  ② 查缓存 = 重复剪枝（图搜索的 visited）
  ③ 存缓存 = 标记已访问 + 记录结果
```

> 🎯 **模板的搜索语义**："**记忆化三步 = 搜索三步 + 缓存——'基线（叶子）→ 查缓存（剪重复）→ 算存（标记+记录）'**。会普通 DFS 就能 30 秒改出记忆化版。"

## 3. 缓存结构选型

| 状态类型 | 缓存结构 | 例子 |
|------|------|------|
| 一维整数 | int[]（-1 = 未算） | 爬楼梯、LIS |
| 二维坐标 | int[][] | 62/329 |
| 三维状态 | int[][][] | 576 出界路径 |
| 复杂组合 | HashMap<状态键, 结果> | 403 青蛙（位置+跳跃） |
| 布尔结果 | Boolean[]（三态） | 464 博弈 |
| 位掩码 | int[]（下标 = mask） | 691 贴纸 |

```text
⚠️ 选型原则:
  "状态可索引（整数/坐标）→ 数组；
   状态复杂（组合/对象）→ HashMap；
   结果可能是任意值 → -1 标记；
   结果是布尔（博弈）→ Boolean 三态"
```

> 💡 **缓存键完备性**："**缓存键必须包含全部状态参数——漏一个参数 = 不同状态共用一个缓存 = 结果错误**。403 青蛙过河的 (位置, 上一步跳跃) 是经典'隐藏状态'案例。"

## 4. 博弈记忆化：三态缓存

### 4.1 为什么需要三态

```text
博弈搜索: dfs(状态) 返回"当前玩家能否赢"
  → 结果只有 true/false 两种
  → 用 boolean[] 缓存无法区分"未算"与"算过 = false"！

三态缓存: Boolean[]（包装类）
  null = 未算；true/false = 结果

⚠️ 记忆: "结果可能是 false → 缓存初值必须 null"
  （与"结果可能为 0 → 初值 -1"同一陷阱）
```

### 4.2 博弈转移（存在性）

```java
/**
 * 博弈记忆化模板: "存在一步让对手必输 = 我赢"
 */
boolean dfs(状态, Boolean[] memo) {
    if (memo[状态] != null) return memo[状态];   // ① 三态缓存

    for (选择 : 所有可行动作) {
        if (直接获胜) return memo[状态] = true;    // ② 立即赢
        if (!dfs(对手状态)) return memo[状态] = true;  // ③ 对手必输 → 我赢
    }
    return memo[状态] = false;                    // ④ 所有路都输 → 我输
}
// 例: 464 我能赢吗（mask 状态）、486 预测赢家、877 石子游戏
```

> 🎯 **博弈记忆化的必考点**："**'存在一步让对手必输 = 赢'的胜负传递 + Boolean 三态缓存**——博弈搜索与普通搜索的差异就在'胜负语义'与'三态标记'。"

## 5. 记忆化 vs 剪枝 vs DP

### 5.1 三者关系

```text
剪枝: 砍"必然无解/不优"的分支（搜索树的修剪）
记忆化: 砍"重复状态"的分支（去重——重复剪枝的一种）
DP: 记忆化的"递推版"（自底向上表格）

关系:
  剪枝 ⊃ 记忆化（记忆化是剪枝的子集）
  记忆化 ≡ DP 递归版（数学等价，实现视角不同）

⚠️ 面试表达:
  "记忆化 = 重复剪枝——同状态只算一次；
   与 DP 等价但自顶向下；
   是剪枝家族中'去重'这一类"
```

### 5.2 何时用哪个

```text
重叠子问题明显 → 记忆化 / DP（选实现偏好）
有"必然无解"判据 → 可行性剪枝（配合）
有"必然不优"上界 → 最优性剪枝（配合）
无重叠 → 纯 DFS（记忆化无意义）

⚠️ 组合: 竞赛搜索题 = 记忆化 + 可行性剪枝 + 最优性剪枝
  三者叠加（5. 剪枝进阶子目录）
```

## 6. 识别信号与易错点

### 6.1 识别信号

```text
"DFS 会超时 + 状态可索引/哈希" → 记忆化
"博弈 + 双方轮流" → 三态缓存
"计数/最优 + 重叠子问题" → 记忆化（= DP 递归版）

⚠️ 判断: 画递归树——相同状态出现多次？
  是 → 记忆化；否 → 纯 DFS
```

### 6.2 易错点

| # | 易错点 | 正确写法 | 后果 |
|:---:|------|------|------|
| 1 | 缓存初值 = 结果可能值 | -1 / null 标记 | 未算误判已算 |
| 2 | 忘查缓存 | 递归开头查 | 白记忆化 |
| 3 | 忘存缓存 | 算完写 | 永不命中 |
| 4 | 缓存键漏参数 | 含全部状态 | 状态污染 |
| 5 | 博弈用 boolean[] | Boolean[]（三态） | false 无法区分 |
| 6 | 无重叠硬记忆化 | 先验证 | 白加缓存 |
| 7 | 基线漏写 | 叶节点返回 | 死循环/越界 |

> 🎯 **核心要点**：记忆化搜索通关四件事——**① 本质 = 重复剪枝**（同一状态只算一次）；**② 三步模板**（基线/查缓存/算存）；**③ 缓存选型**（数组/HashMap/三态）；**④ 博弈三态**（null 区分未算）。**记忆化是"剪枝家族的去重武器"——'visited + 结果缓存'合体，就是搜索提速的第一板斧**。
