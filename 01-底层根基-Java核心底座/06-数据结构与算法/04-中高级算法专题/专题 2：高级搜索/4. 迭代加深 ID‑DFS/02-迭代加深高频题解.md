## 1. 埃及分数（迭代加深经典）

### 1.1 题目与思路

**题**：把分数 a/b 拆成若干单位分数（1/x）之和，要求项数最少且分母升序。

**为什么迭代加深**：答案项数（深度）未知但通常较小——阈值递增找最少项数：

```java
/**
 * 埃及分数（迭代加深经典）
 * 深度 = 项数（阈值递增找最少项）
 * 剪枝: 剩余分数 ≥ 剩余项数 × 当前分母（可行性）
 */
boolean egyptian(long a, long b, int depth, int maxDepth,
                 List<Long> result) {
    if (depth == maxDepth) {                     // ① 达到项数阈值
        if (a == 0) return true;                 //    分数拆完 → 找到
        return false;
    }
    // ② 分母下界: 从 ceil(b/a) 开始（1/x ≤ a/b）
    long start = Math.max(
        result.isEmpty() ? 2 : result.get(result.size() - 1) + 1,  // 升序
        (b + a - 1) / a);
    // ③ 可行性剪枝: 剩余项数 × 当前分数 < 剩余分数 → 不可能
    for (long x = start; ; x++) {
        // 剩余 (maxDepth−depth) 项，每项最大 1/x
        if ((maxDepth - depth) * b < a * x) break;   // ④ 剪枝: 项数不够
        result.add(x);
        if (egyptian(a * x - b, b * x, depth + 1, maxDepth, result))
            return true;                         // ⑤ 递归下一项
        result.remove(result.size() - 1);
    }
    return false;
}
// 调用: for (depth = 1; ; depth++) if (egyptian(a, b, 0, depth, result)) break;
// 推演 3/7: 深度 1 无解 → 深度 2: 1/3 + 2/21 不行 → 1/4 + 5/28...
//   实际 3/7 = 1/3 + 1/11 + 1/231（深度 3）或 1/4 + 1/7 + 1/28 ✓
// ⚠️ 可行性剪枝: "剩余项数 × 最大项 1/x < 剩余分数 → 永远拆不完"
```

> 🎯 **埃及分数的必考点**："**'项数 = 深度（阈值递增）+ 分母下界（ceil(b/a)）+ 可行性剪枝'三件套**——它同时演示了迭代加深与可行性剪枝的配合，是竞赛经典。"

## 2. 15 数码 IDA*（内存受限最优搜索）

### 2.1 题目与思路

**题**：4×4 拼图归位的最少步数。

**为什么 IDA***：状态空间 16!/2 ≈ 10¹³（A* 优先队列内存爆炸）——IDA* 用 O(d) 栈：

```java
/**
 * 15 数码 IDA*（核心骨架）
 * 阈值 = f = g + 曼哈顿；超阈值剪枝；返回最小超限作下轮阈值
 */
int idaStar(String start) {
    String target = "123456789ABCDEF0";
    int threshold = manhattan(start, target);    // ① 初始阈值 = h

    while (true) {
        int result = dfs(start, 0, threshold, target, -1);
        if (result == FOUND) return threshold;   // ② 找到（阈值即最优步数）
        if (result == -1) return -1;             // 无解
        threshold = result;                      // ③ 阈值 = 最小超限 f
    }
}

int dfs(String state, int g, int threshold, String target, int prevMove) {
    int f = g + manhattan(state, target);
    if (f > threshold) return f;                 // ④ 超阈值剪枝 → 返回超限值

    if (state.equals(target)) return FOUND;      // ⑤ 到达目标

    int minOver = Integer.MAX_VALUE;
    for (移动 : 合法移动) {
        if (移动 == prevMove 的反向) continue;   // ⑥ 防回退（剪枝）
        String next = 交换0后的状态;
        int result = dfs(next, g + 1, threshold, target, 移动);
        if (result == FOUND) return FOUND;
        minOver = Math.min(minOver, result);     // ⑦ 记录最小超限
    }
    return minOver;
}
// 推演: 15 数码最坏需 80 步——IDA* 阈值从 h 递增到 80
// ⚠️ 防回退剪枝: 记录上一步移动，反向移动直接跳过（省一半分支）
//   曼哈顿 admissible → IDA* 最优 ✓
```

> 💡 **15 数码的工程细节**："**'防回退剪枝（跳过反向移动）+ 曼哈顿启发式 + 阈值递增'是 15 数码 IDA* 的三件套**——'上一步的反向移动无意义'省一半分支，是最容易忽略的剪枝。"

## 3. 骑士巡逻（深搜 + 加深）

### 3.1 题目与思路

**题**：骑士走遍棋盘每格恰好一次（经典回溯 + 优化）。

**迭代加深视角**：求"走遍 n×n 的最短路径"用加深；**Warnsdorff 规则**是排序剪枝的经典：

```java
/**
 * 骑士巡逻（Warnsdorff 规则 = 排序剪枝）
 * 每次优先走"下一步可选位置最少"的方向
 * ⚠️ 排序剪枝: 改变搜索顺序——先试最可能成功的分支
 */
boolean knightTour(int n, int[][] board) {
    // ① 骑士 8 方向
    int[][] moves = {{2,1},{2,-1},{-2,1},{-2,-1},
                     {1,2},{1,-2},{-1,2},{-1,-2}};

    // ② Warnsdorff: 每步选"后继最少"的方向
    // 对每个候选方向，统计它的下一步可选数 → 升序排序
    // 先尝试"最受限"的方向（成功率高）
    return dfs(board, n, 0, 0, 1, moves);
}

boolean dfs(int[][] board, int n, int i, int j, int step, int[][] moves) {
    if (step == n * n) return true;              // ① 走满
    // ② 生成候选并按"后继数"排序（Warnsdorff）
    List<int[]> candidates = getCandidates(board, n, i, j, moves);
    candidates.sort((a, b) -> countNext(a) - countNext(b));  // ③ 排序剪枝
    for (int[] next : candidates) {
        board[next[0]][next[1]] = step + 1;      // ④ 走
        if (dfs(board, n, next[0], next[1], step + 1, moves)) return true;
        board[next[0]][next[1]] = 0;             // ⑤ 回溯
    }
    return false;
}
// ⚠️ 排序剪枝的本质: 不砍分支、只调顺序——
//   先试"最可能成功"的分支 → 找到解更快
//   （与 5. 剪枝进阶的"搜索顺序"同一哲学）
```

> 🎯 **排序剪枝的价值**："**Warnsdorff = '先走最受限的'——排序剪枝不砍分支只调顺序，但找到解的速度提升巨大**。它是'搜索顺序影响效率'的最佳案例，与可行性/最优性剪枝并列三大剪枝思想。"

## 4. 迭代加深家族总览

| 题 | 深度语义 | 剪枝配合 | 定位 |
|:---:|:---:|:---:|:---:|
| 埃及分数 | 项数 | 可行性（分母上界） | 竞赛经典 |
| 15 数码 | 步数（f 阈值） | IDA* + 防回退 | 内存受限最优 |
| 骑士巡逻 | 步数 | Warnsdorff 排序 | 排序剪枝 |
| 8 数码 | 步数（f 阈值） | IDA* + 曼哈顿 | IDA* 入门 |
| 数独 | 空格数 | 约束传播 | 深搜 + 剪枝 |

```text
⚠️ 家族规律:
  "深度 = 问题目标（项数/步数）——阈值递增找最少目标；
   剪枝配合 = 可行性（项数）+ 防回退（对称）+ 排序（Warnsdorff）"
```

## 5. 剪枝配合：ID + 可行性剪枝

### 5.1 为什么必须配合剪枝

```text
纯迭代加深: 每轮重搜——浅层还好，深层代价大
配合剪枝: 每轮搜索量大幅下降

ID + 可行性剪枝（埃及分数）:
  剩余项数 × 最大项 < 剩余分数 → 剪
  → 每轮搜索量从指数级降到可接受

ID + 防回退（15 数码）:
  跳过反向移动 → 分支因子 4→3（省 25%）

ID + 排序（骑士）:
  Warnsdorff 先走受限 → 找到解快 10 倍+

⚠️ 结论: "迭代加深负责'深度控制'、
   剪枝负责'每轮瘦身'——两者配合才是完整方案"
```

## 6. 易错点与面试要点

### 6.1 易错点

| # | 易错点 | 正确写法 | 后果 |
|:---:|------|------|------|
| 1 | 埃及分数分母下界错 | `ceil(b/a)` 起步 | 漏解/负分数 |
| 2 | 埃及分数可行性剪枝忘 | `(maxDepth−depth)·b < a·x` 剪 | 指数爆炸 |
| 3 | IDA* 忘防回退 | 记录上一步反向跳过 | 分支翻倍 |
| 4 | IDA* 阈值更新错 | 用最小超限 f | 阈值不收敛 |
| 5 | 骑士忘回溯 | board 复原 | 状态污染 |
| 6 | 排序剪枝理解错 | 调顺序不砍分支 | 误删分支 |
| 7 | 阈值从 1 开始 | 从 h(start) 开始 | 浅层白搜 |

### 6.2 面试要点

```text
① 为什么迭代加深: "答案深度小 + 空间 O(d)"
② 重搜论证: "浅层重搜代价 ≈ 最后一层（几何级数）"
③ IDA* vs A*: "A* 优先队列 vs IDA* DFS 栈——内存换时间"
④ 剪枝配合: "可行性/防回退/排序——每轮瘦身"

⚠️ 高频追问: "迭代加深一定比 BFS 好吗？"
  → "看需求——空间紧 → 迭代加深（O(d) vs O(b^d)）；
    时间紧且空间够 → BFS/双向 BFS 更快"
```

> 🎯 **核心要点**：迭代加深题解通关——**埃及分数（可行性剪枝）+ 15 数码 IDA*（防回退）+ 骑士（Warnsdorff 排序）**。三题覆盖"加深 × 三类剪枝"的组合——"深度控制 + 每轮瘦身"，就是迭代加深家族的完整方案。
