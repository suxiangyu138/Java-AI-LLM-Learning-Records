## 1. 8 数码问题（A* 经典案例）

### 1.1 题目与思路

**题**：3×3 拼图（0 为空格）归位的最少步数。

**A* + 曼哈顿启发式**：

```java
/**
 * 8 数码（A* 完整实现）
 * 状态: 棋盘序列化字符串；启发式: 曼哈顿距离
 */
int solve8Puzzle(String start) {
    String target = "123456780";                 // ① 目标态
    if (start.equals(target)) return 0;

    // ② 0 的邻居（3×3）
    int[][] neighbors = {
        {1, 3}, {0, 2, 4}, {1, 5},
        {0, 4, 6}, {1, 3, 5, 7}, {2, 4, 8},
        {3, 7}, {4, 6, 8}, {5, 7}
    };

    // ③ 优先队列按 f = g + h 排序
    PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[0] - b[0]);
    Map<String, Integer> gScore = new HashMap<>();
    gScore.put(start, 0);
    pq.offer(new int[]{manhattan(start), 0, 0}); // [f, g, 状态序号?]

    // ⚠️ 完整实现需要状态 ↔ 序号映射（或用 Map<String, int[]> 存 f/g）
    // 核心流程: 弹 f 最小 → 到达目标返回 → 生成邻居（0 交换）→ 更新 g → 入队
    // 启发式: manhattan(state) = Σ 每格到目标位的曼哈顿距离（admissible）

    return -1;                                   // 无解（8 数码奇偶性判断可先验）
}
// ⚠️ 8 数码无解判定: 逆序数奇偶性（偶数逆序才有解）——
//   面试可提"先判可解性再搜索"
```

### 1.2 8 数码面试要点

```text
① 状态编码: 序列化字符串（可哈希）
② 启发式: 曼哈顿距离（每格 |行差|+|列差| 之和）
   admissible ✓（每步移动一格 → 实际步数 ≥ 曼哈顿）
③ 可解性: 逆序数奇偶性（偶数可解）
④ 复杂度: 状态 9!/2 ≈ 18 万——A* 通常秒级

⚠️ 面试表达:
  "8 数码是 A* 的经典案例——状态 18 万、
   曼哈顿启发式 admissible、
   优先队列按 f=g+h 扩展"
```

> 🎯 **8 数码的面试价值**："**8 数码 = A* 的'Hello World'——状态编码 + 曼哈顿启发式 + f 排序三件套全演示**。面试考 A* 必提 8 数码，'为什么曼哈顿 admissible'是必答细节。"

## 2. 迷宫最短路径：BFS vs A* 对比

### 2.1 同一问题的双解

```java
/**
 * 迷宫最短路径——BFS vs A* 对比
 * BFS: 单位代价最短路（O(b^d)，无信息）
 * A*: 曼哈顿引导（启发式好时搜索量小）
 */
// BFS 版（01 模板）: 队列按层扩展——简单但探索所有方向
// A* 版（01 模板）: 优先队列按 g+h——优先往终点方向走

// ⚠️ 对比结论:
//   小迷宫: 两者几乎一样（BFS 更简单）
//   大迷宫: A* 探索量显著更小（启发式导向）
//   障碍迷宫: 曼哈顿仍 admissible（障碍只会让路径更长）✓
```

### 2.2 对比表

| 维度 | BFS | A* |
|------|:---:|:---:|
| 排序键 | 层数 | g + h |
| 信息 | 无 | 启发式 |
| 小迷宫 | ✅ 简单 | 同效 |
| 大迷宫 | 探索多 | **探索少** |
| 最优性 | ✔ | ✔（admissible） |
| 实现 | 简单 | 优先队列 + 启发式 |

> 💡 **选型**："**迷宫小 → BFS（简单够用）；迷宫大 + 启发式可用 → A***。面试先写 BFS 保底，追问'迷宫很大怎么办'再升级 A*——'从 BFS 到 A* 只换排序键'是优雅的升级路径。"

## 3. 启发式设计实战：曼哈顿 vs 欧氏

### 3.1 两种启发式对比

```java
// 曼哈顿距离（网格常用，admissible）
int manhattan(int[] a, int[] b) {
    return Math.abs(a[0] - b[0]) + Math.abs(a[1] - b[1]);
}

// 欧氏距离（直线距离——也 admissible 但信息更少）
int euclidean(int[] a, int[] b) {
    int dx = a[0] - b[0], dy = a[1] - b[1];
    return (int) Math.sqrt(dx * dx + dy * dy);
}

// 对角距离（允许斜走时: max(|dx|, |dy|)——Chebyshev）

// ⚠️ 对比:
//   曼哈顿 ≥ 欧氏（网格移动只能走直线 → 曼哈顿更接近真实）
//   h 越大（信息越多）→ 搜索越少
//   但 h 必须 admissible（≤ 真实）——曼哈顿/欧氏都满足
```

### 3.2 启发式设计原则

```text
① admissible: h ≤ 真实剩余（不低估）
② 信息量: 越接近真实越好（但计算成本要低）
③ 常见设计: 曼哈顿（网格）、欧氏（任意）、对角（斜走）

⚠️ 面试表达:
  "启发式要在'信息量'与'计算成本'间权衡——
   曼哈顿 O(1) 且 admissible → 网格标配；
   更精确的启发式（如模式数据库）搜索更少但预处理贵"
```

> 🎯 **启发式的设计哲学**："**'admissible 是底线、信息量是追求、成本是约束'——好启发式 = 接近真实且便宜**。面试能讲'为什么曼哈顿优于欧氏'（网格移动下的信息量），启发式设计就及格了。"

## 5. 算法家族对比

| 算法 | 排序键 | 最优性 | 信息 | 适用 |
|------|:---:|:---:|:---:|------|
| BFS | 层数 | ✔（单位代价） | 无 | 单位代价最短路 |
| Dijkstra | g | ✔ | 无 | 带权最短路 |
| 贪心最佳优先 | h | ✘ | 有 | 快速但不保证最优 |
| A* | g + h | ✔（admissible） | 有 | 带权 + 启发式 |

```text
⚠️ 家族谱系:
  BFS ⊂ Dijkstra ⊂ A*（信息逐渐增强）
  贪心最佳优先 = A* 去掉 g（只按 h——快但不优）
```

## 6. 易错点与面试要点

### 6.1 易错点

| # | 易错点 | 正确写法 | 后果 |
|:---:|------|------|------|
| 1 | 8 数码不判可解性 | 逆序数奇偶性预判 | 白搜 |
| 2 | 启发式高估 | 保守（admissible） | 丢最优 |
| 3 | 队列按 g 排序 | 按 g + h | 退化 Dijkstra |
| 4 | 状态编码不可哈希 | 字符串/整数编码 | 集合/Map 失效 |
| 5 | 忘过期跳过 | `cost > g` continue | 重复扩展 |
| 6 | 欧氏当曼哈顿 | 网格用曼哈顿（信息更多） | 搜索偏多 |
| 7 | 8 数码无解硬搜 | 先判可解 | 白算/超时 |

### 6.2 面试要点

```text
① 开场: "A* = Dijkstra + 启发式——f = g + h"
② admissible 论证: "曼哈顿 ≤ 真实（每步移一格）"
③ 与 BFS 关系: "h=0 退化；单位代价 + h=0 = BFS"
④ 复杂度: "理论指数、启发式好时接近线性"

⚠️ 高频追问: "A* 什么时候不是最优？"
  → "h 高估（非 admissible）时——高估会让 A* 放弃
    可能更优的路径；保守估计（下界）才保证最优"
```

> 🎯 **核心要点**：A* 题解通关——**8 数码（状态编码 + 曼哈顿 + 可解性）+ 迷宫对比（BFS→A* 升级）+ 启发式设计（admissible/信息量/成本）**。A* 是"有方向的搜索"——'g 管已走、h 管预估、f 管排序'，三合一就是 A* 的全部。
