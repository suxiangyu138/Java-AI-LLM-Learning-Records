## 1. 启发式搜索模型：用信息换搜索量

```text
问题: 大状态空间找最优路径（8 数码、迷宫最短路）
BFS/Dijkstra: 无差别探索（不知道"哪个方向更接近目标"）
A*: 用"启发式信息"引导搜索方向——
  优先扩展"看起来最接近目标"的状态

类比: 出门找路——
  BFS: 东南西北都走一遍再判断
  A*: 看一眼地图（启发式）先往目标方向走

⚠️ 核心: 启发式 = 对"剩余距离"的估计——
  估计越好（越接近真实）→ 搜索越少
  估计不能"太乐观"（不低估）→ 否则可能错过最优
```

> 🎯 **核心认知**："**A* = '有方向的 Dijkstra'——启发式 h 告诉搜索'目标在哪边'，优先往那边走**。'估计的质量决定搜索量'，'不低估保证最优'——两个性质是 A* 的全部理论。"

## 2. 估价函数：f = g + h

### 2.1 三要素

```text
f(n) = g(n) + h(n)
  g(n): 从起点到 n 的已走实际成本
  h(n): 从 n 到终点的预估剩余成本（启发式）
  f(n): n 的总预估成本（排序键）

扩展规则: 每次从 open 表取 f 最小的状态扩展
  → 先扩展"总预估最小"的 → 搜索向目标方向推进

⚠️ 启发式设计（8 数码）:
  曼哈顿距离: h = Σ|行差| + |列差|（每个方块到目标位）
  不低估: 每步移动至少改变 1 个方块 1 格 → 曼哈顿是下界 ✓
  比 h=0（Dijkstra）信息多 → 搜索更少
```

### 2.2 启发式的质量

```text
h 越大（信息越多）→ 搜索越少，但计算 h 的成本越高
h = 0 → Dijkstra（无信息，最稳）
h = 真实值 → 完美启发（直线到达，几乎不搜）
h 过高（高估）→ 可能丢最优解（非 admissible）

⚠️ 权衡: "h 的精度 vs 计算成本——
   曼哈顿距离 O(1) 且 admissible → 8 数码的标准选择"
```

> 🎯 **f = g + h 的直觉**："**g 管'已经花了多少'、h 管'还要花多少'——f 最小 = '这条路总成本看起来最低'**。A* 每次走'总预估最小'的路，方向自然偏向目标。"

## 3. admissible 与 consistent：最优性前提

### 3.1 admissible（可采纳）

```text
定义: h(n) ≤ 真实剩余成本（从 n 到终点）
  → h 不"低估"真实代价（保守估计）

直觉: 预估不能比实际"更乐观"——
  实际要走 5 步，预估 ≤ 5 才对
  预估 3 步（高估）→ 可能错过真实最优路径

⚠️ 为什么低估才行:
  高估时 A* 可能"以为某条路很贵"而放弃它——
  但那可能是唯一的最优路 → 丢最优
  低估（保守）→ 不会放弃任何可能更优的路

例: 8 数码曼哈顿距离 ≤ 真实步数 ✓ admissible
```

### 3.2 consistent（一致性）

```text
定义: h(n) ≤ c(n, m) + h(m)（对任意边 n→m）
  → 三角形不等式（启发式沿边不剧增）

consistent ⇒ admissible（更强的条件）
consistent 下: A* 每个状态首次出 open 即最优（无需重开）
  → 实现更简单（visited 即可，不用降级更新）

⚠️ 面试表达:
  "admissible（不低估）保证最优；
   consistent（三角不等式）让实现简单——
   曼哈顿距离两者都满足（网格场景）"
```

> 🎯 **最优性的钥匙**："**'不低估'（admissible）是 A* 最优的充分条件——h 保守，任何可能更优的路都不会被丢弃**。'consistent 更强'让实现免降级更新，面试两个概念都能讲 = 深度。"

## 4. A* 与 BFS/Dijkstra 的关系

### 4.1 统一视角

```text
BFS:      f = 层数（g 恒为层数，h = 0）——单位代价
Dijkstra: f = g（h = 0）——带权最短路
A*:       f = g + h（h ≠ 0）——带权 + 启发式

关系:
  A*(h=0) = Dijkstra
  Dijkstra(单位代价) = BFS
  → A* 是 BFS/Dijkstra 的"信息增强版"

⚠️ 面试表达:
  "A* 是 Dijkstra 的推广——Dijkstra 用 g 排序、
   A* 用 g+h 排序；h=0 时 A* 就是 Dijkstra"
```

### 4.2 完备性与最优性

```text
完备性: 有解必找到（图有限 + 不无限循环）
最优性: 一致启发式下必找到最优解

⚠️ 复杂度: 时间/空间均指数级（最坏）——
  启发式好时实际接近 O(b^(d/2))~O(b^d)
  面试: 讲"理论上指数、实际启发式越好越快"
```

## 5. A* 模板（优先队列）

### 5.1 核心模板（网格最短路）

```java
/**
 * A* 模板（网格最短路径）
 * f = g + h，优先队列按 f 排序
 */
int aStar(int[][] grid, int[] start, int[] end) {
    int m = grid.length, n = grid[0].length;
    // ① 优先队列: 按 f 排序（[f, g, i, j]）
    PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[0] - b[0]);
    int[][] g = new int[m][n];
    for (int[] row : g) Arrays.fill(row, Integer.MAX_VALUE);

    g[start[0]][start[1]] = 0;
    pq.offer(new int[]{heuristic(start, end), 0, start[0], start[1]});

    int[][] dirs = {{0,1},{0,-1},{1,0},{-1,0}};
    while (!pq.isEmpty()) {
        int[] cur = pq.poll();
        int f = cur[0], cost = cur[1], i = cur[2], j = cur[3];
        if (i == end[0] && j == end[1]) return cost;    // ② 到达终点
        if (cost > g[i][j]) continue;                   // ③ 过期条目跳过

        for (int[] d : dirs) {
            int ni = i + d[0], nj = j + d[1];
            if (ni < 0 || ni >= m || nj < 0 || nj >= n) continue;
            if (grid[ni][nj] == 障碍) continue;
            int newCost = cost + 1;                     // ④ 新 g
            if (newCost < g[ni][nj]) {                  // ⑤ 更优 → 更新
                g[ni][nj] = newCost;
                pq.offer(new int[]{newCost + heuristic(new int[]{ni, nj}, end),
                                    newCost, ni, nj});
            }
        }
    }
    return -1;
}

// 启发式: 曼哈顿距离（admissible）
int heuristic(int[] a, int[] b) {
    return Math.abs(a[0] - b[0]) + Math.abs(a[1] - b[1]);
}
// ⚠️ 模板四要素: 优先队列按 f、g 数组防重、过期跳过、启发式函数
```

### 5.2 模板要点

```text
四要素: ① 优先队列（f 排序）② g 数组（防重/更新）
        ③ 过期条目跳过 ④ 启发式 h

⚠️ 与 Dijkstra 的差异: 队列排序键从 g 变成 g+h——
  其他（g 数组、过期跳过）完全一致！

记忆: "Dijkstra + 启发式 = A*"
```

> 🎯 **模板的灵魂**："**A* = Dijkstra 换排序键（g → g+h）——其余结构完全一致**。'会 Dijkstra 就会 A*'是面试的自信表达，也是 A* 学习的捷径。"

## 6. 识别信号与易错点

### 6.1 识别信号

```text
"最优路径 + 可设计启发式" → A*（8 数码、迷宫）
"状态空间大 + 启发式可用" → A*
"带权图最短路 + 想更快" → A*（h 不低估）

⚠️ 面试定位: A* 面试出现率中等——
  8 数码是经典案例；工程（游戏寻路）是谈资
```

### 6.2 易错点

| # | 易错点 | 正确写法 | 后果 |
|:---:|------|------|------|
| 1 | h 高估（非 admissible） | 保守估计（下界） | 丢最优解 |
| 2 | 队列按 g 排序 | 按 f = g + h | 退化为 Dijkstra |
| 3 | 忘过期条目跳过 | `cost > g[i][j]` continue | 重复扩展 |
| 4 | 障碍判断漏 | grid 检查 | 走入障碍 |
| 5 | 启发式计算错 | 曼哈顿/欧氏选对 | 不低估失效 |
| 6 | g 数组忘初始化 | MAX_VALUE | 更新失效 |
| 7 | 边界检查位置 | 越界先判 | 越界崩溃 |

> 🎯 **核心要点**：A* 通关四件事——**① f = g + h 语义**（已走 + 预估）；**② admissible 前提**（不低估保最优）；**③ 与 Dijkstra 关系**（h=0 退化）；**④ 模板四要素**（优先队列/g 数组/过期跳过/启发式）。**A* = '有方向的 Dijkstra'——'启发式保守、方向偏向目标'十个字，就是 A* 的全部哲学**。
