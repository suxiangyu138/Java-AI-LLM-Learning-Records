## 1. 剪枝的本质：提前掉头

```text
搜索的本质: 遍历决策树的所有分支
剪枝: 在进入分支前判断"这条路走不通/不优" → 提前掉头

类比: 迷宫中看到"死胡同标志"就不进去——
  而不是走进去再退出来

⚠️ 核心: 剪枝不减"最优解"只减"搜索量"——
  正确剪枝 = 被剪的分支必然无解/必然不优

复杂度影响:
  理论最坏不变（O(b^d) 是最坏上界）
  实际搜索量大幅下降（平均情况远小于最坏）

⚠️ 判断: "被剪的分支必然无解吗？"
  是 → 安全剪枝；可能无解 → 会丢解（错误剪枝！）
```

> 🎯 **核心认知**："**剪枝 = '提前知道走不通'——在进入分支前用判据掉头**。正确性铁律：被剪的分支必须'必然无解/必然不优'，'可能'不行（会丢解）。"

## 2. 剪枝分类全景

| 剪枝 | 判据 | 例子 |
|------|------|------|
| 可行性剪枝 | 必然无解 | 剩余项数不够（埃及分数） |
| 最优性剪枝 | 必然不优 | 当前已 ≥ 已知最优 |
| 排序剪枝 | 调顺序不砍 | Warnsdorff 先走受限 |
| 重复剪枝 | 同状态已探索 | visited / 记忆化 |
| 搜索位置剪枝 | 起点限制 | 组合的 startIndex（防重复组合） |
| 层数剪枝 | 深度超限 | 迭代加深的阈值 |
| 逆向剪枝 | 对称操作 | 防回退（上一步反向） |
| 枚举剪枝 | 范围收窄 | 上/下界推导 |

```text
⚠️ 主线: 三大类——
  砍分支: 可行性 + 最优性（最常用）
  调顺序: 排序剪枝（不减量只加速）
  去重复: 重复剪枝 = 记忆化（1. 子目录已讲）
```

> 🎯 **分类的价值**："**剪枝不是玄学——可行性/最优性/排序/重复/搜索位置五类各有判据**。面试讲剪枝按类展开，比'加几个剪枝'显专业。"

## 3. 可行性剪枝：必然无解

### 3.1 原理与模板

```java
/**
 * 可行性剪枝模板: 递归开头判断"必然无解"
 */
boolean dfs(状态) {
    if (必然无解(状态)) return false;            // ① 可行性剪枝（最前置）
    if (到达目标) return true;

    for (后继 : 分支) {
        if (可行性检查(后继)) continue;           // ② 分支级剪枝
        if (dfs(后继)) return true;
    }
    return false;
}
// 例: 埃及分数 "剩余项数 × 最大项 < 剩余分数" → 必然拆不完
// 例: 数独 "某空格无可填数字" → 必然无解
// 例: N皇后 "位置冲突" → 必然不合法
```

### 3.2 常见可行性判据

```text
① 资源不足: 剩余步数/项数/容量不够
② 约束冲突: 位置占用、数字重复、条件不满足
③ 边界越界: 坐标/索引出界
④ 数学下界: 剩余能达到的最大值 < 目标

⚠️ 面试表达:
  "可行性剪枝 = 在递归开头判断'这条路必然无解'——
   判据要'必然'而非'可能'"
```

> 🎯 **可行性剪枝的定位**："**可行性剪枝是最基础的剪枝——'必然无解'判据放在递归最前置**。N 皇后的列/对角线检查、数独的冲突检查、埃及分数的项数下界，全是它。"

## 4. 最优性剪枝：必然不优

### 4.1 原理与模板

```java
/**
 * 最优性剪枝模板（求最小值）
 * 当前已 ≥ 已知最优 → 继续只会更差 → 剪
 */
int best = Integer.MAX_VALUE;                    // ① 全局已知最优

void dfs(状态, int currentCost) {
    if (currentCost >= best) return;             // ② ⚠️ 最优性剪枝
    if (到达目标) {
        best = Math.min(best, currentCost);      // ③ 更新最优
        return;
    }
    for (后继 : 分支) {
        dfs(后继, currentCost + 代价(后继));
    }
}
// 例: 最短路径搜索——已走距离 ≥ 已知最短 → 剪
// 例: 最小代价分割——当前代价 ≥ 已知最优 → 剪
// 例: 旅行商分支限界——当前路径 ≥ 已知最优 → 剪
```

### 4.2 与可行性剪枝的区别

```text
可行性: 必然无解（连解都不是）→ 砍
最优性: 有解但必然不优（比已知差）→ 砍

⚠️ 最优性剪枝依赖"已知最优"——
  越早找到好解，剪枝越有效
  → 常配合排序剪枝（先搜可能更好的分支）

记忆: "可行性管'有没有'、最优性管'好不好'"
```

> 🎯 **最优性剪枝的依赖**："**最优性剪枝 = '当前已 ≥ 已知最优就剪'——它依赖'已知最优'的质量**。先搜好分支（排序剪枝）→ 早得优解 → 剪枝更狠，两者是黄金搭档。"

## 5. 排序与搜索位置剪枝

### 5.1 排序剪枝（调顺序不砍量）

```java
/**
 * 排序剪枝: 改变分支搜索顺序——
 * 先试"最可能成功/最可能最优"的分支
 */
void dfs(状态) {
    List<分支> candidates = 生成候选();
    // ⚠️ 排序: 按"成功概率/上限"排序
    candidates.sort(按启发式排序);
    for (分支 : candidates) { ... }
}
// 例: Warnsdorff 骑士（先走后继最少的）
// 例: 背包分支限界（按价值密度排序）
// 例: 数独（先填约束最多的格）

// ⚠️ 本质: 不减搜索量、只减"无效探索"——
//   先试对的 → 早找到解 → 配合最优性剪枝更狠
```

### 5.2 搜索位置剪枝（起点限制）

```java
/**
 * 搜索位置剪枝: 记录上一层位置，下一层只搜"之后"的
 * 例: 组合问题 startIndex（防 [1,2] 与 [2,1] 重复）
 */
void dfs(列表, int start) {                       // ① 起点参数
    for (int i = start; i < n; i++) {             // ② 只搜 start 之后
        // ⚠️ 等价剪枝: 组合的对称性（顺序无关）→ 起点限制
        // 例: 子集/组合/分割（回溯专题的 startIndex 本质就是它）
    }
}
// 记忆: "顺序无关的组合 → 起点限制（startIndex）；
//   顺序相关的排列 → 用 used 标记（不能剪起点）"
```

> 💡 **两类剪枝的定位**："**排序剪枝 '不减量只加速'（先试对的）、搜索位置剪枝 '利用对称性减量'（组合起点限制）**——一个是顺序优化、一个是结构优化。"

## 6. 剪枝正确性三问

### 6.1 三问自查

```text
① 被剪的分支必然无解/必然不优吗？
   → 是 → 安全；可能 → 丢解（错误剪枝！）

② 剪枝会丢最优解吗？
   → 任何最优解都不在被剪分支 → 正确

③ 剪枝位置够早吗？
   → 检查越靠前，搜索树越瘦（前置优先）

⚠️ 常见错误: 用"可能无解"的判据剪枝——
  例: 排序后"当前和已 > target"却用 continue 而非 break
  → 后续可能有更小的数（未排序）→ 丢解！

测试: 小数据对拍（带剪枝 vs 不带剪枝结果一致）
```

### 6.2 剪枝的工程流程

```text
① 先写朴素搜索（验证正确性）
② 加可行性剪枝（必然无解）
③ 加最优性剪枝（配合排序剪枝）
④ 对拍验证（剪枝前后结果一致）

⚠️ 竞赛铁律: "剪枝是优化不是改答案——
   剪枝前后结果必须完全一致（对拍验证）"
```

> 🎯 **核心要点**：剪枝通关四件事——**① 正确性铁律**（必然无解/不优才剪）；**② 五类全景**（可行性/最优性/排序/重复/搜索位置）；**③ 两大主线**（砍分支 + 调顺序）；**④ 对拍验证**。**剪枝 = '提前知道走不通'——'必然'二字是全部判据的底线，也是正确与错误剪枝的分界线**。
