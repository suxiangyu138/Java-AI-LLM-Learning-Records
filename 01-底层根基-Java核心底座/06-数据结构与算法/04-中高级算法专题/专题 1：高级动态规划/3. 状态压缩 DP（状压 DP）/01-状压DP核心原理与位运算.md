## 1. 状压 DP 模型：位掩码 = 集合

```text
状态压缩: 用整数的二进制位表示"集合"——
  第 i 位 = 1 → 元素 i 已被选/访问
  mask = 0b1011 → {0, 1, 3} 已被选

为什么能压:
  集合状态无法用数组下标直接表示 →
  用整数编码 → dp[mask] 或 dp[mask][i] 可索引

⚠️ 前提: 元素数 N ≤ 20——
  2²⁰ ≈ 100 万状态可行；2³⁰ ≈ 10 亿爆内存

适用: 子集/指派/遍历全部节点/博弈状态
  例: TSP、464 我能赢吗、847 访问所有节点、526 优美排列
```

> 🎯 **核心认知**："**状压 DP = '把集合装进整数'——mask 的每一位是一个元素的'选/不选'**。它把'无法索引的集合状态'变成'可索引的整数状态'，代价是 2ⁿ 的状态数（N ≤ 20 前提）。"

## 2. 位运算三件套与子集枚举

### 2.1 三件套

```java
// ① 加入元素: mask | (1 << i)
int add = mask | (1 << i);

// ② 检查元素: (mask >> i) & 1
boolean has = ((mask >> i) & 1) == 1;

// ③ 移除元素: mask & ~(1 << i)
int remove = mask & ~(1 << i);

// 额外: 元素个数: Integer.bitCount(mask)
//      全集: (1 << n) − 1
```

### 2.2 子集枚举（O(3ⁿ)）

```java
// 枚举 mask 的所有子集（sub 从 mask 递减）
for (int sub = mask; sub > 0; sub = (sub - 1) & mask) {
    // 处理子集 sub
}
// ⚠️ (sub−1) & mask 技巧: 跳过非 mask 子集——
//   所有 (mask, sub) 对总数 = 3ⁿ（每个元素三种状态: 在 mask 不在 sub/都在/都不在）
```

> 🎯 **位运算纪律**："**'加入/检查/移除'三件套是状压的全部位操作**——写错一位就全错，面试先默写三件套再写 DP。子集枚举的 `(sub−1) & mask` 是竞赛技巧，面试 TSP 用不到。"

## 3. TSP 模型：dp[mask][i]

### 3.1 题目与思路

**题**：旅行商——从 0 出发访问所有节点恰好一次并返回的最短路径。

**状态**：`dp[mask][i]` = 已访问 mask、当前在 i 的最短距离：

```java
/**
 * TSP（旅行商）——状压 DP 母题
 * dp[mask][i] = 已访问 mask、当前在 i 的最短路径
 * 转移: 从 i 走到未访问的 j → dp[mask|1<<j][j]
 * 时间 O(n²·2ⁿ)，空间 O(n·2ⁿ)
 */
int tsp(int[][] dist) {
    int n = dist.length;
    int full = (1 << n) - 1;                     // ① 全集
    int[][] dp = new int[1 << n][n];
    for (int[] row : dp) Arrays.fill(row, Integer.MAX_VALUE / 2);
    dp[1][0] = 0;                                // ② 起点: 只访问 0

    for (int mask = 1; mask <= full; mask++) {
        for (int i = 0; i < n; i++) {
            if (dp[mask][i] == Integer.MAX_VALUE / 2) continue;
            for (int j = 0; j < n; j++) {        // ③ 走向未访问的 j
                if (((mask >> j) & 1) == 1) continue;   // 已访问跳过
                int nextMask = mask | (1 << j);
                dp[nextMask][j] = Math.min(dp[nextMask][j],
                    dp[mask][i] + dist[i][j]);
            }
        }
    }
    // ④ 返回起点: min(dp[full][i] + dist[i][0])
    int best = Integer.MAX_VALUE;
    for (int i = 1; i < n; i++)
        best = Math.min(best, dp[full][i] + dist[i][0]);
    return best;
}
// 复杂度: O(n²·2ⁿ) vs 暴力 O(n!)——n=15 时快约 10¹⁰ 倍！
// ⚠️ 面试 n 通常 ≤ 15（2¹⁵×15 ≈ 50 万状态）
```

> 🎯 **TSP 的模板地位**："**TSP = 状压 DP 的母题——'dp[mask][i] = 已访问集合 + 当前位置'**。847 访问所有节点、943 最短超级串都是它的换皮，会 TSP 就会一族题。"

## 4. 状态设计：mask + 当前位置

### 4.1 为什么需要两个维度

```text
只 dp[mask]: 无法知道"下一步能从哪走"——
  最短路径依赖"当前在哪个节点"

dp[mask][i]: mask 记"访问了谁"、i 记"现在在哪"——
  转移: 从 i 走到 j（j 未访问）→ 完整描述决策

⚠️ 何时需要第二维:
  "下一步决策依赖当前位置" → 加 i 维（TSP）
  "只关心集合本身" → dp[mask] 即可（464 博弈）

判断口诀: "下一步从'哪'走 → 需要位置维；
           只问'集合状态' → mask 一维够"
```

### 4.2 464 我能赢吗（mask 一维博弈）

```java
/**
 * LeetCode 464. 我能赢吗
 * dp[mask] = 该状态先手能否赢（Boolean 三态缓存）
 * 转移: 任一选择让对手必输 → 本状态必赢
 */
public boolean canIWin(int maxChoosableInteger, int desiredTotal) {
    int sum = (1 + maxChoosableInteger) * maxChoosableInteger / 2;
    if (sum < desiredTotal) return false;        // ① 总和不够必输
    return dfs(0, desiredTotal, maxChoosableInteger,
               new Boolean[1 << maxChoosableInteger]);
}

private boolean dfs(int mask, int remain, int max, Boolean[] memo) {
    if (memo[mask] != null) return memo[mask];
    for (int i = 1; i <= max; i++) {
        if (((mask >> (i - 1)) & 1) == 1) continue;   // ② 已选跳过
        if (i >= remain) return memo[mask] = true;    // ③ 直接赢
        // ④ 选 i 后对手必输 → 本状态赢
        if (!dfs(mask | (1 << (i - 1)), remain - i, max, memo))
            return memo[mask] = true;
    }
    return memo[mask] = false;
}
// ⚠️ 博弈状压: mask 记"选过的数字集合"，Boolean 三态缓存
//   （0/1/2 语义与 DFS 三色同源）
```

## 5. 规模意识：为什么 N ≤ 20

### 5.1 规模对照

| N | 2ⁿ 状态 | × n（TSP） | 可行性 |
|:---:|:---:|:---:|:---:|
| 10 | 1024 | 10K | ✅ 轻松 |
| 15 | 32K | 500K | ✅ 面试上限 |
| 20 | 100 万 | 2000 万 | ⚠️ 极限（内存 160MB+） |
| 25 | 3300 万 | 8 亿 | ❌ 不可行 |

```text
⚠️ 面试表达:
  "这题 N=20 以下 → 状压可行（2²⁰ × 20 ≈ 2000 万状态）；
   提出方案前先确认规模——N > 20 换思路（贪心/搜索）"
```

### 5.2 空间优化

```text
TSP 空间: O(n·2ⁿ)（int[1<<n][n]）
  n=15 → 32K × 15 × 4B ≈ 2MB ✓
  n=20 → 100 万 × 20 × 4B ≈ 80MB ⚠️

优化: 只保留上一层 mask（滚动）——但 TSP 依赖任意 mask，难滚动
  实际: 面试 n ≤ 15 无压力，n=20 提"内存极限"即可
```

## 6. 识别信号与易错点

### 6.1 识别信号

```text
"访问所有/子集/指派 + N ≤ 20" → 状压 DP
"遍历全部节点最短" → TSP（dp[mask][i]）
"博弈 + 数字集合" → 464（dp[mask] 三态）
"排列/组合计数 + 状态约束" → 526 优美排列

⚠️ 判断: "状态是'集合'且无法用下标表示" → 状压
   "N > 20" → 换思路（不是所有集合题都能状压）
```

### 6.2 易错点

| # | 易错点 | 正确写法 | 后果 |
|:---:|------|------|------|
| 1 | 位运算优先级错 | `((mask >> i) & 1) == 1` 加括号 | 逻辑错 |
| 2 | 忘初始化起点 | `dp[1][0] = 0` | 全 MAX 无解 |
| 3 | 转移忘判已访问 | `(mask>>j)&1 == 1` 跳过 | 重复访问 |
| 4 | 溢出用 MAX_VALUE | 用 `MAX_VALUE/2`（防 + 溢出） | 加和溢出变负 |
| 5 | 464 忘总和不判断 | `sum < target` 提前 false | 漏剪枝 |
| 6 | N > 20 硬用 | 先确认规模 | 内存爆 |
| 7 | 子集枚举死循环 | `(sub−1) & mask` 正确递减 | 死循环 |

> 🎯 **核心要点**：状压 DP 通关四件事——**① 位运算三件套**（加入/检查/移除）；**② TSP 母题**（dp[mask][i] + O(n²·2ⁿ)）；**③ 规模意识**（N ≤ 20、面试 ≤ 15）；**④ mask 一维 vs +i 二维**（看"下一步依赖什么"）。**状压是'把集合装进整数'的魔法——N ≤ 20 时 O(n!) 变 O(n²·2ⁿ)，这是压轴题的入场券**。
