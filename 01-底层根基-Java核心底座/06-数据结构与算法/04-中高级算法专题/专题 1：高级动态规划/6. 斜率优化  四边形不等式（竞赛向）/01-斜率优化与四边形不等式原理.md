## 1. DP 优化总览：什么时候需要

```text
DP 优化的目的: 把 O(n²) / O(n³) 降到 O(n log n) / O(n)

常见优化手段:
  ① 滚动数组: 空间优化（O(n²) → O(n)）——多维 DP 已讲
  ② 单调队列: 窗口最值优化（dp 转移取窗口 max/min）
  ③ 四边形不等式: 决策单调性（O(n²) → O(n log n)）
  ④ 斜率优化: 凸包 + 单调队列（O(n²) → O(n)）
  ⑤ 数据结构优化: 线段树/树状数组（动态区间最值）

⚠️ 前提: 转移方程存在"单调性/凸性"结构——
  不是所有 DP 都能优化，先识别结构再选工具

面试 vs 竞赛:
  面试: 斜率优化提及即可（很少手撕）
  竞赛: 蓝桥杯/ACM 必考（石子合并四边形、HDU 3507 斜率）
```

> 🎯 **核心认知**："**DP 优化 = '利用转移结构的单调性'——四边形不等式用'决策点单调'、斜率优化用'候选点凸包'**。识别'转移方程的结构'比背模板重要：O(n²) 的转移有规律可循才值得优化。"

## 2. 决策单调性：优化的前提

### 2.1 什么是决策单调性

```text
决策单调性: 最优决策点随 i 单调移动——
  dp[i] 的最优 k 记为 opt[i]，则 opt[i] 随 i 单调不减

例（一维 DP）:
  dp[i] = min(dp[k] + cost(k, i))  k < i
  若 opt[i] ≤ opt[i+1] → 决策单调 → 可优化

直观: "问题越往后，最优'分界点'越往右"——
  石子合并中合并区间越大，最优分割点越靠后

⚠️ 验证: 打表看 opt[i] 是否单调（小数据验证）
```

### 2.2 为什么单调可优化

```text
决策单调 → 分治/队列维护"决策候选区间":
  ① 四边形不等式法: 每轮只用一部分候选（O(n log n)）
  ② 斜率优化法: 候选点构成凸包，队头即最优（O(n)）
  ③ 分治优化: 决策区间分治递归（O(n log n)）

⚠️ 一句话: "决策单调 = 候选点有序 = 可以用队列/分治维护"
```

> 🎯 **优化的前提**："**'决策单调性'是一切 DP 优化的前提——最优决策点单调移动，候选集才有'滑动窗口'结构**。先验证单调（打表），再选优化工具。"

## 3. 四边形不等式（决策单调性剪枝）

### 3.1 定义与判定

```text
四边形不等式（Quadrangle Inequality）:
  对任意 a ≤ b ≤ c ≤ d:
    w(a,c) + w(b,d) ≤ w(a,d) + w(b,c)   （交叉 ≤ 包含）
  → 满足则区间 DP 的决策单调性成立

常见满足场景:
  代价函数 w(i,j) 满足"凸性"（如区间和、石子合并代价）
  石子合并: w(i,j) = 前缀和差 → 满足四边形不等式

⚠️ 判定口诀: "代价函数'交叉和 ≤ 包含和' → 决策单调"
```

### 3.2 优化效果（石子合并 O(n³) → O(n²)）

```java
// 普通区间 DP: O(n³)（长度 × 起点 × 分割点）
// 四边形优化: 分割点 k 范围收窄到 [opt[i][j-1], opt[i+1][j]]
for (int len = 2; len <= n; len++) {
    for (int i = 0; i + len <= n; i++) {
        int j = i + len - 1;
        // ⚠️ k 只查决策单调区间（原 [i, j) → 收窄）
        for (int k = opt[i][j - 1]; k <= opt[i + 1][j]; k++) {
            ...更新 dp[i][j]，记录 opt[i][j] = 最优 k...
        }
    }
}
// 复杂度: O(n³) → O(n²)（每个区间平均常数个候选）
// ⚠️ 前提: 代价满足四边形不等式——不满足则不能用！
```

> 🎯 **四边形不等式的价值**："**'opt[i][j-1] ≤ k ≤ opt[i+1][j]'把石子合并从 O(n³) 压到 O(n²)**——经典竞赛考点。判定'代价函数凸性'是使用前提，蓝桥/ACM 常考。"

## 4. 斜率优化模型：凸包维护

### 4.1 什么时候用斜率优化

```text
转移方程形如:
  dp[i] = min(dp[j] + a[i]·b[j] + c[j]) + C[i]   （j < i）
  → 展开为: dp[i] = min(斜率·x + 截距) 的形式

具体: 把转移看成"点 (x_j, y_j) 与斜率 k_i 的直线截距":
  dp[i] = min(y_j − k_i · x_j) + C[i]
  其中 x_j = b[j]、y_j = dp[j] + c[j]、k_i = a[i]

→ 问题变成: 求"过所有候选点、斜率为 k_i 的最小截距"
  → 候选点下凸包上的点才可能是最优 → 维护凸包 + 单调队列

⚠️ 前提: k_i 单调（斜率单调递增/递减）——
  → 队头即最优（指针单调移动，O(n)）
```

### 4.2 三步识别

```text
① 展开: 把转移方程展开成"y = k·x + b"形态
② 定参: x/y = 只与 j 有关；k = 只与 i 有关；b = 待最小化
③ 判单: k_i 是否单调？（单调 → 单调队列维护凸包）

⚠️ 例（HDU 3507）:
  dp[i] = min(dp[j] + (sum[i]−sum[j])²) + M
  展开 → y_j = dp[j] + sum[j]²、x_j = sum[j]、k_i = 2·sum[i]
  sum[i] 递增 → k 单调 → 斜率优化可行
```

> 🎯 **斜率优化的本质**："**'把转移看成直线截距——候选点构成凸包，最优解在凸包边界上'**。'k 单调 → 队头最优 → O(n)'是它的全部魔法；识别'能否展开成 y=kx+b'是第一步。"

## 5. 斜率优化模板（单调队列）

### 5.1 核心模板（HDU 3507 石子印钞机）

```java
/**
 * 斜率优化模板（单调队列维护下凸包）
 * dp[i] = min(dp[j] + (sum[i]−sum[j])²) + M
 * 时间 O(n)（每点入队出队各一次）
 */
long[] solve(int[] c, int M) {
    int n = c.length;
    long[] sum = new long[n + 1];
    for (int i = 1; i <= n; i++) sum[i] = sum[i - 1] + c[i - 1];

    long[] dp = new long[n + 1];
    int[] q = new int[n + 1];                    // ① 单调队列（存下标）
    int head = 0, tail = 0;

    // ② 斜率比较函数: (y_j − y_k) / (x_j − x_k) 与 k_i 比较
    // 用叉积避免浮点: (y2−y1)(x3−x2) vs (y3−y2)(x2−x1)
    for (int i = 1; i <= n; i++) {
        // ③ 队头弹出: 队头两点斜率 ≤ k_i → 队头不再最优
        while (head < tail && slope(q[head], q[head + 1]) <= 2 * sum[i])
            head++;
        int j = q[head];                          // ④ 队头 = 最优决策点
        dp[i] = dp[j] + (sum[i] - sum[j]) * (sum[i] - sum[j]) + M;

        // ⑤ 队尾弹出: 新点破坏凸性（斜率不递增）→ 弹出
        while (head < tail && slope(q[tail - 1], q[tail]) >= slope(q[tail], i))
            tail--;
        q[++tail] = i;                            // ⑥ 新点入队
    }
    return dp;
}
// ⚠️ 三部分: 队头出（斜率条件）、队尾进（凸包维护）、叉积比较
//   浮点陷阱: 用叉积（整数乘法）替代除法比较
```

### 5.2 模板三部分

```text
① 队头弹出: 队头斜率 ≤ 当前 k → 队头不再最优（指针前进）
② 取队头: 最优决策点 = 队头（k 单调保证）
③ 队尾维护: 新点使凸包"凹陷" → 弹队尾（保持凸性）

⚠️ 记忆: "头出（斜率条件）、尾进（凸性维护）——
   单调队列 + 叉积比较 = 斜率优化全部"
```

## 6. 识别信号与选型

### 6.1 识别信号

```text
"转移含 i×j 交叉项（a[i]·b[j]）" → 斜率优化
"区间 DP + 代价凸性" → 四边形不等式
"dp 转移取窗口最值" → 单调队列优化
"决策点单调可打表验证" → 分治优化

⚠️ 选型表:
  转移交叉项 + k 单调 → 斜率优化（O(n)）
  区间 DP + 凸代价 → 四边形不等式（O(n²)）
  窗口最值 → 单调队列（O(n)）
```

### 6.2 易错点

| # | 易错点 | 正确写法 | 后果 |
|:---:|------|------|------|
| 1 | 不验证决策单调 | 先打表验证 | 优化出错 |
| 2 | 四边形前提不满足硬用 | 代价凸性判定 | 答案错 |
| 3 | 斜率用除法 | 叉积（整数）比较 | 浮点误差 |
| 4 | k 不单调用单调队列 | 非单调需二分凸包 | 队头非最优 |
| 5 | 队尾凸性维护错 | 新点破坏凸性才弹 | 凸包失效 |
| 6 | 优化后 dp 含义变 | 优化不改变状态定义 | 转移错 |
| 7 | 小数据验证跳过 | 打表对拍普通 DP | 优化 bug 难查 |

> 🎯 **核心要点**：竞赛优化通关四件事——**① 决策单调性是前提**（打表验证）；**② 四边形不等式**（代价凸性 + opt 区间收窄）；**③ 斜率优化三步识别**（展开 y=kx+b、定参、判 k 单调）；**④ 模板三部分**（头出/取头/尾进 + 叉积）。**竞赛向优化是"识别结构 > 背模板"——'决策单调'四个字，就是一切优化的总纲**。
