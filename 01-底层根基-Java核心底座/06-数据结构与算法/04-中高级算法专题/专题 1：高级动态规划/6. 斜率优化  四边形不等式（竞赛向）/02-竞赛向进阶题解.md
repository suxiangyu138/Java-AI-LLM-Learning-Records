## 1. HDU 3507 斜率优化母题

### 1.1 题目与完整实现

**题**：把序列分段，段代价 = (段和)² + M，求最小总代价。

```java
/**
 * HDU 3507 Print Article（斜率优化母题）
 * dp[i] = min(dp[j] + (sum[i]−sum[j])²) + M
 * 展开: dp[i] = min(dp[j] + sum[j]² − 2·sum[i]·sum[j]) + sum[i]² + M
 *      → y_j = dp[j] + sum[j]²、x_j = sum[j]、k = 2·sum[i]
 *      → k 单调递增（sum 递增）→ 单调队列维护下凸包
 */
long solve(int[] c, int M) {
    int n = c.length;
    long[] sum = new long[n + 1];
    for (int i = 1; i <= n; i++) sum[i] = sum[i - 1] + c[i - 1];

    long[] dp = new long[n + 1];
    int[] q = new int[n + 1];                    // 单调队列（存下标）
    int head = 0, tail = 0;                      // 初始: 只有 j=0

    for (int i = 1; i <= n; i++) {
        // ① 队头弹出: 队头两点斜率 ≤ 2·sum[i] → 队头不再最优
        while (head < tail &&
               (dp[q[head+1]] + sum[q[head+1]]*sum[q[head+1]]
              - dp[q[head]] - sum[q[head]]*sum[q[head]])
              <= 2 * sum[i] * (sum[q[head+1]] - sum[q[head]]))
            head++;

        int j = q[head];                         // ② 队头 = 最优决策
        long x = sum[i] - sum[j];
        dp[i] = dp[j] + x * x + M;

        // ③ 队尾维护凸性: 新点使斜率不递增 → 弹出
        while (head < tail && cross(q[tail-1], q[tail], i, sum, dp) <= 0)
            tail--;
        q[++tail] = i;
    }
    return dp[n];
}

// 叉积比较（避免浮点）: 斜率(j,k) ≥ 斜率(k,i) ⇔ 叉积 ≤ 0
private long cross(int a, int b, int c, long[] sum, long[] dp) {
    long ya = dp[a] + sum[a] * sum[a];
    long yb = dp[b] + sum[b] * sum[b];
    long yc = dp[c] + sum[c] * sum[c];
    return (yb - ya) * (sum[c] - sum[b]) - (yc - yb) * (sum[b] - sum[a]);
}
// 推演 [1,2,3], M=5：
//   分段 [1,2,3] → 36+5=41；[1,2]+[3] → 9+5 + 9+5 = 28
//   [1]+[2,3] → 6+5 + 25+5 = 41 → 最优 28（拆 [1,2] 与 [3]）✓
// ⚠️ 核心: 队头弹出用"斜率 ≤ k"（整数比较防浮点）、
//   队尾用叉积 ≤ 0 保持凸性
```

> 🎯 **HDU 3507 的模板地位**："**3507 是斜率优化的'Hello World'——'展开 y=kx+b → 判 k 单调 → 单调队列凸包'三步全演示**。会它，斜率优化家族（任务安排、锯木厂选址）都是换参数。"

## 2. 石子合并四边形不等式优化

### 2.1 优化版实现

```java
/**
 * 石子合并（四边形不等式优化版）
 * 普通 O(n³) → 优化 O(n²)
 * ⚠️ 前提: 代价 w(i,j) = 区间和（满足四边形不等式）
 */
int stoneMergeOptimized(int[] stones) {
    int n = stones.length;
    int[] prefix = new int[n + 1];
    for (int i = 0; i < n; i++) prefix[i + 1] = prefix[i] + stones[i];

    int[][] dp = new int[n][n];
    int[][] opt = new int[n][n];                 // ① 记录最优决策点
    for (int i = 0; i < n; i++) opt[i][i] = i;   // ② 长度 1 的决策点

    for (int len = 2; len <= n; len++) {
        for (int i = 0; i <= n - len; i++) {
            int j = i + len - 1;
            dp[i][j] = Integer.MAX_VALUE;
            // ③ ⚠️ 决策区间收窄: [opt[i][j-1], opt[i+1][j]]
            for (int k = opt[i][j - 1]; k <= opt[i + 1][j]; k++) {
                int cost = dp[i][k] + dp[k + 1][j] + (prefix[j + 1] - prefix[i]);
                if (cost < dp[i][j]) {
                    dp[i][j] = cost;
                    opt[i][j] = k;               // ④ 记录最优决策点
                }
            }
        }
    }
    return dp[0][n - 1];
}
// 推演 [1,2,3] → 6 ✓（与普通版一致——优化不改变答案）
// ⚠️ 优化的核心: opt 数组记录"最优 k"→ 下一轮 k 范围收窄——
//   决策单调性让每个区间平均只查常数个候选
```

> 🎯 **四边形优化的必考点**："**'opt[i][j−1] ≤ k ≤ opt[i+1][j]'的决策区间收窄 + opt 数组记录**——O(n³) 变 O(n²)。'优化不改变答案'是自检原则：小数据对拍普通版。"

## 3. 单调队列优化：窗口最值 DP

### 3.1 模型与模板

```java
/**
 * 单调队列优化 DP
 * 适用: dp[i] = max(dp[i-k..i-1]) + cost[i]（窗口最值转移）
 * 例: 1696 跳跃游戏 VI（dp[i] = max(dp[i-k..i-1]) + nums[i]）
 */
int jumpGameVI(int[] nums, int k) {
    int n = nums.length;
    int[] dp = new int[n];
    Deque<Integer> deque = new ArrayDeque<>();   // 单调递减队列（存下标）
    dp[0] = nums[0];
    deque.offer(0);

    for (int i = 1; i < n; i++) {
        // ① 队头过期: 滑出窗口 [i-k, i-1]
        while (!deque.isEmpty() && deque.peekFirst() < i - k)
            deque.pollFirst();
        dp[i] = dp[deque.peekFirst()] + nums[i]; // ② 队头 = 窗口最大

        // ③ 队尾踢小: 保持单调递减
        while (!deque.isEmpty() && dp[deque.peekLast()] <= dp[i])
            deque.pollLast();
        deque.offerLast(i);
    }
    return dp[n - 1];
}
// 推演 [1,-1,-2,4,-7,3], k=2 → 7 ✓（1→-1→4→3 或 1→-1→4）
// ⚠️ 与 239 滑动窗口最大值同模板——DP 转移套窗口最值
```

> 💡 **单调队列 × DP 的识别**："**'dp[i] 转移取固定窗口的最值' → 单调队列优化 O(n)**——1696/1425 是代表。与斜率优化的区别：单调队列优化的是'窗口最值'、斜率优化的是'凸包截距'。"

| 手段 | 适用 | 效果 | 难度 |
|------|------|:---:|:---:|
| 滚动数组 | 空间超限 | O(n²)→O(n) 空间 | 🟢 |


## 6. 易错点与调试技巧

### 6.1 易错点

| # | 易错点 | 正确写法 | 后果 |
|:---:|------|------|------|
| 1 | 不验证决策单调 | 打表验证 | 优化出错 |
| 2 | 浮点斜率比较 | 叉积整数比较 | 精度错误 |
| 3 | 单调队列头尾混 | 头出（过期/斜率）、尾进（凸性） | 队列失效 |
| 4 | opt 数组忘记录 | 每轮更新 opt | 收窄失效 |
| 5 | 优化后不自检 | 小数据对拍普通 DP | bug 难发现 |
| 6 | 四边形前提不满足 | 代价凸性判定 | 答案错 |
| 7 | k 不单调硬用队列 | 非单调用二分凸包 | 队头非最优 |

### 6.2 调试技巧

```text
① 对拍法: 优化版 vs 普通版——小数据（n ≤ 50）随机对拍
② 打表验证: 打印 opt[i] 检查决策单调性
③ 叉积验证: 打印凸包点检查凸性
④ 复杂度验证: n=10⁵ 计时——O(n) 应毫秒级

⚠️ 竞赛铁律: "优化前后必须对拍——
   优化引入的 bug 比普通 DP 的 bug 难找 10 倍"
```

> 🎯 **核心要点**：竞赛优化题解通关——**3507 母题（展开/凸包/单调队列）+ 石子四边形（opt 收窄）+ 单调队列 DP（1696）**。三类模板 + 对拍自检——"先验证决策单调、再选优化工具、最后对拍验证"，就是竞赛 DP 优化的完整方法论。
