## 1. AC 自动机模型：Trie + fail

```text
问题: 在一段文本中同时匹配 K 个模式串（敏感词过滤）
朴素: 对每个模式串跑 KMP → O(k·(n+m))——k 大时慢
AC 自动机（Aho-Corasick，1975）: O(n + m_total)

核心: Trie（组织模式串集合）+ fail 指针（KMP 的 border 思想）
  Trie: 所有模式串的前缀树（一次建树）
  fail: 当前节点失配时跳到"最长真后缀"所在节点（多模式 border）

类比: KMP 的单模式 border → AC 的 fail（跨模式 border）

⚠️ 复杂度: 建 Trie O(m_total) + fail 构建 O(m_total) + 匹配 O(n)
  vs 逐个 KMP O(k·n)——k 大时优势巨大
```

> 🎯 **核心认知**："**AC 自动机 = 'Trie 组织集合 + fail 处理失配'——KMP 的 border 思想从单模式推广到多模式**。敏感词过滤/多模式匹配是它的主战场，O(n+m) 是它的价值。"

## 2. Trie 构建（多模式集合）

### 2.1 Trie 节点与插入

```java
/**
 * AC 自动机 Trie 构建
 * 节点: children（字符边）+ fail（失配指针）+ count（模式串结尾标记）
 */
class ACAutoNode {
    ACAutoNode[] children = new ACAutoNode[26];  // ① 字符边
    ACAutoNode fail;                             // ② 失配指针
    int count;                                   // ③ 模式串结尾标记
}

void insert(String word) {
    ACAutoNode cur = root;
    for (char c : word.toCharArray()) {
        int idx = c - 'a';
        if (cur.children[idx] == null)
            cur.children[idx] = new ACAutoNode();
        cur = cur.children[idx];
    }
    cur.count++;                                 // ④ 标记模式串结尾
}
// 推演 插入 "he", "she", "his", "hers"：
//   Trie: 根 → h → e(he✓) → r → s(hers✓)
//              → s → h → e(she✓)
//              → i → s(his✓)
// ⚠️ Trie 是 AC 自动机的骨架——模式串集合的组织结构
```

> 💡 **Trie 的角色**："**Trie 把 K 个模式串的公共前缀合并存储——空间 O(m_total)、查询 O(L)**。它是 AC 自动机的骨架，fail 指针是灵魂。"

## 3. fail 指针：多模式的 border

### 3.1 语义

```text
fail 指针: 节点失配时跳转的目标——
  指向"当前路径的最长真后缀"在 Trie 中的节点

例: 路径 "she" 的 fail → 节点 "he"（"she" 的最长真后缀 "he" 在 Trie 中）

⚠️ 与 KMP border 的对应:
  KMP: 已匹配部分的最长 border（单模式内）
  AC: 当前路径的最长真后缀（跨模式——可能是其他模式的前缀）

跳转效果: 失配时不用回到根——
  跳转到"最长真后缀"节点，继续匹配（复用已匹配的后缀）

⚠️ fail 链: 沿 fail 一路跳到根——链上所有节点都是"当前后缀"的模式
  → 匹配时沿 fail 链统计所有命中的模式
```

### 3.2 fail 的构建规则

```text
根的孩子: fail = 根（首字符失配 → 重新开始）
其他节点: fail = 父节点的 fail 沿路找"相同字符的子节点"
  例: 节点 'e'（路径 "she"）的 fail =
      父 'h' 的 fail（"he" 路径）的 'e' 子节点 → "he"

⚠️ 规则: "父 fail 的同字符子节点 = 最长真后缀的目标"
  （与 KMP 的 next 构建同构——父的 border + 匹配字符）
```

> 🎯 **fail 的灵魂**："**fail = '当前路径的最长真后缀所在节点'——失配时跳到它，后缀已匹配、继续比**。与 KMP 的 border 完全同构，只是从'单模式内'扩展到'模式集合间'。"

## 4. fail 构建（BFS）

### 4.1 完整构建

```java
/**
 * fail 指针构建（BFS 层序）
 * 规则: 节点的 fail = 父 fail 的同字符子节点
 */
void buildFail() {
    Queue<ACAutoNode> queue = new LinkedList<>();

    // ① 根的孩子 fail = 根（首字符失配回根）
    for (ACAutoNode child : root.children) {
        if (child != null) {
            child.fail = root;
            queue.offer(child);
        }
    }

    // ② BFS: 逐层构建
    while (!queue.isEmpty()) {
        ACAutoNode cur = queue.poll();
        for (int i = 0; i < 26; i++) {
            ACAutoNode child = cur.children[i];
            if (child == null) continue;

            // ③ 沿父 fail 链找"同字符子节点"
            ACAutoNode f = cur.fail;
            while (f != null && f.children[i] == null) f = f.fail;
            child.fail = (f == null) ? root : f.children[i];

            queue.offer(child);
        }
    }
}
// ⚠️ BFS 保证: 处理节点时父的 fail 已构建（层序）
//   fail 链查找: 沿 fail 向上找同字符（最坏 O(深度)，Trie 图优化见下）
```

> 💡 **BFS 的原因**："**fail 构建必须 BFS——节点的 fail 依赖父的 fail，层序保证依赖先构建**。与树的层序遍历（专题 7 BFS）同构，只是'边'变成 fail 关系。"

## 5. 匹配主流程与 Trie 图

### 5.1 匹配 + fail 链统计

```java
/**
 * 匹配主流程: 沿 Trie 走 + 失配跳 fail + fail 链统计
 */
int match(String text) {
    ACAutoNode cur = root;
    int count = 0;
    for (char c : text.toCharArray()) {
        int idx = c - 'a';
        // ① 失配跳 fail（直到有该字符或到根）
        while (cur != root && cur.children[idx] == null) {
            cur = cur.fail;
        }
        if (cur.children[idx] != null) cur = cur.children[idx];

        // ② 沿 fail 链统计所有命中的模式
        for (ACAutoNode p = cur; p != root && p.count > 0; p = p.fail) {
            count += p.count;                  // ③ 命中计数
            // ⚠️ 敏感词过滤可置 0 防重复计数
        }
    }
    return count;
}
// 推演 text="ushers", 模式 she/he/his/hers：
//   匹配 "she" 后沿 fail 统计 "he"（she 的后缀也是模式）✓
// ⚠️ fail 链统计: 每个命中节点的 fail 链上的模式也命中——
//   这是多模式匹配与单模式 KMP 的核心差异
```

### 5.2 Trie 图优化

```java
// Trie 图: 空儿子直接指向"fail 的同字符儿子"——
//   匹配时无需 while 跳 fail（O(1) 转移）
for (节点 cur) {
    for (i = 0..25) {
        if (cur.children[i] == null)
            cur.children[i] = cur.fail.children[i];   // ① 空儿子补 fail 儿子
        // 否则 fail 构建照常
    }
}
// 效果: 匹配转移 O(1)（无 while 循环）——
//   Trie 图 = Trie + fail 的"确定性自动机"形态
// ⚠️ 匹配时: cur = cur.children[idx]（直接转移，无失配循环）
```

> 🎯 **Trie 图的定位**："**Trie 图 = '空儿子补 fail 儿子'——匹配转移从 while 变 O(1)**。它是 AC 自动机的工程形态（确定性有限自动机 DFA），面试讲清'为什么补空儿子'即可。"

## 6. 识别信号与易错点

### 6.1 识别信号

```text
"多个模式串 + 一段文本 + 匹配/过滤" → AC 自动机
"敏感词过滤/多模式匹配" → AC 自动机
"K 个模式串统计出现" → AC 自动机（HDU 2222 经典）

⚠️ 面试定位: 竞赛/工程向——
  面试提到"AC 自动机 = Trie + fail，O(n+m) 多模式"即可
  手写是竞赛要求
```

### 6.2 易错点

| # | 易错点 | 正确写法 | 后果 |
|:---:|------|------|------|
| 1 | fail 构建用 DFS | BFS（依赖父 fail） | 依赖未建 |
| 2 | 根的孩子 fail 忘设 | fail = root | 首字符失配错 |
| 3 | 匹配忘跳 fail | 失配沿 fail | 漏匹配 |
| 4 | fail 链统计漏 | 每个节点沿链 | 后缀模式漏计 |
| 5 | Trie 图空儿子忘补 | 补 fail 儿子 | 匹配退化 |
| 6 | count 重复计数 | 命中后置 0 | 重复统计 |
| 7 | 数组越界（字符索引） | 统一转 0-25 | 越界 |

> 🎯 **核心要点**：AC 自动机通关四件事——**① 模型**（Trie + fail）；**② fail 语义**（最长真后缀，与 KMP border 同构）；**③ 构建 BFS**（依赖层序）；**④ 匹配 + fail 链统计**（多模式核心差异）。**AC 自动机 = 'Trie 组织 + fail 复用'——'多模式匹配 O(n+m)'一句话，就是它的全部价值**。
