## 1. 核心概念

### 1.1 什么是单调队列

> 单调队列：用**双端队列（Deque）**维护窗口内元素的单调性（递增或递减），队头恒为窗口最值。配合窗口滑动 → O(n)。

```
单调递减队列（维护窗口最大值）：
  入队 5 → [5]
  入队 3 → [5, 3]
  入队 4 → 弹出 3 → [5, 4]   （4 > 3，3 不可能再是最大值）

为什么"比当前小的都弹出"？
  元素 x 比新元素 y 小且 x 在 y 左边（更早过期）：
    y 比 x 大 → x 在窗口内时 y 也在 → 最大值轮不到 x
    y 比 x 晚过期 → y 存活时间覆盖 x
  → x 永久淘汰 ✓
```

### 1.2 识别信号

```
"滑动窗口内最大值/最小值" → 单调队列（239）
"窗口最值 + DP 优化" → 单调队列（1696）
"实时数据流极值" → 单调队列

⚠️ 与普通队列的区别：
  普通队列：FIFO 存全部元素
  单调队列：只保留"可能成为最值"的元素
  → 空间 O(k) 但实际远小于 k
```

### 1.3 为什么是 O(n)

```
每个元素：
  入队恰好 1 次
  出队最多 1 次（被淘汰或过期）
  → 总操作 2n → O(n)

对比暴力：每窗口扫描 k 个 → O(nk)

⚠️ 面试必答：
"每个元素进出队各一次 → O(n)，
 暴力 O(nk) 是它的 k 倍。"
```

## 2. 完整代码模板

### 2.1 239. 滑动窗口最大值（母题）

```java
/**
 * LeetCode 239. 滑动窗口最大值（Hot 100）
 * 单调递减队列（存下标！）三件套：
 *   ① 入队：弹出所有比当前小的（永久淘汰）
 *   ② 过期：队头滑出窗口 → 弹出
 *   ③ 取值：队头 = 当前窗口最大值
 */
public int[] maxSlidingWindow(int[] nums, int k) {
    int n = nums.length;
    int[] result = new int[n - k + 1];
    Deque<Integer> deque = new ArrayDeque<>();   // 存下标！

    for (int i = 0; i < n; i++) {
        // ① 入队：弹出所有比当前小的（不可能再是最大值）
        while (!deque.isEmpty() && nums[deque.peekLast()] < nums[i]) {
            deque.pollLast();
        }
        deque.offerLast(i);

        // ② 过期：滑出窗口的旧下标
        if (deque.peekFirst() <= i - k) {
            deque.pollFirst();
        }

        // ③ 取值：窗口形成后取队头
        if (i >= k - 1) {
            result[i - k + 1] = nums[deque.peekFirst()];
        }
    }
    return result;
}
```

### 2.2 推演：[1, 3, -1, -3, 5, 3, 6, 7], k = 3

```
i=0: 入队 1 → deque=[0(1)]
i=1: 3 > 1 弹出 0 → deque=[1(3)]
i=2: -1 < 3 → deque=[1(3), 2(-1)]；i≥2 → 结果[0]=3
i=3: -3 < -1 → deque=[1(3),2(-1),3(-3)]；结果[1]=3
i=4: 5 弹出 3,2,1 → deque=[4(5)]；结果[2]=5
i=5: 3 < 5 → deque=[4(5),5(3)]；结果[3]=5
i=6: 6 弹出 5,4 → deque=[6(6)]；结果[4]=6
i=7: 7 弹出 6 → deque=[7(7)]；结果[5]=7
结果 [3,3,5,5,6,7] ✓
```

### 2.3 通用模板（最大/最小）

```java
/**
 * 单调队列通用模板（窗口最值）
 * 单调递减 → 队头最大；单调递增 → 队头最小
 */
public int[] slidingWindowExtreme(int[] nums, int k, boolean wantMax) {
    int n = nums.length;
    int[] result = new int[n - k + 1];
    Deque<Integer> deque = new ArrayDeque<>();

    for (int i = 0; i < n; i++) {
        // ① 维护单调性：弹出"比当前弱"的队尾
        while (!deque.isEmpty()) {
            int tailVal = nums[deque.peekLast()];
            boolean shouldPop = wantMax
                ? tailVal < nums[i]     // 求最大：弹出更小的
                : tailVal > nums[i];    // 求最小：弹出更大的
            if (!shouldPop) break;
            deque.pollLast();
        }
        deque.offerLast(i);

        // ② 过期弹出
        if (deque.peekFirst() <= i - k) deque.pollFirst();

        // ③ 取最值
        if (i >= k - 1) result[i - k + 1] = nums[deque.peekFirst()];
    }
    return result;
}
```

## 3. 单调队列的原理

### 3.1 为什么"晚到且大"淘汰"早到且小"

```
元素 x（早到、值小）vs 元素 y（晚到、值大）：
  x 在窗口内时，y 必然也在（y 晚过期）
  y 比 x 大 → 窗口最大值永远是 y 或更晚的
  → x 永远不可能是答案 → 永久淘汰 ✓

关键：两个维度都输（值小 + 早过期）
  → 淘汰是安全的

⚠️ 只淘汰"两个维度都输"的元素
  （值大但早到 → 保留：可能成为新窗口的最大）
```

### 3.2 与单调栈的关系

```
单调栈：无"过期"概念（找下一个更大）
单调队列：有"过期"（窗口滑出）

关系：单调队列 = 单调栈 + 窗口过期处理
  → 多一个"队头过期弹出"步骤

⚠️ 面试对比：
  "单调栈处理'下一个更大'（无过期）；
   单调队列处理'窗口最值'（有过期）。
   两者都用单调性淘汰不可能的元素。"
```

### 3.3 为什么存下标不存值

```
需要判断"过期"：
  队头下标 ≤ i - k → 滑出窗口
  存值无法判断过期时间！

⚠️ 与单调栈相同：
  "需要位置信息 → 存下标"
```

## 4. 单调队列的 DP 优化

### 4.1 问题模式

```
DP 转移需要"窗口内最大值"：
  dp[i] = max(dp[i-1], dp[i-2], ..., dp[i-k]) + cost[i]

暴力：每步扫描窗口 → O(nk)
单调队列：窗口内最大 → O(n)

⚠️ 识别信号：
  "转移需要最近 k 个状态的最大/最小"
  → 单调队列优化
```

### 4.2 1696. 跳跃游戏 VI

```java
/**
 * LeetCode 1696. 跳跃游戏 VI
 * dp[i] = nums[i] + max(dp[i-k..i-1])
 * 单调队列维护 dp 窗口最大值
 */
public int maxResult(int[] nums, int k) {
    int n = nums.length;
    int[] dp = new int[n];
    dp[0] = nums[0];

    // 单调递减队列（存下标，存 dp 值）
    Deque<Integer> deque = new ArrayDeque<>();
    deque.offerLast(0);

    for (int i = 1; i < n; i++) {
        // ① 过期：滑出窗口
        while (!deque.isEmpty() && deque.peekFirst() < i - k) {
            deque.pollFirst();
        }

        // ② 转移：队头 = 窗口内 dp 最大
        dp[i] = nums[i] + dp[deque.peekFirst()];

        // ③ 维护单调：弹出 dp 更小的队尾
        while (!deque.isEmpty() && dp[deque.peekLast()] <= dp[i]) {
            deque.pollLast();
        }
        deque.offerLast(i);
    }
    return dp[n - 1];
}
// O(n)（对比暴力 O(nk)）
// ⚠️ 与 239 的差异：单调性按 dp 值而非 nums
```

### 4.3 DP 优化的通用框架

```
① 识别"窗口最值"依赖：
   dp[i] 依赖 dp[i-k..i-1] 的最值
② 单调队列维护 dp 窗口：
   存下标 + dp 值比较
③ 过期 + 转移 + 维护单调

应用家族：
  1696 跳跃游戏 VI
  1425 带限制的子序列和
  239 窗口最大值（非 DP 版）

⚠️ 面试表达：
"状态转移需要窗口内最大值时，
 用单调队列把 O(nk) 降到 O(n)。"
```

## 6. 面试要点与追问

### 6.1 面试话术模板

```
"窗口最大值用单调递减队列（存下标）：
 ① 入队：弹出所有比当前小的（它们不可能
    再成为最大值——晚到且大淘汰早到且小）；
 ② 过期：队头滑出窗口弹出；
 ③ 队头 = 当前窗口最大值。
 每个元素进出队各一次 → O(n)。"
```

### 6.2 高频追问 TOP 8

| # | 追问 | 标准回答 |
|:---:|------|------|
| 1 | 为什么 O(n)？ | 每元素进出队各一次（总 2n） |
| 2 | 为什么存下标？ | 判断过期（队头 ≤ i-k 弹出） |
| 3 | 淘汰原理？ | 晚到且大淘汰早到且小（两维度都输） |
| 4 | 与单调栈区别？ | 单调队列有过期概念（窗口滑出） |
| 5 | DP 优化？ | 转移依赖窗口最值 → O(nk) 降到 O(n) |
| 6 | 求最小怎么改？ | 单调递增队列（弹更大的） |
| 7 | 相等元素？ | 保留（可能成为新窗口最值） |
| 8 | 空间？ | O(k)（实际远小于 k） |

### 6.3 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| 存值不存下标 | 无法判断过期 | 存下标 |
| 过期判断错 | 窗口外元素残留 | peekFirst <= i-k |
| 比较方向反 | 最值反了 | 求大弹小 |
| 忘相等处理 | 结果错误 | 相等保留（<= 或 >=） |
| DP 题忘按 dp 值比较 | 转移错 | 单调性用 dp |

> 🎯 **核心要点**：单调队列 = **入队淘汰 + 过期弹出 + 队头取值**三件套。识别信号："窗口最值、DP 窗口依赖"。239 是母题（O(n) vs 暴力 O(nk)）；DP 优化（1696）是进阶应用；"晚到且大淘汰早到且小"是淘汰原理必答。
