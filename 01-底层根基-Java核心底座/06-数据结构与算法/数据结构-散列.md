## 散列基础概念

### 1. 定义

散列（哈希）是将**任意长度**数据映射为**固定长度**值的过程。

| 术语 | 说明 |
|------|------|
| **散列函数（Hash Function）** | 映射函数 |
| **散列值（Hash Code）** | 映射结果，即哈希码 |

### 2. 核心思想

> **空间换时间**，通过 O(1) 时间复杂度实现快速查找。核心解决：快速插入、查找、删除。

### 3. 关键问题

| 问题 | 说明 |
|------|------|
| **散列冲突** | 不同输入得到相同散列值 |
| **冲突解决** | 开放寻址法、链地址法（Java 主流） |

## 散列函数设计

### 1. 设计原则

- **计算高效** —— 散列函数本身不能太耗时
- **分布均匀** —— 减少冲突概率
- **雪崩效应** —— 微小输入变化导致散列值巨变

### 2. Java 常用散列函数

| 方法 | 实现原理 |
|------|----------|
| `Object.hashCode()` | native 方法，基于内存地址 |
| `String.hashCode()` | `s[0]*31^(n-1) + s[1]*31^(n-2) + ... + s[n-1]` |
| 自定义对象 | 重写 `hashCode()`，需与 `equals()` 保持一致 |

## 散列冲突解决策略

### 1. 链地址法（Java HashMap 默认）

```
    索引        链表/红黑树
    ┌─────┐
    │  0  │ → null
    ├─────┤
    │  1  │ → Node → Node → Node
    ├─────┤
    │  2  │ → null
    ├─────┤
    │  3  │ → Node → Node
    └─────┘
```

- 每个散列桶对应一个**链表**或**红黑树**
- 冲突元素挂载到同一桶的链表上
- **JDK 8 优化：** 链表长度 > 8 转为红黑树，< 6 转回链表

### 2. 开放寻址法

| 方法 | 原理 | 缺点 |
|------|------|------|
| **线性探测** | 冲突时向后查找空桶 | 容易产生**聚集效应** |
| **二次探测** | 冲突时按二次方步长查找 | 删除困难 |

> 开放寻址法的主要缺点：删除操作复杂、存在聚集效应。Java 未采用此方案。

## Java 核心散列实现

### 1. HashMap（最常用）

| 特性 | 说明 |
|------|------|
| **结构** | 数组 + 链表 + 红黑树 |
| **初始容量** | 16 |
| **负载因子** | 0.75（时间与空间的平衡值） |
| **扩容机制** | 容量翻倍，重新散列（rehash） |
| **线程安全** | ❌ 线程不安全，高并发需使用 `ConcurrentHashMap` |

### 2. ConcurrentHashMap

| 版本 | 线程安全实现 |
|------|-------------|
| JDK 7 | 分段锁（Segment） |
| JDK 8+ | CAS + synchronized（更细粒度） |

> **高并发场景首选** `ConcurrentHashMap`，效率远高于 `Hashtable`。

### 3. HashSet

基于 `HashMap` 实现，值存于 key，value 为固定 `Object` 常量。

### 4. Hashtable

| 特性 | 说明 |
|------|------|
| 线程安全 | synchronized 全表锁，性能低 |
| 状态 | **已淘汰**，不推荐使用 |

## 散列算法应用场景

### 1. 数据存储

- 快速去重：`HashSet`
- 键值对存储：`HashMap`、Redis 字典

### 2. 缓存系统

| 系统 | 实现 |
|------|------|
| Redis | 全局哈希表 + 渐进式 rehash |
| 本地缓存 | Caffeine（基于 W-TinyLFU 算法） |

### 3. 分布式系统

| 技术 | 应用场景 |
|------|----------|
| **一致性哈希** | 负载均衡、分布式缓存 |
| **哈希分片** | 数据库分库分表 |

### 4. 安全领域

| 算法 | 用途 |
|------|------|
| MD5、SHA-1 / SHA-256 | 数据校验、加密存储 |
| BCrypt、Argon2 | 密码哈希（加盐慢哈希） |

## 性能与复杂度分析

### 1. 理想情况

```
插入  O(1)
查找  O(1)
删除  O(1)
```

### 2. 最坏情况

| 冲突解决方式 | 最坏复杂度 |
|-------------|-----------|
| 链表 | O(n) |
| 红黑树 | O(log n) |

### 3. 负载因子影响

| 负载因子 | 空间利用率 | 冲突概率 |
|----------|-----------|----------|
| ↑ 增大 | ↑ 提高 | ↑ 增加 |
| ↓ 减小 | ↓ 降低 | ↓ 减少 |

> Java 默认负载因子 0.75 是时间与空间的平衡选择。

## Java 后端实战要点

### 1. 自定义对象哈希

```java
@Override
public int hashCode() {
    return Objects.hash(field1, field2);
}

@Override
public boolean equals(Object o) {
    if (this == o) return true;
    if (o == null || getClass() != o.getClass()) return false;
    MyClass other = (MyClass) o;
    return Objects.equals(field1, other.field1);
}
```

> **核心原则：** 相等的对象必须有相同的哈希码。

### 2. 高并发优化

- 使用 `ConcurrentHashMap` 替代 `HashMap`
- **预估容量初始化**，避免扩容开销：`new HashMap<>(initialCapacity)`

### 3. 分布式哈希

| 技术 | 说明 |
|------|------|
| **一致性哈希** | 解决节点增减导致的大规模数据迁移问题 |
| **虚拟节点** | 优化数据分布均匀性 |

---

## 总结

1. **散列**是 Java 后端高效数据处理的核心技术
2. **HashMap / ConcurrentHashMap** 是开发中最基础的散列工具
3. **链地址法 + 红黑树** 平衡了性能与空间
4. 应用覆盖**存储、缓存、分布式、安全**全场景

> 掌握散列原理是后端性能优化的关键能力。
