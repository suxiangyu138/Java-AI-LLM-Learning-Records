## 1. Trie 变体家族

### 1.1 三种实现

| 实现 | 结构 | 适用 |
|------|------|------|
| 数组版 | children[26] | 小写字母（208） |
| Map 版 | Map<Character, Node> | 任意字符 |
| 压缩 Trie | 边存字符串 | 空间优化（竞赛） |

```
⚠️ 面试必答：
"Trie 三种实现——数组版最快（固定字符集）、
 Map 版最灵活（任意字符）、压缩版最省空间。"
```

### 1.2 节点字段设计

```java
/** Trie 节点：children + 附加信息 */
class TrieNode {
    TrieNode[] children = new TrieNode[26];
    boolean isEnd;              // ⚠️ 单词结束标记
    int count;                  // 经过次数（前缀计数）
    int wordCount;              // 以该节点结尾的单词数（自动补全）

    // ⚠️ 附加字段按题扩展：
    //   前缀计数（208 变体）、最大异或（01 Trie 无 children 数组）

//   isEnd（是否单词）、count（前缀频次）是
//   两个最常用附加量。"
```

## 2. 01 Trie：最大异或的利器

### 2.1 421 最大异或的核心

```
问题：数组两个数的最大异或值
01 Trie：
  ① 把所有数按二进制位插入 Trie（从高位到低位）
  ② 对每个数：贪心走"相反位"（0 找 1、1 找 0）
  → 异或值最大化

⚠️ 贪心正确性：高位决定大小 → 高位优先相反位

⚠️ 面试必答：
"01 Trie = 二进制字典树——
 插入所有数，查询时高位贪心走相反位；
 最高位优先保证异或最大。"
```

### 2.2 完整实现（421）

```java
/**
 * LeetCode 421. 数组中两个数的最大异或值（01 Trie）
 */
public int findMaximumXOR(int[] nums) {
    // ① 构建 01 Trie（31 位，从高位到低位）
    int[][] trie = new int[nums.length * 31][2];   // ⚠️ 每节点两个分支（0/1）
    int nodeCount = 0;

    int maxXor = 0;
    for (int x : nums) {
        // ② 插入 x（同时查询与 x 最大异或的数）
        int node = 0, query = 0;
        for (int bit = 30; bit >= 0; bit--) {
            int b = (x >> bit) & 1;
            // 插入路径
            if (trie[node][b] == 0) trie[node][b] = ++nodeCount;
            // ⚠️ 查询贪心：走相反位
            int want = b ^ 1;
            if (trie[node][want] != 0) {
                query |= 1 << bit;           // 相反位存在 → 该位异或为 1
                node = trie[node][want];
            } else {
                node = trie[node][b];        // 否则走同位
            }
        }
        maxXor = Math.max(maxXor, query);
    }
    return maxXor;
}
// 推演 [3,10,5,25,2,8] → 最大异或 28（5^25）✓
// ⚠️ 复杂度：O(31n) ≈ O(n)
// ⚠️ 面试必答："421 = 01 Trie——
//   31 位二进制字典树，查询时每步
//   贪心选相反位（高位优先）。"
```

## 3. Trie + DFS：搜索与剪枝

### 3.1 212 单词搜索 II 的核心

```
网格中找字典单词（多个模式匹配）
Trie + 网格 DFS：
  ① 字典建 Trie（所有模式压缩共享前缀）
  ② 网格每个格子 DFS，用 Trie 节点剪枝
  ⚠️ Trie 节点无该字符分支 → 剪枝（不深入）
```

⚠️ 与朴素对比：
  朴素：每个单词独立 DFS → O(单词数 × 网格 DFS)
  Trie：一次 DFS 覆盖所有模式 → 共享前缀剪枝

⚠️ 面试必答：
"212 = Trie 压缩模式 + 网格 DFS——
 Trie 让'多个单词'共享一次搜索，
 不存在的分支直接剪枝。"
```

### 3.2 剪枝技巧

```
⚠️ Trie + DFS 三大剪枝：
  ① 节点分支不存在 → 剪
  ② 节点是单词结尾 → 收集（继续搜更长单词）
  ③ 访问标记（visited/沉没）→ 防环

⚠️ 面试必答：
"Trie 剪枝三件套——分支剪、结尾收、
 visited 防环；'共享前缀'是加速本质。"
```

## 4. Trie 与哈希/后缀树对比

### 4.1 三结构对比

| 维度 | Trie | 哈希 | 后缀树 |
|------|:---:|:---:|:---:|
| 前缀查询 | ✅ O(L) | ❌ | ✅ |
| 单词查找 | ✅ O(L) | ✅ O(1) | ✅ |
| 模式匹配多 | ✅ | ❌ | ✅ |
| 内存 | 较大 | 小 | 大 |
| 有序输出 | ✅ 字典序 | ❌ | ✅ |

```
⚠️ 选型：
  前缀/自动补全 → Trie（哈希做不到前缀）
  精确查找 → 哈希（更快）
  子串全信息 → 后缀数组/树

⚠️ 面试必答：
"Trie 的独门是'前缀'——
 哈希只能精确匹配；
 自动补全/前缀统计必须 Trie。"
```

## 6. Trie 的复杂度与空间

### 6.1 复杂度

```
插入/查询：O(L)（L = 单词长度）
空间：O(总字符数 × 分支数)
  ⚠️ 数组版：每个节点 26 个引用（大量空指针）
  ⚠️ Map 版：只存实际分支（稀疏更省）

⚠️ 面试必答：
"Trie 时间 O(L) 恒定（与集合大小无关）；
 空间是'总字符数'量级——数组版 26 分支
 有空间浪费，Map 版稀疏场景更省。"
```

### 6.2 空间优化

```
① Map 替代数组（稀疏字符集）
② 压缩 Trie（边存子串）
③ 尾指针共享（后缀树思想）
④ 位图分支（定长键）

⚠️ 面试表达：
"空间优化按'稀疏程度'选——
 字符集全用数组、稀疏用 Map、
 极致压缩用压缩 Trie。"
```
