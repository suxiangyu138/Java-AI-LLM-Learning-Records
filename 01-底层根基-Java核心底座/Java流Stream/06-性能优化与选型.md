## 1. 选型原则：Stream vs 循环

> **背景**：Stream 的「优雅」不等于「快」——简单场景循环更直观、性能无差异。
> **目的**：建立选型判断（可读性优先 + 性能按场景）。
> **适用范围**：所有集合数据处理。

```text
选型原则（2026 共识）
├── ① 简单遍历/赋值/打印 → for（直观）
├── ② 复杂过滤/转换/分组 → Stream（可读性远超嵌套循环）
├── ③ 大数据量无状态计算 → 并行流（评估后）
├── ④ 需要下标/中断/精确控制 → for
└── ⑤ 金句：不为 Stream 而 Stream——可读性优先，性能按场景

数据量分级建议
├── < 1000 条：传统循环（或 Stream——无差异）
├── 1000 - 10 万：串行 Stream（优雅）
└── > 10 万：评估并行（见 05 篇）
```

## 2. 优化一：短路操作

> 🎯 **短路操作是最廉价的优化**——结果确定即停止，不全量处理：

```java
// ① limit 短路（最常用）
list.stream()
    .filter(...)
    .limit(3)          // 找到 3 个就停
    .toList();

// ② findFirst/findAny 短路
Optional<Order> first = orders.stream()
    .filter(o -> o.getStatus() == PAID)
    .findFirst();      // 找到即停

// ③ anyMatch/allMatch 短路
boolean hasPaid = orders.stream()
    .anyMatch(o -> o.getStatus() == PAID);   // 命中即停

// ④ takeWhile 短路（有序数据）
sortedList.stream()
    .takeWhile(x -> x < threshold)   // 到条件不满足即停
    .toList();
```

```text
短路 vs 非短路
├── 短路：limit/findFirst/findAny/anyMatch/allMatch/takeWhile
├── 非短路：collect/forEach/count/sorted/distinct
├── 场景：只关心「有没有/前几个」→ 必须短路
└── ⚠️ 短路在并行流：findFirst 反而慢（顺序保证）
```

## 3. 优化二：原始类型流

> 🎯 **原始类型流免装箱拆箱**——数值处理的性能关键（实测快 30-50%）：

```java
// ❌ 装箱开销：Stream<Integer> 每个元素装箱
int sum = list.stream()
    .reduce(0, Integer::sum);   // Integer 对象流

// ✅ 原始流：IntStream 直接 int
int sum = list.stream()
    .mapToInt(x -> x)
    .sum();                     // 免装箱

// 其他原始流
long total = list.stream().mapToLong(Order::getId).sum();
double avg = list.stream().mapToDouble(Order::getAmount).average().orElse(0);

// 范围生成（原始流）
IntStream.range(1, 1000000).sum();

// ⚠️ 注意：mapToInt 后是原始流——需要对象时 boxed()
List<Integer> boxed = IntStream.range(0, 10).boxed().toList();
```

```text
原始流性能要点
├── ① mapToInt/mapToLong/mapToDouble：转原始流
├── ② 聚合方法原生：sum/average/min/max（免装箱）
├── ③ 实测：千万级求和 IntStream 快 30-50%
└── ④ 适用：数值聚合/范围生成/索引遍历
```

## 4. 优化三：操作顺序

> 🎯 **操作顺序 = 性能**——把「缩量」操作放前面，减少后续工作量：

```java
// ❌ 错误顺序：map 昂贵转换处理了全部元素
list.stream()
    .map(expensiveOperation)      // 100 万次昂贵转换
    .filter(x -> x > threshold)
    .limit(3)
    .toList();

// ✅ 正确顺序：先 filter + limit 缩量，再转换
list.stream()
    .filter(x -> x > threshold)   // 先过滤（可能只剩 1 万）
    .limit(3)                     // 再短路（只剩 3）
    .map(expensiveOperation)      // 只转换 3 个！
    .toList();

// 其他顺序原则
├── ① filter 前置（过滤最廉价）
├── ② limit/skip 前置（短路缩量）
├── ③ sorted 后置（有状态——先缩量再排序）
├── ④ distinct 在 filter 后（减少去重状态）
└── ⑤ flatMap 尽量后置（展开最贵）
```

## 5. 优化四：减少中间集合

> 🎯 **避免「collect 后又 stream」**——利用惰性求值一次完成流水线：

```java
// ❌ 错误：多次物化（中间集合浪费）
List<Order> paid = orders.stream()
    .filter(o -> o.getStatus() == PAID)
    .collect(Collectors.toList());            // 物化 1
List<String> ids = paid.stream()
    .map(Order::getOrderId)
    .collect(Collectors.toList());            // 物化 2

// ✅ 正确：一条流水线完成
List<String> ids = orders.stream()
    .filter(o -> o.getStatus() == PAID)
    .map(Order::getOrderId)
    .toList();

// ⚠️ 什么时候必须物化：
// ① 需要中间结果做其他事（分组后查某组）
// ② 流要被多次消费（一次性）
// ③ 中间操作要复用（同一管道多个终止）
```

## 6. 优化五：无状态 Lambda

```text
无状态 Lambda 原则
├── ① Lambda 不修改外部变量（副作用）
│   ├── ❌ 累加到外部计数器（并行必炸）
│   └── ✅ 用 reduce/collect（函数式）
├── ② 避免昂贵操作在每次调用重复
│   ├── 常量提取到外面
│   └── 避免 lambda 内 new 对象（能复用就复用）
├── ③ peek 不用于业务（只调试）
├── ④ 有状态操作（sorted/distinct）放最后
└── ⑤ 金句：无状态 = 可并行 + 可预测

示例
// ❌ 低效：lambda 内重复创建
list.stream().map(x -> new BigDecimal("0.1").multiply(x)).toList();
// ✅ 高效：常量提取
BigDecimal RATE = new BigDecimal("0.1");
list.stream().map(x -> RATE.multiply(x)).toList();
```

## 7. 优化六：批量与聚合收集器

> 🎯 **聚合收集器单次遍历**——避免多次遍历（每个操作一次全遍历）：

```java
// ❌ 多次遍历（每次操作全遍历）
long count = orders.stream().count();                  // 遍历 1
int sum = orders.stream().mapToInt(Order::getAmount).sum();  // 遍历 2
int max = orders.stream().mapToInt(Order::getAmount).max().orElse(0); // 遍历 3

// ✅ 一次遍历拿全统计（summarizing）
IntSummaryStatistics stats = orders.stream()
    .collect(Collectors.summarizingInt(Order::getAmount));
stats.getCount();   // 数量
stats.getSum();     // 总和
stats.getMax();     // 最大

// 分组统计（一次遍历完成）
Map<OrderStatus, Long> countByStatus = orders.stream()
    .collect(Collectors.groupingBy(Order::getStatus, Collectors.counting()));

// 双收集（teeing——一次遍历两个统计）
record Stats(long count, int total) {}
Stats stats = orders.stream()
    .collect(Collectors.teeing(
        Collectors.counting(),
        Collectors.summingInt(Order::getAmount),
        Stats::new
    ));
```

## 8. JMH 基准验证

### 8.1 为什么必须实测

> 🎯 **测量而非直觉**——Stream 性能反直觉（字符串拼接并行反而慢）；选型/优化必须用数据验证。

### 8.2 JMH 示例

```java
// JMH 基准：Stream vs 循环 vs 原始流
@BenchmarkMode(Mode.AverageTime)
@OutputTimeUnit(TimeUnit.MILLISECONDS)
@State(Scope.Thread)
public class StreamBenchmark {
    private List<Integer> data;

    @Setup
    public void setup() {
        data = IntStream.range(0, 1_000_000).boxed().collect(Collectors.toList());
    }

    @Benchmark
    public long forLoop() {          // 传统循环
        long sum = 0;
        for (int x : data) sum += x;
        return sum;
    }

    @Benchmark
    public long streamBoxed() {      // 装箱流
        return data.stream().mapToInt(x -> x).sum();
    }

    @Benchmark
    public long intStream() {        // 原始流（对象→原始）
        return data.stream().mapToInt(Integer::intValue).sum();
    }

    @Benchmark
    public long parallelSum() {      // 并行
        return data.parallelStream().mapToInt(Integer::intValue).sum();
    }
}
// 运行：mvn clean package && java -jar target/benchmarks.jar
// 输出：平均耗时对比（ms/op）——数据说话
```

## 9. 性能检查清单

```text
Stream 性能检查清单（上线前）
[ ] 选型合理？（简单遍历用 for？复杂处理用 Stream？）
[ ] 短路用了？（limit/findFirst——结果确定即停）
[ ] 原始流用了？（数值聚合 mapToInt——免装箱）
[ ] 操作顺序对？（filter/limit 前置、sorted 后置）
[ ] 无中间集合？（避免 collect 后又 stream）
[ ] 无状态 Lambda？（无副作用——可并行）
[ ] 聚合收集器？（summarizing 一次遍历 vs 多次）
[ ] 并行评估过？（条件满足 + JMH 实测）
[ ] 无 IO 密集在 Stream？（用虚拟线程）
[ ] 大数据量分页？（内存分页 or 数据库分页）
→ 金句：性能 = 选型 + 写法 + 实测——不是「用了 Stream 就快」
```

## 10. 核心要点

> 🎯 **核心要点**：
> 1. **Stream 不会让代码变快**——性能取决于任务性质与写法（选型优先）
> 2. 六大优化：短路（最廉价）/原始流（快 30-50%）/操作顺序（filter/limit 前置）/减少物化/无状态 Lambda/聚合收集器
> 3. 操作顺序 = 性能：先缩量再转换（filter → limit → map 昂贵）
> 4. 聚合收集器：summarizing/teeing 单次遍历（避免多次全遍历）
> 5. **JMH 实测验证**——测量而非直觉（字符串拼接并行变慢的教训）
> 6. 检查清单十项：选型/短路/原始流/顺序/物化/状态/聚合/并行/IO/分页
