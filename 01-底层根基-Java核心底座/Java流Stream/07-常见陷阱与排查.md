## 1. 陷阱全景

```text
Stream 十二陷阱（高频事故）
├── ① 流一次性：二次消费抛 IllegalStateException
├── ② 忘记终止操作：惰性——什么都没执行
├── ③ 副作用：map/forEach 修改外部状态（并行致命）
├── ④ 无限流：iterate/generate 无 limit = 死循环/OOM
├── ⑤ 空指针：流中 null 元素（filter/map 直接 NPE）
├── ⑥ effectively final：Lambda 捕获可变变量
├── ⑦ findFirst vs findAny：顺序与性能的误用
├── ⑧ toList 可变性：Java 16+ 不可变 vs 预期可变
├── ⑨ peek 误用：当终止操作/修改元素
├── ⑩ sorted 无限流：有状态操作永远等不完
├── ⑪ 并行共享状态：非线程安全集合/计数器
└── ⑫ 操作顺序错误：昂贵操作处理了多余元素
```

## 2. 陷阱 1：流的一次性

```java
// ❌ 错误：同一流消费两次
Stream<String> stream = list.stream();
long count = stream.count();            // 第一次 ✅
List<String> result = stream.toList();  // ❌ IllegalStateException!

// 异常信息：
// stream has already been operated upon or closed

// ✅ 正确：需要多次操作 → 重新创建流
long count = list.stream().count();
List<String> result = list.stream().filter(...).toList();

// ✅ 正确：需要多次消费 → 先物化成集合
List<String> materialized = list.stream().filter(...).toList();
// 之后 materialized 可反复使用（它是集合不是流）
```

## 3. 陷阱 2：忘记终止操作

```java
// ❌ 错误：没有终止操作——什么都不执行
list.stream()
    .filter(x -> x > 10)
    .map(x -> x * 2);
// ⚠️ 惰性求值：无终止 = 管道没构建完 = 什么都没发生

// ✅ 正确：必须终止操作触发
List<Integer> result = list.stream()
    .filter(x -> x > 10)
    .map(x -> x * 2)
    .toList();

// 常见场景：只写了中间操作忘收集
// ❌ stream().filter(...)  // 没 collect/toList
// ✅ stream().filter(...).toList()

// 排查：检查每个 stream 链末尾是否有终止操作
```

## 4. 陷阱 3：副作用

```java
// ❌ 错误：map 中修改外部状态
List<String> result = new ArrayList<>();
list.stream()
    .map(s -> {
        result.add(s.toUpperCase());   // 副作用！
        return s.toUpperCase();
    })
    .count();
// ⚠️ 串行可能「碰巧对」；并行必炸（线程不安全）

// ❌ 错误：forEach 修改共享集合
list.parallelStream()
    .forEach(x -> sharedList.add(x));  // AIOOBE/数据丢失

// ✅ 正确：用终止操作收集（无副作用）
List<String> result = list.stream()
    .map(String::toUpperCase)
    .toList();

// ✅ 正确：聚合用 reduce（函数式）
int sum = list.stream().reduce(0, Integer::sum);
```

## 5. 陷阱 4：无限流

```java
// ❌ 错误：无限流无截断
Stream.iterate(0, i -> i + 1)
    .forEach(System.out::println);   // 无限打印！死循环

// ❌ 错误：并行无限流（更危险）
Stream.iterate(0, i -> i + 1)
    .parallel()                      // CPU 飙升/OOM
    .limit(100)
    .toList();

// ✅ 正确：limit 截断（先 limit 再并行）
Stream.iterate(0, i -> i + 1)
    .limit(100)                      // 先截断
    .parallel()                      // 再并行（安全）
    .toList();

// ✅ Java 9+：带终止条件（更安全）
Stream.iterate(0, i -> i < 100, i -> i + 1).toList();

// ✅ generate + limit
Stream.generate(Math::random).limit(5).toList();

// ⚠️ 无限流 + 有状态操作（sorted/distinct）：永远等不完
// Stream.iterate(0, i -> i + 1).limit(100).sorted().toList();
// ⚠️ sorted 需要全量——limit 100 后 sorted 是可以的（有限）
// 真正危险：无限流直接 sorted（没有 limit）
```

## 6. 陷阱 5：空指针

```java
// ❌ 错误：流中 null 元素直接操作
List<String> list = Arrays.asList("a", null, "b");
list.stream()
    .map(String::toUpperCase)      // ❌ NPE（null 调用方法）
    .toList();

// ✅ 正确：先过滤 null
list.stream()
    .filter(Objects::nonNull)      // 过滤 null
    .map(String::toUpperCase)
    .toList();

// ✅ 数据源兜底：Optional.ofNullable
Optional.ofNullable(collection)
    .map(Collection::stream)
    .orElse(Stream.empty())
    .toList();

// ✅ 排序 null 处理
list.stream()
    .sorted(Comparator.nullsLast(Comparator.naturalOrder()))
    .toList();

// ✅ 查找结果处理
Order order = orders.stream()
    .filter(...)
    .findFirst()
    .orElseThrow(() -> new OrderNotFoundException());  // 不返回 null
// ⚠️ 生产铁律：不返回 null（用 Optional/异常/默认值）
```

## 7. 陷阱 6：effectively final

```java
// ❌ 错误：Lambda 捕获可变变量
int threshold = 10;
threshold = 20;                    // ⚠️ 修改变量
list.stream()
    .filter(x -> x > threshold)    // ❌ 编译错误（not effectively final）

// ✅ 正确：变量不再修改（effectively final）
int threshold = 10;                // 声明后不再赋值
list.stream()
    .filter(x -> x > threshold)
    .toList();

// 数组/对象的「变通」（不推荐——可读性差）
int[] box = {10};                  // 数组可变（hack）
list.stream().filter(x -> x > box[0]).toList();
// ⚠️ 有副作用风险——推荐用原子引用或重新设计
```

## 8. 陷阱 7：findFirst vs findAny

```java
// findFirst：保证第一个（顺序敏感）
Optional<Order> first = orders.stream()
    .filter(...)
    .findFirst();                  // 串行：第一个匹配

// findAny：任意一个（不保证顺序）
Optional<Order> any = orders.stream()
    .filter(...)
    .findAny();                    // 串行通常也是第一个（非保证）

// ⚠️ 并行流差异：
// findFirst：需要顺序保证 → 并行开销大（反而慢）
// findAny：无顺序要求 → 并行性能好

// 选型：
// ✅ 顺序敏感（业务要求第一个）→ findFirst
// ✅ 只关心「有没有/任意一个」→ findAny（并行友好）
// ✅ 布尔场景 → anyMatch（最短路）
```

## 9. 陷阱 8：toList 可变性

```java
// Java 16+ 的 toList()：返回「不可变」列表！
List<String> result = list.stream().toList();
// result.add("x");  // ❌ UnsupportedOperationException！

// Java 8 的 collect(toList())：可变（具体类型未保证）
List<String> result = list.stream().collect(Collectors.toList());
// result.add("x");  // ✅ 通常可变（ArrayList）

// ⚠️ 陷阱：代码从 collect 迁移到 toList 后，add 抛异常

// 需要可变：指定实现
List<String> mutable = list.stream()
    .collect(Collectors.toCollection(ArrayList::new));

// 需要不可变（推荐生产）：直接 toList（安全）
// 金句：默认不可变更安全——需要修改再显式 toCollection
```

## 10. 陷阱 9：peek 的误用

```java
// ❌ 错误 1：把 peek 当终止操作
list.stream().peek(System.out::println);
// ⚠️ 什么都不输出（peek 是中间操作——无终止不执行）

// ❌ 错误 2：peek 中修改元素
list.stream()
    .peek(s -> s = s.toUpperCase())   // 无效！（不改原流）
    .toList();

// ✅ 正确：调试用 peek（中间查看）
list.stream()
    .peek(x -> log.debug("处理前: {}", x))
    .filter(...)
    .peek(x -> log.debug("处理后: {}", x))
    .toList();

// ✅ 正确：peek 做「无副作用」的观察（打日志/统计）
list.stream()
    .peek(x -> counter.incrementAndGet())   // 原子计数（可并行）
    .toList();
// ⚠️ 生产代码应移除 peek（调试痕迹）
```

## 11. 陷阱 10-12：其他高频

### 11.1 sorted + 无限流/大流

```java
// sorted 是有状态 + 全量操作
// ❌ 无限流 sorted：永远等不完
// Stream.iterate(0, i -> i + 1).sorted()  // 死等！
// ✅ 有限流 sorted：OK（但全量排序——数据大评估）
// 优化：先 filter/limit 缩量再 sorted
```

### 11.2 并行共享状态

```java
// ❌ 并行共享非线程安全集合
Set<String> set = new HashSet<>();
list.parallelStream().forEach(s -> set.add(s));  // 数据丢失！
// ✅ 用并发收集器
Set<String> set = list.parallelStream()
    .collect(Collectors.toConcurrentSet());
```

### 11.3 操作顺序错误

```java
// ❌ 昂贵 map 在前（处理全部）
list.stream().map(expensive).filter(...).limit(3);
// ✅ 便宜 filter 在前（缩量）
list.stream().filter(...).limit(3).map(expensive);
// 详见 06 篇优化三
```

## 12. 排查方法论

```text
Stream 问题排查五步
├── ① 症状分类：
│   ├── 异常 → 一次性/副作用/空指针
│   ├── 死循环 → 无限流
│   ├── 结果错误 → 顺序/共享状态
│   └── 性能差 → 选型/操作顺序/装箱
├── ② 检查终止操作：没 collect/toList = 白写
├── ③ 检查无限流：iterate/generate 有 limit 吗
├── ④ 检查副作用：map/forEach 修改外部状态
├── ⑤ 检查并行：共享集合/顺序敏感（见 05 篇）
→ 金句：Stream 排障 = 「一次性 + 惰性 + 副作用 + 无限」四查
```

## 13. 核心要点

> 🎯 **核心要点**：
> 1. 十二陷阱归类：一次性/惰性/副作用/无限/空指针/final/顺序/可变性/peek/sorted/并行/顺序
> 2. 一次性：二次消费抛 IllegalStateException——重新创建流
> 3. 惰性：无终止操作 = 什么都没发生
> 4. 副作用：map/forEach 不修改外部状态（并行必炸）
> 5. 无限流：iterate/generate 必须 limit（先 limit 再并行）
> 6. 空指针：Objects::nonNull 过滤 + Optional 兜底（不返回 null）
> 7. toList（Java 16+）不可变 vs collect(toList()) 可变——按需选择
> 8. 排查五步：症状分类 → 终止 → 无限 → 副作用 → 并行
