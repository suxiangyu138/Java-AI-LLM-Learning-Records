## 1. 面试高频题与答题框架

### 1.1 概念类

**Q1：为什么 Windows 用反斜杠而 Linux 用正斜杠？**

```text
① Unix 继承：Multics（1960s）就用 / 分隔目录
② MS-DOS 2.0（1983）：/ 已被用作命令行参数标志（dir /w）
   → 为避免路径与参数混淆，选择 \ 作为路径分隔符
③ 本质：历史偶然 + 当时约束下的合理妥协
④ 现状：Windows 新工具（PowerShell）向 - 参数风格迁移，\ 只剩兼容负担
⑤ 加分：现代 Windows 大多兼容 /（C:/Windows 可用），但 UNC 必须 \\
```

**Q2：跨平台代码中路径应该怎么写？**

```text
① 统一 /：/ 是全平台交集（Windows 兼容、Unix 唯一、URL 标准）
② \ 是 Windows 子集：Unix 不识别
③ 展示给用户：系统 API 生成（getRealPath 返回 D:\...）
④ 拼接：路径库（Paths.get / path.join / pathlib）
⑤ 金句：代码写 / 保证处处可用，写 \ 赌 Windows 兼容
```

**Q3：为什么代码中不能直接写 `"D:\data"`？**

```text
① 字符串中 \ 是转义字符（Java/JS/C 等）
② \d 不是合法转义序列：Java 编译错误；Python 保留但 IDE 警告
③ 正确写法：双写 "D:\\data" 或（推荐）"D:/data"
④ 各语言免转义方案：Python r"..." / C# @"..." / Go 反引号
```

### 1.2 转义与正则类

**Q4：正则中匹配反斜杠为什么那么麻烦？**

```text
① 双重转义：正则层转义 + 字符串层转义
② 匹配字面 \ 的写法：
   Java "\\\\"（4 个）/ Python r"\\" / JS /\\/（字面量）
③ 优雅解法：字符类 [\\/] 同时匹配 \ 和 /
④ 金句：一层正则转义 + 一层字符串转义 = 双重转义
```

**Q5：replace 和 replaceAll 有什么区别？路径替换用哪个？**

```text
① replace：字面替换（第一个参数不是正则）——"\\" 就是字面反斜杠
② replaceAll：正则替换——"\\\\" 才是匹配字面反斜杠
③ 路径替换优先 replace（零转义陷阱）
④ JS 注意：str.replace("\\", "/") 只替换第一个！
   必须 str.replace(/\\/g, "/")（正则全局）
⑤ 加分：replaceAll 替换串含 $ 或 \ 时用 Matcher.quoteReplacement
```

### 1.3 跨平台类

**Q6：代码在 Windows 开发正常，部署 Linux 崩溃，可能原因？**

```text
① 硬编码 Windows 路径（D:\xxx）→ Linux 不存在
② 硬编码绝对路径（C:\Users\张三）→ 换机器就挂
③ 反斜杠转义问题在 Windows 上「恰好没报错」
④ 解法：相对路径 + 配置注入 + 路径库 + 双平台 CI 矩阵
⑤ 金句：Windows 上「能跑」掩盖了跨平台问题——矩阵测试早发现
```

**Q7：URL 中能写反斜杠吗？**

```text
① 不能：RFC 3986 规定 URL 路径分隔符只能是 /
② 浏览器会修正 \（Firefox 提示）；服务器 404/解析异常
③ 拼 URL 前：路径 \ → /（replace），再 URL 编码
④ 路径参数中的 / 编码为 %2F
⑤ 场景延伸：类路径资源（classpath:/config）、Spring 路由都是 /
```

**Q8：Java File 类有哪些跨平台常量？**

```text
① File.separator：路径分隔符（Win \ / Unix /）
② File.pathSeparator：路径列表分隔符（Win ; / Unix :）
③ 拼接：new File(parent, child) 自动处理
④ NIO：Paths.get(...) / path.resolve(...) 自动适配平台
⑤ 展示：toAbsolutePath().toString() 自动转系统格式
```

### 1.4 安全与实战类

**Q9：文件上传如何防路径穿越？**

```text
① 威胁：../../etc/passwd 拼接路径（CWE-22）
② 防护四件套：basename（只取文件名）/ normalize + startsWith 校验
   / 扩展名白名单 / UUID 随机文件名
③ 金句：用户输入永远不可信——路径拼接前必须净化
```

**Q10：Windows 文件名有什么限制？**

```text
① 9 个非法字符：< > : " / \ | ? *
② 保留名：CON PRN AUX NUL COM1-9
③ 结尾不能是空格/点；路径 ≤260 字符（长路径需 \\?\ 前缀）
④ 跨平台：Linux 允许 : 和 *——同一文件名两平台命运不同
⑤ 上传文件名清洗：replaceAll("[<>:\"/\\\\|?*]", "_")
```

**Q11：脚本在 Windows 编辑后 Linux 报错 `$'\r'` 是什么？**

```text
① CRLF 换行问题：Windows 保存为 \r\n，Linux bash 把 \r 当命令
② 可能叠加 BOM：EF BB BF 让 #!/bin/bash 失效
③ 解法：dos2unix / 编辑器默认 LF 无 BOM
④ 根治：.gitattributes 声明 *.sh text eol=lf
⑤ 金句：换行符差异是跨平台协作的第一行配置
```

**Q12：Docker 挂载 Windows 路径报错怎么解决？**

```text
① 统一正斜杠：docker run -v C:/data:/app/data
② PowerShell：引号包裹 "C:\data:/app/data"
③ Compose：相对路径 ./data:/app/data
④ Git Bash：MSYS_NO_PATHCONV=1 禁用路径转换
⑤ 金句：容器内是 Linux——挂载源路径用 / 最稳
```

## 2. 代码题实战

**题 1：把 Windows 路径转正斜杠（手写）**

```java
// Java
String normalized = windowsPath.replace("\\", "/");
// 或正则版（知道区别）：replaceAll("\\\\", "/")

// Python
normalized = windows_path.replace("\\", "/")
// 或 pathlib：Path(windows_path).as_posix()

// JS
const normalized = windowsPath.replace(/\\/g, "/");
// ⚠️ 不是 replace("\\", "/")——只替换第一个！
```

**题 2：按分隔符拆分路径（跨平台）**

```java
// Java：匹配 \ 或 /（字符类）
String[] parts = path.split("[\\\\/]");

// Python
import re
parts = re.split(r"[\\/]", path)

// JS
const parts = path.split(/[\\/]/);
```

**题 3：安全拼接上传路径（手写）**

```java
public Path safeUploadPath(String uploadDir, String userFilename) {
    String safeName = Paths.get(userFilename).getFileName().toString();
    Path target = Paths.get(uploadDir).resolve(safeName).normalize();
    if (!target.startsWith(Paths.get(uploadDir).toAbsolutePath())) {
        throw new SecurityException("非法路径: " + userFilename);
    }
    return target;
}
```

**题 4：判断字符串是否含反斜杠（转义测试）**

```java
// Java：contains 字面（最简单）
path.contains("\\");                     // ✅ 一个反斜杠字符

// 正则版本（理解双重转义）
path.matches(".*\\\\.*");                // 4 个反斜杠

// Python
"\\" in path                             // ✅
re.search(r"\\", path)                   // ✅ 原始字符串
```

## 3. 终极速查表

| 场景 | 写法 | 平台 |
|------|------|:---:|
| 跨平台代码路径 | `/` | 全 |
| URL / HTTP | `/`（只能） | 全 |
| Windows 路径展示 | `\`（系统生成） | Win |
| Java 字符串 | `"D:/data"` 或 `"D:\\data"` | 全 |
| Python 字符串 | `r"D:\data"` | 全 |
| Java 正则匹配 `\` | `"\\\\"` | 全 |
| Python 正则匹配 `\` | `r"\\"` | 全 |
| JS 正则匹配 `\` | `/\\/` 或 `"\\\\"` | 全 |
| 分割两种斜杠 | `split("[\\\\/]")` / `re.split(r"[\\/]", p)` | 全 |
| 反斜杠转正斜杠 | `replace("\\", "/")`（JS 用正则 g） | 全 |
| 路径分隔符常量 | `File.separator` / `path.sep` / `os.sep` | 全 |
| 路径列表分隔符 | `File.pathSeparator`（Win `;` / Unix `:`） | 全 |
| UNC 路径 | `\\server\share`（必须反斜杠） | Win |
| Docker 挂载 | `C:/data:/app/data` | 全 |
| 配置文件路径 | `/` 优先；properties/JSON 双写 | 全 |
| 用户输入路径 | basename + normalize + startsWith | 全 |

## 4. 五大常见误区

| # | 误区 | 真相 |
|---|------|------|
| 1 | 「反斜杠是 Windows 的标准，代码里就该用它」 | 代码用 `/`（全平台交集）；`\` 只留给展示与转义 |
| 2 | 「replaceAll 和 replace 差不多」 | replace 字面 / replaceAll 正则——路径替换用 replace |
| 3 | 「JS replace('\\\\','/') 就够」 | 只替换第一个——必须正则全局 `/\\/g` |
| 4 | 「Windows 能跑 = 跨平台没问题」 | 硬编码路径在 Windows 恰好存在——双平台 CI 才见真相 |
| 5 | 「\ 在 Python 里没问题」 | 普通字符串中 \d 等是「隐式保留」——IDE 警告 + 语义错误，要用 r"" |

## 5. 一句话总结全系列

```text
01 历史：Unix 继承 /（1960s）；MS-DOS 2.0 因参数冲突偶然选 \（1983）
02 规则：五场景——路径 /、URL /、命令行 -、字符串 \\、正则双重转义
03 语言：Java 严格转义 / Python 原始字符串 / JS 正则字面量 / Shell 三规则
04 实践：代码 / + 系统 API 展示 + 路径库拼接 + 配置注入 + 输入净化
05 踩坑：8 反斜杠/正则双重/硬编码路径/URL 反斜杠/Docker 挂载/穿越
06 面试：12 题框架 + 4 道代码题 + 终极速查表
```

> 🎯 **系列总结**：正斜杠与反斜杠的背后是**平台历史 × 语言设计 × 场景规则**的三维知识——掌握它，跨平台开发不再踩坑。终极口诀只有一句：**网络和跨平台代码用 `/`；转义和 Windows 本地显示才用 `\`，且代码中不能单独书写反斜杠**——记住这句，就记住了 90% 的规则。
