### 1.2 核心代码实现

```java
@Service
public class SeckillService {

    /**
     * 秒杀核心逻辑 —— 三步走：
     * ① Redis Lua 原子预扣
     * ② 返回"排队中"
     * ③ MQ 异步落库
     */
    public SeckillResult doSeckill(Long goodsId, Long userId) {
        // ── 步骤1: 风控校验 ──
        if (isBlocked(userId)) {
            return SeckillResult.blocked("用户被限流");
        }

        // ── 步骤2: Redis Lua 原子扣库存 ──
        Long result = redisLua.deductStock(goodsId, userId, 1);
        // 返回值: 1=成功, 0=库存不足, -1=重复抢购, -2=未开始/已结束

        switch (result.intValue()) {
            case -2: return SeckillResult.error("活动未开始或已结束");
            case -1: return SeckillResult.error("您已参与过本次活动");
            case  0: return SeckillResult.soldOut();
            case  1: // 预扣成功，继续
        }

        // ── 步骤3: 异步下单 ──
        String orderId = UUID.randomUUID().toString();
        rocketMQ.send("SECKILL_ORDER", new SeckillMessage(orderId, goodsId, userId));

        // ── 步骤4: 立即返回排队中 ──
        return SeckillResult.queued(orderId);  // 前端轮询订单结果
    }
}
```

### 1.3 Redis Lua 原子脚本（核心）

```lua
-- seckill.lua —— 库存预扣 + 用户限购 + 活动时间校验
-- KEYS[1]: 库存 key       (seckill:stock:{goodsId})
-- KEYS[2]: 用户集合 key   (seckill:users:{goodsId})
-- KEYS[3]: 活动标记 key   (seckill:active:{goodsId})
-- ARGV[1]: userId
-- ARGV[2]: limitCount    (每人限购数量)

-- 校验活动状态
local active = redis.call('GET', KEYS[3])
if not active or active ~= '1' then
    return -2  -- 活动未开始或已结束
end

-- 校验用户限购
local userKey = KEYS[2] .. ':' .. ARGV[1]
local bought = tonumber(redis.call('GET', userKey) or 0)
local limit = tonumber(ARGV[2])
if bought >= limit then
    return -1  -- 已达限购
end

-- 校验并扣减库存
local stock = tonumber(redis.call('GET', KEYS[1]) or 0)
if stock <= 0 then
    return 0   -- 库存不足
end

redis.call('DECR', KEYS[1])
redis.call('INCR', userKey)
redis.call('EXPIRE', userKey, 86400)  -- 24 小时过期

return 1  -- 抢购成功
```

```java
public class RedisLuaExecutor {
    private final StringRedisTemplate redis;
    private final DefaultRedisScript<Long> seckillScript;

    public RedisLuaExecutor(StringRedisTemplate redis) {
        this.redis = redis;
        this.seckillScript = new DefaultRedisScript<>();
        seckillScript.setLocation(
            new ClassPathResource("lua/seckill.lua"));
        seckillScript.setResultType(Long.class);
    }

    public Long deductStock(Long goodsId, Long userId, int limitCount) {
        List<String> keys = List.of(
            "seckill:stock:" + goodsId,
            "seckill:users:" + goodsId,
            "seckill:active:" + goodsId
        );
        return redis.execute(seckillScript, keys,
            String.valueOf(userId), String.valueOf(limitCount));
    }
}
```

## 2. 库存防超卖方案矩阵 {#2}

### 2.1 四种方案对比

| 方案 | 实现 | QPS支撑 | 复杂度 | 超卖风险 |
|------|------|:---:|:---:|:---:|
| **Redis Lua 原子** | 单线程原子操作 | 10万+ | 中 | ✅ 无风险 |
| **DB 行锁** | `SELECT ... FOR UPDATE` | 1000 | 低 | ✅ 无风险 |
| **乐观锁** | `UPDATE ... WHERE stock>0 AND version=?` | 5000 | 低 | ⚠️ 高并发下大量重试 |
| **分布式锁 (Redisson)** | `RLock` + 看门狗 | 5000 | 中 | ✅ 无风险 |

### 2.2 各方案代码

```java
// ── 方案2: 数据库行锁 ──
@Transactional
public boolean deductStockDB(Long goodsId, int quantity) {
    // SELECT ... FOR UPDATE 行锁
    Product product = productMapper.selectForUpdate(goodsId);
    if (product.getStock() < quantity) return false;
    productMapper.deduct(goodsId, quantity);
    return true;
}

// ── 方案3: 乐观锁 ──
@Transactional
public boolean deductStockOptimistic(Long goodsId, int quantity) {
    int rows = productMapper.deductWithVersion(goodsId, quantity,
        productMapper.getVersion(goodsId));
    if (rows == 0) {
        throw new OptimisticLockException("库存扣减失败，请重试");
    }
    return true;
}
```

```java
// ── 方案4: Redisson 分布式锁 ──
public boolean deductStockRedisson(Long goodsId, int quantity) {
    RLock lock = redisson.getLock("stock:lock:" + goodsId);
    try {
        // tryLock(等待时间, 锁过期时间, 单位)
        if (lock.tryLock(1, 10, TimeUnit.SECONDS)) {
            Product product = productMapper.selectById(goodsId);
            if (product.getStock() < quantity) return false;
            productMapper.deduct(goodsId, quantity);
            return true;
        }
    } finally {
        if (lock.isHeldByCurrentThread()) {
            lock.unlock();
        }
    }
    return false;
}
```

## 3. 高并发计数器方案 {#3}

### 3.1 方案演进

```text
场景：亿级 PV 统计、点赞数、排行榜

方案1: DB COUNT → 行锁，QPS < 1000
方案2: Redis INCR → 单 Key 热点，QPS ~10万（单机瓶颈）
方案3: Redis 分片计数器 → 多 Key 并行，QPS 100万+
方案4: 本地聚合 + 定时刷 Redis → QPS 无限
```

### 3.2 Redis 分片计数器

```java
/**
 * 分片计数器 —— 将单 Key 热点分散到 N 个分片
 * 写: 随机选一个分片 INCR
 * 读: 汇总所有分片的值
 */
public class ShardedCounter {
    private final StringRedisTemplate redis;
    private final int shardCount;  // 分片数，建议 32 或 64

    public ShardedCounter(StringRedisTemplate redis, int shardCount) {
        this.redis = redis;
        this.shardCount = shardCount;
    }

    // 递增
    public long increment(String key) {
        int shard = ThreadLocalRandom.current().nextInt(shardCount);
        return redis.opsForValue()
            .increment(key + ":" + shard);  // counter:like:27
    }

    // 获取总数
    public long getTotal(String key) {
        long total = 0;
        for (int i = 0; i < shardCount; i++) {
            String val = redis.opsForValue().get(key + ":" + i);
            total += val != null ? Long.parseLong(val) : 0;
        }
        return total;
    }
}
```

### 3.3 本地聚合方案（最高性能）

```java
/**
 * 本地聚合计数器 —— 内存中攒够一批再刷 Redis
 * 适合：可容忍少量延迟的计数场景 (点赞、PV)
 */
public class LocalAggregateCounter {
    private static final int BATCH_SIZE = 100;

    // 每个线程独立计数，避免竞争
    private final ThreadLocal<Long> localCounter = ThreadLocal.withInitial(() -> 0L);
    private final AtomicLong globalCount = new AtomicLong(0);
    private final String redisKey;

    public void increment() {
        long count = localCounter.get() + 1;
        localCounter.set(count);

        if (count >= BATCH_SIZE) {
            flush();  // 攒够 100 个刷一次 Redis
        }
    }

    private void flush() {
        long count = localCounter.get();
        if (count > 0) {
            redis.opsForValue().increment(redisKey, count);
            globalCount.addAndGet(count);
            localCounter.set(0L);
        }
    }

    // 定时刷（兜底）
    @Scheduled(fixedRate = 1000)
    public void scheduledFlush() {
        flush();
    }
}
```

### 3.4 HyperLogLog —— 近似去重计数

```java
/**
 * 场景：统计 UV（独立访客），亿级数据
 * 传统方式：SET 存储所有 userId → 内存爆炸
 * HyperLogLog：12KB 即可统计 10 亿 UV，误差 ~0.81%
 */
public class UVCounter {

    public void recordVisit(String pageKey, Long userId) {
        redis.opsForHyperLogLog().add("uv:" + pageKey, String.valueOf(userId));
    }

    public long getUV(String pageKey) {
        return redis.opsForHyperLogLog().size("uv:" + pageKey);
    }

    // 合并多天 UV
    public long getWeeklyUV(String pageKey, String... dailyKeys) {
        String mergedKey = "uv:" + pageKey + ":weekly";
        redis.opsForHyperLogLog().union(mergedKey, dailyKeys);
        return redis.opsForHyperLogLog().size(mergedKey);
    }
}
```

## 4. 请求排队与异步处理 {#4}

### 4.1 排队机制设计

```java
/**
 * 秒杀排队 —— "先到先得"的公平机制
 *
 * 流程：
 * 1. 用户请求 → 获取排队序号 (Redis INCR)
 * 2. 将请求写入 MQ（按序号有序消费）
 * 3. 前端轮询队列位置
 * 4. 处理完成 → WebSocket 推送结果
 */
public class SeckillQueue {
    private final StringRedisTemplate redis;

    // ── 加入排队 ──
    public QueuePosition enqueue(Long goodsId, Long userId) {
        String queueKey = "queue:" + goodsId;
        Long position = redis.opsForList().rightPush(queueKey,
            userId.toString());
        Long queueLength = redis.opsForList().size(queueKey);

        return new QueuePosition(position, queueLength);
    }

    // ── 查询排队位置 ──
    public QueuePosition getPosition(Long goodsId, Long userId) {
        String queueKey = "queue:" + goodsId;
        Long index = redis.opsForList().indexOf(queueKey, userId.toString());
        Long queueLength = redis.opsForList().size(queueKey);

        if (index == null) {
            return QueuePosition.processing();  // 已出队，正在处理
        }
        return new QueuePosition(index + 1, queueLength);
    }
}

@Data
@AllArgsConstructor
class QueuePosition {
    private long position;  // 当前位置
    private long total;     // 总排队数
    private boolean processing;

    public static QueuePosition processing() {
        QueuePosition qp = new QueuePosition(-1, -1, true);
        return qp;
    }
}
```

## 5. 全链路压测方案 {#5}

### 5.1 六阶段压测流程

```text
阶段1: 单链路基准 (5 并发 → 50 → 200)
       目的：获取单接口的基准 TPS/RT
       每个接口独立压测，记录 CPU/内存/GC

阶段2: 核心链路组合 (100 → 500 → 1000 并发)
       目的：模拟用户行为流 (浏览→加购→下单)
       发现组合场景下的瓶颈

阶段3: 全链路 (预估峰值 80% 压力)
       目的：端到端验证，包含 CDN/网关/服务/缓存/DB/MQ
       所有微服务同时施压

阶段4: 极限压测 (持续加压直到错误率 > 5%)
       目的：找到系统崩溃的临界点
       记录最大 QPS / 最小 RT / 极限并发数

阶段5: 长稳压测 (峰值 × 70%, 持续 4-8 小时)
       目的：发现内存泄漏、连接泄漏、GC 恶化
       观察 JVM 指标是否持续劣化

阶段6: 破坏性压测 (故障注入)
       目的：验证熔断降级是否生效
       模拟: Redis 宕机、DB 主从切换、MQ 积压
```

### 5.3 流量染色与数据隔离

```java
/**
 * 压测流量染色 —— 保证压测数据不污染生产
 * 核心：通过 HTTP Header / RPC Attachment 传递压测标记
 */
@Component
public class TrafficDyeingFilter implements Filter {

    public static final String PRESSURE_TEST_HEADER = "X-Pressure-Test";
    private static final ThreadLocal<Boolean> PRESSURE_TEST_FLAG =
        new ThreadLocal<>();

    @Override
    public void doFilter(ServletRequest req, ServletResponse resp,
            FilterChain chain) throws IOException, ServletException {
        HttpServletRequest httpReq = (HttpServletRequest) req;
        String flag = httpReq.getHeader(PRESSURE_TEST_HEADER);

        if ("true".equals(flag)) {
            PRESSURE_TEST_FLAG.set(true);
            // 切换数据源 → 影子表/影子库
            DynamicDataSourceContextHolder.set("shadow");
        }

        try {
            chain.doFilter(req, resp);
        } finally {
            PRESSURE_TEST_FLAG.remove();
            DynamicDataSourceContextHolder.clear();
        }
    }

    public static boolean isPressureTest() {
        return Boolean.TRUE.equals(PRESSURE_TEST_FLAG.get());
    }
}
```

### 5.4 压测指标看板

| 指标 | 目标值 | 告警阈值 | 严重阈值 |
|------|:---:|:---:|:---:|
| QPS | 按业务定 | 低于目标 30% | 低于目标 50% |
| P99 RT | < 200ms | > 500ms | > 1000ms |
| 错误率 | < 0.1% | > 1% | > 5% |
| CPU | < 70% | > 85% | > 95% |
| 堆内存 | < 80% | > 90% | > 95% |
| GC 暂停 | < 50ms | > 200ms | > 500ms |
| DB 连接数 | < 80% | > 90% | =100% |
| MQ 积压 | 接近 0 | 持续增长 | 队列满 |

> 🎯 **核心要点**：压测不是"跑一次就完了"——它是一个持续的工程实践。每次大促前至少 3 轮全链路压测，每轮都要有明确的指标目标和改进记录。
