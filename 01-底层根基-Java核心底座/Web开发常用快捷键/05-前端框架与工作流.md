## 1. VS Code 前端调试配置

> **背景**：VS Code 通过 Debugger for Chrome/Edge 扩展把浏览器调试搬进编辑器——断点、变量、调用栈与 DevTools 同款体验。
> **目的**：在编辑器内完成「代码编辑 → 断点调试」闭环。
> **适用范围**：VS Code 用户的前端/Node 调试。
> **不适用场景**：已用 DevTools 熟练调试的场景（两套二选一）。

### 1.1 launch.json 配置

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "type": "chrome",
      "request": "launch",
      "name": "Chrome Debug",
      "url": "http://localhost:3000",      // 开发服务器地址
      "webRoot": "${workspaceFolder}"
    },
    {
      "type": "chrome",
      "request": "attach",
      "name": "Attach to Chrome",
      "port": 9222                          // Chrome 远程调试端口
    }
  ]
}
```

### 1.2 调试快捷键（VS Code）

| 快捷键 | 功能 |
|:---:|------|
| `F5` | 启动/继续调试 |
| `F9` | 切换断点 |
| `F10` | 单步跳过 |
| `F11` | 单步进入 |
| `Shift+F11` | 单步跳出 |
| `Shift+F5` | 停止调试 |
| `Ctrl+Shift+D` | 打开调试面板 |
| `Ctrl+Shift+Y` | 调试控制台 |

```text
VS Code 调试工作流（React/Vue 项目）
├── ① npm start 启动开发服务器（或 Live Server）
├── ② F5 启动调试（launch 模式自动开浏览器）
├── ③ 编辑器内设置断点（F9）
├── ④ 浏览器操作触发 → 断点暂停在编辑器
├── ⑤ 左侧面板：变量/Watch/调用栈
├── ⑥ 修复代码 → 保存 → 热更新 → 继续验证
└── ⑦ TypeScript：Source Map 自动映射（.ts 断点）
```

## 2. Live Server 热更新工作流

### 2.1 Live Server 是什么

> **背景**：Live Server 是 VS Code 最流行的静态服务器扩展——保存自动刷新浏览器。
> **目的**：纯前端页面（无构建工具）的「保存即刷新」工作流。
> **适用范围**：HTML/CSS/JS 静态页面、教学演示、快速原型。
> **不适用场景**：有构建工具的项目（Vite/Webpack 自带 HMR）。

### 2.2 快捷键与配置

```text
Live Server 快捷键
├── Alt+L Alt+O：启动 Live Server（Go Live）
├── Alt+L Alt+C：停止
├── Ctrl+Shift+P → "Live Server: Open With Live Server" 也可启动
└── 状态栏 "Go Live" 按钮（鼠标入口）

配置要点（settings.json）
{
  "liveServer.settings.port": 5500,
  "liveServer.settings.ChromeDebuggingAttachment": true,
  "liveServer.settings.AdvanceCustomBrowserCmdLine": "chrome --remote-debugging-port=9222"
}
```

### 2.3 完整闭环（2026 热门组合）

```text
Live Server + Chrome 调试闭环（纯前端）
├── ① Alt+L Alt+O 启动服务器
├── ② 配置 ChromeDebuggingAttachment（远程调试端口）
├── ③ VS Code 调试选择 "Attach to Chrome"
├── ④ 效果：
│   改代码 → 保存 → 自动刷新 → 断点可命中
├── ⑤ 完整链路：编辑 → 刷新 → 调试（无需手动操作）
└── ⑥ 替代方案：Vite 项目自带 HMR（无需 Live Server）
```

## 3. React DevTools

### 3.1 安装与打开

```text
React DevTools（浏览器扩展）
├── ① Chrome 扩展商店安装 React Developer Tools
├── ② F12 → Components/Profiler 面板出现
├── ③ 生产环境显示「Not in production」（确认连接）
└── ④ 无面板 = 页面不是 React 或扩展未启用
```

### 3.2 Components 面板快捷键

```text
Components 面板（组件树调试）
├── ① 组件树导航：↑↓ 移动 / ←→ 展开折叠
├── ② 选中组件 → 右侧面板：
│   ├── Props：组件属性（修改实时生效）
│   ├── Hooks：hook 状态（useState/useEffect）
│   └── State：组件状态
├── ③ 搜索组件：Ctrl+F（按名称）
├── ④ 点击「查看源码」：跳转到 Sources 对应组件文件
├── ⑤ 定位 DOM：选中组件 → 点击 DOM 图标 → Elements 定位
└── ⑥ 反选：Elements 选中元素 → 组件图标 → 定位到组件

调试场景
├── Props 传错 → Components 看实际传入值
├── State 没更新 → Hooks 面板看状态
├── 组件不渲染 → 组件树看是否存在
└── 定位渲染代码 → 查看源码跳转
```

### 3.3 Profiler 面板（性能）

```text
Profiler（性能分析）
├── ① 点击录制按钮 → 操作页面 → 停止
├── ② 火焰图：组件渲染耗时（哪次渲染慢）
├── ③ 每次渲染的 Props 变化对比（为什么重渲染）
├── ④ 优化场景：找出不必要的重渲染
└── 快捷键：录制按钮（无需快捷键——操作少）
```

## 4. Vue DevTools

### 4.1 核心能力

```text
Vue DevTools（浏览器扩展）
├── ① 安装：Chrome 扩展 Vue.js devtools
├── ② F12 → Vue 面板出现（Components/Events 等）
├── ③ 组件树：层级查看 + 选中组件
├── ④ 右侧面板：
│   ├── Data：组件数据（修改实时生效）
│   ├── Props / Computed
│   └── Store（Pinia/Vuex 状态）
├── ⑤ 时间旅行：状态变更历史回放（调试状态问题）
└── ⑥ 事件追踪：Events 面板看事件发射

调试场景
├── data 不对 → Data 面板查看/修改
├── computed 不更新 → Computed 面板看依赖
├── 组件通信问题 → 组件树 + Events
└── Pinia 状态问题 → Store 面板
```

### 4.2 与 React DevTools 的对照

| 能力 | React DevTools | Vue DevTools |
|------|:---:|:---:|
| 组件树 | ✅ | ✅ |
| Props/Data 查看 | ✅ | ✅ |
| 状态修改 | ✅（实时） | ✅（实时） |
| Hooks 面板 | ✅ | - |
| Store 面板 | - | ✅（Pinia） |
| 时间旅行 | - | ✅（状态历史） |
| 性能分析 | ✅ Profiler | ⚠️ 基础 |

## 5. 接口调试工具（Postman/Apifox）

### 5.1 Postman 快捷键（2026）

| 快捷键 | 功能 |
|:---:|------|
| `Ctrl+N` | 新建请求/集合 |
| `Ctrl+S` | 保存请求 |
| `Ctrl+Enter` | **发送请求** |
| `Ctrl+\` | 切换侧边栏 |
| `Ctrl+Shift+P` | 命令面板 |
| `Tab` | 参数/头/体标签切换 |

```text
Postman 调试工作流
├── ① 从浏览器复制请求：DevTools → Copy as cURL → Postman Import
├── ② 或手动构建：Method + URL + Headers + Body
├── ③ Ctrl+Enter 发送 → 看响应
├── ④ 环境变量：{{base_url}}（环境切换）
├── ⑤ 断言测试：Tests 标签写脚本（自动验证）
└── ⑥ 集合运行：批量接口测试（CI 可集成）

Apifox（国内 2026 主流）
├── ① 接口管理 + Mock + 文档一体
├── ② 从 Swagger/OpenAPI 导入
├── ③ 快捷键与 Postman 类似（Ctrl+Enter 发送）
└── ④ 团队协作：接口文档与调试同步
```

## 6. 前端日常工作流

### 6.1 一天的完整键盘流

```text
前端开发一天（快捷键版）
├── 08:30  Ctrl+Shift+P → 打开项目 → Ctrl+` 开终端
├── 09:00  npm start（或 Alt+L Alt+O Live Server）
├── 09:30  F5 启动调试 → 代码 + 断点
├── 10:00  改组件 → Ctrl+S 保存 → 热更新 → F9 设断点验证
├── 11:00  接口联调：F12 Network 看请求 → Postman Ctrl+Enter 调试
├── 14:00  React/Vue DevTools 看状态
├── 15:00  Ctrl+Shift+F 全局搜索 → F12 跳定义
├── 16:00  性能：DevTools Performance 录制 → Profiler 分析
└── 17:00  提交代码前：格式化 + 检查
```

### 6.2 常见问题

```text
前端工作流常见问题
├── ⚠️ 热更新不生效：检查终端报错/缓存（Ctrl+Shift+R）
├── ⚠️ 断点不命中：
│   ① 开发模式确认（生产构建无 Source Map）
│   ② 文件路径对应（webRoot 配置）
├── ⚠️ DevTools 面板消失：确认扩展启用/刷新页面
├── ⚠️ CORS 拦截：代理配置或后端放行
├── ⚠️ Live Server 端口冲突：改端口
└── ⚠️ 调试附加失败：Chrome 远程调试端口被占用
```

## 7. 核心要点

> 🎯 **核心要点**：
> 1. VS Code 调试：launch.json（launch/attach 两种模式）+ F5 启动/F9 断点/F10/F11 单步——编辑器内完成调试闭环
> 2. Live Server：Alt+L Alt+O 启动 + ChromeDebuggingAttachment 配置——纯前端「保存即刷新」工作流
> 3. React DevTools：Components 面板看 Props/Hooks/State（修改实时生效）+ Profiler 性能分析
> 4. Vue DevTools：Data/Computed/Store 面板 + 时间旅行（状态历史回放）
> 5. Postman/Apifox：Ctrl+Enter 发送 + Copy as cURL 导入——接口调试标配
> 6. 断点不命中排查：开发模式确认 + webRoot 配置 + 热更新缓存
