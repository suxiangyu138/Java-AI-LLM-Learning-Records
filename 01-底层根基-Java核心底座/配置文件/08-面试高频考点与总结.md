## 1. 面试高频题与答题框架

### 1.1 基础类

**Q1：Spring Boot 配置加载的优先级？**

```text
答题框架（14 级分组记忆）：
① 运行期：命令行 --key > JVM 参数 -Dkey（调试/临时）
② 环境：SPRING_APPLICATION_JSON > 环境变量（部署/容器）
③ 远程：Nacos 配置中心（分布式标准）
④ 文件位置：外部 config/ > 外部根 > classpath:/config/ > classpath:/
⑤ 环境专属：application-{profile}.yml（覆盖基础）
⑥ 兜底：@PropertySource > bootstrap.yml > 代码默认值
⑦ 核心规则：同名 key 高者覆盖；不同 key 合并
⑧ 金句：命令行最高，代码默认最低；外部的压包内的
```

**Q2：@Value 和 @ConfigurationProperties 的区别？**

```text
① 绑定方式：@Value 单值注入；@ConfigurationProperties 整对象绑定
② 类型安全：@Value 运行时转换；@ConfigurationProperties 强类型
③ 校验：@Value 无；@ConfigurationProperties 支持 @Validated
④ 嵌套/集合：@Value 手写；@ConfigurationProperties 原生支持
⑤ 松散绑定：@Value 不支持（精确匹配）；@ConfigurationProperties 支持（timeout-ms ↔ timeoutMs）
⑥ 动态刷新：@Value 需 @RefreshScope；@ConfigurationProperties 更友好
⑦ 结论：企业规范业务配置用 @ConfigurationProperties + @Validated
```

**Q3：Profile 是什么？多环境怎么管理？**

```text
① 定义：环境选择开关（dev/test/prod）
② 机制：spring.profiles.active 激活 + application-{profile}.yml 覆盖
③ 激活三方式：配置文件默认（dev）/ 环境变量 / 命令行（最强）
④ 铁律：默认写 dev，生产必须外部注入（防本地连生产库）
⑤ 隔离：数据库/中间件/密钥/日志全隔离；Nacos Namespace 物理隔离
⑥ 金句：环境差异是配置问题不是代码问题——代码零环境判断
```

### 1.2 外部化配置类

**Q4：外部化配置是什么？为什么需要？**

```text
① 定义：配置与代码分离，运行时可覆盖（环境变量/命令行/外部文件）
② 价值：一套 jar 跑所有环境；敏感信息不进包；不改代码调参数
③ 12-Factor 原则：环境差异用配置表达
④ 分层：包内默认 + 外部文件 + 配置中心 + 环境变量
⑤ 反模式：硬编码路径/密码/环境判断（if env == prod）
```

**Q5：环境变量怎么映射 Spring 属性？**

```text
① 宽松绑定：server.port ↔ SERVER_PORT（点变下划线、大写）
② myapp.timeout-ms ↔ MYAPP_TIMEOUTMS（- 变 _）
③ 复杂结构：SPRING_APPLICATION_JSON（JSON 环境变量）
④ 数组：MYAPP_HOSTS_0=node1 索引式
⑤ 注意：环境变量全是字符串——类型转换由 Spring 处理
⑥ 场景：Docker -e / K8s ConfigMap/Secret
```

**Q6：密码为什么不能传命令行参数？**

```text
① ps 可见：进程命令行对所有用户可见（ps aux）
② Docker 历史：docker inspect 可见命令行（含密码！）
③ 正确方式：环境变量 / Secret / 文件注入
④ 补充：配置文件也不落明文（占位符 + 外部注入）
⑤ 金句：敏感信息的三不原则——不进代码库、不进命令行、不进日志
```

### 1.3 配置中心类

**Q7：配置中心解决了什么问题？**

```text
① 背景：微服务配置散落 → 改公共配置要改 N 个服务
② 五大价值：集中管理/动态刷新/环境隔离/变更审计/灰度
③ 场景：业务开关/日志级别/限流阈值（动态调整）
④ 权衡：增加组件复杂度——单体别过度设计
⑤ 2026 结论：国内 Java 生态默认 Nacos（与注册中心一体）
```

**Q8：Nacos 动态刷新怎么实现？有什么坑？**

```text
① 链路：Nacos 修改 → 客户端长轮询感知 → Environment 刷新 → @RefreshScope 重建
② 标准组合：@ConfigurationProperties + @RefreshScope
③ 坑 1：@Value 需 @RefreshScope 才刷新
④ 坑 2：static 字段永远不刷新
⑤ 坑 3：数据源连接池不重建（改地址无效，需重启）
⑥ 适用：日志级别/开关/阈值；不适用：连接池/已持引用
```

**Q9：Nacos Data ID 命名规范？加载不到怎么排查？**

```text
① 规范：{app-name}-{profile}.{ext}（order-service-prod.yaml）
② 服务名必须与 spring.application.name 一致
③ 静默失败：Data ID 不匹配不报错（危险特性）
④ 排查：--debug 看启动日志是否有 Nacos 配置源
⑤ 补充：file-extension 与 Data ID 扩展名必须匹配
```

**Q10：配置中心挂了怎么办？**

```text
① 三层兜底：Nacos → 本地快照（客户端缓存）→ 包内默认
② 降级策略：非敏感配置降级+告警；敏感配置 fail-fast
③ HealthIndicator：NacosConfigManager 注册健康检查
④ 高可用：≥3 节点集群 + MySQL 持久化（不用内嵌 Derby）
⑤ 金句：配置中心不是单点依赖——设计上必须可降级
```

### 1.4 安全类

**Q11：敏感配置怎么管理？**

```text
① 四方案：环境变量（基础）/ K8s Secret（标准）/ KMS-Vault（强）/ 配置加密（配置中心）
② 配置中心敏感值：ENC 加密存储 + 密钥走 KMS/环境变量（双保险）
③ 防泄露五道防线：.gitignore / pre-commit hook / CI gitleaks / 模板文件 / 配置分离
④ 日志脱敏：启动日志不打印配置、异常脱敏
⑤ 金句：配置泄露 = 系统边界的失守——先轮换再清理
```

**Q12：.env 文件能不能提交 Git？**

```text
① 绝对不能：.env 泄露是 GitHub 最高频密钥泄露原因
② .gitignore 必须包含 .env* / *.pem / *.key
③ 模板方案：.env.example 可提交（占位符）
④ 检测：gitleaks 扫描（pre-commit + CI + 全量）
⑤ 已泄露处理：先轮换密钥，再 git filter-repo 清历史
```

### 1.5 排查与实战类

**Q13：配置没生效怎么排查？**

```text
① 三板斧：--debug（看配置源加载）/ /actuator/env/{key}（溯源）/ Environment 遍历
② 四类问题：加载/覆盖/绑定/刷新
③ 常见：properties 与 yml 并存（properties 优先）/ profile 拼写 / 编码
④ 金句：配置问题本质是来源定位问题
```

**Q14：bootstrap.yml 和 application.yml 的区别？**

```text
① 加载时机：bootstrap 最早（引导阶段）
② 作用：配置中心地址等引导配置
③ 优先级：bootstrap 最低（任何源可覆盖）
④ 版本差异：Spring Boot 2.4+ 默认禁用 bootstrap（需 starter-bootstrap）
⑤ 3.x 推荐：spring.config.import 替代
```

**Q15：配置类怎么测试？**

```text
① 绑定测试：@SpringBootTest 验证字段与 yml 匹配
② 默认值测试：@SpringBootTest(properties = "key=") 验证兜底
③ 校验测试：非法值验证启动失败（fail-fast）
④ 环境测试：不同 profile 加载验证
⑤ 金句：配置测试防「配置改了代码不知道」
```

**Q16：生产环境配置有哪些安全红线？**

```text
① 密码/密钥只留占位符（无默认值）
② 启动日志不打印敏感配置
③ actuator/env 生产禁开（或脱敏 + 内网）
④ 命令行不传密码（ps 可见）
⑤ 配置中心敏感值加密 + 权限控制
⑥ 生产 profile 外部注入（不写死在 yml）
```

## 2. 优先级速查表

```text
高 ┌─────────────────────────────────────────┐
   │ 命令行参数 --key=value                  │
   │ JVM 系统属性 -Dkey=value                │
   │ SPRING_APPLICATION_JSON                 │
   │ JNDI 属性（遗留）                       │
   │ 操作系统环境变量（宽松绑定）             │
   │ Nacos 配置中心（远程）                  │
   │ 外部 config/ 目录                       │
   │ 外部当前目录                            │
   │ classpath:/config/                      │
   │ classpath:/application.yml              │
   │ application-{profile}.yml               │
   │ @PropertySource                         │
   │ bootstrap.yml                           │
   │ 代码默认值 ${key:default}               │
低 └─────────────────────────────────────────┘
记忆：命令行最高，代码默认最低；外部压包内；环境变量压配置中心
```

## 3. 五大常见误区

| # | 误区 | 真相 |
|---|------|------|
| 1 | 「配置写死也能跑」 | Windows 能跑 ≠ 跨环境能跑——硬编码路径/密码是事故源 |
| 2 | 「@Value 和 @ConfigurationProperties 差不多」 | 类型安全/校验/嵌套/刷新差距巨大——生产用后者 |
| 3 | 「bootstrap.yml 永远生效」 | Spring Boot 2.4+ 默认禁用——3.x 用 spring.config.import |
| 4 | 「配置中心挂了服务就挂」 | 设计上必须可降级（本地快照 + 包内兜底） |
| 5 | 「.env 提交没关系（私有仓库）」 | 私有仓库也会泄露（协作者/机器人扫描）——永不提交 |

## 4. 一句话总结全系列

```text
01 格式：YAML（服务配置）/TOML（构建）/properties（遗留）/JSON（交换）——各归其位
02 体系：application.yml + @Value/@ConfigurationProperties + 占位符/松散绑定/校验
03 优先级：命令行最高代码默认最低；同名覆盖不同名合并；外部压包内
04 多环境：Profile 机制 + 默认 dev 生产外部注入 + 环境隔离红线
05 Nacos：Data ID 规范 + @RefreshScope 动态刷新 + Namespace 隔离 + 三层兜底
06 安全：三不原则（不进库/不进命令行/不进日志）+ 加密 + 泄露先轮换
07 排查：三板斧（--debug/actuator/env/Environment）+ 配置即代码 + 评审审计
08 面试：16 题框架 + 优先级速查 + 避坑清单
```

> 🎯 **系列总结**：配置文件 = **代码与环境的边界**——格式选型、Spring Boot 绑定机制、14 级优先级、多环境隔离、配置中心、安全加密、排查方法论，七层构成完整配置管理能力。2026 年的配置管理标准答案：**分层配置（包内默认 + 配置中心动态 + 环境变量敏感）+ 类型安全绑定 + 加密与审计**——掌握这套体系，配置不再成为生产事故的来源。
