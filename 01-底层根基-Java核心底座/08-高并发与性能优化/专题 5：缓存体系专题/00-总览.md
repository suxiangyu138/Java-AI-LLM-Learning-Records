# 缓存体系专题 · 知识体系总览

> 缓存是高并发系统性价比最高的第一杠杆——一个命中率 95% 的缓存能把数据库 QPS 砍掉 95%。本专题站在"性能"视角：从原理到分层架构、从三大问题到一致性、从本地到分布式、从治理到容量，2026 年的共识是"缓存治理是体系化工程，不只是加一层 Redis"

## 6. 十大常见误区

1. **缓存 = Redis**：分层缓存链路上 Redis 只是 L2，浏览器/CDN/本地缓存常被忽略，链路收益白白浪费。
2. **命中率越高越好**：命中率是手段不是目标，过大的缓存容量挤占业务内存，且一致性窗口变大。
3. **先删缓存再更 DB**：高并发下读请求会把旧值回填，产生永久脏数据；先更 DB 后删缓存才是主流。
4. **延迟双删包治百病**：延迟靠经验拍脑袋、删除失败无兜底，双删只是兜底不是保证，核心数据要上 Canal。
5. **加缓存就能解决一切**：写多读少、强一致、一次性数据场景不该用缓存，加了反而引入一致性与故障域。
6. **过期时间全院统一**：统一 TTL 是雪崩的温床；不同数据按变更频率分档，再加随机抖动。
7. **热点 key 靠人工圈定**：大促前不建热点识别机制，活动开始才发现热点打穿 DB，为时已晚。
8. **本地缓存不值得用**：单机 QPS 上万时 Redis 网络往返是瓶颈，Caffeine 微秒级 L1 收益巨大。
9. **缓存挂了就完了**：没有降级预案（直连 DB + 限流）的缓存是单点；Redis 故障时服务要能兜底存活。
10. **只配 maxmemory 不管淘汰**：默认 noeviction 下写满直接报错；缓存场景必须显式选择淘汰策略。

## 7. 一周学习计划

- **Day 1**：00 总览 + 01 原理，画出自己项目当前的分层缓存链路，标出缺失层。
- **Day 2**：02 分层架构，给静态资源配 CDN 缓存头，统计请求命中率与字节命中率。
- **Day 3**：03 三大问题 + 04 一致性，给自己接口的缓存加空值防护与过期随机化。
- **Day 4**：05 本地缓存，用 Caffeine 重构一个热点接口的 L1 缓存，开启 recordStats 观察命中率。
- **Day 5**：06 分布式缓存，检查 Redis maxmemory 与淘汰策略，用 HOTKEYS 扫一遍热点。
- **Day 6**：07 热点治理 + 08 并发降级，给热点 key 加多副本扩散与单飞保护，写降级预案。
- **Day 7**：09 监控容量 + 10 自测，搭命中率监控看板并做一次预热演练，完成 20 题自测。

## 8. 快速自测 10 题

1. 缓存成立的物理依据是什么？命中率如何决定平均延迟？
2. 分层缓存链路上有哪些层？每层各缓存什么数据？
3. 穿透/击穿/雪崩的触发条件与核心解法分别是什么？
4. 为什么主流是"先更新 DB 再删除缓存"？四种双写策略各自的坑？
5. 延迟双删的延迟时间怎么定？它的局限是什么？
6. W-TinyLFU 解决了 LRU 与 LFU 各自的什么缺陷？
7. Redis 8.6 新增的 LRM 淘汰策略与 LRU 有什么区别？适用什么场景？
8. 热点 key 的识别手段有哪些？多副本扩散方案的原理？
9. singleflight 的正确使用姿势是什么？为什么必须双重检查缓存？
10. 命中率告警阈值怎么定？缓存容量规划为什么必须与命中率联动？
