| 概念 | 一句话本质 | 所在篇 |
|---|---|---|
| 雪崩 | 单点故障经线程池/连接池耗尽逐级放大为系统级宕机 | 01 |
| 固定窗口 | 时间窗内计数，边界处可放行 2 倍流量 | 03 |
| 滑动窗口计数 | 两个窗口加权近似，O(1) 内存、误差 <1% | 03 |
| 令牌桶 | 恒定速率补充 + 桶容量兜突发，工业界最常用 | 03 |
| 漏桶 | 恒定速率输出，流量绝对平滑，无突发 | 03 |
| Lua 原子限流 | Redis 单线程执行脚本，读改写一次 RTT 完成 | 05 |
| fail-closed | 限流后端不可用时拒绝放行，防击穿 | 05 |

| 舱壁隔离 | 依赖/资源隔离，一个舱进水不沉全船 | 08 |
| 分级降级 | 按业务优先级 L1/L2/L3 定义兜底链，保核心弃非核心 | 07 |

## 6. 十大常见误区

1. **加机器就能抗大促**：限流阈值不按压测设置，扩容再多也会被瞬时流量打穿。
2. **限流就是网关限一次**：单层限流挡不住热点与业务维度攻击，需要网关+应用双层。
3. **固定窗口够用**：窗口边界 2 倍突刺在秒杀场景就是击穿。
4. **Redis 限流用 INCR 就行**：读改写非原子，并发下会超发；必须 Lua。
5. **熔断阈值拍脑袋**：慢调用阈值应取 2-3 倍 P99，错误率阈值应设最小调用数防误触。
6. **熔断了就完事**：熔断不配降级兜底，用户体验是"直接报错"而不是"排队稍后"。
7. **降级预案上线时再想**：预案必须在压测前设计并演练，故障时没人能冷静设计 fallback。
8. **线程池隔离就是万能**：每依赖一个线程池，线程数×依赖数会放大资源成本，小依赖用信号量。
9. **限流失败要放行**：fail-open 在 Redis 抖动时等于没有限流；关键链路必须 fail-closed。
10. **规则写死配置里**：限流熔断阈值必须动态下发（Nacos），大促调参不重启。
