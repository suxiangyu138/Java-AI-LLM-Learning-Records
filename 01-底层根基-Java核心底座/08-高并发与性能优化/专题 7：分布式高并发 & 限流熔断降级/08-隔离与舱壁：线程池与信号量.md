## 1. 舱壁思想与隔离的三个层次

船的分舱设计：一个舱进水，水被隔在舱内，船不沉。对应到系统：**每个依赖（下游服务、DB、外部 API）独占一份资源（线程池/信号量/连接池），一个依赖打满只影响自己，不拖垮全局**。没有隔离时，库存服务耗尽线程池，同进程的订单服务、营销服务一起遭殃——[雪崩链条](01-分布式高并发全景与雪崩链条.md)里"同机其他服务被拖死"就是这么发生的。

隔离按粒度分三个层次：

- **资源隔离**：线程池/信号量按依赖隔离（本节重点）。
- **集群隔离**：按业务/租户划分独立集群或独立实例池，大促时为交易链路单独部署一组实例，营销活动与交易互不干扰。
- **架构隔离**：读写分离、独立部署非核心功能（评论、推荐单独集群），物理上杜绝传染。

## 2. 线程池隔离：物理隔离的代价

Hystrix 的经典方案：**每个下游依赖一个独立线程池**（如订单服务线程池、库存服务线程池各 10 线程）。库存依赖打满，订单池的线程照常运行——物理上不可传染，同时每个池的指标（活跃线程、队列深度）天然形成该依赖的健康仪表盘，故障定位直接看池。

代价同样明确：**线程成本与依赖数量成正比**。一个服务依赖 10 个下游 = 10 个线程池；每个线程池还要留余量，总线程数爆炸，上下文切换开销抵消收益。Hystrix 当初建议线程池线程数 = 峰值 QPS × P99 延迟（秒），是"容量换隔离"。

2026 年的新变量是**虚拟线程**（JDK 21+）：阻塞不再占载体线程，线程成本骤降，理论上"每依赖一个虚拟线程池"的物理隔离可以以极低代价铺开。但虚拟线程本身不解决阻塞资源（连接池、外部服务的并发上限），且 synchronized 会 pin 载体线程——这也是 Resilience4j 2.3.0 把内部统计改为无锁的直接动机（[06 篇](06-熔断机制：状态机与参数设计.md)）。虚拟线程时代的隔离设计，本质是把"线程数隔离"升级为"资源配额隔离"。

## 3. 信号量隔离：轻量但防线单薄

Sentinel 默认的信号量隔离：**不换线程，只计数**——调用前信号量 tryAcquire，占用数超阈值直接拒绝（快速失败），调用结束 release。开销极小（一个原子计数），适合调用量大的同步快速路径，也天然适配异步非阻塞调用（不阻塞事件循环线程）。

短板同样明显：**信号量只挡"并发数"，挡不住"慢调用"**——10 个并发全是慢调用（每个 5 秒），信号量照样放行，线程持续被占用；而线程池隔离下，池里的线程被慢调用占满后新任务排队，指标直接暴露问题。Sentinel 的解决方式是**信号量 + 熔断（慢调用比例）组合**：信号量挡并发峰值，熔断在慢调用比例超标时切断调用。选型口诀：**快调用（RT 低）用信号量，慢调用或混合用线程池**。

## 4. 隔离粒度选择

隔离粒度是"成本与效果"的权衡，三个判断标准：

1. **依赖故障是否致命**：核心交易依赖（支付、库存）必须线程池隔离；周边依赖（推荐、画像）信号量够用。
2. **调用时长与阻塞性**：RT > 100ms 的阻塞调用用线程池，短促调用用信号量。
3. **依赖数量**：依赖 <5 个且都重要 → 全线程池；依赖多且杂 → 分层（重要的池隔离，其余信号量）。

大促实践的标准形态是**按链路隔离**：交易主链路（下单→支付）独立线程池 + 独立集群，营销/推荐链路降级到信号量或直接功能降级（[07 篇](07-降级与兜底预案：分级设计.md)）。隔离 + 降级组合使用：池打满 → 熔断 → 降级兜底，三级联动才算完整防线。

容易被忽略的是**连接池隔离**：数据库连接池、Redis 连接池是比线程更稀缺的资源——一个慢 SQL 占住连接，其他链路全部排队等连接。生产规范是核心链路用独立连接池（或至少独立的最大连接数配额），配合连接超时（获取连接超过 200ms 直接失败）而不是无限等待。线程隔离只挡了"线程层面的传染"，连接池隔离挡的是"资源层面的传染"，两者叠加才是完整舱壁。

## 5. 超时金字塔：隔离的基石

没有超时的隔离是假的——慢调用不超时，线程池/信号量迟早被打满。超时设计必须成体系，逐层递减：

```
调用方总超时 3s
├── DNS 解析 500ms
├── 建连（TCP/TLS） 500ms
├── 读超时 1.5s
└── 写超时 1s
```

三个纪律：**层层递减**（内层超时 < 外层，否则外层超时永远不触发）；**不设"无限"**（任何 connect/read 都要显式超时）；**超时与重试算总账**（单次 500ms × 重试 3 次 = 1.5s，必须小于链路总超时，否则用户侧先超时，重试毫无意义）。超时触发后进入重试（幂等 + 指数退避）或熔断统计——**超时是熔断的输入信号**，超时金字塔是[06 篇](06-熔断机制：状态机与参数设计.md)与本节所有机制的物理前提。

> 🎯 **核心要点**：隔离阻断雪崩的物理传播，分资源/集群/架构三层；线程池隔离物理阻断但成本与依赖数成正比，虚拟线程时代要升级为资源配额视角；信号量隔离轻量但挡不住慢调用，需与熔断组合；粒度按"依赖致命性 × 调用时长 × 依赖数量"选择；超时金字塔（层层递减、不设无限、算重试总账）是隔离体系的地基。
