## 1. 复盘报告模板：可直接照抄的结构

按[01 篇](01-故障复盘方法论：无指责与四步法.md)的四步法，报告固定九段式（[00 篇](00-总览.md) 的参考来源有 Rootly/incident.io 的完整模板）：

1. **摘要**：一句话讲清事故（时间、影响、根因类型）——供管理层与后来者快速判断"是否与我相关"。
2. **影响**：量化——受影响用户数/请求数、故障时长、SLO 预算消耗（如"P99 劣化 4 小时，消耗本月 30% 错误预算"）。
3. **时间线**：UTC 时间戳按分钟记录——发现、告警、止血动作、恢复，每条对应责任人（来自[02 篇](02-故障分级与响应机制.md) 的记录员）。
4. **促成因素**：2-5 个，系统视角表述（"监控未覆盖该指标"而非"没人看监控"）。
5. **做得好的地方**：不回避——记录有效的止血动作与响应，这是团队的正向资产。
6. **根因分析**：5 Whys 或因果树，指向可修复的系统缺口。
7. **行动项**：缓解性 + 预防性，每条带责任人（自然人）+ 截止日期 + 优先级。
8. **经验教训**：对团队的通用启示（"此类变更需压测"）。
9. **验证方式**：行动项如何验证有效（演练/压测/监控确认）。

发布纪律：**48 小时内完成**，存入事故库（可检索），Sev 1 在 5 个工作日内开评审会。

写报告的两个实用技巧：**时间线用工具自动生成**（故障群消息/告警记录导出，人工回忆的时间线不可靠——[02 篇](02-故障分级与响应机制.md) 的记录员职责就在此）；**影响量化不要猜**（用监控数据算"故障时段失败请求数/受影响用户数"，写"影响约 1.2 万用户"而不是"影响很大"）——无指责复盘（[01 篇](01-故障复盘方法论：无指责与四步法.md)）的文档要求"基于事实"，这两条是把事实落地的具体动作。

## 2. 故障速查表

| 现象 | 第一怀疑 | 处置 |
|---|---|---|
| 下单接口成功率骤降 | 最近变更（发布/配置/DB） | 查变更时间线，优先回滚 |
| 线程池打满 | 下游无超时/慢 SQL/重试风暴 | jstack 看阻塞资源，对症下药 |
| Redis 延迟突增 | 大 Key/慢命令/持久化 fork | --bigkeys + INFO commandstats |
| 缓存命中率骤降 | 大 Key 击穿/降级反噬/OOM 淘汰 | 查 TTL 与降级策略，多级缓存 |
| MQ 堆积 | 生产洪峰 or 消费瓶颈 | 看 lag 与消费耗时，先止血再查因 |
| 数据库 CPU 100% | 慢 SQL（深分页/锁/DDL） | processlist + explain，找到那条 SQL |
| 全链路超时 | 网络抖动/依赖故障 | 链路追踪归因，熔断快速失败 |
| 故障恢复后又挂 | 恢复后重试风暴 | 恢复限流 + 退避抖动 |

## 3. 应急响应流程速查

故障发生时的标准动作序列（[02 篇](02-故障分级与响应机制.md) 的压缩版）：

1. **确认与分级**：确认告警真实性，按影响面定 P 级，P0/P1 立即拉群。
2. **止血**（与定位并行）：先回滚/限流/扩容/摘流把影响控制住——**止血优先于根因**；止血动作由指挥官批准并记录时间线（[02 篇](02-故障分级与响应机制.md) 的八种手段按侵入性从低到高选）。
3. **定位**：拉时间线（发布在前？告警在前？）→ 四层排查（症状/资源/变更/依赖）→ 工具下钻。
4. **恢复确认**：监控指标回到基线 + 持续观察 30 分钟（防恢复后风暴）。
5. **记录**：时间线记录员全程留痕（这是复盘的第一手材料）。
6. **复盘**：48 小时内出报告，行动项进工单跟踪。

## 4. 毕业检查单

- 能用无指责语言完成一次复盘，报告九段式完整、48 小时内发布
- 能按影响面定 P0-P3 并给出止血手段排序
- 熟悉 JVM/Redis/DB 定位工具组合，能在 30 分钟内给出初步定位
- 能讲清缓存三兄弟（穿透/击穿/雪崩）与"善意降级反噬"机制
- 能画出慢 SQL→连接池→线程池→雪崩的传导链并指出防护点
- 理解重试放大与恢复后风暴，能给出退避与恢复限流配置
- 掌握变更管控四件套，能对公共库变更做影响半径评估
- 能设计并执行一次 GameDay 演练，产出闭环行动项

4. P0 与 P1 的判定标准差异？八种止血手段列 5 个。
5. Incident Commander 的核心职责是什么？
6. 四层排查法的顺序是什么？为什么变更层要先看？
7. --bigkeys 与 --hotkeys 分别解决什么问题？
8. 缓存穿透、击穿、雪崩的区别？
9. 慢 SQL 的经典传导链是什么？

> 🎯 **核心要点**：复盘报告九段式模板可直接照抄，48 小时内发布进事故库；故障速查表覆盖八类高频现象（变更/线程池/Redis/缓存/MQ/DB/网络/恢复风暴）；应急六步（确认分级→止血→定位→恢复确认→记录→复盘）以止血优先；毕业检查单 8 项 + 20 题通过，即具备独立处理线上故障、完成高质量复盘、建设演练体系的能力。
