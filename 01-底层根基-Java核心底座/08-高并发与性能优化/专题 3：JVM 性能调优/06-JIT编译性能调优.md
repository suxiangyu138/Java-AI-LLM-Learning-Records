## 1. 分层编译与热点识别

JVM 默认分层编译（Tiered Compilation），方法随调用热度逐级编译：

- **0 解释执行**：启动期，无编译开销但执行慢。
- **1-3 C1 编译**：带 profiling 的快速编译，编译快、优化浅，为 C2 收集热点数据。
- **4 C2 编译**：深度优化，编译慢但执行最优。C2 的优化（逃逸分析、内联、循环优化）是 JVM 吞吐的引擎。

性能含义：**服务吞吐的"热身"时间 = C2 完成关键方法编译的时间**。压测刚启动的服务会看到吞吐随时间爬升，就是这个过程。线上"启动后前几分钟毛刺多"的常见来源之一，就是解释执行 + 反优化（C2 判定 profiling 数据变化而回退层级）。

调优认知：编译参数（`CompileThreshold` 等）一般不动——C2 的默认启发式经过二十年调校。真正有效的两个方向：**给 Code Cache 留足空间**（默认 240MB，大型服务编译量大时 `-XX:ReservedCodeCacheSize=512m`，满了会退化为解释执行）与**预热**（第 4 节）。

## 2. 逃逸分析三件套

C2 分析对象是否逃逸（被方法外部引用），不逃逸则应用三种优化，**从根上消灭堆分配**：

- **标量替换**：对象字段拆成局部标量，对象根本不创建——方法内的临时 DTO、Point、局部 String 拼接结果都可能被替换。
- **栈上分配**：少量对象直接分配在栈帧，方法返回即销毁，不进堆、不劳烦 GC。
- **锁消除**：对象不逃逸则其上的 synchronized 同步被移除——`StringBuffer` 局部变量拼接、局部 HashMap 操作都在此列。

对调优的启示：**逃逸分析是"写友好代码换性能"的最佳例子**——方法局部、无引用逸出的小对象是免费的（不产生 GC 压力）；对象一旦被缓存、被返回、进容器，逃逸分析立刻失效，转化为真实分配。用 `-XX:+PrintEliminateAllocations`（诊断参数）可确认替换效果；业务侧优化就是**保持临时对象不逃逸**，这与 [专题 2](../专题%202：Java%20单机并发编程/02-synchronized与volatile深潜.md) 的锁消除话题同源。

## 3. 内联与 Code Cache

- **内联**：C2 把热点小方法直接展开进调用方，消除调用开销——这是 JIT 收益最大的单一优化。判断标准：方法字节码小（默认阈值内）、调用频繁。对业务代码的启示：**热点路径避免深调用链**，把高频方法写小、写在调用方近旁，比任何参数都实在。
- **Code Cache**：编译产物存放区，默认上限约 240MB（JDK 8 起 ReservedCodeCacheSize）。满则停止新编译、回退解释执行——症状是**运行一段时间后吞吐突然下降且 CPU 升高**。排查：`jcmd <pid> Compiler.codecache` 看使用率，`-XX:+PrintCodeCache` 确认。调大上限即可，属少数真正值得调的 JIT 参数。

## 4. 预热策略

预热的目标是让**流量高峰到达前** C2 已完成关键路径编译：

- **启动后健康检查触发预热**：服务上线流程中，压测/健康检查请求先打若干轮核心接口，编译自然完成。
- **代码显式预热**：`@PostConstruct` 里循环调用核心服务方法（数千次），触发编译阈值；注意预热数据要用真实形态的假数据，避免序列化路径不同。
- **压测必做**：压测结果只取"吞吐稳定后的区间"——预热前数据反映的是编译过程，不是稳态性能，会误导容量决策（[专题 1](../专题%201：性能理论基础/04-性能测试方法论.md)）。
- **慎用参数**：`-XX:CompileThreshold` 调小会加快编译但增加 C2 负担，非必要不动。

## 5. CDS 与 AOT：启动性能

启动性能是 2026 年 JVM 调优最热的新战场，三个层次渐进：

- **CDS（类数据共享）**：JDK 13+ 动态归档（`-XX:ArchiveClassesAtExit` / `-XX:SharedArchiveFile`），把类加载结果缓存，下次启动直接映射。Spring Boot 3.5 已支持自动化 CDS 归档，`java -XX:+AutoCreateSharedArchive` 一键开启。
- **JEP 483（JDK 24）AOT 类加载与链接**：在 CDS 之上进一步缓存**链接状态**（字节码校验、常量池解析、方法/字段链接）。训练运行（`-XX:AOTMode=record`）→ 生成缓存（`create`）→ 生产运行（`on`）。Spring PetClinic 实测启动快约 41%（约 2.1 万类预加载链接）。
- **JEP 516（JDK 26）AOT 对象缓存**：把对象也缓存进归档，且**支持任何 GC 含 ZGC**（对象引用以逻辑索引存储、启动时重映射）——之前 ZGC 因着色指针与缓存不兼容而被排除在外，现在训练用 G1、部署用 ZGC 的组合成为可能。实测 Spring Boot 3.5 + Java 26 AOT 缓存把微服务启动从约 3 秒压到 0.8 秒。

落地注意：AOT 缓存与类路径/模块图强绑定，依赖版本、启动参数变更需重新生成缓存（CI 里随版本归档）；带 `--patch-module` 等场景缓存自动禁用。启动优化的边界是**不改变 JVM 语义**——与 GraalVM Native Image 的"编译成原生二进制"路线不同，Leyden 方案保持 JVM 全能力，是 Java 主流的演进方向。

> 🎯 **核心要点**：JIT 吞吐引擎是 C2，热身即 C2 编译，预热与压测稳态取数是一体两面；逃逸分析让"不逃逸的临时对象"免费——写友好代码胜过调编译参数；Code Cache 满会退化为解释执行，是唯一高收益的编译参数；启动优化三层次 CDS → JEP 483 AOT 类加载 → JEP 516 AOT 对象缓存，Spring Boot 3.5 自动归档 + JDK 26 可把启动压到 1 秒内，AOT 缓存要随版本归档重新生成。
