## 5. 核心概念速查

| 概念 | 一句话本质 | 所在篇 |
|---|---|---|
| 顺序写 | 追加式写入，无寻道，SSD/HDD 性能相差数十倍 | 02/09 |
| 页缓存 PageCache | OS 缓存磁盘页，命中即内存速度 | 02/09 |
| 零拷贝 | 跳过用户态拷贝，内核态直达网卡/磁盘 | 07 |
| KRaft | Kafka 4.0 起的 Raft 元数据自管理，去 ZooKeeper | 02 |
| 多路复用 | 单线程监听海量连接事件，epoll O(1) | 05 |
| 虚拟线程 | JDK 21+ 百万级线程，阻塞代码高并发 | 05 |
| EventLoop | 一个线程绑定多连接的事件循环，串行无锁 | 06 |
| 内存池 | 预分配 ByteBuf，减少 GC 与分配开销 | 06 |
| triple 协议 | Dubbo 3.3 基于 HTTP/2+Protobuf，兼容 gRPC | 04 |
| TLV 编码 | Protobuf 的 Tag-Length-Value 紧凑结构 | 07 |
| 仲裁队列 | RabbitMQ 4.x 默认，数据多副本高可靠 | 03 |
| group commit | 批量刷盘，日志系统吞吐的关键 | 09 |

## 6. 十大常见误区

1. **MQ 吞吐不行就加机器**：吞吐瓶颈常在分区数与参数，横向扩容前先纵向调优。
2. **Kafka 快是因为写磁盘**：快在顺序写+页缓存+零拷贝的组合，不是"磁盘本身快"。
3. **linger.ms 设 0 最好**：牺牲批量换取延迟，吞吐可能掉一个数量级；先想清楚业务要吞吐还是延迟。
4. **RPC 慢就换序列化**：序列化通常只占 10% 延迟，先查连接复用、线程模型与网络往返。
5. **Netty 是"高性能"所以默认最快**：默认参数（分配器、线程数）是通用值，不调优一样有瓶颈。
6. **io_uring 一定比 epoll 快**：高吞吐场景收益明显，延迟敏感小请求未必，且要内核 5.19+。
7. **有了虚拟线程就不需要 NIO**：虚拟线程解决线程数，不解决系统调用与内核拷贝，两者是不同维度。
8. **JSON 够用就不用 Protobuf**：高吞吐内部链路体积差 4-5 倍，带宽与 GC 都是成本。
9. **TCP_NODELAY 开了就低延迟**：只解决 Nagle，还有确认延迟、重传、对端处理时间。
10. **刷盘越勤越安全**：每次 fsync 吞吐骤降；WAL+group commit 才是数据库级方案。

## 7. 一周学习计划

- **Day 1**：00 总览 + 01 方法论，画出自己项目请求链路上所有中间件与 IO 环节。
- **Day 2**：02 Kafka，用压测数据审视自己集群的生产者参数与分区数。
- **Day 3**：03 横向对比，给自己业务做一次 MQ 选型复盘。
- **Day 4**：04 RPC，检查 Dubbo/gRPC 的连接数、超时与序列化配置。
- **Day 5**：05 IO 模型 + 06 Netty，读懂一次网络请求在内核与应用间怎么流动。
- **Day 6**：07 零拷贝 + 08 网络治理，检查大文件下载与连接池配置。
- **Day 7**：09 磁盘 IO + 10 自测，梳理 WAL/刷盘策略并完成 20 题自测。

## 8. 快速自测 10 题

1. Kafka 高性能四支柱是什么？为什么顺序写是关键？
2. KRaft 相比 ZooKeeper 解决了什么？控制面切换快多少？
3. RocketMQ 同步刷盘与异步刷盘差多少吞吐？什么场景必须同步？
4. Dubbo 3.3 的 triple 协议为什么是官方推荐？它与 gRPC 什么关系？
5. BIO/NIO/多路复用/虚拟线程各自解决什么问题？
6. epoll 为什么是 O(1)？io_uring 比 epoll 强在哪？
7. Netty 的 EventLoop 为什么不需要加锁？内存池怎么减少 GC？
8. 传统 IO 读文件发网络要几次拷贝？sendfile 之后剩几次？
9. Protobuf 比 JSON 小多少？快多少？代价是什么？
10. 大量 CLOSE_WAIT 说明什么？TIME_WAIT 大量出现正常吗？
