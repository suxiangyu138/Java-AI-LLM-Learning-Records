## 1. 生产压测的两大风险

在生产环境压测，两个风险不解决就是事故：

- **数据污染**：压测产生的订单、库存、用户数据写进生产库——订单统计翻倍、库存被压测扣光、风控模型被污染。数据污染是生产压测最常见的翻车点。
- **真实用户受影响**：压测流量与真实流量抢资源，压测失控时真实请求延迟飙升——必须有"压测流量可识别、可隔离、可秒停"的机制。

隔离的目标是双重的：**流量隔离**（区分压测与真实流量）+ **数据隔离**（压测数据不落生产存储）。2026 年的成熟技术体系是"流量染色/打标 + 影子库/表/缓存/队列隔离 + 流量录制回放 + 全链路监控"。

## 2. 流量打标 vs 机器打标

生产压测的流量隔离主流是两种方案：

- **流量打标（染色）**：压测流量打上特殊标记（如 HTTP 头 `X-Pressure-Test: true`），全链路组件识别标记后把请求路由到影子资源。改造点在中间件层（网关识别标记并传递、RPC 透传、MQ 打标），业务代码几乎不动——**成本低，阿里、美团均采用此路线**，是 2026 年的主流选择。
- **机器打标（独立部署）**：压测机器独立部署，压测流量天然只在压测机器上，配合独立 DB/MQ——隔离彻底、无需改造代码，但机器成本高，适合压测频率高或改造受限的场景（达达采用）。

选型判断：**能改造中间件选流量打标**（一次改造长期复用），改不动或隔离要求极严选机器打标。两者的共同前提是打标必须"端到端透传"——从网关到最深的依赖，任何一个环节丢失标记，该环节就会把压测流量当真实流量处理。

流量打标的技术落地按链路逐层展开：HTTP 用请求头（`X-Pressure-Test: true`）、RPC 用隐式参数透传（Dubbo attachment / Feign RequestInterceptor 注入）、MQ 用消息属性打 tag、数据库访问用连接参数或上下文标识。每一层都要有"识别标记 → 路由到影子资源 → 继续透传"三件事，缺一不可；改造完成后必须有一轮**全链路染色验证**（打一个标记请求走完整条链路，确认每一跳都命中影子资源），这是染色上线前的门禁。

## 3. 影子资源：库、缓存、队列

数据隔离落在影子资源上，每个存储层都有对应方案：

- **影子库/影子表**：压测流量路由到同结构的影子库（`order_press`）或影子表（`order_press_01`）。影子库隔离最彻底，影子表省资源但和真实表共享实例（互相有资源影响）。
- **影子缓存**：Redis key 加前缀（`press:`），避免压测 key 污染真实缓存与热点统计。
- **影子队列**：MQ 使用影子 topic（`A_press_`），压测消息不混入真实消费链路。

影子资源的设计要点：**结构必须与生产一致**（数据量可以小，结构不能差——SQL 计划失真）；**造数要贴近生产分布**（热点数据、大 key 都要有，否则压不出真实瓶颈）；**影子资源要可一键清空**（压完即清理，防止残留污染）。影子链路的自动化管理（创建/注入/清理）是压测平台的职责（[08 篇](08-压测工具与平台全景.md)）。

## 4. 流量录制与回放：Goreplay 等

流量录制回放把"随机模拟"升级为"确定性仿真"：录制线上真实流量、保持原始请求序列与时间间隔回放——能暴露特定调用序列导致的锁竞争、缓存失效等随机压测发现不了的问题。核心工具：

- **Goreplay**：基于内核态抓包（libpcap/BPF）的 HTTP 流量录制回放，**不侵入应用、不改网络拓扑**，旁路监听复制流量，支持按倍速回放（1x/10x）——生产压测录制事实标准。
- **kafka-replay**：MQ topic 回放，消息写入影子 topic，支持按生产时间/偏移量回放——验证消费链路的吞吐与积压。
- **vegeta**：Go 写的接口压测工具，支持分布式施压与结果断言——适合回放之外的定向加压。

录制回放的坑：**回放倍速失真**（10x 回放丢失思考时间分布，压的是"连续请求"而非"用户行为"）；**动态数据失效**（录制的请求带真实 token/ID，回放时资源可能已变化）——回放前需要做参数化清洗，配合[06 篇](06-全链路压测方法论.md) 的业务模型使用。

## 5. 染色链路的注意事项

染色方案落地时三个高频翻车点：

- **标记透传断层**：HTTP/2 请求头与 gRPC 元数据、MQ 消息头、跨语言服务的透传规则不同——Service Mesh（Sidecar）架构下尤其要注意标记在代理链路的兼容透传，任何一个断点都会让下游把压测流量当真流量。
- **压测数据出圈**：压测订单触发了真实的第三方回调（支付、短信）——影子链路要覆盖所有出站调用（Mock 外部依赖或隔离测试账号），压测前必须盘点全量出站依赖。
- **监控污染**：压测流量混入真实监控指标，容量分析失真——监控模型必须支持"按标记过滤压测流量"，压测期间看"真实 + 压测"两张视图（2026 年实践把"压测流量识别"列为监控的第一要求）。

> 🎯 **核心要点**：生产压测必须解决数据污染与真实用户受影响两大风险；流量打标（改造中间件、端到端透传）是 2026 主流路线，机器打标适合改造受限场景；影子资源三件套（影子库/表、缓存前缀、影子队列）结构必须与生产一致、可一键清空；Goreplay/kafka-replay 实现确定性流量回放；标记透传、出站依赖、监控过滤是染色链路三个最高频的翻车点。
