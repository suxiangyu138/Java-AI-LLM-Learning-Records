## 1. 面试高频题与答题框架

### 1.1 SSH 隧道类

**Q1：SSH 三种端口转发有什么区别？**

```text
① -L 本地转发：把远程服务映射到本地端口（本地访问远程）
   示例：ssh -L 3306:db:3306 bastion → 本地连 localhost:3306 = 连 db
② -R 远程转发：把本地服务暴露到远程端口（远程访问本地）
   示例：ssh -R 5005:localhost:5005 → 远程访问 bastion:5005 = 访问本机
③ -D 动态转发：本机 SOCKS5 代理（访问任意目标）
   示例：ssh -D 1080 → 浏览器走代理访问任意站点
④ 共同点：都基于 SSH 加密连接；限制：仅 TCP、断线即断
```

**Q2：SSH 隧道能转发 UDP 吗？**

```text
① 不能：SSH 端口转发仅支持 TCP
② UDP 场景（DNS/视频流/游戏）：用 socat / iptables / Nginx stream
③ socat 示例：socat UDP4-LISTEN:53,fork UDP4:8.8.8.8:53
④ 面试加分：说清「为什么」——SSH 隧道按连接转发，UDP 无连接概念
```

**Q3：SSH 隧道断了怎么办？**

```text
① 问题：SSH 连接断 → 隧道即断 → 服务不可用
② 方案一：autossh（自动重连）
   autossh -M 0 -N -L 3306:db:3306 bastion
③ 方案二：ServerAliveInterval 保活检测
④ 方案三：systemd 托管（Restart=always）
⑤ 面试加分：生产长期隧道 = autossh + systemd + 密钥认证
```

**Q4：-L 转发中 localhost 指的是谁？**

```text
① 关键认知：-L 的目标主机是「跳板机视角」的地址
② ssh -L 8080:localhost:80 bastion → localhost 是跳板机自己
③ 想访问本机服务要用本机 IP 或再一层隧道
④ 面试考点：这个误解是 SSH 转发的第一坑
```

### 1.2 系统级转发类

**Q5：iptables 端口转发的完整步骤？**

```text
① 开启内核转发：sysctl net.ipv4.ip_forward=1（+ 持久化）
② DNAT：iptables -t nat -A PREROUTING --dport 8080 -j DNAT --to-destination 内网:80
③ FORWARD 放行：默认拒绝转发，必须显式 ACCEPT
④ SNAT/MASQUERADE：回程路径（静态 IP 用 SNAT，动态用 MASQUERADE）
⑤ 持久化：iptables-persistent / service iptables save
⑥ 金句：三要素（ip_forward + DNAT + FORWARD/SNAT）缺一流量不通
```

**Q6：DNAT 和 SNAT 的区别？**

```text
① DNAT（目的地址转换）：改「目的」——入站流量转发（PREROUTING）
   例：公网 8080 → 内网 80
② SNAT（源地址转换）：改「来源」——出站流量伪装（POSTROUTING）
   例：内网出网固定公网 IP
③ MASQUERADE：SNAT 的动态版（宽带拨号 IP 变化时用）
④ REDIRECT：本机端口重定向（不跨机器）
⑤ 面试延伸：回程路径为什么需要 SNAT——目标服务直接回原始客户端会绕过转发点
```

**Q7：firewalld 端口转发注意什么？**

```text
① 基本命令：firewall-cmd --add-forward-port=port=80:proto=tcp:toport=8080
② 三个隐藏前置：ip_forward 开启 / 目标端口 zone 放行 / 跨机器需 masquerade
③ --permanent 持久化 + --reload 生效
④ 面试加分：很多人只配 forward-port 忘了前置 → 「规则生效流量不通」经典故障
```

**Q8：socat 有什么用？什么场景用它？**

```text
① 定位：网络瑞士军刀（TCP/UDP/Unix Socket 任意互转）
② TCP 转发：socat TCP-LISTEN:8080,fork TCP:目标:80
③ UDP 转发：socat UDP4-LISTEN:53,fork UDP4:8.8.8.8:53
④ Unix Socket 桥接：容器/服务间通信
⑤ 适用：UDP 场景（SSH 不行）、Unix Socket、快速原型；大流量用 iptables
```

### 1.3 容器与穿透类

**Q9：Docker -p 和 K8s 端口暴露的区别？**

```text
① Docker -p：单机映射（宿主机端口 → 容器端口，底层 iptables DNAT）
② K8s 四方式：
   port-forward（本地调试）/ NodePort（节点端口 30000-32767）
   / LoadBalancer（云 LB）/ Ingress（HTTP 七层，生产标准）
③ Docker 容器间通信：同网络用容器名直连（不用 -p！）
④ 面试加分：-p 是宿主↔容器的桥，不是容器↔容器的桥
```

**Q10：内网穿透的原理是什么？**

```text
① 问题：内网无公网 IP，公网无法入站访问
② 原理：反向连接——内网主动出站连公网服务器建隧道
③ 代表：frp（frps 公网 + frpc 内网）
④ 对比：ngrok（托管隧道秒开）、ZeroTier（P2P 组网）
⑤ 面试加分：本质是「出站可用、入站不可用」的 NAT 特性——用出站建通道
```

**Q11：frp 的安全配置有哪些？**

```text
① token 认证（必配，强随机）
② TLS 加密（transport.tls.enable = true）
③ 端口白名单（allowPorts 限制客户端可开端口）
④ 内网服务加固（被穿透的服务必须自带认证）
⑤ 面试加分：穿透是开一扇门——门后必须有锁（认证），门外必须有人看（日志）
```

### 1.4 安全与排查类

**Q12：哪些端口不能随便暴露公网？**

```text
① 数据库：3306（MySQL）/ 6379（Redis）/ 27017（MongoDB）——禁止公网
② Redis/MongoDB 默认无认证 → 暴露即沦陷（历史事故重灾区）
③ 调试端口：5005（Java 调试）/ JMX —— RCE 风险，用完即关
④ 管理端口：9200（ES）/ 控制台 —— 强认证 + 限源
⑤ 正确姿势：数据库远程访问走 SSH 隧道/VPN，不开公网端口
```

**Q13：端口转发「规则生效但流量不通」怎么排查？**

```text
① 分层验证：客户端 telnet → 防火墙层；转发点 iptables → NAT 层；目标 ss → 服务层
② 回程检查：握手通但数据不通 = SNAT/MASQUERADE 缺失
③ 三板斧：telnet/nc（连通）+ tcpdump（流量路径）+ conntrack（连接跟踪）
④ 高频根因：ip_forward 未开 / FORWARD 默认拒绝 / 绑定 127.0.0.1 / 重启丢规则
⑤ 金句：逐层验证不凭感觉——故障大概率在「你没想到的那一层」
```

**Q14：转发规则的安全治理怎么做？**

```text
① 最小暴露三维：端口最小 × 来源最小（限 IP）× 时间最小（用后即删）
② 认证与加密：转发解决可达性、认证解决谁能用——两层都要
③ 生命周期：申请→审批→创建→监控→回收（规则清单 + 到期提醒）
④ 定期巡检：季度暴露面扫描（nmap 高危端口）+ 僵尸规则清理
⑤ 规则即代码：Ansible/Terraform 管理（可审计可回滚）
```

## 2. 命令速查表

|------|------|
| SSH 本地转发 | `ssh -N -f -L 3306:db:3306 bastion` |
| SSH 远程转发 | `ssh -N -R 5005:localhost:5005 dev` |
| SSH 动态转发 | `ssh -N -D 1080 proxy` |

| iptables 本机转发 | `iptables -t nat -A PREROUTING -p tcp --dport 80 -j REDIRECT --to-port 8080` |

## 3. 五大常见误区

| # | 误区 | 真相 |
|---|------|------|
| 1 | 「SSH 隧道能转发 UDP」 | 仅 TCP——UDP 用 socat/iptables/Nginx stream |
| 2 | 「配了 DNAT 就通了」 | 三要素缺一不可：ip_forward + DNAT + FORWARD/SNAT |
| 3 | 「localhost 是本机」 | -L 的目标 localhost 是跳板机视角 |
| 4 | 「转发后服务就安全了」 | 转发解决可达性——服务自身的认证/加固不可少 |
| 5 | 「规则重启还在」 | 不持久化 = 重启丢规则（iptables save / --permanent） |

## 4. 一句话总结全系列

```text
01 原理：流量改道——TCP/UDP 差异、三种方向、五层级、NAT 三要素
02 SSH：-L/-R/-D 三模式 + autossh + 多级跳转——仅 TCP、断线即断
03 系统级：iptables/nftables/firewalld/socat/Nginx stream——内核高性能
04 容器：Docker -p / K8s 四方式 / 云安全组三层链路
05 穿透：frp（自建）/ngrok（临时）/ZeroTier（P2P）——反向连接原理
06 安全：最小暴露三维 + 高危端口治理 + 生命周期管理
07 排查：分层验证法 + 回程检查 + 三板斧（telnet/tcpdump/conntrack）
08 面试：14 题框架 + 命令速查 + 避坑清单
```

> 🎯 **系列总结**：端口转发 = **原理（流量改道）× 工具（六种武器）× 安全（暴露面治理）× 排查（分层验证）** 四维能力。2026 年的转发标准答案：**临时用 SSH、高性能走内核、容器用平台内建、长期穿透用 frp——且一切暴露都在最小化与审计之下**。打通网络是能力，管住暴露是智慧。
