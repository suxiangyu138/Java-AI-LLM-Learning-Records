## 1. Docker 端口映射

### 1.1 -p 参数详解

```bash
# 格式：-p [宿主机IP:]宿主机端口:容器端口[/协议]

# 最简
docker run -p 8080:8080 myapp

# 指定协议
docker run -p 8080:8080/tcp -p 53:53/udp myapp

# 仅本地访问
docker run -p 127.0.0.1:8080:8080 myapp

# 随机宿主机端口
docker run -P myapp    # 所有 EXPOSE 的端口随机映射

# 查看映射
docker port container-name
```

```yaml
# docker-compose.yml
services:
  app:
    image: myapp:1.0
    ports:
      - "8080:8080"          # 对外暴露
      - "127.0.0.1:5005:5005" # 仅本地 Debug

  mysql:
    image: mysql:8.0
    ports:
      - "127.0.0.1:3306:3306"  # 仅本机访问（安全！）
```

### 1.2 Docker 网络模式

```text
bridge 模式（默认）：
  容器有自己的 IP（172.17.x.x）
  -p 做 DNAT 转发：宿主机端口 → 容器 IP:端口

host 模式：
  容器共享宿主机网络栈（--network host）
  不需要 -p，直接监听宿主机端口
  性能最好，但端口冲突风险

none 模式：
  无网络，完全隔离
```

## 2. Kubernetes 端口暴露

### 2.1 四种方式对比

| 方式 | 用途 | 场景 |
|------|------|------|
| **kubectl port-forward** | 临时调试 | 本地连 Pod/Service ⭐ |
| **ClusterIP** | 集群内部 | 微服务间调用 |
| **NodePort** | 对外简单暴露 | 测试/临时 |
| **Ingress** | 生产 HTTP/HTTPS | 域名路由 |

### 2.2 常用命令

```bash
# 临时转发 Pod 端口到本地（调试必备）
kubectl port-forward pod/myapp-7d5f8c9b-abc 8080:8080
kubectl port-forward pod/myapp-7d5f8c9b-abc 5005:5005  # Debug

# 转发 Service
kubectl port-forward svc/myapp 8080:8080

# 指定命名空间
kubectl port-forward -n production svc/myapp 8080:8080

# 后台运行
kubectl port-forward svc/myapp 8080:8080 &

# NodePort（Service 定义中）
spec:
  type: NodePort
  ports:
    - port: 8080
      targetPort: 8080
      nodePort: 30080    # 30000-32767
```

## 3. 堡垒机真实场景

### 3.1 开发者日常

```text
场景：公司所有服务器只能通过堡垒机访问

需求1：本地连生产数据库（DataGrip/DBeaver）
  ssh -N -L 3306:prod-db.internal:3306 user@bastion
  DataGrip 配置：Host=127.0.0.1 Port=3306

需求2：本地连 K8s 集群 API
  kubectl 已配置 proxy 走 bastion
  ssh -N -L 6443:k8s-api.internal:6443 user@bastion

需求3：远程调试 K8s 中的 Pod
  kubectl port-forward pod/myapp-xxx 5005:5005
  ssh -N -R 5005:localhost:5005 user@bastion
  # IDE 连接 localhost:5005

多合一推荐配置（~/.ssh/config）：
  Host bastion
      HostName bastion.example.com
      User developer
      ServerAliveInterval 30
      LocalForward 3306 prod-db.internal:3306
      LocalForward 6379 prod-redis.internal:6379
      LocalForward 9200 prod-es.internal:9200
  # 一条命令启动所有隧道：ssh -N bastion
```

## 4. 内网穿透 frp/ngrok

### 4.1 frp

```ini
# frps.toml（服务器端）
bindPort = 7000

# frpc.toml（客户端，在内网机器上）
serverAddr = "vps.example.com"
serverPort = 7000

[[proxies]]
name = "web"
type = "tcp"
localIP = "127.0.0.1"
localPort = 3000
remotePort = 8080
# 效果：vps:8080 → 内网机器:3000
```

```bash
# 启动
./frps -c frps.toml    # 服务端
./frpc -c frpc.toml    # 客户端
```

### 4.2 ngrok

```bash
# 临时将本机 3000 暴露到公网（开发演示）
ngrok http 3000
# 输出：https://abc123.ngrok.io → localhost:3000

# 固定域名（付费）
ngrok http --domain=myapp.ngrok.dev 3000
```

| 工具 | 适用 | 优势 | 劣势 |
|------|------|------|------|
| **frp** | 自建长期使用 | 免费、可控、高性能 | 需 VPS |
| **ngrok** | 临时演示/调试 | 无需 VPS、一行命令 | 免费版限速 |
| **Cloudflare Tunnel** | 生产环境 | 免费、CDN 加速、DDoS 防护 | 需域名托管 CF |

## 5. 端口转发决策树

```text
你的需求是什么？

  ├── 临时连远程数据库/Redis？
  │     → SSH -L（本地转发）

  ├── 让远程服务器访问你本地的服务？
  │     → SSH -R（远程转发）

  ├── 浏览器走代理？
  │     → SSH -D 1080（Socks5）

  ├── 生产环境持久化转发？
  │     ├── 同机器低端口 → firewalld forward-port
  │     ├── TCP 代理多端口 → Nginx stream
  │     └── 简单临时中继 → socat

  ├── Docker 容器？
  │     → docker run -p / docker-compose ports

  ├── Kubernetes 调试？
  │     → kubectl port-forward

  └── 内网服务暴露公网？
        ├── 临时演示 → ngrok
        ├── 自建长期 → frp
        └── 生产级 → Cloudflare Tunnel
```

---

> 🎯 **一句话总结**：**SSH 隧道**解决 90% 日常需求，**Docker -p** 管容器，**kubectl port-forward** 管 K8s，**frp/ngrok** 管内网穿透。系统级转发只在 SSH 不适用时才考虑。
