## 1. 内网穿透的本质

> **背景**：家宽/办公网通常没有公网 IP（或 NAT 后不可达）——公网无法直接访问内网服务。
> **目的**：让公网流量「绕道」到达内网服务——本质是**反向连接**（内网主动连公网服务器，建立通道）。
> **适用范围**：家庭 NAS/开发机/演示服务暴露、远程办公、临时公网访问。
> **不适用场景**：有公网 IP 的环境（直接端口转发更简单）；强合规场景（穿透绕过安全边界需审批）。

```text
内网穿透的原理（反向连接）
┌────────┐ ①主动连接 ┌────────┐ ②公网访问 ┌────────┐
│ 内网服务  │ ←———————→ │ 公网服务器 │ ←——————— │ 公网用户 │
│ (frpc)  │  隧道    │ (frps)  │          │        │
└────────┘          └────────┘          └────────┘
关键：内网主动出站连接公网（NAT 允许出站）→ 建立反向隧道
     → 公网用户访问公网服务器端口 = 流量经隧道到内网服务
```

| 方案 | 类型 | 公网依赖 | 特点 |
|------|------|:---:|------|
| **frp** | 反向代理 | 自建服务器 | 功能全、可定制、开源 |
| **ngrok** | 托管隧道 | 官方服务器 | 秒开、临时、免费额度 |
| **ZeroTier** | P2P 组网 | 控制器（免费） | 虚拟局域网、双向直达 |

## 2. frp：自建穿透首选

### 2.1 架构与安装

> **背景**：frp（Fast Reverse Proxy）开源高性能反向代理——fatedier 出品，国内使用最广。
> **目的**：自建服务器 + 内网客户端，实现持久化穿透（TCP/UDP/HTTP/HTTPS）。
> **适用范围**：有云服务器的场景（一年几十元的轻量服务器即可）。
> **前提假设**：公网服务器有固定 IP；frps 与 frpc 版本匹配。

```bash
# 下载（GitHub releases，Linux amd64 示例）
wget https://github.com/fatedier/frp/releases/download/v0.61.0/frp_0.61.0_linux_amd64.tar.gz
tar -xzf frp_*.tar.gz && cd frp_*
# 目录包含：frps（服务端）/ frpc（客户端）+ .toml 配置

# 公网服务器：启动 frps（服务端）
./frps -c frps.toml

# 内网机器：启动 frpc（客户端）
./frpc -c frpc.toml
```

### 2.2 基础配置（frps.toml）

```toml
# frps.toml（公网服务器）
bindPort = 7000                    # 服务端监听端口（frpc 连接用）
auth.method = "token"
auth.token = "your-secure-token"   # ⚠️ 认证令牌（必配！）

# HTTP 穿透支持（可选）
vhostHTTPPort = 8080               # HTTP 虚拟主机端口
```

### 2.3 基础配置（frpc.toml）

```toml
# frpc.toml（内网机器）
serverAddr = "203.0.113.10"        # 公网服务器 IP
serverPort = 7000
auth.token = "your-secure-token"   # 与服务端一致

# 第一个代理：SSH 穿透（公网 6000 → 内网 22）
[[proxies]]
name = "ssh-home"
type = "tcp"
localIP = "127.0.0.1"
localPort = 22
remotePort = 6000                  # 公网服务器上的端口

# 第二个代理：Web 服务（公网 8080 → 内网 NAS:80）
[[proxies]]
name = "web-nas"
type = "tcp"
localIP = "192.168.1.100"
localPort = 80
remotePort = 8080
```

```bash
# 使用：公网访问内网
ssh -p 6000 user@203.0.113.10      # SSH 到内网机器
curl http://203.0.113.10:8080      # 访问内网 NAS
```

## 3. frp 高级配置

### 3.1 HTTP 域名穿透

```toml
# frpc.toml：HTTP 虚拟主机（一个端口多域名）
[[proxies]]
name = "web-blog"
type = "http"
localIP = "127.0.0.1"
localPort = 80
customDomains = ["blog.example.com"]   # 域名指向 frps IP

[[proxies]]
name = "web-photo"
type = "http"
localIP = "127.0.0.1"
localPort = 81
customDomains = ["photo.example.com"]

# frps.toml 需开启：vhostHTTPPort = 8080
# DNS 把两个域名都解析到 frps 服务器 IP
# 访问：http://blog.example.com:8080
```

### 3.2 安全增强配置

```toml
# frpc.toml 安全配置
[[proxies]]
name = "web-nas"
type = "tcp"
localIP = "127.0.0.1"
localPort = 80
remotePort = 8080
transport.tls.enable = true        # 启用 TLS 加密
# 访问白名单（frps 侧限制）
```

```toml
# frps.toml 安全加固
auth.token = "strong-random-token"
# 允许的端口范围（防止客户端任意开端口）
allowPorts = [{ start = 6000, end = 6999 }]
# 限速（防止滥用）
# bandwidthLimit 可在代理级别设置
```

### 3.3 systemd 托管（长期运行）

```ini
# /etc/systemd/system/frpc.service（内网机器）
[Unit]
Description=frp client
After=network-online.target

[Service]
ExecStart=/opt/frp/frpc -c /opt/frp/frpc.toml
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now frpc
sudo systemctl status frpc
```

## 4. ngrok：快速临时隧道

### 4.1 定位

> **背景**：ngrok 是托管式穿透服务——一行命令把本地端口暴露到公网（官方域名）。
> **目的**：秒开临时隧道（演示/联调/Webhook 回调）。
> **适用范围**：临时演示、本地联调、Webhook 测试。
> **不适用场景**：长期生产服务（免费额度限制 + 依赖第三方）。

```bash
# 安装（单二进制）
wget https://bin.equinox.io/c/bNyj1mQVY4c/ngrok-v3-stable-linux-amd64.tgz
tar -xzf ngrok*.tgz && sudo mv ngrok /usr/local/bin/

# 注册 + 认证（官网拿 token）
ngrok config add-authtoken <你的token>

# 穿透本地 8080（秒开公网地址）
ngrok http 8080
# 输出：
# Forwarding https://xxxx.ngrok-free.app -> http://localhost:8080

# TCP 穿透（SSH/数据库等）
ngrok tcp 22

# 穿透其他机器的服务
ngrok http 192.168.1.100:80
```

### 4.2 ngrok 的边界

```text
ngrok 取舍
├── ✅ 优点：秒开、免费额度、HTTPS 自动
├── ❌ 限制：免费域名随机、带宽/连接数限制、依赖第三方
├── ✅ 场景：演示给客户看、本地 Webhook 调试、临时分享
└── ❌ 场景：生产服务、敏感数据（流量经第三方）
```

## 5. ZeroTier：P2P 虚拟组网

### 5.1 定位

> **背景**：ZeroTier 是 P2P 虚拟局域网——把分布各处的设备组成一个虚拟网络（像在同一个局域网）。
> **目的**：多设备互联（不暴露公网端口），设备间直接 P2P 通信（流量不经过服务器）。
> **适用范围**：多台机器组成私有网络（办公/家庭 NAS/服务器集群互联）。
> **不适用场景**：公网用户访问（ZeroTier 需要客户端）；临时穿透。

```bash
# 安装（Linux）
curl -s https://install.zerotier.com | sudo bash

# 加入网络（网络 ID 在 ZeroTier 控制台创建）
sudo zerotier-cli join <network-id>

# 授权（控制台勾选设备）/ 查看状态
sudo zerotier-cli listnetworks

# 效果：所有加入网络的设备获得虚拟 IP（如 192.168.196.x）
# 设备间直接互访（无需端口映射）
ssh user@192.168.196.5        # 像访问局域网一样
```

### 5.2 与 frp 的对比（关键权衡）

| 维度 | frp | ZeroTier |
|------|:---:|:---:|
| 访问方式 | 公网端口（用户无感） | 虚拟 IP（需装客户端） |
| 流量路径 | 经 frps 服务器中转 | **P2P 直连（速度更快）** |
| 适用 | 公网用户访问内网服务 | 自己的多台设备互联 |
| 依赖 | 自建服务器 | 官方控制器（免费） |
| 场景 | NAS 公网访问/Web 暴露 | 多机互联/远程办公 |

> 🎯 **选型**：公网用户访问 → frp；自己的设备互联 → ZeroTier（P2P 更快且无需中转）。

## 6. 方案选型与权衡

### 6.1 选型决策表

```text
内网穿透选型
├── 有云服务器 + 长期服务 → frp（自建、可控、功能全）
├── 临时演示/联调 → ngrok（秒开）
├── 多设备私有互联 → ZeroTier（P2P）
├── 需求穿透 UDP → frp（支持 UDP 代理）
├── 需要域名 + HTTPS → frp HTTP 模式 + 自签/Let's Encrypt
└── 无服务器且临时 → ngrok 免费额度
```

### 6.2 权衡要点

| 决策点 | 权衡 | 建议 |
|--------|------|------|
| 自建 vs 托管 | 自建可控但维护；托管省事但依赖 | 长期自建、临时托管 |
| 中转 vs P2P | 中转稳定但慢；P2P 快但 NAT 复杂 | 公网访问中转、互联 P2P |
| 安全 | 穿透=绕过边界——必须认证加密 | token + TLS + 端口白名单 |
| 合规 | 国内 80/443 需备案 | Web 服务注意备案要求 |

## 7. 穿透安全

### 7.1 穿透的安全风险

```text
内网穿透的固有风险
├── ① 暴露面扩大：内网服务直接暴露公网
├── ② 认证绕过：默认无认证的服务（Redis/MySQL）被扫到即被打
├── ③ 中转信任：流量经过第三方（ngrok 类）可被截获
├── ④ 端口滥用：frp 客户端可任意开端口（需白名单）
```

### 7.2 安全基线

```text
穿透安全七项（必做）
├── ① 认证令牌：frp token（强随机）必配
├── ② TLS 加密：transport.tls.enable = true
├── ③ 端口白名单：frps allowPorts 限制客户端开端口范围
├── ④ 内网服务加固：被穿透的服务必须有认证（禁用 Redis 无密码）
├── ⑤ 最小暴露：只开必要端口，用后即关
├── ⑥ 高危端口规避：穿透 22 时公网侧用高位端口（6000+）
├── ⑦ 监控日志：frps 日志 + 异常连接告警
└── 金句：穿透是「开一扇门」——门后必须有锁（认证），门外必须有人看（日志）
```

## 8. 核心要点

> 🎯 **核心要点**：
> 1. 内网穿透本质 = 反向连接（内网主动出站建隧道）——绕过 NAT 无法入站的限制
> 2. frp：自建首选（TCP/UDP/HTTP 全支持）——token 认证 + TLS + 端口白名单三件安全必配
> 3. ngrok：临时隧道秒开（演示/Webhook 调试）；ZeroTier：P2P 设备互联（流量不中转更快）
> 4. 选型：公网用户访问用 frp、设备互联用 ZeroTier、临时演示用 ngrok
> 5. 安全金句：穿透是开一扇门——门后必须有锁（认证），门外必须有人看（日志）
