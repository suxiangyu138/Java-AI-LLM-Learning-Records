# 00 - 端口转发知识体系总览

> 🔗 端口转发 = 流量改道——把 A 端口的流量送到 B 端口。SSH 隧道、系统级 NAT、容器映射、内网穿透四大家族覆盖 99% 场景。但转发也是双刃剑：一条无认证的规则 = 一个被攻破的入口。本系列从原理到安全，打通网络也管住暴露

> 🎯 本系列共 **8 篇**，从核心原理到工具实战、从内网穿透到安全治理、从故障排查到面试考点，覆盖端口转发全链路

## 4. 核心概念速查

| 概念 | 一句话解释 |
|------|-----------|
| **端口转发** | 流量改道：把 A 端口的流量送到 B 端口（客户端无感知） |
| **本地转发 -L** | 把远程服务映射到本地端口（本地访问远程） |
| **远程转发 -R** | 把本地服务暴露到远程端口（远程访问本地） |
| **动态转发 -D** | 本机 SOCKS5 代理（访问任意目标） |
| **DNAT** | 目的地址转换（PREROUTING）——入站转发核心 |
| **SNAT/MASQUERADE** | 源地址转换（POSTROUTING）——回程路径 |
| **ip_forward** | 内核转发开关——不开启则跨机器转发静默失败 |
| **内网穿透** | 反向连接：内网主动出站建隧道（frp/ngrok） |
| **最小暴露** | 端口最小 × 来源最小 × 时间最小——暴露面治理原则 |
| **分层验证法** | 防火墙层 → NAT 层 → 服务层逐层排查（不凭感觉） |

## 5. 场景速查

| 场景 | 方案 | 命令一句话 |
|------|:--:|------|
| 远程数据库连本地 | SSH 本地转发 | `ssh -N -L 3306:db:3306 bastion` |
| 远程调试本地服务 | SSH 远程转发 | `ssh -R 5005:localhost:5005 dev` |
| 全局代理/科学上网 | SSH 动态转发 | `ssh -N -D 1080 proxy` |
| 低端口转发高端口 | firewalld/iptables | `firewall-cmd --add-forward-port=port=80:toport=8080` |
| 高性能生产转发 | iptables/nftables | DNAT + FORWARD + SNAT 三要素 |
| UDP 转发（DNS） | socat | `socat UDP4-LISTEN:53,fork UDP4:8.8.8.8:53` |
| Docker 服务暴露 | docker -p | `docker run -p 8080:8080 myapp` |
| K8s 调试 Pod | kubectl | `kubectl port-forward pod/xxx 8080:8080` |
| 内网服务暴露公网 | frp/ngrok | frps + frpc + token 认证 |
| 多设备私有互联 | ZeroTier | `zerotier-cli join <network-id>` |

---

> 🎯 **一句话定位**：端口转发 = **原理（流量改道）× 工具（SSH/内核/容器/穿透）× 安全（暴露面治理）× 排查（分层验证）**——打通网络是能力，管住暴露是智慧。
