## 3. 学习路线推荐

### 路线一：入门（1-2 天）——先会用

01 → 03 → 05，重点掌握：

- 虚拟线程"便宜"在哪里（内存数字：~1MB vs 200-300B 元数据）
- 三种创建方式与 `newVirtualThreadPerTaskExecutor()` 的定位
- 迁移决策：I/O 密集场景直接换执行器，**CPU 密集场景不要迁**
- 会用 `jcmd Thread.dump_to_file` 看虚拟线程转储

### 路线二：进阶（3-5 天）——搞懂机制

02 → 04 → 06 → 07，重点掌握：

- mount/unmount 与 Continuation 的底层机制
- pinning 的历史问题与 JEP 491（JDK 24）修复原理
- 结构化并发为何是虚拟线程的"最佳拍档"
- ScopedValue 为何替代 ThreadLocal

### 路线三：专家（1 周+）——源码级与生产级

02 源码层面 + 04 的 JVM 实现（LockStack、ObjectMonitor._owner）+ 08 的 JFR 分析与压测，阅读：

- [JEP 444: Virtual Threads](https://openjdk.org/jeps/444)
- [JEP 491: Synchronize Virtual Threads without Pinning](https://openjdk.org/jeps/491)
- [JEP 506: Scoped Values](https://openjdk.org/jeps/506)
- [JEP 525: Structured Concurrency (Sixth Preview)](https://openjdk.org/jeps/525)

## 4. 核心概念速查

| 概念 | 一句话定义 | 关键要点 |
|------|-----------|---------|
| 虚拟线程 | JVM 调度的轻量级线程，与 OS 线程无 1:1 映射 | JDK 21（JEP 444）转正，M:N 模型 |
| 载入线程（Carrier） | 真正执行虚拟线程代码的 OS 平台线程 | ForkJoinPool 管理，数量 = CPU 核数 |
| mount / unmount | 虚拟线程上/下载入线程的切换 | 阻塞点自动卸载，恢复后重新入队调度 |
| Continuation | 可挂起/恢复的 JVM 级执行状态 | 分块栈（chunk）存于堆上，可被 GC |
| pinning | 虚拟线程无法卸载、卡住载入线程的现象 | JDK 24（JEP 491）基本消除，原生回调等仍存在 |
| task-per-thread | 一个任务一个虚拟线程，不池化 | `newVirtualThreadPerTaskExecutor()` 的语义 |
| 结构化并发 | 子任务与作用域同生命周期，统一错误处理与取消 | JDK 26 为第六次预览（JEP 525），需 `--enable-preview` |
| ScopedValue | 有界生命周期的不可变上下文值 | JDK 25（JEP 506）转正，ThreadLocal 的替代者 |

## 5. 与周边知识的关系

```text
Java 并发知识体系
│
├── Java 多线程基础（进程线程、三要素、synchronized/volatile）
│   └── 虚拟线程本质仍是"线程"，基础模型完全适用
├── JUC_Java高并发
│   ├── 线程池与 Executor 框架 ──→ 虚拟线程改变选型（05）
│   ├── CompletableFuture 异步编程 ──→ 与结构化并发互补（06）
│   ├── JUC 并发工具类（Semaphore 限流）──→ 虚拟线程限流手段（05）
│   └── ThreadLocal 详解 ──→ ScopedValue 是其继任者（07）
└── 本体系：虚拟线程（线程载体）+ 结构化并发（编排）+ ScopedValue（上下文）
```

> 💡 **一句话理解整套 Loom 组合拳**：虚拟线程解决"线程不够用"，结构化并发解决"并发难管理"，ScopedValue 解决"上下文怎么传"——三者共同组成 JDK 21+ 时代的新并发编程范式。

## 6. 版本演进时间线

| 版本 | 日期 | 虚拟线程相关变化 | 状态 |
|:---:|------|-----------------|:---:|
| JDK 19 | 2022-09 | JEP 425 虚拟线程首次预览；JEP 428 结构化并发孵化 | 预览 |
| JDK 20 | 2023-03 | JEP 436 第二次预览；JEP 429 ScopedValue 孵化 | 预览 |
| JDK 21 LTS | 2023-09 | **JEP 437 虚拟线程转正（JEP 444 为最终版）**；JEP 453 结构化并发预览 | ✅ 转正 |
| JDK 22 | 2024-03 | JEP 462 结构化并发二览；JEP 464 ScopedValue 二览 | 预览 |
| JDK 23 | 2024-09 | JEP 480 结构化并发三览；JEP 481 ScopedValue 三览 | 预览 |
| JDK 24 | 2025-03 | **JEP 491 synchronized 无 pinning 转正**；JEP 499 结构化四览；JEP 487 ScopedValue 四览 | ✅ 转正 |
| JDK 25 LTS | 2025-09 | **JEP 506 ScopedValue 转正**；JEP 505 结构化五览 | ✅ 转正 |
| JDK 26 | 2026-03 | JEP 525 结构化并发六览（onTimeout 等新 API）；虚拟线程稳定性修复 | 预览 |
| JDK 27+ | 预计 | JEP 533 结构化并发七览，最终转正预计在 JDK 29 | 规划中 |

> ⚠️ **版本窗口**：本体系以 **JDK 26**（2026-03-17 GA）为基线。若使用 JDK 21/24/25，注意 04 章 pinning 行为、06 章结构化并发 API 形态均随版本不同。
