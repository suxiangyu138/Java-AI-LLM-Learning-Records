## 1. 五维能力模型

横向通用能力可以组织为五个能力族，每个族对应本体系的两篇左右：

**决策族**——权衡分析（02 篇）与决策记录（03 篇）：架构师的核心产出是「决策」——决策质量取决于「权衡是否显式、备选是否充分、记录是否完整」。**表达族**——架构表达（04 篇）：把决策与系统结构讲清楚（C4 模型、图与文档）——「说不清的架构等于没有」。**质量族**——NFR 定义与验收（05 篇）与模式知识（06 篇）：质量属性是可验收的契约，模式库是决策的弹药。**治理族**——架构评审（07 篇）与债务管理（08 篇）与技术治理（09 篇）：让架构「持续符合目标」的机制。**成长族**——贯穿全篇的学习姿态：评审中学习、债治理中学习、雷达中学习。

**五个能力族的共性是「方法论」**——不绑定具体技术栈，换技术不变方法论——这正是「横向」的含义：**L1-L4 纵向体系回答「不同级别该懂什么」，横向体系回答「所有级别都用什么方法做事」**。

## 2. 与 L1-L4 纵向体系的分工

同级四个纵向级别体系与本体系的关系：

| 体系 | 视角 | 内容 |
|------|------|------|
| L1 初级开发 | 看懂架构、落地模块 | 读懂现有架构、按规范落地 |
| L2 中级开发 | 模块级设计 | 模块内设计、接口设计 |
| L3 高级开发 | 子系统架构 | 子系统级设计、跨模块协调 |
| L4 架构师 | 全局系统架构 | 系统级架构、技术路线 |
| **横向通用能力** | **所有级别的方法论** | 决策、表达、评审、治理、债 |

**协作姿势**：纵向体系提供「该掌握的技术深度」，横向体系提供「做事的通用方法」——**一个 L3 工程师做子系统设计时要用横向的权衡决策与 ADR 方法，一个 L4 架构师做全局架构时同样要用**——**「横向能力随级别加深，方法论不变」**：L1 用 ADR 记录小决策，L4 用 ADR 记录重大路线决策——工具相同、粒度不同。

## 3. 2026 方法论基线

**证据驱动（zero-assumption）**——架构决策基于代码分析、仓库数据、事故复盘，而非假设与印象——「你没有分析过就说不行」是 2026 被明确否定的姿态；**权衡显式化**——options matrix（3+ 备选 × 加权维度）替代单选项论证，「被否决的方案」写进 ADR（「为什么不是它」与「为什么是它」同等重要）；**自动化治理**——fitness functions（ArchUnit 等）把架构约束变成 CI 里的自动校验，替代人肉审批的重复劳动；**债管理商业化**——技术债量化到 FTE-月、用商业语言向管理层沟通（08 篇）；**模式反思**——微服务祛魅（分布式单体是最常见失败模式）、Modular Monolith 与 Monolith First 成为务实选项（06 篇）。

**这些基线的共同方向**：**架构从「个人英雄主义」走向「工程化」**——决策有方法、表达有标准、治理有自动化、债务有账本——架构师从「最懂技术的人」变成「让架构决策可复制的人」。

## 4. 架构师的角色定位

2026 年架构师角色的重新定义：**不是「技术权威」而是「技术引路人」**——**「赋能改变而非阻止改变」**是治理的核心姿态（09 篇）；**不是「画图的人」而是「决策的人」**——图是表达的载体，决策是价值的载体；**不是「单打独斗」而是「团队杠杆」**——ADR 库、评审机制、fitness functions 都是「让团队能力复制」的杠杆——**「架构师的价值 = 团队决策质量的提升，而非个人技术深度的展示」**。

## 5. 能力成长路径

横向能力的成长不是「学完就会」，而是「实践循环」：**决策 → 记录 → 评审 → 反思 → 再决策**——具体到动作：**每周一次架构讨论**（决策练习场）；**每月一次评审**（评审能力与系统健康的双重检查）；**每季度债盘点**（债务可视化与治理）；**持续技术雷达**（选型视野的更新）。**「成长靠循环不靠课程」**——横向能力是「做出来的能力」，本体系十篇提供方法与工具，成长发生在你实际用它们做的每一次决策里。

## 6. 五条边界

**不替代技术深度**——方法论需要技术知识支撑（模式、中间件、语言）——L1-L4 纵向体系补深度。

**不替代业务理解**——架构决策要懂业务（价值、约束、演进）——「技术正确但业务错误」是常见失败。

**不解决组织问题**——跨团队协调、资源博弈是组织课题——方法论提供工具，落地靠组织。

**不承诺完美架构**——「最不坏的取舍」是常态——接受不完美是成熟标志。

**不替代实际动手**——架构师脱离代码会失去「证据驱动」的基础——「不会写代码的架构师是纸上谈兵」。

**「架构师的横向能力画像」**——面试与晋升视角的能力清单：**决策能力**（权衡显式、备选充分、证据驱动——02/03 篇）；**表达能力**（C4 分层、文档即代码——04 篇）；**质量标准**（NFR 可验收、映射可追踪——05 篇）；**评审能力**（ATAM、产出闭环——07 篇）；**治理能力**（fitness、雷达、豁免——09 篇）；**沟通能力**（商业语言、跨层翻译——08 篇）——**「画像 = 本体系各篇的验收标准集合」**——用画像自评：哪个能力族最弱 → 对应篇目精读 + 实战。
