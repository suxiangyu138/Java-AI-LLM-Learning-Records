## 1. 实战：横向能力体系落地

把全体系知识点压进一个项目：为自己的系统落地「决策 → 记录 → 评审 → 治理」的完整横向能力闭环。

**第一步，ADR 库落地（03 篇）**——建 `docs/adr/` 目录 + 模板 + 首批决策记录：

```bash
# docs/adr/ 目录结构
docs/adr/
├── 001-模块化单体作为订单系统架构.md   # 架构风格决策（单向门）
├── 002-订单查询引入Redis缓存.md        # 性能决策（含备选方案）
└── template.md                        # Nygard/MADR 模板
```

**第二步，权衡决策实践（02 篇）**——选一个真实决策（如「消息队列选型」）走全流程：问题定义 → 证据收集（压测/对比数据）→ 3 个备选 → options matrix（加权维度）→ 决策 + ADR（含被否决方案）。

**第三步，架构评审跑通（07 篇）**——组织一次真实评审：输入（C4 图 + ADR + NFR 清单）→ ATAM 场景收集 → 逐场景对照 → 产出问题清单（严重级 + 责任人 + 期限）→ 跟进闭环。

**第四步，技术债盘点（08 篇）**——季度债务盘点：证据定位（依赖分析 + 变更热点 + SonarQube 度量）→ 债务清单（FTE-月量化）→ 风险优先路线图 → 商业语言报告。

**第五步，fitness functions 进 CI（09 篇）**——ArchUnit 依赖规则测试 + 架构约束快照：

```java
// archunit 依赖 + 规则测试（09 篇示例）
@AnalyzeClasses(packages = "com.example.order")
public class ArchitectureTest {
    @Test
    void controller_should_only_depend_on_service() { /* 依赖规则断言 */ }
    @Test
    void no_cycle_dependencies() { /* 循环依赖检测 */ }
}
```

**验收四问**：**决策有记录吗**——ADR 库有首批记录（含备选与后果双侧）；**权衡显式吗**——options matrix 的维度加权有依据；**评审有产出吗**——问题清单闭环（责任 + 期限 + 状态）；**约束自动生效吗**——fitness 进 CI（改代码违反约束 → 构建失败）。

## 2. 生产配置模板与纪律清单

**决策**：单向门深分析（options matrix + 原型 + 评审）、双向门快决策；决策写证据清单。**记录**：ADR 进 `docs/adr/`（序号 + 模板）、Nygard/MADR 格式、备选必写、后果双侧、生命周期维护（Superseded 引用）。**表达**：C4 四层（L1 一张 + L2 一张 + L3 按需）、图即代码（Mermaid/Structurizr 进仓库）、文档与代码同 PR。**质量**：NFR 可验收（指标+阈值+场景+验收方式）、NFR ↔ 架构选择映射、启动时 NFR 检查清单。**评审**：输入是文档（C4+ADR+NFR）、ATAM 场景驱动、问题清单跟进闭环、评审习惯常态化。**债**：季度盘点 + 月度例会、FTE-月量化、风险优先路线图、商业语言报告。**治理**：fitness 进 CI、Tech Radar 季度更新、豁免有到期机制、参考架构季度评审。

## 3. 常见失败模式

**「决策不记录」**——三个月后「为什么是它」无人能答——ADR 是决策的默认动作（不是可选项）；**「评审无产出」**——会开了问题没跟——评审问题清单与 bug 同级跟踪；**「债永远在讨论」**——盘点做了、路线图画了、就是不执行——债治理要有「还债迭代」（Boy Scout 原则落地）；**「fitness 写了不进 CI」**——约束测试沦为演示——fitness 进流水线是硬要求；**「方法论只挂在墙上」**——ADR 模板建了没人写——**「方法的落地 = 流程嵌入 + 习惯养成」**：ADR 进 PR 规范、评审进迭代节奏、盘点进季度计划——**「横向能力的失败模式都是「做了一次不持续」，持续是横向能力的试金石」**。

## 4. 面试三范式

**价值式**：「我为团队落地了横向能力体系——ADR 库 20+ 条决策记录（含被否决方案），架构决策可追溯；fitness functions 进 CI 后架构约束自动校验，依赖违规零容忍；技术债盘点量化到 FTE-月，风险优先路线图驱动季度治理。」——先讲机制与数据，再讲工具。

**技术式**：「架构第一定律是一切权衡——options matrix（3+ 备选 × 加权维度）让权衡显式；单向门深分析、双向门快决策（回退成本判断）；C4 四层分离抽象层级；ATAM 场景驱动评审（刺激-环境-响应-度量）；fitness functions 是架构的单元测试（ArchUnit 依赖规则即测试）。」——方法论到「为什么」，别停在「我会画架构图」。

**生产式**：「治理是赋能而非阻止——fitness 自动化替代人肉审批；豁免有到期机制（临时豁免不永久化）；技术债用商业语言沟通（时间浪费/事故风险/ROI）；Tech Radar 管选型入口（Hold 防简历驱动选型）；演进式架构——变化是设计的一部分，ADR 是演进史。」——治理姿态、豁免机制、商业沟通三点是区分度。

**追问四连**：权衡怎么显式化？（options matrix + ADR 的 Consequences 双侧）｜架构怎么防腐化？（fitness + 评审 + 债盘点三机制）｜技术债怎么排优先级？（利息 × 风险 ÷ 修复成本）｜治理与创新怎么平衡？（标准粒度按风险敏感度 + 约束可变更走 ADR）。

## 5. 简历呈现

项目经历写法：「搭建团队横向能力体系——ADR 决策记录库（20+ 条，含备选与后果）与 C4 架构文档（图即代码进仓库）；fitness functions（ArchUnit）依赖约束进 CI，架构违规自动拦截；季度技术债盘点（FTE-月量化 + 风险优先路线图）驱动治理；ATAM 场景驱动的架构评审机制落地。」技能栏：「架构方法论（权衡决策/ADR/C4/NFR），架构治理（fitness/评审/技术债）」。——机制 + 数据 + 工具链三要素。
