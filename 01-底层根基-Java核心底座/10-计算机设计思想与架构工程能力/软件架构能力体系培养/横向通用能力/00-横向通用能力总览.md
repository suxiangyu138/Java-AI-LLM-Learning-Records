## 3. 学习路线推荐

**路线一：基础方法论（1-2 天）**——01 → 02 → 03 → 04。目标：掌握权衡决策与 ADR/C4 两个表达工具，能写出规范的决策记录。

**路线二：评审与治理（3-5 天）**——路线一 + 05 → 07 → 09。目标：NFR 定义与架构评审跑通，fitness functions 进 CI。

**路线三：债务与实战（一周）**——路线二 + 06 → 08 → 10。目标：模式选型与反模式识别、技术债量化治理、完整实战。

**先厘清定位**：本体系是「横向能力」——与同级 [[../L1：初级开发｜看懂架构，落地模块|L1]]、[[../L2：中级开发｜模块级设计|L2]]、[[../L3：高级开发｜子系统架构|L3]]、[[../L4：架构师｜全局系统架构|L4]] 四个纵向级别体系互补：**纵向体系按级别讲「该懂什么技术」，本体系讲「所有级别都要用的方法论」**——决策、表达、评审、治理贯穿整个成长路径。技术深度对照 [[../../../04-设计模式/01-面向对象设计原则与UML|设计模式体系]] 与 [[../../../../02-后端核心技术%20微服务%20分布式%20云原生/08-分布式系统与架构/Java分布式框架/00-Java分布式框架总览|分布式框架体系]]。

## 4. 核心概念速查

| 概念 | 一句话 |
|------|-------|
| 权衡第一定律 | 「一切都是权衡」——没有完美架构，只有最不坏的取舍 |
| options matrix | 备选方案 × 加权维度的评估矩阵（3+ 备选防单选项偏差） |
| 单向门/双向门 | 决策分类：难撤销的重分析、易撤销的快决策 |
| ADR | 架构决策记录：Context/Decision/Consequences |
| MADR | 轻量 ADR 模板（Markdown Any Decision Records） |
| C4 模型 | Context/Container/Component/Code 四层架构视图 |
| Structurizr | C4 原生工具（代码即图） |
| NFR | 非功能需求（-ilities：性能/安全/可扩展性...） |
| ATAM | 架构权衡分析方法（质量属性场景驱动的评审） |
| 技术债 | 次优决策的积累成本（可量化、可治理） |
| Fitness Function | 适应度函数：自动化校验架构约束（ArchUnit 等） |
| Tech Radar | 技术雷达：技术选型的团队共识视图 |
| 反模式 | 高频失败形态（分布式单体、简历驱动架构...） |
| 证据驱动 | zero-assumption：决策基于代码/仓库/事故分析而非假设 |

## 5. 常见误区

**误区一：架构师只做技术选型**。选型只是权衡决策的一个场景——横向能力的核心是「决策方法论 + 表达 + 治理」，选型是结果不是能力。

**误区二：决策不做记录**。「讨论完就定了」——三个月后没人知道为什么——ADR 是决策的「审计痕迹」，不是文档负担。

**误区三：一张图讲全部**。系统级架构图塞满所有细节——C4 四层分离抽象层级，每层只讲该层的粒度。

**误区四：NFR 是「性能要好」**。不可验收的 NFR 等于没有——「P99 < 200ms」才是 NFR，验收标准不写等于没定义。

**误区五：微服务是默认答案**。分布式单体是最常见失败模式——Monolith First / Modular Monolith 是多数场景的正确起点——「按场景选，不按流行选」。

**误区六：技术债是「脏代码」**。技术债是「次优决策的积累」——有意的债（快速上线）要记账、无意的债（隐藏债）才是问题——「债要显式化」。

**误区七：治理就是审批**。治理是「赋能改变而非阻止改变」——fitness functions 自动校验比人肉审批高效——「治理即文化」。

**误区八：架构评审走过场**。评审会开了、问题没跟——评审要有方法（ATAM）、有产出（问题清单 + 责任 + 期限）——「评审是流程不是仪式」。

## 6. 一周计划

| 天 | 内容 | 产出 |
|:---:|------|------|
| Day1 | 01 + 02：能力模型与权衡 | 一次真实决策的 options matrix |
| Day2 | 03：ADR | 3 条 ADR（含被否决方案） |
| Day3 | 04：C4 模型 | 自己系统的 C4 四层图 |
| Day4 | 05 + 06：NFR 与模式 | NFR 清单 + 模式选型表 |
| Day5 | 07：架构评审 | 一次有产出的评审 |
| Day6 | 08 + 09：债与治理 | 债量化报告 + fitness 进 CI |
| Day7 | 10：综合实战 + 自测 | ADR 库 + 评审 + 债治理 + 20 题 |

**学习姿态的约定**：横向能力是「做出来的能力」——每个方法论都要在真实场景用一遍：ADR 写自己系统的真实决策（不是抄模板）、C4 画自己负责的模块、options matrix 评估一次真实选型、fitness 约束自己项目的依赖规则——**「方法论只有用过一次才算学会」**；本体系与 [[../L1：初级开发｜看懂架构，落地模块|L1-L4 纵向体系]] 配合学习——横向给方法、纵向给深度。
