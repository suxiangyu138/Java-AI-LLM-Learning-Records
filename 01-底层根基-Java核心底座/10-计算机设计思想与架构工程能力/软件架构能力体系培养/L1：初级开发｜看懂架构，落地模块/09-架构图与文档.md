## 1. 为什么要有架构图与文档

**架构图与文档是架构的"表达层"**——**代码是架构的实现，图与文档是架构的说明**。**三个价值**：**沟通**（一张图比一千行代码讲得清——**团队对齐的语言**）；**导航**（新成员看图找方向——**02 篇"先看地图再逛街"**）；**决策记录**（文档记录"为什么这么设计"——**架构决策的上下文**）。**图与文档的分工**：**图回答"是什么"**（结构/关系——**空间视角**）；**文档回答"为什么"**（决策/取舍——**时间视角**）——"**图是地图，文档是历史：地图告诉你在哪，历史告诉你为什么在这**"。**L1 的定位**：**会读**（看懂图与文档——本体系）；**会画简单的**（模块结构图/类图——L2 的要求）——"**L1 先学会'看图说话'，L2 再学'画图表达'**"（00 篇分工）。

## 2. C4 模型：四层架构图

**C4 模型是 2026 年主流的架构建模方法**——**四个层次从宏观到微观**（00 篇基线）：**Context（系统上下文）**——**系统与外部的关系**（谁在用、依赖什么外部系统——**"系统在大世界的位置"**）；**Container（容器）**——**系统内部的"大组件"**（Web 应用/API/数据库/缓存——**"系统的组件地图"**）；**Component（组件）**——**容器内部的模块**（订单模块/支付模块——**"模块地图"**）；**Code（代码）**——**类级别的图**（类图——**"代码地图"**）。

**L1 会读哪两层**：**Context**（知道"我们的系统在什么位置、和谁打交道"——**入职第一周看这张图**）与**Container**（知道"系统由哪些大件组成、数据在组件间怎么流"——**看懂这张图 = 看懂系统骨架**）；**Component**（配合 04 篇包结构读——**模块地图**）；**Code**（L2 之后）。**C4 的读法**：**从 Context 到 Code 逐层放大**（**先看全局再看局部**）——"**C4 是'架构的望远镜'：先远看（Context）再近看（Container）**"。

## 3. UML 类图：类的关系

**UML 类图（Class Diagram）表达"类与类的关系"**——**读懂类图的五个元素**：**类框**（类名 + 属性 + 方法——**一个类的"名片"**）；**继承**（`▷` 空心三角箭头——**子类继承父类**）；**实现**（`▷` 虚线三角——**类实现接口**）；**关联/依赖**（实线/虚线箭头——**A 用到 B**）；**组合/聚合**（实心/空心菱形——**整体与部分**）。**L1 读类图的三个场景**：**读 Service 接口与实现**（`OrderService` `▷` `OrderServiceImpl`——**04 篇 impl 包的结构图表达**）；**读实体关系**（Entity 之间的关联——**表关系的类图版**）；**读设计模式**（看类图识别模式——**L2 的进阶**）。**类图与代码的对应**：**类图是代码的"鸟瞰图"**——**IDE 里看类层级（Ctrl+H）就是类图的代码版**——"**类图回答'类怎么组织'，包结构回答'代码放哪'，两个视角互补**"。

## 4. UML 时序图：交互的顺序

**UML 时序图（Sequence Diagram）表达"一次交互的先后顺序"**——**读懂时序图的三个元素**：**生命线**（竖线——**参与交互的对象**）；**消息**（横箭头——**对象间的调用**）；**时间轴**（从上到下——**调用顺序**）。**时序图与调用链的关系**（05 篇）：**时序图是调用链的"图版"**——**L1 追踪的"Controller → Service → Mapper → DB"调用链，画成图就是一张时序图**——"**会追调用链的 L1，读时序图零门槛：时序图就是调用链的静态画**"。**L1 读时序图的场景**：**读设计文档里的核心流程时序图**（下单流程/支付流程——**业务主干的交互顺序**）；**读接口交互**（前端 → 后端 → 外部系统的顺序）。**读时序图的要点**：**先读消息顺序**（从上到下——**流程主干**）；**再看返回**（虚线箭头——**结果怎么回**）；**最后找分支**（alt/opt 片段——**条件分支**）——"**时序图是'动态架构'：调用链的静态图，流程的说明书**"。

## 5. 设计文档怎么读

**设计文档（Design Doc）是架构决策的"历史记录"**——**L1 读设计文档的方法**：**先读背景与目标**（为什么做这个——**决策的起点**）；**再读方案**（架构图 + 关键流程——**怎么做的**）；**最后读取舍**（备选方案与选择理由——**"为什么不是另一个方案"——决策的灵魂**）。**设计文档的三种常见形态**：**架构设计文档**（系统/模块设计——**C4 图的文档版**）；**接口设计文档**（契约——**06 篇**）；**技术方案评审文档**（评审会材料——**方案 + 讨论记录**）。**L1 读文档的心态**：**文档是"上下文"不是"真理"**——**文档可能过时**（代码才是最终真相——"**文档与代码冲突时，以代码为准，但去问为什么**"）——"**读文档是为了问出更好的问题，不是为了背答案**"。

## 6. 看图的五个要点

**看任何架构图的五个通用要点**：**① 看图的类型**（C4 哪层/UML 哪种——**图的视角决定读法**）；**② 看图的边界**（图包含什么、不含什么——**范围意识**）；**③ 看主要节点**（大组件/核心类——**主干**）；**④ 看连线**（关系/依赖/消息——**结构**）；**⑤ 看注释与图例**（作者想强调什么——**读图人视角**）。**看图的三问**：**"这张图回答什么问题？"**（意图）；**"主干是什么？"**（重点）；**"与我相关的是哪块？"**（定位自己）——"**看图不是欣赏，是定位——看完图要能说出'我在图里的哪个位置、我的代码在图里的哪块'**"。

## 7. 五个常见坑

- **坑一**：跳过 Context 直接看代码图——**没有全局直接看局部 = 迷路；从 Context 逐层放大**（第 2 节）；
- **坑二**：类图符号认不全就硬读——**先认五个元素再读图**（第 3 节）；
- **坑三**：时序图当类图读——**时序图看顺序、类图看关系；先辨图型**（第 6 节）；
- **坑四**：把文档当真理——**文档可能过时；以代码为准，问为什么**（第 5 节）；
- **坑五**：只看图不定位自己——**看完图说不出"我在哪" = 白看；三问收尾**（第 6 节）。

## 8. 练习 5 题

1. 图与文档的分工？"地图与历史"类比？
2. C4 四层？L1 会读哪两层？"望远镜"类比？
3. UML 类图的五个元素？类图与包结构的关系？
4. 时序图的三个元素？与调用链的关系？
5. 设计文档的三段读法？看图的五个要点与三问？

> 🎯 **核心要点**：架构图与文档 = **"图是地图、文档是历史"**——"**L1 会读 C4 的 Context/Container 两层（先远看再近看）、会看类图（关系）与时序图（顺序）**"；看图三问"回答什么问题/主干是什么/我在哪"——"看完图要能说出自己的位置"。
