## 1. 实战一：读透一个开源项目

**任务**：选一个中等规模开源项目（如 Spring Boot 官方示例/RuoYi 等），完成"读透"：

```text
① 五步读项目（02 篇）：README → 配置 → 依赖 → 入口 → 跑起来
② 架构识别（03 篇）：分层/模块化单体？一句话架构描述
③ 包结构地图（04 篇）：画出 controller/service/mapper 分层与业务模块
④ 调用链追踪（05 篇）：挑 2-3 个核心接口，画出完整调用链 + 数据流
⑤ 数据面阅读（07 篇）：核心表结构 + Redis/MQ 的角色
⑥ 架构图输出（09 篇）：画出项目的 Container 层图（C4 第二层）
```

**验收三问**：① 能用三分钟向别人讲清"这个项目是什么架构、数据怎么流"；② 能画出调用链图并指出"每个类为什么在它所在的层"；③ 能回答"如果我要加一个功能，代码该放哪、走哪条链"——**"读透的标准不是读完，是能讲、能画、能定位"**。

## 2. 实战二：落地一个小模块

**任务**：在实战一的项目（或你的工作项目）里落地一个小模块（如"新增一个查询接口"）：

```text
① 需求理解（08 篇）：功能/边界/验收标准，复述确认
② 设计：接口契约（路径/方法/参数/响应/错误码）+ 数据来源
③ 编码：代码进对层、风格对齐、复用项目已有组件
④ 自测：主流程 + 边界用例 + 回归
⑤ 提交：清晰提交信息 + 主动求评审
⑥ 复盘：六步流程走完，记录"我学到/踩坑"清单
```

**验收三问**：① 模块能跑且边界处理完整（错误码全覆盖）；② 代码 review 通过（四条架构纪律无违反）；③ 能讲清"我的代码为什么放这些位置"——**"落地的标准不是'能跑'，是'放对地方、风格对齐、经得起评审'**"。

## 3. L1 能力清单 10 项

- [ ] 能说出架构三要素并解释"架构是决策集"
- [ ] 会用五步读项目法读懂一个新项目
- [ ] 能识别分层/三层/MVC/模块化单体（一句话描述）
- [ ] 知道包结构规则与依赖方向（能指出违规代码）
- [ ] 会追调用链与数据流（断点 + 日志双视角）
- [ ] 会读接口契约并用 Swagger 对接接口
- [ ] 能读懂表结构/ORM/Redis/MQ 的角色
- [ ] 能按六步流程落地模块（四条纪律零违反）
- [ ] 会读 C4 图与 UML 类图/时序图
- [ ] 会用 AI 工具并"先思考、再生成、后对比"

## 4. 面试三范式

**范式一：项目式**——"我入职后第一周用五步法读透了订单模块：Controller-Service-Mapper 分层 + Redis 缓存热点订单 + MQ 异步发通知；第二周落地了订单取消接口，走完整六步流程，评审一次过"——**用"读透 + 落地"的具体事实讲能力**（10 篇实战）。

**范式二：方法式**——"我看懂架构的方法是定向追踪：包结构看代码在哪（04 篇）、调用链看请求怎么走（05 篇）、数据流看数据怎么变——调试看运行时、日志看生产——新项目我两周能进入状态"——**展示方法论而不只是结论**。

**范式三：架构意识式**——"我知道代码的位置由架构决定：写代码前先问'该进哪个包、走哪层'——依赖只往下、复用不重造、风格对齐——我写的代码要么守护架构，要么腐蚀它，我选择守护"——**展示架构守护者意识**（01/08 篇）。

**追问四连防身**：①"新项目怎么快速上手？"——五步读项目法（02 篇）；②"怎么定位线上 bug？"——日志 traceId 追轨迹 + 调用链还原（05 篇）；③"模块落地最关键的是什么？"——不破坏架构：进对层/只往下/复用/对齐（08 篇）；④"AI 时代初级开发怎么立足？"——AI 是放大器：先思考再生成后对比，架构能力 AI 替代不了（08 篇）。

## 5. 简历呈现

**项目写法示例**："独立完成订单模块读透与扩展：五步法梳理项目架构（分层 + 模块化单体，Redis 缓存 + MQ 异步）；落地订单取消接口（契约设计 → 分层实现 → 边界自测 → 评审通过），错误码全覆盖、异常有兜底；掌握调用链/数据流定向追踪，线上问题定位效率显著提升"——**要点：方法可复用、产出可验证、能力可迁移**。

## 8. 加试 5 题

1. 给你一个从没见过的项目，48 小时内你要交付什么证据证明"看懂了"？
2. 画一个你熟悉模块的调用链图（含数据流标注）？
3. 指出你项目里 3 处"架构被破坏"的代码并说修复方案？
