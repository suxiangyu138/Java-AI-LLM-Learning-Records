## 3. 与 L2-L4 的分工

**架构能力体系的四级分工**（本体系是 L1 第一级，后续级别待建）：

**L1（本体系）——看懂架构，落地模块**：会读项目、懂分层与数据流、在既有架构内实现模块——**"会用地图"**。

**L2 中级开发｜模块级设计**（`../L2：中级开发｜模块级设计/` 待建）：会设计一个模块——接口设计、类设计、设计模式应用——**"会画地图的局部"**。

**L3 高级开发｜子系统架构**（`../L3：高级开发｜子系统架构/` 待建）：会设计子系统——服务划分、技术选型、容量估算——**"会画地图的区块"**。

**L4 架构师｜全局系统架构**（`../L4：架构师｜全局系统架构/` 待建）：会设计全局架构——业务架构/技术架构/演进路线——**"会画整张地图"**。

**横向通用能力**（`../横向通用能力/` 待建）：沟通、文档、评审、软技能——**四级共用的"另一只手"**。

**与既有体系的分工**：写代码的好习惯（`../写代码的好习惯/00-写代码的好习惯知识体系总览.md`）管"代码怎么写好"，**本体系管"代码所在的架构怎么读懂"**；Swagger（`../Swagger/00-Swagger总览.md`）管接口文档工具，**本体系 06 篇讲接口契约的阅读方法**；高级进阶与源码学习（`../../../../02-后端核心技术 微服务 分布式 云原生/06-Spring全家桶/高级进阶 & 源码学习/00-高级进阶与源码学习总览.md`）讲源码阅读方法论——**L1 先学会读项目，进阶再学读框架源码**。

**2026-08 基线（AI 时代定位）**：AI 编程工具已深度融入开发（编码与调试环节 80-90% 合格代码可自动生成）——**AI 是放大器不是替代品**：淘汰的是"只会写 CRUD 的代码搬运工"，**看懂架构、落地模块的能力反而更值钱**（2026 LinkedIn 数据：系统架构设计能力的中级工程师薪资 +16%）；初级开发者的成长共识是"**AI 做辅助、自己先手写核心逻辑、吃透 AI 生成代码**"（先思考 → 再生成 → 后对比）——**L1 的"看懂架构"是 AI 时代最稳的护城河**。

## 4. 学习路线推荐

**路线一：标准路线（3-5 天）**——01 → 10 逐篇 + 每篇动手——**毕业标准：独立完成"读透一个开源项目 + 在既有架构里落地一个小模块"**。

**路线二：入职速成路线（2-3 天）**——01 → 02 → 04 → 05 → 08——**新项目接手最快路径**——"**入职第一周的目标：看懂项目（02/04/05），第二周开始落地模块（08）**"。

**路线三：进阶铺垫路线**——03 → 09 → 10 精读——为 L2 模块设计打基础——"**L1 的终点是'看图说话'，L2 的起点是'自己画图'**"。

## 6. 常见误区

**误区一：架构是架构师的事，初级不用管**——**L1 每天在架构里写代码**：不懂分层就会写错依赖、不懂调用链就定位不了 bug——"**不会看地图的人，在陌生城市寸步难行**"（01 篇）。

**误区二：看懂架构 = 背出技术栈**——**背出"Spring Boot + Redis + MySQL"不等于看懂**——看懂是"**知道每个组件为什么在这、数据怎么流**"（02 篇）。

**误区三：读代码从头读到尾**——**几千个文件从头读必放弃**；正确姿势是"**入口 → 调用链 → 数据流**"的定向阅读（05 篇）。

**误区四：架构模式越多越高级**——**L1 的日常 90% 是分层架构/三层架构**；微服务是"了解级"——"**先认全日常的，再谈高级的**"（03 篇）。

**误区五：落地模块 = 把需求写成代码**——**落地是'在既有架构里'落地**：遵循分层、复用现有工具、对齐既有风格——"**模块落地的第一原则是'不破坏架构'**"（08 篇）。

**误区六：AI 生成代码直接抄**——**AI 是放大器不是替代品**；"先思考、再生成、后对比"，**AI 代码要逐行吃透**（08 篇）。

**误区七：看文档不如看代码**——**架构文档（README/设计文档/C4 图）是地图，代码是街道**——"**先看地图再逛街，方向感完全不同**"（09 篇）。
