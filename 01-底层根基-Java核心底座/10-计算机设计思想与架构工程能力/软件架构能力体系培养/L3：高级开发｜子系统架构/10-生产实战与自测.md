## 1. 实战：子系统设计文档

把全体系知识点压进一个项目：为一个子系统（以「订单子系统」为例）产出完整设计文档——**「L3 的交付物是设计文档，不是代码」**。

**文档结构（对应本体系各篇）**：

```markdown
# 订单子系统设计文档

## 1. 概述与目标（01 篇）
- 子系统职责：一句话（订单全生命周期管理）
- 范围：做什么、不做什么（边界声明）

## 2. 边界与上下文（02 篇）
- 业务能力地图：订单 + 履约 + 售后
- 与其他子系统协作图（C4 L2 视角）
- 独立团队测试：职责/接口/数据/变化四独立

## 3. 模块化设计（03 篇）
- 模块划分（高内聚低耦合）+ 依赖方向图
- 循环依赖检查（ArchUnit 约束）

## 4. 接口契约（04 篇）
- API 目录（REST 端点 + 事件结构）
- 契约要素：数据模型/错误语义/幂等/版本

## 5. 数据设计（05 篇）
- 数据所有权（订单表 → 订单子系统）
- 存储选型（MySQL + Redis 缓存——ADR 记录）
- 一致性声明（订单状态强一致、报表最终一致）

## 6. 性能与容量（06 篇）
- 性能预算表（P95 200ms 分解到环节）
- 容量规划（峰值 QPS 预估 + 扩容路径）

## 7. 可靠性设计（07 篇）
- 故障模式分析表（故障/影响/对策）
- 幂等设计（幂等键 + 唯一约束）

## 8. 安全设计（08 篇）
- 威胁建模（STRIDE 清单）
- 授权设计（对象级校验——订单归属）

## 9. 可观测与运维（09 篇）
- 三支柱清单（RED 指标/trace 透传/日志规范）
- 运维就绪（健康检查/优雅停机/故障手册）

## 10. 决策记录（ADR 索引——横向体系）
- ADR-001：模块化单体起步
- ADR-002：Redis 缓存引入（含备选）
```

**验收五问**：**边界对吗**——业务能力地图 + 独立团队测试通过；**契约全吗**——API 目录 + 错误语义 + 版本策略；**数据清吗**——所有权矩阵无共享表；**非功能全吗**——性能/可靠性/安全/可观测四维都有设计与验收；**决策有据吗**——关键决策有 ADR（含被否决方案）。

## 2. 设计文档模板与纪律清单

**流程**：理解问题 → 边界识别 → 契约设计 → 内部设计 → 非功能设计（01 篇五步）。**边界**：业务能力地图、Common Closure、独立团队测试、数据所有权。**模块**：高内聚低耦合、依赖指向稳定、循环依赖 ArchUnit 拦截、深模块。**契约**：显式 API 面（明示 + 排除）、黑盒 + 可替换性测试、契约优先 + 语义化版本、同步异步按需。**数据**：所有权唯一、存储选型 options matrix + ADR、缓存三问、一致性显式声明。**非功能**：性能预算 + 容量规划 + 手段从便宜到贵；故障模式分析 + 幂等 + 重试退避 + 熔断降级预案 + 备份演练；STRIDE 威胁建模 + 对象级授权 + 数据安全三面；三支柱 + trace 透传 + 运维就绪。**治理**：设计文档进仓库、ADR 配套、评审有产出、fitness 防边界腐化（横向体系）。

## 3. 常见失败模式

**「边界错了」**——按技术层划分、共享数据库——后续设计全错——业务能力地图先行；**「契约不全」**——错误语义缺失、隐式约定——调用方全靠问——契约四要素 + 可替换性测试；**「非功能缺失」**——只画功能图——性能/可靠性/安全/可观测是设计的一部分（06-09 篇）；**「设计文档过期」**——文档写完就扔——**设计文档进仓库、与代码同 PR、ADR 配套**（横向体系活的文档）；**「设计不验证」**——画完图就交付——**设计验证三件套**：契约可替换性测试、性能压测对照预算、故障演练验证对策——**「L3 的失败模式都是「设计不完整或不验证」，完整 + 验证是 L3 的试金石」**。

## 4. 面试三范式

**价值式**：「我为订单子系统做了完整设计——边界按业务能力划分（独立团队测试通过），契约优先 + 版本化（前端并行开发），性能预算分解到链路（压测对照 P95 达标），故障模式分析全覆盖（幂等 + 熔断 + 降级预案），威胁建模 + 对象级授权（BOLA 防线）。」——先讲设计交付物与验证数据，再讲方法。

**技术式**：「子系统是业务叙事边界不是代码结构边界——Common Closure 一起变化的放一起；接口是契约不是方法集合——显式 API 面（明示 + 排除内部）、黑盒可替换性测试；依赖规则依赖指向稳定、循环依赖是红线（ArchUnit 进 CI）；深模块把复杂度拉进模块不推给调用方。」——原理到「为什么」，别停在「我画了架构图」。

**生产式**：「非功能设计是设计的一部分——性能预算 + 容量规划 + 手段从便宜到贵；故障模式分析 → 幂等/重试退避/熔断降级/备份演练；STRIDE 威胁建模 + 对象级授权（BOLA 是 API 头号漏洞）；三支柱可观测性 + trace 透传 + 运维就绪设计期完成。」——四维非功能、安全红线、可观测三点是区分度。

**追问四连**：子系统边界怎么定？（业务能力地图 + Common Closure + 独立团队测试）｜契约怎么保证质量？（显式 API 面 + 可替换性测试 + 契约优先版本化）｜缓存三问怎么防？（穿透空值/击穿互斥/雪崩随机过期）｜可靠性怎么验证？（故障演练 + 压测 + 备份恢复演练）。

## 5. 简历呈现

项目经历写法：「负责订单子系统架构设计——业务能力边界划分 + 契约优先接口设计（版本化 + 向后兼容）；性能预算分解与压测验证（P95 达标）；故障模式分析落地幂等/熔断/降级预案；STRIDE 威胁建模 + 对象级授权（越权漏洞归零）；三支柱可观测性 + trace 贯穿；设计决策 ADR 记录 10+ 条。」技能栏：「子系统架构设计（边界/契约/数据/非功能），可靠性工程（幂等/熔断/降级）」。——设计交付物 + 验证数据 + 决策记录三要素。

## 8. 加试 5 题

1. 为一个真实子系统画业务能力地图并验证边界。
2. 设计一个接口契约（含错误语义与版本策略）。
3. 性能预算表 + 容量规划完整设计。
4. 故障模式分析表（10 项故障 + 对策）。
5. 完整子系统设计文档（五步流程产出）。
