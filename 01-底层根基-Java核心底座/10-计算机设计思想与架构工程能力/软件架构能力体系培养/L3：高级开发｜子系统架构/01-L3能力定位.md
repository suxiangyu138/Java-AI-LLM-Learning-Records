# 01-L3能力定位
> 定位：L3 高级开发 = 「一个子系统的设计者」——从「把模块做对」（L2）进阶到「把子系统设计对」；核心能力是边界思维、契约思维与四维设计（数据/性能/可靠性/安全/可观测）。

## 1. 能力阶梯中的 L3

能力阶梯的四个级别，每级是「设计对象的扩大」：**L1 初级开发**——看懂架构、落地模块（「照着设计实现」）；**L2 中级开发**——模块级设计（「把一个模块设计对」——类与接口、模式应用）；**L3 高级开发**——子系统架构（「把一个子系统设计对」——边界、契约、数据、非功能）；**L4 架构师**——全局系统架构（「把整个系统设计对」——系统拓扑、技术路线、跨子系统协调）。

**L3 与 L2 的分界**：L2 在「既定边界内」做设计（模块内部）；**L3 要「定义边界本身」**——子系统怎么切、接口怎么定、数据归谁——**「从设计者到边界设计者」是 L2→L3 的跃迁**；**L3 与 L4 的分界**：L4 管「系统级」（子系统间拓扑、全局技术选型、组织协调），**L3 管「子系统内」（本子系统的完整设计）**——L3 是「L4 的组件级执行者 + 子系统的所有者」。

## 2. L3 的核心能力

L3 的能力清单（按本体系篇章组织）：**边界能力**（02 篇）——子系统识别与边界定义（业务能力、Common Closure、独立团队测试）；**模块化能力**（03 篇）——高内聚低耦合、依赖规则、复杂度治理（深模块）；**契约能力**（04 篇）——接口契约设计（显式 API 面、黑盒、版本化、兼容）；**数据能力**（05 篇）——数据所有权、存储选型、缓存与一致性；**非功能设计**（06-09 篇）——性能预算、可靠性韧性、安全、可观测运维——**「功能设计 + 非功能设计」双翼是 L3 与 L2 的另一个分界**（L2 主要做功能设计，L3 必须四维非功能）。

**L3 的交付物**：子系统设计文档（边界与组件图、接口契约、数据模型、NFR 设计、运维设计）+ 设计决策记录（ADR）——**「交付物是可评审的设计文档，不是代码」**——L3 的产出是「设计」，代码是 L2/L1 的落地。

## 3. 设计流程总览

L3 子系统设计的五步流程（与 [[../横向通用能力/02-架构权衡与决策|横向决策流程]] 同构，场景化到子系统）：**第一步，理解问题**——业务目标、功能与非功能需求、约束（「歧义是设计之敌」——需求不明确先澄清再设计）；**第二步，边界识别**（02 篇）——子系统切分、边界定义（业务能力地图）；**第三步，契约设计**（04 篇）——对外接口契约（同步/异步、数据模型、错误语义、版本）；**第四步，内部设计**（03/05 篇）——模块划分、数据设计、依赖方向；**第五步，非功能设计**（06-09 篇）——性能/可靠性/安全/可观测——**每步产出进入设计文档与 ADR**（「设计过程 = 文档化过程」——横向方法论贯穿）。

**流程的迭代**：不是线性的——「契约设计发现边界问题 → 回边界调整」——**「设计是迭代的，文档要跟得上迭代」**。

## 4. 与横向方法论的配合

横向通用能力提供「工具」，L3 提供「场景」——配合关系：**权衡决策（横向 02）→ 子系统的每次选型**（存储选型、缓存策略——options matrix）；**ADR（横向 03）→ 子系统的每个设计决策**（「为什么这个边界、为什么这个存储」——L3 的 ADR 是子系统设计的审计痕迹）；**NFR（横向 05）→ 子系统的性能预算**（06 篇的输入——「NFR 分解到子系统」）；**评审（横向 07）→ 子系统设计评审**（「设计文档 + 契约 + ADR 输入评审」）；**技术债（横向 08）→ 子系统的债治理**（设计时防新债、存量债排期）——**「L3 用横向的方法论做子系统的设计」**——两套体系配合阅读：横向讲「怎么决策」，L3 讲「设计什么」。

## 5. 2026 环境要求

L3 在 2026 年的环境要求（技术与方法）：**云原生与事件驱动**——子系统设计默认要考虑容器化部署、消息/事件驱动的异步协作（06 篇分布式模式的场景应用——[[../../../../02-后端核心技术%20微服务%20分布式%20云原生/03-消息队列/消息队列理论与实战/00-消息队列理论与实战总览|消息队列体系]]）；**契约工程**——OpenAPI/契约优先是接口设计的默认姿势（04 篇——[[../../../../02-后端核心技术%20微服务%20分布式%20云原生/09-Web开发全流程/RESTful%20API/00-RESTful%20API总览|RESTful 体系]]）；**可观测性内建**——三支柱是设计的组成部分不是事后补（09 篇）；**AI 辅助设计**——AI 编码助手参与设计文档生成与评审（「AI 是设计效率工具，设计决策仍是人的」）；**安全左移**——威胁建模在设计期进行（08 篇）。

## 6. 五条边界

**不替代 L4 的全局职责**——系统拓扑、跨子系统协调、全局技术路线是 L4——「L3 管子系统内，别越级定全局」。

**不替代横向方法论**——权衡/ADR/NFR 工具在横向体系——「L3 用工具，工具在横向」。

**不替代业务分析**——子系统边界源于业务理解——「业务不懂，边界必错」。

**不保证系统级正确**——子系统各自正确 ≠ 系统正确（接口协作、全局一致性是 L4 视角）——「L3 的正确是局部正确」。

**不做终极设计**——设计随业务演进——「设计是演进式的，文档跟着改」。

**L3 的能力验收（晋升与面试视角）**：**面试问题族**——「给你一个子系统，你怎么设计」（考察设计流程——01 篇五步）、「这个边界为什么这么切」（考察边界思维——02 篇）、「接口怎么保证不破坏调用方」（考察契约思维——04 篇）、「缓存三问怎么防」（考察非功能设计——05/06 篇）、「故障时怎么保可用」（考察韧性设计——07 篇）——**「面试问的是设计方法，不是背知识点」**——本体系十篇是「方法」，面试考「用方法回答问题」；**晋升的验收**——「能否独立交付一个子系统的设计文档」（10 篇实战就是验收标准）。
