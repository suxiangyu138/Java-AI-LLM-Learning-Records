# 10-生产实践与面试冲刺

> 定位：把前九篇收束为可执行的工程清单、可复用的排查表、可背诵的面试弹药。MVC 面试的考察核心是"概念区分（MVC/MVP/MVVM/Flux）+ 后端纪律（薄控制器）+ 前端演进（为什么退场）"三层。

## 生产落地清单（10 项）

1. **后端控制器纪律**：Controller 只做路由/绑定/编排；业务规则进 Service/领域层；行数超 200 行触发下沉审查。
2. **强类型绑定**：路径/查询参数用 Converter 绑定值对象；请求体用 record DTO + @Valid 校验；禁止 String 裸参数。
3. **错误契约统一**：@RestControllerAdvice + ProblemDetail（RFC 7807）；业务错误码进扩展字段；生产隐藏内部细节。
4. **防批量赋值**：@InitBinder setDisallowedFields 锁定不可由客户端提交的字段（id/role/status）。
5. **API 契约管理**：DTO 而非实体出网；OpenAPI 文档自动生成；契约测试（Pact）锁定跨服务接口。
6. **API 版本化**：Spring 7 用 @ApiVersion 统一策略（内部 API 选请求头、公开 API 选路径段）；策略全站一致。
7. **缓存与性能**：GET 加 ETag/Cache-Control；列表默认分页；响应 gzip；写操作幂等键。
8. **测试分层**：Controller 层 MockMvc 薄测（映射/绑定/异常映射）、Service 层厚测、领域层纯单测。
9. **前端状态分类**：局部用框架原生、共享用轻 Store、服务端数据用查询库、复杂可追溯性需求才上 Redux 系。
10. **演进路径**：简单页面 MVC/组件化够用；>300 行视图逻辑或 >20 屏上 MVVM；状态复杂再分层/DDD——架构随规模演进。

## 故障模式排查表

| 症状 | 根因 | 对策 |
|---|---|---|
| Controller 越来越胖、逻辑散落 | 上帝控制器成形 | 业务规则下沉 Service/领域层，行数门禁 |
| 改了数据库字段 API 响应变了 | 实体泄漏出网 | 一律 DTO/record 序列化，实体不出 Controller |
| 400/500 语义混乱、错误格式五花八门 | 无统一错误契约 | @RestControllerAdvice + ProblemDetail 全站统一 |
| 用户提交 role=admin 越权 | 批量赋值漏洞 | @InitBinder setDisallowedFields + 服务端二次校验 |
| 前端改了字段名接口就挂 | 无契约管理 | OpenAPI + 契约测试 + DTO 显式声明 |
| API 升级破坏老客户端 | 无版本化 | @ApiVersion（Spring 7）或网关规则统一 |
| 组件状态改不动/改了乱 | 状态层级混乱 | 按 08 篇分类：局部/共享/服务端各归其位 |
| 状态变更来源不可追 | 双向绑定滥用 | 复杂状态换单向流 Store（Pinia/Redux） |

## 面试 12 题（含答题范式）

1. **MVC 是什么？解决了什么问题** → 1979 Smalltalk 起源；关注点分离：数据/展示/控制三类变化隔离。
2. **三组件职责边界** → Model 数据规则、View 呈现、Controller 路由绑定编排；依赖方向单向。
3. **贫血模型为什么是反模式** → 业务规则散落外部、Model 退化 DTO；"加规则要改自己"才是健康 Model。
4. **MVC vs MVP vs MVVM** → 第三角色不同（Controller/Presenter/ViewModel）；View 被动化与绑定演进；可测试性递增。
5. **为什么前端 MVC 退场** → 上帝控制器、双向数据流失控、DOM 手动同步三困境；SPA 复杂度放大。
6. **MVVM 的数据绑定怎么工作** → 声明式映射 + 引擎同步；Vue 响应式（Proxy 自动追踪）vs React 单向渲染循环。
7. **Flux 解决什么** → 状态变更可追溯；单向流四纪律；Redux 三大原则（单一源/只读/纯函数）。
8. **Spring MVC 薄控制器怎么落地** → 只注入 Service、返回 DTO、业务规则下沉、行数门禁。
9. **Spring 7 API 版本化怎么做** → @ApiVersion + 四种策略（请求头/路径/查询/媒体）；基线版本语义。
10. **前后端分离后 MVC 变什么** → 后端剩 M+C（View 移交前端）；接口契约成为协作核心。
11. **MVC 与 DDD 的关系** → 不同轴：MVC 是接口层实现，DDD 是模型边界；Controller 经用例层访问领域。
12. **MVCPVM 的等价性悖论** → Model/View 恒定、第三角色必膨胀；模式之争是职责分配之争（2026）。

## 实战演练：一个评审现场

用生产清单的第 1-3 条过一遍典型评审现场：某订单模块的 OrderController 共 400 行，内含"金额计算（if 金额>1000 打 95 折）"、"直接调 JdbcTemplate 查库存"、"手写 JSON 拼接返回"、"try-catch 吞掉 SQL 异常返回 {success:false}"四处典型违规。评审结论按清单逐条：**薄控制器违规**——业务规则（打折）应下沉领域层，数据访问（库存查询）应进 Service/仓储；**错误契约违规**——手写 JSON 与吞异常应替换为 @RestControllerAdvice + ProblemDetail（错误码 + 状态码语义化）；**DTO 违规**——手写 JSON 说明没有 DTO 契约，应定义 OrderDto 并序列化。改造后的 Controller 缩至 60 行，四个违规清零。演练的意义：**清单的价值在评审现场被激活**——拿着清单过代码，比凭感觉 review 发现问题的速度快一个量级；这也是 10 篇清单的设计目的。面试中讲这个演练比背十条纪律更打动人——它同时证明了你"知道纪律"和"用过纪律"。

## 高频题的完整答题模板

**模板一：MVC 是什么（1 分半版）**——先给起源（1979 Smalltalk，Trygve Reenskaug，解决图形应用的三类变化隔离），再给三组件职责（Model 数据规则/View 呈现/Controller 路由绑定编排），最后给依赖方向（View→Controller→Model 单向，Model 不感知 UI）。收尾一句："关注点分离是思想，三组件是制度化，上帝控制器是它的代价"——三个层次全答到，直接进入加分区。

**模板二：MVC vs MVVM（2 分钟版）**——用 03 篇的等价性框架：Model 与 View 恒定，第三角色不同（Controller 管输入路由、ViewModel 管状态转换）；MVVM 的绑定引擎消灭手动刷新；可测试性差异（ViewModel 零 UI 依赖）。补 2026 实证（SwiftUI/Compose 把 MVVM 设为默认）与选择阈值（<250 行用 MVC、>300 行迁 MVVM）。

**模板三：前端 MVC 为什么退场（1 分半版）**——四大困境（上帝控制器、双向数据流失控、职责混合、DOM 手动同步）→ 三步演进（MVVM 消灭手动同步 → 组件化拆散职责 → 微前端扩展组织）→ 2026 结论（MVC 遗产 = 关注点分离，以 hooks/组合式函数形态重生）。Backbone 复盘是加分素材（同步自动化与可追踪性两条主线）。

**模板四：Spring MVC 实践（2 分钟版）**——薄控制器纪律（路由/绑定/编排，<150 行）→ 强类型绑定（Converter 值对象）→ 集中错误处理（ProblemDetail）→ 测试（MockMvc + 契约测试）→ Spring 7 版本化（@ApiVersion 四种策略）。全部来自 05/06 篇，回答顺序即"从日常到前沿"。

## 加分深度题

**Q：为什么 MVVM 可测试性高于 MVC？** ViewModel 是零 UI 依赖的纯对象（不 import View），两行代码实例化即测；Controller 绑死 servlet/UI 环境。2026 年迁移研究结论：可测试性是团队迁离 MVC 的第一驱动力。

**Q：Vue 与 React 谁更 MVVM？** 机制差异而非优劣：Vue 用 Proxy 响应式（双向绑定语法糖 v-model，自动但不透明）；React 用渲染循环（单向显式，受控组件手写双向）。两者都实现"状态驱动视图"的 MVVM 思想。

**Q：状态管理为什么从 Redux 大一统走向分类管理？** Redux 解决可追溯但代价是样板与全局重渲染；状态实际分四类（局部/派生/共享/服务端），各自有更优方案（框架原生/计算属性/轻 Store/查询库）——分类是 2026 共识。

## 面试速记

1. MVC = 关注点分离的粗粒度制度化；第三角色（Controller）的职责边界是永恒议题。
2. 家族演进 = 每个新模式修正前一个的"第三角色膨胀"；MVCPVM 证明五角色显式分配才是终局。
3. 2026 格局 = 后端 MVC（Spring 7 仍在进化）+ 前端 MVVM/组件化 + Flux 单向流兜底复杂状态。
4. Spring 7 四件套 = @ApiVersion 版本化、ProblemDetail 错误契约、PathPatternParser、Jackson 3。
5. 架构提问式 = "它在哪个轴上做决策"——接口/分层/边界/部署四轴分离，组合而非互斥。

> 🎯 **核心要点**：MVC 的生产价值 = 接口层的纪律（薄控制器、强绑定、统一错误）；面试价值 = 用"第三角色职责分配"串起全部家族史（01-03 篇），用"轴系思维"串起全部架构关系（09 篇）。能画出"1979 → 2026 的完整演进逻辑"与"后端纪律清单"，就拿到了 MVC 的满分答案。四个答题模板覆盖了 MVC 面试的全部高频题型——概念、对比、演进、实践——背熟结构，现场填充细节，是最高效的备战方式。评审演练段落则证明：清单的价值在评审现场被激活——拿着清单过代码，比凭感觉 review 快一个量级。
