# 09-成本管理与生产规范：账单治理与团队工程

> 定位：Actions 账单失控的路径是"规格 × 频率 × 无效运行"的复利——没人治理时，90% 的分钟烧在空跑、超大规格与低命中缓存上。本篇给出成本模型、优化手段清单与团队规范，让 CI 账单可解释、可收敛、可审计。

## 1. 成本模型：账单从哪来

总成本 = **计费分钟 × Runner 单价 + 存储超量费**，其中：

- 计费分钟 = 每次运行的 job 分钟数 × 运行次数 × 矩阵组合数——三个乘数各自可优化。
- Runner 单价按规格分档（04 篇定价表）：同一分钟数，64 核是 2 核的 27 倍价——**规格选错是最大的隐性浪费**。
- 存储费 = 制品/缓存超量部分（$0.25/GB/月 + $0.07/GB/月，07 篇）——小型团队通常不超，超了说明治理缺失。

**成本画像三问**：① 每月的运行次数分布（哪个工作流占大头）？② 平均规格利用率（4 核跑 lint 就是浪费）？③ 缓存命中率（命中率低 = 每次全量装依赖）？用 GitHub 用量 API 或 Billing 页面拉数据再动手，禁止凭感觉优化。

## 2. 优化手段清单（按 ROI 排序）

**第一梯队（零成本，立即生效）**：

- **路径过滤**：`paths` 限定代码变更才触发——文档、配置、README 变更不跑 CI，直接砍掉 20-50% 空跑（01 篇）。
- **规格匹配**：lint/单测 2 核、编译 4-8 核封顶；Java 构建优先 `ubuntu-24.04-arm`（arm64 便宜 20-39%，JDK 支持完整）。
- **timeout-minutes**：job 全设超时，防死循环/挂起烧分钟（02 篇）——一条配置挡住最贵的单次事故。
- **手动重跑纪律**：失败排查用 `workflow_dispatch` 小范围复现，别用"重跑全部"试错（重跑 = 全矩阵 × 全步骤）。

**第二梯队（改配置，一周内）**：

- **矩阵收敛**：日常只跑代表组合，全组合挪到发版前/夜间（08 篇）；`exclude` 剔除无意义组合。
- **缓存治理**：确认命中率（设置页看 cache 命中数据）；key 用内容哈希；Maven 用 `setup-java` 的 `cache: maven` 内置；避免缓存抖动触发 2026 上传限流（07 篇）。
- **并发治理**：`concurrency` 取消重复 push 的旧运行（02 篇）；schedule 任务合并（一天一次全量，不要每个仓库各跑一遍）。

**缓存与制品的成本对比（容易搞混的一块）**：缓存与制品都占存储，但计费模型不同——缓存按仓库 10GB 免费（超量付费扩容，$0.07/GB/月），制品与 Packages 共享组织存储池（Free 500MB 起步，超量 $0.25/GB/月）。预算分配时的参考口径：**依赖缓存尽量吃免费额度**（10GB 对多数团队绰绰有余，key 治理好即可）；**制品池要按"保留期 × 上传量"预估**——大量上传 + 默认 90 天保留的组合是小团队超量的头号原因。两条治理线并行：缓存放量、制品收敛（保留期缩短 + 上传裁剪），才能让存储账单稳定在免费线内。

**第三梯队（结构性，按季度）**：

- **自托管迁移**：高频重复的工作流（每日全量构建）移到自托管（04 篇）；注意维护成本与安全隔离的权衡。
- **可复用收敛**：多仓库重复工作流抽成 reusable（08 篇）——省的不只是分钟，还有维护人力。
- **企业级账单分析**：GitHub API（`GET /repos/{owner}/{repo}/actions/workflows/{id}/timing` 拿每工作流时长与费用）或第三方分析工具，按"工作流 × 仓库"出月度报表，超支看板化。

**用量监控的工程化**：账单页面（Settings → Billing）只给总额，要"哪个工作流烧了多少分钟"必须自己建监控。最小实现：定时工作流每天调 `GET /repos/{owner}/{repo}/actions/workflows` 遍历 + `timing` 接口拉各工作流本月 `billable` 分钟，落表后按"工作流 × 分支 × 矩阵成员"聚合，超阈值发群通知；进阶做法是接成本分析服务（按仓库、按团队分账）。监控的价值不在数字本身，而在**归因**——知道"release 工作流的 64 核重跑"烧掉多少钱，优化动作才有靶心。

**分钟配额与超支控制**：配额是 org 全局共享的——一个仓库的失控会挤占其它团队。控制手段按强度递增：① 用量告警（接近配额 80% 告警）；② 分支限制（`on` 限定受信分支跑全量，其它分支只跑 lint）；③ 规格限制（组织规范"编译级才允许 8 核以上"，review 把关）；④ 超支预算（月度预算 + 超出冻结手动触发）。把"配额是公共资源"写进团队规范，比任何技术手段都重要。

## 3. 团队规范：CI 即代码的工程纪律

**仓库结构规范**：`.github/workflows/` 按"触发域"命名（`ci.yml`、`release.yml`、`weekly.yml`）；可复用件放 `.github/actions/` 与独立仓库；模板仓库（`java-service-template`）内置标准 CI，新仓库十分钟接入。

**代码规范**：

- 工作流文件过 review（PR 里改 `.github/workflows/` 视为代码变更，与代码同门禁）。
- actionlint 进 pre-commit 与 CI——工作流自身质量问题（字段拼错、表达式错）在合并前拦住（02 篇）。
- YAML 不写超过 200 行的单文件——拆文件、抽 reusable（可读性即可维护性）。
- 版本引用规范：官方 `@major`，第三方 pin SHA（05/06 篇）。

**权限与密钥规范**：`permissions` 全部显式声明；secrets 按"环境级 > org 级 > repo 级"放置；明文配置走 `vars`；密钥季度轮换（06 篇）。

### 3.1 规范落地的三步走

写规范容易，让团队执行难——按"模板 → 门禁 → 复盘"三步落地：第一步，**模板仓库**承载标准 CI（Java 服务模板、前端模板、Lib 模板），新仓库一律从模板起，杜绝"每个仓库一套写法"；第二步，**门禁**——工作流文件变更走 PR review，actionlint 进 pre-commit，关键仓库用组织级规则（如"禁止缺少 permissions 的工作流合并"）兜底；第三步，**复盘**——月度成本报表开会过一遍，超支工作流当场定优化动作，把"成本意识"沉淀成团队习惯。三步都做到位，规范才不是墙上的文档而是运行的制度。

**评审清单（工作流 PR 必查六项）**：① 触发事件与路径过滤是否符合预期？② permissions 是否显式最小？③ secrets 引用是否经 env、无明文？④ 有无 concurrency 与 timeout？⑤ 矩阵组合是否收敛、规格是否匹配负载？⑥ 失败路径（always/failure）是否覆盖？六项与 actionlint 的静态检查互补——lint 查语法，清单查设计。

**成本文化的建立（治理的最后一公里）**：技术手段（路径过滤、矩阵收敛、规格匹配）解决的是"能省的都省了"，而账单长期稳定靠的是**成本文化**——把"这次改动多花了多少分钟"写进工作流 PR 的描述模板（改动矩阵、加步骤时自评分钟影响）；月度成本复盘会展示"优化成果 vs 新增消耗"的趋势线；把分钟消耗做成团队 KPI 的一部分（如"每千次部署的 CI 分钟数"）。成本文化不是抠门，而是让每个开发者都理解"CI 是公共资源"——这与《软件工程上的设计思想》里"系统韧性"的思想一致：资源意识是工程素养的一部分。

## 4. 2026 最佳实践基线（Modernize 清单）

社区与企业共识的"2026 现代化工作流"检查单：

1. 新仓库默认 `permissions: read-all` 或显式最小权限。
2. 所有 job 有 `timeout-minutes` 与 `concurrency` 组。
3. 依赖缓存用内容哈希 key + setup 工具内置缓存。
4. 制品裁剪上传 + 保留期设置 + SBOM 附签。
5. 第三方 Action pin SHA + Dependabot 自动更新。
6. 部署类 job 挂 environment + 审批 + OIDC 云凭证。
7. 模板仓库统一标准，杜绝"每个仓库一套写法"。
8. 月度成本报表 + 超支告警。

逐项打勾后，CI 从"能跑"进入"可治理"——这也是面试讲"我的 CI 做得怎么样"的完整叙事（10 篇答题范式）。

## 5. 企业治理（Org 级视图）

- **Runner Groups 与配额**：org 级分组限制哪组 Runner 能跑哪些环境（04 篇）；托管 Runner 并发上限按计划封顶，超限排队属正常。
- **审计日志**：企业版可查"谁改了工作流、谁用了 secrets"——供应链合规（06 篇）与成本审计的底账。
- **禁用策略**：org 可限制市场 Action 白名单（允许列表模式）——金融机构与政务场景的标准配置，杜绝"开发者随手装了个来路不明的 Action"。

> 🎯 核心要点：成本治理的三板斧是**路径过滤、规格匹配、矩阵收敛**——零成本先做；生产规范的核心是"CI 即代码"——过 review、跑 lint、有模板；企业治理的关键是"市场白名单 + 审计日志"——把供应链风险关进笼子。
