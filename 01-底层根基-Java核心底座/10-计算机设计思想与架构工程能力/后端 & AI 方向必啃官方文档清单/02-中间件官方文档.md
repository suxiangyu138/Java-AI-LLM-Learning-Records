## 2. MySQL（8.4 LTS / 9.x）

### 2.1 版本策略

| 版本 | 性质 | 建议 |
|------|------|------|
| 8.0 | 老 GA（2018），仍大量部署 | 阅读时注意行为已变（默认认证、JSON、优化器） |
| **8.4 LTS** | 2024 起的 LTS，**推荐阅读基准** | 面试与生产首选 |
| 9.x | Innovation 版（功能先行） | 了解新特性即可，不选型 |

> ⚠️ **5.7 时代的坑**：网上的"MySQL 总结帖"大量基于 5.7——默认字符集、`caching_sha2_password`、JSON 索引、优化器行为（直方图、代价模型）在 8.0+ 全部不同。答案以 8.4 手册为准。

### 2.2 精读章节清单

| 主题 | 手册章节 | 面试触点 |
|------|---------|---------|
| InnoDB 存储引擎 | InnoDB In-Depth（行格式、页结构、表空间） | 页/B+树/聚簇索引 |
| 索引 | InnoDB 索引类型（聚簇/二级/全文）、B-Tree 索引细节、索引优化（EXPLAIN 输出列） | 最左前缀、回表、覆盖索引、索引下推 |
| 事务与隔离 | InnoDB 事务模型、隔离级别、MVCC（隐藏列/undo log/ReadView）、锁（记录/间隙/临键锁） | MVCC 原理、幻读、隔离级别 |
| 锁机制 | InnoDB 锁类型与兼容矩阵、死锁检测 | 锁升级、死锁分析 |
| Buffer Pool | 缓冲池结构与 LRU、预读、change buffer | 缓存命中率、淘汰 |
| SQL 优化 | EXPLAIN 详解、optimizer trace 简介 | 慢 SQL 分析流程 |
| 复制与高可用 | 主从复制（binlog）、半同步、Group Replication | 主从延迟、数据一致性 |

## 3. Redis（8.x）

### 3.1 精读章节清单

| 主题 | 文档章节 | 面试触点 |
|------|---------|---------|
| 数据结构 | Data types（String/Hash/List/Set/ZSet/Stream/JSON）、内部编码简介 | 底层实现、选型 |
| 持久化 | Persistence（RDB/AOF、混合持久化、AOF 重写） | 数据丢失窗口、重启恢复 |
| 复制 | Replication（主从、增量同步、PSYNC2） | 主从延迟、断线续传 |
| 哨兵 | Sentinel（故障转移、客观/主观下线） | 哨兵选举、脑裂 |
| 集群 | Cluster（槽位、重分片、MOVED/ASK） | 集群一致性、扩缩容 |
| 过期与淘汰 | Expire 机制、Memory management（LRU/LFU/随机） | 过期删除策略、内存淘汰 |
| 事务与脚本 | Transactions、Lua 脚本（原子性） | 分布式锁可靠性 |
| 可靠性进阶 | Redis 8 新特性页（可搜索索引、JSON、触发器等模块演进） | 新版本能力 |

> ⚠️ 网上"Redis 八股"错误高发区：过期删除是惰性 + 定期（不是定时删除）；淘汰策略是 `maxmemory-policy` 配置；哨兵不是数据层方案。以上均以官方 Persistence/Replication/Cluster 章节为准。

## 4. Apache Kafka（4.x）

### 4.1 版本大事件

| 版本 | 变化 |
|------|------|
| 3.x | KRaft 逐步替代 ZooKeeper（3.5+ 默认） |
| **4.0（2025-04）** | **彻底移除 ZooKeeper**，KRaft-only；API 兼容但内部协议变化 |
| 4.x 新特性 | 弹性复制、层级存储（Tiered Storage）推进、性能提升 |

> ⚠️ **旧教程全面过时**：写 "ZooKeeper 管理 Kafka" 的教程在 4.x 下直接失效；配置项 `zookeeper.connect` 已删除。以 [Kafka Documentation](https://kafka.apache.org/documentation/) 顶部版本标注为准。

### 4.2 精读章节清单

| 主题 | 文档章节 | 面试触点 |
|------|---------|---------|
| 核心设计 | Design（消息日志、分区、副本、消费者组原理） | 分区消费模型、ISR |
| 生产者 | Producer（异步发送、acks、幂等、事务） | 可靠投递参数 |
| 消费者 | Consumer / Consumer Groups（提交、再均衡、组协议） | 再均衡触发、offset |
| 可靠性 | Delivery semantics（at-most/at-least/exactly-once）、事务 | 恰好一次实现 |
| 副本与高可用 | Replication（ISR、leader 选举、min.insync） | 副本因子、数据丢失边界 |
| 运维 | KRaft（控制器、格式化与迁移）、Topic 管理 | 集群部署形态 |
| Kafka Streams | 流处理概念（KTable/KStream、窗口） | 流式计算理解 |

## 5. RocketMQ（5.x）与 RabbitMQ（4.x）

### 5.1 RocketMQ（rocketmq.apache.org/docs/）

| 主题 | 章节 | 面试触点 |
|------|------|---------|
| 架构 | 架构设计（NameServer/Broker/Producer/Consumer）、存储设计（CommitLog/ConsumeQueue） | 为什么用 NameServer、零拷贝 |
| 消息模型 | 消息类型（普通/顺序/延迟/事务/批量）、消息过滤 | 顺序消息实现 |
| 可靠性 | 消息重试与死信、消息轨迹、消息去重、事务消息（半消息机制） | 事务消息原理 |
| 高可用 | 主从同步（Dledger）、消费者负载均衡 | 故障转移 |
| 5.x 变化 | 5.x 新架构（Proxy、gRPC 协议、Pop 消费模式） | 与 4.x 差异 |

### 5.2 RabbitMQ（www.rabbitmq.com/docs/）

| 主题 | 章节 | 面试触点 |
|------|------|---------|
| 核心模型 | Exchanges/Queues/Bindings（类型与路由规则） | 四种交换器、消息流转 |
| 可靠性 | Publisher Confirms、Consumer ACKs（basic.ack/nack）、DLX | 确认机制、死信 |
| 集群 | 集群概念、仲裁队列（Quorum）、流队列（Streams）、镜像队列（已弃用） | 高可用演进 |
| 延迟消息 | 延迟插件（Delayed Message Exchange） | 延迟队列实现 |
| 网络分区 | 网络分区处理策略 | 集群脑裂 |

> 🎯 **选读原则**：RocketMQ 与 RabbitMQ 面试二选一深读即可（国内岗位 RocketMQ 更常见，外企/云原生岗位 RabbitMQ 常见）；但 Kafka 是必读。三者的**可靠性思维框架**（确认/重试/死信/幂等）是通用的。

## 6. Elasticsearch（9.x）

| 主题 | 章节 | 面试触点 |
|------|------|---------|
| 基础概念 | 文档/索引/分片/副本、映射（mapping）、分析器 | 分词、倒排索引 |
| 查询 | Query DSL（term/match/bool/范围/复合查询） | 检索语法 |
| 聚合 | Metrics/Bucket/Pipeline 聚合 | 统计场景 |
| 集群 | 分片路由、节点角色、ILM（索引生命周期） | 扩容、冷热架构 |
| 版本变化 | 7.x 移除 types → 8.x 默认安全 → 9.x 特性 | 版本迁移概念 |

> 🟢 按需：只有做全文检索/日志平台岗位才深读；校招掌握概念 + Query DSL 基础即可。

## 7. Nacos（3.x）

| 主题 | 章节 | 面试触点 |
|------|------|---------|
| 注册中心 | 服务注册与发现流程、健康检查、心跳 | 与 Eureka 对比 |
| 配置中心 | 配置管理、动态刷新（长轮询）、灰度发布 | 配置推送原理 |
| 一致性 | 一致性协议（Raft/JRaft 应用）、AP/CP 模式切换 | 临时/持久实例一致性权衡 |
| 3.x 变化 | 3.0 架构重构（新存储层、多数据库支持） | 与 2.x 差异 |
| 高可用 | 集群部署、Distro 协议 | 注册中心高可用 |

> ⚠️ 网上教程多为 1.x/2.x 时代（含 ZooKeeper 选主描述），Nacos 3.x 一致性实现已演进；概念问答以官方 3.x 文档为准。

## 8. 面试对照：一篇文档对应一道题

| 官方文档章节 | 面试题 |
|-------------|--------|
| MySQL InnoDB MVCC | "MVCC 怎么实现可重复读？ReadView 怎么生成？" |
| Redis Persistence | "AOF 和 RDB 的区别？重启恢复顺序？" |
| Kafka Design/Consumer Groups | "分区再均衡会发生什么？怎么避免？" |
| RocketMQ 事务消息 | "半消息怎么保证本地事务与消息发送一致？" |
| RabbitMQ Publisher Confirms | "如何确认消息不丢？confirm 与事务区别？" |
| Nacos 一致性 | "临时实例为什么用 AP？配置中心为什么偏 CP？" |

> 🎯 **核心要点**：中间件面试的高分路径 = 官方文档的**机制章节**（原理图 + 时序）+ 一张自画的对比表。八股背结论，官方文档背机制，面试官要的是后者。
