## 3. 学习路线（双轨）

### 3.1 校招路线（3 个月倒排）

| 阶段 | 时间 | 内容 | 产出 |
|------|:---:|------|------|
| 第一阶段：地基 | 第 1~3 周 | JDK 集合/并发/NIO API 精读 + Spring Framework 容器章节 | 每类画 1 页原理图 + 1 篇笔记 |
| 第二阶段：框架 | 第 4~6 周 | Spring Boot 自动配置 + Redis + MySQL 8.4 | 手写 starter 一个、索引原理笔记 |
| 第三阶段：中间件 | 第 7~9 周 | Kafka/Rabbit + Nacos + 消息可靠性 | 消息链路对比表 |
| 第四阶段：AI 分叉 | 第 10~12 周 | OpenAI/DeepSeek API + LangChain + Milvus | 一个 RAG Demo + 评估笔记 |

优先级排序（校招）：`Spring Boot > Spring Core > JDK API > Redis > MySQL 8.4 > Git > Docker > Kafka 基础 > LangChain > MDN HTTP`

### 3.2 在职精进路线（按需打点）

| 方向 | 文档打点顺序 |
|------|-------------|
| 微服务/云原生 | Spring Cloud 子集 → Nacos → Kubernetes → 可观测性 |
| 数据/AI 应用 | Spring AI → Milvus → 部署推理（Ollama/vLLM）→ 评估 |
| 性能调优 | JVMS GC 规范 → JDK 工具参考 → Linux man/perf → MySQL 执行计划 |

> 🎯 **核心要点**：两条路线的共同原则——**文档是查的，不是背的**。第一遍建立索引（知道"哪类问题去哪章"），第二遍按需精读（遇到问题带题进来读），第三遍才是面试前"结论速查"。

## 4. 方法论七条（为什么官方文档值得啃）

| # | 方法 | 具体做法 | 常见误区 |
|---|------|---------|---------|
| 1 | 问题驱动，勿逐字通读 | 带着问题跳转对应章节；第一遍只做"目录级索引" | 把 Reference 当小说读，两周看完一无所获 |
| 2 | Reference > QuickStart | QuickStart 只用于"跑通"，原理看 Reference 章节 | 只跑 demo 就以为自己会了 |
| 3 | 版本纪律 | 读文档前先看页脚版本与语言；**版本错了等于白读** | MySQL 看 5.7 文档答 8.0 行为；Boot 3 教程套 Boot 4 |
| 4 | API 文档与 Reference 分开看 | Javadoc 看契约（参数/异常/线程安全），Reference 看设计意图 | 只看博客结论，不读方法契约 |
| 5 | 结论笔记 + 交叉验证 | 官方结论抄录 → 与博客对比 → 标注"博客错误点" | 无条件采信"总结帖"（多为 5.7 时代/3.x 时代产物） |
| 6 | 中文版看时效 | 官方中文翻译通常滞后英文版数个版本，术语也容易过时 | 中文站内容与版本下拉不一致 |
| 7 | AI 陪读但要防幻觉 | 把官方章节喂给 AI 提问、做错题讲解；**AI 答错时以官方文档为准** | 把 AI 回答当事实源（它不会告诉你它没读文档） |

> ⚠️ **AI 时代的学习纪律**：AI 能加速阅读，但知识库文档常有幻觉。正确姿势 = "AI 生成初稿 → 官方文档核验 → 标记版本"三步走；面试输出时引用文档结论而非 AI 转述。

## 6. 原稿剖析：优化了什么、修正了什么

| 维度 | 原稿观点 | 本文处置 | 理由 |
|------|---------|---------|------|
| 结构 | 单篇堆叠列表，URL 用代码块 | 6 篇分域 + 表格化 + 每篇精读章节清单 | 列表无法支撑"查得着"；表格适合速查 |
| 遗漏 | 无 Kafka、ES、Spring AI、LangChain4j、JVM 规范、K8s、Linux | 全部补入并标注优先级 | 后端高频中间件与 AI 主战场不可缺 |
| 版本盲区 | 只写"MySQL 8.0"，未提 8.4 LTS 与 9.x | 明确版本窗口与 LTS 选择 | 5.7→8.0→8.4/9.x 行为差异巨大 |
| 偏颇建议 | "Spring Cloud 全套可暂时不硬啃"一刀切 | 拆成**必啃子集**（Nacos + OpenFeign + Gateway 概念 + Stream 基础） | 校招被问微服务是常态，子集必须会 |
| URL 错误 | MDN 链接含全角连字符 `zh‑CN`（无法访问） | 修正为 `zh-CN` 并给出镜像 | 链接失效 = 文档白给 |
| 方法深度 | 三条泛泛建议 | 方法论七条 + 双轨路线 + 版本纪律 | 空话变可执行清单 |
| AI 方向 | 仅 4 条 | 扩展至模型 API/框架/向量库/部署/评估五层 | 覆盖 RAG/Agent 完整链路 |

> 💡 **保留的原稿精华**：① "不要逐字通读"；② "Reference 优先于 QuickStart"；③ "做笔记对比博客甄别错误"——这三条直接吸收进方法论。
