## 2. MDN HTTP：事实上的官方文档

### 2.1 精读章节清单

| 主题 | MDN 章节 | 面试触点 |
|------|---------|---------|
| 状态码 | HTTP 响应状态码（1xx~5xx 全表） | 301/302/307/308 区别、401 vs 403、429 |
| 请求方法 | GET/HEAD/POST/PUT/DELETE/PATCH/OPTIONS 语义 | 幂等性、安全方法 |
| 请求头/响应头 | 请求头与响应头参考（Accept/Cache-Control/ETag 等） | 协商缓存 vs 强缓存 |
| 缓存 | HTTP 缓存（Cache-Control 指令表、ETag/Last-Modified、新鲜度） | **缓存是面试必考** |
| Cookie | Cookie 属性（HttpOnly/Secure/SameSite/Partitioned） | 会话管理、CSRF 防护 |
| CORS | CORS（跨源资源共享、预检请求、简单请求） | 跨域原理、预检触发条件 |
| 版本对比 | HTTP/1.1 vs HTTP/2 vs HTTP/3（协议指南） | 多路复用、队头阻塞 |

> 🎯 **核心要点**：HTTP 面试五连 = 状态码语义 + 缓存机制 + Cookie 属性 + CORS 流程 + 版本演进。MDN 的这五个章节就是标准答案来源，比零散博客完整且无版本过期问题。

### 2.2 阅读建议

- 先读"HTTP 缓存"与"CORS"两个长文（概念完整、配图清晰）；
- 状态码与头字段用**查表法**：遇到问题回来看对应条目；
- 中文版与英文版有同步差异，术语存疑时切英文页确认。

## 3. RFC：规范怎么读

### 3.1 RFC 是什么

RFC（Request for Comments）是互联网工程任务组（IETF）发布的规范文档，**是协议的"法律原文"**。特性：

| 特点 | 说明 | 阅读策略 |
|------|------|---------|
| 规范性语言 | MUST/SHOULD/MAY 有严格语义 | 只关注 MUST/必须 与关键定义 |
| 结构固定 | 术语表、消息格式、状态机、错误码 | 直接跳对应章节 |
| 修订频繁 | HTTP 语义 2022 年整合进 RFC 9110-9114 | 不要读 7230-7235 旧号（已废弃替代） |
| 英文长文 | 单篇几十页 | 目标导向：查定义 → 抄关键表 → 走人 |

### 3.2 HTTP 系列规范对应

| 新版 RFC | 内容 | 对应旧 RFC |
|----------|------|-----------|
| RFC 9110 | HTTP 语义（方法/状态码/头字段语义） | 7230/7231/7232/7233/7235 等 |
| RFC 9111 | HTTP 缓存 | RFC 7234 |
| RFC 9112 | HTTP/1.1 消息语法 | RFC 7230 |
| RFC 9113 | HTTP/2 | RFC 7540 |
| RFC 9114 | HTTP/3（QUIC） | RFC 7540 的替代方向 |

> ⚠️ **别读旧号**：网上大量引用 RFC 7230-7235，2022 年已被 9110-9114 替代。面试答"RFC 怎么说的"时引用新号更专业。

## 4. HTTP 演进精读（1.1 → 2 → 3）

| 维度 | HTTP/1.1 | HTTP/2 | HTTP/3 |
|------|----------|--------|--------|
| 连接模型 | 每请求一连接（keep-alive 复用） | 单连接多路复用（流/帧） | 单连接多路复用（QUIC） |
| 队头阻塞 | 请求级队头阻塞 | 传输层仍有 TCP 队头阻塞 | 无 TCP 队头阻塞（QUIC over UDP） |
| 头部压缩 | 无 | HPACK | QPACK |
| 加密 | 可选 | 事实强制 TLS | 内置 TLS 1.3 |
| 二进制 | 文本协议 | 二进制分帧 | 二进制分帧 |

面试高频追问点：

| 追问 | 官方依据 |
|------|---------|
| HTTP/2 的队头阻塞为什么还存在？ | TCP 层面丢包重传阻塞（RFC 9113 第 1 节 + RFC 9114 第 1 节） |
| 3xx 重定向为什么 307/308 保留方法？ | RFC 9110 第 15.4 节（307/308 语义保持） |
| 缓存什么场景不该用？ | RFC 9111 缓存键与 Vary 语义 |

## 5. TCP 与 TLS 关键规范

| 规范 | 精读点 | 面试触点 |
|------|--------|---------|
| RFC 9293（TCP） | 三次握手/四次挥手状态机、连接建立与释放、超时重传与拥塞控制概念 | 握手挥手、TIME_WAIT |
| RFC 8446（TLS 1.3） | 握手流程（1-RTT/0-RTT）、密钥协商、与 TLS 1.2 差异 | HTTPS 握手过程、前向安全 |
| RFC 6455（WebSocket） | 升级握手（Upgrade 头）、帧格式、关闭帧 | 长连接、全双工 |

> 💡 TCP 的官方文档是"规范语言"，学习阶段配合抓包（Wireshark）看真实时序比纯读 RFC 高效得多——规范给定义，抓包给直觉。

## 6. 协议面试考点对照表

| 考点 | 首选来源 | 官方章节 |
|------|---------|---------|
| 强缓存 vs 协商缓存 | MDN HTTP 缓存 | Cache-Control/ETag/Last-Modified |
| 状态码 301/302/307/308 | MDN 状态码 | 重定向语义 |
| CORS 预检流程 | MDN CORS | 预检请求、Access-Control-* |
| Cookie SameSite | MDN Cookie | 同站策略、CSRF |
| HTTP/2 多路复用 | MDN 协议指南 + RFC 9113 | 流与帧 |
| HTTPS 握手 | RFC 8446 | 密钥交换流程 |
| 幂等性 | RFC 9110 第 9.2 节 | 方法语义表 |

## 7. 本方向避坑清单

| # | 坑 | 规避 |
|---|----|------|
| 1 | 读 7230-7235 旧 RFC | 一律用 9110-9114（2022 整合版） |
| 2 | RFC 全文通读 | 只查定义与状态机，目标导向 |
| 3 | 中文 MDN 版本滞后（新状态码如 425 中文缺失） | 关键条目切英文页确认 |
| 4 | 背状态码数字不背语义场景 | 结合"缓存/重定向/CORS"场景理解 |
| 5 | HTTP/3 答成"就是快" | 答得出 QUIC 解决的 TCP 队头阻塞与 0-RTT |
| 6 | 忽略抓包验证 | 握手/缓存行为用浏览器 DevTools + Wireshark 实测 |
