## 2. Maven（3.9 LTS / 4.x）

### 2.1 版本说明

| 版本 | 说明 |
|------|------|
| 3.9.x | 长期维护线，企业存量主力 |
| **4.x（2025 发布）** | 新主版本：默认构建管线重构（pom 与 builder 分离）、`mvn build` 简写、性能提升；兼容 3.x 多数项目 |

> ⚠️ 面试与日常项目大概率仍是 3.9 语法，但 4.x 已进入主流——知道差异点即可（4.x 的 `mvn build`、removed plugins 等）。

### 2.2 精读章节清单（Maven Guides）

| 主题 | 文档 | 面试触点 |
|------|------|---------|
| 生命周期 | Lifecycle Reference（clean/default/site 三套生命周期与阶段） | 各阶段执行顺序 |
| 依赖机制 | Dependency Mechanism（scope 表、传递依赖、依赖仲裁） | 传递冲突、scope 语义 |
| 坐标与仓库 | POM Reference（groupId/artifactId/version）、settings.xml | 私服、mirror |
| 插件 | Plugin 机制（phase ↔ goal 绑定） | 常用插件（compiler/surefire/spring-boot） |
| 4.x 变化 | Maven 4 新特性页 | 构建管线、速度 |

## 3. Git Book 与 GitHub Docs

### 3.1 Git Book（官方免费书）

| 章节 | 内容 | 深度 |
|------|------|------|
| 1 起步 | 安装、首次配置、获取帮助 | 略读 |
| **2 Git 基础** | 快照概念、暂存区、diff/commit、撤销、远程 | 精读 |
| **3 Git 分支** | 分支原理、合并（fast-forward/三方）、rebase vs merge、冲突解决 | 精读（面试高频） |
| 4 服务器 | 协议、托管 | 略读 |
| **5 分布式** | 工作流（集中式/特性分支）、贡献模型 | 精读 |
| 6 GitHub | PR、fork、协作 | 精读 |
| **7 Git 工具** | 修订版本选择、stash、reset 三态、reflog、交互式暂存 | 精读（reflog/reset 必考） |

> 🎯 **核心要点**：Git 面试考的不是命令大全，而是**模型**——工作区/暂存区/仓库三态、分支是指针、merge/rebase 的本质区别、reflog 是"后悔药"。Git Book 第 2/3/7 章就是模型答案。

### 3.2 GitHub Docs

| 主题 | 场景 |
|------|------|
| Pull Requests | 提交流程、审查 |
| GitHub Actions | CI/CD 编写（workflow/trigger/job） |
| Codespaces / Issues / Projects | 协作效率 |

## 4. Docker Docs

### 4.1 精读章节清单

| 主题 | 章节 | 要点 |
|------|------|------|
| 镜像 | Dockerfile 最佳实践（Best practices） | 分层缓存、合并 RUN、多阶段构建、.dockerignore |
| 镜像原理 | 镜像分层（Layers）、存储驱动简介 | 分层复用、写时复制 |
| 容器 | 容器生命周期、资源限制（--memory/--cpus） | 运行参数 |
| 网络 | 网络模式（bridge/host/overlay）、端口映射、DNS | 容器互通 |
| 存储 | Volumes 与 bind mounts、持久化 | 数据卷 |
| 编排 | Compose（services/volumes/networks） | 多容器开发环境 |
| 生产 | 容器安全（非 root 用户、只读根文件系统）、日志驱动 | 生产化 |

> ⚠️ 网文常见错误：把"镜像体积最小化"当唯一目标（过度精简反而难排查）；混淆容器网络与宿主机网络。以官方 Best practices 与网络章节为准。

## 6. Linux：man 手册与排障

### 6.1 man 手册结构

| 分区 | 内容 | 常用示例 |
|:---:|------|---------|
| 1 | 用户命令 | `man ls`、`man grep` |
| 2 | 系统调用 | `man 2 open`、`man 2 epoll` |
| 3 | 库函数 | `man 3 printf` |
| 5 | 文件格式 | `man 5 crontab` |
| 7 | 杂项/约定 | `man 7 man`、`man 7 signal` |
| 8 | 系统管理命令 | `man 8 iptables` |

官方站点：https://man7.org/linux/man-pages/（内核维护的权威手册）；本地 `man` 命令优先（版本与发行版一致）。

### 6.2 排障精读清单

| 场景 | 命令/手册 | 面试触点 |
|------|----------|---------|
| 进程 | `ps`/`top`/`htop`、`/proc` 目录结构 | 进程模型、僵尸进程 |
| 内存 | `free`、`vmstat`、OOM killer | 内存泄漏定位 |
| 磁盘 | `df`/`du`/`iostat`、inode | 磁盘满排查 |
| 网络 | `ss`/`netstat`/`ping`/`traceroute`、`/proc/net` | 端口占用、连接状态 |
| Java 服务 | `jcmd`/`jstat`/`jstack`（见 [01](01-Java生态与JVM官方文档.md)） | 线程转储分析 |

## 7. 可观测性：Prometheus / Grafana

| 工具 | 精读点 | 场景 |
|------|--------|------|
| Prometheus | 数据模型（指标/标签）、PromQL 基础、采集（pull 模型）、Alertmanager | 监控体系基座 |
| Grafana | 数据源接入、面板/Dashboard、告警规则 | 可视化 |
| Micrometer（Java） | https://docs.micrometer.io/ | JVM/Spring 指标暴露到 Prometheus 的桥梁 |

> 🟢 工程必备但校招非重点：理解"指标采集 → 存储 → 查询 → 告警"闭环即可，细节入职后按需读。

## 8. 本方向避坑清单

| # | 坑 | 规避 |
|---|----|------|
| 1 | Maven 4 新教程混用 3.x 语法 | 先确认项目用的 Maven 版本，再选文档 |
| 2 | Git 只背命令不懂模型 | Git Book 第 2/3/7 章模型优先 |
| 3 | Docker 镜像无限精简 | 以官方 Best practices 平衡体积与可排查性 |
| 4 | K8s 文档全量啃 | 校招只啃概念层，其余按需 |
| 5 | 查 Linux 问题用碎片化博客 | 先 `man` 后上网，man 是权威 |
| 6 | 监控只装不查 | 建立"指标 → 告警 → 排查"闭环后再谈工具 |
