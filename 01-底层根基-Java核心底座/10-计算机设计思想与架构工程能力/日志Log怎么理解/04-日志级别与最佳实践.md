## 1. 级别使用规范

> **背景**：日志级别是「严重度分级」——用错级别 = 该看的看不到、不该看的刷屏。
> **目的**：建立统一的级别使用规范（团队约定）。
> **适用范围**：所有 Java 项目。
> **前提假设**：级别是「严重度」不是「喜好」——ERROR 必须是错误。

### 1.1 级别定义（2026 团队规范）

| 级别 | 定义 | 何时用 | 谁看 |
|:---:|------|--------|------|
| **ERROR** | 错误（功能不可用） | 异常/失败/数据错误 | 值班/开发 |
| **WARN** | 警告（潜在问题） | 降级/重试/可恢复 | 开发 |
| **INFO** | 关键业务节点 | 主流程/状态变化 | 业务/运维 |
| **DEBUG** | 调试细节 | 排查时开启 | 开发 |
| **TRACE** | 最细流程 | 深度排查 | 开发 |

### 1.2 级别判断三问

```text
级别判断（写日志前问自己）
├── ① 这个日志「不出现」说明出问题了吗？
│   ├── 是 → INFO（关键节点）
│   └── 否 → 继续问
├── ② 出现时系统「功能受影响」吗？
│   ├── 是 → ERROR（必须处理）
│   └── 否 → WARN（潜在问题）
├── ③ 细节对排查有用吗？
│   ├── 是 → DEBUG（生产关闭）
│   └── 否 → 不打（噪音！）
└── 金句：级别 = 「不出现是问题」→ INFO；「出现是问题」→ ERROR
```

## 2. 该打什么：关键节点清单

### 2.1 必打清单

```text
关键节点必打清单
├── ① 请求入口/出口：
│   ├── 收到请求（参数摘要）
│   └── 返回响应（结果/耗时）
├── ② 业务主流程节点：
│   ├── 订单创建/状态变更/支付成功
│   └── 每个状态转换打 INFO
├── ③ 外部调用（接口/数据库/MQ）：
│   ├── 调用开始（参数摘要）
│   ├── 调用成功（结果/耗时）
│   └── 调用失败（异常/重试信息）
├── ④ 事务边界：
│   ├── 事务开始/提交/回滚
│   └── 回滚必须 ERROR（数据一致性风险）
├── ⑤ 异步任务：
│   ├── 任务开始/结束/失败
│   └── 任务重试（次数/原因）
└── ⑥ 配置变更/开关切换：
    ├── 谁改了什么（审计）
    └── 新配置生效/回退
```

### 2.2 好的日志示例

```java
// ✅ 关键节点（含上下文 + 可操作）
log.info("订单创建成功: orderId={}, userId={}, amount={}",
         order.getId(), order.getUserId(), order.getAmount());

// ✅ 外部调用（含耗时 + 结果）
long start = System.currentTimeMillis();
try {
    PaymentResult result = paymentGateway.charge(order);
    log.info("支付调用成功: orderId={}, result={}, costMs={}",
             order.getId(), result.getCode(),
             System.currentTimeMillis() - start);
} catch (PaymentException e) {
    log.error("支付调用失败: orderId={}, error={}, costMs={}",
              order.getId(), e.getMessage(),
              System.currentTimeMillis() - start, e);
}

// ✅ 状态变更（可追踪）
log.info("订单状态变更: orderId={}, {} -> {}", order.getId(), "PAYING", "PAID");
```

## 3. 不该打什么：噪音清单

```text
日志噪音清单（禁止/限制）
├── ① 循环内高频日志：
│   ├── for 循环里打 DEBUG（海量）
│   └── 解法：统计后打一次 / 采样
├── ② 大对象全文：
│   ├── 打印整个对象（大 JSON/List）
│   └── 解法：摘要（id/数量）
├── ③ 无意义的 DEBUG：
│   ├── 打了没人看、排查用不上
│   └── 解法：DEBUG 只打「排查需要」的
├── ④ 重复日志：
│   ├── 同一错误多处打（框架 + 业务）
│   └── 解法：统一出口（全局异常处理器）
├── ⑤ 敏感信息：
│   ├── 密码/密钥/手机号/身份证
│   └── 解法：脱敏（见第 6 节）
├── ⑥ 过度 INFO：
│   ├── 每个方法进出一行（噪音）
│   └── 解法：只打「有业务意义」的节点
└── ⑦ 金句：日志量 = 存储成本 + 噪音成本——克制是美德
```

## 4. 异常日志最佳实践

### 4.1 异常日志的完整姿势

```java
// ❌ 错误 1：只打消息（丢堆栈）
log.error("订单处理失败: " + e.getMessage());

// ❌ 错误 2：吞异常（打日志不抛——静默失败）
try {
    paymentGateway.charge(order);
} catch (Exception e) {
    log.error("支付失败");
    // 什么都不做！订单还是 PAYING，用户被扣钱了
}

// ✅ 正确：异常对象完整传入（含堆栈）
try {
    paymentGateway.charge(order);
} catch (PaymentException e) {
    // 上下文 + 异常对象（堆栈自动带上）
    log.error("支付失败: orderId={}, code={}, msg={}",
              order.getId(), e.getCode(), e.getMessage(), e);
    // 决策：抛出去 or 降级（不能静默）
    throw new OrderProcessingException("订单支付失败", e);
}
```

### 4.2 异常日志要点

```text
异常日志五要点
├── ① 必须传异常对象：log.error("消息", e)（堆栈自动）
├── ② 上下文前置：orderId/userId（先于异常）
├── ③ 不吞异常：catch 后至少要「记录 + 决策」
├── ④ 错误码：业务异常带 code（机器可处理）
├── ⑤ 统一出口：全局异常处理器（@RestControllerAdvice）
│   ├── 避免每处手打（重复/不一致）
│   └── 错误日志一次打全（上下文 + 堆栈）
└── ⑥ 金句：异常日志 = 上下文 + 堆栈 + 决策（不静默）
```

## 5. 上下文与字段

### 5.1 必备字段（日志格式设计）

```text
日志必备字段（统一规范）
├── ① 时间：yyyy-MM-dd HH:mm:ss.SSS（精确毫秒）
├── ② 级别：%-5level
├── ③ 线程：%thread（定位并发问题）
├── ④ logger：%logger{36}（定位代码位置）
├── ⑤ traceId：%X{traceId:-}（链路串联——见 05 篇）
├── ⑥ 业务标识：orderId/userId（MDC 或消息中）
└── ⑦ 消息：%msg%n

Pattern（2026 推荐）
%d{yyyy-MM-dd HH:mm:ss.SSS} %-5level [%thread] %logger{36}
[%X{traceId:-}] [%X{userId:-}] - %msg%n
```

### 5.2 业务字段注入（MDC）

```java
// 请求入口注入（Filter）
@Component
public class TraceFilter implements Filter {
    @Override
    public void doFilter(ServletRequest req, ServletResponse res,
                         FilterChain chain) throws IOException, ServletException {
        try {
            MDC.put("traceId", generateTraceId());
            MDC.put("userId", extractUserId(req));
            chain.doFilter(req, res);
        } finally {
            MDC.clear();   // ⚠️ 必须清理（线程复用污染！）
        }
    }
}
```

## 6. 脱敏清单

### 6.1 敏感字段清单

```text
必须脱敏的字段
├── ① 密码/密钥：password/token/secret/API Key
├── ② 身份信息：身份证号/手机号/邮箱
├── ③ 财务：银行卡号/支付账号
├── ④ 地址：详细地址/坐标
├── ⑤ Cookie/Session：会话标识
└── ⑥ 授权头：Authorization

脱敏方式
├── ① 打码：138****5678（保留前 3 后 4）
├── ② 替换：password=***（敏感字段不打印值）
├── ③ 过滤：日志 Filter 统一脱敏
└── ④ ⚠️ toString 陷阱：对象 toString 可能带敏感字段
```

### 6.2 脱敏实现

```java
// 统一脱敏工具（日志使用）
public class LogMask {
    private static final Pattern PASSWORD =
        Pattern.compile("(password|pwd|token)\\s*[=:]\\s*[^\\s,;]+");

    public static String mask(String log) {
        return PASSWORD.matcher(log).replaceAll("$1=***");
    }
}
// ⚠️ 最佳实践：
// ① 打日志前脱敏（对象摘要）
// ② 禁止打印：请求对象全文（含密码）
// ③ 框架层：logback Pattern 或 Filter 统一处理
```

## 7. 日志评审清单

```text
日志 Code Review 检查清单
[ ] 级别正确？（ERROR 是真错误？INFO 是关键节点？）
[ ] 有上下文？（orderId/traceId/关键参数）
[ ] 异常传堆栈？（log.error(msg, e)——不是只 getMessage）
[ ] 无吞异常？（catch 后有决策？）
[ ] 无敏感信息？（密码/身份证/密钥）
[ ] 无噪音？（循环内/大对象/重复）
[ ] 关键节点全覆盖？（入口/外部调用/状态变更）
[ ] 可操作？（看日志知道下一步做什么）
[ ] MDC 清理？（finally 中 clear）
[ ] 性能？（占位符？异步？）
→ 金句：日志评审 = 日志质量的第一道门（防「上线后没日志」）
```

## 8. 核心要点

> 🎯 **核心要点**：
> 1. 级别判断：不出现是问题 → INFO；出现是问题 → ERROR；潜在 → WARN
> 2. 必打节点：入口出口/主流程/外部调用/事务边界/异步任务/配置变更
> 3. 噪音禁令：循环高频/大对象/无意义 DEBUG/重复/过度 INFO
> 4. 异常日志：上下文 + 堆栈 + 决策——**绝不吞异常**
> 5. 字段规范：时间/级别/线程/logger/traceId/业务标识
> 6. 脱敏：密码/身份证/银行卡——toString 陷阱注意
> 7. 评审清单十项：日志质量第一道门
