## 4. 核心概念速查

| 概念 | 一句话定义 | 关键要点 |
|------|-----------|---------|
| 同步/异步 | 调用方是否等待结果 | 异步 = 发起后不等待，结果回调/轮询/挂起 |
| 阻塞/非阻塞 | 调用是否让出 CPU | 与同步异步正交，组合出四种形态 |
| 多路复用 | 单线程监听大量 fd | select→poll→epoll 三代演进 |
| Reactor | 就绪通知模型（读/写可用了再处理） | epoll、Netty、Redis 的模型 |
| Proactor | 完成通知模型（内核做完再通知） | io_uring 的模型 |
| io_uring | 共享队列提交/完成 IO（Linux 5.1+） | 2026 高性能异步 IO 新标准 |
| 事件循环 | 单线程轮转任务队列 | JS/Python/Netty 的共同骨架 |
| 回调地狱 | 嵌套回调导致的不可读代码 | 无顺序、难取消、错误碎片化 |
| Future/Promise | 未来值的容器 | CompletableFuture、JS Promise |
| 函数着色 | 同步/异步函数不可互调 | 虚拟线程/goroutine 的解法 |
| futurelock | 异步代码中的死锁新形态 | 等待链成环、栈丢失难排查 |
| 协程 | 语言级可挂起计算（状态机） | async/await 的编译产物 |
| 虚拟线程 | JVM 管理的轻量线程 | 透明：同步代码获得异步容量 |
| 背压 | 消费者反推速率限制生产 | request(n) 协议 |

## 6. 版本演进时间线

| 时间 | 异步编程里程碑 | 说明 |
|:---:|---------------|------|
| 2001 | epoll 进入 Linux 2.5.44 | C10K 问题的工程答案 |
| 2009 | Node.js 发布、Go 发布 | 事件循环与 goroutine 两大流派 |
| 2011 | C++11 async、Java 7 NIO2 | Future 模型起步 |
| 2014 | Java 8 CompletableFuture | 组合子补齐 |
| 2015 | ES6 Promise、Python 3.5 async/await | 两语言协程语法定稿 |
| 2019 | io_uring 进入 Linux 5.1 | Proactor 模型回归 |
| 2021 | Kotlin coroutines 1.6 结构化并发稳定 | 语言级协程标杆 |
| 2023 | JDK 21 虚拟线程定稿（JEP 444） | "隐形协程"落地 |
| 2025 | io_uring multishot 成熟、"杀事件循环"论战 | .NET 接入（15-40% CPU 下降） |
| 2026 | 结构化并发 JEP 525 第 6 预览；C++26 Sender 模型；Ktor 50K 连接基准 | 协程/虚拟线程成为主流共识 |

> ⚠️ **版本窗口**：本体系以 2026-08 检索为准——JDK 26 / Python 3.14 / Go 1.2x / Node 2x 时代基线；io_uring 特性需 Linux 5.19+（multishot）/ 6.0+（零拷贝）内核。
