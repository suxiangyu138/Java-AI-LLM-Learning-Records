## 1. 内置组件

内置组件是页面的「积木」（小程序无 HTML 标签——03 篇）：**布局**——`view`（div——块级容器）、`scroll-view`（滚动容器——列表滚动）；**内容**——`text`（文本——span）、`image`（图片——**mode 属性控制裁剪模式**）、`rich-text`（富文本——HTML 渲染的替代）；**交互**——`button`（按钮——open-type 支持开放能力：分享/获取手机号）、`input`（输入框）、`textarea`、`picker`（选择器——日期/地区）、`swiper`（轮播）、`form`（表单容器）。

**内置组件的要点**：**image 的 mode**（aspectFill 裁剪/widthFix 自适应——图片显示的第一个坑）；**button 的 open-type**（分享、授权等平台能力——[[../小程序UniAPP开发/00-小程序UniAPP开发总览|平台能力]] 的入口）；**scroll-view vs 页面滚动**（局部滚动用 scroll-view）；**「先想内置组件，再想自定义」**——内置组件覆盖 80% 需求。

## 2. 自定义组件

**自定义组件——「复用与封装的单元」**（[[../../10-前端知识拓展/Vue/02-Vue组件化开发|Vue 组件化]] 的小程序版）：

```vue
<!-- components/order-card/order-card.vue —— 订单卡片组件 -->
<script setup>
const props = defineProps({ order: { type: Object, required: true } })
const emit = defineEmits(['click'])
</script>
<template>
  <view class="card" @click="emit('click', props.order)">
    <text>{{ props.order.title }}</text>
    <text class="price">¥{{ props.order.amount }}</text>
  </view>
</template>
```

**使用姿势**：**easycom 机制**——`components/组件名/组件名.vue` 目录规范 → 页面直接使用**免注册**（`<order-card :order="item" />`）——「easycom 是 uni-app 的组件自动注册」；**props/emits**——数据与事件（单向数据流）；**组件化的价值**——**「列表项、卡片、表单控件等高频 UI 抽组件」**——「一个页面不超 300 行」是组件化的健康信号。

## 3. rpx 与样式

**rpx（responsive pixel）——uni-app 的响应式单位**：**750rpx = 屏幕宽度**——「设计稿 750px 宽 → 直接写 rpx 数」——不同屏幕自动缩放（iPhone 与安卓同比例）——**「rpx 是跨端样式的核心单位」**（px 是固定像素——跨屏不一致）。**样式写法**——`<style scoped>`（页面/组件样式隔离——03 篇）、uni.scss（全局变量——颜色/尺寸）、`<style lang="scss">`（SCSS 预编译——2026 技术栈标配）。

**样式注意**：**flex 布局是主力**（小程序布局基本 flex——`display: flex`）；**`box-sizing: border-box` 默认**；**图片尺寸**（image 组件默认 320×240——要设宽高）；**状态样式**（`:hover-class`——按钮按压态）。

## 4. UI 组件库

**UI 组件库——「别重复造轮子」**（覆盖 90% 的常见 UI）：**官方 uni-ui**——uni-app 官方组件库（基础组件增强）；**uView Plus**——Vue3 生态的流行 UI 库（表单/导航/反馈组件全）；**uview-ultra v4**——2026 新版本（兼容 uni-app x 与鸿蒙——01 篇）。**安装**——uni_modules 插件市场（HBuilderX 插件市场安装/`npm` 安装）——**「按需引入」**（组件库的体积控制——分包限制考量——08 篇）。

**组件库的选型**：**官方 uni-ui**（基础需求、包小）；**uView Plus**（功能全、社区大——国内主流）；**uview-ultra**（要兼容 uni-app x 的新项目）——**「组件库是工程决策不是炫技」**（引入组件库 = 引入依赖——体积与维护成本权衡——[[../横向通用能力/02-架构权衡与决策|权衡决策]] 的前端版）。

## 5. 列表与表单

**列表页与表单页是业务页面的两大形态**：**列表页**——请求列表数据 → `v-for` 渲染（**`:key` 必写**——04 篇）→ **下拉刷新**（`enablePullDownRefresh` + `onPullDownRefresh`——页面配置开启）→ **上拉加载更多**（`onReachBottom`——分页加载——「列表分页是常态——[[../项目从开始开发到上线全流程/00-项目全流程知识体系总览|项目实践]] 的分页对接」）→ **空态/加载态**（loading 骨架/空数据提示——「列表三态：加载中/有数据/空」）；**表单页**——表单组件（input/picker/switch）→ `v-model` 双向绑定 → **提交校验**（前端基础校验 + 后端校验兜底——[[../../09-Web开发全流程/RESTful%20API/00-RESTful%20API总览|RESTful 校验语义]]）→ 提交（请求封装——05 篇）。

**样式与设计规范**（页面「好看且一致」的工程姿势）：**设计稿到 rpx**——设计稿 750px 宽 → rpx 数值直接抄（1px 设计 = 1rpx）——「rpx 是设计与开发的换算桥梁」；**全局样式变量**——uni.scss 定义颜色/字号/间距变量（`$primary-color`、`$font-size-base`）——**「颜色/字号不散落硬编码」**（改主题只改变量——与后端「常量集中」同构）；**组件库的样式定制**——组件库支持主题定制（uView 的主题变量覆盖——`uni.scss` 覆盖默认值）；**页面样式规范**——页面背景色统一、圆角/阴影统一（设计规范落成 SCSS 变量与公共类）——**「样式的工程化：变量集中 + 公共类 + 组件复用」**——「每个页面自己调样式」是样式混乱的开始。

## 6. 常见坑

**坑一：image 不设宽高**。默认 320×240——图片变形/空白——宽高 + mode。

**坑二：列表无 key**。渲染告警/复用错乱——:key。

**坑三：下拉刷新没开配置**。onPullDownRefresh 不触发——页面配置 enablePullDownRefresh。

**坑四：分页无限加载**。到底了还请求——has_more 判断（[[../../09-Web开发全流程/RESTful%20API/00-RESTful%20API总览|分页契约]]）。

**坑五：组件不注册**。自定义组件用了没生效——easycom 目录规范。

**坑六：样式写死 px**。跨屏不一致——rpx。

**坑七：重复造轮子**。列表空态/表单校验手写——组件库。

**坑八：组件通信只靠 props 深传**。多层组件 prop 透传（爷孙通信）——provide/inject（跨层注入——Vue3 标准）或 store——「props 一层、跨层 provide/store」。

**坑九：表单校验前端只做展示**。前端校验通过但后端 422——前端校验是体验、后端校验是安全——「校验双层：前端体验 + 后端兜底」（[[../../09-Web开发全流程/RESTful%20API/00-RESTful%20API总览|RESTful 校验语义]]）。

**坑十：组件库版本不锁**。组件库升级破坏页面——锁版本（依赖管理纪律——[[../横向通用能力/02-架构权衡与决策|权衡决策]] 的前端依赖版）。

**坑十一：组件样式隔离失效**。组件样式穿透（`::v-deep` 滥用）污染全局——样式隔离纪律（scoped 为主、穿透限制场景）。

**坑十二：列表项组件过度拆分**。每个 view 都拆组件——渲染开销反增——「组件粒度与渲染性能的权衡」（08 篇虚拟列表的组件考量）。

**坑十三：事件名不统一**。组件 emit 的事件命名随意（click/onClick/clicked）——事件命名规范（kebab-case 或统一风格——「组件契约的一部分」）。

**坑十四：样式类名冲突**。全局类与页面类同名——类名前缀规范（组件类名加组件名前缀——「样式隔离的命名纪律」）。
