## 1. 环境三件套

开发环境三件套：**HBuilderX**（DCloud 官方 IDE——5.x——创建项目、代码编辑、运行、云打包一站式——**入门首选**）；**微信开发者工具**（微信官方——预览/调试/上传小程序——**必须安装**——UniAPP 编译产物由它运行）；**Node.js**（CLI 工程与依赖管理需要——LTS 版）。**选 HBuilderX 还是 CLI**（第 5 节）：入门与快速迭代 HBuilderX；团队工程化（git/CI/自定义构建）CLI。

**微信开发者工具的配置**：安装后「设置 → 安全」开启服务端口（HBuilderX 通过端口把编译产物推给它）；**工具里登录微信账号**（无账号无法预览——小程序开发要用微信扫码登录）；**AppID**——测试用「测试号」（无需注册——正式项目要注册小程序获取 AppID——09 篇）。

## 2. 创建项目

HBuilderX 创建项目：**文件 → 新建 → 项目**——选择「uni-app」模板——**模板选择**：**默认模板**（Vue3 + Vite——2026 新项目选这个）；**uni-ui 模板**（带官方 UI 库）；**hello uni-app**（示例项目——学习用）。CLI 创建：

```bash
npx degit dcloudio/uni-preset-vue#vite my-app   # Vue3 + Vite 模板
cd my-app && npm install
```

**项目的目录结构**（创建后先认识骨架——03 篇详解）：`pages/`（页面）、`static/`（静态资源）、`uni_modules/`（插件）、`App.vue`（应用入口）、`main.js`（入口）、`pages.json`（路由配置）、`manifest.json`（应用配置）——**「pages.json 与 manifest.json 是 uni-app 的两大配置文件」**（03 篇）。

## 3. 运行到微信开发者工具

**运行链路**：HBuilderX「运行 → 运行到小程序模拟器 → 微信开发者工具」——**链路过程**：UniAPP 编译（Vue → 小程序代码）→ 推送到微信开发者工具 → 工具打开模拟器预览——**「编译发生在 HBuilderX，运行发生在微信工具」**。

**首次运行的配置**：**微信工具的服务端口要开**（第 1 节——HBuilderX 推送失败先查这里——「端口未开是最常见首次运行坑」）；**AppID**——首次运行选「测试号」（无 AppID 也能预览）；**编译产物目录**——`dist/dev/mp-weixin`（CLI 工程）/ HBuilderX 自动管理——**「产物目录是调试的入口」**（报错定位先看编译输出）。

**调试姿势**：微信工具的**调试器**（Console 看日志、Network 看请求、Sources 断点）、**真机预览**（工具「预览」生成二维码——手机扫码真机运行——**「真机预览是验证环境差异的必备动作」**（模拟器与真机有差异——08 篇）。

## 4. 第一个页面

模板自带的 index 页面已经能跑——**第一个「自己的页面」**三步：

**第一步，写页面**（`pages/index/index.vue`——组合式 API 风格）：

```vue
<script setup>
import { ref } from 'vue'
const message = ref('你好，小程序')
</script>

<template>
  <view class="container">
    <text class="title">{{ message }}</text>
    <button @click="message = '点击了按钮'">点我</button>
  </view>
</template>

<style scoped>
.container { padding: 40rpx; }
.title { font-size: 40rpx; color: #333; }
</style>
```

**第二步，注册路由**（`pages.json`——页面必须注册才能访问）：

```json
{ "pages": [
  { "path": "pages/index/index", "style": { "navigationBarTitleText": "首页" } }
] }
```

**第三步，运行**——HBuilderX 运行到微信工具——看到页面与按钮交互——**「页面 = template + script + style + 路由注册」四件套**（03 篇展开）。

## 5. 工程形态：HBuilderX vs CLI

两种工程形态的选型：**HBuilderX 工程**——可视化创建/运行/云打包，**入门最快**（无需 Node 环境）；局限——工程化定制弱（CI 集成、自定义构建要绕）。**CLI 工程（Vite）**——标准 npm 工程（git/依赖管理/CI 全支持）、**团队协作与持续集成的正确选择**——局限——运行/打包命令化（`npm run dev:mp-weixin`）、云打包走命令行（HBuilderX 的云打包 API）。**选型**：个人学习与快速原型 → HBuilderX；**团队项目与 CI → CLI**——**「CLI 是工程化方向」**（与前端主流工程形态一致——[[../../10-前端知识拓展/Node.JS|Node 体系]] 的工程化思维）。

**开发调试的效率姿势**（后端开发者的调试习惯迁移）：**Network 面板是联调主战场**——微信工具的 Network 看请求（URL/参数/响应——「请求发了没、后端回了什么」一目了然——与浏览器 F12 同款思维）；**Console 与 Source**——console.log 排查逻辑、Sources 断点调试（后端调试器思维的前端版）；**真机调试**——微信工具的「真机调试」模式（手机跑 + 电脑看日志——**「模拟器与真机的差异问题用真机调试定位」**）；**Mock 与本地联调**——后端没写好时前端先 Mock（数据模拟——「前后端并行开发的配合」——[[../项目从开始开发到上线全流程/00-项目全流程知识体系总览|项目流程]] 的联调节奏）——**「调试工具链：Network/Console/Source/真机」四件套**。

## 6. 常见坑

**坑一：微信工具端口未开**。HBuilderX 推送失败——设置 → 安全 → 服务端口开启。

**坑二：AppID 用错**。正式项目用测试号 → 上线不了——正式 AppID 要注册申请（09 篇）。

**坑三：页面没注册路由**。页面文件写了但 pages.json 没有——访问 404/空白——路由注册是必做。

**坑四：运行到 App 报错**。App 端要云打包/真机基座——入门先跑小程序端。

**坑五：Node 版本过旧**。CLI 工程依赖安装失败——Node LTS。

**坑六：Vue2 模板**。默认模板选成 Vue2——新项目用 Vue3 + Vite 模板。

**坑七：编译产物混淆**。改代码没生效——先确认编译成功（HBuilderX 控制台/CLI 输出）。

**坑八：git 忽略产物与依赖**。`dist/`、`node_modules/` 进 git——工程混乱——`.gitignore` 配置（dist/unpackage/node_modules——「CLI 工程的 git 纪律」）。

**坑九：多人协作格式混乱**。代码风格不统一——ESLint + Prettier 配置（CLI 工程标配——「工程化从格式统一开始」）。

**坑十：环境变量不分离**。baseURL 写死——dev/test/prod 环境切换改代码——`import.meta.env.VITE_API_BASE` 环境变量（05 篇封装配合）。

**坑十一：依赖锁版本缺失**。CLI 工程依赖漂移（构建环境不一致）——`package-lock.json` 提交 git（依赖可复现——「CI 构建与本地一致的保证」）。

**坑十二：HBuilderX 项目与 CLI 项目混用**。两种工程形态的配置不通用——团队统一一种（02 篇选型——团队用 CLI 就全员 CLI）。

**坑十三：首次运行报「appid 缺失」**。manifest 未填或测试号未选——创建项目时选测试号或填正式 AppID——「首次运行三查：端口/AppID/编译产物」。

**坑十四：HBuilderX 版本过旧**。新特性/新平台支持缺失——升级 HBuilderX（5.x 线——01 篇基线）——「工具链版本随框架迭代」。

**坑十五：命令行运行不熟**。CLI 工程不会跑 dev 命令——`npm run dev:mp-weixin`（构建到 dist/dev/mp-weixin 后用微信工具打开该目录——「CLI 工程的运行姿势」）。
