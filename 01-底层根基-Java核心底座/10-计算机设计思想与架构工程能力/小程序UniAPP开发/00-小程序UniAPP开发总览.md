## 3. 学习路线推荐

**路线一：快速上手（1-2 天）**——01 → 02 → 03 → 10。目标：跑通「创建项目 → 运行到微信开发者工具 → 第一个页面」。

**路线二：核心开发（3-5 天）**——路线一 + 04 → 07。目标：页面开发、网络请求、状态管理，能独立开发完整小程序功能。

**路线三：生产交付（一周）**——路线二 + 08 → 09。目标：多端适配、性能优化、发布上线，交付可上架的小程序。

**先厘清定位**：本体系是「后端开发者的前端知识拓展」——小程序是后端的常见消费端（[[../../09-Web开发全流程/RESTful%20API/00-RESTful%20API总览|RESTful API]] 与 [[../../10-前端知识拓展/Token/00-Token总览|Token 鉴权]] 的小程序侧落地）；Vue 基础见 [[../../10-前端知识拓展/Vue/00-Vue总览与核心概念|Vue 体系]]；上线流程见 [[../项目从开始开发到上线全流程/00-项目全流程知识体系总览|项目全流程体系]]。

## 4. 核心概念速查

| 概念 | 一句话 |
|------|-------|
| uni-app | 跨端框架：一套 Vue 代码编译到 10+ 小程序平台 + H5 + App |
| uni-app x | 下一代引擎：uts 语言 + uvue 原生渲染（蒸汽模式） |
| uts | 跨平台强类型语言（JS/Web→Kotlin/Swift/ArkTS） |
| 蒸汽模式 Vapor | 2026 起的新渲染模式（免 vnode 创建，快 2-3 倍） |
| HBuilderX | 官方 IDE（5.x），创建/运行/云打包一站式 |
| pages.json | 页面路由与窗口配置（小程序的「路由表」） |
| manifest.json | 应用配置（AppID/平台配置） |
| 双线程模型 | 小程序逻辑层（JSCore）+ 视图层（WebView） |
| setData | 逻辑层→视图层的数据传递（大数据量卡顿根源） |
| rpx | 响应式像素单位（750rpx = 屏幕宽度） |
| uni.request | 网络请求 API（axios 的小程序版） |
| 条件编译 | `#ifdef` 按平台编译差异代码 |
| Pinia | Vue3 状态管理（替代 Vuex） |
| 分包加载 | 主包 2MB 限制的拆分方案 |
| 云打包 | HBuilderX 云服务打包 App（免本地环境） |

## 5. 常见误区

**误区一：小程序 = 网页**。小程序是双线程模型（逻辑层 + 视图层）——DOM 操作不存在、setData 有性能代价——「网页思维写小程序会踩性能坑」（08 篇）。

**误区二：还在用 Vue2 写新项目**。Vue2 2026 进入淘汰期（下半年停新功能、微信收紧老基座审核）——新项目一律 Vue3 + Vite。

**误区三：一套代码到处跑不用适配**。跨端是「一次编写、按平台适配」——条件编译处理平台差异是常态（08 篇）——「零适配」是宣传不是现实。

**误区四：小程序不用做安全**。小程序同样要 Token 鉴权、防越权、HTTPS——「小程序安全 = Web 安全的小程序版」（05 篇）。

**误区五：网络请求直接裸调 uni.request**。不封装、不做拦截器——统一封装（baseURL/Token/错误处理）是工程底线（05 篇）。

**误区六：2MB 主包无限制**。主包 2MB 限制是硬约束——分包加载是必做设计（08 篇）。

**误区七：App 和小程序一样开发**。App 打包（云打包/原生插件）、上架（应用市场）与小程序差异大（09 篇）。

**误区八：小程序性能问题怪框架**。卡顿多半是 setData 量与频、列表全量渲染、图片未优化——先按 08 篇五问排查再谈框架。

**误区九：审核一次过**。类目/隐私/内容问题被拒是常态——预留审核时间、按原因迭代。

**误区十：只测模拟器**。模拟器与真机差异（字体/滚动/API）——真机预览是上线前必做。

九个误区的共同根源只有一个：**把小程序当成「网页换个壳」**。小程序是双线程模型 + 平台托管的独立生态——setData 通信、2MB 主包、平台审核都是硬约束——带着「网页思维」写小程序，性能坑、平台坑、上线坑一个都躲不掉；换成「平台内开发」的心智——先懂运行模型、再写页面、最后过平台流程——整套体系才立得住。

## 6. 一周计划

| 天 | 内容 | 产出 |
|:---:|------|------|
| Day1 | 01 + 02：定位与环境 | 项目跑通到微信开发者工具 |
| Day2 | 03：结构与生命周期 | 页面 + 路由配置 |
| Day3 | 04 + 05：语法与网络 | 请求封装 + 登录对接 |
| Day4 | 06 + 07：状态与 UI | Pinia + 页面开发 |

**学习姿态的约定**：小程序的每个机制都要「跑通 + 看效果」——页面跑起来看渲染、请求封装后 Network 看请求、登录流程走一遍看 Token 流转、性能优化后对比体验、发布流程走一遍体验版——本体系是「后端开发者的前端拓展」，代码以 JavaScript/Vue3 为主，后端配合（登录/API/Token）对照 [[../../10-前端知识拓展/Token/00-Token总览|Token 体系]] 与 [[../../09-Web开发全流程/RESTful%20API/00-RESTful%20API总览|RESTful API 体系]]——「前端怎么调、后端怎么给」两套体系对照读。
