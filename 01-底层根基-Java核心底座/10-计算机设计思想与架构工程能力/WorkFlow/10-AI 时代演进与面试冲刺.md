# 10-AI 时代演进与面试冲刺：Agentic Workflow 与 20 自测

> 定位：工作流的下一站是 Agentic Workflow——确定性引擎与自主 Agent 的融合。本篇讲清融合机制、平台实践与"工作流 vs Agent"辨析，并以 20 道自测题 + 面试题 + 速记收尾整个体系。

## 1. 融合范式：智能体决定怎么做，工作流决定何时何地在何约束下做

2026 年行业共识：**Agent 没有淘汰工作流引擎，反而需要它**。纯 Agent 方案在合规性、审计追踪、幻觉纠错、兜底机制四方面有系统性短板；工作流引擎以确定性、可审计性成为智能体的基座。

四个融合机制：

- **Agent 作为 BPMN 服务任务**：LLM 调用被建模为 service task，外部 Worker 长轮询执行——引擎"不关心也不理解"任务背后是否有模型，它只知道"这是接收上下文、产出变量、可能失败的步骤"。这种"无知"恰恰保证编排确定性，任务内部允许非确定。
- **任务租约 + 心跳**：引擎以租约（lease）机制让 Worker 独占任务，配合心跳防止 90 秒级模型思考/工具调用被其他 Worker 抢占。
- **错误处理一等公民**：模型返回垃圾成为可建模事件——Worker 抛 BPMN 错误码，匹配边界错误事件，实现"LLM 失败三次走建模好的恢复路径"；技术故障（Worker 崩溃）与业务错误（Agent 完不成）分开处理。
- **人工审批一等公民**：人在发布前审核是 Agent 最普遍的产线需求，建模为用户任务（user task），支持认领、指派、审批、编辑、拒绝。

**落地场景案例（智能客服工单）**：工单流程建模为 BPMN——用户任务（受理）→ 服务任务（Agent 分析工单、生成回复草案，LLM 调用封装在 Worker 内）→ 用户任务（人工审核发布，Agent 输出不直接触达用户）→ 服务任务（归档与反馈收集）。Agent 输出不合规时 Worker 抛 BPMN 错误码，边界事件捕获后走"二次改写 → 再审核"的建模恢复路径。这套结构里，引擎贡献确定性（流程一定按序走完）、审计（每一步 Agent 输出都留痕）、兜底（失败三次有人工介入），Agent 贡献灵活性（草案内容不可预测也没关系，被约束在审核环节内）。

## 2. 平台实践：ProcessOS 与治理三原则

Camunda 8.9 的 **ProcessOS**（智能体操作系统）是代表性实践：识别现有流程、按业务目标重新设计并生成完整流程工件（BPMN 模型、数据映射、Agent 提示词、决策规则、UI 表单），底层集成 MCP 服务器、Agent 间连接器与 ad-hoc 子流程。治理三原则：

- 可视化 BPMN 模型展示"AI 独立行动"与"人工参与"的位置。
- 所有流程变更需人工审核。
- 优先复用经过验证的模式与连接器。

工具链常见组合（2026 企业落地）：**n8n**（跨系统自动化）+ **Dify**（知识与上下文管理）+ **RAG**（降低业务幻觉）+ BPMN 引擎（流程编排）——当模型能力趋同，差距在系统调度与工程治理能力。

## 3. 工作流 vs Agent 辨析（面试必考）

| 维度 | 确定性工作流 | AI Agent |
|---|---|---|
| 执行逻辑 | 预定义节点与路由 | 模型自主规划 |
| 可预测性 | 强（图即结果） | 弱（每次可能不同） |
| 审计合规 | 天然留痕 | 需额外工程兜底 |
| 兜底机制 | 边界事件/重试/人工 | 幻觉滚雪球，难兜底 |
| 适用 | 稳定流程、强监管 | 开放任务、非结构化输入 |
| 2026 关系 | 基座（何时何地做） | 执行者（怎么做） |

演进路线（Forrester 五阶段，CamundaCon 2026 展示）：基础脚本 → 自动化工作流 → 自适应流程 → 智能体编排 → 完全自主组织。**当前行业主流停在第三、四阶段之间**——"自适应流程自动化"正加速落地。

## 5. 自测通过线

- **通过标准**：20 题中对 16 题可进入面试冲刺；错题集中在 11-19 题（中国式审批与 Camunda 8）属正常现象，回到 05/07 篇重读对应章节后重测。
- **错题归因表**：1-5 题错 → 补 01/02 篇；6-10 题错 → 补 03 篇；11-16 题错 → 补 05/06 篇；17-19 题错 → 补 07/09 篇；20 题错 → 补 10 篇第 1-3 节。
- **面试前 10 分钟**：只背 7 速记卡十条 + 8 道答题范式的四段式骨架，其余靠体系理解现场组织。
- **面试高频追问准备**：面试官从"会签怎么实现"往下追的三连问——"会签人员怎么确定"（流程服务层解析注入）→"加签后完成条件怎么变"（多实例计数动态变化）→"会签中有人驳回怎么办"（或签直接终止、会签走否决策略），这三问答顺了，中国式审批就过关了。

## 6. 面试题与答题范式（8 题）

- **请介绍你做过的工作流项目**：答题范式 = 业务场景（审批流/编排）+ 选型理由（为什么引擎/为什么这个引擎）+ 架构（三层：引擎/流程服务/应用）+ 难点（退回/会签/性能）+ 量化结果。
- **Flowable 和 Camunda 8 的区别**：嵌入式 vs 分布式 → 事务一致性 vs 弹性 → 中国式审批能力 → 许可成本，四段式。
- **会签怎么实现**：多实例 + 完成条件 + 平台层策略（一票否决/比例），顺带讲加减签底层。
- **任意节点驳回的难点**：可退回节点可达性计算 + 并行分支收敛 + 业务回滚同事务 + 意见留痕。
- **流程卡死如何排查**：令牌在哪（ACT_RU_EXECUTION）→ 在等谁（人/消息/定时器/Job 失败）→ 对症处理。
- **状态机 vs 工作流**：单对象生命周期 vs 多参与者协作；临界点 = 是否需要任意回退/会签/审计可视化。
- **工作流会死吗**：不会——确定性 + 审计 + 兜底是 Agent 落地的基座；引用"Agent 决定怎么做、工作流决定何时何地做"。
- **生产运维注意什么**：历史归档、异步执行器、死信 Job、事务边界、升级兼容（Jackson/Boot）五条。

## 7. 速记卡（背诵版）

1. 工作流本质 = 过程变数据、执行交引擎；流程定义≈类、实例≈对象。
2. BPMN 2.0 = 图与 XML 双向映射，ISO 19510；网关必须条件完备。
3. 三剑客同源（jBPM4→Activiti 2010），Camunda 2013 分叉、Flowable 2016 分叉，十年后互不兼容。
4. 嵌入式 = 共享事务强一致；分布式 = 分区日志高弹性。中国式审批选 Flowable。
5. 会签 = 多实例；加签 = 多实例动态增删；退回 = ChangeActivityStateBuilder + 可达性计算；撤回三态独立成路。
6. 状态机管对象状态，引擎管过程协作；临界点 = 任意回退需求。
7. Camunda 8 = Zeebe 分区 + 外部 Worker + 生产许可；7 CE 2025-10 EOL，延续用 Operaton。
8. 运维四件事：归档历史、开异步执行器、盯死信 Job、升级先做兼容回归。
9. 选型四步：分类 → 同类对比 → 算 TCO → PoC。
10. Agentic Workflow：Agent 决定怎么做，工作流决定何时何地在何约束下做——引擎是基座，不是累赘。

> 🎯 收尾要点：把工作流讲出体系感的三板斧——模式视角（为什么退回难）、架构视角（嵌入式 vs 分布式）、成本视角（许可与二次开发量）。答出这三点，面试官会认为你不是用过，而是懂。
