# 00-工作流知识体系总览：从 BPMN 建模到引擎实战再到 AI 融合

> 定位：面向后端工程师的工作流（WorkFlow）完整知识体系——工作流不是"引个 Flowable 就能跑"的工具，而是建模（BPMN 2.0）、引擎内核、中国式审批语义、分布式编排、生产运维、选型决策六层能力的系统工程。本体系讲透机制与取舍，配可复现代码，与同级《状态机思想》《软件工程上的设计思想》分工互补。

**版本窗口：2026-08 基准**（Flowable 8.0.0、Camunda 8.9.13、Activiti 9.0、Camunda 7 CE 已于 2025-10 EOL、BPMN 2.0 = ISO 19510）

## 3. 学习路线推荐

**路线 A（实战落地，3 天）**：01 → 02 → 03 → 04 → 05 → 08。以 Flowable 为主线快速上手中国式审批项目，适合急用 OA/审批场景的开发者。产出物：能独立完成一个"提交 → 审批 → 会签 → 退回"的完整流程开发，并给出历史清理与异步执行器两份配置清单。

**路线 B（架构纵深，4 天）**：A 全量 + 06 状态机选型 + 07 Camunda 8 分布式编排 + 09 选型决策。适合做微服务编排、平台选型的架构师，其中 06 与同级《软件工程上的设计思想》的"状态机思想"篇联动阅读。产出物：能输出一份含四类产品对比、TCO 测算与 PoC 验收标准的选型报告。

**路线 C（面试冲刺，2 天）**：速查表 → 05 中国式审批 → 09 选型 → 10 面试冲刺（20 自测 + 面试题 + 速记）。工作流是大厂 OA/低代码方向高频考点，能讲清"退回为什么难、引擎凭什么可靠"即拉开差距。

三条路线的共同前提是先把 02（BPMN）与 03（引擎内核）过一遍——建模语言与执行原理是所有后续篇章的公共地基，跳过这两篇直接看实战容易"会调 API 不懂原理"，面试一追就露馅。

## 4. 核心速查表

| 主题 | 一句话本质 | 速记 |
|---|---|---|
| 工作流 | 把业务过程固化为可执行、可审计的流程模型 | 过程建模 + 运行时执行 + 审计留痕 |
| BPMN 2.0 | 流程建模的事实标准，ISO 19510 | 事件/活动/网关 + 连线 + 泳道 |
| 三剑客 | jBPM4 同源三兄弟，分叉后路线各异 | Activiti 存量、Flowable 中国式、Camunda 8 分布式 |
| 嵌入式 vs 分布式 | 同 JVM 共享事务 vs Zeebe 分区日志 + 外部 Worker | 单体选嵌入式，微服务高吞吐选分布式 |
| ACT_* 表族 | 引擎持久化：RE 定义、RU 运行、HI 历史、GE 通用 | 历史表膨胀是运维头号问题 |
| 中国式审批 | 会签/加签/驳回/撤回是平台层语义，引擎只给积木 | 三层架构：引擎层→流程服务层→应用层 |
| 状态机 vs 引擎 | 单对象状态流转用状态机，多角色多分支流程用引擎 | 复杂度临界点：是否需要回退/会签/审计 |
| Agentic Workflow | Agent 决定怎么做，工作流决定何时何地在何约束下做 | 引擎是可控性基座，Agent 是执行者 |
| 选型铁律 | 先分类再比较，别拿四类产品同一张表比 | 人工审批→Flowable；编排→Camunda 8/Temporal；国产化→JFlow |

## 5. 体系联动与学习地图

本体系不是孤立的知识岛，工作流的正确姿势是与其他能力体系协同：

- **与《状态机思想（专项深潜）》**：06 篇的选型决策树即源于该体系的思想——单对象生命周期用状态机，多参与者流程用引擎，两者可叠加（订单状态机 + 审批工作流）。
- **与《软件工程上的设计思想》**：幂等（重复审批/重复消费）、韧性（降级熔断）、可观测性（流程埋点）是工作流生产化的前提，04/08 篇的坑位与故障排查均默认这些思想已落地。
- **与《Seata 分布式事务》**：跨服务长流程的 Saga 补偿与工作流引擎编排是同一件事的两面，07 篇讲结合方式。
- **与《主流 Agent 范式》**：03-AI 体系的"工作流 vs Agent 五工作流"是 10 篇的前置知识，本体系 10 篇讲的是反向问题——引擎如何编排 Agent。
- **与《Spring 全家桶》**：04 篇的 Flowable 集成是 Spring Boot 4 体系下的实战，事件监听与事务边界复用 Spring 事件机制。

**读法建议**：本体系"概念 → 标准 → 引擎 → 实战"四篇是主线，读完即可开工；"中国式审批、建模方法论、分布式编排"三篇是差异化价值所在，面试与平台建设靠它们；"运维、选型、AI 演进"三篇按需取用。

## 6. 常见误区速避

- 误区一：**工作流 = Flowable**。引擎只是载体，建模语义与平台层二次开发才是工程量主体。
- 误区二：**流程图画完就能跑**。BPMN 图到可执行模型之间隔着条件完备、边界事件、变量定义三层工程。
- 误区三：**状态机可以平替工作流**。单对象可行，多角色任意回退场景下状态机复杂度爆炸。
- 误区四：**Camunda 8 是 Camunda 7 的新版本**。两套架构、两套运维、两套 API，迁移是重写不是升级。
- 误区五：**开源引擎可以免费商用**。Camunda 8 自 8.6 起生产许可收费，Flowable 开源范围不含商业低代码体验。
- 误区六：**AI Agent 会取代工作流**。2026 年共识是融合：引擎提供确定性、审计与兜底，Agent 提供灵活性。
- 误区七：**流程变量当数据库用**。审批明细塞流程变量会导致变量表爆炸、查询性能雪崩，明细应落业务表、变量只留控制字段。
- 误区八：**历史表随便删**。直接手写 SQL 删 ACT_HI_ 关联表会破坏引擎内部一致性，归档删除必须走引擎 API 且先备份。

**阅读约定**：代码示例一律以 Flowable 8.0 + Spring Boot 4 为基线（Flowable 是 2026 年中国式审批最均衡的开源底座），涉及 Camunda 8 的示例单独标注；术语"引擎"默认指嵌入式引擎，"流程"默认指 BPMN 流程模型；版本信息均以 2026-08 检索校准，升级前务必复核官方发布说明。正文中"中国式审批"特指会签、加签、任意节点驳回、撤回三态等中国 OA 语境下的审批语义，与 BPMN 标准语义严格区分。
