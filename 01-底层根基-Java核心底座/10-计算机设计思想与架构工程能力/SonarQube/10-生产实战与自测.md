## 1. 实战：搭建质量门禁体系

把全体系知识点压进一个项目：从零搭建「代码质量门禁体系」——部署、配置、CI 集成、治理节奏四步闭环。交付「不合格代码进不了 main」的完整机制。

**第一步，部署（02/09 篇）**：

```bash
# docker-compose.yml：SonarQube + PostgreSQL（02 篇完整版）
docker compose up -d
curl -s http://localhost:9000/api/system/status | grep '"status":"UP"'   # 等就绪
```

**第二步，配置（04/07 篇）**——初始化四件事 + 规则治理：

```bash
# 1. 登录改密码（admin/admin → 强密码）
# 2. 生成 Token（My Account → Security → Generate Token → 存到 CI 变量）
# 3. 创建项目拿 projectKey（如 order-service）
# 4. 门禁与规则：默认 Sonar way 起步；按团队裁剪 Profile（复制默认再调）
```

**第三步，CI 集成（05 篇）**——GitLab CI 完整流水线片段：

```yaml
quality-gate:
  stage: test
  image: sonarsource/sonar-scanner-cli:latest
  variables:
    SONAR_USER_HOME: "${CI_PROJECT_DIR}/.sonar"
  script:
    - sonar-scanner -Dsonar.token=$SONAR_TOKEN \
        -Dsonar.host.url=$SONAR_HOST_URL \
        -Dsonar.projectKey=order-service \
        -Dsonar.sources=src/main/java \
        -Dsonar.java.binaries=target/classes \
        -Dsonar.coverage.jacoco.xmlReportPaths=target/site/jacoco/jacoco.xml
  after_script:
    - "STATUS=$(curl -s -u $SONAR_TOKEN: $SONAR_HOST_URL/api/qualitygates/project_status?projectKey=order-service | jq -r '.projectStatus.status')"
    - "echo \"Quality Gate: $STATUS\""
    - 'if [ "$STATUS" != "OK" ]; then echo "门禁失败：查看 $SONAR_HOST_URL/dashboard?id=order-service"; exit 1; fi'
  allow_failure: false
```

**第四步，治理节奏（07 篇）**——每周 30 分钟误报评审 + 门禁失败例会 + 存量债排期 + 季度升级（含规则评审）。

**验收四问**：**能扫吗**——Pipeline 里扫描成功、Dashboard 有数据；**能卡吗**——故意引入一个 Blocker 级问题 → 门禁失败 → 流水线红（修复后绿）；**标准对吗**——团队确认「规则少而准、误报有治理」；**能运营吗**——备份脚本、升级流程、误报评审节奏都跑过一遍。

## 2. 生产配置模板与纪律清单

**部署**：Compose/K8s + PostgreSQL + 数据卷 + TLS 反向代理 + 健康检查。**安全**：admin 改密、Token 最小化（CI 独立 Token 只给 scan）、HTTPS。**配置**：`sonar.java.binaries` 双件套、排除生成代码与 node_modules、覆盖率报告路径、DTO/Config 覆盖率剔除。**门禁**：Sonar way 起步、只卡新代码、底线而非完美、分项目门禁。**CI**：轮询门禁 API 或官方 action、`allow_failure: false`、PR 注释补偿。**运维**：备份三件套每日执行、升级五步流程、磁盘水位监控、权限审计。**版本**：锁月版 tag（26.7.0-community）、升级配套 Scanner 与插件。

## 3. 报错速查十条

| 报错 | 含义 | 处理 |
|------|------|------|
| 首次启动几分钟未就绪 | 索引初始化/数据库迁移 | 看日志 `SonarQube is up`，健康检查轮询 |
| `ANALYSIS SUCCESS` 但 Dashboard 空 | 分析异步未完成 | 等 1-2 分钟刷新；查 CE 任务日志 |
| Java 分析报「无编译产物」 | `sonar.java.binaries` 缺失 | `mvn compile` + 配置 binaries |
| 覆盖率显示 0% | 报告路径未配 | `sonar.<lang>.coverage.reportPaths` |
| 门禁读到空状态 | 分析未完成就读 | 轮询 `project_status` API |
| 老 Scanner 连新服务器报错 | 版本不配套 | Scanner 同步升级 |
| 内存 OOM 启动失败 | 资源不足 | 8GB 起步或调 sonar.ce.javaOpts |
| 升级后插件失效 | 插件不兼容 | 升级前检查、先卸再升 |
| 项目问题数突然暴增 | 新规则纳入/未排除生成代码 | 规则评审 + exclusions |
| Token 失效 | 被吊销/过期 | 重新生成并更新 CI 变量 |

## 4. 面试三范式

**价值式**：「我搭建的质量门禁体系——不合格代码进不了 main，合入前问题拦截率 X%，重复 bug 事故归零；误报治理后规则可信度提升，团队从『应付检查』变成『用报告修代码』。」——先讲事故与行为变化，再讲手段。

**技术式**：「SonarQube 是平台不是工具——Server 承载规则引擎与门禁、Scanner 采集分析、SonarLint 做 IDE 实时反馈；Clean as You Code 只卡新代码（New Code Period 定义边界），存量债排期治理；门禁是异步分析后轮询 API 判定的。」——原理到机制，别停在「能查 bug」。

**生产式**：「Community Build 用日历版本每月一发、无 LTA——升级是常态，流程是备份三件套 + Release Notes + 插件兼容 + 验证 + 规则评审；免费版无 PR 装饰用 CI 注释补偿；Token 最小化 + HTTPS + 审计。」——版本意识、升级流程、补偿方案三点是区分度。

**追问四连**：质量门禁怎么设计？（新代码条件 + 底线非完美 + 分项目）｜误报怎么治理？（排除生成代码 + 标记 + 规则裁剪）｜覆盖率怎么集成？（JaCoCo 报告路径 + 同一构建）｜升级怎么保障？（备份 → Release Notes → 插件 → 验证 → 规则评审）。

## 5. 简历呈现

项目经历写法：「搭建 SonarQube 代码质量平台——Docker 部署 + PostgreSQL + CI 门禁集成（GitLab/Jenkins），新代码质量问题合入前拦截；规则治理（排除生成代码、误报标记、Profile 裁剪）提升报告可信度；JaCoCo 覆盖率集成 + 分项目门禁；月度升级流程 + 备份演练；团队质量问题率下降 X%。」技能栏：「SonarQube 代码质量平台（质量门禁/规则治理/CI 集成）」。——机制 + 治理 + 数据收益三要素。
