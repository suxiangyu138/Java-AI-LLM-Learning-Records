## 1. 部署前置条件

SonarQube 的运行时要求（2026 基线）：**完整 JDK 21**（JRE 已不够——分析引擎需要 javac 等编译工具）、**内存建议 4GB+**（服务器 2GB + 分析引擎余量）、**磁盘按扫描规模**（每个项目的历史数据积累，GB 级起步）、**端口 9000**（默认 Web 端口）。**架构**：官方 Docker 镜像（`sonarqube:26.7.0-community` 或 `sonarqube:latest-community`——锁月版 tag 而非 latest）与 Helm 图表（K8s 场景，09 篇）；Community Build 支持 ARM 与 IPv6。

**数据库**：SonarQube 自带嵌入式 H2 数据库（**仅用于体验**——重启数据即丢），生产必须外接 PostgreSQL（Community 支持 PostgreSQL 是主流选择；商业版另有 Oracle/MSSQL）。**「先体验后生产」**：体验用默认 H2 跑通流程，生产部署直接上 PG + 数据卷（09 篇）。

## 2. Docker 快速部署

体验级最小部署——一个 Compose 文件拉起服务：

```yaml
services:
  sonarqube:
    image: sonarqube:26.7.0-community
    ports:
      - "9000:9000"
    environment:
      - SONAR_JDBC_URL=jdbc:postgresql://db:5432/sonarqube
      - SONAR_JDBC_USERNAME=sonar
      - SONAR_JDBC_PASSWORD=sonar
    volumes:
      - sonar_data:/opt/sonarqube/data
      - sonar_ext:/opt/sonarqube/extensions
    depends_on:
      db:
        condition: service_healthy
  db:
    image: postgres:16
    environment:
      - POSTGRES_USER=sonar
      - POSTGRES_PASSWORD=sonar
      - POSTGRES_DB=sonarqube
    volumes:
      - pg_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U sonar"]
      interval: 5s
```

```bash
docker compose up -d
# 等待启动（首次初始化 1-3 分钟）：容器日志出现 "SonarQube is up"
```

要点：**生产必须接 PostgreSQL**（H2 数据随容器消失）；**数据卷持久化**（data/extensions 挂卷——升级不丢数据）；**启动慢是正常的**（首次初始化 ES 索引与数据库迁移）；**健康检查**——`curl http://localhost:9000/api/system/status` 返回 `"status":"UP"` 才算就绪。**资源不够的替代**：内存 2GB 以下的小机器用官方 jar 直跑（`sonarqube-26.7.0.zip` + JDK21），体验级够用。

## 3. 初始化与配置

**首次访问 `http://localhost:9000`**：默认账号 `admin/admin`（首次登录强制改密码——改完记住，忘记用 `docker exec` 重置或删卷重来）。初始化四件事：

**改密码**（第一步，安全红线）；**生成令牌（Token）**——`My Account → Security → Generate Token`——**Scanner 与分析全部用 Token 认证**（比密码进 CI 安全，Token 可随时吊销）；**创建项目**——`Projects → Create Project` 拿 `projectKey`（如 `my-app`）；**配置 Quality Gate/Profile**（04/07 篇）——默认 Gate 与默认 Profile 开箱可用，先跑通再调。

**管理入口**：`Administration` 菜单是平台治理（权限、规则、门禁、系统信息）；`Projects` 是项目视角（问题、指标、门禁状态）。**权限模型**：默认 admin 全权，普通用户可分配项目权限（09 篇权限治理）。

## 4. 第一个项目扫描

三种 Scanner 任选其一（05 篇详解差异），最快的是 CLI：

```bash
# 1. 下载 sonar-scanner-cli（与服务器版本配套）解压，配 PATH
# 2. 项目根目录建 sonar-project.properties
sonar.projectKey=my-app
sonar.projectName=My Application
sonar.sources=src
sonar.java.binaries=target/classes        # Java 项目需编译产物
sonar.sourceEncoding=UTF-8
# 3. 执行分析
sonar-scanner -Dsonar.token=<token> -Dsonar.host.url=http://localhost:9000
```

Maven 项目更简单（插件内置于 pom 集成）：

```bash
mvn clean verify sonar:sonar -Dsonar.token=<token> -Dsonar.host.url=http://localhost:9000
```

**分析流程**：Scanner 采集源码（+编译产物）→ 发送到服务器 → 服务器跑规则引擎 → 结果入库 → 报告可查。**首次分析 1-2 分钟**（索引构建），之后增量。**验证成功**：控制台输出 `ANALYSIS SUCCESS` + 服务器报告 URL；打开 URL 看到项目 Dashboard。

## 5. 看懂第一份报告

Dashboard 的四个核心区（03/04 篇详解）：

**Overview（总览）**——质量门禁状态（Passed/Failed）、问题数、覆盖率、重复率、技术债——**先看门禁状态**（绿/红决定一切）；**Issues（问题）**——问题列表（按严重级/类型/规则过滤）——每条问题有：规则名、severity、文件与行号、修复建议（**规则详情页是「为什么这么写」的最好教材**）；**Security**——漏洞与安全热点（hotspot 需要人工审查判定）；**Code（度量）**——覆盖率、复杂度、重复、注释率按文件分布。

**第一份报告的行动**：别急着修全部——**按 severity 从 Blocker/Critical 看起**（优先修真 bug 与漏洞）；**先看懂 3 条问题再批量处理**（每类问题第一条点开看规则说明——理解了再动手）；**误报标记**（确认不是问题 → 标记 Won't Fix/False Positive——07 篇治理）。

**分析参数速查**（扫一次就懂的参数族）：**连接类**——`sonar.host.url`（服务器地址）、`sonar.token`（认证）；**项目类**——`sonar.projectKey/Name/Version`；**源码类**——`sonar.sources/tests/java.binaries`；**质量类**——`sonar.exclusions`（排除）、`sonar.sourceEncoding`（编码）；**覆盖率类**——`sonar.coverage.jacoco.xmlReportPaths`。**「先扫一个简单项目」的原则**：第一个项目选「小、纯 Java、无特殊框架」——把环境问题（连接/认证/编译产物）与业务问题（排除规则/多模块）分开排查——**环境通了再上真实项目**，别一上来拿大项目当试验田（报错分不清是环境还是配置）。

## 6. 常见坑

**先记住排障顺序**：部署问题按「容器起来了没 → 数据库连上了没 → 健康检查过了没 → 端口通了没」四步查——**90% 的「访问不了」是端口/防火墙或数据库未就绪**，不是 SonarQube 本身坏了。

**坑一：H2 当生产库**。重启数据全没——生产接 PostgreSQL。

**坑二：忘记挂数据卷**。容器重建配置全丢——data/extensions 挂卷。

**坑三：用密码进 CI**。密码改了就失效、泄露了没法单独吊销——Token 认证 + 定期轮换。

**坑四：Java 项目不配 sonar.java.binaries**。分析报「无编译产物」或漏检——先 `mvn compile` 再扫。

**坑五：锁 latest tag**。月度版本漂移——锁 `26.7.0-community`。

**坑六：内存不足启动失败**。容器 OOM——给足 4GB 或缩小配置（sonar.ce.javaOpts 调整）。

**坑七：首次登录忘改密码**。默认 admin/admin 是公开靶子——改密码是初始化第一步。

**坑八：Scanner 版本与服务器不匹配**。老 scanner 连新服务器报错——Scanner 配套升级。

**坑九：容器日志爆炸**。SonarQube 日志默认打到 stdout 无限增长——生产配置日志轮转（logs 挂卷 + logback 轮转配置）。

**坑十：端口冲突/防火墙**。9000 端口被占或云安全组没放行——「部署了访问不了」的第一排查项——先 `netstat` 再查防火墙。

**坑十一：时区与编码**。分析结果时间戳乱/中文乱码——`SONAR_JAVA_OPTS=-Duser.timezone=Asia/Shanghai` + `sonar.sourceEncoding=UTF-8` 双配。

**坑十二：docker compose 版本与插件缓存**。升级镜像后浏览器还看旧版——强制刷新/清缓存——浏览器缓存不是服务器问题。

**坑十三：首次分析后 Dashboard 无门禁状态**。项目还没绑定 Quality Gate——Administration → Quality Gates 里给项目显式绑定（默认门禁是「新项目自动绑默认」——绑定延迟/未绑是常见空状态原因）。

**坑十四：Token 权限不足**。用只读用户扫不了——Token 需要 scan 权限（全局 Permission 的 Execute Analysis）——生成 Token 时确认权限，报 403 先查这里——这是新手最常踩的权限坑之一。
