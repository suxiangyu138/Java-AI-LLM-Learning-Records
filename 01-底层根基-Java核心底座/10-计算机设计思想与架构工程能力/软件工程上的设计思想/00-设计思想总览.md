# 00-设计思想总览：28 条工程思想全景

> 定位：面向后端与系统工程的 28 条高频设计思想——不是 23 种设计模式，而是模式之上的思想层：指导"类怎么写、模块怎么切、系统怎么扛"。每条思想给出定义、工程体现、反例与面试话术。

**版本窗口：2026-08 基准**（对齐 SOLID 2026 学术实证、幂等与状态机工程实践研究）

## 3. 学习路线推荐

**路线 A（对象与模块，2 天）**：01 SOLID → 02 类与模块 → 03 工程约束。建立"类与模块怎么设计"的完整认知，配合同级《MVC》与《DDD 领域驱动设计》理解思想在架构中的应用。

**路线 B（系统韧性，3 天）**：04 健壮性 → 05 幂等 → 06 状态机 → 08 系统韧性。面试与生产最高频的专项，覆盖"分布式下系统怎么不出错、出错怎么扛"。

**路线 C（全量冲刺，5 天）**：A + B + 07 配置演进 + 09 规模并发 + 10 面试冲刺。适合秋招/跳槽前系统复习，28 条思想一条不落。

## 4. 核心速查表

| 思想 | 一句话本质 | 反例速记 |
|---|---|---|
| SRP | 一个类只有一个变更理由 | 订单 Service 管订单+支付+物流 |
| OCP | 扩展开放、修改关闭 | 新业务狂改老 if-else |
| LSP | 子类可完全替换父类 | 父类传 null 可以、子类空指针 |
| ISP | 客户端不依赖用不到的方法 | 大胖接口 + 一堆空实现 |
| DIP | 高层依赖抽象不依赖细节 | Service 直接 new DAO 实现类 |
| 迪米特 | 只和直接朋友交互 | a.getB().getC().doSomething() |
| 高内聚低耦合 | 相关内聚、模块间少依赖 | 改一个模块十个模块遭殃 |
| 正交 | 修改 A 不影响 B | 业务与日志打印耦合 |
| KISS | 保持简单不过度设计 | 炫技上复杂中间件 |
| YAGNI | 现在不需要就不实现 | 提前实现假想功能 |
| DRY | 逻辑重复抽公共 | 复制粘贴代码 |
| SoC | 不同问题分不同模块 | 数据访问+业务+视图混在一起 |
| 防御式 | 不信任外部输入提前校验 | 疯狂 try-catch 吞异常 |
| Fail-Fast | 错误尽早暴露 | 带错误数据继续跑 |
| 幂等 | 重复执行结果一致 | 重复提交、MQ 重复消费 |
| 容错 | 局部故障整体可用 | 无降级无熔断 |
| 配置驱动 | 规则进配置不进代码 | 改规则要发版 |
| 状态机 | 状态流转严格定义 | 到处乱改 status 字段 |
| 最小权限 | 只给完成任务所需权限 | 数据库账号给 drop 权限 |
| 可观测性 | 设计时就要埋点 | 出问题才补日志 |
| 缓存 | 空间换时间 | 不设计失效策略 |
| 分层 | 职责纵向切分 | 跨层直接调用 |
| 分治 | 大问题拆小问题 | 单库单表扛所有 |
| 备份冗余 | 不要单点 | 数据只存一份 |
| 约定大于配置 | 默认约定减配置 | 每个项目重建配置 |
| 向后兼容 | 升级不破坏旧客户端 | 删字段、改语义 |
| 推拉 | 推送 vs 轮询按场景选 | 全用轮询 |
| 悲观乐观 | 上锁 vs 版本号 | 不分场景全上锁 |

> 🎯 **核心要点**：28 条思想分四层记忆——对象层（SOLID + 模块约束）管"怎么设计"、韧性层（健壮/幂等/状态机/可观测）管"怎么不出错"、演进层（配置/分层/兼容）管"怎么变化"、规模层（分治/推拉/并发）管"怎么变大"。设计模式是"怎么写的模板"，设计思想是"为什么这样写的判断"——先立思想，模式自然生长。

## 4.5 与同级知识库的分工

本体系位于 `10-计算机设计思想与架构工程能力/`，与同级内容的分工：**软件架构能力体系培养**是架构师能力全景与评估框架；**MVC** 与 **DDD 领域驱动设计**是具体的架构模式与方法论（本体系的"思想"是它们的"判断依据"——SOLID 指导类设计、高内聚低耦合指导模块切分、状态机与幂等是 DDD 战术落地的支撑）；**代码质量**与 **SonarQube** 是工程化的检查工具。阅读关系：先读本体系建立 28 条思想的完整坐标系，再进 MVC/DDD 体系看思想如何落到具体架构，最后用代码质量体系把思想变成 CI 门禁——思想是"为什么"、模式是"怎么做"、工具是"怎么查"。

## 4.6 学习顺序与面试优先级

28 条思想的学习优先级（面试出现频率排序）：**第一梯队（必背）**——SOLID、幂等、状态机、缓存四大问题、悲观乐观、容错（降级熔断限流）；**第二梯队（高频）**——高内聚低耦合、DRY、KISS/YAGNI、配置驱动、向后兼容、可观测性；**第三梯队（加分）**——迪米特、正交、分层、约定大于配置、最小权限、分治、推拉、备份冗余、SoC、防御式、Fail-Fast。优先级依据：第一梯队是"分布式 + 并发"面试的必考域（决定 offer），第二梯队是项目经历深挖的常客，第三梯队是体系完整性的证明。学习顺序建议：先按路线 A（对象层）建立"思想坐标系"，再死磕第一梯队的专项篇（05/06 幂等状态机、08 缓存），最后用 10 篇的速记表做背诵收尾——体系感（知道思想怎么分类）与纵深（专项能讲深）两者都要，面试才稳。

## 5. 常见误区速查

- **误区一："SOLID 是 23 种设计模式"**。SOLID 是设计原则（判断标准），设计模式是解决方案模板；原则指导模式的选择，模式是原则的落地。面试先区分"思想/原则/模式"三层次。
- **误区二："原则要全用"**。原则是"管理复杂度的工具箱"（2026 学术共识），不是每条类必查清单——过度套用（给单一实现类硬造接口）是过度设计（NDepend 2026 实证：只有一个实现且无前景的接口只是增加间接层）。
- **误区三："幂等 = 请求 ID 去重"**。幂等必须与业务状态绑定（2026 华为云教训：状态机回滚后缓存未清会二次划扣）；(order_id, expected_version) 组合约束才是生产级方案。
- **误区四："状态机就是 if-else 状态判断"**。状态机的价值在"合法迁移的显式契约"——迁移表 + CAS 原子更新 + 非法迁移抛错，散落的 if(status==) 是状态机思想的对立面。
- **误区五："防御式编程 = 疯狂 try-catch"**。防御式是"提前拦截非法输入"（Fail-Fast 的校验分支），吞异常把错误藏到后面流程是反 Fail-Fast 的。
- **误区六："KISS 与 DRY 冲突"**。冲突场景出现在"为 DRY 强行合并业务含义不同的代码"——DRY 只针对逻辑重复；长得像但语义不同的代码合并才是过度耦合。
