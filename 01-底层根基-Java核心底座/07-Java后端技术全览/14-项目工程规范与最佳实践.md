## 1. Java 编码规范

### 1.1 命名规范

```java
// === 类名：大驼峰（UpperCamelCase） ===
public class UserService { }
public class OrderController { }
public class UserNotFoundException { }  // 异常类以 Exception 结尾

// === 方法名/变量名：小驼峰（lowerCamelCase） ===
public List<User> findByDeptId(Long deptId) { }
private String userName;
private LocalDateTime createTime;

// === 常量：全大写 + 下划线 ===
public static final int MAX_RETRY_COUNT = 3;
public static final String DEFAULT_TIMEZONE = "Asia/Shanghai";

// === 包名：全小写 + 点分隔 ===
package com.example.user.service;

// === 枚举：大驼峰，枚举值全大写 ===
public enum OrderStatus {
    PENDING_PAYMENT, PAID, SHIPPED, COMPLETED, CANCELLED
}

// === 方法命名前缀规范 ===
find / get  → 查询单个（find 可能返回 null，get 返回 Optional 或抛异常）
list        → 查询列表
search      → 搜索（关键词匹配）
count       → 计数
create / add  → 创建
update / modify → 更新
delete / remove → 删除
save        → 保存（创建或更新）
process / handle → 处理
build       → 构建
convert     → 转换

// === 布尔变量/方法命名 ===
boolean isDeleted;
boolean hasPermission;
boolean canExecute();
boolean contains(User user);
// 避免：boolean deleted; boolean flag; boolean status;
```

### 1.2 代码风格

```java
// 【阿里规约】POJO 类不要写基本类型的默认值
// ❌
public class User {
    private int age = 0;      // 不需默认值
    private boolean deleted = false;
}
// ✅
public class User {
    private int age;
    private boolean deleted;
}

// 【阿里规约】所有覆写方法加 @Override
@Override
public String toString() { ... }

// 【阿里规约】Object.equals() 容易抛 NPE
// ❌
if (user.getName().equals("张三")) { }  // NPE 风险
// ✅
if ("张三".equals(user.getName())) { }
// 或 Objects.equals(user.getName(), "张三")

// 【阿里规约】包装类比较用 equals
// ❌
Integer a = 128; Integer b = 128;
if (a == b) { }  // false!
// ✅
if (a.equals(b)) { }

// 【阿里规约】集合初始化时指定大小
// ❌
List<String> list = new ArrayList<>();  // 默认 10，不够就扩容
// ✅
List<String> list = new ArrayList<>(expectedSize);
// Guava: Lists.newArrayListWithExpectedSize(size)

// 【阿里规约】不要在 foreach 循环中 remove
// ❌
for (User user : users) {
    if (user.isDeleted()) users.remove(user);  // ConcurrentModificationException
}
// ✅
users.removeIf(User::isDeleted);
// 或 Iterator + iterator.remove()
```

### 2.2 对象转换规范

```
PO (Persistent Object)   — 与数据库表字段一一对应，存放 Entity 包
DTO (Data Transfer Object)— 层间传输数据（如 Controller → Service），存放 DTO 包
VO (View Object)         — 返回给前端的数据，存放 VO 包
Query / Command / Request — 前端传入的查询/命令/请求参数，存放 Query/DTO 包
BO (Business Object)     — 包含业务逻辑的复杂对象（可选）

转换工具：
  MapStruct（编译期生成代码，无反射，推荐）
  BeanUtils.copyProperties（反射，性能差）
  手动 get/set（最灵活，但代码量大）

// MapStruct 示例
@Mapper(componentModel = "spring")
public interface UserConverter {
    UserConverter INSTANCE = Mappers.getMapper(UserConverter.class);
    UserVO toVO(User user);
    List<UserVO> toVOList(List<User> users);
}
```

## 3. Git 工作流

### 3.1 分支模型

```
Git Flow（传统）：
  main        — 生产环境
  develop     — 开发主分支
  feature/*   — 功能分支（从 develop 创建，合并回 develop）
  release/*   — 预发布分支
  hotfix/*    — 紧急修复

GitHub Flow（简单，推荐小团队）：
  main        — 可随时部署
  feature/*   — 功能分支（从 main 创建 → PR → 合并回 main）

GitLab Flow：
  main → staging → production
  环境分支模式

推荐企业级方案：
  main/master       — 生产就绪代码
  develop           — 开发集成分支
  feature/xxx       — 功能开发
  bugfix/xxx        — Bug 修复
  hotfix/xxx        — 紧急修复（从 main 创建）
  release/x.y.z     — 发布版本
```

### 3.2 Commit 规范

```
Conventional Commits（约定式提交）：

格式：
  <type>(<scope>): <subject>

type:
  feat        新功能
  fix         Bug 修复
  docs        文档
  style       代码格式（不影响功能）
  refactor    重构
  perf        性能优化
  test        测试
  chore       构建/工具
  revert      回滚

示例：
  feat(user): 添加用户登录功能
  fix(order): 修复订单金额计算错误
  refactor(pay): 重构支付模块，使用策略模式
  perf(query): 优化用户查询，添加索引
  chore(deps): 升级 Spring Boot 到 3.3.0

Commit Message 示例：
  feat(user): 添加用户注册功能

  - 支持手机号注册
  - 支持邮箱注册
  - 短信验证码验证
  - 密码 BCrypt 加密存储

  Closes #123
```

### 3.3 分支命名

```
feature/user-login
feature/order-refund
bugfix/order-amount-calc
hotfix/npe-in-user-query
release/2.1.0
```

## 4. 代码审查清单

```
🔍 功能性检查：
  [ ] 代码实现了需求中的所有功能？
  [ ] 边界条件是否处理（null、空集合、0、负数）？
  [ ] 错误处理是否完整？
  [ ] 并发安全问题？

🔍 代码质量：
  [ ] 命名是否清晰、符合规范？
  [ ] 方法是否过⻓（> 50 行）？
  [ ] 类是否过大（> 500 行）？
  [ ] 有无重复代码？
  [ ] 有无魔法数字/字符串？应提取为常量

🔍 安全：
  [ ] SQL 注入防护（MyBatis 用 #{} 而非 ${}）？
  [ ] XSS 防护（输出编码）？
  [ ] 敏感信息是否脱敏（日志/返回值）？
  [ ] 权限校验是否在服务端？

🔍 性能：
  [ ] 数据库查询是否合理（N+1 问题）？
  [ ] 大数据集是否分页？
  [ ] 缓存策略是否正确？
  [ ] 是否有不必要的循环内 IO？

🔍 可维护性：
  [ ] 注释是否有价值（不是复述代码）？
  [ ] 日志是否充分（关键路径有日志）？
  [ ] 单元测试覆盖新逻辑？
  [ ] 是否有向后兼容性问题？
```

## 5. 日志规范

```java
@Slf4j  // Lombok 注解
public class UserService {

    public User getUser(Long id) {
        // ✅ 参数 + 结果都记录
        log.info("查询用户开始, userId={}", id);

        User user = userMapper.findById(id);

        if (user != null) {
            log.info("查询用户成功, userId={}, userName={}", id, user.getUserName());
        } else {
            log.warn("用户不存在, userId={}", id);
        }
        return user;
    }

    // ❌ 错误示范
    // log.info("查询用户：" + user);          // 字符串拼接，不推荐
    // log.info("用户信息：" + user.toString()); // 同上
    // System.out.println("用户：" + user);   // 禁止！不用 System.out
    // log.error(e.getMessage());            // 丢掉了堆栈信息！
}

// ✅ 正确日志实践：
log.info("下单成功, orderId={}, userId={}, amount={}", orderId, userId, amount);
log.error("下单失败, orderDTO={}", orderDTO, e);  // 第二个参数是 Throwable
```

## 6. 异常处理规范

```java
// ❌ 反模式 1：吞掉异常
try {
    doSomething();
} catch (Exception e) {
    // 什么都不做
}

// ❌ 反模式 2：只打印不处理
try {
    doSomething();
} catch (Exception e) {
    e.printStackTrace();  // 禁止使用 printStackTrace！
}

// ❌ 反模式 3：返回 null 代替异常
public User getUser(Long id) {
    try {
        return userMapper.findById(id);
    } catch (Exception e) {
        return null;  // 调用方突然 NPE
    }
}

// ❌ 反模式 4：异常用来做流程控制
try {
    return userMapper.findByName(name);
} catch (Exception e) {
    return null;  // 找不到就抛异常？→ 应该用 Optional
}

// ✅ 正确姿势
public User getUser(Long id) {
    try {
        User user = userMapper.findById(id);
        if (user == null) {
            throw new BusinessException(ErrorCode.USER_NOT_FOUND, "用户不存在: " + id);
        }
        return user;
    } catch (BusinessException e) {
        throw e;  // 业务异常直接抛
    } catch (DataAccessException e) {
        log.error("查询用户数据库异常, userId={}", id, e);
        throw new SystemException("查询用户服务暂时不可用", e);
    }
}
```

## 7. 注释规范

```java
/**
 * 用户服务实现类
 *
 * <p>提供用户相关的业务逻辑，包括：
 * <ul>
 *   <li>用户注册与登录</li>
 *   <li>用户信息管理</li>
 *   <li>用户权限校验</li>
 * </ul>
 *
 * @author 张三
 * @since 2024-06-01
 */
@Service
public class UserServiceImpl implements UserService {

    /**
     * 根据 ID 查询用户
     *
     * @param id 用户ID（必填，> 0）
     * @return 用户对象，若不存在则抛出 BusinessException
     * @throws BusinessException 用户不存在时抛出
     */
    @Override
    public User getUser(@NotNull Long id) {
        // 从缓存中获取
        User cached = cacheService.getUserCache(id);
        if (cached != null) return cached;
        // 从数据库获取
        return userMapper.findById(id);
    }
}

// 好的注释解释"为什么"（Why），不是复述代码（What）
// 代码本身应该能表达 What 和 How

// ✅ 好注释
// 使用 Redis 缓存降低数据库压力，用户信息变更频率低（< 1次/月）
User cached = cacheService.getUserCache(id);

// ❌ 坏注释
// 从缓存中获取用户
User cached = cacheService.getUserCache(id);
```

## 8. API 接口规范

```java
// 完整的 Controller 示例
@RestController
@RequestMapping("/api/v1/users")
@RequiredArgsConstructor
@Tag(name = "用户管理", description = "用户增删改查")
public class UserController {

    private final UserService userService;

    @GetMapping
    @Operation(summary = "分页查询用户列表")
    public Result<PageResult<UserVO>> listUsers(
            @Parameter(description = "页码") @RequestParam(defaultValue = "1") int page,
            @Parameter(description = "每页条数") @RequestParam(defaultValue = "20") int size,
            @Parameter(description = "搜索关键词") @RequestParam(required = false) String keyword) {
        return Result.success(userService.listUsers(page, size, keyword));
    }

    @GetMapping("/{id}")
    @Operation(summary = "获取用户详情")
    public Result<UserVO> getUser(
            @Parameter(description = "用户 ID") @PathVariable Long id) {
        return Result.success(userService.getUser(id));
    }

    @PostMapping
    @Operation(summary = "创建用户")
    public Result<UserVO> createUser(
            @Parameter(description = "用户信息") @Valid @RequestBody CreateUserRequest request) {
        return Result.success(userService.createUser(request));
    }

    @PutMapping("/{id}")
    @Operation(summary = "更新用户信息")
    public Result<UserVO> updateUser(
            @Parameter(description = "用户 ID") @PathVariable Long id,
            @Parameter(description = "用户信息") @Valid @RequestBody UpdateUserRequest request) {
        return Result.success(userService.updateUser(id, request));
    }

    @DeleteMapping("/{id}")
    @Operation(summary = "删除用户")
    public Result<Void> deleteUser(
            @Parameter(description = "用户 ID") @PathVariable Long id) {
        userService.deleteUser(id);
        return Result.success();
    }
}
```
