## 3. Spring 面试 15 题

### Q1: IoC 和 DI 的区别？

```
IoC（控制反转）：将对象的创建和管理控制权交给 Spring 容器
DI（依赖注入）：IoC 的一种实现方式，容器在运行时动态将依赖注入到对象中

IoC 是设计思想，DI 是具体实现方式
```

### Q2: @Autowired 和 @Resource 的区别？

```
@Autowired：Spring 注解，默认按类型注入，配合 @Qualifier 按名称
@Resource：JSR-250（Jakarta），默认按名称，找不到再按类型
```

### Q3: Bean 的作用域？

```
singleton：整个容器一个实例（默认）
prototype：每次获取新实例
request / session / application：Web 环境专用
```

### Q4: 事务传播行为有哪些？

```
REQUIRED（默认）：有则加入，无则创建
REQUIRES_NEW：总是新建，挂起当前
NESTED：嵌套事务
SUPPORTS / NOT_SUPPORTED / MANDATORY / NEVER
```

### Q5: 事务什么情况下会失效？

```
1. 方法非 public
2. 同类方法内部调用（不经过代理）
3. 异常被 catch 且未重新抛出
4. 异常类型不匹配（默认只回滚 RuntimeException）
5. 数据库引擎不支持事务（MyISAM）
```

### Q6: Spring Boot 自动配置原理？

```
@EnableAutoConfiguration → AutoConfigurationImportSelector
→ 读取 spring/autoConfiguration.imports
→ @ConditionalOnXxx 条件过滤
→ 满足条件 → 加载配置类 → 注册 Bean
```

### Q7: Spring 如何解决循环依赖？

```
三级缓存机制：
singletonObjects（一级）→ earlySingletonObjects（二级）→ singletonFactories（三级）
只解决 setter/字段注入的循环依赖
构造器注入的循环依赖无法解决
```

### Q8: Spring MVC 处理请求的流程？

```
DispatcherServlet → HandlerMapping（找 Controller）
→ HandlerAdapter（调用）→ Controller 方法
→ 参数解析 → 返回值处理 → 响应
```

### Q9: Filter 和 Interceptor 的区别？

```
Filter：Servlet 级别，可修改请求/响应，Spring 容器外
Interceptor：Spring MVC 级别，可获取 Handler，Spring 容器内
执行顺序：Filter → Interceptor → Controller
```

### Q10: 怎么自定义一个 Starter？

```
1. 创建 autoconfigure 模块（自动配置类 + spring/autoConfiguration.imports）
2. 创建 starter 模块（空模块，引入 autoconfigure）
3. @ConfigurationProperties + @AutoConfiguration + @ConditionalOnXxx
```

### Q11: Spring AOP 的原理？

```
基于动态代理：
有接口 → JDK 动态代理（Proxy + InvocationHandler）
无接口 → CGLIB（生成子类）
Spring Boot 2.x+ 默认使用 CGLIB
```

### Q12: JDK 动态代理和 CGLIB 的区别？

```
JDK：基于接口（必须实现至少一个接口），创建快调用慢（反射）
CGLIB：基于继承（生成子类），创建慢调用快，不能代理 final 类/方法
```

### Q13: BeanFactory 和 ApplicationContext 区别？

```
BeanFactory：底层容器，懒加载（getBean 时才创建）
ApplicationContext：高级容器，预加载（启动时创建所有单例 Bean）
→ 继承 BeanFactory + 国际化 + 事件 + 资源加载等
```

### Q14: @Component 和 @Bean 的区别？

```
@Component：标注在类上，Spring 自动扫描并注册
@Bean：标注在方法上（@Configuration 类中），返回值注册为 Bean
→ @Bean 适合注册第三方库的类（如 RestTemplate）
```

### Q15: Spring Boot 的 Starter 是什么？

```
一组预定义的依赖集合，引入一个 Starter 即引入该功能所需的全部 jar
如 spring-boot-starter-web：内嵌 Tomcat + Spring MVC + Jackson + ...
```

## 4. 数据库面试 10 题

### Q1: MySQL 索引底层为什么是 B+Tree？

```
1. 多叉树矮胖 → 减少磁盘 IO 次数
2. 非叶子节点不存数据 → 一个节点存更多索引项 → 更矮
3. 叶子节点链表连接 → 范围查询高效
4. 叶子存完整数据（聚簇索引）或主键值（二级索引）
```

### Q2: 聚簇索引 vs 非聚簇索引？

```
聚簇索引：叶子节点存完整数据行，一个表只有一个
非聚簇索引（二级索引）：叶子节点存主键值，查到主键后需回表
覆盖索引：索引包含了查询所需的所有列 → 无需回表
```

### Q3: 什么情况索引会失效？

```
1. LIKE '%xxx' 前置模糊
2. WHERE 中对索引列用函数或计算（WHERE YEAR(time) = 2024）
3. 隐式类型转换（varchar 列用数字比较）
4. OR 条件不是两边都有索引
5. 联合索引不满足最左前缀
6. NOT IN / != / IS NULL（部分情况）
```

### Q4: 事务隔离级别有哪些？

```
READ UNCOMMITTED  → 脏读、不可重复读、幻读都有
READ COMMITTED    → 解决脏读（Oracle 默认）
REPEATABLE READ   → 解决脏读 + 不可重复读（MySQL 默认，InnoDB 还防幻读）
SERIALIZABLE      → 全部解决，性能最差
```

### Q5: MVCC 解决什么问题？怎么工作的？

```
解决：读写不冲突（读不加锁，写不加锁给读），提高并发
原理：隐藏列（DB_TRX_ID + DB_ROLL_PTR）+ ReadView + undo log 版本链
```

### Q6: EXPLAIN 各个字段怎么看？

```
type：访问类型，const > eq_ref > ref > range > index > ALL（ALL 需优化）
key：使用的索引
rows：扫描行数
Extra：
  Using index（覆盖索引，最优）
  Using filesort（文件排序，需优化）
  Using temporary（临时表，需优化）
```

### Q7: 慢查询怎么排查和优化？

```
1. 开启慢查询日志（long_query_time=1s）
2. EXPLAIN 分析执行计划
3. type=ALL → 加索引；Using filesort → 优化 ORDER BY
4. 深分页 → 游标分页；COUNT → 汇总表
5. 大表 DDL → pt-online-schema-change
```

### Q8: MyBatis 中 #{} 和 ${} 的区别？

```
#{}：预编译占位符 ?，防 SQL 注入，自动加引号（用于参数值）
${}：字符串直接拼接，可能 SQL 注入（仅用于表名/列名/ORDER BY，需白名单校验）
```

### Q9: 分库分表后怎么处理跨库查询？

```
1. 应用层拼接（分别查，代码里合并）
2. 冗余存储（把一些数据冗余到多个表）
3. 全局表（每个库都有的小表，如字典表）
4. 绑定表（关联表使用相同分片规则，同一个库）
5. 根本：设计时就应该避免跨库查询
```

### Q10: 如何保证分库分表后的全局唯一 ID？

```
雪花算法（趋势递增，本地生成）→ 最常用
号段模式（数据库批量取号）→ Leaf-segment
Redis INCR → 简单场景
UUID → 有序性差，适合非主键
```

## 5. Redis 面试 8 题

### Q1: Redis 为什么快？

```
1. 纯内存操作
2. 单线程避免上下文切换和锁竞争
3. IO 多路复用（epoll）
4. 高效的数据结构（SDS/ziplist/listpack/skiplist）
5. 简单协议（RESP）
```

### Q2: 缓存穿透、击穿、雪崩？

```
穿透：查不存在的数据 → 布隆过滤器 / 缓存空值
击穿：热点 Key 过期 → 互斥锁 / 逻辑过期 / 永不过期
雪崩：大量 Key 同时过期 → TTL + 随机值 / 多级缓存 / 限流
```

### Q3: Redis 持久化方式？

```
RDB：快照，定时全量备份。紧凑、恢复快，可能丢数据
AOF：记录写命令，可配置每秒刷盘。安全、文件大
混合（4.0+）：RDB + AOF 增量 → 同时享受两者的优点
```

### Q4: 过期删除策略 + 内存淘汰？

```
过期删除：惰性删除（访问时检查）+ 定期删除（定时抽样）
内存淘汰（8 种策略）：
  allkeys-lru（推荐）：所有 key 中淘汰最近最少用的
  volatile-lru：有 TTL 的 key 中淘汰
  allkeys-lfu（4.0+）：按使用频率
  noeviction：不淘汰，内存满了报错
```

### Q5: Redis 分布式锁怎么实现？

```
SET key value NX PX 30000：原子加锁
value 用 UUID：解铃还须系铃人
Lua 脚本释放：先校验 value 再 DEL（原子）
Redisson 看门狗：定时续期（默认 30s，每 10s 续期 30s）
```

### Q6: Redis 主从、哨兵、Cluster 区别？

```
主从：读写分离，一主多从，手动故障转移
哨兵：自动故障转移 + 通知，不解决水平扩展
Cluster：数据分片（16384 slots），自动故障转移，水平扩展
```

### Q7: Redis 集群数据如何分布？

```
slot = CRC16(key) % 16384
每个节点负责一部分 slot
Hash Tag → 用 {key} 固定 slot（如 user:{1000}:name 和 user:{1000}:age 同 slot）
```

### Q8: 如何保证缓存和数据库双写一致？

```
策略：先更新数据库 → 再删除缓存（不是更新缓存！）
为什么删而不是更新？并发场景下更新可能导致各版本回退
最终一致性：短 TTL + 删除缓存 + Canal 监听 binlog 异步补偿
```

## 6. 分布式面试 10 题

### Q1: CAP 理论是什么？

```
C（一致性）：所有节点同时看到相同数据
A（可用性）：每个请求都能获得响应
P（分区容错）：网络故障时系统仍可用
三者只同时满足两个。P 必须保证，在 C 和 A 间选择
```

### Q2: 什么是 BASE 理论？

```
Basically Available（基本可用）：允许损失部分可用性
Soft State（软状态）：允许中间状态
Eventually Consistent（最终一致性）：最终达到一致
是 AP 的延伸
```

### Q3: 分布式事务有哪些方案？

```
强一致：2PC / 3PC / TCC（代码侵入大）
最终一致：Seata AT（无侵入）/ Saga / 本地消息表 / RocketMQ 事务消息
```

### Q4: 如何保证消息不被重复消费？

```
消息队列只保证 at-least-once
业务端必须实现幂等：
  1. DB 唯一约束（最可靠）
  2. Redis SETNX 记录消费过的消息 ID
  3. 消费记录表（与业务同事务）
```

### Q5: 如何保证消息不丢？

```
生产者：同步发送 + 重试 + Confirm 机制
Broker：多副本 + 同步刷盘（可选）
消费者：手动确认（业务成功后 ack）
```

### Q6: 服务雪崩怎么防止？

```
限流（Sentinel QPS 限流）→ 保护自己
熔断（Sentinel 熔断降级）→ 不被下游拖死
降级（Fallback）→ 系统降级有兜底
```

### Q7: 分布式 ID 生成方案？

```
雪花算法：高性能、趋势递增、本地生成 → 主推
号段模式：数据库批量取号 → Leaf-segment
Redis INCR：简单，需持久化
UUID：最简单，但无序（索引 B+Tree 分裂）
```

### Q8: 分布式 Session 存储方案？

```
方案一：Spring Session + Redis → 经常用
方案二：JWT 无状态 → 前后端分离首选
方案三：IP Hash 到固定服务器 → 不推荐
```

### Q9: 网关的作用是什么？

```
统一入口：路由转发
认证鉴权：在网关统一校验 Token
限流：保护后端服务
日志/监控：统一日志采集
跨域：统一处理 CORS
灰度发布：根据 Header 路由到不同版本
```

### Q10: Nacos vs Eureka vs Consul vs ZK 怎么选？

```
Nacos：阿里开源，注册中心 + 配置中心一体，AP/CP 可选 → 国货之光
Consul：HashiCorp 出品，健康检查强 → 多数据中心
Eureka：AP 系统，2.x 已停更 → 不再推荐
ZK：CP 系统，太重 → 非注册中心首选
```

## 7. JVM 面试 7 题

### Q1: JVM 内存结构？

```
线程共享：堆（对象）+ 方法区/元空间（类信息+常量池）
线程私有：虚拟机栈（栈帧）+ 程序计数器 + 本地方法栈
```

### Q2: 堆的结构（分代）？

```
新生代（1/3）：Eden(80%) + S0(10%) + S1(10%)
  → 新对象分配在 Eden
  → Minor GC 后存活对象移到 Survivor
  → 年龄超过阈值（默认 15）→ 晋升老年代
老年代（2/3）：长期存活的对象
```

### Q3: GC 如何判断对象可回收？

```
引用计数法：循环引用问题（Java 不用）
可达性分析：从 GC Roots 出发，不可达的对象可回收
GC Roots：栈帧局部变量、静态变量、常量、JNI 引用等
```

### Q4: GC 算法有哪些？

```
标记-清除：产生碎片
标记-复制：无碎片但浪费空间 → 新生代
标记-整理：无碎片无浪费但耗时 → 老年代
G1/ZGC：不分代的现代算法
```

### Q5: CMS 和 G1 的区别？

```
CMS：老年代并发回收，标记-清除，碎片多。JDK14 已移除
G1：分 Region，预测停顿，Mixed GC。JDK9+ 默认
```

### Q6: 你知道哪些 JVM 调优参数？

```
-Xms2g -Xmx2g → 堆大小（建议相等）
-XX:+UseG1GC → 用 G1
-XX:MaxGCPauseMillis=200 → 停顿目标
-XX:+HeapDumpOnOutOfMemoryError → OOM dump
```

### Q7: 怎么排查 CPU 100% 问题？

```
1. top → 找高 CPU 的 Java PID
2. top -H -p <pid> → 找高 CPU 线程 TID
3. printf "%x" <tid> → 转 16 进制
4. jstack <pid> | grep <16进制tid> → 定位到代码
5. 或用 Arthas：thread -n 3 看 Top 3 CPU 线程
```

## 8. 项目经验面试指南

```
项目介绍公式（STAR）：
  Situation   → 项目的背景和目标
  Task        → 你的角色和任务
  Action      → 你做了什么，怎么做的（技术、方案、决策）
  Result      → 成果和影响（性能提升 XX%、QPS 达到 XX、解决了 XX 问题）

示例回答：
  "我负责订单服务的重构，从单体拆分为微服务。
   遇到的核心挑战是分布式事务和跨服务调用。
   选用 Seata AT 模式解决事务一致性问题，
   OpenFeign + Nacos 解决服务发现和调用。
   重构后订单服务 QPS 从 500 提升到 3000，
   平均响应时间从 200ms 降到 50ms。"

高频追问方向：
  1. 为什么选择这个技术方案？比较过哪些选项？
  2. 遇到的最大技术挑战是什么？怎么解决？
  3. 上线后有没有出过线上问题？怎么排查和修复的？
  4. 如果重来一次，会做什么不同的选择？
  5. 这个项目你学到了什么？

准备建议：
  - 准备 2-3 个有深度的项目
  - 对每个项目的技术细节了如指掌
  - 会画架构图、流程图
  - 准备几个"失败的教训"（体现反思能力）
```
