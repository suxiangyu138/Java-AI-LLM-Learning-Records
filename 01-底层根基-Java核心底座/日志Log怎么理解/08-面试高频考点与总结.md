## 1. 面试高频题与答题框架

### 1.1 框架类

**Q1：SLF4J 是什么？为什么用它？**

```text
① 定义：日志门面（Facade）——只提供 API 不实现
② 价值：API 统一 + 实现可换（Logback ↔ Log4j2 不改代码）
③ 结构：代码依赖 SLF4J → 运行时绑定实现
④ 占位符：{} 懒格式化（性能优于字符串拼接）
⑤ 桥接：log4j-over-slf4j 等统一第三方库日志
⑥ 金句：代码永远依赖门面——实现是运行时的事
```

**Q2：Logback 和 Log4j2 的区别？怎么选？**

```text
① Logback：SLF4J 官方实现（零适配）、配置灵活、Spring Boot 默认
② Log4j2：异步原生（Async Loggers 性能最强）、JSON 原生（JsonTemplateLayout）
③ 安全：Log4j2 有 Log4Shell 历史（已修复）
④ 选型：默认 Logback；高并发/强 JSON → Log4j2
⑤ 金句：默认 SLF4J + Logback——特殊需求再换
```

**Q3：Log4j 2 的 Log4Shell 漏洞是什么？**

```text
① 漏洞：CVE-2021-44228——日志消息中的 JNDI 注入
② 原理：${jndi:ldap://...} 触发远程代码执行
③ 影响：全球范围的严重漏洞（打日志即中招）
④ 修复：升级 2.17+ / 禁用 JNDI
⑤ 启示：日志框架也是攻击面——依赖安全要重视
⑥ 金句：打日志也可能被打——框架安全是底线
```

### 1.2 实践类

**Q4：日志级别怎么选？**

```text
① ERROR：系统异常/关键业务失败（出现是问题）
② WARN：潜在问题（可恢复/降级）
③ INFO：关键业务节点（不出现是问题）
④ DEBUG：排查细节（生产关闭）
⑤ 判断三问：不出现是问题 → INFO；出现是问题 → ERROR
⑥ 金句：级别 = 严重度不是喜好——ERROR 必须是错误
```

**Q5：异常日志怎么写？（手写）**

```text
① 必须传异常对象：log.error("消息", e)（堆栈自动）
② 上下文前置：orderId/userId
③ 不吞异常：catch 后「记录 + 决策」
④ 错误码：业务异常带 code
⑤ 统一出口：全局异常处理器（不每处手打）
⑥ 金句：异常日志 = 上下文 + 堆栈 + 决策
```

**Q6：日志性能怎么优化？**

```text
① 占位符 {}（懒格式化）——不用字符串拼接
② 异步日志：AsyncAppender（queueSize 2048 + 不丢 INFO + neverBlock）
③ 级别控制：生产 INFO（DEBUG 关闭）
④ 减少噪音：循环内不打印/大对象摘要
⑤ 日志量控制：滚动策略 + 采样
⑥ 金句：日志性能 = 占位符 × 异步 × 级别 × 克制
```

### 1.3 MDC 类

**Q7：MDC 是什么？怎么用？**

```text
① 定义：基于 ThreadLocal 的 Map（线程级日志上下文）
② 用法：MDC.put("traceId", xxx) → 格式 %X{traceId}
③ 铁律：入口注入 + finally 清理（线程复用污染！）
④ 价值：一次请求的日志带同一 traceId（Kibana 串联）
⑤ 金句：MDC = 日志的线程级随身包——挂上处理完卸下
```

**Q8：MDC 在线程池中为什么丢失？怎么解决？**

```text
① 原因：MDC 基于 ThreadLocal——线程池复用线程不传递
② 五大场景：线程池/@Async/ForkJoinPool/Reactor/Kafka 容器
③ 解法 1：手动快照（getCopyOfContextMap → 恢复 → 清理）
④ 解法 2：Spring MdcTaskDecorator（全局装饰）
⑤ 解法 3：TTL（TransmittableThreadLocal——透明传递）
⑥ 金句：异步场景 MDC = 「快照恢复」或「TTL」
```

**Q9：traceId 怎么跨服务传递？**

```text
① 原则：无则生成、有则透传
② HTTP：自定义头（X-Trace-Id）
③ MQ：消息头传递
④ 入口：Filter 读取/生成 → MDC 注入
⑤ 消费端：MQ 头恢复 traceId
⑥ 金句：traceId 贯穿全链路——搜到它 = 看到一次请求全部
```

### 1.4 结构化与采集类

**Q10：为什么用结构化日志（JSON）？**

```text
① 机器可解析（无正则）——采集平台原生支持
② 字段可索引（Kibana 直接搜/统计）
③ 异常堆栈完整封装（不跨行）
④ MDC 字段自动包含（traceId）
⑤ 文本日志的 Grok 解析脆弱
⑥ 金句：日志即数据——结构化是采集的基础
```

**Q11：ELK 的日志链路是什么？**

```text
① 应用：JSON 日志写文件
② Filebeat：轻量采集（搬运不解析）
③ Logstash：解析/过滤/增强
④ Elasticsearch：存储与索引
⑤ Kibana：查询/可视化/告警
⑥ 金句：应用 → Filebeat → Logstash → ES → Kibana
```

**Q12：日志滚动策略怎么配？**

```text
① RollingFileAppender + SizeAndTimeBasedRollingPolicy
② 按天 + 大小（100MB）先到先切
③ maxHistory：保留 30 天
④ totalSizeCap：总容量上限（防磁盘爆满）
⑤ 金句：滚动 = 切分 + 保留 + 上限三件套
```

**Q13：异步日志的参数有哪些讲究？**

```text
① queueSize：2048（默认 256 太小）
② discardingThreshold：0（默认 20% 会丢 INFO！）
③ neverBlock：true（不阻塞业务线程）
④ includeCallerData：false（性能）
⑤ 金句：异步 = 不丢 INFO + 不阻塞业务
```

**Q14：日志里能打敏感信息吗？**

```text
① 不能：密码/身份证/银行卡/密钥
② 脱敏：打码（138****5678）/替换（***）
③ toString 陷阱：对象 toString 可能带敏感字段
④ 统一脱敏：日志 Filter/工具类
⑤ 金句：日志泄露 = 安全事件——脱敏是底线
```

## 2. 代码题实战

**题 1：判断下面日志的问题**

```java
// 代码 1
log.info("订单创建成功: " + order.getId() + ", 金额: " + order.getAmount());
// 问题：字符串拼接（无条件时也格式化）
// 修复：log.info("订单创建成功: orderId={}, amount={}", ...)

// 代码 2
try {
    paymentGateway.charge(order);
} catch (Exception e) {
    log.error("支付失败: " + e.getMessage());
}
// 问题 1：只打消息（丢堆栈）
// 问题 2：吞异常（catch 后无决策）
// 修复：log.error("支付失败: orderId={}", order.getId(), e);
//      并处理（抛出/降级）
```

**题 2：MDC 正确使用**

```java
// 入口 Filter
public void doFilter(req, res, chain) {
    try {
        MDC.put("traceId", UUID.randomUUID().toString());
        chain.doFilter(req, res);
    } finally {
        MDC.clear();   // 必须清理！
    }
}
```

**题 3：线程池传递 MDC**

```java
// 快照恢复（装饰 Runnable）
public class MdcRunnable implements Runnable {
    private final Runnable task;
    private final Map<String, String> ctx = MDC.getCopyOfContextMap();
    public void run() {
        try { MDC.setContextMap(ctx); task.run(); }
        finally { MDC.clear(); }
    }
}
```

## 3. 速查表

```text
框架：SLF4J（门面）+ Logback（默认）/Log4j2（高并发 JSON）
级别：ERROR 错误 / WARN 警告 / INFO 关键 / DEBUG 调试 / TRACE 最细
占位符：{} 懒格式化（性能）——不用拼接
MDC：put/clear（finally）+ %X{traceId} + 线程池需传递（TTL）
异步：queueSize 2048 + discardingThreshold=0 + neverBlock=true
滚动：SizeAndTime + maxHistory 30 + totalSizeCap
异常：log.error("msg", e) 传堆栈 + 上下文 + 不吞
脱敏：密码/身份证/银行卡——toString 陷阱
采集：JSON → Filebeat → Logstash → ES → Kibana
告警：ERROR 阈值/耗时超标/静默——收敛 + 升级
```

## 4. 五大常见误区

| # | 误区 | 真相 |
|---|------|------|
| 1 | 「字符串拼接没问题」 | 无条件时仍格式化——占位符是性能关键 |
| 2 | 「MDC 自动跨线程」 | ThreadLocal 不传递——需快照/TTL |
| 3 | 「异步日志默认不丢」 | discardingThreshold 默认丢 20%（含 INFO）——设 0 |
| 4 | 「异常打 getMessage 够了」 | 丢堆栈 = 排障无头绪——传异常对象 |
| 5 | 「JSON 日志只是格式」 | 结构化 = 采集基础——字段可索引/可统计/可告警 |
