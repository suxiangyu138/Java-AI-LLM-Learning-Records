## 3. 为什么必须学透 SDK

1. **每天打交道的第一对象**：JDK 本身就是 SDK——每天 `javac`/`java`/Maven 拉依赖，不懂它的结构与模块化，等于"开着车不懂发动机"。
2. **业务开发的核心技能**：支付 SDK、云厂商 SDK、消息 SDK……后端开发 30%+ 的代码是在"集成第三方 SDK"。**会集成 = 会评估、会鉴权、会防坑**——这是拉开工程能力差距的地方。
3. **AI 时代的新战场**：大模型厂商（OpenAI、DeepSeek）都在发布 SDK，Spring AI、LangChain4j 也在封装——**SDK 设计与集成能力是 AI 应用开发的前置技能**（本仓库 03-AI 层大量使用 SDK）。
4. **面试高频概念题**："API 和 SDK 的区别""JDK/JRE/JVM 的关系""JDK 9 为什么拆分模块""怎么设计一个 SDK"——区分度极高。
5. **工程体系的衔接点**：构建工具（Maven/Gradle）、模块系统、制品发布、容器化——SDK 是这些主题的"交汇点"。

## 4. 核心概念速查

### 4.1 四概念辨析

| 概念 | 一句话 | 类比 |
|------|--------|------|
| **API** | 接口规范——"能调用什么" | 餐厅菜单 |
| **SDK** | 开发工具箱——"怎么方便地调用" | 厨师上门全套（食材+工具+菜谱） |
| **Framework** | 骨架框架——"按我的规则填代码" | 装修公司的施工标准（你不能改结构） |
| **Platform** | 平台——"在我之上构建生态" | 购物中心（提供场地+流量+规则） |

### 4.2 JDK 组成速查

| 组成 | 内容 | 说明 |
|------|------|------|
| 编译器 | `javac` | 源码 → 字节码 |
| 运行时 | `java` + JVM | 字节码执行 |
| 标准库 | `java.*` / `javax.*` / `jdk.*` | 8000+ 类 |
| 工具 | jar / jlink / jmod / javadoc / jshell 等 | 打包、定制、文档、REPL |
| 模块 | 74 个 JMod（JDK 9+） | 模块化拆分 |
| 配置 | conf/ | 安全策略、日志、时区等 |

### 4.3 常用 SDK 一览（各自封装了什么）

| SDK | 类型 | 封装的核心复杂度 |
|-----|------|----------------|
| JDK | 语言 SDK | 编译、运行时、标准库（本体系 02-03 模块） |
| AWS / 阿里云 SDK | 云 SDK | 签名（SigV4）、分页、重试、多语言一致性 |
| 微信支付 / 支付宝 SDK | 支付 SDK | 签名验签、证书管理、回调验签 |
| Redis / Kafka 客户端 | 中间件 SDK | 协议、连接池、消费语义 |
| JDBC 驱动 | 数据 SDK | 网络协议、驱动注册、类型映射 |
| OpenAI / DeepSeek SDK | AI SDK | 流式响应、Token 计费、模型版本 |
| Spring AI / LangChain4j | AI 框架 SDK | 对话状态机、工具调用、多模型抽象 |

### 4.4 版本时间线（时效性重点）

| 版本 | 类型 | 发布 | 关键点 |
|------|------|:----:|--------|
| JDK 8 | LTS | 2014 | 仍在使用（历史遗留主力） |
| JDK 11 | LTS | 2018 | 企业过渡主力 |
| JDK 17 | LTS | 2021 | 现代基线 |
| **JDK 21** | LTS | 2023 | 虚拟线程、记录模式 |
| **JDK 25** | LTS | 2025-09 | 灵活构造器体、模块导入 |
| JDK 26 | 非 LTS | 2026-03 | HTTP/3、Thread.stop 移除 |
| **JDK 29** | LTS | 预计 2027-09 | 下一个 LTS |

## 6. 学习路线推荐

**路线一：入门夯实（1~2 天，对应模块 01-03）**
概念辨析 → JDK 解剖 → 模块系统；`java --list-modules` 亲眼看一下 JDK 的 74 个模块，`jlink` 打一个最小运行时。

**路线二：工程实战（3 天，对应模块 04-06）**
第三方 SDK 集成（拿一个支付/云 SDK 完整走一遍评估与接入）→ 自研 SDK 设计（给内部服务设计一个客户端 SDK）→ 多版本管理与 SDKMAN（装 2 个 JDK 切换）。

**路线三：面试冲刺（对应模块 07）**
背概念题 → 自测陷阱题 → 场景设计题；结合 `JDK/` 系统的版本题与迁移题查漏补缺。

> 🎯 **核心要点**：SDK 是"**平台与开发者之间的产品**"——理解它的组成（JDK）、集成（第三方）、设计（自研）、管理（SDKMAN）四个视角，SDK 从"黑盒依赖"变成"可控工具"。

## 8. 常见误区

| 误区 | 真相 |
|------|------|
| "API 就是 SDK" | API 是契约，SDK 是契约的实现+工具+文档——一个 REST 接口没有客户端封装不算 SDK |
| "JDK 就是 Java 语言" | JDK 是 SDK（工具+运行时），语言是语法规范（JLS）——JDK 是语言的载体 |
| "JRE 还能单独下载" | JDK 9+ 无独立 JRE，运行时 = 完整 JDK 或 jlink 定制 |
| "jlink 是给专家用的" | 容器镜像精简的标配手段，多阶段构建一行搞定 |
| "SDK 越抽象越好" | 90% 自动 + 10% 逃生通道才是平衡——全黑盒不可排查 |
| "重试越多越可靠" | 只重试可重试错误，业务失败重试 = 放大事故 |
| "升级 SDK 很安全" | 主版本升级 = 破坏性变更，必须走迁移指南与灰度 |
| "AI SDK 就是多一个 HTTP 客户端" | 流式、Token 成本、模型漂移——三个新维度不可忽略 |
