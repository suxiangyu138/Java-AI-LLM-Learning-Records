## 1. 必背考点：十问

### 1.1 API、SDK、Framework、Platform 的区别？

**标准话术**：四个概念层层递进——**API 是接口契约（能调什么），SDK 是契约的开发者友好实现（库+工具+文档+示例），Framework 是控制反转的骨架（你被调用），Platform 是生态容器（提供前三者 + 规则）**。判断核心：控制权——调用它的是 SDK，被它调用的 Framework。加分：SDK = API + 封装（鉴权/重试/类型安全）+ 工具 + 文档 + 示例。

### 1.2 JDK、JRE、JVM 的关系？

**标准话术**：**JVM 执行字节码 → JRE = JVM + 标准库（能跑）→ JDK = JRE + 开发工具（能开发）**。加分：**JDK 9 后没有独立 JRE**——模块化后运行时要么用完整 JDK，要么 jlink 定制（替代了预打包 JRE）。

### 1.3 JDK 9 为什么模块化？

**标准话术**：三大动机——**强封装**（内部 API 不外泄，`jdk.internal.*` 黑箱）、**可靠配置**（requires 显式依赖，启动期校验）、**可裁剪**（jlink 按依赖图生成最小运行时）。JDK 自身拆成 74 个模块，`java.base` 是根。

### 1.4 jlink 是什么？什么时候用？

**标准话术**：jlink 按应用的模块依赖图生成**只含所需模块的精简运行时**（体积从 ~300MB 到 40-60MB）。用在**容器化部署**（多阶段构建镜像精简）、离线环境。原料是 `$JAVA_HOME/jmods` 目录。

### 1.5 集成第三方 SDK 前评估什么？

**标准话术**：四维检查——**安全（漏洞/密钥处理）> 维护（活跃度/支持）> 兼容（依赖冲突/版本要求）> 功能**。加分：评估动作（依赖树审查、漏洞扫描、quick-start 是否开箱即用）。

### 1.6 支付回调怎么处理才安全？

**标准话术**：三铁律——**先验签（防伪造）→ 后幂等（按订单号去重，防重复回调）→ 快返回（返回平台要求的成功标识）**。验签失败拒绝 + 告警；私钥走密钥管理，不进代码/日志。

### 1.7 SDK 调用的重试策略？

**标准话术**：只对**可重试错误**重试（网络/超时/5xx），业务失败（4xx/验签失败）不重试；**指数退避 + 抖动**；重试前确认接口幂等。加分：Spring 7.0 原生 `@Retryable` 已内置（无需 Spring Retry）。

### 1.8 好 SDK 的设计标准？

**标准话术**：**90% 场景自动处理 + 10% 边缘留逃生通道**（rawRequest）；默认安全（密钥不落日志/超时默认）；类型安全（record/枚举而非字符串）；最小暴露（API 少而精）；可观测；零配置起步。加分：mock server 让调用方离线可测。

### 1.9 语义化版本怎么定？

**标准话术**：主版本=破坏性变更、次版本=向后兼容新功能、修订号=向后兼容修复。SDK 铁律：**永不删除 public API**（@Deprecated + 过渡期）、新增是"加"不是"改"、破坏性变更必须主版本号 + 迁移指南 + Changelog。

### 1.10 SDKMAN 的作用？

**标准话术**：JVM 生态的多版本管理工具——**发行版 + 版本 + 切换**三维管理；`.sdkmanrc` 把 JDK 版本变成项目资产；机制是软链接（current → 具体版本）。加分：与 CI 矩阵、Dockerfile 配合实现"环境即代码"。

## 2. 高频陷阱题 10 连问

1. **对错**：JDK 9 之后仍然单独发布 JRE。（❌ 已无独立 JRE，jlink 替代）
2. **对错**：Framework 和 SDK 都是"我们调用它"。（❌ Framework 反过来调用我们——好莱坞原则）
3. **结果**：`java --list-modules` 输出什么？（JDK 的 74 个模块列表）
4. **对错**：jlink 生成的运行时还需要完整 JDK 才能运行。（❌ 定制运行时自包含，无需 JDK）
5. **结果**：支付回调先处理业务还是先验签？（先验签——顺序颠倒等于开门揖盗）
6. **对错**：所有 SDK 失败都值得重试。（❌ 业务失败重试 = 放大错误；只重试可重试错误）
7. **对错**：SDK 升级可以自由删 API。（❌ 永不删除，@Deprecated + 过渡期）
8. **对错**：JMOD 可以像 JAR 一样放到 classpath 用。（❌ JMOD 仅链接期使用，不可运行期依赖）
9. **结果**：`java Hello.java` 直接运行单文件需要先 javac 吗？（❌ JDK 11+ 支持直接运行源码文件；JDK 25 JEP 512 支持无 class 声明）
10. **对错**：AI SDK 与普通 SDK 的集成考虑完全相同。（❌ 多出流式、Token 成本、模型版本漂移三个维度）

## 3. 高频追问速答（一句话版本）

| 追问 | 速答 |
|------|------|
| 为什么不自己写 HTTP 调用要引入 SDK？ | SDK 封装了签名/重试/序列化/错误语义——手写既慢又容易错（安全与可靠性的差距） |
| SDK 和依赖库（library）的区别？ | 库解决单点功能；SDK 是"面向平台的完整工具箱"（库+工具+文档+示例+封装） |
| 什么情况下该自己封装而不是用官方 SDK？ | 官方 SDK 质量差（文档脱节/漏洞未修/维护停滞）时，用 OpenAPI 规范自封装或生成 |
| jlink 和 jpackage 的区别？ | jlink 定制运行时（裁剪 JDK）；jpackage（JDK 14+）打包**桌面应用**安装包（含运行时） |
| 为什么模块化后反射会失效？ | 模块只导出 exports 的包，反射默认不可达——需 `opens` 显式开放（框架集成要点） |
| SDK 客户端该单例还是每次新建？ | 看线程安全：官方客户端多数线程安全可单例共享（连接池复用）；不安全则用池/ThreadLocal |
| 灰度升级 SDK 怎么做？ | 新版本独立实例（双客户端并存）→ 小流量切换 → 监控失败率/耗时 → 全量 |
| 平台没有 Java SDK 怎么办？ | 用 OpenAPI 生成器（OpenAPI Generator）生成骨架 + 手工补鉴权/重试/文档 |
| SDK 的测试怎么覆盖？ | 单元（Mock 传输）+ 契约（平台响应 fixtures）+ mock server 离线集成 |
| 什么是"自动模块"？ | 无 module-info 的 jar 放模块路径时，按 jar 文件名成为模块（Automatic-Module-Name 更可控） |

> 💡 这十问覆盖面试官的"随口追问"——每题一句话定性，展开细节对应本体系各模块。

## 4. 场景题：SDK 选型与集成设计

**题目**：公司要接入某支付平台的支付能力，平台提供 REST API 和官方 Java SDK，你怎么做？

**答题框架**（按评分点展开）：

```text
① 评估（四维）：SDK 质量（文档/quick-start）、安全（验签/密钥）、维护（活跃度）、兼容（依赖冲突）
② 接入设计：
   - 配置集中（@ConfigurationProperties + 环境变量注入密钥）
   - 业务层包装（Service 封装 SDK 调用，不直接暴露 SDK 类型）
   - 异常统一（SDK 异常 → 业务异常 + 错误码，见 Java异常体系/06）
③ 可靠性：超时必设（连接 3s/读 10s）、可重试错误重试（指数退避）、熔断降级
④ 回调安全：先验签 → 后幂等 → 快返回；验签失败告警
⑤ 监控灰度：失败率/耗时指标、沙箱先行、灰度发布
⑥ 加分点：
   - 谈 SDK 与裸 API 的取舍（评估 SDK 质量后决定用哪个）
   - 谈密钥管理（KMS/Vault，不进代码库）
   - 谈升级策略（语义化版本 + 灰度 + 变更记录对照）
```

## 5. 扩展追问：五道连环题

### 4.1 为什么说 SDK 是"产品"而不是"代码"？

**答题链**：SDK 的用户是开发者 → 采用率取决于开发者体验（quick-start 是否开箱即用、错误是否可定位、文档是否与版本锁定）→ 出问题能否 5 分钟定位 → "开发者体验 = SDK 的生死线"。加分：mock server、沙箱、迁移指南都是"产品特性"。

### 4.2 平台 API 升级了（v1 → v2），你的 SDK 怎么办？

**答题链**：版本策略三选——**① SDK 同时支持双版本（PayClientV1/V2，过渡期最稳）② SDK 主版本跟随平台（2.x 对应 v2，破坏性变更走迁移指南）③ 抽象层隔离（业务代码只依赖自己的接口，换 SDK 只改适配层）**。加分：谈"接口版本化"（URL 版本/Header 版本）+ 灰度切换。

### 4.3 怎么设计一个 AI 服务的 SDK？

**答题链**：传统 SDK 设计（Builder/record/异常体系/语义化版本）+ **AI 专属维度**——流式响应 API（call vs stream）、Token 成本控制（缓存/上下文裁剪/谨慎重试）、模型版本锁定、超时放宽（30-60s）、输出安全过滤。加分：谈"AI SDK 封装的是对话状态机而非接口调用"。

### 4.4 SDK 里怎么管理密钥？

**答题链**：**不硬编码、不进日志、不提交仓库**——由调用方注入（环境变量/KMS/Vault/配置中心）；SDK 只负责"使用密钥"不负责"存储密钥"；日志脱敏（密钥字段打码）；密钥轮换支持（每次请求读最新配置）。加分：谈 KMS 信封加密与密钥轮换策略。

### 4.5 你用过哪些 SDK？对比它们的优缺点？

**答题链**（准备 2-3 个真实例子）：如 AWS SDK（规范生成 + 多语言一致，但代码量大）、微信支付 SDK（签名封装好但文档碎片化）、Spring AI（流式与抽象优秀但版本演进快）→ 从**开发者体验四维**（上手/文档/错误处理/版本稳定性）对比 → 落到"好 SDK 的标准"（呼应 05 模块）。

## 6. 记忆口诀

```text
API 是菜单，SDK 是厨师，Framework 是施工标准，Platform 是购物中心。
JDK 里三层：JVM 引擎、JRE 能跑、JDK 能开发；九之后没有独立 JRE。
模块化三动机：封装、可靠、可裁剪；74 模块 java.base 是根。

集成 SDK 四件套：评估、封装、可靠、可观测。
回调三铁律：先验签、后幂等、快返回。
自研 SDK 两平衡：默认智能兜 90%，逃生通道留 10%。
版本三铁律：不删 API、只加不改、破坏走迁移。
环境三声明：.sdkmanrc 本地、CI 矩阵构建、Dockerfile 运行。
```
