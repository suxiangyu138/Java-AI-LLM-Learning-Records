## 1. 符号错误全景

> **背景**：符号是编译器的「语法传感器」——一处符号错误立刻中断编译。掌握符号错误的「长相」，排错速度翻倍。
> **目的**：从报错信息反推符号问题，建立「报错 → 符号」的映射。
> **适用范围**：Java 编译错误排查；也适用于 C/JS 等 C 系语言。

```text
符号错误四大类
├── ① 标点错误：缺分号/括号不配对/中文标点
├── ② 运算符错误：= vs ==、短路混用、优先级
├── ③ 转义错误：\d 非法、路径反斜杠、正则双重转义
├── ④ 结构错误：引号不闭合/块注释未结束/泛型括号
└── 占比：标点错误 > 转义错误 > 运算符 > 结构
```

## 2. 编译报错速查表（符号相关）

| 报错信息 | 符号问题 | 解法 |
|---------|---------|------|
| **`';' expected`** | 缺分号 | 上一语句末尾加分号 |
| **`illegal character: '（'`** | 中文括号！ | 换英文括号（输入法） |
| **`unclosed string literal`** | 字符串引号未闭合 | 检查双引号配对 |
| **`unclosed character literal`** | 字符引号问题（可能多字符） | char 只能一个字符 |
| **`')' expected`** | 缺右括号 | 检查括号配对 |
| **`'{' expected`** | 缺左花括号 | 方法/类体缺大括号 |
| **`cannot find symbol`** | 符号找不到（可能拼写/括号混用） | 检查方法名/括号类型 |
| **`bad operand types`** | 运算符类型错误 | `+` 用于不兼容类型 |
| **`incompatible types`** | 类型不匹配（可能 `==`/赋值混用） | 检查赋值与比较 |
| **`unexpected token`** | 意外符号（常见中文符号/多余符号） | 定位 token 位置 |
| **`illegal start of expression`** | 表达式开头非法（括号/分号错位） | 检查表达式结构 |
| **`reached end of file while parsing`** | 文件结束但语法未闭合（缺大括号！） | 检查最后一个方法/类括号 |
| **`char literal must contain exactly one char`** | 单引号内多字符 | `'ab'` 非法（用字符串） |

```text
读报错的技巧
├── ① 看「位置」：IDE 报错行列号 → 光标定位
├── ② 看「符号」：报错里的字符（'}' expected → 缺花括号）
├── ③ 向上看：真实错误常在上方几行（编译器后续报错是连锁）
└── ④ 金句：编译器说 '}' expected 时，先看「最近的未闭合结构」
```

## 3. 易混符号对照

### 3.1 高频易混组

| 易混组 | 区别 | 场景 |
|--------|------|------|
| `=` vs `==` | 赋值 vs 比较 | `if (x = 5)` 永远 true！ |
| `&` vs `&&` | 位与/不短路 vs 短路与 | 布尔逻辑用 && |
| `\|` vs `\|\|` | 位或 vs 短路或 | 同上 |
| `/` vs `\` | 除法/注释 vs 转义/路径 | 路径是 `\\` |
| `'` vs `"` | 字符 vs 字符串 | 'a' 与 "a" 类型不同 |
| `()` vs `[]` | 调用 vs 索引 | arr(0) 错误 |
| `<>` 泛型 vs 比较 | 声明 vs 运算 | `List<>` vs `a < b` |
| `{}` 代码块 vs JSON | Java 块 vs 数据 | Map 无 {} 字面量 |
| `:` vs `;` | 三元/标签 vs 语句结束 | for 骨架是分号 |
| `?` 三元 vs 通配符 | 条件 vs 泛型 | `? :` vs `List<?>` |
| `...` 可变参数 vs 省略 | Java varargs vs 展示 | `String... args` |
| `@` 注解 vs Javadoc 标签 | 注解 vs 文档 | @Override vs @param |

### 3.2 易混符号的判别方法

```text
判别技巧
├── ① 看上下文：`x = 5`（赋值）vs `x == 5`（比较）
├── ② 看类型：`'a'` 是 char（基本类型）vs `"a"` 是 String（对象）
├── ③ 看位置：`[]` 跟在变量后是索引；`()` 跟在方法名后是调用
├── ④ 看配对：`{}` 成对出现（块）；`<>` 在泛型声明中
└── ⑤ 求助 IDE：鼠标悬停看类型/语义提示
```

## 5. 排查方法论

### 5.1 符号错误排查四步

```text
符号错误排查四步（遇到编译错误）
├── ① 定位：点报错行 → 看具体字符与位置
├── ② 判类：属于哪类？（标点/运算符/转义/结构——见第 1 节）
├── ③ 检查：按类别查对应问题
│   ├── 标点类 → 分号/括号配对/中文标点
│   ├── 运算符 → = vs == / 类型兼容
│   ├── 转义类 → 反斜杠/引号内特殊字符
│   └── 结构类 → 引号闭合/块注释/大括号
└── ④ 修复：最小改动 + 重新编译
→ 金句：80% 的符号错误在「最近改的几行」——先查 diff
```

### 5.2 中文符号的专项排查

```text
中文符号事故排查（中国开发者高频）
├── ① 症状：illegal character 或 unexpected token
├── ② 特征：报错行看起来「没有错误」
├── ③ 排查：光标逐字符移动——中文符号宽度与英文不同
├── ④ 高频元凶：中文括号（）/中文引号“”/中文分号；/全角空格
├── ⑤ 根治：写代码切英文输入法；IDE 显示「输入法状态」插件
└── ⑥ 检测：grep 中文标点
    grep -rn '[（）；“”、，]' --include="*.java" .
```

## 6. 实战案例复盘

### 案例 1：`illegal character: ' '`

```text
现象：编译报 illegal character: ' '（不可见字符）
根因：  是不间断空格（NBSP）——从网页/文档复制代码带入
排查：报错位置看似空白——实际是不可见字符
解法：删除该位置的「空格」重新输入；或全文替换
    sed -i 's/\xc2\xa0/ /g' File.java    # 替换 NBSP 为普通空格
预防：不从网页直接复制代码；编辑器显示不可见字符（IDEA: View → Active Editor → Show Whitespace）
```

### 案例 2：`unclosed string literal` 连锁报错

```text
现象：unclosed string literal + 后续多行全报错
根因：字符串引号未闭合（如 "abc 少了结尾 "）
连锁：编译器把后面的代码全当成字符串内容 → 大量连锁错误
排查：只看「第一个错误」（后续都是连锁）
解法：找到字符串开头补引号
经验：多个报错时先修第一个——连锁错误会自动消失
```

### 案例 3：`reached end of file while parsing`

```text
现象：文件末尾报错（缺大括号）
根因：某个方法/类的大括号未闭合（少了一个 }）
排查：数括号配对（IDE 折叠功能看方法边界）
解法：在报错行前补 }
预防：IDE 自动缩进异常处 = 结构错误处（缩进突然变浅）
```

## 7. 核心要点

> 🎯 **核心要点**：
> 1. 符号错误四大类：标点/运算符/转义/结构——**标点错误占一半以上**
> 2. 13 条报错速查表：`';' expected`（缺分号）/`illegal character`（中文符号）/`reached end of file`（缺大括号）
> 3. 12 组易混符号：`=` vs `==`、`&` vs `&&`、`'` vs `"`、`/` vs `\`——看上下文判别
> 4. 排查四步：定位 → 判类 → 检查 → 修复；**80% 错误在最近改的几行**
> 5. 中文符号事故：NBSP 不可见字符/中文括号引号——写代码切英文输入法
> 6. 三个实战案例：NBSP/引号连锁/缺大括号——连锁报错先修第一个
