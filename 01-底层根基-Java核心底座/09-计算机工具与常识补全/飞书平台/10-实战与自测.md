## 1. 实战：运维通知机器人三合一

```java
// 目标：机器人接收群 @ 消息 → 查多维表格数据 → 发消息卡片回复
// 三合一：应用机器人（收发）+ 消息卡片（交互）+ 多维表格（数据）

// ① 初始化（05 篇：SDK + 长连接）
Client client = new Client.Builder(appId, appSecret).build();
EventDispatcher dispatcher = EventDispatcher.newBuilder("vt", "ek")
    .onP2ImMessageReceiveV1(event -> {
        String text = event.getEvent().getMessage().getContent();  // 收到消息
        if (text.contains("查询发布记录")) {
            // ② 读多维表格（06 篇：base_id/table_id）
            List<Record> records = client.bitable().record().list(baseId, tableId);
            // ③ 组装卡片回复（04 篇：interactive 消息）
            String card = buildCard(records);   // 卡片 JSON（版本/状态/时间）
            client.im().message().reply(event.getEvent().getMessage().getMessageId(), card);
        }
    })
    .build();
new WebSocketClient(client, dispatcher).start();   // 长连接收事件（无需公网）
```

**验收三问**：① 群 @机器人说"查询发布记录" → 机器人回复卡片（数据来自多维表格）；② 卡片带"查看详情"按钮 → 点击回调处理（card.action.trigger 订阅已配）；③ 重复发送相同消息 → 无重复副作用（幂等生效）。

## 2. 生产纪律清单

- **凭证纪律**：App Secret 只在环境变量；泄露立即重置；
- **权限纪律**：scope 最小化，im:message.group_msg 谨慎申请；
- **事件纪律**：长连接首选；event_id 去重；回调 3 秒返 200；
- **消息纪律**：合并推送、分级通知、@ 该 @ 的人；
- **卡片纪律**：交互有回调、状态有更新、失败有兜底；
- **数据纪律**：多维表格字段类型设计先行；API 分页读取；
- **密钥纪律**：Webhook token 加签名/轮换；CI 用 masked 变量；
- **运维纪律**：机器人健康检查 + 日志 + 监控 + 值班；
- **版本纪律**：配置变更必发布新版本；回滚路径明确；
- **AI 纪律**：aily 生成内容人确认再分发。

## 3. 报错速查十条

| 报错/现象 | 原因 | 修复 |
|------|------|------|
| code: 200340（卡片点击无响应） | card.action.trigger 未订阅/未发布 | 订阅回调 + 发布版本（04 篇） |
| 收不到消息 | 机器人不在群/可用范围没覆盖/事件未订阅 | 四步排查：范围→在群→订阅→版本（03 篇） |
| token 无效/过期 | tenant_access_token 过期（2 小时） | 重新获取 + 缓存复用（05 篇） |
| 权限不足（无权限操作） | scope 没申请/没发布 | 申请权限 + 发版本（03 篇） |
| 频控报错 | 达到 QPS 上限 | 退避重试 + 批量限速（09 篇） |
| 卡片 JSON 解析失败 | content 引号未转义 | 转义 JSON 字符串（05 篇） |
| 回调超时被重试 | 同步处理重活超 3 秒 | 先返 200 再异步（09 篇） |
| 事件重复处理 | 未按 event_id 去重 | event_id + 业务幂等（09 篇） |
| 长连接频繁断线 | 网络/防火墙 | SDK 自动重连 + 健康检查（09 篇） |
| 多维表格读不到数据 | base_id/table_id 错误/无权限 | 核对标识 + 权限 + 分页（06 篇） |

## 4. 面试三范式

**范式一：价值式**——"我做了个运维通知机器人：CI 构建失败自动推告警群并 @值班人，告警卡片带确认按钮形成处理闭环，发布记录自动写入多维表格——团队不用盯流水线了"——**用"免盯 + 闭环"讲价值**（08 篇）。

**范式二：技术式**——"飞书集成的关键是双 token 与事件订阅：tenant token 办事、user token 替人办事；长连接无需公网、Webhook 要验签（encrypt_key + HMAC-SHA256）；回调 3 秒约束下先返 200 再异步；event_id 幂等防重复"——**展示协议与工程细节**（05/09 篇）。

**范式三：架构式**——"我把飞书集成做成独立服务：薄入口（事件解析）+ 异步处理（队列）+ 能力层（API 封装）+ 数据层（多维表格）——机器人也是服务，有日志有监控有值班"——**展示服务化思维**（08 篇集成架构）。

**追问四连防身**：①"群机器人和应用机器人区别？"——**群机器人 Webhook 只能推，应用机器人能收发/交互/订阅**（04 篇）；②"为什么用长连接？"——**无需公网、延迟低、SDK 内置验签**（05 篇）；③"回调怎么保证安全？"——**verification_token 校验 + encrypt_key 解密 + 签名验证**（05 篇）；④"机器人消息刷屏怎么办？"——**合并 + 分级 + 节流，尊重接收者注意力**（09 篇）。
