## 1. IM：消息与群

**IM（即时通讯）是飞书的入口**——**消息的三种形态**：**单聊**（一对一）、**群聊**（团队/项目组）、**话题**（群内主题讨论——**多人协同时保持话题清晰**）。**消息的五种类型**：**文本**（普通消息）、**富文本**（@人/链接/加粗）、**文件**（代码/文档/压缩包）、**消息卡片**（结构化消息——**机器人推送的主力**，04 篇）、**表情回应**（轻量互动）。**开发者视角的 IM**：**通知的终点**——**CI/CD 结果、监控告警、定时报告推送到群**（08 篇）；**群的三个用途**：**项目群**（开发协作）、**告警群**（监控通知，机器人常驻）、**值班群**（轮值交接）。**IM 的工程细节**：**@人 触发通知**（重要消息 @相关人）、**群公告置顶**（团队规则/链接）、**消息免打扰分级**（告警群常开、闲聊群静音）——"**IM 是飞书的'进程通信'：重要消息要能直达，垃圾消息要能屏蔽**"。

## 2. 云文档：沉淀与协作

**云文档是团队的知识载体**——**三种文档形态**：**文档**（富文本：设计文档/方案）、**表格**（在线表格：轻量数据）、**幻灯片**（演示：评审材料）。**云文档的四个协作特性**：**多人实时编辑**（同时在线改——**看到别人的光标**）；**评论与讨论**（选中文字评论——**异步评审**）；**@人 通知**（文档里 @某人 → 对方收到提醒）；**版本历史**（回滚/看谁改了什么）。**开发者视角的文档**：**设计文档**（需求/技术方案——**评审的载体**）、**API 文档**（接口说明——**Swagger 是机器可读版，飞书文档是人读版**，Swagger 体系交叉：`../Swagger/00-Swagger总览.md`）、**复盘文档**（项目结束后沉淀）。**文档的组织**：**知识库**（07 篇——文档的"文件夹 + 权限"体系）——"**云文档是团队的'记忆'：设计、方案、复盘都在这里沉淀**"。

## 3. 多维表格：数据容器

**多维表格（Bitable）是飞书的"杀手锏"**——**业务系统的 Excel**：**表**（数据）、**视图**（同一数据的不同看法：看板/表格/甘特图）、**仪表盘**（图表统计）、**表单**（数据收集入口）、**自动化**（触发器 + 动作）。**多维表格 vs Excel 的本质区别**：**多人实时协作**（不用传文件）、**权限精细**（按表/按行控制）、**可编程**（API 读写——06 篇）、**视图分离**（同一数据不同人不同看法）。**开发者视角的多维表格**：**需求池**（需求/优先级/状态——看板视图）、**缺陷跟踪**（Bug 列表 + 表单收集）、**排期表**（任务/负责人/日期——甘特视图）、**发布记录**（版本/内容/状态）——"**多维表格是程序猿的'第二个数据库'：不存高并发，但管团队协作数据**"（06 篇深潜）。

## 4. 日历：排期与提醒

**日历是时间管理**——**三个核心能力**：**日程**（会议/评审/截止——**邀请人自动收通知**）；**会议室**（预定/显示占用）；**提醒**（提前提醒——**不迟到**）。**开发者视角的日历**：**评审排期**（设计评审/代码评审时间）、**发布窗口**（上线时间安排）、**值班排班**（轮值日历）。**日历与消息的联动**：**日程开始前自动提醒**、**日程变更自动通知**——"**日历是团队的'时间表'：排期公开，协作才有预期**"。**2026 的 aily 集成**：**对话让 aily 管理日程**（"帮我约周五下午的评审"——01 篇基线）——"**日历从手动管理走向对话管理**"。

## 5. 审批：流程与表单

**审批是"流程治理"**——**两个核心要素**：**表单**（申请内容：请假/报销/发布）、**流程**（审批链：发起 → 逐级审批 → 通过/拒绝）。**审批的开发者用法**：**日常**（请假/报销/加班）；**工程治理**（**发布审批**——上线前走审批流、**权限申请**——开环境权限）；**自动化对接**（审批事件可订阅——**审批通过 → 自动触发后续操作**，08 篇）。**审批与开发流程的结合**：**发布审批流**（代码合并 → 审批 → 部署——**流程留痕**）——"**审批是团队的'制度'：把规则变成流程，把流程变成记录**"。

## 6. 会议：沟通与妙记

**会议是同步沟通**——**三个能力**：**音视频会议**（多人/屏幕共享）、**妙记**（**自动生成会议纪要**——语音转文字 + AI 总结——"**开完会纪要已生成**"）、**字幕/翻译**（跨国会议）。**开发者视角的会议**：**评审会**（设计/代码评审——**妙记留痕**）、**周会**（同步进展——**妙记自动分发**）、**故障复盘会**（事故分析——**纪要是复盘材料**）。**会议的异步化**：**能文档讨论的别开会**（异步 > 同步）、**开过的会妙记沉淀进知识库**（07 篇）——"**会议的价值在决策，妙记的价值在留痕——飞书让会议的产出自动沉淀**"。

## 7. 六件套的协同场景

**六件套的"深度打通"是飞书的灵魂**——三个典型协同流：

**场景一：需求到排期**——**多维表格收需求（表单）→ 讨论在话题 → 排期进日历 → 状态更新自动通知**（自动化）；**场景二：发布流程**——**设计文档评审（文档+评论）→ 代码合并（GitLab）→ 发布审批（审批）→ 结果推送群（机器人）**；**场景三：会议闭环**——**日历约会议 → 会议妙记 → 纪要进知识库 → 待办进多维表格**——"**六件套不是六个工具，是一条协作流水线：数据在工具间自动流转**"——**开发者用好飞书 = 用好这条流水线**。
