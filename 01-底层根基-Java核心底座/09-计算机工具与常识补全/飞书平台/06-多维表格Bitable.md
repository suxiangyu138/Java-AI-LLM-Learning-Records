## 1. 多维表格是什么

**多维表格（Bitable）是飞书内置的"轻量数据库 + 协作表格"**——**一句话定位：业务系统的 Excel**——**它比 Excel 强在五件事**：**多人实时协作**（不用传文件、看到别人编辑）；**权限精细**（按表/按视图/按行控制）；**视图分离**（同一数据不同人不同看法）；**可编程**（API 读写 + 自动化——**这是程序猿的价值点**）；**AI 能力**（2026 自然语言搭建——第 7 节）。**2026 的容量**（00 篇基线）：**单表 1000 万热行、毫秒级计算**、向量一体化存储（结构化 + 向量混合）——"**多维表格是飞书的'数据中枢'：六件套里唯一'数据容器'**"（02 篇）。

## 2. 核心概念：表 / 视图 / 仪表盘 / 表单 / 自动化

**多维表格的五个核心概念**：**表（Table）**——数据的容器（**字段 + 记录**——类似数据库表）；**视图（View）**——同一数据的不同"看法"（**表格视图/看板视图/甘特视图/画册视图**——切换看法不改变数据）；**仪表盘（Dashboard）**——**图表统计**（数量/趋势/占比——**数据可视化**）；**表单（Form）**——**数据收集入口**（别人填表单 → 数据进表——**收集与存储分离**）；**自动化（Automation）**——**触发器 + 动作**（新记录 → 发消息通知——**表的"程序"**）。**五个概念的关系**：**表是仓库、视图是窗户、仪表盘是报表、表单是入口、自动化是管道**——"**多维表格不是一张表，是一套小型业务系统**"。

## 3. 开发者用它管什么

**程序猿用多维表格管的四类数据**（02 篇）：**需求池**（需求/优先级/状态/负责人——**看板视图拖拽流转**）；**缺陷跟踪**（Bug 列表 + 表单收集——**测试填表单 → 数据进表 → 看板视图**）；**排期与任务**（任务/负责人/截止日——**甘特视图**）；**发布记录**（版本/内容/环境/状态——**发布历史可查**）。**为什么用多维表格而不是 Excel/数据库**：**vs Excel**——多人协作/权限/视图/API（Excel 是单机工具）；**vs 数据库**——零运维/可视化/表单/自动化（数据库要建表写代码）——"**多维表格是'协作数据'的最佳容器：不用写代码就有表，要写代码也有 API**"。

## 4. API 读写：base_id 与 table_id

**API 读写是程序猿用多维表格的"程序入口"**——**两个核心标识**（00 篇基线）：**base_id**（**表格库的全局唯一标识**——`bascnxxx`）；**table_id**（**库内具体数据表的标识**——`tblxxx`）。**核心 API**（05 篇鉴权模式）：

```bash
# 读取记录
GET /open-apis/bitable/v1/apps/{base_id}/tables/{table_id}/records?page_size=100
# 新增记录
POST /open-apis/bitable/v1/apps/{base_id}/tables/{table_id}/records
{ "fields": { "需求名称": "登录优化", "优先级": "高", "状态": "待评审" } }
```

**API 的四个要点**：**字段按"字段名"操作**（fields 是"字段名 → 值"的映射——**字段名即 API 的键**）；**分页读取**（page_size/page_token——**数据多要翻页**）；**权限**（申请 bitable:app 相关 scope——**03 篇**）；**字段值类型**（文本/数字/日期/人员——**按字段类型传值**）。**典型集成**（00 篇基线）：**订阅"表格新记录"事件 → 自动同步到知识库/分发通知**——"**base_id + table_id 是表格的'坐标'：拿到坐标，就能用代码读写团队的协作数据**"。

## 5. 字段类型与公式

**字段类型（Field Type）决定"这列能存什么"**——**常用类型**：**文本**（单行/多行）、**数字**（金额/百分比）、**日期**（时间点/日期）、**单选/多选**（状态/标签）、**人员**（@人——**关联通讯录**）、**附件**（文件）、**公式**（计算字段——**类似 Excel 公式**：`SUM`/`IF`/`CONCATENATE`）。**字段设计的三个要点**：**状态用单选**（待评审/进行中/已完成——**看板视图的分组依据**）；**负责人用人员字段**（@人 可通知——**与 IM 打通**）；**统计用公式/仪表盘**（**金额汇总/进度百分比**——**数据自动算**）——"**字段类型是表的'Schema'：类型定对，视图/仪表盘/自动化才能跑起来**"。

## 6. 自动化流程

**自动化（Automation）是表格的"程序"**——**触发器 + 条件 + 动作**：

```text
触发器：新记录创建 / 记录字段变化 / 定时
条件：状态 = "已完成"
动作：发送消息到群 / 通知人员 / 更新记录 / 创建任务
```

**自动化的三个场景**（02 篇协同流）：**需求流转**（状态变"待评审" → 通知评审人）；**Bug 闭环**（新 Bug 记录 → 通知开发群）；**数据上报**（定时汇总 → 推送报表到群）。**自动化 vs API 的分工**：**自动化是"平台内配置"**（不写代码——**简单场景**）；**API 是"代码控制"**（复杂逻辑/系统集成——**程序猿的活**）——"**先问自动化能不能配，配不了再写 API——能用配置解决的别写代码**"。

## 7. 2026 的 AI 能力

**2026-03 发布的多维表格 AI 搭建是"杀手级"更新**（00 篇基线）：**自然语言描述需求 → AI 理解并澄清 → 自动生成数据表/仪表盘/问卷/权限配置乃至整套业务系统**——"**搭建业务系统从'人工设计'走向'AI 生成'**"。**AI 能力的其他部分**：**AI 字段捷径**（调用大模型提取信息/生成内容——**字段级 AI**）；**智能问答**（对表格数据提问）。**程序猿的视角**：**AI 搭建能快速出"原型表"**（**先 AI 生成骨架，再人工调字段/权限**）；**AI 字段捷径能自动化"人工整理"类工作**（提取/分类/摘要）——"**AI 搭建是'表格的脚手架'：AI 搭骨架，人做精修**"。

## 8. 五个常见坑

- **坑一**：把多维表格当数据库用（高频写）——**它适合协作数据管理，不适合高并发事务；选型认清**（01 篇边界）；
- **坑二**：字段类型不设计直接建——**视图/统计跑不起来；先定字段类型**（第 5 节）；
- **坑三**：API 不翻页读取——**数据多只读到第一页；page_token 循环**（第 4 节）；
- **坑四**：能用自动化配置的写代码——**配置优先；代码留给复杂场景**（第 6 节）；
- **坑五**：权限不配（表格给全员）——**敏感数据泄露；按表/按行配权限**（第 1 节）。
