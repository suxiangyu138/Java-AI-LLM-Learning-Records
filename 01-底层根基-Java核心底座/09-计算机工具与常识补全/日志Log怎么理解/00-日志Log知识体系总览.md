## 4. 核心概念速查

| 概念 | 一句话解释 |
|------|-----------|
| **日志（Log）** | 系统运行事件的记录——排障/审计/监控的基础 |
| **SLF4J** | 日志门面（API 标准）——只提供接口不实现 |
| **Logback** | SLF4J 官方实现（三层架构）——2026 主流 |
| **Log4j2** | 高性能实现（异步原生）——高并发场景 |
| **日志级别** | ERROR/WARN/INFO/DEBUG/TRACE——严重度分级 |
| **MDC** | 线程级日志上下文（ThreadLocal）——traceId 贯穿 |
| **结构化日志** | JSON 格式输出——机器可解析（采集核心） |
| **traceId** | 一次请求的唯一标识——全链路串联 |
| **异步日志** | 日志写入不阻塞业务线程——高并发必备 |
| **滚动策略** | 按时间/大小切分日志文件——防磁盘爆满 |
| **ELK** | Elasticsearch+Logstash+Kibana——日志采集分析 |
| **Filebeat** | 轻量日志采集器（文件 → Logstash/ES） |
| **TTL** | TransmittableThreadLocal——线程池上下文传递 |

## 5. 一图看懂：日志的完整链路（2026）

```text
日志全链路（从产生到告警）
┌─────────────────────────────────────────────┐
│ ① 产生：代码打日志（SLF4J API）              │
│    ├── INFO 业务节点 / ERROR 异常            │
│    └── MDC 注入 traceId/userId               │
├─────────────────────────────────────────────┤
│ ② 输出：Logback/Log4j2 写文件                │
│    ├── JSON 结构化（logstash encoder）       │
│    ├── 滚动策略（时间+大小）                  │
│    └── 异步 Appender（高并发）                │
├─────────────────────────────────────────────┤
│ ③ 采集：Filebeat → Logstash                 │
│    └── 解析/过滤/清洗                        │
├─────────────────────────────────────────────┤
│ ④ 存储：Elasticsearch（索引）                │
├─────────────────────────────────────────────┤
│ ⑤ 分析：Kibana（搜索/可视化）                │
│    └── 按 traceId 串联全链路                  │
├─────────────────────────────────────────────┤
│ ⑥ 告警：阈值触发（ERROR 数/耗时）            │
└─────────────────────────────────────────────┘
```
