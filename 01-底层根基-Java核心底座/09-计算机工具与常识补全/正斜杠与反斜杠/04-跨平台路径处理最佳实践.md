## 1. 跨平台路径六原则

> 🎯 **跨平台路径处理的黄金六原则**——团队代码规范的基础：

```text
① 代码中统一用 /（Windows 兼容，Unix 唯一）
② 展示给用户的路径：系统 API 生成（getRealPath/absolutePath）
③ 拼接路径：用路径库（Path/Path.join/pathlib），不用字符串 +
④ 配置路径：外部注入（环境变量/配置中心），不硬编码
⑤ 分隔符常量：File.separator / path.sep / os.sep（不手写 \ 或 /）
⑥ 用户输入路径：规范化后再用（防 .. 穿越/符号链接攻击）
```

| 原则 | 为什么 | 反例 |
|------|--------|------|
| ① 代码写 `/` | `/` 是全平台交集 | 硬编码 `\` → Linux 直接挂 |
| ② 展示用系统 API | 用户习惯本地格式 | 手写 `D:\` 路径 → Windows 换盘符就挂 |
| ③ 路径库拼接 | 自动处理分隔符/规范化 | `"D:/" + "data/" + file` → 尾部斜杠问题 |
| ④ 配置外部注入 | 环境差异不进代码 | 配置写死 C:\Users\张三 → 别人跑不了 |
| ⑤ 分隔符常量 | 平台差异代码化 | `if (win) ... else ...` 散落 |
| ⑥ 输入规范化 | 安全与正确性 | 直接拼接用户输入 → 路径穿越漏洞 |

## 2. Java：File 与 NIO Path

### 2.1 File 类的跨平台能力

```java
// File 类的分隔符常量（跨平台正确性核心）
File.separator;        // 路径分隔符：Windows "\"  /  Linux "/"
File.separatorChar;
File.pathSeparator;    // 路径列表分隔符：Windows ";"  /  Linux ":"

// 拼接路径：不用 +，用构造与父路径
File dir = new File("data");
File file = new File(dir, "orders.csv");      // 自动处理分隔符
File log = new File("logs", "app.log");

// 路径规范化（处理 . 和 ..）
File normalized = new File("data/../conf/app.yml").getCanonicalFile();

// 系统真实路径（展示给用户用）
String realPath = file.getAbsolutePath();
// Windows → D:\work\project\data\orders.csv（系统格式）
```

### 2.2 NIO Path（推荐，Java 7+）

```java
import java.nio.file.*;

// Path 拼接：/ 运算符语义（与平台无关）
Path p = Paths.get("data", "orders.csv");
Path abs = Paths.get("D:", "data", "orders.csv");
// Windows → D:\data\orders.csv   Linux → D:/data/orders.csv

// 规范化与解析
Path normalized = Paths.get("data/../conf/app.yml").normalize();
Path resolved = Paths.get("data").resolve("orders.csv");   // 拼接

// 相对路径
Path base = Paths.get("D:/data");
Path target = base.relativize(Paths.get("D:/data/sub/a.txt"));
// → sub/a.txt

// 获取系统格式路径（展示用）
String display = Paths.get("D:/data/a.txt").toAbsolutePath().toString();
// Windows → D:\data\a.txt（自动转反斜杠）
```

> 🎯 **Java 实践结论**：**代码写 `/`；拼接用 `Paths.get(...)`/`resolve`（自动适配平台）；展示用 `toAbsolutePath().toString()`（自动转系统格式）**。

### 2.3 读取配置文件（类路径）

```java
// 类路径资源：永远用 /（不是文件系统路径！）
InputStream in = getClass().getResourceAsStream("/config/app.yml");
// 或
Resource resource = new ClassPathResource("config/app.yml");

// ⚠️ 类路径 ≠ 文件系统路径
// ❌ new File("classpath:config/app.yml")  → 无效
// ✅ 用 ClassPathResource 或 getResourceAsStream
```

## 3. Node.js：path 模块

### 3.1 核心 API

```javascript
const path = require('path');

// 拼接（自动处理分隔符与规范化）
path.join('D:', 'data', 'orders.csv');
// Windows → D:\data\orders.csv  Linux → D:/data/orders.csv

// 解析为绝对路径（从当前工作目录）
path.resolve('data', 'orders.csv');
// → C:\work\project\data\orders.csv（基于 cwd）

// 规范化（处理 . 和 ..）
path.normalize('D:/data/../conf/app.yml');
// → D:\conf\app.yml（Windows 自动转 \）

// 平台分隔符
path.sep;            // Windows '\\'  Linux '/'

// 解析路径组件
const parsed = path.parse('D:/data/orders.csv');
// { root: 'D:\\', dir: 'D:\\data', base: 'orders.csv', ext: '.csv', name: 'orders' }
```

### 3.2 跨平台注意事项

```javascript
// ⚠️ 坑 1：path.resolve 基于 process.cwd()——不同启动目录结果不同
// 解法：用 __dirname 固定基准
path.resolve(__dirname, 'data', 'orders.csv');   // 永远基于文件位置

// ⚠️ 坑 2：浏览器环境没有 path 模块
// 解法：Web 场景一律用 '/'（URL 语义）

// ⚠️ 坑 3：用户上传文件名可能含 ../ 或 \ 或 /
// 解法：规范化 + 白名单
const safeName = path.basename(userFileName);   // 只取文件名部分
const safePath = path.join(uploadDir, path.basename(userFileName));
```

> 🎯 **Node.js 实践结论**：**拼接用 `path.join`（自动适配）；基准用 `__dirname`（不依赖 cwd）；用户输入取 `path.basename`（防穿越）**。

## 4. Python：pathlib

### 4.1 核心 API

```python
from pathlib import Path

# 拼接（/ 运算符，自动适配平台）
p = Path("D:") / "data" / "orders.csv"
# Windows → WindowsPath('D:/data/orders.csv')（内部用 /，显示用 \）

# 规范化
Path("data/../conf/app.yml").resolve()      # 绝对 + 规范化
Path("data/../conf/app.yml").absolute()     # 绝对（不解析符号链接）

# 平台格式转换
p.as_posix()        # 强制正斜杠：D:/data/orders.csv
str(p)              # 系统格式：D:\data\orders.csv（Windows）

# 路径组件
p.name          # orders.csv
p.stem          # orders
p.suffix        # .csv
p.parent        # D:/data

# 遍历/匹配
Path("data").glob("*.csv")          # 通配
Path("data").rglob("*.log")         # 递归
```

### 4.2 跨平台注意

```python
# ⚠️ 坑 1：Windows 原始路径与 pathlib
p = Path(r"D:\data\orders.csv")     # 原始字符串读入
p.as_posix()                        # → D:/data/orders.csv（统一）

# ⚠️ 坑 2：不要用 os.path 字符串拼接（旧写法）
# ❌ os.path.join("D:", "data", "orders.csv")   # 能用但繁琐
# ✅ Path("D:") / "data" / "orders.csv"         # pathlib 首选

# ⚠️ 坑 3：Windows 盘符与 UNC
Path(r"\\server\share\file.txt")    # UNC 路径
p.exists()                          # 检查网络共享

# ⚠️ 坑 4：Linux 下 Windows 路径字符串是「普通字符串」
# Path("D:\\data") 在 Linux 就是目录名 D:\data（不报错但语义错）
# 跨平台代码统一入口：配置注入 + 平台判断
```

> 🎯 **Python 实践结论**：**`pathlib.Path` 是跨平台路径处理的标准答案**（`/` 拼接、`as_posix()` 统一、`resolve()` 规范化）。

## 5. 配置文件与资源加载

### 5.1 配置路径的外部注入（12-Factor 原则）

```text
路径配置三原则（跨平台部署核心）
├── ① 环境变量注入：DB_PATH=${DB_PATH}（部署时决定）
├── ② 相对工作目录：不写绝对路径（部署目录可迁移）
├── ③ 平台差异交给框架：Spring 配置/环境区分

示例（Java Spring Boot）：
  application.yml:
    file:
      upload-dir: ${UPLOAD_DIR:./uploads}     # 默认相对路径
      log-dir: ${LOG_DIR:./logs}

  部署：UPLOAD_DIR=/var/data/uploads java -jar app.jar（Linux）
        UPLOAD_DIR=D:\data\uploads java -jar app.jar（Windows）
```

### 5.2 用户上传与下载路径（安全规范）

```java
// 文件上传保存（防路径穿越）
String filename = Paths.get(userFilename).getFileName().toString();
Path target = Paths.get(uploadDir).resolve(filename).normalize();
if (!target.startsWith(Paths.get(uploadDir).toAbsolutePath())) {
    throw new SecurityException("非法路径");
}

// 文件下载 Content-Disposition（文件名转义）
String encoded = URLEncoder.encode(filename, StandardCharsets.UTF_8);
header("Content-Disposition", "attachment; filename*=UTF-8''" + encoded);
```

### 5.3 临时文件与跨平台目录

```java
// 临时目录（跨平台系统常量，不要硬编码 /tmp 或 C:\Temp）
Path tmp = Files.createTempFile("app", ".log");
// Windows → C:\Users\xxx\AppData\Local\Temp\app123.log
// Linux   → /tmp/app123.log

// 用户主目录
System.getProperty("user.home");
// Windows → C:\Users\xxx   Linux → /home/xxx
```

## 6. Docker 与 CI 中的路径

### 6.1 Dockerfile 路径规范

```dockerfile
# Docker 内是 Linux——统一 /（即使构建在 Windows 上）
WORKDIR /app
COPY ./src /app/src          # Windows 上构建也是 / 语义
RUN mkdir -p /data/logs

# ⚠️ Windows 容器（少用）：路径用 \ 与 C:\
# 但推荐统一用 Linux 容器 + /
```

### 6.2 CI 中的跨平台路径（GitHub Actions）

```yaml
# GitHub Actions 跨平台矩阵——路径用 ${{ }} 上下文，不硬编码
jobs:
  test:
    strategy:
      matrix:
        os: [ubuntu-latest, windows-latest]   # 双平台跑
    steps:
      - name: 创建目录
        run: |
          mkdir -p build/reports
        shell: bash                           # 统一 bash 语法
      # 上传产物（路径用 CI 变量）
      - uses: actions/upload-artifact@v4
        with:
          path: build/reports
```

> 🎯 **CI 实践**：**`shell: bash` 统一语法（Windows runner 也有 bash）+ CI 变量代替硬编码路径 + 相对路径代替绝对路径**——矩阵测试是验证路径跨平台性的最佳手段。

## 7. 团队规范与检查工具

### 7.1 团队路径规范（Code Review 检查项）

```text
代码审查中的路径检查清单
[ ] 代码中是否硬编码了 \ ？（统一 /）
[ ] 是否用字符串 + 拼接路径？（用路径库）
[ ] 配置是否写死了本地绝对路径？（外部注入）
[ ] 用户输入路径是否规范化？（防穿越）
[ ] 上传/下载文件名是否处理？（basename + 编码）
[ ] 是否用了 File.separator/path.sep 常量？
```

### 7.2 自动化检查工具

```text
路径问题自动化检查
├── ① IDE 检查：硬编码绝对路径警告（IDEA/VS Code 插件）
├── ② 代码搜索：git grep 找可疑路径模式
│   git grep -n '[A-Za-z]:\\' -- '*.java'      # 找硬编码 Windows 路径
│   git grep -n 'C:\\\\' -- '*.java'           # 找转义后的
├── ③ 跨平台 CI：Windows + Linux 双平台跑测试
└── ④ 静态分析：SonarQube 规则（硬编码路径）
```

### 7.3 检查示例（grep 实战）

```bash
# 找出代码中所有硬编码的 Windows 盘符路径
grep -rnE '[A-Za-z]:[\\/]' --include="*.java" --include="*.js" --include="*.py" .

# 找出字符串拼接路径的反模式
grep -rn 'File(".*" + ' --include="*.java" .

# 找出硬编码分隔符（应该用常量）
grep -rn '"\\\\"' --include="*.java" .    # 出现处要人工确认合理性
```

## 8. 核心要点

> 🎯 **核心要点**：
> 1. 跨平台六原则：代码 `/`、展示用系统 API、路径库拼接、配置外部注入、分隔符常量、输入规范化
> 2. Java 用 `Paths.get`/`Path.resolve`（自动适配）；Node 用 `path.join` + `__dirname`；Python 用 `pathlib.Path`
> 3. 类路径资源永远 `/`（不是文件系统路径）；上传下载防路径穿越（`basename` + `startsWith` 校验）
> 4. Docker/CI 统一 Linux `/` 语义 + 双平台矩阵测试是验证路径跨平台性的最佳手段
> 5. Code Review 路径检查清单 + grep 自动化扫描（`[A-Za-z]:[\\/]` 硬编码路径模式）
