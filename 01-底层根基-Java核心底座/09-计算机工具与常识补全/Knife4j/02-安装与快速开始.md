## 1. starter 选型：Boot 版本匹配是唯一难点

Knife4j 集成的 90% 问题出在 starter 选错。选型表（2026-08）：

| 场景 | artifactId | 说明 |
|------|-----------|------|
| Spring Boot 3.x / Jakarta | knife4j-openapi3-jakarta-spring-boot-starter | JDK 17+，OpenAPI 3，4.5.0 |
| Spring Boot 4.x / Jakarta | knife4j-openapi3-boot4-spring-boot-starter | 或直接用 Next 5.x |
| Spring Boot 2.x / OpenAPI 3 | knife4j-openapi3-spring-boot-starter | javax 命名空间 |
| Spring Boot 2.x / Swagger 2 | knife4j-openapi2-spring-boot-starter | OAS2，仅存量 |
| Spring Boot 2.x 老版本 | knife4j-spring-boot-starter | 更老，尽量不用 |

**三条铁律**：Boot 3 必须 Jakarta 版本（混用 Boot 2 的 starter 直接依赖冲突）；Boot 2 不要用 Jakarta 版本（javax/jakarta 命名空间不兼容）；**不要手动加 springdoc-openapi**（4.x 已内置，重复引入版本冲突）。JDK 版本也要匹配：Boot 3 需 JDK 17+。

## 2. Boot 3 完整集成（五步）

**① 加依赖**（pom.xml）：

```xml
<dependency>
    <groupId>com.github.xiaoymin</groupId>
    <artifactId>knife4j-openapi3-jakarta-spring-boot-starter</artifactId>
    <version>4.5.0</version>
</dependency>
```

**② 配置**（application.yml）：

```yaml
springdoc:
  api-docs:
    path: /v3/api-docs          # OpenAPI 文档路径（默认即可）
  group-configs:                # 分组（可选）
    - group: default
      paths-to-match: /**
      packages-to-scan: com.example.controller

knife4j:
  enable: true                  # 开启增强模式（doc.html 生效的前提）
  setting:
    language: zh_cn             # 中文界面
  production: false             # 开发环境 false，生产 true（隐藏文档）
  basic:                        # HTTP 基础认证（可选）
    enable: false
    username: admin
    password: 123456
```

**③ 控制器加注解**（文档质量的关键）：

```java
@Tag(name = "用户管理", description = "用户的增删改查")
@RestController
@RequestMapping("/api/users")
public class UserController {

    @Operation(summary = "查询用户详情", description = "按 ID 查询用户信息")
    @GetMapping("/{id}")
    public User getUser(@Parameter(description = "用户 ID") @PathVariable Long id) { ... }
}
```

**④ 启动应用**：`spring-boot:run` 或 IDE 启动。

**⑤ 访问验证**：浏览器打开 `http://localhost:8080/doc.html`——看到增强界面即集成成功。

## 3. 基础配置项

| 配置 | 默认 | 作用 |
|------|------|------|
| knife4j.enable | false | 开启增强模式（doc.html 的前提） |
| knife4j.production | false | true 时屏蔽文档访问 |
| knife4j.setting.language | zh_cn | 界面语言 |
| knife4j.setting.enable-footer | true | 是否显示页脚 |
| knife4j.basic.enable | false | 开启 HTTP basic 认证 |
| knife4j.basic.username/password | — | 认证凭据 |

**最小可用配置只有 `knife4j.enable: true`**——其余都是可选项。生产环境配置（`knife4j.production: true` + basic 认证）见 08 篇，那是上线前的必做项。

## 4. 接口分组配置

分组让多模块/多业务线的接口在 doc.html 里分 tab 展示：

```yaml
springdoc:
  group-configs:
    - group: 用户服务
      packages-to-scan: com.example.user.controller
    - group: 订单服务
      paths-to-match: /api/orders/**
```

```java
// 也可以编程式分组（OpenApiCustomizer 或 GroupedOpenApi Bean）
@Bean
public GroupedOpenApi orderApi() {
    return GroupedOpenApi.builder()
        .group("订单服务")
        .pathsToMatch("/api/orders/**")
        .build();
}
```

分组价值：**按业务域隔离文档**——微服务聚合场景（07 篇）每组对应一个服务，单体大项目按模块分组。分组粒度与团队结构对齐（一个团队一组），不要按技术层分（controller/service 没有意义）。

## 5. 访问入口与验证

```text
/doc.html              Knife4j 增强界面（主入口）
/swagger-ui.html       Swagger UI 原生界面（保留，若引了 springdoc-ui）
/v3/api-docs            OpenAPI 原始 JSON（数据源，Knife4j 读取它渲染）
```

验证清单：doc.html 打开正常（无白屏/404）；接口列表与注解一致（分组/排序生效）；点击接口能展开参数与响应；在线调试能真实调用后端（返回 200/数据）。**三个入口的差异**：doc.html 是增强层、swagger-ui.html 是官方原生、/v3/api-docs 是数据源——排查问题先看数据源（/v3/api-docs 有没有内容），再判断是解析层还是 UI 层问题。

## 6. 常见报错速查

| 报错 | 原因 | 解法 |
|------|------|------|
| 404 /doc.html | 未开增强或 starter 未生效 | knife4j.enable=true；检查依赖 |
| 依赖冲突 | 手动加了 springdoc-openapi | 删掉，4.x 内置 |
| NoClassDefFoundError jakarta/javax | starter 与 Boot 版本不匹配 | Boot 3 用 jakarta starter |
| 接口不显示 | packages-to-scan 配错 | 核对扫描包路径 |
| Spring Security 拦截 doc.html | 未放行 | 放行 /doc.html 等路径（08 篇） |
| 生产环境能访问文档 | production 未配 | knife4j.production=true |

排查顺序：**先数据源（/v3/api-docs 有内容吗）→ 再入口（doc.html 可达吗）→ 后配置（enable/production/basic）**——按层定位，不要一上来怀疑注解。

**IDE 内的集成体验**：IDEA 的 Spring Boot 运行后可直接访问 doc.html（无需额外配置）；使用 devtools 热重载时，注解修改会自动刷新文档（SpringDoc 监听 bean 变化）——但 `knife4j.enable` 等配置修改需要重启。Maven 多模块项目注意：文档 starter 应加在**启动模块**（含 @SpringBootApplication 的模块），加到库模块不生效且可能引入无用依赖。

**一个常见的团队问题**："为什么我加了依赖 doc.html 还是 404"——90% 是 `knife4j.enable: true` 没写。Knife4j 的增强模式默认关闭（enable 默认 false），依赖加了对齐 swagger 原生行为但不开增强界面。把"enable 必须显式开启"写进团队接入文档的第一行，能省掉一半的接入问题咨询。

再补充版本管理建议：Knife4j 版本与 Spring Boot 版本要一起锁——在 pom 的 dependencyManagement 里统一管理 Knife4j 版本，配合 Boot BOM；升级 Boot 大版本时（2→3、3→4）同步评估 Knife4j starter 是否匹配（见 09 篇 Next 分支）。**锁版本纪律与 Gradle 体系的版本目录同理**——构建工具细节不同，工程原则一致：版本单一来源、升级有计划、变更可回滚。

**升级 Boot 3 的典型迁移路径**（从 Springfox/Swagger 2 时代）：删掉 springfox 依赖（swagger 2 注解 @Api/@ApiModel 与 OpenAPI 3 的 @Tag/@Schema 不兼容）→ 注解批量替换（@Api → @Tag、@ApiOperation → @Operation、@ApiModel → @Schema）→ 引入 Knife4j jakarta starter → 验证文档。注解替换是最耗时的部分（几十个控制器），可用 IDE 全局替换 + 逐类核对；springfox 与 springdoc 共存会冲突，必须一次性完成切换。这条路径在 Swagger 体系 07 篇有对照，本体系聚焦 Knife4j 侧。

**验证迁移的三个信号**：doc.html 正常打开（springfox 移除后若仍访问 swagger-ui.html 会 404——正常，新入口是 doc.html）；接口列表与迁移前一致（注解替换无遗漏）；调试请求正常返回（替换过程中若改了参数语义会暴露）。迁移期间建议保留一份迁移前文档导出（04 篇）做对照——**先导出旧文档再迁移，是迁移类的通用安全姿势**。

**与 API 网关/反向代理的配合**：生产环境 doc.html 通常经 Nginx/网关转发而非直连应用端口——Nginx 侧要放行 `/doc.html`、`/v3/api-docs/**`、`/webjars/**` 等路径；用 Spring Security 的项目在网关层保持同样的放行策略（双层放行要一致，否则一端 404 一端 401）。配置 HTTPS 后要验证 doc.html 的资源加载（WebJar 资源加载失败是 HTTPS 下的常见问题）。文档入口的部署拓扑（直连/网关/域名路径）建议画进接入文档——部署层问题占 Knife4j 线上故障的三成。容器化部署注意：doc.html 是应用内置资源，容器只需暴露 8080 端口即可访问，无需额外挂载静态文件——**"文档 404 先查网络层"**（端口映射/网关路由/路径前缀）是容器场景的第一排查方向。
