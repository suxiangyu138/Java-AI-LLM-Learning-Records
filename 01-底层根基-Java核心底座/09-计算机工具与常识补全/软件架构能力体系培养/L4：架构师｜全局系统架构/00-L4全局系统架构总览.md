## 1. 知识体系导图

架构能力四层递进：**L1 看懂架构 → L2 设计模块 → L3 设计子系统 → L4 设计全局系统**。L4 与前三层的差异不是"更多技术"，而是三个视角转变：

- **从局部到全局**：L2/L3 管一个模块/子系统的边界，L4 管整个系统的蓝图——服务划分、数据架构、依赖治理、演进规划
- **从技术到业务**：L4 的决策服务业务战略——架构与业务对齐，用业务语言向管理层解释技术权衡（技术翻译官）
- **从设计到治理**：L4 不只设计，还要治理——评审体系、架构度量、技术债、腐化防线（架构是持续过程，不是一次性蓝图）

L4 的标志性能力：**做选型决策**（并承担后果）、**定容量与弹性规则**、**算成本账**（FinOps）、**主导全局性难题**（一致性/容灾/性能瓶颈）。毕业标准：独立完成一份全局架构设计文档（蓝图 + 选型 + 容量 + 治理计划），通过架构委员会评审。

## 4. 体系定位

| 体系 | 主题 | L4 的衔接 |
|------|------|-----------|
| L1/L2/L3 | 看懂架构/模块设计/子系统设计 | L4 的全局蓝图由各层设计支撑——"全局视角"不是脱离细节 |
| 横向通用能力 | 权衡/ADR/C4/评审/NFR/技术债 | L4 大量使用：NFR 量化、架构评审、ADR、技术债治理 |
| 其他体系 | 微服务/DDD/消息队列/K8s/数据库 | L4 的选型与设计落地依赖各领域知识 |

**学习顺序**：L1 → L2 → L3 → 横向（NFR/评审/ADR）→ L4。L4 是"把横向工具用在全局场景"，把 L1-L3 的设计能力串成系统。

## 6. 核心概念速查

| 概念 | 一句话 |
|------|--------|
| 技术翻译官 | 把架构权衡翻译成业务语言向管理层解释 |
| NFR 量化 | 质量属性数字化：QPS/延迟/RTO/可用性 |
| 性能预算 | 把端到端延迟预算分配到各环节 |
| SLA | 服务等级协议：可用性 99.99% 等量化承诺 |
| 过度设计 | 为不存在的需求引入复杂度（Kent Beck 四原则） |
| 前瞻性设计 | 最小化预留（接口抽象/边界），不做完整扩展 |
| 服务网格 | Istio 等：服务间流量治理基础设施 |
| 韧性工程 | 快速恢复优先于绝对稳定，混沌工程常态化 |
| 流体架构 | 弹性规则取代静态资源规划（Serverless 成熟） |
| 分库分表 | 数据规模突破单库时的水平拆分 |
| FinOps | 成本治理：把成本监控嵌入架构设计每个环节 |
| 每瓦特产出 | 能效比评估：绿色计算核心 KPI |
| 模型路由层 | AI 架构中按意图/成本/延迟动态选模型 |
| 概率性治理 | AI 输出的不确定性设计（幻觉容忍/校验） |

## 7. 常见误区

1. **"架构师 = 技术最牛的人"**——核心是决策与治理：选型判断、权衡沟通、评审把关
2. **"架构设计一次性完成"**——架构是持续治理过程，蓝图要随业务演进（十年蓝图是幻觉）
3. **"大厂方案 = 好方案"**——大厂架构适配其亿级体量与千人团队，照搬是给自行车装飞机发动机
4. **"五个九 = 好系统"**——2026 韧性共识：快速恢复与优雅降级比绝对稳定更实用
5. **"容量规划 = 买多少服务器"**——流体架构时代，重点是定义弹性规则而非静态资源
6. **"成本是运维的事"**——FinOps：成本视角嵌入设计（低负载持有成本是架构决策）
7. **"AI 架构 = 接个 API"**——AI 原生架构要设计模型路由、概率治理、RAG 存储体系
