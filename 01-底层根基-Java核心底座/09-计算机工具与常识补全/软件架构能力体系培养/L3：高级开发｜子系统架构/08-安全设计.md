## 1. 安全设计思维

**「安全是设计出来的，不是扫出来的」**——安全扫描（SAST/DAST）只能发现「已知漏洞的已知模式」，设计缺陷（错误的信任边界、缺失的授权检查）扫描器查不出来——**「安全设计在方案阶段决定安全上限」**。

**安全设计的三个前提**：**威胁模型意识**（「谁可能攻击我、怎么攻击」——不是「我们是内网所以安全」）；**信任边界意识**（「哪里是不可信输入」——**「一切外部输入不可信」是安全设计的默认**）；**安全是 NFR 的一部分**（[[../横向通用能力/05-质量属性与NFR|安全 NFR]]——「高危漏洞为零 + 合规要求」可验收）。

## 2. 威胁建模

**威胁建模（Threat Modeling）——安全设计的前置步骤**：**标准方法 STRIDE**——六类威胁逐类过：**Spoofing**（伪装——身份伪造——对策：认证）；**Tampering**（篡改——数据被改——对策：完整性校验/签名）；**Repudiation**（抵赖——否认操作——对策：审计日志）；**Information Disclosure**（泄露——机密泄露——对策：加密/权限）；**Denial of Service**（拒绝服务——不可用——对策：限流/配额）；**Elevation of Privilege**（提权——越权——对策：授权）。

**威胁建模的流程**：**画数据流图**（子系统内的数据流向——输入 → 处理 → 存储 → 输出）；**逐条过 STRIDE**（每个数据流节点过六类威胁——「这里能被伪装吗/篡改吗/泄露吗」）；**输出威胁清单 + 缓解措施**——**「威胁建模的产出是安全设计的输入」**——评审检查「威胁清单是否覆盖」（[[../横向通用能力/07-架构评审与ATAM|评审]] 的安全维度）。

## 3. 认证设计

**认证（Authentication）——「你是谁」**：子系统级认证设计要点：**认证方案**——用户态（Session/JWT 双 Token——[[../../../../02-后端核心技术%20微服务%20分布式%20云原生/10-前端知识拓展/Token/00-Token总览|Token 体系]]）、服务间（API Key/mTLS——服务调用认证）；**认证的边界**——「子系统自己认证还是复用统一认证」（SSO/OAuth——[[../../../../02-后端核心技术%20微服务%20分布式%20云原生/10-前端知识拓展/Token/07-单点登录与第三方登录|SSO 体系]]）——**「认证是平台级能力，子系统尽量复用」**；**凭证管理**——密码策略（强度/哈希——bcrypt/argon2——[[../../../../02-后端核心技术%20微服务%20分布式%20云原生/06-Spring全家桶/Spring%20Security与Spring%20Security%20OAuth2|Spring Security 体系]]）、密钥管理（环境变量/密钥管理服务——不落代码）；**会话安全**——令牌生命周期（过期/轮换/吊销——Token 体系的双 Token 纪律）。

## 4. 授权设计

**授权（Authorization）——「你能做什么」——安全设计的主战场**：**「认证是容易的一半，授权是难的一半」**——越权（BOLA）连续多年是 OWASP API Top10 榜首（[[../横向通用能力/06-架构模式知识地图|模式地图]] 与 [[../../../../02-后端核心技术%20微服务%20分布式%20云原生/09-Web开发全流程/RESTful%20API/00-RESTful%20API总览|RESTful 体系]] 的安全红线）。

**授权设计的三层**：**身份层**——令牌里的用户/角色信息（JWT 的 claims——Token 体系）；**策略层**——角色/权限模型（RBAC——角色 → 权限；ABAC——属性 → 策略——复杂场景）；**对象层**——**对象级授权（BOLA 的防线）**——「每个资源访问校验归属」——**「订单 123 属于你吗」**——「ID 能猜到 ≠ 能访问」——对象级校验是 L3 设计的必做项。**授权的实现**——框架（Spring Security 的方法级安全——[[../../../../02-后端核心技术%20微服务%20分布式%20云原生/06-Spring全家桶/Spring%20Security与Spring%20Security%20OAuth2|Spring Security 体系]]）+ 对象层手动校验（「归属校验不能省」）。

## 5. 数据安全

**数据安全——「数据在传输、存储、使用中的保护」**：**传输安全**——HTTPS 全覆盖（TLS——[[../../../../02-后端核心技术%20微服务%20分布式%20云原生/09-Web开发全流程/Web%20高阶知识/03-HTTPS与TLS深入|TLS 体系]]——无明文端点）；**存储安全**——敏感数据加密（密码哈希、证件号加密存储——[[../../../../02-后端核心技术%20微服务%20分布式%20云原生/01-关系型数据库/MySQL|MySQL 加密]]）、密钥管理（KMS/密钥服务——密钥不落代码）；**使用安全**——**数据最小化**（只存必要数据——「不收集 = 不泄露」）、**脱敏**（日志脱敏、展示脱敏——[[../../../../02-后端核心技术%20微服务%20分布式%20云原生/07-工程运维基础/运维/日志监控指标/00-日志监控指标总览|日志监控]] 的脱敏纪律）、**访问审计**（敏感数据的访问留痕——「谁看了手机号」可查）；**合规**——数据合规要求（个保法/GDPR——[[../横向通用能力/05-质量属性与NFR|合规 NFR]]）。

## 6. 安全左移

**安全左移（Shift Left）——安全活动前置到设计/开发期**：**设计期**——威胁建模（第 2 节）、安全设计评审（评审检查单的安全维度——[[../横向通用能力/07-架构评审与ATAM|评审]]）；**开发期**——安全编码规范（注入防护——[[../../../../02-后端核心技术%20微服务%20分布式%20云原生/09-Web开发全流程/Web%20高阶知识/07-Web安全攻防|Web 安全体系]] 的漏洞清单）、SAST（静态扫描——SonarQube 安全规则——[[../../../../02-后端核心技术%20微服务%20分布式%20云原生/07-工程运维基础/开发/代码质量/00-代码质量管理体系总览|代码质量体系]]）；**CI 期**——依赖漏洞扫描（SCA——CVE 检查）、容器镜像扫描（Trivy 类——[[../../../../02-后端核心技术%20微服务%20分布式%20云原生/07-工程运维基础/运维/CI%20CD灰度发布|CI/CD 安全左移]]）；**上线期**——安全配置检查（默认口令、暴露面——[[../横向通用能力/05-质量属性与NFR|安全基线]]）。

**「安全左移的成本逻辑」**——设计期发现安全问题改设计（便宜），上线后发现问题打补丁（贵且狼狈）——**「安全问题的发现越早越便宜」**。

## 7. 常见坑

**坑一：内网即安全**。内网也有威胁（横向移动、内鬼）——威胁建模照做。

**坑二：认证做了授权不做**。能登录 ≠ 能访问——对象级授权（BOLA 防线）。

**坑三：ID 可枚举当公开**。订单 ID 能猜到就能访问——归属校验。

**坑四：敏感数据明文存**。证件号/手机号明文——加密 + 脱敏。

**坑五：密钥进代码**。密钥写死/进 git——密钥管理服务。

**坑六：扫描代替设计**。SAST 扫过就完事——威胁建模前置。

**坑七：安全 NFR 不验收**。「要安全」——高危漏洞为零 + 合规清单。
