## 1. 五步读项目法

**读项目的错误姿势**：从第一个文件开始逐行读——**几千个文件，三天后放弃**。**正确姿势：五步定向阅读**——**① README 与文档**（项目是什么）→ **② 配置文件**（连了什么）→ **③ 依赖清单**（用了什么）→ **④ 入口与启动类**（从哪开始）→ **⑤ 跑起来**（亲手运行）——"**读项目不是'读'，是'调查'：像侦探一样先看案卷（文档）、再看现场（配置）、最后还原过程（运行）**"。**五步的产出**：**一张技术栈清单 + 一张结构地图 + 一次成功运行**——拿到这三样，就算"看懂项目"了。

## 2. 第一步：README 与文档

**README 是项目的"自我介绍"**，先读它回答三个问题：**项目是干什么的**（业务定位）；**怎么启动**（快速开始）；**目录结构说明**（如果有）。**文档的优先级**：**README > docs/ 目录（架构文档/设计文档）> wiki**——**架构文档是"地图"**（09 篇 C4 模型），README 是"入口指南"。**没有 README 怎么办**：**看 pom.xml/package.json 的 artifactId/描述**、看代码目录名（模块名即业务线索）、问带教——"**好项目的文档是'先看地图再逛街'，差项目只能'走一步问一步'**"。

## 3. 第二步：配置文件

**配置文件回答"项目连了什么"**——**application.yml/properties**（Spring 系）是核心：**数据源**（数据库地址/账号——**连哪个库**）；**Redis/MQ 配置**（中间件地址——**用没用、连哪**）；**端口与上下文路径**（服务地址）；**日志配置**（日志级别/输出）。**配置文件的三个读法**：**先看数据源与中间件**（项目的"基础设施清单"）；**再看 profile 区分**（dev/test/prod 的环境差异——**本地连哪、生产连哪**）；**最后看自定义配置项**（业务配置——**项目特有的开关与参数**）——"**配置文件是项目的'血管图'：看出数据往哪流、依赖什么服务**"（07 篇数据与中间件角色详讲）。

## 4. 第三步：依赖清单

**依赖清单回答"项目用了什么"**——**pom.xml（Maven）/build.gradle（Gradle）/package.json（前端）**。**读依赖的三个重点**：**框架版本**（Spring Boot 版本 → 项目技术基线——**Boot 3 还是 Boot 4 决定了大量写法差异**）；**中间件客户端**（redis/mq/mybatis/es 的 starter——**项目用了哪些中间件一目了然**）；**公共组件**（自己团队的 common 包——**项目内部的公共能力**）。**依赖的深一层读法**：**依赖即架构的"技术栈声明"**——**看依赖清单就能说出项目的技术栈**（"Spring Boot 4 + MyBatis-Plus + Redis + RocketMQ"）——**技术栈识别（第 7 节）主要靠这一步**。

## 5. 第四步：入口与启动类

**入口回答"从哪开始"**——**Spring Boot 的启动类**（`@SpringBootApplication` 标注的 main 方法所在类——**扫描路径的根**：`@SpringBootApplication` 默认扫描启动类所在包及其子包——**看懂包结构的第一线索**）；**Web 配置**（拦截器/过滤器/全局异常处理——**请求进来先过谁**）；**路由入口**（Controller 包——**接口都在哪**）。**入口的三个价值**：**知道包结构的根**（从启动类展开看包——04 篇）；**知道请求的"第一站"**（拦截器/过滤器/Controller）；**知道项目的"骨架起点"**（启动类所在的包名通常是公司的业务根包）——"**入口是项目的地标：从地标出发，不会迷路**"。

## 6. 第五步：跑起来

**跑起来是看懂项目的最后一公里**——**"读十遍文档不如跑一次"**：**按 README 的快速开始启动**（数据库要本地起/连测试库）；**启动成功看日志**（端口、数据源、中间件连接——**启动日志是项目的"体检报告"**）；**调用一个接口验证**（Swagger 里 Try it out——**界面点一遍，接口的真实响应就是最好的架构说明**，Swagger 体系交叉：`../Swagger/00-Swagger总览.md`）。**跑不起来的三个常见原因**：**依赖服务没起**（MySQL/Redis 先起）；**配置不对**（本地 profile 没切）；**版本不匹配**（JDK 版本/依赖冲突）——"**跑起来的意义：从'听说'变成'亲见'——亲手点过的接口，比读十篇文档记得牢**"。

## 7. 技术栈识别速查

**看依赖/配置文件快速识别技术栈**（Java 系）：

| 看到什么 | 说明 |
|---------|------|
| spring-boot-starter-web | Spring Boot Web 应用 |
| spring-boot-starter-webflux | 响应式 Web（WebFlux） |
| mybatis-plus / mybatis-spring | MyBatis-Plus 数据访问层 |
| spring-boot-starter-data-redis | Redis（缓存/分布式组件） |
| rocketmq/kafka/rabbitmq starter | 消息队列（异步解耦） |
| spring-cloud-starter-gateway | 微服务网关 |
| nacos/feign 相关 | 微服务注册/调用 |
| springdoc-openapi | 接口文档（Swagger UI） |
| spring-boot-starter-security | 安全框架 |

**识别的用途**：**技术栈 = 架构的"语言"**——**知道项目说什么语言，才能读懂它的架构**；**识别后按需补课**（不熟的组件先看它在项目里的用法，再补原理）——"**技术栈识别不是目的，是'知道自己要补什么课'的起点**"；**产出清单**：一张"项目技术栈 + 我熟/我不熟"对照表——**不熟的组件就是本周的学习清单**。

## 8. 五个常见坑

- **坑一**：从第一个文件逐行读——**必放弃；五步定向阅读**（第 1 节）；
- **坑二**：只看代码不看文档——**先看地图再逛街**（第 2 节）；
- **坑三**：配置文件只看数据源——**中间件/自定义配置才是项目特色；全看**（第 3 节）；
- **坑四**：不跑起来——**纸上谈兵；亲手运行 + 点接口**（第 6 节）；
- **坑五**：技术栈不认识的硬猜——**先看用法再补原理；问带教最快**（第 7 节）。

## 9. 练习 5 题

1. 五步读项目法是什么？五步各自的产出？
2. README 回答哪三个问题？没有 README 怎么办？
3. 配置文件怎么读？"血管图"类比指什么？
4. 入口的三个价值？启动类与包结构的关系？
5. 跑起来的意义？跑不起来的三个常见原因？

> 🎯 **核心要点**：看懂项目 = **五步定向阅读**——"README（是什么）→ 配置（连了什么）→ 依赖（用了什么）→ 入口（从哪开始）→ 跑起来（亲见）"；**产出三件套：技术栈清单 + 结构地图 + 一次成功运行**。
