## 1. 接口契约：五要素

**接口（API）是模块之间协作的契约**——**调用方与服务方之间的"协议"**。**一个接口契约的五要素**：**路径**（URL：`POST /api/orders`）；**方法**（GET/POST/PUT/DELETE——**语义**：查/增/改/删）；**参数**（入参：路径参数/查询参数/请求体）；**响应**（出参：成功响应的结构）；**错误码**（失败时的约定——**错误怎么表达**）。**契约的三个价值**：**并行开发**（前端按契约开发，后端按契约实现——**不用等**）；**边界清晰**（模块间只认契约，不碰实现——**04 篇模块边界的实现方式**）；**可测试**（契约即测试依据）。**L1 的契约视角**：**落地模块 = 实现一个契约**（08 篇）；**对接模块 = 调用一个契约**（第 6 节）——"**接口是架构的'接缝'：看懂接缝，就懂模块怎么拼**"。

## 2. REST 接口的阅读

**REST 风格是 2026 的接口事实标准**——**阅读 REST 接口的四个要点**：**路径即资源**（`/api/orders` = 订单资源；`/api/orders/{id}` = 某个订单——**路径的层级表达资源归属**）；**方法即操作**（GET 查、POST 增、PUT 全量改、DELETE 删——**PATCH 部分改**）；**状态码即结果**（200 成功/400 参数错/401 未认证/403 无权限/404 不存在/500 服务错——**先看状态码再谈响应体**）；**REST 的边界**（不是所有接口都 REST——**RPC 风格接口也常见**，识别看风格统一性）。**阅读顺序**：**先看方法 + 路径**（"做什么"）→ **再看参数**（"要什么"）→ **最后看响应与错误码**（"得到什么"）——"**REST 接口读法：路径是名词、方法是动词、状态码是标点**"（Web 高阶知识体系 REST 交叉：`../../../../02-后端核心技术 微服务 分布式 云原生/09-Web开发全流程/Web 高阶知识/`）。

## 3. 参数与响应结构

**参数的三种位置**：**路径参数**（`/api/orders/{id}`——**资源定位**）；**查询参数**（`?page=1&size=10`——**过滤/分页**）；**请求体**（JSON Body——**新增/修改的数据**）。**响应的结构**（Java 项目的统一返回约定——**common 包的 Result**，04 篇）：

```json
{
  "code": 0,          // 业务码：0 = 成功
  "message": "success",
  "data": { "orderId": "A1024", "status": "PAID" }
}
```

**读参数与响应的三个重点**：**字段类型与约束**（String/Integer、必填/可选——**Swagger 注解里能看到**）；**数据来源**（入参 → DTO → Entity——**05 篇数据流**）；**分页结构**（page/size/total——**列表接口的通用约定**）。**L1 的注意**：**接口文档（Swagger）里的 example 是"调试默认值"**（Swagger 体系交叉：`../Swagger/00-Swagger总览.md`）——"**读契约先读字段语义，别被 example 误导**"。

## 4. 错误码与异常约定

**错误码是契约的"失败语义"**——**成功时大家都一样，失败时约定决定对接成本**。**错误码的两层**：**HTTP 状态码**（传输层：400/401/500——**框架/网关处理**）；**业务错误码**（业务层：`code` 字段——**业务失败的具体原因**）。**业务错误码的阅读**：**看项目的错误码规范**（common 包的错误码枚举——**错误码字典**）；**看常见码**（0 成功/参数错误/无权限/资源不存在/状态不允许——**每个系统的约定不同，先看枚举再对接**）。**异常约定的三个要素**：**全局异常处理**（GlobalExceptionHandler 把异常转成统一错误响应——**接口不会裸抛 500 堆栈**，04 篇）；**错误信息的用户友好性**（message 给用户看 vs 给开发者看——**日志里留完整错误，响应里给友好信息**）；**错误码文档**（Swagger 的错误响应定义——**契约的一部分**）——"**错误码约定是接口契约里最容易被忽略、对接时最花时间的部分**"。

## 5. 用 Swagger 读接口

**Swagger UI 是接口契约的可视化窗口**（Swagger 体系 11 篇深潜，此处讲 L1 的读法）：**打开 `/swagger-ui.html`（或 `/doc.html` Knife4j）**——**项目所有接口的"活文档"**。**L1 用 Swagger 的三个动作**：**浏览**（按标签找接口——**标签即模块分组**）；**读详情**（点开接口看五要素——**参数/响应/错误码/注解描述**）；**Try it out**（**直接在页面上发真实请求**——**对接前先验证接口行为**——"**Swagger 是接口的'试衣间'：穿上看效果再买（对接）**"）。**Knife4j**（国内增强版）——**离线文档/聚合文档**（多服务接口一个页面看——**微服务场景**，Knife4j 体系交叉：`../Knife4j/00-Knife4j知识体系总览.md`）。**注意**：**生产环境 Swagger 默认关闭**（安全管控——Swagger 体系 08 篇）——"**开发环境 Swagger 随便玩，生产环境要访问先问权限**"。

## 6. 对接一个接口

**对接（集成）一个接口的完整流程**——**L1 落地模块时的高频任务**：**① 读契约**（Swagger/文档看五要素——**路径/方法/参数/响应/错误码**）；**② 造数据**（用 Swagger Try it out 或 Postman 先调通——**验证接口真实行为**）；**③ 写调用代码**（HTTP 客户端：RestTemplate/WebClient/OpenFeign——**按契约构造请求**）；**④ 处理响应**（成功分支 + 错误码分支——**每个错误码都要有处理**）；**⑤ 异常兜底**（网络异常/超时——**调用外部接口必须有超时与重试策略**）。**对接的三个纪律**：**先调通再写代码**（Swagger/Postman 验证过的契约，写代码不会错）；**错误码全处理**（别只处理成功分支——**对接事故大多在错误分支**）；**超时与重试**（外部调用必须有超时，**非幂等操作禁自动重试**，Java 分布式框架体系交叉）——"**对接的秘诀：把契约当法律读，把错误当正常处理**"。

## 7. 五个常见坑

- **坑一**：不看错误码只处理成功——**失败分支是事故高发区；错误码全处理**（第 6 节）；
- **坑二**：把 example 当真实约束——**example 是示例不是规则；读字段语义与约束**（第 3 节）；
- **坑三**：接口调用不设超时——**外部服务挂了你的服务也跟着挂；超时必配**（第 6 节）；
- **坑四**：改了接口不更新文档——**契约失真；改接口同步改 Swagger 注解**（第 5 节）；
- **坑五**：REST 语义乱用——**GET 里做删除、POST 里做查询；方法语义是契约的一部分**（第 2 节）。
