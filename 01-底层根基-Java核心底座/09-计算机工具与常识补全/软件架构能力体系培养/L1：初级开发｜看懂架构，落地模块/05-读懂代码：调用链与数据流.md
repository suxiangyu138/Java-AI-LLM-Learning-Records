## 1. 定向阅读：入口 → 调用链 → 数据流

**读代码的核心方法不是"通读"，是"定向追踪"**——**三个问题驱动阅读**：**入口在哪**（这个方法从哪被调用）；**调用链多长**（一路调了哪些方法）；**数据怎么流**（参数怎么变、结果怎么回）。**一次完整追踪的路径**：**Controller 方法（入口）→ Service（业务）→ Mapper（数据）→ 返回**——**沿着 04 篇的分层结构走**——"**分层结构是调用链的'路标'：知道代码该在哪层，就知道下一步去哪找**"。**追踪的三个技巧**：**先读方法签名**（返回类型/参数——**方法在做什么**）；**再读方法体骨架**（异常处理/分支/事务注解——**流程轮廓**）；**最后读细节**（具体逻辑）——"**读代码像读文章：先标题（签名）→ 段落（骨架）→ 句子（细节）**"。

## 2. 调用链：一次请求的完整路径

**调用链（Call Chain）是"一次请求经过的所有代码"**——**L1 必须会追踪的完整链路**：

```text
HTTP 请求
  → 过滤器/拦截器（鉴权/日志，可跳过）
  → OrderController.createOrder(dto)          # 入口：参数校验
    → OrderService.createOrder(dto)           # 业务：事务/规则
      → OrderMapper.insert(order)             # 数据：SQL
        → MySQL 落库
      → StockService.deductStock(...)         # 跨模块：走 Service（04 篇）
    → 返回 OrderResp
  → 全局异常处理（出错时兜底）
  → HTTP 响应
```

**追踪调用链的三板斧**：**IDE 的"查看调用/被调用"**（Ctrl+Alt+H 看方法被谁调——**往上找入口**；Ctrl+Click 跳实现——**往下找实现**）；**断点堆栈**（第 4 节——**运行时看完整路径**）；**接口文档**（Swagger 的接口定义是调用链的"起点地图"，Swagger 体系交叉：`../Swagger/00-Swagger总览.md`）——"**调用链是架构的'动态视图'：包结构告诉你代码在哪，调用链告诉你请求怎么走**"。

## 3. 数据流：数据怎么变

**数据流（Data Flow）是"数据从入口到落库的变化过程"**——**调用链是"代码路径"，数据流是"数据的变形记"**。**一个典型的数据流**：

```text
前端 JSON → DTO（OrderCreateReq：金额 100，数量 2）
  → 参数校验（金额 > 0）
  → Entity（Order：状态 PENDING）
  → Mapper 落库
  → 返回 DTO（OrderResp：订单号 + 状态）
```

**数据流的三次变形**：**DTO → Entity**（接口入参 → 业务实体——**字段可能增加默认值/状态**）；**Entity → 落库**（ORM 映射——07 篇）；**Entity → DTO**（业务实体 → 接口出参——**敏感字段过滤**）。**追踪数据流的两个重点**：**字段在哪被改**（状态变化/默认值设置——**业务逻辑的隐藏位置**）；**类型在哪转换**（DTO/Entity/VO 的互转——**转换器/MapStruct 等**）——"**看懂数据流 = 知道'数据从哪来、经过谁、变成什么样'——排查'为什么结果不对'全靠它**"。

## 4. 断点调试：运行时真相

**断点调试（Debug）是"运行时真相"的获取方式**——**静态读代码是"猜"，断点看运行是"看"**。**L1 必会的四个调试动作**：**打断点**（方法入口/关键赋值行）；**单步执行**（Step Over 跳过当前方法、Step Into 进入方法——**追踪调用链的利器**）；**查看变量**（Watch 窗口看参数/局部变量变化——**数据流可视化**）；**查看调用堆栈**（Call Stack——**当前执行到哪、怎么来的——调用链的运行时版**）。**调试的三个场景**：**bug 定位**（"结果不对"→ 断点在关键转换处 → 看哪一步数据变了）；**理解逻辑**（新接手的代码读不懂 → 跑一遍看实际流程）；**验证假设**（"我以为这里会走这个分支" → 断点确认）。**注意**：**调试是开发环境的行为，生产环境靠日志**（第 5 节）——"**断点看'现在'，日志看'过去'——两个视角都要会**"。

## 5. 日志定位：历史轨迹

**日志（Logging）是生产环境的"断点"**——**不能打断点的线上问题，靠日志还原现场**。**L1 必会的日志三板斧**：**看日志文件**（应用日志/错误日志——**先看报错堆栈（Exception + 行号）**）；**按关键字搜**（订单号/用户 ID/请求 ID——**追踪一次请求的完整轨迹**——**traceId 全链路追踪是生产标配**，日志监控指标体系交叉：`../../../../02-后端核心技术 微服务 分布式 云原生/07-工程运维基础/运维/日志监控指标/`）；**看日志级别**（ERROR/WARN/INFO——**先看 ERROR，再按时间倒序**）。**日志与断点的分工**：**开发环境断点（详细/可交互）、生产环境日志（无侵入/留痕）**——"**断点是放大镜，日志是行车记录仪——L1 两个都要会用**"。**L1 写日志的纪律**：**关键路径打 INFO**（入参/结果）、**异常打 ERROR**（带上下文——**日志体系交叉**）——"**好日志是未来排障的你写给现在的你的信**"。

## 6. 阅读工具与快捷键

**IDE（IntelliJ IDEA）的读码快捷键**（Java 系）：**Ctrl+Click**（跳定义/实现）；**Ctrl+Alt+B**（跳实现类——**接口到实现**）；**Ctrl+Alt+H**（查看方法调用层级——**调用链追踪**）；**Ctrl+F12**（看类结构——**方法列表**）；**Alt+F7**（查找方法被谁使用——**往上找入口**）；**Ctrl+Shift+F**（全局搜索——**按字符串找代码**）。**非 IDE 场景**：**grep/rg 搜索**（"方法名出现在哪"——**不用 IDE 也能追调用链**）；**git log/blame**（代码历史——**这行代码谁写的、为什么改**，Git 体系交叉：`../../../../02-后端核心技术 微服务 分布式 云原生/05-开发流程工具/Git/`）。**工具心法**：**IDE 快捷键是"读码速度"的杠杆**——**每天多会两个快捷键，一个月后读码速度翻倍**——"**工具熟练度是 L1 的隐性竞争力**"。

## 7. 五个常见坑

- **坑一**：从项目第一个文件通读到最后一个——**必放弃；定向追踪**（第 1 节）；
- **坑二**：只读静态代码不跑——**静态是猜、运行是看；断点跑一遍**（第 4 节）；
- **坑三**：生产问题不查日志凭感觉——**先看 ERROR 堆栈 + traceId 追轨迹**（第 5 节）；
- **坑四**：只追调用链不看数据流——**"代码走到了"不等于"数据对了"；两个视角都要**（第 3 节）；
- **坑五**：调试时 Step Over 一路到底——**错过关键分支；关键行 Step Into 看内部**（第 4 节）。
