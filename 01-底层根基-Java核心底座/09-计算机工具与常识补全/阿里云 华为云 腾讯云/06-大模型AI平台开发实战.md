## 1. 三平台定位与选择

> **背景**：2026 年大模型平台成为云厂商竞争主战场——模型能力、价格、生态三线竞争。
> **目的**：按场景选择正确的 AI 平台。
> **适用范围**：AI 应用开发（RAG/Agent/客服/内容生成）。
> **不适用场景**：自建训练（考虑 GPU 集群而非平台）。

| 平台 | 定位 | 强项 | 适合 |
|------|------|------|------|
| **阿里百炼** | 模型超市 + MaaS | 开源 Qwen 生态、文档全 | 通用 AI 应用 |
| **华为 ModelArts** | 训练/部署平台 | 昇腾算力、私有化 | 政企工业 AI |
| **腾讯 TI** | 智能体平台 | 微信生态、VITA 价格 | C 端智能体 |

```text
2026 选择要点
├── ① 通用应用 → 百炼（模型最全 + 文档最好）
├── ② 多模态性价比 → 腾讯 VITA（竞品 50% 价格）
├── ③ 政企私有化 → ModelArts（数据不出域）
├── ④ C 端智能体 → TI（微信生态）
├── ⑤ 工业视觉 → 盘古（ModelArts）
└── ⑥ 开源可控 → Qwen 开源 + 百炼
```

### 2.1 开通与 API Key

```text

├── qwen-plus：通用业务（均衡）
├── qwen-max：复杂推理（最强）
├── qwen3.5-omni-plus/flash：多模态
└── 开源版：私有化部署（可微调）
```

### 2.2 Java 接入

```xml
<!-- pom.xml 依赖 -->
<dependency>
    <groupId>com.alibaba</groupId>
    <artifactId>dashscope-sdk-java</artifactId>
    <version>2.x</version>
</dependency>
```

```java
// 基础对话
import com.alibaba.dashscope.aigc.generation.Generation;
import com.alibaba.dashscope.aigc.generation.GenerationParam;
import com.alibaba.dashscope.common.Message;
import com.alibaba.dashscope.common.Role;

public class QwenService {
    private static final String API_KEY = System.getenv("DASHSCOPE_API_KEY");

    public String chat(String prompt) {
        Generation gen = new Generation();
        Message msg = Message.builder()
            .role(Role.USER.getValue())
            .content(prompt)
            .build();
        GenerationParam param = GenerationParam.builder()
            .model("qwen-plus")
            .apiKey(API_KEY)
            .messages(java.util.List.of(msg))
            .build();
        return gen.call(param).getOutput().getText();
    }
}

// 流式输出（SSE）
// GenerationParam.builder().incrementalOutput(true)
// → 适合打字机效果（见本仓库 SSE 相关）
```

## 5. RAG 应用开发

### 5.1 平台 vs 自建

```text
RAG 的两种路径
├── ① 平台内置（百炼知识库/TI 知识库）
│   ├── 快速：上传文档 → 自动切片/向量化
│   ├── 适用：标准问答（客服/文档助手）
│   └── 局限：深度定制受限（切片策略/重排）
├── ② 自建（本仓库 RAG 系列）
│   ├── 流程：文档 → 切片 → Embedding → 向量库 → 检索 → 生成
│   ├── 适用：深度定制（多路召回/重排/评估）
│   └── 组件：向量库（云厂商向量服务/开源 Milvus）
└── 选型：快速验证用平台；生产深度定制自建
```

```text
Java 自建 RAG（架构图）

自建 Agent（本仓库 Agent 开发系列）
├── ① 框架：LangChain4j/Spring AI（Java）
├── ② 模式：ReAct/H-V-R/多 Agent
├── ③ 工具：Function Calling/MCP
├── ④ 记忆：Redis + 向量库
├── ⑤ 评估：测试集 + 门禁
└── ⑥ 适用：复杂逻辑/深度定制
```

### 6.2 Java Agent 示例（Spring AI）

```java
// Spring AI + 通义千问（Java Agent 快速开始）
@Configuration
public class AiConfig {
    @Bean
    public ChatClient chatClient(ChatClient.Builder builder) {
        return builder.build();
    }
}

@Service
public class AgentService {
    private final ChatClient chatClient;

    public AgentService(ChatClient chatClient) {
        this.chatClient = chatClient;
    }

    public String ask(String question) {
        return chatClient.prompt()
            .system("你是订单助手，回答要简洁")
            .user(question)
            .call()
            .content();
    }
}
// 模型配置：spring.ai.dashscope.api-key=xxx
// 详见本仓库「06-开发框架-LangChain4j-SpringAI」系列
```

## 7. 大模型成本控制

### 7.1 成本构成（2026）

```text
大模型应用成本构成
├── ① Token 费（最大头）：
│   ├── 输入/输出比例约 1:2 或更高
│   ├── 输出 Token 贵（生成式）
│   └── 模型分级：Turbo vs Max 差数倍
├── ② 基础设施：
│   ├── 向量库读写（RAG 场景）
│   ├── 缓存缺失（重复调用）
│   └── 计算资源（GPU 实例高位）
├── ③ 隐性成本：
│   ├── 跨地域带宽（CEN）
│   └── 并发预留
```

### 7.2 省钱策略

```text
2026 成本优化六招
├── ① 模型分级：简单任务用 Turbo/VITA（成本差数倍）
├── ② 缓存命中：合理缓存可省 60%+ Token
│   ├── 相同问题结果缓存（Redis）
│   ├── 语义缓存（相似问题复用）
│   └── 流式输出优化（减少输出 Token）
├── ③ 提示词优化：精简上下文（Token = 成本）
├── ④ 批量处理：非实时任务批量调用
├── ⑤ 计费理解：输入/输出分开计费（优化输出）
├── ⑥ 长期合约：涨价潮下锁定价格
└── ⑦ 金句：Token 成本 = 输入优化 + 缓存 + 模型分级
```

## 8. 核心要点

> 🎯 **核心要点**：
> 1. 三平台定位：百炼（通用模型超市）/ModelArts（政企私有化）/TI（C 端智能体）
> 2. 百炼实战：DashScope SDK（Java）——qwen 系列按场景分级（turbo/plus/max/omni）
> 3. ModelArts：昇腾算力 + 私有化（数据不出域）——政企交付平台
> 4. TI：微信生态 + VITA 3.0（竞品 50% 价格）——C 端智能体最短路径
> 5. RAG 两种路径：平台内置（快速）vs 自建（深度定制）——见本仓库 RAG 系列
> 6. Agent 两种路径：平台编排（标准流程）vs 自建框架（Spring AI/LangChain4j）
> 7. 成本六招：模型分级 + 缓存命中（省 60%+）+ 提示词精简——2026 涨价潮下更重要
