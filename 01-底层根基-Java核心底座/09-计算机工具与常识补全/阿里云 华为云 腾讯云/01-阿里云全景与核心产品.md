## 1. 阿里云定位与优势

> **背景**：阿里云诞生于 2009 年（阿里内部「去 IOE」运动）——从支撑淘宝天猫走向公有云服务商。
> **目的**：理解阿里云的全能定位与核心优势。
> **适用范围**：电商/互联网/中小企业/AI 研发/出海。
> **不适用场景**：强信创要求（华为云更合适）、微信生态强依赖（腾讯云）。

```text
阿里云的核心优势（2026 评价：国内全能 4.5 分）
├── ① 综合能力最均衡：计算/存储/网络/数据库/AI 无短板
├── ② 中文文档完整度 + SDK 覆盖率 + 社区 = 国内标杆
├── ③ Java 中间件兼容最佳（RDS/Redis/MQ 全家桶）
├── ④ 自研芯片落地：倚天 710 深度融入 RDS 等托管服务（降本）
├── ⑤ AI 生态最丰富：通义千问开源 + 百炼平台
├── ⑥ 稳定性：2025 无跨 AZ 严重事故（秒级十万级 QPS 扩容）
└── ⑦ 出海：东南亚深耕（亚太区入口）

市场份额（2025）
├── 份额从 33% 升至 36%（连续攀升）
├── 阿里云目标：2026 中国 AI 云 80% 新增份额
└── 金句：阿里云 = 「不出错的全能选手」——多数场景的默认选择
```

## 2. 云服务器 ECS

### 2.1 ECS 家族

```text
ECS（Elastic Compute Service）实例族
├── 通用型 g 系列：均衡（Web/应用/微服务）
├── 计算型 c 系列：CPU 密集（批处理/渲染）
├── 内存型 r 系列：内存密集（缓存/数据库）
├── 大数据型 d 系列：本地盘（Hadoop/Spark）
├── 高主频 h 系列：高频计算（游戏/仿真）
├── GPU 型 gn 系列：AI 训练/推理（NVIDIA/倚天）
└── 抢占式实例：低成本（实验/弹性任务）

实例规格（Java 后端常见）
├── 入门：2C4G（轻量应用/个人项目）
├── 常用：4C8G（中小服务/开发测试）
├── 生产：8C16G+（正式服务/集群节点）
└── 选型：CPU 密集选 c 系、内存密集选 r 系、AI 选 GPU 系
```

### 2.2 计费与购买

```text
ECS 计费模式（2026）
├── ① 包年包月：长期稳定（生产首选）——折扣最高
├── ② 按量付费：弹性（测试/突发）——贵但灵活
├── ③ 抢占式实例：极低成本（实验）——⚠️ 可被回收
├── ④ 节省计划/承诺消费：长期合约折扣
├── ⑤ 2026 趋势：GPU 实例高位（芯片紧张）、CPU 微降
└── 组合策略：通用计算（包年）+ 弹性 GPU（按量）

购买流程（Java 开发者视角）
├── ① 选地域（就近原则：华东/华南/华北）
├── ② 选实例族 + 规格
├── ③ 选镜像（CentOS/Ubuntu/Alinux）
├── ④ 配置安全组（端口放行——见端口系列）
├── ⑤ 绑定公网 IP（弹性 IP EIP）
└── ⑥ 建密钥对（SSH 登录——见 SSH 系列）
```

## 3. 自研技术栈：飞天/倚天/神龙

### 3.1 三件套

```text
阿里云自研三件套
├── ① 飞天（Apsara）：云操作系统
│   ├── 管理全球数据中心资源
│   ├── 弹性调度/容灾/安全
│   └── 支撑「双 11」级流量（稳定性验证）
├── ② 倚天 710：自研 ARM 服务器芯片
│   ├── 深度融入 RDS 等托管服务（降本）
│   ├── 性价比优于同规格 x86（特定负载）
│   └── 国产芯片大规模训练可节省约 30% 算力开支
└── ③ 神龙架构：虚拟化方案
    ├── 裸金属性能 + 虚拟化弹性
    ├── 网络/存储/计算分离
    └── 低延迟（网络性能接近物理机）

对 Java 开发者的意义
├── 倚天实例：成本优化选项（兼容 ARM 的 Java 应用）
├── 神龙网络：低延迟（微服务性能）
└── 选择：默认 x86 通用实例；成本敏感评估倚天
```

## 4. 数据库与中间件

### 4.1 数据库家族

| 产品 | 类型 | 特点 |
|------|------|------|
| **PolarDB** | 云原生数据库 | 自研、TPC-C/TPC-H 认证、兼容 MySQL/PG |
| **RDS MySQL** | 托管 MySQL | 全托管（备份/高可用/监控） |
| **RDS PostgreSQL** | 托管 PG | 功能全面 |
| **Tair** | 云 Redis | 兼容 Redis 协议 + 企业特性 |
| **Lindorm** | 多模数据库 | 宽表/时序/向量 |
| **AnalyticDB** | 分析型 | 实时分析/ADB |

```text
Java 后端数据库选型
├── 新项目 → PolarDB（云原生、性能强）或 RDS MySQL
├── 缓存 → Tair（Redis 兼容——无缝迁移）
├── 搜索 → Elasticsearch（阿里云 ES 服务）
├── 向量检索 → Lindorm 向量引擎（RAG 场景）
└── 消息 → 云消息队列（RocketMQ/Kafka 托管）

托管服务的价值（对比自建）
├── 高可用（主备/跨 AZ）
├── 自动备份/恢复
├── 监控告警（内置）
├── 弹性扩缩容
└── 金句：托管 = 用成本换运维时间——生产推荐托管
```

## 5. 百炼大模型平台

### 5.1 平台定位

> **背景**：百炼（Model Studio）是阿里云的一站式大模型平台——模型超市 + MaaS + 应用开发。
> **目的**：企业快速接入大模型（无需自建训练）。
> **适用范围**：AI 应用开发（RAG/Agent/客服/内容生成）。
> **不适用场景**：需要私有化训练的政企（华为 ModelArts 更合适）。

```text
百炼平台能力
├── ① 模型超市：通义千问全系列 + 第三方模型
├── ② MaaS：API 调用（OpenAI 兼容）
├── ③ 知识库：RAG 一站式（文档接入/向量化）
├── ④ 智能体：Agent 编排（工具调用/多轮）
├── ⑤ 微调：LoRA/全参微调（开源模型）
├── ⑥ 评测：模型对比/效果评估
└── ⑦ 应用部署：API 网关/监控

适用场景（2026）
├── 电商（淘宝/天猫生态无缝对接）
├── 客服/知识库问答
├── 内容生成/营销
├── Agent 应用（多工具编排）
└── 出海（东南亚模型支持）
```

### 5.2 API 接入（Java）

```java
// 百炼 API 接入（OpenAI 兼容协议）
// 依赖：dashscope-sdk-java
import com.alibaba.dashscope.aigc.generation.Generation;
import com.alibaba.dashscope.aigc.generation.GenerationParam;

public class QwenChat {
    public static void main(String[] args) {
        Generation gen = new Generation();
        GenerationParam param = GenerationParam.builder()
            .model("qwen-plus")                    // 模型名
            .apiKey(System.getenv("DASHSCOPE_API_KEY"))
            .prompt("你好，介绍一下自己")
            .build();
        // 调用并输出
        System.out.println(gen.call(param).getOutput().getText());
    }
}
```
