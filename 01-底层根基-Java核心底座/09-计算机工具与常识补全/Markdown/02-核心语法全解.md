## 1. 块级语法全解

块级元素以「行」为单位组织文档骨架。CommonMark 规定：一行内容归属哪个块，由**起始标记 + 缩进 + 空行**三者共同决定，而不是靠「看起来像」。

### 1.1 标题

ATX 标题用 1-6 个 `#` 开头，**`#` 后必须有空格**（否则是普通文本）：

```text
# 一级标题
## 二级标题
### 三级标题
```

尾部 `#` 可省略，写 `## 标题 ##` 时尾部 # 会被剥掉。Setext 标题用下划线形式，只支持两级：

```text
一级标题
========

二级标题
--------
```

实践中统一用 ATX——Setext 的 `---` 与分隔线、YAML frontmatter 存在歧义风险，不推荐。

### 1.2 段落与换行

段落由空行分隔。**单个换行在 CommonMark 里不产生 `<br>`**（这是与很多人直觉相反的第一条规则）。需要强制换行时三种写法：

- 行尾两个及以上空格（原始语法，编辑器不可见，易丢失）
- 行尾反斜杠 `\`（可见，推荐）
- 段内插入 `<br>`（万能但破坏纯文本可读性）

### 1.3 引用块

`>` 开头构成引用，支持嵌套与惰性延续：

```text
> 第一层引用
> > 嵌套引用
> 继续第一层
```

「惰性延续」指段落中途没写 `>` 也会被并入引用——这是规范明确允许的行为，跨平台一致。

### 1.4 列表

无序列表用 `-`、`*`、`+`（功能等价，同一列表内混用会产生新列表）；有序列表用 `1.` `2.` 等数字加点，**起始数字决定 `<ol start>`**。

列表有两条核心规则：

1. **紧凑 vs 松散**：列表项之间无空行为紧凑（`<li>` 内不加 `<p>`），有空行为松散（每项包 `<p>`）——这个差异直接影响最终 HTML 结构与样式
2. **缩进决定归属**：子内容缩进量取决于标记宽度（`- ` 是 2 格，`1. ` 是 3 格），缩进足够的行归入当前项，不足则结束列表

```text
- 第一项
  - 子项（缩进 2 格，属于上一项）
- 第二项

1. 有序项一
   - 子项（缩进 3 格，对齐 "1. " 宽度）
```

### 1.5 代码块

两种形式，行为完全不同：

- **缩进式**：4 空格或 1 个 Tab 缩进，无语言标注能力，内部无法再嵌列表
- **围栏式**：` ``` ` 或 `~~~` 包裹，可标注语言（信息字符串），是工程事实标准

围栏长度必须大于内部出现的反引号串：内容含 ` ``` ` 时外层用四个反引号。围栏内**一切原样保留**，无需转义——这是展示 Markdown 语法的唯一正确方式。

### 1.6 分隔线与块级嵌套

分隔线由三个及以上 `-`、`*` 或 `_` 独占一行构成，前后需空行。它的两个歧义陷阱：紧跟段落下方出现 `---` 时，若上一行是普通文本会被解析为 Setext 二级标题而非分隔线；文件顶部 `---` 则可能被解析为 YAML frontmatter 或被直接忽略。**规避方式统一且简单：分隔线前后各留一个空行，且不与标题紧邻。**

块级元素可以互相嵌套，组合能力是 Markdown 表达力的来源：

| 组合 | 写法要点 | 典型用途 |
|------|---------|---------|
| 列表 + 引用 | 子内容缩进对齐，`>` 前留缩进 | 任务清单含说明块 |
| 引用 + 代码块 | 围栏前缀 `> ` | 引用一段配置示例 |
| 列表 + 代码块 | 围栏缩进到列表内容位置 | 分步操作的命令 |
| 表格 + 行内语法 | 单元格支持强调/代码/链接 | API 速查表 |

嵌套的通用判据还是那条底层规则：**行首标记 + 足够缩进 = 归属内层；缩进不足 = 归属外层**。列表内的代码块因此必须缩进到「列表标记宽度 + 4」或使用围栏式并整体缩进对齐——这是「列表里代码块总是写不对」的完整答案。

## 2. 行内语法全解

### 2.1 强调的边界规则

`*` 与 `_` 生成 `<em>`，`**` 与 `__` 生成 `<strong>`。但左右相邻字符决定标记是否生效，这条规则叫 **delimiter run（分隔符串）判定**：

| 写法 | 结果 | 原因 |
|------|------|------|
| `*强调*` | 强调 | 两侧边界合规 |
| `_emphasis_` | 强调 | 同上 |
| `snake_case_name` | 原样 | `_` 词内（左右皆为字母数字）不触发，保护标识符 |
| `*snake_case*` | 强调 | `*` 无此限制 |
| `中*文*强调` | 强调 | 中文视为普通字符 |

推论：**代码命名场景优先用 `*`**；要强调含下划线的词时 `_` 会失效，必须换 `*`。

### 2.2 行内代码

单个反引号包裹；内容含反引号时用更多反引号包裹并加空格边界：

```text
`` code with ` backtick ``
```

行内代码内**不做任何 Markdown 解析、不需 HTML 转义**，是行内展示特殊字符的标准手段。

### 2.3 删除线（GFM）

`~~text~~` → `<del>text</del>`，属 GFM 扩展，CommonMark 原生不支持。

## 3. 链接与图片体系

链接有三种形态，各有适用场景：

| 形态 | 语法 | 适用场景 |
|------|------|---------|
| 行内式 | `[文字](url "标题")` | 默认选择，直观 |
| 引用式 | `[文字][ref]` + `[ref]: url` | 同一链接多处引用，正文更干净 |
| 自动链接 | `<https://example.com>` | 裸 URL；GFM 中直接写裸链接也生效 |

引用式定义可集中放在文档尾部，长文档中能显著降低正文噪声——本仓库的「参考来源」章节即典型用法。

图片语法为 `![替代文本](url)`，是链接语法的前缀 `!` 变体。要点：

- **替代文本是必写项而非装饰**：无障碍阅读、图片加载失败、AI 解析全靠它
- **本地图片路径**：相对路径基于当前文件；路径含空格时必须写成 `%20`（`./图 1.png` → `./图%201.png`），否则多数渲染器断链
- 图片加链接的标准写法：外层方括号包住整个图片语法

## 4. 转义与 HTML 混写

Markdown 可转义的字符集是**明确的 12 个 ASCII 标点**：

```text
\  `  *  _  {  }  [  ]  (  )  #  +  -  .  !  |  >  ~
```

（`|`、`~` 为 GFM 扩展可转义字符。）转义其他字符（如 `\d`）反斜杠会原样输出——这是「反斜杠消失」问题的根因。

HTML 混写分两层：

- **行内 HTML**：`<span>`、`<kbd>`、`<br>` 等直接写，原始输出
- **块级 HTML**：整块 `<div>` 内容原样透传，内部 Markdown 默认不再解析（块级 HTML 内的空行决定是否恢复解析）

> **安全提醒**：GitHub 通过 tagfilter 转义 9 个危险标签（`<script>`、`<iframe>`、`<style>` 等），但这只是平台级防护。自建渲染管线必须做 sanitize（如 DOMPurify），详见第 04 篇。

## 5. 高频陷阱与边界行为

| 现象 | 根因 | 正确姿势 |
|------|------|---------|
| `#hashtag` 渲染成标题 | 忘了 `#` 后空格 | 补空格或用转义 |
| 列表后代码块「缩进不够」失效 | 代码块相对列表需 4+ 标记宽度的缩进 | 围栏式替代缩进式 |
| 4 空格缩进意外变代码块 | 缩进式代码块规则触发 | 全文统一缩进 2 格 + 围栏代码块 |
| 表格不渲染 | 表格前缺空行，或分隔行没写 | 表格前后留空行，第二行写 `---` |
| `1.` `2.` 全改成 `1.` 也不影响 | 有序列表数字不参与渲染，只认起始值 | 想表达「第几步」时别依赖数字渲染 |
| 中文行内代码后紧跟文字粘连 | 中英混排缺空格 | 代码 span 两侧留空格 |
| `**加粗**文` 变成全加粗 | 强调边界吃掉了后续内容 | 明确闭合标记位置，必要时转义 |

---

> **核心要点**：块级看「起始标记 + 缩进 + 空行」，行内看「边界字符判定」。两条底层规则一旦建立，九成「玄学渲染」都能自行解释——不理解的现象，先问：这是块级问题还是行内问题？
