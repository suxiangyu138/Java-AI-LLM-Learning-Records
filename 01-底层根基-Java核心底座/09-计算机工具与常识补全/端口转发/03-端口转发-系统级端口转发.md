## 1. 系统级方案全景

> **背景**：SSH 隧道适合临时与加密场景；系统级转发（内核态/守护进程）适合长期与高性能场景。
> **目的**：让端口转发「常驻、高性能、可管理」——不依赖交互式连接。
> **适用范围**：生产环境端口映射、网关/路由器转发、UDP 转发、多端口批量转发。
> **不适用场景**：临时调试（SSH 更快）、需要应用层逻辑（用 Nginx 反向代理）。

| 工具 | 层级 | 性能 | 复杂度 | 适用 |
|------|:---:|:---:|:---:|------|
| **iptables** | 内核 NAT | ⭐⭐⭐⭐⭐ | 中 | 网关/高性能/UDP |
| **nftables** | 内核 NAT | ⭐⭐⭐⭐⭐ | 中 | 现代发行版（RHEL9+/Ubuntu22+） |
| **firewalld** | 封装层 | ⭐⭐⭐⭐ | 低 | RHEL/CentOS 管理 |
| **socat** | 用户态 | ⭐⭐⭐ | 低 | 复杂协议/调试/UDP |
| **Nginx stream** | 应用层 | ⭐⭐⭐⭐ | 中 | HTTP 生态/负载均衡 |
| **rinetd** | 用户态 | ⭐⭐⭐ | 极低 | 简单 TCP 批量转发 |

## 2. iptables NAT 转发

### 2.1 同机器端口转发（80 → 8080）

```bash
# ===== 同机器端口转发 =====
# 开启内核转发（转发的前提）
echo 1 | sudo tee /proc/sys/net/ipv4/ip_forward

# 本机重定向（REDIRECT：同机器端口互转）
sudo iptables -t nat -A PREROUTING -p tcp --dport 80 -j REDIRECT --to-port 8080

# 或者（本机访问也生效的写法）
sudo iptables -t nat -A OUTPUT -p tcp --dport 80 -j REDIRECT --to-port 8080
# PREROUTING 只管外部来的流量；本机自己访问 80 要走 OUTPUT 链
```

### 2.2 跨机器转发（公网 → 内网，核心场景）

```bash
# ===== 跨机器转发：公网 8080 → 内网 192.168.1.100:80 =====

# ① 开启内核转发（永久生效写 /etc/sysctl.conf）
echo 1 | sudo tee /proc/sys/net/ipv4/ip_forward
echo 'net.ipv4.ip_forward = 1' | sudo tee -a /etc/sysctl.conf

# ② DNAT：改目的地址（PREROUTING，流量进来时）
sudo iptables -t nat -A PREROUTING \
    -d 203.0.113.10 -p tcp --dport 8080 \
    -j DNAT --to-destination 192.168.1.100:80

# ③ FORWARD 放行（默认拒绝转发！必须显式允许）
sudo iptables -A FORWARD -p tcp -d 192.168.1.100 --dport 80 -j ACCEPT

# ④ SNAT：改源地址（POSTROUTING，回程路径）
# 静态公网 IP 用 SNAT
sudo iptables -t nat -A POSTROUTING -p tcp -d 192.168.1.100 --dport 80 \
    -j SNAT --to-source 203.0.113.10
# 动态 IP（宽带拨号）用 MASQUERADE（自动取当前出口 IP）
sudo iptables -t nat -A POSTROUTING -s 192.168.1.0/24 -j MASQUERADE
```

### 2.3 持久化与清理

```bash
# 保存规则
# Debian/Ubuntu
sudo apt install iptables-persistent
sudo netfilter-persistent save        # 保存到 /etc/iptables/rules.v4

# RHEL/CentOS 7
sudo service iptables save            # 保存到 /etc/sysconfig/iptables

# 查看与清理
sudo iptables -t nat -L -n -v         # 查看 NAT 规则
sudo iptables -t nat -D PREROUTING 1  # 删除第 1 条
sudo iptables -t nat -F               # 清空 NAT 表（⚠️ 小心！）
```

### 2.4 性能优化（高并发场景）

```text
iptables 转发性能优化
├── ① conntrack 表容量（默认几万，高并发不够）
│   sysctl -w net.netfilter.nf_conntrack_max=1000000
├── ② conntrack 超时（缩短无效连接占用）
│   sysctl -w net.netfilter.nf_conntrack_tcp_timeout_established=600
├── ③ 实测案例：调优后 QPS 12k → 35k，延迟 -60%
└── ④ 注意：性能瓶颈通常在 conntrack 而非规则匹配
```

> ⚠️ **iptables 三要素复盘**（见 01 篇）：**ip_forward=1 + DNAT + FORWARD 放行/SNAT**——缺一流量不通，这是跨机器转发最经典的故障。

## 3. nftables：现代替代

### 3.1 为什么用 nftables

> **背景**：nftables 是 iptables 的现代替代（Linux 3.13+），RHEL 9 / Ubuntu 22.04+ 默认防火墙后端。
> **目的**：统一语法、性能更好、可编程（脚本友好）。
> **适用范围**：新部署的现代发行版。
> **不适用场景**：存量 iptables 脚本环境（迁移成本）。

```bash
# nftables 同机器转发（80 → 8080）
sudo nft add table nat                                # 建表
sudo nft add chain nat prerouting { type nat hook prerouting priority 0; }
sudo nft add rule nat prerouting tcp dport 80 redirect to :8080

# nftables 跨机器转发（公网 8080 → 内网 100:80）
sudo nft add table ip nat
sudo nft add chain ip nat prerouting { type nat hook prerouting priority 0; }
sudo nft add rule ip nat prerouting \
    ip daddr 203.0.113.10 tcp dport 8080 \
    dnat to 192.168.1.100:80
```

### 3.2 查看与持久化

```bash
sudo nft list ruleset              # 查看全部规则
sudo nft flush table nat           # 清空（⚠️ 小心）
# 持久化
sudo nft list ruleset > /etc/nftables.conf   # RHEL
# Debian/Ubuntu：nftables.service 自动加载
```

### 3.3 iptables vs nftables 对比

| 维度 | iptables | nftables |
|------|:---:|:---:|
| 语法 | 命令行参数式 | 统一规则语言 |
| 性能 | 好 | 更好（新内核） |
| 脚本友好 | 一般 | 好（nft 脚本文件） |
| 生态 | 教程多 | 逐渐成为主流 |
| 2026 选择 | 存量环境 | **新部署优先** |

## 4. firewalld 封装层

### 4.1 firewalld 端口转发（最简）

```bash
# RHEL/CentOS/Fedora 的防火墙管理工具（底层仍是 nftables/iptables）

# 开启端口转发（80 → 本机 8080）
sudo firewall-cmd --add-forward-port=port=80:proto=tcp:toport=8080

# 转发到其他机器（80 → 192.168.1.100:80）
sudo firewall-cmd --add-forward-port=\
    port=80:proto=tcp:toaddr=192.168.1.100:toport=80

# 永久生效（--permanent 参数）
sudo firewall-cmd --permanent --add-forward-port=\
    port=80:proto=tcp:toport=8080
sudo firewall-cmd --reload

# 查看/删除
sudo firewall-cmd --list-forward-ports
sudo firewall-cmd --remove-forward-port=port=80:proto=tcp:toport=8080
```

### 4.2 firewalld 的隐藏依赖

> ⚠️ **firewalld 转发前的两个前置**（很多人漏配）：

```bash
# ① 开启 IP 转发（firewalld 不做这个）
echo 1 | sudo tee /proc/sys/net/ipv4/ip_forward
echo 'net.ipv4.ip_forward = 1' | sudo tee -a /etc/sysctl.conf

# ② 目标端口所在的 zone 要允许（否则流量被防火墙拦）
sudo firewall-cmd --zone=public --add-port=8080/tcp --permanent
sudo firewall-cmd --reload

# ③ 如果是跨机器转发，还需要 masquerade（伪装）
sudo firewall-cmd --zone=public --add-masquerade --permanent
sudo firewall-cmd --reload
```

### 4.3 firewalld vs 直接 iptables

| 维度 | firewalld | 直接 iptables |
|------|:---:|:---:|
| 上手 | 低（命令友好） | 中（链/表概念） |
| 持久化 | 内置（--permanent） | 手动（save 工具） |
| 粒度 | 封装（部分受限） | 全量 |
| 适用 | RHEL 系管理 | 深度定制/脚本 |

## 5. socat：万能中继

### 5.1 定位

> 🎯 **socat（SOcket CAT）**：网络工具瑞士军刀——TCP/UDP/Unix Socket/SSL 任意互转，调试与复杂协议场景的首选。

### 5.2 核心用法

```bash
# ① 基本 TCP 转发（监听 8080 → 转发到内网 80）
socat TCP-LISTEN:8080,fork TCP:192.168.1.100:80
# fork：每个连接独立处理（支持并发）

# ② UDP 转发（DNS 场景：本地 53 → 8.8.8.8:53）
socat UDP4-LISTEN:53,fork UDP4:8.8.8.8:53

# ③ Unix Socket → TCP（容器/服务间通信）
socat TCP-LISTEN:8080,fork UNIX-CONNECT:/var/run/app.sock

# ④ TCP → Unix Socket（反向）
socat UNIX-LISTEN:/tmp/test.sock,fork TCP:127.0.0.1:8080

# ⑤ 后台运行 + 日志
nohup socat TCP-LISTEN:8080,fork TCP:192.168.1.100:80 \
    > /var/log/socat.log 2>&1 &

# ⑥ systemd 托管（长期运行）
# 同 SSH 隧道模式（ExecStart 换成 socat 命令）
```

### 5.3 socat 的边界

```text
socat 的取舍
├── ✅ 优点：TCP/UDP/Unix Socket 全支持、fork 并发、调试友好
├── ❌ 缺点：用户态（性能低于内核 NAT）、无内置负载均衡
├── ⚠️ 注意：大流量转发优先 iptables（内核态）
└── ✅ 最佳场景：UDP 转发、Unix Socket 桥接、快速原型
```

## 6. Nginx stream：四层代理

### 6.1 定位

> **背景**：Nginx 不只做 HTTP 反向代理——`stream` 模块提供 TCP/UDP 四层转发。
> **目的**：在 Nginx 生态内统一管理四层与七层转发，支持负载均衡。
> **适用范围**：已有 Nginx 的环境、需要 TCP 负载均衡的场景。
> **不适用场景**：无 Nginx 的纯转发（iptables 更轻）。

```nginx
# /etc/nginx/nginx.conf（stream 块，与 http 平级）
stream {
    # TCP 转发 + 负载均衡（多个后端）
    upstream backend_8080 {
        server 192.168.1.100:8080;
        server 192.168.1.101:8080;
    }
    server {
        listen 80;
        proxy_pass backend_8080;
    }

    # 简单 TCP 转发
    server {
        listen 3306;
        proxy_pass 192.168.1.100:3306;   # MySQL 转发
    }

    # UDP 转发（DNS）
    server {
        listen 53 udp;
        proxy_pass 8.8.8.8:53;
    }

    # 带超时与缓冲控制
    server {
        listen 443;
        proxy_pass 192.168.1.100:443;
        proxy_timeout 60s;
        proxy_connect_timeout 5s;
    }
}
```

### 6.2 Nginx stream vs iptables

| 维度 | Nginx stream | iptables |
|------|:---:|:---:|
| 层级 | 应用层（用户态） | 内核态 |
| 负载均衡 | ✅ 原生支持 | ❌（需额外方案） |
| 日志/监控 | ✅ access_log | ⚠️ 有限 |
| 性能 | 好（高并发优化好） | 最好 |
| 适用 | HTTP 生态 + 均衡 | 纯转发/高性能 |

## 7. rinetd：极简 TCP 转发

```bash
# rinetd：极简 TCP 转发（配置文件驱动，适合批量端口映射）

# 安装
sudo apt install rinetd    # Debian/Ubuntu
sudo yum install rinetd    # RHEL/CentOS

# /etc/rinetd.conf 配置（bindaddress bindport connectaddress connectport）
0.0.0.0 8080 192.168.1.100 80
0.0.0.0 3306 192.168.1.101 3306

# 启动
sudo systemctl enable --now rinetd

# ⚠️ 限制：仅 TCP；无负载均衡；用户态
# 适用：几十条简单 TCP 转发规则的场景
```

## 8. 方案选型与权衡

### 8.1 选型决策表

```text
系统级转发选型
├── RHEL/CentOS + 简单转发 → firewalld（命令最友好）
├── 高性能/网关/UDP → iptables 或 nftables（内核态）
├── 现代发行版新部署 → nftables（未来主流）
├── 复杂协议/Unix Socket/快速原型 → socat
├── 已有 Nginx + 需要负载均衡 → Nginx stream
├── 批量简单 TCP 规则 → rinetd（配置文件驱动）
└── 综合决策：性能需求 × 环境 × 运维习惯
```

### 8.2 权衡要点

| 决策点 | 权衡 | 建议 |
|--------|------|------|
| 性能 vs 灵活 | 内核快但规则复杂；socat 灵活但慢 | 大流量走内核 |
| 管理方式 | firewalld 友好但封装；iptables 原始但全面 | 按团队习惯 |
| UDP 需求 | SSH 不行；iptables/socat/Nginx stream 行 | UDP 场景先排除 SSH |
| 持久化 | firewalld 内置；iptables 需 save 工具 | 别忘持久化（重启丢规则） |
| 负载均衡 | Nginx stream 原生；其他需组合 | 有均衡需求选 Nginx |

## 9. 核心要点

> 🎯 **核心要点**：
> 1. 系统级六工具：iptables（内核高性能）/nftables（现代替代）/firewalld（封装）/socat（万能）/Nginx stream（四层+均衡）/rinetd（极简）
> 2. iptables 跨机器三要素：**ip_forward=1 + DNAT + FORWARD 放行/SNAT**——缺一流量不通
> 3. firewalld 转发前三个隐藏前置：ip_forward、目标端口 zone 放行、跨机器需 masquerade
> 4. socat 是 UDP/Unix Socket 场景的首选（SSH 不支持 UDP）
> 5. 持久化是高频遗漏：iptables save / firewalld --permanent / nftables.conf——重启丢规则 = 生产事故
