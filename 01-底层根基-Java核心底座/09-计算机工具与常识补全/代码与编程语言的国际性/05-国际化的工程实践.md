## 1. 国际化的工程全景

> **背景**：国际化（i18n = Internationalization，18 个字母）是「让产品支持多语言」的工程体系——翻译只是其中一环。
> **目的**：文本/日期/数字/时区/货币全部随 Locale 变化。
> **适用范围**：多语言产品（Web/移动/桌面）。
> **不适用场景**：单一语言内部工具（过度设计）。

```text
国际化（i18n）vs 本地化（L10n）
├── 国际化（i18n）：让产品「支持」多语言的能力（架构层）
│   ├── 文本外部化（不硬编码）
│   ├── Locale 感知的格式化
│   └── 字符编码统一
├── 本地化（L10n）：为「具体地区」提供内容（内容层）
│   ├── 翻译文本
│   ├── 本地习惯（日期/货币/单位）
│   └── 文化适配（颜色/图标/禁忌）
└── 工程顺序：先 i18n（架构）→ 后 L10n（内容）

国际化的五大维度
├── ① 文本：资源文件（不硬编码字符串）
├── ② 数字：千分位/小数点/货币符号
├── ③ 日期时间：格式/时区/日历
├── ④ 排序：语言规则（拼音/字母序）
├── ⑤ 布局：文字方向（LTR/RTL）/长度膨胀
```

## 2. Locale 体系

### 2.1 Locale 的结构

> **背景**：Locale（语言环境）= 语言 + 地区（+ 变体）——决定格式化与资源选择。
> **目的**：用标准标识描述「语言 + 地区」组合。
> **适用范围**：所有国际化 API 的输入参数。
> **前提假设**：Locale 标识遵循 BCP 47 标准。

```text
Locale 标识（BCP 47）
├── 格式：语言_地区（或语言-地区）
├── 示例：zh_CN（简体中文-中国）
│         zh_TW（繁体中文-台湾）
│         en_US（美式英语）
│         en_GB（英式英语）
├── 语言代码：ISO 639（zh/en/ja/ko）
├── 地区代码：ISO 3166（CN/US/JP）
└── ⚠️ 语言 ≠ 地区：zh_CN 与 zh_TW 格式不同（简体/繁体）

Java Locale
├── Locale.SIMPLIFIED_CHINESE（zh_CN）
├── Locale.TRADITIONAL_CHINESE（zh_TW）
├── Locale.US / Locale.UK
├── Locale.forLanguageTag("zh-CN")（BCP 47）
└── 默认：Locale.getDefault()（⚠️ 不依赖——显式指定！）
```

### 2.2 Locale 的工程原则

```text
Locale 工程三原则
├── ① 显式指定：所有格式化 API 传 Locale（不依赖默认）
│   → 服务器默认 Locale 变化 = 输出变化（事故源！）
├── ② 用户 Locale 贯穿：请求 → 业务 → 响应全程携带
│   → HTTP：Accept-Language 头 → 服务端读取
├── ③ 存储用标准格式：内部统一（如 ISO 日期）→ 展示时格式化
└── 金句：Locale 是「贯穿请求的上下文」——不是启动时定死的全局
```

## 3. 资源文件管理

### 3.1 资源文件体系（Java ResourceBundle）

```text
资源文件命名（Java 标准）
├── messages.properties          （默认——英文）
├── messages_zh_CN.properties   （简体中文）
├── messages_zh_TW.properties   （繁体中文）
├── messages_ja.properties      （日文）
└── 规则：basename + _语言[_地区] + .properties

加载顺序（Locale 匹配）
├── messages_zh_CN → messages_zh → messages（逐级回退）
├── 找不到 key → 抛 MissingResourceException
└── 最佳实践：默认文件必须有完整 key（兜底）
```

### 3.2 资源文件格式与陷阱

```properties
# messages_zh_CN.properties（UTF-8）
welcome=欢迎，{0}！
order.total=订单总额：{0} 元
error.timeout=操作超时，请重试
# ⚠️ Java properties 默认 ISO-8859-1——中文需转 \uXXXX 或读 UTF-8！

# 正确做法（UTF-8 资源文件）
# ① 编译器参数：-encoding UTF-8（Maven/Gradle 配置）
# ② 或 properties 文件存 \u 转义
welcome=欢迎，{0}！

# 占位符（参数化消息）
# 代码：MessageFormat.format(bundle.getString("welcome"), userName)
```

```text
资源文件管理的工程要点
├── ① 文案不硬编码：所有用户可见文本走资源文件
├── ② 占位符代替拼接：{0}/{1}（翻译顺序可能变！）
├── ③ 翻译完整性检查：key 数量对比（工具/CI）
├── ④ 变量占位符一致：代码与资源文件的 {0} 对应
├── ⑤ 文化差异注意：
│   ├── 文案长度膨胀（德文比英文长 30%+）
│   ├── 图标/符号差异（✅ 非全球通用）
│   └── 占位符顺序（"您有 {0} 条消息" vs "You have {0} messages"）
└── ⑥ 翻译管理：外部化（PoEditor/Crowdin）或自建
```

## 4. Java 国际化实战

### 4.1 完整示例

```java
// 1. 获取用户 Locale（HTTP 请求）
@RestController
public class GreetingController {
    @GetMapping("/greet")
    public String greet(@RequestHeader(name = "Accept-Language",
                         defaultValue = "zh-CN") String lang) {
        Locale locale = Locale.forLanguageTag(lang);
        return MessageFormat.format(
            bundle(locale).getString("welcome"), "用户");
    }

    private ResourceBundle bundle(Locale locale) {
        return ResourceBundle.getBundle("messages", locale);
    }
}

// 2. 格式化（Locale 感知）
public String formatPrice(BigDecimal amount, Locale locale) {
    NumberFormat nf = NumberFormat.getCurrencyInstance(locale);
    return nf.format(amount);   // ¥1,234.50 / $1,234.50
}

// 3. 日期（ISO 存储 + Locale 展示）
public String displayDate(LocalDate date, Locale locale) {
    DateTimeFormatter fmt = DateTimeFormatter.ofPattern(
        "yyyy年M月d日", locale);   // 或 DateTimeFormatter.ofLocalizedDate
    return date.format(fmt);
}
```

### 4.2 Spring Boot 国际化配置

```yaml
# application.yml（Spring Boot i18n）
spring:
  messages:
    basename: messages        # 资源文件前缀
    encoding: UTF-8           # 编码（关键！）
    cache-duration: 3600
```

```java
// MessageSource 自动注入
@Autowired
private MessageSource messageSource;

public String getMessage(String key, Locale locale, Object... args) {
    return messageSource.getMessage(key, args, locale);
}
// 请求中获取 Locale：LocaleContextHolder.getLocale()
```

## 5. 时区与货币处理

### 5.1 时区的最佳实践

```text
时区处理原则（2026 标准）
├── ① 存储统一 UTC：数据库/接口全部 UTC（ISO 8601）
├── ② 展示时转换：按用户时区格式化
├── ③ 用户时区：请求携带（或前端传偏移）
├── ④ ⚠️ 绝不存储本地时间（无时区信息 = 歧义）
├── ⑤ 夏令时（DST）：依赖时区库（ZoneId 自动处理）
└── ⑥ 数据库：TIMESTAMP WITH TIME ZONE

Java 时区实战
Instant now = Instant.now();               // UTC 时刻
ZonedDateTime user = now.atZone(ZoneId.of("Asia/Shanghai"));
// 展示：DateTimeFormatter.withZone(ZoneId)
// 时区获取：请求头 X-Timezone 或前端传偏移
```

### 5.2 货币处理

```text
货币的国际差异（容易踩坑）
├── ① 符号位置：$1,234（美国）vs 1.234 €（欧洲）
├── ② 千分位：1,234,567（美国）vs 1.234.567（欧洲）
├── ③ 小数：¥ 通常无小数 / $ 两位小数 / 科威特第纳尔三位
├── ④ 三位代码：CNY/USD/EUR（接口用代码不用符号！）
└── ⑤ 金额计算：BigDecimal + 货币（05 篇同）

Java 货币
NumberFormat.getCurrencyInstance(locale).format(amount);
// 或 java.util.Currency.getInstance("CNY")
// ⚠️ 接口传输：用 ISO 4217 代码（CNY/USD）而非符号
```

## 6. 前端国际化配合

### 6.1 前后端职责划分

```text
前后端 i18n 分工（2026 推荐）
├── 前端（展示层）：
│   ├── 界面文案（i18n 库：i18next/vue-i18n）
│   ├── 本地格式化（Intl API）
│   └── 语言切换（无刷新）
├── 后端（数据层）：
│   ├── 业务文案（错误消息/邮件/通知）
│   ├── 数据格式化（金额/日期存储）
│   └── Accept-Language 处理
└── 原则：展示用前端 i18n、数据/服务端消息用后端 i18n
```

### 6.2 关键配合点

```text
前后端 i18n 配合要点
├── ① Accept-Language：浏览器自动发送 → 后端读取
├── ② 接口错误消息：返回「错误码」而非文案
│   ├── 前端根据错误码本地化显示
│   └── 后端不返回翻译文本（避免双语言维护）
├── ③ 日期传输：ISO 8601 字符串（含时区）
├── ④ 金额传输：数值 + ISO 4217 货币代码
├── ⑤ 语言切换：前端切换 → 刷新或局部更新
└── ⑥ 字体：中文/日文/韩文需要字体栈（font-family 回退）
```

## 7. 国际化质量保障

### 7.1 测试要点

```text
国际化测试清单
├── ① 全 Locale 冒烟：每个支持的语言跑核心流程
├── ② 字符完整性：无乱码/无豆腐块（缺字形）
├── ③ 布局测试：文案膨胀后的 UI 是否溢出
├── ④ 日期/数字：各 Locale 格式正确
├── ⑤ 排序测试：中文拼音/日文五十音
├── ⑥ 时区测试：UTC 存储 + 各时区展示
├── ⑦ 双向文本（RTL）：阿拉伯语布局
└── ⑧ 编码测试：Emoji/生僻字/组合字符

自动化建议
├── ① 资源文件 key 完整性检查（CI 脚本）
├── ② 编码校验（UTF-8 合法性）
├── ③ 截图对比（视觉回归——布局膨胀）
└── ④ 伪本地化（pseudo-localization：长度模拟）
```

### 7.2 常见事故

```text
国际化事故案例
├── ⚠️ 硬编码文案：改语言只改了部分（遗漏）
├── ⚠️ 字符串拼接：占位符顺序错（"您有 {0}" 翻译后位置变）
├── ⚠️ 默认 Locale 依赖：服务器换环境输出变
├── ⚠️ 数据库 latin1：中文存 ????（不可恢复）
├── ⚠️ 日期本地化混淆：存储和展示混用
└── ⚠️ 翻译后长度膨胀：按钮/标题溢出
```

## 8. 核心要点

> 🎯 **核心要点**：
> 1. i18n（架构能力）≠ L10n（翻译内容）——先架构后内容
> 2. Locale 三原则：**显式指定**（不依赖默认）+ 贯穿请求 + 存储标准格式
> 3. 资源文件：basename + 语言_地区 + 逐级回退——**文案不硬编码 + 占位符**
> 4. 时区铁律：存储 UTC、展示转用户时区、绝不存本地时间
> 5. 货币：ISO 4217 代码传输（CNY 而非 ¥）+ BigDecimal 计算
> 6. 前后端分工：前端界面文案（i18n 库）+ 后端错误码（不返翻译文本）
> 7. 质量保障：key 完整性 CI 检查 + 全 Locale 冒烟 + 伪本地化
