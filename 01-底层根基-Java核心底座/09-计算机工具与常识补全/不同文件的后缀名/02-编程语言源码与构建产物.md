## 1. Java / JVM 生态

### 1.1 源码 → 编译 → 打包全链路

```text
.java → .class → .jar / .war
  ↓       ↓         ↓
源码    字节码    归档包

  Hello.java  ─── javac编译 ──→  Hello.class
  Hello.class  ─── jar打包 ──→  app.jar
  app.jar      ─── java执行 ──→  JVM 加载运行
```

| 后缀 | 全称/说明 | 阶段 | 打开方式 |
|:----:|------|:--:|---------|
| **.java** | Java 源码文件 | 编写 | IDE/文本编辑器 |
| **.class** | JVM 字节码（编译产物） | 编译后 | javap 反编译 / JD-GUI |
| **.jar** | Java Archive（ZIP 格式） | 打包 | zip 解压 / `java -jar` |
| **.war** | Web Application Archive | Web 部署 | Tomcat/Jetty 部署 |
| **.ear** | Enterprise Archive | 企业部署 | Java EE 服务器 |
| **.jsp** | JavaServer Pages（已过时） | Web 模板 | 文本编辑器 |
| **.kt** | Kotlin 源码 | 编写 | IntelliJ IDEA |
| **.kts** | Kotlin Script | 脚本 | `kotlinc -script` |
| **.groovy** | Groovy 源码 | 脚本/DSL | `groovy xxx.groovy` |
| **.scala** | Scala 源码 | 编写 | IntelliJ IDEA |

### 1.2 JVM 相关特殊文件

| 后缀 | 说明 |
|:----:|------|
| **.jmod** | Java 9+ 模块文件（JPMS 模块化） |
| **.jlink** | 自定义 JRE 镜像（只含所需模块） |

## 2. 字节码深入：.class 文件结构

### 2.1 魔数与文件头

> 🎯 **.class 文件的魔数是 `CA FE BA BE`**（Coffee Baby 的咖啡梗）——所有 JVM 语言（Java/Kotlin/Scala/Groovy）编译出的 class 都以它开头：

```text
.class 文件头部（16 字节）
├── CA FE BA BE     ← 魔数（识别 JVM 字节码）
├── 00 00 00 62     ← 次版本+主版本（0x62 = 98 = Java 14）
├── 常量池计数      ← constant_pool_count
└── 常量池表        ← 类/方法/字段/字符串的符号引用

用 hexdump 查看：
$ hexdump -C Hello.class | head -1
00000000  ca fe ba be 00 00 00 34 00 1e 07 00 02 01 00 0a
           ↑魔数        ↑版本(52=Java8)  ↑常量池数量(30)
```

### 2.2 javap 实战：读字节码

```java
// Hello.java
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello JVM");
    }
}
```

```bash
# 编译 + 反汇编
javac Hello.java
javap -c Hello                 # 反汇编字节码指令
javap -verbose Hello           # 完整信息（常量池/签名/行号表）
javap -p Hello                 # 含私有成员
```

```text
javap -c 输出解读
public static void main(java.lang.String[]);
  Code:
     0: getstatic     #7    ← 获取 System.out（常量池#7）
     3: ldc           #13   ← 加载字符串常量（常量池#13）
     5: invokevirtual #15   ← 调用 println 方法
     8: return               ← 返回
→ 常量池就是「符号表」：方法调用通过索引引用，这就是 JVM 动态链接的基础
```

### 2.3 反编译工具链

| 工具 | 用途 | 命令 |
|------|------|------|
| **javap** | 官方反汇编（字节码指令） | `javap -c Hello.class` |
| **CFR** | 反编译回 Java 源码 | `java -jar cfr.jar Hello.class` |
| **JD-GUI** | 图形化反编译 | GUI |
| **Procyon** | 反编译（支持新语法） | CLI |

## 3. JAR 与部署产物的结构

### 3.1 JAR 本质

> 🎯 **JAR = ZIP + META-INF/MANIFEST.MF**——把 .class 打包压缩，并带上清单文件声明入口类：

```text
app.jar 解压后的结构
├── META-INF/
│   ├── MANIFEST.MF      ← 清单：Main-Class、版本、签名
│   └── maven/           ← 构建信息
├── com/example/         ← 编译后的 .class 树
│   └── Hello.class
└── 资源文件（.properties/.xml）

关键：MANIFEST.MF 中的 Main-Class 决定 `java -jar` 启动哪个类
```

### 3.2 三类部署产物对比

| 维度 | JAR | WAR | EAR |
|------|:---:|:---:|:---:|
| 形态 | ZIP | ZIP | ZIP |
| 场景 | 独立应用/库 | Web 应用 | 企业级多模块 |
| 部署 | `java -jar` | Tomcat/Jetty | 完整 Java EE 服务器 |
| 特征 | Main-Class 入口 | WEB-INF/web.xml | 含多个 war/jar 模块 |
| Spring Boot | **Fat JAR**（内嵌 Tomcat） | 传统 war 外置 | 已少见 |

### 3.3 Spring Boot Fat JAR 结构

```text
app.jar（Spring Boot 可执行 jar）
├── BOOT-INF/
│   ├── classes/          ← 你的业务代码
│   └── lib/              ← 所有依赖 jar（fat 的关键！）
├── META-INF/
│   └── MANIFEST.MF       ← Main-Class 指向 Launcher
└── org/springframework/boot/loader/
    └── ...               ← 自定义类加载器（启动入口）

→ Fat JAR 体积大但可独立运行：java -jar app.jar
→ 分层打包（Spring Boot 2.3+）：BOOT-INF/lib 独立层 → Docker 缓存优化
```

```bash
# JAR 常用操作
jar -tf app.jar              # 列出文件
jar -xf app.jar              # 解压
jar -uf app.jar 文件          # 更新
unzip -l app.jar             # ZIP 视角查看（等价）
```

## 5. 解释型 vs 编译型：运行机制对比

| 维度 | 编译型（Go/Rust/C） | 字节码型（Java/Kotlin） | 解释型（Python/JS） |
|------|:---:|:---:|:---:|
| 产物 | 机器码二进制 | 字节码 .class | 无（直接解释源码） |
| 运行前 | 编译链接 | javac + JVM | 解释器直接跑 |
| 速度 | 最快 | 中（JIT 热路径接近编译型） | 最慢 |
| 跨平台 | 需各自编译 | 一次编译到处跑（JVM） | 解释器跨平台 |
| 调试 | 编译期类型检查 | 编译期 + JVM 检查 | 运行期才发现错误 |
| 代表后缀 | .go/.rs/.c | .java/.kt/.scala | .py/.js/.rb |

```text
.pyc 是什么？
├── Python 首次运行 .py → 编译为字节码 → 缓存到 __pycache__/*.pyc
├── 之后运行直接加载 .pyc（免编译，启动更快）
├── 跨 Python 版本不兼容（pyc 带版本标记）
└── 不是「编译型」——.pyc 依然由解释器执行

.ipynb 是什么？
├── Jupyter Notebook：JSON 文件（cells + 输出 + 元数据）
├── 打开 = 逐格执行（交互式探索）
├── 可导出 .py（纯代码）/ .html / .md
└── 适合：数据分析、教学演示（生产代码用 .py）
```

## 6. 系统与编译语言

| 后缀 | 语言 | 编译 → 产物 |
|:----:|------|:----------:|
| **.c** | C | `.o` → 可执行文件 (Linux) / `.exe` (Win) |
| **.cpp / .cc / .cxx** | C++ | 同上 |
| **.h / .hpp** | C/C++ 头文件 | 编译时引用 |
| **.a** | 静态库 (Linux) | 链接进可执行文件 |
| **.so** | 共享库/动态库 (Linux) | 运行时加载 |
| **.dylib** | 动态库 (macOS) | 运行时加载 |
| **.dll** | 动态链接库 (Windows) | 运行时加载 |
| **.lib** | 静态/导入库 (Windows) | 链接阶段 |
| **.o** | 目标文件 | 编译中间产物 |
| **.obj** | 目标文件 (Windows) | 编译中间产物 |
| **.s / .asm** | 汇编源码 | 汇编器 → 目标文件 |
| **.i** | 预处理后的 C 源码 | 预处理产物（`gcc -E`） |

### 6.1 静态库 vs 动态库

```text
静态链接 vs 动态链接
├── 静态库（.a / .lib）：
│   ├── 编译时嵌入可执行文件 → 独立分发但体积大
│   ├── 更新库需重新编译所有使用者
│   └── 优点：无运行时依赖
├── 动态库（.so / .dll / .dylib）：
│   ├── 运行时加载 → 体积小、可热更新
│   ├── 需要库在运行路径上（LD_LIBRARY_PATH / PATH）
│   └── 经典事故：DLL 缺失（"找不到 xxx.dll"）
```

## 7. C 编译链路四阶段

### 7.1 四阶段全景

```text
C 编译四阶段（每阶段产物都是一种文件类型）
hello.c ──预处理──▶ hello.i ──编译──▶ hello.s ──汇编──▶ hello.o ──链接──▶ hello(可执行)
  源码       gcc -E    预处理源码     gcc -S   汇编源码   gcc -c   目标文件   gcc     二进制
  (文本)                (文本)                  (文本)              (二进制)           (ELF/PE)
```

| 阶段 | 命令 | 产物 | 做的事 |
|------|------|------|--------|
| 预处理 | `gcc -E` | `.i` | 展开 #include/#define（文本） |
| 编译 | `gcc -S` | `.s` | C → 汇编（文本） |
| 汇编 | `gcc -c` | `.o` | 汇编 → 机器码（二进制） |
| 链接 | `gcc` | 可执行 | 合并目标文件+库 → 可执行 |

```bash
# 实战：从源码到可执行（每一步可见）
gcc -E hello.c -o hello.i      # ① 预处理（可读，宏展开）
gcc -S hello.i -o hello.s      # ② 编译为汇编
gcc -c hello.s -o hello.o      # ③ 汇编为目标文件
gcc hello.o -o hello           # ④ 链接为可执行文件
file hello                     # → ELF 64-bit LSB executable
```

> 🎯 **认知**：Java 的 `javac` 把「编译+汇编」合并为一步（源码 → 字节码），`jar` 把「链接+打包」合并——所以 Java 开发者只看到 .java → .class → .jar 三个形态。

### 9.2 .editorconfig 实战

```ini
# .editorconfig 示例（推荐每个项目都放！）
root = true

[*]
charset = utf-8
end_of_line = lf
indent_style = space
indent_size = 4
insert_final_newline = true
trim_trailing_whitespace = true

[*.md]
trim_trailing_whitespace = false

[Makefile]

[{*.yml,*.yaml}]

```

> 🎯 **.editorconfig 的价值**：让所有团队成员（无论用 VS Code/IDEA/Vim）的缩进、换行、编码自动统一——**一行配置解决「为什么你的代码在我电脑上格式全乱」**。

### 9.3 .gitignore 核心模板

```gitignore
# Java 项目（通用）
target/
*.class
*.jar
!.mvn/wrapper/maven-wrapper.jar

# IDE
.idea/
*.iml
.vscode/
.settings/
```

## 10. 核心要点

> 🎯 **核心要点**：
> 1. Java 开发关注 `.java → .class → .jar` 链路；.class 魔数 `CA FE BA BE` + 常量池是 JVM 动态链接的基础
> 2. JAR = ZIP + MANIFEST.MF；Spring Boot Fat JAR = 内嵌依赖 + 自定义类加载器
> 3. C 编译四阶段（预处理→编译→汇编→链接）产物：.i/.s/.o/可执行——理解编译 = 理解所有编译型语言
> 4. 构建文件铁律：声明文件 + lock 文件都提交；产物目录永不提交；.env/.pem 密钥文件永不提交
> 5. 团队协作必加 `.editorconfig` 和 `.gitattributes`（格式化与换行符统一）
