# 05-Swagger UI使用
> 定位：Swagger UI 是契约的「阅读器 + 调试器」——浏览结构、在线调试、认证配置、定制体验；它是开发者与对接方使用 API 的第一入口，用得好能省掉大量「接口怎么调」的沟通。

## 1. 界面结构

Swagger UI 的五个区域（从上到下）：**顶部栏**——标题（@OpenAPIDefinition 的 info）+ Explore 输入框（契约源切换）；**认证区**——Authorize 按钮（配置后出现——04 篇 securitySchemes）；**标签组**——按 @Tag 分组的接口列表（左侧/折叠式）；**操作条目**——每个接口的 summary + 方法徽标（GET 绿/POST 蓝/DELETE 红）+ 展开箭头；**展开面板**——参数表、请求体 schema、响应结构（按状态码）、Try it out 按钮。

**「UI 是契约的渲染」**——界面长什么样完全由契约决定（注解质量 = UI 质量，03 篇）；理解这个对应关系，UI 问题排查就变成了契约问题排查（少了分组查 @Tag、少了状态码查 @ApiResponse）。

## 2. 浏览：结构阅读

高效浏览的四个动作：**按标签定位模块**（@Tag 分组即模块地图——「用户管理」「订单管理」）；**展开看参数与响应**（每个操作面板：参数表（名/位置/类型/必填/描述）、请求体 schema（DTO 字段 + 约束）、响应（每个状态码的结构）——**对接方不用看代码就能拼请求**）；**看模型定义**（DTO 的 schema 独立展示——嵌套模型可点开——「返回结构长什么样」一目了然）；**搜索接口**（顶部过滤框——按路径/标签过滤——接口多了必备）。

**浏览的工程价值**：**前端对接零沟通**（结构自解释）；**评审文档质量**（UI 里走一遍 = 文档走查——「接口描述全不全」眼见为实）；**新人上手**（看 UI 即了解系统能力全貌）。

## 3. 调试：Try it out

Try it out 是 UI 的调试能力——**文档 + 调试合一**（02 篇的「价值时刻」）：点击操作面板的 Try it out → 参数变为可编辑输入框（**example 自动预填**——03 篇 example 的调试价值）→ 填参数 → Execute → 显示真实请求与响应（状态码、响应体、耗时）。

**调试的三个场景**：**开发期自测**（改完代码 UI 里验证——免切 Postman）；**对接验证**（前端/第三方用 UI 试调——「你说的接口我调通了」）；**排查问题**（UI 调试 + curl 对比——「UI 里成功、代码里失败」定位差异——多半是认证或头参数）。**调试的注意**：Try it out 是真实请求——**生产环境必须禁用**（`try-it-out-enabled: false`——08 篇）。

## 4. 认证：Authorize

Authorize 按钮是认证配置入口——**「接口要带什么凭证」在 UI 里可配置**：点击 Authorize → 按契约声明的 securitySchemes 填（Bearer Token 填 JWT、Basic 填账号密码、API Key 填密钥）→ 保存——**之后的 Try it out 请求自动携带凭证**。

**使用姿势**：登录系统拿 Token → 填进 Authorize → 调试受保护接口；**`persist-authorization: true`** 记住认证信息（刷新页面不丢——开发期省事）；**认证信息是浏览器的本地状态**（不会上传——本地存储于 localStorage——注意生产环境的凭证管理）。**「认证配置在 UI 里可见」的意义**：对接方知道「这接口要什么凭证」——配合 03 篇 @SecurityRequirement。

## 5. 契约源切换

Explore 栏可以加载「任意来源的契约」——**UI 不只能看本地**：**本地默认**（`/v3/api-docs`）；**外部契约文件**（粘贴 OpenAPI JSON/YAML URL 或内容——查看其他服务的文档——**多服务文档聚合**的手动形态）；**环境切换**（04 篇 servers 声明多环境——Explore 里选目标环境）。

**多服务的文档聚合**：微服务架构每个服务各带一个 Swagger UI——**聚合方案**：网关层聚合（`/v3/api-docs` 转发各服务）+ 统一 UI（Knife4j 支持聚合——07 篇）；**「一个入口看全部服务」是微服务文档的工程需求**——单服务 UI 各自为政是痛点。

## 6. UI 定制

UI 的工程化定制（02 篇配置 + 进阶）：

```yaml
springdoc:
  swagger-ui:
    path: /swagger-ui.html
    tags-sorter: alpha              # 标签按字母序
    operations-sorter: method       # 操作按方法序（GET 在前）
    display-request-duration: true  # 显示请求耗时
    doc-expansion: list             # 默认展开（list/none）
    filter: true                    # 显示过滤框
    syntax-highlight:
      activated: true               # 代码高亮
```

**「UI 即产品」的配置思路**：排序（标签/操作）让接口列表可扫读；doc-expansion 控制默认展开层级（接口多时 none 减少噪音）；filter 在接口多的项目必开。「再深一层的定制」（主题、品牌）——Swagger UI 是前端应用，可自定义静态资源（高级场景，团队需前端能力）——**默认配置覆盖 90% 需求，别为定制而定制**。

**UI 的三种使用角色**（按角色理解 UI 价值）：**开发者**（自测与排查——Try it out 验证自己接口、看契约确认返回结构）；**对接方**（前端/第三方——浏览结构拼请求、Authorize 配认证、调试验证——「文档 + 调试合一」省掉沟通）；**评审者**（架构/QA——走查文档质量：分组合理吗、描述完整吗、示例有吗——**「UI 走查 = 文档评审」是质量把关动作**）。**「UI 是角色驱动的工具」**——不同角色看到的价值不同，但共同前提是契约质量（03 篇）——「UI 好不好用，先问契约写没写好」。

## 7. 常见坑

**坑一：生产开着 Try it out**。生产 UI 可调试 = 生产接口可被调用——生产关闭（`try-it-out-enabled: false` + 08 篇认证/禁用）。

**坑二：Authorize 填了没生效**。securitySchemes 声明与 @SecurityRequirement 不配对——全局声明检查（04 篇）。

**坑三：Explore 加载外部契约失败**。跨域/内网访问——契约 URL 可达性 + CORS（[[../../../02-后端核心技术%20微服务%20分布式%20云原生/09-Web开发全流程/Web%20高阶知识/04-跨域与浏览器安全机制|CORS 体系]]）。

**坑四：UI 白屏**。契约加载失败（`/v3/api-docs` 被拦截/404）——先 curl 契约端点排查（02 篇三端点）。

**坑五：接口太多找不到**。没开 filter、分组混乱——`filter: true` + @Tag 分组治理（03 篇）。

**坑六：persist-authorization 生产开着**。凭证持久化在浏览器——生产关闭。

**坑七：Try it out 的结果误导**。「UI 里调通了」不等于「对接没问题」——UI 的请求环境（认证、头、环境）与真实客户端可能不同——**UI 调试是验证「接口本身」，对接问题要回真实客户端场景排查**。

**坑八：大契约 UI 卡顿**。接口/模型太多渲染慢——按模块拆分文档（多 projectKey）或搜索优先——「文档也要分页治理」。
