## 1. 实战：搭建 API 文档体系

把全体系知识点压进一个项目：Spring Boot 项目从零搭建文档体系——接入、注解、契约资产、生产管控、AI 集成五步闭环。

**第一步，接入（02 篇）**：

```xml
<!-- pom.xml：springdoc 3.1.0（Boot 4 配套） -->
<dependency>
    <groupId>org.springdoc</groupId>
    <artifactId>springdoc-openapi-starter-webmvc-ui</artifactId>
    <version>3.1.0</version>
</dependency>
```

**第二步，全局定义与注解（03/04 篇）**——OpenApiConfig（info/servers/securitySchemes）+ Controller 全注解（@Tag/@Operation/@ApiResponse/@Schema）——**验收标准：每个接口有 summary、每个状态码有描述、每个字段有 example**。

**第三步，契约资产化（06 篇）**——CI 里导出契约进仓库 + 快照测试：

```yaml
# CI 步骤：契约导出与快照断言
- curl -s http://localhost:8080/v3/api-docs -o api-docs/openapi.json
- git diff --exit-code api-docs/openapi.json   # 契约变更必须走评审（diff 可见）
```

**第四步，生产管控（08 篇）**——prod 配置关闭（或认证）+ 发布检查断言 404：

```bash
# 发布检查：生产文档端点必须不可达
curl -s -o /dev/null -w "%{http_code}" https://api.example.com/swagger-ui.html | grep -q 404
```

**第五步，AI 集成（09 篇）**——加 MCP starter + @McpToolDescription + guardrails 配置——**验收：MCP 客户端（Claude Desktop 等）能发现并调用你的查询接口，变更接口需要人工确认**。

**验收四问**：**能看吗**——开发环境 UI 完整可读（分组/描述/示例/状态码）；**能测吗**——Try it out 调试跑通；**能管吗**——生产 404、契约进仓库、变更走评审；**能被 AI 用吗**——MCP 客户端实测调用成功。

## 2. 生产配置模板与纪律清单

**接入**：`springdoc-openapi-starter-webmvc-ui:3.1.0`（Boot 4 配套，锁版本查矩阵）；**配置**：`api-docs.version: openapi_3_1`、`disable-swagger-default-url: true`、`cache.disabled`（开发）；**注解**：@Tag 分组 + @Operation 四要素 + @ApiResponse 全覆盖 + @Schema example；**契约**：CI 导出进仓库、快照测试拦漂移、契约版本与 API 版本对应；**生产**：prod 默认关（或认证）+ 发布检查断言 + 访问审计；**AI**：MCP starter + @McpToolDescription 四要素 + 变更操作人工确认；**版本**：springdoc/Knife4j/UI 配套升级（07/09 篇纪律）。

## 3. 报错速查十条

| 现象 | 原因 | 处理 |
|------|------|------|
| UI 404 | api-docs/swagger-ui 未启用或路径错 | 检查配置与三端点 |
| UI 白屏 | 契约加载失败 | curl /v3/api-docs 排查 |
| 接口没出现 | 扫描范围/paths-to-match | packages-to-scan 覆盖 |
| 改了注解没变化 | 契约缓存 | 开发期 cache.disabled |
| 契约 3.0 非 3.1 | version 未配 | openapi_3_1 |
| 状态码只有 200 | @ApiResponse 缺失 | 全状态码描述 |
| Authorize 无效 | securitySchemes 未声明 | 全局定义配对 |
| 生产还能访问 UI | 配置未按环境分 | prod 关闭 + 发布检查 |
| Knife4j 404 | enable 未开/版本不配套 | 查兼容矩阵 |
| MCP 工具不出现 | starter/开关未配 | webmvc-mcp + enabled |
| 注解改了契约没变 | 契约缓存/未重启 | 开发期 cache.disabled + 重启 |
| 聚合文档部分 404 | 某服务契约不可达 | 逐服务 curl /v3/api-docs |
| AI 调用参数错误 | 描述/示例缺失 | @McpToolDescription 四要素 + example |
| AI 能调写接口 | guardrails 未配置 | 变更操作默认人工确认 |

## 4. 面试三范式

**价值式**：「我搭建的 API 文档体系——springdoc 接入 + 注解规范（全接口 summary/全状态码/全 example），契约 CI 导出进仓库 + 快照测试，文档漂移归零；生产管控三板斧，发布检查自动断言；升级到 3.x MCP 集成后，查询接口直接被 AI agent 调用，变更操作人工确认。」——先讲资产化与安全收益，再讲手段。

**技术式**：「OpenAPI 是规范、Swagger 是工具、springdoc 是 Spring 集成——契约启动时生成（三信息源：MVC 注解/OpenAPI 注解/类型反射）；注解补语义不补结构；契约是资产（导出/评审/版本化）；3.x 的 MCP 集成把已文档化端点语义映射成 AI 工具。」——原理到机制，别停在「Swagger 能生成文档」。

**生产式**：「Swagger 生产是暴露面（接口地图 + 参数手册）——prod 默认禁用 + 认证 + 白名单三板斧，发布检查自动化断言；契约脱敏根治是模型隔离；文档访问要审计；AI 集成（MCP）要 guardrails——变更操作人工确认。」——暴露面、环境边界、AI 护栏三点是区分度。

**追问四连**：OpenAPI 与 Swagger 什么关系？（规范改名史——工具家族）｜文档怎么防漂移？（CI 导出 + 快照测试 + Dredd）｜生产怎么管控？（禁用/认证/白名单 + 发布断言）｜AI 怎么用你的 API？（MCP 集成 + 描述四要素 + guardrails）。

## 5. 简历呈现

项目经历写法：「基于 springdoc 的 API 文档体系——注解规范（描述/示例/状态码全覆盖）+ 契约 CI 导出与快照测试，文档零漂移；生产管控（环境配置隔离 + 发布检查断言 + 访问审计）；springdoc 3.x MCP 集成让 REST 端点成为 AI 工具（@McpToolDescription + 变更操作人工确认）。」技能栏：「API 文档工程（OpenAPI/Swagger/springdoc），AI 工具集成（MCP）」。——资产化 + 安全 + AI 三要素。
