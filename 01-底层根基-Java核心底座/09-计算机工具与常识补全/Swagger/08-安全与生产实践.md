## 1. Swagger 的暴露面

Swagger 文档是「接口的完整地图」——暴露的内容远超想象：**全部端点**（含内部接口——如果 paths-to-match 没限定，04 篇）；**请求/响应结构**（DTO 字段——**含字段名与类型——攻击者的参数枚举手册**）；**认证方式**（securitySchemes——知道用什么凭证）；**服务器地址**（servers 声明——攻击目标清单）；**Try it out**（生产开启 = 生产接口可被任何人调用）。

**「上线忘关 Swagger」的后果**：攻击者打开 `/swagger-ui.html`——**不用逆向、不用猜参数**——完整 API 手册直接呈上——配合 [[../../../02-后端核心技术%20微服务%20分布式%20云原生/09-Web开发全流程/Web%20高阶知识/07-Web安全攻防|Web 安全]] 的常见漏洞，攻击成本降到零。**Swagger 在非生产环境是效率工具、在生产环境是暴露面**——环境的边界就是管控的分界。

## 2. 管控三板斧

生产环境的 Swagger 管控三板斧（按安全强度递增，可组合）：

**第一板斧：直接禁用**——`springdoc.api-docs.enabled: false` + `springdoc.swagger-ui.enabled: false`——**最彻底**（端点 404，什么信息都不暴露）——内部系统无文档需求时的默认选择。

**第二板斧：认证保护**——文档端点挂 Spring Security（`/swagger-ui/**`、`/v3/api-docs` 要求登录）——**需要文档但只给内部人看**——配合 [[../../../02-后端核心技术%20微服务%20分布式%20云原生/06-Spring全家桶/Spring%20Security与Spring%20Security%20OAuth2/00-Spring%20Security与OAuth2知识体系总览|Spring Security 体系]] 的配置；**注意**：契约端点与 UI 都要保护（只保护 UI 不保护 `/v3/api-docs`——契约仍可 curl 拿到）。

**第三板斧：网络白名单**——文档端点只在内网/运维网络可达（网关层限制路径、VPN 内网暴露）——**「文档不过公网」**是底线。

**组合策略**：内网系统 → 禁用或内网白名单；半公开系统（合作伙伴要文档）→ 认证保护；**「默认禁用、按需放开」**是生产纪律——开发/测试环境放开，生产默认关。

## 3. 环境差异化配置

「开发开着、生产关闭」的工程实现——**配置按环境分离**：

```yaml
# application-dev.yml（开发环境）
springdoc:
  api-docs: { enabled: true }
  swagger-ui: { enabled: true, try-it-out-enabled: true }

# application-prod.yml（生产环境）
springdoc:
  api-docs: { enabled: false }       # 或认证保护
  swagger-ui: { enabled: false }
```

**配置纪律**：**文档开关进环境配置**（dev/test/prod 各一份——不写死在主配置）；**prod 的默认值写「关闭」**（忘了配置时是安全的——「默认安全」原则）；**部署检查清单带「Swagger 状态」项**（上线检查：生产 `/swagger-ui.html` 返回 404 或登录页——**发布脚本里加自动化检查**（curl 断言 404）——「忘关 Swagger」变成「发布失败」而非「线上事故」）。

## 4. 契约脱敏

需要文档但不能暴露全部信息时——契约脱敏的三个层次：**接口级脱敏**——`@Operation(hidden = true)` 隐藏敏感接口（内部管理接口、审计接口——不出现在文档）；**路径级脱敏**——`paths-to-match` 限定文档范围（04 篇——`/internal/**` 不匹配）；**字段级脱敏**——DTO 的敏感字段处理：`@Schema(hidden = true)` 隐藏字段；**更彻底的方案**——对外文档用**独立的对外 DTO**（内部字段根本不进对外模型——「契约脱敏的根治是模型隔离」——与 [[../../../02-后端核心技术%20微服务%20分布式%20云原生/09-Web开发全流程/RESTful%20API/00-RESTful%20API总览|RESTful 敏感数据治理]] 的 DTO 裁剪同一纪律）。

**脱敏的验收**：导出契约 grep 敏感字段（身份证、手机号、内部字段名——**「契约里没有的字段才是安全的」**）。

## 5. 审计与治理

文档体系的生产治理：**访问审计**——文档端点访问日志（谁、何时、从哪 IP 看了文档——**文档是敏感资产，访问要可查**）；**契约变更审计**——契约进仓库（06 篇）——契约 diff 即接口变更记录（`/v3/api-docs` 快照入库，变更走评审）；**定期安全检查**——发布检查单带「Swagger 暴露状态」+ 周期性扫描（自动化 curl 断言生产文档端点状态——「每季度确认一次生产没开文档」）。**治理的落点**：文档既是效率工具也是敏感资产——「好用」与「安全」的平衡在环境边界与审计机制。

## 6. 常见坑

**坑一：只禁用 UI 不禁用契约**。`/v3/api-docs` 还开着——契约照样可 curl——两处都关。

**坑二：认证只保护 UI**。契约端点无保护——同样加认证。

**坑三：Try it out 生产开着**。生产可调试 = 生产可调用——关闭。

**坑四：dev 配置写死开关**。prod 复用 dev 配置——按环境分离（prod 默认关）。

**坑五：脱敏只靠 hidden**。内部字段还在 DTO——模型隔离（对外 DTO）。

**坑六：发布不检查**。「忘关 Swagger」上线——发布检查单自动化断言。

**坑七：文档访问无审计**。谁看了文档不可查——访问日志。

**坑八：认证保护的密码泄露**。文档账号共用弱密码——文档访问认证也要独立账号 + 强密码 + 定期轮换（与业务账号隔离）。

**坑九：第三方需要文档时临时开公网**。「给客户看两天」直接开公网忘了关——给第三方的文档走「一次性临时链接/独立部署的只读文档站」——「临时开放要带到期」。

**「文档是敏感资产」的完整视角**：文档的价值与风险一体两面——**价值面**：对接效率、调试效率、AI 集成（09 篇）——**风险面**：接口地图泄露、参数结构暴露、可调试接口（第 1 节）——**「管控不是禁用文档，是管理文档的暴露范围」**：开发环境全开（效率）、测试环境半开（契约给自动化）、生产环境最小化（禁用或认证）——**「按环境的暴露梯度」是文档治理的核心姿态**——同一套代码，dev 开着用、prod 关着防——这就是 08 篇全部内容的浓缩。
