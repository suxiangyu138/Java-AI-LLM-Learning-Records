## 1. 跨平台差异的本质

> **背景**：Linux（Unix 哲学）与 Windows 的命令体系源自不同传统——文件系统、路径、工具集、权限模型全不同。
> **目的**：掌握映射关系，跨平台开发不卡壳。
> **适用范围**：任何需要在多平台写命令/脚本的人。
> **前提假设**：Windows 侧以 PowerShell 为现代标准（cmd 仅遗留兼容）。

```text
三大本质差异
├── ① 路径：/ 与 \（见「正斜杠与反斜杠」系列）
├── ② 大小写：Linux 敏感（File.txt ≠ file.txt）/ Windows 不敏感
├── ③ 输出格式：文本流（Unix）vs 对象（PowerShell）

PowerShell 的独特优势
├── 管道传「对象」而非文本（Get-Process | Where-Object CPU -gt 10）
├── 命令更语义化（Get-Content 而非 cat）
└── 别名兼容 Unix 习惯（cat/ls 在 PowerShell 可用）
```

## 2. 文件与目录操作对照

| 操作 | Linux/macOS（Bash） | Windows（PowerShell） | 说明 |
|------|:---:|:---:|------|
| 列目录 | `ls -la` | `ls` / `Get-ChildItem` | PowerShell 兼容 ls |
| 切换目录 | `cd /home/user` | `cd C:\Users\xxx` | 路径分隔符不同 |
| 当前目录 | `pwd` | `pwd` / `Get-Location` | |
| 创建目录 | `mkdir -p a/b/c` | `New-Item -ItemType Directory -Force a\b\c` | -p 递归 |
| 删除文件 | `rm file.txt` | `Remove-Item file.txt` | 无回收站（都危险） |
| 删除目录 | `rm -rf dir` | `Remove-Item -Recurse -Force dir` | ⚠️ 高危 |
| 复制 | `cp -r src dst` | `Copy-Item -Recurse src dst` | |
| 移动/重命名 | `mv a b` | `Move-Item a b` / `Rename-Item` | |
| 查看文件 | `cat file` | `Get-Content file` / `cat` | |
| 查看尾部 | `tail -f log` | `Get-Content log -Wait` | 日志跟随 |
| 查找文件 | `find . -name "*.java"` | `Get-ChildItem -Recurse -Filter *.java` | |
| 文件信息 | `stat file` | `Get-Item file \| Format-List *` | |
| 权限 | `chmod 600 file` | `icacls file /grant user:F` | 权限模型不同 |

```text
⚠️ 高危命令对照（三思后行）
├── rm -rf /       ≈  Remove-Item -Recurse -Force C:\
├── 都无回收站：删除 = 永久删除
└── 安全习惯：alias rm='rm -i'（交互确认）
```

## 3. 文本处理对照

| 操作 | Linux（Bash） | Windows（PowerShell） | 说明 |
|------|:---:|:---:|------|
| 文本搜索 | `grep "xxx" file` | `Select-String "xxx" file` | PowerShell: `grep` 别名可用 |
| 递归搜索 | `grep -r "xxx" .` | `Get-ChildItem -Recurse \| Select-String` | 或 ripgrep（见第 7 节） |
| 排序 | `sort file` | `Sort-Object` | |
| 去重 | `sort -u file` | `Sort-Object -Unique` | |
| 行数统计 | `wc -l file` | `(Get-Content file).Count` | |
| 替换 | `sed 's/a/b/g' file` | `(Get-Content file) -replace 'a','b'` | |
| 切割列 | `cut -d',' -f1 file` | `Import-Csv file \| Select-Object col1` | PowerShell 对象化 |
| 管道 | `cat a \| grep x` | `Get-Content a \| Select-String x` | 语法相似 |
| 输出重定向 | `cmd > file 2>&1` | `cmd > file 2>&1` | 兼容 |
| 变量赋值 | `x=$(cmd)` | `$x = cmd` | 语法不同 |

```bash
# 对照示例：统计日志中 ERROR 数量
# Linux
grep -c "ERROR" app.log
# PowerShell
(Select-String -Path app.log -Pattern "ERROR").Count
```

> 🎯 **2026 建议**：文本处理跨平台首选 **ripgrep（rg）**——Windows/Linux/macOS 通用且性能远超 grep（见第 7 节），跨平台脚本不再为语法差异烦恼。

## 4. 系统管理对照

| 操作 | Linux | Windows（PowerShell） |
|------|:---:|:---:|
| 进程列表 | `ps aux` | `Get-Process` |
| 杀进程 | `kill -9 PID` | `Stop-Process -Id PID -Force` |
| 端口监听 | `ss -tlnp` | `Get-NetTCPConnection -State Listen` |
| 查看端口占用 | `lsof -i :8080` | `Get-NetTCPConnection -LocalPort 8080` |
| 磁盘空间 | `df -h` | `Get-PSDrive` |
| 内存 | `free -h` | `Get-Counter '\Memory\Available MBytes'` |
| 系统信息 | `uname -a` | `systeminfo` |
| 环境变量 | `echo $PATH` | `$env:PATH` |
| 服务管理 | `systemctl status sshd` | `Get-Service sshd` |
| 定时任务 | `crontab -e` | `schtasks /create` |
| 当前用户 | `whoami` | `whoami`（相同） |
| 网络配置 | `ip addr` | `Get-NetIPAddress` |

```text
进程管理对照（Java 开发高频）
├── Linux：jps（Java 进程）→ kill -3 PID（线程 dump）
├── Windows：Get-Process java → Stop-Process
└── 端口排查：lsof -i :8080 ≈ Get-NetTCPConnection -LocalPort 8080
```

## 5. 网络操作对照

| 操作 | Linux | Windows（PowerShell） |
|------|:---:|:---:|
| 连通测试 | `ping host` | `Test-Connection host`（ping 也可用） |
| 端口测试 | `nc -vz host 8080` | `Test-NetConnection host -Port 8080` |
| DNS 查询 | `dig example.com` | `Resolve-DnsName example.com` |
| HTTP 请求 | `curl -s http://x` | `curl.exe`（新版内置）`Invoke-WebRequest` |
| 抓包 | `tcpdump -i eth0` | `pktmon` / Wireshark |
| 路由 | `traceroute host` | `tracert host`（cmd 遗留） |
| 接口信息 | `ip addr` | `Get-NetIPConfiguration` |
| 下载 | `wget url` | `curl.exe -O url` / `Invoke-WebRequest` |

```bash
# 端口测试对照（排障高频）
# Linux
nc -vz 192.168.1.100 3306
# Windows
Test-NetConnection 192.168.1.100 -Port 3306
# 两者都输出端口是否开放
```

> 💡 **curl 的跨平台**：Windows 10+ 自带 curl.exe（不是 PowerShell 的 curl 别名）——**脚本中显式写 `curl.exe`** 避免别名歧义。

## 6. 包管理对照

| 操作 | Debian/Ubuntu | RHEL/CentOS | macOS | Windows |
|------|:---:|:---:|:---:|:---:|
| 安装 | `apt install x` | `dnf install x` | `brew install x` | `winget install x` / `choco` |
| 更新索引 | `apt update` | `dnf check-update` | `brew update` | `winget upgrade` |
| 搜索 | `apt search x` | `dnf search x` | `brew search x` | `winget search x` |
| 卸载 | `apt remove x` | `dnf remove x` | `brew uninstall x` | `winget uninstall x` |
| 语言包 | pip/npm/maven | 同左 | 同左 | 同左（跨平台） |

```text
包管理要点
├── ① 系统包：随发行版/平台（上表）
├── ② 语言包：pip/npm/go 跨平台一致（无差异）
├── ③ 2026 趋势：winget（Windows 官方）/ brew（macOS）
└── ④ 权限：Linux 需 sudo；Windows 装系统级需管理员
```

## 7. 2026 增强工具链（跨平台现代替代）

### 7.1 增强工具一览

> 🎯 **2026 跨平台命令行的核心升级**：用 Rust 编写的增强工具替代传统命令——**速度快、输出彩色、跨平台一致**：

| 传统命令 | 增强替代 | 优势 |
|:---:|:---:|------|
| `ls` | **eza** | 彩色、图标、更多信息 |
| `cd` | **zoxide** | 记住常用目录（敲几个字符跳转） |
| `find` | **fd** | 简单、快速、友好默认 |
| `grep` | **ripgrep (rg)** | 快 10-100 倍、gitignore 感知 |
| `cat` | **bat** | 语法高亮、行号、分页 |
| `top` | **btop** | 可视化资源监控 |
| `history` | **atuin** | SQLite 历史 + 搜索 + 加密同步 |
| `diff` | **delta** | Git diff 美化 |
| Git CLI | **lazygit** | Git TUI（可视化操作） |

### 7.2 安装与配置

```bash
# 跨平台安装（多数支持 winget/brew/apt + cargo）
# 示例：ripgrep + fd + bat + eza
sudo apt install ripgrep fd-find bat eza    # Debian/Ubuntu
brew install ripgrep fd bat eza             # macOS
winget install BurntSushi.ripgrep sharkdp.fd sharkdp.bat eza-community.eza  # Windows

# zoxide（智能 cd）
curl -sS https://raw.githubusercontent.com/ajeetdsouza/zoxide/main/install.sh | sh
# 启用（.bashrc/.zshrc）
eval "$(zoxide init bash)"    # 之后 z 跳转：z proj（记住的目录）

# 别名接管（.bashrc）
alias ls='eza --icons'
alias cat='bat'
alias grep='rg'
alias cd='z'
```

### 7.3 使用效果对比

```bash
# grep vs rg（性能与体验）
grep -r "ERROR" /var/log/app/          # 传统（慢、无颜色）
rg "ERROR" /var/log/app/               # 快、彩色、显示上下文

# find vs fd
find . -name "*.java"                  # 传统（语法怪）
fd -e java                             # 简单（扩展名过滤）

# cat vs bat
cat config.yml                         # 无高亮
bat config.yml                         # 语法高亮 + 行号
```

> 🎯 **2026 结论**：**增强工具链是「一次学习、全平台受益」的最高性价比投资**——脚本兼容性用传统命令，日常交互用增强工具（别名切换即可）。

## 8. 核心要点

> 🎯 **核心要点**：
> 1. 三大本质差异：路径（/ vs \）、大小写敏感、输出格式（文本 vs 对象）
> 2. PowerShell 对象管道是 Windows 的独特优势（Get-Process | Where-Object）
> 3. 五类命令映射：文件/文本/系统/网络/包管理——高频对照表即查即用
> 4. 跨平台文本处理首选 rg（ripgrep）——性能与一致性兼得
> 5. 2026 增强工具链：eza/zoxide/fd/rg/bat——「一次学习、全平台受益」
