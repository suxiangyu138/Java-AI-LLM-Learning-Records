## 1. 面试高频题与答题框架

### 1.1 原理类

**Q1：端口号分几类？范围是多少？**

```text
① 0-1023：公认端口（标准协议）——需 root 绑定
   （HTTP 80/HTTPS 443/SSH 22/DNS 53）
② 1024-49151：注册端口（主流应用）
   （MySQL 3306/Redis 6379/Tomcat 8080）
③ 49152-65535：动态端口（客户端临时）
④ 关键：TCP 与 UDP 端口空间独立（DNS 53 双协议）
⑤ 金句：IP 找机器、端口找服务
```

**Q2：TCP 和 UDP 的端口有什么区别？**

```text
① 空间独立：TCP 53 ≠ UDP 53（同一数字可同时用）
② TCP：面向连接（有监听/建立/关闭状态）
③ UDP：无连接（端口是接收数据的标签）
④ 双协议常见：DNS 53（UDP 查询 + TCP 传输）
⑤ 排查注意：ss -tlnp（TCP）vs ss -ulnp（UDP）
```

**Q3：127.0.0.1 和 0.0.0.0 绑定有什么区别？**

```text
① 127.0.0.1（localhost）：仅本机可访问（回环）
② 0.0.0.0：所有接口（本机 + 网络）
③ 经典故障：绑定 127.0.0.1 → 外部访问不到
④ 排查：ss -tlnp 看 LISTEN 行的绑定地址
⑤ 实践：对外服务 0.0.0.0；调试端口 127.0.0.1
```

### 1.2 清单类

**Q4：常见数据库端口有哪些？**

```text
① MySQL 3306 / PostgreSQL 5432
② SQL Server 1433 / Oracle 1521
③ MongoDB 27017 / Redis 6379
④ Elasticsearch 9200（REST）+ 9300（集群）
⑤ 连接串含端口：jdbc:mysql://host:3306/db
⑥ 安全：数据库端口绝不公网暴露
```

**Q5：Tomcat 的三个端口分别是什么？**

```text
① 8080：HTTP 连接器（访问入口）
② 8005：关闭端口（shutdown——勿暴露公网）
③ 8009：AJP 连接器（与 Apache 协作——Ghostcat 漏洞历史）
④ 2026 建议：不用 AJP 就禁用；8005 限本地
⑤ 生产：Nginx 80/443 → Tomcat 8080（内网）
```

**Q6：消息队列的端口？**

```text
① Kafka 9092（Broker 通信）
② RabbitMQ 5672（AMQP）+ 15672（管理界面）
③ RocketMQ 9876（NameServer）+ 10911（Broker）
④ MQTT 1883/8883（物联网）
⑤ 排查：生产者连不上 → 9092 防火墙 + 监听
```

### 1.3 排查类

**Q7：端口被占用怎么排查？（手写流程）**

```text
① 确认端口：报错信息（8080）
② 找占用进程：
   Windows：netstat -ano | findstr 8080 → PID
   Linux：ss -tlnp | grep 8080 → PID
③ 判断进程：tasklist / ps -p PID -f
④ 决策：自己的残留 → kill；别的服务 → 换端口
⑤ 验证：netstat/ss 确认释放
```

**Q8：服务连不上怎么排查？**

```text
四步排查：
① 服务在监听？（ss -tlnp | grep 端口）
② 绑定地址？（127.0.0.1 仅本机）
③ 防火墙？（ufw/firewalld/云安全组）
④ 网络？（nc -vz host 端口）
金句：监听 → 绑定 → 防火墙 → 网络
```

**Q9：CLOSE_WAIT 和 TIME_WAIT 的区别？**

```text
① CLOSE_WAIT：对方关闭、本端未关——程序 bug！
   （连接未正确关闭——资源泄漏）
② TIME_WAIT：连接关闭后的等待期
   （正常机制——防旧包；高并发堆积可优化）
③ CLOSE_WAIT 堆积 → 查连接关闭逻辑（try-with-resources）
④ TIME_WAIT 多 → 连接复用优化
```

**Q10：Docker 端口映射后外部访问不到？**

```text
三层排查：
① 容器内：docker exec 容器 curl localhost:端口
② 宿主：curl localhost:宿主端口
③ 外部：nc -vz 宿主IP 端口
根因举例：安全组未放行/防火墙/绑定 127.0.0.1
金句：容器内 → 宿主 → 外部 三层验证
```

### 1.4 安全类

**Q11：Redis 6379 为什么高危？**

```text
① 默认无认证（bind 127.0.0.1 是默认防护）
② 公网暴露攻击链：连接 → 写 SSH 公钥 → 登录服务器！
③ 防护：bind 内网 + requirepass + 禁危险命令
④ 2026 红线：Redis 绝不公网暴露
⑤ 其他默认无认证：MongoDB 老版本/ES 老版本
```

**Q12：哪些端口绝不能公网暴露？**

```text
🔴 高危清单：
① 445 SMB（永恒之蓝）——勒索软件传播通道
② 3389 RDP（勒索软件部署第一向量）
③ 6379 Redis / 27017 MongoDB（无认证默认）
④ 3306 MySQL / 5432 PG（数据大门）
⑤ 2375 Docker（远程 API——容器接管）
⑥ 1099 RMI / 9200 ES（反序列化/数据泄露）
正确做法：数据库驻私有子网 + 远程走 SSH 隧道/VPN
```

**Q13：K8s 的端口体系？**

```text
① 四层暴露：ClusterIP（集群内）/NodePort（30000-32767）
   /LoadBalancer（云）/Ingress（生产 HTTP 标准）
② 组件端口：API Server 6443 + etcd 2379 + Kubelet 10250
③ etcd 公网暴露 = 集群被接管（🔴）
④ 金句：Ingress → Service → Pod 多层映射
```

**Q14：端口耗尽是什么？怎么解决？**

```text
① 现象：大量连接失败（address already in use）
② 根因：动态端口耗尽（49152-65535 用完）
③ 高并发短连接场景（每次连接用新端口）
④ 临时：扩大动态端口范围（netsh）
⑤ 根本：连接复用（连接池）/减少短连接
```

## 3. 五大常见误区

| # | 误区 | 真相 |
|---|------|------|
| 1 | 「端口一样就冲突」 | TCP 与 UDP 空间独立——同数字可同时用于两者 |
| 2 | 「绑定 127.0.0.1 也能对外」 | 仅本机——对外必须 0.0.0.0 |
| 3 | 「服务监听 = 外部可访问」 | 还有防火墙/安全组/绑定地址三层 |
| 4 | 「Redis 默认有密码」 | 默认无认证！暴露公网 = 可被写入公钥 |
| 5 | 「改端口只是配置问题」 | 改端口 = 破坏约定（所有连接方要同步） |

> 🎯 **系列总结**：端口知识 = **原理（分类与协议）× 清单（常用端口）× 实战（占用排查）× 安全（暴露红线）** 四维能力。2026 年端口实践标准答案：**常用端口背下来、排查按三层（监听→绑定→防火墙）、高危端口绝不公网（Redis/445/3389/Docker）**——连不上不慌、启动失败秒解、暴露风险可控。
