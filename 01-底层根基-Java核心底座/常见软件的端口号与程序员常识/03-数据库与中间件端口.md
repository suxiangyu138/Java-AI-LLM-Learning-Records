## 1. 数据库端口

> **背景**：数据库端口是「数据的大门」——连不上 = 服务不可用；暴露公网 = 数据风险。
> **目的**：掌握主流数据库默认端口与配置。
> **适用范围**：所有使用数据库的开发与运维。

| 端口 | 数据库 | 说明 |
|:---:|--------|------|
| **3306** | MySQL / MariaDB | 最主流开源数据库 |
| **5432** | PostgreSQL | 开源数据库（功能全面） |
| **1433** | SQL Server | 微软数据库 |
| **1521** | Oracle | Oracle TNS 监听 |
| **27017** | MongoDB | 文档型数据库 |
| **9042** | Cassandra | 分布式 NoSQL |
| **9200/9300** | Elasticsearch | REST API / 集群通信 |
| **11211** | Memcached | 分布式内存缓存 |

```text
数据库端口关键认知
├── ① 默认端口可改（配置文件）——改了要同步所有连接方
├── ② 连接串包含端口：jdbc:mysql://host:3306/db
├── ③ 连不上排查顺序：
│   1. 服务在监听？（ss -tlnp | grep 3306）
│   2. 防火墙放行？（本机 + 云安全组）
│   3. 绑定地址？（127.0.0.1 仅本机）
│   4. 网络可达？（nc -vz host 3306）
├── ④ 多实例：同机多个 MySQL 用不同端口（3306/3307）
└── ⑤ 容器映射：宿主端口 ↔ 容器端口（-p 3307:3306）
```

## 2. Redis 与缓存

### 2.1 Redis（6379）

> 🔴 **Redis 是「默认无认证」的高危服务**——暴露公网 = 可被写入 SSH 公钥夺取服务器（经典攻击）：

```text
Redis 6379 的攻防
├── ① 默认无密码（bind 127.0.0.1 是默认防护）
├── ② 公网暴露后果（真实攻击链）：
│   1. 扫描 6379 开放端口
│   2. 连接（无认证）
│   3. 写入 SSH 公钥（config set dir）
│   4. 登录服务器！
├── ③ 防护基线：
│   ├── bind 127.0.0.1（默认）或内网 IP
│   ├── requirepass 强密码
│   ├── rename-command 禁用危险命令（FLUSHALL 等）
│   └── 防火墙限源（公网禁止 6379）
└── ④ 2026 红线：Redis 绝不公网暴露

配置示例（redis.conf）
bind 127.0.0.1 192.168.1.10   # 内网绑定
requirepass strong-password    # 认证
rename-command FLUSHALL ""     # 禁用危险命令
```

### 2.2 其他缓存

```text
缓存服务端口
├── Memcached(11211)：
│   ├── 分布式内存缓存（键值对）
│   ├── ⚠️ 默认无认证（仅内网）
│   └── 公网暴露 = 可被滥用
├── 对比（本仓库 Redis 系列）：
│   ├── Redis：数据结构丰富（List/Hash/Set）
│   ├── Memcached：简单键值（更轻量）
│   └── 2026 实践：Redis 为主（功能全）
```

## 3. 搜索引擎

### 3.1 Elasticsearch（9200/9300）

```text
Elasticsearch 双端口
├── 9200：RESTful API（HTTP）——开发对接
│   ├── http://localhost:9200 查看集群状态
│   ├── _search 查询 / _bulk 批量写入
│   └── 客户端：Java RestHighLevelClient/ElasticsearchClient
├── 9300：集群内部通信（TCP）
│   └── 节点间数据/状态同步
└── 安全提示：
    ├── ⚠️ 老版本默认无认证（数据泄露事件多）
    ├── 2026 实践：X-Pack 安全（内置认证）
    └── 公网暴露 9200 = 数据裸奔（🔴 红线）

常见问题
├── 9200 连不上：服务未启动/防火墙/绑定地址
├── 9300 集群不通：节点网络/防火墙
└── 端口冲突：9200 与开发服务冲突（改配置）
```

## 4. 消息队列

| 端口 | 消息队列 | 说明 |
|:---:|---------|------|
| **9092** | Kafka | Broker 核心通信 |
| **5672** | RabbitMQ | AMQP 协议（生产环境） |
| **15672** | RabbitMQ | Web 管理界面 |
| **9876** | RocketMQ | NameServer |
| **10911** | RocketMQ | Broker |
| **1883/8883** | MQTT / MQTTS | 物联网消息 |

```text
消息队列端口要点
├── ① Kafka(9092)：生产者/消费者连接
│   ├── 集群：多个 broker 同端口（配置列表）
│   └── 注意：9092 是「客户端端口」——协议端口不一定是监听端口
├── ② RabbitMQ 双端口：
│   ├── 5672：AMQP（应用连接）
│   └── 15672：管理界面（Web）
├── ③ RocketMQ 双组件：
│   ├── 9876：NameServer（路由）
│   └── 10911：Broker（消息存储）
└── ④ 排查：生产者连不上 → 9092 防火墙 + 监听 + 协议
```

## 5. 协调与注册中心

| 端口 | 服务 | 说明 |
|:---:|------|------|
| **2181** | ZooKeeper | 分布式协调（客户端连接） |
| **2888/3888** | ZooKeeper | 集群选举/同步 |
| **8848** | Nacos | 注册中心 + 配置中心 |
| **9848** | Nacos | gRPC 通信（新版） |
| **8500** | Consul | 服务发现 + 配置 |
| **2379/2380** | etcd | K8s 存储 / 集群通信 |

```text
协调服务端口要点
├── ① ZooKeeper 三端口（经典）：
│   ├── 2181：客户端连接（服务注册/发现）
│   ├── 2888：集群数据同步
│   └── 3888：Leader 选举
├── ② Nacos(8848)：注册 + 配置一体
│   ├── 8848：HTTP（控制台/客户端）
│   └── 9848：gRPC（Java 客户端新版）
├── ③ etcd(2379)：K8s 的「大脑存储」
├── ④ 排查：客户端连不上注册中心 → 2181/8848 可达性
└── ⑤ 安全：协调服务公网暴露 = 集群被接管（内网服务）
```

## 6. Java 生态中间件

| 端口 | 服务 | 说明 |
|:---:|------|------|
| **20880** | Dubbo | 微服务 RPC（默认） |
| **7001** | WebLogic | 老牌 Java 中间件（🔴 漏洞多） |
| **8005/8009** | Tomcat | 关闭端口 / AJP |
| **1099** | RMI | Java 远程调用（⚠️ 高危） |
| **9090** | Spring Boot Actuator | 监控端点（部分配置） |

```text
Java 生态端口要点
├── ① Dubbo(20880)：RPC 服务暴露
│   ├── 多服务多端口（可配置）
│   └── 注册中心协调（Nacos/ZK）
├── ② RMI(1099)：远程方法调用
│   ├── ⚠️ 公网暴露 1099 = 高危（反序列化漏洞历史）
│   └── 内网使用 + 限源
├── ③ WebLogic(7001)：历史漏洞多（🔴 补丁要及时）
└── ④ Actuator：监控端口暴露需鉴权
    └── 未鉴权的 actuator = 信息泄露（2026 常见漏洞）
```

## 7. 数据库端口安全红线

### 7.1 红线清单

```text
数据库/中间件端口安全红线（2026）
├── 🔴 绝不对公网开放：
│   ├── 3306 MySQL / 5432 PostgreSQL / 6379 Redis
│   ├── 27017 MongoDB / 9200 ES
│   └── 1099 RMI / 2375 Docker
├── 🔴 默认无认证的高危：
│   ├── Redis（无认证 + 可写公钥）
│   ├── MongoDB（老版本无认证——数据勒索事件）
│   └── ES 老版本（无认证——数据泄露）
├── 🟡 内网 + 限源：
│   ├── 消息队列（9092/5672）
│   ├── 注册中心（2181/8848）
│   └── 协调服务
└── ✅ 正确做法：
    ├── 数据库驻留私有子网（无公网路由）
    ├── 远程访问走 SSH 隧道/VPN（见端口转发系列）
    └── 防火墙 + 云安全组双重限制
```

### 7.2 连接排查三板斧

```bash
# ① 端口监听检查（服务是否启动）
ss -tlnp | grep -E '3306|6379'        # Linux
netstat -ano | findstr "3306"         # Windows

# ② 连通性测试（网络与防火墙）
nc -vz 192.168.1.10 3306              # TCP 可达？
telnet 192.168.1.10 3306

# ③ 连接验证（应用级）
mysql -h 192.168.1.10 -P 3306 -u root -p   # MySQL
redis-cli -h 192.168.1.10 -p 6379 -a pass   # Redis
curl http://192.168.1.10:9200               # ES

# 金句：连不上按「监听 → 网络 → 防火墙 → 应用」顺序排查
```

## 8. 核心要点

> 🎯 **核心要点**：
> 1. 数据库端口全家：MySQL 3306 / PG 5432 / SQL Server 1433 / Oracle 1521 / MongoDB 27017——连接串包含端口
> 2. **Redis 6379 是经典高危**：默认无认证 + 可写 SSH 公钥夺服务器——bind 内网 + requirepass + 禁危险命令
> 3. ES 双端口：9200（REST API）+ 9300（集群通信）——老版本无认证是数据泄露重灾区
> 4. 消息队列端口：Kafka 9092 / RabbitMQ 5672+15672 / RocketMQ 9876+10911
> 5. 协调服务：ZK 2181/2888/3888 三端口 / Nacos 8848+9848 / etcd 2379
> 6. 安全红线：数据库/Redis/MongoDB/ES/RMI/Docker 端口**绝不对公网开放**——远程访问走 SSH 隧道/VPN
