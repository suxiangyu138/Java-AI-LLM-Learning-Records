## 1. Web 协议端口

> **背景**：HTTP/HTTPS 是互联网的基础协议——80/443 是「全球约定」的默认端口。
> **目的**：掌握 Web 端口语义与常见坑。
> **适用范围**：所有 Web 开发与运维。

| 端口 | 协议 | 用途 | 安全提示 |
|:---:|:---:|------|---------|
| **80** | HTTP | 明文 Web | 生产应跳转 HTTPS |
| **443** | HTTPS | 加密 Web | **Web 生产标准** |
| **8080** | HTTP-ALT | 开发/代理（Tomcat 默认） | 开发环境 |
| **8443** | HTTPS-ALT | HTTPS 测试非特权端口 | 测试环境 |
| **8000** | HTTP | Python 后端/Django/FastAPI | 开发 |

```text
Web 端口关键认知
├── ① 80/443 是「隐含默认」：访问 https:// 自动用 443
├── ② 改端口 = 用户必须显式指定（https://x:8443）
├── ③ 80 → 443 跳转：Nginx/云负载均衡配置
├── ④ 国内合规：对外 Web 服务需 ICP 备案（80/443）
├── ⑤ 开发环境：8080/8000 免特权绑定（<1024 需 root）
└── ⑥ 2026 现状：HTTPS 已是绝对主流（HTTP 仅跳转用）

Web 端口排查
├── 连不上 80 → 防火墙放行？服务在监听？（ss -tlnp）
├── 访问到别的服务 → 端口冲突（两个服务争 80）
└── 443 证书错误 → 证书配置（不是端口问题）
```

## 2. 远程管理端口

| 端口 | 协议 | 用途 | 安全提示 |
|:---:|:---:|------|---------|
| **22** | SSH | 安全远程登录/SFTP/SCP | **密钥认证 + 限源** |
| **23** | Telnet | 明文远程登录 | ❌ 已废弃（明文！） |
| **3389** | RDP | Windows 远程桌面 | 🔴 **勒索软件首要目标** |
| **5900-5906** | VNC | 跨平台远程桌面 | 需强密码 |
| **5985/5986** | WinRM | Windows 远程管理 | 内网使用 |
| **6000-6063** | X11 | Linux 图形转发 | 公网禁止 |

```text
远程管理端口安全（2026 红线）
├── ① SSH(22)：密钥认证 + 改高位端口 + fail2ban
│   （详见本仓库 SSH 系列）
├── ② RDP(3389)：勒索软件部署第一大向量
│   ├── 公网暴露 3389 = 持续被爆破
│   ├── 建议：VPN/网关访问（不直接暴露）
│   └── 必须暴露：改端口 + 限源 + 2FA
├── ③ Telnet(23)：明文——密码可被嗅探（废弃）
├── ④ VNC(5900)：无加密（SSH 隧道封装）
└── ⑤ 金句：远程管理端口 = 「服务器大门」——必须锁好
```

## 3. 邮件协议端口

### 3.1 邮件三协议

| 端口 | 协议 | 用途 | 加密版本 |
|:---:|:---:|------|---------|
| **25** | SMTP | 服务器间转发 | 465(SMTPS) |
| **110** | POP3 | 邮件下载（本地） | 995(POP3S) |
| **143** | IMAP | 邮件管理（多端同步） | 993(IMAPS) |
| **587** | SMTP-MSA | 客户端提交邮件 | 465 或 587 |

```text
邮件端口语义（程序员常识）
├── ① SMTP(25)：发信（服务器间转发）
│   ├── 客户端提交用 587（25 常被云厂商封锁防垃圾邮件）
├── ② POP3(110)：收信（下载到本地——邮件离开服务器）
├── ③ IMAP(143)：收信（留在服务器——多设备同步）
├── ④ 加密版：465(SMTPS)/993(IMAPS)/995(POP3S)
└── ⑤ 2026 实践：邮件客户端用加密端口（587/993/995）
```

## 4. DNS 与时间同步

### 4.1 DNS（53）

```text
DNS 端口语义（TCP 与 UDP 双协议）
├── ① UDP 53：常规域名查询（快、无连接）
├── ② TCP 53：区域传输 + 大响应（UDP 装不下时）
├── ③ 查询流程：客户端 → 本地 DNS → 递归 → 根服务器
├── ④ 排查：dig/nslookup（见本仓库 Ubuntu/网络系列）
└── ⑤ 常见问题：
    ├── DNS 解析慢 → 检查 DNS 服务器配置
    ├── DNS 污染 → 换公共 DNS（223.5.5.5 等）
    └── 容器内 DNS 异常 → 检查 /etc/resolv.conf
```

### 4.2 NTP（123）

```text
NTP 时间同步（123/UDP）
├── ① 作用：系统时间校准（所有服务依赖正确时间）
├── ② 时间不准的后果：
│   ├── 日志时间错乱（排障困难）
│   ├── 证书验证失败（HTTPS 依赖时间）
│   ├── 分布式系统一致性问题
│   └── 定时任务错乱
├── ③ 2026 实践：容器/云服务器统一 NTP 配置
└── ④ 排查：timedatectl status（Linux）
```

## 5. 文件传输端口

| 端口 | 协议 | 用途 | 安全提示 |
|:---:|:---:|------|---------|
| **20/21** | FTP | 数据传输/控制 | ❌ 明文——用 SFTP |
| **69** | TFTP | 简单文件传输（UDP） | 局域网/嵌入式 |
| **873** | Rsync | Linux 文件同步 | 认证 + 限源 |
| **445** | SMB/CIFS | Windows 文件共享 | 🔴 **永恒之蓝漏洞** |

```text
文件传输端口要点
├── ① FTP(20/21)：明文（密码可嗅探）——现代用 SFTP(22)
├── ② SMB(445)：Windows 共享——「永恒之蓝」漏洞载体
│   ├── 公网暴露 445 = 高危（勒索软件传播通道）
│   └── 2026 红线：445 绝不对公网开放
├── ③ Rsync(873)：增量同步（备份场景）
└── ④ 传输选型（本仓库「端口转发」系列相关）：
    ├── 大文件：rsync（增量+断点）
    ├── 安全传输：SFTP/SCP（走 SSH 22）
    └── 网页传输：HTTPS（443）
```

## 6. 网络管理与认证

| 端口 | 协议 | 用途 | 说明 |
|:---:|:---:|------|------|
| **161/162** | SNMP | 设备监控/告警（UDP） | 网络设备 |
| **389** | LDAP | 目录访问/统一认证 | 企业认证 |
| **636** | LDAPS | 加密目录访问 | LDAP + TLS |
| **88** | Kerberos | 身份认证 | Windows 域 |
| **1812/1813** | RADIUS | AAA 认证/计费 | 网络接入 |
| **514** | Syslog | 系统日志收集（UDP） | 日志平台 |
| **67/68** | DHCP | IP 分配（UDP） | 局域网 |
| **179** | BGP | 边界路由（TCP） | 骨干网络 |

```text
认证相关端口要点
├── ① LDAP(389)/LDAPS(636)：企业统一认证（AD 域）
├── ② Kerberos(88)：域认证的核心协议
├── ③ RADIUS(1812)：WiFi/VPN 接入认证
├── ④ Syslog(514)：日志集中收集（安全审计）
└── ⑤ 程序员场景：
    ├── 对接企业 LDAP 认证 → 389/636
    ├── 接入日志平台 → syslog 514
    └── VPN 认证 → RADIUS 1812
```

## 8. 核心要点

> 🎯 **核心要点**：
> 1. Web 双端口：80（HTTP 跳转用）/443（HTTPS 生产标准）——改端口 = 用户要显式指定
> 2. 远程管理安全红线：SSH 22 密钥认证 + RDP 3389 走 VPN（勒索软件第一向量）+ Telnet 已废弃
> 3. 邮件四端口：SMTP 25/587（发信）+ POP3 110/IMAP 143（收信）——加密版 465/995/993
> 4. DNS 53 双协议（UDP 查询/TCP 传输）+ NTP 123 时间同步（时间不准 = 证书/日志/分布式全乱）
> 5. 445 SMB 是「永恒之蓝」载体——**绝不对公网开放**；FTP 明文已淘汰（用 SFTP）
> 6. 速查表 21 个端口背下来——面试与排障高频
