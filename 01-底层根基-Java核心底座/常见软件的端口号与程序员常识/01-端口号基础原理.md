## 1. 端口号是什么

> **背景**：一台服务器运行多个服务（Web/数据库/缓存）——数据包到达后怎么知道交给谁？端口号解决「同一 IP 上多服务寻址」。
> **目的**：理解端口在传输层的作用。
> **适用范围**：所有网络编程与排障。
> **前提假设**：端口是传输层（TCP/UDP）概念——IP 负责「到哪台机器」，端口负责「交给哪个服务」。

```text
端口的本质
├── 类比：IP = 楼栋地址（找到服务器）
│         端口 = 房间号（找到服务）
├── 格式：16 位无符号整数（0-65535）
├── 作用：传输层多路复用（一个 IP 承载多个服务）
└── 约定：服务启动时「绑定」一个端口——客户端连该端口 = 连该服务

寻址链路
客户端 → IP（找到服务器）→ 端口（找到服务）→ 进程（处理请求）
      ├── 源 IP + 源端口（客户端侧）
      └── 目的 IP + 目的端口（服务侧）
```

## 2. 三类端口范围

> 🎯 **端口分三类**（IANA 分配）——记住分类就懂「为什么有的要 root、有的不用」：

| 范围 | 类型 | 特点 | 示例 |
|:---:|------|------|------|
| **0-1023** | 公认端口（知名端口） | 标准协议、**需管理员/root 权限绑定** | 80 HTTP / 443 HTTPS / 22 SSH |
| **1024-49151** | 注册端口 | 主流应用、普通用户可绑定 | 3306 MySQL / 6379 Redis |
| **49152-65535** | 动态/私有端口 | 客户端临时端口、用完释放 | 浏览器连接的源端口 |

```text
三类端口的实际意义
├── ① 公认端口：标准协议固定（客户端默认知道）
│   ├── 访问 https:// 默认 443（不用指定）
│   └── ⚠️ 绑定需 root（Linux <1024）
├── ② 注册端口：主流软件约定（MySQL 3306 等）
│   └── 修改需客户端同步（改了 3306 要告诉所有连接方）
├── ③ 动态端口：客户端出站连接随机分配
│   └── 连接关闭后释放（重复使用）
→ 金句：常见服务用「约定端口」——改端口 = 破坏约定（需同步所有人）
```

## 3. TCP vs UDP 的端口空间

### 3.1 独立空间

> 🎯 **TCP 与 UDP 各有独立的端口空间**——同一个数字可以同时用于 TCP 和 UDP 且不冲突：

```text
关键认知
├── ① 端口号空间独立：TCP 53 ≠ UDP 53
├── ② 常见双协议：DNS 53（UDP 查询 + TCP 区域传输）
├── ③ 服务绑定：socket 绑定需指定协议
│   ├── TCP 监听 8080 → 只接受 TCP 连接
│   └── UDP 监听 53 → 只处理 UDP 数据报
├── ④ 排查注意：ss -tlnp（TCP）vs ss -ulnp（UDP）
└── ⑤ 防火墙注意：放行时指定协议（TCP 8080 ≠ UDP 8080）

程序中的体现
// Java ServerSocket = TCP
new ServerSocket(8080);                    // TCP 监听
// Java DatagramSocket = UDP
new DatagramSocket(53);                    // UDP 监听
// 两者可同时绑定 8080（不同协议互不冲突）
```

### 3.2 协议与端口的组合

```text
协议的端口语义
├── TCP：面向连接——端口有「监听/建立/关闭」状态
├── UDP：无连接——端口只是「接收数据的标签」
├── TCP 常见：HTTP(80)/HTTPS(443)/SSH(22)/MySQL(3306)
├── UDP 常见：DNS(53)/NTP(123)/SNMP(161)/DHCP(67)
└── 双协议：DNS(53)/NTP(123)/HTTPS(443 支持 QUIC)
```

## 4. 绑定与监听

### 4.1 绑定（Bind）

```text
绑定的本质
├── ① 服务启动 → 向系统申请「占用某端口」
├── ② 绑定成功 → 该端口归该进程（其他进程绑定失败）
├── ③ 绑定失败 → 端口被占用（最常见的启动失败！）
├── ④ 绑定地址：可指定 IP（127.0.0.1 仅本机 / 0.0.0.0 全部）
└── ⑤ 释放：进程退出 → 端口自动释放（TIME_WAIT 可能延迟）

Java 绑定示例
new ServerSocket(8080);        // 绑定所有接口 8080
new ServerSocket(8080, 50, InetAddress.getByName("127.0.0.1"));
// 仅本机可访问（安全）
```

### 4.2 监听状态（LISTEN）

```text
端口状态（ss/netstat 查看）
├── LISTEN：服务在监听（等待连接）
├── ESTABLISHED：已建立连接
├── TIME_WAIT：连接关闭后的等待（防旧包）
├── CLOSE_WAIT：对方关闭、本端未关（程序 bug 常见）
└── 排查：ss -tlnp 看 LISTEN（服务是否启动）

经典问题
├── 「服务启动了但连不上」→ 看端口是否 LISTEN + 绑定地址
├── 「端口 TIME_WAIT 堆积」→ 高并发短连接（调优方向）
└── 「CLOSE_WAIT 堆积」→ 程序未正确关闭连接（bug！）
```

## 5. IP + 端口：四元组

### 5.1 四元组概念

> 🎯 **网络连接用四元组唯一定位**：(源 IP, 源端口, 目的 IP, 目的端口)：

```text
四元组示例
客户端 192.168.1.10:52345 → 服务器 203.0.113.10:8080
├── 源 IP：192.168.1.10（客户端）
├── 源端口：52345（动态端口——客户端临时）
├── 目的 IP：203.0.113.10（服务器）
└── 目的端口：8080（服务端口）

为什么源端口是动态的
├── ① 每个连接独立源端口（多连接不冲突）
├── ② 动态范围 49152-65535（用完释放）
├── ③ 高并发时动态端口耗尽（经典故障！）
│   └── 现象：大量 TIME_WAIT + 无法建立新连接
│   └── 解法：调大动态端口范围/长连接复用
```

### 5.2 端口耗尽问题（2026 常见）

```text
Windows 端口耗尽（微软文档常见案例）
├── 症状：大量连接失败（address already in use）
├── 根因：动态端口耗尽（默认范围约 16K 个）
├── 检查：netstat -ano | findstr TIME_WAIT（数量巨大）
├── 临时缓解：扩大动态端口范围
│   netsh int ipv4 set dynamicport tcp start=10000 num=1000
├── 根本解法：连接复用（连接池）/减少短连接
└── 金句：端口耗尽 = 「门牌号用完了」——复用比扩容更治本
```

## 6. 特殊地址：127.0.0.1 与 0.0.0.0

### 6.1 绑定地址语义

| 地址 | 含义 | 访问范围 | 场景 |
|------|------|---------|------|
| **127.0.0.1**（localhost） | 本机回环 | 仅本机 | 本地开发/调试 |
| **0.0.0.0** | 所有接口 | 本机 + 网络 | 对外提供服务 |
| **具体 IP** | 指定网卡 | 仅该网卡 | 多网卡服务器 |
| **::** | IPv6 所有接口 | 同 0.0.0.0 | IPv6 环境 |

### 6.2 绑定地址的常见问题

```text
绑定地址引发的经典问题
├── ⚠️ 服务绑定 127.0.0.1 → 外部访问不到！
│   ├── 症状：本机能访问、外部 telnet 不通
│   ├── 排查：ss -tlnp 看绑定地址（127.0.0.1 vs 0.0.0.0）
│   └── 解法：绑定 0.0.0.0（或配置 host 地址）
├── ⚠️ 安全选择：调试端口绑定 127.0.0.1（不暴露公网）
├── ⚠️ 容器场景：容器内 127.0.0.1 ≠ 宿主机（网络隔离）
└── ⚠️ 防火墙：绑定 0.0.0.0 后需防火墙放行
→ 金句：连不上先看「绑定地址」——127.0.0.1 是「本机专属门牌」
```

## 7. 端口的生命周期

```text
端口生命周期（一次服务会话）
├── ① 服务启动 → 绑定端口（LISTEN）
├── ② 客户端连接 → 建立连接（ESTABLISHED）
├── ③ 数据传输 → 双向通信
├── ④ 连接关闭 → 释放
│   ├── 正常：TIME_WAIT 短暂存在后释放
│   ├── 异常：CLOSE_WAIT 堆积（程序 bug）
│   └── 强制：kill 进程 → 端口释放（可能 TIME_WAIT）
└── ⑤ 端口复用：SO_REUSEADDR（服务重启快速重绑）

工程要点
├── ① 服务重启端口占用：等 TIME_WAIT 或开 SO_REUSEADDR
├── ② kill -9 后端口未释放：等几秒（TIME_WAIT）
├── ③ 端口被未知进程占：netstat 找 PID → 确认后处理
└── ④ 容器端口映射：宿主机端口 ↔ 容器端口（见 05 篇）
```

## 8. 核心要点

> 🎯 **核心要点**：
> 1. 端口 = 服务的门牌号（0-65535）——IP 找机器、端口找服务
> 2. 三类端口：公认（0-1023，标准协议 + root 绑定）/注册（1024-49151，主流应用）/动态（49152+，客户端临时）
> 3. **TCP 与 UDP 端口空间独立**——同一数字可同时用于两者（DNS 53）
> 4. 绑定 = 申请占用；端口被占 = 最常见的启动失败；TIME_WAIT/CLOSE_WAIT 是排查线索
> 5. 四元组（源 IP/源端口/目的 IP/目的端口）——高并发端口耗尽（动态端口用光）
> 6. 绑定地址：127.0.0.1（仅本机）vs 0.0.0.0（对外）——「连不上先看绑定地址」
