## 1. Java 应用服务器端口

> **背景**：Java Web 部署的端口体系（Tomcat/Spring Boot/网关）——开发与生产的端口规划。
> **目的**：掌握 Java 生态端口配置与冲突处理。
> **适用范围**：Java Web 开发与部署。

| 端口 | 服务 | 说明 |
|:---:|------|------|
| **8080** | Tomcat / Spring Boot | HTTP 主端口（默认） |
| **8005** | Tomcat | 关闭命令端口（⚠️ 勿暴露） |
| **8009** | Tomcat | AJP 协议（⚠️ 历史漏洞） |
| **8443** | Tomcat | HTTPS 端口（配置时） |
| **9090** | 管理/监控 | 各种管理台 |

```text
Tomcat 三端口语义
├── ① 8080：HTTP 连接器（浏览器/客户端访问）
├── ② 8005：关闭端口（shutdown 命令——本地）
│   ├── ⚠️ 公网暴露 8005 = 可远程关闭服务！
│   └── 生产建议：禁用或限本地
├── ③ 8009：AJP 连接器（与 Apache/Nginx 协作）
│   ├── ⚠️ Ghostcat 漏洞（CVE-2020-1938）历史
│   └── 2026 建议：不使用 AJP 就禁用
└── 配置：server.xml 修改三端口

Nginx 反向代理模式（生产常见）
├── 80/443（Nginx）→ 8080（Tomcat 内网）
├── 好处：统一入口 + 静态资源 + HTTPS 终止
└── 内网 8080 不对公网（只 Nginx 可达）
```

## 2. Spring Boot 端口配置

### 2.1 配置方式

```yaml
# application.yml（Spring Boot 端口配置）
server:
  port: 8080                # HTTP 端口
  address: 0.0.0.0          # 绑定地址（默认所有接口）
  servlet:
    context-path: /api      # 上下文路径
  ssl:
    enabled: true           # HTTPS
    port: 8443              # HTTPS 端口
```

```bash
# 命令行覆盖（部署时）
java -jar app.jar --server.port=8081
# 环境变量
SERVER_PORT=8081 java -jar app.jar
# 多环境（见配置文件系列）
SPRING_PROFILES_ACTIVE=prod java -jar app.jar
```

### 2.2 端口相关配置要点

```text
Spring Boot 端口配置要点
├── ① server.port：HTTP 端口（默认 8080）
├── ② 随机端口：server.port=0（测试/多实例）
├── ③ 绑定地址：server.address=127.0.0.1（仅本机调试）
├── ④ 管理端口：management.server.port（Actuator 独立端口）
├── ⑤ 端口冲突：启动报 Port 8080 was already in use
└── ⑥ 多实例：不同端口（8080/8081/8082——负载均衡场景）

端口冲突处理（高频）
├── ① 找占用进程（见 06 篇）
├── ② 换端口（--server.port=8081）
├── ③ 或杀占用进程（确认是多余的）
└── ④ 常见占用者：另一个 Spring Boot/IDEA 残留/Tomcat
```

## 3. 前端开发端口

| 端口 | 框架/工具 | 说明 |
|:---:|---------|------|
| **3000** | React (CRA)/Node.js | 前端开发服务器 |
| **5173** | Vite（Vue/React） | 现代前端开发 |
| **4200** | Angular | Angular 开发服务器 |
| **8000** | Python 后端 | Django/FastAPI 开发 |
| **8080** | 后端 API（开发） | 前后端联调 |

```text
前端开发端口要点
├── ① 前端开发服务器（3000/5173）：热更新预览
├── ② 后端 API（8080）：接口服务
├── ③ 联调：前端代理转发（Vite proxy → 后端）
│   // vite.config.ts
│   server: {
│     port: 5173,
│     proxy: { '/api': 'http://localhost:8080' }
│   }
├── ④ 端口冲突：多个前端项目同端口
│   ├── Vite 自动换端口（5174）
│   └── 或配置固定端口
└── ⑤ 部署后：前端构建产物 → Nginx 80/443
    └── API 反代（/api → 后端 8080）
```

```text
前后端联调网络拓扑（开发）
浏览器 → localhost:5173（前端）
              ↓ proxy /api
         localhost:8080（后端 API）
              ↓
         localhost:3306（数据库）
→ 金句：开发期「本地多端口」、生产期「统一 80/443 反代」
```

## 4. 反向代理与网关

| 端口 | 服务 | 说明 |
|:---:|------|------|
| **80/443** | Nginx | 统一入口（生产标准） |
| **8080** | Nginx | 测试/备用 |
| **9000** | PHP-FPM | PHP 处理（Nginx 转发） |
| **8888** | 面板 | 宝塔等面板（⚠️ 限源） |
| **8080/8443** | 网关 | 微服务网关（Zuul/Gateway 默认） |

```text
Nginx 端口规划（生产标准）
├── ① 80：HTTP → 跳转 HTTPS
├── ② 443：HTTPS（证书终止）
├── ③ 反代目标：内网服务（8080/其他端口——不暴露公网）
├── ④ 配置要点：
│   server {
│       listen 443 ssl;
│       location /api/ {
│           proxy_pass http://backend:8080;
│       }
│   }
└── ⑤ 金句：生产统一「443 入口 + 内网多端口」——公网只见 443

微服务网关
├── 网关端口（8080 等）统一入口
├── 路由到各服务（随机/注册端口）
└── 注册中心协调（Nacos 8848）
```

## 6. 开发端口冲突实战

### 6.1 冲突场景

```text
开发端口冲突的常见场景
├── ① 两个 Spring Boot 项目都默认 8080
├── ② 前端 5173 被占用（Vite 自动换 5174）
├── ③ IDE 残留进程占端口（IDEA 关闭后 java 进程还在）
├── ④ 本地数据库 3306 与容器映射冲突
├── ⑤ 全局工具（代理/抓包）占 8080
└── ⑥ 网盘/下载工具占 80（老问题）

经典流程（端口被占怎么办）
① 确认哪个进程占：netstat/ss（见 06 篇）
② 判断是否可杀：自己的残留 → 杀；系统服务 → 别动
③ 换端口：应用配置修改（--server.port=8081）
④ 验证：新端口可访问
⑤ 根治：IDE 停止时清理残留进程/统一端口规划
```

### 6.2 端口规划建议

```text
团队端口规划（避免冲突）
├── ① 约定规范：
│   ├── 前端：5173（Vite 默认）
│   ├── 后端：8080（主）/8081（备用）
│   ├── 数据库：3306（本地）
│   └── 管理：9090（监控）
├── ② 多项目：端口段分配（项目 A 8080/项目 B 8082）
├── ③ 容器：宿主端口映射规划（3307→3306 等）
└── ④ 文档化：端口清单写入 README（新人少踩坑）
→ 金句：端口冲突的根治 = 「规划」不是「救火」
```

## 8. 核心要点

> 🎯 **核心要点**：
> 1. Tomcat 三端口：8080（HTTP）+ 8005（关闭——勿暴露）+ 8009（AJP——历史漏洞，不用就禁）
> 2. Spring Boot 端口：server.port 配置 + 命令行/环境变量覆盖——冲突报 `Port was already in use`
> 3. 前端开发：5173（Vite）/3000（React）——联调用 proxy 转发到后端 8080
> 4. 生产标准：**443 统一入口（Nginx）+ 内网多端口**——公网只见 443
> 5. 监控标配：Prometheus 9090 + Grafana 3000 + Alertmanager 9093
> 6. 端口冲突根治 = 规划（团队端口规范）不是救火；端口清单写入 README
