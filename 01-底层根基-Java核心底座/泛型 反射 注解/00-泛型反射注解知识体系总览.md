### 3.2 各层协作细节

| 协作场景 | 泛型角色 | 反射角色 | 注解角色 |
|---------|---------|---------|---------|
| Spring `@Autowired` 注入 | 依赖类型安全检查 | `Field.set()` 运行时赋值 | `@Autowired` 标记注入点 |
| MyBatis Mapper + `@Select` | `List<User>` 返回类型保障 | `Proxy.newProxyInstance()` 创建代理 | `@Select` 提供 SQL 元数据 |
| JPA `@Entity` 实体映射 | `JpaRepository<User, Long>` 泛型约束 | `EntityManager` 反射读写字段 | `@Column` 映射列名 |
| Spring AOP 切面 | 切点表达式泛型匹配 | JDK/CGLIB 动态代理生成 | `@Aspect` 标记切面类 |
| Jackson JSON 序列化 | `List<T>` 类型令牌 `TypeReference` | `ObjectMapper` 反射读 getter | `@JsonProperty` 重命名 |
| JUnit 5 参数化测试 | `@MethodSource` 返回 `Stream<Arguments>` | `Method.invoke()` 执行测试 | `@ParameterizedTest` 标记 |
| Retrofit HTTP 客户端 | `Call<Result>` 泛型声明返回类型 | 动态代理实现接口方法 | `@GET("/api/users")` 定义端点 |

### 3.3 生命周期维度

```
编译时 (Compile)             运行时 (Runtime)
───────────────────────────────────────────────►
                                                        
泛型类型擦除                                         反射破封装
(编译期检查, 运行时擦除)                              (运行时全知)
        │                                                 │
        │                                                 │
        ▼                                                 ▼
┌─────────────────┐                           ┌─────────────────────┐
│ 注解APT编译期处理 │                           │ 注解运行期反射处理    │

│  MapStruct)     │                           │                     │
└─────────────────┘                           └─────────────────────┘
```

> 💡 **关键认知**：泛型是 Java 为了兼容旧版本而做的"编译期假把戏"（类型擦除），反射是 Java 提供的"运行时通行证"（突破封装），注解是"贴在代码上的标签"（供编译期或运行期读取）。三者分别在**不同阶段**发挥作用，但框架将它们串联成完整链路。

## 4. 核心概念速查

### 4.1 泛型 (36 概念)

| 概念 | 一句话描述 | 关键点 |
|------|-----------|--------|
| 类型擦除 Type Erasure | 编译后泛型信息被移除，替换为 Object 或上界 | 无界 → Object，有界 → 上界类型 |
| Signature 属性 | 字节码中保留的泛型元数据签名 | 可通过反射 `getGenericType()` 读取 |
| 通配符 `?` | 未知类型的占位符 | 用于方法参数声明，不可用于实例化 |
| 上界通配符 `? extends T` | 类型是 T 或 T 的子类 | **生产者**：读取安全，写入禁止 |
| 下界通配符 `? super T` | 类型是 T 或 T 的父类 | **消费者**：写入安全，读取受限 |
| 无界通配符 `?` | 任意类型 | `List<?>` 等价于 `List<? extends Object>` |
| PECS | Producer Extends, Consumer Super | 从集合读用 `extends`，写入集合用 `super` |
| 桥方法 Bridge Method | 编译器自动生成的合成方法，解决擦除后的多态冲突 | `synthetic bridge` 标志，返回值协变 |
| 泛型方法 `<T> T method()` | 方法级别定义类型参数 | 类型参数在返回类型前声明 |
| 类型推断 Type Inference | 编译器根据参数自动推断泛型类型 | Java 7 钻石操作符 `<>`，Java 8 改进 |
| 钻石操作符 `<>` | 简化泛型实例化写法 | `List<String> list = new ArrayList<>();` |
| 原始类型 Raw Type | 不使用泛型参数的类 | `List list = new ArrayList();` 不安全 |
| Heap Pollution | 堆中变量类型与实际类型不一致 | 常由 unchecked warning 导致 |
| `@SafeVarargs` | 声明可变参数方法安全 | 用于 `static final` 方法，抑制 Heap Pollution |
| `Unchecked` Warning | 编译器因类型擦除无法验证类型安全 | 可用 `@SuppressWarnings("unchecked")` |
| 泛型数组创建 | `new T[]` 不允许 | 因数组协变与泛型不变冲突 |
| `List<String>[]` | 不允许创建 | 类型擦除后无法检查数组元素 |
| 协变 Covariance | `String[]` 是 `Object[]` 的子类型 | 数组是协变的，泛型是不变的 |
| 不变 Invariance | `List<String>` 不是 `List<Object>` 的子类型 | 泛型安全性源于不变性 |
| 逆变 Contravariance | `<? super String>` 类型关系相反 | 通过下界通配符模拟 |
| 类型参数 Naming | 常用单字母：E(集合), K/V(键值), T(类型), R(返回) | 约定俗成的命名规范 |
| 多重边界 `T extends A & B` | 类型参数可以有多个上界 | 类在前，接口在后 |
| 静态方法泛型 | 静态方法不能使用类的泛型参数 | 必须自己声明类型参数 |
| 内部类泛型 | 非静态内部类可访问外部类的类型参数 | 静态内部类独立 |
| `Class<T>` | 类字面量的泛型版本 | `String.class` 的类型是 `Class<String>` |
| 类型令牌 Type Token | 用 `Class<T>` 传递类型信息 | Spring 的 `ResolvableType` 进阶用法 |
| `TypeReference` | Jackson 用于保留泛型信息 | 匿名内部类方式捕获类型 |
| `ResolvableType` | Spring 提供的泛型解析工具 | 可以解析类/方法/字段的泛型参数 |
| 泛型接口 | 实现类可以指定或保留泛型 | `Comparable<T>` 典型应用 |
| `Comparable<T>` | 泛型接口经典范例 | 避免强制类型转换 |
| 泛型构造函数 | 构造函数也可以有类型参数 | 较少使用但合法 |
| `catch(T e)` | 不允许捕获泛型类型异常 | 类型擦除后无法区分异常类型 |
| `throws T` | 允许在声明中抛出泛型异常 | 用于泛型异常处理模式 |
| `TypeVariable` | 反射 API 表示类型参数 | `TypeVariable.getBounds()` |
| `ParameterizedType` | 反射 API 表示参数化类型 | `ParameterizedType.getActualTypeArguments()` |
| 泛型擦除的五大后果 | ①不能 `instanceof` ②不能 `new T()` ③不能 `new T[]` ④静态字段线程共享 ⑤重载冲突 | 面试常考的五点 |

### 4.2 反射 (28 概念)

| 概念 | 一句话描述 | 关键点 |
|------|-----------|--------|
| `Class` 对象 | 每个类在 JVM 中的元数据表示 | 一个类只有一个 `Class` 实例 |
| 类加载 | JVM 将 `.class` 文件加载到方法区 | 三种方式：`Class.forName()` / `.class` / `getClass()` |
| `forName()` | 类加载的主动方式，执行静态块 | 常用于 JDBC 驱动加载 |
| `Constructor` | 构造方法反射封装 | `newInstance()` / `setAccessible()` |
| `Method` | 成员方法反射封装 | `invoke()` / `getParameterTypes()` |
| `Field` | 成员变量反射封装 | `get()` / `set()` / `setAccessible(true)` |
| `setAccessible()` | 绕过 Java 语言访问检查 | 影响性能（JIT 优化失效） |
| `getDeclaredField()` | 获取本类所有字段（含私有） | 不包括继承来的字段 |
| `getField()` | 获取 public 字段（含继承） | 仅限 public 可见性 |
| 动态代理 Dynamic Proxy | 运行时创建代理类实例 | 两种方案：JDK / CGLIB |
| `InvocationHandler` | JDK 代理方法调用的处理接口 | `invoke(proxy, method, args)` |
| `Proxy.newProxyInstance()` | JDK 创建代理实例的工厂方法 | 需要 `ClassLoader` + 接口数组 + `InvocationHandler` |
| 切面编程 AOP | 将横切关注点与业务逻辑分离 | 底层依赖动态代理 |
| 方法句柄 `MethodHandle` | Java 7 引入的轻量级反射 | 比 `Method.invoke()` 更快 |
| `VarHandle` | Java 9 引入的变量句柄 | 替代 `Unsafe` 的部分功能 |
| 反射性能开销 | 反射比直接调用慢 2~3 个数量级 | 主要开销：查找 + 装箱 + 访问检查 |
| 反射缓存优化 | 缓存 `Method` / `Field` 对象减少查找 | `ConcurrentHashMap` 缓存 Key |
| `InvocationTargetException` | `invoke()` 抛出的包装异常 | 用 `getCause()` 获取原始异常 |
| `AccessibleObject` | Field / Method / Constructor 的基类 | `setAccessible()` 方法在该类定义 |
| 模块化限制 | Java 9+ 模块系统限制反射 | `--add-opens` JVM 参数或 `Module.addOpens()` |
| `Unsafe` | 底层操作类（不推荐直接使用） | 可绕过 `Class`/`Constructor` 直接创建对象 |
| 反射获取泛型 | `ParameterizedType` / `TypeVariable` | 需要保留 Signature 属性的场景 |
| `getGenericSuperclass()` | 获取父类的泛型参数 | Spring `ResolvableType` 底层实现 |
| `AnnotatedElement` | 可被注解元素的接口 | `Class` / `Method` / `Field` 等都实现 |
| `isSynthetic()` | 判断是否是编译器合成元素 | 桥方法、匿名内部类等方法/类 |
| `isBridge()` | 判断是否是桥方法 | 专用于 `Method` 的判断 |
| 反射调用 setAccessible 的安全限制 | SecurityManager 检查权限 | JDK 17+ 默认不允许反射私有成员 |
| 反射在 Spring 中的 8 大应用 | IoC / DI / AOP / MVC / `@Transactional` / `@Cacheable` / 事件机制 / `@Value` 注入 | 高频面试题 |

### 4.3 注解 (22 概念)

| 概念 | 一句话描述 | 关键点 |
|------|-----------|--------|
| 注解本质 | 一种特殊的接口，继承自 `Annotation` | `@interface` 语法糖 |
| `Annotation` 接口 | 所有注解的公共父接口 | `annotationType()` / `equals()` / `hashCode()` |
| 元注解 Meta-Annotation | 定义注解的注解 | `@Retention` / `@Target` / `@Documented` / `@Inherited` / `@Repeatable` |
| `@Retention` | 注解保留策略 | SOURCE / CLASS / RUNTIME |
| `RetentionPolicy.SOURCE` | 仅源码，编译即丢弃 | `@Override` / `@SuppressWarnings` |
| `RetentionPolicy.CLASS` | 保留到字节码，运行时不加载 | 默认策略，APT 处理器可读取 |
| `RetentionPolicy.RUNTIME` | 运行时可通过反射读取 | Spring / MyBatis 注解都是 RUNTIME |
| `@Target` | 注解可修饰的元素类型 | TYPE / FIELD / METHOD / PARAMETER 等 |
| `@Documented` | 注解出现在 JavaDoc 中 | 按文档工具要求使用 |
| `@Inherited` | 注解可被子类继承 | 仅对类继承有效，接口和方法无效 |
| `@Repeatable` | 同一元素可重复使用同一注解 | Java 8 引入，需要容器注解 |
| 注解属性 | 注解中可以定义方法 | 返回类型受限：primitive / String / Class / Enum / Annotation / 数组 |
| 默认值 | 注解属性的默认值 | `default` 关键字定义 |
| 注解处理器 Annotation Processor | 编译期处理注解的工具 | `AbstractProcessor` / `RoundEnvironment` |
| APT (Annotation Processing Tool) | 编译期间扫描和处理注解 | Java 5 引入的 `javac` 功能 |
| `AbstractProcessor` | 自定义 APT 的基类 | `process()` 方法实现处理逻辑 |
| `RoundEnvironment` | 每轮处理的环境信息 | `getElementsAnnotatedWith()` |
| `Elements` | 编译时元素 API | `TypeElement` / `ExecutableElement` / `VariableElement` |
| Lombok | "编译期注解魔法" | `@Getter` / `@Setter` / `@Data` = APT + AST 修改 |
| `@Generated` | 标识代码由工具生成 | 标准注解，IDE 可识别 |
| `@Native` | 标识可被 native 代码访问的字段 | `@Retention(SOURCE)`，文档用途 |
| 运行时注解处理 | 反射 + 注解实现声明式编程 | `getAnnotations()` / `isAnnotationPresent()` |

## 5. 框架中的应用矩阵

| 框架 | 泛型 | 反射 | 注解 | 三者协同场景 |
|------|------|------|------|------------|
| **Spring Core** | `JdbcTemplate` 参数化查询、`ResolvableType` 解析 | IoC 反射创建 Bean、DI 反射注入属性 | `@Component`、`@Autowired`、`@Configuration` | Bean 定义 → 注解扫描 → 反射实例化 → 泛型类型解析 |
| **Spring AOP** | 切点表达式支持泛型类型匹配 | JDK 动态代理 / CGLIB 代理生成 | `@Aspect`、`@Before`、`@Around` | 注解标记切点 → 动态代理生成 → 泛型切点过滤 |
| **Spring MVC** | `ResponseEntity<T>`、`HandlerMethodArgumentResolver` | 请求参数反射绑定、`MethodParameter` 解析 | `@RequestMapping`、`@RequestParam`、`@RestController` | 注解路由映射 → 反射调用控制器方法 → 泛型返回类型处理 |
| **MyBatis** | Mapper 方法的泛型返回值 `List<User>` | `MapperProxy` 动态代理、`Reflector` 元数据解析 | `@Select`、`@Insert`、`@Param`、`@Results` | 注解提供 SQL → 动态代理生成 Mapper → 泛型映射结果集 |
| **MyBatis-Plus** | `Wrapper<T>` 泛型查询条件、`IService<T>` 通用服务 | 反射读取实体字段、自动填充 | `@TableName`、`@TableField`、`@TableId`、`@Version` | 注解映射表结构 → 反射自动 SQL 生成 → 泛型类型安全查询 |
| **Hibernate/JPA** | `JpaRepository<T, ID>`、`Specification<T>` | `EntityManager` 反射 ORM 映射 | `@Entity`、`@Column`、`@OneToMany`、`@Query` | 注解实体关系 → 反射读写字段 → 泛型查询接口 |
| **Jackson** | `TypeReference<List<T>>`、泛型反序列化 | `ObjectMapper` 反射读/写 getter/setter | `@JsonProperty`、`@JsonIgnore`、`@JsonFormat` | 注解自定义映射 → 反射字段操作 → 泛型类型信息保留 |
| **JUnit 5** | `@MethodSource` 返回 `Stream<Arguments>` | `Method.invoke()` 执行 @Test 方法 | `@Test`、`@ParameterizedTest`、`@BeforeEach` | 注解标记生命周期 → 反射执行测试方法 → 泛型参数化测试 |
| **Retrofit** | `Call<T>`、`Observable<T>` 泛型声明 | 接口动态代理实现 | `@GET`、`@POST`、`@Path`、`@Query` | 注解定义 HTTP → 动态代理生成实现 → 泛型解析返回类型 |
| **Lombok** | 泛型方法自动生成 | AST 语法树操作（非传统反射） | `@Getter`、`@Setter`、`@Data`、`@Builder` | 注解触发 APT → 编译期解析 AST → 泛型兼容代码生成 |
| **MapStruct** | 泛型映射方法 `List<T>` | APT 编译期生成映射实现类 | `@Mapper`、`@Mapping` | 注解定义映射规则 → APT 编译期生成 → 泛型安全类型转换 |
| **Feign** | 声明式 HTTP 客户端泛型返回 | 动态代理 + 反射方法解析 | `@FeignClient`、`@RequestMapping` | 注解定义服务 → 动态代理生成 → 泛型解析响应体 |
| **Spring Cloud Gateway** | `GatewayFilter` 泛型链式处理 | 反射加载 Filter 实现 | `@Component` 自动注册 | 注解注册组件 → 反射路由匹配 → 泛型类型安全断言 |
| **Spring `@Transactional`** | `TransactionAttribute` 泛型属性 | AOP 代理事务拦截 | `@Transactional` | 注解标记事务边界 → AOP 代理拦截 → 泛型异常回滚判定 |
| **gRPC** | `StreamObserver<T>` 泛型流式处理 | 动态代理 Stub 生成 | `@GrpcService` | 注解注册服务 → 动态代理调用 → 泛型消息序列化 |
| **Spring Validation** | 泛型校验器 `Validator<T>` | 反射字段值校验 | `@Valid`、`@NotNull`、`@Size` | 注解声明约束 → 反射读取字段 → 泛型校验逻辑执行 |
| **Spring Cache** | `CacheResolver` 泛型缓存键 | AOP 代理缓存拦截 | `@Cacheable`、`@CacheEvict` | 注解标记缓存 → 动态代理拦截 → 泛型参数键生成 |

> 💡 **面试官视角**：框架源码类面试题的本质就是在问"注解在哪里定义、反射在哪里调用、泛型在哪里做类型约束"。能说清楚三者在具体框架中的协作链路，远比死记硬背 API 重要。

## 6. 面试为何将三者放在一起考

### 6.1 三者天然互补

| 维度 | 泛型 | 反射 | 注解 |
|------|------|------|------|
| 时间 | 编译期（检查） | 运行时（突破） | 编译期/运行期（标记） |
| 作用 | 类型安全约束 | 动态访问操作 | 声明式元数据 |
| 对框架意义 | 保证 API 签名的类型安全 | 实现"写一次、通用执行" | 减少配置，声明即用 |
| 单独使用 | 集合框架、工具类 | 一般用不到（不安全） | 只有定义没处理器 = 装饰 |
| 协同使用 | 配合反射保留签名信息 | 配合注解读取元数据 | 配合反射在被标记处执行 |
| 面试考察点 | 编译原理理解 | JVM 运行时理解 | 声明式编程思想理解 |

### 6.2 面试官的底层逻辑

面试官将三者放在一起考，不是因为他们是"一个章节"，而是因为：

1. **框架原理题必涉及三者**：Spring 的 `@Transactional` 是怎么工作的？—— `@Transactional` 注解标记 → AOP 动态代理拦截 → 方法反射调用 → 泛型异常匹配。**一道题考三个知识域**。

2. **区分"会使用"和"懂原理"**：大部分人会用 `@Autowired`、会用 `List<String>`，但只有少数人能把"类型擦除 → 字节码 Signature → 反射 `getGenericType()` → Spring `ResolvableType` 解析 → 最终实现泛型注入"这条链说清楚。

3. **考察系统化思维**：能讲清楚三者关系的人，说明：
   - 理解编译期 vs 运行期的区别（JVM 基础扎实）
   - 理解框架设计的"声明式 + 反射执行"模式（框架设计思维）
   - 理解 Java 类型系统及其局限（语言深入程度）

### 6.3 典型面试题映射

| 面试题 | 涉及泛型 | 涉及反射 | 涉及注解 |
|--------|:-------:|:-------:|:-------:|
| `@Autowired` 工作原理 | ✅ 类型匹配 | ✅ 反射注入 | ✅ 标记注入点 |
| MyBatis Mapper 如何生成实现类 | ✅ 泛型返回值 | ✅ 动态代理 | ✅ Mapper 注解 |
| `@Transactional` 失效场景 | ✅ 异常类型匹配 | ✅ AOP 代理 | ✅ 注解声明 |
| Spring 为什么使用 CGLIB 而非 JDK 代理 | ✅ 泛型参数泛化 | ✅ 两种代理机制对比 | ❌ |
| Lombok 如何实现 `@Data` | ❌ | ✅ AST 修改 | ✅ 触发 APT |
| `@Cacheable` 的 Key 生成策略 | ✅ 参数泛型 | ✅ SpEL 反射求值 | ✅ 标记缓存行为 |
| `@JsonFormat` 反序列化支持枚举 | ✅ 泛型反序列化 | ✅ 反射写字段 | ✅ 日期格式标记 |
| Hibernate 懒加载代理对象原理 | ✅ 泛型实体 ID | ✅ CGLIB 代理 | ✅ `@Entity` 标记 |

> ⚠️ **在回答"三者关系"相关面试题时**：不要只回答泛型擦除是啥、反射 API 有哪些、注解有几种 RetentionPolicy——这些太基础。要做到"看到一个框架特性，能分析出它用了哪几个 Java 底层能力、分别在何时生效"。
