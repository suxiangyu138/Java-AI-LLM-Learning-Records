## 1. 反射的核心API

### 1.1 Class对象的获取方式

Java反射的起点是`Class<?>`对象。获取Class对象有三种方式，它们在时机和使用场景上各有不同。

```java
public class ReflectionDemo {

    static class User {
        private String name;
        private int age;

        public User() {}
        public User(String name, int age) {
            this.name = name;
            this.age = age;
        }

        private String secretMethod() {
            return "This is secret!";
        }

        @Override
        public String toString() {
            return "User{name='" + name + "', age=" + age + "}";
        }
    }

    public static void main(String[] args) throws Exception {
        // 方式一：Class.forName() —— 最常用，可用于全限定类名字符串
        // 优点：类名可在运行时动态决定（配置文件/参数传入）
        // 注意：会执行静态初始化块
        Class<?> clazz1 = Class.forName("com.example.ReflectionDemo$User");
        System.out.println("方式一: " + clazz1.getName());

        // 方式二：类名.class —— 最安全，编译时就确定
        // 优点：类型安全，不会抛ClassNotFoundException
        // 缺点：类名必须在编译期确定
        Class<User> clazz2 = User.class;
        System.out.println("方式二: " + clazz2.getName());

        // 方式三：对象.getClass() —— 已有实例时使用
        // 常用于多态场景，运行时获取实际类型
        User user = new User();
        Class<?> clazz3 = user.getClass();
        System.out.println("方式三: " + clazz3.getName());

        // 三种方式获取的是同一个Class对象
        System.out.println("同一个对象: " + (clazz1 == clazz2 && clazz2 == clazz3));
    }
}
```

```text
输出：
方式一: com.example.ReflectionDemo$User
方式二: com.example.ReflectionDemo$User
方式三: com.example.ReflectionDemo$User
同一个对象: true
```

### 1.2 Constructor的获取与调用

通过反射构造对象是框架中最常见的操作之一。

```java
public class ConstructorDemo {

    public static void main(String[] args) throws Exception {
        Class<?> clazz = User.class;

        // 获取所有public构造方法
        Constructor<?>[] publicConstructors = clazz.getConstructors();

        // 获取全部构造方法（包括private）
        Constructor<?>[] allConstructors = clazz.getDeclaredConstructors();

        // 获取无参构造（public）
        Constructor<?> noArgConstructor = clazz.getConstructor();
        Object user1 = noArgConstructor.newInstance();

        // 获取有参构造（public）
        Constructor<?> paramConstructor = clazz.getConstructor(String.class, int.class);
        Object user2 = paramConstructor.newInstance("Alice", 25);

        // 获取私有构造并调用 —— 需要setAccessible
        Constructor<?> privateConstructor = clazz.getDeclaredConstructor(String.class);
        privateConstructor.setAccessible(true);  // 暴力反射，跳过Java权限检查
        Object user3 = privateConstructor.newInstance("PrivateUser");

        System.out.println(user1);
        System.out.println(user2);
        System.out.println(user3);

        // 获取内部类的构造器（隐式带外部类引用参数）
        Class<?> innerClazz = User.Inner.class;
        Constructor<?> innerConstructor = innerClazz.getDeclaredConstructor(User.class);
        innerConstructor.setAccessible(true);
        Object inner = innerConstructor.newInstance(user1);
        System.out.println(inner);
    }
}
```

> 💡 **核心要点**：`getConstructor()` 只返回public构造方法，`getDeclaredConstructor()` 返回所有构造方法（包括private、protected、默认权限）。`setAccessible(true)` 可以绕过Java语言访问权限检查，是"暴力反射"的核心。

### 1.3 Field的获取与操作

```java
public class FieldDemo {

    public static void main(String[] args) throws Exception {
        Class<?> clazz = User.class;
        Object user = clazz.getDeclaredConstructor().newInstance();

        // 获取public字段
        Field[] publicFields = clazz.getFields();
        System.out.println("public字段数: " + publicFields.length);  // 0, 因为name和age都是private

        // 获取所有字段
        Field[] allFields = clazz.getDeclaredFields();
        for (Field field : allFields) {
            System.out.println("字段: " + field.getName() + " | 类型: " + field.getType());
        }

        // 操作私有字段
        Field nameField = clazz.getDeclaredField("name");
        nameField.setAccessible(true);
        nameField.set(user, "反射设置的名称");

        Field ageField = clazz.getDeclaredField("age");
        ageField.setAccessible(true);
        ageField.setInt(user, 30);

        System.out.println("读取字段: name=" + nameField.get(user) + ", age=" + ageField.getInt(user));

        // ⚠️ 绕过String不可变性的经典面试题
        String str = "Hello";
        Field valueField = String.class.getDeclaredField("value");
        valueField.setAccessible(true);
        char[] value = (char[]) valueField.get(str);
        value[0] = 'Y';
        value[1] = 'e';
        value[2] = 'l';
        value[3] = 'l';
        value[4] = 'o';
        System.out.println("修改后的字符串: " + str); // 输出: Yello

        // Java 9+ 对模块化系统的限制
        // 在module-info.java中使用open关键字或在启动参数添加--add-opens
    }
}
```

### 1.4 Method的获取与调用

```java
public class MethodDemo {

    public static void main(String[] args) throws Exception {
        Class<?> clazz = User.class;
        Object user = clazz.getDeclaredConstructor(String.class, int.class)
                .newInstance("Bob", 28);

        // 获取所有public方法（包括从父类继承的）
        Method[] publicMethods = clazz.getMethods();

        // 获取当前类所有方法（不包括继承的）
        Method[] declaredMethods = clazz.getDeclaredMethods();

        // 调用toString方法（public，继承自Object）
        Method toStringMethod = clazz.getMethod("toString");
        Object result = toStringMethod.invoke(user);
        System.out.println("toString: " + result);

        // 调用私有方法
        Method secretMethod = clazz.getDeclaredMethod("secretMethod");
        secretMethod.setAccessible(true);
        Object secret = secretMethod.invoke(user);
        System.out.println("secret: " + secret);

        // 调用静态方法
        Method staticMethod = clazz.getMethod("staticInfo");
        Object staticResult = staticMethod.invoke(null);  // 静态方法传入null实例
        System.out.println("static: " + staticResult);
    }
}
```

### 1.5 setAccessible的魔法与安全风险

`setAccessible(boolean)` 是 `AccessibleObject` 类的方法（Constructor/Field/Method的父类），它控制是否启用/禁用语言访问权限检查。

**原理：**
- 当 `setAccessible(false)`（默认）时，每次调用都会进行访问权限检查
- 当 `setAccessible(true)` 时，绕过访问权限检查，直接操作字段或调用方法

**安全风险：**

```java
// 风险1：破坏封装性——可以修改final字段
public class SecurityRiskDemo {

    public static void main(String[] args) throws Exception {
        // 修改Integer缓存
        Class<?> cacheClass = Integer.class.getDeclaredClasses()[0]; // IntegerCache
        Field cacheField = cacheClass.getDeclaredField("cache");
        cacheField.setAccessible(true);
        Integer[] cache = (Integer[]) cacheField.get(null);
        cache[130] = 1000;  // 修改 Integer.valueOf(5) 的缓存值

        System.out.println("2 + 3 = " + (2 + 3)); // 可能输出 1000 ???
        System.out.println("Integer.valueOf(5) = " + Integer.valueOf(5));
    }
}
```

> ⚠️ **setAccessible安全风险总结：**
> - 破坏封装：可以修改private/final字段
> - 绕过验证：可以调用设计上不应暴露的API
> - 模块系统限制：Java 9+模块化系统默认阻止反射访问，需使用 `--add-opens`
> - 生产环境建议：使用SecurityManager限制setAccessible权限

> 🎯 **核心要点**：`Class.forName()` 是最灵活的方式（配置驱动），`类名.class` 是最安全的方式（编译时确定），`对象.getClass()` 是运行时多态的常用方式。`setAccessible(true)` 是绕过访问控制的手段，但在Java 9+模块化系统中受到严格限制。

## 2. 反射性能深度剖析

### 2.1 反射方法调用为什么慢？

反射慢不是都市传说，它有四个层面的性能损耗：

**第一层：动态方法查找（Method resolution）**
- 直接调用时，JVM在编译期就确定了目标方法的符号引用，链接时直接解析
- 反射调用时，`Method.invoke()` 需要根据方法名称和参数类型，在运行期动态搜索方法

**第二层：访问权限检查（Access check）**
- 每次 `invoke()` 调用都会执行 `AccessibleObject.override` 检查和 `Reflection.quickCheckMemberAccess`
- 即使 `setAccessible(true)` 也并非完全消除检查，只是跳过了语言访问检查

**第三层：JIT内联失效（Inlining failure）**
- JIT编译器可以直接内联普通方法调用（invokevirtual被优化为内联代码）
- 反射调用通过 `Method.invoke()` 间接调用目标方法，调用链更长，JIT难以内联
- 内部涉及 `MethodAccessor.invoke()` 委派、native方法调用等

**第四层：自动装箱和数组分配（Boxing & array allocation）**
- `invoke(Object, Object...)` 需要将参数包装成Object数组
- 基本类型参数需要自动装箱（int -> Integer）
- 返回值也需要拆箱处理

### 2.2 基准测试数据对比

```java
import java.lang.invoke.MethodHandle;
import java.lang.invoke.MethodHandles;
import java.lang.invoke.MethodType;
import java.lang.reflect.Method;

public class ReflectionBenchmark {

    private static final int WARMUP = 10_000_000;
    private static final int ITERATIONS = 10_000_000;

    public static class Target {
        private int value = 42;

        public int getValue() {
            return value;
        }

        public void setValue(int value) {
            this.value = value;
        }
    }

    public static void main(String[] args) throws Throwable {
        Target target = new Target();
        Method reflectedMethod = Target.class.getMethod("getValue");
        reflectedMethod.setAccessible(true);

        // 预热
        for (int i = 0; i < WARMUP; i++) {
            target.getValue();
            reflectedMethod.invoke(target);
        }

        // 1. 直接调用 (baseline)
        long start = System.nanoTime();
        int sum = 0;
        for (int i = 0; i < ITERATIONS; i++) {
            sum += target.getValue();
        }
        long directTime = System.nanoTime() - start;

        // 2. 反射调用 (无setAccessible优化)
        start = System.nanoTime();
        sum = 0;
        for (int i = 0; i < ITERATIONS; i++) {
            sum += (int) reflectedMethod.invoke(target);
        }
        long reflectTime = System.nanoTime() - start;

        // 3. 反射 + setAccessible(true)
        // 注意: 实际上上面已经setAccessible了，但为了演示，单独测试
        Method reflectedAccessible = Target.class.getMethod("getValue");
        reflectedAccessible.setAccessible(true);
        start = System.nanoTime();
        sum = 0;
        for (int i = 0; i < ITERATIONS; i++) {
            sum += (int) reflectedAccessible.invoke(target);
        }
        long reflectAccessibleTime = System.nanoTime() - start;

        // 4. MethodHandle (Java 7+)
        MethodHandle mh = MethodHandles.lookup()
                .findVirtual(Target.class, "getValue", MethodType.methodType(int.class));
        start = System.nanoTime();
        sum = 0;
        for (int i = 0; i < ITERATIONS; i++) {
            sum += (int) mh.invokeExact(target);
        }
        long mhTime = System.nanoTime() - start;

        System.out.println("===== 性能对比 (1亿次调用) =====");
        System.out.printf("直接调用:       %10d ns  (基准 1.00x)%n", directTime);
        System.out.printf("反射(setAccess): %10d ns  (约 %.2fx)%n", reflectAccessibleTime,
                (double) reflectAccessibleTime / directTime);
        System.out.printf("反射(无优化):    %10d ns  (约 %.2fx)%n", reflectTime,
                (double) reflectTime / directTime);
        System.out.printf("MethodHandle:    %10d ns  (约 %.2fx)%n", mhTime,
                (double) mhTime / directTime);
    }
}
```

> 💡 **典型性能数据（参考值）：**
>
> | 调用方式 | 相对耗时 | 说明 |
> |---------|---------|------|
> | 直接调用 | 1x | 基准线 |
> | MethodHandle | 1.2x ~ 1.5x | 接近直接调用，JIT可内联 |
> | 反射 + setAccessible(true) | 2x ~ 10x | 最佳实践应使用 |
> | 反射（默认） | 10x ~ 50x+ | 每次做完整权限检查 |

### 2.3 反射优化策略

#### 策略一：setAccessible(true) + 缓存Method对象

```java
public class OptimizedReflection {

    private static final Map<Class<?>, Map<String, Method>> METHOD_CACHE = new ConcurrentHashMap<>();

    public static Method getCachedMethod(Class<?> clazz, String methodName, Class<?>... paramTypes) {
        return METHOD_CACHE
                .computeIfAbsent(clazz, k -> new ConcurrentHashMap<>())
                .computeIfAbsent(methodName + ":" + Arrays.toString(paramTypes), k -> {
                    try {
                        Method method = clazz.getDeclaredMethod(methodName, paramTypes);
                        method.setAccessible(true);
                        return method;
                    } catch (NoSuchMethodException e) {
                        throw new RuntimeException(e);
                    }
                });
    }

    // 使用示例——只需一次setAccessible和反射查找，后续调用复用Method对象
    public static void cachedInvokeDemo(Object target, String methodName) throws Exception {
        Method method = getCachedMethod(target.getClass(), methodName);
        // 多次调用只走invoke，无需再次查找和权限检查
        for (int i = 0; i < 1000; i++) {
            method.invoke(target);
        }
    }
}
```

#### 策略二：提前调用触发JIT优化

```java
// 在启动阶段（非热点路径）预先调用一次
// JIT会将频繁调用的Method.invoke()路径编译为本地代码
// 甚至可以在某些JVM版本中触发MethodAccessor从"委派模式"切换到"本地方法模式"
public class WarmupStrategy {

    public static void warmupReflection(Method method, Object target, Object... args) throws Exception {
        // 触发JIT编译优化
        for (int i = 0; i < 10_000; i++) {
            method.invoke(target, args);
        }
    }
}
```

#### 策略三：LambdaMetafactory —— 终极优化

```java
import java.lang.invoke.CallSite;
import java.lang.invoke.LambdaMetafactory;
import java.lang.invoke.MethodHandle;
import java.lang.invoke.MethodHandles;
import java.lang.invoke.MethodType;
import java.util.function.IntSupplier;

public class LambdaMetafactoryOptimization {

    public static IntSupplier createGetter(Object target, Method method) throws Throwable {
        MethodHandles.Lookup lookup = MethodHandles.lookup();
        MethodHandle targetHandle = lookup.unreflect(method);

        // 使用LambdaMetafactory生成getter的函数接口
        // 性能接近直接调用，因为JIT可以完全内联
        CallSite callSite = LambdaMetafactory.metafactory(
                lookup,
                "getAsInt",
                MethodType.methodType(IntSupplier.class, target.getClass()),
                MethodType.methodType(int.class),
                targetHandle,
                MethodType.methodType(int.class, target.getClass())
        );

        IntSupplier supplier = (IntSupplier) callSite.getTarget().invokeExact(target);
        return supplier;
    }

    public static void main(String[] args) throws Throwable {
        Target target = new Target();
        Method getter = Target.class.getMethod("getValue");

        // 生成一次，像直接调用一样快
        IntSupplier getterFunc = createGetter(target, getter);

        // 此后调用完全无反射开销
        for (int i = 0; i < 100_000; i++) {
            int val = getterFunc.getAsInt();  // 接近直接调用
        }
    }
}
```

> 🎯 **核心要点**：反射的性能损耗主要来自：方法查找、权限检查、JIT内联失效、装箱/数组包装。优化三板斧：**缓存Method对象**避免重复查找、**setAccessible(true)**跳过权限检查、**LambdaMetafactory**生成函数式接口实现接近直接的调用。在实际框架中，Spring等会在启动阶段完成反射调用的预热。

## 3. MethodHandle vs 反射

### 3.1 MethodHandle简介

Java 7引入`java.lang.invoke.MethodHandle`，它提供了类似反射的方法调用能力，但更轻量、更快速。MethodHandle本质上是**对方法、构造器、字段的"可操作引用"**，类似于C/C++中的函数指针。

```java
import java.lang.invoke.MethodHandle;
import java.lang.invoke.MethodHandles;
import java.lang.invoke.MethodType;

public class MethodHandleDemo {

    public static class Calculator {
        private int base = 10;

        public int add(int a, int b) {
            return a + b + base;
        }

        public static int multiply(int a, int b) {
            return a * b;
        }
    }

    public static void main(String[] args) throws Throwable {
        Calculator calc = new Calculator();
        MethodHandles.Lookup lookup = MethodHandles.lookup();

        // 1. 查找实例方法
        // MethodType: 参数类型列表，第一个是函数签名（返回值类型，参数类型...）
        MethodType mt = MethodType.methodType(int.class, int.class, int.class);
        MethodHandle addHandle = lookup.findVirtual(Calculator.class, "add", mt);

        // 调用: 第一个参数是接收者（this），后续是方法参数
        int result = (int) addHandle.invokeExact(calc, 3, 4);
        System.out.println("add(3,4) = " + result);  // 10 + 3 + 4 = 17

        // 2. 查找静态方法
        MethodHandle multiplyHandle = lookup.findStatic(
                Calculator.class, "multiply", mt);
        int mulResult = (int) multiplyHandle.invokeExact(5, 6);
        System.out.println("multiply(5,6) = " + mulResult);

        // 3. 访问私有字段（通过反射的查找对象）
        MethodHandle fieldHandle = lookup.findGetter(
                Calculator.class, "base", int.class);
        int baseVal = (int) fieldHandle.invokeExact(calc);
        System.out.println("base = " + baseVal);

        // 4. 绑定接收者——将实例方法转化为无接收者的方法句柄
        MethodHandle boundAdd = addHandle.bindTo(calc);
        int boundResult = (int) boundAdd.invokeExact(7, 8);
        System.out.println("boundAdd(7,8) = " + boundResult);

        // 5. 参数转换——MethodHandle是类型安全的
        // invokeExact要求精确类型匹配，invoke则允许自动类型转换
        Object objResult = addHandle.invoke(calc, 1, 2);  // invoke自动转型
        System.out.println("invoke result = " + objResult);
    }
}
```

### 3.2 MethodHandle vs 反射API对比

```java
import java.lang.invoke.*;
import java.lang.reflect.Method;

public class MethodHandleVsReflection {

    public static class Service {
        public void doWork(String input) {
            // 模拟业务逻辑
            String result = input.toUpperCase();
        }
    }

    public static void main(String[] args) throws Throwable {
        Service service = new Service();
        int WARMUP = 10_000_000;
        int ITER = 10_000_000;

        // === 反射方式 ===
        Method reflectMethod = Service.class.getMethod("doWork", String.class);
        long start = System.nanoTime();
        for (int i = 0; i < WARMUP; i++) {
            reflectMethod.invoke(service, "test");
        }
        start = System.nanoTime();
        for (int i = 0; i < ITER; i++) {
            reflectMethod.invoke(service, "test");
        }
        long reflectTime = System.nanoTime() - start;

        // === MethodHandle方式 ===
        MethodHandles.Lookup lookup = MethodHandles.lookup();
        MethodType mt = MethodType.methodType(void.class, String.class);
        MethodHandle mh = lookup.findVirtual(Service.class, "doWork", mt);
        // 预热
        for (int i = 0; i < WARMUP; i++) {
            mh.invokeExact(service, "test");
        }
        start = System.nanoTime();
        for (int i = 0; i < ITER; i++) {
            mh.invokeExact(service, "test");
        }
        long mhTime = System.nanoTime() - start;

        System.out.println("反射: " + reflectTime / 1_000_000 + " ms");
        System.out.println("MethodHandle: " + mhTime / 1_000_000 + " ms");
        System.out.println("加速比: " + (double) reflectTime / mhTime + "x");
    }
}
```

### 3.3 对比总结表

| 对比维度 | MethodHandle | 反射 (java.lang.reflect) |
|---------|-------------|------------------------|
| **引入版本** | Java 7 (JSR 292) | Java 1.1 |
| **本质** | 方法句柄——轻量级函数指针 | 方法对象——完整的元数据对象 |
| **类型安全** | 强类型（invokeExact要求精确匹配） | 弱类型（invoke(Object...)） |
| **性能** | 接近直接调用（JIT可内联） | 较慢（多层委派、权限检查） |
| **访问控制** | lookup对象受限于创建时的上下文 | setAccessible可暴力绕过 |
| **编译期检查** | 无 | 无 |
| **灵活性** | 可组合变换（bindTo, filterArguments等） | 较低 |
| **适用场景** | 高性能框架、语言运行时 | 通用反射、框架启动期 |
| **JIT内联** | 支持内联 | 几乎不可内联 |
| **参数处理** | 无装箱（原始类型直接处理） | 装箱/拆箱开销 |
| **安全检查** | 仅限lookup时检查一次 | 每次invoke都检查 |

```java
// MethodHandle的变换能力——反射无法做到
public class MethodHandleTransformDemo {

    public static void main(String[] args) throws Throwable {
        MethodHandles.Lookup lookup = MethodHandles.lookup();

        // 原始方法: String.concat(String)
        MethodHandle concat = lookup.findVirtual(
                String.class, "concat",
                MethodType.methodType(String.class, String.class));

        // 变换1: 交换参数顺序
        // concat("Hello", "World") -> 交换后传参变成了 concat("World", "Hello")
        MethodHandle swapped = MethodHandles.permuteArguments(
                concat,
                MethodType.methodType(String.class, String.class, String.class),
                1, 0  // 新的参数顺序: arg[1], arg[0]
        );
        String result1 = (String) swapped.invokeExact("Hello", "World");
        System.out.println("交换参数: " + result1);  // WorldHello

        // 变换2: 绑定第一个参数
        MethodHandle boundHello = MethodHandles.insertArguments(concat, 0, "Hello ");
        String result2 = (String) boundHello.invokeExact("World");
        System.out.println("绑定参数: " + result2);  // Hello World

        // 变换3: 过滤参数（类型转换）
        MethodHandle toString = lookup.findVirtual(
                Object.class, "toString",
                MethodType.methodType(String.class));
        MethodHandle filtered = MethodHandles.filterArguments(
                concat, 1, toString);  // 第二个参数先经过toString转换
        String result3 = (String) filtered.invokeExact("Value: ", 42);
        System.out.println("过滤参数: " + result3);  // Value: 42
    }
}
```

> 🎯 **核心要点**：MethodHandle比反射更快，因为JIT可以内联MethodHandle调用链，且无装箱/拆箱、无权限检查。MethodHandle的变换（permuteArguments、insertArguments、filterArguments）是反射API无法实现的灵活能力。Spring、MyBatis等框架已在内部大量使用MethodHandle替代反射。

## 4. 动态代理

### 4.1 JDK动态代理（Proxy + InvocationHandler）

JDK动态代理是Java原生支持的代理方式，基于**接口实现**。核心要求：**目标对象必须实现至少一个接口**。

```java
import java.lang.reflect.InvocationHandler;
import java.lang.reflect.Method;
import java.lang.reflect.Proxy;

// === 1. 定义业务接口 ===
interface UserService {
    void addUser(String username);
    void deleteUser(int id);
    String getUserInfo(int id);
}

// === 2. 目标类（实现接口） ===
class UserServiceImpl implements UserService {
    @Override
    public void addUser(String username) {
        System.out.println("添加用户: " + username);
    }

    @Override
    public void deleteUser(int id) {
        System.out.println("删除用户: " + id);
    }

    @Override
    public String getUserInfo(int id) {
        return "{id=" + id + ", name='User" + id + "'}";
    }
}

// === 3. InvocationHandler实现（代理逻辑） ===
class LogInvocationHandler implements InvocationHandler {

    private final Object target;

    public LogInvocationHandler(Object target) {
        this.target = target;
    }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        String methodName = method.getName();
        long start = System.currentTimeMillis();

        System.out.println("[前置日志] 调用方法: " + methodName);

        Object result;
        try {
            // 调用目标对象的方法
            result = method.invoke(target, args);
        } catch (Exception e) {
            System.out.println("[异常日志] 方法 " + methodName + " 抛出异常: " + e.getCause());
            throw e;
        }

        long cost = System.currentTimeMillis() - start;
        System.out.println("[后置日志] 方法: " + methodName + " 耗时: " + cost + "ms");

        return result;
    }
}

// === 4. 使用 ===
public class JdkProxyDemo {

    public static void main(String[] args) {
        // 保存生成的代理类文件到磁盘（方便反编译查看）
        System.setProperty("sun.misc.ProxyGenerator.saveGeneratedFiles", "true");
        // Java 8+ 使用:
        // System.setProperty("jdk.proxy.ProxyGenerator.saveGeneratedFiles", "true");

        // 创建目标对象
        UserService target = new UserServiceImpl();

        // 创建代理
        UserService proxy = (UserService) Proxy.newProxyInstance(
                target.getClass().getClassLoader(),          // 类加载器
                target.getClass().getInterfaces(),           // 接口列表
                new LogInvocationHandler(target)             // 调用处理器
        );

        // 通过代理调用方法
        proxy.addUser("Alice");
        System.out.println("---");
        proxy.deleteUser(42);
        System.out.println("---");
        String info = proxy.getUserInfo(100);
        System.out.println("getUserInfo返回: " + info);

        // 验证代理对象的类型
        System.out.println("proxy是UserService? " + (proxy instanceof UserService));
        System.out.println("proxy是Proxy? " + (proxy instanceof Proxy));
        System.out.println("proxy类名: " + proxy.getClass().getName());
        // 输出: com.sun.proxy.$Proxy0
    }
}
```

### 4.2 源码剖析：ProxyGenerator生成$Proxy类

JDK动态代理的核心是**运行时动态生成字节码**。ProxyGenerator负责在运行时生成代理类的字节码。

**生成的$Proxy0类结构（伪代码）：**

```java
// 这是JDK在运行时生成的类，继承java.lang.reflect.Proxy，实现UserService接口
package com.sun.proxy;

import java.lang.reflect.InvocationHandler;
import java.lang.reflect.Method;
import java.lang.reflect.Proxy;
import java.lang.reflect.UndeclaredThrowableException;

public final class $Proxy0 extends Proxy implements UserService {

    // 缓存Method对象——反射优化
    private static Method m1;  // equals
    private static Method m2;  // toString
    private static Method m3;  // hashCode
    private static Method m4;  // addUser
    private static Method m5;  // deleteUser
    private static Method m6;  // getUserInfo

    // 构造器传入InvocationHandler
    public $Proxy0(InvocationHandler h) {
        super(h);
    }

    // 静态初始化块——反射获取所有Method
    static {
        try {
            m1 = Class.forName("java.lang.Object").getMethod("equals",
                    Class.forName("java.lang.Object"));
            m2 = Class.forName("java.lang.Object").getMethod("toString");
            m3 = Class.forName("java.lang.Object").getMethod("hashCode");
            m4 = Class.forName("UserService").getMethod("addUser",
                    Class.forName("java.lang.String"));
            m5 = Class.forName("UserService").getMethod("deleteUser", Integer.TYPE);
            m6 = Class.forName("UserService").getMethod("getUserInfo", Integer.TYPE);
        } catch (NoSuchMethodException e) {
            throw new NoSuchMethodError(e.getMessage());
        } catch (ClassNotFoundException e) {
            throw new NoClassDefFoundError(e.getMessage());
        }
    }

    // 生成的代理方法——委托给InvocationHandler
    @Override
    public void addUser(String username) {
        try {
            super.h.invoke(this, m4, new Object[]{username});
        } catch (RuntimeException | Error e) {
            throw e;
        } catch (Throwable e) {
            throw new UndeclaredThrowableException(e);
        }
    }

    @Override
    public void deleteUser(int id) {
        try {
            super.h.invoke(this, m5, new Object[]{id});
        } catch... { /* 同上 */ }
    }

    @Override
    public String getUserInfo(int id) {
        try {
            return (String) super.h.invoke(this, m6, new Object[]{id});
        } catch... { /* 同上 */ }
    }

    // equals/hashCode/toString也委托给InvocationHandler
}
```

> 💡 **关键理解**：生成的代理类继承 `java.lang.reflect.Proxy`，所以**只能基于接口代理**（Java是单继承）。它在静态初始化块中通过反射缓存所有Method对象，每次调用时委托给InvocationHandler。

### 4.3 CGLIB代理（继承 + MethodInterceptor）

当目标类没有实现接口时，JDK动态代理无能为力。CGLIB（Code Generation Library）通过**继承目标类**生成子类代理。

```java
import net.sf.cglib.proxy.Enhancer;
import net.sf.cglib.proxy.MethodInterceptor;
import net.sf.cglib.proxy.MethodProxy;

// === 1. 目标类（无接口） ===
class UserDao {
    public void save(String username) {
        System.out.println("保存用户: " + username);
    }

    public final String getFinalInfo() {
        return "final方法无法被CGLIB代理";
    }

    public String query(int id) {
        return "查询结果: id=" + id;
    }
}

// === 2. MethodInterceptor实现 ===
class LogMethodInterceptor implements MethodInterceptor {

    @Override
    public Object intercept(Object obj, Method method, Object[] args,
                            MethodProxy proxy) throws Throwable {
        System.out.println("[CGLIB前置] 方法: " + method.getName());

        // 注意：这里用proxy.invokeSuper，不是method.invoke！
        // proxy.invokeSuper(obj, args) 调用父类（目标类）的方法
        Object result = proxy.invokeSuper(obj, args);

        System.out.println("[CGLIB后置] 方法: " + method.getName() + " 完成");
        return result;
    }
}

// === 3. 使用 ===
public class CglibProxyDemo {

    public static void main(String[] args) {
        Enhancer enhancer = new Enhancer();
        enhancer.setSuperclass(UserDao.class);           // 设置父类（目标类）
        enhancer.setCallback(new LogMethodInterceptor()); // 设置回调

        // 生成代理对象
        UserDao proxy = (UserDao) enhancer.create();

        // 通过代理调用方法
        proxy.save("Alice");
        System.out.println("---");
        String result = proxy.query(100);
        System.out.println(result);

        // ⚠️ final方法无法被代理
        System.out.println("final方法: " + proxy.getFinalInfo());

        // 验证类型
        System.out.println("proxy是UserDao的子类? " + (proxy instanceof UserDao));
        System.out.println("proxy类名: " + proxy.getClass().getName());
        // 输出: com.example.UserDao$$EnhancerByCGLIB$$xxxx
    }
}
```

```text
输出：
[CGLIB前置] 方法: save
保存用户: Alice
[CGLIB前置] 方法: save 完成
---
[CGLIB前置] 方法: query
[CGLIB后置] 方法: query 完成
查询结果: id=100
proxy是UserDao的子类? true
proxy类名: com.example.UserDao$$EnhancerByCGLIB$$xxxxxxxx
```

**CGLIB代理的三大限制：**

| 限制 | 原因 | 解决方案 |
|------|------|---------|
| `final`方法无法被代理 | 子类不能重写final方法 | 设计类时避免final方法 |
| `private`方法无法被代理 | 子类不可见，无法重写 | 改为protected或public |
| 无参构造器要求 | Enhancer.create()需调用父类构造 | 添加无参构造，或用`Enhancer.create(Class[], Object[])`指定构造参数 |

```java
// CGLIB的MethodProxy.invokeSuper vs method.invoke 关键区别
// 用一个对比更清楚:
class InvokeSuperDemo {

    public static void main(String[] args) {
        // ⚠️ 在Interceptor内部，必须用proxy.invokeSuper()
        // 而不能用method.invoke(targetObj, args)
        // 因为：method.invoke(proxy, args) 会再次调用代理方法，造成无限递归！
    }
}
```

> ⚠️ **无限递归陷阱**：在CGLIB的intercept方法中，一定不要调用 `method.invoke(obj, args)` 这是调用代理对象的相同方法，会再次进入拦截器，形成无限递归。必须使用 `proxy.invokeSuper(obj, args)` 调用父类（目标类）的原始方法。

### 4.4 JDK动态代理 vs CGLIB代理对比表

| 对比维度 | JDK动态代理 | CGLIB代理 |
|---------|-------------|-----------|
| **原理** | 实现接口 + 反射委托给InvocationHandler | 继承目标类 + 字节码生成 + MethodInterceptor |
| **要求** | 目标必须实现接口 | 目标类不能是final，不能有final方法 |
| **性能（创建）** | 较快 | 较慢（需生成字节码） |
| **性能（调用）** | 较慢（反射委派） | 较快（ASM生成的字节码直接调用） |
| **版本要求** | Java原生，无需额外依赖 | 需要cglib.jar（Spring已内置） |
| **产生的类** | $Proxy0（继承Proxy，实现接口） | 目标类$$EnhancerByCGLIB$$xxxx |
| **方法调用** | method.invoke(target, args) 反射 | FastClass机制直接调用 |
| **限制** | 只支持接口方法 | final/private方法无法代理 |
| **Spring默认选择** | 目标有接口时**默认使用** | 目标无接口时回退 |

```java
                System.out.println("[AOP前置]");
                Object result = proxy.invokeSuper(obj, args);
                System.out.println("[AOP后置]");
                return result;
            });
            return enhancer.create();
        }
    }

    // Spring实际代码在DefaultAopProxyFactory中:

@EnableAspectJAutoProxy(proxyTargetClass = true)  // 强制CGLIB
```

> 🎯 **核心要点**：
> - **JDK动态代理**：基于接口，运行时生成Proxy子类。每次调用经过InvocationHandler.invoke()，通过反射调用目标方法。
> - **CGLIB代理**：基于继承，通过ASM字节码生成目标类的子类。MethodProxy.invokeSuper()使用FastClass机制直接调用父类方法，比反射快。
> - **Spring默认策略**：有接口 -> JDK代理；无接口 -> CGLIB代理。可通过 `proxyTargetClass=true` 强制CGLIB。
> - **关键考点**：CGLIB的intercept中必须用`proxy.invokeSuper()`而非`method.invoke()`避免无限递归。

### 5.1 Spring IoC依赖注入

```java
// 简化版Spring IoC容器——展示反射如何实现依赖注入
public class SimpleSpringContainer {

    // 存储所有Bean实例
    private final Map<String, Object> beans = new ConcurrentHashMap<>();

    /**
     * 注册Bean并执行依赖注入
     */
    public void registerBean(String beanName, Class<?> clazz) throws Exception {
        // 1. 通过反射创建实例
        Object instance = clazz.getDeclaredConstructor().newInstance();
        beans.put(beanName, instance);

        // 2. 遍历所有字段，执行@Autowired注入
        for (Field field : clazz.getDeclaredFields()) {
            if (field.isAnnotationPresent(Autowired.class)) {
                // 获取字段类型
                Class<?> fieldType = field.getType();
                // 在容器中查找匹配的Bean
                Object dependency = findBeanByType(fieldType);
                if (dependency != null) {
                    field.setAccessible(true);
                    field.set(instance, dependency);  // 反射注入依赖
                }
            }
        }
    }

    private Object findBeanByType(Class<?> type) {
        return beans.values().stream()
                .filter(type::isInstance)
                .findFirst()
                .orElse(null);
    }

    @SuppressWarnings("unchecked")
    public <T> T getBean(String name) {
        return (T) beans.get(name);
    }
}
```

### 5.2 MyBatis Mapper接口代理

MyBatis的核心机制是**为Mapper接口生成JDK动态代理**，在代理中解析SQL注解/XML并执行。

```java
// 简化版MyBatis MapperProxy
public class MapperProxy<T> implements InvocationHandler, Serializable {

    private final Class<T> mapperInterface;
    private final SqlSession sqlSession;

    public MapperProxy(Class<T> mapperInterface, SqlSession sqlSession) {
        this.mapperInterface = mapperInterface;
        this.sqlSession = sqlSession;
    }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        // Object方法直接调用
        if (Object.class.equals(method.getDeclaringClass())) {
            return method.invoke(this, args);
        }

        // 解析方法上的@Select/@Update等注解
        Select select = method.getAnnotation(Select.class);
        if (select != null) {
            String sql = select.value()[0];
            // 解析参数，执行SQL
            return sqlSession.selectList(sql, args);
        }

        Insert insert = method.getAnnotation(Insert.class);
        if (insert != null) {
            String sql = insert.value()[0];
            return sqlSession.insert(sql, args);
        }

        // ... 其他注解处理

        return null;
    }

    // MyBatis使用示例——Mapper接口只需要定义，MyBatis通过JDK动态代理实现
    public static <T> T newMapperProxy(Class<T> mapperInterface, SqlSession sqlSession) {
        return (T) Proxy.newProxyInstance(
                mapperInterface.getClassLoader(),
                new Class[]{mapperInterface},
                new MapperProxy<>(mapperInterface, sqlSession)
        );
    }
}

// 一个标准的MyBatis Mapper接口
interface UserMapper {
    @Select("SELECT * FROM user WHERE id = #{id}")
    User selectById(int id);

    @Insert("INSERT INTO user(name, age) VALUES(#{name}, #{age})")
    int insertUser(User user);
}
```

### 5.3 JUnit @Test反射调用

```java
// 简化版JUnit框架——展示反射如何执行测试方法
public class SimpleJUnitFramework {
```

### 5.4 @Autowired原理简述

```java
// Spring @Autowired的底层原理
// 1. Spring扫描Bean定义，创建Bean实例（反射 Constructor.newInstance）
// 2. 实例化后，遍历所有字段/方法，查找@Autowired注解
// 3. 通过反射获取字段类型 -> 在容器中查找匹配的Bean
// 4. 通过反射 field.set() 注入依赖
// 5. 如果注入的是Proxy，则Bean本身也是通过反射/动态代理创建

// 关键流程伪代码:
public class AutowiredBeanPostProcessor implements BeanPostProcessor {

    @Override
    public Object postProcessBeforeInitialization(Object bean, String beanName) {
        Class<?> clazz = bean.getClass();
        for (Field field : clazz.getDeclaredFields()) {
            Autowired autowired = field.getAnnotation(Autowired.class);
            if (autowired != null) {
                Object dependency = beanFactory.getBean(field.getType());
                field.setAccessible(true);
                try {
                    field.set(bean, dependency);  // 反射注入
                } catch (IllegalAccessException e) {
                    throw new RuntimeException("注入失败", e);
                }
            }
        }
        return bean;
    }
}
```

> 🎯 **核心要点**：反射是Java框架的"基础设施能力"——IoC容器靠反射创建对象和注入依赖、MyBatis靠动态代理将Mapper接口转化为SQL执行器、JUnit靠反射发现并调用@Test方法。理解反射在这些框架中的具体运用，是面试的加分项。

```java
public class SecurityManagerDemo {

    public static void main(String[] args) throws Exception {
        // 启用默认SecurityManager
        // System.setSecurityManager(new SecurityManager());

        // 策略文件示例 (reflection.policy):
        // grant {
        //     permission java.lang.reflect.ReflectPermission "suppressAccessChecks";
        // };

        // 启动参数:
        // java -Djava.security.manager -Djava.security.policy=reflection.policy MyApp

        // 如果没有授予suppressAccessChecks权限:
        // 调用 setAccessible(true) 会抛出 AccessControlException
    }
}
```

### 6.3 各版本安全特性演变

| Java版本 | 安全特性变化 |
|---------|-------------|
| Java 8 (2014) | 反射无模块限制，setAccessible广泛使用 |
| Java 9 (2017) | 引入模块化系统，默认禁止跨模块反射访问 |
| Java 16 (2021) | 封装JDK内部API（`--illegal-access=deny` 成为默认） |
| Java 17 (2021) LTS | 强封装，`sun.misc` 等内部API完全不可访问 |
| Java 21+ (2023) | 进一步限制反射，鼓励使用MethodHandle和变量句柄(VarHandle) |

> 🎯 **核心要点**：Java 9+模块化系统使反射安全从"运行时全部可访问"变为"模块需要显式opens"。生产环境中，对框架必要的反射操作通过 `--add-opens` 参数授权，或通过module-info.java中 `opens` 声明。SecurityManager在Java 17中被标记为deprecated，未来将被移除。

## 7. 面试追问

### Q1: "反射很慢，为什么Spring还在大量使用？"

```text
面试官考察点：理解反射性能问题的本质 + 框架设计权衡

回答思路：
1. 反射确实慢，但Spring只在启动阶段大量使用反射：
   - 创建Bean实例（Constructor.newInstance）
   - 注入依赖（Field.set）
   - 扫描注解、解析配置
   这些都是启动时做一次，不是每次请求都做。

2. Spring的运行时性能优化：
   - 启动阶段缓存反射获得的Method/Field对象
   - 对AOP代理，启动后走的是代理对象的方法（直接调用或MethodHandle）
   - 3.x后大量改用ASM字节码操作（比反射快）
   - 5.x后引入MethodHandle优化

3. 反射的灵活性无可替代：
   - 框架无法预知用户会定义什么类、字段、方法
   - 反射是唯一能在运行时"发现"和"操作"未知类的手段
   - 替代方案（编译时APT、字节码增强）各有局限

4. 结论：启动时的反射性能代价可接受，运行时热点路径已通过
   MethodHandle、字节码代理、编译增强等路径规避。
```

### Q2: "JDK动态代理和CGLIB有什么区别？Spring怎么选的？"

```text
区别：
- JDK动态代理：基于接口，运行时生成Proxy子类，通过InvocationHandler转发
- CGLIB代理：基于继承，通过ASM生成子类字节码，通过MethodInterceptor拦截

Spring选择策略：
- 默认：有接口 -> JDK动态代理；无接口 -> CGLIB代理
- @EnableAspectJAutoProxy(proxyTargetClass=true) 强制CGLIB
- 从Spring Boot 2.x开始，很多场景默认CGLIB（如@Transactional）

选择CGLIB的原因：
- JDK代理要求目标必须实现接口，有些类（如Controller）可能没有接口
- CGLIB可以直接代理类，不需要额外的接口设计
- 调用性能上CGLIB的FastClass机制比JDK代理的反射调用快

选择JDK代理的原因：
- Java原生支持，无需额外依赖
- 接口代理更符合面向接口编程的设计理念
- 创建代理对象的性能更好（不需要生成额外的字节码类）
```

### Q3: "怎么用反射绕过String的不可变性？"

```java
public class BreakStringImmutability {

    public static void main(String[] args) throws Exception {
        // Java 8及以下：String内部是 char[] value 字段
        String s = "Hello";

        // 获取String的value字段
        Field valueField = String.class.getDeclaredField("value");
        valueField.setAccessible(true);

        // 修改value数组的内容
        char[] value = (char[]) valueField.get(s);
        value[0] = 'Y';
        value[1] = 'e';
        value[2] = 'l';
        value[3] = 'l';
        value[4] = 'o';

        System.out.println(s);  // 输出: Yello

        // 注意：Java 9+ String底层改用 byte[]，字段名也是 value
        // 但类型变成了 byte[]，需要做相应调整

        // ⚠️ 重要：Java 17+ 模块化系统默认阻止此操作
        // 需要 --add-opens java.base/java.lang=ALL-UNNAMED
    }
}
```

```text
面试追问延伸：
- "这个绕过对String常量池有影响吗？"
  答：有！如果修改了常量池中的字符串（如"Hello"），所有引用该字符串的对象都会受影响，
  可能导致各种诡异的bug。这是setAccessible的严重安全风险之一。

- "Java 9+为什么不可用？"
  答：两个原因：(1) String的value字段从char[]改为了byte[]（Compact Strings优化），
  反射方式需要适配；(2) Java 9+模块化系统阻止了对java.lang包内部字段的反射访问。

- "有没有其他不可修改的类可以被绕过？"
  答：Integer缓存、Boolean.TRUE/FALSE、枚举常量等，都是面试中常见的反射绕过案例。
```

### Q4: "构造器 `newInstance()` 和 `clazz.getDeclaredConstructor().newInstance()` 有什么区别？"

```text
关键区别：
1. JDK 9开始 Class.newInstance() 被标记为 @Deprecated
2. Class.newInstance() 只能调用无参构造器，且异常包装不清晰（将checked异常包装为InvocationTargetException）
3. Constructor.newInstance() 可以调用任意参数的构造器
4. Constructor.newInstance() 抛出异常时，Checked异常被正确包装

推荐：始终使用 Constructor.newInstance() 而不是 Class.newInstance()
```

> 🎯 **面试核心**：反射相关的面试题，本质上在考察三个层次——**会不会用**（API）、**懂不懂原理**（性能/安全）、**有没有深度**（框架设计/替代方案）。建议从"框架为什么要用它"和"运行时性能代价"两个角度深入理解，而不是死记硬背API。
