## 1. 进阶的本质：从执行到杠杆

> 🎯 **核心认知**：职场进阶不是「做更多任务」，而是「让每份投入产生更大杠杆」——从自己产出，到让别人/系统产出。

```
杠杆进阶路线
├── L1 个人杠杆：自己的产出（写更多代码）
├── L2 工程杠杆：让系统产出（自动化/工具/框架）
├── L3 团队杠杆：让别人产出（评审/指导/规范）
├── L4 组织杠杆：让业务产出（技术战略/平台化）
└── 精英的标志：影响范围从「我的代码」扩展到「团队的产出」
```

| 层级 | 时间投入 | 产出性质 | 职业阶段 |
|------|:---:|---------|---------|
| 执行 | 80% 写码 | 功能交付 | 初级 |
| 工程 | 50% 写码 + 30% 工具化 | 效率杠杆 | 中级 |
| 团队 | 30% 写码 + 40% 协作指导 | 团队杠杆 | 高级 |
| 组织 | 20% 写码 + 50% 战略 | 业务杠杆 | 专家/架构师 |

## 2. A/B/C 三类工作

### 2.1 Kent Beck 分类法

> 🎯 **A/B/C 类工作**（Kent Beck）：按「创造的价值类型」给工作分类——精英的本质是**多做 A 类，少做 C 类**：

| 类别 | 特征 | 例子 | 价值 |
|:---:|------|------|------|
| **C 类（危险）** | 只做被分配的任务且缺乏思考 | 机械照搬需求、从不质疑 | 消耗职业信用 |
| **B 类（稳健）** | 高质量完成任务、及时沟通不添乱 | 按规范交付 + 测试 + 文档 | 建立信任 |
| **A 类（高光）** | 逆向思考论证任务必要性 | 用 ROI 找出关键 20% 工作 | 创造杠杆价值 |

### 2.2 A 类工作的五种形态

```text
A 类工作五种形态
├── ① 逆向思考：论证任务是否必要（「这个功能真需要吗？
│     A/B 测试显示没人用」→ 省下 2 周）
├── ② ROI 意识：找出关键 20% 工作（帕累托：20% 工作产出 80% 价值）
├── ③ 修路而非赶路：解决根本问题（见第 6 节）
├── ④ 编写通用工具：一次投入，处处复用
└── ⑤ 沉淀输出：文档/规范/复盘——让经验成为团队资产
```

### 2.3 工作配比建议

```text
每周工作配比（精英参考）
├── B 类（保证下限）：60% —— 高质量交付核心任务
├── A 类（提升上限）：30% —— 工具化/复盘/优化
└── C 类（控制下限）：≤10% —— 不可避免的杂务
→ 金句：C 类工作是「保住饭碗」，A 类工作是「赢得晋升」——
    每天留出 A 类时间，是精英的自我要求
```

## 3. 九段工程师成长框架

### 3.1 九段模型

> 🎯 **九段工程师**：从基础执行到战略布局的完整成长框架——看清自己在哪里，才知道下一步去哪：

```text
九段工程师成长路线
┌─────────────────────────────────────┐
│ 9 段 战略布局：技术战略影响业务方向       │ ← 技术专家/CTO
│ 8 段 团队引领：建设团队能力与文化         │
│ 7 段 业务赋能：技术方案驱动业务增长       │
│ 6 段 项目操盘：多模块/跨团队统筹          │
│ 5 段 模块统筹：一个系统的整体设计         │
│ 4 段 经验复用：沉淀方法论与组件           │
│ 3 段 模块独立：独立负责一个模块           │
│ 2 段 主动校验：交付前自我验证             │
│ 1 段 基础执行：能完成分配的任务           │ ← 新人起点
└─────────────────────────────────────┘
```

### 3.2 各段的跃迁关键

| 阶段跨越 | 跃迁关键 |
|---------|---------|
| 1→3 段 | 从「完成任务」到「独立负责」：质量意识 + 主动校验 |
| 3→5 段 | 从「负责模块」到「设计模块」：架构思维 + 经验复用 |
| 5→7 段 | 从「设计系统」到「赋能业务」：业务视角 + 算账思维 |
| 7→9 段 | 从「业务赋能」到「战略布局」：行业洞察 + 技术趋势 |

### 3.3 贯穿全阶段的三习惯

```text
九段成长的三个底层习惯
├── ① 双维持续学习：技术深度 × 业务广度（不偏科）
├── ② 常态化复盘沉淀：每段结束复盘，经验进知识库
└── ③ 主动担当破局：卡点主动上，难题主动啃
→ 金句：段位不是年资，是「能独立承担的问题复杂度」
```

## 4. Top 1% 的三个关键习惯

### 4.1 三个习惯

| # | 习惯 | 说明 | 为什么有效 |
|---|------|------|-----------|
| 1 | **每天至少提交一个 PR** | 可量化的微小进步 | 复利积累 + 小步快跑获得及时反馈 |
| 2 | **主人翁心态** | 以「项目成功」为目标而非「我的任务」 | 从执行者变推动者（见 01 篇） |
| 3 | **主动告知职业目标** | 让经理知道你的发展意图 | 经理是资源不是监工——善用他加速成长 |

### 4.2 习惯一的进阶用法

```text
每天一个 PR 的三重价值
├── ① 产出可见：每天有交付物（进度可视化）
├── ② 反馈及时：每天被评审（快速修正方向）
├── ③ 复利积累：一年 250 个 PR = 250 次改进
└── 注意：PR 质量 > 数量（不是凑数，是「可验证的小步前进」）
```

### 4.3 与经理的关系

```text
把经理当资源的三件事
├── ① 对齐目标：季度初对齐「我这一季最有价值的 3 件事」
├── ② 主动沟通：进展同步 + 风险前置（不带惊喜）
├── ③ 表达发展：告诉经理你想成为什么样的人
│   → 他会把合适的机会分配给你
└── 金句：经理不知道你的目标，就无法帮你——主动告知是双赢
```

## 5. 晋升的底层逻辑

### 5.1 晋升的本质

> 🎯 **晋升的本质**：不是「时间到了」，而是「你已经用下一级的标准工作了」——**先成为，后获得**。

```text
晋升底层逻辑
├── ① 下一级的标准是什么？（观察/访谈）
├── ② 用下一级的标准工作 2-3 个月（先成为）
├── ③ 让成果可见（汇报/评审/分享）
└── ④ 时机成熟时提出（有据可依）
→ 常见错误：等晋升 → 被晋升（被动）；主动成为 → 获得晋升（主动）
```

### 5.2 晋升的三种资本

| 资本 | 内容 | 积累方式 |
|------|------|---------|
| **绩效资本** | 交付结果（算账思维展示价值） | 每季度价值复盘 |
| **信任资本** | 靠谱形象（说到做到） | 承诺必达 + 风险前置 |
| **影响力资本** | 别人愿意跟你干（指导/分享） | 评审导师化 + 技术分享 |

### 5.3 晋升受阻的信号

```text
晋升受阻的常见原因
├── ① 只有执行没有杠杆（全是 B 类没有 A 类）
├── ② 成果不可见（做了但不汇报 = 没做）
├── ③ 影响力局限（只影响自己的代码）
└── ④ 方向不对齐（做的是团队不需要的）
→ 自我诊断：用「杠杆 × 可见性 × 影响力」三维自评
```

## 6. 修路而非赶路

### 6.1 核心思想

> 🎯 **修路而非赶路**：同样的坑反复踩 → 修路（解决根本问题）；反复处理个案 → 赶路（永远在救火）。

```text
修路 vs 赶路
├── 赶路：每次部署都手工操作 20 分钟（重复 100 次 = 2000 分钟）
├── 修路：写自动化脚本（1 天投入 → 每次 30 秒）
└── 判断标准：
    ├── 这个操作我做过 3 次了吗？→ 修路
    ├── 这个问题我修过 3 次了吗？→ 修路
    └── 修路投入 < 3 次赶路总成本？→ 立即修
```

### 6.2 修路的三种形态

```text
修路三形态
├── ① 工具化：重复操作 → 脚本/工具（部署/测试/构建）
├── ② 制度化：重复问题 → 规范/检查清单（事故复盘 → 规范）
└── ③ 平台化：团队重复 → 公共组件/平台（三处以上复用）
→ 金句：赶路的人永远在救火，修路的人越走越宽
```

## 7. 核心要点

> 🎯 **核心要点**：
> 1. 进阶的本质：从个人产出（L1）到系统/团队/组织杠杆（L2-L4）
> 2. A/B/C 类工作：B 类保下限（60%）、A 类提上限（30%）、C 类控制（≤10%）——A 类 = 逆向思考/ROI/修路/工具/沉淀
> 3. 九段模型看清位置：段位 = 能独立承担的问题复杂度；三习惯（双维学习/复盘/担当）贯穿全程
> 4. 晋升 = 先成为后获得：绩效 × 信任 × 影响力三资本 + 每天一个 PR 的复利 + 把经理当资源
