## 1. WSL 演进：从翻译层到真内核

### 1.1 WSL1 设计（2016）

```text
WSL1 = Linux 系统调用 → NT 内核翻译

┌────────────────────────────────────────┐
│          Linux 用户态二进制 (ELF)         │
│  bash, git, python, java, apt...        │
├────────────────────────────────────────┤
│  LXCore / LXSS (Linux 子系统)            │
│  → 将 Linux 系统调用 翻译为 NT 系统调用     │
│  → 不完全兼容：约 80% Linux syscall 覆盖  │
├────────────────────────────────────────┤
│            Windows NT 内核               │
└────────────────────────────────────────┘

优点：文件系统直通（/mnt/c/ 直接操作 NTFS，性能好）
缺点：系统调用不完全、无完整内核、不支持 Docker
```

### 1.2 WSL2 设计（2019）

```text
WSL2 = Hyper-V 轻量虚拟机 + 完整 Linux 内核

┌────────────────────────────────────────────────┐
│               Linux 用户态 (完整)                 │
│   bash, systemd, Docker, Snap, 所有 syscall     │
├────────────────────────────────────────────────┤
│               Linux 内核 (Microsoft 维护)         │
│   完整提供 330+ Linux 系统调用                     │
├────────────────────────────────────────────────┤
│             Hyper-V 轻量虚拟机                    │
│   按需分配、<2秒启动、内存动态回收                 │
├────────────────────────────────────────────────┤
│              Windows 宿主机                      │
└────────────────────────────────────────────────┘

优点：100% 系统调用兼容、原生 Docker、完整 Linux 体验
缺点：跨文件系统 I/O 慢（/mnt/c/ 需要走网络协议 → 9P）
```

### 1.3 核心差异对比

| 维度 | WSL1 | WSL2 |
|------|------|------|
| **架构** | 系统调用翻译层 | Hyper-V 轻量虚拟机 |
| **Linux 内核** | ❌ 无（翻译 NT 内核调用） | ✅ 完整 Microsoft Linux 内核 |
| **系统调用兼容** | ~80% | **100%** (330+) |
| **Docker 支持** | ❌ 需 Docker Desktop 用 Hyper-V | ✅ 原生 Docker Engine |
| **文件 I/O (跨系统)** | ⭐⭐⭐⭐⭐ 直接 NTFS 操作 | ⭐ 通过 9P 网络协议（慢） |
| **文件 I/O (Linux 内)** | ⭐⭐ ext4 on NTFS | ⭐⭐⭐⭐⭐ 原生 ext4 |
| **启动速度** | 极快 (<1s) | 快 (<2s) |
| **内存占用** | 共享 Windows 内存 | 独立（可动态回收） |
| **GPU 加速** | ❌ | ✅ CUDA / DirectML |
| **systemd 支持** | ❌ | ✅ (0.67.6+) |
| **推荐场景** | 跨系统文件操作 | **一切场景** |

> 🎯 **核心结论**：除非需要频繁操作 `/mnt/c/` 下的大文件，否则无脑选 WSL2。

### 2.1 组件全景图

```text
┌─────────────────────────────────────────────────────────┐
│                    Windows 用户态                         │
│  ┌───────────┐  ┌───────────┐  ┌─────────────────────┐  │
│  │ wsl.exe   │  │ Windows   │  │ VS Code / IDEA      │  │
│  │           │  │ Terminal  │  │ └─ Remote Extension  │  │
│  └─────┬─────┘  └───────────┘  └──────────┬──────────┘  │
│        │                                  │              │
│  ┌─────▼──────────────────────────────────▼───────────┐  │
│  │                  LxssManager 服务                    │  │
│  │  管理 WSL2 实例生命周期 (启动/暂停/终止/关机)       │  │
│  └──────────────────────┬───────────────────────────────┘  │
├─────────────────────────┼──────────────────────────────────┤
│                    Windows 内核态                           │
│  ┌─────────────────────▼────────────────────────────┐     │
│  │              Hyper-V Hypervisor                   │     │
│  │  ┌──────────────────────────────────────────┐    │     │
│  │  │          WSL2 轻量虚拟机 (VMWorker)        │    │     │
│  │  │                                          │    │     │
│  │  │  ┌──────────────────────────────────┐    │    │     │
│  │  │  │       Microsoft Linux 内核        │    │    │     │
│  │  │  │  (基于 linux-msft-wsl-6.6.x)    │    │    │     │
│  │  │  │                                  │    │    │     │
│  │  │  │  ┌──────────────────────────┐    │    │    │     │
│  │  │  │  │  Linux 发行版用户空间     │    │    │    │     │
│  │  │  │  │  (Ubuntu/Debian/...)     │    │    │    │     │
│  │  │  │  │  bash, apt, systemd...   │    │    │    │     │
│  │  │  │  └──────────────────────────┘    │    │    │     │
│  │  │  └──────────────────────────────────┘    │    │     │
│  │  │                                          │    │     │
│  │  │  虚拟磁盘: ext4 (vhdx 动态扩展)           │    │     │
│  │  │  网络接口: Hyper-V Virtual Switch          │    │     │
│  │  │  Windows 文件挂载: 9P 协议 (/mnt/c/)       │    │     │
│  │  └──────────────────────────────────────────┘    │     │
│  └─────────────────────────────────────────────────┘     │
├──────────────────────────────────────────────────────────┤
│                    硬件 (CPU / RAM / Disk / GPU)           │
└──────────────────────────────────────────────────────────┘
```

### 2.2 关键组件说明

| 组件 | 职责 | 开发者须知 |
|------|------|-----------|
| **wsl.exe** | 前端命令（启动、管理、配置） | 所有操作入口 |
| **LxssManager** | Windows 服务，管理 VM 生命周期 | 服务异常时 WSL2 打不开 |
| **Hyper-V Hypervisor** | 虚拟机监控器 | Windows 11 必须开启虚拟化 |
| **VMWorker** | WSL2 的轻量 VM 进程 | 每个发行版启动一个 VM |
| **Microsoft Linux Kernel** | 微软维护的 Linux 内核 | `wsl --update` 更新内核 |
| **9P 协议** | Windows ↔ Linux 文件共享 | 跨文件系统 I/O 慢的根源 |
| **vhdx** | ext4 虚拟磁盘文件 | 存放在 `%LOCALAPPDATA%\Packages\<发行版>\` |

## 3. WSL2 资源管理模型

### 3.1 内存分配机制

```text
WSL2 内存管理 = "激进分配 + 惰性回收"

特点：
├── 默认使用宿主机 50% 内存（或 8GB，取较小值）
├── 启动时几乎不占内存，随使用增长
├── 空闲内存不会自动归还给 Windows
├── Linux 内 free -h 看到的内存 = VM 分配的内存
├── Windows 内存压力大时，Hyper-V 会回收部分内存

Java 开发者注意：
├── 如果 WSL2 中跑多个 Java 服务（占用大量堆），建议限制 .wslconfig
├── WSL2 占太多内存 → Windows 宿主机变卡 → IDEA 变慢
└── 合理配置：宿主机 32GB → WSL2 限制 12GB
```

### 3.2 .wslconfig 全局资源限制

```ini
# %USERPROFILE%\.wslconfig
[wsl2]
# === 内存限制 ===
memory=12GB                    # 最大内存（建议 ≤ 物理内存的 50%）

# === CPU 核心数 ===
processors=8                   # 限制 CPU 核心（默认 = 全部）

# === Swap 交换空间 ===
swap=8GB                       # 交换文件大小（0 = 禁用）

# === 网络 ===
localhostForwarding=true       # localhost 端口转发（默认 true）
networkingMode=NAT             # NAT / Mirrored (Windows 11 22H2+)

# === 内核 ===
kernelCommandLine=vsyscall=emulate  # 内核启动参数

# === 其他 ===
pageReporting=true             # 内存页面回收（Windows 回收空闲内存）
guiApplications=true           # WSLg GUI 应用支持
```

### 3.3 虚拟磁盘管理

```powershell
# WSL2 虚拟磁盘文件位置
# 每个发行版一个 .vhdx 文件（ext4 格式）
Get-ChildItem "$env:LOCALAPPDATA\Packages\" -Recurse -Filter "*.vhdx" | 
    Select-Object FullName, @{N="Size(GB)";E={[math]::Round($_.Length/1GB,2)}}

# vhdx 文件会动态增长但不会自动缩小
# 需要手动压缩释放未使用空间：
wsl --shutdown
diskpart
# select vdisk file="path\to\ext4.vhdx"
# compact vdisk
```

## 4. WSL2 启动流程

```text
用户输入: wsl / bash / wsl -d Ubuntu-24.04
    │
    ▼
wsl.exe 检查发行版状态
    │
    ├── 发行版正在运行 → 直接连接终端
    │
    └── 发行版已停止 → 启动流程：
        │
        ▼
    LxssManager 服务接管
        │
        ├── 1. 检查内核是否已启动
        │     ├── 已启动 → 复用内核
        │     └── 未启动 → 启动轻量 VM + 加载 Linux 内核
        │
        ├── 2. 挂载 ext4 虚拟磁盘（vhdx）
        │
        ├── 3. 挂载 Windows 文件系统（/mnt/c/, /mnt/d/...）
        │     使用 9P 协议
        │
        ├── 4. 初始化发行版：
        │     ├── /etc/fstab 挂载
        │     ├── /etc/wsl.conf 配置生效
        │     ├── [boot] command 执行
        │     └── systemd 启动（如果启用）
        │
        └── 5. 启动用户 Shell（bash/zsh）
    
总耗时：1-3 秒（冷启动）、<0.5 秒（热启动）
```

```powershell
# 查看 WSL2 运行状态
wsl --list --verbose
#   NAME            STATE           VERSION
# * Ubuntu-24.04    Running         2
#   Debian          Stopped         2

# 手动关机（释放内存！）
wsl --shutdown

# 终止特定发行版
wsl --terminate Ubuntu-24.04
```

## 5. WSL2 与传统虚拟机的本质差异

| 维度 | WSL2 | VirtualBox / VMware | Hyper-V 标准 VM |
|------|:---:|:---:|:---:|
| **启动速度** | <2 秒 | 30-60 秒 | 10-30 秒 |
| **内存占用** | 按需 + 动态回收 | 预分配 + 常驻 | 预分配 + 动态 |
| **内核** | 微软优化的专用内核 | 发行版自带 | 发行版自带 |
| **文件系统** | 9P 直通 + 原生 ext4 | 仅虚拟磁盘 | 仅虚拟磁盘 |
| **网络** | NAT / Mirrored + localhost 自动转发 | NAT / Bridged | NAT / Bridged |
| **GPU** | ✅ 原生支持 | ❌ / 3D 加速有限 | ✅ (DDA) |
| **GUI 集成** | ✅ WSLg (Wayland) | ❌ 需额外配置 | ❌ 需额外配置 |
| **与 Windows 集成** | ⭐⭐⭐⭐⭐ 最深 | ⭐⭐ | ⭐⭐⭐ |
| **systemd** | ✅ | ✅ | ✅ |
| **快照/备份** | wsl --export | ✅ 快照 | ✅ Checkpoints |
| **使用场景** | 开发 + 轻量服务器 | 兼容性测试 | 生产服务器 |

> 🎯 **核心要点**：WSL2 不是"另一个虚拟机"，而是 Windows 与 Linux 的深度交融层。目标是让 Linux 命令行工具、容器、开发环境成为 Windows 的原生能力。
