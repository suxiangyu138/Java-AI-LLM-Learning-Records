## 1. 进程与线程

### 1.1 核心定义

| 维度 | 进程 (Process) | 线程 (Thread) |
|------|---------------|--------------|
| **定义** | 操作系统资源分配的基本单位 | CPU 调度和执行的基本单位 |
| **内存空间** | 独立的内存空间（堆、栈、方法区），进程间相互隔离 | 共享进程的堆内存、方法区，独享线程栈、程序计数器 |
| **通信方式** | 进程间通信（IPC）成本高：管道、Socket、共享内存 | 线程间通信成本低：共享变量、wait/notify、管道流 |
| **创建销毁开销** | 大，需分配独立资源 | 小，轻量级 |
| **故障影响** | 一个进程崩溃不影响其他进程 | 一个线程崩溃导致整个进程崩溃 |
| **类比** | 工厂（独立厂房、设备） | 工人（共享工厂资源，各自工具柜） |

> 💡 **一句话区分**：进程是资源分配的最小单位，线程是 CPU 调度的最小单位。Java 程序启动默认创建一个 JVM 进程，在该进程内可创建多个线程并发执行。

### 1.2 Java 线程的底层映射

Java 线程采用 **一对一（1:1）内核线程模型**，即每一个 Java 线程都会映射到操作系统的一个内核线程上。JVM 通过调用操作系统内核 API 完成线程的创建、调度和销毁：

```
┌──────────────────────────────────────────┐
│            JVM 进程                       │
│                                          │
│  ┌─────────┐  ┌─────────┐  ┌─────────┐  │
│  │ Java     │  │ Java     │  │ Java     │  │
│  │ Thread A │  │ Thread B │  │ Thread C │  │
│  └────┬────┘  └────┬────┘  └────┬────┘  │
│       │             │             │       │
│  ┌────▼────┐  ┌────▼────┐  ┌────▼────┐  │
│  │ 内核线程 │  │ 内核线程 │  │ 内核线程 │  │
│  │  (OS)   │  │  (OS)   │  │  (OS)   │  │
│  └─────────┘  └─────────┘  └─────────┘  │
└──────────────────────────────────────────┘
```

JVM 为每个线程维护独立的 **程序计数器**、**虚拟机栈** 和 **本地方法栈**，保证线程执行的独立性：

- **程序计数器**：记录当前线程执行的字节码行号，线程切换后能恢复到正确位置
- **虚拟机栈**：存储局部变量表、操作数栈、方法出口等信息，每个方法调用对应一个栈帧
- **本地方法栈**：支持 native 方法调用

### 1.3 多线程的优势与代价

**优势：**

- **提升 CPU 利用率**：避免单线程因 I/O 等待导致 CPU 空闲
- **提高程序响应性**：UI 程序后台处理任务，前台仍可交互
- **充分利用多核硬件**：现代 CPU 均为多核，多线程可并行执行
- **实现异步非阻塞**：如异步日志、异步通知、异步任务处理

**代价与风险：**

- **线程安全**：多线程操作共享资源导致数据不一致（如并发修改同一变量）
- **死锁**：多线程互相持有对方需要的资源，导致永久阻塞
- **上下文切换开销**：线程切换消耗 CPU 时间，过度切换反而降低性能
- **资源竞争**：线程争抢锁、CPU 时间片等资源，导致执行效率下降
- **复杂度上升**：调试、测试、维护成本显著增加

> ⚠️ **线程不是越多越好**。线程数超过 CPU 核心数过多时，上下文切换开销会抵消并行带来的性能收益，甚至导致系统吞吐量下降。

## 2. 并发与并行

### 2.1 核心概念对比

| 概念 | 定义 | 硬件前提 | 关键特征 |
|------|------|---------|---------|
| **并发 (Concurrency)** | 同一时间段内多个任务交替执行 | 单核 CPU 即可实现 | 逻辑上同时，物理上轮流 |
| **并行 (Parallelism)** | 同一时刻多个任务同时执行 | 多核 CPU 必须 | 物理上同时执行 |

### 2.2 图解：并发 vs 并行

```
并发（单核）：               并行（多核）：
时间 ───────────────────▶   时间 ───────────────────▶
                             ┌─ Core 1 ─┐
CPU: [A][B][A][C][B][C]     │ A │ B │ C │
     └──── 交替执行 ────┘     └───┴───┴───┘
                              ┌─ Core 2 ─┐
实际上任一时刻              │ D │ E │ F │
只有一个任务运行              └───┴───┴───┘
                            ── 同时执行 ──
```

### 2.3 高并发的本质

**高并发** 不是并行，而是系统在单位时间内处理大量请求/任务的能力。核心目标是提升系统的 **吞吐量（TPS/QPS）** 和 **资源利用率**，同时控制 **响应时间**。

| 指标 | 定义 | 高并发追求 |
|------|------|-----------|
| **QPS** (Queries Per Second) | 每秒查询数 | 越高越好 |
| **TPS** (Transactions Per Second) | 每秒事务数 | 越高越好 |
| **RT** (Response Time) | 响应时间 | 越低越好 |
| **并发数** | 同时处理的请求数 | 合理控制 |

> 💡 **并发编程的目标**：在保证线程安全的前提下，最大化利用硬件资源，提升程序处理效率。

## 3. 线程创建的 4 种方式

### 3.1 四种方式总览

| 方式 | 返回结果 | 抛出异常 | 与任务解耦 | 生产推荐度 |
|------|:-------:|:--------:|:---------:|:---------:|
| **继承 `Thread`** | ❌ 无 | ❌ 不可 | ❌ 耦合 | ⭐ (不推荐) |
| **实现 `Runnable`** | ❌ 无 | ❌ 不可 | ✅ 解耦 | ⭐⭐⭐ (基础推荐) |
| **实现 `Callable` + `FutureTask`** | ✅ 有 | ✅ 可抛 | ✅ 解耦 | ⭐⭐⭐ (需返回值) |
| **线程池 (`ExecutorService`)** | ✅ 有 | ✅ 可抛 | ✅ 解耦 | ⭐⭐⭐⭐⭐ (生产首选) |

> 💡 **核心区别**：`Runnable` 无返回值、不可抛受检异常；`Callable` 有返回值、可抛异常；线程池解决线程复用问题，避免频繁创建/销毁的开销。

### 3.2 方式一：继承 Thread 类

```java
class MyThread extends Thread {
    @Override
    public void run() {
        // 线程执行体
        System.out.println(Thread.currentThread().getName() + " 执行中");
        for (int i = 0; i < 10; i++) {
            System.out.println(getName() + ": " + i);
        }
    }
}

// 启动方式
public class ThreadDemo {
    public static void main(String[] args) {
        MyThread t1 = new MyThread();
        MyThread t2 = new MyThread();
        t1.start(); // 启动线程，JVM 自动调用 run()
        t2.start();
    }
}
```

**缺点：**
- Java 单继承限制，继承 `Thread` 后无法继承其他类
- 线程与任务耦合，任务无法复用
- 无返回值，无法抛受检异常

### 3.3 方式二：实现 Runnable 接口（推荐基础方式）

```java
class MyRunnable implements Runnable {
    @Override
    public void run() {
        // 线程执行体
        System.out.println(Thread.currentThread().getName() + " 执行中");
        for (int i = 0; i < 10; i++) {
            System.out.println(Thread.currentThread().getName() + ": " + i);
        }
    }
}

// 启动方式
public class RunnableDemo {
    public static void main(String[] args) {
        MyRunnable task = new MyRunnable();
        Thread t1 = new Thread(task);
        Thread t2 = new Thread(task);
        t1.start();
        t2.start();

        // Lambda 简化写法（JDK 8+）
        Thread t3 = new Thread(() -> System.out.println("Lambda thread"));
        t3.start();
    }
}
```

**优点：**
- 避免单继承限制，可同时实现其他接口
- 线程与任务解耦，同一个 `Runnable` 实例可被多个 `Thread` 复用
- 更符合面向对象的设计原则（面向接口编程）

### 3.4 方式三：实现 Callable 接口 + FutureTask（带返回值）

当需要线程执行完成后返回结果或抛出异常时，使用 `Callable`。

```java
import java.util.concurrent.Callable;
import java.util.concurrent.FutureTask;

class MyCallable implements Callable<Integer> {
    @Override
    public Integer call() throws Exception {
        // 线程执行体，可返回结果
        int sum = 0;
        for (int i = 1; i <= 100; i++) {
            sum += i;
        }
        return sum;
    }
}

// 启动方式——方式 A：通过 Thread 启动
public class CallableDemo {
    public static void main(String[] args) throws Exception {
        MyCallable callable = new MyCallable();
        FutureTask<Integer> futureTask = new FutureTask<>(callable);
        Thread thread = new Thread(futureTask);
        thread.start();

        // 获取返回值（阻塞直到任务完成）
        Integer result = futureTask.get();
        System.out.println("计算结果：" + result);

        // futureTask 支持的其他操作
        // futureTask.cancel(true);   // 取消任务
        // futureTask.isDone();       // 判断是否完成
    }
}

// 启动方式——方式 B：通过线程池（推荐）
// ExecutorService executor = Executors.newFixedThreadPool(3);
// Future<Integer> future = executor.submit(new MyCallable());
// Integer result = future.get(1, TimeUnit.SECONDS); // 支持超时
```

**`Future` 核心方法：**

| 方法 | 作用 | 说明 |
|------|------|------|
| `get()` | 获取结果 | 阻塞直到任务完成 |
| `get(timeout, unit)` | 带超时获取 | 超时抛 `TimeoutException` |
| `cancel(mayInterrupt)` | 取消任务 | `true` 时中断正在执行的线程 |
| `isDone()` | 是否完成 | 正常/异常/取消均返回 `true` |
| `isCancelled()` | 是否取消 | — |

> ⚠️ **`get()` 是阻塞方法**，调用线程会进入 `WAITING` 状态直到任务完成。如果任务永远不完成会导致线程阻塞，建议使用带超时的 `get(timeout, unit)`。

### 3.5 方式四：线程池（生产环境首选）

```java
import java.util.concurrent.*;

public class ThreadPoolDemo {
    public static void main(String[] args) {
        // 创建固定线程数的线程池
        ExecutorService executor = Executors.newFixedThreadPool(4);

        // 提交 Runnable 任务
        executor.execute(() -> System.out.println("Runnable 任务执行"));

        // 提交 Callable 任务
        Future<String> future = executor.submit(() -> {
            Thread.sleep(1000);
            return "Callable 任务完成";
        });

        // 关闭线程池
        executor.shutdown();
    }
}
```

**生产环境注意：** 禁止使用 `Executors` 创建线程池，须手动使用 `ThreadPoolExecutor` 定义参数，避免 OOM 风险（具体原因在后续线程池章节详述）。

### 3.6 创建方式选择决策树

```
需要返回值或抛异常？
  ├── 是 → 使用 Callable + FutureTask / 线程池 submit()
  └── 否 → 需要任务复用？
               ├── 是 → 实现 Runnable（推荐）或使用线程池
               └── 否 → 简单场景可用 Lambda 简化

生产环境统一原则 → 使用 ThreadPoolExecutor 线程池
```

## 4. Thread 类核心方法

### 4.1 方法速查表

| 方法 | 作用 | 释放锁？ | 恢复条件 | 注意 |
|------|------|:-------:|---------|------|
| `start()` | 启动线程，进入 RUNNABLE 状态 | — | JVM 自动调用 `run()` | 只能调用一次 |
| `run()` | 线程执行体 | — | — | 直接调用只是普通方法，无多线程效果 |
| `sleep(millis)` | 当前线程休眠 | ❌ 不释放 | 时间到或被中断 | 静态方法，不释放锁 |
| `yield()` | 让出 CPU，回到就绪状态 | ❌ 不释放 | 调度器重新调度 | 不保证生效，依赖调度器 |
| `join()` | 等待目标线程终止 | — | 目标线程执行完毕 | 当前线程进入 WAITING |
| `join(millis)` | 带超时的等待 | — | 目标线程终止/超时 | — |
| `interrupt()` | 设置中断标志 | — | — | 不强制停止，需配合检查 |
| `isInterrupted()` | 检查中断标志 | — | — | 不清除标志位 |
| `interrupted()` | 检查并清除中断标志 | — | — | 静态方法，清除标志 |
| `currentThread()` | 获取当前执行的线程对象 | — | — | 静态方法 |
| `setDaemon(boolean)` | 设置守护线程 | — | — | 必须在 start() 前调用 |
| `setPriority(int)` | 设置优先级 (1-10) | — | — | 不保证生效，依赖操作系统 |
| `Thread.onSpinWait()` | **JDK 9+** 自旋等待提示 | — | — | 优化自旋循环性能 |

> ⚠️ **废弃方法**：`stop()`、`suspend()`、`resume()` 已被标记为废弃（`@Deprecated`），强制停止线程会导致资源未释放、数据不一致，**禁止使用**。

### 4.2 sleep vs wait 核心区别

| 对比维度 | `Thread.sleep()` | `Object.wait()` |
|---------|:----------------:|:----------------:|
| 归属类 | `Thread` | `Object` |
| **释放锁** | ❌ 不释放 | ✅ 释放（必须持有锁） |
| 调用前提 | 任意位置 | 必须在 `synchronized` 块内 |
| 唤醒方式 | 时间到 / `interrupt()` | `notify()` / `notifyAll()` / 超时 / 中断 |
| 状态 | `TIMED_WAITING` | `WAITING` 或 `TIMED_WAITING` |
| 用途 | 暂停执行、模拟耗时 | 线程间协调通信 |

```java
// sleep — 不释放锁
synchronized (lock) {
    Thread.sleep(1000); // 持有锁休眠，其他线程无法进入同步块
}

// wait — 释放锁
synchronized (lock) {
    lock.wait();        // 释放锁，其他线程可进入同步块
}
```

### 4.3 线程中断机制

Java 的中断是一种 **协作式机制** —— 调用 `interrupt()` 仅仅设置一个中断标志位，不会强制停止线程。线程需要自行检查标志并决定如何响应。

```java
public class InterruptDemo {
    public static void main(String[] args) throws InterruptedException {
        Thread t = new Thread(() -> {
            // 方式一：检查中断标志
            while (!Thread.currentThread().isInterrupted()) {
                // 执行任务...
                System.out.println("working...");
                try {
                    Thread.sleep(500);
                } catch (InterruptedException e) {
                    // 方式二：捕获中断异常后恢复标志并退出
                    System.out.println("收到中断信号，清理资源后退出");
                    Thread.currentThread().interrupt(); // 重新设置中断标志
                    break;
                }
            }
            System.out.println("线程安全退出");
        });
        t.start();
        Thread.sleep(2000);
        t.interrupt(); // 设置中断标志
    }
}
```

> 💡 **中断处理最佳实践**：捕获 `InterruptedException` 后通常应调用 `Thread.currentThread().interrupt()` 恢复中断标志，以便上层调用栈感知中断状态。

### 4.4 join 用法详解

```java
public class JoinDemo {
    public static void main(String[] args) throws InterruptedException {
        Thread t1 = new Thread(() -> {
            try { Thread.sleep(2000); } catch (InterruptedException e) { }
            System.out.println("t1 完成");
        });

        Thread t2 = new Thread(() -> {
            try { Thread.sleep(1000); } catch (InterruptedException e) { }
            System.out.println("t2 完成");
        });

        t1.start();
        t2.start();

        System.out.println("等待 t1 完成...");
        t1.join();     // 主线程等待 t1 终止
        System.out.println("t1 已结束，t2 可能已结束或未结束");

        t2.join(500);  // 只等 500ms，超时后继续
        System.out.println("主线程继续执行");
    }
}
```

### 4.5 线程优先级

Java 线程优先级范围 1~10，默认 5（`Thread.NORM_PRIORITY`）：

| 常量 | 值 | 含义 |
|------|:--:|------|
| `MIN_PRIORITY` | 1 | 最低优先级 |
| `NORM_PRIORITY` | 5 | 默认优先级 |
| `MAX_PRIORITY` | 10 | 最高优先级 |

> ⚠️ **优先级不保证生效**：线程优先级依赖操作系统调度器实现，不同操作系统处理方式不同（如 Linux 下可能忽略 Java 设置的优先级），**不要依赖优先级控制执行顺序**。

## 5. 线程 6 种状态与生命周期

### 5.1 状态流转图

```
                        ┌───────────────┐
                        │     NEW       │
                        │ (new Thread())│
                        └───────┬───────┘
                                │ start()
                                ▼
                        ┌───────────────┐
                  ┌────▶│  RUNNABLE     │◀────┐
                  │     │ (就绪+运行)    │     │
                  │     └───────┬───────┘     │
  ┌───────────────┐            │              │
  │   BLOCKED     │◀── 未获得 ─┤              │
  │ (等待锁)      │   sync锁   │              │
  └───────────────┘            │              │
                               │ wait()       │ notify()/notifyAll()
                  ┌────────────▼───────┐      │
                  │     WAITING        │──────┘
                  │ (Object.wait,      │
                  │  Thread.join,      │
                  │  LockSupport.park) │
                  └────────────┬───────┘
                               │
                  ┌────────────▼───────┐
                  │  TIMED_WAITING     │
                  │ (wait(ms), sleep,  │
                  │  parkNanos, join)  │
                  └────────────┬───────┘
                               │ 条件满足
                        ┌──────▼───────┐
                        │  TERMINATED  │
                        │ (执行完毕)    │
                        └──────────────┘
```

### 5.2 六种状态详表

| 状态 | 枚举值 | 进入条件 | 如何退出 | 是否占用 CPU |
|------|:-----:|---------|---------|:-----------:|
| **新建** | `NEW` | `new Thread()` 创建，未调 `start()` | 调用 `start()` | ❌ |
| **就绪/运行** | `RUNNABLE` | 调用 `start()` 后等待 CPU 调度 | 获取 CPU 时间片；或主动 yield | ⚠️ 可能 |
| **阻塞** | `BLOCKED` | 未获取到 `synchronized` 隐式锁 | 获取到锁 | ❌ |
| **等待** | `WAITING` | `wait()` / `join()` / `park()` | `notify()` / `notifyAll()` / `unpark()` / 目标线程终止 | ❌ |
| **超时等待** | `TIMED_WAITING` | `sleep(ms)` / `wait(ms)` / `join(ms)` / `parkNanos()` | 超时 / 被唤醒 / 被中断 | ❌ |
| **终止** | `TERMINATED` | `run()` / `call()` 执行完毕或异常终止 | — | ❌ |

> 🎯 **Thread.State 枚举**：Java 线程的 6 种状态定义在 `java.lang.Thread.State` 枚举中。相比传统 OS 的 5 状态模型（新建、就绪、运行、阻塞、终止），Java 将 **运行和就绪合并为 RUNNABLE**，并将阻塞细分为 **BLOCKED（等待锁）**、**WAITING（无限等待）** 和 **TIMED_WAITING（超时等待）** 三种。

### 5.3 状态验证代码

```java
/**
 * 线程状态演示 — 验证 6 种状态流转
 */
public class ThreadStateDemo {
    public static void main(String[] args) throws Exception {
        // 1. NEW
        Thread t = new Thread(() -> {
            try {
                Thread.sleep(2000);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        });
        System.out.println("1. NEW: " + t.getState()); // NEW

        // 2. RUNNABLE
        t.start();
        System.out.println("2. RUNNABLE: " + t.getState()); // RUNNABLE

        // 3. TIMED_WAITING（sleep）
        Thread.sleep(100);
        System.out.println("3. TIMED_WAITING: " + t.getState()); // TIMED_WAITING

        // 4. TERMINATED
        t.join();
        System.out.println("4. TERMINATED: " + t.getState()); // TERMINATED
    }
}
```

### 5.4 BLOCKED vs WAITING vs TIMED_WAITING 区别

| 对比维度 | BLOCKED | WAITING | TIMED_WAITING |
|---------|:-------:|:-------:|:-------------:|
| **触发原因** | 等待 `synchronized` 锁 | 主动调用 `wait()` / `join()` / `park()` | 调用带超时参数的等待方法 |
| **唤醒方式** | 获取到锁后自动唤醒 | 必须由其他线程显式唤醒 | 超时自动唤醒或被显式唤醒 |
| **超时机制** | ❌ 无 | ❌ 无 | ✅ 有 |
| **典型使用** | 锁竞争 | 生产者-消费者等待 | 定时任务、超时等待 |
| **可中断** | 不响应中断 | 可中断（抛 `InterruptedException`） | 可中断 |

### 5.5 线程生命周期要点

1. **线程无法从 TERMINATED 重启**：一旦进入终止状态，调用 `start()` 会抛 `IllegalThreadStateException`
2. **`start()` 只能调用一次**：重复调用抛异常
3. **RUNNABLE 包含就绪和运行**：Java 层面不区分，由操作系统决定是否正在运行
4. **阻塞状态不消耗 CPU**：`BLOCKED`、`WAITING`、`TIMED_WAITING` 均不占用 CPU 时间片
5. **`sleep` 不释放锁**：这是和 `wait` 最根本的区别

## 6. 守护线程与用户线程

### 6.1 概念对比

| 对比维度 | 用户线程 (User Thread) | 守护线程 (Daemon Thread) |
|---------|:---------------------:|:-----------------------:|
| **定义** | 执行业务逻辑的线程 | 为用户线程提供服务的线程 |
| **JVM 退出条件** | JVM 等待所有用户线程结束才退出 | JVM 检测到所有用户线程结束即退出，不会等待守护线程 |
| **典型示例** | `main` 线程、业务处理线程 | GC 垃圾回收线程、Finalizer 线程 |
| **用途** | 执行应用程序核心任务 | 后台服务：GC、内存管理、监控、心跳检测 |
| **生命周期** | 与任务绑定 | 依赖用户线程，最后一个用户线程退出时守护线程自动终止 |

### 6.2 设置守护线程

```java
public class DaemonThreadDemo {
    public static void main(String[] args) throws InterruptedException {
        Thread daemon = new Thread(() -> {
            while (true) {
                System.out.println("守护线程运行中...");
                try {
                    Thread.sleep(500);
                } catch (InterruptedException e) {
                    break;
                }
            }
        });
        daemon.setDaemon(true); // ⚠️ 必须在 start() 前调用
        daemon.start();

        // 主线程休眠 2 秒后结束
        Thread.sleep(2000);
        System.out.println("主线程结束，JVM 退出，守护线程自动终止");
        // 即使守护线程是死循环，也会随 JVM 退出而终止
    }
}
```

### 6.3 注意事项

> ⚠️ **守护线程使用守则：**
> 1. `setDaemon(true)` 必须在 `start()` 之前调用，否则抛 `IllegalThreadStateException`
> 2. 守护线程中创建的子线程默认为守护线程
> 3. **守护线程不应执行业务关键操作**（如文件写入、数据库操作），因为 JVM 退出时不会等待守护线程完成
> 4. **守护线程的 `finally` 块不一定执行**，因 JVM 直接退出，不保证资源清理
> 5. 守护线程适用于**周期性清理、监控统计、心跳检测**等非核心任务

## 7. 上下文切换与线程开销

### 7.1 上下文切换（Context Switch）

上下文切换是指 CPU 从一个线程切换到另一个线程执行时，需要保存当前线程的执行状态并恢复另一个线程的状态的过程。

**切换过程：**

```
线程 A 运行中
    │
    ▼
保存线程 A 的上下文 ───▶ 程序计数器
（CPU 寄存器状态）        ├── 寄存器数据
                          ├── 栈指针
                          └── 内存映射信息
    │
    ▼
线程 B 的上下文恢复
    │
    ▼
线程 B 运行中
```

### 7.2 上下文切换的开销

| 开销类型 | 具体内容 | 影响 |
|---------|---------|------|
| **直接开销** | 保存/恢复寄存器、程序计数器、栈指针 | 纯 CPU 耗时，执行额外指令 |
| **间接开销** | CPU 缓存失效（Cache Miss）、TLB 刷新 | 重新加载数据到缓存，影响远大于直接开销 |
| **调度开销** | 操作系统调度器决策时间 | 线程越多，调度复杂度越高 |
| **内存开销** | 每个线程独占栈空间（默认 1MB） | 千级线程可能耗尽内存 |

> 🎯 **关键结论**：上下文切换是并发编程中不可忽视的性能杀手。**线程数量超过 CPU 核心数过多**时，大量的上下文切换反而会导致系统吞吐量下降，响应时间变长。

### 7.3 减少上下文切换的策略

| 策略 | 做法 | 原理 |
|------|------|------|
| **无锁并发** | 使用 CAS、不可变对象、ThreadLocal | 避免锁竞争导致线程阻塞 |
| **协程/纤程** | JDK 21+ 虚拟线程（Virtual Threads） | 用户态调度，切换成本极低 |
| **线程池合理配置** | 控制线程数量，避免过多线程 | 减少调度层切换频率 |
| **减少锁竞争** | 锁分段、读写分离、减小锁粒度 | 降低线程阻塞率 |
| **使用异步编程** | CompletableFuture、响应式编程 | 减少线程等待时间 |

### 7.4 Java 线程的内存开销

```text
线程栈空间（默认）：
  - HotSpot JVM：默认 1MB（可通过 -Xss 调整）
  - 1000 个线程 → 约 1GB 栈空间（不含堆内存）

开销对比：
  - 用户态线程（虚拟线程）占用 ≈ KB 级别
  - 内核线程（平台线程）占用 ≈ MB 级别
```

> 💡 **线程池配置经验**：
> - **CPU 密集型**：线程数 = `N_CPU + 1`（或 `N_CPU * 2`）
> - **I/O 密集型**：线程数 = `N_CPU * (1 + wait_time / compute_time)`
> - **示例**：8 核 CPU，I/O 等待 100ms，计算 10ms → `8 * (1 + 100/10) = 88` 线程

## 8. 面试高频考点

### 8.1 基础概念问答

| 问题 | 核心回答要点 |
|------|------------|
| **进程和线程的区别** | 资源分配 vs CPU 调度；内存独立 vs 共享；创建开销大 vs 小；一个崩溃不影响 vs 全部崩溃 |
| **并发和并行的区别** | 交替执行（单核可）vs 同时执行（必须多核）|
| **为什么使用多线程** | 提高 CPU 利用率；充分利用多核；提高响应速度；异步处理 |
| **线程越多越好吗** | 不是。上下文切换开销、内存开销、资源竞争会抵消收益 |
| **start() 和 run() 的区别** | `start()` 启动线程进入 RUNNABLE；`run()` 直接调用是普通方法 |
| **Java 线程的 6 种状态** | NEW → RUNNABLE → BLOCKED/WAITING/TIMED_WAITING → TERMINATED |

### 8.2 创建方式问答

| 问题 | 核心回答要点 |
|------|------------|
| **4 种创建方式** | 继承 Thread、实现 Runnable、实现 Callable、线程池 |
| **Runnable vs Callable** | 无返回值 vs 有返回值；不可抛受检异常 vs 可抛；`run()` vs `call()` |
| **为什么推荐 Runnable 而非 Thread** | 避免单继承限制；任务与线程解耦；面向接口编程 |
| **线程池优势** | 复用线程减少开销；控制并发数；管理生命周期；提升系统稳定性 |
| **生产环境为何禁止 Executors** | 无界队列导致 OOM；最大线程数无限导致 OOM；缺少监控 |

### 8.3 状态与生命周期问答

| 问题 | 核心回答要点 |
|------|------------|
| **BLOCKED vs WAITING 区别** | BLOCKED 是被动等待锁；WAITING 是主动调用 wait/join/park |
| **sleep 会释放锁吗** | 不会。sleep 不释放任何锁 |
| **wait 会释放锁吗** | 会。wait 释放锁并进入 WAITING，被唤醒后重新竞争锁 |
| **线程死后能重新 start 吗** | 不能。TERMINATED 状态无法重新进入 RUNNABLE |
| **如何正确停止线程** | 用中断标志协作式停止。禁止使用 `stop()` |
| **yield 的作用和局限** | 让出 CPU，但不保证生效，不释放锁 |

### 8.4 守护线程问答

| 问题 | 核心回答要点 |
|------|------------|
| **守护线程和应用线程的区别** | JVM 等待用户线程退出；守护线程不阻止 JVM 退出 |
| **设置守护线程的时机** | `setDaemon()` 必须在 `start()` 之前 |
| **守护线程的典型应用** | GC 线程、心跳检测、定时清理、监控线程 |
| **守护线程的注意事项** | 不能执行关键业务操作；`finally` 不一定执行；子线程默认也是守护线程 |

> 🎯 **本章核心总结**
>
> 1. **进程是资源单位，线程是调度单位** — Java 线程 1:1 映射到 OS 内核线程
> 2. **4 种创建方式**：`Thread`（不推荐）、`Runnable`（推荐基础）、`Callable`（需返回值）、**线程池**（生产首选）
> 3. **6 种状态**：`NEW → RUNNABLE → BLOCKED / WAITING / TIMED_WAITING → TERMINATED`
> 4. **核心 API**：`sleep` 不释放锁，`wait` 释放锁；中断是协作式而非强制式
> 5. **守护线程**随 JVM 退出而终止，不执行业务关键操作
> 6. **上下文切换**是并发性能杀手，合理控制线程数量比盲目增加更有效
