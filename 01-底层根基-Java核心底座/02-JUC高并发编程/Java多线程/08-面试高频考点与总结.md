## 1. 必背考点：十二问

### 1.1 线程和进程的区别？

**答题链**：进程=资源容器（独立地址空间），线程=执行单元（共享进程内存）→ 切换成本差异（TLB/缓存）→ 通信方式差异（IPC vs 共享变量）→ Java 视角：JVM 进程内的 main/GC/编译器线程。

### 1.2 创建线程有哪几种方式？生产用什么？

**答题链**：四种方式（Thread/Runnable/Callable/线程池）→ Runnable 与任务解耦、Callable 带返回值 → **生产一律线程池**（资源管理：复用/限流/排队）→ 虚拟线程场景每任务一个（JDK 21+）。

### 1.3 线程有哪些状态？

**答题链**：6 状态（NEW/RUNNABLE/BLOCKED/WAITING/TIMED_WAITING/TERMINATED）→ RUNNABLE 含运行与就绪 → **BLOCKED 只发生在等 synchronized 锁**（等 Lock 是 WAITING）→ 状态机迁移图。

### 1.4 interrupt 怎么用？能强制停线程吗？

**答题链**：协作式中断（设置标志）→ 三件套语义 → 阻塞中 interrupt 抛 InterruptedException 并清标志 → 正确模式（循环检查 + 恢复标志）→ **不能强制停**：Thread.stop 不安全且 **JDK 26 已移除**。

### 1.5 什么是线程安全？三要素？

**答题链**：原子性/可见性/有序性定义与破坏例 → 保障手段映射（锁/CAS/volatile）→ 三要素同时满足才安全（volatile 不修原子性）→ 线程安全四级分类（不可变>绝对>相对>不安全）。

### 1.6 volatile 和 synchronized 的区别？

**答题链**：volatile=单字段可见性+禁重排（**无互斥、不修原子性**）；synchronized=互斥+可见性+原子性 → 场景：标志位用 volatile、复合操作用锁 → 三大场景与三大误用。

### 1.7 synchronized 锁升级？偏向锁现状？

**答题链**：锁对象（Mark Word/Monitor）→ 现代路径 = 无锁 → 轻量级（CAS+自旋）→ 重量级 → **偏向锁 JDK 15 废弃（JEP 374）/JDK 18 移除**（现代 JDK 没有偏向锁！）→ 可重入与异常自动释放。

### 1.8 wait 和 sleep 的区别？

**答题链**：四维对比——锁（释放 vs 抱着）、场景（条件协作 vs 定时暂停）、位置（必须 synchronized vs 不需要）、唤醒（notify vs 超时）→ 附加：wait 进 WaitSet、sleep 不释放锁。

### 1.9 为什么 wait 必须在 synchronized 里？虚假唤醒？

**答题链**：wait 操作 Monitor 的 WaitSet + 释放锁——无锁无法"释放与登记" → 虚假唤醒是 OS 允许行为 → **while 循环范式**（唤醒后重查条件）→ notify vs notifyAll 选择。

### 1.10 死锁的条件？怎么排查和预防？

**答题链**：四条件（互斥/持有并等待/不可剥夺/循环等待）→ jstack "Found one Java-level deadlock" → 预防三策略（锁顺序/tryLock 超时/findDeadlockedThreads 检测）→ 活锁（都在动）与饥饿（总轮不到）区分。

### 1.11 synchronized 和 ReentrantLock 怎么选？

**答题链**：自动释放 vs 手动 finally → 四场景选 Lock（可中断/超时/公平/多条件）→ 默认 synchronized → **虚拟线程附加题**：21-23 pinning 用 Lock、24+（JEP 491）恢复正常。

### 1.12 虚拟线程对多线程编程的影响？

**答题链**：线程成本革命（百万级/用户态调度）→ IO 密集默认虚拟线程、CPU 密集平台线程 → **不池化虚拟线程** → 稀缺资源用 Semaphore 限流 → synchronized pinning 与 JEP 491 → ThreadLocal → ScopedValue（JDK 25）。

## 2. 高频陷阱题 12 连问

1. **结果**：100 线程各自增 10 万次，`int count` 最终值？（< 1000 万——非原子丢更新）
2. **对错**：`volatile int i; i++` 是线程安全的。（❌ 不修原子性）
3. **结果**：wait() 被调用后，线程状态？（WAITING，且**释放锁**）
4. **对错**：sleep() 会释放锁。（❌ 抱着锁睡）
5. **对错**：BLOCKED 状态是等 ReentrantLock。（❌ 等 ReentrantLock 是 WAITING（park）；BLOCKED 只等 synchronized）
6. **结果**：JDK 18 的锁升级路径？（无锁 → 轻量级 → 重量级——**没有偏向锁**）
7. **对错**：notify() 一定唤醒"条件满足"的线程。（❌ 不确定唤醒谁——条件不满足会再等，这是用 notifyAll 的理由）
8. **结果**：虚假唤醒后会怎样？（while 重新检查条件则安全；if 判断会出错）
9. **对错**：Thread.stop() 还能用吗？（JDK 26 已移除——协作式中断才是正解）
10. **对错**：虚拟线程需要池化复用。（❌ 每任务一个，池化是反模式）
11. **对错**：synchronized 在虚拟线程中 Java 21-24 都有 pinning 问题。（❌ JEP 491 在 **JDK 24 已修复**——21-23 有问题，24+ 恢复正常）
12. **结果**：两个线程各写 `volatile long x` 的不同缓存行，性能正常吗？（若 x 与 y 同缓存行 → 伪共享互相拖累——`@Contended` 或 padding 隔离）

## 3. 高频追问速答

| 追问 | 速答 |
|------|------|
| 单核 CPU 上多线程有用吗？ | 有用——并发解决"IO 等待时不闲着"（交替执行），不只是并行 |
| 线程数设多少合适？ | CPU 密集 = 核数+1；IO 密集 = 核数×(1+等待/计算)；虚拟线程时代 IO 密集不用猜 |
| 局部变量线程安全吗？ | 安全——每个线程独立栈，局部变量在栈上 |
| 为什么 double 读写不保证原子（32 位）？ | 64 位值可能被拆成两次 32 位写（volatile 修饰可保证——现代 JVM 已基本原子，但规范不保证） |
| String 为什么线程安全？ | 不可变（final 字段 + 无 setter）——不可变即线程安全（03 模块第 4 节） |
| 什么时候用 ReadWriteLock？ | 读多写少且读操作耗时——读不互斥提升并发 |
| 线程池耗尽怎么查？ | jstack 看线程都阻塞在哪 → 通常是外部依赖无超时 → 加超时 + 有界队列 + 拒绝策略 |
| volatile 数组线程安全吗？ | 不——volatile 保证的是"引用"可见性，数组元素访问不经过 volatile 语义（用 AtomicIntegerArray） |
| 什么是安全发布？ | 对象安全交给其他线程的四方式：静态初始化/volatile/不可变/并发容器 |
| 单例最佳写法？ | 枚举单例（反射/序列化免疫）或静态内部类（见 `Java面向对象/06`） |
| 为什么 ConcurrentHashMap 不用锁整个 Map？ | 锁粒度细化（锁桶头/CAS 空桶）——不同桶并行，锁竞争大幅降低（见 `Java集合框架/06`） |
| 怎么判断一段代码"看起来安全"？ | 三问推演：共享吗？可变吗？操作原子吗？再对照 happens-before 检查可见性（03 模块第 6 节） |

## 4. 场景题：并发代码评审

**题目**：评审这段代码，找出所有并发问题并修复：

```java
public class ShoppingCart {
    private static Map<String, Integer> couponCounters = new HashMap<>();  // ① 静态共享可变
    private int total;

    public void applyCoupon(String code) {
        if (couponCounters.containsKey(code)) {             // ② check-then-act 竞态
            int c = couponCounters.get(code);
            couponCounters.put(code, c + 1);                // ③ 读改写非原子
        } else {
            couponCounters.put(code, 1);
        }
        total += calculateDiscount(code);                   // ④ total 非原子自增
    }
}
```

**答题框架**：

```text
问题清单：
① static Map 共享可变 → 并发修改 HashMap 会链表错乱/丢数据
② containsKey + get + put = check-then-act + 读改写，三重竞态
③ total += 非原子（读改写）
修复：
① Map → ConcurrentHashMap（复合操作仍不原子）
② 计数 → merge 原子方法：couponCounters.merge(code, 1, Integer::sum)
③ total → AtomicInteger 或 synchronized 方法（若必须精确）
④ 更进一步：HashMap 与 total 是"两个共享状态"——是否允许短暂不一致？不允许则统一锁
加分点：
- 指出"并发 bug 必须推演时序"而非"看起来没问题"
- 指出统计类高并发写可用 LongAdder
- 指出若 total 可接受近似值，LongAdder 更快
```

**同类题变体**（面试官换壳再问）：双检锁单例（考 volatile 与重排）、多线程计数（考原子类选择）、转账（考锁顺序与死锁）、缓存初始化（考安全发布）——**解题框架通用：找共享状态 → 找复合操作 → 选同步手段 → 检查发布**。

## 5. 记忆口诀

```text
线程进程分资源执行：进程管资源、线程管执行，共享内存是根源。
三要素定安全：原子、可见、有序——volatile 只修后两个。
锁的四件事：互斥、可见、可重入、自动放。
锁升级今昔变：8 有偏向、15 废弃、18 移除——现代就是轻量到重量。
wait 三连：持锁、释放、进 WaitSet；while 循环防假醒。
死锁四条件：互斥、持有等、不可夺、循环——打破一个即解脱。
排查三工具：jstack 找锁环、JFR 看竞争、压测找拐点。
优化四板斧：少切换、细锁、分缓存行、无锁 CAS。
虚拟线程观：线程无限、资源有限——Semaphore 限资源，不池化虚拟线程。
```
