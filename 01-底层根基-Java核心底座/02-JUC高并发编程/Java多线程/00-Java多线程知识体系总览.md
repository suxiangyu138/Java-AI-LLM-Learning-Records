## 3. 为什么必须学透多线程

1. **并发正确性是"推演"不是"背诵"**：原子性/可见性/有序性、竞态条件、死锁——多线程问题无法靠"试出来"，只能靠原理推演。**原理扎实的人写一遍就对，靠试的人线上炸**。
2. **一切并发框架的地基**：JUC 的 AQS、线程池、并发容器全部建立在"锁、CAS、volatile、wait/notify"之上——本体系给基础与思维，`02-JUC高并发编程/` 给组件深挖，两者缺一不可。
3. **虚拟线程时代基础依然成立**：JDK 21 虚拟线程改变的是"线程的性价比"，没有改变"共享可变状态需要同步"这一事实——**synchronized 的 pinning 问题（Java 21-23）与 JEP 491 修复（Java 24）就是最鲜活的例子**：不懂 synchronized 原理，就无法理解虚拟线程为何需要 ReentrantLock。
4. **面试必考且区分度最高**：线程安全、synchronized/volatile、wait/notify、死锁——Java 后端面试的"常青树"，答深答浅一眼可见。
5. **性能与故障的第一现场**：上下文切换、锁竞争、伪共享、线程泄漏——多线程是性能优化与生产排障的主战场。

## 4. 核心概念速查

### 4.1 三大关键概念

| 概念 | 一句话 | 保障手段 |
|------|--------|---------|
| 原子性 | 操作不可分割（要么全做要么不做） | synchronized / Lock / CAS |
| 可见性 | 一个线程的修改，其他线程能看到 | volatile / synchronized / Lock |
| 有序性 | 指令不被重排破坏语义 | volatile（禁止重排）/ 锁 |

### 4.2 线程 6 状态速查

```text
NEW → RUNNABLE（含运行/就绪）→ BLOCKED（等锁）→ WAITING（wait/join/park）
                                    → TIMED_WAITING（sleep/wait(timeout)）
                                    → TERMINATED
```

### 4.3 同步手段速查

| 手段 | 互斥 | 可见性 | 特点 |
|------|:----:|:------:|------|
| synchronized | ✅ | ✅ | 语言级、自动释放、现代 JDK 性能好 |
| volatile | ❌ | ✅（单个字段） | 只解决可见性/有序性，不解决原子性 |
| ReentrantLock | ✅ | ✅ | 可中断/可超时/公平锁/条件变量 |
| CAS + 原子类 | 无锁 | ✅ | 乐观并发，冲突少时最快 |
| wait/notify | 与锁配合 | — | 线程间协作（等待/通知） |

### 4.4 版本时间线（时效性重点）

| 版本 | 变化 | 说明 |
|------|------|------|
| JDK 15 | JEP 374 偏向锁废弃并默认禁用 | 锁升级去掉偏向锁第一步 |
| **JDK 18** | 偏向锁代码移除（obsolete） | 现代锁路径 = 无锁 → 轻量 → 重量 |
| JDK 21 | 虚拟线程转正（JEP 444） | 但 synchronized 存在 pinning 问题 |
| **JDK 24** | JEP 491 修复虚拟线程 pinning | synchronized 在虚拟线程恢复正常 |
| JDK 25 | ScopedValue 转正（JEP 506） | ThreadLocal 的虚拟线程替代品 |
| **JDK 26** | Thread.stop() 移除 | 遗留 API 清理（2026-03） |

## 6. 学习路线推荐

**路线一：入门夯实（2~3 天，对应模块 01-03）**
并发本质 → Thread API → 线程安全三要素；每个概念手写小实验（如多线程自增看丢值），重点建立"共享可变状态需要同步"的直觉。

**路线二：进阶深化（1 周，对应模块 04-07）**
synchronized/volatile → 协作机制 → 死锁诊断 → 性能优化；用 jstack 亲手抓一次死锁、用伪共享实验验证性能差异。

**路线三：面试冲刺（对应模块 08 + JUC 系统）**
背考点 → 自测陷阱题 → 场景设计题；然后进入 `02-JUC高并发编程/` 啃 AQS、线程池源码。

> 🎯 **核心要点**：多线程学习的终点是"**能推演**"——给你一段代码，你能推出"哪里不安全、会怎么错、怎么修"。原理 + 推演 + 工具验证三件套，胜过背一百道题。
