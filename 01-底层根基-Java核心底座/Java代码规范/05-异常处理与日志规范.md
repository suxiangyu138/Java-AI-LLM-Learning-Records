## 1. 异常捕获原则

### 1.1 不要 catch Throwable

```java
// ❌ 错误：会捕获 Error（OutOfMemoryError、StackOverflowError）
try {
    doSomething();
} catch (Throwable t) {
    log.error("error", t);
}

// ✅ 正确：只 catch Exception
try {
    doSomething();
} catch (Exception e) {
    log.error("error", e);
}
```

### 1.2 不要 catch 后不处理

```java
// ❌ 错误：异常被吞掉
try {
    doSomething();
} catch (Exception e) {
    // 什么都不做
}

// ❌ 错误：只打印 message，丢失堆栈
try {
    doSomething();
} catch (Exception e) {
    log.error("error: " + e.getMessage());  // ❌ 丢失堆栈
}

// ✅ 正确：打印完整堆栈
try {
    doSomething();
} catch (Exception e) {
    log.error("doSomething failed", e);  // ✅ 自动打印堆栈
}
```

### 1.3 finally 里不要 return

```java
// ❌ 错误：finally 的 return 覆盖 try 的 return
public int getValue() {
    try {
        return 1;
    } finally {
        return 2;  // ❌ 永远返回 2
    }
}

// ✅ 正确：finally 只做资源清理
public int getValue() {
    try {
        return 1;
    } finally {
        cleanup();
    }
}
```

## 2. 受检异常 vs 非受检异常

### 2.1 选型原则

| 类型 | 特点 | 适用场景 | 示例 |
|------|------|---------|------|
| 受检异常 | 编译期强制处理 | 可恢复的外部错误 | IOException / SQLException |
| 非受检异常 | 运行时才抛出 | 编程错误 / 业务异常 | NullPointerException / BizException |

### 2.2 受检异常转非受检异常

```java
// ❌ 强迫调用方处理
public String readFile(String path) throws IOException {
    return Files.readString(Path.of(path));
}

// ✅ 包装为非受检异常
public String readFile(String path) {
    try {
        return Files.readString(Path.of(path));
    } catch (IOException e) {
        throw new UncheckedIOException("读取文件失败: " + path, e);
    }
}
```

## 3. 自定义异常设计

### 3.1 异常层次设计

```java
// 基础业务异常
public class BizException extends RuntimeException {
    private String errorCode;
    
    public BizException(String message) {
        super(message);
    }
    
    public BizException(String errorCode, String message) {
        super(message);
        this.errorCode = errorCode;
    }
    
    public BizException(String message, Throwable cause) {
        super(message, cause);
    }
}

// 参数异常
public class ParamException extends BizException {
    public ParamException(String message) {
        super("PARAM_ERROR", message);
    }
}

// 系统异常
public class SystemException extends BizException {
    public SystemException(String message, Throwable cause) {
        super("SYSTEM_ERROR", message, cause);
    }
}
```

### 3.2 异常链传递

```java
// ✅ 保留原始异常堆栈
try {
    doSomething();
} catch (IOException e) {
    throw new BizException("处理订单失败, orderId: " + orderId, e);
}

// ❌ 丢失原始堆栈
try {
    doSomething();
} catch (IOException e) {
    throw new BizException("处理订单失败");  // ❌ 丢失 e
}
```

## 4. try-with-resources 规范

### 4.1 标准用法

```java
// ✅ 自动关闭资源
try (InputStream in = new FileInputStream("file.txt");
     BufferedReader reader = new BufferedReader(new InputStreamReader(in))) {
    return reader.readLine();
} catch (IOException e) {
    throw new UncheckedIOException(e);
}
```

### 4.2 关闭顺序

```java
// 后开先关（栈顺序）
try (InputStream in = ...;      // 先开
     BufferedReader reader = ...) {  // 后开
    // ...
}
// 关闭顺序：reader → in
```

### 4.3 异常抑制

```java
try (InputStream in = new FileInputStream("file.txt")) {
    throw new IOException("读取失败");
} catch (IOException e) {
    // e 包含主异常 + 关闭时的抑制异常
    for (Throwable suppressed : e.getSuppressed()) {
        log.error("suppressed", suppressed);
    }
}
```

## 5. 异常处理最佳实践

### 5.1 不要在循环里 try-catch

```java
// ❌ 性能差
for (User user : users) {
    try {
        process(user);
    } catch (Exception e) {
        log.error("process failed", e);
    }
}

// ✅ 性能好
try {
    for (User user : users) {
        process(user);
    }
} catch (Exception e) {
    log.error("batch process failed", e);
}
```

### 5.2 不要用异常控制流程

```java
// ❌ 性能差（异常创建成本高）
public User getUser(Long id) {
    try {
        return userMap.get(id);
    } catch (NullPointerException e) {
        return null;
    }
}

// ✅ 性能好
public User getUser(Long id) {
    if (id == null) {
        return null;
    }
    return userMap.get(id);
}
```

### 5.3 全局异常处理器

```java
@RestControllerAdvice
public class GlobalExceptionHandler {
    
    @ExceptionHandler(BizException.class)
    public Result<Void> handleBizException(BizException e) {
        log.error("biz error: {}", e.getMessage(), e);
        return Result.error(e.getErrorCode(), e.getMessage());
    }
    
    @ExceptionHandler(Exception.class)
    public Result<Void> handleException(Exception e) {
        log.error("system error", e);
        return Result.error("SYSTEM_ERROR", "系统异常");
    }
}
```

## 6. 日志框架选型

### 6.1 SLF4J 门面 + Logback 实现

```java
// ✅ 推荐：SLF4J API
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

public class UserService {
    private static final Logger log = LoggerFactory.getLogger(UserService.class);
    
    public void doSomething() {
        log.info("do something");
    }
}

// ❌ 避免：直接用 Logback API
import ch.qos.logback.classic.Logger;
```

### 6.2 日志门面 vs 日志实现

```text
SLF4J (门面)
    ↓
Logback / Log4j2 / JUL (实现)
```

> 💡 **优势**：切换实现只需换依赖，代码不用改。

## 7. 日志级别使用规范

### 7.1 五个级别

| 级别 | 用途 | 示例 |
|------|------|------|
| ERROR | 系统错误，需要人工介入 | 数据库连接失败、RPC 超时 |
| WARN | 潜在问题，不影响主流程 | 参数不合法、降级处理 |
| INFO | 关键业务节点 | 订单创建、支付成功 |
| DEBUG | 调试信息 | SQL 参数、方法入参 |
| TRACE | 最详细信息 | 框架内部调用 |

### 7.2 使用示例

```java
// ERROR：需要人工介入
log.error("订单创建失败, orderId: {}", orderId, e);

// WARN：潜在问题
log.warn("用户 {} 密码错误次数过多", username);

// INFO：关键业务节点
log.info("订单创建成功, orderId: {}, userId: {}", orderId, userId);

// DEBUG：调试信息
log.debug("查询用户, id: {}, result: {}", id, user);
```

## 8. 日志占位符 vs 字符串拼接

### 8.1 性能对比

```java
// ❌ 字符串拼接：即使日志级别不满足也会执行
log.info("user: " + user + ", order: " + order);

// ✅ 占位符：延迟求值
log.info("user: {}, order: {}", user, order);
```

### 8.2 占位符的异常处理

```java
// ✅ 最后一个参数是异常时自动打印堆栈
log.error("处理订单失败, orderId: {}", orderId, e);

// ❌ 占位符会把异常当普通对象
log.error("处理订单失败, orderId: {}, error: {}", orderId, e);
```

## 9. 日志输出规范

### 9.1 关键业务字段

```java
// ✅ 包含关键字段
log.info("订单创建成功, orderId: {}, userId: {}, amount: {}", 
         orderId, userId, amount);

// ❌ 缺少关键字段
log.info("订单创建成功");
```

### 9.2 日志脱敏

```java
// ❌ 泄露敏感信息
log.info("用户登录, username: {}, password: {}", username, password);

// ✅ 脱敏
log.info("用户登录, username: {}", username);
```

### 9.3 MDC 追踪请求链路

```java
// 在 Filter/Interceptor 中设置
MDC.put("traceId", UUID.randomUUID().toString());
try {
    chain.doFilter(request, response);
} finally {
    MDC.clear();
}

// logback.xml 配置
<pattern>%d{yyyy-MM-dd HH:mm:ss} [%thread] [%X{traceId}] %-5level %logger{36} - %msg%n</pattern>
```

## 10. 常见反模式

| 反模式 | 问题 | 正确做法 |
|--------|------|---------|
| e.printStackTrace() | 输出到控制台，无法管理 | log.error("msg", e) |
| catch 后只打印 message | 丢失堆栈 | log.error("msg", e) |
| 日志里打印大对象 | 序列化开销大 | 只打印关键字段 |
| 日志级别混乱 | ERROR 当 INFO 用 | 按规范使用级别 |
| 日志里包含敏感信息 | 合规风险 | 脱敏处理 |
| catch Throwable | 捕获 Error | 只 catch Exception |
| finally 里 return | 覆盖 try 的 return | finally 只做清理 |
