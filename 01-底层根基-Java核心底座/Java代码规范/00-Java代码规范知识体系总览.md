## 3. 为什么必须遵守代码规范

### 3.1 不规范代码的真实代价

| 现象 | 根因 | 代价 |
|------|------|------|
| `public static final int MAX_COUNT = 100;` 写成 `max_count` | 命名不规范 | 团队协作时理解成本翻倍 |
| `if (list != null && list.size() > 0)` | 不知道 `CollectionUtils.isNotEmpty` | 代码冗余，可读性差 |
| `Executors.newFixedThreadPool(100)` | 不知道线程池规范 | OOM 风险，资源耗尽 |
| `catch (Exception e) { e.printStackTrace(); }` | 异常处理不规范 | 线上问题无法定位，日志丢失 |
| `String sql = "SELECT * FROM user WHERE id = " + id;` | SQL 注入 | 数据库被拖库，安全事故 |
| 日志里打印用户密码/身份证号 | 敏感信息未脱敏 | 合规风险，法律问题 |

### 3.2 规范的三个层次

| 层次 | 说明 | 示例 |
|------|------|------|
| **强制** | 违反会导致 bug 或安全事故 | 线程池必须自定义、SQL 必须参数化 |
| **推荐** | 最佳实践，提升可读性和可维护性 | 使用 `Optional` 替代 null 返回 |
| **参考** | 个人习惯或团队约定 | 缩进用 4 空格还是 2 空格 |

### 3.3 一句话定位

> 🎯 **代码规范 = 把"能跑"的代码变成"能维护"的代码**。它解决的不是技术问题，而是**团队协作成本**和**长期维护成本**。阿里巴巴手册之所以成为标准，是因为它把"什么是对的"变成了"什么必须做"。

## 4. 核心规范速查

| 规范 | 一句话解释 | 详见 |
|------|-----------|------|
| 命名：类名 UpperCamelCase | `UserService` 不是 `userService` 或 `user_service` | 01 |
| 命名：常量全大写下划线 | `MAX_RETRY_COUNT` 不是 `maxRetryCount` | 01 |
| 命名：布尔变量前缀 | `isDeleted` / `hasPermission` / `canEdit` | 01 |
| equals 必须同时重写 hashCode | 否则 HashMap/HashSet 行为异常 | 02 |
| 构造器里不要放业务逻辑 | 构造器只做字段初始化 | 02 |
| POJO 必须重写 toString | 便于日志打印和问题排查 | 02 |
| 集合初始化指定容量 | `new ArrayList<>(100)` 避免多次扩容 | 03 |
| 遍历 Map 用 entrySet | `map.keySet()` + `get()` 是双重查找 | 03 |
| 线程池禁止用 Executors | 必须 `new ThreadPoolExecutor(...)` 自定义 | 04 |
| ThreadLocal 用完必须 remove | 否则内存泄漏 | 04 |
| 锁必须放在 try-finally 里 | 防止异常导致死锁 | 04 |
| 异常不要 catch Throwable | 会捕获 OutOfMemoryError 等致命错误 | 05 |
| 日志用 SLF4J 占位符 | `log.info("user: {}", user)` 不是字符串拼接 | 05 |
| SQL 禁止 SELECT * | 只查需要的字段，减少 IO 和网络传输 | 06 |
| 分页必须带排序字段 | 否则分页结果不稳定 | 06 |
| 用户输入必须参数化 | 防止 SQL 注入 | 07 |
| 日志脱敏敏感信息 | 密码/身份证/手机号必须打码 | 07 |

## 5. 学习路线推荐

### 路线 A：新人入职速通（3 天）

1. **D1**：01 命名与格式 + 02 OOP 规约（把代码写"对"）
2. **D2**：03 集合 + 04 并发（把代码写"稳"）
3. **D3**：05 异常日志 + 06 SQL + 07 安全（把代码写"安全"）

### 路线 B：面试冲刺（1 天）

1. 直接看 **08 阿里巴巴手册精讲**，重点背"强制"级规则
2. 快速过一遍 03 集合陷阱（Arrays.asList / subList / fail-fast）
3. 04 并发重点：线程池参数、ThreadLocal 内存泄漏
4. 05 日志重点：占位符 vs 拼接、日志级别

### 路线 C：团队规范制定（架构师向）

1. 精读 **08 手册精讲**，理解每条规则背后的"为什么"
2. 结合团队现状，从 01-07 中筛选必须执行的规则
3. 制定 IDE 代码模板 + Checkstyle 规则 + Code Review 清单
4. 参考手册的"强制 / 推荐 / 参考"三级分类，标注团队优先级

## 6. 快速自测 10 题

| # | 问题 | 自测要点 |
|:-:|------|---------|
| 1 | 为什么 POJO 必须重写 toString？ | 日志打印、问题排查、RPC 序列化 |
| 2 | `new ArrayList()` 默认容量是多少？ | JDK 8 起是 0，首次 add 扩容到 10 |
| 3 | `Arrays.asList()` 返回的 List 能 add 吗？ | 不能，是固定大小的内部类 ArrayList |
| 4 | 线程池为什么禁止用 `Executors.newFixedThreadPool`？ | 队列无界，会 OOM |
| 5 | ThreadLocal 用完为什么要 remove？ | 线程池场景会内存泄漏 |
| 6 | `catch (Exception e)` 和 `catch (Throwable t)` 的区别？ | Throwable 会捕获 Error（OOM、StackOverflow） |
| 7 | 日志为什么用 `log.info("user: {}", user)` 而不是拼接？ | 占位符延迟求值，性能更好 |
| 8 | SQL 为什么禁止 `SELECT *`？ | 网络 IO、无法覆盖索引、字段变更风险 |
| 9 | 什么是 SQL 注入？如何防御？ | 用户输入拼接到 SQL；参数化查询 |
| 10 | 阿里巴巴手册的"强制 / 推荐 / 参考"三级分别是什么意思？ | 强制=必须做，推荐=最佳实践，参考=个人习惯 |

> 💡 答不上来的题，优先回对应模块精读，不要只背结论。
