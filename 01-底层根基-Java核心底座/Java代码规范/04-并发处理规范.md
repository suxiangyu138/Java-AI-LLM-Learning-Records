## 1. 线程池创建规范

### 1.1 为什么禁止 Executors

```java
// ❌ 禁止：队列无界，会 OOM
ExecutorService pool1 = Executors.newFixedThreadPool(10);
// 底层：new LinkedBlockingQueue<Runnable>() 容量 Integer.MAX_VALUE

// ❌ 禁止：线程无上限，会 OOM
ExecutorService pool2 = Executors.newCachedThreadPool();
// 底层：maximumPoolSize = Integer.MAX_VALUE

// ✅ 必须：自定义 ThreadPoolExecutor
ThreadPoolExecutor pool = new ThreadPoolExecutor(
    10,                      // corePoolSize
    20,                      // maximumPoolSize
    60L,                     // keepAliveTime
    TimeUnit.SECONDS,
    new LinkedBlockingQueue<>(1000),  // 有界队列
    new ThreadFactoryBuilder().setNameFormat("pool-%d").build(),
    new ThreadPoolExecutor.CallerRunsPolicy()  // 拒绝策略
);
```

### 1.2 七个参数详解

| 参数 | 说明 | 推荐值 |
|------|------|--------|
| corePoolSize | 核心线程数 | CPU 密集型：N+1；IO 密集型：2N |
| maximumPoolSize | 最大线程数 | 根据业务峰值预估 |
| keepAliveTime | 空闲线程存活时间 | 60s |
| workQueue | 任务队列 | LinkedBlockingQueue（有界） |
| threadFactory | 线程工厂 | 自定义命名 |
| rejectedExecutionHandler | 拒绝策略 | CallerRunsPolicy |

### 1.3 拒绝策略选型

| 策略 | 行为 | 适用场景 |
|------|------|---------|
| AbortPolicy | 抛 RejectedExecutionException | 默认，不容忍丢失 |
| CallerRunsPolicy | 提交者线程执行 | 减缓提交速度 |
| DiscardPolicy | 静默丢弃 | 允许丢失 |
| DiscardOldestPolicy | 丢弃最老任务 | 时效性强的任务 |

### 1.4 自定义 ThreadFactory

```java
ThreadFactory factory = new ThreadFactory() {
    private final AtomicInteger count = new AtomicInteger(1);
    
    @Override
    public Thread newThread(Runnable r) {
        Thread thread = new Thread(r);
        thread.setName("order-pool-" + count.getAndIncrement());
        thread.setDaemon(false);  // 非守护线程
        return thread;
    }
};

// Guava 简化
ThreadFactory factory2 = new ThreadFactoryBuilder()
    .setNameFormat("order-pool-%d")
    .setDaemon(false)
    .build();
```

## 2. ThreadLocal 使用规范

### 2.1 内存泄漏原理

```java
// ThreadLocalMap 的 Entry 结构
static class Entry extends WeakReference<ThreadLocal<?>> {
    Object value;  // ⚠️ 强引用
    Entry(ThreadLocal<?> k, Object v) {
        super(k);  // key 是弱引用
        value = v;
    }
}

// 问题：key 被 GC 回收后，value 无法访问但不会被回收（内存泄漏）
```

### 2.2 线程池场景的泄漏风险

```java
// ❌ 线程池场景：线程复用导致 ThreadLocal 永久持有
ExecutorService pool = Executors.newFixedThreadPool(10);
pool.execute(() -> {
    ThreadLocal<User> userLocal = new ThreadLocal<>();
    userLocal.set(user);
    // ❌ 线程执行完不销毁，ThreadLocal 一直持有 user
});

// ✅ 必须 remove()
pool.execute(() -> {
    ThreadLocal<User> userLocal = new ThreadLocal<>();
    try {
        userLocal.set(user);
        // 业务逻辑
    } finally {
        userLocal.remove();  // ✅ 必须
    }
});
```

### 2.3 TransmittableThreadLocal 解决线程池传递

```java
// ❌ InheritableThreadLocal 在线程池场景失效
ThreadLocal<User> inheritable = new InheritableThreadLocal<>();
pool.execute(() -> {
    // ❌ 拿不到父线程的值（线程池线程已创建）
});

// ✅ TransmittableThreadLocal（阿里开源）
ThreadLocal<User> transmittable = new TransmittableThreadLocal<>();
ExecutorService ttlPool = TtlExecutors.getTtlExecutorService(pool);
ttlPool.execute(() -> {
    // ✅ 可以拿到父线程的值
});
```

## 3. 锁的使用规范

### 3.1 synchronized vs ReentrantLock

| 维度 | synchronized | ReentrantLock |
|------|--------------|---------------|
| 锁释放 | 自动 | 必须 finally unlock |
| 可中断 | ❌ | ✅ lockInterruptibly |
| 超时 | ❌ | ✅ tryLock(timeout) |
| 公平锁 | ❌ | ✅ new ReentrantLock(true) |
| 条件变量 | ❌ | ✅ newCondition |
| 性能 | JDK 6+ 优化后相当 | 相当 |

### 3.2 锁必须放在 try-finally

```java
// ❌ 错误：异常导致死锁
Lock lock = new ReentrantLock();
lock.lock();
doSomething();  // 如果抛异常，锁不会释放
lock.unlock();

// ✅ 正确：finally 释放锁
lock.lock();
try {
    doSomething();
} finally {
    lock.unlock();
}
```

### 3.3 锁顺序一致防死锁

```java
// ❌ 死锁：线程 A 锁 1→2，线程 B 锁 2→1
synchronized (lock1) {
    synchronized (lock2) { }
}

// ✅ 统一锁顺序
synchronized (lock1) {
    synchronized (lock2) { }
}
```

### 3.4 锁超时避免死锁

```java
Lock lock = new ReentrantLock();
if (lock.tryLock(3, TimeUnit.SECONDS)) {
    try {
        doSomething();
    } finally {
        lock.unlock();
    }
} else {
    // 超时处理
}
```

## 4. 线程安全集合选型

### 4.1 Map 选型

| 集合 | 特点 | 适用场景 |
|------|------|---------|
| ConcurrentHashMap | 分段锁，高并发 | 读多写多 |
| Hashtable | 全表锁，性能差 | 不推荐 |
| Collections.synchronizedMap | 全表锁 | 不推荐 |
| ConcurrentSkipListMap | 有序并发 Map | 需要排序 |

### 4.2 List 选型

| 集合 | 特点 | 适用场景 |
|------|------|---------|
| CopyOnWriteArrayList | 写时复制 | 读多写少 |
| Collections.synchronizedList | 全表锁 | 不推荐 |

### 4.3 Queue 选型

| 集合 | 特点 | 适用场景 |
|------|------|---------|
| ConcurrentLinkedQueue | 无锁 CAS | 高并发无界队列 |
| LinkedBlockingQueue | 锁 + 条件变量 | 有界队列 |
| ArrayBlockingQueue | 数组实现有界队列 | 固定容量 |

## 5. 原子类与 CAS

### 5.1 LongAdder vs AtomicLong

```java
// AtomicLong：高并发下 CAS 竞争激烈
AtomicLong atomicLong = new AtomicLong(0);

// LongAdder：分段思想，性能更好
LongAdder longAdder = new LongAdder();
longAdder.increment();
long sum = longAdder.sum();
```

> 💡 **性能对比**：并发度越高，LongAdder 优势越明显（10 倍以上）。

### 5.2 CAS 的 ABA 问题

```java
// 问题：A → B → A，CAS 认为没变化
AtomicInteger atomic = new AtomicInteger(100);
atomic.compareAndSet(100, 200);  // A → B
atomic.compareAndSet(200, 100);  // B → A
atomic.compareAndSet(100, 300);  // ✅ 成功，但中间被改过

// 解决：AtomicStampedReference（带版本号）
AtomicStampedReference<Integer> stamped = new AtomicStampedReference<>(100, 0);
stamped.compareAndSet(100, 200, 0, 1);  // 版本号 0 → 1
```

## 6. 并发工具类

### 6.1 CountDownLatch vs CyclicBarrier

```java
// CountDownLatch：等待多个线程完成（一次性）
CountDownLatch latch = new CountDownLatch(3);
for (int i = 0; i < 3; i++) {
    new Thread(() -> {
        doWork();
        latch.countDown();
    }).start();
}
latch.await();  // 等待 3 个线程完成

// CyclicBarrier：多线程互相等待（可复用）
CyclicBarrier barrier = new CyclicBarrier(3, () -> {
    System.out.println("全部到达");
});
for (int i = 0; i < 3; i++) {
    new Thread(() -> {
        doWork();
        barrier.await();  // 等待其他线程
    }).start();
}
```

### 6.2 Semaphore 限流

```java
// 限制同时访问的线程数
Semaphore semaphore = new Semaphore(10);
semaphore.acquire();
try {
    doWork();
} finally {
    semaphore.release();
}
```

## 7. 线程安全单例

### 7.1 四种实现对比

```java
// 1. 饿汉式（推荐：简单安全）
public class Singleton {
    private static final Singleton INSTANCE = new Singleton();
    private Singleton() { }
    public static Singleton getInstance() {
        return INSTANCE;
    }
}

// 2. 双重检查锁（懒加载）
public class Singleton {
    private static volatile Singleton instance;
    private Singleton() { }
    public static Singleton getInstance() {
        if (instance == null) {
            synchronized (Singleton.class) {
                if (instance == null) {
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}

// 3. 静态内部类（推荐：懒加载 + 线程安全）
public class Singleton {
    private Singleton() { }
    private static class Holder {
        private static final Singleton INSTANCE = new Singleton();
    }
    public static Singleton getInstance() {
        return Holder.INSTANCE;
    }
}

// 4. 枚举（推荐：防序列化/反射攻击）
public enum Singleton {
    INSTANCE;
    public void doSomething() { }
}
```

## 8. 常见反模式

| 反模式 | 问题 | 正确做法 |
|--------|------|---------|
| 线程池参数拍脑袋 | OOM 风险 | 根据业务计算 |
| ThreadLocal 忘 remove | 内存泄漏 | finally remove |
| 锁放在 try 外面 | 异常导致死锁 | try-finally |
| 用 HashMap 当并发 Map | 数据不一致 | ConcurrentHashMap |
| 用 synchronized 锁字符串常量 | 字符串常量池导致意外共享 | new Object() |
| 线程池提交任务不处理返回值 | 异常被吞掉 | Future.get() 处理 |
