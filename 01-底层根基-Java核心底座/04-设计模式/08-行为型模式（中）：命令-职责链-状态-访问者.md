# 行为型模式（中）：命令-职责链-状态-访问者

> 命令模式将请求封装为对象，职责链模式将请求沿链传递，状态模式自动切换状态行为，访问者模式将数据结构与操作分离。

## 1. 命令模式

### 1.1 核心定义

**将一个请求或操作封装为一个独立的对象，把请求的发送者与请求的执行者完全解耦，让请求具备可传递、可排队、可撤销的能力。**

核心是"行为对象化"——将行为转化为对象，让系统可以像管理普通对象一样管理操作。

### 1.2 四大角色

```
┌──────────┐    ┌─────────────┐    ┌──────────────┐
│ Invoker  │───▶│  Command    │───▶│  Receiver    │
│ (调用者)  │    │  (命令接口)  │    │  (接收者)    │
└──────────┘    └──────┬──────┘    └──────────────┘
                       │
              ┌────────┴────────┐
              │ ConcreteCommand │
              │ (持有Receiver)   │
              └─────────────────┘
```

| 角色 | 说明 |
|------|------|
| **抽象命令（Command）** | 定义命令执行/撤销的统一接口 |
| **具体命令（Concrete Command）** | 持有接收者引用，封装请求内容 |
| **命令接收者（Receiver）** | 实际执行业务逻辑的对象 |
| **命令调用者（Invoker）** | 触发命令执行，不关心命令内容 |

### 1.3 代码实现（订单操作命令）

```java
// 抽象命令
public interface OrderCommand {
    void execute(String orderId);
    void undo(String orderId); // 可选：撤销
}

// 接收者：实际执行业务
public class OrderReceiver {
    public void createOrder(String orderId) {
        System.out.println("下单：" + orderId);
    }
    public void cancelOrder(String orderId) {
        System.out.println("取消订单：" + orderId);
    }
    public void undoCreate(String orderId) {
        System.out.println("撤销下单：" + orderId);
    }
}

// 具体命令：下单
public class CreateOrderCommand implements OrderCommand {
    private OrderReceiver receiver;

    public CreateOrderCommand(OrderReceiver receiver) {
        this.receiver = receiver;
    }

    @Override
    public void execute(String orderId) { receiver.createOrder(orderId); }

    @Override
    public void undo(String orderId) { receiver.undoCreate(orderId); }
}

// 具体命令：取消订单
public class CancelOrderCommand implements OrderCommand {
    private OrderReceiver receiver;

    public CancelOrderCommand(OrderReceiver receiver) {
        this.receiver = receiver;
    }

    @Override
    public void execute(String orderId) { receiver.cancelOrder(orderId); }

    @Override
    public void undo(String orderId) {
        System.out.println("取消操作无法撤销");
    }
}

// 调用者：支持命令队列和撤销
public class OrderInvoker {
    private OrderCommand command;
    private List<OrderCommand> queue = new ArrayList<>();

    public void setCommand(OrderCommand command) { this.command = command; }

    public void execute(String orderId) {
        if (command != null) command.execute(orderId);
    }

    public void undo(String orderId) {
        if (command != null) command.undo(orderId);
    }

    public void addToQueue(OrderCommand cmd) { queue.add(cmd); }

    public void executeQueue(String orderId) {
        queue.forEach(cmd -> cmd.execute(orderId));
        queue.clear();
    }
}

// 客户端
OrderReceiver receiver = new OrderReceiver();
OrderInvoker invoker = new OrderInvoker();

invoker.setCommand(new CreateOrderCommand(receiver));
invoker.execute("ORDER_001"); // 下单
invoker.undo("ORDER_001");    // 撤销下单
```

### 1.4 适用场景

- 电商订单操作（下单、取消、支付、退款）
- 操作撤销与重做（文本编辑器、后台指令）
- 任务队列与异步处理（Runnable + 线程池）

```java
// Runnable就是命令模式的日常应用
Runnable task = () -> System.out.println("执行任务");
ExecutorService executor = Executors.newFixedThreadPool(10);
executor.execute(task); // 线程池是调用者
```

## 2. 职责链模式

### 2.1 核心定义

**将多个处理请求的对象连成一条链，请求沿着链传递，直到有一个对象能够处理该请求，避免请求发送者与接收者耦合。**

相当于给请求搭建一条"处理流水线"，每个处理节点只负责自己的职责范围，超出范围就自动转交给下一个节点。

### 2.2 角色结构

```
Client → Handler A → Handler B → Handler C → ...
         能处理则处理，不能则传递给下一个
```

### 2.3 代码实现（费用审批）

```java
// 请求封装
public class ExpenseRequest {
    private String name;
    private double money;
    private String status;
    // constructor, getters...
}

// 抽象处理者
public abstract class Approver {
    protected Approver next;
    protected String name;

    public void setNext(Approver next) { this.next = next; }

    public abstract void handle(ExpenseRequest request);
}

// 具体处理者：组长（≤1000元）
public class GroupLeader extends Approver {
    public GroupLeader() { this.name = "组长"; }

    @Override
    public void handle(ExpenseRequest request) {
        if (request.getMoney() <= 1000) {
            System.out.println(name + "审批通过，金额：" + request.getMoney());
            request.setStatus("组长审批通过");
        } else if (next != null) {
            System.out.println(name + "无权审批，转交下一级");
            next.handle(request);
        }
    }
}

// 具体处理者：经理（1000~5000元）
public class Manager extends Approver {
    public Manager() { this.name = "经理"; }

    @Override
    public void handle(ExpenseRequest request) {
        if (request.getMoney() <= 5000) {
            System.out.println(name + "审批通过，金额：" + request.getMoney());
            request.setStatus("经理审批通过");
        } else if (next != null) {
            System.out.println(name + "无权审批，转交下一级");
            next.handle(request);
        }
    }
}

// 具体处理者：总经理（>5000元）
public class Director extends Approver {
    public Director() { this.name = "总经理"; }

    @Override
    public void handle(ExpenseRequest request) {
        System.out.println(name + "审批通过，金额：" + request.getMoney());
        request.setStatus("总经理审批通过");
    }
}

// 客户端：编排链条
GroupLeader leader = new GroupLeader();
Manager manager = new Manager();
Director director = new Director();
leader.setNext(manager);
manager.setNext(director);

// 发起请求
leader.handle(new ExpenseRequest("张三", 800));   // 组长审批
leader.handle(new ExpenseRequest("李四", 3000));  // 经理审批
leader.handle(new ExpenseRequest("王五", 8000));  // 总经理审批
```

### 2.4 Web过滤器链

```java
// Servlet Filter——经典职责链
@WebFilter("/*")
public class LoggingFilter implements Filter {
    @Override
    public void doFilter(ServletRequest request, ServletResponse response, FilterChain chain)
            throws IOException, ServletException {
        System.out.println("请求前");
        chain.doFilter(request, response); // 调用下一个Filter
        System.out.println("请求后");
    }
}

// Spring MVC Interceptor
@Component
public class AuthInterceptor implements HandlerInterceptor {
    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) {
        String token = request.getHeader("Authorization");
        if (token == null) {
            response.setStatus(401);
            return false; // 阻断链
        }
        return true; // 继续执行链
    }
}
```

### 2.5 两种链式结构

| 类型 | 说明 | 示例 |
|------|------|------|
| **普通职责链** | 找到能处理的节点即终止 | 审批流程 |
| **全链路职责链** | 经过所有节点，各执行部分逻辑 | Filter链、Interceptor链 |

### 2.6 注意事项

- 控制链条长度（建议不超过5个节点）
- 做好末端兜底处理，防止请求未处理
- 杜绝循环引用导致无限递归

## 3. 状态模式

### 3.1 核心定义

**允许一个对象在其内部状态发生变化时，改变它的行为，使对象看起来好像修改了它的类。**

将不同状态对应的行为封装到独立的状态类中，彻底消除大量if-else/switch-case。

### 3.2 四大角色

| 角色 | 说明 |
|------|------|
| **上下文（Context）** | 持有当前状态引用，委派行为给状态对象 |
| **抽象状态（State）** | 定义所有状态的统一行为规范 |
| **具体状态（Concrete State）** | 封装该状态下的具体行为，可在行为中触发状态切换 |
| **状态管理器（可选）** | 管理状态对象的创建与流转规则 |

### 3.3 代码实现（订单状态流转）

```java
// 抽象状态
public interface OrderState {
    void pay(OrderContext context);
    void cancel(OrderContext context);
    void deliver(OrderContext context);
    void complete(OrderContext context);
    String getStateName();
}

// 具体状态：待支付
public class PendingPayState implements OrderState {
    @Override
    public void pay(OrderContext context) {
        System.out.println("待支付 → 支付成功");
        context.setState(new PaidState());
    }
    @Override
    public void cancel(OrderContext context) {
        System.out.println("待支付 → 已取消");
        context.setState(new CancelledState());
    }
    @Override
    public void deliver(OrderContext context) {
        System.out.println("待支付 → 无法发货，请先支付");
    }
    @Override
    public void complete(OrderContext context) {
        System.out.println("待支付 → 无法完成");
    }
    @Override
    public String getStateName() { return "待支付"; }
}

// 具体状态：已支付
public class PaidState implements OrderState {
    @Override
    public void pay(OrderContext context) {
        System.out.println("已支付 → 无需重复支付");
    }
    @Override
    public void cancel(OrderContext context) {
        System.out.println("已支付 → 取消（触发退款）");
        context.setState(new CancelledState());
    }
    @Override
    public void deliver(OrderContext context) {
        System.out.println("已支付 → 已发货");
        context.setState(new DeliveredState());
    }
    @Override
    public void complete(OrderContext context) {
        System.out.println("已支付 → 请先发货");
    }
    @Override
    public String getStateName() { return "已支付"; }
}

// 其他状态：已发货、已取消、已完成（结构类似，略）

// 上下文：订单
public class OrderContext {
    private String orderNo;
    private OrderState currentState;

    public OrderContext(String orderNo) {
        this.orderNo = orderNo;
        this.currentState = new PendingPayState(); // 初始状态
    }

    public void setState(OrderState state) { this.currentState = state; }

    // 委派行为给当前状态对象
    public void pay() { currentState.pay(this); }
    public void cancel() { currentState.cancel(this); }
    public void deliver() { currentState.deliver(this); }
    public void complete() { currentState.complete(this); }
}

// 客户端
OrderContext order = new OrderContext("ORDER_001");
order.pay();     // 待支付 → 已支付
order.deliver(); // 已支付 → 已发货
order.complete();// 已发货 → 已完成
order.cancel();  // 已完成 → 无法取消
```

### 3.4 状态 vs 策略

| 对比 | 状态模式 | 策略模式 |
|------|---------|---------|
| 切换触发 | 内部状态变化自动切换 | 客户端主动选择 |
| 状态间关系 | 有关联，自动流转 | 彼此独立，可互换 |
| 目的 | 根据状态改变行为 | 选择不同算法 |

### 3.5 适用场景

- 订单状态管理（电商核心场景）
- 工作流节点流转
- 电梯运行状态控制
- 设备状态管理

## 4. 访问者模式

### 4.1 核心定义

**表示一个作用于某对象结构中的各元素的操作，使你可以不改变各元素类的前提下，定义作用于这些元素的新操作。**

核心是将**数据结构与数据操作分离**，新增操作只需新增访问者类，无需修改元素类。

### 4.2 五大角色

| 角色 | 说明 |
|------|------|
| **抽象访问者（Visitor）** | 定义对所有具体元素的访问方法 |
| **具体访问者（Concrete Visitor）** | 封装每种元素的具体操作逻辑 |
| **抽象元素（Element）** | 定义`accept(visitor)`方法 |
| **具体元素（Concrete Element）** | 实现`accept`，调用`visitor.visitXxx(this)` |
| **对象结构（Object Structure）** | 存储并遍历所有元素 |

### 4.3 代码实现（商品多维操作）

```java
// 抽象元素
public interface ProductElement {
    void accept(ProductVisitor visitor);
}

// 抽象访问者
public interface ProductVisitor {
    void visitElectronic(ElectronicProduct p);
    void visitClothing(ClothingProduct p);
    void visitFood(FoodProduct p);
}

// 具体元素：电子商品
public class ElectronicProduct implements ProductElement {
    private String name;
    private BigDecimal price;
    private int stock;

    public ElectronicProduct(String name, BigDecimal price, int stock) {
        this.name = name; this.price = price; this.stock = stock;
    }

    @Override
    public void accept(ProductVisitor visitor) {
        visitor.visitElectronic(this); // 双分派
    }
    // getters...
}

// 具体元素：服装商品
public class ClothingProduct implements ProductElement {
    private String name;
    private BigDecimal price;
    private String size;

    public ClothingProduct(String name, BigDecimal price, String size) {
        this.name = name; this.price = price; this.size = size;
    }

    @Override
    public void accept(ProductVisitor visitor) {
        visitor.visitClothing(this);
    }
    // getters...
}

// 具体元素：食品商品
public class FoodProduct implements ProductElement {
    private String name;
    private BigDecimal price;
    private String expirationDate;
    // constructor, accept...
}

// 具体访问者：统计总价
public class TotalPriceVisitor implements ProductVisitor {
    private BigDecimal total = BigDecimal.ZERO;

    @Override
    public void visitElectronic(ElectronicProduct p) {
        total = total.add(p.getPrice().multiply(new BigDecimal(p.getStock())));
    }

    @Override
    public void visitClothing(ClothingProduct p) {
        total = total.add(p.getPrice());
    }

    @Override
    public void visitFood(FoodProduct p) {
        total = total.add(p.getPrice());
    }

    public BigDecimal getTotal() { return total; }
}

// 具体访问者：打印详情
public class PrintDetailVisitor implements ProductVisitor {
    @Override
    public void visitElectronic(ElectronicProduct p) {
        System.out.println("【电子】" + p.getName() + " 库存" + p.getStock());
    }
    @Override
    public void visitClothing(ClothingProduct p) {
        System.out.println("【服装】" + p.getName() + " 尺码" + p.getSize());
    }
    @Override
    public void visitFood(FoodProduct p) {
        System.out.println("【食品】" + p.getName() + " 保质期" + p.getExpirationDate());
    }
}

// 对象结构
public class ProductStructure {
    private List<ProductElement> products = new ArrayList<>();

    public void add(ProductElement p) { products.add(p); }

    public void accept(ProductVisitor visitor) {
        for (ProductElement p : products) {
            p.accept(visitor);
        }
    }
}

// 客户端
ProductElement phone = new ElectronicProduct("手机", new BigDecimal("2999"), 50);
ProductElement shirt = new ClothingProduct("衬衫", new BigDecimal("199"), "M");
ProductElement milk = new FoodProduct("牛奶", new BigDecimal("6.9"), "2026-12-31");

ProductStructure structure = new ProductStructure();
structure.add(phone);
structure.add(shirt);
structure.add(milk);

// 操作1：统计总价
TotalPriceVisitor priceVisitor = new TotalPriceVisitor();
structure.accept(priceVisitor);
System.out.println("总价：" + priceVisitor.getTotal());

// 操作2：打印详情（新增操作，无需修改任何商品类）
PrintDetailVisitor printVisitor = new PrintDetailVisitor();
structure.accept(printVisitor);
```

### 4.4 优缺点

| 优点 | 缺点 |
|------|------|
| 结构与操作彻底解耦 | **元素扩展困难**：新增元素需改所有访问者 |
| 新增操作仅需新增访问者类 | 可能破坏元素封装性 |
| 同类操作集中管理 | 元素频繁变化时不适用 |

### 4.5 适用场景

- 数据结构稳定、操作频繁变化（如报表生成、数据统计）
- 对复杂结构执行统一多维操作
- Java后端：订单多维度统计、数据导出、规则校验
