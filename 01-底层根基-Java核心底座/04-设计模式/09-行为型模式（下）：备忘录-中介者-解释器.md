## 1. 备忘录模式

### 1.1 核心定义

**在不破坏封装的前提下，捕获一个对象的内部状态，并在该对象之外保存这个状态，以便后续可以将对象恢复到之前的状态。**

核心是"状态快照、封装隔离、可逆恢复"，将需要备份的对象状态封装为独立的备忘录对象，交由专门的管理者统一托管。

### 1.2 三大核心角色

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  Originator  │────▶│   Memento    │◀────│   Caretaker  │
│  (原发器)     │创建  │  (备忘录)    │托管  │  (管理者)     │
└──────────────┘     └──────────────┘     └──────────────┘
```

| 角色 | 说明 |
|------|------|
| **原发器（Originator）** | 需要备份状态的核心业务对象，负责创建和恢复备忘录 |
| **备忘录（Memento）** | 存储原发器内部状态的快照，对外隐藏状态数据 |
| **管理者（Caretaker）** | 托管备忘录对象，不修改、不访问备忘录内部状态 |

### 1.3 代码实现（订单状态回滚）

```java
// 备忘录窄接口：对外无任何暴露方法
public interface Memento { }

// 原发器：订单对象
public class OrderOriginator {
    private String orderNo;
    private String orderStatus;
    private BigDecimal orderAmount;

    // 创建备忘录
    public Memento createMemento() {
        return new OrderMemento(orderNo, orderStatus, orderAmount);
    }

    // 恢复状态
    public void restoreFromMemento(Memento memento) {
        OrderMemento orderMemento = (OrderMemento) memento;
        this.orderNo = orderMemento.orderNo;
        this.orderStatus = orderMemento.orderStatus;
        this.orderAmount = orderMemento.orderAmount;
    }

    // 私有备忘录类：宽接口，仅原发器可访问
    private static class OrderMemento implements Memento {
        private final String orderNo;
        private final String orderStatus;
        private final BigDecimal orderAmount;

        OrderMemento(String orderNo, String orderStatus, BigDecimal orderAmount) {
            this.orderNo = orderNo;
            this.orderStatus = orderStatus;
            this.orderAmount = orderAmount;
        }
    }

    public void updateOrder(String orderStatus, BigDecimal orderAmount) {
        this.orderStatus = orderStatus;
        this.orderAmount = orderAmount;
    }

    public void setOrderNo(String orderNo) { this.orderNo = orderNo; }

    public void printInfo() {
        System.out.println("订单：" + orderNo + " 状态：" + orderStatus + " 金额：" + orderAmount);
    }
}

// 管理者：管理备忘录
public class OrderCaretaker {
    private Memento memento;

    public void saveMemento(Memento memento) { this.memento = memento; }
    public Memento getMemento() { return memento; }
}

// 客户端
OrderOriginator order = new OrderOriginator();
order.setOrderNo("ORDER_001");
order.updateOrder("待支付", new BigDecimal("99.00"));
order.printInfo(); // 初始状态

OrderCaretaker caretaker = new OrderCaretaker();
caretaker.saveMemento(order.createMemento()); // 备份

order.updateOrder("已支付", new BigDecimal("109.00"));
order.printInfo(); // 修改后

order.restoreFromMemento(caretaker.getMemento()); // 回滚
order.printInfo(); // 已恢复至初始状态
```

### 1.4 优缺点

| 优点 | 缺点 |
|------|------|
| 完美保障封装性 | 频繁备份消耗内存 |
| 快速实现状态回滚 | 大状态对象开销高 |
| 职责分离清晰 | 需手动控制备份频率 |

### 1.5 适用场景

- 文本编辑器撤销/恢复
- 电商订单修改回退
- 系统配置快照与回滚
- 工作流节点回退

## 2. 中介者模式

### 2.1 核心定义

**定义一个中介者对象，封装多个对象之间的交互，使对象之间无需直接通信，而是通过中介者传递消息，降低对象之间的耦合。**

将多对多的网状交互转化为一对多的星形交互，是迪米特法则的极致体现。

```
         ┌─────────────────────────┐
         │       Mediator          │  (中介者)
         └──────┬──────┬──────┬────┘
            ▲   │  ▲   │  ▲   │
            └───┘  └───┘  └───┘
         ColleagueA  B       C    (同事类，不直接交互)
```

### 2.2 四大角色

| 角色 | 说明 |
|------|------|
| **抽象中介者（Mediator）** | 定义同事注册与消息转发的统一方法 |
| **具体中介者（Concrete Mediator）** | 持有所有同事引用，实现具体协调逻辑 |
| **抽象同事类（Colleague）** | 持有中介者引用，定义发送/接收标准流程 |
| **具体同事类（Concrete Colleague）** | 处理自身核心业务，通过中介者与其他同事通信 |

### 2.3 代码实现（订单模块协调）

```java
// 抽象中介者
public interface OrderMediator {
    void registerColleague(Colleague colleague);
    void coordinate(Colleague sender, String operate);
}

// 抽象同事类
public abstract class Colleague {
    protected OrderMediator mediator;
    protected String moduleName;

    public Colleague(String moduleName, OrderMediator mediator) {
        this.moduleName = moduleName;
        this.mediator = mediator;
        mediator.registerColleague(this); // 自动注册
    }

    public void sendRequest(String operate) {
        mediator.coordinate(this, operate);
    }

    public abstract void execute(String operate);
}

// 具体同事类：各业务模块
public class OrderColleague extends Colleague {
    public OrderColleague(OrderMediator mediator) { super("订单模块", mediator); }
    @Override
    public void execute(String operate) {
        if ("create".equals(operate)) System.out.println("订单模块：生成订单");
    }
}

public class StockColleague extends Colleague {
    public StockColleague(OrderMediator mediator) { super("库存模块", mediator); }
    @Override
    public void execute(String operate) {
        if ("deduct".equals(operate)) System.out.println("库存模块：扣减库存");
    }
}

public class PayColleague extends Colleague {
    public PayColleague(OrderMediator mediator) { super("支付模块", mediator); }
    @Override
    public void execute(String operate) {
        if ("pay".equals(operate)) System.out.println("支付模块：扣款成功");
    }
}

public class LogColleague extends Colleague {
    public LogColleague(OrderMediator mediator) { super("日志模块", mediator); }
    @Override
    public void execute(String operate) {
        System.out.println("日志模块：记录" + operate + "日志");
    }
}

// 具体中介者：统一调度器
public class OrderMediatorImpl implements OrderMediator {
    private List<Colleague> colleagues = new ArrayList<>();

    @Override
    public void registerColleague(Colleague colleague) {
        colleagues.add(colleague);
    }

    @Override
    public void coordinate(Colleague sender, String operate) {
        // 订单模块发起创建请求，中介者调度全流程
        if (sender instanceof OrderColleague && "create".equals(operate)) {
            for (Colleague c : colleagues) {
                if (c instanceof OrderColleague) c.execute("create");
                else if (c instanceof StockColleague) c.execute("deduct");
                else if (c instanceof PayColleague) c.execute("pay");
                else if (c instanceof LogColleague) c.execute("订单创建");
            }
        }
    }
}

// 客户端
OrderMediator mediator = new OrderMediatorImpl();
Colleague order = new OrderColleague(mediator);
new StockColleague(mediator);
new PayColleague(mediator);
new LogColleague(mediator);

order.sendRequest("create");
// 输出：订单模块：生成订单 → 库存模块：扣减库存 → 支付模块：扣款成功 → 日志模块：记录订单创建日志
```

### 2.4 中介者 vs 观察者

| 对比维度 | 中介者模式 | 观察者模式 |
|----------|-----------|-----------|
| 核心目的 | 消除多对象网状耦合，集中协调 | 一对多事件通知 |
| 通信方式 | 双向协作，主动调度 | 单向推送，被动响应 |
| 依赖结构 | 星形结构 | 一对多结构 |
| 适用场景 | 多模块复杂协作 | 状态变更通知 |

### 2.5 适用场景

- 电商订单全流程协同（订单→库存→支付→日志）
- 聊天室消息转发
- UI组件交互（按钮、输入框、弹窗联动）
- API网关服务调度

### 2.6 注意事项

- 严禁同事类直接交互，所有通信必须通过中介者中转
- 控制中介者复杂度，按业务域拆分
- 避免过度设计（3个以内对象的简单协作无需使用）

## 3. 解释器模式

### 3.1 核心定义

**定义一个语言的文法，并提供一个解释器来解释该语言中的句子，用于处理特定格式的文本或表达式。**

属于小众但专业的模式，在规则引擎、表达式解析、DSL（领域特定语言）场景中不可替代。

### 3.2 五大角色

| 角色 | 说明 |
|------|------|
| **抽象表达式（Abstract Expression）** | 定义统一的解释方法`interpret(context)` |
| **终结符表达式（Terminal Expression）** | 最小、不可拆分的语法单元（数字、变量） |
| **非终结符表达式（Nonterminal Expression）** | 可拆分的复合语法单元（加减乘除） |
| **上下文（Context）** | 存储全局变量映射、解析状态 |
| **客户端（Client）** | 构建表达式树，触发解析 |

### 3.3 代码实现（数学表达式计算）

```java
// 上下文：存储变量值
public class ExpressionContext {
    private Map<String, Integer> map = new HashMap<>();

    public int get(String key) { return map.get(key); }
    public void set(String key, int value) { map.put(key, value); }
}

// 抽象表达式
public interface Expression {
    int interpret(ExpressionContext context);
}

// 终结符表达式：变量解析（最小单元）
public class VariableExpression implements Expression {
    private String name;

    public VariableExpression(String name) { this.name = name; }

    @Override
    public int interpret(ExpressionContext context) {
        return context.get(name);
    }
}

// 非终结符表达式：加法
public class AddExpression implements Expression {
    private Expression left;
    private Expression right;

    public AddExpression(Expression left, Expression right) {
        this.left = left;
        this.right = right;
    }

    @Override
    public int interpret(ExpressionContext context) {
        return left.interpret(context) + right.interpret(context);
    }
}

// 非终结符表达式：减法
public class SubExpression implements Expression {
    private Expression left;
    private Expression right;

    public SubExpression(Expression left, Expression right) {
        this.left = left;
        this.right = right;
    }

    @Override
    public int interpret(ExpressionContext context) {
        return left.interpret(context) - right.interpret(context);
    }
}

// 客户端：构建表达式树 "a + b - a"
ExpressionContext context = new ExpressionContext();
context.set("a", 10);
context.set("b", 20);

Expression a = new VariableExpression("a");
Expression b = new VariableExpression("b");

// 构建： (a + b) - a
Expression add = new AddExpression(a, b);
Expression sub = new SubExpression(add, a);

int result = sub.interpret(context);
System.out.println("a + b - a = " + result); // 10+20-10=20
```

### 3.4 优缺点

| 优点 | 缺点 |
|------|------|
| 规则与执行逻辑彻底解耦 | 仅适合简单语法场景 |
| 扩展性强（新增运算符只需新增类） | 复杂语法会产生大量类 |
| 复杂逻辑模块化 | 递归解析性能较差 |

### 3.5 适用场景

- 轻量级规则引擎（审批规则、风控规则、积分计算）
- 数学表达式计算（自定义公式）
- Spring EL表达式、MyBatis动态SQL
- DSL领域特定语言

### 3.6 注意事项

> 生产环境复杂规则解析，优先使用成熟框架：
> - 复杂规则：Drools规则引擎、阿里QLExpress
> - 简单表达式：Spring EL（SpEL）
> - 高性能场景：编译型方案而非解释型

## 4. 行为型模式全对比

| 模式 | 核心一句话 | 关注点 | 适用场景 |
|------|-----------|--------|----------|
| **模板方法** | 父类定骨架，子类实现细节 | 流程标准化 | 框架扩展点、JdbcTemplate |
| **策略模式** | 算法封装，灵活切换 | 算法替换 | 支付方式、排序、促销 |
| **观察者模式** | 一对多通知，状态变更联动 | 事件驱动 | Spring Event、消息订阅 |
| **迭代器模式** | 统一遍历集合，屏蔽底层 | 遍历解耦 | Java集合框架 |
| **命令模式** | 封装请求，支持排队/撤销 | 行为对象化 | 任务队列、撤销重做 |
| **职责链** | 请求沿链传递，自动匹配处理者 | 链式处理 | 审批流、Filter、拦截器 |
| **状态模式** | 状态改变，行为自动改变 | 状态流转 | 订单状态机、工作流 |
| **访问者模式** | 数据与操作分离，新增操作不改元素 | 操作扩展 | 数据统计、报表生成 |
| **备忘录模式** | 状态快照，支持回滚 | 状态恢复 | 撤销恢复、配置回滚 |
| **中介者模式** | 中介者协调，多对多转一对多 | 交互解耦 | 多模块协作、聊天室 |
| **解释器模式** | 定义语法，解释执行 | 语法解析 | 规则引擎、表达式计算 |
