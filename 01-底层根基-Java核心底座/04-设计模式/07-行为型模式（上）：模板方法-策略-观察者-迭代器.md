# 行为型模式（上）：模板方法-策略-观察者-迭代器

> 行为型模式关注对象间的职责分配与通信。模板方法固化算法骨架，策略模式灵活切换算法，观察者实现一对多事件通知，迭代器统一集合遍历。

## 1. 模板方法模式

### 1.1 核心定义

**定义一个操作的算法骨架（模板），将一些步骤延迟到子类中实现，使子类可以在不改变算法结构的前提下重新定义某些步骤。**

核心是"固定骨架、灵活实现"——父类定义业务流程的统一框架，子类实现可变的细节步骤。

### 1.2 角色结构

```
AbstractClass (抽象类)
├── templateMethod() ← final，定义算法骨架
├── step1() ← 具体方法（不变步骤）
├── step2() ← 抽象方法（可变步骤，子类必须实现）
└── hook()  ← 钩子方法（默认实现，子类可选覆盖）

ConcreteClassA         ConcreteClassB
└── step2()            └── step2()
└── hook() (可选)       └── hook() (可选)
```

### 1.3 代码实现（数据导出模板）

```java
// 抽象类：定义数据导出的统一流程
public abstract class AbstractDataExport {

    // 模板方法（final禁止子类重写）
    public final void exportData(String exportParam) {
        // 步骤1：参数校验（不变步骤）
        if (!validateParam(exportParam)) {
            System.out.println("参数校验失败");
            return;
        }
        // 步骤2：查询数据（不变步骤）
        List<String> dataList = queryData(exportParam);
        if (dataList == null || dataList.isEmpty()) return;

        // 步骤3：数据处理（可变步骤——子类实现）
        List<String> processedData = processData(dataList);
        // 步骤4：导出文件（可变步骤——子类实现）
        exportFile(processedData, exportParam);

        // 钩子方法：是否需要额外操作
        if (needLog()) {
            System.out.println("记录操作日志");
        }
    }

    // 不变步骤：父类统一实现
    private boolean validateParam(String param) {
        return param != null && !param.isEmpty();
    }

    private List<String> queryData(String param) {
        System.out.println("查询数据：" + param);
        return List.of("订单1,99.00", "订单2,199.00");
    }

    // 可变步骤：抽象方法，子类实现
    protected abstract List<String> processData(List<String> dataList);
    protected abstract void exportFile(List<String> data, String param);

    // 钩子方法：默认实现，子类可覆盖
    protected boolean needLog() { return true; }
}

// 具体子类：Excel导出
public class ExcelDataExport extends AbstractDataExport {
    @Override
    protected List<String> processData(List<String> dataList) {
        System.out.println("Excel格式：添加表头");
        return dataList;
    }

    @Override
    protected void exportFile(List<String> data, String param) {
        System.out.println("导出Excel文件：" + param + ".xlsx");
    }
}

// 具体子类：PDF导出
public class PdfDataExport extends AbstractDataExport {
    @Override
    protected List<String> processData(List<String> dataList) {
        System.out.println("PDF格式：格式化数据");
        return dataList;
    }

    @Override
    protected void exportFile(List<String> data, String param) {
        System.out.println("导出PDF文件：" + param + ".pdf");
    }

    @Override
    protected boolean needLog() { return false; } // PDF导出无需日志
}

// 客户端
AbstractDataExport export = new ExcelDataExport();
export.exportData("D:/订单数据");
```

### 1.4 Spring中的模板方法

```java
// Spring源码：AbstractApplicationContext.refresh() 是模板方法的典范
@Override
public void refresh() throws BeansException {
    synchronized (this.startupShutdownMonitor) {
        prepareRefresh();                    // 1. 准备刷新上下文
        ConfigurableListableBeanFactory beanFactory = obtainFreshBeanFactory(); // 2. 获取BeanFactory（抽象）
        prepareBeanFactory(beanFactory);     // 3. 准备BeanFactory
        postProcessBeanFactory(beanFactory); // 4. 子类扩展点（钩子）
        invokeBeanFactoryPostProcessors(beanFactory); // 5. 调用后置处理器
        registerBeanPostProcessors(beanFactory);      // 6. 注册BeanPostProcessor
        initMessageSource();                 // 7. 初始化消息源
        initApplicationEventMulticaster();   // 8. 初始化事件多播器
        onRefresh();                         // 9. 子类扩展点（钩子）
        registerListeners();                 // 10. 注册监听器
        finishBeanFactoryInitialization(beanFactory); // 11. 实例化单例Bean
        finishRefresh();                     // 12. 完成刷新
    }
}
```

其他Spring模板方法应用：`JdbcTemplate`、`RestTemplate`、`JmsTemplate`。

### 1.5 优缺点

| 优点 | 缺点 |
|------|------|
| 流程标准化，确保统一执行顺序 | 子类数量可能过多 |
| 代码复用性高 | 流程灵活性受限 |
| 扩展性好（新增子类即可） | 抽象类与子类耦合较高 |
| 解耦流程与实现 | 不适用于流程差异大的场景 |

## 2. 策略模式

### 2.1 核心定义

**定义一系列算法，将每个算法封装起来，并使它们可以互相替换，让算法的变化独立于使用算法的客户端。**

策略模式的核心是"封装变化"——将同类业务的不同实现方案抽象为统一策略接口，让客户端根据需求选择不同策略。

### 2.2 四大角色

| 角色 | 说明 |
|------|------|
| **抽象策略（Strategy）** | 定义所有算法的统一接口 |
| **具体策略（Concrete Strategy）** | 封装具体的算法逻辑 |
| **上下文（Context）** | 持有策略引用，负责策略的调用 |
| **客户端（Client）** | 选择具体策略，注入上下文 |

### 2.3 代码实现（订单优惠计算）

```java
// 抽象策略：优惠策略接口
public interface DiscountStrategy {
    BigDecimal calculate(BigDecimal originalAmount);
    String getStrategyName();
}

// 具体策略：普通用户无优惠
public class NormalDiscount implements DiscountStrategy {
    @Override
    public BigDecimal calculate(BigDecimal amount) {
        return amount; // 无优惠
    }
    @Override
    public String getStrategyName() {
        return "普通用户无优惠";
    }
}

// 具体策略：VIP用户9折
public class VipDiscount implements DiscountStrategy {
    @Override
    public BigDecimal calculate(BigDecimal amount) {
        return amount.multiply(new BigDecimal("0.9")).setScale(2, RoundingMode.HALF_UP);
    }
    @Override
    public String getStrategyName() {
        return "VIP用户9折";
    }
}

// 具体策略：至尊用户8折+满100减20
public class SupremeDiscount implements DiscountStrategy {
    @Override
    public BigDecimal calculate(BigDecimal amount) {
        BigDecimal after = amount.multiply(new BigDecimal("0.8"));
        if (after.compareTo(new BigDecimal("100")) >= 0) {
            after = after.subtract(new BigDecimal("20"));
        }
        return after;
    }
    @Override
    public String getStrategyName() {
        return "至尊用户8折+满减";
    }
}

// 上下文
public class DiscountContext {
    private DiscountStrategy strategy;

    public DiscountContext(DiscountStrategy strategy) {
        this.strategy = strategy;
    }

    // 运行时切换策略
    public void setStrategy(DiscountStrategy strategy) {
        this.strategy = strategy;
    }

    public BigDecimal calculate(BigDecimal amount) {
        return strategy.calculate(amount);
    }
}

// 客户端
DiscountContext context = new DiscountContext(new NormalDiscount());
context.calculate(new BigDecimal("80"));       // 普通用户

context.setStrategy(new VipDiscount());
context.calculate(new BigDecimal("120"));       // VIP用户
```

### 2.6 策略 vs 状态

| 对比 | 策略模式 | 状态模式 |
|------|---------|---------|
| 切换触发者 | 客户端主动选择 | 对象内部状态被动切换 |
| 目的 | 选择不同算法 | 根据状态改变行为 |
| 策略/状态间关系 | 彼此独立，可互换 | 有关联，自动流转 |

## 3. 观察者模式

### 3.1 核心定义

**定义对象间的一对多依赖关系，当一个对象（主题）的状态发生变化时，所有依赖它的对象（观察者）都会收到通知并自动更新。**

又称"发布-订阅模式"，核心是分离"状态发布者"与"状态订阅者"。

### 3.2 四大角色

| 角色 | 说明 |
|------|------|
| **抽象主题（Subject）** | 维护观察者列表，提供注册/注销方法 |
| **具体主题（Concrete Subject）** | 状态发布者，状态变化时通知所有观察者 |
| **抽象观察者（Observer）** | 定义统一的更新接口 |
| **具体观察者（Concrete Observer）** | 实现更新方法，接收通知后执行业务 |

### 3.3 代码实现（订单状态通知）

```java
// 抽象观察者
public interface Observer {
    void update(String orderNo, String orderStatus);
}

// 抽象主题
public abstract class Subject {
    protected List<Observer> observerList = new ArrayList<>();

    public void registerObserver(Observer observer) {
        observerList.add(observer);
    }

    public void removeObserver(Observer observer) {
        observerList.remove(observer);
    }

    public abstract void notifyObservers(String orderNo, String orderStatus);
}

// 具体主题：订单
public class OrderSubject extends Subject {
    private String orderNo;
    private String orderStatus;

    public void updateOrderStatus(String orderStatus) {
        this.orderStatus = orderStatus;
        notifyObservers(this.orderNo, this.orderStatus);
    }

    @Override
    public void notifyObservers(String orderNo, String orderStatus) {
        for (Observer observer : observerList) {
            observer.update(orderNo, orderStatus);
        }
    }

    public void setOrderNo(String orderNo) { this.orderNo = orderNo; }
}

// 具体观察者
public class StockObserver implements Observer {
    @Override
    public void update(String orderNo, String orderStatus) {
        if ("已支付".equals(orderStatus)) {
            System.out.println("库存模块：扣减库存");
        } else if ("已取消".equals(orderStatus)) {
            System.out.println("库存模块：回补库存");
        }
    }
}

public class LogObserver implements Observer {
    @Override
    public void update(String orderNo, String orderStatus) {
        System.out.println("日志模块：记录订单" + orderNo + "状态变更为" + orderStatus);
    }
}

// 客户端
OrderSubject order = new OrderSubject();
order.setOrderNo("ORDER_001");
order.registerObserver(new StockObserver());
order.registerObserver(new LogObserver());

order.updateOrderStatus("已支付");
// 输出：
// 库存模块：扣减库存
// 日志模块：记录订单ORDER_001状态变更为已支付
```

### 3.5 优缺点

| 优点 | 缺点 |
|------|------|
| 解耦主题与观察者 | 观察者过多时通知效率下降 |

| 符合开闭原则 | 无法控制通知顺序 |

## 4. 迭代器模式

### 4.1 核心定义

**提供一种统一的方式遍历集合/容器对象中的各个元素，同时不暴露集合内部的底层存储结构。**

迭代器模式分离"集合本身"和"元素遍历"两大职责，是Java集合框架的底层核心设计。

### 4.2 四大角色

| 角色 | Java对应 |
|------|----------|
| **抽象迭代器** | `java.util.Iterator`（hasNext/next/remove） |
| **具体迭代器** | ArrayList内部的`Itr`类 |
| **抽象聚合** | `java.lang.Iterable`（iterator方法） |
| **具体聚合** | ArrayList、LinkedList、HashSet |

### 4.3 Java源码中的迭代器

```java
// 抽象迭代器：java.util.Iterator
public interface Iterator<E> {
    boolean hasNext();
    E next();
    default void remove() { throw new UnsupportedOperationException(); }
}

// 抽象聚合：java.lang.Iterable
public interface Iterable<T> {
    Iterator<T> iterator();
}

// 日常使用的foreach底层就是迭代器
List<String> list = Arrays.asList("Java", "Python", "Go");
for (String s : list) { // 编译后转换为迭代器
    System.out.println(s);
}
```

### 4.4 自定义集合和迭代器

```java
// 抽象迭代器
public interface MyIterator<E> {
    boolean hasNext();
    E next();
}

// 抽象聚合
public interface MyCollection<E> {
    MyIterator<E> iterator();
    void add(E element);
    int size();
}

// 具体聚合：自定义数组集合
public class MyArrayList<E> implements MyCollection<E> {
    private Object[] elementData = new Object[10];
    private int size;

    @Override
    public void add(E element) { elementData[size++] = element; }

    @Override
    public MyIterator<E> iterator() {
        return new ArrayListIterator();
    }

    @Override
    public int size() { return size; }

    // 具体迭代器：私有内部类
    private class ArrayListIterator implements MyIterator<E> {
        private int cursor;

        @Override
        public boolean hasNext() { return cursor < size; }

        @Override
        @SuppressWarnings("unchecked")
        public E next() { return (E) elementData[cursor++]; }
    }
}

// 客户端：统一遍历，无感底层结构
MyCollection<String> collection = new MyArrayList<>();
collection.add("Java");
collection.add("Python");

MyIterator<String> it = collection.iterator();
while (it.hasNext()) {
    System.out.println(it.next());
}
```

### 4.5 注意事项

| 坑点 | 正确做法 |
|------|----------|
| 遍历过程中直接修改集合 | 使用迭代器的remove()方法 |
| 多个线程共用一个迭代器 | 每个线程单独获取迭代器 |
| 迭代器复用 | 遍历完成后重新调用iterator() |

### 4.6 适用场景

- Java集合框架遍历（ArrayList、HashSet、HashMap等）
- 自定义容器元素遍历
- 数据流逐行读取（IO流、ResultSet）
- 分页迭代加载（大数据量懒加载）
