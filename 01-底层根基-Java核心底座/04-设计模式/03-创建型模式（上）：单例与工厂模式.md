# 创建型模式（上）：单例与工厂模式

> 创建型模式的核心思想是"将创建与使用分离"。单例模式保证全局唯一实例，工厂模式体系（简单工厂、工厂方法、抽象工厂）将对象创建逻辑从业务代码中解耦出来。

## 1. 单例模式

### 1.1 核心定义

**确保一个类在整个JVM进程中，有且仅有一个实例对象，且提供一个全局唯一的访问入口。**

### 核心特征

- **构造器私有**：禁止外部通过new创建实例
- **自身持有唯一实例**：静态私有成员变量存储唯一实例
- **全局访问入口**：公共静态方法作为获取唯一实例的唯一通道
- **线程安全**：多线程并发下必须保证实例唯一性

### 1.2 8种实现方式

#### 1. 饿汉式（静态常量）

```java
public class Singleton {
    private static final Singleton INSTANCE = new Singleton();
    private Singleton() {}
    public static Singleton getInstance() {
        return INSTANCE;
    }
}
```

**优点**：实现简单、线程安全、无同步开销
**缺点**：类加载即创建，可能造成资源浪费

#### 2. 饿汉式（静态代码块）

```java
public class Singleton {
    private static Singleton INSTANCE;
    private Singleton() {}
    static {
        // 可添加复杂初始化逻辑
        INSTANCE = new Singleton();
    }
    public static Singleton getInstance() {
        return INSTANCE;
    }
}
```

#### 3. 懒汉式（线程不安全）—— 绝对禁止

```java
public class Singleton {
    private static Singleton instance;
    private Singleton() {}
    public static Singleton getInstance() {
        if (instance == null) {
            instance = new Singleton(); // 线程不安全！
        }
        return instance;
    }
}
```

> 多线程并发下会创建多个实例，后端生产环境绝对禁止使用。

#### 4. 懒汉式（方法加锁）—— 不推荐

```java
public class Singleton {
    private static Singleton instance;
    private Singleton() {}
    public static synchronized Singleton getInstance() {
        if (instance == null) {
            instance = new Singleton();
        }
        return instance;
    }
}
```

**缺点**：每次获取实例都加锁，性能极差。

#### 5. 双重检查锁（DCL）—— 高并发首选

```java
public class Singleton {
    // volatile禁止指令重排，保证多线程下实例可见性
    private static volatile Singleton instance;

    private Singleton() {}

    public static Singleton getInstance() {
        // 第一次检查：避免每次都加锁
        if (instance == null) {
            synchronized (Singleton.class) {
                // 第二次检查：防止多线程等待锁时重复创建
                if (instance == null) {
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
```

**volatile关键字的作用**：
- **禁止指令重排序**：`new Singleton()` 不是原子操作（分配内存→初始化→赋值），volatile防止其他线程拿到半初始化对象
- **保证可见性**：一个线程对instance的修改立即被其他线程看到

#### 6. 静态内部类—— 极简推荐

```java
public class Singleton {
    private Singleton() {}

    // 静态内部类：外部类加载时不会立即加载
    private static class SingletonHolder {
        private static final Singleton INSTANCE = new Singleton();
    }

    public static Singleton getInstance() {
        return SingletonHolder.INSTANCE;
    }
}
```

**原理**：JVM类加载机制保证线程安全，只有调用`getInstance()`时才加载内部类，实现懒加载。

#### 7. 枚举单例—— 终极方案（防反射/反序列化）

```java
public enum Singleton {
    INSTANCE;

    private String config;

    public void doSomething() {
        // 业务方法
    }

    public String getConfig() { return config; }
    public void setConfig(String config) { this.config = config; }
}
```

**为什么枚举能防反射？**
- Java反射无法通过`Constructor.newInstance()`创建枚举实例（JDK源码中对此做了限制）
- 枚举的序列化由JVM保证，反序列化不会创建新实例

```java
// 反射攻击测试会抛出：java.lang.IllegalArgumentException: Cannot reflectively create enum objects
```

#### 8. 容器单例—— 框架级实现

```java
public class SingletonContainer {
    private static Map<String, Object> singletonMap = new HashMap<>();

    public static void registerSingleton(String key, Object instance) {
        if (!singletonMap.containsKey(key)) {
            singletonMap.put(key, instance);
        }
    }

    public static Object getSingleton(String key) {
        return singletonMap.get(key);
    }
}
```

Spring的Bean单例基于此思想实现。

### 1.3 单例的破坏与防护

| 破坏方式 | 说明 | 防护方案 |
|----------|------|----------|
| **反射破坏** | 通过`setAccessible(true)`强行调用私有构造器 | 构造器中添加判空逻辑抛出异常；枚举天生防反射 |
| **反序列化破坏** | 反序列化会创建新实例 | 添加`readResolve()`方法返回已有实例 |
| **克隆破坏** | 调用`clone()`创建新实例 | 不实现Cloneable接口；重写clone()返回单例 |

```java
// 构造器防反射
private Singleton() {
    if (SingletonHolder.INSTANCE != null) {
        throw new RuntimeException("单例对象禁止通过反射创建！");
    }
}

// 防序列化破坏
private Object readResolve() {
    return getInstance();
}
```

### 1.4 实现方式对比

| 实现方式 | 线程安全 | 懒加载 | 性能 | 防反射破坏 | 推荐度 |
|----------|----------|--------|------|-----------|--------|
| 饿汉式（静态常量） | 是 | 否 | 高 | 否 | ⭐⭐⭐ |
| 双重检查锁（DCL） | 是 | 是 | 极高 | 否 | ⭐⭐⭐⭐⭐ |
| 静态内部类 | 是 | 是 | 极高 | 否 | ⭐⭐⭐⭐⭐ |
| 枚举 | 是 | 否 | 高 | 是 | ⭐⭐⭐⭐⭐ |

**最终推荐**：常规业务用静态内部类（极简高效）；高并发核心组件用DCL；需防破坏的全局对象用枚举。

## 2. 简单工厂模式（非GoF）

### 2.1 核心定义

提供一个统一工厂类，对外暴露静态创建方法；外部传入类型标识，工厂内部根据参数动态判断并实例化对应产品。**不属于GoF 23种标准设计模式**，却是工厂方法、抽象工厂模式的底层基础。

### 2.2 三大角色

| 角色 | 说明 |
|------|------|
| **抽象产品** | 定义所有产品统一的业务行为规范 |
| **具体产品** | 实现抽象产品接口，承载专属业务逻辑 |
| **工厂** | 唯一集中创建类，提供静态创建方法 |

### 2.3 代码实现

```java
// 抽象产品
public interface MessageHandler {
    void handleMessage(String message);
}

// 具体产品
public class TextMessageHandler implements MessageHandler {
    @Override
    public void handleMessage(String message) {
        System.out.println("文本消息处理：" + message);
    }
}

public class ImageMessageHandler implements MessageHandler {
    @Override
    public void handleMessage(String message) {
        System.out.println("图片消息处理：" + message);
    }
}

// 统一工厂类
public class MessageHandlerFactory {
    private MessageHandlerFactory() {}

    public static MessageHandler createHandler(String type) {
        if ("text".equals(type)) {
            return new TextMessageHandler();
        } else if ("image".equals(type)) {
            return new ImageMessageHandler();
        } else {
            throw new IllegalArgumentException("不支持的消息类型：" + type);
        }
    }
}

// 客户端
public class Client {
    public static void main(String[] args) {
        MessageHandler handler = MessageHandlerFactory.createHandler("text");
        handler.handleMessage("Hello");
    }
}
```

### 2.4 优缺点

| 优点 | 缺点 |
|------|------|
| 职责分离，基础解耦 | **严重违背开闭原则**——新增产品需修改工厂 |
| 消除重复实例化代码 | 单一工厂职责过载 |
| 实现简单，上手成本低 | 静态方法无法扩展 |

### 2.5 适用场景

- 产品品类少、类型固定，新增修改频次低
- 对象创建逻辑简单，无需分层工厂

> 工程规范：入参使用枚举替代字符串；无状态产品做单例优化。

## 3. 工厂方法模式

### 3.1 核心定义

定义一个创建对象的抽象工厂接口，将各类产品的实例化逻辑下沉到独立具体工厂。**每个具体工厂只负责生产一类产品**，严格遵守开闭原则。

### 3.2 四大角色

| 角色 | 说明 |
|------|------|
| **抽象产品** | 定义所有产品统一的业务行为规范 |
| **具体产品** | 实现抽象产品接口 |
| **抽象工厂** | 声明统一的创建方法，不包含实例化代码 |
| **具体工厂** | 实现抽象工厂，内部只创建对应单一产品 |

### 3.3 代码实现

```java
// 抽象产品
public interface MessageHandler {
    void handleMessage(String content);
}

public class TextMessageHandler implements MessageHandler {
    @Override
    public void handleMessage(String content) {
        System.out.println("文本消息处理：" + content);
    }
}

// 抽象工厂
public interface MessageHandlerFactory {
    MessageHandler createHandler();
}

// 具体工厂：一个工厂只生产一种产品
public class TextMessageHandlerFactory implements MessageHandlerFactory {
    @Override
    public MessageHandler createHandler() {
        return new TextMessageHandler();
    }
}

public class ImageMessageHandlerFactory implements MessageHandlerFactory {
    @Override
    public MessageHandler createHandler() {
        return new ImageMessageHandler();
    }
}

// 客户端
public class Client {
    public static void main(String[] args) {
        MessageHandlerFactory factory = new TextMessageHandlerFactory();
        MessageHandler handler = factory.createHandler();
        handler.handleMessage("工厂方法模式实战");
    }
}
```

### 3.4 与简单工厂对比

| 对比维度 | 简单工厂模式 | 工厂方法模式 |
|----------|-------------|-------------|
| 设计原则 | 违反开闭原则 | 严格遵守开闭、单一职责、依赖倒置 |
| 工厂职责 | 一个工厂创建全部产品 | 一个工厂仅生产一类产品 |
| 扩展方式 | 新增产品必须修改工厂 | 新增产品仅新增类 |
| 适用场景 | 小型项目、产品固定 | 中大型项目、产品持续迭代 |

## 4. 抽象工厂模式

### 4.1 核心定义

提供一个统一接口，用于创建一系列相关或相互依赖的对象（**产品族**），无需指定具体实现类。它是"工厂的工厂"。

### 4.2 产品族 vs 产品等级

- **产品族**：同一品牌/系列、配套使用的一组对象（如MySQL系列的Connection、Statement、DataSource）
- **产品等级**：不同品牌/系列的同类对象（如MySQL Connection、Oracle Connection）

### 4.3 代码实现

```java
// 抽象产品接口
public interface DbConnection { void getConnection(); }
public interface DbStatement { void executeSql(String sql); }

// 具体产品：MySQL系列
public class MysqlConnection implements DbConnection {
    @Override
    public void getConnection() {
        System.out.println("获取MySQL数据库连接");
    }
}
public class MysqlStatement implements DbStatement {
    @Override
    public void executeSql(String sql) {
        System.out.println("MySQL执行SQL：" + sql);
    }
}

// 具体产品：Oracle系列
public class OracleConnection implements DbConnection {
    @Override
    public void getConnection() {
        System.out.println("获取Oracle数据库连接");
    }
}
public class OracleStatement implements DbStatement {
    @Override
    public void executeSql(String sql) {
        System.out.println("Oracle执行SQL：" + sql);
    }
}

// 抽象工厂
public interface DbFactory {
    DbConnection createConnection();
    DbStatement createStatement();
}

// 具体工厂：一个工厂生产一整套产品族
public class MysqlFactory implements DbFactory {
    @Override
    public DbConnection createConnection() { return new MysqlConnection(); }
    @Override
    public DbStatement createStatement() { return new MysqlStatement(); }
}

public class OracleFactory implements DbFactory {
    @Override
    public DbConnection createConnection() { return new OracleConnection(); }
    @Override
    public DbStatement createStatement() { return new OracleStatement(); }
}

// 客户端
public class Client {
    public static void main(String[] args) {
        DbFactory factory = new MysqlFactory();
        // 只需更换工厂实例，业务代码无需改动
        DbConnection conn = factory.createConnection();
        DbStatement stmt = factory.createStatement();
        conn.getConnection();
        stmt.executeSql("select * from user");
    }
}
```

### 4.4 优缺点

| 优点 | 缺点 |
|------|------|
| 保障产品族兼容性 | 扩展产品等级成本极高（需改抽象工厂接口） |
| 符合开闭原则（扩展产品族） | 类数量膨胀 |
| 代码解耦彻底 | 设计复杂度高于工厂方法 |

## 5. 三大工厂模式对比

| 对比维度 | 简单工厂 | 工厂方法 | 抽象工厂 |
|----------|---------|---------|---------|
| 创建对象数量 | 单一产品 | 单一产品 | 一系列相关产品（产品族） |
| 开闭原则 | 违反 | 完全符合 | 扩展产品族符合，扩展产品等级不符合 |
| 工厂职责 | 一个工厂创建全部产品 | 一个工厂只生产一类产品 | 一个工厂生产一整套产品族 |
| 代码结构 | 单层结构 | 双层抽象架构 | 双层+多产品维度 |
| 适用场景 | 小型项目、产品固定 | 中大型项目、产品持续迭代 | 多组件配套、多环境切换 |
| 复杂度 | 低 | 中 | 高 |

> **选型建议**：固定少量产品用简单工厂；单一产品多实现用工厂方法；多系列配套产品用抽象工厂。
