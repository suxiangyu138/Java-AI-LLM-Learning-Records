# 访问者模式核心知识点全解（理论 + 实战）

> **定位**：访问者模式（Visitor Pattern）属于行为型设计模式，核心目标是将**数据结构与数据操作分离**，使操作独立于元素结构变化，支持不修改元素类的前提下新增操作。

## 1. 模式基础理论

### 1.1 三大核心设计思想

| 思想 | 说明 |
|------|------|
| **结构与操作分离** | 数据结构仅维护存储与遍历，访问者封装所有操作 |
| **双分派机制** | 元素选择接受哪种访问者 → 访问者选择操作哪种元素 |
| **开闭兼容** | 新增操作仅需新增访问者类，不修改元素类 |

### 1.2 适用场景

| 场景 | 示例 |
|------|------|
| 数据结构稳定，操作频繁变化 | 对象集合固定，需新增统计/校验/导出 |
| 对复杂结构执行统一多维操作 | 同时统计、打印、过滤所有元素 |
| 不修改元素类新增操作 | 避免修改原有代码风险 |
| Java 后端典型场景 | 订单多维度统计、数据导出、语法树解析、规则校验、报表生成 |

### 1.3 五大核心角色

| 角色 | 职责 | 示例 |
|------|------|------|
| **抽象访问者（Visitor）** | 定义对所有具体元素的访问方法 | `ProductVisitor` 接口 |
| **具体访问者（Concrete Visitor）** | 封装每种元素的具体操作逻辑 | `TotalPriceVisitor`、`PrintDetailVisitor` |
| **抽象元素（Element）** | 定义 `accept(visitor)` 方法 | `ProductElement` 接口 |
| **具体元素（Concrete Element）** | 实现 `accept`，调用 `visitor.visitXxx(this)` | `ElectronicProduct` |
| **对象结构（Object Structure）** | 存储/管理所有元素，提供遍历方法 | `ProductStructure` |

### 1.4 优缺点

| 优势 | 局限 |
|------|------|
| ✅ 结构与操作彻底解耦 | ❌ **元素扩展困难**：新增元素需改所有访问者 |
| ✅ 新增操作仅需新增访问者类 | ❌ 访问者需访问元素内部数据 → 破坏封装 |
| ✅ 同类操作集中管理，便于维护 | ❌ 元素与访问者有一定耦合 |
| ✅ 多访问者同时操作同一结构 | ❌ 元素频繁变化时不适用 |

### 1.5 与其他模式区分

| 对比 | 迭代器模式 | 策略模式 | 访问者模式 |
|------|-----------|----------|-----------|
| 核心功能 | 遍历元素 | 同一操作的不同实现切换 | 对**不同元素**执行**不同操作** |
| 关注点 | 遍历顺序 | 操作方案选择 | 操作与结构分离 |
| 操作对象 | — | 固定 | 多类型元素 |

## 2. 实战实现

> 场景：电商平台商品数据多维度处理。三种商品（电子、服装、食品），两种操作（统计总价、打印详情），后续可新增导出/校验等。

### 2.1 类图概览

```text
ProductElement（抽象元素）
    ├── ElectronicProduct
    ├── ClothingProduct
    └── FoodProduct
            │  accept(visitor)
            ▼
ProductVisitor（抽象访问者）
    ├── TotalPriceVisitor
    ├── PrintDetailVisitor
    └── ComplianceCheckVisitor（新增，无需改元素）
            │
ProductStructure（对象结构）
    └── List<ProductElement> + accept(visitor)
```

### 2.2 步骤 1-2：定义元素

```java
// 抽象元素
public interface ProductElement {
    void accept(ProductVisitor visitor);
}

// 具体元素：电子商品
public class ElectronicProduct implements ProductElement {
    private String name;
    private BigDecimal price;
    private int stock;

    public ElectronicProduct(String name, BigDecimal price, int stock) {
        this.name = name; this.price = price; this.stock = stock;
    }

    @Override
    public void accept(ProductVisitor visitor) {
        visitor.visitElectronic(this);  // 双分派
    }

    public String getName() { return name; }
    public BigDecimal getPrice() { return price; }
    public int getStock() { return stock; }
}

// 具体元素：服装商品
public class ClothingProduct implements ProductElement {
    private String name;
    private BigDecimal price;
    private String size;

    public ClothingProduct(String name, BigDecimal price, String size) {
        this.name = name; this.price = price; this.size = size;
    }

    @Override
    public void accept(ProductVisitor visitor) {
        visitor.visitClothing(this);
    }

    public String getName() { return name; }
    public BigDecimal getPrice() { return price; }
    public String getSize() { return size; }
}

// 具体元素：食品商品
public class FoodProduct implements ProductElement {
    private String name;
    private BigDecimal price;
    private String expirationDate;

    public FoodProduct(String name, BigDecimal price, String expirationDate) {
        this.name = name; this.price = price; this.expirationDate = expirationDate;
    }

    @Override
    public void accept(ProductVisitor visitor) {
        visitor.visitFood(this);
    }

    public String getName() { return name; }
    public BigDecimal getPrice() { return price; }
    public String getExpirationDate() { return expirationDate; }
}
```

### 2.3 步骤 3-4：定义访问者

```java
// 抽象访问者
public interface ProductVisitor {
    void visitElectronic(ElectronicProduct product);
    void visitClothing(ClothingProduct product);
    void visitFood(FoodProduct product);
}

// 具体访问者：统计总价
public class TotalPriceVisitor implements ProductVisitor {
    private BigDecimal totalPrice = BigDecimal.ZERO;

    @Override
    public void visitElectronic(ElectronicProduct p) {
        BigDecimal sub = p.getPrice().multiply(new BigDecimal(p.getStock()));
        totalPrice = totalPrice.add(sub);
        System.out.println("电子商品【" + p.getName() + "】：小计 " + sub);
    }

    @Override
    public void visitClothing(ClothingProduct p) {
        totalPrice = totalPrice.add(p.getPrice());
    }

    @Override
    public void visitFood(FoodProduct p) {
        totalPrice = totalPrice.add(p.getPrice());
    }

    public BigDecimal getTotalPrice() { return totalPrice; }
}

// 具体访问者：打印详情
public class PrintDetailVisitor implements ProductVisitor {
    @Override
    public void visitElectronic(ElectronicProduct p) {
        System.out.println("【电子】" + p.getName() + " 单价" + p.getPrice() + " 库存" + p.getStock());
    }
    @Override
    public void visitClothing(ClothingProduct p) {
        System.out.println("【服装】" + p.getName() + " 单价" + p.getPrice() + " 尺码" + p.getSize());
    }
    @Override
    public void visitFood(FoodProduct p) {
        System.out.println("【食品】" + p.getName() + " 单价" + p.getPrice() + " 保质期" + p.getExpirationDate());
    }
}
```

### 2.4 步骤 5-6：对象结构 + 客户端

```java
// 对象结构
public class ProductStructure {
    private List<ProductElement> productList = new ArrayList<>();

    public void addProduct(ProductElement product) { productList.add(product); }
    public void removeProduct(ProductElement product) { productList.remove(product); }

    public void accept(ProductVisitor visitor) {
        for (ProductElement product : productList) {
            product.accept(visitor);
        }
    }
}

// 客户端
public class VisitorClient {
    public static void main(String[] args) {
        ProductElement phone = new ElectronicProduct("智能手机", new BigDecimal("2999"), 50);
        ProductElement shirt = new ClothingProduct("纯棉衬衫", new BigDecimal("199"), "M");
        ProductElement milk = new FoodProduct("纯牛奶", new BigDecimal("6.9"), "2026-12-31");

        ProductStructure structure = new ProductStructure();
        structure.addProduct(phone);
        structure.addProduct(shirt);
        structure.addProduct(milk);

        // 操作 1：统计总价
        TotalPriceVisitor priceVisitor = new TotalPriceVisitor();
        structure.accept(priceVisitor);
        System.out.println("总价：" + priceVisitor.getTotalPrice());

        // 操作 2：打印详情
        PrintDetailVisitor printVisitor = new PrintDetailVisitor();
        structure.accept(printVisitor);

        // 操作 3：新增合规校验（无需修改任何商品类 ✅）
        ComplianceCheckVisitor checkVisitor = new ComplianceCheckVisitor();
        structure.accept(checkVisitor);
    }
}

// 新增访问者：零侵入
class ComplianceCheckVisitor implements ProductVisitor {
    @Override
    public void visitElectronic(ElectronicProduct p) {
        System.out.println("校验【" + p.getName() + "】：合规");
    }
    @Override
    public void visitClothing(ClothingProduct p) {
        System.out.println("校验【" + p.getName() + "】：合规");
    }
    @Override
    public void visitFood(FoodProduct p) {
        System.out.println("校验【" + p.getName() + "】：合规");
    }
}
```

## 3. Spring 框架落地

```java
// 1. 元素和访问者加 @Component
@Component
public class ElectronicProduct implements ProductElement { ... }

@Component("totalPriceVisitor")
public class TotalPriceVisitor implements ProductVisitor { ... }

// 2. 对象结构交给 Spring 管理
@Service
public class ProductStructureSpring {
    @Autowired
    private Map<String, ProductElement> productMap;  // Spring 自动注入所有 ProductElement Bean

    public void accept(ProductVisitor visitor) {
        productMap.values().forEach(p -> p.accept(visitor));
    }
}

// 3. 访问者工厂
@Service
public class VisitorFactory {
    @Autowired
    private Map<String, ProductVisitor> visitorMap;

    public ProductVisitor getVisitor(String operationType) {
        ProductVisitor visitor = visitorMap.get(operationType);
        if (visitor == null) {
            throw new IllegalArgumentException("不支持的操作类型：" + operationType);
        }
        return visitor;
    }
}

// 4. Controller 调用
@RestController
@RequestMapping("/product")
public class ProductController {
    @Autowired
    private ProductStructureSpring productStructure;
    @Autowired
    private VisitorFactory visitorFactory;

    @PostMapping("/operate")
    public String operate(@RequestParam String operationType) {
        ProductVisitor visitor = visitorFactory.getVisitor(operationType);
        productStructure.accept(visitor);
        return "操作执行成功";
    }
}
```

## 4. 注意事项与落地建议

### 4.1 使用原则

| 原则 | 说明 |
|------|------|
| **明确适用场景** | 仅"结构稳定、操作多变"时使用；元素频繁变化不适用 |
| **保护封装性** | 通过接口/方法封装，避免直接暴露私有属性 |
| **命名规范** | `visitXxx` 对应 `XxxElement`，便于扩展 |
| **控制访问者数量** | 同类操作集中一个访问者，避免数量膨胀 |
| **避免过度设计** | 简单场景（元素少、操作少）直接在元素类中实现 |

### 4.2 落地检查清单

| 检查项 | 要求 |
|--------|------|
| 抽象访问者方法 | 与具体元素类型一一对应 |
| 元素 `accept` 方法 | 正确调用 `visitor.visitXxx(this)` |
| 对象结构遍历 | 确保所有元素（含树形子节点）均被访问 |
| 新增操作 | 仅新增访问者类，不修改元素 |
| Spring 整合 | 元素/访问者 `@Component` + 工厂模式解耦 |

---

> 🎯 **核心总结**：访问者模式 = 分离结构与操作，实现操作灵活扩展。核心优势是操作扩展便捷（新增访问者类即可），核心局限是元素扩展困难（需改所有访问者）。适用于 Java 后端"结构稳定、操作多变"的复杂场景，也是面试高频考点。
