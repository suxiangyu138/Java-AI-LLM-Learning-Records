# 结构型模式（下）：外观-享元-代理

> 外观模式为复杂子系统提供统一入口，享元模式通过共享对象减少内存占用，代理模式为对象提供访问控制与增强。三个模式分别解决"简化调用""共享复用""访问控制"三类结构设计问题。

## 1. 外观模式

### 1.1 核心定义

**为子系统中的一组接口提供一个统一的入口，简化子系统的调用，隐藏子系统的复杂性。**

外观模式相当于给一组复杂、分散的子系统加一层"统一门面"，将复杂调用逻辑、依赖关系、参数传递全部隐藏，客户端只需与外观类交互。

### 1.2 核心角色

| 角色 | 说明 |
|------|------|
| **外观类（Facade）** | 对外提供统一简洁方法，内部持有所有子系统引用 |
| **子系统（SubSystem）** | 底层各个独立的功能模块 |

### 1.3 代码实现（订单创建流程）

```java
// 子系统
public class StockService {
    public boolean checkStock(Long goodsId, Integer num) {
        System.out.println("库存校验：库存充足");
        return true;
    }
}
public class OrderService {
    public Long createOrder(Long userId, Long goodsId, Integer num) {
        Long orderId = System.currentTimeMillis();
        System.out.println("订单创建成功，ID=" + orderId);
        return orderId;
    }
}
public class PayService {
    public boolean payOrder(Long orderId, BigDecimal amount) {
        System.out.println("支付成功");
        return true;
    }
}
public class MessageService {
    public void sendNotify(Long userId, Long orderId) {
        System.out.println("发送订单通知");
    }
}

// 外观类：统一封装
public class OrderFacade {
    private StockService stockService = new StockService();
    private OrderService orderService = new OrderService();
    private PayService payService = new PayService();
    private MessageService messageService = new MessageService();

    /**
     * 对外统一方法：一键创建并支付订单
     */
    public boolean createAndPayOrder(Long userId, Long goodsId, Integer num, BigDecimal amount) {
        boolean stockFlag = stockService.checkStock(goodsId, num);
        if (!stockFlag) return false;

        Long orderId = orderService.createOrder(userId, goodsId, num);
        boolean payFlag = payService.payOrder(orderId, amount);
        if (!payFlag) return false;

        messageService.sendNotify(userId, orderId);
        return true;
    }
}

// 客户端：只依赖外观类
OrderFacade orderFacade = new OrderFacade();
orderFacade.createAndPayOrder(1001L, 2001L, 1, new BigDecimal("199"));
```

### 1.4 优缺点

| 优点 | 缺点 |
|------|------|
| 解耦客户端与子系统 | 外观类可能变得臃肿 |
| 简化调用口径，减少冗余代码 | 不符合开闭原则极致要求 |
| 统一流程管控，便于维护 | 子系统独立访问受限 |

### 1.5 适用场景

- 复杂业务流程封装（订单创建、支付退款）
- 第三方接口统一对接（多个支付/短信接口）
- 框架：Spring的JdbcTemplate、RedisTemplate

## 2. 享元模式

### 2.1 核心定义

**运用共享技术，减少创建大量相似对象的开销，复用已存在的对象，提高系统性能。**

享元模式将对象属性分为**内部状态**（可共享、不变）和**外部状态**（不可共享、可变），共享内部状态不变的对象，外部状态通过调用时传入。

### 2.2 内部状态 vs 外部状态

| 对比 | 内部状态 | 外部状态 |
|------|---------|---------|
| 定义 | 可共享的、不变的属性 | 随场景变化的属性 |
| 存储位置 | 享元对象内部 | 客户端传入方法参数 |
| 示例 | 角色名、权限列表 | 当前用户ID、登录IP |
| 线程安全 | 必须不可变 | 互不干扰 |

### 2.3 代码实现（角色权限共享）

```java
// 抽象享元
public interface RoleFlyweight {
    void operation(String userId); // userId为外部状态
}

// 具体享元：包含不可变的内部状态
public class ConcreteRole implements RoleFlyweight {
    private final String roleName;          // 内部状态：不可变
    private final List<String> permissionList; // 内部状态：不可变

    public ConcreteRole(String roleName, List<String> permissionList) {
        this.roleName = roleName;
        this.permissionList = permissionList;
    }

    @Override
    public void operation(String userId) {
        System.out.println("用户" + userId + "，角色：" + roleName + "，对象哈希：" + this.hashCode());
    }
}

// 享元工厂：管理享元池
public class RoleFlyweightFactory {
    private static final Map<String, RoleFlyweight> POOL = new HashMap<>();

    static {
        POOL.put("ADMIN", new ConcreteRole("管理员", Arrays.asList("新增", "删除", "修改", "查询")));
        POOL.put("USER", new ConcreteRole("普通用户", Arrays.asList("查询", "修改")));
        POOL.put("GUEST", new ConcreteRole("访客", Arrays.asList("查询")));
    }

    public static RoleFlyweight getRole(String roleKey) {
        return POOL.get(roleKey); // 池中复用，不新建
    }
}

// 客户端：不同用户复用同一角色对象
RoleFlyweight admin1 = RoleFlyweightFactory.getRole("ADMIN");
admin1.operation("user001");
RoleFlyweight admin2 = RoleFlyweightFactory.getRole("ADMIN");
admin2.operation("user002");
// admin1和admin2是同一个对象（哈希值相同）
System.out.println("池中对象总数：" + RoleFlyweightFactory.getPoolSize()); // 3
```

### 2.4 Java中的享元应用

```java
// Integer.valueOf() 缓存 -128~127
Integer a = Integer.valueOf(100);
Integer b = Integer.valueOf(100);
System.out.println(a == b); // true —— 享元

Integer c = Integer.valueOf(200);
Integer d = Integer.valueOf(200);
System.out.println(c == d); // false —— 超出缓存范围

// 字符串常量池
String s1 = "hello";
String s2 = "hello";
System.out.println(s1 == s2); // true —— 享元
```

### 2.5 优缺点

| 优点 | 缺点 |
|------|------|
| 大幅减少内存占用 | 增加设计复杂度 |
| 降低对象创建损耗 | 线程安全风险 |
| 贴合后端池化思想 | 外部状态维护成本 |

### 2.6 享元 vs 单例

| 对比 | 享元模式 | 单例模式 |
|------|---------|---------|
| 对象数量 | 多个共享实例（按内部状态区分） | 一个类只有一个实例 |
| 核心目的 | 共享大量相似对象 | 全局唯一 |
| 示例 | 不同角色的权限对象 | 配置管理器 |

### 2.7 适用场景

- String字符串常量池
- 线程池、数据库连接池
- 系统固定角色、全局配置项、字典项

## 3. 代理模式

### 3.1 核心定义

**为其他对象提供一个代理，以控制对这个对象的访问。代理对象在客户端和目标对象之间起到中介作用。**

代理模式可以在不修改目标对象的前提下，在方法执行前后添加额外逻辑（权限、日志、缓存等），是Spring AOP的底层核心原理。

### 3.2 三种代理实现

#### 1. 静态代理

```java
// 目标接口
public interface UserService {
    void saveUser(String username);
}

// 目标类
public class UserServiceImpl implements UserService {
    @Override
    public void saveUser(String username) {
        System.out.println("保存用户：" + username);
    }
}

// 代理类（编译期手动编写）
public class UserServiceProxy implements UserService {
    private UserService target;

    public UserServiceProxy(UserService target) {
        this.target = target;
    }

    @Override
    public void saveUser(String username) {
        System.out.println("[代理] 前置：权限校验");
        target.saveUser(username);
        System.out.println("[代理] 后置：日志记录");
    }
}

// 使用
UserService target = new UserServiceImpl();
UserService proxy = new UserServiceProxy(target);
proxy.saveUser("张三");
```

**缺点**：每个目标类需要手动编写代理类，类爆炸。

#### 2. JDK动态代理（基于接口）

```java
import java.lang.reflect.InvocationHandler;
import java.lang.reflect.Method;
import java.lang.reflect.Proxy;

public class LogHandler implements InvocationHandler {
    private Object target;

    public LogHandler(Object target) {
        this.target = target;
    }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        System.out.println("[JDK代理] 方法执行前：" + method.getName());
        Object result = method.invoke(target, args);
        System.out.println("[JDK代理] 方法执行后");
        return result;
    }
}

// 创建代理
UserService target = new UserServiceImpl();
UserService proxy = (UserService) Proxy.newProxyInstance(
        target.getClass().getClassLoader(),
        target.getClass().getInterfaces(),
        new LogHandler(target)
);
proxy.saveUser("李四");
```

**原理**：运行时生成`$Proxy0`类，实现目标接口并继承`Proxy`。

**限制**：必须基于接口，不能代理没有实现接口的类。

#### 3. CGLIB动态代理（基于子类）

```java
import org.springframework.cglib.proxy.Enhancer;
import org.springframework.cglib.proxy.MethodInterceptor;
import org.springframework.cglib.proxy.MethodProxy;

// 目标类无需实现接口
public class UserDao {
    public void save(String name) {
        System.out.println("保存用户：" + name);
    }
}

public class LogInterceptor implements MethodInterceptor {
    private Object target;

    public LogInterceptor(Object target) {
        this.target = target;
    }

    @Override
    public Object intercept(Object obj, Method method, Object[] args, MethodProxy proxy) throws Throwable {
        System.out.println("[CGLIB] 方法执行前");
        Object result = proxy.invokeSuper(obj, args); // 注意是invokeSuper
        System.out.println("[CGLIB] 方法执行后");
        return result;
    }
}

// 创建代理
Enhancer enhancer = new Enhancer();
enhancer.setSuperclass(UserDao.class);
enhancer.setCallback(new LogInterceptor());
UserDao proxy = (UserDao) enhancer.create();
proxy.save("王五");
```

### 3.3 三种代理对比

| 特性 | 静态代理 | JDK动态代理 | CGLIB代理 |
|------|---------|------------|-----------|
| 实现方式 | 手动编写代理类 | 运行时生成接口实现类 | 运行时生成子类 |
| 是否需要接口 | 需要 | 需要 | 不需要 |
| 性能（调用） | 直接调用，最快 | 反射调用，较慢 | 方法调用，较快 |
| 灵活性 | 低 | 高 | 高 |
| 限制 | 类爆炸 | 必须基于接口 | 不能代理final类/方法 |

### 3.4 Spring AOP中的应用

```java
// Spring AOP是代理模式的集大成者
@Service
public class OrderService {
    @Transactional // 事务——通过代理实现
    public void createOrder(Order order) {
        orderDao.insert(order);
        inventoryService.deduct(order.getProductId(), order.getQuantity());
    }
}

@Cacheable(value = "users", key = "#id") // 缓存——通过代理实现
public User getUser(Long id) {
    return userDao.findById(id);
}

@PreAuthorize("hasRole('ADMIN')") // 权限——通过代理实现
public void deleteUser(Long id) {
    userDao.deleteById(id);
}
```

> Spring AOP：当Bean有接口时默认使用JDK动态代理，否则使用CGLIB。可通过`@EnableAspectJAutoProxy(proxyTargetClass = true)`强制使用CGLIB。

### 3.5 代理 vs 装饰器

| 对比维度 | 代理模式 | 装饰器模式 |
|----------|---------|-----------|
| 核心目的 | 控制对象访问，间接调用 | 动态增强对象功能 |
| 目标对象创建 | 代理内部创建/注入，客户端无感 | 客户端手动创建，传入装饰器 |
| 关系性质 | 一对一 | 可嵌套多对一 |
| 典型场景 | AOP、权限拦截、远程调用 | 日志、缓存、IO流增强 |

## 4. 结构型模式全对比

| 模式 | 核心一句话 | 适用阶段 | 关注点 |
|------|-----------|---------|--------|
| **适配器** | 让不兼容的接口一起工作 | 项目后期 | 接口转换 |
| **桥接** | 抽象和实现独立变化 | 设计初期 | 维度分离 |
| **组合** | 部分-整体统一对待 | 树形场景 | 层级结构 |
| **装饰器** | 给对象动态叠加功能 | 功能增强 | 能力叠加 |
| **外观** | 封装多子系统，简化调用 | 复杂流程 | 统一入口 |
| **享元** | 共享对象，减少内存 | 大量重复对象 | 对象复用 |
| **代理** | 控制对象访问，间接调用 | 访问控制 | 间接访问 |
