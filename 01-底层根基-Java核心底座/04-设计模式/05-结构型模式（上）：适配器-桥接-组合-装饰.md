# 结构型模式（上）：适配器-桥接-组合-装饰

> 结构型模式关注类与对象的组合方式。适配器解决接口不兼容，桥接分离抽象与实现，组合统一处理部分-整体层次，装饰器动态增强对象功能。

## 1. 适配器模式

### 1.1 核心定义

**将一个类的接口转换成客户端期望的另一个接口，让原本接口不兼容的类可以一起工作。**

相当于生活中的"电源适配器"或"转接头"，不修改原有核心业务代码，只通过新增适配层解决接口不匹配问题。

### 1.2 核心术语

| 角色 | 说明 |
|------|------|
| **目标接口（Target）** | 客户端期望使用的标准接口 |
| **适配者（Adaptee）** | 已有功能正常但接口不兼容的类 |
| **适配器（Adapter）** | 核心角色，实现目标接口，持有适配者对象 |
| **客户端（Client）** | 只依赖目标接口，无感知适配过程 |

### 1.3 两种实现方式

#### 对象适配器（组合实现——首选）

```java
// 目标接口：客户端期望的USB接口
public interface Usb {
    void transferData();
}

// 适配者：老系统的PS2接口
public class Ps2Keyboard {
    public void typeWithPs2() {
        System.out.println("通过PS2接口输入");
    }
}

// 对象适配器：持有适配者实例（组合）
public class Ps2ToUsbAdapter implements Usb {
    private Ps2Keyboard ps2Keyboard;

    public Ps2ToUsbAdapter(Ps2Keyboard ps2Keyboard) {
        this.ps2Keyboard = ps2Keyboard;
    }

    @Override
    public void transferData() {
        ps2Keyboard.typeWithPs2(); // 内部转换为PS2操作
    }
}

// 客户端
Usb adapter = new Ps2ToUsbAdapter(new Ps2Keyboard());
adapter.transferData();
```

#### 类适配器（继承实现——少用）

```java
// 类适配器：继承适配者 + 实现目标接口
public class ClassAdapter extends Ps2Keyboard implements Usb {
    @Override
    public void transferData() {
        super.typeWithPs2();
    }
}
```

#### 对比

| 对比维度 | 对象适配器（组合） | 类适配器（继承） |
|----------|-------------------|-----------------|
| 实现方式 | 持有适配者实例 | 继承适配者类 |
| 耦合度 | 低 | 高 |
| 多适配支持 | 支持适配多个适配者 | 不支持（单继承） |
| 灵活性 | 高 | 低 |
| **后端推荐度** | **首选** | 仅临时简单场景 |

### 1.4 Spring MVC中的适配器

```java
// Spring源码：HandlerAdapter接口
public interface HandlerAdapter {
    boolean supports(Object handler);
    ModelAndView handle(HttpServletRequest request, HttpServletResponse response, Object handler);
}

// 适配不同类型的Controller
public class SimpleControllerHandlerAdapter implements HandlerAdapter {
    @Override
    public boolean supports(Object handler) {
        return (handler instanceof Controller);
    }
    @Override
    public ModelAndView handle(HttpServletRequest request, HttpServletResponse response, Object handler) {
        return ((Controller) handler).handleRequest(request, response);
    }
}

public class RequestMappingHandlerAdapter implements HandlerAdapter {
    @Override
    public boolean supports(Object handler) {
        return (handler instanceof HandlerMethod);
    }
    // 通过反射调用@Controller中的@RequestMapping方法
}
```

### 1.5 适用场景

- 第三方接口/SDK适配（支付、短信、日志）
- 老系统功能兼容，不修改老代码实现平滑过渡
- 多数据源/中间件适配，统一上层调用接口
- 旧接口升级时兼容旧调用方

## 2. 桥接模式

### 2.1 核心定义

**将抽象部分与实现部分分离，使二者可以独立变化，通过组合关系搭建"桥梁"进行协作。**

桥接模式专门解决多维度独立变化的场景，把复杂的继承关系拆解为两个或多个独立维度，依靠组合替代多层继承，避免"类爆炸"。

### 2.2 核心结构

```
         ┌──────────────┐
         │  Abstraction │───────▶│ Implementor │
         └──────┬───────┘ 桥接    └──────────────┘
                ▲                         ▲
         ┌──────┴──────┐          ┌──────┴──────┐
         │ Refined     │          │ Concrete    │
         │ Abstraction │          │ Implementor │
         └─────────────┘          └─────────────┘
```

### 2.3 四种角色

| 角色 | 说明 |
|------|------|
| **抽象（Abstraction）** | 顶层抽象类，持有实现层接口引用 |
| **修正抽象（Refined Abstraction）** | 抽象类的具体子类，扩展抽象层功能 |
| **实现（Implementor）** | 实现层的顶层接口 |
| **具体实现（Concrete Implementor）** | 完成具体的业务逻辑 |

### 2.4 代码实现（消息通知场景）

```java
// 实现层接口：消息发送渠道
public interface MessageSender {
    void send(String content);
}

// 具体实现：短信、邮件、APP推送
public class SmsSender implements MessageSender {
    @Override
    public void send(String content) {
        System.out.println("【短信】" + content);
    }
}
public class EmailSender implements MessageSender {
    @Override
    public void send(String content) {
        System.out.println("【邮件】" + content);
    }
}

// 抽象层：消息抽象类，持有MessageSender引用（核心桥梁）
public abstract class AbstractMessage {
    protected MessageSender messageSender; // 桥接关系

    public AbstractMessage(MessageSender messageSender) {
        this.messageSender = messageSender;
    }

    public abstract void sendMessage(String content);
}

// 修正抽象：普通消息、紧急消息
public class NormalMessage extends AbstractMessage {
    public NormalMessage(MessageSender messageSender) {
        super(messageSender);
    }
    @Override
    public void sendMessage(String content) {
        messageSender.send("[普通]" + content);
    }
}

public class UrgentMessage extends AbstractMessage {
    public UrgentMessage(MessageSender messageSender) {
        super(messageSender);
    }
    @Override
    public void sendMessage(String content) {
        messageSender.send("【紧急】" + content);
    }
}

// 客户端：自由组合
MessageSender sms = new SmsSender();
AbstractMessage normalMsg = new NormalMessage(sms);
normalMsg.sendMessage("您的订单已发货");

AbstractMessage urgentMsg = new UrgentMessage(new EmailSender());
urgentMsg.sendMessage("服务器CPU过高");
```

**继承方案需 2×3=6个类，桥接仅需 2+3=5个类；新增维度只需新增类，无需修改现有代码。**

### 2.5 适用场景

- 消息通知体系（消息类型×发送渠道）
- 支付业务（支付方式×支付渠道）
- 数据库操作（数据库类型×操作方式）
- 文件上传（文件类型×存储渠道）
- **JDBC底层设计**：JDBC API是典型的桥接模式

### 2.6 桥接 vs 适配器

| 对比维度 | 桥接模式 | 适配器模式 |
|----------|---------|-----------|
| 核心目的 | 分离抽象与实现，多维度独立扩展 | 解决接口不兼容 |
| 使用阶段 | 项目设计初期 | 项目后期兼容已有代码 |
| 核心关系 | 组合关系，搭建桥梁 | 转换关系，接口适配 |

## 3. 组合模式

### 3.1 核心定义

**将对象组合成树形结构以表示"部分-整体"的层次关系，使得客户端对单个对象和组合对象的使用具有一致性。**

### 3.2 三种角色

```
           ┌──────────────┐
           │  Component   │  (抽象组件)
           └──────┬───────┘
              ▲           ▲
      ┌───────┴───┐  ┌───┴────────┐
      │   Leaf    │  │  Composite  │  (容器节点)
      └───────────┘  │  -children  │
                      └────────────┘
```

| 角色 | 说明 |
|------|------|
| **抽象组件（Component）** | 定义叶子节点和容器节点的统一公共方法 |
| **叶子节点（Leaf）** | 最底层对象，无子节点 |
| **容器节点（Composite）** | 包含子节点（叶子或其他容器） |

### 3.3 代码实现（文件系统）

```java
// 抽象组件
public interface FileSystemNode {
    String getName();
    long getSize();
    void display(String indent);
}

// 叶子节点：文件
public class FileLeaf implements FileSystemNode {
    private String name;
    private long size;

    public FileLeaf(String name, long size) {
        this.name = name;
        this.size = size;
    }

    @Override
    public long getSize() { return size; }

    @Override
    public void display(String indent) {
        System.out.println(indent + "📄 " + name + " (" + size + " bytes)");
    }
}

// 容器节点：文件夹
public class FolderComposite implements FileSystemNode {
    private String name;
    private List<FileSystemNode> children = new ArrayList<>();

    public FolderComposite(String name) { this.name = name; }

    public void add(FileSystemNode node) { children.add(node); }
    public void remove(FileSystemNode node) { children.remove(node); }

    @Override
    public long getSize() {
        return children.stream().mapToLong(FileSystemNode::getSize).sum();
    }

    @Override
    public void display(String indent) {
        System.out.println(indent + "📁 " + name + "/");
        for (FileSystemNode child : children) {
            child.display(indent + "  ");
        }
    }
}

// 客户端：统一对待文件和文件夹
FolderComposite root = new FolderComposite("项目");
root.add(new FileLeaf("README.md", 500));
FolderComposite src = new FolderComposite("src");
src.add(new FileLeaf("Main.java", 1024));
root.add(src);

root.display(""); // 统一调用，无需区分文件和文件夹
System.out.println("总大小: " + root.getSize() + " bytes");
```

### 3.4 透明模式 vs 安全模式

| 对比 | 透明模式 | 安全模式 |
|------|---------|---------|
| 方法定义 | 所有方法定义在Component中 | 只有通用方法在Component中 |
| 叶子节点 | 有冗余方法（抛异常） | 无冗余方法 |
| 客户端 | 无需区分节点类型 | 需要区分节点类型 |
| 推荐度 | 常用 | 较少用 |

### 3.5 适用场景

- 系统菜单管理、组织部门架构、文件目录结构
- 商品分类体系、权限组管理
- 树形数据展示、流程审批节点

## 4. 装饰器模式

### 4.1 核心定义

**动态地给一个对象添加额外的职责，不改变原对象的结构，同时不影响其他对象。**

装饰器模式是"继承的优雅替代方案"，通过嵌套组合实现功能的层层叠加，是Java IO包的底层设计思想。

### 4.2 四种角色

| 角色 | 说明 |
|------|------|
| **抽象组件（Component）** | 核心业务接口，装饰前后接口统一 |
| **具体组件（Concrete Component）** | 核心业务逻辑实现类 |
| **抽象装饰器（Decorator）** | 持有抽象组件引用，定义包装基础 |
| **具体装饰器（Concrete Decorator）** | 实现具体的功能增强 |

### 4.3 代码实现

```java
// 抽象组件
public interface Coffee {
    double cost();
    String description();
}

// 具体组件
public class PlainCoffee implements Coffee {
    @Override
    public double cost() { return 5.0; }
    @Override
    public String description() { return "原味咖啡"; }
}

// 抽象装饰器
public abstract class CoffeeDecorator implements Coffee {
    protected Coffee coffee; // 持有被装饰者

    public CoffeeDecorator(Coffee coffee) {
        this.coffee = coffee;
    }

    @Override
    public double cost() { return coffee.cost(); }
    @Override
    public String description() { return coffee.description(); }
}

// 具体装饰器
public class MilkDecorator extends CoffeeDecorator {
    public MilkDecorator(Coffee coffee) { super(coffee); }
    @Override
    public double cost() { return super.cost() + 2.0; }
    @Override
    public String description() { return super.description() + " + 牛奶"; }
}

public class SugarDecorator extends CoffeeDecorator {
    public SugarDecorator(Coffee coffee) { super(coffee); }
    @Override
    public double cost() { return super.cost() + 1.0; }
    @Override
    public String description() { return super.description() + " + 糖"; }
}

// 自由组合——"套娃"
Coffee coffee = new PlainCoffee();
coffee = new MilkDecorator(coffee);
coffee = new SugarDecorator(coffee);
System.out.println(coffee.description() + " = " + coffee.cost() + "元");
// 输出：原味咖啡 + 牛奶 + 糖 = 8.0元
```

### 4.4 Java I/O流——最经典的装饰器

```java
// FileInputStream是具体组件，BufferedInputStream/DataInputStream是具体装饰器
InputStream in = new DataInputStream(
        new BufferedInputStream(
                new FileInputStream("test.txt")));
// DataInputStream 装饰 BufferedInputStream 装饰 FileInputStream
```

### 4.5 装饰器 vs 代理

| 对比维度 | 装饰器模式 | 代理模式 |
|----------|-----------|---------|
| 核心目的 | 动态增强对象功能 | 控制对象访问 |
| 对象关系 | 层层嵌套，多对一 | 一对一 |
| 使用方式 | 客户端手动嵌套 | 客户端无感代理对象 |
| 侧重点 | 功能扩展、能力叠加 | 访问控制、远程调用 |

### 4.6 适用场景

- 通用功能增强：日志、缓存、参数校验、权限校验
- IO流增强：BufferedReader、BufferedInputStream
- 框架扩展：Spring MVC的HttpServletRequest装饰

## 5. 易混对比总结

| 模式 | 核心一句话 | 关注点 |
|------|-----------|--------|
| **适配器** | 让不兼容的接口一起工作 | 接口转换 |
| **桥接** | 抽象和实现独立变化 | 维度分离 |
| **组合** | 部分-整体统一对待 | 树形结构 |
| **装饰器** | 给对象动态叠加功能 | 功能增强 |

> 装饰器模式 vs 代理模式：装饰器是"增强功能，套娃叠加"；代理是"控制访问，间接调用"。
> 适配器模式 vs 桥接模式：适配器是"事后兼容，解决不匹配"；桥接是"事前设计，分离维度"。
