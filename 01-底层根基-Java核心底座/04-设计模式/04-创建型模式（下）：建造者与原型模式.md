# 创建型模式（下）：建造者与原型模式

> 当对象创建过程复杂时，建造者模式将"分步组装"与"最终表示"分离，原型模式则直接通过"克隆"替代高成本的new初始化。

## 1. 建造者模式

### 1.1 核心定义

**将一个复杂对象的构建过程与它的具体表示分离，使得同样的构建过程可以创建不同的对象表示。**

建造者模式专门解决复杂对象创建的问题，适合属性多、参数组合灵活、存在必选+可选参数的对象，避免构造器重载和set方法导致的代码混乱。

> 与工厂模式的区别：工厂模式关注"生产不同系列产品"，建造者模式关注"一步步组装复杂产品"。

### 1.2 四大核心角色

| 角色 | 说明 |
|------|------|
| **产品类（Product）** | 需要创建的复杂对象，属性设为私有 |
| **抽象建造者（Builder）** | 定义创建产品各个部件的抽象方法 |
| **具体建造者（Concrete Builder）** | 实现抽象建造者，定制组装细节 |
| **指挥者（Director）** | 控制构建流程，隐藏对象创建细节 |

### 1.3 两种实现方式

#### 方式一：标准建造者模式（含指挥者）

```java
// 产品类
public class DbConfig {
    private String url;
    private String username;
    private String password;
    private Integer maxActive;
    private Long timeout;

    private DbConfig() {} // 私有构造器

    // getter only，不提供setter
    public String getUrl() { return url; }
    public Integer getMaxActive() { return maxActive; }
    // setters for Builder...
}

// 抽象建造者
public abstract class DbConfigBuilder {
    protected DbConfig dbConfig = new DbConfig();
    public abstract void buildUrl(String url);
    public abstract void buildUsername(String username);
    public abstract void buildPassword(String password);
    public abstract void buildOptionalConfig();
    public DbConfig getDbConfig() { return dbConfig; }
}

// 具体建造者
public class MysqlDbConfigBuilder extends DbConfigBuilder {
    @Override
    public void buildUrl(String url) { dbConfig.setUrl(url); }
    @Override
    public void buildOptionalConfig() {
        dbConfig.setMaxActive(20);
        dbConfig.setTimeout(3000L);
    }
}

// 指挥者
public class DbConfigDirector {
    private DbConfigBuilder builder;
    public DbConfigDirector(DbConfigBuilder builder) {
        this.builder = builder;
    }
    public DbConfig construct(String url, String username, String password) {
        builder.buildUrl(url);
        builder.buildUsername(username);
        builder.buildPassword(password);
        builder.buildOptionalConfig();
        return builder.getDbConfig();
    }
}

// 客户端
DbConfigBuilder builder = new MysqlDbConfigBuilder();
DbConfigDirector director = new DbConfigDirector(builder);
DbConfig config = director.construct("jdbc:mysql://localhost:3306/test", "root", "123456");
```

#### 方式二：简化链式建造者（日常开发首选）

```java
// 产品类，内部定义静态Builder类
public class User {
    // 必选属性
    private final Long id;
    private final String username;
    // 可选属性
    private String phone;
    private Integer age;
    private String email;

    // 私有构造器，只允许Builder创建
    private User(Builder builder) {
        this.id = builder.id;
        this.username = builder.username;
        this.phone = builder.phone;
        this.age = builder.age;
        this.email = builder.email;
    }

    // 只提供getter，保证对象不可变
    public Long getId() { return id; }
    public String getUsername() { return username; }

    // 静态内部建造者类
    public static class Builder {
        private final Long id;       // 必选参数通过构造器传入
        private final String username;
        private String phone;        // 可选参数默认null
        private Integer age;
        private String email;

        public Builder(Long id, String username) {
            this.id = id;
            this.username = username;
        }

        public Builder phone(String phone) { this.phone = phone; return this; }
        public Builder age(Integer age) { this.age = age; return this; }
        public Builder email(String email) { this.email = email; return this; }

        public User build() {
            // 可在build()中做参数校验
            if (id == null || username == null) {
                throw new IllegalArgumentException("用户ID和用户名不能为空");
            }
            return new User(this);
        }
    }
}

// 客户端——链式调用
User user = new User.Builder(1L, "zhangsan")
        .age(25)
        .phone("13800138000")
        .email("zhangsan@163.com")
        .build();
```

**Lombok版本——一行注解搞定**：

```java
@Data
@Builder
public class Computer {
    private String cpu;
    private String gpu;
    private int ram;
    private int storage;
    private boolean hasBluetooth;
}

// 使用
Computer computer = Computer.builder()
        .cpu("Intel i9")
        .ram(32)
        .storage(1024)
        .build();
```

### 1.4 优缺点

| 优点 | 缺点 |
|------|------|
| 封装复杂创建过程，客户端无需关心组装细节 | 类数量增加 |
| 避免参数顺序错乱 | 属性频繁变动时维护成本上升 |
| 支持对象不可变（无setter） | 简单对象使用属于过度设计 |
| 链式调用优雅，可读性强 | — |

### 1.5 适用场景

- 实体类/DO/DTO/VO封装（属性多、有必选+可选）
- 配置类对象创建（DB连接池、Redis配置、线程池参数）
- 不可变对象创建（多线程共享对象）
- 框架：MyBatis的SqlSessionFactory、OkHttp的Request、Lombok的@Builder

### 1.6 与工厂模式对比

| 对比维度 | 建造者模式 | 工厂模式 |
|----------|-----------|---------|
| 核心目标 | 组装复杂对象，关注分步过程 | 创建不同系列对象，关注产品种类 |
| 对象复杂度 | 针对复杂、多属性对象 | 简单或中等复杂度对象 |
| 客户端关注点 | 传入参数，获取完整对象 | 选择工厂，获取对应产品 |
| 对象可变性 | 推荐不可变对象 | 可变对象居多 |

## 2. 原型模式

### 2.1 核心定义

**用一个已经创建的实例（原型）作为模板，通过复制（克隆）来创建新的对象，无需重新初始化。**

原型模式把对象的"创建逻辑"替换为"复制逻辑"，适合创建成本高（数据库查询、网络请求）、属性多且初始化复杂的对象。

### 2.2 核心角色

| 角色 | 说明 |
|------|------|
| **抽象原型（Prototype）** | 定义克隆接口，Java中实现`Cloneable`接口 |
| **具体原型（Concrete Prototype）** | 实现克隆方法，完成自身复制 |

### 2.3 浅克隆 vs 深克隆

| 对比 | 浅克隆 | 深克隆 |
|------|--------|--------|
| 基本类型 | 复制值 | 复制值 |
| 引用类型 | 复制引用地址（共享） | 创建新对象（独立） |
| 实现难度 | 简单 | 较复杂 |
| 安全性 | 修改克隆对象影响原对象 | 完全独立 |
| 后端推荐度 | 不推荐（有陷阱） | 推荐 |

### 2.4 代码实现

```java
// 引用类型
class UserInfo implements Serializable {
    private Long userId;
    private String username;
    // constructor, getters, setters...
}

class Goods implements Serializable {
    private Long goodsId;
    private String goodsName;
    // constructor, getters, setters...
}

// 具体原型：订单对象
public class Order implements Cloneable, Serializable {
    private Long orderId;
    private Double amount;
    private UserInfo userInfo;       // 引用类型
    private List<Goods> goodsList;   // 引用类型

    // 构造器模拟高成本初始化
    public Order(Long orderId, Double amount, UserInfo userInfo, List<Goods> goodsList) {
        // 模拟耗时操作（数据库查询）
        this.orderId = orderId;
        this.amount = amount;
        this.userInfo = userInfo;
        this.goodsList = goodsList;
    }

    // ========== 浅克隆 ==========
    @Override
    protected Object clone() throws CloneNotSupportedException {
        return super.clone();
    }

    // ========== 深克隆（序列化方式，推荐） ==========
    public Order deepClone() throws IOException, ClassNotFoundException {
        ByteArrayOutputStream bos = new ByteArrayOutputStream();
        ObjectOutputStream oos = new ObjectOutputStream(bos);
        oos.writeObject(this);

        ByteArrayInputStream bis = new ByteArrayInputStream(bos.toByteArray());
        ObjectInputStream ois = new ObjectInputStream(bis);
        return (Order) ois.readObject();
    }
}

// 客户端
public class Client {
    public static void main(String[] args) throws Exception {
        UserInfo userInfo = new UserInfo(1L, "张三");
        List<Goods> goodsList = new ArrayList<>();
        goodsList.add(new Goods(1001L, "手机"));
        Order prototype = new Order(10001L, 5999.0, userInfo, goodsList);

        // 浅克隆：引用共享
        Order shallow = (Order) prototype.clone();
        shallow.getUserInfo().setUsername("李四"); // 影响原对象

        // 深克隆：完全独立
        Order deep = prototype.deepClone();
        deep.getUserInfo().setUsername("王五"); // 不影响原对象
    }
}
```

### 2.5 深克隆方式对比

| 克隆方式 | 实现方式 | 优点 | 缺点 |
|----------|---------|------|------|
| **序列化克隆** | 实现Serializable，字节流读写 | 通用、支持多层嵌套 | 性能略低 |
| **手动克隆** | 重写clone()，递归克隆所有引用 | 性能最高 | 代码冗余 |
| **第三方工具** | SerializationUtils.clone() | 无需手写序列化代码 | 依赖第三方包 |

### 2.6 适用场景

- **缓存对象复制**：克隆缓存中的热点对象后修改属性，避免污染原对象
- **批量对象创建**：订单、报表等复杂对象，克隆原型后修改少量属性
- **原型池**：结合享元模式，池中预留原型对象供克隆
- **Spring中的应用**：`@Scope("prototype")` 每次获取都创建新Bean

### 2.7 注意事项

- **浅克隆陷阱**：包含引用类型的对象禁止直接使用浅克隆
- **序列化限制**：所有嵌套类必须实现Serializable
- **过度克隆风险**：简单对象直接new更高效

## 3. 创建型模式横向对比

| 模式 | 核心差异 | 后端适用场景 |
|------|----------|-------------|
| **单例模式** | 保证唯一实例，全局共享 | 配置类、工具类、连接池 |
| **简单工厂** | 统一工厂创建产品，违反OCP | 轻量固定产品场景 |
| **工厂方法** | 一个工厂一个产品，符合OCP | 单一产品多实现 |
| **抽象工厂** | 一个工厂一个产品族 | 多系列配套产品 |
| **建造者模式** | 分步构建复杂对象 | 多属性复杂对象、不可变对象 |
| **原型模式** | 克隆已有对象，替代高成本new | 高成本对象、批量创建 |

### 创建型模式面试高频题

| 问题 | 核心答案 |
|------|----------|
| 单例模式的DCL为什么需要volatile？ | 禁止指令重排，防止其他线程拿到半初始化对象 |
| 枚举单例为什么能防反射？ | JDK对枚举反射做了限制，`Constructor.newInstance()`直接抛异常 |
| 简单工厂和工厂方法的区别？ | 简单工厂一个类创建所有产品（违反OCP），工厂方法每个产品对应一个工厂（符合OCP） |
| 抽象工厂解决了什么问题？ | 保证产品族内对象兼容性，避免不同系列组件混用 |
| 建造者模式和工厂模式的区别？ | 工厂关注"生产什么产品"，建造者关注"如何一步步组装产品" |
| 浅克隆和深克隆的区别？ | 浅克隆引用类型共享，深克隆引用类型独立复制 |
| 什么是Lombok的@Builder？ | 建造者模式的注解实现，自动生成静态内部Builder类 |

### 创建型模式选择决策树

```
需要全局唯一实例？ → 单例模式
    ↓ 需要创建对象
创建不同类型产品？
    ├── 只有少量固定类型 → 简单工厂
    ├── 单一产品多种实现 → 工厂方法
    └── 多系列配套产品 → 抽象工厂
    ↓ 复杂组装
属性多、有必选/可选参数？ → 建造者模式
    ↓ 创建成本高
对象初始化和创建开销大？ → 原型模式
```
