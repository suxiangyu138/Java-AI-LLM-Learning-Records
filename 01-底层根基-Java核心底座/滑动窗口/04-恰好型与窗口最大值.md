## 1. 恰好型问题：为什么难

### 1.1 问题定义

```
恰好型：统计"恰好满足某条件"的子数组/子串数量
  恰好有 K 个不同整数（992）
  和恰好为 K（930）
  恰好有 K 个奇数（1248）

为什么滑动窗口不能直接处理"恰好"？
  窗口状态是"当前窗口"的单一快照
  "恰好 K 个不同整数"在扩窗/缩窗时无法保持
  恰好状态不满足单调性！
```

### 1.2 单调性分析

```
"至多 K 个不同整数" → 单调！
  扩窗 → 不同整数数增加（可能超过 K）→ 更难满足 ✓
  缩窗 → 不同整数数减少 → 更易满足 ✓

"恰好 K 个不同整数" → 不单调！
  扩窗 → 可能变成 K+1（超过）
  缩窗 → 可能变成 K-1（不足）
  → 指针移动无法保证条件朝向可预测

解决方案：容斥原理——把"恰好"转化为"至多"
```

## 2. atMost 容斥原理

### 2.1 核心公式

```
恰好 K = 至多 K - 至多 (K-1)

exactlyK = atMost(K) - atMost(K-1)

例：K 个不同整数的子数组数
  = (不同整数数 ≤ K 的子数组数) - (不同整数数 ≤ K-1 的子数组数)
  → 剩下恰好有 K 个不同整数的子数组

原理：集合论容斥（A \ B 差集）
  {≤K} 包含 {≤K-1} → 差集恰好是 {=K}
```

### 2.2 为什么 atMost 能用滑窗？

```
"至多 K"满足条件单调性 → 滑动窗口可解：
  窗口不合法（种类 > K）→ 缩窗
  合法 → 累加子数组数

累加技巧：以 right 结尾的合法子数组数 = right - left + 1
  （从 left 到 right 的每个位置都可以作为左端点）
```

## 3. 992. K 个不同整数的子数组

### 3.1 完整实现（atMost 差集）

```java
/**
 * LeetCode 992. K 个不同整数的子数组（Hard）
 * 统计恰好有 K 个不同整数的子数组个数
 *
 * 解法：exactlyK = atMost(K) - atMost(K-1)
 * 每个 atMost 用滑动窗口 O(n)
 */
public int subarraysWithKDistinct(int[] nums, int k) {
    return atMostK(nums, k) - atMostK(nums, k - 1);
}

/**
 * 至多有 K 个不同整数的子数组数
 * 窗口合法：不同整数种类 ≤ K
 * 累加：以 right 结尾的合法子数组 = right - left + 1
 */
private int atMostK(int[] nums, int k) {
    Map<Integer, Integer> count = new HashMap<>();
    int left = 0, total = 0;

    for (int right = 0; right < nums.length; right++) {
        count.put(nums[right], count.getOrDefault(nums[right], 0) + 1);

        while (count.size() > k) {          // 不合法：种类太多
            int leftVal = nums[left];
            count.put(leftVal, count.get(leftVal) - 1);
            if (count.get(leftVal) == 0) {
                count.remove(leftVal);      // 移除键（种类减 1）
            }
            left++;
        }

        total += right - left + 1;          // ⚠️ 累加合法子数组数
    }
    return total;
}
```

### 3.2 推演：nums = [1, 2, 1, 2, 3], k = 2

```
atMost(2) 的计算：
right=0 加1 → 窗口[1]，种类1 ≤ 2 → total += 1 = 1
right=1 加2 → [1,2]，种类2 → total += 2 = 3
right=2 加1 → [1,2,1] → total += 3 = 6
right=3 加2 → [1,2,1,2] → total += 4 = 10
right=4 加3 → [1,2,1,2,3]，种类3 > 2 → 缩到 [2,3]（left=3）
  → total += 2 = 12
atMost(2) = 12

atMost(1)：只有单一种类的子数组
  [1,2,1,2] 中：单种类子数组 = 4 个（[1],[2],[1],[2]）
  [3]：1 个 → atMost(1) = 5

答案 = 12 - 5 = 7 ✓
```

### 3.3 恰好型家族

| 题号 | 题目 | 容斥公式 | 窗口条件 |
|:---:|------|------|------|
| 992 | K 个不同整数 | atMost(K)-atMost(K-1) | 种类 ≤ K |
| 930 | 和相同的二元子数组 | atMost(K)-atMost(K-1) | 和 ≤ K |
| 1248 | K 个奇数的子数组 | atMost(K)-atMost(K-1) | 奇数 ≤ K |
| 1358 | K 个至少出现一次的子串 | atMost(K-1) 变体 | 所有种类 ≥ 1 |

## 4. 239. 滑动窗口最大值：单调队列

### 4.1 完整实现

```java
/**
 * LeetCode 239. 滑动窗口最大值（Hot 100 Hard）
 * 窗口大小为 k，返回每个窗口的最大值
 * [1,3,-1,-3,5,3,6,7], k=3 → [3,3,5,5,6,7]
 *
 * 单调递减队列（存下标！）：
 *   ① 入队：从队尾弹出所有比当前小的元素
 *      （它们不可能成为窗口最大值 → 永久淘汰）
 *   ② 出队：队头下标滑出窗口 → 弹出
 *   ③ 取值：队头就是当前窗口最大值
 * 每个元素进出一次 → O(n)
 */
public int[] maxSlidingWindow(int[] nums, int k) {
    int n = nums.length;
    int[] result = new int[n - k + 1];
    Deque<Integer> deque = new ArrayDeque<>();   // 存下标，单调递减

    for (int i = 0; i < n; i++) {
        // ① 入队：弹出所有比当前小的（不可能再是最大值）
        while (!deque.isEmpty() && nums[deque.peekLast()] < nums[i]) {
            deque.pollLast();
        }
        deque.offerLast(i);

        // ② 出队：滑出窗口的旧下标
        if (deque.peekFirst() <= i - k) {
            deque.pollFirst();
        }

        // ③ 取值：窗口形成后取队头
        if (i >= k - 1) {
            result[i - k + 1] = nums[deque.peekFirst()];
        }
    }
    return result;
}
```

### 4.2 推演：nums = [1, 3, -1, -3, 5, 3, 6, 7], k = 3

```
i=0: 入队 1 → deque=[0(1)]
i=1: 3 > 1 弹出 0 → deque=[1(3)]
i=2: -1 < 3 → deque=[1(3), 2(-1)]；i≥2 → 结果[0]=nums[1]=3
i=3: -3 < -1 → deque=[1(3),2(-1),3(-3)]；队头 1 > 3-3=0 在窗内 → 结果[1]=3
i=4: 5 弹出 3,2,1 → deque=[4(5)]；结果[2]=5
i=5: 3 < 5 → deque=[4(5),5(3)]；结果[3]=5
i=6: 6 弹出 5,4 → deque=[6(6)]；结果[4]=6
i=7: 7 弹出 6 → deque=[7(7)]；结果[5]=7
结果 [3,3,5,5,6,7] ✓
```

### 4.3 为什么"比当前小的都弹出"是正确的？

```
元素 x 比新元素 y 小且 x 在 y 左边（更早过期）：
  x 不可能成为窗口最大值：
    y 比 x 大 → 只要 x 在窗口中，y 也在 → 最大值轮不到 x
    y 比 x 晚过期 → y 活着的时间覆盖 x
  → x 永久淘汰 ✓

这是单调队列的核心思想："晚到且更大"淘汰"早到且更小"
```

## 5. 单调队列原理与模板

### 5.1 与普通队列/单调栈对比

| 结构 | 特点 | 适用 | 代表题 |
|------|------|------|:---:|
| 普通队列 | FIFO | BFS/层序 | 102 |
| 单调栈 | 找下一个更大/更小 | 739/84 | 见栈体系 |
| **单调队列** | 窗口内最值 | 滑动窗口最值 | 239 |

```
单调队列 = 双端队列 Deque
  队头：当前窗口最值（最大/最小）
  队尾：维护单调性（弹出破坏单调的）

操作三件套：
  ① 新元素入队前：弹出队尾所有比它"弱"的
  ② 滑出窗口：队头过期弹出
  ③ 取最值：队头
```

### 5.2 单调队列通用模板

```java
/**
 * 单调队列模板（窗口最值）
 * 单调递减 → 队头最大；单调递增 → 队头最小
 */
public int[] slidingWindowExtreme(int[] nums, int k, boolean wantMax) {
    int n = nums.length;
    int[] result = new int[n - k + 1];
    Deque<Integer> deque = new ArrayDeque<>();

    for (int i = 0; i < n; i++) {
        // ① 维护单调性：弹出"比当前弱"的队尾
        while (!deque.isEmpty()) {
            int tailVal = nums[deque.peekLast()];
            boolean shouldPop = wantMax
                ? tailVal < nums[i]     // 求最大：弹出更小的
                : tailVal > nums[i];    // 求最小：弹出更大的
            if (!shouldPop) break;
            deque.pollLast();
        }
        deque.offerLast(i);

        // ② 过期弹出
        if (deque.peekFirst() <= i - k) deque.pollFirst();

        // ③ 取最值
        if (i >= k - 1) result[i - k + 1] = nums[deque.peekFirst()];
    }
    return result;
}
```

### 5.3 单调队列的 DP 优化应用

```
单调队列除了窗口最值，还能优化 DP：
  dp[i] = max(dp[i-1], dp[i-2], ..., dp[i-k]) + cost[i]
  （滑动窗口内的最大值 → 单调队列 O(n)）
  
代表题：
  1696. 跳跃游戏 VI（窗口最大 + DP）
  1425. 带限制的子序列和

面试话术："状态转移需要窗口内最大值时，
 可以用单调队列把 O(nk) 降到 O(n)。"
```

> 🎯 **核心要点**：进阶滑窗两大武器——**容斥原理**把"恰好 K"转化为"至多 K"的差值（992/930/1248 三题同一公式），**单调队列**用"晚到且更大淘汰早到且更小"的机制 O(n) 求窗口最值（239）。记忆"恰好等于至多减至多"和"入队淘汰、过期弹出、队头取值"三件套，Hard 滑窗题也能拆解。
