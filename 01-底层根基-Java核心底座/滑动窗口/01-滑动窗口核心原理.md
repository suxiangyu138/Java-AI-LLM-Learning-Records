## 1. 滑动窗口的本质

### 1.1 定义

> 滑动窗口：两个指针（left/right）**同向移动**，维护一个**连续区间**。右指针负责扩展探索，左指针负责收缩修正，窗口始终满足/逼近题目条件。

```
示例（3. 无重复字符的最长子串）：
窗口 [left, right] 内无重复字符

  a b c a b c b b
    ↑     ↑
   left  right     ← 窗口 [b,c,a] 合法
        ↑   ↑
       left right  ← 窗口 [a,b,c] 合法（右扩）
```

### 1.2 与暴力枚举的本质区别

```
暴力：枚举所有 (left, right) 对 → O(n²) 种区间，逐个检查
滑窗：left/right 各自单调递增、永不回退
      → 总共 O(2n) = O(n) 次操作

暴力为什么慢？每个区间都重新计算状态，前一轮信息全部丢弃
滑窗为什么快？窗口移动时只做"增量更新"（加右去左）
```

### 1.3 直觉类比

```
滑动窗口像"呼吸"：
  右扩 = 吸气（尝试更多元素，探索边界）
  左缩 = 呼气（移除多余元素，恢复合法）

窗口状态是"增量维护"的：
  扩窗：加入 arr[right]，更新计数
  缩窗：移除 arr[left]，更新计数
  → 窗口状态始终是当前区间的最新快照
```

## 2. 信息复用：O(n) 的秘密

### 2.1 增量计算

```
定长窗口示例（643. 最大平均子数组）：
  k=4 的窗口和：
  窗口 [0..3] 和 = 1+2+3+4 = 10
  窗口 [1..4] 和 = 10 - 1 + 5 = 14     ← 增量！(去掉旧头，加上新尾)

错误做法：每次重新计算整个窗口 → O(nk)
正确做法：sum -= nums[i-k]; sum += nums[i] → O(n)
```

### 2.2 三大复用机制

| 机制 | 含义 | 例子 |
|------|------|------|
| **边界继承** | 新窗口 = 旧窗口 ± 边界元素 | 643 定长和 |
| **增量计算** | 状态用 O(1) 更新而非重算 | 438 频次数组 |
| **不可行传播** | 缩窗后状态直接继承 | 3 无重复子串 |

```
记忆："窗口不是重新构建的，而是增量演进的"
这是滑动窗口 O(n) 的根本原因
```

## 3. 条件单调性：成立的前提

### 3.1 定义

> 滑动窗口成立的前提：窗口条件满足**单调性**——**扩窗更难满足条件，缩窗更易满足条件**。

```
以"无重复字符"为例：
  窗口合法（无重复）
  右扩 → 可能引入重复 → 更难满足 ✓
  左缩 → 移除重复 → 更易满足 ✓

以"和 ≥ target"为例（209）：
  窗口和 ≥ target（满足）
  右扩 → 和更大 → 依然满足（条件单调）✓
```

### 3.2 为什么单调性必要？

```
如果没有单调性，指针移动就无法保证"窗口状态可预测"：
  左缩后条件可能变差（需重新搜索）→ 无法用 while 快速收缩

单调性保证：
  缩窗时 while 能一次性收缩到合法（每步都有进展）
  扩窗时状态单调变化（或单调满足/不满足）

等价于"子集继承性"：合法窗口的子集仍合法（部分题目）
或"条件随窗口大小单调"
```

### 3.3 判定方法

```
拿到连续子数组/子串题 → 问：
  ① 窗口扩大时，条件"更不容易满足"吗？
  ② 窗口缩小时，条件"更容易满足"吗？
  都成立 → 滑动窗口
  不成立 → 换前缀和/DP（见失效场景）
```

## 4. 通用模板

### 4.1 不定长模板（核心）

```java
/**
 * 滑动窗口通用模板（不定长）
 * 口诀："右扩左缩，先进后出；最长在外更新，最短在内更新"
 */
public int slidingWindowTemplate(int[] nums, 条件) {
    int left = 0;
    int answer = 0;
    // 窗口状态：计数数组/哈希表/和等

    for (int right = 0; right < nums.length; right++) {
        // ① 扩窗：加入 nums[right]，更新状态
        add(nums[right]);

        // ② 缩窗：while 窗口不合法（必须 while 不是 if！）
        while (窗口不合法) {
            remove(nums[left]);       // 移除左边界
            left++;                   // 左指针前进
        }

        // ③ 更新答案
        //    求最长 → while 外更新（窗口已合法，取最大）
        //    求最短 → while 内更新（窗口刚合法，取最小）
        answer = Math.max(answer, right - left + 1);
    }
    return answer;
}
```

### 4.2 定长模板

```java
/**
 * 定长窗口模板（窗口大小恒为 k）
 * 关键：先建第一个窗口，再逐个滑动
 */
public int fixedWindowTemplate(int[] nums, int k) {
    // ① 先建第一个窗口 [0, k-1]
    int sum = 0;
    for (int i = 0; i < k; i++) sum += nums[i];
    int answer = sum;

    // ② 滑动：加新尾，去旧头
    for (int i = k; i < nums.length; i++) {
        sum += nums[i];          // 加新尾
        sum -= nums[i - k];      // 去旧头（⚠️ i-k 不是 k-i）
        answer = Math.max(answer, sum);
    }
    return answer;
}
```

### 4.3 模板要点

```
① 缩窗必须用 while：if 只缩一次可能仍不合法
② 更新位置：求最长在 while 外，求最短在 while 内
③ 定长去旧头：nums[i-k]（先加后减，顺序无所谓）
④ 忘记处理第一个窗口（定长模板）——最常见的坑
```

## 5. 失效场景：什么时候不能用

### 5.1 含负数的子数组和（最经典反例）

```
nums = [-1, 1, 0, -2, 2], 找和为 0 的子数组个数（560 题）

❌ 滑动窗口为什么失效？
  窗口和 < 0 时无法判断该缩窗还是扩窗：
    扩窗加负数 → 和更小；缩窗减负数 → 和变大
    → 条件不单调 → 指针移动无法预测 → 滑窗错误

✅ 正确解法：前缀和 + 哈希表
  prefix[j] - prefix[i] = 0 → 找相同前缀和出现次数
```

### 5.2 其他失效场景

| 场景 | 失效原因 | 替代解法 |
|------|------|------|
| 含负数的子数组和 | 窗口和不单调 | 前缀和+哈希 (560) |
| 异或和为 K | 异或无单调性 | 前缀异或+哈希 |
| 中位数类问题 | 中位数不增量可维护 | 双堆 (480) |
| 区间最大值（非单调） | 需要历史信息 | 单调队列 (239) |

### 5.3 判定口诀

```
"连续看单调，单调看维护，维护看结构"
  连续子数组/子串 → 检查单调性
  单调 → 滑动窗口
  维护结构：计数/哈希/单调队列
```

## 6. 四大子模型总览

| 子模型 | 缩窗触发 | 答案更新 | 代表题 | 记忆点 |
|------|------|------|:---:|------|
| **定长** | 窗口长度恰为 K | 恰 K 时 | 438/567/643 | 先建首窗 |
| **不定长求最长** | while 窗口不合法 | **while 外**取 max | 3/1004/424 | 合法后更新 |
| **不定长求最短** | while 窗口合法 | **while 内**取 min | 76/209 | 合法时更新 |
| **恰好型** | while 超过限制 | while 外累加 | 992/930 | atMost 容斥 |

```
核心公式（恰好型）：
  exactlyK = atMost(K) - atMost(K-1)
  "恰好 K" 不满足单调性 → 转化为"至多 K"两个窗口相减
```

> 🎯 **核心要点**：滑动窗口 = 双指针 + 连续区间 + 增量维护。**条件单调性**是成立前提（负数场景失效→前缀和），**信息复用**是 O(n) 秘密，**右扩左缩**是模板骨架。记住"连续看单调，单调看维护"口诀与"恰好等于至多减至多"公式，四大子模型 30 秒识别。
