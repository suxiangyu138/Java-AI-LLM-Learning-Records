## 1. 脚本安全防护 {#1}

### 1.1 命令注入防护

Shell 脚本最大的安全风险之一是**命令注入**——用户输入被直接拼接到命令中执行。

```bash
#!/bin/bash
# ❌ 危险写法 —— 命令注入示例
read -p "输入文件名: " filename
cat "${filename}"          # 用户输入 "; rm -rf /" 会导致灾难

# ✅ 安全写法 —— 参数化
read -p "输入文件名: " filename
# 1. 白名单验证
if [[ ! "${filename}" =~ ^[a-zA-Z0-9_.-]+$ ]]; then
    echo "❌ 非法文件名"
    exit 1
fi
# 2. 限制在安全目录内
readonly BASE_DIR="/var/data"
filepath="${BASE_DIR}/${filename}"
# 3. 防止路径穿越
if [[ ! "$(realpath "${filepath}")" =~ ^${BASE_DIR}/ ]]; then
    echo "❌ 不允许访问该路径"
    exit 1
fi
cat "${filepath}"
```

### 1.2 防注入检查清单

| 注入类型 | 风险场景 | 防御措施 |
|---------|---------|---------|
| **命令注入** | `eval "${user_input}"` | 参数化，避免 eval |
| **SQL 注入** | 脚本拼接 SQL 字符串 | 使用 PreparedStatement |
| **路径穿越** | `../../etc/passwd` | `realpath` 验证路径前缀 |
| **环境变量注入** | 恶意 `$PATH` / `$LD_PRELOAD` | 脚本开头重置关键变量 |
| **Shellshock** | 恶意环境变量导出函数 | 不执行来自外部的 Bash 环境 |
| **XML 注入** | XML 解析实体注入 | 禁用外部实体解析 |

### 1.3 敏感信息管理

```bash
#!/bin/bash
# ❌ 绝对禁止的写法

# 硬编码密码
DB_PASSWORD="P@ssw0rd123"                  # 明文密码

# 命令行传密码（会出现在 ps 输出和历史中）
mysql -u root -p"${PASSWORD}"               # 密码暴露

# 密钥写入临时文件未加密
echo "${API_KEY}" > /tmp/key.txt            # 明文落地

# ✅ 安全的替代方案

# 1. 从环境变量读取（CI/CD 平台注入）
DB_PASSWORD="${DB_PASSWORD:?未设置数据库密码}"

# 2. 从密钥管理服务获取
DB_PASSWORD=$(vault kv get -field=password secret/myapp/db)

# 3. 通过 stdin 传递密码
mysql -u root --password="" < "${SQL_FILE}" # 使用 .my.cnf 配置文件

# 4. 使用临时文件 + 权限控制
umask 077                                    # 仅当前用户可读写
TEMP_FILE=$(mktemp)
trap 'rm -f "${TEMP_FILE}"' EXIT             # 确保清理
echo "${API_KEY}" > "${TEMP_FILE}"
```

### 1.4 ScriptEngine 安全沙箱

```java
import javax.script.*;
import java.security.*;

public class ScriptSandbox {

    /**
     * 在受限权限下执行脚本
     */
    public static Object evalSecure(ScriptEngine engine, String script)
            throws Exception {

        // ── 最小权限策略 ──
        PermissionCollection perms = new Permissions();
        // 仅允许读取特定目录
        perms.add(new FilePermission("/opt/scripts/data/-", "read"));
        // 允许有限的计算资源
        perms.add(new RuntimePermission("accessDeclaredMembers"));
        // 拒绝：文件写入、网络访问、进程执行...

        AccessControlContext acc = new AccessControlContext(
            new ProtectionDomain[] {
                new ProtectionDomain(null, perms)
            }
        );

        return AccessController.doPrivileged(
            (PrivilegedExceptionAction<Object>) () -> engine.eval(script),
            acc
        );
    }
}
```

```java
// GraalVM 安全沙箱（推荐方案）
import org.graalvm.polyglot.*;

public class GraalVMSandbox {

    public static Object evalSecurely(String script) {
        try (Context context = Context.newBuilder("js")
                // ── 沙箱配置 ──
                .allowHostAccess(HostAccess.NONE)        // 禁止 Java 互操作
                .allowHostClassLookup(c -> false)        // 禁止加载任何 Java 类
                .allowIO(HostIOAccess.NONE)              // 禁止文件/网络 IO
                .allowCreateThread(false)                 // 禁止创建线程
                .allowNativeAccess(false)                 // 禁止本地代码
                .allowCreateProcess(false)                // 禁止创建进程
                .sandbox(SandboxPolicy.STRICT)            // 严格沙箱模式
                // ── 资源限制 ──
                .resourceLimits(ResourceLimits.newBuilder()
                    .statementLimit(10000, null)          // 最多 1 万条语句
                    .build())
                .build()) {

            return context.eval("js", script);
        }
    }
}
```

> ⚠️ **警告**：永远不要信任用户提交的脚本。始终在沙箱中执行，限制 CPU、内存、文件系统和网络访问。

### 2.2 脚本开发规范

```bash
#!/bin/bash
# ═══════════════════════════════════════════════════════════════
# 脚本名称: health-check.sh
# 功能描述: 检查所有微服务健康状态
# 作者: devops-team
# 创建日期: 2026-07-30
# 最后修改: 2026-07-30
# 依赖: curl, jq (安装: apt-get install jq)
# 适用系统: Linux (Ubuntu 22.04+ / CentOS 7+)
# 版本: v1.2.0
# ═══════════════════════════════════════════════════════════════

# ── 严格模式 ──
set -euo pipefail
IFS=$'\n\t'    # 防止空格分词带来的意外

# ── 常量和配置 ──
readonly SCRIPT_NAME="$(basename "$0")"
readonly SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
readonly TIMEOUT_SECONDS=5
readonly RETRY_COUNT=3

# ── 颜色输出 ──
readonly RED='\033[0;31m'
readonly GREEN='\033[0;32m'
readonly YELLOW='\033[1;33m'
readonly NC='\033[0m' # No Color

# ── 函数定义 ──
#######################################
# 打印带时间戳的日志
# Arguments:
#   $1 - 日志级别 (INFO/WARN/ERROR)
#   $2 - 日志消息
#######################################
log() {
    local level="$1"; shift
    local color=""
    case "${level}" in
        INFO)  color="${GREEN}" ;;
        WARN)  color="${YELLOW}" ;;
        ERROR) color="${RED}" ;;
    esac
    printf "[%s] ${color}%-5s${NC} %s\n" \
        "$(date '+%Y-%m-%d %H:%M:%S')" "${level}" "$*"
}

#######################################
# 检查单个服务健康状态
# Arguments:
#   $1 - 服务名称
#   $2 - 服务 URL
# Returns:
#   0 - 健康
#   1 - 不健康
#######################################
check_service() {
    local name="$1"
    local url="$2"

    log INFO "检查 ${name} (${url})..."

    if curl -sf --max-time "${TIMEOUT_SECONDS}" "${url}" > /dev/null 2>&1; then
        log INFO "${name} ✅ 健康"
        return 0
    else
        log ERROR "${name} ❌ 不健康"
        return 1
    fi
}

# ── 清理函数 ──
cleanup() {
    log INFO "清理临时文件..."
    # 清理逻辑
}
trap cleanup EXIT

# ── 主流程 ──
main() {
    log INFO "开始健康检查..."

    local failed=0
    local services=(
        "gateway:http://localhost:8080/actuator/health"
        "user-service:http://localhost:8081/actuator/health"
        "order-service:http://localhost:8082/actuator/health"
    )

    for entry in "${services[@]}"; do
        local name="${entry%%:*}"
        local url="${entry#*:}"
        check_service "${name}" "${url}" || ((failed++))
    done

    if [[ ${failed} -eq 0 ]]; then
        log INFO "全部服务健康 ✅"
    else
        log ERROR "${failed}/${#services[@]} 个服务异常 ❌"
        exit 1
    fi
}

main "$@"
```

## 3. 性能优化策略 {#3}

### 3.1 JVM 脚本启动优化

| 策略 | 说明 | 效果 |
|------|------|:---:|
| **Class Data Sharing (CDS)** | 预加载类数据到共享归档 | 启动快 20-40% |
| **AppCDS** | 应用级类数据共享 | 启动快 30-50% |
| **AOT 编译 (jaotc)** | 提前编译为本地代码 | 预热时间缩短 |
| **CRaC** | Coordinated Restore at Checkpoint | 毫秒级启动 |
| **GraalVM Native Image** | 编译为原生可执行文件 | 亚秒级启动 |
| **Spring Boot 3.3+ CDS** | Spring 原生 CDS 支持 | 显著加速 |

```bash
# ── 生成 CDS 归档 ──
java -Xshare:dump

# ── 应用级 CDS (AppCDS) ──
# 第1步：记录运行时加载的类
java -XX:DumpLoadedClassList=classes.lst -jar myapp.jar
# 第2步：生成共享归档
java -Xshare:dump -XX:SharedClassListFile=classes.lst \
     -XX:SharedArchiveFile=myapp.jsa -jar myapp.jar
# 第3步：使用共享归档启动
java -Xshare:auto -XX:SharedArchiveFile=myapp.jsa -jar myapp.jar
```

### 3.2 脚本执行缓存策略

```java
// ── CompiledScript 缓存 ──
public class ScriptCache {
    private final Map<String, CompiledScript> cache = new ConcurrentHashMap<>();
    private final ScriptEngine engine;

    public ScriptCache(ScriptEngine engine) {
        this.engine = engine;
    }

    public Object eval(String scriptId, String script) throws Exception {
        CompiledScript compiled = cache.computeIfAbsent(scriptId, id -> {
            try {
                return ((Compilable) engine).compile(script);
            } catch (ScriptException e) {
                throw new RuntimeException("脚本编译失败: " + id, e);
            }
        });
        return compiled.eval();
    }

    public void invalidate(String scriptId) {
        cache.remove(scriptId);
    }

    public long cacheSize() {
        return cache.size();
    }
}
```

## 4. 错误处理与容错设计 {#4}

### 4.1 错误处理模式

```bash
#!/bin/bash
set -euo pipefail

# ── 模式1: 错误积累 + 最终汇总 ──
errors=()

step1() {
    echo "执行步骤1..." || errors+=("步骤1失败")       # 不中断
}
step2() {
    echo "执行步骤2..." || errors+=("步骤2失败")
}
step3() {
    echo "执行步骤3..." || errors+=("步骤3失败")
}

step1; step2; step3

if [[ ${#errors[@]} -gt 0 ]]; then
    echo "❌ 以下步骤失败:"
    printf '  - %s\n' "${errors[@]}"
    exit 1
fi

# ── 模式2: 重试模板 ──
retry() {
    local max_attempts="$1"
    local delay="$2"
    shift 2
    local cmd=("$@")

    for attempt in $(seq 1 "${max_attempts}"); do
        if "${cmd[@]}"; then
            return 0
        fi
        echo "⚠️  第 ${attempt}/${max_attempts} 次尝试失败，${delay}s 后重试..."
        sleep "${delay}"
        delay=$((delay * 2))    # 指数退避
    done
    return 1
}

retry 5 2 curl -f http://localhost:8080/health

# ── 模式3: 熔断器 ──
readonly CIRCUIT_BREAKER_FILE="/tmp/circuit-breaker-$(basename "$0")"

is_circuit_open() {
    [[ -f "${CIRCUIT_BREAKER_FILE}" ]] && \
    [[ $(($(date +%s) - $(stat -c %Y "${CIRCUIT_BREAKER_FILE}"))) -lt 300 ]]
}

open_circuit() {
    touch "${CIRCUIT_BREAKER_FILE}"
}

if is_circuit_open; then
    echo "🔴 熔断器开启，跳过此执行"
    exit 0
fi

# 执行任务...
if ! curl -f http://critical-service/api; then
    open_circuit
    echo "❌ 关键服务不可用，熔断器已开启（5分钟）"
    exit 1
fi
```

### 4.2 Java 侧容错设计

```java
// ── Resilience4j 重试 + 熔断 ──
import io.github.resilience4j.retry.Retry;
import io.github.resilience4j.circuitbreaker.CircuitBreaker;
import java.util.function.Supplier;

public class ScriptExecutor {

    private final Retry retry = Retry.ofDefaults("script-retry");
    private final CircuitBreaker cb = CircuitBreaker.ofDefaults("script-cb");

    public String executeWithResilience(Supplier<String> scriptExecution) {
        return Retry.decorateSupplier(retry,
            CircuitBreaker.decorateSupplier(cb, scriptExecution)
        ).get();
    }
}
```

```bash
# 输出 JSON 格式日志，便于 ELK/Loki 采集

log_json() {
    local level="$1"
    local message="$2"
    local extra="${3:-{}}"

    jq -nc \
        --arg timestamp "$(date -u +%Y-%m-%dT%H:%M:%SZ)" \
        --arg level "${level}" \
        --arg script "${SCRIPT_NAME}" \
        --arg message "${message}" \
        --argjson extra "${extra}" \
        '{
            timestamp: $timestamp,
            level: $level,
            script: $script,
            message: $message,
            pid: '$$',
            host: $HOSTNAME,
            extra: $extra
        }'
}

# 使用示例
log_json "INFO" "部署开始" '{"environment":"production","version":"1.2.3"}'
log_json "ERROR" "数据库连接失败" '{"host":"db-1.internal","port":5432,"retry":3}'
```

```bash
#!/bin/bash
# metrics.sh —— 简单的脚本指标收集

record_duration() {
    local task="$1"
    local start="$2"
    local end=$(date +%s%N)
    local duration_ms=$(( (end - start) / 1000000 ))

    # 写入指标文件（Prometheus 可抓取）
    echo "script_duration_ms{task=\"${task}\",script=\"${SCRIPT_NAME}\"} ${duration_ms}" \
        >> /var/log/scripts/metrics.prom
}

record_count() {
    local metric="$1"
    local value="$2"
    local labels="${3:-}"

    echo "${metric}{${labels}} ${value}" >> /var/log/scripts/metrics.prom
}

# 使用示例
start_time=$(date +%s%N)

# ... 执行任务 ...

record_duration "deploy" "${start_time}"
record_count "scripts_run_total" 1 "script=${SCRIPT_NAME},status=success"
```

```bash
                    text: $text,

            }')"
```

### 6.2 构建脚本验证

```java
import org.junit.jupiter.api.Test;

    @Test
    void noSnapshotDependencies() throws Exception {
        // 验证发布的 JAR 不包含 SNAPSHOT 依赖
        String pom = Files.readString(Path.of("pom.xml"));
        // 简化检测：实际项目中应解析依赖树
        assertFalse(pom.contains("SNAPSHOT"),
            "发布版不应有 SNAPSHOT");
    }
}
```

### 7.2 版本管理策略

```bash
# ── Git 标签管理脚本版本 ──
git tag -a "scripts/v1.2.0" -m "新增蓝绿部署脚本"
git push origin "scripts/v1.2.0"

# ── 脚本内嵌版本号 ──
readonly VERSION="1.2.0"

if [[ "${1:-}" == "--version" ]]; then
    echo "${SCRIPT_NAME} v${VERSION}"
    exit 0
fi

# ── 语义化版本 (SemVer) ──
# MAJOR.MINOR.PATCH
# MAJOR: 不兼容 API 修改
# MINOR: 向下兼容的功能新增
# PATCH: 向下兼容的问题修复
```

### 7.3 文档化要求

```bash
#!/bin/bash
# 每个脚本必须包含的文档：

# ── HEADER ──
# @name: 脚本名称
# @description: 一句话描述脚本功能
# @usage: 使用方法和参数说明
# @dependencies: 外部工具依赖
# @environment: 需要的环境变量
# @exitcodes: 退出码说明
#   0 - 成功
#   1 - 通用错误
#   2 - 参数错误
#   3 - 依赖缺失

# ── USAGE 函数 ──
usage() {
    cat <<EOF
用法: ${SCRIPT_NAME} [OPTIONS] <ENVIRONMENT>

OPTIONS:
    -h, --help          显示此帮助信息
    -v, --verbose       详细输出模式
    -d, --dry-run       仅预览，不实际执行
    -f, --force         跳过确认，强制执行

ENVIRONMENT:
    dev                 开发环境
    staging             预发布环境
    production          生产环境（需二次确认）

示例:
    ${SCRIPT_NAME} dev
    ${SCRIPT_NAME} -f production
    ${SCRIPT_NAME} --dry-run staging

版本: ${VERSION}
仓库: https://github.com/company/scripts
EOF
    exit 0
}
```
