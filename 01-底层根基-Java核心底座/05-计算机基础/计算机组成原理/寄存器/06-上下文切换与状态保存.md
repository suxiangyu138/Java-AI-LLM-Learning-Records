## 1. 上下文切换的层次

"保存寄存器"不是一个动作，而是多个层次的组合：

| 层次 | 触发 | 保存内容 | 频率 |
|------|------|---------|------|
| 用户态函数调用 | `call` | 按 ABI：调用者/被调用者保存寄存器（04 模块） | 微秒级 |
| 用户态↔内核态 | 系统调用/中断 | 通用寄存器 + 部分段/标志 | 微秒级 |
| 进程/线程切换 | 调度器 | 全部通用寄存器 + FPU/向量 + CR3 | 毫秒级 |
| VM 切换 | VM-Exit/Enter | 全部 + 控制寄存器 + MSR 子集 | 微秒-毫秒级 |
| CPU 电源状态 | C 状态 | 全部状态（由微码处理） | 系统级 |

> 💡 层次递进的核心原则：**越频繁的切换，保存越少**——函数调用只保存 ABI 约定的子集；系统调用只保存用户可见寄存器；进程切换才保存全部（含 CR3 换地址空间）。

## 2. 内核态切换：保存什么、在哪保存

### 2.1 中断/系统调用入口（x86-64）

```text
硬件自动（trap 到内核瞬间）：
  用户 RSP、RFLAGS、RIP → 压入内核栈（由 TSS.RSP0 指向）
  切换 CS/SS（特权级提升）

软件（内核入口代码，entry_64.S）：
  保存 RAX..R15、RDI..R9（参数）、段寄存器、CR3 相关
  → 压入 pt_regs 结构
```

### 2.2 调度器切换（Linux `switch_to` 语义）

```
进程 A → 进程 B 时保存：
  ① 内核栈指针 RSP（保存到 task_struct.thread.sp）
  ② 被调用者保存寄存器 RBX/RBP/R12-R15（压内核栈）
  ③ 返回地址 RIP（用 call 的返回地址隐式保存——switch_to 就是一场"函数调用")
  ④ CR3 → 新进程页表（TLB 整体失效，PCID 可保留部分）
  ⑤ 浮点/向量状态 → xsave 区域（见下节）
```

```asm
; switch_to 的本质（伪代码）
push rbp
mov  rbp, rsp                 ; 保存 A 的栈
mov  [task_A.sp], rsp         ; 存到 task_struct
mov  rsp, [task_B.sp]         ; 换成 B 的栈
pop  rbp
ret                           ; 返回"B 上次离开的地方" —— 状态转移完成
```

> 🎯 理解关键：**上下文切换不需要"保存所有寄存器到内存"**——因为 ABI 规定被调用者保存的寄存器（RBX 等）在切换期间值不变；切换本身被建模成一次"永不返回的函数调用"。内核栈上保留的就是完整现场。

## 3. FPU/向量状态的困境与 xsave

### 3.1 问题：状态膨胀

| 时代 | 状态 | 大小 |
|------|------|:---:|
| 早期 x87 FPU | 8×80 位 FPU | 108B |
| SSE2 | 16×128 位 XMM | 512B |
| AVX | 16×256 位 YMM | ~1KB |
| AVX-512 | 32×512 位 ZMM | ~2.7KB |
| **AMX** | 8×1KB TMM + 配置 | **~8KB+** |
| ARM SVE | 动态 32×VL（VL≤2048 位）+ 谓词 | 1-16KB+ |

寄存器状态从百字节膨胀到 KB 级——每次进程切换都全量保存，代价不可接受。

### 3.2 解决方案：分段惰性 + xsave 指令集

```
历史：fxsave/fxrstor（128 位时代）→ xsave/xrstor（可变状态，XCR0 位图）
现状：Linux 把 FPU 状态保存推迟到"真正需要时"（惰性），
     内核自身尽量不用浮点 —— 避免保存自己的浮点现场
```

```text
xsave 的核心设计：
  XCR0 寄存器：位图声明"启用哪些状态"（SSE/AVX/AVX512/AMX 各一位）
  xsave 保存时只存"已修改的"状态（优化位图，dirty tracking）
  xrstor 按 XCR0 恢复

Linux 惰性策略（经典实现）：
  进程 A 切换 B 时若 A 用过浮点 → 保存 A 的 xstate
  若 B 不用浮点（多数内核线程）→ 无需恢复，省掉一次 xrstor
  首次使用 FPU 时触发 #NM 异常 → 此时才恢复状态（真正惰性）
```

> ⚠️ 惰性保存 vs 抢占：现代内核已放弃完全惰性（FPU 用户态抢占导致"状态已切换但未保存"的竞态），改为**切换时条件保存、但从不推迟恢复**——即"保存惰性，恢复及时"。

## 4. 惰性保存与抢占的冲突

### 4.1 历史竞态（经典考点）

```text
① 线程 T1 用 FPU，状态存于 T1 的 xstate 区域
② 抢占到 T2：T2 不用 FPU → 不恢复 T1 状态，但也不标记"T2 拥有 FPU"
③ T2 被抢占回 T1：T1 以为状态还在（没被 T2 碰过）→ 恢复顺利
④ 危险场景：T2 用 FPU 但 T1 的 xstate 没保存 → T1 状态被 T2 覆盖 → 数据损坏

解法：T1 切换出时若 FPU 曾被 T2 使用过，就必须保存 T1 状态
     （即使 T1 此后不用 FPU）——"dirty"标记（fpu_state_used）
```

### 4.2 现代实现结论

```
- 每任务 xstate 区域按需分配（AMX 大状态默认懒加载）
- 内核自身：保留少量专用 FPU 上下文（加密/RAID 用），其余一律不动
- 线程迁移：NUMA 亲和外加状态迁移成本——浮点重的线程跨核迁移更贵
```

## 5. 虚拟化：Guest 寄存器状态管理

### 5.1 VMCS 的自动保存/加载

x86 虚拟化（VT-x）用 **VMCS**（VM Control Structure）管理 Guest 状态：

| 状态类别 | 处理方式 |
|---------|---------|
| 部分 GPR | **自动**保存/恢复（VMCS 字段，硬件代劳） |
| 全部 GPR + 标志 | 软件（Guest 内核入口自己保存，同普通中断） |
| CR0/CR3/CR4/EFER | 自动保存/恢复（VM-entry/exit） |
| MSR 子集 | 自动（VMCS 列出）；其余靠 `MSR 位图` 触发 VM-Exit 模拟 |
| FPU/AVX/AMX | 可"加载延迟"：退出时不保存，进 Guest 首次用 FPU 再保存（Lazy FPU 的虚拟化版） |

```
VM-Exit 开销分解（典型 ~200-2000 周期）：
  自动状态保存（几百周期）+ 软件路径（vmx_exit_handlers）
  → 频繁 VM-Exit（如 PIO 模拟）是虚拟化性能杀手
  → 缓解：MSR 位图、EPT（影子页表免了）、APICv（虚拟中断不退出）
```

### 5.2 ARM 的虚拟化寄存器

```
vCPU 状态在 kernel 中保存（无 VMCS 概念）：
  - 通用寄存器 + 系统寄存器子集（VCPU 结构体）
  - EL1/EL0 寄存器组切换：vhe 用 EL2 直接运行 Guest
  - SME/SVE 状态：规模可变 → 按需分配，超过阈值时"退出流式模式"
```

> 💡 对比：x86 靠硬件自动保存（VMCS），ARM 靠软件在 VCPU 结构中保存——前者退出更贵但一致性强，后者灵活但需软件精细管理。这是两大虚拟化路线的寄存器层面差异。

## 6. 状态保存的规模演进

### 6.1 上下文大小对比（实测量级）

| 状态集 | 大小 | 一次保存成本 |
|--------|:---:|:---:|
| 整数 GPR（16×8B） | 128B | ~10-20 周期 |
| + SSE/AVX（XMM/YMM） | ~1KB | 几十周期 |
| + AVX-512 | ~2.7KB | 数百周期 |
| + AMX（8×1KB TMM） | ~8KB+ | 上千周期 |
| ARM64 SVE（VL=2048） | ~16KB（Z+谓词） | 上千周期 |

### 6.2 工程启示

```
① 状态越大，切换越贵 → 向量重负载进程频繁切换是性能杀手
   （JVM 场景：GC 线程少切换、绑核可缓解）
② 引入新扩展要先算切换成本：AMX 的 8KB 状态让 Linux 默认懒加载
③ 线程迁移 vs 状态缓存：per-CPU 保存区域（FPU state cache）减少重复保存
④ 对应用层的启示：减少线程切换（绑核/协程）的本质之一就是
   少付"状态保存税"
```

> 🎯 **核心要点**：寄存器状态保存是"频率 × 大小"的乘积游戏——系统调用频繁但保存小，进程切换罕见但保存大；架构演进（AVX/AMX/SVE）不断把"大"推向极端，于是懒加载、按需分配、硬件自动保存成了系统软件的主战场。

## 7. 小结

| 问题 | 答案 |
|------|------|
| 调度器切换保存什么？ | 内核栈 + 被调用者保存寄存器 + CR3 + FPU 状态 |
| xsave 解决什么？ | AVX-512/AMX 等大状态的按需保存与恢复 |
| 惰性 FPU 为什么被改？ | 用户态抢占引入竞态，改为"保存惰性、恢复及时" |
| VMCS 管什么？ | VM-Exit/Entry 的寄存器自动保存、加载与 MSR 处理 |
| AMX 状态多大？ | 8KB+，是普通整数状态的 60 倍 |
