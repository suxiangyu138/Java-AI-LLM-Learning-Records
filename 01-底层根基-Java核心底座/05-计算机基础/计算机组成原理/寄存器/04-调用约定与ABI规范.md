## 1. 为什么要调用约定

### 1.1 问题的本质

函数调用跨越编译单元（甚至语言），调用者与 callee 必须就三件事达成协议：

```
① 参数放在哪？         → 寄存器（前 N 个）+ 栈（剩余）
② 返回值放在哪？       → 固定寄存器
③ 哪些寄存器谁负责恢复？ → 调用者保存 vs 被调用者保存
```

没有约定，编译器无法优化任何跨模块调用——约定即 ABI 的寄存器部分，是**二进制兼容性的基石**。

### 1.2 保存者分工的逻辑

| 类型 | 规则 | 含义 | 编译器行为 |
|------|------|------|-----------|
| 调用者保存（Caller-saved） | 调用后值不保证 | callee 可随意使用 | 调用方若还要用，调用前自己压栈 |
| 被调用者保存（Callee-saved） | 返回时值必须还原 | 对调用者透明 | callee 使用前压栈，返回前弹出 |

> 💡 记忆：**参数寄存器都是调用者保存的**（callee 必然重写它们）；**被调用者保存的寄存器给 callee 当"长期变量"用**——分配局部变量时优先用 callee-saved，减少保存开销。

## 2. System V AMD64（Linux/macOS/BSD）

### 2.1 寄存器分工表

| 寄存器 | 职责 |
|--------|------|
| RDI, RSI, RDX, RCX, R8, R9 | 整数/指针参数 1-6 |
| RAX | 返回值（浮点返回用 XMM0） |
| RBX, RBP, R12-R15 | **被调用者保存** |
| RSP | 栈指针（被调用者保存，返回时须还原） |
| RAX, RCX, RDX, RSI, RDI, R8-R11 | 调用者保存（临时） |
| RBP | 可选帧指针（`-fomit-frame-pointer` 后作通用寄存器） |
| XMM0-7 | 浮点/向量参数；XMM0 返回 |
| XMM8-15 | 调用者保存 |
| 栈 | 第 7 个起参数按逆序压栈；栈须 16 字节对齐（call 前 RSP≡8 mod 16） |

### 2.2 规则细节

```
参数分类：整数类 6 个寄存器用完后走栈；浮点类 8 个 XMM 用完走栈
分类时按声明顺序：一个函数混传 int/float，各自独立排队

返回值：
  整数 8 字节内 → RAX
  128 位 → RAX:RDX
  浮点 → XMM0
  大结构体 → 调用者分配空间，RDI 处传隐藏指针（x86-64 的"返回区域"）

红区（Red Zone）：call 指令下方 128 字节区域可被叶子函数直接使用
  → 编译器对简单叶子函数省略 push/pop，直接使用红区
```

## 3. Windows x64

### 3.1 与 SysV 的关键差异

| 维度 | System V | Windows x64 |
|------|----------|-------------|
| 参数寄存器 | RDI/RSI/RDX/RCX/R8/R9 | **RCX/RDX/R8/R9**（仅 4 个） |
| 浮点参数 | XMM0-7 | XMM0-3 |
| 被调用者保存 | RBX/RBP/R12-R15 | **RBX/RBP/RDI/RSI/R12-R15 + XMM6-15** |
| 影子空间 | 无 | 调用者需预留 **32 字节**（4 个参数槽） |
| 栈对齐 | 16 字节（call 前 RSP≡8 mod 16） | 16 字节（call 前 RSP≡8 mod 16） |
| 返回 | RAX / XMM0 | RAX / XMM0 |

### 3.2 影子空间（Shadow Space）

```
调用者在 call 之前必须在栈上为前 4 个寄存器参数预留 32 字节
→ callee 可以把参数"倒映"到固定栈偏移（[rsp+8] 起），
  便于调试器与寄存器不足时使用

代价：每个非叶子调用多 32 字节栈开销
原因：Windows 调试器（WinDbg）约定可以随时改写参数，
      需要固定的参数存储位置 —— 这是调试优先的 ABI 设计
```

> ⚠️ 混用陷阱：Windows 上开发 C/C++ 库，导出函数必须遵循 Windows x64 约定；JNI/FFI 调用（Java `invoke`、Rust FFI）必须按目标平台约定声明——这是跨平台 FFI bug 的头号来源。

## 4. ARM64 AAPCS64

### 4.1 寄存器分工表

| 寄存器 | 职责 |
|--------|------|
| X0-X7 | 参数/返回值（X0 返回） |
| X8 | 间接结果寄存器（大结构体返回指针） |
| X9-X15 | 临时（调用者保存） |
| X16-X17 | IP0/IP1（链接器跳板专用，调用者保存） |
| X18 | 平台寄存器（OS 保留，用户代码不可用） |
| X19-X28 | **被调用者保存** |
| X29 (FP) | 帧指针（被调用者保存） |
| X30 (LR) | 返回地址（调用者保存——调用时被覆盖） |
| SP | 栈指针（被调用者保存） |
| V0-V7 | 浮点/向量参数（V0 返回） |
| V8-V15 | 低 64 位被调用者保存（D 视图） |
| V16-V31 | 完全调用者保存 |

### 4.2 特殊规则

```
① 无红区：ARM64 的 ABI 没有 SysV 式红区（早期约定有，已废弃）——叶子函数也要正规压栈
② 16 字节栈对齐（任何时刻 SP 须 16 对齐）
③ X18 不可用：用户代码不得使用平台寄存器（Apple 用它存部分 TLS）
④ 可变参数（va_arg）：同 SysV，通过"寄存器保存区"（AAPCS 的 64 字节区域）定位
⑤ 返回地址在 LR，不入栈 —— 叶子函数调用零栈开销；非叶子才 push x29/x30
```

> 💡 ARM64 调用比 x86 省事的根本：**返回地址走 LR 寄存器而非栈**。x86 的 `call` 必须压栈，ARM64 的 `bl` 直接写 LR——这是 RISC 精简调用路径的代表设计。

## 5. RISC-V ABI

### 5.1 分工表（RV64GC + F/D）

| 寄存器 | ABI | 职责 |
|:---:|-----|------|
| x0 | zero | 硬连线零 |
| x1 | ra | 返回地址（调用者保存） |
| x2 | sp | 栈指针（被调用者保存） |
| x3 | gp | 全局指针（平台保留） |
| x4 | tp | 线程指针（平台保留） |
| x5-7, x28-31 | t0-2, t3-6 | 临时（调用者保存） |
| x8 | s0/fp | 保存/帧指针 |
| x9, x18-27 | s1-s11 | 被调用者保存 |
| x10-17 | a0-a7 | 参数/返回值 |
| f10-17 | fa0-fa7 | 浮点参数（与整数寄存器对偶命名） |
| f0-9, f28-31 | ft0-11 | 浮点临时 |
| f8-9, f18-27 | fs0-11 | 浮点保存 |

### 5.2 特点

```
① 与 SysV 高度同构：6+2 整数参数、调用者/被调用者划分几乎一致 → 移植编译器容易
② 返回地址在 ra（同 ARM 的 LR 思想）
③ 整数与浮点参数寄存器编号故意错位（a0-a7 vs fa0-fa7），
   避免寄存器压力相互污染
④ 栈 16 字节对齐；无红区（v2023 规范移除红区？实际 RV64 psABI 无红区）
```

## 6. 平台对比与实战反汇编

### 6.1 四大 ABI 一表流

| 维度 | SysV x86-64 | Windows x64 | AAPCS64 | RISC-V |
|------|:---:|:---:|:---:|:---:|
| 整数参数寄存器 | 6（RDI..R9） | 4（RCX..R9） | 8（X0-X7） | 8（a0-a7） |
| 浮点参数寄存器 | 8（XMM0-7） | 4（XMM0-3） | 8（V0-V7） | 8（fa0-fa7） |
| 被调用者保存 | RBX/RBP/R12-15 | RBX/RBP/RSI/RDI/R12-15 | X19-X28+X29 | s0-s11 |
| 返回地址 | 栈（call 压栈） | 栈 | LR（X30） | ra（x1） |
| 返回寄存器 | RAX | RAX | X0 | a0 |
| 红区 | ✅ 128B | ❌ | ❌ | ❌ |
| 额外空间 | — | 影子空间 32B | 可变参数区 | — |

### 6.2 实战：`int sum(int a, int b, int c)` 的反汇编

```asm
; GCC -O2 Linux (SysV)：参数在 edi/esi/edx
sum:
    lea     eax, [rdi+rsi]      ; a+b（LEA 不碰标志）
    add     eax, edx            ; +c
    ret                         ; 返回 eax

; MSVC Windows：参数在 ecx/edx/r8d
sum:
    lea     eax, [rcx+rdx]
    add     eax, r8d
    ret

; GCC ARM64：参数在 w0/w1/w2
sum:
    add     w0, w0, w1
    add     w0, w0, w2
    ret                         ; LR 无需恢复，直接 ret
```

> 🎯 **核心要点**：ABI 是"寄存器的宪法"——它决定了函数调用是快是慢、二进制能否互操作。后端工程师至少应记住 SysV 的 6 参数寄存器顺序（RDI RSI RDX RCX R8 R9），这是读懂一切崩溃栈与反汇编的基础。

## 7. 小结

| 问题 | 答案 |
|------|------|
| 前 6 个整数参数寄存器？ | SysV：RDI RSI RDX RCX R8 R9；Windows 只 4 个 |
| 谁负责保存？ | 参数寄存器=调用者保存；RBX/R12-15 等=被调用者保存 |
| ARM64 为什么省调用？ | 返回地址在 LR 寄存器，叶子函数零压栈 |
| 影子空间是什么？ | Windows 为前 4 参数预留的 32B 栈槽 |
| 红区是什么？ | SysV 独有的 128B 免压栈区域，仅叶子函数可用 |
