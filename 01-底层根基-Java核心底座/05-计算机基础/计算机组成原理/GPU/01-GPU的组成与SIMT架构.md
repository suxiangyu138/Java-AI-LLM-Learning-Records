## 1. GPU vs CPU：两种设计哲学

### 1.1 面积预算的差异

```
CPU 的面积（~400mm²）：30%+ 花在"让单线程更快"
  —— 分支预测、乱序窗口、大缓存、重命名
GPU 的面积（~800mm²+）：85%+ 花在"执行单元 + 寄存器"
  —— 计算单元海量，控制逻辑极简

核心对照：
  CPU：少量强大核（4-24 核 × 超线程）—— 为"单线程延迟"优化
  GPU：海量简单核（16384 核！）—— 为"总吞吐"优化
```

### 1.2 延迟 vs 吞吐

| 维度 | CPU | GPU |
|------|-----|-----|
| 优化目标 | 单线程延迟（latency） | 总吞吐（throughput） |
| 核数 | 4-24 | 数千-数万 |
| 隐藏延迟手段 | 乱序 + 缓存 + 预测 | **线程切换**（换人干活） |
| 缓存 | 大（每核 1-3MB） | 小（每核 KB 级，靠带宽） |
| 时钟 | 4-5 GHz | 1.5-2.5 GHz |
| 适用 | 分支多、依赖强、延迟敏感 | 数据并行、无依赖、吞吐敏感 |

> 🎯 一句话哲学：**CPU 是"一个聪明人做难事"，GPU 是"一万个听话的工人做简单重复的事"**。GPU 的每个线程都很笨（无预测、无乱序），但人多到可以淹没延迟。

## 2. SIMT：单指令多线程

### 2.1 从 SIMD 到 SIMT

```
SIMD（CPU 向量化）：一条指令操作一组数据（AVX-512 一次 16 个 float）
  —— 数据宽度固定，软件写死

SIMT（GPU）：一条指令驱动一组"独立线程"同时执行同一操作
  —— 每个线程有自己的寄存器、自己的 PC 上下文（概念上）
  —— 硬件按 32 个线程为一组（warp）取指、执行

关键差异：
  SIMD 是"数据级并行"，SIMT 是"线程级并行 + 硬件打包执行"
  SIMT 让程序员写"每个元素一个线程"，编译器/硬件负责打包
```

### 2.2 为什么叫"单指令多线程"

```c
// 一个 SIMT 程序（CUDA 视角）：每个线程处理一个数组元素
__global__ void vecAdd(float *a, float *b, float *c) {
    int i = threadIdx.x + blockIdx.x * blockDim.x;  // 我的元素下标
    c[i] = a[i] + b[i];   // 所有线程执行同一条指令，操作不同数据
}
// 硬件执行：32 个线程（一个 warp）同时执行 c[i]=a[i]+b[i]
```

### 2.3 SIMT 的三层模型

```
线程（Thread）   ：最小执行单元，有自己的寄存器
Warp（束）       ：32 个线程的硬件调度单位（一条指令驱动 32 线程）
线程块（Block）  ：软件定义的一组线程（64-1024），映射到一个 SM

程序写"线程"，硬件按"warp"执行，调度按"块"分配 —— 三层解耦
```

## 3. SM 的内部解剖

### 3.1 SM（NVIDIA）/ CU（AMD）的结构

以 H100 SM 为例（各代略有差异，结构通用）：

```text
┌──────────────────────────────────────┐
│ SM（流式多处理器）                      │
│  ┌────────────────────────────────┐  │
│  │ 4 个处理子块（Sub-Core / 调度器）  │  │
│  │  每个子块：32 个 CUDA 核（FP32）   │  │
│  │           16 个 FP64 核          │  │
│  │           16 个 Tensor Core      │  │
│  └────────────────────────────────┘  │
│  ┌─────────────┐  ┌─────────────┐   │
│  │ 寄存器堆      │  │ 共享内存/L1  │   │
│  │ 64K×32 位    │  │ 228KB       │   │
│  └─────────────┘  └─────────────┘   │
│  ┌────────────────────────────────┐  │
│  │ 调度器：4 个 warp 调度器，每周期     │  │
│  │ 各发射 1 条指令（1 个 warp）       │  │
│  └────────────────────────────────┘  │
└──────────────────────────────────────┘
```

| 部件 | 数量/容量 | 职责 |
|------|:---:|------|
| 子块（分区） | 4 | 每个独立调度 |
| CUDA 核（FP32） | 128/SM | 整数/单精度运算 |
| Tensor Core | 4/SM | 矩阵乘（AI 主力） |
| 寄存器堆 | 256KB/SM | 线程现场（隐藏延迟） |
| 共享内存+L1 | 228KB/SM | 块内快速通信 |
| warp 调度器 | 4 | 每周期 1 条指令/调度器 |

### 3.2 为什么没有分支预测/乱序

```
GPU 线程切换成本 = 0：现场就在寄存器堆里，调度器换个 warp 即可
  → 不需要乱序窗口（隐藏延迟靠"换人"）
  → 不需要大缓存（靠带宽 + 并行访问）
  → 不需要分支预测（代价巨大但收益低，只有简单预测器）

省下的面积 → 全给执行单元和寄存器 —— 这就是 GPU 核多的来源
```

> ⚠️ 但"无预测"有代价：分支发散时 warp 要串行走各路（见 03 模块）——GPU 把"预测"换成了"容忍"，把复杂度转移给了程序员。

## 4. warp 的由来与意义

### 4.1 为什么是 32

```
warp = 32 线程（NVIDIA 固定；AMD 用 64 线程的 wavefront，RDNA 后 32）

理由：
  ① 指令带宽摊薄：一条指令取指/译码成本由 32 个线程分摊
  ② 存储带宽匹配：32 线程 × 4B（float）= 128B = 2 个 64B 缓存行
     → 合并访问时正好一趟拿满
  ③ 调度粒度合适：4 调度器 × 每周期 1 warp → 每周期处理 128 线程
```

### 4.2 warp 的两个关键性质

```
① 同步执行（近似）：同一 warp 内线程基本同步（无发散时）
   → 共享内存访问无竞争、SIMT 语义简单

② 调度单位：GPU 的"线程"不是线程，是 warp
   → 调度器每周期选一个"就绪 warp"发射
   → 64 个 warp 驻留一个 SM 时，访存等待被完全隐藏
```

### 4.3 warp 与 CPU 线程的对照

| 维度 | CPU 线程 | GPU warp |
|------|---------|----------|
| 切换成本 | 微秒级（保存全部状态） | ~0（现场在寄存器堆） |
| 切换频率 | 罕见（调度器决定） | 每周期都可能 |
| 数量 | 每核 2（SMT） | 每 SM 64（最大） |
| 编程视角 | 同步原语（锁/信号量） | 近似同步（无发散） |

> 💡 类比：warp 切换 ≈ 电影院换一排人坐——观众（寄存器）原位不动，只是聚光灯（调度器）换了一排照。这就是 GPU 能"万线程在飞"的物理秘密。

## 5. GPU 的宏观组成

### 5.1 一张全景图（以 B200 双 die 为例）

```text
┌────────────────────────────────────────────────┐
│ B200（双 die，208B 晶体管，TSMC 4NP）            │
│  ┌───────────────┐    ┌───────────────┐        │
│  │ Die 0         │    │ Die 1         │        │
│  │ 多组 GPC       │    │ 多组 GPC       │        │
│  │  ┌─────────┐  │    │  ┌─────────┐  │        │
│  │  │ SM×N    │  │    │  │ SM×N    │  │        │
│  │  └─────────┘  │    │  └─────────┘  │        │
│  │  L2 分片      │    │  L2 分片      │        │
│  └───────────────┘    └───────────────┘        │
│  ┌────────────────────────────────────────┐    │
│  │ HBM3e 192GB（8 个堆叠），8 TB/s 带宽      │    │
│  └────────────────────────────────────────┘    │
│  NVLink 5：GPU 间 1.8 TB/s；PCIe 5.0 主机接口   │
└────────────────────────────────────────────────┘
```

### 5.2 组织结构（NVIDIA 术语）

```
GPU → GPC（图形处理集群，含若干 SM）
    → SM（流式多处理器）
    → 子块（4 个/SM）→ warp 调度器
    → CUDA 核 / Tensor Core / 访存单元

AMD 对应：GCD/Shader Engine → CU（计算单元，=SM）
         → 4 个 SIMD 单元（每个 32 lane，≈warp）
```

### 5.3 规模对比（2025-2026）

| GPU | 晶体管 | 计算单元 | 峰值算力 | 显存/带宽 |
|-----|:---:|:---:|:---:|:---:|
| H100 | 80B | 132 SM | 989 TF FP16 | 80GB / 3.5TB/s |
| B200 | 208B | 双 die | 2.25 PF FP8 | 192GB / 8TB/s |
| MI355X | 185B | 256 CU | ~20 PF FP4 | 288GB / 8TB/s |
| Rubin（2026） | 336B | 双 die | 50 PF FP4 | 288GB / 22TB/s |

> 🎯 **核心要点**：GPU = SIMT 执行模型 + 海量小核 + 零成本线程切换。记住"warp 是调度单位、切换免费、带宽为王"三句话，就抓住了 GPU 架构的骨架——其余都是这三句的展开。
