## 1. 计算机系统层次结构

### 1.1 冯·诺依曼体系结构

```
┌──────────────────────────────────────────────────┐
│                   主存储器（Main Memory）           │
│                ┌─────┬─────┬─────┬─────┐          │
│                │ 指令 │ 数据 │ ... │ ... │          │
│                └─────┴─────┴─────┴─────┘          │
└──────┬──────────────┬────────────────────────────┘
       │ 读取指令/数据  │ 写回结果
┌──────┴──────┐ ┌─────┴──────────┐
│  控制器(CU)  │ │ 运算器(ALU/FPU) │
│ PC/IR/译码  │ │ 加减乘除/逻辑运算 │
└──────┬──────┘ └────────────────┘
       │ 控制信号
       ▼
┌──────────────────────┐
│    输入/输出设备       │
│  键盘 显示器 磁盘 网络  │
└──────────────────────┘
```

**核心思想**：程序和数据以二进制形式存储在同一存储器中，按地址访问。

**五大部件**：运算器、控制器、存储器、输入设备、输出设备。

### 1.2 计算机层次结构

```
第 5 层 — 高级语言层（Java / C++ / Python）
第 4 层 — 汇编语言层（x86 / ARM / RISC-V）
第 3 层 — 操作系统层（进程管理 / 文件系统）
第 2 层 — 指令集架构 ISA（x86 / ARM / RISC-V）← 软硬件分界
第 1 层 — 微程序控制 / 硬布线控制
第 0 层 — 数字逻辑电路（门电路 / 寄存器 / 触发器）
```

### 1.3 CPU 基本结构

| 部件 | 功能 | 说明 |
|------|------|------|
| **PC**（程序计数器） | 存放下一条指令地址 | 控制流的核心 |
| **IR**（指令寄存器） | 存放当前正在执行的指令 | 控制器译码 |
| **MAR** | 存储器地址寄存器 | 访存时存放地址 |
| **MDR** | 存储器数据寄存器 | 访存时暂存数据 |
| **ALU** | 算术逻辑单元 | 执行算术和逻辑运算 |
| **寄存器堆** | 存放操作数和中间结果 | CPU 内部最快存储 |

### 1.4 指令周期

```pseudocode
取指(Fetch) → 译码(Decode) → 执行(Execute) → 访存(Memory) → 写回(Write Back)
     │                                                          │
     └──────────────────── 循环 ────────────────────────────────┘
```

## 2. CPU 结构与指令系统

### 2.1 RISC vs CISC

| 特性 | RISC（精简指令集） | CISC（复杂指令集） |
|------|-------------------|-------------------|
| 指令长度 | 定长（如 32 位） | 变长 |
| 寻址方式 | 少（通常 Load/Store） | 多（内存直接参与运算） |
| 指令数 | 少（基础指令） | 多（复杂指令） |
| 实现 | 硬布线控制 | 微程序控制 |
| 典型架构 | ARM、RISC-V、MIPS | x86 |
| 应用领域 | 移动端、嵌入式 | PC、服务器 |

> **Java 开发者关联**：Android 运行在 ARM 架构上，JDK 同时支持 x86 和 ARM（如 Mac M 系列芯片用 ARM 版本 JDK）。

### 2.2 常见寻址方式

| 寻址方式 | 描述 | 示例（伪代码） |
|----------|------|---------------|
| 立即寻址 | 指令中直接给出操作数 | `ADD R1, #5` |
| 直接寻址 | 指令中给出操作数地址 | `LOAD R1, [0x1000]` |
| 间接寻址 | 寄存器存地址，从该地址取操作数 | `LOAD R1, [R2]` |
| 基址 + 变址 | 基址寄存器+变址寄存器=操作数地址 | `LOAD R1, [R2+R3]` |
| 寄存器寻址 | 操作数在寄存器中 | `ADD R1, R2` |

### 2.3 中断与异常

| 特性 | 中断（Interrupt） | 异常（Exception） |
|------|-------------------|-------------------|
| 来源 | CPU 外部（I/O 设备、时钟） | CPU 内部（指令执行错误） |
| 是否异步 | 异步（与当前指令无关） | 同步（指令执行的结果） |
| 示例 | 键盘按下、网卡收到数据 | 除零、缺页（Page Fault）、断点 |
| 处理 | 保存现场 → 中断服务 → 恢复现场 | 保存现场 → 异常处理 → 恢复或终止 |

**Java 中的体现**：
- `NullPointerException`：换页/访问违规 → OS 发 SIGSEGV → JVM 捕获 → 抛出 NPE
- `Thread.interrupt()`：设置中断标志，不直接触发硬件中断

## 3. 存储层次

### 3.1 存储金字塔

```
       ┌──────────┐
       │ 寄存器    │  ~1ns,  <1KB,  CPU 内部
      ┌┴──────────┴┐
      │  L1 Cache  │  ~2ns,  32-64KB,  每核独享
     ┌┴────────────┴┐
     │  L2 Cache    │  ~7ns,  256KB-1MB, 每核独享
    ┌┴──────────────┴┐
    │  L3 Cache(LLC) │  ~20ns,  8-32MB,  多核共享
   ┌┴────────────────┴┐
   │  主存（DRAM）     │  ~100ns,  GB 级
  ┌┴──────────────────┴┐
  │  SSD / HDD         │  ~10μs-10ms,  TB 级
 └─────────────────────┘
```

**局部性原理（Program Locality）**：
- **时间局部性**：刚访问的数据很快会再次访问（Cache 依赖于此）
- **空间局部性**：访问某个地址后，很快会访问其相邻地址（缓存行依赖于此）

### 3.2 Cache 与缓存行

**Cache 行（Cache Line）**：通常 64 字节，CPU 从内存取数据的最小单位。

**缓存映射方式**：

| 方式 | 描述 | 优缺点 |
|------|------|--------|
| 直接映射 | 每块内存固定映射到一个 Cache 行 | 简单但冲突多 |
| 全相联 | 任意块可放到任意 Cache 行 | 灵活但硬件成本高 |
| 组相联 | 折中，多路组相联 | 主流实现（如 8 路组相联） |

**缓存一致性协议（MESI）**：

| 状态 | 全称 | 含义 |
|------|------|------|
| **M**odified | 已修改 | 只在本 Cache 中有效，已被修改，与内存不一致 |
| **E**xclusive | 独占 | 只在本 Cache，与内存一致 |
| **S**hared | 共享 | 多 Cache 中均有效，与内存一致 |
| **I**nvalid | 失效 | Cache 行无效，需重新加载 |

### 3.3 伪共享（False Sharing）——Java 并发必须关注

```java
// 伪共享：两个线程分别递增 x 和 y，但 x 和 y 在同一缓存行
class Counter {
    volatile long x;
    volatile long y;
}

// 解决：JDK 8+ 推荐方式：@Contended 注解
@sun.misc.Contended
class ContendedCounter {
    volatile long x;
    volatile long y;
}
```

### 3.4 虚拟内存

- 每个进程 4GB（32 位）或 256TB（64 位）虚拟地址空间
- MMU（Memory Management Unit）负责虚拟 → 物理地址转换
- TLB（Translation Lookaside Buffer）缓存页表项
- 缺页中断：访问未在物理内存中的页 → 从磁盘调入

**JVM 关联**：
- `-Xmx` / `-Xms` 设置在虚拟地址空间内，不直接等于物理内存
- GC 频繁可能因堆过大导致换页（swap），性能雪崩
- `-XX:+AlwaysPreTouch` 启动时预申请物理内存，避免运行时缺页

## 4. 流水线技术

### 4.1 五级流水线

```pseudocode
时钟周期  1      2      3      4      5      6      7      8
指令1   IF →  ID →  EX →  MEM →  WB
指令2         IF →  ID →  EX →  MEM →  WB
指令3               IF →  ID →  EX →  MEM →  WB
指令4                     IF →  ID →  EX →  MEM →  WB
指令5                           IF →  ID →  EX →  MEM →  WB

IF=取指  ID=译码  EX=执行  MEM=访存  WB=写回
```

**流水线性能指标**：
- **吞吐率**：单位时间完成的指令数，理想情况 1 条/周期
- **加速比**：流水方式 vs 非流水方式的执行时间比
- **效率**：各段利用率

### 4.2 流水线冒险（Hazard）

| 类型 | 描述 | 解决方案 |
|------|------|----------|
| **结构冒险** | 硬件资源冲突 | 增加硬件资源（如分离指令/数据 Cache） |
| **数据冒险** | 指令间数据依赖 | 转发（Forwarding）、流水线暂停（Stall） |
| **控制冒险** | 分支指令导致流水线清空 | 分支预测、延迟分支 |

**数据冒险示例**：

```asm
ADD R1, R2, R3     ; R1 = R2 + R3
SUB R4, R1, R5     ; 依赖 ADD 的 R1，需等待或转发
```

### 4.3 分支预测

| 预测类型 | 描述 |
|---------|------|
| **静态预测** | 总是预测不跳转，或编译时由编译器决定 |
| **动态预测** | 基于历史行为（分支历史表 BHT），现代 CPU 预测准确率 > 95% |

> **Java 开发启示**：分支预测失败导致流水线清空，性能损失约 10-20 个时钟周期。对热点路径，将高概率分支放在 `if` 中，低概率分支放在 `else` 中。

## 5. 总线与 I/O

### 5.1 总线类型

| 总线 | 功能 | 特点 |
|------|------|------|
| 数据总线 | 传输数据 | 双向，宽度决定一次传输量 |
| 地址总线 | 传输地址 | 单向，宽度决定寻址范围 |
| 控制总线 | 发送控制信号 | 读写/中断/复位等 |

### 5.2 I/O 方式

| 方式 | CPU 参与度 | 传输效率 | 适用场景 |
|------|-----------|----------|----------|
| 程序查询 | 全参与（轮询） | 极低 | 简单嵌入式 |
| 程序中断 | 部分参与（中断驱动） | 中等 | 低速设备 |
| DMA | 仅开始/结束参与 | 高 | 磁盘、网卡等高速设备 |

> **DMA（Direct Memory Access）**：数据在设备和内存间直接传输，CPU 仅参与初始化和结束处理。是现代磁盘 I/O 和网络 I/O 的基础机制。

## 6. 后端开发关联

### 6.1 JVM 内存模型与底层

| JVM 概念 | 硬件层对应 |
|----------|-----------|
| `volatile` | 内存屏障 → 写回主存 + 使无效其他核心缓存行 → 依赖 MESI 协议 |
| `synchronized` | MonitorEnter/MonitorExit → 可能用到 `LOCK` 指令前缀 |
| CAS（`Unsafe.compareAndSwap`） | `CMPXCHG` 指令 + `LOCK` 前缀 |
| 对象内存布局 | 根据字段类型对齐，8 字节边界（影响 false sharing） |

### 6.2 CPU 性能分析

```bash
# Linux 下查看 CPU 缓存信息
lscpu                              # CPU 架构总览
cat /sys/devices/system/cpu/cpu0/cache/index*/size  # 各级缓存大小

# 性能计数器（perf）
perf stat -e cache-misses,cache-references java -jar app.jar
```

### 6.3 存储对性能的影响

```
L1 缓存命中      ~1ns   (4 个 CPU 周期)
L2 缓存命中      ~7ns   (14 个 CPU 周期)
L3 缓存命中      ~20ns  (40 个 CPU 周期)
主存访问         ~100ns (200 个 CPU 周期)
SSD 访问         ~10-100μs
HDD 访问         ~1-10ms

在等待一次内存访问的间隙，CPU 可执行 ~200 条指令
→ 这就是"缓存友好"代码和"缓存不友好"代码的性能差距根源
```

**缓存友好编程建议**：
1. 使用数组而非链表（连续内存，空间局部性好）
2. 多维数组行优先遍历（非列优先）
3. 结构体字段按访问频率排序（热点字段放一起）
4. 避免伪共享（`@Contended` 或手动填充）
