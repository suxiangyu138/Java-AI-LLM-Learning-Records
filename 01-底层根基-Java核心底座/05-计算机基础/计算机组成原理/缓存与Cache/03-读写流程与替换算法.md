## 1. 读路径：命中与缺失的完整流程

### 1.1 一次读命中（以 L1D 为例，Zen 5 ~4 周期）

```text
Cycle 1  发送虚拟地址，TLB 并行翻译；同时用 Index 选中 64 组中的 1 组
Cycle 2  12 路 Tag 并行比较（52 位比较器 × 12）
Cycle 3  比较结果汇聚：命中信号 + 选中的 way
Cycle 4  从命中行的 Data 阵列按 Offset 取出数据，交付执行单元
```

关键工程细节：

- **Tag 比较与数据读取并行**（先读所有路数据，命中后靠 MUX 选出）——用功耗换延迟
- **多端口/银行化**：64B 行拆成多个 bank，允许同一周期不同 bank 并行访问
- **命中判定失败怎么办**：向下一级发起缺失请求，同时"填充"路径把数据带回

### 1.2 一次读缺失（Miss Handling）

```
L1 缺失 → 生成 Miss 请求（含地址）→ 查询 MSHR（Miss Status Holding Register）
       → 若该地址已有在途请求则合并（避免重复取数）
       → 下钻 L2 → L3 → DRAM
       → 数据返回后：填充 L1 行 + 转发给执行单元（先供数，后写回行）
```

> 💡 **MSHR 与"按需供数"**：现代 CPU 数据到达后先绕过缓存行直接送给等待的执行单元（critical-word-first），缓存行随后在后台完成填充——这是流水线不停顿的关键机制。

## 2. 写路径：四种策略组合

### 2.1 两个正交维度

| 维度 | 选项 | 行为 | 优点 | 缺点 |
|------|------|------|------|------|
| 写命中后 | **Write-Through 直写** | 同时写缓存和主存 | 主存永远最新，一致性简单 | 每次写都占总线带宽（写放大） |
| | **Write-Back 写回** | 只写缓存，置 Dirty | 带宽节省 90%+，现代主流 | 驱逐时必须回写，一致性复杂 |
| 写缺失时 | **Write-Allocate 写分配** | 先把行调入缓存再写 | 与后续读命中共享（时间局部性） | 缺失时多一次取数 |
| | **No-Write-Allocate 非写分配** | 直接写主存，不进缓存 | 流式写入不污染缓存 | 连续写无缓存加速 |

### 2.2 经典组合矩阵

```
                 Write-Allocate        No-Write-Allocate
Write-Through   早期 CPU（如 80386）    直写+非分配（写直达设备）
Write-Back      ★ 现代 CPU 默认组合     少见（配合流式指令）
```

> 🎯 **工业标准**：现代处理器多级缓存全部采用 **Write-Back + Write-Allocate**。唯一例外是显式绕过缓存的流式写（`MOVNTDQ`/`st.relaxed` 无缓存语义），用于大数据流不污染 L1/L2。

### 2.3 Write-Back 的隐藏成本：Dirty 行驱逐

```
组满 + 新行调入 → 选中驱逐行（替换算法决定）
   ├── 行干净（非 Dirty）→ 直接丢弃
   └── 行 Dirty → 回写 DRAM（写 64B，可能触发整行读改写）
```

**回写缓冲（Write Buffer）**：Dirty 行驱逐时先入缓冲异步写回，避免 CPU 阻塞等待 DRAM——但缓冲满时会"反压"停顿，这是极端写密集负载的性能瓶颈之一。

## 3. 替换算法：从理论最优到硬件现实

### 3.1 理论最优：Belady 算法（MIN）

**驱逐未来最长时间内不会被访问的行**。命中率上界，但需要预知未来，**物理不可实现**——它的意义是作为所有算法的比较基准（模拟器中计算"离最优差多少"）。

### 3.2 教科书理想：LRU

驱逐最久未被访问的行。对时间局部性强的工作集接近最优，但**完美 LRU 需要记录访问顺序，硬件成本随相联度爆炸**：

| 相联度 | 完美 LRU 状态数 | 每行位数 |
|:---:|:---:|:---:|
| 4-way | 4! = 24 | 5 位 |
| 8-way | 8! = 40320 | 16 位 |
| 16-way | 16! ≈ 2×10¹³ | 45 位 |

16-way 每行 45 位 → 1MB L2 光替换状态就要约 90KB SRAM，**不可接受**。

### 3.3 硬件现实：LRU 的近似

| 策略 | 思想 | 硬件开销 | 代表 |
|------|------|---------|------|
| Pseudo-LRU（树形 PLRU） | 二叉树游标指示近似最近最少 | N−1 位/组，无每行计数 | 大量服务器 CPU |
| **Intel Quad-Age（四龄）** | 每行 2 位年龄，命中只更新被访问行 | 2 位/行 | Intel 现代核心 |
| FIFO / Random | 进序 / 随机驱逐 | 0 位 | 兜底策略 |

Intel quad-age 细节：新行插入到"比 MRU 老"的年龄档；命中将该行年龄降低一档（只有被访问行更新）。它不是真 LRU（多个行的年龄可能相同），且已知存在侧信道弱点（见 [06-安全模块](06-Cache安全与侧信道攻击.md)）。

> ⚠️ 一个被反复验证的工程结论：**对现代混合负载，LRU 本身并非最优**——流式数据会把"马上还要用的行"挤出去。这就是 RRIP 家族登场的原因。

## 4. RRIP 家族：现代工业标准

### 4.1 SRRIP（Static Re-reference Interval Prediction）

核心思想：不用"最近多久没访问"，而是用 **RRPV（Re-reference Prediction Value，重访预测值）** 表示"离下一次被访问还有多远"的估计，2 位：

| RRPV | 含义 | 行为 |
|:---:|------|------|
| 0 | 近期必被重访（HIT） | 命中时置 0，永不优先驱逐 |
| 1 | 近期可能重访 | 正常驻留 |
| 2 | 重访可能性低 | 接近驱逐 |
| 3 | 流式数据（远距离重访） | 最高驱逐优先级 |

插入行为差异是关键创新：**新行以 RRPV=2（而非 LRU 式的 0）插入**，避免"新来的行挤掉活跃行"——正好修复 LRU 面对流式负载的缺陷。命中时 RRPV 置 0。

### 4.2 DRRIP（Dynamic RRIP）：按工作负载自动切换

同时维护两个策略（SRRIP 与"仅一档提升"变体），用 **set dueling** 采样少量专用组，动态选择全局胜者：

```
Set D0..Dk：专用运行策略 A 的采样组（统计命中率）
Set E0..Ek：专用运行策略 B 的采样组
其余组：当前"获胜"策略
每 N 周期比较采样组命中率 → 切换全局策略（ppm 寄存器）
```

### 4.3 RRIP 家族演进与实证

| 策略 | 年份 | 改进点 |
|------|:---:|------|
| SRRIP | 2010 | 插入值=2 的静态 RRPV |
| DRRIP | 2010 | Set dueling 动态选择插入/提升向量 |
| SHiP | 2013 | 按"历史签名"（PC/地址）定制插入值 |
| EHC（Expected Hit Count） | 2022 | 3 位 Tag 近似 Belady，MPKI 较 LRU 降 17.5%，优于 Hawkeye/DRRIP |

**2025 实证数据（PACIPV，ISCA'25）**：对指令密集负载，SRRIP 较 LRU 提速 2.2%，最新 PACIPV 策略达 3.3%（配合 EIP 预取器）——**轻量 RRIP 变体依然是最强性价比阵营**。

## 5. 学习型替换：2025 前沿

### 5.1 动机

传统策略无法适应负载阶段切换（phase change）与流式/阻塞混合模式。学习型策略用"过去预测未来"：

| 策略 | 年份/会议 | 核心方法 | 成果 |
|------|:---:|---------|------|
| Hawkeye | ISCA 2018 | 基于访存历史预测"行是否值得缓存"，近似 Belady | 超越所有传统策略 |
| Parrot | 2021 | 模仿学习监督神经网络，模仿 Belady 决策 | SPEC 命中率最高 +16% |
| LSTM-CRP | 2025 | LSTM 把访问模式分 4 类（FRI/TRA/STR/MIX），各配 3 位 RRPV 预测器 | 统一网络不靠谱（<60% 准确率），分模式才有效 |
| PACIPV | **ISCA'25** | 预取感知的粗粒度插入/提升向量（IPV），约 12KB 硬件 | 指令密集负载提速 3.3%，持平 127KB 的 Mockingjay |

### 5.2 PACIPV 亮点解读（ISCA'25）

- 对 demand 访问与 prefetch 访问**分别**配置插入/提升向量——预取污染是指令缓存的顽疾
- 硬件开销仅 ~12KB，而 SOTA 的 Mockingjay 要 127.62KB
- 不依赖 PC 值，规避了 SHiP/SDBP 在指令负载上的失效

### 5.3 工程现实：学得动，装不下

| 障碍 | 说明 |
|------|------|
| 存储开销 | 神经权重无法塞进 L1/L2 的替换电路 |
| 训练时机 | 离线训练无法覆盖在线负载分布 |
| 硬件验证 | 学习型策略难形式化验证，认证成本高 |

> 💡 **2025 行业共识**：工业界短期仍以 pseudo-LRU + RRIP 变体为主；学习型策略的价值在于两类结合——把"学到的模式"编译成小型查表/计数器电路（如 PACIPV 的向量搜索），而非在芯片上跑神经网络。

## 6. 预取与替换的协同

### 6.1 为什么必须协同

预取器提前把数据搬入缓存（掩盖 DRAM 延迟），但**预取也消耗容量、污染替换决策**。协同设计是 2025 年热点（PACIPV 即为预取感知设计）。

### 6.2 常见预取器

| 预取器 | 原理 | 场景 |
|--------|------|------|
| Stream（流式） | 检测顺序访问，提前取下一行 | 数组遍历 |
| Stride（步长） | 学习固定步长模式 | 矩阵、结构体数组 |
| TLB 预取 | 预取页表项 | 大页访问 |
| 指令预取 | EIP（Entangling Instruction Prefetcher）等 | 分支目标链 |

### 6.3 协同原则

- 预取行插入 RRPV=2/3（低优先级），避免驱逐 demand 行——"预取只占便宜不添乱"
- 预取置信度低时停止（误预取浪费带宽）
- 预取与替换共同作用于缺失率：预取治"强制缺失"，替换治"容量/冲突缺失"

## 7. 边界与异常场景

| 场景 | 行为 | 设计含义 |
|------|------|---------|
| 驱逐时行正在被预取填充 | 填充方先完成，后驱逐 | 协议顺序保证，MSHR 协调 |
| 同一组多行同时 Dirty | 一次驱逐一个，回写缓冲排队 | 写密集时回写带宽瓶颈 |
| 替换目标恰好是"锁存行"（L1D 部分行锁定） | 锁定行不可驱逐 | 实时系统的确定性问题 |
| 自修改代码（JIT） | 指令缓存需按缓存行失效（`clflush`/`ICache invalidation`） | JIT 编译后的指令可见性 |
| 写入主存但缓存行已无效 | 直接穿透 | Write-Through 场景 |

> 🎯 **核心要点**：替换算法的本质是在"2 位状态"的预算内逼近 Belady 最优；从 LRU → quad-age → RRIP → 学习型，演进主线是**用更少的状态位、更准确的"重访距离"预测**。理解 RRPV 的三档插入逻辑，就理解了现代缓存行为的一半。
