## 1. 3D 堆叠缓存：AMD 3D V-Cache

### 1.1 原理

缓存容量受制于芯片面积——SRAM 占 die 面积 50%+，容量翻倍意味面积翻倍、良率暴跌。**3D 堆叠**用 TSV（硅通孔）把独立制造的 SRAM 裸片垂直叠在 CPU 裸片上：

```text
传统 2D：计算单元与 L3 挤在同一平面，L3 大 → die 大 → 良率低
3D 堆叠：计算 die 保持不变，SRAM die 单独制造后 TSV 相连
         → 总容量提升 2-3 倍，die 面积与良率不受影响
```

### 1.2 演进路线

| 产品 | 时间 | L3 配置 | 说明 |
|------|:---:|---------|------|
| Ryzen 7 5800X3D | 2022 | 32MB + 64MB 3D = 96MB | 开山之作，游戏性能飞跃 |
| Ryzen 7 7800X3D | 2023 | 32MB + 64MB = 96MB | 一代游戏神 U |
| Ryzen 9 7950X3D | 2023 | 2 × 96MB = 192MB | 双 CCD，一颗带 3D 一颗不带 |
| **Ryzen 7 9800X3D** | 2024 | 96MB（Zen 5） | 3D V-Cache 移到 CCD 下方，散热改进 |
| **Ryzen 9 9950X3D** | 2025 | **2 × 96MB = 192MB** | 双 CCD 全带 3D，频率接近非 X3D |

### 1.3 为什么 X3D 有效（实测数据）

- L3 命中延迟仅比普通 L3 略高（TSV 路径 ~10-15 周期），但**命中率大幅提升**——游戏工作集常驻 L3
- 效果等价于"免费的内存带宽 + 低延迟"：L3 带宽（TB/s 级）vs DRAM 带宽（数十 GB/s）
- 2025 实测：Zen 5 X3D 在缓存敏感负载（游戏、数据库、部分科学计算）领先同代非 X3D 10-30%

> ⚠️ 限制：3D SRAM 的功耗/散热约束曾经限制频率（5800X3D 基频低于普通版），9800X3D 通过堆叠位置改进解决了此问题。且**只有 L3 受益**，L1/L2 仍受单 die 面积限制。

### 1.4 局限与生态影响

| 局限 | 说明 |
|------|------|
| 频率约束 | 堆叠层散热差，早期 X3D 基频比普通版低 200-400MHz（已缓解） |
| 面积成本 | SRAM die 独立制造 + TSV 工艺，成本显著高于平面 L3 |
| 仅 L3 受益 | 对 L1/L2 敏感负载（短循环）无提升 |
| 收益依赖负载 | 工作集 >32MB 且 <96MB 的负载收益最大；纯流式负载无感 |

**生态影响**：X3D 让"缓存容量"重新成为 CPU 的差异化卖点，AMD 已把 3D V-Cache 引入 EPYC（Genoa-X 系列，L3 达 768MB/双路），服务器场景中数据库/内存计算负载受益显著——**缓存容量的竞争，本质是"谁能让更多数据留在片上"的竞争**。

## 2. Intel 两级数据缓存：L0 与 L1.5

### 2.1 设计动机

L1 命中延迟与容量矛盾：容量越大命中越慢。Intel Lion Cove 把数据缓存拆成两级：

| 级别 | 容量 | 相联度 | 职责 |
|------|:---:|:---:|------|
| L0D | 48KB | 12-way | 极低延迟（约 4 周期），拦截简单访问 |
| L1D（L1.5） | 192KB | 12-way | 更大容量，吸收 L0 缺失 |

### 2.2 实测行为（Chips and Cheese 2024-2025）

- **大部分 L0 缺失被 L1.5 拦截**——不少负载中 L1.5 取代 L2 成为主要数据源（如 525.x264）
- 两级之间约 3-4 周期差距，比 L0→L2 的跳变平滑得多
- 代价：L1 总容量（48+192=240KB）的 Tag 开销与面积上升；L3 延迟在 ARL 上不降反升（80+ 周期）

> 💡 设计哲学对比：AMD 用"48KB L1 + 快 L3"整体均衡；Intel 用"L0+L1.5 两级拆解"把延迟曲线拉平。两种路线在 2024-2025 同台竞技，说明**缓存层级是"延迟曲线形状"的设计问题，没有唯一解**。

## 3. 内存侧缓存（Memory-Side Cache）

### 3.1 定义

位于内存控制器与 DRAM 之间的缓存层，容量 GB 级、延迟比 DRAM 低——本质是"把一部分 DRAM 当缓存用"。

### 3.2 实例

| 平台 | 内存侧缓存 | 说明 |
|------|:---:|------|
| Lunar Lake | 8MB | 挂在内存控制器旁，E 核/SoC 访问的加速层 |
| Intel Sapphire Rapids | 部分 SKU | 用于 HBM 直连加速（近存计算） |
| NVIDIA Grace-Hopper | 数十 GB | 用 LPDDR5X 缓存 HBM 访问 |
| AMD MI300A | — | 统一内存架构，内存与 L3 协同 |

### 3.3 为什么突然流行

- 内存控制器外移（Intel 分离式 IO die）后，CPU 到 DRAM 路径变长——中间加一层缓存是"找回延迟"的工程手段
- CXL 内存扩展的配套：远端内存延迟 300ns+，本地内存侧缓存把它"洗"回 ~100ns 级
- 与 3D V-Cache 互补：**3D V-Cache 加速"数据"，内存侧缓存加速"容量"**——前者十几 MB，后者 GB 级

> ⚠️ 内存侧缓存的容量开销：用 DRAM 做缓存意味着内存总容量打折（8MB 缓存通常需 128MB+ DRAM 池），且标签表管理复杂——只在内存带宽/延迟是瓶颈的平台有价值。

## 4. CXL 与缓存层次的扩展

### 4.1 CXL 的三种设备类型

| 类型 | 定义 | 缓存语义 |
|------|------|---------|
| Type 1 | 缓存设备（智能网卡等） | 只缓存，无主存 |
| Type 2 | 内存+加速器（GPU 等） | 缓存 + 自有内存，与主机一致 |
| Type 3 | 纯内存扩展 | 无缓存，仅扩展容量 |

### 4.2 CXL 对缓存架构的影响

```
传统：缓存层次 = CPU 核内 L1/L2/L3 + DRAM（单机闭合系统）
CXL 时代：缓存域跨越设备边界
  - Type 2 设备（GPU/加速器）通过 CXL.cache 加入主机一致性域
  - 远端内存 + 本地缓存组合 → 分级缓存体系延伸到整机柜
  - 2025-2026 研究（HPCA'26 C3）：不同协议簇（MESI/MOESI/MESIF）经 CXL 互连
```

### 4.3 一致性协议研究前沿（2025）

| 成果 | 出处 | 要点 |
|------|------|------|
| 两级层次目录 | J-STAGE 2025 | 芯片级：芯粒内目录 + I/O die 目录，目录开销 O(N²)→O(n²+) |
| CORD | ISCA 2025 | 目录侧为直写定序，性能 +24%、流量 −13% |
| C3 | HPCA'26 | CXL 一致性控制器，异构协议簇互联验证 |

## 5. GPU 与加速器缓存

### 5.1 GPU 缓存层次（NVIDIA/AMD）

| 层次 | 说明 |
|------|------|
| SM/LDS（共享内存） | 可编程 Scratchpad，替代 L1 的角色（CUDA 手动管理） |
| L1 缓存 | 每 SM 私有，纹理/常量路径 |
| L2 缓存 | 全 GPU 共享，**一致性+带宽枢纽**，H100 达 50MB |
| Infinity Cache（AMD） | L3 级大容量内存侧缓存，MI300X 256MB、RX 7900 XTX 96MB |

### 5.2 GPU 与 CPU 缓存哲学差异

| 维度 | CPU | GPU |
|------|-----|-----|
| 目标 | 低延迟（单线程敏感） | 高带宽（吞吐优先） |
| 容量 | 每核 L1 几十 KB | L1 每 SM 几十 KB，但 L2 数十 MB |
| 一致性 | 硬件强制（MESI） | 软件同步（global memory fence）为主 |
| 局部性控制 | 隐式（自动预取） | **显式**（共享内存、纹理缓存手动管理） |

> 💡 深度学习训练（Attention 计算）高度依赖缓存优化：算子融合（FlashAttention 把中间结果留在寄存器/SMEM，不落 HBM）本质就是**把缓存局部性做到极致**——理解 CPU Cache 的人学 GPU 优化事半功倍。

### 5.3 GPU 缓存设计要点（与 CPU 对照）

| 设计点 | CPU 做法 | GPU 做法 |
|--------|---------|---------|
| 行大小 | 64B 统一 | 32B 分段（sector），细粒度传输 |
| 替换 | 硬件近似 LRU/RRIP | 常用 LRU + 软件提示（`evict_first`/`persisting`） |
| 一致性 | MESI/MOESI 硬件 | 软件栅栏 + L2 原子操作 |
| 调试 | perf/Linux | Nsight Compute 的 cache 命中分析器 |

NVIDIA 从 Ampere 起为 L2 增加"持久化访问（persisting）"提示，让热点张量钉在 L2——这与 CPU 的"锁存行"思想同源，说明**显式缓存控制正在从 CPU 特殊场景走向 GPU 常规手段**。

## 6. 未来方向

### 6.1 可见的趋势（2025-2026 检索）

| 方向 | 内容 | 挑战 |
|------|------|------|
| 学习型缓存 | 替换/预取策略引入轻量学习电路（PACIPV 12KB 已验证） | 硬件开销与验证 |
| 更大 3D 缓存 | X3D 向服务器/EPYC 全面普及，容量向 1GB+ 演进 | 散热、良率 |
| CXL 分层内存 | 内存侧缓存 + 远端内存的分级体系成为服务器标配 | 一致性语义、延迟 |
| 缓存感知编译 | 编译器自动分块/布局（如 Polly、JIT 循环优化） | 编译时间 |
| 安全化缓存 | 推测路径不污染（Pre-cache 类设计）成为新核心默认 | 性能损失控制 |

### 6.2 对学习者的建议

```
① 数字会过期，原理不会：2026 年再查 Zen 5 延迟会发现新架构，
   但 MESI/局部性/AMAT 模型永远适用
② 三个数字要记牢：64B 行、L1 ~1ns、DRAM ~100ns（数量级比精确值重要）
③ 动手验证：perf / 微基准观察缓存效应（矩阵分块前后对比）
④ 交叉视角：把缓存思想带进 Redis/数据库/JVM 的理解中
```

> 🎯 **核心要点**：缓存技术的 2024-2026 主线是"容量往上堆（3D/CXL）、延迟往下压（L0/L1.5/内存侧缓存）、决策智能化（学习型替换）"。但所有演进都围绕同一个赌局——用局部性把存储墙平均化。
