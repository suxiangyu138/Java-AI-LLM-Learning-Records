## 1. 信息的二进制本质

计算机中所有信息（数值、字符、图像、指令等）最终都以**二进制**（0 和 1）形式存储和传输。

| 概念 | 说明 |
|------|------|
| **二进制** | "逢二进一"的记数系统，由 0 和 1 两个数字组成 |
| **高电平 / 低电平** | 电路中的 1 和 0，对应不同的电压状态 |
| **位模式** | 二进制位的组合可以表示任何类型的信息 |

### 1.1 常用数制

| 数制 | 基数 | 后缀 | 说明 |
|------|------|------|------|
| **十进制** | 10 | D | 按权展开求和 |
| **二进制** | 2 | B | 逢二进一 |
| **八进制** | 8 | O | 每 3 位二进制对应 1 位八进制 |
| **十六进制** | 16 | H | 每 4 位二进制对应 1 位十六进制 |

```java
// Java 进制转换
Integer.toBinaryString(42);    // "101010"
Integer.toHexString(255);      // "ff"
Integer.parseInt("1010", 2);   // 10
Integer.parseInt("ff", 16);    // 255
```

## 2. 比特、字节与字长

| 概念 | 定义 | 说明 |
|------|------|------|
| **比特（bit）** | 最小的信息单位，0 或 1 | 对应电路的高电平和低电平 |
| **字节（Byte）** | 最小可寻址存储单位，8 比特 | 可表示 0\sim255（无符号）或 -128\sim127（有符号） |
| **字长（Word Size）** | CPU 一次能处理的二进制数据位数 | 决定寻址能力和数据处理效率 |

> 💡 现代计算机多为 64 位字长，但仍兼容 32 位程序，其核心差异在于"可处理的数据范围"和"寻址能力"。64 位系统最大可寻址 2^64 字节（约 16EB），远超 32 位的 4GB。

### 2.1 Java 基本数据类型

| 类型 | 位数 | 取值范围 |
|------|------|---------|
| `byte` | 8 | [-128, 127] |
| `short` | 16 | [-32768, 32767] |
| `int` | 32 | [-2^31, 2^31-1] |
| `long` | 64 | [-2^63, 2^63-1] |
| `float` | 32（IEEE 754） | 单精度浮点数 |
| `double` | 64（IEEE 754） | 双精度浮点数 |

## 3. 字节序：大端与小端

当信息占用多个字节时，字节在内存中的存储顺序有两种方式：

| 字节序 | 存储方式 | 示例（0x12345678） |
|--------|----------|-------------------|
| **大端（Big-Endian）** | 高位字节存低地址，低位字节存高地址 | 低地址存 `0x12`，高地址存 `0x78` |
| **小端（Little-Endian）** | 低位字节存低地址，高位字节存高地址 | 低地址存 `0x78`，高地址存 `0x12` |

> ⚠️ **核心结论**：x86 架构采用小端存储，ARM 架构可切换，网络传输默认采用大端字节序。跨平台传输多字节数据时，必须进行字节序转换（如 `htonl`、`htons`）。

```c
#include <arpa/inet.h>
uint32_t net_long = htonl(host_long);  // 主机字节序 → 网络字节序
uint32_t host_long = ntohl(net_long);  // 网络字节序 → 主机字节序
```

## 4. 整数的表示

### 4.1 机器数与真值

- **机器数**：计算机中表示的二进制数，符号数字化（0 表示正，1 表示负）
- **机器数形式**：原码、反码、补码、移码
- **真值**：机器数对应的实际数值

### 4.2 原码、反码、补码、移码

| 编码 | 正数 | 负数 | 特点 |
|------|------|------|------|
| **原码** | 符号位 0 + 数值位 | 符号位 1 + 数值位 | 存在两个零（+0 和 -0），减法运算复杂 |
| **反码** | 与原码相同 | 符号位不变，其余位取反 | 同样存在两个零 |
| **补码** | 与原码相同 | 反码 + 1 | **只有一个零**，减法可转换为加法，最常用 |
| **移码** | 补码的符号位取反 | 补码的符号位取反 | 常用于浮点数的阶码比较 |

### 4.3 补码的核心优势

| 优势 | 说明 |
|------|------|
| **消除 0 的二义性** | 补码中 0 只有一种表示（00000000） |
| **减法统一为加法** | `5 - 3 = 5 + (-3)`，无需单独设计减法电路 |
| **取值范围更合理** | n 比特补码范围为 -2^(n-1) ~ 2^(n-1) - 1 |

### 4.4 无符号数与有符号数

| 类型 | n 比特取值范围 | 说明 |
|------|---------------|------|
| **无符号数** | 0 ~ 2^n - 1 | 仅表示非负整数 |
| **有符号数（补码）** | -2^(n-1) ~ 2^(n-1) - 1 | 最高位为符号位 |

### 4.5 无符号数与有符号数的转换陷阱

```c
// 32 位系统中，unsigned int 和 int 混合运算
unsigned int u = 10;
int i = -20;
if (u + i > 0) {
    printf("正\n");  // 实际输出：正
}
```

> ⚠️ **原因解析**：`-20` 的补码为 `0xFFFFFFEC`，转换为无符号数后为 4294967276，`u + i = 10 + 4294967276 = 4294967286`，因此输出"正"。**C 语言中无符号数与有符号数混合运算时，有符号数会被隐式转换为无符号数。**

## 5. 整数的运算

### 5.1 运算的底层实现

| 运算 | 底层实现 | 效率 |
|------|---------|------|
| **加减法** | 二进制按位运算，减法用补码加法实现 | 最快 |
| **乘法** | 移位 + 加法 | 中等 |
| **除法** | 移位 + 减法，涉及取整与余数 | 最慢 |

### 5.2 溢出

| 溢出类型 | 处理方式 | 示例 |
|----------|----------|------|
| **无符号数溢出** | 采用"模运算"，结果对 2^n 取模 | 8 比特无符号数 300 -> 300 - 256 = 44 |
| **有符号数溢出** | 结果"失真"，计算机不会主动提示 | `int` 最大值 2147483647 + 1 = -2147483648 |

> ⚠️ **有符号数溢出在 C 语言中是未定义行为**。Java 中可通过 `Math.addExact()`、`Math.multiplyExact()` 在溢出时抛异常。

```java
// Java 防护方案
int safeAdd = Math.addExact(a, b);       // 溢出时抛 ArithmeticException
int safeMul = Math.multiplyExact(a, b);  // 溢出时抛 ArithmeticException
```

### 5.3 截断（Truncation）

截断是指"将高位比特丢弃，保留低位比特"，发生在将高位数据类型转换为低位数据类型时：

```c
int x = 0x12345678;
char c = (char)x;  // 丢弃高 24 位，保留低 8 位 0x78
```

### 5.4 取模运算

取模运算应用广泛：哈希分片、奇偶判断、循环计数。

> 💡 模数为 2 的幂时，位运算效率更高：`n % 8` 等价于 `n & 7`。

## 6. 浮点数的表示与处理

### 6.1 IEEE 754 标准

IEEE 754 标准将浮点数表示为 **"符号位 + 阶码 + 尾码"** 三部分：

| 类型 | 符号位（S） | 阶码（E） | 尾码（M） | 总比特数 |
|------|-------------|-----------|-----------|----------|
| **单精度（float）** | 1 位 | 8 位（偏移量 127） | 23 位 | 32 位 |
| **双精度（double）** | 1 位 | 11 位（偏移量 1023） | 52 位 | 64 位 |

**真值计算公式**：
```
V = (-1)^S × (1 + M) × 2^(E - Bias)
```

### 6.2 浮点数的分类

| 类别 | 阶码 E | 说明 |
|------|--------|------|
| **规格化浮点数** | 1 ~ 2^(n) - 2 | 最常用，尾码隐含整数部分 1 |
| **非规格化浮点数** | 0 | 用于表示接近 0 的小数 |
| **特殊值** | 全为 1 | 无穷大或 NaN（非数字） |

### 6.3 精度损失

> ⚠️ 浮点数无法精确表示所有实数，尤其是十进制小数。根源是"二进制无法精确表示某些十进制分数"（如 0.1 是无限循环二进制小数）。

```java
// 错误写法：直接判断浮点数相等
if (0.1 + 0.2 == 0.3) { }  // 实际结果为 false

// 正确写法：判断差值小于极小值
if (Math.abs(0.1 + 0.2 - 0.3) < 1e-6) { }  // 结果为 true
```

### 6.4 Java 精度解决方案

| 方案 | 方法 | 适用场景 |
|------|------|---------|
| **BigDecimal** | `new BigDecimal("0.1")` | 金融场景，需精确十进制运算 |
| **整数化运算** | 金额单位"元"改"分"，用 `long` 存储 | 高性能金融计算 |
| **误差容忍比较** | `Math.abs(a - b) < epsilon` | 普通浮点数场景 |

```java
// BigDecimal 正确保造
BigDecimal num1 = new BigDecimal("0.1");  // 必须使用 String 构造
BigDecimal num2 = new BigDecimal("0.2");
BigDecimal sum = num1.add(num2);          // 精确结果 0.3
```

## 7. 位运算

### 7.1 基本运算

| 运算 | 规则 | 用途 |
|------|------|------|
| 按位与（`&`） | 同位均为 1 则为 1 | 清零、取指定位、判断奇偶 |
| 按位或（`\|`） | 同位有 1 则为 1 | 设置指定位、权限组合 |
| 按位异或（`^`） | 同位不同则为 1 | 交换变量、加密、去重 |
| 按位取反（`~`） | 0 变 1，1 变 0 | 取反码、生成掩码 |
| 左移（`<<`） | 低位补 0，等价于 ×2^n | 快速乘法 |
| 右移（`>>`） | 带符号右移，高位补符号位 | 快速除法 |
| 无符号右移（`>>>`） | 高位补 0 | 数据分片 |

### 7.2 Java 后端实战应用

**权限管理：**

```java
int READ  = 1 << 0;  // 0001
int WRITE = 1 << 1;  // 0010
int perm  = READ | WRITE;            // 赋予读写权限
boolean hasWrite = (perm & WRITE) != 0;  // 判断权限
```

**高性能判断：**

```java
// 判断 2 的幂
boolean isPowerOfTwo = n > 0 && (n & (n - 1)) == 0;

// Redis 槽位计算
int slot = crc16(key) & 16383;

// 取模优化（模数为 2 的幂）
int idx = hash & (capacity - 1);  // 等价于 hash % capacity
```

## 8. 字符与字符串的编码

### 8.1 ASCII 编码

ASCII 编码是最早的字符编码，采用 7 比特表示，共 128 个字符：

| 范围 | 类型 | 示例 |
|------|------|------|
| 0~31 | 控制字符 | 换行（10）、回车（13） |
| 32~126 | 可打印字符 | `'A'`=65，`'a'`=97，`'0'`=48 |

### 8.2 Unicode 与 UTF-8

Unicode 为每个字符分配唯一的数值（码点），范围 0~0x10FFFF。

UTF-8 是 Unicode 的可变长度编码，兼容 ASCII：

| 字节数 | 格式 | 码点范围 |
|--------|------|----------|
| 1 字节 | `0xxxxxxx` | 0~127（ASCII） |
| 2 字节 | `110xxxxx 10xxxxxx` | 128~2047 |
| 3 字节 | `1110xxxx 10xxxxxx 10xxxxxx` | 2048~65535 |
| 4 字节 | `11110xxx 10xxxxxx 10xxxxxx 10xxxxxx` | 65536~0x10FFFF |

> 💡 UTF-8 按需分配字节，英文字母占用 1 字节，中文占用 3 字节，兼容 ASCII，跨语言、跨平台兼容性好。

## 9. Java 后端实战指南

### 9.1 核心避坑清单

| 陷阱 | 说明 | 解决方案 |
|------|------|---------|
| **整数溢出** | `int` 最大值 + 1 变为最小值 | 使用 `Math.addExact()` 或 `long` |
| **浮点精度** | `0.1 + 0.2 != 0.3` | 使用 `BigDecimal` 或整数化 |
| **无符号混合** | 有符号与无符号混合运算结果异常 | 手动类型转换，避免隐式转换 |
| **字节序问题** | 跨平台数据传输乱码 | 统一使用网络字节序（大端） |
| **编码问题** | 中文乱码 | 统一使用 UTF-8 编码 |

### 9.2 性能优化建议

| 优化 | 说明 |
|------|------|
| 优先整数组运算 | 位运算 > 整数运算 > 浮点运算 > BigDecimal |
| 使用位运算替代乘除 | `n * 2` → `n << 1`，`n / 2` → `n >> 1` |
| 高并发计数 | 优先 `LongAdder`，其次 `AtomicLong` |
| 浮点数比较 | 使用误差容忍方式，而非 `==` |

## 10. 总结

> 🎯 **核心价值**：揭示"高级语言中的数据，在计算机底层如何以二进制形式存在、运算和转换"，打破高级语言抽象，让开发者理解数据在计算机底层的真实面貌。

| 核心要点 | 说明 |
|---------|------|
| **二进制本质** | 所有信息最终以二进制形式存储和传输 |
| **补码** | 现代计算机统一采用补码表示有符号整数 |
| **IEEE 754** | 浮点数的国际标准，存在精度损失 |
| **字节序** | 小端（x86）与大端（网络）需注意转换 |
| **UTF-8** | 跨平台编码的最佳实践 |

> 💡 **实践原则**：避免混合运算、警惕溢出、浮点数不直接比较、跨平台统一字节序、明确编码。
