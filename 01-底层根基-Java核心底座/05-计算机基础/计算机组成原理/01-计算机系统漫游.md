## 1. 计算机系统的核心定义与分层架构

计算机系统是由**硬件和软件**组成的一个有机整体，二者协同工作，共同完成程序的执行。

### 1.1 核心分层架构

| 层次 | 核心组件 | 核心职责 |
|------|----------|----------|
| **硬件层** | CPU、内存（DRAM）、磁盘、I/O 设备 | 程序执行的物理载体 |
| **操作系统层** | 内核、驱动、系统调用接口 | 管理硬件资源，为应用提供统一接口 |
| **应用程序层** | 应用程序、编译器、Shell 等 | 完成具体业务逻辑 |

### 1.2 性能指标

| 指标 | 说明 |
|------|------|
| **字长** | CPU 一次能处理的二进制数据位数（决定寻址能力） |
| **主频** | CPU 的时钟频率（Hz） |
| **运算速度** | MIPS（每秒百万条指令）、FLOPS（每秒浮点运算次数） |
| **存储容量** | 主存容量（GB）、辅存容量（TB） |
| **存取周期** | 存储器完成一次读/写操作所需的时间 |

> 💡 **系统级思维**：任何软件操作最终都会转化为硬件指令。理解从应用到硬件的完整链路，是定位性能问题的关键。

## 2. 冯·诺依曼体系结构

冯·诺依曼体系结构是现代计算机的设计基础，由美籍匈牙利数学家冯·诺依曼于 1946 年提出。

### 2.1 五大核心思想

| 思想 | 说明 |
|------|------|
| **五大基本部件** | 运算器、控制器、存储器、输入设备、输出设备 |
| **二进制表示** | 数据和指令均采用二进制形式 |
| **存储程序原理** | 程序和数据存放在同一存储器中，按地址访问 |
| **顺序执行** | 指令按程序计数器（PC）的指向依次读取执行 |
| **以存储器为中心** | 现代计算机已优化为以存储器为中心 |

### 2.2 五大部件与 Java 后端的映射

| 五大部件 | 硬件对应 | Java 后端对应 |
|---------|---------|--------------|
| **存储器** | 内存（RAM）、硬盘 | JVM 堆内存、栈内存、方法区 |
| **运算器** | CPU 的 ALU | 数值计算、条件判断、循环逻辑 |
| **控制器** | CPU 的控制单元（CU） | JVM 执行引擎、操作系统调度器 |
| **输入设备** | 键盘、鼠标、网卡 | HTTP/RPC 请求、数据库查询、消息队列消费 |
| **输出设备** | 显示器、打印机、网卡 | 响应数据返回、数据库写入、消息队列发送 |

> 🎯 **核心洞察**：存储程序原理是 Java 后端开发的核心底层逻辑。Java 源代码经 `javac` 编译为字节码，JVM 将字节码加载到内存，执行引擎从内存中读取并执行指令，这一过程完全遵循冯·诺依曼的"程序存储、自动执行"思想。

## 3. 程序的生命周期：从 hello.c 到输出

以 `hello.c` 程序为例，其完整生命周期如下：

```
源代码（hello.c）→ 编译系统 → 可执行文件（hello）
→ Shell 加载运行 → CPU 执行 → 操作系统调度 I/O → 屏幕输出 → 程序终止
```

### 3.1 各环节概览

| 环节 | 核心操作 | 主导者 |
|------|---------|--------|
| **源代码编写** | 编写 C 语言代码，字符以 ASCII 编码存储 | 程序员 |
| **编译阶段** | 预处理 → 编译 → 汇编 → 链接 | 编译系统（cpp、cc1、as、ld） |
| **加载阶段** | 将可执行文件从磁盘读入内存 | 操作系统加载器 |
| **运行阶段** | CPU 取指译码执行，操作系统调度资源 | CPU + 操作系统 |
| **I/O 操作** | 调用系统调用驱动设备输出结果 | 操作系统 + 设备驱动 |
| **程序终止** | 回收资源，返回退出状态 | 操作系统 |

### 3.2 关键理解

> ⚠️ 源代码本身不具备执行能力，它只是"指令的描述"，必须经过编译、链接，才能转化为可执行程序。CPU 只能执行内存中的机器指令，不能直接执行源代码或可执行文件。

## 4. 编译系统：预处理、编译、汇编、链接

编译过程并非一步完成，而是分为 **4 个阶段**：

| 阶段 | 工具 | 输入 | 输出 | 核心工作 |
|------|------|------|------|----------|
| **预处理** | `cpp` | `hello.c` | `hello.i` | 处理 `#include`、`#define` 等预处理指令 |
| **编译** | `cc1` | `hello.i` | `hello.s` | 将源代码转化为汇编语言代码 |
| **汇编** | `as` | `hello.s` | `hello.o` | 将汇编代码转化为机器语言指令（目标文件） |
| **链接** | `ld` | `hello.o` + 库文件 | `hello` | 合并目标文件与库文件，生成可执行文件 |

> 💡 链接的核心作用是解决"外部依赖"问题——几乎所有应用程序都需要依赖系统库或第三方库，链接器将这些分散的目标文件整合为一个完整的可执行二进制文件。

### 4.1 编译阶段详解

**预处理阶段**：
- 展开 `#include` 头文件
- 替换 `#define` 宏定义
- 删除注释
- 处理条件编译指令

**编译阶段**：
- 词法分析、语法分析、语义分析
- 生成中间代码
- 优化代码
- 最终生成汇编代码

**汇编阶段**：
- 将汇编代码翻译为机器指令
- 生成可重定位目标文件（`.o`）

**链接阶段**：
- 符号解析：将符号引用与符号定义关联
- 重定位：将相对地址修正为绝对地址

## 5. 程序的加载与运行

### 5.1 加载过程

当在 Shell 中输入 `./hello` 执行可执行文件时：

1. Shell 进程调用 `fork()` 系统调用，创建新的子进程
2. 子进程调用 `execve()` 系统调用，请求操作系统加载可执行文件
3. 操作系统的**加载器**将文件从磁盘读取到内存中，分配内存空间
4. 加载完成后，操作系统将 CPU 的控制权交给新进程

### 5.2 运行过程

1. CPU 从内存的代码段中取出第一条机器指令
2. CPU 对指令进行译码
3. CPU 执行指令，调用系统调用完成输出
4. 操作系统调度显示器设备，将字符串输出到屏幕上

> ⚠️ **关键细节**：内存是"临时存储介质"，速度介于 CPU 和磁盘之间——CPU 无法直接访问磁盘，必须通过内存中转。CPU 的执行权由操作系统调度，并非程序直接控制。

### 5.3 I/O 操作

`hello` 程序的核心功能是"打印字符串"，这属于 I/O 操作：

1. 程序调用 `printf` 函数（库函数），内部调用 `write` 系统调用
2. 操作系统接收系统调用后，调用显示器的设备驱动程序
3. 设备驱动程序将字符串转化为显示器能识别的信号

### 5.4 程序终止

当程序执行到 `return 0` 时，操作系统会执行资源回收：
- 回收程序占用的内存资源
- 关闭程序打开的所有 I/O 设备
- 将退出状态返回给 Shell 进程

## 6. 操作系统的核心抽象

### 6.1 四大抽象

| 抽象 | 本质 | 作用 |
|------|------|------|
| **文件** | 对 I/O 设备的抽象 | 统一接口操作所有设备 |
| **虚拟内存** | 对主存和磁盘的抽象 | 每个进程拥有独立的地址空间 |
| **进程** | 对 CPU、内存、I/O 的抽象 | 多个程序同时运行 |
| **虚拟机** | 对整个计算机的抽象 | 操作系统 + 应用程序 |

### 6.2 系统调用

系统调用是操作系统提供给应用程序的接口，是用户态进入内核态的唯一通道：

| 类别 | 系统调用示例 | Java 对应 |
|------|-------------|-----------|
| 进程控制 | `fork`、`execve`、`exit` | `Runtime.exec()` |
| 文件操作 | `open`、`read`、`write`、`close` | `FileInputStream` |
| 设备管理 | `ioctl` | NIO |
| 信息维护 | `getpid`、`alarm` | `Thread.sleep()` |
| 通信 | `pipe`、`shmget`、`mmap` | `Socket` |

## 7. Amdahl 定律与性能度量

### 7.1 Amdahl 定律

**Amdahl 定律**：系统某部分加速后，整体性能提升受限于该部分在总执行时间中的占比。

```
加速比 = 1 / ((1 - 可优化比例) + 可优化比例 / 优化倍数)
```

> 💡 **核心启示**：优先优化占用执行时间最长的部分（二八定律——20% 的代码占用 80% 的执行时间）。

### 7.2 性能度量指标

| 指标 | 公式 | 说明 |
|------|------|------|
| **吞吐量** | 任务数 / 时间 | 单位时间完成任务数 |
| **响应时间** | 完成时间 - 开始时间 | 用户感知延迟 |
| **加速比** | T_old / T_new | 优化效果衡量 |
| **效率** | 加速比 / 处理器数 | 资源利用率 |

## 8. 计算机系统的层次结构

### 8.1 经典七层模型

```
第 7 层 — 应用层（业务代码、微服务、API、分布式系统）
第 6 层 — 库函数层（Java 标准库、Spring、MyBatis、Netty）
第 5 层 — 虚拟机层（JVM：类加载、运行时数据区、GC）
第 4 层 — 操作系统层（进程/线程、虚拟内存、系统调用）
第 3 层 — 指令集架构层（x86-64/ARM/RISC-V）← 软硬件分界线
第 2 层 — 微体系结构层（CPU 流水线、Cache、总线协议）
第 1 层 — 数字逻辑层（门电路、触发器、ALU、寄存器）
```

### 8.2 核心价值

| 原则 | 说明 |
|------|------|
| **抽象隐藏细节** | 每层只暴露接口，隐藏实现细节 |
| **分层解耦** | 层间变化互不影响 |
| **标准化接口** | ISA 是软硬件之间的契约 |

> 🎯 理解该层次结构，是定位性能问题（慢 SQL、GC 停顿、上下文切换、I/O 阻塞）的关键。所有性能问题最终都能追溯到某一层的具体瓶颈。

## 9. 总结

**计算机系统漫游**的核心价值在于建立**系统级思维**——理解计算机系统不是孤立的硬件和软件的堆砌，而是一个有机的整体。

| 核心要点 | 说明 |
|---------|------|
| **程序生命周期** | 源代码 → 编译 → 加载 → 执行 → 终止，每个环节都涉及系统不同层级的协同工作 |
| **编译的 4 个阶段** | 预处理、编译、汇编、链接，每个阶段由不同工具完成 |
| **操作系统的抽象** | 文件、虚拟内存、进程、虚拟机，屏蔽硬件复杂性 |
| **系统级思维** | 任何软件操作最终都会转化为硬件指令，理解底层才能写出高效代码 |

> 🎯 **一句话总结**：计算机系统漫游以程序执行为主线，串联起硬件、操作系统、编译器、链接器等核心组件，帮助开发者建立从代码到硬件的全链路认知。
