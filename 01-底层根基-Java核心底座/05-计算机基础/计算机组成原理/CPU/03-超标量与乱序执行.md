## 1. 超标量：多路并行流水线

### 1.1 定义

**超标量（Superscalar）**：每周期发射（issue）多条指令到多个执行单元——多条流水线并行工作。

```
标量（1 路）：每周期最多完成 1 条指令
超标量（4 路）：每周期最多完成 4 条指令
```

### 1.2 发射宽度（Issue Width）演进

| 核心 | 发射宽度（近似） | 说明 |
|------|:---:|------|
| 1990s Pentium | 2 | 双 ALU |
| 2000s 酷睿系 | 4 | 4 发射 |
| Zen 4/5 | 8（6 整数 + 更多） | 6 ALU + 4 FP 等 |
| Lion Cove | 8+ | 宽发射极致 |
| Apple M 系 | 8-10 | 移动端最高发射宽度 |

> 💡 发射宽度是"纸面并行度上限"，实际受指令依赖与前端供给限制——IPC 很少达到宽度值。

### 1.3 宽度 vs 深度的本质

```
深度（流水线）：把一条指令拆得更细 → 提频率
宽度（超标量）：同时跑多条指令 → 提吞吐
现代核心两者兼有：20+ 级 × 6-10 宽
```

## 2. 乱序执行的核心架构

### 2.1 动机：依赖挡路，乱序绕行

```asm
mul r1, r2, r2     ; 慢运算：5 周期
add r3, r4, r5     ; 与 r1 无关 —— 凭什么等 mul？
sub r6, r7, r8     ; 也无依赖 —— 也可以先做
```

按序执行：add/sub 白等 mul 5 个周期。乱序执行：add/sub 先做完，mul 完成后再提交——**吞吐翻倍而不改变结果**。

### 2.2 乱序执行五件套

| 组件 | 作用 | 详见 |
|------|------|------|
| 重命名表 (RAT) | 架构寄存器 → 物理寄存器 | 寄存器/05 |
| 物理寄存器堆 (PRF) | 在飞结果的实际存储 | 寄存器/05 |
| 重排序缓冲 (ROB) | 按序提交与异常回滚 | 寄存器/05 |
| 调度器 (Scheduler) | 按"操作数就绪"选择发射 | 本节 |
| 保留站 (Reservation Station) | 等待操作数的指令队列 | 本节 |

### 2.3 一条指令的乱序旅程

```text
译码 → 重命名（拿物理寄存器）→ 进入调度器等待
   → 所有操作数就绪 + 执行单元空闲 → 发射执行
   → 结果写 PRF，置就绪位
   → ROB 按序提交（即使执行完成早，提交仍按程序顺序）
```

**乱序执行 ≠ 乱序提交**：执行可乱，提交必须按序——这是"精确异常"（程序在任意点可中断/回滚）的保证。

### 2.4 乱序窗口与规模

```
乱序窗口（OoO Window）：同时"在飞"的指令数
  2000s 核心：~100 条
  现代核心：300-500+ 条（Zen 5 调度器队列、Lion Cove 的 ROB 均超 500）

窗口越大：隐藏延迟的能力越强（load 等待 500 周期也能被"填满"）
窗口代价：PRF 面积、调度器功耗（每周期全扫描）、设计复杂度
```

> 🎯 关键认识：乱序执行把"数据依赖"之外的所有延迟都藏进了窗口——现代 CPU 单线程性能的秘密一半在这里，另一半在分支预测。

## 3. 执行单元集群

### 3.1 现代核心的执行单元配置（以 Zen 5 为参照）

| 单元类型 | 数量 | 说明 |
|---------|:---:|------|
| 整数 ALU | 6 | 加/逻辑/移位 |
| 整数乘法 | 1-2 | 部分与 ALU 复用 |
| 分支单元 | 2-3 | 解析预测、快速提交 |
| 加载单元 | 3-4 | 发起 load（含地址计算） |
| 存储单元 | 2-3 | 处理 store |
| 浮点/FMA | 4 | 128 位 FMA ×4 = 向量 512 位 |
| 除/平方根 | 1-2 | 慢操作，几十周期 |

### 3.2 集群化设计（Cluster）

```
现代核心常把执行单元分为两组（Cluster）：
  Cluster 0：ALU0-2 + Branch + Load0-1
  Cluster 1：ALU3-5 + Store + Load2-3
每组有自己的调度器 → 指令派发到哪组由译码/分派阶段决定

好处：每组调度器变小（功耗/延迟下降）
代价：跨组数据传递需要额外周期（转发路径变长）
```

### 3.3 旁路网络（Bypass Network）

```
结果直送 vs 写回再读：
  直送（旁路）：+0-1 周期（多数 RAW 冒险）
  写回再读：+3-5 周期（旁路没覆盖的远程依赖）
→ 执行单元间的"距离"决定旁路延迟 —— 集群布局就是旁路拓扑设计
```

## 4. 前端：指令供给的瓶颈

### 4.1 前端管线

```text
分支预测 → 取指（32B+ 宽）→ 预译码 → 指令队列 → 译码（4-8 宽）
            ↓
         uop cache（微操作缓存）：已译码指令缓存，跳过译码
```

### 4.2 x86 的前端之痛

```
x86 指令变长（1-15 字节）：译码边界难以并行切分 → 前端瓶颈
对策（现代 x86 核心）：
  ① 预译码流水（Intel）：指令长度并行预标记
  ② uop cache：热点循环的译码结果直接复用（省译码延迟与功耗）
  ③ 译码器非对称（1 复杂 + 3 简单）：复杂指令走微码（MS-ROM）

ARM/RISC-V 定长指令 → 前端天然简单 —— 这是 RISC 的隐藏优势
```

### 4.3 前端带宽 vs 执行带宽

```
不匹配后果：执行单元饿死（前端 < 执行）或浪费（前端 > 执行）
现代核心平衡点：前端 6-10 条/周期 ≈ 执行发射 6-10 条/周期
```

## 5. SMT：超线程的取舍

### 5.1 原理：一核两线程

```
SMT（Simultaneous Multithreading）：一个物理核跑 2（或 4）个硬件线程
  共享：执行单元、缓存、分支预测器、调度器
  独立：寄存器状态（架构寄存器组 ×2）、PC、返回栈

Intel 超线程：每核 2 线程；Zen 5 服务器版：每核 2 线程
EPYC 9965：192 核 × 2 = 384 线程
```

### 5.2 收益与代价

| 维度 | 说明 |
|------|------|
| 收益 | 填满单线程留下的执行单元空闲（线程并行度 +30-40% 典型） |
| 代价 | 两线程争抢缓存/预测器（互相驱逐，单线程性能 -10-20%） |
| 安全 | SMT 是侧信道放大器（同一核共享预测器）—— 云厂商常禁用 |
| 设计 | 重命名/ROB 等核心结构要加倍或分区（面积 +5-10%） |

### 5.3 2026 的大转折：Diamond Rapids 弃用 SMT

```
Intel Diamond Rapids（Xeon 7，2026 中期）：首发版本不支持 SMT！
理由（业界分析）：核心数翻倍（192-256 核）后，
  线程密度可由物理核直接提供；SMT 的调度复杂性与安全面不值得
后续 Coral Rapids（2027-28）重新引入 SMT

启示：SMT 不是免费午餐 —— 核多到一定程度，物理核 > SMT 是正解
```

> 💡 后端视角：云厂商（AWS 等）长期禁用超线程——同一核的两线程共享缓存与预测器，既损性能隔离又放大侧信道。Java 线程池满核跑时，`Runtime.availableProcessors()` 会数到超线程（可能高估吞吐）。

## 6. 现代核心的宏观布局

### 6.1 一张全景图

```text
┌────────────────────────────────────────────────────┐
│ 分支预测 → 取指 → 译码 → uop cache → 重命名 → 调度器    │ ← 前端
├────────────────────────────────────────────────────┤
│ 调度器发射 → 执行单元集群（ALU×6 / FP×4 / LD×4 ...）   │ ← 乱序核心
│            → 旁路网络 → 结果写回 PRF                 │
├────────────────────────────────────────────────────┤
│ ROB 按序提交 → 精确异常 → 架构状态更新                 │ ← 提交
├────────────────────────────────────────────────────┤
│ L1I / L1D / 预取器 / TLB —— 与缓存子系统交互           │ ← 存储
└────────────────────────────────────────────────────┘
```

### 6.2 2025-2026 各核心的宏观参数（详见 04 模块）

| 核心 | 发射宽度 | 乱序窗口 | SMT | 特色 |
|------|:---:|:---:|:---:|------|
| AMD Zen 5 | 8 | 500+ | 2 | 快速 L3 域、6 ALU |
| Intel Lion Cove | 8-10 | 500+ | 2 | L0/L1.5 两级数据缓存 |
| ARM Cortex-X925 | 8 | — | 无（移动端） | +36% ST vs X4 |
| Apple M 系大核 | 9-10 | 600+ | 无 | 最高 IPC/瓦 |
| Neoverse V3 | 8 | — | 2 | SVE2/SME2 服务器核 |

> 🎯 **核心要点**：超标量+乱序 = "宽度 × 深度 × 聪明度"的组合拳——宽度管每周期几条、深度管藏多少延迟、预测器管分支、调度器管依赖。现代 CPU 单线程性能 = 这四者的乘积。

## 7. 小结

| 问题 | 答案 |
|------|------|
| 超标量是什么？ | 每周期发射多条指令（宽度 6-10） |
| 乱序执行改什么？ | 无依赖指令先执行；提交仍按序（精确异常） |
| 执行单元多少？ | 6 ALU + 4 FP + 4 LD + 2 ST（Zen 5 参照） |
| x86 前端痛点？ | 变长指令译码慢 → uop cache 弥补 |
| SMT 值与不值？ | 填闲时 +30%，争抢时 -20%；Diamond Rapids 先弃后复 |
