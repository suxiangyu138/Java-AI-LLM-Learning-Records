## 1. 从单 die 到 Chiplet

### 1.1 单 die 的物理困境

```
面积法则：die 越大 → 良率指数下降（缺陷密度 × 面积² 量级）
  300mm² 的良率约 50%+，600mm² 掉到 20% 以下
经济结论：超大单 die 的成本不可接受（每片废品几万美元）
```

### 1.2 Chiplet 的答案

```
把大芯片拆成多个小芯粒（chiplet），各自制造再封装：
  计算芯粒（CCD）：用最先进工艺（贵但核多）
  I/O 芯粒（IOD）：用成熟工艺（便宜，I/O 不吃先进工艺红利）
  缓存芯粒（3D V-Cache）：独立 SRAM 堆叠

收益：
  ① 良率：每个小 die 良率高 → 整体成本下降
  ② 复用：同一 CCD 可用于桌面/服务器/EPYC（产品线模块化）
  ③ 异构：不同工艺、不同功能自由组合（Intel 混合 3 种工艺于一片）
```

### 1.3 Chiplet 的代价

| 代价 | 说明 |
|------|------|
| 芯粒间延迟 | 片内互连延迟 2-4 倍于 die 内（跨 CCD 访存惩罚） |
| 带宽瓶颈 | 芯粒间带宽 << die 内带宽（Infinity Fabric 等） |
| 功耗 | 片上网络与 SerDes 功耗 |
| 测试/组装 | 复杂化，KGD（已知良好 die）测试成本 |

> ⚠️ 典型受害者：Zen 跨 CCD 访问 L3 延迟大增；Intel ARL 的内存控制器在独立 die 上导致 DRAM 延迟 565+ 周期——Chiplet 不是免费午餐，架构必须为"远距离"优化。

## 2. 芯粒间互连：环形总线 vs 网格

### 2.1 环形总线（Ring Bus）

```
所有代理（核/L3 分片/内存控制器）挂在一个环上，数据环向传递
  一跳 = 经过一个节点

Intel 桌面/移动：环形总线（Lunar Lake/ARL 均用）
  环频率 × 节点数 = 带宽（环越快、节点越多带宽越高）

优点：实现简单、延迟可预测、功耗低
缺点：节点多时环太长（一跳延迟线性上升）
  → ARL 的 L3 延迟 80+ 周期正是环扩展问题的实证
```

### 2.2 网格互连（Mesh）

```
XY 路由网格：数据先走 X 再走 Y（或最短路径）
  每跳延迟固定 → 节点多时扩展性远好于环

Intel 服务器（至强）与 AMD 部分产品：网格
  典型：56 核 × 网格 ≈ 每跳 ~10 周期

优点：扩展到 100+ 核仍可控
缺点：路径较长、需要路由逻辑
```

### 2.3 对比与演进

| 维度 | 环形总线 | 网格 |
|------|---------|------|
| 延迟 | 节点少时低（桌面 8-16 核） | 跳数固定（4-8 跳） |
| 扩展性 | 差（>16 节点恶化） | 好（100+ 核） |
| 功耗 | 低 | 中 |
| 适用 | 桌面/移动 | 服务器/大核数 |

```
2025-2026 趋势：
  Intel 桌面（Lion Cove）：仍在环 —— 并为此设计大 L2/L1.5 补偿环延迟
  Intel 服务器（至强）：网格
  AMD Zen：CCD 内私有互连 + CCD 间 Infinity Fabric（见下节）
```

## 3. AMD Infinity Fabric 与 CCD 结构

### 3.1 层级结构（Zen 5 世代）

```text
┌────────────────────────────────────────────┐
│ EPYC 9965（192 核，Turin）                  │
│  ┌────────────────────────────────────┐    │
│  │ 8 个 CCD（每个 16 核 Zen 5）          │    │
│  │  ┌────────┐ ┌────────┐ ...          │    │
│  │  │ 16 核   │ │ 16 核   │            │    │
│  │  │ 32MB L3 │ │ 32MB L3 │            │    │
│  │  └────────┘ └────────┘              │    │
│  └────────────────────────────────────┘    │
│  ┌────────────────────────────────────┐    │
│  │ IOD（I/O 芯粒）：内存控制器/PCIe/一致性│    │
│  └────────────────────────────────────┘    │
└────────────────────────────────────────────┘
```

### 3.2 Infinity Fabric 的职责

```
① CCD 内部：16 核通过片内互连共享 32MB L3（快路径）
② CCD 间：经 IOD 的 Infinity Fabric 互联（慢路径，跨 CCD 访问 L3 ~200+ 周期）
③ 内存/IO：12 通道 DDR5-6400、128 条 PCIe 5.0/CXL 2.0（Turin 实测规格）

设计要点：
  - CCD 内一致（同簇共享 L3 快）
  - CCD 间目录式一致（慢但可扩展）
  - X3D：3D 缓存挂到 CCD 上，L3 96MB/CCD 依然片内快路径
```

> 💡 为什么 9950X3D 游戏帧数高：游戏线程绑定同一 CCD 时，96MB L3 全部在"片内快路径"上——**把数据留在快域里**，是 Chiplet 时代的性能第一法则。

### 3.3 跨 CCD 的代价量化

```
同一 CCD 内：L3 ~50 周期
跨 CCD：~150-250 周期（经 IOD 往返）
跨 socket：~500+ 周期（NUMA 两级都踩）

→ 线程/数据亲和性（NUMA 绑核）决定是否踩中慢路径
→ 这是 Linux 内核自动均衡与 Java 应用的 bind 建议的底层原因
```

## 4. Intel 的分区与多 tile 设计

### 4.1 Intel 的 Chiplet 路线（2024-2026）

| 产品 | 芯粒构成 | 工艺 |
|------|---------|------|
| Arrow Lake | 计算 tile + 内存控制器 tile + GPU tile + IO tile | 混合 3 种工艺 |
| Lunar Lake | 计算 tile + 平台 tile（内存焊在板上） | TSMC + 自研 |
| Panther Lake | 多 tile，**18A + TSMC 混合** | 18A 首发 |
| Nova Lake | 多 tile（TSMC 为主 + 一片 18A） | 混合 |

```
Intel 多 tile 的关键点：
  ① 内存控制器独立 tile：CPU 核到 DRAM 路径变长（ARL 的 565 周期之痛）
  ② 混合工艺：计算用先进、IO 用成熟——与 AMD 的 CCD/IOD 思路殊途同归
  ③ 后果：核心间通信依赖片内互连（环）→ 大核数桌面性能受制
```

### 4.2 Intel 与 AMD 的封装哲学

| 维度 | AMD | Intel |
|------|-----|-------|
| 计算芯粒 | CCD 统一模块复用（同 CCD 全产品线） | 按产品线单独设计 |
| I/O 位置 | 独立 IOD（成熟工艺） | tile 拆分或内存控制器外移 |
| 一致性 | CCD 内快 + CCD 间目录 | 环/网格全片一致 |
| 3D 缓存 | X3D 堆叠 SRAM | 无（InFO/EMIB 用于桥接） |

## 5. 3D 堆叠与先进封装

### 5.1 封装技术谱系

| 技术 | 原理 | 用途 |
|------|------|------|
| 传统 2D 封装 | 芯片平铺 PCB | 简单但面积大 |
| 2.5D（CoWoS/EMIB） | 芯片并排放在硅中介层上 | HBM 与 GPU/CPU 并排 |
| **3D（TSV 堆叠）** | 芯片垂直堆叠，硅通孔互联 | 3D V-Cache、HBM |
| Foveros（Intel） | 3D face-to-face 堆叠 | 多 die 垂直封装 |

### 5.2 3D V-Cache 的封装经济学

```
AMD X3D 把 64MB SRAM die 堆在 CCD 上（TSV 连接）
  → L3 容量 32MB → 96MB，延迟仅增加 ~10-15 周期
  → 游戏/数据库负载 +10-30%（工作集常驻 L3）

为什么值得：SRAM 密度低（每 die 大），独立小 die 制造
  → 避开"超大 die 良率陷阱"，又获得容量

Intel 路线：用 Foveros 做多 tile 垂直集成（Lunar Lake 的内存
  直接封装在 SoC 上 —— 内存侧缓存的物理基础）
```

## 6. 先进工艺：5nm 之后的世界

### 6.1 工艺路线图（2024-2026）

| 厂商 | 工艺节点 | 代表产品 | 关键创新 |
|------|---------|---------|---------|
| TSMC | N3E/N3P | Apple M4、Zen 5（部分） | 鳍式到环绕栅极过渡 |
| TSMC | N2（2025 量产） | 未来旗舰 | GAA（全环绕栅极） |
| Intel | Intel 4 → 3 → **18A（2025 量产）** | Panther Lake、Diamond Rapids | **RibbonFET + PowerVia** |
| Samsung | GAA 3nm | 早期 Exynos | GAA |

### 6.2 Intel 18A 的底气

```
RibbonFET：GAA 晶体管（栅极四面环绕沟道）→ 漏电更低
PowerVia：背面供电 —— 电源线移到晶圆背面
  → 正面布线资源释放（密度 +30%）、电压降改善
官方数据：较 Intel 3 每瓦性能 +15%、密度 +30%
2025-2026 已进入大规模量产（Fab 52，良率达标）

意义：18A 支撑三代产品（Panther Lake → Nova Lake → Diamond Rapids）
```

### 6.3 工艺红利的递减

```
摩尔定律的物理现实（2025）：
  每代密度提升从 2 倍降到 ~1.3-1.5 倍
  成本不降反升（先进节点研发费数十亿美元级）
  频率红利早已耗尽 —— 性能增长全靠架构（IPC）

行业新共识：工艺 + 封装 + 架构三位一体
  （先进工艺做计算、成熟工艺做 IO、3D 堆叠做容量）
```

> 🎯 **核心要点**：Chiplet + 先进封装 + 混合工艺是 2025-2026 所有旗舰 CPU 的同一张配方——**用模块化解良率、用堆叠解容量、用分工解成本**。看懂 CCD/IOD、环/网格、TSV 这三个概念，就能看懂任何旗舰芯片的 die 图。

## 7. 小结

| 问题 | 答案 |
|------|------|
| 为什么 Chiplet？ | 良率（面积平方定律）+ 复用 + 异构工艺 |
| 环 vs 网格？ | 环适合 ≤16 核（低延迟），网格适合 100+ 核（可扩展） |
| Infinity Fabric 管什么？ | CCD 内快路径 + CCD 间目录一致 + IO |
| 3D 堆叠解决什么？ | 容量（X3D 96MB L3）与集成（Foveros） |
| 18A 强在哪？ | RibbonFET + PowerVia，密度 +30%、每瓦 +15% |
