## 1. ISA 与微架构：两层世界

### 1.1 分层模型

```
┌─────────────────────────────────────────┐
│ 软件层：应用 / 编译器 / 汇编器            │
├─────────────────────────────────────────┤
│ ISA（指令集架构）—— 契约层，稳定不变        │
│   x86-64、ARMv9、RISC-V 定义：            │
│   指令格式、寄存器、内存模型、特权级       │
├─────────────────────────────────────────┤
│ 微架构（Microarchitecture）—— 实现层，自由 │
│   流水线、乱序、缓存、预取、分支预测        │
├─────────────────────────────────────────┤
│ 物理层：晶体管、逻辑门、触发器             │
└─────────────────────────────────────────┘
```

### 1.2 为什么分层如此重要

| 层 | 变化速度 | 决定者 | 兼容性 |
|----|---------|--------|--------|
| ISA | 十年一代（x86-64 20 年不变） | 架构委员会 | 向上兼容（旧软件跑新 CPU） |
| 微架构 | 一年一代 | 芯片公司 | 无需兼容（软件无感知） |

```
软件只要遵守 ISA → 任何微架构实现都能跑
→ Intel 可以每年换微架构（Golden Cove → Lion Cove → Coyote Cove）
  而你的程序十年不用重新编译
```

> 🎯 核心洞察：**微架构是 ISA 的"内部实现自由"**——这就是为什么"同频率的 Zen 5 比 Zen 4 快 17%"（同 ISA，微架构更强），也是为什么 x86 的兼容包袱反而成了优势（软件生态锁定）。

### 1.3 指令集风格

| 风格 | 特征 | 代表 |
|------|------|------|
| CISC（复杂指令集） | 变长指令、内存操作数、微码辅助 | x86 |
| RISC（精简指令集） | 定长指令、Load/Store 架构、寄存器操作 | ARM、RISC-V |
| VLIW（超长指令字） | 指令显式编码并行度 | 已边缘化（Itanium） |

> ⚠️ 现代 x86 内部已 RISC 化：CISC 指令被译码成微操作（uops）再执行——"x86 是 RISC 内核穿 CISC 外衣"。

## 2. CPU 的三大组成

### 2.1 组成总览

```
┌──────────────────────────────────────┐
│              CPU                     │
│  ┌──────────┐  ┌──────────┐          │
│  │ 数据通路   │  │ 控制单元  │          │
│  │ Datapath  │  │ Control  │          │
│  │ ALU/寄存器 │  │ 译码/调度 │          │
│  └──────────┘  └──────────┘          │
│  ┌────────────────────────────────┐  │
│  │ 存储与接口：寄存器堆/L1/总线     │  │
│  └────────────────────────────────┘  │
└──────────────────────────────────────┘
```

| 组成 | 职责 | 关键部件 |
|------|------|---------|
| 数据通路 | 数据的实际运算与移动 | ALU、寄存器堆、多路选择器 |
| 控制单元 | 决定"数据走哪条路" | 译码器、控制信号生成 |
| 存储与接口 | 指令/数据供给 | 寄存器堆、L1 Cache、总线接口 |
| 时钟系统 | 节奏统一 | 时钟树、PLL |

### 2.2 运算单元：ALU 家族

| 单元 | 功能 | 位宽/数量（现代核心） |
|------|------|---------------------|
| 整数 ALU | 加减、逻辑、移位 | 4-6 个，32/64 位 |
| 乘除单元 | 乘法、除法 | 1-2 个（除法极慢，几十周期） |
| FPU | 浮点加减乘 | 2-4 个，FMA 融合 |
| SIMD/向量单元 | 打包并行运算 | 128-512 位（AVX-512） |
| 加载/存储单元 | 访存地址计算 | 2-4 个 + 内存子系统 |

### 2.3 控制单元

```
控制单元 = 解码器 + 控制信号逻辑
职责：把机器码翻译成"谁在什么时候做什么"的开关信号
  - 从指令中提取操作码与操作数
  - 生成寄存器读/写使能、ALU 操作选择、存储器访问使能
  - 现代实现：译码成微操作序列（x86 前端，见 03 模块）
```

## 3. 一条指令的生命周期

### 3.1 经典五步骤

```text
① 取指 (Fetch)    ：按 PC（指令指针）从 I-Cache 取指令
② 译码 (Decode)   ：解析操作码与操作数，生成控制信号
③ 执行 (Execute)  ：ALU 运算 / 地址计算
④ 访存 (Memory)   ：Load/Store 访问 D-Cache（仅访存指令需要）
⑤ 写回 (Writeback)：结果写入寄存器堆，更新 PC
```

### 3.2 逐步演示：`add rax, [rbx+8]`

```asm
① 取指：PC 指向本指令地址 → 从 L1I 取回 4 字节机器码
② 译码：操作码=add；源1=rax（寄存器）；源2=[rbx+8]（内存寻址）
③ 执行：ALU 把 rax 的值与（rbx+8 处读出的值）相加
④ 访存：读 [rbx+8]（若不在 L1D 则逐级下钻）
⑤ 写回：结果写入 rax；PC += 指令长度
```

> 💡 注意：x86 的内存操作数让"执行"与"访存"交错（RISC 里 Load 是独立指令）——这正是 CISC 与 RISC 流水线差异的微观来源。

### 3.3 指令周期的时间观

| 阶段 | 典型耗时 | 优化手段 |
|------|:---:|---------|
| 取指 | 1 周期 + 缓存命中风险 | I-Cache、预取、宽取指 |
| 译码 | 1-3 周期（x86 复杂） | 预译码缓存（uop cache） |
| 执行 | 1 周期（简单运算） | 多 ALU 并行 |
| 访存 | 4-5 周期（命中 L1） | 缓存层次、乱序提前加载 |
| 写回 | 1 周期 | 旁路直送（见 02 模块转发） |

## 4. 冯诺依曼 vs 哈佛：指令与数据

### 4.1 两种结构

| 结构 | 指令/数据存储 | 优点 | 缺点 |
|------|:---:|------|------|
| 冯诺依曼 | 同一存储器、同总线 | 简单、存储利用率高 | 取指与访存争抢总线（瓶颈） |
| 哈佛 | 分离的指令/数据存储 | 取指与访存并行 | 需两条总线/两个缓存 |

### 4.2 现代 CPU 的混合答案

```
内核级：L1 分离（L1I + L1D）——哈佛思想
系统级：L2/L3/主存统一 —— 冯诺依曼思想
→ 现代 CPU = "哈佛核心 + 冯诺依曼后段"的混合结构

分离的好处：取指带宽与数据带宽互不干扰
统一的必要：指令可以当数据处理（JIT 编译、自修改代码）
```

> ⚠️ 自修改代码（JIT）：写指令数据后需显式刷 I-Cache（`clflush` 指令），现代 JIT（HotSpot、V8）都在执行 `cacheflush`——这就是"哈佛外衣"给 JIT 留下的尾巴。

## 5. 从单周期到多周期

### 5.1 设计演进

| 方案 | 思想 | 时钟周期 | 缺点 |
|------|------|:---:|------|
| 单周期 | 一条指令一个时钟 | = 最慢指令时间 | 快指令等慢指令，浪费 |
| 多周期 | 一条指令分多步，每步一个时钟 | 1/5 步长 | 每步间有状态转换开销 |
| 流水线 | 指令重叠执行（02 模块） | 1 个级延迟 | 冒险处理复杂 |

### 5.2 为什么必须流水线

```
单周期：最慢指令 10ns → 全部指令 10ns → 吞吐 1 亿条/秒
流水线（5 级）：每级 2ns → 每 2ns 完成一条指令 → 吞吐 5 亿条/秒
→ 同频率下吞吐提升 5 倍 —— 流水线是"用时间重叠换吞吐"
```

> 🎯 频率与吞吐的区别：单周期靠"缩短最慢指令"提频率；流水线靠"重叠"提吞吐。现代 CPU 两者都用——先流水线（吞吐×N），再靠工艺提频率。

## 6. 时钟、频率与功耗的基本关系

### 6.1 功耗公式

```
P = C × V² × f      （动态功耗 = 电容 × 电压² × 频率）

推论：
  频率翻倍 → 功耗翻倍（线性）
  电压降 20% → 功耗降 36%（平方）——降压比降频划算！
  这就是"降频省电、低压省更多"的物理根源
```

### 6.2 频率的现实约束

| 约束 | 说明 |
|------|------|
| 关键路径 | 最长逻辑链决定最高频率 |
| 功耗墙 | 500W 上限（EPYC 9965 实测 TDP 500W） |
| 漏电流 | 晶体管越细漏电越大，静态功耗占比上升 |
| 工艺红利见顶 | 5GHz 以上每代提升 <5%——靠架构（IPC）补 |

### 6.3 为什么现在拼 IPC 而非频率

```
2005-2010：Pentium 4 路线，冲 3-4GHz 失败（功耗爆炸），被酷睿打回
2010-2025：频率稳定在 4-5GHz，性能增长全靠 IPC
  Zen 5 较 Zen 4 IPC +17%（云负载），较 Zen 3 +37%（HPC）
  未来：IPC 仍是主战场（见 04 模块核心对比）
```

> 🎯 **核心要点**：CPU = ISA 契约 + 微架构实现。理解"指令周期五步"与"流水线思想"，是读懂后面所有模块（冒险、乱序、现代核心）的入场券。
