## 一、计算机系统层次结构

### 1.1 经典层次模型（自底向上）

```
第 7 层 — 应用层（业务代码、微服务、API、分布式系统）
第 6 层 — 库函数层（Java 标准库、Spring、MyBatis、Netty）
第 5 层 — 虚拟机层（JVM：类加载、运行时数据区、GC）
第 4 层 — 操作系统层（进程/线程、虚拟内存、系统调用）
第 3 层 — 指令集架构层（x86-64/ARM/RISC-V）
第 2 层 — 微体系结构层（CPU 流水线、Cache、总线协议）
第 1 层 — 数字逻辑层（门电路、触发器、ALU、寄存器）
```

### 1.2 Java 应用的执行链路

一条 Java 方法调用（如 `userService.getById(1L)`）的完整旅程：

```
应用层 → 库层 → JVM 层 → OS 层 → ISA 层 → 微体系层 → 硬件层
```

> **理解该链路，是定位性能问题（慢 SQL、GC 停顿、上下文切换、I/O 阻塞）的关键。**

## 二、指令集架构（ISA）

### 2.1 CISC vs RISC

| 特性 | CISC（x86-64） | RISC（ARM/RISC-V） |
|------|---------------|-------------------|
| 指令 | 复杂、变长 | 精简、定长 |
| 寻址 | 多种 | Load-Store |
| 寄存器 | 16 个 | 31 个 |
| 特点 | 乱序执行 | 流水线高效、低功耗 |

### 2.2 关键指令对 Java 后端的影响

| CPU 指令 | Java 对应 | 作用 |
|---------|-----------|------|
| `CMPXCHG` | CAS 原子操作 | 支撑 AtomicInteger、ConcurrentHashMap |
| `SFENCE/LFENCE/MFENCE` | 内存屏障 | 支撑 volatile、锁、Happens-Before |
| SIMD（SSE/AVX/NEON） | 向量化运算 | 加密、统计等数据密集型任务 |

## 三、CPU 微体系结构

### 3.1 核心组成

- **控制单元 CU**：取指、译码、调度
- **算术逻辑单元 ALU**：整数运算
- **浮点单元 FPU**：float/double 运算
- **寄存器组**：PC、SP、FLAGS、通用寄存器
- **多级 Cache**：L1i/L1d、L2、L3（共享）
- **总线接口**：与内存/IO 通信

### 3.2 关键机制与 Java 优化

#### 3.2.1 指令流水线与分支预测

```pseudocode
流水线：取指 → 译码 → 执行 → 访存 → 写回
```

> **Java 优化**：减少循环内复杂分支、避免深度递归、使用三元运算符替代复杂 if-else。

#### 3.2.2 多级 Cache 与局部性

- **Cache Line**：64 字节（x86），以行为单位加载
- **时间局部性**：近期访问的数据会再次访问
- **空间局部性**：相邻地址数据会一起访问

> **Java 优化**：数组优于链表（连续内存）；避免伪共享（缓存行填充、LongAdder 分段）。

#### 3.2.3 缓存一致性协议（MESI）

| 状态 | 含义 |
|------|------|
| **M**odified | 已修改，与内存不一致 |
| **E**xclusive | 独占，与内存一致 |
| **S**hared | 共享，多 Cache 有效 |
| **I**nvalid | 失效 |

> **Java 优化**：`volatile` 避免指令重排；锁粒度细化；使用分段锁（ConcurrentHashMap）。

## 四、存储层次结构

### 4.1 经典金字塔

```
寄存器 → L1 → L2 → L3 → DRAM（主存） → SSD → HDD → 分布式存储
（速度递减、容量递增）
```

### 4.2 主存（DRAM）与虚拟内存

#### 4.2.1 物理内存与虚拟地址空间

- 每个进程拥有独立虚拟地址空间
- OS 通过页表（Page Table）映射虚拟页 → 物理页（通常 4KB）
- 缺页中断：页面不在内存时从 Swap/磁盘加载

#### 4.2.2 JVM 与虚拟内存

| JVM 区域 | 虚拟内存关联 |
|---------|-------------|
| 堆（-Xms/-Xmx） | 虚拟内存分配，物理内存按需使用 |
| 元空间（Metaspace） | 使用本地内存，不受 PermGen 限制 |
| 栈 | 线程私有，连续虚拟内存 |

> **Java 优化**：禁用 Swap（避免 GC 卡顿）；堆设置为物理内存 50%-70%；使用大页（HugePage）降低 TLB miss。

### 4.3 Java 多级缓存映射

| 层级 | 对应技术 | 设计原则 |
|------|---------|---------|
| L0 | ThreadLocal | 热点上移 |
| L1 | Caffeine/Guava 本地缓存 | 写穿透 |
| L2 | Redis 分布式缓存 | 过期淘汰 |
| L3 | MySQL/Elasticsearch | 防击穿/雪崩 |

## 五、总线与 I/O 系统

### 5.1 总线体系

| 总线 | 连接 | 带宽影响 |
|------|------|---------|
| 前端总线（FSB） | CPU-内存 | 内存访问速度 |
| PCIe | 高速 I/O（网卡、SSD、GPU） | 网络/磁盘 IO 上限 |

### 5.2 I/O 控制方式

| 方式 | CPU 参与度 | 效率 |
|------|-----------|------|
| 程序查询 | CPU 轮询 | 低效 |
| 中断 | I/O 完成发中断 | 中等 |
| DMA | 直接内存访问 | 高效 |
| 通道 | 独立 I/O 处理器 | 最高效 |

### 5.3 Java I/O 模型

| 模型 | 硬件机制对应 | 特点 |
|------|-------------|------|
| BIO | 中断 | 同步阻塞，一连接一线程 |
| NIO | epoll 多路复用 | 同步非阻塞，Selector |
| AIO | DMA/通道 | 异步非阻塞，OS 完成后回调 |

### 5.4 磁盘 I/O 优化

- SSD 替代 HDD（随机读写提升 100x）
- 顺序写优于随机写
- 批量写入、内存映射（`MappedByteBuffer`）

## 六、并行与多核心体系

### 6.1 并行等级

| 并行类型 | 描述 |
|---------|------|
| 指令级并行（ILP） | 流水线、乱序、SIMD |
| 线程级并行（TLP） | 多核、超线程 |
| 任务级并行（DLP） | 多服务器、分布式 |

### 6.2 Java 线程与内核线程

- Java 线程 = 内核线程（1:1 模型）
- 线程切换保存上下文（寄存器、PC、栈）
- 优化：线程池大小 = CPU 核心数 × (1 + IO 等待 / CPU 计算)

### 6.3 锁与同步的硬件支撑

| 锁类型 | 硬件机制 |
|--------|---------|
| 自旋锁 | CPU 循环等待 |
| 偏向锁 → 轻量级锁 → 重量级锁 | CAS → 总线锁 → futex (syscall) |

## 七、异常、中断与系统调用

### 7.1 中断机制

| 类型 | 来源 | Java 对应 |
|------|------|-----------|
| 硬件中断 | 网卡、磁盘、定时器 | Netty 事件 |
| 异常 | 除零、缺页、非法指令 | ArithmeticException、OOM |
| 系统调用 | 应用 → 内核 | Socket、文件、Thread.sleep |

### 7.2 对 Java 性能的影响

频繁系统调用 → 用户态/内核态切换 → 开销巨大

> **优化**：使用 NIO 减少 syscall 次数；池化连接；零拷贝（sendfile、mmap）。

## 八、JVM 与体系结构的深度融合

### 8.1 对象内存布局

| 组成部分 | 说明 |
|---------|------|
| 对象头 | Mark Word + Klass Pointer |
| 实例数据 | 实际字段值 |
| 对齐填充 | 保证 64 字节对齐 |

> **避免伪共享**：`@Contended` 注解、字段分组。

### 8.2 GC 与内存体系

| GC 算法 | 特点 | 对 Cache 的影响 |
|---------|------|----------------|
| 复制算法 | Eden → Survivor | 连续内存，Cache 友好 |
| 标记清除 | 碎片化 | 导致 Cache miss |
| G1/ZGC/Shenandoah | 面向大堆、低延迟 | 利用多核与大页 |

### 8.3 JIT 优化

- 方法内联、死码消除、循环展开、常量传播
- 向量化（利用 SIMD）
- 逃逸分析：栈上分配、标量替换、消除同步

## 九、分布式体系结构

### 9.1 分布式核心依赖

| 维度 | 技术 |
|------|------|

|------|-----------|

| 线程池 | 服务集群 + 负载均衡 |

## 十、Java 后端性能优化全景

| 瓶颈类型 | 优化方向 |
|---------|---------|
| **CPU 瓶颈** | 减少分支、提升 Cache 命中率、无锁、SIMD、合理线程池 |
| **内存瓶颈** | 堆优化、GC 调优、大页、避免内存泄漏、对象复用 |
| **I/O 瓶颈** | 万兆网卡、SSD、NIO/Netty、零拷贝、批量、池化 |
| **并发瓶颈** | CAS、分段锁、ThreadLocal、LongAdder、协程 |
| **分布式瓶颈** | 就近访问、多级缓存、异步解耦、分片、一致性优化 |

## 十一、总结

计算机体系结构与组成是 Java 后端的"内功"。所有性能问题、并发问题、内存问题、I/O 问题，最终都能追溯到 CPU 流水线、Cache 一致性、虚拟内存、总线带宽、中断与系统调用等底层机制。

掌握体系结构，你将能：
- 写出更贴近硬件的高效代码
- 快速定位线上瓶颈（CPU/内存/IO/锁）
- 设计更合理的缓存、并发、分布式架构
- 理解 JVM、OS、硬件的协同关系
