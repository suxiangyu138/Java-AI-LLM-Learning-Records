# 传输层与 TCP

## 📌 课程定位
TCP是互联网最核心的协议——HTTP、WebSocket、gRPC、数据库连接都建立在其上。TCP的三次握手、四次挥手、拥塞控制是面试最高频考点，没有之一。

## 🎯 核心章节

### 1. 传输层概述
- **功能**：端到端通信（进程→进程），通过端口号定位应用进程
- **端口号**：16位，0-65535。0-1023知名端口(HTTP=80, HTTPS=443, SSH=22, MySQL=3306)
- **Socket = IP地址 + 端口号**：`192.168.1.1:8080` 唯一标识一个通信端点

### 2. UDP（用户数据报协议）
- **特点**：无连接、不可靠、无拥塞控制、头部小(8字节)
- **适用场景**：DNS查询、实时视频/语音(QQ/微信)、广播/多播
- **UDP首部**：源端口(2B)|目的端口(2B)|长度(2B)|校验和(2B)
- **为什么DNS用UDP**：一次查询响应数据量小，丢了重发即可，TCP握手开销太大

### 3. TCP 的核心特性
- **面向连接**：通信前必须建立连接（三次握手）
- **可靠传输**：确认应答+超时重传+序号机制
- **全双工**：双方可同时收发数据
- **字节流**：无消息边界——应用层需自行分包（HTTP的Content-Length/chunked）

### 4. TCP 首部格式（⭐ 重点字段）
```
|源端口(16)|              目的端口(16)              |
|              序号/Seq Number(32)                   |
|              确认号/Ack Number(32)                  |
|首部长|保留|URG|ACK|PSH|RST|SYN|FIN|  窗口大小(16) |
|  校验和(16)           |      紧急指针(16)           |
```
- **序号(Seq)**：本段数据第一个字节的编号——初始序号ISN随机生成
- **确认号(Ack)**：期望收到的下一个字节的序号——即"我这边的接收窗口起点"
- **SYN**：建立连接；**FIN**：释放连接；**RST**：重置连接；**PSH**：催促交付；**ACK**：确认

### 5. 三次握手（⭐ 必能画出并解释为什么是三次）
```
Client                              Server
  |-------- SYN(seq=x) -------------->|
  |<--- SYN+ACK(seq=y, ack=x+1) -----|
  |-------- ACK(ack=y+1) ----------->|
```
- **为什么不是两次？** 防止已失效的连接请求报文突然到达服务器——"已失效的SYN"问题
- **SYN Flood攻击**：攻击者发大量SYN不回复ACK——半连接队列耗尽→SYN Cookie防御

### 6. 四次挥手（⭐ 必能画出）
```
Client                              Server
  |-------- FIN(seq=u) -------------->|
  |<------ ACK(ack=u+1) -------------|
  |                              (等待关闭)|
  |<------ FIN(seq=v) ---------------|
  |-------- ACK(ack=v+1) ----------->|
  |(TIME_WAIT 2MSL)                  |
```
- **为什么是四次不是三次？** 全双工——一方发FIN只代表自己没数据要发了，另一方可能还有数据要发
- **TIME_WAIT 为什么等2MSL？** 确保最后的ACK能被对方收到、让旧连接的报文在网络上消失
- **CLOSE_WAIT过多**：服务器应用层没正确调用close()——常见开发Bug

### 7. TCP 可靠传输机制
- **停等协议**：发一个确认一个——效率太低
- **滑动窗口**（⭐ 核心）：流水线发送，窗口大小=可连续发送的字节数
  - 累计确认：ACK n 表示 n-1 及之前的数据全部收到
  - 发送窗口 = min(拥塞窗口, 接收窗口)
- **超时重传**：RTT动态估算(Jacobson算法)，超时时间RTO自适应
- **快速重传**：收到3个重复ACK直接重传，不等超时

### 8. TCP 拥塞控制（⭐ 面试高频）
- **慢启动**：cwnd从1开始指数增长，直到ssthresh
- **拥塞避免**：超过ssthresh后线性增长(每RTT +1 MSS)
- **快速恢复**：收到3个重复ACK→ssthresh=cwnd/2, cwnd=ssthresh+3→直接进入拥塞避免
- **超时**：ssthresh=cwnd/2, cwnd=1→重新慢启动
- **BBR（Google提出）**：基于带宽和RTT的拥塞控制——Linux 4.9+合入

## ✅ 学习建议
- 三次握手和四次挥手必须能手画时序图——面试必问
- TCP状态机（LISTEN→SYN_SENT→ESTABLISHED→FIN_WAIT→TIME_WAIT...）要能讲清转换条件
- TIME_WAIT、CLOSE_WAIT是生产环境常见问题——理解原因才能排查
