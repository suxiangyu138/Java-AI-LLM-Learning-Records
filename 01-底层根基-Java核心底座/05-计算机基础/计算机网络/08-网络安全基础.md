## 1. 网络安全概述

### 1.1 CIA三元组

| 目标 | 说明 | 实现手段 | 典型威胁 |
|:----:|------|---------|---------|
| **机密性** | 仅授权方可见 | 加密（AES、RSA）、访问控制 | 窃听、数据泄露 |
| **完整性** | 数据未被篡改 | 哈希校验、数字签名 | 中间人篡改 |
| **可用性** | 系统持续服务 | 冗余部署、DDoS防护、限流 | DDoS攻击、硬件故障 |

### 1.2 各层级安全概览

| OSI层 | 常见威胁 | 防护手段 | 后端关注度 |
|:-----:|---------|---------|:----------:|
| **应用层** | SQL注入、XSS、CSRF、SSRF、未授权访问 | 输入校验、WAF、权限控制 | ★★★★★ |
| **传输层** | 窃听、中间人攻击、会话劫持 | SSL/TLS、HTTPS | ★★★★★ |
| **网络层** | IP欺骗、DDoS、路由攻击 | 防火墙、IPsec | ★★★ |
| **数据链路层** | ARP欺骗、MAC泛洪 | 静态ARP绑定、端口安全 | ★★ |

> Kerckhoffs原则：系统安全性应依赖于**密钥的保密**，而非算法的保密。开源算法经全球审查，比闭源更可靠。

## 2. 密码学基础

### 2.1 对称加密

加密解密使用**同一密钥**，速度快，适合大数据量加密。

| 算法 | 密钥长度 | 状态 | 特点 |
|------|---------|:----:|------|
| **AES** | 128/256位 | ✅ 推荐 | 当前标准，硬件加速 |
| DES | 56位 | ❌ 废弃 | 易暴力破解 |
| 3DES | 112/168位 | ⚠️ 逐步淘汰 | 慢于AES |
| ChaCha20 | 256位 | ✅ 推荐（移动端） | 流密码，软件效率高 |

**AES加密模式**：ECB（不安全，暴露模式）、CBC（需IV，防填充预言攻击）、CTR（可并行）、**GCM**（AEAD，推荐——同时保证机密性和完整性）。

```java
// AES-GCM加密
import javax.crypto.Cipher;
import javax.crypto.KeyGenerator;
import javax.crypto.SecretKey;
import javax.crypto.spec.GCMParameterSpec;
import java.security.SecureRandom;

public class AesUtil {
    private static final int GCM_IV_LENGTH = 12;
    private static final int GCM_TAG_LENGTH = 128;

    public static SecretKey generateKey() throws Exception {
        KeyGenerator kg = KeyGenerator.getInstance("AES");
        kg.init(256);
        return kg.generateKey();
    }

    public static byte[] encrypt(byte[] plaintext, SecretKey key) throws Exception {
        byte[] iv = new byte[GCM_IV_LENGTH];
        SecureRandom.getInstanceStrong().nextBytes(iv);
        Cipher cipher = Cipher.getInstance("AES/GCM/NoPadding");
        cipher.init(Cipher.ENCRYPT_MODE, key, new GCMParameterSpec(GCM_TAG_LENGTH, iv));
        byte[] ciphertext = cipher.doFinal(plaintext);
        byte[] result = new byte[iv.length + ciphertext.length];
        System.arraycopy(iv, 0, result, 0, iv.length);
        System.arraycopy(ciphertext, 0, result, iv.length, ciphertext.length);
        return result;
    }

    public static byte[] decrypt(byte[] encrypted, SecretKey key) throws Exception {
        byte[] iv = new byte[GCM_IV_LENGTH];
        System.arraycopy(encrypted, 0, iv, 0, iv.length);
        Cipher cipher = Cipher.getInstance("AES/GCM/NoPadding");
        cipher.init(Cipher.DECRYPT_MODE, key, new GCMParameterSpec(GCM_TAG_LENGTH, iv));
        return cipher.doFinal(encrypted, iv.length, encrypted.length - iv.length);
    }
}
```

### 2.2 非对称加密

公钥/私钥对，安全性高但速度慢，用于**密钥交换**和**数字签名**。

| 算法 | 密钥长度 | 安全性 | 用途 |
|------|---------|:-----:|------|
| RSA | 2048/4096位 | 高 | 加密、签名 |
| **ECC** | 256位（≈RSA 3072） | 更高 | 移动端、TLS密钥交换 |
| DH | 2048位 | 高 | 密钥交换 |

```
公钥加密 → 私钥解密：加密通信
私钥签名 → 公钥验签：数字签名
```

### 2.3 哈希函数

单向不可逆，固定长度输出，用于**完整性校验**和**数字签名**。

| 算法 | 摘要长度 | 状态 | 说明 |
|------|---------|:----:|------|
| MD5 | 128位 | ❌ 不安全 | 仅用于非安全校验 |
| SHA-1 | 160位 | ❌ 不安全 | 已被碰撞攻击 |
| **SHA-256** | 256位 | ✅ 推荐 | 当前主流 |
| **SHA-3** | 可变 | ✅ 新一代 | 抗量子攻击更强 |
| BLAKE3 | 可变 | ✅ 极快 | 远超SHA-256速度 |

```java
public static String sha256(String data) throws Exception {
    MessageDigest md = MessageDigest.getInstance("SHA-256");
    byte[] digest = md.digest(data.getBytes("UTF-8"));
    StringBuilder hex = new StringBuilder();
    for (byte b : digest) hex.append(String.format("%02x", b & 0xff));
    return hex.toString();
}
```

> ⚠️ **密码存储警告**：绝不使用MD5/SHA直接存密码！它们是快速哈希，可被GPU暴力破解。必须用**BCrypt**、SCrypt或Argon2（慢速哈希+内置盐）。

### 2.4 数字证书

**X.509证书**由CA签发，将**公钥与实体身份绑定**，是TLS信任的基础。

```
Certificate
├── Version, Serial Number
├── Issuer (CA名称), Subject (持有者)
├── Validity (有效期)
├── Subject Public Key (持有者公钥)
├── SAN (Subject Alternative Name，域名)
└── CA Signature (CA对证书的签名)
```

**证书验证链**：服务器证书 → 中间CA证书 → 根CA证书（在操作系统信任列表中则为通过）。

## 3. SSL-TLS协议

### 3.1 版本演进

| 版本 | 发布 | 状态 | 说明 |
|------|:----:|:----:|------|
| SSL 2.0 | 1995 | ❌ 废弃 | 严重缺陷 |
| SSL 3.0 | 1996 | ❌ 禁用 | POODLE漏洞 |
| TLS 1.0 | 1999 | ❌ 废弃 | 逐步淘汰 |
| TLS 1.1 | 2006 | ❌ 废弃 | |
| **TLS 1.2** | 2008 | ✅ **当前主流** | 最广泛部署 |
| **TLS 1.3** | 2018 | ✅ **推荐** | 更快（1-RTT）、更安全 |

### 3.2 TLS 1.2握手（2-RTT）

```
Client                                      Server
  │                                            │
  │ 1. ClientHello（TLS版本、密码套件、随机数）  │
  │ ───────────────────────────────────────→  │
  │ 2. ServerHello（选定版本/套件、随机数）      │
  │    数字证书（含公钥）                       │  ← 1-RTT
  │ ←───────────────────────────────────────  │
  │ 3. 验证证书，生成预主密钥，用公钥加密后发送   │
  │ ───────────────────────────────────────→  │
  │ 4. 私钥解密，双方计算会话密钥               │
  │ 5. Change Cipher Spec + Finished          │  ← 2-RTT
  │ ←───────────────────────────────────────  │
  │ ✅ 安全连接建立，开始对称加密数据传输          │
```

### 3.3 TLS 1.3改进（1-RTT）

```
Client                                      Server
  │                                            │
  │ 1. ClientHello（密码套件+密钥共享Key Share） │
  │ ───────────────────────────────────────→  │
  │ 2. ServerHello（选定套件+密钥共享）          │  ← 1-RTT
  │    证书 + CertificateVerify + Finished     │
  │ ←───────────────────────────────────────  │
  │ ✅ 连接建立（0-RTT模式还可更快）              │
```

| 对比 | TLS 1.2 | TLS 1.3 |
|------|---------|---------|
| 握手 | 2-RTT | 1-RTT（0-RTT可选） |
| 密码套件 | 37种 | 5种（仅AEAD） |
| 密钥交换 | RSA/DHE/ECDHE | **仅ECDHE**（强制前向安全） |
| 对称加密 | CBC/GCM/CCM | 仅GCM/ChaCha20-Poly1305 |
| 移除 | - | RSA密钥交换、RC4、DES、CBC |

### 3.4 HSTS

```http
Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
```

强制浏览器使用HTTPS：`max-age`内拒绝HTTP，`includeSubDomains`覆盖子域名，`preload`加入浏览器列表。

## 4. Java安全Socket编程

### 4.1 核心API

| 类 | 说明 |
|---|------|
| **SSLContext** | SSL/TLS上下文入口，配置密钥/信任库 |
| **SSLSocket / SSLServerSocket** | 客户端/服务端安全Socket |
| **KeyManager** | 管理私钥和证书（证明自身身份） |
| **TrustManager** | 验证对端证书合法性 |
| **KeyStore** | 密钥库/信任库存储容器 |

### 4.2 证书生成（测试环境）

```bash
# 生成服务器端密钥库
keytool -genkey -alias serverCert -keyalg RSA -keysize 2048 \
    -keystore server.keystore -validity 3650 -dname "CN=localhost, OU=Dev, O=Co, L=City, C=CN"
# 导出证书
keytool -export -alias serverCert -keystore server.keystore -file server.crt
# 导入到客户端信任库
keytool -import -alias serverCert -file server.crt -keystore client.truststore
```

> ⚠️ 自签名证书仅用于测试！生产必须使用权威CA（Let's Encrypt、DigiCert等）。

### 4.3 安全Socket服务器端

```java
import javax.net.ssl.*;
import java.io.*;
import java.security.KeyStore;

public class SecureServer {
    public static void main(String[] args) throws Exception {
        // 1. 加载密钥库
        KeyStore ks = KeyStore.getInstance("JKS");
        ks.load(new FileInputStream("server.keystore"), "changeit".toCharArray());

        // 2. 初始化KeyManager
        KeyManagerFactory kmf = KeyManagerFactory.getInstance(
                KeyManagerFactory.getDefaultAlgorithm());
        kmf.init(ks, "changeit".toCharArray());

        // 3. 创建SSLContext（TLS 1.2）
        SSLContext ctx = SSLContext.getInstance("TLSv1.2");
        ctx.init(kmf.getKeyManagers(), null, null);

        // 4. 创建SSLServerSocket
        SSLServerSocket sss = (SSLServerSocket) ctx.getServerSocketFactory()
                .createServerSocket(8443);
        sss.setEnabledProtocols(new String[]{"TLSv1.2"});
        System.out.println("Secure server on port 8443");

        while (true) {
            SSLSocket socket = (SSLSocket) sss.accept();
            socket.startHandshake();
            new Thread(() -> {
                try (BufferedReader r = new BufferedReader(
                        new InputStreamReader(socket.getInputStream()));
                     PrintWriter w = new PrintWriter(socket.getOutputStream(), true)) {
                    w.println("Echo: " + r.readLine());
                } catch (IOException e) { e.printStackTrace(); }
            }).start();
        }
    }
}
```

### 4.4 安全Socket客户端

```java
import javax.net.ssl.*;
import java.io.*;
import java.security.KeyStore;

public class SecureClient {
    public static void main(String[] args) throws Exception {
        // 1. 加载信任库
        KeyStore ts = KeyStore.getInstance("JKS");
        ts.load(new FileInputStream("client.truststore"), "changeit".toCharArray());

        // 2. 初始化TrustManager
        TrustManagerFactory tmf = TrustManagerFactory.getInstance(
                TrustManagerFactory.getDefaultAlgorithm());
        tmf.init(ts);

        // 3. 创建SSLContext
        SSLContext ctx = SSLContext.getInstance("TLSv1.2");
        ctx.init(null, tmf.getTrustManagers(), null);

        // 4. 连接
        SSLSocket socket = (SSLSocket) ctx.getSocketFactory()
                .createSocket("localhost", 8443);
        socket.startHandshake();

        try (PrintWriter w = new PrintWriter(socket.getOutputStream(), true);
             BufferedReader r = new BufferedReader(
                     new InputStreamReader(socket.getInputStream()))) {
            w.println("Hello secure server!");
            System.out.println("Response: " + r.readLine());
        }
        socket.close();
    }
}
```

## 5. 应用层安全

### 5.1 常见攻击与防御

| 攻击 | 原理 | 防御 | Java实现 |
|------|------|------|---------|
| **SQL注入** | 输入中嵌入恶意SQL | 参数化查询/预编译 | `PreparedStatement`、MyBatis `#{}` |
| **XSS** | 注入恶意JS到页面 | 输出转义、CSP、HttpOnly | `HtmlUtils.htmlEscape()` |
| **CSRF** | 利用已登录态伪造请求 | CSRF Token、SameSite Cookie | Spring Security CSRF |
| **SSRF** | 诱导服务器向内网发请求 | URL白名单、禁内网IP | 自定义URL过滤器 |
| **未授权访问** | 绕过权限校验 | RBAC、JWT/OAuth2 | Spring Security/Shiro |
| **暴力破解** | 大量尝试密码 | 限流、验证码、锁定 | RateLimiter |

**SQL注入防御**：

```xml
<!-- 安全：#{} 预编译 -->
<select id="findUser" resultType="User">
    SELECT * FROM user WHERE username = #{username}
</select>
<!-- 危险：${} 拼接，注入风险 -->
```

**XSS防御**：

```java
String safe = HtmlUtils.htmlEscape(userInput);  // <script> → &lt;script&gt;
response.setHeader("Set-Cookie", "sessionId=xxx; HttpOnly; Secure; SameSite=Strict");
```

**CSRF防御（Spring Security）**：

```java
@Configuration
@EnableWebSecurity
public class SecurityConfig {
    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http.csrf(csrf -> csrf.csrfTokenRepository(
                CookieCsrfTokenRepository.withHttpOnlyFalse()))
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/public/**").permitAll()
                .anyRequest().authenticated());
        return http.build();
    }
}
```

### 5.2 JWT（JSON Web Token）

三部分构成：`Header.Payload.Signature`

```
Header: {"alg":"HS256","typ":"JWT"}
Payload: {"sub":"userId","role":"admin","exp":1700000000}
Signature: HMACSHA256(base64Url(Header)+"."+base64Url(Payload), secret)
```

```java
// JJWT库示例
public class JwtUtil {
    private static final SecretKey KEY = new SecretKeySpec(
            "my-secret-key-32-chars-long!!!!!".getBytes(), "HmacSHA256");
    private static final long EXP = 30 * 60 * 1000;

    public static String generate(String userId, String role) {
        return Jwts.builder().subject(userId).claim("role", role)
                .issuedAt(new Date())
                .expiration(new Date(System.currentTimeMillis() + EXP))
                .signWith(KEY).compact();
    }

    public static String validate(String token) {
        return Jwts.parser().verifyWith(KEY).build()
                .parseSignedClaims(token).getPayload().getSubject();
    }
}
```

### 5.3 接口限流（Redis实现）

```java
@Component
public class RateLimitInterceptor implements HandlerInterceptor {
    private final StringRedisTemplate redis;
    private static final int MAX = 100;
    private static final int WINDOW = 60;

    public boolean preHandle(HttpServletRequest req, HttpServletResponse resp,
                             Object handler) throws Exception {
        String key = "rl:" + req.getRemoteAddr() + ":" + req.getRequestURI();
        Long count = redis.opsForValue().increment(key);
        if (count == 1) redis.expire(key, WINDOW, TimeUnit.SECONDS);
        if (count > MAX) {
            resp.setStatus(429);
            resp.getWriter().write("Too many requests");
            return false;
        }
        return true;
    }
}
```

## 6. 网络层与链路层安全

### 6.1 DDoS攻击与防护

| 类型 | 原理 | 防护层次 | 防护手段 |
|------|------|:-------:|---------|
| **SYN Flood** | 大量SYN不完成三次握手 | L4 | SYN Cookie、增大backlog |
| **UDP Flood** | 大量UDP占带宽 | L3/L4 | 限速、云清洗 |
| **HTTP Flood** | 大量HTTP请求耗应用资源 | L7 | WAF+限流+验证码 |
| **DNS放大** | 伪造源IP发小DNS查询放大攻击 | L4 | 关闭递归、限速 |
| **Slowloris** | 慢HTTP头占满连接池 | L7 | 连接超时+最小速率 |

**分层防护**：L3/L4 DDoS → 云清洗（Cloudflare、阿里云高防）；L7 DDoS → CDN + WAF + 限流 + 验证码。

### 6.2 防火墙类型

| 类型 | 层 | 能力 | 代表 |
|:----:|:--:|------|------|
| 包过滤 | L3/L4 | 按IP/端口/协议放行 | iptables |
| 状态检测 | L3/L4 | 跟踪连接状态 | iptables + conntrack |
| WAF | L7 | 识别SQL注入/XSS/CSRF等 | ModSecurity、云WAF |

### 6.3 常见网络攻击

| 攻击 | 原理 | 防护 |
|------|------|------|
| **ARP欺骗** | 伪造ARP响应，流量导向攻击者 | 静态ARP绑定、端口安全 |
| **DNS劫持** | 篡改DNS响应 | DNSSEC、DoH（DNS over HTTPS） |
| **SSL剥离** | HTTP降级攻击 | HSTS强制HTTPS |
| **IP欺骗** | 伪造源IP | 防火墙过滤、反向路径验证 |

### 6.4 DNS安全：DNSSEC（防篡改）、DoH/DoT（加密传输）、DNS防火墙（过滤恶意域名）

## 7. Java后端安全实践

### 7.1 密码安全存储

```java
// BCrypt（推荐）：慢速哈希+内置随机盐
private static final BCryptPasswordEncoder encoder = new BCryptPasswordEncoder();

public static String hash(String raw) { return encoder.encode(raw); }
public static boolean check(String raw, String encoded) { return encoder.matches(raw, encoded); }
```

### 7.4 核心安全规范

- **输入校验**：所有用户输入不可信，严格校验和清理
- **日志脱敏**：不记录密码、身份证等敏感字段
- **最小权限**：数据库读写账号分离、应用非root启动、接口分级授权

### 7.5 面试高频问题

| 问题 | 核心要点 |
|------|---------|
| **HTTPS比HTTP安全在哪？** | TLS加密（对称+非对称）、证书验证身份、MAC完整性校验 |
| **TLS 1.2和1.3区别？** | 1.3更快（1-RTT）、更安全（仅ECDHE+AEAD）、更简洁（5种套件） |
| **如何防止SQL注入？** | 预编译语句/`#{}`、ORM框架、最小数据库权限 |
| **JWT vs Session？** | JWT无状态适合分布式，但不可撤销；Session有状态需共享存储 |
| **密码如何存储？** | **BCrypt/SCrypt/Argon2**慢速哈希+随机盐，绝不MD5/SHA |
| **如何防范DDoS？** | 云清洗（L4）+ WAF+限流（L7）+ CDN隐藏源站 |
| **CSRF防御？** | CSRF Token、SameSite Cookie、Referer校验 |
| **MITM防御？** | TLS证书验证 + HSTS + 证书钉扎 |

> ⚠️ **永远不信任用户输入**——所有输入都需要校验和清理。生产环境务必启用HTTPS。

> 💡 **BCrypt vs MD5**：MD5/SHA每秒数十亿次计算，BCrypt每秒约千次，暴力破解成本相差百万倍。密码存储永远选BCrypt/SCrypt/Argon2。

> 🎯 **纵深防御**：安全没有银弹，需多层防护贯穿全系统——应用层输入校验和权限控制，传输层HTTPS/TLS加密，网络层防火墙和限流。安全不是附加功能，应在系统设计之初就纳入考量。
