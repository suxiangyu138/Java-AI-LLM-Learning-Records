## 1. 高频面试题 16 问

### Q1：完整描述一次 DNS 解析过程？

> 答：① 客户端（浏览器）向本地递归器发起**递归查询**（"你帮我查到底"）；② 递归器向**根服务器**迭代查询"com 归谁管"→ 返回 com 的 NS 委派；③ 递归器向 **com TLD** 查询"example.com 归谁管"→ 返回其 NS；④ 递归器向 **example.com 权威**查询 A 记录 → 返回答案 + TTL；⑤ 递归器缓存并返回客户端。热查询时②③④被缓存跳过（1 RTT 内返回）。
> 参考：02 章 2 节

### Q2：递归查询和迭代查询的区别？

> 答：递归 = 客户端→递归器："查到底，给我最终答案"（工作由递归器承担）；迭代 = 递归器→各级权威："告诉我下一步问谁"（权威只做委派指路，负载极轻）。链路中只有第一跳是递归，后续全是迭代。根服务器能扛全球查询正是因为只做"指路"（+Anycast）。
> 参考：02 章 1/3 节

### Q3：A 记录和 CNAME 的区别？CNAME 的限制？

> 答：A = 域名直接映射 IP（真实地址）；CNAME = 别名指向另一域名（查询时跟随目标再查一次）。限制：① CNAME 不能与其他记录共存于同一名字（尤其不能与 A 同时存在）；② 裸域（example.com）不能设 CNAME（多数权威/解析器行为）；③ CNAME 目标必须是域名（不能是 IP）。用途：CDN 接入（www CNAME → CDN 域名）、服务别名（www → 主域）。
> 参考：03 章 2/5 节

### Q4：MX 记录是干什么的？SPF/DKIM/DMARC 呢？

> 答：MX = 邮件路由（优先级 + 目标域名，数字小优先）；SPF（TXT）= 声明谁允许代发该域邮件；DKIM（TXT）= 邮件签名公钥；DMARC（TXT）= 接收方对未通过 SPF/DKIM 邮件的处理策略（quarantine/reject）。四者共同构成邮件信誉体系——**缺 SPF/DKIM 的域名邮件被拒收率极高**。
> 参考：03 章 3/4 节

### Q5：TTL 是什么？发版前为什么要调小？

> 答：TTL = 记录在各级缓存（浏览器/OS/递归器）中的存活秒数。发版/IP 切换前 1-2 天把 TTL 从 86400 降到 60s：让全球缓存的旧记录"缩水"——切换后 1 分钟内全部生效；切错了 60s 内可回滚。**不降 TTL 直接改记录 = 用户最长 24 小时访问旧 IP**（缓存渐进过期）。
> 参考：05 章 3/4 节

### Q6：DNS 缓存有几级？谁控制时长？

> 答：四级——浏览器缓存、OS 缓存、递归器缓存、权威（数据源不缓存自己）。时长都由 **TTL** 统一控制（各自独立倒计时）。命中越靠客户端越快：浏览器命中 0 网络请求，OS 命中 0 系统外网络，递归命中 1 次 UDP 往返。改 TTL 影响的是"缓存多久"，不是"缓存在哪"。
> 参考：05 章 1 节

### Q7：什么是缓存投毒？Kaminsky 攻击？

> 答：投毒 = 攻击者伪造 DNS 响应，让递归器缓存"错误记录"（用户被导向恶意 IP）。Kaminsky 攻击（2008）：不依赖等目标记录过期——海量查询"随机不存在的子域名"迫使递归器反复向上查询，同时爆破 Transaction ID + 端口，把伪造的 NS 记录塞进缓存 → 整个域被"接管"（比经典投毒危害大得多）。防御：源端口随机化（猜测空间 2^32，现代递归器已防住爆破）+ DNSSEC（根治）。
> 参考：06 章 2/3 节

### Q8：DNSSEC 的原理？为什么部署率低？

> 答：给 DNS 数据加签名验证真实性——DS（父域发子域密钥摘要）→ DNSKEY（域公钥）→ RRSIG（记录签名）逐级验证到根（信任锚）。验证失败 → SERVFAIL（拒绝伪造）。部署率低的原因：密钥轮换复杂、响应变大（依赖 EDNS）、NSEC 枚举问题、托管商支持参差——2026 年全球**校验率 ~36%**、**.com 签名率仅 4-5%**（.nl 60% 是激励成功的样板）。
> 参考：06 章 4/5 节

### Q9：DNS 反射放大攻击？怎么防御？

> 答：攻击者伪造源 IP（=受害者），向**开放递归器**发小查询（如 ANY，~60B），递归器返回大响应（几百 B~KB）→ 放大 30-50× 打向受害者。防御：① 关闭开放递归（只服务授权客户）；② 递归器 RRL（响应限速）；③ 限制 ANY 查询；④ 受害者侧 Anycast 分散 + 清洗。
> 参考：04 章 6 节、06 章 6 节

### Q10：Anycast 是什么？为什么能抗 DDoS？

> 答：同一 IP 通过 BGP 在多个物理地点广播——全球用户自动就近接入（低延迟），攻击流量被分散到最近节点（单点压力下降），且单节点故障无缝接管。部署：根服务器（13 逻辑根 = 1000+ 物理节点）、1.1.1.1（300+ PoP）、CDN 权威。**分散 + 就近 + 自愈**是 DNS 高可用的基石。
> 参考：07 章 1 节

### Q11：GSLB 是什么？和负载均衡的区别？

> 答：GSLB = DNS 层的全局负载均衡：权威根据客户端位置（ECS 子网）动态返回不同机房的 IP，配健康检查自动摘除故障节点。与流量层 LB 的分工：**GSLB 选机房（IP 级），LB 选机器（四层/七层转发）**。切换速度受"探测周期 + TTL"约束——秒级容灾要小 TTL + 快探测 + 多节点冗余。
> 参考：07 章 2/3 节

### Q12：DoH 和 DoT 的区别？2026 年现状？

> 答：DoH（RFC 8484）= DNS over HTTPS，走 443 端口（与 Web 流量混合、难被防火墙识别、穿透性强，浏览器集成）；DoT = DNS over TLS，走独立 853 端口（易被识别阻断，实现简单）；DoQ = DNS over QUIC（低延迟新兴）。2026 现状：全球 DNS 流量约 **20% 已加密**（其余 80% 明文）；Firefox/Chrome 2020 年起默认 DoH；Android DoT 约 15%。
> 参考：07 章 5/6 节

### Q13：公共 DNS 8.8.8.8 和 1.1.1.1 的区别？

> 答：8.8.8.8（Google）：查询量全球第一（>1 万亿次/日），有日志（隐私弱）；1.1.1.1（Cloudflare）：速度最快（中位 <12ms，DNSPerf），无日志，300+ PoP。选型：隐私敏感 → 1.1.1.1/Quad9（安全拦截）；国内 → 阿里 223.5.5.5（节点近）。
> 参考：07 章 4 节

### Q14：K8s 里 DNS 怎么工作？Pod 解析失败怎么排查？

> 答：CoreDNS（Service 暴露）是集群递归器：集群域（service.namespace.svc）权威解析，外部域 forward 到上游。排查顺序：① 分"集群域/外部域"——集群域失败查 Service/namespace（用 FQDN 最稳）；② 外部失败查 Corefile 的 forward 配置与上游可达性；③ 性能问题查 CoreDNS 副本数与 cache 插件。
> 参考：08 章 4 节

### Q15：域名解析慢怎么定位？

> 答：拆链路——`dig +trace` 看哪一跳慢（根/TLD/权威）；`dig @公共递归` 对比（若是权威慢 = 权威问题，若是递归慢 = 递归器问题）；本地命中率低 = TTL 太小或冷启动。常见根因：权威跨运营商访问慢、递归器配置差、EDNS 被中间设备丢弃（UDP 大包回退 TCP 变慢）。
> 参考：08 章 6 节

### Q16：HTTPDNS 解决什么问题？

> 答：移动端绕开运营商 LocalDNS——① 防劫持/污染（LocalDNS 结果不可信）；② 精准调度（ECS 精确到客户端而非递归器位置）；③ 解析质量稳定（直连权威级 API）。移动 App 标配（直播/支付类对解析质量敏感），SDK 集成 + 缓存 + 失败回退传统 DNS。
> 参考：07 章 7 节

### 追问：DNS 解析慢怎么优化？（工程向深挖）

> 答：分链路优化——① 客户端：本地缓存（TTL 内零网络）、预解析（浏览器 prefetch/应用预热）、就近递归器（内网自建 vs 公共）；② 递归器：缓存命中率优化、热点预热、多实例冗余；③ 权威：Anycast 就近（07 章）、低 TTL 结合预取。加分项：冷启动解析风暴的应对（预热 + 限速平滑）、HTTPDNS 绕过 LocalDNS（07 章）。
> 参考：02 章 7 节、07 章

### 追问：运营商 LocalDNS 劫持怎么对抗？

> 答：三层对策——① 检测：对比权威与 LocalDNS 的解析结果（不一致 = 劫持/污染）；② 绕过：HTTPDNS（直连权威级 API，07 章）或 DoH/DoT（加密解析，07 章）；③ 兜底：应用层重试 + 结果校验（证书固定/IP 白名单）。加分项：说明"劫持常见形态"（广告注入/错误 IP/缓存投毒）再给对策。
> 参考：07 章 7 节

### 追问：DNS 与 CDN 的关系？（架构向）

> 答：CDN 的核心调度就是 DNS——域名 NS 指向 CDN 权威，GSLB 按客户端位置（ECS）返回就近节点 IP（07 章 2 节）。所以"接入 CDN" = 改 NS/CNAME 记录；"CDN 节点调整" = 改权威应答（用户感知取决于 TTL）。加分项：DNS 层故障切换速度受 TTL 限制 → 秒级容灾需要 LB 层配合。
> 参考：07 章 2/3 节

### 追问：内网 DNS 和公网 DNS 的设计差异？（架构向）

> 答：三个差异——① 域：内网用保留域（.internal）避免与公网冲突（01 章 7 节）；② 递归：内网自建递归器（低延迟、可控、防 LocalDNS 劫持）；③ 安全：内网解析器不开开放递归（防放大器）、DNSSEC 在内网可简化（信任边界不同）。加分项：K8s 场景的 CoreDNS 形态（集群域权威 + 外部 forward，08 章 4 节）。
> 参考：01 章 7 节、08 章 4 节

### 追问：域名解析"时好时坏"怎么排查？（排障向）

> 答：按三视角对比（08 章 6 节）——① dig @权威（真相）：记录对 → 问题在缓存链；② dig @公共递归（8.8.8.8）：正常 → 问题在本地/运营商；③ dig @本地（默认）：异常 → 本地缓存污染或 LocalDNS 问题。高频根因：负缓存（新记录未生效）、缓存不一致（渐进过期）、运营商劫持（与权威结果不一致）。加分项：分"用户侧"与"权威侧"两个层面回答，并给 30 秒定位流程。
> 参考：08 章 6 节

## 2. 易错点清单

| # | 易错点 | 正确认知 |
|---|--------|---------|
| 1 | "DNS 是中央数据库" | 是**分布式**目录：分层授权 + 缓存 + 委派链 |
| 2 | "递归器是权威" | 递归器替客户端查（可缓存），权威只答自己的域 |
| 3 | "CNAME 可以和 A 共存" | 同一名字上互斥；裸域不能 CNAME |
| 4 | "改记录立即生效" | 生效时间 = TTL 剩余（不降 TTL 最长等一天） |
| 5 | "no-cache 类逻辑适用于 DNS" | DNS 只有 TTL；小 TTL 才快生效（与 HTTP 缓存不同） |
| 6 | "SERVFAIL = 域名不存在" | NXDOMAIN 才是"不存在"；SERVFAIL 是解析失败（权威挂/DNSSEC 错） |
| 7 | "DNSSEC 已普及" | 校验率 ~36%、.com 签名率仅 4-5%——部署前确认托管商支持 |
| 8 | "8.8.8.8 最隐私" | 1.1.1.1 无日志；8.8.8.8 有日志（隐私弱） |
| 9 | "DoT 比 DoH 更难拦截" | 相反：DoT 独立 853 端口易被阻断；DoH 伪装 443 更难拦 |
| 10 | "开放递归 = 服务大众" | 开放递归是反射放大器（关闭只对内/授权） |
| 11 | "Anycast 是 CDN 专利" | 根服务器、公共递归器、权威托管都是 Anycast |
| 12 | "Zone 文件里名字随便写" | 相对名/绝对名（带点）是最常见配置错误源 |

## 3. 知识体系一句话串讲

```text
域名空间（分层树：根→TLD→二级→子域，FQDN 带点）
   │
   ├─ 解析：客户端→递归器（递归）→ 根/TLD/权威（迭代）→ 缓存返回
   │        A/AAAA 定地址 · CNAME 定别名 · MX 定邮件 · NS 定授权
   │
   ├─ 缓存：四级（浏览器/OS/递归器/权威=数据源），TTL 统一时钟
   │        发版/切换：先降 TTL（60s）→ 改记录 → 稳定后恢复
   │
   ├─ 安全：信任模型缺陷（明文无验证）→ 投毒（Kaminsky：随机子域+ID爆破）
   │        随机化防爆破 · DNSSEC 根治（2026 校验率 36%）
   │        DDoS：反射放大（关开放递归+RRL）vs Anycast 分散
   │
   ├─ 高可用：多 NS + Anycast（就近+抗D）+ GSLB（健康检查动态调度）
   │        切换速度 = 探测周期 + TTL
   │
   └─ 隐私与实战：DoH（443 伪装）/DoT（853）/DoQ（QUIC）——2026 加密 20%
                HTTPDNS（移动端绕 LocalDNS）· dig 三视角排障 · CoreDNS
```

## 4. 快速自测（含答案）

1. **解析链路里只有哪一跳是递归？** 客户端→递归器（02 章）。
2. **根服务器为什么扛得住？** 只做委派指路 + Anycast（02/07 章）。
3. **裸域能设 CNAME 吗？** 不能（03 章）。
4. **发版前 TTL 调到多少？** 60s（05 章）。
5. **缓存投毒的防御演进？** 端口随机化（2^32 猜测空间）→ DNSSEC 根治（06 章）。
6. **2026 DNSSEC 校验率？** ~36%（.com 签名率 4-5%）（06 章）。
7. **放大攻击的放大器是？** 开放递归器（04/06 章）。
8. **GSLB 与 LB 的分工？** GSLB 选机房，LB 选机器（07 章）。
9. **DoH 走什么端口？** 443（伪装 HTTPS）（07 章）。
10. **2026 加密 DNS 流量占比？** ~20%（07 章）。
11. **SERVFAIL vs NXDOMAIN？** 解析失败 vs 域名不存在（04/08 章）。
12. **CoreDNS 在 K8s 的角色？** 集群递归器：集群域权威 + 外部 forward（08 章）。
