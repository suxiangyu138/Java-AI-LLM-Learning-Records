## 1. 计算机网络概述

### 1.1 定义与本质

计算机网络是将**地理上分散的、具有独立功能的多台计算机**（及其他网络设备），通过**通信线路和通信设备**连接起来，在网络操作系统、网络协议及网络管理软件的协调下，实现**资源共享**和**信息传递**的系统。

> 💡 网络的价值在于"连接"与"协同"——单台设备的功能有限，通过网络将设备联动，可突破地理限制、提升效率。

### 1.2 核心关键点

| 序号 | 关键点 | 说明 |
|:----:|--------|------|
| 1 | 多台独立设备 | 不是单台计算机，而是多台具备独立处理能力的设备互联 |
| 2 | 连接介质+协议 | 硬件（网线/光纤/无线）+ 软件（TCP/IP等协议）缺一不可 |
| 3 | 资源共享 | 文件、硬件（打印机）、软件等资源的共用 |
| 4 | 信息传递 | 数据、消息在不同设备间的传输 |

### 1.3 网络的主要功能

| 功能 | 说明 | 后端典型场景 |
|------|------|--------------|
| 资源共享 | 硬件/软件/数据共享 | 多台服务器共用一台打印机；数据库共享 |
| 数据通信 | 电子邮件、文件传输、视频通话等 | HTTP接口调用、RPC服务通信 |
| 分布式处理 | 多台计算机协同完成任务 | 大型网站的服务器集群、云计算 |
| 负载均衡 | 流量分配到多台设备 | Nginx分发请求到多台后端服务器 |
| 提高可靠性 | 一台故障，其他计算机替代工作 | 主备切换、多副本部署 |

### 1.4 网络性能指标

| 指标 | 说明 | 单位 |
|------|------|------|
| 带宽（Bandwidth） | 信道能传输的最高数据率 | bps（如 100Mbps、1Gbps） |
| 吞吐量（Throughput） | 单位时间内实际传输的数据量 | bps（吞吐量 ≤ 带宽） |
| 时延（Delay） | 发送时延 + 传播时延 + 处理时延 + 排队时延 | ms |
| 时延带宽积 | 时延 × 带宽，链路的"管道容量" | bit |
| 往返时间（RTT） | 数据从发送到收到确认的总时间 | ms（TCP超时重传的关键参数） |
| 丢包率 | 丢失包数量 / 总发送包数量 | % |
| 利用率 | 信道占用时间比例 | %（过高导致排队时延剧增） |

> ⚠️ **带宽 vs 延迟**：带宽影响"传输速度"（下载快慢），延迟影响"响应速度"（游戏流畅度）。**高带宽 ≠ 低延迟**。

### 1.5 协议的三要素

| 要素 | 说明 |
|------|------|
| 语法（Syntax） | 数据与控制信息的结构或格式（如报文格式、字段定义） |
| 语义（Semantics） | 需要发出何种控制信息，完成何种动作以及做出何种响应 |
| 同步（Timing） | 事件实现顺序的详细说明（如先发SYN再发ACK） |

### 1.6 网络核心与网络边缘

计算机网络在组成上可以分为网络核心和网络边缘两部分：

| 组成部分 | 说明 | 典型设备/技术 |
|----------|------|---------------|
| 网络边缘 | 用户直接使用的设备和应用 | PC、手机、服务器、IoT设备 |
| 接入网 | 边缘设备连接到网络核心的链路 | DSL、光纤宽带、WiFi、4G/5G |
| 网络核心 | 由分组交换机和链路构成的骨干网 | 路由器、交换机、光纤骨干 |

### 1.7 分组交换 vs 电路交换

| 对比维度 | 分组交换（Packet Switching） | 电路交换（Circuit Switching） |
|----------|:--------------------------:|:---------------------------:|
| 基本原理 | 数据分割为包，存储转发 | 建立专用物理线路 |
| 资源分配 | 按需共享（统计复用） | 预先分配（独占资源） |
| 连接建立 | 无需提前建立连接 | 需要建立连接（拨号） |
| 线路利用率 | 高（资源共享） | 低（空闲时也占用） |
| 时延特性 | 存在排队时延，不确定 | 固定时延，无排队 |
| 适用场景 | 互联网数据通信 | 传统电话网络 |
| 典型代表 | IP网络、以太网 | PSTN、ISDN |

> 💡 计算机网络使用**分组交换**，而传统电话网络使用电路交换。分组交换的统计复用特性使得网络资源利用率更高，但会引入排队时延和丢包风险。

### 1.8 网络性能的时延分析

时延由以下四个部分构成：

```
总时延 = 发送时延 + 传播时延 + 处理时延 + 排队时延

  发送时延 = 数据帧长度 / 发送速率
  传播时延 = 信道长度 / 电磁波传播速率
  处理时延 = 路由器检查头部、查路由表的时间
  排队时延 = 在路由器队列中等待转发的时间
```

| 时延类型 | 影响因素 | 优化方向 |
|----------|----------|----------|
| 发送时延 | 数据大小、接口速率 | 提升带宽、压缩数据 |
| 传播时延 | 物理距离、介质类型 | 降低物理距离（CDN） |
| 处理时延 | 路由器性能 | 升级硬件、优化路由表 |
| 排队时延 | 网络拥塞程度 | 流量控制、QoS |

> ⚠️ **关键结论**：时延带宽积 = 时延 × 带宽，表示链路上能容纳的最大比特数。理解这个公式对于分析TCP吞吐量至关重要。

## 2. OSI七层模型

### 2.1 分层模型总览

OSI（Open System Interconnection）七层参考模型是国际标准化组织（ISO）制定的理论标准，从下到上依次为：

```
 7 │ 应用层（Application）
 6 │ 表示层（Presentation）
 5 │ 会话层（Session）
 4 │ 传输层（Transport）
 3 │ 网络层（Network）
 2 │ 数据链路层（Data Link）
 1 │ 物理层（Physical）
```

> 💡 **记忆口诀**：All People Seem To Need Data Processing（应用-表示-会话-传输-网络-数据链路-物理）

### 2.2 各层详细说明

| 层次 | 功能描述 | 核心协议/设备 | PDU（协议数据单元） |
|:----:|----------|---------------|:-------------------:|
| 7 应用层 | 为用户程序提供网络服务接口 | HTTP、FTP、SMTP、DNS、SSH | 报文（Message） |
| 6 表示层 | 数据格式转换、加密解密、压缩 | JPEG、ASCII、SSL/TLS | 报文（Message） |
| 5 会话层 | 建立/管理/终止会话，同步 | NetBIOS、RPC | 报文（Message） |
| 4 传输层 | 端到端可靠/不可靠传输、差错控制、流量控制 | TCP、UDP | 段（Segment） |
| 3 网络层 | 路由选择、拥塞控制、跨网络寻址 | IP、ICMP、ARP、路由器 | 包/数据报（Packet） |
| 2 数据链路层 | 相邻节点间可靠传输、成帧、差错检测 | Ethernet、PPP、交换机 | 帧（Frame） |
| 1 物理层 | 在物理介质上传输比特，定义电气/机械特性 | 集线器、中继器、网线 | 比特（Bit） |

### 2.3 各层核心协议与设备详解

| 层次 | 典型协议 | 典型设备 | 核心功能 | 常见故障现象 |
|:----:|----------|----------|----------|-------------|
| 7 应用层 | HTTP、HTTPS、DNS、FTP、SMTP、SSH | 应用层网关、防火墙 | Web服务、文件传输、邮件 | 接口超时、404/500错误 |
| 6 表示层 | SSL/TLS、JPEG、ASCII | — | 加密解密、数据格式转换 | HTTPS证书错误、乱码 |
| 5 会话层 | RPC、NetBIOS、NFS | — | 会话建立、同步、管理 | RPC调用失败、会话超时 |
| 4 传输层 | TCP、UDP | 四层负载均衡器 | 可靠/不可靠传输、流量控制 | 连接超时、端口不通 |
| 3 网络层 | IP、ICMP、ARP、OSPF、BGP | 路由器、三层交换机 | 路由选择、IP寻址 | ping不通、路由不可达 |
| 2 数据链路层 | Ethernet、PPP、VLAN（802.1Q） | 交换机、网卡 | 帧传输、MAC寻址 | MAC冲突、ARP异常 |
| 1 物理层 | 10Base-T、1000Base-T、光纤 | 集线器、中继器、Modem | 比特流传输 | 网线松动、信号衰减 |

### 2.4 分层的意义

> 💡 将复杂的网络功能划分为若干层，每层实现特定的功能，层与层之间通过接口通信。分层设计降低了系统复杂性，便于开发、维护和标准化。每一层只关注自己的职责，为上层提供服务，调用下层的能力。

## 3. TCPIP四层五层模型

### 3.1 TCP/IP四层模型（实际应用标准）

TCP/IP模型是互联网实际使用的协议体系，比OSI更精简：

```
┌───────────────┬──────────────────────────────────┬─────────────────┐
│    层次        │              功能                 │   Java对应       │
├───────────────┼──────────────────────────────────┼─────────────────┤
│   应用层       │ HTTP / DNS / FTP / SMTP          │ HttpURLConnection│
│   传输层       │ TCP / UDP                        │ Socket           │
│   网际层       │ IP / ICMP / 路由                  │ InetAddress      │
│   网络接口层   │ MAC / ARP / 以太网                │ —               │
└───────────────┴──────────────────────────────────┴─────────────────┘
```

### 3.2 OSI与TCP/IP对比

| 对比维度 | OSI七层模型 | TCP/IP四层模型 |
|----------|-------------|----------------|
| 制定时间 | 先于协议出现（理论先行） | 后于协议出现（实践先行） |
| 层次数量 | 7层 | 4层 |
| 会话层/表示层 | 独立层次 | 合并到应用层 |
| 物理层/数据链路层 | 独立层次 | 合并为网络接口层 |
| 使用范围 | 理论参考模型 | 互联网实际标准 |
| 协议关系 | 通用框架 | 以TCP/IP协议族为核心 |

### 3.3 五层参考模型（教学推荐模型）

五层模型是OSI和TCP/IP的折中方案，贯穿后续所有章节的分析框架：

```
应用层 → 传输层 → 网络层 → 数据链路层 → 物理层
```

**各层关键协议速查表：**

| 层次 | 核心协议 | 一句话概括 |
|------|----------|-----------|
| 应用层 | HTTP、HTTPS、DNS、FTP、SMTP | 具体应用服务 |
| 传输层 | TCP（可靠）、UDP（高效） | 端到端传输 |
| 网络层 | IP、ICMP、ARP | 寻址与路由 |
| 数据链路层 | Ethernet、WiFi、PPP | 局域网帧传输 |
| 物理层 | 传输介质、编码 | 原始比特流传输 |

> 🎯 **学习建议**：五层模型要能画出每一层及对应协议，面试高频题"输入URL到页面显示的全过程"涉及所有层。

### 3.4 各层核心协议一览

| 层次 | 协议 | 关键功能 |
|------|------|----------|
| 应用层 | HTTP/1.1, HTTP/2, HTTP/3, WebSocket, DNS | 应用数据传输 |
| 传输层 | TCP（可靠）、UDP（快速） | 端到端传输 |
| 网络层 | IP、ICMP、ARP | 寻址与路由 |
| 链路层 | Ethernet、WiFi | 局域网帧传输 |

## 4. 网络的分类与拓扑结构

### 4.1 按地理覆盖范围划分

| 网络类型 | 英文 | 覆盖范围 | 典型场景 | 核心特点 |
|----------|------|----------|----------|----------|
| 个人区域网 | PAN | 10m以内 | 蓝牙耳机、智能手表 | 短距离无线 |
| 局域网 | LAN | 1km以内 | 家庭、办公室、学校机房 | 速率高、延迟低、成本低 |
| 城域网 | MAN | 1km ~ 100km | 城市宽带骨干网 | 速率介于LAN和WAN之间 |
| 广域网 | WAN | 100km以上 | 互联网、企业跨区域专网 | 速率较低、延迟较高 |

> ⚠️ **常见误区**："网络 = 互联网"是错误的。互联网是最大的广域网，网络包含局域网、城域网、广域网等。

### 4.2 按拓扑结构划分

| 拓扑类型 | 连接方式 | 优点 | 缺点 | 现状 |
|----------|----------|------|------|------|
| 星型拓扑 | 所有设备连接到核心设备（交换机） | 结构简单、故障排查容易 | 核心设备故障导致全网瘫痪 | **最常用** |
| 总线型拓扑 | 所有设备连接到一条主干线缆 | 成本低、布线简单 | 总线故障全网瘫痪 | 几乎淘汰 |
| 环型拓扑 | 设备依次连接成闭合环 | 结构稳定、传输延迟均匀 | 单点故障导致全网中断 | 很少使用 |
| 网状拓扑 | 设备之间多对多连接 | 可靠性极高、无单点故障 | 布线复杂、成本高 | 广域网骨干网 |
| 树型拓扑 | 层次结构、分级管理 | 易于扩展、集中管理 | 根节点故障影响大 | 校园网 |

### 4.3 按传输介质划分

| 介质类型 | 优点 | 缺点 | 适用场景 |
|----------|------|------|----------|
| 双绞线（网线）STP/UTP | 成本低、部署方便 | 传输距离有限（≤100m） | 家庭、办公室局域网 |
| 同轴电缆 | 抗干扰能力较强 | 带宽有限 | 有线电视（逐渐被替代） |
| 光纤（单模/多模） | 速率极高、距离远、抗干扰 | 成本高、易折断 | 骨干网、核心网、IDC |
| 无线（WiFi/4G/5G/蓝牙） | 灵活、移动方便 | 稳定性受环境干扰 | 移动设备、无线覆盖 |

### 4.4 其他分类维度

| 分类维度 | 类型 |
|----------|------|
| 按传输技术 | 广播式网络（共享信道）、点对点网络（专用链路） |
| 按使用对象 | 公用网络（互联网）、专用网络（企业内网/政府专网） |

## 5. 核心网络设备

### 5.1 设备分层与功能对比

| 设备 | 工作层次 | 核心功能 | 通俗理解 | 常见场景 |
|------|----------|----------|----------|----------|
| 集线器（Hub） | 物理层 | 信号放大和广播转发（已基本被替代） | 信号"扩音器" | 已被交换机取代 |
| 交换机（Switch） | 数据链路层 | 根据MAC地址转发帧，每个端口独占带宽 | 局域网的"数据中转站" | 办公室多台电脑互连 |
| 路由器（Router） | 网络层 | 路由选择、跨网络互联、NAT转换 | 网络的"交通指挥" | 家庭/企业连接互联网 |
| 无线AP | 数据链路层 | 有线信号 ↔ 无线信号转换 | WiFi信号发射器 | 商场、办公室无线覆盖 |
| 调制解调器（Modem） | 物理层 | 数字信号 ↔ 模拟信号转换 | 宽带"翻译官" | 家用宽带连接 |
| 网关（Gateway） | 多层 | 协议转换、连接异构网络 | 不同网络的"翻译" | 企业网络出口 |
| 防火墙 | 网络层/应用层 | 非法流量过滤 | 网络的"安保" | 网络安全边界 |

> ⚠️ **交换机 vs 路由器**：交换机连接局域网内设备，根据MAC地址转发；路由器连接不同网络，根据IP地址转发。两者分工不同，切勿混淆。

### 5.2 交换技术与转发方式

| 技术 | 说明 |
|------|------|
| 分组交换（Packet Switching） | 当前主流，数据分割为包独立传输 |
| 电路交换（Circuit Switching） | 建立专用线路，如传统电话网络 |
| 报文交换（Message Switching） | 完整报文逐跳转发 |

## 6. 数据封装与解封装

### 6.1 封装过程（发送方，自上而下）

数据从应用层产生，每经过一层就添加该层的头部，如同"俄罗斯套娃"：

```
发送方（自上而下封装）：

    应用层数据
          │
          ▼
    ┌─────────────┐
    │  应用层报文  │
    └──────┬──────┘
           │  TCP头
           ▼
    ┌─────────────┐
    │ TCP头 │ 数据│  ← 传输层段（Segment）
    └──────┬──────┘
           │  IP头
           ▼
    ┌─────────────┐
    │IP头│TCP头│数据│  ← 网络层数据报（Datagram）
    └──────┬──────┘
           │  MAC头 + MAC尾
           ▼
    ┌──────────────────────┐
    │MAC头│IP头│TCP头│数据│CRC│  ← 链路层帧（Frame）
    └──────┬───────────────┘
           │  编码成比特
           ▼
    ┌──────────────────────────┐
    │  010110101011001010...   │  ← 物理层比特流（Bit）
    └──────────────────────────┘
```

### 6.2 解封装过程（接收方，自下而上）

```
接收方（自下而上解封装）：

    ┌──────────────────────────┐
    │  010110101011001010...   │  物理层比特流
    └──────────┬───────────────┘
               │  检帧头尾、CRC校验
               ▼
    ┌──────────────────────┐
    │MAC头│IP头│TCP头│数据│CRC│  链路层剥帧头帧尾
    └──────┬───────────────┘
           │  剥IP头
           ▼
    ┌─────────────┐
    │ TCP头 │ 数据│  网络层剥IP头
    └──────┬──────┘
           │  剥TCP头
           ▼
    ┌─────────────┐
    │  应用层报文  │  传输层剥TCP头
    └─────────────┘
```

### 6.3 各层PDU（协议数据单元）与封装单位

| 层次 | PDU名称 | 封装内容 | 头部信息 |
|:----:|:-------:|----------|----------|
| 应用层 | 报文（Message） | 用户数据 | — |
| 传输层 | 段（Segment） | TCP/UDP头 + 数据 | 源端口、目的端口、序列号等 |
| 网络层 | 数据报（Datagram） | IP头 + 传输层数据 | 源IP、目的IP、TTL等 |
| 数据链路层 | 帧（Frame） | MAC头 + IP数据报 + CRC | 源MAC、目的MAC、类型等 |
| 物理层 | 比特（Bit） | 原始二进制流 | — |

> 🎯 **核心理解**：每一层只看和自己同层的头部，这就是分层设计的精髓——解耦。下层为上层提供服务，上层无需关心下层的实现细节。

## 7. 核心网络概念与术语

### 7.1 关键技术术语

| 术语 | 定义 | 单位 | 通俗理解 |
|------|------|:----:|----------|
| 带宽（Bandwidth） | 单位时间可传输的最大数据量 | Mbps/Gbps | 水管粗细，决定下载速度 |
| 延迟（Latency） | 数据从源到目标的传输时间 | ms | 响应快慢，影响游戏/通话体验 |
| 吞吐量（Throughput） | 实际传输的数据量 | bps | 实际水流速度 |
| RTT（往返时间） | 数据发出到收到确认的往返时间 | ms | 发一个包到收到回复的时间 |
| MTU（最大传输单元） | 链路层帧能承载的最大数据量 | 字节 | 以太网标准MTU = 1500字节 |
| MSS（最大报文段长度） | TCP段能承载的最大数据量 | 字节 | MSS = MTU - IP头(20) - TCP头(20) = 1460 |
| PDU（协议数据单元） | 每层处理的数据单位 | — | 段/包/帧/报文 |
| TTL（生存时间） | IP数据报的最大跳数 | 跳 | 防止数据报无限循环（每经一跳减1） |
| 网关（Gateway） | 连接不同网络的关口设备 | — | 局域网访问外网的"出口" |
| 子网掩码 | 区分IP地址的网络位和主机位 | — | 判断两台设备是否在同一网段 |
| 防火墙 | 保护网络安全的设备/软件 | — | 阻止非法访问，允许合法流量 |
| NAT | 网络地址转换（私有↔公有IP） | — | 解决IPv4地址短缺 |
| DHCP | 动态主机配置协议 | — | 自动分配IP地址、网关、DNS |
| DNS | 域名系统 | — | 域名→IP地址的"网络通讯录" |
| 广播域 | 广播帧能到达的范围 | — | 路由器隔离广播域 |
| 冲突域 | 可能发生冲突的范围 | — | 交换机隔离冲突域 |

### 7.2 协议与服务的区别

| 对比项 | 协议（Protocol） | 服务（Service） |
|--------|------------------|-----------------|
| 方向 | 水平——同一层次间对等实体通信的规则 | 垂直——本层为上层提供的功能 |
| 内容 | 语法 + 语义 + 时序 | 通过层间接口（SAP服务访问点）调用 |
| 本质 | 通信规则 | 功能提供 |
| 关系 | 协议的实现支撑服务的提供 | 服务的使用需依赖协议的协商 |

### 7.3 网络服务模式

| 模式 | 说明 | 示例 |
|------|------|------|
| 面向连接 | 传输前建立连接，传输后释放 | TCP（三次握手） |
| 无连接 | 直接发送数据，无需建立连接 | UDP、IP |
| 可靠传输 | 确认、重传、保证有序到达 | TCP |
| 不可靠传输 | 尽力而为、不保证到达 | UDP、IP |

### 7.4 信道工作方式

| 信道类型 | 方向性 | 示例 |
|----------|--------|------|
| 单工信信道（Simplex） | 只能单向传输 | 广播、电视 |
| 半双工信信道（Half-Duplex） | 可双向，同一时刻只能单向 | 对讲机 |
| 全双工信信道（Full-Duplex） | 可同时双向传输 | 电话、以太网 |

### 7.5 多路复用技术

| 技术 | 原理 | 应用 |
|------|------|------|
| 频分多路复用（FDM） | 划分不同频带 | 有线电视、WiFi信道 |
| 时分多路复用（TDM） | 划分不同时隙 | 电话网络 |
| 波分多路复用（WDM） | 光的频分复用 | 光纤通信 |
| 码分多路复用（CDM） | 不同的码片序列 | CDMA移动通信 |

### 7.6 易于混淆的概念辨析

| 误区 | 正解 |
|------|------|
| "网络 = 互联网" | 互联网是最大的广域网，网络包含LAN/MAN/WAN/PAN |
| "交换机 = 路由器" | 交换机连接局域网内设备；路由器连接不同网络 |
| "TCP比UDP更好" | 按需使用：可靠传输用TCP，实时性要求高用UDP |
| "IP地址是固定的" | 家用设备通常动态分配（DHCP）；服务器通常是静态IP |
| "带宽越高，延迟越低" | 二者无直接关联，高带宽也可能高延迟 |
| "集线器和交换机一样" | 集线器共享带宽（半双工），交换机每个端口独占带宽（全双工） |

### 7.7 知识体系速查

**网络分类速查：**
```
地理范围：PAN → LAN → MAN → WAN
传输介质：有线（双绞线/光纤/同轴）↔ 无线（WiFi/蓝牙/蜂窝）
拓扑结构：星型 → 总线型 → 环型 → 网状 → 树型
```

**网络设备和协议速查：**
```
设备  ： 集线器(物理) → 交换机(链路) → 路由器(网络) → 应用层(网关/防火墙)
PDU   ： 比特(物理) → 帧(链路) → 包(网络) → 段(传输) → 报文(应用)
```

**记忆口诀：**
```
网络本质：硬件搭台，协议唱戏
协议分层：应传网链物（应用-传输-网络-链路-物理）
TCP vs UDP：要稳选TCP，要快选UDP
带宽 vs 延迟：带宽管快慢，延迟管早晚
```

> 🎯 **本章总结**：计算机网络体系结构是一切网络知识的框架。五层模型（应用层 → 传输层 → 网络层 → 数据链路层 → 物理层）是贯穿所有网络知识的核心。数据封装与解封装过程是理解网络传输的核心——像"俄罗斯套娃"，每层添加自己的头部。核心网络设备（交换机、路由器）工作在不同层次，完成不同的转发任务。理解这些基础概念是深入学习各层协议的前提。
