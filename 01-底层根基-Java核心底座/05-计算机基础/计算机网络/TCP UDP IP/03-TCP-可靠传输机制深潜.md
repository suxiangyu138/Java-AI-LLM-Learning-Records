# TCP 可靠传输机制深潜

> TCP 的可靠 = 确认 + 重传 + 窗口三件套：累积确认（SACK 打破限制）、超时重传（RTT 估计的精度决定一切）、滑动窗口（接收方能力通告）。流量控制管"接收方装不装得下"，拥塞控制管"网络扛不扛得住"——先分清这两个窗口，机制才不会混

## 1. 可靠传输的三件套

```text
可靠 = 不丢、不错、不乱
  TCP 的实现：
  ① 确认（ACK）：接收方报告"收到了哪些字节"
  ② 重传（RTO/Fast）：发送方发现丢失就补发
  ③ 窗口（滑动）：控制发送节奏（流量控制）

完整链路：
  发送方：发送窗口内的数据 → 等 ACK → 收到后窗口前移
  接收方：接收窗口内的数据 → 乱序暂存 → 连续后交付应用 → 回 ACK
```

## 2. 确认机制：累积确认与 SACK

### 2.1 累积确认的语义与缺陷

```text
ACK = N：N 之前的字节全部收到（01 章）

缺陷（丢包场景）：
  发送：段1 段2 段3（seq 1/1461/2921）
  网络：段2 丢失
  接收：收到段1、段3 → 段3 乱序暂存
       ACK 仍回 ack=1461（期望段2）——即使段3 已收到！
  发送：重传段2 后，段3 才被确认（累积式：ack 追到 4381）
  → 段3 白等一个 RTT；若段3 也"丢"（只是慢），会与重传段2 一起到 → 浪费

  问题本质：累积确认"知道丢了哪个"，但"不知道哪个没丢"
```

### 2.2 SACK：选择性确认

```text
SACK（Selective ACK，RFC 2018）：
  接收方在 ACK 中附带"已收到的乱序块"：
    ack=1461, SACK: 2921-4380
  → 发送方明确知道：段2 丢了，段3 已收到
  → 只重传段2，段3 不重传 → 一次 RTT 内恢复

DSACK（RFC 2883）：
  报告"重复收到的块"（帮助发送方识别重传是否必要）
  → 判断网络是否存在"乱序导致的伪重传"

现代内核：SACK 默认开启（无 SACK 时回退累积确认+快速重传）
```

> 🎯 **核心要点**：SACK 让"丢包恢复"从"等一个 RTT 全量确认"变成"精确重传"——高丢包链路上（移动网络/跨洋）吞吐差距可达数倍。抓包看 `SACK` 标志确认是否生效。

## 3. 重传机制：超时重传与快速重传

### 3.1 超时重传（RTO）

```text
触发：发送后 RTO 超时未收到 ACK → 重传
代价：一个 RTO（通常 200ms+）的空等 —— 慢
现代改进（RFC 6298）：
  首次重传后 RTO 指数退避（×2）→ 防网络已拥塞时雪上加霜
  时间戳选项辅助：无数据段也可测 RTT
```

### 3.2 快速重传（Fast Retransmit）

```text
触发：连续收到 3 个重复 ACK（DupACK）
  → 说明"后面的数据都到了，就这个丢了"——网络没堵，只是丢了一包
  → 不等 RTO，立即重传 → 从 RTO 级（200ms+）降到 RTT 级（几十 ms）

配合快速恢复（Fast Recovery）：
  进入快速恢复后 cwnd 减半（而非慢启动归 1）
  → 用"线性增长"恢复，吞吐损失最小（04 章拥塞控制细化）

3 个 DupACK 的阈值由来：1-2 个 DupACK 可能是乱序（到达即确认），
3 个才判定"真丢了"
```

| 机制 | 触发 | 速度 | 适用 |
|------|------|:---:|------|
| 超时重传 | RTO 到期 | 慢（200ms+） | 整段丢失无任何线索 |
| 快速重传 | 3 个 DupACK | 快（RTT 级） | 单段丢失（其余在流动） |
| SACK 重传 | SACK 报告精确块 | 最快 | 多段丢失 |

## 4. RTT 估计：重传定时器的精度

```text
RTO 必须 > 实际 RTT，但又不能太大（否则重传太慢）
→ 动态估计：

  SRTT（平滑 RTT）= (1−α)·SRTT + α·RTT        （α=1/8）
  RTTVAR（抖动）= (1−β)·RTTVAR + β·|RTT−SRTT| （β=1/4）
  RTO = SRTT + 4×RTTVAR（下限 1s，RFC 6298）

Karn 算法（重传歧义）：
  重传后的 RTT 样本不可信（无法区分"原段"还是"重传段"的确认）
  → 重传期间不使用该样本更新 RTT；下次成功传输再启用

时间戳选项（TS）：让每个 ACK 携带精确 RTT（重传歧义也随之消失）
  → 现代高带宽网络 RTO 精度大幅提升
```

## 5. 滑动窗口与流量控制

### 5.1 机制

```text
接收方在 ACK 中通告"还能收多少"（窗口大小，01 章首部 16 位）
发送方：未确认字节数 ≤ 通告窗口 → 可连续发送（流水线）

  ┌────── 已确认 ──────┬───── 已发送未确认 ─────┬── 未发送（窗口内）──┬─ 窗口外 ─┐
  发送窗口随 ACK 前移：
  收到 ack + 新窗口 → 发送窗口前移 → 继续发送新数据

窗口的意义：不用"发一包等一包"（停止等待的吞吐灾难）——
  窗口 = N 包流水线，吞吐提升 N 倍
```

### 5.2 窗口缩放（Window Scaling）

```text
问题：窗口字段只有 16 位（最大 65535 字节）
  → 高带宽长时延（BDP 大）下窗口不够用（08 章 BDP 计算）

解法：握手期协商缩放因子（Shift Count，0-14）
  实际窗口 = 16 位值 × 2^Shift
  例：shift=7 → 窗口最大 ~8MB
现代内核默认启用（ss -tin 看 wscale）
```

## 6. 零窗口与糊涂窗口

| 问题 | 场景 | 机制 |
|------|------|------|
| **零窗口** | 接收方缓冲耗尽 → 通告窗口=0 → 发送方停发 | 发送方定期发**窗口探测**（1 字节）；接收方缓冲恢复后回更新窗口 |
| **糊涂窗口** | 应用读得很慢 → 窗口一点点释放 → 双方互传小包（几十字节） | 发送方：Nagle 算法合包（并发体系 06 章）；接收方：窗口积累到 MSS/2 或缓冲一半才通告 |

```text
糊涂窗口的双方对策：
  发送侧：Nagle（小包合并，交互场景用 TCP_NODELAY 关闭）
  接收侧：推迟通告（窗口不足阈值不更新）—— 现代内核默认
```

## 7. 流量控制 vs 拥塞控制

| 维度 | 流量控制（接收窗口） | 拥塞控制（拥塞窗口 cwnd） |
|------|:---:|:---:|
| 管什么 | **接收方**能不能装下 | **网络**能不能扛住 |
| 依据 | 接收方通告（rwnd） | 丢包/延迟信号（自测） |
| 窗口 | 接收窗口 rwnd（16 位+缩放） | 拥塞窗口 cwnd（内核维护） |
| 谁的视角 | 点对点（两端都知道） | 全网（发送方推测） |
| 生效 | 每次 ACK 通告 | 算法动态调整（04 章） |

```text
发送上限 = min(rwnd, cwnd)
  接收方慢 → rwnd 小（应用读得慢）
  网络差 → cwnd 小（丢包/拥塞）
  两者独立调节，共同约束发送节奏
```

> 🎯 **核心要点**：面试答"滑动窗口"先问清是哪个窗口——接收窗口（流量控制，通告制）与拥塞窗口（拥塞控制，自测制）是两套机制，合流于"发送上限 = min 二者"。

## 8. 可靠传输的工程排查实战

### 8.1 重传问题的定位流程

```text
症状：吞吐低/时延高/连接假死

排查步骤：
  ① 抓包统计重传率：tcpdump + Wireshark（07 章）
  ② 区分重传类型：
     RTO 重传（间隔 200ms+ 指数）→ 链路丢包严重
     快速重传（3 DupACK）→ 单段丢失（浅缓冲/拥塞）
     SACK 重传 → 精确恢复（正常机制，说明 SACK 生效）
  ③ 链路层定位：ping 丢包率、中间设备（traceroute）
  ④ 归因：链路质量 / 拥塞（算法，04 章）/ 中间设备（MSS/防火墙）
```

### 8.2 常见"伪重传"场景

| 场景 | 现象 | 真相 |
|------|------|------|
| 网络乱序 | 看起来像重传（seq 重复） | 非丢包：乱序到达（Wireshark 标 Out-of-Order） |
| 路径切换 | 突然重传风暴 | LB/多路径漂移（连接迁移到慢路径） |
| 缓冲溢出 | 周期性重传 | 中间设备队列满（bufferbloat，04 章） |
| 应用慢读 | 窗口变小而非重传 | 接收方问题（07 章窗口信号） |

```text
判断口诀（07 章重申）：乱序不重传、重传才是丢；
  但"看起来像重传"要先排除乱序与路径切换
```

### 8.3 可靠性的协议层对照

```text
TCP 的可靠 = 端到端重传（浪费带宽换简单）
QUIC 的可靠 = 流级独立（丢包只重传该流，HTTP/3 体系）
UDP + 应用层 = 应用自管（选择性重传/FEC，05 章）
→ 可靠性设计是"重传粒度"的权衡：粒度越细，恢复越快，代价越复杂
```

## 9. 核心要点与思考题

> 🎯 **本章三句话总结**：
> 1. 可靠三件套：累积确认（SACK 精确化）、超时重传（RTO 动态估计 + Karn 防歧义）、快速重传（3 DupACK 触发，RTT 级恢复）；
> 2. 滑动窗口 = 接收方能力通告（rwnd），窗口缩放选项让高 BDP 场景可用；
> 3. 流量控制管接收方、拥塞控制管网——发送上限 = min(rwnd, cwnd)。
