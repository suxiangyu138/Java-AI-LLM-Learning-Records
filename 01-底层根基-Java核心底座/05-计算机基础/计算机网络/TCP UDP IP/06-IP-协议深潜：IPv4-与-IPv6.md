## 1. IP 的职责：寻址、分片、尽力而为

```text
IP（网络层）的三大职责：
  ① 寻址：全球唯一的地址标识（IPv4 32 位 / IPv6 128 位）
  ② 分片：报文超过链路 MTU 时拆分（IPv4 中间设备可分；IPv6 仅源端）
  ③ 尽力而为：不可靠交付（丢包由上层 TCP/UDP 应用处理）

与 TCP 的分工：
  IP 找路（路由表逐跳转发）
  TCP 管送达（端到端确认重传）
  → "IP 是邮政系统，TCP 是挂号信"

2026 现实：IPv4 地址池早已耗尽
  IANA 池 2011 年耗尽；RIPE NCC（欧洲）2019 年耗尽
  → NAT 遍地、IPv6 成为唯一增量出路
```

## 2. IPv4 报文结构与分片

### 2.1 报文结构（核心字段）

```text
 0                   1                   2                   3
├─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┤
│版本│ 首部长度 │  服务类型   │           总长度              │
├─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┤
│      标识（16）          │标志│     片偏移（13）           │
├─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┤
│   生存时间 TTL（8）      │ 协议号（8）   │   首部校验和      │
├─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┤
│                    源 IP 地址（32）                        │
├─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┤
│                    目的 IP 地址（32）                       │
└─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┘
```

| 字段 | 作用 |
|------|------|
| 版本/首部长度 | IPv4 / 首部长度（单位 4 字节） |
| 总长度 | 首部+数据（最大 65535） |
| 标识/标志/片偏移 | **分片三件套**（重组依据） |
| TTL | 每跳减 1，为 0 丢弃（防环路；`traceroute` 靠它） |
| 协议号 | 上层协议（6=TCP，17=UDP） |
| 源/目的地址 | 32 位 |

### 2.2 分片机制

```text
触发：报文 > 出接口 MTU → 路由器拆分（IPv4 允许中间分片）
规则：
  标识相同 → 属于同一原始报文
  标志 MF=1 → 后面还有分片；MF=0 → 最后一片
  片偏移 → 数据在原报文中的位置（单位 8 字节）

分片的代价（为什么要避免）：
  ① 任一分片丢失 → 整包无法重组 → 上层重传整包（更糟）
  ② 分片报文易被防火墙/IDS 丢弃（安全设备常见策略）
  ③ 性能：中间设备 CPU 负担

避免：端到端 PMTUD / 应用控制报文 < MTU
```

## 3. MTU 与 PMTUD

```text
MTU（最大传输单元）：链路层能承载的最大报文
  以太网：1500 字节（IP 层可用 1500）
  隧道（GRE/VXLAN/PPPoE）：更小（1400-1450 常见）

PMTUD（路径 MTU 发现）：
  发送端设置 DF 标志（不分片）→ 途中小 MTU 链路回 ICMP
  "Fragmentation Needed"（Type 3 Code 4）→ 发送端调小
  现代补充：PLPMTUD（丢包探测法，不依赖 ICMP——ICMP 常被防火墙拦）

工程要点：
  ⚠️ MSS = MTU − 40（IPv4）或 − 60（IPv6）——抓包常见 1460/1400
  VPN/隧道环境下 MSS 钳制（tcp mss clamp）是常见故障点：
    隧道 MTU 1400，TCP 仍按 1460 发 → 分片被丢 → 连接假死
    → 隧道设备做 MSS 钳制：SYN 里改写 MSS 为 1360
```

> 🎯 **核心要点**：MTU/MSS 错配是"能 ping 通但 HTTP 打不开"的头号原因——PMTUD 被 ICMP 拦截 + MSS 未钳制 = 大包死、小包活。

## 4. CIDR、子网与 NAT

### 4.1 CIDR 表示

```text
CIDR（无类域间路由）：IP/前缀长度
  192.168.1.0/24 → 前 24 位网络号，后 8 位主机号（256 地址）
  10.0.0.0/8 → 前 8 位（A 类私网）
  172.16.0.0/12 → B 类私网（16 个 /16）
  192.168.0.0/16 → C 类私网

子网计算：
  掩码 255.255.255.0 = /24；可用主机 = 2^(32-24) − 2（减网络号+广播）
  例：192.168.1.0/24 可用 192.168.1.1 - 254
```

### 4.2 NAT：私网地址的公共出口

```text
私网地址（RFC 1918）：10/8、172.16/12、192.168/16 —— 公网不可路由
NAT（网络地址转换）：
  出站：私网 IP:端口 → 公网 IP:端口（映射表）
  入站：反向转换
  NAPT/端口复用：一个公网 IP 服务整个私网（5.5 万端口 × 复用）

NAT 的代价：
  ① 破坏端到端（入站连接需端口映射/UPnP）
  ② 连接跟踪有状态（NAT 设备是状态点）
  ③ 四元组被改写 → 移动网络切换断连（QUIC 的 CID 方案动机）

IPv6 的意义之一：全球可路由 → NAT 不再必要（IPv6 无 NAT 概念）
```

## 5. IPv6：设计变更全解析

### 5.1 地址与格式

```text
128 位：2001:0db8:85a3:0000:0000:8a2e:0370:7334
  压缩规则：前导零省略；连续 0 组用 :: 一次
  例：::1（回环）、fe80::/10（链路本地）、2001:db8::/32（文档）
  全球单播：2000::/3；组播：ff00::/8（无广播！）

地址分配：无状态自动配置（SLAAC）——
  路由器通告前缀 → 主机用 EUI-64/随机数生成接口 ID → 即插即用
  （对比 IPv4 的 DHCP 依赖）
```

### 5.2 与 IPv4 的协议差异

| 维度 | IPv4 | IPv6 |
|------|:---:|:---:|
| 地址 | 32 位 | 128 位 |
| 分片 | 中间设备可分 | **仅源端**（路由器不再分片） |
| 校验和 | 有（首部） | **无**（端到端由上层/链路层保证） |
| 广播 | 有 | 无（用组播） |
| 自动配置 | DHCP | **SLAAC**（即插即用） |
| 安全 | 可选（IPsec 常被跳过） | IPsec 内建（但实际未强制） |
| 首部 | 固定 20B + 可变 | 固定 40B + 扩展头链 |
| NAT | 普遍 | 不需要（地址充足） |
| 移动性 | 无原生支持 | 原生移动支持（但实际靠 QUIC） |

## 6. 2026 采用现状：50% 里程碑

```text
（2026-08 检索数据）
里程碑：2026-03-28 Google 统计 IPv6 访问占比首次突破 50%（50.10%）
   — Google 追踪 18 年后 IPv6 迎来多数时刻（ISOC 报道）

多源数据（2026 年初）：
  Google 46%、APNIC 43%、Facebook 43%、Cloudflare 40%（流量包口径）
  ISOC 综合口径约 43%；行业报告 45-47%
  → 可靠区间 43-50%

区域差异（APNIC，2026-01）：
  领先：法国 80.3%、印度 79.1%、马来西亚 71.4%、德国 69.1%
  落后：意大利 17%、西班牙 10%、埃及 4%
  移动网络远超固定宽带（移动 ~70%；中国移动 54.1%）

中国：2026-03 活跃 IPv6 用户 8.47 亿（占网民 76.2%）
  移动 IPv6 流量占比预计超 60%，固定宽带 ~38%（年底预测）

形态：绝大多数仍为双栈（IPv4+IPv6 共存）；
  纯 IPv6（IPv6-only）主要在移动网络与数据中心内网
```

> 🎯 **核心要点**：IPv6 从"辅助协议"变为"主流协议"——2026-03 的 50% 是 18 年进程的标志性时刻。服务器侧含义：**监听 IPv6 地址（::）不再是可选项**，云原生/CDN 已默认双栈。

## 7. 双栈与迁移路径

```text
迁移路径三阶段：
  ① 双栈（当前主流）：同时提供 v4/v6 地址，客户端择优
  ② 隧道过渡（辅助）：6to4/Teredo/NAT64（DNS64+NAT64 桥接 v6-only 客户端）
  ③ IPv6-only（目标）：移动与新建数据中心先行

工程清单（服务器侧）：
  □ 监听 ::（IPv6 通配）与 0.0.0.0（IPv4）
  □ DNS AAAA 记录 + A 记录并存（双栈解析）
  □ 安全组/防火墙放行 v6 规则（常被遗漏！）
  □ 日志/监控记录 v6 来源（归属地解析兼容）
  □ CDN/云 LB 确认双栈启用
```

## 8. 核心要点与思考题

> 🎯 **本章三句话总结**：
> 1. IP 三职责（寻址/分片/尽力而为）；IPv4 靠 CIDR 与 NAT 续命，分片三件套（标识/标志/偏移）与 MTU/MSS 错配是故障高发区；
> 2. IPv6：128 位地址 + SLAAC 即插即用 + 仅源端分片 + 无 NAT——2026-03 全球采用率首次破 50%，双栈是当前形态；
> 3. 工程落地：监听 ::、双 AAAA/A 记录、防火墙 v6 规则、MSS 钳制检查。
