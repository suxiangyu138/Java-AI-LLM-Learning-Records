## 1. 排障方法论：分层定位

```text
四层定位法（从底到顶）：
  ① 链路层：网卡/线缆/交换机 → ping 网关
  ② 网络层：路由可达性 → ping 远端 IP、traceroute
  ③ 传输层：端口与服务 → telnet/ss/抓 SYN
  ④ 应用层：协议与业务 → 抓包分析 / 应用日志

原则：先"通不通"，再"对不对"，最后"快不快"
  ping 通 ≠ 端口通（防火墙）
  端口通 ≠ 应用正常（服务挂/超时）
  抓包 = 最终裁决（一切推断以报文为准）
```

## 2. 基础工具链：ping / telnet / ss / traceroute

| 工具 | 验证什么 | 判读要点 |
|------|---------|---------|
| `ping` | 网络层可达 + RTT + 丢包 | `packet loss` 丢包率；RTT 波动 |
| `telnet ip port` | 传输层端口可达 | 连上=端口开；`Connection refused`=未监听/被拒；超时=防火墙丢包 |
| `ss -tnp` | 本机连接状态 | LISTEN/ESTABLISHED/TIME_WAIT 分布 |
| `traceroute`（Win: tracert） | 路由路径与瓶颈跳 | `* * *`=节点不回（可能正常）；延迟突变=瓶颈 |
| `nc -vz` | 端口探测（脚本友好） | exit 0 = 通 |
| `curl -v` | HTTP 全链路 | 能看连接/握手/请求头 |

```bash
# 快速分层定位示例
ping -c 3 10.0.0.1            # ① 网关通不通（链路+网络）
traceroute -n 8.8.8.8         # ② 路由路径
nc -vz 10.0.0.2 8080          # ③ 端口通不通
curl -v http://10.0.0.2:8080/ # ④ 应用对不对
```

## 3. tcpdump 实战

```bash
# 常用姿势
tcpdump -i eth0 port 443               # 按端口抓
tcpdump -i any host 10.0.0.2           # 按主机抓
tcpdump -i eth0 tcp                    # 只看 TCP
tcpdump -i eth0 'tcp[13] & 2 != 0'     # 只看 SYN（标志位过滤）
tcpdump -i eth0 -w cap.pcap            # 存文件（Wireshark 分析）
tcpdump -i eth0 -nn -c 100             # 不解析域名、抓 100 包

# 结合目标连接（示例）
tcpdump -i eth0 -nn 'tcp port 8080 and host 10.0.0.2'
```

```text
tcpdump 输出解读：
  14:22:01.123456 IP 10.0.0.1.51234 > 10.0.0.2.8080: Flags [S], seq 1000
  └时间戳──┘ └源─┘  └──目的──┘        └标志─┘  └序列号─┘
  Flags: [S]=SYN [S.] = SYN+ACK [.] = ACK [P.] = PSH+ACK [F.] = FIN+ACK [R]=RST
  [.], cksum ok, length 0    ← 长度 0 = 纯控制段
```

## 4. 抓包识别：三次握手与四次挥手

### 4.1 三次握手（健康样板）

```text
① 10.0.0.1.51234 > 10.0.0.2.8080: Flags [S], seq 1000
② 10.0.0.2.8080 > 10.0.0.1.51234: Flags [S.], seq 5000, ack 1001
③ 10.0.0.1.51234 > 10.0.0.2.8080: Flags [.], ack 5001
   → 三次交换后连接建立（2.1ms 内完成 = 健康）
```

| 异常形态 | 含义 |
|---------|------|
| 只有 ① 没有 ② | SYN 被丢弃（防火墙/队列满）或服务器未监听 |
| ① → ② 间隔大 | 服务器 accept 慢/SYN 队列问题（并发体系 06 章） |
| ① 重发多次（间隔 1s 2s 4s） | SYN 丢失——链路丢包或中间设备丢弃 |
| 收到 [R] 回应 | 端口未监听 / 安全设备拒绝 |

### 4.2 四次挥手（识别半关闭与异常）

```text
健康：FIN → ACK →（服务器可能继续发）→ FIN → ACK
异常信号：
  大量 FIN+ACK 对（双向）→ 短连接场景正常
  只有 FIN 无后续 → 对端半关闭（可能等应用 close）
  RST 替代 FIN → 异常终止（进程崩溃/协议错误）
```

## 5. 抓包识别：重传、乱序与 SACK

### 5.1 超时重传（Retransmission）

```text
形态：同一 seq 出现两次，间隔 ≈ RTO（200ms+ 指数增长）
  [P.], seq 1000-2460（第一次）
  [P.], seq 1000-2460（第二次，间隔 0.25s）← Retransmission
tcpdump 标记：TCP Retransmission

归因链：
  重传 ↑ → 丢包（链路/中间设备/拥塞）或 RTO 过小
  配合 Wireshark 的 Expert Info 统计重传率
```

### 5.2 快速重传与乱序

```text
快速重传形态：
  连续 3 个 DupACK（ack 相同）→ 紧跟同 seq 重传
   [.], ack 2461
   [.], ack 2461   （DupACK ×3）
   [.], ack 2461
   [P.], seq 1461-2920  ← 快速重传（未等 RTO）

乱序（Out-of-Order）形态：
  seq 较大段先到、较小段后到（无重传）→ 网络乱序，非丢包
  Wireshark 标记：TCP Out-of-Order
  → 判断：乱序不重传；重传才是丢
```

### 5.3 SACK 生效确认

```text
ACK 中带 SACK 选项：
  [.], ack 2461, sack 1 3921-5380    ← 段2 丢了，段3/4 已收
  → 发送方只重传缺失段 → 恢复快
排查：抓包确认 SACK 选项在握手期协商（SYN 的 SACKPermitted）
```

## 6. 抓包识别：慢启动与窗口

```text
慢启动形态（新连接/超时后）：
  数据段长度按 1×MSS → 2× → 4× → 8× ... 翻倍（指数）
   [P.], seq 1000-2460   (1460B)
   [P.], seq 2460-5380   (2920B)    ← 翻倍
   [P.], seq 5380-8300   (2920B)
  → cwnd 指数增长直到 ssthresh → 转为线性（每 RTT +1）

窗口边界形态（接收窗口小）：
  持续低长度发送 + 对端窗口通告小（win 4096 等）
  → 接收方应用读得慢（应用层问题，非网络）

零窗口形态：
  win 0 通告 → 窗口探测（1 字节段）定期出现
  → 接收方缓冲满——应用消费不及时
```

## 7. 常见故障模式速查

| 症状 | 抓包特征 | 根因方向 |
|------|---------|---------|
| 连接建立失败 | 只有 SYN 无响应 | 防火墙丢弃/未监听/队列满 |
| 连接假死（超时） | 数据发出无 ACK → 重传 | 丢包链路/中间设备/MSS 错配 |
| 吞吐极低 | 重传风暴 + 窗口小 | 丢包率高（浅缓冲/无线）或应用读慢 |
| 间歇性卡顿 | 乱序 + DupACK | 多路径/负载均衡路径漂移 |
| HTTP 打不开但 ping 通 | SYN 后无响应 | MSS/MTU 错配（06 章）或防火墙只放 ICMP |
| 大量 RST | 对端主动拒/崩溃 | 服务未就绪、进程重启、安全设备 |
| 时延周期性尖峰 | 重传对齐时钟 | 定时器与业务周期共振 |

```bash
# 重传率/丢包率速查
tcpdump -i eth0 -nn 'tcp' -w /tmp/a.pcap &
# ... 运行一段时间后 Ctrl-C，用 Wireshark → Statistics → TCP Stream Graphs
# 关键指标：重传数/总数、ACK 延迟、吞吐时间线
```

> 🎯 **核心要点**：抓包排障的"三板斧"——**看握手**（建连问题）、**看重传**（丢包问题）、**看窗口**（应用消费问题）。95% 的 TCP 疑难都落在这三处。

## 8. 核心要点与思考题

> 🎯 **本章三句话总结**：
> 1. 排障先分层：ping（网络）→ telnet/ss（传输）→ curl/抓包（应用），从底到顶收敛；
> 2. 抓包三信号：握手（建连）、重传/DupACK/SACK（丢包）、窗口与慢启动（吞吐）——每类信号对应确定的根因方向；
> 3. 判断口诀：乱序不重传、重传才是丢；SYN 无响应先查防火墙与监听，大包不通先查 MSS。

**思考题**：

1. 三次握手中只有 SYN 无响应，可能的原因有哪些？（→ 4.1）
2. 乱序与丢包怎么从抓包区分？（→ 5.2）
3. 慢启动的指数增长在抓包里的形态？（→ 6）
4. "ping 通但应用假死"的排查顺序？（→ 7 + 06 章 MTU）
