## 1. 物理层概述

### 1.1 核心职责

物理层位于网络模型的最底层，负责处理物理介质上的信号传输，为数据链路层提供原始比特流传输服务。它定义了接口的机械特性、电气特性、功能特性和过程特性。

> 💡 物理层关注的是"怎么传比特"，不关心比特的含义。将0和1转换为物理信号在介质上传输。

### 1.2 通信基础概念

| 概念 | 说明 |
|------|------|
| 信号（Signal） | 模拟信号（连续变化）vs 数字信号（离散跳变） |
| 码元（Symbol） | 代表一个离散值的基本波形 |
| 波特率（Baud） | 码元传输速率（码元/秒），**波特率 ≠ 比特率** |
| 比特率（bps） | 信息传输速率（比特/秒） |

### 1.3 核心定理

| 定理 | 公式 | 物理意义 |
|------|------|----------|
| 奈奎斯特准则（无噪声） | 最大码元速率 = 2W Baud（W=带宽Hz） | 无噪声信道中码元速率的理论上限 |
| 香农定理（有噪声） | C = W × log₂(1 + S/N) | 有噪声信道的信息传输速率上限，S/N为信噪比 |

> 💡 带宽越大、信噪比越高，信息传输速率上限越高。香农定理给出了信道容量的理论上限。

### 1.4 编码与调制

| 技术 | 转换方向 | 常见方式 | 说明 |
|------|----------|----------|------|
| 编码（Encoding） | 数字信号 → 数字波形 | NRZ、曼彻斯特编码、差分曼彻斯特 | 位中间跳变（曼彻斯特） |
| 调制（Modulation） | 数字信号 → 模拟信号 | ASK（调幅）、FSK（调频）、PSK（调相）、QAM | QAM是WiFi 6/5G的核心 |

> ⚠️ **曼彻斯特编码**：每个比特位中间有一次跳变（高→低表示0，低→高表示1），兼具时钟同步和数据传输功能，但效率只有50%。

### 1.5 传输介质特性对比

| 介质类型 | 速率 | 最大距离 | 抗干扰 | 成本 | 典型场景 |
|----------|:----:|:--------:|:------:|:----:|----------|
| 双绞线UTP Cat5e | 1000Mbps | 100m | 低 | 低 | 家庭、办公桌面连接 |
| 双绞线UTP Cat6 | 10Gbps | 55m | 中 | 中 | 企业机房 |
| 双绞线STP（屏蔽） | 1000Mbps | 100m | 高 | 中 | 工业环境、干扰强区域 |
| 单模光纤 | 100Gbps+ | 40km+ | 极高 | 高 | 核心骨干网、跨城连接 |
| 多模光纤 | 10Gbps | 550m | 高 | 中 | 数据中心内互联 |
| WiFi 6 (802.11ax) | 9.6Gbps | 50m室内 | 低 | 低 | 家庭、办公室无线 |
| 蓝牙 | 3Mbps | 10m | 低 | 低 | 个人设备互联 |
| 5G蜂窝 | 20Gbps | 基站覆盖 | 中 | 高 | 移动互联网 |

### 1.6 信道工作模式

| 模式 | 方向性 | 同一时刻 | 硬件要求 | 示例 |
|:----:|:------:|:--------:|----------|------|
| 单工 | 单向 | 单向传输 | 一条线路 | 广播、电视 |
| 半双工 | 双向 | 只能一个方向 | 可切换 | 对讲机 |
| 全双工 | 双向 | 可同时双向 | 两条线路或专用技术 | 电话、交换式以太网 |

> 💡 现代交换式以太网使用全双工模式，不再有冲突检测问题。

## 2. 数据链路层核心职责

### 2.1 基本功能

数据链路层位于网络层之下、物理层之上，负责将物理层接收到的比特流组织成帧，实现**相邻节点之间**的可靠数据传输。

| 职责 | 说明 | 后端关联 |
|------|------|----------|
| 成帧（Framing） | 将比特流划分成有边界的帧 | 所有后端通信的最终封装形式 |
| 差错检测（Error Detection） | CRC校验，检测传输错误 | 错误帧由TCP触发重传，影响接口响应 |
| 流量控制（Flow Control） | 控制相邻设备帧传输速率 | 避免后端服务器缓存溢出 |
| 链路管理（Link Management） | 建立、维护、释放相邻设备链路 | 链路异常导致通信中断 |

### 2.2 成帧方法

| 方法 | 说明 | 使用协议 |
|------|------|----------|
| 字符计数法 | 帧头字段标明帧长度 | 较少使用 |
| 字节填充法 | 用转义字符标记帧边界 | PPP协议 |
| 比特填充法 | 用特殊比特模式标记帧边界 | HDLC（标志: 01111110） |

> ⚠️ **透明传输**：当数据中出现与帧定界符相同的模式时，需通过填充/转义机制解决，确保数据不受干扰。

### 2.3 差错检测——循环冗余校验（CRC）

CRC是目前使用最广泛的检错码技术：

```
发送方：
  1. 将数据D视为二进制数
  2. 在D后附加r个0（r为生成多项式G的阶数）
  3. 除以生成多项式G，得到余数R
  4. 实际发送数据 = D + R（附加在D后面）

接收方：
  1. 收到数据除以同样的生成多项式G
  2. 余数为0 → 传输无误
  3. 余数不为0 → 传输有误，丢弃帧
```

| 特性 | CRC | 奇偶校验 | 校验和 |
|:----:|:---:|:--------:|:------:|
| 检测能力 | 强（可检测突发错误） | 弱（只能检测奇数位错） | 中 |
| 开销 | 中（需要硬件支持） | 极低 | 低 |
| 使用层次 | 数据链路层 | 简单硬件 | 传输层（TCP/UDP） |
| 常见标准 | CRC-32（以太网） | 内存校验 | Internet Checksum |

> 💡 CRC是**检错码**不是纠错码——检测到错误后丢弃帧，由上层协议（如TCP）触发重传。CRC的误判率极低，CRC-32的碰撞概率约为1/2³²。

### 2.4 流量控制机制

| 协议 | 机制 | 效率 | 使用场景 |
|------|------|:----:|----------|
| 停止-等待协议 | 每发一帧等待ACK | 低（链路利用率低） | 简单可靠传输 |
| 滑动窗口协议 | 窗口内多帧连续发送 | 高 | 现代网络协议 |
| 后退N帧ARQ（GBN） | 出错则重传所有未确认帧 | 中 | 简单实现 |
| 选择重传ARQ（SR） | 仅重传出错帧 | 高 | 复杂但高效 |

> 💡 滑动窗口协议是TCP流量控制的底层原理——发送窗口和接收窗口共同决定传输效率。

## 3. 以太网与MAC地址

### 3.1 MAC地址

MAC地址（Media Access Control Address）是网卡的物理地址，全球唯一。

| 特性 | 说明 |
|------|------|
| 长度 | 48位（6字节） |
| 表示格式 | `00:16:3E:77:88:99` 或 `00-16-3E-77-88-99` |
| 分配方式 | 网卡厂商固化（出厂前写入ROM） |
| 作用范围 | **仅在同一链路（同一局域网）内有效** |
| 查看命令 | `ipconfig /all`（Windows）或 `ip addr`（Linux） |
| 地址类型 | 前3字节OUI（Organizationally Unique Identifier）↵ 后3字节由厂商分配 |

### 3.2 MAC地址类型

| 类型 | 目的MAC特征 | 说明 |
|:----:|:----------:|------|
| 单播（Unicast） | 第一个字节最低位为0 | 一对一通信，帧只发给特定设备 |
| 多播（Multicast） | 第一个字节最低位为1 | 一对多通信，帧发给组内所有设备 |
| 广播（Broadcast） | `FF:FF:FF:FF:FF:FF` | 一对所有通信，帧发给所有设备（ARP请求使用） |

### 3.3 数据帧结构（Ethernet 802.3）

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                             以太网帧结构                                      │
├──────────┬──────────┬──────────┬──────────────────────┬────────────────────┤
│ 前导码     │ 帧起始符  │ 目的MAC  │ 源MAC   │ 类型/长度  │ 数据（IP数据报）    │ FCS/CRC │
│  7B       │   1B     │   6B    │   6B    │    2B     │ 46~1500B           │   4B    │
├──────────┴──────────┴──────────┴──────────┴──────────┴────────────────────┴─────────┤
│                              帧头（14B）                              │ 帧尾（4B） │
└─────────────────────────────────────────────────────────────────────────────────────┘
```

| 字段 | 长度 | 说明 |
|------|:----:|------|
| 前导码（Preamble） | 7B | 同步时钟，10101010...交替 |
| 帧起始符（SFD） | 1B | 10101011，标志帧的开始 |
| 目的MAC地址 | 6B | 接收方MAC地址 |
| 源MAC地址 | 6B | 发送方MAC地址 |
| 类型/长度 | 2B | 0x0800=IPv4，0x0806=ARP，0x86DD=IPv6 |
| 数据 | 46~1500B | 网络层IP数据报（最小46B，最大1500B） |
| FCS/CRC | 4B | CRC-32校验码 |

> ⚠️ **最小帧长64B**：由CSMA/CD的碰撞检测窗口决定（10Mbps以太网，2.5km最大距离）。不足64B的帧会被认为"冲突碎片"而丢弃。

### 3.4 以太网工作原理——CSMA/CD

CSMA/CD（载波监听多点接入/碰撞检测）是以太网在**半双工**模式下的核心介质访问控制协议：

```
  ① 监听信道（载波监听）
  ② 若信道空闲则发送数据，若忙则等待
  ③ 发送数据时继续监听，检测冲突（碰撞检测）
  ④ 检测到冲突：
     → 立即停止发送
     → 发送强化干扰信号（32bit）
     → 等待随机时间后退（二进制指数退避算法）
     → 重新尝试发送
```

> 💡 **二进制指数退避算法**：第n次重传在 0 ~ (2ⁿ - 1) 个时隙中随机选择等待时间。重传尝试16次后仍失败则向上层报告错误。

### 3.5 信道划分MAC协议

| 协议 | 原理 | 应用 |
|------|------|------|
| 频分多路复用（FDM） | 划分不同频带 | 有线电视、WiFi |
| 时分多路复用（TDM） | 划分不同时隙 | 电话网络 |
| 波分多路复用（WDM） | 光的频分复用 | 光纤通信 |
| 码分多路复用（CDMA） | 码片序列 | 移动通信 |

### 3.6 随机接入MAC协议对比

| 协议 | 基本策略 | 吞吐率上限 | 使用场景 |
|------|----------|:----------:|----------|
| 纯ALOHA | 想发就发，碰撞后随机重发 | 18% | 早期无线网络 |
| 时隙ALOHA | 只能在时隙开始处发送 | 36% | 改进ALOHA |
| 1-坚持CSMA | 信道忙则持续监听，空闲立即发送 | 中 | CSMA/CD以太网 |
| 非坚持CSMA | 信道忙则等待随机时间再监听 | 中 | 无线网络 |
| p-坚持CSMA | 空闲时以概率p发送 | 中 | 有线电视 |
| CSMA/CD | 边发边听，碰撞后退避 | 高（冲突域内） | 传统以太网 |

## 4. ARP协议

### 4.1 ARP核心作用

ARP（Address Resolution Protocol，地址解析协议）的核心功能是实现 **IP地址 → MAC地址** 的映射。在局域网内通信时，发送方知道目标IP，但需要目标MAC才能封装数据帧，ARP就是解决这个"最后一公里"寻址问题的协议。

### 4.2 ARP工作原理

```
  主机A                         主机B
(192.168.1.100)              (192.168.1.101)
      │                           │
      │  ① 检查ARP缓存：是否有     │
      │     192.168.1.101的MAC？   │
      │     没有 → 发起ARP请求     │
      │                           │
      │  ② 广播ARP请求             │
      │  "谁拥有192.168.1.101？"   │
      │  ─────────────────────►    │
      │  目标MAC: FF:FF:FF:FF:FF:FF│
      │                           │
      │                           │ ③ 检查IP是否为自己
      │                           │    → 是我的IP！
      │                           │
      │  ④ 单播ARP响应             │
      │  "我是，我的MAC是BB:BB"     │
      │  ◄─────────────────────    │
      │                           │
      │  ⑤ 记录到ARP缓存：         │
      │  192.168.1.101 → BB:BB     │
      │                           │
      │  ⑥ 封装帧，发送数据给主机B  │
      │  目的MAC = BB:BB           │
      │  ─────────────────────►    │
```

### 4.3 ARP报文格式

| 字段 | 长度 | 说明 |
|------|:----:|------|
| 硬件类型 | 2B | 1=以太网 |
| 协议类型 | 2B | 0x0800=IPv4 |
| 硬件地址长度 | 1B | MAC地址=6 |
| 协议地址长度 | 1B | IP地址=4 |
| 操作类型 | 2B | 1=ARP请求，2=ARP响应 |
| 发送方MAC | 6B | 主机A的MAC |
| 发送方IP | 4B | 主机A的IP |
| 目标MAC | 6B | 请求时填0，响应时填目标MAC |
| 目标IP | 4B | 主机B的IP |

### 4.4 ARP缓存表

ARP缓存在操作系统内核中管理，通过 `arp -a` 命令查看：

```
# Windows: arp -a
接口: 192.168.1.100 --- 0x5
  Internet 地址      物理地址        类型
  192.168.1.1        00-16-3E-77-88-01  动态
  192.168.1.101      00-16-3E-77-88-99  动态
  192.168.1.102      00-16-3E-77-88-AA  动态
```

| 缓存特性 | 说明 |
|----------|------|
| 老化时间 | 通常2~10分钟（Windows约2分钟，Linux约30秒） |
| 动态条目 | 通过ARP协议自动学习，会老化 |
| 静态条目 | 手动添加（`arp -s IP MAC`），不会老化 |
| 缓存大小 | 操作系统自动管理，超出则淘汰最久未用条目 |

> ⚠️ **ARP欺骗（ARP Spoofing）**：攻击者伪造ARP响应，将自己伪装成目标主机（如网关），实现中间人攻击（MITM）。防御措施包括：静态ARP绑定、交换机端口安全（DAI动态ARP检测）、使用HTTPS加密通信。

### 4.5 ARP相关命令

| 命令 | 用途 | 示例 |
|------|------|------|
| `arp -a` | 查看ARP缓存表 | 查看所有IP↔MAC映射 |
| `arp -d <IP>` | 删除指定ARP缓存 | `arp -d 192.168.1.101` |
| `arp -s <IP> <MAC>` | 添加静态ARP映射 | `arp -s 192.168.1.101 00:16:3E:77:88:99` |
| `arping <IP>` | 链路层连通性检测 | `arping 192.168.1.101` |

## 5. 交换机与VLAN

### 5.1 交换机工作原理

交换机是数据链路层的核心设备，它根据MAC地址表进行帧的转发和过滤。

**MAC地址表学习过程：**

```
交换机初始化：MAC地址表为空
                    │
                    ▼
  主机A(00:AA) ────┤端口1├──── 交换机 ────┤端口3├──── 主机B(00:BB)

  ① 主机A发送帧到交换机端口1（目的MAC = 00:BB）
     → 交换机检查MAC地址表，未找到00:BB
     → 洪泛（Flooding）：向所有端口（除端口1）广播此帧
  
  ② 学习：记录 00:AA ↔ 端口1 到MAC地址表
  
  ③ 主机B收到帧后回复（目的MAC = 00:AA）
     → 交换机检查MAC地址表，找到00:AA → 端口1
     → 精确转发：只向端口1发送

  ④ 学习：记录 00:BB ↔ 端口3 到MAC地址表

  最终MAC地址表：
  ┌──────────────┬────────┐
  │  MAC地址     │  端口   │
  ├──────────────┼────────┤
  │  00:AA       │   1    │
  │  00:BB       │   3    │
  └──────────────┴────────┘
```

### 5.2 交换机 vs 集线器

| 对比维度 | 交换机（Switch） | 集线器（Hub） |
|----------|:----------------:|:-------------:|
| 工作层次 | 数据链路层（Layer 2） | 物理层（Layer 1） |
| 转发方式 | 根据MAC地址表转发 | 广播所有端口（无智能） |
| 带宽模式 | 每个端口独占带宽（全双工） | 所有端口共享带宽（半双工） |
| 冲突域 | 每个端口独立冲突域 | 所有设备在同一冲突域 |
| 广播域 | 所有端口在同一广播域 | 所有端口在同一广播域 |
| 当前状态 | 广泛使用 | 基本被淘汰 |

### 5.3 交换机分类

| 类型 | 特点 | 场景 |
|------|------|------|
| 傻瓜交换机 | 即插即用，无管理功能 | 家庭、小型办公 |
| 网管交换机 | 支持VLAN、STP、端口聚合等 | 企业网络 |
| 三层交换机 | 支持部分路由功能（IP转发） | 大型局域网核心 |

### 5.4 VLAN（虚拟局域网）

VLAN（Virtual LAN）是在物理交换机上划分逻辑上的隔离网络，解决广播域过大、安全隔离等问题。

```
                     ┌──── 交换机 ────┐
                     │                │
              VLAN 10:                 VLAN 20:
  主机A(192.168.1.2) │  端口1-5        │  端口6-10  主机C(192.168.2.2)
  主机B(192.168.1.3) │                │            主机D(192.168.2.3)
                     └────────────────┘
  VLAN 10内的广播不会传播到VLAN 20
  跨VLAN通信需要三层设备（路由器/三层交换机）
```

| 特性 | 说明 |
|:----:|------|
| 标准 | IEEE 802.1Q |
| 标签 | 在以太网帧头中插入4字节VLAN标签（VID：12位，支持4096个VLAN） |
| 作用 | 逻辑隔离广播域，不同VLAN间不能直接通信（除非通过路由器） |
| 好处 | 减少广播流量、增强安全、简化管理、灵活划分部门 |

> 💡 交换机隔离冲突域（每个端口独立），路由器隔离广播域。VLAN是交换机上逻辑隔离广播域的技术。

## 6. PPP协议

### 6.1 协议概述

PPP（Point-to-Point Protocol，点对点协议）是目前使用最广泛的广域网数据链路层协议，用于在两个网络节点之间的**点对点**链路上传输数据。

| 特性 | 说明 |
|------|------|
| 适用范围 | 拨号上网、DSL、专线连接、VPN隧道 |
| 封装 | 支持多种网络层协议（IP、IPX等） |
| 身份认证 | 支持PAP（明文）、CHAP（加密） |
| 功能 | 帧定界、透明传输、差错检测、链路控制 |

### 6.2 PPP帧结构

```
┌──────────┬────────┬──────────┬──────────┬──────────┬──────────┬──────────┐
│ 标志(1B) │ 地址(1B)│ 控制(1B) │ 协议(2B) │ 数据(≤1500B)│ FCS(2B)  │ 标志(1B) │
│ 0x7E     │ 0xFF   │ 0x03    │          │          │          │ 0x7E     │
└──────────┴────────┴──────────┴──────────┴──────────┴──────────┴──────────┘
```

| 字段 | 说明 |
|:----:|------|
| 标志 | 0x7E，帧的开始和结束 |
| 地址 | 0xFF（广播地址，PPP中点对点无需寻址） |
| 控制 | 0x03（无序号帧） |
| 协议 | 标识网络层协议类型（0x0021=IP） |
| 数据 | 不超过1500字节 |
| FCS | 帧校验序列（CRC校验） |

> ⚠️ **透明传输**：当数据中出现0x7E时，PPP使用字节填充法（转义为0x7D 0x5E），确保数据不被误判为帧边界。

## 7. Java后端开发关联

### 7.1 链路层与后端服务的关联逻辑

```
业务数据 → 应用层报文 → 传输层报文段 → 网络层IP数据报 → 链路层数据帧 → 物理层信号

                                            ↑
                                    链路层问题会导致：
                                    • 帧丢失 → TCP重传 → 接口超时
                                    • 帧出错 → CRC校验失败 → 数据重传
                                    • MAC冲突 → 通信混乱
                                    • ARP异常 → 无法连接同局域网设备
```

### 7.2 后端常用排查命令

| 命令 | 用途 | 示例 |
|------|------|------|
| `ipconfig /all`（Windows） | 查看MAC地址、IP、网关 | 确认网卡`物理地址`字段 |
| `ip addr`（Linux） | 查看MAC地址、网卡状态 | 确认`ether`字段 |
| `arp -a` | 查看ARP缓存表 | 查看IP↔MAC映射关系 |
| `arp -d <IP>` | 删除ARP缓存 | `arp -d 192.168.1.101` |
| `arping <IP>` | 链路层连通性检测 | `arping 192.168.1.101` |
| `netstat -i` | 查看网卡帧传输统计 | 查看错误帧、丢弃帧数 |
| `ping <IP>` | 网络层连通性检测 | `ping 8.8.8.8` |
| `tracert <IP>` | 路由追踪 | `tracert www.baidu.com` |

```bash
# 查看网卡统计信息（Linux）
$ netstat -i
Kernel Interface table
Iface      MTU    RX-OK RX-ERR RX-DRP RX-OVR    TX-OK TX-ERR TX-DRP TX-OVR
eth0      1500  1234567      0      0      0  2345678      0      0      0
# RX-ERR: 接收错误帧数  RX-DRP: 接收丢弃帧数
# 这两个值过高说明链路层存在问题
```

### 7.3 MTU问题与后端关联

MTU（Maximum Transmission Unit，最大传输单元）是链路层帧能承载的最大数据量，以太网标准MTU为1500字节。

| MTU问题 | 影响 | 现象 |
|---------|------|------|
| IP数据报 > MTU | 触发IP分片 | 分片过多导致性能下降，分片丢失导致全部重传 |
| 分片丢失 | 接收方无法重组 | TCP超时重传，接口响应变慢 |
| MTU不匹配（路径MTU发现） | PMTUD探测被防火墙拦截 | 连接建立成功但大数据传输卡死 |

```bash
# 查看/设置本机MTU
ip link show eth0
ip link set eth0 mtu 1400

# 路径MTU发现测试（Linux）
tracepath 8.8.8.8
```

> ⚠️ **MTU与Java后端**：当后端处理大数据量传输（如大文件上传、大JSON响应）时，MTU不匹配可能导致IP分片和TCP性能下降。严重情况下，PMTUD被防火墙拦截会导致连接"建立但无法传输数据"的死结。

### 7.4 VLAN与后端部署

| 部署场景 | VLAN划分建议 |
|----------|-------------|
| 微服务集群 | 同VLAN内部署（低延迟通信） |
| 数据库集群 | 独立VLAN（安全隔离） |
| 缓存集群（Redis） | 与应用同VLAN（低延迟读写） |
| 管理网络 | 独立管理VLAN（运维安全） |
| DMZ | 独立VLAN（对外暴露服务隔离） |

### 7.5 链路层常见问题排查

**问题1：同一局域网内无法连接数据库**

| 排查步骤 | 命令 | 解决方案 |
|----------|------|----------|
| 检查ARP映射 | `arp -a \| grep 数据库IP` | 映射错误时删除：`arp -d 数据库IP` |
| 链路层连通性 | `arping 数据库IP` | 不通则检查网线、交换机端口 |
| 检查MAC冲突 | `ifconfig` 查看所有设备MAC | 修改冲突设备的MAC地址 |

**问题2：接口频繁超时，但ping正常**

| 排查方向 | 命令 | 解决方案 |
|----------|------|----------|
| 网卡丢帧统计 | `netstat -i` 查看RX-DRP/TX-DRP | 数值过高则检查网线、重启网卡 |
| 网卡错误帧 | `netstat -i` 查看RX-ERR/TX-ERR | 检查网卡驱动、更换网卡 |
| 交换机端口 | 登录交换机管理界面 | 确认端口速率匹配、未禁用 |

**问题3：ARP缓存老化导致周期性通信中断**

```bash
# 临时解决方案：添加静态ARP映射
arp -s 192.168.1.101 00:16:3E:77:88:99

# 永久生效：配置 /etc/ethers 文件
echo "00:16:3E:77:88:99 192.168.1.101" >> /etc/ethers
```

**问题4：链路层帧校验失败，TCP重传频繁**

| 排查方向 | 具体措施 |
|----------|----------|
| 传输介质 | 更换高质量网线/光纤，远离强电干扰 |
| 网卡驱动 | 更新网卡驱动到最新版本 |
| 速率匹配 | 确认网卡与交换机端口速率一致（均为千兆/万兆） |

### 7.6 后端开发注意事项

| 场景 | 注意事项 |
|------|----------|
| 部署时 | 确保网卡正常启用，MAC地址唯一（尤其虚拟机部署） |
| 高并发场景 | 使用千兆/万兆网卡（1000Mbps+），避免网卡成为瓶颈 |
| 分布式部署 | 同局域网服务器使用同一品牌/速率交换机 |
| 防火墙配置 | 不要随意拦截ICMP（影响PMTUD），开放业务端口 |
| 网卡优化 | 开启RSS多队列、关闭节能模式、设置全双工 |
| 冗余设计 | 双网卡绑定（Bonding），双交换机冗余 |

> 🎯 **本章总结**：物理层关注"怎么传比特"——通过编码、调制和传输介质将原始比特从一端传到另一端。数据链路层关注"怎么可靠传帧"——通过成帧、CRC校验、MAC寻址、ARP协议和交换机转发，实现相邻设备间的可靠数据传输。虽然Java后端开发者不直接操作链路层，但理解CSMA/CD、MAC地址、交换机原理和ARP协议是网络问题排查的基础。链路层的帧丢失、CRC错误、MAC冲突等问题最终都会表现为上层的TCP重传和接口超时。
