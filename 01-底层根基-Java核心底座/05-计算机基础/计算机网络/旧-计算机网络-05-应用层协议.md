# 应用层协议

## 📌 课程定位
应用层是离你最近的层——HTTP就是后端开发者的日常。理解DNS、HTTP、HTTPS是Web开发、API设计、系统架构的基础。

## 🎯 核心章节

### 1. DNS（域名解析系统）
- **作用**：域名↔IP地址的映射——互联网的"电话簿"
- **域名层次结构**：`www.example.com.` → 根域(.)→顶级域(.com)→二级域(example)→三级域(www)
- **解析过程（⭐ 必掌握）**：
  1. 浏览器缓存 → OS hosts文件 → 本地DNS服务器(递归查询)
  2. 本地DNS → 根域名服务器 → .com顶级域名服务器 → example.com权威服务器(迭代查询)
  3. 获得IP返回客户端，客户端缓存(浏览器+OS两级)
- **DNS记录类型**：A(域名→IPv4)、AAAA(→IPv6)、CNAME(别名)、MX(邮件服务器)、NS(域名服务器)、PTR(反向解析)
- **DNS over HTTPS(DOH)**：加密DNS，防止ISP劫持DNS请求

### 2. HTTP 协议（⭐ Web开发基石）
- **无状态**：每次请求独立，不保存客户端信息→Cookie/Session解决
- **报文格式**：
  ```
  请求：GET /index.html HTTP/1.1\r\nHost: example.com\r\n\r\n
  响应：HTTP/1.1 200 OK\r\nContent-Type: text/html\r\n\r\n<html>...
  ```

- **常见状态码（必须秒答）**：
  - 1xx：信息——101(WebSocket协议升级)
  - 2xx：成功——200(OK)、201(Created)、204(No Content)
  - 3xx：重定向——301(永久)、302(临时)、304(Not Modified，缓存)
  - 4xx：客户端错误——400(Bad Request)、401(未认证)、403(无权限)、404(未找到)、429(请求过多)
  - 5xx：服务端错误——500(内部错误)、502(网关错误)、503(服务不可用)、504(网关超时)

- **HTTP/1.1 vs HTTP/2 vs HTTP/3**：
  | 版本 | 特点 |
  |------|------|
  | HTTP/1.1 | 持久连接(keep-alive)、管道化(队头阻塞问题) |
  | HTTP/2 | 二进制分帧、多路复用(同一连接并发)、头部压缩(HPACK)、服务器推送 |
  | HTTP/3 | 基于QUIC(UDP)、0-RTT握手、无队头阻塞 |

### 3. HTTPS（⭐ TLS/SSL 必理解）
- **HTTPS = HTTP + TLS**：加密+身份验证+数据完整性
- **TLS握手流程**（ECDHE为例）：
  1. Client Hello：支持的加密套件+随机数1
  2. Server Hello：选定的加密套件+随机数2+证书(含公钥)
  3. 客户端验证证书→CA链校验
  4. 双方分别生成ECDHE参数，交换后各自计算预主密钥→主密钥→会话密钥
- **证书链**：根CA→中间CA→服务器证书——信任链验证
- **中间人攻击(MITM)**：攻击者伪造证书拦截通信——CA体系防御
- **HSTS**：强制HTTPS，浏览器自动升级HTTP到HTTPS

### 4. 其他常见应用层协议
- **FTP**：文件传输（21控制+20数据，主动/被动模式）
- **SMTP + POP3 + IMAP**：邮件三件套——SMTP发、POP3/IMAP收
- **WebSocket**：基于HTTP升级的全双工通信——聊天、实时推送
- **gRPC**：基于HTTP/2和Protobuf的高性能RPC框架——微服务主流

### 5. Cookie 与 Session
- **Cookie**：客户端存储（4KB限制），随HTTP请求自动发送
  - Set-Cookie响应头设置，Cookie请求头携带
  - Secure(仅HTTPS)、HttpOnly(JS不可读防XSS)、SameSite(防CSRF)
- **Session**：服务端存储，SessionID通过Cookie传递给客户端

## ✅ 学习建议
- HTTP状态码100-599不需要全背，但2xx/3xx/4xx/5xx代表什么必须秒答
- DNS解析过程要能完整讲一遍（递归+迭代）
- HTTPS握手是面试高频题——能画出密钥协商的完整流程图
