## 核心知识点

### 实验一：网络基础与常用命令
- ipconfig/ifconfig
  - ipconfig /all：查看MAC地址、IP地址、子网掩码、默认网关、DNS服务器
  - ipconfig /release 和 /renew：释放和重新获取DHCP IP地址
- ping
  - ping IP/域名：发送ICMP回显请求→等待ICMP回显应答
  - ping -n 10：发送10个请求包
  - ping -l 1000：发送1000字节的数据包
  - 结果分析：往返时间(RTT)、TTL值（猜测对方OS类型，Windows通常128，Linux 64）
  - ping不通的可能原因：对方禁用ICMP、防火墙拦截、网络不可达
- tracert/traceroute
  - 原理：利用IP数据报中的TTL字段，TTL从1开始递增每跳+1
  - 每个TTL值发送3个探测包，路径上第n跳路由器收到TTL=1的数据报→返回ICMP超时报文
  - 输出分析：每一跳的IP地址和三段往返时间（*表示该跳未响应）
- netstat
  - netstat -an：显示所有TCP/UDP连接(-a所有，-n数字格式)
  - 状态解读：LISTENING(监听)、ESTABLISHED(已建立)、TIME_WAIT(等待关闭)、CLOSE_WAIT
  - netstat -anb：显示对应进程(-b需管理员权限)
- arp -a
  - 查看ARP缓存表：IP地址→MAC地址的映射
  - 条目类型：动态(通过ARP协议学习)、静态(手动配置)

### 实验二：Wireshark抓包基础
- Wireshark界面与操作
  - 选择捕获网卡→开始捕获→设置过滤器→停止→分析
  - 三栏布局：数据包列表(时间/源/目的/协议/长度/信息)→数据包详情(分层解析)→原始数据(十六进制)
- 捕获过滤器(BPF语法)
  - host 192.168.1.1：只捕获与该IP相关的包
  - port 80：只捕获端口80的包
  - tcp or udp：只捕获TCP或UDP包
  - src/dst：限定源/目的
- 显示过滤器
  - ip.addr == 192.168.1.1
  - tcp.port == 443
  - http.request.method == "GET"
  - dns.qry.name contains "baidu"
- 以太网帧结构分析
  - 目的MAC(6字节) + 源MAC(6字节) + 类型(2字节，0x0800=IPv4，0x0806=ARP) + 数据(46-1500字节) + FCS(4字节，Wireshark不显示)
- IP数据报结构分析
  - 版本(4位=4)、首部长度(4位=5，即20字节)、服务类型、总长度
  - 标识+标志(DF/MF)+片偏移：用于IP分片重组
  - TTL(8位，每跳减1)、协议(1=ICMP, 6=TCP, 17=UDP)、首部校验和
  - 源IP、目的IP
- TCP段结构分析
  - 源端口、目的端口
  - 序号(Seq)：本段第一个数据字节的编号
  - 确认号(Ack)：期望收到对方下一个字节的序号
  - 数据偏移(首部长度)、标志位(URG/ACK/PSH/RST/SYN/FIN)、窗口大小(接收窗口)
  - 校验和、紧急指针

### 实验三：ARP协议与ICMP协议
- ARP请求/应答抓包
  - 场景：ping同网段的一个IP→先发ARP请求(broadcast FF:FF:FF:FF:FF:FF)→收到ARP应答
  - ARP请求：Who has 192.168.1.1? Tell 192.168.1.100
  - ARP应答：192.168.1.1 is at XX:XX:XX:XX:XX:XX
  - 观察ARP缓存：ping前arp -a为空(或无该条目)，ping后arp -a显示新条目
- ICMP协议抓包
  - ping产生的ICMP包：
    - 请求：Type=8(Echo Request), Code=0
    - 应答：Type=0(Echo Reply), Code=0
    - 观察ICMP包中携带的数据（Windows默认32字节abcde...）
  - traceroute产生的ICMP包：
    - 路由器返回：Type=11(Time Exceeded), Code=0
    - 最终目标返回：Type=0(Echo Reply)（如果开放ICMP）

### 实验四：TCP连接管理
- TCP三次握手抓包
  - 第1次：客户端→服务器，SYN=1, Seq=x（客户端初始序号，随机值）
  - 第2次：服务器→客户端，SYN=1, ACK=1, Seq=y, Ack=x+1
  - 第3次：客户端→服务器，ACK=1, Seq=x+1, Ack=y+1
  - 观察：SYN包不携带数据但消耗一个序号，ACK包可以不消耗序号
  - 状态变化：CLOSED→SYN_SENT→SYN_RCVD→ESTABLISHED
- TCP四次挥手抓包
  - 第1次：主动关闭方→被动方，FIN=1, Seq=u（不携带数据但消耗序号）
  - 第2次：被动方→主动方，ACK=1, Ack=u+1（确认收到FIN）
  - 第3次：被动方→主动方，FIN=1, ACK=1, Seq=v, Ack=u+1
  - 第4次：主动方→被动方，ACK=1, Ack=v+1
  - TIME_WAIT：主动关闭方发送最后ACK后进入，等待2MSL（约1-2分钟）
- TCP数据传输
  - 观察Seq和Ack的变化：Seq增加量=发送字节数，Ack增加量=接收字节数
  - 滑动窗口：接收方在ACK中通告可用窗口大小
  - 零窗口探测：接收方窗口=0时，发送方周期性发送探测包

### 实验五：应用层协议分析
- HTTP协议
  - HTTP请求报文：请求行(方法 URL 版本) + 请求头(Host/User-Agent/Accept/Cookie) + 空行 + 请求体(POST有)
  - HTTP响应报文：状态行(版本 状态码 描述) + 响应头(Content-Type/Content-Length/Set-Cookie) + 空行 + 响应体(HTML/JSON)
  - 常见状态码：200 OK、301/302 重定向、403 Forbidden、404 Not Found、500 Internal Server Error
  - HTTP vs HTTPS：HTTPS在TCP之上添加TLS层加密，端口443
- DNS协议
  - DNS查询：客户端→DNS服务器，端口53 UDP
  - 查询报文：Transaction ID + 标志位 + 问题段(QNAME/ QTYPE=1(A记录))
  - 响应报文：问题段 + 回答段(NAME/TYPE/CLASS/TTL/数据长度/IP地址)
  - 递归查询 vs 迭代查询
- 其他协议
  - DHCP：UDP端口67/68，Discover→Offer→Request→ACK四步获取IP
  - FTP：控制连接(21端口) + 数据连接(20端口)，主动模式PORT vs 被动模式PASV

### 实验六：Socket网络编程
- TCP Socket编程流程
  - 服务器端：
    1. socket()：创建套接字（AF_INET IPv4, SOCK_STREAM TCP）
    2. bind()：绑定地址和端口（sockaddr_in结构体）
    3. listen()：监听，指定等待队列最大长度
    4. accept()：阻塞等待客户端连接，返回新socket用于通信
    5. recv()/send()：收发数据
    6. closesocket()：关闭连接
  - 客户端：
    1. socket()
    2. connect()：向服务器发起连接（三次握手在此完成）
    3. send()/recv()
    4. closesocket()
- UDP Socket编程
  - 服务器端：socket→bind→recvfrom→sendto
  - 客户端：socket→sendto→recvfrom
  - recvfrom可获取发送方地址，sendto需指定目标地址
- 练习
  - 实现简单的回显(Echo)服务器（服务器原样返回客户端发送的消息）
  - 实现简单的聊天程序（全双工，客户端和服务器可互发消息）
  - 实现简单的HTTP服务器（监听80端口，返回固定HTML页面）

### 实验七：路由协议配置（Packet Tracer/GNS3模拟）
- 静态路由配置
  - ip route 目标网络 子网掩码 下一跳地址
  - 默认路由：ip route 0.0.0.0 0.0.0.0 下一跳
- RIP协议配置
  - router rip → network 直连网络号 → version 2
  - 观察RIP路由表：show ip route
  - RIP的特点：距离向量、最大跳数15、周期性更新(30s)
- OSPF协议（单区域）
  - router ospf 进程号 → network 网络 反掩码 area 区域号
  - OSPF的特点：链路状态、SPF算法、快速收敛、支持VLSM
  - 观察OSPF邻居状态：show ip ospf neighbor
