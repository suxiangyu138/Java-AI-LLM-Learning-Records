### 1.2 传输层深度对比

| 特性 | TCP | UDP |
|------|-----|-----|
| 连接性 | 面向连接（三次握手） | 无连接 |
| 可靠性 | 可靠（确认+重传） | 不可靠 |
| 首部大小 | 20~60 字节 | 8 字节 |
| 传输方式 | 面向字节流 | 面向报文 |
| 流量控制 | 滑动窗口 | 无 |
| 拥塞控制 | 有（慢启动/拥塞避免/快重传/快恢复） | 无 |
| 典型应用 | HTTP、FTP、SMTP | DNS、DHCP、流媒体、QUIC |

| 协议 | 端口 | 传输层 | 说明 |
|------|------|--------|------|

| HTTPS | 443 | TCP | HTTP + TLS 加密握手 |
| DNS | 53 | UDP（主）/ TCP（辅） | 递归查询、迭代查询 |
| FTP | 21(控制) / 20(数据) | TCP | 控制连接与数据连接分离 |

### 4.2 SQL 高频面试模式

```sql
-- 1. 窗口函数：每个部门工资前三
SELECT dept, name, salary FROM (
  SELECT dept, name, salary,
         DENSE_RANK() OVER (PARTITION BY dept ORDER BY salary DESC) AS rk
  FROM employee
) t WHERE rk <= 3;

-- 2. JOIN + 聚合：订单最多的用户
SELECT u.name, COUNT(o.id) AS cnt
FROM users u LEFT JOIN orders o ON u.id = o.user_id
GROUP BY u.id ORDER BY cnt DESC LIMIT 10;

-- 3. 子查询：从未下过单的用户
SELECT name FROM users WHERE id NOT IN (
  SELECT DISTINCT user_id FROM orders
);

-- 4. CTE：递归查询部门树
WITH RECURSIVE dept_tree AS (
  SELECT id, name, parent_id, 1 AS level
  FROM department WHERE parent_id IS NULL
  UNION ALL
  SELECT d.id, d.name, d.parent_id, dt.level + 1
  FROM department d JOIN dept_tree dt ON d.parent_id = dt.id
)
SELECT * FROM dept_tree;
```

### 4.3 索引知识点总结

| 概念 | 说明 |
|------|------|
| B+ 树 vs B 树 | B+ 树只有叶子节点存数据，非叶子节点存索引；叶子节点形成有序链表，适合范围查询 |
| 聚簇索引 | 数据行和索引存储在一起（InnoDB 主键索引），一张表只有一个聚簇索引 |
| 非聚簇索引 | 索引和数据分离，叶子节点存储主键值（需回表查询） |
| 最左前缀匹配 | 联合索引 (a,b,c) 可匹配 (a)、(a,b)、(a,b,c)，跳列则失效 |
| 覆盖索引 | 查询列全部在索引中，无需回表 |
| 索引下推（ICP） | 在索引遍历过程中过滤数据，减少回表次数 |
| 索引失效场景 | 隐式类型转换、!= / NOT IN、LIKE '%xxx'、函数操作、OR 条件 |

### 4.4 事务与隔离级别

| 隔离级别 | 脏读 | 不可重复读 | 幻读 | 实现方式 |
|----------|------|-----------|------|---------|
| 读未提交 | 可能 | 可能 | 可能 | 无锁 |
| 读已提交 | 避免 | 可能 | 可能 | 语句级快照（Oracle 默认） |
| 可重复读 | 避免 | 避免 | 可能（InnoDB 通过 Gap Lock 避免） | 事务级快照（MySQL 默认） |
| 串行化 | 避免 | 避免 | 避免 | 表级锁 + 范围锁 |

> 🎯 **目标**：能独立写复杂查询，能讲清索引为什么快。

### 5.2 存储系统层次

```
寄存器 (1ns)   →  L1 Cache (2ns)   →  L2 Cache (10ns)
→  L3 Cache (30ns)  →  主存 (100ns)  →  磁盘 (10ms)
```

> 速度差：寄存器比磁盘快 **1000 万倍**。

### 5.3 与 Java 后端的关联

| 组成原理概念 | Java 中的体现 |
|-------------|-------------|
| 缓存行（Cache Line） | `@Contended` 避免伪共享，Disruptor 高性能队列的设计基础 |
| 内存屏障 | `volatile`、`synchronized`、`Unsafe.loadFence/storeFence/fullFence` |
| 大小端 | `ByteBuffer.order(ByteOrder.BIG_ENDIAN/LITTLE_ENDIAN)` |
| 内存对齐 | 压缩指针（`-XX:+UseCompressedOops`），32G 堆内存限制 |
| CPU 乱序执行 | 指令重排序 → 单例模式必须用 `volatile`（DCL 问题） |

### 5.4 数据表示速查

| 概念 | 要点 |
|------|------|
| 原码/反码/补码 | 计算机使用补码存储整数；补码 1000 0000 表示 -128 |
| IEEE 754 浮点 | 阶码移码 127(+127)；规格化隐含 1；精度问题 EPSILON |
| 校验码 | 奇偶校验、CRC、海明码（距离 3 纠 1 位） |

## 7. 交叉面试题与速记口诀

### 7.1 五大件交叉面试题

这些是典型的"一个面试题考多个领域"的高频题：

| 面试题 | 涉及领域 |
|--------|---------|
| "从浏览器输入 URL 到看到页面，发生了什么？" | 网络（DNS/TCP/HTTP/HTTPS）+ OS（进程调度/IO）+ 数据库（查询缓存） |
| "一条 SQL 执行很慢，怎么排查？" | 数据库（索引/锁/MVCC）+ OS（磁盘 IO/内存）+ 网络（连接池/超时） |
| "如何设计一个短链系统？" | 算法（哈希/Base62）+ 数据库（分库分表/缓存）+ 网络（重定向/301 vs 302） |
| "线程池的核心参数怎么设置？" | OS（CPU 核心数/上下文切换）+ 算法（排队论）+ 网络（IO 密集型 vs CPU 密集型） |
| "HashMap 为什么线程不安全？" | 数据结构（链表/红黑树）+ OS（并发/CPU 缓存）+ 组成原理（CAS/内存屏障） |

### 7.2 易错速记口诀

```
OS:  互斥占有非剥夺，循环等待死锁决。
CN:  三次握手中断收，四次挥手等发收。
     慢启拥避快重恢，Tahoe/Reno 各不同。
CO:  补码加减看进位，溢出判断最高位。
DSA: 快排不稳归并稳，哈希冲突链开放。
     建堆 O(n) 排 O(nlogn)，动态规划状转方。
DB:  B+ 树索引快，覆盖索引免回表。
     MVCC 读快照，Gap Lock 防幻读。
```

> 🎯 **五大件不是独立的知识孤岛，它们互相交织构成了计算机科学的底层逻辑。** 学习时注重知识点之间的关联，面试时才能应对自如。
