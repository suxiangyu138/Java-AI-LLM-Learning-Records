## 1. 数据库系统体系结构

### 1.1 集中式架构

```
应用 ←→ DBMS ←→ 数据库（同一台机器）
```

特点：所有组件在同一台机器上，简单但扩展性有限。

### 1.2 客户端-服务器架构

```
客户端 1 ──┐
客户端 2 ──┼──→ DBMS 服务器 → 存储
客户端 3 ──┘
```

特点：应用与数据库分离，多客户端并发访问，最常见的架构模式。

### 1.3 三层架构

```
展示层（客户端） → 应用层（应用服务器） → 数据库层（DBMS）
  UI/API           业务逻辑              数据存储
```

特点：Java Web 开发的标准架构（Browser → Tomcat → MySQL）。

### 1.4 分布式架构

```
         ┌─────────────┐
         │  应用服务器   │
         └──────┬──────┘
                │
         ┌──────┴──────┐
         │   负载均衡    │
         └──────┬──────┘
                │
    ┌───────────┼───────────┐
    │           │           │
┌───┴───┐   ┌───┴───┐   ┌───┴───┐
│ DB 1  │   │ DB 2  │   │ DB 3  │
└───────┘   └───────┘   └───────┘
```

特点：多个数据库节点协同工作，提供高可用和高扩展性。

## 2. 并行数据库

### 2.1 并行架构

| 架构 | 说明 | 代表 |
|------|------|------|
| 共享内存 | 所有 CPU 共享内存 | 单机多核 |
| 共享磁盘 | 节点共享磁盘，不共享内存 | Oracle RAC |
| 无共享 | 各节点独立 CPU/内存/磁盘 | 大规模并行处理（MPP） |

### 2.2 并行查询

```sql
-- 并行数据库会自动将查询分解到多个节点并行执行
SELECT COUNT(*) FROM huge_table;
-- 节点 1: 处理 id 1~10000
-- 节点 2: 处理 id 10001~20000
-- 节点 3: 处理 id 20001~30000
-- 合并结果: SUM 各节点 COUNT
```

### 2.3 并行 vs 分布式

| 特性 | 并行数据库 | 分布式数据库 |
|------|-----------|-------------|
| 数据分布 | 显式分区 | 可能跨地域分布 |
| 节点距离 | 通常在同一机房 | 可能跨地域 |
| 耦合度 | 紧耦合 | 松耦合 |
| 扩展 | Scale-up | Scale-out |

## 3. 分布式数据库

### 3.1 数据分片

| 方式 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| 水平分片 | 按行划分（取模/范围/哈希） | 数据均匀分布 | 跨分片查询复杂 |
| 垂直分片 | 按列划分（按业务模块拆分） | 减少不必要的数据访问 | 需 JOIN 还原数据 |
| 混合分片 | 水平 + 垂直组合 | 综合两者优点 | 管理复杂 |

### 3.2 分布式系统的挑战

| 挑战 | 说明 |
|------|------|
| 数据一致性 | 多副本同步延迟导致读写不一致 |
| 分布式事务 | 跨节点事务需两阶段提交（2PC） |
| 查询复杂性 | 跨分片 JOIN 需要聚合计算 |
| 节点故障 | 单点故障会影响整体可用性 |

### 3.3 CAP 理论

| 特性 | 说明 |
|------|------|
| **C**onsistency（一致性） | 所有节点在同一时刻看到相同的数据 |
| **A**vailability（可用性） | 每个请求都能得到响应（非错误） |
| **P**artition Tolerance（分区容忍性） | 系统能容忍网络分区 |

> CAP 定理：分布式系统最多同时满足上述两项。通常选择 AP 或 CP，无法三者兼顾。

## 4. NoSQL 概述

### 4.1 什么是 NoSQL

**NoSQL（Not Only SQL）** 是一类非关系型数据库的统称，核心特征：

- **无需预定义表结构**：支持动态扩展字段
- **灵活的数据模型**：键值、文档、列族、图等
- **弱化事务**：不严格遵循 ACID，优先保证高性能和高可用
- **易于水平扩展**：天然支持分布式

### 4.2 产生背景

| 需求 | 说明 |
|------|------|
| 高并发读写 | 传统关系型数据库无法支撑每秒数万次写入 |
| 海量数据存储 | 单表数据量达 TB 级别时，关系型数据库瓶颈明显 |
| 灵活的数据模型 | 半结构化/非结构化数据不适于固定的表结构 |

### 4.3 BASE 理论

| 特性 | 说明 |
|------|------|
| BA（Basically Available） | 基本可用 |
| S（Soft State） | 软状态（数据可暂时不一致） |
| E（Eventually Consistent） | 最终一致 |

> BASE 是 NoSQL 的理论基础，与关系型数据库的 ACID 形成对比。

## 5. NoSQL 类型及应用

### 5.1 四大类型

| 类型 | 数据模型 | 代表产品 | 适用场景 |
|------|----------|----------|----------|
| **键值型** | key-value | **Redis**、Memcached | 缓存、会话、计数器 |
| **文档型** | JSON/BSON | **MongoDB**、CouchDB | 日志、用户行为、内容管理 |
| **列族型** | 列族 | HBase、Cassandra | 海量结构化数据、时序数据 |
| **图型** | 节点+边 | Neo4j、ArangoDB | 社交关系、推荐系统 |

### 5.2 主流产品对比

| 产品 | 存储类型 | 核心优势 | 典型场景 |
|------|----------|----------|----------|
| Redis | 键值 + 数据结构 | 极致性能、丰富的数据类型 | 缓存、限流、分布式锁 |
| MongoDB | 文档（JSON） | 灵活 schema、易扩展 | 日志、用户画像、CMS |
| Elasticsearch | 倒排索引 | 全文搜索、聚合分析 | 搜索引擎、日志分析 |
| HBase | 列族 | 海量存储、强一致性 | 大数据存储 |

### 5.3 混合使用策略

在实际项目中，关系型数据库 + NoSQL 是常见架构：

```
核心业务数据（订单、用户） → 关系型数据库（MySQL/PostgreSQL）
缓存/计数器（热点数据）    → 键值型（Redis）
搜索引擎（商品搜索）       → 搜索引擎（Elasticsearch）
行为日志（海量写入）       → 文档型（MongoDB）
```

## 6. 关系型 vs 非关系型数据库对比

| 维度 | 关系型数据库（RDBMS） | NoSQL |
|------|----------------------|-------|
| 数据模型 | 二维表（固定 schema） | 灵活（无 schema 或动态 schema） |
| 事务支持 | ACID（强事务） | BASE（弱事务/最终一致） |
| 查询语言 | SQL（标准化） | 各自专用的查询接口 |
| 扩展方式 | 垂直扩展为主 | 水平扩展（天然支持） |
| 一致性 | 强一致性 | 最终一致性为主 |
| 典型场景 | 金融、电商、ERP | 缓存、日志、推荐、IoT |
| 关系 | 外键、JOIN 强关联 | 数据通常无关联或弱关联 |

> 🎯 **关系型数据库和 NoSQL 是互补关系，不是替代关系**——选择合适的工具解决合适的问题，而不是在一个工具上死磕。
