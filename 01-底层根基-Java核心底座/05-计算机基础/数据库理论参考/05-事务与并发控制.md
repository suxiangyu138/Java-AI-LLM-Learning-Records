## 1. 事务概念与 ACID

### 1.1 什么是事务

事务是一组**不可分割**的 SQL 操作，要么全部执行成功，要么全部失败回滚。

```sql
START TRANSACTION;
UPDATE account SET balance = balance - 100 WHERE id = 1;
UPDATE account SET balance = balance + 100 WHERE id = 2;
COMMIT;   -- 或 ROLLBACK;
```

### 1.2 ACID 特性

| 特性 | 说明 | 实现机制 |
|------|------|----------|
| **A** 原子性（Atomicity） | 事务是最小单元，全部成功或全部回滚 | undo log |
| **C** 一致性（Consistency） | 事务前后数据约束完整 | 应用层 + 数据库约束 |
| **I** 隔离性（Isolation） | 事务之间互不干扰 | MVCC + 锁 |
| **D** 持久性（Durability） | 提交后永久保存，崩溃不丢失 | redo log |

## 2. 隔离级别

### 2.1 并发问题

| 问题 | 定义 |
|------|------|
| **脏读** | 读到另一个事务**未提交**的数据 |
| **不可重复读** | 同一事务内两次查同一条数据，结果不同（其他事务修改提交） |
| **幻读** | 同一事务范围查询，前后行数不一致（其他事务插入/删除） |
| **丢失更新** | 两个事务同时修改同一行，后提交的覆盖了先提交的 |

### 2.2 隔离级别

| 级别 | 脏读 | 不可重复读 | 幻读 | 默认数据库 |
|------|------|-----------|------|-----------|
| READ UNCOMMITTED | 可能 | 可能 | 可能 | - |
| READ COMMITTED | 避免 | 可能 | 可能 | Oracle、PostgreSQL |
| **REPEATABLE READ** | 避免 | **避免** | 可能 | **MySQL InnoDB 默认** |
| SERIALIZABLE | 避免 | 避免 | 避免 | - |

> MySQL InnoDB 在 REPEATABLE READ 级别下通过 Gap Lock 抑制了幻读，实际表现接近 SERIALIZABLE。

## 3. MVCC 多版本并发控制

### 3.1 什么是 MVCC

MVCC（Multi-Version Concurrency Control）是 InnoDB 实现**无锁读**的机制——读操作不阻塞写操作，写操作不阻塞读操作。

### 3.2 核心组成

| 组件 | 作用 |
|------|------|
| **undo log** | 保存数据的历史版本（回滚段） |
| **ReadView** | 事务可见性快照 |
| **隐藏列** | `DB_TRX_ID`（事务 ID）、`ROLL_PTR`（回滚指针）组成版本链 |

### 3.3 版本链结构

```
每次更新操作不直接覆盖旧值，而是：
1. 将旧值写入 undo log
2. DB_ROLL_PTR 指向旧版本
3. DB_TRX_ID 记录当前事务 ID

一行数据的版本链：
[最新版本] ← ROLL_PTR ← [旧版本] ← ROLL_PTR ← [更旧版本]
```

### 3.4 RR 与 RC 的 ReadView 区别

| 隔离级别 | ReadView 生成时机 | 表现 |
|----------|-------------------|------|
| **READ COMMITTED** | 每次查询都重新生成 | 每次看到最新提交的数据 |
| **REPEATABLE READ** | 事务首次查询时生成，后续复用 | 整个事务看到一致的数据快照 |

## 4. 锁机制

### 4.1 锁分类

| 维度 | 类型 | 说明 |
|------|------|------|
| 粒度 | 表锁 | 开销小，并发低 |
| | 行锁 | 粒度细，InnoDB 默认 |
| | 页锁 | 介于表锁和行锁之间 |
| 模式 | 共享锁（S） | 读锁，可共享 |
| | 排他锁（X） | 写锁，互斥 |
| 意向锁 | 意向共享锁（IS） | 表级标记，快速判断是否有行锁 |
| | 意向排他锁（IX） | 表级标记 |

### 4.2 InnoDB 行锁三种算法

| 算法 | 说明 | 影响范围 |
|------|------|----------|
| **Record Lock**（记录锁） | 锁单行记录 | 仅锁住索引记录 |
| **Gap Lock**（间隙锁） | 锁两个索引之间的间隙 | 防止其他事务插入到间隙中 |
| **Next-Key Lock**（临键锁） | 记录锁 + 间隙锁 | RR 级别默认，解决幻读 |

```sql
-- 行锁示例
SELECT * FROM users WHERE id = 1 FOR UPDATE;     -- 行锁（X）
SELECT * FROM users WHERE id = 1 LOCK IN SHARE MODE;  -- 行锁（S）
```

### 4.3 两阶段锁协议

InnoDB 使用两阶段锁协议保证事务的隔离性：

| 阶段 | 说明 |
|------|------|
| 扩展阶段 | 事务执行过程中可以不断获取锁，但不会释放锁 |
| 收缩阶段 | 事务开始释放锁（通常是在 COMMIT/ROLLBACK 时），不再获取新锁 |

### 4.4 乐观锁与悲观锁

| 锁类型 | 思路 | 实现方式 | 适用场景 |
|--------|------|----------|----------|
| 悲观锁 | 默认冲突多，主动加锁 | `SELECT ... FOR UPDATE` | 写多读少 |
| 乐观锁 | 默认冲突少，提交时校验 | 版本号 `UPDATE ... WHERE version = old` | 读多写少 |

```sql
-- 乐观锁（版本号方式）
UPDATE products SET stock = stock - 1, version = version + 1
WHERE id = 1 AND version = old_version;
```

## 5. 死锁

### 5.1 死锁条件

| 条件 | 说明 |
|------|------|
| 互斥 | 资源一次只能被一个事务持有 |
| 持有并等待 | 事务持有资源时，请求其他事务持有的资源 |
| 不可剥夺 | 资源只能由持有的事务主动释放 |
| 循环等待 | 两个以上事务形成循环等待链 |

### 5.2 死锁预防与解决

| 方式 | 说明 |
|------|------|
| 预防 | 破坏死锁四大条件之一 |
| 检测 | InnoDB 自动死锁检测，回滚代价较小的事务 |
| 避免 | 统一加锁顺序、小事务、索引优化减少锁范围 |

```sql
-- 查看 InnoDB 状态（含锁信息）
SHOW ENGINE INNODB STATUS;
```

## 6. 高级事务处理

### 6.1 长事务的危害

| 危害 | 说明 |
|------|------|
| 锁久不释放 | 影响其他事务并发 |
| undo log 膨胀 | 占用大量磁盘空间 |
| MVCC 版本链过长 | 影响查询性能 |
| 主从同步延迟 | binlog 集中传输 |

### 6.2 保存点

```sql
START TRANSACTION;
INSERT INTO users(name) VALUES('A');
SAVEPOINT sp1;
INSERT INTO users(name) VALUES('B');
ROLLBACK TO sp1;    -- 回滚到 sp1，A 还在
COMMIT;             -- A 被提交，B 被回滚
```

### 6.3 事务隔离级别设置

```sql
-- 设置当前会话的隔离级别
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;

-- 查看当前隔离级别
SELECT @@transaction_isolation;
```
