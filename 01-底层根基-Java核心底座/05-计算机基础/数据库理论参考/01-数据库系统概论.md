## 1. 数据库系统概述

### 1.1 文件系统的缺陷

| 问题 | 描述 | 影响 |
|------|------|------|
| 数据冗余与不一致 | 多应用重复存储相同数据，修改不同步 | 数据冲突、业务异常 |
| 数据孤立 | 数据分散在不同文件中，难以跨文件查询 | 无法支撑复杂业务关联 |
| 完整性约束缺失 | 无统一约束规则，易存储非法数据 | 数据质量无法保证 |
| 并发访问问题 | 并发读写易冲突，无事务保障 | 数据错乱、超卖 |
| 安全性差 | 权限控制弱，数据易泄露 | 安全风险 |
| 应用程序与数据强耦合 | 数据结构变更需修改大量代码 | 维护成本高 |

### 1.2 核心概念

| 概念 | 定义 |
|------|------|
| 数据库（DB） | 长期存储在计算机内、有组织、可共享的数据集合 |
| 数据库管理系统（DBMS） | 管理数据库的系统软件，是数据库系统的核心 |
| 数据库系统（DBS） | DB + DBMS + 应用程序 + 用户 + DBA 组成的完整系统 |

### 1.3 数据库系统的目标

- **数据独立性**：应用程序与数据结构解耦
- **数据完整性**：保证数据正确性、一致性
- **并发控制**：多用户同时访问不冲突
- **故障恢复**：系统崩溃后数据不丢失
- **安全性**：权限控制，防止未授权访问

## 2. 数据模型

### 2.1 数据模型三代

| 模型 | 结构 | 代表 |
|------|------|------|
| 层次模型 | 树 | IMS |
| 网状模型 | 图 | IDS |
| 关系模型 | 二维表 | **MySQL、Oracle、PostgreSQL** |
| 对象-关系模型 | 嵌套表、引用 | PostgreSQL |
| 半结构化模型 | XML、JSON、KV、文档、图 | MongoDB、Redis、Neo4j |

### 2.2 关系模型核心概念

| 概念 | 对应 SQL 术语 | 说明 |
|------|-------------|------|
| 关系（Relation） | 表（Table） | 二维表结构 |
| 元组（Tuple） | 行（Row） | 一条记录 |
| 属性（Attribute） | 列（Column） | 一个字段 |
| 域（Domain） | 数据类型 | 属性取值范围 |
| 关系模式 | 表结构定义 | 表名 + 字段名列表 |

### 2.3 键的概念

| 键类型 | 说明 |
|--------|------|
| 超键 | 能唯一标识元组的属性集 |
| 候选键 | 最小的超键（去掉任何属性就不唯一了） |
| 主键 | 选中的候选键 |
| 外键 | 引用另一个关系的主键，保证参照完整性 |

### 2.4 关系三大完整性

| 完整性 | 说明 |
|--------|------|
| 实体完整性 | 主键非空且唯一 |
| 参照完整性 | 外键要么为 NULL，要么等于被参照表主键值 |
| 用户定义完整性 | 业务自定义约束（如年龄 0~150） |

## 3. 数据库系统体系结构

### 3.1 三层模式两层映射

```
外模式（视图层） ←→ 逻辑模式（概念层） ←→ 内模式（存储层）
     ↑                       ↑                       ↑
   视图 1...n             概念模式                物理存储
```

| 层级 | 说明 | 对应概念 |
|------|------|----------|
| 外模式（External Level） | 用户看到的数据库 | 视图（View） |
| 逻辑模式（Conceptual Level） | 整个数据库的逻辑结构 | 表结构定义 |
| 内模式（Internal Level） | 数据在存储介质上的组织方式 | 索引、文件组织 |

### 3.2 数据独立性

| 类型 | 说明 | 改变影响 |
|------|------|----------|
| **逻辑数据独立性** | 逻辑结构改变不影响外模式 | 增加字段不影响已有视图 |
| **物理数据独立性** | 物理存储改变不影响逻辑模式 | 索引变更不影响 SQL 查询 |

### 3.3 数据抽象层次

```
视图层（Level 1）：用户看到的部分数据         ---- 最高抽象
逻辑层（Level 2）：存储什么数据以及数据间的关系
物理层（Level 3）：数据如何存储               ---- 最低抽象
```

## 4. 数据库语言

| 语言类型 | 作用 | 关键字 |
|----------|------|--------|
| DDL（数据定义语言） | 定义库、表结构 | CREATE, ALTER, DROP |
| DML（数据操作语言） | 增删改数据 | INSERT, UPDATE, DELETE |
| DQL（数据查询语言） | 查询数据 | SELECT |
| DCL（数据控制语言） | 权限管理 | GRANT, REVOKE |
| TCL（事务控制语言） | 事务管理 | COMMIT, ROLLBACK, SAVEPOINT |

## 5. 数据库用户与 DBA

| 角色 | 职责 |
|------|------|
| 数据库管理员（DBA） | 管理数据库系统，权限控制，备份恢复，性能监控 |
| 应用开发者 | 编写 SQL 和应用程序访问数据库 |
| 终端用户 | 通过应用间接使用数据库 |

## 6. 存储引擎

| 引擎 | 事务 | 锁 | 特点 | 推荐场景 |
|------|------|-----|------|----------|
| **InnoDB** | 支持 | 行锁 | 崩溃安全恢复，MVCC | OLTP 业务（最常用） |
| MyISAM | 不支持 | 表锁 | 查询快，不支持事务 | 只读场景（基本淘汰） |
| Memory | 不支持 | 表锁 | 数据存内存 | 临时数据缓存 |

> 💡 **生产环境存储引擎统一使用 InnoDB**——支持事务、行锁、崩溃恢复，是唯一正确的选择。
