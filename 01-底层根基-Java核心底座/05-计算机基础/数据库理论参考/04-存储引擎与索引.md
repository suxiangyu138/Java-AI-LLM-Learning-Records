| 特性 | InnoDB | MyISAM |

| 事务 | 支持 | 不支持 |

## 2. 文件与存储结构

### 2.1 存储层次

```
CPU 寄存器 → L1/L2/L3 Cache → 内存 → 磁盘（SSD/HDD）
            速度递减，容量递增，价格递减
```

### 2.2 文件组织方式

| 方式 | 特点 | 适用 |
|------|------|------|
| 堆文件（Heap） | 无序，插入快，查询需全表扫描 | 日志表 |
| 顺序文件 | 按某字段有序存储 | 常用于索引 |
| 散列文件 | 根据散列值定位 | 等值查询快 |
| 聚簇文件 | 关联表数据存储在一起 | 减少 JOIN 的 IO |

### 2.3 InnoDB 存储结构

```
表空间（.ibd 文件）
  └── 段（Segment）
       ├── 索引段（B+ 树的非叶子节点）
       └── 数据段（B+ 树的叶子节点）
            └── 区（Extent，1MB = 64 个连续页）
                 └── 页（Page，默认 16KB）
                      ├── 数据行
                      ├── 索引键
                      └── 事务信息（MVCC）
```

## 3. 索引概述

### 3.1 索引类型

| 类型 | 说明 |
|------|------|
| B+ 树索引 | 最常见，支持范围查询和排序 |
| 散列索引 | 等值查询 O(1)，不支持范围查询 |
| 全文索引 | 用于文本内容的模糊搜索 |
| 空间索引 | GIS 数据类型专用 |
| 位图索引 | 低基数场景（如性别，MySQL 不支持） |

### 3.2 索引优缺点

| 优点 | 缺点 |
|------|------|
| 加速 WHERE、JOIN、ORDER BY | 占用存储空间 |
| 保证唯一性（唯一索引） | 增加写入（INSERT/UPDATE/DELETE）开销 |
| 覆盖索引可避免回表 | 索引维护需要成本 |

## 4. B+ 树索引

### 4.1 B+ 树结构

```
                  [根节点（非叶子）]
                 /       |       \
        [内节点]       [内节点]     [内节点]
        /    |  \      /   |  \    /   |   \
   [叶子] [叶子] [叶子] [叶子] [叶子] [叶子] [叶子] [叶子] [叶子]
   └──── 叶子节点之间通过双向指针连接 ────→ 支持范围扫描
```

### 4.2 B+ 树 vs B 树 vs 哈希

| 特性 | B+ 树 | B 树 | 哈希索引 |
|------|-------|------|----------|
| 非叶子节点存数据 | 不存（只存键） | 存 | 不适用 |
| 叶子节点链表 | 有（双向链表） | 无 | 不适用 |
| 范围查询 | 高效 | 中 | 不支持 |
| 等值查询 | O(log n) | O(log n) | O(1) |
| 排序 | 高效 | 中 | 不支持 |
| 磁盘 IO | 少（3~4 层即可存千万数据） | 略多 | 不适用 |

### 4.3 B+ 树为什么适合数据库

1. **多路平衡树**：层高低（3~4 层可存千万级数据），磁盘 IO 次数少
2. **非叶子节点只存键**：内存利用率高，可缓存更多索引
3. **叶子节点双向链表**：范围查询、排序、分页性能极强

## 5. 散列索引

### 5.1 散列函数

| 函数 | 示例 | 特点 |
|------|------|------|
| 除留余数法 | `h(K) = K mod M` | 最常用 |
| 乘法散列 | `h(K) = floor(M * (KA mod 1))` | 对 M 选择不敏感 |
| 全域散列 | 随机选择散列函数族 | 防止恶意攻击 |

### 5.2 冲突解决

| 方案 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| 链地址法 | 冲突时用链表链接 | 实现简单 | 链表过长退化为 O(n) |
| 开放寻址 | 冲突时寻找下一个空位 | 空间紧凑 | 删除复杂，装载因子有限 |

### 5.3 适用场景

> 散列索引适用于**等值查询**（O(1) 时间复杂度），但不支持范围查询（`>` `<` `BETWEEN`）和排序。MySQL Memory 引擎支持哈希索引。

## 6. 聚簇索引与二级索引

### 6.1 聚簇索引

| 说明 | 详情 |
|------|------|
| 定义 | 数据行和索引存储在一起，叶子节点存整行数据 |
| 数量 | 一张表只能有一个聚簇索引 |
| InnoDB | 主键索引就是聚簇索引 |

### 6.2 二级索引

| 说明 | 详情 |
|------|------|
| 定义 | 索引和数据分离，叶子节点存主键值 |
| 回表 | 通过二级索引查到主键后，再到聚簇索引中取完整数据 |

```sql
-- 聚簇索引：id（主键）→ 直接获取整行
SELECT * FROM users WHERE id = 1;

-- 二级索引 + 回表：name 索引存 id → 根据 id 再到聚簇索引取数据
SELECT * FROM users WHERE name = 'zhangsan';

-- 覆盖索引（不回表）：查询列都在索引中
SELECT name FROM users WHERE name = 'zhangsan';
```

### 6.3 索引设计原则

| 原则 | 说明 |
|------|------|
| 查询频繁的字段建索引 | WHERE、JOIN、ORDER BY 涉及的字段 |
| 区分度高的字段优先 | 如身份证号 > 性别 |
| 联合索引注意最左匹配 | (a,b,c) 可匹配 a、a+b、a+b+c |
| 长字段用前缀索引 | `INDEX(col(N))` |
| 索引不是越多越好 | 每个索引增加写入开销 |

## 7. 索引优化策略

### 7.1 索引失效场景

| 场景 | 示例 | 解决 |
|------|------|------|
| LIKE 以 % 开头 | `LIKE '%abc'` | 改 `LIKE 'abc%'` 或全文索引 |
| 隐式类型转换 | `WHERE phone = 13800000000` | 字符串加引号 |
| OR 两边未都建索引 | `WHERE a=1 OR b=2` | 两边都建索引或用 UNION |
| NOT IN / NOT EXISTS | `WHERE id NOT IN (1,2)` | 改 LEFT JOIN + IS NULL |
| 函数操作索引列 | `WHERE YEAR(date)=2024` | 改 BETWEEN 范围查询 |
| 联合索引跳列 | 索引(a,b,c)，查询 b | 调整索引顺序 |

### 7.2 位图索引

位图索引适用于**低基数**列（如性别、状态值），通过位运算快速进行 AND/OR 查询。MySQL 不支持位图索引，Oracle 支持。

> 🎯 **B+ 树是现代关系型数据库索引的事实标准**——理解 B+ 树原理是理解 SQL 查询性能的关键。
