## 1. TLS 协议基础

```text
TLS (Transport Layer Security) = SSL 的继任者

协议栈：
┌─────────────────────┐
│   HTTP / SMTP / ... │  ← 应用层
├─────────────────────┤
│   TLS 握手层         │  ← 密钥协商
├─────────────────────┤
│   TLS 记录层         │  ← 加密传输
├─────────────────────┤
│   TCP               │  ← 可靠传输
└─────────────────────┘

TLS 1.2（主流，2018）vs TLS 1.3（推荐，2018+）：
  1.2: 2-RTT 握手（慢 1 个来回）
  1.3: 1-RTT 握手（快）+ 移除不安全算法
```

### 核心能力

| 能力 | 实现方式 |
|------|---------|
| **加密（机密性）** | 对称加密（AES-GCM / ChaCha20） |
| **身份验证** | 非对称加密 + 数字证书（RSA/ECDSA） |
| **完整性** | HMAC（Hash-based Message Authentication Code） |

## 2. TLS 握手流程

```text
TLS 1.3 握手（1-RTT）：

Client → Server:  ClientHello
  "我支持 TLS 1.3, 算法: AES-GCM/ChaCha20, 密钥交换: ECDHE"
  (附送: 密钥交换参数 key_share)

Server → Client:  ServerHello + 证书 + Finished
  "用 TLS 1.3, 算法 AES-GCM, 这是我的证书"
  (附送: 服务器密钥交换参数, 签名证明身份)
  
  → 此时 Server 已经可以发送加密数据了！

Client → Server:  Finished
  (附送: 客户端身份证明, 如果需要双向认证)

→ 握手完成！后续数据全部加密传输
```

### 关键密码操作

```text
握手期间的密码学操作：

1. ECDHE 密钥交换：
   双方各自生成临时公私钥对 → 交换公钥 → 各自计算共享密钥
   → 前向安全性（服务器私钥泄露不影响历史会话）

2. 证书验证：
   客户端验证证书链: 网站证书 → 中间CA → 根CA（内置在浏览器/OS）

3. Finished 消息：
   用协商的密钥加密一个 MAC → 双方验证 → 确认握手未被篡改
```

## 3. 证书与 PKI

```text
PKI (Public Key Infrastructure) = 证书的签发、验证、吊销体系

证书链验证：
  根 CA (自签名，浏览器内置信任)
    └── 中间 CA (由根 CA 签发)
          └── 网站证书 (由中间 CA 签发)

X.509 证书内容：
  → 持有者 (CN=example.com)
  → 颁发者 (CA 名称)
  → 有效期 (Not Before / Not After)
  → 公钥
  → 签名 (CA 用私钥签名)
```

### 证书类型

| 类型 | 验证内容 | 适合 |
|------|---------|------|
| **DV** (域名验证) | 仅验证域名控制权 | 个人网站、博客 |
| **OV** (组织验证) | 域名 + 组织信息 | 企业网站 |
| **EV** (扩展验证) | 域名 + 严格组织审查 | 银行、金融（地址栏绿色） |

## 4. 常见网络攻击防御

| 攻击 | 原理 | 防御 |
|------|------|------|
| **MITM 中间人** | 攻击者拦截+转发通信 | TLS 证书验证 + HSTS |
| **DNS 劫持** | 篡改 DNS 解析结果 | DNSSEC + DoH/DoT |
| **SSL 剥离** | 将 HTTPS 降级为 HTTP | **HSTS**（强制 HTTPS） |
| **证书伪造** | 伪造证书冒充网站 | Certificate Transparency + CA 审计 |
| **重放攻击** | 重放加密的请求 | Nonce + 时间戳 |

```text
HSTS (HTTP Strict Transport Security)：
  → 服务器响应头: Strict-Transport-Security: max-age=31536000
  → 浏览器强制使用 HTTPS（即使用户输入 http://）
  → 证书错误时禁止用户"继续访问"
  → 彻底杜绝 SSL 剥离攻击
```

## 核心要点回顾

- TLS 1.3 只握手 1-RTT（比 1.2 快一个来回）
- ECDHE = 前向安全的密钥交换（服务器私钥泄露不影响历史数据）
- 证书链：网站证书 → 中间 CA → 根 CA（浏览器/OS 内置）
- HSTS = 强制 HTTPS + 禁止忽略证书错误
- MITM 防御 = 验证证书链 + HSTS + Certificate Transparency
