## 1. 高频面试题

### Q1（⭐⭐⭐⭐⭐）: HTTPS 是怎么保证安全的？

> TLS 握手 → 非对称加密交换密钥 → 对称加密传输数据
> 核心三步：身份验证（证书）+ 密钥协商（ECDHE）+ 加密传输（AES-GCM）
> HSTS 防止降级攻击

### Q2: SQL 注入怎么防？

> 四层防线：
> 1. 预编译 + 参数化查询（`#{}` 不用 `${}`）
> 2. 输入校验（白名单 + 类型检查）
> 3. 数据库最小权限（不给 DDL）
> 4. WAF / RASP

### Q3: XSS 和 CSRF 的区别？怎么防？

> XSS：在目标网站注入脚本（反射/存储/DOM），防御 = 输出编码 + CSP
> CSRF：利用用户已登录状态发起请求，防御 = Token + SameSite Cookie
> 记忆口诀：XSS = 脚本注入，CSRF = 跨站伪造

### Q4: JWT vs Session 认证的区别？

| 维度 | Session | JWT |
|------|:---:|:---:|
| 存储 | 服务端 | 客户端 |
| 状态 | 有状态 | 无状态 |
| 扩展性 | 需共享 Session | 天然分布式 |
| 注销 | 删除 Session | 难主动失效 |
| 适合 | 单体应用 | 微服务/API |

### Q5: OAuth 2.0 的授权码流程？

> 1. 用户点击"用 Google 登录"
> 2. 跳转 Google 授权页 → 用户同意
> 3. Google 回调 → 返回授权码 (Authorization Code)
> 4. 服务端用授权码 + Client Secret → 换 Access Token
> 5. 用 Access Token 获取用户信息

### Q6: 怎么设计一个安全的文件上传功能？

> 1. 客户端校验：扩展名白名单
> 2. 服务端校验：MIME type + Magic Number（文件头）
> 3. 存储分离：上传目录不允许执行权限
> 4. 重命名：UUID 文件名（防路径遍历）
> 5. 杀毒扫描：ClamAV
> 6. 大小限制：拒绝 > 10MB

### Q7: AI 系统特有安全威胁？

> Prompt 注入（最高危）、训练数据投毒、模型窃取、对抗样本
> Agent 过度自主权 → 安全护栏 + Human-in-the-Loop

## 核心要点回顾

- 安全面试 = 攻击路径 + 防御方案 + 工具选型
- 必会：HTTPS(TLS握手) + SQL注入(预编译) + XSS/CSRF + JWT/OAuth
- 加分：威胁建模(STRIDE) + AI安全(Prompt注入) + 零信任
