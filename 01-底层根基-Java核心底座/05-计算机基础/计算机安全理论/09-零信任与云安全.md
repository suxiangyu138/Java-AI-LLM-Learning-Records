## 1. 零信任架构

```text
传统安全模型（边界模型）：
  防火墙+内网 = 安全的 → 一旦突破防火墙 = 全部暴露 ❌

零信任模型：
  不信任任何人、任何设备、任何网络 → 每次都验证
```

### 零信任三大支柱

```text
1. 身份认证（Who）
   → MFA 多因素认证（密码 + 生物识别 + 硬件 Key）
   → 持续验证（不是登录一次就永远信任）

2. 设备信任（What）
   → 设备合规性检查（是否打补丁？是否有 EDR？）
   → 设备健康度评分

3. 最小权限（Access）
   → JIT (Just-In-Time) 权限（需要时才给，用完回收）
   → 微隔离（Micro-segmentation）——服务间也必须认证
```

### Google BeyondCorp

```text
Google 的零信任实现：
  → 没有内网 VPN —— 员工从任何网络直接访问
  → 每次请求都经过身份代理 (Access Proxy)
  → 代理检查：用户身份 + 设备状态 + 上下文（时间/位置）
  → 全部通过才放行
```

## 2. 云原生安全

### 4C 安全模型

```text
Cloud → Cluster → Container → Code
  │        │          │         │
 云提供商   K8s集群     容器      应用代码

每一层都有独立的安全责任：
  Cloud:  IAM / 网络策略 / 加密
  Cluster: RBAC / Pod 安全策略 / 审计
  Container: 镜像扫描 / 非 root 运行 / 只读文件系统
  Code: 输入校验 / SQL 注入防御 / 密钥管理
```

### K8s 安全实践

```yaml
# Pod Security Context（最小权限）
securityContext:
  runAsNonRoot: true          # 非 root 运行
  runAsUser: 1000
  readOnlyRootFilesystem: true  # 只读根文件系统
  allowPrivilegeEscalation: false  # 禁止提权
  capabilities:
    drop: ["ALL"]              # 丢弃所有 capabilities

# Network Policy（微隔离）
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
spec:
  podSelector:
    matchLabels:
      app: database
  ingress:
  - from:
    - podSelector:
        matchLabels:
          app: backend         # 只允许 backend pod 访问
```

## 3. IAM 身份与访问管理

```text
现代 IAM 组件：

认证 (Authentication)：     我是谁？
  → SSO (单点登录)
  → MFA (多因素认证)
  → FIDO2/WebAuthn (无密码认证)

授权 (Authorization)：      我能做什么？
  → RBAC (角色)
  → ABAC (属性)
  → Policy as Code (OPA/Rego)

审计 (Auditing)：           谁做了什么？
  → 操作日志
  → 异常行为检测
  → 合规报告
```

### OPA/Rego 策略示例

```rego
# OPA 策略：只有 owner 或 admin 能删除资源
package app.authz

default allow = false

allow {
    input.method == "DELETE"
    input.role == "admin"
}

allow {
    input.method == "DELETE"
    input.user == input.resource.owner
}
# 请求: GET /resource/123 → 不需要特殊权限
# 请求: DELETE /resource/123 → 必须是 admin 或 resource.owner
```

## 核心要点回顾

- 零信任 = 从不信任 + 每次验证 + 最小权限
- BeyondCorp = Google 的零信任实现（无需 VPN）
- 4C 安全：Cloud → Cluster → Container → Code
- K8s 安全 = RBAC + NetworkPolicy + PodSecurity + 镜像扫描
- OPA/Rego = 策略即代码（安全规则版本化管理）
