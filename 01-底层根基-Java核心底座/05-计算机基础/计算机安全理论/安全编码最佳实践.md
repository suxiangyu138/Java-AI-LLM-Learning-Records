## 一、输入安全

> **第一原则：永远不要信任用户输入。** 所有从外部来的数据——URL 参数、Header、Cookie、上传文件、第三方 API 返回——都必须校验。

### 1.1 通用校验清单

```java
// ① 类型校验
// ② 长度限制
// ③ 范围限制
// ④ 格式校验（正则白名单）
// ⑤ 业务逻辑校验

// 示例：用户注册
public class RegisterRequest {
    @NotBlank @Size(min=3, max=20)
    @Pattern(regexp = "^[a-zA-Z0-9_]+$")  // 白名单字符
    private String username;

    @NotBlank @Size(min=8, max=128)
    private String password;  // 不强校验格式，让用户自由

    @Email @Size(max=100)
    private String email;

    @Min(0) @Max(150)
    private Integer age;

    @Pattern(regexp = "^1[3-9]\\d{9}$")
    private String phone;
}
```

### 1.2 特殊字符处理

```java
// 场景1：动态排序字段 → 必须白名单
private static final Set<String> ALLOWED_SORT_FIELDS =
    Set.of("id", "username", "create_time", "update_time");

public List<User> getUsersByOrder(String orderBy, String direction) {
    if (orderBy == null || !ALLOWED_SORT_FIELDS.contains(orderBy)) {
        throw new IllegalArgumentException("Invalid sort field: " + orderBy);
    }
    if (!"ASC".equalsIgnoreCase(direction) && !"DESC".equalsIgnoreCase(direction)) {
        throw new IllegalArgumentException("Invalid direction: " + direction);
    }
    // 安全：orderBy 和 direction 都经过白名单校验
}
```

## 二、输出安全

### 2.1 API 响应：最小信息原则

```java
// ❌ 错误：返回了整个 Entity
@GetMapping("/user/{id}")
public User getUser(@PathVariable Long id) {
    return userMapper.selectById(id);
    // 返回了 password_hash, salt, is_deleted, 内部备注 等字段！
}

// ✅ 正确：使用 DTO，只返必须字段
@GetMapping("/user/{id}")
public UserDTO getUser(@PathVariable Long id) {
    User user = userMapper.selectById(id);
    return UserDTO.from(user);  // 只包含 id, username, avatar, bio
}
```

### 2.2 错误信息脱敏

```java
// ❌ 生产环境暴露细节
@ExceptionHandler(Exception.class)
public ResponseEntity<?> handle(Exception e) {
    return ResponseEntity.status(500).body(e.getMessage());
    // "Table 'xxx.users' doesn't exist" → 暴露表结构
    // "Connection refused to 10.0.1.5:3306" → 暴露内网 IP
}

// ✅ 统一错误响应，隐藏细节
@ExceptionHandler(Exception.class)
public ResponseEntity<ErrorResponse> handle(Exception e) {
    log.error("Internal error, traceId: {}", traceId, e);  // 日志记录详细信息
    return ResponseEntity.status(500)
        .body(new ErrorResponse("INTERNAL_ERROR", "服务内部错误，请稍后重试"));
        // 不返回具体错误原因，只返回 traceId 用于排查
}
```

### 2.3 防止信息泄露的响应头

```java
// 去掉默认暴露的中间件版本信息
response.setHeader("Server", "");            // 不返回 Nginx/Apache 版本
response.setHeader("X-Powered-By", "");      // 不返回框架版本
response.setHeader("X-Application-Context", ""); // Spring Boot 默认返回
```

## 三、数据存储安全

### 3.1 密码存储

```java
// ❌ 绝对禁止
String hash = md5(password);           // MD5 太弱
String hash = sha256(password);        // 无 salt，可彩虹表攻击

// ✅ 生产标准
BCryptPasswordEncoder encoder = new BCryptPasswordEncoder();
String hash = encoder.encode(password);
// cost factor = 10 → 2^10 = 1024 次迭代，约 0.1s/次
// 对于攻击者，0.1s × 100亿次试错 = 不可行
```

### 3.2 敏感配置加密

```yaml
# ❌ 敏感信息明文写在配置中
spring.datasource.password=MyPassword123
jwt.secret=my-secret-key
aliyun.oss.access-key-secret=xxx

# ✅ 方案1：环境变量（Docker/K8s）
spring.datasource.password=${DB_PASSWORD}

# ✅ 方案2：配置中心加密（Nacos/Apollo 支持加密存储）
spring.datasource.password=ENC(xxxxxx)

# ✅ 方案3：Vault / KMS（云服务密钥管理）
```

### 3.3 数据库操作安全

```java
// ① 最小权限原则：应用 DB 账号只有业务所需权限
// GRANT SELECT, INSERT, UPDATE, DELETE ON mydb.* TO 'app'@'%';
// 不给 DROP, ALTER, CREATE 权限

// ② 敏感字段加密存储
// 身份证、手机号等用 AES 加密存储（密钥放 KMS）
@TableField(typeHandler = EncryptedTypeHandler.class)  // MyBatis-Plus 自定义
private String idCard;

// ③ 逻辑删除代替物理删除
@TableLogic
private Integer isDeleted;  // 0-未删, 1-已删
```

## 四、日志安全

```java
// ❌ 危险：日志泄露敏感信息
log.info("用户登录: username={}, password={}", username, password);
log.info("支付请求: cardNo={}, cvv={}", cardNo, cvv);
log.info("短信验证码: phone={}, code={}", phone, code);

// ✅ 安全：日志脱敏
log.info("用户登录: username={}, password=***", username);
log.info("支付请求: cardNo={}****, cvv=***", cardNo.substring(0, 4));
log.info("短信验证码: phone={}****, code=***", phone.substring(0, 3));

// ✅ 关键操作审计日志（记录操作人/时间/IP/内容，不可删除）
auditLog.info("操作:删除用户, operator:{}, targetId:{}, ip:{}, time:{}",
    currentUser, targetUserId, requestIP, LocalDateTime.now());
```

### 日志级别与安全

| 级别 | 使用场景 | 安全注意 |
|------|---------|---------|
| **ERROR** | 系统错误 | 记录详细信息用于排查，但不要记录敏感参数 |
| **WARN** | 潜在风险（如频繁登录失败） | 登录失败可记录用户名，但不记录密码 |
| **INFO** | 关键业务节点（下单、支付） | 审计日志，不可记录敏感字段 |
| **DEBUG** | 开发调试 | 生产环境必须关闭 |

## 五、依赖与配置安全

### 5.1 依赖管理

```xml
<!-- ① 定期扫描漏洞 -->
<!-- Maven: mvn dependency-check:check -->
<!-- Gradle: gradle dependencyCheckAnalyze -->
<!-- OWASP Dependency-Check 插件 -->

<!-- ② 锁定版本，避免自动升级引入风险 -->
<dependency>
    <groupId>com.fasterxml.jackson.core</groupId>
    <artifactId>jackson-databind</artifactId>
    <version>2.15.2</version>  <!-- 不用版本范围 -->
</dependency>

<!-- ③ 排除不需要的传递依赖 -->
<exclusions>
    <exclusion>
        <groupId>commons-logging</groupId>
        <artifactId>commons-logging</artifactId>  <!-- 已知漏洞 -->
    </exclusion>
</exclusions>
```

### 5.2 Spring Boot 安全配置

```yaml
# application.yml 安全配置

spring:
  # 关闭 actuator 敏感端点（或限制内网访问）
  # management.endpoints.web.exposure.include=health,info  # 用白名单

  # Session Cookie 安全
  server:
    servlet:
      session:
        cookie:
          http-only: true     # JS 不可读
          secure: true        # 仅 HTTPS 传输
          same-site: strict   # 防 CSRF

# 自定义错误页面，不暴露默认错误信息
server:
  error:
    whitelabel:
      enabled: false

# 限制文件上传
spring:
  servlet:
    multipart:
      max-file-size: 10MB
      max-request-size: 20MB
```

## 六、API 安全清单

### 上线的安全检查清单

```
□ 所有接口都有认证（除非明确公开）
□ 所有接口都有授权校验（不能越过权访问别人的数据）
□ 输入参数都有校验（@Valid / 类型 / 长度 / 格式 / 范围）
□ SQL 查询都用参数化（PreparedStatement / MyBatis #{}）
□ 错误响应不泄露堆栈/版本/内网信息
□ 日志中不打印密码/Token/验证码/身份证/银行卡号
□ Cookie 设置了 HttpOnly + Secure + SameSite
□ 全站 HTTPS，配置了 HSTS
□ 文件上传有类型/大小/内容校验
□ 敏感配置不在代码/配置文件中（用环境变量/KMS）
□ 第三方依赖无已知严重漏洞（OWASP Dependency-Check）
□ 关键操作有审计日志（不可删除）
□ CORS 只允许信任域名（不用 *）
□ 接口有频率限制（防暴力攻击/爬虫）
```

## 七、面试高频问题

**Q1：你们的项目怎么保证安全？**
> 分层防护：① 代码层（输入校验+参数化查询+输出脱敏+DTO）② 框架层（Spring Security 认证授权+CSRF Token+CORS 限制）③ 基础设施层（HTTPS+WAF+限流+Nginx 安全配置）④ 流程层（Code Review 关注安全、定期依赖扫描、渗透测试）。

**Q2：密码到底应该怎么存？**
> bcrypt/Argon2 慢哈希 + 随机 salt（存在哈希值中）。绝不用 MD5/SHA-256 直接哈希，也绝不用可逆加密。

**Q3：发现生产环境有安全漏洞，怎么处理？**
> ① 评估严重程度（CVSS 评分）② 制定修复方案和回滚方案 ③ 灰度发布 ④ 验证修复效果 ⑤ 排查是否有数据泄露 ⑥ 复盘和改进流程。

**Q4：你是怎么理解"安全是贯穿全流程的"？**
> ① 设计阶段：威胁建模（敏感数据识别、攻击面分析）② 开发阶段：安全编码规范 + Code Review ③ 测试阶段：SAST(静态扫描) + DAST(动态扫描) + 渗透测试 ④ 部署阶段：安全配置 + 最小权限 ⑤ 运维阶段：监控告警 + 漏洞响应。

## 📖 核心要点速记

1. **输入**：永远不信任 → 校验（类型/长度/范围/格式/业务逻辑）
2. **输出**：最小信息 → DTO + 错误脱敏 + 响应头清理
3. **存储**：密码 bcrypt + 配置 KMS + 日志脱敏 + 数据库最小权限
4. **依赖**：定期扫描（OWASP DC）+ 锁定版本 + 排除不安全传递依赖
5. **上线清单**：14 项安全检查，逐项确认
6. **心态**：安全不是功能，是习惯。每写一行代码都问："如果这是恶意输入会怎样？"
