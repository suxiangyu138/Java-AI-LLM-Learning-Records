## 1. 密码学核心目标

| 目标 | 含义 | 实现手段 |
|------|------|---------|
| **机密性（Confidentiality）** | 数据不可被未授权者读取 | 对称/非对称加密 |
| **完整性（Integrity）** | 数据不被篡改 | 哈希函数、MAC |
| **认证（Authentication）** | 确认通信双方身份 | 数字签名、证书 |
| **不可否认性（Non-repudiation）** | 发送方不能否认发送过 | 数字签名 |

## 2. 对称加密

> 加密和解密使用**同一把密钥**。速度快，适合大量数据加密。

### 2.1 主流算法对比

| 算法 | 密钥长度 | 分组大小 | 安全性 | 性能 | 推荐度 |
|------|---------|---------|--------|------|--------|
| **AES** | 128/192/256 | 128 bit | 极高 | 高 | 首选 |
| DES | 56 bit | 64 bit | 已破解 | 低 | 废弃 |
| 3DES | 168 bit | 64 bit | 中等 | 极低 | 废弃 |
| ChaCha20 | 256 bit | 流加密 | 极高 | 高 | 移动端首选 |
| SM4 | 128 bit | 128 bit | 高 | 高 | 国密标准 |

### 2.2 AES 工作模式

| 模式 | 特点 | 并行 | 需要 IV | 推荐度 |
|------|------|------|---------|--------|
| **ECB** | 每块独立加密，相同明文相同密文 | 是 | 否 | 不安全 |
| **CBC** | 每块与前一块 XOR 再加密 | 解密可并行 | 是 | 可用 |
| **CTR** | 计数器模式，转为流加密 | 是 | 是 | 推荐 |
| **GCM** | CTR + GMAC 认证标签，加密+完整性校验（AEAD） | 是 | 是 | 首选 |

> 生产推荐：AES-256-GCM，同时提供加密和完整性校验（AEAD），兼具安全性与性能。

### 2.3 核心问题：密钥分发

对称加密的前提是双方拥有同一把密钥。如何安全地将密钥传给对方？答案是在非对称加密的帮助下交换密钥——TLS 正是这么做的。

## 3. 非对称加密

> 使用**不同密钥**：公钥加密，私钥解密。速度慢，适合加密少量数据（密钥、签名）。

### 3.1 主流算法对比

| 算法 | 原理 | 密钥长度（等同安全） | 用途 |
|------|------|---------------------|------|
| **RSA** | 大整数分解 | 2048/3072/4096 | 加密、签名 |
| **ECC** | 椭圆曲线离散对数 | 256 bit = RSA 3072 | 加密（ECIES）、签名（ECDSA） |
| **SM2** | 椭圆曲线（国密） | 256 bit | 加密/签名 |
| **DH/DHE** | 离散对数 | 2048+ | 密钥交换 |
| **ECDHE** | 椭圆曲线 DH | 256 bit | TLS 密钥交换首选 |

### 3.2 RSA vs ECC

| 对比 | RSA | ECC |
|------|-----|-----|
| 同安全级别密钥长度 | 2048 bit（112 bit 安全） | 256 bit（128 bit 安全） |
| 性能 | 慢（大数运算） | 快（曲线运算） |
| 密钥大小 | 大 | 小（适合移动端） |
| 成熟度 | 极高 | 高 |
| 抗量子计算 | 否 | 否 |

### 3.3 非对称加密的缺点

- **速度慢**：比对称加密慢 100~1000 倍
- **不支持大文件**：RSA-2048 最多加密 245 字节
- 实际用法：非对称加密传输**对称密钥**，对称密钥加密**数据**

## 4. 哈希函数

> 任意长度输入 -> 固定长度输出。单向不可逆。核心特性：**雪崩效应**（改 1 位输入导致一半输出位变化）。

### 4.1 主流算法

| 算法 | 输出长度 | 安全性 | 推荐度 |
|------|---------|--------|--------|
| MD5 | 128 bit | 已被碰撞攻击 | 废弃 |
| SHA-1 | 160 bit | 已被碰撞攻击 | 废弃 |
| **SHA-256** | 256 bit | 极高 | 推荐 |
| SHA-512 | 512 bit | 极高 | 需要更长输出时 |
| SHA-3 | 可变 | 极高 | 新项目 |
| BLAKE3 | 可变 | 极高 | 性能最强 |
| SM3 | 256 bit | 极高 | 国密标准 |

### 4.2 哈希的常见用途

| 用途 | 说明 | 示例 |
|------|------|------|
| **密码存储** | 加盐哈希后存储 | `bcrypt(password + salt)` |
| **文件完整性** | 下载文件后对比哈希值 | SHA-256 校验 |
| **数字签名** | 对哈希值签名，不对原文 | RSA-SHA256 |
| **数据去重** | 哈希值相同视为重复 | 云存储去重 |

### 4.3 密码哈希（慢哈希）

> 密码哈希要**慢**——增加暴力破解成本。

| 算法 | 特点 | 推荐度 |
|------|------|--------|
| **bcrypt** | 自带 salt + 可调节迭代次数 | 首选 |
| **scrypt** | 内存密集，抵抗 GPU/ASIC 攻击 | 推荐 |
| **Argon2** | 2015 年密码哈希竞赛冠军（最安全） | 首选 |
| **PBKDF2** | 基于 HMAC，NIST 推荐 | 可用 |

> 生产推荐：bcrypt（兼容性最好）或 Argon2id（最新最安全）。

## 5. 数字签名与 PKI

### 5.1 数字签名流程

```
签名：
  原文 -> SHA-256 -> 哈希值 -> 私钥加密 -> 数字签名

验证：
  原文 -> SHA-256 -> 哈希值 A
  数字签名 -> 公钥解密 -> 哈希值 B
  比较 A == B？相等则验证通过
```

> 数字签名 = 反过来的非对称加密：**私钥签名，公钥验证**。

### 5.2 PKI 体系

```
CA（证书颁发机构）
  |
  ├─ 根证书（自签名，预装在操作系统/浏览器中）
  │   └─ 中间 CA 证书
  │       └─ 服务器证书（域名）
  |
  └─ 证书链验证：
      服务器证书 <- 中间 CA <- 根 CA（信任锚点）
```

### 5.3 X.509 证书内容

| 字段 | 说明 |
|------|------|
| Subject | 证书持有者（域名） |
| Issuer | 颁发者（CA） |
| Validity | 有效期（Not Before / Not After） |
| Public Key | 公钥 |
| Signature | CA 对证书的签名 |
| SAN | Subject Alternative Name，多域名支持 |

## 6. 密钥交换协议

> 如何在不安全的信道上**安全地协商出共享密钥**？

### 6.1 DH 密钥交换

```
Alice                           Bob
  |                               |
  |  1. 公开参数 g, p（大素数）   |
  |                               |
  |  2. Alice 生成私钥 a          |
  |     计算 A = g^a mod p        |
  |     发送 A  -->               |
  |                               |
  |  3. Bob 生成私钥 b            |
  |     计算 B = g^b mod p        |
  |                  <-- 发送 B   |
  |                               |
  |  4. 共享密钥 K = B^a mod p    |
  |               K = A^b mod p   |
  |                               |
  |  g^ab mod p 双方都知道，窃听者无法计算（离散对数难题）
```

### 6.2 ECDHE（TLS 1.3 默认）

> 椭圆曲线 + 临时（Ephemeral）密钥 = **前向安全性（Forward Secrecy）**。

即使服务器私钥泄露，历史会话也无法解密——每次会话使用临时密钥，用完即销毁。

## 7. Java 密码学实践

### 7.1 AES-GCM 加密

```java
import javax.crypto.Cipher;
import javax.crypto.spec.GCMParameterSpec;
import javax.crypto.spec.SecretKeySpec;

// 加密
Cipher cipher = Cipher.getInstance("AES/GCM/NoPadding");
GCMParameterSpec gcmSpec = new GCMParameterSpec(128, iv); // 96-bit IV 推荐
cipher.init(Cipher.ENCRYPT_MODE, new SecretKeySpec(key, "AES"), gcmSpec);
byte[] ciphertext = cipher.doFinal(plaintext);
// ciphertext 自带 GMAC 认证标签（最后 16 字节）
```

### 7.2 密码哈希（bcrypt）

```java
// Spring Security 自带 BCryptPasswordEncoder
BCryptPasswordEncoder encoder = new BCryptPasswordEncoder();
String hash = encoder.encode("mypassword");
// $2a$10$N9qo8uLOickgx2ZMRZoMyeIjZAgcfl7p92ldGxad68LJZdL17lhWy
// $2a$ -> bcrypt, 10 -> cost factor (2^10 次迭代)

boolean matches = encoder.matches("mypassword", hash); // true
```

### 7.3 安全随机数

```java
// 错误：伪随机，可预测
Random random = new Random();

// 正确：加密安全随机数
SecureRandom secureRandom = SecureRandom.getInstanceStrong();
byte[] randomBytes = new byte[32];
secureRandom.nextBytes(randomBytes);
```

## 8. TLS/SSL 协议

> TLS（Transport Layer Security）在 TCP 之上提供加密通信。SSL 是其前身（已废弃）。

### 8.1 TLS 在协议栈中的位置

```
应用层  HTTP | SMTP | FTP ...
       --------------------
       TLS（安全层）       <- 这里！
       --------------------
传输层  TCP
网络层  IP
```

### 8.2 TLS 1.3 握手（1-RTT）

```
Client                                    Server
  |                                          |
  |  1. ClientHello                          |
  |     支持的密码套件、密钥共享(Key Share)  |
  |     --------------------------------->   |
  |                                          |
  |  2. ServerHello + 加密扩展               |  (1-RTT)
  |     选定密码套件、密钥共享               |  此时服务器已可发送加密数据
  |     服务器证书 + 证书验证 + Finished      |
  |     <---------------------------------   |
  |                                          |
  |  3. Finished（加密的）                   |
  |     --------------------------------->   |  此时客户端已可发送加密数据
  |                                          |
  |  加密通道建立（0-RTT 模式还可更快）      |
```

### 8.3 TLS 1.2 vs TLS 1.3

| 对比 | TLS 1.2 | TLS 1.3 |
|------|---------|---------|
| 握手 RTT | 2-RTT | 1-RTT（0-RTT 可选） |
| 密钥交换 | RSA / DHE / ECDHE | 仅 ECDHE（强制前向安全） |
| 密码套件 | 37 种 | 5 种（删除不安全算法） |
| 对称加密 | CBC / GCM | 仅 AEAD（GCM / ChaCha20-Poly1305） |

### 8.4 密码套件

```
TLS_AES_256_GCM_SHA384
  +- TLS：协议版本
  +- AES_256_GCM：对称加密算法（AEAD）
  +- SHA384：哈希/伪随机函数
```

## 9. HTTPS 深入

### 9.1 HTTPS 解决的问题

| 问题 | HTTP（明文） | HTTPS（加密） |
|------|-------------|--------------|
| 窃听 | 中间人可读所有内容 | 加密内容不可读 |
| 篡改 | 中间人可修改内容 | MAC 校验防篡改 |
| 冒充 | DNS 劫持到钓鱼站 | 证书验证身份 |
| 重放 | 抓包重放请求 | 时间戳 + Nonce 防重放 |

### 9.2 证书验证链

```
浏览器验证流程：
1. 收到服务器证书
2. 检查证书是否在有效期内
3. 检查证书是否被吊销（CRL / OCSP）
4. 用中间 CA 公钥验证服务器证书签名
5. 用根 CA 公钥验证中间 CA 证书签名
6. 根 CA 在信任列表中？通过
7. 验证域名是否匹配（SAN / CN）
8. 全部通过 -> 信任
```

### 9.3 HSTS

```
Strict-Transport-Security: max-age=31536000; includeSubDomains; preload

作用：
1. 浏览器强制 HTTPS，拒绝 HTTP 连接
2. 证书错误时用户无法跳过
3. includeSubDomains -> 所有子域名强制 HTTPS
4. preload -> 加入浏览器预加载列表
```

### 9.4 HTTPS 优化

| 优化点 | 做法 |
|--------|------|
| **Session 复用** | 首次握手后缓存 Session ID/Ticket，后续 0-RTT |
| **OCSP Stapling** | 服务器主动获取证书状态并随握手发送，省去客户端查询 |
| **证书链优化** | 证书链尽量短（根->中间->服务器，3 级为佳） |
| **证书类型** | ECC 证书（256-bit）比 RSA（2048-bit）快 |

## 10. DDoS 攻击与防护

### 10.1 常见 DDoS 攻击类型

| 类型 | 原理 | OSI 层 | 典型工具 |
|------|------|--------|---------|
| **SYN Flood** | 大量 SYN 包不完成握手，耗尽连接队列 | L4 | hping3 |
| **UDP Flood** | 大量 UDP 包占满带宽 | L4 | DNS/NTP 放大 |
| **HTTP Flood** | 大量 HTTP 请求消耗应用资源 | L7 | CC 攻击 |
| **DNS 放大** | 伪造源 IP 发小请求给 DNS，放大响应 | L4 | 放大倍数 50x+ |
| **Slowloris** | 慢速发送 HTTP Header，占满连接池 | L7 | 连接不释放 |

### 10.2 防护层次

```
L3/L4 DDoS -> 黑洞路由 / IP 清洗 / 云防护（Cloudflare、阿里云高防）
L7 DDoS   -> CDN + WAF + 限流 + 验证码 + 源站隐藏
DNS 放大  -> 关闭递归查询 / 限制响应速率
```

### 10.3 后端基础防护

```java
// 接口限流
@RateLimiter(permitsPerSecond = 100)

// 请求大小限制
spring.servlet.multipart.max-file-size=10MB

// 连接超时
server.tomcat.connection-timeout=5000

// 并发连接数限制（Nginx）
// limit_conn_zone $binary_remote_addr zone=addr:10m;
// limit_conn addr 10;
```

## 11. 防火墙与 IDS/IPS

### 11.1 防火墙类型

| 类型 | 工作层 | 能力 | 代表 |
|------|--------|------|------|
| **包过滤** | L3/L4 | 按 IP/端口/协议放行 | iptables、ACL |
| **状态检测** | L3/L4 | 跟踪连接状态 | iptables + conntrack |
| **应用层代理** | L7 | 代理应用协议，内容过滤 | Nginx 反向代理、WAF |
| **WAF** | L7 | 识别 Web 攻击（SQL 注入/XSS/CSRF） | ModSecurity、阿里云 WAF |

### 11.2 IDS vs IPS

| 对比 | IDS（检测） | IPS（防御） |
|------|------------|------------|
| 部署方式 | 旁路（镜像流量） | 串联（inline） |
| 作用 | 发现攻击 -> 告警 | 阻断攻击 |
| 对性能影响 | 无（不经过） | 有（所有流量经过） |
| 代表性工具 | Snort、Suricata | Suricata（IPS 模式） |

## 12. 中间人攻击（MITM）

### 12.1 常见 MITM 攻击

| 攻击 | 手法 | 防御 |
|------|------|------|
| **ARP 欺骗** | 伪造 ARP 响应，将流量导向攻击者 | 静态 ARP 绑定、交换机端口安全 |
| **DNS 劫持** | 篡改 DNS 响应，指向钓鱼站 | DNSSEC、DoH |
| **SSL 剥离** | 将 HTTPS 降级为 HTTP | HSTS |
| **伪造证书** | 自签证书冒充服务器 | 证书钉扎（Certificate Pinning） |
| **WiFi 钓鱼** | 伪造同名 WiFi 截获流量 | VPN、HSTS |

### 12.2 TLS 对 MITM 的防护

TLS 通过证书验证基本杜绝了 MITM，除非：
- 攻击者控制了受信任的 CA（极少见）
- 用户在浏览器中点了"继续访问（不安全）"
- 企业内部安装了自定义根证书做 TLS 检查（合法 MITM）

## 13. DNS 安全

### 13.1 DNS 安全威胁

| 威胁 | 说明 |
|------|------|
| **DNS 劫持** | 篡改 DNS 响应，引导到钓鱼站 |
| **DNS 缓存投毒** | 伪造 DNS 响应注入递归 DNS 缓存 |
| **DNS 隧道** | 利用 DNS 协议传输非 DNS 数据（数据外泄） |
| **DDoS 放大** | 伪造源 IP 发起 DNS 查询，响应放大到受害者 |

### 13.2 防护方案

| 方案 | 作用 |
|------|------|
| **DNSSEC** | 对 DNS 数据进行数字签名，防篡改 |
| **DoH（DNS over HTTPS）** | DNS 查询走 HTTPS，防窃听/劫持 |
| **DoT（DNS over TLS）** | DNS 查询走 TLS |
| **DNS 防火墙** | 过滤恶意域名请求 |

## 14. 安全核心原则

> 四原则贯穿开发、测试、部署全生命周期。

| 原则 | 核心思想 | 实践要点 |
|------|----------|----------|
| **最小权限原则** | 应用、用户、进程仅拥有完成任务必需的最小权限 | 数据库账号仅授予业务必需权限；Java 程序使用非 root 用户运行 |
| **纵深防御原则** | 构建多层防护体系，某一层失效时其他层仍能阻挡 | 防御 SQL 注入：输入验证 + 参数绑定 + ORM 框架三重防护 |
| **数据最小化原则** | 仅收集和存储业务必需的数据 | 敏感数据无需完整存储的不存，减少泄露风险面 |
| **可审计原则** | 记录关键操作日志，便于安全事件追溯 | 记录操作人、操作时间、IP 地址、操作内容 |

## 15. Java 后端安全威胁模型

| 威胁类型 | 典型场景 | 后端危害 |
|----------|----------|----------|
| **SQL 注入** | 用户输入拼接 SQL 语句 | 数据泄露、篡改、删除，甚至获取服务器权限 |
| **XSS** | 评论区、表单输入恶意 JS 脚本 | 窃取 Cookie、会话劫持 |
| **CSRF** | 伪造已登录用户身份发起恶意请求 | 越权操作，财产损失或数据泄露 |
| **权限越界** | 低权限用户访问高权限资源 | 敏感信息泄露、越权操作 |
| **敏感数据泄露** | 密码明文存储、接口明文传输 | 用户隐私泄露、账号被盗 |
| **依赖包漏洞** | 使用存在漏洞的第三方依赖（Log4j、FastJSON） | 远程代码执行、服务器被入侵 |
| **配置不当** | 数据库弱密码、Redis 未授权访问、生产环境开启调试 | 服务器被入侵、数据泄露 |

## 核心要点速记

1. **对称加密**：AES-256-GCM（首选），加密+认证一体化
2. **非对称加密**：RSA（老牌）/ ECC（新锐），用于密钥交换和签名
3. **哈希**：SHA-256（通用）/ bcrypt（密码）/ Argon2（最安全）
4. **签名**：私钥签名 + 公钥验证 = 防篡改 + 防否认
5. **密钥交换**：ECDHE（前向安全）-> TLS 1.3 默认
6. **TLS 1.3**：1-RTT + ECDHE + AEAD 加密
7. **HTTPS**：加密 + 认证 + 完整性，证书链 + HSTS
8. **DDoS 防护**：云清洗（L4）+ WAF + 限流（L7）
9. **DNS 安全**：DNSSEC（签名）+ DoH/DoT（加密传输）
10. **安全原则**：最小权限 + 纵深防御 + 数据最小化 + 可审计
