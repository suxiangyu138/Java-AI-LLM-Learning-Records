## 1. 访问控制模型

| 模型 | 全称 | 原理 | 使用场景 |
|------|------|------|---------|
| **DAC** | Discretionary AC | 文件所有者决定权限 | Linux 传统权限(rwx) |
| **MAC** | Mandatory AC | 系统策略强制访问 | SELinux / AppArmor |
| **RBAC** | Role-Based AC | 基于角色的权限 | K8s / 数据库 / 企业 |
| **ABAC** | Attribute-Based AC | 基于属性的权限 | AWS IAM / 现代云 |

### Linux 权限模型

```bash
# DAC: 传统 Unix 权限
-rwxr-xr-- 1 alice dev 4096 Jan 1 file.txt
#  owner=rwx, group=rx, others=r

# 特殊权限
chmod u+s /usr/bin/passwd   # SUID: 以文件所有者的身份执行
chmod g+s /shared/dir       # SGID: 继承目录的组
chmod +t /tmp               # Sticky: 只有文件所有者能删除

# MAC: SELinux
ls -Z                         # 查看安全上下文
semanage fcontext -a -t httpd_sys_content_t "/web(/.*)?"
```

## 2. 进程隔离与沙箱

```text
进程隔离层次（由弱到强）：
  chroot → 容器(Docker) → 虚拟机(VM) → 物理隔离

容器安全边界：
  Docker 不是 VM！共享同一个内核
  → Namespace: 隔离进程/网络/文件系统视图
  → Cgroups: 限制 CPU/内存/IO 资源
  → Capabilities: 细粒度权限控制（替代 root）
  → Seccomp: 限制可用的系统调用
```

### Docker 安全最佳实践

```dockerfile
# ❌ 不安全
FROM ubuntu
USER root
CMD ["python", "app.py"]

# ✅ 安全
FROM ubuntu
RUN useradd -m -s /bin/bash appuser
USER appuser                      # 非 root 运行
CMD ["python", "app.py"]

# docker run --read-only --cap-drop=ALL --security-opt=no-new-privileges
```

### Seccomp 系统调用过滤

```json
// seccomp-profile.json — 限制可用的系统调用
{
  "defaultAction": "SCMP_ACT_ERRNO",
  "syscalls": [
    {"names": ["read","write","open","close","fstat","mmap"], "action": "SCMP_ACT_ALLOW"}
  ]
}
// docker run --security-opt seccomp=profile.json
```

## 3. 内存保护机制

| 机制 | 全称 | 防御 |
|------|------|------|
| **ASLR** | Address Space Layout Randomization | 随机化内存地址 → 难以预测跳转地址 |
| **DEP/NX** | Data Execution Prevention | 堆栈不可执行 → 防止代码注入 |
| **Stack Canary** | 栈金丝雀 | 检测栈溢出 |
| **PIE** | Position Independent Executable | 配合 ASLR 随机化代码地址 |
| **CFI** | Control Flow Integrity | 限制控制流跳转目标 |

```bash
# 查看进程的安全特性
cat /proc/self/status | grep -E "^(VMR|Name|Seccomp)"
# VmRSS — 内存使用
# Seccomp — 0=关闭, 1=strict, 2=filter
```

## 4. Linux 安全加固

```bash
# 1. 最小权限原则
useradd -m -s /bin/bash app    # 创建专用用户
# 不用 root 跑应用！不用 root 跑应用！

# 2. SSH 加固
# /etc/ssh/sshd_config
PermitRootLogin no             # 禁止 root 登录
PasswordAuthentication no      # 禁密码登录（只用密钥）
MaxAuthTries 3                 # 最多试 3 次

# 3. 防火墙
ufw default deny incoming
ufw allow 22/tcp               # SSH
ufw allow 443/tcp              # HTTPS
ufw enable

# 4. 审计
auditctl -w /etc/passwd -p wa -k passwd_changes  # 监控文件修改
ausearch -k passwd_changes                       # 查询审计日志

# 5. 自动更新
apt install unattended-upgrades
```

## 核心要点回顾

- DAC(所有者决定) → MAC(系统强制的 SELinux) → RBAC(角色)
- 容器安全 = Namespace + Cgroups + Capabilities + Seccomp
- 内存保护五件套：ASLR + DEP/NX + Stack Canary + PIE + CFI
- Linux 加固：不用 root + 密钥登录 + 防火墙 + 审计
- 攻击者的终极目标 = 提权到 root → 所有防御的最终目标 = 阻止提权
