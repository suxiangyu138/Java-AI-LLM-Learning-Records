## 1. 接口演进史

```text
PATA（IDE）→ SATA 1.0 (1.5Gbps) → SATA 2.0 (3Gbps) → SATA 3.0 (6Gbps，2009 至今)
                                                          │
                    AHCI 协议（为 HDD 设计）───────────────┤ 死区：SATA Express 已死
                                                          │
NVMe 1.0 (2011) → 1.3/1.4 → 2.0/2.1 → 2.2 ──────────────┴→ PCIe 3.0/4.0/5.0/6.0
```

**SATA 的瓶颈本质**：不是带宽（6Gbps ≈ 550MB/s 实测），而是 AHCI 协议为 HDD 设计——单队列、高中断、寄存器轮询。SSD 快但协议排队，1 个队列 × 32 深度让多核 CPU 无法并行下达命令。

## 2. NVMe 革命：队列模型

| 维度 | AHCI（SATA） | NVMe |
|------|:---:|:---:|
| 队列数 | 1 | **64K（65535）** |
| 每队列深度 | 32 | **64K（65535）** |
| 命令提交 | 寄存器写（串行） | 内存队列提交/完成（MMIO 敲门一次） |
| 中断 | 单中断线，每 IO 中断 | **MSI-X 每队列独立中断**，中断聚合 |
| 命令集 | 8 个命令 | 多命令族（读写/管理/元数据/点名） |
| 多核扩展 | 差（单队列锁竞争） | 每核一队列，无锁并行 |
| 延迟开销 | 高（协议层 ~10-20μs） | 低（~1-5μs） |

**NVMe 为何快**：① 命令放共享内存环形队列，一次 MMIO 敲醒控制器即可批量取走；② 每核独立队列消除锁竞争；③ MSI-X 中断直达 CPU 核；④ 支持多命名空间（NS）与 NVMe-oF（网络化）。

## 3. PCIe 通道与带宽

| 代际 | 编码 | 每通道速率 | ×4 理论带宽 | ×4 实测典型 | 发布时间 |
|------|:---:|:---:|:---:|:---:|------|
| PCIe 3.0 | 128b/130b | 8 GT/s | 3.94 GB/s | ~3.5 GB/s | 2010 |
| PCIe 4.0 | 128b/130b | 16 GT/s | 7.88 GB/s | ~7 GB/s | 2017 |
| PCIe 5.0 | 128b/130b | 32 GT/s | 15.75 GB/s | ~14 GB/s | 2019 |
| **PCIe 6.0** | **PAM4 + FLIT** | 64 GT/s | **31.5 GB/s** | ~28 GB/s | 2022 规范，2026 量产 |

**要点**：
- 理论带宽 = 通道速率 × 通道数 ÷ 编码开销；实测约理论的 85-90%。
- **PCIe 6.0 用 PAM4 信号**（4 电平调制，每周期 2 比特）+ FLIT 定长包 + 前向纠错（FEC），延迟反而低于 5.0。
- 2026 实测标杆：三星 PM1763（Gen6 ×4）顺序读 **28.4GB/s**——比两年前 Gen5 旗舰快一倍，40GB LLM 权重加载约 1.4 秒。
- 消费级 M.2 走 ×4；数据中心 E3.S 走 ×4（也有 ×2/×8 变体）；未来 Gen7 已在规范中。

## 4. NVMe 协议版本演进

| 版本 | 时间 | 关键新增 |
|------|------|---------|
| 1.0 | 2011 | 基础队列模型、PRP |
| 1.2 | 2014 | 断电通知、温控 |
| 1.3 | 2017 | 每命名空间写保护、Sanitize |
| 1.4 | 2019 | **CMB/SMB（控制器内存缓冲）**、KV 命令（TP 4000）、多路径 |
| 2.0 | 2021 | 分区命名空间 ZNS（TP 4053）、持久化事件日志、NVMe-oF 强化 |
| 2.1 | 2024 | **FDP（TP 4146）**、TLS、多控制器、实时遥测 |
| 2.2 | 2026 | 强化 FDP 组合、接口优化（铠侠 GP1 采用） |

**常用命令速查**：`Identify`（设备能力）、`Read/Write`、`Flush`（强制落盘）、`DSM`（Dataset Management = TRIM）、`Sanitize`（安全擦除）、`Get Log Page`（SMART）。

## 5. FDP：灵活数据放置深潜

### 5.1 问题背景

SSD 的 GC 是"盲人摸象"：不知道数据什么时候失效，只能靠读-搬-擦，WAF 高达 1.9-2.7。数据库/文件系统其实知道每个数据流的生命周期（日志 vs 索引 vs 冷数据），但这个信息无法传给 SSD。

### 5.2 机制

```text
主机写入 → 附加 8-bit Placement Identifier（PI，放置标识）
              ↓
SSD 将不同 PI 的数据流路由到独立的 Reclaim Unit Handle（RUH，回收单元句柄）
              ↓
同一生命周期数据物理聚在一起 → GC 整块回收 → WAF → ~1.0
```

- 兼容性：FDP 是 NVMe 2.1 规范特性，老设备/老内核不感知时退化为普通 SSD 行为。
- 实现现状：Linux 内核 6.x 支持；主控厂商（DapuStor、Solidigm、铠侠、闪迪）已落地。

### 5.3 收益数据（2026 实测口径）

| 方案/厂商 | WAF 改善 | 寿命影响 |
|-----------|---------|---------|
| DapuStor（企业 QLC） | 特定负载 WAF → 1.0 | **PBW 寿命提升至 4 倍** |
| Solidigm CSAL | 1.8 → 1.0 | QLC 达标企业级标准，TCO -25% |
| 闪迪 SN861 | 写入放大 -50% | DWPD 灵活配置 |
| VLDB 2026 论文 | 消除设备级写放大 | 吞吐与耐久同步提升 |

### 5.4 FDP vs ZNS

| 维度 | FDP | ZNS |
|------|-----|-----|
| 谁管放置 | 主机给提示，SSD 自主放置 | 主机完全管区（zone）内顺序写 |
| 兼容性 | 渐进式，老软件无感 | 需要文件系统/应用深度改造 |
| 落地进度 | 2024-2026 快速落地（企业盘标配） | 生态慢（ZenFS 等小众） |
| 场景 | 数据库/日志/checkpoint 混合负载 | 全顺序写、超大容量 QLC |

> 💡 结论：2026 年 FDP 是 QLC 进数据中心的关键钥匙——"QLC 寿命不够"的问题，一半靠介质改进，一半靠 FDP 把 WAF 压到 1。

## 6. 形态因子全景

| 形态 | 尺寸 | 接口 | 场景 |
|------|------|------|------|
| M.2 2230/2280/22110 | 22×30/80/110mm | PCIe ×4 / SATA | 消费级、笔记本、边缘 |
| 2.5" U.2/U.3 | 2.5 英寸 | SAS / PCIe ×4 | 通用服务器 |
| E1.S（EDSFF 短） | 矮条 | PCIe ×4 | OCP 高密度，正反双面散热 |
| **E1.L / E3.L** | 长条 | PCIe ×4 | 最大容量（DapuStor R6060 245TB） |
| E3.S 9.5mm | 中条 | PCIe ×4 | **冷板液冷兼容**（铠侠 CM10 主打） |
| 内置卡（HHHL） | PCIe 卡 | PCIe ×8/×16 | 老式高性能，渐被 EDSFF 取代 |

2026 数据中心主流：**E3.S（液冷兼容）+ E1.S（风冷高密）**，U.2 存量仍大；消费级继续 M.2。

## 7. 移动端：UFS 与 eMMC

| 标准 | 顺序读 | 随机性能 | 场景 | 2026 状态 |
|------|--------|---------|------|----------|
| eMMC 5.1 | ~300 MB/s | 差 | 低端机、IoT | 份额萎缩 |
| UFS 3.1 | ~2100 MB/s | 中 | 中端机 | 存量 |
| UFS 4.0 | ~4200 MB/s | 好 | 旗舰 | 主流 |
| **UFS 4.1** | **~5800 MB/s** | **随机读较 4.0 +90%** | 旗舰/AI 手机 | 2026 量产送样 |

**UFS 4.1 关键产品（2026）**：
- 铠侠 QLC UFS 4.1（2026-01 送样）：512GB/1TB，顺序写 +25%、随机读 +90%、随机写 +95%，WAF 改善 3.5 倍，CBA 工艺封装缩至 9×13mm，兼容 4.0/3.1。
- 闪迪 iNAND MC EU721（2026-03）：顺序读 4500MB/s、写 4300MB/s，针对边缘 AI/AR/MR。
- 三星 UFS 4.1：1TB，面向 AI 手机与汽车。

**microSD 误区**：microSD 卡与 UFS 完全不是一类——主流 Class 10 卡连续读仅 10-20MB/s，是 UFS 4.1 的 1/300；microSD 只有 A2/V30 级别可用作轻量扩展存储，无法承担系统级 IO。

## 8. 接口选型速查

| 场景 | 推荐接口/协议 | 原因 |
|------|--------------|------|
| 消费台式机/笔记本 | M.2 + PCIe 4.0/5.0 NVMe | 性价平衡，Gen5 需散热 |
| 数据库服务器热盘 | U.2/E3.S + PCIe 5.0/6.0 | 低延迟、双端口、液冷兼容 |
| 高容量读密集（冷热混合） | E1.L/E3.L QLC + FDP | 容量最大化、寿命靠 FDP 保 |
| GPU 直连/高 IOPS AI | E3.S/E1.S + Gen6 + 低延迟闪存 | 512B 小 IO 也快（见 10 篇） |
| 移动端 | UFS 4.1 | 嵌入式、低功耗、随机快 |
| 老服务器兼容 | SATA/SAS + U.2 | 存量平台，性能上限 ~550MB/s |

> 🎯 **核心要点**：接口层决定性能天花板——NVMe 用"多队列+无锁+低中断"把协议开销降到 SSD 物理极限，PCIe 6.0 把带宽推到 28GB/s 量级；而 FDP 是 2026 年最重要的协议层创新，它把"数据生命周期"这一主机知识注入设备，让 QLC 在企业级落地。选型口诀：**先看接口协议（决定上限），再看介质类型（决定寿命成本），最后看形态（决定能装哪）**。
