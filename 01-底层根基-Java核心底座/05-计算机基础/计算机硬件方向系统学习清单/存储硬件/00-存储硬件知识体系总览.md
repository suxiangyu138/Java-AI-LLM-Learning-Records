## 3. 学习路线推荐

**路线 A：入门速成（半天）**
01 → 02 → 03 的核心小节 + 05 的接口带宽表。目标是建立"存储 = 金字塔各层各司其职"的心智模型，看懂容量/延迟/成本三角，能区分介质、设备、接口、系统四个概念层次。

**路线 B：系统进阶（2-3 天，推荐）**
01 → 03 → 04 → 05 → 07 → 08 全链路。掌握 SSD 为什么"先擦后写"、写放大从哪来、NVMe 为什么吊打 SATA、RAID 与纠删码怎么选、性能指标怎么读。这是后端工程师理解"磁盘慢"的根本原因与优化空间的必经路线。

**路线 C：应用深化（Java 后端 / AI 工程师）**
在路线 B 基础上加 09 与 10：fsync 与数据库落盘、io_uring 与虚拟线程、checkpoint 存储优化、KV cache 卸载、GPU 直连存储。这是面试"你项目里磁盘 IO 怎么优化"的弹药库。

> 💡 与知识库其他模块的关系：与 `05-计算机基础/计算机组成原理/` 下的存储器层次结构与缓存与Cache 互为主从——本目录讲"存储设备与系统"，那边讲"Cache 内核与 CPU 访存"；`02-.../MinIO` 与 `03-AI.../Milvus` 体系覆盖对象存储与向量库落地，本文 07/10 给出其架构位置。

## 4. 核心概念速查

| 概念 | 一句话定义 | 关键数据/要点 |
|------|-----------|--------------|
| 存储金字塔 | 寄存器→Cache→DRAM→SSD→HDD→磁带 的层级 | 每降一级容量约 ×10、延迟约 ×10 |
| 容量-延迟-成本铁三角 | 任何一层都无法同时三项最优 | 快=贵、大=慢，只能分层组合 |
| NAND 单元类型 | 每单元存储的位数 | SLC 1 位 / MLC 2 / TLC 3 / QLC 4 / PLC 5 |
| 3D NAND | 垂直堆叠的闪存层数 | 2026 主流 276-400+ 层；铠侠 BiCS10=332 层 |
| P/E 循环 | 擦写寿命计数 | SLC 约 10 万 / TLC 数千 / QLC 约 1000 |
| 写放大 WAF | 实际写入物理量 ÷ 主机请求量 | 常规 1.9-2.7；FDP 优化后接近 1.0 |
| TRIM | 通知 SSD 块内数据已删除 | 消除"已删除数据仍被 GC 搬移"的浪费 |
| OP 预留空间 | 出厂预留的不可见空间 | 7%-28%；越高 WAF 越低、寿命越长 |
| NVMe 队列模型 | 主机与 SSD 的并发通道 | 64K 队列 × 64K 深度 vs AHCI 1 队列 ×32 |
| PCIe 带宽 | 接口物理吞吐 | Gen5 ×4 ≈ 14 GB/s；Gen6 ×4 ≈ 30 GB/s |
| FDP | 灵活数据放置（NVMe TP 4146） | 按生命周期分流写入，WAF 压向 1，QLC 寿命 ×2-4 |
| RAID | 多盘冗余阵列 | RAID5 单盘容错 / RAID6 双盘 / RAID10 镜像条带 |
| 纠删码 | 数据切分 + 冗余校验块 | RS(4,2) 用 1.5 倍空间换 2 块容错 |
| fsync | 强制刷盘系统调用 | 数据库 WAL 落盘可靠性的关键 |
| CXL.mem | 内存池化/扩展协议 | Meta 2026 实测服务器数量 -25% |
| HAMR | 热辅助磁记录 | 希捷 2026 量产 44TB（Mozaic 4+） |
| Checkpoint | 训练中定期保存模型状态 | 400B 参数模型单次可达数 TB |

> 🎯 **核心要点**：存储硬件的全部设计——介质（NAND/磁介质）、设备（SSD/HDD）、接口（NVMe/PCIe）、系统（RAID/分布式）——都由一个物理事实驱动：**写入是昂贵的**。闪存要先擦后写、HDD 要机械寻道、RAID 要写多份；所有优化（FTL、TRIM、FDP、日志结构、checkpoint 缓冲）本质上都是"减少物理写入、或让写入更有序"。
