## 1. SSD 解剖：三大件

```text
主机接口（PCIe/SATA） → 控制器（Controller） → NAND 通道 ×N → 闪存 Die
                          │
                      DRAM 缓存（FTL 表 + 数据缓冲）
                          │
                      电源管理 + 掉电保护（钽电容）
```

| 部件 | 职责 | 关键参数（2026 企业级） |
|------|------|------------------------|
| 控制器（主控） | CPU 核 + DMA + 通道控制器 + **ECC 引擎（LDPC 硬件加速）** + 加密引擎 | 4-8 核 RISC 核心，28nm-12nm 制程 |
| NAND 通道 | 控制器与闪存 Die 的总线 | 8-16 通道，通道内多 Die 交错 |
| DRAM 缓存 | 存 FTL 映射表 + 写缓冲 | 企业盘按容量 1GB/1TB 级 |
| 无 DRAM 方案 | 借用主机内存（HMB）或纯 FTL 压缩 | 消费级 M.2 常见，性能打折 |
| 电源 | 掉电保护电容（钽/超级电容） | 企业盘标配，消费盘无 |

## 2. FTL：逻辑到物理的映射层

### 2.1 为什么需要 FTL

- 应用看到的是连续的 LBA 逻辑地址，但闪存"先擦后写"导致物理位置不断漂移：
  - 覆盖写 → 不擦旧页，而是写到新的已擦除页 → 旧页标记失效。
  - GC/磨损均衡 → 有效数据被搬移到别处。
- FTL 维护 `逻辑页号 → 物理页号` 映射表，让主机看到"完美的可覆盖写设备"。

### 2.2 映射粒度与代价

| 映射粒度 | 映射表大小（1TB 盘） | 写放大 | 说明 |
|---------|:---:|:---:|------|
| 页级（4KB） | ~1GB DRAM | 低 | 企业盘标准，表大、需掉电保护 |
| 块级（4MB） | ~1MB | 高（部分页更新也要搬整块） | 老方案，已被淘汰 |

- 映射表本身必须持久化：断电时表丢失 = 全盘数据不可读 → 定期把表落 NAND + 掉电时将内存表紧急刷入（见 7）。

### 2.3 FTL 的隐藏工作

- 前台处理主机 IO；后台执行：GC、磨损均衡、读干扰巡检、数据保持刷新、坏块替换。
- 后台活动与前台 IO 争抢带宽 → 这就是 SSD 延迟毛刺与"脏盘变慢"的原因（QoS 好的企业盘用带宽隔离）。

## 3. 磨损均衡（Wear Leveling）

- **问题**：热点数据（日志、索引）反复擦写同一物理块 → 局部磨损耗尽，而冷数据块（静态文件）几乎不擦写 → 全盘寿命被最差块绑架。
- **动态均衡**：新写入优先选择磨损最少的块（写入侧均衡）。
- **静态均衡**：后台把冷数据搬走、让出磨损少的新块（静止侧均衡）——代价是额外搬移流量。
- **目标**：全盘擦写次数趋同（磨损差 <20%）。均衡越好，WAF 略高、寿命上限越高，两者需要权衡。

## 4. 垃圾回收 GC 与写放大 WAF

### 4.1 GC 流程

```text
1. 选择 victim 块（失效页多的块优先，代价函数加权）
2. 把该块内仍有效的页搬移到已擦除的新块
3. 整块擦除，块回到空闲池
4. 前台无空闲块可写时 → 前台 GC（卡顿根源）
```

### 4.2 写放大（WAF）

```text
WAF = 实际写入 NAND 的数据量 ÷ 主机请求写入的数据量
```

**WAF 的三个来源**：

| 来源 | 说明 | 典型倍数 |
|------|------|---------|
| GC 搬移 | 回收块时搬走有效页 | 1.5-2.5（满盘时飙升） |
| 页内部分写 | 主机 4KB 写、页 16KB → 读改写 | 1.1-1.5 |
| 元数据与映射表更新 | FTL/掉电保护日志本身要写 | 0.1-0.3 |

- 现实企业负载 WAF ≈ **1.9-2.7**（DapuStor 实测口径）；空闲时后台 GC 可把盘"洗干净"，但高负载下前台 GC 直接拖慢 IO。
- **满盘状态**：空闲块越少 → GC 越频繁 → WAF 上升 → 性能跌落到标称的 30-60%（消费盘 QLC 更明显）。

### 4.3 降低 WAF 的手段

| 手段 | 原理 | 效果 |
|------|------|------|
| 加大 OP 预留空间 | 出厂/用户预留不可见空间，空闲块池变大 | 7%→28% 可降 WAF 30-50% |
| TRIM | 及时回收"已删除"空间（见 5） | 避免死数据被 GC 反复搬移 |
| FDP 数据流隔离 | 同类生命周期数据放同区，GC 整区回收（见 05 篇） | WAF → 1.0-1.2 |
| 顺序写友好调度 | 固件合并顺序 IO | 日志类负载 WAF 显著下降 |

## 5. TRIM：让 SSD 知道数据已删除

- **问题**：文件系统删除文件 = 只改元数据，数据页仍"有效"（SSD 视角）→ 直到 GC 才发现是死数据 → 白搬移一次。
- **TRIM 机制**：OS 删除时发 TRIM/Dataset Management 命令，SSD 立即把对应页标记失效 → 进 GC 候选。
- **实现**：SATA 的 TRIM（queued trim）；NVMe 的 `Dataset Management (DSM)` 命令（`fstrim` 手动、`discard=async` 自动、`-o discard` 挂载选项）。
- **Windows/macOS**：系统级自动 TRIM 已内置多年；Linux 需要显式 `fstrim.timer`（systemd 每周跑一次）或挂载时 `discard`。

> ⚠️ 陷阱：虚拟机镜像、容器 overlayfs 里做删除，TRIM 不一定透传到物理盘 → 虚拟磁盘会慢慢膨胀变慢。云厂商 2026 年普遍把 discard 透传作为默认配置解决此问题。

## 6. SLC 缓存与混合模式

| 模式 | 原理 | 优点 | 代价 |
|------|------|------|------|
| 动态 SLC 缓存 | 把 QLC/TLC 区域按 SLC 方式写（1 位/单元） | 爆发写入性能接近 SLC | 缓存耗尽后掉速明显；需后台回写 |
| pSLC 固定分区 | 出厂划分固定 SLC 区 | 性能稳定可预期 | 容量打折 |
| 全盘直写 | 无缓存，QLC 原速 | 企业读密集盘常见 | 写入速度慢 |

- 消费级盘标称顺序写高数字多是"缓存内"成绩——缓存写满后跌到介质原速（QLC 可能只有标称 1/5）。
- 企业盘一般不玩消费级 SLC 缓存（一致性优先），靠 FDP + 大 OP + 固件调度保证稳态性能。
- **评测方法**：fio 先写满盘再测稳态（见 08 篇），才能暴露真实性能。

## 7. 企业级可靠性设计

| 设计 | 作用 |
|------|------|
| 掉电保护（PLP） | 钽电容供电 → 断电时将 DRAM 中的 FTL 表/写缓冲紧急刷入 NAND，防映射表损坏 |
| 读干扰巡检 | 后台定期重读热块，必要时搬运数据 |
| 数据保持刷新 | 老化数据定期重写，对抗电荷泄漏 |
| 双端口（Dual Port） | 双控制器链路，单控制器故障不掉线（SAS/U.2 双端口） |
| 热插拔与 FRU | 数据中心免停机更换 |
| NVMe-MI 遥测 | 带外监控温度、寿命、固件升级 |
| 固件双镜像 | 固件损坏自动回滚 |

消费级 vs 企业级本质差异：**企业级保证的是稳态性能与 QoS 下限，消费级只保证峰值**。

## 8. 2026 新方向：FDP 与计算型存储

- **FDP（灵活数据放置）**：主机给每次写入打"生命周期标签"，SSD 将不同寿命数据物理隔离 → GC 整区回收 → WAF 逼近 1。这本质是把"放置决策"从设备内部升级为主机-设备协作（详见 05 篇专章）。
- **计算型存储（SmartSSD）**：把数据密集型算子（过滤、压缩、checkpoint 优化器更新）下沉到 SSD 内执行，减少主机到设备的搬移。SK 海力士 2026 发布方案：用 SmartSSD 卸载 LLM 训练优化器状态更新，缓解 HBM 压力（详见 10 篇）。
- **ZNS（分区命名空间）**：主机直接管理块放置（顺序写区内、区级重置），QLC 友好，但生态推进慢于 FDP。

> 🎯 **核心要点**：SSD 是一个"带缓存的小型数据库系统"——FTL 管映射（索引）、GC 管空间回收（垃圾收集）、磨损均衡管寿命（负载均衡）、掉电保护管持久性（WAL）。而所有这些后台机制都会与前台 IO 争抢资源，所以 **SSD 的真实性能必须看稳态**（缓存写满、后台活动满负荷时），这既是选型标准，也是评测标准（08 篇展开）。
