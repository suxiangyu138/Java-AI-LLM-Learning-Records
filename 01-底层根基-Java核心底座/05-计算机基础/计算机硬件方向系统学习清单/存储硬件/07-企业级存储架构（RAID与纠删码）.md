## 1. 四种访问形态：DAS/SAN/NAS/对象存储

| 形态 | 访问粒度 | 协议 | 特点 | 典型场景 |
|------|---------|------|------|---------|
| DAS | 块（直连） | SATA/SAS/PCIe | 简单、性能好、不共享 | 单机数据库、缓存 |
| SAN | 块（网络） | FC / iSCSI / NVMe-oF | 低延迟共享块存储 | 数据库集群、虚拟化 |
| NAS | 文件（网络） | NFS / SMB | POSIX 语义、易管理 | 共享文件、CI 制品 |
| 对象存储 | 对象（HTTP） | S3 API | 无限扩展、扁平命名、最终一致 | 数据湖、备份、AI 数据集 |

**选型第一问**：应用要"块"（数据库裸设备）还是"文件"（共享目录）还是"对象"（云原生数据）？

> 💡 本仓库的 MinIO 体系专门深讲对象存储（S3 模型、桶/对象、生命周期、Java 集成），本文给出它在整体架构中的位置与对比。

## 2. RAID 全解

### 2.1 级别对比

| 级别 | 原理 | 空间效率 | 容错 | 随机写惩罚 | 典型用途 |
|:---:|------|:---:|:---:|:---:|------|
| RAID0 | 条带（Stripe） | 100% | 0 | 1 | 缓存/临时盘，无冗余 |
| RAID1 | 镜像 | 50% | 1 盘 | 2 | 系统盘、小容量关键数据 |
| RAID5 | 条带+分布式奇偶 | (n-1)/n | 1 盘 | **4** | 通用（3-8 盘） |
| RAID6 | 双奇偶 | (n-2)/n | 2 盘 | **6** | 大容量关键数据 |
| RAID10 | 镜像+条带 | 50% | 每组 1 盘 | 2 | 数据库（性能优先） |

### 2.2 写惩罚（Write Penalty）——选型核心

- RAID5 写 4KB → 实际 4 次 IO（读旧数据、读旧奇偶、写数据、写奇偶）= 惩罚 4。
- RAID6 双奇偶 = 惩罚 6；RAID1/10 只需写两份 = 惩罚 2。
- **惩罚只影响随机写**：顺序写可批量合并，惩罚摊薄。

### 2.3 RAID5 的大容量陷阱

```text
8TB × 6 盘 RAID5（1 盘冗余）
重建：读 5 盘 × 8TB = 40TB，以 200MB/s 算 → 55+ 小时
重建期间 URE：每读 10^14 位可能 1 次错误
40TB = 4×10^14 位 → 重建中大概率遇到 URE → 重建失败
```

- **结论**：>8TB 级大盘 RAID5 重建成功率低，2026 年行业标准是 **RAID6 或 RAID10**（或转纠删码）。
- 硬件 RAID 卡 vs 软 RAID（mdadm/LVM/ZFS）：2026 年软 RAID（ZFS/ZRAID、mdadm）因 CPU 足够快 + 灵活性高，在主流服务器占比已超硬件卡。

## 3. 纠删码与副本

### 3.1 Reed-Solomon 原理

```text
原始数据：D1 D2 D3 D4          （数据块 k=4）
校验生成：P1 P2                （校验块 m=2，线性代数运算）
任意丢失 ≤ m 块 → 可恢复      （RS(4,2)，空间效率 2/3 ≈ 66.7%）
```

- 对比 RAID：纠删码是"分布式 RAID"——跨节点放置，任意节点故障可恢复。
- 常见配置：RS(4,2)（1.5 倍空间）、RS(6,3)（1.5 倍）、RS(10,4)（1.4 倍）——空间效率越高，恢复计算量越大。

### 3.2 副本 vs 纠删码

| 维度 | 三副本 | 纠删码 RS(4,2) |
|------|:---:|:---:|
| 空间效率 | 33%（3 倍空间） | 66.7% |
| 容错 | 任意 2 副本故障 | 任意 2 块故障 |
| 写放大 | 3 倍（写 3 份） | 1.5 倍（含校验） |
| 恢复成本 | 读 1 副本即可 | 需读 k 块 + 矩阵运算 |
| 一致性复杂度 | 相对低 | 高（部分失败处理） |
| 适用 | 小对象、热数据 | 大对象、冷数据 |

- 主流实践：**热数据用副本（读快），冷数据用纠删码（省空间）**——对象存储通常两套并存（MinIO 的纠删码、Ceph 的 EC 池 + 副本池）。

## 4. 分层存储与生命周期

```text
热层（NVMe SSD，7×24 随机 IO）─────┐
温层（HDD 近线，大容量顺序 IO）─────┼── 自动迁移策略（Tiering）
冷层（磁带/归档，极少访问）─────────┘
```

| 分层 | 介质 | 每 TB 成本 | 典型保留策略 |
|------|------|-----------|-------------|
| 热 | NVMe（TLC/QLC） | $50-150 | 秒-天 |
| 温 | HDD（ePMR/HAMR 40TB+） | $10-20 | 天-年 |
| 冷 | 磁带 LTO / 光碟 | <$5 | 年-数十年（含 WORM 合规归档） |

**2026 实践**：AI 数据湖普遍采用"对象存储 + 生命周期规则"自动分层（AWS S3 Glacier / MinIO 生命周期 / Backblaze HDD 层为 CoreWeave 提供冷层）。

## 5. 企业级 SSD 特性

| 特性 | 消费级 | 企业级 |
|------|:---:|:---:|
| 断电保护（PLP） | 无 | 有（钽电容，DRAM 数据落盘） |
| 双端口 | 无 | SAS/U.2 支持 |
| 耐久标注 | 保修 TBW | **DWPD（0.6-50）** 明确分级 |
| 稳态性能 | 峰值参考 | **QoS 保证（P99 延迟上限）** |
| 遥测 | SMART 基础 | NVMe-MI 带外管理、温度/寿命预测 |
| 固件 | 更新少 | 定期安全补丁、双镜像 |

**DWPD 分级速查**：0.6（读密集，QLC 大容量）→ 1（通用）→ 3（混合）→ 10-25（写密集，TLC）→ 50+（超高 IOPS，AI 缓存，如铠侠 GP1）。

## 6. NVMe-oF 与共享存储

| 传输 | 协议 | 延迟 | 适用 |
|------|------|:---:|------|
| NVMe/TCP | TCP 网络传输 NVMe | ~100μs+ | 通用以太网（云原生标准） |
| NVMe/RDMA（RoCE/iWARP） | RDMA 直连 | ~10μs | 高性能块存储 |
| FC（Fibre Channel） | 专用光网络 | ~10μs | 传统 SAN 存量 |
| iSCSI | TCP | ~100μs+ | 老牌 IP-SAN |

- **NVMe-oF 的意义**：把 NVMe 队列模型网络化 → 分布式块存储延迟从"网络级"降到"接近本地"。
- 软件栈：Lustre（HPC 并行文件系统）、Ceph（分布式块/文件/对象三合一）、JuiceFS（对象存储之上的 POSIX 层）、GPFS（IBM 高性能）。
- **JBOF（Just a Bunch of Flash）**：NVMe SSD 直连交换机组成闪存机箱，作为 NVMe-oF 共享块池——2026 数据中心的主流形态之一。

## 7. 2026 架构趋势

| 趋势 | 内容 |
|------|------|
| 全闪存数据中心 | 热路径 100% NVMe；HDD 只留冷层（对象/备份） |
| QLC 大容量普及 | 245TB（DapuStor R6060）/ 256TB（闪迪 SN670）级 QLC 进冷热交界层 |
| 存储即内存 | CXL 让 SSD 以内存语义访问，checkpoint/推理缓存提速 |
| 计算型存储 | 压缩/过滤/checkpoint 算子下沉 SSD（SK 海力士 SmartSSD） |
| 数据保护升级 | 大规模用纠删码替代 RAID5；RAID6 只留中小场景 |

> 🎯 **核心要点**：企业存储架构的演进主线是"**从单盘冗余走向系统冗余**"——RAID 保护单机（块级、写惩罚 4-6）、纠删码保护集群（跨节点、写放大 1.5）、副本换读取性能（写放大 3）；介质分层把成本效率拉满（热 SSD/温 HDD/冷磁带）。2026 年的新变量是 CXL 与 NVMe-oF：**连接方式（协议）的进步，比介质进步更快地改变着架构形态**。
