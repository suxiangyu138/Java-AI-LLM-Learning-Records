## 1. 三个核心指标

| 指标 | 定义 | 单位 | 关注场景 |
|------|------|------|---------|
| IOPS | 每秒完成的 IO 操作数 | 次/秒 | 随机小 IO（数据库事务、KV） |
| 延迟 | 单次 IO 完成时间 | μs / ms | 在线业务（P99 敏感） |
| 吞吐 | 每秒传输数据量 | MB/s / GB/s | 大块 IO（备份、checkpoint、日志） |

**三者关系**：`吞吐 = IOPS × 单次 IO 大小`。4K 随机读 100K IOPS ≈ 400MB/s；128K 顺序写 2GB/s ≈ 16K IOPS。**指标必须成对看**，单独报 IOPS 或吞吐都会误导。

> ⚠️ 常见误区：厂商标称"顺序读 14GB/s"和"随机读 1000K IOPS"分别来自不同测试条件——顺序看吞吐、随机看 IOPS，用错场景等于选错盘。

## 2. 随机 vs 顺序：四象限

| 象限 | 代表负载 | HDD（7200rpm） | NVMe SSD（TLC） | 差距 |
|------|---------|:---:|:---:|:---:|
| 4K 随机读 | 数据库事务、KV 查询 | ~200 IOPS | 300K-1000K IOPS | **~1000-5000 倍** |
| 4K 随机写 | 事务日志、索引更新 | ~200 IOPS | 100K-400K IOPS | 1000 倍+ |
| 128K 顺序读 | 数据加载、备份恢复 | ~250 MB/s | 7-28 GB/s | 30-100 倍 |
| 128K 顺序写 | checkpoint、日志归档 | ~300 MB/s | 4-21 GB/s | 15-70 倍 |

**规律**：
- 随机 IO 的差距（数量级）远大于顺序 IO → **随机场景 SSD 是唯一选择**。
- HDD 随机/顺序差距 ~3 个数量级；SSD 只有 ~3-10 倍 → SSD 让"随机访问"不再可怕。
- 顺序写注意 SLC 缓存与稳态（见 04 篇）：QLC 盘缓存外顺序写可能掉到 500MB/s-1GB/s。

## 3. 队列深度与并发

| 队列深度 | 含义 | 行为 |
|:---:|------|------|
| QD1 | 单线程单请求 | 反映**纯延迟**；NVMe 下 4K 读 ~20-80μs |
| QD16-64 | 常规服务器负载 | 吞吐随 QD 近似线性上升 |
| QD256+ | 压测/饱和 | 吞吐封顶，延迟开始抬升 |

- **延迟-吞吐权衡**：加大 QD 提吞吐，但单请求延迟上升 → 在线业务要"低 QD 低延迟"，批处理要"高 QD 高吞吐"。
- 饱和点：SSD 内部通道数（8-16）× 每通道 Die 并发决定；超过饱和点后延迟暴涨（排队）。
- 评测统一：企业评测固定 QD（如 4/16/64/256）画"延迟-吞吐曲线"，比单点数字更全面。

---

## 4. 延迟分布与分位

- **平均值骗人**：SSD 平均 50μs，但 GC 触发时单次延迟可能 5ms——对在线业务，均值没意义，**P99/P999 才是用户体验**。
- 长尾来源：后台 GC、磨损均衡搬移、SLC 缓存回写、固件队列调度（见 04 篇）。
- 企业级 QoS 承诺：P99 延迟上限（如 4K 随机读 P99 ≤ 200μs）——消费盘无此保证。
- **评测规范**：SNIA SSS PTS 要求"稳态 + 分位延迟报告"，读延迟、写延迟、混合延迟分开列。

## 5. fio 基准方法

### 5.1 常用参数

| 参数 | 含义 | 示例 |
|------|------|------|
| `rw` | 读写模式 | randread / randwrite / read / write / rw |
| `bs` | 块大小 | 4k / 128k |
| `iodepth` | 队列深度 | 1 / 32 |
| `numjobs` | 并发进程数 | 4 |
| `direct=1` | 绕过页缓存（必须） | O_DIRECT |
| `ioengine` | IO 引擎 | libaio / io_uring |
| `runtime` | 测试时长 | 60s+ |
| `size` | 测试文件大小 | 100G |

### 5.2 四象限模板

```bash
# 4K 随机读（QD32，经典基线）
fio --name=randread --rw=randread --bs=4k --iodepth=32 --numjobs=4 \
    --ioengine=libaio --direct=1 --size=100G --runtime=60 --filename=/dev/nvme0n1

# 128K 顺序写（吞吐测试）
fio --name=seqwrite --rw=write --bs=128k --iodepth=16 --numjobs=8 \
    --ioengine=libaio --direct=1 --size=100G --runtime=60 --filename=/dev/nvme0n1

# 混合负载 70/30（数据库模拟）
fio --name=mix --rw=rw --rwmixread=70 --bs=4k --iodepth=64 --numjobs=4 \
    --ioengine=io_uring --direct=1 --runtime=120 --filename=/tmp/mixfile
```

### 5.3 测试纪律（防骗分）

1. **直接测块设备或 direct=1**：绕过页缓存，否则测的是内存。
2. **先写满、测稳态**：SLC 缓存和空闲块耗尽后才是真实性能；企业评测跑 1-3 轮稳态。
3. **固定环境**：同一内核/固件/温度，散热决定降频与否。
4. **看分位**：不只报平均 IOPS，看 lat 的 p99/p999。
5. **对照 SSD 寿命状态**：写放大/寿命耗尽会影响性能，测前看 SMART。

## 6. 耐久度量：TBW 与 DWPD

### 6.1 换算公式

```text
TBW = 容量(TB) × DWPD × 质保年数 × 365
例：3.84TB × 3 DWPD × 5 年 = 21,024 TBW

日均写入量估算（运维视角）：
寿命年限 ≈ 盘 TBW ÷ (日均写入 TB × 365)
例：1800TBW 盘，日均写 0.5TB → 1800/(0.5×365) ≈ 9.9 年
```

### 6.2 选型对照

| 负载 | 日均写入 | 推荐 DWPD | 介质 |
|------|---------|:---:|------|
| 系统盘/只读缓存 | 少量 | 0.3-1 | QLC/TLC |
| 通用数据库 | 中量 | 1-3 | TLC |
| WAL/日志密集 | 高 | 3-10 | TLC/SLC 缓存盘 |
| AI checkpoint 暂存 | 极高 | 10-50 | 高耐久 TLC（如铠侠 GP1 50 DWPD） |

> ⚠️ 生命周期管理：SSD 寿命不是"到点报废"，而是**坏块率持续上升直到 ECC 兜不住**。SMART 的媒体磨损指示（percentage used）到 100% 前就该规划换盘。

## 7. 负载画像：场景 → 指标

| 场景 | IO 模式 | 关键指标 | 推荐盘型 |
|------|---------|---------|---------|
| MySQL/PostgreSQL 事务 | 4-16K 随机读写 + WAL 顺序写 | 随机 IOPS、fsync 延迟 | TLC 企业盘，DWPD 1-3 |
| Redis AOF / 消息队列 | 顺序追加写 | 顺序写吞吐、fsync | 中端 NVMe |
| 日志/监控采集 | 顺序写 + 小随机读 | 顺序写吞吐、寿命 | QLC 大容量 |
| 数据仓库/分析 | 大块顺序读 | 顺序读吞吐 | QLC/TLC 高容量 |
| AI checkpoint | 大块顺序写（突发洪峰） | 写入带宽、P99 延迟 | 高耐久 + 高带宽（Gen5/6） |
| 冷数据备份 | 顺序写读 | 每 TB 成本 | HDD 40TB+ |
| 向量数据库 | 4K 随机读密集 | 随机读 IOPS、P99 | 高 IOPS 企业盘 |

**方法论**：先画像（读写比、块大小、QD、分位要求、日写入量）→ 再定指标 → 再选盘 → 最后用 fio 复现负载验证。**"买最贵的盘"是最偷懒也最贵的选择**。

> 🎯 **核心要点**：存储性能评测的四个关键动作——① 指标成对看（IOPS/延迟/吞吐相关不可分）；② 随机与顺序分开测（差距可达 4 个数量级）；③ 只信稳态与分位（SLC 缓存和 GC 会骗人）；④ 按负载画像定指标（数据库看随机延迟、checkpoint 看顺序带宽）。能回答"我的负载是什么画像、盘能不能稳态撑住"，就已经超过大多数只抄跑分单的人。
