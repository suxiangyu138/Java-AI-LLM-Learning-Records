## 1. 结构与工作原理

### 1.1 物理组成

| 部件 | 作用 | 关键参数 |
|------|------|---------|
| 盘片（Platter） | 磁性介质载体 | 3.5" 企业级 7-10 碟，单碟密度 2.2-4.4TB |
| 主轴电机 | 驱动盘片旋转 | 5400/7200 rpm，企业级 7200 为主 |
| 磁头臂（Actuator） | 摆动定位磁头 | 音圈马达（VCM）驱动 |
| 磁头（Head） | 写入=线圈磁化、读取=磁阻传感器 | 每面 1 头，读写一体 |
| 缓存 | 固件与 IO 缓冲 | 256MB-512MB（DRAM） |

### 1.2 数据组织

```text
盘片同心圆 → 磁道（Track）
磁道分弧段 → 扇区（Sector，物理 4096 字节，4Kn/512e）
所有盘面同半径磁道 → 柱面（Cylinder）
寻址：CHS（柱面/磁头/扇区）→ 现代统一为 LBA（逻辑块地址）
```

- 数据按 LBA 顺序写入 = 从外圈磁道开始 → 外圈线速度高，吞吐大于内圈（ZBR 恒定角速度分区记录）。
- 扇区大小：老盘 512B，现代盘物理 4KB（4Kn 原生 / 512e 模拟兼容）。
- 磁盘固件做逻辑到物理映射：坏道重映射、SMR 的隐式管理都在盘内完成。

## 2. 延迟模型：为什么 HDD 随机 IOPS 只有 ~200

单次随机读延迟 ≈ 寻道时间 + 旋转延迟 + 传输时间：

| 分量 | 说明 | 7200rpm 典型值 |
|------|------|---------------|
| 寻道时间 | 磁头移动到目标磁道 | 平均 8-10 ms |
| 旋转延迟 | 目标扇区转到磁头下 | 平均半圈 = 60/7200/2 ≈ 4.16 ms |
| 传输 | 数据从盘面读出 | 4KB 仅 ~0.01 ms |
| **合计** | — | **~12-15 ms** |

> 💡 推理链：单 IO 15ms → 每秒最多 ~66 次 → 实测随机 IOPS 约 150-200（盘内队列+缓存优化后）。而顺序读不需要寻道和等旋转，单碟 4.4TB 的盘持续吞吐可达 ~300 MB/s。**随机与顺序相差 3-4 个数量级，这就是 HDD 与 SSD 应用场景分野的根源。**

SSD 对照：无机械部件，随机与顺序延迟差距仅 3-10 倍（见 04/05 篇），随机 IOPS 是 HDD 的 1000 倍以上。

## 3. 记录技术演进：CMR → SMR → ePMR → HAMR

### 3.1 四种技术一览

| 技术 | 全称 | 原理 | 写入代价 | 2026 状态 |
|------|------|------|---------|----------|
| CMR/PMR | 传统垂直磁记录 | 磁道互不重叠 | 无（随机写友好） | 主流基线 |
| SMR | 叠瓦式磁记录 | 磁道像瓦片重叠，密度 +20-25% | 随机写需重写邻道，10-100 倍放大 | WD 40TB 主打 |
| ePMR | 能量增强垂直记录 | 写入磁头加辅助能量场 | 无 | WD 40TB 在用 |
| HAMR | 热辅助磁记录 | 激光局部加热使介质易磁化 | 需激光器，成本高 | 希捷 44TB 量产 |

### 3.2 SMR 详解：密度换随机写

- 磁道重叠后，更新一条内道数据会破坏相邻外道 → 需先读回外道整块、合并、重写（Write-In-Place 禁止）。
- 应对：盘内固件把数据组织成"可顺序追加的区域"（类似 SSD 的 GC），随机写小文件代价巨大。
- 结论：**SMR 只适合顺序写为主的工作负载**（备份、日志归档、近线数据）。数据库/虚拟机随机写场景禁用。

### 3.3 HAMR 详解：密度竞赛的钥匙

- 原理：磁记录介质要缩小颗粒才能提密度，但颗粒小到一定程度热稳定性下降（超顺磁极限）；HAMR 用激光把记录点瞬时加热到居里点附近，让高稳定介质在小尺寸下仍能可靠写入。
- 希捷 Mozaic 平台：Mozaic 3+（30TB+）→ Mozaic 4+（44TB，第二代，单碟 4.4TB）→ Mozaic 5+（50TB，单碟 5TB+，2027 认证）。
- 挑战：激光器可靠性、介质污染控制、良率；希捷 2026 年已实现大规模量产并获超大规模云厂认证，成为行业唯一大规模部署的 HAMR 平台。

## 4. 2026 高容量硬盘现状

### 4.1 厂商与产品格局

| 厂商 | 技术路线 | 2026 产品 | 路线图 |
|------|---------|----------|--------|
| 希捷 | HAMR 单碟密度优先 | Mozaic 4+ 44TB（10 碟、单碟 4.4TB），2026-03 获两家超大规模认证量产；HAMR 占其近线 EB 出货 40%，年底目标 50% | Mozaic 5+ 50TB：2027 认证/2028 出货；2033 年前后 100TB |
| 西部数据 | ePMR 增碟片 + HAMR 双线 | 40TB UltraSMR（ePMR+SMR）2026Q2 出货、下半年量产 | ePMR：2028 年 60TB；HAMR：44TB 2027H1 → 60TB 2028 → 100TB 2029 |
| 东芝 | 跟随 | 30TB 级为主 | 路线保守 |

### 4.2 两条技术路线之争

- **希捷**：赌单碟面密度（HAMR），碟数不变，密度涨 → 4.4TB/碟。
- **西数**：赌碟片数量（10→11→14 碟） + ePMR 渐进 + 双磁头臂（2028） → 44TB 用 11 碟、单碟 4TB。
- 共同点：**容量增长目标都是 2027-2029 年 50-100TB**，且产能已被云厂商预订至 2028 年——AI 数据湖冷层需求把 HDD 生命周期又延长了十年。

### 4.3 典型规格（希捷 Exos M 40TB 级）

| 项目 | 参数 |
|------|------|
| 接口 | SATA 6Gbps / SAS 12Gbps |
| 转速 | 7200 rpm（CMR 模式） |
| 持续传输率 | ~300 MB/s |
| 缓存 | 512MB |
| 平均无故障 | 250 万小时 MTBF（企业级） |
| 年故障率 | ~0.35%-0.7%（企业级目标） |

## 5. 可靠性指标与统计

| 指标 | 含义 | 说明 |
|------|------|------|
| MTBF | 平均无故障时间 | 统计概念，不等于单盘寿命，250 万小时 ≈ 285 年（数学期望） |
| AFR | 年故障率 | MTBF 换算：AFR ≈ 8760/MTBF(小时)；Backblaze 实测消费/企业盘年故障率 0.5%-2.5% |
| URE | 不可恢复读错误 | 每读 10^14-10^15 位可能遇到一次；大容量盘影响 RAID 重建（见 07 篇） |
| SMART | 自监控属性 | 重映射扇区数（05）、待定扇区（C5）、UDMA CRC 错误（C7）为关键项 |
| 坏道重映射 | 缺陷扇区透明替换 | 备用区用尽前用户无感知，但性能可能劣化 |

**实践要点**：
- 单盘故障不可预防 → 冗余（RAID/副本）是唯一答案。
- 高容量盘（16TB+）重建时间长（小时级），重建期间再坏一盘 = 数据丢失 → 用 RAID6/RAID10 或纠删码（见 07 篇）。
- 购买渠道看重置计数（POH、通电时长），矿盘/翻新盘风险极高。

## 6. 适用场景与 SSD 的边界

| 场景 | 推荐介质 | 原因 |
|------|---------|------|
| 操作系统/热数据库 | NVMe SSD | 随机 IOPS 高 3 个数量级 |
| 大文件顺序写（备份、视频归档） | HDD（CMR 或 SMR） | 顺序吞吐够用、每 TB 成本最低 |
| 近线/冷数据湖 | HDD 大容量（40-44TB） | 每 TB 成本 ~SSD 的 1/10 |
| 对象存储底座 | HDD 池 + SSD 缓存层 | 分层组合（如 Backblaze 为 CoreWeave 提供 HDD 层） |
| 归档（几十年） | LTO 磁带 / 光碟 | 功耗与介质寿命最优 |

**HDD 不会消失的原因**：数据中心每 TB 成本依然是决策第一要素——AI 时代数据量爆炸，但 90% 数据是冷数据；SSD 容量增长靠 QLC（245TB 级已出现），但成本仍高于 HDD 一个数量级。**2026 共识：热数据 SSD、冷数据 HDD、极冷数据磁带。**

> 🎯 **核心要点**：HDD 的一切特征都由机械物理决定——随机 IOPS 被寻道+旋转钉死在 ~200，但顺序吞吐和每 TB 成本依然无敌；记录技术的每一次演进（SMR→ePMR→HAMR）都在"密度"上做文章，因为 HDD 与 SSD 的竞争核心是**每 TB 成本**，而不是性能。2026 年 HAMR 让希捷率先量产 44TB，把 HDD 的寿命又延续到 2030 年代。
