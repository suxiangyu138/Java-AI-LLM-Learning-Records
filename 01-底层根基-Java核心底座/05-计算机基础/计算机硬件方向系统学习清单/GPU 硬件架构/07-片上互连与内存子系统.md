# 片上互连与内存子系统
> 算力是"执行"出来的，但吞吐是"搬运"出来的——本模块覆盖芯片内部 NoC/L2 切片的数据路由，以及 2026 年决定多卡规模的关键：NVLink 5.0/6.0、NVLink-C2C 与 NVSwitch。

## 1. 片上互连：NoC 与 L2 切片的对称网格

芯片上 160 个 SM 各自访问全局内存，谁来汇总这些请求？答案是 **L2 切片 + 片上网络（NoC）**：L2 被切成若干片（slice），与 HBM 控制器交错分布在版图四周；SM 发出的访存请求通过 NoC 路由到目标地址对应的 L2 切片。设计约束有三：

- **带宽**：NoC 每周期必须搬运所有 SM 的访存（峰值远超 HBM 带宽），否则 SM 在 L2 就堵车——NoC 线宽是芯片面积的大户
- **延迟均匀性**：任意 SM 到任意地址的距离近似相等，避免"远端 SM 吃亏"——GPC 对称排布的意义所在
- **一致性**：多 SM 并发写同一地址，L2 需要原子操作与一致性协议支持——`atomicAdd` 的硬件成本就在这里
- **公平性**：NoC 的路由必须防止少数 SM 的密集访存饿死其他 SM——仲裁策略与 CPU 内存总线的 QoS 同源

2026 年芯粒化进一步考验片上互连：双晶粒（B300）的 SM 访问对方晶粒的 L2 切片，需要跨晶粒互连（约 10TB/s 片内带宽）——芯粒间延迟比片内高一个量级，编译器与运行时（CUDA 的 P2P 优化、TMA 的跨晶粒搬移）都要感知这个不对称。

## 2. HBM 子系统：控制器、堆栈与带宽预算

每个 HBM 控制器管理一组堆栈：B300 为 8 堆栈 × 12-Hi HBM3e，总位宽 8192 bit（1KB/周期），8TB/s 带宽。控制器要处理三件事：**调度**（合并行激活/预充电，HBM 的 bank 时序对访问模式敏感）、**纠错**（HBM 需要 ECC，企业卡强制开启）、**一致性代理**（多 SM 的原子操作由控制器协同 L2 完成）。

HBM 的功耗同样惊人：8 个堆栈的 IO 驱动功耗占整卡 TDP 的相当比例，降位宽换能效的变体模式成为数据中心卡的常见选项。控制器侧的调度与 CPU 内存控制器同构但更激进：行缓冲命中、bank 交织、伪通道都是带宽工程的手段，而这些参数对程序员不可见——软件能做的只有"访问模式尽量流式、尽量对齐"，其余交给控制器。一致性协议还承担原子操作的执行（L2 内做读-改-写），`atomicAdd` 的吞吐由 L2 原子单元的并行度决定——高竞争原子（如全局计数器）是 2026 年 MoE 路由器的经典瓶颈。

带宽预算的经验法则：8TB/s 的 HBM 要喂 15 PFLOPS FP4，算术强度需 ~1,875 FLOP/byte；实际 GEMM 在良好分块下可达 100-300 FLOP/byte，**所以推理是纯带宽受限**——这也解释了为什么 2026 年的 KV Cache 量化、权重量化全部围绕"省字节"展开（见 `量化背后硬件约束/` 与 `内存墙/`）。

## 3. NVLink：机内 Scale-up 互连

NVLink 是 NVIDIA 的机内 GPU 直连协议，2026 年两代在产：

- **NVLink 5.0（Blackwell）**：每 GPU 18 链路 × 100GB/s = **1.8TB/s 双向**，是 PCIe 5.0 x16 的 ~14 倍；HGX B200/B300 机内 8 卡全连接
- **NVLink 6.0（Rubin）**：每 GPU 3.6TB/s，NVSwitch 单芯片 28.8TB/s，NVL72 机柜聚合 260TB/s

NVLink 的硬件形态是 GPU 上独立的 PHY 与协议栈：每链路 100GB/s（8 个 12.5GHz 差分对 × 双向），支持对等访问（P2P 读写、原子操作）。其价值在 MoE 推理与张量并行中无可替代——专家分片后每 token 的 all-to-all 通信都要走 NVLink，带宽直接决定吞吐（见第 5 节拓扑）。

## 4. NVLink-C2C：CPU-GPU 一致性互连

C2C 是芯片间一致性链路，用在 GB200 的 Grace CPU 与 GPU 之间：**900GB/s 每方向**（Rubin 上翻倍为 1.8TB/s），提供全缓存一致性 + 统一地址空间——GPU 可直接读 CPU 的 LPDDR5X 内存（经 ATS 地址转换），省掉显式拷贝与 PCIe 的软件开销。它不属于 NVSwitch 层，是 die-to-die 直连，延迟低于任何交换路径。

C2C 的架构意义：**内存池化**——Grace 的 1.5TB LPDDR5X 与 GPU 的 HBM 构成统一寻址空间，KV Cache 可以分层放置（热数据 HBM、冷数据 CPU 内存），这是 `内存墙/08-CXL 与内存池化` 的私有化先行版（C2C 一致性带宽是 CXL 的数倍）。

## 5. NVSwitch 与 NVL72：机柜级无阻塞域

单卡互连再快，8 卡以上就需要交换：NVSwitch 芯片把最多 72 颗 GPU（GB200 NVL72：36 超芯粒 × 2 GPU）连成**单一无阻塞 NVLink 域**——任意 GPU 对任意 GPU 以全带宽（1.8TB/s）同时通信，聚合 130TB/s，4KB 传输亚微秒延迟。拓扑是可扩展的两级胖树，最多 576 卡。

Rubin 的 VR200 NVL72 把聚合带宽推到 260TB/s，整个机柜 3.6 EFLOPS FP4 推理——**多卡系统的性能天花板不再是单卡算力，而是互连带宽与机柜功耗（190-230kW）**。理解这一点，才能理解 2026 年为什么"GPU 服务器"的采购决策重心在 NVLink 域规模与液冷。

## 6. 通信层次全景：Scale-up 与 Scale-out 的分工

GPU 系统的通信按距离分四层，每一层的带宽与延迟相差一个量级：

- **片内**（SM↔L2/HBM）：8-10TB/s 级，NoC 路由，延迟百周期
- **卡间**（NVLink）：1.8-3.6TB/s，机内直连或 NVSwitch，延迟微秒级
- **节点间**（网络）：InfiniBand/以太网 400-800Gbps（即 50-100GB/s），延迟数微秒——比 NVLink 低两个数量级
- **跨机房**：数百 Gbps，毫秒级

2026 年的分工原则：**训练与推理的"数据平面"必须走 NVLink**——张量并行、MoE 的 all-to-all 通信每秒 TB 级，网络带宽无法承接；网络只承担"跨机柜的扩展平面"（流水线并行的层间通信、专家并行的跨机通信）与控制平面。这就是 Scale-up（机内聚合，NVLink 域）与 Scale-out（机间扩展，以太网/IB）的分界：NVL72 把 72 卡聚合为"一个逻辑 GPU"，跨机柜才走网络。Blackwell 的 NVLink 域最多可扩到 576 卡（两级胖树），Rubin 的 NVLink Fusion 更进一步把 NVLink 协议开放给超大规模厂商自研硅片——**互连正在取代单卡算力成为系统设计的核心变量**。

PCIe 在这场分层里位置尴尬但不可替代：它负责"控制与长尾"——驱动、CUDA 运行时、NVMe 存储、网卡都挂在 PCIe 上；Gen6 x16 的 256GB/s 对数据搬运不值一提，但 PCIe 作为外设总线标准的生态地位意味着它短期内无法被替代。C2C 则补上 CPU-GPU 一致性互连的空白（900GB/s→Rubin 1.8TB/s），让 Grace 的 CPU 内存成为 GPU 的"扩展内存池"——这是 2026 年 KV Cache 分层放置的硬件前提。

> 🎯 **核心要点**：片上 NoC+L2 切片保证 160 个 SM 的访存均匀汇聚到 HBM；HBM 8TB/s 带宽只够喂 ~5% 的 FP4 峰值算力，推理必然带宽受限；机内靠 NVLink 5.0（1.8TB/s）直连、机柜靠 NVSwitch 组成无阻塞 NVL72 域（130TB/s 聚合），C2C 把 CPU 内存并入统一寻址——2026 年的 GPU 性能 = SM 算力 × 带宽（片内/机内/机柜三层都要喂饱），Scale-up/Scale-out 的分工与互连开放正在重塑系统设计。
