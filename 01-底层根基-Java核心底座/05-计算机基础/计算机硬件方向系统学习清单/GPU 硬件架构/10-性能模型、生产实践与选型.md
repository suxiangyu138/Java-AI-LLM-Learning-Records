# 性能模型、生产实践与选型
> 把架构知识变成决策能力：Roofline 定瓶颈、占用率模型定配置、显存规划定容量、实测基准定选型——外加 2026 年的采购红线与高频面试题。

## 1. Roofline：先算天花板再谈优化

Roofline 模型在 GPU 上的应用：纵轴为算力（FLOP/s），横轴为算术强度（FLOP/byte），斜率即带宽。B300 的 FP4 峰值 15 PFLOPS、HBM 带宽 8TB/s，**ridge point ≈ 1,875 FLOP/byte**——任何算术强度低于此的算子都是带宽受限。

推理算子实测的算术强度：GEMM 分块良好时 100-300，attention 的 softmax/KV 加载段 <10，逐元素算子 ~1——**推理的绝大多数环节坐在 Roofline 的带宽受限区**。因此生产优化顺序有明确答案：先省字节（量化、KV Cache 压缩，见 `量化背后硬件约束/`），再提强度（融合算子、FlashAttention 类重排），最后才谈"让算力跑满"。一张卡的真实利用率的参考区间：训练 GEMM 密集段 50-70%，推理端到端 15-35%——"标称 PFLOPS 除以 5"是估算真实吞吐的粗起点。

实测的锚点建议用 MLPerf Inference 与 vLLM 的官方基准（tok/s、tokens/美元），而非厂商自报的峰值——MLPerf 6.0 中 MI355X 的 Llama 2 70B 成绩（93K tok/s）与 GB200 同场可比的数字，才是选型真正该看的表。

## 2. 占用率与内核配置：三个旋钮

对应 05 篇的机制，生产内核的配置实践三问：

- **块大小**：默认 256 线程/块（8 warp），大块（512-1024）减少调度开销但降低灵活性；目标是让"SM 内 CTA 数 × 块内 warp 数"尽量逼近 64 驻留上限
- **共享内存**：分块尺寸 × 每块驻留块数 ≤ 128KB（B300），双缓冲需要 2× 容量——FlashAttention 把块做成 64×128 而非 128×128，正是共享内存约束下的妥协
- **寄存器**：`__launch_bounds__(线程数, 最小块数)` 强制编译器压低每线程寄存器数换取占用率——低占用率的算子（矩阵大块）与高占用率的算子（带宽敏感）需要分别调

判断工具：CUDA Occupancy Calculator / AMD 的 occupancy 推算公式（VGPR/SGPR/LDS/工作槽四约束取最小），以及 `nsight compute` 的 Warp Stall 分析——**看 stall 原因（访存 vs 依赖 vs 屏障）比看占用率数字更能定位问题**。

## 3. 显存规划：KV Cache 与容量的两本账

2026 年推理显存的三块大账：权重（70B FP16 ≈ 140GB，INT4 量化后 ~40GB）、**KV Cache（长上下文下超过权重，70B@128K 约 150GB）**、激活与临时缓冲。规划公式：`总显存 ≥ 权重 + KV Cache + 预留 20%`。KV Cache 的取舍空间巨大：GQA 减少 4-8×、量化到 INT8/FP8 再省 2×、分层卸载（热数据 HBM、冷数据 CPU 内存，C2C 场景可用）——这正是 `内存墙/` 与 `量化背后硬件约束/` 的实践落点。

## 4. 选型决策：2026 年的五条红线

- **看实际精度而非标称**：FP4 15 PFLOPS 的 B300 在 INT8 工作负载上约 3.5-7 PFLOPS；厂商海报永远用最稀疏、最低精度
- **看带宽与显存**：推理吞吐 ≈ 带宽利用率——8TB/s vs 5.3TB/s 的差距就是真实差距；显存容量决定能否装下模型（B300 288GB vs MI355X 288GB 平手）
- **看互连规模**：多卡训练/大 MoE 推理的瓶颈在 NVLink——NVL72 的 130TB/s 域 vs 8 卡 PCIe 机是数量级差异
- **看生态成本**：CUDA 的软件护城河（vLLM/FlashAttention 首发支持）仍是默认选择；ROCm 在 2026 年已追到可用，国产卡需评估适配层风险
- **看总拥有成本**：MI355X 的 tokens/美元 可高 40%，Rubin NVL72 单价 ~$7.8M 但 token 成本降 10×——**单位 token 成本而非单卡价格**才是决策指标；TCO 还须计入电力（230kW 机柜的电网改造）与散热（液冷基础设施），这两项在 2026 年常占机柜总成本的 20% 以上

## 5. 面试高频题

- **GPU 为什么能比 CPU 算得快**：吞吐优先哲学——晶体管投给执行单元与寄存器，用万线程并发隐藏延迟（01/03/05 篇）
- **占用率是什么、怎么调**：活跃 warp/驻留上限，四约束取最小；低占用率未必差，看瓶颈（05 篇）
- **合并访问为什么快**：32 线程连续地址合并为一次 128B 事务，离散地址退化为多事务（04 篇）
- **Tensor Core 与 CUDA Core 的区别**：专用矩阵阵列 vs 标量单元；MMA 指令、TMEM 累加器（06 篇）
- **为什么推理是带宽受限**：Roofline 算术强度 1-300 vs ridge ~1,875（10 篇，链接 `量化背后硬件约束/`）
- **Blackwell 与 Hopper 的关键差异**：tcgen05/TMEM/NVFP4/双晶粒/NVLink 5.0（08 篇）
- **NVLink 与 PCIe 的区别**：带宽 14×、协议栈直连、C2C 一致性（07 篇）
- **AMD MI355X 凭什么追平 GB200**：8 芯粒 + 每 CU 矩阵翻倍 + 160KB LDS + MXFP4/6（09 篇）
- **一张卡装得下 70B 模型吗**：FP16 需 ~140GB 权重 + KV Cache，INT4 量化后 ~40GB——用显存规划公式当堂验算（10 篇第 3 节）

## 6. 观测与调优工作流：一套可复制的四步法

把前五节变成日常操作，2026 年推荐的四步工作流：

1. **Profile**：`nsight compute`（内核级）/ `nsight systems`（系统级）抓基线——先看 Memory Throughput 与 Compute Throughput 判定受限方向；AMD 用 ROCm 的 rocprof，国产卡用各家 Profiler
2. **Roofline 定位**：把内核的算术强度标在 Roofline 图上，确定带宽受限还是算力受限——决定优化方向是省字节还是改计算结构
3. **Stall 分析**：看 warp 停等的原因分布（访存/依赖/屏障/发射端口）——访存多则优化数据布局与合并访问，依赖多则调 `__launch_bounds__` 压寄存器，屏障多则检查同步粒度
4. **单变量调优**：一次只改一个旋钮（块大小/共享内存/流水深度），每个改动重跑基准——GPU 性能曲线非线性，组合改动无法归因

生产纪律：每次调优记录"改动-吞吐-受限方"三元组；内存与计算吞吐双双 90%+ 即停止——继续调收益递减。2026 年 vLLM 等推理框架已把多数内核级优化固化为配置项（KV 分块、prefill/decode 分离、专家预取），工程师的职责从"写内核"转向"配参数 + 验证"——但读懂本节仍能解释"为什么这个参数有效"。

落地检查单（10 秒版）：显存是否留 20% 余量？KV Cache 是否量化/分层？网格是否为驻留容量整数倍？共享内存是否双缓冲？NVLink 域是否覆盖张量并行规模？液冷与电力是否在采购前确认？——六问六答，架构认知转化为生产动作。

> 🎯 **核心要点**：性能工程的第一性顺序——Roofline 先定受限方向（推理几乎永远是带宽），占用率模型再定内核配置（四约束取最小），显存规划定容量（KV Cache 是第二黑洞），最后用实际精度、带宽、互连、生态、单位 token 成本五条红线做选型；标称 PFLOPS 除以 5，是估算真实推理吞吐最诚实的起点；落地靠 Profile→Roofline→Stall→单变量四步工作流与六问检查单闭环。
