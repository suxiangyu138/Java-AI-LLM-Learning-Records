# SIMT 执行模型与指令流水线
> "单指令多线程"不是宣传口号，而是一条条指令如何在 32 个线程间广播、如何排队发射、如何被流水化的硬件机制——以及分支发散为什么是性能杀手。

## 1. warp：锁步执行的 32 个线程

程序里的一万个线程在硬件上被组织为 warp（NVIDIA 32 线程、AMD wave32/wave64 可选 32 或 64）。**一个 warp 内的所有线程共享同一条指令流，锁步执行**——调度器取一条指令，广播给 32 个执行单元，各自处理自己的数据。

锁步带来两个推论：一是取指与解码开销被 32 个线程摊薄（一条指令服务 32 个线程，这就是吞吐经济学的来源）；二是 **warp 是调度与同步的最小单位**——线程没有独立指令流，所以"线程级分支"只能以 warp 为单位处理（见第 3 节）。

## 2. 指令流水线：发射、执行与等待

GPU 指令流水线与 CPU 同源，但更短更直：**取指 → 解码 → 发射 → 执行 → 写回**。SM 的 4 个调度器每周期各发射一条指令，但指令能否发射取决于操作数就绪状态——寄存器依赖、访存未返回都会让 warp 停在"等待"状态。

GPU 流水线的独特之处在于**不依赖乱序执行来消解等待**：与其在硬件里做寄存器重命名与乱序发射（浪费面积），不如把"等待的 warp"赶下调度器、换上一个就绪 warp。代价是每个 warp 的指令延迟被完整暴露（访存 100-600 周期），但换来的吞吐却更高——这是 05 篇"延迟隐藏"机制的硬件前提。指令延迟暴露的另一个后果：编译器（nvcc/PTX）必须做显式的指令级调度，把不相关的指令插在依赖之间，填充流水线气泡。

## 3. 分支发散：执行所有路径

SIMT 处理分支的方式是硬件掩码：当 warp 内线程走不同分支时，硬件**依次执行所有分支路径，对未选中的线程用谓词（predicate）掩蔽其写回**。例如 `if (tid % 2 == 0) A else B`，硬件先执行 A 路径（偶数线程活跃、奇数线程掩蔽），再执行 B 路径——两条指令都要花掉各自的发射周期。

发散的成本因此有两个：执行时间翻倍（两条路径都要跑），且全 warp 以最慢路径为准。但 2026 年的编译器已把多数发散转化为**谓词指令（predicated instructions）**——把 if/else 压成"计算两个结果 + select 选择"，单条指令完成，无分支跳转。这解释了为什么 GPU 不投资分支预测器：掩码与谓词让"猜对分支"变得不必要。

## 4. 收敛与同步：warp 内与跨 warp

**warp 内同步**是隐式的：锁步执行天然保证 warp 内线程同步，`__syncwarp()` 只是防御性显式化。**跨 warp 同步**则需要显式屏障：`__syncthreads()` 对应 CTA 级屏障，硬件用栅栏计数器实现——所有线程到达后才放行。跨 SM 的同步（grid 级）只能通过全局内存 + 原子操作或 cooperative groups 完成，成本高一个量级。

屏障的硬件实现值得注意：CTA 级屏障是共享内存里的一个计数器，到达的 warp 原子递增，计数等于块内 warp 总数时全部放行——因此屏障代价与块内 warp 数成正比，频繁调用 `__syncthreads()` 是真实性能开销而非安全空转。经验法则：块内屏障次数应与数据搬运次数同量级，每多一次屏障，warp 就多一次全停等。

另一个硬件细节是**部分 warp 收敛**：当发散的分支路径在后续点汇合时，硬件在汇合点恢复全 warp 执行。编译器负责插入收敛点（convergent point），把发散区间的开销控制在路径本身。

## 5. 执行单元流水细节：吞吐与延迟的数字观感

以 B300 的 FP32 单元为例感受数量级：128 核/SM × 160 SM × 每周期 1 次 = 20,480 次 FP32/周期；在 ~2GHz 下即约 **40 TFLOPS FP32**——但 L2/HBM 的访存延迟是 200-600 周期，意味着每次缓存缺失都要用几十个 warp 的并发去掩盖。矩阵引擎（Tensor Core）走完全独立的数据通路（见 06 篇），其吞吐（FP4 15 PFLOPS）比 FP32 高两个数量级——2026 年几乎所有训练与推理算力都发生在 Tensor Core 上，通用单元的职责更多是数据搬运与标量控制。

## 6. 波前效应：网格不整除时的尾部浪费

warp 是硬件执行单位，但程序员调度的是块。当网格大小与 SM 驻留能力不整除时，出现"波次（wave）"现象：GPU 把所有块按驻留容量分成几波执行，每波把 SM 填满；最后一波若块数不足，部分 SM 空转——**尾部浪费**。以 B300 为例：160 SM、每 SM 驻留 16 块（256 线程块场景），整卡一波驻留 2,560 块；若网格有 2,600 块，第二波仅 40 块，120 个 SM 在最后一波全程空闲——利用率打八折。

两个补救手段：其一，网格大小取驻留容量的整数倍（2,560、5,120……）；其二，改用**持久内核（persistent kernel）**——只启动与驻留容量相等的块，块内循环领取任务直到耗尽。后者彻底消除尾波，代价是任务队列的原子操作开销与负载均衡复杂度，但在 MoE 推理这类"任务粒度不均"的场景（专家大小不一、耗时各异）收益显著——这正是 2026 年 vLLM 等推理引擎做块级调度的底层原因。

波次效应还解释了块大小的选择逻辑：块越小、每波容纳块数越多，尾波浪费的绝对值越小——但块太小又增加调度与屏障开销。实践中 256-512 线程块是吞吐与碎片的最优区间，且天然为 2 的幂，与块槽、warp 槽的资源分片对齐。

> 🎯 **核心要点**：SIMT 的硬件本质是"一条指令广播给 32 个执行单元"的锁步执行，warp 是调度/同步的最小单位；GPU 用显式指令调度 + 多 warp 轮换来对付指令延迟，用掩码/谓词来回避分支预测，用显式屏障来跨 warp 同步；此外网格与驻留容量不整除会引发尾波浪费，块大小的选择与持久内核是软件侧的补齐手段——这四条机制共同决定了所有 CUDA 优化（合并访问、避免发散、减少屏障、块调度）的底层逻辑。
