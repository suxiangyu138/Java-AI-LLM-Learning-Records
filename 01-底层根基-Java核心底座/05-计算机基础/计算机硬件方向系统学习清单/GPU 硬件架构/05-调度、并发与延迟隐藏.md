# 调度、并发与延迟隐藏
> GPU 不靠乱序执行消解等待，而靠"一个 warp 等内存时换另一个上"——调度策略、占用率计算与异步拷贝机制，共同决定这张卡到底喂饱了多少算力。

## 1. 延迟隐藏的基本账

先算一笔账：B300 的 L2 命中约 200 周期、HBM 约 600 周期，而一条 FP32 指令延迟约 4-20 周期。若一个 warp 发出一条访存指令后必须等结果，它在该指令上停顿数百周期——**单个 warp 的算力利用率不到 5%**。要喂饱执行单元，SM 必须同时驻留足够多的 warp：每 SM 需 ~20-48 个活跃 warp 才能把 600 周期的访存延迟藏进其他 warp 的执行时间里。这就是"并发换吞吐"的完整逻辑：**延迟无法消除，只能用并发淹没**。

## 2. 调度策略：谁先发射

每 SM 4 个调度器，每周期各选一个就绪 warp 发射。就绪判定是"本条指令的源操作数都可用"——访存未返回、寄存器依赖未解除的 warp 靠边站。2026 年 NVIDIA 调度策略的主流选择：

- **GTO（老 warp 优先）**：默认策略，优先发射最早就绪的 warp——让快完成的 warp 尽快释放资源，提高驻留吞吐
- **LRR（轮转）**：所有就绪 warp 轮流发射——延迟均匀但整体吞吐略低，适合延迟敏感的调试场景
- **启发式组合**：Blackwell 硬件上可在 PTX/CUDA 层通过优先级提示影响发射次序（warp 优先级、特化 warp 的服务质量）

调度是**每个周期都在发生的硬件决策**，4 个调度器互不干扰、并行发射——所以 SM 的指令吞吐是"4 条/周期 × 32 线程 = 128 线程/周期"，与 128 个 CUDA 核完全对齐。调度器之间没有负载均衡的机制：一个调度器负载重、另一个空闲是常态——内核设计让每个 warp 的执行时间尽量均匀（对称代码、均匀分支），就是变相给四个调度器做负载均衡。

## 3. 占用率：一张公式一张表

**占用率 = 活跃 warp 数 ÷ SM 最大驻留 warp 数**（B300 为 64）。它不是"越高越好"的终极指标，而是"隐藏延迟够不够"的判据。决定占用率的四个硬件约束同时成立，取最小者：

- **寄存器**：每线程寄存器数 × 线程数 ≤ 256KB/SM（如 32 寄存器/线程 → 64KB/2048 线程，占用率受限于 64KB 分片）
- **共享内存**：每 CTA 共享内存量 × CTA 数 ≤ 128KB 可配置上限
- **CTA 槽位**：SM 最多驻留 32 个 CTA（32 块）
- **warp 上限**：64 个 warp

典型矛盾：FlashAttention 的算子为了共享内存分块把块做大，共享内存上限先到——占用率跌到 50% 但带宽吃得饱，性能反而最好；反之寄存器吃满也会砍占用率。**性能优化的方向不是最大化占用率，而是让实际瓶颈（算力或带宽）持续满载**。

## 4. 异步拷贝与生产者-消费者模型

纯靠"等待+切换"隐藏延迟有上限：同步访存的 warp 仍需占用发射槽。Hopper 起引入 **TMA（Tensor Memory Accelerator）**，Blackwell 增强：TMA 是一条**异步拷贝引擎**——一次指令把全局内存的整块数据搬进共享内存，搬运期间 SM 的寄存器与发射槽完全空闲去做计算。配套的编程模型是 **warp 特化（warp specialization）**：把 warp 分成"生产者"（只发 TMA 指令搬数据）与"消费者"（只做矩阵运算），两者通过共享内存/屏障流水线协作。B300 进一步提供 **TMA 2SM Load**：两个 CTA 配对，一个专职 TMA 生产、一个专职 MMA 消费，配合双 CTA 驻留达到 ~35% FP16 峰值（约 1.3 PFLOPS）的实测吞吐。

AMD 的对应物是 CDNA4 的 L1 直连 LDS 通路与更大的 LDS（160KB/CU）；Rubin 则把 TMA 描述符管理进一步优化，用于 MoE 场景的专家权重调度——**异步数据通路是 2026 年各家架构竞争的焦点**。

TMA 的另一个能力是集群内共享内存互拷贝（DSMEM 支持）：数据可以不经全局内存、直接在 SM 之间搬移，时延与带宽都优于"落盘再读"的路径。Blackwell 还允许 TMA 描述符携带 2:4 稀疏与非连续布局信息，搬运的同时完成格式转换——数据格式的转换被折叠进搬运流水，省掉一次单独的转换内核。这些细节解释了为什么同样的 GEMM 在 Blackwell 上比 Hopper 快 30-40%：不止算力涨了，数据通路也做了减法。

## 5. 双缓冲与多级流水：把搬运时间藏进计算

TMA 解决了"搬运占发射槽"的问题，但搬运本身仍要花时间——双缓冲是标准解法：共享内存切两半，TMA 把下一块数据搬进"后台半区"，矩阵引擎同时计算"前台半区"，交替使用。理想流水下，搬运时间与计算时间完全重叠——**吞吐 = max(计算时间, 搬运时间)，而不是两者之和**。流水可以更深：三段流水（搬运→计算→写回）需要 3 倍共享内存，但进一步消除写回停顿；Hopper 的 wgmma + TMA 组合、Blackwell 的 2SM 配对（一个 CTA 专产数据、一个专算矩阵）都是这条路的工程化。

判断流水是否打满的指标很直接：`nsight compute` 的 Memory Throughput 与 Compute Throughput 双双 90%+，说明搬运与计算都吃满——这才是"性能调好了"的证据，而不是占用率数字。多级流水还延伸到跨卡：NVLink 的 P2P 搬运同样可以异步（`cudaMemcpyAsync` + 多流），MoE 推理中"下一层专家权重提前搬到本地"的预取，是 2026 年吞吐优化的最大机会点。

占用率计算的实感：B300 每 SM 驻留 64 warp，内核每线程 64 个寄存器——256KB ÷（64×4B）= 1,024 线程 = 32 warp，占用率 50%；若每块还申请 96KB 共享内存，则 128KB ÷ 96KB = 1 块、块内 8 warp → 占用率骤降 12.5%——共享内存先触顶。可见"拼命压寄存器"往往不如"减少每块共享内存"来得快，优化要按四约束中最短的那块木板补。

> 🎯 **核心要点**：延迟隐藏的账本很清晰——600 周期的访存延迟需要 20+ 个 warp 并发去淹没，占用率由寄存器/共享内存/CTA 槽/warp 上限四重约束取最小；默认 GTO 调度让老 warp 先完成先释放；TMA + warp 特化把数据搬运从发射流水里剥离，Blackwell 的 2SM 配对让生产与消费彻底分工；双缓冲与多级流水把搬运时间藏进计算，吞吐由 max(计算, 搬运) 而非两者之和决定——"把数据提前搬到离算力最近的地方"是比调度更高级的隐藏手段。
