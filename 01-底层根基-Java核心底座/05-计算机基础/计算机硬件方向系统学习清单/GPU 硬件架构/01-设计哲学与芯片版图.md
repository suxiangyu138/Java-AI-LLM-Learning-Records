# GPU 设计哲学与芯片版图
> 为什么 GPU 和 CPU 长得完全不一样？答案藏在"吞吐优先"的设计哲学里——从晶体管预算的分配，到 2026 年双芯粒、多芯粒的封装版图。

## 1. 设计哲学：吞吐优先 vs 时延优先

CPU 与 GPU 的设计目标从根上分道扬镳。CPU 面对的是"一个复杂任务要尽快完成"，因此把晶体管预算投向分支预测、乱序执行、大容量缓存——目的是降低单线程时延；GPU 面对的是"一万个简单任务要一起完成"，因此把预算投向执行单元、寄存器堆与带宽——目的是提高总吞吐。

这造成一组耐人寻味的数字对比：2026 年一颗旗舰 CPU（如 AMD EPYC）拥有不到百个高性能核、数十 MB 缓存；而 Blackwell Ultra B300 拥有 20,480 个 CUDA 核心，却在 208B 晶体管里只留了比 CPU 小得多的缓存。GPU 的底层假设是：**线程数量多到可以互相掩护**——一个 warp 在等内存时，调度器立刻切到另一个就绪 warp，时延被并发掩盖而非被硬件消除。

## 2. 晶体管面积预算：钱花在哪里

芯片设计本质是"面积预算"问题——每一块电路都要用硅片面积与功耗去换。GPU 的面积分配遵循"执行优先"原则：

- **执行单元**（CUDA 核、Tensor Core、SFU、LSU）占最大份额，这是吞吐的来源
- **寄存器堆**（每 SM 256KB）被投到极限——寄存器是延迟最低的存储，为了藏延迟宁可不做缓存
- **缓存/控制逻辑**被刻意压缩——分支预测器在 GPU 里几乎不存在，因为 SIMT 用"执行所有路径+掩码"回避了分支预测
- **片上互连与 L2 切片**是隐性大户——数据要在 SM 与 HBM 之间流动，NoC 的线宽直接决定带宽

## 3. 从晶粒到封装：芯粒化与互连

2000 年代 GPU 是单晶粒（monolithic）设计，一颗芯片一次光刻完成。但光刻掩膜尺寸（reticle limit）限制了单晶粒的面积，2020 年代后主流旗舰全面走向芯粒化（chiplet）：

- **NVIDIA 双芯粒路线**：B300 用两个计算晶粒（compute die）通过片内高带宽互连（约 10TB/s）封装在一起，对外表现为一张卡、统一寻址；Rubin 同样双晶粒（NV-HBI 互连），晶体管数从 208B 涨到 336B
- **AMD 多芯粒路线**：MI355X 采用 8 个计算芯粒（XCD，每颗约 110mm²）+ 2 颗 IO 芯粒，用 Infinity Fabric 连接；芯粒化让 AMD 能把不同工艺、不同功能的晶粒混合封装，成本与良率可控
- **IO 芯粒的关键作用**：内存控制器、PCIe/NVLink PHY 集中在 IO 芯粒，计算芯粒专做计算——芯粒间每次穿越都要消耗功耗与延迟，MI355X 把 IO 芯粒从 4 颗合并为 2 颗、去除域穿越电路，就是为了省下这层开销

芯粒化的代价是互连工程——芯粒间带宽（B300 约 10TB/s 片内、Rubin NV-HBI 同量级）必须远高于 HBM 带宽（8-22TB/s 的访问需求由片上 L2 切片消化），否则"1+1<2"。这正是 07 篇片上互连要回答的问题。

芯粒化的直接收益是良率经济学：大晶粒上任意缺陷都可能导致整颗报废，而 8 颗小芯粒中坏掉一颗只损失约 1/8 的产量成本——NVIDIA 的双晶粒方案同样受益。此外芯粒化还让"混合工艺"成为可能：计算芯粒用最先进工艺、IO 芯粒用成熟工艺，性能与成本分别优化。代价是封装复杂度与测试成本上升，且芯粒间带宽必须大于实际访存需求，否则出现"1+1<2"的互连瓶颈——这正是各家把片内互连（NV-HBI、Infinity Fabric）当作核心卖点的原因。

## 4. 芯片版图总览：从 GPC 到 SM

以 B300 为例自上而下看版图：芯片分为 8 个 **GPC（图形处理簇）**，每个 GPC 含 20 个 **SM（流式多处理器）**，共 160 SM；每 SM 内是 128 个 CUDA 核 + 4 个第五代 Tensor Core + 4 个 warp 调度器 + 256KB 寄存器堆 + 256KB TMEM。GPC 是版图布局的基本重复单元，围绕 GPC 对称排布的是 L2 切片与 HBM 控制器——这种"重复单元 + 周围插满存储控制器"的布局，让每颗芯片的制造版图极其规整，也决定了所有数据流动都要穿越 L2。具体的 GPC 数与每 GPC 的 SM 数（8×20、每代每型号不同）由功耗、互连带宽与封装尺寸综合决定——数字本身不必背，数字背后的"重复单元 × 存储环绕"结构才是架构的本质。

## 5. 功耗墙与频率天花板：面积之外的另两本账

设计 GPU 不只是分配面积，还要同时分配功耗预算与频率预算。B300 的 TDP 已达 1,400W、Rubin 更至 1.8-2.3kW，功耗的三大去向是执行单元动态功耗（占大头）、片上互连与 L2（数据搬运的代价）、以及 HBM 本身（8 个堆栈的 IO 驱动）。功耗约束直接改变架构决策：

- **液冷从选配变标配**：1,400W 以上风冷无解，Blackwell 机柜级强制液冷；Rubin NVL72 用 45°C 进水实现多数气候区免冷水机——散热从"附赠工程"变成"架构设计输入"
- **功耗密度限制算力密度**：一个标准机柜供电约 40-60kW，而 Rubin 单机柜需 190-230kW——采购 GPU 实质是采购电力，供电改造成本常超显卡本身
- **性能/瓦成为第一指标**：NVIDIA 宣称 Rubin 相对 Blackwell 每单位能量的 agentic 推理吞吐提升 10×——电力是 2026 年最稀缺的"算力货币"

另一个隐藏约束是频率天花板：GPU 主频十年停留在约 1.5-2.5GHz——不是做不快，而是频率翻倍意味着电压与功耗非线性暴涨（动态功耗与频率约三次方相关），且信号在芯片上横穿一个周期都困难。于是每一代性能几乎全靠"堆并行"（更多 SM、更宽的矩阵引擎）而非"提频率"——这正是 GPU 与 CPU 的功耗策略分野：CPU 用少量高频大核，GPU 用大量中频小核，同样功耗预算下后者总吞吐高两个数量级。

> 🎯 **核心要点**：GPU 用"吞吐优先"哲学分配晶体管——执行单元与寄存器堆拿到最大份额，缓存与控制被压缩；2026 年旗舰全部芯粒化（NVIDIA 双晶粒、AMD 8 XCD），芯粒间互连带宽决定芯粒化成败；芯片版图是"GPC/SM 重复单元 + L2 切片 + HBM 控制器"的规整网格，读懂这张图才能读懂后面所有数据通路的讨论；而面积、功耗、频率三本账叠加，才构成架构决策的完整约束。
