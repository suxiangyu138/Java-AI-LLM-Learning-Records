# GPU 存储层次与带宽工程
> 存储层次决定了数据搬运成本，而 GPU 的每一次算力提升都要靠带宽喂饱——本模块讲清各级存储的结构、合并访问的硬件机制，以及 2026 年 HBM3e/HBM4 的带宽工程。

## 1. 存储层次全景：两级私有 + 两级共享

GPU 存储层次按"谁可见"分为四层，时延与容量逐级跳升：

- **寄存器堆（每线程私有）**：256KB/SM，延迟约 0 周期，容量极小（每线程 ≤255 个寄存器）
- **共享内存/L1（CTA 内共享）**：128KB/SM 可配置拆分，延迟 20-30 周期，带宽 128B/周期——程序员可显式管理的"片上 SRAM"
- **L2（全片共享）**：B300 约 126MB 级别，延迟 200-400 周期，是所有 SM 与 HBM 之间的汇聚点
- **HBM（全局内存）**：288GB，延迟 600+ 周期，带宽 8TB/s——容量以 GB 计、延迟以百周期计

带宽视角更残酷：**每上一层，带宽约降一个数量级**（寄存器 256B/周期 → 共享内存 128B/周期 → L2 若干 TB/s → HBM 8TB/s）。这就是 `内存墙/` 体系在 GPU 上的直接体现——8TB/s 的 HBM 带宽要喂 15 PFLOPS 的 FP4 算力，算术强度需求高达 ~1,875 FLOP/byte，而典型算子远达不到，**所以 GPU 实际性能长期是带宽受限**。

## 2. 合并访问：带宽利用的唯一前提

当 warp 的 32 个线程同时访问全局内存时，硬件按"**合并访问（coalesced access）**"规则工作：如果 32 个线程访问 128 字节连续地址（32 × 4B），**整组访问被合并为一次 128B 的缓存线事务**；如果地址离散，则退化为最多 32 次独立事务——带宽利用率掉一个数量级。

硬件机制：LSU 检查 warp 的访存地址集合，把它们拼成对齐的段（32B/64B/128B 段），一次事务从 HBM/L2 取回整个段并分发。因此"线程 tid 访问 `A[tid]`"（连续）是教科书级正确写法，而"线程 tid 访问 `A[tid * 1024]`"（步长跳跃）是灾难。**所有矩阵运算库（cuBLAS/FlashAttention）的核心优化，本质都是重新排列数据让访存连续**——例如转置矩阵用共享内存做"读入转置、写出连续"，而非直接跳跃读。

## 3. 共享内存：程序员控制的 SRAM

共享内存是 GPU 存储层次中最独特的一层：它是片上 SRAM，由程序员显式分配、显式同步（`__syncthreads()`），延迟只有 L2 的十分之一。典型用法是**分块（tiling）**：把 HBM 中的大矩阵切成 32×32 之类的块搬进共享内存，块内反复重用，把对 HBM 的访问次数从 O(N³) 降到 O(N²) 量级——FlashAttention 把 KV 分块驻留共享内存，正是共享内存工程的最佳范例。

共享内存有 bank 结构：被分为 32 个 bank（每 bank 4B），同一周期不同 bank 可并行访问；若多线程命中同一 bank（bank conflict），则串行化。与合并访问同理：**bank 冲突是共享内存版的"未合并访问"**，设计数据结构时按"连续线程访问连续 bank"的规则布局。

存储层次里还有两条常被忽略的旁路：常量内存（constant memory，经广播路径以每线程 32 位读取，全 warp 访问同一地址时零额外成本）与纹理路径（纹理缓存，为图形设计，具备硬件插值与重复寻址模式）。AI 内核中常量内存仍用于只读参数的广播（如 GEMM 的缩放因子），纹理路径则基本退役。理解旁路的意义在于：GPU 存储层次不是简单的四层阶梯，而是"主干四层 + 旁路若干"的复杂网络——每个单元都可能是性能的隐藏捷径或陷阱，这也是为什么 `nsight compute` 的访存分析要按单元逐个看。

## 4. HBM 控制器与带宽工程

HBM 不是普通内存：DRAM die 垂直堆叠（B300 为 8 堆栈 × 12-Hi，共 288GB），通过硅通孔（TSV）与逻辑 die 相连，数据总线宽度惊人（8192 bit，即每周期可搬 1KB）。芯片上的每个 HBM 控制器管理一组堆栈，L2 切片与控制器交错排布，保证任意 SM 访问任意地址的路径长度近似——**延迟均匀性**是 GPU 版图设计的隐性约束。

2026 年的带宽工程三件套：一是 **HBM 代际升级**——B300 的 8TB/s 到 Rubin HBM4 的 22TB/s（2.8×），HBM4 把接口位宽翻倍；二是 **L2 吞吐与一致性**——L2 必须以远高于 HBM 的带宽服务 160 个 SM 的并发访存，L2 切片间的数据路由（NoC）是瓶颈所在（07 篇）；三是 **省字节**——量化、稀疏、缓存重用都在降低"每 FLOP 需搬运的字节数"，与 `量化背后硬件约束/` 体系完全同构：硬件把路修宽，软件把货变轻。

## 5. 弱内存模型：GPU 的同步纪律

GPU 采用弱内存模型（weak memory model）：**没有显式同步，硬件不保证访存顺序**。同一 warp 内的访存可能被编译器重排，不同 SM 的访存更是任意交错——程序员必须用显式机制建立顺序：

- `__syncthreads()`：块内屏障，同时充当共享内存与全局内存的同步点
- `__threadfence()` / `__threadfence_block()`：内存围栏，保证围栏前的写入对后续代码可见
- `volatile` 与原子指令：绕过缓存直接访问；`atomicAdd` 由 L2 的原子单元执行（AMD 由全局内存控制器协同）

弱模型是性能与便利的交换：强一致性（如 x86 的 TSO）需要硬件在每个访存之间维护秩序，浪费面积与延迟；GPU 把秩序成本转嫁给软件，代价是 bug 形态隐蔽——**跨块共享数据的竞态几乎无法靠调试器复现，只能靠设计纪律**。一个典型模式：生产者写共享内存 → `__syncthreads()`（或原子释放标志）→ 消费者读取；若漏掉屏障，编译器可能把消费者的读取上提到写入之前（二者无数据依赖），数据竞态不报错、时好时坏——这类 bug 是 GPU 排障榜的前三。生产铁律：块间通信只走全局内存 + 原子/栅栏，块内通信走共享内存 + 屏障，绝不混用未同步的读写。

> 🎯 **核心要点**：GPU 存储是"寄存器→共享内存→L2→HBM"的带宽漏斗，每层降一个数量级；合并访问把 32 个线程的连续访问合成一次 128B 事务，是带宽利用的唯一前提；共享内存用显式分块把对 HBM 的访问从 O(N³) 降到 O(N²)；2026 年 HBM3e 8TB/s → HBM4 22TB/s 的军备竞赛，配合软件省字节，共同决定 GPU 真实性能；而弱内存模型要求显式屏障纪律——访存优化的另一半是同步正确性。
