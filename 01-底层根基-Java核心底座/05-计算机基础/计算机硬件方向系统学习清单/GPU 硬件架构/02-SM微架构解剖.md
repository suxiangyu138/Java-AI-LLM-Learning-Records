# SM 微架构解剖
> SM（流式多处理器）是 GPU 的基本计算单元——它同时容纳 128 个 CUDA 核、4 个 Tensor Core、4 个调度器与 256KB 寄存器堆，是"吞吐优先"哲学在硅片上的直接体现。

## 1. SM 概览：一座自包含的"迷你处理器"

一个 SM 可以看作一座自包含的迷你处理器：它有自己的指令缓存、取指/解码/发射逻辑、执行单元、寄存器堆与共享内存，**不与其他 SM 共享执行资源**。2026 年 Blackwell Ultra B300 的每个 SM 配置为：

- **128 个 CUDA 核心**（FP32/INT32 单元，实际是 64 个 FP32 单元按 Ampere 起的 2× 派发方式工作）
- **4 个第五代 Tensor Core**（支持 FP4/FP8/FP6/BF16/FP16/TF32 与 FP32 累加）
- **4 个 warp 调度器**，每个调度器每周期可发射一条指令
- **256KB 寄存器堆**（128 线程 × 32 寄存器/线程 × 64 位 × 128 单元——容量是 CPU 单核的数百倍）
- **256KB TMEM**（Tensor Memory，矩阵累加专用存储，B300 全片共 40MB）
- **128KB L1/共享内存**（可配置拆分）+ SFU 特殊函数单元 + 加载存储单元

全片 160 个 SM 同构重复，这就是第 01 篇说的"重复单元"版图——制造简单、扩展线性。SM 的物理尺寸与功耗占比在整卡中也举足轻重：一个 SM 的功耗预算通常占整卡 TDP 的 0.5% 上下，160 个 SM 就是整卡功耗的大头——所以"关 SM"（降低活跃 SM 数）是数据中心卡最直接的降功耗手段。

## 2. warp 调度器：每周期一次发射

每个 SM 内 4 个 warp 调度器各自服务一批 warp（每 SM 最多驻留 48-64 个 warp）。调度器每周期从就绪 warp 中选择一个发射指令——就绪条件是：指令不依赖尚未完成的操作、操作数可用。由于一条 warp 指令驱动 32 个线程，**每个调度器每周期实际驱动 32 个线程执行**，4 个调度器即 128 线程/周期的吞吐——与 128 个 CUDA 核完全对齐，这正是"128 核/4 调度器"配比的由来。

调度策略（见 05 篇）决定了谁先发射：Blackwell 默认策略偏"老 warp 优先"（GTO 风格），因为老 warp 更接近完成、先完成先释放资源。

调度器的燃料是指令缓存（I-cache，数十 KB 级）与取指带宽：SM 要同时服务 48-64 个 warp 的指令流，I-cache 未命中会让调度器空转，吞吐直接受挫——所以内核代码要避免无节制的循环展开（unroll），防止指令流膨胀击穿 I-cache。取指宽度与发射宽度对齐（每周期约 1 条/调度器），部分代际支持双发射，让指令级并行多一条出口——但双发射只在两条指令互不争抢执行单元时有效，编译器负责找出这样的配对。

## 3. 执行单元块：每组的 32 个核

每个 warp 调度器对应一组 32 个执行单元（一个"处理块"）。一条 FP32 指令被广播到该组 32 个核，每个核处理一个线程的数据——这就是 SIMT 的"单指令多线程"在硬件上的落点：**执行单元不做选择，只做执行**。该组还包括：

- **FP32 单元**：做常规算术；Ampere 起 FP32 与 INT32 双派发，同周期可同时喂两条
- **SFU**：sin/cos/exp/倒数等特殊函数，吞吐远低于主流水（如 1/16）
- **LSU（加载存储）**：负责访存指令，通过交叉开关访问 L1/共享内存，带宽约束是 128B/周期
- **Tensor Core**：独立于通用单元的矩阵引擎，有自己与 TMEM 相连的数据通路（06 篇）

## 4. 寄存器堆与 TMEM：两种"私有"存储

SM 的寄存器堆是 GPU 时延隐藏的根基：每线程最多 255 个 32 位寄存器，访问延迟约 0 周期（旁路直通）。寄存器堆总量固定（256KB），**线程数 × 每线程寄存器数 ≤ 总量**——因此"占用率"与"每线程寄存器用量"互为跷跷板，这是 05 篇占用率计算的核心输入。

TMEM 是 Blackwell 引入的新存储层：Tensor Core 的累加结果直接写入 TMEM，而不再绕经寄存器堆——矩阵乘的 C 矩阵（通常 128×128×FP32）吞吐要求极高，专用累加器存储把 MMA 指令的寄存器压力与数据移动量大幅削减。AMD 在 CDNA4 上的对应做法是把每 CU 的 LDS（局部数据共享）从 64KB 扩到 160KB 并加直连 L1 的加载通路——两家殊途同归：**给矩阵引擎配专用、够大的片上存储**。

## 5. CTA 与线程块的硬件落点

SM 之上是线程块的分配机制：程序创建线程网格（grid），硬件以块（CTA，Cooperative Thread Array）为单位把块分配到 SM——一个 SM 同时驻留多个块（B300 上限 32 个），块内 warp 轮流占用 64 个驻留槽位。三个硬件细节决定分配行为：

- **块是资源分配的单位**：共享内存、寄存器按块预留，块执行完才整体释放——块大小影响资源碎片，256 线程块（8 warp）是吞吐与碎片之间的通用默认值
- **块间无同步**：不同 CTA 之间没有硬件屏障，只能靠全局内存原子或 cooperative launch 协同——软件必须假设块的执行顺序完全任意
- **尾波效应**：网格大小若非 SM 容量的整数倍，最后一个"波次"的块数不满，尾部 SM 空转——2,600 个块跑在每波 2,560 块容量的卡上，第二波只有 40 块，120 个 SM 闲置

CTA 槽位是占用率四约束之一（05 篇）：即便寄存器与共享内存都够，32 个块槽占满也无法再驻留——这也是 2 的幂块大小（128/256/512 线程）更受欢迎的原因，块槽、warp 槽与资源分片都是 2 的幂划分。

Hopper 起还引入了线程块簇（Thread Block Cluster）：允许最多 8 个 CTA 组成簇，共享"分布式共享内存（DSMEM）"——簇内块可直接读写彼此的共享内存，簇粒度屏障由硬件保证。这弥补了"块间无同步"的空白，是 MoE 专家路由与多级 GEMM 拆分的重要硬件支撑；AMD 侧没有等价机制，CU 间只能经 L2 协作——这是 NVIDIA 在片上协作计算上的一个结构性优势。

> 🎯 **核心要点**：SM 是"128 核 + 4 调度器 + 4 Tensor Core + 256KB 寄存器 + 256KB TMEM"的自包含计算单元，4 调度器与 128 核的配比保证了每周期全核派发；寄存器堆与 TMEM 是两条独立的"私有存储"通路，前者支撑通用线程时延隐藏，后者为矩阵引擎专用；块（CTA）是资源分配单位，32 块槽与 64 warp 槽共同构成驻留上限，簇机制（DSMEM）补上块间协作的空白——读懂 SM 内部的数据流与分配规则，是理解占用率、Tensor Core 与所有 CUDA 优化的起点。
