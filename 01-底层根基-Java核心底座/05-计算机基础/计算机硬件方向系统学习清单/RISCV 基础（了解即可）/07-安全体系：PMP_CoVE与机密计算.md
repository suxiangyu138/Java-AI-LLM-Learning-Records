# 安全体系：PMP、CoVE 与机密计算
> 开源指令集的隐藏红利是安全：PMP 提供无 MMU 的物理隔离、Stateen 控制扩展状态访问、CoVE 给出对标 SEV/TDX 的机密计算——2026 年 RISC-V 的安全体系从"嵌入式隔离"长到了"云上机密"。

## 1. 三层安全架构

RISC-V 的安全能力按场景分层，2026 年已形成完整工具箱：

- **硬件隔离层**：PMP/ePMP（物理内存保护，M 模式固件定义 S/U 代码可访问的物理地址区域与读写执行权限）、IOPMP（I/O 物理内存保护，阻止恶意 DMA 访问）、IOMTT（物理页级 I/O 隔离）
- **机密虚拟化层**：CoVE（机密虚拟机扩展，第 3 节）、Supervisor Domains/Smmtt（监督域隔离，多租户物理地址空间隔离，减少监督者 TCB）
- **数据加密层**：标量加密（Zkne/Zknd/Zknh、Zbkb 位操作）、向量加密（Zvk 系列——Zvkn 覆盖国际标准算法、**Zvks 覆盖中国国密算法**）、Zkr 真随机熵源（RVA23 强制）

三层的组合哲学：**按设备形态取用**——无 MMU 的 MCU 用 PMP 做 TEE；有 MMU 的应用处理器用特权级 + CoVE；服务器再加 IOPMP 与 Smmtt 收紧 I/O 侧。**同一个 ISA，安全纵深从单片机排到数据中心**，这是模块化在安全上的复利。

## 2. PMP/ePMP 与 Stateen：硬件级的最小隔离

**PMP（Physical Memory Protection）**是 RISC-V 安全的地基：M 模式固件把物理地址空间划分成若干区域（通常 16 个 PMP entry），每个区域设定 S/U 模式的访问权限（读/写/执行）。没有 MMU 的嵌入式设备（MCU、安全协处理器）靠它实现"固件与代码互相隔离"——例如蓝牙协议栈与主应用互相不能读写对方内存，这正是 x86 在低端设备上给不了的（x86 没有轻量物理保护机制，MCU 界用 MPU 或干脆没有）。

**ePMP** 进一步收紧：机器模式自己的执行也受限，把 TEE 的 TCB 压到最小。**Stateen 扩展**（Smstateen/Ssstateen，1.0 已批准）解决另一个问题：扩展状态（向量寄存器、浮点寄存器、加密引擎状态）的访问控制——mstateen/sstateen/hstateen CSR 逐位控制低特权级能否访问扩展状态，防止侧信道与状态泄漏。

两个设计的共同点：**都是规范定义的最小硬件原语**，组合出各种安全方案；且因为是开源规范，**每一项都被安全社区逐行审计过**——这是闭源指令集永远无法承诺的资产（第 4 节）。

## 3. CoVE：RISC-V 的机密计算

机密计算（Confidential Computing）是 2026 年云安全的主题：**云厂商也读不了你的数据**。x86 有 AMD SEV/Intel TDX，ARM 有 CCA，RISC-V 的答案叫 **CoVE（Confidential VM Extension）**，由 AP-TEE 规范定义：

- **TEE 虚拟机（TVM）**：客户机内存与 vCPU 状态归 TEE 安全管理器（TSM，运行在 M 模式）所有，宿主机 Hypervisor 与云运维**完全不可见、不可改**
- **构建在 H 扩展之上**：复用两级地址翻译，新增"TVM 内存的宿主机访问被硬件拦截"语义
- **启动度量**：内核、initrd、设备树在启动前被度量（哈希），虚拟机启动后校验——"从启动那一刻起可信任"
- **硬件/软件要求**：MSI 专用中断（IMSIC 强制）、PCI virtio 现代传输、vCPU 固定绑定；QEMU/KVM 的 CoVE 支持 2026-07 已有 RFC 补丁（KVM_VM_TYPE_RISCV_COVE），1.0 规范仍在打磨（ecall 前后置条件、TVM 创建模式收敛）

CoVE 的意义与 x86 的 SEV/TDX 完全对位：**让 RISC-V 服务器能进金融、政务、多云共用的机密工作负载**——没有它，RISC-V 服务器在云市场没有门票。2026 年玄铁 C950 已"原生支持 CoVE"，服务器平台规范 1.0 也把机密计算写入路线图。

## 4. 开源可审计：安全性的范式级差异

RISC-V 安全叙事里最被低估的一点是**可审计性**：指令集规范、特权规范、CoVE 规范全部公开，任何安全研究者可以逐条审计"硬件承诺了什么"；对比之下，x86 的微码（microcode）是闭源的、ARM 的 EL3 固件细节半公开——**安全审计的对象从"可信黑盒"变成"可验证白盒"**。

这在实践中的价值：安全漏洞发生后，RISC-V 生态可以公开讨论根因与修复（2024 年"GhostWrite"漏洞就是公开分析 T-Head C910 微架构的案例）；安全评估机构（金融、航天、国防）可以要求源码级审计；后门担忧（地缘政治语境下的敏感话题）有了"可排除"的机制性答案——**对主权算力项目，可审计性不是锦上添花，而是采购前提**（09 篇国产化叙事）。

## 5. 信任链的构建：从启动到应用的完整链条

安全体系单独看是部件，串起来是一条信任链：**信任根（M 模式固件，OpenSBI/TSM）→ 启动度量（CoVE 的 TVM 启动前哈希）→ 运行时隔离（特权级 + PMP + 页表）→ I/O 边界（IOPMP）→ 数据保护（Zvk 加密）**。对照 x86：UEFI Secure Boot → TPM → SEV/TDX 的链条同样存在，但每一环的"信任锚"是闭源的（BIOS 微码、Intel 管理引擎 ME——ME 的漏洞曾让整条链的信任崩塌）；RISC-V 的每一环都有公开规范与可审计实现——**"信任锚可审计"是 RISC-V 安全叙事区别于 x86/ARM 的本质**（第 4 节把它上升到战略价值）。

部署路径（2026 基准）：TSM（M 模式）→ 支持 CoVE 的 KVM（QEMU 已出 RFC）→ 容器运行时标记机密容器——**从芯片到容器的每一层都构建在公开规范上**；对云厂商，这意味着"机密虚拟机"功能可以自研实现，不受上游黑盒约束（对比 Intel TDX 的 SDK 依赖）。

### 5.1 侧信道与微架构安全：GhostWrite 的启示

2024 年的 GhostWrite 漏洞（T-Head C910 的向量单元可越权访问物理内存）是 RISC-V 生态的第一个重大安全事件——它的价值恰恰在于**分析过程完全公开**：漏洞根因（向量单元实现未遵守规范）、修复方案（固件禁用向量单元）、影响面评估，全部在开源社区完成；对比 x86 的 Meltdown/Spectre 时代，Intel 的响应是闭门打补丁、外界只能猜测。**开源的"坏消息"也是资产**——安全研究者可以独立验证修复是否有效，这是闭源架构给不了的信任基础。对实现方的启示：RVA23 配套的合规测试套件正在把"规范合规"变成"上市前提"，GhostWrite 之后测试只会更严。I/O 侧还有 SMMT（I/O 内存管理标记）与 IOPMP 配合，2026 年服务器平台规范标准化 PCIe/IOMMU 后，"设备不能乱摸内存"从 MCU 专属升级为服务器标配（与 `PCIe 带宽/` 的 IOMMU 论述互文）。

### 3.1 CoVE 与 x86 机密计算的对位

一句话对位：**AMD SEV ↔ Intel TDX ↔ ARM CCA ↔ RISC-V CoVE**——四家实现差异很大，但功能契约一致：客户机内存对宿主机不可见、启动可度量、密钥在芯片内保护。RISC-V 的差异化在两点：**TSM 是开放实现**（M 模式软件，任何人可审计，对比 Intel 的专有 SEV 固件）；**规范先于实现**（AP-TEE 规范公开推进，QEMU/KVM 支持 RFC 已出）——2026 年 CoVE 处于"规范打磨 + 实现验证"期，1.0 正式批准与量产芯片（玄铁 C950 原生支持）预计 2026-2027 对齐。对云厂商的决策含义：**机密计算是云上合规（金融、政务）的硬需求，RISC-V 服务器若无 CoVE 则无参赛资格**——这正是把 CoVE 称为"服务器门票"的原因。

安全层的"最小化"原则也值得记住：**方案的安全性与"它依赖多少代码"成反比**——PMP 只有 16 个寄存器条目，攻击面小；CoVE 的 TSM 刻意保持小而专；对比 x86 的 SMM 模式（历史遗留、攻击面大、几乎不可审计），RISC-V 的每个安全部件都是"小即是美"的践行者。

> 🎯 **核心要点**：RISC-V 安全是"模块化复利"的典型——PMP/ePMP 让无 MMU 的 MCU 也能做物理隔离，IOPMP/Stateen 补上 I/O 与扩展状态两个漏洞面，Zvk 向量加密覆盖国际与国密算法；CoVE 是 RISC-V 的 SEV/TDX——TVM 内存归 M 模式 TSM 所有，宿主机不可见不可改，2026 年 QEMU/KVM 支持 RFC 已出、玄铁 C950 原生支持；开源规范让每一项安全承诺都可审计——对主权算力项目，这是比性能更硬的采购理由。
