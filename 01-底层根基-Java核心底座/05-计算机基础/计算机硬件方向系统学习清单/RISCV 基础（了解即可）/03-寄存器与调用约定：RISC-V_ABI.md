# 寄存器与调用约定：RISC-V ABI
> 32 个通用寄存器、x0 硬连线为零、8 个参数寄存器、一套极简的调用规则——RISC-V 的 ABI 是三种主流架构里最规整的，读懂它，汇编和反汇编就不再是黑盒。

## 1. 寄存器文件：32 个 GPR 与 ABI 名

RV32I/RV64I 提供 32 个通用寄存器 x0-x31（各 XLEN 位宽）加一个程序计数器 pc。硬件上寄存器没有任何功能区分，是**ABI 规范赋予了名字与职责**：

| 寄存器 | ABI 名 | 职责 | 谁保存 |
|:---:|:---:|------|:---:|
| x0 | zero | 硬连线零（读恒 0、写忽略） | — |
| x1 | ra | 返回地址 | 调用者 |
| x2 | sp | 栈指针 | 被调者 |
| x3 | gp | 全局指针（数据段基址） | — |
| x4 | tp | 线程指针（TLS） | — |
| x5-x7 | t0-t2 | 临时寄存器 | 调用者 |
| x8 | s0/fp | 保存寄存器/帧指针 | 被调者 |
| x9 | s1 | 保存寄存器 | 被调者 |
| x10-x11 | a0-a1 | 参数/返回值 | 调用者 |
| x12-x17 | a2-a7 | 参数 | 调用者 |
| x18-x27 | s2-s11 | 保存寄存器 | 被调者 |
| x28-x31 | t3-t6 | 临时寄存器 | 调用者 |

**x0 是 RISC-V 的标志性设计**：硬连线为零，写入被忽略。它让"清零"（add x0, x0, x0）、"比较跳转"（beq x0, x0, label = 无条件跳转）、"复制"（addi rd, x0, imm = 加载立即数）都不需要专用指令——寄存器越少、指令集越小，硬件的解码与旁路越简单。

另一层设计：**没有专用栈指针指令**。sp 就是普通寄存器，栈操作 = 通用算术 + 访存指令。对比 x86 的 PUSH/POP 专用栈指令，RISC-V 把"栈"降级为 ABI 约定而非硬件机制——代价是代码密度略低（C 压缩扩展部分补偿），收益是硬件极简。

## 2. 调用约定：函数之间怎么交接

RISC-V psABI 定义函数调用的全部规则，核心五条：

- **参数传递**：前 8 个整数参数放 a0-a7，第 9 个起压栈（从低地址到高地址按顺序）；浮点参数走 f0-f7（按类型混合排布）
- **返回值**：整数放 a0，浮点放 f0；64 位返回值用 a0+a1 组合
- **保存规则**：被调者必须保存 s0-s11（callee-saved，用前保存、返回前恢复）；t0-t6、a0-a7 调用者负责（caller-saved，调用方自保）
- **栈对齐**：栈指针按 16 字节对齐（RV64）；ABI 要求栈向下增长，叶子函数可不开栈帧
- **帧指针**：s0/fp 可选（优化开启时仅作普通保存寄存器），栈回溯依赖编译器的 .eh_frame 而非固定帧指针——x86-64 同款现代方案

这套规则与 x86-64 的 System V ABI 高度同构（都是"参数进寄存器 + 被调者保存 + 16 字节对齐"），但比 x86-64 更简单：没有红区（red zone）约定、没有 AL 寄存器隐含计数、立即数规则统一。**用 x86 知识学 RISC-V ABI，只需要记忆差异表**（10 篇对照表）。

## 3. 伪指令与汇编助记符

RISC-V 汇编器的"糖衣"让代码更可读，常见伪指令（汇编时展开为真实指令）：

- `mv rd, rs` → `addi rd, rs, 0`
- `nop` → `addi x0, x0, 0`
- `li rd, 立即数` → 序列 LUI/ADDI（大立即数分两条）
- `call func` → `auipc ra, offset 高位; jalr ra, offset 低位`（PC 相对调用）
- `ret` → `jalr x0, 0(ra)`（跳回返回地址）
- `j label` / `beqz rs, label` / `bnez rs, label` → 无条件/零值分支

阅读反汇编时先展开伪指令，再对照六种格式（04 篇）——**伪指令是语法糖，真实指令永远是那四十多条**。一个实用技巧：`objdump -d` 加 `-M no-aliases` 选项可以关闭伪指令还原，看到最真实的编码。

### 3.1 一个最小函数示例

```asm
# int add(int a, int b) { return a + b; }
add:
    addi sp, sp, -16    # 开栈帧
    sd   ra, 8(sp)      # 保存返回地址（非叶子，可选）
    add  a0, a0, a1     # 结果 = a + b
    addi sp, sp, 16     # 收栈
    ret                 # jalr x0, 0(ra) —— a0 已带结果返回
```

对照 x86-64 版本，RISC-V 的差异一目了然：返回地址存 ra 寄存器而非压栈（x86 的 CALL 压栈）；参数在 a0/a1 而非 edi/esi；无 push/pop 专用指令。**同一份 C 代码，两种架构的汇编差距就是 ABI 规则的差距**——理解了 ABI，反汇编任何 RISC-V 程序都不再费力。

## 4. 浮点与向量寄存器：扩展带来的第二套寄存器

M/A/C 扩展只增强指令，**F/D 与 V 扩展引入新寄存器文件**：

- **f0-f31**（F/D 扩展）：32 个浮点寄存器，双精度模式（D）下 64 位宽。ABI 规则：浮点参数走 f0-f7、返回走 f0，整数与浮点参数按位置混合分配（如 add(double, int) → f0, a0）
- **v0-v31**（RVV 1.0 向量扩展）：32 个向量寄存器，宽度 VLEN 可配置（128 位到 512 位以上），配合 vsetvli 指令动态设置向量长度（06 篇）——**向量长度不写死在 ISA 里，这是 RISC-V 对 SIMD 最大的创新**：同一份向量代码在新旧硬件上运行，自动适配不同 VLEN

寄存器资源是"按扩展解锁"的：基础集只用 32 个整数寄存器，加 F/D 多 32 个浮点，加 V 多 32 个向量——硬件按需实现，软件按能力使用，与模块化哲学一脉相承（02 篇）。

## 5. 一次函数调用的全流程解剖

把 2/3 节的规则串成一个完整例子——C 代码 `long sum(long n) { long s = 0; for(long i=1;i<=n;i++) s+=i; return s; }` 的汇编骨架：

```asm
sum:
    li    t0, 0          # s = 0（伪指令 → addi t0, x0, 0）
    li    t1, 1          # i = 1
loop:
    bgt   t1, a0, done   # i > n 则跳出（伪指令 → blt a0, t1 反转）
    add   t0, t0, t1     # s += i
    addi  t1, t1, 1      # i++
    j     loop           # 无条件跳转
done:
    mv    a0, t0         # 返回值放 a0（伪指令 → addi a0, t0, 0）
    ret                  # jalr x0, 0(ra)
```

三个观察：**参数 n 从 a0 进入、结果经 a0 返回**（第 2 节调用约定）；**循环体没有用到任何栈操作**（s 和 i 都住在寄存器里，编译器寄存器分配的结果）；**返回地址 ra 由调用者保存**（sum 是叶子函数，无需动 ra——若被调者再调函数，必须先 sd ra 到栈）。对照 x86-64：同样的循环会看到 push/pop 与参数寄存器 rdi——**ABI 差异（第 2 节表）在真实代码里的投影**。练习建议：用 RARS 单步观察每条指令后的寄存器变化，这是最快的内化方式。

### 5.1 参数超过 8 个怎么办

当参数超过 8 个（或浮点参数打乱整数排布）时，第 9 个起的参数按顺序压栈：调用者从右往左压，被调者通过 sp 偏移访问栈上参数。这是 printf 这类可变参数函数的日常路径——**"为什么可变参数函数必须知道参数类型"的硬件原因就在这里**：类型决定参数从寄存器还是栈取、占几个槽位。对比 x86-64 的前 6 个参数进寄存器，RISC-V 的前 8 个参数槽位更宽——大函数调用的寄存器压力更小，这是 RV64 ABI 的实用优势。补充一个面试高频点：**可变参数的扫描规则与 x86-64 完全一致**——固定参数进寄存器、可变部分按"寄存器用尽后进栈"处理，编译器生成 va_arg 的寄存器保存区。

### 5.2 参数传递的完整规则：类型与位置

调用约定的细节藏在类型与位置的对应里：整数参数按位置占 a0-a7；浮点参数（F/D 扩展）占 f0-f7；**当整数与浮点混合时，按参数序号独立排队**——例如 f(double d, int i) 中 d 占 f0、i 占 a0（各自按序号，不互相挤占）；而 g(int i, double d) 中 i 占 a0、d 占 f0。返回值同理：整数走 a0、浮点走 f0。这套"按类型分流"的规则与 x86-64 一致，但槽位更多（8 个 vs 6 个）。另一个细节：**聚合类型（结构体）大于两个寄存器时按内存传递**——调用方在栈上留出空间、被调者通过 a0 收到指针——这是"结构体按值传递"的硬件成本来源，与语言无关、与 ABI 有关。

补充一个编译器视角的观察：**RISC-V ABI 的"无红区"设计**（x86-64 的 System V ABI 允许叶子函数使用栈指针下方 128 字节，RISC-V 不允许）让信号处理与栈回溯更简单——函数栈帧的边界完全确定，调试器与 profiler 的实现负担更小；代价是叶子函数的临时空间必须显式开栈帧，代码密度略有牺牲（由 C 扩展补偿）。

寄存器资源的另一个维度是**调用约定对它们的保存责任**：浮点寄存器 f0-f7 与向量寄存器 v0-v31 的保存规则与整数寄存器同构——fs 系列（被调者保存）、ft/fa 系列（调用者保存）；向量寄存器按 ABI 分参数/临时/保存三组。多一套寄存器多一套保存规则，但编译器全部自动处理——**对工程师，只需要知道"ABI 是编译器的事，但报 bug 时要能读懂它"**。

> 🎯 **核心要点**：RISC-V 的 ABI 是三种主流架构里最规整的——32 个 GPR 中 x0 硬连线零、x1-x4 承担 ra/sp/gp/tp、a0-a7 传参 + a0 返回、s0-s11 被调者保存、16 字节栈对齐；无专用栈指令、无 PUSH/POP，栈是 ABI 约定而非硬件机制；伪指令是糖、真实指令永远是四十多条；F/D/V 扩展按需解锁第二、第三套寄存器文件——读懂 ABI，反汇编任何 RISC-V 程序都不再是黑盒。
