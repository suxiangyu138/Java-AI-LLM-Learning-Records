# 精度与硬件效率的权衡：异常值、校准与混合精度
> 位宽越低压硬件越满意，但精度崩不崩由数值分布说了算——2026 年研究的重心是把 4-bit 精度补到"生产可用"，同时吃满原生指令。

## 1. 异常值（Outlier）是 4-bit 精度的头号杀手

大模型权重/激活的数值分布并非高斯：少数通道的值比均值大几个数量级。对低比特量化的影响链：

- 固定 scale 下，异常值直接把量化区间顶爆 → 正常值全挤进 1-2 个量化阶梯，有效精度归零
- 激活异常值比权重更严重：权重可离线按通道精调 scale，激活是每 token 在线出现
- 这解释了为什么 W8A8 全量化需要 SmoothQuant，而 W4A16 只碰权重就能保持精度

SmoothQuant 的思路是**把激活的异常值迁移到权重侧**：用数学等价变换把激活分布变平（除以通道方向缩放因子），同时把缩放乘进权重，使两侧都变"好量化"。这一变换让 W8A8 在 2024-2026 成为 FP8 之前的全量化主流。核心教训：**量化前先看分布，异常值治理是精度的前置条件**。

### 1.1 平滑变换的数学：等价变换如何保护精度

SmoothQuant 的核心是一个逐通道缩放的对角变换：

```text
Y = (X · diag(s)) · (diag(s)⁻¹ · W)   —— 括号内均可预先/在线计算
```

- 左侧：激活 X 每通道除以 s，激活范围被压平（异常值被吸收）
- 右侧：权重 W 每通道乘以 s⁻¹，吸收激活减掉的范围——权重侧离线重算，无推理开销
- 整体矩阵乘结果不变（数学等价），只是把"激活难量化"换成了"权重好量化"

s 的选取在"激活范围 vs 权重范围"之间权衡：s 太大会破坏权重侧（权重量化误差上升），太小压不平激活。实践中以通道统计（绝对值最大值、分位数）为依据搜索 s。**这个变换揭示了量化精度的本质：精度不是位宽的函数，而是"数值分布与量化网格匹配度"的函数**——分布经过变换后匹配变好，位宽不变精度也提升。

## 2. 校准：量化结果是校准数据的函数

PTQ（训练后量化）的 scale 不是数学算出来的，而是**用校准数据集跑一遍模型、统计数值范围**得到的。硬件约束体现在三个维度：

- **校准数据相关性**：校准集分布偏离线上流量，scale 就偏——Gaudi 的校准结果设备相关（Gaudi 2/3 不能互用），NVIDIA 侧不同架构的 scale 同样不通用
- **校准粒度**：动态量化（每 token 现算 scale）精度好但开销大，静态量化（离线固定 scale）快但怕漂移；FP8 动态量化是 Hopper 起的主流配置
- **校准即回归测试**：量化后必须用业务真实流量做评估（MMLU/GSM8K 等基准 + 业务指标），量化是部署动作，不是模型训练动作

### 2.1 校准协议：一套可复现的最小步骤

1. 取业务分布代表性的校准集（几百到几千条样本，覆盖任务类型与语言）
2. 跑一次前向收集每层激活统计（min/max、分位数、直方图）——**注意统计张量的显存开销，分块执行**
3. 选定位宽与粒度（对称/非对称、group 大小），计算 scale/zero-point
4. 量化权重，保存检查点 + 量化元数据（格式、粒度、scale、引擎假设）
5. 回归评估：通用基准（MMLU/GSM8K）+ 业务指标，与 BF16 基线对比
6. 把校准管线接入 CI：模型更新即重量化，量化制品随模型版本发布

两个高频坑：**校准集与线上分布漂移**（新任务类型上线后量化质量下降，需周期性重校准）；**校准张量类型错误**（FP32 统计与 BF16 推理的分布差异，导致 scale 偏小 2 个数量级——用推理精度做校准）。

## 3. 2026 年两个关键进展：MR-GPTQ 与 MicroMix

4-bit 量化的精度天花板在 2026 年被两项工作大幅推高：

**MR-GPTQ（ICLR 2026，Micro-Rotated-GPTQ）**：在量化前对权重块施加阿达玛（Hadamard）正交旋转，把异常值"摊平"到块内所有元素——旋转后块内每个值都变得可量化。效果：70B 级模型 MMLU 追平甚至超过 AWQ INT4，在 B200 上逐层加速约 3.6×（对比 BF16），70B 端到端吞吐 2.0-2.2×。**它解决的是"FP4 精度不够"这个曾经否决 FP4 的理由**。

**MicroMix（ICLR 2026）**：基于误差阈值自适应地为激活通道分配 MXFP4/MXFP6/MXFP8 位宽，平均 ~5.5 位/权重。效果：接近 FP16 精度，较 FP16 提速 2.3-3.4×。它的意义在于展示了 MX 格式族的优势——同一套 Tensor Core 指令（E2M1/E2M3/E3M2 家族）天然支持混合位宽，这是 INT 格式做不到的（INT4/INT8 指令不互通）。

## 4. 混合精度的硬件现实：W4A6 是 FP8 与 MXFP4 的折中点

AMD 在 MI355X 上的实测给出了清晰的精度-速度光谱（Llama-3.1-8B / Qwen3.6-27B）：

- 纯 MXFP4（A4W4）：最快，但困难评测集上精度损失明显
- **W_MXFP4_A_MXFP6**：仅慢 2-3%，精度大幅回升——当前速度-精度平衡点
- FP8：精度最稳，速度为基线

结论不是"位宽越小越好"，而是**按层/按通道混合位宽是精度-速度联合优化的事实标准**。硬件已为此铺好路：MFMA 指令族 `f8f6f4` 原生支持 8/6/4 位混合矩阵乘，Blackwell 的 FP4 Tensor Core 同样执行 MX 格式族。

### 4.1 混合位宽的工程形态：从研究到生产的落差

论文里的混合位宽（MicroMix 的按通道动态分配）与生产可用的混合位宽之间有明显距离：

- **研究形态**：按激活通道误差阈值动态分配 4/6/8 位，需要运行期统计与重分配逻辑，内核复杂度高
- **生产形态**：静态的层级混合（如：注意力投影 W4A4、FFN 中间层 W4A6、输出层 FP8）——量化器一次性决定，内核按层选择预编译变体
- **折中路径**：AMD 实测的 W_MXFP4_A_MXFP6（权重 4 位、激活 6 位）单方案混合，引擎支持成熟，精度-速度平衡优于纯 A4W4

实践建议：**先跑纯位宽梯度（FP16/FP8/MXFP4），确认哪个层是精度瓶颈，再对该层单独升位宽**——避免一上来就上动态分配。混合位宽的收益在 10-20% 精度恢复量级，而工程成本在数周——按业务精度缺口决定是否值得。

## 5. 精度-效率权衡的决策框架

1. 先量化，后评估：每个位宽档位（FP16→FP8→INT4/MXFP4）跑基准 + 业务指标，记录"精度损失-延迟收益"对
2. 精度敏感任务（数学、代码、长推理链）保守用 FP8 或 W4A6；吞吐敏感任务（高并发 chat）可上 A4W4
3. 参考量级：GSM8K 上 MXFP4 A4W4 恢复 BF16 的 98.64%（Qwen3-235B），GLM-5.2 MXFP4 在 GSM8K 损失约 1 个百分点——2026 年的 4-bit 精度已不是"不可用"，而是"按任务验收"
4. 校准与评估投入计入部署成本：量化省下的 GPU 时，要留一部分给校准迭代

> 🎯 **核心要点**：异常值是 4-bit 精度的头号杀手，SmoothQuant 把激活异常值迁到权重侧；量化结果是校准数据的函数，scale 不跨架构/设备通用；MR-GPTQ（Hadamard 旋转摊平异常值）让 FP4 精度追平 AWQ，MicroMix（MX 族混合 4/6/8 位）在 ~5.5 位均宽下接近 FP16 精度——2026 年 4-bit 已从"不可用"进入"按任务验收"；混合位宽（W4A6）是速度-精度的实际甜点，且 MX 格式族天然支持混位宽指令，INT 族做不到。
