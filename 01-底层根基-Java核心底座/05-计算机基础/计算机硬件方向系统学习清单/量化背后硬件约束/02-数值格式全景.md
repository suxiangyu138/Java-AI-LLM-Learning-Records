# 数值格式全景
> 理解 FP16/BF16/FP8/INT8/INT4/FP4 各自的位宽结构、动态范围与硬件映射——量化方案选型的第一步是看懂格式。

## 1. 位宽结构的两个维度：动态范围与精度

任何数值格式都由位宽分配决定两种能力：**动态范围**（能表示多大/多小的数）由指数位决定，**精度**（相邻数的间隔）由尾数位决定。位数从 32 压到 8、4，本质是同时牺牲两者，只是牺牲方式不同：

- FP16（1+5+10）：指数 5 位，范围适中，尾数 10 位——早期训练的默认格式
- BF16（1+8+7）：指数与 FP32 相同，动态范围广，尾数仅 7 位——精度低但不怕溢出，训练主格式
- FP8 双变体：**E4M3**（1+4+3）给权重用，尾数略多；**E5M2**（1+5+2）给 KV Cache 用，范围更大
- INT8/INT4：整数格式，动态范围=0，全靠缩放因子补——**整数量化必须搭配 scale**
- FP4 E2M1（1+2+1）：4 位浮点，本身范围太窄，必须依赖块级缩放

> 💡 一个常见误解：FP8 精度比 INT8 高吗？不是"比"，而是结构不同——FP8 自带指数，天然覆盖大范围数值；INT8 靠每张量一个 scale 归一化到 [-1,1]，遇到异常值直接饱和溢出。两者各有适用场景：FP8 适合激活与权重兼顾，INT8 适合统计量稳定的权重。

### 1.1 量化映射：scale 与 zero-point 的数学

整数格式没有小数表示能力，映射由两个参数完成：

```text
量化：q = round((r - zero_point) / scale)
反量化：r ≈ q × scale + zero_point
```

- **scale**：把浮点范围 [min, max] 压缩到整数网格的步长，由校准统计得到
- **zero-point**：整数网格与浮点零点的对齐，保证浮点 0 量化后仍是 0（卷积填充、padding 语义依赖）
- **对称量化**：zero-point 恒为 0，实现最简单，硬件最友好——W8A8 对称量化是 Tensor Core 原生路径
- **非对称量化**：多一个 zero-point 参数，精度略高但每块多存 2-8 字节，且反量化多一次加法

硬件对对称格式有明显偏好：**几乎所有 Tensor Core/MFMA 指令都只吃对称格式**，非对称量化要拆成两次对称矩阵乘再合并，吞吐减半——这是"硬件约束反过来约束算法设计"的典型例子。

## 2. 从 FP16 到 FP4：主流格式一览

| 格式 | 位宽 | 结构 | 动态范围 | 典型用途 | 硬件原生支持 |
|------|:---:|------|---------|---------|-------------|
| FP16 | 16 | 1+5+10 | 中 | 训练/推理基线 | 全世代 |
| BF16 | 16 | 1+8+7 | 大 | 训练主流 | Ampere 起 |
| FP8 | 8 | E4M3/E5M2 | 大 | 权重/激活/KV | Hopper 起 |
| INT8 | 8 | 有符号整数 | 靠 scale | W8A8 全量化 | Turing 起 |
| INT4 | 4 | 有符号整数 | 靠 scale | W4A16 权重专用 | 任意（CUDA Core 反量化） |
| FP4 | 4 | E2M1 | 极小 | W4A4 全量化 | 仅 Blackwell/AMD CDNA4 |

### 2.1 FP8 的两个变体为什么各司其职

FP8 有 E4M3 与 E5M2 两个官方变体，并非重复：

- **E4M3（1+4+3）**：最大有限值约 448，尾数 3 位——精度高但范围小，适合**权重**（分布相对集中，怕精度损失）
- **E5M2（1+5+2）**：最大有限值约 57344，尾数仅 2 位——范围大但精度低，适合**KV Cache 与梯度**（注意力分数与梯度分布跨度大，怕溢出不怕粗精度）

实际部署的经验：权重用 E4M3、KV Cache 用 E5M2，各取其长。TensorRT-LLM/vLLM 的 FP8 选项默认即按此分配。这也是"格式选型不是选一个数字位宽，而是为每个张量角色选结构"的第一次体现。

### 2.2 4 位以下为什么必须靠块级缩放：数值论证

FP4 的 E2M1 结构（1 符号 + 2 指数 + 1 尾数）只能表示 0、±1、±2 附近共 6 个离散值——**单靠 FP4 自身，动态范围约 ±6，任何真实权重都塞不下**。解决方案是微缩放：每 32 个值共享一个 8 位指数 E8M0（无符号，仅表示 2 的幂），实际数值 = E2M1 值 × 2^(共享指数)。共享指数按块统计，块内 32 个值通常取自同一层/同一通道组，数值尺度接近——这正是"微缩放"名字的由来：**它把动态范围从每个值转移到每个块，用块内尺度一致性换 2 字节的共享成本**。

## 3. MX 微缩放格式：4 位量化的关键转折

INT4 的问题在 2025-2026 年浮出水面：**它无法进入 FP4 Tensor Core**。Blackwell 的 4 位执行单元吃的是 E2M1 格式的 FP4 载荷，INT4 整数格式与其不兼容（MicroMix 论文明确点出：INT4 kernel 与 FP4 Tensor Core 数据格式冲突，而 INT8 Tensor Core 只能 FP32/INT32 累加）。于是 OCP 组织推出了微缩放（Microscaling）格式族：

- **MXFP4**：每个值 E2M1（1 符号 + 2 指数 + 1 尾数），每 32 个值共享一个 8 位指数（E8M0）作为块级缩放
- **MXFP6 / MXFP8**：同一机制下的 6/8 位变体，组成混合精度选项

MX 格式带来 4 倍内存缩减：70B 模型权重从 BF16 的 ~140 GB 降到 ~35 GB。**硬件加速层面，NVFP4 就是 NVIDIA 对兼容 E2M1 格式的硬件实现**，与 MXFP4 检查点基本互换。

## 4. 格式选型的硬件约束链

格式能否发挥全部价值，取决于三段链路是否都通：

1. **存储端**：权重能否以该格式紧凑存放（决定了省多少 HBM 流量）
2. **执行端**：Tensor Core/MFMA 能否原生吃该格式（决定是否真加速）
3. **反量化端**：scale 能否在片上完成回扩（决定是否 HBM 往返）

以 INT4 为例：存储端 ✅、执行端 ❌（多数 GPU 无 INT4 Tensor Core，只能在 CUDA Core 上反量化成 FP16 再进 Tensor Core）——所以 W4A16 在 A100/H100 上只是"省内存"而非"提吞吐"。FP4 则三段全通但**仅限 Blackwell**。这就是"格式 × 硬件"矩阵的由来：**选格式不是在选精度，是在选哪条硬件链路完整**。

### 4.1 格式生态的演进主线（2022-2026）

- **2022-2023**：INT8 是唯一工业级选项，W8A8（SmoothQuant）与 W4A16（GPTQ/AWQ）双线并行，硬件无新增精度
- **2023-2024**：FP8 随 Hopper 落地，E4M3/E5M2 分工确立，成为训练与推理的过渡标准
- **2025**：MXFP4 规范随 Blackwell 发布走向生产，NVFP4 成为其 NVIDIA 实现；INT4 进入"精度够用但硬件无指令"的尴尬期
- **2026**：MR-GPTQ/MicroMix 把 FP4 精度补到生产可用，混合位宽（MXFP4+MXFP6）成为新主线；AMD CDNA4 同步原生支持

主线规律：**每次硬件解锁新格式，软件生态要用 1-2 年才把精度补到生产级**——硬件先行、算法追赶，选型时不要追最新格式，追"精度已验证的次新格式"。

> 🎯 **核心要点**：格式由位宽分配决定范围与精度；整数格式靠 scale 补范围（对称格式是硬件唯一亲儿子），FP8 双变体各司其职（E4M3 权重/E5M2 KV）；MX 微缩放（E2M1+E8M0 块缩放）解决了 INT4 无法进 FP4 Tensor Core 的兼容性缺口，是 2026 年 4 位量化的核心格式；E2M1 单值范围仅 ±6，块级共享指数是 4 位格式存在的前提。选格式的实质是选"存储-执行-反量化"三段硬件链路是否完整，且要按硬件新指令 1-2 年的精度验证节奏来。
