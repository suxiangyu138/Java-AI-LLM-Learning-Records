## 3. 学习路线推荐

**路线 A：搞懂"量化为什么快"（半天）**
01 → 02 → 07。从带宽瓶颈出发，理解数值格式与权重部署——适合后端工程师判断"量化后延迟能降多少、模型放不放在得下"。

**路线 B：硬件量化能力系统学习（2-3 天，推荐）**
01 → 02 → 03 → 04 → 05。这条线回答"每种精度格式在哪种硬件上能真正加速"：Tensor Core 指令 → NVIDIA 全谱 → 竞品支持。**配合 `GPU 硬件架构/` 与 `内存墙/` 目录阅读**，形成推理硬件底层认知闭环。

**路线 C：生产落地（面向推理工程师/AI 平台）**
路线 B + 06 + 08 + 10。聚焦 KV Cache 量化、混合精度新方法与引擎选型——这是 2026 年 Blackwell/AMD FP4 时代部署的核心命题。

### 三条路线的共同前置知识

无论走哪条路线，都建议先建立三个底层直觉：

1. **算术强度直觉**：decode 的 ~1 FLOP/byte 与 Tensor Core 需要的 ~200 FLOP/byte 之间的巨大落差——这是"量化为什么快"的物理根因
2. **格式-硬件映射直觉**：每种精度格式对应一段硬件链路（存储/执行/反量化三段），链路不全就是"省内存不加速"
3. **收益边界直觉**：量化收益集中在下述场景——decode 主导的交互流量、长上下文（KV 量化）、容量受限的部署形态；计算密集的 prefill 与批量场景收益递减

这三个直觉贯穿全部 11 篇，是阅读时的主线索。

> 💡 与知识库关系：04 模块与 `GPU 硬件架构/05-NVIDIA架构演进` 互补（那里讲架构，这里讲精度指令）；06 模块与 `内存墙/` 深度呼应（内存受限的机制根因）；09 模块衔接 03-AI 大模型层的端侧部署话题。

### 阅读时的三个常见误区

1. **"量化精度越低越好"**：位宽每降一档，精度回归失败的风险非线性上升；2026 年的经验是 FP8 几乎无损、INT4/MXFP4 需按任务验收——不是越低越好，是"低到精度允许的极限"
2. **"支持 = 原生加速"**：框架文档的"支持 FP4"往往包含软件回退路径；判断标准是引擎内核是否走 Tensor Core/MFMA 原生指令（04/05 篇给出判定方法）
3. **"量化只影响推理"**：校准、scale 布局、引擎构建都绑定具体硬件与量化器版本，一套量化制品不是到处能跑——检查点的可移植性边界（07/10 篇）是生产事故的高发区

带着这三个误区读完全书，会比线性读收获更多——每一篇其实都在回答"误区的边界在哪"。

## 4. 核心概念速查

| 概念 | 一句话定义 | 关键事实（2026） |
|------|-----------|---------------------|
| 内存受限推理 | decode 耗时由权重搬运决定，而非计算 | 算术强度约 1 FLOP/byte，饱和 Tensor Core 需 ~200 |
| 量化 | 降低数值位宽压缩模型，换取带宽与容量 | INT8 减半带宽流量，INT4 降至 1/4 |
| FP8 | 8 位浮点，E4M3/E5M2 双变体 | Hopper 起原生支持，<1% 精度损失 |
| INT4 | 4 位整数，W4A16 权重专用 | Turing 起通用，A100/H100 都可用 |
| MXFP4 | 微缩放 4 位：E2M1 + 32 元素共享 E8M0 缩放 | 70B 从 140GB 降到 ~35GB |
| NVFP4 | NVIDIA 的 FP4 硬件实现 | 仅 Blackwell（SM100）Tensor Core 支持 |
| Tensor Core | 矩阵乘专用执行单元 | 反量化须在片上 SRAM 完成，HBM 往返则失效 |
| HBM 带宽 | 显存数据搬运速率 | B200/B300 约 8 TB/s，算力每代 4×、带宽仅 2× |
| KV Cache | 注意力缓存，随序列长度线性增长 | FP8 量化减半流量，128K 上下文可提速 4.5× |
| Roofline | 以算术强度判定计算/内存受限的模型 | 量化把模型推向计算受限区 |
| 组缩放 | 每 N 个权重共享一个 scale | group=128 是精度-带宽甜点，scale 也要过 HBM |
| W4A16 | 4 位权重 + 16 位激活的部署格式 | 旧卡唯一实用 4-bit 方案，吞吐收益 2-3× |
| MFMA | AMD 的矩阵乘指令族 | CDNA4 原生 FP4：`v_mfma_scale_f32_16x16x128_f8f6f4` |
| AMX | Intel 的矩阵扩展指令 | Xeon 量化上限 INT8/BF16 |
| GGUF Q4_K_M | llama.cpp 的 4 位端侧格式 | 占量化下载 70%+，质量保留 96-98% |

> 🎯 **核心要点**：量化提速的全部秘密压缩为一句话——**大模型 decode 是"搬权重"而不是"算权重"，把每个权重从 2 字节压到 0.5 字节，延迟近似线性下降；但前提是硬件有对应的低精度执行单元（Tensor Core/MFMA），否则只省内存不省时间**。
