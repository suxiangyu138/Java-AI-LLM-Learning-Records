# 生产实践与硬件选型决策
> 从"知道原理"到"上线省钱"：按硬件代际选精度、按引擎选实现、按成本结构定方案——附 2026 年避坑清单与面试题。

## 1. 硬件 × 精度的选型决策树

选型第一问永远是你手上/预算里的硬件是什么，而不是业界流行什么：

1. **Blackwell（B200/B300/RTX 5090）**：首选 NVFP4/MXFP4，吞吐是 FP8 的 2 倍；精度敏感任务退 W4A6 混合或 FP8
2. **Hopper（H100/H200）**：FP8 是甜点（原生指令 + 成熟内核）；需要更大容量上 INT4 W4A16（仅省内存）
3. **Ampere/Turing（A100/T4）**：INT8 W8A8 或 INT4 W4A16，两个都无原生 4-bit，定位是容量优先
4. **CPU/端侧**：W8A8-INT8（AMX）或 GGUF Q4_K_M；FP8 不可用
5. **AMD MI355X**：MXFP4/MXFP6 混合；**Intel Gaudi 3**：FP8（INC 路径）

跨硬件约束再强调三条铁律：FP4 引擎必须在真实 Blackwell/MI355X 上构建（TensorRT-LLM 禁止跨代编译）；校准 scale 不跨架构复用；MoE 模型的 FP4 需要引擎特殊开关（vLLM 的 `VLLM_USE_FLASHINFER_MOE_FP4`）。

### 1.1 决策树的三个典型入口场景

- **场景 A：预算只够 A100 级旧卡，要部署 70B**——格式答案唯一：INT4 W4A16（GPTQ/AWQ）。35 GB 单卡装下，接受"省内存不加速"的定位，靠批量化与 KV 量化提吞吐
- **场景 B：持有 Blackwell，MoE 模型（DeepSeek 级 256+ 专家）**——NVFP4/MXFP4 + SGLang/FlashInfer 内核，TP 并行按专家分布实测调优；若精度回归失败，退 W4A6 混合或 FP8
- **场景 C：长上下文为主要卖点（128K+）**——KV 量化优先于权重量化：FP8 KV + INT4 权重组合，序列上限由 KV 体积公式决定

三个场景的共同点：**格式选择永远是"硬件代际 × 模型形态 × 流量特征"三变量函数**，没有全局最优格式。

## 2. 推理引擎选型：内核工程比框架名气重要

| 引擎 | 强项 | 短板 |
|------|------|------|
| TensorRT-LLM | Blackwell FP4 吞吐上限，确定性高 | 引擎构建必须绑定真实硬件，迭代慢 |
| vLLM | 格式全、社区大、集成最广 | MoE FP4 需手动开关，实测常落后专项内核 |
| SGLang/FlashInfer | MoE FP4 内核领先（DeepSeek 256 专家场景） | 生态成熟度低于 vLLM |
| LMDeploy TurboMind | MXFP4 软件支持覆盖 H100/V100 | 无硬件加速，容量优先场景 |

2026 实测提醒：B200 上同一 MoE 模型，FlashInfer 1132 TFLOPS vs vLLM 968 TFLOPS——**选引擎前先用目标模型 + 目标硬件跑基准**，峰值密度只是参考线。

## 3. 成本结构：量化直接改写单价

成本视角的换算逻辑：

- 每百万 token 成本 = 单卡成本 ÷ 吞吐（token/s）÷ 卡数
- FP4 把吞吐翻倍的同时把卡数需求砍半（1T MoE 从 8 卡变 4 卡），成本结构双重改善
- 实测参照（2026-06）：Llama 3.3 70B FP4 在 B300 约 $0.055/百万 token，B200 约 $0.074；GLM-5.2 MXFP4 在 MI355X 约 $0.22 vs B200 $0.30
- 别忘了量化本身的成本：校准数据准备、精度回归、FP4 引擎构建与缓存

### 3.1 成本换算实战：一次"该不该换 FP4"的决策

以 70B 模型、单卡月租金 $3 万（约合每小时 $41）为例：

```text
B200 FP16：约 1200 tok/s → 每百万 token ≈ $41 ÷ 1200 × 1e6 ÷ 3600 ≈ $9.5
B200 FP4：约 5000 tok/s → 每百万 token ≈ $2.3
```

换格式的月节余：按日均 100M token 流量，FP4 每月省约 $2.4 万——**够覆盖量化与引擎工程的全部投入**。而量化工程质量（校准集质量、回归流程）是这笔账的前提：一次精度翻车导致的质量事故成本，可能吞掉数月量化收益。所以生产实践的排序是：**先建量化 CI（校准+回归+制品管理），再上量**。

## 4. 2026 避坑清单

- 别信"支持 FP4"：查是不是原生 Tensor Core 执行，还是软件回退
- 别跨架构复用校准结果：Gaudi 2/3 的 scale 互不通用，NVIDIA 各代同理
- 别在旧卡上期望 FP4 提速：H100 加载 NVFP4 只省显存
- 别忽略 KV Cache：长上下文场景先量化 KV（`--kv-cache-dtype fp8`），再谈权重位宽
- 别把校准当一次性：线上分布漂移要监控量化质量指标
- 别用峰值数字选型：SGLang/vLLM/FlashInfer 的实测差距可达 15%，必须目标模型实测
- MoE 模型的 FP4 内核差异巨大：张量并行 + 专家并行配置要按引擎实测调优

### 4.1 量化质量的线上监控三件套

- **精度代理指标**：线上采样请求跑"参考答案对比"（如关键字段抽取、分类一致性），与 BF16 基线对照，超阈值告警
- **数值健康检查**：激活分布漂移监控（scale 越界比例、饱和率）——分布漂移是量化失效的前兆
- **性能回归**：TPOT/P99 延迟监控，内核版本升级或引擎换版后自动对比——量化收益必须持续验证

监控的意义在于把"量化质量"从发布时的一次性验收，变成运行期的持续保障——分布漂移、引擎升级、校准集老化都会让量化质量随时间衰减。

### 4.2 上线前检查单（Checklist）

- [ ] 目标模型在目标硬件的**原生精度上限**已确认（对照 05 篇速查总表）
- [ ] 校准集与线上流量分布一致，校准管线已接入 CI
- [ ] 精度回归通过：通用基准 + 业务指标 vs BF16 基线
- [ ] 量化器版本 / 引擎版本 / 硬件型号 / scale 布局已写入制品元数据
- [ ] 引擎实测（同模型同硬件）已跑，记录 TPOT/TP99 基线
- [ ] KV Cache 量化已开启（长上下文场景必查）
- [ ] MoE 模型 FP4 开关（`VLLM_USE_FLASHINFER_MOE_FP4` 等）已配置
- [ ] 线上监控三件套（精度代理/数值健康/性能回归）已上线

每项背后都是一次真实的线上事故（跨代编译、校准复用、开关漏配、引擎版本漂移）——检查单不是仪式，是事故清单的浓缩。

## 5. 面试题速答

1. **量化为什么能让模型变快？** Decode 是带宽受限负载，量化降低每权重的字节数（2→0.5），等效带宽翻 4 倍，延迟近似线性下降；前提是反量化在片上完成。
2. **INT4 与 FP4 的区别？** INT4 无原生 Tensor Core 指令（软件反量化），FP4（E2M1/MX 格式）有 Blackwell/MI355X 原生指令；INT4 兼容旧卡，FP4 绑定新硬件。
3. **为什么说 NVFP4 是 Blackwell 专属？** FP4 Tensor Core 是 SM100 新指令，H100 只能软件回退（省内存不加速）。
4. **组缩放为什么不能无限细？** scale 也要过 HBM，group=32/16 时 scale 开销把等效位宽抬回 5-6 位，压缩收益被吃掉。
5. **KV Cache 量化的意义？** KV 随序列长度线性增长且每步重读，长上下文下与权重同量级；FP8 化 KV 减半流量，率失真联合优化（RDKV）可达 4.5× 加速。
6. **选 A100 还是 B200 做量化推理？** 无统一答案：旧卡只有 INT4 软件路径（省内存不加速），Blackwell 才有 FP4 原生加速；且模型实测显示 B200 对部分 MoE 反而优于 B300——按"模型 × 引擎 × 硬件"三维实测决策。
7. **量化上线最容易被忽视的坑？** 三个：反量化被编译器写回 HBM（收益清零）、校准 scale 跨架构复用（精度崩）、FP4 引擎跨代编译（跑不起来）——前两个隐蔽、第三个直接报错。

> 🎯 **核心要点**：选型第一问是硬件代际（Blackwell→NVFP4、Hopper→FP8、旧卡→INT4 容量优先、CPU→W8A8、Gaudi→FP8/INC）；引擎选择要实测（同一 B200 上 MoE FP4 引擎间差 15%）；量化同时改善吞吐与卡数需求，是 2026 年成本减半叙事的核心手段；七条避坑清单覆盖了从跨代编译、校准复用到大模型 FP4 开关的全部高频事故。
