# 权重部署格式：W4A16 与反量化陷阱
> W4A16（4 位权重 + 16 位激活）是 2026 年部署最广的量化形态：几乎任何 CUDA 卡都能跑，但它的硬件效率取决于组缩放粒度与反量化落点。

## 1. 为什么是 W4A16：只压权重，不动激活

LLM 推理中，**权重是固定的，激活是每 token 变化的**。权重可以离线慢慢校准量化，激活却必须在线量化——激活异常值（outlier）远多于权重，全量化（W8A8/W4A4）对激活的伤害大、且需要专用指令配合。W4A16 的取舍：

- 权重以 INT4 存储与搬运（省 4× 带宽、4× 容量）
- 激活保持 FP16/BF16，不做量化
- 计算时在片上把 INT4 反量化为 FP16，矩阵乘全程 FP16

这使 W4A16 在**只支持 INT4 软件路径的旧卡（Turing 到 Hopper）上成为唯一实用的 4-bit 方案**：无需 INT4 Tensor Core、无需激活量化校准，接入成本最低。GPTQ 与 AWQ 是两大代表：GPTQ 用二阶误差最小化逐层校准，AWQ 基于激活感知的权重保护，两者精度接近，AWQ 在硬件友好性（无重排、支持离线群缩放）上更优。

### 1.1 GPTQ 与 AWQ：两种哲学，同一部署目标

- **GPTQ**（2022-2023）：基于最优脑量纲（OBS）的逐层二阶误差最小化——量化权重时补偿其对未量化权重的影响，误差在层内重分配。优点：理论最优；缺点：校准计算重（需要 Hession 逆的近似），且量化后的权重**通道顺序被打乱**，部分硬件内核需重排才能高效访问
- **AWQ**（2023）：不重排权重，按激活统计识别"重要通道"（激活幅度大的通道），这些通道保留 FP16 精调 scale，其余通道 INT4。优点：硬件友好（无重排）、离线群缩放、校准成本低；缺点：需要激活数据统计

部署视角的差异比算法视角更关键：**AWQ 的检查点能被更多内核直接消费**（vLLM/TRT-LLM/TensorRT Model Optimizer 对 AWQ 的集成深度远超 GPTQ），2026 年新格式（FP4/MX）的量化器也普遍从 AWQ 的"激活感知"思路继承。选型经验：精度敏感且可接受重排成本选 GPTQ，求兼容性与部署速度选 AWQ。

## 2. 组缩放（Group Scale）：精度的代价藏在内存里

INT4 的动态范围为零，必须靠 scale 归一化。**scale 的粒度决定精度与内存开销的平衡**：

- 张量级（1 个 scale）：内存开销可忽略，但异常值直接溢出，精度崩
- 通道级（per-channel，每输出通道 1 个 scale）：每权重 2/4 字节的 scale 开销，精度大幅改善
- 组级（group=128，每 128 个权重共享 scale）：GPTQ/AWQ 的标准配置，精度与开销的甜点

硬件视角的关键是：**scale 也要过 HBM**。group=128 时 scale 开销约为权重体积的 1/32（4 位值 + 1 个 4 字节 scale ≈ 4.5 位/权重的等效流量），把组缩放到 32 或 16 会让等效位宽涨到 5-6 位——"省下来"的带宽又还回去一部分。所以组缩放粒度不是纯精度问题，是**精度 × 带宽流量的联合优化**。

### 2.1 组缩放粒度的量化账：group 128 vs 32 vs 16

以 7B 模型、INT4 权重为例（约 3.5 GB 压缩值）：

| 组粒度 | scale 数量 | scale 开销 | 等效位宽 | 精度特性 |
|:---:|:---:|:---:|:---:|------|
| group=128 | ~3.5G/128 | ~110 MB | ~4.25 位 | 生产标准（GPTQ/AWQ 默认） |
| group=32 | ~3.5G/32 | ~440 MB | ~5 位 | 异常值多的层可局部用 |
| group=16 | ~3.5G/16 | ~880 MB | ~5.5 位 | 精度最高，带宽收益打折 |
| 通道级 | 隐藏维 × 层数 | 数 GB 级 | ~6 位+ | 仅少量敏感层值得 |

两个实践要点：**组粒度不必全局统一**——2026 年的量化器支持按层分配粒度，异常值集中层（如首层、输出投影）用细粒度，其余粗粒度；group=128 是吞吐与精度的默认甜点，**除非精度回归失败，不要整体调细**。

## 3. 反量化陷阱：编译器帮你把收益清零

这是 W4A16 部署中最高频的隐性事故（详见 03 篇第 3 节）：BF16 激活 × INT4 权重类型不匹配时，自动编译器（XLA、部分 PyTorch eager 路径）会做"宽泛的正确"：

```text
INT4 权重 ──反量化──> BF16 权重 ──写回 HBM──> 重新读入 ──> Tensor Core
（带宽成本 4×，量化白做）
```

正确链路必须是内核内熔合：

```text
HBM 只读 INT4 权重（0.5B/权重）──> 片上 SRAM 反量化 ──> 直接进 Tensor Core
（BF16 永不回 HBM）
```

判断一个推理框架是否踩坑，看两点：权重是否以压缩格式进入显存（`nvidia-smi` 里模型显存占用应接近压缩后体积）；反量化是否发生在 kernel 内部（性能实测是否线性于位宽）。

## 4. W4A16 的硬件效率分层

| 硬件代际 | W4A16 定位 | 收益结构 |
|---------|-----------|---------|
| Turing~Ampere | 容量换吞吐 | 4× 容量、带宽流量减半，CUDA Core 反量化有吞吐代价 |
| Hopper | 稳定主力 | 同上，FP8 出现后精度敏感任务转投 W8A8 |
| Blackwell | 过渡方案 | NVFP4 原生指令更快，W4A16 仅用于兼容旧检查点 |

注意一个细节：W4A16 的带宽收益是"权重侧"的完整 4×，但因为反量化在 CUDA Core 执行，其吞吐上限受反量化开销约束——**吞吐提升典型 2-3×，达不到 4×**。这也是框架文档普遍宣称"INT4 提速 2-3 倍"而非 4 倍的原因。

### 4.1 W8A8 与 W4A16 的选型分界

W8A8（权重激活都量化）与 W4A16（只量化权重）不是精度阶梯，而是**两套硬件路径**：

- W8A8 走 INT8 Tensor Core（Turing 起全世代原生），激活量化引入额外校准与异常值治理（SmoothQuant），但吞吐上限高——适合 **prefill 占比高、并发高** 的吞吐型场景
- W4A16 的带宽收益 4×，但吞吐受反量化开销约束（典型 2-3×）——适合 **decode 占比高、延迟敏感** 的交互型场景

生产上的常见组合：**同一模型双检查点**——高并发档用 W8A8 保吞吐，交互档用 W4A16 保延迟，按请求类型路由。这要求量化流水线把两种格式作为同一 CI 的产出物，而非二选一。

## 5. 检查点迁移的硬件现实

W4A16 检查点的最大价值是**可移植性**：INT4 GPTQ/AWQ 检查点在从 T4 到 B300 的任何卡上都能加载（软件路径），格式即接口。而 NVFP4/MXFP4 检查点绑定 Blackwell/MI355X——迁移硬件等于重新量化（TensorRT-LLM 的 FP4 引擎必须在真实 Blackwell 上构建，跨代编译不允许）。部署选型时要先问：**这个检查点要服务几代硬件？** 要长期复用选 INT4/AWQ，要榨干当前硬件选 FP4/MX。

> 🎯 **核心要点**：W4A16 只压权重不碰激活，是旧卡上唯一实用的 4-bit 方案（GPTQ/AWQ 为代表）；组缩放的粒度是精度 × 带宽流量的联合优化（group=128 是甜点，更细粒度会吃掉压缩收益）；反量化必须在 kernel 内熔合完成，编译器自动反量化会写回 HBM 让量化白做；W4A16 吞吐收益典型 2-3× 而非 4×，瓶颈在 CUDA Core 反量化；检查点可移植性 vs 硬件原生性能（INT4 vs NVFP4）是部署选型的第一道分叉。
