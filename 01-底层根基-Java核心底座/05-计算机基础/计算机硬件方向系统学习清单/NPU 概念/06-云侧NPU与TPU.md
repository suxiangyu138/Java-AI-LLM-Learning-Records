# 云侧 NPU 与 TPU：定制加速器的战场
> 云侧是"极致专用"的试验场：Google TPU 把数据流架构推到 42.5 EFLOPS 集群，华为昇腾在受限工艺下量产，寒武纪、AWS、Groq 各占一席——本模块盘点 2026 年云侧格局。

## 1. Google TPU：数据流架构的教科书

TPU 是脉动阵列的工业代表，v7（Ironwood，2026 年 4 月发布）的核心规格：

- **算力**：FP8 4,614 TFLOPS、BF16 2,307 TFLOPS——首代支持 FP8 的 TPU（此前推理 INT8、训练 BF16 分家）
- **存储**：192GB HBM/芯片、7.2Tbps（约 7,380GB/s）带宽，双芯粒（每芯粒 96GB）经裸片间互连（D2D，速度 6 倍于片间 ICI）连接
- **结构**：每芯片 2 个 TensorCore + 4 个第三代 SparseCore——SparseCore 专攻推荐/排序的超大规模稀疏嵌入，并扩展至金融与科学计算（嵌入表可超 TB 级，稀疏单元的内存侧工程决定其吞吐）
- **集群**：单 Pod 9,216 芯片、42.5 EFLOPS（El Capitan 超算的 24 倍），3D 网格拓扑 + Pathways 架构，并拿下 Anthropic 百万芯片订单

TPU 的设计哲学始终如一：**围绕谷歌自己的负载（Transformer 训练、推荐系统）定制，砍掉一切通用性**——没有通用图形、没有通用计算，只有矩阵与稀疏。它的代价是生态封闭（JAX 优先、PyTorch 靠 XLA 适配），收益是训练成本与效率的极致优化。

一个值得记录的工程细节：Ironwood 的双芯粒在 JAX 里被暴露为两个"设备"（4D 拓扑新增一维）——软件与硬件的协同设计深入到"设备视图"层面。这与 NVIDIA 的双晶粒（封装成统一黑盒设备）形成哲学差异：Google 把"两颗芯粒"交给框架做显式并行，NVIDIA 把双 die 藏在硬件抽象后面。两种做法各有代价：前者给编译器更多自由度、后者给开发者更低的迁移成本。

## 2. 华为昇腾：受限工艺下的全栈量产

昇腾是国产云侧主力：**910C 已量产出货**——7nm 制程、96GB HBM2e、约 800 TFLOPS FP16，训练 + 推理双用；910B 一代的架构在 `GPU 硬件架构/09` 有详述（达芬奇架构、Cube/Vector/Scalar 三单元）。昇腾的意义不在单卡规格（与 TPU/GPU 有代差），而在**全栈闭环**：昇腾芯片 + CANN 算子库 + MindSpore 框架 + 昇腾云服务，配合国产大模型（DeepSeek 等）适配，形成"数据不出境"的替代方案。2026 年寒武纪首次盈利、海光深算成为国产训练集群选择之一——国产阵营已从"能不能用"进入"规模化可用"阶段，但 7nm 制程与 HBM 供应仍是天花板。

## 3. AWS Trainium 与云厂商自研潮

AWS 的 Trainium2 是云厂商自研的代表：以 30-40% 的成本优势（相对同等性能 GPU）吸引客户，与 Nitro 系统深度集成。自研潮的逻辑很直白：**大云厂商的 AI 算力账单已大到"自研芯片的固定成本 < GPU 溢价"**——Google（TPU）、AWS（Trainium/Inferentia）、Microsoft（Maia）、Meta（MTIA）全部入局。它们共同面对的问题是"软件栈追赶"：自研芯片必须支持 PyTorch 生态，否则省下的硬件成本会被工程师时间吃光——AWS 的 Neuron SDK 与 Google 的 XLA 都在赌"生态兼容换成本优势"。隐形成本还有人才结构：芯片团队、编译器团队、运行时团队三线并行（AWS 的 Annapurna Labs、Google 的 TPU 团队均为千人级投入）——这个进入壁垒解释了为什么自研潮只发生在头部云厂商，二三线云厂商连"跟随"的资格都没有。

## 4. Groq LPU 与推理新物种

Groq 的 LPU（Language Processing Unit）是 2026 年推理市场的"新物种"：无 HBM 的 SRAM-only 设计（全部数据驻留片上）、软件编译器决定数据流（全静态调度）、推理吞吐与低延迟惊人——走的是"彻底放弃灵活性、为推理实时性定制"的路线。它印证了 02 篇的哲学：**专用性的每一步都在换效率**，LPU 是"极端专用"的推理版本。局限同样明显：大模型权重放不进 SRAM（70B 需要 288GB 级容量，LPU 无解），只能服务中小模型或配合分片。

## 5. 推理专用芯片的完整名单

云侧推理 NPU 的名单比训练更长：AWS Inferentia（推理专用，Trainium 的推理版）、Google Edge TPU（边缘）、百度昆仑芯（自研推理/训练两用）、阿里平头哥含光（主攻推理）、Groq LPU（SRAM-only）、Cerebras WSE（晶圆级，2026 年主攻推理市场）。它们的共性是**为"推理成本"而战**：推理的算力需求远低于训练（一次预训练 ≈ 几百万次推理），但单位成本极度敏感——专用芯片把"训练不需要的灵活性"全部砍掉，换 2-4 倍的成本优势。2026 年的新趋势是**推理芯片训练化**：随着 MoE 与长上下文推理的算力密度上升，纯推理卡开始支持 FP8 训练（TPU v7 首代 FP8 支持即为信号）——训练与推理的芯片分界在模糊，与 07 篇的"融合"判断同向。

云侧部署的现实形态是**混合池**：大厂推理集群普遍为"GPU + NPU 混合池"——调度器按负载特性路由：请求式交互（延迟敏感）走 GPU，批量异步（吞吐优先）走 NPU。混合池的利用率与成本比单一 GPU 池高 30-50%，是 2026 年云厂商降本的核心手段之一；这也意味着云侧选型的问题不再是"选 GPU 还是选 NPU"，而是"池子里各放多少"。

## 6. 云侧格局的底层逻辑

把云侧各家放回同一坐标系：**训练被 GPU（NVIDIA 垄断）与 TPU（Google 自用）瓜分，推理是开放战场**——GPU（高灵活低成本部署）、TPU（谷歌生态）、昇腾（国产替代）、Trainium（AWS 自用）、LPU（极端专用）各守一隅。云侧选型的真正变量不是峰值算力，而是：**生态兼容度（PyTorch/JAX 支持）、单位 token 成本、数据合规要求（GDPR/数据出境）、供应稳定性**——昇腾的 800 TFLOPS 与 TPU 的 4,614 TFLOPS 之间的代差，在这些变量面前并不总是决定性的：合规刚需的用户选昇腾，成本敏感的选 Trainium，生态绑定的选 GPU/TPU，各得其所。

> 🎯 **核心要点**：云侧 NPU 的 2026 坐标——TPU v7 Ironwood 用 FP8 与 9,216 卡 Pod 定义训练上限（42.5 EFLOPS）、SparseCore 表明稀疏嵌入仍是商业价值高地；昇腾 910C 在 7nm 与全栈闭环内量产，国产阵营进入规模化阶段；Trainium 代表云厂商自研的经济学逻辑，Groq LPU 证明"极端专用"在推理实时性上的价值；云侧选型的真实变量是生态、成本、合规与供应，而非单卡峰值。
