# 核心架构：MAC 阵列与数据流
> 所有 NPU 的心脏都是乘加单元（MAC）组成的计算阵列——本模块拆解 MAC 阵列的三种组织形态（脉动阵列、向量引擎、统一核），以及决定效率的三种数据流。

## 1. MAC 单元：一切 NPU 的最小积木

乘加运算（C = C + A × B）是神经网络的全部计算本质。MAC 单元是执行这一运算的硬件单元：一个乘法器 + 一个累加器，每个周期算一次乘加。**NPU 的算力 = MAC 数量 × 频率 × 每 MAC 每周期操作数**——华为昇腾 310 集成 2,048 个 MAC 单元，在约 1GHz 下达 16 TOPS（INT8），就是这条公式的实例。

MAC 单元的设计要点在"累加精度"与"面积效率"：累加器用 INT32/FP32 保持精度、乘数用低精度（INT8/INT4/FP8）控制面积——单个 INT8 MAC 面积约 144μm²，而多精度 MX 核要 2,766μm²（约 19 倍），这就是"精度每升一级、面积翻几番"的硬件现实，也决定了厂商对 INT8 主口径的执念。

## 2. 脉动阵列：数据在单元间流动

脉动阵列（systolic array）是 NPU 的代表形态（TPU 一代、昇腾 Cube 单元）：MAC 单元排成规整网格，**数据像血液一样在相邻单元间按节拍传递**——一个方向流入权重、一个方向流入激活，乘积在单元内累加后随阵列流动输出。三个特性：

- **复用最大化**：每个输入数据被阵列中多个 MAC 依次使用——权重/激活从 HBM 加载的次数降到理论下限
- **无寄存器堆中转**：单元间直接数据传递，消除了"读-算-写回"的每步访存，内存访问近零（这正是"脉动"命名的由来）
- **面积规整**：重复单元 + 简单互连，版图与功耗好控制

代价是**灵活性差**：阵列形状（如 128×128）固定，不匹配的矩阵形状会产生填充浪费；稀疏矩阵在普通脉动阵列上效率崩塌（需要专门硬件支持）。所以 2026 年的脉动阵列普遍做成"可重构"——通道级驻留切换、支持多种形状，如昇腾的 Cube 单元与 AMD XDNA 的 2D 阵列。

## 3. 三种数据流：谁驻留、谁流动

数据流（dataflow）决定阵列工作方式，经典三分类：

- **权重驻留（weight-stationary）**：权重矩阵固定驻留在片上 SRAM/阵列，激活流式流过——卷积与推理场景首选，权重复用率高
- **输出驻留（output-stationary）**：累加结果留在单元内，权重与激活都流动——GEMM 场景常用，避免中间累加反复搬运（AMD XDNA 的 GEMM 优化即采用输出驻留 + 双缓冲）
- **数据驻留（data-stationary）**：数据不动、权重轮流被每个单元读取——适合逐元素与低复用流水

实际 NPU 常混合多种数据流：编译器根据算子形状在部署时选择最优组织——**数据流选择是 NPU 编译器的核心决策**，效果差异可达数倍（这也是 08 篇软件栈重要的原因）。

## 4. 向量引擎与统一核：另一条路线

不是所有 NPU 都用脉动阵列：

- **向量引擎**（如 Apple ANE 的架构形态）：宽 SIMD 向量单元处理逐元素与向量运算，配合专用矩阵单元——灵活性高于脉动阵列，更贴合 Transformer 的多算子混合负载
- **统一核**（unified core，如 Intel Xe-Core 思路与 AMD XDNA 的 AI Engine tile）：把矩阵、向量、标量单元集成在一个核内，tile 间用 2D 片上网络连接、显式 DMA 搬运——AMD XDNA2 的 50 TOPS 即由 2D tile 阵列达成，实测 GEMM 效率达峰值 78.7%
- **混合路线**（2026 趋势）：学术界的 T-NPU 把脉动阵列与向量引擎合并进统一核，用共享指数-尾数数据通路支持 INT4/INT8/FP4/FP8——"一个核吃所有精度"是低成本多精度化的方向

2026 年的方向共识：**单一形态不满足所有负载**，Transformer 时代的 NPU 越来越像"迷你 GPU"——多形态阵列 + 编译器调度（详见 07 篇"谁在往谁那边靠"）。

## 5. 稀疏支持：阵列的另一半效率

脉动阵列对稀疏矩阵天然低效（零乘加浪费节拍），硬件侧三条解法：**结构化稀疏**（2:4 等规则稀疏，跳过零块）、**稀疏感知调度**（编译器把非零元素重排，压缩填充空洞）、**稀疏单元**（TPU v7 的 SparseCore 专攻嵌入/推荐场景的超大规模稀疏表）。2026 年稀疏的价值分化明显：权重稀疏需要训练补偿、收益不干净，而 MoE 与嵌入表是天然稀疏——SparseCore 出现在 TPU v7 里，说明"推荐系统负载"仍在云侧有巨大商业价值。一个值得注意的结构信号：TPU v7 用 4 个 SparseCore 配 2 个 TensorCore——稀疏单元占芯片面积的三分之二，反映的是谷歌营收里嵌入/推荐负载的权重，远高于舆论对 Transformer 的关注度。

## 6. 从阵列到芯片：NPU 的宏观结构

把 MAC 阵列放回整颗 NPU 芯片里看：典型 NPU 由四部分组成——**计算阵列**（MAC 阵列 + 向量引擎）、**片上 SRAM 组**（权重/激活分区）、**DMA 引擎**（与片外内存的搬运通道，双缓冲流水）、**控制单元**（执行编译器生成的指令序列，驱动阵列与 DMA 协同）。开源验证案例 nanoNPU（2026 年 Silicon Sprint 流片）展示了最小形态：8×8 MAC 阵列 + 自定义 32 位 ISA + UART-APB 主机接口，130nm 工艺上验证了胸部 X 光肺炎检测——**架构思想与旗舰完全同构，差的只是规模**。昇腾 310 则把 2,048 个 MAC 组织成 Cube 单元集群，配合 Vector/Scalar 单元与 L1 Buffer，达 16 TOPS INT8——同样的四件套，规模放大 128 倍。这个宏观视角的用处：读任何 NPU 规格书时，先找"阵列-存储-DMA-控制"四件套的位置与规模，芯片的强弱已可预估大半；再看数据流选择（03 篇）与精度支持（02 篇），即可拼出完整画像。

> 🎯 **核心要点**：NPU 算力 = MAC 数 × 频率，累加高精度、乘数低精度是面积效率的关键；脉动阵列用"数据在单元间流动"消灭访存，三种数据流（权重/输出/数据驻留）由编译器按算子形状选择；芯片层面由"阵列-存储-DMA-控制"四件套构成，从 nanoNPU 的 8×8 到昇腾的 2,048 MAC 同构缩放；2026 年脉动阵列、向量引擎、统一核三条路线走向融合，T-NPU 类"一核多精度"与 TPU SparseCore 的稀疏专攻代表两个新方向——架构的演进方向始终是"更贴负载、更省搬运"。
