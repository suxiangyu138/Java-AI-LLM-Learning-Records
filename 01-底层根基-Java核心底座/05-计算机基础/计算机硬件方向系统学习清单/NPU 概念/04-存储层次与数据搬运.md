# 存储层次与数据搬运
> NPU 的效率一半在阵列，另一半在"数据怎么到达阵列"——片上 SRAM 分层、DMA 搬运与内存带宽，共同决定 NPU 的真实吞吐。

## 1. 片上 SRAM：NPU 的"主内存"

与 GPU 把 L2/HBM 当缓存、靠命中率吃饭不同，NPU 把片上 SRAM 当作**规划性主内存**：部署时编译器就确定每层权重放哪、激活放哪、何时搬入搬出。典型容量：端侧 NPU 数百 KB 到 2MB，云侧（TPU v7）为芯片级缓存层次。片上 SRAM 的三个优势是 NPU 效率的物理基础：

- **带宽**：SRAM 读带宽是片外 DRAM 的 10 倍以上——矩阵运算需要"每 FLOP 配字节"，片上带宽才能喂饱 MAC 阵列
- **能耗**：片上访问能耗比片外低一个数量级（片外引脚驱动是能耗大户）
- **确定性**：编译器规划后的访问模式完全可预测，无需缓存命中率的概率博弈

## 2. 分层与容量预算：编译器的三明治

典型 NPU 存储布局是三明治：**寄存器/累加器（MAC 内）→ 片上 SRAM（每层权重 + 激活双缓冲）→ 片外 DRAM/LPDDR**。容量预算遵循"驻留复用"原则：权重矩阵如果放得进 SRAM（如 230M 模型的一层权重），就整层驻留、反复复用；放不下就分块流式（tiling），块与块之间用 DMA 预取重叠。

2026 年端侧 LLM 的残酷算术：一个 3B 模型 INT8 权重 3GB，片上 SRAM 只有 1-2MB——**权重永远在片外，每层都要从 DRAM 搬一遍**。这就是为什么"内存带宽决定 decode 速度"：decode 阶段每 token 只需一次权重全扫描（约 3GB 读取），带宽直接是吞吐上限——LPDDR5X 的 ~100GB/s 与桌面 GDDR/HBM 的差距，就是端侧 3B vs 云端 70B 的差距根源（与 `内存墙/` 的"推理内存受限"同构）。

## 3. DMA 与搬运引擎：NPU 的血管系统

NPU 没有"load 指令"（静态图不需要），取而代之的是 **DMA 搬运引擎**：编译器把每一层的搬运序列（源地址、目的 SRAM 地址、长度、双缓冲轮换）编译成 DMA 描述符，运行时按序执行。搬运与计算通过**双缓冲流水**重叠：DMA 搬第 N+1 层数据时，阵列算第 N 层——吞吐 = max(计算时间, 搬运时间)。与 GPU 的 TMA 异曲同工（见 `GPU 硬件架构/05`）：**2026 年所有加速器的第一优先都是"搬运与计算重叠"**。

## 4. 统一内存：端侧 NPU 的带宽命脉

端侧 NPU 通常访问**统一内存**（CPU/GPU/NPU 共享的 LPDDR）——好处是零拷贝（模型加载后 CPU 与 NPU 共享同一份权重）、坏处是带宽竞争（CPU 游戏与 NPU 推理抢同一总线）。2026 年的演进主线就是带宽升级：LPDDR5X → LPDDR6，封装内统一内存（如 Apple 的 SoC 级内存、AMD Ryzen AI Max 的 on-package 内存）把带宽推向 GPU 级——这正是业界"7-13B 模型 2026 年底上端侧"预言的硬件前提。

## 5. 云侧对比：HBM 与互连的规模差异

（承接第 4 节的统一内存话题，云侧的"统一内存"问题被拆成两层：芯片内 HBM 与芯片间 ICI——训练时权重驻留 HBM、中间张量在芯片间流动，两层带宽都要规划，这是云侧编译器的内存规划比端侧复杂一个量级的原因。）

云侧 NPU 的存储工程是另一量级：TPU v7 Ironwood 每芯片 192GB HBM、7.2Tbps 带宽（约 7,380GB/s），双芯粒设计通过裸片间互连（速度是片间 ICI 的 6 倍）共享；昇腾 910C 为 96GB HBM2e。数据复用率的量化视角可以统一端侧与云侧：一个 128×128×128 的 GEMM 需要 128×128 权重与 128×128 激活输入（约 64KB INT8），若全部驻留 SRAM，片外流量仅输入输出各一次；若 SRAM 放不下（如大模型单层权重），则每层完整流一遍，片外流量变成"权重体积 × 层数"，相差可达千倍——这就是"片上驻留优先"为什么是 NPU 架构的第一原则，它直接决定片外流量这个数量级。端侧 LLM 的残酷现实是 3B 权重永远放不下（3GB vs 2MB SRAM），因此"压缩权重（量化）+ 精简结构（GQA/MoE）"成为与带宽同样重要的端侧优化轴；统一内存的另一面是 KV Cache 也占同一池子——长上下文（32K+）下 KV Cache 可达 1-2GB，与权重抢带宽抢容量，2026 年端侧 RAG 场景必须做 KV 量化，原因正在于此。云侧的关键差异在于**跨芯片数据流**：训练/超大推理需要数据在芯片间流动（ICI 1.2Tbps），存储层次多了"芯片间"这一层——9,216 卡 Pod 的 42.5 EFLOPS 意味着每张卡都在与相邻卡交换中间张量，互连带宽与存储带宽共同决定集群效率。7,380GB/s 对端侧 LPDDR5X 的 ~100GB/s，是 70 倍量级——这是 70B 模型训练与 3B 模型端侧推理之间最本质的工程鸿沟，也是 `内存墙/`"带宽差两个数量级"在芯片形态上的注脚。

## 6. 带宽瓶颈的工程现实：为什么 decode 快不起来

把公式落到数字：3B 模型 INT8 权重 3GB，decode 每 token 需完整扫描一遍权重 → 每 token 至少 3GB 读取。LPDDR5X 理论 ~100GB/s、实际有效 50-70% → 每 token 约 50-90ms → 仅 11-20 tok/s——这就是端侧 3B 模型的真实天花板，与 TOPS 无关。QHexRT 实测 CPU 在 decode 反胜（250 vs 172 tok/s）的原因也在这里：CPU 的缓存与预取能吸收部分权重读取，而 NPU 的 DMA 序列是静态排定的，对"反复扫描同一权重"模式的优化反而受限。对策三件套：**量化到 INT4**（3GB → 1.5GB，带宽需求减半）、**KV Cache 量化与压缩**（decode 的注意力部分）、**模型结构精简**（GQA 少头、MoE 专家缓存）。2026 年的带宽军备竞赛（LPDDR6、封装内统一内存）正是为打破这个公式而生：带宽翻倍 = decode 翻倍——统一内存的带宽竞争治理（操作系统为 NPU 预留访存比例）也是工程必修课，防止游戏/视频抢占后 AI 任务断崖。把公式翻过来看还能得到一条选型直觉：**同带宽下"权重越小 decode 越快"，INT4 的 3B 与 INT8 的 1B 模型可能跑出相同 tok/s**——端侧选型的优化对象是"带宽 ÷ 权重体积"，而不是模型参数的绝对大小。

> 🎯 **核心要点**：NPU 把片上 SRAM 当主内存、用 DMA 描述符驱动搬运、以双缓冲重叠隐藏片外延迟；端侧 decode 速度 = 内存带宽 ÷ 权重体积——这就是为什么 2026 年 NPU 的瓶颈清单里"内存带宽"排在"TOPS"前面；云侧则在"芯片内 HBM → 芯片间 ICI → 集群网络"三层上做工程，存储与互连共同定义集群的真实算力。
