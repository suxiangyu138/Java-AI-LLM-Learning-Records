# 8086 寻址方式
> 操作数在哪里、怎么找到它——七种寻址方式是把"立即数、寄存器、内存"三类操作数组合起来的语法，也是读懂指令编码与高级语言指针本质的钥匙。

## 1. 寻址方式要解决什么问题

一条指令要工作，必须指明操作数的来源。8086 的操作数只有三种形态：**立即数**（写死在指令里）、**寄存器**（就在 CPU 内部）、**内存**（在 1MB 空间某处）。对内存操作数，指令里装不下 20 位地址，于是设计了一套"用寄存器与偏移组合出有效地址（EA）"的规则——这套规则就是寻址方式。它的本质是：**用 16 位寄存器 + 可选的 16 位位移，在某个段内定位一个存储单元**。

## 2. 七种寻址方式逐一解析

**立即寻址**：操作数直接跟在操作码之后，MOV AX, 1234H。数据取自指令本身，不访问内存；立即数只能作源操作数。

**寄存器寻址**：操作数在寄存器里，MOV AX, BX。指令最短、最快——"能放寄存器就不放内存"由此而来。

**直接寻址**：偏移地址直接写在指令里，MOV AX, [2000H]——EA = 2000H，默认在 DS 段，实际访问物理地址 DS×16+2000H。指令中必须用方括号与立即数区分。

**寄存器间接寻址**：EA = 寄存器内容，MOV AX, [BX]。可用 BX/SI/DI（默认 DS 段）与 BP（默认 SS 段）。一条指令完成"指针解引用"——C 语言里 *p 的读写在汇编中就是一次寄存器间接寻址。

**基址寻址**：EA = BX/BP + 位移，MOV AX, [BX+100H]。适合访问结构体：BX 指向结构体首地址，位移选择字段——C 中 p->field 的字段访问正是这样实现的。

**变址寻址**：EA = SI/DI + 位移，MOV AX, [SI+200H]。与基址寻址在 8086 上效果相同（区别在 80386 的扩展），传统上用于数组元素访问。

**基址变址寻址**：EA = 基址 + 变址 + 位移，MOV AX, [BX+SI+50H]。三种组合（BX/BP 作基址 × SI/DI 作变址），用于二维数组 a[i][j] 的访问——i 放变址寄存器、j 放基址寄存器。

## 3. 默认段规则与段超越

内存操作数默认落在哪个段，由"寻址方式"而非"指令"决定：

- BX/SI/DI 参与的寻址 → 默认 DS 段
- BP/SP 参与的寻址 → 默认 SS 段（栈）
- 串操作的目的 → 固定 ES 段（MOVS/STOS 等）；源默认 DS 段（SI 配合）——使用串指令前必须确认 DS 与 ES 都已装载正确

记住一句话：BX/SI/DI 归 DS，BP/SP 归 SS，串操作目的归 ES。
- 取指令 → 固定 CS 段；栈操作 → 固定 SS 段

这个默认规则可以推翻：在指令前加段超越前缀，如 MOV AX, ES:[BX+SI]——强制从 ES 段取数。段超越前缀是"给指令加修饰"的最早先例，四十多年后 REX 前缀、AVX 前缀都是同一思路的延续。

## 4. 物理地址计算实例

三个实例走一遍合成过程：

- MOV AX, [1234H]，DS=2000H → 物理地址 = 20000H + 1234H = 21234H
- MOV AX, [BX]，DS=3000H，BX=5678H → 35678H
- MOV AX, [BP+10H]，SS=4000H，BP=1000H → 41010H

注意第三条：BP 参与时默认 SS——"栈上的局部变量用 BP 访问"是编译器的标准做法（栈帧的雏形，09 篇 ABI 的祖先）。

还要区分"有效地址 EA"与"物理地址 PA"：EA 是段内偏移（16 位），PA 是段×16+EA 合成后的 20 位结果——两者相差一个"段基址的贡献"。汇编器与 DEBUG 显示的多是逻辑地址（段:偏移），而真正送上地址总线的才是物理地址。

## 5. 与高级语言指针的映射

寻址方式的实用性在"翻译高级语言"时完全显现：

- 数组 a[i] → 变址寻址 [SI+disp]，i 递增 SI
- 结构体 p->field → 基址寻址 [BX+disp]，disp 是字段偏移
- 二维数组 a[i][j] → 基址变址 [BX+SI+disp]
- 链表 p->next → 寄存器间接 [BX]——读 BX 指向的字

一个明显的限制：8086 的基址变址没有比例缩放（无法表达 a[i*4] 的 ×4），数组元素必须手动乘元素大小——这是 80386 引入 SIB 字节（比例变址）的直接动因，也是 08 篇 x86-64 寻址方式的前传。

## 6. 寻址方式的编码：ModRM 字节一瞥

指令中"用哪个寄存器、哪种寻址"由紧随操作码的 **ModRM 字节**编码——mod（2 位）+ reg（3 位）+ rm（3 位）共一个字节：mod 决定位移长度（00 无位移、01 一个字节位移、10 两个字位移、11 表示 rm 是寄存器而非内存）；reg 是寄存器编码（AX=000、CX=001、DX=010、BX=011、SP=100、BP=101、SI=110、DI=111）；rm 是寻址组合编号。例如 MOV AX, [BX+SI+1234H] 的 ModRM 为 mod=10、reg=000（AX）、rm=000（BX+SI），后跟 16 位位移。这个结构回答了"为什么指令长度 1-6 字节不定"——操作数越复杂编码越长；也预示了 08 篇的 REX 前缀：它正是给 reg 与 rm 各补了第 4 位，才把 8 个寄存器扩成 16 个。

## 7. 寻址方式的常见陷阱

- 方括号决定语义：MOV AX, BX 是寄存器传送，MOV AX, [BX] 才是读内存——漏写方括号是最常见的笔误
- BP 默认 SS 段：程序用 [BP] 访问"数据"时若忘记段语义，会读到栈区的意外内容
- 段超越只对当前指令生效：MOV AX, ES:[BX] 之后的下一条指令若仍要访问 ES 段，必须再写一次前缀
- 直接寻址与立即数方向相反：MOV AX, 2000H 是送立即数；MOV AX, [2000H] 才是读内存——一字之差，一个写寄存器、一个读内存
- 进制后缀：立即数默认十进制，十六进制必须写 H 后缀（2000H），漏写后缀会导致数值完全变样

> 🎯 **核心要点**：七种寻址方式不是需要背诵的七条规则，而是同一问题的七个答案——**如何用 16 位寄存器在 64KB 段内定位一个操作数**；默认段规则（BX/SI/DI→DS、BP→SS）与段超越前缀揭示了"寻址是 CPU 硬件行为而非软件约定"；ModRM 字节则暴露了"寻址方式如何被编码进指令"——数组/结构体/指针与寻址方式的逐一对应，正是"汇编让你看见指针本质"这句话的出处。
