# 从 8086 到 x86-64：架构演进路线图
> 四十多年 x86 演进的主线只有两条——把寄存器与地址总线"加宽"、给 CPU 增加"运行模式"；从 16 位到 64 位、从实模式到长模式，这条线就是现代计算机的启动与运行史。

## 1. 演进总览：每一代做了什么

| 型号 | 年份 | 数据/地址宽度 | 核心新特性 |
|------|:---:|------|------|
| 8086 | 1978 | 16 位/20 位（1MB） | x86 起点，分段寻址 |
| 80286 | 1982 | 16 位/24 位（16MB） | 保护模式首次登场 |
| 80386 | 1985 | 32 位/32 位（4GB） | 分页、虚拟 8086、32 位寄存器 |
| 80486 | 1989 | 32 位 | 集成 FPU 与 L1 缓存、流水线化 |
| Pentium | 1993 | 32 位 | 超标量双流水线、分支预测 |
| AMD64 | 2003 | 64 位 | 长模式，兼容 16/32 位 |

每一代都是"加宽 + 加模式"，从来没有重写——这是 x86 与任何 RISC 的最大分野。

## 2. 80286：保护模式的失败首秀

80286 首次引入保护模式：24 位地址、段描述符（基址/限长/属性）、特权级与内存保护。但它有三个致命缺陷：**无法从保护模式切回实模式**（只能复位）、段仍是 16 位（单段 64KB）、保护模式下无法运行海量实模式 DOS 程序——结果 286 的保护模式几乎无人使用，OS/2 在 286 上的失败正是这三条缺陷的直接后果。

## 3. 80386：现代 x86 的真正奠基

80386 把 286 的未竟事业完成，新增的东西塑造了此后所有 x86：**32 位寄存器**（EAX 家族，段内偏移 32 位，单段 4GB）、**分页机制**（4KB 页、两级页表、片内 TLB 缓存 32 项、CR3 指向页目录）、**可切回实模式**、**虚拟 8086 模式**。

保护模式的段机制发生质变：段寄存器不再是"段基址"而是**段选择子**——13 位索引 + TI 位（选 GDT/LDT）+ RPL（请求特权级）；实际基址/限长/属性存在 8 字节的描述符表项里（GDT/LDT）。特权检查围绕 CPL（当前特权级）/DPL（描述符特权级）/RPL 进行，0 级最特权（内核）、3 级最末（用户）——**ring 0/3 的起源**。寻址变成两段式：分段（逻辑地址→线性地址）+ 分页（线性地址→物理地址），分页与分段可以独立开关——现代操作系统的内存保护模型在这里定型。80386 还新增了系统编程必需的寄存器面：**控制寄存器 CR0-CR3**（CR0 的保护允许 PE 与分页允许 PG 位、CR2 记录页故障线性地址、CR3 指向页目录）——现代操作系统切换进程时换页目录、处理缺页时读 CR2 的流程，三十多年来一字未变；**调试寄存器 DR0-DR7** 提供硬件断点（gdb 的硬件断点机制即基于此）。段描述符的 8 字节布局也在此定型：基址 32 位、限长 20 位（配合 G 位粒度 1 字节/4KB）、D 位决定默认操作数宽度 16/32 位——D 位是"一段代码是 16 位还是 32 位程序"的硬件判据，也是兼容模式的开关之一。

## 4. 虚拟 8086 模式

虚拟 8086（V86）解决"保护模式跑不了 DOS 程序"的兼容问题：在保护模式的某个任务里，用与实模式相同的分段规则（段×16+偏移）产生 20 位线性地址，分页仍然生效——一个保护模式操作系统可以同时运行多个 DOS 程序，每个都是"被虚拟化的 8086"。V86 程序运行在特权级 3，V86 监视器运行在特权级 0：程序访问 I/O 端口时由 I/O 许可位图（存于 TSS）决定放行还是陷入监视器模拟。Windows 3.x/95 的 DOS 虚拟机、OS/2 2.x、NTVDM 全部基于此机制。Pentium 增加 VME 扩展（CR4 位 0）降低虚拟化开销；进入 x86-64 长模式后 V86 模式被删除（只在传统模式保留）。

## 5. 80486 与 Pentium：性能时代

486：把 80387 浮点协处理器与 8KB L1 缓存集成进芯片、指令流水线化——"CPU 不再是纯逻辑单元"；Pentium：双整数流水线超标量执行（一个周期可发两条指令）、分支预测、分离的指令/数据缓存；Pentium Pro 引入乱序执行（P6 核心）。1997-2001 年向量化主线登场：MMX（整数 SIMD）→ SSE（浮点 SIMD，新增 XMM 寄存器）→ SSE2（64 位双精度）——x86 的向量能力从这里起步，直接通向 10 篇的 AVX10。

## 6. AMD64：第三方完成 64 位化

64 位化的转折来自 AMD：2000 年 AMD 公布 AMD64 设计，2003 年 Opteron（服务器）与 Athlon 64（桌面）首发——世界上第一个兼容 x86 的 64 位指令集。Intel 的 Itanium（IA-64）因不兼容 x86 而失败，2004 年 Intel 不得不采用 AMD 的扩展并命名 EM64T（后称 Intel 64）。AMD64 的核心设计决策：**长模式 = 64 位模式（新程序）+ 兼容模式（16/32 位程序）**，寄存器扩展到 16 个 64 位（RAX-R15）——向后兼容不是口号而是架构承诺，细节在 08 篇。

## 7. 演进规律的总结

从这条线能提炼三条规律：**兼容性是护城河也是包袱**（每一次加宽都要保留旧的编码语义，于是有了前缀字节、遗留模式）；**模式是虚拟化的源头**（实模式→保护模式→V86→长模式，每一层模式都是对上一层的"托管"）；**厂商竞争推动架构进步**（AMD 完成 64 位化、Intel 联合 AMD 定义 APX——10 篇的主角）。学完这一篇再看现代 x86，看到的不是"寄存器多了几个"，而是"四十六年兼容性约束下的一次次优雅妥协"。

> 🎯 **核心要点**：x86 的演进史可以用一句话压缩——**每一代都在"加宽"（寄存器/地址总线）和"加模式"（实模式→保护模式→虚拟 8086→长模式）之间交替推进，而"向后兼容"是贯穿始终的宪法**；80386 奠定现代内存模型（分段+分页+ring），AMD64 完成 64 位化，V86 模式则是最早的硬件虚拟化——这三个概念是连接"微机原理"与"操作系统"两门课的核心桥梁。
