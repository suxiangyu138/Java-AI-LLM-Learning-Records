# 汇编程序设计：顺序、分支、循环与子程序
> 三种基本结构加子程序，是汇编程序设计的全部骨架——把 if/for/函数翻译成跳转与调用栈的过程，就是理解计算机执行模型的直接途径。

## 1. 程序的三种基本结构

任何程序都能分解为顺序、分支、循环三种结构。高级语言用 if/for/while 表达，汇编里只有一种原语——**跳转**：顺序执行是"不跳"（指令自然递增 IP）；分支是"条件跳"（Jcc 检查标志）；循环是"跳回去"（LOOP 或 Jcc + JMP 组合）。理解这个映射后，读汇编就是在心里把跳转图还原成结构化流程。

## 2. 分支程序设计

if-else 的标准翻译是"条件取反跳转"：

```asm
; if (AX >= 10) 则 BX=1，否则 BX=0
CMP AX, 10
JL  ELSE_BRANCH      ; 条件取反：AX<10 跳走
MOV BX, 1
JMP DONE
ELSE_BRANCH:
MOV BX, 0
DONE:
```

两个要点：**有符号/无符号比较必须选对 Jcc 家族**（AX 是 -1 时 JG 与 JA 结果相反——用错 Jcc 是经典逻辑 bug）；多路分支（switch）用"比较链"（多个 CMP+Jcc）或"跳转表"（表内存目标地址，JMP [table+index*2]）实现——跳转表是查表法在控制流上的应用，也是现代编译器 switch 优化的雏形。

## 3. 循环程序设计

计数循环直接用 LOOP（CX 递减，非零则跳）：

```asm
; 求 1..100 的和
MOV AX, 0
MOV CX, 100
MOV BX, 1
AGAIN: ADD AX, BX
INC BX
LOOP AGAIN
```

条件循环（while 语义）翻译成"条件不满足则跳出"：CMP 条件 + Jcc 跳向循环出口。循环嵌套时内层 CX 必须压栈保存（内层 LOOP 会破坏外层 CX）；循环中提前退出用条件跳转跳出；循环优化三原则：循环不变量外提（不变的表达式挪到循环前）、计数用递减（LOOP 直接支持）、数组访问用变址寄存器递增而非每次重算地址。

## 4. 子程序与调用机制

CALL 把返回地址（CALL 下一条指令的 IP）压栈后转移，RET 弹栈恢复 IP——栈是子程序的运行环境。子程序内部的现场保护有规范：**被用到的寄存器要 PUSH 保存、RET 前 POP 恢复**，特别是 BP——标准写法是进入时 PUSH BP、MOV BP, SP 建立栈帧，退出时 POP BP、RET，这是 09 篇栈帧的直接祖先。保护现场的另一个理由：8086 的 CALL 不自动保存任何寄存器，寄存器由谁用、由谁保存，全靠编程者之间的约定——这就是 ABI（09 篇）最早的形态。嵌套调用与递归完全依赖栈：每次 CALL 压入一层返回地址，递归深度由栈空间决定（栈溢出概念的原型）。注意 8086 递归没有专门支持，全凭栈的自然行为。

## 5. 参数传递的四种方式

子程序与调用方的契约——参数传递有四种方式，各有取舍：

- **寄存器传参**：最快，但寄存器数量有限（约 3-4 个参数）；约定俗成的用法：入口参数 AX/BX/CX，出口参数 AX
- **内存/变量传参**：直接访问全局变量，简单但破坏模块性
- **栈传参**：调用方 PUSH 参数、子程序经 BP 访问、RET n 由子程序清栈——C 语言调用约定的直系祖先（SysV 之前的 cdecl 就是这样）
- **地址表传参**：传参数块首地址（DS:DX 指向参数表），适合参数多或需返回多值

## 6. 常见算法模板

**二进制转十六进制显示**（移位+查表）：

```asm
; AL 中的字节转为两位十六进制显示
MOV CX, 2
MOV BL, AL
HEX_LOOP:
MOV AL, BL
SHR AL, 4          ; 取高 4 位
AND AL, 0FH
CMP AL, 10
JB  IS_DIGIT
ADD AL, 7          ; 'A'-'0'-10
IS_DIGIT:
ADD AL, 30H        ; 转 ASCII
MOV DL, AL
MOV AH, 02H
INT 21H
SHL BL, 4          ; 下一组 4 位
LOOP HEX_LOOP
```

**求最大最小值**：初始化为首元素，循环 CMP+Jcc 更新——注意无符号（JA/JB）与有符号（JG/JL）的选择。**字符串操作**：REP CMPS 比较、REP SCAS 查找、CX 计数+LOOP 遍历——串指令把 03 篇学过的指令家族用在真实算法里。

## 7. 模块化与多文件

较大程序按模块拆分：每个模块一个源文件，用 PUBLIC 导出符号、EXTRN 声明外部符号，链接时合并段。模块化带来两个新问题——**命名冲突**（靠模块名/段名隔离）与**跨模块符号解析**（链接器的工作），这正是现代编译器/链接器模型的原型。8086 时代的段名如 CODE、DATA 在链接时按段合并，规则与 ELF 的 .text/.data 合并逻辑一脉相承（09 篇链接器的前传）。

## 8. 综合实例：递归与栈

递归是栈机制最直观的展示。计算 N! 的递归子程序：每次调用压入返回地址与参数，出口依次弹出——"后进先出"恰好保证最深层的调用最先返回。以 4! 为例：FACT(4) 调 FACT(3) 调 FACT(2) 调 FACT(1)，返回链反向执行。

```asm
; FACT：AX 传入 N，返回 AX=N!（递归版）
FACT  PROC
      CMP AX, 1
      JLE  FACT_END      ; N<=1 返回 1
      PUSH AX            ; 保存 N（栈上参数）
      DEC  AX
      CALL FACT          ; 递归调用 FACT(N-1)
      POP  CX            ; 恢复 N
      MUL  CX            ; AX = FACT(N-1) * N
FACT_END:
      RET
FACT  ENDP
```

注意 MUL 的隐含操作数约定（被乘数在 AX）在这里被自然利用；每层调用约占 8-10 字节栈空间（返回地址 2 字节 + 保存的寄存器与参数），递归深度过大时栈溢出会向低地址蔓延覆盖数据段——与高级语言"栈溢出"的本质完全相同，只是 8086 没有溢出异常来提示你。栈帧的完整形态（返回地址、保存的 BP、局部量、参数）要到 09 篇的 64 位 ABI 才完全定型，但机制从 8086 起就没有变过。

> 🎯 **核心要点**：程序设计篇的全部要义是三个翻译——**if 翻译成"条件取反 + 跳转"、for 翻译成"计数器 + LOOP"、函数翻译成"栈上的调用与参数传递"**；四个层次递进：先写对三种结构，再学会子程序与四种传参，最后用模块化组织大程序——8086 没有"结构化编程语法"，但用跳转和栈实现了全部结构化语义，这正是学习它的价值：没有糖衣，只有机制。
