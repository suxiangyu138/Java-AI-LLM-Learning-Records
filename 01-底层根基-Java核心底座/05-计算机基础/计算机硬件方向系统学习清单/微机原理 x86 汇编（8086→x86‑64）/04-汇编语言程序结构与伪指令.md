# 汇编语言程序结构与伪指令
> 从"会写指令"到"能写程序"，差的是段定义、伪指令与系统调用三件事——这一篇给出 MASM 风格程序的完整组织方式与可调试的最小模板。

## 1. 指令与伪指令的分工

汇编源程序里有两类语句：**指令**（MOV、ADD 等，汇编后生成机器码）与**伪指令**（SEGMENT、DB 等，只告诉汇编器如何组织程序，不生成机器码）。伪指令的存在使汇编语言成为"可描述程序结构"的编程语言，而不仅是机器码的助记符。经典工具链是 Microsoft 的 MASM（宏汇编器，1981 年随 DOS 出现）与 Borland 的 TASM，教材多采用 MASM 语法；现代 NASM（09 篇详述）在段语法上不同，但数据定义、符号、宏的语义一脉相承。

## 2. 段定义与 ASSUME

段是 8086 程序的基本组织单位，用 SEGMENT/ENDS 声明：

```asm
DATA_SEG SEGMENT
    msg DB 'Hello', 0Dh, 0Ah, '$'
DATA_SEG ENDS
```

ASSUME 伪指令声明"哪个段寄存器对应哪个段"：ASSUME CS:CODE_SEG, DS:DATA_SEG, SS:STACK_SEG——它不产生任何机器码，只是告诉汇编器后续指令的默认段解析。段名、ASSUME 与运行时的段寄存器装载（MOV AX, DATA_SEG / MOV DS, AX）三者配合，才能让程序真正访问到数据——ASSUME 管"编译期约定"，MOV DS, AX 管"运行期生效"，两者缺一不可，这是初学者最常见的困惑点。

## 3. 数据定义伪指令

- DB/DW/DD/DQ/DT：定义字节/字/双字/四字/十字节数据，可带初值列表
- DUP：重复，buf DB 100 DUP(0) 定义 100 个零字节——缓冲区声明的标准写法
- $：当前位置计数器，用于计算长度（msg DB 'Hi', '$' 后 LEN EQU $-msg）
- OFFSET 运算符：取标号的段内偏移（MOV DX, OFFSET msg 与 LEA DX, msg 等价）
- 类型修饰：BYTE PTR/WORD PTR——MOV BYTE PTR [BX], 0 必须指明宽度，因为 [BX] 本身不知道自己是字节还是字

## 4. 常量与符号

EQU 定义常量（TEN EQU 10，不可重定义，可定义数值、字符串、标号甚至表达式）；= 也定义常量但可重新赋值（汇编期计数器常用）。ORG 伪指令设定当前偏移（ORG 100H 是 DOS .COM 程序的固定起点）。EQU 与 = 的区别只有一个：EQU 名在其作用域内唯一。

## 5. 完整程序模板

一个最小但完整的"显示字符串"程序：

```asm
DATA   SEGMENT
msg    DB 'Hello, 8086!', 0Dh, 0Ah, '$'
DATA   ENDS

CODE   SEGMENT
       ASSUME CS:CODE, DS:DATA
START: MOV AX, DATA
       MOV DS, AX          ; 装载数据段寄存器
       MOV DX, OFFSET msg  ; 字符串地址
       MOV AH, 09H         ; DOS 显示字符串功能
       INT 21H
       MOV AH, 4CH         ; 返回 DOS
       INT 21H
CODE   ENDS
       END START
```

注意三点：段寄存器的运行期装载、$ 结尾的字符串约定、END 后的 START 指明入口——这三条是 8086 程序的"出厂标配"，缺一个都无法正确运行。

## 6. 系统调用：INT 21H 常用功能

DOS 通过 INT 21H 提供系统服务，功能号放 AH，参数按功能约定：AH=01H 键盘输入单字符（AL 返回）、AH=02H 显示单字符（DL）、AH=09H 显示 $ 结尾字符串（DS:DX 指向）、AH=4CH 程序终止（AL 返回码）。字符 I/O 在实模式下没有更简单的路径——INT 21H 是汇编程序与操作系统之间的第一座桥。BIOS 层还有 INT 10H（显示）、INT 16H（键盘）、INT 13H（磁盘）等服务，构成两层系统调用体系。一个输入回显的最小组合：

```asm
; 键盘输入一个字符并回显
MOV AH, 01H
INT 21H        ; AL = 输入的字符（自带回显）
MOV DL, AL
MOV AH, 02H
INT 21H        ; 显示该字符
```

## 7. DEBUG 调试实践

DEBUG（DOS 自带）是实模式调试的标准工具：R 看/改寄存器与标志、D 查看内存、U 反汇编、A 直接输入汇编指令、T 单步执行、G 运行到断点、E 修改内存。调试流程示例：A 录入 MOV AX, 1234H 等指令 → T 单步 → R 观察标志位变化（T 后 ZF/CF 的翻转是学习标志语义的直观途径）→ D 查看数据段内容验证物理地址计算。一个实用技巧：用 U 命令反汇编自己 A 录入的指令，可以看到实际编码长度——"纸上写的寻址"与"实际编码"由此对上了号。王爽《汇编语言》的全部实验基于 DEBUG——它把"纸面学寻址"变成"肉眼验证"，是 8086 学习不可替代的环节。

## 8. 宏

MACRO/ENDM 定义宏：宏在汇编期被展开为实际指令（不产生调用开销），但代码体积随展开次数膨胀；子程序在运行期调用（体积小，有 CALL/RET 开销）。取舍规则：短小且高频的代码段用宏，长段用子程序。宏还支持参数替换（PRINT MACRO STR），是汇编语言最早的"函数抽象"尝试。

## 9. 常见错误排查清单

- 忘记 ASSUME 或与运行时装载不一致 → 数据访问错位（编译期约定与运行期生效脱节）
- END 后没写入口标号 → 程序从段内偏移 0 开始乱跑
- 字符串不以 $ 结尾却用 AH=09H → 显示超出字符串范围的垃圾内容
- 堆栈段未定义或容量太小 → 嵌套调用/中断时栈溢出，静默破坏相邻段
- 子程序与主程序共用寄存器未保护 → 返回后寄存器值被悄悄改变
- 段内偏移超过 64KB → 访问"溢出"到段外（运行时无提示，最阴险的一类）
- 数据定义类型与指令宽度不符 → 用 BYTE PTR/WORD PTR 显式声明类型

前六条是初学者的高频 bug，每一条都能在 DEBUG 里用 R/D/U 三步定位：R 看寄存器与标志、D 看内存内容、U 看指令流——先把现象缩小到"寄存器、内存、指令"三选一，再顺藤摸瓜。

> 🎯 **核心要点**：汇编程序 = 段（组织） + 伪指令（编译期语义） + 系统调用（与 OS 交互）——SEGMENT/ASSUME 解决"代码和数据放哪、段寄存器怎么认"、DB/EQU 解决"数据怎么定义"、INT 21H 解决"怎么让 DOS 干活"；这一篇建立起的"模板-调试-系统调用"循环，是所有后续程序设计篇的脚手架。
