# x86-64 体系结构深潜
> 长模式把通用寄存器从 8 个扩到 16 个、把地址从 32 位扩到 64 位，并用 REX 前缀优雅地保持向后兼容——这是 2026 年一切主流软件与操作系统运行的地基。

## 1. 长模式与两种子模式

x86-64 的核心是"长模式"（long mode），它内部有两个子模式：**64 位模式**——新程序使用，地址空间 64 位、寄存器 64 位、段的作用被大幅弱化；**兼容模式**——旧的 16/32 位程序不加修改地运行（分段规则与保护模式一致）。长模式之外，实模式与保护模式仍以"传统模式"身份存在（CPU 复位后总是从实模式开始）。由此得到现代 CPU 的启动路径：**复位 → 实模式（BIOS）→ 保护模式（加载系统）→ 开启分页 → 置 EFER.LME 进入长模式**——操作系统引导代码走的正是这条路，理解它等于理解"开机到内核"的全程。

## 2. 寄存器扩展全景

64 位模式下的通用寄存器从 8 个变 16 个、宽度变 64 位：RAX、RBX、RCX、RDX、RSI、RDI、RBP、RSP、R8-R15。命名规则层层兼容：RAX 的低 32 位是 EAX、低 16 位是 AX、低 8 位是 AL；新增寄存器 R8-R15 也支持 8/16/32/64 位部分（R8B/R8W/R8D/R8）。还有一个细节：新 8 位寄存器 SIL/DIL/BPL/SPL 的出现，让编译器能同时使用 RSI/RDI 的高 8 位与低 8 位——寄存器数量翻倍带来的直接收益是减少访存（09 篇 ABI 的参数分配就是基于这套寄存器设计的）。

## 3. 寻址方式的变化

64 位模式寻址有三个关键变化：

- **RIP 相对寻址成为默认**：MOV RAX, [rip+disp32]——操作数地址相对下一条指令计算，范围 ±2GB。这是位置无关代码（PIC/PIE）的基石：库与可执行文件被加载到任何地址都能正确寻址，不需要重定位修复。为什么默认 RIP 相对？因为绝对 64 位地址装不进一条指令，而相对寻址天然与"代码被搬到哪都能跑"的需求吻合
- **比例变址成熟**：[RAX+RCX*8+disp32] 的完整 SIB 编码——元素大小为 2/4/8 的数组访问不再需要手动乘（80386 引入 SIB 的最终形态）
- **16 位寻址消失**：[BX+SI] 这类 16 位地址形式在 64 位模式不可用；立即数方面只有 MOV 支持 64 位立即数，其余指令的立即数按符号扩展 32 位（MOV EAX, 1 比 MOV RAX, 1 短一字节，编译器因此偏爱 32 位写零扩展）

地址空间是 2^64，但处理器只实现低 48 位的规范地址（0 到 2^48-1 与高端负区域）；访问非规范地址触发 #GP 异常——这限制了实际可用地址，也让"64 位能寻址无限内存"的说法需要限定。

## 4. REX 前缀与指令编码

寄存器从 8 个扩到 16 个，编码空间只有 3 位（8 种）——x86 的解法是前缀：**REX 前缀**（0x40-0x4F）有四个位，W（操作数 64 位）、R（ModRM.reg 扩展第 4 位）、X（SIB.index 扩展）、B（ModRM.rm 扩展）。一条 REX 同时干两件事：改操作数宽度（W=1 时是 64 位运算）与扩展寄存器编号。一个随之而来的规则：**64 位模式默认操作数宽度仍是 32 位**——MOV EAX, 1 与 MOV RAX, 1 编码不同，后者多一个 REX.W 字节；这保证了老指令编码在 64 位模式下语义不变（兼容性的具体实现）。REX 前缀与 8086 的段超越前缀、后续的 AVX 前缀（VEX/XOP）一脉相承——**"用前缀修饰指令"是 x86 四十六年不变的编码哲学**。

### 4.1 典型指令的 64 位形态

几个在 64 位模式才完整的指令形态值得单独记忆：**MOVZX/MOVSX**——零扩展/符号扩展传送，是"32 位写零扩展"规则的显式版本；**CDQE/CQO**——把 EAX 符号扩展到 RAX、把 RAX 扩展到 RDX:RAX（64 位版的 CBW/CWD）；**LEA 的算术用途**——LEA RAX, [RAX+RCX*4] 在单条指令内完成"寄存器+寄存器×比例+位移"的纯整数运算，编译器常用它做强度削减（把乘法换成移位与加法）；**MOV 的特殊地位**——唯一的 64 位立即数指令（MOV RAX, imm64），其余指令的立即数一律 32 位符号扩展。记住这些形态，读 gcc -O2 输出时就不会对着 MOVZX/CDQE 发懵。

## 5. 标志与条件转移的延续

RFLAGS 低 32 位与 8086 FLAGS 完全一致（ZF/CF/SF/OF...），条件转移 Jcc 语义原样保留——8086 时代的 CMP+JG 写法在 64 位模式一字不改地工作。64 位模式新增的只与地址计算相关（如地址大小前缀）。这是 x86 兼容性的极佳注脚：**指令语义从未变，变的只是操作数宽度与寄存器编号**。

## 6. x86-64 微架构级别

2020 年 AMD、Intel、Red Hat、SUSE 联合定义了 x86-64 微架构级别（v1-v4，逐级包含）：v1 是原始基线（SSE2 等）；v2 ≈ Nehalem/Bulldozer 世代（SSE4.2、POPCNT）；v3 ≈ Haswell 世代（AVX2、FMA、BMI）；v4 含 AVX-512。级别的意义是"编译目标"：为 v2 编译的程序不会在 v2 以下的 CPU 运行。2026 年的现状：RHEL 9 以 v2 为基线；Anaconda 自 2026-05-01 起 linux-64 新构建要求 v2；MocaccinoOS 2026-08 提供 v3 构建（称 v3 为"甜点"）；v4 因消费级 CPU 长期缺席 AVX-512 而使用受限——直到 10 篇的 AVX10.2 把 512 位带回消费级。

## 7. 与 8086 的精神连续性

把 8086 与 x86-64 并排看：同一个 MOV 家族、同一套 Jcc 语义、同样的前缀哲学、同样的"段+偏移"痕迹（FS/GS 段仍在，用于线程本地存储 TLS 与内核 per-cpu 数据）。学 x86-64 时带着 8086 的底子，看到的不是新架构，而是"同一架构的第六十五个年头"——这正是本体系把 8086 放在前八篇的原因。

> 🎯 **核心要点**：x86-64 的三个关键词——**加宽**（寄存器 8→16、地址 32→64）、**默认化**（RIP 相对寻址、SIB 比例变址成为默认形态）、**前缀兼容**（REX 前缀用"加字节"而非"改语义"的方式完成扩展）；微架构级别 v1-v4 则是编译器与发行版在 2026 年做"最低配置"决策的标准尺。
