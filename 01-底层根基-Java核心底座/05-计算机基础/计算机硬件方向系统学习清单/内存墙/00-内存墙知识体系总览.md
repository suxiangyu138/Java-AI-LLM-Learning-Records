## 3. 学习路线推荐

**路线 A：搞懂"内存为什么慢"（半天）**
01 → 02 → 03。从历史成因到时延阶梯再到分析模型——适合后端工程师理解"为什么程序跑不快的第一嫌疑是内存"。

**路线 B：系统学习（2-3 天，推荐）**
01 → 02 → 03 → 04 → 05。处理器侧与内存侧的双线缓解，形成完整的内存性能认知。**配合 `缓存与Cache/` 目录阅读**，把 04 篇的缓存机制展开到 8 篇的深度。

**路线 C：AI 推理视角（面向推理/性能工程师）**
路线 B + 06 + 07 + 08 + 10。聚焦 2026 年 AI 时代的内存危机与破局（KV Cache、CXL 池化、PIM）——**与 `量化背后硬件约束/` 体系对照阅读**，那套讲"省字节"，这套讲"字节为什么是瓶颈"。

> 💡 与知识库关系：03 篇的 Roofline 与 `量化背后硬件约束/01` 深度呼应；05 篇 HBM 规格与 `GPU 硬件架构/05-NVIDIA架构演进` 互补；06 篇 KV Cache 与 `量化背后硬件约束/06` 共享同一组数字；04 篇缓存机制与 `缓存与Cache/` 全文互补。

### 阅读时的三个常见误区

1. **"内存墙 = 内存慢"**：不准确——内存墙是"计算与内存的速度差"，差的根源在 Dennard 缩放的终结（算力不再等内存），同一块 DRAM 在 1995 年是够用的，2026 年才被甩开。理解成因才能理解对策（01/03 篇）
2. **"加缓存就能解决"**：缓存只解决时延（命中率问题），带宽墙面前缓存无能为力——带宽是硬资源；长上下文场景容量墙连缓存也无解（03/06 篇）
3. **"新技术（HBM/CXL/PIM）会终结内存墙"**：HBM4 论文标题说得很清楚——"HBM4 没有打破内存墙，只是把墙挪远了"。每一代技术把墙推远一点，但模型规模增长（410×/2年）追得更快（05/06 篇）

带着三个误区读完全书，会发现每一篇都在回答同一个问题：**这面墙到底被谁、用什么手段、推远了多少**。

## 4. 核心概念速查

| 概念 | 一句话定义 | 关键事实（2026） |
|------|-----------|---------------------|
| 内存墙 | CPU 速度与内存速度差距逐年拉大，性能被内存拖死 | 1995 年提出，三十年未解决 |
| 时延阶梯 | 层次间访问延迟逐级跳升 | L1 ~1ns → DRAM ~100ns → SSD ~20µs |
| 带宽墙 | 数据搬运速率限制吞吐 | 每级层次带宽约降一个数量级 |
| 容量墙 | 数据装不进离 CPU 近的存储 | KV Cache 70B@128K 可达 ~150GB |
| 算术强度 | 每搬运 1 字节对应的计算量 | decode 仅 ~1 FLOP/byte，需 ~200 才饱和 |
| Roofline | 以算术强度定计算/内存受限 | Ridge Point 之下全是带宽受限 |
| HBM | 堆叠式高带宽内存 | HBM4 单栈 2.0-2.8 TB/s |
| PIM | 存内/近内存计算 | HBM-PIM 声称 2×+ 性能、70%+ 省电 |
| CXL | 内存池化开放协议 | CXL 3.x 机架级池化，4.0 进入商用验证 |
| KV Cache | 注意力缓存，推理第二内存黑洞 | 长上下文下体积超权重 |
| 3C 缺失 | 缓存未命中的三类成因 | 容量/强制/冲突缺失分类治理 |
| NUMA | 非均匀内存访问架构 | 远端内存访问更慢，需线程亲和 |
| STREAM | 带宽测量基准 | 四种流式操作测带宽墙硬度 |
| SOCAMM2 | 高密度 LPDDR5X 内存模块 | 256GB/153.6GB/s，TTFT 改善 2.3× |

> 🎯 **核心要点**：内存墙的全部矛盾压缩为一句话——**算力三十年涨了六万倍，内存带宽只涨了一百倍，而 2026 年 AI 推理恰好把性能压在内存搬砖上**；破局不是单点技术，而是"缓存+预取（隐藏时延）× HBM（加带宽）× 量化（省字节）× CXL/PIM（扩容量/近数据）"的联合阵型。

### 体系速读版（30 秒版）

- **为什么有墙**：Dennard 缩放终结，算力 3×/2年 vs 带宽 1.6×/2年（01 篇）
- **墙长什么样**：时延阶梯 1ns→100ns→20µs，带宽每级降一个数量级（02/03 篇）
- **怎么绕**：处理器藏时延（04）、HBM 加带宽（05）、量化省字节（姊妹体系）、PIM 近数据（07）、CXL 扩容量（08）、软件改布局（09）
- **2026 现状**：训练计算受限、推理内存受限，KV Cache 是最大容量墙（06 篇）
- **怎么决策**：先量化、再分层、后池化，测量闭环（10 篇）
