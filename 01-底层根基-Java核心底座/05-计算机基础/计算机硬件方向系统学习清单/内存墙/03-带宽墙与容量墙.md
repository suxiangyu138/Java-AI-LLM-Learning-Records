# 带宽墙与容量墙：两个独立的约束
> 内存墙不是一堵墙而是两堵：时延墙决定"一次访问多慢"，带宽墙决定"每秒能搬多少"；AI 时代又叠加了第三堵——容量墙。

## 1. 时延墙与带宽墙：概念分离

Wulf & McKee 在 1995 年就指出时延与带宽是不同问题，但实践中常被混淆。两者本质区别：

- **时延（Latency）**：一次访问从发起请求到数据就绪的时间。瓶颈在物理（行激活、电容充放电）。对策是**隐藏**：缓存命中、预取、乱序执行、多线程——让处理器在等待时干别的活
- **带宽（Bandwidth）**：单位时间能搬运的数据量。瓶颈在接口（引脚数、频率、通道数）。对策是**扩大**：更宽的数据通路、更高的频率、更深的流水线

一个直观例子：同样 100ns 时延的 DRAM，DDR4 双通道约 25-35GB/s，HBM3e 约 8TB/s——时延几乎一样，带宽差 200 多倍。**时延墙是"等"，带宽墙是"挤"**，优化手段完全不同。

## 2. 带宽的阶梯式衰减：每级一个数量级

从计算单元往外看，带宽逐级崩塌：

- 片上 SRAM（寄存器堆/L1）：数 TB/s
- HBM（GPU 显存）：8 TB/s（B200/B300 级）
- DDR5（CPU 主存）：50-100 GB/s
- NVMe SSD：3-7 GB/s
- 网络（跨机架）：1-10 GB/s

每降一级约一个数量级，而数据量却逐级膨胀。算术强度（arithmetic intensity）正是衡量"每次搬运对应多少计算"的指标——**低于硬件 Ridge Point（算力÷带宽）的负载，性能完全由带宽决定**。LLM decode 的算术强度约 1 FLOP/byte，而 H100 的 Ridge Point 约 295 FLOP/byte——带宽墙把算力压到理论值的三百分之一。

### 2.1 实测数字：DDR5 的带宽天花板就在眼前

以 2026 年的 CPU 平台为例（Arrow Lake + DDR5），带宽的爬坡与极限清晰可见：

- DDR5-5600（JEDEC 默认）：双通道约 76 GB/s
- DDR5-6000 CL28：约 90 GB/s（+18.5%）
- DDR5-7800 CL36：约 118 GB/s（+30.8%），手动压时序可到 ~122 GB/s

三个量级结论：**CPU 主存带宽的天花板在 ~100 GB/s 级，而 GPU 的 HBM 是 TB/s 级——差 80 倍**；时序（CL）影响时延（109ns→91ns）但几乎不影响带宽；超外频（uncore）超频对带宽几乎无效（+0.37%）但显著降时延（-8.9%）——**再次证明时延与带宽是两套旋钮**。这也是"CPU 跑大模型慢"的底层原因：不是算力，是 DDR 的带宽墙。

## 3. 容量墙：AI 时代的第三堵墙

带宽之外，容量（capacity）在 2026 年成为独立瓶颈：**数据装不进离计算最近的那层内存**。

- 70B 模型 FP16 权重约 140 GB，超过单卡 80GB HBM——要张量并行拆分，跨卡通信成为新开销
- KV Cache 随上下文线性增长：70B 模型 128K 上下文可达约 **150 GB KV 缓存，超过 H100 全部显存**
- 长上下文推理中，KV 体积超过权重体积，容量墙先于带宽墙到来

容量墙的特征是**离散的**：装得下与装不下的分界是悬崖——80GB 装 140GB 模型完全不可运行，不是"慢一点"。容量不足的应对是分级（tiering）：热数据进 HBM、温数据进 CXL 池化内存、冷数据进 NVMe（详见 08 篇）。

### 3.1 容量墙与量化的联动：一套公式两个旋钮

容量墙与量化体系（姊妹篇）用同一套公式联动：**权重体积 = 参数量 × 位宽字节数**。

- 70B 模型：FP16 需 140GB（单卡 80GB 装不下）→ INT4 仅 35GB（单卡装下）——**量化把容量墙推后一个部署档位**
- 1T 参数 MoE：BF16 需整机柜，MXFP4 后 4 卡单节点解决——容量墙直接决定部署形态与成本结构
- KV Cache：FP8 减半、INT4 再减半，配合逐出策略，把"能服务的最大上下文"线性拉长

工程排序建议：**先量化（零硬件成本推容量墙），再分级（CXL/NVMe 按温度扩容），最后才是加 HBM**——成本递增，收益递减，量化永远是容量墙的第一道杠杆。

### 3.2 容量墙的经典案例复盘：为什么"装得下"能改变一切

容量墙的离散性在部署案例中反复验证：

- **70B 模型 INT4（35GB）上单卡 A100 80GB**：装下 → 延迟由带宽决定（可优化）；装不下（FP16 140GB）→ 必须 2 卡张量并行 → 每层 all-reduce 通信成为新瓶颈，性能反而不如单卡 INT4——**量化改变的不只是体积，是部署形态与性能上限**
- **1T MoE MXFP4（4 卡 MI355X）**：从机柜级降到节点级——故障域、运维面、通信拓扑全部简化
- **KV 128K 上下文超显存**：容量墙直接限制"最大可服务上下文长度"——这是产品能力边界，不是性能问题

判断容量墙是否存在的公式：**工作集峰值（权重 + KV 峰值 + 中间激活）≤ 内存容量**——不满足即容量墙，先解容量（量化/分级）再谈带宽（HBM/预取）。这条公式也是容量规划的起点：任何推理服务上线前的第一步，就是把三个分量按峰值并发算出来。

## 4. 用 Roofline 统一分析：一图看穿三堵墙

Roofline 模型把性能画成两段折线：低算术强度段斜率为带宽（带宽墙生效），高算术强度段水平（算力墙生效），转折点为 Ridge Point。三堵墙在图上各有位置：

- 带宽墙：Ridge Point 左侧的斜线——搬得不够快
- 算力墙：Ridge Point 右侧的水平线——算得不够快（多数训练场景）
- 容量墙：不在 Roofline 图内，但决定**负载在图上哪个点**——数据装不进 HBM，就得从 DDR/CXL 搬，算术强度含金量下降

实操价值：**先算算术强度与 Ridge Point 的关系，判断负载卡在哪面墙；再看工作集与内存容量的关系，判断有没有容量墙**——两个判断做完，优化方向自然浮现。

## 5. 测量：STREAM 与指针追逐

- **STREAM**：经典的带宽基准（copy/scale/add/triad 四种流式操作），测"带宽墙有多硬"——注意带宽测量对频率敏感，满载下 L1 带宽可能跌到 0.75×
- **指针追逐（pointer chasing）**：随机链表遍历，测"时延墙有多深"——工作集从 4KB 扫到 128MB，时延阶梯完整呈现
- **sc-membench 等新工具**：补足 bw_mem 的不足，覆盖全层次读写/拷贝带宽与时延

两个基准配合使用，就能在任意机器上把 02 篇的时延阶梯和本篇的带宽墙实测出来——性能优化的第一课永远是测量。

> 🎯 **核心要点**：内存墙分两面——时延墙用"隐藏"（缓存/预取/乱序/多线程），带宽墙用"扩大"（HBM/更宽通路）；带宽逐级衰减约一个数量级，算术强度低于 Ridge Point 的负载（LLM decode 的 1 vs 295 FLOP/byte）性能完全由带宽决定；容量墙是 AI 时代的第三堵墙，装不下的分界是悬崖而非渐变，对策是分级存储；Roofline + STREAM + 指针追逐构成"定位卡在哪面墙"的完整工具箱。
