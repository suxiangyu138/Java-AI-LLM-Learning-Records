# 生产实践与选型决策
> 把前十篇收束成可执行的决策——服务器怎么选、NVMe 怎么配、GPU 互联怎么定、带宽怎么验收；2026 年的核心判断只有一句：Gen5 够用的场景别追 Gen6，需要 1.6T/CXL/KV Cache 外扩的场景别省 Gen6。

## 1. 服务器选型：先算通道账本，再挑型号

PCIe 选型的唯一计算题是通道账本（05 篇）——列出这台机器的全部带宽消费者，加总 lane 需求，对比 CPU 直连通道数：

| 场景 | 典型配置 | 通道预算需求 | 平台建议 |
|------|---------|:---:|---------|
| 通用 Web/后端 | 2×NVMe + 2×网卡(25G) | 4+4 = 8 条 x4/x8 | 单路主流平台足够 |
| 数据库/大数据 | 8-16×NVMe + 2×网卡(100G) | 32-64 + 16 = 48-80 条 | 单路至强/EPYC，优先 CPU 直连 M.2 |
| AI 推理（单卡/双卡） | 1-2×GPU + 4×NVMe + 2×网卡 | 16-32 + 16 + 8 = 40-56 条 | 消费级 Workstation 或单路服务器 |
| AI 训练（8×GPU） | 8×GPU + 4×NVMe + 2×网卡(800G) | 128 + 16 + 32 = 176+ 条 | 双路 128-lane CPU（EPYC 9004+） |

三个选型铁律：

- **GPU 与关键存储必须 CPU 直连**（05 篇），芯片组通道只放低带宽设备
- **2026 年新购 AI 服务器选 "Gen6 Ready"**（EPYC Venice、NVIDIA Vera 等，06 篇时间表）——为 1.6T 网卡、CXL 3.1 内存、Gen6 NVMe 预留，成本差 5% 以内，未来两年不用换主板
- **通道数 > 代数**：128 条 CPU 直连的 Gen5 平台，比 32 条直连的 Gen6 平台能承载更多真实工作负载——先算账，再谈代数

## 2. NVMe 存储选型：代数、容量与通道三分

2026 年 NVMe 的选型决策矩阵：

- **Gen4 x4（~7.9 GB/s 链路上限）**：性价比甜点，数据库/日志/通用负载足够；旗舰 Gen4 盘（7 GB/s）已把链路吃满
- **Gen5 x4（~15.8 GB/s）**：2026 年 AI 集群主流（顺序读 12-14 GB/s）；训练数据读取、checkpoint 落盘显著受益
- **Gen6 x4（~64 GB/s）**：控制器先行（SM8466 宣称 >28 GB/s、700 万 IOPS），**场景是 CMX/KV Cache 外扩**——传统数据库用不上，别为它加钱

三个判断：**盘与插槽代数必须匹配**（Gen5 盘插 Gen4 槽 = Gen4 速度，查 LnkSta 验证）；**容量优先于代数**（KV Cache 卸载要的是容量+带宽，Gen5 盘加 CXL 内存组合比单上 Gen6 盘划算）；**按 0.75-0.85 折算标称**（04 篇），采购单上"14 GB/s"的盘按 11 GB/s 规划业务。

## 3. GPU 互连决策：NVLink、PCIe 与 CXL 的组合

2026 年三类负载的互连答案：

- **单机 NVIDIA 多卡训练/长上下文推理**：NVLink 5.0/6.0 优先（08 篇），PCIe 只做宿主管道（权重加载、数据搬入）；预算受限时层切分管道并行走 PCIe 也成立（Gen5 x8 即可）
- **KV Cache 容量不足**：CXL 内存池化（Gen6 平台 + CXL 3.1 设备）——TTFT 与吞吐双改善（Marvell 实测 4.8× 吞吐、-82.7% TTFT）；NVIDIA CMX 同类方案同样走 PCIe/CXL
- **AMD/Intel 加速器多卡**：UALink 1.0/2.0 硬件 2026-2027 陆续出货，首发用 PCIe/CXL 过渡，规划时预留 UALink 兼容性

预算与性能的最后一层权衡：**单机多卡走 NVLink 的边际收益递减**——两张卡层切分（管道并行）在 Gen5 x8 下已接近无瓶颈，四张卡才显著受益于 NVLink（张量并行全链路通信）；消费级/工作站场景"先加卡、后考虑互连"，服务器场景"互连与卡同时规划"——预算有限时，把 NVLink 的钱花在显存与带宽（CXL）上往往更划算（07 篇 5.1 分层论）。

预算分配的直观公式（一台 8-GPU 推理服务器的带宽预算，07 篇速查表）：**GPU 管道 512-1024 GB/s、NVMe 63 GB/s、网卡 128-256 GB/s、CXL 256 GB/s——总分母是 CPU 的 128-256 条直连通道**，先满足 GPU 与网络，CXL 与存储竞争剩余。

## 4. 验收清单：新机器带宽体检的八项

机器到手后按此清单验收，一次通过率远高于裸测跑分：

1. `lspci -vv` 逐卡核对 **LnkCap == LnkSta**（代数与 lane 全对齐）
2. `nvidia-smi topo -m` 确认 GPU 互连矩阵（NVLink 是否生效、PCIe 是否 x16）
3. fio 顺序读验证 NVMe 实测 vs 标称（差异 >20% 查 MPS/插槽）
4. iperf3 双向验证网卡带宽（800G 卡看是否吃满 Gen5 x16）
5. BIOS 确认 **Max Payload** 与 CPU 支持上限一致（04/09 篇）
6. 中断亲和性检查（/proc/interrupts 是否均匀分布各核）
7. NUMA 验证（numactl --hardware + 关键设备的 node 归属）
8. 虚拟化环境补测：直通 vs SR-IOV 的带宽差异记录归档

## 5. 十大避坑清单

- 把 Gen5 盘插 Gen4 槽然后抱怨"盘不行"（02/09 篇）
- 双卡用户默认 x16+x16——消费级主板通常是 x8+x8（05 篇）
- 把 800G 网卡塞 Gen5 x16 还跑满——已饱和，1.6T 才需要 Gen6（07 篇）
- 用 PCIe 做 GPU 间主力通信还怪框架慢（08 篇）
- 忽略 ASPM 省电模式导致延迟抖动（09 篇红线）
- 芯片组 M.2 插满盘然后抱怨共享瓶颈（05 篇）
- 按标称带宽规划业务（统一打 7.5-8.5 折）
- 追新代数不查平台支持（Gen6 卡插 Gen5 主板 = 自动降级）
- 虚拟化环境不测直通 vs SR-IOV 差异就上线（09 篇红线）
- 不记录基线：每次调优前先测，没有基线的"优化"都是猜（09 篇纪律）
- 忽视 AER 错误日志：链路劣化的早期信号全在 dmesg 里，等"卡顿"出现已是晚期（09 篇 5.2 节）

## 7. 巡检 SOP 与团队规范

带宽问题多为"慢死"而非"急病"，常态化巡检比救火重要。建议每季度一次（或每次硬件变更后）：

**巡检四步**：

1. 链路快照：批量核对全部关键设备的 LnkCap == LnkSta，异动告警（可脚本化：`lspci -vv | grep -A1 LnkCap` 与上次快照 diff）
2. 中断分布：/proc/interrupts 各核负载是否均衡，异常提示驱动或亲和配置漂移
3. 峰值带宽审计：fio/iperf3 基线对比（记录三档：链路协商值、实测峰值、实测持续），降幅 >15% 追查变更
4. 固件登记：BIOS 的 PCIe 策略（代数模式、Max Payload、ASPM）、设备固件版本——**任何 BIOS 改动先记录旧配置再动**（案例一的教训）

**变更纪律三条**：PCIe 相关 BIOS 参数改动走"记录 → 单变量变更 → 复测链路与吞吐 → 回滚预案"；新设备上架前完成本章验收清单；故障复盘固定四段——现象（BDF + LnkSta 快照）→ 变更回溯 → 根因（物理/配置/系统三层定位）→ 固化检查项。

**团队知识沉淀**：把三类高频问题（降速协商、MPS/MRRS、NUMA/中断）写进新人手册与排障 runbook，让带宽问题从"个别专家经验"变成"团队公共知识"——这是比任何工具都值钱的工程资产。

## 8. 常见误区三则

**"跑分低就是硬件不行"**：绝大多数跑分落差是协商、配置、系统三层问题（09 篇案例），先做八项验收再下结论——新硬件被冤枉退货是 2026 年售后工单的常见主题。

**"双链路就是双倍带宽"**：两条 x8 的流量汇聚点（芯片组上行、RC 出口）决定真实上限，链路数 ≠ 带宽倍数；聚合（port bonding）也要看瓶颈在哪一层。

**"用了 NVLink 就不需要 PCIe"**：权重加载、数据管道、checkpoint 回传全部走 PCIe——NVLink 只服务 GPU 间通信，宿主侧永远要 PCIe；两者是加法关系，不是替代关系（08 篇分工）。**"服务器标称 Gen6 就万事大吉"**：电气布线、BIOS 策略、端点代数三方缺一不可，验收清单八项过完才算数——"Ready"是能力声明，LnkSta 才是事实。

### 6.1 面试答题范式

面试官问 PCIe 带宽问题，考察的不是背数字，而是三层能力：**算**（公式与编码效率，02 篇）、**查**（降速协商与 MPS/MRRS 的排查路径，09 篇）、**选**（通道账本与场景判档，05/07 篇）。答题范式：先给公式 → 再给折扣（编码/TLP/系统三层）→ 最后落到场景决策（"先判档位再谈代数"）——三个层次答齐就是满分。高频追问的陷阱是"NVLink 和 PCIe 谁快"：先答分工（08 篇）再答数字（3.6 TB/s vs 256 GB/s），把"谁快"翻译成"谁在什么场景下快"，面试官会高看一眼。

> 🎯 **核心要点**：生产决策的全部逻辑收束为三句话——**先算通道账本再选平台**（GPU 与存储占 CPU 直连、2026 新购选 Gen6 Ready、通道数大于代数）；**按场景选存储代数**（Gen4 甜点、Gen5 主流、Gen6 只给 KV Cache 外扩）；**验收靠八项体检、规划按 0.8 打折、调优永远从 lspci 的 LnkCap/LnkSta 开始**。
