# PCIe 带宽知识体系总览

## 3. 学习路线推荐

**路线 A：搞懂"带宽怎么算"（半天）**
01 → 02 → 04。从定位到公式再到实际折扣——适合后端工程师判断"为什么我的 NVMe 跑不到标称速度"、"为什么双 GPU 不加性能"。

**路线 B：系统学习（2-3 天，推荐）**
01 → 02 → 03 → 04 → 05 → 06。形成"物理-协议-拓扑-演进"的完整认知。**配合 `内存墙/` 体系阅读**，把 04 篇的 DMA 开销与内存时延联系起来。

**路线 C：AI 硬件视角（面向 GPU 部署/性能工程师）**
路线 B + 07 + 08 + 10。聚焦 2026 年 AI 集群里 PCIe 的真实角色：模型加载、KV Cache 外扩、1.6T 网络与 CXL 池化——**与 `GPU 硬件架构/`、`量化背后硬件约束/` 对照阅读**。

> 💡 与知识库关系：02 篇的编码开销与 `内存墙/03` 的算术强度互补；06 篇 HBM 与 `GPU 硬件架构/` 共享同一组数字；07 篇 KV Cache 外扩（CMX）与 `量化背后硬件约束/06` 呼应；08 篇 CXL 与 `内存墙/08` 深度互补——那里讲池化原理，这里讲 PCIe 物理层。

### 阅读时的三个常见误区

1. **"PCIe 带宽 = 显卡插槽的带宽"**：PCIe 是**所有**外设的通用通道——NVMe 硬盘、网卡、GPU、加速卡、CXL 内存设备都走在同一条协议上。理解 PCIe 带宽 = 理解整台机器的数据吞吐上限（01/07 篇）
2. **"标称带宽就是实际带宽"**：从编码开销（Gen1-2 丢 20%）、TLP 包头（小块传输丢 24%+）到芯片组共享、降速协商，实际可用带宽通常只有标称的 60-90%（02/04 篇）
3. **"带宽翻倍就是性能翻倍"**：PCIe 是负载-存储协议，带宽只是其一，时延（几十 ns 级别）、时延一致性、拓扑共享同样决定体验；而 GPU 与 GPU 之间的大流量根本不走 PCIe——那是 NVLink/UALink 的战场（03/08 篇）

带着三个误区读完全书，会发现每一篇都在回答同一个问题：**这条数据高速公路，标称能跑多少、实际能跑多少、谁在抢占它、谁又在绕过它**。

## 4. 核心概念速查

| 概念 | 一句话定义 | 关键事实（2026） |
|------|-----------|---------------------|
| GT/s | 每秒千兆次传输（每次传 1-2 比特） | Gen7 = 128 GT/s，PCIe 8.0 规划 256 GT/s |
| 编码效率 | 数据比特占传输比特的比例 | Gen3+ 为 128b/130b（~98.5%），Gen6+ 为 FLIT（~100%） |
| PAM4 | 四电平调制，一个符号传 2 比特 | Gen6 起启用，眼高损失 ~9.6 dB |
| FLIT | 固定长度流量单元，自带 FEC | RS(242,236)，256B flit，FEC 时延 ~2-6ns |
| Retimer | 中继整形信号的高速芯片 | 128 GT/s 下铜缆距离急剧缩短，retimer 成标配 |
| MPS | 单包最大有效载荷 | 256B 时效率 ~90%，4KB 大块 >99% |
| MRRS | 单次读请求最大长度 | 对读吞吐的影响大于 MPS，RC 常限制 512B |
| LnkSta | 链路实际协商状态 | 降速（如 x16→x8）是带宽杀手，lspci 可查 |
| Bifurcation | 把 x16 拆成多个 x8/x4 | 多 GPU/NVMe 服务器的基础手段 |
| CXL | 基于 PCIe 物理层的缓存/内存协议 | CXL 4.0 基于 Gen7，128 GT/s，多机架池化 |
| NVLink | NVIDIA 专有 GPU 互连 | 第 6 代 3.6 TB/s/GPU（Rubin），14× PCIe Gen6 |
| UALink | 开放加速器互连（无 NVIDIA） | 2.0（2026-04）200 GT/s、In-Network Compute |
| SR-IOV | 单卡虚拟出多虚拟功能 | 云上 GPU/NVMe 共享、多租户隔离的基础 |

## 5. 常见问题速答

**"PCIe 5.0 的盘为什么跑不到标称速度？"** 三层原因按序排查：链路协商降级（lspci 的 LnkCap vs LnkSta，05/09 篇）、MPS/MRRS 配置（BIOS 默认 256B 会把 4KB 大块传输的效率压在 90% 附近，04 篇）、系统开销（IOMMU、中断、NUMA 错位，04/09 篇）。绝大多数"跑不满"是第二三类，第一类在服务器上最常见——**新机器第一件事永远是核对 LnkSta**。

**"为什么 8 张卡插满了，每张都变慢？"** 通道总数是硬预算：CPU 直连 128 条，8 张 x16 GPU 就要 128 条，网卡与 NVMe 就没通道了。服务器靠 bifurcation 拆 lane、靠芯片组分担，消费级主板双卡默认 x8+x8——05 篇的账本告诉你"插得下 ≠ 跑得满"。

**"GPU 之间通信走 PCIe 吗？"** 训练的张量通信不走——走 NVLink（NVIDIA）或 UALink（开放阵营），PCIe 只做宿主管道；消费级无 NVLink 的卡例外，走 PCIe 的层切分（管道并行）对带宽不敏感，08 篇有完整分工。

**"CXL 和 PCIe 是什么关系？"** CXL 跑在 PCIe 物理层上，复用链路与连接器，用内存语义换"可扩展内存"——CXL 4.0 基于 Gen7（128 GT/s），是 PCIe 生态对内存墙的答案（07/08 篇，与 `内存墙/08` 对照读）。

**"2026 年买新服务器该选几代？"** 通用负载 Gen5 足够；AI 集群选 Gen6 Ready 平台（EPYC Venice 等），为 1.6T 网络、CXL 3.1、Gen6 存储预留；Gen7 硬件 2027-2028 才上市，等它没有意义（06 篇时间表）。

**"怎么测量一台机器的 PCIe 实际带宽？"** 分层测量：lspci 看链路协商值（理论上限）、fio/iperf3 测设备级吞吐（协议与配置层）、业务基准看体验——三层数字都对不上才定位得到真正的瓶颈（09 篇四级测量法）。

**"学了这套体系，和内存墙、量化体系什么关系？"** 三者是同一枚硬币的三面：内存墙讲"字节为什么贵"（带宽与容量稀缺），量化讲"怎么少搬字节"（压缩与数值格式），PCIe 讲"字节搬不搬得动"（链路能力）——AI 性能调优在这三面里找答案。

> 🎯 **核心要点**：PCIe 带宽的全部矛盾压缩为一句话——**每三年翻一番的标称速率，被编码、包头、拓扑共享和降速协商层层打折，而 2026 年 AI 时代的数据搬运（权重加载、KV Cache、1.6T 网络、CXL 池化）恰好把压力压在这条通用通道上**；看带宽既要会算（02 篇），更要会查实际协商状态（09 篇），还要知道哪些流量根本不走 PCIe（08 篇）。

### 体系速读版（30 秒版）

- **为什么有它**：PCI 并行总线到顶（133 MB/s 极限），2003 年串行点对点革命（01 篇）
- **怎么算带宽**：速率 GT/s × 通道数 × 编码效率；Gen3 后编码开销仅 1.5%（02 篇）
- **为什么打折扣**：PAM4 信号难（03）、TLP 包头开销（04）、拓扑共享与降速（05/09）
- **2026 现状**：Gen5 主导（约 38% 份额）、Gen6 服务器 H2 2026 落地、Gen7 规范已发布、硬件 2027-2028（06 篇）
- **怎么决策**：先查实际协商链路，再按场景预算（GPU/NVMe/网络/CXL），最后决定是否上专有互联（07/08/10 篇）
