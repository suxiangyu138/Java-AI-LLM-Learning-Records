# 谁需要带宽：GPU、NVMe 与网络的带宽需求图谱
> PCIe 是通用通道，但真正的带宽大客户只有四类：GPU（权重加载与显存交换）、NVMe（存储吞吐）、网卡（800G/1.6T 网络）、CXL（内存扩展）——2026 年 AI 集群的需求排序恰好也是这四类，理解各自的"饱和点"才能正确分 lane。

## 1. GPU：模型加载与显存交换的带宽账

GPU 对 PCIe 的需求分两个层面，带宽逻辑完全不同：

**权重加载与 checkpoint（主存 ↔ 显存）**：这是纯带宽场景。70B 模型 fp16 权重约 140 GB：

- Gen4 x16（32 GB/s 单向）：加载 ~4.4 秒
- Gen5 x16（64 GB/s）：~2.2 秒
- Gen6 x16（128 GB/s）：~1.1 秒

模型越大、换代越频繁，这笔账越难看——**训练集群每次换 checkpoint 都要全量回传权重，8 卡 70B 训练每 N 步 checkpoint 一次，PCIe 速率直接写进训练总时长**。这也是 NVIDIA 把模型加载/checkpoint 列为 Gen6 核心收益的原因。

**训练/推理中的张量通信（GPU ↔ GPU）**：走 NVLink（08 篇），不占 PCIe。但有两类流量必须过 PCIe：**主机-设备数据管道的输入输出**（训练数据搬运、推理结果回传）和 **PCIe 场景下的张量并行**（消费级无 NVLink 时，all-reduce 每 token 多次往返，长上下文时成为硬瓶颈——04 篇的请求/完成往返在 GPU 通信上放大）。llama.cpp 从 2026 年 4 月起的构建已支持真实张量并行并自动检测 NVLink/PCIe 适配。

对模型加载而言还有一层 nuance：**加载与推理是串行关系**（加载期间 GPU 空闲），所以加载快慢直接进"冷启动耗时"，是推理服务的 SLA 指标；而 checkpoint 的写入与训练并行，PCIe 带宽不足会把训练"暂停等保存"——训练集群的 Gen6 升级收益往往先体现在这里，而不是训练本身的张量通信。

2026 年的具体需求：推理服务器 GPU 插 Gen5 x16 即可（权重加载 + 输出回传够用）；训练集群 GPU 插 Gen6 x16 值得（checkpoint 与数据管道翻倍）；**显存外扩（CMX 等 CXL 内存）按 Gen6 起步**——NVIDIA 的 CMX（Context Memory eXtension）把 KV Cache 搬到 PCIe/CXL 内存，128 GB/s 级的 Gen6 链路是吞吐前提。

## 2. NVMe：Gen5 x4 与 Gen6 存储的饱和点

NVMe SSD 的带宽需求完全由"盘自身顺序吞吐"决定，链路是天花板：

| 盘代 | 链路 | 链路上限（x4 单向） | 2026 旗舰盘实测 |
|:---:|:---:|:---:|:---:|
| Gen4 | Gen4 x4 | ~7.9 GB/s | 顺序读 7-7.5 GB/s（已饱和） |
| Gen5 | Gen5 x4 | ~15.8 GB/s | 顺序读 12-14 GB/s（接近饱和） |
| Gen6 | Gen6 x4 | ~64 GB/s | 控制器先于盘：SM8466 宣称 >28 GB/s 顺序读 |

三个关键判断：

- **Gen5 x4 链路喂旗舰 Gen5 盘已接近上限**（12-14 vs 15.75），盘体 NAND 层还有余量，但链路先到头——Gen6 x4 的 64 GB/s 是给"下一档盘"准备的
- **Gen6 控制器已先行**：Silicon Motion SM8466（2026）支持 Gen6 x4、顺序超 28 GB/s、随机 IOPS 超 700 万，直指 NVIDIA CMX 与 KV Cache 外扩场景——**存储的 Gen6 需求来自 AI 推理的 KV Cache 卸载，不是传统数据库**
- **数量对比**：一个 Gen6 x4 的吞吐 ≈ 8 块 2021 年初的 Gen3 盘——**通道与功耗的双重节省是数据中心拥抱 Gen6 存储的经济学理由**

对后端工程师的决策：2026 年新购服务器存储选 Gen5 x4 盘（性价比甜点）；计划上 CMX/KV Cache 外扩的推理集群选 Gen6 Ready 平台 + Gen6 控制器盘。

## 3. 网卡：800G 与 1.6T 的精确换算

网卡是"最抠门"的带宽用户——它必须精确算好链路账，因为网卡带宽是实数：

```text
800G 网卡（双向 800 Gbps 全双工）：需要 PCIe 单向 ≥ 100 GB/s
  Gen5 x16（~64 GB/s）→ 已到极限（实际 800G 网卡在 Gen5 x16 上接近饱和）
  Gen6 x16（~128 GB/s）→ 从容
1.6T 网卡：需要单向 ≥ 200 GB/s → 只有 Gen6 x16（~128 GB/s 单向）+ 双 x16 或 Gen7 才行
```

结论即 2026 年 Gen6 落地的硬理由之一：**800G NIC 已经把 Gen5 x16 用满，1.6T NIC 必须 Gen6**。AI 集群里网卡和 GPU 抢 CPU 直连通道（05 篇账本），于是出现专门的路由：网卡用 x16 占满一个 CPU 的通道预算，GPU 走 NVLink，存储走 CXL/Gen6——通道分配的本质是"谁的数据量最大谁拿最多"。

## 4. CXL：内存扩展把 PCIe 通道变成"第二条内存总线"

CXL（Compute Express Link）复用 PCIe 物理层跑内存语义，是 2026 年 PCIe 带宽需求的最大增量：

- **CXL 3.1（Gen6 物理层）**：服务器 2026-2027 支持，单设备带宽同 Gen6 x16（128 GB/s 单向）——比 DDR5 双通道（~100 GB/s）还宽
- **CXL 4.0（2025-11 发布，基于 Gen7）**：128 GT/s，支持 x2 原生宽度、端口捆绑、4 级 retimer 多机架池化，商用 2026-2027 验证
- **实际需求量级**：Marvell Structera S 30260（2026-03 发布，260-lane CXL 3.0 交换器，聚合带宽 4 TB/s）为 8-GPU 服务器池化 16TB 内存，声称推理吞吐 4.8×、TTFT 降低 82.7%——**KV Cache 卸载到 CXL 池化内存是 2026 年最热的推理架构**（与 `内存墙/08` 篇呼应）

CXL 的带宽消耗形态与 GPU/NVMe 不同：它是"长时间持续占用"（KV Cache 每 token 读写），而 NVMe 是突发型——**CXL 设备的 lane 分配要按持续吞吐算，不能按峰值算**，否则共享链路上出现"隐性带宽饥饿"。

### 4.1 2026 带宽预算速查表（一台典型 8-GPU 推理服务器）

| 组件 | 数量 | 单链路 | 合计单向 | 说明 |
|------|:---:|:---:|:---:|------|
| GPU（模型加载/数据管道） | 8 | Gen5/6 x16 | 512-1024 GB/s | 训练内网走 NVLink |
| NVMe（KV Cache 落盘） | 4 | Gen5 x4 | ~63 GB/s | Gen6 控制器就绪 |
| 网卡（800G） | 2 | Gen5/6 x16 | 128-256 GB/s | 1.6T 时代必须 Gen6 |
| CXL 内存（KV Cache 卸载） | 2 | Gen6 x16 | 256 GB/s | 持续占用型 |
| **CPU 直连通道总预算** | — | — | **128-256 条** | 双路 CPU 的硬上限 |

## 5. 场景优先：带宽敏感度分级

并不是所有负载都需要"更多带宽"——按敏感度分四档，每档的规划逻辑完全不同：

**第一档：持续大流量型（最敏感）**。训练数据管道（GPU 直读 NVMe）、KV Cache 读写（CXL 内存）、800G/1.6T 网络转发。特征：链路长期占用、吞吐直接写进业务指标——**按链路 80% 占用率规划**，代数升级收益立竿见影。

**第二档：突发大流量型（次敏感）**。模型加载与 checkpoint（权重一次性全量过 PCIe）、冷数据恢复。特征：几分钟打满、平时闲置——**峰值带宽决定恢复时长**（70B 加载 Gen4 4.4s vs Gen6 1.1s），看峰值不看持续。

**第三档：随机小 IO 型（对带宽钝感）**。数据库事务、元数据操作、4K 随机读写。特征：带宽占用 <5%，瓶颈在 IOPS 与时延——**升级代数无收益**，优化队列深度与设备 FTL 才有效（04 篇），选 Gen4/Gen5 中端盘即可。

**第四档：时延敏感型（对带宽几乎无感）**。RDMA 尾时延、金融高频、同步屏障。特征：带宽闲置、时延抖动致命——关注点是 ASPM 关闭、中断合并参数、NUMA 对齐（09 篇红线），带宽预算与它无关。

规划口诀：**先判档位再谈代数**——预算花在"第一二档"的代际升级上，三四档的钱省下来换容量与稳定性，这才是带宽预算的正确分配。

### 5.1 分层存储与 KV Cache 的带宽分层

2026 年 AI 集群的存储是分层的，每一层对 PCIe 带宽的诉求不同：热层（GPU 侧 HBM，不占 PCIe）、温层（KV Cache：CXL 内存或 Gen6 NVMe，持续占用型）、冷层（训练数据集/权重：Gen5 NVMe，突发型）。KV Cache 落 CXL 的意义在于它"持续占用"的特性——若落 NVMe，Gen5 x4 的 12-14 GB/s 会成为推理吞吐的硬地板，而 CXL 128 GB/s 级链路才是"每个 token 都读写的缓存"的合格通道。**判断存储代际需求先问"数据多久被访问一次"**：每秒访问（KV Cache）→ 高带宽持续型；每几分钟访问（checkpoint）→ 突发型；每几小时访问（数据集）→ 容量优先。

### 5.2 时延敏感设备的带宽账单

第四档时延敏感负载并非完全不占带宽——它们只是"不占平均带宽"，但每次传输的**瞬时占用**与峰值要求一样苛刻：RDMA 的一个 2MB 突发要在几十 µs 内完成，瞬时带宽需求接近链路上限。因此时延敏感设备的选型规则是"平均带宽 ×10 起配"：平均 1 GB/s 的负载，链路按 10 GB/s 级预留，否则突发时排队——这就是为什么金融/高频服务器宁可用 x8 网卡也不用 x1，宁可 Gen5 也不省 Gen4。**带宽规划看两个数字：平均与峰值，缺一不可**。

> 🎯 **核心要点**：2026 年 PCIe 带宽的四张大单——GPU（权重加载按代数线性提速、张量通信走 NVLink 不占 PCIe）、NVMe（Gen5 x4 链路已近饱和、Gen6 存储为 KV Cache 外扩而生）、网卡（800G 吃满 Gen5 x16、1.6T 必须 Gen6）、CXL（内存池化把 PCIe 通道变成第二条内存总线，持续占用型）；通道分配的本质是"谁的数据量大谁拿最多"，而预算的总分母是 CPU 引脚数。
