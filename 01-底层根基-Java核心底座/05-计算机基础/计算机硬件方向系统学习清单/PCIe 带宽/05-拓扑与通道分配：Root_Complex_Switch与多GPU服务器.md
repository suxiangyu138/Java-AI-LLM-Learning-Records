# 拓扑与通道分配：Root Complex、Switch 与多 GPU 服务器
> 带宽的第三道折扣来自拓扑：PCIe 是树形结构，CPU 引脚预算（通道总数）是硬上限——8 张 GPU 怎么分 128 条 lane、NVMe 与网卡怎么抢通道，决定了这台机器真实的数据吞吐能力，而这些全写在主板的"通道分配账本"里。

## 1. 拓扑三要素：RC、Switch 与 Endpoint

PCIe 的物理拓扑是一棵树，三个角色：

- **Root Complex（根复杂体，RC）**：树的根，通常集成在 CPU 内。所有 PCIe 流量在 RC 汇聚，再通过内部互联（Intel 的 mesh/ring、AMD 的 Infinity Fabric）进入内存控制器或 CPU 核心。RC 拥有全部出口带宽的最终分配权
- **Switch（交换器）**：树的分支节点。把 1 个上游端口扩展成 2-32 个下游端口，每个下游端口独立 x1-x16。Switch 是"通道分配"的物理载体——服务器主板上插满设备的插槽，多数挂在 PCH（芯片组）内部的 Switch 上，而 PCH 到 CPU 的上行只有固定的 x4-x8
- **Endpoint（端点）**：树叶。GPU、NVMe、网卡等设备本体

流量规则：**所有跨端点的通信都要经过 RC**（除非启用 Peer-to-Peer，见第 4 节）。因此端点到端点的带宽 = 两条 PCIe 链路的瓶颈——这也是"GPU 走 PCIe 通信 = 绕远路"的拓扑根源（08 篇 NVLink 的存在理由）。

### 1.1 CPU 直连 vs 芯片组：两种通道，天壤之别

主板上的插槽通道分两类，带宽性质完全不同：

- **CPU 直连通道（直连 CPU）**：CPU 原生 PCIe 通道，全带宽、低时延，直达内存控制器。显卡插槽、部分 NVMe/M.2、服务器网卡走这里
- **芯片组通道（PCH/芯片组）**：先挂到芯片组内部的 Switch，再从芯片组 x4 上行回到 CPU。**所有芯片组通道共享那一条 x4 上行**——这就是"插满 M.2 后速度全部减半"的经典现象

2026 年主流平台的事实：

- Intel Z890/X870E：显卡 16+ 条 CPU 直连，M.2 通常 1-2 条 CPU 直连（x4）、其余挂芯片组
- 消费级 CPU 直连通道总量：Intel 主流平台 ~20 条（16 显卡 + 4 存储）、AMD 主流 ~24-28 条
- 服务器（EPYC 9004/9005、Xeon Scalable）：每颗 CPU 64-128 条（EPYC 9004 达 128 条），8-GPU 服务器标配双路，GPU 走 CPU 直连

**选型铁律：GPU 与关键存储必须占 CPU 直连通道；芯片组通道只放低带宽设备（低速网卡、声卡、扩展卡）**。判断方法：看主板说明书"插槽通道来源"图，或 09 篇的 lspci 逆向推导。

## 2. Bifurcation：把 x16 拆开分的艺术

CPU 直连通道有限（128 条要养 8 张 GPU + 4 块 NVMe），而 PCIe 允许一条物理插槽拆成多条逻辑链路——**bifurcation（分叉）**：x16 插槽可拆为 x8+x8、x8+x4+x4、x4×4 等组合，由 BIOS 配置。

多 GPU 服务器的标准账本（8×GPU + 4×NVMe + 2×网卡）：

```text
双路 CPU 各 128 条 CPU 直连通道（共 256 条，2026 服务器典型）
├── 8 × GPU：8 × x16 = 128 条
├── 4 × NVMe（系统盘+缓存盘）：4 × x4 = 16 条
├── 2 × 网卡（800G）：2 × x16 = 32 条
└── 剩余 ~80 条：CXL 内存设备 / 扩展 / 预留
```

通道账本决定了"插得下插不下"：**8-GPU 服务器对 CPU 通道数的需求是 200+ 条，2027 年 Gen6 时代通道数反而可能成为比核数更稀缺的资源**。消费级双卡用户也吃同样的亏：两张显卡插 x16 插槽，BIOS 默认拆成 x8+x8——每张卡带宽减半（这就是 04 篇"双卡不翻倍"的拓扑原因）。

## 3. 链路训练与降速协商：x16 为什么变成 x8

PCIe 每次上电都要链路训练（LTSSM）：两端协商"代数 + 通道数"的最大公约数。任何一端能力不足、物理接触不良、插槽供电不够，链路就降级——**降速协商是带宽消失的头号日常杀手**：

- **Gen 降级**：Gen5 设备插 Gen4 插槽 → 按 Gen4 跑，带宽减半。Gen6 CPU 配 Gen5 端点同理
- **Lane 降级**：x16 插槽接触不良或插了 x8 转接卡 → 按 x8 跑，带宽再减半
- **组合降级**：Gen5 x16 → Gen4 x8，带宽剩 1/4

诊断入口就是 `lspci -vv` 的 LnkCap/LnkSta 两行（09 篇详述）。工程要点：**降速协商是静默的**——系统正常启动、设备正常识别，只是慢一半。带宽优化第一步永远是查协商状态，而不是换设备。

## 4. 拓扑的暗流：Peer-to-Peer、NUMA 与虚拟化

三条进阶规则决定"标称拓扑"之外的真实行为：

**Peer-to-Peer（P2P）**：默认路径是 A→RC→B（绕 CPU），而支持 P2P 的系统允许 A→Switch→B 直通，带宽翻倍、时延减半。NVMe-to-GPU 拷贝（训练数据直读）、GPU-to-GPU（走 PCIe 时）受益最大。代价：需要 IOMMU 开启 + 驱动显式支持（Linux 的 vfio-pci 场景常用）。2026 年 AI 服务器的"数据不进 CPU"趋势（GPU 直读 NVMe）把 P2P 推成标配。

**NUMA（非均匀内存访问）**：多路平台里，PCIe 设备挂在哪颗 CPU，DMA 就落到哪颗 CPU 的本地内存最近。设备插在 CPU0 的通道上却让 CPU1 的核处理它 → 跨 socket 访问，带宽掉 1-2 倍。**中断亲和性 + 设备通道位置 + 内存分配必须三合一对齐**——这是 09 篇"NUMA 错位"诊断的背景。

**SR-IOV 与虚拟化**：一张物理卡虚拟出多个 Virtual Function（VF），每个 VF 独立 DMA 通道、独立中断、独立队列，宿主与虚拟机共享同一物理链路。云上 GPU 直通（vfio-pci）、NVMe 多租户、SmartNIC 分流全依赖它。代价是 IOMMU 强制开启（每笔 DMA 翻译）——虚拟化环境按"实际可达带宽 0.7"规划不踩坑。

## 5. 从枚举到地址空间：PCIe 世界的"户口本"

带宽之外，理解 PCIe 拓扑还差一块拼图：地址空间与枚举。

**枚举（Enumerate）**：上电后 RC 给每个设备分配总线号、设备号、功能号（BDF），配置空间（256B，扩展 4KB）记录设备身份、能力与 BAR 大小。Linux 下 `lspci` 显示的 01:00.0 就是 BDF——**报问题先报 BDF，比"那块 NVMe"精确得多**。

**BAR（基地址寄存器）**：每个功能声明需要映射的地址窗口（寄存器、MMIO 缓冲、门铃页），RC 把它们放进系统地址空间。设备可见窗口受 BAR 大小限制——GPU 的 BAR 动辄 16-32GB（显存映射），这决定了设备"能直接看到的地址范围"，也是 SR-IOV 直通（vfio-pci）时必须处理大 BAR 的原因。

**门铃（Doorbell）**：软件往设备的门铃寄存器写一个值，通知设备"队列有新命令"——这是 PCIe 软件路径的心脏：一次写操作完成"投递 + 通知"两件事。高性能驱动（io_uring、SPDK）合并门铃写、把队列放主存，本质都在优化这条"软件到设备"的最小通路。

三者的带宽含义：**地址空间决定设备能 DMA 到哪，BAR 大小决定一次映射多大，门铃效率决定软件能多快地发起传输**——带宽是这三者乘以链路速率的结果，缺一环都跑不满。

### 5.1 消费级主板拓扑拆解：一张图的教训

2026 年典型游戏主板的通道账本：CPU 直连 x16 显卡插槽 + 1 条 M.2（x4）+ 芯片组挂 2-3 条 M.2、网卡、声卡、USB 扩展卡，芯片组上行 x4。教训一：**第二块 M.2 与显卡抢通道的场景不存在（显卡直连、M.2 走芯片组），但两块芯片组 M.2 互相抢 x4 上行**——双盘 RAID 性能会被上行锁死；教训二：BIOS 开启 bifurcation 后 x16 可拆 x8+x8 给双卡，代价是每卡带宽减半（04 篇"双卡不翻倍"的根）。**买主板先看说明书通道图，再谈其他参数**。

### 5.2 地址窗口与 DMA 映射

设备发起的 DMA 需要软件先建立映射：虚拟地址 → 物理地址 → 设备可见地址（IOMMU 翻译后）。映射建立的代价（页表操作、TLB 缺失）是 DMA 延迟的一部分——io_uring 的固定缓冲（registered buffers）与 RDMA 的 Memory Region 提前注册，本质都是"把映射成本移出热路径"。**DMA 映射是 PCIe 性能工程的隐藏层**：映射建一次、复用万次（大块连续传输），是效率 99% 的基石；每笔重建映射（小块随机），映射开销与传输时间同量级——这解释了 04 篇"小块传输效率低"的另一半原因（另一半是 TLP 包头）。

对时延敏感设备还有一层：映射建立本身也占时延（页表遍历），所以 vfio-pci 直通里的预注册大内存、RDMA 的 Memory Region 池化，都是"映射工程"——**DMA 映射做得好不好，直接决定设备能多快开始传输**。

> 🎯 **核心要点**：PCIe 是树形拓扑，跨设备流量必经 RC；CPU 直连通道与芯片组通道是两种带宽（后者共享 x4 上行）；bifurcation 把 x16 拆给多设备，多 GPU 服务器的通道账本是选型第一计算题；降速协商（Gen/lane）静默减半带宽，诊断永远先看 LnkSta；P2P、NUMA 对齐、SR-IOV 是 2026 年 AI 服务器拓扑的三条暗流规则。
