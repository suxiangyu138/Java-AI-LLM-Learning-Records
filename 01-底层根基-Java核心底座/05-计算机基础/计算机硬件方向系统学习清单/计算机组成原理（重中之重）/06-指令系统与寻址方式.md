# 06 指令系统与寻址方式

## 1. 指令的构成

一条指令 = 操作码（做什么）+ 操作数地址（对谁做）+ 寻址方式（怎么找操作数）：

```text
指令 = [操作码 OP | 地址码 A（可多个）| 寻址特征]
例：ADD R1, [1000]  → 把内存 1000 号的内容加到 R1
```

指令系统设计要回答三个问题：**要哪些操作**（数据传送/算术/逻辑/转移/IO）、**操作数放哪**（寄存器/内存/立即数）、**如何编码**（长度/格式）。零地址（栈机）、一地址（累加器机）、二/三地址（通用寄存器机）是格式演化的主线——现代 RISC 用三地址格式（两个源 + 一个目的寄存器）。

## 2. 指令格式设计

| 格式 | 特点 | 代表 |
|---|---|---|
| 定长指令 | 长度固定，译码简单、取指流水友好 | RISC（32 位固定） |
| 变长指令 | 长度可变，指令密度高但译码复杂 | x86（1-15 字节） |
| 扩展操作码 | 操作码长度随地址数变化 | 早期教学机/嵌入式 |

定长 vs 变长是 RISC/CISC 之争在格式层面的投影：**定长换译码简单与流水线友好，变长换代码密度**。x86 的变长指令是它流水线前端（译码）复杂化的根源——现代 x86 CPU 内部把 x86 指令翻译成微操作（µop），用 RISC 内核执行 CISC 指令，这是"格式之争"在工程上的折中答案。

## 3. 七种寻址方式

| 寻址 | 操作数来源 | 用途 |
|---|---|---|
| 立即数 | 指令自身携带 | 常量 |
| 直接 | 地址字段即主存地址 | 简单全局变量 |
| 寄存器 | 寄存器号 | 最快，算术运算主力 |
| 寄存器间接 | 寄存器内容作地址 | 指针/链表 |
| 基址 | 基址寄存器 + 偏移 | 数组/重定位（段基址） |
| 变址 | 基址 + 变址寄存器 | 数组遍历（自动增量） |
| 相对 | PC + 偏移 | 分支跳转（位置无关代码） |

寻址方式的本质是"**用不同的地址合成规则，覆盖不同的数据结构访问模式**"。两个高频考点：基址寻址用于程序重定位（操作系统加载程序时改基址不改指令）、相对寻址使代码位置无关（PIC，动态库的基础）——每条寻址方式都能映射到一种软件需求，这是理解记忆的锚点。

## 4. RISC vs CISC

| 维度 | RISC | CISC |
|---|---|---|
| 指令 | 少而规整 | 多而复杂 |
| 格式 | 定长 32 位 | 变长 |
| 寻址 | 少量简单寻址 | 大量复杂寻址 |
| 访存 | 只有 load/store 访存 | 运算可直接访存 |
| 执行 | 流水线友好 | 需微程序/翻译 |
| 代表 | ARM、RISC-V | x86 |

RISC 的哲学：**把复杂的组合留给编译器，把简单的指令做快**——load/store 架构（运算只对寄存器，访存只有两条指令）让流水线干净、频率更高。2026 年格局：ARM 在移动与服务器（Apple Silicon、Grace）攻城略地，RISC-V 开源指令集在嵌入式/边缘崛起，x86 靠"翻译层"维持兼容与性能。**RISC-V 的意义是 ISA 开源**——历史上第一次主流指令集不由单一厂商控制。

## 5. 指令周期

一条指令从取指到执行完毕的完整周期：

```text
取指周期 IF：按 PC 取指令 → PC+1
译码周期 ID：解析操作码与寻址方式，取寄存器
执行周期 EX：ALU 运算/地址计算
访存周期 MEM：load/store 访问内存
写回周期 WB：结果写回寄存器
```

| 周期 | 各指令是否都经历 | 说明 |
|---|---|---|
| IF/ID | 是 | 每条指令必经 |
| EX | 大部分 | load/store 是"算地址" |
| MEM | 仅 load/store | 算术指令无访存 |
| WB | 大多数 | store 无写回 |

五周期模型是 07 篇数据通路与 08 篇流水线的骨架——**流水线就是把五个周期重叠执行**。理解指令周期 = 理解 CPU 执行模型的最小单位，后续全部章节都建立在它之上。

### 5.1 ISA 与编译器的分工演化

RISC 哲学（把复杂组合留给编译器）在 2026 年的深化是编译器与硬件的更深协作：编译器负责指令调度（重排避冒险，08 篇的编译重排）、寄存器分配（ISA 的寄存器数决定压力）、向量化（把循环转成 SIMD 指令）；硬件负责乱序执行与推测（掩盖编译器的保守）。JIT 是这条分工的 Java 形态：C2/Graal 编译器在运行时做机器码优化（内联、向量化、消除检查）——JVM 字节码是"半成品 ISA"，JIT 是"运行时编译器"。理解 ISA 与编译器的分工，就理解了 JVM 的"编译期优化 + 运行期优化"设计为什么存在。

补充一个工程联想：**变长编码的"密度 vs 复杂度"权衡在数据序列化中反复出现**——JVM 字节码是变长（紧凑）、RISC-V 指令是定长（简单），Thrift/Protobuf 的 varint 同样在"省字节"与"解码复杂度"间权衡；理解指令格式的取舍，等于理解一切编码格式设计的通用逻辑。

## 6. 常见误区速排

| 误区 | 事实 |
|---|---|
| "x86 是纯 CISC" | 现代 x86 内部翻译成 µop，RISC 内核执行 |
| "RISC 一定比 CISC 快" | 快在流水线与频率，代价是代码密度与兼容性 |
| "寻址方式背七种即可" | 每种寻址对应一种数据结构访问模式，理解映射 |
| "RISC-V 是又一个 ARM" | 它是开源 ISA，打破指令集厂商垄断，意义不同 |

## 7. 本模块小结


> 🎯 **核心要点**：指令系统 = 操作码 + 操作数 + 寻址（七种寻址对应七种数据结构访问模式）；定长/变长格式之争是 RISC/CISC 的投影，x86 用 µop 翻译折中；RISC 哲学是"把组合留给编译器、把简单做快"，2026 年 RISC-V 开源 ISA 改变格局。指令五周期（IF/ID/EX/MEM/WB）是数据通路与流水线的共同骨架。Java 视角：JVM 字节码是"面向机器的机器码"，栈式 vs 寄存器式指令集对比是理解 JVM 解释执行与 JIT 的入口。
