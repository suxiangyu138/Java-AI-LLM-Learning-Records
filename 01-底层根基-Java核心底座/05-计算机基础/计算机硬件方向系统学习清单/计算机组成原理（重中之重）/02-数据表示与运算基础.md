## 1. 数值编码：原反补移

| 编码 | 定义 | 特点 |
|---|---|---|
| 原码 | 符号位 + 绝对值 | 直观；加减法需判符号，零有 ±0 |
| 反码 | 负数 = 原码按位取反 | 中间产物；零有 ±0 |
| 补码 | 负数 = 反码 + 1 | **加减统一**；零唯一；范围不对称（-2ⁿ ~ 2ⁿ-1） |
| 移码 | 补码符号位取反 | 用于浮点阶码，比较大小直观 |

补码是硬件选择的必然：它把减法变成加法（A-B = A+(-B) 补码相加），让 ALU 只需要加法器——"用硬件复杂度换逻辑简单性"的经典案例。补码的范围不对称（8 位 -128 ~ 127）是高频考点：`-128` 的原码/反码不存在，只有补码。

## 2. 定点运算与溢出检测

定点加减的关键是溢出检测，三种方法：

1. **符号位判断**：正+正=负 或 负+负=正 → 溢出（最常用）。
2. **最高位进位判断**：符号位进位 C₁ 与最高数值位进位 C₂ 异或为 1 → 溢出。
3. **双符号位**：变形补码 00 正、11 负、01/10 溢出——硬件中最直接的实现。

```text
例：7+6（4 位补码）0111+0110=1101=-3？→ 正+正得负 → 溢出 ✅
```

定点乘法（Booth 算法）与除法（恢复余数/不恢复余数）是考点但 2026 年硬件已把乘除做成单周期/多周期部件——理解"乘除靠移位与加法迭代"即可，细节在 03 篇的 ALU 实现中展开。

## 3. IEEE 754 浮点

浮点的核心思想是**用指数把小数点的位置"浮动"起来**，覆盖极大与极小的数值范围：

```text
单精度（32 位）：1 符号 + 8 阶码（移码，偏置 127）+ 23 尾数
双精度（64 位）：1 符号 + 11 阶码（偏置 1023）+ 52 尾数
规格化数：尾数最高位恒为 1（隐含，不占位）→ 实际精度 24/53 位
```

| 阶码特殊值 | 含义 |
|---|---|
| 全 0 阶码 + 尾数 0 | ±0 |
| 全 0 阶码 + 尾数非 0 | 非规格化数（次正规数，下溢渐近） |
| 全 1 阶码 + 尾数 0 | ±∞ |
| 全 1 阶码 + 尾数非 0 | NaN（非数） |

非规格化数的意义常被忽略：它让下溢**渐近到零**而不是突然归零，保证了浮点运算的连续性——这是 IEEE 754 相对早期标准的重大改进。

## 4. 浮点运算与精度

浮点运算三步：**对阶（小阶向大阶看齐）→ 尾数运算 → 规格化**（含舍入）。三个经典坑：

1. **精度损失**：0.1 在二进制下是无限循环小数——`0.1+0.2 ≠ 0.3` 的根因，Java 里用 BigDecimal 的原因。
2. **大数吃小数**：`1e16 + 1 == 1e16`（尾数位数不够），对阶时小数的低位被吃掉。
3. **舍入模式**：默认"就近舍入（偶数）"，金融计算需显式控制。

2026 年硬件视角：FP16/BF16/FP8 等低精度浮点因 AI 训练/推理兴起——BF16 用与 FP32 相同的指数范围换取更少尾数位（训练稳定），FP8 用于推理加速（H100 原生支持）。IEEE 754 是"精度完备"的基准，低精度格式是"按需裁剪"的工程选择。

## 5. 数据宽度与类型演化

| 时代 | 数据宽度 | 说明 |
|---|---|---|
| 8 位机 | 8 bit | 早期微型机 |
| 32 位 | 4 字节 | 32 位 ISA 统治 20 年 |
| 64 位 | 8 字节 | 2000s 至今主流，地址空间 2⁶⁴ |
| 向量宽度 | 128-512 bit（AVX-512） | SIMD 并行数据通道 |

数据宽度的两个演进逻辑：**寻址空间驱动**（内存变大需要更宽地址）与**计算密度驱动**（SIMD 一次算更多数据）。Java 后端的实际影响：long/double 原子性（64 位在 32 位 JVM 需加锁）、Unsafe 内存操作、JOL 对象布局——数据表示是 Java 面试"对象头/伪共享"考点的硬件源头。

### 5.1 数据表示的现代战场

数据表示在 2026 年的主战场是 AI 数值格式：FP32 训练精度充足但太贵，BF16 用指数共享保证训练稳定（与 FP32 相同范围，不溢出不下溢），FP8（E4M3/E5M2）把推理算力密度翻倍，INT8/INT4 量化进一步压缩显存与带宽。选型的核心权衡是"动态范围 vs 精度"：指数位决定范围（防止溢出），尾数位决定精度（防止误差累积）——这完全是 IEEE 754 设计哲学（阶码移码 + 隐含位）在低精度时代的延伸。理解 IEEE 754 的人看 AI 数值格式一眼就能看懂，这就是经典知识的前沿价值。

一个常被忽略的实践点：补码与浮点的表示规则直接决定**序列化与解析的正确性**——网络协议里的大小端、Java 的 `Float.floatToRawIntBits`、数据库的数值精度，全部是"数据表示"在工程层的投影。表示选错（如金额用 double），后果在金融场景是事故级。

### 5.2 表示与容错

数据表示的最后一个视角是容错：补码让溢出可检测（溢出标志是"算错了"的信号）、IEEE 754 用无穷与 NaN 让异常可传播（而不是静默出错）、校验位/ECC 在存储与传输层兜底。工业级系统的设计顺序是"表示正确 → 运算可检错 → 异常可传播 → 错误可恢复"——Java 的数值溢出检查（Math.addExact）、金融的 BigDecimal、数据库的校验和，全部是这条链上的工程落点。

## 6. 常见误区速排

| 误区 | 事实 |
|---|---|
| "浮点就是小数" | 浮点是"有限精度近似"，0.1 二进制是无限循环 |
| "溢出 = 进位" | 溢出是符号错乱（双符号位/进位异或检测），进位≠溢出 |
| "FP16 是 IEEE 754 子集" | BF16/FP8 是工程裁剪，指数/尾数分布与 754 不同 |
| "补码范围对称" | 8 位是 -128~127，负数多一个（-128 无原码） |

## 7. 本模块小结


> 🎯 **核心要点**：补码统一加减（ALU 只要加法器）、变形补码最直接检测溢出、IEEE 754 用移码阶码 + 隐含位规格化、非规格化数保证下溢渐近。三个高频坑：0.1 二进制无限循环、大数吃小数、舍入模式。2026 锚点：BF16/FP8 低精度格式随 AI 兴起，是 IEEE 754 之上的"按需裁剪"。数据宽度演进 = 寻址需求 + 计算密度双驱动，64 位与 SIMD 是当前基线。
