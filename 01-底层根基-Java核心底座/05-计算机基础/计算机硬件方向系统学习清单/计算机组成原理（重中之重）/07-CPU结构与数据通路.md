## 1. CPU 的基本结构

CPU = 数据通路（datapath）+ 控制器（control）：

```text
数据通路：寄存器堆、ALU、多路选择器、总线——数据流动的"路"
控制器：译码指令 → 产生控制信号 → 指挥数据通路的"大脑"
```

| 部件 | 职责 | 实现 |
|---|---|---|
| 寄存器堆 | 32-128 个通用寄存器，双口读写 | SRAM 阵列 |
| ALU | 算术逻辑运算 | 03 篇的加法器/逻辑单元 |
| PC | 程序计数器，指向下一条指令 | 寄存器 + 加法器 |
| 指令存储器 | 取指（现代为 L1 指令 Cache） | SRAM |
| 控制单元 | 操作码 → 控制信号 | 组合逻辑/微程序存储器 |

两条硬性结构规律：**数据通路决定"能做什么"**（没有某个元件，相应指令就无法执行）、**控制信号决定"这次做什么"**（同一通路，不同信号组合执行不同指令）——理解 CPU 就是把这两句话落到图上。

## 2. 数据通路元件

数据通路由四类元件构成，每种元件都有标准的"连接规则"：

| 元件 | 功能 | 数据流特性 |
|---|---|---|
| 寄存器（含 PC/寄存器堆） | 存储 + 时钟驱动 | 边沿触发，周期末写入 |
| ALU | 组合逻辑运算 | 无状态，输入变输出即变 |
| 多路选择器 MUX | 选择数据来源 | 由控制信号选择 |
| 存储器（指令/数据） | 读写 | 读组合、写时钟驱动 |

设计要点：**每条指令的每个周期只能写一个寄存器**（单端口写）、控制信号在周期开始前稳定、关键路径（最长的组合逻辑链）决定时钟频率——"数据通路设计 = 元件连接 + 控制信号规划"。

## 3. 单周期数据通路

单周期设计：一条指令在一个时钟周期内完成（CPI=1）：

```text
时钟周期 = 最慢指令的延迟（如 load：IMem→RegFile→ALU→DMem→RegFile）
```

| 优点 | 缺点 |
|---|---|
| 设计简单，CPI 恒定 | 周期被最慢指令拖长（load 决定全局频率） |
| 适合教学 | 各指令快慢差异被抹平（快速算术指令也被拖慢） |

单周期的关键结论：**CPI=1 但时钟慢，性能未必好**——这是多周期与流水线的出发点。单周期数据通路的图纸（五部件 + 控制信号表）是组成原理的"必画图"，画会它，多周期与流水线都是它的变体。

## 4. 多周期与微程序

多周期设计：每条指令拆成多个周期（每条指令 3-5 周期），共享硬件分时复用：

```text
同一 ALU/存储器在多个周期被不同指令阶段使用
周期 1：取指（IF）
周期 2：译码 + 读寄存器（ID）
周期 3：执行/访存地址（EX）
周期 4：访存（MEM）
周期 5：写回（WB）
```

| 优点 | 缺点 |
|---|---|
| 硬件复用（一个 ALU 干五件事）→ 省面积 | 控制复杂（状态机） |
| 每条指令用自己需要的周期数 | CPI 随指令类型变化 |

多周期引入**状态机控制器**：每个周期由状态转换决定下一步——这就是微程序控制器的雏形（微程序 = 用"程序"描述控制逻辑）。

## 5. 硬布线 vs 微程序控制器

| 维度 | 硬布线（组合逻辑） | 微程序（存储逻辑） |
|---|---|---|
| 控制信号来源 | 译码 + 组合逻辑电路 | 微指令存储器（ROM）查表 |
| 速度 | 快 | 慢（多一次访存） |
| 灵活性 | 改指令 = 改电路 | 改指令 = 改 ROM 内容 |
| 适用 | RISC/流水线 CPU | CISC（x86 早期）、教学机 |

历史演化：CISC 时代微程序是主流（指令复杂，逻辑式控制难设计）；RISC 时代硬布线回归（指令简单规整，组合逻辑可控）；现代 x86 是混合——复杂指令走微码（微程序），简单指令直接硬布线译码。这个演化完美呼应 06 篇的 RISC/CISC 之争：**控制器的选择取决于指令集的复杂度**。

### 5.1 数据通路思想的现代延伸

数据通路设计的两条原则在现代 CPU 中继续生效：**关键路径定频率**（现代 CPU 的关键路径在访存与浮点流水线，设计者的工作就是缩短它）与**控制与数据分离**（数据通路 + 控制器的分离在现代变成"执行流水线 + 调度器/ROB"，08 篇乱序执行的架构）。另一个延伸是功耗：数据通路中"哪些元件这次没用到"决定动态功耗——现代 CPU 的门控时钟（clock gating）就是"控制信号关掉不用的通路"，这是数据通路设计与功耗管理的交汇点。理解数据通路 = 理解 CPU 的物理骨架，所有微架构演进都在这副骨架上长肉。

补充一个理解锚点：**"一个周期只写一个寄存器"的规则在乱序执行中被 ROB 打破又重建**——乱序核允许内部乱写，但提交阶段按序写回（等价于"每周期按序提交一个结果"）；这条规则的"破与立"正是理解现代 CPU 从顺序到乱序演进的钥匙。

## 6. 常见误区速排

| 误区 | 事实 |
|---|---|
| "单周期比多周期快" | CPI=1 但周期被最慢指令拖长，性能未必优 |
| "控制器只是译码器" | 控制器 = 译码 + 状态机 + 时序，指挥全部数据流 |
| "微程序过时了" | x86 复杂指令仍走微码，RISC 才用纯硬布线 |
| "数据通路图会画就行" | 会写控制信号表才算会——通路与控制是一体两面 |

## 7. 本模块小结


> 🎯 **核心要点**：CPU = 数据通路 + 控制器。单周期（CPI=1 但周期被最慢指令拖长）→ 多周期（硬件分时复用，状态机控制）→ 流水线（08 篇）是性能演化的三步。控制器的硬布线/微程序之争是 RISC/CISC 的投影，现代 x86 混合使用。必会技能：画单周期数据通路图 + 写出各指令的控制信号表——这是组成原理"会不会"的试金石。2026 视角：数据通路设计原则（关键路径定频率、周期末写入）同样适用于 AI 加速器设计。
