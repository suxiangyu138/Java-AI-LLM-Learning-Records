## 1. 存储层次结构

存储器的三个矛盾特性（快、大、便宜不可兼得）催生了层次结构：

```text
寄存器（ns 级，KB 级）
  ↓  L1 Cache（1ns，几十 KB）
  ↓  L2/L3 Cache（几 ns，MB 级）
  ↓  主存 DRAM（几十 ns，GB-TB 级）
  ↓  持久内存/SSD（µs-ms 级，TB 级）
  ↓  磁盘/磁带（ms-s 级，PB 级）
速度递减、容量递增、每比特成本递减
```

层次的本质是"**用局部性赌命中**"：上层小而快，下层大而慢，数据按需逐级复制（不是移动）——上层是下层的缓存。层次设计的两个核心参数：命中率（数据在上层的概率）与未命中代价（掉到下一层的开销）——"命中率 × 速度差"决定了整个层次的平均访问时间。

## 2. 局部性原理

局部性原理是层次结构存在的理论依据：

| 局部性 | 定义 | 典型来源 |
|---|---|---|
| 时间局部性 | 刚访问的数据很快再访问 | 循环、变量重用、栈操作 |
| 空间局部性 | 刚访问地址附近的很快被访问 | 顺序数组、代码顺序执行、指令预取 |

局部性对软件的反向约束：**数据结构布局决定 Cache 命中率**——数组优于链表（连续存储）、行优先优于列优先（C 语言二维数组）、热字段聚拢（Java 对象布局优化、伪共享问题的反面）。"程序员写的每一行代码都在和 Cache 打交道"是组成原理对软件工程最直接的输出。

## 3. 主存：DRAM 的组织

主存 = DRAM（动态随机存储器），名字里的"动态"指电容电荷会漏电，需周期性刷新（毫秒级）。组织层次：

```text
存储芯片（bank）→ 行（row）→ 列（column）
访问流程：行激活（RAS）→ 列选择（CAS）→ 数据传输
刷新：每行周期刷新，与访问互斥（刷新影响带宽的 3-5%）
```

| 参数 | 含义 | 2026 基线 |
|---|---|---|
| 频率/速率 | 数据传输率 | DDR5 最高 8000 MT/s |
| 延迟 | RAS-CAS 延迟 | 几十 ns 级（速度远慢于 CPU 时钟） |
| 带宽 | 每通道传输量 | 双通道 ~70-100 GB/s |
| 容量 | 单条/整机 | 单条 32-64GB 普及，CXL 扩展可达 TB 级 |

主存的"慢"是结构性的：DRAM 靠电容存储、靠行列寻址，物理延迟与工艺相关，几十年只提升了约一个数量级——而 CPU 速度提升了几百倍，两者差距就是存储墙。

## 4. 存储墙问题

存储墙（Memory Wall）指 CPU 算力增速远超内存带宽/延迟改善速度，导致"CPU 等数据"：

```text
CPU 4GHz 每周期 0.25ns
内存访问 ~50-100ns（DDR5）
未命中一次 ≈ 200-400 个 CPU 周期！← 存储墙的核心数字
```

存储墙的三大应对：

1. **多层 Cache**（05 篇）：用局部性把大部分访问挡在纳秒级。
2. **指令/数据预取**：硬件预测下一步访问并提前拉取。
3. **计算下移**：把计算搬到数据附近（GPU 高带宽内存、存算一体）——2026 年 CXL 内存池化是"数据供给侧"的解法，存算一体是"消灭搬运"的激进路线。

> 💡 Java 后端的存储墙体验：`System.arraycopy` 与手写循环的性能差异、`volatile` 的缓存一致性代价、大对象 GC 的缓存污染——全都能用存储层次解释。

## 5. 2026 存储新格局

| 技术 | 状态 | 意义 |
|---|---|---|
| DDR5 | 主流（最高 8000 MT/s） | 主存新基线 |
| CXL 3.2 | **2026-07 量产试产**（澜起 MXC 芯片） | 内存扩展/池化：突破单机内存容量，多机共享内存池 |
| 分层内存 | 演进中 | 热数据在 DDR5、冷数据在 CXL 内存/持久内存 |
| 3D 堆叠 HBM | AI 服务器标配 | 高带宽内存，GPU 显存主力 |
| 存算一体 | 研究到早期产品 | 在存储内计算，消灭搬运（AI 推理场景先行） |

CXL 3.2 的意义：内存从"每台机器的私有资源"变为"可池化共享的资源"——PCIe 6.0（64 GT/s）承载的 CXL.mem 协议让内存扩展卡（MXC）直连 DDR5 控制器，整机内存从几百 GB 扩展到 TB 级。这是 2026 年对"存储墙"最直接的系统级回应。

### 5.1 层次结构的软件对应物

存储层次的思想在软件层被反复复制：Java 的对象布局（热字段聚拢 → 空间局部性）、GC 分代（新生代 = L1 的"热数据常驻"思想）、Redis 与本地缓存的组合（多级缓存）、数据库的缓冲池（页管理 = Cache 行管理）——"快小贵 vs 慢大廉"的矛盾在每个软件层次都会重现，而解法永远是同一个：加一层缓存。理解存储层次的人看软件缓存设计会"一眼看穿"：命中率、未命中代价、替换策略，三个参数到处适用。这也是为什么存储层次是组成原理里对软件工程师最直接有用的章节。

补充一个规划技巧：**按"带宽账"而不是"容量账"规划存储**——AI 训练与数据分析场景的瓶颈几乎总是带宽（数据搬不动）而非容量（装得下），这也是 HBM 与 CXL 优先解决带宽/池化的原因；容量账不够用可以加，带宽账不够用只能换结构。

## 6. 常见误区速排

| 误区 | 事实 |
|---|---|
| "内存不够就加内存" | 带宽与延迟是更硬的墙，容量只是其一 |
| "SSD 能替代主存" | 延迟差三个数量级（µs vs ns），层次不可取消 |
| "刷新是缺陷" | DRAM 动态刷新是容量与成本的必然交换 |
| "CXL 只是大内存" | CXL 3.2 的意义是池化与分层，不只是容量扩展 |

## 7. 本模块小结


> 🎯 **核心要点**：存储层次 = 用局部性赌命中，快小贵 vs 慢大廉的矛盾用逐级缓存化解；主存 DRAM 的电容刷新与行列寻址决定了它的物理延迟（几十 ns ≈ 数百 CPU 周期）；存储墙是算力与存储增速差的必然结果，应对靠多层 Cache + 预取 + 计算下移。2026 锚点：DDR5 8000MT/s 是主存基线，CXL 3.2 量产把内存带进池化时代，HBM 成为 AI 算力的标配显存。Java 视角：数据布局即 Cache 命中率。
