## 1. 加法器设计

加法器的演进是一条"用逻辑换速度"的路线：

```text
半加器：本位和 + 进位（不考虑低位进位）
全加器：本位和 + 进位输入（考虑低位进位）
串行加法器：n 个全加器串接，进位逐级传递
```

| 加法器 | 延迟 | 说明 |
|---|---|---|
| 串行（行波进位） | O(n) | 32 位加法进位链 32 级，每级 2 门延迟——太慢 |
| 并行（先行进位 CLA） | O(log n) | 进位"提前计算"，不依赖低位结果 |
| 混合（进位选择/跳跃） | 折中 | 分块并行 + 块间选择 |

关键认知：**加法是几乎所有运算的基底**（减法=补码加法、乘法=移位加法、比较=减法判符号），所以加法器的速度决定 ALU 的天花板——这也是进位链设计成为组成原理重点的原因。

## 2. 进位链：速度的关键

行波进位的核心问题是"每一位的进位要等低位算完"——32 位加法最坏 64 门延迟。先行进位（CLA）的思想：

```text
把进位生成分成两个信号：
  Gᵢ = Aᵢ·Bᵢ（本位必然产生进位）
  Pᵢ = Aᵢ⊕Bᵢ（本位可传递进位）
Cᵢ₊₁ = Gᵢ + Pᵢ·Cᵢ  ← 展开后所有进位只依赖 C₀ 与输入
```

展开后 C₁-C₃₂ 可并行计算，延迟从 O(n) 降到 O(log n)。实际工程用**多级 CLA**（4 位一组先行进位，组间再先行）——这是"层次化设计"在硬件中的第一次出现，后续的 Cache、流水线全是同一思想（局部优化 + 层级组合）。

## 3. ALU 结构

ALU（算术逻辑单元）把运算功能收敛进一个部件：

```text
输入：A、B、控制信号（S₀S₁ 选择运算）
功能：加/减/与/或/异或/比较/移位
输出：结果 F + 状态标志（Z 零/N 负/C 进位/O 溢出）
```

| 标志 | 含义 | Java/汇编中的用途 |
|---|---|---|
| Z | 结果为零 | 条件跳转（je/jeqz） |
| N | 结果为负 | 符号比较 |
| C | 最高位进位/借位 | 无符号比较、多精度运算 |
| O/V | 溢出 | 有符号比较（带符号跳转） |

状态标志是"运算结果的语言"：CPU 不"知道"结果含义，只是把标志交给条件跳转逻辑——`if (a > b)` 在机器层就是一次减法 + 标志判断，这是编译原理与组成原理的交界点。2026 年视角：ALU 已向量化（SIMD 执行单元一次处理 128-512 位），但标量 ALU 的标志机制原样保留。

## 4. 乘法与除法的硬件实现

乘法的移位加思想（以 4 位为例）：

```text
1011 × 1101
= 1011×1 + 1011×0×2 + 1011×1×4 + 1011×1×8
硬件：被乘数左移 + 部分积累加，乘数位决定加不加
优化：Booth 算法（相邻位编码，减少部分积个数）
```

| 实现 | 速度 | 说明 |
|---|---|---|
| 串行移位乘 | O(n) 周期 | 简单但慢 |
| Booth 乘法 | 减少部分积 | 经典考点 |
| 阵列乘法器 | 1-2 周期 | 并行部分积 + 加法树（现代 CPU 用） |
| 除法（恢复/不恢复余数） | O(n) 周期 | 二进制长除法，现代用查表/迭代近似 |

现代 CPU 的乘法是**阵列乘法器**（1-3 周期），除法用 Newton-Raphson 迭代或查表加速（硬件除法单元独立于 ALU）——考点的"串行乘法器"是理解基线，不是现代实现。

## 5. 现代运算器形态

2026 年 CPU 的运算能力由三类执行单元共同承担：

| 单元 | 处理数据 | 典型宽度 |
|---|---|---|
| 整数 ALU | 标量整数 | 64 位 |
| 浮点单元 FPU | 单/双精度浮点 | 64/80 位 |
| 向量单元（SIMD） | 向量数据（AVX/SVE） | 128-512 位 |
| 矩阵单元 | 矩阵乘（AI 推理） | FP8/BF16 加速 |

**异构计算趋势**：CPU 的向量/矩阵单元、GPU 的 SIMT 阵列、NPU 的矩阵引擎——"运算器"从单一 ALU 演变为多形态执行单元集合，但底层仍是"加法器 + 移位 + 比较"的组合。理解 ALU 原理是理解一切加速器的起点。

### 5.1 从 ALU 到 AI 加速器

2026 年运算器的演化主线是"标量 → 向量 → 矩阵"：标量 ALU 处理单数据（64 位）、向量单元处理一维数组（AVX-512 等，128-512 位）、矩阵单元处理二维矩阵（NVIDIA Tensor Core、NPU 矩阵引擎，FP8/BF16 低精度加速）。矩阵单元本质是"大量乘法器 + 加法树"的阵列——乘法器阵列思想（03 篇第 4 节）的直接放大。理解这条演化的价值：面试"为什么 AI 芯片快"的标准答案 = 数据并行度 × 低精度 × 高带宽内存，其中数据并行度就是 ALU 阵列化的产物。运算器不是过时知识，是加速器的最小单元。

补充一个工程视角：**状态标志是条件分支的硬件契约**，Java 的 `if/switch` 在机器层就是"减法/比较 + 标志跳转"的组合——理解标志位，就理解了为什么编译器要消除边界检查（JIT 的 range check elimination 就是证明标志可安全跳过的优化）。

### 5.2 运算器的未来形态

运算器在 AI 时代的终极形态是"**可重构的运算阵列**"：Tensor Core 的矩阵单元可配置精度（FP16/BF16/FP8/INT8）、NPU 的脉动阵列按数据流重排、FPGA 的逻辑单元按需组合——但无论形态怎么变，"加法器 + 移位 + 比较"是永远的地基。理解地基的人看任何新加速器都能快速定位它的"算术单元 + 数据通路 + 控制"三件套，这是组成原理"以不变应万变"的体现。

## 6. 常见误区速排

| 误区 | 事实 |
|---|---|
| "加法器只有一种" | 串行 O(n) vs 先行进位 O(log n)，速度差数量级 |
| "乘法靠重复加法" | 移位加 + Booth 编码 + 阵列并行，现代 1-3 周期 |
| "ALU 只管加减" | ALU = 算术 + 逻辑 + 移位 + 标志输出 |
| "除法也是简单循环" | 现代用迭代近似（Newton-Raphson）与查表 |

## 7. 本模块小结


> 🎯 **核心要点**：运算器三件套——加法器（进位链决定速度，CLA 把延迟从 O(n) 压到 O(log n)）、ALU（控制信号选功能 + 状态标志输出）、乘除法（移位加思想 + 阵列/迭代加速）。层次化设计（4 位 CLA 组合）是硬件的第一课，贯穿 Cache 与流水线。现代形态：整数/浮点/向量/矩阵四类执行单元并存，AI 驱动的低精度矩阵单元是 2026 的新增长点。
