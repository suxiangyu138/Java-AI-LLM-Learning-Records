## 1. 交换机的角色

交换机是数据链路层（二层）设备，连接同一广播域内的主机，按**目的 MAC 地址**转发帧。与集线器的本质区别：集线器共享冲突域（所有端口收到所有帧，一次只能一人发送），交换机**每个端口独立冲突域**（点对点全双工，多端口并行转发），且只把帧送往目标端口——带宽利用率与并发能力全面提升。

交换机的"记忆"是**MAC 地址表**（转发表）：`MAC → 端口` 的映射。转发决策三原则：
1. 表命中 → 从指定端口转发；
2. 表未命中 → 向除源端口外**所有端口泛洪**（洪泛，接收方应答后学习）；
3. 目的地址是本机/广播/多播 → 按相应规则处理。

## 2. MAC 自学习与转发决策

**自学习算法**（这就是"交换机不需要配置就能工作"的原因）：

1. 收到帧，记录**源 MAC → 入端口**（带时间戳）；
2. 查目的 MAC：命中转发表 → 定向转发；未命中 → 泛洪；
3. **老化机制**：表项闲置超时删除（默认 300s，可配置）——主机移动/断电后表项不会永远错下去。

**硬件实现**：MAC 表用 **哈希表**（按 MAC 哈希到桶，链式解决冲突）存于芯片 SRAM/TCAM。数据中心交换机表容量从几千条（入门）到百万级（数据中心 ToR，支持大规模租户），**表容量决定一台交换机可连接的"活跃主机数"上限**。

**环路问题**：二层没有 TTL，环路会让广播风暴无限循环——因此引入 **STP/RSTP（生成树协议）**：逻辑上砍掉冗余链路成树，物理链路保留作备份。代价是**一半链路闲置**（三层路由+ECMP 用满所有链路的对比见 10 篇）。现代数据中心"二层域"被压缩到极小（通常一个 POD 内），大规模横向扩展靠三层。

## 3. 二层转发细节：VLAN 与广播域

| 概念 | 说明 | 关键数字 |
|------|------|---------|
| VLAN | 把一个物理交换机切成多个独立广播域 | 12bit VID：0-4095，可用 1-4094 |
| Access 口 | 端口固定属于某 VLAN，进出帧不带标签 | 通常用于接服务器 |
| Trunk 口 | 端口透传多 VLAN 帧（带 802.1Q 标签） | 用于交换机互联 |
| 本征 VLAN | Trunk 上不带标签的流量归属（默认 VLAN1） | 安全建议改掉默认 |
| VXLAN | 把二层域扩展到三层之上的隧道（MAC-in-UDP） | 云网络虚拟化基石 |

VLAN 的意义在于隔离：不同 VLAN 间广播、ARP 互不可见，**跨 VLAN 通信必须走三层**（交换机路由口或路由器）。这就是"二层隔离、三层互联"的现代网络模型。2026 年服务器虚拟化场景中，VLAN 之上叠加 VXLAN，物理交换机退化为"大管道"，虚拟网络由软件（OVS）或 DPU（见 08 篇）承载——但物理交换机仍要硬件卸载 VXLAN 封装，否则吞吐崩盘。

## 4. 三层交换

"三层交换机"= 二层转发引擎 + 三层路由查表硬件，同台设备线速处理 VLAN 间路由。核心是 **LPM（最长前缀匹配）** 查表（路由表按 IP 前缀匹配，选最长匹配项）。硬件查表两路线：

| 方案 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| TCAM | 内容可寻址，一次并行比较所有条目，找最长匹配 | 确定性 O(1) 查表、纳秒级 | 贵、功耗大、容量有限 |
| 前缀树/哈希 | 软件查表或哈希加速 | 便宜、容量大 | 哈希冲突需处理、查表链路更长 |

现代数据中心交换机（BGP/OSPF 全三层）把路由表放 TCAM 或优化哈希结构，查表+修改+调度全程纳秒级——这就是"线速三层转发"。**硬件的核心指标不是"能不能路由"，而是"路由查表能否不拖慢转发"**。

## 5. 线速与交换容量

- **交换容量（背板带宽）**：所有端口双向带宽之和。64 口 × 100G 双向 = 12.8Tbps。
- **线速（Wire Speed）**：任意端口组合都能满速率转发不丢包。判据：**任意 N 端口同时收发时，交换容量 ≥ N 端口全双工带宽之和**，即"无阻塞"。
- **PPS 上限**：线速下的每秒包数由最小帧（64B）+ 帧间间隙 + 前导码决定：`线速(Gbps) / (64+20)B×8 ≈ 1.488Mpps/Gbps`。100G 端口 ≈ 148.8 Mpps，800G ≈ 1.19 Gpps——**小包线速是交换芯片最苛刻的测试**（每包处理时间硬上限约 0.84ns/Gbps，800G 时每包仅 ~0.84ns，流水线必须并行化）。

**"交换容量"陷阱**：很多厂商标"交换容量"含双向，或把扩展槽、堆叠口也算进去——真正看**线速转发率（Mpps）与端口密度**。2026 年 102.4T 芯片（Tomahawk 6）意味着 128 个 800G 端口全速转发，这是"线速"在百 T 级别的具象化。

## 6. 交换芯片 ASIC 流水线

交换机的"大脑"是交换芯片（ASIC），数据面是一条**深度流水线**，每个包从进到出经过固定级站：

```
入端口(SerDes 接收)
  → 帧解析(Parser: 提取 MAC/IP/端口/隧道头)
  → 查表(源 MAC 学习 / 目的 MAC / LPM 路由 / ACL)
  → 策略(ACL/流表: 允许-丢弃-重定向 / 计费 / 采样)
  → 修改(改写 MAC、VLAN 标签、TTL、隧道封装 VXLAN)
  → 转发决策(单播端口 / 多播复制 / 哈希选 ECMP 路径)
  → 队列与调度(QoS: 8 级队列、WRED 丢弃、PFC 流控)
  → 出端口(SerDes 发送, 包切分/重组)
```

每个级站由专用硬件单元并行处理，**多包同时处于流水线不同级站**（和 CPU 流水线同理），保证每包延迟与处理时间的硬上限。设计取舍：ASIC 越快越专，但**功能固化**——因此有了可编程数据面（P4 芯片，如 Intel Tofino）与 CPU 旁路（慢路径交给板载 CPU 处理异常包，如协议报文、查表未命中）。

**拥塞管理硬件**：数据中心无损网络（RoCE）依赖 PFC（按优先级暂停）、ECN（显式拥塞通知）在芯片内实现；WRED 随机早丢弃防 TCP 全局同步。这些机制全在芯片队列调度器中，**交换芯片的调度能力（队列深度、调度精度）直接决定 AI 训练尾延迟**。

AI 集群把交换芯片推向 100T+ 时代，格局三巨头：

## 8. 交换机形态与部署

| 形态 | 特征 | 典型场景 |
|------|------|---------|
| ToR（架顶）盒式 | 1/2U，32-128 端口，叶角色 | 每机柜 1-2 台，接服务器 |
| 脊盒式 | 大端口密度（64×800G+），脊角色 | 汇聚所有叶 |
| 模块化框式 | 线卡可插拔、板载路由引擎 | 核心层、运营商 |
| 堆叠 | 多台逻辑一台 | 中小机房简化管理（有扩展上限，数据中心不推荐） |

**数据中心部署范式**：叶-脊两层（详见 10 篇）。叶交换机接服务器（ToR），脊交换机全互联叶；**叶脊之间用 ECMP（等价多路径）让所有链路同时满载**，带宽 = 脊数 × 链路速率。2026 年 AI 集群在叶脊基础上叠加"rail-optimized"（轨道优化）拓扑：把同一训练作业的 GPU 调度到同一 rail（叶脊的一个切片），集合通信只走一小片网络，减少拥塞——AI 流量模式重塑了拓扑设计（见 09/10 篇）。

> 🎯 **核心要点**：交换机 = "硬件记忆（MAC/LPM 表）+ 硬件流水线（解析-查表-修改-调度）"。自学习让它免配置即插即用，ASIC 流水线让它线速转发，TCAM/哈希让它纳秒级查表。2026 年交换芯片进入 100T 时代（Tomahawk 6 量产、200T 流片），"线速"的定义从 12.8T 推到 102.4T，AI 集群的扩展性、拥塞控制与可编程性都压在芯片级实现上——交换机从未如此"芯片即产品"。

## 9. 交换机关键指标与生成树补充

**选型关键指标解读**（厂商参数表的正确读法）：

| 指标 | 读法 | 陷阱 |
|------|------|------|
| 交换容量 | 全端口双向之和；验证是否线速（非阻塞） | 部分厂商含扩展槽/管理口充数；看"线速转发率 Mpps" |
| 转发率（Mpps） | 64B 包线速能力；1G 端口≈1.488Mpps | 容量大但 Mpps 低 = 芯片内部无法全速 |
| MAC 表容量 | 接入级 8-16K、汇聚 128K+、数据中心百万级 | 超容量后表项被随机踢出 → 泛洪增多 |
| 路由表容量 | LPM 条目数（TCAM 大小） | 数据中心 BGP 全三层需要大路由表 |
| 缓存（Buffer） | 端口队列缓存（MB 级） | 无损网络/AI incast 场景需要大缓冲吸收突发 |
| 时延 | 端口到端口延迟（ns-μs 级） | 低延迟场景选 cut-through 转发模式 |

**生成树细节**：RSTP 收敛秒级、MSTP 支持多实例；**链路聚合（LACP/静态）把多条链路绑成一条逻辑链路**（负载均衡粒度是流，不是包——避免乱序）。数据中心叶脊不依赖 STP（BGP 三层自带防环），STP 只存在于接入层残余场景。

**交换机的"三速"**：线速转发（硬件满速率）、**存储转发 vs 直通转发**（cut-through 收到目的 MAC 即转发，延迟可降到 ns 级，适合 HPC/AI 低延迟场景，但坏帧也会被转发）；大网段标准部署用存储转发（校验完整）。

## 10. 安全与防护硬件功能

交换机不只是转发，还承载接入层的安全基线：

| 功能 | 机制 | 防什么 |
|------|------|--------|
| ACL（访问控制列表） | TCAM 硬匹配（源/目的 IP+端口） | 非法访问、恶意流量 |
| 端口安全 | 限制端口学习 MAC 数、绑定 MAC | 私接设备、ARP 欺骗雏形 |
| DHCP Snooping | 信任/非信任端口区分 DHCP 应答 | 伪造 DHCP 服务器 |
| 风暴控制 | 广播/多播/单播泛洪限速 | 广播风暴打瘫网络 |
| 流量镜像 | 端口镜像到监控口 | 抓包取证（也是运维利器） |
| M-LAG/多主检测 | 双活链路组 | 单链路故障切换 |

**接入层安全的"硬件现实"**：所有安全规则都要进芯片 TCAM/流表——**规则数上限 = 硬件表容量上限**，规则加多了转发性能会掉（查表流水线变慢或降级到 CPU）。部署策略：规则按"能进硬件则进硬件、必须软件则放网关"分层。

**常见交换机故障速查**：

| 症状 | 原因 | 处理 |
|------|------|------|
| 单端口 CRC 错误 | 线缆/模块故障 | 换线换模块，再看计数 |
| 端口 err-disable | 环路/风暴/双工冲突触发保护 | 查环路（STP 未生效）、恢复端口 |
| 整机吞吐骤降 | 表项满（MAC/ACL）、CPU 高 | 查表利用率（show mac address-table count） |
| 间歇性丢包 | 缓冲区溢出（incast） | 调大端口缓存/启用 PFC 或 ECN |

## 11. 端口形态速查

交换机的"脸"是端口，速率越高形态越统一：

| 端口形态 | 通道 | 典型速率 | 场景 |
|---------|------|---------|------|
| RJ45 | 电口 | 1G/10G/25G（Cat8 30m） | 接入层、PoE |
| SFP+ | 光/电 | 10G | 存量接入/汇聚 |
| SFP28 | 光/电 | 25G | 服务器上联（云标配） |
| QSFP28 | 4×25G | 100G | 汇聚/叶-脊 |
| QSFP-DD | 8× | 400G/800G | 400G 时代主力 |
| OSFP/OSFP224 | 8× | 800G/1.6T | **2026 AI 集群主力** |

**拆分配置（Breakout）**：一个 800G 端口可拆成 2×400G 或 8×100G（用 DAC/分叉光缆）——**端口形态与拆分配置决定一台交换机实际能接多少台服务器**，是采购规划的第一张表。
