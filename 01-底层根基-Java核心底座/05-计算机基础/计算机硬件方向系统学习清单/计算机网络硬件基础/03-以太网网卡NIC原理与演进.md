## 1. 网卡的角色与内部组成

网卡（NIC，Network Interface Card）是主机网络栈的最底层硬件，承担**帧的组装/拆解、介质访问、主机与链路之间的搬运**。内部三大功能块：

| 功能块 | 职责 | 说明 |
|--------|------|------|
| PHY | 物理信号收发 | 编码（PAM4 等）、串并转换、时钟恢复；介质接口（RJ45/光模块座） |
| MAC 控制器 | 帧级处理 | 组装/解析帧、CRC 校验、地址过滤、流量控制（PAUSE 帧）、VLAN 标记 |
| 主机接口 | 与 CPU/内存交互 | PCIe 接口、DMA 引擎、发送/接收描述符环形队列 |

关键点：**MAC 控制器 + DMA 引擎是网卡的灵魂**——它们决定了一个帧从线缆到内存（或反向）需要多少 CPU 参与。现代网卡还集成了**卸载引擎**（校验和、分段、散列）与**队列管理**（多队列、流分类），这些将在 06、07 篇展开。

**PCIe 接口与带宽匹配**：网卡速率必须与 PCIe 通道匹配——100G 网卡至少 PCIe 4.0 x16（理论 64GB/s 双向，实际单向约 32GB/s，而 100G 单向仅 12.5GB/s，留足余量）；2026 年的 800G 网卡（ConnectX-8）走 PCIe Gen6（最高 48 lanes），因为 800G 单向 100GB/s 已经逼近 PCIe 5.0 x16 的上限。**接口带宽永远是先于介质出现的瓶颈**。

## 2. MAC 地址与以太网帧

**MAC 地址**：48 位（6 字节），前 24 位是 OUI（厂商唯一标识），后 24 位厂商分配。三种寻址：单播（第 1 位=0）、多播（第 1 位=1）、广播 FF-FF-FF-FF-FF-FF。**MAC 只在同一广播域（二层域）内有效**，跨网段必须靠 IP + 路由器。

**以太网帧结构**（802.3）：

```
┌──────────┬─────────┬──────────┬──────────────┬────────┬───────┐
│ 前导码 7B │ SFD 1B  │ 目的 MAC 6B │ 源 MAC 6B    │ 类型/长度 2B │ Payload │ FCS 4B │
└──────────┴─────────┴──────────┴──────────────┴────────┴───────┘
```

- **类型/长度**：≥1536 视为类型（IPv4=0x0800、ARP=0x0806、VLAN=0x8100），≤1500 视为长度——网卡据此判帧格式。
- **FCS**：CRC-32 帧校验，**网卡硬件计算与验证**，这是最基础也最被忽略的卸载。
- **帧间间隙 IFG**：帧间最小 96 bit 时间，是线速下 PPS 上限的物理来源。
- **VLAN 标签**（802.1Q）：在源 MAC 后插入 4 字节（TPID 0x8100 + 3bit 优先级 + 12bit VID），可嵌套（QinQ）。
- **巨型帧 Jumbo**：MTU 9000，高层每包装更多数据，**包数减少 6 倍、CPU 与中断开销大减**——数据库/存储网络标配，但要求整条路径所有设备 MTU 一致。

## 3. 收包路径：从信号到内存

一次收包，硬件与软件的分工边界（x86/ARM 通用模型）：

```
PHY 收信号 → 还原比特 → MAC 解析帧(去 FCS/校验) → 地址过滤(非本机单播/多播/广播丢弃)
   → DMA 引擎把帧拷入内存中的接收环形队列(RX Ring, 预分配 skb/页)
   → 网卡写描述符状态位 → 触发中断(MSI-X, 可指定 CPU)
   → 驱动(NAPI)收包 → 协议栈处理(TCP/IP) → 应用
```

效率关键点：
- **DMA 直达内存**：数据从网卡直接写主机内存，**不经过 CPU**——这是"零拷贝"的物理基础（见 11 篇的 sendfile）。
- **环形队列预分配**：驱动提前把内存页交给网卡（缓冲池），网卡写入后归还；队列满则丢包（或触发 PAUSE）。
- **NAPI 混合轮询**：中断通知后切轮询模式批量收包，低负载中断响应、高负载免中断风暴。
- **地址过滤在硬件完成**：非本机帧在网卡内被丢弃，不浪费 DMA 带宽——虚拟化场景由 VF 的 MAC 过滤实现租户隔离。

## 4. 发包路径：从内存到信号

```
应用 → 协议栈(组 TCP 段/IP 包) → 驱动把 skb 挂入发送队列(TX Ring)
   → DMA 引擎从内存搬数据 → MAC 加前导码/帧头/CRC → PHY 编码发送
   → 完成中断(或轮询确认) → 释放 skb 缓冲
```

发送方向的核心开销是**数据搬移与校验计算**。协议栈通常先在内存中拼好帧（skb 各段通过 DMA 描述符散列表征，硬件做 gather 发送），**校验和由网卡硬件计算**（checksum offload，见第 6 节）。发送完成通知有中断与轮询两种模式，高吞吐下通常关闭 TX 完成中断、依赖队列深度回收。

## 5. 多队列与中断机制

单队列网卡是"一条管道全队排"：所有包进一个 RX Ring，一个 CPU 中断处理，多核 CPU 只能单核收包——10G 以上必废。现代网卡标配**多队列**：

| 技术 | 作用 | 机制 |
|------|------|------|
| RSS（接收侧扩展） | 收包分散到多核 | 硬件对五元组哈希 → 哈希值选队列（间接表）→ 每队列绑定一个 CPU |
| RPS（软件 RSS） | 无硬件多队列时的软件替代 | 内核按哈希把包分发到其他 CPU 的 backlog |
| RFS（流级 RPS） | 让处理流量的 CPU 与队列一致 | 跟踪流所在 CPU，减少缓存漂移 |
| XPS（发送侧扩展） | 发包分散到多核 | 每 TX 队列绑定 CPU，避免锁竞争 |

**MSI-X 中断**：每条队列独立中断向量，直通指定 CPU（中断亲和性）。**中断聚合**：攒 N 个包或 T 微秒再中断一次，把"每包一次中断"降为"每批一次"——高 PPS 下 CPU 从"忙于中断"变为"忙于处理"。代价是延迟：聚合窗口越大延迟越高，**低延迟场景（交易、AI 集合通信）要调小甚至关闭聚合**，这与吞吐场景互斥，是网卡调优的第一对矛盾。

## 6. 四大基础卸载

网卡把高频、模式固定的包处理从 CPU 挪到硬件，四大件是任何现代网卡的标配：

| 卸载 | 全称 | CPU 省了什么 | 硬件做了什么 |
|------|------|-------------|-------------|
| Checksum Offload | 校验和卸载 | 每包校验计算 | 收：硬件校验 IPv4/TCP/UDP 校验和；发：硬件计算填充 |
| TSO/GSO | TCP 分段卸载 | 大包切分循环 | 协议栈一次交出 64KB 大段，网卡切成 MTU 大小段并生成校验 |
| LRO/GRO | 接收合并 | 每包协议栈处理 | 把同一流相邻小包合并成大包再上交（GRO 是内核版，更安全） |
| RSS | 接收散列 | 单核瓶颈 | 硬件哈希分队列（见上节） |

性能影响量化：**TSO 是吞吐翻倍的功臣**——40G 线上小包满速每秒约 6000 万包，CPU 每秒只能处理数百万包，没有 TSO 任何 TCP 高速传输都到不了线速。**LRO/GRO 则直接砍协议栈处理数**：4 个 1500B 包合并为 1 个 6000B 包上交，协议栈处理量降 75%。

进阶卸载：VLAN 标记卸载（硬件插/剥标签）、隧道卸载（VXLAN/Geneve 外层头硬件封装，虚拟化必备）、流分类（按五元组送不同队列，QoS 基础）、SDP（安全数据路径，IPsec 硬件加解密）。**完整卸载家族见 07 篇**。

## 7. 速率演进与形态

| 速率 | 年代 | 线缆 | 主机接口 | 典型场景 |
|------|------|------|---------|---------|
| 10M | 1980s | 同轴/双绞 | ISA | 历史 |
| 100M | 1990s | 双绞 Cat5 | PCI | 历史 |
| 1G | 2000s | Cat5e/Cat6 | PCIe x1 | 桌面/办公服务器（存量） |
| 10G | 2010s | Cat6A/光纤 | PCIe 2.0 x8 | 传统数据中心服务器标配 |
| 25G | 2010s 末 | DAC/光纤 | PCIe 3.0 x8 | **云厂商服务器事实标准**（单 25G 性价比最优） |
| 100G | 2020s | 光纤/DAC | PCIe 4.0 x16 | 存储/网络服务、AI 推理 |
| 400G | 2023-2025 | 光纤/DAC | PCIe 5.0 x16 | AI 集群主流（ConnectX-7 等） |
| 800G | 2025-2026 | 光纤（OSFP/QSFP-DD） | PCIe 6.0 | AI 超大规模集群（ConnectX-8/Thor Ultra） |

形态要点：
- **板载 vs 独立**：服务器主板集成 1G/10G（或 25G）网卡，AI/存储/云服务器用独立 PCIe 网卡（可换可扩、带卸载与 RDMA）。
- **OCP 3.0 规格**：开放计算项目定义的开源网卡形态（半高/全高、低功耗），微软/Meta 等大规模采购的主选，2026 年 800G 网卡主流形态。
- **Socket Direct（NVIDIA）**：网卡直接对接双路 CPU 内存，绕开 PCIe 交换机与跨 NUMA，延迟再降。
- **多端口**：单卡 2×400G、2×800G 是 AI 节点标配（双口冗余 + 直连多机）。

## 8. 2026 高端网卡格局

AI 集群把网卡从"服务器配件"推上"集群控制点"——拥塞控制、重传、多路径都下沉到网卡，2026 年四款代表：

| 网卡 | 速率 | 核心亮点 | 生态 |
|------|------|---------|------|
| NVIDIA ConnectX-8（C8180/C8240） | 800G | PCIe Gen6、RDMA/RoCE、GPUDirect RDMA、网内计算 SHARP、OSFP224/双口 QSFP112 | Spectrum-X 2.1 参考架构 |
| Broadcom Thor Ultra | 800G | 首个全合规 UEC 800G 网卡、包级多路径、乱序数据放置、硬件重传、可编程拥塞控制、线速加密、SPDM 固件认证 | Tomahawk 6 + UEC |
| 华为 SP560 | 800GE（国内首个） | "灵衢+PCIe"双总线、数据面直通 GPU/NPU 内存、GPU 直通集合通信卸载、可编程协议 | 昇腾集群 10 万节点 |
| Intel E835 系列 | 200G | 低功耗（约为 ConnectX-6 Dx 一半）、RoCEv2/iWARP/DCB、面向存量基础设施 | HPE Discover 2026 首发 |

**速率协商的工程细节**：自协商（Auto-Negotiation）决定双方最终速率与双工——**手工固定速率会导致一端 25G、一端 10G 协商失败或双工不匹配**（全/半双工冲突是 10G 以前的老坑，现代网卡全双工无此问题，但速率协商仍须自动）。机房扩容换线缆后首查协商结果（`ethtool eth0`），"网卡 25G 却协商成 1G"九成是线缆等级不够。

趋势判断：**网卡 = 交换机之外的第二控制面**。800G/1.6T 时代，拥塞控制、可靠性（硬件重传）、多路径（包级 ECMP）这些原本在交换机和协议栈的职责正在迁移到网卡——因为 AI 流量模式（AllReduce 同步、短流突发）让"端到端感知"成为必需。**UEC 1.0 规范的核心机制（credit-based 传输）就直接实现在 NIC 固件里**，这是 09 篇的前奏。

> 🎯 **核心要点**：网卡是"主机 CPU 税"的税务署——四大卸载（checksum/TSO/GRO/RSS）把每包开销从百级 CPU 周期压到十级；多队列 + MSI-X + 中断聚合让多核 CPU 并行收包；2026 年网卡更进一步，承担 RDMA、拥塞控制、硬件重传与安全（加密/认证），成为 AI 集群的性能与可靠性控制点。理解网卡 = 理解"主机侧网络性能的全部来源"。

## 9. 驱动与性能数据：NAPI 与每包成本

**NAPI（内核新式 API 收包模型）**是现代网卡驱动的事实标准，理解它就理解了"网卡-内核"的协作：

```
低负载：中断模式 —— 每包一个中断，延迟最优（几十 μs 级）
   ↓ 中断次数超过阈值（net.core.busy_poll 相关）
高负载：轮询模式 —— 中断后切轮询，批量收完本批次包再退出
   好处：高 PPS 下不再被中断风暴淹没，CPU 时间全部用于收包处理
```

**每包成本对比**（x86 量级，64B 小包）：

| 路径 | 每包 CPU 成本 | 单核吞吐上限 |
|------|--------------|-------------|
| 传统中断路径（旧驱动） | 1-3μs 级 | 0.3-0.5 Mpps |
| NAPI + 卸载 + 多队列 | 0.2-0.8μs | 1-2 Mpps |
| XDP 快速路径 | 0.05-0.1μs | 10-30 Mpps |
| DPDK 轮询 | 0.02-0.05μs | 数千万 PPS |

**验证卸载是否生效**：

```bash
ethtool -k eth0 | grep -E "tcp-segmentation|generic-receive|rx-checksumming"
# tcp-segmentation-offload: on
# generic-receive-offload: on
# rx-checksumming: on
```

> ⚠️ TSO/GRO 的代价：抓包（tcpdump）看到的是网卡重组后的包；wireshark 分析 TCP 时序要留意；部分 DPI/安全设备对 GRO 合并的包特征识别不全。

## 10. 网卡常见故障与排查

| 现象 | 首查 | 典型根因 |
|------|------|---------|
| 协商成 1G 而不是 10G/25G | `ethtool eth0` 看 Speed | 线缆等级不足、对端端口速率配置、**自协商失败（手工固定速率导致）** |
| 随机丢包 | `ethtool -S` rx_missed | 队列缓冲不足（`net.core.rmem_max`）、中断处理不过来 |
| 高延迟 | 检查中断聚合参数 | 聚合窗口过大（延迟敏感场景需调小） |
| 性能下降但无告警 | 固件/驱动版本 | **网卡固件 bug 是"幽灵故障"大户**，升级前先查厂商 release notes |
| 虚拟机吞吐暴跌 | 检查 SR-IOV/vhost 配置 | VF 队列数不足、宿主与 VM NUMA 错位 |
| 多网卡流量不均 | `/proc/interrupts` | 未绑核、RSS 哈希不均、多队列未开 |

**网卡维护基线**：驱动与固件纳入版本管理（线上网卡型号/固件/驱动版本应全量登记）；**更换网卡后必做三项验证**——速率协商、卸载状态（ethtool -k）、中断分布；大规模服务器故障中"同批次网卡固件缺陷"是隐蔽的群体性故障源头。

## 11. 网卡形态选择与双网卡实践

| 形态 | 场景 | 取舍 |
|------|------|------|
| 板载（主板集成） | 通用服务器 1G/10G | 省钱省槽位；换代受限 |
| PCIe 独立卡 | 云/AI/存储服务器 25G-800G | 可换可扩；散热占用 |
| OCP 3.0 夹层卡 | 超大规模采购（Meta/微软风格） | 低功耗、标准化；兼容性受机箱约束 |
| 多端口卡（2×100G/2×400G） | AI 节点、双上联 | 一卡完成冗余直连 |

**双网卡/双口实践**：服务器双上联是标准冗余（一张卡双口或两张卡各一口）；**bonding 模式**：主备（mode 1，安全第一）、负载均衡（mode 4 LACP，需交换机配合）。**注意**：bonding 是链路级冗余，交换机故障仍可能双挂（接入两台不同叶交换机才是真正的"接入冗余"）。AI 节点双口直连两台 ToR 是标配，避免单交换故障拖垮训练。
