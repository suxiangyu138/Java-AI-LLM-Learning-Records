## 3. 学习路线推荐

**路线 A：性能意识速成（半天）**
01 → 02 → 03 → 09。先建立"代码在硬件上怎么跑"的心智模型，再学会测量——适合想给调优开窍的开发者。

**路线 B：后端 I/O 主线（1-2 天，推荐）**
04 → 05 → 06 → 07。系统调用、存储、网络、并发四条腿，覆盖后端性能问题 80% 的根因面——NIO、数据库、高并发锁的理解全部落在这里。

**路线 C：全量系统（2-3 天）**
路线 A + B + 08 + 10。补齐 JVM 与硬件映射、现代硬件趋势（NUMA/Vector API/CXL），达到能独立做"性能问题定位→硬件归因→方案落地"的水平。

> 💡 与知识库关系：03 篇的缓存机制与 `缓存与Cache/`、`内存墙/02` 互补；05 篇的存储数字与 `量化背后硬件约束/` 共享硬件基线；08 篇 GC 与 `内存墙/06` 的 KV Cache 对照（都是"内存受限"）；10 篇 CXL 与 `内存墙/08` 同源。

### 阅读时的三个常见误区

1. **"调优 = 改配置"**：调优的正确顺序是先测量定位、再归因到硬件行为（缓存/带宽/锁/系统调用）、最后才动参数——顺序反了就是瞎调（09 篇）
2. **"Java 与硬件无关"**：volatile 的可见性、CAS 的原子性、GC 的停顿、大页的 TLB 收益——处处是硬件语义在 JVM 里的投影（03/07/08 篇）
3. **"学硬件就是背参数"**：参数会过时（2026 年 NVMe Gen6 已达 550 万 IOPS，Kioxia GP1 宣称 1000 万），但"映射关系"永不过时——缓存行不会变、系统调用代价不会消失、页缓存语义不会改（05 篇）

## 4. 核心概念速查

| 概念 | 一句话定义 | 软件侧的表现 |
|------|-----------|---------------------|
| 指令集 | 软件与硬件的第一道契约 | JIT 按 CPU 特性生成机器码 |
| 流水线/乱序 | 指令级并行 | 热点代码形态决定 IPC 高低 |
| 分支预测 | 猜测跳转方向 | 分支密集代码的惩罚 |
| MMU/TLB | 虚拟地址→物理地址翻译 | 内存分配、缺页、大页收益 |
| 缓存行 | 缓存读写最小单元（64B） | 局部性、伪共享 |
| MESI | 缓存一致性协议 | volatile 可见性的硬件基础 |
| 系统调用 | 用户态→内核态切换 | 高并发 I/O 的第一成本 |
| epoll | 事件多路复用 | NIO/Netty 的底层 |
| 零拷贝 | 数据少搬一次 | sendfile/DMA 减少拷贝 |
| 页缓存 | 磁盘数据的 OS 缓存 | fsync、WAL、脏页 |
| fsync | 强制刷盘 | 数据库持久化的真相 |
| futex | 快速用户态互斥 | synchronized 重量级锁 |
| 伪共享 | 无关字段共享缓存行 | 并发计数器性能杀手 |
| GenZGC | JDK 21 稳定的分代 ZGC | 亚毫秒停顿、大堆首选 |
| eBPF | 内核可编程观测 | 零代码连续 profiling |
| CXL | 内存池化互连 | 数据中心内存再分配 |

> 🎯 **核心要点**：这套体系的全部价值压缩为一句话——**硬件行为不是背景知识，而是代码性能与并发正确性的"第一性原理"：每一条 volatile、每一次系统调用、每一块缓存行、每一次 fsync，最终都落到一组固定的硬件机制上；学会把软件现象翻译成硬件归因，就掌握了性能工程的底层语言**。

### 体系速读版（30 秒版）

- **代码怎么跑**：指令集契约 + 流水线/乱序/分支预测决定单线程速度（01 篇）
- **内存怎么分**：虚拟地址 + MMU/TLB + 页错误，malloc/new 只是触发缺页的入口（02 篇）
- **可见性哪来的**：缓存行 + MESI + 内存屏障——JMM 是硬件模型的软件化（03 篇）
- **I/O 为什么慢**：系统调用、中断、DMA、epoll、零拷贝（04 篇）
- **数据怎么落盘**：页缓存 + fsync + WAL + 数据结构迎合磁盘（05 篇）
- **并发锁怎么造**：CAS → 缓存锁 → futex → 无锁结构的硬件逻辑（07 篇）
- **怎么测量**：perf 采样 + eBPF 火焰图，先测后调（09 篇）
