## 1. 文件系统层次结构

```
用户层（Java File / Path / Stream API / 系统调用）
    ↓
文件系统层（inode、目录项、权限、缓存）
    ↓
物理文件系统（磁盘驱动）
    ↓
存储层（磁盘、SSD 物理读写）
```

> 💡 调用 `File.createNewFile()` 时，底层依次经过：用户层（Java API）→ 文件系统层（解析路径、检查权限、分配 inode）→ 存储层（磁盘操作）。

### 1.1 文件系统内部层次

```
用户接口（open/read/write 等系统调用）
    ↓
文件目录系统（目录查找、路径解析）
    ↓
存取控制模块（权限检查）
    ↓
逻辑文件系统（文件逻辑块号 → 物理块号）
    ↓
物理文件系统（磁盘驱动、缓存管理）
```

## 2. 文件与文件系统基础

## 3. inode 与目录项

### 3.1 inode（索引节点）

**inode** 是描述文件属性和存储位置的核心数据结构。每个文件对应一个唯一的 inode。

```
inode 包含：
├── 文件类型和权限（rwx）
├── 所有者信息（UID、GID）
├── 文件大小
├── 时间戳（atime / mtime / ctime）
├── 链接计数（硬链接数）
└── 数据块指针
    ├── 直接指针（12 个，指向数据块）
    ├── 一级间接指针
    ├── 二级间接指针
    └── 三级间接指针
```

### 3.2 inode 与 Java 方法关联

| inode 字段 | Java 对应方法 |
|------------|---------------|
| 文件权限 | `file.canRead()`/`canWrite()`/`canExecute()` |
| 文件大小 | `file.length()` |
| 修改时间 | `file.lastModified()` |
| 数据块指针 | NIO `FileChannel.map()` |
| 链接计数 | `Files.links()` |

> ⚠️ **关键注意**：inode **不存储文件名**。文件名存储在"目录项"中。修改文件名本质是修改目录项的映射，不改变 inode。

### 3.3 目录项

**目录**也是一个文件，其数据块存储目录项列表（文件名 → inode 号映射）。

```
目录项 = [ 文件名 | inode号 ]
目录文件内容：
├── "."     → inode 100（当前目录）
├── ".."    → inode 2（上级目录）
├── "a.txt" → inode 200
└── "b.txt" → inode 201
```

> `file.listFiles()` 本质是读取目录文件的数据块，获取目录项列表。

### 3.4 硬链接 vs 软链接

| 对比维度 | 硬链接 | 软链接（符号链接） |
|----------|--------|-------------------|
| 本质 | 同一个 inode 的多个目录项 | 独立的特殊文件，存目标路径 |
| inode | **相同**（同一文件） | **不同**（独立文件） |
| 跨文件系统 | **不可以** | **可以** |
| 目录 | 不可以（通常） | **可以** |
| 源文件删除后 | 仍可访问（引用计数 > 0） | **失效**（断链） |
| 创建命令 | `ln file link` | `ln -s file link` |

## 4. 文件的物理结构

### 4.1 三种分配方式

| 结构 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| **连续分配** | 文件在磁盘上连续存放 | 读取速度快，简单 | 外部碎片严重，不利于动态增长 |
| **链接分配** | 每个数据块存储下一块的指针 | 无外部碎片，利于增长 | 随机访问慢（需链表遍历）|
| **索引分配** | 每个文件一个索引块，存所有数据块指针 | 支持随机访问，兼顾大小文件 | 索引块额外占用空间 |

### 4.2 索引分配（Unix/Linux inode 设计）

```
inode 数据块指针：
┌──────────────────────┐
│  直接指针 [0]  → 数据块  │
│  直接指针 [1]  → 数据块  │
│    ...           ...   │
│  直接指针 [11] → 数据块  │   ← 小文件直接访问
├──────────────────────┤
│  一级间接指针 → 索引块 → 数据块  │  ← 中等文件
├──────────────────────┤
│  二级间接指针 → 索引块 → 索引块 → 数据块  │  ← 大文件
├──────────────────────┤
│  三级间接指针 → ... │  ← 超大文件
└──────────────────────┘
```

这种设计兼顾小文件（直接指针快速访问）和大文件（多级间接索引）的存储效率。

## 5. 目录管理

### 5.1 目录结构演进

```
单级目录 → 二级目录 → 树形目录（多级） → 无环图目录（共享）
```

| 目录结构 | 说明 | 限制 |
|----------|------|------|
| **单级目录** | 所有文件在一个目录 | 文件不能重名 |
| **二级目录** | 每个用户一个目录 | 用户内不能重名 |
| **树形目录**（现代 OS） | 多级嵌套，路径唯一 | 不能共享文件 |
| **无环图目录** | 允许硬链接/软链接共享 | 需维护引用计数 |

### 5.2 路径解析

| 路径类型 | 说明 | 示例 |
|----------|------|------|
| **绝对路径** | 从根目录开始的完整路径 | `/var/log/app.log` |
| **相对路径** | 基于当前工作目录的路径 | `./config/app.yml` |
| **当前目录** | 进程的当前工作目录 | `.` |
| **上级目录** | 当前目录的父目录 | `..` |

## 6. 文件存储空间管理

| 方法 | 原理 | 特点 |
|------|------|------|
| **空闲表法** | 维护空闲块列表（连续块合并记录） | 适合连续分配 |
| **空闲链表法** | 空闲块链成链表 | 简单，但遍历慢 |
| **位示图法** | 每个块用 1 bit 标记（0=空闲, 1=占用） | **简单高效**，广泛使用 |
| **成组链接法** | Unix 采用，分组管理空闲块 | 兼顾速度和空间效率 |

```java
// 位示图逻辑示意（1 bit 表示一个块）
BitSet freeBlocks = new BitSet(totalBlocks);
freeBlocks.set(0, totalBlocks, true); // 初始化全空闲
boolean isFree = !freeBlocks.get(blockNo); // 检查块是否空闲
```

## 7. 文件共享与保护

### 7.1 访问控制

**DAC（自主访问控制）**——Linux 文件权限模型：

```
权限表示：rwx  r-x  r-x
           │    │    └── 其他用户权限（读+执行）
           │    └─────── 所属组权限（读+执行）
           └─────────── 所有者权限（读+写+执行）
```

| 权限 | 数字表示 | 说明 |
|------|----------|------|
| `rwx` | 7 | 读 + 写 + 执行 |
| `rw-` | 6 | 读 + 写 |
| `r-x` | 5 | 读 + 执行 |
| `r--` | 4 | 只读 |
| `---` | 0 | 无权限 |

### 7.2 Java 权限操作

```java
import java.nio.file.*;
import java.nio.file.attribute.PosixFilePermissions;

// 设置权限为 rwxr-xr-x（0755）
Files.setPosixFilePermissions(
    path, PosixFilePermissions.fromString("rwxr-xr-x"));

// 检查权限
Files.isReadable(path);
Files.isWritable(path);
Files.isExecutable(path);
```

> ⚠️ **跨平台注意**：`PosixFilePermission` 仅适用于 Linux/Unix。Windows 下需使用 `File` 类的 `canRead()`/`canWrite()`。

## 8. 缓存机制（Page Cache）

### 8.1 页缓存原理

```
用户空间                 内核空间                  磁盘
┌─────────┐  write()  ┌──────────┐  pdflush  ┌──────┐
│ 应用程序  │ ───────→ │  页缓存   │ ───────→ │ 磁盘  │
│ Buffer  │ ←─────── │ Page     │ ←─────── │      │
└─────────┘  read()   │ Cache    │          └──────┘
                      └──────────┘
```

| 机制 | 说明 | 配置命令 |
|------|------|----------|
| **Page Cache** | 缓存磁盘文件内容，减少磁盘 I/O | `free -h` 查看缓存使用 |
| **Buffer Cache** | 缓存块设备元数据 | 与 Page Cache 协同 |
| **写回策略（Write-back）** | 数据先写缓存，异步刷盘 | `sysctl -w vm.dirty_ratio=20` |
| **强制刷盘** | 立即写入磁盘 | Java `FileChannel.force()` |

### 8.2 fsync 与 Direct I/O

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| **默认（Write-back）** | 数据缓存在 Page Cache，异步刷盘 | 日志（允许少量数据丢失）|
| **fsync 强制刷盘** | 立即将数据写入磁盘，保证持久化 | 数据库 WAL、核心业务日志 |
| **O_DIRECT** | 绕过 Page Cache，直接 I/O | 自管理缓存的应用（数据库）|

```java
// Java 中强制刷盘
FileChannel channel = new FileOutputStream("data.log").getChannel();
channel.write(ByteBuffer.wrap("data".getBytes()));
channel.force(true); // 强制刷盘，确保数据持久化
```

## 9. 磁盘结构与调度算法

### 9.1 磁盘物理结构

```
磁盘由盘片组成
每个盘片有多个磁道（Track）
磁道分为多个扇区（Sector，通常 512B）
多个盘片同一位置的磁道形成柱面（Cylinder）
```

**寻道时间（Seek Time）+ 旋转延迟（Rotational Latency）+ 传输时间（Transfer Time）**

> ⚠️ **SSD 无寻道时间和旋转延迟**，所以传统磁盘调度算法对 SSD 意义不大。但队列深度和 I/O 合并依然重要。

### 9.2 磁盘调度算法

| 算法 | 策略 | 特点 |
|------|------|------|
| **FCFS** | 按请求顺序处理 | 简单，公平，效率低 |
| **SSTF**（最短寻道时间优先） | 先服务离当前磁头最近的请求 | 效率高，但可能**饥饿** |
| **SCAN**（电梯算法） | 单向扫描，到端后折返 | 公平性好，不考虑最远端情况 |
| **C-SCAN**（循环扫描） | 单向扫描，快速回起点（不服务） | 各位置等待时间更均匀 |
| **LOOK / C-LOOK** | SCAN 的优化，到最远端请求即折返 | 效率更高（不到底）|

## 10. 文件系统类型对比

| 文件系统 | 适用系统 | 最大文件 | 特性 | Java 注意点 |
|----------|----------|----------|------|-------------|
| **NTFS** | Windows | 16EB | 日志、压缩、加密、权限 | 路径分隔符 `\`，大小写**不敏感** |
| **EXT4** | Linux（主流） | 16TB | 日志、extent、延迟分配 | 路径分隔符 `/`，大小写**敏感**，权限严格 |
| **XFS** | Linux（大数据） | 8EB | 高并发、大文件友好 | 适合日志存储 |
| **FAT32** | 通用（旧） | 4GB | 兼容性最好 | 单文件不能超过 4GB |

## 11. 虚拟文件系统（VFS）

**VFS（Virtual File System）**：Linux 支持多种文件系统的关键——提供统一接口层。

```
系统调用（open/read/write）
    ↓
  VFS（统一接口：vnode / super_block）
    ↓
   ┌────┼────┐
   │    │    │
  EXT4  XFS  NFS  ...
```

| VFS 核心对象 | 说明 |
|--------------|------|
| **超级块（super_block）** | 已挂载文件系统的元信息 |
| **索引节点（inode / vnode）** | 文件属性与位置信息 |
| **目录项（dentry）** | 目录项的缓存（路径解析加速）|
| **文件对象（file）** | 进程打开的文件视图 |

## 12. Java 后端实战：文件操作的最佳实践

### 12.1 跨平台路径处理

```java
// 推荐方式（避免硬编码分隔符）
Path path = Paths.get("var", "log", "app.log");
// 或使用 File.separator
String path = "var" + File.separator + "log" + File.separator + "app.log";
```

### 12.2 大文件读写（内存映射 + 零拷贝）

```java
// 大文件读取（内存映射）
try (RandomAccessFile raf = new RandomAccessFile("/data/large.mp4", "r");
     FileChannel channel = raf.getChannel()) {
    MappedByteBuffer buffer = channel.map(
        FileChannel.MapMode.READ_ONLY, 0, channel.size());
    byte[] data = new byte[1024 * 1024];
    while (buffer.hasRemaining()) {
        int read = Math.min(buffer.remaining(), data.length);
        buffer.get(data, 0, read);
    }
}

// 零拷贝传输
sourceChannel.transferTo(0, sourceChannel.size(), targetChannel);
```

### 12.3 高频问题：too many open files

```bash
# 查看当前限制
ulimit -n

# 临时修改
ulimit -n 65535

# 永久修改（/etc/security/limits.conf）
* soft nofile 65535
* hard nofile 65535
```

```java
// Java 中使用 try-with-resources 自动关闭
try (FileInputStream fis = new FileInputStream("test.txt")) {
    // 自动关闭，不会泄漏文件描述符
}
```

### 12.4 避坑指南

| 坑点 | 解决方案 |
|------|----------|
| 硬编码路径分隔符 | 使用 `File.separator` 或 `Path.of()` |
| 大文件使用传统 I/O | 使用 NIO 的 `MappedByteBuffer` + 零拷贝 |
| 忽略 Linux 文件权限 | 部署时设置合理权限（`chmod 750`）|
| 频繁小文件读写 | 批量读写，利用 Page Cache |
| 文件描述符泄漏 | 使用 try-with-resources |
