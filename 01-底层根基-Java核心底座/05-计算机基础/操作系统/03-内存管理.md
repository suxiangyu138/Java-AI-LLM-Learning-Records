## 1. 内存分层架构

### 1.1 三层结构

```
物理内存（RAM）→ 虚拟内存 → 进程地址空间
```

| 层级 | 说明 | 速度 | 容量 |
|------|------|------|------|
| **CPU 寄存器** | CPU 内部，最快 | ~1ns | ~KB |
| **CPU 缓存（L1/L2/L3）** | 缓存数据和指令 | ~10ns | ~MB |
| **物理内存（RAM）** | 硬件内存，程序执行场所 | ~100ns | ~GB |
| **磁盘（Swap / Page File）** | 虚拟内存的交换区 | ~10ms | ~TB |

### 1.2 Linux 进程地址空间

```
高地址 ┌──────────────────────┐
       │    内核空间（1GB）    │ ← JVM 无法直接访问
       │    代码 + 数据 + 栈    │
       ├──────────────────────┤
       │    栈（向下增长）      │ ← 局部变量、方法调用
       │         ↓             │
       │        ─ ─ ─ ─        │
       │         ↑             │
       │    堆（向上增长）      │ ← JVM 堆、动态分配
       ├──────────────────────┤
       │   BSS 段（未初始化数据）│
       │   数据段（初始化数据）  │
       │   代码段（只读）       │ ← 程序指令
低地址 └──────────────────────┘
```

> 💡 **JVM 关联**：JVM 的所有内存区域（堆、栈、方法区、直接内存）本质上都是 OS 用户空间的一块虚拟内存。JVM 堆通过 `brk()` 扩展，直接内存通过 `mmap()` 分配。

## 2. 逻辑地址与物理地址

### 2.1 概念

| 地址类型 | 说明 |
|----------|------|
| **逻辑地址（虚拟地址）** | 程序编译生成，CPU 执行时使用的地址 |
| **物理地址（物理内存地址）** | 硬件实际内存地址，真实访问内存的地址 |
| **逻辑地址空间** | 程序视角的地址范围（如 0 ~ 4GB） |
| **物理地址空间** | 硬件实际的地址范围（取决于内存大小） |

### 2.2 地址转换

```
逻辑地址 → MMU（内存管理单元）→ 物理地址
              ↓
           页表 / 段表
```

地址转换是 OS 内存管理最核心的功能，由 **MMU（硬件）** 和 **OS 内核（软件）** 协作完成。

## 3. 程序的装入与链接

### 3.1 装入方式

| 装入方式 | 说明 | 特点 |
|----------|------|------|
| **绝对装入** | 程序编译时生成绝对物理地址 | 仅适合单道程序，不灵活 |
| **可重定位装入（静态重定位）** | 装入时修改指令中的地址 | 不支持程序移动 |
| **动态运行时装入** | 运行时 MMU 转换地址 | **现代 OS 采用**，支持分页/虚拟内存 |

### 3.2 链接方式

| 链接方式 | 说明 | 特点 |
|----------|------|------|
| **静态链接** | 链接时将所有库代码合并到可执行文件中 | 文件大，部署方便 |
| **装入时动态链接** | 装入时加载需要的库 | 灵活，可节省内存 |
| **运行时动态链接** | 运行时按需加载（如 .so、.dll）| **最灵活**，现代 OS 默认 |

## 4. 连续分配方式

### 4.1 分配方式对比

| 方式 | 说明 | 碎片问题 |
|------|------|----------|
| **单一连续分配** | 内存分系统区和用户区，只存一个用户程序 | 无（但利用率低） |
| **固定分区** | 预先划分固定大小的分区 | **内部碎片**（分区内未用完的空间） |
| **动态分区** | 按需分配大小不等的分区 | **外部碎片**（无法利用的零散空闲块） |

### 4.2 动态分区分配算法

| 算法 | 策略 | 特点 |
|------|------|------|
| **首次适应（First Fit）** | 从低地址找到第一个足够大的空闲分区 | 简单，速度快 |
| **最佳适应（Best Fit）** | 找到满足需求的最小空闲分区 | 避免大块浪费，但碎片更细碎 |
| **最坏适应（Worst Fit）** | 找到最大的空闲分区 | 减少小碎片，但大分区很快被用完 |
| **邻近适应（Next Fit）** | 从上一次分配位置继续查找 | 比 First Fit 更均匀分配 |

> ⚠️ 连续分配方式的**外部碎片**问题严重，且无法充分利用内存。现代 OS 几乎都采用**非连续分配**（分页/分段）。

## 5. 分页存储管理

### 5.1 核心思想

- **页面（Page）**：逻辑地址空间划分为大小相等的固定块（通常 4KB）
- **页框（Frame）**：物理内存划分为与页面等大的固定块
- **页表**：记录页面到页框的映射关系
- **地址转换**：MMU 通过页表完成逻辑地址 → 物理地址的转换

### 5.2 地址结构

```
逻辑地址 = [ 页号 P | 页内偏移 W ]
                ↑          ↑
           页表索引    页内位置（0 ~ 页大小-1）
```

**地址转换计算**（面试必考题）：

```
虚拟地址 A，页大小 L → 页号 P = A / L，偏移 W = A % L
查页表得到帧号 F → 物理地址 = F × L + W
```

**示例**：虚拟地址 4097，页大小 4096（4KB）
- 页号 = 4097 / 4096 = 1
- 页内偏移 = 4097 % 4096 = 1
- 查页表：页号 1 → 帧号 3
- 物理地址 = 3 × 4096 + 1 = 12289

### 5.3 页表

```
逻辑地址                 页表                   物理地址
┌──────────────┐   ┌──────────────┐   ┌──────────────────┐
│ 页号 │ 偏移量  │ → │ 页号→帧号映射  │ → │ 帧号 │ 偏移量    │
│  1   │   1    │   │ 1 → 3       │   │  3   │   1      │
└──────────────┘   └──────────────┘   └──────────────────┘
```

| 页表项内容 | 说明 |
|------------|------|
| **帧号** | 物理页框号 |
| **有效位** | 该页是否在内存中 |
| **访问位** | 页面是否被访问过（用于置换算法） |
| **修改位** | 页面是否被修改过（脏页标记）|
| **保护位** | 读/写/执行权限 |

### 5.4 快表（TLB）

**TLB（Translation Lookaside Buffer）**：页表的硬件缓存，位于 CPU 内部，用于加速地址转换。

| 关键指标 | 说明 |
|----------|------|
| 命中率 | **> 99%**（得益于局部性原理） |
| 命中延迟 | ~1 个 CPU 周期 |
| 缺失代价 | 多次访存查多级页表（~100 个 CPU 周期） |
| 管理方式 | 硬件管理（部分架构支持软件管理） |

### 5.5 多级页表

**问题**：32 位地址空间（4GB），4KB 页大小，需要 1M 个页表项（4MB 连续内存）。

**解决方案**：多级页表——页表本身也分页存放，按需分配。

```
一级页表 → 二级页表 → 三级页表 → 帧号
```

| 页表层级 | 地址位数 | 页大小 |
|----------|----------|--------|
| 32 位（二级页表） | 10 + 10 + 12 | 4KB |
| 64 位（四级页表） | Linux x86_64 使用 4 级 | 4KB |

## 6. 分段存储管理

### 6.1 核心思想

按程序的**逻辑结构**划分段（代码段、数据段、栈段），每个段大小不固定。

### 6.2 分页 vs 分段

| 对比维度 | 分页 | 分段 |
|----------|------|------|
| 划分依据 | 固定大小（**物理划分**） | 程序逻辑（**逻辑划分**） |
| 大小 | 固定（通常 4KB） | 不固定（由程序决定） |
| 地址结构 | 页号 + 页内偏移 | 段号 + 段内偏移 |
| 碎片 | 内部碎片（小） | 外部碎片 |
| 对程序员 | **透明**（看不到分页） | **可见**（可感知段结构） |
| 共享和保护 | 较难 | 容易（段级别控制） |
| 现代使用 | **主流**（多级页表 + TLB）| Intel 兼容模式保留 |

### 6.3 JVM 关联

| JVM 内存区域 | 类比 OS 分段 |
|--------------|-------------|
| 堆（Heap） | 数据段 |
| 栈（Stack） | 栈段 |
| 方法区（Metaspace） | 代码段 |
| 程序计数器 | — |

> 💡 JVM 内存分区（堆、栈、方法区）在逻辑上体现了分段思想，但底层实际使用分页机制分配物理内存。

## 7. 段页式存储管理

**思想**：先分段，每段内部分页。

```
逻辑地址 = [ 段号 | 段内页号 | 页内偏移 ]
```

| 优点 | 缺点 |
|------|------|
| 兼具分段的逻辑性和分页的高效性 | 地址转换需要查两级表（段表 + 页表）|
| 方便共享和保护 | 硬件实现复杂 |

> Intel x86 架构采用段页式机制，但现代 Linux 通过设置段寄存器"绕过"分段，实际只用分页。

## 8. 虚拟内存

### 8.1 核心思想

**虚拟内存**：程序不需要全部装入内存就能运行——只装入当前需要的部分。

基于**局部性原理**：

| 局部性类型 | 说明 | 实例 |
|------------|------|------|
| **时间局部性** | 刚访问的指令/数据短期内可能再次访问 | 循环中的代码 |
| **空间局部性** | 刚访问的地址附近的数据可能被访问 | 数组遍历、连续指令执行 |

### 8.2 虚拟内存的作用

| 作用 | 说明 | Java 影响 |
|------|------|-----------|
| **扩大内存空间** | 可用内存超过物理内存 | JVM 堆可超过物理内存 |
| **内存隔离** | 每个进程虚拟地址空间独立 | 保障 Java 进程安全 |
| **优化内存使用** | 页面置换将不常用页面换出 | JVM GC 与 OS 页面置换协同 |

### 8.3 请求分页

```
进程访问页面 → 页表查询 → 有效位=1（在内存）→ 正常访问
                          → 有效位=0（缺页）→ 缺页中断 → 从磁盘调入页面
```

**缺页中断处理流程**：

```
1. CPU 触发缺页中断
2. OS 检查虚拟地址合法性
3. 寻找空闲页框或置换一个页面
4. 从磁盘读取页面到页框
5. 更新页表（有效位置 1）
6. 重新执行被中断的指令
```

## 9. 页面置换算法

### 9.1 算法总览

| 算法 | 策略 | 优点 | 缺点 |
|------|------|------|------|
| **OPT**（最佳置换） | 置换**未来最久**不使用的页面 | 理论最优（不可实现） | 需预知未来访问序列 |
| **FIFO**（先进先出） | 置换最先进入内存的页面 | 简单 | **Belady 异常**（帧多反缺页多）|
| **LRU**（最近最久未使用） | 置换最长时间未被访问的页面 | 性能接近 OPT | 硬件实现成本高 |
| **Clock（NRU）** | 环形链表 + 访问位扫描 | LRU 近似，开销小 | 近似而非精确 |
| **改进型 Clock** | 访问位 + 修改位联合判断 | 优先换出未修改页 | 复杂度增加 |

### 9.2 Belady 异常

**定义**：采用 FIFO 置换算法时，物理块数增加，缺页率反而上升的异常现象。

```
页面访问序列：1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5

物理块=3：缺页 9 次
物理块=4：缺页 10 次（更多！）
```

### 9.3 LRU 的 Java 实现

```java
import java.util.LinkedHashMap;
import java.util.Map;

public class LRUCache<K, V> extends LinkedHashMap<K, V> {
    private final int capacity;

    public LRUCache(int capacity) {
        super(capacity, 0.75f, true); // accessOrder=true：按访问顺序排序
        this.capacity = capacity;
    }

    @Override
    protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
        return size() > capacity;
    }
}
```

## 10. 内存回收与抖动

### 10.1 内存回收场景

| 场景 | 说明 |
|------|------|
| **进程终止** | OS 回收所有虚拟和物理内存 |
| **Swap（内存交换）** | 物理内存不足时，将不常用页面交换到磁盘 |
| **OOM killer** | Linux 检测到内存耗尽时终止进程 |

### 10.2 抖动（Thrashing）

**定义**：频繁缺页、大量页面置换，导致系统效率暴跌。

**原因**：进程数过多，每个进程的工作集（活跃页面集合）无法全部装入内存。

**解决方案**：

| 方案 | 说明 |
|------|------|
| **工作集模型** | 确保每个进程的工作集都在内存中 |
| **降低多道程序度** | 中级调度挂起部分进程 |
| **增加物理内存** | 硬件扩容 |

### 10.3 JVM GC 与 OS 内存回收的协同

| 协同问题 | 说明 |
|----------|------|
| JVM GC 释放虚拟内存 | OS 根据系统情况决定是否回收物理内存 |
| GC 不及时 | 触发 Swap → 进程卡顿 |
| GC 过于频繁 | 增加系统调用开销 |

> ⚠️ **JVM 配置原则**：堆内存设置过大（超过物理内存 70%）可能导致页面置换频繁，触发 Swap，引发性能雪崩。

## 11. Linux 内核内存分配

### 11.1 伙伴系统（Buddy System）

Linux 内核的内存分配基础——以 2 的幂次分配，合并相邻空闲块。

```
需求 3KB → 分配 4KB（2^2）块
释放后 → 检查相邻 4KB 块是否空闲 → 合并为 8KB 块
```

### 11.2 Slab 分配器

内核对象缓存，减少频繁分配释放的开销——对象复用 + 硬件缓存友好。

### 11.3 用户态内存分配

| 函数 | 说明 | Java 关联 |
|------|------|-----------|
| **brk() / sbrk()** | 调整程序中断点，分配连续的虚拟内存 | JVM 堆初始分配、扩容 |
| **mmap()** | 分配非连续虚拟内存，文件/设备映射 | `DirectByteBuffer` |
| **malloc() / free()** | 用户态封装（C 库），封装 brk() 和 mmap() | JNI 调用需手动 free() |

## 12. Java 后端实战：OS 内存管理的落地应用

### 12.1 JVM 堆内存配置

```bash
# 物理内存 32G，生产环境配置
java -jar app.jar -Xms16G -Xmx16G -XX:+UseG1GC

# 禁用 Swap（生产环境推荐）
swapoff -a
echo 0 > /proc/sys/vm/swappiness
```

> **核心原则**：JVM 堆内存设置为 OS 物理内存的 **50%-70%**。过大导致页面置换频繁，过小导致 GC 频繁。

### 12.2 Java 进程 RSS 远大于 JVM 堆内存

**根因**：进程内存占用包括：
- JVM 堆（-Xmx 设置）
- 非堆内存（元空间、线程栈、代码缓存）
- 直接内存（DirectByteBuffer）
- 本地内存（JNI、共享库）

```bash
# 排查命令
ps -o rss,vsize -p <PID>        # 查看 RSS 和 VSZ
jmap -histo:live <PID> | grep DirectByteBuffer  # 查看直接内存
```

### 12.3 直接内存泄漏排查

```bash
# 监控 OS 内存
free -h
top
lsof -p <PID>

# JVM 参数限制直接内存
-XX:MaxDirectMemorySize=4G
```

### 12.4 不同 OS 环境下的内存配置

| 差异点 | Windows | Linux |
|--------|---------|-------|
| 虚拟内存 | pagefile.sys | swap 分区/文件 |
| 内存回收 | 被动式 | 主动式（kswapd）|
| OOM 处理 | 系统卡顿 | OOM killer 杀进程 |
| 建议 | 调整页面文件大小 | 禁用 Swap，使用 G1/ZGC |
