# I/O 与设备管理

## 📌 课程定位
I/O是程序与外部世界交互的通道。理解阻塞/非阻塞/多路复用的区别，是后端开发中网络框架选型和高并发设计的理论基础。

## 🎯 核心章节

### 1. I/O 设备分类
- **按传输速率**：低速(键盘/鼠标)、中速(打印机)、高速(磁盘/网卡)
- **按信息交换单位**：块设备(磁盘，以块为单位)、字符设备(键盘/网卡，以字符为单位)
- **设备控制器**：CPU通过控制器与设备交互，控制器内有寄存器(命令/状态/数据)

### 2. I/O 控制方式（复习 + 深入）
- **程序直接控制**：CPU轮询设备状态寄存器
- **中断驱动**：设备完成时发中断通知CPU——每次I/O仍需CPU介入
- **DMA**：CPU只参与开始和结束，数据搬运由DMA控制器完成

### 3. I/O 软件层次
```
用户层I/O软件（printf/scanf等库函数）
    ↓
设备独立性软件（统一接口、缓冲区管理、错误处理）
    ↓
设备驱动程序（与硬件交互的具体代码）
    ↓
中断处理程序（处理I/O完成信号）
```

### 4. 缓冲区技术（⭐ 重要）
- **单缓冲**：一个缓冲区，处理时间和I/O时间串行
- **双缓冲**：两个缓冲区交替，处理和数据传输并行——相当于流水线
- **循环缓冲**：多个缓冲区组成环，用于生产者-消费者模型

### 5. SPOOLing技术（假脱机）
- 将独占设备（如打印机）改造为共享设备
- 输入/输出井在磁盘上缓冲数据，输入/输出进程在后台调度

### 6. I/O 模型（⭐ 后端开发必知）
这是网络编程的核心概念——五种I/O模型：

- **阻塞I/O**：进程阻塞直到数据就绪并拷贝完成——Java BIO
- **非阻塞I/O**：立即返回，没数据返回错误——轮询浪费CPU
- **I/O多路复用**：select/poll/epoll 同时监听多个fd，就绪时通知——Nginx/Redis采用
  - **select**：fd_set位图，最多1024个，O(n)轮询
  - **poll**：pollfd数组，无数量限制但仍是O(n)轮询
  - **epoll（Linux）**：红黑树+就绪链表，O(1)获取就绪事件——高并发标配
- **信号驱动I/O**：数据就绪时内核发SIGIO信号通知
- **异步I/O（AIO）**：内核完成所有操作（包括数据拷贝）后通知——真正的异步

### 7. 设备分配
- **设备分配表**（SDT）：记录系统所有设备及状态
- **逻辑设备名→物理设备名**：设备独立性——程序用`/dev/tty`而非具体物理端口
- **虚拟设备**：如 `/dev/null`（丢弃数据）、`/dev/zero`（输出0）

## ✅ 学习建议
- epoll 的实现原理（红黑树+链表+回调）是后端高级面试常客，要能讲清楚
- 理解epoll的两种触发模式：LT（水平触发，默认）和 ET（边缘触发，高效）
- 对比 select/poll/epoll 的实现差异和适用场景
