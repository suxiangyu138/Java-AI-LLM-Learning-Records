## 一、I/O 模型板块（笔试最高频，占比 40%+）

> 四种 I/O 模型的区别、阻塞 / 非阻塞 I/O 的底层实现、I/O 多路复用（select/poll/epoll）、Java BIO/NIO/AIO 与操作系统 I/O 模型的对应关系。

### 常考题目 1：选择题 —— 四种 I/O 模型的区别

**题目**：下列关于操作系统 I/O 模型的描述，错误的是（ ）

A. 阻塞 I/O（BIO）中，用户态程序发起 I/O 请求后，会阻塞直到内核完成 I/O 操作

B. 非阻塞 I/O（NIO）中，用户态程序发起 I/O 请求后，无需阻塞，立即返回结果，未就绪时需轮询

C. I/O 多路复用（epoll）中，多路复用器会主动轮询所有注册的文件描述符，判断是否就绪

D. 异步 I/O（AIO）中，内核完成 I/O 操作（包括数据复制）后，通过回调通知用户态程序

**答案**：C

**考点解析**：epoll 采用"事件驱动"模式，无需轮询，仅通知就绪的 fd。select/poll 需要轮询所有 fd。

**核心特征区分法**：

| I/O 模型 | 核心特征 |
|----------|----------|
| 阻塞 I/O | 阻塞等待内核完成 |
| 非阻塞 I/O | 不阻塞、需轮询 |
| I/O 多路复用 | 单线程监听多 fd，select/poll 轮询、epoll 事件驱动 |
| 异步 I/O | 完全异步，内核完成所有操作后回调 |

**Java 实战延伸**：

- Java BIO → 操作系统阻塞 I/O
- Java NIO → 操作系统非阻塞 I/O + I/O 多路复用（Linux 下 epoll）
- Java AIO → 操作系统异步 I/O

### 常考题目 2：简答题 —— select、poll、epoll 的区别

| 对比维度 | select | poll | epoll |
|----------|--------|------|-------|
| fd 数量限制 | 有（默认 1024） | 无（基于链表） | 无（支持海量 fd） |
| 轮询方式 | 轮询所有 fd，效率低 | 轮询所有 fd，效率低 | **事件驱动**，仅通知就绪 fd |
| 内存拷贝 | 每次调用需拷贝 fd 集合 | 同 select | 注册时拷贝一次，后续无需 |
| 触发方式 | 水平触发（LT） | 水平触发（LT） | 水平触发（LT）+ 边缘触发（ET） |

> **易错点**：poll 无 fd 限制不意味着比 epoll 高效；epoll 的 ET 仅通知一次状态变化，LT 只要就绪就持续通知。

### 常考题目 3：编程题 —— Java NIO 实现高并发服务器

```java
import java.io.IOException;
import java.net.InetSocketAddress;
import java.nio.ByteBuffer;
import java.nio.channels.SelectionKey;
import java.nio.channels.Selector;
import java.nio.channels.ServerSocketChannel;
import java.nio.channels.SocketChannel;
import java.util.Iterator;

/**
 * Java NIO 高并发服务器（笔试标准答案）
 * 核心：利用 Selector（I/O 多路复用）监听多个 Channel，适配 Linux epoll 机制
 */
public class NioHighConcurrencyServer {
    public static void main(String[] args) throws IOException {
        ServerSocketChannel serverChannel = ServerSocketChannel.open();
        serverChannel.configureBlocking(false); // 关键：非阻塞模式
        serverChannel.bind(new InetSocketAddress(8080));

        Selector selector = Selector.open();
        serverChannel.register(selector, SelectionKey.OP_ACCEPT);
        System.out.println("NIO 高并发服务器已启动，监听端口 8080...");

        while (selector.select() > 0) {
            Iterator<SelectionKey> iterator = selector.selectedKeys().iterator();
            while (iterator.hasNext()) {
                SelectionKey key = iterator.next();
                if (key.isAcceptable()) {
                    ServerSocketChannel acceptChannel = (ServerSocketChannel) key.channel();
                    SocketChannel clientChannel = acceptChannel.accept();
                    clientChannel.configureBlocking(false);
                    clientChannel.register(selector, SelectionKey.OP_READ);
                    System.out.println("新客户端连接：" + clientChannel.getRemoteAddress());
                } else if (key.isReadable()) {
                    SocketChannel clientChannel = (SocketChannel) key.channel();
                    ByteBuffer buffer = ByteBuffer.allocate(1024);
                    int len = clientChannel.read(buffer);
                    if (len > 0) {
                        buffer.flip();
                        byte[] data = new byte[buffer.remaining()];
                        buffer.get(data);
                        String request = new String(data);
                        System.out.println("收到客户端请求：" + request);
                        String response = "服务器响应：" + request;
                        ByteBuffer responseBuffer = ByteBuffer.wrap(response.getBytes());
                        clientChannel.write(responseBuffer);
                    } else if (len == -1) {
                        clientChannel.close();
                        key.cancel();
                        System.out.println("客户端断开连接");
                    }
                }
                iterator.remove(); // 关键：移除已处理事件
            }
        }
        serverChannel.close();
        selector.close();
    }
}
```

**笔试评分点**：

1. ✅ Channel 必须设置为非阻塞模式（`configureBlocking(false)`）
2. ✅ Selector 注册事件（`OP_ACCEPT` 监听连接，`OP_READ` 监听读事件）
3. ✅ 处理就绪事件后必须调用 `iterator.remove()`，避免重复处理
4. ✅ 缓冲区的 `flip()` 方法切换为读模式

## 二、进程 / 线程管理板块（笔试高频，占比 30%）

### 常考题目 1：选择题 —— 进程与线程的区别

**题目**：下列关于进程和线程的描述，正确的是（ ）

A. 进程是资源分配的基本单位，线程是调度的基本单位

B. 进程之间共享所有资源，线程之间不共享任何资源

C. 进程切换的开销小于线程切换的开销

D. 一个进程只能包含一个线程

**答案**：A

**Java 实战延伸**：Java 线程在 Linux 下通过 JNI 调用 `clone()` 系统调用创建轻量级进程（LWP），每个 Java 线程对应一个 OS 的 LWP。

### 常考题目 2：简答题 —— 死锁的产生条件、预防与解决

**死锁 4 个必要条件**：

| 条件 | 说明 |
|------|------|
| 互斥 | 资源只能被一个进程/线程占用 |
| 请求与保持 | 持有部分资源，同时请求其他资源 |
| 不可剥夺 | 已持有资源无法被强制剥夺 |
| 循环等待 | 多个进程/线程形成循环等待链 |

**Java 中预防死锁的代码示例**：

```java
import java.util.concurrent.locks.ReentrantLock;

/**
 * Java 避免死锁：按固定顺序获取锁
 */
public class AvoidDeadLock {
    private static final ReentrantLock lock1 = new ReentrantLock();
    private static final ReentrantLock lock2 = new ReentrantLock();

    static class Thread1 extends Thread {
        @Override
        public void run() {
            try {
                lock1.lock();
                Thread.sleep(100);
                lock2.lock();
                System.out.println("Thread1 执行完成");
            } catch (InterruptedException e) {
                e.printStackTrace();
            } finally {
                lock2.unlock();
                lock1.unlock();
            }
        }
    }

    static class Thread2 extends Thread {
        @Override
        public void run() {
            try {
                lock1.lock(); // 同样先获取 lock1，破坏循环等待
                Thread.sleep(100);
                lock2.lock();
                System.out.println("Thread2 执行完成");
            } catch (InterruptedException e) {
                e.printStackTrace();
            } finally {
                lock2.unlock();
                lock1.unlock();
            }
        }
    }
}
```

## 三、内存管理板块（笔试中频，占比 20%）

### 常考题目 1：选择题 —— 页面置换算法

**题目**：下列页面置换算法中，能有效避免"Belady 异常"的是（ ）

A. FIFO &nbsp;&nbsp; B. LRU &nbsp;&nbsp; C. OPT &nbsp;&nbsp; D. Clock

**答案**：B（LRU）

**Java 实战延伸**：LinkedHashMap 实现 LRU 缓存

```java
import java.util.LinkedHashMap;
import java.util.Map;

public class LRUCache<K, V> extends LinkedHashMap<K, V> {
    private final int capacity;

    public LRUCache(int capacity) {
        super(capacity, 0.75f, true); // accessOrder=true：按访问顺序排序
        this.capacity = capacity;
    }

    @Override
    protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
        return size() > capacity;
    }

    public static void main(String[] args) {
        LRUCache<Integer, String> cache = new LRUCache<>(3);
        cache.put(1, "A");
        cache.put(2, "B");
        cache.put(3, "C");
        System.out.println(cache); // {1=A, 2=B, 3=C}
        cache.get(1);
        System.out.println(cache); // {2=B, 3=C, 1=A}
        cache.put(4, "D");
        System.out.println(cache); // {3=C, 1=A, 4=D}
    }
}
```

### 常考题目 2：简答题 —— 内存泄漏与内存溢出

| 概念 | 定义 | 关系 |
|------|------|------|
| **内存泄漏**（Memory Leak） | 已分配内存不再使用但无法回收 | 可积累，是导致 OOM 的主因 |
| **内存溢出**（OOM） | 需要的内存超过可用空间 | 直接崩溃 |

**避免方法**：

- 及时关闭资源（try-with-resources）
- 避免静态集合引用
- 合理配置 JVM 参数（-Xms, -Xmx）
- 使用对象池复用对象

## 四、文件系统板块（笔试低频，占比 10%）

### 常考题目：选择题 —— 文件权限

**题目**：Linux 系统中，权限 "rwxr-xr-x" 的含义是？

**答案**：B — 所有者拥有读、写、执行权限，组用户和其他用户拥有读、执行权限

**Java 实战延伸**：

```java
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.Paths;
import java.nio.file.attribute.PosixFilePermissions;

public class FilePermissionDemo {
    public static void main(String[] args) throws Exception {
        Path logPath = Paths.get("/var/log/app.log");
        // 设置权限为 rwxr-xr-x（对应 0755）
        Files.setPosixFilePermissions(logPath, PosixFilePermissions.fromString("rwxr-xr-x"));
        System.out.println("文件权限设置成功");
    }
}
```
