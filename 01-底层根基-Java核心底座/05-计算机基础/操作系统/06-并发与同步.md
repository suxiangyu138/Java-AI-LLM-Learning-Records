## 1. 并发与并行的本质

### 1.1 定义

| 概念 | 定义 | 硬件要求 |
|------|------|----------|
| **并发（Concurrency）** | 多个程序在一段时间内交替执行（逻辑同时） | 单核即可 |
| **并行（Parallelism）** | 多个程序在同一时刻真正同时执行（物理同时） | 多核 |

```
并发（单核）：          │  并行（多核）：
时间点1: A执行 B等待    │  时间点1: A在核1 B在核2
时间点2: A等待 B执行    │  时间点2: A在核1 B在核2
...                     │  ...
```

### 1.2 并发问题的根源

**竞态条件（Race Condition）**：多个执行流共享可变状态，且执行结果依赖于执行顺序。

```
竞态条件 = 共享可变状态 + 非原子操作 + 不恰当的执行顺序
```

**示例**：`count++` 本质是三条指令
```
load count → add 1 → store count
```
两个线程同时执行可能导致丢失更新。

## 2. 竞态条件与临界区

### 2.1 临界资源与临界区

| 概念 | 定义 |
|------|------|
| **临界资源** | 同一时刻只允许一个进程访问的资源（打印机、共享变量） |
| **临界区（Critical Section）** | 访问临界资源的代码段 |

### 2.2 临界区访问原则

| 原则 | 说明 |
|------|------|
| **互斥进入** | 一次只允许一个进程进入临界区 |
| **有空让进** | 无进程在临界区时，应允许一个等待进程进入 |
| **有限等待** | 进程应在有限时间内进入临界区（避免饥饿） |
| **让权等待** | 不能进入时立即释放 CPU（避免忙等） |

## 3. 互斥锁（Mutex）

### 3.1 定义

**互斥锁**：保证同一时刻只有一个执行流进入临界区的同步机制。

### 3.2 互斥锁的实现

```
lock(mutex)：
    if (mutex == 0) {
        mutex = 1;    // 上锁成功
        return;
    } else {
        阻塞当前线程，加入等待队列；
    }

unlock(mutex)：
    mutex = 0;
    if (等待队列不空) {
        唤醒一个等待线程；
    }
```

### 3.3 OS 互斥锁 vs Java 锁

| OS 锁机制 | Java 对应 | 特点 |
|-----------|-----------|------|
| `pthread_mutex_lock()` | `synchronized` | 阻塞等待，重量级 |
| `pthread_spin_lock()` | — | 自旋等待，轻量级 |
| `futex`（Linux 快速用户态互斥） | `LockSupport.park()` | 用户态 + 内核态结合 |
| `pthread_rwlock_t` | `ReentrantReadWriteLock` | 读写分离 |

## 4. 信号量（Semaphore）

### 4.1 定义

信号量是 Dijkstra 提出的同步机制，本质是一个**计数器**，控制多个线程对共享资源的并发访问。

### 4.2 P/V 操作

| 操作 | 别名 | 语义 |
|------|------|------|
| **P 操作** | `wait()` / `acquire()` | 信号量减 1，若 < 0 则阻塞 |
| **V 操作** | `signal()` / `release()` | 信号量加 1，若 ≤ 0 则唤醒 |

```
P(s)：s.value--;  if (s.value < 0) 阻塞当前进程
V(s)：s.value++;  if (s.value <= 0) 唤醒一个等待进程
```

### 4.3 二元信号量 vs 计数信号量

| 类型 | 初始值 | 功能 | 与互斥锁的关系 |
|------|--------|------|---------------|
| **二元信号量** | 0 或 1 | 互斥 | 功能等同互斥锁 |
| **计数信号量** | N（N > 1）| 控制并发数量 | — |

### 4.4 Java Semaphore 示例

```java
import java.util.concurrent.Semaphore;

public class SemaphoreDemo {
    // 允许 3 个线程并发访问
    private static final Semaphore semaphore = new Semaphore(3);

    public static void main(String[] args) {
        for (int i = 0; i < 10; i++) {
            new Thread(() -> {
                try {
                    semaphore.acquire();   // P 操作
                    System.out.println(Thread.currentThread().getName() + " 访问资源");
                    Thread.sleep(1000);
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                } finally {
                    semaphore.release();   // V 操作
                }
            }, "线程-" + i).start();
        }
    }
}
```

## 5. 管程（Monitor）

### 5.1 定义

**管程**：封装共享数据和对数据的操作，保证同一时刻只有一个进程能访问管程内的数据。

### 5.2 管程 vs 信号量

| 对比维度 | 管程 | 信号量 |
|----------|------|--------|
| 编程复杂度 | **低**（封装性好）| 高（需手动 PV）|
| 互斥保证 | 内置 | 显式调用 |
| 错误风险 | 低 | 高（忘记 V 操作则死锁）|
| Java 对应 | `synchronized` | `Semaphore` |

### 5.3 Java 中的管程

```java
// synchronized 关键字实现管程
class Account {
    private int balance;

    public synchronized void withdraw(int amount) {
        // 管程保证同一时刻只有一个线程执行此方法
        if (balance >= amount) {
            balance -= amount;
        }
    }
}
```

> 💡 每个 Java 对象都有一个**监视器锁（Monitor Lock）**，`synchronized` 的本质就是获取对象的监视器锁。

## 6. 条件变量

### 6.1 概念

**条件变量**：与互斥锁配合，实现等待-通知模式的同步机制。

| 操作 | 说明 |
|------|------|
| **wait()** | 原子地释放互斥锁并进入等待状态 |
| **signal()** | 唤醒一个等待该条件的线程 |
| **broadcast()** | 唤醒所有等待该条件的线程 |

### 6.2 条件变量 vs Java 机制

| 条件变量操作 | Java 对应 |
|-------------|-----------|
| `pthread_cond_wait()` | `Object.wait()` |
| `pthread_cond_signal()` | `Object.notify()` |
| `pthread_cond_broadcast()` | `Object.notifyAll()` |

> ⚠️ **虚假唤醒（Spurious Wakeup）**：`wait()` 可能在没有被 `notify()` 的情况下返回。必须在循环中检查条件：
> ```java
> synchronized (lock) {
>     while (!condition) { // 使用 while 而非 if
>         lock.wait();
>     }
> }
> ```

## 7. 自旋锁与读写锁

### 7.1 自旋锁（Spinlock）

**定义**：获取锁时若锁被占用，则不断循环检查（忙等），而不阻塞。

| 场景 | 推荐 | 原因 |
|------|------|------|
| 临界区极短 | **自旋锁** | 阻塞/唤醒开销更大 |
| 临界区较长 | **互斥锁** | 避免 CPU 空转 |

```java
// Java 中自旋的体现（AtomicInteger 的 CAS 实现）
public class SpinLockDemo {
    private AtomicBoolean locked = new AtomicBoolean(false);

    public void lock() {
        while (!locked.compareAndSet(false, true)) {
            // 自旋等待
        }
    }

    public void unlock() {
        locked.set(false);
    }
}
```

### 7.2 读写锁

**核心思想**：读操作不互斥（可并发读），写操作互斥（写独占）。

| 场景 | 策略 |
|------|------|
| 读-读 | **不互斥**（可同时读） |
| 读-写 | **互斥**（读时不能写） |
| 写-写 | **互斥**（不能同时写）|

```java
import java.util.concurrent.locks.ReentrantReadWriteLock;

public class ReadWriteLockDemo {
    private final ReentrantReadWriteLock rwLock = new ReentrantReadWriteLock();
    private final Lock readLock = rwLock.readLock();
    private final Lock writeLock = rwLock.writeLock();
    private int data;

    public int read() {
        readLock.lock();
        try { return data; }
        finally { readLock.unlock(); }
    }

    public void write(int value) {
        writeLock.lock();
        try { data = value; }
        finally { writeLock.unlock(); }
    }
}
```

## 8. 经典同步问题

### 8.1 生产者-消费者

**问题**：生产者向有限缓冲区放数据，消费者从缓冲区取数据。缓冲区满时生产者等待，空时消费者等待。

```
信号量：mutex = 1（互斥）, full = 0（已满项数）, empty = N（空闲项数）

生产者：                       消费者：
P(empty)                      P(full)
P(mutex)                      P(mutex)
放数据到缓冲区                 从缓冲区取数据
V(mutex)                      V(mutex)
V(full)                       V(empty)
```

### 8.2 读者-写者

| 策略 | 原则 | 问题 |
|------|------|------|
| **读优先** | 只要有读者在读，后续读者直接进入 | 写者可能饥饿 |
| **写优先** | 只要有写者在等，后续读者阻塞 | 读者可能饥饿 |
| **公平策略** | 按到达顺序交替服务 | 吞吐量下降 |

### 8.3 哲学家进餐

**问题**：5 个哲学家围坐，每两人之间一支筷子。哲学家需要同时拿两根筷子才能吃饭。

**死锁预防方案**：规定所有哲学家先拿编号小的筷子（破坏循环等待）。

## 9. 死锁

### 9.1 定义

多个进程（或线程）互相持有对方所需的资源，且都无法主动释放自己持有的资源，导致所有进程都陷入永久阻塞。

### 9.2 四大必要条件（必须同时满足）

| 条件 | 说明 | Java 场景 |
|------|------|-----------|
| **互斥** | 资源同一时间只能被一个线程持有 | `synchronized` 锁 |
| **持有并等待** | 持有部分资源的同时请求其他资源 | 持有锁 A 请求锁 B |
| **不可剥夺** | 已持有资源无法被强制剥夺 | 同步锁默认不可抢占 |
| **循环等待** | 多个线程形成循环等待链 | A 等 B，B 等 C，C 等 A |

> 💡 只要打破**任意一个**条件，死锁就不会发生。

### 9.3 死锁处理策略

| 策略 | 方法 | 说明 |
|------|------|------|
| **预防** | 破坏四个必要条件之一 | 固定锁顺序、一次性获取所有资源 |
| **避免** | 银行家算法 | 分配前判断是否安全 |
| **检测 + 解除** | 资源分配图化简法 | 允许死锁发生，检测后终止进程或剥夺资源 |
| **鸵鸟策略** | 假装没看见 | 多数 OS 的做法（死锁很少发生）|

### 9.4 银行家算法

**核心思想**：分配资源前检查是否会使系统进入**不安全状态**，若会则不分配。

```
安全状态 = 存在一个安全序列，使得每个进程都能按序获得所需资源并完成。
```

| 数据结构 | 说明 |
|----------|------|
| Available | 系统可用资源数 |
| Max | 每个进程的最大需求 |
| Allocation | 每个进程已分配的资源数 |
| Need | 每个进程还需要多少（Need = Max - Allocation）|

### 9.5 Java 死锁示例

```java
public class DeadLockDemo {
    private static final Object lockA = new Object();
    private static final Object lockB = new Object();

    public static void main(String[] args) {
        // 线程 1：持有 lockA，等待 lockB
        new Thread(() -> {
            synchronized (lockA) {
                try { Thread.sleep(100); } catch (InterruptedException e) { }
                synchronized (lockB) { // 永远等不到
                    System.out.println("线程1执行");
                }
            }
        }).start();

        // 线程 2：持有 lockB，等待 lockA
        new Thread(() -> {
            synchronized (lockB) {
                try { Thread.sleep(100); } catch (InterruptedException e) { }
                synchronized (lockA) { // 永远等不到
                    System.out.println("线程2执行");
                }
            }
        }).start();
    }
}
```

### 9.6 Java 死锁排查

| 方法 | 命令/工具 | 说明 |
|------|-----------|------|
| **jps + jstack** | `jps -l` → `jstack <PID>` | 输出包含 "Found one Java-level deadlock" |
| **VisualVM** | `jvisualvm.exe` | 可视化，自动检测死锁 |
| **Arthas** | `thread -d` | 线上场景，功能强大 |
| **jconsole** | JDK 自带 | 连接进程，查看线程状态 |

## 10. Java 并发同步实战

### 10.1 synchronized 底层原理

```java
public class SyncDemo {
    // 锁对象：当前实例
    public synchronized void method() { /* 临界区 */ }

    // 锁对象：类 Class 对象
    public static synchronized void staticMethod() { /* 临界区 */ }

    // 锁对象：自定义对象
    public void block() {
        synchronized (this) { /* 临界区 */ }
    }
}
```

`synchronized` 在 JVM 中通过 **monitorenter / monitorexit** 字节码指令实现，底层依赖 OS 的互斥锁（Mutex）。

### 10.2 ReentrantLock 使用

```java
import java.util.concurrent.locks.ReentrantLock;

public class LockDemo {
    private final ReentrantLock lock = new ReentrantLock();

    public void safeMethod() {
        lock.lock();
        try {
            // 临界区
        } finally {
            lock.unlock(); // 必须在 finally 中释放
        }
    }
}
```

### 10.3 死锁预防（固定锁顺序）

```java
// 所有线程按相同顺序获取锁，破坏"循环等待"
public class SafeTransfer {
    private final ReentrantLock lockA = new ReentrantLock();
    private final ReentrantLock lockB = new ReentrantLock();

    public void transfer() {
        // 统一先获取 lockA，再获取 lockB
        lockA.lock();
        try {
            Thread.sleep(100);
            lockB.lock();
            try {
                // 转账逻辑
            } finally { lockB.unlock(); }
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        } finally { lockA.unlock(); }
    }
}
```

### 10.4 线程安全设计原则

| 原则 | 说明 |
|------|------|
| **不可变性** | 使用 `final` 字段、不可变对象 |
| **线程封闭** | 栈封闭、ThreadLocal |
| **同步策略** | 合理使用锁，避免死锁 |
| **分段锁** | `ConcurrentHashMap` 的分段锁思想 |
| **CAS + 自旋** | 无锁编程，轻量级并发（`AtomicInteger`）|
