## 一、核心前提：Java 后端为什么必须懂 OS 多处理机系统？

| 原因 | 说明 |
|------|------|
| **Java 并发底层依赖** | 线程、锁、线程池本质上是对 OS 多处理机调度机制的封装 |
| **性能优化关键** | CPU 利用率、上下文切换、多线程竞争，根源在多处理机调度 |
| **分布式基础** | 分布式系统是多处理机系统的"扩展形态" |

## 二、OS 多处理机系统核心理论

### 2.1 多处理机系统的分类

#### 紧密耦合多处理机（SMP）

| 特征 | 说明 |
|------|------|
| 内存 | 多个 CPU 共享同一套系统内存 |
| 地位 | 所有 CPU 平等，无主从之分 |
| 瓶颈 | CPU 数量过多时，内存总线成为瓶颈 |
| **Java 关联** | 线程池核心线程数配置需结合 CPU 核心数 |

#### 松散耦合多处理机（DMP）

| 特征 | 说明 |
|------|------|
| 内存 | 每个 CPU 拥有独立本地内存 |
| 通信 | 通过高速互连网络交换数据 |
| 优势 | 可扩展性强 |
| **Java 关联** | 分布式系统多节点本质是 DMP 架构的延伸 |

### 2.2 多处理机系统的核心机制

#### 进程 / 线程调度机制

| 调度策略 | 说明 | Java 关联 |
|----------|------|-----------|
| **全局调度**（SMP） | 单个全局就绪队列 | ThreadPoolExecutor 的工作队列 |
| **局部调度**（DMP/NUMA） | 每个 CPU 本地队列，任务窃取 | Fork/Join 框架的任务窃取算法 |

#### 同步与互斥机制

| OS 机制 | 说明 | Java 对应 |
|---------|------|-----------|
| 互斥锁（Mutex） | 保证同一时刻只有一个 CPU 访问共享资源 | synchronized |
| 信号量（Semaphore） | 控制资源并发访问数量 | ReentrantLock |

#### 内存一致性模型

| 模型 | 说明 | Java 对应 |
|------|------|-----------|
| 释放-获取一致性 | 释放锁后修改对其他 CPU 可见 | volatile（禁止重排序） |
| 顺序一致性 | 所有 CPU 看到相同的执行顺序 | synchronized |

### 2.3 性能瓶颈

| 瓶颈 | 说明 | Java 优化方向 |
|------|------|---------------|
| 总线瓶颈 | 多 CPU 同时访问内存导致总线冲突 | 减少锁竞争 |
| 资源竞争 | 共享资源竞争导致上下文切换频繁 | 分段锁、无锁编程 |
| 调度开销 | 线程过多时上下文切换开销增大 | 合理设置线程池参数 |

## 三、Java 后端实战：多处理机系统的落地应用

### 3.1 实战场景 1：线程池参数优化

**根因**：SMP 架构中，线程数远大于 CPU 核心数时，上下文切换开销大。

```java
// CPU 密集型任务
int corePoolSize = Runtime.getRuntime().availableProcessors() + 1;

// I/O 密集型任务
int corePoolSize = Runtime.getRuntime().availableProcessors() * 2;
```

| 任务类型 | 核心线程数公式 | 队列建议 |
|----------|---------------|----------|
| CPU 密集型 | CPU 核心数 + 1 | 容量小（如 ArrayBlockingQueue） |
| I/O 密集型 | CPU 核心数 × 2 | 容量大（如 LinkedBlockingQueue） |

### 3.2 实战场景 2：并发锁选型

| 锁 | 底层机制 | 适用场景 |
|---|----------|----------|
| **synchronized** | OS 互斥锁（Mutex），重量级锁 | 锁竞争不激烈 |
| **ReentrantLock** | OS 信号量（Semaphore），支持自旋 | 锁竞争激烈 |

```java
// 锁竞争激烈时使用 ReentrantLock
private final ReentrantLock lock = new ReentrantLock();

public void update() {
    lock.lock();
    try {
        // 业务逻辑
    } finally {
        lock.unlock();
    }
}
```

### 3.3 实战场景 3：解决 CPU 利用率过低

**常见原因**：

1. 线程数小于 CPU 核心数
2. 任务依赖过重（串行执行）
3. 锁竞争过于激烈

**解决方案**：

```java
// 使用 CompletableFuture 并行执行任务
CompletableFuture.supplyAsync(() -> task1())
    .thenCombine(CompletableFuture.supplyAsync(() -> task2()), (r1, r2) -> r1 + r2);
```

### 3.4 实战场景 4：分布式任务调度

**核心原则**：

- 任务分片，并行执行
- 节点负载感知
- 任务去重（分布式锁）

## 四、核心总结

| 知识点 | 关键要点 |
|--------|----------|
| **SMP 架构** | 线程池参数匹配 CPU 核心数 |
| **同步互斥** | 锁选型适配 OS 机制，减少竞争 |
| **内存一致性** | volatile 基于 OS 内存屏障 |
| **分布式调度** | 模拟 OS 负载均衡和互斥机制 |

> **避坑提醒**：不要只关注 Java 并发 API 的使用，而忽略 OS 多处理机的底层逻辑；不要盲目增加线程数、滥用锁。
