## 二、文件系统核心原理

### 2.1 三层结构

```
用户层（Java File/Path/Stream API）
    ↓
文件系统层（inode、目录项、权限、缓存）
    ↓
存储层（磁盘、SSD 物理读写）
```

> 调用 `File.createNewFile()` 时，底层依次经过：用户层 → 文件系统层（解析路径、检查权限、分配 inode）→ 存储层。

### 2.2 inode 与目录项

#### inode（索引节点）

每个文件对应一个唯一的 inode，包含：

| 信息 | Java 对应方法 |
|------|---------------|
| 文件权限（rwx） | `file.canRead()`/`canWrite()` |
| 文件大小 | `file.length()` |
| 修改时间 | `file.lastModified()` |
| 数据块指针 | 指向磁盘物理地址 |

> **关键注意**：inode **不存储文件名**。文件名存储在"目录项"中。修改文件名本质是修改目录项的映射。

#### 目录项

目录也是一个文件，其数据块存储"目录项列表"（文件名 → inode 号映射）。`file.listFiles()` 本质是读取目录文件的数据块。

### 2.3 缓存机制（Page Cache）

```
用户空间                        内核空间                    磁盘
┌─────────┐     系统调用      ┌──────────┐   pdflush   ┌──────┐
│ 应用程序  │ ───────────────► │ 页缓存     │ ─────────► │ 磁盘   │
│ Buffer  │ ◄─────────────── │ Page Cache│ ◄───────── │      │
└─────────┘                  └──────────┘            └──────┘
```

**关键点**：

- 写操作通常先写页缓存（write-back），由内核异步刷盘
- `fsync` / `fdatasync` 强制刷盘
- `O_DIRECT` 绕过页缓存直接 I/O

### 2.4 文件系统类型对比

| 文件系统 | 适用系统 | Java 注意点 |
|----------|----------|-------------|
| **NTFS** | Windows | 路径分隔符 `\\`，大小写不敏感 |
| **EXT4** | Linux（主流） | 路径分隔符 `/`，大小写敏感，权限严格 |
| **XFS** | Linux（大数据） | 单文件最大 16EB，适合日志存储 |

## 三、Java 后端实战：文件操作的最佳实践

### 3.1 场景 1：日志文件的高效读写

```xml
<!-- Logback 配置：异步日志 + 滚动策略 + 利用 Page Cache -->
<configuration>
    <appender name="FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>/var/log/myapp/app.log</file>
        <rollingPolicy class="ch.qos.logback.core.rolling.TimeBasedRollingPolicy">
            <fileNamePattern>/var/log/myapp/app.%d{yyyy-MM-dd}.log</fileNamePattern>
            <maxHistory>30</maxHistory>
        </rollingPolicy>
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss} [%thread] %-5level %logger{36} - %msg%n</pattern>
        </encoder>
        <immediateFlush>false</immediateFlush>
    </appender>
    <appender name="ASYNC_FILE" class="ch.qos.logback.classic.AsyncAppender">
        <appender-ref ref="FILE"/>
        <queueSize>1024</queueSize>
    </appender>
</configuration>
```

### 3.2 场景 2：大文件上传下载（内存映射 + 零拷贝）

```java
// 大文件读取（内存映射方式）
public class LargeFileReadDemo {
    public static void main(String[] args) throws Exception {
        try (RandomAccessFile raf = new RandomAccessFile("/var/upload/largeFile.mp4", "r");
             FileChannel channel = raf.getChannel()) {
            MappedByteBuffer buffer = channel.map(
                FileChannel.MapMode.READ_ONLY, 0, channel.size());
            byte[] data = new byte[1024 * 1024];
            while (buffer.hasRemaining()) {
                int read = Math.min(buffer.remaining(), data.length);
                buffer.get(data, 0, read);
            }
        } finally {
            System.gc();  // 手动释放内存映射
        }
    }
}
```

```java
// 大文件写入（内存映射方式）
public class LargeFileWriteDemo {
    public static void main(String[] args) throws Exception {
        try (RandomAccessFile raf = new RandomAccessFile("/var/upload/largeFile.mp4", "rw");
             FileChannel channel = raf.getChannel()) {
            MappedByteBuffer buffer = channel.map(
                FileChannel.MapMode.READ_WRITE, 0, 1024 * 1024 * 1024); // 1GB
            byte[] data = new byte[1024 * 1024];
            for (int i = 0; i < 1024; i++) {
                buffer.put(data);
            }
            buffer.force();  // 强制刷盘
        }
    }
}
```

### 3.3 场景 3：配置文件加载

```java
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.Paths;
import java.nio.file.attribute.PosixFilePermissions;

public class AppConfig {
    public void loadConfig() throws Exception {
        Path path = Paths.get("/var/config/application.yml");

        // 1. 检查文件是否存在
        if (!Files.exists(path)) {
            throw new RuntimeException("配置文件不存在：" + path);
        }

        // 2. Linux 环境下检查文件权限
        if (System.getProperty("os.name").toLowerCase().contains("linux")) {
            Files.setPosixFilePermissions(path,
                PosixFilePermissions.fromString("rw-r--r--"));
        }

        // 3. 读取文件内容
        String configContent = Files.readString(path);
        System.out.println("配置内容：" + configContent);
    }
}
```

### 3.4 场景 4：文件权限与安全

```java
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.Paths;
import java.nio.file.attribute.PosixFilePermission;
import java.util.HashSet;
import java.util.Set;

public class FilePermissionDemo {
    public static void main(String[] args) throws Exception {
        Path sensitiveFile = Paths.get("/var/config/secret.key");

        // 设置权限：所有者读写，其他无权限（rw-------）
        Set<PosixFilePermission> permissions = new HashSet<>();
        permissions.add(PosixFilePermission.OWNER_READ);
        permissions.add(PosixFilePermission.OWNER_WRITE);
        Files.setPosixFilePermissions(sensitiveFile, permissions);
    }
}
```

## 四、核心总结与避坑指南

### 4.1 核心总结

Java 后端的 I/O 能力，本质是对文件系统底层逻辑的理解和合理运用。

| 底层机制 | 实战价值 |
|----------|----------|
| inode 与目录项 | 理解文件操作（重命名、删除）的本质 |
| Page Cache | 优化读写效率，利用缓存 |
| 文件权限 | 跨环境部署的安全保障 |
| 文件系统类型 | 适配不同 OS，避免兼容性问题 |

### 4.2 避坑指南

| 坑点 | 解决方案 |
|------|----------|
| 硬编码路径分隔符 | 使用 `File.separator` 或 `Path.of()` |
| 大文件使用传统 I/O | 使用 NIO 的 MappedByteBuffer + 零拷贝 |
| MappedByteBuffer 未释放 | 手动调用 `System.gc()` 或 `Cleaner.clean()` |
| 忽略 Linux 文件权限 | 部署时设置合理权限 |
| 频繁小文件读写 | 批量读写，利用文件系统缓存 |
