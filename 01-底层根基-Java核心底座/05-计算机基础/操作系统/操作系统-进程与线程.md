## 一、核心理论：进程与线程的本质

### 1.1 进程：操作系统资源分配的最小单位

进程是一个"正在运行的程序"。每个进程拥有**独立的内存空间、文件描述符、CPU 时间片**等资源。

| 特征 | 说明 |
|------|------|
| **资源独立** | 每个进程有自己的地址空间（代码段、数据段、堆栈段） |
| **调度独立** | OS 通过调度算法为每个进程分配 CPU 时间 |
| **生命周期独立** | 进程有明确的创建→就绪→运行→阻塞→终止生命周期 |

> **Java 场景**：每个 Spring Boot 服务就是一个独立的 Java 进程，拥有各自的 JVM 实例和内存空间。

### 1.2 线程：操作系统任务调度的最小单位

线程是进程内部的一个执行单元，共享进程的所有资源，但拥有独立的程序计数器（PC）和栈空间。

| 特征 | 说明 |
|------|------|
| **资源共享** | 同一进程内线程共享堆内存、方法区、文件句柄 |
| **轻量高效** | 创建/销毁开销远小于进程 |
| **调度依赖** | 必须依附于进程，进程终止则线程终止 |

### 1.3 进程与线程的核心区别

| 对比维度 | 进程 | 线程 | Java 后端实战影响 |
|----------|------|------|-------------------|
| 资源分配 | 最小单位，独立分配 | 不独立，共享进程资源 | 多进程隔离性好但开销大；多线程资源利用率高 |
| 调度单位 | OS 调度的基本单位（早期） | OS 调度的最小单位（现在） | Java 多线程依赖 OS 调度，适合高并发 |
| 通信方式 | IPC（管道、消息队列、Socket） | 共享内存、锁机制 | 微服务间用 HTTP/RPC；线程间用 synchronized/Lock |
| 开销 | 创建、销毁、切换开销大 | 创建、销毁、切换开销小 | 用线程池复用线程，减少开销 |
| 故障影响 | 进程崩溃不影响其他进程 | 线程崩溃可能导致进程崩溃 | 需处理线程异常，避免宕机 |

### 1.4 Java 中的进程与线程

> **误区纠正**：Java 线程不是用户级线程。从 JDK 1.2 开始，Java 线程采用"1:1 线程模型"——一个 Java 线程对应一个操作系统线程。

- **Java 进程**：一个 `java -jar` 对应一个 JVM 进程
- **Java 线程**：Thread 类通过 JNI 调用 OS 底层线程 API（Linux 的 `pthread_create`）

## 二、底层机制：调度与通信

### 2.1 调度机制

#### 时间片轮转调度（RR）

Linux/Windows 默认采用的调度算法。CPU 时间划分为固定长度"时间片"（如 10ms），线程轮流占用。

> **Java 关联**：多线程执行顺序不确定，本质是 OS 采用时间片轮转调度。

#### 优先级调度

| 项目 | 说明 |
|------|------|
| OS 调度 | 优先调度优先级高的线程 |
| Java 线程优先级 | 1-10，默认 5，仅是"建议"，最终调度权在 OS |

#### 阻塞调度

线程遇到阻塞操作（I/O、等待锁、sleep）时，主动放弃 CPU。

### 2.2 通信机制

#### 进程间通信（IPC）—— Java 微服务场景

| 方式 | Java 实现 |
|------|-----------|
| Socket 通信（TCP/UDP） | Socket、ServerSocket |
| 消息队列（MQ） | RabbitMQ、Kafka |
| 远程过程调用（RPC） | Dubbo、Spring Cloud OpenFeign |

#### 线程间通信 —— Java 多线程场景

| 方式 | 说明 |
|------|------|
| 共享内存 | 通过共享变量 + synchronized/Lock 保证线程安全 |
| wait()/notify() | 基于对象监视器（monitor）的协作 |
| volatile | 保证可见性和有序性 |
| CountDownLatch/CyclicBarrier | 基于 AQS 的线程协作工具 |

## 三、Java 后端实战：进程与线程的核心应用

### 3.1 基础实战：Java 线程的创建

#### 继承 Thread 类

```java
class MyThread extends Thread {
    @Override
    public void run() {
        // 线程执行逻辑
    }
}
// 底层：start() 通过 JNI 调用 pthread_create(Linux) / CreateThread(Windows)
```

#### 实现 Runnable 接口（推荐）

```java
class MyRunnable implements Runnable {
    @Override
    public void run() {
        // 解耦：将任务与线程分离
    }
}
```

#### 实现 Callable 接口（带返回值）

```java
class MyCallable implements Callable<Integer> {
    @Override
    public Integer call() throws Exception {
        int sum = 0;
        for (int i = 1; i <= 100; i++) sum += i;
        return sum;
    }
}
```

#### Java 线程生命周期（对应 OS 线程状态）

| Java 状态 | 说明 | OS 对应 |
|-----------|------|---------|
| NEW | 对象已创建，未调用 start() | 线程尚未创建 |
| RUNNABLE | 就绪/运行 | 就绪+运行 |
| BLOCKED | 等待锁 | 阻塞 |
| WAITING | 无限等待（wait/join） | 阻塞 |
| TIMED_WAITING | 计时等待（sleep/wait(timeout)） | 阻塞 |
| TERMINATED | 执行完成 | 线程被回收 |

### 3.2 进阶实战：线程池的使用

```java
ThreadPoolExecutor threadPool = new ThreadPoolExecutor(
        5,              // 核心线程数（CPU核心数+1 或 2*CPU核心数）
        10,             // 最大线程数
        60L,            // 空闲时间
        TimeUnit.SECONDS,
        new ArrayBlockingQueue<>(20),  // 有界队列
        new ThreadPoolExecutor.AbortPolicy()
);
```

**核心线程数配置原则**：

- **CPU 密集型**：CPU 核心数 + 1
- **I/O 密集型**：CPU 核心数 × 2

### 3.3 高阶实战：线程安全与锁机制

```java
// 线程安全问题：count++ 非原子操作
class Counter {
    private int count = 0;
    public synchronized void increment() { count++; }  // 加锁保证原子性
}
```

```java
// 使用 Lock
class Counter2 {
    private int count = 0;
    private final Lock lock = new ReentrantLock();
    public void increment() {
        lock.lock();
        try { count++; } finally { lock.unlock(); }  // 必须在 finally 中释放
    }
}
```

## 四、实战避坑

| 坑点 | 原因 | 解决方案 |
|------|------|----------|
| **频繁创建线程** | OS 线程创建/销毁开销大 | 使用线程池复用线程 |
| **线程死锁** | 线程互相持有对方需要的锁 | 固定顺序获取锁；tryLock() 设置超时 |
| **忽视线程异常** | 未捕获异常导致进程崩溃 | try-catch 捕获所有异常；设置 UncaughtExceptionHandler |
| **依赖线程优先级** | Java 优先级仅是"建议" | 通过锁机制、CountDownLatch 保证执行顺序 |
