## 1. I/O 设备分类

### 1.1 按传输速率分类

| 类型 | 速度 | 示例 | 特征 |
|------|------|------|------|
| **低速设备** | ~KB/s | 键盘、鼠标 | 字符交互 |
| **中速设备** | ~MB/s | 打印机、扫描仪 | 批量数据传输 |
| **高速设备** | ~GB/s | 磁盘、网卡、SSD | 大数据块传输 |

### 1.2 按信息交换单位分类

| 类型 | 单位 | 特点 | 示例 |
|------|------|------|------|
| **块设备** | 数据块（通常 512B~4KB） | 可寻址、可随机访问、有缓存 | 磁盘、SSD |
| **字符设备** | 字节流 | 不可寻址、顺序访问、无缓存 | 键盘、鼠标、串口 |

### 1.3 按共享方式分类

| 类型 | 说明 | 示例 |
|------|------|------|
| **独占设备** | 同一时刻只能一个进程使用 | 打印机、磁带机 |
| **共享设备** | 多个进程可同时使用 | 磁盘、SSD |
| **虚拟设备** | 通过 SPOOLing 将独占设备变成共享设备 | 虚拟打印机 |

## 2. I/O 控制方式

### 2.1 演进对比

| 方式 | CPU 参与度 | 数据传输 | 效率 | 适用场景 |
|------|-----------|----------|------|----------|
| **程序直接控制** | 持续轮询 | CPU 亲自搬运 | **极低** | 嵌入式、简单设备 |
| **中断驱动** | 仅在完成时响应 | CPU 参与每次传输 | **较高** | 字符设备、低速 I/O |
| **DMA** | 仅在开始和结束时参与 | DMA 控制器搬运 | **高** | 块设备、磁盘 I/O |
| **通道** | 仅需发送命令 | 通道硬件管理 | **最高** | 大型机、高吞吐场景 |

### 2.2 程序直接控制

```
CPU 反复检查设备状态寄存器 → 未就绪则继续检查 → 就绪则传输数据
```

**问题**：CPU 被完全占用（忙等），无法执行其他任务，效率极低。

### 2.3 中断驱动

```
CPU 发起 I/O 请求 → 继续执行其他程序 → 设备完成时发中断 → CPU 响应中断处理
```

> 💡 **中断解决了 CPU 忙等问题**，但每次传输仍需 CPU 参与数据搬运（从设备控制器到内存）。

### 2.4 DMA（直接存储器访问）

```
DMA 流程：
1. CPU 配置 DMA 控制器（源地址、目标地址、数据量）
2. CPU 执行其他任务
3. DMA 控制器直接与内存交换数据（无需 CPU）
4. DMA 完成后发中断通知 CPU
```

| DMA 优势 | 说明 |
|----------|------|
| **解放 CPU** | CPU 仅在开始和结束时参与 |
| **批量传输** | 一次传输多个数据块 |
| **高速** | 传输速度接近内存带宽 |

### 2.5 通道

通道是**专用硬件处理器**，拥有自己的指令集，可以执行 I/O 程序。CPU 只需发出 I/O 命令，通道自行完成全部 I/O 操作。

## 3. I/O 软件层次

```
用户层 I/O 软件（库函数：printf、scanf、Java API）
    ↓
设备独立性软件（统一接口、缓冲区管理、错误处理）
    ↓
设备驱动程序（与硬件交互的具体代码）
    ↓
中断处理程序（处理 I/O 完成信号）
```

| 层次 | 功能 | Java 对应 |
|------|------|-----------|
| **用户层** | 系统调用封装、格式化 I/O | Java I/O 类库（`InputStream`/`OutputStream`） |
| **设备独立性** | 设备命名、保护、缓冲、分配 | JVM 封装层 |
| **设备驱动** | 硬件寄存器操作、中断处理 | JNI 调用 OS 驱动 |
| **中断处理** | 保存现场、唤醒等待进程 | `InterruptibleChannel` |

## 4. 缓冲区技术

### 4.1 缓冲的目的

缓解 **CPU 与 I/O 设备速度不匹配**的矛盾，减少对 CPU 的中断频率。

### 4.2 缓冲区类型

| 类型 | 结构 | 特点 |
|------|------|------|
| **单缓冲** | 一个缓冲区 | 处理与 I/O 串行 |
| **双缓冲** | 两个缓冲区交替使用 | 处理与 I/O 并行（流水线） |
| **循环缓冲** | 多个缓冲区组成环 | 适合生产者-消费者模型 |
| **缓冲池** | 统一管理多个缓冲区 | 共享、动态分配 |

### 4.3 Java 中的缓冲

```java
// 无缓冲：每次 read 都触发系统调用
InputStream in = new FileInputStream("file.txt");

// 有缓冲：减少系统调用次数
InputStream in = new BufferedInputStream(new FileInputStream("file.txt"), 8192);

// NIO 缓冲区
ByteBuffer buffer = ByteBuffer.allocate(4096);
```

> 💡 **缓冲区大小建议**：与 OS 页大小对齐（4KB、8KB 或 16KB），避免内部碎片。

## 5. SPOOLing 技术

### 5.1 定义

**SPOOLing（假脱机技术）**：利用外存（磁盘）模拟脱机 I/O，将**独占设备转换为共享设备**。

### 5.2 工作原理

```
输入进程 → 输入井（磁盘缓存）→ 应用程序 → 输出井（磁盘缓存）→ 输出进程 → 设备
```

### 5.3 示例：共享打印机

```
多个进程同时请求打印 → 各进程将打印数据写入磁盘"输出井"
→ SPOOLing 系统调度打印 → 打印机依次处理（不冲突）
```

> 用户感觉"打印机可共享使用"，实际是 SPOOLing 在后台排队调度。

## 6. 五大 I/O 模型

### 6.1 模型总览

| 模型 | 阻塞阶段 | 轮询 | 特点 | Linux 实现 |
|------|----------|------|------|------------|
| **阻塞 I/O** | 数据就绪 + 数据复制 | 否 | 简单，效率低 | 默认 socket |
| **非阻塞 I/O** | 不阻塞 | **是** | 轮询浪费 CPU | `O_NONBLOCK` |
| **I/O 多路复用** | 阻塞在 select/poll/epoll | 否 | **单线程监听多 fd** | select / poll / epoll |
| **信号驱动 I/O** | 不阻塞（信号通知） | 否 | 信号不可靠 | `fcntl + SIGIO` |
| **异步 I/O** | 全部由内核完成 | 否 | **真正的异步** | Linux AIO / IOCP |

### 6.2 阻塞 I/O（BIO）

```
应用程序 → read() 系统调用 → 内核等待数据 → 数据从内核复制到用户 → 返回
         ←────────────── 阻塞 ───────────────→
```

**特征**：用户态程序发起 I/O 请求后一直阻塞，直到内核完成操作。

**核心问题**：阻塞不仅发生在"硬件读取数据"，还发生在"内核缓冲区 → 用户缓冲区"的数据复制阶段。

### 6.3 非阻塞 I/O（NIO）

```
应用程序 → read() → 返回 EWOULDBLOCK（无数据）
         → read() → 返回 EWOULDBLOCK（无数据）
         → read() → 返回数据（就绪）
```

**特征**：立即返回（成功/失败/未就绪），需定期轮询。

**核心问题**：轮询开销——频繁系统调用导致 CPU 飙升。

### 6.4 I/O 多路复用（select/poll/epoll）

#### select / poll / epoll 对比

| 对比维度 | select | poll | epoll（Linux） |
|----------|--------|------|----------------|
| 数据结构 | 位图（fd_set） | 链表（pollfd） | **红黑树 + 就绪链表** |
| FD 上限 | 默认 **1024** | 无上限 | 无上限 |
| 轮询方式 | 遍历所有 fd（O(n)） | 遍历所有 fd（O(n)） | **事件驱动，仅通知就绪 fd** |
| 内核态拷贝 | 每次调用拷贝全量 fd | 每次调用拷贝全量 fd | **一次注册，持续使用** |
| 触发方式 | 水平触发（LT） | 水平触发（LT） | LT + **边缘触发（ET）** |
| 复杂度 | O(n) | O(n) | **O(1)**（就绪事件数）|

> ⚠️ epoll 采用**事件驱动**模式，无需轮询，仅通知就绪的 fd。select/poll 需要轮询所有 fd。这是面试必考点。

#### epoll 两种触发模式

| 模式 | 说明 | 特点 |
|------|------|------|
| **LT（水平触发）** | 只要 fd 就绪，就**持续通知** | 默认，编程简单，不易漏事件 |
| **ET（边缘触发）** | 仅状态**变化时通知**一次 | 高效，需一次读完所有数据，易漏 |

### 6.5 信号驱动 I/O

```
应用程序发起 I/O → 立即返回 → 数据就绪时内核发 SIGIO 信号 → 在信号处理程序中读取数据
```

**特点**：数据就绪时通知，但数据复制阶段仍是阻塞的（同步 I/O）。

### 6.6 异步 I/O（AIO）

```
应用程序发起 aio_read() → 立即返回 → 内核完成数据就绪+数据复制 → 回调通知
```

**核心特征**：**完全异步**——内核完成所有操作（包括数据就绪和数据复制）后通过回调通知。**真正的异步 I/O**。

## 7. Java I/O 模型演进

### 7.1 BIO / NIO / AIO 对应关系

| 类型 | OS 底层 | 特点 | 适用场景 |
|------|---------|------|----------|
| **Java BIO** | 阻塞 I/O | 简单，一个连接一个线程 | 低并发、小数据量 |
| **Java NIO** | I/O 多路复用（epoll） | **高并发**，Selector 监听多路 | 高并发网络通信 |
| **Java AIO** | 异步 I/O（IOCP/Linux AIO） | 完全异步，回调通知 | 特定低延迟场景 |

### 7.2 Java NIO 实战（高并发服务器）

```java
public class NioServer {
    public static void main(String[] args) throws IOException {
        ServerSocketChannel serverChannel = ServerSocketChannel.open();
        serverChannel.configureBlocking(false); // 关键：非阻塞模式
        serverChannel.bind(new InetSocketAddress(8080));

        Selector selector = Selector.open();
        serverChannel.register(selector, SelectionKey.OP_ACCEPT);

        while (selector.select() > 0) { // 阻塞直到有事件就绪
            Iterator<SelectionKey> iterator = selector.selectedKeys().iterator();
            while (iterator.hasNext()) {
                SelectionKey key = iterator.next();
                if (key.isAcceptable()) {
                    // 处理新连接
                    SocketChannel client = serverChannel.accept();
                    client.configureBlocking(false);
                    client.register(selector, SelectionKey.OP_READ);
                } else if (key.isReadable()) {
                    // 处理数据读取
                    SocketChannel client = (SocketChannel) key.channel();
                    ByteBuffer buffer = ByteBuffer.allocate(1024);
                    client.read(buffer);
                }
                iterator.remove(); // 关键：移除已处理事件
            }
        }
    }
}
```

### 7.3 Java AIO 实战

```java
public class AioReadDemo {
    public static void main(String[] args) throws Exception {
        AsynchronousFileChannel channel = AsynchronousFileChannel.open(
                Paths.get("test.txt"), StandardOpenOption.READ);
        ByteBuffer buffer = ByteBuffer.allocate(1024);

        channel.read(buffer, 0, null, new CompletionHandler<Integer, Void>() {
            @Override
            public void completed(Integer result, Void attachment) {
                buffer.flip();
                byte[] data = new byte[buffer.remaining()];
                buffer.get(data);
                System.out.println(new String(data));
            }

            @Override
            public void failed(Throwable exc, Void attachment) {
                exc.printStackTrace();
            }
        });
    }
}
```

### 7.4 生产环境 I/O 选型建议

| 场景 | 推荐方案 | 原因 |
|------|----------|------|
| 读取配置文件 | BIO | 简单，小数据量 |
| 高并发 RPC 通信 | **Netty（NIO）** | 封装 epoll，业界标准 |
| 大文件传输 | **NIO 零拷贝**（FileChannel） | 减少数据复制 |
| Web 服务器 | Netty / Tomcat NIO | 高并发连接 |
| 特定低延迟场景 | AIO | Windows 下 IOCP 性能好 |

> 💡 **不要盲目追求"最先进"的 I/O 模型**：读取配置文件用 BIO 就足够；高并发通信用 Netty 的 NIO 模式；大文件传输用 NIO 的零拷贝机制。

## 8. 零拷贝技术

### 8.1 传统 I/O 的数据拷贝

```
磁盘 → 内核缓冲区（DMA 拷贝）
     → 用户缓冲区（CPU 拷贝）
     → 内核 Socket 缓冲区（CPU 拷贝）
     → 网卡（DMA 拷贝）
```

**共 4 次拷贝 + 3 次上下文切换**，效率低。

### 8.2 零拷贝优化

```
磁盘 → 内核缓冲区（DMA 拷贝）
     → 网卡（DMA 拷贝，仅需描述符）
```

**共 2 次拷贝 + 0 次 CPU 拷贝**，通过 `sendfile()` 或 `mmap()` 实现。

### 8.3 Java 零拷贝实现

```java
// FileChannel.transferTo() 底层调用 OS 零拷贝机制
try (FileChannel source = new FileInputStream("source.txt").getChannel();
     FileChannel target = new FileOutputStream("target.txt").getChannel()) {
    source.transferTo(0, source.size(), target);
}
```

| 零拷贝 API | 底层机制 | Linux | Windows |
|------------|----------|-------|---------|
| `FileChannel.transferTo()` | `sendfile()` | 支持 | `TransmitFile()` |
| `FileChannel.map()` | `mmap()` | 支持 | 内存映射文件 |

## 9. 设备分配与管理

### 9.1 设备分配数据结构

| 数据结构 | 说明 |
|----------|------|
| **系统设备表（SDT）** | 记录系统中所有设备及状态 |
| **设备控制表（DCT）** | 记录每个设备的状态、属性 |
| **控制器控制表（COCT）** | 设备控制器信息 |
| **通道控制表（CHCT）** | 通道信息 |

### 9.2 设备独立性

**逻辑设备名 → 物理设备名的映射**，应用程序使用逻辑设备名（如 `/dev/tty`），不关心具体物理端口。

## 10. Java 后端实战：I/O 优化

### 10.1 文件 I/O 优化

| 技巧 | 说明 |
|------|------|
| 缓冲区大小 | 建议 4KB、8KB 或 16KB（与 OS 页大小对齐）|
| 大文件用 DirectBuffer | 减少内核 → 用户缓冲区的复制 |
| 复用 FileChannel | 避免频繁打开/关闭文件 |
| 零拷贝 | 使用 `FileChannel.transferTo()` |

### 10.2 网络 I/O 优化

| 技巧 | 说明 |
|------|------|
| 优先使用 Netty | 封装 NIO 细节，解决空轮询、资源泄漏 |
| Worker 线程数 | = CPU 核心数 × 2 |
| 禁用 Nagle 算法 | `ChannelOption.TCP_NODELAY=true`（低延迟场景）|
| 开启 TCP Keep-Alive | `ChannelOption.SO_KEEPALIVE=true` |

### 10.3 通用优化技巧

| 技巧 | 说明 |
|------|------|
| 减少系统调用次数 | 批量操作、加大缓冲区 |
| 避免频繁 GC | 复用 ByteBuffer 或使用对象池 |
| 监控 I/O 性能 | `iostat`、`netstat`、`jstat` |

### 10.4 IOPS 与吞吐量监控

```bash
# 磁盘 I/O 监控
iostat -x 1        # 查看磁盘读写、IOPS、响应时间

# 网络 I/O
netstat -s         # 网络统计信息
ss -tlnp           # 查看 TCP 连接状态

# 进程级 I/O
lsof -p <PID>      # 查看进程打开的文件描述符
```
