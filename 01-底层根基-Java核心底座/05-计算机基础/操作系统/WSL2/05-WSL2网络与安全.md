## 1. WSL2 网络模式

### 1.1 NAT 模式（传统/默认）

```text
WSL2 NAT 网络架构：

┌─────────────────────────────────────────────────┐
│              Windows 宿主机                       │
│  IP: 192.168.1.100 (物理网络)                    │
│  IP: 172.28.0.1 (vEthernet WSL 虚拟交换机)       │
│                                                  │
│  ┌────────────────────────────────────┐          │
│  │         WSL2 虚拟机                 │          │
│  │   IP: 172.28.x.x (DHCP, 每次重启变)│          │
│  │   ┌──────────────────────────┐     │          │
│  │   │  Java App :8080          │     │          │
│  │   │  MySQL :3306             │     │          │
│  │   └──────────────────────────┘     │          │
│  └────────────────────────────────────┘          │
│                                                  │
│  外部网络 ←→ Windows (NAT 转换) ←→ WSL2 虚拟机    │
└─────────────────────────────────────────────────┘

特点：
├── WSL2 在独立的子网中（172.x.x.x）
├── 每次重启 IP 可能变化
├── 外部网络无法直接访问 WSL2 IP
├── localhost 端口自动转发（Windows→WSL2）
└── WSL2 通过 NAT 访问外部网络
```

```bash
# 查看 WSL2 的 IP（在 WSL2 中）
ip addr show eth0
# inet 172.28.10.55/20
# → 每次 wsl --shutdown 后可能变化

# 查看 Windows 上的 vEthernet (WSL) 网卡（PowerShell）
Get-NetIPAddress -InterfaceAlias "vEthernet (WSL)" | Select-Object IPAddress
# → 172.28.0.1
```

### 1.2 Mirrored 模式（Windows 11 22H2+）

```text
WSL2 Mirrored 网络架构（Win11 22H2+）：

┌─────────────────────────────────────────────────┐
│              Windows 宿主机                       │
│  IP: 192.168.1.100                               │
│                                                  │
│  ┌────────────────────────────────────┐          │
│  │         WSL2 虚拟机                 │          │
│  │   IP: 192.168.1.100 (镜像！同一 IP) │          │
│  │   ┌──────────────────────────┐     │          │
│  │   │  Java App :8080          │     │          │
│  │   │  MySQL :3306             │     │          │
│  │   └──────────────────────────┘     │          │
│  └────────────────────────────────────┘          │
│                                                  │
│  外部网络 ←→ 直接访问 ←→ WSL2 虚拟机               │
└─────────────────────────────────────────────────┘

特点：
✅ Windows 与 WSL2 共享同一个 IP
✅ 无需 localhost 转发，外部直接访问
✅ IPv6 支持
✅ VPN 兼容性更好
✅ Docker 网络更简单
⚠️ 端口冲突（同一端口 Windows 和 WSL2 不能同时监听）
```

```ini
# %USERPROFILE%\.wslconfig
[wsl2]
networkingMode=Mirrored
```

### 1.3 两种模式对比

| 维度 | NAT (默认) | Mirrored (Win11 22H2+) |
|------|:---:|:---:|
| **IP 地址** | 独立子网 (172.x) | 与 Windows 共享 |
| **外部访问** | 需端口转发 | 直接访问 |
| **localhost 转发** | ✅ 自动 | ❌ 不需要 |
| **VPN 兼容** | ⚠️ 部分不兼容 | ✅ 更好 |
| **Docker 网络** | 较复杂 | ✅ 简单 |
| **端口冲突** | 无 | ⚠️ 同一端口不能同时用 |
| **稳定性** | 成熟 | ⭐ 新特性 |
| **IPv6** | ⚠️ 有限 | ✅ 完整 |

> 💡 **推荐**：Win11 22H2+ 的用户如果不需要"同一端口 Windows 和 WSL2 分别监听"，选 Mirrored 模式体验更好。

## 2. localhost 端口转发

### 2.1 工作原理（NAT 模式）

```text
NAT 模式下的 localhost 转发：

WSL2 内: java -jar app.jar (监听 0.0.0.0:8080)
    │
    ▼ (自动转发)
Windows: http://localhost:8080 → 可以访问！

原理：
Windows 上的 wslhost.exe 监听 localhost 端口，
收到连接后转发到 WSL2 虚拟机内的对应端口。

触发条件：
├── WSL2 中程序监听 0.0.0.0 或 :: (所有接口) → ✅ 自动转发
├── WSL2 中程序监听 127.0.0.1 → ⚠️ 仅 WSL2 内部可访问
└── 系统端口 (<1024) → ✅ 也可转发（无需管理员）
```

### 2.2 常见问题与解决

```bash
# === 问题 1: localhost 无法访问 WSL2 服务 ===
# 原因：端口被 Hyper-V 预留，或 localhostForwarding 被禁用

# 检查
wsl cat /proc/sys/net/ipv4/ip_local_port_range

# 解决方案 1: 检查 .wslconfig
# localhostForwarding=true

# 解决方案 2: 重启 winnat（Windows）
# PowerShell 管理员:
net stop winnat
net start winnat

# 解决方案 3: 排除被 Hyper-V 预留的端口
netsh interface ipv4 show excludedportrange protocol=tcp
# 如果 8080 在此列表中，需要调整 Windows TCP 动态端口范围
netsh int ipv4 set dynamicport tcp start=49152 num=16384

# === 问题 2: 端口被 Windows 自身占用 ===
# PowerShell:
Get-Process -Id (Get-NetTCPConnection -LocalPort 8080).OwningProcess
# 如果是 Windows 程序占用，改 WSL2 应用端口
```

### 2.3 端口转发高级配置

```powershell
# === Windows 端手动端口转发 ===
# 将 Windows 某端口转发到 WSL2 的某端口

# 获取 WSL2 IP
$wsl_ip = wsl bash -c "ip addr show eth0 | grep 'inet\b' | awk '{print \$2}' | cut -d/ -f1"

# 添加端口转发
netsh interface portproxy add v4tov4 listenport=8080 listenaddress=0.0.0.0 connectport=8080 connectaddress=$wsl_ip

# 查看所有转发规则
netsh interface portproxy show all

# 删除转发规则
netsh interface portproxy delete v4tov4 listenport=8080 listenaddress=0.0.0.0

# === 为 WSL2 设置固定 IP ===
# 创建脚本：Set-WslStaticIP.ps1
$wsl_ip = "172.28.0.99"
wsl -u root ip addr add $wsl_ip/20 dev eth0
wsl -u root ip route add default via 172.28.0.1

# 然后在 Windows 中添加端口转发到固定 IP
netsh interface portproxy add v4tov4 listenport=8080 listenaddress=0.0.0.0 connectport=8080 connectaddress=$wsl_ip
```

## 3. 从外部访问 WSL2 服务

### 3.1 NAT 模式下的外部访问

```text
场景：手机/其他电脑需要访问 WSL2 中运行的 Spring Boot 应用

问题：WSL2 IP (172.28.x.x) 只在 Windows 宿主机内可见

方案一：Windows 端口转发（推荐）
  → netsh interface portproxy 将 Windows 物理 IP:8080 转给 WSL2:8080

方案二：Mirrored 网络模式
  → WSL2 与 Windows 共享 IP，外部直接访问 Windows IP:8080

方案三：SSH 隧道
  → 外部机器 SSH 到 Windows，通过 -L 转发端口
```

### 3.2 端口转发脚本

```powershell
# Enable-WslExternalAccess.ps1
# 以管理员身份运行，使 WSL2 服务可被外部网络访问

param(
    [int]$WslPort = 8080,
    [int]$WindowsPort = $WslPort
)

# 获取 WSL2 IP
$wsl_ip = wsl bash -c "ip addr show eth0 | grep -oP '(?<=inet\s)\d+(\.\d+){3}'"
Write-Host "WSL2 IP: $wsl_ip"

# 删除旧转发规则（如果存在）
try { 
    netsh interface portproxy delete v4tov4 listenport=$WindowsPort listenaddress=0.0.0.0 
} catch {}

# 添加新转发规则
netsh interface portproxy add v4tov4 `
    listenport=$WindowsPort `
    listenaddress=0.0.0.0 `
    connectport=$WslPort `
    connectaddress=$wsl_ip

# 开放 Windows 防火墙
New-NetFirewallRule -DisplayName "WSL2 Port $WindowsPort" `
    -Direction Inbound -LocalPort $WindowsPort `
    -Protocol TCP -Action Allow

Write-Host "✅ 端口转发已设置: Windows:$WindowsPort → WSL2:$WslPort" -ForegroundColor Green
Write-Host "❗ WSL2 重启后 IP 会变，需要重新执行此脚本" -ForegroundColor Yellow
```

## 4. SSH 服务配置

### 4.1 WSL2 中启用 SSH 服务

```bash
# 进入 WSL2
wsl

# 1. 安装 SSH Server
sudo apt install -y openssh-server

# 2. 修改 SSH 配置
sudo vim /etc/ssh/sshd_config
# 关键配置：
# Port 2222                     ← 避免与 Windows SSH 冲突
# ListenAddress 0.0.0.0
# PasswordAuthentication yes    ← 或 no（推荐密钥登录）
# PubkeyAuthentication yes
# PermitRootLogin no

# 3. 生成 Host Key
sudo ssh-keygen -A

# 4. 启动 SSH 服务
# systemd 方式（推荐，WSL2 0.67.6+）
sudo systemctl enable ssh
sudo systemctl start ssh

# 非 systemd 方式
sudo service ssh start

# 5. 设置 SSH 自启动（WSL2 启动时自动启动）
# 如果不用 systemd，在 /etc/wsl.conf 中添加：
# [boot]
# command=service ssh start

# 6. 添加公钥
mkdir -p ~/.ssh && chmod 700 ~/.ssh
# 将客户端公钥追加到 authorized_keys
echo "ssh-rsa AAAAB3..." >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
```

### 4.2 从外部连接 WSL2

```bash
# === Windows 端端口转发（使 SSH 可从外部连接）===
# 管理员 PowerShell：
netsh interface portproxy add v4tov4 `
    listenport=2222 listenaddress=0.0.0.0 `
    connectport=2222 connectaddress=<WSL2_IP>
New-NetFirewallRule -DisplayName "WSL2 SSH" -Direction Inbound -LocalPort 2222 -Protocol TCP -Action Allow

# === 客户端连接 ===
# 局域网内其他机器
ssh -p 2222 username@192.168.1.100    # Windows 宿主机 IP

# VS Code Remote SSH
# .ssh/config
Host wsl2-dev
    HostName 192.168.1.100
    Port 2222
    User username
    IdentityFile ~/.ssh/id_rsa
```

### 4.3 SSH Agent 转发

```bash
# 在 WSL2 中使用 Windows SSH Agent（避免 WSL2 中重新加载密钥）

# Windows 端：启动 ssh-agent 服务，添加密钥
# PowerShell:
Set-Service ssh-agent -StartupType Automatic
Start-Service ssh-agent
ssh-add ~/.ssh/id_rsa

# WSL2 端：安装 socat 转发到 Windows ssh-agent
sudo apt install -y socat
# 在 ~/.bashrc 或 ~/.zshrc 中添加：
export SSH_AUTH_SOCK=$HOME/.ssh/agent.sock
# 启动 socat
socat UNIX-LISTEN:$SSH_AUTH_SOCK,fork EXEC:"/mnt/c/Windows/System32/OpenSSH/ssh.exe -W '//./pipe/openssh-ssh-agent'",nofork &

# 或使用社区方案：wsl-ssh-agent
# https://github.com/rupor-github/wsl-ssh-agent
```

## 5. 安全边界与防火墙

### 5.1 WSL2 的安全模型

```text
安全边界：
├── WSL2 虚拟机与 Windows 之间：✅ 安全边界存在
│   └── Windows Defender 覆盖 WSL2 文件系统
│
├── WSL2 访问 Windows 文件系统：
│   └── 通过 9P 协议，遵循 Windows 文件权限
│   └── Linux 用户以挂载时的 uid/gid 访问
│
├── WSL2 网络访问：
│   ├── 出站：受 Windows 防火墙规则约束
│   └── 入站：NAT 模式外网不可达，Mirrored 模式需关注
│
└── WSL2 中的 root 权限：
    ├── root 在 WSL2 中可做任何 Linux 操作
    ├── root 无法绕过 Windows 文件权限访问 /mnt/c/
    └── root 无法影响 Windows 宿主机内核
```

### 5.2 Windows Defender 与 WSL2

```powershell
# === Windows Defender 实时保护会扫描 WSL2 ===
# 建议排除 WSL2 项目目录，避免编译时被扫描降速

# 排除 WSL2 项目目录
# 方式一：排除 ext4 虚拟磁盘（不推荐，粒度太粗）
# 方式二：排除 \\wsl$\ 路径（推荐）
Add-MpPreference -ExclusionPath "\\wsl.localhost\Ubuntu-24.04\home\username\projects"

# 排除 Java 相关进程
Add-MpPreference -ExclusionProcess "java"
Add-MpPreference -ExclusionProcess "javac"

# 查看已排除项
Get-MpPreference | Select-Object ExclusionPath, ExclusionProcess, ExclusionExtension
```

### 5.3 防火墙配置

```powershell
# === Windows 防火墙对 WSL2 的影响 ===

# WSL2 出站访问外网 → 默认允许
# WSL2 入站（外部访问 WSL2 服务）→ 需要配置

# 场景：让局域网其他设备访问 WSL2 中的 Web 服务

# 1. 先设置端口转发（如第 3 节）
# 2. 开放防火墙端口
New-NetFirewallRule -DisplayName "WSL2 Spring Boot" `
    -Direction Inbound -LocalPort 8080 -Protocol TCP -Action Allow `
    -Profile Private                        # 仅私有网络

# 3. 如果是 Mirrored 模式，WSL2 共享 Windows 网络栈
#    防火墙规则同时影响 Windows 和 WSL2

# 4. 查看防火墙规则
Get-NetFirewallRule -DisplayName "WSL2*" | Format-Table DisplayName, Enabled, Direction
```

### 5.4 安全最佳实践

```text
✅ DO:
├── 项目代码放在 WSL2 ext4 上（不共享给 Windows 用户）
├── WSL2 中使用非 root 用户进行日常开发
├── 定期 wsl --update 更新内核（安全补丁）
├── SSH 密钥登录，禁用密码认证
├── 敏感文件（密钥、证书）放在 WSL2 内而非 /mnt/c/
├── Docker 容器以非 root 运行
└── 防火墙仅开放必要端口

❌ DON'T:
├── 不要在 WSL2 的 /mnt/c/ 下存放敏感文件（权限模型不同）
├── 不要以 root 身份运行日常开发容器
├── 不要在生产环境使用 WSL2（它不是为生产设计的）
├── 不要在 WSL2 中运行面向公网的服务（单机稳定性不足）
└── 不要关闭 Windows Defender（它会保护 WSL2 边界）
```
