## 1. systemd 启用与管理

### 1.1 为什么需要 systemd

```text
没有 systemd 时的问题：
├── service 命令工作不稳定
├── systemctl 不可用
├── 服务自启动需手动写在 [boot] command 中
├── snap 包不工作（snapd 依赖 systemd）
├── Docker Engine 不自启
└── 定时器（systemd timer）不可用

启用 systemd 后：
✅ systemctl start/stop/enable 完全可用
✅ Docker Engine 自启动
✅ MySQL/Redis/PostgreSQL 作为系统服务运行
✅ snap 包管理可用
✅ 与标准 Linux 服务器行为一致
```

### 1.2 启用 systemd

```bash
# 要求：WSL 版本 ≥ 0.67.6
wsl --version | grep "WSL"
# → WSL 版本：2.4.x ← 满足条件

# 在 /etc/wsl.conf 中添加
sudo vim /etc/wsl.conf
# [boot]
# systemd=true

# Windows PowerShell 中重启 WSL2
wsl --shutdown
wsl

# 进入后验证 systemd 是否运行
ps -p 1 -o comm=
# → systemd（成功了！）

# 或
systemctl status
# → State: running
```

### 1.3 systemd 启用后的常见服务管理

```bash
# === Docker Engine 自启动 ===
sudo systemctl enable docker
sudo systemctl start docker

# === MySQL 8.0 ===
sudo apt install -y mysql-server
sudo systemctl enable mysql
sudo systemctl start mysql

# === Redis ===
sudo apt install -y redis-server
sudo systemctl enable redis-server
sudo systemctl start redis-server

# === PostgreSQL ===
sudo apt install -y postgresql
sudo systemctl enable postgresql
sudo systemctl start postgresql

# === Nginx ===
sudo apt install -y nginx
sudo systemctl enable nginx
sudo systemctl start nginx

# === 查看所有自启动服务 ===
systemctl list-unit-files --state=enabled

# === 查看运行中的服务 ===
systemctl list-units --state=running
```

> ⚠️ **注意**：启用 systemd 后，WSL2 冷启动时间从 <2s 增加到 ~5-10s（需要启动所有 enabled 服务）。

## 2. WSLg：Linux GUI 应用

### 2.1 什么是 WSLg

```text
WSLg (Windows Subsystem for Linux GUI) = Windows 上原生运行 Linux GUI 应用

架构：
  Linux GUI 应用
       │
  Wayland / X11
       │
  Weston (Wayland compositor) -- RDP --→ WSLg System Distro
       │                                      │
  FreeRDP ──────────────────────────→ mstsc (Windows RDP 客户端)
                                            │
                                    渲染在 Windows 窗口中

支持：
✅ 无需额外配置：WSL 1.0+ 默认启用
✅ GNOME / KDE / XFCE 应用
✅ IntelliJ IDEA Community Linux 版
✅ 音频、剪贴板、GPU 加速
```

### 2.2 运行 GUI 应用

```bash
# GUI 应用支持默认启用（.wslconfig: guiApplications=true）

# === 基础 GUI 应用 ===
# 文件管理器
sudo apt install -y nautilus
nautilus &

# 文本编辑器
sudo apt install -y gedit
gedit pom.xml &

# 图片查看器
sudo apt install -y eog
eog screenshot.png &

# === 浏览器 ===
sudo apt install -y firefox
firefox &

# === 轻量级 IDE ===
sudo snap install code --classic
# 或下载 Linux 版 IDEA
# 解压后运行 bin/idea.sh

# === Java GUI 应用（Swing/JavaFX）===
# 直接在 WSL2 中运行
java -jar swing-app.jar &
# WSLg 自动处理 X11/Wayland 显示
```

### 2.3 IDEA Linux 版通过 WSLg 运行

```bash
# 1. 下载 Linux 版 IntelliJ IDEA
cd ~
wget https://download.jetbrains.com/idea/ideaIC-2024.3.tar.gz
tar -xzf ideaIC-2024.3.tar.gz

# 2. 安装依赖
sudo apt install -y libxext6 libxrender1 libxtst6 libxi6 libfreetype6

# 3. 运行
~/idea-IC-*/bin/idea.sh &
# IDEA 窗口会在 Windows 桌面上显示！

# 4. 创建桌面快捷方式
cat > ~/Desktop/idea.desktop << 'EOF'
[Desktop Entry]
Name=IntelliJ IDEA
Exec=/home/username/idea-IC-243.22562.43/bin/idea.sh
Type=Application
Icon=/home/username/idea-IC-243.22562.43/bin/idea.png
EOF
chmod +x ~/Desktop/idea.desktop
```

> 💡 **WSLg 适合**：数据库 GUI 工具（DBeaver Linux 版）、轻量编辑器、偶尔的 IDEA 使用。日常重度开发还是用 Windows 原生 IDEA 体验更好。

## 3. GPU 加速：CUDA / DirectML

### 3.1 概述

```text
WSL2 GPU 支持矩阵：

├── NVIDIA GPU  → CUDA / cuDNN / TensorRT ✅ 原生支持
├── AMD GPU    → ROCm / DirectML          ✅
├── Intel GPU  → oneAPI / DirectML        ✅
└── DirectML   → 所有 GPU（Windows ML 框架）✅

要求：
├── Windows 11 或 Win10 21H2+
├── GPU 厂商最新驱动（含 WSL2 支持）
├── WSL 内核已更新（wsl --update）
```

### 3.2 NVIDIA CUDA on WSL2

```bash
# 1. Windows 端安装 NVIDIA 驱动（含 WSL2 CUDA 支持）
#    https://developer.nvidia.com/cuda/wsl
#    不需要在 WSL2 中安装 Linux 驱动！

# 2. WSL2 中安装 CUDA Toolkit
wget https://developer.download.nvidia.com/compute/cuda/repos/wsl-ubuntu/x86_64/cuda-wsl-ubuntu.pin
sudo mv cuda-wsl-ubuntu.pin /etc/apt/preferences.d/cuda-repository-pin-600
wget https://developer.download.nvidia.com/compute/cuda/12.6.2/local_installers/cuda-repo-wsl-ubuntu-12-6-local_12.6.2-1_amd64.deb
sudo dpkg -i cuda-repo-wsl-ubuntu-12-6-local_12.6.2-1_amd64.deb
sudo apt update
sudo apt install -y cuda-toolkit-12-6

# 3. 验证
nvidia-smi
# → 显示 GPU 信息，证明 CUDA 可用

# 4. 编译 CUDA 程序
nvcc --version
```

### 3.3 深度学习框架

```bash
# === PyTorch with CUDA ===
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu126

# === TensorFlow with CUDA ===
pip install tensorflow[and-cuda]

# === Java 中的 GPU 计算 ===
# 通过 JNI 调用 CUDA，或使用 JavaCPP Presets for CUDA
# <!-- pom.xml -->
# <dependency>
#     <groupId>org.bytedeco</groupId>
#     <artifactId>cuda-platform</artifactId>
#     <version>12.6-9.5-1.5.11</version>
# </dependency>
```

### 3.4 DirectML（跨 GPU）

```bash
# DirectML = 微软的跨平台 ML 加速 API
# 所有 GPU（Intel/AMD/NVIDIA）都支持

# Python
pip install torch-directml

# 验证
python -c "
import torch
import torch_directml
dml = torch_directml.device()
t = torch.tensor([1.0, 2.0]).to(dml)
print(t.device)
"
```

## 4. USB 设备直通

### 4.1 usbipd-win

```powershell
# === Windows 端：安装 usbipd-win ===
winget install dorssel.usbipd-win

# 查看可用的 USB 设备
usbipd list
# BUSID  VID:PID    DEVICE
# 4-1    12d1:108a  Android Phone
# 4-2    0bda:5682  USB Camera

# 将设备绑定（连接到 WSL2）
usbipd bind --busid 4-1

# 附加到 WSL2
usbipd attach --wsl --busid 4-1

# 查看当前挂载状态
usbipd list
# 4-1    12d1:108a  Attached - Ubuntu-24.04
```

```bash
# === WSL2 端：安装 usbip 客户端 ===
sudo apt install -y linux-tools-generic hwdata
sudo update-alternatives --install /usr/local/bin/usbip usbip /usr/lib/linux-tools/*-generic/usbip 20

# 验证设备已连接
lsusb
# Bus 002 Device 001: ID 12d1:108a Huawei Technologies Co., Ltd.

# Java 中通过 JNI / libusb 访问 USB 设备
# ADB 调试 Android 手机（经典场景）
sudo apt install -y android-tools-adb
adb devices
# → 设备列表中应显示通过 USB 连接的手机
```

### 4.2 常见 USB 直通场景

| 设备 | WSL2 用途 |
|------|----------|
| **Android 手机** | ADB 无线调试 + USB 文件传输 |
| **Arduino/ESP32** | 串口烧录固件 |
| **USB 摄像头** | OpenCV 采集图像 |
| **USB 加密狗** | Java 认证系统开发 |
| **USB 串口** | 嵌入式设备调试 |

## 5. 多发行版 + Docker 组合开发

### 5.1 场景设计

```text
Java 开发者的多发行版策略：

发行版 1: ubuntu-dev（日常开发）
├── JDK (SDKMAN: 8/11/17/21)
├── Maven + Gradle
├── Git + SSH
├── VS Code Server
└── 用途：日常 Java 项目开发

发行版 2: docker-host（容器环境）
├── Docker Desktop WSL2 Backend
├── 自动创建 docker-desktop + docker-desktop-data
└── 用途：运行 MySQL/Redis/Kafka 等中间件

发行版 3: test-env（测试环境）
├── JDK (干净环境)
├── 模拟 CI/CD 环境
└── 用途：构建验证、自动化测试

发行版 4: pentest（可选）
├── Kali Linux WSL
└── 用途：安全测试学习
```

### 5.2 管理脚本

```bash
#!/bin/bash
# multi-wsl-manager.sh —— WSL2 多发行版管理

case $1 in
  start-dev)
    wsl -d ubuntu-dev
    ;;
  start-docker)
    wsl -d ubuntu-dev bash -c "docker ps" 2>/dev/null || echo "Docker Desktop not running"
    ;;
  update-all)
    for distro in $(wsl -l -q | tr -d '\r'); do
      echo "🔄 Updating $distro..."
      wsl -d "$distro" -u root bash -c "apt update && apt upgrade -y" 2>/dev/null
    done
    ;;
  status)
    wsl -l -v
    ;;
  snapshot)
    wsl --export ubuntu-dev "D:\backup\ubuntu-dev-$(date +%Y%m%d).tar"
    echo "✅ Snapshot saved"
    ;;
  *)
    echo "Usage: $0 {start-dev|start-docker|update-all|status|snapshot}"
    ;;
esac
```

## 6. 备份、快照与灾难恢复

### 6.1 备份策略

```powershell
# === 完整备份：wsl --export ===
# 定期备份发行版为 tar 文件
$date = Get-Date -Format "yyyyMMdd-HHmm"
wsl --export Ubuntu-24.04 "D:\backup\wsl\ubuntu-$date.tar"

# === 增量备份：备份关键目录 ===
# 在 WSL2 中备份项目 + 配置到 Windows
wsl bash -c "
  tar -czf /mnt/d/backup/wsl-config-\$(date +%Y%m%d).tar.gz \
    ~/.ssh \
    ~/.gitconfig \
    ~/.zshrc \
    ~/.m2/settings.xml \
    ~/.gradle/gradle.properties
"

# === 自动备份脚本（Windows 计划任务）===
# backups.ps1
$backupDir = "D:\Backup\wsl"
$date = Get-Date -Format "yyyyMMdd"
wsl --export Ubuntu-24.04 "$backupDir\ubuntu-$date.tar"
# 保留最近 7 天
Get-ChildItem "$backupDir\ubuntu-*.tar" | 
    Sort-Object LastWriteTime -Descending | 
    Select-Object -Skip 7 | 
    Remove-Item
```

### 6.2 灾难恢复

```powershell
# === 系统重装后恢复 WSL2 环境 ===

# 1. 安装 WSL2
wsl --install --no-distribution

# 2. 导入备份
wsl --import Ubuntu-24.04 D:\wsl\Ubuntu-24.04 D:\backup\wsl\ubuntu-backup.tar --version 2

# 3. 设置默认用户
wsl -d Ubuntu-24.04 -u root
# 在 WSL2 中执行:
# echo -e "[user]\ndefault=yourname" >> /etc/wsl.conf

# 4. 退出并重启
wsl --terminate Ubuntu-24.04
wsl -d Ubuntu-24.04

# 5. 验证
java --version
mvn --version
```

### 6.3 盘迁移（C盘→D盘）

```powershell
# === WSL2 发行版迁移到其他盘 ===

# 1. 查看当前位置
Get-ChildItem "$env:LOCALAPPDATA\Packages\*Ubuntu*" -Recurse -Filter "ext4.vhdx"

# 2. 导出
wsl --shutdown
wsl --export Ubuntu-24.04 D:\wsl-migrate.tar

# 3. 注销（⚠️ 确认数据已导出！）
wsl --unregister Ubuntu-24.04

# 4. 导入到新位置
wsl --import Ubuntu-24.04 D:\wsl\Ubuntu-24.04 D:\wsl-migrate.tar --version 2

# 5. 清理导出文件
Remove-Item D:\wsl-migrate.tar

# 6. 设置默认用户
wsl ~ -d Ubuntu-24.04 -u root
# echo -e "[user]\ndefault=yourname" >> /etc/wsl.conf && exit
wsl --terminate Ubuntu-24.04
```

## 7. 常见问题排错大全

### 7.1 WSL2 无法启动

```powershell
# 错误：The Windows Subsystem for Linux has not been enabled
# 解决：以管理员身份运行
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
# 重启计算机

# 错误：WslRegisterDistribution failed with error: 0x800701bc
# 原因：内核版本太旧
# 解决：
wsl --update

# 错误：WslRegisterDistribution failed with error: 0x80370102
# 原因：BIOS 未开启虚拟化
# 解决：进入 BIOS → 开启 Intel VT-x / AMD-V

# 错误：The connection to the VM was lost
# 原因：Hyper-V 问题
# 解决：
bcdedit /set hypervisorlaunchtype auto
# 重启
```

### 7.2 网络问题

```bash
# 问题：WSL2 内 ping 不通外网
# 原因：DNS 配置问题
# 解决：
sudo vim /etc/resolv.conf
# nameserver 8.8.8.8
# nameserver 1.1.1.1

# 或禁用自动生成
sudo vim /etc/wsl.conf
# [network]
# generateResolvConf=false

# 问题：localhost 端口转发失效
# Windows PowerShell (管理员):
net stop winnat
net start winnat
# 检查 .wslconfig: localhostForwarding=true

# 问题：WSL2 与 VPN 冲突
# 解决：使用 Mirrored 网络模式
# .wslconfig: networkingMode=Mirrored
```

### 7.3 内存问题

```powershell
# 问题：WSL2 内存占用过高（vmmem 进程占用过多）

# 临时解决：回收内存
wsl --shutdown

# 永久解决：限制 .wslconfig
# memory=8GB          # 限制最大内存
# pageReporting=true  # 启用页面回收

# 手动回收（不重启 WSL2）
# 在 WSL2 中以 root 执行：
echo 1 > /proc/sys/vm/drop_caches      # 释放页面缓存
echo 2 > /proc/sys/vm/compact_memory   # 压缩内存
```

### 7.4 磁盘空间问题

```powershell
# 问题：vhdx 文件太大（虚拟磁盘不自动收缩）

# 1. 在 WSL2 中清理空间
sudo apt autoremove
sudo apt clean
rm -rf ~/.gradle/caches/
rm -rf ~/.m2/repository/   # 可选，下次构建会重新下载

# 2. 压缩 vhdx 文件
wsl --shutdown
diskpart
# select vdisk file="C:\Users\xxx\AppData\Local\Packages\...\ext4.vhdx"
# compact vdisk
# exit
```

### 7.5 快速问题诊断命令

```bash
# === WSL2 端 ===
uname -r                                    # 内核版本
lsb_release -a                              # 发行版信息
df -h                                       # 磁盘使用
free -h                                     # 内存使用

```
