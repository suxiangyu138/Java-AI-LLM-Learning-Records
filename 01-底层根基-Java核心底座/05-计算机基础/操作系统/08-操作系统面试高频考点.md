## 1. 基础必考题

### 题目 1：进程和线程的区别（★★★★★）

**理论核心**：

| 维度 | 进程 | 线程 |
|------|------|------|
| 定义 | 资源分配的基本单位 | CPU 调度的最小单位 |
| 内存 | 独立地址空间 | 共享进程地址空间 |
| 切换开销 | 大（页表切换、TLB 刷新）| 小 |
| 通信方式 | IPC（管道、共享内存、Socket）| 共享变量（需同步）|
| Java 对应 | JVM 进程 | `java.lang.Thread` |

**Java 关联**（面试标准回答）：

> "进程是 OS 资源分配的基本单位，有独立内存空间，切换开销大；线程是进程内的执行单元，共享进程资源，切换开销小。Java 线程底层依赖 OS 线程，采用**1:1 线程模型**。JVM 通过 `new Thread()` 创建线程时，会调用 OS API（Linux 下 `pthread_create` / `clone()`）创建对应的 OS 线程，调度由 OS 完成（抢占式调度）。"

**避坑**：
- ❌ 不要混淆"进程与线程的区别"：核心是"资源分配单位"vs"调度单位"
- ❌ 不要认为"Java 线程与 OS 无关"

### 题目 2：死锁的四个必要条件及预防（★★★★★）

**四个必要条件**（缺一不可）：

| 条件 | 说明 |
|------|------|
| **互斥** | 资源同一时间只能被一个线程占用 |
| **请求与保持** | 持有部分资源，同时请求其他资源 |
| **不可剥夺** | 已持有资源无法被强制剥夺 |
| **循环等待** | 多个线程形成循环等待链 |

**Java 中预防死锁的方案**：

```java
// 方案 1：固定锁顺序（破坏循环等待）
// 所有线程按统一顺序获取锁
lock1.lock();
lock2.lock();

// 方案 2：tryLock 设置超时（破坏不可剥夺）
if (lock1.tryLock(1, TimeUnit.SECONDS)) {
    try {
        if (lock2.tryLock(1, TimeUnit.SECONDS)) {
            // ...
        }
    } finally {
        lock1.unlock();
    }
}

// 方案 3：使用可中断锁
lock.lockInterruptibly();
```

**Java 死锁排查**：

```bash
jps -l              # 查看 Java 进程 PID
jstack <PID>        # 输出包含 "Found one Java-level deadlock"
VisualVM            # 可视化死锁检测
Arthas thread -d    # 线上排查
```

### 题目 3：虚拟内存的概念与作用（★★★★）

**核心作用**：

| 作用 | 说明 |
|------|------|
| **扩大内存空间** | 程序可使用超过物理内存的地址空间 |
| **内存隔离** | 每个进程拥有独立的虚拟地址空间 |
| **优化内存使用** | 按需调页，页面置换将不常用页面换出 |

**对 Java 的影响**：

| 影响 | 说明 |
|------|------|
| **正面** | JVM 堆内存可超过物理内存，支持内存密集型应用 |
| **负面** | 堆内存过大导致页面置换频繁，性能下降 |

> **JVM 配置建议**：堆内存设置为物理内存的 50%-70%，避免过大触发 Swap。

### 题目 4：用户态和内核态的区别（★★★★）

| 维度 | 用户态 | 内核态 |
|------|--------|--------|
| 权限 | 受限 | 全部（特权指令）|
| 内存 | 仅进程虚拟空间 | 全部物理内存 |
| 崩溃影响 | 仅该进程崩溃 | 系统崩溃（内核恐慌）|
| 切换方式 | 系统调用 / 中断 | 硬件触发 |

> **面试回答**："系统调用是用户态到内核态的唯一入口。每次 I/O 操作都涉及用户态/内核态切换，这是性能瓶颈的核心。Java NIO 的设计目的之一就是减少系统调用次数。"

## 2. 进阶高频题

### 题目 5：I/O 模型与 Java BIO/NIO/AIO 的对应关系（★★★★★）

| OS I/O 模型 | 说明 | Java 对应 |
|-------------|------|-----------|
| **阻塞 I/O** | 进程阻塞直到 I/O 完成 | **BIO**（InputStream/OutputStream）|
| **非阻塞 I/O** | 不阻塞，需轮询 | — |
| **I/O 多路复用** | select/poll/epoll 监听多路 I/O | **NIO**（Selector，Linux 下 epoll）|
| **信号驱动 I/O** | 信号通知数据就绪 | — |
| **异步 I/O** | 内核完成后回调 | **AIO**（实际使用较少）|

> ⚠️ **易错点**：Java NIO 底层依赖操作系统的 **I/O 多路复用（epoll）**，而非操作系统的非阻塞 I/O。

**epoll vs select/poll 对比**：

| 对比维度 | select | poll | epoll |
|----------|--------|------|-------|
| FD 上限 | 默认 1024 | 无 | 无 |
| 轮询方式 | 遍历所有 fd（O(n)）| 遍历所有 fd（O(n)）| **事件驱动，仅通知就绪 fd** |
| 内核拷贝 | 每次调用拷贝 | 每次调用拷贝 | **一次注册，持续使用** |
| 触发方式 | LT | LT | LT + ET |

> **易错点**：epoll 采用事件驱动模式，无需轮询，仅通知就绪的 fd。select/poll 需要轮询所有 fd。

---

### 题目 6：select / poll / epoll 的区别（★★★★★）

**标准回答框架**：

```
1. select：fd_set 位图 → 上限 1024 → O(n) 遍历 → 每次全量拷贝
2. poll：pollfd 链表 → 无上限 → O(n) 遍历 → 每次全量拷贝
3. epoll：红黑树 + 就绪链表 → 无上限 → O(1) 获取 → 一次注册
```

| 说明 | select | poll | epoll |
|------|--------|------|-------|
| **数据结构** | 位图 | 链表 | 红黑树 + 链表 |
| **最大连接数** | 1024 | 无上限 | 无上限 |
| **复杂度** | O(n) | O(n) | O(1) |
| **触发模式** | LT | LT | LT + ET |
| **跨平台** | 全平台 | 全平台 | 仅 Linux |

### 题目 7：进程调度算法（★★★★）

| 算法 | 核心思想 | 特点 |
|------|----------|------|
| **FCFS**（先来先服务） | 按到达顺序 | 简单，护航效应 |
| **SJF**（短作业优先） | 优先最短作业 | 平均等待时间最小，长作业饥饿 |
| **RR**（时间片轮转） | 固定时间片轮流 | 响应快，分时系统核心 |
| **优先级调度** | 最高优先级 | 低优先级饥饿（老化解决）|
| **多级反馈队列** | 多队列 + 动态调整 | **现代 OS 默认** |

**Java 关联**：
- Java 线程优先级（1-10）本质是给 OS 优先级"打标签"，**仅供参考**
- Java 采用**抢占式调度**，与 OS 一致
- 实战中**不依赖线程优先级**保证执行顺序

### 题目 8：分页 vs 分段（★★★★）

| 维度 | 分页 | 分段 |
|------|------|------|
| 划分依据 | 固定大小（物理划分）| 按程序逻辑（逻辑划分）|
| 大小 | 固定（通常 4KB）| 不固定 |
| 目的 | 提高内存利用率 | 满足程序逻辑需求 |
| 对程序员 | 透明 | 可见 |
| 碎片 | 内部碎片 | 外部碎片 |
| JVM 关联 | 内存分配依赖 OS 分页 | 内存分区（堆、栈、方法区）体现场景 |

---

### 题目 9：inode 是什么？包含哪些信息？（★★★★）

**inode（索引节点）**：描述文件属性和存储位置的核心数据结构。

**关键信息**：
- 文件权限、大小、所有者、时间戳
- **文件名不存储在 inode 中**（存储在目录项中）

**Java 关联**：

| 方法 | 对应 inode 字段 |
|------|----------------|
| `file.length()` | 文件大小 |
| `file.lastModified()` | 修改时间（mtime）|
| `file.canRead()`/`canWrite()` | 文件权限 |
| `file.delete()` | 删除目录项映射（inode 引用减 1）|

> ⚠️ **坑点**：不要说"inode 存储文件名"。文件名存储在目录项（dentry）中。

### 题目 10：硬链接 vs 软链接的区别（★★★★）

| 对比 | 硬链接 | 软链接（符号链接）|
|------|--------|-------------------|
| inode | **相同**（同一文件）| **不同** |
| 跨文件系统 | **不可以** | **可以** |
| 目录 | 不可以 | 可以 |
| 源文件删除后 | 仍可访问 | 失效 |


### 题目 11：操作系统的缓存机制与 Java I/O 优化（★★★★★）

**核心缓存**：

| 缓存 | 说明 |
|------|------|
| **页缓存（Page Cache）** | 缓存磁盘文件内容，减少磁盘 I/O |
| **Buffer Cache** | 缓解 CPU 与 I/O 设备的速度差异 |

**优化方案**：

| 方案 | 原理 | Java 实现 |
|------|------|-----------|
| 零拷贝 | 减少数据在内核与用户空间之间的复制 | `FileChannel.transferTo()` |
| 内存映射文件 | 将文件直接映射到进程地址空间 | `MappedByteBuffer` |
| 批量 I/O | 减少系统调用次数 | `BufferedInputStream` |
| 大缓冲区 | 与 OS 页大小对齐（4KB/8KB） | `ByteBuffer.allocate(4096)` |

> **面试回答**："Java 程序写文件时，数据先写入 Page Cache，由内核异步刷盘。核心业务需要在写完后调用 `FileChannel.force(true)` 强制刷盘，防止数据丢失。"

## 3. 高阶难点题

### 题目 12：信号量的原理与 Java 实现（★★★★）

**信号量**：Dijkstra 提出的同步机制，本质是一个计数器。

**核心操作**：
- **P 操作（acquire）**：申请资源，信号量减 1，<0 则阻塞
- **V 操作（release）**：释放资源，信号量加 1，≤0 则唤醒

```java
import java.util.concurrent.Semaphore;

// 限流 5 个并发线程
Semaphore semaphore = new Semaphore(5);
semaphore.acquire();  // P 操作：申请资源
// ... 使用资源 ...
semaphore.release();  // V 操作：释放资源
```

### 题目 13：死锁检测与排查（★★★★）

**OS 检测方法**：**资源分配图算法**——构建进程和资源的关系图，如果存在无法化简的环路，则存在死锁。

**Java 排查方法**：

| 方法 | 命令 | 说明 |
|------|------|------|
| **jstack** | `jstack <PID>` | 最常用，查找 "Found one Java-level deadlock" |
| **VisualVM** | `jvisualvm` | 可视化自动检测 |
| **Arthas** | `thread -d` | 线上排查，功能强大 |
| **jconsole** | `jconsole` | JDK 自带，查看线程状态 |

### 题目 14：零拷贝的原理与 Java 实现（★★★★）

**传统 I/O 的数据拷贝路径**：

```
磁盘 → 内核缓冲区（DMA）→ 用户缓冲区（CPU）→ 内核 Socket 缓冲区（CPU）→ 网卡（DMA）
```

**零拷贝优化后**：

```
磁盘 → 内核缓冲区（DMA）→ 网卡（DMA，仅需描述符）
```

**Java 零拷贝 API**：

```java
// 底层调用 Linux sendfile()
sourceChannel.transferTo(0, sourceChannel.size(), targetChannel);
```

### 题目 15：LRU 缓存的 Java 实现（★★★★）

```java
import java.util.LinkedHashMap;
import java.util.Map;

public class LRUCache<K, V> extends LinkedHashMap<K, V> {
    private final int capacity;

    public LRUCache(int capacity) {
        super(capacity, 0.75f, true); // accessOrder=true
        this.capacity = capacity;
    }

    @Override
    protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
        return size() > capacity;
    }
}
```

## 4. 笔试高频题

### 4.1 选择题高频陷阱

**核心易错点**：

| 知识点 | 易错说法 | 正确理解 |
|--------|----------|----------|
| 进程 vs 线程 | "线程是资源分配的基本单位" | 进程是资源分配的基本单位，线程是调度的基本单位 |
| 并发 vs 并行 | "并发就是同时运行" | 并发是逻辑同时（单核交替），并行是物理同时（多核）|
| epoll 轮询 | "epoll 也需轮询所有 fd" | epoll 是事件驱动，仅通知就绪 fd |
| 分页 vs 分段 | "分页按逻辑划分" | 分页按固定大小（物理划分），分段按逻辑划分 |
| inode | "inode 存储文件名" | inode 不存文件名，目录项存文件名到 inode 的映射 |
| 死锁条件 | "三个条件即可" | 必须同时满足四个条件 |
| 内存泄漏 vs 溢出 | "内存泄漏等于溢出" | 泄漏积累可能导致溢出，但概念不同 |

### 4.2 编程题：Java NIO 高并发服务器

**笔试评分点**：

1. ✅ Channel 必须设置为非阻塞模式（`configureBlocking(false)`）
2. ✅ Selector 注册事件（`OP_ACCEPT` + `OP_READ`）
3. ✅ 处理就绪事件后必须调用 `iterator.remove()`，避免重复处理
4. ✅ 缓冲区的 `flip()` 方法切换为读模式

### 4.3 计算题：地址转换

**题型**：给定逻辑地址（虚拟地址）和页大小，计算页号和页内偏移，查页表得到物理地址。

```
虚拟地址 A=4097，页大小 L=4096（4KB）
页号 P = A / L = 4097 / 4096 = 1
页内偏移 W = A % L = 4097 % 4096 = 1
查页表：页号 1 → 帧号 3
物理地址 = 3 × 4096 + 1 = 12289
```

### 5.3 易错点汇总

| # | 易错点 | 正确理解 |
|---|--------|----------|
| 1 | 混淆 epoll 和 select/poll 的轮询方式 | epoll 事件驱动，select/poll 轮询 |
| 2 | 死锁条件记忆不完整 | 必须同时满足四个条件 |

| 5 | 遗漏 `iterator.remove()` | 不调用会导致重复处理 |
| 6 | Java 线程优先级可控制执行顺序 | 仅是建议，OS 最终决定 |
