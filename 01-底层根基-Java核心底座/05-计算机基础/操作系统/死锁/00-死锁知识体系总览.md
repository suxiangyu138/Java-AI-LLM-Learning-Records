## 3. 学习路线推荐

### 路线一：入门（1 天）——建立直觉

01 → 02 → 03，重点掌握：

- 四条件判断法：先看互斥，再看持有等待、不可剥夺、循环等待
- 哲学家就餐与转账 ABBA 两个标准模型
- 预防的核心手段：**全局锁序**（按固定顺序加锁）

### 路线二：进阶（2-3 天）——算法与系统

04 → 05 → 06，重点掌握：

- 银行家算法的手算推演（会画表、会找安全序列）
- WFG 找环（DFS）与解除策略
- InnoDB 死锁检测机制与参数（面试 + 生产双高频）

### 路线三：专家（1 周+）——内核与前沿

07 → 08 + 源码，阅读：

- lockdep 与 DEPT 的依赖图思想（[DEPT v19 patchset](https://lists.linaro.org/archives/list/linaro-mm-sig@lists.linaro.org/thread/R47Q7TNQ3H2NXLZEXQF2NEKTBMDN6B7O/)）

## 4. 核心概念速查

| 概念 | 一句话定义 | 关键要点 |
|------|-----------|---------|
| 死锁 | 一组进程互相等待对方持有的资源而永远阻塞 | 四条件同时成立 |
| 互斥 | 资源一次只能被一个进程使用 | 死锁的必要非充分条件 |
| 持有并等待 | 持有一个资源的同时等待另一个 | 可被"一次性获取"破坏 |
| 不可剥夺 | 资源只能由持有者主动释放 | 可被"超时抢占"破坏 |
| 循环等待 | 等待链形成环 | 可被"全局锁序"破坏 |
| 饥饿 | 进程永远等不到资源（不阻塞，是调度不公） | 与死锁不同：等得到就是不死锁 |
| 活锁 | 进程不断让出资源重试，但永不前进 | 与死锁不同：资源在流动 |
| 等待图（WFG） | 节点=事务，边=等待关系 | 有环 = 死锁 |
| 银行家算法 | 按安全性检查分配，保证安全状态 | 需先知每个进程的最大需求 |
| 安全状态 | 存在安全序列，可保证所有进程完成 | 无死锁的充分非必要条件 |
| lockdep | Linux 内核锁序校验器 | 构建锁序图，发现违反顺序 |
| DEPT | 依赖跟踪器（2026 实验性） | 跟踪 S/W/E，覆盖 lockdep 盲区 |
| innodb_lock_wait_timeout | 锁等待超时（默认 50s） | 检测失效时的兜底 |
| CMH 探测 | 分布式死锁的边沿追逐算法 | probe 回到起点 = 有环 |
