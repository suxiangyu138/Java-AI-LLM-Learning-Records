# 线程与并发

## 📌 课程定位
并发编程是后端开发的必备技能。从Java的多线程到Go的goroutine，从锁到无锁编程，理解线程模型和同步机制是写出正确并发程序的前提。

## 🎯 核心章节

### 1. 线程概念
- **线程 = 轻量级进程**：同一进程的线程共享代码段、数据段、打开文件，独享栈和寄存器
- **线程 vs 进程的取舍**：线程切换开销小（无需切换地址空间），但一个线程崩溃可能拖垮整个进程
- **内核级线程 vs 用户级线程**：
  | 内核级线程 | 用户级线程（协程前身） |
  |----------|-------------------|
  | OS可见、可调度 | OS不可见、用户态管理 |
  | 多核并行 | 同一时刻只能一个执行 |
  | 切换需进内核态 | 切换极快（用户态） |

### 2. 并发与并行
- **并发（Concurrency）**：单核上交替执行，逻辑上"同时"——通过时间片轮转实现
- **并行（Parallelism）**：多核上真正同时执行——需要硬件支持
- **并发问题本质**：多个执行流共享可变状态 → 竞态条件（Race Condition）

### 3. 同步与互斥（⭐ 面试核心）

**互斥锁（Mutex）**：
- 临界区一次只允许一个线程进入
- 自旋锁：忙等（不释放CPU），适合临界区极短的场景
- 互斥锁：阻塞等待（释放CPU），适合临界区较长的场景

**信号量（Semaphore）**：
- P操作(wait)：信号量减1，若<0则阻塞
- V操作(signal)：信号量加1，若≤0则唤醒
- 二元信号量 = 互斥锁；计数信号量 = 资源池管理

**条件变量（Condition Variable）**：
- `wait()` + `signal()`/`broadcast()` 实现等待-通知模式
- 生产者-消费者模型的优雅实现

**经典同步问题（⭐ 必能分析）**：
- **生产者-消费者**：有限缓冲区，mutex+full+empty三个信号量
- **读者-写者**：读共享、写独占、写优先/读优先策略
- **哲学家进餐**：死锁预防（破坏循环等待条件）

### 4. 死锁（⭐ 必考）
- **死锁四必要条件**（缺一不死锁）：
  1. 互斥：资源一次只能被一个进程用
  2. 占有且等待：持有资源的同时等待新资源
  3. 不可抢占：已分配的资源不能被强制剥夺
  4. 循环等待：存在进程资源的环形等待链
- **死锁处理策略**：
  - 预防：破坏四个条件之一（如一次性分配所需全部资源）
  - 避免：银行家算法——分配前判断是否仍处于安全状态
  - 检测与恢复：允许死锁发生，检测到后终止进程或回滚
  - 鸵鸟策略：假装没看见（多数OS的做法——死锁很少发生）

### 5. 锁与并发编程实践
- **CAS（Compare-And-Swap）**：无锁编程的原子操作基础——Java AtomicInteger、Go atomic包
- **volatile**：禁止指令重排、保证可见性（但不保证原子性）
- **线程安全的数据结构**：ConcurrentHashMap(synchronized+分段锁/CAS)、CopyOnWriteArrayList
- **死锁排查**：jstack 查看线程栈 / `gdb attach` + `thread apply all bt`

## ✅ 学习建议
- 信号量和互斥锁的区别一定要搞清楚（信号量是"资源数"的概念）
- 手写生产者-消费者模型（Java wait/notify 或 Go channel 两种实现）
- 死锁分析是面试高频题——拿到问题先判断是不是死锁，再分析四个条件
