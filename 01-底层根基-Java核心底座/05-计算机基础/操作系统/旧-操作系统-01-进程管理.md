# 进程管理

## 📌 课程定位
进程是操作系统最核心的抽象——它让每个程序以为自己独占CPU。理解进程是理解并发、调度、容器（docker本质是进程+namespace隔离）的基础。

## 🎯 核心章节

### 1. 进程概念
- **进程定义**：运行中的程序 = 程序代码(静态) + 数据 + PCB(进程控制块)
- **进程映像**：代码段 + 数据段 + 堆 + 栈 + PCB
- **进程特征**：动态性、并发性、独立性、异步性
- **进程 vs 线程 vs 协程**：资源分配单位 vs CPU调度单位 vs 用户态轻量级调度

### 2. 进程状态与转换（⭐ 三态/五态/七态模型）
```
创建 → 就绪 ⇄ 运行 → 终止
         ↖ 等待/阻塞 ↗
```
- **五态**：创建 → 就绪 → 运行 → 阻塞 → 终止（新增挂起态变为七态）
- **状态转换触发**：
  - 就绪→运行：被调度程序选中（获得CPU）
  - 运行→就绪：时间片用完（被抢占）
  - 运行→阻塞：等待I/O完成、等待锁释放
  - 阻塞→就绪：I/O完成、获得锁

### 3. PCB（进程控制块）
- **PCB内容**：PID、进程状态、PC值、寄存器上下文（保存现场）、内存管理信息、打开文件列表
- **组织方式**：链表(就绪队列、阻塞队列)、索引表

### 4. 进程调度（⭐ 面试重点）
- **调度层次**：高级(作业调度，决定哪个作业进内存)、中级(内存调度，挂起/激活)、低级(进程调度，决定哪个进程获得CPU)
- **调度时机**：
  - 运行→阻塞（非抢占）
  - 运行→就绪（抢占——时间片用完/更高优先级就绪）
  - 阻塞→就绪（新就绪进程优先级可能更高→抢占）
  - 进程终止

### 5. 经典调度算法
| 算法 | 规则 | 特点 |
|------|------|------|
| FCFS（先来先服务） | 按到达顺序 | 简单，短作业可能等长作业（护航效应） |
| SJF（短作业优先） | 选预计运行时间最短的 | 平均等待时间最优，但需要预知运行时间 |
| 优先级调度 | 最高优先级先运行 | 低优先级可能饿死→老化(aging)技术 |
| RR（时间片轮转） | 每个进程轮流运行固定时间片 | 交互式系统常用，时间片选择很重要 |
| 多级反馈队列（⭐ 最实用） | 多队列不同优先级和时间片 | 兼顾响应时间和吞吐量，Linux/Windows都采用 |

### 6. 进程间通信（IPC）
- **管道（Pipe）**：半双工、父子进程间——匿名管道 `|`、命名管道(FIFO)
- **消息队列**：消息的链表，独立于进程存在
- **共享内存**：最快IPC，多进程映射同一物理内存→需同步（信号量）
- **信号（Signal）**：异步通知——SIGKILL(-9)、SIGTERM(-15)、SIGCHLD
- **Socket**：网络通信，不仅限于同机进程

## ✅ 学习建议
- 理解"进程是资源分配单位"这个定义——Linux fork() 创建进程，clone() 有不同参数
- 调度算法重点看多级反馈队列——灵活且实际使用最广
- 用 ps/top/htop 观察系统进程，用 `kill -l` 查看信号列表
