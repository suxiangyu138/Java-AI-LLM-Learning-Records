## 1. 进程的基本概念

### 1.1 进程的定义

**进程**：程序在计算机中的一次执行过程，是系统进行**资源分配和调度的基本单位**。

```
进程 = 程序代码（静态） + 数据 + PCB（进程控制块）
     = 代码段 + 数据段 + 堆 + 栈 + PCB
```

### 1.2 进程 vs 程序

| 对比维度 | 程序 | 进程 |
|----------|------|------|
| 本质 | 静态指令集合（如 .exe 文件） | 动态执行过程 |
| 生命周期 | 长期存在（磁盘上） | 创建→运行→终止（有生命周期） |
| 资源占用 | 不占用系统资源（CPU、内存） | 占用 CPU、内存、I/O 资源 |
| 对应关系 | 一个程序可对应多个进程 | 一个进程只对应一个程序实体 |

### 1.3 进程的四大特征

| 特征 | 说明 |
|------|------|
| **动态性** | 进程是程序的执行过程，有生命周期 |
| **并发性** | 多个进程可在一段时间内同时运行 |
| **独立性** | 进程是资源分配的基本单位，相互独立 |
| **异步性** | 进程以不可预知的速度推进 |

> 💡 **Java 场景**：每个 Spring Boot 服务就是一个独立的 Java 进程，拥有各自的 JVM 实例和内存空间。多个微服务就是多个独立的 JVM 进程。

## 2. 进程控制块（PCB）

### 2.1 定义

PCB（Process Control Block）是**进程存在的唯一标志**。OS 通过 PCB 管理和控制所有进程。创建进程时创建 PCB，终止进程时回收 PCB。

### 2.2 PCB 包含的信息

| 信息类别 | 具体内容 | Java 类比 |
|----------|----------|-----------|
| **进程标识** | PID（进程 ID）、PPID（父进程 ID） | `Thread.getId()` |
| **进程状态** | 就绪、运行、阻塞等 | `Thread.getState()` |
| **CPU 状态信息** | 程序计数器（PC）、寄存器上下文 | 线程栈帧 |
| **调度信息** | 优先级、调度队列指针 | Java 线程优先级（1-10） |
| **内存管理信息** | 页表指针、内存限制 | JVM 内存区域信息 |
| **资源分配信息** | 打开文件列表、设备使用情况 | `FileDescriptor` |

### 2.3 PCB 的组织方式

- **链表方式**：就绪队列、阻塞队列、运行队列——按状态分队列管理
- **索引表方式**：按进程状态建立索引表，通过索引快速定位

## 3. 进程状态与转换

### 3.1 三态模型（基础）

```
        ┌──────────┐
        │   创建    │
        └────┬─────┘
             │ 就绪
        ┌────▼─────┐
   ┌───►│   就绪    │◄──────────┐
   │    └──┬───┬───┘           │
   │ 调度 │   │ 时间片用完     │ 事件完成
   │    ┌─▼──┐│                │
   │    │运行├┘                │
   │    └─┬──┘                 │
   │      │ 等待事件（I/O 请求）  │
   │   ┌──▼────┐               │
   │   │  阻塞  ├───────────────┘
   │   └──┬────┘
   │      │ 终止
   │   ┌──▼────┐
   └───┤  终止  │
       └───────┘
```

### 3.2 五态模型（加入创建和终止）

| 状态 | 说明 |
|------|------|
| **创建（New）** | 进程正在创建，OS 为其分配资源、初始化 PCB |
| **就绪（Ready）** | 进程已具备运行条件，等待 CPU 调度 |
| **运行（Running）** | 进程获得 CPU，正在执行指令 |
| **阻塞（Blocked）** | 进程等待某个事件（I/O 完成、锁释放） |
| **终止（Terminated）** | 进程执行完毕或被强制终止，OS 回收资源 |

### 3.3 状态转换触发条件

| 转换 | 触发条件 |
|------|----------|
| 就绪 → 运行 | 调度程序选中该进程（获得 CPU） |
| 运行 → 就绪 | 时间片用完 / 被更高优先级进程抢占 |
| 运行 → 阻塞 | 等待 I/O 完成 / 等待锁释放 / 等待信号 |
| 阻塞 → 就绪 | I/O 完成 / 获得锁 / 收到信号 |

### 3.4 Java 线程状态对应关系

| OS 进程状态 | Java `Thread.State` |
|-------------|---------------------|
| 就绪 + 运行 | **RUNNABLE** |
| 阻塞（锁等待） | **BLOCKED** |
| 阻塞（无条件等待） | **WAITING** |
| 阻塞（计时等待） | **TIMED_WAITING** |
| 终止 | **TERMINATED** |
| 创建 | **NEW** |

> ⚠️ Java 的 `RUNNABLE` 状态合并了 OS 的"就绪"和"运行"两个状态，这是面试常考点。

## 4. 进程调度

### 4.1 调度层次

| 层次 | 别名 | 功能 | 频率 |
|------|------|------|------|
| **高级调度** | 作业调度 | 外存作业 → 内存（创建进程） | 低 |
| **中级调度** | 内存调度 | 挂起/激活进程（释放内存） | 中 |
| **低级调度** | 进程调度 | 就绪队列 → CPU（分配 CPU） | **最高** |

### 4.2 调度时机（抢占 vs 非抢占）

| 触发场景 | 调度类型 | 说明 |
|----------|----------|------|
| 运行 → 阻塞 | **非抢占** | 进程主动放弃 CPU |
| 运行 → 就绪（时间片用完） | **抢占** | 时间片轮转的基础 |
| 运行 → 就绪（新进程优先级更高） | **抢占** | 优先级调度 |
| 进程终止 | **非抢占** | 进程正常结束 |

### 4.3 调度目标

| 目标 | 说明 |
|------|------|
| **CPU 利用率** | CPU 尽可能忙碌 |
| **吞吐量** | 单位时间完成的进程数 |
| **周转时间** | 从提交到完成的总时间（越短越好） |
| **等待时间** | 在就绪队列中等待的总时间 |
| **响应时间** | 从提交到首次响应的时间（交互式系统关注）|

## 5. 经典调度算法

### 5.1 算法总览

| 算法 | 核心思想 | 特点 | 饥饿问题 |
|------|----------|------|----------|
| **FCFS**（先来先服务） | 按到达顺序依次执行 | 简单公平，护航效应（短作业等长作业） | 无 |
| **SJF**（短作业优先） | 优先执行最短作业 | 平均周转时间最短，需预知运行时间 | 长作业可能饥饿 |
| **RR**（时间片轮转） | 固定时间片轮流执行 | 响应快，分时系统核心，时间片大小关键 | 无 |
| **优先级调度** | 高优先级先执行 | 支持抢占/非抢占 | 低优先级可能饥饿 |
| **HRRN**（高响应比优先） | 响应比 = (等待+运行)/运行 | 兼顾长短作业，无饥饿 | 无 |
| **多级反馈队列** | 多队列 + 动态调整 | **现代 OS 默认**（如 Linux CFS） | 兼顾所有作业 |

### 5.2 调度算法选择策略

```
批处理系统：FCFS + SJF / 优先级
分时系统：RR + 多级反馈队列
实时系统：硬实时调度（EDF、RMS）
Java 线程：由 OS 调度（Linux CFS），Java 优先级仅是建议
```

### 5.3 Java 线程调度关联

| Java 特性 | OS 调度对应 |
|-----------|-------------|
| `Thread.setPriority()` | 给 OS 优先级打标签（**仅供参考**）|
| 抢占式调度 | Java 多线程默认采用，与 OS 一致 |
| `Thread.yield()` | 建议 OS 暂停当前线程（不保证） |
| 时间片 | 由 OS 决定，Java 无法控制 |

> ⚠️ **实战警示**：不要依赖线程优先级保证执行顺序。Java 线程优先级（1-10）映射到 OS 优先级后，具体调度行为由 OS 决定，不同 OS 映射规则不同。

## 6. 进程间通信（IPC）

### 6.1 IPC 方式总览

| IPC 方式 | 特点 | 数据量 | Java 对应 |
|----------|------|--------|-----------|
| **管道（Pipe）** | 半双工，父子进程间 | 小 | — |
| **命名管道（FIFO）** | 无亲缘关系也可用 | 小 | — |
| **信号（Signal）** | 异步通知，传输信息量小 | 极小 | `Thread.interrupt()` |
| **消息队列** | 有类型和边界，内核维护 | 中 | JMS、RabbitMQ（应用层） |
| **共享内存** | 最快 IPC，需额外同步 | **大** | `MappedByteBuffer` |
| **信号量** | 计数器，控制资源访问 | — | `java.util.concurrent.Semaphore` |
| **Socket** | 跨网络通信 | 大 | `java.net.Socket`、Netty |

### 6.2 通信方式对比

```
管道：     进程A ——————→ 进程B    （单向，父子进程）
共享内存：  进程A ────────┐
            共享内存 ←───┤  （最快，需同步）
          进程B ────────┘
Socket：   进程A ←──网络──→ 进程B  （跨机器，通用）
```

### 6.3 Java 微服务场景的 IPC

| 通信方式 | 实现技术 | 适用场景 |
|----------|----------|----------|
| **RPC** | Dubbo、gRPC、Spring Cloud OpenFeign | 服务间同步调用 |
| **消息队列** | RabbitMQ、Kafka、RocketMQ | 异步解耦、削峰填谷 |
| **HTTP API** | RestTemplate、WebClient | 轻量级服务通信 |

## 7. 线程

### 7.1 线程的定义

**线程**：进程内的一个执行单元，是 CPU **调度和分派的基本单位**。

### 7.2 线程的特征

| 特征 | 说明 |
|------|------|
| **轻量级** | 创建/销毁开销远小于进程 |
| **资源共享** | 同一进程内线程共享堆内存、方法区、文件句柄 |
| **独立栈** | 每个线程拥有独立的程序计数器（PC）和栈空间 |
| **调度依赖** | 必须依附于进程，进程终止则线程终止 |

### 7.3 进程 vs 线程核心区别

| 对比维度 | 进程 | 线程 | Java 后端实战影响 |
|----------|------|------|-------------------|
| 资源分配 | 最小单位，独立分配 | 不独立，共享进程资源 | 多进程隔离性好但开销大；多线程资源利用率高 |
| 调度单位 | OS 调度的基本单位（早期） | OS 调度的最小单位（现在） | Java 多线程依赖 OS 调度 |
| 通信方式 | IPC（管道、消息队列、Socket） | 共享内存、锁机制 | 微服务间用 HTTP/RPC；线程内用 synchronized/Lock |
| 切换开销 | **大**（切换页表、刷新 TLB） | **小**（共享地址空间） | 用线程池复用线程，减少切换 |
| 故障影响 | 进程崩溃不影响其他进程 | 线程崩溃可能导致**进程崩溃** | 需处理线程异常，避免宕机 |

### 7.4 内核级线程 vs 用户级线程

| 维度 | 内核级线程（KLT） | 用户级线程（ULT） |
|------|------------------|-------------------|
| OS 可见性 | OS 可见、可调度 | OS 不可见、用户态管理 |
| 多核并行 | 支持（真正的并行） | 不支持（同一时刻只能一个执行） |
| 切换开销 | 大（需进内核态） | **小**（用户态切换） |
| 实现 | OS 内核管理 | 用户程序（线程库）管理 |
| 阻塞影响 | 阻塞单独线程 | 阻塞整个进程 |

> 💡 **Java 线程模型**：从 JDK 1.2 开始，Java 采用 **1:1 线程模型**，即一个 Java 线程对应一个内核级线程（系统级线程）。Java 线程不是用户级线程。

## 8. Java 线程与 OS 线程的映射关系

### 8.1 1:1 线程模型

```
Java 代码              JVM                 OS 内核
┌──────────────┐   ┌──────────────┐   ┌──────────────┐
│ new Thread() │ → │ JNI 调用      │ → │ pthread_    │
│ .start()     │   │              │   │ create()    │
│              │   │              │   │ (clone())   │
└──────────────┘   └──────────────┘   └──────┬───────┘
                                             │
                                      ┌──────▼───────┐
                                      │ OS 内核线程    │
                                      │（轻量级进程）  │
                                      └──────────────┘
```

### 8.2 线程创建方式对比

```java
// 方式 1：继承 Thread 类（直接）
class MyThread extends Thread {
    @Override
    public void run() { /* 线程逻辑 */ }
}

// 方式 2：实现 Runnable 接口（推荐，解耦任务与线程）
class MyRunnable implements Runnable {
    @Override
    public void run() { /* 线程逻辑 */ }
}

// 方式 3：实现 Callable 接口（带返回值）
class MyCallable implements Callable<Integer> {
    @Override
    public Integer call() { return 42; }
}

// 方式 4：线程池（生产环境首选）
ExecutorService executor = Executors.newFixedThreadPool(10);
executor.submit(() -> System.out.println("任务执行"));
```

### 8.3 Java 线程生命周期

```
NEW ──start()──► RUNNABLE ──运行结束──► TERMINATED
                    │
              阻塞操作（sleep/wait/lock）
                    │
               ┌────▼────┐
               │ BLOCKED │ WAITING │ TIMED_WAITING
               └────┬────┘
                    │ 条件满足
                    │
              返回 RUNNABLE
```

### 8.4 Linux 下 Java 线程的底层实现

```bash
# 查看 Java 进程的线程（轻量级进程）
ps -T -p <PID>

# 查看线程详细信息
top -H -p <PID>

# Java 线程名与 OS 线程名对应
jstack <PID> | grep "tid"
```

## 9. 协程与虚拟线程

### 9.1 协程概念

**协程**：用户态的轻量级线程，由程序自身管理调度，不由 OS 内核管理。

| 维度 | 线程 | 协程/虚拟线程 |
|------|------|---------------|
| 调度者 | OS 内核 | 用户态调度器（JVM） |
| 切换开销 | 大（内核态切换） | **极小**（用户态切换） |
| 栈大小 | 固定（通常 1MB） | 动态增长（可小至几 KB） |
| 创建数 | 有限（数千） | **海量**（数十万） |
| 阻塞影响 | 阻塞 OS 线程 | 仅阻塞当前协程 |

### 9.2 Java 虚拟线程（Project Loom）

JDK 21 正式引入**虚拟线程（Virtual Thread）**，采用 **M:N 映射**：

```
Java 虚拟线程 → 平台线程（载体线程）→ OS 线程
     M                  N                  N
```

```java
// 创建虚拟线程（JDK 21+）
Thread vThread = Thread.startVirtualThread(() -> {
    System.out.println("虚拟线程执行");
});

// 使用虚拟线程池
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    executor.submit(() -> task());
}
```

## 10. 多处理机系统

### 10.1 SMP vs DMP

| 特征 | SMP（对称多处理） | DMP（松散耦合） |
|------|------------------|-----------------|
| 内存 | 多 CPU 共享同一套内存 | 每个 CPU 拥有独立本地内存 |
| 地位 | 所有 CPU 平等 | 各节点独立 |
| 瓶颈 | 内存总线争用 | 网络通信延迟 |
| Java 关联 | 线程池参数匹配 CPU 核心数 | 分布式系统微服务架构 |

### 10.2 多核环境下的同步

| OS 机制 | 说明 | Java 对应 |
|---------|------|-----------|
| 互斥锁（Mutex） | 保证同一时刻只有一个 CPU 访问共享资源 | `synchronized` |
| 信号量（Semaphore） | 控制资源并发访问数量 | `ReentrantLock` |
| 自旋锁（Spinlock） | 忙等，适合临界区极短场景 | — |
| 缓存一致性（MESI） | 保证多核缓存数据一致 | `volatile` 语义 |

### 10.3 线程池配置原则（结合多处理机）

| 任务类型 | 核心线程数公式 | 说明 |
|----------|---------------|------|
| **CPU 密集型** | CPU 核心数 + 1 | 避免过多上下文切换 |
| **I/O 密集型** | CPU 核心数 × 2 | 充分利用 I/O 等待时间 |

```java
int cores = Runtime.getRuntime().availableProcessors();

// CPU 密集型
ThreadPoolExecutor cpuPool = new ThreadPoolExecutor(
    cores + 1, cores + 1, 60L, TimeUnit.SECONDS,
    new ArrayBlockingQueue<>(100));

// I/O 密集型
ThreadPoolExecutor ioPool = new ThreadPoolExecutor(
    cores * 2, cores * 4, 60L, TimeUnit.SECONDS,
    new LinkedBlockingQueue<>());
```
