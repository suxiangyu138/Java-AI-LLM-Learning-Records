## 一、操作系统死锁核心理论精讲

### 1.1 死锁的定义

多个进程（或线程）互相持有对方所需的资源，且都无法主动释放自己持有的资源，导致所有进程都陷入永久阻塞，无法继续执行的状态。

> **误区一**：死锁不是"单个线程阻塞"，而是"多个线程互相等待"。
>
> **误区二**：死锁的核心是"资源不可剥夺"。

### 1.2 死锁的成因

| 成因 | 说明 | Java 场景 |
|------|------|-----------|
| **资源有限性** | OS 资源（CPU、内存、锁）是有限的 | 数据库连接池耗尽 |
| **资源不可剥夺性** | 线程持有资源后除非主动释放，否则无法强制剥夺 | synchronized 锁 |
| **资源请求与保持** | 持有部分资源的同时请求其他资源 | 持有锁 A 请求锁 B |
| **循环等待条件** | 多个线程形成循环等待链 | A 等 B，B 等 A |

### 1.3 死锁的四大必要条件（必须同时满足）

| 条件 | 说明 |
|------|------|
| **互斥** | 资源同一时间只能被一个线程持有 |
| **持有并等待** | 持有部分资源后等待其他资源，且不释放已持有资源 |
| **不可剥夺** | 已持有资源无法被强制剥夺 |
| **循环等待** | 多个线程形成循环等待链 |

> 只要打破其中一个条件，死锁就不会发生。

## 二、Java 后端死锁实战剖析

### 2.1 常见死锁场景

#### 场景 1：多线程竞争多个对象锁（最基础）

```java
public class DeadLockDemo {
    private static final Object lockA = new Object();
    private static final Object lockB = new Object();

    public static void main(String[] args) {
        // 线程 1：持有 lockA，等待 lockB
        new Thread(() -> {
            synchronized (lockA) {
                System.out.println("线程1：持有lockA，等待lockB");
                try { Thread.sleep(1000); } catch (InterruptedException e) { }
                synchronized (lockB) {
                    System.out.println("线程1：获取lockB，执行完成");
                }
            }
        }).start();

        // 线程 2：持有 lockB，等待 lockA
        new Thread(() -> {
            synchronized (lockB) {
                System.out.println("线程2：持有lockB，等待lockA");
                try { Thread.sleep(1000); } catch (InterruptedException e) { }
                synchronized (lockA) {
                    System.out.println("线程2：获取lockA，执行完成");
                }
            }
        }).start();
    }
}
```

#### 场景 2：线程池 + 锁竞争（线上高频）

线程池线程有限 + 锁竞争，导致线程持有一个锁后等待另一个锁，线程无法释放，最终线程池耗尽。

#### 场景 3：分布式场景下的死锁

多个微服务竞争分布式锁，形成跨节点的循环等待。

### 2.2 死锁排查方法

#### 方法 1：jps + jstack（最常用）

```bash
jps -l                    # 查看 Java 进程 PID
jstack <PID>              # 查看线程栈，输出包含 "Found one Java-level deadlock"
jstack <PID> > deadlock.log  # 输出到文件
```

#### 方法 2：VisualVM（可视化）

JDK 安装目录下 `jvisualvm.exe` → 连接进程 → 点击"线程"标签 → "死锁检测"。

#### 方法 3：Arthas（线上进阶）

```bash
# 启动 Arthas 后执行
thread -d
```

### 2.3 死锁预防策略（核心重点）

#### 策略 1：固定锁的获取顺序（打破"循环等待"）

```java
// 两个线程都先获取 lockA，再获取 lockB
new Thread(() -> {
    synchronized (lockA) {
        synchronized (lockB) {
            System.out.println("线程1：执行完成");
        }
    }
}).start();

new Thread(() -> {
    synchronized (lockA) {  // 同样先获取 lockA
        synchronized (lockB) {
            System.out.println("线程2：执行完成");
        }
    }
}).start();
```

#### 策略 2：一次性获取所有资源（打破"持有并等待"）

一次性申请所有需要的资源，失败则全部释放。

#### 策略 3：使用可中断锁（打破"不可剥夺"）

```java
private static final Lock lockA = new ReentrantLock();
private static final Lock lockB = new ReentrantLock();

new Thread(() -> {
    try {
        lockA.lockInterruptibly();  // 可中断获取锁
        try {
            Thread.sleep(1000);
            lockB.lockInterruptibly();
        } finally {
            lockB.unlock();
        }
    } catch (InterruptedException e) {
        // 被中断时释放已持有的锁
        if (lockA.isHeldByCurrentThread()) lockA.unlock();
        if (lockB.isHeldByCurrentThread()) lockB.unlock();
    }
}).start();
```

#### 策略 4：合理配置线程池与资源池（打破"资源有限性"）

```java
// 根据 CPU 核心数配置线程池
int corePoolSize = Runtime.getRuntime().availableProcessors() + 1;
ThreadPoolExecutor executor = new ThreadPoolExecutor(
    corePoolSize, corePoolSize * 2, 60L, TimeUnit.SECONDS,
    new ArrayBlockingQueue<>(100)
);
```

### 2.4 死锁解决方法（已发生）

| 方法 | 说明 |
|------|------|
| 手动终止线程 | `kill -9 <线程ID>` |
| 重启服务 | 最直接，适合紧急场景 |
| 自动释放资源 | 定时任务检测，中断长期等待的线程 |

## 三、理论与实战总结

| 要点 | 说明 |
|------|------|
| **底层逻辑相通** | Java 死锁 = OS 死锁在应用层的体现 |
| **预防优于解决** | 固定锁顺序、一次性获取资源、使用可中断锁 |
| **实战落地为王** | 写多线程代码时固定锁顺序，使用 Lock 替代 synchronized |
