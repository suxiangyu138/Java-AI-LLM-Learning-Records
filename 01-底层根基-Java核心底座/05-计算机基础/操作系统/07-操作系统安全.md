## 1. 安全目标与威胁模型

### 1.1 CIA 三元组

| 目标 | 说明 | 安全措施 |
|------|------|----------|
| **机密性（Confidentiality）** | 数据不被未授权访问 | 权限控制、加密 |
| **完整性（Integrity）** | 数据不被篡改 | 访问控制、校验和 |
| **可用性（Availability）** | 系统持续可用 | 冗余、DDoS 防护 |

### 1.2 常见威胁

| 威胁类型 | 说明 | 攻击方式 |
|----------|------|----------|
| **内核漏洞** | OS 内核代码缺陷 | 缓冲区溢出、权限提升 |
| **配置不当** | OS 和组件配置不严 | 默认口令、开放过多端口 |
| **恶意软件** | 病毒、木马、勒索软件 | 文件注入、提权 |
| **侧信道攻击** | 利用 CPU 缓存等侧信道 | Spectre、Meltdown |

## 2. 权限管控

### 2.1 最小权限原则

**核心**：任何用户、进程，仅拥有完成其任务所需的最小权限。

### 2.2 Linux 用户与权限分级

| 用户类型 | 权限范围 | Java 后端建议 |
|----------|----------|---------------|
| **root**（超级用户） | 全部权限 | **绝对禁止**运行 Java 进程 |
| **系统用户**（如 nginx、mysql） | 受限，仅运行特定服务 | 建议使用 |
| **普通用户** | 仅访问自身目录和授权资源 | **推荐**运行 Java 进程 |

### 2.3 生产环境实践

```bash
# 创建专用用户运行 Java 进程（禁止登录）
useradd -r -s /sbin/nologin javaapp

# 设置目录权限
chown -R javaapp:javaapp /opt/javaapp
chmod -R 750 /opt/javaapp

# 配置文件只读
chmod 400 /opt/javaapp/config/application.yml

# 以普通用户运行
su - javaapp -c "nohup java -jar /opt/javaapp/app.jar &"

# 特权端口授权（免 root 绑定 80/443 端口）
setcap cap_net_bind_service=+eip /usr/local/jdk/bin/java
```

> ⚠️ **安全红线**：永远不要以 root 用户运行 Java 进程。Java 进程的权限完全继承自运行它的 OS 用户。

## 3. 访问控制

### 3.1 DAC（自主访问控制）

Linux 文件权限模型，文件所有者自主决定权限设置：

```bash
# 格式：类型 rwx rwx rwx
#       │    │   │   └── 其他用户（Other）
#       │    │   └────── 所属组（Group）
#       │    └────────── 所有者（Owner）
#       └─────────────── 文件类型（- 普通文件，d 目录）

# 权限示例：rwxr-xr-x（755）
chmod 755 application.yml

# 敏感文件：rwx------（700）
chmod 700 /etc/ssl/private/key.pem
```

| 权限 | 二进制 | 数字 | 含义 |
|------|--------|------|------|
| `---` | 000 | 0 | 无权限 |
| `r--` | 100 | 4 | 只读 |
| `rw-` | 110 | 6 | 读写 |
| `rwx` | 111 | 7 | 读写执行 |

### 3.2 MAC（强制访问控制）

适用于金融、政务等高安全场景，用户无法自主修改安全策略：

| 机制 | 说明 | Java 适配 |
|------|------|-----------|
| **SELinux** | Linux 内核 MAC 模块 | 需配置 SELinux 策略允许 Java 进程访问资源 |
| **AppArmor** | Ubuntu 采用的 MAC | 限制程序能力 |

### 3.3 Java 文件权限操作

```java
import java.nio.file.*;
import java.nio.file.attribute.PosixFilePermission;
import java.util.Set;

public class FilePermissionDemo {
    public static void main(String[] args) throws Exception {
        Path path = Paths.get("/opt/config/secret.key");

        // 设置权限：所有者读写，其他无权限（rw-------）
        Set<PosixFilePermission> perms = PosixFilePermissions.fromString("rw-------");
        Files.setPosixFilePermissions(path, perms);

        // 检查权限
        System.out.println("可读: " + Files.isReadable(path));
        System.out.println("可写: " + Files.isWritable(path));
    }
}
```

## 4. 用户与进程隔离

### 4.1 隔离机制

| 机制 | 说明 | 安全价值 |
|------|------|----------|
| **用户隔离** | 不同用户权限不同 | 限制文件访问范围 |
| **进程隔离** | 进程拥有独立虚拟地址空间 | 防止进程间内存篡改 |
| **容器隔离** | namespace + cgroups | 限制系统资源访问 |
| **虚拟化隔离** | 完整虚拟机 | 完全隔离 |

### 4.2 Java 安全管理器（SecurityManager）

> ⚠️ **注意**：Java 17 起 `SecurityManager` 已被标记为弃用，计划在后续版本移除。

## 5. 内存安全

### 5.1 内存保护机制

| 机制 | 说明 |
|------|------|
| **虚拟地址空间隔离** | 进程间无法直接访问对方内存 |
| **内存权限控制** | 代码段只读、数据段可读写、堆栈可读写执行（NX 位防止代码注入）|
| **ASLR**（地址空间布局随机化）| 随机化内存基址，防止缓冲区溢出利用 |
| **栈保护** | Canary 值检测栈溢出 |

### 5.2 NX 位（不可执行）

标记内存页为"不可执行"，防止攻击者将数据页中的代码作为指令执行。

```bash
# 检查 NX 是否启用
dmesg | grep "NX (Execute Disable) protection"
```

## 6. 网络安全

### 6.1 防火墙配置

```bash
# 启动防火墙
systemctl start firewalld
systemctl enable firewalld

# 开放必要端口
firewall-cmd --permanent --add-port=8080/tcp
firewall-cmd --permanent --add-port=443/tcp

# SSH 端口限制指定 IP
firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="192.168.1.0/24" port protocol="tcp" port="22" accept'

# 拒绝其余
firewall-cmd --permanent --add-rich-rule='rule family="ipv4" port protocol="tcp" port="22" drop'

firewall-cmd --reload
```

### 6.2 Java 后端网络防护要点

| 措施 | 说明 |
|------|------|
| 仅开放必要端口 | 关闭 FTP、Telnet 等不安全服务 |
| 使用 TLS/SSL | 数据传输加密 |
| IP 白名单 | 限制可访问 IP |
| 连接限速 | 防 DDoS |

## 7. 安全审计与日志

### 7.1 OS 日志与 Java 日志协同

```bash
# OS 安全日志
/var/log/secure     # 认证和授权日志
/var/log/messages   # 系统消息
/var/log/audit/audit.log  # 审计日志（auditd）

# 查看登录失败记录
lastb
```

### 7.2 Java 安全日志

```java
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

public class SecurityLogUtil {
    private static final Logger SECURITY_LOG = LoggerFactory.getLogger("security");

    /**
     * 记录敏感操作日志
     */
    public static void recordSensitiveOperation(
            String ip, String userId, String operation) {
        // 格式：时间 | 操作IP | 用户ID | 操作内容
        SECURITY_LOG.info("{} | {} | {} | {}",
            System.currentTimeMillis(), ip, userId, operation);
    }

    public static void recordLoginFailure(String ip, String username) {
        SECURITY_LOG.warn("登录失败 | {} | {}", ip, username);
    }
}
```

### 7.3 全链路审计架构

```
应用日志（Java Logback/Log4j）→ 操作系统日志（syslog）
                                   ↓
                            集中式日志系统（ELK）
                                   ↓
                            安全告警与审计
```

## 8. 漏洞防护

### 8.1 常见漏洞类型

| 漏洞类型 | 影响 | 防护措施 |
|----------|------|----------|
| **内核漏洞** | 系统完全被控制 | 及时内核更新 |
| **缓冲区溢出** | 代码执行、权限提升 | ASLR、NX、栈保护 |
| **JDK 漏洞** | Java 应用被攻击 | 更新 JDK（如 CVE-2017-5645）|
| **SSH 弱密码** | 远程登录被破解 | 使用密钥登录，禁用密码 |
| **开放端口** | 攻击入口 | 关闭不必要端口 |

### 8.2 更新与补丁管理

```bash
# CentOS/RHEL 系统更新
yum update -y

# Ubuntu
apt update && apt upgrade -y

# 内核更新后需重启
uname -r   # 查看当前内核版本
```

### 8.3 依赖安全检查

```xml
<!-- Maven OWASP 依赖检查插件 -->
<plugin>
    <groupId>org.owasp</groupId>
    <artifactId>dependency-check-maven</artifactId>
    <version>8.4.0</version>
    <executions>
        <execution>
            <goals><goal>check</goal></goals>
        </execution>
    </executions>
</plugin>
```

## 9. Java 后端安全最佳实践

### 9.1 敏感配置加密

```java
import javax.crypto.Cipher;
import javax.crypto.spec.SecretKeySpec;
import java.util.Base64;

public class AesEncryptUtil {
    // 密钥存储在 OS 环境变量中（不写死在代码或配置文件中）
    private static final String KEY = System.getenv("APP_AES_KEY");
    private static final String ALGORITHM = "AES";

    public static String encrypt(String content) throws Exception {
        SecretKeySpec keySpec = new SecretKeySpec(KEY.getBytes(), ALGORITHM);
        Cipher cipher = Cipher.getInstance(ALGORITHM);
        cipher.init(Cipher.ENCRYPT_MODE, keySpec);
        byte[] encrypted = cipher.doFinal(content.getBytes());
        return Base64.getEncoder().encodeToString(encrypted);
    }

    public static String decrypt(String encrypted) throws Exception {
        SecretKeySpec keySpec = new SecretKeySpec(KEY.getBytes(), ALGORITHM);
        Cipher cipher = Cipher.getInstance(ALGORITHM);
        cipher.init(Cipher.DECRYPT_MODE, keySpec);
        byte[] decrypted = cipher.doFinal(Base64.getDecoder().decode(encrypted));
        return new String(decrypted);
    }
}
```

```bash
# 环境变量设置
echo "export APP_AES_KEY='your-secret-key'" >> /etc/profile
source /etc/profile
```

### 9.2 安全配置速查

| 类别 | 最佳实践 |
|------|----------|
| **进程权限** | 专用用户运行，限制到最小权限 |
| **文件权限** | 配置文件 400/600，目录 750 |
| **网络** | 防火墙限制端口和 IP，启用 TLS |
| **日志** | 敏感操作记录审计日志，OS+Java 联动 |
| **更新** | 定期更新 OS 内核和 JDK 版本 |
| **加密** | 敏感数据加密存储，密钥存环境变量 |

### 9.3 安全基线检查命令

```bash
# 检查运行用户
whoami

# 检查开放端口
netstat -tlnp
ss -tlnp

# 检查文件权限
ls -la /opt/javaapp/config/

# 检查 Java 进程运行用户
ps aux | grep java

# 检查安全日志
tail -f /var/log/secure

# 检查系统更新
yum --security check-update
```

## 10. 云原生安全延伸

### 10.1 容器安全

```dockerfile
# 安全 Dockerfile 示例
FROM openjdk:17-jdk-slim

# 创建非 root 用户
RUN groupadd -r appuser && useradd -r -g appuser appuser

WORKDIR /app
COPY --chown=appuser:appuser app.jar app.jar

# 切换到非 root 用户
USER appuser

EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```

### 10.2 容器 vs 传统安全

| 安全维度 | 传统部署 | 容器化部署 |
|----------|----------|------------|
| 进程隔离 | 用户隔离 | namespace 隔离 |
| 资源限制 | 手动配置 | cgroups 限制 |
| 镜像安全 | — | 镜像扫描 + 最小化 |
| 密钥管理 | 环境变量 | 密钥管理服务（KMS）|

> 💡 **云原生时代的启示**：容器的安全防护本质是操作系统安全的延伸（namespace 和 cgroups 机制）。理解 OS 安全，是从"传统部署"走向"云原生部署"的关键。
