## 1. 信源编码定理

### 1.1 定理内容

**香农第一定理（无失真信源编码定理）**：对熵为 H 的信源，无损压缩的平均码长 L 满足：

L ≥ H，且存在编码使 L 任意接近 H

```text
含义：
  ① 熵 = 无损压缩的绝对下限（不可突破！）
  ② 下限可达（存在逼近编码）
  ③ 压不动的文件 = 熵已经最大（再次压缩无效）

示例：公平硬币（H = 1 bit）→ 任何无损方案平均 ≥ 1 bit/符号
```

### 1.2 压缩率的度量

| 指标 | 定义 |
|------|------|
| 压缩比 | 原始大小 / 压缩大小 |
| 平均码长 | Σ pᵢ·lᵢ（加权平均编码长度） |
| 冗余度 | 平均码长 − 熵（编码效率的缺口） |
| 相对熵利用 | H / 平均码长（接近 1 越好） |

## 2. 前缀码与 Kraft 不等式

### 2.1 为什么必须前缀码

**前缀码**：没有任何码字是另一码字的开头——解码无需分隔符、可即时解码。

```text
反例：码表 {0, 01, 1}——01 以 0 开头，接收 0 时无法确定
好例：码表 {0, 10, 11}——任何序列可唯一切分（前缀性质）

前缀码 = 二叉树的叶子（每个叶子一个码字）
```

### 2.2 Kraft 不等式

存在 D 元前缀码（码长 lᵢ）⟺ Σ D^(−lᵢ) ≤ 1

```text
工程含义：
  ① 前缀码不是无限的——总码长被"树的空间"约束
  ② 最优编码 = 在 Kraft 约束下最小化平均码长
  ③ 等号成立 = 树被完全使用（最优码的必要条件）

示例：码长 {1, 2, 2}（D=2）：1/2 + 1/4 + 1/4 = 1 ✓ 可行
      码长 {1, 2, 3, 3}：1/2+1/4+1/8+1/8 = 1 ✓
      码长 {1, 1, 2}：1/2+1/2+1/4 > 1 ✗ 不可行
```

## 3. Huffman 编码

### 3.1 算法（贪心构造最优前缀码）

```text
① 每个符号作为叶子节点（权重 = 概率）
② 反复合并两个最小权重的节点（新节点权重 = 和）
③ 合并树 → 左 0 右 1 标注路径 → 叶子路径即码字

示例：符号 {A:0.4, B:0.3, C:0.2, D:0.1}
  合并 D(0.1)+C(0.2) = 0.3
  合并 B(0.3)+新(0.3) = 0.6
  合并 A(0.4)+新(0.6) = 1.0
  编码：A=0, B=10, C=110, D=111
  平均码长 = 0.4·1 + 0.3·2 + 0.2·3 + 0.1·3 = 1.9
  熵 = −Σ p log p ≈ 1.846 → 冗余仅 0.054 bit ✓
```

### 3.2 最优性与局限

| 性质 | 内容 |
|------|------|
| 最优性 | 给定符号概率，Huffman 平均码长最短（前缀码中） |
| 熵差距 | L ≤ H + 1（单个符号整数位导致的 ≤1 bit 冗余） |
| 局限 1 | 单符号整数位 → 极端分布浪费（0.999/0.001 时） |
| 局限 2 | 需先知道概率分布（两遍扫描或自适应） |

```java
// Huffman 编码（Java 实现骨架）
class Node { char ch; int freq; Node left, right; }
PriorityQueue<Node> pq = new PriorityQueue<>(
    (a, b) -> a.freq - b.freq);
// 叶子入队 → 反复合并最小两个 → 得到编码树
// 编码表：DFS 树，路径 0/1 即码字
```

### 3.3 自适应 Huffman

```text
动态更新频率表（一遍扫描）：
  编码端每处理一个符号更新权重，解码端同步重算
  应用：JPEG 的 Huffman 表（两遍）、传真标准、ZIP 的静态模式
```

## 4. 算术编码

### 4.1 思想：一个符号用一个实数区间

```text
Huffman 的短板：每个符号至少 1 位（整数码长）
算术编码：整个消息映射到 [0,1) 区间的一个子区间
  → 平均码长可逼近熵到任意精度（理论最优）

流程：
  ① 初始区间 [0, 1)
  ② 每处理一个符号，把区间按概率比例缩小到子区间
  ③ 编码结果 = 最终区间的任意一个点（用最短二进制表示）

示例：符号 A(0.5) B(0.25) C(0.25)，消息 "AB"
  A → [0, 0.5)；B → [0.25, 0.375)？
  不对——按比例缩：A 后区间 [0,0.5)，B 取 [0, 0.25)？...
  （实际：B 在 [0,0.5) 中占 [0.5·0.5, 0.5·0.75) 等，需按比例）
  正确：A → [0, 0.5)；在 [0,0.5) 内 B 占后半 → [0.25, 0.375)
  区间长度 0.125 = 3 bit（而熵 2·1.5 = 3 bit ✓ 逼近最优）
```

### 4.2 算术编码的应用

| 场景 | 说明 |
|------|------|
| JPEG/JPEG2000 | 熵编码阶段（JPEG 默认 Huffman，JPEG2000 用算术） |
| H.264/H.265 | CABAC（上下文自适应二进制算术编码） |
| 7z/LZMA | 压缩后端（配合 LZ 字典） |
| 理论地位 | 达到熵极限的通用编码（无需整数码长） |

> 💡 对照结论：Huffman 简单但最多浪费 1 bit/符号；算术编码复杂但逼近熵——现代压缩器（视频、7z）用算术，经典压缩器（ZIP）用 Huffman。

## 5. LZ 家族：字典方法

### 5.1 思想：用"引用"代替"重复"

```text
LZ77：滑动窗口——发现已出现过的子串，用 (距离, 长度) 引用
LZ78/LZW：字典——为首次出现的片段建编号，后续引用编号

示例（LZ77 视角）：
  "abracadabra" → "abracad" + 引用(7, 4)？距离 7、长度 4
  （"abra" 在前面出现过 → 用指针替代）

特性：
  ① 无需先验概率（自适应，一遍扫描）
  ② 对重复型数据（文本、日志、代码）效果极佳
  ③ 熵框架之外的第二范式——"结构冗余"而非"概率冗余"
```

### 5.2 家族对照

| 变体 | 改进 | 应用 |
|------|------|------|
| LZ77 | 基础滑动窗口 | Deflate 前身 |
| LZ78/LZW | 字典编号 | GIF、早期 Unix compress |
| LZSS | 最小匹配长度阈值 | 现代 Deflate 内核 |
| LZMA | + 算术编码 + 大窗口 | 7z、XZ |
| Zstandard（Zstd） | + 熵 + 并行 | 2020s 新标准（日志/备份） |

## 6. 工程压缩器解剖

### 6.1 gzip（Deflate）内部结构

```text
Deflate = LZ77（字典）+ Huffman（熵编码）的两级结构：
  第一级：LZ77 滑动窗口（32KB）找出重复 → (距离,长度) 引用
  第二级：Huffman 对"字面量 + 距离 + 长度"编码（动态或静态表）

数据流：原始字节 → LZ77 匹配 → 三类符号流 → Huffman → 比特流
```

### 6.2 主流压缩器对比

| 压缩器 | 算法 | 压缩比（文本） | 速度 | 场景 |
|--------|------|:---:|:---:|------|
| gzip | LZ77+Huffman | 3-4× | 快 | Web 传输、日志 |
| zstd | LZ77+熵（FSE） | 3-5× | 极快 | 现代默认（Kafka/备份） |
| 7z/XZ | LZMA（大窗口+算术） | 5-8× | 慢 | 分发包、归档 |
| Brotli | LZ77 变体+上下文 | 4-6×（HTML） | 中 | HTTP 压缩 |

### 6.3 压缩的 Java 工程

```java
// Java 内建压缩（java.util.zip）
byte[] compress(byte[] data) throws IOException {
    ByteArrayOutputStream bos = new ByteArrayOutputStream();
    try (GZIPOutputStream gz = new GZIPOutputStream(bos)) {
        gz.write(data);
    }
    return bos.toByteArray();
}
// 注意：小数据压缩可能"变大"（头+表开销）——阈值经验 100B+
```

## 7. 压缩的工程决策

| 决策点 | 建议 |
|--------|------|
| 何时压缩 | 数据重复/结构化明显；网络 IO 是瓶颈时 |
| 何时不压 | 已压缩格式（图片/视频）、密文（熵已满）、小对象 |
| 选哪个 | 吞吐优先 zstd；极致压缩比 XZ；兼容性 gzip |
| 压缩顺序 | **先压后加密**（密文熵满无法再压） |
| 数据去重 vs 压缩 | 去重先（跨对象重复），压缩后（对象内冗余） |
| 内存代价 | 解压需内存（大压缩块 = 大缓冲，流式处理） |

> 🎯 **核心要点**：无损压缩 = "熵是下限（概率冗余）+ 字典是捷径（结构冗余）"——Huffman/算术逼近熵，LZ 家族抓重复，工程压缩器两级组合。压缩率上不去时先问：数据真的还有冗余吗（熵多少）？还是算法没匹配结构？

## 8. 小结

| 问题 | 答案 |
|------|------|
| 压缩下限？ | 熵 H（香农第一定理，不可突破） |
| 前缀码条件？ | Kraft 不等式 ΣD^(−lᵢ) ≤ 1 |
| Huffman 最优性？ | 前缀码中平均码长最短，但 ≤ H+1 |
| 算术编码强在哪？ | 区间编码逼近熵到任意精度 |
| LZ 家族？ | 字典引用抓结构冗余（无先验概率） |
| gzip 内部？ | LZ77 + Huffman 两级 |
