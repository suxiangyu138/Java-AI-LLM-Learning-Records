## 2. 语言与文法基础

### 2.1 基本定义

```
字母表 Σ：有限符号集合      (如 Σ = {0, 1} 或 Σ = {a, b, ..., z})
字符串 w：Σ 中符号的有限序列  (如 "hello", "10110")
语言 L：Σ 上字符串的集合      (如 L = { 所有回文 } = {"a","aba","abba",...})

空串 ε：长度为 0 的字符串
空语言 ∅：不含任何字符串的语言（≠ {ε}，{ε} 含一个空串）
```

### 2.2 文法

```
文法 G = (V, Σ, R, S)

  V：非终结符集合（变量，如 <expr>, <stmt>）
  Σ：终结符集合（符号，如 +, -, num, if）
  R：产生式规则集合（如 <expr> → <expr> + <term>）
  S：起始符号

推导 ⇒：从起始符号出发，反复应用产生式规则，直到全部变成终结符
```

### 2.3 产生式示例：简单算术表达式

```text
<expr>   → <term> | <expr> + <term> | <expr> - <term>
<term>   → <factor> | <term> * <factor> | <term> / <factor>
<factor> → num | ( <expr> )

推导 "3 + 4 * 2"：
  <expr>
  ⇒ <expr> + <term>
  ⇒ <term> + <term>
  ⇒ <factor> + <term>
  ⇒ 3 + <term>
  ⇒ 3 + <term> * <factor>
  ⇒ 3 + <factor> * <factor>
  ⇒ 3 + 4 * 2
```

## 3. 乔姆斯基谱系（Chomsky Hierarchy）

### 3.1 四种语言层次

| 类型 | 语言类 | 产生式限制 | 自动机 | 计算能力 |
|------|--------|-----------|--------|---------|
| **3 型** | 正则语言 | `A → aB` 或 `A → a` | 有限自动机 (FA) | 模式匹配 |
| **2 型** | 上下文无关 (CFL) | `A → α`（α 任意串） | 下推自动机 (PDA) | 嵌套结构 |
| **1 型** | 上下文有关 (CSL) | `αAβ → αγβ`（\|γ\|≥1） | 线性有界自动机 | 复杂约束 |
| **0 型** | 递归可枚举 (RE) | 无限制 | 图灵机 (TM) | 全部可计算 |

### 3.2 包含关系

```
正则语言 ⊂ 上下文无关语言 ⊂ 上下文有关语言 ⊂ 递归可枚举语言

RE (可计算)
├── 上下文有关 (CSL) — 如 {aⁿbⁿcⁿ}
│   └── 上下文无关 (CFL) — 如 {aⁿbⁿ}，大多数编程语言语法
│       └── 正则 — 如 {a*}，正则表达式
```

### 3.3 泵引理（区分语言层次的关键工具）

```
正则语言的泵引理：
  若 L 是正则语言，则存在常数 p ≥ 1，使得
  对任意 w∈L 且 |w|≥p，w 可拆分为 xyz：
    ① |xy| ≤ p
    ② |y| ≥ 1
    ③ xyⁿz ∈ L, ∀n ≥ 0

用途：证明某语言不是正则的
  例：{aⁿbⁿ} 不是正则（无法用有限状态记忆 n 的计数）
```

## 4. 正则语言与有限自动机

### 4.1 DFA（确定性有限自动机）

```
DFA M = (Q, Σ, δ, q₀, F)

  Q：有限状态集合
  Σ：输入字母表
  δ：转移函数 Q×Σ → Q
  q₀：初始状态
  F：接受状态集合

性质：
  每步转移唯一确定（确定性）
  仅有有限个状态 → 无法计数无限量
```

### 4.2 NFA（非确定性有限自动机）

```
NFA 与 DFA 的区别：
  ① 同一输入可有多个转移（非确定性）
  ② 可有 ε 转移（不消耗输入的状态跳转）

等价性定理：
  每个 NFA 都存在一个等价的 DFA（子集构造法）
  → DFA 和 NFA 识别能力相同
  → 但 NFA 状态数可能指数级更少
```

### 4.3 正则表达式与自动机的对应

| 正则表达式 | 含义 | 对应的 NFA 模式 |
|-----------|------|----------------|
| `a` | 字符 a | 状态 A →(a)→ 状态 B |
| `ab` | a 后接 b | 串联 |
| `a\|b` | a 或 b | 并行分支（ε 分叉） |
| `a*` | 零或多个 a | ε 自环 + ε 旁路 |
| `a+` | 一或多个 a | a·a* |
| `a?` | 零或一个 a | a\|ε |

### 4.4 正则语言的应用

```java
// Java 正则引擎 = DFA/NFA 混合（回溯 NFA 为主）
String regex = "[a-zA-Z_][a-zA-Z0-9_]*"; // 标识符：字母开头 + 字母数字
Pattern pattern = Pattern.compile(regex);
Matcher matcher = pattern.matcher("hello_world123");
boolean isMatch = matcher.matches();  // true

// 常见用途：
// ① 输入验证（邮箱、手机号、URL）
// ② 日志解析（Log4j pattern）
// ③ 文本替换（IDE 重构工具）
// ④ 路由匹配（Spring MVC @RequestMapping）
```

## 5. 上下文无关语言与下推自动机

### 5.1 下推自动机 (PDA)

```
PDA = FA + 栈（无限记忆）

栈的作用：处理嵌套结构
  "((()))" → 每遇到 '(' 压栈，每遇到 ')' 弹栈 → 栈空则匹配

能力边界：
  能处理 {aⁿbⁿ}（匹配计数，用栈）
  不能处理 {aⁿbⁿcⁿ}（需要两个栈，超出 CFL）
```

### 5.2 解析方法

| 方法 | 方向 | 复杂度 | 特点 |
|------|------|--------|------|
| **递归下降** | 自顶向下 | O(n³) 最坏 | 手写解析器常用 |
| **LL(k)** | 自顶向下 | O(n) | 无回溯，k 为前瞻符号数 |
| **LR(0)/SLR/LALR** | 自底向上 | O(n) | Yacc/Bison 使用 LALR |
| **GLR** | 通用 | O(n³) | 处理有二义性的文法 |
| **Earley** | 通用 | O(n³) | 任何 CFG |

### 5.3 抽象语法树 (AST)

```text
代码：a = 3 + 4 * 2

解析树（CST，包含所有语法细节）：
         <stmt>
          |
       <assign>
      /    |    \
    id    =    <expr>
     |        /  |  \
     a     <expr> + <term>
             |       /  |  \
           <term> <term> * <factor>
             |       |       |
          <factor> <factor>  num(2)
             |       |
           num(3)  num(4)

AST（抽象语法树，去掉冗余）：
        =
       / \
      a   +
         / \
        3   *
           / \
          4   2
```

## 6. 图灵机与可计算性

### 6.1 图灵机定义

```
图灵机 M = (Q, Σ, Γ, δ, q₀, q_accept, q_reject)

  无限长的纸带（读写头可左右移动）
  与 FA/PDA 的本质区别：无限存储 + 随机访问

丘奇-图灵论题：
  "任何直觉上可计算的函数都可以用图灵机计算"
  → 图灵机 = 可计算性的定义
  → Python / Java / C++ 的计算能力都 = 图灵机（图灵完备）
```

### 6.2 不可判定问题

```
停机问题（Halting Problem）：
  是否存在算法，能判断任意程序在给定输入下是否会停机？

答案：不存在（图灵 1936 年证明，对角论证法）

推论：
  不存在完美的静态分析工具（能找出所有 bug）
  不存在完美的死循环检测器
  不存在完美的病毒检测器

→ 理论计算机科学的重要性：知道什么是"不可能"的
```

### 6.3 P vs NP

```
P（多项式时间可解）：
  存在 O(nᵏ) 算法的问题
  例：排序 O(n log n)、最短路径 O((V+E)log V)

NP（多项式时间可验证）：
  给定一个解，可以在多项式时间内验证其正确性
  例：数独、旅行商问题、SAT

P ⊆ NP 是确定的，但 P = NP ? 是百万美元问题
  → 普遍认为 P ≠ NP，但无法证明
  → 这就是为什么密码学（依赖困难问题）目前是安全的
```

## 7. Java 工程中的应用

### 7.1 ANTLR 4 生成解析器

```java
// 文法文件 Expr.g4：
// grammar Expr;
// expr: term (('+'|'-') term)* ;
// term: factor (('*'|'/') factor)* ;
// factor: INT | '(' expr ')' ;
// INT: [0-9]+ ;
// WS: [ \t\r\n]+ -> skip ;

// ANTLR 自动生成 Java 解析器
// import org.antlr.v4.runtime.*;
// import org.antlr.v4.runtime.tree.*;

public class ExprEval {
    public static void main(String[] args) {
        String input = "3 + 4 * (2 - 1)";
        ExprLexer lexer = new ExprLexer(CharStreams.fromString(input));
        CommonTokenStream tokens = new CommonTokenStream(lexer);
        ExprParser parser = new ExprParser(tokens);

        ParseTree tree = parser.expr();  // 自动构建 CST
        System.out.println(tree.toStringTree(parser));  // 打印解析树
    }
}
```

### 7.2 手写状态机

```java
// 场景：订单状态流转（经典 DFA 应用）
public enum OrderState {
    PENDING, CONFIRMED, SHIPPED, DELIVERED, CANCELLED, REFUNDED;

    static {
        // 转移表：当前状态 → (事件 → 下一状态)
        PENDING.transitions   = Map.of("pay", CONFIRMED, "cancel", CANCELLED);
        CONFIRMED.transitions = Map.of("ship", SHIPPED, "cancel", REFUNDED);
        SHIPPED.transitions   = Map.of("deliver", DELIVERED);
        DELIVERED.transitions = Map.of("refund", REFUNDED);
        CANCELLED.transitions = Map.of();   // 终态
        REFUNDED.transitions  = Map.of();   // 终态
    }

    private Map<String, OrderState> transitions = Map.of();

    public OrderState transition(String event) {
        OrderState next = transitions.get(event);
        if (next == null) throw new IllegalStateException(
            String.format("Cannot %s from %s", event, this));
        return next;
    }
}

// 使用：
// OrderState current = OrderState.PENDING;
// current = current.transition("pay");    // → CONFIRMED
// current = current.transition("ship");   // → SHIPPED
// current = current.transition("cancel"); // → IllegalStateException!
```
