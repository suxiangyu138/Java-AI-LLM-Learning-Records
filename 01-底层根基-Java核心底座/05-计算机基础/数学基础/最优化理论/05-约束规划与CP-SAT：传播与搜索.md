# 约束规划与 CP-SAT：传播与搜索
> 同一类组合问题，MIP 用"线性不等式"表达，约束规划（CP）用"任意关系"表达——当约束是非线性的、异质的、逻辑化的（排班、装箱、调度），CP 的约束传播比割平面更锋利；2026 年 OR-Tools CP-SAT 在 MiniZinc Challenge 拿下四金，宣告它成为组合问题的事实标准之一。

## 1. 约束规划的核心：声明式建模与约束传播

**约束规划（Constraint Programming）**的建模哲学与 MIP 截然不同：MIP 要求所有约束写成线性不等式（模型是"代数"），CP 允许任意关系的约束（x 与 y 必须不同、x 必须在集合里、x 是 y 的排列、绝对差至少为 3）——**模型是"声明式"的：描述问题，不描述求解过程**。CP 的变量是有限域的离散变量（可以是整数、枚举、排列），求解引擎由两件武器驱动：

- **约束传播（propagation）**：每条约束内置"域缩减规则"——例如"AllDifferent(x₁..xₙ)"约束会检查当前各变量剩余域，若某值只可能属于一个变量则立即赋值（域缩减）；约束传播在搜索树的每个节点把"不可能的值"从变量域中删除——**传播是 CP 的割平面：同样不改变可行解，只缩小搜索空间**
- **回溯搜索（backtracking）**：选一个变量、试一个值、传播、冲突则回溯——与分支定界同构，但分支单位是"值"而非"半空间"

关键对比（对 04 篇）：**MIP 用"松弛+切割"收紧连续空间，CP 用"传播+域缩减"收紧离散空间**——MIP 擅长数值结构（成本、容量），CP 擅长逻辑结构（互斥、排序、排列）；前者的问题写成不等式，后者写成关系。

## 2. CP-SAT：2026 年的组合问题之王

**OR-Tools CP-SAT**（Google 开源，2026 年 MiniZinc Challenge 固定/自由/并行/开放四组全部金牌）是 CP 技术的集大成者，内部早已不是"朴素 CP"：

- **Lazy 子句生成（Lazy Clause Generation）**：把传播过程"翻译"成 SAT 风格的蕴含子句并缓存——**把 CP 的传播与 SAT 的学习（冲突驱动回跳、子句学习）结合**，搜索树大幅缩小（理论上是 CP 近二十年的最大突破）
- **线性松弛内嵌**：CP-SAT 内部同时维护一个 LP 松弛（检测到线性结构时启用）——**CP 与 MIP 的技术在它体内融合**
- **丰富的约束库**：AllDifferent、Circuit（TSP 类）、Cumulative（资源调度）、NoOverlap（装箱）、Interval 变量（时间窗）——**写排班/调度/装箱模型的效率远高于手写 MIP**
- **重要边界**：CP-SAT **不支持连续变量**（浮点数要放大成整数近似）——连续与整数混合且线性结构主导的问题仍是 MIP 的领地

**选型口诀（2026）**：约束逻辑复杂（排班、装箱、排序、图着色）→ CP-SAT；线性成本结构主导且变量大（生产计划、物流网络）→ MIP（Gurobi/HiGHS）；两者皆可时，**先用 CP-SAT 快速建原型**（建模门槛低），再用 MIP 精调性能。

## 3. CP 与 MIP 的实战对比：排班问题

以**护士排班**（N 名护士、7 天、每天各班次人数需求、连续工作天数限制、休息日约束）为例对比两条路线：

**MIP 建模**：xₙₙ 二元变量（护士 n 第 d 天是否值班），约束全写成线性不等式——"每天需求"好写，"连续工作不超过 5 天"要引入额外的滑动窗口变量族，"两个护士不能同班"是配对不等式——**模型膨胀、调试痛苦、割平面识别不出逻辑结构**。

**CP-SAT 建模**：xₙ 是"护士 n 的班表数组"（取值 0-3 表示班型），约束直接写——shift 需求用 count 约束、连续天数用滑动窗口约束、互斥用 AllDifferent/Forbidden 约束——**模型与业务语言一一对应**；求解时传播引擎把"班表一致性"当第一公民处理。实测：**同类排班问题，CP-SAT 建模时间约为 MIP 的 1/5，求解时间在中等规模相当或更优**。

**关键教训**：**"模型的表达贴近问题"本身就是性能**——约束的"语义保真度"决定传播效率；把逻辑约束硬编码成线性不等式，等于把传播信息全部扔掉，MIP 求解器只能靠数值割平面重新发现（且往往发现不了）。

## 4. 工程实践：CP-SAT 的使用纪律

- **建模**：优先用内置约束库（Circuit/Cumulative/AllDifferent）而非手写分解——库约束带专用传播器，性能差 10-100 倍
- **目标函数**：CP-SAT 支持线性目标与部分非线性（含绝对值、最大值）——非线性目标用辅助变量表达
- **整数化纪律**：连续量放大 100-1000 倍取整（精度与规模的权衡）；**不适合高精度连续优化**（那去 MIP 或凸优化）
- **参数**：max_time（时间预算）、num_search_workers（并行）、log_search_progress（看传播与搜索统计）——三个参数解决 90% 场景
- **验证**：结果必须做"解校验器"检查（CP-SAT 提供 solution checker）——约束复杂时"看似对的解"漏约束是常见事故
- **与 MIP 混合**：同一问题拆两半——逻辑部分 CP、数值部分 MIP，通过 CP-SAT 的接口或两阶段求解对接（10 篇决策树）

### 4.1 CP-SAT 与 MIP 的混合实战：生产排程

用生产排程展示"CP + MIP 混合"的完整姿势：**问题**——一条产线多台机器加工多道工序，工序有时序依赖（先粗后精）、机器有产能与切换时间、目标是最小化拖期成本。**为什么 CP-SAT 是默认**：Interval 变量（每道工序的开始-结束区间）加 NoOverlap 约束（同机工序不重叠）加时序约束（工序链）——**模型与业务一一对应**（第 3 节排班案例同款逻辑），传播引擎把"机器时间轴"当第一公民；**什么时候切 MIP**：拖期成本与产能有线性成本结构、且问题以"数量"为主（多少件、多少批次）时，MIP 的线性下界更紧，Gurobi 可能更快；**混合姿势**：先用 CP-SAT 快速建原型拿可行解（通常已经很好），再对"优化量"（拖期成本）用 MIP 精化——**CP-SAT 的热启动支持把 CP 解喂给 MIP**（反之亦可），两阶段接力是 2026 年工业界最常见的组合；**数据纪律**：工序数量、机器数量、时间粒度（分钟还是小时）直接决定规模——排程模型的第一件事是"时间离散化粒度"（CP-SAT 用整数时间，粒度过细直接爆炸）。**选型自检五问**：约束是否逻辑主导（互斥/时序/资源）？目标是线性成本还是可行性优先？时间是否可离散化？规模（工序乘机器）在万级内？需要精确最优还是预算内好解？——五问的答案组合基本决定 CP-SAT 还是 MIP：四问倾向 CP 就 CP-SAT，成本结构主导就 MIP。**这五问是排程建模的入口**，也是面试"排班问题怎么建模"的答题骨架。

CP-SAT 的局限也要认清（防止"有了锤子看什么都像钉子"）：**第一，无连续变量**——浮点必须整数化（放大取整），高精度连续问题（金融风控、物理参数辨识）不是它的战场；**第二，大 M 式的"线性成本主导"问题不如 MIP**——纯运输/生产计划类（百万连续变量加少量整数）Gurobi 会快一个量级；**第三，约束库是双刃剑**——内置约束高效，但"复杂自定义约束"（比如行业特有的非线性规则）要么手写传播器（门槛高）要么分解成多个内置约束（性能退化）；**第四，内存与并行**——大规模（百万级布尔变量）时 CP-SAT 的内存与并行扩展性弱于 MIP 求解器。**选型口诀补全：逻辑密集选 CP-SAT、数值密集选 MIP、混合问题先 CP 原型再 MIP 精化**——2026 年没有一个求解器通吃，组合才是答案。

> 🎯 **核心要点**：约束规划用"声明式建模 + 约束传播"处理 MIP 难表达的逻辑结构——传播是 CP 的割平面（只缩搜索空间不改可行解）；CP-SAT（2026 年 MiniZinc 四金）通过 Lazy 子句生成把 CP 传播与 SAT 学习结合，内部还融合了 LP 松弛——CP 与 MIP 的技术已经合流；选型口诀：逻辑复杂选 CP-SAT、线性主导选 MIP、"模型贴近问题本身就是性能"；排班/装箱/调度类问题，CP-SAT 是 2026 年的默认答案。
