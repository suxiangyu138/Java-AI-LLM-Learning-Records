# 图与网络优化：流与匹配
> 图是优化最富饶的结构：最短路、最小生成树、最大流、最小割、匹配——每个问题都有优雅的多项式算法，且几乎全部能写成全幺模的线性规划（LP 解即整数解）；网络流是整个运筹学里"理论最优且工程可用"结合得最好的分支。

## 1. 四大家族：路径、树、流、匹配

图优化按目标分四大家族，各有一个或几个多项式算法：

- **最短路**：单源（Dijkstra，非负权）、负权（Bellman-Ford）、全源（Floyd-Warshall）——地图导航、网络路由、机器人路径规划的基础；Dijkstra 用优先队列优化后是 O(E log V)，工程上可处理千万级节点
- **最小生成树**：Kruskal（按边排序并查集）与 Prim（贪心扩展）——网络铺设（电网/通信/管道）的最小成本连接；"树上任意两点唯一路径"的结构让它成为 TSP 近似（Christofides）与聚类（单链）的原料
- **最大流/最小割**：Ford-Fulkerson 与 Dinic——**最大流 = 最小割（max-flow min-cut 定理）**是图论的皇冠：网络带宽、供应链吞吐、二分图匹配、图像分割（图割）全部是它的化身；最小割还回答"最少切断哪些边能让 s-t 不连通"
- **匹配**：二分图最大匹配（匈牙利算法/增广路）与加权匹配——任务分配、配对、多对多调度；**指派问题（03 篇"看似组合实则易"）就是加权二分匹配**

**共同的理论底座**：四个家族的 LP 松弛约束矩阵全部**全幺模**——顶点处自动整数，**LP 解即整数解**（凸优化 04 篇"全幺模=整数免费"在这里集中兑现）；且都有**组合专用算法**比通用 LP 快几个数量级——这就是"结构识别"的价值：认出图结构，算法与理论全部白送。

## 2. 网络流理论：最大流最小割定理

**最大流问题**：源 s 到汇 t 的容量网络中，求能推过的最大流量。**Ford-Fulkerson 思想**：反复找 s-t 增广路（残余网络中还有容量的路径）并推流，直到找不到增广路——此时流量即最大（**增广路定理**）。Dinic 用 BFS 分层 + DFS 多路增广，O(V²E) 的复杂度在实践中常接近线性。

**max-flow min-cut 定理**：最大流的值 = 最小割的容量——**"能推多少"与"最少切多少"是同一枚硬币的两面**。工程推论（2026 年仍被大量使用）：**最小割就是"资源受限时最便宜的单点故障集"**——网络可靠性分析（切断哪几条链路会断网且代价最小）、图分割（把图切成两块的最小代价）、项目依赖的割集分析。**对偶的视角（凸优化 05 篇）在这里有几何化身**：流是"原变量"，割是"对偶变量"，最大流-最小割定理就是强对偶定理在图上的投影。

## 3. 从流到匹配：二分图与指派问题

**二分图匹配**的桥接关系：二分图最大匹配 = 网络流特例（源连左部、左连右、右连汇，容量全 1）——**"匹配是流的一个特例"**，这是图论最优雅的归约之一；匈牙利算法（O(n³)）用增广路思想直接解加权指派（"n 任务分 n 人成本最小"），是运筹学教科书的常驻主角。

匹配的现代应用远超"分人干活"：**器官捐献配对**（多轮交换）、**大学录取匹配**（Gale-Shapley 稳定婚姻的变体——2026 年仍被诺贝尔经济学奖得主 Shapley 的理论惠及）、**推荐系统的二分图 embedding**（用户-物品二分图上的匹配与随机游走）、**自动驾驶的任务-车辆分配**。**匹配理论从"图的数学"长成了"市场的数学"**——"匹配市场设计"（找对象、找学校、找器官）是 2012 年诺贝尔经济学奖的主题，底层全是图算法。

## 4. 网络优化在工程中的现实位置

2026 年网络优化的工程现实：**理论成熟、工具完备、应用广泛但常被忽视**——三个原因：**算法简单**（几十行代码，Python 的 networkx 一行调用）；**被 LP 求解器吸收**（网络单纯形在 Gurobi 内部自动识别——"把问题建模成网络流，求解器免费提速"）；**被机器学习掩盖**（推荐系统的图方法、社交网络分析看起来是"AI"，骨子里是流与匹配）。工程上值得记住的三件事：

- **认出网络结构**：物流、电力、通信、排班里隐藏的网络流结构一旦认出，建模与求解成本骤降（10 篇决策树的第一分支）
- **网络流当"子程序"用**：大规模组合问题的分解（列生成、拉格朗日松弛）里，网络流是最常用的子问题求解器——"复杂问题拆出网络结构"是运筹工程师的核心技能
- **与图神经网络的关系**：2026 年 GNN 在组合优化上的工作（10 篇）大量用"求解器解网络流"当监督信号与验证器——**经典算法是学习方法的"老师"与"裁判"**

### 4.1 网络流的建模技巧与实战

网络流的建模技巧，用三个实战场景展开：**场景一，产能分配**——多个供应商（源）多个客户（汇）中转仓（中间节点）：建"源-仓-汇"三层图，边容量等于运输上限、边成本等于单位运费——**最小费用流**直接给出最优调运；技巧：把"产能上限"写成源边容量、"需求下限"写成汇边容量，多产品用"分层图"（每层一个产品）。**场景二，员工排班匹配**——员工作息与班次需求的二分图匹配：左边员工、右边班次，边表示可胜任，最大匹配等于最大覆盖；加"员工成本"变加权匹配（匈牙利算法）；技巧：**多对多的"配对问题"先问是不是二分图**——是则匹配，不是则一般图匹配（开花算法，工程少用）。**场景三，图像分割（图割）**——图像像素二分（前景/背景）：像素为节点、相似像素连边（容量等于相似度）、前景背景各连一个超级源汇——**最小割等于最佳分割**（语义分割的经典骨架，2026 年仍被深度学习方法沿用为精化器）；技巧：**"把问题翻译成割"的三个要素**——节点（实体）、边容量（代价）、源汇（两个类别）。**三条通用技巧**：容量与成本分开放（容量在边、成本在费用）；图构建先在纸上画（节点语义写清楚再编码）；**网络流当子程序**——列生成与分解方法里网络流是最常用子求解器（第 4 节）。**复杂度直觉**：Dinic 的复杂度在实践中接近线性；万节点百万边的问题 Python 库秒级、C++ 毫秒级——网络流是"理论最优且工程极快"的结合，这也是它被广泛内嵌的原因。

算法的选型记忆卡（图家族）：**无权最短路用 BFS、非负权用 Dijkstra、负权用 Bellman-Ford、全源用 Floyd**；**稀疏图生成树用 Kruskal（并查集）、稠密图用 Prim**；**最大流首选 Dinic、边权统一时 BFS 增广更快**；**二分匹配用匈牙利（加权）或 Hopcroft-Karp（无权）**——每张卡对应一个"几十行代码"的实现，2026 年直接调库即可（C++ 的 boost graph、Python 的 networkx），但**"什么场景调哪个函数"的判断必须自己会**——库不替你做结构识别。

> 🎯 **核心要点**：图优化四大家族（最短路/生成树/流/匹配）全部多项式可解、全部全幺模（LP 解即整数解）、全部有专用算法——认出图结构等于白拿算法与理论；最大流-最小割定理是强对偶的图化身，最小割 = 最便宜的单点故障集；匹配从"分人干活"长成"市场设计"（诺奖级应用）；工程现实：网络流常被求解器内建吸收、被 ML 掩盖，但"认出网络结构 + 当子程序用"仍是运筹工程师的核心技能——经典算法是 2026 年学习方法（GNN）的老师与裁判。
