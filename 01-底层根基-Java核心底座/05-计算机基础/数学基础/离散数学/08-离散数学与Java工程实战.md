## 1. 集合框架的数学本质

### 1.1 集合 → 实现家族

| 数学概念 | Java 接口 | 实现 | 特性 |
|---------|----------|------|------|
| 集合（无序不重复） | Set | HashSet / LinkedHashSet | 哈希（等价类桶） |
| 有序集合（全序） | SortedSet / NavigableSet | TreeSet | 红黑树（偏序） |
| 多重集合 | — | HashMap<K, Long> | 元素 + 计数 |
| 序列（有序可重复） | List | ArrayList / LinkedList | 非集合语义 |
| 笛卡尔积子集（关系） | 表/ORM | 数据库行集 | 外键=关系复合 |

### 1.2 HashSet 的数学契约

```java
// 等价关系三性质 → equals 三要求（Java 文档原文的数学本质）
// ① 自反：x.equals(x) == true
// ② 对称：x.equals(y) == y.equals(x)
// ③ 传递：x.equals(y) && y.equals(z) ⟹ x.equals(z)
// ④ 一致性：无修改时多次调用结果一致
// ⑤ 等价对象 hashCode 必须相等（等价类 → 同一桶）

// 违背的后果（全是等价类破坏）：
// 传递性不满足 → 对象"时而相等时而不等" → HashSet 去重失效
// hashCode 依赖可变字段 → 对象进桶后桶位置变了 → 再也查不到
```

> 🎯 面试高频："重写 equals 必须重写 hashCode 为什么？"——答案就是等价关系与等价类：**equals 定义等价类，hashCode 决定桶归属；等价类必须映射到同一桶，否则划分不成立**（02 模块第 4 节的工程版）。

### 1.3 集合运算的 API 映射

```java
Set<Integer> a = ..., b = ...;
a.addAll(b);              // a ∪ b
a.retainAll(b);           // a ∩ b
a.removeAll(b);           // a − b
// 对称差：a⊕b = (a−b) ∪ (b−a)

// 容斥的工程应用：统计"同时满足多个条件"的数量
long size = a.size() + b.size() - (intersection(a, b)).size();
```

## 2. Map：函数与等价类的实现

### 2.1 HashMap 的数学结构

```
HashMap = 函数（键 → 值）的实现：
  单射性保障：键唯一（每个输入一个输出）
  O(1) 查找的数学：哈希 = 把键空间压缩到桶（鸽巢 → 冲突必然）
  冲突处理：链地址法（链表/红黑树）—— 等价类内的线性查找

HashMap 结构 = 数组 + 链表/红黑树
  → 数组索引 = 哈希值 mod 容量（模运算！06 模块）
  → 树化阈值 8：等价类过大时从线性变对数（工程对鸽巢的妥协）
```

### 2.2 TreeMap：偏序的工程化

```java
// TreeMap = 键的偏序关系（Comparable/Comparator）
// 数学要求：compareTo 必须是全序（可比较性）+ 一致于 equals
TreeMap<Integer, String> map = new TreeMap<>();
map.floorKey(10);     // ≤10 的最大键（偏序的极元查询）
map.ceilingKey(10);   // ≥10 的最小键
map.subMap(5, 15);    // 区间（偏序的序区间）

// 工程价值：区间查询、最近邻查找 = 有序集合的偏序操作
// 应用：日程表、限价订单簿（价格偏序）、IP 段匹配
```

### 2.3 函数式映射

```
Function<K,V> = 数学函数（每输入一输出）
  纯函数 = 无副作用（确定性）→ 可缓存、可并行、可测试
  Map 的 merge/computeIfAbsent = 函数的组合操作

Stream 的 map/filter = 数学的映射/过滤
  —— 函数式编程就是把"函数"当公民
```

## 3. Stream 与代数契约

### 3.1 并行归约的正确性 = 结合律

```java
// Stream.reduce 的代数契约（05 模块的工程版）：
// ① accumulator 必须满足结合律
// ② identity 必须是单位元

int sum = list.parallelStream()
    .reduce(0, Integer::sum);      // ✅ 结合 + 单位元 0
// double avg = list.parallelStream()
//     .reduce(0, (a, b) -> (a + b) / 2);   // ❌ 非结合 → 结果随机！

// 正确求平均：map 后归约
double avg = list.parallelStream()
    .mapToDouble(x -> x)
    .average().orElse(0);
```

| 归约操作 | 结合律 | 单位元 | 可并行 |
|---------|:---:|:---:|:---:|
| 求和 | ✅ | 0 | ✅ |
| 求积 | ✅ | 1 | ✅ |
| max/min | ✅ | ±∞ | ✅ |
| 平均数 | ❌ | 无 | ❌（需拆分） |
| 拼接（按序） | ❌ | — | ❌（顺序依赖） |

> 🎯 经典面试陷阱："`parallelStream` 为什么比 `stream` 慢/结果错？"——回答框架：**结合律不满足 → 分段结果无法合并**。离散数学的代数结构直接决定并行化可行性。

### 3.2 惰性求值 = 集合的映射视角

```
Stream 的惰性 = 函数式"延迟计算"：
  filter/map 不立即执行，终止操作才触发
  数学对应：映射的复合 f∘g 可以先组合后应用

工程红利：无限流（生成函数）、短路（findFirst）、
         只算需要的部分 —— 集合论"子集选取"的流式版
```

## 4. 位运算与状态压缩

### 4.1 位集合（BitSet）

```java
// BitSet = 用位表示的集合（布尔代数的工程实现，02/05 模块）
BitSet a = new BitSet();
a.set(3); a.set(7);
BitSet b = new BitSet();
b.set(7); b.set(9);

a.and(b);             // 交集（位与）
a.or(b);              // 并集
a.xor(b);             // 对称差
a.get(7);             // 成员判断 O(1)
// 空间：1 亿个整数集合 ≈ 12.5MB（vs HashSet 数百 MB）

// 工程：权限位图、在线用户统计（天/小时位）、
//      布隆过滤器的底层、并发位集合（CopyOnWriteArraySet 的替代）
```

### 4.2 状态压缩 DP

```java
// 状态压缩 = 用 int/long 表示子集（幂集的二进制编码）
// 经典：TSP 的 Held-Karp DP（O(2ⁿ·n²)）
// dp[mask][v] = 已访问 mask 且当前在 v 的最短路径
int n = 16;                    // 最多 16 个点（int 位集）
int[][] dp = new int[1 << n][n];

for (int mask = 0; mask < (1 << n); mask++)
    for (int v = 0; v < n; v++)
        for (int u = 0; u < n; u++)
            if ((mask & (1 << u)) == 0)
                dp[mask | (1 << u)][u] = Math.min(
                    dp[mask | (1 << u)][u],
                    dp[mask][v] + dist[v][u]);

// 数学本质：2ⁿ 个子集 = 2ⁿ 状态 = 布尔代数 + 组合计数（04/05 模块）
```

### 4.3 位运算技巧速查

| 技巧 | 代码 | 数学本质 |
|------|------|---------|
| 最低位 1 | `x & (-x)` | 补码 = 取反+1（布尔+数论） |
| 清除最低位 | `x & (x-1)` | 借位传播 |
| 判断 2 幂 | `x > 0 && (x & (x-1)) == 0` | 二进制只有一个 1 |
| 交换 | `a ^= b; b ^= a; a ^= b;` | 异或自反（群） |
| 奇偶 | `(x & 1) == 1` | mod 2 |
| 哈希取模 | `hash & (n-1)` | 2 幂取模优化 |

## 5. 图与图算法在 Java 中的形态

### 5.1 Java 生态的图工具

| 工具 | 用途 | 说明 |
|------|------|------|
| JGraphT | 通用图库 | 最短路/流/匹配开箱即用 |
| Guava Graph | 轻量图接口 | ValueGraph/MutableGraph |
| Neo4j（嵌入式） | 图数据库 | 知识图谱生产级 |
| 手写邻接表 | 算法题标准 | 见 03 模块模板 |

```java
// Guava Graph 示例（图 = 关系的建模）
MutableGraph<String> g = GraphBuilder.directed().build();
g.addNode("A"); g.addNode("B");
g.putEdge("A", "B");            // A → B（关系 (A,B)）
g.successors("A");              // 出邻居
Graphs.hasCycle(g);             // 环检测（依赖死锁检查）

// 工程场景：任务依赖 DAG、微服务调用链、权限继承图
// 拓扑排序 = 构建顺序（Maven 依赖）
```

### 5.2 工程高频图算法清单

| 算法 | 场景 | 复杂度 |
|------|------|--------|
| BFS | 无权最短路、层级关系 | O(V+E) |
| Dijkstra（堆优化） | 加权最短路（导航/路由） | O((V+E)logV) |
| 拓扑排序 | 依赖解析、调度 | O(V+E) |
| 并查集 | 动态连通性、等价类合并 | O(α(n)) 近似常数 |

| 强连通分量 | 循环依赖分析 | O(V+E) |

## 6. 并发编程中的数学建模

### 6.1 锁与关系

```
并发正确性的数学视角：
  锁的互斥性 = 同一资源上的"排他关系"
  死锁 = 资源依赖图（有向图）存在环！
    线程 T1 持锁 A 等 B，T2 持 B 等 A
    → 图：T1→B→T2→A→T1 有环 ⟹ 死锁

死锁四条件（互斥/占有且等待/不可剥夺/循环等待）
  = 资源分配图成环的图论条件（03 模块环检测的工程形态）
```

### 6.2 无锁与原子

```
原子操作 = 操作的不分割性（数学：操作的"整体性"）
CAS（比较并交换）的数学：
  compareAndSet(expected, new) = 偏序下的条件更新
  循环 CAS = 单调逼近（偏序的收敛）

LongAdder 的设计 = 等价类拆分：
  多个计数单元（分桶）→ 最终合并（结合律！）
  —— 伪共享避免 + 归约的数学设计（05 模块结合律）

并发安全的深层逻辑：
  "可交换的"（顺序无关）→ 可乱序/可并行
  "可结合的"（分组无关）→ 可归约/可拆分
  —— 代数结构决定并发可行性
```

### 6.3 分布式系统与代数

| 分布式概念 | 数学对应 |
|-----------|---------|
| 幂等操作 | 重复执行结果不变（幂等的代数：x∘x=x） |
| CRDT 收敛 | 结合+交换+幂等的合并操作 |
| 最终一致 | 收敛到同一值（偏序的收敛） |
| 分布式哈希（一致性哈希） | 模运算 + 环（哈希环） |

```
一致性哈希的数学：
  哈希环 = 模 2³² 的环；节点与键都映射到环上
  键归属 = 顺时针第一个节点（环上的后继查询）
  —— 06 模块模运算 + 02 模块偏序的组合应用
```

## 7. 工程速查：问题 → 数学 → API

| 工程问题 | 数学本质 | 解决方案 |
|---------|---------|---------|
| 去重/成员判断 | 集合 | HashSet、BitSet、Bloom |
| 统计多条件重叠 | 容斥原理 | 集合运算 + 计数 |
| 区间查询/最近邻 | 偏序/全序 | TreeMap、跳表 |
| 依赖顺序/死锁检测 | 拓扑排序/环检测 | DAG 算法、JGraphT |
| 权限/组合枚举 | 子集/幂集 | 位掩码、回溯 |
| 哈希冲突 | 鸽巢原理 | 链地址、扩容、一致性哈希 |
| 大数取模/加密 | 数论/有限域 | BigInteger、AES/RSA 库 |
| 并行归约 | 结合律+单位元 | parallelStream（注意契约） |
| 幂等接口 | 幂等代数 | 幂等键、去重表 |
| 缓存淘汰 | 偏序/访问模式 | LRU（双向链表+Map） |

> 🎯 **核心要点**：Java 工程是离散数学的"活化石"——集合框架是集合论、TreeMap 是偏序、位运算是布尔代数、Stream 归约是幺半群、并发是代数结构与图论。**当你遇到"为什么这样设计"的困惑时，回到数学找答案，通常有标准解释。**
