## 1. 复杂度分析：离散数学的度量衡

### 1.1 渐进分析

```
O(g(n))：上界（最坏）—— 工程最关心
Ω(g(n))：下界（最优）
Θ(g(n))：紧界

常见阶：1 < log n < √n < n < n log n < n² < 2ⁿ < n!

估计技巧（组合数学的直接应用）：
  Σᵢ₌₁ⁿ i = n(n+1)/2 → O(n²)
  Σᵢ₌₁ⁿ 2ⁱ = 2ⁿ⁺¹−1 → O(2ⁿ)
  递归 T(n) = 2T(n/2) + n → O(n log n)（主定理）
```

### 1.2 递归与主定理

```
T(n) = aT(n/b) + f(n)
  若 f(n) = O(n^(log_b a − ε)) → T(n) = Θ(n^(log_b a))
  若 f(n) = Θ(n^(log_b a)) → T(n) = Θ(n^(log_b a) · log n)
  若 f(n) = Ω(n^(log_b a + ε)) 且满足正则 → T(n) = Θ(f(n))

例：归并排序 T(n)=2T(n/2)+n → log₂2=1，f(n)=n=Θ(n¹) → O(n log n)
例：二分 T(n)=T(n/2)+1 → log₂1=0，f(n)=1=Θ(n⁰) → O(log n)
```

> 🎯 工程意义：**算法选型 = 复杂度计算的实战**——数据量 10⁶ 时 O(n²) 秒级、O(n log n) 毫秒级。面试"为什么用这个算法"的标准答案结构就是：先算复杂度再选型。

## 2. 自动机与形式语言

### 2.1 Chomsky 层级

| 层级 | 文法 | 自动机 | 工程代表 |
|:---:|------|--------|---------|
| 3 型 | 正则文法 | **有限自动机（DFA/NFA）** | 正则表达式、词法分析 |
| 2 型 | 上下文无关 | 下推自动机（PDA） | 语法分析（编译器） |
| 1 型 | 上下文相关 | 线性有界自动机 | 自然语言（近似） |
| 0 型 | 无限制 | 图灵机 | 通用计算 |

```
有限自动机（DFA）工程应用：
  正则表达式编译为 DFA → O(n) 匹配（Java Pattern 内部）
  状态机：协议解析（HTTP）、词法分析器（Lex）、
  有限状态控制（LLM 的 tokenizer 边界）

正则表达式能表达什么 = 正则语言 = DFA 能识别什么
  —— 这解释了为什么"回文不能用正则匹配"
```

### 2.2 正则语言的工程边界

```
不可正则的经典语言：
  {aⁿbⁿ}（n 个 a 后 n 个 b）—— 需要记忆深度 → PDA
  回文 —— 需要栈 → PDA
  → 用正则硬匹配 HTML/JSON = 理论上的不可能（需要上下文无关）

工程结论：嵌套结构（括号、标签）必须用解析器而非正则
  这是"不要用正则解析 HTML"的数学证明
```

### 2.3 图灵机与可计算性

```
图灵机 = 计算的抽象定义
  停机问题不可判定（对角线论证）
  哥德尔不完备（逻辑 ↔ 计算的内在边界）

工程意义：理解"有些问题在数学上无解"
  —— 程序正确性验证的局限（Rice 定理）
```

## 3. P vs NP：图论埋下的世纪难题

### 3.1 问题分类

```
P：多项式时间可解（排序、最短路、最大流）
NP：多项式时间可验证（哈密顿回路、3-SAT、背包）
NP 完全（NPC）：NP 中最难的（若一个 NPC 有多项式解 → 全部 NP 可解）
```

### 3.2 经典 NPC 问题（全部来自图论/组合）

| 问题 | 图论形式 |
|------|---------|
| 3-SAT | 布尔公式可满足性 |
| 哈密顿回路 | 经过每点一次（03 模块） |
| 图着色 3 色 | 色数判定（03 模块） |
| 背包 | 组合优化 |
| 旅行商（TSP） | 加权哈密顿回路 |

```
工程现实：NPC 问题照样天天解 —— 用近似/启发式
  近似算法：TSP 的 2-近似（MST 法）
  启发式：模拟退火、遗传算法
  精确解：分支限界 + 剪枝（小规模）

知识：知道"这是 NPC"→ 停止寻找多项式算法，
  转向近似/启发式 —— 这是算法设计的第一决策
```

### 3.3 2025 视角

```
量子计算对 NP 的现状：Shor 算法攻破因式分解（RSA），
  但对 NPC 无多项式加速 —— 量子时代数论密码要换，
  图着色/背包类问题依然安全

—— 数论与图论在密码学命运上的分叉（详见 密码学/）
```

## 4. 逻辑与 LLM：Logic-LM 范式

### 4.1 问题：LLM 的逻辑短板

```
2025 研究共识：LLM 在严格逻辑任务上表现不稳定：
  ① 三段论推理会出错（量化陷阱）
  ② 多步推理的中间步错误会累积
  ③ 无法保证"一致性与完备性"（数学意义上）

根因（离散数学视角）：LLM 是统计模型，
  而逻辑推理要求"符号精确"——两者是不同范式
```

### 4.2 Logic-LM 范式（2025 主流方案）

```
LLM + 符号求解器混合：
  Step 1  LLM 翻译：自然语言问题 → 逻辑公式（命题/谓词）
  Step 2  符号求解：交给 Z3 等求解器验证/求解
  Step 3  回填修正：求解结果反馈给 LLM 完善回答

具体流程（推理链验证）：
  LLM 生成推理步骤 → 每步转成命题公式 → SAT 求解验证
  → 发现矛盾 → 返回 LLM 重新推理

工程落地：RAG 检索结果的一致性检查、
          Agent 计划的可行性验证（约束满足）
```

### 4.3 逻辑增强的工程价值

```
① 可验证性：符号解可证明 → AI 回答可审计（合规场景）
② 约束注入：数据库 CHECK、业务规则 → 提示词约束
③ 事实性：全称量词事实（"所有 X 都是 Y"）的检查
   —— 谓词逻辑直接翻译成验证查询
④ 形式验证：生成代码 → 断言/前置条件的逻辑检查

2025 状态：Logic-LM 类方案从论文走向工具
  （LangChain 的 SQL 校验、Agent 的 DAG 规划合法性检查）
```

> 🎯 认知更新：**离散数学不是 LLM 的"替代品"，而是"安全带"**——统计推理负责生成，符号逻辑负责校验。2025-2026 的 AI 工程共识：让 LLM 自由发挥，用逻辑约束兜底。

## 5. 图论与知识图谱 RAG

### 5.1 GraphRAG 的完整链路（2025）

```
Step 1  实体/关系抽取：LLM 从文档抽取三元组 → 建图
Step 2  社区检测：Louvain 算法找社区（图的聚类）
Step 3  社区摘要：LLM 为每个社区生成摘要（层级索引）
Step 4  检索：问题 → 实体定位 → 图遍历 + 社区摘要 → 拼上下文
Step 5  生成：LLM 基于图增强上下文作答

每一步都是离散数学：
  图构建 = 集合/关系建模
  社区检测 = 图聚类（Louvain 基于模块度最大化）
  遍历检索 = BFS/最短路径
  去重合并 = 集合运算
```

### 5.2 图算法的具体角色

| 图算法 | RAG/AI 角色 | 2025 论文实证 |
|--------|------------|--------------|
| 多跳检索（BFS/DFS） | 实体关联扩展 | 知识图谱 RAG 的标准检索 |
| 最短路径 | 概念间推理链 | "A 与 B 的关系最短链" |
| 社区检测 | 层级摘要结构 | GraphRAG 索引核心 |
| 图嵌入（TransE 等） | 实体语义向量 | 链接预测（SimE 2025） |
| PageRank | 实体重要性 | 检索排序加权 |
| 环检测 | 防循环推理 | LLM 输出去重循环 |

### 5.3 从数学到工程

```
为什么图比向量更适合某些检索：
  向量：语义相似（连续空间）
  图：结构关系（离散结构）——"能回答 结构性问题"：
    "X 的供应商的供应商是谁"（两跳）
    "哪些实体与 X 同社区"（聚类）

2025 工程共识：向量检索 + 图检索混合 = 语义 × 结构
  —— 这正是 03-AI 层 RAG 目录里 GraphRAG 模块的数学底子
```

## 6. 离散结构与神经网络

### 6.1 Transformer 的图论视角

```
注意力矩阵 = 完整有向图（每个 token 对之间有权重边）
  注意力分数 = 边权；多头 = 多层图
  上下文窗口 = 图的顶点规模

2025 视角：LLM 推理链 ≈ 图上行走
  "最佳推理链" ≈ 加权最短路径问题（注意力的解释工具）
```

### 6.2 图神经网络（GNN）

```
核心运算：消息传递（邻居聚合）
  h_v^(k+1) = σ(Σ_{u∈N(v)} W·h_u^k)

谱图论基础：图上卷积 = 拉普拉斯算子的特征分解
  GCN 的数学 = 归一化邻接矩阵的幂近似

2025 实证：RDF 知识图谱 + GNN 推荐系统
  （AutoRDF2GML 等框架把知识图谱转成 GNN 输入）
```

### 6.3 组合结构在模型中的角色

```
Tokenizer：BPE 合并 = 贪心组合优化
位置编码：正弦/旋转位置 = 群论（旋转群）应用
注意力掩码：图的结构约束（因果掩码 = DAG）
KV 缓存：图的记忆结构（检索 = 图查询）

—— 离散数学的每个分支都在模型内部有对应物
```

> 🎯 **核心要点**：离散数学与 AI 的关系 2025 年进入"深度咬合"：逻辑管正确性（Logic-LM）、图管结构（知识图谱 RAG）、组合管复杂度（模型规模分析）。**学离散数学不是为了考试，是为了读懂 AI 论文与设计 AI 系统。**
