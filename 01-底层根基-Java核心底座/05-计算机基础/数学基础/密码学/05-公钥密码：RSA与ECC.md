## 1. 公钥密码学的核心思想

### 1.1 非对称的突破

```text
对称密码的困境：密钥分发（怎么把密钥安全交给对方？）
公钥密码（Diffie-Hellman 1976）：双密钥体系
  公钥：公开（加密/验证）
  私钥：保密（解密/签名）
  从公钥推出私钥 = 数学难题（不可行）

用途两类：
  加密（公钥加密 → 私钥解密）
  签名（私钥签名 → 公钥验证）
```

### 1.2 数学难题家族（初等数论/08 的引擎）

| 体系 | 难题 | 当前建议强度 |
|------|------|:---:|
| RSA | 大整数分解 | 2048-3072 位 |
| DH/ElGamal | 离散对数（DLP） | 2048 位 |
| ECC | 椭圆曲线离散对数（ECDLP） | 256 位 |
| 后量子 | 格（LWE/SIS） | ML-KEM-768 |

> 🎯 核心认知：**公钥密码 = 单向函数（正向易、逆向难）+ 陷门（密钥）**。RSA 的陷门是分解 n；ECC 的陷门是标量倍乘 vs 离散对数。数学基础见 `初等数论/` 目录。

## 2. RSA：数学与实现

### 2.1 密钥生成与加解密（初等数论/02 的完整应用）

```text
密钥生成：
  ① 选大素数 p、q（2048 位 n → 各 1024 位）
  ② n = pq，φ(n) = (p−1)(q−1)
  ③ 选 e（通常 65537），求 d ≡ e⁻¹ (mod φ(n))（扩展欧几里得）
  ④ 公钥 (n, e)，私钥 (n, d)（或 (p, q, d) 加速）

加密：c = m^e mod n
解密：m = c^d mod n（欧拉定理保证正确，见 初等数论/02）

加速：CRT 分解（mod p 与 mod q 并行）→ 约 4 倍（初等数论/04）
```

### 2.2 攻击与防御要点

| 攻击 | 原理 | 防御 |
|------|------|------|
| 暴力分解 | 因数分解 n | 2048+ 位 |
| 低指数 | e 小 + 消息短 | OAEP 填充（随机化） |
| 共模攻击 | 同 n 不同 e | 永不共享模数 |
| 时序/功耗 | 私钥运算泄露 | 常数时间实现（蒙哥马利） |
| 故障注入 | 诱导计算错误 | 结果验证 |

> ⚠️ RSA 裸实现（教科书 RSA）不安全：确定性加密 + 可预测性。必须加 OAEP 填充（加密）与 PSS（签名）——**填充不是可选优化，是安全性的组成部分**。

## 3. RSA 的填充：OAEP

### 3.1 为什么需要填充

```text
教科书 RSA 的问题：
  ① 确定性：同一明文加密结果相同 → 可猜测/字典
  ② 可延展：密文可被数学变换 → 明文可被修改
  ③ 低指数风险：m^e < n 时密文直接开 e 次方

OAEP（最优非对称加密填充）：
  用哈希 + 掩码函数把明文"随机化"再指数运算
  → 加密结果随机、不可延展
  → 安全归约到"随机预言机模型"
```

### 3.2 填充选型

| 场景 | 填充 | 说明 |
|------|------|------|
| RSA 加密 | OAEP | 现代唯一推荐 |
| RSA 签名 | PSS | 概率签名（替代 PKCS#1 v1.5） |
| 密钥封装 | RSA-KEM | 与现代体系对齐 |
| 旧兼容 | PKCS#1 v1.5 | 有 Bleichenbacher 攻击史 |

```text
工程结论：RSA 加密必用 OAEP、签名必用 PSS；
  2026 现实：RSA 正在被 ECC/后量子替代（08 模块），
  新系统优先 ECC 或 ML-KEM
```

## 4. 椭圆曲线密码（ECC）

### 4.1 椭圆曲线的群结构

```text
曲线方程：y² = x³ + ax + b（有限域 GF(p) 上）
点加运算：曲线上两点连线的"反射点"（群运算，见 离散数学/05）
标量倍乘：k·P = P + P + … + P（k 次点加）

安全假设（ECDLP）：给定 P 与 Q = k·P，求 k 极难
  无亚指数算法（对比整数分解有数域筛）→ 同安全强度密钥短 8 倍
```

### 4.2 常用曲线

| 曲线 | 位长 | 安全强度 | 状态 |
|------|:---:|:---:|------|
| P-256（secp256r1） | 256 | 128 | 互联网标准（TLS 默认） |
| P-384 | 384 | 192 | 高安全场景 |
| Curve25519（X25519） | 255 | 128 | **现代首选**（TLS 1.3） |
| Ed25519 | 255 | 128 | **签名首选**（现代） |

```text
Curve25519 为什么流行：
  ① 常数时间实现天然简单（Montgomery 阶梯）
  ② 无标准曲线"后门担忧"（nothing-up-my-sleeve 生成）
  ③ 快：X25519 密钥交换 ~0.1ms（OpenSSL 实测量级）
  → TLS 1.3 默认群、WireGuard、Signal 全部使用
```

## 5. ECDH 与 ECDSA

### 5.1 ECDH 密钥交换

```text
共享参数：曲线 + 基点 G（公开）
  Alice 私钥 a，公钥 A = a·G
  Bob 私钥 b，公钥 B = b·G
  共享密钥：Alice 算 a·B = ab·G；Bob 算 b·A = ab·G ✓
  窃听者只有 A、B、G —— 求 ab 需要 ECDLP

ECDHE（临时版）：每次会话新密钥对（前向保密）
  TLS 1.3 的默认密钥交换：X25519（群）+ 后量子混合（08 模块）
```

### 5.2 ECDSA 签名

```text
签名（私钥 d）：
  选随机 k → 计算 r = (k·G).x mod n
  s = k⁻¹(H(m) + r·d) mod n
验证（公钥 Q）：
  u₁ = H(m)·s⁻¹，u₂ = r·s⁻¹
  (u₁·G + u₂·Q).x ≡ r 则有效

致命陷阱：随机数 k 必须唯一！
  k 复用（或可预测）→ 私钥可直接解出（PS3 事件、Android 事件）
  → 现代推荐 EdDSA（确定性 k = H(私钥‖消息)）
```

### 5.3 签名方案选型

| 方案 | 随机数 | 特点 | 推荐 |
|------|:---:|------|:---:|
| RSA-PSS | 无 | 兼容广泛 | 存量系统 |
| ECDSA | 需要（危险） | 标准 | 可用但注意 k |
| **EdDSA（Ed25519）** | 确定性 | 快、安全、常数时间 | **新系统首选** |
| ML-DSA（后量子） | 需保护 | 2024 标准 | 2026 迁移目标 |

## 6. 安全强度对照

### 6.1 同强度对照表

| 安全强度 | 对称（AES） | RSA | ECC | 哈希 |
|:---:|:---:|:---:|:---:|:---:|
| 112 | — | 2048 | 224 | SHA-224 |
| 128 | AES-128 | 3072 | 256（P-256） | SHA-256 |
| 192 | AES-192 | 7680 | 384 | SHA-384 |
| 256 | AES-256 | 15360 | 521 | SHA-512 |

```text
关键对比：
  RSA-2048 ≈ P-256 ≈ AES-128 ≈ SHA-256（都是 128 位强度）
  ECC 以 1/8 的密钥长度达到同级强度 → 效率碾压
  → 这就是现代系统"放弃 RSA 转 ECC"的理由

NIST 展望（2026）：RSA-2048 与 P-256 计划 2030 弃用、
  2035 禁用（IR 8547，08 模块的迁移时间线）
```

## 7. 工程实践

### 7.1 Java 使用示例

```java
// ECDH 密钥交换（TLS 的底层，JDK 直接支持）
KeyPairGenerator kpg = KeyPairGenerator.getInstance("EC");
kpg.initialize(new ECGenParameterSpec("secp256r1"));
KeyPair alice = kpg.generateKeyPair();
KeyPair bob = kpg.generateKeyPair();

KeyAgreement ka = KeyAgreement.getInstance("ECDH");
ka.init(alice.getPrivate());
ka.doPhase(bob.getPublic(), true);
byte[] secret = ka.generateSecret();   // 双方一致的共享密钥

// 实际工程：直接用 TLS/库（如 JDK 的 SSLSocket、BouncyCastle），
// 不要手写密钥协商协议
```

### 7.2 公钥密码决策清单

| 决策 | 推荐（2026） |
|------|-------------|
| 密钥交换 | X25519（+ ML-KEM 混合，见 08） |
| 签名 | Ed25519（新）/ ECDSA（存量） |
| 加密 | 公钥加密基本淘汰 → 用 KEM/混合方案 |
| RSA | 仅存量兼容（OAEP/PSS 填充） |
| 密钥长度 | 对称 256、ECC 256、RSA 3072+（若用） |

> 🎯 **核心要点**：公钥密码 = "数学难题 + 工程填充"的组合——RSA 靠分解难题 + OAEP，ECC 靠 ECDLP + 常数时间。2026 年的转折点：RSA/P-256 进入退役倒计时（2030 弃用），X25519/Ed25519 已是当下最优，ML-KEM/ML-DSA 正接管未来（08 模块完整展开）。

## 8. 小结

| 问题 | 答案 |
|------|------|
| 公钥密码靠什么？ | 单向函数 + 陷门（分解/离散对数） |
| RSA 为什么必须 OAEP？ | 裸 RSA 确定性、可延展、低指数可破 |
| ECC 优势？ | 同强度密钥短 8 倍（256 位 ≈ RSA-3072） |
| Curve25519 为什么流行？ | 常数时间、无后门疑虑、TLS 1.3 默认 |
| ECDSA 头号风险？ | 随机数 k 复用 → 私钥泄露 |
| 现代签名首选？ | Ed25519（确定性随机数） |
