## 1. 对称密码概览

### 1.1 定义与地位

**对称密码**：加密与解密使用同一密钥。

| 特性 | 说明 |
|------|------|
| 速度 | 极快（硬件加速，GB/s 级） |
| 密钥长度 | 128/192/256 位 |
| 用途 | 数据加密（TLS 记录层、磁盘、数据库） |
| 分类 | 分组密码（AES）与流密码（ChaCha20） |
| 挑战 | 密钥分发（需要非对称密码解决） |

### 1.2 混淆与扩散（Shannon 的设计原则）

| 原则 | 含义 | 实现 |
|------|------|------|
| 混淆（Confusion） | 密文与密钥的关系复杂到无法分析 | 非线性替换（S 盒） |
| 扩散（Diffusion） | 明文的微小变化扩散到整个密文 | 置换、轮运算 |

```text
雪崩效应（扩散的量化）：改变 1 位明文 → 约一半密文位改变
  AES 的雪崩效应在 2-3 轮后完全建立
```

## 2. 分组密码的两种结构

### 2.1 Feistel 结构（DES 传统）

```text
每轮：把分组分成左右两半
  左' = 右
  右' = 左 ⊕ F(右, 子密钥)

特点：
  ① 解密 = 逆序重跑（F 不需要可逆！）
  ② 硬件实现对称（加解密同电路）
  ③ 代表：DES、Blowfish、Camellia

局限：F 函数设计不当则弱；轮数多（DES 16 轮）才安全
```

### 2.2 SPN 结构（AES 采用）

```text
每轮：S 盒替换（混淆）→ 置换/线性变换（扩散）→ 加子密钥
  S 盒：非线性查表（每字节 8→8 位）
  线性层：行移位 + 列混合（扩散）

特点：
  ① 混淆扩散分离设计，理论分析更清晰
  ② 加解密结构不同（需逆变换）
  ③ 现代标准的选择：AES、SM4

对照：Feistel 圆润通用、SPN 锐利高效——AES 代表 SPN 胜出
```

## 3. AES 内部机制

### 3.1 总体结构

```text
AES-128：128 位分组，10 轮（192 位 → 12 轮；256 位 → 14 轮）

状态矩阵：16 字节按列排列成 4×4 矩阵
每轮四步：
  ① SubBytes：S 盒逐字节替换（非线性，抗差分/线性分析）
  ② ShiftRows：行循环移位（扩散）
  ③ MixColumns：列混合（GF(2⁸) 上的矩阵乘！）
  ④ AddRoundKey：与轮密钥异或（密钥引入）

密钥扩展：主密钥经扩展生成每轮子密钥
```

### 3.2 为什么 AES 安全

```text
S 盒的数学性质（GF(2⁸) 上的设计，见 初等数论/05）：
  最大差分概率 2⁻⁶（抗差分密码分析）
  最大线性偏差 2⁻⁴（抗线性密码分析）
  无不动点、代数次数高（抗代数攻击）

20+ 年全球审查结论：AES 除侧信道外无实用攻击
  —— 侧信道（时序/功耗）成为 AES 工程实现的唯一主战场（07 模块）
```

### 3.3 Java 使用 AES

```java
// AES-GCM（现代推荐，JDK 内置）
SecretKey key = new SecretKeySpec(keyBytes, "AES");
Cipher cipher = Cipher.getInstance("AES/GCM/NoPadding");
cipher.init(Cipher.ENCRYPT_MODE, key, new GCMParameterSpec(128, iv));
byte[] ciphertext = cipher.doFinal(plaintext);
// 注意：GCMParameterSpec(标签长度位, IV)；IV 每加密一次必须更换！
```

## 4. 工作模式

### 4.1 模式的意义

分组密码只加密固定分组（AES 128 位）——**模式**定义如何用分组密码加密任意长度数据。

### 4.2 模式家族对比

| 模式 | 原理 | 认证 | 平行 | 状态 |
|------|------|:---:|:---:|------|
| ECB | 各分组独立加密 | 无 | ✅ | ❌ 禁止使用（见下） |
| CBC | 前组密文与当前明文异或 | 无 | ❌ | 传统（需配合 MAC） |
| CTR | 计数器流加密 | 无 | ✅ | 流式替代品 |
| **GCM** | CTR + Galois 认证 | ✅ | ✅ | **现代默认** |
| **ChaCha20-Poly1305** | 流密码 + Poly1305 | ✅ | ✅ | 现代替代 |

### 4.3 ECB 的经典失败（必知教训）

```text
ECB 问题：相同明文分组 → 相同密文分组
  → 图像加密后轮廓依然可见（企鹅图攻击！）

工程铁律：ECB 永远不要用
  即使"数据看起来随机"也不行——模式级信息泄露
```

### 4.4 IV 的使用规则

```text
CBC/CTR/GCM 都需要 IV（初始向量）：
  规则 1：IV 不可重复（同密钥下重复 = 灾难）
  规则 2：IV 无需保密（公开传输）
  规则 3：GCM 的 IV 长度 96 位推荐值；随机或计数器

反例教训：WEP 的 IV 复用 → 密钥可被恢复（RSA 攻击）
```

## 5. AEAD：认证加密

### 5.1 加密必须带认证

```text
只加密不认证的后果：
  攻击者可以翻转密文比特 → 明文被可预测地篡改（CBC bit-flipping）
  解密端无法察觉 → 完整性崩溃

现代标准：AEAD（Authenticated Encryption with Associated Data）
  一次操作完成 加密 + 认证：
    密文可验证（篡改即解密失败）
    附带数据可认证（如 TLS 头部信息）

经典教训：先 MAC 后加密（Encrypt-then-MAC）是正确的组合
  先加密后 MAC（MAC-then-Encrypt）有历史漏洞（Lucky13）
```

### 5.2 主流 AEAD 方案

| 方案 | 结构 | 特点 |
|------|------|------|
| AES-GCM | CTR + GHASH | 硬件加速快；注意 GCM 生日界限 |
| ChaCha20-Poly1305 | 流密码 + Poly1305 | 软件快、无硬件依赖；移动端友好 |
| AES-CCM | CBC-MAC 变体 | 旧标准（TLS 1.2） |

```text
工程选型（2025 共识）：
  x86 服务器：AES-GCM（AES-NI 硬件指令）
  移动/嵌入式：ChaCha20-Poly1305（无硬件 AES 时）
  TLS 1.3 两种都支持（套件协商）
```

## 6. 工程实践

### 6.1 对称加密决策清单

| 决策 | 推荐 |
|------|------|
| 算法 | AES-256 或 ChaCha20 |
| 模式 | GCM（AEAD） |
| 密钥长度 | 256 位（128 位也可但无理由选低） |
| IV | 96 位随机，永不重复 |
| 密钥存储 | 密钥管理服务（KMS）/ 硬件安全模块（HSM） |
| 密码学库 | 用 JDK/JCA 或 BouncyCastle，永不手写算法 |

### 6.2 常见错误清单

| 错误 | 后果 |
|------|------|
| 使用 ECB | 模式泄露（明文结构可见） |
| IV 复用 | 密钥可恢复（GCM 灾难） |
| 只用加密不用 MAC | 密文可篡改 |
| 手写 AES 实现 | 侧信道/常数时间问题 |
| 密钥硬编码 | 源码泄露 = 全部数据泄露 |
| 压缩+加密顺序 | 压缩后加密正确；反之有 CRIME/BREACH 攻击 |

> 🎯 **核心要点**：对称密码是"快而强"的数据加密主力——AES 本身安全（数学层面），工程安全完全取决于**模式选择（GCM）、IV 管理、认证（AEAD）**三件事。2026 年视角：对称密码不受量子威胁直接冲击（Grover 只减半安全强度，AES-256 仍安全），迁移重点全在非对称侧（08 模块）。
