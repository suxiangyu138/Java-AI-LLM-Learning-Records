## 1. 哈希函数的三性质

### 1.1 定义

**哈希函数** H：任意长度输入 → 固定长度输出（如 SHA-256 输出 256 位）。

### 1.2 三个安全性质（密码学哈希必背）

| 性质 | 定义 | 攻击难度 |
|------|------|:---:|
| 抗原像（单向） | 给 y，找不到 x 使 H(x) = y | 2ⁿ |
| 抗第二原像 | 给 x₁，找不到 x₂≠x₁ 使 H(x₁)=H(x₂) | 2ⁿ |
| 抗碰撞 | 找不到任意 x₁≠x₂ 使 H(x₁)=H(x₂) | **2^(n/2)**（生日攻击） |

```text
关键差异：抗碰撞只有 2^(n/2)（比前两者弱一半）
  → SHA-256 的碰撞安全 = 128 位（而非 256 位）
  → 这就是"哈希至少用 256 位"的原因（128 位抗碰撞只剩 64 位）

工程推论：
  完整性校验（抗碰撞）→ SHA-256 起步
  指纹/去重（仅需抗原像）→ 可考虑较短输出
```

### 1.3 哈希 vs 加密（易混概念）

| 维度 | 哈希 | 加密 |
|------|------|------|
| 可逆 | 不可逆（单向） | 可逆（密钥） |
| 输出 | 固定长度摘要 | 与明文等长 |
| 用途 | 完整性、口令 | 机密性 |
| 密钥 | 无（HMAC 除外） | 有 |

## 2. SHA 家族与构造

### 2.1 主流算法

| 算法 | 输出 | 状态 | 特点 |
|------|:---:|------|------|
| MD5 | 128 | ❌ 已破（碰撞 2²⁴） | 仅用于校验和 |
| SHA-1 | 160 | ❌ 已破（碰撞 2⁶³，2017 SHAttered） | 禁止 |
| SHA-2（256/384/512） | 256+ | ✅ 标准 | Merkle-Damgård |
| SHA-3（Keccak） | 224-512 | ✅ 标准 | **海绵结构** |
| BLAKE2/BLAKE3 | 256 | ✅ 流行 | 极快（软件） |

### 2.2 两种构造

```text
Merkle-Damgård（SHA-2）：
  消息分块 → 每块与状态压缩 → 最终块补长度（MD 填充）
  性质：压缩函数安全 → 整体安全（归约证明）

海绵结构（SHA-3）：
  吸收阶段：消息块异或进状态（内部置换迭代）
  挤出阶段：从状态读输出（可任意长）
  性质：简单、输出长度灵活、免长度扩展攻击

对照：MD 有长度扩展攻击（HMAC 需规避）；
     海绵结构天然免疫 → SHA-3 在设计上更干净
```

## 3. 生日攻击与安全强度

### 3.1 生日悖论

```text
n 位哈希的碰撞期望：
  约 2^(n/2) 次随机输入后出现碰撞（生日悖论推广）
  例：64 位哈希 → 2³² 次尝试即碰撞（现代算力分钟级）

攻击流程（生日攻击）：
  ① 收集 2^(n/2) 个哈希值（计算/中间人）
  ② 找碰撞 → 伪造内容与合法内容同哈希
  ③ 用于证书伪造/文档篡改（先碰撞后利用）

经典事件：
  MD5 碰撞 2²⁴（2004）→ 证书伪造（2008）
  SHA-1 碰撞 2⁶³（2017）→ SHAttered 论文（两 PDF 同哈希）
```

### 3.2 安全强度速查

| 哈希 | 输出位 | 碰撞安全 | 结论 |
|------|:---:|:---:|------|
| MD5 | 128 | 64（实际 2²⁴） | 已破 |
| SHA-1 | 160 | 80（实际 2⁶³） | 已破 |
| SHA-256 | 256 | 128 | ✅ 安全 |
| SHA-384 | 384 | 192 | ✅（高安全） |
| SHA-512 | 512 | 256 | ✅ |
| SHA-3-256 | 256 | 128 | ✅ |

## 4. MAC 与 HMAC

### 4.1 为什么哈希不够

```text
裸哈希的问题：任何人可对任意消息计算 H(m)
  → 无法区分"合法发送者"与"篡改者"

MAC（消息认证码）：密钥化哈希
  MAC_K(m) 需要密钥 K 才能计算/验证
  → 完整性 + 发送方认证（对称世界）
```

### 4.2 HMAC 构造

```text
HMAC(K, m) = H((K' ⊕ opad) ‖ H((K' ⊕ ipad) ‖ m))
  K'：密钥填充/压缩到哈希块长
  ipad/opad：内外填充常数

性质：
  ① 基于哈希的安全性归约（哈希安全 ⟹ HMAC 安全）
  ② 免疫 MD 长度扩展攻击（双哈希结构）
  ③ 任意长度密钥（内部哈希压缩）

Java 示例：
  Mac mac = Mac.getInstance("HmacSHA256");
  mac.init(new SecretKeySpec(key, "HmacSHA256"));
  byte[] tag = mac.doFinal(message);
```

### 4.3 MAC 家族

| 方案 | 类型 | 场景 |
|------|------|------|
| HMAC-SHA256 | 哈希基 | JWT 传统签名、TLS 1.2 |
| AES-CMAC | 分组基 | 网络协议 |
| GCM 标签 | AEAD 内置 | 现代 TLS（02 模块） |
| Poly1305 | 流密码基 | ChaCha20-Poly1305 |

## 5. 口令哈希

### 5.1 口令存储的独特问题

```text
口令不是随机密钥：可猜测（字典/暴力/社会工程）
  → 直接 SHA-256(口令) 存储的灾难：
    ① 查表攻击（预计算彩虹表）
    ② 快速暴力（GPU 每秒数十亿次 SHA-256）

正确方案：慢哈希 + 盐
  盐（salt）：每用户随机 → 彩虹表失效
  慢：迭代/内存硬 → 暴力成本指数上升
```

### 5.2 口令哈希算法演进

| 算法 | 设计 | 特点 | 状态 |
|------|------|------|------|
| MD5/SHA-1 直接 | 无 | 秒破 | ❌ |
| bcrypt | Blowfish 变体 | 慢哈希（约 100ms） | ✅ 仍广泛 |
| scrypt | 内存硬 | 抗 ASIC | ✅ |
| **argon2** | 内存硬 + 并行 | 2015 密码哈希竞赛冠军 | ✅ 现代推荐 |
| PBKDF2 | HMAC 迭代 | 标准但可 ASIC 加速 | 可用（FIPS） |

```text
选择建议（2025 共识）：
  新系统：argon2id（默认参数：内存 64MB、迭代 3、并行 4）
  兼容系统：bcrypt（cost 12+）或 scrypt
  口令哈希 ≠ 会话 token 哈希（后者用 SHA-256 即可，非口令）
```

### 5.3 口令验证的常数时间

```text
比较哈希时禁止用普通字符串比较（== / equals）：
  逐字符比较会泄露"前多少位相同"（时序侧信道）
  正确：MessageDigest.isEqual（常数时间比较）

Java 工程：
  MessageDigest.isEqual(computed, stored)  ✅
  stored.equals(computed)                   ❌（时序泄露）
```

## 6. 工程实践

### 6.1 哈希用途速查

| 场景 | 算法 | 说明 |
|------|------|------|
| 文件完整性 | SHA-256 | 下载校验 |
| 口令存储 | argon2id/bcrypt | 慢 + 盐 |
| 消息认证 | HMAC-SHA256 | 带密钥 |
| 证书/签名 | SHA-256/384 | 配合非对称 |
| 数据指纹/去重 | SHA-256 | 内容寻址 |
| 快速校验 | CRC-32 | 非安全（信息论/05） |
| JWT 签名 | HS256/RS256 | 见 07 模块 |

### 6.2 常见错误清单

| 错误 | 后果 |
|------|------|
| 口令直接 SHA-256 | 彩虹表秒破 |
| 无盐 | 相同口令相同哈希 → 批量破解 |
| bcrypt/argon2 参数过低 | 暴力成本不足 |
| 哈希比较用 equals | 时序侧信道 |
| 用已破哈希（MD5/SHA-1）做安全 | 碰撞伪造 |
| 混淆"哈希"与"加密" | 设计错误 |

> 🎯 **核心要点**：哈希家族按"安全强度 × 场景"选型——完整性用 SHA-256+（抗碰撞 2¹²⁸）、消息认证用 HMAC（密钥化）、口令存储用 argon2（慢+盐+内存硬）。哈希是"最常用也最容易用错"的密码学原语，参数与场景的匹配是工程重点。
