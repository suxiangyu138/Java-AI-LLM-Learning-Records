## 4. 核心概念速查

| 概念 | 一句话解释 |
|------|-----------|
| **GAV 坐标** | groupId:artifactId:version——包的唯一身份证 |
| **仓库（Registry）** | 包的中央仓库（Maven Central / npmjs / PyPI） |
| **依赖解析** | 根据坐标 + 版本约束找到具体版本的过程 |
| **锁文件** | 固定全量依赖版本（package-lock / uv.lock / pom 依赖树） |
| **SemVer** | `主.次.补丁`——主版本破坏兼容，次版本加功能，补丁修 bug |
| **传递依赖** | A→B→C，A 自动获得 C（Maven 自动传递；npm 平铺） |
| **依赖冲突** | 同坐标多版本 → 各生态不同裁决策略（Maven 就近/前端 dedupe） |
| **Maven** | Java 声明式构建工具（POM），2026 Maven 4 rc 阶段 |
| **Gradle** | Java 编程式构建工具（Task 图 + 增量缓存），2026 已 9.3 |
| **pnpm** | 前端硬链接式包管理，磁盘高效、杜绝幽灵依赖 |
| **uv** | Python 极速包管理器（Rust），2026 快速蚕食 pip 份额 |
| **winget** | Windows 官方包管理器（Win11 内置，2026 v1.29 支持 MCP/DSC） |
| **SDKMAN/mise** | 多语言版本管理（JDK/Node/Python 一键切换） |

## 5. 一图看懂：各生态包管理器格局（2026）

```text
Java 生态
├── Maven 4（rc-5 阶段，JDK 17+ 运行）→ 传统王者、声明式
├── Gradle 9.3 → 性能怪兽、编程式
└── 选型金句：团队熟悉度优先；新项目重性能选 Gradle

前端生态
├── npm → 注册表霸主（生态默认）
├── yarn → 老牌挑战者（2026 已边缘化）
├── pnpm → monorepo 首选（硬链接 + 幽灵依赖拦截）
└── bun → 「有趣 → 真正可用」（2026 装机量快速上升）

Python 生态
├── pip + venv → 官方默认（慢但稳）
├── uv → 单二进制替代全家（pip/venv/poetry），2026 主流化
├── poetry → 完整项目治理（pyproject 原生）
└── conda → 二进制环境（AI/数据科学首选）

其他语言生态
├── Go modules → 官方内置（MVS 最小版本 + go.sum 校验）
├── Rust cargo → 官方内置（语义化 + crates.io + audit）
├── Ruby gem+Bundler / PHP Composer / .NET NuGet / Swift SPM
├── Dart pub / Scala sbt / R CRAN+renv / Julia Pkg / PowerShell Gallery
├── C/C++ → vcpkg（微软）/ Conan（二进制库分发）
└── 共性：全部是「清单 + 锁文件」模型（详见 08 长尾速查）

系统级包管理器
├── Windows → winget（官方内置，v1.29 支持 MCP/DSC）
│             choco（企业存量）/ scoop（便携 CLI）
├── Linux → apt（Debian）/ dnf（RHEL）/ pacman（Arch）/ apk（Alpine）
├── macOS → Homebrew（唯一主流）
└── 容器 → Docker 镜像成为「基础设施软件」事实标准

版本管理（横切）
├── SDKMAN（JVM）/ mise（多语言统一）/ nvm（Node）/ pyenv（Python）
└── 金句：包管理管「依赖」，版本管理管「运行时」——两件事分开管
```
