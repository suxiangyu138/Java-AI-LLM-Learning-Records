## 1. 正则问题的三类症状

> **背景**：生产中的正则问题通常表现为「慢」「错」「崩」三类——症状不同，排查路径不同。
> **目的**：按症状快速定位问题类型，走对排查路径。
> **适用范围**：所有正则相关线上问题。

| 症状 | 表现 | 根因方向 | 排查工具 |
|------|------|---------|---------|
| **慢（性能）** | 接口响应变慢、CPU 高 | 回溯复杂度/重复编译/长输入 | 基准测试 + 火焰图 |
| **错（逻辑）** | 校验误判/提取缺失 | 语义误解/标志位/字符类 | 调试工具 + 边界测试 |
| **崩（异常）** | StackOverflowError/超时 | 深嵌套模式/灾难回溯 | 复杂度测试 + 防护 |

```text
三类症状的优先处理顺序
├── 崩 > 慢 > 错（先止血再修逻辑）
├── 崩：立即加长度限制 + 超时（见 04 篇）
├── 慢：基准定位热点模式 → 改写
└── 错：补齐边界用例 → 修正模式
```

## 2. 性能分析与基准

### 2.1 JMH 基准（微基准标准工具）

```java
// JMH 基准：对比模式写法的性能
@BenchmarkMode(Mode.AverageTime)
@OutputTimeUnit(TimeUnit.MICROSECONDS)
public class RegexBenchmark {

    @Benchmark
    public boolean compiledPattern(Blackhole bh) {
        // 预编译（正确写法）
        return PATTERN.matcher(INPUT).matches();
    }

    @Benchmark
    public boolean inlineCompile(Blackhole bh) {
        // 每次编译（反模式）
        return Pattern.compile("...").matcher(INPUT).matches();
    }

    @Benchmark
    public boolean greedy(Blackhole bh) {
        return GREEDY.matcher(EVIL_INPUT).matches();   // 危险模式
    }

    @Benchmark
    public boolean atomic(Blackhole bh) {
        return ATOMIC.matcher(EVIL_INPUT).matches();   // 原子化
    }
}

// 运行：mvn clean package && java -jar target/benchmarks.jar
// 输出：平均耗时对比（us/op）——数据说话
```

### 2.2 复杂度探测测试（生产必做）

```java
// 复杂度测试：输入翻倍看耗时是否翻倍
public class RegexComplexityTest {
    @Test
    void complexity_shouldBeLinear() {
        long t10 = time("a".repeat(10) + "X");
        long t20 = time("a".repeat(20) + "X");
        long t40 = time("a".repeat(40) + "X");

        // 线性：翻倍输入 ≈ 翻倍耗时
        // 指数：+10 字符耗时 ×4 以上 → 危险！
        assertTrue(t40 < t10 * 16,
            "疑似灾难性回溯：10=" + t10 + "ms 40=" + t40 + "ms");
    }

    private long time(String input) {
        long start = System.nanoTime();
        PATTERN.matcher(input).matches();
        return (System.nanoTime() - start) / 1_000_000;
    }
}
```

## 3. 慢正则的定位方法

### 3.1 定位三步

```text
慢正则定位三步
├── ① 确认正则参与：性能分析（Async Profiler 火焰图）
│   → Pattern.matcher / Matcher.match 占用时间比例
├── ② 找到具体模式：堆栈定位到调用点（哪个校验/解析方法）
├── ③ 复杂度验证：用长输入实测该模式（见 2.2）
└── ④ 输入画像：确认实际输入的典型长度/分布
```

### 3.2 Async Profiler 火焰图

```bash
# 采集 CPU 火焰图（定位正则热点）
./profiler.sh -d 30 -f flamegraph.html <pid>

# 火焰图看什么：
# ① 宽块 = 耗时大户：Pattern.matcher 相关栈
# ② 调用链：哪个业务方法在调用正则
# ③ 对比：优化前后火焰图宽度变化
```

### 3.3 常见慢正则根因

| 根因 | 特征 | 解法 |
|------|------|------|
| **热循环重复编译** | 火焰图 Pattern.compile 宽 | 预编译为静态常量 |
| **灾难性回溯** | 特定输入卡死 | 改写模式（03 篇七原则） |
| **长输入扫描** | 大文本整体匹配 | 长度限制/分段处理 |
| **find 循环重复扫描** | find() + 长输入 | 一次收集或换引擎 |
| **宽松模式** | `.*` 大范围 | 精确字符类收窄 |

## 4. 性能优化清单

```text
正则性能优化清单（按收益排序）
├── ① 预编译 Pattern（静态常量）——最大收益（100 倍级）
├── ② 消除歧义（嵌套量词/重叠分支）——消除灾难可能
├── ③ 精确字符类（[0-9]{4} 优于 \\d+）——收窄搜索空间
├── ④ 锚定（^ $ \\b）——快速失败
├── ⑤ 前置短路（length/startsWith 先行）——避免正则启动
├── ⑥ 原子化/占有量词——防跨段回溯
├── ⑦ 简单任务换原生 API（Character.isDigit/contains）——零正则开销
└── ⑧ 缓存动态正则（ConcurrentHashMap + computeIfAbsent）
```

```java
// 优化示例：校验逻辑的前置短路
public boolean isValidOrderId(String id) {
    // ① 前置短路（零正则开销）
    if (id == null || id.length() != 12) return false;
    if (!id.startsWith("ORD")) return false;
    // ② 预编译精确模式
    return ORDER_ID.matcher(id).matches();   // ^ORD\d{9}$
}
```

## 5. CI 自动化安全审查

### 5.1 静态扫描（入门禁）

```yaml
# GitHub Actions 正则安全审查
name: regex-security
on: [push, pull_request]
jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: 危险模式扫描（嵌套量词）
        run: |
          # (x+)+ / (x*)* 模式
          grep -rnE '\([^)]*[+*]\)[+*]' --include="*.java" . \
            && exit 1 || echo "✅ 无嵌套量词"
      - name: 危险模式扫描（重叠交替）
        run: |
          grep -rnE '\(([^)|]+\|[^)]*)\)\+' --include="*.java" . \
            && exit 1 || echo "✅ 无重叠交替"
      - name: Semgrep 正则规则
        run: |
          semgrep --config p/owasp-top-ten --lang java .
```

### 5.2 复杂度测试入门禁

```text
CI 正则质量门禁（三层）
├── ① 静态扫描：危险模式（嵌套量词/重叠交替）→ 直接拦截
├── ② 复杂度测试：新正则的最坏输入测试 → 超时即失败
├── ③ 覆盖率：正则工具类（校验/脱敏）的单测覆盖
└── 效果：危险正则在 CI 拦截，不上生产
```

## 6. 团队正则规范

### 6.1 代码规范

```text
团队正则规范（Code Review 检查项）
├── ① 正则必须预编译（静态常量 Pattern）
├── ② 正则必须带注释（说明匹配什么/边界）
├── ③ 危险模式禁止（嵌套量词/重叠交替）
├── ④ 不可信输入：长度限制 + 复杂度测试
├── ⑤ 命名组替代魔法数字（group("year") 而非 group(1)）
├── ⑥ 复杂正则集中管理（RegexConstants 类）
└── ⑦ 脱敏/校验方法统一工具类（不散落）
```

```java
// 带注释的正则（团队规范示例）
public class RegexConstants {
    /**
     * 订单号：ORD + 9 位数字
     * 示例：ORD123456789
     * 边界：固定 12 位（长度由业务保证）
     */
    public static final Pattern ORDER_ID =
            Pattern.compile("^ORD\\d{9}$");
}
```

### 6.2 正则评审清单

```text
正则 PR 评审六查
[ ] 预编译了吗？（静态常量）
[ ] 有注释说明边界吗？
[ ] 是危险模式吗？（嵌套量词/重叠/反向引用+不可信）
[ ] 处理不可信输入有防护吗？（长度/超时/RE2J）
[ ] 测试覆盖了吗？（正常/边界/恶意输入）
```

### 7.2 本地调试技巧

```java
// 用 Java 小工具快速验证（JShell 或测试类）
// jshell（Java 9+ 内置）
jshell> import java.util.regex.*;
jshell> Pattern.compile("(a+)+b").matcher("aaaaX").matches()
// （小心！这行会卡死——正好演示灾难性回溯）

// 逐步调试：打印匹配过程（理解回溯）
public void debugMatch(Pattern p, String input) {
    Matcher m = p.matcher(input);
    // 用 matches + 分组位置观察匹配路径
    if (m.matches()) {
        for (int i = 0; i <= m.groupCount(); i++) {
            System.out.printf("group(%d)=[%s]@[%d,%d]%n",
                i, m.group(i), m.start(i), m.end(i));
        }
    }
}
```

## 8. 核心要点

> 🎯 **核心要点**：
> 1. 三类症状分路排查：崩（防护优先）> 慢（基准定位）> 错（边界用例）
> 2. 性能定位：JMH 基准 + Async Profiler 火焰图 + 复杂度探测测试（翻倍输入看耗时）
> 3. 优化清单按收益排序：预编译（100 倍级）> 消除歧义 > 精确字符类 > 前置短路
> 4. CI 三层门禁：静态扫描（嵌套量词/重叠交替）+ 复杂度测试 + 工具类单测
> 5. 团队规范：预编译 + 带注释 + 命名组 + 危险模式禁止 + 评审六查——**能被同事读懂的正则才是好正则**
