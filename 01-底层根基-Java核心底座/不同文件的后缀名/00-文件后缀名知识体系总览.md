## 4. 核心概念速查

| 概念 | 一句话解释 |
|------|-----------|
| **后缀名** | 文件的「身份证」——操作系统关联默认程序，内容才是真实身份 |
| **魔数（Magic Number）** | 文件头部的固定字节，识别文件真实格式（不依赖后缀名） |
| **MIME 类型** | 互联网标准文件类型（`text/html`/`application/json`），HTTP 传输用 |
| **UTF-8 / GBK / BOM** | 文本编码三兄弟：UTF-8 国际标准、GBK 中文默认、BOM 是记事本陷阱 |
| **CRLF / LF** | 换行符差异：Windows \r\n vs Linux/macOS \n——跨平台第一坑 |
| **二进制 vs 文本** | 文本可读可 diff；二进制高效但需工具（file 命令识别） |
| **ZIP 本质** | 一半以上「高级格式」都是 ZIP 外壳（jar/war/docx/apk/ipa） |
| **容器 vs 编码** | 视频/音频的「壳」（mp4/mkv）与「核」（H.264/AAC）分离 |
| **有损 vs 无损** | 图片/音频压缩的两派：体积换质量 vs 质量保体积 |
| **ELF / PE / Mach-O** | 三大系统可执行文件格式（Linux/Windows/macOS） |
| **符号链接 vs 硬链接** | 快捷方式指向 vs 同一文件多个名（`.lnk`/`.symlink`） |

## 5. 场景速查：怎么选格式

| 场景 | 推荐格式 | 理由 |
|------|---------|------|
| 接口数据交换 | **JSON** | 通用、可读、生态全 |
| 服务配置 | **YAML** | 层级清晰、支持注释 |
| 大数据列式存储 | **Parquet** | 压缩率高、列式查询快 |
| 文档发布 | **PDF** | 跨平台、不可变 |
| Java 后端部署 | **JAR** | JVM 直接运行 |
| 容器打包 | **Docker 镜像（layers）** | 分层缓存、可复用 |
| 压缩传输 | **ZIP** | 通用、自带目录结构 |
| 高压缩率归档 | **7z** | 压缩率之王 |
| 图片网站用 | **WebP/AVIF** | 体积小质量高 |
| 日志存储 | **.log + 轮转** | 简单可 tail |

## 6. 魔数速查表（file 命令识别依据）

| 魔数（十六进制） | 文件格式 | 魔数文本 |
|:---:|---------|---------|
| `50 4B 03 04` | ZIP/jar/war/docx | `PK` |
| `CA FE BA BE` | Java .class 字节码 | - |
| `89 50 4E 47` | PNG 图片 | `PNG` |
| `FF D8 FF` | JPEG 图片 | - |
| `25 50 44 46` | PDF 文档 | `%PDF` |
| `7F 45 4C 46` | ELF（Linux 可执行） | `ELF` |
| `4D 5A` | PE（Windows exe） | `MZ` |
| `1F 8B` | GZIP | - |
| `28 B5 2F FD` | 7z | - |
| `47 49 46 38` | GIF | `GIF8` |
| `4F 67 67 53` | OGG | `OggS` |

> 💡 **file 命令实战**：`file xxx` 按内容识别真实格式——改名骗不了它：`mv app.jar app.txt && file app.txt` 依然输出 `Zip archive data`。

---

> 🎯 **核心认知**：**后缀名只是约定，魔数才是真相**——恶意文件可以改名伪装，但文件头部的魔数不会说谎。安全场景（上传校验/安全扫描）必须按内容校验，不能只看后缀名。
