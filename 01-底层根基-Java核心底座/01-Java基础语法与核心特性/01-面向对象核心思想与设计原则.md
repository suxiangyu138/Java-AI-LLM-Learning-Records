# 面向对象核心思想与设计原则

## 📌 课程定位
OOP是现代软件开发的主流范式。理解封装、继承、多态以及SOLID原则，是写出可维护、可扩展代码的思维基础——不只是学语法，是学"怎么设计"。

## 🎯 核心章节

### 1. OOP 三大/四大特性
- **封装**：隐藏内部实现细节，只暴露接口——变化隔离
- **继承**：复用父类代码+建立is-a关系——但多用组合少用继承
- **多态**：
  - 编译时多态：重载(方法签名不同)、泛型
  - 运行时多态：重写(虚函数/动态绑定)——OOP的灵魂
  - 本质：同一个接口，不同的实现，运行时根据实际对象类型调用对应方法
- **抽象**：提取共性、忽略细节——从具体到一般的思维过程

### 2. SOLID 五大原则（⭐ 设计核心）
| 原则 | 含义 | 一句话 |
|------|------|--------|
| **S**ingle Responsibility | 单一职责 | 一个类只干一件事 |
| **O**pen/Closed | 开闭原则 | 对扩展开放，对修改关闭 |
| **L**iskov Substitution | 里氏替换 | 子类必须能完全替换父类 |
| **I**nterface Segregation | 接口隔离 | 接口拆分得小而精 |
| **D**ependency Inversion | 依赖倒置 | 依赖抽象而不是具体实现 |

### 3. 组合优于继承
- **继承的问题**：破坏封装(子类依赖父类实现)、强耦合、单继承限制
- **组合**：持有另一个类的实例，通过委托实现复用——更灵活
- **何时用继承？** 确实存在"is-a"关系，且行为稳定不变

### 4. 设计模式概览（23种GoF，重点掌握5-8种）
- **创建型**：单例(懒汉/饿汉/DCL)、工厂方法、抽象工厂、建造者
- **结构型**：适配器(接口转换)、装饰器(动态增强)、代理(控制访问)
- **行为型**：观察者(发布-订阅)、策略(算法族切换)、模板方法(算法骨架)
- **核心原则**：把变化的部分封装起来，让变化的部分与不变的部分隔离

### 5. 面向对象 vs 面向过程 vs 函数式
| 范式 | 核心 | 优点 | 缺点 |
|------|------|------|------|
| 面向过程 | 函数调用 | 简单直接 | 复杂度高时难维护 |
| 面向对象 | 对象+消息 | 封装变化、可扩展 | 过度设计、性能开销 |
| 函数式 | 无副作用函数 | 无状态、易并行 | 学习曲线、IO操作麻烦 |

## ✅ 学习建议
- SOLID原则不是背的，而是通过重构体验的——把一段烂代码一步步改造
- 先掌握单例、工厂、策略、观察者4个模式——80%场景会用到
- 《Head First 设计模式》是入门佳作，《设计模式之禅》适合深入
