## 1. 封装的核心思想

封装是面向对象编程的四大基石之一（封装、继承、多态、抽象），其本质是**数据隐藏 + 行为暴露**——将数据和操作数据的方法绑定，通过访问控制隐藏内部细节，只暴露稳定的接口。

| 价值 | 说明 |
|------|------|
| 变化隔离 | 内部实现变化不影响外部调用方 |
| 降低复杂度 | 调用方只需关心接口，无需理解内部实现 |
| 保护完整性 | 防止外部非法修改对象状态 |
| 可维护性 | 修改内部实现时不破坏已有代码 |

```java
// 错误：直接暴露内部状态                // 正确：隐藏数据，暴露行为
public class BadCounter {                public class GoodCounter {
    public int count;                        private int count;
}                                            public void increment() { count++; }
                                             public int getCount() { return count; }
                                         }
```

> 💡 **核心原则**：最小化访问权限——能不公开就不公开。接口是契约，实现可随时重构（《Thinking in Java》）。

## 2. 四种访问修饰符详解

### 2.1 `private` —— 最严格

可见范围：**仅本类内部**。成员变量优先使用 private。

```java
public class User {
    private Long id;
    private String password;               // 敏感信息不对外暴露

    private void encrypt(String raw) {     // 内部辅助方法
        this.password = BCrypt.hashpw(raw, BCrypt.gensalt());
    }

    public void setPassword(String raw) {
        if (raw == null || raw.length() < 6) throw new IllegalArgumentException("密码长度至少 6 位");
        encrypt(raw);                      // 内部调用私有方法
    }
}
```

> ⚠️ `private` 不能修饰外部（顶层）类，但可以修饰内部类。

### 2.2 `default`（无修饰符）

可见范围：本类 + **同包**。用于包内协作的工具类、辅助方法。

```java
class PackageUtil {
    static String formatDate(LocalDate date) {
        return date.format(DateTimeFormatter.ISO_LOCAL_DATE);
    }
}
```

### 2.3 `protected`

可见范围：本类 + 同包 + **子类（不同包）**。用于父类向子类暴露的扩展点。

```java
public abstract class AbstractHttpClient {
    protected String baseUrl;
    protected String buildUrl(String endpoint) { return baseUrl + endpoint; }
    protected abstract String doSend(String url);
}
```

> ⚠️ **易错点**：`protected` 在跨包子类中只能通过**继承关系**访问，不能通过父类引用访问。`default` 限定在**包内**，即使有继承关系，跨包子类也无法访问父类的 default 成员。

### 2.4 `public` —— 最宽松

可见范围：**所有类**。用于对外 API、接口定义。

```java
public interface UserService {
    UserDTO getUserById(Long id);
    Long createUser(CreateUserRequest request);
}
```

## 3. 访问控制范围对照表

| 修饰符 | 本类 | 同包 | 子类（不同包） | 任意类 |
|--------|:----:|:----:|:--------------:|:------:|
| `private` | Y | N | N | N |
| `default`（无修饰符） | Y | Y | N | N |
| `protected` | Y | Y | Y | N |
| `public` | Y | Y | Y | Y |

| 目标 | 可用修饰符 | 默认值 |
|------|-----------|--------|
| 外部类 | `public` / `default` | `default` |
| 内部类 | 全部四种 | `default` |
| 成员变量 / 方法 | 全部四种 | `default` |
| 接口方法 | `public`（JDK 9+ 支持 `private`） | `public` |
| 接口字段 | `public static final`（隐式） | `public` |

```java
public class AccessGuide {
    private Long id;                      // 字段优先 private
    public static final int MAX = 3;      // 常量 public
    public void doSomething() {}          // 对外 API
    void packageHelper() {}               // 包内工具
    protected void beforeProcess() {}     // 子类扩展点
}
```

## 4. 包（Package）与访问控制

包是 Java 的命名空间和访问控制的基本单元：
- **命名空间**：避免同名类冲突
- **访问控制边界**：`default` 作用域以包为边界
- **逻辑组织**：按模块/功能分层

```java
package com.example.user;                 // 包声明必须是文件第一行

public class User {
    private Long id;                      // 仅 User 类内部
    String internalNote;                  // 同包可见（default）
    protected String role;                // 同包 + 子类可见
    public String name;                   // 全局可见
}
```

## 5. Getter 与 Setter 最佳实践

### 5.1 Java Bean 规范

```java
public class UserBean {
    private Long id;
    private String username;
    private boolean active;               // boolean 用 isXxx()

    public UserBean() {}                  // 无参构造必须
    public Long getId() { return id; }
    public void setId(Long id) { this.id = id; }
    public String getUsername() { return username; }
    public void setUsername(String username) { this.username = username; }
    public boolean isActive() { return active; }
    public void setActive(boolean active) { this.active = active; }
}
```

### 5.2 Setter 中的验证逻辑

```java
public class Account {
    private Long id;
    private String accountNo;

    public void setId(Long id) {
        if (id == null || id <= 0) throw new IllegalArgumentException("ID 不合法");
        this.id = id;
    }

    public void setAccountNo(String accountNo) {
        if (!accountNo.matches("\\d{16,19}")) throw new IllegalArgumentException("格式错误");
        this.accountNo = accountNo;
    }
}
```

### 5.3 行为方法优于直接 Setter

```java
// 错误：暴露 setBalance 让外部随意修改
public class AccountBad {
    private BigDecimal balance;
    public void setBalance(BigDecimal b) { this.balance = b; }  // ❌
}

// 正确：业务行为方法代替 setter
public class AccountGood {
    private BigDecimal balance;

    public void deposit(BigDecimal amount) {
        if (amount.compareTo(BigDecimal.ZERO) <= 0) throw new IllegalArgumentException("金额必须为正数");
        this.balance = this.balance.add(amount);
    }

    public void withdraw(BigDecimal amount) {
        if (this.balance.compareTo(amount) < 0) throw new IllegalArgumentException("余额不足");
        this.balance = this.balance.subtract(amount);
    }

    public BigDecimal getBalance() { return balance; }    // 只读，不提供 setter
}
```

### 5.4 防御性拷贝

```java
public class Order {
    private List<OrderItem> items;

    public Order(List<OrderItem> items) {
        this.items = new ArrayList<>(items);              // 构造时防御拷贝
    }

    public List<OrderItem> getItems() {
        return Collections.unmodifiableList(items);       // 返回不可变视图
    }

    public void addItem(OrderItem item) { this.items.add(item); }
}
```

> 💡 防御性拷贝的两种场景：**构造时保护**（防止引用泄露进入）和 **getter 时保护**（防止引用泄露出去）。

## 6. 包结构设计原则

标准企业级后端包结构（Spring Boot）：

```
com.xxx
├── common                    # 通用模块（constant, exception, utils, enums）
├── user                      # 用户模块
│   ├── controller            # 控制层
│   ├── service               # 服务层 + impl 实现
│   ├── mapper                # 数据访问层
│   ├── entity                # 数据库实体
│   └── dto                   # 数据传输对象
├── order                     # 订单模块
└── config                    # 配置类
```

| 原则 | 说明 |
|------|------|
| **按业务模块分包** | `user`、`order` 而非按层分包 |
| **包内聚** | 紧密相关的类放在同一包下 |
| **避免循环依赖** | 包 A 依赖包 B，包 B 不能反过来依赖包 A |
| **最小可见性** | 包内工具类用 `default` 修饰，不对外暴露 |

> 🎯 **包设计口诀**：按模块分包，逐层依赖，避免循环，最小可见。

## 7. import 与静态导入

### 7.1 import 语法

```java
package com.example.service;
import java.util.List;
import java.util.*;               // 通配符导入，编译器处理，无运行时开销
```

> ⚠️ `import *` 不会导入子包的类。

### 7.2 静态导入

```java
import static java.lang.Math.PI;
import static java.lang.Math.sqrt;
import static java.util.Collections.*;

public class StaticImportDemo {
    public void demo() {
        double r = sqrt(16.0);              // 无需 Math.sqrt()
        double area = PI * r * r;
        List<String> list = emptyList();    // 相当于 Collections.emptyList()
    }
}
```

> ⚠️ 静态导入会降低可读性，仅在频繁使用同一类静态成员时使用（如 `import static org.junit.Assert.*`）。

### 7.3 冲突解决

```java
import java.util.Date;
// import java.sql.Date;                    // 冲突！

public class ImportConflict {
    private Date now = new Date();          // 使用 java.util.Date
    private java.sql.Date sqlDate =         // 全限定名避免冲突
        new java.sql.Date(System.currentTimeMillis());
}
```

## 8. 类的设计原则（SOLID 入门）

SOLID 是面向对象设计的五大原则，封装是这一切的基石。

| 原则 | 含义 | 一句话 |
|------|------|--------|
| **S**ingle Responsibility | 单一职责 | 一个类只干一件事 |
| **O**pen/Closed | 开闭原则 | 对扩展开放，对修改关闭 |
| **L**iskov Substitution | 里氏替换 | 子类必须能完全替换父类 |
| **I**nterface Segregation | 接口隔离 | 接口拆分得小而精 |
| **D**ependency Inversion | 依赖倒置 | 依赖抽象而非具体实现 |

```java
// SRP：拆分职责
public class OrderService { public void createOrder(Order o) { } }
public class EmailService { public void sendEmail(Order o) { } }

// OCP：多态扩展而非修改
public interface PaymentStrategy { void pay(BigDecimal amount); }
public class AlipayStrategy implements PaymentStrategy { }

// LSP：子类不能改变父类行为约定（正方形≠长方形）

// ISP：细粒度接口
interface Workable { void work(); }
interface Eatable { void eat(); }
class Robot implements Workable { public void work() { } }  // 无需 eat()

// DIP：依赖抽象
public interface MessageSender { void send(String msg); }
public class NotificationService {
    private final MessageSender sender;   // 依赖抽象
    public NotificationService(MessageSender sender) { this.sender = sender; }
}
```

## 9. 权限设计实战案例

```java
package com.example.bank;

/**
 * 银行账户 —— 完整封装示例
 * 字段全部 private，只暴露安全的行为方法
 */
public class BankAccount {
    private final String accountNo;          // 不可变
    private BigDecimal balance;
    private boolean frozen;

    public BankAccount(String accountNo, BigDecimal initialBalance) {
        if (initialBalance.compareTo(BigDecimal.ZERO) < 0)
            throw new IllegalArgumentException("初始余额不能为负数");
        this.accountNo = accountNo;
        this.balance = initialBalance;
    }

    // 脱敏 getter
    public String getMaskedAccountNo() {
        return accountNo.replaceAll("(\\d{4})\\d{8}(\\d{4})", "$1****$2");
    }

    public BigDecimal getBalance() { return balance; }

    // 业务行为方法 —— 替代直接 setter
    public void deposit(BigDecimal amount) {
        if (amount.compareTo(BigDecimal.ZERO) <= 0) throw new IllegalArgumentException("金额必须为正数");
        if (frozen) throw new IllegalStateException("账户已冻结");
        this.balance = this.balance.add(amount);
    }

    public void withdraw(BigDecimal amount) {
        if (frozen) throw new IllegalStateException("账户已冻结");
        if (this.balance.compareTo(amount) < 0) throw new IllegalArgumentException("余额不足");
        this.balance = this.balance.subtract(amount);
    }

    // 包内可见的管理方法
    void freeze() { this.frozen = true; }
    void unfreeze() { this.frozen = false; }
}
```

## 10. 常见封装反模式

| 反模式 | 问题 | 正确做法 |
|--------|------|----------|
| 直接暴露字段 | `public String name;` | 字段 private，提供 getter/setter |
| 返回内部引用 | `return this.items;` | 返回不可修改视图或防御性拷贝 |
| 全部提供 setter | 每个字段都提供 setter | 只暴露必要的，用行为方法替代 |
| 贫血模型 | 只有 getter/setter，无业务方法 | 将业务逻辑放入领域模型 |
| 过度暴露 API | 所有方法都 public | 包内方法用 default，继承用 protected |

```java
// ❌ 返回内部集合引用
public class Team {
    private List<String> members = new ArrayList<>();
    public List<String> getMembers() { return members; }   // 外部可 clear() 清空！
}

// ✅ 返回不可变视图
public class Team {
    private List<String> members = new ArrayList<>();
    public List<String> getMembers() { return Collections.unmodifiableList(members); }
    public void addMember(String name) { this.members.add(name); }
}
```

```java
// ❌ 贫血模型
public class CartItem {
    private BigDecimal price;
    private int quantity;
    // 只有 getter/setter，计算逻辑散落在各处
}
// ✅ 行为方法封装
public class CartItem {
    private BigDecimal price;
    private int quantity;
    public BigDecimal getSubtotal() { return price.multiply(BigDecimal.valueOf(quantity)); }
}
```

### 封装质量检查清单

- [ ] 所有字段是否都是 `private`？（常量除外）
- [ ] 是否暴露了不稳定的内部实现？
- [ ] getter 返回的是否是内部引用的副本/不可变视图？
- [ ] 是否用行为方法替代了直接 setter？
- [ ] 是否最小化了类和成员的访问权限？

> 🎯 **封装的核心**：隐藏变化，暴露契约。好的封装让调用方**无需知道**内部实现，也**无法破坏**内部状态。
