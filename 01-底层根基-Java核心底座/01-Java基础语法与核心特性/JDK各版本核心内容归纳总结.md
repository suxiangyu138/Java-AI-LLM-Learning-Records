# JDK各版本核心内容归纳总结
## 一、基础概念：命名规则 & 版本分类
### 1. 版本命名规范
1. **JDK1.0 ~ JDK1.8**：旧命名体系，完整格式 `JDK 1.x`，日常简称 JDK8（1.8）、JDK7（1.7）
2. **JDK9 及以后**：简化命名，直接数字编号 JDK9、11、17、21，不再带 `1.` 前缀

### 2. 两大版本分类（生产选型核心依据）
#### （1）LTS 长期支持版（企业生产唯一推荐）
- 发布周期：2~3年一版
- 官方支持周期：8年以上商业维护，安全补丁持续更新
- 优势：稳定、兼容性强、无频繁废弃API、生态适配完善
- 主流代表：JDK8、JDK11、JDK17、JDK21

#### （2）短期非LTS版本（仅用于体验新特性，禁止上线）
- 发布周期：每6个月一个小版本
- 支持周期：仅6个月，无长期安全更新
- 定位：实验性预览特性，成熟功能会下沉至下一个LTS
- 代表：JDK9/10、12~16、18~20

## 二、主流LTS版本核心特性、定位与适用场景
### 1. JDK 8（2014，史上经典LTS）
#### 核心新增特性
1. Lambda表达式 + 函数式接口
2. Stream流式处理集合
3. `Optional` 空指针安全工具类
4. 接口默认方法、静态接口方法
5. 新日期时间API `java.time`（LocalDateTime等，替代Date）
6. 重复注解、并行流、CompletableFuture异步工具
7. Metaspace元空间，永久代PermGen移除

#### 优缺点
- 优势：生态全覆盖，所有老旧框架、中间件完美兼容，教程资源最多
- 短板：无模块化、原生无轻量化GC、无内置HTTP客户端

#### 适用场景
老系统维护、老旧第三方组件项目、Java入门学习

### 2. JDK 11（2018，过渡型LTS）
#### 核心升级
1. 引入模块系统（JDK9铺垫，11完善落地）
2. 内置标准HTTP客户端 `java.net.http`
3. 局部变量类型推断 `var`
4. ZGC低延迟垃圾收集器（实验特性）
5. 彻底移除Java EE、CORBA、JAXB等内置模块
6. 单文件源码直接运行 `java xxx.java`
7. 废弃Applet、废弃部分老旧安全API

#### 优缺点
- 优势：体积精简、GC性能优于JDK8、自带HTTP工具、支持模块化
- 短板：部分老旧EE相关代码需额外引入依赖，生态适配弱于JDK8

#### 适用场景
JDK8老项目平滑升级、中小型微服务、对延迟有基础要求业务

### 3. JDK 17（2021，当前新项目主流LTS）
#### 核心升级
1. Oracle免费商用授权，无版权收费限制
2. 密封类Sealed Class，限制类继承范围
3. Switch表达式增强（支持返回值、yield）
4. Records记录类，快速创建数据载体类
5. 文本块 `""" """`，多行字符串免转义
6. ZGC正式稳定、G1GC优化，内存占用更低
7. 废弃大量过时API，删除Applet整套工具链

#### 优缺点
- 优势：免费商用、新语法大幅简化代码、GC性能优秀、稳定长期支持
- 短板：极古老框架存在少量兼容问题

#### 适用场景
全新微服务/分布式项目、中长期迭代业务、追求低延迟服务

### 4. JDK 21（2023，最新长期支持LTS）
#### 核心重磅特性
1. **虚拟线程 Virtual Threads**，轻量级并发，大幅简化异步/IO并发编程
2. 字符串模板，拼接字符串更安全简洁
3. 未命名变量、未命名模式匹配，简化冗余代码
4. ZGC持续优化，分代ZGC正式落地
5. 模式匹配增强、集合有序工厂方法优化

#### 优缺点
- 优势：并发能力革命性提升，高吞吐低延迟首选，语法最现代化
- 短板：部分老旧中间件适配滞后，学习成本略高

#### 适用场景
高并发IO服务、网关、消息消费、高性能分布式前沿项目

### 非LTS版本统一说明
JDK9/10、12~16、18~20均为过渡尝鲜版本：
- JDK9：模块化系统、JShell交互式控制台、私有接口方法
- JDK14~16：Record、文本块、模式匹配预览特性
仅做技术调研学习，**严禁部署线上生产环境**。

## 三、企业实战版本选型标准
### 1. 学习入门
首选 JDK8：资料最全，所有基础语法、主流框架基于8讲解，吃透后再升级17学习新特性。

### 2. 线上生产强制规则
1. 只允许LTS版本：8 / 11 / 17 / 21
2. 存量老系统（5年以上，依赖老旧组件）：维持 JDK8
3. 老系统平滑迭代升级：选择 JDK11
4. 全新开发项目、中长期业务：优先 JDK17
5. 高并发、高吞吐、低延迟IO密集服务：JDK21

### 3. 特殊场景选型
- 低延迟交易、网关、长连接服务：JDK17/21 启用ZGC
- 传统单体老旧项目、依赖过时第三方Jar：JDK8
- 云原生、轻量微服务：JDK11 / JDK17

## 四、面试高频核心总结
1. **LTS与非LTS核心区别**
LTS长期安全补丁、稳定、适合生产；短期版仅6个月支持，仅体验新特性，禁止上线。

2. 四大主流LTS定位
- JDK8：经典兼容款，老项目维护、入门学习
- JDK11：过渡精简款，8升级首选
- JDK17：免费商用，新项目通用最优解
- JDK21：虚拟线程，高并发高性能场景专用

3. 版本兼容逻辑
高版本LTS向下兼容JDK8核心API，但逐步移除老旧EE、CORBA等模块，升级需补充对应依赖。

4. 选型核心判断标准
不盲目追最新，优先匹配项目框架/中间件兼容性，其次根据业务并发、迭代周期选择LTS版本。
