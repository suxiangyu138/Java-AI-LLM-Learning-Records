# 泛型 反射 注解 面试问答

### Q1. 讲讲泛型擦除，Java 为什么要设计成擦除？

**口述答案**

泛型只在编译期存在。编译器检查完类型就把类型参数擦掉，无界擦成 Object，有界擦成第一个上界，需要的地方插入强制转换，所以 `List<String>` 和 `List<Integer>` 的 getClass 是同一个对象。

设计成擦除是为了兼容 Java 5 之前的字节码和类库，让新老代码能混跑。代价是运行时没有类型信息，不能 instanceof，不能 new T()，也不能 new T[]。C++ 模板走单态化，每个类型生成一份代码，运行时有完整类型信息，代价是代码膨胀，这是两种不同的取舍。

---

### Q2. 擦除之后，运行时还能拿到泛型信息吗？

**口述答案**

能拿到签名里保存的那部分。类、字段、方法的泛型签名会写进 class 文件的 Signature 属性，反射的 getGenericType 和 getGenericReturnType 读的就是它。

典型用法是匿名子类，new `TypeReference<List<User>>()` {}，父类构造器里通过 getGenericSuperclass 拿到 ParameterizedType，再取 actualTypeArguments，就还原出了 User。Jackson 的 TypeReference 和 Spring 的 ResolvableType 都是这个思路。拿不到的是局部变量和运行时对象，它们没有签名记录。

---

### Q3. `List<String>` 为什么不能传给 `List<Object>`？数组为什么可以？

**口述答案**

因为泛型是不变的，`List<String>` 和 `List<Object>` 之间没有继承关系，编译器直接拒绝。

如果允许，就能往这个 `List<Object>` 里塞一个 Integer，再通过原来的 `List<String>` 引用取出来，运行时必然抛 ClassCastException，编译期检查就失去了意义。数组是协变的，String[] 可以赋给 Object[]，但代价是运行时可能抛 ArrayStoreException。所以泛型用不变换编译期安全，数组用协变换使用灵活，方向正好相反。

---

### Q4. 通配符的 extends 和 super 分别适合什么场景？

**口述答案**

PECS 是 Producer Extends、Consumer Super。只读的集合当生产者，用 ? extends T，读出来至少能当 T 用，但写不进去，因为编译器不知道实际是哪个子类。

只写的集合当消费者，用 ? super T，写 T 及子类都安全，读出来只能当 Object。JDK 的 Collections.copy 就是标准写法，目标集合用 super，源集合用 extends，这也是集合工具类常见的方法签名。读写都要的场景就别用通配符，直接传具体类型，让调用方自己保证一致性，写通用工具类时这条尤其重要。

---

### Q5. 桥方法是什么？编译器为什么非要生成它？

**口述答案**

桥方法是编译器为了维持多态生成的转发方法。父类 `Box<T>` 的 get 擦除后是 Object get()，子类 StringBox 覆写的是 String get()。

如果只保留子类版本，通过父类引用调用时按 Object get() 去找，就找不到实现，多态断了。编译器于是在子类里生成桥方法，把 Object get() 转发到 String get()。javap 能看到它带 ACC_BRIDGE 和 ACC_SYNTHETIC 标志，源码里不存在，只能用反射的 isBridge 识别。只要子类把泛型父类的方法具体化并覆写，就会出现。

---

### Q6. 泛型为什么不能用基本类型？为什么不能 new T[]？

**口述答案**

类型参数擦除后要替换成 Object 或上界，基本类型不是 Object 的子类，没法参与替换，所以只能写 `List<Integer>`，自动装箱由编译器补上。

new T[] 不行的根因是数组创建需要运行时的元素类型做存储检查，擦除后 T 不可知。强转 (T[]) new Object[n] 能编译，但数组真实类型是 Object[]，存什么都不会报错，取出来才炸，这就是堆污染。更安全的做法是 Array.newInstance 带上 componentType，或者用 @SafeVarargs 标注只读的可变参数方法。

---

### Q7. 反射拿 Class 对象有几种方式？Class.forName 和 loadClass 有什么区别？

**口述答案**

三种：

- 类名点 class，编译期字面量，最安全
- getClass()，需要先有实例
- Class.forName()，用字符串加载，最灵活

关键差别在初始化时机。forName 会触发类的静态初始化，静态块会执行，所以 JDBC 驱动能把自己注册进 DriverManager。而 ClassLoader.loadClass 只加载不初始化，静态块不跑。框架里常见的是 forName 加反射，因为类名往往来自配置，编译期根本不知道。

---

### Q8. getMethod 和 getDeclaredMethod 有什么区别？反射怎么访问私有成员？

**口述答案**

getMethod 只返回 public 方法，而且包含从父类继承来的。getDeclaredMethod 返回本类声明的全部方法，包括 private，但不包含继承的。字段同理。

所以访问私有成员必须用 declared 系列，再配合 setAccessible(true)。另外 Class.newInstance 已经废弃，它把构造器抛出的受检异常原样抛出、不包装，而且只能调无参构造，应该改用 getDeclaredConstructor().newInstance()。这两个方法名只差一个单词，面试里经常故意混着问。

---

### Q9. 反射调用为什么比直接调用慢？你们怎么优化？

**口述答案**

慢在四个地方：

- 方法查找，每次 getMethod 都要按名字和参数类型搜索
- 访问检查，每次 invoke 都要判断可见性
- 无法内联，普通调用 JIT 能直接内联，反射要走 MethodAccessor 委派，调用链长
- 参数装箱和数组分配，invoke 每次都要建 Object 数组

优化按收益排序：缓存 Method 和 Field 对象，setAccessible(true) 跳过语言检查，高频路径改用 MethodHandle，极致场景用 LambdaMetafactory 生成函数式接口。缓存是最有效的一步，Spring 和 MyBatis 都这么干。

---

### Q10. setAccessible 到底做了什么？JDK 17 之后还能用吗？

**口述答案**

它设置的是 override 标志，让反射调用跳过 Java 语言的访问检查，private 成员也能读写。它不是破解，只是绕过了编译器层面的可见性规则。

JDK 9 引入模块系统后，跨模块反射非 public 成员会被拒绝，需要加 --add-opens 启动参数，同一个模块内部仍然可用。另外 SecurityManager 在 JDK 17 弃用、JDK 24 永久禁用，访问控制现在由模块系统承担，跨模块场景要额外配置模块开放。网上说 JDK 17 之后不能反射私有成员，是误传。

---

### Q11. JDK 动态代理和 CGLIB 有什么区别？Spring 怎么选？

**口述答案**

JDK 代理要求目标类实现接口，运行时生成实现同一组接口的代理类，所有调用转发给 InvocationHandler。

CGLIB 生成目标类的子类，覆写方法插拦截逻辑，所以不要求接口，但类和方法不能是 final。Spring AOP 的规则是，目标类实现了接口且 proxyTargetClass 为 false 就用 JDK，否则用 CGLIB。Spring Boot 2.x 起默认 proxyTargetClass 为 true，也就是默认走 CGLIB，好处是不强制接口，代价是 final 类没法代理。

---

### Q12. 注解的本质是什么？元注解有哪些？

**口述答案**

注解是一个特殊的接口，用 @interface 声明，编译后隐式继承 java.lang.annotation.Annotation。它没有实现类，不能 new，运行时由 JVM 生成动态代理对象来承载数据。

属性返回类型受限，只能是基本类型、String、Class、枚举、注解以及它们的数组，因为数据要直接写进 class 文件的常量池。元注解常用的有五个：Retention 管保留阶段，Target 管能修饰谁，Documented 管文档，Inherited 管子类继承，Repeatable 管重复标注。

---

### Q13. @Retention 三个级别有什么区别？默认是哪个？

**口述答案**

SOURCE 只保留在源码，编译就丢，@Override 这种给编译器看的注解用它。CLASS 保留到字节码但运行时不加载，是默认级别，很多人误以为默认是 RUNTIME，这是高频误区。

RUNTIME 保留到运行时，能通过反射读出来。默认值是 CLASS 这一点，面试里经常被当作陷阱题。判断标准很简单：运行时要靠反射读就必须标 RUNTIME，Spring、MyBatis、Jackson 的注解都是这个级别。只给编译器或 APT 看，用 SOURCE 或 CLASS 就够，还能减小 class 文件体积。

---

### Q14. 自己写的注解为什么不生效？怎么排查？

**口述答案**

最常见的原因是 Retention 没写 RUNTIME，注解在运行时根本不存在，反射读不到。另外两种常见情况：

- 没有处理器，注解只是数据，没人读就等于注释，得写切面、拦截器或者扫描器去读
- Target 写错，标在了不支持的元素上

排查按这三步倒着查：先看 Retention，再看有没有读取方，最后看 Target。切点写错或者切面没被 Spring 扫描到，也会表现成不生效，那属于配置问题，不是注解本身的问题。实际排查时先用断点确认注解有没有被读到，再往上找读取方。

---

### Q15. Lombok 是怎么在编译期生成方法的？为什么说它不是标准 APT？

**口述答案**

标准 APT 的处理器只能生成新文件，不能修改已有的类，这是 Processor API 的硬限制。

Lombok 绕过这套 API，直接操作 javac 的抽象语法树，在编译过程中往原类里插入 getter、setter、构造器，所以才能在同一个类上长出方法。代价是强依赖编译器内部实现，JDK 升级或者换编译器容易出问题，团队里经常因为 Lombok 和 JDK 版本不匹配编译失败。MapStruct、Dagger 走的是标准路线，编译期生成实现类，稳定得多。

---

### Q16. @Inherited 和组合注解，Spring 是怎么处理的？

**口述答案**

@Inherited 只在类继承时生效：

- 父类标了注解，子类能通过 getAnnotation 拿到
- 接口上标了，实现类拿不到
- 方法上的注解不会因为覆写而继承

组合注解是 Spring 大量使用的技巧，@SpringBootApplication 本身就是三个注解的组合。但 getAnnotation 拿不到被组合的注解，因为它只查直接标注，要递归查元注记得用 MergedAnnotations 或者 AnnotatedElementUtils.findMergedAnnotation。

---

### Q17. @Autowired 的注入过程说一遍？

**口述答案**

注解标记位置，反射完成查找和赋值，泛型决定按什么类型匹配。

启动时扫描器用 ASM 读字节码找 @Component，只登记 BeanDefinition，不加载类。实例化时反射调构造器。属性填充时 AutowiredAnnotationBeanPostProcessor 反射扫描字段上的 @Autowired，按类型匹配候选 Bean。遇到 `List<UserDao>` 这种泛型注入点，用 ResolvableType 解析出实际类型参数，最后 Field.set 写入。同名多个候选时再按名称兜底，这就是 @Qualifier 的用武之地。

---

### Q18. MyBatis 的 Mapper 接口没有实现类，为什么能直接调用？

**口述答案**

因为它拿到的是动态代理对象。启动时 MyBatis 扫描 @Mapper 接口，解析注解或 XML 生成 MappedStatement。

MapperProxyFactory 用 Proxy.newProxyInstance 创建代理，MapperProxy 实现 InvocationHandler。调用方法时进入 invoke，按方法找到 MappedStatement，绑定参数执行 JDBC。结果映射时用 getGenericReturnType 拿到 `List<User>` 里的 User，反射创建对象逐字段赋值。注解提供 SQL 元数据，动态代理解释接口方法，这是框架最经典的一套组合。

---

### Q19. @Transactional 在哪些情况下会失效？

**口述答案**

因为它靠 AOP 代理生效，代理没生效或者拦不到，事务就不存在。常见四种：

- 类内自调用，this 调用不走代理
- 方法不可代理，private、static、final 方法 CGLIB 覆写不了
- 异常类型不匹配，默认只对 RuntimeException 和 Error 回滚，受检异常要配 rollbackFor
- 对象不是 Spring Bean，自己 new 出来的没有代理

排查先看调用是否走了代理对象，再看方法修饰符，最后确认异常类型有没有命中回滚规则。同类调用即使加了注解也不会新开事务。

---

### Q20. 如果让你设计一个接口限流注解，你会怎么做？

**口述答案**

分三层。注解层定义 @RateLimit，属性包括限流维度（接口、用户、IP）、阈值、时间窗口和降级提示，Retention 设 RUNTIME，Target 设 METHOD。

切面层用 @Around 拦截带注解的方法，从请求上下文取维度值，拼出 Redis key。存储层用 Lua 脚本做原子计数，key 带过期时间，避免并发下先读后写。关键取舍是分布式限流必须走 Redis 原子操作，本地 Guava 只能做单机限流。另外要处理 Redis 故障时的降级，宁可放行也不能把接口全部打挂。
