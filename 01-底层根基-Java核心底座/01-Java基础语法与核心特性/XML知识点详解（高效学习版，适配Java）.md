# XML知识点详解（高效学习版，适配Java）
XML（可扩展标记语言，Extensible Markup Language）是用于存储、传输结构化数据的标记语言，核心定位：**描述数据，而非展示数据**，和HTML有本质区别。
Java开发中XML大量用于框架配置（Spring/MyBatis/web.xml）、老旧项目跨系统数据交互，是后端必备基础。
学习思路：吃透强制语法规则 → 分清核心组成 → 结合Java框架场景理解 → 熟悉主流解析方案。

## 一、XML核心基础（必懂前提）
### 1. 定义与核心作用
- 定义：W3C制定纯文本标记语言，支持自定义标签，通过层级标签描述数据结构与语义。
- 三大核心用途
  1. 数据存储：项目配置、结构化业务数据（用户、商品）；
  2. 跨平台数据传输：异构系统、不同编程语言之间交换数据；
  3. 语义化描述：标签天然形成父子层级，可读性强，机器易解析。

### 2. XML vs HTML（高频区分考点）
| 维度 | XML | HTML |
|------|-----|------|
| 核心目标 | 描述数据、承载语义 | 展示页面、渲染样式 |
| 标签规则 | 全部自定义，无固定标签 | 标签固定（div/p/span等） |
| 语法约束 | 极其严格，错一处直接解析失败 | 容错性高，标签漏闭合仍可渲染 |
| 大小写 | 区分大小写 | 不区分大小写 |

### 3. XML四大核心特性
1. **可扩展**：按需自定义`<student>`、`<user>`等业务标签，无内置固定词汇；
2. **平台无关**：纯文本文件，Windows/Linux/macOS通用，Java/Python均可解析；
3. **层级结构化**：标签嵌套形成树状父子结构，关系清晰；
4. **人机可读**：文本直观，同时适配程序DOM/SAX解析。

## 二、XML强制语法规则（重中之重）
任意规则违规都会直接解析失败，逐条记忆搭配示例理解。
### 完整标准XML示例
```xml
<?xml version="1.0" encoding="UTF-8"?>
<students>
    <student id="1">
        <name>张三</name>
        <age>18</age>
        <gender>男</gender>
    </student>
    <student id="2">
        <name>李四</name>
        <age>19</age>
        <gender>女</gender>
    </student>
</students>
```

### 1. 文档声明
必须放在**文件第一行**，声明前不能有空格、换行、注释。
格式：
```xml
<?xml version="版本" encoding="编码"?>
```
- `version`：必填，主流使用`1.0`；
- `encoding`：推荐统一写`UTF-8`，解决中文乱码；

### 2. 元素（标签）规则
1. 成对闭合：开始标签`<xxx>`必须匹配结束标签`</xxx>`；
2. 空标签简写：无内容标签可单标签闭合 `<address/>`；
3. 严格区分大小写：`<Student>` 和 `<student>` 是两个完全不同标签；
4. 命名限制：不能数字/符号开头、不能包含空格、`& < > " '` 等特殊符号。

### 3. 属性规则
1. 依附于标签，格式：`<标签 属性名="值">`，值必须用单/双引号包裹；
2. 同一个标签**不能存在同名属性**；
3. 属性文本内不能直接写`< & >`特殊字符，需转义或改用CDATA。

### 4. 层级嵌套规则
1. 标签嵌套必须完整，禁止交叉：错误示例 `<a><b></a></b>`；
2. 全局仅允许**唯一根标签**，所有内容全部包裹在根标签内。

### 5. 转义字符（必背）
`<`/`&`等字符为XML语法关键字，文本中使用必须替换转义符：
| 原符号 | 转义字符 | 含义 |
|--------|----------|------|
| `<`    | `&lt;`   | 小于号 |
| `>`    | `&gt;`   | 大于号 |
| `&`    | `&amp;`  | 和号 |
| `"`    | `&quot;` | 双引号 |
| `'`    | `&apos;` | 单引号 |

示例：文本 `a<b&c` 需写成 `a&lt;b&amp;c`

### 6. 注释规则
格式：`<!-- 注释内容 -->`
- 禁止嵌套注释；
- 不能写在文档声明上方。

## 三、XML四大核心组成（Java开发高频使用）
### 1. 元素（核心载体）
分为三类：
- 根元素：全局唯一顶层标签；
- 父/子元素：存在嵌套关系；
- 叶子元素：无内部子标签，仅存放文本。

### 2. 属性
用于存放标签简短附属标识（id、type）；
最佳实践：**简单标识用属性，完整结构化数据用子元素**。
反例（不推荐）：`<student id="1" name="张三" age="18"/>`
规范写法：
```xml
<student id="1">
    <name>张三</name>
    <age>18</age>
</student>
```

### 3. 文本内容
起始、结束标签中间的纯文本，是业务数据主体，特殊字符必须转义。

### 4. CDATA区块（实战高频）
适用场景：存放大量含`< > &`的文本、Java代码、SQL语句，无需逐个转义。
格式：`<![CDATA[ 原始文本 ]]>`
示例：
```xml
<code>
<![CDATA[
public void test(){
    if(1 < 2 && 3 > 1){
        System.out.println("XML Test");
    }
}
]]>
</code>
```

## 四、XML在Java开发中的实战场景
### 1. 主流框架配置（最常用）
1. Spring XML配置
```xml
<bean id="userService" class="com.service.UserServiceImpl"/>
```
2. MyBatis Mapper映射文件
```xml
<mapper namespace="com.mapper.UserMapper">
    <select id="getById" resultType="com.pojo.User">
        select * from user where id = #{id}
    </select>
</mapper>
```
3. JavaWeb 传统项目 `web.xml`
```xml
<servlet>
    <servlet-name>UserServlet</servlet-name>
    <servlet-class>com.servlet.UserServlet</servlet-class>
</servlet>
```

### 2. 跨系统数据传输
传统接口使用XML报文交互示例：
```xml
<?xml version="1.0" encoding="UTF-8"?>
<resp>
    <code>200</code>
    <msg>success</msg>
    <data>
        <id>1</id>
        <name>张三</name>
    </data>
</resp>
```

### 3. Java三种XML解析方案（面试基础考点）
1. **DOM**
   一次性加载全文档到内存，生成完整树；支持增删改查；适合小体积XML，大文件内存占用高。
2. **SAX**
   流式逐行读取，不加载整份文档；仅支持查询，无法修改；适配超大XML文件。
3. **DOM4J（企业首选）**
   第三方开源工具，融合DOM易用性与SAX低内存优势，API简洁，框架底层大量使用，开发优先选用。

## 五、高效学习技巧 & 高频避坑点
### 1. 学习步骤
1. 先手写简单XML，保证无语法报错，吃透标签、属性、CDATA、转义；
2. 阅读Spring/MyBatis官方XML配置，理解业务场景用法；
3. 简单使用DOM4J实现XML读取、写入。

### 2. 高频错误避坑
1. 中文乱码：未加 `encoding="UTF-8"` 或文件保存编码不匹配；
2. 解析报错：标签漏闭合、大小写混用、交叉嵌套、属性值无引号；
3. 特殊字符报错：未转义`< &`，大批量代码直接套CDATA；
4. 结构混乱：大量复杂业务数据全部塞到属性中。

## 六、总结
1. XML核心定位：结构化数据描述语言，语法严格，自定义标签；
2. 核心区分：XML存数据，HTML做页面展示；
3. 开发价值：Spring/MyBatis等主流框架核心配置格式，老旧项目接口报文标准；
4. 开发规范：短标识用属性，复杂数据用子元素；含代码/SQL优先CDATA；统一UTF-8编码；
5. 解析选型：小型配置文件用DOM4J，超大文件使用SAX。
