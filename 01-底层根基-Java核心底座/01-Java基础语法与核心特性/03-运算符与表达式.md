## 1. 运算符分类总览

Java 的运算符按功能可分为以下六大类：

| 分类 | 运算符 | 用途 |
|------|--------|------|
| 算术运算符 | `+` `-` `*` `/` `%` `++` `--` | 数学计算 |
| 赋值运算符 | `=` `+=` `-=` `*=` `/=` `%=` `&=` `\|=` `^=` `<<=` `>>=` `>>>=` | 赋值与复合赋值 |
| 关系运算符 | `==` `!=` `>` `<` `>=` `<=` | 比较大小/相等 |
| 逻辑运算符 | `&&` `\|\|` `!` `&` `\|` `^` | 布尔逻辑运算 |
| 位运算符 | `&` `\|` `^` `~` `<<` `>>` `>>>` | 二进制位操作 |
| 三元运算符 | `? :` | 条件表达式 |

> 此外还有 `instanceof` 类型检查运算符、`->` Lambda 箭头运算符（JDK 8+）、`::` 方法引用运算符（JDK 8+）等特殊运算符。

## 2. 算术运算符

### 2.1 基本算术

| 运算符 | 描述 | 示例 | 结果 |
|--------|------|------|------|
| `+` | 加法 / 字符串连接 | `5 + 3` | `8` |
| `-` | 减法 | `5 - 3` | `2` |
| `*` | 乘法 | `5 * 3` | `15` |
| `/` | 除法（整数截断 / 浮点精确） | `7 / 3` | `2`（整数除法） |
| `%` | 取模（余数） | `7 % 3` | `1` |

```java
// 整数除法与浮点除法的区别
System.out.println(5 / 2);      // 2（截断小数，不是四舍五入）
System.out.println(5 / 2.0);    // 2.5（浮点数除法）
System.out.println(5.0 / 2);    // 2.5

// 取模运算
System.out.println(7 % 3);      // 1
System.out.println(-7 % 3);     // -1（结果的符号与被除数相同）
System.out.println(7 % -3);     // 1
```

### 2.2 自增与自减

| 运算符 | 名称 | 说明 |
|--------|------|------|
| `++i` | 前缀自增 | 先加 1，再取表达式的值 |
| `i++` | 后缀自增 | 先取表达式的值，再加 1 |
| `--i` | 前缀自减 | 先减 1，再取表达式的值 |
| `i--` | 后缀自减 | 先取表达式的值，再减 1 |

```java
// 前缀 vs 后缀的关键区别
int i = 1;
int a = i++;    // a = 1, i = 2（先赋值再加）
int b = ++i;    // b = 3, i = 3（先加再赋值）

// 复杂表达式中的执行顺序
int x = 1;
int y = 2;
int z = x++ + ++y;  // x++ 取值 1 后 x 变为 2，++y 先变为 3 再取值 3
System.out.println(z); // 4

// 经典陷阱：连续自增
int n = 0;
// n = n++;  // n 最终为 0（先用 n=0 赋值，再自增但结果被覆盖）
```

### 2.3 字符串连接运算符（+）

Java 中 `+` 被重载用于字符串连接，这是 Java 唯一支持运算符重载的场景。

```java
// 左结合规则：从左向右依次计算
System.out.println(1 + 2 + "3");    // "33"（1+2=3，再+"3"="33"）
System.out.println("1" + 2 + 3);    // "123"（"1"+2="12"，再+3="123"）
System.out.println("1" + (2 + 3));  // "15"（括号优先，先算 2+3=5）

// 字符串连接中自动类型转换
String s = "值 = " + 42;            // "值 = 42"
String t = "布尔 = " + true;        // "布尔 = true"

// 编译器优化：字面量连接直接合并
String c = "Hello" + " " + "World"; // 编译时直接优化为 "Hello World"
```

> 💡 循环中大量字符串拼接应使用 `StringBuilder`，而非 `+` 运算符，否则会创建大量临时 String 对象。

> ⚠️ 浮点数运算存在精度问题：`0.1 + 0.2` 的结果是 `0.30000000000000004`，而非精确的 `0.3`。金融计算必须使用 `BigDecimal`。

## 3. 赋值运算符

### 3.1 基本赋值运算符

| 运算符 | 描述 | 示例 | 等价于 |
|--------|------|------|--------|
| `=` | 赋值 | `x = 5` | — |
| `+=` | 加后赋值 | `x += 3` | `x = x + 3` |
| `-=` | 减后赋值 | `x -= 3` | `x = x - 3` |
| `*=` | 乘后赋值 | `x *= 3` | `x = x * 3` |
| `/=` | 除后赋值 | `x /= 3` | `x = x / 3` |
| `%=` | 取模后赋值 | `x %= 3` | `x = x % 3` |
| `&=` | 按位与后赋值 | `x &= 3` | `x = x & 3` |
| `\|=` | 按位或后赋值 | `x \|= 3` | `x = x \| 3` |
| `^=` | 按位异或后赋值 | `x ^= 3` | `x = x ^ 3` |
| `<<=` | 左移后赋值 | `x <<= 2` | `x = x << 2` |
| `>>=` | 右移后赋值 | `x >>= 2` | `x = x >> 2` |
| `>>>=` | 无符号右移后赋值 | `x >>>= 2` | `x = x >>> 2` |

### 3.2 复合赋值的隐藏类型转换

复合赋值运算符隐含了强制类型转换，这是它们与普通赋值的关键区别。

```java
// 复合赋值隐含类型转换
byte b = 1;
// b = b + 1;   // 编译错误：int 不能隐式转为 byte
b += 1;          // 等价于 b = (byte)(b + 1)，编译通过

int i = 5;
i *= 3.5;        // 等价于 i = (int)(i * 3.5)，结果为 17（截断小数）

// 链式赋值
int x, y, z;
x = y = z = 10;  // 从右向左结合：z=10, y=z, x=y
```

> 💡 复合赋值运算符不仅代码更简洁，还自带类型转换，在处理 `byte`/`short`/`char` 类型时特别有用。

## 4. 关系运算符

关系运算符的结果类型为 `boolean`（`true` 或 `false`）。

| 运算符 | 描述 | 示例 | 结果 |
|--------|------|------|------|
| `==` | 等于 | `5 == 3` | `false` |
| `!=` | 不等于 | `5 != 3` | `true` |
| `>` | 大于 | `5 > 3` | `true` |
| `<` | 小于 | `5 < 3` | `false` |
| `>=` | 大于等于 | `5 >= 5` | `true` |
| `<=` | 小于等于 | `5 <= 3` | `false` |

```java
// 基本类型比较：比较值
int a = 10, b = 10;
System.out.println(a == b);  // true

// 引用类型比较：== 比较的是引用地址，而非内容
String s1 = new String("hello");
String s2 = new String("hello");
System.out.println(s1 == s2);        // false（不同对象，不同引用地址）
System.out.println(s1.equals(s2));   // true（内容相同）

// Integer 缓存陷阱
Integer i1 = 127;
Integer i2 = 127;
System.out.println(i1 == i2);        // true（从缓存 -128~127 取同一个对象）

Integer i3 = 128;
Integer i4 = 128;
System.out.println(i3 == i4);        // false（超出缓存范围，创建了新对象）

// 浮点数比较：避免直接使用 ==
double d1 = 0.1 + 0.2;
double d2 = 0.3;
System.out.println(d1 == d2);        // false（浮点数精度问题）
// 推荐用差值比较
double epsilon = 1e-10;
System.out.println(Math.abs(d1 - d2) < epsilon); // true
```

> ⚠️ 比较包装类型时，应始终使用 `equals()` 而非 `==`，除非你确定值在缓存范围内且明白引用比较的含义。`null` 值拆箱会导致 `NullPointerException`。

## 5. 逻辑运算符

### 5.1 逻辑运算符总览

| 运算符 | 描述 | 示例 | 说明 |
|--------|------|------|------|
| `&&` | 短路与 | `a && b` | `a` 为 `false` 时不再计算 `b` |
| `\|\|` | 短路或 | `a \|\| b` | `a` 为 `true` 时不再计算 `b` |
| `!` | 逻辑非 | `!a` | 取反 |
| `&` | 非短路与 | `a & b` | 无论 `a` 的值如何都计算 `b` |
| `\|` | 非短路或 | `a \| b` | 无论 `a` 的值如何都计算 `b` |
| `^` | 逻辑异或 | `a ^ b` | 相同为 `false`，不同为 `true` |

### 5.2 短路运算（&& 和 ||）

短路运算可以避免不必要的计算和潜在的异常，是实际开发中最常用的逻辑运算符。

```java
// ★ 短路避免 NullPointerException
String str = null;
if (str != null && str.length() > 0) {  // 安全：str=null 时短路，不执行 str.length()
    System.out.println("非空字符串");
}

// 对比：非短路 & 会抛异常
// if (str != null & str.length() > 0) {  // NullPointerException！
// }

// 短路或的典型应用
if (isValid(input) || logWarning(input)) {
    // isValid 返回 true 时，logWarning 不会被执行
}

// 短路与的链式调用
boolean success = validate(input) && saveToDb(input) && sendNotify(input);
// 只要前一个操作失败，后续操作就不会执行
```

### 5.3 逻辑异或（^）

```java
// 逻辑异或：两边不同则为 true
System.out.println(true ^ true);    // false
System.out.println(true ^ false);   // true
System.out.println(false ^ true);   // true
System.out.println(false ^ false);  // false

// 实用技巧：不使用临时变量交换布尔值（实际不常用）
boolean a = true, b = false;
a = a ^ b;
b = a ^ b;
a = a ^ b;
System.out.println(a + ", " + b);  // false, true
```

### 5.4 逻辑运算真值表

| a | b | `a && b` | `a \|\| b` | `a & b` | `a \| b` | `a ^ b` | `!a` |
|:-:|:-:|:--------:|:----------:|:-------:|:--------:|:-------:|:----:|
| F | F | F | F | F | F | F | T |
| F | T | F | T | F | T | T | T |
| T | F | F | T | F | T | T | F |
| T | T | T | T | T | T | F | F |

> 💡 日常开发应优先使用 `&&` 和 `||`（短路运算），它们更高效且能利用短路特性做前置条件检查。`&` 和 `|` 作为逻辑运算符很少使用，它们的主要用途是位运算。

## 6. 位运算符

位运算符直接操作整型数据的二进制位，适用于底层编程、权限控制、性能优化等场景。

### 6.1 按位逻辑运算

| 运算符 | 描述 | 示例 | 二进制 | 结果 |
|--------|------|------|--------|------|
| `&` | 按位与 | `5 & 3` | `0101 & 0011` | `0001`（1） |
| `\|` | 按位或 | `5 \| 3` | `0101 \| 0011` | `0111`（7） |
| `^` | 按位异或 | `5 ^ 3` | `0101 ^ 0011` | `0110`（6） |
| `~` | 按位取反 | `~5` | `~0101` | `1010`（-6，补码） |

```java
// 按位与：常用作掩码操作
int flag = 0b1100;       // 二进制：1100
int mask = 0b0100;       // 二进制：0100
boolean hasPermission = (flag & mask) != 0;  // true（检查第 3 位）

// 按位或：用于设置位
int newFlag = flag | 0b0011;  // 结果：1111

// 按位异或：相同为 0，不同为 1
int a = 5, b = 3;
a ^= b;
b ^= a;
a ^= b;
System.out.println(a);  // 3（交换成功，但实际不推荐此用法）
System.out.println(b);  // 5
```

### 6.2 移位运算

| 运算符 | 描述 | 示例 | 结果 | 说明 |
|--------|------|------|------|------|
| `<<` | 左移 | `5 << 2` | `20`（`5 * 4`） | 低位补 0，相当于乘以 2ⁿ |
| `>>` | 算术右移（符号位填充） | `-5 >> 2` | `-2` | 高位补符号位，相当于除以 2ⁿ |
| `>>>` | 无符号右移（零填充） | `-5 >>> 2` | `1073741822` | 高位补 0，结果总为正 |

```java
// 左移：低位补 0，相当于乘以 2^n
System.out.println(5 << 2);   // 20（5 * 4 = 20）
System.out.println(-5 << 2);  // -20

// 算术右移：高位补符号位，相当于除以 2^n 后向下取整
System.out.println(16 >> 3);  // 2（16 / 8 = 2）
System.out.println(-16 >> 3); // -2
System.out.println(-15 >> 3); // -3（向下取整）

// 无符号右移：高位补 0，负数会变成很大的正数
System.out.println(16 >>> 3);       // 2
System.out.println(-1 >>> 1);       // 2147483647（Integer.MAX_VALUE）

// 移位运算的边界：只对低 5 位有效（int 类型）
System.out.println(5 << 32);        // 5（等价于 5 << 0）
System.out.println(5 << 33);        // 10（等价于 5 << 1，33 & 0x1f = 1）
```

### 6.3 位运算高效技巧

```java
// 1. 用移位替代乘除 2 的幂（性能更高）
int x = 100;
int times4   = x << 2;      // 100 * 4 = 400
int divide8  = x >> 3;      // 100 / 8 = 12
int times10  = (x << 3) + (x << 1);  // 100 * 8 + 100 * 2 = 100 * 10

// 2. 判断奇偶（比 % 2 更快）
boolean isOdd = (n & 1) == 1;

// 3. 取模 2 的幂（HashMap 的核心优化）
int hash = 15;
int size = 16;
int index = hash & (size - 1);  // 等价于 hash % 16，但位运算更快

// 4. 判断 2 的幂
boolean isPowerOfTwo = (n > 0) && (n & (n - 1)) == 0;

// 5. 取绝对值
int abs = (n ^ (n >> 31)) - (n >> 31);

// 6. 获取 int 中的某个字节
int value = 0xAABBCCDD;
byte b0 = (byte) (value);           // DD
byte b1 = (byte) (value >> 8);      // CC
byte b2 = (byte) (value >> 16);     // BB
byte b3 = (byte) (value >> 24);     // AA
```

> ⚠️ 移位运算符的右操作数只有低 5 位有效（`int` 类型）或低 6 位有效（`long` 类型）。例如 `5 << 33` 实际等价于 `5 << (33 & 0x1f) = 5 << 1`。

> 💡 位运算非常高效，但过度使用会降低代码可读性。在非性能敏感场景中，使用语义清晰的算术运算和工具方法。

## 7. 三元运算符

### 7.1 基本用法

```java
// 语法：condition ? 表达式1 : 表达式2
// 如果 condition 为 true，返回表达式1的值，否则返回表达式2的值

int a = 10, b = 20;
int max = (a > b) ? a : b;  // max = 20

// 三元运算符可以作为表达式直接放入其他语句
System.out.println(score >= 60 ? "及格" : "不及格");
```

### 7.2 嵌套与可读性

```java
// 嵌套三元（可读性差，不推荐）
int result = (a > b) ? ((a > c) ? a : c) : ((b > c) ? b : c);

// 推荐方式：拆分逻辑
int max;
if (a > b) {
    max = (a > c) ? a : c;
} else {
    max = (b > c) ? b : c;
}
```

> 阿里巴巴规范：三元运算符嵌套不要超过 3 层，超过时用 `if-else` 替代。

### 7.3 类型一致性

```java
// 两个表达式类型必须一致或兼容
int x = 5;
double y = 3.0;
// 结果类型会自动提升
Number result = (x > 0) ? x : y;    // 结果为 double 类型 5.0

// null 与包装类型的陷阱
Integer val = (condition) ? 1 : null;  // null 可以自动拆箱？不会 NPE 吗？
// 实际：Integer 类型可以接受 null
Object obj = (condition) ? new Object() : null;  // 安全
```

## 8. instanceof 运算符

### 8.1 传统用法

`instanceof` 用于检查对象是否为某个类（或接口、超类、超接口）的实例。

| 表达式 | 结果 |
|--------|------|
| `"hello" instanceof String` | `true` |
| `null instanceof String` | `false` |
| `new ArrayList() instanceof List` | `true` |
| `new ArrayList() instanceof RandomAccess` | `true` |

```java
Object obj = "Hello, Java!";

// 传统方式：先判断类型，再强制转换
if (obj instanceof String) {
    String s = (String) obj;          // 显式强制转换
    System.out.println(s.length());
}

// instanceof 检查 null 时返回 false（不会抛异常）
String str = null;
System.out.println(str instanceof String);  // false

// 向下转型前的安全检查
Animal animal = new Dog("旺财");
if (animal instanceof Dog) {          // true
    Dog dog = (Dog) animal;           // 安全向下转型
    dog.bark();
}
```

### 8.2 JDK 16+ 模式匹配（Pattern Matching）

```java
// JDK 16+：类型判断后直接声明变量，省去显式强转
if (obj instanceof String s) {
    System.out.println(s.length());   // 直接使用变量 s
}

// 更复杂的条件组合
if (obj instanceof String s && s.length() > 5) {
    System.out.println(s.toUpperCase());
}

// JDK 17+ switch 模式匹配 + 守卫
Object value = "Hello";
String result = switch (value) {
    case Integer i when i > 0 -> "正整数: " + i;
    case Integer i            -> "非正整数: " + i;
    case String s             -> "字符串长度: " + s.length();
    case null                 -> "null 值";
    default                   -> "未知类型: " + value;
};

// 泛型中的 instanceof：由于类型擦除，不能直接检查泛型类型
// if (list instanceof ArrayList<String>) { }  // 编译错误
// 只能检查原始类型
if (list instanceof ArrayList) { }  // 正确
```

> 🎯 `instanceof` 模式匹配减少了冗长的类型检查和强制转换代码，使代码更简洁、更安全。这是 Java 迈向更表达性语言的重要改进。

## 9. 运算符优先级完整表

当多个运算符出现在同一个表达式中时，优先级决定了运算顺序。下表按优先级从高到低排列。

| 优先级 | 分类 | 运算符 | 结合性 |
|:------:|:----:|:------:|:-------:|
| 1（最高） | 括号/成员访问 | `()` `[]` `.` `::` | 左→右 |
| 2 | 一元后缀 | `expr++` `expr--` | 左→右 |
| 3 | 一元前缀 | `++expr` `--expr` `+expr` `-expr` `~` `!` | 右→左 |
| 4 | 创建/转型 | `new` `(type)` | 右→左 |
| 5 | 乘除 | `*` `/` `%` | 左→右 |
| 6 | 加减 | `+` `-` | 左→右 |
| 7 | 移位 | `<<` `>>` `>>>` | 左→右 |
| 8 | 关系 | `<` `<=` `>` `>=` `instanceof` | 左→右 |
| 9 | 相等 | `==` `!=` | 左→右 |
| 10 | 按位与 | `&` | 左→右 |
| 11 | 按位异或 | `^` | 左→右 |
| 12 | 按位或 | `\|` | 左→右 |
| 13 | 逻辑与 | `&&` | 左→右 |
| 14 | 逻辑或 | `\|\|` | 左→右 |
| 15 | 三元 | `? :` | 右→左 |
| 16 | 赋值 | `=` `+=` `-=` `*=` `/=` `%=` `&=` `\|=` `^=` `<<=` `>>=` `>>>=` | 右→左 |
| 17（最低） | Lambda | `->` | 右→左 |

```java
// 优先级实战分析
int result = 2 + 3 * 4 - 5 / 2;
// 计算顺序：先乘除后加减
// 3 * 4 = 12, 5 / 2 = 2（整数除法）
// 2 + 12 - 2 = 12
System.out.println(result);  // 12

// 移位和算术的优先级
int r = 5 << 2 + 3;          // 实际：5 << (2 + 3) = 5 << 5 = 160
// 因为 + 优先级高于 <<
System.out.println(r);       // 160，而非 (5 << 2) + 3 = 23

// 赋值运算符优先级最低
boolean flag;
int x = 1;
// if (flag = true) { }   // 编译错误！x = true 的类型不匹配（Java 中不会混淆赋值和比较）
```

> ⚠️ 不要依赖优先级写出复杂的表达式。使用括号 `()` 明确表达意图，既避免错误也提升可读性。良好的代码宁可多写一组括号，也不要让读者查优先级表。

## 10. 表达式求值与类型提升

### 10.1 表达式中的自动类型提升

Java 在计算表达式时，会按以下规则自动提升操作数的类型：

1. **所有 `byte`、`short`、`char` 类型自动提升为 `int`**
2. **如果表达式中包含 `long`，整个表达式提升为 `long`**
3. **如果表达式中包含 `float`，整个表达式提升为 `float`**
4. **如果表达式中包含 `double`，整个表达式提升为 `double`**

```java
// byte/short/char 参与运算时自动提升为 int
short s1 = 10, s2 = 20;
// short sum = s1 + s2;     // 编译错误：s1 + s2 的结果是 int 类型
int sum = s1 + s2;          // 正确

byte b = 1;
// b = b + 1;               // 编译错误：b + 1 是 int 类型
b += 1;                     // 正确：复合赋值隐含类型转换

// 混合类型提升
int i = 10;
long l = 20L;
float f = 3.0f;
double d = 2.0;

// i + l -> long
// (i + l) * f -> float（long 提升为 float）
// 整个结果 -> double（因为有 double 参与）
double result = (i + l) * f / d;
System.out.println(result);  // 计算过程：30L * 3.0f / 2.0d = 90.0 / 2.0 = 45.0

// 常量表达式的编译期计算
final int MAX = 100;
final int MIN = 1;
byte range = MAX - MIN;     // 编译通过：常量表达式在编译期计算，结果为 99 不超出 byte 范围
```

### 10.2 字符串参与的表达式

```java
// 字符串 + 任何类型 = 字符串
int age = 25;
String msg = "年龄: " + age; // "年龄: 25"

// 当字符串出现在 + 表达式中时，后续操作变为字符串连接
System.out.println(1 + 2 + "=" + 3 + 4); // "3=34"（1+2=3，然后字符串拼接）
```

### 10.3 常量折叠

编译器会对编译期可知的常量表达式进行提前计算（常量折叠），这不会产生运行时开销。

```java
// 以下表达式在编译期就完成计算
final int SECONDS_PER_DAY = 24 * 60 * 60;        // 编译为 86400
double circle = 2 * 3.14159 * 5;                 // 编译期计算
String hello = "Hel" + "lo";                     // 编译为 "Hello"
```

> 🎯 理解类型提升规则能帮助你避免很多隐蔽的编译错误和精度损失问题。记住一个口诀：**小类型参与运算，先变 `int`；混合类型运算，往宽的类型提升**。

## 11. 常见陷阱与最佳实践

### 11.1 陷阱清单

| 陷阱 | 问题 | 正确做法 |
|:-----|:------|:---------|
| 整数除法截断 | `5 / 2 = 2`（丢失小数） | 使用 `5 / 2.0` 或 `5.0 / 2` |
| 浮点数精度 | `0.1 + 0.2 != 0.3` | 精确计算用 `BigDecimal` |
| `==` 比较字符串 | `new String("a") == new String("a")` 为 `false` | 用 `equals()` |
| Integer 缓存 | `Integer.valueOf(128) == Integer.valueOf(128)` 为 `false` | 用 `equals()` |
| `=` 与 `==` 混淆 | 在条件中误用赋值（Java 可避免此类错误） | 常量放左边：`if (5 == x)` |
| 短路运算忽略 | 未利用短路特性导致 NPE | 先判 null 再访问成员 |
| 复合赋值误解 | `b += 1` 和 `b = b + 1` 在类型转换上不等价 | 理解隐含强转 |
| 自增覆盖 | `n = n++` 结果不是预期的加 1 | 避免在一行中重复赋值同一变量 |
| 优先级错误 | `5 << 2 + 3` 结果是 `160` 而非 `23` | 不确定时加括号 |
| `short`/`byte` 运算提升 | `short + short` 结果是 `int` | 显式强转或使用 `int` 接收 |
| 浮点数 `==` 比较 | 直接 `==` 比较浮点数结果不稳定 | 使用差值比较：`Math.abs(a - b) < epsilon` |
| 三元运算符类型不匹配 | `(cond) ? int : double` 结果可能出乎意料 | 保持两个表达式类型一致 |

### 11.2 最佳实践总结

```java
// 1. 用括号明确优先级，不要依赖默认规则
int result = (a + b) * c - (d << 2);  // 清晰

// 2. 短路运算做前置条件检查
if (str != null && str.length() > 0) { /* 安全 */ }

// 3. 使用具名常量代替魔法数字
private static final double TAX_RATE = 0.15;
double tax = income * TAX_RATE;  // 优于 income * 0.15

// 4. 包装类型比较始终用 equals()，而非 ==
Integer x = 200, y = 200;
System.out.println(x.equals(y));  // true（正确）
// System.out.println(x == y);    // false（陷阱）

// 5. 精度计算使用 BigDecimal
BigDecimal a = new BigDecimal("0.1");
BigDecimal b = new BigDecimal("0.2");
BigDecimal sum = a.add(b);  // 精确的 0.3

// 6. 位运算用于性能敏感场景，但不牺牲可读性
// 好的例子（HashMap 源码风格）：
int bucket = (hash & 0x7FFFFFFF) % table.length;
// 不好的例子：
int obscure = (x << 3) ^ (y >> 2) | (z & 0xFF);  // 难以理解

// 7. 善用复合赋值运算符
list[index++] += value;  // 简洁且正确

// 8. 避免极长的表达式链，拆分为多行
boolean canProceed = (user != null)
                  && user.isActive()
                  && (permission & ADMIN_FLAG) != 0
                  && !isExpired();
```

### 11.3 面试考点速查

| 考点 | 核心要点 |
|:-----|:---------|
| `i++` vs `++i` | 后缀先取值后自增，前缀先自增后取值 |
| `&&` vs `&` | `&&` 有短路效果，`&` 无短路（且可用作位与） |
| `>>` vs `>>>` | `>>` 符号位填充，`>>>` 零填充（无符号） |
| `==` vs `equals()` | `==` 比较引用地址，`equals()` 比较内容（视重写而定） |
| 位运算替代运算 | `n & 1` 代替 `n % 2`、`n << 1` 代替 `n * 2` |
| 字符串 `+` 的优化 | 循环中用 `StringBuilder`，常量拼接编译器优化 |
| 复合赋值强转 | `a += b` 自带 `(type)(a + b)` 强转 |
| 三元运算符类型 | 两个分支类型必须兼容，会自动类型提升 |

> 🎯 运算符是 Java 中最基础也最容易出错的部分。**最佳策略**是：清晰优先于简洁。多用括号、多用临时变量、多用注释，你的代码不是写给编译器看的，而是写给下一个维护者（包括未来的你）看的。
