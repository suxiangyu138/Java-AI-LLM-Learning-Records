## 1. 策略模式 —— 接口定义算法族 {#1}

### 1.1 经典实现

```java
// ── 策略接口 ──
public interface DiscountStrategy {
    BigDecimal apply(BigDecimal originalPrice);
}

// ── 具体策略 ──
public class NoDiscount implements DiscountStrategy {
    public BigDecimal apply(BigDecimal price) { return price; }
}
public class PercentageDiscount implements DiscountStrategy {
    private final double rate;
    public PercentageDiscount(double rate) { this.rate = rate; }
    public BigDecimal apply(BigDecimal price) {
        return price.multiply(BigDecimal.valueOf(1 - rate));
    }
}
public class ThresholdDiscount implements DiscountStrategy {
    private final BigDecimal threshold;
    private final BigDecimal reduce;
    public ThresholdDiscount(BigDecimal t, BigDecimal r) {
        this.threshold = t; this.reduce = r;
    }
    public BigDecimal apply(BigDecimal price) {
        return price.compareTo(threshold) >= 0
            ? price.subtract(reduce) : price;
    }
}

// ── 上下文：使用策略 ──
public class OrderService {
    // 运行时选择策略
    public BigDecimal calculatePrice(Order order, DiscountStrategy strategy) {
        BigDecimal total = order.getItems().stream()
            .map(Item::getPrice)
            .reduce(BigDecimal.ZERO, BigDecimal::add);
        return strategy.apply(total);
    }
}
```

### 1.2 Lambda 简化策略

```java
// 简单策略无需单独建类
Map<String, Function<Order, BigDecimal>> strategies = Map.of(
    "vip",     order -> order.getTotal().multiply(new BigDecimal("0.8")),
    "normal",  order -> order.getTotal().multiply(new BigDecimal("0.95")),
    "student", order -> order.getTotal().multiply(new BigDecimal("0.7")),
    "none",    Order::getTotal
);

public BigDecimal calculate(Order order, String userType) {
    return strategies.getOrDefault(userType, Order::getTotal).apply(order);
}
```

## 2. 工厂模式 —— 接口解耦创建 {#2}

### 2.1 简单工厂 + 接口

```java
// ── 产品接口 ──
public interface MessageSender {
    void send(String to, String content);
}

// ── 具体产品 ──
public class SmsSender implements MessageSender {
    public void send(String to, String content) {
        smsApi.send(to, content);
    }
}
public class EmailSender implements MessageSender {
    public void send(String to, String content) {
        emailApi.send(to, "通知", content);
    }
}
public class WeChatSender implements MessageSender {
    public void send(String to, String content) {
        wechatApi.sendTemplate(to, content);
    }
}

// ── 工厂 ──
public class MessageSenderFactory {
    private static final Map<String, Supplier<MessageSender>> REGISTRY =
        new ConcurrentHashMap<>();

    static {
        register("sms", SmsSender::new);
        register("email", EmailSender::new);
        register("wechat", WeChatSender::new);
    }

    public static void register(String type, Supplier<MessageSender> supplier) {
        REGISTRY.put(type, supplier);
    }

    public static MessageSender create(String type) {
        Supplier<MessageSender> supplier = REGISTRY.get(type);
        if (supplier == null) throw new IllegalArgumentException("Unknown: " + type);
        return supplier.get();
    }
}

// ── 使用 ──
MessageSender sender = MessageSenderFactory.create("email");
sender.send("user@example.com", "您的订单已发货");
```

### 2.2 函数式工厂

```java
// ── Builder 模式 + 函数式接口 ──
public class HttpClientBuilder {
    private int timeout = 5000;
    private int maxRetries = 3;
    private List<Consumer<HttpRequest>> interceptors = new ArrayList<>();

    public HttpClientBuilder timeout(int timeout) {
        this.timeout = timeout;
        return this;
    }
    public HttpClientBuilder maxRetries(int maxRetries) {
        this.maxRetries = maxRetries;
        return this;
    }
    public HttpClientBuilder addInterceptor(Consumer<HttpRequest> interceptor) {
        this.interceptors.add(interceptor);
        return this;
    }

    public HttpClient build() {
        return new HttpClient(timeout, maxRetries, interceptors);
    }
}

// 使用
HttpClient client = new HttpClientBuilder()
    .timeout(3000)
    .maxRetries(2)
    .addInterceptor(req -> log.info("Request: {}", req))
    .build();
```

## 3. SPI —— 服务提供者接口 {#3}

### 3.1 Java SPI 机制

```text
SPI (Service Provider Interface):
  框架定义接口，第三方实现接口。
  通过在 META-INF/services 声明实现类，自动发现和加载。

典型案例:
  JDBC: java.sql.Driver → MySQL Driver / PostgreSQL Driver
  SLF4J: org.slf4j.LoggerFactory → Logback / Log4j2
  JAXP: javax.xml.parsers.DocumentBuilderFactory → Xerces
```

```java
// ── 步骤1: 定义 SPI 接口 ──
// 模块 A (API): 只定义接口
public interface PaymentGateway {
    String getName();                        // 支付网关名称
    PayResult pay(PayRequest request);       // 支付
    RefundResult refund(RefundRequest req);  // 退款
}

// ── 步骤2: 编写 ServiceLoader 调用方 ──
public class PaymentGatewayLoader {
    private static final ServiceLoader<PaymentGateway> LOADER =
        ServiceLoader.load(PaymentGateway.class);

    public static PaymentGateway getByName(String name) {
        for (PaymentGateway gw : LOADER) {
            if (gw.getName().equals(name)) {
                return gw;
            }
        }
        throw new IllegalArgumentException("No gateway: " + name);
    }

    public static List<PaymentGateway> all() {
        List<PaymentGateway> list = new ArrayList<>();
        LOADER.forEach(list::add);
        return list;
    }
}
```

```text
// ── 步骤3: 第三方实现（模块 B）──
// src/main/resources/META-INF/services/
//   文件名: com.example.spi.PaymentGateway
//   内容:
//     com.wechat.WechatPaymentGateway
//     com.alipay.AlipayPaymentGateway
```

```java
// ── 步骤4: 框架自动发现 ──
PaymentGateway gateway = PaymentGatewayLoader.getByName("wechat");
gateway.pay(request);

// ── ClassPath 扫描无需写死实现类！
// 添加新支付方式 → 加 JAR → 自动生效
```

### 3.2 Spring Boot 自动配置 (SPI 的变体)

```java
// Spring Boot 的 spring.factories 就是 SPI 的变体
// META-INF/spring.factories:
// org.springframework.boot.autoconfigure.EnableAutoConfiguration=\
//   com.example.MyAutoConfiguration

@Configuration
@ConditionalOnClass(WeChatPayClient.class)  // 有 wechat-pay-sdk 才生效
public class WeChatPayAutoConfiguration {

    @Bean
    @ConditionalOnMissingBean
    public PaymentGateway wechatPaymentGateway(WeChatConfig config) {
        return new WeChatPaymentGateway(config);
    }
}
// 引入依赖 → 自动注入 → 零配置
```

## 4. 适配器模式 —— 接口转接 {#4}

### 4.1 经典适配器

```java
// ── 场景：第三方返回的数据格式与我们系统的接口不匹配 ──

// 我们系统的接口
public interface UserProfileService {
    UserProfile getProfile(Long userId);
}

// 第三方服务（格式不同）
public class LegacyUserSystem {
    public LegacyUser fetch(String userId) { /* 旧格式 */ }
}

// ── 适配器：桥接新旧接口 ──
public class LegacyUserAdapter implements UserProfileService {
    private final LegacyUserSystem legacy;

    public LegacyUserAdapter(LegacyUserSystem legacy) {
        this.legacy = legacy;
    }

    @Override
    public UserProfile getProfile(Long userId) {
        LegacyUser legacyUser = legacy.fetch(String.valueOf(userId));
        // 转换旧格式 → 新格式
        return new UserProfile(
            legacyUser.getUid(),
            legacyUser.getDisplayName(),
            legacyUser.getContactEmail()
        );
    }
}

// 现在可以在新系统中透明使用旧服务
UserProfileService service = new LegacyUserAdapter(new LegacyUserSystem());
UserProfile profile = service.getProfile(123L);
```

### 4.2 默认方法实现适配器

```java
// ── 场景：接口有 20 个方法，但我只需要其中 2 个 ──

// 原始接口（很胖）
public interface MouseListener {
    void onClick();
    void onDoubleClick();
    void onRightClick();
    void onDrag();
    void onScroll();
}

// ── 适配器：提供所有方法的空实现 ──
public class MouseAdapter implements MouseListener {
    public void onClick() { }
    public void onDoubleClick() { }
    public void onRightClick() { }
    public void onDrag() { }
    public void onScroll() { }
}

// 子类只需覆盖需要的方法
MouseListener listener = new MouseAdapter() {
    @Override
    public void onClick() {
        System.out.println("Click!");
    }
    // 其他方法全是空实现，无需关注
};
```

## 5. 模板方法 vs 策略模式 {#5}

### 5.1 核心区别

```text
模板方法 (Template Method)：
  在抽象类中定义算法骨架 → 子类通过继承填空细节
  "把相同的部分放在父类，变化的部分留给子类"

策略模式 (Strategy)：
  用接口定义算法 → 通过组合注入不同策略
  "把变化的部分提取为接口，运行时组合"

关键差异：
  模板方法 = 继承 (IS-A)，编译期绑定
  策略模式 = 组合 (HAS-A)，运行时可切换
```

### 5.2 代码对比

```java
// ── 模板方法：抽象类 + 继承 ──
public abstract class AbstractDataExporter {
    // 模板方法（final 锁定骨架）
    public final String export(DataSet data) {
        String header = buildHeader(data);     // 子类实现
        String body = buildBody(data);         // 子类实现
        String footer = buildFooter(data);     // 子类实现
        return header + "\n" + body + "\n" + footer;
    }
    protected abstract String buildHeader(DataSet data);
    protected abstract String buildBody(DataSet data);
    protected abstract String buildFooter(DataSet data);
}

// 使用时必须继承
public class CsvExporter extends AbstractDataExporter { ... }

// ── 策略模式：接口 + 组合 ──
public interface ExportStrategy {
    String export(DataSet data);
}

public class DataExporter {
    private final ExportStrategy strategy;    // 组合！

    public DataExporter(ExportStrategy strategy) {
        this.strategy = strategy;
    }

    // 运行时切换策略
    public void setStrategy(ExportStrategy strategy) {
        this.strategy = strategy;
    }

    public String export(DataSet data) {
        return strategy.export(data);
    }
}
```

### 5.3 何时用哪个？

| 模板方法 | 策略模式 |
|---------|---------|
| 算法骨架基本不变 | 算法频繁变化 |
| 有受保护的钩子方法 | 策略可以独立测试 |
| 子类共享一些状态 | 策略是无状态的 |
| 需要在父类控制执行顺序 | 需要运行时切换 |
| 编译期绑定足够 | 需要动态绑定 |

> 🎯 **核心要点**：优先策略模式（组合），除非真的需要共享状态和骨架控制。这就是 GoF 的核心建议——**组合优于继承**。

## 6. sealed interface + record —— 代数数据类型 {#6}

### 6.1 建模"非此即彼"的结果

```java
// ── 经典: Either<L,R> ──
// 一种类型表示"要么是左值，要么是右值"
public sealed interface Either<L, R>
    permits Either.Left, Either.Right {

    record Left<L, R>(L value) implements Either<L, R> {}
    record Right<L, R>(R value) implements Either<L, R> {}

    // 工具方法
    default <T> T fold(
            Function<L, T> leftMapper,
            Function<R, T> rightMapper) {
        return switch (this) {
            case Left<L, R> l  -> leftMapper.apply(l.value());
            case Right<L, R> r -> rightMapper.apply(r.value());
        };
    }
}

// ── 使用 ──
public Either<String, User> createUser(CreateUserRequest req) {
    if (req.getName() == null || req.getName().isBlank()) {
        return new Either.Left<>("用户名不能为空");
    }
    return new Either.Right<>(new User(req.getName()));
}

// 调用方必须处理两种情况
String message = result.fold(
    error -> "错误: " + error,       // 处理 Left
    user  -> "欢迎: " + user.getName()  // 处理 Right
);
```

### 6.2 建模状态机

```java
// ── 订单状态机 ──
public sealed interface OrderState
    permits Pending, Paid, Shipped, Completed, Cancelled {

    record Pending() implements OrderState {}
    record Paid(String transactionId) implements OrderState {}
    record Shipped(String trackingNo, LocalDateTime shippedAt)
        implements OrderState {}
    record Completed(LocalDateTime completedAt) implements OrderState {}
    record Cancelled(String reason, LocalDateTime cancelledAt)
        implements OrderState {}

    // 状态转换
    default OrderState pay(String transactionId) {
        return switch (this) {
            case Pending p  -> new Paid(transactionId);
            case Paid p     -> throw new IllegalStateException("已支付");
            case Shipped s  -> throw new IllegalStateException("已发货");
            case Completed c -> throw new IllegalStateException("已完成");
            case Cancelled c -> throw new IllegalStateException("已取消");
        };
    }
}
```

### 6.3 建模命令执行结果

```java
// ── CQRS 命令结果 ──
public sealed interface CommandResult
    permits Success, BusinessError, SystemError {

    record Success(String message) implements CommandResult {}
    record BusinessError(String code, String detail) implements CommandResult {}
    record SystemError(Throwable cause) implements CommandResult {}

    default boolean isSuccess() {
        return this instanceof Success;
    }
}

// ── 使用 ──
public CommandResult handle(CreateOrderCommand cmd) {
    try {
        // 业务校验
        if (cmd.getQuantity() <= 0) {
            return new CommandResult.BusinessError(
                "INVALID_QUANTITY", "数量必须大于 0");
        }
        // 执行
        orderRepository.save(new Order(cmd));
        return new CommandResult.Success("订单创建成功");

    } catch (Exception e) {
        return new CommandResult.SystemError(e);
    }
}

// 统一处理结果
String response = switch (result) {
    case CommandResult.Success s           -> "200: " + s.message();
    case CommandResult.BusinessError e     -> "400: " + e.code() + " - " + e.detail();
    case CommandResult.SystemError e       -> "500: 系统内部错误";
};
```

> 🎯 **核心要点**：sealed interface + record 是 Java 版本代数数据类型 (ADT) 的实现。它让"非此即彼"的类型建模变得安全——编译器帮你保证穷尽性，模式匹配帮你优雅处理每种情况。这就是用**类型系统消除运行时错误**的最佳实践。
