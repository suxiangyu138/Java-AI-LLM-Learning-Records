## 1. 高频面试题 12 问

### Q1：Java 和 Python 的核心区别是什么？

> 答：三个层次——类型系统（静态强类型 vs 动态强类型）、执行模型（JIT 编译 vs 解释执行）、生态定位（企业后端 vs AI/数据）。一句话：Java 把契约写在编译期、性能交给 JIT；Python 把自由留给运行时、速度交给开发速度与生态密度。（→ 01/02）

### Q2：为什么说 Python 有 GIL？它锁住了什么？

> 答：CPython 的全局解释器锁，保证同一时刻只有一个线程执行字节码——因为引用计数内存管理不是线程安全的。锁字节码执行，不锁 C 扩展内部（NumPy 释放 GIL）、不锁阻塞 IO（等待时释放）。推论：多线程 Python 跑 CPU 计算 ≈ 单核。（→ 04）

### Q3：GIL 会消失吗？2026 年是什么状态？

> 答：正在消失但还没消失。PEP 703 实验（3.13）→ PEP 779 官方可选支持（3.14，2025-06-16 通过）→ 3.15（2026-10 计划）统一 ABI（PEP 803，一个扩展二进制兼容两种构建）→ 预计 3.16-3.20 成为默认。生产环境 2026 年仍用带 GIL 构建，但路线已定。（→ 04）

### Q4：Java 为什么比 Python 快？快多少？

> 答：第一性原因是执行模型——JVM 热点方法 JIT 编译为机器码并深度优化（内联、逃逸、向量化），CPython 逐行解释字节码还要付动态分派税。CPU 密集场景典型 10-100 倍；IO 密集差距 <2 倍；短任务 Python 反而快（无预热）。2026 MCP 基准：Java 0.835ms vs Python 26.45ms。（→ 02/03）

### Q5：Python 怎么提速？你用过哪些手段？

> 答：按性价比排序——① 真实瓶颈优先（慢 SQL/缺缓存，与语言无关）；② C 扩展外包（NumPy/PyTorch 内核是 C）；③ 换实现（PyPy，但 2026 尚无 3.12 兼容版）；④ 实验性 JIT（3.13+）。数据科学场景 Python 的性能劣势因 C 内核几乎消失。（→ 03）

### Q6：虚拟线程和 asyncio 的区别？

> 答：虚拟线程（JDK 21 定稿）是"轻量线程"——阻塞即让出载体线程，代码保持同步直白，可承载百万级；asyncio 是"事件循环 + 协程"——单线程内 await 切换，代码必须异步化且不能有阻塞调用。核心差异：Java 用同步代码获得并发，Python 用异步代码获得并发；虚拟线程的心智负担低得多。（→ 04）

### Q7：Spring Boot 和 Django/FastAPI 怎么选？

> 答：看系统画像——微服务治理、五年维护、大团队 → Spring Boot（Spring Cloud 全家桶无对手）；快速上线、内部工具、Admin 需求 → Django（Admin/自动迁移效率王牌）；高性能 API/模型服务 → FastAPI（类型标注一次换校验+文档+IDE）。Django 6.0 内置后台任务，FastAPI 0.139 仍是异步 API 首选。（→ 05）

### Q8：Python 是 AI 之王，Java 还有 AI 生态吗？

> 答：分工视角——Python 统治研发层（训练/实验/数据科学，生态密度无人可敌）；Java 接管生产层（服务化/编排/治理）：Spring AI 2.0、LangChain4j、DJL 都成熟，62% 企业用 Java 写 AI 功能。企业 AI 的标准形态是"Java 业务 + Python 模型"混合。（→ 06）

### Q9：你做过双语言混合架构吗？怎么集成？

> 答：做过/了解标准形态——核心业务 Java（事务/治理），模型服务 Python（FastAPI + vLLM），无状态黑盒，通过 gRPC/HTTP/MCP 对接；异步任务走 Kafka，traceId 跨语言贯通（OTel）。原则：能进程级不进程内；契约先行（proto/OpenAPI）；幂等消费。（→ 08）

### Q10：Jython 还能用吗？Python on JVM 现状？

> 答：不能用——Jython 停在 Python 2.x，最后发布 2024-08，实际停滞。现役答案是 GraalPy（Python 3.12 兼容、纯 Python 约 4x CPython、Maven 内嵌 Java、可编 Native Image）；OpenJDK 的 Project Detroit 在探索直接把 CPython 嵌进 JVM。Apache Camel 已从 Jython 迁移到 GraalPy。（→ 08）

### Q11：Python 工程怎么保证类型安全？

> 答：动态类型 + 自觉纪律——PEP 484 类型标注 + mypy/pyright 静态检查（CI 强制才有用）；FastAPI + Pydantic 的类型标注同时服务校验与检查器，是 2026 年最顺手的组合。对比 Java 的编译期强制，Python 是"可选的契约"。（→ 01/07）

### Q12：一个 AI 应用（如企业知识库问答）怎么分工？

> 答：标准答案——Java 主体：Spring AI 编排 RAG 管道与 Agent、对接企业权限/审计/工单系统、MCP 工具暴露业务能力；Python 模型层：FastAPI + vLLM 包装推理、Embedding、微调任务；gRPC/HTTP 对接，Kafka 处理异步。理由：业务工程 Java 生态成熟，模型工程 Python 生态成熟，各用所长。（→ 06/09）

## 2. 项目话术：混合架构叙事模板

面试讲项目时用"分工心智"叙事，比罗列技术栈有区分度：

```text
项目背景：XX 智能客服平台（RAG + Agent），需要对接企业订单系统。
我的方案：
  ① 分工决策——交易与工单逻辑用 Java（Spring AI 2.0 编排 Agent，
     订单查询/退款通过 MCP 工具暴露），模型侧用 Python（FastAPI 封装
     向量检索与 LLM 调用），gRPC 对接；
  ② 关键设计——模型服务无状态黑盒、水平扩容；traceId 跨语言贯通；
     工具调用失败幂等重试；
  ③ 结果量化——P99 延迟 XXms、工具调用成功率 XX%、单机 QPS XX。
```

加分点：主动说出"为什么这么分"（治理/生态/维护年限），并引用 62% 数据与 MCP 基准——证明你不是"会两门语言"，而是"有选型判断力"。

**常见追问与应对**：

- 追问"为什么不用纯 Python？"→ 答：交易链路强一致与微服务治理在 Java 生态最成熟；模型服务无状态所以可以自由选 Python——**分工的前提是边界清楚**
- 追问"gRPC 和 REST 怎么分？"→ 答：高频小消息用 gRPC（省带宽、强类型），低频或外部对接用 REST（生态工具多）；契约先行、错误码共享枚举
- 追问"AI 模型换供应商怎么办？"→ 答：Java 侧只依赖 OpenAI 兼容协议 + MCP 抽象，模型侧换实现不换接口——这正是混合架构的价值
- 追问"成本怎么控制？"→ 答：token 用量与缓存命中率在 Java 侧统一记账，prompt 缓存（前缀稳定）与模型分级（贵模型只给高价值请求）是 2026 年两个杠杆

## 3. 知识体系一句话串讲

双语言对比 = 类型系统定契约（01）→ 运行时定性能（02/03）→ 并发模型定规模（04）→ 生态定效率（05/06）→ 工程化定维护（07）→ 互操作定架构（08）→ 选型定方向（09）。

面试的"终局叙事"记住这一句即可：**我不是在选语言，我是在选"系统生命周期内总成本最低的组合"**——短命项目 Python 更快，长命系统 Java 更省，两者并存的系统用混合架构各取所长。把这句话连同 62% 数据、MCP 基准、GIL 时间线一起讲出来，就是一次完整的"对比题满分答案"。

## 4. 快速自测（含答案）

1. 静态/强类型的区分维度是什么？（时机/尺度；Java 静态强、Python 动态强 → 01）
2. JIT 为什么需要"预热"？（热点方法才编译，冷启动慢、热后爆发 → 02）
3. GIL 下怎么吃多核？（multiprocessing 或多进程部署 → 04）
4. free-threading 2026 官方状态？（3.14 官方可选支持，非默认 → 04）
5. Django 6.0 两个新特性？（内置后台任务、原生 CSP → 05）
6. Java 侧 LLM 框架叫什么？（Spring AI 2.0/LangChain4j → 06）
7. pytest fixture 对比 JUnit 优势？（依赖注入式、scope 复用 → 07）
8. GraalPy 比 CPython 快多少？（纯 Python 约 4 倍 → 08）
9. 混合架构默认集成通道？（HTTP/gRPC/MCP，进程级优先 → 08）
10. 62% 数据的含义？（用 Java 写 AI 功能的企业比例 → 06）

附加题（深水区）：

11. 你们的 AI 项目模型服务为什么用 FastAPI 而不是 Spring AI 直接调？（答：模型服务与业务解耦、独立扩容、Python 推理生态；Spring AI 负责业务侧编排，各用所长 → 06/08）
12. 如果让你把一个纯 Python 服务迁到 Java，怎么评估？（答：先画像——流量与延迟要求、生态依赖（是否重度用 PyPI 计算库）、团队技能；迁移顺序"接口层→业务层→数据层"，行为用契约测试锁定 → 09）
