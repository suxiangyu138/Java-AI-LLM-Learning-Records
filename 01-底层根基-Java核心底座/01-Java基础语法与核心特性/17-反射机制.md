## 1. 反射的概念与价值

### 1.1 什么是反射

反射（Reflection）是 Java 在 **运行时** 获取类的完整元数据并动态操作类成员的能力，是 Spring、MyBatis、Jackson 等框架的底层基石。

```
编译器 (javac)             运行时 (JVM)
  ┌─────────────┐         ┌──────────────────┐
  │ .java → .class│        │ Class Object      │
  │ 编译期类型检查 │        │ 反射 API          │
  │ 静态绑定     │        │ 动态调用         │
  └─────────────┘         └──────────────────┘
```

### 1.2 核心作用

| 作用 | 说明 |
|------|------|
| 运行时获取类的元数据 | 获取类名、包名、父类、接口、注解等 |
| 动态创建对象 | 通过构造器创建实例，无需 `new` |
| 动态调用方法 / 修改属性 | 调用任意方法、读写任意属性（含 `private`） |
| 突破封装性 | `setAccessible(true)` 访问私有成员 |
| 框架核心 | Spring IoC、MyBatis ORM、JUnit 等框架的基础 |

### 1.3 核心类

| 核心类 | 说明 | 常用场景 |
|--------|------|----------|
| `Class<?>` | 类的字节码对象，反射入口 | 获取类信息、创建实例 |
| `Field` | 成员变量 | 动态读写属性值 |
| `Method` | 方法 | 动态调用方法 |
| `Constructor<?>` | 构造器 | 动态创建对象 |
| `Modifier` | 解析修饰符标志 | 判断可见性 |

> **关键理解**：JVM 为每个加载的类在方法区维护唯一的 `Class` 实例，反射 API 通过 JNI 访问方法区元数据。

## 2. 获取 Class 对象的三种方式

```java
/**
 * 获取 Class 对象的三种方式
 */
public class GetClassDemo {
    public static void main(String[] args) throws Exception {
        // 方式 1: 类字面常量 —— 最安全、不触发 static 初始化
        Class<String> clazz1 = String.class;

        // 方式 2: 对象的 getClass() 方法 —— 需已有实例
        String str = "hello";
        Class<? extends String> clazz2 = str.getClass();

        // 方式 3: Class.forName() —— 最灵活，触发 static 初始化
        Class<?> clazz3 = Class.forName("java.lang.String");
        // 延迟初始化版本（不触发 static 块）
        Class<?> clazz4 = Class.forName("java.lang.String", false,
                Thread.currentThread().getContextClassLoader());

        System.out.println(clazz1 == clazz2); // true
        System.out.println(clazz2 == clazz3); // true
    }
}
```

| 方式 | 时机 | 触发 static 初始化 | 适用场景 |
|------|------|-------------------|----------|
| `类名.class` | 编译期 | 否 | 编译期已知具体类 |
| `对象.getClass()` | 运行时 | 否（类已加载） | 已有对象实例 |
| `Class.forName("全类名")` | 运行时 | 是（默认） | 配置驱动、动态加载 |

> 💡 编译期已知类型用 `类名.class`；动态加载配置类用 `Class.forName()`。

## 3. Class 对象的核心方法

### 3.1 getXxx() vs getDeclaredXxx()

| 方法 | 可见性 | 继承范围 |
|------|--------|----------|
| `getMethods()` / `getFields()` / `getConstructors()` | 仅 `public` | 包含继承成员 |
| `getDeclaredMethods()` / `getDeclaredFields()` / `getDeclaredConstructors()` | 全部（含 private） | 仅本类定义 |

### 3.2 Class API 速查

| 方法 | 返回值 | 说明 |
|------|--------|------|
| `getSimpleName()` / `getName()` | `String` | 类名 / 全类名 |
| `getSuperclass()` / `getInterfaces()` | `Class<?>` / `Class<?>[]` | 父类 / 接口 |
| `getFields()` / `getDeclaredFields()` | `Field[]` | 字段 |
| `getMethods()` / `getDeclaredMethods()` | `Method[]` | 方法 |
| `getConstructors()` / `getDeclaredConstructors()` | `Constructor<?>[]` | 构造器 |
| `getModifiers()` | `int` | 修饰符位标志 |
| `isAnnotationPresent(Class)` | `boolean` | 是否有某注解 |
| `cast(Object)` | `T` | 对象转型 |

## 4. 操作 Field（字段）

```java
import java.lang.reflect.Field;

public class FieldDemo {
    static class User { public String gender; private String name; private int age; }

    public static void main(String[] args) throws Exception {
        Class<?> clazz = User.class;
        User user = (User) clazz.getDeclaredConstructor().newInstance();

        // 操作 public 字段
        Field genderField = clazz.getField("gender");
        genderField.set(user, "男");
        System.out.println("gender: " + genderField.get(user));

        // 操作 private 字段（需 setAccessible）
        Field nameField = clazz.getDeclaredField("name");
        nameField.setAccessible(true);
        nameField.set(user, "Alice");
        System.out.println("name: " + nameField.get(user));

        Field ageField = clazz.getDeclaredField("age");
        ageField.setAccessible(true);
        ageField.setInt(user, 25);
        System.out.println("age: " + ageField.getInt(user));
    }
}
```

| Field 方法 | 说明 |
|-----------|------|
| `get/set(Object obj, Object value)` | 读写属性值 |
| `setBoolean/Int/Long/Double(...)` | 基本类型专用（避免装箱） |
| `getBoolean/Int/Long/Double(...)` | 基本类型专用 |
| `setAccessible(boolean)` | 取消访问检查 |
| `getName()` / `getType()` / `getModifiers()` | 获取元信息 |

## 5. 操作 Method（方法）

```java
import java.lang.reflect.Method;

public class MethodDemo {
    static class Calc {
        public int add(int a, int b) { return a + b; }
        private int mul(int a, int b) { return a * b; }
        public static String greet(String name) { return "Hello, " + name; }
    }

    public static void main(String[] args) throws Exception {
        Class<?> clazz = Calc.class;
        Object obj = clazz.getDeclaredConstructor().newInstance();

        // 1. 调用 public 方法
        Method add = clazz.getMethod("add", int.class, int.class);
        System.out.println("add(3,4) = " + add.invoke(obj, 3, 4));

        // 2. 调用 private 方法
        Method mul = clazz.getDeclaredMethod("mul", int.class, int.class);
        mul.setAccessible(true);
        System.out.println("mul(5,6) = " + mul.invoke(obj, 5, 6));

        // 3. 调用 static 方法（第一个参数传 null）
        Method greet = clazz.getMethod("greet", String.class);
        System.out.println(greet.invoke(null, "World"));
    }
}
```

| Method 方法 | 说明 |
|------------|------|
| `invoke(Object obj, Object... args)` | 调用方法 |
| `getName()` / `getParameterTypes()` / `getReturnType()` | 获取元信息 |

> 💡 调用 static 方法时 `invoke` 第一个参数传 `null`。调用 private 方法前必须 `setAccessible(true)`。

## 6. 操作 Constructor（构造器）

```java
import java.lang.reflect.Constructor;

public class ConstructorDemo {
    static class User {
        private final String name; private final int age;
        public User() { this.name = "default"; this.age = 0; }
        public User(String name, int age) { this.name = name; this.age = age; }
        @Override public String toString() { return "User{name='" + name + "', age=" + age + "}"; }
    }

    public static void main(String[] args) throws Exception {
        Class<?> clazz = User.class;

        // JDK 9+ 推荐方式：getDeclaredConstructor().newInstance()
        User u1 = (User) clazz.getDeclaredConstructor().newInstance();
        System.out.println(u1);

        Constructor<?> c = clazz.getDeclaredConstructor(String.class, int.class);
        User u2 = (User) c.newInstance("Alice", 25);
        System.out.println(u2);
    }
}
```

> ⚠️ `Class.newInstance()` 从 JDK 9 标记为 `@Deprecated`，统一使用 `clazz.getDeclaredConstructor().newInstance()`。

## 7. setAccessible 与私有成员访问

### 7.1 原理与风险

```java
import java.lang.reflect.Field;

public class SetAccessibleDemo {
    static class Secret { private String secret = "secret data"; }

    public static void main(String[] args) throws Exception {
        Class<?> clazz = Secret.class;
        Object obj = clazz.getDeclaredConstructor().newInstance();

        Field field = clazz.getDeclaredField("secret");
        field.setAccessible(true); // 跳过 JVM 访问权限检查
        System.out.println("Before: " + field.get(obj));
        field.set(obj, "modified");
        System.out.println("After: " + field.get(obj));
    }
}
```

**原理**：`AccessibleObject` 维护 `override` 标志位。`setAccessible(true)` 将其设为 true，JVM 跳过 `Reflection.verifyMemberAccess()` 权限检查。

**JPMS 影响**：JDK 9+ 模块化系统限制反射。目标模块需 `exports` 或 `opens`，否则抛 `InaccessibleObjectException`。解决：`module-info.java` 声明 `opens`，或加 `--add-opens java.base/java.lang=ALL-UNNAMED`。

> ⚠️ 反射访问私有成员仅限框架底层或单元测试。业务代码应走 getter/setter。

## 8. 反射的性能开销与优化

### 8.1 反射慢的原因

| 原因 | 说明 |
|------|------|
| 动态查找 | `Method.invoke()` 运行时解析方法 |
| 类型检查 | 参数动态匹配，基本类型装箱/拆箱 |
| 安全检查 | 每次调用检查访问权限 |
| JIT 无法内联 | 反射调用阻碍 JIT 内联优化 |

```java
public class PerformanceDemo {
    public static int add(int a, int b) { return a + b; }

    public static void main(String[] args) throws Exception {
        Method method = PerformanceDemo.class.getMethod("add", int.class, int.class);
        int n = 10_000_000;
        long t1, direct, reflect, optimized;

        t1 = System.nanoTime();
        for (int i = 0; i < n; i++) add(1, 2);
        direct = System.nanoTime() - t1;

        t1 = System.nanoTime();
        for (int i = 0; i < n; i++) method.invoke(null, 1, 2);
        reflect = System.nanoTime() - t1;

        method.setAccessible(true);
        t1 = System.nanoTime();
        for (int i = 0; i < n; i++) method.invoke(null, 1, 2);
        optimized = System.nanoTime() - t1;

        System.out.printf("直接: %dms | 反射: %dms (%.1fx) | 反射+accessible: %dms (%.1fx)%n",
                direct/1000000, reflect/1000000, (double)reflect/direct,
                optimized/1000000, (double)optimized/direct);
    }
}
```

### 8.2 优化技巧

| 优化手段 | 效果 |
|----------|------|
| `setAccessible(true)` | 跳过安全检查，提升 50%+ |
| 缓存 Method/Field/Constructor 对象 | 避免重复查找，用 `ConcurrentHashMap` |
| 提取反射对象到循环外 | 减少重复开销 |
| 使用 MethodHandle | 接近直接调用性能，JIT 可内联 |
| 使用 LambdaMetafactory | 终极优化，JIT 完全内联 |

```java
public class MethodCache {
    private static final Map<String, Method> CACHE = new ConcurrentHashMap<>();

    public static Object invoke(String className, String methodName,
                                 Object obj, Object... args) throws Exception {
        String key = className + "#" + methodName;
        Method m = CACHE.computeIfAbsent(key, k -> {
            try {
                Method mt = Class.forName(className).getMethod(methodName);
                mt.setAccessible(true);
                return mt;
            } catch (Exception e) { throw new RuntimeException(e); }
        });
        return m.invoke(obj, args);
    }
}
```

## 9. MethodHandle 与 VarHandle（JDK 7/9+）

### 9.1 MethodHandle（JDK 7+）

| 对比 | Method | MethodHandle |
|------|--------|--------------|
| 定位 | 代码级调用模拟 | 字节码级调用模拟 |
| JIT 内联 | 难以内联 | 可内联，近直接调用 |
| 安全检查 | 检查访问权限 | 仅检查类型签名 |
| 性能 | 慢 10-50x | 快 2-5x |

```java
import java.lang.invoke.*;

public class MethodHandleDemo {
    public String greet(String name) { return "Hello, " + name; }

    public static void main(String[] args) throws Throwable {
        MethodHandles.Lookup lookup = MethodHandles.lookup();
        MethodType mt = MethodType.methodType(String.class, String.class);
        MethodHandle handle = lookup.findVirtual(MethodHandleDemo.class, "greet", mt);

        MethodHandleDemo demo = new MethodHandleDemo();
        System.out.println(handle.invoke(demo, "World"));        // 自动类型适配
        System.out.println(handle.invokeExact(demo, "World"));  // 严格类型匹配

        MethodHandle bound = handle.bindTo(demo);
        System.out.println(bound.invoke("Bound"));               // 绑定接收者
    }
}
```

### 9.2 VarHandle（JDK 9+）

替代 `AtomicXxxFieldUpdater`，提供字段级别 CAS、volatile 等原子操作。

```java
import java.lang.invoke.*;

public class VarHandleDemo {
    private volatile int counter = 0;
    private static final VarHandle COUNTER;
    static {
        try { COUNTER = MethodHandles.lookup()
                .findVarHandle(VarHandleDemo.class, "counter", int.class);
        } catch (Exception e) { throw new ExceptionInInitializerError(e); }
    }
    public void increment() {
        int cur; do { cur = (int) COUNTER.getVolatile(this); }
        while (!COUNTER.compareAndSet(this, cur, cur + 1));
    }
    public static void main(String[] args) {
        VarHandleDemo d = new VarHandleDemo(); d.increment();
        System.out.println(COUNTER.getVolatile(d)); // 1
    }
}
```

## 10. JDK 动态代理

原理：运行时生成 `$Proxy0.class`（实现目标接口），所有方法调用转发给 `InvocationHandler`。**只能代理接口**。

```java
import java.lang.reflect.*;

public class JdkProxyDemo {
    interface Hello { String sayHello(String name); void goodbye(); }
    static class HelloImpl implements Hello {
        public String sayHello(String name) { return "Hello, " + name; }
        public void goodbye() { System.out.println("Goodbye!"); }
    }
    static class LogHandler implements InvocationHandler {
        private final Object target;
        LogHandler(Object target) { this.target = target; }
        @Override
        public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
            System.out.println("[LOG] " + method.getName());
            return method.invoke(target, args);
        }
    }
    public static void main(String[] args) {
        Hello proxy = (Hello) Proxy.newProxyInstance(
                Hello.class.getClassLoader(), new Class<?>[]{Hello.class},
                new LogHandler(new HelloImpl()));
        System.out.println(proxy.sayHello("Alice"));
        proxy.goodbye();
    }
}
```

### 10.2 JDK 动态代理 vs CGLIB

| 对比 | JDK 动态代理 | CGLIB |
|------|-------------|-------|
| 原理 | 实现接口的代理类 | 继承目标类的子类 |
| 要求 | 必须有接口 | 无接口限制 |
| 目标方法 | 接口方法 | 非 final 方法 |
| Spring AOP | 有接口时使用 | Boot 2.x+ 默认 |

> 💡 Spring AOP 选择逻辑：有接口用 JDK 动态代理，无接口用 CGLIB。Spring Boot 2.x+ 默认 CGLIB。

## 11. 框架中的反射实战（简单 IoC/ORM）

### 11.1 简易 DI 容器

```java
import java.lang.annotation.*;
import java.lang.reflect.*;
import java.util.*;

/**
 * 简易 DI 容器 —— 模拟 Spring IoC 核心逻辑
 */
public class SimpleDI {
    @Retention(RetentionPolicy.RUNTIME) @Target(ElementType.TYPE) @interface Component {}
    @Retention(RetentionPolicy.RUNTIME) @Target(ElementType.FIELD) @interface Inject {}

    static class Container {
        private final Map<Class<?>, Object> beans = new HashMap<>();
        @SuppressWarnings("unchecked")
        public <T> T getBean(Class<T> clazz) {
            return (T) beans.computeIfAbsent(clazz, c -> {
                try {
                    Object inst = c.getDeclaredConstructor().newInstance();
                    for (Field f : c.getDeclaredFields()) {
                        if (f.isAnnotationPresent(Inject.class)) {
                            f.setAccessible(true);
                            f.set(inst, getBean(f.getType()));
                        }
                    }
                    return inst;
                } catch (Exception e) { throw new RuntimeException(e); }
            });
        }
    }

    @Component static class Db { void connect() { System.out.println("DB connected"); } }
    @Component static class Repo { @Inject private Db db; void findAll() { db.connect(); } }

    public static void main(String[] args) {
        Container c = new Container();
        c.getBean(Repo.class).findAll();
        System.out.println("Singleton: " + (c.getBean(Repo.class) == c.getBean(Repo.class))); // true
    }
}
```

### 11.2 反射在主流框架中的应用

| 框架 | 反射应用场景 | 核心用法 |
|------|-------------|----------|
| **Spring IoC** | 注解/XML 配置 → 创建 Bean → 注入依赖 | `Class.forName()` → `Constructor.newInstance()` → `Field.set()` |
| **MyBatis** | ResultSet → 实体对象映射 | `Field.set()` 逐字段赋值 |
| **JUnit** | 扫描 `@Test` → 反射执行测试方法 | `Method.isAnnotationPresent()` → `Method.invoke()` |
| **Jackson / Gson** | 序列化/反序列化 | `Field.get()` / `Field.set()` |
| **Spring AOP** | 动态代理 | `Proxy.newProxyInstance()` / CGLIB `Enhancer` |

## 12. 反射的局限与替代方案

### 12.1 主要局限

| 局限 | 说明 |
|------|------|
| 性能差 | 比直接调用慢 10-50 倍 |
| 类型不安全 | 拼写错误、类型错误只在运行时暴露 |
| 破坏封装 | `setAccessible(true)` 绕过访问控制 |
| 安全限制 | JPMS 模块系统可能禁止反射 |
| 泛型擦除 | `List<String>` 运行时擦除为 `List` |

### 12.2 替代方案

| 场景 | 传统反射 | 现代替代 |
|------|----------|----------|
| 方法调用 | `Method.invoke()` | `MethodHandle`（JIT 可内联） |
| 字段原子操作 | `Field` + 同步 | `VarHandle`（JDK 9+, CAS） |
| 动态代理 | `Proxy.newProxyInstance()` | CGLIB / ByteBuddy |
| 编译期代码生成 | — | APT + JavaPoet（零反射开销） |
| 泛型类型 | 无法直接获取 | `TypeToken`（Gson） |

> ⚠️ 反射可绕过泛型约束插入错误类型数据。框架层应做好类型校验。

## 13. 面试高频考点

### 13.1 基础问题

**Q1: 获取 Class 对象的三种方式？**
- 类名`.class`（安全，不触发 static 块）| `对象.getClass()`（需实例）| `Class.forName("全类名")`（最灵活，触发 static 块）

**Q2: `getMethods()` 和 `getDeclaredMethods()` 的区别？**
- `getMethods()` 返回所有 public 方法（含继承的）；`getDeclaredMethods()` 返回本类全部方法（不含继承的，含 private）

**Q3: `setAccessible(true)` 做了什么？**
- 设置 override 标志为 true，JVM 跳过访问权限检查。风险：破坏封装，JPMS 下可能受限

**Q4: JDK 动态代理和 CGLIB 的区别？**
- JDK：基于接口生成 `$Proxy0` 实现类；CGLIB：基于继承生成子类（不能代理 final 方法）

### 13.2 进阶问题

**Q5: 反射性能开销？如何优化？**
- 开销：动态查找 + 装箱/拆箱 + 安全检查 + JIT 无法内联
- 优化：`setAccessible(true)` + 缓存 Method/Field + MethodHandle

**Q6: MethodHandle 和 Method 的区别？**
- MH 更快（JIT 可内联），有严格类型签名；Method 功能更全但性能差

**Q7: 如何获取泛型参数类型？**
- 运行时已擦除。使用 `ParameterizedType` + `TypeToken`（如 Gson 的 `TypeToken<T>`）

**Q8: `Class.forName()` 和 `ClassLoader.loadClass()` 区别？**
- `forName()` 默认执行 static 初始化块；`loadClass()` 不执行（延迟加载）

**Q9: InvocationHandler.invoke() 的 proxy 参数注意什么？**
- 不要在 proxy 上调用被代理的方法，会递归死循环

### 13.3 使用原则

```
┌─────────────────────────────────────────────┐
│          反射使用黄金原则                      │
├─────────────────────────────────────────────┤
│ 1. 优先直接调用 —— 编译期已知类型就不反射      │
│ 2. 缓存反射对象 —— Method/Field 创建成本高     │
│ 3. 限定框架层 —— 业务代码避免直接使用反射       │
│ 4. 最小权限 —— 仅对必需成员 setAccessible(true)│
│ 5. 显式异常处理 —— 反射异常必须精确处理         │
│ 6. 考虑替代方案 —— MethodHandle / APT / 字节码 │
└─────────────────────────────────────────────┘
```
