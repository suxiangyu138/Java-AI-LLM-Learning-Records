## 1. 面试高频题与答题框架

### 1.1 原理类

**Q1：Stream 是什么？和集合的区别？**

```text
① 定义：元素序列的函数式处理管道
② 区别：集合存数据、Stream 只处理（不存储）
③ 四大特性：惰性求值/非侵入/一次性/可并行
④ 类比：工厂流水线（过滤工位 → 加工工位 → 包装）
⑤ 金句：Stream 描述「数据怎么流动」——不是数据本身
```

**Q2：什么是惰性求值？**

```text
① 定义：中间操作不执行，遇到终止操作才触发
② 执行时序：逐元素流水线（非分阶段）
③ 价值：短路优化（limit/findFirst 找到即停）
④ 代价：无终止操作 = 白写
⑤ 示例：filter → map → limit(2)：处理到第 4 个元素就停
```

**Q3：中间操作和终止操作的区别？**

```text
① 中间操作：filter/map/sorted/distinct——返回新 Stream（惰性）
② 终止操作：collect/forEach/count/reduce——触发执行
③ 分类：无状态（filter/map）vs 有状态（sorted/distinct）
④ 短路终止：findFirst/anyMatch（结果确定即停）
⑤ 金句：中间操作建管道、终止操作开引擎
```

### 1.2 操作类

**Q4：map 和 flatMap 的区别？**

```text
① map：一对一转换（1 → 1）
② flatMap：一对多展开（1 → N）或扁平化
③ 场景：嵌套集合/对象内集合/每行拆词
④ 类比：map 换包装、flatMap 拆箱
⑤ 示例：List<List<String>> → flatMap → List<String>
```

**Q5：filter 和 takeWhile 的区别？**

```text
① filter：扫描全部元素（保留满足条件的）
② takeWhile：从头取到「第一个不满足」即停（短路）
③ 对比：filter 全扫；takeWhile 提前停
④ 场景：有序数据的范围截取（时间序列）
⑤ 金句：filter 扫全部、takeWhile 见好就收
```

**Q6：groupingBy 怎么用？常见下游收集器？**

```text
① 基本：按字段分组（Map<K, List<T>>）
② 下游：counting（计数）/summingInt（求和）/mapping（映射）
③ 多级：嵌套 groupingBy（状态 × 渠道）
④ 保序：LinkedHashMap 参数
⑤ 分区：partitioningBy（boolean 二分）
⑥ 金句：分组 + 下游 = 单次遍历完成统计
```

**Q7：Collectors 有哪些常用？**

```text
① 收集：toList/toSet/toMap（toMap 必须处理键冲突）
② 连接：joining（分隔符/前后缀）
③ 统计：summarizingInt（单次遍历全统计）
④ 分组：groupingBy/partitioningBy
⑤ 高级：teeing（双收集 Java 12+）/collectingAndThen（最终转换）
⑥ 金句：summarizing 一次遍历 vs 多次调用（性能）
```

### 1.3 并行类

**Q8：并行流是什么？什么时候用？**

```text
① 机制：parallelStream + commonPool（ForkJoinPool）
② 适用三条件：数据量大（10 万+）+ 无状态 + 计算密集
③ 实测：计算密集 3-5 倍；字符串拼接反而变慢（0.41 倍）
④ 禁用：小数据/有状态/顺序敏感/IO 密集/JDBC
⑤ 金句：并行不是银弹——条件满足 + JMH 实测
```

**Q9：并行流有什么陷阱？**

```text
① commonPool 全局共享：一个阻塞影响所有
② 共享集合：forEach 修改 List → AIOOBE
③ findFirst 并行变慢（顺序敏感）
④ 无限流 parallel：CPU 飙升
⑤ 禁止改 commonPool 系统属性
⑥ 解法：collect 收集 + findAny + 先 limit + 自定义池
```

**Q10：并行流和虚拟线程的区别？**

```text
① 问题不同：并行流=数据并行（压榨 CPU）；虚拟线程=大量阻塞（IO）
② 场景：纯计算用并行流；HTTP/DB/文件用虚拟线程
③ 实测：阻塞任务虚拟线程快 8 倍+
④ 金句：IO 密集 → 虚拟线程；计算密集 → 并行流
```

### 1.4 陷阱类

**Q11：Stream 能消费两次吗？**

```text
① 不能：一次性（二次终止操作抛 IllegalStateException）
② 原因：管道设计（重建成本低 + 状态管理）
③ 解法：重新创建流 / 先物化成集合
④ 金句：流用一次、集合用多次
```

**Q12：无限流怎么安全使用？**

```text
① 必须 limit 截断（否则死循环/OOM）
② Java 9+：iterate 带终止条件（更安全）
③ 先 limit 再 parallel（并行无限流危险）
④ 有状态操作（sorted）不能用于无限流
⑤ 金句：无限流 + limit = 安全；无限流无 limit = 灾难
```

**Q13：Lambda 捕获变量有什么限制？**

```text
① 必须 effectively final（声明后不再赋值）
② 修改即编译错误
③ 可变需求：原子类/数组 hack（不推荐）
④ 原因：并发安全（捕获的是值不是变量）
```

**Q14：toList() 和 collect(toList()) 的区别？**

```text
① toList()（Java 16+）：不可变列表（add 抛异常）
② collect(toList())（Java 8）：可变（通常 ArrayList）
③ 需要可变：collect(toCollection(ArrayList::new))
④ 金句：默认不可变更安全；需要修改显式指定
```

### 1.5 实战类

**Q15：用 Stream 做分组统计怎么写？**

```java
// 按状态分组 + 计数 + 求和
Map<OrderStatus, Long> count = orders.stream()
    .collect(Collectors.groupingBy(Order::getStatus, Collectors.counting()));
Map<OrderStatus, Integer> sum = orders.stream()
    .collect(Collectors.groupingBy(Order::getStatus,
             Collectors.summingInt(Order::getAmount)));
// 面试加分：summarizingInt 单次遍历全统计
```

**Q16：Stream 性能怎么优化？**

```text
① 短路：limit/findFirst（最廉价）
② 原始流：mapToInt（免装箱快 30-50%）
③ 操作顺序：filter/limit 前置、sorted 后置
④ 无中间集合：避免 collect 后又 stream
⑤ 聚合收集器：summarizing 单次遍历
⑥ JMH 实测验证：测量而非直觉
```

## 2. 代码题实战

**题 1：写出下面代码的输出**

```java
Stream.of(1, 2, 3, 4, 5)
    .filter(x -> x % 2 == 0)
    .map(x -> x * 10)
    .limit(2)
    .toList();
// 答案：[20, 40]（filter 出 2,4 → map 20,40 → limit 2）
```

**题 2：找出代码问题**

```java
// 代码 1：分组统计
Map<String, Long> count = orders.stream()
    .collect(Collectors.groupingBy(Order::getStatus, Collectors.counting()));
// 问题：无（正确）

// 代码 2：
List<String> result = list.stream().map(...);
// 问题：无终止操作（惰性——什么都不执行）
// 修复：加 toList()

// 代码 3：
list.parallelStream().forEach(s -> sharedList.add(s));
// 问题：共享非线程安全集合（并行必炸）
// 修复：collect(Collectors.toList())
```

**题 3：用 Stream 实现「按金额分组 + 每组平均」**

```java
Map<OrderStatus, Double> avgByStatus = orders.stream()
    .collect(Collectors.groupingBy(Order::getStatus,
             Collectors.averagingDouble(Order::getAmount)));
```

**题 4：字符串列表转 Map（id → name）**

```java
// 场景：userList → Map<id, name>
Map<String, String> idToName = users.stream()
    .collect(Collectors.toMap(User::getId, User::getName, (a, b) -> a));
```

**题 5：找出金额最大的订单**

```java
Order max = orders.stream()
    .max(Comparator.comparing(Order::getAmount))
    .orElseThrow(() -> new OrderNotFoundException());
```

## 3. 速查表

```text
创建：list.stream() / Arrays.stream(arr) / Stream.of(...) /
      Stream.iterate(seed, f).limit(n) / Stream.generate(s).limit(n) /
      Files.lines(path) / IntStream.range(a, b)

中间操作（惰性）：
├── 无状态：filter/map/flatMap/peek
├── 有状态：sorted/distinct/limit/skip/takeWhile/dropWhile

终止操作（触发）：
├── 短路：findFirst/findAny/anyMatch/allMatch/noneMatch
├── 非短路：collect/toList/forEach/count/min/max/reduce

Collectors：
├── toList/toSet/toMap/joining/groupingBy/partitioningBy
├── counting/summingInt/averagingDouble/summarizingInt
├── mapping/reducing/collectingAndThen/teeing

并行：parallelStream() / stream().parallel()——条件满足 + 实测
陷阱：一次性/惰性/副作用/无限流/空指针/final/共享状态
```

## 4. 五大常见误区

| # | 误区 | 真相 |
|---|------|------|
| 1 | 「Stream 一定比循环快」 | Stream 不加速——性能看任务性质与写法 |
| 2 | 「开了并行就快」 | 字符串拼接并行反而 0.41 倍——条件 + 实测 |
| 3 | 「流可以反复用」 | 一次性——二次消费抛异常 |
| 4 | 「toList 能随便改」 | Java 16+ 不可变——add 抛异常 |
| 5 | 「中间操作会执行」 | 惰性——没终止 = 白写 |

## 5. 一句话总结全系列

```text
01 原理：惰性求值/非侵入/一次性/可并行——流不是集合
02 操作：创建七方式 + 中间操作（filter/map/flatMap/sorted/limit）
03 收集：toList/toMap/groupingBy/summarizing/teeing
04 实战：八大模式（报表/清洗/分页/关联/TopN/批量/转换/树）
05 并行：commonPool + 三条件 + 陷阱 + 虚拟线程
06 性能：短路/原始流/操作顺序/聚合收集器 + JMH 实测
07 陷阱：十二陷阱 + 五步排查
08 面试：16 题框架 + 代码题 + 速查
```

> 🎯 **系列总结**：Stream 能力 = **原理（惰性/生命周期）× 操作（中间/终止）× 收集（Collectors）× 并行（何时用）× 性能（选型/测量）** 五维体系。2026 年心法：**可读性优先、测量而非直觉、简单 for 循环有时才是最佳方案**——成熟的标志不是「全用 Stream」，而是「知道什么时候不用」。
