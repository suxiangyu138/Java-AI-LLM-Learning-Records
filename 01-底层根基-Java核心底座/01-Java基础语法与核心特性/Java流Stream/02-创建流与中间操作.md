## 1. 创建流的方式

> **背景**：Stream 的数据源多样——集合、数组、生成器、文件、字符串。
> **目的**：掌握各种创建方式（按场景选对）。
> **适用范围**：所有 Stream 处理的开端。

```java
// ① 集合（最常用）
List<String> list = List.of("a", "b", "c");
list.stream();                    // 顺序流
list.parallelStream();            // 并行流

// ② 数组
int[] arr = {1, 2, 3};
Arrays.stream(arr);               // IntStream
Arrays.stream(arr, 1, 3);         // 范围 [1,3)

// ③ 直接值
Stream.of("a", "b", "c");         // 多个元素
Stream.of(arr);                   // ⚠️ 数组是单元素（对象）！

// ④ 生成器（无限流——必须 limit！）
Stream.generate(() -> Math.random()).limit(5);
Stream.iterate(0, n -> n + 2).limit(10);       // 0,2,4,...
Stream.iterate(0, n -> n < 100, n -> n + 1);   // Java 9+ 带终止条件

// ⑤ 文件（行处理）
Files.lines(Paths.get("app.log"));             // Stream<String>
Files.walk(Paths.get("src"));                  // 遍历目录

// ⑥ 字符串
"hello".chars();                  // IntStream（字符码点）

// ⑦ 范围（原始类型流）
IntStream.range(1, 10);           // [1,10)
IntStream.rangeClosed(1, 10);     // [1,10]
LongStream.range(1, 100);
```

> ⚠️ **数组陷阱**：`Stream.of(arr)` 把数组当**单个元素**（对象流）——想要元素流用 `Arrays.stream(arr)`。

## 2. 过滤操作

### 2.1 filter（过滤）

```java
// filter：保留满足条件的元素
List<Order> paid = orders.stream()
    .filter(o -> o.getStatus() == PAID)
    .toList();

// 空值过滤（生产必用！）
list.stream()
    .filter(Objects::nonNull)          // 过滤 null
    .toList();

// 多条件组合
orders.stream()
    .filter(o -> o.getAmount() > 100)
    .filter(o -> o.getStatus() == PAID)   // 链式（可读性）
    .toList();

// 自定义 Predicate 组合
Predicate<Order> big = o -> o.getAmount() > 100;
Predicate<Order> paid = o -> o.getStatus() == PAID;
orders.stream().filter(big.and(paid)).toList();   // 组合
```

### 2.2 takeWhile / dropWhile（Java 9+）

```java
// takeWhile：从头取「满足条件」的元素，遇到不满足即停
// （与 filter 不同：filter 扫全部，takeWhile 短路）
List<Integer> list = List.of(1, 2, 3, 4, 1, 2);
list.stream().takeWhile(x -> x < 3).toList();   // [1, 2]（到 3 停）
list.stream().filter(x -> x < 3).toList();      // [1, 2, 1, 2]（全扫）

// dropWhile：跳过开头的满足元素（互补）
list.stream().dropWhile(x -> x < 3).toList();   // [3, 4, 1, 2]

// 场景：有序数据的范围截取（时间序列）
logs.stream()
    .takeWhile(log -> log.time < endTime)
    .dropWhile(log -> log.time < startTime)
```

## 3. 转换操作

### 3.1 map（一对一转换）

```java
// map：每个元素转换（一对一）
List<String> names = users.stream()
    .map(User::getName)
    .toList();

// 类型转换
List<Integer> lengths = strings.stream()
    .map(String::length)
    .toList();

// ⚠️ 不要在有副作用（修改外部状态）
// ❌ 错误：map 中修改外部 List
List<String> result = new ArrayList<>();
list.stream().map(s -> { result.add(s); return s; });  // 副作用！
// ✅ 正确：用终止操作收集
```

### 3.2 flatMap（一对多/扁平化）

```java
// flatMap：每个元素展开为多个元素（扁平化）
// 场景 1：嵌套集合
List<List<String>> nested = List.of(List.of("a", "b"), List.of("c"));
nested.stream().flatMap(Collection::stream).toList();   // [a, b, c]

// 场景 2：对象内集合展开
List<Order> orders = ...;
List<Item> allItems = orders.stream()
    .flatMap(o -> o.getItems().stream())
    .toList();

// 场景 3：文件多行（每行再拆词）
Files.lines(path)
    .flatMap(line -> Arrays.stream(line.split("\\s+")))
    .distinct()
    .toList();

// flatMap 与 map 对比
// map：1 → 1（转换）
// flatMap：1 → N（展开）或 1 → 0（过滤空）
```

### 3.3 类型转换（mapToInt 等）

```java
// 转原始类型流（性能优化——免装箱）
list.stream().mapToInt(String::length).sum();     // IntStream
list.stream().mapToDouble(Order::getAmount).average();

// 原始类型流转回
IntStream.range(0, 10).boxed().toList();          // List<Integer>

// ⚠️ 注意：对象流 → 原始流是 mapToInt；原始流 → 对象流是 boxed
```

## 4. 去重与排序

### 4.1 distinct（去重）

```java
// 基本去重（按 equals）
List<String> unique = list.stream().distinct().toList();

// 对象按字段去重（自定义——distinct 不支持字段！）
// 方法 1：先 map 字段再 distinct
List<String> uniqueIds = orders.stream()
    .map(Order::getOrderId)
    .distinct()
    .toList();

// 方法 2：toMap（保一个对象）
Map<String, Order> byId = orders.stream()
    .collect(Collectors.toMap(Order::getOrderId, o -> o, (a, b) -> a));

// ⚠️ distinct 是有状态操作（内部 Set 记录）
```

### 4.2 sorted（排序）

```java
// 自然排序（元素实现 Comparable）
list.stream().sorted().toList();

// 自定义排序（Comparator）
orders.stream()
    .sorted(Comparator.comparing(Order::getAmount))           // 升序
    .sorted(Comparator.comparing(Order::getAmount).reversed()) // 降序
    .toList();

// 多级排序
orders.stream()
    .sorted(Comparator.comparing(Order::getStatus)
        .thenComparing(Order::getAmount, Comparator.reverseOrder()))
    .toList();

// null 处理（排序遇到 null 会 NPE）
list.stream()
    .sorted(Comparator.nullsLast(Comparator.naturalOrder()))
    .toList();

// ⚠️ sorted 是「有状态 + 全量」操作：
// ① 需要读完全部元素才能排序（惰性失效）
// ② 无限流上不能用（永远等不完）
```

## 5. 切片操作

### 5.1 limit / skip

```java
// limit：取前 N 个（短路操作！）
list.stream().limit(3).toList();      // 前 3 个

// skip：跳过前 N 个
list.stream().skip(2).toList();       // 去掉前 2 个

// 分页（传统方式）
int page = 0, size = 10;
list.stream().skip((long) page * size).limit(size).toList();

// ⚠️ limit 的短路价值（性能关键）：
// list.stream().filter(...).limit(3) → 找到 3 个就停
// （配合无限流：Stream.iterate(...).limit(10) 安全截断）
```

### 5.2 无限流的正确使用

```java
// ✅ 正确：无限生成 + limit 截断
Stream.iterate(0, n -> n + 1)
    .limit(10)
    .toList();                        // [0..9]

// ✅ Java 9+：带终止条件的 iterate（更安全）
Stream.iterate(0, n -> n < 100, n -> n + 1).toList();

// ✅ Fibonacci（无限 + 截断）
Stream.iterate(new int[]{0, 1}, f -> new int[]{f[1], f[0] + f[1]})
    .limit(10)
    .map(f -> f[0])
    .toList();                        // [0,1,1,2,3,5,...]

// ❌ 危险：无限流 + 无截断 = 死循环/OOM
// Stream.iterate(0, n -> n + 1).forEach(System.out::println);  // 无限！
```

## 6. 调试操作 peek

```java
// peek：查看中间结果（调试专用——不修改数据）
list.stream()
    .peek(x -> System.out.println("filter 前: " + x))
    .filter(x -> x > 2)
    .peek(x -> System.out.println("filter 后: " + x))
    .toList();

// ⚠️ peek 的注意：
// ① 是中间操作（无终止操作不执行！）
// ② 并行流下输出顺序不确定
// ③ 不要在其中修改元素（副作用——流模型破坏）
// ④ 生产代码应移除（调试痕迹）

// 更好的调试：日志形式
list.stream()
    .peek(x -> log.debug("处理元素: {}", x))
    .filter(...)
    .toList();
```

## 7. 有状态操作的注意

### 7.1 有状态 vs 无状态

```text
无状态操作（每个元素独立）
├── filter / map / flatMap / peek / limit（近似）

有状态操作（需记录状态）
├── distinct（记录已见元素）
├── sorted（记录全部元素）
├── limit / skip（记录计数）
├── takeWhile / dropWhile（记录条件状态）
└── ⚠️ 并行流下的有状态操作：正确性依赖实现（非线程安全状态）
```

### 7.2 并行流的操作顺序注意

```text
并行流中的操作顺序影响
├── ① sorted 在并行流中开销更大（合并排序）
├── ② distinct 在并行流中正确但慢（全局去重）
├── ③ findFirst 在并行流中反而慢（顺序敏感）
├── ④ 无状态操作（filter/map）并行收益最大
└── ⑤ 金句：并行适合「无状态 + 计算密集」——有状态先串行想清楚
```

## 8. 核心要点

> 🎯 **核心要点**：
> 1. 创建七方式：集合/数组/值/生成器/文件/字符串/范围——**数组用 Arrays.stream（Stream.of 是单元素陷阱）**
> 2. filter 扫全部 vs takeWhile 短路（有序数据截取用 takeWhile）
> 3. map 一对一 vs flatMap 扁平化（嵌套集合/对象内集合）
> 4. distinct 按字段去重：先 map 字段或 toMap；sorted 有状态全量（无限流禁用）
> 5. limit 短路是性能关键：配合无限流安全截断（iterate + limit）
> 6. peek 只调试不修改；有状态操作在并行流中开销大
> 7. 操作顺序：filter/limit 前置、sorted 后置
