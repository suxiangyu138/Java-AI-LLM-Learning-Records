## 1. 类与对象的概念边界

**类（Class）**：对一类事物的抽象，描述"有哪些属性、哪些行为"。类是静态的，存在于编译期产生的字节码与运行期的方法区（元空间）中，一份类定义全局共享。

**对象（Object/Instance）**：类的具体实例，在堆中独占一份内存，携带自己的状态。

| 维度 | 类 | 对象 |
|------|----|----|
| 本质 | 抽象模板 / 数据类型 | 具体实例 / 内存数据块 |
| 存放位置 | 方法区（元空间） | 堆（Heap） |
| 数量 | 一份（按类加载器） | 任意多份 |
| 生命周期 | 与类加载器同寿 | 由引用链决定，GC 回收 |

```java
public class User {          // 类：模板
    private String name;     // 实例字段：每个对象一份

    public User(String name) { this.name = name; }

    public String getName() { return name; }   // 行为：所有对象共享方法字节码
}

User u1 = new User("张三");   // 对象 1
User u2 = new User("李四");   // 对象 2，与 u1 数据独立、方法共享
```

> 💡 实例方法只有一个副本，通过 `this` 区分"当前调用者是谁"——这是理解内存布局的关键。

## 2. new 一个对象的完整流程

```text
User u = new User("张三");
                    │
                    ▼
  1. 类加载（首次）: 验证 → 准备（static 变量零值）→ 解析 → 初始化（static 块执行）
                    │
                    ▼
  2. 分配内存: 指针碰撞或空闲列表，在堆中分配一块连续内存
                    │
                    ▼
  3. 零值初始化: 实例字段默认值（null / 0 / false），保证字段在使用前有确定值
                    │
                    ▼
  4. 设置对象头: Mark Word（锁状态、hashCode、GC 分代年龄）+ 类型指针（指向类元数据）
                    │
                    ▼
  5. 实例块与构造器: 按序执行实例初始化块 → 构造器体，字段赋值真正生效
                    │
                    ▼
  6. 返回引用: 栈上变量 u 持有堆对象地址（OOP 指针）
```

```java
public class Demo {
    static { System.out.println("1.静态块：类加载阶段执行一次"); }        // 第一步
    { System.out.println("3.实例块：每次 new 都执行"); }                  // 第三步
    private int count = 1;                                                // 字段初始化也是"实例块"的一部分

    public Demo() { System.out.println("4.构造器"); }                     // 第四步

    public static void main(String[] args) {
        System.out.println("2.main 开始");
        new Demo();   // 输出 3 → 4
        new Demo();   // 静态块不再执行，只输出 3 → 4
    }
}
// 输出顺序：1.静态块 → 2.main 开始 → 3.实例块 → 4.构造器 → 3.实例块 → 4.构造器
```

> ⚠️ 逃逸分析 + 标量替换：JIT 编译期若发现对象不逃逸出方法，会把对象拆成标量直接分配在栈上，`new` 不必然发生在堆。这属于 JVM 优化，不影响语义理解。

## 3. JVM 内存视角：对象与引用

| 内存区域 | 存放内容 | 特点 |
|---------|---------|------|
| 虚拟机栈（栈帧） | 局部变量、方法参数、引用（对象地址）、返回地址 | 线程私有，方法调用即压栈 |
| 堆（Heap） | 对象本体、数组、实例字段数据 | 线程共享，GC 主战场，分新生代/老年代 |
| 方法区（元空间） | 类元数据、静态变量（JDK 7+ 起对象在堆）、常量池、方法字节码 | 线程共享，默认受本机内存限制 |

```java
public void test() {
    int i = 10;                 // 栈帧局部变量表：直接存值
    User u = new User("张三");  // 栈上存引用(地址)，堆上存对象数据
    u = null;                   // 切断引用，对象成为垃圾，等待 GC
}
```

**引用与对象的三种关系**：

- **强引用**：`User u = new User()`，只要强引用存在，对象永不回收，OOM 元凶之一。
- **软引用**（`SoftReference`）：内存不足时回收，适合做缓存（图片、配置）。
- **弱引用**（`WeakReference`）：GC 扫描到即回收，ThreadLocal 的 key 即弱引用，用于防泄漏。

| 引用类型 | 回收时机 | 典型场景 |
|---------|---------|---------|
| 强引用 | 永不（除非断开） | 日常变量 |
| 软引用 | 内存将要溢出时 | 内存敏感的缓存 |
| 弱引用 | 每次 GC | ThreadLocal key、缓存兜底 |
| 虚引用 | 随时，主要用于对象回收跟踪 | 堆外内存（DirectByteBuffer）回收通知 |

> 🎯 **核心要点**：写代码操作的是"引用"而非对象本身；方法间传参传的是引用副本，因此"对象内状态可被修改、引用重新赋值不影响调用方"。

## 4. 三类变量成员对比

| 维度 | 成员变量（实例字段） | 静态变量（类变量） | 局部变量 |
|------|--------------------|------------------|---------|
| 归属 | 每个对象一份 | 整个类一份（JDK 7+ 对象在堆） | 方法栈帧 |
| 生命周期 | 随对象创建/回收 | 随类加载/卸载 | 随方法调用/返回 |
| 默认值 | 有（null/0/false） | 有 | **无，必须显式初始化** |
| 访问方式 | 实例方法内直接访问，静态上下文需 `对象.字段` | `类名.字段`（推荐） | 直接使用 |

```java
public class Counter {
    private int instanceCount;       // 实例字段：每个 Counter 对象各一个
    private static int classCount;   // 静态字段：全类共享一个

    public void increment() {
        int local = 0;               // 局部变量：必须初始化才能使用
        instanceCount++;
        classCount++;
        local++;
        // System.out.println(local); // local 已赋值，可以读取
    }
}
```

> ⚠️ 局部变量未初始化直接使用是编译错误（`variable might not have been initialized`）；成员变量有默认值，但业务上仍建议显式初始化或经构造器赋值，避免"隐式 null"。

## 5. this 关键字：两种语义

**语义一：当前对象引用**——区分实例字段与局部变量、方法内转发：

```java
public class Person {
    private String name;

    public Person(String name) {
        this.name = name;      // 左侧是实例字段，右侧是参数
    }

    public Person withName(String name) {
        this.setName(name);    // 显式强调调用当前对象的方法
        return this;           // 链式调用：builder 风格依赖返回 this
    }
}
```

**语义二：构造器重载调用**——必须是构造器**第一条语句**：

```java
public class Person {
    private String name;
    private int age;

    public Person() {
        this("默认名", 0);     // 必须第一行，this(...) 调用重载构造器
    }

    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

> ⚠️ **易错点**：`this` 和 `super` 不能在静态上下文（static 方法、静态块）中使用——静态上下文没有"当前对象"；`this(...)` 与 `super(...)` 只能二选一且必须放第一行。

## 6. static 的本质与使用场景

**本质**：`static` 成员属于"类"而不是"对象"，随类加载初始化一次，全局共享。静态成员不能访问实例成员（静态方法没有 `this`，无法确定是哪个对象的字段）。

| 用法 | 说明 | 典型场景 |
|------|------|---------|
| 静态变量 | 类级别状态，一份 | 全局计数、常量池持有（`public static final`） |
| 静态方法 | 不依赖实例状态的行为 | 工具方法（`Math`、`Collections`）、工厂方法 |
| 静态块 | 类加载时执行一次，可给静态变量赋值 | 读取配置文件初始化常量 |
| 静态内部类 | 不持有外部类引用的嵌套类 | Builder、单例持有者 |

```java
public class Config {
    private static final Map<String, String> SETTINGS = new HashMap<>();
    public static final String APP_NAME = "MyApp";

    static {
        // 类加载时执行一次：从配置文件装载
        SETTINGS.put("timeout", "3000");
        System.out.println("Config 类已加载");
    }

    public static String get(String key) { return SETTINGS.get(key); }   // 工具方法
}
```

**static 的三大陷阱**：

1. **滥用静态状态 = 全局变量**：多线程下静态可变字段是并发安全的重灾区（需要加锁或使用 `ThreadLocal`）。
2. **静态方法不能重写**：子类声明同名同参静态方法叫"隐藏（hiding）"，调用方取决于引用类型而非对象实际类型，极易踩坑。
3. **静态代码块中的异常**：静态块抛 `ExceptionInInitializerError` 会导致类无法使用，且该错误不可捕获恢复。

## 7. 对象生命周期与可达性

```text
创建（new） → 使用（读字段/调方法） → 不再可达（引用断开/出作用域） → 可达性分析标记 → GC 回收
                                                                              ↓
                                                                    finalize() 已废弃（JDK 9 标记弃用，JDK 18 默认禁用）
```

GC 判断对象是否存活的算法是**可达性分析**：从 GC Roots（栈帧局部变量、静态字段、JNI 引用等）出发遍历，不可达的对象即垃圾。

> 💡 **finalize 为什么不建议用**：执行时机不确定、且对象可能"复活"（再次可达）引发更复杂的问题。资源释放请用 try-with-resources。

**内存泄漏的经典场景**（与对象生命周期强相关）：

```java
// 静态集合持有对象 → 对象永远可达 → 泄漏
private static final List<Order> CACHE = new ArrayList<>();  // 只加不删就是泄漏

// 内部类隐式持有外部类引用 → 外部类无法回收（详见 07 模块）
// ThreadLocal 键为弱引用但值为强引用 → 必须 remove()（详见并发专题）
```

## 8. 对象相等性：equals 与 hashCode

`Object` 是所有类的终极父类（没有 `extends` 时默认继承），提供了三个被重写率最高的方法：

| 方法 | 默认实现 | 重写契约 |
|------|---------|---------|
| `equals` | 引用相等（`==`） | 自反、对称、传递、一致；与 `null` 比较返回 `false` |
| `hashCode` | 基于地址 | **equals 相等则 hashCode 必相等**（反之不必） |
| `toString` | `类名@哈希值` | 返回有意义的字符串描述 |

```java
public class Money {
    private final int amount;
    private final String currency;

    public Money(int amount, String currency) {
        this.amount = amount;
        this.currency = currency;
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;                    // 1. 同一对象直接返回
        if (o == null || getClass() != o.getClass()) return false;  // 2. 类型校验
        Money other = (Money) o;                       // 3. 强转
        return amount == other.amount
                && Objects.equals(currency, other.currency);   // 4. 逐字段比较
    }

    @Override
    public int hashCode() {
        return Objects.hash(amount, currency);         // 字段参与哈希
    }
}
```

> ⚠️ **两个必须记住的细节**：① `equals` 用 `getClass()` 还是 `instanceof` 决定是否允许子类相等（集合规范建议 `instanceof`，严格语义建议 `getClass()`）；② 重写 `equals` 不重写 `hashCode`，HashMap/HashSet 会表现诡异——因为先按 hash 找桶，再 `equals` 比较。JDK 16+ 的 `record` 自动实现了值相等（见 08 模块）。
