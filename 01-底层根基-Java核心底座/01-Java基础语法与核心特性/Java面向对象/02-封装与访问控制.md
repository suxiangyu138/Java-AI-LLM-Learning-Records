## 1. 封装是什么：状态、行为与不变量

**封装的本质**：把"数据（字段）"和"操作这些数据的行为（方法）"绑定在一个类里，并**对外隐藏实现细节**，只通过公开方法访问。

封装的三个层次含义：

1. **数据隐藏**：字段 `private`，外部无法直接读写，绕过不合法状态。
2. **行为封装**：把校验、日志、权限等逻辑收敛到方法内部，调用方只需关心"做什么"。
3. **不变量保护**（最核心）：对象在任何时刻都保持合法状态——余额不能为负、年龄不能为负、状态机的状态转换必须合法。

```java
public class BankAccount {
    private double balance;                 // 私有状态

    public void deposit(double amount) {    // 公开行为：带校验
        if (amount <= 0) {
            throw new IllegalArgumentException("存款金额必须为正数");
        }
        balance += amount;                  // 不变量：balance 永远 ≥ 0
    }

    public boolean withdraw(double amount) {
        if (amount <= 0 || amount > balance) {
            return false;                   // 余额不足：拒绝，不允许透支
        }
        balance -= amount;
        return true;
    }

    public double getBalance() { return balance; }   // 只读暴露
}
```

> 🎯 **核心要点**：如果字段是 `public`，外部代码可以绕过 `deposit()` 的校验直接 `account.balance = -1000`，不变量瞬间被破坏。封装保护的不是"秘密"，而是**对象的合法状态**。

## 2. 四档访问修饰符

| 修饰符 | 同类 | 同包 | 子类（跨包） | 任意类 | 设计意图 |
|:------:|:----:|:----:|:----------:|:------:|---------|
| `private` | ✅ | ❌ | ❌ | ❌ | 字段、内部实现细节 |
| `default`（不写） | ✅ | ✅ | ❌ | ❌ | 包内协作的组件（如包私有的工具类） |
| `protected` | ✅ | ✅ | ✅ | ❌ | 子类需要复用的成员（模板方法骨架） |
| `public` | ✅ | ✅ | ✅ | ✅ | 对外 API |

**使用原则**（从阿里 Java 开发手册吸收的规约）：

- 字段一律 `private`，不允许 `public` 字段（常量 `public static final` 除外）。
- 对外暴露的最小化：能 `private` 不 `default`，能 `default` 不 `protected`，能 `protected` 不 `public`。
- `protected` 是双刃剑：跨包子类可访问，意味着**继承者能看到内部结构**——它事实上打破了封装，仅用于"明确要被子类使用"的成员。

```java
public class TemplateBase {
    private String secret;                    // 只属于本类
    void packageHelper() { }                  // 仅包内可用（同包协作）
    protected void hook() { }                 // 子类扩展点（模板方法模式）
    public void execute() {                   // 对外 API
        // 固定骨架...
        hook();                               // 骨架中调用扩展点
    }
}
```

> ⚠️ **protected 跨包陷阱**：`protected` 成员在**不同包**的子类中，只能通过"子类自身的引用"访问，不能通过"父类引用"访问其他对象。这是面试高频判断题。

```java
package p1;
public class Parent { protected int x; }

package p2;
public class Child extends Parent {
    void test() {
        this.x = 1;        // ✅ 子类自身引用可以
        Parent p = new Parent();
        // p.x = 1;        // ❌ 编译错误：不能通过父类引用访问 protected 成员
    }
}
```

## 3. getter / setter 设计规范

### 3.1 四类典型设计

| 设计 | 写法 | 适用场景 |
|------|------|---------|
| 纯只读 | 只有 getter，无 setter | 不可变值、由构造器赋值的字段 |
| 校验型 | setter 内做合法性校验 | 年龄、金额、状态等有约束字段 |
| 脱敏型 | getter 返回处理后的值 | 手机号、身份证、密码等敏感信息 |
| 内部可变 | 无 getter/setter，方法内修改 | 计数器、状态机内部状态 |

### 3.2 脱敏与校验的完整示例

```java
public class UserProfile {
    private String phone;         // 原始数据仅内部持有
    private int age;

    public void setPhone(String phone) {
        if (phone == null || !phone.matches("^1\\d{10}$")) {
            throw new IllegalArgumentException("手机号格式不合法");
        }
        this.phone = phone;
    }

    public String getPhone() {
        // 脱敏：13812345678 → 138****5678，日志与接口返回用
        return phone.replaceAll("(\\d{3})\\d{4}(\\d{4})", "$1****$2");
    }

    public void setAge(int age) {
        if (age < 0 || age > 150) {
            throw new IllegalArgumentException("年龄非法: " + age);
        }
        this.age = age;
    }
}
```

### 3.3 引用类型字段的防御性拷贝

> ⚠️ 对 `List`、`Map`、数组等可变引用类型，直接返回内部引用会让调用方**绕过封装修改内部状态**。

```java
public class Order {
    private final List<String> items = new ArrayList<>();

    public void addItem(String item) { items.add(item); }

    // 错误：外部拿到同一 List，可以自由增删
    public List<String> getItemsDirect() { return items; }

    // 正确：返回不可变副本
    public List<String> getItems() { return Collections.unmodifiableList(items); }

    // 或者返回副本（适合外部需要独立修改的场景）
    public List<String> getItemsCopy() { return new ArrayList<>(items); }
}
```

## 4. package 与 import：包级可见性

- **package**：命名空间与代码组织单元，也是 `default` 权限的作用域边界。包名规范：域名倒序 + 模块名（`com.company.order.service`）。
- **import**：引入其他包的类型；`import static` 引入静态成员（如 `import static java.util.Objects.requireNonNull`）。
- **同包免 import**：同包类直接使用。
- **默认包（无 package）**：企业项目禁止使用——无法被其他包引用，也不利于模块化。

```java
package com.example.user.service;

import java.util.List;
import static java.util.stream.Collectors.toList;   // 静态导入：直接写 toList()

public class UserService {
    public List<User> queryAll() {
        return userDao.findAll().stream().map(...).collect(toList());
    }
}
```

> 💡 JDK 25（JEP 511）新增**模块导入**：`import module java.base;` 可一次导入整个模块的公开类型，减少 import 行数——属于语法糖，不影响访问控制语义。

## 5. 不可变对象：封装的终极形态

不可变对象一旦创建，状态永不改变。它是线程安全的天然实现，是并发编程和函数式风格的基石（`String`、`BigDecimal`、`LocalDate` 都是不可变类）。

**实现五要素**：

1. 类声明 `final`（防止子类破坏不可变性）；
2. 所有字段 `private final`；
3. 不提供任何 setter；
4. 构造器对所有字段赋值；
5. 字段若为可变引用类型（List、数组），用**防御性拷贝**。

```java
public final class Money {
    private final int amount;
    private final String currency;
    private final BigDecimal[] history;   // 可变数组

    public Money(int amount, String currency, BigDecimal[] history) {
        this.amount = amount;
        this.currency = currency;
        this.history = history == null ? null : history.clone();  // 防御性拷贝
    }

    public int getAmount() { return amount; }

    public BigDecimal[] getHistory() {
        return history == null ? null : history.clone();          // 返回拷贝
    }

    public Money add(Money other) {        // 运算产生新对象，而不是改自己
        return new Money(amount + other.amount, currency, history);
    }
}
```

> 🎯 **权衡取舍**：不可变对象无状态修改，每次变化都新建对象——短生命周期对象多，依赖 JVM 逃逸分析与分代 GC 消化成本；换来的是**免锁并发安全**与**可缓存可共享**（如缓存 `Color` 常量）。JDK 16+ 的 `record` 一行声明即可获得上述五要素（见 08 模块）。

## 6. 封装常见错误与反模式

| 反模式 | 表现 | 后果 | 修正 |
|--------|------|------|------|
| 字段全 public | 外部直接赋值 | 不变量可被破坏 | 字段 private + 方法 |
| 上帝 setter | 每个字段都开放 setter | 对象可被改得面目全非 | 只保留必要的修改入口，优先构造器注入 |
| 无脑 getter | 为属性而属性，无业务含义 | 类退化成数据容器 | 思考"行为"而非"数据" |
| 返回内部引用 | getter 直接返回 List | 封装名存实亡 | 不可变视图 / 拷贝 |
| 方法级全 public | 内部逻辑全部公开 | API 面过大，难以演进 | 按职责缩小可见性 |
| 用 public 常量表状态 | `public static final int STATE_A = 1` | 魔法数字，无类型安全 | 枚举（Java 5+）或 sealed 层次 |

## 7. 从封装到 record：现代简化

对于**纯数据载体**（DTO、VO、查询参数），传统"字段 + getter/setter + equals/hashCode/toString"会产生几十行样板代码。Java 16+ 的 `record` 用一行声明同时获得：私有 final 字段、构造器、访问器、值相等的 `equals/hashCode`、`toString`。

```java
// 传统写法：约 40 行样板代码
public final class UserDto {
    private final String name;
    private final int age;
    public UserDto(String name, int age) { this.name = name; this.age = age; }
    public String name() { return name; }
    // equals / hashCode / toString ... 30 行
}

// record 写法：一行
public record UserDto(String name, int age) { }
```

> ⚠️ record 是"值语义"数据载体，不是"状态模型"——业务行为复杂、状态可变的对象（如银行账户）仍然需要传统封装。**封装的思想没有变，只是样板代码被语言吸收了**（详见 08 模块）。
