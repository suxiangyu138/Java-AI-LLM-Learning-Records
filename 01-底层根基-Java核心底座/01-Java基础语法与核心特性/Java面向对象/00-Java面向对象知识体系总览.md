## 3. 为什么必须学透面向对象

1. **一切框架的底层语言**：Spring 的 IoC 容器是「封装 + 反射 + 工厂」的组合，MyBatis 的 Mapper 代理是「接口 + 动态代理」，JUC 的工具类大量使用「组合 + 模板方法」——不懂 OOP 只能背用法，永远看不到框架的骨架。
2. **面试必考且淘汰率高**：HashMap 的定位算法、Spring 的 Bean 生命周期、AQS 的模板方法，全部建立在「封装、继承、多态、初始化顺序」之上。重载与重写、接口与抽象类、`this` 与 `super` 是面试区分度最高的基础题。
3. **从「写代码」到「设计代码」的分水岭**：封装把"数据 + 行为"绑定并保护不变量；多态让代码面向抽象编程；SOLID 原则把经验沉淀成可传授的决策规则。没有 OOP，设计模式无从谈起。
4. **现代 Java 正在重塑 OOP 的边界**：record 取代一半的 POJO 手写量、密封类把"继承的开放性"变成"受控的穷尽性"、模式匹配让多态从"方法分派"延伸到"数据分派"——老的 OOP 教材没有这部分，本体系补齐。

## 4. 核心概念速查

### 4.1 三大特性一句话

| 特性 | 一句话定义 | 核心机制 | 关键字/手段 |
|------|-----------|---------|------------|
| 封装 | 隐藏内部状态与实现细节，仅暴露安全接口 | 访问控制 + getter/setter + 不变量保护 | `private`、`public` |
| 继承 | 子类复用父类成员并扩展，形成 is-a 关系 | 单继承链、`super`、方法重写 | `extends`、`super`、`final` |
| 多态 | 同一行为在不同对象上呈现不同表现 | 动态绑定（vtable）+ 重载（静态分派） | `override`、`overload` |

### 4.2 关键字速查

| 关键字 | 含义 | 典型使用位置 | 易错点 |
|--------|------|-------------|--------|
| `this` | 当前对象引用；构造器重载调用 | 实例方法、构造器 | 静态上下文不能用 |
| `super` | 父类引用；父类构造器调用 | 实例方法、构造器首行 | 必须是构造器第一条语句 |
| `static` | 类级别成员，随类加载 | 静态变量/方法/块 | 静态方法不能访问实例成员 |
| `final` | 类不可继承 / 方法不可重写 / 变量不可变 | 任意位置 | 引用不可变 ≠ 对象不可变 |
| `abstract` | 抽象类 / 抽象方法 | 类、方法 | 抽象方法不能有方法体 |
| `extends` | 类继承类 | 类声明 | 单继承 |
| `implements` | 类实现接口 | 类声明 | 可多实现 |
| `instanceof` | 类型判断 | 向下转型前 | 与泛型擦除有关 |
| `record` | 不可变数据载体 | 类声明 | Java 16+ |
| `sealed` | 受控继承 | 类/接口声明 | Java 17+，permits 限定 |

### 4.3 访问修饰符权限表

| 修饰符 | 同类 | 同包 | 子类（跨包） | 任意类 |
|:------:|:----:|:----:|:----------:|:------:|
| `private` | ✅ | ❌ | ❌ | ❌ |
| `default`（包私有） | ✅ | ✅ | ❌ | ❌ |
| `protected` | ✅ | ✅ | ✅ | ❌ |
| `public` | ✅ | ✅ | ✅ | ✅ |

## 5. 与周边知识的关系

```text
                    ┌── JVM 体系（内存模型、类加载、GC）—— 01 的内存视角
                    ├── 泛型 / 反射 / 注解 —— 框架如何"看穿"封装读写类
Java 面向对象 ──────┼── Lambda 表达式 —— 接口的现代用法（函数式接口）
                    ├── Stream / Optional —— 声明式处理对象集合
                    ├── 设计模式 —— 面向对象原则的落地（09 衔接）
                    └── Spring 全家桶 —— 工厂 + 代理 + 模板方法的大成者
```

- **往上走（底层）**：面向对象的"对象"最终是 JVM 堆里的一块内存——理解引用、GC、逃逸分析需要内存模型；`new` 的过程本质是类加载 + 内存分配。
- **往旁走（语法）**：泛型与接口结合定义强类型契约；Lambda 是"接口即行为"的极致表达；注解 + 反射让框架在运行时读取类的结构。
- **往高走（设计）**：SOLID 原则 → 设计模式 → 领域驱动设计（DDD）是同一思想的三层递进，09 模块是这条路的入口。

## 6. 学习路线推荐

**路线一：入门夯实（3~5 天，对应模块 01-04）**
类与对象 → 封装 → 继承 → 多态，每个概念必须配合手写代码验证；重点吃透初始化顺序、重写规则、转型规则这三个高频考点。

**路线二：进阶深化（1 周，对应模块 05-08）**
抽象类与接口（重点看演进史，理解为什么接口越来越"厚"）→ 构造器与单例 → 内部类 → 记录类/密封类/模式匹配；用 sealed + record + switch 重构一个状态机练手。

**路线三：设计升华（持续，对应模块 09-10）**
SOLID 五原则逐个找真实反例与正例 → 模式速览并手写策略与模板方法 → 面试模块做自测；之后进入设计模式专题与 Spring 源码。

> 🎯 **核心要点**：面向对象不是语法清单，而是一套"如何组织代码以应对变化"的思维。语法 3 天可学完，原则需在项目中反复验证。

## 7. 快速自测 10 题

1. `new Object()` 完整经过哪些步骤？对象在 JVM 的哪个区域，引用在哪个区域？
2. `static` 方法里为什么不能直接用 `this`？
3. `protected` 修饰的成员，子类在**不同包**中如何访问？（提示：不能通过父类引用在子类外部访问）
4. 子类构造器为什么必须调用父类构造器？如果不写会怎样？
5. 静态块、实例块、父类构造器、子类构造器的执行顺序？
6. 重写父类方法时，访问权限、返回值、异常各有何限制？
7. 接口中的变量为什么默认是 `public static final`？
8. 为什么 Java 不支持多继承？
9. 匿名内部类访问局部变量为什么要求 `effectively final`？
10. 什么场景该用 `record` 而不是普通类？什么场景反而不能用？
