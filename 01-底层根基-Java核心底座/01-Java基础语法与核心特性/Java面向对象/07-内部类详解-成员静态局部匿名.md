# 07 内部类详解：成员 / 静态 / 局部 / 匿名

## 1. 为什么需要内部类

1. **强关联逻辑的聚合**：只有外部类才关心的辅助逻辑放在内部，避免外部命名空间被无关类污染；
2. **访问外部私有成员**：内部类天然可以访问外部类的 private 字段与方法，无需 getter 暴露；
3. **多重行为实现**：单继承限制下，内部类可以"各自继承不同父类/实现不同接口"，组合出多重能力；
4. **回调与事件**：事件监听器、回调处理器与业务类生命周期绑定，内部类表达"这个类属于谁"。

```java
public class OrderProcessor {
    private final List<String> auditLog = new ArrayList<>();

    public void process(Order order) {
        new AuditTask().run(order);       // 内部类直接用外部私有成员
    }

    // 只服务 OrderProcessor 的辅助逻辑，外部不可见
    private class AuditTask {
        void run(Order order) {
            auditLog.add(order.getId());  // ✅ 直接访问外部类私有字段
            notifyOrderChange();          // ✅ 直接调用外部类私有方法
        }
    }
}
```

## 2. 四种内部类对比总表

| 维度 | 成员内部类 | 静态内部类 | 局部内部类 | 匿名内部类 |
|------|:---------:|:---------:|:---------:|:---------:|
| 定义位置 | 类成员 | 类成员（static） | 方法/代码块内 | 方法/代码块内，无名字 |
| 是否持有外部类引用 | ✅ 隐式持有 | ❌ 不持有 | ✅（effectively final 变量） | ✅ |
| 是否可以定义静态成员 | ❌（JDK 16+ 允许静态常量） | ✅ | ❌（JDK 16+ 允许常量） | ❌ |
| 实例化方式 | `outer.new Inner()` | `new Outer.Inner()` | 方法内 `new` | `new 接口/类(){}` |
| 典型用途 | 辅助逻辑、回调 | Builder、嵌套数据结构、单例 Holder | 局部临时逻辑 | 一次性回调（已被 Lambda 替代） |
| 字节码文件 | `Outer$Inner.class` | `Outer$Inner.class` | `Outer$1Inner.class` | `Outer$1.class` |

```java
public class Outer {
    private int count;

    // 1. 成员内部类：必须依附外部实例
    class MemberInner {
        void bump() { count++; }                       // 隐式 Outer.this.count
    }

    // 2. 静态内部类：完全独立
    static class StaticInner {
        void work() { /* 无外部引用可用 */ }
    }

    public void test() {
        // 3. 局部内部类：作用域在方法内
        class LocalInner { void run() { } }
        LocalInner li = new LocalInner();
        li.run();

        // 4. 匿名内部类：无名字，一次性
        Runnable r = new Runnable() {
            @Override public void run() { }
        };
        r.run();
    }
}

// 使用
Outer o = new Outer();
Outer.MemberInner mi = o.new MemberInner();    // 成员内部类：外部实例.new
Outer.StaticInner si = new Outer.StaticInner(); // 静态内部类：普通 new
```

## 3. 成员内部类：隐式持有外部引用

**核心机制**：成员内部类编译后会生成一个 `this$0` 字段，指向创建它的外部类实例——这就是"内部类可以直接访问外部类私有成员"的原理。

```java
public class Outter {
    private String secret = "S3CRET";

    class Inner {
        void show() {
            System.out.println(secret);            // 等价于 Outter.this.secret
            System.out.println(Outter.this.secret);// 显式写法（重名时必需）
        }
    }
}
```

**重名遮蔽时的显式写法**：

```java
public class Outter {
    private String name = "outter";

    class Inner {
        private String name = "inner";
        void show() {
            System.out.println(name);             // inner
            System.out.println(Outter.this.name); // outter
        }
    }
}
```

> ⚠️ **关键代价**：成员内部类**必然**持有外部类引用。若内部类对象生命周期长于外部类对象（如被存入静态集合、注册为全局监听器），外部类对象将**无法被 GC 回收**——这是经典内存泄漏源（见第 7 节）。

## 4. 静态内部类：天然的嵌套容器

静态内部类不持有外部类引用，可以独立创建、拥有静态成员。两个经典用途：

**用途一：Builder 容器**（见 06 模块的 `HttpRequest.Builder`）。

**用途二：内部数据结构节点**（HashMap 的 `Node`、LinkedList 的 `Node` 都是如此设计——节点只服务于宿主容器，但无需访问容器实例）：

```java
public class LruCache<K, V> {
    static class Node<K, V> {          // 静态：节点不需要缓存实例引用
        final K key;
        V value;
        Node<K, V> prev, next;

        Node(K key, V value) { this.key = key; this.value = value; }
    }
}
```

> 🎯 **核心要点**：**能用静态内部类就别用成员内部类**——不持有外部引用意味着无泄漏风险、可独立测试、可定义静态成员。判断标准：内部类逻辑是否需要访问外部实例的字段/方法，不需要就是静态的。

## 5. 局部内部类与匿名内部类

**局部内部类**：定义在方法内的类，只能被所在代码块使用，且可访问**方法内的 `effectively final` 局部变量**（Java 8 起不再强制 `final` 声明，只要求赋值后不再改变）。

**匿名内部类**：局部内部类的极端形态——连名字都没有，必须实现/继承一个已存在的类型：

```java
public void process(List<String> names) {
    String prefix = "USER:";               // effectively final：匿名类可捕获

    // 匿名内部类：实现 Comparator
    names.sort(new Comparator<String>() {
        @Override
        public int compare(String a, String b) {
            return b.compareTo(a);         // 倒序
        }
    });

    // 匿名内部类：继承抽象类
    Thread t = new Thread(new Runnable() {
        @Override
        public void run() {
            System.out.println(prefix + names.size());
        }
    });
}
```

**为什么局部/匿名类只能捕获 effectively final 变量？** 因为捕获的是**值的副本**（编译期复制到内部类构造器）。若变量还能被修改，副本与原始变量就分叉了，语义混乱。语法层面：内部类修改捕获变量是编译错误（`Local variable ... defined in an enclosing scope must be final or effectively final`）。

## 6. 匿名内部类 vs Lambda

| 维度 | 匿名内部类 | Lambda |
|------|:---------:|:------:|
| 适用范围 | 任何类/接口 | 仅函数式接口（唯一抽象方法） |
| 编译产物 | 生成独立 class 文件 | `invokedynamic` + LambdaMetafactory 动态生成（见 Lambda 系统 04 模块） |
| `this` 指向 | 内部类自身 | **外层对象**（Lambda 没有自己的 this） |
| 捕获变量 | effectively final | 同左 |
| 实例化开销 | 每次 new 一个新类实例 | 非捕获型可复用单例（无状态 Lambda 全局共享） |
| 可读性 | 样板多 | 极简 |
| 扩展 | 可重写多个方法/新增字段 | 只能表达一个行为 |

```java
public class ThisDemo {
    Runnable anon = new Runnable() {
        @Override public void run() {
            System.out.println(this.getClass());  // 内部类自身（ThisDemo$1）
        }
    };

    Runnable lambda = () -> System.out.println(this.getClass());  // ThisDemo（外层）
}
```

> 🎯 **核心要点**：新代码中匿名内部类基本只用在"必须实现多方法接口"（如 `Comparator` 的多个方法）或"不能是函数式接口"的场景，其余一律用 Lambda——**this 语义差异**（Lambda 的 this 指向外层）是两者最容易踩的坑。

## 7. 编译产物与内存泄漏陷阱

**编译产物**：每个内部类独立成 class 文件，命名规则见第 2 节总表——多级嵌套是 `Outer$Inner$Deeper`，匿名类是 `Outer$1`、`Outer$2`（按出现顺序编号）。用 `javap -p Outer$Inner.class` 可以亲眼看到 `final Outer this$0` 字段（成员内部类）。

**内存泄漏场景一：内部类对象被外部持有**

```java
public class LeakDemo {
    private class Listener { void onChange() { /* ... */ } }

    private static final List<Listener> REGISTRY = new ArrayList<>();  // 静态集合

    public void register() {
        REGISTRY.add(new Listener());   // Listener 持有 this（LeakDemo），
    }                                   // 而 REGISTRY 是静态的 → LeakDemo 永不回收 → 泄漏！
}
```

**内存泄漏场景二：Android 经典——Activity 中的匿名 Handler**

```java
Handler handler = new Handler() {      // 匿名内部类隐式持有 Activity 引用
    @Override public void handleMessage(Message msg) { /* 更新 UI */ }
};
// 主线程 Looper 持有一个 MessageQueue → Message 持有 handler → 持有 Activity → Activity 无法回收
```

**防御手段**：

| 手段 | 说明 |
|------|------|
| 优先静态内部类 | 不持有外部引用，从源头解决 |
| 用 `WeakReference` 包装外部引用 | `static class Handler extends ...` + `WeakReference<Activity>` |
| 生命周期同步 | 内部类对象随外部对象一起销毁（注册/注销成对） |
| 使用完后清理静态集合 | `remove()` 或软引用集合 |
| 能 Lambda 就 Lambda | 非捕获 Lambda 复用单例，不产生引用链 |

> ⚠️ **序列化陷阱**：内部类默认是可序列化的（实现了 `Serializable`），但**成员内部类的序列化需要外部类也可序列化**，且内部类名称、字段在不同 JDK 间可能变化导致 `InvalidClassException`。内部类序列化属于反模式，如需传输请提取为顶层类或 record（见 08 模块）。
