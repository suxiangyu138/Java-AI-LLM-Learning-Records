## 1. 必背清单：先过这七道题

### 1.1 什么是面向对象？三大特性是什么？

**答题框架**：定义 → 三特性逐一展开 → 联系实际。

> 面向对象是一种编程范式：以"对象"为单位组织代码，对象 = 状态（字段）+ 行为（方法）。三大特性：**封装**——隐藏内部状态、暴露安全接口，通过访问修饰符与 getter/setter 保护不变量；**继承**——子类复用父类并扩展，表达 is-a 关系，Java 类单继承避免菱形问题；**多态**——同一行为不同表现，三要素是继承/实现关系、方法重写、父类引用指向子类对象，机制是运行期动态绑定（invokevirtual + 虚方法表）。

### 1.2 重载（Overload）和重写（Override）的区别？

见 04 模块第 6 节全景表，答题关键点：位置（同类 vs 父子类）、参数（必须不同 vs 必须相同）、分派时机（编译期 vs 运行期）、返回值（无关 vs 协变）、访问权限（无关 vs 不能更严格）。

### 1.3 抽象类和接口的区别？怎么选？

见 05 模块第 3 节十维对比表。答题关键点：**继承方式**（单继承 vs 多实现）、**成员**（任意字段+构造器 vs 常量+default/static/private 方法）、**语义**（is-a 骨架复用 vs can-do 行为契约）、**演化**（加抽象方法破坏子类 vs default 方法无损升级）。决策：接口定契约、抽象类沉淀骨架、两者组合（List/AbstractList/ArrayList 模式）。

### 1.4 子类构造器为什么要调用父类构造器？

**对象完整性**：子类对象的内存包含父类所有字段（含 private），这些字段必须由父类构造器完成初始化——子类无法直接访问父类 private 字段，只能委托 `super(...)`。Java 保证：构造器链从 Object 一路执行到当前类，且 `super()` 必须是子类构造器第一条语句。若不显式写，编译器插入无参 `super()`，父类无无参构造器则编译失败。

### 1.5 static 成员与实例成员的区别？静态方法能访问实例成员吗？

区别见 01 模块第 4 节表。**静态方法不能访问实例成员**——静态上下文没有 `this`，无法确定"哪个对象的字段"。反过来，实例方法可以访问静态成员（通过类名）。扩展问：静态方法能否被重写？不能——同名同参静态方法是"隐藏"，分派看引用类型，容易踩坑。

### 1.6 this 和 super 的区别？

| 维度 | this | super |
|------|------|-------|
| 指向 | 当前对象引用 | 父类部分的引用 |
| 典型用途 | 区分字段/参数、构造器重载链接 `this(...)`、链式返回 | 调用父类构造器 `super(...)`、父类方法/字段 |
| 位置限制 | `this(...)` 必须构造器第一行 | `super(...)` 必须构造器第一行，且与 `this(...)` 互斥 |
| 静态上下文 | 不可用 | 不可用 |

### 1.7 一个对象的完整创建过程？

类加载（验证→准备→解析→初始化，静态块执行一次）→ 堆中分配内存 → 字段零值初始化 → 对象头设置 → 实例块与字段初始化 → 构造器体执行 → 栈上引用指向对象。详见 01 模块第 2 节。

## 2. 场景设计题：三道高频题

### 2.1 设计一个支付体系，支持微信、支付宝、银联，未来可能新增渠道

```text
答题要点（按评分点展开）：
① 抽象：定义 Payment 接口（pay/refund/channelId）——体现依赖倒置
② 实现：每个渠道一个类实现接口——体现开闭原则
③ 工厂/注册表：根据 channelId 获取实现（Map<String, Payment> 注册），避免 if-else
④ 注入：业务层构造器注入 Payment 或 PaymentFactory——体现 DIP + IoC
⑤ 扩展：新增渠道 = 新增一个类 + 注册一行，已有代码零修改
加分：谈到模板方法沉淀签名/日志/重试（05 模块第 7 节）、默认方法做渠道公共能力
```

### 2.2 你负责的模块里有大量 if-else 判断类型，怎么重构？

```text
① 识别变化点：if-else 分支是否按"类型"在分派行为？
② 引入接口：行为抽象为接口方法（策略模式）
③ 分支替换：Map 注册表 / 工厂按 key 取策略 / switch 模式匹配（Java 21+）
④ 注意：类型确定且稳定（如状态机枚举）时保留 switch 更简洁——避免过度设计
加分：Java 21 的 switch 模式匹配 + sealed 接口可以消灭整段 if-else 并拿到编译期穷尽性检查
```

### 2.3 写一个线程安全的单例，并说明各写法的取舍

见 06 模块第 5 节。答题顺序：饿汉（简单无懒加载）→ 静态内部类（推荐懒加载方案）→ DCL+volatile（说明 volatile 防重排）→ **枚举（最优：反射/序列化免疫）**。能画出 DCL 为什么需要 volatile（分配内存→初始化→赋引用三步重排会暴露半初始化对象）是加分项。

## 3. 高频陷阱题 10 连问

1. **输出什么？** `new Child()` 时静态块、实例块、父类构造器、子类构造器的顺序？（答案见 03 模块第 6 节）
2. **对错判断**：重载可以只通过返回值区分。（❌ 返回值不参与重载区分）
3. **对错判断**：子类重写方法可以缩小访问权限。（❌ 只能相同或更宽松）
4. **对错判断**：抽象类不能有非抽象方法；接口不能有方法实现。（❌ 抽象类可以；Java 8+ 接口有 default/static 方法）
5. **输出什么？** 父类构造器调用被子类重写的方法，子类字段输出 null 还是初始值？（null——初始化顺序，见 03 模块第 6 节）
6. **编译结果？** `Parent p = new Child(); p.onlyInChild()`？（❌ 编译错误：引用类型决定可见方法集合，多态只作用于重写方法）
7. **输出什么？** `List<Object> list = new ArrayList<String>()`？（❌ 编译错误：泛型不变性，与继承无关——面试最爱混淆的点）
8. **对错判断**：`final` 修饰的引用类型对象不可变。（❌ 引用不可变，对象内容可变，见 03 模块第 5 节）
9. **为什么**：匿名内部类访问局部变量要求 effectively final？（捕获的是副本，修改变量会让副本与源分叉，见 07 模块第 5 节）
10. **选择**：DTO 传输、状态机状态、可变业务对象，分别用什么建模？（record / sealed+record / 传统类，见 08 模块第 8 节）

> ⚠️ 陷阱题的共同规律：**考的是"引用 vs 对象"、"编译期 vs 运行期"、"继承 vs 泛型"三组边界**——答题先定边界再下结论。

## 4. 扩展追问：五道连环题

面试官常在一道基础题后连环追问，以下五问是最高频的"第二问"：

### 4.1 String 为什么设计成 final？

三个理由层层递进：① **安全**：String 被用作类名、文件路径、网络地址，若可被继承重写核心方法，恶意子类可伪造身份（历史上有过漏洞先例）；② **不可变**：final 类 + final 字段 + 值语义保证不可变，从而**线程安全**、可被常量池缓存共享（相同字面量复用同一对象）、可作 HashMap 的 key；③ **设计一致性**：JVM 与整个标准库对 String 的大量优化（常量池、字符串拼接、intern）都建立在不可变假设上。答出"**安全 + 缓存 + key 语义**"三点即满分。

### 4.2 深拷贝和浅拷贝的区别？怎么实现深拷贝？

- **浅拷贝**：复制对象本身，引用类型字段仍指向同一对象——`Object.clone()` 默认行为；
- **深拷贝**：引用字段指向的对象也复制——实现方式：重写 `clone()` 逐层复制、序列化/反序列化（需实现 `Serializable`，性能差）、手写拷贝构造器。

```java
public class Order implements Cloneable {
    private List<String> items = new ArrayList<>();

    @Override
    public Order clone() {
        try {
            Order copy = (Order) super.clone();      // 浅拷贝出骨架
            copy.items = new ArrayList<>(this.items); // 对可变引用字段深拷贝一层
            return copy;
        } catch (CloneNotSupportedException e) {
            throw new AssertionError();              // 类已实现 Cloneable，不会发生
        }
    }
}
```

> 💡 现代实践：不可变对象（record）天然无需拷贝——这也是 record 受青睐的原因之一。

### 4.3 接口的默认方法冲突怎么解决？

三条规则（优先级从高到低）：**类优先于接口**（父类方法胜出）→ **子接口优先于父接口**（更具体的接口胜出）→ 否则**必须显式覆盖**并用 `接口名.super.方法()` 指定调用哪个实现。详见 05 模块第 5 节。

### 4.4 Java 是"纯面向对象"语言吗？

**不是**，经典反例：① **基本类型**（`int`、`double` 等 8 种）不是对象，虽然 JDK 有包装类做桥接；② **static 成员**属于类而非实例，本质是过程式残留；③ 某些核心设计（如 `Math` 的工具方法、switch 语句）是命令式的。追问"包装类怎么解决"时答：自动装箱/拆箱 + 缓存池（`Integer.valueOf` 缓存 -128~127）+ 字符串常量池。

### 4.5 面向对象和面向过程的本质区别？

**面向过程**：以"操作（函数）"为中心组织代码，数据是函数的输入输出，强调"怎么做"；**面向对象**：以"对象（数据+行为）"为中心，强调"谁来做"——行为与数据绑定，状态由对象自己守护（封装）。举例：面向过程计算订单费用要传一堆参数；面向对象 `order.calculateFee()` 自己完成。面试延伸：二者不是对立，Java 的 main 方法、工具类（`Collections`）里大量过程式写法，**工程是混合体，面向对象负责组织，过程式负责执行细节**。

## 5. 面试答题框架与话术

| 场景 | 框架 | 示例话术开头 |
|------|------|------------|
| 概念题 | 定义 → 机制 → 对比 → 场景 | "多态是……，它的机制是运行期动态绑定，与重载的编译期静态分派不同，典型场景是……" |
| 对比题 | 表格维度逐项说 | "我从继承方式、成员能力、设计语义三个维度对比：……" |
| 设计题 | 抽象 → 实现 → 扩展 → 权衡 | "我会先抽象一个接口定义契约，再……，这样新增渠道时……，代价是……" |

**话术要点**：永远先给结论再展开；谈"代价/权衡"是区分度（"接口的代价是间接层，所以只有一个实现时我不抽象"）；提到版本与 JEP 是加分（"sealed 是 JEP 409，17 转正"）。
