## 1. 复杂度总表与选择决策树

**单集合核心操作复杂度**：

| 实现 | 增 | 删 | 查 | 特殊 | 有序 |
|------|:--:|:--:|:--:|------|:----:|
| ArrayList | 尾 O(1)、中 O(n) | 尾 O(1)、中 O(n) | get O(1)、contains O(n) | 扩容 1.5 倍 | 插入序 |
| LinkedList | 头尾 O(1)、中 O(n) | 头尾 O(1)、中 O(n) | O(n) | 节点内存翻倍 | 插入序 |
| ArrayDeque | 双端 O(1) | 双端 O(1) | 无索引查询 | 循环数组 | 双端序 |
| PriorityQueue | O(log n) | O(log n) 顶 | peek O(1)、contains O(n) | 二叉堆 | 堆序（部分） |
| HashSet | O(1) | O(1) | O(1) | 负载 0.75 | 无 |
| LinkedHashSet | O(1) | O(1) | O(1) | 额外链表 | 插入序 |
| TreeSet | O(log n) | O(log n) | O(log n) | floor/ceiling | 比较器序 |
| EnumSet | O(1) 位运算 | O(1) | O(1) | 位向量 | 枚举序 |
| HashMap | O(1) | O(1) | O(1) | 树化 8/64 | 无 |
| LinkedHashMap | O(1) | O(1) | O(1) | LRU | 插入/访问序 |
| TreeMap | O(log n) | O(log n) | O(log n) | 范围查询 | 键序 |
| ConcurrentHashMap | O(1) | O(1) | O(1) | 禁 null | 无 |

**选择决策树**（面试必背版）：

```text
单线程：
├── 键值 → HashMap
│     ├── 要顺序 → LinkedHashMap / TreeMap（排序/范围）
│     └── 键是枚举 → EnumMap
├── 单元素
│     ├── 要去重 → HashSet（保序 LinkedHashSet / 有序 TreeSet / 枚举 EnumSet）
│     ├── 要索引 → ArrayList
│     └── 队列/栈 → ArrayDeque（优先级 → PriorityQueue）
多线程：
├── 键值 → ConcurrentHashMap
├── 列表 → 读多写少 CopyOnWriteArrayList / 否则 synchronizedList
├── 有序并发 → ConcurrentSkipListMap
└── 队列 → 阻塞协作 BlockingQueue / 无阻塞 ConcurrentLinkedQueue
```

## 2. 必背考点：十二问

### 2.1 HashMap 的底层结构与树化

**答题链**：数组+链表+红黑树（JDK 8+）→ 默认容量 16、负载因子 0.75 → 链表 ≥8 且容量 ≥64 树化（O(n)→O(log n)）、节点 ≤6 转回 → 扩容 2 倍 rehash → JDK 7 头插法 vs JDK 8 尾插法（解决循环链表死循环）。源码细节见 `Java有关Hash的一切/02-HashMap源码深度剖析.md`。

### 2.2 负载因子为什么是 0.75？

**空间与时间的权衡**：太小（0.5）→ 频繁扩容浪费空间；太大（1.0）→ 冲突激增查询变慢。0.75 是 Poisson 分布推导的"碰撞可接受"经验值——容量 16 时树化阈值 8 的理论依据也来自此。

### 2.3 ArrayList 扩容机制

**答题链**：空数组懒加载 → 首次 add 扩到 10 → 1.5 倍（`old + (old >> 1)`）→ `Arrays.copyOf` 复制 → 均摊 O(1) → 预估容量 `new ArrayList<>(n)` 避免扩容。

### 2.4 为什么 LinkedList 不推荐？

**答题链**：内存 ~2 倍（每节点 24B+）→ 随机访问 O(n) → 中间插入也要 O(n) 遍历 → 头尾 O(1) 被 ArrayDeque 取代 → **结论：99% 场景 ArrayList；队列栈用 ArrayDeque**。

### 2.5 ConcurrentHashMap 与 Hashtable / synchronizedMap 的区别？

**答题链**：三者的锁粒度——Hashtable/synchronizedMap 全局锁（并发度 1）→ CHM JDK 7 分段锁（16 段）→ **JDK 8 CAS + synchronized 锁桶头**（并发度≈桶数）→ 迭代器弱一致 vs fail-fast → CHM 禁 null 的语义原因 → 复合操作原子方法（computeIfAbsent 等）。

### 2.6 fail-fast 与弱一致？

fail-fast：modCount 快照比对，结构性修改抛 ConcurrentModificationException——普通集合迭代器的保护机制，**单线程遍历删除也会触发**（要用迭代器 remove/removeIf）。弱一致：并发容器迭代器不抛异常、不保证看到最新——用"可能过期但绝不崩溃"换取无锁。

### 2.7 HashSet 去重原理？

**答题链**：内部 HashMap 马甲 → 元素作 key、统一 PRESENT 占位 value → add = map.put 判 null → 去重依赖 hashCode 定位桶 + equals 比较 → **equals 相等必须 hashCode 相等** → 放入后修改参与哈希的字段会"丢元素"。

### 2.8 TreeMap/TreeSet 与 HashMap/HashSet 的差异？

结构：红黑树 vs 哈希表；复杂度：O(log n) vs O(1)；顺序：键序 vs 无；null 键：禁 vs 允许 1 个；相等判定：**compareTo==0 vs equals/hashCode**；能力：范围查询/floor/ceiling vs 无。

### 2.9 ArrayDeque 为什么替代 Stack？

Stack 继承 Vector：暴露违反栈语义的方法（中间插入）、方法级同步白付锁开销。ArrayDeque：循环数组、O(1) 双端、无锁（单线程）、push/pop/peek API 一致。

### 2.10 List.of 与 Arrays.asList 的区别？

| 维度 | `List.of` | `Arrays.asList` |
|------|-----------|----------------|
| 可变性 | 完全不可变 | 固定大小（不可增删，可 set） |
| null | 禁止 | 允许 |
| 与原数组 | 复制脱离 | 共享视图（改数组写穿） |
| 版本 | JDK 9+ | 一直存在 |

### 2.11 Stream.toList() 与 collect(Collectors.toList())？

`toList()`（JDK 16+）：不可变 List（同 List.copyOf 语义）、更简单；`collect(toList())`：可变 ArrayList、可再操作。**默认用 toList()**，需要后续修改才 collect。

### 2.12 线程安全 Map 的复合操作怎么写？

**用原子方法**：`computeIfAbsent`（不存在才算）、`merge`（累加）、`putIfAbsent`（不存在才放）——**禁止手写 containsKey + put**（check-then-act 竞态）。

## 3. 高频陷阱题 10 连问

1. **结果**：`list.remove(1)` 与 `list.remove(Integer.valueOf(1))` 有何区别？（前者删索引 1，后者删值为 1 的元素）
2. **对错**：LinkedList 的中间插入比 ArrayList 快。（❌ 都是 O(n)，且 LinkedList 缓存差）
3. **结果**：`HashMap` 允许几个 null 键？TreeMap 呢？ConcurrentHashMap 呢？（1 个 / 0 个 / 0 个且 null 值也禁）
4. **结果**：`HashSet<String> s = new HashSet<>(); s.add("a"); s.add("a"); s.size()`？（1——重复被拒，add 第二次返回 false）
5. **结果**：for-each 遍历时 `list.remove(s)` 会发生什么？（ConcurrentModificationException，见 01 模块）
6. **对错**：`Collections.unmodifiableList(list)` 之后，list 任何修改都会抛异常。（❌ 是视图：原 list 还能改，视图"穿透"可见）
7. **结果**：`Arrays.asList(1,2,3)` 返回的 List 能 add 吗？（不能，固定大小视图）
8. **对错**：PriorityQueue 迭代顺序就是优先级顺序。（❌ 堆是部分有序，迭代不是全序）
9. **结果**：`TreeSet` 中 compareTo 返回 0 但 equals 为 false 的两个对象？（视为重复，后者被吞——比较器与 equals 不一致的后果）
10. **对错**：ConcurrentHashMap 的 get 返回 null 说明键不存在。（❌ 也可能值为 null——虽然 CHM 禁止 put null 值，但 get 返回 null 仍只代表"键不在"；注意禁止 null 恰恰是为了消除这个歧义）

### 4.2 100 万数据中找最大的 10 个

```text
答题链：
① 数据结构：大小为 10 的最小堆（PriorityQueue）——堆顶是当前第 10 大
② 流程：不足 10 直接进堆；元素 > 堆顶 → poll 顶 + offer 新值
③ 复杂度：O(n log k) ≈ O(n)，远优于全排序 O(n log n)；内存 O(k)
④ 边界：k 接近 n 时直接排序更快；数据分布在多机用分治 + 归并 TopK
完整代码见 04 模块第 3 节。
```

### 4.3 按状态分组统计订单（并发安全版本）

```java
// 单线程
Map<String, Long> count = orders.stream()
        .collect(Collectors.groupingBy(Order::status, Collectors.counting()));

// 并发累加
ConcurrentHashMap<String, LongAdder> c = new ConcurrentHashMap<>();
orders.forEach(o -> c.computeIfAbsent(o.status(), k -> new LongAdder()).increment());
// 或 merge：c.merge(o.status(), 1L, Long::sum);
// 答题要点：并发计数不要用 Integer（非原子），用 LongAdder 或 merge 原子方法
```
