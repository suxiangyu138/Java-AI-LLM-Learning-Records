## 1. Comparable 与 Comparator 设计对比

| 维度 | Comparable（自然序） | Comparator（比较器） |
|------|---------------------|---------------------|
| 位置 | 元素类自身实现 | 独立类/lambda/方法引用 |
| 方法 | `compareTo(T o)` | `compare(T a, T b)` |
| 修改元素类 | 需要（侵入） | 不需要（零侵入） |
| 多个排序规则 | 只能一个自然序 | 任意多个策略 |
| 函数式接口 | 是（JDK 8+） | 是 |
| 典型使用 | `Integer`/`String` 内置排序 | `Comparator.comparing(User::age)` |

**接口签名与语义**：返回负/零/正分别表示"小于/等于/大于"。

```java
// Comparable：元素自己会排序
public class Player implements Comparable<Player> {
    private final int score;
    private final String name;

    @Override
    public int compareTo(Player o) {
        return Integer.compare(this.score, o.score);   // 升序
    }
}

// Comparator：排序规则外置（推荐，零侵入）
Comparator<Player> byScoreDesc = (a, b) -> Integer.compare(b.score, a.score);
```

> 🎯 **核心要点**：**优先用 Comparator**——排序规则是"易变的需求"（今天按分数、明天按时间），外置策略不必改动元素类；`Comparable` 只适合"这个类型天生有唯一顺序"（如 `Integer`、`LocalDate`）。

## 2. Comparator 现代写法：lambda 与方法引用

**`Comparator.comparing` 键提取器**是核心 API——只需告诉它"按什么排"：

```java
// 按年龄升序
Comparator<User> byAge = Comparator.comparingInt(User::getAge);
// 按姓名字典序
Comparator<User> byName = Comparator.comparing(User::getName);
// 按日期降序
Comparator<User> byCreatedDesc = Comparator.comparing(User::getCreatedAt).reversed();
// 逆序泛型限制：reversed() 后的类型推断需要显式声明变量类型或用下面写法
Comparator<User> byCreatedDesc2 = Comparator.comparing(User::getCreatedAt,
        Comparator.reverseOrder());
```

**原始类型特化**（避免装箱，性能与规范双优）：

```java
Comparator.comparingInt(User::getAge)     // int → 无装箱
Comparator.comparingLong(Order::getAmount)
Comparator.comparingDouble(Product::getPrice)
```

**方法引用简写**：

```java
Comparator<User> a = Comparator.comparing(User::getName);          // 实例方法引用
Comparator<Integer> b = Comparator.comparingInt(x -> x);           // 等价
list.sort(String.CASE_INSENSITIVE_ORDER);                          // 预置比较器
list.sort(Comparator.naturalOrder());                              // 自然序
list.sort(Comparator.reverseOrder());                              // 逆自然序
```

> 💡 `Collections.sort(list)` 已让位于 `list.sort(comparator)`（List 自己的方法，JDK 8+）；`stream().sorted(cmp)` 用于不可变结果。

## 3. 比较器组合：thenComparing 链式

**多字段排序**：先按主键，相等再按次键——`thenComparing` 链：

```java
// 需求：先按分数降序，分数相同按姓名升序
Comparator<Player> cmp = Comparator
        .comparingInt(Player::getScore).reversed()
        .thenComparing(Player::getName);

List<Player> ranking = new ArrayList<>(players);
ranking.sort(cmp);

// 混合写法：主键比较器也可整体传入
ranking.sort(
    Comparator.comparing(Player::getScore, Comparator.reverseOrder())
              .thenComparing(Player::getName)
              .thenComparingInt(Player::getLevel)
);
```

**比较器还有两个常用工厂**：

```java
// 先处理 null 的比较器（null 排最前/最后）
Comparator<User> c = Comparator.nullsFirst(Comparator.comparing(User::getName));
Comparator<User> c2 = Comparator.nullsLast(...);

// 用 null-safe 键提取：按可能为 null 的字段排
Comparator<User> byPhone = Comparator.comparing(User::getPhone,
        Comparator.nullsFirst(Comparator.naturalOrder()));
```

> 🎯 **核心要点**：`comparing(...)` 选主键 → `.reversed()` 定方向 → `.thenComparing(...)` 补次键——这条链覆盖 90% 的排序需求，且完全可读。

## 4. Collections / Arrays 排序：稳定性与算法

| API | 目标 | 底层算法 | 复杂度 | 稳定性 |
|-----|------|---------|:------:|:------:|
| `list.sort(cmp)` / `Collections.sort` | List | `TimSort`（归并变种） | O(n log n) | **稳定** |
| `Arrays.sort(Object[])` | 对象数组 | 同 TimSort | O(n log n) | 稳定 |
| `Arrays.sort(int[])` 等 | 基本类型数组 | **双轴快速排序**（Dual-Pivot Quicksort） | O(n log n) | **不稳定**（无所谓） |
| `Arrays.parallelSort` | 大数据量数组 | 并行归并/快排 | O(n log n) | 同左 |

**稳定性为什么重要**：稳定排序保证"**相等元素的相对顺序不变**"——多字段排序时先按次键排一次，再按主键排，稳定排序能让"主键相同的元素保持次键已排好的顺序"：

```java
// 需求：先按分数降序，再按姓名升序（两遍排序利用稳定性）
players.sort(Comparator.comparing(Player::getName));              // 第一遍：姓名
players.sort(Comparator.comparingInt(Player::getScore).reversed()); // 第二遍：分数
// TimSort 稳定 → 分数相同的，姓名仍然有序 —— 效果等价 thenComparing 单遍链
```

> ⚠️ **基本类型数组 vs 对象数组的算法差异**：对象用稳定归并（需要 O(n) 辅助空间），基本类型用原地快排（不稳定但省空间）——基本类型元素没有"身份"，稳定性无意义。

## 5. 比较器一致性契约

**核心契约**（`Comparator`/`Comparable` 文档要求，违反即行为未定义）：

1. **自反**：`compare(x, x) == 0`；
2. **对称**：`compare(a, b)` 与 `compare(b, a)` 符号相反；
3. **传递**：`a < b` 且 `b < c` → `a < c`；
4. **与 equals 一致（强烈建议）**：`compare(a, b) == 0` ⟺ `a.equals(b)`。

**违反的后果**：

```java
// 反例：只按分数比较，分数相同的两个"不同玩家"被视为"相等"
Comparator<Player> bad = Comparator.comparingInt(Player::getScore);
TreeSet<Player> set = new TreeSet<>(bad);
set.add(new Player("张三", 90));
set.add(new Player("李四", 90));     // compareTo == 0 → 视为重复 → 李四被吞！
System.out.println(set.size());      // 1
```

**与 equals 不一致的连锁问题**：TreeSet/TreeMap 去重判"相等"用比较器（`compare == 0` 即重复）；PriorityQueue 的堆序用比较器但 `contains/remove` 用 equals——两者不一致时"remove 不掉""contains 不准"。HashMap/HashSet 不受影响（用 equals/hashCode），但**跨容器行为会不一致**。

> 🎯 **核心要点**：写比较器时刻对照"**compare==0 的元素应 equals 相等**"——做不到时明确知道后果（去重/删除/包含判断会错位），宁可用 `thenComparing` 补字段让比较更精细。

## 6. 常见坑：溢出、null、可变字段

### 坑 1：整数减法的溢出

```java
// ❌ 危险写法：a - b 在 int 溢出时结果符号反转
Comparator<Integer> bad = (a, b) -> a - b;
// 反例：Integer.MAX_VALUE - Integer.MIN_VALUE 溢出为负数 → 排序完全错乱

// ✅ 正确写法：Integer.compare 或比较器工厂
Comparator<Integer> good = Integer::compare;              // 或 Comparator.naturalOrder()
Comparator<Player> good2 = Comparator.comparingInt(Player::getScore);
```

### 坑 2：null 处理

`compare` 里直接 `a.getAge() - b.getAge()` 遇 null 字段抛 NPE——要么 `nullsFirst/nullsLast` 包装，要么保证字段非 null。

### 坑 3：可变字段排序

排序后修改"参与比较的字段"，TreeSet/TreeMap/PriorityQueue 的顺序结构已失效（堆/树不自动调整）——元素应不可变或排序字段不可变。

### 坑 4：reversed() 与泛型推断

```java
// ❌ 编译失败：链式 reversed 后目标类型丢失
Comparator<User> c = Comparator.comparing(User::getAge).reversed();
// ✅ 变量类型声明为 Comparator<User> 即可（上例其实可以）；更安全写法：
Comparator<User> c = Comparator.comparing(User::getAge, Comparator.reverseOrder());
```

> 💡 排查排序"看起来不对"的顺序：先检查比较器是否满足契约（自反/对称/传递），再看是否用了减法比较，最后确认元素 equals 是否与比较器一致——三连查覆盖绝大多数排序 bug。
