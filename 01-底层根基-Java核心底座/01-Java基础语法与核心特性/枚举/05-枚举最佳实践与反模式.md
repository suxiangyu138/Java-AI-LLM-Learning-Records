## 1. 最佳实践总览

**枚举的四大黄金场景**（工程价值排序）：

| 场景 | 用枚举解决 | 核心收益 |
|------|-----------|---------|
| **单例** | 语言级单例 | 反射/序列化免疫（最安全） |
| **错误码** | 类型安全 + 集中管理 | 编译期检查 + 可读性 |
| **状态机** | 状态 + 转移 + 动作一体 | 非法转移立即报错（见 02 模块） |
| **框架集成** | 数据库/JSON 的值映射 | 业务代码无魔法数字 |

**通用最佳实践五条**：

```text
① 字段全部 final（枚举不可变）
② 用自定义 code 持久化（绝不用 ordinal）
③ 行为入枚举（抽象方法/成员类体）而非外部 switch
④ 声明返回类型用接口（Set/Map），实现用 Enum 家族
⑤ 提供 fromCode/fromValue 静态工具（反查 + 容错）
```

> 🎯 **核心要点**：枚举最佳实践 = "**四大场景 + 五条纪律**"——单例/错误码/状态机/集成是"用对地方"，final/code/行为内聚/接口声明/反查工具是"写好写法"。

## 2. 枚举单例：最安全的单例

**Effective Java 明确推荐：枚举单例是最佳单例**（详见 `Java面向对象/06-构造器与对象初始化` 第 5 节）：

```java
public enum ConfigManager {
    INSTANCE;                        // 唯一实例

    private final Properties props = new Properties();

    public void load() { /* 加载配置 */ }
    public String get(String key) { return props.getProperty(key); }
}

// 使用
ConfigManager.INSTANCE.get("timeout");
```

**为什么枚举单例最安全**（对比四种写法）：

| 攻击手段 | 饿汉/懒汉/DCL/静态内部类 | 枚举单例 |
|---------|:------------------------:|:--------:|
| **反射**（`Constructor.newInstance`） | ❌ 可破坏（需防御代码） | ✅ **直接抛异常**（Enum 构造禁止反射） |
| **序列化**（反序列化新实例） | ❌ 需 `readResolve()` | ✅ **天然返回同一实例**（JVM 保证） |
| 多线程 | ⚠️ 需 volatile/锁 | ✅ 类加载天然安全 |
| 代码量 | 多（防御代码） | 一行 |

```java
// 反射攻击演示（对普通单例有效，对枚举无效）
Constructor<?> c = ConfigManager.class.getDeclaredConstructor();
c.setAccessible(true);
c.newInstance();     // ✅ 对普通类：创建新实例（破坏单例）
                     // ❌ 对枚举：java.lang.IllegalArgumentException
```

> 🎯 **核心要点**：枚举单例 = "**语言级单例**"——**反射禁止（Enum 构造器抛异常）+ 序列化安全（JVM 保证同实例）**，两种攻击手段天然免疫；面试答"最安全单例"直接给枚举。

## 3. 错误码与枚举

**错误码是枚举的最佳实践之一**（与 `Java异常体系/06-自定义异常与错误码设计` 联动）：

```java
// 错误码枚举：类型安全 + 集中管理 + 携带消息
public enum ErrorCode {
    // 通用错误（1000 段）
    PARAM_INVALID("PARAM_INVALID", "参数不合法"),
    UNAUTHORIZED("UNAUTHORIZED", "未登录或登录过期"),
    // 订单错误（2000 段）
    ORDER_NOT_FOUND("ORDER_NOT_FOUND", "订单不存在"),
    ORDER_ALREADY_SHIPPED("ORDER_ALREADY_SHIPPED", "订单已发货，无法操作");

    private final String code;
    private final String defaultMessage;

    ErrorCode(String code, String defaultMessage) {
        this.code = code;
        this.defaultMessage = defaultMessage;
    }

    public String code() { return code; }
    public String defaultMessage() { return defaultMessage; }
}

// 业务异常携带枚举（见异常体系 06 模块）
public class BusinessException extends RuntimeException {
    private final ErrorCode errorCode;
    public BusinessException(ErrorCode errorCode) {
        super(errorCode.defaultMessage());
        this.errorCode = errorCode;
    }
    public ErrorCode errorCode() { return errorCode; }
}

// 使用
throw new BusinessException(ErrorCode.ORDER_NOT_FOUND);
```

**错误码枚举 vs 字符串常量**：

| 维度 | 字符串常量 | 错误码枚举 |
|------|:----------:|:----------:|
| 类型安全 | ❌（任意字符串） | ✅ |
| 集中管理 | 散落各文件 | ✅ 一处定义 |
| 携带消息 | ❌ | ✅（defaultMessage） |
| 拼写检查 | ❌（运行时才炸） | ✅ 编译期 |
| 文档化 | 手动 | ✅（枚举即文档） |

> 🎯 **核心要点**：错误码枚举 = "**稳定契约**"——**代码、日志、前端、文档共享同一枚举**；分段管理（1000 通用/2000 订单/3000 支付）+ 新增只增不改（前端依赖）。

## 4. 与 Jackson 集成

**JSON 序列化的枚举处理**（Spring Boot 默认 Jackson）：

```java
public enum OrderStatus {
    @JsonProperty("pending") PENDING(0, "待支付"),
    @JsonProperty("paid") PAID(1, "已支付");

    private final int code;
    private final String desc;
    OrderStatus(int code, String desc) { this.code = code; this.desc = desc; }

    @JsonValue          // 序列化：输出 code（而非枚举名）
    public int getCode() { return code; }

    @JsonCreator        // 反序列化：按 code 构造
    public static OrderStatus fromCode(int code) {
        for (OrderStatus s : values()) {
            if (s.code == code) return s;
        }
        throw new IllegalArgumentException("未知状态码: " + code);
    }
}

// 序列化结果
// OrderStatus.PAID → {"code": 1}（@JsonValue 生效）
// 反序列化：{"code": 1} → OrderStatus.PAID（@JsonCreator 生效）
```

**Jackson 枚举策略速查**：

| 需求 | 方案 |
|------|------|
| 默认（枚举名） | 什么都不配（`"PAID"`） |
| 输出/读取 code | `@JsonValue` + `@JsonCreator` |
| 前端友好（小写/别名） | `@JsonProperty` 标注 |
| 全局配置 | `WRITE_ENUMS_USING_TO_STRING` 等 Jackson 特性 |
| 容错反序列化 | `READ_UNKNOWN_ENUM_VALUES_USING_DEFAULT_VALUE` |

> 🎯 **核心要点**：Jackson 集成 = "**@JsonValue（输出 code）+ @JsonCreator（读回 code）**"两注解——**code 是数据库/前端的稳定契约，枚举名只是 Java 内部表示**；未知值容错按需配置。

## 5. 与 MyBatis 集成

**MyBatis/MyBatis-Plus 的枚举处理**（与 `MyBatisPlus/02-实体映射与注解体系` 第 7 节联动）：

```java
// 方案一：实现 IEnum 接口（MyBatis-Plus 推荐）
@Getter
public enum OrderStatus implements IEnum<Integer> {
    PENDING(0, "待支付"),
    PAID(1, "已支付");

    private final int value;
    private final String desc;
    OrderStatus(int value, String desc) { this.value = value; this.desc = desc; }

    @Override
    public Integer getValue() { return value; }    // 数据库存 0/1
}

// 方案二：@EnumValue 注解（通用 MyBatis）
public enum OrderStatus {
    @EnumValue PENDING(0, "待支付"),     // 标注数据库值
    @EnumValue PAID(1, "已支付");
    // ...
}

// 实体直接使用枚举类型（自动转换）
public class Order {
    private OrderStatus status;    // 数据库 0/1 ↔ Java 枚举
}
```

**配置**（MyBatis-Plus）：

```yaml
mybatis-plus:
  configuration:
    default-enum-type-handler: com.baomidou.mybatisplus.extension.handlers.MybatisEnumTypeHandler
  type-enums-package: com.example.entity.enums   # 枚举包扫描
```

**集成收益**：**数据库存数值、Java 用枚举、业务零魔法数字**——状态字段（订单/用户状态）是最大受益者。

> 🎯 **核心要点**：MyBatis 集成 = "**IEnum / @EnumValue 标注数据库值 + 枚举类型直接入库**"——**"数据库 0/1、Java 枚举、业务语义"三层解耦**；复杂类型（JSON 字段）用 `JacksonTypeHandler`。

## 6. 反模式清单

| # | 反模式 | 表现 | 正确做法 |
|:-:|--------|------|---------|
| 1 | **可变枚举字段** | 常量字段被修改（单例被污染） | 字段全部 final |
| 2 | **ordinal 持久化** | 数据库存 ordinal（插入常量即错位） | 显式 code 字段 |
| 3 | **外部 switch 分派** | 行为逻辑散落调用方 switch | 行为入枚举（抽象方法） |
| 4 | **魔法数字替代品未用** | 状态用 int 常量 | 枚举（类型安全） |
| 5 | **枚举当常量类** | 只有 name 无状态无行为 | 区分：纯常量用常量类 |
| 6 | **switch 漏分支** | default 兜底掩盖遗漏 | JDK 21 穷尽性（省略 default） |
| 7 | **依赖 name() 持久化** | 改名即破坏存储数据 | code 字段独立于 name |
| 8 | **枚举类过大** | 十几常量 + 复杂类体 | 策略类 + 枚举注册表 |
| 9 | **null 返回** | `fromCode` 返回 null（调用方 NPE） | 抛异常或返回兜底常量 |
| 10 | **误用 Set** | 权限用 HashSet | EnumSet（位向量） |

```java
// 反模式 2 演示（ordinal 持久化的灾难）：
// 数据库已有 PAID=1（ordinal）
public enum OrderStatus {
    PENDING, PAID, SHIPPED, COMPLETED
    // 业务需要新增 CANCELED —— 插在开头？
    CANCELED, PENDING, PAID, ...   // ❌ 全部 ordinal 移位！历史数据全错
    // 正确：显式 code，插入任意位置都安全
    CANCELED(99, "已取消")          // ✅ code 独立于位置
}
```

> 🎯 **核心要点**：反模式总纲 = "**枚举是'固定值 + 不可变'的契约**"——**可变/移位/依赖位置/外部散落**都是对契约的破坏；十条清单中 **ordinal 持久化与外部 switch** 是最高频事故源。
