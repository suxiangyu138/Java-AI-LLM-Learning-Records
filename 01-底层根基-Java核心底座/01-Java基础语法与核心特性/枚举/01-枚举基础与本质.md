## 1. 枚举的语法与基本用法

```java
// 最基本的枚举：声明即常量集合
public enum Day {
    MONDAY, TUESDAY, WEDNESDAY, THURSDAY, FRIDAY, SATURDAY, SUNDAY
}

// 使用
Day today = Day.MONDAY;
System.out.println(today);                 // MONDAY（toString 返回 name）

// 比较：== 即可（单例保证）
if (today == Day.MONDAY) { ... }

// 遍历
for (Day d : Day.values()) { ... }
```

**三个基本认知**：

1. **类型安全**：`Day.MONDAY` 只能赋给 `Day` 类型变量——传 `"MONDAY"` 字符串编译错误（对比魔法数字/字符串常量）；
2. **编译期检查**：switch 分支漏枚举常量会编译告警（配合 JDK 21 穷尽性更强，见 03 模块）；
3. **自动方法**：每个枚举免费获得 `values()`/`valueOf()`/`ordinal()`/`name()`。

> 🎯 **核心要点**：枚举的第一价值 = "**类型安全的常量**"——编译器知道你有哪些合法值，写错、传错在编译期就暴露（魔法数字/字符串做不到）。

## 2. 枚举的本质：继承 Enum 的特殊类

**`enum Day { ... }` 编译后的真实形态**：

```java
// 编译器展开（简化）：
public final class Day extends java.lang.Enum<Day> {   // 隐式继承 Enum
    public static final Day MONDAY = new Day("MONDAY", 0);   // 每个常量 = 一个静态实例
    public static final Day TUESDAY = new Day("TUESDAY", 1);
    // ...

    private Day(String name, int ordinal) {        // 构造器必须私有
        super(name, ordinal);
    }
}
```

**这个本质推导出五个事实**：

| 事实 | 说明 |
|------|------|
| 枚举是类 | 可以有字段、方法、构造器、实现接口 |
| 隐式 final | 枚举不能被继承（`class X extends Day` 编译错误） |
| 构造器私有 | 外部无法 `new`——**实例数量编译期固定** |
| 每个常量单例 | `Day.MONDAY == Day.MONDAY` 永远成立 |
| 泛型父类 | `Enum<E extends Enum<E>>`——`Comparable` 与 `Serializable` 自动实现 |

```java
// 验证本质：枚举可以调用 Object 方法（它是 Object 的子类）
Day d = Day.MONDAY;
d.toString();        // MONDAY
d.hashCode();        // 基于 name（Enum 重写）
d.equals(d);         // ==（单例）
d.getClass();        // class Day
```

> 🎯 **核心要点**：**"枚举是类"是理解一切的钥匙**——常量特定方法、接口实现、字段方法全都来自"枚举是类"；"实例数量固定 + 单例"来自"构造器私有 + 静态实例"。

## 3. 构造器与成员

**枚举可以像普通类一样携带状态**：

```java
public enum OrderStatus {
    PENDING(0, "待支付"),
    PAID(1, "已支付"),
    SHIPPED(2, "已发货"),
    COMPLETED(3, "已完成");

    private final int code;          // 字段：与数据库/前端对齐的编码
    private final String desc;       // 描述文案

    OrderStatus(int code, String desc) {   // 构造器：必须私有（可省略 private）
        this.code = code;
        this.desc = desc;
    }

    public int getCode() { return code; }
    public String getDesc() { return desc; }
}

// 使用
OrderStatus status = OrderStatus.PAID;
System.out.println(status.getCode());   // 1
System.out.println(status.getDesc());   // 已支付
```

**构造器规则**：

1. **必须私有**（不写也默认私有）——外部无法创建新实例，保证"实例集合固定"；
2. 每个常量声明处传参：`PENDING(0, "待支付")` 调用构造器；
3. **字段建议 final**——枚举状态不可变（可变枚举字段是反模式，见 05 模块）。

> 🎯 **核心要点**：带状态枚举 = "**常量 + 编码 + 描述 + 行为**"的完整值对象——`code` 对齐数据库、`desc` 对齐前端展示、枚举本身供代码使用，三位一体。

## 4. 内置方法：values / valueOf / ordinal

| 方法 | 功能 | 注意事项 |
|------|------|---------|
| `values()` | 返回全部常量数组 | **每次调用新建数组**（性能场景注意） |
| `valueOf(String)` | 按名字取常量 | 名字不存在抛 `IllegalArgumentException` |
| `name()` | 返回常量名（字符串） | 与 valueOf 互逆 |
| `ordinal()` | 返回声明顺序（从 0 起） | **依赖顺序——重构时插入常量会移位！** |
| `compareTo(E)` | 按 ordinal 比较 | 继承自 Enum 的 Comparable |
| `toString()` | 返回 name | 可重写（与 name() 解耦） |

```java
// 常用组合
Day d = Day.valueOf("MONDAY");        // 从字符串（如前端参数/数据库值）取常量
String name = d.name();               // "MONDAY"（序列化存储用）

// ⚠️ ordinal 的坑：不要用于持久化
// 若在 PENDING 前插入 CANCELED，所有已存数据的 ordinal 全错位！
// 正确：用自定义 code 字段持久化（见第 3 节）
```

> ⚠️ **ordinal 是面试高频坑**：它依赖声明顺序——**增删常量会改变所有后续常量的 ordinal**。持久化（数据库/JSON）必须用显式 code 字段，绝不用 ordinal（详见 05 模块反模式）。

## 5. 枚举的边界：能做什么不能做什么

| 能做 | 不能做 |
|------|--------|
| 字段、方法、构造器（私有） | ❌ 被继承（隐式 final） |
| 实现接口（任意多个） | ❌ 继承其他类（已继承 Enum） |
| 抽象方法（由各常量实现） | ❌ 被 new（构造器私有） |
| 静态方法/静态字段 | ❌ 泛型枚举（`enum E<T>` 不合法） |
| 内部类/嵌套枚举 | ❌ 可变实例（字段建议 final） |
| 实现 Comparable/Serializable | ❌ 懒加载扩展（实例编译期固定） |

```java
// 静态工厂是枚举的常见配套
public enum Status {
    PENDING(0), PAID(1);

    private final int code;
    Status(int code) { this.code = code; }

    public static Status fromCode(int code) {     // 静态方法：按 code 查找
        for (Status s : values()) {
            if (s.code == code) return s;
        }
        throw new IllegalArgumentException("未知状态码: " + code);
    }
}
```

> 🎯 **核心要点**：枚举的边界记忆 = "**它是类的子集 + 单例集合**"——能做的（字段/方法/接口）来自"是类"，不能做的（继承/new/泛型）来自"固定实例集合"的语义。

## 6. 枚举 vs 常量 vs 普通类

| 维度 | 魔法数字/字符串常量 | 枚举 | 普通类（静态实例） |
|------|:------------------:|:----:|:------------------:|
| 类型安全 | ❌（int/String 任意值） | ✅ | ✅ |
| 编译期检查 | ❌ | ✅（switch 穷尽） | ❌ |
| 自带方法 | ❌ | ✅（values/valueOf） | ❌（手写） |
| 单例保证 | ❌ | ✅（语言级） | ⚠️（需手写） |
| 序列化安全 | — | ✅（天然） | ❌ |
| switch 支持 | ✅（int/String） | ✅ | ❌ |
| 行为绑定（每个值不同行为） | ❌ | ✅（成员类体） | ⚠️（手写分派） |

**选型判断**：

```text
有限且固定的取值集合 → 枚举（首选）
  状态、类型、渠道、级别、错误码、配置开关
仅常量无语义 → 常量类（public static final）
  数学常量（PI）、固定配置值
需要动态扩展的"类型" → 普通类 + 注册表
  插件系统、动态类型（枚举实例固定无法扩展）
```

> 🎯 **核心要点**：选型口诀 = "**值集合固定用枚举、纯常量用常量类、动态类型用注册表**"——90% 的"状态/类型"场景枚举是正确答案；**"固定"是枚举的根基，需要扩展性时它反而是限制**。
