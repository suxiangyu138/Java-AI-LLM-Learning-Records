## 1. 面试高频题与答题框架

### 1.1 语法类

**Q1：正则中贪婪、勉强、占有量词的区别？**

```text
① 贪婪 .*：尽可能多匹配，回溯逐步减少（默认）
② 勉强 .*?：尽可能少匹配，回溯逐步增加
③ 占有 .*+：匹配即提交，永不回溯（线性）
④ 示例：<a><b> 用 <.*> 匹配全部；<.*?> 匹配 <a>
⑤ 关键：勉强 ≠ 安全（(a*?)+ 同样灾难）——占有/原子才线性
```

**Q2：零宽断言是什么？有什么应用？**

```text
① 定义：只判断位置不消耗字符（看而不取）
② 四件套：正向前瞻 (?=...) / 负向前瞻 (?!...) / 正向后顾 (?<=...) / 负向后顾 (?<!...)
③ 经典应用：密码强度校验（多断言组合）、金额提取（(?<=￥)\d+）、千分位（\B(?=(\d{3})+(?!\d))）
④ 兼容性：Java 支持变长后顾；Python/JS 只支持定长
```

**Q3：捕获组和非捕获组有什么区别？**

```text
① 捕获组 (abc)：提取数据（group(1) 获取）
② 非捕获组 (?:abc)：只组织不捕获（量词/或边界用）——性能更好
③ 命名组 (?<name>abc)：语义化提取（group("name")）——大正则可读性
④ 原子组 (?>abc)：提交不回溯——防灾难性回溯
⑤ 工程建议：只提取用捕获组；纯组织用非捕获组
```

### 1.2 引擎与性能类

**Q4：什么是灾难性回溯？怎么防护？**

```text
① 机制：NFA 回溯引擎 + 嵌套量词 (a+)+ → 2^N 次尝试
② 触发：危险模式 + 失败路径输入（"aaaaX"）+ 足够长度
③ 案例：Cloudflare 2019 宕机 27 分钟（WAF 正则）
④ 四层防护：模式改写（治本）→ 长度限制 → 执行超时 → RE2J（免疫）
⑤ 高危模式：嵌套量词/重叠交替 (a|a)+/共享字符连续量词/无界重复
```

**Q5：NFA 和 DFA 引擎的区别？**

```text
① NFA（回溯型）：Java/Python/JS——功能全（反向引用/断言），最坏指数
② DFA（线性型）：RE2/RE2J——O(N) 线性保证，免疫 ReDoS，无反向引用
③ 选型：不可信输入用 RE2J；业务可信文本用 java.util.regex
④ 2026 趋势：JEP 8260688（可预测正则性能）仍在草案
```

**Q6：Java 正则为什么可能 StackOverflowError？**

```text
① 深嵌套模式（大量分组嵌套）触发递归深度超限
② JDK 官方承认（JEP 8260688）：缓解但未消除 O(2^N) 与 StackOverflowError
③ 反向引用会关闭回溯优化（JDK-6328855）
④ 防护：嵌套深度限制 + 复杂度测试 + 不可信输入用 RE2J
```

### 1.3 API 类

**Q7：Pattern 和 Matcher 的区别？线程安全吗？**

```text
① Pattern：编译后不可变 → 线程安全 → 可静态共享
② Matcher：有状态（位置/分组）→ 非线程安全 → 每次新建或 reset
③ 标准实践：静态共享 Pattern + 每线程独立 Matcher
④ 反模式：共享 Matcher 多线程并发 → 数据错乱
⑤ 性能：热循环重复 compile = 100 倍损失——必须预编译
```

**Q8：matches 和 find 的区别？**

```text
① matches：整个输入完全匹配（等价 ^模式$）——校验用
② find：子串查找（迭代，从上次位置继续）——提取用
③ lookingAt：从开头前缀匹配（不要求到结尾）
④ 陷阱：find 忘写循环只匹配一次；find 配合长输入可能 O(N²)
```

**Q9：replace 和 replaceAll 的区别？**

```text
① replace：字面替换（参数不是正则）——"a.b.c".replace(".","/") 只换点
② replaceAll：正则替换——"." 匹配所有字符（灾难！）
③ 陷阱：replaceAll(".") 把每个字符都替换
④ 转义：正则里匹配 . 需要 "\\."
⑤ 结论：字面替换用 replace（免转义更快）；正则替换才用 replaceAll
```

**Q10：split 的坑有哪些？**

```text
① 尾部分隔符被丢弃："a,b,".split(",") → [a, b]
② 解法：split(",", -1) 保留空元素
③ 正则特殊字符："a.b.c".split("\\.") 或 split(Pattern.quote("."))
④ 性能：热循环用预编译 Pattern.split（String.split 内部也编译）
```

### 1.4 实战类

**Q11：手机号/邮箱/身份证校验怎么写？边界是什么？**

```text
① 手机号：^1[3-9]\d{9}$（格式校验——不校验号段真实）
② 邮箱：[\\w.+-]+@[\\w-]+(\\.[\\w-]+)+（加 254 长度限制；真实归属要发邮件）
③ 身份证：\d{17}[0-9Xx]（严格版校验日期合理性；不校验校验位）
④ 金句：正则负责格式，业务负责语义——各司其职
```

**Q12：金额校验为什么必须配合 BigDecimal？**

```text
① 正则只校验格式（^\\d+(\\.\\d{1,2})?$）
② 浮点陷阱：0.1 + 0.2 ≠ 0.3（二进制无法精确表示）
③ 金额运算必须 BigDecimal（精度/舍入模式）
④ 完整方案：正则验格式 + BigDecimal 做运算 + 范围校验
```

**Q13：手机号脱敏怎么写？**

```text
① 核心：捕获组 + 替换引用
② "(1[3-9]\\d)\\d{4}(\\d{4})" 替换 "$1****$2"
③ 相似：身份证 (\\d{6})\\d{8}(\\d{4}) → $1********$2
④ 银行卡：首 4 尾 4 保留中间打码
⑤ 注意：脱敏在日志/存储/响应全链路执行
```

**Q14：Java 正则怎么实现超时？**

```text
① Java 无内置超时（.NET 有 matchTimeout）
② 方案：Future + 线程池 get(timeout) → 超时拒绝 + shutdownNow 中断
③ 代价：每次匹配一个线程——只用于不可信输入高危路径
④ 更优：RE2J（自带超时 + 线性保证）
⑤ 综合：长度限制 > 超时 > 引擎替换（多层叠加）
```

### 1.5 综合类

**Q15：正则的性能优化有哪些手段？**

```text
① 预编译（静态常量）——最大收益
② 消除歧义（嵌套量词/重叠分支）——消除灾难
③ 精确字符类（[0-9]{4} 优于 \\d+）
④ 锚定（^ $ \\b）快速失败
⑤ 前置短路（length/startsWith 先行）
⑥ 原子化/占有量词（防跨段回溯）
⑦ 简单任务原生 API（Character.isDigit/contains）
```

**Q16：什么样的正则容易引发安全问题？**

```text
① 四类高危：嵌套量词 (a+)+/重叠交替 (a|a)+/共享字符连续量词/无界重复
② 反向引用：关闭回溯优化（不可信输入禁用）
③ 大范围 .*：与嵌套结合灾难
④ 防护：模式审查（CI 扫描）+ 长度限制 + 超时 + RE2J
⑤ 用户提供的正则必须沙箱化（RE2J + 限长 + 超时）
```

## 2. 代码题实战

**题 1：手机号脱敏**

```java
public String maskPhone(String phone) {
    return phone.replaceAll("(1[3-9]\\d)\\d{4}(\\d{4})", "$1****$2");
}
// 13812345678 → 138****5678
```

**题 2：数字千分位格式化**

```java
public String formatThousands(String num) {
    return num.replaceAll("\\B(?=(\\d{3})+(?!\\d))", ",");
}
// 1234567890 → 1,234,567,890
// 考点：零宽断言（前瞻 + 负前瞻 + 非单词边界）
```

**题 3：密码强度校验（多断言）**

```java
public boolean isStrongPassword(String pw) {
    return pw.matches("(?=.*[a-z])(?=.*[A-Z])(?=.*\\d)(?=.*[!@#$%]).{8,16}");
}
// 考点：断言「检查不消耗」——四个条件独立成立
```

**题 4：判断是否含重复单词**

```java
public boolean hasDuplicateWord(String text) {
    return Pattern.compile("\\b(\\w+)\\s+\\1\\b").matcher(text).find();
}
// "the the cat" → true；考点：反向引用 \1
```

**题 5：提取所有金额**

```java
public List<String> extractMoney(String text) {
    Pattern p = Pattern.compile("(?<=￥)\\d+(\\.\\d{2})?");
    Matcher m = p.matcher(text);
    List<String> result = new ArrayList<>();
    while (m.find()) result.add(m.group());
    return result;
}
// "商品￥299.00，运费￥10" → [299.00, 10]
```

## 3. 终极速查表

| 场景 | 模式（Java） | 说明 |
|------|-------------|------|
| 手机号 | `^1[3-9]\d{9}$` | 格式校验 |
| 邮箱（简化） | `^[\w.+-]+@[\w-]+(\.[\w-]+)+$` | 加长度限制 |
| IPv4 | `^((25[0-5]\|2[0-4]\d\|1\d\d\|[1-9]?\d)\.){3}(...)$` | 分段校验 |
| 金额 | `^\d+(\.\d{1,2})?$` | 配合 BigDecimal |
| 日期严格 | `^\d{4}-(0[1-9]\|1[0-2])-(0[1-9]\|[12]\d\|3[01])$` | 闰年用 LocalDate |
| 千分位 | `\B(?=(\d{3})+(?!\d))` | 替换为 `,` |
| 密码强度 | `(?=.*[a-z])(?=.*[A-Z])(?=.*\d)(?=.*[!@#$%]).{8,16}` | 断言组合 |
| 重复单词 | `\b(\w+)\s+\1\b` | 反向引用 |
| HTML 标签 | `<[^>]+>` | 简单清理（正式用解析库） |
| 中文 | `[一-龥]+` | 或 `\p{IsHan}` |
| 匹配反斜杠 | `\\\\`（Java 字符串） | 4 个反斜杠 |
| 危险模式 | `(a+)+` | ❌ 嵌套量词禁用 |

## 4. 五大常见误区

| # | 误区 | 真相 |
|---|------|------|
| 1 | 「勉强量词比贪婪安全」 | 勉强只改回溯方向——嵌套量词下同样灾难 |
| 2 | 「replaceAll 能替换字面字符」 | 参数是正则——`.` 会匹配一切（用 replace） |
| 3 | 「Pattern/Matcher 都能共享」 | Pattern 线程安全可共享；Matcher 有状态不可共享 |
| 4 | 「正则校验 = 安全校验」 | 正则管格式——邮箱归属要发邮件、SSRF 要白名单 |
| 5 | 「Java 正则有超时保护」 | Java 无内置超时——需线程池实现或 RE2J |
