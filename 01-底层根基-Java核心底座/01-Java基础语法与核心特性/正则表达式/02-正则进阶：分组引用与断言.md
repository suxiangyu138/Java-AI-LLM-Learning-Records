## 1. 分组：提取与组织

> **背景**：基础正则只能整体匹配；分组让正则能「拆解」匹配结果——提取子片段、应用量词、回溯控制。
> **目的**：从匹配结果中提取结构化数据（订单号/金额/日期等）。
> **适用范围**：日志解析、表单提取、数据清洗。
> **不适用场景**：只做校验不提取（非捕获组更高效）；性能敏感场景（捕获组有开销）。

```text
分组的两大用途
├── ① 提取：捕获组 = 数据容器（group(1) 拿第一段）
├── ② 组织：量词作用于组 (ab)+、或 | 的边界 (cat|dog)
└── ③ 控制：非捕获组 (?:...) 只组织不捕获（性能更好）
```

## 2. 捕获组类型全集

| 类型 | 语法 | 捕获？ | 用途 |
|------|:---:|:---:|------|
| **普通捕获组** | `(abc)` | ✅ | 提取数据 |
| **非捕获组** | `(?:abc)` | ❌ | 组织/量词，无开销 |
| **命名捕获组** | `(?<name>abc)` | ✅ | 语义化提取（Java 7+） |
| **内联标志组** | `(?i)abc` | ❌ | 局部开关标志 |
| **原子组** | `(?>abc)` | ❌ | 防回溯（见第 6 节） |

```java
// 捕获组的编号规则（从 1 开始，按左括号顺序）
Pattern p = Pattern.compile("(\\d{4})-(\\d{2})-(\\d{2})");
Matcher m = p.matcher("2026-08-04");
if (m.matches()) {
    m.group(1);   // 2026（年）
    m.group(2);   // 08（月）
    m.group(3);   // 04（日）
    m.group(0);   // 2026-08-04（整体）
}
```

## 3. 反向引用

### 3.1 语法与用途

> 🎯 **反向引用**：`\1` 引用前面第 1 个捕获组匹配的「实际内容」——用于检测重复模式：

```java
// 重复单词检测（"the the"）
Pattern p = Pattern.compile("\\b(\\w+)\\s+\\1\\b");
p.matcher("the the cat").find();       // ✅ 匹配重复的 the
p.matcher("the cat").find();           // ❌

// 成对标签检测（HTML 简化）
Pattern p2 = Pattern.compile("<(\\w+)>.*?</\\1>");
p2.matcher("<b>bold</b>").matches();   // ✅ 标签名一致
p2.matcher("<b>bold</i>").matches();   // ❌ 标签不匹配

// 替换中使用（Java 用 $1 而非 \1）
"13812345678".replaceAll("(\\d{3})\\d{4}(\\d{4})", "$1****$2");
```

### 3.2 反向引用的致命代价（重要！）

> ⚠️ **反向引用会关闭回溯优化**（JDK-6328855 已知问题）——Java 的正则引擎对大部分指数级回溯有记忆化优化，但**存在反向引用时优化被关闭**，且用户得不到任何性能保证：

```text
反向引用的性能风险
├── ① 正常模式：引擎有记忆化优化（缓解灾难性回溯）
├── ② 含反向引用：优化关闭 → 灾难性回溯风险回归
├── ③ 结论：反向引用 + 嵌套量词 = 高危组合
└── 工程建议：
    ├── 优先用「重新匹配」替代反向引用（如写两次模式）
    ├── 不可信输入场景避免反向引用
    └── 必须用时限制输入长度（见 04 篇）
```

## 4. 零宽断言：看而不取

### 4.1 断言家族

> 🎯 **零宽断言**：匹配位置而不消耗字符——「向前看/向后看」但不拿走：

| 断言 | 语法 | 含义 | 示例 |
|------|:---:|------|------|
| **正向前瞻** | `(?=...)` | 后面必须跟 | `\d+(?=元)` 匹配 "100" in "100元" |
| **负向前瞻** | `(?!...)` | 后面不能跟 | `\d+(?!元)` 匹配 "100" in "100个" |
| **正向后顾** | `(?<=...)` | 前面必须是（Java 支持变长） | `(?<=￥)\d+` 匹配 "100" in "￥100" |
| **负向后顾** | `(?<!...)` | 前面不能是 | `(?<!￥)\d+` 匹配非￥开头的数字 |

### 4.2 断言实战（关键场景）

```java
// 场景 1：提取金额（前后断言精确定位）
Pattern p = Pattern.compile("(?<=￥)\\d+(?:\\.\\d{2})?");
// 从 "商品￥299.00，运费￥10" 中提取 [299.00, 10]

// 场景 2：密码强度校验（多断言组合——最经典的用法！）
String pw = "Abc12345";
boolean strong = pw.matches(
    "(?=.*[a-z])(?=.*[A-Z])(?=.*\\d)(?=.*[!@#$%]).{8,16}"
);
// 解释：必须含小写 AND 大写 AND 数字 AND 特殊字符，长度 8-16
// 断言只「检查位置」不消耗——四个检查独立成立

// 场景 3：单词边界内的数字（排除 URL 中的数字）
Pattern p3 = Pattern.compile("(?<!\\w)\\d+(?!\\w)");
// 从 "abc123 456 def789" 中只提取 456

// 场景 4：金额格式化（千分位）
"1234567".replaceAll("\\B(?=(\\d{3})+(?!\\d))", ",");
// → 1,234,567（断言实现千分位——经典面试题！）
```

### 4.3 断言的语言差异

```text
后顾断言的兼容性（各语言不同！）
├── Java：支持变长后顾（(?<=a{2,5}) 合法）
├── Python：只支持定长后顾（变长报错）
├── JS：只支持定长后顾（变长报错；新标准有进展）
└── 结论：跨语言复用正则时，后顾断言是最大兼容性风险
```

## 5. 命名捕获组

### 5.1 语法与使用（Java 7+）

```java
// 命名捕获组：语义化提取（大正则可读性救星）
Pattern p = Pattern.compile(
    "(?<year>\\d{4})-(?<month>\\d{2})-(?<day>\\d{2})"
);
Matcher m = p.matcher("2026-08-04");
if (m.matches()) {
    m.group("year");    // 2026
    m.group("month");   // 08
    m.group("day");     // 04
}

// 命名组在替换中的使用
"2026-08-04".replaceAll(
    "(?<y>\\d{4})-(?<m>\\d{2})-(?<d>\\d{2})",
    "${d}/${m}/${y}"
);   // → 04/08/2026
```

### 5.2 命名组的权衡

| 优势 | 代价 |
|------|------|
| 可读性（大正则的救星） | 命名冲突（重复名报错） |
| 语义明确（group("year")） | 兼容性（旧语言不支持） |
| 重构友好（顺序变化不影响） | 稍慢（查找开销，可忽略） |

## 6. 原子组：防回溯利器

### 6.1 原理

> 🎯 **原子组 `(?>...)`**：组内匹配完成后「提交」——引擎不会回溯进组内重新尝试。把可能灾难的回溯空间一次性截断：

```java
// 对比（输入 "aaaaab"，模式 (a+)ab）
// 普通组 (a+)：贪婪先吃 5 个 a，然后 ab 失败 → 回溯到 4 个 a
//   → 反复回溯尝试，最坏 O(N²)
Pattern p1 = Pattern.compile("(a+)ab");

// 原子组 (?>a+)：吃 5 个 a 提交 → ab 失败 → 整体失败（不回溯！）
//   → 一次尝试，线性
Pattern p2 = Pattern.compile("(?>a+)ab");

// 结果差异（关键！）：
p1.matcher("aaaaab").matches();   // ✅ true（回溯找到 aaaa+ab）
p2.matcher("aaaaab").matches();   // ❌ false（提交后不回溯）
```

> ⚠️ **原子组改变了匹配语义**：不是「同样的匹配更快」，而是「不同的匹配结果」——**使用前必须确认原子化不会丢掉合法匹配**。通用安全场景是「去掉外层冗余量词」而不是盲目加原子组。

### 6.2 原子组的正确用法

```text
原子组的使用场景
├── ① 嵌套量词去重：(a+)+ 中的外层 + 无意义 → 原子化 (?>a+)+
├── ② 无歧义段落：一段字符类 + 明确分隔符（防回溯跨段）
├── ③ 处理不可信输入的核心防线（与占有量词并列）
└── ④ 替换方案：直接用占有量词 a++（等价于原子组 (?>a+)）
```

## 7. 进阶实战示例

```java
// 示例 1：日志行解析（分组 + 断言组合）
String log = "2026-08-04 10:30:12 INFO [order-service] 订单创建成功 orderId=ORD-1001";
Pattern p = Pattern.compile(
    "(?<ts>\\d{4}-\\d{2}-\\d{2} \\d{2}:\\d{2}:\\d{2}) " +
    "(?<level>INFO|WARN|ERROR) " +
    "\\[(?<service>[^]]+)\\] " +
    "(?<msg>.*?) orderId=(?<orderId>\\w+)"
);
Matcher m = p.matcher(log);
if (m.matches()) {
    m.group("ts");      // 2026-08-04 10:30:12
    m.group("level");   // INFO
    m.group("service"); // order-service
    m.group("orderId"); // ORD-1001
}

// 示例 2：数字千分位（断言经典）
String formatted = "1234567890".replaceAll(
    "\\B(?=(\\d{3})+(?!\\d))", ",");
// → 1,234,567,890

// 示例 3：URL 参数提取
Pattern p3 = Pattern.compile("[?&](?<key>\\w+)=(?<value>[^&#]+)");
Matcher m3 = p3.matcher("/api?page=2&size=10");
while (m3.find()) {
    m3.group("key");    // page → size
    m3.group("value");  // 2 → 10
}
```

## 8. 核心要点

> 🎯 **核心要点**：
> 1. 分组四类型：捕获（提取）/非捕获（组织，性能好）/命名（语义化）/原子（防回溯）
> 2. 反向引用 `\1` 检测重复模式（成对标签/重复单词）——**但会关闭回溯优化**，不可信输入慎用
> 3. 零宽断言四件套（前瞻/负前瞻/后顾/负后顾）：密码强度校验、金额提取、千分位是三大经典
> 4. 后顾断言跨语言兼容性差（Java 支持变长，Python/JS 只支持定长）
> 5. 原子组 `(?>...)` = 占有量词 `++`：提交不回溯——防灾难回溯的核心武器，但**改变匹配语义**，使用需确认不丢合法匹配
