## 4. 核心概念速查

| 概念 | 一句话解释 |
|------|-----------|
| **正则表达式** | 描述文本模式的「微型语言」——校验/提取/替换/分割 |
| **NFA 引擎** | 回溯型引擎（Java/Python/JS 用）——功能强但可能灾难性回溯 |
| **DFA 引擎** | 线性时间引擎（RE2 用）——免疫 ReDoS 但不支持反向引用 |
| **回溯（Backtracking）** | 匹配失败时回退重试其他路径——性能问题的根源 |
| **灾难性回溯** | 嵌套量词等模式触发 O(2^N) 指数爆炸——ReDoS 的机制 |
| **贪婪量词** | `.*` 尽可能多匹配（默认）——可能吞掉后续内容 |
| **勉强量词** | `.*?` 尽可能少匹配——解析嵌套内容推荐 |
| **占有量词** | `.*+` 匹配后不回溯——把指数级变线性 |
| **原子组** | `(?>...)` 组内匹配提交后不回溯——防灾难回溯利器 |
| **零宽断言** | `(?=...)`/`(?<=...)` 只判断不消耗字符 |
| **反向引用** | `\1` 引用前面捕获组——但会关闭回溯优化！ |
| **ReDoS** | 正则拒绝服务攻击——恶意输入触发指数回溯打垮服务 |
| **预编译** | `Pattern.compile` 一次编译多次复用（线程安全） |
| **RE2/RE2J** | Google 线性时间引擎——处理不可信输入的标准答案 |

## 5. 一图看懂：量词三种模式

```
输入: "<a><b><c>"
模式: <.*>    → 匹配 "<a><b><c>"（贪婪：吞到最后一个 >）
模式: <.*?>   → 匹配 "<a>"（勉强：第一个 > 就停）
模式: <.*+>   → 匹配 "<a><b><c>"（占有：不回溯，一次到底）

关键区别（匹配失败时的行为）：
├── 贪婪  .*    ：回溯逐步减少匹配 → 可能 O(N²) 或指数
├── 勉强  .*?   ：回溯逐步增加匹配 → 同样可能灾难
└── 占有  .*+   ：匹配即提交，永不回溯 → 线性 ✅
→ 安全等级：占有（安全）> 精确字符类 > 贪婪（危险嵌套时）
```
