## 1. 正则的定位与适用边界

> **背景**：正则表达式是描述文本模式的微型语言，1968 年 Ken Thompson 发明，1970s 起成为文本处理标准工具。
> **目的**：校验（输入格式）、提取（抓取片段）、替换（批量改写）、分割（按模式切分）。
> **适用范围**：文本格式校验、日志解析、数据清洗、编辑器查找替换。
> **不适用场景**：嵌套结构解析（HTML/JSON——正则不是解析器！）、任意深度递归（正则无递归能力）、需要语义理解的任务。

```text
正则能做的 vs 不能做的
├── ✅ 能：固定/规则文本（邮箱、手机号、IP、日期、日志行）
├── ⚠️ 勉强：有限嵌套（HTML 标签）——深度受限
├── ❌ 不能：任意嵌套（括号匹配数学表达式——需上下文无关文法）
└── 金句：正则不是解析器——解析 HTML/JSON 用专门的解析库
```

## 2. 字面字符与元字符

### 2.1 两类字符

| 类型 | 说明 | 示例 |
|------|------|------|
| **字面字符** | 匹配自身 | `a` 匹配 "a"，`abc` 匹配 "abc" |
| **元字符** | 有特殊含义 | `. * + ? { } [ ] ( ) \ \| ^ $` |

### 2.2 元字符全集（14 个）

| 元字符 | 含义 | 例子 |
|:---:|------|------|
| `.` | 任意字符（默认不含换行） | `a.c` 匹配 "abc"/"a1c" |
| `*` | 前一项 0 次或多次 | `ab*c` 匹配 "ac"/"abc"/"abbbc" |
| `+` | 前一项 1 次或多次 | `ab+c` 匹配 "abc" 不匹配 "ac" |
| `?` | 前一项 0 次或 1 次 | `ab?c` 匹配 "ac"/"abc" |
| `{n,m}` | 前一项 n 到 m 次 | `a{2,3}` 匹配 "aa"/"aaa" |
| `[ ]` | 字符类 | `[abc]` 匹配 a/b/c 之一 |
| `( )` | 分组 | `(ab)+` 匹配 "abab" |
| `\|` | 或 | `cat\|dog` 匹配 cat 或 dog |
| `^` | 行首锚点 | `^abc` 匹配行首 abc |
| `$` | 行尾锚点 | `abc$` 匹配行尾 abc |
| `\` | 转义/预定义类 | `\.` 匹配字面点 |
| `\d \w \s` | 预定义字符类 | `\d` 匹配数字 |

> ⚠️ **误区**：`.` 不匹配换行符（默认）——需要跨行时用 `(?s)` 标志或 `[\s\S]`。

## 3. 字符类

### 3.1 字符类语法

| 语法 | 含义 | 示例 |
|------|------|------|
| `[abc]` | 集合中任一 | `[aeiou]` 匹配元音 |
| `[a-z]` | 范围 | `[a-zA-Z0-9]` 字母数字 |
| `[^abc]` | 取反（不在集合中） | `[^0-9]` 非数字 |
| `[a-d[m-p]]` | 并集 | `[a-z[0-9]]` 字母或数字 |
| `[a-z&&[^bc]]` | 交集/差集（Java） | `[a-z&&[^aeiou]]` 非元音字母 |
| `[0-9]` | 数字范围 | 等价 `\d`（但只 ASCII） |

### 3.2 字符类的关键认知

```text
字符类内部规则
├── ① 字符类内 . * + ? 是字面量（无需转义）：[.] 匹配点
├── ② 字符类内 ^ 在开头表示取反：[-^] 中 ^ 是字面量
├── ③ 连字符 - 在开头/结尾是字面量：[-a] 或 [a-] 匹配 -
├── ④ 字符类是一个「字符」，量词作用于整个类：[0-9]{4}
└── ⑤ 空字符类 [^] 非法（Java）
```

### 3.3 范围陷阱

```text
范围书写的坑
├── ❌ [z-a]：范围颠倒 → 非法或匹配异常
├── ❌ [a-9]：混合类型范围 → 依赖 ASCII 码，行为诡异
├── ✅ [a-z]、[0-9]、[A-Z]：单类型范围
└── 中文范围：[一-龥]（Java 中可用，但注意码点边界）
```

## 4. 量词

### 4.1 量词全集

| 量词 | 含义 | 匹配 "aaaa" 中的 a |
|:---:|------|:---:|
| `a*` | 0 次或多次 | 全部（贪婪） |
| `a+` | 1 次或多次 | 全部 |
| `a?` | 0 次或 1 次 | 1 个 |
| `a{2}` | 恰好 2 次 | "aa" |
| `a{2,}` | 至少 2 次 | 全部 |
| `a{2,4}` | 2 到 4 次 | "aaaa" |

### 4.2 量词的三种模式（核心！）

| 模式 | 写法 | 行为 | 场景 |
|------|:---:|------|------|
| **贪婪**（默认） | `.*` | 尽可能多匹配，回溯减少 | 默认行为 |
| **勉强（懒惰）** | `.*?` | 尽可能少匹配，回溯增加 | 解析嵌套内容 |
| **占有** | `.*+` | 匹配即提交，永不回溯 | 防灾难性回溯（见 04 篇） |

```java
// 三种模式对比（输入 "<a><b>"）
Pattern.compile("<.*>").matcher("<a><b>").find();
// 贪婪：匹配 "<a><b>"（吞到最后一个 >）

Pattern.compile("<.*?>").matcher("<a><b>").find();
// 勉强：匹配 "<a>"（第一个 > 就停）

Pattern.compile("<.*+>").matcher("<a><b>").find();
// 占有：匹配 "<a><b>"（不回溯，一次到底）

// ⚠️ 占有量词配合 < > 时若失败：直接整体失败（不回溯尝试其他）
// 例如 "<a>" 用 <.*+> 匹配成功；但 "<a" 用 <.*+> 匹配失败
// （不会回溯尝试 . 少匹配——这就是防灾难回溯的原理）
```

### 4.3 量词与回溯（预告）

> ⚠️ **量词是双刃剑**：`(a+)+` 这类「嵌套量词」会让回溯变成指数级（O(2^N)）——30 个 `a` 加一个不匹配字符就有约 2^30 次尝试。这是 ReDoS 的根源，详见 04 篇。

## 5. 锚点与边界

### 5.1 锚点全集

| 锚点 | 含义 | 示例 |
|:---:|------|------|
| `^` | 行首 | `^Error` 匹配以 Error 开头的行 |
| `$` | 行尾 | `Exception$` 匹配以 Exception 结尾 |
| `\b` | 单词边界 | `\bcat\b` 匹配 cat 不匹配 catalog |
| `\B` | 非单词边界 | `\Bcat` 匹配 concatenate 中的 cat |
| `\A` | 输入开头（Java） | 类似 ^ 但不受多行模式影响 |
| `\z` | 输入结尾（Java） | 类似 $ 但不受多行模式影响 |
| `\Z` | 输入结尾（允许末尾换行） | 宽松版 \z |

### 5.2 锚点陷阱

```text
锚点的常见误解
├── ① ^ $ 默认匹配「行」首尾（多行文本中每行都算）
├── ② 想匹配「整个输入」首尾：用 \A \z（Java）或 Pattern.MULTILINE 关闭
├── ③ \b 是「字符类型切换点」——不是空格！
│   cat 在 "cat " 中 \bcat\b 匹配（c 前是边界，t 后空格是边界）
│   "catalog" 中 \bcat 匹配但 cat\b 不匹配（o 不是边界）
└── ④ 中文没有 \b 边界（中文不是 \w 类）——处理中文边界用查边界或分组
```

## 6. 预定义字符类

### 6.1 全集

| 预定义类 | 等价写法 | 含义 |
|:---:|---------|------|
| `\d` | `[0-9]` | 数字（**仅 ASCII**，不含中文数字） |
| `\D` | `[^0-9]` | 非数字 |
| `\w` | `[a-zA-Z_0-9]` | 单词字符（**不含中文！**） |
| `\W` | `[^a-zA-Z_0-9]` | 非单词字符 |
| `\s` | `[ \t\n\x0B\f\r]` | 空白（空格/制表/换行） |
| `\S` | `[^ \t\n\x0B\f\r]` | 非空白 |

### 6.2 关键陷阱（中文场景必读）

```text
预定义类的中文陷阱
├── ⚠️ \w 不含中文：想匹配中文用 [一-龥] 或 Unicode 属性
├── ⚠️ \d 不含全角数字：全角 １２３ 需要显式列出
├── ✅ Java 支持 Unicode 属性：
│   ├── \p{L} 所有字母（含中文）
│   ├── \p{N} 所有数字（含全角）
│   ├── \p{IsHan} 汉字（Java）
│   └── 匹配中文：\p{IsHan}+
└── 结论：国际化文本用 \p{...}，纯英文场景用 \d \w
```

## 7. 转义的艺术

### 7.1 双重转义（Java 字符串 + 正则）

> 🎯 **Java 中正则的转义是双层的**——正则层转义 + 字符串层转义（详见「正斜杠与反斜杠」系列 03 篇）：

```java
// 正则想匹配的字面字符 → Java 字符串写法
// 字面点 .       → 正则 \.      → Java "\\."
// 字面反斜杠 \   → 正则 \\      → Java "\\\\"
// 字面 +         → 正则 \+      → Java "\\+"
// 字面括号 ( )   → 正则 \( \)   → Java "\\(" "\\("

// 实战
Pattern.compile("\\d+\\.\\d{2}")      // 小数 123.45
Pattern.compile("\\\\")               // 匹配反斜杠（4 个！）
Pattern.compile("[\\[\\]]")           // 字符类内的括号
```

### 7.2 避免双重转义的技巧

```text
减少转义痛苦的方案
├── ① 字符类：需要转义的字符放进 [] 可少转义（部分）
├── ② 原始字符串：Python r"..." / C# @"..." / Java 15+ 文本块
├── ③ 正则测试工具：先在线工具验证正则本身，再翻译成 Java
└── ④ Java 文本块（Java 15+）：
    String regex = """
        \\d+\\.\\d{2}
        """;
    // 文本块不解决转义（仍需双写），但提高可读性
```

## 8. 基础实战示例

```java
// 校验类（matches 全匹配）
boolean isPhone = "13812345678".matches("1[3-9]\\d{9}");        // 手机号
boolean isEmail = "a@b.com".matches("[\\w.]+@[\\w.]+\\.[a-z]{2,}"); // 邮箱（简化版）
boolean isDate = "2026-08-04".matches("\\d{4}-\\d{2}-\\d{2}");  // 日期

// 提取类（find + group）
Matcher m = Pattern.compile("\\d+").matcher("订单号: 12345, 金额: 99.50");
while (m.find()) {
    System.out.println(m.group());   // 12345 → 99 → 50
}

// 替换类
String masked = "13812345678".replaceAll("(\\d{3})\\d{4}(\\d{4})", "$1****$2");
// → 138****5678（手机号脱敏）

// 分割类
String[] parts = "a,b;c,d".split("[,;]");   // [a, b, c, d]
```

## 9. 核心要点

> 🎯 **核心要点**：
> 1. 正则四用途：校验/提取/替换/分割——但**不是解析器**（HTML/JSON 用专门库）
> 2. 元字符 14 个 + 字符类（并集/交集 Java 独有）+ 量词三模式（贪婪/勉强/占有）
> 3. 锚点区分「行」与「输入」：^ $ 是行级，\A \z 是输入级（Java）
> 4. 中文陷阱：`\w` 不含中文、`\d` 不含全角——国际化用 `\p{IsHan}`/`\p{L}`
> 5. Java 双重转义：匹配 `\` 写 4 个反斜杠；字符类能减少转义
> 6. 预判预警：嵌套量词 `(a+)+` 是灾难性回溯的起点——详见 04 篇
