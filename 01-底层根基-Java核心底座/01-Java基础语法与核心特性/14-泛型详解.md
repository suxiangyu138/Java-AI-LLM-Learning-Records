## 1. 为什么需要泛型

### 1.1 泛型引入前的问题（JDK 1.4 及以前）

JDK 5 之前，Java 依靠 `Object` 实现通用容器，存在两大缺陷：**类型不安全**、**强制转换繁琐**。

```java
/**
 * 泛型引入前 —— 使用 Object 实现通用容器
 */
class Container {
    private Object obj;

    public void setObj(Object obj) {
        this.obj = obj;
    }

    public Object getObj() {
        return obj;
    }
}

public class WithoutGenerics {
    public static void main(String[] args) {
        Container container = new Container();
        container.setObj(100);
        container.setObj("hello");     // 可以放任意类型，无类型约束

        // 取出时必须强制类型转换
        Integer num = (Integer) container.getObj(); // ❌ ClassCastException
        
        List list = new ArrayList();
        list.add("Hello");
        list.add(123);          // 可以放任意类型
        list.add(new Object());

        String str = (String) list.get(0); // ✅
        // String str2 = (String) list.get(1); // ❌ ClassCastException
    }
}
```

### 1.2 泛型引入后（JDK 5+）

泛型 = **参数化类型**，本质是将数据类型作为"参数"传递给类、接口或方法，在声明时不固定具体类型，在使用时再指定。

```java
/**
 * 泛型引入后 —— 类型安全 + 消除强转
 */
public class WithGenerics {
    public static void main(String[] args) {
        List<String> list = new ArrayList<>();
        list.add("Hello");
        // list.add(123); // ❌ 编译不通过 —— 编译期就能发现问题

        String str = list.get(0); // 不需要强转 —— 编译器自动处理
    }
}
```

### 1.3 核心作用对比

| 维度 | 泛型引入前 | 泛型引入后 |
|------|-----------|-----------|
| **类型安全** | 运行时才暴露 `ClassCastException` | 编译期类型校验，提前拦截错误 |
| **代码简洁** | 每次取出需手动强转 `(Type) obj` | 编译器自动处理类型转换 |
| **代码复用** | 为每种类型单独写容器/工具类 | 一套通用代码适配所有引用类型 |
| **可读性** | `List` 看不出来存什么类型 | `List<String>` 一目了然 |
| **扩展性** | 新增类型需修改通用逻辑 | 无需修改，符合开闭原则 |

```text
> 💡 泛型的本质是编译期语法糖：
> - 编译阶段：检查类型安全
> - 编译之后：执行类型擦除，运行时无额外性能开销
```

### 1.4 常用泛型占位符

| 占位符 | 含义 | 典型场景 |
|--------|------|----------|
| `E` | Element（元素） | 集合元素类型，如 `List<E>`、`Set<E>` |
| `T` | Type（类型） | 普通任意类型，通用泛型类/方法 |
| `K` | Key（键） | Map 的键，如 `Map<K, V>` |
| `V` | Value（值） | Map 的值，如 `Map<K, V>` |
| `N` | Number（数值） | `Number` 及其子类 |
| `R` | Result（返回值） | 方法返回值类型 |
| `?` | 未知类型（通配符） | 方法参数中的灵活适配 |

> ⚠️ 泛型参数不能是基本类型（如 `int`、`double`），仅支持引用类型；基本类型需使用对应包装类（`Integer`、`Double`）。

## 2. 泛型类、泛型接口、泛型方法

### 2.1 泛型类

在类名后加 `<T>`，整个类内都可以使用该泛型类型。实例化时必须指定具体类型。

```java
/**
 * 泛型类 —— 通用容器
 */
class Box<T> {
    private T content;

    public void set(T content) {
        this.content = content;
    }

    public T get() {
        return content;
    }

    public void showType() {
        System.out.println("类型: " + content.getClass().getName());
    }
}

// 使用：JDK 7+ 菱形语法
Box<String> stringBox = new Box<>();
stringBox.set("Hello Generics");
String str = stringBox.get(); // 不需要强转

Box<Integer> intBox = new Box<>();
intBox.set(100);
Integer num = intBox.get();

// Box<int> errorBox = new Box<>(); // ❌ 编译错误：不支持基本类型
```

> ⚠️ `Box<Integer>` 与 `Box<String>` 属于两种完全不同的类型，不可互相赋值。一旦泛型参数确定，全类统一约束。

### 2.2 泛型接口

在接口名后加 `<T>`，实现类可指定具体类型或保留泛型。

```java
/**
 * 泛型接口
 */
interface Pair<K, V> {
    K getKey();
    V getValue();
}

// 实现方式 1：保留泛型（实现类也是泛型类）
class OrderedPair<K, V> implements Pair<K, V> {
    private K key;
    private V value;

    public OrderedPair(K key, V value) {
        this.key = key;
        this.value = value;
    }

    public K getKey() { return key; }
    public V getValue() { return value; }
}

// 实现方式 2：指定具体类型
class StringPair implements Pair<String, Integer> {
    public String getKey() { return "key"; }
    public Integer getValue() { return 42; }
}

// 实际项目中的通用服务接口
interface BaseService<T> {
    T getById(Long id);
    List<T> findAll();
}

class UserServiceImpl implements BaseService<User> {
    @Override
    public User getById(Long id) {
        // 业务逻辑
        return null;
    }

    @Override
    public List<User> findAll() {
        return new ArrayList<>();
    }
}
```

### 2.3 泛型方法

泛型方法的类型参数 **独立于类**，写在返回值前面。普通类也可以定义泛型方法。

```java
/**
 * 泛型方法示例
 */
public class GenericMethodDemo {

    // 1. 基础泛型方法
    public static <T> T getMiddle(T... a) {
        return a[a.length / 2];
    }

    // 2. 交换数组元素
    public static <T> void swap(T[] arr, int i, int j) {
        T temp = arr[i];
        arr[i] = arr[j];
        arr[j] = temp;
    }

    // 3. 打印任意类型数据
    public static <T> void print(T t) {
        System.out.println("数据: " + t + " 类型: " + t.getClass().getName());
    }

    // 4. 获取列表第一个元素
    public static <T> T getFirst(List<T> list) {
        return (list == null || list.isEmpty()) ? null : list.get(0);
    }

    public static void main(String[] args) {
        // 自动推断类型
        String middle = GenericMethodDemo.getMiddle("A", "B", "C");
        
        // 显式指定类型
        Integer mid = GenericMethodDemo.<Integer>getMiddle(1, 2, 3);

        GenericMethodDemo.print(100);       // 自动推断为 Integer
        GenericMethodDemo.print("hello");   // 自动推断为 String
    }
}
```

### 2.4 三种形式对比

| 类型 | 定义位置 | 作用范围 | 类型参数来源 | 典型场景 |
|------|----------|----------|-------------|----------|
| 泛型类 | 类名后 `<T>` | 整个类 | 实例化时指定 | 通用容器、`Result<T>` |
| 泛型接口 | 接口名后 `<T>` | 接口+实现类 | 实现时指定 | `BaseService<T>` |
| 泛型方法 | 返回值前 `<T>` | 仅当前方法 | 调用时推断 | 工具类静态方法 |

> ⚠️ **静态方法必须用泛型方法**，不能使用类的泛型参数（静态成员属于类，类泛型属于实例）。正确做法：`public static <E> E doSomething(E e)`。

## 3. 类型擦除（Type Erasure）深入

### 3.1 什么是类型擦除

Java 泛型是**纯编译期语法糖**，编译完成后擦除所有泛型标记，运行时 JVM 不感知泛型信息。

```text
编译前（带泛型）：                 编译后（擦除后）：
  List<String>           →       List (raw type)
  List<Integer>          →       List (raw type)
  Box<T> (无边界)        →       Box<Object>
  Box<T extends Number>  →       Box<Number> (有边界 → 边界类型)
```

### 3.2 擦除规则

| 泛型定义 | 擦除后等价代码 |
|----------|---------------|
| `<T>`（无界） | 替换为 `Object` |
| `<T extends Number>`（单上界） | 替换为 `Number` |
| `<T extends Comparable<T> & Serializable>`（多上界） | 替换为**第一个**边界类型 `Comparable` |

```java
/**
 * 类型擦除验证 —— 运行时泛型信息消失
 */
public class TypeErasureDemo {
    public static void main(String[] args) {
        List<String> strings = new ArrayList<>();
        List<Integer> integers = new ArrayList<>();

        // ⭐ 运行时泛型类型信息被擦除
        System.out.println(strings.getClass() == integers.getClass());
        // 输出: true —— 都是 ArrayList.class

        // ⭐ 反射可以绕过泛型检查（危险！）
        try {
            // 泛型擦除后，底层是 Object[]
            strings.getClass().getMethod("add", Object.class)
                    .invoke(strings, 123);  // 可以添加 Integer!

            // 但取出来时就会出问题
            for (String s : strings) { // ❌ ClassCastException
                System.out.println(s.length());
            }
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
```

### 3.3 字节码层面查看擦除

```text
编译前（Box.java）:
  class Box<T> {
      private T data;
      public T getData() { return data; }
  }

编译后（javap -c Box.class）:
  class Box {
      private Object data;      // T → Object

      public Object getData() { // T → Object
          return this.data;
      }
  }

有边界时（NumberBox.java）:
  class NumberBox<T extends Number> {
      private T data;
      public T getData() { return data; }
  }

编译后:
  class NumberBox {
      private Number data;      // T → Number（边界类型）
      public Number getData() {
          return this.data;
      }
  }
```

```java
/**
 * 反编译验证 —— 查看字节码
 */
// 在命令行运行：javap -c -p Box.class
// 输出示例：
// public class Box {
//   private java.lang.Object data;
//   public Box();
//   public java.lang.Object getData();
//   public void setData(java.lang.Object);
// }
```

### 3.4 编译期 vs 运行时

| 维度 | 编译期 | 运行时 |
|------|--------|--------|
| 类型参数 | 有效，进行类型检查 | 被擦除，无法获取具体类型 |
| `List<String>` vs `List<Integer>` | 不同类型 | 同为 `List`（原始类型） |
| `instanceof` 检查 | 可检查 `obj instanceof List` | 禁止 `obj instanceof List<String>` |
| 性能 | 无影响 | 无额外开销（擦除后与普通代码相同） |

> 🎯 **核心结论**：Java 泛型是"伪泛型"——类型擦除的目的是**兼容 JDK 5 之前的旧代码**。编译后 `<>` 消失，字节码中变回原始类型。

## 4. 泛型的边界：extends与super

### 4.1 类型上界 `T extends Class`

限制 T 必须是指定类或子类，用于确保类型参数具有某些能力。

```java
/**
 * 类型上界 —— 限制 T 必须是 Number 及其子类
 */
class NumBox<T extends Number> {
    private T num;

    public NumBox(T num) {
        this.num = num;
    }

    // 可以安全调用 Number 的方法
    public double getDouble() {
        return num.doubleValue(); // ✅ Number 的方法
    }

    public int intValue() {
        return num.intValue();    // ✅ Number 的方法
    }
}

// 使用
NumBox<Integer> intBox = new NumBox<>(10);
NumBox<Double> doubleBox = new NumBox<>(3.14);
// NumBox<String> strBox = new NumBox<>("hello"); // ❌ 编译错误

/**
 * 多重边界 —— T 必须同时实现所有指定类型
 * 语法：<T extends ClassA & InterfaceB & InterfaceC>
 */
class MultiBoundBox<T extends Comparable<T> & java.io.Serializable> {
    private T data;

    public int compare(T other) {
        return data.compareTo(other); // ✅ Comparable 的方法
    }
}
```

> ⚠️ 多重边界时，**类必须写在最前面**，接口在后。擦除时替换为**第一个边界**类型。

### 4.2 类型下界

**泛型类型参数没有下界语法**（不存在 `T super Integer`），只有通配符有下界 `? super T`。

| 语法 | 说明 |
|------|------|
| `<T extends Number>` | 类型参数上界：T 可以是 Number 或其子类 |
| `<? super Integer>` | 通配符下界：? 可以是 Integer 或其父类 |
| `<T super Integer>` | ❌ **不存在**，编译错误 |

## 5. 通配符详解：?、? extends T、? super T

### 5.1 为什么需要通配符

泛型不支持协变 —— `List<String>` **不是** `List<Object>` 的子类，即使 `String` 是 `Object` 的子类。通配符 `?` 用于解决这个灵活性问题。

```java
// ❌ 错误：泛型不支持协变
List<Object> list = new ArrayList<String>(); // 编译错误

// ✅ 正确：使用通配符
List<? extends Object> list = new ArrayList<String>(); // ✅

// 对比：数组支持协变
Object[] arr = new String[10]; // ✅ 数组天然协变
```

### 5.2 三种通配符

#### 无界通配符 `?`

匹配任意类型，等价于 `? extends Object`。**只能读取，不能写入**（除 null 外）。

```java
/**
 * 无界通配符 —— 适合只读遍历场景
 */
public static void printList(List<?> list) {
    // 只能读取（用 Object 接收）
    for (Object obj : list) {
        System.out.println(obj);
    }
    // 不能写入
    // list.add("hello");  // ❌ 编译错误
    list.add(null);          // ✅ 唯一例外
}
```

#### 上界通配符 `? extends T`

代表 T 或 T 的子类。**只读不写** —— 适用于生产者（Producer）场景。

```java
/**
 * 上界通配符 —— 读取 Number 及其子类的列表
 */
public static double sumOfList(List<? extends Number> list) {
    double sum = 0.0;
    for (Number n : list) {     // ✅ 可以调用 Number 的方法
        sum += n.doubleValue();
    }
    // list.add(42);            // ❌ 不能写入（类型不确定）
    return sum;
}

// 使用：可以传入 Integer、Double、Long 等
List<Integer> ints = List.of(1, 2, 3);
List<Double> doubles = List.of(1.1, 2.2, 3.3);
System.out.println(sumOfList(ints));    // ✅ 6.0
System.out.println(sumOfList(doubles)); // ✅ 6.6
```

#### 下界通配符 `? super T`

代表 T 或 T 的父类。**可写入 T 及其子类对象**，读取只能转为 Object —— 适用于消费者（Consumer）场景。

```java
/**
 * 下界通配符 —— 向 Integer 及其父类的列表中添加数据
 */
public static void addNumbers(List<? super Integer> list) {
    // 可以写入 Integer 或子类
    list.add(1);    // int → Integer
    list.add(2);
    // 读取时只能用 Object 接收
    // Integer i = list.get(0);  // ❌ 不能保证是 Integer
    Object obj = list.get(0);     // ✅ 只能当 Object 读
}

// 使用：可以传入 Integer、Number、Object 类型的 List
List<Number> nums = new ArrayList<>();
addNumbers(nums); // ✅ List<Number> 是 List<? super Integer> 的子类型
```

### 5.3 三种通配符对比

| 通配符 | 含义 | 可读 | 可写（除 null） | 适用场景 |
|--------|------|------|----------------|----------|
| `?` | 任意类型 | ✅ Object | ❌ | 遍历/打印集合 |
| `? extends T` | T 或 T 的子类 | ✅ T 类型 | ❌ | 读取数据（生产者） |
| `? super T` | T 或 T 的父类 | ✅ Object | ✅ T 子类 | 写入数据（消费者） |

## 6. PECS原则

### 6.1 核心定义

**PECS** = **P**roducer **E**xtends, **C**onsumer **S**uper

| 场景 | 使用 | 记忆口诀 |
|------|------|----------|
| **读取数据**（生产者产出数据供我们消费） | `? extends T` | Producer → Extends |
| **写入数据**（消费者消费我们提供的数据） | `? super T` | Consumer → Super |
| **既读又写** | 不使用通配符，直接 `<T>` | 固定泛型参数 |

### 6.2 PECS 视觉图解

```text
┌─────────────────────────────────────────────────────────┐
│                     PECS 原则                            │
│                                                         │
│  Producer Extends                        Consumer Super  │
│  ────────────────                       ─────────────── │
│                                                         │
│  List<? extends Number>                 List<? super Integer>│
│       │                                      │          │
│       │ 只能读取                               │ 只能写入   │
│       │                                      │          │
│  ┌────▼────┐                           ┌────▼────┐     │
│  │ Number  │   ▲                       │ Object  │     │
│  │  / \    │   │ 读取时                 │   / \   │     │
│  │ Integer │   │ 向上转型               │ Number  │     │
│  │ Double  │   │ 到 T                  │ Integer │  ← 写入│
│  └─────────┘                           └─────────┘     │
│                                                         │
│  可以传入                         可以传入               │
│  List<Integer>                    List<Number>          │
│  List<Double>                     List<Object>          │
│  List<Number>                     List<Integer>         │
└─────────────────────────────────────────────────────────┘
```

### 6.3 源码中的应用

```java
/**
 * Collections.copy 源码 —— PECS 经典应用
 *
 * dest: 消费者（需要写入 T）→ ? super T
 * src:  生产者（需要读取 T）→ ? extends T
 */
public static <T> void copy(List<? super T> dest, List<? extends T> src) {
    for (int i = 0; i < src.size(); i++) {
        dest.set(i, src.get(i)); // 从 src 读，往 dest 写
    }
}

/**
 * Collections.sort 源码 —— 递归通配符
 * T 必须实现 Comparable<T> 或 Comparable 的父类
 */
public static <T extends Comparable<? super T>> void sort(List<T> list) {
    // T 自身或 T 的父类实现了 Comparable 接口
}

/**
 * Collections.addAll
 */
public static <T> boolean addAll(Collection<? super T> c, T... elements) {
    // c: 消费者，写入 T 类型
}
```

### 6.4 实际应用示例

```java
public class PECSExample {
    public static void main(String[] args) {
        List<Number> dest = new ArrayList<>();
        List<Integer> src = List.of(1, 2, 3);

        // dest: 需要写入 Integer → ? super Integer → List<Number> 符合
        // src:  需要读取 Integer → ? extends Integer → List<Integer> 符合
        copy(dest, src);
    }

    public static <T> void copy(List<? super T> dest, List<? extends T> src) {
        for (T item : src) {
            dest.add(item);
        }
    }

    // ❌ 错误用法：既读又写时不能用通配符
    // public static <T> void reverse(List<? extends T> list) {
    //     T temp = list.get(0);  // ✅ 读
    //     list.set(0, list.get(1)); // ❌ 写不进去
    // }

    // ✅ 正确：不用通配符
    public static <T> void reverse(List<T> list) {
        T temp = list.get(0);
        list.set(0, list.get(1));
        list.set(1, temp);
    }
}
```

### 6.5 PECS 速查表

| 场景 | 通配符 | 可读（安全类型） | 可写 | 示例 |
|------|--------|-----------------|------|------|
| 只读取数据 | `? extends T` | ✅ **T** | ❌ | `sum(List<? extends Number>)` |
| 只写入数据 | `? super T` | ✅ Object | ✅ **T 子类** | `addIntegers(List<? super Integer>)` |
| 既读又写 | `<T>` | ✅ **T** | ✅ **T** | `sort(List<T>)` |
| 不关心类型 | `?` | ✅ Object | ❌（仅 null） | `printList(List<?>)` |

> 💡 实际开发中，如果 API 的参数类型不确定，遵循 PECS 原则能提供最大灵活性。

## 7. 泛型与数组

### 7.1 数组支持协变，泛型不支持

```java
// 数组是协变的（可以看作子类型数组是父类型数组的子类型）
Object[] arr = new String[10];   // ✅ 编译通过
arr[0] = "hello";                 // ✅
arr[0] = 123;                     // ✅ 编译通过，但运行时 ArrayStoreException

// 泛型不支持协变
List<Object> list = new ArrayList<String>(); // ❌ 编译错误

// 对比：必须用通配符
List<? extends Object> wildcardList = new ArrayList<String>(); // ✅
```

### 7.2 不能创建泛型数组

```java
// ❌ 不能直接创建泛型数组
// T[] arr = new T[10];              // 编译错误

// ❌ 不能创建参数化类型的数组
// List<String>[] array = new List<String>[10]; // 编译错误

// ✅ 正确方式：创建原始类型数组后强转
@SuppressWarnings("unchecked")
T[] createArray(int size) {
    return (T[]) new Object[size]; // 有 unchecked 警告，但这是唯一办法
}

// ✅ 使用通配符可以创建
List<?>[] array = new List<?>[10];

// ✅ 推荐：用 ArrayList 替代数组
public static <T> List<T> createList() {
    return new ArrayList<>();
}
```

### 7.3 为什么不能创建泛型数组

根本原因：**数组要求运行时类型信息是确定的**（通过 `ArrayStoreException` 保证安全），而泛型的类型信息在运行时已被擦除，无法满足数组的运行时类型检查。

## 8. 泛型擦除的影响：桥接方法、重载冲突

### 8.1 桥接方法（Bridge Method）

桥接方法是编译器自动生成的 **合成方法**，用于保持多态。场景：子类重写泛型父类的方法时。

```java
/**
 * 桥接方法示例
 */
public class BridgeMethodDemo {
    static class Node<T> {
        private T data;

        public void setData(T data) {
            this.data = data;
        }

        public T getData() {
            return data;
        }
    }

    static class StringNode extends Node<String> {
        @Override
        public void setData(String data) {
            System.out.println("StringNode.setData: " + data);
            super.setData(data);
        }
    }

    public static void main(String[] args) throws Exception {
        // 查看 StringNode 的所有方法
        for (java.lang.reflect.Method m : StringNode.class.getDeclaredMethods()) {
            System.out.println(m.toGenericString());
        }
        // 输出（实际有两个 setData 方法）：
        // 1. public void BridgeMethodDemo$StringNode.setData(java.lang.String) ← 我们写的
        // 2. public void BridgeMethodDemo$StringNode.setData(java.lang.Object)  ← 桥接方法
        //
        // 桥接方法内部：调用 (String) arg 版本的 setData

        // 桥接方法的作用：保持多态
        // 当通过父类引用调用时：
        Node<String> node = new StringNode();
        node.setData("hello");  // 实际调用桥接方法 → 再调用 String 版本
    }
}
```

```text
桥接方法原理图：

编译前                          编译后（擦除后）
  Node<T>                       Node
    setData(T data)    →          setData(Object data)
                                    ↑
  StringNode extends              桥接方法自动生成：
    Node<String>                  void setData(Object data) {
    setData(String data)            → 调用 setData(String)
                                  }
```

### 8.2 重载冲突

类型擦除导致两个方法签名在编译后相同，无法作为重载区分。

```java
// ❌ 编译错误：擦除后都是 process(List list)
// public void process(List<String> list) {}
// public void process(List<Integer> list) {}

// ✅ 正确：通过方法名区分
public void processStrings(List<String> list) {}
public void processIntegers(List<Integer> list) {}

// ✅ 或者：使用不同的参数数量
public <T> void process(List<T> list) {}
public <T> void process(List<T> list, String extra) {}
```

> ⚠️ 擦除后方法签名冲突是常见的面试陷阱，记住：**不能以不同类型的泛型参数作为方法重载的区分依据**。

## 9. 泛型的限制与注意事项

### 9.1 六大限制

| 限制 | 错误写法 | 正确写法 | 原因 |
|------|----------|----------|------|
| **不能使用基本类型** | `Box<int>` | `Box<Integer>` | 擦除后是 Object，基本类型不是对象 |
| **不能创建泛型对象** | `new T()` | 反射 `clazz.newInstance()` | 运行时 T 被擦除，无法确定构造器 |
| **不能创建泛型数组** | `new T[10]` | `(T[]) new Object[size]` | 数组运行时需确定类型 |
| **静态成员不能用类泛型** | `static T value` | 静态方法声明自己的 `<E>` | 静态成员先于实例存在 |
| **不能 instanceof 参数化类型** | `obj instanceof List<String>` | `obj instanceof List<?>` | 运行时泛型信息已擦除 |
| **异常类不能是泛型** | `class MyException<T>` | 使用普通异常类 | JVM 异常机制不支持泛型 |

```java
/**
 * 泛型限制演示
 */
public class GenericRestrictions {

    // 1. 不能使用基本类型
    // List<int> list;       // ❌
    List<Integer> list;        // ✅ 必须用包装类

    // 2. 不能创建泛型对象
    public <T> T createBad() {
        // return new T();    // ❌
        return null;
    }

    public <T> T createGood(Class<T> clazz) throws Exception {
        return clazz.getDeclaredConstructor().newInstance(); // ✅ 反射
    }

    // 3. 不能创建泛型数组（但可以通过强转实现）
    @SuppressWarnings("unchecked")
    public <T> T[] createArray(int size) {
        return (T[]) new Object[size]; // ✅ 但有 unchecked 警告
    }

    // 4. 静态变量不能使用类泛型
    // static T staticField;  // ❌

    // 5. 不能 instanceof 参数化类型
    public void check(Object obj) {
        // if (obj instanceof List<String>) // ❌
        if (obj instanceof List<?>) { // ✅ 无界通配符
            List<?> list = (List<?>) obj;
        }
    }
}

// 6. 异常类不能是泛型
// class MyException<T> extends Exception { } // ❌ 编译错误
```

### 9.2 常见误区

| 误区 | 真相 |
|------|------|
| 菱形语法是空指针？ | ❌ 不是！`new ArrayList<>()` 是 JDK 7+ 简化写法，自动匹配左侧类型 |
| 泛型可以存任意类型？ | ❌ 一旦指定类型，只能存该类型及子类对象 |
| `List<?>` 和 `List<Object>` 一样？ | ❌ `List<?>` 只读不可添加，`List<Object>` 可添加任意对象 |
| 泛型会影响运行性能？ | ❌ 不会！编译后泛型被擦除，运行时无额外性能损耗 |
| `List<String>` 是 `List<Object>` 的子类？ | ❌ 泛型不支持继承关系，需用通配符 |

## 10. 泛型在集合框架中的应用

### 10.1 常用集合泛型

```java
// List —— 单类型元素约束
List<String> stringList = new ArrayList<>();
stringList.add("Java");
String s = stringList.get(0); // 无需强制转换

// Set —— 去重单类型约束
Set<Integer> intSet = new HashSet<>();
intSet.add(100);

// Map —— 双类型约束（键 + 值）
Map<String, List<Integer>> dataMap = new HashMap<>();
dataMap.put("numbers", Arrays.asList(1, 2, 3));

// 嵌套泛型的遍历
for (Map.Entry<String, List<Integer>> entry : dataMap.entrySet()) {
    String key = entry.getKey();
    List<Integer> values = entry.getValue();
}
```

### 10.2 集合框架源码中的泛型

```java
// List 接口定义
public interface List<E> extends Collection<E> {
    E get(int index);
    boolean add(E e);
    E remove(int index);
}

// Map 接口定义
public interface Map<K, V> {
    V get(Object key);
    V put(K key, V value);
    Set<Map.Entry<K, V>> entrySet();
}

// Comparable 接口 —— 泛型递归边界
public interface Comparable<T> {
    int compareTo(T o);
}

// Collections.sort —— PECS 应用
public static <T extends Comparable<? super T>> void sort(List<T> list) {
    // T 必须实现 Comparable（T 自身或父类实现了都行）
}
```

> 💡 集合框架是泛型应用最广泛的场景。**90% 的泛型使用都在集合中**，理解集合中的泛型就能应对大部分日常开发。

## 11. 泛型最佳实践

### 11.1 编码规范

| 原则 | 说明 |
|------|------|
| **命名规范** | `E`（元素）、`K`（键）、`V`（值）、`T`（类型）、`R`（返回值） |
| **PECS 原则** | 生产者用 `? extends`，消费者用 `? super` |
| **泛型方法优先** | 工具类方法优先使用泛型方法而非泛型类，更灵活 |
| **避免原始类型** | 不要写 `List` 而不写 `List<String>`，会绕过编译期检查 |
| **使用菱形语法** | JDK 7+ 使用 `new ArrayList<>()` 简化右侧类型 |
| **`@SuppressWarnings("unchecked")` 加注释** | 无法避免 unchecked 时，标注警告并说明理由 |

### 11.2 通用工具类

```java
/**
 * 泛型集合工具类
 */
class CollectionUtils {

    // 数组转 List
    public static <T> List<T> arrayToList(T[] array) {
        List<T> list = new ArrayList<>();
        if (array != null) {
            Collections.addAll(list, array);
        }
        return list;
    }

    // 交换列表元素
    public static <T> void swap(List<T> list, int i, int j) {
        T temp = list.get(i);
        list.set(i, list.get(j));
        list.set(j, temp);
    }
}

/**
 * 类型安全的异构容器 —— 泛型进阶应用
 * 同一个 Map 可以存储不同类型的值，且类型安全
 */
class TypeSafeMap {
    private final Map<Class<?>, Object> map = new HashMap<>();

    public <T> void put(Class<T> type, T value) {
        map.put(type, type.cast(value));
    }

    @SuppressWarnings("unchecked")
    public <T> T get(Class<T> type) {
        return type.cast(map.get(type));
    }

    public static void main(String[] args) {
        TypeSafeMap map = new TypeSafeMap();
        map.put(String.class, "hello");
        map.put(Integer.class, 42);

        String str = map.get(String.class);  // 不需要强转
        Integer num = map.get(Integer.class); // 不需要强转
    }
}
```

### 11.3 常见设计模式中的泛型

| 设计模式 | 泛型用法 | 作用 |
|----------|----------|------|
| **组合模式** | `List<MenuComponent>` | 约束容器只能存统一组件类型 |
| **享元模式** | `Map<String, RoleFlyweight>` | 约束享元池的键值类型 |
| **装饰模式** | 泛型接口定义通用规范 | 适配不同类型的被装饰对象 |
| **适配器模式** | 泛型接口实现通用适配 | 一套代码适配多种类型 |
| **策略模式** | `Comparator<T>` 泛型接口 | 通用的比较策略 |
| **建造者模式** | `GenericBuilder<T>` | 链式调用，返回具体类型 |

    }

## 12. 面试高频考点

### 12.1 基础问题

**Q1: 什么是泛型？核心作用是什么？**
> 泛型是 JDK 5 引入的"参数化类型"，本质是编译期语法糖。核心作用：类型安全（编译期检查）、消除强转、代码复用。

**Q2: 什么是类型擦除？擦除规则是什么？**
> 泛型信息只在编译期存在，运行时被擦除。无界 `<T>` 擦为 `Object`，有界 `<T extends Number>` 擦为边界类型 `Number`。

**Q3: 三种通配符的区别？**
> `?` 无界，只读；`? extends T` 上界，只读（生产者）；`? super T` 下界，可写（消费者）。

**Q4: 什么是 PECS 原则？**
> Producer Extends, Consumer Super。读取用 `? extends T`，写入用 `? super T`，既读又写用 `<T>`。

**Q5: 为什么泛型不能用基本类型？**
> 编译后泛型擦除为 `Object`，基本类型不继承 Object，无法向上转型，必须用包装类。

### 12.2 进阶问题

**Q6: 什么是桥接方法？为什么需要？**
> 编译器自动生成的合成方法。目的：保持多态 —— 子类重写泛型父类方法后，擦除导致方法签名不一致，桥接方法作为桥梁。

**Q7: 泛型方法 vs 泛型类的区别？**
> - 泛型类参数作用于整个类，实例化时指定；泛型方法参数仅作用于当前方法，调用自动推断
> - 泛型方法可独立存在，非泛型类也能定义
> - 静态方法不能使用类的泛型，但可以有自己的泛型方法

**Q8: 为什么不能创建泛型数组 `new T[10]`？**
> 数组运行时类型信息必须确定（用于 `ArrayStoreException` 检查），泛型运行时已擦除，矛盾。

**Q9: List<String> 和 List<Integer> 运行时是同一个类吗？**
> 是的。`strings.getClass() == integers.getClass()` 返回 `true` —— 都是 `ArrayList.class`。

**Q10: 如何通过反射绕开泛型检查？**
> 利用类型擦除，通过 `Method.invoke(list, obj)` 添加非泛型类型元素。但取出时会抛 `ClassCastException`。

### 12.3 易错代码题

```java
// 题1：以下代码会编译报错吗？
List<?> list = new ArrayList<Integer>();
list.add(1); // ❌ 编译错误 —— ? 不能写入（除 null）

// 题2：以下代码会编译报错吗？
List<Object> list = new ArrayList<String>(); // ❌ 泛型不支持协变

// 题3：以下代码会输出什么？
List<String> a = new ArrayList<>();
List<Integer> b = new ArrayList<>();
System.out.println(a.getClass() == b.getClass()); // true —— 类型擦除

// 题4：以下两个方法能共存吗？
// void foo(List<String> list) {}
// void foo(List<Integer> list) {}
// ❌ 不能 —— 擦除后都是 foo(List list)

// 题5：静态方法能这样用泛型吗？
class Test<T> {
    // public static T getValue() { return null; }  // ❌ 静态方法不能使用类泛型
    public static <E> E getValue(E e) { return e; }  // ✅ 定义自己的泛型
}
```
