## 1. 继承的核心概念

### 1.1 什么是继承

继承（Inheritance）是 Java 面向对象三大核心特性（封装、继承、多态）之一，允许一个类（子类）直接获取另一个类（父类）的非私有成员，并在其基础上扩展新功能。

| 概念 | 英文 | 说明 |
|------|------|------|
| **继承** | Inheritance | 子类直接获取父类的非私有属性和方法 |
| **子类（派生类）** | Subclass / Derived Class | 继承父类的类，可在父类基础上扩展 |
| **父类（基类）** | Superclass / Base Class | 被继承的类，提供公共属性和方法 |

### 1.2 三大核心价值

| 价值 | 说明 |
|------|------|
| **代码复用** | 减少重复代码，降低开发成本，子类复用父类已有实现 |
| **代码扩展** | 子类新增属性和方法，实现功能升级 |
| **奠定多态基础** | 子类对象可以赋值给父类引用，通过方法重写实现运行时多态 |

### 1.3 继承关系判断：is-a 原则

> 💡 继承必须符合 **is-a**（是一个）关系，否则应优先考虑组合。

| 判断 | 示例 | 结论 |
|------|------|------|
| ✅ 正确 | `Student is a Person` | Student 继承 Person |
| ✅ 正确 | `Dog is a Animal` | Dog 继承 Animal |
| ❌ 错误 | `Student is a Teacher` | 平级关系，不应互相继承 |
| ❌ 错误 | `Square is a Rectangle` | 违反里氏替换原则（详见第 10 节） |

## 2. extends 关键字与继承语法

### 2.1 关键字说明

`extends` 是 Java 中实现继承的核心关键字，位于类声明之后，父类名之前。

> `extends` 关键字：表示一个类继承另一个类（类单继承）或一个接口继承另一个接口（接口多继承）。

### 2.2 基本语法

```java
// 父类（基类）：定义公共的属性和方法
class 父类名 {
    访问修饰符 数据类型 属性名;
    访问修饰符 返回值类型 方法名(参数列表) { }
}

// 子类（派生类）：继承父类，扩展自身功能
class 子类名 extends 父类名 {
    // 子类特有属性
    访问修饰符 数据类型 子类特有属性;

    // 子类特有方法
    访问修饰符 返回值类型 子类特有方法(参数列表) { }

    // 重写父类方法
    @Override
    访问修饰符 返回值类型 父类方法名(参数列表) { }
}
```

### 2.3 完整实战案例

```java
// 父类：Person（人）
class Person {
    String name;
    int age;

    public void eat() {
        System.out.println(name + " 在吃饭");
    }

    public void sleep() {
        System.out.println(name + " 在睡觉");
    }
}

// 子类：Student（学生）
class Student extends Person {
    String studentId;           // 子类特有属性：学号

    public void study() {       // 子类特有方法
        System.out.println(name + "（学号：" + studentId + "）在学习 Java");
    }

    @Override
    public void eat() {         // 重写父类方法
        System.out.println(name + " 在学校食堂吃饭，注重营养均衡");
    }
}

// 测试
public class TestInheritance {
    public static void main(String[] args) {
        Student student = new Student();
        student.name = "张三";          // 继承父类属性
        student.age = 18;               // 继承父类属性
        student.studentId = "2024001";  // 子类特有属性

        student.eat();     // 调用重写后的方法
        student.sleep();   // 继承父类的方法
        student.study();   // 子类特有方法
    }
}
```

### 2.4 继承的传递性

> 💡 继承具有传递性：子类不仅继承直接父类的成员，还继承所有间接父类的成员。

```java
class Grandfather {
    public void run() { System.out.println("祖父会跑步"); }
}

class Father extends Grandfather {
    public void work() { System.out.println("父亲会工作"); }
}

class Son extends Father {
    public void play() { System.out.println("儿子会玩耍"); }
}

Son son = new Son();
son.run();   // 继承祖父类的方法
son.work();  // 继承父类的方法
son.play();  // 自身的方法
```

## 3. Java 单继承与多层继承

### 3.1 单继承规则

> ⚠️ Java **只支持单继承**：一个子类只能有一个直接父类。

```java
// ❌ 错误：不能同时继承多个父类
class Student extends Person, Animal { }  // 编译报错
```

### 3.2 为什么不支持多继承

核心原因：**避免菱形继承（Diamond Problem）**导致的歧义。

```
      Animal
      /    \
   Mammal  Pet
      \    /
      Dog  ← 同时继承 Mammal 和 Pet，
             如果两个父类都有同名方法 speak()，
             子类无法确定调用哪个
```

**解决方案**：通过"接口多实现"弥补单继承的局限性。

```java
// ✅ 正确：单继承 + 多实现
class Student extends Person implements Studyable, Sportable { }
```

### 3.3 多层继承

Java 虽然不支持多继承，但支持**多层继承**（继承链）：

```java
class A { }
class B extends A { }
class C extends B { }   // C → B → A 三层继承
```

> 💡 多层继承有助于建立清晰的类层次结构，但层数不宜过深（一般不超过 3 层），否则会增加维护复杂度。

## 4. 子类构造方法与 super 关键字

### 4.1 构造方法的继承规则

> ⚠️ 子类**不能继承**父类的构造方法，但必须（显式或隐式）调用父类构造方法。

| 场景 | 规则 |
|------|------|
| 父类有无参构造 | 子类构造方法默认调用 `super()`（隐式） |
| 父类只有有参构造 | 子类必须手动调用 `super(参数)` |
| `super()` 位置 | 必须放在子类构造方法**第一行** |

```java
class Person {
    String name;

    // 父类只有有参构造
    public Person(String name) {
        this.name = name;
    }
}

class Student extends Person {
    String studentId;

    // 子类必须手动调用父类有参构造
    public Student(String name, String studentId) {
        super(name);          // ⚠️ 必须放在第一行
        this.studentId = studentId;
    }
}
```

### 4.2 构造方法链执行顺序

当创建子类对象时，构造方法会从最顶层父类开始逐层调用：

```java
class GrandParent {
    GrandParent() { System.out.println("1-GrandParent"); }
}

class Parent extends GrandParent {
    Parent() { System.out.println("2-Parent"); }
}

class Child extends Parent {
    Child() { System.out.println("3-Child"); }
}

// 输出顺序：1-GrandParent → 2-Parent → 3-Child
new Child();
```

### 4.3 super 关键字详解

`super` 关键字指代父类对象，有三种用法：

| 用法 | 语法 | 场景 |
|------|------|------|
| 调用父类构造方法 | `super(参数)` / `super()` | 子类构造方法中，必须第一行 |
| 访问父类属性 | `super.属性名` | 子类与父类有同名属性时区分 |
| 调用父类方法 | `super.方法名(参数)` | 子类重写了方法，仍想调用父类原实现 |

```java
public class Manager extends Employee {
    private double bonus;

    public Manager(String name, double salary, double bonus) {
        super(name, salary);   // 调用父类构造方法
        this.bonus = bonus;
    }

    public double getTotalSalary() {
        return super.getSalary() + bonus;  // 调用父类方法
    }

    @Override
    public String toString() {
        return super.toString() + ", bonus=" + bonus;  // 调用父类被重写的方法
    }
}
```

### 4.4 super vs this

| 关键字 | 指代 | 用途 |
|--------|------|------|
| `this` | 当前对象 | 访问当前类的属性、方法、构造方法 |
| `super` | 父类对象 | 访问父类的属性、方法、构造方法 |

```java
class Child extends Parent {
    private String name;

    public Child(String name, String parentName) {
        super(parentName);       // 调用父类构造（必须第一行）
        this.name = name;        // this.name = 当前类的成员变量
    }
}
```

> 💡 `this()` 和 `super()` 都必须在构造方法的第一行，因此二者**不能同时出现**。

## 5. 方法重写（Override）

### 5.1 什么是方法重写

子类定义与父类**方法名、参数列表、返回值类型**完全一致的方法，覆盖父类的实现。

### 5.2 重写规则

| 规则 | 要求 |
|------|------|
| 方法签名 | 方法名、参数列表必须与父类完全一致 |
| 返回值类型 | 必须是父类返回值的子类或本身（协变返回类型，JDK 5+） |
| 访问修饰符 | 子类权限**不能低于**父类（父 `protected`，子必须 `protected` 或 `public`） |
| 异常声明 | 不能抛出比父类更宽泛的异常（可以不抛或抛出子类异常） |
| `@Override` | 强烈建议使用，编译器可检查是否真正重写 |
| 不可重写 | `final` 方法、`static` 方法、`private` 方法 |

### 5.3 重写代码示例

```java
class Parent {
    protected Number calculate(int x) throws IOException {
        return x * 2;
    }
}

class Child extends Parent {
    @Override
    public Integer calculate(int x) {     // 协变返回类型：Number → Integer
        return x * 3;                     // 不抛异常（比父类更严格，允许）
    }
}
```

### 5.4 Override vs Overload

| 对比维度 | 重写（Override） | 重载（Overload） |
|----------|-----------------|------------------|
| 发生范围 | 子类与父类之间 | 同一类中 |
| 方法签名 | 必须完全一致 | 必须不同（参数个数/类型/顺序） |
| 返回值类型 | 相同或是父类返回值的子类型 | 无要求 |
| 访问修饰符 | 不能比父类更严格 | 无要求 |
| 异常声明 | 不能比父类更宽泛 | 无要求 |
| 核心作用 | 扩展父类方法，实现子类特有逻辑 | 同一方法名处理不同参数，简化调用 |
| 关键字 | `@Override` 推荐使用 | 无对应注解 |

### 5.5 重写注意事项

> ⚠️ **构造方法中调用可重写方法存在风险**：子类对象可能还未初始化完全，调用重写方法会导致意外行为。

```java
class Parent {
    Parent() { init(); }  // 构造方法中调用可重写方法
    public void init() { System.out.println("Parent init"); }
}

class Child extends Parent {
    private String value = "child-value";

    @Override
    public void init() {
        System.out.println("Child init, value = " + value.length());  // NullPointerException!
    }
}
// 输出异常：因为子类字段还未初始化，调用的是子类的 init() 但 value 为 null
```

## 6. 访问权限与继承

### 6.1 子类可继承的成员

| 修饰符 | 同类 | 同包 | 子类（不同包） | 任意 |
|--------|:----:|:----:|:--------------:|:----:|
| `private` | Y | N | N | N |
| `default`（无修饰符） | Y | Y | N | N |
| `protected` | Y | Y | Y | N |
| `public` | Y | Y | Y | Y |

### 6.2 子类不能继承的成员

> ⚠️ `private` 修饰的属性和方法，子类无法直接访问、继承或重写。

```java
class Person {
    private String idCard;                // 私有属性

    public String getIdCard() {           // 公共 getter
        return idCard;
    }
}

class Student extends Person {
    public void showIdCard() {
        // System.out.println(idCard);     // ❌ 不能直接访问
        System.out.println(getIdCard());   // ✅ 通过公共 getter 间接访问
    }
}
```

### 6.3 方法重写的访问权限规则

> 💡 子类重写方法时，访问修饰符**不能比父类更严格**，但可以更宽松。

```java
class Parent {
    protected void method() { }     // protected 访问权限
}

class Child extends Parent {
    @Override
    public void method() { }        // ✅ 可以提升为 public
    // @Override
    // void method() { }            // ❌ 不能降级为 default（比 protected 更严格）
}
```

## 7. final 关键字：阻止继承

### 7.1 final 对继承的限制

| 修饰目标 | 效果 | 示例 |
|----------|------|------|
| **类** | 不能被继承 | `final class String {}` |
| **方法** | 不能被重写 | `public final void init() {}` |
| **变量** | 常量，定义时必须赋值 | `final int MAX = 100;` |

### 7.2 final 类

`final` 修饰的类不能被继承，常用于安全性和不可变性设计。

```java
// String 类被 final 修饰，不可被继承
public final class String { /* ... */ }

// ❌ 编译错误：无法从 final 类继承
// class MyString extends String { }
```

### 7.3 final 方法

`final` 方法可以被子类继承使用，但不能被子类重写。

```java
class Parent {
    public final void init() {
        System.out.println("初始化流程，不可修改");
    }
}

class Child extends Parent {
    // ❌ 编译错误：不能重写 final 方法
    // @Override
    // public void init() { }
}
```

### 7.4 final 的继承与子类使用

```java
class Parent {
    public final int MAX_SIZE = 100;   // 常量（子类可继承使用）
}

class Child extends Parent {
    public void show() {
        System.out.println(MAX_SIZE);  // ✅ 继承使用，值为 100
        // MAX_SIZE = 200;             // ❌ 不能修改 final 变量
    }
}
```

## 8. Object 类：所有类的根

### 8.1 Object 类概述

`Object` 是 Java 中所有类的根父类（包括数组）。任何类都直接或间接继承自 `Object`。

> 💡 如果一个类没有显式使用 `extends` 继承其他类，则默认继承 `Object` 类。

```java
// 以下两种写法等价
public class MyClass { }
public class MyClass extends Object { }
```

### 8.2 Object 类的主要方法

| 方法 | 用途 | 说明 |
|------|------|------|
| `equals(Object obj)` | 判断对象是否相等 | 默认比较内存地址，推荐重写为值比较 |
| `hashCode()` | 返回对象的哈希码 | 与 `equals` 一致，重写 `equals` 必须重写 |
| `toString()` | 返回对象的字符串表示 | 默认输出 `类名@哈希码` |
| `clone()` | 创建并返回对象的副本 | 需实现 `Cloneable` 接口 |
| `getClass()` | 返回对象的运行时类 | 不可重写（`final` 方法） |
| `finalize()` | 垃圾回收前调用 | JDK 9+ 已弃用 |
| `notify()` / `wait()` | 线程间通信 | 与 synchronized 配合使用 |

### 8.3 示例：继承 Object 的意义

```java
public class Student extends Object {   // 显式继承 Object
    private String name;

    @Override
    public String toString() {
        return "Student{name='" + name + "'}";
    }

    public static void main(String[] args) {
        Student s = new Student();
        System.out.println(s.toString());               // 调用重写后的 toString
        System.out.println(s.getClass().getName());     // 继承自 Object
        System.out.println(s.hashCode());               // 继承自 Object
    }
}
```

## 9. 继承 vs 组合

### 9.1 核心对比

| 对比维度 | 继承（Inheritance） | 组合（Composition） |
|----------|-------------------|-------------------|
| 关系 | is-a（是一个） | has-a（有一个） |
| 代码复用 | 子类自动获取父类成员 | 通过持有其他类的引用来复用 |
| 耦合度 | 高（子类依赖父类实现） | 低（通过接口依赖） |
| 灵活性 | 编译期确定，不易改变 | 运行时可替换，更灵活 |
| 封装性 | 破坏封装（子类可访问父类细节） | 保持封装（通过接口交互） |
| 变更影响 | 父类变更可能影响所有子类 | 被组合对象的变更影响范围小 |

### 9.2 组合优先于继承

> 🎯 **Effective Java 第 18 条**：组合优先于继承（Favor composition over inheritance）。

继承并非所有场景都适用。当子类和父类之间**不是严格的 is-a 关系**，或父类的实现细节可能变化时，继承会带来脆弱性。

### 9.3 继承不当的反例

```java
// 继承：不适合的场景 —— 会导致计数不准确
public class InstrumentedHashSet<E> extends HashSet<E> {
    private int addCount = 0;

    @Override
    public boolean add(E e) {
        addCount++;
        return super.add(e);
    }

    @Override
    public boolean addAll(Collection<? extends E> c) {
        addCount += c.size();  // 但父类的 addAll 内部调用了 add，导致重复计数
        return super.addAll(c);
    }
}

// 使用时计数异常
InstrumentedHashSet<String> set = new InstrumentedHashSet<>();
set.addAll(Arrays.asList("A", "B", "C"));
System.out.println(set.getAddCount());  // 输出 6，而非 3！
// 原因：父类 HashSet 的 addAll 内部调用了 add，每个元素被计数两次
```

### 9.4 组合的更优方案

```java
// 组合：更好的方案
public class InstrumentedSet<E> {
    private final Set<E> set;           // 组合一个 Set 对象
    private int addCount = 0;

    public InstrumentedSet(Set<E> set) {
        this.set = set;
    }

    public boolean add(E e) {
        addCount++;
        return set.add(e);
    }

    public boolean addAll(Collection<? extends E> c) {
        addCount += c.size();
        return set.addAll(c);
    }

    public int getAddCount() { return addCount; }
}
```

### 9.5 何时使用继承

| 使用继承 ✅ | 使用组合 ✅ |
|-----------|-----------|
| 明确的 is-a 关系 | has-a 关系 |
| 子类不会改变父类核心行为 | 只需要使用某个类的功能 |
| 父类设计稳定，不常变更 | 不确定父类是否会变更 |
| 子类与父类处于同一抽象层次 | 需要运行时动态替换行为 |
| 需要利用方法重写实现多态 | 需要解耦和更低的依赖 |

## 10. 继承设计最佳实践

### 10.1 里氏替换原则（LSP）

> 🎯 **里氏替换原则**：所有引用基类的地方必须能透明地使用其子类对象。子类可以扩展功能，但不能改变父类已约定的行为。

**违反 LSP 的反例**：

```java
// 反例：正方形不是好的长方形子类
class Rectangle {
    private int width;
    private int height;

    public void setWidth(int w) { this.width = w; }
    public void setHeight(int h) { this.height = h; }
    public int getArea() { return width * height; }
}

class Square extends Rectangle {
    @Override
    public void setWidth(int w) {
        super.setWidth(w);
        super.setHeight(w);     // 强制宽高相等
    }

    @Override
    public void setHeight(int h) {
        super.setWidth(h);
        super.setHeight(h);
    }
}

// 使用方期望 Rectangle 行为一致 —— 但 Square 破坏了它
Rectangle rect = new Square();
rect.setWidth(5);
rect.setHeight(10);
System.out.println(rect.getArea());  // 输出 100，而非预期的 50！
```

**LSP 实践指南**：
- 子类重写方法时，前置条件不能放大，后置条件不能缩小
- 子类不应抛出父类未预期的异常
- 可以用组合替代继承来避免 LSP 问题

### 10.2 继承设计原则总结

| 原则 | 说明 |
|------|------|
| **is-a 验证** | 确保子类与父类存在"是一个"关系 |
| **LSP 验证** | 确保子类对象可替换父类对象而不改变程序正确性 |
| **抽象类优于具体类** | 继承抽象类比继承具体类更安全（具体类的实现细节可能变更） |
| **避免过深继承链** | 继承层次一般不超过 3 层，过深增加维护成本 |
| **优先使用接口** | 接口定义契约，比继承更灵活、解耦 |
| **组合优先于继承** | 不是严格 is-a 关系时，优先使用组合 |
| **构造方法中避免调用可重写方法** | 防止子类未完全初始化导致的异常 |

### 10.3 常见陷阱

| 陷阱 | 说明 |
|------|------|
| 滥用继承 | 没有 is-a 关系却使用继承，导致高耦合 |
| 构造方法中调用可重写方法 | 子类可能还未初始化完全 |
| 向下转型不检查 `instanceof` | 可能抛出 `ClassCastException` |
| 父类私有方法"重写" | 子类可以定义同名方法，但这不是重写（父类私有方法不可见） |
| 忽略 `@Override` 注解 | 拼写错误时编译器不会报错，变成新方法而非重写 |
| 继承链过深 | 理解和维护成本指数级增加 |

## 11. 面试高频考点

### 11.1 Java 为什么不支持多继承？

> 核心原因：**避免菱形继承（歧义）问题**。

假设子类同时继承两个父类，两个父类有同名方法，子类无法确定调用哪个。Java 通过 **"单继承 + 接口多实现"** 解决——既满足多维度的功能扩展，又避免歧义。

### 11.2 父类的私有方法，子类能继承吗？

> ❌ **不能**。`private` 修饰的方法仅父类内部可见，子类无法继承、访问、重写。

但子类可通过父类的 `public`/`protected` getter/setter **间接访问**私有属性。

### 11.3 子类能继承父类的构造方法吗？

> ❌ **不能**。子类必须在自己的构造方法中通过 `super()` 调用父类构造方法。

- 父类有无参构造：子类默认隐式调用 `super()`
- 父类只有有参构造：子类必须显式调用 `super(参数)`

### 11.4 静态方法能被重写吗？

> ❌ 不能。静态方法属于类而非对象，子类定义的同名静态方法称为**方法隐藏**（Method Hiding），不是重写（不参与多态）。

```java
class Parent {
    public static void show() { System.out.println("Parent"); }
}

class Child extends Parent {
    public static void show() { System.out.println("Child"); }  // 隐藏，非重写
}

Parent p = new Child();
p.show();   // 输出 "Parent"（编译时绑定，非多态）
```

### 11.5 方法重写 vs 方法重载

| 对比维度 | 重写（Override） | 重载（Overload） |
|----------|-----------------|------------------|
| 发生范围 | 子类与父类之间 | 同一类中 |
| 方法名 | 相同 | 相同 |
| 参数列表 | 必须完全一致 | 必须不同（个数/类型/顺序） |
| 返回值 | 相同或子类型（协变） | 无要求 |
| 访问修饰符 | 不能更严格 | 无要求 |
| 编译/运行时 | 运行时多态 | 编译时多态 |

### 11.6 super vs this

```java
class Child extends Parent {
    private String name;

    public Child(String name, String parentName) {
        super(parentName);      // 调用父类构造
        this.name = name;       // 区分成员变量和参数
    }
}
```

### 11.7 继承知识体系

```text
继承知识体系
├── 核心价值：代码复用 → 代码扩展 → 奠定多态基础
├── 语法：extends + super + @Override
├── 特性：单继承、传递性、不可继承私有、方法重写
├── 限制：构造方法不继承、final 不可重写/继承、必须 is-a
└── 面试：菱形继承、Override vs Overload、super vs this、LSP
```

> 🎯 **核心总结**：继承是 Java 面向对象的三大支柱之一，合理使用继承可以显著提升代码复用性和可维护性。但继承也伴随着高耦合的风险，务必遵循 **is-a 原则**、**里氏替换原则**，并在不满足继承条件时优先使用**组合**。掌握 `super` 关键字、方法重写规则、`final` 的限制以及继承链的执行顺序，是应对面试和实战开发的基础。
