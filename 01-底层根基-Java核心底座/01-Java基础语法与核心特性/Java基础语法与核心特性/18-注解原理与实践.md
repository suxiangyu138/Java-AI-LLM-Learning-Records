## 1. 注解概述与价值

### 1.1 什么是注解

> 注解（Annotation）是 Java 5 引入的**元数据**形式，为代码添加结构化、可被工具读取的标记信息。注解本身不影响代码直接执行，但可通过编译器或运行时框架触发特定行为。

**注解的三种角色**：

| 角色 | 说明 | 示例 |
|------|------|------|
| 编译器指令 | 辅助编译检查 | `@Override`、`@SuppressWarnings` |
| 编译时代码生成 | javac 扫描生成额外源码 | `@Data` (Lombok)、`@Mapper` (MyBatis) |
| 运行时行为 | 反射读取注解动态执行逻辑 | `@Autowired`、`@Transactional` |

### 1.2 注解 vs 注释

| 维度 | 注解（Annotation） | 注释（Comment） |
|------|-------------------|-----------------|
| 定义 | `@interface` | `//` 或 `/* */` |
| 处理者 | 编译器 / JVM / 框架 | 仅人类阅读 |
| 作用 | 影响编译、代码生成、运行行为 | 纯说明 |
| 保留策略 | SOURCE / CLASS / RUNTIME | 编译即丢弃 |

## 2. 内置注解：@Override、@Deprecated、@SuppressWarnings、@SafeVarargs

| 注解 | JDK | 作用 | 保留策略 |
|------|-----|------|----------|
| `@Override` | 5 | 标识方法重写，编译器校验签名 | SOURCE |
| `@Deprecated` | 5 | 标记已过时元素，编译时产生警告 | RUNTIME |
| `@SuppressWarnings` | 5 | 抑制指定编译器警告 | SOURCE |
| `@SafeVarargs` | 7 | 抑制堆污染警告，用于泛型可变参数 | CLASS |
| `@FunctionalInterface` | 8 | 标识函数式接口（仅一个抽象方法） | RUNTIME |

```java
public class BuiltInAnnotationDemo {
    @Override
    public String toString() { return "重写校验"; }

    @Deprecated(since = "2.0", forRemoval = true)
    public void oldMethod() {}

    @SuppressWarnings("unchecked")
    public void suppressWarning() {
        List raw = new ArrayList();
        List<String> safe = raw;
    }

    @SafeVarargs
    public static <T> void safeVarargs(T... args) {}

    @FunctionalInterface
    interface Converter<F, T> {
        T convert(F from);
    }
}
```

> ⚠️ `@Override` 是 SOURCE 级别，编译后即消失，反射不可读。`@Deprecated` 保留到 RUNTIME。

## 3. 元注解：@Target、@Retention、@Documented、@Inherited、@Repeatable

### 3.1 元注解一览

元注解是**注解其他注解**的注解，是定义注解时的基础语法。

| 元注解 | 说明 | 常用参数 |
|--------|------|----------|
| `@Target` | 限定注解可用范围 | TYPE, FIELD, METHOD, PARAMETER, CONSTRUCTOR, ANNOTATION_TYPE, PACKAGE, TYPE_PARAMETER, TYPE_USE |
| `@Retention` | 注解生命周期 | SOURCE, CLASS, RUNTIME |
| `@Documented` | 注解出现在 Javadoc | 无参数 |
| `@Inherited` | 子类继承父类注解（限类） | 无参数 |
| `@Repeatable` | 允许同一位置重复标注 | 值为容器注解的 Class |

### 3.2 @Retention 详解

| 策略 | 源码 | Class文件 | JVM运行时 | 适用场景 |
|------|:----:|:---------:|:---------:|----------|
| SOURCE | ✅ | ❌ | ❌ | `@Override`, `@SuppressWarnings`, Lombok 注解 |
| CLASS | ✅ | ✅ | ❌ | 字节码增强工具 |
| RUNTIME | ✅ | ✅ | ✅ | Spring 注解, JUnit, MyBatis |

> 💡 **选型建议**：能选 SOURCE 不选 CLASS，能选 CLASS 不选 RUNTIME。仅当框架需要在运行时通过反射读取注解时才用 RUNTIME。

### 3.3 @Repeatable 示例

```java
@Repeatable(Schedules.class)
@interface Schedule {
    String dayOfWeek();
}

@interface Schedules {
    Schedule[] value();
}

@Schedule(dayOfWeek = "Mon")
@Schedule(dayOfWeek = "Fri")
class WeekPlan {}

// 获取：clazz.getAnnotationsByType(Schedule.class)
```

> 💡 `@Repeatable` 是 JDK 8 语法糖，底层仍以容器数组形式存储。

## 4. 自定义注解的设计与实现

### 4.1 定义语法与支持类型

```java
@Target(ElementType.FIELD)
@Retention(RetentionPolicy.RUNTIME)
@interface Length {
    int min() default 0;               // 基本类型
    int max() default Integer.MAX_VALUE;
    String message() default "长度不合法";  // String
}
```

| 支持类型 | 示例 |
|----------|------|
| 基本类型 | `int value() default 0;` |
| String | `String name() default "";` |
| Class | `Class<?> clazz() default Object.class;` |
| 枚举 | `Level level() default Level.INFO;` |
| 注解 | `Another ann() default @Another;` |
| 以上类型的数组 | `String[] tags() default {};` |

### 4.2 完整示例

```java
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
@interface LogExecution {
    String value() default "";          // 特殊属性：名称为 value 可省略 "value ="
    Level level() default Level.INFO;

    enum Level { INFO, WARN, DEBUG }
}

// 使用：@LogExecution("login") 等价于 @LogExecution(value = "login")
class UserForm {
    @LogExecution("login")
    public boolean login() { return true; }
}
```

### 4.3 注意事项

- 属性不能为 `null` 作为默认值（`String` 用 `""`，数组用 `{}`）
- 不能定义 `throws` 异常
- 属性名为 `value` 且仅此属性需赋值时可省略 `value =`

## 5. 运行时注解解析（反射+注解）

### 5.1 核心 API

| 方法 | 作用 |
|------|------|
| `clazz.isAnnotationPresent(Class)` | 判断是否存在指定注解 |
| `clazz.getAnnotation(Class)` | 获取指定注解，不存在返回 null |
| `clazz.getAnnotations()` | 获取所有注解（含继承） |
| `clazz.getDeclaredAnnotations()` | 获取本类所有注解（不含继承） |
| `clazz.getAnnotationsByType(Class)` | 获取 @Repeatable 重复注解 |

### 5.2 表单验证框架实战

```java
import java.lang.annotation.*;
import java.lang.reflect.Field;
import java.util.*;

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
@interface NotNull {
    String message() default "不能为 null";
}

class UserForm {
    @NotNull(message = "用户名不能为空")
    private String username;

    public UserForm(String username) { this.username = username; }
}

class AnnotationValidator {
    public static List<String> validate(Object obj) {
        List<String> errors = new ArrayList<>();
        for (Field field : obj.getClass().getDeclaredFields()) {
            field.setAccessible(true);
            try {
                Object value = field.get(obj);
                NotNull nn = field.getAnnotation(NotNull.class);
                if (nn != null && value == null) {
                    errors.add(field.getName() + ": " + nn.message());
                }
            } catch (IllegalAccessException e) {
                errors.add(field.getName() + ": 无法访问");
            }
        }
        return errors;
    }

    public static void main(String[] args) {
        UserForm uf = new UserForm(null);
        validate(uf).forEach(System.out::println);
        // 输出：username: 用户名不能为空
    }
}
```

## 6. 编译时注解处理（APT/Pluggable Annotation Processing）

### 6.1 APT 工作原理

```text
javac 编译流程：
  .java 源码 → AST（抽象语法树）→ 注解扫描 → 匹配 Processor
  → RoundEnvironment → process() → 生成新 .java / 资源文件
  → 再次编译（多轮处理）→ .class 字节码
```

> APT 是 javac 的内置机制，通过 `ServiceLoader` 发现并执行注解处理器，支持**多轮处理**。

### 6.2 核心 API

| API | 作用 |
|------|------|
| `AbstractProcessor` | 自定义处理器基类，必须继承 |
| `ProcessingEnvironment` | 处理器环境，提供 `Filer`、`Elements`、`Messager` |
| `RoundEnvironment` | 当前轮次信息，获取被注解的元素 |
| `Filer` | 生成新源文件、class 文件、资源文件 |
| `Elements` | 操作包/类/方法/字段等源码元素 |
| `Messager` | 输出日志、错误、警告到编译器 |

### 6.3 处理器骨架

```java
import javax.annotation.processing.*;
import javax.lang.model.SourceVersion;
import javax.lang.model.element.*;
import javax.tools.Diagnostic;
import java.util.Set;

/**
 * APT 处理器 — 编译时扫描 @AutoBuilder 生成 Builder 类
 */
@SupportedAnnotationTypes("com.example.AutoBuilder")
@SupportedSourceVersion(SourceVersion.RELEASE_21)
public class AutoBuilderProcessor extends AbstractProcessor {

    @Override
    public synchronized void init(ProcessingEnvironment processingEnv) {
        super.init(processingEnv);
        // 可获取：processingEnv.getFiler() / getElementUtils() / getMessager()
    }

    @Override
    public boolean process(Set<? extends TypeElement> annotations,
                           RoundEnvironment roundEnv) {
        for (TypeElement annotation : annotations) {
            for (Element element : roundEnv.getElementsAnnotatedWith(annotation)) {
                if (element.getKind() != ElementKind.CLASS) {
                    processingEnv.getMessager().printMessage(
                            Diagnostic.Kind.ERROR, "@AutoBuilder 只能用于类", element);
                    continue;
                }
                generateBuilder((TypeElement) element);
            }
        }
        return true;
    }

    private void generateBuilder(TypeElement element) {

}
```

> 💡 APT 只能**生成新文件**，不能修改现有源码。Lombok 修改 AST 属于 Hack 编译器内部 API 的特殊机制。

## 7. 自定义 APT 处理器实战

### 7.1 定义编译期注解 + 完整处理器

```java
// 注解定义 — 必须 @Retention(SOURCE)
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.SOURCE)
public @interface AutoBuilder {
    String suffix() default "Builder";
}

// 处理器注册：META-INF/services/javax.annotation.processing.Processor
// 内容：com.example.AutoBuilderProcessor

// 完整处理器（使用 JavaPoet 生成代码）
@SupportedAnnotationTypes("com.example.AutoBuilder")
@SupportedSourceVersion(SourceVersion.RELEASE_21)
public class AutoBuilderProcessor extends AbstractProcessor {

    @Override
    public boolean process(Set<? extends TypeElement> annotations,
                           RoundEnvironment roundEnv) {
        for (Element element : roundEnv.getElementsAnnotatedWith(AutoBuilder.class)) {
            TypeElement type = (TypeElement) element;
            AutoBuilder ann = element.getAnnotation(AutoBuilder.class);

            // 使用 JavaPoet 构建 Builder 类
            TypeSpec builderClass = TypeSpec
                    .classBuilder(type.getSimpleName() + ann.suffix())
                    .addModifiers(Modifier.PUBLIC)
                    .addMethod(MethodSpec.methodBuilder("build")
                            .addModifiers(Modifier.PUBLIC)
                            .returns(ClassName.get(type))
                            .addStatement("return new $T()", ClassName.get(type))
                            .build())
                    .build();

            try {
                String pkg = processingEnv.getElementUtils()
                        .getPackageOf(type).toString();
                JavaFile.builder(pkg, builderClass).build()
                        .writeTo(processingEnv.getFiler());
            } catch (IOException e) {
                processingEnv.getMessager().printMessage(
                        javax.tools.Diagnostic.Kind.ERROR,
                        "生成失败: " + e.getMessage());
            }
        }
        return true;
    }
}
```

### 7.2 APT 注意事项

| 问题 | 解决 |
|------|------|
| 处理器未执行 | 检查 `META-INF/services/` 注册 + IDE 开启注解处理 |
| 不能修改源码 | APT 只能生成新文件；Lombok 是 AST Hack |
| 多轮处理 | `roundEnv.processingOver()` 判断最后轮 |
| 异常中断编译 | 用 `Messager` 输出错误而非抛出异常 |

> 💡 JavaPoet（`com.squareup:javapoet`）提供类型安全的 Java 源码生成 API，避免字符串拼接。

## 8. 注解 vs XML 配置

| 维度 | 注解配置 | XML 配置 |
|------|---------|----------|
| 位置 | 紧贴 Java 代码 | 独立配置文件 |
| 类型安全 | 编译期校验 | 运行时才发现错误 |
| 重构友好 | 自动同步 | 需手动同步 |
| 修改代价 | 需重新编译 | 修改 XML 即时生效 |
| 可读性 | 分散在代码中 | 集中管理 |
| 管理复杂配置 | ❌ 仅简单属性 | 支持继承/模板/通配符 |

**演进路线**：XML 一统天下（EJB/Spring 1.x）→ 注解辅助（Spring 2.x-3.x）→ 注解为主 + YAML/Properties 精简外配（Spring Boot）。

> 🎯 **选型原则**：业务逻辑标记用注解，基础设施/多环境/免编译变更用外部配置。

## 9. Spring/MyBatis/JUnit 中的注解原理

### 9.1 Spring 核心注解

```text
@SpringBootApplication（组合注解）
  ├── @SpringBootConfiguration   → 标识配置类
  ├── @EnableAutoConfiguration   → 读取 META-INF/spring.factories 自动配置
  └── @ComponentScan             → 扫描 @Component 类

@Component / @Service / @Controller / @Repository
  → ClassPathScanningCandidateComponentProvider 扫描包
  → 反射读取 @Component，创建 BeanDefinition

@Autowired / @Resource
  → BeanPostProcessor 后置处理器
  → 反射遍历字段，按类型/名称注入

@Transactional
  → AOP 代理，目标方法前后织入 commit/rollback
```

### 9.2 MyBatis @Mapper 原理

```java
// @Mapper → MapperFactoryBean → JDK 动态代理
// InvocationHandler.invoke() 解析 @Select/@Insert 注解
// 读取 SQL、参数映射 → 构建 SqlSource → 执行数据库操作

@Mapper
public interface UserMapper {
    @Select("SELECT * FROM users WHERE id = #{id}")
    User findById(@Param("id") Long id);
}
```

### 9.3 框架共性模式

```text
所有运行时注解框架的流程：
1. 启动期扫描：ClassPathBeanDefinitionScanner / MapperScannerConfigurer / TestEngine
2. 反射读取注解：clazz.getAnnotation(Component.class)
3. 生成代理/元数据：BeanDefinition → Bean / MapperProxy → InvocationHandler
```

## 10. 注解设计最佳实践

### 10.1 设计原则

| 原则 | 说明 |
|------|------|
| 单一职责 | 一个注解只表达一种语义 |
| 合理保留策略 | 能用 SOURCE 不用 CLASS，能用 CLASS 不用 RUNTIME |
| 默认值友好 | 给属性合理默认值，减少配置量 |
| 语义清晰 | 注解名和属性名见名知意 |
| 组合优于继承 | 参考 `@SpringBootApplication` 组合注解模式 |

### 10.2 常见反模式

```java
// ❌ 反模式：key/value 泛化命名
@interface Config { String key(); String value(); }

// ✅ 推荐：语义化命名
@interface DataSourceConfig {
    String jdbcUrl();
    String username();
    String password();
}

// ❌ 反模式：RUNTIME 纯标记但不反射读取 → 应改为 SOURCE
@Retention(RetentionPolicy.RUNTIME)
@interface Todo { String value(); }   // 仅作标记
```

### 10.3 性能建议

| 场景 | 建议 |
|------|------|
| 频繁反射读取 | 缓存 `Method.getAnnotation()` 结果到 `Map` |
| 批量处理 | 提取注解到局部变量，避免循环内重复查找 |
| 编译时能做的 | 优先用 APT 生成代码，零运行时开销 |

## 11. 面试高频考点

### 基础篇

**Q1: `@Retention` 的三个值？**
SOURCE（源码保留，编译丢弃）、CLASS（class 保留，JVM 不加载）、RUNTIME（JVM 加载，反射可读）。

**Q2: `@Inherited` 的作用与局限？**
子类继承父类注解（仅类继承生效，接口/方法/字段不继承）。

**Q3: 自定义注解属性支持哪些类型？**
基本类型、String、Class、枚举、注解、以上类型的数组。

### 进阶篇

**Q4: APT 和运行时注解处理的区别？**

| 维度 | APT | 运行时反射 |
|------|-----|-----------|
| 时机 | 编译期 | 运行期 |
| 性能 | 零开销 | 有反射开销 |
| 能力 | 可生成新源码 | 可动态修改行为 |
| 代表 | Lombok, MapStruct | Spring, Hibernate |

**Q5: Lombok 修改源码的原理？**
Lombok 编写定制的 javac **Plugin**，直接修改 AST（抽象语法树），不是标准 APT（标准 APT 只能生成新文件）。

**Q6: Spring `@Transactional` 失效场景？**
`private` 方法（AOP 无法拦截）、同类内部调用（未走代理）、传播属性配置错误。

**Q7: 注解 vs XML 选型？**
注解适合类型安全和业务标记，XML 适合免编译的多环境配置。现代实践：注解启动 + YAML/Properties 精简外配。

### 实战篇

**Q8: APT 处理器注册方式？**
1. `META-INF/services/javax.annotation.processing.Processor`
2. Maven `annotationProcessorPaths`
3. `javac -processor` 命令行
4. `@AutoService(Processor.class)` 自动生成

**Q9: 设计 `@Loggable` 注解需考虑哪些方面？**
| 方面 | 考虑点 |
|------|--------|
| 目标 | METHOD |
| 保留策略 | RUNTIME（需运行时织入） |
| 属性 | 日志级别、是否记录参数/返回值 |
| 实现 | AOP 环绕通知 或 动态代理 |

**Q10: 注解、泛型、反射三者的关系？**

```text
泛型：编译期类型检查
反射：运行时动态操作
注解：元数据标记

三者结合：反射读取注解 → 根据注解类型动态操作（Spring DI 就是典型）
```

---

> 🎯 **终极总结**：注解是 Java 生态的"元数据标准化"方案。掌握注解 = 理解元注解 + 能自定义注解 + 能在运行时（反射）和编译时（APT）两种模式下处理注解。多数 Java 框架以注解为核心，理解注解原理是读懂框架源码的第一步。
