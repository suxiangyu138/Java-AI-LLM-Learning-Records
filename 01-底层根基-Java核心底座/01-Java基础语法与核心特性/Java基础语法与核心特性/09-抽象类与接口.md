## 1. 抽象类（abstract class）

> 抽象类是用 `abstract` 修饰的类，**不能被实例化**，用于定义子类的共性模板。可包含抽象方法（仅声明无实现）和具体方法。

### 1.1 核心特性

| 特性 | 说明 |
|------|------|
| 实例化 | **不能**被直接实例化 |
| 构造方法 | **可以有**，供子类通过 `super()` 调用 |
| 字段 | **任意类型**的成员变量 |
| 方法 | 抽象方法 + 具体方法均可包含 |
| 访问修饰符 | **无限制**（private / protected / public 均可） |
| 继承 | 单继承（`extends`） |

```java
abstract class Animal {
    protected String name;
    protected int age;

    public Animal(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public void eat() { System.out.println(name + " 正在进食"); }

    // 抽象方法：子类必须实现
    public abstract void makeSound();
}

class Dog extends Animal {
    public Dog(String name, int age) { super(name, age); }

    @Override
    public void makeSound() { System.out.println(name + " 汪汪叫"); }
}
```

### 1.2 抽象方法规则

- 抽象方法没有方法体（以分号结束）
- 子类**必须重写**所有抽象方法（除非子类也是抽象类）
- 抽象方法不能用 `private`、`final`、`static` 修饰

> 💡 抽象类本质上是"**不完整的类**"，将部分实现留给子类完成，体现**模板方法设计模式**思想。

## 2. 接口（interface）

> 接口是用 `interface` 定义的**完全抽象的契约**，定义一组能力规范（can-do），实现类必须遵守这些规范。

### 2.1 核心特性

| 特性 | 说明 |
|------|------|
| 实例化 | **不能**被实例化（无构造方法） |
| 构造方法 | **不能有** |
| 字段 | 只能是 `public static final` 常量 |
| 方法 | JDK 7：仅抽象方法；JDK 8+：default / static；JDK 9+：private |
| 访问修饰符 | 默认 `public`（JDK 9+ 支持 `private`） |
| 实现 | 多实现（`implements`） |

```java
interface Flyable {
    // 常量（默认 public static final）
    int MAX_SPEED = 1000;

    // 抽象方法（默认 public abstract）
    void fly();

    // JDK 8+ 默认方法
    default void takeOff() {
        System.out.println("起飞中...");
        fly();
    }

    // JDK 8+ 静态方法
    static String category() {
        return "飞行器";
    }

    // JDK 9+ 私有方法
    private void log(String msg) {
        System.out.println("[FLY] " + msg);
    }
}

class Bird implements Flyable {
    @Override
    public void fly() { System.out.println("鸟扇动翅膀飞行"); }
    // takeOff() 可不重写，直接使用默认实现
}
```

> 多个接口包含相同 default 方法时，实现类必须重写并显式指定：`A.super.hello()`

## 3. 抽象类 vs 接口：核心区别

| 对比项 | 抽象类 | 接口 |
|--------|--------|------|
| 关键字 | `abstract class` | `interface` |
| 实例化 | 不能 | 不能 |
| 构造方法 | 可以有 | 不能有 |
| 字段 | 任意类型 | 仅 `public static final` 常量 |
| 方法类型 | 抽象方法 + 具体方法 | 抽象、default、static、private |
| 访问修饰符 | 无限制 | 默认 `public`（JDK 9+ 支持 private） |
| 多继承/实现 | 单继承（`extends`） | 多实现（`implements`） |
| 设计目标 | 代码复用、模板定义 | 能力契约、行为规范 |
| 关系描述 | `is-a` 关系 | `has-a` / `can-do` 关系 |

> 🎯 抽象类是"**是什么**"的层级抽象，接口是"**能做什么**"的能力契约。

## 4. 接口的演进：JDK 8 默认方法与静态方法

> Java 8 是接口的**里程碑版本**，引入 `default` 和 `static` 方法，使接口从纯粹声明演变为具备行为定义能力的契约。

**解决的问题**：接口演进兼容性。为现有接口添加新方法时，若不使用默认方法，所有实现类都必须修改。

```java
interface Vehicle {
    void start();
    void stop();

    // default 方法：实现类可不重写，解决接口演进兼容问题（如 Collection.stream()）
    default void honk() { System.out.println("默认喇叭: 滴滴!"); }

    // static 方法：属于接口本身，不被实现类继承，只能通过接口名调用
    static String getCategory() { return "交通工具"; }
}
```

| 方法类型 | 能否被实现类继承 | 能否被重写 | 调用方式 |
|----------|:----------------:|:----------:|----------|
| 抽象方法 | 必须实现 | 是 | 实现类实例 |
| default 方法 | 继承 | 可以 | 实现类实例 |
| static 方法 | **不被继承** | **不能** | 接口名调用 |

| 版本 | 增强内容 | 意义 |
|------|----------|------|
| JDK 7 及以前 | 仅抽象方法 + 常量 | 纯粹契约 |
| **JDK 8** | `default` + `static` | 解决集合库演进问题（如 `Collection.stream()`） |
| **JDK 9** | `private` + `private static` | 提升代码复用，隐藏实现细节 |

## 5. JDK 9+：接口私有方法

> Java 9 允许在接口中定义 `private` 方法，用于在 default 方法间共享代码，**不暴露给外部**。

```java
interface Vehicle {
    default void honk() { log("喇叭"); System.out.println("滴滴!"); }
    default void displayStatus() { log("检查"); System.out.println("状态正常"); }

    // private 方法：辅助 default 方法复用代码，对外部隐藏
    private void log(String msg) { System.out.println("[Vehicle] " + msg); }
}
```

**私有方法约束**：
- 只能在接口内部被 default 或 private 方法调用
- 不能被实现类继承或重写
- 不能是 `abstract` 的

> ⚠️ 接口私有方法本质上是接口内部代码复用的工具，不属于接口对外契约的一部分。

## 6. 函数式接口（@FunctionalInterface）

> **有且仅有一个抽象方法**的接口，是 Java 8 Lambda 表达式的基础。

```java
@FunctionalInterface
interface Calculator { int calculate(int a, int b); }

Calculator add = (a, b) -> a + b;
System.out.println(add.calculate(3, 4));  // 7
```

### Java 内置的四大核心函数式接口

| 接口 | 方法签名 | 用途 | 示例 |
|------|----------|------|------|
| `Predicate<T>` | `boolean test(T t)` | 判断/过滤 | `s -> s.length() > 5` |
| `Function<T, R>` | `R apply(T t)` | 转换/映射 | `String::length` |
| `Consumer<T>` | `void accept(T t)` | 消费数据 | `System.out::println` |
| `Supplier<T>` | `T get()` | 提供数据 | `Math::random` |

**扩展**：`BiFunction<T,U,R>`、`UnaryOperator<T>`、`BinaryOperator<T>`、`BiPredicate<T,U>`、`BiConsumer<T,U>`。

## 7. 标记接口（Marker Interface）

> **不包含任何方法声明**的接口，用于运行时通过 `instanceof` 判断类是否具备某种能力。

### 7.1 常见标记接口

| 标记接口 | 用途 |
|----------|------|
| `Serializable` | 标记类可被序列化 |
| `Cloneable` | 标记类可调用 `clone()` |
| `Remote` | RMI 远程调用标记 |

```java
// 自定义标记接口
public interface Auditable { /* 仅作为标记 */ }

class Order implements Auditable { /* ... */ }

// 运行时判断
if (obj instanceof Auditable) {
    // 执行审计逻辑
}
```

### 7.2 标记接口 vs 注解

| 对比项 | 标记接口 | 注解 |
|--------|----------|------|
| 类型检查 | `instanceof`（编译+运行时） | 反射（运行时） |
| 继承传递 | 子类天然继承 | 需 `@Inherited` |
| 灵活性 | 不能携带参数 | 可定义属性参数 |
| 性能 | O(1) 快速 | 反射相对较慢 |

> 💡 《Effective Java》建议：标记应用于**类和接口**且频繁使用 `instanceof` 检查时，优先用标记接口；需要携带参数或用于方法/字段时，用注解。

## 8. 接口设计原则：接口隔离

> **接口隔离原则**（ISP）是 SOLID 原则之一：**客户端不应依赖它不需要的接口**。

### 8.1 违反 ISP 的反例

```java
// 胖接口——包含不相关的职责
interface Worker {
    void work();
    void eat();
    void sleep();
}

// Robot 只需要 work()，但被迫实现 eat() 和 sleep()
class Robot implements Worker {
    public void work() { /* ok */ }
    public void eat() { throw new UnsupportedOperationException(); }
    public void sleep() { throw new UnsupportedOperationException(); }
}
```

### 8.2 符合 ISP 的正确设计

```java
// 细粒度接口
interface Workable { void work(); }
interface Eatable  { void eat(); }
interface Sleepable { void sleep(); }

class Robot implements Workable {
    public void work() { System.out.println("机器人工作"); }
}

class Human implements Workable, Eatable, Sleepable {
    public void work() { System.out.println("人类工作"); }
    public void eat() { System.out.println("人类吃饭"); }
    public void sleep() { System.out.println("人类睡觉"); }
}
```

| ISP 实践指南 | 说明 |
|-------------|------|
| 接口粒度 | 一个接口只代表**一个角色**或**一种能力** |
| 方法数量 | 通常 3~5 个以内，超过则考虑拆分 |
| 命名规范 | 体现能力（-able 后缀：Runnable, Comparable） |

> 🎯 **不要强迫调用方依赖它们不需要的方法**。大型接口应拆分为多个小型、高内聚的接口。

## 9. 面向接口编程实战

> 通过策略模式演示接口定义契约、多态扩展、组合切换。

```java
// 1. 接口定义（契约）
interface PayStrategy {
    boolean supports(String channel);
    void pay(BigDecimal amount);
}

// 2. 实现类（多态）
class Alipay implements PayStrategy {
    public boolean supports(String c) { return "ALIPAY".equalsIgnoreCase(c); }
    public void pay(BigDecimal a) { System.out.println("支付宝支付: " + a); }
}

class Wechat implements PayStrategy {
    public boolean supports(String c) { return "WECHAT".equalsIgnoreCase(c); }
    public void pay(BigDecimal a) { System.out.println("微信支付: " + a); }
}

// 3. 上下文（依赖接口，不依赖具体实现）
class PayContext {
    private final List<PayStrategy> strategies;
    public PayContext(List<PayStrategy> strategies) { this.strategies = strategies; }

    public void execute(String channel, BigDecimal amount) {
        strategies.stream()
            .filter(s -> s.supports(channel))
            .findFirst()
            .orElseThrow(() -> new IllegalArgumentException("不支持的渠道"))
            .pay(amount);
    }
}

// 4. 使用：新增支付方式只需新增实现类，无需修改现有代码
new PayContext(List.of(new Alipay(), new Wechat()))
    .execute("ALIPAY", new BigDecimal("100"));
```

> 🎯 **核心价值**：降低耦合、易于扩展（开闭原则）、易于测试（Mock）、依赖倒置。

## 10. 何时用抽象类？何时用接口？

### 10.1 使用抽象类的场景

| 场景 | 原因 | 示例 |
|------|------|------|
| `is-a` 层次关系 | 类之间有明确继承层级 | `Dog extends Animal` |
| 需要共享状态 | 子类有公共成员变量 | `baseUrl`, `timeout` |
| 需要公共构造逻辑 | 父类构造器初始化公共字段 | `super(name, level)` |
| 模板方法模式 | 定义算法骨架，子类实现特定步骤 | `AbstractLogger.writeLog()` |
| 需要非 public 方法 | 抽象类允许 protected / default 方法 | 保护性抽象方法 |

```java
abstract class AbstractHttpClient {
    protected String baseUrl;
    protected int timeout;

    public AbstractHttpClient(String baseUrl, int timeout) {
        this.baseUrl = baseUrl;
        this.timeout = timeout;
    }

    public String execute(String endpoint) {
        return doSend(baseUrl + endpoint);  // doSend 由子类实现
    }

    protected abstract String doSend(String url);
}
```

### 10.2 使用接口的场景

| 场景 | 原因 | 示例 |
|------|------|------|
| `can-do` 能力契约 | 定义某种能力 | `Comparable`, `Runnable` |
| 多继承类型 | 一个类实现多个接口 | `class Duck implements Flyable, Swimmable` |
| 不相关类间共同行为 | 跨越类层次定义行为 | `PaymentService` 被不同业务类实现 |
| 接口演进 | default 方法提供向后兼容 | `Collection.stream()` |
| 依赖倒置 | 高层模块依赖抽象 | Spring 依赖注入 |


### 10.3 选型决策树

```
需要子类间代码复用和共享状态？
├── 是 ──> 是否需要多继承？
│           ├── 是 ──> 接口
│           └── 否 ──> 抽象类
└── 否 ──> 是否需要描述"能做什么"而非"是什么"？
            ├── 是 ──> 接口
            └── 否 ──> 考虑具体类
```

> 💡 《Effective Java》第 20 条：**接口优于抽象类**。接口更容易被组合、更灵活、更易测试。存在共享状态或跨类层次提取行为时，才考虑抽象类。

## 11. 面试高频考点

| 类别 | 问题 | 核心要点 |
|------|------|----------|
| 概念 | 抽象类和接口的区别？ | JDK 8 前后差异：构造器、字段、多继承、default/static 方法 |
| 概念 | 接口字段为何 `public static final`？ | 接口是契约而非状态容器 |
| 概念 | Java 为何不支持多继承？ | 菱形继承问题，接口多实现 + default 方法部分解决 |
| 演进 | default 方法解决了什么？ | 接口演进兼容性（如 `Collection.stream()`） |
| 演进 | 默认方法冲突如何解决？ | 类方法 > 子接口 > 父接口；实现类手动重写 |
| 演进 | 接口 static 方法能被继承吗？ | **不能**，只能通过接口名调用 |
| 演进 | JDK 9 接口私有方法的作用？ | default 方法间复用代码，隐藏实现细节 |
| 函数式 | `@FunctionalInterface` 作用？ | 编译期校验是否只有一个抽象方法 |
| 函数式 | 四大核心函数式接口？ | Predicate / Function / Consumer / Supplier |
| 标记 | 标记接口 vs 注解如何选择？ | instanceof 检查 + 继承传递用标记接口；参数携带用注解 |
| 设计 | 什么是接口隔离原则？ | 客户端不应依赖它不需要的接口 |
| 设计 | 何时用抽象类 vs 接口？ | is-a + 共享状态用抽象类；can-do + 多能力用接口 |

### 易错点

```text
1. 抽象类不能实例化，但可以有构造方法
2. 接口方法默认是 public abstract（JDK 9 前不能用 private）
3. 接口 default 方法不是 abstract，实现类可不重写
4. 接口字段必须是 public static final
5. 抽象方法不能被 private、final、static 修饰
```
