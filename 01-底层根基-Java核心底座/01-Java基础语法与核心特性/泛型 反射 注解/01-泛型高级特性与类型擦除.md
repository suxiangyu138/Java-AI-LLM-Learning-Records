## 1. 类型擦除的本质

### 1.1 什么是类型擦除

Java 泛型是**编译期特性**。编译器在编译时会执行以下操作：

1. **擦除类型参数**：将泛型类型参数替换为它的限定类型（无界 → Object，有界 → 上界）
2. **插入类型转换**：在必要位置插入 `checkcast` 指令确保类型安全
3. **生成桥方法**：维护多态性（详见第 5 节）

```java
// 源码（带泛型）
public class Box<T> {
    private T value;

    public T getValue() { return value; }
    public void setValue(T value) { this.value = value; }
}

// 编译后等价代码（类型擦除，无界 → Object）
public class Box {
    private Object value;

    public Object getValue() { return value; }
    public void setValue(Object value) { this.value = value; }
}
```

```java
// 有界类型参数的情况
public class NumberBox<T extends Number> {
    private T value;

    public T getValue() { return value; }
}

// 编译后等价代码（有界 → Number）
public class NumberBox {
    private Number value;

    public Number getValue() { return value; }
}
```

### 1.2 编译器擦除规则

| 类型参数声明 | 擦除后的类型 | 说明 |
|-------------|------------|------|
| `T` (无界) | `Object` | 最常见的擦除结果 |
| `T extends Number` | `Number` | 取上界类型 |
| `T extends Comparable<T>` | `Comparable` | 取上界（原始类型） |
| `T extends A & B & C` | `A` | 取第一个上界（类必须在前） |
| `T extends Comparable & Serializable` | `Comparable` | 取第一个接口上界 |

```java
// 多重边界示例
public class MultiBound<T extends Number & Comparable<T> & Serializable> {
    private T value;

    public void test() {
        // 可以调用 Number 的方法
        value.doubleValue();
        // 也可以调用 Comparable 的方法
        value.compareTo(null);         // ⚠️ 注意：擦除后是 raw Comparable，不安全
        // 也可以调用 Serializable 的方法（虽然是标记接口）
    }
}

// 擦除后
public class MultiBound {
    private Number value;  // 第一个上界

    public void test() {
        value.doubleValue();
        // Comparable 的方法需要手动强转
        ((Comparable) value).compareTo(null);
    }
}
```

### 1.3 字节码中的 Signature 属性

虽然类型被擦除了，但 Java 编译器在 `.class` 文件的 **Signature 属性** 中保留了泛型签名信息，供反射 API 使用。

```java
// Demo.java
import java.lang.reflect.ParameterizedType;
import java.lang.reflect.Type;
import java.util.List;

public class SignatureDemo {
    public List<String> getNames() { return null; }

    public static void main(String[] args) throws Exception {
        Method m = SignatureDemo.class.getMethod("getNames");
        Type returnType = m.getGenericReturnType();  // 获取泛型返回类型

        if (returnType instanceof ParameterizedType) {
            ParameterizedType pt = (ParameterizedType) returnType;
            System.out.println("Raw type: " + pt.getRawType());       // interface java.util.List
            System.out.println("Type args: " + pt.getActualTypeArguments()[0]); // class java.lang.String
        }
    }
}
```

```bash
# javap -verbose 反编译验证 Signature 属性
$ javap -verbose SignatureDemo.class

# 输出中包含：
#   public java.util.List<java.lang.String> getNames();
#     descriptor: ()Ljava/util/List;
#     flags: (0x0001) ACC_PUBLIC
#     Signature: #12                          // ()Ljava/util/List<Ljava/lang/String;>;
```

> 💡 **Signature 是泛型的"幽灵"**：类型被擦除了，但签名信息仍保存在字节码的 Signature 属性中。这就是为什么运行时仍然能通过 `getGenericReturnType()` / `getGenericSuperclass()` 获取到泛型信息。

### 1.4 checkcast 插入

编译器会在调用泛型方法获取返回值的地方插入类型转换指令：

```java
// 源码
List<String> list = new ArrayList<>();
list.add("hello");
String s = list.get(0);

// 编译后等价代码
List list = new ArrayList();
list.add("hello");
String s = (String) list.get(0);  // ✅ 编译器自动插入 checkcast
```

### 1.5 泛型不是"真泛型"的证据

| 证据 | 说明 |
|------|------|
| `new T()` 不允许 | 因为 T 被擦除为 Object，编译器不知道如何调用构造器 |
| `instanceof T` 不允许 | 运行时 T 已不存在，无法做类型检查 |
| `new T[]` 不允许 | 数组是协变的，与泛型的不可变性冲突 |
| 不同泛型参数的同一个类，只有一个 Class 对象 | `List<String>.class` 不存在，只有 `List.class` |
| 静态变量是类型参数共享的 | 一个类只有一个静态变量副本 |
| 方法签名重载冲突 | `void foo(List<String>)` 和 `void foo(List<Integer>)` 擦除后相同 |

```java
public class EraseEvidence {

    public static void main(String[] args) {
        List<String> strList = new ArrayList<>();
        List<Integer> intList = new ArrayList<>();

        // ✅ 同一个 Class 对象
        System.out.println(strList.getClass() == intList.getClass()); // true

        // ✅ 静态变量所有实例共享
        System.out.println(StaticGeneric.count);  // 不管 T 是什么
    }
}

class StaticGeneric<T> {
    public static int count = 0;  // 所有 T 的实例共享这一个 count
    // public static T value;     // ❌ 编译错误：静态成员不能使用类级类型参数
}
```

> 🎯 **核心要点**：Java 泛型是"编译期语法糖 + 类型擦除 + 自动类型转换"的组合。它提供编译期类型安全性，但运行时不保留具体类型参数信息（除了 Signature 属性的"幽灵"）。这是 Java 为了向后兼容（迁移兼容性）做出的设计妥协。

## 2. 通配符上界下界与PECS原则

### 2.1 通配符基础

通配符 `?` 代表"某种未知类型"，用在泛型类型中表示不关心具体是什么类型：

```java
// 无界通配符：接受任意类型的 List
public static void printList(List<?> list) {
    for (Object item : list) {
        System.out.print(item + " ");
    }
}

// 💡 但下面的写法会编译错误：
public static void addAnything(List<?> list) {
    // list.add("hello");  // ❌ 编译错误：? 不能添加元素（null 除外）
    list.add(null);         // ✅ 唯一允许的添加
}
```

### 2.2 上界通配符 `? extends T`

**含义**：集合的元素类型是 T 或 T 的子类，具体是哪个子类未知。

```java
// 上界通配符——生产者（Producer）
public static double sumOfList(List<? extends Number> list) {
    double sum = 0.0;
    for (Number num : list) {   // ✅ 读取安全：所有元素至少是 Number
        sum += num.doubleValue();
    }
    return sum;
}
```

**特性**：

| 操作 | 是否允许 | 原因 |
|------|:-------:|------|
| 读取 get() | ✅ | 元素类型至少是 T，可以赋值给 T |
| 写入 add() | ❌ | 不知道具体是哪个子类，无法确定类型安全 |

```java
List<? extends Number> list = new ArrayList<Integer>();
list.add(null);           // ✅ null 例外
// list.add(Integer.valueOf(1)); // ❌ 编译错误：即使实际类型是 Integer 也不行
// list.add(Double.valueOf(1.0)); // ❌ 编译错误

Number num = list.get(0);   // ✅ 读取安全：最坏情况也是 Number
// Integer i = list.get(0); // ❌ 编译错误：可能是 Double
```

### 2.3 下界通配符 `? super T`

**含义**：集合的元素类型是 T 或 T 的父类，具体是哪个父类未知。

```java
// 下界通配符——消费者（Consumer）
public static void addNumbers(List<? super Integer> list) {
    list.add(1);       // ✅ 写入安全：Integer 一定是 Integer 或其父类的合法元素
    list.add(2);
    // Integer num = list.get(0); // ❌ 编译错误：可能是 Object，无法安全赋值
}
```

**特性**：

| 操作 | 是否允许 | 原因 |
|------|:-------:|------|
| 写入 add(T) | ✅ | T 一定是下界的合法子类型 |
| 读取 get() | ❌ | 元素可能是 Object，无法安全赋值给更具体的类型 |

```java
List<? super Integer> list = new ArrayList<Number>();
list.add(1);              // ✅ 写入安全：Integer 是 Number 的子类
list.add(2);
Object obj = list.get(0);  // ✅ 只能读为 Object
// Integer i = list.get(0); // ❌ 编译错误：实际类型可能是 Number
```

### 2.4 PECS 原则

**PECS = Producer Extends, Consumer Super**

> "生产者使用 extends，消费者使用 super" —— Joshua Bloch, *Effective Java* 第 3 版 Item 31

```java
// 典型应用：Collections.copy()
public static <T> void copy(List<? super T> dest, List<? extends T> src) {
    // src 是生产者（提供元素）          → extends
    // dest 是消费者（接收元素）          → super
    for (int i = 0; i < src.size(); i++) {
        dest.set(i, src.get(i));
    }
}
```

```java
// 实战案例：合并集合
public class PecsDemo {

    // ❌ 错误设计：没有使用通配符，过于严格
    public static <T> void addAllBad(List<T> dest, List<T> src) {
        dest.addAll(src);
    }

    // ✅ 正确设计：灵活运用 PECS
    public static <T> void addAllGood(List<? super T> dest, List<? extends T> src) {
        dest.addAll(src);
    }

    public static void main(String[] args) {
        List<Number> nums = new ArrayList<>();
        List<Integer> ints = Arrays.asList(1, 2, 3);

        // addAllBad(nums, ints);  // ❌ 编译错误
        addAllGood(nums, ints);     // ✅ OK：dest 是 consumer (super)，src 是 producer (extends)
    }
}
```

### 2.5 PECS 核心应用：Comparable & Comparator

```java
// java.lang.Comparable 的源码设计
// ❌ 早期设计（没有 ? super T）
public interface Comparable<T> {
    public int compareTo(T o);
}

// ✅ Collections.max() 用了 PECS
public static <T extends Comparable<? super T>> T max(Collection<? extends T> coll) {
    // T extends Comparable<? super T> — T 应该是可比较的，且比较器的下界包含 T
    // Collection<? extends T> — 集合是 T 的生产者
}
```

```java
// 理解为什么 Comparable 要 ? super T
class Animal implements Comparable<Animal> {
    int age;
    public int compareTo(Animal o) { return this.age - o.age; }
}

class Dog extends Animal {
    // 没有重新实现 Comparable
}

// ❌ 如果 max 声明为 <T extends Comparable<T>>
// 那么 Dog 不满足 Comparable<Dog>，只能手动转型
//
// ✅ 用 <T extends Comparable<? super T>>
// Dog extends Animal, Animal implements Comparable<Animal>
// 所以 Dog 满足 Comparable<? super Dog> ✓
// Comparable<Animal> 是 Comparable<? super Dog> 的子类型 ✓
```

```java
// 完整的 PECS 实战：通用对象复写方法
public class BeanCopyUtil {

    // 从一个对象复制到另一个对象
    public static <T> void copyProperties(
            T source,                         // 来源：既是生产者也是消费者（非集合）
            T target) {                        // 目标
        // 框架实现（如 Spring BeanUtils）
        BeanUtils.copyProperties(source, target);
    }

    // 从一个集合批量复制到另一个集合 —— PECS
    public static <T> void copyList(
            List<? extends T> source,          // ✅ 生产者：extends
            List<? super T> target) {          // ✅ 消费者：super
        for (T item : source) {
            target.add(item);
        }
    }

    // 使用示例
    public static void main(String[] args) {
        List<Integer> intList = new ArrayList<>();
        List<Object> objList = new ArrayList<>();

        // 如果方法签名写的是 List<T> source, List<T> target，这里就会编译失败
        copyList(intList, objList);  // ✅ 灵活
    }
}
```

### 2.6 通配符捕获

编译器在通配符无法直接匹配时使用"通配符捕获"：

```java
public class WildcardCapture {

    // ❌ 编译错误：? 无法直接用于不需要通配符的上下文
    public static void swap(List<?> list, int i, int j) {
        // list.set(i, list.get(j));  // ❌ 编译错误
    }

    // ✅ 通配符捕获：将 ? 捕获为正式类型参数
    public static void swap(List<?> list, int i, int j) {
        swapHelper(list, i, j);
    }

    // 辅助方法，将 ? 捕获为 T
    private static <T> void swapHelper(List<T> list, int i, int j) {
        list.set(i, list.set(j, list.get(i)));  // ✅ OK
    }
}
```

| 通配符 | 语法 | 读取 | 写入 | 场景 |
|--------|------|:---:|:---:|------|
| 无界 | `List<?>` | ✅ Object | ❌ | 只读通用方法 |
| 上界 | `List<? extends T>` | ✅ T | ❌ | 生产者（读数据） |
| 下界 | `List<? super T>` | ✅ Object | ✅ T | 消费者（写数据） |

> 🎯 **核心要点**：PECS 原则的本质是**保证类型安全的同时提供最大灵活性**。`? extends T` 让方法的参数类型范围更宽（子类型也行），`? super T` 让方法的参数类型范围更宽（父类型也行）。记住：**extends 读，super 写**。

## 3. 泛型方法 vs 泛型类

### 3.1 泛型方法

泛型方法在方法声明中引入自己的类型参数，该参数独立于类级别的类型参数：

```java
public class GenericMethodDemo {

    // ✅ 泛型方法 —— 类型参数在方法返回类型之前声明
    public static <T> T getMiddle(T... args) {
        return args[args.length / 2];
    }

    // 编译器类型推断 —— 可以自动推断类型参数
    public static void main(String[] args) {
        // 显式类型参数
        String mid1 = GenericMethodDemo.<String>getMiddle("A", "B", "C");

        // 类型推断（Java 7+ 支持）
        String mid2 = getMiddle("A", "B", "C");  // 编译器推断出 T = String

        // 类型推断的边界情况 —— 编译器选取最具体的共同父类型
        Number mid3 = getMiddle(1, 2.0, 3L);     // Number 是 Integer/Double/Long 的共同父类
        // Serializable & Comparable 也是共同父类型 —— 需要显式指定
        // Serializable mid4 = getMiddle("A", 1, 2.0);  // 💡 看编译器自动推断类型
    }
}
```

### 3.2 泛型方法 vs 泛型类的对比

| 对比维度 | 泛型类 | 泛型方法 |
|---------|-------|---------|
| 类型参数作用域 | 整个类 | 仅该方法 |
| 静态方法用泛型 | ❌ 不能使用类的泛型参数 | ✅ 必须声明自己的泛型参数 |
| 类型推断 | 构造时需要指定 | 调用时自动推断 |
| 实例化 | `new Box<String>()` | 调用时确定 |
| 使用场景 | 容器类、集合类 | 工具方法、静态工厂方法 |

### 3.3 静态方法为什么不能使用类的泛型参数

```java
public class GenericClass<T> {

    private T value;

    // ✅ 实例方法可以使用类的泛型参数
    public T getValue() { return value; }

    // ❌ 静态方法不能使用类的泛型参数
    // public static T getStaticValue() { return null; } // 编译错误

    // ✅ 静态方法可以声明自己的泛型参数
    public static <E> E doSomething(E input) {
        return input;
    }

    // 为什么？
    // 因为静态方法属于类，不属于实例。
    // 类的泛型参数是在实例化时确定的：
    //   GenericClass<String> obj1 = new GenericClass<>();  // T = String
    //   GenericClass<Integer> obj2 = new GenericClass<>();  // T = Integer
    // 但静态方法没有实例概念：
    //   GenericClass.doSomething()  — 应该用哪个 T？
}
```

Java 的类型推断随着版本不断改进：


### 3.5 泛型方法实战：类型安全的 Builder

```java
public class GenericBuilder<T> {
    private final T instance;

    private GenericBuilder(T instance) {
        this.instance = instance;
    }

    // ✅ 泛型静态工厂方法 —— 类型推断
    public static <T> GenericBuilder<T> of(T instance) {
        return new GenericBuilder<>(instance);
    }

    // ✅ 泛型方法 —— 属性设置
    public <R> GenericBuilder<T> with(Consumer<T> setter) {
        setter.accept(instance);
        return this;
    }

    public T build() {
        return instance;
    }

    // 使用示例
    public static void main(String[] args) {
        User user = GenericBuilder.of(new User())
                .with(u -> u.setName("Alice"))
                .with(u -> u.setAge(25))
                .build();
    }
}
```

> 🎯 **核心要点**：泛型方法和泛型类的类型参数是独立的。**泛型方法常用于工具类和静态方法**，类型推断让调用更简洁。记住：静态方法无法使用类的泛型参数，但可以声明自己的泛型参数。

## 4. 泛型与数组

### 4.1 数组协变 vs 泛型不变

Java 数组是**协变**的，而泛型是**不变**的，这是所有数组泛型限制的根本原因：

```java
public class ArrayCovariance {

    public static void main(String[] args) {
        // ---------- 数组协变 ----------
        // String[] 是 Object[] 的子类型
        String[] strings = new String[10];
        Object[] objects = strings;     // ✅ 编译通过（协变）
        objects[0] = 42;                // ❌ 运行时 ArrayStoreException！
        // 数组在运行时保留元素类型，会做检查
        
        // ---------- 泛型不变 ----------
        List<String> strList = new ArrayList<>();
        // List<Object> objList = strList;  // ❌ 编译错误（不变）
        // 泛型在编译期就不允许这样的赋值，提前杜绝了运行时错误
        
        // 总结：
        // 数组：编译时允许（协变），运行时抛异常
        // 泛型：编译时禁止（不变），从根本上杜绝问题
    }
}
```

### 4.2 为什么不能 `new T[]`

```java
public class GenericArray<T> {

    // ❌ 编译错误：不能创建泛型数组
    // private T[] array = new T[10];  // cannot create array with type parameters

    private T[] array;

    @SuppressWarnings("unchecked")
    public GenericArray(int size) {
        // ✅ 可行的做法：创建 Object 数组然后强转
        this.array = (T[]) new Object[size];
    }

    public void set(int index, T value) {
        array[index] = value;
    }

    public T get(int index) {
        return array[index];
    }

    // ⚠️ 但是有隐患：
    public T[] getArray() {
        return array;
    }

    public static void main(String[] args) {
        GenericArray<String> ga = new GenericArray<>(10);
        ga.set(0, "hello");

        // 看似安全，但 getArray() 暴露了类型擦除后的真相
        String[] arr = ga.getArray();  // ❌ ClassCastException！

        // 实际类型是 Object[]，不是 String[]
        // 因为擦除后 array 是 Object[]，(T[])new Object[size] 只是"欺骗"编译器
    }
}
```

**根本原因**：

```
数组要求运行时知道元素类型（协变检查），但泛型运行时类型已被擦除。
new T[] → 运行时不知道 T 具体是什么 → 无法创建。

编译器限制的推理链：
  1. 数组是协变的 —— 运行时做类型检查
  2. 泛型是不变  —— 编译期做类型检查
  3. 泛型类型擦除 —— 运行时 T 不存在
  4. ∴ 创建泛型数组时，无法确定运行时数组元素类型
  5. ∴ new T[] 被禁止
```

### 4.3 为什么 `List<String>[]` 也不行

```java
// ❌ 编译错误：泛型数组创建
// List<String>[] arrayOfLists = new List<String>[10];

// 为什么不允许？—— 看下面的例子就知道了

// 如果 Java 允许泛型数组，会发生什么：
// 假设允许这样写
List<String>[] stringLists = new List<String>[10];  // 假想的

// 数组是协变的，所以：
Object[] objects = stringLists;                    // ✅ 编译通过

// 现在放一个 List<Integer> 进去：
objects[0] = new ArrayList<Integer>();             // ✅ 数组不检查泛型类型（运行时已擦除）

// 但取出来的时候：
String s = stringLists[0].get(0);                  // ❌ 运行时 ClassCastException！
// 取出的是 Integer，却强转为 String
```

**原理**：

```java
// List<String>[] 被禁止的核心原因：
// 1. 数组协变：List<String>[] → Object[] ✅（编译允许）
// 2. 类型擦除：List<String> 运行时是 List（没留下"String"信息）
// 3. 运行时数组检查：objects[0] = new ArrayList<Integer>() 
//    ↓ 数组检查的只是是否是 List 类型
//    ↓ 无法检查是否是 List<String> 类型（因为擦除了）
//    ↓ 所以检查通过 ✅（实际上已经放了错误类型）
// 4. 取出时强转：stringLists[0].get(0) 隐式强转为 String → ClassCastException
```

### 4.4 安全替代方案

```java
public class ArrayAlternatives {

    // 方案 1: 使用 ArrayList
    public static void useArrayList() {
        List<List<String>> lists = new ArrayList<>();  // ✅ 类型安全的嵌套集合
        lists.add(Arrays.asList("a", "b"));
        // lists.add(Arrays.asList(1, 2));  // ❌ 编译错误，类型安全
    }

    // 方案 2: 使用 Object[] 封装，不对外暴露数组
    public static class SafeArray<T> {
        private final Object[] array;

        public SafeArray(int size) {
            this.array = new Object[size];
        }

        @SuppressWarnings("unchecked")
        public T get(int index) {
            return (T) array[index];  // ✅ 局部强转，受控
        }

        public void set(int index, T value) {
            array[index] = value;
        }

        // ❌ 不暴露 getArray() 方法
    }

    // 方案 3: 类型令牌 + Array.newInstance()
    public static <T> T[] createArray(Class<T> clazz, int size) {
        @SuppressWarnings("unchecked")
        T[] array = (T[]) Array.newInstance(clazz, size);
        return array;
    }
}
```

### 4.5 `@SafeVarargs` 与可变参数

可变参数本质上会创建数组，所以泛型可变参数会触发 heap pollution 警告：

```java
public class SafeVarargsDemo {

    // ❌ 泛型可变参数 —— 本质上创建了 T[]
    @SafeVarargs
    public static <T> List<T> flatten(List<T>... lists) {   // 实际上变为 List[] lists
        List<T> result = new ArrayList<>();
        for (List<T> list : lists) {
            result.addAll(list);
        }
        return result;
    }

    // 用法
    public static void main(String[] args) {
        List<String> list1 = Arrays.asList("a", "b");
        List<String> list2 = Arrays.asList("c", "d");
        List<String> result = flatten(list1, list2);  // ✅ 安全使用

        // ❌ heap pollution 场景
        List<String>[] array = new List[2];     // raw type — 来自泛型可变参数
        Object[] objArray = array;
        objArray[0] = Arrays.asList(1, 2, 3);   // heap pollution!
    }
}
```

| 场景 | 是否允许 | 说明 |
|------|:-------:|------|
| `new T[size]` | ❌ 禁止 | 编译错误，运行时不知道 T |
| `new List<String>[size]` | ❌ 禁止 | 类型擦除 + 数组协变的双重问题 |
| `(T[]) new Object[size]` | ⚠️ 允许，但有警告 | 需要 `@SuppressWarnings("unchecked")` |
| `List<String>[]` 类型声明 | ✅ 允许 | 只是不能创建实例 |
| `List<?>[]` 通配符数组 | ✅ 允许 | 通配符数组是安全的 |
| `@SafeVarargs` 泛型可变参数 | ⚠️ 允许，需要注解 | 声明方法内部处理是安全的 |

> 🎯 **核心要点**：数组的运行时协变检查与泛型的编译期类型擦除是互斥的设计哲学。Java 选择了"不允许泛型数组创建"来保证类型安全，但留了 `@SuppressWarnings("unchecked")` 和 `@SafeVarargs` 作为后门。**永远优先使用 `List<E>` 替代数组**。

## 5. 桥方法 Bridge Method

### 5.1 什么是桥方法

桥方法是编译器自动生成的**合成方法**（synthetic method），用于解决泛型类型擦除后造成的多态冲突问题。

```java
// 场景：泛型父类 + 子类具体化类型参数
class Box<T> {
    private T value;

    public void setValue(T value) {
        this.value = value;
    }

    public T getValue() {
        return value;
    }
}

class StringBox extends Box<String> {
    private String description;

    @Override
    public void setValue(String value) {
        this.description = value;
    }

    @Override
    public String getValue() {
        return description;
    }
}
```

### 5.2 擦除后的多态冲突

```java
// 类型擦除后，Box 变成：
class Box {
    private Object value;

    public void setValue(Object value) {   // 方法签名：setValue(Object)
        this.value = value;
    }

    public Object getValue() {             // 方法签名：getValue() -> Object
        return value;
    }
}

// StringBox 擦除后想要的样子：
class StringBox extends Box {
    private String description;

    // 🔴 问题 1：这不是重写！
    // 父类方法签名：setValue(Object)
    // 子类方法签名：setValue(String)
    // 参数不同！这是重载（overload），不是重写（override）
    public void setValue(String value) {    // ⚠️ 不是 @Override
        this.description = value;
    }

    // 🔴 问题 2：返回值协变不符合！ 
    // 父类：getValue() → Object
    // 子类：getValue() → String
    // Java 5 之前这是不允许的
    public String getValue() {
        return description;
    }
}

// 结果：通过父类引用调用 setValue(Object) 不会执行子类的 setValue(String)
Box box = new StringBox();
box.setValue("hello");   // ❌ 调用的是 Box.setValue(Object)，不是 StringBox.setValue(String)
```

### 5.3 桥方法的生成

编译器自动在 `StringBox` 中生成桥方法来解决上述问题：

```java
// 编译器自动生成的 StringBox 字节码等价形式
class StringBox extends Box {

    private String description;

    // 子类自己的方法
    public void setValue(String value) {
        this.description = value;
    }

    // 🔧 桥方法 1：setValue(Object) → 委托给 setValue(String)
    // 该桥方法重写了父类的 setValue(Object)
    public void setValue(Object value) {
        this.setValue((String) value);     // ✅ 强制转型后委托给实际方法
    }

    // 子类自己的方法
    public String getValue() {
        return description;
    }

    // 🔧 桥方法 2：getValue() → Object（返回值协变）
    // 子类的 getValue() 返回 String，编译器还需要一个返回 Object 的版本
    public Object getValue() {
        return this.getValue();            // 实际调用了返回 String 的那个
    }
}
```

### 5.4 桥方法的特征

```java
public class BridgeMethodDetect {

    public static void main(String[] args) throws Exception {
        for (Method m : StringBox.class.getMethods()) {

                System.out.println("Bridge: " + m.getName() + " " +
```

|------|------|
| `ACC_BRIDGE` | 字节码标志 `0x0040`，标识该方法是桥方法 |
| `ACC_SYNTHETIC` | 字节码标志 `0x1000`，标识该方法是编译器合成的 |
| 方法体 | 桥方法只做类型转换并委托给同名的实际方法 |
| 返回值协变 | 桥方法返回父类擦除后的类型（如 Object） |
| 不可直接调用 | 通过父类引用调用时会走桥方法，子类引用调用时走真实方法 |

### 5.5 返回值协变与桥方法

```java
class Parent {
    public Object get() { return null; }
}

class Child extends Parent {
    @Override
    public String get() { return "hello"; }  // ✅ Java 5+ 允许协变返回类型
}

// 编译器自动生成桥方法：
// public Object get() { return this.get(); }  // 桥方法，返回 Object

// 使用验证

// 这里 p.get() 从字节码看调用的是桥方法 Child.get() -> Object
```

> 🎯 **核心要点**：桥方法是 Java 编译器"撒谎"的证据。它伪装成父类方法的实现（与父类方法签名一致），做类型转换后委托给实际方法。本质上，桥方法是「**类型擦除之后的最后一层类型安全防护**」——它保证多态在擦除后仍然正确工作。

## 6. 泛型与异常

### 6.1 不能 catch 泛型异常

```java
// ❌ 编译错误：不能 catch 泛型类型
public class GenericException<T extends Exception> {
    
    public void badTry() {
        try {
            throw new RuntimeException();
        } catch (T e) {                // ❌ 编译错误：Type parameter 'T' cannot be caught
            System.out.println(e);
        }
    }
}

// 为什么不允许？
// 原因 1：类型擦除。
//   catch(T e) 擦除后变为 catch(Exception e)，T 的具体类型丢失
//   如果 T = IOException，那么本应只 catch IOException
//   但擦除后 catch(Exception e) 会 catch 所有 Exception，范围扩大了

// 原因 2：JVM 异常表需要精确类型。
//   JVM 的异常表（exception table）在字节码中记录的是具体的异常类（如 IOException）
//   但擦除后 T 被替换为 Exception，导致异常表无法精确匹配
```

### 6.2 可以在 throws 中使用泛型

```java
// ✅ 允许：在 throws 声明中使用泛型
public class GenericThrows<T extends Exception> {

    // throws 中的泛型是"声明时"的信息，不影响 JVM 运行时
    public void method() throws T {
        // ...
    }

    // 实战用途：泛型异常封装器
    public static <T extends Throwable> void throwAs(Throwable e) throws T {
        throw (T) e;  // ⚠️ unchecked warning，但可行
    }

    public static void main(String[] args) {
        // 异常类型擦除 + 类型推断 —— 可以抛出"非受检异常"而不声明
        try {
            throwAs(new RuntimeException("Oops"));
        } catch (RuntimeException e) {
            System.out.println("Caught: " + e.getMessage());
        }
    }
}
```

### 6.3 泛型异常模式

```java
// 模式 1: 泛型包装异常
public class GenericExceptionWrapper {

    // ✅ 利用泛型 + 类型推断绕过受检异常检查
    @SuppressWarnings("unchecked")
    public static <T extends Throwable> void sneakyThrow(Throwable t) throws T {
        throw (T) t;
    }

    // 使用示例
    public static void main(String[] args) {
        // 不需要在方法签名中声明 Exception
        sneakyThrow(new Exception("这是一个受检异常，但不用声明！"));
    }
}

// 模式 2: 泛型异常区分
interface ErrorCode<T extends Enum<T>> {
    T getCode();
    String getMessage();
}

class BusinessException<T extends Enum<T>> extends RuntimeException {
    private final T errorCode;

    public BusinessException(T errorCode) {
        super(errorCode.name() + ": " + errorCode);
        this.errorCode = errorCode;
    }

    public T getErrorCode() { return errorCode; }
}

// 使用
enum UserError { NOT_FOUND, DUPLICATE, INVALID }
enum OrderError { OUT_OF_STOCK, PAYMENT_FAILED }

// BusinessException<UserError> 和 BusinessException<OrderError> 不同
void handleUserError(BusinessException<UserError> e) {
    // 编译期类型安全
}
```

### 6.4 异常与泛型的限制总结

| 操作 | 是否允许 | 原因 |
|------|:-------:|------|
| `catch(T e)` | ❌ | 类型擦除导致异常表精确匹配无法保证 |
| `catch(E e)`（E 是泛型类成员） | ❌ | 同上 |
| `throws T` | ✅ | throws 是声明，不影响运行时 |
| `throw new T()` | ❌ | `new T()` 不允许 |
| `extends Exception`（泛型边界） | ✅ | 常见模式 `T extends Exception` |
| `try-catch` 中使用泛型类型变量 | ❌ | 必须使用具体类 |

> 🎯 **核心要点**：泛型与异常的核心限制源于类型擦除——**运行时异常处理依赖具体类型信息，但泛型运行时已被擦除**。`throws T` 是唯一允许的泛型-异常结合点，它被用于"偷偷抛出受检异常"等 hack 技巧。

## 7. 类型擦除的遗留问题

### 7.1 Heap Pollution（堆污染）

堆污染指**堆中一个变量指向的类型与它声明的泛型类型不一致**：

```java
public class HeapPollution {

    public static void main(String[] args) {
        // 场景 1: raw type 与泛型混用
        List rawList = new ArrayList();           // raw type
        List<String> strList = rawList;           // ⚠️ unchecked warning

        rawList.add(42);                          // ✅ 编译通过（raw type）
        String s = strList.get(0);                // ❌ 运行时 ClassCastException：Integer cannot be cast to String

        // 场景 2: 未受检的转换
        List<Integer> intList = new ArrayList<>();
        List<String> unsafeList = (List<String>)(List<?>) intList;  // 强制通过通配符转换
        unsafeList.add("hello");                  // 看似安全，但 intList 被污染
    }
}
```

### 7.2 unchecked warning

```java
public class UncheckedWarningDemo {

    @SuppressWarnings("unchecked")  // 压制已知安全的 unchecked 警告
    public static <T> T[] toArray(List<T> list) {
        // ⚠️ unchecked cast warning：(T[]) new Object[size]
        T[] array = (T[]) new Object[list.size()];
        for (int i = 0; i < list.size(); i++) {
            array[i] = list.get(i);
        }
        return array;
    }

    public static void main(String[] args) {
        // unchecked 警告的来源
        // 1. 将 raw type 赋值给参数化类型
        List<String> list = new ArrayList();      // Warning: unchecked

        // 2. 类型转换
        Object obj = new ArrayList<Integer>();
        List<String> strList = (List<String>) obj; // Warning: unchecked

        // 3. varargs
        List<String>[] arr = new List[10];          // Warning: unchecked
    }
}
```

### 7.3 @SafeVarargs 的详细用法

`@SafeVarargs` 用于声明可变参数方法是安全的（不会对 varargs 参数进行污染操作）：

```java
// @SafeVarargs 适用条件：
// 1. 方法必须是 static 或 final（防止子类覆盖破坏安全性）
// 2. 方法不能对 varargs 数组进行"写"操作（只读使用）

public class SafeVarargsRules {

    // ✅ 正确使用 @SafeVarargs：只读，不修改
    @SafeVarargs
    public static <T> List<T> asList(T... elements) {
        List<T> list = new ArrayList<>();
        for (T elem : elements) {             // ✅ 只读使用，不修改数组
            list.add(elem);
        }
        return list;
    }

    // ❌ 错误使用 @SafeVarargs：修改了数组
    @SafeVarargs
    public static <T> void badUse(T... elements) {
        Object[] objects = elements;           // 将 T[] 赋值给 Object[]（协变）
        objects[0] = 42;                       // ❌ 可能导致 heap pollution！
    }

    // ❌ 不能在非 final 的实例方法上使用
    // @SafeVarargs
    // public <T> void instanceVarargs(T... args) {}  // 编译错误
}
```

### 7.4 常见陷阱总结

```java
public class ErasureTraps {

    // 陷阱 1: instanceof 检查 —— 编译错误
    public static <T> boolean isString(Object obj) {
        // return obj instanceof T;  // ❌ 编译错误：T 已擦除
        return obj instanceof String;  // ✅ 必须使用具体类型
    }

    // 陷阱 2: 重载冲突 —— 擦除后签名一致
    // public void process(List<String> list) {}  // ❌ 与下面方法擦除后签名相同
    // public void process(List<Integer> list) {} // ❌ 都是 process(List)

    // 陷阱 3: 重载和桥方法的底层细节
    // 见第 5 节桥方法

    // 陷阱 4: 异常 catch
    // 见第 6 节

    // 陷阱 5: 静态变量的共享
    public static <T> void staticMethod() {
        // static T value;  // ❌ 不能
    }

    // 陷阱 6: 不能 new T()
    public static <T> T createInstance(Class<T> clazz) throws Exception {
        // return new T();         // ❌ 编译错误
        return clazz.getDeclaredConstructor().newInstance();  // ✅ 反射方式
    }
}
```

| 遗留问题 | 表现 | 解决方案 |
|---------|------|---------|
| Heap Pollution | 堆中类型与实际不一致 | 避免 raw type 与泛型混用 |
| unchecked warning | 编译器无法验证类型安全 | `@SuppressWarnings("unchecked")` 已知安全的场景 |
| `@SafeVarargs` 警告 | 泛型可变参数潜在污染 | 仅在只读使用 varargs 时标注 |
| `instanceof T` | 编译错误 | 使用 `Class<T>` 参数替代 |
| 重载冲突 | 擦除后签名相同 | 改用不同方法名 |
| 静态成员 | 不能使用类泛型参数 | 静态方法自行声明泛型参数 |

> 🎯 **核心要点**：类型擦除带来的所有问题都可以归结为"运行时需要确切类型信息，但泛型已经被擦除了"。解决方案要么在编译期解决（`@SuppressWarnings`），要么通过反射/Class 在运行时传递类型信息（`Class<T>` 参数）。

## 8. 泛型面试连环追问

### 8.1 泛型擦除后为什么还能 get 到正确类型？

> **问**：类型擦除后 T 都变成 Object 了，那 `list.get(0)` 返回的应该是 Object，为什么能直接赋值给 String？

**答**：

```java
List<String> list = new ArrayList<>();
list.add("hello");
String s = list.get(0);     // ✅ 为什么能直接赋值？
```

**完整回答**：
```
虽然运行时 list.get(0) 返回的是 Object，但编译器在编译时会在 get 调用处自动插入 checkcast 指令：

字节码：
  0: aload_1                    // 加载 list
  1: invokeinterface #2, 1      // InterfaceMethod List.get:(I)Ljava/lang/Object;
  6: checkcast     #3           // class java/lang/String  ← 这里！
  9: astore_2                   // 赋值给 s

这就是为什么能 get 到"正确类型" ——
不是运行时能识别类型，而是编译器在编译期就插入了类型转换。
如果运行时类型不对，会在 checkcast 处抛出 ClassCastException。
```

### 8.2 什么是桥方法？怎么产生的？

> **问**：详细解释桥方法是怎么产生的，从字节码层面解释。

**答**：

**完整回答**：
```
桥方法的产生需要三个条件：
1. 存在泛型父类（如 Box<T>）
2. 子类具体化了类型参数（如 StringBox extends Box<String>）
3. 子类有 @Override 方法

产生原因（分步解释）：

第 1 步：擦除后签名冲突
  - 父类擦除后：setValue(Object)
  - 子类擦除后：setValue(String)
  - 子类方法并没有重写父类方法（参数不同）

第 2 步：编译器需要保证多态
  - 父类引用调用 setValue(Object) 时，必须进入子类逻辑
  - 所以编译器在子类中生成了一个"额外的方法"：
    public void setValue(Object value) {
        this.setValue((String) value);  // 委托给子类实际方法
    }
  - 这个方法与父类方法签名完全一致，因此是真正的 @Override
  - 它又委托给了子类自己的 setValue(String) 方法

第 3 步：javap 验证
  - 使用 javap -verbose 可以看到桥方法有 ACC_BRIDGE, ACC_SYNTHETIC 标志
  - 方法体只是一个 checkcast + invokevirtual

直观比喻：
  子类说"我只会处理 String 类型"，
  编译器说"但你爸让你处理 Object，我给你加个翻译官（桥方法）吧"。
```

### 8.3 List\<String\> 能不能赋值给 List\<Object\>？

> **问**：`List<String>` 和 `List<Object>` 是什么关系？能不能互相赋值？

**答**：

```java
// ❌ 编译错误：不变性
List<String> strings = new ArrayList<>();
List<Object> objects = strings;  // ❌ 编译错误

// ❌ 反过来的错误也是
List<Object> objects = new ArrayList<>();
List<String> strings = objects;  // ❌ 编译错误
```

**完整回答**：
```
不可以。Java 泛型是不变（invariant）的。

原因：类型安全问题。

如果 List<String> 可以赋值给 List<Object>，会发生：
  List<String> strings = new ArrayList<>();
  List<Object> objects = strings;           // 假想允许
  objects.add(42);                          // Integer 放进去了
  String s = strings.get(0);                // ❌ ClassCastException！

数组 String[] 可以赋值给 Object[]（协变），
但数组有运行时检查会抛 ArrayStoreException。
泛型通过编译期的"不变性"直接从源头杜绝了这个问题。

那如果我想接收两种类型的集合怎么办？
  - 使用通配符：List<? extends Object> 或 List<?>
  - 具体来说：
    void process(List<?> list) { ... }  // 可以传入任意 List
```

### 8.4 为什么基本类型不能作为泛型参数？

> **问**：`List<int>` 为什么不行？Java 为什么没做成 C++ 模板那样？

**答**：

**完整回答**：
```
核心原因：类型擦除 + Object 的局限。

1. 类型擦除后 T 变成 Object
   - int 不是 Object 的子类，不能放在 Object 的位置
   - Object[] 可以放 Integer，但不能放 int（值类型 vs 引用类型）

2. Java 泛型设计的目标是"迁移兼容性"
   - Java 5 之前没有泛型，当时的集合用 Object
   - 为了不用重写所有代码，泛型被设计为"编译期擦除"方案
   - 这要求所有类型参数最终都能用 Object 表示

3. 如果支持 int，必须保留值类型信息
   - 但擦除方案不允许保留 → 死锁

4. 解决方案：自动装箱（autoboxing）
   - int → Integer（编译器自动处理）
   - 但带来了性能开销（堆上对象 vs 栈上值）

5. 未来：Project Valhalla 在探索"值类型"和"专门化泛型"
   - 但目前（Java 21+）仍未正式实现
   - C# 的泛型是真泛型（运行时保留），所以可以 List<int>

面试中可以说：Java 选择"类型擦除 + 装箱"是为了向后兼容，
这是工程妥协。Project Valhalla 正在尝试解决这个问题。
```

### 8.5 什么是 PECS？给个实战案例

> **问**：PECS 原则是什么？如何在方法设计中应用？

**答**：

**完整回答**：
```
PECS = Producer Extends, Consumer Super

内存口诀：
  extends → 读（生产）→ 只读不写
  super   → 写（消费）→ 只写不读

实战案例：通用集合复制方法

public class CollectionCopier {
    
    // ✅ PECS 设计
    public static <T> void copy(
            List<? extends T> source,    // Producer: 只读
            List<? super T> dest) {      // Consumer: 只写（这里要写）
        for (T item : source) {
            dest.add(item);
        }
    }
    
    // 使用
    public static void main(String[] args) {
        List<Integer> ints = Arrays.asList(1, 2, 3);
        List<Number> nums = new ArrayList<>();
        List<Object> objs = new ArrayList<>();
        
        copy(ints, nums);  // ✅ Int -> Number
        copy(ints, objs);  // ✅ Int -> Object
    }
}

反面案例（不用 PECS 的后果）：
  public static <T> void copyBad(List<T> source, List<T> dest) { ... }
  // 调用时必须两个 List 的 T 完全一致！
  // copyBad(ints, nums);  // ❌ 编译失败
```

### 8.6 为什么 `static <T>` 方法中的 T 和类的 T 不是同一个？

> **问**：类上声明了 `<T>`，静态方法又声明了 `<T>`，这两个 T 冲突吗？

**答**：

**完整回答**：
```
不冲突，它们是两个完全独立的类型参数。

public class GenericClass<T> {        // 第 1 个 T：实例级别
    private T value;
    
    public T getInstanceValue() {     // ✅ 用的是第 1 个 T
        return value;
    }
    
    public static <T> T doStatic(T param) {  // ✅ 第 2 个 T：方法级别
        // 这里的 T 和方法调用时传入的类型一致
        // 不能访问 value（因为 value 是类 T 的）
        return param;
    }
}

推荐风格：为避免混淆，不要在静态方法中用同名字母
public class GenericClass<T> {
    
    public static <E> E doStatic(E param) {  // ✅ 用 E 避免混淆
        return param;
    }
}

核心区别：
  - 类的 T：实例化时确定    new GenericClass<String>() → T = String
  - 方法 T：调用时确定       GenericClass.doStatic(42)  → T = Integer

再记一句话：静态方法属于类，类的泛型参数属于实例，两者无关。
```

### 8.7 MyBatis 中泛型是怎么保留的？

> **问**：MyBatis 的 Mapper 接口中 `List<User> findAll()` 擦除后变成 `List`，MyBatis 怎么知道返回的是 User？

**答**：

**完整回答**：
```
虽然类型擦除了，但字节码中保留了 Signature 属性。
MyBatis 通过反射读取 Signature 属性来获取泛型信息。

关键流程：
  1. MyBatis 创建 Mapper 的 JDK 动态代理
  2. 调用接口方法时，代理获取 Method 对象
  3. 通过 method.getGenericReturnType() 获取参数化类型
  4. 如果是 ParameterizedType，取出 actualTypeArguments[0]
  5. 得到 User.class
  6. 用 User.class 指导结果集映射

// MyBatis 源码简化
public class GenericTypeParser {
    
    public Class<?> resolveReturnType(Method method) {
        Type returnType = method.getGenericReturnType();
        
        if (returnType instanceof ParameterizedType) {
            ParameterizedType pt = (ParameterizedType) returnType;
            if (pt.getRawType() == List.class) {
                Type typeArg = pt.getActualTypeArguments()[0];
                return (Class<?>) typeArg;  // 得到 User.class！
            }
        }
        return Object.class;
    }
}

这就是为什么泛型并没有"消失"—— 
它被保存在字节码 Signature 属性中，供框架通过反射读取。
Spring 的 ResolvableType 也是基于同样的原理。
```

### 8.8 类型擦除后 equals 方法怎么工作？

> **问**：类型擦除后，`ArrayList<String>` 和 `ArrayList<Integer>` 比较 equals 会怎么样？

**答**：

```java
public class EqualsAfterErasure {

    public static void main(String[] args) {
        List<String> strList = new ArrayList<>(Arrays.asList("1", "2"));
        List<Integer> intList = new ArrayList<>(Arrays.asList(1, 2));

        System.out.println(strList.equals(intList));  // false
        
        // 因为底层是 List.equals()，擦除后两者都是 List
        // 比较逻辑：
        // 1. 检查是否是同一个对象
        // 2. 检查是否是 List 的实例
        // 3. 逐个元素 equals 比较
        // 4. String.equals(Integer) → false
    }
}
```

**完整回答**：
```
类型擦除不影响 equals 的调用行为：
  - 两个 List 的 Class 对象相同（都是 ArrayList.class）
  - equals 方法根据元素内容比较
  - String.equals(Integer) → false
  - 所以即使类型参数不同，equals 仍然正常工作

但要注意：类型擦除后，不能通过 instanceof 区分
  if (list instanceof ArrayList<String>)  // ❌ 编译错误
  if (list instanceof ArrayList)           // ✅ OK

扩展点：可以用 Class<T> 参数来区分
  public <T> boolean typedEquals(List<T> a, List<T> b, Class<T> clazz) {
      // 但运行期仍然只是 List.equals()
  }
```

---

> 🎯 **本章终极核心**：Java 泛型是"编译期伪泛型"——编译器用它做类型检查，然后擦除为 Object/上界，在需要的地方插入 checkcast。理解了这个本质，就能解释所有泛型面试题：桥方法是擦除后维持多态的补丁，PECS 是让类型参数范围更灵活的约束，数组限制源于协变与擦除的冲突，异常限制是因为运行时异常表需要具体类型。
