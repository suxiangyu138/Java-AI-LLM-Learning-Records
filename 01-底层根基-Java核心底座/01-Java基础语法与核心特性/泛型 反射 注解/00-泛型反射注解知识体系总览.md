## 3. 三者的协作关系

### 3.1 分工：各自解决什么问题

三者在语言层面并不处于同一层，把它们摆在一起讲，容易误以为它们是可以互相替代的三种「技术」。实际上它们解决的问题完全不同：泛型面对的是编译期的类型正确性，反射面对的是运行期的动态性，注解面对的是「意图如何表达」的问题。

泛型的存在意义是让类型错误在编译期暴露。没有泛型时，`List` 里存什么全靠程序员自觉，取出来必须强制转换，转错就在运行时抛 `ClassCastException`。泛型把这层校验前移到编译期，代价是类型参数在编译后会被擦除，运行时拿不到 `List<String>` 里的 `String`。

反射解决的是「代码写的时候不知道要操作谁」的问题。框架要实例化用户写的类、调用用户写的方法，编译期根本不知道这些类的名字，只能等到运行时通过 `Class` 对象去查。反射的代价是绕过编译期检查、把错误推迟到运行时，并且带来可观的查找开销。

注解本身不执行任何逻辑，它只是把结构化元数据写进 class 文件。单独写一个 `@interface` 没有任何效果，必须有处理器去读：编译期的 APT 在生成代码时读，运行期的反射在装配对象时读。这也是「自定义注解不生效」最常见的原因——只定义了注解，没有写读取它的代码。

| 能力 | 生效阶段 | 操作对象 | 缺失后的后果 |
|------|---------|---------|------------|
| 泛型 | 编译期 | 类型参数、方法签名、集合元素 | 类型错误推迟到运行时，靠强制转换和人工约定 |
| 反射 | 运行期 | `Class`、`Method`、`Field`、`Constructor` | 框架无法在不知道类名的前提下创建对象、调用方法 |
| 注解 | 编译期与运行期 | 类、方法、字段等声明位置上的元数据 | 配置只能写死在代码或 XML 里，无法声明式表达 |

### 3.2 协作链路：`@Autowired` 的完整旅程

把 Spring 的属性注入拆开看，三者各自出现在哪一步就非常清楚了：

1. 启动阶段，`ClassPathBeanDefinitionScanner` 扫描 classpath，通过反射读取类上的 `@Component`、`@Service`，判断哪些类需要被容器管理——这一步是**反射 + 注解**。
2. 扫描结果被登记为 `BeanDefinition`，其中保存了类的类型信息，包括类和方法签名里的泛型参数——这一步是**泛型信息的保存**（`Signature` 属性）。
3. 实例化时，容器反射调用构造器创建对象，再反射扫描字段和方法上的 `@Autowired`。
4. 注入时按类型匹配候选 Bean。当注入点是 `List<UserDao>` 或 `Map<String, Handler>` 时，容器必须解析出泛型参数才能匹配到正确的 Bean，Spring 用 `ResolvableType` 完成这一步——这一步是**泛型 + 反射**。
5. 匹配成功后，`Field.set()` 反射写入属性值，访问检查被 `setAccessible(true)` 绕过。

整条链路里，注解负责「标记哪里需要注入」，反射负责「运行时找到并执行」，泛型负责「按什么类型去找」。缺任何一环，IoC 都跑不起来。

### 3.3 生效阶段

| 阶段 | 泛型 | 反射 | 注解 |
|------|------|------|------|
| 源码 | 声明类型参数，参与编译期类型检查 | 不参与 | `SOURCE` 级注解在此可见，编译后被丢弃 |
| 编译期 | 类型检查、擦除、必要时生成桥方法；泛型签名写入 `Signature` 属性 | 不参与 | `CLASS` 与 `RUNTIME` 级注解写入 class 文件；APT 在此读取并生成代码 |
| 类加载 | 随 class 文件一起加载，仅剩签名信息 | 生成 `Class` 对象，方法区持有元数据 | `RUNTIME` 级注解随 `Class` 元数据常驻 |
| 运行期 | 已擦除，只剩上界类型（无界为 `Object`），`getGenericType()` 可读回签名 | 可读注解、可反射调用方法、可绕过访问控制 | 被反射读取，或被框架的注解扫描器读取 |

> **要点**：泛型和注解都「看不见」运行时行为——泛型在编译后消失，注解在没人读的时候等于注释。真正让它们在运行时产生效果的是反射，这也是框架代码里 `getAnnotation()`、`getGenericType()` 出现频率极高的原因。

### 3.4 各层协作细节

| 协作场景 | 泛型角色 | 反射角色 | 注解角色 |
|---------|---------|---------|---------|
| Spring `@Autowired` 注入 | 依赖类型匹配（含泛型参数） | `Field.set()` 运行时赋值 | `@Autowired` 标记注入点 |
| MyBatis Mapper + `@Select` | `List<User>` 返回类型保障 | `Proxy.newProxyInstance()` 创建代理 | `@Select` 提供 SQL 元数据 |
| JPA `@Entity` 实体映射 | `JpaRepository<User, Long>` 泛型约束 | `EntityManager` 反射读写字段 | `@Column` 映射列名 |
| Spring AOP 切面 | 切点表达式泛型匹配 | JDK/CGLIB 动态代理生成 | `@Aspect` 标记切面类 |
| Jackson JSON 序列化 | `TypeReference<List<T>>` 保留类型 | `ObjectMapper` 反射读 getter | `@JsonProperty` 重命名 |
| JUnit 5 参数化测试 | `Stream<Arguments>` 泛型数据源 | `Method.invoke()` 执行测试 | `@ParameterizedTest` 标记 |
| Retrofit HTTP 客户端 | `Call<Result<T>>` 泛型返回类型 | 动态代理实现接口方法 | `@GET("/api/users")` 定义端点 |

## 4. 核心概念速查

### 4.1 泛型（36 概念）

| 概念 | 一句话描述 | 关键点 |
|------|-----------|--------|
| 类型擦除 Type Erasure | 编译后泛型信息被移除，替换为 `Object` 或上界 | 无界 → `Object`，有界 → 上界类型 |
| Signature 属性 | 字节码中保留的泛型元数据签名 | 反射 `getGenericType()` 读的就是它 |
| 通配符 `?` | 未知类型的占位符 | 用于方法参数声明，不能用于实例化 |
| 上界通配符 `? extends T` | 类型是 T 或 T 的子类 | 生产者：读取安全，写入禁止 |
| 下界通配符 `? super T` | 类型是 T 或 T 的父类 | 消费者：写入安全，读取受限 |
| 无界通配符 `?` | 任意类型 | `List<?>` 等价于 `List<? extends Object>` |
| PECS | Producer Extends, Consumer Super | 从集合读用 `extends`，写入集合用 `super` |
| 桥方法 Bridge Method | 编译器生成的合成方法，解决擦除后的多态冲突 | `synthetic bridge` 标志，返回值协变 |
| 泛型方法 `<T> T method()` | 方法级别定义类型参数 | 类型参数声明在返回类型之前 |
| 类型推断 Type Inference | 编译器根据上下文推断泛型类型 | Java 7 钻石操作符，Java 8 目标类型推断 |
| 钻石操作符 `<>` | 简化泛型实例化写法 | `List<String> list = new ArrayList<>();` |
| 原始类型 Raw Type | 不使用泛型参数的类 | `List list = new ArrayList();` 会丢失类型检查 |
| Heap Pollution | 堆中变量实际类型与声明类型不一致 | 常由 unchecked 操作引起 |
| `@SafeVarargs` | 声明可变参数方法类型安全 | 只能用于 `static`、`final` 或构造器 |
| Unchecked 警告 | 编译器无法验证类型安全时的提示 | 可用 `@SuppressWarnings("unchecked")` 抑制 |
| 泛型数组创建 | `new T[]` 不允许 | 数组协变与泛型不变冲突 |
| `List<String>[]` | 不允许创建泛型数组 | 擦除后无法检查元素类型 |
| 协变 Covariance | `String[]` 是 `Object[]` 的子类型 | 数组协变，泛型不变 |
| 不变 Invariance | `List<String>` 不是 `List<Object>` 的子类型 | 泛型安全性来源于不变性 |
| 逆变 Contravariance | 类型关系相反 | Java 用下界通配符模拟 |
| 类型参数命名 | E（集合）、K/V（键值）、T（类型）、R（返回） | 约定俗成，非语法要求 |
| 多重边界 `T extends A & B` | 类型参数可有多个上界 | 类在前，接口在后 |
| 静态方法泛型 | 静态方法不能用类的类型参数 | 必须自己声明类型参数 |
| 内部类泛型 | 非静态内部类可访问外部类的类型参数 | 静态内部类独立 |
| `Class<T>` | 类字面量的泛型版本 | `String.class` 的类型是 `Class<String>` |
| 类型令牌 Type Token | 用 `Class<T>` 传递类型信息 | Spring 进阶用 `ResolvableType` |
| `TypeReference` | Jackson 保留泛型信息的手段 | 匿名子类捕获类型参数 |
| `ResolvableType` | Spring 的泛型解析工具 | 可解析类、方法、字段上的泛型参数 |
| 泛型接口 | 实现类可指定或保留泛型 | `Comparable<T>` 是典型应用 |
| `Comparable<T>` | 泛型接口经典范例 | 避免比较时的强制转换 |
| 泛型构造器 | 构造器也可以声明类型参数 | 合法但少见 |
| `catch(T e)` | 不能捕获泛型类型异常 | 擦除后无法区分异常类型 |
| `throws T` | 可以在声明中抛出泛型异常 | 泛型异常处理模式的基础 |
| `TypeVariable` | 反射 API 中类型参数的表示 | `getBounds()` 取上界 |
| `ParameterizedType` | 反射 API 中参数化类型的表示 | `getActualTypeArguments()` 取实参 |
| 擦除的五大后果 | 不能 `instanceof`、不能 `new T()`、不能 `new T[]`、静态字段共享、重载冲突 | 面试高频五点 |

### 4.2 反射（28 概念）

| 概念 | 一句话描述 | 关键点 |
|------|-----------|--------|
| `Class` 对象 | 每个类在 JVM 中的元数据表示 | 同一个类加载器下只有一个 `Class` 实例 |

| `Method` | 成员方法的反射封装 | `invoke()` / `getParameterTypes()` |
| `Field` | 成员变量的反射封装 | `get()` / `set()` / `setAccessible(true)` |
| `setAccessible()` | 关闭该成员的访问检查 | 模块化后跨模块需要 `--add-opens` |
| `getDeclaredField()` | 取本类声明的字段（含私有） | 不含继承字段 |
| `getField()` | 取 public 字段（含继承） | 只返回 public |
| 动态代理 Dynamic Proxy | 运行时生成代理类 | JDK 与 CGLIB 两条路线 |

| AOP | 横切关注点与业务逻辑分离 | 底层依赖动态代理 |

| `VarHandle` | Java 9 引入的变量句柄 | 替代 `Unsafe` 的大部分场景 |

| `AccessibleObject` | Field/Method/Constructor 的公共基类 | `setAccessible()` 定义在此 |
| 模块化限制 | JDK 9+ 模块系统约束跨模块反射 | 需要 `--add-opens` 或 `Module.addOpens()` |
| `Unsafe` | 底层内存与对象操作 | 可直接分配对象，JDK 23 起逐步限制 |
| 反射获取泛型 | `ParameterizedType` / `TypeVariable` | 依赖 `Signature` 属性 |
| `getGenericSuperclass()` | 取父类的泛型参数 | `ResolvableType` 的底层实现之一 |
| `AnnotatedElement` | 可被注解修饰元素的公共接口 | `Class`/`Method`/`Field` 都实现它 |
| `isSynthetic()` | 判断是否编译器合成元素 | 桥方法、匿名类等 |
| `isBridge()` | 判断是否桥方法 | 仅 `Method` 有 |
| 访问控制演进 | SecurityManager 退场，模块系统接管 | JDK 17 弃用（JEP 411），JDK 24 永久禁用（JEP 486） |
| 反射在 Spring 中的应用 | IoC、DI、AOP、MVC、`@Transactional`、`@Cacheable`、事件、`@Value` | 高频面试题 |

### 4.3 注解（22 概念）

| 概念 | 一句话描述 | 关键点 |
|------|-----------|--------|
| 注解本质 | 特殊的接口，隐式继承 `Annotation` | `@interface` 是语法糖 |
| `Annotation` 接口 | 所有注解的公共父接口 | `annotationType()` / `equals()` / `hashCode()` |
| 元注解 Meta-Annotation | 定义注解的注解 | `@Retention`/`@Target`/`@Documented`/`@Inherited`/`@Repeatable` |
| `@Retention` | 注解保留策略 | `SOURCE` / `CLASS` / `RUNTIME` |
| `RetentionPolicy.SOURCE` | 仅源码可见，编译即丢弃 | `@Override`、`@SuppressWarnings` |
| `RetentionPolicy.CLASS` | 保留到字节码，运行时不加载 | 默认策略，APT 可读 |
| `RetentionPolicy.RUNTIME` | 运行时可通过反射读取 | Spring、MyBatis 注解均为 RUNTIME |
| `@Target` | 注解可修饰的元素类型 | TYPE/FIELD/METHOD/PARAMETER 等 |
| `@Documented` | 注解出现在 Javadoc 中 | 文档型注解使用 |
| `@Inherited` | 注解可被子类继承 | 仅类继承有效，接口与方法无效 |
| `@Repeatable` | 同一元素可重复使用 | Java 8 引入，需容器注解 |
| 注解属性 | 注解中定义的方法 | 返回类型限于基本类型、`String`、`Class`、枚举、注解及其数组 |
| 默认值 | 属性的默认值 | `default` 关键字 |
| 注解处理器 | 编译期处理注解的工具 | `AbstractProcessor` + `RoundEnvironment` |
| APT | 编译期扫描与处理注解 | Java 5 起由 `javac` 支持 |
| `AbstractProcessor` | 自定义 APT 的基类 | 重写 `process()` |
| `RoundEnvironment` | 每轮处理的上下文 | `getElementsAnnotatedWith()` |
| `Elements` | 编译期元素 API | `TypeElement`/`ExecutableElement`/`VariableElement` |
| Lombok | 编译期改写的典型代表 | APT + javac 内部 API 修改 AST |
| `@Generated` | 标识代码由工具生成 | 标准注解，IDE 可识别并跳过覆盖率统计 |
| `@Native` | 标识可被 native 代码访问的字段 | `SOURCE` 级，文档用途 |
| 运行时注解处理 | 反射 + 注解实现声明式编程 | `getAnnotations()` / `isAnnotationPresent()` |

## 5. 框架中的应用矩阵

| 框架 | 泛型 | 反射 | 注解 | 协同链路 |
|------|------|------|------|---------|
| Spring Core | `JdbcTemplate` 参数化查询、`ResolvableType` | IoC 反射创建 Bean、DI 反射注入 | `@Component`、`@Autowired`、`@Configuration` | 注解扫描 → 反射实例化 → 泛型类型解析 → 反射注入 |
| Spring AOP | 切点表达式支持泛型匹配 | JDK / CGLIB 代理生成 | `@Aspect`、`@Before`、`@Around` | 注解标记切点 → 代理生成 → 泛型切点过滤 |
| Spring MVC | `ResponseEntity<T>`、`HandlerMethodArgumentResolver` | 请求参数反射绑定、`MethodParameter` 解析 | `@RequestMapping`、`@RequestParam`、`@RestController` | 注解路由 → 反射调用 → 泛型返回类型处理 |
| Spring `@Transactional` | 事务属性的泛型封装 | AOP 代理拦截 | `@Transactional` | 注解标记边界 → 代理拦截 → 异常类型判定回滚 |
| MyBatis | `List<User>` 返回类型 | `MapperProxy` 动态代理、`Reflector` 元数据 | `@Select`、`@Insert`、`@Param` | 注解提供 SQL → 动态代理生成 Mapper → 泛型映射结果 |
| MyBatis-Plus | `Wrapper<T>`、`IService<T>` | 反射读取实体字段、自动填充 | `@TableName`、`@TableField`、`@TableId` | 注解映射表结构 → 反射生成 SQL → 泛型查询 |
| Hibernate/JPA | `JpaRepository<T, ID>`、`Specification<T>` | `EntityManager` 反射映射 | `@Entity`、`@Column`、`@OneToMany` | 注解声明关系 → 反射读写字段 → 泛型查询接口 |
| Jackson | `TypeReference<List<T>>` | `ObjectMapper` 反射读写属性 | `@JsonProperty`、`@JsonIgnore`、`@JsonFormat` | 注解定义映射 → 反射取值 → 泛型信息保留 |
| JUnit 5 | `Stream<Arguments>` 参数化 | `Method.invoke()` 执行测试 | `@Test`、`@ParameterizedTest`、`@BeforeEach` | 注解标记生命周期 → 反射执行 → 泛型数据源 |
| Spring Validation | `Validator<T>` | 反射读取字段值 | `@Valid`、`@NotNull`、`@Size` | 注解声明约束 → 反射取值 → 执行校验 |
| Spring Cache | 缓存键的泛型参数 | 代理拦截方法调用 | `@Cacheable`、`@CacheEvict` | 注解标记缓存 → 代理拦截 → 泛型参数生成键 |
| OpenFeign | 接口方法泛型返回 | 动态代理生成实现 | `@FeignClient`、`@RequestMapping` | 注解定义服务 → 动态代理 → 泛型解析响应体 |
| MapStruct | 泛型映射方法 | APT 编译期生成实现类 | `@Mapper`、`@Mapping` | 注解定义规则 → 编译期生成 → 类型安全转换 |
| Lombok | 泛型方法自动生成 | javac AST 修改 | `@Getter`、`@Data`、`@Builder` | 注解触发 APT → 改 AST → 生成代码 |

> **面试官视角**：框架源码类问题本质是在问「注解在哪里声明、反射在哪里调用、泛型在哪里约束类型」。能把三者在具体框架里的链路讲清楚，比背 API 有用得多。

## 6. 面试为何将三者放在一起考

### 6.1 三者天然互补

| 维度 | 泛型 | 反射 | 注解 |
|------|------|------|------|
| 时间 | 编译期检查 | 运行时执行 | 编译期/运行期被读取 |
| 作用 | 类型安全约束 | 动态访问与调用 | 声明式元数据 |
| 对框架的意义 | 保证 API 签名的类型安全 | 实现「写一次、通用执行」 | 用声明替代配置 |
| 单独使用 | 集合框架、工具类 | 业务代码很少直接用 | 只有定义没有处理器等于注释 |
| 协同 | 为反射提供类型线索 | 为注解提供执行入口 | 为反射提供元数据 |
| 考察点 | 编译原理与类型系统 | JVM 运行时机制 | 声明式编程思想 |

### 6.2 面试官的底层逻辑

三者被放在一起考，不是因为它们属于同一章节，而是因为一道框架题往往同时踩中三个知识域。以「`@Transactional` 为什么失效」为例：注解声明了事务边界，AOP 代理决定拦截是否生效，异常类型匹配决定回滚与否——答不完整，往往不是不知道 `@Transactional` 的属性，而是讲不清代理机制和类型匹配。

区分「会用」和「懂原理」的分水岭也在这里。多数人会用 `@Autowired`、会写 `List<String>`，但能把「类型擦除 → `Signature` 属性 → `getGenericType()` → `ResolvableType` → 泛型注入」这条链完整说出来的人不多。

最后是对系统化思维的考察：能讲清三者关系，说明至少理解了三件事——编译期与运行期的边界（JVM 基础）、框架「声明式 + 反射执行」的设计模式（框架设计思维）、Java 类型系统的能力与局限（语言深度）。

### 6.3 典型面试题映射

| 面试题 | 泛型 | 反射 | 注解 |
|--------|:---:|:---:|:---:|
| `@Autowired` 工作原理 | 涉及（类型匹配） | 涉及（反射注入） | 涉及（标记注入点） |
| MyBatis Mapper 如何生成实现类 | 涉及（泛型返回值） | 涉及（动态代理） | 涉及（Mapper 注解） |
| `@Transactional` 失效场景 | 涉及（异常类型匹配） | 涉及（AOP 代理） | 涉及（注解声明） |
| Spring 为何默认改用 CGLIB | 涉及（代理类需覆盖泛型签名） | 涉及（两种代理对比） | 不涉及 |
| Lombok 如何实现 `@Data` | 不涉及 | 涉及（AST 修改） | 涉及（触发 APT） |
| `@Cacheable` 的 Key 生成策略 | 涉及（参数泛型） | 涉及（SpEL 求值） | 涉及（标记缓存行为） |
| Hibernate 懒加载代理原理 | 涉及（实体 ID 类型） | 涉及（CGLIB 代理） | 涉及（`@Entity` 标记） |

> **要点**：回答「三者关系」类问题时，不要停在「泛型擦除是什么、反射有哪些 API、注解有几种 Retention」。要能拿到一个框架特性就拆出它用了哪几项底层能力、各自在哪一步生效。

## 7. 学习路线推荐

### 路线 A：面试突击（3~5 天）

适合已有 Java 基础、需要在短时间内补齐面试话术的人。

- 第 1 天：泛型通配符、PECS、桥方法、类型擦除本质，对应模块 01
- 第 2 天：反射核心 API、JDK 动态代理与 CGLIB 对比，对应模块 02
- 第 3 天：注解原理、元注解、APT 与运行期处理的区别，对应模块 03
- 第 4 天：Spring 与 MyBatis 中的三者协作，手写一个简易 IoC，对应模块 04
- 第 5 天：高压模拟面试，限时作答并按标准答案自查，对应模块 05

### 路线 B：系统学习（2~3 周）

适合想真正理解原理、能读懂框架源码的读者。

- 第 1 周：泛型两天、反射两天、注解一天，余下时间做练习和断点调试
- 第 2 周：Spring AOP 源码、MyBatis `MapperProxy` 源码、JPA 映射源码，逐段走读
- 第 3 周：手写简易框架（IoC + AOP + Mapper 模拟），再用面试题检验掌握程度

### 路线 C：源码深挖（架构方向）

适合以框架研发或中间件方向为目标、需要读源码的人。

- 类型系统：`javac` 泛型擦除实现（`com.sun.tools.javac.code.Types`）、class 文件中 `Signature` 属性的格式、Spring `ResolvableType` 的解析路径
- 代理机制：`java.lang.reflect.Proxy` 生成字节码的逻辑、CGLIB `Enhancer` 与 ASM、`java.lang.invoke` 包中的 `MethodHandle` 与 `VarHandle`
- 注解处理：javac 的 Annotation Processing API、Lombok 的注解处理器实现、Spring 的 `AnnotationMetadata` 与 `MergedAnnotations`
