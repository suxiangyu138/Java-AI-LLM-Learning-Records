## 1. 包名规范

### 1.1 基本规则

| 规则 | 正确示例 | 错误示例 |
|------|---------|---------|
| 全小写 | `com.alibaba.user` | `com.Alibaba.User` |
| 单数名词 | `com.company.order` | `com.company.orders` |
| 公司域名反写 | `com.baidu.search` | `baidu.com.search` |
| 避免缩写 | `com.company.util` | `com.company.u` |

### 1.2 分层包名

```text
com.company.project
├── controller      # 控制层
├── service         # 业务层
│   └── impl        # 实现类
├── dao / mapper    # 数据访问层
├── entity / model  # 实体类
├── dto             # 数据传输对象
├── vo              # 视图对象
├── config          # 配置类
├── util            # 工具类
└── exception       # 异常类
```

> 💡 **单数 vs 复数**：阿里手册推荐单数（`util` 不是 `utils`），但实际项目中 `utils` 也很常见。团队统一即可。

## 2. 类名规范

### 2.1 基本规则

| 类型 | 规则 | 示例 |
|------|------|------|
| 普通类 | UpperCamelCase，名词 | `UserService` / `OrderManager` |
| 接口 | 形容词或名词 | `Comparable` / `Runnable` / `UserRepository` |
| 抽象类 | Abstract 前缀 | `AbstractController` / `BaseService` |
| 异常类 | Exception 后缀 | `BizException` / `ParamException` |
| 工具类 | Utils 后缀 | `StringUtils` / `DateUtils` |
| 测试类 | Test 后缀 | `UserServiceTest` |

### 2.2 特殊约定

```java
// ✅ 接口能力用形容词
public interface Comparable<T> { }
public interface Runnable { }

// ✅ 抽象类用 Abstract/Base 前缀
public abstract class AbstractHandler { }
public abstract class BaseController { }

// ✅ 工具类用 Utils/s 后缀 + 私有构造器
public class StringUtils {
    private StringUtils() {
        throw new AssertionError("不能实例化");
    }
}

// ❌ 避免拼音和英文混合
public class PingjiaUtils { }  // 应该用 CommentUtils
```

## 3. 方法名规范

### 3.1 基本规则

| 类型 | 规则 | 示例 |
|------|------|------|
| 普通方法 | lowerCamelCase，动词 | `getUserById()` / `createOrder()` |
| 布尔返回 | is/has/can/should 前缀 | `isDeleted()` / `hasPermission()` |
| 静态工厂 | of/valueOf/from/getInstance | `List.of()` / `Integer.valueOf()` |
| 转换方法 | to/as 前缀 | `toString()` / `asList()` |
| 查询方法 | get/find/query/select | `getUser()` / `findByName()` |
| 更新方法 | update/modify/save | `updateStatus()` / `saveOrder()` |

### 3.2 布尔方法前缀

```java
// ✅ 清晰表达布尔语义
public boolean isDeleted() { }
public boolean hasPermission() { }
public boolean canEdit() { }
public boolean shouldRetry() { }

// ❌ 语义模糊
public boolean deleted() { }      // 是判断还是删除？
public boolean permission() { }   // 是判断还是获取？
```

### 3.3 静态工厂方法命名

```java
// of：多个参数聚合
List<String> list = List.of("a", "b", "c");

// valueOf：类型转换
Integer num = Integer.valueOf("123");

// from：从其他对象转换
LocalDate date = LocalDate.from(temporal);

// getInstance：获取单例或缓存实例
Calendar cal = Calendar.getInstance();

// newInstance：每次返回新实例
ArrayList<String> list = ArrayList.newInstance();

// create：创建对象
UserService service = UserServiceFactory.create();
```

## 4. 变量名规范

### 4.1 基本规则

| 规则 | 正确示例 | 错误示例 |
|------|---------|---------|
| lowerCamelCase | `userName` | `user_name` / `UserName` |
| 布尔前缀 | `isDeleted` | `deleted` / `deleteFlag` |
| 集合用复数 | `users` / `orderList` | `user` / `order` |
| 避免单字母 | `index` / `count` | `i` / `j`（除循环临时变量） |
| 避免拼音 | `name` | `xingming` |

### 4.2 布尔变量命名

```java
// ✅ 推荐
private boolean isDeleted;
private boolean hasPermission;
private boolean canEdit;

// ❌ 避免（getter 会变成 isDeleteFlag，语义不直观）
private boolean deleteFlag;
private boolean permissionFlag;
```

### 4.3 集合变量命名

```java
// ✅ 推荐
List<User> users;
List<Order> orderList;
Map<Long, User> userMap;
Set<String> nameSet;

// ⚠️ 避免（list 实际是 Set 时误导）
List<User> userList;  // 可以，但 users 更简洁
Set<User> userList;   // ❌ 错误，应该用 userSet 或 users
```

## 5. 常量名规范

### 5.1 基本规则

```java
// ✅ 全大写 + 下划线
public static final int MAX_RETRY_COUNT = 3;
public static final String DEFAULT_CHARSET = "UTF-8";
public static final long CACHE_EXPIRE_TIME = 3600L;

// ❌ 错误
public static final int maxRetryCount = 3;
public static final String defaultCharset = "UTF-8";
```

### 5.2 常量类 vs 接口常量

```java
// ✅ 推荐：常量类 + 私有构造器
public class CacheConstants {
    private CacheConstants() { }
    
    public static final String USER_CACHE_KEY = "user:";
    public static final long EXPIRE_TIME = 3600L;
}

// ❌ 避免：接口常量污染命名空间
public interface CacheConstants {
    String USER_CACHE_KEY = "user:";
}
```

> ⚠️ **接口常量问题**：实现类会继承所有常量，污染命名空间；而且接口的本职是定义行为，不是存常量。

### 5.3 魔法数字必须提取

```java
// ❌ 魔法数字
if (retryCount > 3) {
    throw new BizException("重试次数超限");
}

// ✅ 提取为常量
private static final int MAX_RETRY_COUNT = 3;

if (retryCount > MAX_RETRY_COUNT) {
    throw new BizException("重试次数超限");
}
```

## 6. 代码格式规范

### 6.1 缩进与括号

| 规则 | 推荐 | 说明 |
|------|------|------|
| 缩进 | 4 空格 | 不要用 Tab（不同编辑器显示不一致） |
| 大括号 | K&R 风格 | 左括号不换行，右括号独占一行 |
| 行宽 | 120 字符 | 超过换行，运算符留在行尾 |

```java
// ✅ K&R 风格
public void method() {
    if (condition) {
        doSomething();
    } else {
        doOther();
    }
}

// ❌ Allman 风格（Java 不推荐）
public void method()
{
    if (condition)
    {
        doSomething();
    }
}
```

### 6.2 换行规则

```java
// ✅ 运算符留在行尾
String result = "第一段" +
        "第二段" +
        "第三段";

// ✅ 方法链换行，点号留在行首
List<String> names = users.stream()
        .filter(u -> u.getAge() > 18)
        .map(User::getName)
        .collect(Collectors.toList());

// ✅ 参数换行，逗号留在行尾
public void createUser(String name,
                       Integer age,
                       String email) {
    // ...
}
```

### 6.3 空行使用场景

- 方法之间：1 个空行
- 逻辑块之间：1 个空行
- 字段与方法之间：1 个空行
- 类与类之间：2 个空行

## 7. 注释规范

### 7.1 Javadoc 模板

```java
/**
 * 用户服务
 *
 * @author 张三
 * @since 1.0.0
 */
public class UserService {

    /**
     * 根据 ID 查询用户
     *
     * @param id 用户 ID，必须大于 0
     * @return 用户对象，不存在返回 null
     * @throws BizException 查询失败时抛出
     */
    public User getUserById(Long id) throws BizException {
        // ...
    }
}
```

### 7.2 注释标记

| 标记 | 用途 | 示例 |
|------|------|------|
| TODO | 待办事项 | `// TODO: 待优化性能` |
| FIXME | 需要修复 | `// FIXME: 这里有 NPE 风险` |
| XXX | 需要改进 | `// XXX: 临时方案，后续重构` |

### 7.3 注释的"为什么" vs "是什么"

```java
// ❌ 不好的注释（重复代码）
// 判断用户年龄是否大于 18
if (user.getAge() > 18) { }

// ✅ 好的注释（解释为什么）
// 未成年人不允许下单
if (user.getAge() > 18) { }
```

> 🎯 **核心原则**：注释应该解释"为什么这么做"，而不是"做了什么"。代码本身已经说明了"是什么"。

## 8. IDE 配置实战

### 8.1 IntelliJ IDEA 配置

**File → Settings → Editor → Code Style → Java**
- Tab size: 4
- Indent: 4
- Continuation indent: 8
- Use tab character: 不勾选

**File → Settings → Editor → File and Code Templates**
```java
/**
 * ${NAME}
 *
 * @author ${USER}
 * @date ${DATE}
 */
```

### 8.2 Checkstyle 集成

```xml
<!-- checkstyle.xml -->
<module name="Checker">
    <module name="TreeWalker">
        <module name="MethodName">
            <property name="format" value="^[a-z][a-zA-Z0-9]*$"/>
        </module>
        <module name="ConstantName">
            <property name="format" value="^[A-Z][A-Z0-9]*(_[A-Z0-9]+)*$"/>
        </module>
    </module>
</module>
```

## 9. 常见反模式

| 反模式 | 问题 | 正确做法 |
|--------|------|---------|
| 拼音命名 | `PingjiaUtils` | `CommentUtils` |
| 缩写过度 | `usrMgr` | `userManager` |
| 误导性命名 | `list` 实际是 Set | `userSet` 或 `users` |
| 匈牙利命名 | `strName` / `iAge` | `name` / `age` |
| 过长命名 | `getUserInformationByUserIdAndUserName` | `getUserInfo(id, name)` |
| 布尔无前缀 | `deleted` | `isDeleted` |
| 魔法数字 | `if (count > 3)` | `if (count > MAX_COUNT)` |
