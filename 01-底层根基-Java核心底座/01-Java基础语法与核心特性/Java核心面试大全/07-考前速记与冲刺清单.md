## 1. Top 50 高频考点速记表

### 🏗️ Java 基础（01 模块，12 题）

| # | 考点 | 一句话答案 |
|---|------|-----------|
| 1 | 三大特性 | 封装藏数据、继承传血脉、多态靠重写（动态绑定） |
| 2 | 接口 vs 抽象类 | 抽象类是 is-a 骨架（单继承、有字段）；接口是 can-do 契约（多实现、默认方法） |
| 3 | == vs equals | 基本类型比值、引用类型比地址；equals 默认同 ==，String 重写比内容 |
| 4 | equals 与 hashCode | equals 相等 → hashCode 必须相等；hashCode 定桶、equals 定同 |
| 5 | String 不可变 | 常量池共享、线程安全、hashCode 缓存、安全防篡改 |
| 6 | String/StringBuilder/StringBuffer | 不可变 / 单线程快 / 多线程同步；拼接不用 +（O(n²)） |
| 7 | 常量池与 intern | JDK7+ 池在堆；intern 返回池中引用；池对象不被 GC |
| 8 | 值传递 | Java 只有值传递，引用类型传地址副本；改内容生效、换引用不生效 |
| 9 | 装箱陷阱 | Integer 缓存 -128~127；拆箱 null → NPE；POJO 用包装类型 |
| 10 | 受检 vs 非受检 | checked 必须捕获（IO/SQL）；unchecked 是 bug（NPE）；业务异常自定义 |
| 11 | 泛型擦除 | 编译期检查后擦除；? extends 读安全 / ? super 写安全（PECS） |
| 12 | 反射 | Class 三获取方式；性能慢；Spring 靠反射 + RUNTIME 注解 |

### 🗂️ 集合（02 模块，14 题）

| # | 考点 | 一句话答案 |
|---|------|-----------|
| 13 | 集合体系 | List 有序可重复 / Set 无序不可重复 / Map 键值对 |
| 14 | fail-fast | modCount 校验，遍历中结构修改抛 ConcurrentModificationException |
| 15 | HashMap 结构 | JDK8：数组+链表+红黑树；尾插法 |
| 16 | 树化条件 | 链表 ≥8 **且** 数组 ≥64；退化 6 |
| 17 | 为什么是 8 | 泊松分布概率千万分之六 — 防御性设计 |
| 18 | 负载因子 0.75 | 时空权衡平衡点 |
| 19 | 容量 2 的幂 | (n-1)&hash 位运算；扩容元素只移原位/原位+oldCap |
| 20 | JDK7 死循环 | 头插法 + 并发扩容 → 环形链表 |
| 21 | CHM JDK8 | CAS + synchronized 锁桶头；读无锁（volatile） |
| 22 | CHM 为什么不支持 null | 无法区分"值为 null"与"不存在" |
| 23 | ArrayList vs LinkedList | 随机访问 O(1) vs O(n)；无理由选 ArrayList |
| 24 | ArrayList 扩容 | 1.5 倍（>>1）；预判容量防频繁扩容 |
| 25 | HashSet 去重 | 底层 HashMap 的 key；hashCode+equals |
| 26 | LinkedHashMap LRU | accessOrder=true + removeEldestEntry 钩子 |

### ⚡ 并发（03 模块，14 题）

| # | 考点 | 一句话答案 |
|---|------|-----------|
| 27 | sleep vs wait | sleep 不释放锁；wait 释放锁（必须持锁） |
| 28 | 锁升级 | 无锁→偏向→轻量→重量；JDK15+ 默认禁用偏向锁 |

| 33 | CAS | 比较-交换原子指令；缺点：自旋/ABA/单变量 |
| 34 | ABA 解决 | AtomicStampedReference 版本号 |
| 35 | LongAdder | 分段 Cell 累加，高竞争计数首选 |
| 36 | AQS | state + CLH 队列 + 模板方法；JUC 锁的基座 |
| 37 | 公平 vs 非公平 | 非公平先 CAS 插队；性能好 |
| 38 | 线程池 7 参数 | core/max/keepAlive/queue/threadFactory/handler |
| 39 | 拒绝策略 | Abort（默认）/CallerRuns（兜底）/Discard（丢） |

| 41 | ThreadLocal 泄漏 | key 弱引用、value 强引用；线程池场景必须 remove |
| 42 | CountDownLatch | 一次性门闩；await 带超时防卡死 |
| 43 | 虚拟线程 | M:N、IO 密集百万级；不解决 CPU 密集 |

## 2. 易混点对比速查

| 易混对比 | 关键区分 |
|----------|----------|
| `String a == b` vs `a.equals(b)` | 字面量相同时 == 可能 true（常量池）；new 出来必 false |
| `sleep` vs `wait` vs `join` | 不释放锁 / 释放锁 / 等待线程结束 |
| `shutdown` vs `shutdownNow` | 等任务完成 / 中断立即停 |
| `execute` vs `submit` | 异常吞掉（后台日志）/ get() 抛 ExecutionException |
| `thenApply` vs `thenApplyAsync` | 复用提交线程 / 新线程执行 |
| `AtomicLong` vs `LongAdder` | 单槽 CAS / 分段累加（读时合并） |
| `HashMap` vs `Hashtable` vs `CHM` | 线程不安全 / 全锁过时 / CAS+锁桶 |
| `ArrayList` vs `LinkedList` | 数组随机访问快 / 链表中间插入快 |
| `HashSet` vs `TreeSet` | 哈希无序 O(1) / 红黑树有序 O(log n) |
| `CountDownLatch` vs `CyclicBarrier` | 一次性等任务完 / 循环等线程集合 |
| `ConcurrentHashMap` vs `Collections.synchronizedMap` | 桶级锁弱一致 / 全局锁强一致 |
| `ThreadLocal` vs `ScopedValues` | 需 remove 防泄漏 / 作用域自动清理 |
| `record` vs Lombok @Data | 语言级不可变 / 编译期生成可变 bean |
| `Optional.of` vs `ofNullable` | of(null) 抛 NPE / 允许 null |

## 3. 代码手写自测清单

> 💡 面试手写题高频 — 不看书能默写才合格：

```java
// ① 单例（DCL + volatile）— 追问重排序
// ② 生产者消费者（wait/notify 或 Lock+Condition）
// ③ 自定义线程池 + 提交 + 优雅关闭
// ④ 用 Stream 实现：过滤/分组/聚合/排序
// ⑤ LRU 缓存（LinkedHashMap 版 + 手动链表版）
// ⑥ 手写 CAS 自旋计数（AtomicInteger 原理复刻）
// ⑦ 死锁代码（讲清 4 个必要条件）
// ⑧ CompletableFuture 并行聚合（thenCombine/allOf）
// ⑨ 手写 HashMap 核心：put/哈希/扩容思路（简化版）
// ⑩ 单例注册表 / 工厂（设计模式与并发结合）
```

**自测方法：** 每道题 15 分钟白纸手写 → 对照答案 → 错误点标记 → 次日重写。达到"边写边能讲原理"才过关。

## 4. 考前 24 小时冲刺节奏

### 📅 考前一天

| 时间段 | 内容 |
|--------|------|
| 上午 | 07 速记表通读 2 遍（重点：易混点对比表） |
| 下午 | 06 三条连环追问链各自测 1 遍（HashMap/线程池/GC） |
| 晚上 | 手写自测清单 10 题快速过 5 题 + 休息（不熬夜） |

### 🎤 面试当天答题心法

```text
① 结论先行：一句话答案 → 再展开（面试官最烦"嗯...首先..."）
② 主动分层：讲 1 分钟有结构：是什么 → 为什么 → 对比 → 场景
③ 主动补刀：答完自动补"这题的典型坑是..."（展示实战感）
④ 不会就跳：先答相关知识点 + 表明"这块我可以补充学习"
⑤ 写代码先讲思路：注释式书写（先骨架后细节），讲清楚再动手
```

### 📊 自测评分标准（考前自评）

| 分数 | 状态 | 行动 |
|------|------|------|
| ≥90 | 速记表 50 题全过 + 追问链顺畅 | 直接冲，重点准备项目深挖 |
| 70-89 | 1-2 个模块卡壳 | 突击卡壳模块 + 手写清单 |
| <70 | 原理能背、追问卡壳 | 按 06 连环追问链重刷对应模块 |
