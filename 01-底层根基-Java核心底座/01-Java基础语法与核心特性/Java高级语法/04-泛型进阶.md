## 1. 通配符与 PECS

```java
// PECS: Producer Extends, Consumer Super

// ? extends T: 生产者——只能读，不能写
// "我只知道你至少是 T 类型"
List<? extends Number> numbers = new ArrayList<Integer>();
Number n = numbers.get(0);   // ✅ 读取（安全，至少是 Number）
numbers.add(10);             // ❌ 编译错误！不能写（不知道具体是 Integer 还是 Double）

// ? super T: 消费者——只能写，不能读
// "容器能接收 T 及其父类"
List<? super Integer> integers = new ArrayList<Number>();
integers.add(10);              // ✅ 写入（安全，Integer 能被接收）
Object obj = integers.get(0);  // ⚠️ 只能读到 Object（不知道具体类型）

// PECS 实战
public <T> void copy(List<? extends T> src, List<? super T> dest) {
    for (T item : src) dest.add(item);
}

// Spring 源码示例
public interface Converter<S, T> {
    T convert(S source);
}
// S=Source(输入), T=Target(输出)
```

### 通配符决策表

| 场景 | 使用 | 原因 |
|------|------|------|
| 只读 | `? extends T` | 可以安全读为 T |
| 只写 | `? super T` | 可以安全写入 T |
| 读写 | 不用通配符 `<T>` | 需要确定类型 |

## 2. 类型擦除与局限

```java
// 泛型在编译后被擦除 → 运行时没有泛型信息

List<String> strings = new ArrayList<>();
List<Integer> integers = new ArrayList<>();
// 运行时两者都是 ArrayList.class（没有泛型信息）

// 局限 1: 不能创建泛型数组
T[] array = new T[10];  // ❌ 编译错误

// 局限 2: 不能 instanceof 检查泛型
if (list instanceof List<String>) { }  // ❌ 编译错误

// 局限 3: 静态域不能使用泛型参数
class MyClass<T> {
    static T staticField;  // ❌ 编译错误
}

// 局限 4: 不能 new T()
T obj = new T();  // ❌ 需要传入 Class<T> 或 Supplier<T>

// 保留泛型信息的技巧
// 用匿名子类捕获泛型类型（Spring TypeReference / Jackson）
TypeReference<Map<String, List<User>>> ref = new TypeReference<>() {};
```

## 3. 泛型方法设计

```java
// 泛型方法：返回类型由参数决定
public <T> T firstOrNull(List<T> list) {
    return list.isEmpty() ? null : list.get(0);
}

// 泛型工厂：运行时的类型安全
public <T> T createInstance(Class<T> clazz) throws Exception {
    return clazz.getDeclaredConstructor().newInstance();
}

// 多重边界：T 必须同时满足多个约束
public <T extends Comparable<T> & Serializable> T max(T a, T b) {
    return a.compareTo(b) > 0 ? a : b;
}

// 递归泛型：builder 模式（Spring Security / Lombok）
public abstract class Builder<T extends Builder<T>> {
    public T self() { return (T) this; }
}
```

## 核心要点回顾

- PECS: `? extends`(读/生产) / `? super`(写/消费)
- 类型擦除 = 编译后消失，运行时无法获取泛型信息
- 泛型数组/instanceof/new T() 都不行
- Spring `TypeReference` = 保留泛型信息的密技
- 递归泛型 `<T extends Builder<T>>` = 流式 API 的基石
