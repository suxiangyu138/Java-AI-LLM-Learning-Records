## 1. 12 项落地清单

1. **先改数据模型**：新代码一律 `record` + 不可变集合（`List.copyOf`/`toList`），可变集合只留在边界装配
2. **核心层禁 IO**：Service 层"计算/决策"方法保持纯函数，IO 全部下沉到 Repository/Adapter（02 章边界模型）
3. **返回类型显式化**：可能无值返回 `Optional`，可能失败返回 `Result`，禁止返回裸 null
4. **管线优先于循环**：集合变换一律 Stream 三件套，循环只在"确实需要索引/相邻互操作"时保留
5. **lambda 小而纯**：超过 3 行的 lambda 体提取为具名方法；lambda 内不写日志、不改外部状态
6. **统一组合方向**：团队约定 `andThen` 优先于 `compose`，减少方向歧义
7. **Gatherers 替换 workaround**：JDK 24+ 环境，窗口/分页/去重相邻值等场景用内置 gatherer，不再 `collect` 后手写循环
8. **异步编排写契约**：CompletableFuture 链注释每个环节的线程与失败策略；嵌套 Future 一律 `thenCompose` 拍平
9. **并发约束进 review 清单**：`parallelStream`/`mapConcurrent` 的 lambda 检查"无状态无干扰"
10. **异常只在边界**：领域方法不抛业务异常改用 Result；框架边界统一 catch 兜底
11. **性能先测后优**：不可变/装箱成本按 03 章真相判断，压测出瓶颈再优化，不提前返工
12. **版本同步**：JDK 25 LTS 基线 + Gatherers；预览特性（结构化并发）开启需显式评估

存量代码的函数式改造遵循**"由内向外、只改纯处"**五步，禁止一步到位大重构：

1. 选一条无 IO 的计算链（计价/校验/状态转移），先改数据模型为 record + 不可变集合
2. 把链上方法改纯：依赖参数化、副作用抽走，加单测锁定行为（行为不变优先于风格优美）
3. 循环改管线：`for + if` 逐个翻译为 filter/map/collect，跑同一组用例对比结果
4. 空值与错误显式化：返回 null 改 Optional，业务失败改 Result，接口签名变动同步调用方
5. 扩展到边界：核心全部纯化后，最后处理 IO 适配层——此时边界薄、改动面小，回归风险最低

改造判据：**每个 PR 只交"纯函数 + 测试"**，测试通过即合并；风格问题交给 review 而不是重构风暴。

## 2. 性能真相：lambda 不贵，代价在别处

三个常见误解逐一澄清（基于 JDK 24+ 现状）：

- **lambda 本身几乎零开销**：lambda 编译为 `invokedynamic` + 引导方法生成，首次调用后 JIT 内联良好，无每次调用分配（对比匿名类"每次 new 一个类"的时代已过）
- **真实代价是装箱与分配**：`map(x -> x + 1)` 对 `Integer` 流产生装箱；热路径用 `IntStream`/`mapToInt` 规避。不可变"每次修改新建对象"的分配成本靠逃逸分析消化（03 章）
- **收集成本可感知**：`collect(toList())` 与 `toList()` 有微差（后者直接转不可变列表、少一层包装），大数据量管线注意中间收集次数

基准结论（2026）：**函数式管线的性能与等价命令式代码在同一量级**，JIT 对管线的优化（循环展开、S2C 转换）相当成熟；可测出的差距集中在装箱与中间分配，按热点定点优化即可。

## 3. 调试函数式代码的三板斧

管线式代码的调试痛点与解法：

1. **分段验证**：把长管线拆成命名中间变量（每段 `List<X> mid = ...`），逐个断点查看——比在长链上打步点直观得多；验证完再合回
2. **调试期 peek**：`peek(System.out::println)` 只在本地调试用，进线上一律删除（07 章陷阱）；IDEA 的 Stream 调试面板（trace 中间结果）比 peek 更安全
3. **异常溯源**：lambda 里的异常栈会带 `lambda$xxx` 方法名——用 `-XX:+ShowCodeDetailsInExceptionMessages`（JDK 14+ 默认开启）让 NPE 报出"哪个变量为 null"，lambda 里主动 `Objects.requireNonNull` 明确失败点

## 4. 10 大避坑

1. `orElse(build())` 无条件求值——换 `orElseGet`
2. `Optional.get()` 裸取——换 `orElseThrow`，让失败点明确
3. `Stream<Optional<T>>` 不拍平——`flatMap(Optional::stream)`
4. `forEach` 收集到共享集合——换 `map().collect()`
5. `peek` 当业务钩子用（并行下次数不确定）
6. 有状态 lambda 进并行流（计数器/SimpleDateFormat）——数据竞态潜伏
7. `reduce` 做可变累积（StringBuilder 拼接）——换 `collect`
8. 自定义函数式接口直接抛受检异常——编译失败，先包装（05 章）
9. 递归深度无上界——万级爆栈，迭代/trampoline（08 章）
10. 实体字段塞 Optional / 集合元素塞 Optional——序列化与语义双双踩雷（06 章）

## 5. 高频面试题 12 问

### Q1：什么是纯函数？纯函数有什么好处？

> 答：输出只由输入决定、无观察副作用、不抛意外异常。好处三条：可缓存（memoize）、可并行（免锁）、可测试（零 mock）。判据：能否被任意重排/复制/缓存而不变行为。（→ 02）

### Q2：引用透明是什么？和不可变什么关系？

> 答：表达式可被其值替换而行为不变。不可变 + 纯函数 ⇒ 引用透明；引用透明是推理与缓存的根基。（→ 01/02）

### Q3：Function 的 andThen 与 compose 区别？

> 答：`f.andThen(g)` = 先 f 后 g；`f.compose(g)` = 先 g 后 f。读法：andThen 从左到右，compose 从右往左。建议团队统一 andThen。（→ 04）

### Q4：Optional 为什么不能做实体字段？缺失和失败的区别？

> 答：序列化框架（ORM）不支持字段级 Optional；字段空值语义应由 null 表达。缺失（Optional）表达"查无此值"，失败（Result/异常）表达"操作出错"——前者无原因，后者携带原因。（→ 06）

### Q5：Stream Gatherers 解决什么问题？内置有哪些？

> 答：中间操作的官方扩展点（JEP 485，JDK 24 定稿，类比 collect 之于终止操作）。内置五个：windowFixed/windowSliding/scan/fold/mapConcurrent。（→ 07）

### Q6：并行流的 lambda 有什么约束？

> 答：无状态、无干扰（non-interfering, stateless）——不读写共享可变状态、不修改数据源。共享公共 ForkJoinPool，I/O 场景不用并行流。（→ 09/03）

### Q7：thenApply 和 thenCompose 区别？

> 答：变换函数返回普通值用 thenApply（map），返回新 CompletableFuture 用 thenCompose（flatMap 拍平），避免 Future 嵌套。（→ 09）

### Q8：Java 为什么深递归爆栈？怎么解决？

> 答：JVM 无尾调用优化（TCO），每层递归新开栈帧，默认栈深约万级即 StackOverflowError。解法：改迭代、显式栈、trampoline（把递归转循环驱动）。（→ 08）

### Q9：柯里化和部分应用的区别？

> 答：柯里化把多参函数拆成单参函数链（f(a)(b)(c)）；部分应用固定部分参数得到少参函数。Java 都需手工实现，场景是"配置先行、数据后到"。（→ 04）

### Q10：函数式接口为什么不能抛受检异常？

> 答：函数式接口抽象方法默认无 throws 子句，lambda 无法声明受检异常（Java 至今无类型化异常方案）。解法：边界包装成 UncheckedIOException 或自建 Throwing 接口。（→ 05）

### Q11：reduce 和 collect 什么区别？

> 答：reduce 收束为单值（要求结合律、单位元）；collect 收束为容器（内部可变装箱）。可变累积（StringBuilder）必须用 collect，否则并行顺序未定义。（→ 07）

### Q12：虚拟线程时代还需要函数式并发吗？

> 答：需要，分工变化。编排用虚拟线程顺序代码（可读性优先）；并行扇出/结果组合用 CompletableFuture 或结构化并发（JEP 525 预览中）；纯变换并行用 mapConcurrent/parallel stream。函数式思想（不可变、纯函数）是所有并发模型的共同地基。（→ 09）

## 6. 知识体系一句话串讲

Java 函数式 = 三大支柱（纯函数/不可变/无副作用）定性质 → 副作用边界定架构 → 组合子与接口定表达 → Optional/Result 定错误 → Stream/Gatherers 定数据流 → 递归与惰性定时序 → CompletableFuture/虚拟线程定并发 → 清单与避坑定落地。
