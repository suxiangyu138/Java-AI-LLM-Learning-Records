# 装箱拆箱与泛型擦除知识体系总览

## 3. 学习路线推荐

### 路线一：入门（1 天）——先懂机制

01 → 03 → 04，重点掌握：

- 装箱拆箱的字节码真相（`valueOf`/`intValue`）与缓存池边界
- `==` 与 `equals` 在包装类型上的六种组合
- 擦除规则与桥方法的由来（多态性如何被保住）

### 路线二：进阶（2-3 天）——性能与类型系统

02 → 05 → 07，重点掌握：

- 装箱的真实内存成本与 GC 压力（结合集合与 Stream）
- 为什么 `new T[]` 非法、堆污染怎么产生
- 反射中 Type 体系如何"部分恢复"被擦除的类型

### 路线三：专家（1 周+）——框架视角与未来

06 → 08 + 源码，阅读：

- [JEP 390: Warnings for Value-Based Classes](https://openjdk.org/jeps/390)

- javap 反编译自己的泛型类，对照 04 章的桥方法分析

## 4. 核心概念速查

| 概念 | 一句话定义 | 关键要点 |
|------|-----------|---------|
| 自动装箱 | 编译器把 `int` 隐式转换为 `Integer` | 实为 `Integer.valueOf()` 调用 |
| 自动拆箱 | 编译器把 `Integer` 隐式转换为 `int` | 实为 `intValue()` 调用，**null 时 NPE** |
| 包装类缓存 | `valueOf` 对部分范围值返回缓存实例 | Integer -128..127；`-XX:AutoBoxCacheMax` 可调上限 |
| 值类型类 | 无身份（identity）语义的类（包装类等） | JEP 390（JDK 16）警告其被 synchronized |
| 类型擦除 | 编译后泛型参数替换为边界类型 | 无界→`Object`，有界→上界 |
| Signature 属性 | 类文件里保留泛型信息的元数据 | 反射读取的原料，运行时对类型检查"透明" |
| checkcast | 编译器插入的类型检查指令 | 擦除后安全性的执行点 |
| 桥方法 | 编译器为多态性生成的合成方法 | `getValue()` → `getValue():Object` 的转发 |
| 可具体化类型 | 运行时完整信息可用的类型 | `List<String>` 不可具体化，`List<?>` 可以 |
| 堆污染 | 变量类型与运行时实际对象不一致 | unchecked 警告的后果，可能 `ClassCastException` |
| TypeToken | 用匿名子类捕获泛型实参的类型技巧 | `new TypeToken<List<String>>(){}.getType()` |
| 值类（Valhalla） | 无身份、可展平的类 | JEP 401 首个预览计划 JDK 28（2026-07 并入主线） |

## 6. 版本演进时间线

| 版本 | 装箱/擦除相关变化 | 状态 |
|:---:|------------------|:---:|
| Java 5（2004） | 自动装箱/拆箱 + 泛型（擦除实现）引入；`valueOf` 缓存只保证 -128..127 | ✅ 已定稿 |
| JDK 6 | 引入 `-XX:AutoBoxCacheMax`（提升 Integer 缓存上限） | ✅ |
| JDK 9 | `-XX:AutoBoxCacheMax` 并入官方选项集；包装类构造器开始标记废弃 | ✅ |
| JDK 16 | **JEP 390**：包装类声明为值类型类，构造器废弃，synchronized 警告 | ✅ |
| JDK 21 | 包装类构造器**废弃告警升级**（`deprecation` 警告级别变化，移除规划中） | ✅ |
| JDK 26 | JEP 401 早期访问构建出现（`value class` 语法可试玩） | 预览中 |
| JDK 28 | **JEP 401 首个预览**（计划 2026-07 并入主线） | 计划中 |
| 远期 | JEP 402 增强原始类型装箱、泛型特化（Universal Generics 草稿） | 草稿 |

> ⚠️ **版本窗口**：本体系以 **JDK 26**（2026-03 GA）为基线；JEP 401 目标版本与并入时间以 openjdk.org 最新公告为准（本文基于 2026-08 检索）。
