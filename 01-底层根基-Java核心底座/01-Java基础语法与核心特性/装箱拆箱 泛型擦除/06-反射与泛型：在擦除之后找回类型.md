# 反射与泛型：在擦除之后找回类型

> 擦除抹掉了泛型参数，但 javac 在 Signature 属性里留了"档案"——反射的 `Type` 体系就是读取档案的钥匙。TypeToken 把这条链走通：匿名子类 → getGenericSuperclass → ParameterizedType → 类型实参。Gson、MyBatis、Spring 都靠它

## 1. Type 五子体系

`java.lang.reflect.Type` 是泛型反射的根接口，五个实现各管一类"类型"：

```text
java.lang.reflect.Type
├── Class<?>            具体类/接口/数组/基本类型（可具体化类型）
├── ParameterizedType   参数化类型：List<String>、Map<K, V>
├── GenericArrayType    泛型数组：T[]、List<String>[]
├── TypeVariable<?>     类型变量：T、E、K
└── WildcardType        通配符：? extends Number、? super T
```

| Type 实现 | 代表 | 关键方法 | 识别方式 |
|-----------|------|---------|---------|
| `Class` | `String`、`int[]` | 无（本身就够用） | `type instanceof Class` |
| `ParameterizedType` | `List<String>` | `getRawType()`（→ List）、`getActualTypeArguments()`（→ String）、`getOwnerType()` | `type instanceof ParameterizedType` |
| `GenericArrayType` | `T[]` | `getGenericComponentType()`（→ T） | `type instanceof GenericArrayType` |
| `TypeVariable` | `T`（类/方法声明处） | `getBounds()`、`getName()` | `type instanceof TypeVariable` |
| `WildcardType` | `? extends Number` | `getUpperBounds()`、`getLowerBounds()` | `type instanceof WildcardType` |

```java
// 一个类型令牌的解析示例
Type type = new TypeToken<List<String>>() {}.getType();   // ParameterizedType
ParameterizedType pt = (ParameterizedType) type;
System.out.println(pt.getRawType());                  // interface java.util.List
System.out.println(pt.getActualTypeArguments()[0]);   // class java.lang.String
```

> 🎯 **核心要点**：`Type` 五子体系是"擦除后类型档案"的**数据结构化**——`ParameterizedType` 恰好保存了被擦掉的实参。所有泛型框架的运行时类型恢复都在这五个节点上做模式匹配。

## 2. 获取入口：泛型反射 API 全景

| 目标 | API（在哪个对象上） | 返回 |
|------|--------------------|------|
| 父类（含泛型实参） | `Class.getGenericSuperclass()` | `Type`（多为 ParameterizedType） |
| 父接口（含泛型实参） | `Class.getGenericInterfaces()` | `Type[]` |
| 字段类型（含泛型实参） | `Field.getGenericType()` | `Type` |
| 方法返回类型 | `Method.getGenericReturnType()` | `Type` |
| 方法参数类型 | `Method.getGenericParameterTypes()` | `Type[]` |
| 方法抛出的异常类型 | `Method.getGenericExceptionTypes()` | `Type[]` |
| 构造器参数类型 | `Constructor.getGenericParameterTypes()` | `Type[]` |
| 类上的类型变量 | `Class.getTypeParameters()` | `TypeVariable[]` |

```java
// 全链路示例：把"被擦除的泛型"在反射中完整取回
public class UserService extends BaseService<User, Long> {
    private List<User> users;
    public List<User> queryByName(String name) { return null; }
}
// 反射遍历（省略 try/catch）：
Class<?> clazz = UserService.class;
Type superType = clazz.getGenericSuperclass();          // BaseService<User, Long>
Field f = clazz.getDeclaredField("users");
Type fieldType = f.getGenericType();                    // List<User>
Method m = clazz.getDeclaredMethod("queryByName", String.class);
Type retType = m.getGenericReturnType();                // List<User>
```

## 3. 为什么能找回：Signature 档案链

```text
信息流：源码 → javac → 类文件 → 反射 → 框架
  List<String> users
      │ javac 生成
      ▼
  Signature 属性: Ljava/util/List<Ljava/lang/String;>;   ← "档案"
      │ JVM 执行时完全透明（类型检查用擦除后的 List）
      ▼
  Field.getGenericType() 解析 Signature → ParameterizedType(List, String)
      ▼
  框架（Gson/MyBatis/Spring）据此做运行时类型决策
```

**关键认知**：

- 恢复能力来自 **Signature 属性**，而非运行时类型检查——JVM 从不校验档案；
- 恢复范围：**声明处**的泛型（字段/方法/父类声明），**不含**"变量指向的实例"（见第 7 节局限）；
- `getGenericXxx` 返回 `Type` 后可以继续向下解析（ParameterizedType 的实参可能又是 ParameterizedType——嵌套泛型）。

```java
// 嵌套解析示例：Map<String, List<Integer>>
Type nested = ...;   // Map<String, List<Integer>>
ParameterizedType pt = (ParameterizedType) nested;
Type arg = pt.getActualTypeArguments()[1];              // List<Integer>（又是 ParameterizedType）
ParameterizedType inner = (ParameterizedType) arg;
inner.getActualTypeArguments()[0];                      // Integer
```

## 4. TypeToken 原理拆解

### 4.1 核心问题：调用方怎么把泛型实参"带进"运行时

```java
// 框架想要 List<String> 的类型信息，但方法签名只是 Type
// 解决方案：类型令牌（TypeToken）——匿名子类把实参冻结在继承链上
```

### 4.2 三步原理

```java
// 第 1 步：创建匿名子类（关键！）
TypeToken<List<String>> token = new TypeToken<List<String>>() { };
//                              ↑ 匿名子类：编译期生成 class 文件，其签名链上保留 List<String>

// 第 2 步：getGenericSuperclass 拿到"带实参的父类"
class TypeToken<T> {
    Type getType() {
        Type superClass = getClass().getGenericSuperclass();
        // 返回：TypeToken<List<String>>（ParameterizedType）
        ParameterizedType pt = (ParameterizedType) superClass;
        // 第 3 步：取第一个实参
        return pt.getActualTypeArguments()[0];   // List<String>
    }
}
```

```text
为什么必须是匿名子类？
  new TypeToken<List<String>>() { }  —— 匿名子类的 getGenericSuperclass 指向带实参的父类 ✅
  new TypeToken<List<String>>()      —— 错误！TypeToken 自己继承自 Object，
                                          getGenericSuperclass 拿不到 List<String>
```

### 4.3 Gson 的真实用法

```java
// Gson 用 TypeToken 实现 List<User> 的反序列化（TypeToken 来自 Gson，原理同上）
Type type = new TypeToken<List<User>>() {}.getType();
List<User> users = gson.fromJson(json, type);
// 没有 TypeToken 的替代：gson.fromJson(json, User[].class) —— 但数组语义不同且要二次转换
```

> 💡 **认识**：TypeToken 不是 Gson 发明，Java 世界里它来自 Guice/Guava（`com.google.common.reflect.TypeToken`）；JDK 自身没有公开的 TypeToken，但 `ResolvableType`（Spring）实现了同一思路的完整版。

## 5. 实战一：泛型 DAO 提取实体类型

```java
// 框架设计：BaseDao<T> 子类继承时，框架自动提取 T 的运行时 Class
public abstract class BaseDao<T> {
    private final Class<T> entityClass;

    @SuppressWarnings("unchecked")
    protected BaseDao() {
        Type superclass = getClass().getGenericSuperclass();   // BaseDao<User>
        if (superclass instanceof ParameterizedType pt) {
            this.entityClass = (Class<T>) pt.getActualTypeArguments()[0];
        } else {
            throw new IllegalStateException("BaseDao 必须被直接继承并指定泛型实参");
        }
    }

    public T findById(long id) {
        // 有了 entityClass，可以查缓存、走 ORM 映射、拼接表名……
        return mapper.selectById(entityClass, id);
    }
}

class UserDao extends BaseDao<User> { }        // ✅ 正常用法
class BrokenDao<T> extends BaseDao<T> { }      // ❌ 实参还是 T → 提取失败（见 7 节）
```

**这就是 MyBatis-Plus `BaseMapper<T>`、Spring `JpaRepository<T, ID>` 的底层模式**——框架在构造器里读继承链上的泛型实参。

## 6. 实战二：Gson 反序列化 List<String>

```java
// 完整链路：JSON → Type → 泛型实例
import com.google.gson.Gson;
import com.google.gson.reflect.TypeToken;

String json = "[{\"name\":\"a\"},{\"name\":\"b\"}]";
Type type = new TypeToken<List<User>>() {}.getType();
List<User> users = new Gson().fromJson(json, type);   // ✅ 得到 List<User>

// 对照：错误做法（擦除陷阱在框架层的体现）
List<User> users = new Gson().fromJson(json, List.class);
// 结果：得到 List<LinkedTreeMap>！—— 框架不知道元素类型，只能给 Map
```

```text
框架侧的处理逻辑（Gson 内部简化）：
fromJson(json, Type)
  → type 是 ParameterizedType（List, [User]）
  → 解析器按 User 的字段反射构造每个元素 → List<User>
  → type 只是 List（raw）→ 元素类型未知 → 回退 LinkedTreeMap
```

## 7. 局限与陷阱

### 7.1 局限一：恢复的是"声明处"类型，不是"实例"类型

```java
// ❌ 无法做到：从 List 实例反推泛型实参
List<String> list = new ArrayList<>();
list.getClass()              // ArrayList.class —— 无泛型信息
list.getClass().getGenericSuperclass()   // AbstractList<E> —— 类型变量 E，没有 String

// 运行时"List<String>"信息只存在于：字段/方法/父类的 Signature 声明
// 变量赋值路径上的实参信息在编译后彻底消失
```

### 7.2 局限二：中间层泛型传递会丢失

```java
// ❌ 两层继承：B 的签名是 Base<T>（T 未具体化）→ 提取不到
abstract class BaseDao<T> { ... 读取 getGenericSuperclass() ... }
class MiddleDao<T> extends BaseDao<T> { }        // 实参是 T（TypeVariable）
class UserDao extends MiddleDao<User> { }
// UserDao 的 getGenericSuperclass() = MiddleDao（raw！）→ 实参无法一步取到
// 必须沿链向上（getGenericSuperclass 返回 raw Class 时无实参）——Spring ResolvableType 处理了这种链

// ✅ 规范：框架要求子类直接继承基类并写死实参（BaseDao<User>）
```

### 7.3 局限三：类型令牌的运行时类型安全

```java
// 编译器无法验证 TypeToken 的实参与使用处一致
Type token = new TypeToken<List<String>>() {}.getType();
// 若误传：List<User> u = gson.fromJson(json, token);  → 运行时才炸
// 这是"泛型信息只在声明处"的推论：令牌是数据，类型检查在消费端。
```

### 7.4 陷阱清单

| 陷阱 | 表现 | 对策 |
|------|------|------|
| `new TypeToken<>()` 不加 `{}` | 取到的是 Object | 必须匿名子类（4.2） |
| 泛型中间层继承 | 实参为 TypeVariable | 写死实参或上溯解析 |
| `(Class<T>) obj` 强转 | 运行时 ClassCastException 少见但 unchecked 警告 | 用 Type 全链路而非 Class |
| `instanceof ParameterizedType` 判断写错 | 返回 raw Class | 检查 `type instanceof ParameterizedType` 再强转 |
| 接口 vs 类 | `getGenericSuperclass` 不含接口 | 接口用 `getGenericInterfaces()` |

## 8. 核心要点与思考题

> 🎯 **本章三句话总结**：
> 1. Type 五子体系（Class/ParameterizedType/GenericArrayType/TypeVariable/WildcardType）是擦除档案的结构化模型，`getGenericXxx` 全家桶是入口；
> 2. TypeToken 原理三步：匿名子类冻结实参 → getGenericSuperclass 取带实参父类 → getActualTypeArguments 提取——Gson/MyBatis-Plus/Spring 泛型框架的地基；
> 3. 恢复有边界：只恢复**声明处**类型；实例无泛型信息；中间层泛型传递丢失——"运行时类型"永远依赖类型令牌这条显式通道。

**思考题**：

1. `Type` 五子各自代表什么？`ParameterizedType.getActualTypeArguments()` 返回什么？（→ 1）
2. 为什么 `new TypeToken<List<String>>(){}` 能拿到类型而直接 `new TypeToken` 不能？（→ 4.2）
3. MyBatis-Plus 的 `BaseMapper<User>` 是怎么知道 User 的？（→ 5）
4. `gson.fromJson(json, List.class)` 得到什么？为什么？（→ 6）
