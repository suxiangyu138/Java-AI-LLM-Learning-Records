## 1. == 与 equals 的六种组合

### 1.1 总规则（一章记住）

```text
== 的比较语义由"两端类型"决定：
  int   == int      → 值比较
  int   == Integer  → 拆箱后值比较（编译器自动 intValue）
  Integer == Integer → 引用比较（陷阱来源）
equals 永远值比较（但不同包装类之间也 false，见第 7 节）
```

| # | 组合 | 行为 | 例子 |
|:---:|------|------|------|
| ① | `int == int` | 值比较 | `1 == 1` → true |
| ② | `int == Integer` | **拆箱**后值比较 | `1000 == Integer.valueOf(1000)` → **true** |
| ③ | `Integer == Integer` | **引用**比较 | 缓存内 true / 缓存外 false |
| ④ | `Integer.equals(Integer)` | 值比较 | 恒正确 |
| ⑤ | `int.equals`（不存在） | — | `1.equals(...)` 编译错误 |
| ⑥ | `Integer == null` | 引用比较（不拆箱） | `null == null` → true |

```java
// ② 的反直觉点：混合比较会拆箱，所以"直觉中的 == 陷阱"在这里不成立
Integer big = Integer.valueOf(1000);
System.out.println(big == 1000);        // true —— 拆箱后比较（无 NPE 时）
System.out.println(big == 1000L);       // true —— 拆箱并提升为 long

// ③ 的经典坑
Integer a = 1000, b = 1000;
System.out.println(a == b);             // false（缓存外，两个对象）
System.out.println(a == 1000);          // true（混合比较，拆箱）
```

> 🎯 **核心要点**：**判断 == 是否安全，先看操作数类型**——任一操作数是基本类型就拆箱比较（安全）；两个都是包装类型就是引用比较（危险）。生产规则：包装类型之间一律 `equals`（或用 `Objects.equals` 处理 null）。

### 1.2 为什么"缓存外 a==b 是 false"不可靠

`Integer c = 1000; Integer d = 1000; c == d` 默认 false，但：

- 若 `-XX:AutoBoxCacheMax=2000` 则变 true；
- 若经过 `valueOf` 之外的构造路径（反序列化、`new`）则行为不同；
- **结论**：缓存外的 == 结果是"实现细节"，任何依赖它的代码都是 bug。

## 2. 缓存边界陷阱

```java
// 经典连环题
Integer a = 127, b = 127;          // 缓存内
Integer c = 128, d = 128;          // 缓存外
System.out.println(a == b);        // true
System.out.println(c == d);        // false

// 边界值最容易踩：128 恰好出界（新手最容易记成"100 以内"）
Integer m = -128, n = -128;        // true（下限在缓存内）
Integer p = -129, q = -129;        // false（出下界）

// 解析 JSON/序列化回来的 Integer 可能绕过 valueOf
Integer x = Integer.parseInt("128");    // parseInt 返回 int → 赋给 Integer 仍走 valueOf
```

| 边界 | 行为 |
|------|------|
| `-128..127` 内 | `valueOf` 返回缓存实例，== 恒 true |
| `-129` / `128` 及以上 | 每次 new，== 恒 false（同一表达式两次除外——字面量折叠时可能合并） |
| `Integer.parseInt("127")` | 仍走 valueOf → 缓存 |
| 反序列化（某些框架） | 可能直接构造对象，== 结果不确定 |

## 3. 拆箱 NPE 的七个隐蔽触发点

```java
Integer boxed = null;
```

| # | 触发点 | 代码 | 结果 |
|:---:|--------|------|:---:|
| ① | 显式赋值 | `int x = boxed;` | NPE |
| ② | 算术运算 | `int y = boxed + 1;` | NPE |
| ③ | 混合比较 | `if (boxed > 0)` | NPE |
| ④ | 混合 == | `if (boxed == 0)` | NPE（先拆箱再比较） |
| ⑤ | 方法实参（形参为基本类型） | `consume(boxed); void consume(int v)` | NPE |
| ⑥ | switch 包装类型 | `switch (boxed)` | NPE（switch 要求 int） |
| ⑦ | 三元表达式 | `Integer r = flag ? 1 : boxed;` | **先拆箱 boxed 再装箱** → NPE |

```java
// ⑥ switch 陷阱详解
Integer day = null;
switch (day) {                    // 编译期自动拆箱 → NPE
    case 1: ...
}
// 等价于 switch (day.intValue())

// ⑦ 三元陷阱详解（最隐蔽）
Integer boxed = null;
Integer r = true ? 1 : boxed;     // 两个分支类型为 int 和 Integer → 统一为 int → boxed 拆箱！
                                  // → NullPointerException（而不是 r == null）
```

> ⚠️ **最隐蔽的三个**：⑤ 形参拆箱（IDE 不提示）、⑥ switch（写法上毫无痕迹）、⑦ 三元（"结果赋值给包装类型"的直觉误导）。生产修复：入口处 `Objects.requireNonNull` / `Optional` / 空值防御。

## 4. Map 与 null 的语义陷阱

```java
Map<String, Integer> scores = new HashMap<>();
scores.put("alice", 90);

// 陷阱 A：get 返回 null → 拆箱 NPE
int alice = scores.get("alice");          // OK，有值
int bob = scores.get("bob");              // null → intValue() → NPE！
                                          // 即使 key 存在但 value 为 null，同样 NPE

// 陷阱 B：getOrDefault 的隐式装箱
int bob = scores.getOrDefault("bob", 0);  // 没有 NPE（default 参与判断）
// 但注意 getOrDefault 的第二个参数是 V（Integer）→ 0 自动装箱 → 缓存内零成本，缓存外一次分配

// 陷阱 C：computeIfAbsent 返回 null 的语义
Integer x = scores.computeIfAbsent("bob", k -> null);  // 该 key 不会被放入
int y = scores.computeIfAbsent("bob", k -> null);      // 但拆箱时 NPE！

// 陷阱 D：put 允许 null value，读取时炸
scores.put("temp", null);
System.out.println(scores.get("temp") + 1);            // NPE
```

> 🎯 **核心要点**：**包装类型作为 Map 值时，读取后立即拆箱是 NPE 重灾区**。规则：凡 `Map<K, Integer>` 读取，先 `Objects.requireNonNullElse(get(k), 0)` 或明确处理 null；`Map<String, Integer>` 只在确定无 null 值且 key 必存在时才直接拆箱。

## 5. 重载陷阱：List<Integer>.remove 双胞胎

```java
// 经典面试题：输出什么？
List<Integer> list = new ArrayList<>(List.of(1, 2, 3));
list.remove(1);                    // ① ?
list.remove(Integer.valueOf(2));   // ② ?
System.out.println(list);          // ?

// 答案：① 按【下标】删除元素 2（remove(int index) 重载优先）
//       ② 按【值】删除元素 2（remove(Object o)）
// 结果：[1, 3] → [1]  ... 最终 list = [1]

// 结论：int 实参永远命中 remove(int)，想按值删必须显式装箱或 valueOf
```

**重载决议规则**（装箱发生前先看基本类型重载）：

```text
方法调用重载解析顺序（Java 5+）：
1. 精确匹配（int → int）
2. 基本类型拓宽（int → long → float → double）
3. 装箱（int → Integer）
4. 装箱后拓宽（Integer → Number → Object）
```

```java
void f(int i)  { }   void f(long l)  { }   void f(Integer i)  { }
f(1);       // 精确匹配 f(int)
f(Integer.valueOf(1));  // 精确匹配 f(Integer)（不拆箱！）
```

> ⚠️ **扩展坑**：`Long.valueOf(1)` 与 `longValue` 在 `f(long)` 处走**拆箱**——方向相反。写重载 API 时避免同时提供 `(int)` 与 `(Integer)` 版本，否则调用方类型决定语义，极易错位。

## 6. 三元表达式与类型提升

```java
// 规则：三元表达式两个分支会被"统一"到公共类型，再参与后续赋值

// 陷阱 1：int + double → double → 装箱成 Double（不是 Integer！）
Object o = true ? 1 : 2.0;
System.out.println(o.getClass());   // class java.lang.Double

// 陷阱 2：int + null → Integer（null 合法），不拆箱
Integer x = false ? 1 : null;       // x == null（不是 NPE）

// 陷阱 3：Integer + int → 统一为 int → 拆箱！（第 3 节 ⑦）
Integer boxed = null;
Integer r = true ? 1 : boxed;       // NPE

// 陷阱 4：混合条件链
Integer a = true ? 1 : (false ? 2 : 3L);   // 全部提升为 Long → 装箱 Long，赋值 Integer 编译错误！
```

| 分支类型组合 | 统一结果 | 风险 |
|------------|---------|------|
| `int` + `int` | `int` | 赋给 Integer → 装箱 |
| `int` + `long` | `long` | 同上 |
| `int` + `double` | `double` | 装箱成 **Double**，与直觉不符 |
| `Integer` + `int` | `int` | **Integer 分支拆箱** → NPE 风险 |
| `int` + `null` | `Integer` | 合法（null 不拆箱） |

## 7. equals 的类型对称性

```java
// equals 比较的隐藏不对称：不同包装类型直接 false，即使值相等
Integer i = 1;
Long l = 1L;
System.out.println(i.equals(l));              // false（类型不同）
System.out.println(i.equals(1));              // true（int 1 自动装箱成 Integer）
System.out.println(i.equals((long) 1));       // false（装箱成 Long）

// Objects.equals 同样严格
System.out.println(Objects.equals(1, 1L));    // false

// 混合类型数值比较的正确姿势
long a = i.longValue(), b = l.longValue();
System.out.println(a == b);                   // true（值比较，无装箱）
```

> 💡 **教训**：`equals` 的值相等只对**同包装类型**成立。跨类型数值比较（Integer vs Long）必须显式转成同一基本类型再比——这又是一处"装箱 + 类型系统"交汇的暗礁。

```java
// 每题先自己想，再看文末答案
// 1
Integer a = 100, b = 100;  System.out.println(a == b);          // ?
// 2
Integer c = 1000, d = 1000;  System.out.println(c == d);        // ?
// 3
Integer e = 1000;  System.out.println(e == 1000);               // ?
// 4
Integer f = null;  System.out.println(f == 0);                  // ?
// 5
Integer g = null;  int h = g;                                   // ?
// 6
Integer i = null;  Integer j = (true ? 1 : i);                  // ?
// 7
List<Integer> l = new ArrayList<>(List.of(1,2,3));
l.remove(1);  System.out.println(l);                            // ?
// 8
Object o = true ? 1 : 2.0;  System.out.println(o.getClass());   // ?
// 9

// 10
Integer r = 128, s = 128;  System.out.println(r == s);          // ?
```

**答案**：1. true（缓存）2. false（缓存外）3. true（混合拆箱）4. **NPE**（拆箱）5. NPE 6. **NPE**（三元拆箱）7. `[1, 3]`（删下标）8. `Double` 9. false 10. false

## 9. 核心要点

> 🎯 **本章三句话总结**：
> 1. `==` 的语义由操作数类型决定：混合比较必拆箱（值比较），双包装必引用比较——只此一条规则，其余都是推论；
> 2. NPE 七连触发点（赋值/运算/比较/形参/switch/三元/Map.get）全部源于编译器替你调用 `intValue()`；
> 3. 重载决议"基本类型优先于装箱"，三元"统一类型后装箱/拆箱"——这两处语言级规则与直觉相反，面试与代码评审重点关注。
