## 1. 异常层次结构

```
                     +-----------+
                     | Throwable |  (所有异常和错误的基类)
                     +-----+-----+
                           |
              +------------+------------+
              |                         |
         +----v----+             +------v------+
         |  Error   |             | Exception   |  (程序可处理的异常)
         +---------+             +------+------+
                                        |
                        +---------------+---------------+
                        |                               |
                   +----v----+                   +------v--------+
                   | RuntimeException |           | Checked     |
                   | (Unchecked)      |           | Exception    |
                   +------------------+           | (编译时检查)  |
                                                   +--------------+
```

### 1.1 Error（错误）

`Error` 表示程序无法处理的严重问题，通常由 JVM 抛出，程序不应捕获或处理。

```java
// 常见的 Error
// StackOverflowError：栈溢出（递归过深）
public class StackOverflowExample {
    public static void recursive(int i) {
        System.out.println(i);
        recursive(i + 1);  // 无终止条件，最终 StackOverflowError
    }
}

// OutOfMemoryError：内存溢出
// java.lang.OutOfMemoryError: Java heap space
// java.lang.OutOfMemoryError: Metaspace
// java.lang.OutOfMemoryError: Direct buffer memory

// NoClassDefFoundError：类找不到
// UnsatisfiedLinkError：本地方法找不到
```

> **企业实践**: 不要捕获 `Error`。当出现 `Error` 时，程序通常无法恢复，应尽早失败。

### 1.2 Exception（异常）

`Exception` 表示程序可以处理的异常情况。分为两类：

| 类型 | 检查时机 | 需要处理 | 常见异常 | 使用场景 |
|------|---------|---------|---------|---------|
| Checked Exception | 编译时 | 必须 try-catch 或 throws | IOException, SQLException | 可恢复的外部错误 |
| Unchecked Exception (RuntimeException) | 运行时 | 可选 | NullPointerException, IllegalArgumentException | 编程错误 |

## 2. Checked vs Unchecked 异常

### 2.1 Checked Exception（受检查异常）

必须显式处理（try-catch）或声明抛出（throws），否则编译不通过。

```java
import java.io.*;

public class CheckedExceptionDemo {

    // 方式 1：声明 throws，交给调用者处理
    public String readFile(String path) throws IOException {
        BufferedReader reader = new BufferedReader(new FileReader(path));
        String line = reader.readLine();
        reader.close();
        return line;
    }

    // 方式 2：try-catch 自己处理
    public String readFileSafe(String path) {
        try {
            BufferedReader reader = new BufferedReader(new FileReader(path));
            String line = reader.readLine();
            reader.close();
            return line;
        } catch (IOException e) {
            System.err.println("读取文件失败: " + e.getMessage());
            return null;
        }
    }

    // 方式 3：try-with-resources 自动关闭（JDK 7+）
    public String readFileAuto(String path) throws IOException {
        try (BufferedReader reader = new BufferedReader(new FileReader(path))) {
            return reader.readLine();  // reader 自动关闭
        }  // 捕获不到异常，但会抛出
    }
}
```

### 2.2 Unchecked Exception（非受检查异常）

也称为 `RuntimeException`，不强制处理，但良好的代码应当预防和处理。

```java
public class UncheckedExceptionDemo {

    public static void main(String[] args) {
        // NullPointerException：手动预防
        String str = null;
        if (str != null) {
            System.out.println(str.length());
        }

        // IllegalArgumentException：参数校验
        setAge(-5);  // 抛出异常

        // ArrayIndexOutOfBoundsException
        int[] arr = new int[5];
        if (index >= 0 && index < arr.length) {
            System.out.println(arr[index]);
        }

        // ClassCastException：instanceof 检查
        Object obj = "Hello";
        if (obj instanceof String) {
            String s = (String) obj;
        }

        // NumberFormatException
        String num = "abc";
        try {
            int value = Integer.parseInt(num);
        } catch (NumberFormatException e) {
            System.out.println("数字格式错误: " + num);
        }
    }

    public static void setAge(int age) {
        if (age < 0 || age > 150) {
            throw new IllegalArgumentException("年龄不合法: " + age);
        }
        System.out.println("年龄: " + age);
    }
}
```

### 2.3 选择原则

```
Checked Exception 的使用原则（《Effective Java》第 71 条）:

1. 如果调用者可以合理地恢复程序，使用 Checked Exception
   - 如：文件不存在（可以用默认配置继续）
   - 如：网络超时（可以重试）

2. 如果调用者无法恢复程序，使用 Unchecked Exception
   - 如：NullPointerException（编程错误）
   - 如：IllegalArgumentException（参数错误）
   - 如：数据库连接失败（通常无法恢复）

3. 现代 Java 实践倾向于少用 Checked Exception
   - Spring、Hibernate 等框架大量使用 Unchecked Exception
   - 过度使用 Checked Exception 导致代码冗长
```

## 3. try-catch-finally

### 3.1 基本语法

```java
public class TryCatchFinallyDemo {

    public static void main(String[] args) {
        // ---- 基本结构 ----
        try {
            // 可能抛出异常的代码
            int result = divide(10, 0);
            System.out.println("结果: " + result);
        } catch (ArithmeticException e) {
            // 捕获特定异常
            System.out.println("算术异常: " + e.getMessage());
        } catch (Exception e) {
            // 捕获更通用的异常（顺序很重要：子类在前，父类在后）
            System.out.println("其他异常: " + e.getMessage());
        } finally {
            // 无论是否抛出异常，都执行
            System.out.println("finally 总是执行");
        }

        // ---- 多异常捕获（JDK 7+）：用 | 分隔 ----
        try {
            riskyOperation();
        } catch (IOException | SQLException e) {
            // 同时捕获多个异常
            System.err.println("IO 或 SQL 异常: " + e.getMessage());
            // 注意：e 在这里是 final 类型（不能重新赋值）
        }

        // ---- try-catch 可以有返回值 ----
        String result = tryWithReturn();
        System.out.println(result);
    }

    public static int divide(int a, int b) {
        return a / b;
    }

    public static void riskyOperation() throws IOException, SQLException {
        // 可能抛出多个异常
        throw new IOException("网络错误");
    }

    public static String tryWithReturn() {
        try {
            int[] arr = {1, 2, 3};
            return "正常: " + arr[0];
        } catch (Exception e) {
            return "异常: " + e.getMessage();
        } finally {
            System.out.println("finally 在 return 之前执行");
            // finally 中的 return 会覆盖 try 中的 return（不推荐！）
            // return "finally 返回值";
        }
    }
}
```

### 3.2 finally 的执行时机

```java
public class FinallyExecutionDemo {

    public static void main(String[] args) {
        System.out.println(testFinally());  // 输出什么？
    }

    @SuppressWarnings("finally")
    public static String testFinally() {
        try {
            System.out.println("try 执行");
            return "try 返回值";    // 先计算返回值，再执行 finally
        } catch (Exception e) {
            System.out.println("catch 执行");
            return "catch 返回值";
        } finally {
            System.out.println("finally 执行");
            // finally 中 return 会覆盖 try/catch 的 return
            // return "finally 返回值";
        }
    }
}
```

**执行流程**:

```
1. 执行 try 块中的代码
2. 如果未抛异常：计算 try 中的返回值（但不立即返回）
3. 执行 finally 块
4. 如果 finally 没有 return，返回 try 中计算的返回值
5. 如果 finally 有 return，返回 finally 的返回值（覆盖 try）

注意：如果 finally 中抛出了异常，try 中的异常会被抑制
```

### 3.3 try-with-resources（JDK 7+）

自动关闭实现了 `AutoCloseable` 或 `Closeable` 接口的资源。

```java
public class TryWithResourcesDemo {

    public static void main(String[] args) {
        // ---- 传统方式（JDK 7 之前）----
        BufferedReader reader = null;
        try {
            reader = new BufferedReader(new FileReader("test.txt"));
            System.out.println(reader.readLine());
        } catch (IOException e) {
            e.printStackTrace();
        } finally {
            if (reader != null) {
                try {
                    reader.close();
                } catch (IOException e) {
                    e.printStackTrace();
                }
            }
        }

        // ---- try-with-resources（简洁、安全）----
        try (BufferedReader br = new BufferedReader(new FileReader("test.txt"));
             FileWriter fw = new FileWriter("output.txt")) {
            // 同时管理多个资源，用 ; 分隔
            String line;
            while ((line = br.readLine()) != null) {
                fw.write(line + "\n");
            }
        } catch (IOException e) {
            e.printStackTrace();  // 资源自动关闭
        }

        // ---- 自定义 AutoCloseable 资源 ----
        try (MyResource resource = new MyResource()) {
            resource.doSomething();
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}

class MyResource implements AutoCloseable {
    public void doSomething() {
        System.out.println("使用资源");
    }

    @Override
    public void close() throws Exception {
        System.out.println("关闭资源");
    }
}
```

**try-with-resources 的抑制异常**:

```java
public class SuppressedExceptionDemo {

    public static void main(String[] args) {
        try {
            readFileBad();
        } catch (Exception e) {
            System.err.println("主异常: " + e.getMessage());
            Throwable[] suppressed = e.getSuppressed();  // 获取被抑制的异常
            for (Throwable s : suppressed) {
                System.err.println("抑制异常: " + s.getMessage());
            }
        }
    }

    public static void readFileBad() throws Exception {
        // 模拟 try-with-resources 中的抑制异常
        try (AutoCloseable resource = () -> { throw new Exception("关闭时异常"); }) {
            throw new Exception("业务异常");
        }  // 关闭异常被抑制，抛出的是业务异常
    }
}
```

## 4. throw vs throws

| 关键字 | 位置 | 作用 | 数量 |
|--------|------|------|------|
| `throw` | 方法体内部 | 主动抛出异常对象 | 一次抛出一个 |
| `throws` | 方法声明末尾 | 声明方法可能抛出的异常 | 可声明多个 |

```java
public class ThrowThrowsDemo {

    // throws：声明方法可能抛出的异常
    public void validateAge(int age) throws IllegalArgumentException {
        if (age < 0) {
            // throw：主动抛出异常
            throw new IllegalArgumentException("年龄不能为负数: " + age);
        }
        if (age > 150) {
            throw new IllegalArgumentException("年龄超过合理范围: " + age);
        }
    }

    // 多个异常
    public void processFile(String path) throws IOException, FileNotFoundException {
        if (path == null) {
            throw new IllegalArgumentException("路径不能为空");
        }
        if (!new File(path).exists()) {
            throw new FileNotFoundException("文件不存在: " + path);
        }
        // 处理文件
    }

    // 实际抛出的异常可以与声明的不同（子类多态）
    public void read(String path) throws IOException {
        if (path == null) {
            throw new NullPointerException("路径为 null");  // RuntimeException，无需声明
        }
        throw new FileNotFoundException("文件不存在");
    }
}
```

### 4.1 方法重写时的异常规则

```java
class Parent {
    public void method() throws IOException, SQLException {
        // 父类方法
    }

    public void noException() { }
}

class Child extends Parent {

    // 规则 1：可以不抛出任何异常（更严格的限制）
    @Override
    public void method() {
        // 不抛异常，合法
    }

    // 规则 2：可以抛出父类异常的子类型
    @Override
    public void method() throws FileNotFoundException {
        // FileNotFoundException 是 IOException 的子类，合法
    }

    // 规则 3：不能抛出父类异常的父类型
    // @Override
    // public void method() throws Exception { }  // 编译错误！

    // 规则 4：不能抛出父类没有声明的新 CheckedException
    // @Override
    // public void noException() throws Exception { }  // 编译错误！

    // 规则 5：可以抛出 RuntimeException（不需要声明）
    @Override
    public void noException() {
        throw new RuntimeException("运行时异常");
    }
}
```

## 5. 自定义异常

### 5.1 企业级自定义异常设计

```java
/**
 * 自定义异常的最佳实践：
 * 1. 异常名以 Exception 结尾
 * 2. 提供多个构造方法以覆盖常见场景
 * 3. 包含错误码（便于国际化/前端处理）
 * 4. 属于 Unchecked 或 Checked 视业务场景而定
 * 5. 实现序列化（因为异常可能需要网络传输）
 */

// 基类异常（Unchecked，便于统一处理）
public class BusinessException extends RuntimeException {

    private static final long serialVersionUID = 1L;

    private final String errorCode;

    public BusinessException(String errorCode, String message) {
        super(message);
        this.errorCode = errorCode;
    }

    public BusinessException(String errorCode, String message, Throwable cause) {
        super(message, cause);
        this.errorCode = errorCode;
    }

    public BusinessException(String errorCode, String message, Object... args) {
        super(String.format(message, args));
        this.errorCode = errorCode;
    }

    public String getErrorCode() {
        return errorCode;
    }
}

// 具体异常类
public class UserNotFoundException extends BusinessException {
    public UserNotFoundException(Long userId) {
        super("USER_NOT_FOUND", "用户不存在: " + userId);
    }
}

public class InsufficientBalanceException extends BusinessException {
    public InsufficientBalanceException(String accountNo) {
        super("INSUFFICIENT_BALANCE", "账户余额不足: " + accountNo);
    }
}

public class OrderExpiredException extends BusinessException {
    public OrderExpiredException(String orderId) {
        super("ORDER_EXPIRED", "订单已过期: " + orderId);
    }
}

// 使用自定义异常
public class OrderService {

    public void cancelOrder(Long orderId, Long userId) {
        // 业务校验，失败时抛出自定义异常
        if (orderId == null) {
            throw new IllegalArgumentException("订单 ID 不能为空");
        }

        Order order = findOrder(orderId);
        if (order == null) {
            throw new OrderExpiredException(String.valueOf(orderId));
        }

        if (!order.getUserId().equals(userId)) {
            throw new BusinessException("NO_PERMISSION",
                "用户 %d 无权取消订单 %d", userId, orderId);
        }

        if (order.getStatus() == OrderStatus.DELIVERED) {
            throw new BusinessException("ORDER_CANNOT_CANCEL",
                "订单 %d 已发货，无法取消", orderId);
        }

        // 正常业务逻辑
        order.setStatus(OrderStatus.CANCELLED);
        saveOrder(order);
    }

    private Order findOrder(Long orderId) {
        return null;  // 模拟
    }

    private void saveOrder(Order order) { }
}
```

### 5.2 异常定义规范（阿里巴巴）

```
阿里巴巴 Java 开发手册 异常处理章节核心条款：

1. 【强制】异常不要用来做流程控制，条件控制
2. 【强制】catch 时请分清稳定代码和非稳定代码
3. 【强制】不要在 finally 块中使用 return
4. 【强制】捕获异常是为了处理它，不要捕获了却什么都不做
5. 【强制】事务场景中，被 catch 异常需要回滚时，注意手动回滚
6. 【推荐】方法的返回值可以为 null，可以不返回空集合或空对象等
7. 【推荐】防止 NPE，是程序员的基本素养
8. 【推荐】定义时区分 unchecked / checked 异常
```

## 6. 异常链与异常翻译

### 6.1 异常链（Exception Chaining）

```java
public class ExceptionChainingDemo {

    public static void main(String[] args) {
        try {
            serviceLayer();
        } catch (BusinessException e) {
            System.err.println("错误码: " + e.getErrorCode());
            System.err.println("消息: " + e.getMessage());
            System.err.println("原始异常: " + e.getCause());
            // 打印完整堆栈
            e.printStackTrace();
        }
    }

    // 数据访问层：抛出原始异常
    public static void dataAccessLayer() throws SQLException {
        throw new SQLException("数据库连接失败: timeout");
    }

    // 业务层：捕获底层异常，翻译为业务异常（异常链）
    public static void serviceLayer() {
        try {
            dataAccessLayer();
        } catch (SQLException e) {
            // 将 SQLException 转换为业务异常，保留原异常信息
            throw new BusinessException("DB_ERROR", "数据库操作失败", e);
        }
    }

    // 表现层：异常最终会在统一处理中被捕获
}
```

### 6.2 异常翻译最佳实践

```java
public class ExceptionTranslationDemo {

    // 异常翻译：将底层异常转换为上层理解的异常
    // 适用于分层架构（Controller -> Service -> DAO）

    // DAO 层抛出技术异常
    public User findUserById(Long id) throws SQLException {
        // JDBC 操作
        throw new SQLException("查询用户失败");
    }

    // Service 层翻译为业务异常
    public User getUserById(Long id) {
        try {
            return findUserById(id);
        } catch (SQLException e) {
            // 翻译异常：技术异常 -> 业务异常
            throw new BusinessException("DB_ERROR",
                "查询用户 %d 失败: %s", id, e.getMessage());
        }
    }

    // Controller 层无需处理业务异常（由全局异常处理器处理）
}
```

## 7. 最佳实践

### 7.1 永远不要吞没异常

```java
// ❌ 错误：空 catch，吞没异常
try {
    riskyOperation();
} catch (Exception e) {
    // 什么都没做！异常被完全忽略
}

// ❌ 错误：只打印不处理
try {
    riskyOperation();
} catch (Exception e) {
    e.printStackTrace();  // 虽然打印了，但程序继续执行，状态可能已不一致
}

// ✅ 正确：至少要记录日志
try {
    riskyOperation();
} catch (Exception e) {
    log.error("操作失败", e);
    throw new BusinessException("OPERATION_FAILED", "操作失败", e);
    // 要么重新抛出，要么业务上处理（如返回默认值）
}
```

### 7.2 尽早失败（Fail-Fast）

```java
// ✅ 推荐：尽早检查参数，失败时立即抛出异常
public void processOrder(Order order) {
    // 参数校验先行
    if (order == null) {
        throw new IllegalArgumentException("订单不能为空");
    }
    if (order.getItems() == null || order.getItems().isEmpty()) {
        throw new IllegalArgumentException("订单必须包含商品");
    }
    if (order.getTotalAmount() == null || 
        order.getTotalAmount().compareTo(BigDecimal.ZERO) <= 0) {
        throw new IllegalArgumentException("订单金额必须为正数");
    }

    // 业务逻辑
    // ...
}

// ❌ 不推荐：先执行，后失败
public void processOrderBad(Order order) {
    // 先执行大量操作
    saveToDb(order);
    updateInventory(order);
    sendNotification(order);
    // 在最后才发现问题
    if (order == null) {
        // 已经做了很多无用功
    }
}
```

### 7.4 异常的性能影响

```java
public class ExceptionPerformanceDemo {

    public static void main(String[] args) {
        // 异常创建的开销：填充堆栈是一个非常昂贵的操作
        long start = System.nanoTime();
        for (int i = 0; i < 100000; i++) {
            try {
                throw new Exception();
            } catch (Exception e) {
                // 不处理
            }
        }
        long end = System.nanoTime();
        System.out.println("使用异常: " + (end - start) / 1_000_000 + " ms");

        // 替代方案：条件判断
        long start2 = System.nanoTime();
        for (int i = 0; i < 100000; i++) {
            if (shouldFail()) {
                // 不抛出异常
            }
        }
        long end2 = System.nanoTime();
        System.out.println("条件判断: " + (end2 - start2) / 1_000_000 + " ms");
    }

    private static boolean shouldFail() {
        return false;
    }
}
```

**性能影响总结**:

```
异常创建：慢（需要填充堆栈跟踪，约 1000-2000 纳秒）
try-catch：快（无异常时基本零开销，约 2 纳秒）
finally：快（几乎零开销）

结论：不要用异常做流程控制，异常应该只用于异常情况！
```

### 7.5 异常处理模式速查

| 场景 | 处理方式 | 示例 |
|------|---------|------|
| 参数校验失败 | 抛出 IllegalArgumentException | `throw new IllegalArgumentException(msg)` |
| 业务规则违反 | 抛出自定义业务异常 | `throw new InsufficientBalanceException(...)` |
| 外部资源不可用 | 捕获后重试或优雅降级 | 重试 3 次，超时用缓存 |
| 数据不存在 | 返回 Optional 或抛异常 | `Optional.empty()` 或 `EntityNotFoundException` |
| 线程中断 | 恢复中断状态 | `Thread.currentThread().interrupt()` |
| 无法恢复的错误 | 尽早失败，向上传播 | 抛运行时异常 |

## 9. 常见面试题

1. **Error 和 Exception 的区别？**
   - Error：JVM 级别的严重问题，程序无法处理（OOM、StackOverflow）
   - Exception：程序可处理的异常情况

2. **Checked 和 Unchecked 异常的区别？**
   - Checked（如 IOException）：编译时强制处理，可恢复
   - Unchecked（如 NullPointerException）：运行时出现，编程错误
   - 现代框架倾向于使用 Unchecked

3. **try-catch-finally 中哪个部分可以省略？**
   - catch 和 finally 至少出现一个
   - 可以 try-finally（不捕获只清理）
   - 可以 try-catch（不清理只捕获）

4. **finally 块在什么情况下不会执行？**
   - `System.exit(0)` 退出 JVM
   - 线程被 kill
   - try 块中无限循环

5. **throw 和 throws 的区别？**
   - throw：方法内部抛出异常对象
   - throws：方法声明可能抛出的异常类型

6. **try-with-resources 中资源关闭的顺序？**
   - 先创建的后关闭（逆序）
   - 所有资源都会自动关闭

7. **什么是异常链？为什么需要？**
   - 将低级异常包装为高级异常，保留原始异常信息
   - 便于定位问题的根本原因

8. **如何自定义异常？有哪些注意事项？**
   - 继承 Exception（Checked）或 RuntimeException（Unchecked）
   - 命名以 Exception 结尾
   - 提供多个构造方法
   - 包含错误码
   - 实现序列化

9. **`@Override` 重写方法抛异常的限制？**
   - 可以不抛（更严格）
   - 可以抛子类型
   - 不能抛父类型
   - 不能抛新的 Checked 异常

10. **性能方面，异常处理有哪些需要注意的？**
    - 异常创建开销大（堆栈填充）
    - 不要用异常做流程控制
    - try-catch 无异常时零开销
