## 4. 核心概念速查

| 概念 | 一句话速查 | 详见 |
|------|-----------|------|
| 哈希函数 | 任意长度输入 → 固定长度输出的确定性映射 | 01 |
| hashCode 契约 | equals 相等 → hashCode 必须相等（反向不要求） | 01 |
| String.hashCode | `s[0]*31^(n-1) + s[1]*31^(n-2) + ... + s[n-1]` | 01 |
| 哈希碰撞 | 不同 key 映射到同一桶，用链表/红黑树解决 | 02 |
| 扰动函数 | `h ^ (h >>> 16)` 让高位参与低位计算 | 02 |
| 装载因子 | 0.75，扩容阈值 = 容量 × 0.75 | 02 |
| 树化阈值 | 链表 ≥ 8 且容量 ≥ 64 转红黑树（泊松分布 <1e-8） | 02 |
| 扩容重定位 | `hash & oldCap == 0` 原位，否则 原位 + oldCap | 02 |
| HashDoS | 构造碰撞 key 打满链表，把 O(1) 拖成 O(n) 的攻击 | 05 |
| 一致性哈希 | 哈希环 + 顺时针查找 + 虚拟节点，扩缩容只影响 1/n | 06 |
| 布隆过滤器 | m 位数组 + k 个哈希，有误判率但绝不漏判（可能假阳性） | 06 |
| 密码哈希 | 必须慢：Argon2id / bcrypt(cost≥12) / PBKDF2(≥600k) | 07 |

## 6. 高频追问速答

| # | 追问 | 一句话答案 |
|---|------|-----------|
| 1 | 重写 equals 不重写 hashCode 会怎样？ | HashMap 中 equals 相等的对象可能落在不同桶，永远 get 不到（详见 01） |
| 2 | 为什么 String 哈希乘数是 31？ | 奇素数防低位信息丢失，且 JVM 可优化为 `(h<<5)-h`（详见 01） |
| 3 | 扰动函数 `h^(h>>>16)` 的意义？ | 下标计算只用低位，异或把高位信息混入，减少碰撞（详见 02） |
| 4 | 树化阈值 8 哪来的？ | 装载因子 0.75 下泊松分布 P(链表到 8) < 1e-8，出现即视为恶意/劣质输入（详见 02） |
| 5 | 扩容为什么不用重算 hash？ | 容量是 2 的幂，`hash & oldCap == 0` 原位，否则原位+oldCap（详见 02） |
| 6 | CHM 并发度是多少？ | JDK 8 起等于桶数（JDK 7 固定 16）：空桶 CAS、非空桶锁头节点（详见 04） |
| 7 | HashDoS 怎么防？ | JDK 红黑树化兜底 + 随机化种子；应用层：DTO 代替 Map 接参、限流（详见 05） |
| 8 | 一致性哈希为什么防雪崩？ | 取模分片节点变化全量重排；哈希环只影响相邻区间约 1/n 数据（详见 06） |
| 9 | 布隆过滤器会不会漏判？ | 不会漏判（假阴性=0），只可能误判（假阳性>0），且不可删除（详见 06） |
| 10 | 密码存储为什么不能用 MD5？ | MD5/SHA 设计目标是快，GPU 每秒数十亿次可秒破；密码哈希必须慢：Argon2id/bcrypt（详见 07） |
