## 1. 泛型基础

### 1.1 为什么需要泛型？

```java
/**
 * 泛型引入前（JDK 1.4 及以前）
 */
public class WithoutGenerics {
    public static void main(String[] args) {
        List list = new ArrayList();
        list.add("Hello");
        list.add(123);          // 可以放任意类型
        list.add(new Object());

        // 取出时必须强制类型转换
        String str = (String) list.get(0); // ✅
        // String str2 = (String) list.get(1); // ❌ ClassCastException
    }
}

/**
 * 泛型引入后（JDK 5+）
 * 优点：
 * 1. 类型安全：编译期检查
 * 2. 消除强制类型转换
 * 3. 编译期就能发现问题
 */
public class WithGenerics {
    public static void main(String[] args) {
        List<String> list = new ArrayList<>();
        list.add("Hello");
        // list.add(123); // ❌ 编译不通过

        String str = list.get(0); // 不需要强转
    }
}
```

```java
 * 泛型方法

        String middle = GenericMethod.getMiddle("A", "B", "C");
        // 或者显式指定类型

    }
```

## 2. 类型擦除与桥接方法

### 2.1 类型擦除 (Type Erasure)

```
泛型信息只在编译期存在，运行时被擦除为 Raw Type

编译前：                    编译后（擦除后）：
  List<String>       →      List (raw type)
  List<Integer>      →      List (raw type)
  Box<String>        →      Box<Object> (T → Object)
  Box<? extends Comparable> → Box<Comparable> (有边界时 → 边界)
```

```java
/**
 * 类型擦除验证
 */
public class TypeErasureDemo {
    public static void main(String[] args) {
        List<String> strings = new ArrayList<>();
        List<Integer> integers = new ArrayList<>();

        // 运行时泛型类型信息被擦除
        System.out.println(strings.getClass() == integers.getClass());
        // true — 都是 ArrayList.class

        // 反射可以绕过泛型检查（危险）
        try {
            // 泛型擦除后，底层是 Object[]
            strings.getClass().getMethod("add", Object.class)
                    .invoke(strings, 123);  // 可以添加 Integer!
            System.out.println(strings); // [123] — 运行良好

            // 但取出来时就会出问题
            for (String s : strings) { // ❌ ClassCastException
                System.out.println(s.length());
            }
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
```

### 2.2 桥接方法 (Bridge Method)

```java
/**
 * 桥接方法（JVM 自动生成）
 *
 * 场景：子类重写泛型父类的方法时
 * 目的：保持多态（子类具体类型的方法和父类泛型方法签名不同）
 */
public class BridgeMethodDemo {
    static class Node<T> {
        private T data;

        public void setData(T data) {
            this.data = data;
        }
    }

    static class StringNode extends Node<String> {
        @Override
        public void setData(String data) {
            System.out.println("StringNode.setData: " + data);
            super.setData(data);
        }
    }

    public static void main(String[] args) throws Exception {
        // 查看 StringNode 的字节码
        for (Method m : StringNode.class.getDeclaredMethods()) {
            System.out.println(m.toGenericString());
        }
        // 输出（实际有两个方法）：
        // public void BridgeMethodDemo$StringNode.setData(java.lang.String)  ← 我们写的
        // public void BridgeMethodDemo$StringNode.setData(java.lang.Object)  ← 桥接方法

        // 桥接方法的作用：保持多态
        // 当通过父类引用调用时：
        Node<String> node = new StringNode();
        node.setData("hello");  // 实际调用桥接方法 → 再调用 String 版本
    }
}
```

## 3. 通配符与 PECS

### 3.1 通配符类型

```java
/**
 * 通配符三种形式
 *
 * 1. 无界通配符: ?          — 表示任意类型
 * 2. 上界通配符: ? extends T — 可以是 T 或 T 的子类（协变）
 * 3. 下界通配符: ? super T   — 可以是 T 或 T 的父类（逆变）
 */
public class WildcardDemo {
    // 1. 无界通配符
    // 适用：只读操作，不关心具体类型
    public static void printList(List<?> list) {
        // 只能读取（用 Object 接收）
        for (Object obj : list) {
            System.out.println(obj);
        }
        // 不能写入（除了 null）
        // list.add("hello"); // ❌ 编译错误
    }

    // 2. 上界通配符 — 生产者 (Producer Extends)
    // 适用：从集合中读取数据
    public static double sumOfList(List<? extends Number> list) {
        double sum = 0.0;
        for (Number n : list) {
            sum += n.doubleValue(); // 可以调用 Number 的方法
        }
        // 不能写入（除了 null）
        // list.add(42); // ❌
        return sum;
    }

    // 3. 下界通配符 — 消费者 (Consumer Super)
    // 适用：向集合中写入数据
    public static void addNumbers(List<? super Integer> list) {
        // 可以写入 Integer 或子类
        list.add(1);    // int → Integer
        list.add(2);
        // 读取时只能用 Object 接收
        // Integer i = list.get(0); // ❌ 不能保证是 Integer
        Object obj = list.get(0); // ✅
    }

    public static void main(String[] args) {
        // 协变: List<Integer> 是 List<? extends Number> 的子类型
        List<Integer> ints = List.of(1, 2, 3);
        sumOfList(ints); // ✅

        // 逆变: List<Number> 是 List<? super Integer> 的子类型
        List<Number> nums = new ArrayList<>();
        addNumbers(nums); // ✅
    }
}
```

### 3.2 PECS 原则

```java
/**
 * PECS: Producer Extends, Consumer Super
 *
 * 口诀：
 * - 读取数据（生产者）→ ? extends T
 * - 写入数据（消费者）→ ? super T
 * - 既读又写 → 直接使用 T（不用通配符）
 *
 * Java Collections 中的应用：
 */
public class PECSDemo {
    // Collections.copy 源码
    public static <T> void copy(List<? super T> dest, List<? extends T> src) {
        // dest: 消费者（写入 T）→ ? super T
        // src: 生产者（读取 T）→ ? extends T
        for (int i = 0; i < src.size(); i++) {
            dest.set(i, src.get(i));
        }
    }

    // Collections.sort 源码
    public static <T extends Comparable<? super T>> void sort(List<T> list) {
        // T 必须实现 Comparable<T> 或 Comparable 的父类
    }

    // 实际应用
    public static void main(String[] args) {
        List<Number> dest = new ArrayList<>();
        List<Integer> src = List.of(1, 2, 3);

        // dest 需要写入 Integer → ? super Integer → List<Number> 符合
        // src 需要读取 Integer → ? extends Integer → List<Integer> 符合
        copy(dest, src);
    }
}
```

## 4. 泛型限制与最佳实践

### 4.1 泛型的限制

```java
/**
 * 泛型的六种限制
 */
public class GenericRestrictions {

    // 1. 不能使用基本类型
    // List<int> list;    // ❌ 编译错误
    List<Integer> list;    // ✅ 必须用包装类

    // 2. 不能创建泛型数组
    // T[] arr = new T[10]; // ❌
    @SuppressWarnings("unchecked")
    T[] createArray(int size) {
        return (T[]) new Object[size]; // ✅ 强制转换
    }

    // 3. 不能 instanceof 参数化类型
    public void checkType(Object obj) {
        // if (obj instanceof List<String>) // ❌
        if (obj instanceof List<?>) { // ✅ 无界通配符
            List<?> list = (List<?>) obj;
        }
    }

    // 4. 不能 new 泛型对象
    public <T> T createInstance(Class<T> clazz) throws Exception {
        // return new T();    // ❌
        return clazz.getDeclaredConstructor().newInstance(); // ✅
    }

    // 5. 静态字段不能使用类型参数
    // static T staticField; // ❌

    // 6. 泛型类不能用于异常
    // class MyException<T> extends Exception { } // ❌
}
```

### 4.2 泛型最佳实践

```java
/**
 * 泛型最佳实践
 */
public class GenericBestPractice {

    // ✅ 良好命名：E (Element), K (Key), V (Value), T (Type), R (Result)
    interface Repository<K, V> {
        V findById(K id);
        List<V> findAll();
    }

    // ✅ 使用多重边界
    public static <T extends Comparable<T> & Serializable>
    void sortAndSerialize(List<T> list) {
        Collections.sort(list);      // Comparable
        // serialize(list);          // Serializable
    }

    // ❌ 避免无意义的泛型
    // public static <T> T identity(T t) { return t; }
    // 直接用 Object 即可

    // ✅ 用通配符提高 API 灵活性
    public static void addAll(List<? super Integer> dest, List<? extends Integer> src) {
        for (Integer i : src) {
            dest.add(i);
        }
    }

    // ✅ 泛型辅助类（类型安全的异构容器）
    public static class TypeSafeMap {
        private final Map<Class<?>, Object> map = new HashMap<>();

        public <T> void put(Class<T> type, T value) {
            map.put(type, value);
        }

        @SuppressWarnings("unchecked")
        public <T> T get(Class<T> type) {
            return (T) map.get(type);
        }

        // 使用
        public static void main(String[] args) {
            TypeSafeMap map = new TypeSafeMap();
            map.put(String.class, "hello");
            map.put(Integer.class, 42);

            String str = map.get(String.class); // 不需要强转
            Integer num = map.get(Integer.class);
        }
    }
}
```

### 5.1 数据结构

```
  │  │ Object[] elementData                      │  │
  │  │ [0] [1] [2] [3] [4] [5] [6] ... [n-1]   │  │

```

### 5.2 核心源码

```java
/**
 * ArrayList 核心源码解析 (JDK 8-17 大同小异)
 */
public class ArrayListSourceAnalysis {

    // ========== 1. 常量定义 ==========
    private static final int DEFAULT_CAPACITY = 10;           // 默认初始容量
    private static final Object[] EMPTY_ELEMENTDATA = {};      // 空实例
    private static final Object[] DEFAULTCAPACITY_EMPTY_ELEMENTDATA = {}; // 默认空
    transient Object[] elementData;  // 非序列化，存储元素
    private int size;                // 元素个数

    // ========== 2. 构造器 ==========
    // 无参构造：初始化为空数组（延迟分配）
    public ArrayList() {
        this.elementData = DEFAULTCAPACITY_EMPTY_ELEMENTDATA;
    }

    // 指定容量：创建对应大小的数组
    public ArrayList(int initialCapacity) {
        if (initialCapacity > 0) {
            this.elementData = new Object[initialCapacity];
        } else if (initialCapacity == 0) {
            this.elementData = EMPTY_ELEMENTDATA;
        } else {
            throw new IllegalArgumentException();
        }
    }

    // ========== 3. add() 方法 ==========
    public boolean add(E e) {
        // 确保容量（如果不够则扩容）
        ensureCapacityInternal(size + 1);  // modCount 在这里被修改
        elementData[size++] = e;           // 尾部插入
        return true;
    }

    // 在指定位置插入
    public void add(int index, E element) {
        rangeCheckForAdd(index);           // 检查索引
        ensureCapacityInternal(size + 1);  // 确保容量
        // 复制 [index, size-index) 的元素到 [index+1, size-index)
        System.arraycopy(elementData, index, elementData, index + 1,
                         size - index);
        elementData[index] = element;
        size++;
    }

    // ========== 4. 扩容机制 ==========
    private void ensureCapacityInternal(int minCapacity) {
        // 如果是首次添加（空数组），取默认容量 10 和 minCapacity 的最大值
        if (elementData == DEFAULTCAPACITY_EMPTY_ELEMENTDATA) {
            minCapacity = Math.max(DEFAULT_CAPACITY, minCapacity);
        }
        ensureExplicitCapacity(minCapacity);
    }

    private void ensureExplicitCapacity(int minCapacity) {
        modCount++;  // 结构性修改计数
        // 如果需要的容量 > 当前数组长度，扩容
        if (minCapacity - elementData.length > 0)
            grow(minCapacity);
    }

    // ⭐ 扩容核心
    private void grow(int minCapacity) {
        int oldCapacity = elementData.length;
        // JDK 6: (oldCapacity * 3/2 + 1)
        // JDK 7+: oldCapacity + (oldCapacity >> 1) = 1.5 倍
        int newCapacity = oldCapacity + (oldCapacity >> 1);

        if (newCapacity - minCapacity < 0)
            newCapacity = minCapacity;          // 取所需的最小值
        if (newCapacity - MAX_ARRAY_SIZE > 0)
            newCapacity = hugeCapacity(minCapacity);  // 处理大数组

        // 创建新数组并复制（⚠️ 主要性能开销）
        elementData = Arrays.copyOf(elementData, newCapacity);
    }

    // ========== 5. get() ==========
    public E get(int index) {
        rangeCheck(index);                    // 检查索引 < size
        return elementData(index);            // O(1) 随机访问
    }

    // ========== 6. remove() ==========
    public E remove(int index) {
        rangeCheck(index);
        modCount++;
        E oldValue = elementData(index);

        int numMoved = size - index - 1;
        if (numMoved > 0)
            // 向前移动元素 ⚠️ 删除中间元素是 O(n)
            System.arraycopy(elementData, index+1, elementData, index,
                             numMoved);
        elementData[--size] = null;  // 让 GC 可以回收

        return oldValue;
    }

    // 按对象删除
    public boolean remove(Object o) {
        // 遍历查找 → O(n)
        if (o == null) {
            for (int index = 0; index < size; index++)
                if (elementData[index] == null) {
                    fastRemove(index);
                    return true;
                }
        } else {
            for (int index = 0; index < size; index++)
                if (o.equals(elementData[index])) {
                    fastRemove(index);
                    return true;
                }
        }
        return false;
    }

    // ========== 7. 快速失败 (fail-fast) ==========
    // modCount 在迭代器中使用
    // 如果在迭代过程中 modCount 发生变化 → ConcurrentModificationException
    // 这不是线程安全的保障，而是 bug 检测机制

    // ========== 8. 性能分析 ==========
    // 操作     时间复杂度   说明
    // get(i)   O(1)        数组随机访问
    // add(e)   O(1) 均摊    尾部插入（可能扩容）
    // add(i,e) O(n)        需要移动元素
    // remove(i) O(n)       需要移动元素
    // contains O(n)        线性查找
}
```

### 5.3 扩容对比 (JDK 6 vs JDK 7+)

| 版本 | 扩容公式 | 说明 |
|------|---------|------|
| JDK 6 | `(oldCapacity * 3/2) + 1` | 乘 1.5 再加 1 |
| JDK 7+ | `oldCapacity + (oldCapacity >> 1)` | 位运算高效 1.5 倍 |

### 5.4 ArrayList vs LinkedList

| 特性 | ArrayList | LinkedList |
|------|-----------|------------|
| 底层结构 | 动态数组 | 双向链表 |
| get(i) | O(1) | O(n) |
| add(e) | O(1) 均摊 | O(1) |
| add(i,e) | O(n) | O(n) |
| remove(i) | O(n) | O(n) |
| 内存占用 | 更小（只有数组） | 更大（Node 对象） |
| 适用场景 | 随机访问多 | 频繁插入删除头部/尾部 |

## 6. LinkedList 源码深度解析

```java
/**
 * LinkedList 核心源码解析
 *
 * 双向链表结构：
 *  ┌──────────┐    ┌──────────┐    ┌──────────┐
 *  │    Node   │    │    Node   │    │    Node   │
 *  │ prev ────┼───▶│ prev ────┼───▶│ prev     │
 *  │ item     │    │ item     │    │ item     │
 *  │ next ────┼───▶│ next ────┼───▶│ next null│
 *  └──────────┘    └──────────┘    └──────────┘
 *       ↑                               ↑
 *     first                            last
 */
public class LinkedListSourceAnalysis {
    // 节点结构
    private static class Node<E> {
        E item;         // 数据
        Node<E> next;   // 后继
        Node<E> prev;   // 前驱

        Node(Node<E> prev, E element, Node<E> next) {
            this.item = element;
            this.next = next;
            this.prev = prev;
        }
    }

    transient int size = 0;
    transient Node<E> first;  // 头节点
    transient Node<E> last;   // 尾节点

    // ========== 头部插入 ==========
    private void linkFirst(E e) {
        final Node<E> f = first;
        final Node<E> newNode = new Node<>(null, e, f);
        first = newNode;
        if (f == null)
            last = newNode;     // 原来是空链表
        else
            f.prev = newNode;   // 原头节点的 prev 指向新节点
        size++;
        modCount++;
    }

    // ========== 尾部插入 ==========
    private void linkLast(E e) {
        final Node<E> l = last;
        final Node<E> newNode = new Node<>(l, e, null);
        last = newNode;
        if (l == null)
            first = newNode;
        else
            l.next = newNode;
        size++;
        modCount++;
    }

    // ========== 中间位置插入 ==========
    void linkBefore(E e, Node<E> succ) {
        // 在 succ 节点之前插入
        final Node<E> pred = succ.prev;
        final Node<E> newNode = new Node<>(pred, e, succ);
        succ.prev = newNode;
        if (pred == null)
            first = newNode;
        else
            pred.next = newNode;
        size++;
        modCount++;
    }

    // ========== 按索引查找 ==========
    // ⚠️ 二分查找优化：根据 index 靠近头还是尾决定遍历方向
    Node<E> node(int index) {
        if (index < (size >> 1)) {
            // 前半部分 → 从头向后遍历
            Node<E> x = first;
            for (int i = 0; i < index; i++)
                x = x.next;
            return x;
        } else {
            // 后半部分 → 从尾向前遍历
            Node<E> x = last;
            for (int i = size - 1; i > index; i--)
                x = x.prev;
            return x;
        }
    }
}
```

## 7. HashMap 源码深度解析 (JDK 8)

### 7.1 数据结构总览

```
JDK 8 HashMap 结构：

┌─────────────────────────────────────────────┐
│ Node<K,V>[] table (桶数组)                    │
├──────┬──────┬──────┬────────┬──────┬────────┤
│ 0    │ 1    │ 2    │ ...    │ n-2  │ n-1    │
├──────┼──────┼──────┼────────┼──────┼────────┤
│ null │ Node │ null │ Node   │ null │ Node   │ ← 链表 > 8 → 红黑树
│      ├──K───┤      ├──K─────┤      ├──K─────┤
│      │  V   │      │  V     │      │  V     │
│      │ next─┼──▶   │  ▓     │      │  ▓     │
│      └──────┘      │  ▓     │      │  ▓     │
│                    │  ▓     │      │  ▓     │
│                    └────────┘      └────────┘
└─────────────────────────────────────────────┘

关键参数：
  DEFAULT_INITIAL_CAPACITY = 16    — 默认初始容量（必须是 2 的幂）
  DEFAULT_LOAD_FACTOR = 0.75f      — 负载因子
```

### 7.3 hash() 函数 —— 扰动函数

```java
/**
 * ⭐ HashMap 的 hash 函数
 *
 * 为什么要 (h = key.hashCode()) ^ (h >>> 16)？
 *
 * 1. hashCode() 可能设计得不好（高位没区别）
 * 2. 下标计算只用到低位：(n - 1) & hash
 * 3. 如果两个 key 的高 16 位不同但低 16 位相同，容易碰撞
 * 4. 把高 16 位异或到低 16 位，让高位也参与下标计算
 */
static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}

// 示例：
// hashCode:   0x12345678
// h >>> 16:   0x00001234
// XOR:        0x1234464C  ← 高位信息混合到低位

// 下标计算（扩容时也相同）：
// index = (n - 1) & hash
// 当 n=16: index = 0x0FFF & hash = 保留低 12 位
// 这个 & 运算的结果只取决于 hash 的低位
```

### 7.4 put() 完整流程

```java
/**
 * put(K key, V value) 完整流程 (JDK 8)
 */
final V putVal(int hash, K key, V value, boolean onlyIfAbsent,
               boolean evict) {
    Node<K,V>[] tab; Node<K,V> p; int n, i;

    // 步骤 1: 首次 put 时初始化数组 (延迟初始化)
    if ((tab = table) == null || (n = tab.length) == 0)
        n = (tab = resize()).length;

    // 步骤 2: 计算下标 (n-1)&hash，如果该桶为空直接放入
    //        i = (n - 1) & hash
    if ((p = tab[i = (n - 1) & hash]) == null)
        tab[i] = newNode(hash, key, value, null);
    else {
        // 步骤 3: 桶不为空 → 处理冲突
        Node<K,V> e; K k;

        // 3a: 第一个节点 key 相同 → 直接替换
        if (p.hash == hash &&
            ((k = p.key) == key || (key != null && key.equals(k))))
            e = p;
        // 3b: 红黑树节点 → 树插入
        else if (p instanceof TreeNode)
            e = ((TreeNode<K,V>)p).putTreeVal(this, tab, hash, key, value);
        else {
            // 3c: 链表 → 遍历
            for (int binCount = 0; ; ++binCount) {
                // 到达链表尾部 → 追加新节点
                if ((e = p.next) == null) {
                    p.next = newNode(hash, key, value, null);
                    // 如果链表长度 >= 8 → 尝试树化
                    if (binCount >= TREEIFY_THRESHOLD - 1)
                        treeifyBin(tab, hash);
                    break;
                }
                // 找到相同 key → 跳出替换
                if (e.hash == hash &&
                    ((k = e.key) == key || (key != null && key.equals(k))))
                    break;
                p = e;
            }
        }

        // 步骤 4: 如果是替换（已存在的 key）
        if (e != null) {
            V oldValue = e.value;
            if (!onlyIfAbsent || oldValue == null)
                e.value = value;        // 替换值
            afterNodeAccess(e);
            return oldValue;
        }
    }

    // 步骤 5: 结构调整次数 +1
    ++modCount;

    // 步骤 6: 检查是否需要扩容
    if (++size > threshold)
        resize();

    afterNodeInsertion(evict);
    return null;
}
```

### 7.5 resize() —— 扩容机制

```java
/**
 * ⭐ 扩容机制 (JDK 8 优化)
 *
 * JDK 7 的扩容问题：
 * - 头插法：多线程下可能产生循环链表（死循环）
 * - 需要重新计算 hash（耗时）
 *
 * JDK 8 的优化：
 * - 尾插法：避免循环链表
 * - 不需要重新计算 hash：利用 2 次幂扩容的特性
 */

final Node<K,V>[] resize() {
    Node<K,V>[] oldTab = table;
    int oldCap = (oldTab == null) ? 0 : oldTab.length;
    int oldThr = threshold;
    int newCap, newThr = 0;

    // 计算新容量
    if (oldCap > 0) {
        if (oldCap >= MAXIMUM_CAPACITY) {
            threshold = Integer.MAX_VALUE;
            return oldTab;
        }
        // 新容量 = 旧容量 * 2
        else if ((newCap = oldCap << 1) < MAXIMUM_CAPACITY &&
                 oldCap >= DEFAULT_INITIAL_CAPACITY)
            newThr = oldThr << 1; // 阈值也翻倍
    }
    else if (oldThr > 0)
        newCap = oldThr;           // 从带参数的构造器初始化
    else {
        // 默认值
        newCap = DEFAULT_INITIAL_CAPACITY;
        newThr = (int)(DEFAULT_LOAD_FACTOR * DEFAULT_INITIAL_CAPACITY);
    }

    // ... 创建新数组
    @SuppressWarnings({"unchecked"})
    Node<K,V>[] newTab = (Node<K,V>[])new Node[newCap];
    table = newTab;

    // ⭐ JDK 8 优化：数据迁移
    if (oldTab != null) {
        for (int j = 0; j < oldCap; ++j) {
            Node<K,V> e;
            if ((e = oldTab[j]) != null) {
                oldTab[j] = null;  // 让 GC 回收

                // 情况 1: 单个节点 → 直接计算新下标
                if (e.next == null)
                    newTab[e.hash & (newCap - 1)] = e;

                // 情况 2: 红黑树
                else if (e instanceof TreeNode)
                    ((TreeNode<K,V>)e).split(this, newTab, j, oldCap);

                // 情况 3: 链表 ⭐ JDK 8 优化
                else {
                    // 关键规律：
                    // 容量翻倍后，元素要么在原位置，要么在原位置 + oldCap
                    // 判断依据：e.hash & oldCap == 0 → 在原位置
                    //                        != 0 → 在原位置 + oldCap

                    Node<K,V> loHead = null, loTail = null; // 低位链表(原位)
                    Node<K,V> hiHead = null, hiTail = null; // 高位链表(原位+oldCap)

                    do {
                        Node<K,V> next = e.next;
                        if ((e.hash & oldCap) == 0) {
                            // 在原位置
                            if (loTail == null)
                                loHead = e;
                            else
                                loTail.next = e;
                            loTail = e;
                        } else {
                            // 在原位置 + oldCap
                            if (hiTail == null)
                                hiHead = e;
                            else
                                hiTail.next = e;
                            hiTail = e;
                        }
                        e = next;
                    } while (e != null);

                    // 保持原来的顺序（尾插法）
                    if (loTail != null) {
                        loTail.next = null;
                        newTab[j] = loHead;           // 低位
                    }
                    if (hiTail != null) {
                        hiTail.next = null;
                        newTab[j + oldCap] = hiHead;  // 高位
                    }
                }
            }
        }
    }
    return newTab;
}

/**
 * JDK 8 resize 优化举例：
 * 扩容前：容量 16，hash=5 的元素放在 index=5
 * 扩容后：容量 32
 *   hash=5: 5 & 31 = 5   → 还在 index=5  (原位置)
 *   hash=21: 21 & 31 = 21 → index=21 (原位置+16)
 *   hash=37: 37 & 31 = 5  → index=5  (原位置, 因为 37&16=0)
 *   hash=53: 53 & 31 = 21 → index=21 (原位置+16, 因为 53&16=16)
 *
 * 规律：只用看 hash & oldCap (16)
 *   =0: 原位
 *   =16: 原位+16
 */
```

### 7.6 get() 流程

```java
/**
 * get() 流程 — O(1) 平均，最坏 O(log n)
 */
public V get(Object key) {
    Node<K,V> e;
    return (e = getNode(hash(key), key)) == null ? null : e.value;
}

final Node<K,V> getNode(int hash, Object key) {
    Node<K,V>[] tab; Node<K,V> first, e; int n; K k;

    if ((tab = table) != null && (n = tab.length) > 0 &&
        (first = tab[(n - 1) & hash]) != null) {
        // 1. 检查第一个节点
        if (first.hash == hash &&
            ((k = first.key) == key || (key != null && key.equals(k))))
            return first;

        // 2. 遍历链表或红黑树
        if ((e = first.next) != null) {
            if (first instanceof TreeNode)
                // 红黑树 → O(log n)
                return ((TreeNode<K,V>)first).getTreeNode(hash, key);
            do {
                // 链表 → O(n)，但平均很短
                if (e.hash == hash &&
                    ((k = e.key) == key || (key != null && key.equals(k))))
                    return e;
            } while ((e = e.next) != null);
        }
    }
    return null;
}
```

### 7.7 HashMap 为什么不是线程安全的

```java
/**
 * JDK 7: 并发 put → 环形链表 → get 死循环
 * JDK 8: 尾插法避免了环形链表，但仍然有数据丢失问题
 */
public class HashMapThreadSafeIssue {
    public static void main(String[] args) throws Exception {
        // JDK 8 中的问题：数据丢失
        Map<Integer, Integer> map = new HashMap<>();
        final int THREADS = 10;
        final int COUNT = 1000;

        // 多线程并发 put
        ExecutorService executor = Executors.newFixedThreadPool(THREADS);
        CountDownLatch latch = new CountDownLatch(THREADS);

        for (int i = 0; i < THREADS; i++) {
            int threadId = i;
            executor.submit(() -> {
                for (int j = 0; j < COUNT; j++) {
                    map.put(threadId * COUNT + j, j);
                }
                latch.countDown();
            });
        }

        latch.await();
        executor.shutdown();

        // 期望 size = THREADS * COUNT = 10000
        // 实际 size < 10000 (数据丢失)
        System.out.println("Expected size: " + (THREADS * COUNT));
        System.out.println("Actual size: " + map.size());
    }
}
```

### 8.2 JDK 8 put 流程

```java
/**
 * ConcurrentHashMap.put() JDK 8
 *
 * 锁粒度：每个桶（Node 数组的一个位置）
 * 锁方案：CAS（空桶） + synchronized（非空桶的链表/树头节点）
 */
final V putVal(K key, V value, boolean onlyIfAbsent) {
    if (key == null || value == null) throw new NullPointerException();
    int hash = spread(key.hashCode());
    int binCount = 0;

    for (Node<K,V>[] tab = table;;) {
        Node<K,V> f; int n, i, fh; K fk; V fv;

        // 1. 延迟初始化（CAS 保证线程安全）
        if (tab == null || (n = tab.length) == 0)
            tab = initTable();

        // 2. 空桶 → CAS 放入（无锁）
        else if ((f = tabAt(tab, i = (n - 1) & hash)) == null) {
            // ⭐ CAS 操作：比较当前值是否为 null，是则放入
            if (casTabAt(tab, i, null, new Node<K,V>(hash, key, value)))
                break;
        }

        // 3. 正在扩容 → 帮忙迁移（ForwardingNode）
        else if ((fh = f.hash) == MOVED)
            tab = helpTransfer(tab, f);

        // 4. 桶非空 → 加锁（只锁桶的头节点！）
        else {
            V oldVal = null;
            synchronized (f) {       // ⭐ 细粒度锁：只锁链表/树的头节点
                if (tabAt(tab, i) == f) {  // 双重检查
                    if (fh >= 0) {
                        // 链表操作（同 HashMap）
                        binCount = 1;
                        for (Node<K,V> e = f;; ++binCount) {
                            if (e.hash == hash &&
                                ((ek = e.key) == key || ek.equals(key))) {
                                oldVal = e.val;
                                if (!onlyIfAbsent)
                                    e.val = value;
                                break;
                            }
                            Node<K,V> pred = e;
                            if ((e = e.next) == null) {
                                pred.next = new Node<K,V>(hash, key, value);
                                break;
                            }
                        }
                    } else if (f instanceof TreeBin) {
                        // 红黑树操作
                        ...
                    }
                }
            }

            // 5. 链表过长 → 树化
            if (binCount >= TREEIFY_THRESHOLD)
                treeifyBin(tab, i);
            if (oldVal != null)
                return oldVal;
        }
    }

    // 6. 计数
    addCount(1L, binCount);
    return null;
}
```

### 8.3 sizeCtl 核心

```java
/**
 * sizeCtl — 多用途控制字段
 *
 * -1:      正在初始化
 * -N:      N-1 个线程在进行扩容
 * >0:      扩容阈值 (capacity * loadFactor)
 * >0 且 table 正在扩容: 扩容完成后的新容量
 */
private transient volatile int sizeCtl;

private final Node<K,V>[] initTable() {
    Node<K,V>[] tab; int sc;
    while ((tab = table) == null || tab.length == 0) {
        if ((sc = sizeCtl) < 0)
            // 其他线程已经在初始化 → 让出 CPU
            Thread.yield();
        else if (U.compareAndSetInt(this, SIZECTL, sc, -1)) {
            // CAS 将 sizeCtl 设为 -1 → 当前线程获得初始化权
            try {
                if ((tab = table) == null || tab.length == 0) {
                    int n = (sc > 0) ? sc : DEFAULT_CAPACITY;
                    @SuppressWarnings("unchecked")
                    Node<K,V>[] nt = (Node<K,V>[])new Node<?,?>[n];
                    table = tab = nt;
                    sc = n - (n >>> 2);   // sc = 0.75n
                }
            } finally {
                sizeCtl = sc;  // 设为扩容阈值
            }
            break;
        }
    }
    return tab;
}
```

## 9. LinkedHashMap 与 TreeMap

### 9.1 LinkedHashMap

```java
/**
 * LinkedHashMap = HashMap + 双向链表
 *
 * 维持两种顺序：
 * 1. 插入顺序（默认）：迭代顺序与插入顺序一致
 * 2. 访问顺序：每次访问将元素移到尾部（适合 LRU 缓存）
 */
public class LinkedHashMapDemo {
    public static void main(String[] args) {
        // 插入顺序
        LinkedHashMap<String, Integer> insertionOrder = new LinkedHashMap<>();
        insertionOrder.put("c", 3);
        insertionOrder.put("a", 1);
        insertionOrder.put("b", 2);
        System.out.println(insertionOrder.keySet()); // [c, a, b] 保持插入顺序

        // 访问顺序（LRU Cache）
        LinkedHashMap<String, Integer> accessOrder = new LinkedHashMap<>(
                16, 0.75f, true   // accessOrder=true
        );
        accessOrder.put("c", 3);
        accessOrder.put("a", 1);
        accessOrder.put("b", 2);

        accessOrder.get("a");       // 访问 a → a 移到最后
        accessOrder.get("c");       // 访问 c → c 移到最后
        System.out.println(accessOrder.keySet()); // [b, a, c] 最近访问的在最后

        // 实现 LRU 缓存：重写 removeEldestEntry
        LinkedHashMap<String, Integer> lruCache = new LinkedHashMap<>(
                16, 0.75f, true
        ) {
            @Override
            protected boolean removeEldestEntry(Map.Entry<String, Integer> eldest) {
                // 当缓存超过 3 个元素时，移除最老的
                return size() > 3;
            }
        };

        lruCache.put("a", 1);
        lruCache.put("b", 2);
        lruCache.put("c", 3);
        System.out.println(lruCache.keySet()); // [a, b, c]
        lruCache.put("d", 4);     // 触发移除最老的 a
        System.out.println(lruCache.keySet()); // [b, c, d]
        lruCache.get("b");        // b 移到末尾
        System.out.println(lruCache.keySet()); // [c, d, b]
    }
}
```

## 10. 面试经典问题

### 基础问题

**Q1: HashMap 的 put 流程？**
- 计算 hash → 计算下标 → 空桶直接放 → 非空桶遍历链表/树 → 找到替换 → 未找到追加 → 检查树化 → 检查扩容

**Q2: hash 函数为什么是 (h ^ (h >>> 16))？**
- 让高位也参与低位的下标计算，减少碰撞

**Q3: HashMap 为什么容量是 2 的幂？**
- 下标计算：`(n - 1) & hash` 等价于取模，但更快
- 扩容时元素要么在原位置要么在原位置+oldCap，不需要重新计算 hash

**Q4: 链表转红黑树的阈值为什么是 8？**
- 泊松分布计算：负载因子 0.75 下，链表长度到 8 的概率 < 千万分之一
- 8 是时间和空间的平衡点

### 进阶问题

**Q5: HashMap 和 ConcurrentHashMap 的区别？**
- HashMap 线程不安全；ConcurrentHashMap 线程安全
- JDK 8 CHM：CAS + synchronized（桶锁），支持多线程扩容

**Q6: ConcurrentHashMap JDK 7 和 JDK 8 的区别？**
- JDK 7：Segment（继承 ReentrantLock），并发度固定 16
- JDK 8：Node + CAS + synchronized，并发度 = 桶数

**Q7: ArrayList 的扩容机制？**
- 默认容量 10（延迟分配）
- 每次扩容 1.5 倍：`oldCapacity + (oldCapacity >> 1)`
- 使用 Arrays.copyOf 创建新数组

**Q8: 什么是 fail-fast 机制？**
- modCount 在迭代器中使用
- 迭代过程中检测到 modCount 变化 → ConcurrentModificationException
- 不是线程安全的保障，而是 bug 检测

**Q9: 什么是 PECS 原则？**
- Producer Extends：读取用 ? extends T
- Consumer Super：写入用 ? super T

**Q10: 类型擦除是什么？桥接方法是什么？**
- 泛型信息编译后擦除为原始类型
- 桥接方法由编译器自动生成，保持多态
