## 1. 基础知识

### 1.1 高并发 IO 的底层原理

| 知识点 | 说明 |
|--------|------|
| BIO（阻塞 IO） | 一连接一线程，资源消耗大 |
| NIO（非阻塞 IO） | 多路复用，少量线程处理大量连接 |
| AIO（异步 IO） | 回调机制，完全异步 |

### 1.2 Java NIO 核心详解

| 组件 | 作用 |
|------|------|
| `Buffer` | 数据容器，读写双向 |
| `Channel` | 数据传输通道 |
| `Selector` | 多路复用器，一个线程管理多个 Channel |

## 2. 网络编程核心

### 2.1 Reactor 模式

| 模式变体 | 说明 |
|----------|------|
| 单线程 Reactor | 一个线程处理所有事件 |
| 多线程 Reactor | Handler 线程池处理业务 |
| 主从 Reactor | Acceptor + Worker 分离 |

### 2.2 Netty 核心原理与基础实战

| 知识点 | 说明 |
|--------|------|
| `EventLoop` | 事件循环，Reactor 模式的实现 |
| `ChannelPipeline` | 责任链模式处理 IO 事件 |
| `Bootstrap` | 客户端/服务端启动引导 |

### 2.3 Decoder 与 Encoder 核心组件

| 组件 | 方向 | 说明 |
|------|------|------|
| `Decoder` | 入站 | 字节 → 对象 |
| `Encoder` | 出站 | 对象 → 字节 |
| `Codec` | 双向 | 编解码一体 |

### 3.1 序列化与反序列化

| 方案 | 特点 | 适用场景 |
|------|------|----------|
| JSON | 可读性好，跨语言 | HTTP API、WebSocket |
| Protobuf | 体积小，速度快 | 内部 RPC、高性能场景 |

### 3.2 HTTP 原理与 Web 服务器实战

- HTTP/1.1 与 HTTP/2 协议差异
- 高并发 HTTP 通信的核心原理
- 连接池、Keep-Alive、长连接优化

### 3.3 WebSocket 原理与实战

| 特性 | 说明 |
|------|------|
| 全双工 | 服务端可主动推送 |
| 长连接 | 一次握手，持续通信 |
| 适用场景 | IM、实时推送、协作编辑 |

## 6. 学习路线建议

### 推荐顺序

```text
阶段 1：基础原理 ──────────────────────────
  ├── 高并发 IO 底层原理（BIO → NIO → AIO）
  └── Java NIO 核心组件（Buffer / Channel / Selector）
        │
        ▼
阶段 2：核心框架 ──────────────────────────
  ├── Reactor 模式（理解 Netty 的设计基础）
  └── Netty 核心原理 + 基础实战
        │
        ▼
阶段 3：序列化与协议 ──────────────────────
  ├── Decoder / Encoder 组件
  ├── JSON / Protobuf
  └── HTTP / WebSocket / SSL-TLS
        │
        ▼
阶段 4：分布式组件 ────────────────────────
  ├── ZooKeeper（分布式协调）
  └── Redis（分布式缓存）
        │
        ▼
阶段 5：实战项目 ──────────────────────────
  ├── 基于 Netty 单体 IM 系统
  └── 亿级高并发 IM 架构
```

### 各阶段目标

| 阶段 | 内容 | 预期成果 |
|------|------|----------|
| 基础原理 | IO 模型 + NIO | 理解"为什么 Netty 快" |
| 核心框架 | Reactor + Netty | 能用 Netty 写服务端/客户端 |
| 协议 | 编解码 + HTTP/WS/TLS | 能设计自定义通信协议 |
| 分布式 | ZK + Redis | 能搭建分布式基础架构 |
| 实战 | IM 系统 | 能独立完成高并发 IM 项目 |

---

> 💡 **面试重点**：NIO 原理、Reactor 模式、Netty 线程模型、Redis 缓存策略、ZK 分布式锁、IM 系统架构设计。
