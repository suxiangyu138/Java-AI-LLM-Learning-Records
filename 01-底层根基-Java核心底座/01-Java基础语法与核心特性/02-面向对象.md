## 1. 类与对象

### 1.1 类的定义

类是对具有相同属性和行为的对象的抽象，是创建对象的模板。

```java
/**
 * 用户类 --- 演示类的基本结构
 */
public class User {
    // ---------- 字段（成员变量） ----------
    private Long id;             // 实例变量（属于对象）
    private String username;
    private String email;
    private static int counter;  // 类变量（属于类，所有实例共享）

    // ---------- 构造方法 ----------
    public User() {
        // 无参构造方法（如果没定义，编译器会生成默认构造）
    }

    public User(String username, String email) {
        this.username = username;
        this.email = email;
        counter++;
    }

    // ---------- 方法 ----------
    public void displayInfo() {
        System.out.println("ID: " + id + ", Username: " + username);
    }

    public static int getCounter() {
        return counter;
    }
}
```

### 1.2 对象的创建与使用

```java
public class Main {
    public static void main(String[] args) {
        // 声明引用 + 创建对象
        User user1 = new User("alice", "alice@example.com");
        User user2 = new User("bob", "bob@example.com");

        // 调用方法
        user1.displayInfo();
        System.out.println("用户总数: " + User.getCounter());

        // 匿名对象（只用一次）
        new User("temp", "temp@example.com").displayInfo();
    }
}
```

### 1.3 构造方法详解

```java
public class Product {
    private String name;
    private double price;
    private int stock;

    // 无参构造
    public Product() {
        // 显式定义默认值
        this.name = "未命名";
        this.price = 0.0;
        this.stock = 0;
    }

    // 带参构造
    public Product(String name, double price) {
        this(name, price, 0);  // 使用 this() 调用另一个构造方法
    }

    // 全参构造
    public Product(String name, double price, int stock) {
        // 参数验证
        if (price < 0) {
            throw new IllegalArgumentException("价格不能为负数");
        }
        if (stock < 0) {
            throw new IllegalArgumentException("库存不能为负数");
        }
        this.name = name;
        this.price = price;
        this.stock = stock;
    }

    // 拷贝构造（不常用，推荐使用 Clone 或工厂方法）
    public Product(Product other) {
        this(other.name, other.price, other.stock);
    }
}
```

**构造方法要点**:
- 构造方法名必须与类名相同，没有返回值
- 如果没有定义任何构造方法，编译器生成默认无参构造
- 一旦定义了有参构造，编译器不再生成默认构造
- 构造方法可以重载
- `this()` 调用另一个构造方法必须位于第一行
- 构造方法不能被 `final`、`static`、`abstract` 修饰

### 1.4 this 关键字

```java
public class Employee {
    private String name;
    private int age;

    public Employee(String name, int age) {
        this.name = name;      // 区分成员变量和局部变量
        this.age = age;
    }

    public Employee() {
        this("默认", 0);       // 调用本类其他构造方法
    }

    public Employee getThis() {
        return this;           // 返回当前对象的引用
    }

    public void setName(String name) {
        this.name = name;
    }

    public Employee setNameAndReturn(String name) {
        this.name = name;
        return this;           // 链式调用支持
    }
}

// 链式调用
Employee emp = new Employee()
    .setNameAndReturn("张三")
    .setNameAndReturn("李四");
```

## 2. 封装（Encapsulation）

### 2.1 访问修饰符

| 修饰符 | 同类 | 同包 | 子类（不同包） | 任意 |
|--------|------|------|---------------|------|
| `private` | Y | N | N | N |
| `default`（默认） | Y | Y | N | N |
| `protected` | Y | Y | Y | N |
| `public` | Y | Y | Y | Y |

```java
package com.example;

public class AccessExample {
    private int privateField;      // 仅本类可访问
    int defaultField;              // 本包可访问
    protected int protectedField;  // 本包 + 子类可访问
    public int publicField;        // 任何地方可访问

    private void privateMethod() { }
    void defaultMethod() { }
    protected void protectedMethod() { }
    public void publicMethod() { }
}
```

### 2.2 Getter/Setter 与封装原则

```java
/**
 * 良好的封装示例
 * 阿里巴巴规范：POJO 类必须使用 getter/setter，且 boolean 类型不要加 is 前缀
 */
public class Account {
    // 字段全部私有
    private Long id;
    private String accountNo;
    private BigDecimal balance;
    private boolean active;    // 注意：布尔类型不要命名为 isActive

    // Getter/Setter
    public Long getId() {
        return id;
    }

    public void setId(Long id) {
        if (id == null || id <= 0) {
            throw new IllegalArgumentException("ID 不合法");
        }
        this.id = id;
    }

    public String getAccountNo() {
        // 返回脱敏后的数据
        return accountNo.replaceAll("(\\d{4})\\d{8}(\\d{4})", "$1****$2");
    }

    public void setAccountNo(String accountNo) {
        // 数据验证
        if (accountNo == null || !accountNo.matches("\\d{16,19}")) {
            throw new IllegalArgumentException("银行卡号格式不正确");
        }
        this.accountNo = accountNo;
    }

    public BigDecimal getBalance() {
        return balance;
    }

    // 不提供 setBalance，通过专门的方法修改
    // public void setBalance(BigDecimal balance) { this.balance = balance; }

    public boolean isActive() {    // 注意：boolean 类型用 is 开头
        return active;
    }

    public void setActive(boolean active) {
        this.active = active;
    }

    // 行为方法而非直接 setter
    public void deposit(BigDecimal amount) {
        if (amount.compareTo(BigDecimal.ZERO) <= 0) {
            throw new IllegalArgumentException("存款金额必须为正数");
        }
        this.balance = this.balance.add(amount);
    }

    public void withdraw(BigDecimal amount) {
        if (amount.compareTo(BigDecimal.ZERO) <= 0) {
            throw new IllegalArgumentException("取款金额必须为正数");
        }
        if (this.balance.compareTo(amount) < 0) {
            throw new InsufficientBalanceException("余额不足");
        }
        this.balance = this.balance.subtract(amount);
    }
}
```

**封装原则**:
1. 字段尽量私有（`private`）
2. 通过 getter/setter 访问字段，并在其中添加验证逻辑
3. 不要直接暴露内部状态（如返回内部集合的引用）
4. 优先提供行为方法而非 setter（如 `deposit()` 而非 `setBalance()`）

### 2.3 防御性拷贝

```java
public class Order {
    private List<OrderItem> items;

    public Order(List<OrderItem> items) {
        // 防御性拷贝：防止外部修改传入的集合
        this.items = new ArrayList<>(items);
    }

    public List<OrderItem> getItems() {
        // 返回不可修改的视图，防止外部修改内部状态
        return Collections.unmodifiableList(items);
    }

    public void addItem(OrderItem item) {
        // 通过专门方法修改内部状态
        this.items.add(item);
    }
}
```

## 3. 继承（Inheritance）

### 3.1 extends 关键字与单继承

Java 只支持单继承（一个类只能有一个直接父类），但支持多层继承。

```java
// 父类（基类）
public class Animal {
    protected String name;
    protected int age;

    public Animal(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public void eat() {
        System.out.println(name + " 正在进食");
    }

    public void sleep() {
        System.out.println(name + " 正在睡觉");
    }

    // 父类私有方法不能被子类继承
    private void privateMethod() {
        System.out.println("私有方法");
    }
}

// 子类（派生类）
public class Dog extends Animal {
    private String breed;  // 品种

    public Dog(String name, int age, String breed) {
        super(name, age);  // 必须调用父类构造方法（第一行）
        this.breed = breed;
    }

    // 子类特有的方法
    public void bark() {
        System.out.println(name + " 汪汪叫");
    }

    // 方法重写
    @Override
    public void eat() {
        super.eat();  // 调用父类的 eat 方法
        System.out.println(name + " 吃狗粮");
    }
}
```

**继承要点**:
- 子类通过 `extends` 继承父类
- 子类继承父类所有非 `private` 成员（字段和方法）
- 子类构造方法必须（显式或隐式）调用父类构造方法
- 如果父类没有无参构造，子类必须显式调用 `super()`
- Java 不支持多继承（一个类只能有一个父类）

### 3.2 super 关键字

```java
public class Manager extends Employee {
    private double bonus;

    public Manager(String name, double salary, double bonus) {
        super(name, salary);   // 调用父类构造方法
        this.bonus = bonus;
    }

    public double getTotalSalary() {
        return super.getSalary() + bonus;  // 调用父类方法
    }

    @Override
    public String toString() {
        // super 不能链式调用
        return super.toString() + ", bonus=" + bonus;
    }
}
```

### 3.3 方法重写（Method Overriding）

**规则**:
- 参数列表必须完全相同
- 返回值类型必须相同或是父类返回值的子类型（协变返回类型）
- 访问修饰符不能比父类更严格（可以更宽松）
- 不能抛出比父类更宽泛的异常（可以不抛或抛出子类异常）
- 父类的 `final` 方法不能被重写
- 父类的 `static` 方法不能被重写（只能隐藏）
- `@Override` 注解不是必须的，但强烈建议使用（编译器检查）

```java
public class Parent {
    public Number calculate(int x) throws IOException {
        return x * 2;
    }
}

public class Child extends Parent {
    @Override
    public Integer calculate(int x) {     // 协变返回类型：Number -> Integer
        return x * 3;                     // 不抛异常（比父类更严格）
    }
}
```

### 3.4 构造方法链

```java
class GrandParent {
    GrandParent() { System.out.println("1-GrandParent"); }
}

class Parent extends GrandParent {
    Parent() { System.out.println("2-Parent"); }
}

class Child extends Parent {
    Child() { System.out.println("3-Child"); }  // 输出 1-2-3
}
```

### 3.5 继承 vs 组合

**组合优先于继承**（Effective Java 第 18 条）：

```java
// 继承：不适合的场景
public class InstrumentedHashSet<E> extends HashSet<E> {
    private int addCount = 0;

    @Override
    public boolean add(E e) {
        addCount++;
        return super.add(e);
    }

    @Override
    public boolean addAll(Collection<? extends E> c) {
        addCount += c.size();  // 但父类的 addAll 内部调用了 add，导致重复计数
        return super.addAll(c);
    }
}

// 组合：更好的方案
public class InstrumentedSet<E> {
    private final Set<E> set;           // 组合
    private int addCount = 0;

    public InstrumentedSet(Set<E> set) {
        this.set = set;
    }

    public boolean add(E e) {
        addCount++;
        return set.add(e);
    }

    public boolean addAll(Collection<? extends E> c) {
        addCount += c.size();
        return set.addAll(c);
    }

    public int getAddCount() { return addCount; }
}
```

## 4. 多态（Polymorphism）

### 4.1 编译时多态 vs 运行时多态

| 类型 | 实现方式 | 发生时机 | 示例 |
|------|---------|---------|------|
| 编译时多态 | 方法重载 | 编译期 | `print(int)` vs `print(String)` |
| 运行时多态 | 方法重写 | 运行期 | 父类引用指向子类对象 |

### 4.2 运行时多态（最重要）

```java
// 父类
class Shape {
    public double area() {
        return 0;
    }
}

// 子类 1
class Circle extends Shape {
    private double radius;

    public Circle(double radius) { this.radius = radius; }

    @Override
    public double area() {
        return Math.PI * radius * radius;
    }
}

// 子类 2
class Rectangle extends Shape {
    private double width, height;

    public Rectangle(double width, double height) {
        this.width = width;
        this.height = height;
    }

    @Override
    public double area() {
        return width * height;
    }
}

// 多态的核心：同一方法调用，不同表现
public class Main {
    public static void main(String[] args) {
        Shape s1 = new Circle(5);       // 向上转型
        Shape s2 = new Rectangle(3, 4);

        // 编译时看 Shape（调用 area 方法必须 Shape 中有定义）
        // 运行时看实际对象类型（调用的是 Circle/Rectangle 的 area）
        System.out.println(s1.area());  // 78.54 (圆的面积)
        System.out.println(s2.area());  // 12.0 (矩形面积)

        // 多态的优势：可扩展
        printArea(new Circle(10));
        printArea(new Rectangle(5, 6));
    }

    // 面向抽象/接口编程，不依赖具体类型
    public static void printArea(Shape shape) {
        System.out.println("面积: " + shape.area());
    }
}
```

### 4.3 向上转型与向下转型

```java
// 向上转型（Upcasting）：自动、安全
Dog dog = new Dog();
Animal animal = dog;       // 向上转型，子类 -> 父类（自动）
animal.eat();              // 可以调用父类中定义的方法
// animal.bark();          // 编译错误：Animal 类型没有 bark 方法

// 向下转型（Downcasting）：强制、可能不安全
Animal animal2 = new Dog();
if (animal2 instanceof Dog) {     // 安全检查
    Dog dog2 = (Dog) animal2;     // 向下转型，父类 -> 子类（强制）
    dog2.bark();                  // 现在可以调用子类特有的方法
}

// 错误的转型
Animal animal3 = new Animal();
if (animal3 instanceof Dog) {     // false
    Dog dog3 = (Dog) animal3;     // 不会执行到这里
}
// Dog dog3 = (Dog) new Animal(); // ClassCastException!
```

### 4.4 instanceof 模式匹配（JDK 16+）

```java
// 传统方式
public void process(Object obj) {
    if (obj instanceof String) {
        String s = (String) obj;     // 需要显式转型
        System.out.println(s.length());
    } else if (obj instanceof Integer) {
        Integer i = (Integer) obj;   // 需要显式转型
        System.out.println(i * 2);
    }
}

// JDK 16+ 模式匹配
public void process(Object obj) {
    if (obj instanceof String s) {       // 直接声明变量
        System.out.println(s.length());
    } else if (obj instanceof Integer i) {
        System.out.println(i * 2);
    }

    // 结合条件判断
    if (obj instanceof String s && s.length() > 5) {
        System.out.println(s.toUpperCase());
    }
}
```

## 5. 抽象类与接口

### 5.1 抽象类（Abstract Class）

```java
/**
 * 抽象类：不能被实例化，用于定义模板
 * 抽象方法：只有声明没有实现，必须在子类中实现
 */
public abstract class AbstractLogger {
    // 可以有字段
    protected String name;
    protected Level level;

    // 可以有构造方法（在子类构造中调用）
    public AbstractLogger(String name, Level level) {
        this.name = name;
        this.level = level;
    }

    // 可以有具体方法
    public void info(String message) {
        log(Level.INFO, message);
    }

    public void error(String message) {
        log(Level.ERROR, message);
    }

    // 抽象方法：子类必须实现
    public abstract void log(Level level, String message);

    // 模板方法模式：定义算法骨架
    public void writeLog(Level level, String message) {
        if (!isEnabled(level)) return;
        String formatted = format(message);
        log(level, formatted);
    }

    protected boolean isEnabled(Level level) {
        return level.ordinal() >= this.level.ordinal();
    }

    protected String format(String message) {
        return "[" + LocalDateTime.now() + "] " + message;
    }
}

// 具体实现
public class FileLogger extends AbstractLogger {
    private Path logFile;

    public FileLogger(String name, Level level, Path logFile) {
        super(name, level);        // 调用抽象类构造
        this.logFile = logFile;
    }

    @Override
    public void log(Level level, String message) {
        // 实际写入文件
        System.out.println("写入文件: " + logFile + " - " + message);
    }
}
```

### 5.2 接口（Interface）

```java
/**
 * 接口：完全抽象的契约，定义能力规范
 */
public interface Payable {

    // 常量（接口中的变量默认是 public static final）
    double MIN_PAYMENT = 0.01;

    // 抽象方法（默认是 public abstract）
    void pay(BigDecimal amount);

    // JDK 8+ 默认方法
    default void validate(BigDecimal amount) {
        if (amount.compareTo(BigDecimal.ZERO) <= 0) {
            throw new IllegalArgumentException("金额必须为正数");
        }
    }

    // JDK 8+ 静态方法（工具方法）
    static boolean isValidAmount(BigDecimal amount) {
        return amount != null && amount.compareTo(BigDecimal.ZERO) > 0;
    }

    // JDK 9+ 私有方法（辅助默认方法）
    private void log(String message) {
        System.out.println("[PAY]" + message);
    }
}

// 实现类
public class CreditCardPayment implements Payable {
    private String cardNo;

    public CreditCardPayment(String cardNo) {
        this.cardNo = cardNo;
    }

    @Override
    public void pay(BigDecimal amount) {
        validate(amount);  // 使用默认方法
        System.out.println("信用卡支付: " + amount + " 卡号: " + cardNo);
    }
}

public class AlipayPayment implements Payable {
    private String account;

    public AlipayPayment(String account) {
        this.account = account;
    }

    @Override
    public void pay(BigDecimal amount) {
        validate(amount);
        System.out.println("支付宝支付: " + amount + " 账号: " + account);
    }

    @Override
    public void validate(BigDecimal amount) {
        // 可重写默认方法
        Payable.super.validate(amount);  // 调用父接口的默认方法
        if (amount.compareTo(new BigDecimal("50000")) > 0) {
            throw new IllegalArgumentException("支付宝单笔不能超过 5 万");
        }
    }
}
```

### 5.3 抽象类 vs 接口

| 对比项 | 抽象类 | 接口 |
|--------|--------|------|
| 实例化 | 不能 | 不能 |
| 构造方法 | 可以有 | 不能有 |
| 字段 | 任意字段 | 只能是 `public static final` 常量 |
| 方法 | 抽象、具体都可以 | 抽象、default、static、private |
| 访问修饰符 | 任意 | `public`（JDK 9+ 支持 private） |
| 继承 | 单继承（`extends`） | 多实现（`implements`） |
| 设计目标 | 代码复用、模板定义 | 能力契约、行为规范 |
| 关键词 | `is-a` 关系 | `has-a` / `can-do` 关系 |

**选择原则**:
- 如果类之间的关系是 `is-a`（如 Dog is-a Animal），用抽象类
- 如果类之间的关系是 `can-do`（如 Duck can-swim, can-fly），用接口
- 如果需要在不同的类层次间共享行为，用接口
- 如果需要代码复用或定义模板方法，用抽象类

### 5.4 函数式接口（Functional Interface）

```java
// 有且仅有一个抽象方法的接口（可以有 default/static 方法）
@FunctionalInterface
public interface Calculator {
    int calculate(int a, int b);

    // 错误的：多个抽象方法
    // int otherMethod();
}

// 使用 Lambda 表达式
Calculator add = (a, b) -> a + b;
Calculator multiply = (a, b) -> a * b;

System.out.println(add.calculate(3, 4));       // 7
System.out.println(multiply.calculate(3, 4));  // 12

// Java 内置的函数式接口
// Predicate<T>     : T -> boolean
// Function<T, R>   : T -> R
// Consumer<T>      : T -> void
// Supplier<T>      : () -> T
// UnaryOperator<T> : T -> T
// BinaryOperator<T>: (T, T) -> T
```

### 5.5 接口多实现与冲突解决

```java
interface A {
    default void hello() { System.out.println("A"); }
}

interface B {
    default void hello() { System.out.println("B"); }
}

// 如果一个类同时实现两个有相同默认方法的接口，必须重写解决冲突
class C implements A, B {
    @Override
    public void hello() {
        A.super.hello();  // 明确指定调用哪个接口的默认方法
        B.super.hello();
        System.out.println("C");
    }
}
```

## 6. 内部类（Inner Classes）

### 6.1 内部类分类

| 类型 | 定义位置 | 访问外部类 | 静态性 | 典型用途 |
|------|---------|-----------|--------|---------|
| 静态内部类 | 类内部，static 修饰 | 只能访问外部类的静态成员 | 是 | 辅助类、建造者 |
| 成员内部类 | 类内部，无 static | 可直接访问所有成员（包括 private） | 否 | 迭代器、事件 |
| 局部内部类 | 方法/作用域内 | 可访问外部类成员和 final/effectively final 局部变量 | 否 | 很少用 |
| 匿名内部类 | 表达式内 | 同上 | 否 | 一次性实现接口/抽象类 |

/**
 * 枚举可以包含字段、方法和构造方法

public enum OrderStatus {
    // 枚举常量（必须放在最前面）
    PENDING(0, "待支付"),
    PAID(1, "已支付"),
    SHIPPED(2, "已发货"),
    DELIVERED(3, "已签收"),
    CANCELLED(4, "已取消");

    // 字段
    private final int code;
    private final String description;

    // 构造方法（默认 private）
    OrderStatus(int code, String description) {
        this.code = code;
        this.description = description;
    }

    // 方法
    public int getCode() {
        return code;
    }

    public String getDescription() {
        return description;
    }

    // 根据 code 查找枚举
    public static OrderStatus fromCode(int code) {
        for (OrderStatus status : values()) {
            if (status.code == code) {
                return status;
            }
        }
        throw new IllegalArgumentException("未知状态码: " + code);
    }

    // 判断是否可以取消
    public boolean canCancel() {
        return this == PENDING || this == PAID;
    }

    // 下一个状态
    public OrderStatus next() {
        return switch (this) {
            case PENDING -> PAID;
            case PAID -> SHIPPED;
            case SHIPPED -> DELIVERED;
            case DELIVERED, CANCELLED -> throw new IllegalStateException("终态不能转换");
        };
    }
}

## 8. Records（JDK 14+ 预览，JDK 16+ 稳定）

Record 是一种透明的数据载体，自动生成构造方法、getter、`equals()`、`hashCode()`、`toString()`。

```java
/**
 * 传统 POJO 类（繁琐）
 */
public final class Point {
    private final int x;
    private final int y;

    public Point(int x, int y) {
        this.x = x;
        this.y = y;
    }

    public int getX() { return x; }
    public int getY() { return y; }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Point)) return false;
        Point point = (Point) o;
        return x == point.x && y == point.y;
    }

    @Override
    public int hashCode() {
        return Objects.hash(x, y);
    }

    @Override
    public String toString() {
        return "Point[x=" + x + ", y=" + y + "]";
    }
}

/**
 * Record 等效写法（简洁）
 * 自动生成：构造、getter（x() 而非 getX()）、equals、hashCode、toString
 * 所有字段默认是 private final
 */
public record PointRecord(int x, int y) {
    // 紧凑构造（canonical constructor）：参数验证
    public PointRecord {
        if (x < 0 || y < 0) {
            throw new IllegalArgumentException("坐标不能为负数");
        }
        // 不需要 this.x = x; 编译器自动处理
    }

    // 可以添加静态方法
    public static PointRecord origin() {
        return new PointRecord(0, 0);
    }

    // 可以添加实例方法（但不应修改状态）
    public double distanceFromOrigin() {
        return Math.sqrt(x * x + y * y);
    }

    // 不能添加实例字段（但可以有静态字段）
}
```

**Record 的限制**:
- 不能继承其他类（但可以实现接口）
- 所有字段是 `private final`，不可变
- 不能声明实例字段（只能声明组件和静态字段）
- 是隐式 final 类，不能被继承

## 9. 密封类（Sealed Classes，JDK 17+）

密封类用于限制哪些类可以继承/实现它。

```java
/**
 * 密封类：明确指定哪些类可以继承
 */
public sealed class Shape
    permits Circle, Rectangle, Triangle {  // 只允许这三个子类

    public abstract double area();
}

// 子类必须使用 final、sealed 或 non-sealed 修饰
final class Circle extends Shape {
    private final double radius;

    public Circle(double radius) { this.radius = radius; }

    @Override
    public double area() {
        return Math.PI * radius * radius;
    }
}

// non-sealed：允许任意类继承
non-sealed class Rectangle extends Shape {
    private final double width, height;

    public Rectangle(double width, double height) {
        this.width = width;
        this.height = height;
    }

    @Override
    public double area() {
        return width * height;
    }
}

// sealed interface
sealed interface Service permits UserService, OrderService {
    void execute();
}

final class UserService implements Service {
    @Override
    public void execute() {
        System.out.println("用户服务");
    }
}

final class OrderService implements Service {
    @Override
    public void execute() {
        System.out.println("订单服务");
    }
}

// 密封类与 switch 模式匹配配合（编译器可检查穷举性）
public String process(Shape shape) {
    return switch (shape) {
        case Circle c -> "圆形, 面积: " + c.area();
        case Rectangle r -> "矩形, 面积: " + r.area();
        case Triangle t -> "三角形, 面积: " + t.area();
        // 不需要 default，密封类已穷举
    };
}
```

## 10. Object 类的方法

`Object` 是所有类的根父类（包括数组）。

### 10.1 equals 与 hashCode

**`equals()` 协定**:
- 自反性：`x.equals(x)` 为 true
- 对称性：`x.equals(y) == y.equals(x)`
- 传递性：`x.equals(y) && y.equals(z)` => `x.equals(z)`
- 一致性：多次调用结果相同
- 非空性：`x.equals(null)` 为 false

**`hashCode()` 协定**:
- 如果 `x.equals(y)` 为 true，则 `x.hashCode() == y.hashCode()`
- 如果 `x.hashCode() == y.hashCode()`，`x.equals(y)` 不一定为 true（哈希碰撞）

```java
public class Student {
    private Long id;
    private String name;
    private String email;

    public Student(Long id, String name, String email) {
        this.id = id;
        this.name = name;
        this.email = email;
    }

    @Override
    public boolean equals(Object o) {
        // 1. 自反性检查
        if (this == o) return true;
        // 2. 类型检查（使用 instanceof，包含 null 检查）
        if (!(o instanceof Student)) return false;
        // 3. 类型转换
        Student other = (Student) o;
        // 4. 比较关键字段
        return Objects.equals(id, other.id)
            && Objects.equals(name, other.name)
            && Objects.equals(email, other.email);
    }

    @Override
    public int hashCode() {
        // 使用 equals 用到的所有字段计算 hashCode
        return Objects.hash(id, name, email);
    }

    @Override
    public String toString() {
        return "Student{" +
            "id=" + id +
            ", name='" + name + '\'' +
            ", email='" + email + '\'' +
            '}';
    }
}
```

> **阿里巴巴规范**: 如果重写 `equals()`，必须重写 `hashCode()`。使用 `Objects.hash()` 生成简单的 `hashCode`，或使用 Guava 的 `MoreObjects.toStringHelper()` 实现 `toString`。

### 10.2 clone 方法

```java
public class Person implements Cloneable {  // 必须实现 Cloneable 接口
    private String name;
    private int age;
    private Address address;  // 引用类型字段

    // 浅拷贝：基本类型和 String 没问题，但引用类型共享
    @Override
    protected Object clone() throws CloneNotSupportedException {
        return super.clone();  // 浅拷贝
    }

    // 深拷贝：引用类型也拷贝
    @Override
    protected Object deepClone() throws CloneNotSupportedException {
        Person cloned = (Person) super.clone();
        cloned.address = this.address.clone();  // 假设 Address 也实现了 Cloneable
        return cloned;
    }
}
```

> **Effective Java**: 优先使用拷贝构造方法或拷贝工厂，而非 `clone()`。

```java
// 更好的方案：拷贝构造
public Person(Person other) {
    this.name = other.name;
    this.age = other.age;
    this.address = new Address(other.address);  // 深拷贝
}

// 或使用序列化
```

## 11. SOLID 原则概述

### 11.1 单一职责原则（Single Responsibility Principle）

一个类只负责一个职责，只有一个引起变化的原因。

```java
// 违反 SRP：一个类承担了三个职责
public class OrderService {
    public void createOrder(Order order) { }
    public void sendEmail(Order order) { }
    public void generateReport(Order order) { }
}

// 符合 SRP
public class OrderService {
    public void createOrder(Order order) { }
}
public class EmailService {
    public void sendEmail(Order order) { }
}
public class ReportService {
    public void generateReport(Order order) { }
}
```

### 11.2 开闭原则（Open/Closed Principle）

对扩展开放，对修改关闭。使用抽象和接口实现。

```java
// 违反 OCP：新增支付方式需要修改类
public class PaymentProcessor {
    public void process(String type) {
        if ("alipay".equals(type)) { /* ... */ }
        else if ("wechat".equals(type)) { /* ... */ }
    }
}

// 符合 OCP
public interface PaymentMethod {
    void pay(BigDecimal amount);
}
public class Alipay implements PaymentMethod { /* ... */ }
public class Wechat implements PaymentMethod { /* ... */ }
// 新增支付方式只需新增类，无需修改现有代码
```

### 11.3 里氏替换原则（Liskov Substitution Principle）

子类对象可以替换父类对象且不改变程序正确性。

```java
// 违反 LSP：正方形不是长方形的正确子类
class Rectangle {
    protected int width, height;
    public void setWidth(int w) { this.width = w; }
    public void setHeight(int h) { this.height = h; }
    public int area() { return width * height; }
}

class Square extends Rectangle {
    @Override
    public void setWidth(int w) {
        super.setWidth(w);
        super.setHeight(w);  // 修改了父类的预期行为
    }
}

// 正确的做法：抽象 Shape 类，Rectangle 和 Square 各自实现
```

### 11.4 接口隔离原则（Interface Segregation Principle）

客户端不应依赖它不需要的接口，接口应尽可能小。

```java
// 违反 ISP：胖接口
interface Worker {
    void work();
    void eat();
    void sleep();
}

// 符合 ISP：细粒度接口
interface Workable { void work(); }
interface Eatable { void eat(); }
interface Sleepable { void sleep(); }

class Robot implements Workable {
    public void work() { /* robot works */ }
    // 不需要 eat() 和 sleep()
}
```

### 11.5 依赖倒置原则（Dependency Inversion Principle）

高层模块不应依赖低层模块，两者都应依赖抽象。抽象不应依赖细节，细节应依赖抽象。

```java
// 违反 DIP：高层直接依赖低层
public class NotificationService {
    private EmailSender emailSender = new EmailSender();  // 直接依赖具体实现

    public void send(String message) {
        emailSender.send(message);
    }
}

// 符合 DIP
public interface MessageSender {
    void send(String message);
}

public class EmailSender implements MessageSender { /* ... */ }
public class SmsSender implements MessageSender { /* ... */ }

public class NotificationService {
    private final MessageSender sender;  // 依赖抽象

    public NotificationService(MessageSender sender) {  // 依赖注入
        this.sender = sender;
    }

    public void send(String message) {
        sender.send(message);
    }
}
```

public enum PayStatus {

public interface PayStrategy {

public class AlipayStrategy implements PayStrategy {

## 13. 常见陷阱与最佳实践

### 常见陷阱

| 陷阱 | 说明 |
|------|------|
| 错误使用 `==` 比较对象 | 引用类型用 `equals()` 比较内容 |
| 重写 `equals` 不重写 `hashCode` | 违反协定，HashSet/HashMap 行为异常 |
| 构造方法中调用可重写方法 | 子类可能还未初始化完全 |
| 继承滥用 | 优先使用组合而非继承 |
| 可变对象作为 HashSet 的 key | hashCode 可能变化导致元素"丢失" |
| 内部类持有外部类引用导致内存泄露 | 静态内部类或及时清理 |
| 向下转型不检查 instanceof | 可能抛出 ClassCastException |
| 枚举常量比较用 `==` | 枚举的 `==` 和 `equals` 结果一致，但 `==` 更快 |
| 接口常量被实现类继承 | 接口常量应通过接口名访问，而非实现类 |

### 最佳实践

1. **组合优于继承**（Effective Java 第 18 条）
2. **接口优于抽象类**（Effective Java 第 20 条）
3. **标记接口优于注解**（如 Serializable）
4. **equals/hashCode 成对重写**
5. **优先使用不可变类**
6. **最小化类和成员的访问权限**
7. **使用 Builder 模式替代多个构造参数**
8. **优先使用枚举常量而非常量类**

## 14. 常见面试题

1. **面向对象的三大特性是什么？请举例说明。**
   - 封装：隐藏内部实现，暴露行为接口
   - 继承：子类复用父类代码，建立层次关系
   - 多态：同一接口，不同实现

2. **重写（Override）和重载（Overload）的区别？**
   - 重写发生在父子类之间，方法签名相同
   - 重载发生在同类中，方法名相同参数不同

3. **抽象类和接口的区别（JDK 8 后）？**
   - 见上面对比表

4. **`String` 是值传递还是引用传递？**
   - 永远是值传递。String 的"不可变"特性导致对它的修改会创建新对象

5. **`equals()` 和 `hashCode()` 的协定是什么？为什么需要同时重写？**
   - 如果 `a.equals(b)` 为 true，`a.hashCode() == b.hashCode()` 必须为 true
   - 反之不成立（哈希碰撞）
   - 如果只重写 `equals` 不重写 `hashCode`，HashSet/HashMap 中可能会出现重复

6. **单继承 vs 多继承？Java 为什么不支持多继承？**
   - 多继承存在菱形继承问题（Diamond Problem）
   - Java 通过接口多实现 + 默认方法解决了部分问题

7. **内部类为什么要声明为 static？**
   - 非静态内部类持有外部类引用，可能导致内存泄漏
   - 静态内部类不依赖外部类实例

8. **请解释策略模式，并说明枚举如何实现策略模式。**
   - 策略模式：定义算法家族，使算法可互换
   - 枚举实现：在枚举常量中实现抽象方法

9. **Record 和 POJO 的区别？**
   - Record 自动生成构造、equals、hashCode、toString
   - Record 是不可变的（所有字段 final）
   - Record 不能继承其他类

10. **密封类的用途是什么？**
    - 限制类的继承/实现范围
    - 与 switch 模式匹配配合实现穷举检查
    - 更精确地控制 API 扩展
