## 1. Java IO体系全景图

Java IO体系从三个正交维度划分，所有IO类均可归入下表：

| 维度 | 分类 | 说明 |
|------|------|------|
| 数据单位 | 字节流 / 字符流 | 字节流处理所有类型数据；字符流仅处理文本 |
| 数据流向 | 输入流 / 输出流 | 输入流从外部读取到程序；输出流从程序写入外部 |
| 功能角色 | 节点流 / 处理流 | 节点流直接操作数据源；处理流包装节点流增强功能 |

### IO类层次关系（核心骨架）

```
                        Java IO 体系
                          │
              ┌───────────┴───────────┐
              │  字节流               │  字符流
              ▼                       ▼
  InputStream / OutputStream      Reader / Writer
         │                            │
  ┌──────┴──────┐           ┌─────────┴──────────┐
  ▼             ▼           ▼                    ▼
 FileInputStream  Buffered   FileReader      BufferedReader
 FileOutputStream  InputStream FileWriter    BufferedWriter
                   Buffered              InputStreamReader
                   OutputStream          OutputStreamWriter (桥接)
```

### 字节流 vs 字符流对比

| 对比维度 | 字节流 | 字符流 |
|----------|--------|--------|
| 基类 | InputStream / OutputStream | Reader / Writer |
| 数据单位 | byte（1字节=8位） | char（1字符=2字节，适配中文） |
| 处理范围 | 所有文件类型（文本、图片、视频、音频） | 仅文本数据（.txt、.java、.xml等） |
| 编码处理 | 不处理编码，直接读写原始字节 | 自动编码/解码，解决中文乱码问题 |
| 缓冲区 | 无内置缓冲区（flush可选） | 有内置缓冲区（flush必须调用） |
| 适用场景 | 文件复制、网络传输、二进制数据处理 | 文本文件读写、日志处理、配置文件解析 |

> 💡 **记忆技巧**：字节流"万能"——能处理所有类型数据；字符流"专一"——只处理文本。输入流"读"（Input/Reader），输出流"写"（Output/Writer）。

## 2. File类（传统）vs Path接口（NIO.2）

### 2.1 File类（JDK 1.0）

`java.io.File` 是传统的文件/目录操作类，**不负责读写数据**，只负责文件与目录的增删改查。

```java
// 创建File对象
File file = new File("D:\\data\\test.txt");

// 常用方法
file.exists();          // 文件是否存在
file.isFile();          // 是否为文件
file.isDirectory();     // 是否为目录
file.mkdir();           // 创建单级目录
file.mkdirs();          // 创建多级目录
file.delete();          // 删除文件或空目录
file.listFiles();       // 列出目录下所有文件/子目录
file.length();          // 文件大小（字节）
file.getName();         // 文件名
file.getAbsolutePath(); // 绝对路径
```
> ⚠️ **File类的局限性**：无法获取文件属性（权限、创建时间等）；方法返回boolean而非异常，错误排查困难；不支持符号链接；listFiles()在大目录下性能差。

### 2.2 Path接口与Paths工具类（JDK 7 / NIO.2）

`java.nio.file.Path` 是NIO.2引入的路径抽象，配合 `java.nio.file.Paths` 和 `java.nio.file.Files` 使用，克服了File类的局限。

```java
// 创建Path（推荐使用Paths工具类）
Path path = Paths.get("D:", "data", "test.txt");
Path path2 = Paths.get("D:\\data\\test.txt");

// 路径操作
path.getFileName();       // 文件名 test.txt
path.getParent();         // 父目录 D:\data
path.getRoot();           // 根目录 D:\
path.resolve("sub");      // 解析子路径 D:\data\test.txt\sub
path.relativize(other);   // 计算相对路径
path.normalize();         // 规范化路径（去除.和..）

// 转换为File（兼容旧代码）
File file = path.toFile();
Path back = file.toPath();
```

### 2.3 File vs Path对比

| 对比维度 | File | Path / Files |
|----------|------|--------------|
| 引入版本 | JDK 1.0 | JDK 7 |
| 错误处理 | 返回boolean | 抛异常（便于排查） |
| 符号链接 | 不支持 | 支持 |
| 文件属性 | 有限 | 完整（权限、时间、ACL等） |
| 目录遍历 | listFiles()（性能差） | DirectoryStream/Files.walk（高效） |
| 原子操作 | 不支持 | Files.move支持原子操作 |
| 文件系统 | 单一 | 支持多文件系统（ZIP、NFS等） |

> 🎯 **开发建议**：新项目优先使用Path + Files API，仅在维护遗留代码时使用File。NIO.2的Files工具类提供了大量便捷方法（详见第8节）。

## 3. 字节流：InputStream/OutputStream

### 3.1 核心父类方法

| 方法 | InputStream | OutputStream |
|------|-------------|--------------|
| `int read()` | 读取一个字节，返回0-255，末尾返回-1 | — |
| `int read(byte[] b)` | 批量读入字节数组，返回实际读取数 | — |
| `void write(int b)` | — | 写入一个字节（取int低8位） |
| `void write(byte[] b)` | — | 写入字节数组 |
| `void write(byte[] b, int off, int len)` | — | 写入字节数组指定范围 |
| `int available()` | 返回可读字节数（近似值） | — |
| `void flush()` | — | 刷新缓冲区（字节流可选） |
| `void close()` | 关闭流释放资源 | 关闭流释放资源 |

### 3.2 FileInputStream / FileOutputStream 文件读写

```java
// 字节流读取文件
try (InputStream is = new FileInputStream("test.txt")) {
    byte[] buffer = new byte[1024];
    int len;
    while ((len = is.read(buffer)) != -1) {
        System.out.print(new String(buffer, 0, len, StandardCharsets.UTF_8));
    }
} catch (IOException e) {
    e.printStackTrace();
}
```

```java
// 字节流写入文件（第二个参数true=追加写入，false=覆盖，默认false）
try (OutputStream os = new FileOutputStream("test.txt", true)) {
    String content = "Java IO 字节流写入示例";
    os.write(content.getBytes(StandardCharsets.UTF_8));
    os.flush();
} catch (IOException e) {
    e.printStackTrace();
}
```

### 3.3 其他常用字节流

| 类名 | 作用 | 使用场景 |
|------|------|----------|
| `ByteArrayInputStream/OutputStream` | 以内存字节数组为数据源 | 内存中操作字节数据 |
| `DataInputStream/OutputStream` | 读写基本数据类型 | 二进制数据格式读写 |
| `ObjectInputStream/OutputStream` | 对象序列化/反序列化 | 对象持久化与传输（见第9节） |
| `SequenceInputStream` | 合并多个输入流 | 文件合并 |

## 4. 字符流：Reader/Writer

### 4.1 核心父类方法

| 方法 | Reader | Writer |
|------|--------|--------|
| `int read()` | 读取一个字符，返回Unicode值0-65535，末尾-1 | — |
| `int read(char[] cbuf)` | 批量读入字符数组 | — |
| `void write(int c)` | — | 写入一个字符（取int低16位） |
| `void write(char[] cbuf)` | — | 写入字符数组 |
| `void write(String str)` | — | 直接写入字符串（最常用） |
| `void flush()` | — | 刷新缓冲区（字符流**必须**调用） |
| `void close()` | 关闭流 | 关闭流（关闭前自动flush） |

### 4.2 FileReader / FileWriter 文件读写（不推荐直接使用）

```java
/**
 * FileReader直接读取（不推荐——依赖系统默认编码）
 */
try (Reader reader = new FileReader("test.txt")) {
    char[] buffer = new char[1024];
    int len;
    while ((len = reader.read(buffer)) != -1) {
        System.out.print(new String(buffer, 0, len));
    }
} catch (IOException e) {
    e.printStackTrace();
}
```

> ⚠️ **FileReader/FileWriter的编码陷阱**：默认使用系统编码（Windows -> GBK，Linux/macOS -> UTF-8），直接使用跨平台时极易产生中文乱码。**推荐通过桥接流（InputStreamReader/OutputStreamWriter）手动指定UTF-8编码**，详见第5节。

### 4.3 其他常用字符流

| 类名 | 作用 | 使用场景 |
|------|------|----------|
| `CharArrayReader/Writer` | 以内存字符数组为数据源 | 内存中文本操作 |
| `StringReader/Writer` | 以字符串为数据源 | 字符串作为IO源 |
| `PrintWriter` | 便捷打印字符串、基本数据类型 | 格式化输出 |

## 5. 桥接流：InputStreamReader/OutputStreamWriter

桥接流（也称转换流）是**字节流与字符流之间的桥梁**，负责将字节流转为字符流并处理编码/解码。

**编码（Encoding）**：字符 -> 字节（如 `'A'` -> `0x41`，`'中'` -> `0xE4 0xB8 0xAD`）。**解码（Decoding）**：字节 -> 字符。编解码格式不一致会产生乱码。

### 标准用法

```java
/**
 * InputStreamReader + BufferedReader 读取文本（指定UTF-8编码）
 */
try (BufferedReader br = new BufferedReader(
        new InputStreamReader(new FileInputStream("test.txt"), StandardCharsets.UTF_8))) {
    String line;
    while ((line = br.readLine()) != null) {
        System.out.println(line);
    }
} catch (IOException e) {
    e.printStackTrace();
}
```

```java
/**
 * OutputStreamWriter + BufferedWriter 写入文本（追加模式）
 */
try (BufferedWriter bw = new BufferedWriter(
        new OutputStreamWriter(new FileOutputStream("test.txt", true), StandardCharsets.UTF_8))) {
    bw.write("Hello IO");
    bw.newLine();
    bw.flush();
} catch (IOException e) {
    e.printStackTrace();
}
```

> 💡 **最佳实践**：始终使用 `InputStreamReader` / `OutputStreamWriter` 并指定 `StandardCharsets.UTF_8`，永远不依赖系统默认编码。使用 `StandardCharsets.UTF_8` 常量而非字符串 `"UTF-8"`，避免拼写错误。

## 6. 缓冲流与性能优化

### 6.1 缓冲流工作机制

缓冲流通过**装饰器模式**包装基础流，内部维护一个固定大小的缓冲区（默认 **8192字节 = 8KB**），工作机制如下：

1. **读取时**：一次性从磁盘读取尽可能多的数据到内存缓冲区，后续读取直接从缓冲区获取，减少磁盘I/O次数。
2. **写入时**：先将数据写入内存缓冲区，缓冲区满或调用 `flush()` 时，才一次性写入磁盘。

### 6.2 缓冲流体系

| 类别 | 缓冲字节流 | 缓冲字符流 |
|------|-----------|-----------|
| 输入 | `BufferedInputStream` | `BufferedReader` |
| 输出 | `BufferedOutputStream` | `BufferedWriter` |
| 独有方法 | 无 | `readLine()` / `newLine()` |

### 6.3 缓冲字符流——逐行读写

```java
// BufferedReader逐行读取（readLine()是核心方法）
try (BufferedReader br = new BufferedReader(
        new InputStreamReader(new FileInputStream("test.txt"), StandardCharsets.UTF_8))) {
    String line;
    while ((line = br.readLine()) != null) {
        System.out.println(line);
    }
} catch (IOException e) {
    e.printStackTrace();
}
```

```java
// BufferedWriter写入 + newLine()跨平台换行（比"\n"更规范）
try (BufferedWriter bw = new BufferedWriter(
        new OutputStreamWriter(new FileOutputStream("output.txt"), StandardCharsets.UTF_8))) {
    bw.write("第一行");
    bw.newLine();
    bw.write("第二行");
    bw.flush();
} catch (IOException e) {
    e.printStackTrace();
}
```

### 6.4 性能优化策略

| 优化手段 | 说明 | 建议 |
|----------|------|------|
| 使用缓冲流 | 包装基础流，减少磁盘I/O次数 | 始终在基础流外套缓冲流 |
| 合理设置缓冲区大小 | 默认8KB；大文件可增至32KB-64KB | 不宜过大，避免浪费内存 |
| 批量读写 | 使用 `read(byte[])` / `read(char[])` 而非单字节读写 | 缓冲区设为文件大小的合理倍数 |
| 及时flush | 关键节点刷新缓冲区 | 防止宕机导致数据丢失 |
| 避免在循环内创建流 | 流创建开销大 | 复用流对象，循环外创建 |

## 7. 装饰器模式在IO中的应用

**装饰器模式**通过包装（Wrapper）方式动态添加功能。节点流（如FileInputStream）负责数据读写，处理流（如Buffered、Data）作为装饰器包装节点流增强功能，且可多层叠加：

```java
// 三层装饰：文件读取 + 缓冲 + 基本类型读取
DataInputStream dis = new DataInputStream(
    new BufferedInputStream(new FileInputStream("data.bin")));
```

| 层次 | 类 | 功能 |
|------|-----|------|
| 节点流 | `FileInputStream` | 从文件读取原始字节 |
| 装饰1 | `BufferedInputStream` | 添加缓冲，减少磁盘I/O |
| 装饰2 | `DataInputStream` | 添加基本数据类型读取能力 |

> 🎯 装饰器模式让Java IO像搭积木一样灵活组合不同功能，是理解整个IO框架的关键。

## 8. NIO.2 Files工具类详解

`java.nio.file.Files` 是JDK 7 NIO.2提供的工具类，封装了大量文件操作静态方法，应作为现代Java开发的首选。

### 8.1 文件快捷读写

```java
// 读取所有行 / 全部字节
List<String> lines = Files.readAllLines(Paths.get("test.txt"), StandardCharsets.UTF_8);
byte[] bytes = Files.readAllBytes(Paths.get("test.txt"));
// 写入
Files.write(Paths.get("output.txt"), "Hello".getBytes(StandardCharsets.UTF_8));
Files.write(Paths.get("output.txt"), lines, StandardCharsets.UTF_8);
```

### 8.2 文件元数据与操作

```java
Files.exists(path); Files.isDirectory(path); Files.isRegularFile(path);
Files.size(path); Files.getLastModifiedTime(path); Files.getOwner(path);
Files.createDirectories(Paths.get("D:\\a\\b\\c"));
Files.createFile(Paths.get("D:\\newfile.txt"));
Files.copy(source, target, StandardCopyOption.REPLACE_EXISTING);
Files.move(source, target, StandardCopyOption.ATOMIC_MOVE);
Files.deleteIfExists(path);
// 目录遍历
try (DirectoryStream<Path> s = Files.newDirectoryStream(dirPath, "*.{java,txt}")) {
    for (Path e : s) System.out.println(e.getFileName());
}
Files.walk(Paths.get("D:\\data")).filter(p -> p.toString().endsWith(".java")).forEach(System.out::println);
```

> 💡 **Files vs File**：Files工具类的所有操作均抛出 `IOException`，错误信息清晰；支持符号链接、文件属性操作、原子移动等功能。新项目应首选Files API。

## 9. 序列化与反序列化

### 9.1 基本概念

- **序列化（Serialization）**：将Java对象转换为字节序列，便于存储到文件或通过网络传输。
- **反序列化（Deserialization）**：将字节序列恢复为Java对象。

### 9.2 核心API

```java
// 序列化：对象 -> 文件
try (ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("user.ser"))) {
    User user = new User("张三", 25);
    oos.writeObject(user);
} catch (IOException e) {
    e.printStackTrace();
}

// 反序列化：文件 -> 对象
try (ObjectInputStream ois = new ObjectInputStream(new FileInputStream("user.ser"))) {
    User user = (User) ois.readObject();
    System.out.println(user.getName());
} catch (IOException | ClassNotFoundException e) {
    e.printStackTrace();
}
```

### 9.3 Serializable接口与serialVersionUID

所有需要序列化的类必须实现 `java.io.Serializable` 接口（一个标记接口，不含任何方法）：

```java
import java.io.Serializable;

public class User implements Serializable {
    // 显式声明serialVersionUID（强烈建议）
    private static final long serialVersionUID = 1L;

    private String name;
    private int age;
    // transient字段不参与序列化
    private transient String password;

    // constructor, getters, setters...
}
```

### 9.4 serialVersionUID 详解

`serialVersionUID` 是序列化版本号，用于标识类的版本，在反序列化时校验类的兼容性：

| 要点 | 说明 |
|------|------|
| **作用** | 反序列化时校验发送方与接收方的类版本是否一致 |
| **默认生成** | 若未显式声明，JVM根据类结构（字段、方法、接口等）自动计算哈希值 |
| **为何要显式声明** | 默认值对类细节敏感（如添加一个字段会导致值变化），反序列化时若类结构发生变化将抛出 `InvalidClassException` |
| **最佳实践** | 显式声明为固定值（如1L），确保类在合理变更（增删字段、方法）后仍能兼容反序列化 |
| **何时需修改** | 当类发生**不兼容变更**时（如删除字段、修改字段类型），应更新serialVersionUID |

> ⚠️ **序列化注意事项**：
> 1. `static` 字段不属于对象状态，不参与序列化。
> 2. `transient` 关键字标记的字段不参与序列化（如密码、敏感信息）。
> 3. 反序列化时不会调用构造方法，对象通过 `ObjectInputStream` 直接恢复。
> 4. 如果父类未实现Serializable，父类字段不会被序列化。

### 9.5 Externalizable接口

若需完全控制序列化，可实现 `Externalizable` 接口，重写 `writeExternal()` 和 `readExternal()` 方法。性能优于默认反射机制，但编码量较大。大多数场景下使用Serializable + transient即可满足需求。

## 10. try-with-resources与AutoCloseable

### 10.1 传统写法 vs try-with-resources

**传统写法**：finally中手动close，易遗漏且存在异常屏蔽问题。

**try-with-resources（JDK 7+）**：

```java
/**
 * try-with-resources 自动关闭资源
 * try关键字后的小括号中声明资源，资源必须实现 AutoCloseable 接口
 */
try (InputStream is = new FileInputStream("test.txt");
     OutputStream os = new FileOutputStream("output.txt")) {
    byte[] buffer = new byte[1024];
    int len;
    while ((len = is.read(buffer)) != -1) {
        os.write(buffer, 0, len);
    }
} catch (IOException e) {
    e.printStackTrace();
}
// try结束后，is 和 os 的 close() 方法自动被调用（无论是否发生异常）
```

### 10.2 编译原理（语法糖本质）

编译器自动将 try-with-resources 还原为 `try-catch-finally` + 异常抑制：若try块和close()同时抛异常，close()的异常被抑制，通过 `primaryException.addSuppressed()` 保存，可通过 `e.getSuppressed()` 获取。

### 10.3 关键特性

| 特性 | 说明 |
|------|------|
| **自动关闭** | try代码块结束后，自动调用每个资源的 `close()` 方法 |
| **声明顺序与关闭顺序** | 资源按声明顺序的**相反顺序**关闭（后声明先关闭） |
| **异常抑制** | 若try块抛出异常后close()也抛出异常，close()的异常会被**抑制**（suppressed），可通过 `getSuppressed()` 获取 |
| **多资源** | 可同时声明多个资源，用分号分隔 |
| **适用范围** | 任何实现了 `AutoCloseable`（或 `Closeable`）的类 |

### 10.4 AutoCloseable vs Closeable

| 对比 | Closeable | AutoCloseable |
|------|-----------|---------------|
| 引入版本 | JDK 5 | JDK 7 |
| 异常声明 | `close()` 抛出 `IOException` | `close()` 抛出 `Exception`（更宽泛） |
| 幂等性 | 建议幂等（多次调用无副作用） | 不强制要求幂等 |
| 关系 | Closeable extends AutoCloseable | 基接口 |

> 🎯 **开发铁律**：所有IO操作必须使用 try-with-resources。它既简化代码，又彻底杜绝资源泄漏和异常屏蔽问题。任何实现AutoCloseable的资源（IO流、数据库连接、网络连接等）均适用。

## 11. 大文件处理与FileChannel

传统 `read(byte[])` 逐块读取大文件（GB级别）存在频繁内核态切换、内存占用高的问题。

### 11.1 FileChannel（JDK 4 NIO）

`java.nio.channels.FileChannel` 通过**零拷贝传输**提升大文件读写性能：

```java
// 使用FileChannel零拷贝复制大文件
try (FileChannel src = FileChannel.open(Paths.get("large.zip"), StandardOpenOption.READ);
     FileChannel dst = FileChannel.open(Paths.get("large-copy.zip"),
             StandardOpenOption.WRITE, StandardOpenOption.CREATE)) {
    src.transferTo(0, src.size(), dst); // 零拷贝：从源通道直接到目标通道
} catch (IOException e) {
    e.printStackTrace();
}
```

### 11.2 大文件逐行处理（流式读取）

```java
// 使用Files.lines()流式读取，避免一次性加载到内存
try (Stream<String> lines = Files.lines(Paths.get("large-file.log"), StandardCharsets.UTF_8)) {
    lines.filter(line -> line.contains("ERROR")).forEach(System.out::println);
} catch (IOException e) {
    e.printStackTrace();
}
```

### 11.3 FileChannel vs 传统流

| 对比维度 | 传统流（BIO） | FileChannel |
|----------|--------------|-------------|
| 零拷贝 | 不支持 | 支持（transferTo/transferFrom） |
| 缓冲区 | 堆内存byte[] | ByteBuffer（堆外/直接内存） |
| 文件锁 | 不支持 | 支持（FileLock） |
| 内存映射 | 不支持 | 支持（MappedByteBuffer） |

> 💡 **何时使用FileChannel**：大文件复制（GB级别）、需要文件锁、需要内存映射文件、追求极致IO性能。日常小文件读写仍优先使用 `Files` 工具类或缓冲流。

## 12. 面试高频考点

### 12.1 字节流与字符流的区别

字节流以byte为单位处理所有类型文件（InputStream/OutputStream）；字符流以char为单位仅处理文本（Reader/Writer），底层自动编码/解码解决中文乱码，但写入后必须flush()。

### 12.2 缓冲流为什么高效

内部维护8KB缓冲区，读取时批量加载到内存，写入时缓存满后批量写入磁盘，大幅减少磁盘I/O次数。

### 12.3 装饰器模式在IO中的应用

处理流（Buffered、Data等）通过包装节点流（FileInputStream等）动态增强功能，可多层叠加。如 `new DataInputStream(new BufferedInputStream(new FileInputStream("data.bin")))` 同时获得文件读取、缓冲、基本类型读取三种能力。

### 12.4 try-with-resources的原理

语法糖，编译器自动生成finally块调用close()并处理异常抑制（suppressed exceptions）。相比传统手动关闭，代码更简洁且杜绝资源泄漏。

### 12.5 序列化为什么要实现Serializable？serialVersionUID的作用？

Serializable是标记接口，告知JVM该类允许序列化。serialVersionUID是版本标识，用于反序列化时校验类版本兼容性。应显式声明，否则JVM自动生成哈希值，类结构稍有变化即导致InvalidClassException。

### 12.6 BIO vs NIO对比

| 特性 | BIO（传统IO） | NIO（JDK 4+） |
|------|-------------|---------------|
| 阻塞 | 阻塞 | 非阻塞 |
| 数据载体 | 流（单向） | 通道 + 缓冲区（双向） |
| 线程模型 | 一个连接一个线程 | 一个线程管理多个连接（Selector） |
| 性能 | 低（连接数多时） | 高（支持高并发） |
| 适用场景 | 连接数少、固定架构 | 连接数多、高并发场景 |

### 12.7 NIO三大核心组件

- **Buffer（缓冲区）**：数据载体，通过position、limit、capacity三个指针管理状态，`flip()`切换读/写模式。
- **Channel（通道）**：双向数据传输，支持零拷贝。
- **Selector（选择器）**：单线程管理多Channel事件监听，实现高并发。

### 12.8 为什么字符流能解决乱码

字符流底层使用InputStreamReader/OutputStreamWriter将字节流转为字符流并进行编码/解码。手动指定UTF-8编码后，读写使用相同编解码规则，避免乱码。不指定则使用系统默认编码（Windows=GBK），跨平台易乱码。

### 12.9 flush()和close()的区别

`flush()`强制刷新缓冲区数据到目的地（字符流必须调用）；`close()`关闭流并自动调用flush()。close()包含flush()语义，但应在关键节点调用flush()确保数据及时写入，而非频繁close()。

### 12.10 Files工具类与File类的对比

Files（NIO.2）优于File：抛异常而非返回boolean、支持符号链接和完整文件属性、提供`readAllLines()`/`walk()`/`copy()`等便捷方法、支持原子操作。新项目应优先使用Path + Files API。
