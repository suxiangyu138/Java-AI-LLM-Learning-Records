## 1. Collections vs Collection：一字之差

**最经典的命名混淆**（面试第一题）：

| 类 | 类型 | 作用 |
|----|------|------|
| `Collection<E>` | **接口** | 集合的根接口（List/Set/Queue 的父） |
| `Collections` | **工具类** | 静态方法操作集合（sort/reverse 等） |

```java
// 集合接口：Collection<E> 声明
Collection<String> c = new ArrayList<>();
c.add("a");

// 工具类：Collections 静态调用（不可实例化）
Collections.sort(list);
Collections.reverse(list);
// 现代：list.sort(cmp)（List 自带，JDK 8+）替代 Collections.sort
```

**现代替代趋势**（2026）：

```text
Collections.sort(list, cmp) → list.sort(cmp)（JDK 8+）
Collections.emptyList() → List.of()（JDK 9+）
Collections.unmodifiableList(l) → List.copyOf(l)（JDK 10+，语义不同）
Collections.singletonList(x) → List.of(x)（JDK 9+）
→ Collections 仍用于：同步包装/不可变视图（无 of 替代时）
```

> 🎯 **核心要点**：一字之差 = "**Collection 接口 vs Collections 工具类**"——**现代代码逐步用 List 自带方法与 of 家族替代 Collections**，但 synchronizedXxx/unmodifiableXxx 视图仍无可替代。

## 2. 排序与查找函数

```java
// 排序（现代：list.sort 优先）
Collections.sort(list);                    // 自然序
Collections.sort(list, comparator);        // 自定义
list.sort(comparator);                     // ✅ 现代首选（List 自带）

// 反转与旋转
Collections.reverse(list);                 // 原地反转
Collections.rotate(list, 2);               // 循环右移 2 位

// 二分查找（必须先排序！）
Collections.binarySearch(list, key);       // 索引或 -(插入点)-1

// 极值
Collections.max(list);                     // 最大（自然序）
Collections.min(list, comparator);         // 最小（自定义）

// 洗牌与填充
Collections.shuffle(list);                 // 随机打乱
Collections.fill(list, "x");               // 全部替换

// 频率与不相交
Collections.frequency(list, "a");          // 出现次数
Collections.disjoint(list1, list2);        // 是否无交集
```

**排序的注意**：

```text
① List 的 sort 是 TimSort（稳定，O(n log n)）
② binarySearch 前提 = 已排序（否则结果未定义）
③ frequency 依赖 equals（自定义对象需重写）
④ shuffle 可传 Random 控制种子（测试可复现）
```

> 🎯 **核心要点**：排序查找 = "**list.sort 现代首选 + binarySearch 先排序 + frequency/max 依赖比较器**"——**"二分必须先排序"与"frequency 依赖 equals"是两个前提条件考点**（与 `Java集合框架/07` 联动）。

## 3. 不可变包装：unmodifiableXxx

**unmodifiableXxx = "不可变视图"**（包装而非复制——原集合可改，视图跟着变）：

```java
List<String> inner = new ArrayList<>(List.of("a"));
List<String> view = Collections.unmodifiableList(inner);

view.add("b");         // ❌ UnsupportedOperationException（视图拒绝修改）
inner.add("b");        // ✅ 原集合还能改！
view.size();           // 2（视图"看到"了变化——写穿！）

// 三兄弟：unmodifiableList / unmodifiableSet / unmodifiableMap
```

**unmodifiable 视图 vs 真正不可变（of/copyOf）**：

| 维度 | unmodifiableList（视图） | List.of/copyOf（真不可变） |
|------|:------------------------:|:--------------------------:|
| 复制 | ❌（引用原集合） | ✅（复制后脱离） |
| 原集合可改？ | ✅（视图被穿透） | ❌（彻底隔离） |
| 防御场景 | 防"调用方改内部字段" | 常量/快照 |
| 版本 | 一直 | JDK 9+/10+ |

```java
// 防御性编程的标准姿势（对外暴露内部字段）：
public List<String> getItems() {
    return Collections.unmodifiableList(this.items);   // 防调用方修改内部
}
// 但内部自己改 → 视图跟着变（期望行为）
```

> 🎯 **核心要点**：unmodifiable = "**视图（原集合可改，防的是调用方）**"——**"视图会被穿透"是它与 of/copyOf 的本质区别**（详见 `Java集合框架/08`）；防御性暴露内部字段用它。

## 4. 同步包装：synchronizedXxx

**synchronizedXxx = 方法级全局锁包装**（简单但粗）：

```java
List<String> syncList = Collections.synchronizedList(new ArrayList<>());
Map<String, Object> syncMap = Collections.synchronizedMap(new HashMap<>());

// ⚠️ 迭代必须手动加锁（文档明确要求）：
synchronized (syncList) {                     // 锁"集合对象本身"
    for (String s : syncList) { ... }
}
```

**同步包装的三大问题**（与 `Java集合框架/06` 联动）：

```text
① 全局锁：所有方法串行（并发度 1）
② 迭代要手动同步：忘记 synchronized 块 → 迭代 ConcurrentModificationException
③ 复合操作无原子性：check-then-act 仍竞态
→ 现代：Map 用 ConcurrentHashMap、List 读多写少用 CopyOnWriteArrayList
```

**适用边界**（什么时候还能用）：

```text
① 遗留代码兼容过渡
② 并发度极低（基本单线程访问）
③ 需要"同步 + 不可变"双包装组合
→ 其余场景用并发容器（并发度与语义都更好）
```

> 🎯 **核心要点**：同步包装 = "**全局锁 + 迭代手动同步 + 复合操作无原子**"——**"能用并发容器就不用 synchronizedXxx"**是 2026 共识（CHM/COW 提供了更好的并发语义）；面试答"为什么不用 synchronizedMap"给三连。

## 5. empty / singleton / nCopies 家族

**空集合与单元素集合**（判空的零分配优化）：

```java
// 空集合（共享单例——判空返回不新建对象）
Collections.emptyList();      // 共享的 EMPTY_LIST
Collections.emptySet();
Collections.emptyMap();
// JDK 9+ 等价：List.of()

// 单元素集合
Collections.singletonList("a");    // 单元素不可变列表
Collections.singleton("a");        // 单元素 Set
Collections.singletonMap("k", "v");// 单元素 Map

// nCopies：N 个相同元素（共享引用，零拷贝！）
List<String> copies = Collections.nCopies(5, "x");   // [x,x,x,x,x]（内部共享）

// 类型安全检查包装（防原始类型泄漏）
List<String> checked = Collections.checkedList(rawList, String.class);
// 运行时检查：放入错误类型立即抛 ClassCastException（早期失败）
```

**判空的最佳实践**：

```java
// 查询返回空集合（避免调用方 NPE）
public List<User> findUsers() {
    List<User> result = query();
    return result == null ? Collections.emptyList() : result;
    // 或：return result == null ? List.of() : result;
}
// 调用方：for (User u : findUsers()) 直接遍历（空集合安全）
```

> 🎯 **核心要点**：家族 = "**empty（零分配判空）+ singleton（单元素）+ nCopies（共享）+ checked（类型门禁）**"——**"返回空集合而非 null"是防 NPE 的经典实践**；JDK 9+ 的 of 家族是更简洁的替代。

## 6. 函数速查表

**Collections 工具速查**（开发/面试快查）：

| 函数 | 作用 | 坑点 |
|------|------|------|
| sort / reverse / rotate | 排序/反转/旋转 | 现代用 list.sort |
| binarySearch | 二分 | 必须先排序 |
| max / min | 极值 | 需比较器 |
| shuffle | 洗牌 | 可传 Random |
| frequency | 计数 | 依赖 equals |
| unmodifiableXxx | 不可变视图 | **原集合可改（穿透）** |
| synchronizedXxx | 同步包装 | 迭代需手动锁 |
| emptyXxx / singletonXxx | 空/单元素 | of 家族替代 |
| nCopies | N 个共享元素 | 引用共享 |
| checkedXxx | 类型检查 | 早期失败 |

**一句话总结**：

```text
Collections vs Collection：工具 vs 接口
现代替代：list.sort / List.of / copyOf
不可变两形态：视图（unmodifiable）vs 真不可变（of）
同步包装三问题：全局锁/手动迭代锁/复合无原子
判空规范：返回 emptyList 而非 null
```

> 🎯 **核心要点**：速查 10 项 = "**工具函数 + 包装器 + 家族**"三大块——**"现代替代清单（sort/of/copyOf）"是时效性考点**；unmodifiable 穿透与 synchronized 迭代锁是两个最易踩的坑。
