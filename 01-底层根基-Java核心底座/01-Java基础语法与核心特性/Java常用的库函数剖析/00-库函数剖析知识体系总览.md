## 3. 为什么必须学透库函数

1. **使用率最高的代码**：字符串处理、判空、集合操作、时间格式化——**每天写的代码 80% 是"调库函数"**，函数用错 = 每天踩坑。
2. **隐藏的性能与正确性陷阱**：`split` 的空正则、`Integer` 缓存池的 `==`、`BigDecimal` 用 double 构造、`Date` 的线程安全——**每个函数都有"用对姿势"**。
3. **面试高频细节题**："`==` 与 equals 对 Integer""0.1+0.2 等于什么""substring 的截断规则"——库函数是面试细节题的最大来源。
4. **现代 API 的替代**：`Files.readString`、`String.strip`、`List.of`、`LocalDate`——**老函数（trim/Date）被现代替代**，本体系给对照。
5. **与框架代码的直接关联**：MyBatis/Spring/Jackson 底层全是这些库函数——**读源码的前提是熟悉库函数**。

## 4. 核心概念速查

### 4.1 高频函数速查

| 场景 | 现代首选 | 老写法 |
|------|---------|--------|
| 字符串去空白 | `strip()`（JDK 11） | `trim()`（只去 ≤0x20） |
| 读文件 | `Files.readString()`（JDK 11） | `Files.readAllBytes()` |
| 空集合 | `List.of()`（JDK 9） | `Collections.emptyList()` |
| 时间 | `LocalDate.now()`（JDK 8） | `new Date()` |
| 判空抛异常 | `Objects.requireNonNull()` | 手写 if |
| 比较 | `Objects.equals()` | `a.equals(b)`（NPE 风险） |

### 4.2 三大经典陷阱

| 陷阱 | 例子 | 正确姿势 |
|------|------|---------|
| Integer `==` | `Integer.valueOf(127)==127` ✅ 但 128 ❌ | 用 `equals` 或 `intValue` |
| BigDecimal 构造 | `new BigDecimal(0.1)` 不精确 | `new BigDecimal("0.1")` |
| 浮点运算 | `0.1 + 0.2 != 0.3` | BigDecimal 或阈值比较 |

## 7. 常见误区

| 误区 | 真相 |
|------|------|
| "split 是字面量切割" | split 是**正则**——`split(".")` 无效（需转义） |
| "trim 能去所有空白" | 只去 ≤0x20——**NBSP 去不掉，用 strip（JDK 11）** |
| "包装类 == 安全" | **引用比较**（缓存池内除外）——用 equals |
| "BigDecimal 随便构造" | **double 构造不精确**——用 String/valueOf |
| "SimpleDateFormat 可共享" | **线程不安全**——DateTimeFormatter 才可共享 |
| "Date 还能新用" | java.time 全面替代（不可变 + 线程安全） |
| "文件全读进内存" | 大文件必须流式（lines/transferTo）——OOM 风险 |
| "Optional 到处用" | **返回值专用**——字段/参数不用（七反模式） |
