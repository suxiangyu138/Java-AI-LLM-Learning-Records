## 1. Files：现代文件操作首选

**Files（JDK 7，NIO.2）**：文件操作从"样板代码"到"一行调用"：

```java
// 判断与元数据
Files.exists(path);
Files.isDirectory(path);
Files.isRegularFile(path);
Files.size(path);                    // 文件大小
Files.getLastModifiedTime(path);     // 修改时间

// 创建与删除
Files.createFile(path);              // 创建文件（已存在抛异常）
Files.createDirectories(dirPath);    // 递归创建目录（✅ 不抛已存在）
Files.delete(path);                  // 删除（不存在抛 NoSuchFile）
Files.deleteIfExists(path);          // 删除（不存在不抛 ✅）

// 拷贝与移动
Files.copy(src, dst);                // 拷贝
Files.move(src, dst);                // 移动/重命名
Files.copy(src, dst, StandardCopyOption.REPLACE_EXISTING);   // 覆盖

// 列表
Files.list(dir);                     // 目录项（Stream）
Files.walk(dir);                     // 递归遍历（Stream）
```

**Files vs File（旧 API）**：

| 维度 | File（旧） | Files（现代） |
|------|:---------:|:------------:|
| 设计 | 文件+路径混杂 | 路径（Path）+操作分离 |
| 流式 | 无 | Stream 支持（list/walk/lines） |
| 创建目录 | mkdirs（静默失败） | createDirectories（明确异常） |
| 编码 | 默认平台 | 可指定 UTF-8 |

> 🎯 **核心要点**：Files = "**现代文件操作（Path 分离 + Stream 支持）**"——**"createDirectories 递归 + deleteIfExists 不抛"两个友好函数**；旧 File 的 mkdirs 静默失败是经典坑。

## 2. 读写文件：readString / writeString / lines

**JDK 11 的一行读写**（告别样板代码）：

```java
// 读整个文件为字符串（JDK 11 ✅）
String content = Files.readString(Path.of("config.json"), StandardCharsets.UTF_8);

// 写字符串到文件（JDK 11 ✅）
Files.writeString(Path.of("out.txt"), content, StandardCharsets.UTF_8);

// 读字节（JDK 8）
byte[] data = Files.readAllBytes(Path.of("data.bin"));

// 写字节（JDK 8）
Files.write(Path.of("out.bin"), data);

// 追加写
Files.writeString(path, content, StandardCharsets.UTF_8,
        StandardOpenOption.APPEND, StandardOpenOption.CREATE);

// 按行读（懒加载流）
try (Stream<String> lines = Files.lines(Path.of("log.txt"), StandardCharsets.UTF_8)) {
    lines.filter(l -> l.contains("ERROR")).limit(100).forEach(System.out::println);
}
```

**读写选择的速查**：

| 场景 | 首选 | 版本 |
|------|------|:----:|
| 小文本文件 | Files.readString | JDK 11 |
| 二进制 | Files.readAllBytes | JDK 8 |
| 大文件按行处理 | Files.lines（Stream） | JDK 8 |
| 写文本 | Files.writeString | JDK 11 |
| 追加 | writeString + APPEND | JDK 11 |

> 🎯 **核心要点**：读写 = "**readString/writeString（JDK 11 一行）+ lines（大文件流式）**"——**"小文件 readString、大文件 lines、二进制 readAllBytes"三分法**；编码显式 UTF-8 是规范（防平台差异）。

## 3. Path 与路径操作

**Path（JDK 7）：路径的现代抽象**：

```java
// 创建
Path p = Path.of("/data/app/config.json");    // JDK 11（首选）
Path p2 = Paths.get("/data/app", "config.json");   // JDK 7

// 路径操作
p.getFileName();           // config.json
p.getParent();             // /data/app
p.getRoot();               // /
p.getFileName().toString();// 文件名

// 拼接与解析
Path.of("/data").resolve("app");      // /data/app（拼接）
Path.of("/data/app").resolve("config.json");   // 完整路径

// 规范化
Path.of("/data/../etc").normalize();  // /etc（解析 ..）

// 判断
p.startsWith("/data");     // true
p.endsWith("config.json"); // true

// 转字符串
p.toString();              // "/data/app/config.json"
```

**路径操作规范**：

```text
① Path.of 拼接（不要手动字符串拼接（"a" + "/" + "b"）——平台差异）
② resolve 是标准拼接（处理分隔符）
③ 相对 vs 绝对：toAbsolutePath()
④ 与配置文件联动：@Value("${app.data-dir}") + Path.of
```

> 🎯 **核心要点**：Path = "**路径的标准抽象（of/resolve/normalize）**"——**"用 Path.of + resolve 拼接（别手动加 /）"是跨平台规范**；JDK 11 的 Path.of 是 Paths.get 的现代替代。

## 4. 流式处理：lines / transferTo

**大文件与流的现代处理**：

```java
// ① Files.lines：按行懒加载（大文件内存友好）
try (Stream<String> lines = Files.lines(path)) {
    long count = lines.filter(l -> !l.isBlank()).count();
}

// ② transferTo：流到流（JDK 9 ✅）—— 拷贝/下载
try (InputStream in = Files.newInputStream(src);
     OutputStream out = Files.newOutputStream(dst)) {
    in.transferTo(out);          // 一行拷贝（内部缓冲，省内存）
}

// ③ BufferedReader 的 lines（传统）
try (BufferedReader reader = Files.newBufferedReader(path)) {
    reader.lines().forEach(...);
}

// ④ 新字节流（JDK 11）：读固定字节
InputStream in = ...;
byte[] chunk = in.readNBytes(8192);      // 精确读取 N 字节
in.readAllBytes();                        // 读完（注意内存）
```

**流式处理的选型**：

| 场景 | 函数 | 版本 |
|------|------|:----:|
| 大文件逐行 | Files.lines | JDK 8 |
| 流拷贝 | transferTo | JDK 9 |
| 精确读 N 字节 | readNBytes | JDK 11 |
| 全部读完 | readAllBytes | JDK 9（InputStream 上） |

> 🎯 **核心要点**：流式 = "**lines 逐行 + transferTo 拷贝 + readNBytes 精确读**"——**"大文件必须流式（lines/transferTo）而非 readAllBytes 一次读完"是内存安全规范**（大文件 OOM 的根因）。

## 5. 资源管理：TWR 与 AutoCloseable

**IO 资源必须 TWR**（与 `Java异常体系/04` 联动）：

```java
// ✅ 标准姿势：try-with-resources
try (InputStream in = Files.newInputStream(path);
     BufferedReader reader = new BufferedReader(new InputStreamReader(in, UTF_8))) {
    String line = reader.readLine();
    // 无论成败，in 与 reader 自动关闭（逆序）
}

// ❌ 反模式：手动 close（漏 close = 文件句柄泄漏）
InputStream in = Files.newInputStream(path);
// ... 忘记 close / 异常路径不 close

// JDK 9+：引用外部资源变量
InputStream in = getStream();
try (in) {                    // 直接引用（effectively final）
    in.readAllBytes();
}
```

**资源关闭的要点**：

```text
① 一切 IO 流实现 AutoCloseable → 一律 TWR
② 多资源逆序关闭（自动处理）
③ 关闭失败：suppressed 挂主异常（排查看 getSuppressed）
④ 不要手动 close + TWR 混用（双重关闭）
⑤ 线程池/连接池也实现 AutoCloseable（JDK 19+ ExecutorService）
```

> 🎯 **核心要点**：资源管理 = "**一切 AutoCloseable 一律 TWR**"——**"漏 close = 文件句柄泄漏（Too many open files）"是经典生产事故**；TWR 的逆序关闭与 suppressed 机制（`Java异常体系/04` 深度）。

## 6. 函数速查表

**Files/IO 速查**（开发/面试快查）：

| 场景 | 函数 | 版本 | 坑点 |
|------|------|:----:|------|
| 读文本 | Files.readString | 11 | 小文件用 |
| 写文本 | Files.writeString | 11 | 追加需 APPEND |
| 读字节 | readAllBytes | 8 | 大文件 OOM 风险 |
| 逐行 | Files.lines | 8 | 流需关闭 |
| 拷贝 | transferTo | 9 | 流到流 |
| 建目录 | createDirectories | 7 | 递归（✅） |
| 删除 | deleteIfExists | 7 | 不抛（✅） |
| 路径拼接 | Path.of + resolve | 11 | 别手拼 "/" |
| 大小 | Files.size | 7 | — |
| 关闭 | TWR | 7 | 一律 TWR |

**一句话总结**：

```text
Files 现代文件操作：readString/writeString（11）
大文件必须流式：lines/transferTo（内存安全）
路径用 Path.of + resolve（跨平台）
资源一律 TWR（防句柄泄漏）
编码显式 UTF-8（防平台差异）
```

> 🎯 **核心要点**：IO 速查 10 项 = "**Files 全家 + 流式 + TWR**"——**"小文件 readString、大文件流式、资源 TWR、编码 UTF-8"四条规范**覆盖 IO 正确性；每个坑都是生产事故的高发点。
