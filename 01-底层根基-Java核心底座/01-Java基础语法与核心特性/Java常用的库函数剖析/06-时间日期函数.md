## 1. java.time 家族全景

**JDK 8 的 java.time**（JSR 310）：终结 Date/Calendar 的设计缺陷：

| 类 | 含义 | 特点 |
|----|------|------|
| LocalDate | 日期（年-月-日） | 无时区 |
| LocalTime | 时间（时:分:秒.纳秒） | 无时区 |
| LocalDateTime | 日期+时间 | 无时区 |
| **Instant** | 时间戳（UTC） | **存储/传输标准** |
| ZonedDateTime | 带时区完整时间 | 带 ZoneId |
| Period | 日期差（年/月/日） | 人类单位 |
| Duration | 时间差（秒/纳秒） | 机器单位 |
| DateTimeFormatter | 格式化 | **线程安全**（旧 SimpleDateFormat 不安全） |

**为什么淘汰 Date/Calendar**（面试必答）：

```text
① Date 可变 + SimpleDateFormat 线程不安全（共享格式化器 = 数据错乱）
② Calendar 字段语义混乱（MONTH 从 0 开始！）
③ 时区处理痛苦（Date 无时区概念）
→ java.time 全部不可变 + 线程安全 + 语义清晰
```

> 🎯 **核心要点**：java.time = "**不可变 + 线程安全 + 语义清晰**"——**"SimpleDateFormat 线程不安全、LocalDate 不可变"是面试必答**；Instant 是存储标准（时区无关）。

## 2. LocalDate / LocalTime / LocalDateTime

```java
// 创建
LocalDate today = LocalDate.now();
LocalDate date = LocalDate.of(2026, 8, 5);        // 年月日
LocalDate parsed = LocalDate.parse("2026-08-05"); // ISO 格式（yyyy-MM-dd）

LocalTime time = LocalTime.of(14, 30, 15);        // 14:30:15
LocalDateTime dt = LocalDateTime.of(2026, 8, 5, 14, 30);

// 运算（不可变：返回新对象）
date.plusDays(1);                 // 明天
date.minusMonths(2);              // 两个月前
date.plus(3, ChronoUnit.WEEKS);   // 加 3 周
date.withDayOfMonth(1);           // 改到月初

// 判断
date.isAfter(other);              // 晚于
date.isBefore(other);             // 早于
date.isLeapYear();                // 闰年

// 提取
date.getYear(); date.getMonthValue(); date.getDayOfWeek();
date.getDayOfMonth();             // 当月的第几天

// 转换
dt.toLocalDate();                 // 去掉时间
dt.toLocalTime();                 // 去掉日期
date.atTime(LocalTime.NOON);      // 拼时间
```

**LocalDate 的坑**：

```java
LocalDate.parse("2026/08/05");    // ❌ DateTimeParseException（默认 ISO）
LocalDate.parse("2026-08-05");    // ✅（yyyy-MM-dd 是默认格式）
LocalDate.of(2026, 2, 30);        // ❌ 无效日期（校验）
date.plusDays(1);                 // 不赋值 = 丢弃结果！（不可变）
```

> 🎯 **核心要点**：LocalDate = "**不可变（运算返回新对象）+ 默认 ISO 格式**"——**"parse 默认 yyyy-MM-dd、plusDays 必须赋值"两个坑**；与 `Java集合框架/07` 的比较器（日期排序）联动。

## 3. Instant 与时区

**Instant = UTC 时间戳**（存储/传输的标准形态）：

```java
// 创建
Instant now = Instant.now();              // 当前 UTC 时间戳
Instant epoch = Instant.ofEpochSecond(1_700_000_000L);  // 从纪元秒
Instant parsed = Instant.parse("2026-08-05T06:00:00Z"); // ISO 格式

// 运算
now.plusSeconds(60);
now.plus(Duration.ofHours(1));

// 转带时区时间
ZonedDateTime zdt = now.atZone(ZoneId.of("Asia/Shanghai"));
// 时区列表
ZoneId.systemDefault();                   // 系统时区
ZoneId.of("Asia/Shanghai");               // 指定时区
```

**时区处理的规范**（2026 实践）：

```text
① 存储：Instant / 时间戳（UTC）—— 与数据库 TIMESTAMPTZ 对齐
② 展示：按用户时区转 ZonedDateTime
③ 传输：ISO 8601（带 Z 或偏移）
④ 常见坑：本地时间存库（跨时区错乱）→ 必须存 UTC

// 数据库交互（JDBC 4.2+）：setObject/getObject 支持 LocalDate/Instant
```

> 🎯 **核心要点**：Instant = "**UTC 时间戳（存储标准）+ atZone 转展示时区**"——**"存储用 UTC、展示按时区"是时区处理铁律**（跨时区事故的根因常是"本地时间直接入库"）。

## 4. Period / Duration / ChronoUnit

**Period vs Duration：人类单位 vs 机器单位**：

```java
// Period：日期差（年/月/日）—— 人类语义
LocalDate start = LocalDate.of(2024, 1, 1);
LocalDate end = LocalDate.of(2026, 8, 5);
Period p = Period.between(start, end);
p.getYears();         // 2
p.getMonths();        // 7
p.getDays();          // 4

// Duration：时间差（秒/纳秒）—— 机器语义
Instant start = Instant.now();
// ... 耗时操作
Duration d = Duration.between(start, Instant.now());
d.toMillis();         // 毫秒
d.getSeconds();       // 秒

// ChronoUnit：统一单位
long days = ChronoUnit.DAYS.between(date1, date2);       // 相差天数
long months = ChronoUnit.MONTHS.between(date1, date2);   // 相差月数
ChronoUnit.HOURS.between(time1, time2);                  // 相差小时

// 判断过期
boolean expired = end.isBefore(LocalDate.now().minus(90, ChronoUnit.DAYS));
```

**Period vs Duration 速查**：

| 维度 | Period | Duration |
|------|:------:|:--------:|
| 单位 | 年/月/日 | 秒/纳秒 |
| 语义 | 人类（日历） | 机器（精确） |
| 场景 | 年龄/合同期限 | 耗时/超时 |
| 与 LocalDate | ✅ | ❌（需转换） |
| 与 Instant | ❌ | ✅ |

> 🎯 **核心要点**：Period/Duration = "**人类日期差 vs 机器时间差**"——**"算年龄用 Period、算耗时用 Duration"是选择标准**；ChronoUnit 是统一单位的瑞士军刀（between 计算任意单位差）。

## 5. DateTimeFormatter 与线程安全

**DateTimeFormatter：线程安全（可共享）**——旧 SimpleDateFormat 的最大改进：

```java
// 预定义格式
DateTimeFormatter ISO = DateTimeFormatter.ISO_LOCAL_DATE;   // 2026-08-05

// 自定义格式（模式字母）
DateTimeFormatter FMT = DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss");
// y=年 M=月 d=日 H=24小时 h=12小时 m=分 s=秒
// 注意：M（月）与 m（分）大小写敏感！

// 格式化
LocalDateTime now = LocalDateTime.now();
now.format(FMT);                              // "2026-08-05 14:30:15"

// 解析
LocalDateTime parsed = LocalDateTime.parse("2026-08-05 14:30:15", FMT);

// 线程安全：可定义为静态常量共享（SimpleDateFormat 不能！）
// 格式化数字补零：MM（两位月）dd（两位日）
```

**格式化规范**（2026 实践）：

```text
① 常量共享：DateTimeFormatter 静态 final（线程安全）
② 统一格式：团队约定 ISO 或 "yyyy-MM-dd HH:mm:ss"
③ 时区注意：format 时若含时区需 withZone
④ 与 JSON 联动：Jackson 的 JavaTimeModule（LocalDateTime 序列化）
```

> 🎯 **核心要点**：DateTimeFormatter = "**线程安全（可共享常量）**"——**"SimpleDateFormat 每次 new、DateTimeFormatter 共享"是面试高频对比题**；模式字母大小写（M 月/m 分）是最易拼错处。

## 6. 新旧 API 对照

**Date/Calendar → java.time 迁移对照**：

| 场景 | 旧（Date/Calendar） | 新（java.time） |
|------|:------------------:|:---------------:|
| 当前时间 | new Date() | LocalDateTime.now() / Instant.now() |
| 指定日期 | Calendar.set(2026, 7, 5)（月从 0！） | LocalDate.of(2026, 8, 5) |
| 格式化 | SimpleDateFormat（线程不安全） | DateTimeFormatter（线程安全） |
| 日期差 | 手动计算（痛苦） | Period.between / ChronoUnit.between |
| 时区 | TimeZone/Calendar 混乱 | ZoneId + ZonedDateTime |
| 时间戳 | System.currentTimeMillis() | Instant / toEpochMilli |

```java
// 兼容转换（迁移期）：
// Date ↔ Instant
Date legacy = new Date();
Instant instant = legacy.toInstant();
Date back = Date.from(instant);
// 旧 SimpleDateFormat 处理遗留接口数据（仅遗留场景）
```

**迁移建议**（2026）：

```text
① 新代码一律 java.time（无理由用 Date）
② 遗留接口（老 API 返回 Date）→ 入口转 Instant
③ 数据库：JDBC 4.2+ 原生支持 LocalDate/Instant
④ 框架：Spring/Jackson 默认支持 java.time
```

> 🎯 **核心要点**：新旧对照 = "**Date 遗留、java.time 现代**"——**"Calendar 月从 0 开始 + SimpleDateFormat 线程不安全"是旧 API 两大痛点**；新代码零理由用 Date；遗留接口用 toInstant 桥接。

## 7. 函数速查表

**java.time 速查**（开发/面试快查）：

| 场景 | 函数 | 坑点 |
|------|------|------|
| 当前日期 | LocalDate.now() | 无时区 |
| 指定日期 | LocalDate.of(y, m, d) | 无效日期抛异常 |
| 解析 | LocalDate.parse("2026-08-05") | 默认 ISO 格式 |
| 运算 | plusDays/minusMonths | 不可变（要赋值） |
| 存储 | Instant.now() | UTC 标准 |
| 时区 | atZone(ZoneId.of(...)) | 存储用 UTC |
| 日期差 | Period.between | 人类单位 |
| 耗时 | Duration.between | 机器单位 |
| 格式化 | DateTimeFormatter.ofPattern | 线程安全可共享 |
| 月份 | getMonthValue() | 1-12（非 Calendar 的 0-11） |

**一句话总结**：

```text
java.time 核心认知：
  不可变 + 线程安全（vs Date/SimpleDateFormat）
  LocalDate 本地语义 / Instant UTC 存储
  Period 人类差 / Duration 机器差
  DateTimeFormatter 可共享（静态常量）
  存储 UTC、展示按时区
```

> 🎯 **核心要点**：速查 10 项 = "**java.time 完整考点清单**"——**"月从 1 开始（vs Calendar 0 开始）+ ISO 默认格式 + 不可变"三大差异**是迁移期最容易踩的坑；记忆主线 = "不可变、UTC 存储、线程安全格式化"。
