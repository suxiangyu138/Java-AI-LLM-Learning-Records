## 1. 多态的核心概念

> **多态（Polymorphism）** 源自希腊语 "poly"（多）+"morph"（形态），指同一操作作用于不同对象时产生不同的执行结果。它是面向对象编程的**灵魂**，也是实现"对扩展开放、对修改关闭"（开闭原则）的基础。

同一个接口，不同的实现，运行时根据实际对象类型调用对应方法。

```java
Shape s1 = new Circle(5);       // 编译看左边（Shape），运行看右边（Circle）
Shape s2 = new Rectangle(3, 4);
System.out.println(s1.area());  // 78.54 — 实际调用 Circle.area()
System.out.println(s2.area());  // 12.0  — 实际调用 Rectangle.area()
```

### 1.1 三大前提

| 前提条件 | 说明 |
|---------|------|
| **继承/实现** | 必须存在继承关系或接口实现关系 |
| **方法重写** | 子类必须重写父类的某个方法 |
| **父类引用指向子类对象** | `Parent p = new Child();` |

> 💡 没有重写就没有运行时多态。如果子类没有重写父类方法，调用的是父类的方法，不构成多态。

### 1.2 多态的分类

| 类型 | 实现方式 | 发生时机 | 绑定机制 | 示例 |
|------|---------|---------|---------|------|
| **编译时多态** | 方法重载（Overload） | 编译期 | 静态绑定 | `print(int)` vs `print(String)` |
| **运行时多态** | 方法重写（Override） | 运行期 | 动态绑定 | 父类引用指向子类对象 |

> 🎯 编译时多态解决"同一个方法名处理不同参数"的问题；运行时多态解决"同一个方法调用、不同行为表现"的问题。后者是 OOP 多态的典型含义。

## 2. 编译时多态：方法重载

**方法重载（Method Overloading）** 指在同一类中，多个方法名称相同但参数列表不同。编译器在**编译期**根据调用参数决定调用哪个版本。

### 2.1 重载规则

| 规则 | 说明 |
|------|------|
| 方法名 | 必须相同 |
| 参数列表 | 必须不同（个数/类型/顺序至少一个不同） |
| 返回值 | **不能**作为区分重载的依据 |
| 访问修饰符/异常 | 无限制 |

```java
public class MathUtils {
    public int add(int a, int b) { return a + b; }
    public double add(double a, double b) { return a + b; }
    public int add(int a, int b, int c) { return a + b + c; }
    // ❌ 仅返回值不同不算重载：public long add(int a, int b) { ... }
}
```

### 2.2 常见场景与陷阱

```java
// 构造方法重载
public class User {
    public User() {}
    public User(String name) { this.name = name; }
    public User(String name, int age) { this.name = name; this.age = age; }
}

// 自动装箱导致的重载陷阱
public class Trap {
    public void print(Integer i) { System.out.println("Integer"); }
    public void print(int i)    { System.out.println("int"); }
}
print(42);  // 输出 "int" — 精确匹配优先于自动装箱
```

> ⚠️ **重载选择优先级**：精确匹配 > 自动装箱/拆箱 > 向上转型 > 可变参数

## 3. 运行时多态：方法重写与动态绑定

**方法重写（Method Overriding）** 指子类对父类中允许访问的方法重新定义实现。

### 3.1 重写规则

| 规则 | 说明 |
|------|------|
| 参数列表 | 必须完全一致 |
| 返回值类型 | 相同或父类返回值的子类型（**协变返回类型**） |
| 访问修饰符 | 不能比父类更严格（可更宽松：`protected` → `public`） |
| 异常声明 | 不能比父类更宽泛（可不抛或抛子类异常） |
| `final` / `static` / `private` | 均不能被重写（`static` 只能隐藏，`private` 属新方法） |
| `@Override` | 强烈建议使用——编译器检查方法签名 |

```java
class Shape {
    public double area() { return 0; }
}
class Circle extends Shape {
    private double radius;
    public Circle(double radius) { this.radius = radius; }
    @Override
    public double area() { return Math.PI * radius * radius; }
}
class Rectangle extends Shape {
    private double width, height;
    public Rectangle(double w, double h) { this.width = w; this.height = h; }
    @Override
    public double area() { return width * height; }
}
```

### 3.2 动态绑定机制

**动态绑定（Dynamic Binding / Late Binding）** —— 在运行时根据对象的实际类型决定调用哪个方法，而非在编译期。

```java
public static void printArea(Shape shape) {
    System.out.println("面积: " + shape.area());  // 运行时多态
}
printArea(new Circle(10));      // 调用 Circle.area()
printArea(new Rectangle(5, 6)); // 调用 Rectangle.area()
// 新增形状类无需修改 printArea — 符合开闭原则
```

### 3.3 Override vs Overload

| 对比维度 | 重写（Override） | 重载（Overload） |
|----------|-----------------|------------------|
| 发生范围 | 子类与父类之间 | 同一类中 |
| 参数列表 | 必须完全一致 | 必须不同 |
| 返回值 | 相同或子类型（协变） | 无要求 |
| 访问修饰符 | 不能更严格 | 无要求 |
| 绑定机制 | 运行时多态（动态绑定） | 编译时多态（静态绑定） |
| 核心作用 | 扩展父类方法，实现子类特有逻辑 | 同一方法名处理不同参数 |

## 4. 向上转型与向下转型

### 4.1 向上转型（Upcasting）

子类对象赋给父类引用，**自动、安全**。

```java
Dog dog = new Dog();
Animal animal = dog;       // 向上转型，自动隐式转换
animal.eat();              // OK — 调用 Dog 重写的 eat()
// animal.bark();          // ❌ 编译错误：Animal 类型无 bark 方法
```

> 💡 **"面向抽象编程"** 的本质就是向上转型——将变量声明为抽象类型，运行时指向具体实现，降低耦合。

### 4.2 向下转型（Downcasting）

父类引用还原为子类引用，**强制、可能不安全**，需 `instanceof` 检查。

```java
Animal animal = new Dog();
if (animal instanceof Dog) {        // 先检查
    Dog dog = (Dog) animal;         // 再强制转型
    dog.bark();                     // 调用子类特有方法
}

// Dog d = (Dog) new Animal();      // ❌ ClassCastException!
```

### 4.3 转型关系

```
多态 = 向上转型 + 方法重写 + 动态绑定

Animal a = new Dog();   // 向上转型 — 只能调 Animal 的方法（实际执行 Dog 的实现）
Dog d = (Dog) a;        // 向下转型 — 恢复为 Dog，可调 Dog 特有方法
```

## 5. instanceof运算符与类型检查

### 5.1 基础用法

`instanceof` 判断对象是否为某个类型（类、接口及其子类/实现类）的实例。

```java
"hello" instanceof String;        // true
"hello" instanceof Object;        // true
null instanceof String;           // false（null 不是任何类的实例）
```

### 5.2 传统方式 vs JDK 16+ 模式匹配

```java
// 传统方式：instanceof + 显式转型（样板代码多）
if (obj instanceof String) {
    String s = (String) obj;
    System.out.println(s.length());
}

// JDK 16+ 模式匹配：类型检查与变量声明合一
if (obj instanceof String s) {            // 直接声明变量
    System.out.println(s.length());
}
if (obj instanceof String s && s.length() > 5) {  // 结合条件判断
    System.out.println(s.toUpperCase());
}
```

> 💡 模式匹配消除了传统 `instanceof` + 显式转型的样板代码，且 `null` 始终返回 `false`，后续变量使用安全。

## 6. 多态的实现原理（虚方法表）

### 6.1 虚方法表（vtable）

JVM 通过**虚方法表**实现运行时多态。每个类在方法区维护一张虚方法表，存储该类所有方法的地址。

```
Shape 虚方法表:            Circle 虚方法表:
┌────────────────────┐    ┌────────────────────┐
│ area() → Shape     │    │ area() → Circle    │ ← 指向重写后
│ toString() → Object│    │ toString() → Object│
└────────────────────┘    │ getRadius()→Circle │ ← 特有方法
                          └────────────────────┘
```

### 6.2 执行流程

调用 `s1.area()`（`s1` 声明为 `Shape`，实际为 `Circle`）：
1. **编译期**：检查 `Shape` 是否有 `area()` 方法签名 → 通过
2. **运行期**：从 `Circle` 的虚方法表查找 `area()` → 调用 `Circle::area`

### 6.3 静态绑定 vs 动态绑定

| 绑定类型 | 时机 | 依据 | 适用场景 |
|---------|------|------|---------|
| **静态绑定** | 编译期 | 变量声明类型 | `static`、`private`、`final` 方法，字段访问 |
| **动态绑定** | 运行期 | 对象实际类型 | 普通实例方法（非 private/static/final） |

```java
Parent p = new Child();
p.staticMethod();      // "Parent static"   — 静态绑定
p.instanceMethod();    // "Child instance"  — 动态绑定
```

> 💡 `final` 方法不可重写，JIT 编译器可对其内联优化，是重要性能优化手段。

## 7. 多态中成员访问规则

### 7.1 访问规则总结

| 成员类型 | 编译时（看左边） | 运行时（看右边） | 是否多态 |
|---------|----------------|----------------|:-------:|
| **实例方法** | 检查声明类型是否有该方法 | 调用实际类型重写后的方法 | ✅ |
| **静态方法** | 调用声明类型的方法 | 隐藏 | ❌ |
| **成员变量** | 访问声明类型的变量 | 隐藏 | ❌ |
| **静态变量** | 访问声明类型的变量 | 隐藏 | ❌ |

```java
Parent p = new Child();
System.out.println(p.name);          // "Parent"     — 变量无多态
System.out.println(p.staticName);    // "ParentStatic" — 静态变量无多态
p.say();                             // "Child say"  — 实例方法有多态！
p.staticSay();                       // "Parent staticSay" — 静态方法无多态
```

> ⚠️ **Java 中只有实例方法具有多态性**。成员变量、静态方法、静态变量均为编译时绑定，访问声明类型对应的成员。这是面试高频陷阱。

### 7.2 构造方法中调用可重写方法的危险

```java
class Parent {
    Parent() { init(); }            // 构造中调用可重写方法
    public void init() { System.out.println("Parent init"); }
}
class Child extends Parent {
    private String value = "child-value";
    @Override
    public void init() {
        System.out.println(value.length());  // NullPointerException!
    }
}
new Child();  // Parent() → 动态绑定调用 Child.init() → value 尚未初始化
```

> ⚠️ **构造方法中避免调用可重写方法**。父类构造器执行时，子类字段尚未初始化，动态绑定调用子类重写方法会导致 NPE。

## 8. 多态的实际应用场景

### 8.1 面向接口编程

```java
interface MessageSender { void send(String message); }
class EmailSender implements MessageSender {
    public void send(String msg) { System.out.println("邮件: " + msg); }
}
class SmsSender implements MessageSender {
    public void send(String msg) { System.out.println("短信: " + msg); }
}

public class NotificationService {
    private final MessageSender sender;         // 依赖接口
    public NotificationService(MessageSender s) { this.sender = s; }
    public void send(String msg) { sender.send(msg); }  // 运行时多态
}
new NotificationService(new EmailSender());
new NotificationService(new SmsSender());
```

### 8.2 集合统一处理

```java
List<Shape> shapes = Arrays.asList(new Circle(5), new Rectangle(3, 4));
double total = 0;
for (Shape s : shapes) total += s.area();  // 多态调用各自的 area()
```

### 8.3 策略模式

```java
interface PayStrategy {
    boolean supports(String channel);
    PayResult pay(PayRequest request);
}
class AlipayStrategy implements PayStrategy { /* ... */ }
class WechatPayStrategy implements PayStrategy { /* ... */ }

class PayContext {
    private final List<PayStrategy> strategies;
    public PayResult execute(String channel, PayRequest req) {
        return strategies.stream()
            .filter(s -> s.supports(channel)).findFirst()
            .orElseThrow(() -> new IllegalArgumentException("不支持的渠道"))
            .pay(req);   // 运行时多态
    }
}
```

## 9. 多态与设计模式

多态是 GoF 23 种设计模式的**基石**。典型应用：

| 设计模式 | 类别 | 多态的应用方式 |
|---------|------|---------------|
| **策略模式** | 行为型 | 定义策略接口，不同实现封装算法，运行时切换 |
| **模板方法模式** | 行为型 | 父类定义算法骨架，子类重写步骤方法 |
| **工厂方法模式** | 创建型 | 工厂接口定义创建方法，子工厂决定具体产品 |
| **观察者模式** | 行为型 | 观察者接口的统一注册与通知 |
| **装饰器模式** | 结构型 | 通过接口的层层包装实现功能增强 |

```java
// 模板方法模式示例
abstract class AbstractLogger {
    public void writeLog(String msg) {       // 模板方法
        if (!isEnabled()) return;
        log(format(msg));                    // 多态调用
    }
    protected abstract void log(String msg); // 由子类实现
    protected boolean isEnabled() { return true; }
    protected String format(String msg) { return "[" + LocalDateTime.now() + "] " + msg; }
}
class FileLogger extends AbstractLogger {
    protected void log(String msg) { System.out.println("写入文件: " + msg); }
}
```

## 10. 常见陷阱与最佳实践

### 10.1 常见陷阱

| 陷阱 | 说明 | 正确做法 |
|------|------|---------|
| **向下转型不检查** | 直接 `(SubType)` 抛出 `ClassCastException` | 转型前用 `instanceof` 检查 |
| **构造中调用可重写方法** | 子类字段未初始化，动态绑定导致 NPE | 只调 `private/final` 方法 |
| **误认为成员变量有多态** | 变量访问是编译时绑定 | 只有实例方法有多态 |
| **误认为静态方法有多态** | 静态方法属于类，编译绑定 | 通过类名调用而非对象引用 |
| **重写忽略 `@Override`** | 方法签名错误变成重载而非重写 | 始终使用 `@Override` |
| **重写时缩小访问权限** | 编译错误 | 只能扩大或保持访问权限 |

### 10.2 最佳实践

| 实践 | 说明 |
|------|------|
| **面向接口/抽象编程** | 变量声明为抽象类型，依赖注入具体实现 |
| **多用组合少用继承** | 继承破坏封装、强耦合；组合更灵活 |
| **使用 `@Override`** | 编译器检查方法签名，避免重写变重载 |
| **构造中不调用可重写方法** | 使用 `private`、`final` 或 `static` 方法替代 |
| **向下转型前用 `instanceof`** | 模式匹配 instanceof 可简化代码 |
| **遵循里氏替换原则（LSP）** | 子类必须能完全替换父类，重写时不能比父类更严格 |

### 10.3 数组协变性的陷阱

```java
String[] strings = new String[10];
Object[] objects = strings;         // 数组是协变的
objects[0] = 42;                    // ❌ ArrayStoreException！
// 泛型则编译期禁止：List<Object> objList = strList; // 编译错误
```

## 11. 面试高频考点

### 11.1 基础问答

| 问题 | 核心要点 |
|------|---------|
| **什么是多态？** | 同一操作不同结果。编译时多态（重载）和运行时多态（重写） |
| **重写和重载的区别？** | 见第 3.3 节对比表 |
| **多态的实现原理？** | 虚方法表 + 动态绑定。编译检查声明类型，运行查虚方法表 |
| **静态方法能重写吗？** | 不能。静态方法编译时绑定，子类同签名只是"隐藏"父类方法 |
| **成员变量有多态吗？** | 没有。变量访问编译时绑定，看声明类型 |

### 11.2 进阶问题

| 问题 | 解析 |
|------|------|
| **构造中能否调可重写方法？** | 技术上允许但极其危险，子类字段未初始化会 NPE |
| **`instanceof` 模式匹配优势？** | JDK 16+，消除样板代码，类型检查与变量声明合一 |
| **向下转型为何要检查？** | 避免 `ClassCastException`，实际类型运行时才能确定 |
| **多态与设计模式的关系？** | 多态是设计模式的基石，策略、模板方法等模式均依赖多态 |
| **final 方法与多态？** | final 禁止重写，编译器可内联优化，性能好但丧失灵活 |

### 11.3 经典代码阅读题

```java
class A {
    public String show(D obj) { return "A and D"; }
    public String show(A obj) { return "A and A"; }
}
class B extends A {
    public String show(B obj) { return "B and B"; }
    public String show(A obj) { return "B and A"; }   // 重写
}
class C extends B {}
class D extends B {}

A a = new B();
System.out.println(a.show(new B()));  // ① "B and A"
System.out.println(a.show(new C()));  // ② "B and A"
System.out.println(a.show(new D()));  // ③ "A and D"
```

> 🎯 ③中 `d` 是 `D` 类型，`A` 中有 `show(D)` 直接精确匹配，且 `B` 未重写 `show(D)`，所以调用 `A` 的 `show(D)`（因 `B` 未重写，动态绑定仍执行 `A` 版本）。
