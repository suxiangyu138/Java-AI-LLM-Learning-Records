## 1. 异常体系概述

Java 异常机制是程序容错的核心，通过统一的 `Throwable` 体系将运行期间的异常分为**可恢复的异常**和**不可恢复的错误**。核心价值：**容错**、**分层传播**、**关注点分离**。

> 💡 异常机制不是流程控制工具，不要用异常代替 if-else 做条件判断。

## 2. Throwable、Error与Exception

### 2.1 层次结构

```
                     +-----------+
                     | Throwable  |
                     +-----+-----+
                           |
              +------------+------------+
              |                         |
         +----v----+             +------v------+
         |  Error   |             |  Exception   |
         +---------+             +------+------+
                                        |
                        +---------------+---------------+
                        |                               |
                   +----v----+                   +------v--------+
                   | RuntimeException |           | Checked       |
                   | (Unchecked)      |           | Exception     |
                   +------------------+           +---------------+
```

### 2.2 Error（错误）

无法处理的严重问题，由 JVM 抛出，**不应捕获**。出现时程序无法恢复，应尽早失败。

| 常见 Error | 触发场景 |
|-----------|---------|
| `StackOverflowError` | 递归过深无终止 |
| `OutOfMemoryError` | 堆/元空间溢出 |
| `NoClassDefFoundError` | 类加载失败 |
| `UnsatisfiedLinkError` | JNI 本地方法找不到 |

> ⚠️ **不要捕获 Error**，应尽早失败而非隐藏问题。

### 2.3 Exception（异常）

程序可处理的异常，分为 Checked（编译时检查）和 Unchecked（RuntimeException）。

## 3. Checked vs Unchecked Exception

### 3.1 对比

| 特性 | Checked Exception | Unchecked Exception |
|------|------------------|--------------------|
| 继承 | Exception（不含 RuntimeException） | RuntimeException |
| 编译检查 | 必须 try-catch 或 throws | 不强制处理 |
| 典型 | IOException、SQLException、ClassNotFoundException | NPE、IllegalArgumentException、ArithmeticException |
| 恢复预期 | 调用者可恢复（如重试） | 编程错误，无法恢复 |
| 现代框架 | 倾向于少用 | 大量使用 |

### 3.2 代码对比

```java
import java.io.*;

// Checked Exception：必须处理，否则编译不通过
public class CheckedExceptionDemo {
    public String readFile(String path) throws IOException {
        try (BufferedReader br = new BufferedReader(new FileReader(path))) {
            return br.readLine();
        }  // 自动关闭，不捕获则异常向上传播
    }

    public String readFileSafe(String path) {
        try (BufferedReader br = new BufferedReader(new FileReader(path))) {
            return br.readLine();
        } catch (IOException e) {
            System.err.println("读取失败: " + e.getMessage());
            return null;
        }
    }
}

// Unchecked Exception：不强制处理，但应预防
public class UncheckedDemo {
    public static void setAge(int age) {
        if (age < 0 || age > 150)
            throw new IllegalArgumentException("年龄不合法: " + age);
    }
}
```

### 3.3 选择原则（Effective Java 第71条）

| 场景 | 推荐类型 | 原因 |
|------|---------|------|
| 调用者可恢复（文件→默认配置） | Checked | 强制调用方考虑恢复 |
| 编程错误（空指针、越界） | Unchecked | 应修复代码而非捕获 |
| 外部资源不可恢复（DB断连） | Unchecked | 捕获也无法恢复 |
| 不确定时 | Unchecked | 避免增加调用方负担 |

## 4. try-catch-finally详解

### 4.1 基本语法

```java
public class TryCatchFinallyDemo {
    public static void main(String[] args) {
        try {
            int result = 10 / 0;
        } catch (ArithmeticException e) {
            System.out.println("算术异常: " + e.getMessage());
        } catch (Exception e) {       // 子类在前、父类在后
            System.out.println("其他异常: " + e.getMessage());
        } finally {
            System.out.println("finally 总是执行");  // 资源清理
        }
    }
}
```

### 4.2 语法规则

| 组合 | 说明 |
|------|------|
| try-catch | 捕获处理异常，无需资源清理 |
| try-finally | 仅清理资源，异常向上传播 |
| try-catch-finally | 最完整形式 |
| try-only | ❌ 至少需要一个 catch 或 finally |

### 4.3 finally 执行时序

```java
@SuppressWarnings("finally")
public static String testFinally() {
    try {
        return "try 返回值";       // ① 计算返回值并暂存
    } finally {
        System.out.println("finally 执行");  // ② 在 return 之前执行
        // return "finally 返回值";  // ❌ 会覆盖 try 的返回值
    }
}
```

**流程**：try 计算返回值（暂存）→ finally 执行 → finally 无 return 则返回暂存值。

## 5. 多重catch与异常匹配顺序

### 5.1 子类在前、父类在后

```java
try {
    int[] arr = null;
    int res = 10 / (arr.length - 2);
} catch (NullPointerException e) {      // 子类在前
    System.out.println("空指针：" + e.getMessage());
} catch (ArithmeticException e) {       // 同级
    System.out.println("算术异常：" + e.getMessage());
} catch (Exception e) {                  // 父类兜底
    System.out.println("其他异常：" + e.getMessage());
}
```

> ⚠️ 多重 catch 必须**子类在前、父类在后**，否则编译报错。

### 5.2 多异常捕获（JDK 7+）

```java
try {
    riskyOperation();
} catch (IOException | SQLException e) {
    // 用 | 同时捕获多个异常，e 隐式 final
    System.err.println("IO 或 SQL 异常: " + e.getMessage());
}
```

## 6. throw与throws

### 6.1 对比

| 关键字 | 位置 | 作用 |
|--------|------|------|
| `throw` | 方法体内 | 主动抛出异常对象，中断执行流 |
| `throws` | 方法签名 | 声明可能抛出的异常类型，告知调用方 |

```java
public class ThrowThrowsDemo {
    public void validateAge(int age) throws IllegalArgumentException {
        if (age < 0) throw new IllegalArgumentException("年龄不能为负: " + age);
    }

    public void processFile(String path) throws IOException {
        if (path == null)
            throw new IllegalArgumentException("路径不能为空");  // RuntimeException 无需声明
        throw new FileNotFoundException("文件不存在: " + path);
    }
}
```

### 6.2 方法重写的异常规则

```java
class Parent {
    public void method() throws IOException, SQLException { }
    public void noException() { }
}

class Child extends Parent {
    // ✅ 可以不抛（更严格）
    @Override public void method() { }
    // ✅ 可以抛子类型
    @Override public void method() throws FileNotFoundException { }
    // ❌ 不能抛父类型：@Override public void method() throws Exception { }
    // ❌ 不能抛新 Checked：@Override public void noException() throws Exception { }
    // ✅ 可以抛 RuntimeException
    @Override public void noException() { throw new RuntimeException(); }
}
```

| 规则 | 说明 |
|------|------|
| 可以不抛 | 子类可不抛任何异常（更严格允许） |
| 可抛子类型 | 子类可抛父类异常的子类型 |
| 不可抛父类型 | 不能抛父类异常的父类型 |
| 不可抛新 Checked | 不能抛父类未声明的新 Checked 异常 |
| Runtime 自由 | RuntimeException 不受 throws 约束 |

## 7. try-with-resources

JDK 7 引入，自动关闭实现了 `AutoCloseable` 的资源，替代 finally 中手动关闭的冗长代码。

```java
public class TryWithResourcesDemo {
    // ---- 传统方式（JDK 7 前）：冗长、易错 ----
    public static void traditional() {
        BufferedReader reader = null;
        try {
            reader = new BufferedReader(new FileReader("test.txt"));
            System.out.println(reader.readLine());
        } catch (IOException e) { e.printStackTrace();
        } finally {
            if (reader != null) try { reader.close(); } catch (IOException e) { }
        }
    }

    // ---- try-with-resources：简洁、安全 ----
    public static void autoClose() throws IOException {
        try (BufferedReader br = new BufferedReader(new FileReader("test.txt"));
             FileWriter fw = new FileWriter("output.txt")) {
            String line;
            while ((line = br.readLine()) != null) fw.write(line + "\n");
        }  // 自动关闭，顺序与创建相反
    }

    // ---- JDK 9+：外部声明的 effectively-final 变量 ----
    public static void jdk9style(String src, String dst) throws IOException {
        var input = new FileInputStream(src);
        var output = new FileOutputStream(dst);
        try (input; output) { /* 直接使用变量名 */ }
    }
}
```

**抑制异常**：try 块和 close() 都抛异常时，close 异常被抑制，try 异常作为主异常。

```java
try (AutoCloseable bad = () -> { throw new Exception("关闭异常"); }) {
    throw new Exception("业务异常");  // 主异常
}  // 关闭异常被抑制，通过 e.getSuppressed() 获取
```

| 接口 | 方法签名 |
|------|---------|
| `AutoCloseable` | `void close() throws Exception` |
| `Closeable` | `void close() throws IOException`（继承 AutoCloseable） |

## 8. 自定义异常

### 8.1 企业级设计

```java
/**
 * 最佳实践：
 * - 类名以 Exception 结尾
 * - 继承 RuntimeException（Unchecked）使代码更简洁
 * - 包含 errorCode 错误码，便于前端/国际化
 * - 实现序列化 serialVersionUID
 * - 提供多构造方法覆盖常见场景
 */
public class BusinessException extends RuntimeException {
    private static final long serialVersionUID = 1L;
    private final String errorCode;

    public BusinessException(String errorCode, String message) {
        super(message); this.errorCode = errorCode;
    }
    public BusinessException(String errorCode, String message, Throwable cause) {
        super(message, cause); this.errorCode = errorCode;
    }
    public BusinessException(String errorCode, String message, Object... args) {
        super(String.format(message, args)); this.errorCode = errorCode;
    }
    public String getErrorCode() { return errorCode; }
}

// 具体异常
public class UserNotFoundException extends BusinessException {
    public UserNotFoundException(Long userId) {
        super("USER_NOT_FOUND", "用户不存在: " + userId);
    }
}
public class InsufficientBalanceException extends BusinessException {
    public InsufficientBalanceException(String accountNo) {
        super("INSUFFICIENT_BALANCE", "账户余额不足: " + accountNo);
    }
}
```

### 8.2 阿里巴巴规范要点

```
【强制】异常不要用来做流程控制
【强制】不要在 finally 块中使用 return
【强制】捕获异常是为了处理，不要捕获后什么都不做
【强制】事务场景被 catch 的异常需手动回滚
【推荐】防止 NPE 是程序员的基本素养
```

## 9. 异常链与异常转译

### 9.1 异常链

将底层异常包装为上层异常，保留 cause 以追踪根因。

```java
public class ExceptionChainingDemo {
    // DAO 层：原始技术异常
    public static void dataAccessLayer() throws SQLException {
        throw new SQLException("数据库连接失败: timeout");
    }

    // Service 层：翻译为业务异常，保留 cause
    public static void serviceLayer() {
        try { dataAccessLayer(); }
        catch (SQLException e) {
            throw new BusinessException("DB_ERROR", "数据库操作失败", e);
        }
    }

    public static void main(String[] args) {
        try { serviceLayer(); }
        catch (BusinessException e) {
            System.err.println("根因: " + e.getCause());  // 保留原始异常
        }
    }
}
```

### 9.2 分层转译

| 层次 | 处理策略 |
|------|---------|
| Controller | 不处理，由全局异常处理器统一捕获 |
| Service | 技术异常→业务异常（BusinessException） |
| DAO | 抛出技术异常（SQLException 等） |

## 10. 全局异常处理与最佳实践

### 10.1 核心原则

**原则一：不要吞没异常**

```java
// ❌ 空 catch：异常无声消失
try { riskyOp(); } catch (Exception e) { /* 什么都不做 */ }

// ✅ 记录日志 + 重新抛出或业务降级
try { riskyOp(); } catch (Exception e) {
    log.error("操作失败", e);
    throw new BusinessException("OP_FAILED", "操作失败", e);
}
```

**原则二：尽早失败（Fail-Fast）**

```java
public void processOrder(Order order) {
    if (order == null) throw new IllegalArgumentException("订单不能为空");
    if (order.getItems() == null || order.getItems().isEmpty())
        throw new IllegalArgumentException("订单必须包含商品");
    // 参数已合法，执行业务逻辑...
}
```

**原则三：提供有意义的异常消息**

```java
// ❌ throw new RuntimeException("失败");
// ✅
throw new BusinessException("PAYMENT_FAILED",
    "用户 %d 支付失败，余额不足", userId);
```

**原则四：不要用异常控制流程**

```java
// ❌ 异常做判断（栈快照开销大）
try { Integer.parseInt(s); } catch (NumberFormatException e) { /* 非数字 */ }
// ✅ 条件判断
if (s != null && s.matches("\\d+")) { /* 是数字 */ }
```

### 10.2 异常性能

| 操作 | 性能 |
|------|------|
| 异常对象创建 | 慢：填充栈跟踪，约 1000~2000 纳秒 |
| try-catch（无异常） | 快：几乎零开销，约 2 纳秒 |
| finally | 快：几乎零开销 |

> 🎯 异常应只用于"异常情况"，不要用异常做流程控制。

### 10.3 检查清单

```
[ ] 所有异常都已记录日志（含完整堆栈）
[ ] 用户看到的是友好消息，非技术细节
[ ] 敏感信息（SQL、路径）不会泄露给客户端
[ ] 无空 catch 块
[ ] 资源使用 try-with-resources 正确关闭
[ ] 事务正确处理回滚
[ ] 自定义异常包含错误码
[ ] 异常链保持完整（cause 未丢弃）
[ ] finally 中没有 return
[ ] 统一异常处理器已配置
```

## 11. finally中return的陷阱

> ⚠️ **经典陷阱，面试高频考点。**

### 11.1 修改返回值无效

```java
public static int getValue() {
    int x;
    try {
        x = 1;
        return x;           // ① 暂存 x=1
    } finally {
        x = 3;              // ② 不影响已暂存的值，返回 1
    }
}
// 输出: 1
```

**机制**：try 中执行 `return x` 时，JVM 先将 x 的值暂存到局部变量表，再执行 finally。finally 中修改不影响已暂存的值。

### 11.2 return 覆盖 try 的 return

```java
public static String test() {
    try { return "try"; }
    finally { return "finally"; }  // ❌ 覆盖 try 的返回值
}
// 输出: "finally"
```

### 11.3 return 吞没异常

```java
public static String test() {
    try { throw new RuntimeException("try 异常"); }
    finally { return "正常"; }  // ❌ return 导致异常被完全忽略！
}
// 输出: "正常"
```

### 11.4 finally 抛新异常覆盖原始异常

```java
public static void test() {
    try { throw new RuntimeException("try 异常"); }
    finally { throw new RuntimeException("finally 异常"); }  // ❌ 覆盖 try 异常
}
// finally 异常取代了 try 异常
```

| 陷阱 | 后果 | 解决 |
|------|------|------|
| finally 中有 return | 覆盖 try/catch 的返回值 | 禁止在 finally 使用 return |
| finally 抛新异常 | 覆盖 try 的原始异常 | finally 只做清理，不抛异常 |
| finally 吞没异常 | try 异常被忽略 | 不要在 finally 中 return |

> 🎯 **铁律：finally 只做资源清理，永远不要 return，永远不要抛出新的异常。**

## 12. 面试高频考点

### 12.1 经典问答

**Q1：Error 和 Exception 的区别？**

| 维度 | Error | Exception |
|------|-------|-----------|
| 性质 | JVM 级别严重问题 | 程序可处理 |
| 处理 | 不应捕获 | 应当处理 |
| 典型 | OOM、StackOverflow | IOException、NPE |

**Q2：Checked 和 Unchecked 区别？**
Checked（如 IOException）编译时强制处理；Unchecked（如 NPE）运行时编程错误。现代框架倾向 Unchecked。

**Q3：try-catch-finally 哪些可省略？**
catch 和 finally 至少出现一个。可 try-finally（不捕获只清理）或 try-catch（不清理只捕获）。

**Q4：finally 何时不执行？**
`System.exit(0)`、线程被 kill、try 中死循环。

**Q5：try-with-resources 关闭顺序？**
后创建的先关闭（逆序）。

**Q6：什么是异常链？**
通过 cause 参数将底层异常包装为上层异常，保留根因便于定位。

**Q7：finally 中有 return 会怎样？**
覆盖 try/catch 的返回值，吞没 try 异常。**严禁！**

**Q8：异常性能成本？**
对象创建开销大（栈跟踪填充），try-catch 无异常时零开销。

### 12.2 避坑速查表

| 原则 | 反例 | 正解 |
|------|------|------|
| 不捕获泛 Exception | `catch (Exception e) {}` | 捕获最具体异常 |
| 不空 catch | `catch (E e) {}` | 至少记录日志 |
| finally 不 return | `finally { return x; }` | 只清理资源 |
| 不用异常控制流程 | NumberFormatException 判数字 | if-else 条件判断 |
| 保留 cause | `throw new MyEx(msg)` | `throw new MyEx(msg, cause)` |
| 子类异常在前 | `catch (Exception)` 放前面 | 子类→父类顺序 |
| 优先 try-with-resources | finally 手动关 | `try (资源) { 使用 }` |
