# 必做开源项目（简历天花板加分）

这 3 个项目非常适合你当前路线：**Java 后端求职 + 中大厂简历加分 + 工程化能力证明**。[cite:3][cite:5]

它们和你前面那批“自研项目”不冲突，反而是互补关系：自研项目体现设计能力，开源项目体现阅读源码、理解企业级工程结构、二次开发和快速落地能力。[cite:3][cite:6]

## 项目价值

对于校招、实习和初级到中级后端岗位，这类项目的真正价值不只是“做过”，而是你能不能讲清楚：业务模块、技术选型、核心链路、性能优化点、你做了哪些二开改造。[cite:3][cite:6]

你做这 3 类项目时，建议统一遵循一个原则：**不要只会跑起来，要做到看得懂、改得动、能包装进简历**。[cite:5][cite:6]

## 1. 仿牛客网社区项目

### 1.1 项目定位

这是典型的社区论坛类项目，业务中等复杂，但覆盖面非常广，特别适合校招 Java 后端面试。[cite:3]

它的优势在于：你能同时讲 Web 开发、Redis、Kafka、Elasticsearch、事务、拦截器、登录鉴权、点赞评论消息通知这些典型企业场景。[cite:3][cite:4]

### 1.2 核心模块

- 用户注册、登录、权限控制
- 发帖、评论、私信、通知
- Redis 点赞
- Kafka 异步通知
- Elasticsearch 搜索
- 热帖排序
- 登录态拦截器与统一权限校验

### 1.3 技术亮点怎么讲

#### 1）Redis 点赞

点赞是高频写操作，非常适合放到 Redis，原因是：

- 写入快，抗高并发。
- 适合做用户维度判重。
- 可以延迟刷盘到 MySQL。

典型 Key 设计：

```text
like:entity:post:{postId} -> Set<userId>
like:user:{userId} -> likedCount
```

面试重点：

- 为什么不用数据库直接存点赞？
- 如何防止重复点赞？
- Redis 和 MySQL 最终一致性怎么做？

#### 2）Kafka 消息通知

社区项目里最适合异步化的场景：

- 点赞后通知作者
- 评论后通知被评论人
- 关注后通知目标用户
- 发帖后异步触发 ES 建索引

这样做的价值：

- 主流程响应更快。
- 系统解耦。
- 后续方便扩展站内信、邮件、推送等能力。

#### 3）ES 搜索

社区项目如果只用 MySQL 模糊查询，面试价值很一般；接入 Elasticsearch 后，项目层次立刻上去。

你可以重点讲：

- 发帖数据同步到 ES。
- 按标题、内容做全文检索。
- 搜索结果高亮。
- 热帖与时间排序结合。

#### 4）事务与拦截器

论坛项目很适合讲这两个点：

- 发帖、评论、消息通知涉及多个表更新时，如何保证事务一致性。
- 登录态校验、权限控制、用户信息注入，为什么用拦截器而不是每个接口手写校验。

### 1.4 简历写法

- 基于 Spring Boot + Redis + Kafka + Elasticsearch 实现社区论坛系统，覆盖发帖、评论、点赞、消息通知、搜索等核心业务模块。[cite:3]
- 使用 Redis 优化点赞等高频交互场景，结合 Kafka 异步解耦通知与索引更新链路，提升系统响应性能与扩展性。[cite:3][cite:6]
- 集成 Elasticsearch 实现社区帖子全文检索与高亮展示，并通过拦截器统一完成登录鉴权与用户上下文处理。[cite:4][cite:6]

### 1.5 你该怎么做二开

不要只做课程原版，建议补这些增强点：

- 热帖榜：按点赞、评论、发布时间综合排序
- 帖子审核：敏感词过滤、发帖状态机
- 用户行为日志：埋点统计
- 管理后台：帖子审核、举报处理
- Docker 部署：MySQL、Redis、Kafka、ES 一键启动

### 1.6 面试价值

这个项目最适合你拿来打基础，因为它几乎把 Java Web 后端核心链路全覆盖了。[cite:3]

如果你能把 Redis、Kafka、ES 这三个点真正讲顺，已经能超过一大批“只会做管理系统”的候选人。[cite:3][cite:6]

## 2. 仿抖音短视频后端

### 2.1 项目定位

这是一个明显比社区项目更偏“大厂业务架构”的项目，面试官会更关注你的系统设计能力，而不是普通 CRUD。[cite:3]

它的重点不是把页面做漂亮，而是把“视频上传、推荐流、关注粉丝关系、热点内容推送”这些链路讲清楚。[cite:3][cite:6]

### 2.2 核心模块

- 用户注册登录
- 视频上传与播放
- 点赞、评论、收藏
- 关注/粉丝关系
- 推荐流
- 热门视频榜单
- 消息通知与推送

### 2.3 技术亮点怎么讲

#### 1）分布式存储

视频文件不能直接丢数据库，通常要放对象存储或分布式文件系统。

你做项目时可以用这些思路：

- MinIO 模拟对象存储
- Nginx 做静态资源访问
- 视频元数据放 MySQL
- 封面、视频 URL、作者信息走数据库管理

这部分面试可以讲：

- 为什么视频内容和业务元数据分离存储？
- 上传成功但数据库写失败怎么处理？
- 大文件上传如何分片？

#### 2）推荐流

推荐流是这个项目最有价值的模块之一。

最开始你不需要上复杂推荐算法，可以先做工程版推荐：

- 关注用户新视频优先
- 热门视频加权
- 最近活跃内容提升权重
- 用户历史行为做简单标签偏好

推荐流本质上就是：

- 候选集召回
- 排序打分
- 分页返回

你在面试中能把这 3 步讲清楚，已经足够有含金量。

#### 3）关注/粉丝关系

这是典型社交关系建模问题。

建议你设计：

```text
follow:user:{userId} -> following list
fans:user:{userId} -> fans list
```

数据库中保留关注关系主表，Redis 做热点关系缓存。

典型问题：

- 如何判断是否已关注？
- 粉丝数、关注数如何快速统计？
- 明星用户粉丝量极大时怎么抗压？

#### 4）热点推送

热点推送适合结合 MQ 和 Redis 来做：

- 视频点赞、评论、播放量写入行为日志
- 异步聚合热度分
- 周期性刷新热门榜单
- 给活跃用户推送热点内容

这部分可以和前面的 XXL-Job、Kafka、Redis 体系联动起来，项目深度会更强。

### 2.4 简历写法

- 设计并实现仿短视频平台后端系统，完成视频上传播放、关注粉丝关系、点赞评论收藏与推荐流等核心业务模块。[cite:3]
- 基于对象存储 + MySQL 管理视频资源与元数据，结合 Redis 缓存用户关系链和热点数据，提升高并发访问性能。[cite:3][cite:6]
- 围绕推荐流构建“召回 + 排序”基础链路，并通过异步热度聚合与消息推送实现热门内容分发能力。[cite:3][cite:6]

### 2.5 你该怎么做二开

建议重点补这几项：

- 视频分片上传
- 点赞、评论、收藏三类行为流统一抽象
- 用户推荐标签模型
- 热点榜单定时刷新
- 评论敏感词过滤
- 黑名单与反刷机制

### 2.6 面试价值

这个项目比社区项目更像“业务系统设计题”，很适合冲击中厂和大厂后端岗位。[cite:3]

如果你能讲明白推荐流和热点聚合，而不是只会做增删改查，这个项目的含金量会非常高。[cite:3][cite:6]

## 3. 企业级权限管理框架（RuoYi-Vue）

### 3.1 项目定位

RuoYi-Vue 是 Java 后端非常经典的企业级后台管理框架学习项目，特别适合理解真实企业项目的工程组织方式。[cite:3][cite:4]

它最大的价值不是“自己从零造一个后台”，而是通过源码学习掌握企业级后台常见的组织方式、权限体系、代码生成器、定时任务、监控与多数据源实践。[cite:4][cite:6]

### 3.2 重点学习模块

- RBAC 权限模型
- 代码生成器
- 多数据源切换
- 定时任务
- 操作日志
- 在线用户管理
- 系统监控
- 菜单、角色、部门、岗位体系

### 3.3 技术亮点怎么讲

#### 1）代码生成器

这是 RuoYi 很有辨识度的部分。

你要学的不是“点一下生成代码”，而是：

- 表结构如何映射为实体、Mapper、Service、Controller
- 后台 CRUD 代码是怎么模板化生成的
- 为什么企业里代码生成器可以提升开发效率
- 生成后的代码还需要做哪些业务改造

#### 2）多数据源

多数据源是中大厂常见需求，比如：

- 主库业务数据
- 从库查询
- 历史归档库
- 第三方业务库接入

你要重点理解：

- 动态切换数据源的实现方式
- 事务在多数据源下的边界问题
- 为什么不是所有场景都适合随便切库

#### 3）定时任务

RuoYi 通常会整合 Quartz 或类似调度能力，这一点和你前面要做的 XXL-Job 项目可以形成呼应。

你可以从这里学习：

- 任务调度模型
- Cron 表达式
- 任务执行日志
- 失败处理与状态管理

#### 4）监控与日志

企业后台项目一定要重视这部分：

- 登录日志
- 操作日志
- 在线用户监控
- 服务运行状态监控

这部分非常适合你写进简历，因为它能体现你不仅会写业务，还懂工程治理。

### 3.4 简历写法

- 基于 RuoYi-Vue 源码完成企业级权限管理框架学习与二次开发，深入理解 RBAC 权限模型、菜单路由、角色分配与后台工程组织结构。[cite:4][cite:6]
- 学习并实践代码生成器、多数据源切换、定时任务调度、操作日志与系统监控等企业级通用能力模块。[cite:4][cite:6]
- 在源码阅读基础上完成业务二开改造与模块扩展，提升对中后台系统开发规范、权限设计和工程化实践的理解。[cite:4][cite:6]

### 3.5 你该怎么做二开

不要只停留在“跑起来”，建议最少做一个真实业务改造模块，比如：

- 学生竞赛管理系统
- 实验室设备预约系统
- 校园活动报名管理系统
- 教培机构课程排课系统

这样做的意义很大：

- 你既有框架学习，又有真实业务落地。
- 面试官问“你改了什么”，你能说出具体模块。
- 简历不会显得像“只会照着教程跑开源项目”。

### 3.6 面试价值

这个项目最适合补“企业级后台经验感”。[cite:4][cite:6]

尤其对校招学生来说，很多人不会讲权限体系、菜单路由、角色分配和工程结构，而你如果能讲出来，会非常加分。[cite:4]

## 项目顺序

结合你当前 Java 后端求职路线，推荐顺序如下：

1. 仿牛客网社区项目
2. RuoYi-Vue 企业级权限管理框架
3. 仿抖音短视频后端

原因：

- 牛客社区项目最适合打牢 Redis、Kafka、ES、事务、拦截器这些面试高频点。[cite:3]
- RuoYi-Vue 最适合补企业级后台工程经验与源码阅读能力。[cite:4][cite:6]
- 仿抖音短视频后端技术亮点最强，但系统复杂度也最高，适合放到后面冲高阶。[cite:3][cite:6]

## 简历组合建议

你最推荐的组合方式不是只写开源项目，而是“开源项目 + 自研项目”混搭：[cite:3][cite:6]

- 开源项目：证明源码阅读、框架理解、企业工程经验
- 自研项目：证明独立设计、系统思维、架构能力
- AI 项目：证明差异化竞争力与新技术结合能力

比较适合你的组合：

- 仿牛客网社区项目
- RuoYi-Vue 二开业务项目
- 多级缓存商品详情页 / 分布式短链接系统
- Java + AI 大模型应用项目

## 最终建议

如果你现在时间有限，优先级最高的是：**先做仿牛客网社区项目，再做 RuoYi-Vue 二开**。[cite:3][cite:4]

因为这两个项目一个补“高频中间件与业务链路”，一个补“企业级后台工程化”，对你当前 Java 后端简历提升最直接。[cite:3][cite:4][cite:6]
