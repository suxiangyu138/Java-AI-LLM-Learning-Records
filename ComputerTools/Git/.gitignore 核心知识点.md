# .gitignore 核心知识点
`.gitignore` 是 Git 的**忽略规则文件**，作用是**让 Git 永久不追踪指定文件/文件夹**，避免把无用、敏感、临时文件提交到仓库。

## 一、核心作用
1. 忽略**自动生成文件**（日志、缓存、编译产物）
2. 忽略**敏感文件**（密码、密钥、配置文件）
3. 忽略**大文件/本地文件**（IDE配置、虚拟环境、安装包）
4. 保持仓库干净，只提交核心代码

## 二、基础语法（必记5条）
| 规则 | 含义 | 示例 |
|------|------|------|
| `文件名` | 忽略**所有**叫这个名字的文件 | `debug.log` |
| `/文件夹名/` | 忽略**根目录**下的整个文件夹 | `/node_modules/` |
| `*.后缀` | 忽略**所有**该后缀的文件 | `*.log`、`*.tmp` |
| `!文件名` | **不忽略**（例外，优先级最高） | `!important.log` |
| `文件夹/*` | 忽略文件夹内所有内容 | `build/*` |

### 补充规则
- `#`：注释行，不生效
- `/`：表示**根目录**（避免递归匹配）
- `**`：匹配任意层级目录（`src/**/*.js` 匹配src下所有js文件）

## 三、生效规则
1. **只对未被Git追踪的文件生效**
   已经提交过的文件，即使写进 `.gitignore` 也不会自动忽略。
2. **优先级**：例外规则 `!` > 普通忽略规则
3. **位置**：放在**项目根目录**最通用，也可放子目录（仅作用于子目录）

## 四、常用模板
### 通用前端/项目模板
```gitignore
# 依赖文件夹
/node_modules/
/vendor/

# 编译产物
/dist/
/build/
/out/

# 日志文件
*.log
npm-debug.log*
yarn-debug.log*

# 环境变量/密钥
.env
.env.local
.env.production

# IDE配置
.idea/
.vscode/
*.swp
*.sublime-*

# 系统文件
.DS_Store
Thumbs.db
```

## 五、高频问题解决
### 1. 已提交的文件，想忽略它
执行这两条命令（Git会停止追踪该文件）：
```bash
git rm --cached 要忽略的文件/文件夹
git commit -m "停止追踪xxx文件"
```

### 2. 规则不生效
- 检查文件是否**已被Git追踪**（已提交过）
- 检查规则语法是否写错（比如文件夹漏写 `/`）
- 清除Git缓存：`git rm -r --cached .` 再重新提交

### 3. 查看哪些文件被忽略
```bash
git status --ignored
```

## 六、最佳实践
1. **项目初始化就创建 `.gitignore`**，不要等文件提交后再补
2. 不手动写全，直接用[官方模板](https://github.com/github/gitignore)
3. 绝对不提交：密钥、密码、本地配置、大文件、编译缓存
4. 用 `/文件夹/` 格式忽略文件夹，效率最高

### 总结
1. 核心：**让Git不追踪指定文件**，只保核心代码
2. 必记语法：`文件名`、`*.后缀`、`/文件夹/`、`!例外`
3. 关键：只对**未追踪文件**生效，已提交文件需清缓存
4. 直接用通用模板，避免手写出错
