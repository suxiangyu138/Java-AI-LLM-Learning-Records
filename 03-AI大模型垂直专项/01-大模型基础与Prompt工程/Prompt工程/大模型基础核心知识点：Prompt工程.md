## 1. 核心定义

**Prompt 工程（提示工程）** 是大模型应用的核心辅助技术，通过科学设计和合理优化输入指令（Prompt），精准引导大模型输出符合用户预期的结果。与传统模型优化方式不同，Prompt 工程无需修改模型底层代码或进行二次训练，仅通过调整输入内容的表述、结构和细节，即可显著优化输出效果。

> **核心目标**：最大限度让大模型精准捕捉用户真实需求，减少模糊化和无关化输出，提升响应内容的准确性、相关性和实用性。

---

## 2. 核心原则

### 2.1 清晰具体

避免模糊笼统的表述，细化任务要求、输出格式和各类约束条件，让模型清晰知晓"做什么、怎么做、做到什么程度"。

> **对比示例**：
> - 模糊：写一篇文章
> - 清晰：写一篇 500 字左右、围绕大模型应用的科普短文，语言通俗易懂，适合普通大众阅读

### 2.2 指令明确

优先告知模型"要做什么"，而非反复强调"不要做什么"。使用祈使句，减少模棱两可的表述。

> **对比示例**：
> - 正向引导：重点突出 Prompt 工程的核心原则，每个原则搭配 1 个简单示例
> - 反向约束：不要偏离 Prompt 工程的主题，不要写无关内容

### 2.3 上下文适配

根据任务类型和应用场景，补充必要的背景信息、参考示例或特殊约束。复杂任务可采用分步骤引导方式。

> **示例**：让模型进行专业文本翻译时，补充"目标语言是中文，保留原文的专业术语和核心逻辑，语气正式严谨，符合学术文本表达习惯"。

### 2.4 简洁高效

在保证指令清晰和信息完整的前提下，避免添加冗余信息，防止模型被无关内容干扰。

## 3. 核心技巧

### 3.1 基础技巧（入门必用）

| 技巧 | 说明 | 示例 |
|------|------|------|
| **指令+示例（Few-shot）** | 给出 1-3 个示例，引导模型模仿格式和逻辑 | 先给情感分类示例，再让模型分类新文本 |
| **角色设定** | 赋予模型具体身份，限定输出语气和风格 | "请你作为资深科普作者，用中学生能听懂的语言..." |
| **输出格式指定** | 明确要求分点、加粗、表格等格式 | "用分点、加粗关键词的方式总结 3 个核心技巧" |

### 3.2 进阶技巧（提升输出质量）

**思维链（Chain of Thought, CoT）**：针对逻辑推理和复杂问题，引导模型分步思考，先展示推理过程再给出答案。

> **示例**："计算 123 x 45 + 678，先算 123 x 45 的结果，详细写出计算步骤，再用该结果加上 678，分步写出计算过程和最终答案。"

**反向提示**：明确告知模型需要规避的内容。

> **示例**："不要使用过于学术化的表达，避免出现'大语言模型''预训练''微调'等专业术语。"

**多轮提示**：复杂任务分多轮对话逐步细化需求，先确认核心方向，再补充细节。

> **示例**：先让模型写大纲，确认大纲符合预期后，再根据大纲扩充内容。

## 4. 常见误区

| 误区 | 表现 | 正确的做法 |
|------|------|------------|
| **指令模糊** | "写得好一点""整理一下" | 明确"好"的具体标准 |
| **堆砌无关信息** | 大量背景知识稀释核心任务 | 聚焦核心任务本身 |
| **忽略模型能力边界** | 要求基础模型做专业医学诊断 | 了解模型能力范围 |
| **不做示例引导** | 复杂任务直接要求输出 | 提供 1-3 个参考示例 |

## 5. 核心应用场景

| 场景 | 说明 |
|------|------|
| **内容生成** | 文案、短文、代码、文案润色 |
| **信息处理** | 文本分类、总结、翻译、关键词提取 |
| **逻辑推理** | 数学计算、问题拆解、方案推导 |
| **对话交互** | 客服应答、角色扮演、知识问答 |

## 6. 关键总结

Prompt 工程的核心本质是"与大模型的精准沟通"，无需复杂的技术储备。记住三个核心要点：**清晰指令、必要示例、适配场景**。避开四大误区（指令模糊、堆砌冗余信息、忽略模型边界、不做示例引导），灵活运用基础与进阶技巧，即可让大模型输出高质量结果。

---

## 7. 核心要点回顾

- Prompt 工程是通过优化输入指令引导大模型输出的方法论，无需修改模型参数
- 四大核心原则：清晰具体、指令明确、上下文适配、简洁高效
- 基础技巧（角色设定、Few-shot、格式指定）是入门必备
- 进阶技巧（CoT、反向提示、多轮提示）可显著提升复杂任务效果
- 避开指令模糊、堆砌信息、忽略边界、不做示例四大误区
