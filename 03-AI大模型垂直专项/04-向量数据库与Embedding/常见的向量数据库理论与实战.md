## 一、核心理论基础

### 1.1 核心定义

| 概念 | 说明 |
|------|------|
| **向量嵌入（Embedding）** | 将非结构化数据（文本/图像/音频）通过深度学习模型转为高维实数向量（如 OpenAI `text-embedding-3-small` → 1536 维） |
| **相似性检索** | 计算向量间距离，返回最相似的 Top-K 结果（核心区别于传统 DB 的精确匹配） |
| **k-NN** | k-Nearest Neighbors，返回与查询向量最相似的 k 个向量 |

### 1.2 三种相似性度量

| 度量方式 | 公式核心 | 取值范围 | 适用场景 |
|----------|----------|:------:|----------|
| **余弦相似性** | 方向一致性，忽略模长 | [-1, 1]，越近 1 越相似 | 文本语义检索、图像风格匹配 |
| **欧氏距离** | 空间直线距离 | [0, ∞)，越小越相似 | 图像像素匹配、音频波形对比 |
| **内积** | 向量投影关系 | — | 推荐系统用户-物品匹配 |

### 1.3 四种索引结构

| 索引 | 原理 | 精度 | 速度 | 适用场景 |
|------|------|:---:|:---:|----------|
| **HNSW** ⭐ | 分层图结构，上层导航+底层检索 | 高 | 快 | 主流默认，高并发低延迟 |
| **IVF** | 聚类划分，先定位聚类再精确检索 | 中 | 快 | 大规模数据，常与 PQ 结合 |
| **Flat** | 暴力线性扫描 | 100% | 慢 | 小规模（< 万级）或医疗等精度至上场景 |
| **PQ** | 高维拆分为低维子向量量化编码 | 低 | 极快 | 超大规模，存储成本优化 |

### 1.4 向量数据库 vs 传统数据库

| 维度 | 向量数据库 | 传统数据库（MySQL/Redis/MongoDB） |
|------|-----------|--------------------------------|
| **数据类型** | 高维向量 | 结构化数据（表/键值/文档） |
| **检索方式** | 相似性检索（k-NN、ANN） | 精确匹配（=、LIKE）、键值查找 |
| **索引结构** | HNSW、IVF、PQ 等专用向量索引 | B 树、哈希索引 |
| **适用场景** | RAG、推荐、以图搜图、语义检索 | 业务存储、事务处理 |

### 1.5 主流产品分类

| 类型 | 产品 | 特点 | 适用 |
|------|------|------|------|
| **开源分布式** | Milvus、Weaviate、Qdrant | 大规模、分布式扩展 | 企业级自建 |
| **商业托管** | Pinecone、Zilliz Cloud | 零运维、低延迟 | 中小团队快速落地 |
| **轻量嵌入式** | **Chroma** | API 简单、部署便捷 | 原型开发、小型项目 |
| **搜索库/扩展** | FAISS、pgvector、RedisVL | 无完整 DB 功能 | 二次开发/架构升级 |

## 二、实战一：Chroma（轻量入门）

> 定位：轻量级开源向量数据库，无需复杂部署，API 简洁，适合原型开发。

### 2.1 环境初始化

```bash
pip install chromadb sentence-transformers
```

```python
import chromadb
from sentence_transformers import SentenceTransformer

# 持久化存储（path 参数避免重启丢失）
client = chromadb.PersistentClient(path="./chroma_db")
collection = client.get_or_create_collection(
    name="demo_text_collection",
    metadata={"description": "文本向量集合"}
)
```

### 2.2 数据向量化与入库

```python
# 准备原始数据
raw_data = [
    "向量数据库是专门用于存储、索引和检索高维向量的数据库",
    "HNSW是主流的向量索引结构，兼顾速度与精度",
    "余弦相似性用于衡量向量方向的一致性，适合文本语义检索",
    "Milvus是开源分布式向量数据库，支持大规模数据部署",
    "Chroma是轻量级向量数据库，适合新手入门和原型开发"
]

# 生成 Embedding（384 维）
model = SentenceTransformer('all-MiniLM-L6-v2')
embeddings = model.encode(raw_data)

# 批量入库（Chroma 自动创建 HNSW 索引）
ids = [f"id_{i}" for i in range(len(raw_data))]
metadatas = [{"category": "vector_db", "index": i} for i in range(len(raw_data))]
collection.add(embeddings=embeddings, documents=raw_data,
               ids=ids, metadatas=metadatas)
```

### 2.3 相似性检索

```python
query = "轻量级向量数据库有哪些特点"
query_embedding = model.encode([query])

results = collection.query(
    query_embeddings=query_embedding,
    n_results=3,
    where={"category": "vector_db"},       # 元数据过滤
    include=["documents", "metadatas", "distances"]
)

for i, (doc, dist) in enumerate(zip(results["documents"][0],
                                     results["distances"][0])):
    print(f"结果{i+1}: {doc} | 相似度: {1-dist:.4f}")
```

### 2.4 Chroma 避坑

| 坑点 | 解决 |
|------|------|
| 向量维度不一致 | 查询向量维度必须与库中一致（如均为 384 维） |
| 重启后数据丢失 | `PersistentClient(path=...)` 持久化存储 |
| 过度追求高维 | 384 维已满足大部分文本场景，高维增加成本 |

## 三、实战二：Milvus（企业级分布式）

> 定位：云原生开源向量数据库，支持完整 CRUD、分布式部署、多种索引，适合亿级数据场景。

### 3.1 Docker 部署

```bash
wget https://github.com/milvus-io/milvus/releases/download/v2.4.0/milvus-standalone-docker-compose.yml -O docker-compose.yml
docker-compose up -d
docker-compose ps  # 确认所有容器正常
```

### 3.2 集合创建与索引构建

```python
from pymilvus import connections, Collection, FieldSchema, \
    CollectionSchema, DataType, utility
from sentence_transformers import SentenceTransformer

connections.connect(host='127.0.0.1', port='19530')

# 定义集合 Schema
fields = [
    FieldSchema(name="id", dtype=DataType.INT64, is_primary=True, auto_id=True),
    FieldSchema(name="embedding", dtype=DataType.FLOAT_VECTOR, dim=384),
    FieldSchema(name="text", dtype=DataType.VARCHAR, max_length=500),
    FieldSchema(name="category", dtype=DataType.VARCHAR, max_length=100)
]
schema = CollectionSchema(fields, description="企业级向量存储")

# 创建集合 + 插入数据 + 建索引 + 加载
collection = Collection(name="enterprise_collection", schema=schema)
collection.insert([embeddings, texts, categories])

index_params = {
    "index_type": "HNSW",
    "metric_type": "COSINE",
    "params": {"M": 16, "efConstruction": 64}
}
collection.create_index(field_name="embedding", index_params=index_params)
collection.load()  # ⚠️ 检索前必须加载到内存
```

### 3.3 检索与过滤

```python
query_embedding = model.encode(["Milvus的分布式部署特性"])

search_params = {"metric_type": "COSINE", "params": {"ef": 64}}
results = collection.search(
    data=query_embedding,
    anns_field="embedding",
    param=search_params,
    limit=5,
    expr="category == 'vector_db'",       # SQL 风格元数据过滤
    output_fields=["text", "category"]
)

for i, hit in enumerate(results[0]):
    print(f"结果{i+1}: {hit.entity.get('text')} | 相似度: {hit.score:.4f}")

collection.release()  # 释放内存
```

### 3.4 HNSW 关键参数

| 参数 | 含义 | 默认 | 调优方向 |
|------|------|:---:|----------|
| `M` | 每个节点的邻居数 | 16 | ↑ 提升精度，↑ 增加内存 |
| `efConstruction` | 构建时的搜索宽度 | 64 | ↑ 提升索引质量，↑ 增加构建时间 |
| `ef` | 检索时的搜索宽度 | 64 | ↑ 提升精度，↑ 增加检索延迟 |

## 四、实战三：Pinecone（商业托管）

> 定位：全托管商业向量数据库，零运维、API 调用即可，适合中小团队快速落地。

```python
import pinecone
from sentence_transformers import SentenceTransformer

pinecone.init(api_key="你的Key", environment="us-west1-gcp")
index = pinecone.Index("你的索引名称")

# 数据入库（upsert：存在则更新，不存在则插入）
model = SentenceTransformer('all-MiniLM-L6-v2')
vectors = [(item["id"], model.encode(item["text"]).tolist(),
            {"text": item["text"]}) for item in raw_data]
index.upsert(vectors=vectors)

# 检索
query_vector = model.encode("Pinecone适合哪些场景").tolist()
results = index.query(vector=query_vector, top_k=5, include_metadata=True)

for match in results["matches"]:
    print(f"{match['id']}: {match['metadata']['text']} ({match['score']:.4f})")
```

| Pinecone 特点 | 说明 |
|--------------|------|
| 零运维 | 无需部署，API 调用 |
| 自动索引 | 创建索引时自动管理 |
| 动态更新 | `upsert` 实时写入 |
| 生态集成 | 与 LangChain、OpenAI 无缝对接 |

## 五、RAG 场景落地

> 向量数据库最核心的落地场景：检索外部知识库 → 作为上下文 → LLM 生成精准回答，解决"知识过期"和"幻觉"问题。

```text
用户提问 → Embedding 转查询向量 → 向量数据库检索 Top-K 文档 → 拼接上下文 → LLM 生成答案
```

### 核心代码（Chroma + LangChain）

```python
from langchain.vectorstores import Chroma
from langchain.embeddings import SentenceTransformerEmbeddings
from langchain.chains import RetrievalQA

# 1. 初始化向量存储
embedding_fn = SentenceTransformerEmbeddings(model_name="all-MiniLM-L6-v2")
vectorstore = Chroma(persist_directory="./chroma_db",
                     embedding_function=embedding_fn,
                     collection_name="demo_text_collection")

# 2. 创建 RAG 检索链（配合 LLM）
qa_chain = RetrievalQA.from_chain_type(
    llm=llm,
    chain_type="stuff",      # 将所有检索文档拼接为上下文
    retriever=vectorstore.as_retriever(search_kwargs={"k": 3}),
    return_source_documents=True
)

# 3. 问答
result = qa_chain({"query": "向量数据库的核心索引结构有哪些？"})
print("答案:", result["result"])
print("参考文档:", [d.page_content for d in result["source_documents"]])
```

## 六、总结与选型

### 6.1 产品选型决策

| 场景 | 推荐产品 | 理由 |
|------|----------|------|
| **新手入门/原型开发** | Chroma | 部署简单、API 友好、零运维 |
| **企业级大规模** | Milvus / Zilliz Cloud | 分布式扩展、高可用、亿级数据 |
| **中小团队快速落地** | Pinecone | 零运维、低延迟、专注业务 |
| **已有 PostgreSQL** | pgvector | 无需额外维护数据库 |
| **学术研究/底层优化** | FAISS | 算法丰富、性能极致 |

### 6.2 核心要点

| 要点 | 说明 |
|------|------|
| **本质** | 高维向量相似性检索，核心是 ANN 算法 + 专用索引 |
| **三大度量** | 余弦（语义）/ 欧氏（数值）/ 内积（推荐），按数据类型选 |
| **四大索引** | HNSW（默认首选）/ IVF（大规模）/ Flat（精度至上）/ PQ（压缩） |
| **核心场景** | RAG > 智能推荐 > 以图搜图 > 语义检索 |
| **进阶方向** | 索引参数调优 → 向量压缩（PQ）→ 多模态检索 → 分布式部署 |
