# ChatGPT / DeepSeek 辅助编程核心知识点

> **核心摘要**：ChatGPT 和 DeepSeek 是通用大语言模型，在代码审查、复杂逻辑推演、架构设计、Bug 调试等场景有不可替代的价值。与 IDE 内嵌 AI 工具形成互补关系。

---

## 一、与 IDE 内嵌 AI 的分工

| 场景 | IDE 内嵌 AI（Copilot 等） | 通用 LLM（ChatGPT/DeepSeek） |
|------|---------------------------|------------------------------|
| 代码补全 | 擅长（行内实时补全） | 不适用 |
| 简单方法生成 | 擅长 | 一般 |
| 复杂业务逻辑设计 | 一般 | 擅长（多轮讨论） |
| 架构方案评估 | 不适用 | 擅长 |
| Bug 根因分析 | 一般 | 擅长 |
| 跨文件重构方案 | 不适用 | 擅长 |
| 新技术选型建议 | 不适用 | 擅长 |

## 二、核心编程场景

### 2.1 代码审查与优化

```
Prompt: "请审查以下 Java 代码，关注线程安全、性能、异常处理三个维度，
给出问题和修改建议：\n[粘贴代码]"
```

**审查维度优先级**：线程安全 > 空指针风险 > 资源泄露 > SQL 注入 > 性能隐患

### 2.2 复杂算法与业务逻辑

```
Prompt: "我们需要实现一个订单超时取消功能：
- 订单创建后 30 分钟未支付自动取消
- 需支持 10w+ 并发订单
- 取消后需恢复库存
请给出方案对比（延迟队列 vs Redis 过期回调 vs 定时扫表）"
```

### 2.3 Bug 调试

```
Prompt: "Spring Boot 应用间歇性出现 OutOfMemoryError，以下是堆栈信息：
[粘贴堆栈]
当前：JVM -Xmx2g, 使用 Spring Data JPA
请分析可能的原因和排查步骤"
```

### 2.4 技术方案与选型

```
Prompt: "Java 后端集成大模型能力，LangChain4j vs Spring AI 怎么选？
考虑：团队 Spring 经验丰富、需要 Agent 多步推理、需要私有化部署"
```

## 三、ChatGPT vs DeepSeek 对比

| 维度 | ChatGPT（GPT-4/4o） | DeepSeek |
|------|---------------------|----------|
| 代码生成质量 | 非常高 | 高 |
| 长上下文理解 | 128K tokens | 1M tokens（可读整个代码库） |
| 中文理解 | 优秀 | 顶尖 |
| 代码推理 | 最强 | 强 |
| 价格 | 按量付费 | 极低（甚至有免费额度） |
| 国内访问 | 需科学上网 | 直接访问 |

## 四、高效使用技巧

### 4.1 提示词原则

| 原则 | 示例 |
|------|------|
| 设定角色 | "你是一位资深 Java 架构师，10 年微服务经验..." |
| 明确约束 | "请使用 Java 17、Spring Boot 3.x、不引入第三方库" |
| 分步要求 | "先分析问题，再给出方案对比，最后给出推荐代码" |
| 提供上下文 | "当前项目使用 MyBatis-Plus，Java 17，MySQL 8.0" |

### 4.2 上下文工程

- 粘贴关键代码（相关方法 + 类签名），不是整个文件
- 说明数据库表结构（贴 CREATE TABLE 语句）
- 给出接口定义（入参、出参、异常）

### 4.3 结果验证流程

```
AI 生成代码 → 人工审查（安全/性能/空指针）→ 粘贴入 IDE → 修复编译错误 → 运行单元测试 → 补充边界测试 → 集成测试 → 合并
```

## 五、局限性

1. **训练数据截止日期**：不了解最新框架版本 API 变化
2. **幻觉风险**：可能编造不存在的 API 或依赖
3. **缺乏项目上下文**：不了解现有代码库的约定和架构
4. **数据安全**：不要粘贴生产环境密钥、真实用户数据
5. **需手动操作**：复制粘贴，效率低于 IDE 内置 AI

## 核心要点回顾

- ChatGPT/DeepSeek 是"高级顾问"，不是实时补全工具
- DeepSeek 的 1M 长上下文和极低价格是代码库级分析的利器
- 日常编码（90%）用 IDE 内嵌 AI，复杂问题（10%）用通用 LLM
- 提示词技巧：设定角色、明确约束、分步要求、提供上下文
- AI 生成代码必须经过人工审查，警惕幻觉风险
