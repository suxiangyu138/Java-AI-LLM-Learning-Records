# 大模型工程化

## 📌 定位
**课外自学 | 第二梯队核心 | Java后端+AI的结合点**

这是你"Java后端 + AI方向"最关键的交叉领域——不是训练大模型，而是如何将大模型集成到业务系统中。RAG、Agent、模型部署、Prompt工程是核心技能。

## 🎯 核心章节

### 1. RAG（检索增强生成，⭐ 最重要的落地范式）
- **为什么需要RAG**：大模型有幻觉(编造事实)+知识时效性差+缺乏私有领域知识
- **RAG 标准流程**：
  1. 文档加载(PDF/Word/网页)
  2. 文本分块(Chunking)：固定大小+滑动窗口重叠——平衡语义完整性和检索精度
  3. 向量化(Embedding)：用Embedding模型(text-embedding-3/BGE)将文本块转为向量
  4. 存入向量数据库(Milvus/FAISS)
  5. 用户Query向量化→相似度检索Top-K→拼接进Prompt→LLM生成答案
- **高级RAG**：层级检索+重排序(Reranker)+混合检索(稀疏BM25+稠密向量)
- **GraphRAG**：知识图谱+RAG——实体关系级检索而非文档级

### 2. Agent（智能体，⭐ 2024-2025最热方向）
- **Agent = LLM + 工具调用 + 规划 + 记忆**：
  - LLM作为"大脑"：理解任务、制定计划
  - 工具调用(Function Calling)：搜索/计算器/API/数据库——LLM决定何时调用什么工具
  - 记忆：短期(上下文窗口)+长期(向量数据库存储历史)
  - 规划：ReAct(Reasoning+Acting)、Plan-and-Execute
- **多Agent协作**：多角色分工——AutoGen/CrewAI——这是真正发挥LLM能力的场景
- **Java 实现Agent**：Spring AI+LangChain4j——Java生态接入大模型的主流方案

### 3. 模型部署与推理优化
- **模型量化**：FP16→INT8→INT4——显存/内存大幅缩减，精度损失可控
  - GPTQ/AWQ(需要校准数据)、bitsandbytes(QLoRA量化训练)
- **推理加速**：vLLM(PagedAttention)、TensorRT-LLM(NVIDIA专属)
- **模型服务化**：部署为REST API——Spring Boot调用(vLLM提供OpenAI兼容API)
- **成本优化**：缓存相似问题的回答(Semantic Cache)+小模型处理简单任务+大模型处理复杂任务

### 4. Prompt Engineering
- **基础范式**：Few-shot(给示例)→CoT(思维链)→Self-Consistency(多次采样投票)
- **结构化输出**：要求JSON格式——配合Function Calling实现精确控制
- **Prompt 模板管理**：String Template→版本管理→A/B测试——LangFuse追踪
- **System Prompt设计**：规定角色、约束、输出格式——影响远大于单条用户Prompt

### 5. 安全与评估
- **Prompt注入防御**：用户输入用分隔符+格式校验+权限隔离
- **幻觉检测**：引用溯源(回答必须引用检索到的文档片段)
- **评估指标**：RAGAS(忠实度+相关性)、回答准确性、延迟

## ✅ 学习建议
- RAG是第一优先级——先做一个"上传PDF→提问"的最小可用系统
- 用 Spring AI 或 LangChain4j 写一个Java调用大模型的Demo
- Agent不要一开始就追求复杂——从单工具的ReAct Agent开始
- GitHub搜"RAG"看开源项目(dify/langchain-chatchat)的运行效果
