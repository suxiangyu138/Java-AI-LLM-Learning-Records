# 18 — 大模型厂商与平台选型

> **目标**：系统对比国内外大模型厂商，建立科学的选型决策框架。

---

## 1. 选型决策框架

### 1.1 五维评估模型

```
模型选型 = f(能力, 成本, 延迟, 合规, 生态)

能力：    任务完成质量、推理能力、中文能力、多模态
成本：    输入/输出价格、配额、是否有免费额度
延迟：    TTFT、生成速度、网络延迟
合规：    数据安全、境内部署、法规遵从
生态：    SDK、文档、社区、与其他工具的集成
```

### 1.2 决策矩阵

```
场景 → 推荐模型：

简单对话 / 客服：
  ├── 成本优先    → Qwen-Turbo / GPT-4o-mini / Claude Haiku
  ├── 中文优先    → Qwen-Plus / DeepSeek-V2
  └── 多语言      → GPT-4o-mini

复杂推理 / 代码：
  ├── 最强推理    → Claude Opus 4 / o3
  ├── 代码生成    → Claude Sonnet 4 / DeepSeek-Coder
  └── 数学推理    → DeepSeek-R1 / o3

长文本处理：
  ├── 超长文本    → Gemini 2.5 Pro (1M context)
  ├── 长文档      → Claude 系列 (200K)
  └── 小说创作    → Claude Opus 4

RAG / 知识问答：
  ├── 中文知识    → Qwen-Max / DeepSeek-V3
  ├── 英文知识    → GPT-4o / Claude Sonnet 4
  └── 成本敏感    → Qwen-Plus + bge-m3

多模态：
  ├── 图片理解    → GPT-4o / Claude Vision / Gemini
  ├── 视频理解    → Gemini 2.5 Pro
  ├── 图片生成    → DALL-E 3 / FLUX
  └── 语音        → OpenAI TTS + Whisper

私有化部署：
  ├── 7B 模型     → Qwen2.5-7B / Llama 3.1-8B
  ├── 70B 模型    → Qwen2.5-72B / Llama 3.1-70B
  └── MoE 模型    → DeepSeek-V3 (开源) / Qwen2.5-MoE
```

## 4. 多模型路由架构

### 4.1 智能路由策略

```java
@Component
public class IntelligentModelRouter {

    /**
     * 路由规则引擎
     */
    public RoutedModel route(ChatRequest request) {
        // 规则 1：用户指定 → 优先满足
        if (request.getPreferredModel() != null) {
            return routeToModel(request.getPreferredModel());
        }

        // 规则 2：任务类型路由
        String intent = detectIntent(request.getMessage());

        return switch (intent) {
            case "CODE"     -> routeToModel("claude-sonnet-4");   // Claude 代码最强
            case "MATH"     -> routeToModel("deepseek-r1");      // R1 推理最强
            case "VISION"   -> routeToModel("gpt-4o");           // 4o 视觉好
            case "LONGFORM" -> routeToModel("gemini-2.5-pro");   // 1M 上下文
            case "CHINESE"  -> routeToModel("qwen-max");         // 通义中文强
            default         -> routeToModel("deepseek-v3");      // 性价比之王
        };
    }

    record RoutedModel(ChatModel model, String modelName) {}
}

/**
 * 多模型并发 → 最快响应 wins
 */
@Service
public class RaceModelService {

    public String raceMode(List<String> modelNames, String prompt) {
        List<CompletableFuture<ModelResult>> futures = modelNames.stream()
            .map(name -> CompletableFuture.supplyAsync(() -> {
                long start = System.currentTimeMillis();
                String result = callModel(name, prompt);
                long latency = System.currentTimeMillis() - start;
                return new ModelResult(name, result, latency);
            }))
            .toList();

        // 谁先返回就用谁的
        return CompletableFuture.anyOf(futures.toArray(new CompletableFuture[0]))
            .thenApply(r -> ((ModelResult) r).result())
            .join();
    }
}
```

## 5. 选型检查清单

```
模型选型检查清单：

□ 功能需求
  ├── 核心任务是什么？(对话/代码/推理/翻译/创作)
  ├── 需要多模态吗？(图片/音频/视频)
  ├── 上下文长度需求？
  └── 需要 Function Calling 吗？

□ 性能需求
  ├── 期望的 TTFT 延迟？
  ├── 并发量级？(QPS)
  ├── 是否需要流式输出？
  └── 可用性 SLA 要求？

□ 成本约束
  ├── 月度预算？
  ├── 预估日 Token 消耗？
  └── 是否需要本地部署？

□ 合规需求
  ├── 数据必须存境内？
  ├── 需要算法备案？
  ├── 行业监管要求？(金融/医疗)
  └── 是否有数据安全审计？

□ 技术约束
  ├── 技术栈限制？(Java/Python)
  ├── 是否需要私有化部署？
  ├── 现有基础设施兼容？
  └── 团队技术能力匹配？
```

## 6. 快速复习

```
□ 选型五维：能力 × 成本 × 延迟 × 合规 × 生态
□ 国际三巨头：OpenAI (生态) / Anthropic (代码+安全) / Google (长上下文)
□ 国内首选：Qwen (中文+开源) / DeepSeek (性价比+推理) / 豆包 (便宜)
□ 多模型路由：任务类型 → 最擅长模型
□ 竞速模式：多模型并发，取最快响应
□ DeepSeek 兼容 OpenAI API，Java 代码零改动
□ 私有化部署：Qwen2.5 或 Llama + vLLM/Ollama
```
