# 03 — 大模型训练与微调

> **目标**：理解大模型的完整训练流程，掌握微调（Fine-tuning）的各种方法和适用场景。

## 2. Pre-training（预训练）

### 2.1 核心要素

| 要素 | 说明 | 典型值 |
|------|------|--------|
| **训练数据量** | 训练所用的文本总量 | 1T ~ 15T+ tokens |
| **训练时长** | GPU 集群训练时间 | 数周 ~ 数月 |
| **训练目标** | Next Token Prediction（自回归） | 预测下一个 token |
| **损失函数** | Cross-Entropy Loss | 衡量预测与真实的差距 |
| **GPU 数量** | 训练并行规模 | 数百 ~ 数千张 H100/A100 |

### 2.2 Chinchilla 定律

> **最优训练数据量 ≈ 20 × 模型参数量**

```
如果模型有 7B 参数，最优训练数据 ≈ 140B tokens
如果模型有 70B 参数，最优训练数据 ≈ 1.4T tokens

实际趋势：
  过去（2020-2022）："大力出奇迹"，参数越大越好（GPT-3: 175B）
  现在（2023-2024）：在更多数据上训练"较小"的模型（Llama 3 8B: 15T tokens）
  未来（2025+）  ：数据接近耗尽，合成数据 + 多模态成为新方向
```

### 2.3 数据工程

```
数据处理流水线：

原始数据 (Common Crawl / 书籍 / 论文 / 代码)
  │
  ├─→ [语言检测] → 过滤非目标语言
  ├─→ [去重]      → MinHash / SimHash / 精确去重
  ├─→ [质量过滤]  → 困惑度过滤 / 分类器过滤
  ├─→ [PII 移除]  → 脱敏姓名/电话/邮箱/地址
  ├─→ [毒性过滤]  → 移除有害内容
  ├─→ [去偏]      → 平衡数据分布
  └─→ [分词]      → BPE / SentencePiece Tokenizer
```

## 3. SFT（有监督微调）

### 3.1 是什么

> **SFT (Supervised Fine-Tuning)**：用高质量的「指令-回答」对来训练基座模型，让它学会"对话"和"遵循指令"。

```
SFT 数据格式（对话模板）：

{
  "messages": [
    {"role": "system", "content": "你是一个有用的助手"},
    {"role": "user",   "content": "如何做番茄炒蛋？"},
    {"role": "assistant", "content": "番茄炒蛋的做法：\n1. ..."}
  ]
}

SFT 目标：
  让模型学会：
  ✅ 遵循指令
  ✅ 保持对话格式
  ✅ 拒绝有害请求
  ✅ 承认不知道
```

### 3.2 全量微调 vs 参数高效微调

```
全量微调 (Full Fine-Tuning)：
  → 更新所有参数
  → 需要与预训练相当的 GPU 资源
  → 可能"灾难性遗忘"（遗忘预训练知识）
  → 成本高

参数高效微调 (PEFT)：
  → 只训练少量（0.1%~10%）额外参数
  → 消费级 GPU 可完成
  → 保留原有知识
  → 成本低，是主流
```

## 4. LoRA —— 参数高效微调的首选

### 4.1 LoRA 原理

```
核心思想：不更新原有权重 W，而是在旁边训练一个"低秩适配器"。

传统微调：h = W · x          W 完全更新
LoRA 微调：h = W · x + B·A · x    只训练 A 和 B（W 冻结）

其中：
  W ∈ ℝ^{d×d}          (原始权重，冻结)
  A ∈ ℝ^{r×d}          (低秩矩阵，可训练)
  B ∈ ℝ^{d×r}          (低秩矩阵，可训练)
  r << d                (秩，通常 4~64)

参数量对比：
  全量微调：d² 个参数 → 4096² = 16.8M / 层
  LoRA (r=16)：2dr 个参数 → 2×4096×16 = 131K / 层
  减少 99.2%！
```

### 4.2 LoRA 配置参数

| 参数 | 全称 | 说明 | 建议值 |
|------|------|------|--------|
| **r** | Rank | 低秩矩阵的秩 | 4-64，r 越大能力越强但参数越多 |
| **alpha** | Alpha | 缩放系数 | 通常 = r × 2 或 = r |
| **target_modules** | — | 应用 LoRA 的层 | 通常是 Q、V 投影层（有时加 K、O、FFN） |
| **dropout** | — | Dropout 比例 | 0.05-0.1 |

### 4.3 QLoRA

```
QLoRA = 量化 + LoRA

  LoRA：  在 FP16/BF16 精度下微调 → 仍需 ~28GB 显存（7B 模型）
  QLoRA： 将基座模型量化到 4-bit (NF4)，只在前向时反量化
          → 7B 模型仅需 ~6GB 显存，RTX 3060 就能跑！

关键技术：
  ✅ NF4（NormalFloat4）：专门为正态分布设计的 4-bit 格式
  ✅ 双重量化（Double Quantization）：进一步压缩量化常数
  ✅ 分页优化器（Paged Optimizer）：利用 CPU 内存做 offload
```

## 5. RLHF（基于人类反馈的强化学习）

### 5.1 三阶段流程

```
阶段 1: SFT
  标注员写出高质量回答 → 微调模型 → SFT Model

阶段 2: Reward Model (RM) 训练
  模型对同一 prompt 生成多个回答
  标注员对这些回答排序（A > B > C > D）
  → 训练一个 RM，学习"什么样的回答是人类喜欢的"

阶段 3: PPO 强化学习
  用 RM 作为奖励信号
  用 PPO 算法优化 SFT Model
  同时加 KL 散度约束，防止偏离太远
```

### 5.2 RLHF 的成本

```
RLHF 成本构成：
├── 高质量标注数据（SFT）     → 人工成本
├── 偏好排序数据（RM 训练）    → 人工成本
├── PPO 训练                  → 需要同时加载 4 个模型：
│   ├── Policy Model (被训练)
│   ├── Reference Model（KL 约束基准）
│   ├── Reward Model（打分）
│   └── Value Model（PPO 需要）
└── 训练不稳定性             → 调试成本
```

## 6. DPO（直接偏好优化）—— RLHF 的简化替代

### 6.1 核心思想

```
RLHF：需要训练单独的 Reward Model，然后 PPO 强化学习
DPO：直接从偏好数据中学习，不需要 Reward Model！

数学本质：
  DPO 推导出了一个巧妙的损失函数，使得可以直接在偏好数据上
  用标准分类损失来优化模型，效果等价于 RLHF。

DPO 优势：
  ✅ 不需要训练 Reward Model
  ✅ 不需要 PPO（训练更稳定）
  ✅ 计算资源需求减半
  ✅ 效果与 RLHF 相当
```

### 6.2 DPO vs RLHF 对比

| 维度 | RLHF | DPO |
|------|------|-----|
| 需要 Reward Model | 是 | 否 |
| 需要 PPO 阶段 | 是 | 否 |
| GPU 需求 | 高（4 个模型同时加载） | 中（2 个模型） |
| 训练稳定性 | 较低（RL 训练波动大） | 较高（标准分类损失） |
| 效果 | 好 | 与 RLHF 相当甚至更好 |
| 主流程度 | 曾经的标配 | 2024+ 主流 |

## 7. 量化 (Quantization)

### 7.1 为什么需要量化

```
FP32（全精度）：  每个参数 4 字节 → 7B 模型需要 28GB
FP16/BF16（半精度）：每个参数 2 字节 → 7B 模型需要 14GB
INT8 量化：        每个参数 1 字节 → 7B 模型需要 7GB
INT4 量化：        每个参数 0.5 字节 → 7B 模型需要 3.5GB

BF16 训练，INT4 推理是当下的最佳实践。
```

### 7.2 量化方法对比

| 方法 | 全称 | 特点 | 精度损失 |
|------|------|------|---------|
| **GGUF/GGML** | GPT-Generated Unified Format | llama.cpp 的格式，CPU+GPU 混合推理 | 低（Q4_K_M: ~1-2%） |
| **GPTQ** | GPT Post-Training Quantization | 基于 OBQ 的一次性量化，需校准数据 | 低 |
| **AWQ** | Activation-aware Weight Quantization | 保护重要通道的量化 | 极低（<1%） |
| **BitsAndBytes** | — | HuggingFace 生态的量化库，QLoRA 依赖 | 低 |
| **NF4** | NormalFloat4 | BitsAndBytes 的 4-bit 格式 | 低 |
| **FP8** | 8-bit Floating Point | H100 原生支持，接近无损 | 极低 |

### 7.3 GGUF 文件名解读

```
模型文件名：qwen2.5-7b-instruct-q4_k_m.gguf

  qwen2.5-7b  → 模型名称和大小
  instruct    → 指令微调版本
  q4_k_m      → 量化方法：
                  q4 = 4-bit 量化
                  k  = K-Quant（分组量化，更好）
                  m  = medium 质量（s=small, m=medium, l=large）
  gguf        → 文件格式

质量排序：q8_0 > q6_k > q5_k_m > q4_k_m > q3_k_m > q2_k
速度排序：q2_k > q3_k_m > q4_k_m > q5_k_m > q6_k > q8_0
```

## 8. 分布式训练

### 8.1 并行策略

```
训练大模型必须分布式。几种并行策略：

1. DP (Data Parallelism) —— 数据并行
   每个 GPU 有完整模型副本，各自计算不同 batch 的梯度
   然后 AllReduce 同步梯度

2. DDP (Distributed Data Parallel)
   DP 的改进版，通信更高效

3. FSDP (Fully Sharded Data Parallel)
   每个 GPU 只存一部分参数，用到时再通信取
   可以训练比单卡显存大得多的模型

4. TP (Tensor Parallelism) —— 张量并行
   把单个 Transformer 层切开到多个 GPU
   需要高速互联（NVLink）

5. PP (Pipeline Parallelism) —— 流水线并行
   不同层放在不同 GPU，流水线执行
   有 Bubble 问题（GPU 等待）

6. 3D Parallelism = TP + PP + DP
   大模型训练的标配
```

```
常见组合：
  7B 模型：    DP 或 FSDP，单机 8 卡
  70B 模型：   FSDP + TP，多机
  175B+ 模型： TP + PP + DP (3D)，大规模集群
```

### 8.2 关键概念

| 名词 | 解释 |
|------|------|
| **AllReduce** | 所有 GPU 之间同步梯度的集合通信操作 |
| **NCCL** | NVIDIA Collective Communications Library，GPU 间通信库 |
| **ZeRO** | DeepSpeed 的内存优化技术，分三个阶段优化不同部分 |
| **Gradient Checkpointing** | 用计算换内存：不存中间激活，反向传播时重算 |
| **Mixed Precision** | BF16 前向 + FP32 梯度累加，兼顾速度和精度 |
| **Gradient Accumulation** | 小 batch 多次前向，累加梯度后再更新，模拟大 batch |
| **Flash Attention** | IO-aware 的注意力算法，速度快且省内存 |

## 9. 企业微调决策框架

```
要不要微调？决策树：

你的场景是？
├── 通用对话/知识问答
│   └── 不需要微调，用 Prompt Engineering + RAG
│
├── 需要特定领域术语/风格（法律/医疗/金融）
│   └── 需要微调！用 LoRA + 领域数据
│
├── 需要输出特定格式（JSON/API Schema）
│   └── 先试 Few-Shot Prompt
│       ├── 成功率 > 90% → 不需要微调
│       └── 成功率 < 90% → SFT 微调
│
├── 需要特定"人格"或风格
│   └── SFT 微调（轻量，1K-10K 样本）
│
└── 需要避免某些输出（安全对齐）
    └── DPO 微调
```
