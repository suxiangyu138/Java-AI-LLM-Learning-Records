# 13 — 流式输出与实时通信

> **目标**：掌握 AI 应用流式输出的前后端全链路实现，从 SSE/WebSocket 到网关配置和生产优化。

---

## 1. 为什么需要流式输出

### 1.1 体验对比

```
非流式（同步）：
  用户发送 "写一篇2000字文章"
  → 等待 15-30 秒
  → 一次性返回全部内容
  → 用户焦虑："是不是卡住了？"

流式（异步）：
  用户发送 "写一篇2000字文章"
  → 0.5s 后开始逐字显示
  → 用户可以边看边等
  → 体验大幅提升

延迟指标对比：
  非流式 TTFR (Time to First Response):   15-30s
  流式   TTFT (Time to First Token):      0.3-1s
```

### 1.2 应用场景

```
必须流式：
  ├── 对话型 AI (ChatGPT, Claude, Kimi)
  ├── 长文本生成
  └── 实时翻译

可选流式：
  ├── 结构化输出（可等完整 JSON 再解析）
  ├── 分类/标签（输出很短）
  └── 简单问答
```

## 2. SSE (Server-Sent Events) 详解

### 2.1 SSE 协议格式

```
SSE 数据格式：

data: 这是第一条消息

data: 这是第二条消息
data: 多行数据延续

event: custom-event
data: {"type": "custom", "payload": "..."}

id: 123
data: 带ID的消息（断线重连用）

: 注释行（以冒号开头，客户端忽略）
```

### 2.2 Spring WebFlux SSE

```java
@RestController
public class StreamingChatController {

    private final ChatClient chatClient;

    // ===== 方式 1：Flux<String> 逐 Token 输出 =====
    @GetMapping(value = "/chat/stream/text",
                produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    public Flux<String> streamText(@RequestParam String message) {
        return chatClient.prompt()
            .user(message)
            .stream()
            .content();
    }
    // 输出：data:你 data:好 data:！ (每个 SSE event 是一个 token)

    // ===== 方式 2：Flux<ServerSentEvent> 带事件类型 =====
    @GetMapping(value = "/chat/stream/events",
                produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    public Flux<ServerSentEvent<String>> streamEvents(
            @RequestParam String message) {

        StringBuilder fullText = new StringBuilder();

        return chatClient.prompt()
            .user(message)
            .stream()
            .chatResponse()
            .map(response -> {
                String content = response.getResult().getOutput().getContent();
                fullText.append(content);

                ChatEvent event = new ChatEvent(
                    "token",
                    content,
                    fullText.toString(),
                    null
                );

                return ServerSentEvent.<String>builder()
                    .event("token")
                    .data(toJson(event))
                    .build();
            })
            .concatWith(Flux.just(
                ServerSentEvent.<String>builder()
                    .event("done")
                    .data(toJson(new ChatEvent("done", null, fullText.toString(), null)))
                    .build()
            ));
    }

    // ===== 方式 3：Flux<ChatResponse> 访问完整元数据 =====
    @GetMapping(value = "/chat/stream/full",
                produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    public Flux<ServerSentEvent<Map<String, Object>>> streamFull(
            @RequestParam String message) {

        return chatClient.prompt()
            .user(message)
            .stream()
            .chatResponse()
            .map(response -> {
                var metadata = new HashMap<String, Object>();
                metadata.put("content", response.getResult().getOutput().getContent());
                metadata.put("finishReason", response.getResult().getMetadata().getFinishReason());

                return ServerSentEvent.<Map<String, Object>>builder()
                    .data(metadata)
                    .build();
            });
    }

    record ChatEvent(String type, String delta, String fullText, String error) {}
}
```

### 2.3 前端接收

```javascript
// ===== 原生 EventSource =====
const eventSource = new EventSource('/chat/stream/events?message=' + encodeURIComponent(query));

eventSource.addEventListener('token', (event) => {
    const data = JSON.parse(event.data);
    appendToChat(data.delta);    // 逐字追加
    updateFullText(data.fullText);
});

eventSource.addEventListener('done', (event) => {
    const data = JSON.parse(event.data);
    console.log('Complete:', data.fullText);
    eventSource.close();
});

eventSource.onerror = (error) => {
    console.error('Stream error:', error);
    // EventSource 会自动重连，需要手动处理
    eventSource.close();
};

// ===== Fetch API ReadableStream =====
async function chatStream(query) {
    const response = await fetch('/chat/stream/text?message=' + encodeURIComponent(query), {
        headers: { 'Accept': 'text/event-stream' }
    });

    const reader = response.body.getReader();
    const decoder = new TextDecoder();

    while (true) {
        const { done, value } = await reader.read();
        if (done) break;

        const text = decoder.decode(value, { stream: true });
        const lines = text.split('\n');

        for (const line of lines) {
            if (line.startsWith('data:')) {
                const content = line.slice(5).trim();
                if (content !== '[DONE]') {
                    appendToChat(content);
                }
            }
        }
    }
}
```

## 3. WebSocket 方案

### 3.1 SSE vs WebSocket

```
┌──────────────┬──────────────────┬──────────────────┐
│ 特性          │ SSE              │ WebSocket        │
├──────────────┼──────────────────┼──────────────────┤
│ 通信方向      │ 单向 (S→C)      │ 双向 (S↔C)      │
│ 协议          │ HTTP             │ WS (升级自HTTP)  │
│ 自动重连      │ ✅ 内置          │ ❌ 需手动实现    │
│ 二进制数据    │ ❌ (仅文本)      │ ✅               │
│ 实现复杂度    │ 低                │ 中               │
│ 浏览器兼容    │ 所有现代浏览器    │ 所有现代浏览器    │
│ 代理/防火墙   │ 天然兼容 HTTP    │ 可能被阻挡       │
│ 适用场景      │ 流式输出/通知    │ 实时双向通信      │
└──────────────┴──────────────────┴──────────────────┘
```

### 3.2 Spring WebSocket 实现

```java
@Configuration
@EnableWebSocket
public class WebSocketConfig implements WebSocketConfigurer {

    @Override
    public void registerWebSocketHandlers(WebSocketHandlerRegistry registry) {
        registry.addHandler(new ChatWebSocketHandler(), "/ws/chat")
                .setAllowedOrigins("*");
    }
}

public class ChatWebSocketHandler extends TextWebSocketHandler {

    private final ChatClient chatClient;

    @Override
    protected void handleTextMessage(WebSocketSession session,
                                      TextMessage message) throws Exception {
        String userMessage = message.getPayload();

        // 流式发送
        chatClient.prompt()
            .user(userMessage)
            .stream()
            .content()
            .doOnNext(token -> {
                try {
                    synchronized (session) {
                        session.sendMessage(new TextMessage(
                            toJson(Map.of("type", "token", "content", token))
                        ));
                    }
                } catch (IOException e) {
                    throw new RuntimeException(e);
                }
            })
            .doOnComplete(() -> {
                try {
                    session.sendMessage(new TextMessage(
                        toJson(Map.of("type", "done"))
                    ));
                } catch (IOException e) {
                    throw new RuntimeException(e);
                }
            })
            .blockLast(); // 阻塞直到完成
    }
}
```

## 4. 网关配置

### 4.1 Nginx 流式支持

```nginx
# SSE 流式输出需要特殊配置
location /chat/stream {
    proxy_pass http://backend:8080;

    # 关闭缓冲（关键！）
    proxy_buffering off;
    proxy_cache off;

    # 长连接超时
    proxy_read_timeout 300s;
    proxy_send_timeout 300s;

    # 传递必要头部
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header Connection '';
    proxy_http_version 1.1;

    # CORS（如果需要）
    add_header Access-Control-Allow-Origin *;
    add_header Access-Control-Allow-Methods 'GET, OPTIONS';
}
```

### 4.2 Kong / APISIX

```yaml
# Kong 配置
plugins:
  - name: proxy-cache
    enabled: false  # 流式接口必须禁用缓存！
  - name: request-termination
    config:
      status_code: 408
      message: Request timeout
    # 设定合理的超时

# APISIX 配置
routes:
  - uri: /chat/stream
    upstream:
      type: roundrobin
      nodes:
        "backend:8080": 1
      timeout:
        connect: 6
        send: 300         # 发送超时 300s
        read: 300         # 读取超时 300s
    plugins:
      proxy-rewrite:
        headers:
          set:
            X-Forwarded-For: $remote_addr
```

## 5. 异常处理与稳定性

### 5.1 断流重连

```java
// 后端：发送进度事件，支持恢复
@GetMapping(value = "/chat/stream/resumable",
            produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public Flux<ServerSentEvent<String>> resumableStream(
        @RequestParam String message,
        @RequestParam(required = false) String lastEventId) {

    // 如果有 lastEventId，从断点恢复
    if (lastEventId != null) {
        String cached = redisTemplate.opsForValue().get("stream:" + lastEventId);
        if (cached != null) {
            return Flux.just(
                ServerSentEvent.<String>builder()
                    .id(lastEventId)
                    .data(cached)
                    .build()
            );
        }
    }

    AtomicInteger counter = new AtomicInteger(0);
    return chatClient.prompt()
        .user(message)
        .stream()
        .content()
        .map(token -> ServerSentEvent.<String>builder()
            .id(String.valueOf(counter.incrementAndGet()))
            .event("token")
            .data(token)
            .build()
        );
}
```

### 5.2 背压控制

```java
@GetMapping(value = "/chat/stream/backpressure",
            produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public Flux<String> streamWithBackpressure(@RequestParam String message) {
    return chatClient.prompt()
        .user(message)
        .stream()
        .content()
        // 背压策略：下游处理不过来时缓冲
        .onBackpressureBuffer(100,     // 缓冲 100 条
            BufferOverflowStrategy.DROP_OLDEST)
        // 限速：每秒最多 50 个 token
        .limitRate(50)
        // 如果下游断开连接，取消上游
        .doOnCancel(() -> log.info("Client disconnected"));
}
```

### 5.3 全局异常处理

```java
@RestControllerAdvice
public class StreamingExceptionHandler {

    @ExceptionHandler(TimeoutException.class)
    public Flux<ServerSentEvent<String>> handleTimeout(TimeoutException e) {
        return Flux.just(
            ServerSentEvent.<String>builder()
                .event("error")
                .data(toJson(Map.of("error", "请求超时，请重试", "code", 408)))
                .build()
        );
    }

    @ExceptionHandler(RateLimitException.class)
    public Flux<ServerSentEvent<String>> handleRateLimit(RateLimitException e) {
        return Flux.just(
            ServerSentEvent.<String>builder()
                .event("error")
                .data(toJson(Map.of("error", "请求过于频繁，请稍后重试", "code", 429)))
                .build()
        );
    }
}
```

## 6. 性能优化

### 6.1 流式输出优化清单

```
流式输出生产优化：

□ 网关关闭缓冲 (nginx: proxy_buffering off)
□ 设定合理超时（读超时 ≥ 300s）
□ 背压控制（onBackpressureBuffer）
□ 限速（limitRate）
□ 客户端断开检测和资源释放
□ 长连接池化（避免频繁创建 SSE 连接）
□ CDN 不缓存流式接口
□ 监控：TTFT / Token 生成速率 / 掉线率
```

### 6.2 监控埋点

```java
@Component
public class StreamingMetrics {

    private final MeterRegistry registry;

    public <T> Flux<T> instrument(Flux<T> stream, String endpoint) {
        var counter = Counter.builder("ai.stream.tokens")
            .tag("endpoint", endpoint)
            .register(registry);

        var timer = Timer.builder("ai.stream.duration")
            .tag("endpoint", endpoint)
            .register(registry);

        long start = System.nanoTime();
        return stream
            .doOnNext(token -> counter.increment())
            .doOnTerminate(() -> timer.record(System.nanoTime() - start, TimeUnit.NANOSECONDS));
    }
}
```

## 7. 快速复习

```
□ SSE: 单向(服务端→客户端)、基于HTTP、自动重连
□ WebSocket: 双向、需要握手升级、无自动重连
□ AI 聊天场景用 SSE 即可（够用 + 简单）
□ 网关必须关闭缓冲 (proxy_buffering off)
□ 超时设置 ≥ 300s（长文本生成）
□ 背压：onBackpressureBuffer + limitRate
□ 前端：EventSource (简单) 或 Fetch Stream (灵活)
□ 事件类型区分：token / tool-call / error / done
```
