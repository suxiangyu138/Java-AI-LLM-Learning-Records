# 知识工程与知识图谱

> **优先级**：🟢 拓展选修 | **类型**：校内提升专业课 | **方向**：AI 能力拔高·前沿

## 课程定位

**提升点**：知识建模方法、知识图谱构建全流程、知识推理、知识融合、知识图谱与大模型结合（GraphRAG）

**适用人群**：想做行业知识库/企业知识图谱、增强大模型回答准确性、GraphRAG方向

**学习目标**：能独立构建领域知识图谱，理解知识推理的基本方法，能设计 GraphRAG 系统

---

# 第一章：知识工程概述
- 知识工程定义：从数据中提取、组织、管理和应用知识的系统工程
- DIKW 金字塔：Data→Information→Knowledge→Wisdom——从原始到智慧的跃升
- 知识类型：事实性知识(What)、过程性知识(How)、元知识(关于知识的知识)
- 知识工程的演进：专家系统(80s)→语义网(00s)→知识图谱(10s)→大模型+知识(20s)

# 第二章：知识表示
- 谓词逻辑表示：一阶谓词→Horn子句→Prolog
- 产生式表示：IF-THEN——专家系统核心
- 语义网络：节点(概念)+边(关系)——最早的知识图谱雏形
- 框架表示：槽-值对——Minsky 提出的结构化知识
- 本体（Ontology）表示：形式化的概念化说明——类、实例、属性、公理

# 第三章：知识图谱构建
- 知识图谱 = 实体 + 关系 + 属性 + 语义网络，通常存储为 RDF 三元组(S,P,O)
- 构建流程：
  1. 本体设计：定义概念层次和关系类型（Protégé工具）
  2. 知识抽取：命名实体识别(NER)+关系抽取(RE)+属性抽取
  3. 实体链接：提及→知识库中的实体——消歧
  4. 知识融合：多源数据→实体对齐→冲突消解
  5. 知识补全：推理缺失的链接——TransE(平移假设：h+r≈t)

# 第四章：知识图谱存储与查询
- RDF 存储：三元组为基本单位——Jena TDB / RDF4J / Virtuoso
- 图数据库：Neo4j(Cypher查询语言——属性图模型)、JanusGraph(分布式)
- SPARQL：RDF 标准的查询语言——SELECT / CONSTRUCT / ASK
- 属性图 vs RDF 图：属性图=边和顶点都可带属性；RDF=一切皆三元组

# 第五章：知识推理
- 描述逻辑（DL）：ALC——概念构造子(⊓, ⊔, ¬, ∃R.C, ∀R.C)，OWL 的基础
- 规则推理：Datalog(声明式逻辑语言)、SWRL(语义网规则)
- 基于嵌入的知识推理(Knowledge Graph Embedding)：
  - TransE：h+r≈t——平移不变性
  - TransH：关系超平面投影——解决 N-1, 1-N 问题
  - RotatE：复数空间旋转——对称-反对称-逆-组合
- 基于路径的推理：随机游走+逻辑规则

# 第六章：大模型时代的知识工程
- RAG + 知识图谱（GraphRAG）：
  - 检索：实体→检索KG中的邻域→提取结构化事实→与文档片段共同增强Prompt
  - 好处：关系型推理(多跳问题)远优于纯向量检索
- 知识图谱增强微调：用KG生成训练数据→微调小模型获得特定领域知识
- 大模型辅助知识图谱构建：LLM 做实体/关系抽取(少样本甚至零样本)

# 第七章：行业应用
- 智能问答：KBQA——问题→解析→SPARQL查询→答案
- 推荐系统：物品知识图谱→可解释推荐(因为A所以B)
- 风控：企业关联图谱→担保圈检测→异常模式发现
- 医疗：DrugBank/疾病与症状→辅助诊疗
