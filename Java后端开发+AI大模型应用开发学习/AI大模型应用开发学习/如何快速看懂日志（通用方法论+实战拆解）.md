如何快速看懂日志（通用方法论+实战拆解）
一、先搞懂：日志核心作用
日志本质是程序运行的黑匣子，记录：
1. 程序启动、接口调用、定时任务、数据库操作等行为
2. 关键变量、入参/出参、耗时、调用链路
3. 报错堆栈、异常原因、崩溃现场
 
二、日志基础分级（优先看级别筛重点）
主流日志级别（严重程度从低到高）：
1. TRACE：详细流程，调试用，日常忽略
2. DEBUG：开发调试信息，本地环境常用，线上一般关闭
3. INFO：正常业务流程（接口请求、服务启动、任务执行）
4. WARN：不影响程序运行的异常（参数冗余、降级、重试）
5. ERROR：业务报错、接口失败、数据库异常、代码BUG
6. FATAL：致命错误，服务直接崩溃、停止运行
排查问题优先级：ERROR > WARN > INFO
 
三、标准日志通用格式（看懂每行结构）
常规后端日志一行组成：
plaintext
时间 + 日志级别 + 线程 + 服务名 + 类名.方法 + 自定义内容/异常信息
 
示例：
plaintext
2026-04-26 15:30:22 [ERROR] [http-nio-8080-exec-5] com.demo.UserController.login : 用户名密码错误
java.sql.SQLException: 数据库连接超时
 
逐段拆解
1. 时间：定位报错发生时间，用于结合业务时间复盘
2. 级别：快速判断严重程度
3. 线程：区分并发请求，排查多线程冲突、死锁
4. 类+方法名：直接定位出错代码位置（最关键）
5. 业务内容：入参、返回值、自定义打印文案
6. 异常堆栈：报错根源、调用链
 
四、看日志的核心步骤（排查问题标准流程）
1. 锁定时间范围
根据问题发生时间，筛选对应时间段日志，避免海量无效内容。
2. 过滤错误关键字
直接检索关键词，快速定位问题：
- 报错： ERROR 、 Exception 、 Error 、 Fail 
- 数据库： SQL 、 Timeout 、 Connection 
- 接口： 500 、 404 、 NullPointerException 
- 资源： OOM 、 内存溢出 、 线程阻塞 
3. 先看报错摘要，再看堆栈
1. 第一行错误信息：直接告诉你是什么问题
- 例： NullPointerException  → 空指针
- 例： SQLSyntaxError  → SQL语句写错
2. 下方堆栈信息：告诉你在哪一行代码报错
只看自己项目的包路径，忽略框架底层源码。
4. 结合入参+上下文
很多报错不是代码问题，是入参非法：
- 查看接口请求参数、前端传值
- 查看上游服务调用参数
- 查看数据库查询条件
5. 看链路日志（微服务场景）
微服务会携带traceId/requestId：
- 同一个ID贯穿所有服务调用
- 复制ID全局搜索，完整还原一次请求全流程
 
五、常见日志报错快速识别
1. 空指针 NPE
变量未初始化、对象为null直接调用方法
2. SQL异常
字段不存在、语法错误、索引失效、连接超时
3. 参数绑定异常
前端传参名不对、格式不匹配（日期、数字）
4. 超时异常
接口响应慢、数据库慢查询、第三方接口阻塞
5. OOM内存溢出
内存泄漏、大对象未释放、批量查询未分页
 
六、实用小技巧
1. 检索过滤
本地日志：Notepad++、VSCode 关键词搜索
线上日志：ELK、Graylog、控制台  grep  过滤
2. 忽略无关日志
框架启动日志、第三方依赖INFO日志直接跳过
3. 保留现场
报错后不要立刻重启服务，先导出日志再处理
4. 自定义日志规范
自己写代码时，关键节点打印：入参、出参、耗时、业务ID，方便后续排查
 
七、极简总结（新手速记）
1. 先筛时间 → 再搜  ERROR 
2. 看错误类型 → 看自己项目代码行号
3. 核对入参、SQL、第三方调用
4. 微服务用 traceId 串联全链路
