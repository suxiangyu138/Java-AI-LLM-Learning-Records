快速学会 Prompt Engineering（提示词工程）
一、核心本质
Prompt = 给大模型的「指令说明书」
大模型没有自主意识，你写得越清楚，结果越精准。
提示词工程 = 学会规范、约束、引导大模型输出。
 
二、万能黄金公式（所有场景通用）
plaintext
1. 身份设定（你是谁）
2. 任务目标（要做什么）
3. 输入素材（给什么内容）
4. 规则约束（禁止/要求）
5. 输出格式（怎么呈现）
6. 补充细节（语气、长度、风格）
 
套这个结构，吊打 90% 普通提问。
 
三、五大核心基础技巧（必掌握）
1. 角色设定法（最强）
给模型绑定专业身份，直接提升专业性
示例：
plaintext
你是一名5年经验的Java后端开发工程师，精通SpringBoot、RabbitMQ、ES。
请用通俗易懂、结构化的方式回答问题，不要废话。
 
2. 明确约束 & 边界
限制模型不乱答、不发散：
- 禁止编造数据
- 只回答给定材料内内容（RAG 必备）
- 禁止过度拓展
- 回答精简 / 详细
3. 结构化输出要求
强制列表、表格、分级标题、代码块：
plaintext
回答必须使用Markdown格式，分点罗列，关键内容加粗，代码使用代码块包裹。
 
4. 少样本引导（Few-shot）
给 1～2 个示例，让模型模仿你的格式
适合：格式固定、文案、错题整理、数据处理
5. 思维链 CoT（复杂问题必用）
plaintext
请一步步拆解思考，分步推导，最后给出最终答案。
 
数学、算法、逻辑题、复杂业务分析，准确率翻倍。
 
四、四种高阶经典框架（直接抄用）
1. CRISPE 通用框架
- Context 背景
- Requirement 要求
- Information 已知信息
- Style 风格
- Persona 身份
- Example 示例
2. RTA 极简框架（日常最快）
- Role 角色
- Task 任务
- Answer 输出要求
3. CoT 思维链（逻辑推理）
适合：算法、数学、原理推导、系统设计
4. RAG 专用 Prompt（你必用）
plaintext
请严格仅基于下方参考资料回答用户问题，
禁止编造、禁止知识库外内容，
资料不足时直接说明「资料有限，无法回答」。
参考资料：
{{context}}
用户问题：
{{question}}

六、新手最容易犯的 4 个错误
1. 问题太笼统
❌ 错误：介绍 Docker
✅ 正确：用大白话+结构化，介绍Docker核心作用、核心概念、适用场景
2. 不给背景
模型不知道你的用途（考试？开发？背诵？）
3. 不限制格式
输出杂乱无章，无法直接做笔记/复用
4. 不限制幻觉
大模型容易瞎编数据，专业场景必须加：
 禁止编造事实，无依据内容禁止输出 
 
七、大模型幻觉怎么克制（关键）
在 Prompt 里固定加一句话：
plaintext
所有内容必须有据可依，不确定内容直接说明，禁止编造专业术语、数据、案例。
 
 
八、极简记忆总结
1. 基础四件套：定身份 + 说需求 + 给材料 + 限格式
2. 复杂问题加：分步思考（CoT）
3. 固定格式用：少样本示例
4. RAG 必加：知识库约束，禁止编造
5. 一切 AI 应用（LLM+RAG+Agent），都靠高质量 Prompt 兜底
