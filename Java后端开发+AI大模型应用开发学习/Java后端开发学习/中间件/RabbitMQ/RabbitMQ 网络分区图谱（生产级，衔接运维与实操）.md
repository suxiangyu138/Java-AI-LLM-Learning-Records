一、网络分区核心定义（衔接前文基础）
网络分区（Network Partition）：RabbitMQ集群中，因网络故障导致节点间无法正常通信，集群分裂为两个或多个独立“孤岛”（分区），各分区自主运行、互不感知，进而引发元数据不一致、消息丢失、服务中断等问题，本质是“网络故障引发的集群分裂”，与前文集群元数据中partitions字段、/api/nodes接口返回逻辑完全对应。
核心关联：对应前文 /api/nodes 接口的 partitions 字段（非空即存在分区）、集群元数据中的节点状态字段，是集群运维的核心故障场景。

五、补充说明（避坑重点，衔接前文）
图谱中“自动恢复”环节（F），需提前配置 cluster_formation.auto_heal = true（前文网络分区预防配置），否则网络恢复后不会自动合并分区，需手动干预；同时，自动恢复可能存在数据冲突，需提前开启数据同步校验。
对等分区（如2节点vs2节点）场景中，自动恢复会按“节点名称字典序”选择获胜分区，可能导致非预期节点重启，生产环境建议避免部署偶数节点集群，衔接前文“集群节点数量建议为奇数”的配置。
分区检测时，需区分“集群内部分区”与“跨集群链路异常”，前者通过/api/nodes接口检测，后者通过 rabbitmqctl list_federation_links 查看，避免误判（前文网络分区坑点3）。
所有操作需先在测试环境验证，再部署到生产环境，避免操作失误导致集群故障，衔接前文扩展、运维的避坑原则。
