消息队列核心知识点
---------------------------------------------------------------------------------------------------------------------------------------
一、消息队列是什么
消息队列是分布式系统中用于异步通信的中间件。
生产者发送消息到消息队列服务，消费者从队列中拉取消息并处理，生产者和消费者不直接通信。
--------------------------------------------------------------------------------------------------------------------------------------- 二、核心作用
1. 解耦
系统之间不直接依赖，通过消息通信，方便扩展和维护。
2. 异步
非核心流程异步处理，提高接口响应速度。
3. 削峰填谷
高并发时将请求缓存到队列，避免下游服务被压垮。
4. 缓冲
流量不均匀时平滑处理，提高系统稳定性。
--------------------------------------------------------------------------------------------------------------------------------------- 三、核心角色
1. 生产者
发送消息的应用。
2. 消费者
接收并处理消息的应用。
3. broker
消息队列服务端，负责存储、转发消息。
4. 队列/主题
消息存储的地方。
5. 偏移量
记录消费者消费到的位置。
6. ack
消费确认机制，告诉服务端消息已处理。
--------------------------------------------------------------------------------------------------------------------------------------- 四、两种核心模型
1. 点对点模型
一个消息只能被一个消费者消费。
2. 发布订阅模型
一个消息可以被多个订阅者消费。
--------------------------------------------------------------------------------------------------------------------------------------- 五、消息队列常见问题及解决方案
1. 消息丢失
可能出现在生产者、broker、消费者三个环节。
解决方式
生产者使用确认机制。
broker开启消息持久化、集群部署。
消费者使用手动ack，处理完成再确认。
2. 消息重复消费
由网络重试、ack超时、重试机制导致。
解决方式
保证业务幂等。
使用唯一标识判断是否已处理。
使用分布式锁或数据库唯一约束。
3. 消息堆积
消费者处理速度跟不上生产速度。
解决方式
提高消费者数量。
优化消费逻辑。
使用批量消费。
将消息分流到多个队列。
4. 消息乱序
多线程、多队列、重试都会导致乱序。
解决方式
同一类业务消息发到同一个队列。
单线程消费。
业务层增加序号自行排序。
5. 死信队列
无法被正常消费的消息会进入死信队列。
产生原因
消息过期。
消费者拒绝。
超过最大重试次数。
作用
统一收集失败消息，便于排查和处理。
--------------------------------------------------------------------------------------------------------------------------------------- 六、消息可靠性机制
1. 生产者可靠性
同步或异步发送。
开启发送确认。
失败自动重试。
事务消息。
2. broker可靠性
消息持久化到磁盘。
主从架构。
合理配置刷盘策略。
3. 消费者可靠性
手动ack。
失败重试。
异常消息进入死信。
--------------------------------------------------------------------------------------------------------------------------------------- 七、常见使用场景
1. 异步通知
注册后发送短信、邮件。
2. 系统解耦
订单、库存、物流、积分系统之间解耦。
3. 削峰
秒杀、下单等高并发场景。
4. 延迟任务
订单超时未支付自动关闭。
5. 分布式事务最终一致性
通过消息保证多个系统数据一致。
6. 日志收集与流处理
常用于大数据、日志采集架构。
--------------------------------------------------------------------------------------------------------------------------------------- 八、主流消息队列产品
1. RabbitMQ
轻量易用，社区成熟，适合中小项目。
2. RocketMQ
高吞吐、高可靠，适合电商、金融。
3. Kafka
超高吞吐量，适合日志、流数据处理。
4. ActiveMQ
早期产品，目前使用较少。
---------------------------------------------------------------------------------------------------------------------------------------
九、企业使用原则
1. 不要滥用消息队列，简单场景不需要。
2. 必须保证消息不丢失、不重复、可追溯。
3. 必须监控堆积、延迟、失败、消费速度。
4. 敏感业务必须保证幂等性。
5. 尽量使用手动ack，避免自动ack导致丢失。
