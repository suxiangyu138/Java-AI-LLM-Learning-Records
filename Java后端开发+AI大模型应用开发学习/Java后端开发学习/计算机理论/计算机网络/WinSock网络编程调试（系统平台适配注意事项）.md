WinSock网络编程调试（系统平台适配注意事项）
结合前文WinSock调试“该做的&不该做的”规范，针对系统平台适配（重点覆盖Windows全版本、BSD移植跨平台场景），补充核心注意事项，确保调试过程中规避平台兼容问题，保证程序在目标平台稳定运行，全程贴合后端实战，与前文调试知识点无缝衔接。
一、核心系统平台适配要求（调试必关注）
WinSock仅适配Windows系统（WinXP及以上，主流Win7/Win10/Win11），BSD Sockets移植场景需兼顾Windows与Linux/Unix平台，调试时需重点关注平台差异，避免因平台不兼容导致调试无效。
（一）Windows平台内部适配（重点调试）
WinSock版本适配：所有Windows平台调试时，必须使用WinSock 2.2版本（MAKEWORD(2,2)），避免使用1.1版本（功能不全，不支持部分Socket接口），调试时需校验版本合法性（前文基础调试规范）。
系统位数适配：调试时需区分32位（x86）和64位（x64）平台，DLL编译、主程序编译需保持位数一致，避免“32位DLL被64位主程序调用”或反之，导致DLL加载失败（前文DLL调试重点）。
系统权限适配：Win10/Win11调试时，若涉及端口绑定（如服务器端），需以“管理员身份运行”VS/调试程序，避免系统权限不足导致bind失败（错误码10013 WSAEACCES）。
系统防火墙适配：不同Windows版本防火墙规则不同，调试前需统一关闭防火墙，或手动开放调试所用端口，避免防火墙拦截Socket连接（前文基础环境检查）。
（二）跨平台适配（BSD移植场景调试重点）
针对BSD Sockets向WinSock移植的跨平台调试，需重点区分Windows与Linux/Unix平台差异，严格遵循前文移植调试规范，补充以下平台适配注意事项：
平台标识规范：调试时必须用#ifdef _WIN32标识Windows平台代码，#else标识Linux/Unix平台代码，绝不能混用平台标识（如用#ifdef WINDOWS），避免编译失败。
核心接口适配：调试时需确认BSD接口与WinSock接口适配正确（如close→closesocket、fcntl→ioctlsocket），每一处接口替换都需断点调试，验证调用有效性（前文移植调试重点）。
编译环境适配：Windows端用VS/MinGW调试，Linux端用GCC调试，调试时需确保两端编译参数一致（如字符集、优化等级），避免因编译环境差异导致运行结果不同。
网络配置适配：Linux端调试时无需处理WinSock初始化/清理，但需确保端口复用、字节序转换逻辑与Windows端一致；Windows端调试时需重点校验WSAStartup/WSACleanup的调用时机（前文资源管理规范）。
二、系统平台调试“该做的”（必遵守）
调试前必确认目标平台：明确调试的Windows版本（如Win10 x64）、是否跨平台，针对性配置编译环境和网络环境，避免盲目调试。
Windows平台调试必以管理员身份运行：涉及端口绑定、DLL加载的场景，必须用管理员权限启动调试程序，避免权限不足导致的异常。
跨平台调试必做两端对比：分别在Windows和Linux平台调试，对比数据收发、连接状态、资源释放情况，定位平台适配差异。
必适配系统位数：DLL、主程序、依赖库（如ws2_32.lib）的位数必须统一，调试时通过VS项目属性确认位数设置，避免位数不兼容。
Win10/Win11调试必检查防火墙：关闭系统防火墙或开放调试端口，调试后可恢复防火墙设置，避免遗漏导致后续调试失败。
三、系统平台调试“不该做的”（绝不能犯）
不该忽略Windows版本差异：绝不能默认所有Windows版本适配一致，如WinXP不支持部分WinSock高级接口，调试时需确认目标版本，避免接口调用失败。
不该混用32位与64位环境：绝不能将32位DLL与64位主程序混用，或反之，导致DLL加载失败、程序崩溃，调试时需优先核对位数。
不该跨平台调试时省略平台标识：绝不能取消#ifdef _WIN32条件编译，导致Windows与Linux代码混用，编译失败或运行异常（前文移植调试禁忌）。
不该忽略Linux平台调试：BSD移植后，绝不能只调试Windows端，忽略Linux端，导致跨平台运行异常，无法定位移植适配错误。
不该以普通权限调试端口绑定场景：Win10/Win11调试服务器端时，绝不能不用管理员权限，导致bind失败，却盲目修改代码逻辑。
四、补充说明（衔接前文，强化适配）
系统平台适配是WinSock调试的基础前提，与前文调试规范、避坑禁忌一脉相承——忽略平台差异，会导致调试走弯路、程序上线后兼容性问题。后端实战中，调试时需先明确目标平台，再针对性配置环境、校验接口、对比运行结果，严格遵守上述“该做的”和“不该做的”，确保程序在目标平台稳定运行，同时兼顾跨平台移植的兼容性。
