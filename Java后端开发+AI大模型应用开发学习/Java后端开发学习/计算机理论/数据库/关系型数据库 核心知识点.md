关系型数据库 核心知识点
---------------------------------------------------------------------------------------------------------------------------------------
一、关系型数据库的核心定义
1. 基于关系模型（二维表结构）的数据库，数据以行（记录）和列（字段）的形式存储。
2. 核心特征：
   - 遵循ACID原则（原子性、一致性、隔离性、持久性），保证数据操作的可靠性；
   - 支持SQL（结构化查询语言），用于数据的增删改查和管理；
   - 数据之间通过外键建立关联，保证数据完整性；
   - 表与表之间存在一对一、一对多、多对多的关系。
3. 主流产品：MySQL（中小型项目首选，Bookstore适配）、Oracle（大型企业级）、SQL Server（微软生态）、PostgreSQL（开源高性能）。
---------------------------------------------------------------------------------------------------------------------------------------
二、核心概念（Bookstore场景对应）
1. 数据库（Database）：存储一组相关数据的集合，Bookstore项目对应`bookstore`数据库。
2. 表（Table）：数据库的基本存储单元，Bookstore核心表包括`user`（用户）、`book`（书籍）、`cart`（购物车）、`order`（订单）、`order_item`（订单项）。
3. 行（Row/Record）：表中的一条数据，如`user`表中一条用户注册记录。
4. 列（Column/Field）：表中的一个属性，如`book`表的`name`（书名）、`price`（价格）、`stock`（库存）字段。
5. 主键（Primary Key）：唯一标识表中每行数据的字段，如`book`表的`id`（自增主键），保证记录唯一性。
6. 外键（Foreign Key）：用于关联两个表的字段，如`cart`表的`user_id`关联`user`表的`id`，`order_item`表的`book_id`关联`book`表的`id`，保证数据关联完整性。
7. 索引（Index）：提升查询效率的结构，Bookstore中常给`user`表的`username`、`order`表的`user_id`、`cart`表的`user_id+book_id`建立索引。
---------------------------------------------------------------------------------------------------------------------------------------
三、核心关系（Bookstore表关联）
1. 一对一：一个表的一条记录对应另一个表的一条记录，如`user`表与`user_info`表（用户详情）。
2. 一对多：一个表的一条记录对应另一个表的多条记录，如`user`表（1）对应`order`表（多）、`book`表（1）对应`order_item`表（多）。
3. 多对多：两个表的记录互相对应多条，如`user`表与`book`表（通过`cart`表中间关联）。
---------------------------------------------------------------------------------------------------------------------------------------
四、SQL核心操作（Bookstore常用）
1. DDL（数据定义语言）：创建/修改/删除数据库对象
   - 创建数据库：CREATE DATABASE bookstore;
   - 创建表（以book表为例）：
     CREATE TABLE book (
         id INT PRIMARY KEY AUTO_INCREMENT,
         name VARCHAR(100) NOT NULL,
         author VARCHAR(50),
         price DECIMAL(10,2),
         stock INT,
         category_id INT,
         FOREIGN KEY (category_id) REFERENCES category(id)
     );
   - 修改表：ALTER TABLE book ADD cover VARCHAR(200);
   - 删除表：DROP TABLE IF EXISTS book;
2. DML（数据操作语言）：增删改数据
   - 新增：INSERT INTO book(name, author, price, stock) VALUES ('JavaWeb实战', '张三', 69.9, 100);
   - 修改：UPDATE book SET stock = stock - 1 WHERE id = 1;
   - 删除：DELETE FROM cart WHERE user_id = 1 AND book_id = 2;
3. DQL（数据查询语言）：查询数据
   - 基础查询：SELECT name, author, price FROM book;
   - 条件查询：SELECT * FROM book WHERE price < 100 AND category_id = 2;
   - 排序查询：SELECT * FROM book ORDER BY price DESC;
   - 分页查询：SELECT * FROM book LIMIT 0, 10; -- 第1页，每页10条
   - 关联查询（Bookstore订单详情）：
     SELECT o.id, b.name, oi.quantity, oi.price 
     FROM `order` o
     JOIN order_item oi ON o.id = oi.order_id
     JOIN book b ON oi.book_id = b.id
     WHERE o.user_id = 1;
4. DCL（数据控制语言）：权限管理（企业运维常用）
   - 创建用户：CREATE USER 'bookstore_user'@'%' IDENTIFIED BY '123456';
   - 授权：GRANT ALL PRIVILEGES ON bookstore.* TO 'bookstore_user'@'%';
   - 刷新权限：FLUSH PRIVILEGES;
---------------------------------------------------------------------------------------------------------------------------------------
五、事务管理（Bookstore核心场景）
1. 事务：一组不可分割的SQL操作，要么全部执行成功，要么全部回滚。
2. Bookstore应用场景：生成订单时（扣减库存+插入订单+插入订单项），必须保证原子性。
3. 操作示例：
   START TRANSACTION; -- 开启事务
   -- 1. 扣减书籍库存
   UPDATE book SET stock = stock - 2 WHERE id = 1;
   -- 2. 插入订单
   INSERT INTO `order`(id, user_id, total_price, address, status) VALUES ('ORDER123', 1, 139.8, '北京市', 0);
   -- 3. 插入订单项
   INSERT INTO order_item(order_id, book_id, quantity, price) VALUES ('ORDER123', 1, 2, 69.9);
   COMMIT; -- 提交事务（全部成功）
   -- 若出错则回滚：ROLLBACK;

六、Bookstore项目中关系型数据库的使用要点
1. 表设计原则：
   - 遵循三范式，减少数据冗余（如订单表不重复存储书籍名称，通过外键关联）；
   - 核心表必须设置主键，关联表设置外键；
   - 常用查询字段建立索引，提升查询效率。
2. 性能优化：
   - 避免SELECT *，只查询需要的字段；
   - 分页查询使用LIMIT，避免一次性查询大量数据；
   - 复杂查询优先优化SQL，而非增加硬件。
3. 安全规范：
   - 禁止拼接SQL字符串，防止SQL注入（使用PreparedStatement/MyBatis #{ }）；
   - 数据库用户仅授予最小必要权限；
   - 定期备份数据，防止数据丢失。
---------------------------------------------------------------------------------------------------------------------------------------
七、核心总结
1. 关系型数据库以二维表存储数据，支持SQL和事务，遵循ACID原则，Bookstore项目中MySQL是首选；
2. 核心概念包括数据库、表、主键、外键、索引，表之间通过外键建立一对一/一对多/多对多关系；
3. 核心操作分为DDL（定义）、DML（操作）、DQL（查询）、DCL（控制），查询和事务是Bookstore的核心应用；
4. 订单生成等核心场景必须使用事务保证数据一致性，同时通过索引优化查询性能，防止SQL注入保证安全。
