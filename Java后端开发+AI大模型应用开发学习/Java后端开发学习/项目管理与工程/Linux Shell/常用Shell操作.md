常用Shell操作
本文聚焦Java后端开发日常工作，整理高频Shell操作，按「进程操作、日志操作、文件操作、端口操作、JVM操作、定时任务、权限操作」分类，每个操作包含「命令+说明+后端实操场景」，无需死记硬背，按需查阅即可直接复用。
一、进程操作（Java服务核心操作）
核心用于查看、管理Java进程，解决「服务启动失败、进程残留、强制停止服务」等问题，是后端部署、运维的基础。
操作目的
Shell命令
实操说明（后端场景）
查看所有Java进程
jps
Java专属命令，快速查看当前服务器所有Java进程的PID和进程名（如jar包名称），比ps命令更简洁，部署后快速验证进程是否启动。
查看指定Java进程详情
ps -ef | grep java
查看所有Java相关进程的完整信息（用户名、PID、启动时间、启动命令），可搭配管道筛选指定服务，如：ps -ef | grep project.jar（筛选目标SpringBoot项目进程）。
筛选指定进程（排除grep自身）
ps -ef | grep project.jar | grep -v grep
后端常用，避免grep命令自身被筛选出来，精准获取目标Java服务的进程信息，常用于脚本中判断服务是否运行。
强制停止Java进程
kill -9 PID
PID为进程ID（通过jps或ps命令获取），后端部署时必用，用于停止旧服务或异常残留进程，如：kill -9 12345（停止PID为12345的Java服务）。
优雅停止Java进程（推荐）
kill -15 PID
比kill -9更安全，会允许Java进程释放资源后再停止，适合生产环境正常重启服务，减少资源泄露风险。
二、日志操作（排查Java异常必备）
Java服务异常（接口报错、服务挂掉、JVM异常）均需通过日志排查，以下操作覆盖「实时查看、筛选、搜索、统计」等核心需求，适配SpringBoot默认日志格式。
操作目的
Shell命令
实操说明（后端场景）
实时查看日志（最常用）
tail -f 日志文件路径
实时监控日志输出，排查服务启动失败、接口运行异常，如：tail -f /usr/local/java/project.log（实时查看SpringBoot项目日志），按Ctrl+C停止。
查看日志最后N行
tail -n 100 日志文件路径
快速查看最近的日志内容，无需实时监控，如：tail -n 200 project.log（查看最后200行日志，快速定位最新异常）。
搜索日志中的关键词
grep "关键词" 日志文件路径
筛选包含指定关键词的日志，排查具体异常，如：grep "Error" project.log（筛选所有错误日志）、grep "NullPointerException" project.log（排查空指针异常）。
搜索关键词并显示行号
grep -n "关键词" 日志文件路径
便于定位异常在日志中的具体位置，后续可结合sed命令查看上下文，如：grep -n "接口调用失败" project.log。
筛选指定时间段的日志
sed -n "/开始时间/,/结束时间/p" 日志文件路径
精准排查某一时间段的异常，适配SpringBoot日志时间格式（如2026-03-25 10:00:00），如：sed -n "/2026-03-25 09:00:00/,/2026-03-25 10:00:00/p" project.log。
统计关键词出现次数
grep "关键词" 日志文件路径 | wc -l
统计异常出现频率，判断异常严重程度，如：grep "数据库连接失败" project.log | wc -l（统计数据库连接异常次数）。
三、文件操作（部署Java项目常用）
核心用于「上传/下载jar包、备份文件、管理项目目录」，是Java项目部署的基础操作，覆盖后端日常文件管理需求。
操作目的
Shell命令
实操说明（后端场景）
上传文件（本地→服务器）
rz
直接输入rz，弹出本地文件选择窗口，选择jar包、配置文件等上传到服务器当前目录，部署时上传新jar包常用。
下载文件（服务器→本地）
sz 文件名
将服务器上的文件下载到本地，如：sz project.log（下载日志文件到本地分析）、sz backup.jar（下载备份的jar包）。
复制文件（备份jar包常用）
cp 源文件路径 目标路径
部署时备份旧jar包，如：cp /usr/local/java/project.jar /usr/local/java/backup/project_backup.jar，避免部署失败无法回滚。
创建目录
mkdir -p 目录路径
-p表示递归创建目录（父目录不存在时自动创建），如：mkdir -p /usr/local/java/backup（创建jar包备份目录），部署脚本中常用。
删除文件/目录
rm -rf 文件/目录路径
-r删除目录，-f强制删除（无需确认），后端用于删除旧jar包、无用日志，如：rm -rf old_project.jar（删除旧jar包），注意谨慎使用，避免误删。
查看目录下的文件
ls / ls -l
ls查看简单文件列表，ls -l查看文件详细信息（权限、大小、修改时间），部署时查看jar包是否上传成功、日志文件是否生成。
切换目录
cd 目录路径
切换到指定目录，如：cd /usr/local/java/project（切换到jar包存放目录），执行启动服务、查看日志等操作前必做。
四、端口操作（解决Java服务启动失败）
Java服务启动失败，常见原因是「端口冲突」，以下操作用于查看端口占用、释放端口，快速排查启动异常。
操作目的
Shell命令
实操说明（后端场景）
查看所有监听端口
netstat -tln
查看服务器所有正在监听的端口，了解端口占用情况，排查是否有其他服务占用Java服务的端口（如8080、8090）。
查看指定端口占用情况
netstat -tln | grep 端口号
快速判断目标端口是否被占用，如：netstat -tln | grep 8080（查看8080端口是否被占用），若有输出则表示端口已被占用。
查看占用端口的进程
lsof -i:端口号
比netstat更精准，可直接查看占用指定端口的进程PID和进程名，如：lsof -i:8080，找到占用端口的进程后，用kill命令停止。
释放端口（停止占用进程）
kill -9 PID
通过lsof或netstat找到占用端口的进程PID，执行kill命令停止进程，释放端口，如：lsof -i:8080找到PID为1234，执行kill -9 1234，释放8080端口。
五、JVM操作（排查Java性能问题）
用于监控JVM运行状态、排查「内存溢出、线程死锁、性能瓶颈」等问题，是Java后端高级运维的必备操作。
操作目的
Shell命令
实操说明（后端场景）
监控JVM内存使用情况
jstat -gc PID 1000 10
实时监控JVM堆内存（GC情况、内存占用），1000表示每隔1000毫秒（1秒）输出一次，10表示输出10次，用于排查内存溢出、GC频繁问题。
查看JVM堆内存详细信息
jmap -heap PID
查看JVM堆内存的分配情况（年轻代、老年代、元空间大小及使用情况），判断内存配置是否合理，如：jmap -heap 12345（查看PID为12345的Java进程堆内存）。
查看JVM线程状态（排查死锁）
jstack PID
输出JVM所有线程的状态，排查线程死锁、线程阻塞问题，如：jstack 12345 > thread.log（将线程信息输出到文件，便于分析）。
生成JVM堆内存快照
jmap -dump:format=b,file=heapdump.hprof PID
生成堆内存快照文件，用于后续用JVisualVM等工具分析内存溢出原因，如：jmap -dump:format=b,file=heapdump.hprof 12345，将快照下载到本地分析。
六、定时任务操作（生产环境运维必备）
用于设置「定时监控Java服务、定时备份日志、定时清理文件」等任务，减少后端手动运维成本，适配生产环境需求。
操作目的
Shell命令
实操说明（后端场景）
编辑定时任务
crontab -e
打开定时任务编辑界面，添加定时任务，如：*/5 * * * * /usr/local/java/monitor_service.sh（每5分钟执行一次服务监控脚本）。
查看所有定时任务
crontab -l
查看当前用户的所有定时任务，确认定时任务是否添加成功、是否生效。
删除所有定时任务
crontab -r
谨慎使用，用于删除当前用户的所有定时任务，若需删除单个任务，用crontab -e编辑删除。
查看定时任务执行日志
grep CRON /var/log/syslog
查看定时任务的执行情况，排查定时任务是否执行失败，如：grep CRON /var/log/syslog | grep monitor_service.sh（查看监控脚本的定时执行日志）。
七、权限操作（解决Shell脚本/文件执行异常）
Java后端部署时，常遇到「脚本无法执行、文件无法读写」等权限问题，以下操作用于配置文件、脚本的权限，确保服务正常运行。
操作目的
Shell命令
实操说明（后端场景）
赋予脚本可执行权限（最常用）
chmod +x 脚本路径
部署脚本、监控脚本创建后，必须赋予可执行权限才能执行，如：chmod +x deploy.sh（赋予部署脚本可执行权限）。
赋予文件读写权限
chmod +rw 文件名
确保Java程序能读写日志文件、配置文件，如：chmod +rw project.log（赋予日志文件读写权限，避免日志无法写入）。
递归赋予目录及文件权限
chmod -R 777 目录路径
-R表示递归处理目录下所有文件，777表示所有用户拥有读写执行权限，用于快速解决目录权限不足问题，如：chmod -R 777 /usr/local/java（赋予Java项目目录所有权限），生产环境谨慎使用，避免权限过高。
查看文件/目录权限
ls -l 文件名/目录路径
查看文件/目录的权限配置，排查权限不足问题，如：ls -l deploy.sh（查看脚本的权限，确认是否有可执行权限）。
八、常用快捷键（提升操作效率）
补充后端操作Shell时的高频快捷键，减少命令输入，提升操作效率：
Ctrl+C：停止当前正在执行的命令（如停止tail -f实时日志）。
Ctrl+L：清空终端屏幕，避免日志、命令过多影响查看。
Tab键：自动补全命令、文件名、目录路径（后端常用，减少输入错误）。
↑↓箭头：查看历史执行命令，无需重复输入常用命令（如重复执行jps、tail -f）。
Ctrl+Z：暂停当前命令，后续可通过fg命令恢复执行。
九、注意事项
执行rm -rf命令时务必谨慎，建议先通过ls命令确认文件/目录，避免误删核心文件（如jar包、日志）。
kill -9命令会强制终止进程，可能导致资源泄露，非必要情况下优先使用kill -15优雅停止。
定时任务路径需写绝对路径（如/usr/local/java/monitor_service.sh），避免因相对路径导致任务执行失败。
赋予权限时，生产环境尽量避免使用chmod 777，根据实际需求配置最小权限，保障服务器安全。
查看日志、进程时，可结合管道（|）灵活筛选，减少无效信息，提升排查效率。
