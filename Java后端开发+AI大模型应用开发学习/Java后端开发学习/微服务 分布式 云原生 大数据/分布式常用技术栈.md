分布式常用技术栈
分布式系统的核心目标是解决“高可用、高并发、可扩展、数据一致性”四大问题，常用技术栈围绕核心目标，按功能模块可分为分布式通信、服务治理、数据存储、消息队列、分布式协调、监控运维六大类，每类包含主流技术及适用场景，具体如下：
一、分布式通信技术（核心：实现节点间高效、可靠通信）
分布式系统中，不同节点、服务之间的通信是基础，分为“同步通信”和“异步通信”两类，核心技术如下：
HTTP/HTTPS：最基础的跨节点通信协议，基于请求-响应模式，适用于简单的服务调用（如前后端交互、跨服务简单查询），优点是通用性强、易调试，缺点是开销较大、无长连接支持，常用框架有Spring Cloud OpenFeign（基于HTTP的声明式调用）。
RPC（远程过程调用）：专为服务间通信设计，基于TCP/UDP，调用过程类似本地方法，开销小、效率高，适用于高频、低延迟的服务调用，主流框架包括：
Dubbo：阿里开源，轻量级、高性能，支持负载均衡、服务降级，适用于Java生态的微服务架构；
gRPC：Google开源，基于HTTP/2和Protobuf，跨语言支持性强（Java、Go、Python等），适用于多语言协同的分布式系统；
Thrift：Facebook开源，跨语言、高吞吐量，适用于大数据场景下的服务通信。
WebSocket：基于TCP的长连接协议，支持双向实时通信，适用于实时消息推送、在线聊天、实时监控等场景，常用框架有Netty（Java）、WebSocket-Sharp（C#）。
二、服务治理技术（核心：解决服务集群的可管理、高可用）
当服务数量增多，需解决“服务注册发现、负载均衡、熔断降级、配置管理”等问题，核心技术栈如下：
服务注册与发现：实现服务节点的动态注册和查询，避免硬编码服务地址，主流组件：
Nacos：阿里开源，集注册中心、配置中心于一体，支持CP/AP模式切换，适配微服务架构；
Eureka：Netflix开源，基于AP模式，高可用、易部署，适用于Spring Cloud生态；
Consul：HashiCorp开源，支持服务发现、配置管理、服务网格，跨平台性强。
负载均衡：将请求分发到多个服务节点，避免单点过载，分为“客户端负载均衡”和“服务端负载均衡”：
客户端负载均衡：Dubbo、Ribbon（Spring Cloud），在客户端侧实现请求分发，减少服务端压力；
服务端负载均衡：Nginx、HAProxy，部署在服务集群前端，统一接收请求并分发，支持TCP/HTTP协议。
熔断与降级：防止服务雪崩（一个服务故障导致连锁故障），核心组件：
Sentinel：阿里开源，支持流量控制、熔断降级、系统保护，适配Java生态，配置灵活；
Hystrix：Netflix开源，基于舱壁模式，实现熔断、降级、缓存，适用于Spring Cloud生态（已停止更新，推荐Sentinel）。
配置中心：实现分布式系统中配置的统一管理、动态更新，避免配置分散在各个节点，主流组件：Nacos、Apollo（携程开源，支持灰度发布、权限管理）、Spring Cloud Config。
三、分布式数据存储技术（核心：解决海量数据的分布式存储与一致性）
分布式存储需满足“高容量、高可用、可扩展、数据一致”，分为“关系型数据库”“非关系型数据库”“分布式文件存储”三类：
1. 分布式关系型数据库（MySQL为主）
基于MySQL实现分布式部署，解决单库容量和并发瓶颈，核心方案：
主从复制+读写分离：主库负责写操作，从库负责读操作，提升读并发，常用工具：MHA（主从切换）、Keepalived（高可用）；
分库分表：将单库大表拆分为多个库、多个表，解决数据量大的问题，主流框架：
Sharding-JDBC：客户端侧分库分表，无侵入性，适配Java生态；
MyCat：服务端侧分库分表，支持多种数据库，适用于多语言场景。
分布式数据库产品：TiDB（PingCAP开源，NewSQL，支持强一致性）、OceanBase（阿里开源，高可用、高并发，适配金融级场景）。
2. 分布式非关系型数据库（NoSQL）
适用于非结构化、半结构化数据（如日志、图片、用户行为数据），按存储类型分类：
键值存储：Redis（主流）、Memcached，适用于缓存、会话存储、计数器，Redis支持持久化、集群模式（Redis Cluster），可实现高可用；
文档存储：MongoDB，适用于文档类数据（如文章、商品详情），支持分片集群，可扩展；
列族存储：HBase，基于Hadoop，适用于海量时序数据（如日志、监控数据），高吞吐量、可扩展；
图数据库：Neo4j、NebulaGraph，适用于关系型数据（如社交网络、知识图谱），高效查询节点关系。
3. 分布式文件存储
适用于海量文件（如图片、视频、日志文件）的存储，核心技术：
HDFS（Hadoop Distributed File System）：适用于大数据场景，高吞吐量、高容错，支持PB级数据存储；
MinIO：轻量级、兼容S3协议，适用于对象存储（如图片、附件），支持分布式部署，易维护；
FastDFS：阿里开源，专为文件存储设计，支持文件上传、下载、同步，适用于中小规模文件存储场景。
四、消息队列技术（核心：解耦服务、削峰填谷、异步通信）
通过消息中间件实现服务间异步通信，避免服务直接耦合，应对高并发场景的流量峰值，主流组件：
RabbitMQ：基于AMQP协议，支持多种消息模式（点对点、发布订阅、死信队列），可靠性高、易部署，适用于中小规模系统；
Kafka：基于分区机制，高吞吐量、高可用，适用于大数据场景（如日志收集、实时数据流），支持海量消息存储；
RocketMQ：阿里开源，支持事务消息、延迟消息，可靠性高，适用于金融级、高并发场景（如订单支付、消息推送）；
Pulsar： Yahoo开源，融合Kafka和RabbitMQ的优势，支持多租户、分层存储，适用于复杂场景的消息通信。
五、分布式协调技术（核心：解决分布式一致性、节点同步问题）
分布式系统中，节点间的状态同步、一致性决策（如分布式锁、主节点选举）需依赖协调组件，主流技术：
ZooKeeper：Apache开源，基于ZAB协议，提供分布式锁、节点选举、配置同步等功能，是分布式系统的“协调中枢”，适用于各类分布式场景；
Etcd：CoreOS开源，基于Raft协议，轻量级、高可用，支持键值存储、分布式锁，适用于K8s生态（作为K8s的配置存储）；
Redlock：基于Redis实现的分布式锁方案，适用于高并发场景，解决单机Redis锁的可靠性问题。
六、监控运维技术（核心：保障分布式系统稳定运行、快速排查问题）
分布式系统节点多、逻辑复杂，需完善的监控、日志、链路追踪能力，核心技术栈：
监控系统：Prometheus（主流）+ Grafana，Prometheus负责数据采集（指标监控），Grafana负责可视化展示，支持告警配置；此外还有Zabbix、Nagios（传统监控工具）；
日志收集与分析：ELK Stack（Elasticsearch+Logstash+Kibana），Logstash收集日志，Elasticsearch存储和检索，Kibana可视化分析；Fluentd（轻量级日志收集工具），适用于容器场景；
分布式链路追踪：SkyWalking（开源，支持多语言、多框架）、Jaeger（Uber开源，适配K8s）、Zipkin（Twitter开源，适用于Spring Cloud生态），用于追踪服务调用链路，排查跨服务问题；
容器化与编排：Docker（容器化部署，统一环境）+ Kubernetes（K8s，容器编排，实现节点调度、自动扩缩容、高可用），是分布式系统部署的主流方案，搭配Helm（K8s包管理工具）提升部署效率。
七、补充：分布式核心支撑技术
分布式事务：解决跨服务、跨数据库的事务一致性问题，主流方案：2PC（两阶段提交，如Seata AT模式）、TCC（补偿事务）、SAGA模式、本地消息表；
CDN（内容分发网络）：如阿里云CDN、Cloudflare，将静态资源（图片、视频）分发到边缘节点，提升用户访问速度，减轻源站压力；
反向代理：Nginx、Traefik，除负载均衡外，还支持动静分离、SSL终止、请求过滤，是分布式系统的入口层核心组件。
总结：分布式技术栈的选择需结合业务场景（高并发、高可用、数据量）和技术生态，例如：微服务架构常用「Spring Cloud + Nacos + Dubbo + MySQL + Redis + RabbitMQ」；大数据架构常用「Hadoop + HBase + Kafka + Spark」；容器化部署常用「Docker + K8s + Prometheus + ELK」。
