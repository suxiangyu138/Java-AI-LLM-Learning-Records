# 爬虫知识体系

爬虫生态体系是指围绕网络数据采集构建的一整套技术栈、工具链和工程实践，涵盖从网络基础到分布式架构的完整知识图谱。

---

## 一、网络基础

### 1.1 HTTP/HTTPS 协议

- **请求方法**：GET、POST、PUT、DELETE、PATCH、HEAD、OPTIONS
- **请求头**：User-Agent、Referer、Cookie、Content-Type、Authorization、Origin
- **响应状态码**：2xx 成功、3xx 重定向、4xx 客户端错误、5xx 服务端错误
- **HTTPS 握手流程**：TCP 三次握手 → TLS 1.2/1.3 握手 → 加密通信
- **HTTP/2、HTTP/3（QUIC）**：多路复用、头部压缩、0-RTT

### 1.2 TCP/IP 与网络栈

- TCP 三次握手/四次挥手
- Socket 编程基础
- DNS 解析流程（递归查询、迭代查询）
- CDN 与智能 DNS 调度
- 抓包工具：Wireshark、tcpdump、Fiddler、Charles、mitmproxy

### 1.3 浏览器工作原理

- DOM 树构建与 CSSOM 合成
- JavaScript 执行引擎（V8、JavaScriptCore）
- 事件循环（Event Loop）：宏任务与微任务
- 渲染流程：Layout → Paint → Composite
- Service Worker 与离线缓存机制

### 3.1 常见反爬策略

| 分类 | 策略 | 难度 |
|------|------|------|
| 请求层 | User-Agent 检测、Referer 校验、频率限制 | ⭐ |
| Header 校验 | Cookie 校验、Token 签名、时间戳验证 | ⭐⭐ |
| JS 动态参数 | 前端加密、动态 Token 生成、环境检测 | ⭐⭐⭐ |
| 验证码 | 滑块、点选、旋转、算术、文字识别 | ⭐⭐⭐ |
| 浏览器指纹 | Canvas/WebGL/Audio 指纹、字体检测、WebRTC | ⭐⭐⭐⭐ |
| 行为分析 | 鼠标轨迹、操作间隔、页面停留时间 | ⭐⭐⭐⭐ |
| 网络层 | TLS 指纹（JA3/JA4）、IP 信誉库、ASN 拦截 | ⭐⭐⭐⭐ |
| 高级 | WASM 加密、VM 混淆、设备指纹、风控模型 | ⭐⭐⭐⭐⭐ |

### 3.2 对抗手段

#### IP 代理体系

```
代理池架构：
┌─────────┐    ┌──────────┐    ┌─────────┐
│ 代理源   │ →  │ 校验与评分 │ →  │ 代理池   │
│ (API/自建)│    │  (可用性/延迟)│    │ (Redis)  │
└─────────┘    └──────────┘    └────┬────┘
                                    │
┌─────────┐    ┌──────────┐    ┌───┴─────┐
│ 爬虫客户端 │ ←  │ 中间件分发 │ ←  │ 调度策略  │
└─────────┘    └──────────┘    └─────────┘
```

- **代理类型**：HTTP 代理、HTTPS 隧道、SOCKS5、ADSL 拨号（动态 IP）
- **代理来源**：付费 API（快代理、芝麻代理、Bright Data）、云函数部署、家宽代理
- **校验指标**：可用率、响应延迟、匿名度、地理位置
- **调度策略**：随机轮换、加权分配、按目标站点分池、冷却机制
- **隧道代理 vs 直连代理**：隧道自动切换 IP，直连每次请求更换

#### 验证码识别

| 类型 | 方案 |
|------|------|
| 传统图形验证码 | OCR（Tesseract）、CNN 模型（准确率 95%+） |
| 滑块验证码 | OpenCV 边缘检测 + 轨迹生成（匀加速→匀速→匀减速）|
| 点选验证码 | YOLO 目标检测 + 逻辑坐标映射 |
| 旋转验证码 | 旋转角度回归模型 |
| 文字点击 | NLP 语义匹配 + 目标检测 |
| 无感验证 | 行为模拟 + 环境伪造 + IP 纯净度 |

**识别方案**：
- 本地模型推理（ONNX、TensorFlow Lite）
- 打码平台（超级鹰、图鉴、2Captcha）
- 半自动：人工打码 + 缓存（首次人工，后续复用）

#### 浏览器指纹对抗

```
采集维度：
├── Navigator 属性（platform, hardwareConcurrency, deviceMemory）
├── Canvas/WebGL 指纹（渲染差异性）
├── AudioContext 指纹（音频处理差异）
├── 字体列表枚举
├── WebRTC 泄露真实 IP
├── Screen 分辨率与色深
├── Timezone / Language
└── Battery / 传感器 API
```

**对抗方案**：
- puppeteer-extra + puppeteer-extra-plugin-stealth
- `navigator.webdriver` 抹除
- CDP（Chrome DevTools Protocol）注入 JS 覆盖原生属性
- 定制浏览器（Chromium patch 编译）

#### JS 逆向工程

**核心链路**：请求分析 → 参数定位 → 加密还原 → 算法复现

- **定位技巧**：XHR 断点、DOM 事件断点、Hook（JSON.stringify / Function.prototype.apply）
- **分析工具**：Chrome DevTools Snippets、AST Explorer、Reres 替换
- **加密对抗**：对称加密（AES/DES）、非对称加密（RSA）、哈希（MD5/SHA）、自定义算法
- **混淆对抗**：
  - **OB 混淆**（obfuscator.io）→ AST 反混淆还原
  - **JSVMP**（虚拟机保护）→ 指令集逆向 + 模拟执行
  - **商业混淆**（JScrambler、Akamai、Cloudflare）→ 源码阅读 + 逐行还原
  - **WASM 加密** → wasm2c 反编译 + 动态调试
- **工具链**：AST（babel/espree/recast）、补环境（Proxy + 原型链）、微信小程序反编译（wxappUnpacker）

#### Cookie 与 Session 管理

- **Cookie 生命周期**：登录态刷新、过期提前重登
- **多账号池**：账号轮换、权重评分、异常自动隔离
- **登录方式**：密码登录、验证码登录、扫码登录、第三方 OAuth
- **自动化登录**：Selenium/Playwright 模拟 + 验证码处理 + Cookie 持久化

- **PDF 解析**：pdfplumber、PyMuPDF、Camelot（表格提取）

## 五、数据存储

### 5.1 数据库选型

| 存储类型 | 数据库 | 适用场景 |
|----------|--------|----------|
| 关系型 | MySQL、PostgreSQL | 结构化数据、复杂查询、事务 |
| 文档型 | MongoDB | JSON 文档、Schema 灵活、快速迭代 |
| KV 存储 | Redis、LevelDB | 缓存、去重、计数器、队列 |
| 搜索引擎 | Elasticsearch、Meilisearch | 全文检索、聚合分析 |
| 时序 | InfluxDB、TimescaleDB | 监控指标、价格时间线 |
| 列式 | ClickHouse、HBase | 海量数据分析、日志存储 |
| 图 | Neo4j | 社交关系、知识图谱 |
| 对象存储 | MinIO、S3 | 文件、图片、视频 |

### 5.2 数据去重方案

| 方案 | 原理 | 特点 |
|------|------|------|
| MD5/SHA 指纹 | 内容哈希 | 精确去重，适合文本 |
| Bloom Filter | Bit 数组 + 多哈希 | 内存高效，有误判率，适合 URL 去重 |
| SimHash | 局部敏感哈希 | 海量文本相似去重 |
| MinHash + LSH | 集合相似度 | 段落级去重 |
| Redis Set/ZSet | 内存集合 | 分布式去重，按时间排序 |
| Scrapy-Redis | Redis 去重 | Scrapy 生态集成 |

### 5.3 数据写入策略

- **单条写入**：适合低频采集
- **批量写入**：提高吞吐，MySQL `executemany`、MongoDB `insert_many`
- **异步写入**：生产者-消费者模型，解耦采集与存储
- **流式写入**：Kafka → Flink/Spark Streaming → 存储
- **连接池管理**：控制并发，避免连接耗尽

## 六、分布式架构

### 6.1 核心组件

```
                    ┌─────────────┐
                    │  调度中心    │  (任务分发、状态管理)
                    └──────┬──────┘
                           │
              ┌────────────┼────────────┐
              │            │            │
         ┌────┴───┐   ┌───┴────┐   ┌──┴─────┐
         │ 爬虫节点 │   │ 爬虫节点 │   │ 爬虫节点 │  (多实例，水平扩展)
         └────┬───┘   └───┬────┘   └──┬─────┘
              │            │            │
              └────────────┼────────────┘
                           │
                    ┌──────┴──────┐
                    │   消息队列   │  (Redis/Kafka/RabbitMQ)
                    └──────┬──────┘
                           │
              ┌────────────┼────────────┐
              │            │            │
         ┌────┴───┐   ┌───┴────┐   ┌──┴─────┐
         │ 解析节点 │   │ 清洗节点 │   │ 存储节点 │
         └────────┘   └────────┘   └────────┘
```

### 6.2 消息队列

| 中间件 | 特点 | 适合场景 |
|--------|------|----------|
| Redis List/Stream | 轻量、部署简单 | 中小规模 |
| RabbitMQ | 可靠投递、灵活路由 | 对可靠性要求高 |
| Kafka | 高吞吐、持久化、回溯 | 大规模数据管道 |
| Redis Pub/Sub | 实时推送、不持久 | 配置热更新广播 |
| Disque（已归档） | Redis 作者出品 | 已不推荐 |

### 6.3 任务调度策略

- **公平调度**：轮询分发
- **加权调度**：按节点能力分配
- **哈希调度**：相同域名/任务固定节点（利用本地缓存）
- **优先级队列**：紧急任务插队
- **失败重试**：指数退避（1s → 2s → 4s → 8s…）、最大重试次数
- **死信队列**：超过重试上限的任务进入人工处理

### 6.4 分布式去重

- **布隆过滤器集群**：Redis BitMap + 多 Hash 函数，内存占用 O(n)
- **Redis Set**：直接存储 MD5，精确去重
- **Roaring Bitmap**：压缩位图，适合大规模整数 ID 去重
- **HBase/HDFS 去重**：离线去重场景

### 6.5 分布式锁

- **Redis SET NX EX**：防止重复采集同一任务
- **ZooKeeper/Etcd**：强一致性锁，选主
- **Redlock 算法**：Redis 分布式锁的进阶方案

## 七、爬虫策略

### 7.1 遍历策略

| 策略 | 说明 |
|------|------|
| 广度优先（BFS） | URL 队列先进先出，覆盖面广 |
| 深度优先（DFS） | URL 栈后进先出，适合目录结构 |
| 最佳优先 | 按 URL 质量评分排序，优先高质量页面 |
| 增量式 | 只采集新增/更新的页面 |
| 聚焦爬虫 | 主题相关性打分，只爬取相关内容 |

### 7.2 更新策略

- **定时全量**：定期完整采集
- **增量更新**：时间戳/ID 增量、changefreq+sitemap、etag/last-modified 判断
- **事件驱动**：监听 Webhook / RSS 通知后触发
- **自适应频率**：根据目标站更新频次动态调整

### 7.3 频率控制

| 算法 | 公式/原理 | 特点 |
|------|----------|------|
| 固定间隔 | `sleep(N)` | 简单粗暴 |
| 令牌桶 | 固定速率生成令牌，请求消费令牌 | 允许突发流量 |
| 漏桶 | 固定速率处理请求 | 平滑输出 |
| 滑动窗口 | 统计最近 N 秒内请求数 | 精确限流 |
| PID 控制 | 根据响应时间动态调整并发 | 自适应 |
| 随机延迟 | `sleep(random(min, max))` | 模拟人类行为 |

### 7.4 robots.txt 解析

- 标准字段：User-agent、Allow、Disallow、Crawl-delay、Sitemap
- Python：`urllib.robotparser`、`robotparser`、`reppy`
- 抓取前自动检查，可配置是否遵守

## 八、监控与运维

### 8.1 监控指标

```
采集层：
├── 请求总量 / 成功率 / 失败率
├── 各域名/站点 采集量分布
├── 平均响应时间 / P99 延迟
├── HTTP 状态码分布（200/301/403/429/500...）
└── 代理 IP 使用量 / 可用率

数据层：
├── 入库量 / 入库速率（条/秒）
├── 去重命中率
├── 数据空值率 / 异常值率
└── 数据时效性（采集到入库的时间差）

系统层：
├── 各节点 CPU / 内存 / 磁盘 / 网络
├── 队列积压量
├── 错误日志量
└── 节点在线状态
```

### 8.2 告警体系

- **告警渠道**：邮件、企业微信、钉钉机器人、飞书、Slack、电话
- **告警分级**：
  - P0（紧急）：全站采集停止、数据丢失
  - P1（重要）：单站不可用、入库延迟 > 30min
  - P2（一般）：代理可用率下降、成功率 < 90%
  - P3（通知）：日常任务完成通知
- **告警策略**：告警收敛（5 分钟内同类告警合并）、告警升级（未处理则升级渠道）

### 8.3 日志体系

```yaml
日志分层：
  - 采集日志：请求 URL、状态码、响应时间、代理 IP
  - 错误日志：堆栈跟踪、重试记录、验证码触发记录
  - 数据日志：解析字段、入库状态、数据异常
  - 系统日志：心跳、资源使用、配置变更

工具链：
  - 采集：Python logging / loguru + ELK (Elasticsearch+Logstash+Kibana)
  - 可视化：Grafana + Prometheus
  - 链路追踪：Jaeger / SkyWalking（微服务场景）
```

### 11.1 ETL 流程

```
Extract（抽取）→ Transform（转换）→ Load（加载）
     │                  │                  │
  原始页面          数据清洗            最终存储
  API 响应          字段映射            搜索引擎
  文件下载          格式标准化          数据仓库
```

### 11.2 常见后处理

- **文本处理**：HTML 标签清洗、特殊字符转义、Unicode 规范化
- **字段映射**：不同来源数据字段统一（手机号/电话/mobile/tel → phone）
- **数据关联**：多源数据融合、实体对齐
- **地理编码**：地址 → 经纬度（高德/百度/Google 地理编码 API）
- **敏感信息脱敏**：姓名哈希、手机号掩码（138****1234）

### 11.3 数据质量保障

- **Schema 校验**：JSON Schema / Pydantic 模型验证
- **数据完整性**：必填字段检查、数据条数核对
- **数据准确性**：字段类型校验、枚举值范围检查
- **数据时效性**：采集时间戳验证、过期数据标记
- **数据血缘**：记录数据来源、采集时间、处理链路

## 十二、合规与法律边界

### 12.1 法律框架

- **robots.txt 协议**：行业自律规范，非法律强制
- **《中华人民共和国个人信息保护法》**：个人信息的收集需取得同意
- **《中华人民共和国数据安全法》**：数据分类分级保护、重要数据出境
- **《中华人民共和国网络安全法》**：不得非法侵入他人网络
- **《反不正当竞争法》**：抓取竞争对手数据进行不正当竞争
- **GDPR（欧盟《通用数据保护条例》）**：任何涉及欧盟公民个人数据的处理
- **CCPA（加州消费者隐私法案）**：针对加州居民的数据权利

### 12.2 刑事红线

- **《刑法》第 285 条**：非法侵入计算机信息系统罪
- **《刑法》第 253 条之一**：侵犯公民个人信息罪
- **破坏计算机信息系统罪**：导致目标服务器瘫痪

### 12.3 爬虫合规实践

- ✅ 公开数据：工商信息、政府公开数据、价格展示
- ✅ robots.txt 允许的范围
- ✅ 合理频率采集（不造成服务器压力）
- ✅ 学术研究、个人学习
- ❌ 绕过认证访问非公开数据
- ❌ 抓取个人信息且未经授权（手机号、身份证、聊天记录）
- ❌ 破解加密/认证机制
- ❌ 采集竞争对手的商业秘密
- ❌ 采集后用于不正当竞争（复制网站、截取用户）

### 12.4 业内有代表性的判例

- **大众点评 v 百度地图**：抓取用户点评数据 → 构成不正当竞争
- **LinkedIn v hiQ**（美国）：公开数据抓取是否合法，案件反复
- **微博 v 脉脉**：抓取微博用户数据 → 认定不正当竞争
- **淘宝 v 美景**：抓取商品数据 → 构成不正当竞争
