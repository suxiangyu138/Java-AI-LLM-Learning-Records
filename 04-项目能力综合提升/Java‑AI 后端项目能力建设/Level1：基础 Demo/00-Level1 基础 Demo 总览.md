## 3. 学习路线推荐

**标准路径（2-3 周，每天 1-2 小时）**：按 01→10 顺序推进，前五个 Demo 如果仓库 Java 基础扎实可以加速（每个 1 天），06 之后放慢（每个 2 天），08 闭环留 2-3 天打磨。每个 Demo 完成标准是"**能独立重写一遍**"，而不是"跑通了"。

**加速路径（已有 Spring 基础，1 周）**：01、02 直接跳过，从 03 开始；03-05 快速过；重点在 06-08 的 AI 链路。

**查漏路径（面试前补基础）**：只做 06 与 08，把 LLM 调用与最小闭环跑通，其余回仓库对应体系补知识。

**每日节奏建议**：每次学习以一个"可运行的小目标"收尾（今天让接口返回 JSON、今天让缓存命中），而不是"看完一节"——Demo 期最有价值的是连续的正反馈：每 30-60 分钟有一次"跑通了"的体验，学习动力和记忆效果都远超读教程。卡住超过 30 分钟先查 09 篇速查表，再卡就跳过或问人，不要在一处死磕——Demo 期的时间应该花在"覆盖全链路"上，深度留给 Level2。

## 5. Level1 在能力建设中的定位

三级结构的逻辑是**递进收口**：Level1 用最小成本建立"Java + AI 全链路能跑通"的信心与技术底座；Level2 把链路工程化（规范、测试、部署、可观测）并沉淀成简历核心项目；Level3 在项目上叠加高并发、微服务等加分能力。Level1 容易犯的两个方向性错误要提前避免：**一是追求工程化**——Demo 阶段用 Lombok、写单元测试、搞 CI 都是过度投入，Level2 再做；**二是跳过基础**——直接抄 Level2 的项目代码，结果每个组件都不理解，面试追问全崩。Level1 的正确产出不是"能运行的代码"，而是**"每个环节都亲手写过的理解"**。

与仓库其他体系的关系：01-05 对应「Spring框架核心」「MyBatisPlus」「Redis」等体系，本层是它们的动手验证层；06-08 对应「Spring AI」「Function Calling」「RAG拓展优化深化」体系，本层是它们的入门实践层；「双栈联合实战」是 Level2 之后的主力项目，本层的 08 闭环是它的迷你版预演——双栈项目的 Java 侧做的正是"知识问答闭环 + 业务底座"，08 的代码在 Level2 会被工程化改造后直接复用。

与「Python‑LLM 应用开发项目能力建设」的对称关系：两个能力建设目录是同一张蓝图的两半——本目录用 Java 实现后端与 AI 集成，Python 目录用 FastAPI + LangChain 实现同样的 AI 能力（RAG、Agent）。两套都完成后，把两端拼起来就是「双栈联合实战」的完整项目。**先做哪套都行**，但建议以本目录为先——Java 侧是业务底座，且与仓库既有 Java 体系衔接最顺；做完 Level1 的 08 闭环后，再去看 Python 侧的 RAG 教程，会发现自己已经理解了 80% 的概念（分块、向量化、检索、注入都是同一套思想）。

与「实战项目综合落地」的分工：那边是"做哪些项目"的清单与目标（20 个必做项目的定位），本目录是"每个 Level 怎么做"的实操路径。两者对照使用：实战清单定方向，本目录定步骤。Level1 完成后回头看实战清单里的「SpringBoot 必做项目」「SpringAI 必做项目」，会发现大部分条目已经覆盖。

## 6. 八个 Demo 一览与推进节奏

| Demo | 核心技术点 | 建议耗时 |
|---|---|---|
| 01 环境 | JDK 25 / IDEA / Maven 镜像 | 0.5-1 天 |
| 02 语法 | record / Stream / Optional / 异常 | 1-2 天 |
| 03 Spring | REST 接口 / 自动配置 / 依赖注入 | 1-2 天 |
| 04 数据 | MySQL / MyBatis-Plus / 事务 | 2 天 |
| 05 缓存 | Redis / 序列化 / 旁路缓存 | 1-2 天 |
| 06 模型 | OpenAI 兼容协议 / 双路线 / 流式 | 2 天 |
| 07 RAG | 分块 / 向量化 / 检索 / 注入 | 2 天 |
| 08 闭环 | 四模块整合 / 调优记录 | 2-3 天 |

节奏建议：01-05 是纯后端手感恢复（仓库 Java 基础扎实可压缩到 3 天），06 之后进入 AI 新知识区放慢（每天 1-2 小时连续推进，不要隔几天再碰——AI 链路的知识连续性很强，中断一周等于重看一遍）。

## 7. 使用建议

每个 Demo 模块的结构一致：**目标 → 前置 → 步骤 → 代码 → 验证 → 常见坑**。学习时建议"先自己写、再对照文档"——先不看代码，根据模块开头"目标与验收"独立实现，卡住 30 分钟再翻代码，理解差异后再重写一遍。遇到环境或网络问题先查 09 篇速查表。全部完成后对照 10 篇的毕业检查单逐项打勾，全部通过再进入 Level2——**Level1 的坑不填平，Level2 会加倍偿还**。

> 🎯 **核心要点**：Level1 的唯一目标是**亲手打通每一条链路**：能连上数据库、能读写 Redis、能调通大模型、能做出 RAG 问答。代码可以简陋，理解必须到位——这是 Level2 一切工程化的地基。
