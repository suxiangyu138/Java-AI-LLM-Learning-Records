## 1. 毕业检查单：8 个 Demo 逐项验收

逐项打勾，任何一项不满足先补做再进 Level2——**Level1 欠的债，Level2 会连本带利还**：

| Demo | 验收项 | 完成 |
|---|---|---|
| 01 环境 | 命令行能编译运行 Java；IDEA 能启动 Maven 项目；镜像配置后依赖正常下载 | ☐ |
| 02 语法 | 订单统计器独立重写成功；能用 Stream 讲清过滤/分组/排序；能用一句话讲 HashMap 扩容 | ☐ |
| 03 Spring | 三个接口（GET/带参/JSON）跑通；能讲自动配置与依赖注入；热部署生效 | ☐ |
| 04 数据 | 建库建表成功；CRUD 四接口跑通；事务回滚验证成功；能讲连接池是什么 | ☐ |
| 05 缓存 | 旁路缓存读写验证（redis-cli 可见 key）；TTL 生效；能讲"先更新库再删缓存"的理由 | ☐ |
| 06 模型 | 手写 HttpClient 与 Spring AI 两种方式都跑通；流式接口逐字返回；能默写请求体结构 | ☐ |
| 07 RAG | 四步链路跑通；三个验证实验（正常/边界/对照）做完；能讲注入模板三要素 | ☐ |
| 08 闭环 | 上传→入库→问答全链路通；检索为空有处理；对话入库与问答缓存生效；参数调优做过一次并记录 | ☐ |

验收的客观标准是**"不看代码能重写"**：每个 Demo 的核心逻辑（不是全部代码）能独立重写一遍。重写时卡住的地方，就是理解有洞的地方——回对应模块补，而不是带着洞往前走。

## 2. 能跑 ≠ 能讲：五项口头验收

Level1 的隐性产出是"能讲"——面试与 Level2 学习都依赖表达能力。找同学（或对着录音）做五项口头验收，每项 2 分钟：**第一项**：讲清 Level1 全链路数据流（从上传文档到回答返回，中间经过哪些模块、每步做什么）；**第二项**：讲清 OpenAI 兼容协议（请求体结构、三个字段的含义、为什么用这个协议）；**第三项**：讲清 RAG 四步与每步解决的问题、RAG 的边界（检索不到会怎样）；**第四项**：讲清旁路缓存流程与"先更新库再删缓存"的并发理由；**第五项**：讲清一次你真实踩过的坑（现象 → 排查 → 根因 → 解决，用 09 篇的叙事结构）。

五项全过说明"能跑且能讲"；任何一项讲不顺，回对应模块重读重练。**这五项口头验收就是 Level2 面试训练的第一课**——它们的内容会以更深的形态在 Level2 项目的面试深挖里再次出现。

## 3. Demo 代码的整理规范

Level1 结束时花半天整理代码，为 Level2 复用做准备。整理三件事：**项目合并**——8 个 Demo 里 03-08 是同一个工程演进出来的（03 建工程 → 04 加数据 → 05 加缓存 → 06 加 AI → 07 加 RAG → 08 闭环），最终保留一个 `demo-kb` 工程（即 08 的完整版），其余中间态删除或归档——**工程演进史写进 README**（每个阶段加了什么、为什么），这是面试讲"演进式开发"的素材；**README 补齐**——每个工程一个 README：一句话定位、启动步骤（含 MySQL/Redis/Ollama 前置）、核心接口清单、调优记录、踩坑记录；**环境配置文档化**——把 Key 怎么配、模型名是什么、端口约定写清楚，Level2 换机器或换团队时这份文档就是救命稻草。

整理规范的意义：**代码是写给未来的自己看的**。Level2 要在 08 工程的基础上做工程化改造，一个结构清晰、文档齐全的 Level1 工程，改造成本是整理过的三分之一。

## 4. 常见"假毕业"信号

以下状态出现任何一条，说明还没真正毕业，不要急着进 Level2：**"代码能跑但讲不清"**——全部照抄教程或 AI 生成，没有自己的理解，口头验收过不了；**"每个 Demo 都跑通过但没重写过"**——跑通依赖教程，重写才能暴露理解空洞；**"跳过 06 手写版直接用了框架"**——协议层不懂，Level2 遇到框架不支持的场景就抓瞎；**"08 闭环是抄的没有自己调过参"**——没有调优过程就没有"效果可度量"的方法论；**"踩过的坑一个都讲不出来"**——09 篇的手册是别人的，你自己的坑才是你的经验。

**"假毕业"的本质是"会跑不会造"**——跑通是复制，重写是理解，讲解是内化。三层都做到，才是真毕业。

## 5. Level2 预告：工程化完整项目（简历核心）

Level1 毕业后的下一站：Level2 工程化完整项目。它的目标是把 08 的闭环升级为**可上简历的工程化项目**，在四个方向做深度扩展：**工程规范**——分层架构（controller/service/mapper 规范化）、统一响应体与异常处理、参数校验、日志规范；**可靠性**——向量数据库（Milvus）替代内存存储、异步处理（MQ）、缓存一致性方案升级（延迟双删/消息重试）、降级与限流；**可观测与部署**——单元测试与接口测试、Docker Compose 一键部署、链路追踪与监控；**AI 深度**——RAG 评估体系（测试集 + 指标）、Agent 与工具调用、流式完整实现。Level2 产出的项目将同时具备"能演示、能压测、能深挖"三个面试硬指标，是简历的核心资产。

进 Level2 前的最后建议：**把 Level1 的 8 个 Demo 与「双栈联合实战」体系的 08 篇对照看一遍**——双栈项目的 Python 侧做的是同一件事（AI 问答闭环），两边对照能同时加深对两端架构的理解。

## 6. Level1 复习路线图

进入 Level2 后 Level1 会被覆盖，但面试前需要快速复习时，按此路线回看：**一天版**——重读 00 总览 + 08 闭环代码 + 口头验收五项；**三天版**——一天过数据链路（03-05 的代码与要点），一天过 AI 链路（06-07 的协议与 RAG），一天过 09 手册与踩坑记录；**面试冲刺版**——只看 06 的协议三字段、07 的 RAG 四步、08 的数据流图与调优记录，加 10 篇的检查单自查。复习时优先看自己写的代码与踩坑记录——**那才是 Level1 真正留下的资产**。

## 7. 核心要点

1. 毕业检查单 8 项逐项过，客观标准是"不看代码能重写"。
2. 五项口头验收（链路/协议/RAG/缓存/踩坑）是"能跑 vs 能讲"的分水岭。
3. 代码整理三件事：合并成单一工程、README 补齐、环境配置文档化。
4. "假毕业"四信号：讲不清、没重写、跳过手写版、没调优——会跑不会造不算毕业。
5. Level2 在四方向升级：工程规范、可靠性、可观测部署、AI 深度。

> 🎯 **核心要点**：Level1 的毕业标准一句话：**"能跑、能重写、能讲清、有踩坑记录"**。四条全过，技术底座就位，Level2 的工程化改造是顺水推舟；缺任何一条，Level2 会以放大的形式让你补课。毕业检查单不是形式，是 Level2 成功率的预测器。
