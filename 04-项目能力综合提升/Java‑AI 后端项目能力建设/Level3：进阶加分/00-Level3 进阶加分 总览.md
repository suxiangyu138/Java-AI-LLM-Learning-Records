## 3. 学习路线推荐

**标准路径（4-6 周，每天 2-3 小时）**：01-02 各 3-4 天，压测找瓶颈并做优化专项，每个优化必须有「前后对比」数据；03-08 是微服务化主体，每个 3-4 天，按「拆分 → Nacos → Feign → Sentinel → Seata → 链路」顺序推进，每步完成后跑一遍全链路验证；09 用 4-5 天做 K8s 部署迁移（在 minikube/k3s 上）；10 用 3 天收口：分布式经典问题 + 题库演练 + 验收。

**加速路径（已懂微服务，2-3 周）**：01-02 只做压测与「三个最有说服力的优化」；03-05 快速过（重点是版本矩阵与改造顺序）；06-08 做关键验证实验；09 只部署核心服务到 K8s；10 全部过。

**查漏路径（面试缺分布式深度，1 周）**：只读 03 的拆分决策与版本矩阵、06 的 Sentinel 核心、07 的 AT 原理、10 的经典问题与题库，其余回仓库对应体系（Nacos/Seata/Sentinel/Spring Cloud 各体系）补原理。

**节奏建议**：Level3 的每个模块都以「改造 + 前后对比」为单位——改造前先跑一次基线（压测/调用链），改造后再跑一次，数字差异就是学习产出与面试弹药；**没有对比数据的「优化」在 Level3 不算完成**。

| 概念 | 一句话速查 |

| 瓶颈四查 | 连接池 / 数据库 / MQ / AI 调用——压测结果先归因再优化 |

| 分布式事务 | Seata AT（强一致）vs MQ 消息（最终一致）——按场景选型 |

| 云原生 | K8s 部署替代 Compose：Deployment/Service/ConfigMap/Secret |

## 5. Level3 在能力建设中的定位

三级结构的逻辑是**递进收口**：Level1 打通链路、Level2 工程化沉淀简历核心项目、Level3 叠加「进阶加分」——高并发证明「性能思维」，微服务证明「分布式架构能力」，云原生证明「部署现代化」。Level3 的两个关键转变：**技术上，从「单机思维」到「分布思维」**——单体的缓存一致性（Level2 延迟双删）在分布式下变成服务间一致性问题；单体的 traceId 在分布式下变成跨服务传递问题；单体的事务在分布式下变成 Seata 问题——**同一个问题在分布式的放大形态，正是面试深挖的富矿**；**产出上，从「简历核心项目」到「进阶亮点」**——简历项目模块的「高并发优化 40% 吞吐提升」「微服务化改造」「K8s 部署」三条亮点，全部来自本层。

与仓库其他体系的关系：本层是「Spring Cloud Alibaba 全家桶」（Nacos/Seata/Sentinel）、「Spring Cloud 微服务全家桶」（OpenFeign/LoadBalancer/Gateway）、「Docker 与 Kubernetes 衔接」「虚拟线程」「日志监控指标」等体系的**综合落地层**——那些体系讲原理，本层讲「在进阶项目里怎么用」；与「双栈联合实战」「实战项目综合落地」的分工：本层把 Level2 的单体项目升级为分布式项目，这是双栈项目 Java 侧的最终形态，实战清单里的「SpringCloud 必做项目」「SpringCloudAlibaba 必做项目」在本层直接覆盖。

与 Level2 的递进关系同样要讲清：**本层的每个组件都是 Level2 已有方案的升级而非另起炉灶**——Sentinel 是 Level2 06 篇 Resilience4j 的分布式升级（同一个「限流降级」心智换组件），traceId 跨服务传递是 Level2 08 篇拦截器的延伸（同一个「链路」心智加传递），K8s 是 Level2 09 篇 Compose 的演进（同一个「部署」心智换平台）。面试被问「为什么单体时不用这些」，答案正是这条递进线：**单体用不到，分布式才需要——组件的引入由架构形态决定，不是技术堆砌**。

## 6. 进阶全景与推进节奏

| 阶段 | 模块 | 验收标志 |
|---|---|---|
| 性能阶段 | 01-02 | 压测基线文档更新，至少三个优化有前后对比数据 |
| 拆分阶段 | 03 | 服务划分完成、SCA 版本矩阵就位、改造顺序执行完 |
| 治理阶段 | 04-07 | Nacos 注册配置生效、Feign 调用通、Sentinel 规则生效、Seata/MQ 二选一落地 |
| 追踪阶段 | 08 | 一次跨服务请求 traceId 串联全链路日志 |
| 云原生阶段 | 09 | K8s 上核心服务可部署、Compose 迁移路径文档化 |
| 收口阶段 | 10 | 分布式题库过一遍、验收检查单全过、后续路线明确 |

每个阶段结束对照验收标志自检，不达标不进入下一个——**Level3 的每层都是下一层的压舱石**，与 Level2 同一纪律。

## 7. 使用建议

每个模块的结构一致：**动机（为什么要进阶）→ 方案（怎么做）→ 代码/清单 → 验证（前后对比）→ 坑**。学习时先读动机与方案，动手前先写「改什么、为什么、怎么验证」，再对照实现。Level3 最大的坑是「只加组件不加验证」——引入 Nacos 不算完成，**「配置变更后 1 秒生效」的演示 + 注册列表截图**才算；引入 Sentinel 不算完成，**「压测触发限流 + 规则持久化重启不丢」**才算。全部完成后对照 10 篇验收检查单，再衔接「双栈联合实战」或「实战项目综合落地」的后续路线。

> 🎯 **核心要点**：Level3 的验收标准一句话：**「每个进阶都有对比数据，每个组件都能讲透原理」**——压测优化有前后对比、微服务改造有完整链路、分布式事务能讲清为什么选它。Level3 不产出新项目，它把 Level2 的项目升级成**「分布式生产级」**，把简历的「进阶亮点」变成可深挖的事实。
