## 1. 分布式经典问题：四问四答

微服务化引入的四个经典问题，每个都能在本项目里找到落地场景——「原理 + 落地」的答题结构是面试分水岭：

**CAP 与取舍**——分布式系统的三难：一致性（C）、可用性（A）、分区容错（P）——网络分区（P）必然存在，所以实际是「CP 还是 AP」的取舍。本项目两处答案（承 04 篇）：Nacos 注册发现选 AP（可错不可停）、配置选 CP（不能分叉）；Seata 的强一致（C 优先）与 MQ 最终一致（A 优先）在不同场景共存。答题要点：**「不是三选二，是分区时必须二选一」**——先讲清 P 是前提，再讲本项目两处取舍。

**幂等**——分布式下「重试是常态」（网络超时重试、MQ 重投、用户重复点击），幂等是「重试不产生副作用」的能力。本项目三处落地：状态表幂等（Level2 05 篇解析任务按 docId 判重）、数据库唯一键（用户表、任务表）、Redis 防重键（上传防重复提交）。答题要点：**「幂等键 + 唯一约束 + 结果检查」三层**，并讲清「为什么 MQ 必须幂等」（at-least-once 语义）。

**分布式锁**——跨服务互斥：多个实例同时操作同一资源（如两实例同时执行定时任务、扣减同一库存）。答案：Redis 分布式锁（SETNX + 过期时间 + 看门狗续期——Redisson 的成熟实现）。本项目场景：解析任务的多实例互斥（保证同一文档不同时被两个实例解析——状态机其实已兜底，锁是双保险）。答题要点：**「SETNX 抢锁 + 过期防死锁 + Lua 释放」三步**，进阶讲「看门狗续期与 Redlock 的争议」。

**分布式 ID**——数据库自增 ID 在分库分表/多实例下会冲突。答案：雪花算法（时间戳 + 机器号 + 序列号）——本项目的 ID 生成在 Level2 已是雪花（仓库有完整体系），微服务化后各服务独立生成不冲突。答题要点：**「雪花三部分组成 + 时钟回拨问题」**（时钟回拨是雪花的第一坑，解决方案：等待/备用机器号/新算法）。

## 2. 进阶面试题库：精选与答题范式

按 Level3 六块能力整理高频题（答案在 01-09 篇）：**性能**——「压测怎么做？瓶颈怎么定位？」「虚拟线程原理与适用场景？」「多级缓存一致性怎么保证？」；**微服务**——「为什么拆服务？拆的依据？」「数据库为什么不能跨服务共享？」「注册中心挂了会怎样？」「Nacos 为什么注册 AP 配置 CP？」；**服务调用**——「Feign 的原理？超时怎么配？」「服务间调用超时重试怎么设计？」「雪崩怎么传播？怎么防？」；**治理**——「Sentinel 与 Resilience4j 怎么选？」「热点参数限流怎么实现？」「规则持久化怎么做的？」；**一致性**——「Seata 三组件是什么？」「AT 模式原理？代价？」「什么时候用 MQ 最终一致？」；**云原生**——「Compose 与 K8s 怎么选？」「Deployment 怎么实现滚动更新？」「K8s 与 Nacos 的分工？」

答题范式（三级递进）：**结论**——「我用 Nacos，注册 AP 配置 CP」；**原理**——「AP 是可用性优先，注册列表允许短暂不一致，保证注册中心故障时服务可用」；**落地**——「本项目 4 个服务注册，实例下线 30 秒摘除，Feign 自动不路由」。**每道题都要求能用「结论 + 原理 + 落地」结构讲 2 分钟**——对着录音练，卡壳的地方回对应篇目补。进阶题库的价值：**它不是背题，是把你做过的每个决策变成可表达的论证**——「为什么」的答案在每一篇的「动机」里。

## 3. 项目验收检查单

Level3 收官的验收清单，逐项打勾：**性能**——perf.md 有完整基线 + 至少三个优化前后对比（多级缓存/虚拟线程/调参）；**微服务**——三个服务 + 网关独立部署、Nacos 注册列表正确、kb-ai 重启不影响 kb-doc；**治理**——Sentinel 限流/熔断/降级可演示、规则持久化生效；**一致性**——Seata AT 场景回滚验证过、MQ 最终一致链路完整、四问（CAP/幂等/分布式锁/ID）能答；**可观测**——traceId 跨服务可捞、瀑布图可见、故障剧本三步定位跑通；**云原生**——K8s 全栈迁移完成、自愈/滚动更新/HPA 三演示数据在手。另加三个「硬伤自检」：**没造轮子**——组件全用 SCA 全家桶与官方方案，自研组件讲不出原理就要被质疑；**数据不编**——压测/对比数据全部来自真实实验；**能讲边界**——「多级缓存一致性有窗口」「AT 有全局锁」「拆分带来延迟微升」——**知道每个方案的代价，才证明不是背的**。

## 4. 三级能力建设总验收

整个「Java‑AI 后端项目能力建设」三级金字塔的终验，三个 Level 的产出串成一条完整的故事线：**Level1**——8 个 Demo 打通全链路（能跑）；**Level2**——工程化简历核心项目：规范、可靠性、测试、部署、AI 深度（能演示、能压测、能深挖）；**Level3**——进阶加分：高并发优化、微服务化、云原生（能讲分布式）。总验收标准：**「从环境搭建到 K8s 部署的全链路，每个环节都能讲清『为什么这么做 + 验证数据』」**——按此自查：环境（Level1 01）→ 语法 → Web → 数据 → 缓存 → LLM → RAG → 闭环 → 工程规范 → 可靠性 → 测试 → 可观测 → 部署 → 高并发 → 微服务 → 分布式 → 云原生——这条 17 步的链路就是你的技术简历骨架。**「项目是长在数据上的」**（Level2 10 篇的结论）在这里升维为「**能力是长在项目上的**」——每一层的数据（跑通、压测、对比）都是下一层深挖的证据。

## 5. 后续路线：双栈联合与实战落地

Level3 毕业后，两条主线并行：**「双栈联合实战」**——本项目的 Java 侧（微服务化的知识问答）与「Python‑LLM 应用开发项目能力建设」的 Python 侧（FastAPI + LangChain RAG/Agent）拼成完整双栈项目：Java 侧做业务底座（用户/文档/知识库管理 + 微服务治理），Python 侧做 AI 深度（Agent 编排、评估），中间用 OpenAI 兼容协议对接——**双栈项目的架构题（为什么两端、怎么通信、数据怎么流）是本目录能力建设的最终面试形态**；**「实战项目综合落地」**——实战清单里的「SpringCloud 必做项目」「SpringCloudAlibaba 必做项目」已被本层覆盖，剩余项目（ES 搜索、微调、部署等）按清单推进，补全技术矩阵。复盘建议：**写一份「能力建设复盘」**——17 步链路里每一步的技术点、验证数据、踩坑记录汇总成一页纸，这是秋招简历项目模块与面试自我介绍的总底稿。

## 6. 核心要点

1. 四问四答：CAP（P 是前提，本项目两处取舍）、幂等（三层 + at-least-once）、分布式锁（SETNX 三步）、分布式 ID（雪花 + 时钟回拨）。
2. 答题范式三级递进：结论 → 原理 → 落地（本项目数据），每题能讲 2 分钟。
3. 验收检查单：性能/微服务/治理/一致性/可观测/云原生六项 + 三硬伤自检（不造轮子、数据不编、能讲边界）。
4. 17 步链路终验：从环境搭建到 K8s，每步能讲「为什么 + 数据」——这就是技术简历骨架。
5. 后续双主线：双栈联合实战（Java + Python 拼合）与实战项目综合落地（补全技术矩阵）。
6. 写「能力建设复盘」一页纸，作为秋招简历与自我介绍的总底稿。

> 🎯 **核心要点**：Level3 的终局一句话：**「每个进阶都是可验证的事实，每个决策都能讲清取舍」**——三级金字塔至此收口：Level1 会跑、Level2 会做、Level3 会讲。当「压测数据、对比实验、方案边界」成为你讲项目的默认语言时，能力建设就毕业了——剩下的，是把这份资产写进简历，在面试里讲出来。
