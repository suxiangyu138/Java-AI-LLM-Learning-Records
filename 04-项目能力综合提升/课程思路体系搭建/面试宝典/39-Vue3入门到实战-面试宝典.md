## 一、基础概念速答

### 1.1 Vue3相比Vue2有哪些核心变化？
| 维度 | Vue2 | Vue3 |
|------|------|------|
| 响应式原理 | Object.defineProperty | Proxy |
| API风格 | Options API | Composition API + Options API |
| TypeScript支持 | 较差，需额外配置 | 原生支持 |
| 性能 | 中等 | 提升约1.3~2倍 |
| 打包体积 | 较大 | Tree-shaking优化，体积减少 |
| 新特性 | — | Teleport, Suspense, Fragment, 多个v-model |

### 1.2 什么是Composition API？与Options API有何区别？
> 💡 Composition API是通过导入的函数（ref、reactive、computed等）来组织组件逻辑的方式。

```vue
<script setup>
// Composition API 方式
import { ref, onMounted } from 'vue'
const count = ref(0)
onMounted(() => { console.log('mounted') })
</script>
```

**区别对比：**
| Options API | Composition API |
|---|---|
| 按选项类型拆分（data/methods/computed） | 按功能逻辑组织 |
| 代码分散，复用需mixin | 代码集中，复用通过Hooks |
| this访问数据 | 直接使用变量 |
| 逻辑复用困难（mixin命名冲突） | 逻辑复用灵活（自定义Hooks） |

### 1.3 ref和reactive的区别？
| 特性 | ref | reactive |
|------|-----|---------|
| 数据类型 | 基本类型 + 对象类型 | 仅对象类型 |
| 访问方式 | .value | 直接访问 |
| 响应式原理 | 基本类型靠getter/setter，对象类型靠Proxy | Proxy |
| 解构 | 不会丢失响应式 | toRefs转换 |
| 使用场景 | 基本类型、需要重新赋值的变量 | 对象/数组，不重新赋值 |

```javascript
const count = ref(0)
const state = reactive({ name: 'Vue3', version: 3 })
// ref自动解包：模板中无需.value
count.value++ // JS中需要.value
```

### 1.4 computed和watch的区别？
> 🎯 **computed**：依赖变化后自动重新计算，有缓存，用于派生状态。
> **watch**：监听数据变化执行副作用，无缓存，用于异步/复杂操作。

```vue
<script setup>
const count = ref(0)
// computed：有缓存，只有依赖变化才重新计算
const double = computed(() => count.value * 2)
// watch：监听变化，执行副作用
watch(count, (newVal, oldVal) => {
  console.log(`count从${oldVal}变为${newVal}`)
})
// watchEffect：自动追踪依赖
watchEffect(() => {
  console.log(`count现在是${count.value}`)
})
</script>
```

### 1.5 watch的五种使用场景？
> ⚠️ watch可以监听ref、reactive、computed、getter函数和数组。

```javascript
// 1. 监听ref
watch(count, (n, o) => {})
// 2. 监听reactive对象（隐式开启deep）
watch(state, (n, o) => {})
// 3. 监听getter函数
watch(() => state.name, (n, o) => {})
// 4. 监听多个源（数组）
watch([count, () => state.name], ([c, n], [oc, on]) => {})
// 5. 深度监听
watch(() => state.obj, (n, o) => {}, { deep: true })
```

### 1.6 Vue3生命周期有哪些变化？
> 💡 Vue3生命周期在setup中使用时，前缀加"on"，且移除了beforeCreate和created（setup本身替代）。

| Vue2 | Vue3 |
|------|------|
| beforeCreate | setup() |
| created | setup() |
| beforeMount | onBeforeMount |
| mounted | onMounted |
| beforeUpdate | onBeforeUpdate |
| updated | onUpdated |
| beforeDestroy | onBeforeUnmount |
| destroyed | onUnmounted |
| activated | onActivated |
| deactivated | onDeactivated |

### 1.7 Teleport和Suspense的作用？
**Teleport**：将DOM渲染到指定位置（如body），常用于模态框、通知等。
```vue
<Teleport to="body">
  <div class="modal">模态框内容</div>
</Teleport>
```

**Suspense**：处理异步组件加载状态，提供fallback内容。
```vue
<Suspense>
  <template #default>
    <AsyncComponent />
  </template>
  <template #fallback>
    <div>加载中...</div>
  </template>
</Suspense>
```

### 1.8 Pinia与Vuex的区别？
| 特性 | Pinia | Vuex |
|------|-------|------|
| TypeScript | 原生支持 | 需要额外类型定义 |
| 代码体积 | 约1KB | 约9KB |
| 模块结构 | 无命名空间，每个store独立 | modules + namespaced |
| mutation | 无 | 有 |
| DevTools | 支持 | 支持 |
| API风格 | Composition API风格 | Options API风格 |

### 1.9 Vue3中v-model有哪些变化？
> 💡 Vue3支持多个v-model绑定，且去掉了.sync修饰符。

```vue
<!-- Vue2 -->
<Child v-model="title" />
<Child :value="title" @input="title = $event" />

<!-- Vue3 -->
<Child v-model="title" />
<Child v-model:title="title" v-model:content="content" />
```

### 1.10 Vue3的7种组件通信方式？
| 方式 | 场景 | 代码示例 |
|------|------|---------|
| props | 父传子 | `defineProps({})` |
| emit | 子传父 | `defineEmits(['click'])` |
| v-model | 双向绑定 | `v-model:title="val"` |
| attrs | 透传属性 | `useAttrs()` |
| ref/$parent | 直接访问 | `defineExpose({})` |
| provide/inject | 深层传递 | `provide/inject` |
| mitt | 跨组件事件 | `mitt.on/emit` |

### 1.11 shallowRef和shallowReactive的作用？
> ⚠️ 用于性能优化：只做浅层响应式，深层数据变化不触发更新。

```javascript
const shallow = shallowRef({ a: { b: 1 } })
// 修改深层属性不会触发响应
shallow.value.a.b = 2 // 不触发更新
shallow.value = { a: { b: 2 } } // 触发更新（替换整个值）
```

## 二、深度原理剖析

### 2.1 Vue3响应式原理（Proxy）是如何实现的？
> 🎯 Vue3使用Proxy代理对象，拦截get/set/deleteProperty等操作，实现依赖收集和触发更新。

```javascript
// 简化实现
function reactive(target) {
  return new Proxy(target, {
    get(target, key, receiver) {
      track(target, key) // 依赖收集
      return Reflect.get(target, key, receiver)
    },
    set(target, key, value, receiver) {
      const result = Reflect.set(target, key, value, receiver)
      trigger(target, key) // 触发更新
      return result
    }
  })
}
```

**Proxy vs Object.defineProperty：**
| Object.defineProperty | Proxy |
|---|---|
| 只能监听get/set | 可监听13种操作（deleteProperty、has等） |
| 需要递归遍历对象所有属性 | 惰性劫持，访问到才处理 |
| 无法响应新增/删除属性 | 原生支持新增/删除 |
| 数组需要特殊处理 | 原生支持数组索引和length变化 |

### 2.2 ref的实现原理？
> 💡 ref底层：基本类型用getter/setter包装成RefImpl对象，对象类型用reactive处理。

```javascript
function ref(value) {
  return new RefImpl(value)
}
class RefImpl {
  constructor(value) {
    this._value = isObject(value) ? reactive(value) : value
    this.__v_isRef = true
  }
  get value() {
    track(this, 'value') // 依赖收集
    return this._value
  }
  set value(newVal) {
    this._value = isObject(newVal) ? reactive(newVal) : newVal
    trigger(this, 'value') // 触发更新
  }
}
```

### 2.3 Vue3的Diff算法优化了什么？
> 🎯 Vue3在虚拟DOM Diff中做了多项优化：

1. **PatchFlag**：编译时标记动态节点，Diff时只对比标记内容
2. **静态提升**：静态节点提升到渲染函数外部，避免重复创建
3. **事件缓存**：缓存事件处理函数，避免每次重新创建
4. **Block Tree**：以block为单位的树结构，跳过静态节点比较

```vue
<!-- 模板 -->
<div>
  <span>静态文本</span>
  <span :class="dynamic">{{ dynamic }}</span>
</div>
<!-- 编译后 -->
_createVNode("div", null, [
  _createVNode("span", null, "静态文本"), // 静态提升
  _createVNode("span", { class: _ctx.dynamic }, _toDisplayString(_ctx.dynamic), 1 /* TEXT */)
])
```

### 2.4 Vue3编译优化详解？
**PatchFlag类型：**
| Flag | 值 | 含义 |
|------|----|------|
| TEXT | 1 | 动态文本内容 |
| CLASS | 2 | 动态class |
| STYLE | 4 | 动态style |
| PROPS | 8 | 动态属性 |
| FULL_PROPS | 16 | 全量对比 |
| HYDRATE_EVENTS | 32 | 仅绑定事件 |

## 三、实战场景题

### 3.1 如何用Vue3实现一个防抖搜索组件？
```vue
<script setup lang="ts">
import { ref, watch } from 'vue'
const keyword = ref('')
const results = ref<string[]>([])
const loading = ref(false)

watch(keyword, (val) => {
  if (val.length < 2) return
  loading.value = true
  const timer = setTimeout(async () => {
    const res = await fetch(`/api/search?q=${val}`)
    results.value = await res.json()
    loading.value = false
  }, 300)
  // 利用watch的cleanup取消上一次请求
  onCleanup(() => clearTimeout(timer))
})
</script>
```

### 3.2 Vue3中如何实现权限管理（路由+按钮级）？
> 💡 常见方案：路由守卫 + 权限指令 + 动态路由添加。

```javascript
// 路由守卫
router.beforeEach((to, from, next) => {
  const token = localStorage.getItem('token')
  if (to.meta.requiresAuth && !token) {
    next('/login')
  } else {
    next()
  }
})
// 动态添加路由
const permissionRoutes = filterRoutes(asyncRoutes, userPermissions)
permissionRoutes.forEach(route => router.addRoute(route))
// 权限指令
const vPermission = {
  mounted(el, binding) {
    if (!userPermissions.includes(binding.value)) {
      el.parentNode?.removeChild(el)
    }
  }
}
```

## 四、手写代码题

### 4.1 实现自定义Hooks：useCounter
```typescript
export function useCounter(initial = 0) {
  const count = ref(initial)
  const increment = () => count.value++
  const decrement = () => count.value--
  const reset = () => count.value = initial
  return { count, increment, decrement, reset }
}
```

### 4.2 实现自定义ref（customRef）
```typescript
function useDebouncedRef(value: string, delay = 300) {
  return customRef((track, trigger) => {
    let timer: number
    return {
      get() {
        track() // 依赖收集
        return value
      },
      set(newVal) {
        clearTimeout(timer)
        timer = setTimeout(() => {
          value = newVal
          trigger() // 触发更新
        }, delay)
      }
    }
  })
}
```

### 4.3 实现Pinia的简易版本
```typescript
function defineStore(id: string, options: any) {
  const store = reactive(options.state ? options.state() : {})
  const actions = options.actions || {}
  const getters = options.getters || {}
  
  const composedStore = {
    ...toRefs(store),
    ...actions,
    ...Object.keys(getters).reduce((acc, key) => {
      acc[key] = computed(() => getters[key].call(composedStore))
      return acc
    }, {} as Record<string, any>)
  }
  return () => composedStore
}
```

## 六、常见坑点与最佳实践

| 坑点 | 问题描述 | 解决方案 |
|------|---------|---------|
| reactive重新赋值丢失响应 | `state = newObj` | 用ref或Object.assign |
| ref在模板中忘记.value | 模板自动解包，JS中需要 | 模板无需.value，JS中必须 |
| watch监听reactive不触发 | 默认deep无法获取oldValue | 使用getter函数形式 |
| defineProps解构丢失响应 | 解构后变成普通变量 | 用`toRefs(props)` |
| Teleport被禁用样式 | CSS隔离导致样式丢失 | 全局样式或:deep()穿透 |
| emit事件名大小写 | 父组件监听同名事件 | 统一使用kebab-case |

### 典型Bug案例分析
```javascript
// ❌ 错误：reactive重新赋值
let state = reactive({ count: 0 })
state = { count: 1 } // 失去响应式

// ✅ 正确做法
const state = reactive({ count: 0 })
Object.assign(state, { count: 1 })

// ❌ 错误：watch监听reactive拿不到oldValue
const state = reactive({ count: 0 })
watch(state, (newVal, oldVal) => {
  console.log(oldVal) // 和newVal相同！
})
// ✅ 正确：使用getter函数
watch(() => ({ ...state }), (newVal, oldVal) => {
  console.log(oldVal, newVal) // ✅
}, { deep: true })
```

## 七、面试回答模板

### Q1: 为什么Vue3要用Proxy替代defineProperty？
> Vue2使用Object.defineProperty有以下缺陷：无法监听数组变化（需要hack）、无法监听新增/删除属性、初始化时需要递归遍历所有属性（性能开销大）。Vue3使用Proxy代理整个对象，可以拦截所有操作（get/set/delete/ has等），且是惰性劫持（访问到才处理），性能更好，对数组支持更完整。

### Q2: Composition API相比Options API好在哪？
> 核心优势是逻辑组织更灵活。在Options API中，一个功能的逻辑分散在data/methods/computed/lifecycle多个选项中，组件大了很难维护。Composition API允许按功能组织代码（如把所有用户相关逻辑放在一个单独的函数中），通过自定义Hooks实现真正的逻辑复用。同时，Composition API在TypeScript类型推导方面更好。

### Q3: ref和reactive该选哪个？
> 推荐优先使用ref。因为ref支持所有数据类型，在JS中通过.value访问语义清晰，解构不会丢失响应式。reactive只支持对象类型，解构后需要用toRefs转换，重新赋值会丢失响应式。ref的响应式原理对基本类型用getter/setter，对象类型自动用reactive包装。

### Q4: Vue3中watch和watchEffect的区别？
> watch：惰性执行，需要指定监听源，可以获取新值和旧值，支持配置immediate/deep/flush。watchEffect：自动追踪函数内的响应式依赖，立即执行，拿不到旧值。选择建议：需要旧值时用watch，只需要响应执行副作用时用watchEffect。

### Q5: Pinia和Vuex你应该选哪个？
> 新项目建议直接用Pinia。Pinia体积更小（约1KB），TypeScript支持更好，Composition API风格与现代Vue3更契合，去掉了mutation简化了状态管理流程。Vuex主要用于维护老项目，或团队对mutation严格约束有强烈需求的场景。
