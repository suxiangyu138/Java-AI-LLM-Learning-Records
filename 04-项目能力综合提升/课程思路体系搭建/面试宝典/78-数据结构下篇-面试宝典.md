## 一、基础概念速答（15-20题）

### 1. B树是什么？有什么特性？
B树（B-Tree）是一种**平衡的多路搜索树**，用于磁盘等大容量存储设备的索引结构。每个节点可以包含多个关键字和多个子节点。

| 特性 | 说明 |
|------|------|
| 阶数m | 每个节点最多有m个子节点，m-1个关键字 |
| 根节点 | 至少2个子树（除非是叶子），至少1个关键字 |
| 内部节点 | 至少有 ceil(m/2) - 1 个关键字，最多 m-1 个 |
| 叶子节点 | 所有叶子在同一层（绝对平衡） |
| 关键字有序 | 节点内关键字升序排列 |

> 💡 B树的关键优势：**减少磁盘I/O次数**。每个节点可以存储多个关键字，树的高度远低于BST，查找次数等于树的高度。

### 2. B树与B+树的区别？
| 维度 | B树 | B+树 |
|------|-----|------|
| 数据存储 | 所有节点都存数据 | 仅叶子节点存数据 |
| 叶子节点 | 无链表连接 | 形成有序链表，支持范围查询 |
| 内部节点 | 存key+data | 仅存key，不存data |
| 范围查询 | 需要中序遍历 | 叶子链表直接遍历，效率高 |
| MySQL索引 | 不使用 | 使用（InnoDB） |

### 3. 什么是哈希表？哈希冲突如何处理？
哈希表（Hash Table）通过**哈希函数**将关键字映射到数组下标，实现O(1)平均查找时间。

**哈希冲突处理方式：**

| 方法 | 原理 | 优缺点 |
|------|------|--------|
| 链地址法 | 数组每个元素是一个链表/红黑树 | JDK HashMap采用，简单高效 |
| 开放地址法 | 冲突后找下一个空位（线性探测、二次探测、再哈希） | 删除复杂，容易产生聚集 |
| 再哈希法 | 准备多个哈希函数，冲突则换一个 | 计算开销大 |

> 💡 JDK 8 HashMap采用**链地址法**，当链表长度 >= 8 且数组长度 >= 64 时，链表转为红黑树（TREEIFY_THRESHOLD），优化最差情况性能。

### 4. 八大排序算法中哪些是稳定的？哪些是不稳定的？
| 排序算法 | 稳定性 | 平均时间复杂度 | 最坏时间复杂度 | 空间复杂度 |
|----------|--------|---------------|---------------|-----------|
| 冒泡排序 | 稳定 | O(n²) | O(n²) | O(1) |
| 选择排序 | 不稳定 | O(n²) | O(n²) | O(1) |
| 插入排序 | 稳定 | O(n²) | O(n²) | O(1) |
| 希尔排序 | 不稳定 | O(n^1.3) | O(n²) | O(1) |
| 归并排序 | 稳定 | O(n log n) | O(n log n) | O(n) |
| 快速排序 | 不稳定 | O(n log n) | O(n²) | O(log n) |
| 堆排序 | 不稳定 | O(n log n) | O(n log n) | O(1) |
| 计数排序 | 稳定 | O(n + k) | O(n + k) | O(k) |
| 桶排序 | 稳定 | O(n + k) | O(n²) | O(n) |
| 基数排序 | 稳定 | O(d(n + k)) | O(d(n + k)) | O(n + k) |

> 💡 **稳定排序**：冒泡、插入、归并、计数、桶、基数。**不稳定**：选择、希尔、快排、堆排。

### 5. 图的DFS和BFS分别是什么？适用场景？

| 算法 | 数据结构 | 核心思想 | 适用场景 |
|------|----------|----------|----------|
| DFS | 栈（递归） | 一条路走到黑，回溯再走 | 连通分量、拓扑排序、环检测、路径搜索 |
| BFS | 队列 | 逐层扩散，第一次到达即最短 | 最短路径（无权图）、层序遍历、二分图检测 |

```java
// DFS
void dfs(Graph graph, int v, boolean[] visited) {
    visited[v] = true;
    for (int w : graph.adj(v)) {
        if (!visited[w]) dfs(graph, w, visited);
    }
}

// BFS
void bfs(Graph graph, int s) {
    boolean[] visited = new boolean[graph.V()];
    Queue<Integer> q = new LinkedList<>();
    visited[s] = true;
    q.offer(s);
    while (!q.isEmpty()) {
        int v = q.poll();
        for (int w : graph.adj(v)) {
            if (!visited[w]) {
                visited[w] = true;
                q.offer(w);
            }
        }
    }
}
```

### 6. 什么是拓扑排序？应用场景？
**拓扑排序**是对有向无环图（DAG）所有顶点的一种线性排序，使得对每条边(u,v)，u在排序中出现在v之前。

**应用场景**：任务调度、课程安排（先修课依赖）、编译依赖、包管理器依赖解析。

**两种实现方法：**

| 方法 | 思路 |
|------|------|
| Kahn算法（BFS） | 不断删除入度为0的顶点，记录删除顺序 |
| DFS后序 | DFS遍历，将顶点按完成时间逆序排列 |

> 💡 **检测环**：如果Kahn算法结束后，已排序顶点数 < 总顶点数，说明图中存在环。

### 7. 最短路径的三种经典算法对比？

| 算法 | 适用场景 | 时间复杂度 | 能否处理负权边 | 能否检测负环 |
|------|----------|-----------|---------------|-------------|
| Dijkstra | 单源，非负权 | O((V+E) log V) 堆优化 | 否 | 否 |
| Bellman-Ford | 单源，允许负权 | O(VE) | 是 | 是 |
| Floyd-Warshall | 全源，允许负权 | O(V³) | 是 | 是 |

> 💡 **面试重点**：Dijkstra基于贪心思想，用优先队列优化；Bellman-Ford基于动态规划思想，松弛V-1轮；Floyd-Warshall基于DP，dp[k][i][j]表示允许经过前k个节点时的最短路径。

### 8. Prim和Kruskal算法对比？

| 维度 | Prim | Kruskal |
|------|------|---------|
| 核心思想 | 从顶点出发，每次选最短边连接未访问顶点 | 从边出发，每次选最短且不形成环的边 |
| 数据结构 | 优先队列 + visited数组 | 并查集（Union-Find） |
| 时间复杂度 | O(E log V) | O(E log E) |
| 适用场景 | 稠密图 | 稀疏图 |

### 9. 并查集（Union-Find）的作用？如何优化？
并查集用于解决**动态连通性**问题，支持两个操作：`find(x)` 查找x的根，`union(x,y)` 合并x和y所在集合。

**两种优化：**

1. **路径压缩（Path Compression）**：`find` 时，将路径上所有节点直接指向根节点，时间复杂度接近O(1)。

2. **按秩合并（Union by Rank）**：将高度较低的树合并到高度较高的树上，避免树退化为链表。

```java
class UnionFind {
    private int[] parent;
    private int[] rank;

    public UnionFind(int n) {
        parent = new int[n];
        rank = new int[n];
        for (int i = 0; i < n; i++) parent[i] = i;
    }

    public int find(int x) {
        if (parent[x] != x)
            parent[x] = find(parent[x]); // 路径压缩
        return parent[x];
    }

    public void union(int x, int y) {
        int rootX = find(x), rootY = find(y);
        if (rootX == rootY) return;
        if (rank[rootX] < rank[rootY]) {
            parent[rootX] = rootY;
        } else if (rank[rootX] > rank[rootY]) {
            parent[rootY] = rootX;
        } else {
            parent[rootY] = rootX;
            rank[rootX]++;
        }
    }
}
```

> 🎯 同时使用路径压缩和按秩合并，时间复杂度为反阿克曼函数 O(α(n))，近乎常数时间。

### 10. 贪心算法的核心思想？适用条件？
贪心算法通过**每一步都选择当前最优解**来期望得到全局最优解。适用条件：

| 条件 | 含义 |
|------|------|
| 最优子结构 | 问题的最优解包含子问题的最优解 |
| 贪心选择性质 | 局部最优选择可以导出全局最优解 |

> ⚠️ 贪心不是万能的！零钱兑换（某些面额组合）不能用贪心，必须用DP。0-1背包也不能用贪心，但**分数背包**可以用贪心。

### 11. 动态规划（DP）的核心思想？
DP通过**将原问题拆解为子问题**，**保存子问题结果避免重复计算**来求解最优化问题。

**DP三要素：**

| 要素 | 说明 |
|------|------|
| 状态定义 | dp[i][j] 表示什么含义 |
| 状态转移方程 | 如何从子问题推导出当前问题 |
| 初始条件/边界 | base case 是什么 |

**DP vs 回溯 vs 贪心：**

| 算法 | 特点 | 适用场景 |
|------|------|----------|
| 回溯 | 穷举所有可能，暴力搜索 | 组合、排列、子集问题 |
| 贪心 | 每一步选最优，无后悔药 | 有贪心选择性质的问题 |
| DP | 记录子问题最优解，递推求解 | 重叠子问题 + 最优子结构 |

### 12. 回溯算法的核心模板？
```java
void backtrack(路径, 选择列表) {
    if (满足结束条件) {
        记录结果;
        return;
    }
    for (选择 : 选择列表) {
        做选择;
        backtrack(路径, 选择列表);
        撤销选择;
    }
}
```

### 13. 0-1背包和完全背包的区别？

| 维度 | 0-1背包 | 完全背包 |
|------|---------|---------|
| 物品数量 | 每种物品**只有1个** | 每种物品**无限个** |
| 遍历顺序 | 外层物品，内层**逆序**容量 | 外层物品，内层**正序**容量 |
| 状态转移 | dp[j] = max(dp[j], dp[j-w] + v) | dp[j] = max(dp[j], dp[j-w] + v) |

> 💡 区别的关键：逆序遍历保证每个物品只用一次，正序遍历允许重复使用。

### 14. 最长公共子序列（LCS）和最长公共子串的区别？

| 维度 | 最长公共子序列 (LCS) | 最长公共子串 |
|------|---------------------|-------------|
| 连续性要求 | 不要求连续 | 必须连续 |
| 状态定义 | dp[i][j] = s1[0..i-1]和s2[0..j-1]的LCS长度 | dp[i][j] = 以s1[i-1]和s2[j-1]结尾的最长公共子串长度 |
| 转移方程 | 相等：dp[i-1][j-1]+1；不等：max(dp[i-1][j], dp[i][j-1]) | 相等：dp[i-1][j-1]+1；不等：0 |
| 结果位置 | dp[m][n] | 全局最大值 |

### 15. 什么是Catalan数？有哪些应用？
Catalan数：$C_0 = 1, C_{n+1} = \sum_{i=0}^{n} C_i \cdot C_{n-i}$，通项为 $\frac{1}{n+1} \binom{2n}{n}$。

**经典应用：**

| 问题 | Catalan数含义 |
|------|-------------|
| n个节点的BST数量 | 第n个Catalan数 |
| n对括号的合法组合数 | 第n个Catalan数 |
| n个元素出栈次序数 | 第n个Catalan数 |
| 凸n+2边形的三角剖分数 | 第n个Catalan数 |
| n×n网格不穿越对角线的路径数 | 第n个Catalan数 |

### 16. KMP算法的核心思想？
KMP通过**预处理模式串的LPS数组（最长公共前后缀）**，在匹配失败时利用已经匹配的信息跳过不必要的比较，时间复杂度O(n+m)。

```java
// 构建LPS数组
int[] buildLPS(String pattern) {
    int m = pattern.length();
    int[] lps = new int[m];
    int len = 0;
    int i = 1;
    while (i < m) {
        if (pattern.charAt(i) == pattern.charAt(len)) {
            len++;
            lps[i] = len;
            i++;
        } else {
            if (len != 0) {
                len = lps[len - 1];
            } else {
                lps[i] = 0;
                i++;
            }
        }
    }
    return lps;
}
```

### 17. 什么是LRU缓存？如何实现？
LRU（Least Recently Used）淘汰最近最少使用的数据。核心数据结构：**双向链表 + HashMap**。

```java
class LRUCache {
    class DLinkedNode {
        int key, value;
        DLinkedNode prev, next;
        DLinkedNode(int k, int v) { key = k; value = v; }
    }
    private Map<Integer, DLinkedNode> cache = new HashMap<>();
    private int size, capacity;
    private DLinkedNode head, tail;

    public LRUCache(int capacity) {
        this.capacity = capacity;
        head = new DLinkedNode(0, 0);
        tail = new DLinkedNode(0, 0);
        head.next = tail;
        tail.prev = head;
    }

    public int get(int key) {
        DLinkedNode node = cache.get(key);
        if (node == null) return -1;
        moveToHead(node);
        return node.value;
    }

    public void put(int key, int value) {
        DLinkedNode node = cache.get(key);
        if (node != null) {
            node.value = value;
            moveToHead(node);
        } else {
            DLinkedNode newNode = new DLinkedNode(key, value);
            cache.put(key, newNode);
            addToHead(newNode);
            if (++size > capacity) {
                DLinkedNode removed = removeTail();
                cache.remove(removed.key);
                size--;
            }
        }
    }
    // 辅助方法：addToHead, removeNode, moveToHead, removeTail
}
```

> 💡 双向链表保证O(1)的移动和删除操作，HashMap保证O(1)的查找。

### 18. 滑动窗口最大值（LeetCode 239）如何实现？
使用**单调双端队列（Deque）**，保持队列中元素单调递减。

```java
int[] maxSlidingWindow(int[] nums, int k) {
    if (nums == null || k <= 0) return new int[0];
    int n = nums.length;
    int[] res = new int[n - k + 1];
    Deque<Integer> deque = new ArrayDeque<>();
    int idx = 0;
    for (int i = 0; i < n; i++) {
        while (!deque.isEmpty() && deque.peekFirst() < i - k + 1)
            deque.pollFirst();
        while (!deque.isEmpty() && nums[deque.peekLast()] <= nums[i])
            deque.pollLast();
        deque.offerLast(i);
        if (i >= k - 1) res[idx++] = nums[deque.peekFirst()];
    }
    return res;
}
```

```java
// 快速幂 - 分治
long fastPow(long a, long n) {
    if (n == 0) return 1;
    long half = fastPow(a, n / 2);
    if (n % 2 == 0) return half * half;
    else return half * half * a;
}
```

## 二、深度原理剖析（10-15题）

### 1. B树的插入和删除过程是怎样的？
**插入过程：**
1. 先查找，找到插入位置的叶子节点
2. 如果节点关键字数 < m-1，直接插入
3. 如果节点关键字数 = m-1，触发**分裂（split）**：取中间关键字提升到父节点，左右分成两个节点

**删除过程：**
1. 如果关键字在内部节点，用前驱/后继替换删除
2. 如果删除后节点关键字数 < ceil(m/2)-1，尝试从兄弟节点**借（旋转）**
3. 兄弟不够借时，与兄弟**合并（merge）**，父节点关键字下降

> ⚠️ B树的删除是最复杂的操作，面试通常只问思路，不要求手写完整代码。

### 2. HashMap的底层实现原理？（必问）

**JDK 7 vs JDK 8 区别：**

| 维度 | JDK 7 | JDK 8 |
|------|-------|-------|
| 数据结构 | 数组 + 链表 | 数组 + 链表 + 红黑树 |
| 插入方式 | 头插法（死循环bug） | 尾插法 |
| 哈希计算 | 多次扰动 | 一次高低位异或 |
| 树化 | 无 | >= 8 且数组 >= 64 转红黑树 |
| 扩容时机 | 键值对 > 容量×负载因子 | 同左 |

**put过程：**
1. 计算hash：`(key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16)`
2. 计算索引：`(n - 1) & hash`
3. 如果该位置为空，直接插入
4. 如果该位置有元素，比较key是否相同，相同则覆盖
5. 否则判断是链表还是红黑树，插入到链表尾部或红黑树中
6. 如果链表长度 >= 8，尝试树化
7. 如果size > threshold，扩容

> 💡 HashMap**线程不安全**：JDK 7 扩容时头插法会产生循环链表（死循环），JDK 8 改为尾插法避免了死循环，但仍有数据丢失问题，并发场景请用ConcurrentHashMap。

### 3. 快排为什么是不稳定的？举例说明？
快排的不稳定性源于**分区（partition）操作**。当基准值选择后，大于基准的放右边、小于的放左边，相等元素的相对顺序无法保证。

```
例：数组 [5a, 3, 5b, 1, 4]  以5a为基准分区后
可能变成 [3, 1, 4, 5a, 5b]  或 [3, 1, 4, 5b, 5a]
5a和5b的相对顺序可能改变
```

### 4. 堆排序如何建堆？如何排序？
**建堆（Build Heap）**：从最后一个非叶子节点开始，自底向上下沉（sift down），时间复杂度O(n)。

**排序过程：**
1. 建大顶堆（升序）或小顶堆（降序）
2. 将堆顶元素（最大/最小）与末尾元素交换
3. 堆大小减1，对新的堆顶执行下沉操作
4. 重复直到堆为空

> 💡 堆排序为什么不稳定？在交换堆顶和末尾元素时，可能改变相等元素的相对顺序。

### 5. 归并排序的两种实现方式？自顶向下 vs 自底向上？

| 方式 | 思路 | 优点 | 缺点 |
|------|------|------|------|
| 自顶向下（递归） | 从中间切分，递归排序，再合并 | 实现简单直观 | 递归栈空间O(log n) |
| 自底向上（迭代） | 从长度为1的子数组开始，两两合并 | 无需递归，适用于链表 | 实现稍复杂 |

### 6. Dijkstra算法为什么不能处理负权边？
Dijkstra基于**贪心思想**：每次从优先队列中取距离最短的顶点，认为该顶点的最短路径已经确定，以后不会再更新。

但如果存在负权边，之前确定的最短路径可能因为负权边的出现变得更短，贪心失效。

```
例：
A --(2)--> B --(-3)--> C
A --(1)--> C
Dijkstra: A->C 距离1 (确定)
但实际上 A->B->C 距离 2+(-3) = -1，更短
```

### 7. Bellman-Ford算法的动态规划思想？
Bellman-Ford基于**动态规划**：dp[i][v]表示最多经过i条边到达v的最短距离。

**递推公式**：dp[i][v] = min(dp[i-1][v], min_{(u,v)∈E}(dp[i-1][u] + w(u,v)))

> 💡 对所有的边进行V-1轮松弛（relaxation）操作，最多V-1轮一定能找到最短路径（因为最短路径最多V-1条边）。第V轮如果还能松弛，说明存在负环。

### 8. Floyd-Warshall算法的动态规划思想？
Floyd-Warshall基于**区间DP**思想：dp[k][i][j]表示从i到j，**允许经过前k个节点**的最短路径长度。

**递推公式**：dp[k][i][j] = min(dp[k-1][i][j], dp[k-1][i][k] + dp[k-1][k][j])

**三维降二维**：由于第k层只依赖第k-1层，可以省略第一维。
```java
for (int k = 0; k < n; k++)
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            if (dist[i][k] + dist[k][j] < dist[i][j])
                dist[i][j] = dist[i][k] + dist[k][j];
```

### 9. 动态规划的降维优化（滚动数组）如何做？
**核心思想**：如果dp[i]只依赖dp[i-1]，就可以用一维数组替代二维数组。

**0-1背包降维**：
```java
// 二维
for (int i = 0; i < n; i++)
    for (int j = W; j >= w[i]; j--)
        dp[i][j] = Math.max(dp[i-1][j], dp[i-1][j-w[i]] + v[i]);

// 一维（逆序保证每个物品只用一次）
int[] dp = new int[W + 1];
for (int i = 0; i < n; i++)
    for (int j = W; j >= w[i]; j--)
        dp[j] = Math.max(dp[j], dp[j - w[i]] + v[i]);
```

> 💡 **完全背包**一维优化时，容量**正序遍历**（允许重复使用）：`for (int j = w[i]; j <= W; j++)`

### 10. 旅行商问题（TSP）的DP解法？
TSP（Traveling Salesman Problem）指从一个城市出发，访问所有城市恰好一次后回到起点，求最短路径。

**状态定义**：dp[mask][i] 表示当前访问过的城市集合为mask（状态压缩），当前在i城市的最短距离。

**转移方程**：dp[mask][i] = min_{j ∈ mask且j≠i}(dp[mask ^ (1<<i)][j] + dist[j][i])

> ⚠️ TSP是NP难问题，DP解法的时间复杂度O(n² × 2ⁿ)，n最大约20。

### 11. 为什么HashMap的容量总是2的幂？
因为**取模运算优化**：`hash % n` 等价于 `(n-1) & hash`，当且仅当n是2的幂时成立。

位运算比取模快得多（一次CPU指令 vs 除法指令）。此外，2的幂减1的二进制全是1，能充分散列hash值，减少碰撞。

### 12. 哈希算法的设计原则？MurmurHash是什么？
**设计原则：**
1. **确定性**：相同输入必有相同输出
2. **高效性**：计算速度快
3. **均匀性**：输出均匀分布，减少碰撞
4. **雪崩效应**：输入微小变化，输出剧烈变化

**MurmurHash**：目前最流行的**非加密型哈希算法**之一，比JDK String.hashCode的碰撞率低得多，广泛应用于Redis、Memcached、Cassandra等。

> 💡 Java的String.hashCode计算方式：`s[0]*31^(n-1) + s[1]*31^(n-2) + ... + s[n-1]`。选择31是因为它是一个奇质数，且 `31 * i = (i << 5) - i`，JVM对其有优化。

### 13. 什么是跳表（Skip List）？如何实现？
跳表是一种**多层链表**结构，通过在有序链表上建立"索引层"实现O(log n)查找。

**核心特点：**
- 替代平衡树的一种概率性数据结构
- 插入/删除/查找时间复杂度O(log n)
- 实现简单，不需要复杂的平衡旋转操作
- 空间复杂度O(n)

> 💡 Redis的有序集合（ZSet）底层就使用跳表实现。LeetCode 1206要求设计跳表。

### 14. 并查集在Kruskal算法中如何发挥作用？
Kruskal按权重从小到大遍历边，对于每条边(u,v)：
1. 用并查集查找u和v是否属于同一集合（即是否已连通）
2. 如果不是，合并u和v所在的集合，并将这条边加入最小生成树
3. 重复直到选出V-1条边

并查集在此**高效检测环**：如果u和v已经属于同一集合，加入这条边就会形成环，需要跳过。

### 15. 基数排序和桶排序的区别？

| 维度 | 桶排序 | 基数排序 |
|------|--------|----------|
| 排序依据 | 根据数值范围分桶，桶内再排序 | 按位（个位/十位/百位）逐轮排序 |
| 桶数量 | 通常较少，取决于数据分布 | 固定（10进制就10个桶） |
| 实现方式 | 分桶 + 任意排序 | 逐位分配 + 收集（稳定排序） |
| 适用场景 | 数据均匀分布 | 整数或固定长度字符串 |

### 1. 数据库索引为什么用B+树而不用B树或AVL树？(阿里/美团)
**B+树 vs AVL/BST：**

| 维度 | AVL/BST | B+树 |
|------|---------|------|
| 高度 | 高（2叉） | 矮（多叉） |
| 磁盘I/O | 每次读取一个节点一次I/O，次数多 | 每次读一页，I/O次数少 |
| 范围查询 | 中序遍历，随机I/O | 叶子链表顺序扫描，顺序I/O |

**B+树 vs B树：**

| 维度 | B树 | B+树 |
|------|-----|------|
| 内部节点 | 存key+data，占空间大 | 只存key，一页能存更多key |
| 树高 | 较高 | 更矮（同样数据量） |
| 范围查询 | 中序遍历，需要来回跳 | 叶子链表直接遍历，高效 |

> 🎯 **总结**：B+树用"空间换时间"，内部节点不存data所以更矮，加链表优化范围查询，完美匹配磁盘特性。

2. **实现简单**：跳表代码量约红黑树的一半，调优更容易
3. **锁粒度**：跳表容易做分段锁，并发友好
4. **概率平衡**：跳表通过随机层级实现平衡，不需要复杂的旋转操作
5. **内存**：跳表通过调整概率参数可以控制内存使用

```java
class ExpiringCache<K, V> {
    private ConcurrentHashMap<K, ValueWithExpiry<V>> map = new ConcurrentHashMap<>();
    private DelayQueue<ExpiryKey<K>> delayQueue = new DelayQueue<>();

    public V get(K key) {
        ValueWithExpiry<V> entry = map.get(key);
        return entry == null ? null : entry.value;
    }

    public void put(K key, V value, long ttlMs) {
        long expiry = System.currentTimeMillis() + ttlMs;
        map.put(key, new ValueWithExpiry<>(value, expiry));
        delayQueue.offer(new ExpiryKey<>(key, expiry));
    }
    // 后台线程轮询delayQueue，取出过期key并删除
}
```

### 1. 手写快速排序
```java
void quickSort(int[] arr, int left, int right) {
    if (left >= right) return;
    int pivot = partition(arr, left, right);
    quickSort(arr, left, pivot - 1);
    quickSort(arr, pivot + 1, right);
}

// 单边快排（Lomuto分区）
int partition(int[] arr, int left, int right) {
    int pivot = arr[right];  // 选最右为基准
    int i = left;            // i左边都是小于pivot的
    for (int j = left; j < right; j++) {
        if (arr[j] < pivot) {
            swap(arr, i, j);
            i++;
        }
    }
    swap(arr, i, right);
    return i;
}
```

> 💡 **面试优化**：随机选择基准值避免最坏情况；重复元素多时用三路快排（<pivot, =pivot, >pivot 三区）。

### 2. 手写归并排序
```java
void mergeSort(int[] arr, int left, int right) {
    if (left >= right) return;
    int mid = left + (right - left) / 2;
    mergeSort(arr, left, mid);
    mergeSort(arr, mid + 1, right);
    merge(arr, left, mid, right);
}

void merge(int[] arr, int left, int mid, int right) {
    int[] temp = new int[right - left + 1];
    int i = left, j = mid + 1, k = 0;
    while (i <= mid && j <= right)
        temp[k++] = arr[i] <= arr[j] ? arr[i++] : arr[j++];
    while (i <= mid) temp[k++] = arr[i++];
    while (j <= right) temp[k++] = arr[j++];
    System.arraycopy(temp, 0, arr, left, temp.length);
}
```

### 3. 手写堆排序
```java
void heapSort(int[] arr) {
    int n = arr.length;
    // 建堆（从最后一个非叶子节点开始下沉）
    for (int i = n / 2 - 1; i >= 0; i--)
        siftDown(arr, n, i);
    // 排序
    for (int i = n - 1; i > 0; i--) {
        swap(arr, 0, i);
        siftDown(arr, i, 0);
    }
}

void siftDown(int[] arr, int n, int i) {
    int largest = i;
    int left = 2 * i + 1, right = 2 * i + 2;
    if (left < n && arr[left] > arr[largest]) largest = left;
    if (right < n && arr[right] > arr[largest]) largest = right;
    if (largest != i) {
        swap(arr, i, largest);
        siftDown(arr, n, largest);
    }
}
```

### 4. 手写N皇后问题（LeetCode 51）

```java
List<List<String>> solveNQueens(int n) {
    List<List<String>> res = new ArrayList<>();
    char[][] board = new char[n][n];
    for (char[] row : board) Arrays.fill(row, '.');
    backtrack(res, board, 0, new boolean[n], new boolean[2*n], new boolean[2*n]);
    return res;
}

void backtrack(List<List<String>> res, char[][] board, int row,
               boolean[] cols, boolean[] diag1, boolean[] diag2) {
    int n = board.length;
    if (row == n) {
        List<String> solution = new ArrayList<>();
        for (char[] r : board) solution.add(new String(r));
        res.add(solution);
        return;
    }
    for (int col = 0; col < n; col++) {
        int d1 = row - col + n, d2 = row + col;
        if (cols[col] || diag1[d1] || diag2[d2]) continue;
        board[row][col] = 'Q';
        cols[col] = diag1[d1] = diag2[d2] = true;
        backtrack(res, board, row + 1, cols, diag1, diag2);
        board[row][col] = '.';
        cols[col] = diag1[d1] = diag2[d2] = false;
    }
}
```

```java
    int[] dp = new int[capacity + 1];
    for (int i = 0; i < n; i++) {
        // 逆序遍历，保证每个物品只用一次
        for (int j = capacity; j >= weights[i]; j--) {

        }
    }
    return dp[capacity];
```

### 7. 手写全排列（LeetCode 46）
```java
List<List<Integer>> permute(int[] nums) {
    List<List<Integer>> res = new ArrayList<>();
    backtrack(res, new ArrayList<>(), nums, new boolean[nums.length]);
    return res;
}

void backtrack(List<List<Integer>> res, List<Integer> path,
               int[] nums, boolean[] used) {
    if (path.size() == nums.length) {
        res.add(new ArrayList<>(path));
        return;
    }
    for (int i = 0; i < nums.length; i++) {
        if (used[i]) continue;
        used[i] = true;
        path.add(nums[i]);
        backtrack(res, path, nums, used);
        path.remove(path.size() - 1);
        used[i] = false;
    }
}
```

### 8. 手写最长公共子序列（LCS）
```java
int longestCommonSubsequence(String text1, String text2) {
    int m = text1.length(), n = text2.length();
    int[][] dp = new int[m + 1][n + 1];
    for (int i = 1; i <= m; i++) {
        for (int j = 1; j <= n; j++) {
            if (text1.charAt(i - 1) == text2.charAt(j - 1))
                dp[i][j] = dp[i - 1][j - 1] + 1;
            else
                dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]);
        }
    }
    return dp[m][n];
}
```

**核心流程：**
1. **文档预处理**：分词（Segment）、去停用词、词干提取
2. **构建倒排索引**：`词 -> [doc1, doc2, ...]`，每个doc同时保存位置信息
3. **查询处理**：用户输入 -> 分词 -> 在倒排索引中查找 -> 合并结果 -> 排序（TF-IDF/BM25）
4. **排序优化**：使用PageRank、时效性因子、点击率因子等

### 4. 设计一个分布式限流系统（阿里/字节）
**限流算法对比：**

| 算法 | 原理 | 特点 |
|------|------|------|
| 固定窗口 | 每分钟/每秒计数，超过则限流 | 有突发流量"双倍"问题 |
| **滑动窗口** | 将时间分成更小段，统计最近N段的总数 | 比固定窗口平滑 |
| 令牌桶 | 固定速率往桶里放令牌，请求消耗令牌 | 允许一定程度的突发 |
| 漏桶 | 请求进桶，以固定速率漏出 | 强制平滑，不能应对突发 |

**分布式实现**：Redis + Lua脚本保证原子性。

```lua
-- 滑动窗口限流Lua脚本
local key = KEYS[1]
local now = tonumber(ARGV[1])
local windowMs = tonumber(ARGV[2])
local maxRequests = tonumber(ARGV[3])
redis.call('ZREMRANGEBYSCORE', key, 0, now - windowMs)
local count = redis.call('ZCARD', key)
if count < maxRequests then
    redis.call('ZADD', key, now, now)
    return 1
else
    return 0
end
```

### 5. 设计一个支持多级缓存的架构（美团/阿里）

```
用户请求
  |
  v
[浏览器缓存/CDN] ------> 命中则返回
  |
  | 未命中
  v
[本地缓存/Redis集群] --> 命中则返回
  |
  | 未命中
  v
[数据库/持久层] --------> 查询并回写缓存
```

**多级缓存策略：**
1. **CDN**：静态资源（图片、JS、CSS）
2. **本地缓存**：Caffeine/Guava Cache，热点数据
3. **分布式缓存**：Redis Cluster，共享数据
4. **DB**：最终数据源

**缓存问题：**

| 问题 | 描述 | 解决方案 |
|------|------|----------|
| 缓存穿透 | 缓存和DB都没有的数据 | 布隆过滤器 + 空值缓存 |
| 缓存击穿 | 热点key过期，大并发打到DB | 互斥锁 / 逻辑过期 |
| 缓存雪崩 | 大量key同时过期 | 过期时间加随机值 / 多级缓存 |

## 六、常见坑点与最佳实践（表格）

| 知识点 | 常见坑点 | 最佳实践 |
|--------|----------|----------|
| HashMap | 并发环境下使用HashMap导致死循环/数据丢失 | 使用ConcurrentHashMap |
| 快速排序 | 有序数组时退化为O(n²) | 随机选择基准值 + 三路快排 |
| Dijkstra | 误用在含负权边的图上 | 负权图用Bellman-Ford或SPFA |
| 0-1背包 | 忘记逆序遍历，变成完全背包 | 外层容量逆序 `for j = W to w[i]` |
| 完全背包 | 忘记正序遍历，变成0-1背包 | 内层容量正序 `for j = w[i] to W` |
| 回溯 | 忘记撤销选择 | 模板化：做选择 -> 递归 -> 撤销选择 |
| 递归DP | 重复计算导致指数级复杂度 | 用数组备忘录（记忆化搜索） |
| 归并排序 | 合并时没有使用额外数组，原地归并O(n²) | 使用临时数组辅助合并 |
| 堆排序 | 建堆时从0开始下沉，参数搞错 | 建堆从 `n/2-1` 倒序遍历，下沉用递归 |
| KMP | LPS数组计算错误 | 注意 `len > 0` 时回退 `len = lps[len-1]` |
| 并查集 | 忘记路径压缩，导致find退化为O(n) | 递归find + 路径压缩：`parent[x] = find(parent[x])` |
| B树删除 | 删除后节点不满足最小关键字数 | 先借后合，借兄弟不行再和兄弟合并 |
| 桶排序 | 数据分布不均导致大部分数据落入同一桶 | 采用均匀的散列函数或递归分桶 |
| BitMap索引 | 使用 `%` 取模导致性能差 | HashMap用 `(n-1) & hash` 位运算取模 |
| 最短路径 | 在无权图中使用Dijkstra | 无权图用BFS即可，O(V+E)比Dijkstra快 |

## 七、面试回答模板（Top 5）

### 模板1：HashMap底层实现
> "HashMap底层是**数组+链表+红黑树**的数据结构。
> 1. 计算key的hash值：`(key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16)`，通过高低16位异或减少碰撞。
> 2. 计算索引位置：`(n - 1) & hash`，要求n为2的幂。
> 3. 如果该位置为空直接插入；否则遍历链表/红黑树，key相同则覆盖，不同则插入尾部。
> 4. 链表长度达到TREEIFY_THRESHOLD（8）且数组长度>=64时，链表转为红黑树。
> 5. 当键值对数量超过容量×负载因子（默认0.75）时，触发扩容到2倍，重新hash。"

### 模板2：快排为什么最坏O(n²)，如何优化？
> "快排最坏情况发生在**每次分区都极度不平衡**时，比如数组已经有序且每次选择第一个元素作为基准。
> 这样分区后一个子数组大小为0，另一个为n-1，递归深度O(n)，总复杂度O(n²)。
> **优化方案：**
> 1. 随机选择基准值（Random Pivot），从概率上避免最坏情况。
> 2. 三数取中（Median-of-Three），取left、mid、right的中位数作为基准。
> 3. 小数组切换到插入排序（如长度<16），减少递归开销。
> 4. 三路快排（3-Way Partition），将数组分为<pivot、=pivot、>pivot三区，特别适合重复元素多的场景。"

### 模板3：DP解题思路
> "遇到DP问题，我遵循以下四步法：
> 1. **确定状态定义**：一般是一维或二维数组，明确dp[i]或dp[i][j]的含义。
> 2. **找状态转移方程**：思考当前状态可以从哪些子状态推导出来，写出递推公式。
> 3. **确定初始条件**：base case的值是什么，比如dp[0]=0、dp[i][0]=0等。
> 4. **确定遍历顺序**：根据状态转移方向，确定是从小到大还是从大到小遍历。
> 
> 例如最长递增子序列（LIS）：
> - 状态：dp[i]表示以nums[i]结尾的最长递增子序列长度
> - 转移：dp[i] = max(dp[j] + 1) for j < i and nums[j] < nums[i]
> - 初始：所有dp[i] = 1
> - 结果：max(dp[0..n-1])"

### 模板4：如何解决TopK问题
> "根据数据量不同有不同方案：
> - **小数据量（百万内）**：用快速选择（Quick Select）算法，平均O(n)，只需要O(1)额外空间。
> - **中数据量（千万级）**：用小顶堆，维护大小为k的堆，O(n log k)时间，O(k)空间，且不用修改原数组。
> - **大数据量（亿万级）**：分而治之，将数据分片到多台机器，每台机器求各自的TopK，再汇总合并。
> - **无限数据流**：使用小顶堆 + 概率性数据结构（如Count-Min Sketch）。
> 
> 总结：面试中最推荐**小顶堆**方案，简单可控且能处理大部分场景。"

### 模板5：缓存穿透、击穿、雪崩的区别和解决方案
> "**缓存穿透**：查询一个不存在的数据，每次都穿过缓存打到DB。
> 解决：布隆过滤器拦截不存在key + 空值也缓存。
> 
> **缓存击穿**：一个热点key过期，大并发全部打向DB。
> 解决：互斥锁（只让一个线程去DB加载）+ 逻辑过期（key永不过期，后台线程异步更新）。
> 
> **缓存雪崩**：大量key同时过期，或Redis宕机，导致DB压力暴增。
> 解决：过期时间加随机值 + 多级缓存 + Redis高可用（主从+哨兵/集群）+ 限流熔断降级。"
