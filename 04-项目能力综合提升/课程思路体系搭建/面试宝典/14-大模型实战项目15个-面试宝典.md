### Q3: 什么是Transformer？核心组件有哪些？
Transformer是"Attention Is All You Need"（2017）提出的基于自注意力机制的序列模型架构。

| 组件 | 作用 |
|------|------|
| Self-Attention | 计算序列中每个token与其他token的相关性 |
| Multi-Head Attention | 多头并行注意力，捕捉不同子空间信息 |
| Positional Encoding | 注入位置信息 |
| Feed-Forward Network | 两层全连接，引入非线性变换 |
| Layer Normalization | 稳定训练过程，加速收敛 |
| Residual Connection | 残差连接，缓解梯度消失 |

### Q4: 什么是LLM的幻觉（Hallucination）？如何缓解？
| 幻觉类型 | 表现 | 缓解方案 |
|---------|------|---------|
| 事实性幻觉 | 生成与事实不符的内容 | RAG检索增强，接入外部知识库 |
| 一致性幻觉 | 前后矛盾或逻辑错误 | Chain-of-Thought引导推理 |
| 指令偏差 | 未正确遵循用户指令 | 提示词工程，Few-shot示例 |

### Q5: 什么是RAG（检索增强生成）？
RAG = Retrieval-Augmented Generation，流程：用户Query到检索知识库到获取相关文档到拼接Prompt到LLM生成回答。优势：解决知识截止日期、幻觉问题、私有数据接入。核心组件：Embedding模型、向量数据库、检索器、LLM。

### Q6: 什么是Agent？Agent的核心能力有哪些？
Agent = LLM + 感知 + 规划 + 工具调用 + 记忆

| 能力 | 说明 |
|------|------|
| 感知 | 理解环境信息和用户输入 |
| 规划 | 拆解任务、制定执行计划（ReAct/Plan-and-Execute） |
| 工具调用 | Function Calling调用外部API/工具 |
| 记忆 | 短期记忆（上下文窗口）+ 长期记忆（向量数据库） |

### Q7: 什么是LoRA微调？
LoRA = Low-Rank Adaptation。原理：冻结预训练权重，在Transformer层旁路插入低秩矩阵进行训练。优势：显存占用降低90%，训练速度提升，仅需保存少量参数。公式：W' = W + BA（B为m*r，A为r*n，r远小于min(m,n)）。

### Q8: 什么是Prompt Engineering？有哪些常见技巧？
| 技巧 | 说明 | 示例 |
|------|------|------|
| Role Prompting | 给模型分配角色 | "你是一名资深Java架构师" |
| Few-shot | 提供少量示例 | 给出2-3个输入输出对 |
| Chain-of-Thought | 引导模型逐步推理 | "让我们一步步思考" |
| Output Format | 明确指定输出格式 | "请以JSON格式返回" |
| Negative Prompt | 排除不需要的输出 | "不要解释，直接给出答案" |

### Q9: 什么是Embedding？和Token Embedding的区别？
Embedding将文本映射为固定维度的向量表示。Token Embedding是模型输入层的词向量映射。Text Embedding将整个句子/文档转为向量，用于检索、聚类、相似度计算。常见Embedding模型：text-embedding-ada-002、BGE、M3E、text2vec。

### Q10: 什么是Function Calling（工具调用）？
定义：LLM在生成回复时，能识别需要调用外部工具/API的场景。流程：定义工具描述到LLM判断是否需调用到返回Function Call参数到执行工具到结果返回LLM。应用场景：查询数据库、调用搜索引擎、执行代码、发送通知。

### Q11: 什么是向量数据库？常见的向量数据库有哪些？
| 数据库 | 特性 | 适用场景 |
|--------|------|---------|
| Chroma | 轻量级，嵌入式，Python原生 | 原型开发、小规模RAG |
| Milvus | 分布式，高性能，支持GPU加速 | 生产级大规模向量检索 |
| Pinecone | 全托管SaaS服务 | 快速部署、免运维 |
| Qdrant | Rust实现，高性能Filter | 带过滤条件的检索 |
| FAISS | Meta开源的向量检索库 | 本地高性能检索（非数据库） |

### Q12: 什么是LangChain？核心组件是什么？
LangChain是一个基于LLM的应用程序开发框架。核心组件：Models（封装不同LLM提供商API）、Prompts（模板管理）、Chains（多步LLM调用编排）、Agents（自主决策+工具调用）、Retrievers（文档检索和重排序）、Memory（多轮对话记忆管理）。

### Q13: Streamlit在AI应用中的作用？
Python快速Web应用框架，专为数据科学/ML设计。优势：纯Python开发、热重载、丰富的UI组件。在大模型项目中用于快速搭建Demo和原型验证。

### Q14: 什么是Reranker？和Embedding检索的区别？
| 对比维度 | Embedding检索 | Reranker重排序 |
|---------|--------------|---------------|
| 原理 | 向量相似度（余弦/内积） | Cross-Encoder计算匹配分数 |
| 精度 | 较低（仅粗排） | 较高（精排） |
| 速度 | 快（百万级毫秒） | 慢（千级需百毫秒） |
| 使用阶段 | 第一轮检索 | 第二轮精排 |

### Q15: 什么是CoT（Chain-of-Thought）提示？
引导模型逐步推理后给出答案的提示技术。Zero-shot CoT：仅加"让我们一步步思考"。Few-shot CoT：提供推理步骤示例。适用场景：数学推理、逻辑推理、多步决策。

### Q16: 大模型项目的技术栈通常包含哪些？
前端层：Streamlit / Gradio / React
API层：FastAPI / Spring Boot / Flask
LLM层：Ollama / OpenAI / DeepSeek / Local Model
检索层：Chroma / Milvus / FAISS + Embedding API
编排层：LangChain / LlamaIndex / Spring AI
存储层：PostgreSQL / Redis / MinIO

### Q17: 什么是Prompt注入攻击？如何防御？
Prompt注入：恶意输入覆盖原始Prompt指令。防御方案：输入过滤（检测注入模式关键词）、Prompt隔离（用户输入与系统指令严格分段）、权限限制（限制Function Calling可调用的API范围）、输出验证（二次确认）。

### Q18: 什么是模型量化（Quantization）？
将模型权重从FP16/FP32降低精度到INT4/INT8。优势：显存占用降低4-8倍，推理速度提升。常见方案：GPTQ（GPU）、GGUF（CPU）、AWQ（自适应）。面试关注点：量化后模型性能损失通常小于5%。

### Q25: 文档问答系统如何实现混合检索？
```python
def hybrid_search(query, top_k=10):
    query_embedding = embedding_model.encode(query)
    vector_results = vector_db.similarity_search_by_vector(query_embedding, k=top_k)
    keyword_results = bm25_retriever.get_relevant_documents(query, k=top_k)

    all_docs = {}
    for rank, doc in enumerate(vector_results):
        all_docs[doc.id] = all_docs.get(doc.id, 0) + 1 / (rank + 60)
    for rank, doc in enumerate(keyword_results):
        all_docs[doc.id] = all_docs.get(doc.id, 0) + 1 / (rank + 60)

    ranked = sorted(all_docs.items(), key=lambda x: x[1], reverse=True)
    return ranked[:top_k]
```

```python
def generate_minutes(audio_path):
    result = whisper_model.transcribe(audio_path)
    segments = result["segments"]
    minutes = []
    for seg in segments:
        summary = llm.invoke("总结会议片段：" + seg["text"])
        minutes.append({"speaker": seg.get("speaker"), "summary": summary})

    all_text = "\\n".join([m["summary"] for m in minutes])
    final = llm.invoke("生成结构化会议纪要：" + all_text)
    return {"segments": minutes, "summary": final}
```

### Q37: 如何设计内容生成平台的批量生产管线？
```python
class ContentPipeline:
    def __init__(self, llm, batch_size=10):
        self.llm = llm
        self.batch_size = batch_size

    def generate_batch(self, topics, template, style):
        results = []
        for i in range(0, len(topics), self.batch_size):
            batch = topics[i:i + self.batch_size]
            prompts = [template + "\\n主题：" + t + "\\n风格：" + style for t in batch]
```

```python
from langchain.chains.base import Chain
from typing import Dict, List

class DocumentQACustomChain(Chain):
    retriever: object
    llm: object
    input_key: str = "question"
    output_key: str = "answer"

    @property
    def input_keys(self) -> List[str]:
        return [self.input_key]

    @property
    def output_keys(self) -> List[str]:
        return [self.output_key]

    def _call(self, inputs: Dict[str, str]) -> Dict[str, str]:
        question = inputs[self.input_key]
        docs = self.retriever.get_relevant_documents(question)

        context = ""
        for i, doc in enumerate(docs):
            context += "[" + str(i+1) + "] " + doc.page_content + "\\n"

        prompt = "基于以下文档回答问题，标注引用来源：\\n"
        prompt += context
        prompt += "\\n问题：" + question
        answer = self.llm.invoke(prompt)
        return {self.output_key: answer}
```

### Q45: 手写文档解析与分块代码
```python
import hashlib
from langchain.document_loaders import PyPDFLoader, TextLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter

class DocumentProcessor:
    def __init__(self):
        self.text_splitter = RecursiveCharacterTextSplitter(
            chunk_size=512, chunk_overlap=50,
            separators=["\\n## ", "\\n### ", "\\n\\n", "\\n", ". ", " "])

    def load_document(self, file_path):
        if file_path.endswith(".pdf"):
            loader = PyPDFLoader(file_path)
        else:
            loader = TextLoader(file_path)
        return loader.load()

    def semantic_chunk(self, document):
        chunks = []
        splits = self.text_splitter.split_documents([document])
        for i, split in enumerate(splits):
            chunk_id = hashlib.md5(split.page_content.encode()).hexdigest()[:8]
            split.metadata["chunk_id"] = chunk_id
            split.metadata["chunk_index"] = i
            split.metadata["total_chunks"] = len(splits)
            chunks.append(split)
        return chunks
```

```python
import re

def clean_document(text: str) -> str:
    text = re.sub(r"\s+", " ", text)
    text = re.sub(r"http\S+|www\.\S+", "", text)
    text = re.sub(r"[^\w\s一-鿿.,!?;:()]", "", text)
    lines = [line.strip() for line in text.split("\\n") if line.strip()]
    return "\\n".join(lines)

def split_by_semantic(text: str, max_length: int = 500):
    paragraphs = text.split("\\n")
    chunks = []
    current_chunk = ""
    for para in paragraphs:
        if len(current_chunk) + len(para) < max_length:
            current_chunk += para + "\\n"
        else:
            if current_chunk.strip():
                chunks.append(current_chunk.strip())
            current_chunk = para + "\\n"
    if current_chunk.strip():
        chunks.append(current_chunk.strip())
    return chunks
```

## 六、常见坑点与最佳实践

| 坑点 | 原因 | 解决方案 |
|------|------|---------|
| RAG上下文越长效果反而变差 | 过多噪声信息干扰LLM判断 | 限制Top-K为3-5，结合Reranker精排 |

| 未做Query改写导致检索结果差 | 原始问题与文档表述不一致 | 使用LLM进行一次Query改写和扩展 |
| 多轮对话中忽略上下文 | 每次请求独立处理 | 使用ConversationBufferMemory维护历史 |
| Agent工具调用无限循环 | 没有设置最大迭代次数 | 设置max_iterations和handle_parsing_errors |
| Embedding模型与场景不匹配 | 通用模型在垂直领域表现差 | 在垂直领域数据上Fine-tune Embedding |
| LLM输出不稳定 | temperature大于0 | 关键场景设置temperature=0 |
| 显存OOM | 未做模型量化或批次过大 | 使用INT4量化，减小batch_size |
| 文档更新后向量库未同步 | 缺少增量更新机制 | 实现基于hash的chunk变更检测 |
