## 一、基础概念速答（15-20题）

### 1.1 什么是大模型？与普通模型有什么区别？
大模型（Large Language Model, LLM）指参数规模通常在数十亿到数千亿级别的深度学习模型，基于Transformer架构，在海量文本数据上预训练而成。以GPT系列、LLaMA、DeepSeek、Qwen等为代表。

| 维度 | 传统模型 | 大模型 |
|------|---------|--------|
| 参数量 | 百万~亿级 | 十亿~万亿级 |
| 训练数据 | 任务特定标注数据 | 海量互联网文本 |
| 泛化能力 | 单一任务 | 多任务、零样本/少样本学习 |
| 训练成本 | 单机/少量GPU | 千卡集群，数百万美元 |
| 涌现能力 | 无 | 思维链、上下文学习等涌现能力 |

> 阿里巴巴面试题：大模型为什么会有涌现能力？核心观点：参数量超过某个阈值后，模型内部表征能力发生质变，出现了小模型不具备的推理能力。

### 1.2 什么是Prompt Engineering？典型构成是什么？
Prompt Engineering（提示词工程）是通过精心设计输入文本，引导大模型产生期望输出的技术。其典型构成包括：

> 指令（Instruction） + 上下文（Context） + 示例（Few-shot Examples） + 角色（Role）

| 组件 | 说明 | 示例 |
|------|------|------|
| 指令 | 明确告诉模型要做什么 | "请将以下英文翻译为中文" |
| 上下文 | 提供背景信息 | "这是一篇技术论文的摘要" |
| 示例 | 给出1-5个输入输出对 | "apple -> 苹果, banana -> 香蕉" |
| 角色 | 指定模型扮演的角色 | "你是一名资深Java架构师" |

### 1.3 Zero-shot / Few-shot / CoT / ToT 的区别？

| 方法 | 说明 | 适用场景 |
|------|------|---------|
| Zero-shot | 不给示例，直接提问 | 通用问答、翻译 |
| Few-shot | 给出少量输入输出示例 | 格式要求严格的输出 |
| CoT（思维链） | 引导模型逐步推理 | 数学、逻辑推理题 |
| ToT（思维树） | 探索多条推理路径并回溯 | 复杂规划、24点游戏 |

> 字节跳动面试题：CoT和ToT的本质区别是什么？回答要点：CoT是单条推理路径链式展开，ToT是树状搜索多条路径并做回溯评估，计算量更大但效果更好。

### 1.4 RAG的核心流程是什么？
RAG（Retrieval-Augmented Generation）的核心流程分为三个阶段：

1. **索引阶段**：文档切分（Chunking） -> Embedding向量化 -> 存入向量数据库
2. **检索阶段**：用户查询 -> Embedding -> 向量相似度检索 -> 返回Top-K相关片段
3. **生成阶段**：原始查询 + 检索到的上下文 -> 拼接Prompt -> LLM生成回答

### 1.5 什么是Embedding？
Embedding是将文本、图像等非结构化数据映射到低维稠密向量空间的技术。在RAG中，Embedding模型将文本片段转换为固定维度的向量（如768维、1024维），使得语义相近的文本在向量空间中距离更近。

> 腾讯面试题：Embedding模型和普通文本分类模型有什么区别？核心：Embedding关注的是语义相似度而非类别区分，输出是一个连续向量空间中的坐标而非类别标签。

### 1.6 LangChain核心组件有哪些？
LangChain是一个用于构建LLM应用的框架，核心组件包括：

| 组件 | 功能 |
|------|------|
| Models（模型封装） | 统一各类LLM、Chat、Embedding的接口 |
| Prompts（提示词管理） | 模板化Prompt、Few-shot示例选择 |
| Memory（记忆管理） | 对话历史存储与管理（Buffer、Summary、VectorStore等） |
| Chains（链） | 将多个组件串联为处理流水线 |
| Agents（智能体） | 让LLM自主决策调用哪些工具 |
| Retrievers（检索器） | 从向量数据库或其他源检索相关信息 |
| Document Loaders（文档加载器） | 支持PDF、网页、数据库等多种源 |
| LangServe | 将LangChain应用部署为REST API |

### 1.7 什么是Agent？核心架构是什么？
Agent（智能体）是能**自主感知环境、制定计划、调用工具**来完成任务的AI系统。核心架构包括：

- **感知（Perception）**：接收用户输入和环境信息
- **规划（Planning）**：将任务拆解为子步骤（CoT/ToT）
- **工具调用（Tool Use）**：调用外部API、数据库、搜索引擎等
- **记忆（Memory）**：短期记忆（上下文窗口）和长期记忆（向量数据库）
- **反思（Reflection）**：自我评估和纠错

> 百度面试题：Agent和传统程序有什么区别？传统程序是确定性的if-else逻辑，Agent是基于LLM推理的动态决策系统，能处理未预定义的情况。

### 1.8 什么是LangGraph？与LangChain的关系？
LangGraph是构建**多智能体工作流**的框架，扩展自LangChain。LangChain擅长单链/单Agent流程，LangGraph支持：

- **循环图**：Agent可以循环调用工具、反思结果
- **条件跳转**：根据中间结果决定下一步走向
- **多Agent协作**：支持Agent间的消息传递和任务分配
- **状态管理**：全局状态在节点间共享

> 关系：LangGraph建立在LangChain之上，LangChain提供基础组件，LangGraph提供图执行引擎。

### 1.9 什么是Fine-tuning？与Pre-training的区别？
| 阶段 | Pre-training | Fine-tuning |
|------|-------------|-------------|
| 数据 | 海量互联网文本（TB级） | 任务特定标注数据 |
| 目标 | 学习语言通用知识 | 适配特定任务/风格 |
| 成本 | 千卡GPU、数周 | 单卡/少量GPU、数小时 |
| 模型状态 | 从随机初始化开始 | 从预训练权重继续训练 |

### 1.10 什么是LoRA轻量化微调？
LoRA（Low-Rank Adaptation）是一种参数高效微调方法。核心思想：冻结预训练权重，在Transformer的注意力层插入低秩矩阵作为可训练参数。通常将矩阵分解为 `A * B` 的形式，其中 `A` 和 `B` 的秩较小（如r=8,16）。

### 1.11 Transformer的核心组件是什么？
Transformer的核心组件包括：
- **Self-Attention（自注意力）**：计算序列中每个位置与其他位置的相关性
- **Multi-Head Attention（多头注意力）**：多个注意力头并行，捕捉不同子空间信息
- **Feed-Forward Network（前馈网络）**：每个位置的独立非线性变换
- **Layer Normalization（层归一化）**：稳定训练过程
- **Position Encoding（位置编码）**：为模型提供位置信息
- **Residual Connection（残差连接）**：缓解梯度消失

### 1.12 什么是ReAct框架？
ReAct（Reasoning + Acting）是Agent的核心推理框架，将**推理（Reasoning）**与**行动（Acting）**交替进行：

```
思考（Thought）-> 行动（Action）-> 观察（Observation）-> 思考（Thought）-> ...
```

ReAct让LLM在每一步先思考下一步该做什么（Thought），然后执行具体操作（Action），再根据观察结果（Observation）继续推理，形成循环直到任务完成。

### 1.13 什么是MCP协议？
MCP（Model Context Protocol）是Anthropic提出的开放协议，用于标准化AI模型与外部工具/数据源的交互方式。它定义了统一的接口规范，让LLM应用可以像USB设备即插即用一样接入各种工具。LangGraph等框架已支持MCP接入。

### 1.14 什么是GraphRAG？
GraphRAG是微软提出的融合知识图谱的RAG方法。在传统向量检索的基础上，引入**实体关系图**结构：

1. 从文档中抽取实体和关系构建知识图谱
2. 检索时不仅检索相关文本片段，还检索相关的实体关系路径
3. 生成时结合文本和图结构信息，回答更精准

> 优点：能回答多跳推理问题、实体间关系问题，优于纯向量检索的RAG。

### 1.15 什么是Reranker（重排序器）？
Reranker是对检索结果进行**二次排序**的模型。在RAG中，向量检索召回Top-100候选片段后，Reranker逐对计算每个候选与查询的相关性分数，重新排序后取Top-5送给LLM。

| 维度 | 向量检索 | Reranker |
|------|---------|----------|
| 效率 | 高（百万级毫秒响应） | 低（千级需几十毫秒） |
| 精度 | 中等（语义近似） | 高（深度交互） |
| 计算方式 | 向量余弦相似度 | Cross-Encoder深度匹配 |

## 二、深度原理剖析（10-15题）

### 2.1 Transformer Self-Attention机制详解

Self-Attention的计算公式：

```
Attention(Q, K, V) = softmax(Q * K^T / sqrt(d_k)) * V
```

**计算步骤：**
1. **线性投影**：输入 X 分别乘以 W_Q、W_K、W_V 得到 Q、K、V
2. **计算注意力分数**：Q * K^T，得到每对位置的相似度矩阵
3. **缩放**：除以 sqrt(d_k)，防止内积过大导致softmax梯度消失
4. **Softmax归一化**：将每行的分数转为概率分布
5. **加权求和**：注意力权重与V相乘，得到加权后的表示

> 美团面试题：为什么要除以 sqrt(d_k)？如果d_k=512，QK^T的方差约为512，softmax会进入梯度饱和区，除以sqrt(512)还原方差为1，保持梯度正常。

### 2.2 Multi-Head Attention的原理与优势

**原理**：将Q、K、V拆分为h个头（通常h=8或12），每个头独立计算Self-Attention，最后拼接并线性投影。

```
MultiHead(Q,K,V) = Concat(head_1,...,head_h) * W_O
head_i = Attention(Q * W_Q_i, K * W_K_i, V * W_V_i)
```

**优势：**
- 每个头关注不同的子空间信息（语法、语义、位置等）
- 增加模型容量而不显著增加计算量
- 类似CNN中多个卷积核的作用

### 2.3 Position Encoding：绝对位置编码 vs RoPE

| 类型 | 代表模型 | 原理 | 优缺点 |
|------|---------|------|--------|
| 绝对位置编码 | Transformer原始论文 | 正弦余弦函数生成固定编码 | 外推性差，无法处理超过训练长度的序列 |
| RoPE旋转位置编码 | LLaMA、Qwen、Gemma | 在注意力计算中旋转Q和K向量 | 相对位置感知，外推性好，无需额外参数 |

> RoPE核心公式：通过在Q和K向量上施加旋转矩阵，使得点积结果只依赖于相对位置差。

### 2.4 LLM训练三阶段：Pre-training -> SFT -> RLHF/DPO

| 阶段 | 数据 | 目标 | 代表方法 |
|------|------|------|---------|
| Pre-training（预训练） | 万亿token互联网文本 | 学习语言知识、世界知识 | Next Token Prediction |
| SFT（有监督微调） | 高质量指令-回答对 | 对齐人类指令格式 | 标准交叉熵损失 |
| RLHF（强化学习人类反馈） | 人类偏好对比数据 | 对齐人类价值观偏好 | PPO算法 |
| DPO（直接偏好优化） | 偏好对数据 | 无需强化学习，直接优化偏好 | 二元交叉熵损失 |

> 字节跳动面试题：RLHF和DPO有什么区别？RLHF需要训练Reward Model + PPO在线策略，训练复杂且不稳定；DPO直接利用偏好对优化策略模型，无需Reward Model，训练更稳定但表达能力受限于偏好数据的质量。

### 2.5 RAG各模块详解

1. **Chunking（文档切分）**：将长文档切分为语义完整的片段。策略包括固定大小切分（256/512 tokens）、语义切分（按段落/句子边界）、递归切分（递归字符文本分割器）。

2. **Embedding（向量化）**：将文本映射到向量空间。常见模型：BGE、text-embedding-ada-002、m3e、gte。

3. **Retrieval（检索）**：向量相似度检索（余弦相似度、欧式距离、点积）。进阶：混合检索（向量+关键词BM25） + Reranker重排序。

4. **Re-ranking（重排序）**：Cross-Encoder模型对候选片段深度打分，精选Top-K。

5. **Generation（生成）**：将查询和检索结果组装为Prompt，由LLM生成最终回答。

### 2.6 Agent决策机制：ReAct循环详解

```
# ReAct伪代码
def react_agent(query):
    max_steps = 10
    steps = 0
    completed = False
    
    while not completed and steps < max_steps:
        thought = llm.generate(f"思考：当前进度，下一步做什么？\n查询：{query}\n历史：{history}")
        action = extract_action(thought)  # 调用的工具名称+参数
        observation = execute_tool(action)
        history.append(thought, action, observation)
        
        if check_completed(query, history):
            completed = True
        steps += 1
    
    return final_answer
```

### 2.7 Chain-of-Thought与Tree-of-Thought原理对比

| 维度 | CoT | ToT |
|------|-----|-----|
| 搜索结构 | 链式（一条路径） | 树状（多路径分支） |
| 探索策略 | 贪心解码 | BFS/DFS搜索 |
| 回溯能力 | 无 | 有（路径评估剪枝） |
| 计算成本 | 低（1x） | 高（5-10x） |
| 适用场景 | 简单推理 | 复杂规划、数学难题 |
| 评估机制 | 隐式（内部表示） | 显式（打分函数评估中间步骤） |

> 快手面试题：ToT中如何评估中间节点？常见方法：LLM自评估（让模型打分）、训练专门的评估器、投票机制（多次采样取多数）。

### 2.8 轻量化微调：LoRA原理（低秩分解）

LoRA的核心假设：预训练权重在微调过程中的变化量 `Delta W` 是**低秩**的。

```
W_new = W_original + Delta W = W_original + A * B

其中 A ∈ R^(d x r), B ∈ R^(r x d), r << d
```

- W_original 冻结不更新（d x d 维度）
- A 和 B 是可训练的低秩矩阵（通常 r=8 或 16）
- 参数量从 d² 减少到 2*d*r，减少约 1000倍
- 推理时可以合并回原始权重，**不增加推理延迟**

> 百度面试题：LoRA的秩r怎么选择？r=1和r=64有什么区别？r越小参数量越少但表达能力受限；r越大学习能力越强但可能过拟合。实践中r=8或16是常见选择，简单任务小r，复杂任务大r。

### 2.9 KV Cache优化原理

在自回归生成中，每一步计算注意力时，历史token的K和V矩阵被**缓存**下来，避免重复计算。

**优化效果：**
- 计算量：从 O(n²) 降为 O(n)（每步只计算新token的注意力）
- 内存占用：缓存K和V矩阵，占用 O(n * d) 空间

**存在问题：** 长序列下KV Cache占用大量显存（如128K上下文时KV Cache可达几十GB）。优化方案包括Multi-Query Attention（MQA）、Grouped-Query Attention（GQA）、KV Cache量化等。

### 2.10 解码策略对比

| 策略 | 原理 | 特点 | 适用场景 |
|------|------|------|---------|
| Greedy Decoding | 每步选概率最高的token | 确定性输出，但易重复 | 翻译、摘要 |
| Beam Search | 维护K条候选路径 | 全局最优性更好，计算量大 | 翻译、文本生成 |
| Top-k Sampling | 从概率最高的K个token中采样 | 多样性可控 | 对话生成 |
| Top-p (Nucleus) | 从累积概率>=p的最小集合中采样 | 自适应候选数 | 创意写作 |
| Temperature | 缩放softmax logits | T越高越随机，T越低越确定 | 精细控制随机性 |

```
# Temperature的作用
T -> 0: softmax趋近于one-hot（确定性）
T = 1: 原始概率分布
T -> ∞: 均匀分布（完全随机）
```

### 2.11 幻觉问题（Hallucination）成因与缓解策略

**成因：**
- 模型倾向于生成统计上合理的但不是真实的文本
- 训练数据中存在的噪声和错误被模型学习
- 模型对未知事实的"编造"行为

**缓解策略：**
| 策略 | 方法 | 效果 |
|------|------|------|
| RAG | 检索外部知识作为依据，降低幻觉 | 最佳实践 |
| 约束解码 | 限制模型只能从给定文档中提取内容 | 强但灵活性低 |
| Self-Consistency | 多次采样取一致答案 | 计算成本高 |
| 知识图谱约束 | 引入结构化知识限制生成 | 维护成本高 |
| 提示词工程 | 明确"不知道就说不知道" | 基础但有效 |

## 三、实战场景题（8-12题）

### 3.1 使用DeepSeek + FAISS搭建本地知识库

```python
from sentence_transformers import SentenceTransformer
import faiss
import numpy as np
import json

# 1. 加载Embedding模型
model = SentenceTransformer('BAAI/bge-small-zh-v1.5')

# 2. 准备文档数据
documents = [
    "Java是一种面向对象的编程语言，由Sun Microsystems公司于1995年推出。",
    "Spring Boot是基于Spring框架的快速开发框架，简化了Spring应用的配置。",
    "Redis是一个开源的内存数据结构存储系统，可用作数据库、缓存和消息代理。",
    "MySQL是一个关系型数据库管理系统，由瑞典MySQL AB公司开发。",
    "Docker是一个开源的应用容器引擎，让开发者可以打包应用及依赖到可移植的容器中。"
]

# 3. 生成向量
doc_embeddings = model.encode(documents)
dimension = doc_embeddings.shape[1]

# 4. 创建FAISS索引
index = faiss.IndexFlatL2(dimension)  # L2距离
index.add(doc_embeddings.astype(np.float32))

# 5. 检索函数
def retrieve(query, top_k=2):
    query_embedding = model.encode([query])
    distances, indices = index.search(query_embedding.astype(np.float32), top_k)
    results = [{"doc": documents[i], "score": float(distances[0][j])} 
               for j, i in enumerate(indices[0])]
    return results

# 6. 测试
query = "什么是Spring Boot?"
results = retrieve(query)
for r in results:
    print(f"[Score: {r['score']:.4f}] {r['doc']}")
```

### 3.2 LangChain构建RAG问答链

```python
    return state

def coding_agent(state: AgentState) -> AgentState:
    """编码型Agent"""
    state["code_result"] = f"已生成关于 '{state['query']}' 的代码..."
    return state

    """通用型Agent"""
    state["final_answer"] = f"关于 '{state['query']}' 的回答..."
```

```python
import numpy as np

def softmax(x, axis=-1):
    """稳定的Softmax实现"""
    x_max = np.max(x, axis=axis, keepdims=True)
    exp_x = np.exp(x - x_max)
    return exp_x / np.sum(exp_x, axis=axis, keepdims=True)

def self_attention(Q, K, V):
    """
    手写Self-Attention
    Q, K, V: (batch_size, seq_len, d_model)
    """
    d_k = Q.shape[-1]
    
    # 1. 计算注意力分数：Q @ K^T
    scores = np.matmul(Q, K.transpose(0, 2, 1))  # (batch, seq, seq)
    
    # 2. 缩放
    scores = scores / np.sqrt(d_k)
    
    # 3. Softmax归一化
    attention_weights = softmax(scores, axis=-1)  # (batch, seq, seq)
    
    # 4. 加权求和
    output = np.matmul(attention_weights, V)  # (batch, seq, d_model)
    
    return output, attention_weights

# 测试
```

```python
import numpy as np

def softmax_stable(x, axis=-1):
    """
    数值稳定的Softmax实现
    减去最大值防止exp溢出
    """
    # 减去最大值防止数值溢出
    x_max = np.max(x, axis=axis, keepdims=True)
    x_shifted = x - x_max
    
    # 计算exp
    exp_x = np.exp(x_shifted)
    
    # 归一化
    sum_exp = np.sum(exp_x, axis=axis, keepdims=True)
    
    return exp_x / sum_exp
```

### 4.3 手写Layer Normalization

```python
import numpy as np

def layer_norm(x, gamma=None, beta=None, eps=1e-5):
    """
    手写Layer Normalization
    x: (batch_size, seq_len, hidden_size)
    gamma, beta: 可学习的缩放和偏移参数
    """
    # 计算均值和方差（在最后一个维度上）
    mean = np.mean(x, axis=-1, keepdims=True)
    variance = np.var(x, axis=-1, keepdims=True)
    
    # 归一化
    x_norm = (x - mean) / np.sqrt(variance + eps)
    
    # 缩放和偏移
    if gamma is not None:
        x_norm = x_norm * gamma
    if beta is not None:
        x_norm = x_norm + beta
    
    return x_norm

# 测试
```

### 4.4 手写BPE Tokenizer

```python
from collections import defaultdict
import re

class BPETokenizer:
    """手写简化版BPE分词器"""
    
    def __init__(self, vocab_size=1000):
        self.vocab_size = vocab_size
        self.merges = {}  # 合并规则
        self.vocab = {}   # 词汇表
    
    def get_stats(self, words):
        """统计相邻词对频率"""
        pairs = defaultdict(int)
        for word, freq in words.items():
            symbols = word.split()
            for i in range(len(symbols)-1):
                pairs[symbols[i], symbols[i+1]] += freq
        return pairs
    
    def merge_vocab(self, pairs, words, merge_pair):
        """执行合并操作"""
        new_words = {}
        bigram = ' '.join(merge_pair)
        replacement = ''.join(merge_pair)
        
        for word, freq in words.items():
            new_word = word.replace(bigram, replacement)
            new_words[new_word] = freq
        return new_words
    
    def train(self, corpus):
        """训练BPE分词器"""
        # 初始化：每个字符作为一个token
        words = defaultdict(int)
        for text in corpus:
            word = ' '.join(list(text)) + ' </w>'
            words[word] += 1
        
        self.vocab = {}
        for char in set(''.join(corpus)):
            self.vocab[char] = len(self.vocab)
        self.vocab['</w>'] = len(self.vocab)
        
        # 迭代合并
        for i in range(self.vocab_size - len(self.vocab)):
            pairs = self.get_stats(words)
            if not pairs:
                break
            
            # 找到频率最高的pair
            best_pair = max(pairs, key=pairs.get)
            
            # 记录合并规则
            self.merges[best_pair] = len(self.merges)
            self.vocab[''.join(best_pair)] = len(self.vocab)
            
            # 执行合并
            words = self.merge_vocab(pairs, words, best_pair)
    
    def encode(self, text):
        """编码文本为token ids"""
        words = [' '.join(list(text)) + ' </w>']
        
        for pair, _ in sorted(self.merges.items(), key=lambda x: x[1]):
            bigram = ' '.join(pair)
            replacement = ''.join(pair)
            words = [word.replace(bigram, replacement) for word in words]
        
        tokens = words[0].split()
        return [self.vocab[t] for t in tokens if t in self.vocab]

# 测试
```

```python
import numpy as np
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity

class SimpleRAG:
    """手写简化版RAG系统"""
    
    def __init__(self):
        self.documents = []
        self.chunks = []
        self.vectorizer = TfidfVectorizer()
        self.vectors = None
    
    def ingest(self, documents, chunk_size=200, overlap=50):
        """文档入库"""
        self.documents = documents
        
        # 简单切分
        for doc in documents:
            words = doc.split()
            for i in range(0, len(words), chunk_size - overlap):
                chunk = ' '.join(words[i:i+chunk_size])
                self.chunks.append(chunk)
        
        # 向量化
        self.vectors = self.vectorizer.fit_transform(self.chunks)
        print(f"已索引 {len(self.chunks)} 个文档块")
    
    def retrieve(self, query, top_k=3):
        """检索最相关文档块"""
        query_vector = self.vectorizer.transform([query])
        similarities = cosine_similarity(query_vector, self.vectors)[0]
        top_indices = np.argsort(similarities)[-top_k:][::-1]
        
        results = []
        for idx in top_indices:
            results.append({
                "content": self.chunks[idx],
                "score": float(similarities[idx])
            })
        return results
    
    def generate(self, query, results):
        """基于检索结果生成回答"""
        context = "\n".join([r["content"] for r in results])
        prompt = f"""基于以下信息回答问题：

上下文：{context}

问题：{query}

回答："""
        return prompt  # 实际使用时可送给LLM
```

## 六、常见坑点与最佳实践

| 坑点 | 原因 | 解决方案 |
|------|------|----------|
| RAG检索结果不相关 | 分块策略不当：太大则语义混杂，太小则信息不全 | 使用递归字符切分，chunk_size=500-800，overlap=10-20%，按文档结构自然边界切分 |
| Embedding模型选择错误 | 中英文混用场景选错模型 | 中文场景优先选BGE/BAAI系列或m3e，英文选text-embedding-3-small/large |
| RAG中LLM忽略检索结果 | Prompt中检索结果位置不当，或没有明确指令 | 在Prompt末尾放置检索结果，明确写"请基于以上信息回答"，使用System Message强制约束 |
| Agent陷入死循环 | ReAct循环中工具调用失败或LLM持续思考不行动 | 设置max_iterations(默认5-10)，实现超时退出，增加Fallback路径 |
| Function Calling参数错误 | 函数schema定义不准确，或LLM生成的参数格式错误 | 使用strict mode（如OpenAI的strict=True），增加参数校验，设计更简单的工具接口 |
| 长上下文下模型性能下降 | 注意力分散，中间信息丢失（Lost in the Middle） | 将重要信息放在Prompt开头和结尾，使用RAG压缩上下文，不盲目输入全部内容 |
| LoRA微调后灾难性遗忘 | 微调数据分布与预训练数据偏差过大 | 微调时混合10-20%的通用语料，使用EWC（弹性权重巩固）等正则化方法 |
| 流式输出中断 | 网络不稳定或模型推理超时 | 实现客户端重连机制，服务端使用Server-Sent Events（SSE）标准协议，设置超时重试 |
| Prompt注入攻击 | 用户输入包含恶意指令覆盖原始Prompt | 输入过滤（关键词+正则），使用分隔符明确隔离用户输入，设置System Message优先级最高 |
| 语义缓存命中率低 | 向量相似度阈值设置不合理 | 动态阈值：根据查询复杂度调整，低阈值提高召回但增加LLM开销，平衡点通常在0.85-0.95 |
| 多Agent通信数据不一致 | 各Agent独立运行时状态不同步 | 使用全局状态管理（如LangGraph的StateGraph），所有Agent读写统一状态 |
| 大模型推理显存OOM | 显存管理不足，KV Cache占用过大 | 使用vLLM的PagedAttention、启用FlashAttention、KV Cache量化到INT8 |

## 七、面试回答模板（Top 5高频题的结构化回答模板）

### 7.1 "请解释Transformer的Self-Attention机制"

**核心要点：**
- 定义：Self-Attention让模型在处理每个位置时，关注序列中所有其他位置
- 三步流程：QKV投影 -> 注意力分数计算 -> 加权求和
- 优势：并行计算、长距离依赖捕捉优于RNN
- 局限：计算复杂度O(n²)，长序列开销大

**回答示例：**
> "Self-Attention是Transformer的核心机制，它允许模型在编码某个位置时，动态关注序列中所有其他位置。具体来说，输入X分别通过三个权重矩阵W_Q、W_K、W_V得到Q、K、V三个向量。然后计算Q与所有K的点积得到注意力分数，经过Softmax归一化后对V进行加权求和。这个过程中的关键在于QK点积衡量了两个位置之间的相关性，所以模型可以自动学习到哪些位置更重要。与RNN相比，它的优势是能并行计算且不受序列长度的梯度消失影响；但缺点是计算复杂度是O(n²)，所以长序列场景需要优化，比如使用Sparse Attention或FlashAttention。"

### 7.2 "RAG和Fine-tuning有什么区别？如何选择？"

**核心要点：**
- RAG：检索外部知识辅助生成，不改变模型参数
- Fine-tuning：在特定数据上继续训练，改变模型参数
- 选择依据：知识更新频率、数据隐私、计算成本、需要改变模型行为还是添加知识

**回答示例：**
> "RAG和Fine-tuning解决的是不同层面的问题。RAG的核心在于让模型能访问外部知识库，它不改变模型参数，适用于需要频繁更新知识、处理长尾知识或需要可解释性的场景。而Fine-tuning是改变模型本身的行为和知识，适用于需要适配特定输出风格、学习特定格式或提升在某个领域的整体能力。选择上，如果需要快速接入新知识且知识经常变化，选RAG；如果需要改变模型的行为模式或提升特定领域的深度能力，选Fine-tuning。实际上大厂的做法往往是RAG + Fine-tuning结合，用RAG提供外部知识，用Fine-tuning对齐输出格式和行为。我参与的一个项目中，先用LoRA微调让模型适应客服语气，再用RAG接入知识库，两者互补效果很好。"

### 7.3 "什么是Agent？Agent和传统程序有什么区别？"

**核心要点：**
- Agent定义：能自主感知、推理、行动的系统
- 核心循环：感知 -> 规划 -> 工具调用 -> 反思 -> 迭代
- 与传统程序区别：不确定性和自主决策是其核心特征

**回答示例：**
> "Agent是基于大模型构建的智能系统，它能自主理解用户意图、制定执行计划、调用外部工具、并根据反馈调整行为。与传统程序的根本区别在于两点：第一是非确定性，传统程序是固定的if-else逻辑，同样的输入永远得到同样的输出；而Agent基于LLM推理，即使相同的任务也可能采用不同的策略完成。第二是自主性，传统程序需要程序员预设所有路径，但Agent可以在运行时动态决定调用哪些工具、按什么顺序执行。举个例子，传统客服系统基于决策树，用户稍微偏离预设路径就答不上来；而Agent客服可以自主搜索知识库、查询订单系统、甚至学习新的流程。当然，这也意味着Agent需要更完善的监控和安全机制。"

### 7.4 "如何解决大模型的幻觉问题？"

**核心要点：**
- 定义：模型生成不真实或无根据的内容
- 四种缓解策略层次：输入层、推理层、知识层、评估层

**回答示例：**
> "幻觉是大模型在实际落地中最棘手的问题之一。我从四个层面来解决：第一，输入层优化——在Prompt中明确约束'如果不知道就说不知道'，用Few-shot示例展示拒绝回答的格式，降低模型编造倾向。第二，知识层引入RAG——这是目前最有效的方法，通过检索外部知识库为模型提供事实依据，让模型基于检索到的内容生成，而不是凭记忆编造。第三，推理层采用Self-Consistency——多次采样取多数一致答案，能有效过滤掉随机生成的幻觉内容。第四，评估层建立监控机制——用LLM-as-Judge自动检测回答中的事实一致性，对低分回答做降级处理。在字节跳动的面试中我提到过一个具体案例：我们通过RAG + Self-Consistency组合方案，将知识问答场景的幻觉率从15%降低到3%以下。需要注意的是，RAG也不是万能的，检索质量直接影响生成质量，所以检索链路本身也要优化。"

### 7.5 "LoRA微调的原理是什么？"

**核心要点：**
- 低秩分解假设：预训练权重的更新量是低秩的
- 公式：W_new = W + A*B
- 优势：参数高效、推理零开销、可插拔切换

**回答示例：**
> "LoRA的核心出发点是：大模型在微调过程中，权重的变化量Delta W具有低秩性。也就是说，虽然原始权重W是一个高维矩阵（比如d x d），但它要更新的部分可以用两个低秩矩阵A（d x r）和B（r x d）的乘积来近似，其中r远小于d。这样可训练参数量就从d²降到了2*d*r，通常只有原始参数的千分之一甚至万分之一。微调时，我们冻结原始预训练权重W保持不变，只训练A和B这两个小矩阵。在推理时，我们可以将A*B合并回W中，所以推理延迟是零增加的。更重要的是，我们可以同时训练多个LoRA模块并随时切换，用不同的LoRA适配不同的任务，这在大模型服务中非常实用。实践的技巧是：简单任务r设小一点（4-8），复杂任务r设大一些（16-32）。而且推荐只对Attention层的Q和V矩阵做LoRA，对FFN层做LoRA的收益通常不明显。"
