## 3. 学习路线推荐

**标准路径（5-7 天，对照检查）**：按 01→10 顺序，拿自己的项目逐篇对照——每篇的"自查清单"就是行动项，达标一项划一项。**本体系不是"学新知识"，是"给已有项目做体检"**——建议与 Level2/3 项目同步进行：项目做哪一步，就对照哪一篇的硬性要求。

**体检路径（1-2 天，提交简历前）**：只做 10 篇的最终自查清单 + 回看 01/06/08（环境、Git、文档三篇——简历附的 GitHub 链接被点开时，这三项决定第一印象）。

**陪跑路径（项目全周期）**：做项目前先通读 00 总览的九大分类（知道终点长什么样），每完成一个 Level 对照对应篇自查——**"验收标准先行"是工程化思维的第一步**。

## 4. 核心概念速查

| 概念 | 一句话速查 |
|---|---|
| 硬性要求 | 可被外部验证的工程指标（能跑、能读、有测试、有文档） |
| 环境可复现 | 换机器按文档 15 分钟复现，依赖锁定、说明齐全 |
| 一键运行 | 一条命令跑起服务（uv run / compose up） |
| 配置三态 | dev/test/prod 三套配置可切换，零硬编码 |
| 测试可信 | 测试不依赖真实外部服务、覆盖率有数字、CI 强制执行 |
| README 三件套 | 项目简介 + 快速开始 + 环境要求 |
| 可观测最低线 | 日志有、错误可查、健康检查有响应 |

## 5. 筛选视角：简历是怎么被看的

理解筛选者的动作顺序，就理解为什么这些是"硬性要求"：**初筛（HR/机器）**——按关键词与硬指标过滤（技术栈名称、项目数量、学历），Python/AI 岗位的关键词命中（FastAPI、RAG、LangGraph、Docker 等）是门票；**复筛（技术面试官）**——点开简历附的 GitHub 链接，30 秒内判断"这是真项目还是抄的作业"：仓库能跑吗、README 有吗、提交历史像不像长期维护、测试在不在——**这 30 秒的决定性因素，正是本体系九大类的全部内容**；**深挖（面试）**——从简历句子问原理（Level1-3 已备好弹药）。三个阶段的共性：**筛选者只相信"可验证的事实"**——"精通 Python"没人信，"pytest 覆盖率 70%、CI 强制"一验便知。**本体系的全部价值：把简历上的每一个形容词，替换成可验证的事实**。

## 6. 硬性要求全景：九大类

九大硬性要求按"筛选者验证的先后"排序（第一印象顺序）：**① 环境可复现**（能不能跑）；**② 依赖规范**（跑得稳不稳）；**③ 代码规范**（代码像不像工程）；**④ 结构分层**（有没有设计感）；**⑤ 配置密钥**（安不安全）；**⑥ Git 协作**（有没有工程纪律）；**⑦ 测试**（可不可信）；**⑧ 文档**（能不能快速理解）；**⑨ 可运行维护**（是不是完整产品形态）。**九类的权重不同**：① ⑥ ⑧ 是第一印象（决定 30 秒去留）；③ ⑦ 是专业度证据（决定"像不像工程师"）；② ④ ⑤ ⑨ 是深度证据（决定深挖时的底细）。**达标策略**：前六类每个项目都要过（成本低、见效快），⑦ ⑧ ⑨ 是区分度（大多数人没有，你有就是差异）。**九类与三级体系的对照表**（本体系是验收、Level1-3 是生产——引用关系一目了然）：环境/依赖 ↔ Level2 02（uv 工程化）；代码规范/结构 ↔ Level2 02（ruff/mypy/分层）；配置密钥 ↔ Level2 02 + Level1 01（.env 与预案）；Git/CI ↔ Level2 02/09；测试 ↔ Level2 07；文档 ↔ Level2 10（答辩稿/调优记录）；可运行维护 ↔ Level2 08/09 + Level3 07/09。**与「项目避坑（校招高频踩坑点）」的关系**：那边是"坑长什么样"，本体系是"标准是什么"——遇到坑对照标准修，两条路线互补使用。

## 7. 使用建议

每个模块的结构一致：**筛选者看什么 → 硬性标准 → 项目怎么做（对应 Level1-3 产物）→ 自查清单**。使用方式：**对照检查而非通读**——拿自己的项目逐条核对，达标勾掉，不达标的记下行动项（本体系的产出不是知识，是"待办清单"）。**与三级体系的引用关系**：本体系大量引用 Level2/3 的产物（锁文件、测试、Dockerfile 等）——没做项目的先回 Level1-3，本体系是"验收"不是"教学"；做完项目再对照本体系，你会发现"大部分已经在做了，缺的是把散落的事实整理成简历语言"。

**适用项目类型**（本体系的检查对象）：主推简历的**主力项目**（Python AI 方向——KBQA 类完整项目）必须九类全过；**辅助项目**（课程作业、练手 Demo）过前六类即可（区分度项留给主力项目）；**未完成项目**（做到一半）不占简历位置——**"未完成"比"小但完整"减分得多**——本体系的检查同时是"项目该收尾了"的信号，每个项目问一句"它够格进简历吗"，不够就继续做或放弃——**"放弃不达标的项目"和"做完达标项目"一样是判断力**。

> 🎯 **核心要点**：工程硬性要求的本质是**"把简历从形容词堆砌变成可验证事实"**——能跑、能读、有测试、有文档、有纪律，每一项都是筛选者 30 秒内可验证的。九大类的达标不是为别人做的，是"项目真的能交接"的最低标准——达标即提交，是进入面试阶段的最后一公里。
