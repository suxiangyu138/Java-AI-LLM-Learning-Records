# 08 文档硬性要求

> 第八项硬性要求：**README 三件套、API 文档、部署文档、调优记录**——文档是筛选者理解项目的第一入口（30 秒内决定去留），也是"可交接"的证明。AI 项目还要多一层：评估与调优的过程文档。

## 1. 筛选者看什么

文档是筛选者 30 秒决策的主要材料：**README 第一屏**（项目简介 + 快速开始——10 秒内判断"这是什么、能不能跑"——第一屏信息缺失 = 扣分）；**文档的"读者感"**（文档是写给陌生人看的还是写给自己的——"我项目结构是……"（自述式）vs "快速开始：第一步……"（读者式）——**读者感是文档专业度的分水岭**）；**文档与代码的一致性**（README 说 `uv sync` 但项目没有 uv.lock——文档漂移（Level2 09 的坑）比没有文档更减分）；**AI 项目特有的检查**（有没有调优记录/评估报告——**"检索升级后 NDCG 提升 15 分"这类过程文档是 AI 项目简历叙事的实体支撑**（Level2 06/10 已实践）。**筛选者的潜台词**："**这个项目的知识有没有沉淀**"——代码是结果，文档是过程——**只有结果没有过程 = 作业；结果 + 过程 = 工程**。

## 2. 硬性标准：四类文档、可交接

文档的硬性标准：**四类齐全**——README（门面：简介 + 快速开始 + 环境）、API 文档（接口契约）、部署文档（怎么上线）、调优记录（决策与数据——AI 项目特有）；**可交接**（验收线："明天把项目交给陌生人，他能独立接手吗"——README 能跑、API 能调、部署能上、调优能接续——**"可交接"是文档的终极检验**（Level2 01 的立项文档检验题同源）。**"四类"不是越多越好**：文档贵在"够用且维护得起"——四类之外的文档（会议纪要式废话）是负债（要维护）；**文档与代码同步**（改代码必改相关文档——"文档漂移"是比没文档更差的状态（Level2 09 的教训）。**衡量方法**：陌生人测试（找人按文档独立走完"跑起来 + 调一个接口"）；一致性抽查（README 命令与项目实际命令对比）。

## 3. README：门面的黄金三件套

README 的黄金三件套（第一屏就要齐）：**项目简介**（一句话定位 + 2-3 句能力说明 + 架构图（可选但加分）——"一句话说清做什么"是筛选者第一需求）；**快速开始**（环境要求 → 安装命令 → 启动命令 → 验证方法——**每一行都是可复制的命令**（01 篇的四问覆盖：装/起/配/要）；**目录结构**（可选但推荐——顶部目录树让筛选者 10 秒理解结构）。**README 的进阶内容**（按项目阶段加）：**功能截图/GIF**（对话界面截图——AI 项目最直观的证明——**"一图胜千言"，README 有界面截图的项目，真实感直接拉满**）；**技术栈徽章**（Python/框架/CI 徽章行——一眼看到技术线）；**亮点列表**（"混合检索 + 重排 + RAGAS 评估"3-5 条——引导面试官问你想被问的）。**README 的检验**：**电梯测试**——"一个完全不了解项目的人，读 README 3 分钟，能否复述项目做什么 + 怎么跑"——不能就是 README 不合格。

## 4. API 文档与部署文档

**API 文档**（接口契约的沉淀，2026 年 AI 项目自动生成 + 人工补充）：**自动生成优先**（FastAPI 的 /docs（Swagger）自动生成——"契约即文档"（Level2 03 已实践）——README 写明"接口文档见 /docs"）；**人工补充关键接口的示例**（对话接口的请求/响应示例、流式的 SSE 格式示例——README 或 docs/api.md 放 2-3 个最核心接口的 curl 示例——**"面试官现场 curl 一下"是 API 文档被验证的场景**）。**部署文档**（怎么上线：Docker 部署（compose 命令 + 环境变量清单 + 健康检查方式——Level2 09）；K8s（Level3 09 的话术：helm install 命令 + 配置说明）；回滚与排错（部署文档的"应急段"——回滚命令 + 常见故障排查路径——**"部署文档含排错段"是专业部署文档的标志**）。**两类文档的检验**：API——`curl` 按文档示例能调通；部署——新机器按文档 15 分钟起服务（01 篇的复现标准延伸）。

## 5. 调优记录：AI 项目的独特资产

AI 项目的文档独特性在于**过程文档**（传统项目少有，AI 项目必须有——因为 AI 效果的改进靠"参数-实验-结论"循环）：**调优记录**（每次改动：改了什么参数、评估结果如何、结论是什么——Level2 06 的调优记录格式）；**评估报告**（基线 vs 优化后的指标对比表——"混合检索 + 重排使 NDCG@10 提升 15-25 分"（Level3 02 的量化叙事）；**决策记录**（选型决策与边界——"为什么 SQLite 不换 PG""为什么单 Agent 不拆多 Agent"——**决策记录是面试"为什么"答案的存档**（Level2 01 的选型决策树实践）。**调优记录的筛选价值**：它是"简历数字"的出处——"忠实度 0.85、覆盖率 70%、成本降 60%"这些数字在 docs/ 里都有过程支撑——**面试官问"这个数字怎么来的"，你翻开记录就能讲**。**AI 项目文档的完整形态**（docs/ 目录）：立项、调优记录、评估报告、部署文档、答辩稿（Level2 10 已实践）——五件套齐了，项目是"有记忆的工程"。

**文档的反例对照**（写文档时的"别这样"清单）：**自述式文档**（"我用了……我觉得……"——文档的读者是陌生人不是自己，读者式句式（"快速开始：第一步……"）才对）；**空壳文档**（README 只有标题没有内容——比没有 README 更减分，"敷衍"是筛选者能读出来的）；**过期文档**（命令已失效——文档漂移（Level2 09 的坑）——**"文档更新的时点"是改代码的那一刻**，不是"有空再说"；**术语堆砌**（满屏"高并发、分布式、AI 驱动"没有实际内容——**文档的价值在"可执行的具体"不在"炫目的形容词"**。**文档写作的产出纪律**：每个文档问一句"读者要做什么"（跑起来？调接口？部署？接续调优？）——**按读者动作组织文档结构**，比按"我想写什么"组织专业得多。

## 6. 自查清单

- [ ] README 第一屏：简介 + 快速开始 + 环境要求（电梯测试通过）
- [ ] README 有界面截图或架构图（AI 项目强烈建议）
- [ ] README 有技术栈与亮点列表
- [ ] 接口文档可用（/docs 自动生成，核心接口有 curl 示例）
- [ ] 部署文档完整（compose/helm 命令 + 环境变量 + 健康检查 + 回滚 + 排错段）
- [ ] docs/ 有调优记录（参数-实验-结论格式）与评估报告
- [ ] 决策记录在案（选型与边界，"为什么"有存档）
- [ ] 文档与代码一致（命令可执行、结构未漂移）
- [ ] **验证实验**：陌生人按文档独立走通"跑起来 + 调一个接口 + 讲出项目做什么"

**达标标准**：四类齐全 + 可交接验证通过。文档是九项里"投入产出比最高"的一项——**README 花 2 小时，换来筛选阶段的全部第一印象**。

**文档的面试叙事**（把"有文档"讲成"有工程素养"）：**"我的项目文档四件套"**（README 三件套 + API 文档 + 部署文档 + 调优记录——每类一句话说明读者与用途）；**"文档即交接"**（"我按'明天把项目交给陌生人'的标准写文档——README 能跑、部署能上、调优能接续"——**"可交接"是文档意识的最高表达**（Level2 01 的检验题）；**"过程文档是数字的出处"**（"简历上的忠实度 0.85、覆盖率 70% 在 docs/ 都有评估报告支撑"——**数字有出处 = 可信**（Level3 10 的纪律）。**文档的隐性价值**：它是面试"为什么"的存档——调优记录回答"为什么这么选参数"、决策记录回答"为什么不上 X"——**文档写得好，面试答得稳**。

> 🎯 **核心要点**：文档的硬性标准是"**四类齐全、可交接、与代码同步**"——README 定门面、API 定契约、部署定上线、调优定过程。AI 项目的过程文档（调优记录与评估报告）是简历数字的存档——**文档不只是给别人看的，是给未来的你（和面试时你）留的证据**。
