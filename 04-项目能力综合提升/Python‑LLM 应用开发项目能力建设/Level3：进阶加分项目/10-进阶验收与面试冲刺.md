## 1. 加分项验收清单

逐项核对（做过的才打勾，每项都有真实产物支撑）：

- [ ] 多 Agent：Supervisor 架构图 + 单/多 Agent 对比数据（01 篇）
- [ ] Agentic RAG：检索自愈 + 自检闭环，失败问题集提升数据（02 篇）
- [ ] 成本优化：缓存命中率、成本对比表（降 X%），质量未回退（03 篇）
- [ ] 高并发：压测报告（基线/优化两轮，QPS、P95），至少一个瓶颈定位（04 篇）
- [ ] Redis：缓存/会话共享/分布式限流三件事 + 多 worker 验证（05 篇）
- [ ] 数据升级：PostgreSQL + Milvus 迁移报告 + 规模验证数字（06 篇）
- [ ] 可观测全家桶：Grafana 仪表盘可用、故障演练定位成功（07 篇）
- [ ] 多租户：隔离实验通过（B 用户见不到 A 数据）、计费报表（08 篇）
- [ ] K8s：清单 + Helm + HPA 伸缩演示 + 自愈演示（09 篇）
- [ ] 文档：加分项全部记录进 docs/，答辩稿与简历同步更新（10 篇）

**验收原则**：每个勾背后必须是"可演示、有数字"的产物——"做了多 Agent"和"多 Agent 路由准确率 94%、对比单 Agent 提升 X%"在面试里的分量天差地别。

## 2. 简历升级：从"做了"到"做成了什么"

简历的黄金句式：**"我用了 X，解决了 Y，效果是 Z（数字）"**。把三级项目合成一个"项目块"升级简历（每条都有真实产物支撑）：

**项目标题建议**："企业知识库智能问答系统（多 Agent + RAG）"——关键词密度（FastAPI、LangGraph、多 Agent、Milvus、K8s）让 HR 筛选与面试官预读都命中。

**要点清单（5-6 条，每条约 15-20 字 + 数字）**：① 架构：FastAPI 服务 + LangGraph 多 Agent 编排（Supervisor 模式），路由准确率约 94%；② 检索：混合检索 + 交叉编码器重排 + Agentic 自愈，评估集忠实度从 X 提升到 Y；③ 成本：prompt caching + 响应缓存 + 小模型路由，单问题成本降 Z%；④ 工程：pytest 覆盖率 70% 门禁进 CI、OTel + Prometheus + Grafana 可观测、SLO 管理；⑤ 部署：Docker Compose → Helm + K8s（HPA 自动伸缩），滚动发布无中断；⑥ 产品化：JWT 认证 + 租户隔离（数据层与检索层双重强制）+ 用量计费。

**简历红线**：**每个数字都能讲出出处**（评估报告/压测报告/成本埋点）——讲不出来的数字是简历事故；**不写没做过的**（面试深挖必露馅——"诚实 + 少写 + 能深挖"远胜"全写 + 挖不动"）。

## 3. 面试深挖题库：20 问与答题范式

面试冲刺的核心材料——按模块归类的高频追问（答案都在各篇的"为什么"段落里，这里列题与范式）：

**多 Agent（01）**：为什么拆多 Agent？Supervisor 与 Swarm 怎么选？路由准确率怎么测的？worker 间状态怎么传？多 Agent 成本翻几倍怎么控？→ 范式：**"场景 → 我的方案 → 数据 → 取舍"**（"文档问答场景多类问题混杂，我用 Supervisor 集中路由，30 个混合问题测试路由准确率 94%，成本用 flash/pro 分级压住"）。

**Agentic RAG（02）**：怎么判断检索失败？改写重试几轮？多跳怎么实现？自检用什么模型？Agentic 比线性贵多少？→ 范式：**"信号 → 动作 → 边界"**（"空结果或分数低触发改写，最多 2 轮，评估集失败问题自愈成功率 X%"）。

**成本优化（03）**：缓存命中率多少？怎么保证前缀稳定？为什么用分级模型？本地模型为什么不上？→ 范式：**"机制 → 设计 → 数字"**（"prompt caching 命中缓存按 1/50 计费，前缀固定顺序 + 动态内容放尾部，命中率 80%+，成本降 60%"）。

**高并发（04）**：压测怎么做的？P95 多少？瓶颈怎么定位的？扩 worker 要注意什么？→ 范式：**"基线 → 解剖 → 优化"**（"locust 分级压测，延迟解剖发现检索占大头，重排批量化后 P95 从 X 到 Y"）。

**Redis/数据（05/06）**：为什么引入 Redis？缓存与数据库一致性怎么保证？为什么 Milvus 不继续用 Chroma？迁移怎么不停机？→ 范式：**"触发信号 → 方案 → 验证"**。

**可观测/产品化（07/08）**：全家桶每个组件干嘛的？trace 怎么串？租户隔离怎么做？越权怎么防？→ 范式：**"组件分工 → 落地细节 → 验证实验"**。

**K8s（09）**：Compose 和 K8s 怎么选？探针三件套？HPA 怎么配的？发布策略？→ 范式：**"边界 → 清单 → 演示"**。

**通用终局问**："这个项目你最骄傲/最遗憾的是什么？"→ 最骄傲选一个**有数字的差异化点**（"检索升级用数据证明"），最遗憾选一个**记录过的边界**（"多租户当时用共享库方案，物理隔离留待数据敏感客户"）——"有数字的骄傲 + 有思考的遗憾"是满分结构。

**答题的三个通用心法**（贯穿全部 20 问）：**先说结论再说过程**（"我做了分级通道——简单问题走线性、复杂走 Agentic——效果是成本只增 30% 拿到深问题质量提升"，而不是从第一天开始讲故事）；**承认边界不装全知**（"这部分我当时评估过，单进程方案够用，多机方案在 Level3 之外的演进路径"——诚实 + 有思考，比硬撑专业）；**每个数字都有出处**（评估报告/压测报告/成本埋点——"数字"是面试里最稀缺的信任资产，随口说的数字会变成追问的靶子）。

## 4. 三层能力的面试叙事

三个 Level 串成一条完整的能力叙事线（面试自我介绍的项目部分，60-90 秒）：**Level1 是"我理解原理"**（手写过模型调用、RAG、工具循环——"我懂每一步在做什么"）；**Level2 是"我能工程化"**（服务化、持久化、测试、可观测、部署——"我能交付可上线的系统"）；**Level3 是"我能差异化"**（多 Agent、Agentic、成本优化、云原生——"我能解决别人没解决的问题"）。**叙事模板**："我从零搭过一个知识库问答系统——先手写理解原理，再工程化到可部署，最后做多 Agent 编排与成本优化；系统现在支持多租户、自动伸缩、评估驱动的检索迭代——每个环节都有测试和数据支撑。"**叙事的三个红线**：不背稿（按"原理→工程→差异化"讲自己的真实经历）；不夸大（每个数字可溯源）；不跳层（"我直接做了多 Agent"没有前两层支撑是空中楼阁——**这也是 Level3 为什么必须排在 Level2 之后的原因**）。

## 5. 毕业检查单与双栈衔接

Level3 毕业检查单：**加分项**至少完成 2-3 项（01/02 必做，其余按方向选）；**文档**完整（docs/ 含调优记录、迁移报告、压测报告、SLO、答辩稿）；**简历**升级完毕且每条可深挖；**面试题库**过一遍（20 问能答出"场景→方案→数字→取舍"结构）。

**双栈衔接**（Python 三级完成后的下一步）：**「双栈联合实战」**目录——把 Python 侧（本能力建设全部三级）与 Java 侧（Java-AI 能力建设三级）拼成完整项目：Python 侧负责 AI 能力（多 Agent/RAG/评估），Java 侧负责业务底座（用户/订单/后台），接口契约在 03 篇已预留——**双栈完成后，"AI 场景实现 + 后端工程"的双引擎履历成形，这是校招最稀缺的组合**。**秋招衔接**：面试考察点目录（04 层的「面试考察点（项目会被深挖）」）与「05-综合输出-面试冲刺」体系的题库——本层 20 问是项目侧的深挖题，那边是知识侧的广度题，两者互补，**面试前把两边过一遍**。

> 🎯 **核心要点**：Level3 的毕业标志是**"差异化能力 + 可深挖的数字 + 完整的叙事"**——加分项有产物、简历有数字、面试能讲透。三个 Level 走完，你手里的不只是一个项目，而是一条"原理→工程→差异化"的完整能力链——这在 2026 年的 AI 岗位竞争里，就是"稀缺"二字的实体。
