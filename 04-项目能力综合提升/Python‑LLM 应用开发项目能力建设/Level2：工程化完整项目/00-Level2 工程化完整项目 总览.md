## 3. 学习路线推荐

**标准路径（3-4 周，每天 1-2 小时）**：按 01→10 顺序推进，每篇 2-3 天。01-02 是设计与规范（快读，跟着做目录与配置文件）；03-04 是核心服务改造（重点，代码量最大）；05-06 是 AI 深度（与仓库「主流 Agent 范式」「RAG 拓展优化深化」对照读）；07-09 是工程三件套（测试/可观测/部署）；10 是收尾验收。

**加速路径（Level1 完成度高，2 周）**：01-02 半天过；03-04 一周；05-06 合并一周（框架化与检索升级互为配套）；07-09 一周；10 半天。

**查漏路径（面试冲刺）**：只做 06 与 10——检索升级（简历必讲）与验收（面试必答），其余回仓库对应体系补知识。

**每日节奏建议**：与 Level1 不同，Level2 每个模块产出的是"工程产物"（配置文件、测试用例、Dockerfile），每天以"一个可验证的产物"收尾（今天跑通 pytest、今天容器启动）。**工程化阶段的验收标准是"机器验证"**——测试过了、容器起来了、监控有数据了，比"我理解了"更硬核。**卡住时的资源顺序**：先查本层对应模块的"常见坑"→ 再查仓库「Python 异步 + FastAPI」的集成避坑篇 → 再按 09 篇的部署排错流程走 → 最后才搜网络（提问时带上 trace_id 与日志原文，别人才能帮你定位）。

## 5. Level2 在能力建设中的定位

三级结构的逻辑是**递进收口**：Level1 用最小成本验证"全链路能跑通"；Level2 把链路做成**简历核心项目**——生产级规范、测试保障、可观测、可部署，每一点都是面试深挖的素材；Level3 在项目上叠加高并发、多 Agent、推理优化等加分项。Level2 与 Level1 的根本区别是**验收标准变了**：Level1 验收"能跑"，Level2 验收"能上线"——测试覆盖、错误处理、配置管理、部署脚本，缺一个都不能算完成。

与仓库其他体系的关系：本层是它们的**集成落地层**——「Python 异步 + FastAPI」体系讲 FastAPI 全栈原理（本层 03 篇是它的项目实战）；「主流 Agent 范式」「Agent 开发」讲 Agent 模式（05 篇的 LangGraph 是它的工程实现）；「RAG 拓展优化深化」讲检索进化（06 篇的混合检索/重排序是它的落地）；「CI CD灰度发布」「Docker」体系讲工程化（07-09 篇是它们的 Python 项目实践）。**面试被深挖时，从本层项目出发，往这些体系里找原理答案**。

与「Java‑AI 后端项目能力建设」的对称关系：Java 侧 Level2 是同一项目的 Java 实现（Spring Boot + Spring AI + MySQL + Milvus + RabbitMQ 栈）。两套做完后，Python 侧的 FastAPI 服务与 Java 侧的业务底座在「双栈联合实战」里对接——本层的 API 设计（03 篇）会预留对接契约，两边数据模型在 04 篇对齐。

**两套 Level2 的分工取舍**：Java 侧重"后端业务底座 + 中间件全家桶"（Redis、MQ、微服务），Python 侧重"AI 能力深度 + 快速迭代"（检索优化、编排、评估）。精力有限的优先做本层——AI 项目的简历竞争力集中在检索与编排（06/05 篇），中间件能力靠 Java 侧的 Level2 与仓库「Redis」「消息队列理论与实战」体系补齐。双栈都做时，本层的 06/08 篇成果（评估报告、可观测实践）可以直接迁移到 Java 项目复用，反之亦然——这就是两套体系的"组件级互换"价值。

## 6. 项目全貌与交付物

本层项目名建议：**KBQA 知识库问答助手**（知识库问答 + 对话记忆 + 可插拔检索）。交付物清单：**代码**（FastAPI 服务 + LangGraph 编排 + 检索组件，约 2000-3000 行，Git 管理）；**测试**（单元 + 接口测试，覆盖率 ≥ 70%）；**文档**（README、API 文档、部署文档、调优记录）；**部署产物**（Dockerfile + docker-compose.yml，一键启动）；**评估产物**（评估集 + RAGAS 报告，检索升级前后的指标对比表）。

项目在简历上的表述建议：**"Python 企业知识库问答系统：FastAPI + LangGraph + 混合检索架构，支持对话记忆、流式输出、一键 Docker 部署；RAGAS 评估显示混合检索 + 重排序使检索质量提升 XX%"**——每句话都对应本层一个模块，面试官从任意一句深挖都有内容可讲。

## 7. 使用建议

每个模块的结构一致：**目标 → 前置 → 设计 → 实现 → 验证 → 常见坑**。与 Level1 不同，本层建议"边读边写"：每篇的代码直接落到你的项目目录，读完全篇项目就推进一个里程碑。遇到问题先查 09 篇的部署排错与仓库「Python 异步 + FastAPI」的避坑篇。**坚持"机器验证"习惯**：每篇的"验证"小节必须真实执行（跑测试、起容器、查日志），不要"看着对就行"——Level2 的面试素材全部来自这些真实执行的结果。

**学习期间的工程日志**（比笔记更重要的记录）：每天结束时记三行——今天完成了什么（可验证产物）、卡在哪里（问题与解决路径）、明天做什么。工程日志的价值：**它是答辩"失败与修复"章节的第一手素材**（"评估集第一次低分，日志显示是分块问题"这类真实过程都从日志里来）；**它是进度感的来源**（回看一周的日志，项目从骨架长到部署，这种正反馈支撑 3-4 周的长周期投入）。

> 🎯 **核心要点**：Level2 的唯一目标是**交付一个可上线、可讲解、可深挖的完整项目**。工程规范、测试、可观测、部署不是"加分项"而是"验收项"——它们共同构成了"简历核心项目"与"跑通 Demo"之间的全部距离。
