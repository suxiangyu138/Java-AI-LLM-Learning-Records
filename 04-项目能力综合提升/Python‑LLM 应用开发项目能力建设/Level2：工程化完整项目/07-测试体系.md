## 1. 目标与验收

本模块的产出：tests/ 目录下单元 + 接口测试（30-50 个用例），覆盖率 ≥ 70%，`uv run pytest` 一条命令全绿。验收标准：**改坏一处逻辑，测试能当场报红**（保险丝有效）；**测试不依赖真实 API Key**（mock 到位，CI 无密钥可跑）；**能讲清三层测试各自防什么**。版本基线（2026-08）：pytest 9.1、pytest-asyncio 1.3+、pytest-cov 7.1、httpx（TestClient 依赖）。

## 2. 测试策略：三层测试金字塔

测试不是"越多越好"，是按成本与价值分层：**单元测试**（最多、最快）——测单个函数/组件，mock 掉外部依赖，毫秒级；**接口测试**（中等）——TestClient 打真实路由，验证契约（请求校验、错误格式、SSE 格式），秒级；**评估测试**（少量、最慢）——RAGAS 评估集跑真实链路，分钟级（06 篇，进 CI 的门禁层）。三层对应防什么：单元防"逻辑错"、接口防"契约破"、评估防"质量回退"。**测试金字塔的形状是纪律**：全堆接口测试会慢到没人跑，全堆单元测试会漏契约破——本模块重点在前两层，评估层在 06 篇已建。

## 3. 单元测试：mock LLM 的三种姿势

LLM 是测试里最该 mock 的依赖（真实调用慢、花钱、结果不确定）。三种姿势按需选：**① monkeypatch 替换 client**（最简单——把 OpenAI client 换成返回固定值的假对象）；**② 依赖注入替换**（03 篇的 Depends 在这里兑现——get_chat_service 返回 Mock 版服务）；**③ pytest fixture 构造假数据**（造 messages/context 直接喂函数）。示例：

```python
# tests/unit/test_retrieve.py
import pytest
from app.rag.retrieve import hybrid_search, rerank

def test_hybrid_search_merges_two_sources(monkeypatch):
    monkeypatch.setattr("app.rag.retrieve.embed", lambda t: [[0.1] * 64])
    monkeypatch.setattr("app.rag.retrieve.bm25_index", FakeBM25())   # 假 BM25
    hits = hybrid_search("RNN 是什么", top_k=10)
    assert len(hits) >= 1                    # 融合后至少有条目
    assert isinstance(hits[0][1], float)     # RRF 分数是 float

def test_rerank_orders_by_cross_encoder_score(monkeypatch):
    monkeypatch.setattr("app.rag.retrieve.reranker",
                        lambda pairs: [0.9, 0.3, 0.7])
    result = rerank("q", [("doc1", 1.0), ("doc2", 2.0), ("doc3", 3.0)])
    assert result == ["doc1", "doc3", "doc2"]   # 按重排分数排序，非原序
```

单元测试的三个规范：**只测"自己的逻辑"**（RRF 融合算法、排序逻辑、分块函数——不测 OpenAI 的行为）；**断言行为而非实现**（测输出值，不测"调了几次 mock"这种实现细节）；**命名即文档**（test_检索_融合两份结果——失败时名字告诉你哪坏了）。分块、配置校验、消息裁剪这类纯函数是单元测试的甜区，尽量覆盖满。

LLM 调用点的 mock 形态（最容易写错的单元测试，单独说明）：mock 的对象是"SDK 的响应链"——`client.chat.completions.create` 的返回值要有完整的 choices/delta 结构，否则被测代码取字段时崩出 AttributeError（mock 假得不够"真"）：

```python
def test_chat_service_builds_messages_with_history(monkeypatch):
    calls: list[dict] = []

    class FakeResp:
        class Choice:
            message = type("M", (), {"content": "回答"})()
        choices = [Choice]

    def fake_create(**kwargs):
        calls.append(kwargs)
        return FakeResp()

    monkeypatch.setattr("app.services.chat_service.client.chat.completions",
                        type("C", (), {"create": staticmethod(fake_create)})())
    result = chat_service.ask("s1", "你好")
    assert result == "回答"
    sent = calls[0]["messages"]
    assert sent[0]["role"] == "system"          # 断言发出去的 messages 结构
    assert sent[-1]["content"] == "你好"
```

这个例子的两个要点：**mock 返回结构要匹配真实响应**（choices[0].message.content 能取到）；**断言"发给模型的 messages 长什么样"**——上下文组装是否正确（system 首条、历史在中间、问题在末尾）是对话类测试的核心断言点，比断言"回答内容"更有价值。

## 4. 接口测试：TestClient 全链路

接口测试打真实路由（含依赖注入、校验、错误契约），不启动真实服务——用 FastAPI 的 TestClient（httpx 实现）：

```python
# tests/api/test_chat.py
from fastapi.testclient import TestClient
from app.main import app

client = TestClient(app)

def test_chat_happy_path(monkeypatch):
    monkeypatch.setattr("app.services.chat_service.ChatService.ask",
                        lambda self, sid, q: ("回答内容", ["doc1"]))
    resp = client.post("/api/chat", json={"session_id": "s1", "question": "你好"})
    assert resp.status_code == 200
    body = resp.json()
    assert body["answer"] == "回答内容"
    assert body["citations"] == ["doc1"]

def test_chat_rejects_empty_question():
    resp = client.post("/api/chat", json={"session_id": "s1", "question": ""})
    assert resp.status_code == 422              # Pydantic 校验生效

def test_chat_unknown_session_returns_error_contract():
    resp = client.post("/api/chat", json={"session_id": "nope", "question": "hi"})
    assert resp.status_code == 404
    assert "code" in resp.json()                # 错误契约字段（03 篇）
```

接口测试的清单式覆盖：**每个接口的 happy path**（200 + 响应体字段）；**每个校验规则的违反**（422）；**每个业务错误的契约**（404/400 + code 字段）；**SSE 接口的流式格式**（resp.iter_lines 断言 `data: ` 前缀与 [DONE] 结尾）。SSE 的测试形态（流式接口最容易测错的地方）：

```python
def test_chat_stream_sse_format(monkeypatch):
    async def fake_stream(sid, q):
        yield "你"; yield "好"; yield "[DONE]"
    monkeypatch.setattr(chat_service.ChatService, "ask_stream", fake_stream)
    with client.stream("POST", "/api/chat/stream",
                       json={"session_id": "s1", "question": "hi"}) as resp:
        lines = [l.decode() for l in resp.iter_lines() if l]
    assert lines == ["data: 你", "data: 好", "data: [DONE]"]   # SSE 协议格式
```

测试异步接口用 `pytest-asyncio`（pyproject.toml 配 `asyncio_mode = "auto"`）+ `httpx.AsyncClient`（ASGITransport）。**接口测试是契约的守护者**——03 篇改字段忘改 response_model，接口测试当场报红。

## 5. 测试隔离：数据库与数据目录

测试最怕"互相污染"：用过的库、建过的 Chroma 目录会串测试结果。隔离三件套：**测试专用数据库**——fixture 里用内存 SQLite（`sqlite+aiosqlite:///:memory:`，每个测试新建引擎建表，teardown dispose）；**临时数据目录**——Chroma 与文件读写指向 tmp_path（pytest 内置，每个测试独立临时目录）；**依赖覆盖**——配置模型在测试里重载（settings.db_url 指向内存库），确保被测代码不碰生产 data/：

```python
# tests/conftest.py
import pytest
from app.repository import db
from sqlmodel import SQLModel

@pytest.fixture(autouse=True)
async def clean_db():
    db.engine = db.create_test_engine()          # 内存库引擎
    async with db.engine.begin() as conn:
        await conn.run_sync(SQLModel.metadata.create_all)
    yield
    await db.engine.dispose()                    # 测试结束销毁
```

两条纪律：**绝不连生产库/真实 API**（测试代码里出现真实 Key 就是事故——CI 无密钥可跑是硬要求）；**fixture 职责单一**（一个 fixture 只做一件事，组合用，不写巨型 setup）。

## 6. 数据工厂

测试的数据工厂（fixture 的进阶）：接口测试里"造一条会话 + 三条消息"这类数据准备重复度高——写成工厂 fixture，一处定义多处用：

```python
# tests/factories.py
async def make_session_with_messages(db, session_key="s1", n=3):
    session = await get_or_create_session(db, session_key)
    for i in range(n):
        await save_message(db, session.id, "user" if i % 2 == 0 else "assistant",
                           f"测试消息 {i}")
    return session
```

工厂的价值：**测试数据与测试逻辑分离**（改数据形状只动工厂）、**用例可读**（"造一个带 3 条消息的会话"一句话）、**复用**（单元与接口测试共用）。fixture 体系的完整形态：conftest.py（引擎/会话）、factories.py（业务数据）、每个测试文件按需组合——**三层递进，不写巨型 fixture**。

## 7. 覆盖率门禁与 CI 联动



覆盖率是"测试有没有漏"的粗尺子，门禁标准：**单元 + 接口合并 ≥ 70%**（关键路径——检索、对话编排、错误处理——要 ≥ 85%）。配置与运行：

```toml
[tool.pytest.ini_options]
asyncio_mode = "auto"
testpaths = ["tests"]
addopts = "-q --cov=app --cov-report=term-missing --cov-fail-under=70"
```

```bash
uv run pytest                # 一条命令：跑测试 + 覆盖率门禁
```

**CI 联动**（09 篇的 pipeline 里接上）：每次 push 自动跑 `uv run pytest`，覆盖率低于 70% 或任一用例失败 → 流水线红 → 阻断合并。至此"机器验证"闭环：本地跑、CI 跑、评估门禁跑。**面试讲测试的完整话术**："pytest 9 三层测试体系，单元 mock LLM、接口 TestClient 验契约、RAGAS 评估集防质量回退，覆盖率 70% 门禁接入 CI，每次改动全量回归"——每一句都有真实产物对应。

## 8. 常见坑

**测试依赖真实网络**：测试里调了真实模型/下载模型——所有外部调用必须 mock，CI 环境无密钥也要全绿。

**共享状态泄漏**：fixture 里的数据被多个测试改——每个测试独立数据库（第 5 节），不要图省事共用一个 session。

**只测 happy path**：错误路径（404/422/异常）是接口测试的一半价值——错误契约没测等于契约没写。

**断言过弱**：只断言 status_code 不断言 body——契约测试必须断言响应体字段。

**异步测试忘配**：async 测试报 "no event loop"——pyproject.toml 的 asyncio_mode="auto" 配好，fixture 用 async 定义。

**测试与实现耦合过深**：mock 到内部实现细节（如 mock 了对象内部属性），重构即崩——mock 边界在"外部依赖接口"上，不在"内部实现"上。

**SSE 测试挂起**：client.stream 响应没读完就结束——流式测试必须消费完整响应（iter_lines 读完）再断言，用 `with client.stream(...)` 上下文确保关闭。

**评估类测试太慢**：RAGAS 评估（分钟级）混进单元测试——评估独立目录（tests/eval/）与 `pytest -m "not eval"` 标记分流：常规测试秒级、评估测试单独跑（CI 里评估作为独立 job，09 篇）。

**测试时间随项目膨胀**：每加一个接口测试 +5 秒，几个月后 pytest 变慢跑不动——定期"测试速度审计"（pytest --durations=10 看最慢的 10 个），慢的优化（减少重复 setup、合并断言）；**测试也是代码**，同样要维护——被废弃的测试及时删，注释过时的更新，别让测试变成第二个技术债。**测试覆盖率不是目标而是手段**——覆盖率到 70% 后，把精力从"追数字"转向"补关键路径"（错误分支、边界输入），数字会自己涨。

> 🎯 **核心要点**：测试体系的本质是**把"没坏"从感觉变成证明**——单元测逻辑、接口测契约、评估测质量，覆盖率做兜底，CI 做门禁。测试全绿的那一刻，你的项目第一次有了"被证明过"的状态——这是简历"可维护"三个字的硬通货。
