## 1. 验收标准：每个 Demo 过一遍

验收不是"跑通了"，而是**能独立重写、能讲清原理、能复现结果**三合一。逐个核对：

| Demo | 验收要点（能独立做到） |
|---|---|
| 01 环境 | 新电脑 15 分钟复现环境；讲清 uv/pip/venv 关系；.env 不上 Git |
| 02 语法 | 独立写带类型注解的函数；三层异常防护；pathlib 文件读写 |
| 03 模型 | 不看文档写请求体；base_url 带 /v1；多轮对话与流式 |
| 04 Prompt | 三件套提示词；few-shot 示例；JSON 结构化输出防御解析 |
| 05 Streamlit | 三原语组合；讲清 rerun 机制；session_state 用法 |
| 06 RAG | 画五步链路图；负例拒答实验通过；分块参数权衡 |
| 07 工具 | 画调用循环时序图；工具参数 JSON 解析；错误回传 |
| 08 闭环 | 独立重写三文件架构；每行代码讲出来源；调优记录完整 |

验收的进阶动作（时间允许再做）：**换一篇自己熟悉的文档重新入库**（比如课程笔记、面经整理），验证链路不依赖特定数据——如果换了文档后回答变差，往往不是链路问题而是分块/检索参数需要随文档类型调整，记录下来就是一份"参数敏感性"认知。核对方式：每个 Demo 不看文档重写一遍，重写中"卡住想不起来"的环节就是薄弱点——回对应篇复习，直到能连续写完。**重写比复盘有效**：复盘是"看懂别人的代码"，重写才是"自己的理解"。

## 2. 毕业检查单：全链路自检

全部通过才算 Level1 毕业（逐项打勾）：

- [ ] 环境：`uv run main.py` 在任意新目录可跑通；uv.lock 已提交
- [ ] 密钥：API Key 只存在于 .env；.gitignore 包含 .env
- [ ] 模型：curl 验证 Key 一次通过；模型名均为 V4 新命名
- [ ] 界面：`streamlit run app.py` 打开即用；多轮对话上下文连续
- [ ] RAG：正例答对、负例拒答、溯源编号三实验全部通过
- [ ] 工具：模型正确选择工具、参数解析成功、错误回传生效
- [ ] 闭环：上传 → 导入 → 问答全流程无卡点；调优记录 ≥ 3 条实验
- [ ] 排错：09 篇速查表能定位 3 个真实踩过的坑
- [ ] 代码：08 篇三文件分工清晰；每个函数有类型注解与 docstring
- [ ] 理解：能不看文档画出闭环应用的数据流图

检查单的意义：**它是面试深挖的预演**——每个勾背后都是"你亲手做过、能展开讲"的事实。留一项未通过就补一项，不要带病进入 Level2——**Level1 的坑不填平，Level2 会加倍偿还**。

## 3. 答辩三问：讲清你的 Demo

面试官不会让你"讲代码"，而是问三个层次的问题。现在就用这三个问题自测（对着空气讲一遍，卡壳就是薄弱点）：

**一问：为什么这么做？** 为什么用 RAG 而不用微调（知识可增删、可溯源、成本低）；为什么用 Streamlit（Demo 期快速界面，Level2 换 FastAPI 化服务）；为什么本地 embedding（DeepSeek 官方无 embedding 端点、离线可用）。

**二问：哪里会出问题？** 模型幻觉怎么防（提示词约束"未找到"闸门 + 负例测试）；工具参数解析失败怎么办（错误回传让模型修正）；上下文超长怎么办（历史裁剪，Level2 用向量库/摘要系统化）；并发请求怎么办（Level2 的缓存与连接池）。

**三问：还能怎么改进？** 检索质量（混合检索 BM25+向量、重排序）；性能（流式、缓存）；健壮性（限流重试、日志可观测）；产品化（多用户隔离、权限）。**这三个"改进方向"就是 Level2 的施工图**——答辩时说出"我做了 A，知道 B 能更好，Level2 正在做 B"，是校招最亮眼的信号。

## 4. 知识地图：本层与仓库体系的对照

Level1 的每个 Demo 都有对应的体系纵深，面试被追问时按此地图回仓库补课：

| Level1 内容 | 对应知识体系（进阶深潜） |
|---|---|
| 01-02 Python 环境与语法 | 「Python 虚拟环境」「Python 异步 + FastAPI」的 01-Python语言 |
| 03 模型调用 | 「Function Calling 函数调用」的 API 协议篇；DeepSeek 体系 |
| 04 Prompt | 「02-大模型基础与Prompt工程」Prompt 工程篇 |
| 05 Streamlit | 「Python 异步 + FastAPI」的 FastAPI 与 ASGI 篇（工程化对照） |
| 06 RAG | 「RAG 拓展优化深化」（五代演进、GraphRAG、评估） |
| 07 工具调用 | 「Function Calling 函数调用」（调用循环工程、工具设计规范） |
| 08 闭环 | 「主流 Agent 范式」「Agent 开发」（P-A-M-E、patterns） |

理解这张表的意义：**Level1 是"会做"，体系是"懂理"**——面试深挖时从"做了什么"往"原理与边界"上走，答案都在这些体系里。Demo 跑完不代表知识完成，是**学习起点**：带着"我亲手写过"的体感去读体系，吸收率翻倍。

## 5. Level2 预告：从 Demo 到工程化

Level2 的任务一句话：**把 08 篇的闭环应用改造成可上线的工程化项目**（简历核心）。改造方向预览：**技术栈升级**——从"裸 openai SDK + 脚本"升级为 FastAPI 服务（API 层）、Pydantic 数据校验、日志与可观测性（OTel）、单元测试；**引入 LangChain/LangGraph**——用框架管理 RAG 链路与 Agent 循环（本层手写是为了懂原理，Level2 用框架是为了工程效率）；**检索质量升级**——混合检索、重排序、评估集；**部署**——Docker 化、环境配置管理、CI；**产品化**——多用户、权限、对话持久化（SQLite/PostgreSQL）。

进入 Level2 前顺手补齐的前置技能（都是"用到才学"级）：**Git 基本操作**（add/commit/push/分支——本层代码就该用 Git 管理起来，仓库「Git 知识体系」速查即可）；**JSON 与命令行基础**（curl/jq 调试 API，仓库「HTTPie」体系）；**一点 Pydantic**（本层已通过 dataclass 建立了"结构化数据"直觉，Pydantic 是它的升级版，届时看 FastAPI 篇顺手就会）。这些不是门槛，是 Level2 的配菜——带着本层的底感去学，每个都是半天的事。

过渡建议：**现在就把 08 篇代码重构一遍**（拆文件、加类型注解、写 docstring、留调优记录）——这份"重构前的版本"是 Level2 的起点基线，也是面试时"我的代码演进过程"的素材。Level1 到 Level2 之间不需要休息——趁着手感热，直接开工。

## 6. 常见误区与心态

补完检查单后，再对照四个高频误区自省一遍：**误区一"追求工程化"**——Demo 期加单元测试、搞 CI、写类层次结构都是过度投入，Level1 的代码"能跑 + 能讲清"就够了，工程化留给 Level2（那里有测试、部署、可观测性的完整体系）；**误区二"只跑通不复盘"**——跑通只是第一步，每篇的"重写一遍"才是验收，只跑通等于把理解外包给了教程；**误区三"不记录就继续"**——不写调优记录、不写笔记，一个月后 08 篇的代码全忘光，Level2 又从零开始；**误区四"跳过不理解的部分"**——卡住跳过可以，但要标记下来回补，"暂时跳过"和"永远跳过"是两回事，被跳过的部分会原样出现在面试追问里。

心态上记住一句话：**Level1 的价值不在代码，在"亲手做过"的底感**。这份底感让 Level2 的每一课都建立在真实体验之上——看到 FastAPI 文档不慌，因为知道 HTTP 接口是怎么调的；看到 LangChain 不慌，因为知道 RAG 链路每步在做什么。Demo 期慢一点没关系，底感扎实了，Level2 的速度会成倍找回来。

> 🎯 **核心要点**：Level1 的毕业标志不是"8 个 Demo 跑通"，而是**检查单全勾 + 三问能答**。带着"每行代码都能讲出来源"的底气进入 Level2，工程化的每一步都会踩在理解的地基上。
