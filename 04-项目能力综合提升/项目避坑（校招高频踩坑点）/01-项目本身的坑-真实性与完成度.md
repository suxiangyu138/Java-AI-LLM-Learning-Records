# 01 项目本身的坑：真实性与完成度

> 面试失败的根源往往不在面试技巧，而在项目本身：没有真实问题、没有独立设计、没有完整闭环。这一篇先解决"项目立不立得住"的问题。

## 1. 坑一：网课跟做，没有独立设计

**症状**：面试官问"为什么这个模块要这么设计"，回答是"视频里就是这么写的"。2026 年面试官已经换玩法——"你做得最爽的代码片段，讲讲你怎么设计的"，跟着视频敲代码的候选人当场懵住。跟做项目的本质问题不是"代码一样"，而是**你没有做过任何一个决策**：为什么用这个表结构、为什么拆这个方法、为什么选这个框架，全部是别人的答案。

**根因**：把"会写"当成了"会设计"。跟做时大脑处于抄写模式，决策过程被跳过，记忆里只留下代码没有留下理由。面试追问五层——用法、原理、取舍、演进、边界——任何一层越过"视频里教的"就断掉。

**防复发**：跟做可以做，但必须**二创**：视频跑通后，自己重新设计至少三个环节（表结构、缓存策略、异常处理），并把设计决策写进文档。判断标准：把项目文档给同学看，同学问三个"为什么"，你能否当场给出"我选择 X 是因为对比了 Y 和 Z"的回答。给不出，说明这部分的决策不是你的，重做。

## 2. 坑二：伪项目，CRUD 堆砌无真实问题

**症状**：项目名很大（"XX 管理系统"），功能全是增删改查，面试官问"最大的技术挑战是什么"，憋半天说出"数据库表比较多"。伪项目的典型形态：图书管理、学生信息管理、网上商城（无真实业务复杂度）。这类项目在 2026 年的问题是**面试官见得太多了**——同一个模板项目用完全相同的语言描述，无法判断你的角色与学习成果。

**根因**：立项时以"技术清单"为中心（想练 Redis 就加缓存、想练 MQ 就加消息），而不是以"问题"为中心。没有真实问题，就没有难点，没有难点就没有深挖素材，没有深挖素材的项目在行为面试里等于不存在。

**防复发**：立项倒过来——**先找一个真实问题，再找解决它所需的技术**。判别问题是否真实的三条标准：有没有真实用户（哪怕是自己）、有没有状态流转（不是纯展示）、有没有"不做会出事故"的场景（并发扣库存、退款、幂等）。真实问题的反面教材是"加 Redis 缓存"；正面教材是"秒杀时库存超卖怎么防"——后者自带技术深度与叙事素材。仓库「双栈联合实战」体系的立项篇就是按这个标准设计的项目样板。

## 3. 坑三：没上线、无用户、无证据

**症状**：面试官问"项目上线了吗、多少用户、最大技术挑战是什么"（2026 美团项目深度面的标准三问），回答"本地跑通，我自己一个人用"。没有上线经历，压测数据、故障故事、优化对比全部无从谈起——而这些正是深挖面的主战场。

**根因**：把"写完"当"完成"。完成度标准停留在代码层面，缺部署、缺演示、缺证据链。2026 年招聘方已明确表态：简历与回答中"项目上线"与"有真实用户"是强信号，因为它一次性证明了三件事——你解决过真实问题、你经受过线上环境的拷问、你不是只会写 demo。

**防复发**：项目完成度三件套：**部署可访问**（云服务器或 Docker Compose 一键起，给面试官看演示链接或本地录像）、**压测有报告**（JMeter 或自写脚本压核心链路，记录 QPS 与 P99，报告截图进项目文档）、**真实使用痕迹**（哪怕是家人朋友试用，留存对话记录或访问日志）。完成度不是加分项，是深挖面的入场券。

## 4. 坑四：技术堆砌，贪多嚼不烂

**症状**：简历技术栈列 15 个（Spring Cloud、K8s、Flink、ClickHouse、Kafka、ES……），面试官随机挑一个问原理，每个只能答两句。堆砌的动机可以理解——想让简历看起来"技术全"，但效果恰好相反：**面试官会从最长的那串里随机抽一个问，你答不上来，整个简历的可信度崩塌**。

**根因**：把"列了"当"会了"，把"用过"当"深过"。判断标准错误：用过一次 demo 不等于可以写进简历。2026 年 HR 明确提醒"罗列不熟悉的专业技能，面试被深入提问时难以自圆其说"。

**防复发**：写进简历的每个技术栈过一遍**追问红线测试**——能用 3 句话讲清原理、能说出一个真实使用场景、能说出它和替代方案的取舍。三条中任一不过，从简历移除或标注"了解"。合理配置是：核心 3-5 个（能深挖）、支撑 2-3 个（能讲用法）、了解 1-2 个（只提名词）。深度优先于广度，是 2026 年技术校招的共识。

## 5. 坑五：抄项目，只有 README 级理解

**症状**：GitHub 上 clone 一个星标项目，改个名字写成自己的；面试官问细节，回答全靠回忆 README，代码根本翻过不。2026 年面试官专门练过识别：追问"这个模块你写过哪几行""这个 bug 你查了多久"——抄来的项目没有"我写的"记忆，任何细节追问都穿帮。

**根因**：把"有项目"当"有经历"。诚实性原则的底线：简历上的项目必须是自己写过的代码、自己做的决策、自己踩过的坑。造假不仅丢 offer，背调发现后是行业层面的信用问题。

**防复发**：自检方法简单粗暴——**把项目 clone 到新环境，从零跑起来**，能不能在 10 分钟内说清每个模块的代码位置与职责；面试前对自己项目做一次代码走读，把每个核心文件的功能与设计理由过一遍。真做过的项目，讲细节时语速会不自觉地变快；抄来的项目，讲细节时只有重复。面试官听得出来。

## 6. 合格项目的判断标准

| 维度 | 踩坑状态 | 合格状态 |
|---|---|---|
| 问题来源 | 技术清单驱动（先选技术再找场景） | 问题驱动（先有真实问题再选技术） |
| 决策痕迹 | 全部跟随教程，无自己的决策 | 至少 3 个独立设计决策且能讲理由 |
| 完成度 | 本地跑通 | 部署可访问 + 压测报告 + 使用痕迹 |
| 技术栈 | 15 个浅尝辄止 | 3-5 个能深挖 + 支撑项讲用法 |
| 可追问性 | 细节追问三句内卡壳 | 五层追问（用法→原理→取舍→演进→边界）有内容 |

一个项目同时满足"问题真实、决策独立、闭环完整、可深挖"四条的，才有资格上简历。不满足的，宁可删掉也不要留着当漏洞。

## 7. 核心要点

1. 网课跟做必须二创：至少 3 个独立设计决策，并写进文档。
2. 立项以问题为中心：真实用户 + 状态流转 + 事故场景三标准。
3. 完成度三件套：部署可访问、压测有报告、使用有痕迹。
4. 技术栈追问红线测试：三句话讲不清原理的不上简历。
5. 诚实是底线：抄项目任何细节追问都会穿帮，代价是行业信用。

> 🎯 **核心要点**：项目立得住的唯一标准是**"问不倒"**——面试官沿着项目描述连续追问五层，每一层都有真实内容。所有坑的本质都是同一个：项目里没有"我"的痕迹。把决策、数据、事故都做成"我做过"的证据，坑自然消失。
