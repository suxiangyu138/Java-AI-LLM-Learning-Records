## 3. 学习路线推荐

**快速通道（已有项目基础，1 周）**：09 实战全流程 → 10 面试深挖。直接照着端到端案例把项目搭出来，面试前补 10 的追问与避坑。

**完整路径（校招主力，3-4 周）**：01-02 建立架构认知与立项 → 03-04 分别吃透两端实现 → 05-08 打通通信、数据、安全、部署四个横向主题 → 09 动手落地 → 10 面试冲刺。

**面试突击（已做完项目，3 天）**：只读 10，再回查 01（架构理由）、05（通信选型）、06（一致性）、08（部署）中被追问的细节。

## 4. 核心概念速查

| 概念 | 一句话速查 |
|---|---|
| 双栈架构 | Java 负责状态与动作，Python 负责思考与决策 |
| 稳态底座 | Java 承载高并发、强事务、权限安全的业务生命线 |
| 敏态大脑 | Python 承载意图识别、规划、RAG、生成等快速迭代的 AI 能力 |
| 单写者规则 | 每份数据只有一个栈负责写入，杜绝双写竞争 |
| Tool API | Java 把业务能力（查订单/退款/改地址）标准化为 AI 可调用接口 |
| SSE 流式 | 基于 HTTP 的逐 token 返回通道，FastAPI StreamingResponse + SseEmitter |
| 网关前置 | 前端只进 Java 网关，Python 服务不对外暴露 |
| MCP | 跨语言工具调用标准化协议（2026 官方推荐方向） |
| 最终一致 | 知识库、向量索引等异步数据允许短暂延迟后收敛 |

## 5. 双栈联合实战 vs 单栈项目

2026 年 AI Agent 进入商用落地周期，行业共识是：纯 Java 团队写不出好用的 Agent（AI 开源框架迭代慢，多模态、多智能体、向量检索生态薄弱），纯 Python 团队撑不住企业级业务（高并发交易、分布式事务、复杂权限管控的稳定性不足）。于是「Java 稳态底座 × Python 敏态大脑」成为企业级 LLM 应用的标准蓝图：Java 守住业务的稳，Python 释放 AI 的敏。

从校招视角看，单栈项目（纯 Spring Boot CRUD 或纯 RAG Demo）已经难以建立区分度；双栈联合项目一次覆盖两个岗位的考察面——既展示 Java 后端的高并发与工程化能力，又展示 AI 应用的设计与调优能力，面试官无论问哪一端都有真实的内容可以深挖。这正是本目录被标注「强烈建议完成」的原因：它是前三个项目（FlavorDash / SuGuangMall / LingShu）能力的一次组合输出。

| 维度 | 单栈 AI 项目 | 双栈联合项目 |
|---|---|---|
| 覆盖面 | 只有 AI 或只有业务 | AI 能力 + 企业级业务双覆盖 |
| 面试深挖点 | 集中在 RAG/Agent 单侧 | 两端原理 + 跨栈通信/数据/部署全链路 |
| 工程化体现 | 较弱 | 网关、契约、追踪、CI/CD 一应俱全 |
| 简历含金量 | 中等 | 可同时投 Java 后端与 AI 应用岗 |

## 6. 与仓库其他体系的关系

本体系不是孤立知识，它把仓库既有能力串成一条线：**03 Java 业务底座**复用的是「Spring框架核心」「MyBatisPlus」「Redis」「Sentinel」等体系；**04 Python AI 服务**直接对接「Python 异步 + FastAPI」「主流 Agent 范式」「RAG拓展优化深化」「Function Calling 函数调用」「HuggingFace 生态」；**05 通信**与「MCP 协议」「消息队列理论与实战」联动；**10 面试**与「项目场景题」「面试考察点（项目会被深挖）」互为补充——那边讲已有三项目的答法，这边讲双栈新项目的答法。

## 7. 使用建议

学习时把 03、04 两篇当作「主代码篇」精读，其余横切主题按需查阅；动手时以 09 的端到端案例为蓝本逐模块实现，每完成一个模块回读对应章节对照验收标准。全部完成后，按 10 的 30 问做一轮自我深挖演练，确保简历上写的每一句都能被追问到源码与取舍层面。

> 🎯 **核心要点**：双栈联合实战的核心不是"同时会两种语言"，而是**理解两种技术栈各自的边界，并用清晰的架构把分工、通信、数据、安全粘合起来**。面试官深挖的不是某个 API，而是你如何做架构决策。
