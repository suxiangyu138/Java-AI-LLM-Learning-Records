## 1. 知识体系导图

```
项目深挖面试（认知 → 框架 → 布防 → 技术 → 叙事 → 趋势 → 演练）
│
├── 01-深挖的本质
│     八股已死 → 三个考察目的 → 冰山模型 → 追问的四层递进
│
├── 02-项目叙事框架
│     STAR 法则 → DETAIL 五细节 → 技术故事四节点 → 三层重构
│
├── 03-高危追问区布防
│     形容词区/创新区/协作边界区 → 简历一致性 → 防御性写作
│
├── 04-技术深挖：缓存与一致性
│     删缓存 vs 更新缓存 → 先DB后缓存 → 三兄弟 → 多级缓存 → 对账
│
├── 05-技术深挖：事务并发消息
│     @Transactional 边界 → 分布式事务 → 防重与分布式锁 → MQ 四问
│
├── 06-架构与设计取舍
│     ADR 决策记录 → 方案对比讲法 → 秒杀一致性案例 → 异步与隔离
│
├── 07-数据与性能深挖
│     数字是硬通货 → 压测方法论 → 优化前后对比 → 线上排查四层
│
├── 08-难点故障与复盘
│     难点选择标准 → 故障叙事 → 失败与冲突 → 成长故事线
│
├── 09-2026 趋势：AI 时代的变化
│     八股平权 → 真实性验证 → AI 工具考察 → RAG/Agent 深挖

└── 10-实战演练：模拟深挖与 30 问
      五层追问模拟 → 30 个高频问题 → 答题范式 → 多轮分轮准备
```

模块间依赖：01 是认知基础（为什么准备、准备什么）；02 是叙事骨架（所有回答的组织结构）；03 是简历防线（深挖的入口在简历）；04/05/06/07 是四大技术深挖主线（高频追问的全部落点）；08 是故事素材（最有价值的项目叙事）；09 是 2026 年背景（理解面试官为什么这么问）；10 收束为可执行的演练流程。与同级 `项目避坑（校招高频踩坑点）/`（项目的坑）、`项目场景题/`（场景题作答）、`实战项目综合落地/`（项目本体）构成"项目 + 面试"四件套；与 `05-综合输出-面试冲刺/` 的八股体系互补——那里背知识，这里讲故事。

## 3. 学习路线推荐

**路线 A：紧急备战（3 天，面试在即）**
01 → 02 → 03 → 10。先懂考察逻辑，再用 STAR 重构你的两个核心项目，最后按 30 问清单过一遍——**面试前的救命路线**。

**路线 B：系统备战（1-2 周，推荐）**
路线 A + 04 + 05 + 06 + 07。把四大技术深挖主线全部过一遍，用自己项目里的真实技术点对号入座——**让"做过"变成"讲得透"**。

**路线 C：深度选手（面向目标大厂/资深岗位）**
路线 B + 08 + 09。补齐故障故事、失败复盘与 AI 时代的新考察点（RAG/Agent 项目、AI 工具使用）——**从"能过面试"到"有记忆点"**。

> 💡 与知识库关系：04/05 篇的技术点与 `02-后端核心技术` 的 Redis/MySQL/MQ 体系互文（那里学原理，这里学"怎么讲"）；06 篇架构取舍与 `08-分布式系统与架构` 呼应；09 篇 AI 项目与 `03-AI大模型应用开发` 呼应；10 篇的八股补充走 `05-综合输出-面试冲刺/`。

### 阅读时的三个常见误区

1. **"项目深挖 = 把项目细节背下来"**：细节只是素材，面试官考的是"决策与判断"——为什么这么设计、还有什么方案、代价是什么。背细节的候选人被问"如果重做改哪里"就露馅；讲判断的候选人处处有增量（01/02 篇）
2. **"技术点讲得深 = 项目深挖准备得好"**：恰恰相反——项目深挖的锚是"你的项目"，技术点是配角。把八股背得再熟，说不出"这个技术在项目里解决了什么问题"就是空谈；面试官 2026 年最反感"堆技术栈"的回答（03/09 篇）
3. **"项目越难越好"**：难点不是越多越好，而是"你能讲透的难点"才有价值——讲不透的难点（网课项目里抄来的）在追问下是灾难；一个"自己从 0 到 1 解决的小问题"，胜过三个说不清的大项目（08 篇难点选择标准）

带着三个误区读完全书，会发现每一篇都在回答同一个问题：**如何让面试官在连续追问后确信——这个项目是你做的、你懂、你还能做得更好**。

## 4. 核心概念速查

| 概念 | 一句话定义 | 关键事实（2026） |
|------|-----------|---------------------|
| 行为面试 | 用过去行为预测未来能力的面试方式 | 2026 校招主流，替代八股知识测试 |
| STAR | 情境-任务-行动-结果四段式叙事 | 一切项目回答的组织骨架 |
| DETAIL | 方向-执行-问题-调整-洞察五细节 | STAR 的"抗追问扩展包" |
| 故事四节点 | 场景-假设-验证-结论 | 技术故事的必备结构 |
| 三层重构 | 动机-动作-决策 | 把"做了什么"升级为"为什么做" |
| 高危追问区 | 形容词/创新/协作边界三类区域 | 简历上被追问概率最高的地方 |
| 删缓存而非更新 | 写路径更新 DB 后删缓存 | 缓存一致性最经典的一问 |
| 缓存三兄弟 | 穿透/击穿/雪崩 | 缓存深挖必考三场景 |
| 分布式事务 | 最终一致性 + 事务消息 | RocketMQ 半事务消息是标准答案 |
| 五层追问模拟 | 对同一细节连续追问五次 | 检验准备度的最有效方法 |
| 八股平权 | AI 让八股答案失去区分度 | 2026 面试转向深挖真实项目的根本原因 |

> 🎯 **核心要点**：项目深挖的全部矛盾压缩为一句话——**2026 年八股答案被 AI 平权后，面试官只能用"连续追问真实项目"来区分"做过事的人"与"读过书的人"，你的全部准备就是让每个项目经得起五层追问：做什么、怎么做、为什么、代价是什么、还能怎么做**；体系的三条主线——叙事框架（STAR 讲清楚）、技术纵深（缓存/事务/并发/MQ 讲透彻）、决策叙事（取舍与复盘讲出判断力）——缺一条都会在某个追问层露馅。

### 体系速读版（30 秒版）

- **为什么被深挖**：八股已死，面试官用追问验证"你真做过"（01 篇）
- **怎么讲项目**：STAR + 故事四节点 + 三层重构（02 篇）
- **哪里会被追问**：简历的高危追问区（03 篇）
- **追问什么技术**：缓存一致性、分布式事务、锁与幂等、MQ 四问（04/05 篇）
- **怎么讲出彩**：设计取舍、量化数据、故障复盘（06/07/08 篇）
- **2026 新变化**：AI 工具考察、真实项目验证（09 篇），30 问演练收尾（10 篇）
