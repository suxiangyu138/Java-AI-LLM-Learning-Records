MySQL理论+企业级实战（Java后端入门版）
第一章：数据库入门（Java后端必学基础）
1.1 什么是数据库（DB）？核心作用是什么？
理论核心：数据库（Database，简称DB）是长期存储在计算机内、有组织、可共享的大量数据的集合，它采用特定的数据结构组织数据，能实现数据的高效存储、查询、修改和删除，且保证数据的完整性、安全性和一致性。
Java后端视角（实战关联）：作为后端开发，我们写的接口（如用户登录、订单查询），本质都是通过Java代码操作数据库，获取或修改数据。比如用户登录时，后端代码需要查询数据库中“用户表”的账号密码，判断是否匹配；下单时，需要向“订单表”插入新数据，同时修改“商品表”的库存——数据库就是后端的数据“仓库”，所有业务数据都依赖它存储。
企业级注意：生产环境中，数据库不会是单机运行（避免单点故障），但入门阶段我们先掌握单机基础，后续再讲解集群、主从复制等企业级部署方案。
1.2 数据库管理系统（DBMS）与MySQL的关系
理论核心：数据库管理系统（Database Management System，简称DBMS）是管理数据库的软件，负责统一管理和控制数据库，提供数据的存储、查询、安全控制等功能。我们常说的MySQL、Oracle、SQL Server，都属于DBMS，而“数据库”是DBMS管理的对象（相当于：DBMS是“仓库管理员”，数据库是“仓库”，数据是“仓库里的货物”）。
主流DBMS对比（Java后端常用）：
MySQL：开源免费（企业级常用社区版），轻量、高效、易部署，支持高并发，是Java后端（尤其是互联网项目）的首选（如电商、社交、后台管理系统），本教程全程聚焦MySQL。
Oracle：收费，功能强大，稳定性高，适合大型企业级项目（如银行、政务系统），Java后端也会用到，但入门门槛高，优先掌握MySQL后再拓展。
SQL Server：微软出品，适合.NET技术栈，Java后端很少用，了解即可。
实战要点：Java后端开发中，我们通过JDBC、MyBatis、Spring Data JPA等框架操作MySQL（后续实战章节详细讲解），无需直接操作DBMS软件， but 必须理解DBMS的工作逻辑，才能排查数据操作中的问题（如连接超时、查询缓慢）。
1.3 数据库的核心分类（关系型 vs 非关系型）
理论核心：数据库分为两大类，Java后端开发中通常是“关系型数据库为主，非关系型数据库为辅”，二者搭配使用。
1.3.1 关系型数据库（RDBMS）
定义：以“关系模型”（即表格形式）组织数据，表格之间有明确的关联关系（如用户表和订单表通过“用户ID”关联），支持SQL（结构化查询语言）操作，强调数据的一致性和完整性。
代表：MySQL、Oracle、PostgreSQL，Java后端的核心业务数据（用户、订单、商品、权限），几乎都存在关系型数据库中——因为这些数据需要严格的一致性（比如下单时，库存不能为负、订单不能重复创建）。
1.3.2 非关系型数据库（NoSQL）
定义：不采用表格结构，以键值对、文档、图形等形式存储数据，无需严格的关联关系，追求高并发、高可用、可扩展，不支持标准SQL（有自己的查询语法）。
代表：Redis（键值对，Java后端常用作缓存）、MongoDB（文档型，适合存储非结构化数据，如文章内容、用户日志）、ElasticSearch（搜索引擎，用于全文检索）。
企业级实战搭配：MySQL存储核心业务数据，Redis缓存热点数据（如首页商品列表、用户登录状态），减少MySQL的查询压力；MongoDB存储非结构化数据——这是Java后端最常见的“关系型+非关系型”组合，后续会专门讲解实战场景。
1.4 MySQL的安装与环境配置（企业级实战前置）
理论基础：MySQL的版本分为社区版（Community Edition）和企业版（Enterprise Edition），企业级开发中常用MySQL 8.0（稳定、支持更多新特性，如窗口函数、JSON类型），避免使用5.6及以下版本（部分语法不兼容，且安全性不足）。
实战步骤（简化版，适配Java后端开发，避免冗余操作）：
下载：官网下载MySQL 8.0社区版（https://dev.mysql.com/downloads/mysql/），选择对应系统（Windows/Linux，企业级服务器多为Linux，本地开发用Windows）。
安装：Windows端一路下一步，注意设置root用户密码（企业级环境中，密码需复杂，避免简单密码，如root123，后续会讲解权限管理）；Linux端通过yum或源码安装（后续实战章节详细讲解，适配服务器部署）。
配置：核心配置（my.cnf / my.ini），企业级常用配置（入门先记住，后续详解）：
端口：默认3306（企业级环境中可能修改端口，避免被攻击）；
字符集：utf8mb4（支持所有中文、表情符号，避免中文乱码，企业级必配）；
数据存储路径：默认路径可修改，避免系统盘满导致数据库崩溃；
连接超时：wait_timeout = 86400（避免连接闲置过久被断开，适配Java后端的连接池）。
测试连接：安装完成后，通过命令行（mysql -u root -p）输入密码，能成功进入MySQL控制台，即为安装成功；本地开发可搭配可视化工具（Navicat、DBeaver，企业级常用），方便操作数据库。
企业级注意：生产环境中，MySQL不会直接暴露公网，会通过防火墙限制访问，且root用户仅允许本地登录，业务操作使用普通用户（最小权限原则），避免误操作或黑客攻击——这些权限管理内容，后续章节详细讲解。
1.5 核心概念：数据库、表、字段、记录（Java后端必懂）
理论核心：MySQL作为关系型数据库，所有数据都存储在“表”中，而“表”属于“数据库”，三者是“数据库 > 表 > 记录/字段”的层级关系，对应Java中的“项目 > 实体类 > 实体对象/属性”。
对应关系（Java后端视角，重点记忆）：

1.6 入门实战：创建第一个数据库和表（Java后端视角）
目标：模拟Java后端项目，创建一个“用户管理”相关的数据库和用户表，练习基础SQL操作（创建数据库、创建表），为后续Java代码操作数据库铺垫。
步骤1：登录MySQL控制台（或使用可视化工具），执行SQL创建数据库（企业级命名规范：db_项目名，小写，下划线分隔）：
-- 创建数据库，指定字符集为utf8mb4（避免中文乱码），排序规则utf8mb4_general_ci
CREATE DATABASE IF NOT EXISTS db_user_manage CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
-- 切换到该数据库（后续操作都针对这个数据库）
USE db_user_manage;
步骤2：创建用户表（t_user，企业级命名规范：t_表名，小写，下划线分隔），字段设计符合Java实体类规范：
-- 创建用户表，主键id（自增，Java中对应Long），用户名（非空、唯一），密码（非空），创建时间（默认当前时间）
CREATE TABLE IF NOT EXISTS t_user (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,  -- 主键，自增，对应Java的Long
    username VARCHAR(50) NOT NULL UNIQUE,  -- 用户名，非空，唯一（避免重复注册），对应Java的String
    password VARCHAR(100) NOT NULL,       -- 密码，非空，存储加密后的密码（企业级不存明文），对应Java的String
    phone VARCHAR(20),                    -- 手机号，可空，对应Java的String
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP  -- 创建时间，默认当前时间，对应Java的LocalDateTime
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;  -- 引擎：InnoDB（企业级首选，支持事务、外键），字符集utf8mb4
步骤3：插入测试数据（模拟用户注册），练习插入操作：
-- 插入一条测试数据（密码后续用MD5加密，这里先写明文方便测试）
INSERT INTO t_user (username, password, phone) VALUES ('zhangsan', '123456', '13800138000');
-- 查询t_user表的所有数据，验证插入成功
SELECT * FROM t_user;
企业级注意：
表引擎：InnoDB是企业级首选，支持事务（保证数据一致性，如转账、下单）和外键（表之间的关联），MyISAM引擎不支持事务，仅用于只读场景（如日志表），已基本淘汰。
密码存储：绝对不能存储明文密码，企业级中会用MD5、SHA256等加密方式，后续实战章节讲解Java代码加密和MySQL加密函数。
字段约束：非空约束（NOT NULL）、唯一约束（UNIQUE）是企业级表设计的基础，避免无效数据（如用户名为空、重复注册）。
1.7 本章小结（Java后端重点）
1. 核心认知：数据库是Java后端的数据仓库，MySQL是首选的关系型DBMS，搭配NoSQL使用；
2. 核心概念：数据库、表、字段、记录，对应Java的项目、实体类、属性、对象，必须一一对应；
3. 实战重点：掌握MySQL 8.0的安装配置、基础SQL（创建数据库、表、插入、查询），理解企业级命名规范和基础约束；
4. 后续衔接：下一章讲解MySQL数据类型（Java实体类与MySQL字段的对应关系）、SQL基础操作（查询、修改、删除），逐步过渡到企业级表设计和Java代码操作MySQL。
