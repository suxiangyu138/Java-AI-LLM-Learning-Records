JVM

--------------------------------------------------------------------------------------------------------------------------------------
一、JVM基本概念
1. 定义
    JVM（Java Virtual Machine）即Java虚拟机，是运行Java字节码的虚拟计算机，实现"一次编写，到处运行"的核心，屏蔽不同操作系统硬件差异。
2. 核心作用
    - 加载并执行Java字节码文件（.class）
    - 管理内存（分配/回收）
    - 提供垃圾回收（GC）机制
    - 处理字节码解释/编译执行

--------------------------------------------------------------------------------------------------------------------------------------
二、JVM整体结构
1. 类加载子系统
    - 负责将.class文件加载到内存，分为加载、验证、准备、解析、初始化5个阶段
    - 核心组件：类加载器（启动类加载器、扩展类加载器、应用类加载器、自定义类加载器）
    - 关键机制：双亲委派模型（避免类重复加载，保证核心类安全）
2. 运行时数据区（JVM内存结构）
    -- 线程私有区域
    ① 程序计数器：记录当前线程执行的字节码行号，唯一不会OOM的区域
    ② 虚拟机栈：存储方法调用的栈帧（局部变量表、操作数栈、动态链接、返回地址），栈深度不足抛StackOverflowError，内存不足抛OOM
    ③ 本地方法栈：为Native方法提供服务，与虚拟机栈功能类似
    -- 线程共享区域
    ① 堆：JVM最大内存区域，存储对象实例和数组，垃圾回收主要区域，内存不足抛OOM
    ② 方法区：存储类信息、常量、静态变量、即时编译后的代码等，JDK8后用元空间替代永久代，元空间使用本地内存
    -- 运行时常量池：方法区的一部分，存储编译期生成的字面量和符号引用
3. 执行引擎
    - 解释器：逐行解释执行字节码，启动快，执行慢
    - JIT编译器（即时编译器）：将热点代码（频繁执行的代码）编译为机器码，提升执行效率
    - 垃圾回收器：负责堆内存中无用对象的回收，释放内存
4. 本地方法接口（JNI）
    - 连接Java程序和本地代码（C/C++）的桥梁，调用本地方法库

--------------------------------------------------------------------------------------------------------------------------------------
三、垃圾回收（GC）核心
1. 垃圾判定算法
    - 引用计数法：通过对象引用数判断，无法解决循环引用问题
    - 可达性分析算法：以GC Roots为起点，不可达对象判定为垃圾（主流算法）
  GC Roots包括：虚拟机栈引用的对象、方法区静态变量/常量引用的对象、本地方法栈引用的对象等
2. 常见垃圾回收器
    - Serial GC：单线程回收，适用于单核、小内存场景（客户端）
    - Parallel GC：多线程回收，注重吞吐量（默认JDK8）
    - CMS GC：并发标记清除，注重低延迟，缺点：内存碎片、CPU占用高
    - G1 GC：区域化分代式，兼顾吞吐量和延迟，适用于大内存场景（JDK9默认）
    - ZGC/Shenandoah：低延迟回收器，毫秒级停顿，适用于超大内存场景
3. 垃圾回收流程
    - 标记：标记出需要回收的对象
    - 清除：释放标记对象的内存（产生碎片）
    - 整理：移动存活对象，整理内存（解决碎片）
    - 复制：将内存分为两块，只使用一块，回收时复制存活对象到另一块（无碎片，空间利用率低）

四、JVM参数（常用）
1. 堆内存设置
    -Xms：初始堆内存（如-Xms512m）
    -Xmx：最大堆内存（如-Xmx1024m），通常设置为相同值避免内存动态调整
2. 新生代/老年代设置
    -Xmn：新生代内存大小（如-Xmn256m）
    -XX:SurvivorRatio：新生代中Eden区与Survivor区比例（默认8:1:1）
3. 垃圾回收器设置
    -XX:+UseSerialGC：使用Serial GC
    -XX:+UseParallelGC：使用Parallel GC
    -XX:+UseConcMarkSweepGC：使用CMS GC
    -XX:+UseG1GC：使用G1 GC
4. 监控参数
    -XX:+PrintGCDetails：打印GC详细日志
    -XX:+PrintGCTimeStamps：打印GC时间戳
    -Xloggc:gc.log：将GC日志输出到文件

--------------------------------------------------------------------------------------------------------------------------------------
五、JVM常见问题
1. OOM（OutOfMemoryError）
    - 堆内存OOM：创建大量对象无法回收
    - 虚拟机栈OOM：栈深度过大或创建过多线程
    - 方法区OOM：加载过多类（如动态代理、频繁热部署）
2. StackOverflowError
    - 方法递归调用过深，虚拟机栈栈帧过多
3. 内存泄漏
    - 对象无用但仍被引用，无法被GC回收，最终导致OOM

--------------------------------------------------------------------------------------------------------------------------------------
总结
1. JVM核心是运行时数据区（堆为核心）和垃圾回收机制，保证Java程序的内存管理
2. 不同垃圾回收器适用于不同场景，需根据业务（吞吐量/延迟）选择
3. JVM参数调优核心是合理分配堆内存、选择合适回收器，避免OOM和内存泄漏
