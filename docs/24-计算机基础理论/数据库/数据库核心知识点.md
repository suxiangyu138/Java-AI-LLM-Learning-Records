数据库核心知识点
一、数据库系统概述
1. 数据管理技术的发展阶段
- 人工管理阶段：数据不保存、无专门软件管理、数据不共享、数据不具有独立性，仅适用于科学计算。
- 文件系统阶段：数据可长期保存、由文件系统管理数据、数据共享性差、冗余度高、数据独立性低，数据以文件形式存储。
- 数据库系统阶段：由数据库管理系统（DBMS）统一管理数据，数据共享性高、冗余度低、具有高度的物理独立性和一定的逻辑独立性，数据结构化，是目前主流的数据管理方式。
2. 数据库的基本概念
- 数据：描述事物的符号记录，包括数字、文字、图像、音频、视频等。
- 数据库（DB）：长期存储在计算机内、有组织的、可共享的大量数据的集合，具有统一的结构形式并存放于统一的存储介质。
- 数据库管理系统（DBMS）：位于用户与操作系统之间的一层数据管理软件，核心功能包括数据定义、数据操纵、数据库运行管理、数据库的建立和维护。
- 数据库系统（DBS）：由数据库、数据库管理系统、应用程序、数据库管理员（DBA）和用户组成的完整计算机系统。
3. 数据库系统的特点
- 数据结构化：数据库中的数据按一定的数据模型组织，不仅数据内部结构化，整体也结构化，面向整个系统。
- 数据的共享性高、冗余度低、易扩充：数据可被多个用户、多个应用共享使用，减少数据冗余，避免数据不一致，便于根据需求扩充数据。
- 数据独立性高：分为物理独立性和逻辑独立性，物理独立性指用户的应用程序与数据库的物理存储结构相互独立，逻辑独立性指用户的应用程序与数据库的逻辑结构相互独立。
- 数据由DBMS统一管理和控制：DBMS提供数据的安全性保护（防止未授权访问）、完整性检查（保证数据的正确性和一致性）、并发控制（避免多用户并发操作时的数据冲突）、数据库恢复（故障后恢复数据）。
4. 数据模型
- 概念：数据模型是对现实世界数据特征的抽象，用于描述数据、组织数据和对数据进行操作，是数据库系统的核心和基础。
- 分类：分为概念模型、逻辑模型和物理模型。概念模型用于信息世界建模，常用实体-联系模型（E-R模型）；逻辑模型用于数据库系统建模，常见的有层次模型、网状模型、关系模型、面向对象模型，其中关系模型是目前最常用的模型；物理模型描述数据在存储介质上的存储结构和存取方法。
- 关系模型的基本概念：关系（对应数据库中的表）、元组（对应表中的行）、属性（对应表中的列）、码（能唯一标识元组的属性或属性组，如主键）、域（属性的取值范围）、分量（元组中的一个属性值）、关系模式（对关系的描述，格式为：关系名(属性名1,属性名2,…,属性名n)）。
二、关系数据库
1. 关系的数学定义
- 关系是笛卡尔积的有限子集，笛卡尔积是多个域的所有可能组合，关系中的每个元组对应笛卡尔积中的一个元素。
- 关系必须是规范化的，满足第一范式（1NF）：关系中的每个属性都是不可再分的原子值。
2. 关系的完整性约束
- 实体完整性：关系的主键属性值不能为null，且主键值唯一，用于保证实体的唯一性。
- 参照完整性：外键的值必须是另一个关系主键的有效值，或者为null，用于保证两个关系之间的引用一致性；外键是一个关系中的属性或属性组，它引用另一个关系的主键。
- 用户定义的完整性：根据具体应用需求定义的约束条件，如属性的取值范围、格式限制等。
3. 关系代数
- 关系代数是一种抽象的查询语言，用对关系的运算来表达查询，运算对象是关系，运算结果也是关系。
- 传统的集合运算：包括并、差、交、笛卡尔积。并运算要求两个关系具有相同的关系模式，结果是两个关系的所有元组的集合，去除重复元组；差运算的结果是属于第一个关系但不属于第二个关系的元组集合；交运算的结果是同时属于两个关系的元组集合；笛卡尔积是两个关系的元组的所有可能组合。
- 专门的关系运算：包括选择、投影、连接、除。选择运算是从关系中选取满足给定条件的元组，是对行的操作；投影运算是从关系中选取指定的属性列，是对列的操作；连接运算是从两个关系的笛卡尔积中选取属性间满足一定条件的元组，常用的连接有等值连接（连接条件为属性值相等）、自然连接（等值连接的特殊形式，去掉重复属性列）、左外连接（保留左关系的所有元组，右关系中无匹配元组的部分填null）、右外连接（保留右关系的所有元组，左关系中无匹配元组的部分填null）、全外连接（保留两个关系的所有元组，无匹配的部分填null）；除运算是一种复杂的关系运算，用于求解“查询…全部的…”类问题。
三、结构化查询语言（SQL）
1. SQL的特点
- 综合统一：集数据定义语言（DDL）、数据操纵语言（DML）、数据控制语言（DCL）于一体，语言风格统一。
- 高度非过程化：用户只需说明“做什么”，无需说明“怎么做”，由DBMS自动完成操作。
- 面向集合的操作方式：操作对象和结果都是集合。
- 语言简洁，易学易用：核心功能仅需少量关键词，如SELECT、INSERT、UPDATE、DELETE等。
- 支持多种使用方式：既可作为交互式语言，也可嵌入到高级语言中使用。
2. 数据定义语言（DDL）
- 定义数据库和表的结构，常用命令包括CREATE、ALTER、DROP。
- 创建数据库： CREATE DATABASE 数据库名; 
- 创建表： CREATE TABLE 表名(属性名1 数据类型 [约束], 属性名2 数据类型 [约束], …); ，常见约束有主键约束（PRIMARY KEY）、外键约束（FOREIGN KEY）、非空约束（NOT NULL）、唯一约束（UNIQUE）、检查约束（CHECK）。
- 修改表结构： ALTER TABLE 表名 ADD 列名 数据类型; （添加列）、 ALTER TABLE 表名 MODIFY 列名 数据类型; （修改列的数据类型）、 ALTER TABLE 表名 DROP COLUMN 列名; （删除列）。
- 删除数据库或表： DROP DATABASE 数据库名; 、 DROP TABLE 表名; 
3. 数据操纵语言（DML）
- 用于对表中的数据进行查询、插入、更新、删除操作。
- 查询数据： SELECT [DISTINCT] 列名1,列名2,… FROM 表名 [WHERE 条件] [GROUP BY 列名 [HAVING 条件]] [ORDER BY 列名 [ASC|DESC]]; ，DISTINCT用于去除重复值，WHERE用于筛选行，GROUP BY用于分组，HAVING用于筛选分组后的结果，ORDER BY用于排序（ASC升序，DESC降序）；支持多表连接查询、子查询（嵌套在其他查询中的查询）、聚合函数（如COUNT()统计行数、SUM()求和、AVG()求平均值、MAX()求最大值、MIN()求最小值）。
- 插入数据： INSERT INTO 表名(列名1,列名2,…) VALUES(值1,值2,…); （插入单行数据）、 INSERT INTO 表名 SELECT …; （插入查询结果）。
- 更新数据： UPDATE 表名 SET 列名1=值1,列名2=值2,… [WHERE 条件]; ，无WHERE条件时会更新表中所有行。
- 删除数据： DELETE FROM 表名 [WHERE 条件]; ，无WHERE条件时会删除表中所有行； TRUNCATE TABLE 表名; 也可删除表中所有数据，但TRUNCATE是DDL命令，执行速度更快，且无法回滚。
4. 数据控制语言（DCL）
- 用于控制用户对数据的访问权限，常用命令包括GRANT、REVOKE。
- 授予权限： GRANT 权限列表 ON 表名 TO 用户名; ，常见权限有SELECT、INSERT、UPDATE、DELETE、ALL PRIVILEGES等。
- 回收权限： REVOKE 权限列表 ON 表名 FROM 用户名; 
四、数据库设计
1. 数据库设计的步骤
- 需求分析：调查和分析用户的业务需求和数据需求，确定系统的功能边界，输出需求分析报告。
- 概念结构设计：根据需求分析的结果，设计概念模型，常用E-R模型；E-R模型的基本元素包括实体（客观存在并可相互区别的事物）、属性（实体的特征）、联系（实体之间的关联，分为一对一、一对多、多对多三种类型）；绘制E-R图，直观表示实体、属性和联系。
- 逻辑结构设计：将概念模型（E-R图）转换为具体的数据库管理系统支持的逻辑数据模型，如关系模型；转换规则包括：一个实体转换为一个关系模式，实体的属性转换为关系的属性，实体的码转换为关系的主键；一个一对一联系可转换为一个独立的关系模式，或与任意一端的关系模式合并；一个一对多联系可转换为一个独立的关系模式，或与多端的关系模式合并；一个多对多联系转换为一个独立的关系模式，联系的属性转换为关系的属性，两端实体的码共同作为关系的主键。
- 物理结构设计：为逻辑数据模型选择合适的物理存储结构和存取方法，包括确定数据的存储位置、存储结构（如聚簇存储）、索引设计等，目标是提高数据库的访问效率。
- 数据库实施：创建数据库和表，编写应用程序，插入测试数据，进行功能测试和性能测试。
- 数据库运行和维护：数据库投入运行后，由DBA进行日常维护，包括数据备份与恢复、性能监控与优化、权限管理等。
2. 数据库的规范化（范式）
- 规范化的目的是消除数据冗余，避免数据更新异常、插入异常和删除异常。
- 第一范式（1NF）：关系中的每个属性都是原子属性，不可再分。
- 第二范式（2NF）：满足1NF，且每一个非主属性完全函数依赖于主键，消除部分函数依赖；函数依赖指一个属性的值决定另一个属性的值，部分函数依赖指非主属性仅依赖于主键的一部分。
- 第三范式（3NF）：满足2NF，且每一个非主属性不传递函数依赖于主键，消除传递函数依赖；传递函数依赖指A→B，B→C，从而A→C。
- 更高阶范式：如BCNF（巴斯-科德范式）、4NF、5NF等，范式级别越高，数据冗余度越低，但查询效率可能越低，实际应用中通常达到3NF即可。
五、数据库恢复技术
1. 事务的基本概念
- 事务是数据库的逻辑工作单位，是一个不可分割的操作序列，要么全部执行，要么全部不执行。
- 事务的ACID特性：原子性（事务的所有操作要么全部执行，要么全部回滚）、一致性（事务执行前后，数据库的完整性约束不被破坏）、隔离性（多个事务并发执行时，一个事务的执行不能被其他事务干扰）、持久性（一个事务一旦提交，其对数据库的修改就是永久性的）。
2. 故障的分类
- 事务内部故障：事务执行过程中因逻辑错误或系统错误导致事务无法正常完成，如运算溢出、违反约束等。
- 系统故障：造成系统停止运转的任何事件，如硬件故障、操作系统崩溃等，会导致正在运行的事务全部中断，未提交的事务回滚，已提交的事务可能未写入磁盘。
- 介质故障：存储数据库的介质发生故障，如磁盘损坏，会导致数据库数据部分或全部丢失，是最严重的故障。
- 计算机病毒：恶意程序破坏数据库的数据和结构。
3. 恢复的实现技术
- 数据转储：DBA定期将数据库复制到磁带或磁盘上保存起来的过程，分为静态转储（转储期间不允许对数据库进行任何操作）和动态转储（转储期间允许对数据库进行操作）、海量转储（转储全部数据库）和增量转储（仅转储上次转储后更新的数据）。
- 日志文件：记录事务对数据库的更新操作，包括事务开始标记、事务结束标记、每个更新操作的详细信息（如操作类型、数据项的旧值和新值）；日志文件用于事务故障恢复和系统故障恢复，遵循先写日志后写数据库的原则。
4. 恢复策略
- 事务故障恢复：由DBMS自动完成，反向扫描日志文件，对该事务的更新操作执行逆操作（撤销未提交的修改）。
- 系统故障恢复：由DBMS在系统重启后自动完成，分为撤销未提交的事务、重做已提交但未写入磁盘的事务。
- 介质故障恢复：需要DBA介入，先装入最新的数据库备份，再装入日志文件，重做已提交的事务。
六、并发控制
1. 并发操作带来的问题
- 丢失修改：两个事务同时修改同一数据，一个事务的修改覆盖了另一个事务的修改。
- 不可重复读：一个事务内多次读取同一数据，在读取过程中，另一个事务修改了该数据，导致前后读取结果不一致。
- 幻读：一个事务内多次执行同一查询，在查询过程中，另一个事务插入了新的数据，导致查询结果出现了原本不存在的行。
2. 封锁技术
- 封锁是实现并发控制的主要技术，事务在操作数据前，先向DBMS申请对该数据的封锁，获得封锁后才能操作，操作完成后释放封锁。
- 封锁的类型：共享锁（S锁），多个事务可同时对同一数据加S锁，加S锁后只能读取数据，不能修改数据；排他锁（X锁），一个事务对数据加X锁后，其他事务不能对该数据加任何锁，加X锁后可以读取和修改数据。
3. 封锁协议
- 一级封锁协议：事务在修改数据前加X锁，直到事务结束才释放，可防止丢失修改。
- 二级封锁协议：在一级封锁协议的基础上，事务在读取数据前加S锁，读完后立即释放S锁，可防止丢失修改和不可重复读。
- 三级封锁协议：在一级封锁协议的基础上，事务在读取数据前加S锁，直到事务结束才释放S锁，可防止丢失修改、不可重复读和幻读。
4. 活锁和死锁
- 活锁：多个事务都在等待对同一数据的封锁，导致某个事务长期无法获得封锁，可通过采用先来先服务的策略避免。
- 死锁：两个或多个事务相互等待对方释放封锁，导致所有事务都无法继续执行；死锁的预防方法包括一次封锁法（事务一次性申请所有需要的锁）、顺序封锁法（按规定的顺序申请锁）；死锁的诊断方法包括超时法、等待图法；死锁的解除方法是选择一个代价最小的事务撤销，释放其持有的锁。
七、数据库新技术
1. 分布式数据库系统
- 数据分布在计算机网络的不同节点上，每个节点具有独立处理能力，节点之间通过网络通信；具有数据分布性、逻辑整体性、节点自治性等特点；优点是提高系统可靠性和可用性、平衡负载、降低通信成本，缺点是复杂度高、存在数据一致性维护问题。
2. 面向对象数据库系统
- 结合面向对象程序设计和数据库技术，支持复杂数据类型（如对象、继承、多态），适用于处理复杂数据，如多媒体数据、地理信息数据等。
3. NoSQL数据库
- 非关系型数据库，不遵循关系模型，不支持SQL；常见类型包括键值型数据库（如Redis）、文档型数据库（如MongoDB）、列族数据库（如HBase）、图形数据库（如Neo4j）；优点是高可扩展性、高并发、适合存储非结构化和半结构化数据，缺点是缺乏统一的标准、事务支持较弱。
4. 大数据与云计算相关数据库技术
- 大数据数据库需要支持海量数据的存储和高效查询，常用技术包括分布式存储、并行计算；云计算数据库是部署在云平台上的数据库服务，如阿里云RDS、腾讯云CDB，具有按需付费、弹性扩展、高可用性等特点。
八、数据库安全
1. 数据库安全的威胁
- 非授权访问：未被授权的用户访问数据库数据。
- 数据泄露：敏感数据被非法获取和传播。
- 数据篡改：非法修改数据库中的数据。
- 拒绝服务攻击：导致数据库无法正常提供服务。
2. 数据库安全的防护措施
- 用户身份认证：验证用户的身份，如用户名和密码认证、指纹认证、数字证书认证等。
- 存取控制：对不同用户分配不同的权限，如DBA拥有最高权限，普通用户仅拥有查询权限。
- 数据加密：对敏感数据进行加密存储和传输，分为对称加密和非对称加密。
- 审计跟踪：记录用户对数据库的所有操作，便于事后追查和分析。
- 防火墙：设置数据库防火墙，过滤非法的访问请求。
