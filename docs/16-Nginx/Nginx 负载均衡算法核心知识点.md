Nginx 负载均衡算法核心知识点
---------------------------------------------------------------------------------------------------------------------------------------
一、轮询（默认算法）
1. 请求按顺序依次分配给后端服务器。
2. 某台服务器挂掉，自动剔除。
3. 适用于所有服务器配置相同、请求均匀的场景。
---------------------------------------------------------------------------------------------------------------------------------------
二、加权轮询
1. 给不同服务器设置权重 weight，权重越高，分配请求越多。
2. 适用于服务器性能不一样的场景。
---------------------------------------------------------------------------------------------------------------------------------------
三、ip_hash
1. 根据客户端 IP 计算哈希值，固定分配到某台后端服务器。
2. 保证同一个用户的请求始终落到同一台服务器。
3. 解决 Session 不共享问题。
---------------------------------------------------------------------------------------------------------------------------------------
四、url_hash
1. 根据请求的 URL 计算哈希值，相同 URL 分配到同一台服务器。
2. 用于提高缓存命中率，减少重复查询。
---------------------------------------------------------------------------------------------------------------------------------------
五、least_conn 最少连接
1. 哪个服务器当前连接数最少，就把新请求分给它。
2. 适用于请求处理时间差异大、容易出现负载不均的场景。
---------------------------------------------------------------------------------------------------------------------------------------
六、fair（第三方模块）
1. 根据后端服务器的响应时间分配，响应快的优先分配。
2. 需要额外安装模块才能使用。
---------------------------------------------------------------------------------------------------------------------------------------
七、随机 random
1. 随机选择一台后端服务器。
2. 高并发下也能实现较均匀的分配。
---------------------------------------------------------------------------------------------------------------------------------------
八、企业常用总结
1. 服务器性能相同：轮询。
2. 服务器性能不同：加权轮询。
3. 需要保持用户会话：ip_hash。
4. 请求处理时间差异大：least_conn。
5. 缓存服务：url_hash。
---------------------------------------------------------------------------------------------------------------------------------------
